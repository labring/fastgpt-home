# 股份制银行智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
股份制银行智能尽调报告的数据来源包含内部授信档案、季度/年度财报、监管报送台账，以及外部征信、工商公示接口。数据更新节奏存在差异：授信档案随客户授信变动实时更新，财报按季度/年度同步更新，监管台账按月度报送更新。文档结构通常包含尽调主体基本信息、财务指标明细、风控评级结果、关联交易记录、担保合同摘要等模块，字段多为结构化数值与文本标签，数值字段统一使用万元、亿元作为单位，评级字段采用AA、BBB等标准化字母等级。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据的混合接入要求工具插件需支持内部接口与外部API的统一调用，避免出现数据格式不兼容的问题。不同更新频率的数据需配置差异化的缓存策略，例如实时更新的授信数据需禁用本地缓存，季度财报数据可设置按天缓存。字段的标准化单位要求工具调用时需自动校验参数单位匹配度，避免出现数值与单位错位的解析错误。长文档与多模态附件的存在，要求插件调用需支持分页解析与分块处理，防止单次调用超时或内存溢出。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 股份制银行尽调报告常包含多页财报扫描件与附件，该取值可覆盖绝大多数常规场景的文件上传需求 |
| `TOOL_CALL_TIMEOUT` | `120 秒` | 单份尽调报告需调用财务解析、关联方查询、风控评级等多个工具，该时长可覆盖跨接口调用的平均延迟 |
| `PARSE_TABLE_STRICT_MODE` | 开启 | 尽调报告中的财务表格字段单位统一要求高，严格模式可避免单位解析错误，提升结构化数据准确率 |
| `SESSION_PERSIST_DURATION` | `7 天` | 股份制银行尽调流程常跨多个工作日，该配置可保留完整的会话上下文，确保工具调用的连贯性 |
| `MAX_TOOL_CALL_STEPS` | `8 次` | 单份尽调报告的工具调用链条通常包含5-7个环节，该上限可避免无效循环调用，同时覆盖全流程需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用多模态解析插件时返回`400 <400> InternalError.Algo.InvalidParameter: Multimodal file size is`错误。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，上传的尽调报告扫描件超出平台默认上限。
- 现象：工作流中工具调用模块的输出内容强制返回至对话界面，无法隐藏。原因：未关闭工具调用的`show_tool_output`开关，默认配置为开启状态。
- 现象：输入文本“分享”调用工具时被解析为“分交”。原因：未开启`INPUT_NORMALIZE`配置，中文输入法的候选词未正确截断，导致输入转义异常。

## 怎么确认配好了
- 上传单份最大尺寸的尽调报告扫描件，验证插件调用无参数错误，根据实际文件尺寸调整`UPLOAD_FILE_MAX_SIZE`。
- 运行包含多工具调用的测试工作流，确认会话上下文在多次调用间保持一致，根据尽调流程周期调整`SESSION_PERSIST_DURATION`。
- 输入含易混淆字词的测试文本，验证工具调用时的输入解析结果，确认`INPUT_NORMALIZE`配置是否适配场景。
- 禁用工具输出开关后运行测试，确认对话界面仅展示最终结论，无中间工具调用内容。
