# 自动化设备智能尽调报告的工作流编排

## 这个品类的数据长什么样
自动化设备的尽调数据来源包含厂商出厂参数文档、设备运维日志、第三方质检报告、行业标准合规文件。其中出厂参数为静态数据，随设备型号固定；运维日志为高频更新数据，按日或按班次生成；质检报告为批次更新数据，随设备投产批次同步。单份尽调文档结构包含设备型号、序列号、核心部件参数（如功率、转速、精度等级）、维护周期、故障历史等字段，字段单位包含kW、rpm、μm、小时等，部分字段存在多单位兼容的情况。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的分散来源要求工作流需配置多节点分别拉取不同数据源的内容，避免单一节点过载。不同数据的更新节奏差异，要求工作流需设置差异化的触发间隔，静态参数可按周同步，运维日志需按日触发拉取。字段单位的多样性要求工作流内置单位转换工具，避免参数对比时出现单位不匹配的问题。单份尽调文档的长度波动范围较大，要求工作流配置灵活的分段处理节点，适配从数百字符到数万字符的不同文档长度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `知识库召回条数` | 前8-12条 | 自动化设备的核心参数与运维字段数量较多，需覆盖足够的内容以支撑尽调报告生成 |
| `相似度阈值` | 0.75-0.85 | 设备参数多为专业术语，需较高匹配精度避免低相关性内容混入尽调报告 |
| `工作流超时时间` | 300-600秒 | 需拉取多源数据并处理长文本内容，避免因处理时长不足导致工作流中断 |
| `批量执行批次大小` | 5-10台/次 | 单台设备的数据量差异较大，小批次执行可避免系统资源过载 |
| `全局变量默认值` | 按知识库预设的设备分类标签 | 自动匹配对应品类的尽调模板参数，减少手动配置的工作量 |
| `文件解析分段长度` | 800-1200字符 | 适配运维日志的长文本结构，提升RAG召回的精准度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：全局变量绑定知识库时返回空值，界面提示「未匹配到对应知识库文档」。原因：未将全局变量的预设值与知识库的分类标签保持一致，导致无法自动关联对应数据源。
- 现象：知识库搜索节点返回400状态码，提示「无匹配结果」。原因：自定义知识库未上传自动化设备的标准参数文档与运维日志模板，或相似度阈值设置过高。
- 现象：批量执行节点中插件参数未按指定变量取值，仍使用插件默认配置。原因：未在工作流中配置变量优先级规则，未指定优先从自定义变量获取参数。

## 怎么确认配好了
- 手动触发单台设备的工作流，检查全局变量是否自动关联了对应分类的知识库文档。
- 查看工作流运行日志，确认批量执行节点的批次数量符合预设值，未出现资源过载类报错。
- 验证相似度阈值设置，随机抽取10份尽调报告，检查召回的文档是否包含设备核心参数与运维记录。
- 手动移除指定的插件参数变量，确认插件自动切换为预设的默认配置值。
