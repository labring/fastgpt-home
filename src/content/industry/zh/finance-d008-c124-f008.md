# 自动化设备智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
自动化设备的尽调数据主要来源于制造商公开的产品手册、工业物联网平台的离线采集日志、行业合规检测机构的认证报告。静态参数如型号、额定功率、外形尺寸随设备出厂固定更新，运维性能参数如运行转速、负载压力按日或实时同步，行业合规标准参数按季度更新。文档结构分为基础信息区、性能参数区、合规检测项区、运维记录区，字段包含设备编号、功率单位kW、转速单位r/min、压力单位MPa等标准化标识，部分非标设备会附带自定义扩展字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
自动化设备的多来源、多更新节奏的数据特征，要求工具调用需兼顾静态参数的定期同步与实时数据的按需拉取。字段与单位的多样性，要求插件需内置统一的单位转换逻辑，避免不同数据源的单位差异导致分析误差。文档长度与分段结构，要求工具调用需支持按章节分段解析，避免单段内容超出模型上下文限制。合规检测项的固定字段要求，需工具调用时严格匹配预设的校验字段，无法直接使用通用的非结构化解析逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `stop_sequence` | `["\n\n", "### 合规检测", "END_OF_DOC"]` | 匹配自动化设备尽调报告的段落分隔与章节结尾标识，避免结果截断 |
| `plugin_api_timeout` | `300 秒` | 设备参数文档内容较多，解析与API调用耗时较长，避免提前超时 |
| `field_mapping_rule` | 按自动化设备品类预设字段映射 | 匹配设备参数的固定字段体系，确保解析结果的字段完整性 |
| `unit_conversion_enabled` | `true` | 覆盖不同数据源的单位差异，统一输出标准单位的参数值 |
| `max_parsing_length` | `800–1200 字符` | 适配通用大模型的上下文窗口限制，避免单段内容过长导致解析失败 |
| `retry_count` | `2 次` | 应对网络波动或API临时不可用的场景，降低调用失败率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调用返回的尽调报告结果被截断，仅包含前半部分参数。原因：未配置`stop_sequence`或配置的停止序列与报告实际结尾标识不匹配。
- 现象：调用第三方API生成可视化报告时返回`404 Not Found`错误。原因：插件配置的API URL未匹配对应服务的部署端点，或模型版本名称拼写错误。
- 现象：本地部署调用代码插件时返回`AxiosError 404`。原因：本地服务的端口映射未正确暴露，或插件配置的本地接口路径与实际部署路径不一致。

## 怎么确认配好了
- 上传一份自动化设备的官方产品手册，触发工具调用，检查返回结果是否包含预设的核心参数字段。
- 查看插件调用日志，确认`stop_sequence`匹配文档结尾的标识，无多余或截断的内容。
- 模拟单次API调用失败的场景，检查插件是否按配置的`retry_count`执行重试，最终返回正常结果。
- 输入包含不同单位的参数示例，检查插件是否自动完成单位转换，输出统一的标准单位结果。
