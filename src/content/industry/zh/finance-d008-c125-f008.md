# 航天装备智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
航天装备尽调数据来源包括公开军工科研院所立项公告、型号定型文件、配套供应商年度披露信息、航天发射任务官方记录。数据更新无固定周期，随型号立项、首飞、定型等节点不定期发布。文档结构包含结构化参数报表、技术白皮书、合规性审查文件三类，核心字段涵盖分系统推力（单位千牛）、有效载荷（单位千克）、发射窗口周期（单位天）、配套厂商资质等级等，部分半公开文档需通过合规渠道获取。

## 这些特征在「工具调用与插件」这一环带来什么约束
航天装备尽调数据来源分散，包含公开与半公开渠道，要求工具调用支持跨源拉取与权限适配；文档结构多样，既有结构化参数表也有长文本技术描述，要求插件适配多格式解析；核心字段使用行业专属单位，要求工具支持自定义单位映射以保证数据一致性；数据更新无固定周期且单份文档篇幅较长，要求工具支持增量同步与批量解析，避免无效全量拉取与超时中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `10–15 条` | 航天装备尽调需覆盖分系统、配套厂商、发射记录多维度，过少会丢失关键参数 |
| `分段长度` | `800–1200 字符` | 航天装备技术文档包含长句专业描述，过长会破坏语义关联，过短会拆分参数组 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型分系统技术文档解析耗时较长，默认超时不足以完成完整解析 |
| `自定义单位映射` | `千牛→kN、千克→kg、天→d` | 航天装备参数使用行业专属单位，需统一映射为标准化字段 |
| `增量同步周期` | `按型号节点触发` | 航天装备数据更新无固定周期，按节点触发可避免无效拉取 |
| `batch_exec_limit` | `20 个任务/批` | 航天装备尽调需批量拉取多家供应商数据，限制单批任务数避免接口限流 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流调用知识库搜索时返回`400 Bad Request`，提示字段格式不匹配。原因：未配置航天装备专属的单位映射参数，导致解析后的参数无法匹配尽调报告的校验规则。
- 现象：插件执行时指定参数为空，未使用预设默认值。原因：未开启变量优先于默认值的配置项，且未为必填参数设置 fallback 逻辑。
- 现象：批量执行工具仅返回部分任务结果，后续任务超时失败。原因：未设置合理的`batch_exec_limit`参数，单批任务数超出接口限流阈值，导致部分请求被拦截。

## 怎么确认配好了
- 上传一份航天装备分系统参数文档，检查解析后的字段是否包含正确的单位映射，例如推力字段显示为`120 kN`，不使用`120 千牛`。
- 触发一次批量拉取供应商数据的工作流，检查所有任务是否按配置的`batch_exec_limit`分批次执行，无超时报错。
- 配置插件参数为变量绑定，删除变量值后触发执行，检查是否自动使用预设的默认参数值。
- 开启流式输出测试，检查返回结果是否包含思考过程内容，与最终结论分开展示。
