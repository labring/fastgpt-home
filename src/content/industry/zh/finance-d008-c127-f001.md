# 航空装备智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
航空装备智能尽调报告的数据主要来源于航空工业整机厂商公开技术文档、民用航空管理机构适航认证公开报告、供应链厂商交付台账、试飞测试采集数据。数据更新节奏存在差异：整机定型后的基础参数更新频率较低，供应链部件及试飞批次数据更新频率较高。单份尽调文档通常包含型号参数、适航条款、供应链溯源、试飞数据台账等模块，字段包含翼展（单位米）、最大起飞重量（单位千克）、适航认证编号、供应商批次号、累计试飞时长（单位小时）等，部分文档附带结构化的零部件BOM表及测试原始数据。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
航空装备数据的多源分散特性要求HTTP接口支持多源数据聚合调用，需兼容不同厂商的API鉴权规则。数据更新节奏的差异要求接口支持增量同步与全量同步两种模式，可根据数据源类型切换。单份文档体积较大且包含结构化BOM表，要求接口支持分片上传与断点续传，避免单次请求超时。字段包含专属单位与合规性标识，要求接口内置字段校验逻辑，自动适配航空装备的元数据格式，减少外部系统的格式转换成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 航空装备技术文档包含大量图纸与试飞原始数据，单份文件体积通常超过通用阈值 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1200 秒` | 长文档解析需处理结构化BOM表与多模块内容，耗时远超通用场景 |
| `filter_metadata_fields` | `["适航认证编号", "供应商批次号", "翼展", "最大起飞重量"]` | 覆盖航空装备尽调的核心元数据字段，确保接口返回有效信息 |
| `api_request_timeout` | `600 秒` | 多源数据聚合接口需调用多个外部系统，请求耗时较长 |
| `api_rate_limit` | `10 次/分钟` | 适配航空类外部数据接口的限流规则，避免触发第三方系统拦截 |
| `dataset_sync_interval` | `86400 秒` | 平衡整机数据的低频更新与供应链数据的高频更新需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用`/api/core/dataset/collection/create/localFile`时返回的元数据字段为空。原因是未在`filter_metadata_fields`配置中指定航空装备专属的元数据字段，接口自动过滤了未配置的字段。
- 上传航空装备文档时返回`413 Request Entity Too Large`错误。原因是未调整`UPLOAD_FILE_MAX_SIZE`配置，使用了默认的文件大小限制，无法承载大体积的技术文档。
- 批量同步接口执行超时。原因是未延长`PARSE_FILE_TIMEOUT_SECONDS`配置，默认超时时间不足以完成长文档的解析与多源数据聚合。

## 怎么确认配好了
- 上传一份航空装备技术文档，调用`/api/core/dataset/collection/list`接口，检查返回的元数据是否包含配置的`filter_metadata_fields`字段。
- 调用批量同步接口，查看返回的HTTP状态码是否为`200 OK`，且无超时相关的报错信息。
- 测试元数据过滤接口，传入指定的过滤条件，确认仅返回符合条件的航空装备数据条目。
- 查看接口调用日志，确认每秒调用次数未超过配置的`api_rate_limit`阈值，无限流拦截记录。
