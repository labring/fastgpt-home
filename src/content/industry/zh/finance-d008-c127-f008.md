# 航空装备智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
航空装备智能尽调的数据来源主要包括航空工业集团公开年报、整机厂商披露的核心参数文档、民航局适航认证数据库、供应链上下游企业的公开财报与订单信息。数据更新节奏分为三类：整机型号参数每半年更新一次，适航认证状态随认证进度实时更新，供应链订单数据每月更新。文档结构以结构化表格为主，包含整机型号、空重、最大续航时间、单机采购成本、核心部件供应商等字段，单位多采用千克、小时、万元人民币等专业计量标准。

## 这些特征在「工具调用与插件」这一环带来什么约束
航空装备尽调数据的多源分散特性要求工具调用需同时对接多个独立API或插件，需处理不同数据源的格式差异与权限限制。不同更新节奏的数据源需配置差异化的缓存刷新策略，避免因数据过期导致尽调结果失真。专业字段的标准化要求工具调用返回结果需经过校验，确保适航证编号、核心部件型号等字段符合行业规范。长文档结构则要求工具调用的上下文长度需适配单份尽调文档的篇幅，避免关键信息被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_max_parallel` | `2–4` | 航空装备数据源多为公开API，并发过高会触发限流，2-4的取值可兼顾效率与稳定性 |
| `plugin_request_timeout` | `300 秒` | 部分供应链数据查询需跨多个层级节点，响应延迟较高，300秒可覆盖绝大多数查询场景 |
| `max_context` | `8000–12000 字符` | 单份航空装备尽调文档篇幅较长，需保留足够上下文供工具调用决策，避免关键信息丢失 |
| `mysql_batch_query_enable` | `开启` | 需支持多行INSERT/SELECT语句批量执行，适配供应链数据的批量导入与查询需求 |
| `tool_call_post_process` | `启用自定义代码后处理` | 需抽取适航证编号、整机型号等核心字段，修正工具调用返回的格式误差 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用多数据源插件时频繁出现429 Too Many Requests报错。原因：未调整`tool_call_max_parallel`参数，并发请求数超过航空装备数据源公开API的限流阈值。
- 现象：工具调用返回结果中无适航认证字段，或字段格式不符合航空装备专业规范。原因：未启用`tool_call_post_process`配置，未对返回结果进行专业字段校验与标准化处理。
- 现象：MySQL插件执行多行查询时仅首条语句生效，后续语句无执行记录。原因：未开启`mysql_batch_query_enable`配置，默认仅支持单条SQL语句执行。

## 怎么确认配好了
- 调用测试数据源，观察并发请求的返回状态，调整`tool_call_max_parallel`至无429报错的取值。
- 执行包含多行SQL语句的测试请求，确认所有语句均正常执行并返回预期结果。
- 触发工具调用后，检查自定义后处理代码是否正确抽取了适航证编号、整机型号等核心字段。
- 查看插件请求日志，确认`plugin_request_timeout`设置足够长，无超时报错。
