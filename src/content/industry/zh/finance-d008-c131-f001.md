# 装修装饰智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
装修装饰智能尽调报告的数据主要来源于住建部门备案的装修资质文件、装修项目施工合同、材料供应商报价单、现场监理日志及竣工验收报告。数据更新节奏随项目进度调整，项目立项时更新基础信息，施工阶段每周更新进度记录，竣工后生成最终完整报告。文档结构分为项目基本信息、装修材料清单、施工进度台账、资质文件附件四个模块，字段包含项目地址（纯文本格式）、装修面积（单位为平方米）、材料品牌与型号（文本与统一编码组合）、施工负责人（文本格式）、资质有效期（日期格式），所有字段需符合住建部门的备案规范要求。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
装修装饰尽调数据的多源异构性要求外部接口支持多类型数据的格式校验与批量导入，单次请求的数据量较大，需接口支持分块传输或断点续传。不同数据源的认证方式存在差异，住建备案接口多采用请求头密钥认证，材料供应商接口多采用OAuth2认证，需适配多种认证逻辑。实时性要求较高的现场监理数据需通过SSE协议对接，需保持长连接稳定。数据字段的合规性要求严格，需对资质有效期、面积数值等字段进行格式校验，避免无效数据导入尽调报告。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `external_api_auth_type` | `header_auth` | 装修装饰行业对接的住建备案、材料供应商接口普遍采用请求头传递认证信息 |
| `external_api_request_timeout` | `600 秒` | 单份装修尽调报告包含多份材料清单与施工记录，接口响应耗时较长 |
| `external_api_batch_upload_size` | `50 条/请求` | 单次提交的装修材料条目数量过多会触发外部接口限流，该取值适配多数行业接口阈值 |
| `api_key_scope` | `application_specific` | 装修尽调接口需绑定对应应用权限，不宜使用全局通用密钥避免权限泄露 |
| `external_api_sse_timeout` | `120 秒` | 对接现场监理的SSE数据流时，需预留足够时间等待实时数据推送 |
| `parse_field_required_check` | `enabled` | 装修尽调报告中的项目地址、资质编号为必填字段，需开启强制校验 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用SSE格式的现场监理数据接口时返回`Key is error. You need to use the app key rather than the account key`报错，原因是配置`external_api_auth_type`时误将账号密钥填入认证头，未使用应用专属密钥。
- 批量提交装修材料清单时接口返回429 Too Many Requests状态码，原因是单次提交的条目数超过外部接口的批量上限，未按配置调整`external_api_batch_upload_size`的取值。
- 生成的尽调报告中装修面积字段为空，原因是未配置`external_api_field_mapping`将外部接口的`decorate_area`字段映射到报告的`project_area`字段，导致数据未正确关联导入。

## 怎么确认配好了
- 调用测试接口传入模拟的装修项目数据，检查请求头是否携带正确的认证密钥，确认`external_api_auth_type`与`api_key_scope`配置生效。
- 查看外部接口的请求日志，确认单次提交的材料条目数量符合预设配置，验证`external_api_batch_upload_size`的适配性。
- 触发SSE连接并等待一段时间，检查是否能持续接收监理现场的实时数据，确认`external_api_sse_timeout`配置符合业务需求。
- 手动校验生成的尽调报告字段，确认所有必填字段已完成映射与格式校验，验证`parse_field_required_check`配置生效。
