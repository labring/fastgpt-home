# 计算机设备智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
计算机设备的尽调数据主要来自硬件厂商官方API、企业内部IT资产管理系统、运维监控平台的上报日志。更新节奏分为两类：基础资产信息随设备入网、配置变更实时同步，运维性能指标每5分钟拉取一次。文档结构为结构化JSON或CSV格式，包含设备序列号、型号、CPU主频、内存容量、存储总容量、固件版本、入网时间、维保到期日等字段，字段单位分别为GHz、GB、TB、YYYY-MM-DD格式，无嵌套层级过深的复杂结构。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
结构化字段与多数据源的特性，要求HTTP接口需支持多认证方式适配，如厂商API使用API Key鉴权，内部IT系统使用OAuth2鉴权。字段包含特定单位的数值型内容，接口参数校验需强制匹配字段类型与单位规则，例如CPU主频参数需校验为带GHz后缀的数值。实时同步与高频拉取的更新节奏，要求接口需设置合理的请求频率限制，避免触发外部系统的限流策略。唯一标识字段的存在，要求接口返回数据需携带可用于去重的设备序列号，确保外部系统接入时数据关联准确。日期类字段的查询需求，要求接口支持按入网时间、维保到期日等字段进行范围筛选，以精准拉取指定周期内的设备数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `external_api_auth_type` | `api_key` 或 `oauth2` | 适配计算机设备数据源的多鉴权需求，厂商API多使用api_key，内部IT系统多使用oauth2 |
| `api_request_interval` | `300 秒` | 匹配运维指标每5分钟的拉取节奏，避免频繁调用触发外部系统限流 |
| `response_field_whitelist` | `["serial_number", "model", "cpu_freq", "memory_capacity", "storage_capacity", "maintenance_expire"]` | 仅保留尽调报告必需的字段，减少外部数据传输量，同时避免无关字段干扰报告生成 |
| `field_unit_validation` | `启用` | 计算机设备数据包含带单位的数值字段，启用校验可确保接入数据格式合规 |
| `api_timeout` | `60 秒` | 覆盖硬件厂商API的常规响应时长，避免因外部接口响应慢导致尽调任务中断 |
| `api_retry_times` | `3 次` | 应对外部接口临时波动，提升数据拉取成功率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用外部接口拉取计算机设备数据后，生成的尽调报告缺失部分字段。原因：未配置`response_field_whitelist`，导致接口返回的冗余字段被过滤，或字段名称与系统预设不匹配。
- 现象：HTTP接口调用返回429状态码，请求被拒绝。原因：未设置合理的`api_request_interval`，调用频率超过外部系统的限流阈值。
- 现象：通过API触发的尽调任务未保留上下文信息，后续调用无法关联历史数据。原因：未在工作流配置中启用上下文持久化，或HTTP接口请求未携带正确的会话ID参数。

## 怎么确认配好了
- 发起一次测试HTTP请求，检查返回的字段是否包含设备序列号、CPU主频等核心信息，核对字段单位是否符合预设规则。
- 连续发起多次请求，查看返回状态码，确认未触发429限流，核对请求间隔是否符合外部系统的要求。
- 查看工作流日志，确认每次API调用都携带了会话ID，上下文信息被正确保存并关联。
- 检查接口鉴权配置，使用无效的API Key发起请求，确认返回401未授权状态码，验证鉴权逻辑生效。
