# 计算机设备智能尽调报告的部署与升级

## 这个品类的数据长什么样
计算机设备智能尽调报告的数据来源包括硬件厂商公开参数文档、企业资产台账系统、运维采集的设备运行日志三类。数据更新节奏存在差异：硬件型号、CPU规格等基础参数为静态数据，仅在设备采购或固件升级时更新；运维日志、在线状态等实时数据按分钟或小时级更新。文档结构以结构化字段为主，包含设备序列号、型号、内存容量、硬盘规格、固件版本、采购日期、运维记录等，字段单位多为GB、TB、GHz等硬件通用单位，部分字段需符合企业资产编码规则。

## 这些特征在「部署与升级」这一环带来什么约束
多源数据接入的需求要求部署阶段配置多接口适配规则，避免不同来源的数据格式冲突。静态与实时数据的更新节奏差异，要求升级阶段区分增量同步与全量更新的触发逻辑，减少不必要的资源消耗。字段与单位的多样性要求部署阶段配置字段映射与单位校验规则，防止解析后数据出现格式错误。设备数据包含序列号、MAC地址等敏感信息，要求升级阶段同步更新脱敏配置，符合数据合规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_DEVICE_DATA_TIMEOUT` | `300 秒` | 单份尽调报告包含多台计算机设备的参数解析，需覆盖批量处理的延迟 |
| `UPLOAD_FILE_MAX_SIZE` | `1500–2000 MB` | 计算机设备尽调报告包含硬件规格、运维日志等多类数据，需适配大文件上传需求 |
| `DATA_SYNC_INTERVAL` | `1 小时（运维数据）、24 小时（硬件参数）` | 运维数据更新频率高，硬件参数变更频率低，需区分同步周期 |
| `DATA_DESENSITIZATION_RULES` | `对序列号、MAC地址字段做掩码处理` | 计算机设备数据包含运维敏感字段，需配置脱敏规则符合合规要求 |
| `ALLOWED_DATA_SOURCES` | `厂商API、资产台账系统、运维日志库` | 覆盖计算机设备数据的多源接入场景，确保数据完整性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：执行`docker build`时返回`ERROR: failed to solve: archive/tar: unknown file mod`，部署流程中断。原因：内网环境下未配置本地镜像缓存，拉取基础镜像时的tar包解析异常。
- 现象：尽调报告解析后部分硬件字段为空，或单位匹配错误。原因：未配置计算机设备专属的字段映射规则，将通用解析模板与设备专属字段格式混淆。
- 现象：批量升级后触发`504 Gateway Timeout`，同步任务失败。原因：未调整增量更新的批次大小，导致单次同步数据量超出网关限制。

## 怎么确认配好了
- 上传单台计算机设备的标准导出文件至系统，核对解析后的字段与原始数据的名称、单位完全匹配。
- 在本地内网环境执行`docker build`命令，确认无tar包解析相关报错。
- 触发一次增量同步任务，核对同步的设备数量与配置的同步范围一致。
- 查看系统生成的尽调报告，确认敏感字段已按配置完成脱敏处理。
