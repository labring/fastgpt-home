# 证券智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
证券智能尽调报告的数据来自交易所公开披露文件、上市公司定期报告、行业监管公示信息。更新节奏分为固定周期与实时触发两类：季度报告、年度报告按监管要求固定更新，临时公告在发布后实时同步。文档结构包含披露主体基础信息、财务数据模块、合规核查条目、风险提示四类核心内容，字段包括披露日期（YYYY-MM-DD格式）、营收金额（单位人民币元）、合规文号、风险等级等，部分长文档单份字数可达数万字符。

## 这些特征在「工具调用与插件」这一环带来什么约束
公开披露的多格式文档要求工具调用插件支持PDF、HTML等多种文件格式的解析；固定与实时结合的更新节奏，要求插件支持定时批量拉取与按需触发两种调用模式；多字段且带固定单位的结构化内容，要求插件内置字段标准化处理逻辑，避免单位混淆与数据类型错误；长文档特性则要求工具调用的上下文窗口与解析时长适配大文本处理需求，防止中途中断或结果截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `plugin_parse_timeout` | 300–600 秒 | 证券尽调报告多为长文本文档，需预留足够时间完成全量解析 |
| `structured_extract_threshold` | 0.75–0.85 | 适配财报结构化字段的固定格式，平衡抽取准确率与召回率 |
| `batch_fetch_interval` | 3600 秒 | 匹配定期报告的更新节奏，避免频繁拉取触发接口限制 |
| `max_context_length` | 8000–12000 字符 | 适配单份尽调报告的长文本特性，避免上下文截断 |
| `plugin_log_enabled` | 开启 | 完整记录工具调用的参数与返回结果，便于合规核查与问题排查 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为代码运行插件执行时报「模块未找到」错误，原因是插件运行环境未预装证券分析所需的第三方数据处理库。
- 现象为MCP工具调用时传入的参数未被正确解析，原因是未按照工具定义的JSON参数格式传递，未匹配证券字段的单位与数据类型。
- 现象为工作流调用插件后无对话日志生成，原因是未开启`plugin_log_enabled`配置项，或工作流节点未绑定日志记录环节。

## 怎么确认配好了
- 执行单份上市公司年报的解析测试，核对结构化字段的抽取结果与原始文档内容一致。
- 触发批量拉取任务，检查拉取的文档数量与设定的更新频率匹配。
- 查看工具调用日志，确认参数传递、返回结果均被完整记录。
- 运行测试代码片段，确认第三方依赖库可被正常加载。
