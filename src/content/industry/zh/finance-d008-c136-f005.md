# 贵金属智能尽调报告的多轮对话与提示词

## 这个品类的数据长什么样
数据来源包括上海黄金交易所官方行情接口、伦敦金银市场协会的场外交易报价、国内期货交易所的贵金属合约数据，以及行业协会发布的供需动态。更新节奏为：实时行情每15秒刷新一次，合约交割标准文档为静态更新，行业研报按季度或重大政策节点发布。文档结构分为三类：实时行情快照（含交易代码、交割品级、最新报价、成交量）、交割规则文件（含品级要求、仓储标准）、行业分析文档（含供需趋势、政策影响）。字段与单位方面，报价单位多为克、盎司，成交量与持仓量以手或千克为单位，交割品级标注为指定纯度等级，无百分比数值。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
实时行情的高频更新要求多轮对话每次调用工具时拉取最新数据源，无法依赖长期缓存的静态数据；不同贵金属品种的报价单位、交割规则差异显著，提示词需在每轮对话中明确绑定当前聚焦的具体品类，避免字段混淆；长文档如交割规则需分段召回，多轮对话需记录用户已查看的段落，避免重复推送；单位不统一的问题需要在提示词中预设单位转换规则，确保输出结果符合用户习惯的计量方式；用户常追问行情波动的原因或政策影响，多轮对话需保留上下文的时间范围与品种参数，减少重复确认。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 字符 | 贵金属行情与研报的文本长度较长，需保留足够上下文以处理多轮追问 |
| `toolCallInterval` | 15 秒 | 匹配贵金属实时行情的更新频率，避免调用过时数据 |
| `recallTopK` | 前6条 | 适配行业研报与交割文档的分段长度，优先召回与当前对话强相关的内容 |
| `promptTemplate` | 按用户指定的贵金属品种、时间范围生成尽调内容，统一输出单位为克 | 解决贵金属单位不统一的问题，明确对话聚焦的品类与参数 |
| `workflowVarPassMode` | 绑定用户输入与系统上下文 | 确保工作流能传递实时行情数据与用户追问的上下文参数 |
| `fileParseChunkSize` | 1000–1500 字符 | 适配交割文档的段落结构，避免拆分后破坏规则逻辑 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流运行后，AI对话节点返回“变量未定义”，无法获取代码运行模块的输出内容。原因是未将代码模块的输出绑定到全局变量作用域，仅在模块内部传递参数。
- 现象为升级到v4.8.10版本后，工作流无法获取系统侧传递的行情数据参数，全局变量未被识别。原因是未正确配置变量传递的绑定规则，系统参数未同步到对话上下文。
- 现象为多轮对话中，用户追问行情变化后，生成的尽调报告未包含最新数据。原因是未设置`toolCallInterval`匹配实时行情更新频率，调用了缓存的过时数据。

## 怎么确认配好了
- 发起包含具体贵金属品种与时间范围的测试对话，检查AI返回的报价单位是否符合预设规则。
- 运行工作流测试，查看代码模块的输出是否能被AI对话节点正常读取，无“变量未定义”报错。
- 触发多轮追问，检查上下文是否保留了之前提及的贵金属品种与参数，无需重复确认。
- 查看向量召回的日志，确认召回的文档条数符合`recallTopK`的配置值。
