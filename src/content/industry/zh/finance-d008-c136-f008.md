# 贵金属智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
数据主要来自上海黄金交易所、伦敦金银市场协会等官方交易平台，以及行业权威库存监测机构。更新节奏分为实时报价类数据、每日库存统计类数据两类。文档结构多为结构化表格，包含品种名称、纯度、报价、交易量、库存余量等字段，单位通常为元/克、盎司/美元、千克等。部分第三方数据源会附带交割等级、仓储地点等附加字段，需根据尽调报告的需求筛选适配字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
实时与非实时数据的更新节奏差异，要求工具调用需区分同步高频请求与异步批量拉取的配置，避免触发数据源的调用频率限制。多字段与多单位的特征，要求插件需内置精准的字段映射与单位转换逻辑，否则返回数据无法直接适配尽调报告的标准格式。多官方数据源的调用需分别配置鉴权参数，不同数据源的接口规范存在差异，需在工具编排中设置统一的数据清洗环节，确保合并后的数据一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` 或指定 `["gold_price", "silver_inventory"]` | 支持该参数的模型需具备工具调用能力，auto模式可自动选择适配的工具，指定工具列表可减少模型的决策开销 |
| `PARSE_HTTP_PLUGIN_TIMEOUT` | `10-30 秒` | 贵金属数据源的接口响应通常较快，过长超时会阻塞尽调报告生成，过短会丢失有效数据 |
| `plugin_field_mapping` | 按「报价→实时报价」「库存→期末库存」的规则配置一对一映射 | 贵金属数据字段与尽调报告的标准字段存在命名差异，精准匹配可避免数据错位 |
| `unit_conversion_switch` | `开启` | 不同数据源的单位（元/克、美元/盎司）需统一为报告要求的标准单位，否则会导致数据混乱 |
| `api_external_auth` | 为每个数据源配置独立的API_KEY与请求头 | 上海黄金交易所与伦敦金银市场协会的鉴权参数互不通用，独立配置可避免调用失败 |
| `tool_call_batch_size` | `前3条主流贵金属品种` | 尽调报告通常聚焦主流品种，过多批量会增加计算开销，过少则无法覆盖核心分析需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 配置`toolChoice`为`auto`时，日志中出现`model does not support toolChoice auto mode`的报错文案。原因是未提前确认模型是否支持自动工具选择模式，仅部分具备高级工具调用能力的模型兼容该配置。
- 发布应用后通过API调用无返回数据，API返回状态码`400 Bad Request`且字段`plugin_response`为空。原因是未在插件配置中开启外部调用权限，或未正确配置数据源的API鉴权参数。
- 工具调用的结果被直接输出，未作为上下文，大模型生成的尽调报告中未包含工具返回的结构化数据。原因是未将工具调用的结果通过上下文参数传入大模型，仅配置了工具调用但未关联到后续生成环节。

## 怎么确认配好了
- 调用测试接口，检查返回的`tool_call_results`字段是否包含贵金属报价、库存等预期数据，核对字段单位是否与报告要求一致。
- 查看插件配置页面的鉴权状态标识，确认所有数据源的鉴权参数均通过验证，无`invalid api key`类报错。
- 触发一次完整的尽调报告生成流程，检查大模型生成内容中是否引用了工具返回的结构化数据，未引用通用表述。
- 调整`tool_call_batch_size`参数后，对比不同批量下的生成结果，确认批量设置符合报告的品种覆盖需求。
