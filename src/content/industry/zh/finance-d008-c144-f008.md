# 通信服务智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
通信服务智能尽调报告的数据主要来源于金融机构自用的运营商运维监控系统、跨区域通信链路管理平台及行业合规报备数据库。数据更新节奏分为两类：实时链路状态数据（如带宽使用率、丢包率）为秒级更新，月度合规备案数据为自然月更新。文档结构包含通信链路唯一标识、节点IP地址、带宽使用率（单位Mbps）、丢包率（单位%）、服务可用率（小数形式）、合规备案编号、服务生效时间等字段，部分文档还包含跨区域链路的路由跳转日志。

## 这些特征在「工具调用与插件」这一环带来什么约束
实时秒级更新的链路数据要求工具调用支持短周期的增量拉取，避免因轮询间隔过长导致金融尽调报告的数据过时；多字段带严格单位的特性要求插件内置字段校验逻辑，防止非法数值传入导致尽调结论失真。合规备案字段需联动外部监管校验接口，因此插件需要配置独立的鉴权参数。此外，文档长度差异较大，短则数百字的合规备案说明，长则数万字的路由日志，要求工具调用支持自适应上下文截断，避免超出模型上下文上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `plugin_request_timeout` | `30 秒` | 通信服务实时链路数据的返回延迟通常在10-25秒，设置30秒可覆盖绝大多数正常请求，避免无效等待 |
| `plugin_field_validation_enable` | `开启` | 通信服务数据包含带宽、丢包率等带单位的强校验字段，开启后可自动过滤非法输入 |
| `dataset_recall_top_k` | `前 8 条` | 通信服务尽调报告的核心字段较多，召回8条可覆盖关键信息，同时避免超出模型上下文长度 |
| `plugin_api_base_url` | `按实际部署的通信数据接口地址填写` | 不同运营商的运维接口地址存在差异，需匹配对应数据源的API根路径 |
| `plugin_cron_schedule` | `*/5 * * * *` | 适配实时链路数据每5分钟刷新的需求，同时满足月度合规数据的定期同步 |
| `plugin_max_retries` | `2 次` | 通信链路偶发抖动会导致请求失败，重试2次可提升成功率，且不会过度占用接口资源 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用通信服务插件后返回`api.example.com`的无效地址，原因：未修改`plugin_api_base_url`配置项，使用了平台默认的测试地址。
- 调用`/api/core/dataset/update`接口返回500错误，原因：未在插件配置中添加数据集更新的权限校验参数，导致API鉴权失败。
- 上传通信服务运维文档后，触发部署查询时未召回目标文档，原因：未将上传的文档关联到对应插件的知识库集合，导致查询范围未覆盖目标数据。

## 怎么确认配好了
- 进入插件管理页面，查看`plugin_api_base_url`配置项，确认填写的是实际通信数据接口的根地址，不要使用默认测试地址。
- 发起一次模拟调用，传入合法的通信链路ID，检查返回结果是否包含正确的带宽、丢包率等字段，且字段单位符合预期。
- 调用`/api/core/plugin/invoke`接口，传入合法参数，检查返回的HTTP状态码为200，且无字段校验错误。
- 上传通信服务运维文档后，发起“部署流程”相关查询，确认返回结果引用了上传文档中的内容。
