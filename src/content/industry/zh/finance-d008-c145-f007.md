# 通信设备智能尽调报告的工作流编排

## 这个品类的数据长什么样
通信设备智能尽调报告的数据主要来自运营商集采公示、设备厂商官方技术白皮书、工信部通信设备入网许可公告、第三方检测机构性能测试报告及运维日志。数据更新节奏随设备固件迭代、集采批次调整，无固定周期但核心参数更新频率不低于季度一次。文档结构分为设备基础参数、接口规范、合规认证、运维指标四个模块，字段包含射频频段、传输速率、工作温度范围、入网许可编号、供应商资质文件编号等，部分字段带有专属单位。

## 这些特征在「工作流编排」这一环带来什么约束
通信设备尽调数据的多源属性要求工作流配置多源数据对齐节点，校验不同渠道参数的一致性。无固定更新周期要求工作流支持动态触发拉取，适配临时更新的集采或合规公告数据。固定的文档结构要求工作流配置结构化抽取规则，精准匹配射频频段、入网许可编号等核心字段。数值型字段的单位差异要求工作流内置单位转换逻辑，统一处理不同来源的单位格式，同时校验参数是否符合合规阈值。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 通信设备技术文档多为长篇幅，600秒可覆盖多源文档解析与参数校验全流程 |
| `recall_top_k` | 前 8 条 | 通信设备尽调需覆盖多维度参数，前8条召回可兼顾召回率与处理效率 |
| `similarity_threshold` | 0.75–0.85 | 通信设备参数为标准化数值，该阈值可过滤低相关性的非官方文档，保留权威来源数据 |
| `field_mapping_rule` | 按专属字段名映射 | 统一多源数据的字段命名，避免尽调报告出现字段混乱 |
| `unit_auto_convert` | 开启，强制转换为约定标准单位 | 通信设备参数单位多样，统一单位可确保尽调数据的可对比性 |
| `workflow_node_retry_count` | 3 次 | 多源数据拉取可能出现临时网络波动，3次重试可降低流程失败率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中调用知识库时，变量引用知识库选择参数未生效，导致拉取到无关的非通信设备文档。原因：未将知识库ID配置为可被工作流变量绑定的参数，仅固定选择了单一知识库。
- 现象：与工作流对话时，所有<ai对话>节点的历史回复均被展示。原因：未配置节点输出过滤规则，默认保留了工作流内所有节点的上下文内容。
- 现象：工作流执行超时，返回状态码504。原因：未调整解析超时配置，默认时长不足以处理长篇幅的通信设备技术白皮书。

## 怎么确认配好了
- 执行单节点测试，上传一份通信设备厂商技术白皮书，核对字段提取结果是否包含预设的核心参数。
- 触发动态拉取配置，模拟发布一条新的集采公告，确认工作流自动拉取并更新对应数据。
- 调整单位转换开关，上传一份使用非标准单位的测试文档，核对输出结果是否统一为约定的标准单位。
- 运行完整工作流，核对所有节点的执行日志是否无超时或字段校验错误。
