# 通信设备智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
金融机构开展通信设备供应商尽调时，所需的数据主要来自通信设备厂商公开参数文档、运营商运维管理系统、工信部无线电发射设备备案数据库、行业集采中标公示信息。更新节奏存在差异：厂商参数文档为年度更新，运维数据为每日同步，备案数据库数据为每半年更新一次。单份尽调文档包含设备基础信息、性能参数、运维记录、合规状态四个固定模块，字段包括设备型号、唯一序列号、入网许可编号、端口数量、累计运行时长、固件版本号、合规校验状态等，其中端口数量单位为「个」，累计运行时长单位为「小时」，固件版本号为带点分隔的字符串格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
金融机构的通信设备尽调流程，因数据的多源分散、分周期更新、固定模块结构与特定字段单位，对工具调用与插件提出了特定约束。多源数据源需对接三类不同接口格式的数据源，需为每个数据源配置独立的鉴权与拉取规则。分周期更新的特性要求区分实时拉取的运维数据、定期同步的备案数据与年度更新的厂商参数，需配置不同的缓存过期时长。固定模块结构要求插件按模块拆分字段提取逻辑，避免全量解析导致的字段混乱。特定字段单位要求工具调用时增加单位校验环节，确保导入的端口数量、运行时长等数据符合预设格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_timeout` | `300 秒` | 通信设备尽调需对接多类数据源，300秒可覆盖多接口并发请求的完整耗时 |
| `plugin_cache_ttl` | 按数据源分类配置：厂商参数为`31536000 秒`，备案数据为`15768000 秒`，运维数据为`86400 秒` | 匹配通信设备数据源的不同更新节奏，避免缓存过期或冗余存储 |
| `stream_response_enabled` | `true` | 通信设备尽调报告数据量较大，流响应可分段返回结果，降低交互延迟 |
| `field_validation_required` | `true` | 通信设备字段包含固定单位格式，校验可确保导入数据的单位与预设规则一致 |
| `mcp_protocol` | `sse` | 适配通信设备数据源的实时回调需求，解决本地调用协议的局限 |
| `plugin_api_rate_limit` | `10 次/分钟` | 符合多数通信设备数据源的API访问限流规则，避免触发访问封禁 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置MCP接入方式为`npx`时，无法拉取远程通信设备数据源。原因：NPX协议仅支持本地脚本调用，无法对接远程API接口，不适用于通信设备的多源远程数据拉取需求。
- 现象：调用尽调工具时仅在请求结束后返回完整结果，未实现分段流响应。原因：未开启`stream_response_enabled`配置项，未启用流响应模式。
- 现象：无法将上一次尽调的合规状态作为下一次工具调用的提示词。原因：未配置插件的上下文传递规则，未将历史工具返回结果注入当前请求的prompt中。

## 怎么确认配好了
- 进入插件管理页面，查看`mcp_protocol`配置项的取值，确认与通信设备数据源的API回调格式匹配。
- 发起一次测试调用，观察工具返回的结果是否为分段流式输出，确认流响应配置已生效。
- 导入一份模拟的通信设备运维数据，检查字段校验环节是否过滤不符合单位格式的数值，确认字段校验配置已启用。
- 查看系统运行日志，确认工具调用未触发超时错误，确认超时配置符合实际请求耗时。
