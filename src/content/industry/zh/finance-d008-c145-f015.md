# 通信设备智能尽调报告的部署与升级

## 这个品类的数据长什么样
通信设备的智能尽调数据来源包括基站、核心网、传输设备的运行日志、配置台账、年度维保报告、第三方检测证书，主要服务于金融机构的供应商尽调场景。更新节奏分为实时（告警、射频功率等运行参数）、月度（设备配置台账更新）、季度（维保记录归档）。文档结构多源异构，包含CSV格式的批量运行数据、PDF格式的纸质维保报告扫描件、JSON格式的实时告警流。字段包含设备序列号、安装位置经纬度、射频功率（单位dBm）、丢包率（%）、合同有效期限等，部分字段带有行业专属单位与格式约束。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的数据格式要求部署阶段需提前配置对应格式的解析插件，避免部分文档无法被正常读取，影响尽调报告的完整性。不同更新节奏的数据需要支持灵活的同步调度配置，既要满足实时告警的秒级同步需求，也要适配台账类数据的低频更新，避免数据延迟或冗余。通信设备字段的专属单位与格式，要求部署时配置精准的字段映射规则，防止单位转换错误导致尽调数据失真，影响金融尽调的准确性。升级阶段需兼容旧版的解析与映射规则，避免历史归档的尽调报告无法被重新生成，影响合规性。同时，通信设备数据包含位置、设备标识等敏感信息，部署时需配置数据脱敏规则，符合金融行业的数据安全监管要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 通信设备的批量运行日志与维保文档通常体积较大，解析耗时较长，避免默认超时设置中断解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 单份基站集群的运行日志包可能超过常规文档大小，需适配大文件上传需求 |
| `DATA_SYNC_INTERVAL` | `10 秒-24 小时` | 通信设备数据包含实时告警（10秒同步）、月度配置台账（24小时同步）等不同更新节奏，支持多调度配置 |
| `FIELD_MAPPING_RULE` | `按设备类型预设字段映射` | 通信设备字段包含射频功率（dBm）、丢包率（%）等行业专属单位，预设映射可避免单位转换错误 |
| `DATA_MASKING_ENABLE` | `开启` | 通信设备数据包含安装位置经纬度、设备序列号等敏感信息，开启脱敏可符合数据安全要求 |
| `MODEL_CONTEXT_WINDOW` | `8192 tokens` | 智能尽调报告需整合多源设备数据，该上下文窗口可覆盖单份核心设备文档的完整内容 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：升级后执行docker-compose启动容器，pg容器日志显示“FATAL: role "postgres" does not exist”。原因：升级时未保留原有数据库初始化脚本的默认用户配置，新容器无法识别预设的数据库角色。
- 现象：尝试连接VLLM部署的Qwen3-Embedding-8B模型时返回500错误。原因：未在FastGPT的模型配置页面正确填写VLLM的本地API地址与端口，导致无法建立模型连接。
- 现象：上传通信设备运行日志后显示解析失败，提示“请求超时”。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认的短超时设置无法适配大体积日志文件的解析流程。

## 怎么确认配好了
- 上传单份1000MB的基站运行日志文件，确认上传进度正常且无文件大小超限提示。
- 配置10秒的同步间隔后，查看实时告警数据是否在15秒内完成同步入库。
- 启动容器后查看pg容器日志，确认无“role "postgres" does not exist”报错信息。
- 生成一份测试尽调报告，检查经纬度字段是否已按规则进行脱敏处理。
