# 造纸智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
造纸智能尽调报告的数据来源包含行业协会发布的月度生产监测数据、海关总署的原木及废纸进出口统计、上市造纸企业公开的环评与产能披露文件、以及企业自主提交的月度出货报表。数据更新节奏存在差异：进出口数据按周更新，行业协会报告按季度发布，企业披露文件随财报周期更新。文档结构通常分为原料供应、生产产能、产品出货、环保指标四大板块，字段包含原木进口量（单位：立方米）、纸机设计产能（单位：吨/年）、单位产品能耗（单位：千克标准煤/吨）、COD排放浓度（单位：mg/L）等，无统一的标准化字段格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且更新节奏不同，要求工具调用链路支持同时对接多类第三方数据源插件，并配置差异化的缓存更新周期，避免拉取过时数据。文档篇幅较长且结构不统一，要求工具调用前需对长文本进行分块处理，同时限制单轮工具调用的上下文长度，防止超出模型处理上限。字段单位与统计口径存在差异，要求工具调用模块需内置单位转换与口径对齐逻辑，避免因数据格式不统一导致的参数提取错误。多源数据的交叉验证需求，要求工具调用支持多轮参数校验，确保提取的造纸行业数据准确可靠。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `embedding_model` | `text-embedding-ada-002` 或本地化部署的同参数模型 | 适配造纸尽调报告的长文本向量提取需求，保障原料、产能等核心字段的识别精度 |
| `custom_embedding_url` | `自定义嵌入服务地址` | 绕开one API链路，直接调用专属embedding模型，适配造纸专业文本的处理需求 |
| `embedding_chunk_size` | `800–1200 字符` | 适配造纸尽调报告的分章节结构，避免分块过碎导致上下文丢失 |
| `tool_call_timeout` | `120 秒` | 适配多源插件拉取造纸原料、产能、出货数据的耗时需求，避免中途中断 |
| `enable_manual_confirm` | `当提取参数匹配度低于预设阈值时开启` | 针对造纸数据的多源字段差异，降低工具调用的误执行风险 |
| `max_tool_steps` | `6–8` | 限制造纸尽调报告的工具调用轮次，避免循环调用导致的资源消耗 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用embedding模型时返回403权限错误或请求被拦截。原因：未配置`custom_embedding_url`参数，仍通过one API链路调用，导致权限校验失败。
- 现象：工具调用提取参数后直接执行，未弹出用户确认弹窗。原因：未开启`enable_manual_confirm`配置，或触发条件设置为始终关闭，未匹配造纸数据的校验需求。
- 现象：工具调用完成后，AI自动生成的解释内容无法隐藏，导致输出冗余。原因：未关闭`show_tool_call_result`配置，或工作流中未设置结果过滤节点，未适配造纸尽调报告的精简输出需求。

## 怎么确认配好了
- 上传单份造纸尽调报告的样本文档，查看向量分块的长度是否符合配置的`embedding_chunk_size`范围。
- 触发工具调用流程，核对是否在参数匹配度未达预设阈值时弹出确认弹窗。
- 检查工具调用日志，确认embedding模型请求直接指向自定义地址，未经过one API链路。
- 运行完整工作流，验证仅最后一个步骤的结果被输出，中间步骤的处理结果未展示。
