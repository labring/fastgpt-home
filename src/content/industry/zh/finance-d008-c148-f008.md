# 酒店餐饮智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
酒店餐饮尽调的数据主要来自四类渠道：门店经营证照（营业执照、食品经营许可证）、线上平台经营数据（美团、大众点评的到店消费记录）、线下供应链凭证（食材采购发票、供应商对账单）、内部管理报表（单店营收明细、人力成本台账）。数据更新节奏差异明显：线上经营数据每日更新，供应链凭证按月归档，资质文件每年年检更新。文档结构包含结构化报表与非结构化凭证两类，结构化字段包含单店日均营收（单位：元）、卫生评级（等级型）、租赁合同到期日（日期型），非结构化文档多为PDF格式的发票扫描件与纸质凭证扫描件。

## 这些特征在「工具调用与插件」这一环带来什么约束
酒店餐饮尽调的数据特征对工具调用与插件环节带来多重约束。多源数据的混合调用要求工具链同时支持结构化数据库查询与非结构化文档解析，需分别配置对应插件的权限与超时参数。不同更新节奏的数据需要分批次触发工具调用，避免因混合实时与离线数据导致的结果不一致。字段与单位的特异性要求工具调用的参数校验逻辑匹配品类专属字段，例如需校验数值类字段的单位与范围。单店经营明细的条目较多，单次工具调用返回的结果量可能超出大模型上下文承载上限，需配置分页查询与结果截断规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `function_call_max_tokens` | `8000–12000` | 酒店餐饮尽调的结构化数据字段多、原文片段长，需足够token容纳查询结果与原始数据 |
| `plugin_request_timeout` | `900 秒` | 批量拉取供应链数据与跨平台经营数据时，单请求耗时可能超过默认阈值 |
| `mysql_query_max_rows` | `500–1000` | 单店营收明细通常包含数百条记录，超出该范围会导致结果截断 |
| `rag_recall_top_k` | `前3–5条` | 尽调报告需精准引用原文片段，过多召回结果会干扰大模型的总结逻辑 |
| `parse_file_chunk_size` | `1500–2000 字符` | 酒店餐饮的采购凭证PDF通常包含长段落，分块过短会破坏上下文连贯性 |
| `api_auth_key_scope` | `按工作流绑定专属权限` | 避免通用KEY导致跨项目的数据访问风险，匹配尽调项目的权限隔离需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用MySQL数据库后，返回结果仅包含汇总数据，无原始字段片段。原因：未开启`function_call_return_raw_data`参数，或未关联rag召回逻辑绑定数据库查询结果。
- 工作流执行超时，界面返回`504 Gateway Timeout`错误。原因：未调整`plugin_request_timeout`参数，默认配置无法支撑批量供应链数据的拉取操作。
- 鉴权失败，接口返回`401 Unauthorized`。原因：使用通用KEY绑定工具插件，未按项目隔离权限范围，导致跨项目数据访问被拦截。

## 怎么确认配好了
- 执行测试工作流，调用MySQL查询单店营收明细，检查返回结果中是否包含原始SQL查询的字段值片段。
- 查看工作流执行日志，确认插件请求耗时未超过配置的`plugin_request_timeout`阈值。
- 检查工具插件的鉴权配置，确认未使用通用KEY，而是绑定了对应项目的专属权限范围。
- 批量拉取1000条以上的经营数据，检查返回结果的行数未超过配置的`mysql_query_max_rows`限制。
