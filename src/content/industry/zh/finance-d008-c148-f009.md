# 酒店餐饮智能尽调报告的引用来源与溯源

## 这个品类的数据长什么样
酒店餐饮类尽调数据主要来自市场监管部门公示的经营资质、第三方生活服务平台的门店经营数据、食材供应商的资质文件及门店日常运营台账。资质类数据按季度更新，平台经营数据每日同步，台账类数据由门店按月提交。单份尽调文档通常包含门店基础信息、卫生合规评级、客流波动数据、供应链合作方信息等字段，单位多采用人次/日、元/人、平方米等具象计量标识。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源分散的数据来源要求溯源标识需对应标注监管公示、第三方生活服务平台、门店运营台账三类渠道，避免溯源混淆。不同数据源的更新节奏差异，要求溯源环节需适配不同的时效校验规则，例如资质类数据需校验近季度更新记录，平台经营数据需校验近24小时内的同步状态。字段与单位的特异性要求溯源时需绑定字段名与对应计量标识，防止出现计量匹配错误。部分第三方平台数据存在版权限制，溯源需明确标注数据获取的具体节点或页面路径。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前10-15条` | 酒店餐饮尽调数据字段多且分散，需覆盖资质、运营、供应链多类信息，过多会增加上下文负担，过少则无法覆盖核心字段 |
| `相似度阈值` | `0.75-0.85` | 需区分同品类门店的相似经营数据，避免将邻近门店的客流数据误关联到目标门店，阈值过低会引入无关数据 |
| `引用内容模板` | `{{content}} （来源：{{source}}，更新时间：{{update_time}}）` | 适配多源数据的溯源标识需求，明确标注来源渠道与更新时间，符合尽调报告的合规要求 |
| `数据时效校验时长` | `资质类7天，平台类1天，台账类30天` | 匹配不同数据源的更新节奏，确保引用数据未超出合规时效范围 |
| `溯源字段绑定开关` | `开启` | 需强制绑定字段名与对应计量标识，防止出现单位匹配错误，符合酒店餐饮数据的字段特异性要求 |
| `重排返回条数` | `前5-8条` | 优先返回与目标门店强相关的溯源数据，提升尽调报告的准确性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置溯源环节时，选择变量引用无可选值。原因：未在关联的数据源节点中配置门店标识、更新时间等溯源所需变量的输出，导致变量池无对应可选项。
- 现象：线上环境运行时抛出Cannot redefine property: toString报错。原因：自定义溯源处理脚本中重复声明了toString全局方法，与平台内置的原型方法冲突。
- 现象：生成的尽调报告引用内容未标注数据来源渠道。原因：引用内容模板未配置{{source}}占位符，或未开启溯源字段绑定开关，导致无法自动关联来源信息。

## 怎么确认配好了
- 上传单份酒店餐饮门店的资质文件与经营数据，触发知识库召回，查看召回结果的来源标签是否正确匹配监管平台或第三方平台。
- 配置引用模板后，生成测试尽调报告，检查每条引用内容是否包含来源渠道与更新时间的实际填充值。
- 调整相似度阈值为0.7，测试召回结果，确认未出现非目标门店的无关经营数据。
- 触发数据时效校验规则，上传一份超过7天未更新的资质文件，确认系统会提示数据时效异常。
