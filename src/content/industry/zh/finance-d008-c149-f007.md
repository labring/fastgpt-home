# 钢铁贸易智能尽调报告的工作流编排

## 这个品类的数据长什么样
钢铁贸易智能尽调的数据来源包括购销双方的合同文件、钢厂出库单、物流运单、银行付款水单、海关报关单以及行业协会的产能流通数据。数据更新节奏分为两类：单笔贸易的单据类数据随交易流程实时上传，行业宏观数据按月度固定更新。文档结构分为四个模块：基础贸易信息模块包含合同号、购销双方主体信息；货权凭证模块包含钢材牌号、规格、净重；资金流模块包含发票信息、结算凭证；物流模块包含仓储单、运输路线。字段中钢材相关参数需使用标准牌号（如Q235、SPHC）、规格（如Φ16mm、10mm*2000mm），重量单位统一为吨。

## 这些特征在「工作流编排」这一环带来什么约束
多来源的数据要求工作流串联多个独立的数据拉取节点，分别对接合同系统、物流系统、资金系统与行业数据库，同时需要配置跨数据源的字段映射规则，解决不同系统字段名不统一的问题。实时单据的更新节奏要求工作流支持事件触发模式，确保单笔贸易的尽调报告能即时生成；月度行业数据则需要配置定时触发节点，定期同步更新报告内容。复杂的文档结构与细分的字段要求工作流增加校验节点，对钢材牌号、规格、重量单位进行合法性校验，同时校验跨模块的字段一致性，比如合同货量与物流净重的匹配度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1200 秒` | 钢铁贸易尽调单据包含多份附件，解析耗时高于通用场景 |
| `WORKFLOW_TRIGGER_MODE` | `事件触发+定时触发` | 兼顾实时上传的单笔贸易单据与月度更新的行业数据 |
| `FIELD_MAPPING_RULE` | `按单据类型映射+手动补全` | 不同来源单据字段名不统一，如出库单「净重」对应合同「货量」 |
| `DATA_VALIDATION_RULE` | `单位校验+跨字段一致性校验` | 钢铁贸易重量单位多为吨，需校验跨数据源的货量匹配 |
| `IMAGE_DISPLAY_CONFIG` | `按URL绑定至对应货权节点渲染` | 尽调报告需展示钢材质检报告、仓储照片等图片资源 |
| `SPEECH_TO_TEXT_CONFIG` | `按音频格式自动调用对应引擎` | 部分贸易场景需处理语音形式的沟通记录，需配置语音转文字功能 |
| `PROMPT_LANG_AUTO_SWITCH` | `按请求头语言自动切换` | 适配境内外贸易双方的中英文报告需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 工作流执行返回`ETIMEDOUT`或`504 Gateway Timeout`错误。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，使用默认值导致多附件的钢铁贸易单据解析超时。
- 尽调报告中未渲染图片，或语音格式的沟通记录无法转化为文本内容。原因是未配置`IMAGE_DISPLAY_CONFIG`与`SPEECH_TO_TEXT_CONFIG`，未启用图片渲染与语音转文字功能。
- 混淆工作流与插件的使用边界，且无法实现中英文开场白自动切换。原因是未明确工作流用于串联多步骤流程、插件用于封装单一功能，且未开启`PROMPT_LANG_AUTO_SWITCH`配置。

## 怎么确认配好了
- 上传一份包含多附件的钢铁贸易出库单，检查工作流执行日志中的解析时长是否符合配置的超时阈值。
- 上传包含图片URL与语音格式的尽调素材，检查报告中是否正确渲染图片，且语音素材已转化为文本内容。
- 分别使用中文和英文请求生成报告的接口，检查返回的报告开场白是否自动匹配请求语言。
- 模拟实时上传单笔贸易单据与定时触发行业数据同步，检查工作流是否按配置的触发模式执行。
