# 铁路公路智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
铁路公路智能尽调报告的数据主要来源于交通运输主管部门的公开路网监测数据、项目竣工档案库、日常运营维护日志。更新节奏分为两类：实时路网通行数据为分钟级更新，项目竣工、合规类档案为季度或项目竣工后一次性归档更新。文档结构包含线路基础参数、运营统计、合规文件、维护记录四类核心模块，字段包含明确单位，如设计时速单位为km/h，日均通行量单位为辆/日，维护周期单位为月，无冗余或模糊字段。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
实时路网数据的分钟级更新要求HTTP接口支持低延迟高频调用，单次请求返回数据量需控制在合理范围，避免带宽过载；大体积的竣工档案文件要求接口支持分块上传或配置足够的超时与文件大小阈值；字段带明确单位的特性要求接口返回字段名与预设映射严格对齐，避免后续解析时出现单位转换错误；多数据源（如监测平台、监管系统）的对接需求，要求外部系统配置支持统一的鉴权与密钥管理机制，适配不同数据源的接入标准。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 铁路公路尽调报告常包含竣工图纸、监测报表等大文件，单文件体积通常不超过2000 MB |
| `HTTP_REQUEST_TIMEOUT` | `120 秒` | 多数交通运输外部数据源的接口响应时长在60-100秒区间，预留充足超时时间避免请求中断 |
| `API_AUTH_TYPE` | `Bearer Token` | 国内交通运输监管类公开接口普遍采用Bearer Token鉴权标准，与通用API鉴权规范对齐 |
| `PARSE_FIELD_MAPPING` | `按官方字段名映射` | 铁路公路数据字段（如`daily_traffic_volume`）需与外部接口返回字段严格匹配，避免字段错位导致解析失败 |
| `API_KEY_STORAGE_MODE` | `环境变量存储` | 避免将鉴权密钥硬编码到配置文件或界面中，提升密钥管理安全性 |
| `ASYNC_SYNC_SWITCH` | `按数据类型配置` | 实时通行数据采用同步调用，历史档案数据采用异步回调，适配不同数据的更新节奏 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
-  现象：接口返回401 Unauthorized错误，或解析后数据字段为空。原因：将通用API Key直接填入`ACCESS_TOKEN`配置项，未使用对应数据源的专属鉴权密钥。
-  现象：大文件上传失败，或解析后数据不完整。原因：未调整`UPLOAD_FILE_MAX_SIZE`与`HTTP_REQUEST_TIMEOUT`配置，超出默认阈值导致请求被截断。
-  现象：多数据源对接时出现鉴权冲突，无法正常拉取数据。原因：未采用`API_KEY_STORAGE_MODE`为环境变量存储，多套密钥混存导致调用时匹配错误。

## 怎么确认配好了
-  上传一份铁路公路项目的竣工档案PDF或图纸文件，确认上传进度正常完成且无报错，验证`UPLOAD_FILE_MAX_SIZE`配置生效。
-  调用测试用的路网监测接口，对比返回字段与预设的`PARSE_FIELD_MAPPING`规则，确认字段名称与格式完全对齐。
-  触发一次实时车流量数据的同步调用，查看接口响应时长在`HTTP_REQUEST_TIMEOUT`配置的阈值内，验证超时配置合理。
-  检查系统环境变量与配置文件，确认鉴权密钥未以明文形式暴露，验证`API_KEY_STORAGE_MODE`配置正确。
