# 铁路公路智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
金融领域铁路公路智能尽调报告所需的数据主要来自交通运输主管部门公开运维档案、项目竣工验收资料、路政日常巡检日志、沿线运营监控系统。更新节奏分为三类：线路基础信息在项目验收后归档更新，日常巡检数据每日同步，实时车流与养护状态数据每小时刷新。文档结构包含线路基础信息、养护维修记录、车流通行数据、运维成本台账四类核心模块，字段涵盖线路里程（单位：千米）、病害等级（分级标注）、日通行量（单位：辆次）、单公里养护成本（单位：元）等，部分巡检文档附带现场拍摄的高清附件。

## 这些特征在「工具调用与插件」这一环带来什么约束
针对金融尽调的多维度数据需求，线路基础信息的归档更新周期与实时运营数据的刷新周期差异较大，工具调用需区分定时批量拉取与实时增量拉取两种模式，避免冗余请求或数据滞后。多源数据的字段单位与分类标准不统一，工具入参需增加单位校验逻辑，确保不同来源的养护成本、通行量数据可统一对齐。部分竣工档案与巡检报告附带高清附件，工具调用需支持二进制数据流的传输与解析，同时需适配长文本字段的分页处理，防止单次请求超出内容长度限制。另外，跨模块数据关联需求较高，工具链需支持线路信息、车流数据与养护记录的联合查询，满足尽调报告的多维度分析要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MCP_SERVICE_TIMEOUT` | `120-180 秒` | 铁路公路的复杂跨线路事务查询通常耗时超过默认90秒阈值，适配长流程的多表关联与数据汇总 |
| `PARSE_FILE_MAX_SIZE` | `500 MB` | 部分巡检报告附带高清拍摄附件，需支持大体积文档的上传与解析 |
| `DATA_SYNC_INTERVAL` | `按业务周期标定` | 定时拉取的同步周期需匹配对应数据源的更新节奏，例如实时车流数据可设置为3600秒 |
| `TOOL_INPUT_VALIDATION` | `开启单位校验` | 不同来源的运维数据存在单位差异，需在工具调用前校验入参单位一致性 |
| `MAX_CONTEXT_LENGTH` | `8000-12000 字符` | 尽调报告需整合多模块数据，长文本上下文需适配多轮工具调用的上下文传递需求 |
| `UPLOAD_FILE_ALLOWED_TYPES` | `pdf,jpg,png,csv` | 覆盖铁路公路核心文档类型，包括竣工档案、巡检图片、运维台账 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为调用自定义MCP服务处理跨线路养护成本汇总时，返回以`MC`开头的超时错误，状态码为504。原因是系统默认MCP服务超时时间为90秒，未适配铁路公路复杂查询的耗时需求。
- 现象为工具调用返回的通行量数据字段为空或单位不一致。原因是未开启`TOOL_INPUT_VALIDATION`配置，未对不同来源的字段单位进行对齐校验。
- 现象为大体积巡检PDF无法被工具正常解析。原因是`PARSE_FILE_MAX_SIZE`配置值过小，未适配高清附件的体积要求。

## 怎么确认配好了
- 调用测试接口`/api/core/chat/chatTest`，传入铁路公路线路查询的测试参数，查看工具调用返回的超时状态，确认超时时间配置符合业务需求。
- 上传单份超出默认体积的巡检文档，验证工具是否能正常解析并关联至对应线路数据，确认附件解析配置生效。
- 配置多源MCP服务拉取不同周期的数据，查看数据同步日志，确认定时与实时拉取的配置逻辑正确。
- 传入包含不同单位的字段参数，查看工具是否触发单位校验逻辑，确认输入校验配置生效。
