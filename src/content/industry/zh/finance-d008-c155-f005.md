# 饲料智能尽调报告的多轮对话与提示词

## 这个品类的数据长什么样
饲料尽调数据来源包括饲料原料采购台账、养殖端饲喂记录、第三方原料检测报告及行业流通监测数据。采购台账与饲喂记录为结构化Excel格式，包含原料名称、批次号、采购/饲喂日期、供应商信息等字段；检测报告多为多页PDF格式，包含粗蛋白、水分、重金属等指标的实测数值。数据更新节奏不一：采购与饲喂数据每日更新，检测报告随原料批次出具，行业流通数据每周更新。指标数值的单位包括克每千克、毫克每千克，部分台账会使用简化标注方式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
饲料数据的多源分散特性要求多轮对话需先引导用户明确数据源类型，避免混合解析结构化与非结构化文件导致的字段错位。单位多样的特征要求提示词必须明确统一的单位转换规则，否则模型易出现不同批次指标单位混淆的问题。更新节奏差异要求对话需先确认数据的时间范围，避免使用过期的检测报告与实时采购数据混合生成尽调内容。文档格式多样的特征要求配置中需指定不同文件类型的解析规则，确保Excel台账的列映射与PDF检测报告的关键词提取位置准确。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 字符 | 饲料尽调需关联多批次原料数据与多份检测报告，过长上下文易导致模型遗忘关键批次参数 |
| `systemPrompt` | 固定要求所有数值统一转换为克每千克或毫克每千克单位，输出前核对字段与单位匹配性 | 饲料数据单位多样，需统一格式避免尽调报告出现单位混淆 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 单批次检测报告与台账文件通常不超过200MB，预留冗余空间以兼容大型多页报告 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 大型多页饲料检测PDF解析需较长时间，避免超时中断解析流程 |
| `recallTopN` | 前6条 | 饲料尽调需关联原料采购、检测、饲喂等多维度数据，召回过少无法覆盖全量关联项 |
| `similarityThreshold` | 0.75–0.85 | 饲料原料名称与检测项相似度需较高阈值，避免匹配到无关品类的相似名称数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用对话接口上传饲料检测报告后，返回结果未包含文件解析内容。原因：未正确配置`UPLOAD_FILE_MAX_SIZE`参数，或未在请求体中携带符合要求的`file`字段。
- 现象：对话返回的尽调报告中出现单位混淆，例如同时出现克每千克与简化标注的指标数值。原因：未在`systemPrompt`中明确单位统一规则，或提示词未覆盖多批次数据的单位校验。
- 现象：调用对话接口时返回401状态码。原因：未正确获取并携带应用的`appId`与`apiKey`，或密钥已过期失效。

## 怎么确认配好了
- 上传单份饲料检测报告PDF，查看解析后的字段列表，确认包含原料名称、批次号、各项指标的数值与对应单位。
- 发起两轮对话，先询问某一批次的粗蛋白含量，再询问另一批次的水分含量，确认模型能区分不同批次的数据，不出现单位混淆。
- 调用对话接口，携带正确的`appId`与`apiKey`，上传饲料台账Excel文件，检查返回结果是否包含文件中的关键数据。
- 调整`recallTopN`参数，测试召回不同条数的关联数据，确认能覆盖尽调所需的全部维度。
