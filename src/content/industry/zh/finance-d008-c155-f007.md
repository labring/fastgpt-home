# 饲料智能尽调报告的工作流编排

## 这个品类的数据长什么样
饲料智能尽调的数据来源包括饲料生产企业的生产管理系统、第三方农牧检测机构的化验报告、畜牧养殖端的投喂记录、行业协会的供应链报备数据。数据更新节奏随来源类型区分：生产台账数据随每日生产批次生成更新，质检报告随送检批次完成后更新，行业统计数据按月度发布。文档结构分为两类：结构化的Excel/CSV格式的采购与生产台账，包含批次号、原料名称、供应商信息等字段；PDF格式的质检报告，包含原料配比、营养成分含量、生产工艺参数等内容。字段单位多为克每千克、毫克每千克，部分工艺参数以数值形式记录。字段包括生产批次号、原料采购批次、供应商统一社会信用代码、粗蛋白浓度、粗纤维含量、生产时间、检测日期等。

## 这些特征在「工作流编排」这一环带来什么约束
饲料品类的数据特征对工作流编排带来多维度约束。首先，多源异构的数据格式要求工作流配置字段映射规则，将不同系统返回的供应商名称、批次号等字段统一对齐，避免跨数据源的数据错位。其次，不同来源的数据更新节奏差异，要求工作流设置分层触发逻辑，例如仅当生产台账与质检报告均完成更新后，才启动尽调报告生成流程，避免数据不全导致的尽调偏差。第三，饲料尽调需关联全供应链数据，包括原料采购、生产、质检等环节，要求工作流配置关联查询节点，通过生产批次号作为唯一关联键，串联不同数据源的信息。第四，质检报告多为长文本内容，要求工作流配置文档分段与上下文拼接规则，适配大模型的上下文窗口限制，避免专业检测字段被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_DOC_SPLIT_SIZE` | 800–1200 字符 | 饲料质检报告多为长文本，单段长度适配大模型上下文窗口，避免截断专业检测字段 |
| `trigger_type` | 按结构化数据上传触发 | 饲料生产数据多通过ERP接口或Excel批量上传，按数据上传触发可精准绑定批次ID，避免无效触发 |
| `field_mapping_strategy` | 按批次ID+供应商名称双字段匹配 | 饲料供应链数据存在简称/全称差异，双字段匹配可降低跨数据源的映射误差 |
| `parallel_tool_max` | 2 次 | 饲料尽调需调用多个供应商资质查询接口，限制并发数量可避免接口限流，同时减少重复查询 |
| `llm_system_prompt` | 饲料尽调专属提示词模板 | 需校验粗蛋白浓度、钙磷比等专业指标，专属模板可提升专业字段识别与合规性校验的准确率 |
| `workflow_associate_key` | `production_batch_no` | 饲料生产以批次为核心管理单元，通过该字段关联原料、生产、质检全链路数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置工具调用节点时返回HTTP 400错误，工作流执行中断。原因：未正确传入饲料批次ID作为接口请求参数，或未将检测数据的字段格式转换为接口要求的类型。
- 现象：AI对话节点返回空结果或报错，工作流直接终止且无异常日志。原因：未配置`error_handling_strategy`参数，未设置空结果的 fallback 逻辑，未绑定备用数据查询工具。
- 现象：多工具节点同时触发，导致饲料供应商数据查询重复，尽调报告出现重复条目。原因：未设置工具调用的串行执行规则，未配置`parallel_tool_max`参数限制并发数量。

## 怎么确认配好了
- 上传一份测试用的饲料生产日志与质检报告，查看工作流触发状态是否与配置的`trigger_type`一致。
- 进入工作流日志面板，检查多源数据的字段映射是否符合预设的`field_mapping_strategy`规则。
- 模拟AI节点返回空结果的场景，验证是否触发预设的 fallback 逻辑并生成替代内容。
- 配置多工具调用节点，查看并发执行数量是否符合预设的`parallel_tool_max`参数限制。
