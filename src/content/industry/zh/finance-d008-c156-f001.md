# 黑色家电智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
黑色家电智能尽调数据的来源包含国家家电能效公共服务平台、3C认证查询系统、品牌方公开产品库及供应链管理系统。合规类字段如3C证书号、能效等级随认证变更更新，产品基础参数随新品上线更新，月度销售数据按月同步更新。单条尽调数据包含产品标识、合规校验、供应链关联三类结构化字段，字段包括`product_model`、`3c_cert_id`、`energy_efficiency_level`、`supplier_registration_code`、`monthly_sales_volume`，其中能效等级为枚举编号，销售数量为整数，证书号为字符串格式。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
合规类数据更新无固定周期，仅在认证变更时触发，因此HTTP接口需支持按`3c_cert_id`或`product_model`的增量查询，降低接口调用频次。数据来源包含三类不同系统，外部系统对接需配置多端点路由，分别对应不同字段集的拉取逻辑。部分字段为月度更新的结构化数据，接口需支持时间范围参数，确保数据时间维度对齐。字段包含枚举、整数、字符串多种类型，接口需配置严格的参数校验规则，拦截无效请求。同时，黑色家电型号较多，单批次返回数据量可能较大，需支持分页查询逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `external_api_endpoint` | `["https://energy.efficiency.gov.cn/api/v1", "https://3c-cert.gov.cn/api/v2", "https://supplier-scm.com/api/v1"]` | 对接三类数据源的官方接口地址，覆盖合规、认证、供应链全量尽调数据 |
| `api_request_timeout` | `30 秒` | 黑色家电合规接口的响应延迟通常在10-25秒区间，30秒可覆盖大部分正常请求 |
| `incremental_sync_cursor` | `last_update_time` | 合规类数据以更新时间作为增量拉取的唯一标识，符合各数据源的接口设计逻辑 |
| `response_field_whitelist` | `["product_model", "3c_cert_id", "energy_efficiency_level", "monthly_sales_volume"]` | 仅保留尽调报告必需的字段，减少数据传输量与处理开销 |
| `page_size` | `50 条` | 单批次返回数据量适中，避免接口超时或内存溢出 |
| `auth_type` | `api_key` | 大部分家电行业外部接口采用API密钥鉴权，符合通用对接规范 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：接口返回`413 Request Entity Too Large`错误。原因：未配置`response_field_whitelist`，拉取了数据源中冗余的非必需字段，导致返回体超出接口大小限制。
- 现象：尽调报告中出现重复的产品数据。原因：未使用`last_update_time`作为增量拉取游标，而是全量拉取所有数据，未过滤已同步过的旧记录。
- 现象：接口返回`400 Bad Request`，提示字段格式错误。原因：未配置参数校验规则，传入了超出枚举范围的能效等级值，不符合数据源的接口要求。

## 怎么确认配好了
- 发起单次接口请求，校验返回字段是否与`response_field_whitelist`配置的列表完全匹配。
- 配置增量拉取的游标参数，发起请求后确认仅返回该游标标记的时间范围内更新的数据。
- 使用不符合鉴权规则的凭证发起请求，确认返回对应鉴权失败的错误码。
- 发起批量请求，确认返回数据的分页逻辑符合接口设计，无超量返回的情况。
