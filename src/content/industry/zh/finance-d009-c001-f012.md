# IT 服务研报检索的模型接入与配置

## 这个品类的数据长什么样
IT服务领域的研报主要来源于行业咨询机构、技术厂商公开报告、行业协会统计数据及上市公司披露文件。更新节奏随行业事件波动，常规技术赛道研报按月或季度更新，重大技术迭代或政策发布时会追加临时报告。文档多为长文本结构，包含发布机构标识、发布时间、行业分类、核心趋势分析、量化数据、厂商对比及风险提示等字段，量化数据多附带万台、亿元等标准单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
IT服务研报的长文本特征要求模型接入时配置适配长上下文的窗口参数，避免截断核心分析内容。多字段及量化数据的结构，要求配置召回阶段的字段权重参数，优先召回核心趋势与量化数据模块。随行业事件波动的更新节奏，要求配置增量同步的触发规则，避免全量重复拉取浪费资源。多来源的研报格式差异，要求配置格式适配的预处理参数，统一文本结构后再接入模型。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8192–32768 令牌` | IT服务研报多为长文本，需覆盖完整章节避免核心分析被截断 |
| `recallTopK` | `前10–20条` | IT服务研报涉及多细分赛道，需召回足够模块覆盖核心趋势与量化数据 |
| `chunkSize` | `1024–2048 字符` | 适配研报中紧凑的技术段落与量化数据，平衡语义完整性与召回精度 |
| `chunkOverlap` | `128–256 字符` | 保留跨段落的技术术语连贯性，避免分段破坏语义完整性 |
| `multiApiKeyConfig` | `按业务模型分组配置` | 支持按不同模型组合分配API密钥，规避单密钥调用限额 |
| `ollamaBaseUrl` | `http://localhost:11434/v1` | 适配本地部署的开源模型，匹配官方接口格式 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 点击模型测试返回`status code 404`报错，原因是未正确填写`ollamaBaseUrl`的完整接口路径，或本地部署的ollama服务未完成端口映射。
- docker-compose.yml中配置多CHAT_API_KEY后，模型调用仍触发单密钥调用限额，原因是未按渠道分组配置密钥映射，仅加载了默认单密钥项。
- 4.8.20版本后配置one-api网关时，界面测试提示配置无效，原因是未在FastGPT页面配置区填写网关地址与密钥，仍依赖旧版的本地config文件配置。

## 怎么确认配好了
- 上传单份IT服务研报，核对召回的文本片段是否覆盖核心分析模块，调整召回参数至匹配业务需求。
- 发起多模型并行测试，确认不同API密钥可轮换调用，无单密钥限额触发的报错。
- 配置one-api网关后，查看模型调用日志，确认请求路由至指定网关地址。
- 测试长文本研报的分段处理，确认无关键技术术语被截断，分段保留语义连贯性。
