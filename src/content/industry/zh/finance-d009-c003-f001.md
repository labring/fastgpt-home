# 专业连锁研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
专业连锁研报的数据来源包括金融领域零售行业细分研报、行业协会发布的连锁零售业态分析文档、连锁品牌公开的季度运营公告、第三方调研机构的门店动销研报。更新节奏为每季度更新核心业态研报，月度更新单店运营细分数据。文档结构通常包含门店分布、坪效分析、供应链成本、竞品对标四个模块，字段包含门店ID、单店月营收（单位：万元）、供应链周转天数（单位：天）、竞品门店密度（单位：家/平方公里），数据格式混合结构化表格与半结构化分析文本。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
多源混合的数据格式要求HTTP接口支持CSV、PDF等多种文档解析配置，避免部分门店运营数据无法被正确提取。月度/季度的更新节奏要求接口支持定时同步参数，适配连锁品牌的数据更新周期。精准的字段维度要求接口支持按门店ID、时间范围等条件筛选，保证返回数据与业务需求匹配。单篇研报的篇幅较长，要求接口支持分页召回机制，避免单次返回数据过载影响外部系统性能。对接金融领域的投研系统时，接口需兼容租户鉴权参数，保证数据访问权限的合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 专业连锁研报单篇文档常包含多门店的季度数据，解析耗时较长，需延长超时时间避免解析中断 |
| `maxContext` | 8000–12000 字符 | 研报包含多维度业务字段，需足够上下文长度保留完整的门店运营与分析数据 |
| `召回条数` | 前 8 条 | 专业连锁研报的核心业务维度集中，无需过多召回结果即可覆盖日常检索需求 |
| `相似度阈值` | 0.75–0.85 | 区分门店精准运营数据与通用零售泛研报，避免召回无关的行业通用内容 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 单篇连锁研报可能包含多门店的季度汇总数据，需支持大文件上传 |
| `sync_interval` | 3600 秒 | 月度更新的门店细分数据需定时同步，按小时间隔拉取保证数据时效性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用HTTP接口返回413 Request Entity Too Large错误。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，未适配专业连锁研报的大文件体积要求。
- 现象：连续调用问答接口时，第二个问题无法关联前序指定的门店筛选条件。原因：未启用上下文传递配置，或`maxContext`设置过小导致门店筛选参数被截断。
- 现象：接口返回的坪效数据单位不一致。原因：未配置统一的字段映射规则，导致从不同来源拉取的研报数据单位未对齐，影响外部系统的数据分析。

## 怎么确认配好了
- 发起单篇研报的解析请求，检查接口返回的解析状态为成功，且返回的字段包含预设的门店ID、坪效等业务维度。
- 发起连续两次问答请求，携带门店筛选参数，检查第二次请求的返回结果包含第一次请求指定的门店相关数据。
- 上传单篇符合配置上限的研报文件，检查接口返回的上传状态为成功，且文件解析进度正常更新。
- 调用接口触发异常请求，检查外部日志系统中能捕获到对应的报错信息与完整请求参数。
