# 光模块研报检索的文档解析与分块

## 这个品类的数据长什么样
光模块研报的数据源主要包括券商通信行业研究所报告、金融机构行业配置研报、通信行业协会公开统计文档、光模块供应链厂商的技术白皮书。更新节奏以季度行业研报、半年度供需报告为主，伴随新品发布时会有临时技术文档。文档结构通常包含参数摘要、核心指标表格、下游应用分析、价格走势章节，核心字段包括传输速率（单位Gbps）、封装形式、功耗（单位W）、波长（单位nm）、市场规模等，部分文档会附带链路计算公式与图表。

## 这些特征在「文档解析与分块」这一环带来什么约束
光模块研报的表格与精准数值占比高，要求解析环节需完整保留表格结构与字段对应关系，避免拆分参数与单位的绑定内容。文档中包含的技术公式需要准确解析，否则会丢失链路计算的核心逻辑。多份研报的参数分散在不同章节，分块时需保留上下文关联，避免割裂跨段落的参数说明。大型研报合集的文件体积与页数较多，解析环节需适配更长的处理耗时与上传限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_TABLE_ENABLE` | 开启 | 光模块研报包含大量参数对比表格，需保留表格结构与字段对应关系 |
| `CHUNK_MAX_SIZE` | 800–1200 字符 | 光模块参数多为精准数值与单位绑定，分块过长会割裂参数关联，同时适配检索上下文长度 |
| `PARSE_FORMULA_ENABLE` | 开启 | 部分研报包含光模块链路损耗、带宽计算的公式，需准确解析公式内容 |
| `DOC_SPLIT_BY_FILE` | 开启 | 多份光模块研报上传时，需按单份文档划分分块边界，避免跨文档的内容混淆 |
| `RECALL_CHUNK_TOP_K` | 前 6–8 条 | 光模块研报的核心参数分散在不同章节，需召回足够上下文以关联完整信息 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 大型光模块行业研报合集可能包含多页图表与嵌套表格，需适配解析耗时 |
| `UPLOAD_FILE_MAX_SIZE` | 200 MB | 单份光模块供应链研报合集的文件体积通常较大，需放宽上传限制 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传光模块研报后，部分关键词无法召回，新建知识库后可正常召回。原因：首次上传时未开启`PARSE_TABLE_ENABLE`，导致研报中的参数表格未被正确解析，无法生成有效分块。
- 现象：多份光模块研报上传后，无法按单份文档分别提取参数信息。原因：未开启`DOC_SPLIT_BY_FILE`配置，导致所有文档被合并分块，丢失单份文档的上下文边界。
- 现象：上传光模块研报后，问答时无法准确返回参数数值。原因：分块时`CHUNK_MAX_SIZE`设置过大，将不同参数的分块合并，导致检索时无法精准匹配目标参数。

## 怎么确认配好了
- 上传一份小型光模块研报PDF，查看解析后的分块列表，确认表格与公式内容被完整提取。
- 输入光模块核心参数关键词，检索分块结果，确认召回的分块包含完整的参数与上下文关联。
- 上传多份光模块研报，查看分块列表，确认每份文档的分块被单独划分边界。
- 上传体积较大的研报合集，确认上传与解析流程未出现超时类报错。
