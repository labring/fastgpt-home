# 免税研报检索的工具调用与插件

## 这个品类的数据长什么样
免税研报的数据主要来自券商研究所的行业跟踪报告、免税运营商公开披露的运营公告、行业协会的月度统计数据、海关及文旅部门的政策文件。更新节奏无固定周期，随政策调整、季度财报发布、行业重大活动实时更新。文档结构包含结构化的运营数据表格、非结构化的政策解读文本，以及离岛免税、市内免税等细分品类的专项分析。字段涵盖政策生效时间、客流人次、销售额、客单价、免税额度等，单位包含万人次、亿元、元等。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散要求工具调用支持多数据源聚合配置，避免单一数据源的信息缺失。更新节奏不固定要求插件支持增量更新触发机制，确保检索到的研报为最新内容。文档同时包含结构化与非结构化内容，要求工具调用区分解析模式，对结构化数据提取指定字段，对非结构化文本进行全文召回。免税政策具有地域性与时效性，要求插件支持按地域、政策生效时间过滤检索结果，提升匹配精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `ragRecallTopK` | `前10-15条` | 免税研报包含多维度细分内容，过多召回会超出上下文窗口限制，过少会遗漏专项政策与运营数据 |
| `chunkSize` | `800-1200字符` | 免税研报的专业分析段落较长，分段过短会割裂政策逻辑，过长会影响关键词召回精度 |
| `pluginTriggerThreshold` | `0.75-0.85` | 免税研报包含大量专业术语与行业专属表述，阈值过低会引入无关通用行业文本，过高会遗漏细分政策相关内容 |
| `apiChatIdTransmit` | `始终传递` | 跨会话的研报检索需要保留上下文关联，确保工具调用的连贯性与一致性 |
| `pluginExecutionTimeout` | `300秒` | 多源研报聚合需要调用多个数据源接口，超时过短会中断有效检索流程 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
-  现象：调用工具后，对话详情页仅显示最终回复，未展示插件调用的参数与返回结果。原因：未开启`pluginLogEnable`配置项，导致系统未留存工具调用的完整链路日志。
-  现象：跨会话调用同一研报检索工具时，无法关联之前的检索上下文，返回结果出现重复或偏差。原因：未将`apiChatIdTransmit`配置为始终传递，导致会话标识未被正确携带。
-  现象：部署自定义Python插件后，调用接口返回`400 Bad Request`错误码。原因：未在插件配置中正确指定Python脚本的入口函数与依赖包版本，导致执行环境无法匹配预期要求。

## 怎么确认配好了
-  进入应用的配置页面，查看`pluginLogEnable`是否已开启，发起一次工具调用，查看对话详情是否展示插件调用的完整参数与返回日志。
-  调用工具时携带自定义chatId参数，发起两次同主题的检索，检查第二次检索是否能关联第一次的上下文，验证会话传递是否生效。
-  上传一份测试用的免税研报文档，查看解析后的字段是否包含政策解读、客流数据等预设内容，确认解析模式配置正确。
-  触发插件执行，查看任务状态是否在`300秒`内完成，无超时报错，确认超时配置合理。
