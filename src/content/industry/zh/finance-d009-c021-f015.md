# 其他综合研报检索的部署与升级

## 这个品类的数据长什么样
该品类的数据来源包含公开行业数据库、合规爬虫获取的公开研报站点、用户自主上传的本地文档。更新节奏因来源差异较大，公开研报按发布周期更新，用户上传文档无固定更新节奏。文档结构包含标题、正文段落、发布机构标识、发布时间戳、分类标签、内嵌数据表格字段，字段无统一强制格式，部分文档包含附件链接，数据计量单元包含万元、页、字符等无统一标准。

## 这些特征在「部署与升级」这一环带来什么约束
多数据源接入的权限校验需求随来源变化，部署时需支持配置不同数据源的API密钥、爬虫请求头与访问白名单。非统一的文档结构要求提前配置自定义解析模板，适配不同格式研报的字段提取规则。更新节奏的灵活性要求支持自定义增量同步调度周期，避免固定周期无法适配零散的用户上传文档。长篇研报的体积与解析耗时要求调整文件解析的超时与线程池参数，避免大文件解析失败。版本升级时需兼容旧版解析规则，防止破坏已建立的向量索引。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_DOC_MAX_SIZE` | `2000 MB` | 适配长篇研报PDF、带多表格的Word文档的体积上限，避免大文件解析失败 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 长篇研报解析耗时较长，默认超时时间不足，延长至15分钟保障完整解析 |
| `RECALL_TOP_K` | `前 10–15 条` | 研报内容体量较大，需召回足够数量的上下文片段覆盖核心论点 |
| `SYNC_INCREMENTAL_INTERVAL` | `每小时` | 适配公开研报的实时更新节奏，平衡索引更新开销与数据新鲜度 |
| `UPLOAD_ALLOWED_EXTENSIONS` | `pdf, docx, xlsx, md` | 覆盖研报常见的发布格式，排除非合规格式的上传 |
| `UPLOAD_FILE_STORAGE_PATH` | `/data/fastgpt/uploads` | 指定私有化部署下的本地存储目录，明确文件存放位置 |
| `EMBEDDING_MODEL_BATCH_SIZE` | `32` | 平衡研报段落嵌入的速度与内存占用，避免批量处理时内存溢出 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：启动后出现`permission denied while trying to connect to`报错，无法连接外部模型服务。原因：部署时未配置容器挂载的本地模型目录权限，或未开放对应端口的防火墙规则，导致服务进程无法访问模型实例。
- 现象：无法找到上传研报的本地存储路径，或误判文件上传至公网。原因：未配置`UPLOAD_FILE_STORAGE_PATH`指定本地存储目录，默认路径未被明确标注，导致无法直接定位文件位置。
- 现象：增量同步任务频繁超时中断。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`适配长篇研报的解析耗时，默认超时时间不足以完成完整解析。

## 怎么确认配好了
- 执行本地文件上传测试，上传一份合规格式的研报文档，确认上传后在文档管理界面显示正常，无解析失败提示。
- 配置自定义增量同步任务，设置短周期调度，查看同步日志确认任务正常触发且无权限报错。
- 发起检索测试，输入研报内的核心关键词，确认召回结果包含对应文档片段，且数量符合配置的`RECALL_TOP_K`取值。
- 查看服务监控面板，确认模型嵌入、向量检索的内存与CPU占用未超出预设阈值，无内存溢出报错。
