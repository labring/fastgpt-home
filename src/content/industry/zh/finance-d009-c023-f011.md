# 军工电子研报检索的文档解析与分块

## 这个品类的数据长什么样
军工电子研报的数据来源包括公开券商行业研报、军工行业协会月度简报、军工上市企业定期报告、国防军工领域专项白皮书，多为金融投资领域从业者关注的行业分析文档。更新节奏随行业事件、财报节点灵活调整，券商研报多随订单公布、技术展会发布，行业简报按月更新，白皮书按年度迭代。文档多包含结构化数据表格与段落式分析，部分涉及技术参数细节，字段涵盖细分产品型号、营收占比、单位成本、订单交付周期，单位多为亿元、台套、GHz、kW。

## 这些特征在「文档解析与分块」这一环带来什么约束
军工电子研报的结构化表格占比高，解析时需准确匹配单元格数据与对应分析段落，避免拆分后数据与投资逻辑脱节；技术参数字段包含多类单位，需适配单位归一化处理，确保检索时参数口径统一，支撑投资决策的准确性；单篇文档篇幅跨度大，从数页简报到数十页深度报告，分块需保留技术分析的上下文关联，避免割裂专业逻辑；公开渠道的研报排版格式差异明显，批量解析时需兼容不同页眉页脚、表格嵌套的文档结构。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_TABLE_ENABLE` | `开启` | 军工电子研报包含大量结构化营收、订单表格，开启后可保留表格数据的结构化关联，避免拆分后数据丢失 |
| `maxChunkSize` | `800–1200 字符` | 单篇研报既有技术参数细节又有宏观分析，该区间可平衡上下文完整性与检索精度 |
| `chunkOverlap` | `150–200 字符` | 军工电子技术分析存在跨段落逻辑关联，重叠区间可保留参数与分析的上下文衔接 |
| `OCR_LANGUAGE` | `chi_sim+eng` | 研报中包含中文技术术语与英文型号参数，需同时适配中英文识别 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 深度研报篇幅较长，需预留足够解析时间避免超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 部分批量研报合集体积较大，放宽上限以兼容全量文档上传 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：批量上传研报时，解析结果包含历史上传的非目标文档。原因：未配置单文档解析模式，默认加载全局知识库文档池进行关联解析。
- 现象：上传含技术图表的PDF后，OCR识别结果出现中文乱码。原因：未指定`OCR_LANGUAGE`为混合语言模式，仅默认单语言识别导致专业术语乱码。
- 现象：单篇PDF提问时返回无关知识库内容。原因：未开启单文档检索模式，默认召回全量知识库条目，未限定当前上传文档范围。

## 怎么确认配好了
- 上传单篇10页以内的军工电子研报，查看解析结果中的表格是否完整保留单元格关联，无错位或数据丢失。
- 查看解析日志中的`PARSE_STATUS`字段，确认无超时错误码，匹配`PARSE_FILE_TIMEOUT_SECONDS`的配置时长。
- 发起单文档提问，验证返回结果仅包含当前上传文档的内容，无其他知识库条目。
- 上传含英文型号参数的文档，核对识别出的术语是否准确，无乱码或识别偏差。
