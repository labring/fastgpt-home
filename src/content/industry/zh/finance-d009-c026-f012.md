# 出版研报检索的模型接入与配置

## 这个品类的数据长什么样
出版类研报数据主要来自专业出版机构的官方发布、行业数据库授权获取。更新节奏以定期专题研报为主，配合突发行业事件的临时研报。单篇文档结构包含发布头部、行业背景、核心数据表格、评级结论、投资建议等模块，包含研报ID、发布机构、发布日期、行业标签、目标价、营收预测等字段，目标价单位多为人民币元/股，营收预测单位多为亿元。

## 这些特征在「模型接入与配置」这一环带来什么约束
研报的授权来源要求模型接入环节需适配专属数据权限校验逻辑，避免非授权内容被调用。固定更新节奏与突发内容并存，要求模型缓存策略需支持按发布日期动态刷新。单篇文档长度较长且包含结构化表格，要求模型上下文窗口与分段配置需适配长文本处理。多字段的结构化属性，要求召回与重排参数需精准匹配专业内容的语义关联，避免无效召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–16000 字符` | 单篇研报文本长度多在5000-12000字符，预留检索结果的拼接空间 |
| `rerankTopK` | `前3–5 条` | 研报内容专业且冗余信息较多，过多召回结果会稀释核心论点 |
| `simThreshold` | `0.75–0.85` | 研报行业标签与核心内容关联度高，阈值过低会引入无关文档，过高会遗漏相关内容 |
| `UPLOAD_FILE_TIMEOUT_SECONDS` | `300 秒` | 单篇研报PDF需解析内嵌表格与图片，解析耗时高于普通文档 |
| `MODEL_API_TIMEOUT` | `60 秒` | 研报问答需整合多段检索结果，模型推理耗时高于通用问答场景 |
| `RERANKER_MODEL_MEMORY_LIMIT` | `6G 每张卡` | 适配bge-reranker类重排模型的显存占用，避免单卡显存不足或多卡无限制占用 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用bge-reranker模型后，GPU显存快速增长至6-7G且每张卡均出现占用。原因：未配置重排模型的显存限制参数，默认将全量模型权重加载到每张可用显卡。
- 现象：接入国内模型时显示无效令牌，使用第三方接口测试工具验证接口正常。原因：未在模型接入配置中指定平台要求的API路径前缀，或未携带自定义请求头参数。
- 现象：免登访问页面中出现模型配置入口。原因：误将模型配置节点绑定到公开访问权限，未配置仅内部运维可见的访问规则。

## 怎么确认配好了
- 上传一篇测试研报，查看解析后的文本字段是否完整覆盖研报的标准模块，确认解析配置适配研报结构。
- 发起针对研报内具体内容的问答请求，查看返回结果是否准确关联对应字段与论点，核对召回与重排参数的实际效果。
- 观察GPU监控数据，确认重排模型启动后显存占用稳定在预期范围内，未出现无限制增长的情况。
- 使用伪造的无效令牌发起模型调用请求，确认系统返回对应错误提示，验证令牌校验逻辑生效。
