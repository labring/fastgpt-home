# 动力煤研报检索的文档解析与分块

## 这个品类的数据长什么样
动力煤研报的数据主要来自行业监管机构发布的供需报告、大型煤炭交易平台的实时行情、券商研究所的专项分析文档。更新节奏以周度、月度报告为主，伴随突发政策或行情变动的临时研报。文档结构包含标准化行情表格（含价格、库存、运力数据）、政策解读段落、供需平衡分析、价格走势图表。核心字段包括平仓价、坑口价、港口库存，单位多为元/吨、万吨、万吨/日。

## 这些特征在「文档解析与分块」这一环带来什么约束
动力煤研报的结构化数据占比高，且包含大量专用字段与单位，解析环节需准确识别表格与内嵌图表的结构，避免数据提取错误。长文本分析段落与短数据条目交替出现，分块时需平衡上下文完整性与召回精度，防止核心行情数据被拆分。实时更新的临时研报要求解析流程具备较高效率，避免因解析延迟影响检索时效性。此外，不同来源的研报可能存在字段单位差异，需在解析阶段完成统一适配。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_PDF_USE_MINERU` | 勾选启用 | 动力煤研报多含复杂嵌套表格与内嵌图表，MinerU可保留完整的文本层级与表格结构 |
| `chunk_size` | 800–1200 字符 | 研报既有长段逻辑分析，也有短数据条目，该区间可平衡上下文完整性与召回精度 |
| `chunk_overlap` | 100–150 字符 | 避免跨分块的关键信息断裂，适配研报中连贯的逻辑段落与关联数据 |
| `TABLE_VECTOR_ENABLE` | 勾选启用 | 动力煤研报核心决策数据多为表格形式，启用后可将表格转为结构化向量，提升检索精准度 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 单份动力煤研报多为10-30页，该时长可覆盖完整的解析与分块流程 |
| `UPLOAD_FILE_MAX_SIZE` | 50 MB | 适配单份研报合集或批量上传的文档规模，避免解析超时或资源占用过高 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：勾选`PARSE_PDF_USE_MINERU`后解析失败，返回`504 Gateway Timeout`。原因：本地部署的MinerU端口未正确映射到FastGPT容器网络，或FastGPT配置的解析API地址与实际运行端口不一致。
- 现象：解析后的研报表格字段为空，或单位未统一。原因：未启用`TABLE_VECTOR_ENABLE`，或未配置MinerU的专用字段提取规则适配动力煤的平仓价、港口库存等专属字段。
- 现象：检索核心行情数据时召回结果分散。原因：`chunk_size`设置过小，或`chunk_overlap`取值不足，导致连贯的表格与分析文本被拆分为多个独立分块。

## 怎么确认配好了
- 进入FastGPT知识库设置页面，确认`PARSE_PDF_USE_MINERU`已勾选，且解析API地址与本地部署的MinerU运行端口一致。
- 上传一份标准动力煤研报PDF，查看解析后的文本预览，确认表格结构完整，平仓价、港口库存等核心字段与对应单位被正确提取。
- 查看分块后的结果列表，确认单块长度处于`800–1200 字符`的配置区间，且表格分块未被拆分为零散文本。
- 检索研报中的特定价格数据，确认可精准召回包含该数据的分块，验证`TABLE_VECTOR_ENABLE`的生效效果。
