# 卫星通信研报检索的知识库检索与召回

## 这个品类的数据长什么样
卫星通信研报的数据主要来自卫星运营商公开技术文档、行业协会发布的通信链路分析报告、卫星轨道资源备案文件。更新随新卫星发射、频段调整、链路优化等重大事件触发，事件后1-3天内更新。文档为结构化与非结构化混合形式，包含章节式摘要、卫星轨道高度、带宽、频段等参数表格，字段含轨道高度（单位：千米）、通信带宽（单位：Mbps）、覆盖范围（单位：平方公里），单篇长度可达数万字符。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源数据的字段格式不统一，部分文档的轨道高度参数混用千米与米，需在召回前完成单位标准化处理。文档长度较长且技术细节密集，分段检索时需平衡语义完整性与上下文窗口限制。更新节奏不固定，需支持按需增量同步。特定字段的单位匹配需求强，用户查询常携带频段、带宽等单位关键词，召回逻辑需关联字段单位进行精准匹配。新发布的卫星技术数据需快速纳入召回范围，保障检索时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 卫星通信研报常包含大量星历数据、链路测试图表与原始测试报告，单文件体积较大，需适配大文件上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 长文档包含大量技术细节与表格，解析耗时较长，避免因超时导致解析失败 |
| `分段长度` | `800–1200 字符` | 卫星研报技术细节密集，分段过长会丢失局部语义关联，过短则破坏技术逻辑的完整性 |
| `召回条数` | `前 8–10 条` | 单条研报信息密度高，过多召回会超出上下文窗口限制，过少则无法覆盖相关技术参数 |
| `相似度阈值` | `0.72–0.80` | 需精准匹配技术参数与场景需求，避免低相关的通用通信文档干扰检索结果 |
| `hnsw.max_scan_tuples` | `10000` | 卫星研报数据量较大时，调整扫描元组数量平衡召回精度与检索速度，避免出现配置参数报错 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：搜索知识库时报错`invalid configuration parameter name "hnsw.max_scan_tuples"`。原因：未在对应FastGPT版本中启用HNSW索引配置项，或参数名拼写错误。
- 现象：从4.9.13升级到4.10.1后，知识库页面可见全部内容，但对话时模型提示知识库为空。原因：数据库迁移未同步向量索引配置，或向量库连接参数未完成版本适配更新。
- 现象：调用新建知识库目录的API返回400状态码。原因：请求体未携带正确的`parentId`字段，或目录名称包含非法字符。

## 怎么确认配好了
- 上传一份包含卫星轨道参数的标准研报，检查解析后的分段长度是否落在设定的`800–1200 字符`范围内。
- 发起包含具体卫星频段与带宽的查询，核对召回结果的条数与设定的`前 8–10 条`一致。
- 查看系统日志，确认无`hnsw.max_scan_tuples`相关的配置报错，向量库连接参数正常。
- 调用新建知识库目录的API，验证返回状态码为200，且目录可在知识库页面正常显示。
