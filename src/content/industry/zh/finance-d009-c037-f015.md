# 卫星通信研报检索的部署与升级

## 这个品类的数据长什么样
卫星通信研报数据主要来自卫星运营商公开运营文档、行业产业白皮书、卫星发射任务官方通报及地面站运维日志。更新节奏随内容类型不同，运营商季度报告按季度更新，发射任务通报随任务节点实时发布，运维日志每日更新。文档多包含结构化表格与图表附件，字段涵盖轨道倾角、上行带宽、覆盖区域等，部分字段带有明确单位，单篇文档篇幅跨度较大。

## 这些特征在「部署与升级」这一环带来什么约束
卫星通信研报的多结构化字段、差异化更新节奏及专业图表特征，对部署与升级环节带来多重约束。首先，多字段结构化内容要求部署时配置精准的表格解析规则，避免字段解析错位；其次，实时任务通报与季度报告的差异化更新节奏，需在部署时设置增量同步与全量同步的灵活触发机制；再者，包含轨道图、带宽曲线图等专业图表，需在部署时开启图片OCR解析功能，升级时同步适配专业图表的OCR模型；最后，专业术语的嵌入需求，要求升级时验证向量模型的专业语义召回效果。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `OCR_ENABLE` | 开启 | 卫星通信研报包含轨道热力图、带宽曲线图等专业图表，需通过OCR提取图表内文本 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单篇研报包含多结构化表格与高清图表，解析耗时高于通用文档，需延长超时时间 |
| `RECALL_TOP_N` | `前 8–12 条` | 研报内容专业且信息密度高，需召回足够数量的分段以覆盖核心检索需求 |
| `SIMILARITY_THRESHOLD` | `0.75–0.85` | 过滤低相关度的非专业内容，保留与检索关键词语义匹配度较高的研报分段 |
| `SYNC_INCREMENTAL_ENABLE` | 开启 | 部分卫星通信研报随任务节点实时更新，增量同步可避免重复解析全量文档 |
| `TEXT_SPLITTER_CHUNK_SIZE` | `800–1200 字符` | 研报包含长段落与结构化表格，分段长度适配专业术语的语义完整性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：使用`v4.13.0`版本导出的知识库备份，导入至同版本实例后，原多文件的分类关系丢失。原因：该版本的备份导出逻辑未完整打包知识库的文件关联元数据，仅生成单CSV文件存储基础内容。
- 现象：同一索引模型下，部分卫星通信研报的轨道图、带宽曲线无法被识别为文本内容。原因：未开启`OCR_ENABLE`配置，或OCR模型未适配专业图表的线条与专业标注。
- 现象：升级至`v4.15.0`及以上版本后，无法通过OneAPI对接大模型，出现`400 Bad Request`错误。原因：新版本默认启用`AiProxy`服务，需配置代理参数或关闭代理开关以兼容原有OneAPI对接方式。

## 怎么确认配好了
- 上传一篇包含专业图表的卫星通信研报，查看解析后的文本内容是否包含图表内的轨道参数、带宽数值，确认OCR功能正常生效。
- 发起一次检索请求，核对返回的结果条数是否与配置的`RECALL_TOP_N`取值一致，确认召回配置生效。
- 导入一份包含多文件分类的知识库备份，查看导入后的知识库列表是否保留原有的文件分组关系，确认备份导入逻辑正常。
- 查看实例的日志文件，确认增量同步任务未出现超时报错，确认同步机制正常运行。
