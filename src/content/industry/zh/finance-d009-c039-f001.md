# 厨卫电器研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
厨卫电器研报的数据来源包含券商家电行业研报、品牌官方技术文档、第三方检测报告。更新节奏随研报发布周期，包含季度更新的行业总量报告、月度更新的细分品类销售数据，以及新品上市时的专项文档。文档结构多为结构化参数表搭配段落分析，包含产品型号、核心性能参数、市场表现相关字段。部分字段带有明确单位，如热负荷以kW为单位、风量以m³/min为单位、终端售价以元为单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
厨卫电器研报的结构化参数多且带有明确单位，要求HTTP接口在解析上传文件时保留参数与单位的对应关系，避免字段丢失。研报更新包含突发新品专项文档，要求外部系统调用支持增量更新接口，仅同步新增或修改的内容，减少重复传输。细分品类的SKU数量较多，要求接口支持按产品型号、上市时间等字段进行过滤召回，提升检索精准度。部分文档包含跨品类对比内容，要求接口支持按行业细分维度进行数据隔离，避免无关内容混入检索结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 单份厨卫电器研报包含多页参数表与市场分析，500 MB可覆盖绝大多数单文档体积 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 结构化参数解析需处理大量表格与字段映射，耗时长于普通文本解析场景 |
| `知识库召回条数` | `前8-12条` | 厨卫电器研报的有效检索内容集中，过多召回会增加上下文长度影响响应速度 |
| `相似度阈值` | `0.75-0.85` | 需过滤跨品类家电的无关内容，保留与厨卫电器强匹配的检索结果 |
| `增量同步触发间隔` | `每24小时` | 行业研报多为日/周/月更新周期，24小时间隔可覆盖绝大多数更新节奏 |
| `csv_question_col` / `csv_answer_col` | `0` / `1` | 适配CSV格式的问答对上传，明确指定问题与答案所在列的索引 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：通过`POST /api/v1/dataset/import`接口上传的CSV格式问答对文件，检索时无法正确匹配预设问题与答案。原因：未在上传参数中指定`csv_question_col`为0、`csv_answer_col`为1，默认解析规则可能按行拆分内容，不按列映射。
- 现象：批量上传厨卫电器研报的QA拆分文件后，索引构建耗时超出预期。原因：未启用结构化解析模式，或未配置增量同步接口，每次全量上传重复处理已索引的历史内容。
- 现象：使用`POST /api/v1/workflow/run`调用嵌套知识库的工作流，返回结果为空值。原因：使用v4.8.10及以上版本时，未在工作流配置中开启API调用返回上下文，或知识库相似度阈值设置过高过滤了有效内容。

## 怎么确认配好了
- 调用`GET /api/v1/dataset/{id}/info`接口，检查返回的`parse_mode`字段为`structured`，确认解析模式配置正确。
- 上传一份测试用的厨卫电器研报CSV文件，调用知识库检索接口，验证返回结果中包含预设的问答对内容，确认列映射参数生效。
- 发起增量同步请求，核对外部系统返回的新增文档数量与实际更新的研报数量一致，确认增量同步配置正确。
- 调用工作流API，传入包含厨卫电器核心参数的查询，检查返回结果包含非空的`answer`字段，确认工作流与知识库的关联配置正确。
