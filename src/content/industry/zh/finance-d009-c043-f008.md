# 商业地产研报检索的工具调用与插件

## 这个品类的数据长什么样
商业地产研报的数据主要来自商圈运营监测平台、房企商业板块财报、行业协会调研数据及物业运营后台。更新节奏分为定期与实时两类：定期报告以月度、季度为周期发布固定时段的租金、空置率数据，实时报告则同步商圈异动、租户调整等突发信息。文档结构多包含商圈基础信息、核心运营指标、租户结构分析三个模块，字段多带有明确单位，例如「商铺租金单价（元/㎡/天）」「商圈日均客流人次」「项目空置率（%）」，部分长文档会拆分出单项目、单商圈的细分数据子页。

## 这些特征在「工具调用与插件」这一环带来什么约束
商业地产研报的细分字段与单位要求，要求工具调用时必须精准匹配参数的单位与维度，避免因单位混淆导致数据解析错误。定期与实时结合的更新节奏，需要工具支持增量拉取与即时触发两种调用模式，无法仅依赖全量知识库同步。长文档与细分字段的组合，要求工具调用时需支持按指定字段过滤召回内容，同时需控制单批次解析的内容长度，避免超出模型上下文限制。此外，商业地产研报的数据源多为垂直领域接口，需配置专属的认证与路由规则，无法直接复用通用知识库的插件配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_timeout` | `120 秒` | 商业地产研报数据量较大，解析与接口响应需要更长的等待时间 |
| `rerank_top_n` | `前 8–12 条` | 商业地产研报包含多组细分指标，需足够的召回量覆盖核心查询维度 |
| `tool_param_schema` | `包含「商圈名称」「指标类型」「时间范围」三个必填字段` | 商业地产研报的核心查询维度为这三项，可有效过滤无效召回结果 |
| `file_parse_chunk_size` | `800–1200 字符` | 商业地产研报的段落多包含多组关联数据，该分段长度可保留上下文完整性 |
| `custom_tool_auth_token` | `按数据源要求配置专属令牌` | 垂直领域数据源需专属认证凭证，避免通用令牌导致的访问拒绝 |
| `error_retry_count` | `2–3 次` | 数据源可能因临时数据更新出现波动，有限重试可降低临时故障的影响 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为调用工具返回`400 Bad Request`，原因是未按照`tool_param_schema`的要求传递必填字段，例如遗漏「时间范围」参数导致数据源无法匹配对应时段的研报数据。
- 现象为自定义工具调用返回`401 Unauthorized`，原因是未正确配置`custom_tool_auth_token`，使用了通用的第三方服务凭证，未使用商业地产数据源的专属令牌。
- 现象为工具未触发仅返回通用问答结果，原因是未在工作流中配置问题分类后的工具调用分支，系统未识别到需要调用研报检索工具的查询请求。

## 怎么确认配好了
- 发起包含明确商业地产指标的查询，查看工具调用日志中是否携带`商圈名称`「指标类型」「时间范围」的参数。
- 测试突发的商圈异动查询，确认工具是否能在设定的时间范围内返回最新数据。
- 检查工具调用的返回结果中是否包含正确的单位，例如`元/㎡/天`，其他格式的单位表述不符合要求。
- 查看工作流执行记录，确认分类后的查询触发了对应的研报检索工具分支。
