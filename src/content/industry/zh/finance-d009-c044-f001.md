# 商业物业研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
商业物业研报数据来自商业地产行业公开研究报告、商圈运营机构的月度调研资料、地方商务部门发布的商业业态监测数据。核心商圈数据按月更新，非核心区域按季度更新，重大业态调整或政策出台时追加临时报告。文档结构包含项目区位、租金水平、租户类型占比、空置物业占总规模的比例、周边配套覆盖度等字段，租金单位为元每平方米每日，面积单位为平方米。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
商业物业研报的多维度字段与非固定更新节奏，给HTTP接口与外部系统集成带来多重约束。按月或季度更新的数据源要求接口缓存策略匹配更新周期，避免频繁调用超出数据源接口限流。多字段结构要求接口支持指定返回字段，减少无效数据传输。固定的单位体系要求接口保留原始计量规则，禁止强制单位转换，适配外部系统的统计逻辑。同时，单篇研报内容体量较大，接口需支持分页返回与内容截断配置，适配外部系统的展示与存储限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `cacheTTL` | `7200 秒` | 匹配商业物业研报按月/季度的更新节奏，避免缓存过期前调用到旧数据 |
| `recallTopK` | `前 8 条` | 商业物业研报维度较多，需召回足够条目覆盖租户、租金、配套等核心信息 |
| `similarityThreshold` | `0.72–0.80` | 平衡研报相关性与信息完整性，避免召回无关的泛行业报告 |
| `apiTimeout` | `300 秒` | 单篇研报内容体量较大，接口调用需预留足够的解析与拉取时间 |
| `fieldFilter` | `仅返回区位、租金水平、租户构成、空置情况` | 减少无效数据传输，适配外部系统的核心数据需求 |
| `chunkSize` | `1200–1500 字符` | 适配商业物业研报的长文本结构，避免语义切割破坏专业内容连贯性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用接口返回空数据或核心字段缺失。原因：未正确配置`fieldFilter`参数，默认返回全量字段超出外部系统处理能力，导致接口自动截断返回。
- 现象：接口调用返回408请求超时错误。原因：未调整`apiTimeout`配置，商业物业研报的长文本解析与拉取耗时超出默认超时阈值。
- 现象：外部系统传入的全局变量无法在工作流中生效。原因：未在接口发布页面开启全局变量透传开关，未将外部传入参数映射到工作流的全局变量节点。

## 怎么确认配好了
- 调用接口传入指定商圈的查询参数，核对返回字段是否与配置的`fieldFilter`参数一致。
- 模拟间隔短于`cacheTTL`的高频调用，核对返回数据的更新时间是否匹配预设的缓存周期。
- 传入超出常规长度的查询文本，核对接口返回的研报内容是否按`chunkSize`合理截断。
- 触发超时场景，核对接口返回的状态码与错误信息是否符合`apiTimeout`的配置规则。
