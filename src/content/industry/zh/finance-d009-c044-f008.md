# 商业物业研报检索的工具调用与插件

## 这个品类的数据长什么样
商业物业研报的数据来源包括商业物业行业监测机构、项目运营方公开披露文件、区域商管部门公示信息。更新节奏以月度或季度为主，重点商圈的客流数据支持周度更新。文档结构通常包含项目基础信息、租金定价板块、业态布局说明、运营数据汇总四个部分。核心字段包含项目名称、所在商圈、租金单价、出租率占比、入驻品牌清单，其中租金单价的单位为元/平方米/日，出租率以总可租面积的占比数值呈现。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源的多样性要求工具调用插件支持多源数据接入，包括公开API对接与本地文件上传两种方式。更新节奏的差异需要插件配置增量同步周期，适配月度、季度或周度的数据更新频率，避免拉取过时的运营数据。文档的结构化特征要求插件的参数解析模块需固定字段映射规则，不能依赖通用文本匹配，否则会导致租金单价、出租率等核心字段提取错误。字段与单位的特殊性要求工具调用时需统一单位转换逻辑，避免不同来源的研报出现单位混淆的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `recallTopK` | 前10-15条 | 商业物业研报单篇内容较长，需召回足够覆盖租金、业态等核心字段的相关片段 |
| `similarityThreshold` | 0.72-0.85 | 研报文本相似度区分度较高，阈值过低会引入无关商圈数据，过高会遗漏匹配内容 |
| `chunkSize` | 800-1200字符 | 商业物业研报包含区位说明、数据表格等结构化内容，分段长度需适配表格拆分与字段提取 |
| `pluginTimeout` | 600秒 | 多源数据拉取与解析需较长处理时间，避免超时中断 |
| `incrementalSyncInterval` | 每日/每周 | 匹配商业物业数据月度/季度更新节奏，兼顾时效性与资源消耗 |
| `fileParseMaxSize` | 200 MB | 单篇研报文件体积较大，需放宽上传限制以支持完整文档解析 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：插件调用时返回`403 Forbidden`错误。原因：将内部端口直接暴露至公网，未配置访问白名单与身份验证，对应最新版FastGPT的markdown转文件插件端口安全问题。
- 现象：无法检索到研报中的完整结构化字段内容。原因：未正确配置`chunkSize`参数，导致研报中的表格与运营数据被拆分丢失，无法完成完整字段提取。
- 现象：调用接口返回包含`$schema`字段的校验失败报错。原因：自定义插件参数中使用了以$开头的保留字段，未遵循FastGPT的JSON Schema规范。

## 怎么确认配好了
- 上传单篇商业物业研报文件，通过插件预览功能查看分段解析结果，确认核心字段被完整提取。
- 发起一次模拟调用，检查返回结果中是否包含商圈、租金单价等目标字段，调整相似度阈值与召回条数直至匹配结果符合预期。
- 查看知识库的调用日志面板，确认插件超时时间与增量同步周期的配置被正确加载。
- 测试非授权IP的访问情况，验证暴露端口的访问限制是否生效。
