# 商业物业研报检索的模型接入与配置

## 这个品类的数据长什么样
商业物业研报主要来自商业地产行业协会、专业商业咨询机构发布的商圈运营报告、自持物业的月度运营台账、品牌租户的续约数据。更新节奏为：商圈客流、租金数据按月更新，行业趋势报告按季度发布，单项目运营数据每日同步。文档多为多章节结构，包含商圈概况、租金走势、租户结构、客流画像、风险提示，字段包含日均客流人次、月均租金单价元/平方米·月、租户入驻率、商圈辐射半径公里，单篇篇幅从数千到数万字，部分附带内嵌图表的PDF或结构化Excel附件。

## 这些特征在「模型接入与配置」这一环带来什么约束
商业物业研报的多源异构属性、高频更新、带单位的细分字段及长篇幅特征，对模型接入与配置带来多项约束。多源数据包含结构化台账、PDF报告、Excel附件，需要配置适配多格式的解析规则，避免字段提取偏差。高频更新的月度/每日数据，要求配置定时增量同步任务，确保知识库与数据源同步。带单位的细分字段，如元/平方米·月，需要配置标准化处理环节，避免嵌入时单位信息丢失。单篇数万字的文档，会增加token消耗，需要配置合理的分段长度，适配多数模型的上下文窗口限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 商业物业研报包含多章节长文档及结构化附件，解析耗时较长，600秒可覆盖全量解析流程 |
| `embedding_batch_size` | `8–16` | 单条嵌入数据包含多字段，较小的批处理可避免嵌入接口报错，适配细分字段的处理需求 |
| `recall_top_k` | `5–8 条` | 商业物业研报的细分维度多，过多召回会引入无关信息，5-8条可覆盖核心检索需求 |
| `similarity_threshold` | `0.75–0.85` | 商业物业的细分字段如租金单价具有强相关性，阈值过低会引入无关研报，过高则无法召回有效内容 |
| `sync_interval` | `86400 秒` 或 `2592000 秒` | 商业物业的运营数据按日或按月更新，匹配数据源的更新节奏，确保知识库时效性 |
| `max_context_window` | `8000–16000 字符` | 单篇商业物业研报篇幅较长，需保留足够上下文以支撑连贯问答，适配多数模型的窗口限制 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 对话响应耗时超过10秒，日志显示知识库检索耗时占比过高。原因：未配置合理的召回条数与相似度阈值，导致召回过多无关文档，增加检索耗时。
- 上传的结构化台账解析后字段缺失，如租金单价未被正确提取。原因：未配置字段标准化处理规则，未适配元/平方米·月这类带单位的细分字段，导致解析引擎无法正确识别字段格式。
- 知识库数据与最新运营台账不符，存在数据滞后情况。原因：未根据数据源更新节奏配置`sync_interval`，同步间隔过长或未开启增量同步。

## 怎么确认配好了
- 发起单篇商业物业研报的解析任务，核对解析日志中无超时报错，字段提取完整且单位正确。
- 发起模拟检索，输入商圈租金或客流相关问题，核对召回结果的数量与相似度符合预设配置的取值范围。
- 触发定时同步任务，核对知识库更新时间与数据源更新节奏匹配，无数据滞后情况。
- 发起多轮连贯对话，核对响应耗时符合业务预期，无明显卡顿。
