# 商用车研报检索的工具调用与插件

## 这个品类的数据长什么样
商用车研报数据主要来自券商行业研究报告、第三方汽车产业咨询机构公开数据、交通部门营运上牌统计。更新节奏分两类：终端销量类数据按月更新，行业深度分析类研报按季度或半年度更新。文档结构通常包含核心运营指标、区域市场分布、竞品对标、政策影响分析等模块。字段包含销量（单位：辆）、单车成本（单位：万元）、新能源渗透率（单位：%）、单车续航里程（单位：km）等，部分研报会附带细分车型的配置参数与维保数据。

## 这些特征在「工具调用与插件」这一环带来什么约束
商用车研报的数据源特征对工具调用与插件环节带来多重约束。按月更新的终端销量数据要求工具调用的定时同步周期匹配月度节点，否则返回过时数据。多维度筛选参数需要插件支持多字段传入，否则无法精准召回目标研报。长文档结构要求配置合理的分段长度，避免截断核心指标段落。带单位的结构化字段要求插件返回数据保留单位信息，否则模型无法正确关联指标含义。不同来源的研报字段存在差异，插件需动态适配字段映射，否则会出现参数解析失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_timeout` | `120 秒` | 商用车行业数据源接口响应普遍较慢，120秒可覆盖多数正常调用时长 |
| `parse_file_chunk_size` | `600 字符` | 商用车研报长段落占比高，600字符分段可平衡上下文连贯性与调用效率 |
| `plugin_recall_top_k` | `前 3–5 条` | 商用车研报细分品类较多，过多召回结果会超出模型处理能力，3-5条可覆盖核心需求 |
| `max_context_length` | `8000–12000 字符` | 适配商用车研报单篇文档的平均长度，避免截断包含核心指标的关键内容 |
| `tool_auth_token_type` | `Bearer 类型` | 多数商用车行业数据接口采用标准Bearer token验证，符合官网推荐的调用方式 |
| `field_mapping_mode` | `动态匹配` | 不同来源的商用车研报字段存在差异，动态匹配可减少硬编码的适配成本 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用研报检索插件后返回空结果。原因：未配置正确的数据源接口权限，或筛选参数超出数据源覆盖的车型、时间范围。
- 现象：在工作流中调用插件时出现参数传递报错。原因：混淆了插件独立调用与工作流内嵌调用的参数格式，未在工作流节点中正确映射插件所需的字段。
- 现象：工具调用返回`504 Gateway Timeout`错误。原因：未将`tool_call_timeout`配置为适配商用车数据源的响应时长，默认时长不足以覆盖接口返回数据的周期。

## 怎么确认配好了
- 传入标准商用车研报筛选参数调用测试接口，检查返回结果是否包含对应车型、时间范围的有效数据。
- 查看插件配置页面的权限验证状态，确认token配置与数据源要求的验证方式一致。
- 调整文档分段长度参数，测试长文档解析后的输出是否保留完整的核心指标字段。
- 触发定时同步任务，检查数据更新后的插件召回结果是否包含最新的月度或季度研报数据。
