# 基建工程研报检索的工具调用与插件

## 这个品类的数据长什么样
基建工程研报主要来自行业主管部门公开文件、上市建筑装饰企业定期公告、专业工程咨询机构的专项调研文档。更新节奏随研报类型区分，专项工程可研报告按项目立项节点更新，季度造价分析报告固定每季度末发布。文档结构包含项目基本信息、工程量明细、单位造价核算、进度管控节点、合规审批文件附件，字段涉及工程体量、材料用量、预算金额、工期周期，单位多采用立方米、平方米、吨、万元、自然日等工程领域标准单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
基建工程研报的结构化字段多、单位体系复杂，要求工具调用环节支持多字段精准匹配与单位标准化转换，避免检索结果因单位不统一出现偏差。动态更新的专项项目研报无法依赖固定周期的离线同步，插件需配置实时数据源拉取能力，适配临时新增的项目文档。文档中包含CAD导出的工程量清单PDF、合规审批扫描件等非结构化附件，工具调用需兼容多格式解析，提取隐藏在附件中的关键工程参数。此外，部分研报涉及跨区域的造价基准数据，插件需支持对接区域工程定额数据库完成参数校验。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 基建工程研报常包含大型CAD附件或多页PDF文档，600秒可覆盖绝大多数长文档的解析需求 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 基建工程研报附带的CAD图纸、高清扫描件等附件体积较大，500 MB可满足常规项目文档的上传要求 |
| `召回条数` | `前 15–20 条` | 基建工程研报的核心信息分散在多个章节，15-20条的召回量可覆盖工程量、造价、进度等关键模块 |
| `相似度阈值` | `0.75–0.85` | 基建工程术语专业性强，该区间可平衡检索精准度与对标案例的覆盖范围 |
| `分段长度` | `1000–1200 字符` | 基建工程研报的工程量清单段落较长，该分段长度可避免专业术语被割裂，同时维持上下文连贯性 |
| `插件请求超时时间` | `900 秒` | 部分插件需调用区域工程定额数据库或执行复杂造价计算，900秒可覆盖常规计算流程 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用API解析基建工程研报时返回`408 Request Timeout`错误，原因是未将`PARSE_FILE_TIMEOUT_SECONDS`配置为适配大型文档的时长，导致解析流程中断。
- 发起应用调用后无法查看内部工作流执行详情，原因是未开启应用的日志留存开关，或未配置日志推送至指定存储路径。
- 自定义Python插件执行后返回空结果且无报错日志，原因是未在插件配置中正确绑定运行环境路径，或未将研报解析后的结构化字段作为入参传递至脚本。

## 怎么确认配好了
- 上传一份包含CAD附件的基建工程研报，检查解析后的结构化字段是否完整提取，确认解析耗时未超过配置的`PARSE_FILE_TIMEOUT_SECONDS`。
- 发起API调用，携带固定`chatId`参数，多次发起对话后检查上下文是否连贯，确认会话持久化配置已生效。
- 运行自定义Python插件，传入模拟的基建工程参数，检查脚本是否能正常执行并返回预期结果，确认插件入参配置正确。
- 进入应用管理后台，查看应用日志列表，确认每次API调用的工作流执行步骤均有完整记录，确认日志留存开关已开启。
