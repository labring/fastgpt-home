# 大气治理研报检索的文档解析与分块

## 这个品类的数据长什么样
大气治理研报的数据主要来自生态环境部门公开监测公报、行业协会年度分析报告、科研院所研究论文、排污企业监测报表，以及金融机构发布的环保行业细分研报。更新节奏涵盖月度常规监测、季度行业动态、年度综合总结与突发专项报告。文档包含监测点位明细、污染物浓度数据、治理方案、成本测算等模块，字段涉及点位编号、污染物浓度（单位μg/m³）、减排量（单位吨）、设备运行时长（单位小时），部分报告以扫描件留存原始报表。

## 这些特征在「文档解析与分块」这一环带来什么约束
数据来源多样导致文档格式混杂，包含纯文本PDF、Word文档与扫描版图像文件，需适配不同解析逻辑。更新节奏差异大，短至数页的专项报告与数百页的年度研报并存，对分块长度的灵活性提出要求。字段包含明确的单位与结构化关联信息，如点位与对应浓度绑定，若分块时拆分关联内容会破坏数据完整性。部分报告包含大量表格化监测数据，需保留表格内的行列关联，避免解析后数据错位。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1200 秒` | 大气治理研报常包含多页监测表格与长文本分析，默认超时时间无法覆盖完整解析流程 |
| `maxChunkSize` | `800–1200 字符` | 兼顾结构化数据的完整性与检索上下文的关联性，适配研报中技术分析与监测数据混合的内容结构 |
| `OCR_ENABLED` | `开启` | 覆盖扫描版原始监测报表的文本提取需求，避免因图像格式导致数据丢失 |
| `CHUNK_OVERLAP_RATE` | `10–15%` | 保留监测数据与前后分析内容的上下文关联，防止分块后关联信息断裂 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 支持包含多年历史监测数据的大型年度研报上传，满足全量数据检索需求 |
| `RECALL_CHUNK_NUM` | `前6–8 条` | 匹配大气治理研报的专业内容密度，提供足够上下文支撑精准问答 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为解析后扫描版研报的文本字段为空，仅显示图像占位符。原因是未开启`OCR_ENABLED`配置，无法识别扫描页内的监测数据与文字内容。
- 现象为解析大型研报时报错`504 Gateway Timeout`，且任务日志显示解析超时。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以处理多页复杂文档。
- 现象为检索结果中监测点位与对应浓度数据拆分显示，无法形成完整分析逻辑。原因是`maxChunkSize`设置过小，或`CHUNK_OVERLAP_RATE`不足，导致关联内容被分块断裂。

## 怎么确认配好了
- 上传一份包含扫描页、结构化表格与长文本分析的典型大气治理研报，查看解析后的完整内容，确认所有页面与数据均被正确提取。
- 发起针对性检索测试，输入包含点位与污染物类型的查询词，核对返回结果中是否同时包含关联的监测数据与分析内容。
- 查看解析任务的详细日志，确认`PARSE_FILE_TIMEOUT_SECONDS`参数已生效，无超时相关报错信息。
- 调整`maxChunkSize`参数进行多轮测试，对比不同取值下的检索召回效果，选定符合业务场景的配置。
