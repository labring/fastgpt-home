# 小家电研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
小家电研报数据主要来自家电行业公开数据库、品牌官方产品公告、电商平台销售监测数据及行业协会月度简报。数据更新节奏随新品发布周期波动，新品上市阶段更新频率较高，常规周期为每周1-2次。单份研报文档包含产品型号、额定功率、产品尺寸、上市日期、核心功能参数、竞品对比维度等结构化字段，其中功率单位为瓦，尺寸单位为毫米，日期格式为标准年-月-日。文档主体分为参数说明、市场表现分析、合规提示三个部分，单份文档通常包含3-5款核心小家电的详细信息。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
小家电研报的结构化字段较多，且存在明确的单位与格式要求，因此HTTP接口需要支持多字段精准筛选与单位校验，避免返回不符合业务需求的冗余数据。数据更新节奏波动较大，接口需要支持增量拉取配置，适配日常低频率更新与新品期高频率同步的切换需求。不同小家电品类（如厨房电器、个人护理电器）的核心参数存在差异，外部系统对接时需根据小家电品类动态调整检索维度，接口需提供灵活的字段过滤配置项。此外，部分数据源存在跨域访问限制，接口需要配置白名单以允许外部系统正常调用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `request_timeout` | `30 秒` | 小家电研报数据量适中，超时过久会影响检索响应效率 |
| `filter_fields` | `["product_model", "rated_power", "launch_date"]` | 聚焦小家电研报核心检索维度，减少冗余数据传输 |
| `chunk_size` | `800–1200 字符` | 适配小家电研报单段参数说明的长度，避免拆分冗余或信息断裂 |
| `similarity_threshold` | `0.75–0.85` | 结构化参数匹配需要较高精准度，避免低相关结果混入 |
| `incremental_sync_interval` | `每日 1 次` | 匹配常规更新频率，新品阶段可临时调整为每6小时 |
| `max_return_results` | `前 10 条` | 聚焦核心匹配结果，避免过多信息干扰检索判断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用接口返回502 Bad Gateway，未配置小家电研报数据源的跨域白名单，外部系统请求被拦截。
- 接口返回结果字段为空，未指定`filter_fields`配置项，接口默认返回全量冗余字段导致检索匹配失效。
- Docker部署的服务出现无限重启，未适配小家电研报的大参数批量拉取，内存占用超出容器配额。

## 怎么确认配好了
- 调用测试接口，传入小家电研报的典型检索关键词，核对返回结果包含预设的`product_model`字段。
- 查看接口日志，确认`request_timeout`未触发超时错误，响应时长符合配置预期。
- 测试增量拉取功能，手动触发同步后核对新增数据与数据源更新记录一致。
- 验证跨域配置，从外部系统发起请求，确认无502错误返回。
