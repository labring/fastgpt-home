# 工业金属研报检索的多轮对话与提示词

## 这个品类的数据长什么样
工业金属研报的数据主要来自中国有色金属工业协会、上海期货交易所、头部券商有色行业研究团队。更新节奏覆盖日度（现货价格、库存周报）、月度（供需平衡表）、年度（行业展望）三类。单篇研报结构固定，包含核心摘要、供需数据模块、价格走势分析、政策动态四个部分。字段包含LME铜价（单位美元/吨）、国内电解铝库存（单位万吨）、冶炼产能（单位万吨/年），同时附带发布机构、发布日期、数据统计周期等元数据。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
工业金属研报存在多类更新周期的数据，多轮对话中需明确指定统计周期，否则会出现周度与月度数据混合展示的问题。固定的文档结构要求提示词需引导检索聚焦供需、价格、库存等核心模块，避免无效召回。特定的单位与字段要求，需在多轮对话的上下文窗口中保留单位一致性规则，防止出现美元/吨与人民币/千克混用的情况。多源数据的溯源需求，要求每轮返回的结果需附带发布机构与发布日期，满足工业金属行业数据的严谨性核查要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 工业金属研报单篇内容较长，多轮对话需保留多轮查询的时间、品类限定上下文，避免上下文溢出 |
| `recall_top_k` | `前8–12 条` | 工业金属研报核心数据分散在不同文档，需足够召回覆盖但避免冗余内容干扰结果 |
| `chunk_size` | `1000–1500 字符` | 工业金属研报的供需模块段落较长，分段过短会破坏数据关联性，过长则会降低检索精度 |
| `prompt_template` | 固定加入“请标注数据来源与发布时间，单位统一使用文档中原有的标准单位” | 工业金属数据单位多样，需强制统一输出标准单位，同时满足溯源要求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单篇工业金属研报可能超过100页，解析耗时较长，需延长超时时间避免解析失败 |
| `response_citation` | `开启` | 工业金属行业数据需可追溯，开启引用功能可满足合规与核查需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：开启引用功能后，部分对话返回结果附带引用标识，同时界面弹出“没有权限操作此对话记录”的报错，无法手动关闭引用展示。原因：未正确配置`response_citation`的权限参数，导致引用展示逻辑与对话权限校验冲突。
- 现象：多轮对话中连续查询不同周期的工业金属数据，结果出现单位混乱，比如同时出现美元/吨与人民币/千克。原因：提示词未强制要求统一单位，且上下文窗口未保留单位一致性规则。
- 现象：设置了过高的`recall_top_k`参数，返回的研报片段中出现大量非工业金属内容，比如煤炭、钢铁无关数据。原因：未在`prompt_template`中限定检索范围为工业金属品类，召回的文档未做品类过滤。

## 怎么确认配好了
- 发起包含电解铝库存、LME铜价的复合查询，核对返回结果的单位统一，且每条数据附带来源与发布时间。
- 连续发起3轮分别针对周度、月度、年度工业金属供需数据的查询，核对多轮上下文未出现数据周期混淆。
- 上传一篇超过100页的工业金属研报，核对文件解析未超时，且分段后的内容可完整关联供需逻辑。
- 尝试关闭引用展示功能，核对界面未出现权限报错，且引用标识可按需隐藏。
