# 工程咨询研报检索的工作流编排

## 这个品类的数据长什么样
工程咨询研报的数据主要来自金融机构的专项工程融资报告、官方住建部门公开的项目备案资料、行业协会发布的调研白皮书、专业咨询机构出具的项目可行性研究报告。更新节奏随项目推进、行业政策调整或融资进度变化，无固定周期，部分专项报告仅在项目中标或融资落地后发布。单份文档长度从数千到数万字符不等，包含项目编号、建设地点、总投资额、技术参数、风险评级、融资额度等字段，单位涉及万元、平方米、天、立方米等工程类标准单位。

## 这些特征在「工作流编排」这一环带来什么约束
工程咨询研报的非固定更新周期，要求工作流支持按需触发，适配临时接入的专项报告。单份文档长度跨度大，要求工作流的分段解析参数可灵活调整，避免长文档截断或解析失败。工程类专属的单位字段，要求召回环节保留原始单位信息，避免数值与单位匹配错误。部分文档包含内部项目或融资敏感信息，要求工作流集成权限校验与日志脱敏环节，过滤无访问权限的数据源。多源数据聚合的需求，要求工作流支持不同数据源的格式转换，统一输入到检索环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–1200 秒 | 工程咨询研报单份文档长度跨度大，长文档解析需要更长时间，避免中途超时中断 |
| `segment_length` | 800–1500 字符 | 适配工程类文档的段落结构，避免拆分专业术语或单位组合 |
| `retrieve_top_k` | 前10–15条 | 工程咨询研报的专业信息密度高，需要召回足够多的相关片段覆盖核心内容 |
| `similarity_threshold` | 0.75–0.85 | 过滤低相关的通用表述，保留与项目场景强匹配的研报内容 |
| `workflow_call_timeout` | 1800 秒 | 复杂研报的多步骤处理需要更长的执行时间，避免提前断开连接 |
| `tool_call_output` | 隐藏 | 工程咨询工作流多为自动化检索，无需输出工具调用的中间回复，简化最终输出 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用工作流后，对话日志中检索到的研报运行数据为空。原因：未配置数据源的权限校验规则，内部项目研报被过滤，导致无有效数据返回。
- 现象：主工作流调用子工作流后，子工作流无法完成完整的研报解析流程。原因：子工作流的`PARSE_FILE_TIMEOUT_SECONDS`参数设置过短，长文档解析未完成即被终止。
- 现象：非流式调用工作流超过180秒后，任务被强制断开，未返回完整研报结果。原因：未调整`workflow_call_timeout`参数，默认超时限制无法覆盖工程类长文档的处理时长。

## 怎么确认配好了
- 上传一份典型的工程咨询研报，运行工作流，检查对话日志中是否包含解析后的分段内容，调整`segment_length`直到无明显截断。
- 调用工作流传入内部项目编号，核对返回结果是否包含对应项目的专属字段，确认权限校验规则配置正确。
- 模拟长文档解析场景，运行工作流并观察任务执行时长，调整`PARSE_FILE_TIMEOUT_SECONDS`至任务可正常完成。
- 检查工具调用节点的配置，确认`tool_call_output`的设置符合工作流的输出需求。
