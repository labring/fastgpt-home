# 广告营销研报检索的工作流编排

## 这个品类的数据长什么样
广告营销研报的数据来源涵盖行业监测平台、广告主投放台账、媒体公开报告及第三方调研机构数据。更新节奏覆盖实时投放数据的日报、渠道表现复盘的周报，以及季度、年度的行业分析报告。文档结构包含投放渠道明细、受众画像指标、内容曝光量、转化数据等字段，单位涉及千次曝光成本、点击成本、转化率等专业营销指标，文档格式包含Excel明细报表、PDF行业分析文档、Word项目复盘文档等类型。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流配置多数据源接入节点，需适配不同平台的接口认证规则。更新节奏的差异要求设置灵活的定时触发间隔，避免频繁拉取过时数据或遗漏实时投放信息。专业字段与多样的文档格式要求配置字段映射与自动解析规则，确保不同格式的研报均可被正确提取与标准化。大体积的文档内容要求调整解析超时与文件大小限制参数，避免单文件处理中断。多维度的指标数据要求扩大召回与上下文窗口，确保问答覆盖完整分析维度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `RECALL_TOP_K` | `前 6–10 条` | 广告营销研报包含多维度投放数据，需召回足够数量的相关条目以覆盖全量分析维度 |
| `PARSE_DOCUMENT_TIMEOUT` | `900–1200 秒` | 15000行Excel或10万汉字Word解析耗时较长，需延长超时时间避免中途中断 |
| `DB_CONNECT_TIMEOUT` | `30–60 秒` | 广告营销数据源多为第三方监测平台，需适配网络波动下的连接等待时长 |
| `WORKFLOW_LOOP_NEST_LIMIT` | `2–3 层` | 多层循环嵌套易导致工作流执行超时，需限制嵌套层级避免资源耗尽 |
| `AUTO_SPLIT_ENABLE` | `开启` | 广告营销研报格式多样，自动分段可适配不同文档结构的解析需求 |
| `CONTEXT_WINDOW_SIZE` | `8000–12000 字符` | 广告营销专业术语密集，更长的上下文窗口可提升问答准确性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中数据库连接显示`connect ETIMEDOUT`错误，本地可正常访问数据源。原因：未配置`DB_CONNECT_TIMEOUT`适配云端网络环境，或数据源白名单未包含FastGPT部署节点IP。
- 现象：工作流循环体嵌套超过3层后执行失败，无返回结果。原因：未限制`WORKFLOW_LOOP_NEST_LIMIT`参数，多层循环占用过多系统资源导致超时。
- 现象：上传10万汉字Word或15000行Excel文档后，工作流解析失败或返回不完整内容。原因：未调整`PARSE_DOCUMENT_TIMEOUT`和`UPLOAD_FILE_MAX_SIZE`参数，导致文件超出限制或解析超时。

## 怎么确认配好了
- 执行数据库连接测试节点，查看返回状态码，确认无`connect ETIMEDOUT`报错。
- 上传单份15000行Excel文档，触发工作流后查看解析进度，确认未出现超时中断提示。
- 配置多组AI问答节点，查看最终输出仅包含最后一次问答结果，确认结果截断逻辑生效。
- 触发2层嵌套循环工作流，查看执行日志未出现嵌套超限提示，确认`WORKFLOW_LOOP_NEST_LIMIT`参数生效。
