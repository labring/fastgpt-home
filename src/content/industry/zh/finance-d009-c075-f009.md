# 整车研报检索的引用来源与溯源

## 这个品类的数据长什么样
整车研报数据主要来自券商研究所、汽车行业权威协会、上市车企公开披露的公告与财报。更新节奏覆盖周度销量跟踪、月度产销数据、季度行业趋势分析及专题调研报告，发布周期从单日突发点评到季度深度报告不等。文档结构包含研报标题、发布机构与日期、核心产销数据、车型参数分析、行业评级及风险提示。字段包含整车销量（单位：辆）、产能（单位：万辆/年）、零部件单价（单位：元）、研报评级、发布时间等，部分报告附带车型配置细节与市场份额测算内容。

## 这些特征在「引用来源与溯源」这一环带来什么约束
整车研报的多来源属性要求溯源环节需关联券商研究所、行业协会、车企公告等不同数据源的唯一标识，避免跨源数据混淆。不同更新节奏的研报，从单日突发点评到季度深度报告，需要在溯源信息中记录精确发布时间，确保调用的是对应周期的最新数据。长文档结构下，单篇研报内容体量较大，溯源需定位到具体页码、段落范围，不能仅提供文件名。多字段的差异化单位与统计周期，要求溯源信息同步标注对应内容，避免数据解读偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `引用模板` | `【来源：{source} | 发布时间：{publish_time} | 页码：{page_num}】` | 整车研报需明确标注来源机构、发布时间与具体页码，满足专业场景下的溯源需求 |
| `召回条数` | 前8-12条 | 整车研报数据密度较高，过多召回会增加上下文冗余，过少则无法覆盖核心数据片段 |
| `相似度阈值` | 0.75-0.85 | 整车研报包含大量专业术语，阈值过低易引入无关片段，过高则可能遗漏相关数据内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300-600秒 | 长文档深度研报解析耗时较长，避免因超时导致文档解析不完整 |
| `分段长度` | 800-1200字符 | 整车研报段落信息密度较高，分段过长会破坏上下文关联，过短则导致召回片段信息不完整 |
| `重排返回条数` | 前5-7条 | 重排后筛选最相关的研报片段，确保溯源信息精准且不冗余 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：知识库回答段落末尾未显示预设的引用信息。原因：未在对应版本的AI高级配置中开启自定义引用模板功能，或未正确配置`引用模板`参数，模板中未包含`{source}`、`{publish_time}`等必填占位符。
- 现象：解析长文档深度研报时返回超时错误。原因：`PARSE_FILE_TIMEOUT_SECONDS`配置取值过低，无法覆盖长文档解析所需的耗时。
- 现象：溯源信息中未标注研报对应的统计周期与单位。原因：未在`引用模板`中加入对应字段占位符，或上传文档时未正确提取研报中的统计周期、单位信息。

## 怎么确认配好了
- 上传一篇测试用的整车研报，配置对应参数后发起提问，检查回答末尾是否显示预设的引用信息。
- 查看知识库解析日志，确认长文档研报未出现超时截断，解析耗时符合配置的`PARSE_FILE_TIMEOUT_SECONDS`范围。
- 核对召回的研报片段的来源、发布时间与页码，确认与实际文档内容一致。
- 发起连续提问，检查上下文关联的召回片段是否包含正确的溯源信息。
