# 文娱用品研报检索的工具调用与插件

## 这个品类的数据长什么样
文娱用品研报数据主要来自轻工制造行业协会公开报告、头部品牌厂商季度披露文件、电商平台销售监测数据及线下零售终端抽样数据。更新节奏覆盖月度渠道监测、季度品类趋势分析及年度行业白皮书。文档结构通常包含细分品类拆解、核心玩家市场表现、消费者偏好标签、价格带分布、政策合规提示等字段，字段单位多为万元、百分比、人次等，部分厂商披露数据会包含SKU动销率、复购周期等细分指标。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于文娱用品研报数据来源分散，工具调用需支持多数据源鉴权与数据聚合，需配置对应API的密钥与请求频率限制。不同数据源更新节奏差异较大，需为不同类型数据设置差异化的定时同步间隔，避免增量拉取遗漏或重复请求。研报文档包含细分品类、SKU动销率等多维度字段，插件需支持字段映射与数值型筛选规则，确保召回数据与检索需求匹配。部分厂商披露数据存在格式差异，工具调用需配置标准化转换规则，统一字段命名与单位，避免因字段不匹配导致检索结果偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `recall_top_k` | 前8-12条 | 文娱用品研报包含多维度细分信息，过多召回会增加上下文处理负担，过少则无法覆盖全品类检索需求 |
| `plugin_api_timeout` | 30-60秒 | 多源数据聚合时需等待电商、行业协会等接口返回，过短会导致未完成全量拉取，过长会延长整体响应时间 |
| `parse_chunk_size` | 800-1200字符 | 文娱用品研报包含长段落的渠道分析与品类解读，分段过短会破坏逻辑关联，过长则影响模型对内容的理解 |
| `workflow_trigger_params` | 仅传入研报关键词与品类标签 | 工具调用需精准触发对应数据源的拉取逻辑，避免无关参数干扰接口返回结果 |
| `stream_response_format` | 启用Markdown格式 | 研报内容包含分类标签、价格带表格等结构化信息，Markdown格式可优化前端展示效果 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用工具返回的流数据仅为纯文本，无格式排版。原因：未开启`stream_response_format`的Markdown格式配置，导致返回内容未做结构化标记。
- 现象：调用指定工作流时返回403错误。原因：未配置工作流触发所需的签名密钥，或中间转发服务未正确透传鉴权参数。
- 现象：召回的研报数据缺少SKU动销率字段。原因：未配置字段映射规则，未将第三方接口返回的`sku_sales_rate`字段映射为FastGPT可识别的检索字段。

## 怎么确认配好了
- 发起一次文娱用品品类的研报检索请求，查看返回的流数据是否包含Markdown格式的标题、列表或表格，确认格式配置生效。
- 调用指定工作流接口，检查返回结果是否包含预期的多源聚合数据，确认鉴权参数与触发规则配置正确。
- 查看工具调用日志，确认接口请求的超时时间匹配配置取值，无提前断开的超时记录。
- 检索包含SKU动销率的研报关键词，检查召回结果是否包含该细分字段，确认字段映射规则配置生效。
