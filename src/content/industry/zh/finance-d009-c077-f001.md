# 旅游景区研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
金融领域内旅游景区相关研报的数据，主要来自金融机构采购的文旅行业公开研报、文旅部及地方文旅局开放的景区运营数据接口、第三方文旅咨询机构的专项调研文档。更新节奏分为两类：行业通用研报按季度更新，景区自身运营总结按月度更新。单份文档结构包含景区概况、客流数据、营收构成、竞争分析、发展建议等模块，字段包含接待游客量、营业收入、游客停留时长、停车场泊位使用率等，其中接待游客量单位为万人次，营业收入单位为万元。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多数据源的存在要求对接不同鉴权方式的外部接口，部分第三方文旅研报接口需使用专属API密钥，文旅部门开放接口需使用内网访问权限，同时需符合金融行业的数据加密传输要求。不同更新节奏的数据源需要配置差异化的定时拉取任务，避免重复拉取或遗漏增量数据，适配金融机构的研报库更新周期。景区研报包含结构化数据与长文本分析内容，单份文档篇幅较长，需要调整接口的解析与传输参数。专属字段的存在要求外部接口返回数据与系统标准字段完成映射，否则检索结果无法匹配金融分析对景区特定维度的需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 景区研报包含多维度结构化数据与长文本分析，解析耗时高于通用文档 |
| `RECALL_TOP_K` | `前8-12条` | 景区研报细分维度较多，需覆盖客流、营收、竞争等多类分析角度 |
| `MAX_CHUNK_LENGTH` | `1000-1200 字符` | 平衡文本召回精度与检索效率，适配景区研报的内容结构 |
| `EXTERNAL_DATA_SYNC_INTERVAL` | `86400 秒` | 覆盖景区月度运营数据的每日增量更新，同时适配行业研报的季度更新节奏 |
| `API_AUTH_TYPE` | `多密钥轮换` | 对接多类外部数据源，不同来源使用独立鉴权密钥，符合金融行业数据安全规范 |
| `FIELD_MAPPING_RULE` | `按景区专属字段映射` | 将外部接口返回的`parking_usage_rate`、`stay_duration`等字段映射至系统标准字段 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为接口返回`413 Request Entity Too Large`，原因是未调整`UPLOAD_FILE_MAX_SIZE`配置，景区研报文档篇幅普遍较长，默认上传大小不足以承载完整文件。
- 现象为定时同步任务频繁超时失败，原因是将`PARSE_FILE_TIMEOUT_SECONDS`设置为`300 秒`，未匹配景区研报的解析耗时需求。
- 现象为HTTP接口调用返回`500 Internal Server Error`，日志显示token encoder初始化失败，原因是未正确配置外部模型接口的鉴权参数，导致无法加载对应编码模块。

## 怎么确认配好了
- 上传单份景区研报文档，查看解析后的分段数量，调整`MAX_CHUNK_LENGTH`至符合预期的分段长度。
- 发起外部数据源同步任务，查看返回结果中是否包含`parking_usage_rate`、`stay_duration`等景区专属字段，确认`FIELD_MAPPING_RULE`配置生效。
- 调用HTTP接口发起研报检索请求，检查返回结果的条数是否符合`RECALL_TOP_K`的设置范围。
- 查看定时任务日志，确认同步任务按`EXTERNAL_DATA_SYNC_INTERVAL`的配置周期正常执行。
