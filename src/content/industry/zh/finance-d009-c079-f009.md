# 普钢研报检索的引用来源与溯源

## 这个品类的数据长什么样
普钢研报数据主要来自国内钢铁工业协会月度供需报告、主流大宗商品交易平台的每日行情简报、头部钢厂的生产经营周报。单篇文档长度跨度大，短则数百字的行情速报，长则数万字的行业深度分析。核心字段包含普钢牌号（如Q235、HRB400）、出厂价格、市场库存、周度产量，单位多为元/吨、万吨、千吨。更新频率覆盖每日、每周、每月三类，部分高频行情数据会随交易时段实时更新。

## 这些特征在「引用来源与溯源」这一环带来什么约束
普钢研报的多更新频率特征要求溯源系统区分不同文档的更新时效标签，避免召回过时的月度报告用于当日行情问答。长文档的分段切分需保留核心字段的上下文关联，否则溯源时无法定位具体数据对应的牌号或价格区间。多来源的数据需统一标注来源机构与发布时间，否则无法验证数据可信度。部分实时行情研报的短文本结构，要求溯源链接或引用片段能精准匹配到具体交易时段的行情快照，仅展示该时段的相关内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 普钢研报既有短行情速报也有长深度分析，该区间可保留牌号、价格等核心字段的上下文关联，避免溯源时丢失关键信息 |
| `recallTopK` | `前 6–8 条` | 普钢研报的细分维度较多（如产地、牌号），召回过多会引入无关数据，过少则无法覆盖全量相关报告 |
| `similarityThreshold` | `0.72–0.80` | 普钢价格数据的语义相似度较高，该阈值可过滤低相关的历史报告，同时保留同牌号不同周期的对比数据 |
| `sourceDisplayFormat` | `完整来源+发布时间` | 普钢研报的来源机构与发布时间是用户验证数据可信度的核心依据，需完整展示，仅展示文件名无法满足验证需求 |
| `parseFileTimeout` | `900 秒` | 部分普钢深度研报文档体积较大，需预留足够时间完成解析与分段，避免解析超时 |
| `enableCitation` | `开启` | 普钢研报的专业属性要求明确引用来源，满足合规与数据溯源需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为部分提问触发后，引用列表为空，界面显示“未匹配到相关知识库文档”。原因是未针对普钢研报的多更新频率配置时效过滤规则，导致召回逻辑未筛选当日、当周的有效数据。
- 现象为上下文引用区域出现大量未解析的`|`符号，无法正常展示研报中的表格结构。原因是未调整`chunkSize`参数适配普钢研报的长文本分段，导致分段时保留了原始文档的Markdown表格分隔符未被正确清理。
- 现象为引用来源仅显示文件名，未标注发布机构与时间。原因是错误配置`sourceDisplayFormat`参数，仅返回文件名字段，未添加来源机构与发布时间。

## 怎么确认配好了
- 上传一份普钢研报的测试文档，触发检索后查看引用列表，确认展示的来源包含文件名、发布机构与相关信息。
- 输入包含普钢牌号（如Q235）的提问，核对召回的引用文档与提问的匹配度，确认召回逻辑符合业务预期。
- 上传一份长文档深度研报，检查分段后的引用片段是否保留了核心字段（如价格、牌号）的上下文关联。
- 查看系统运行日志，确认解析普钢研报时未触发超时类报错。
