# 水产养殖研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
水产养殖研报数据主要来自农业农村部海区监测机构、全国水产技术推广总站、行业协会公开报告及高校水产研究成果，多为金融机构研报的核心数据源之一。更新节奏分为月度养殖环境监测周报、季度产业动态分析、年度产业发展白皮书。文档结构包含养殖区域分布、单产水平、病害防控方案、饲料配比参数等内容，字段涉及养殖密度、单位水体产量、病害发生率，单位多为尾/亩、千克/立方米、百分比。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
水产养殖研报的多字段特性要求接口请求参数需支持指定字段筛选，避免返回无关内容，适配金融投研系统的精准检索需求。月度更新的监测数据要求外部同步系统设置按周拉取增量数据的任务，防止全量拉取占用过多资源。长文档结构要求接口配置合理的分段解析阈值，避免单条数据过长导致超时。此外，单位统一需求要求接口返回时携带标准化单位字段，供外部系统直接适配使用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | 前8-12条 | 水产养殖研报单篇内容较长，过多召回会超出上下文限制 |
| `相似度阈值` | 0.72-0.80 | 水产养殖细分领域术语专业性强，需提高阈值过滤低相关结果 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 单篇长研报解析耗时较长，需延长超时时间避免解析失败 |
| `分段长度` | 1000-1200 字符 | 水产养殖研报包含大量专业数据表格与公式，分段过短会破坏数据关联性 |
| `maxContext` | 8000-10000 字符 | 研报内容密度高，需扩大上下文窗口容纳多段召回数据 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 行业研报多包含高清养殖地图与数据附件，需放宽上传限制 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为调用对话接口返回400状态码，提示参数缺失。原因是未正确携带水产养殖研报专属的`source_type`字段，或未指定召回的研报数据源。
- 现象为多次调用接口时，上下文记忆出现混乱。原因是未固定传递`chatId`参数，导致每次请求生成新的会话上下文，无法关联历史研报检索结果。
- 现象为返回结果中包含非水产养殖的无关内容。原因是未设置`相似度阈值`的合理取值，或未指定`召回条数`的上限，导致召回了过多低相关的其他行业研报。

## 怎么确认配好了
- 发起单条研报解析请求，检查返回的解析结果是否包含水产养殖专属字段。
- 连续发起多次携带固定`chatId`的请求，确认上下文会话未被重置，历史检索结果可被正确关联。
- 调用接口时指定`召回条数`为配置项设定的取值，检查返回结果的条数是否符合预期。
- 上传符合`UPLOAD_FILE_MAX_SIZE`配置取值的研报附件，确认解析任务未因超时或文件大小限制失败。
