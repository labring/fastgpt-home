# 水产养殖研报检索的工作流编排

## 这个品类的数据长什么样
水产养殖研报数据主要来自农业农村部直属水产养殖监测机构、地方水产科研院所、行业协会公开报告及第三方调研机构的专项调研。更新节奏覆盖周度、月度及年度周期，周度报告聚焦当日/当周的苗种价格、病害动态，月度报告包含区域养殖规模、单产数据，年度报告则涵盖全产业链趋势。文档结构通常包含核心监测字段：养殖密度、饵料系数、单产水平、病害发生率、饲料采购成本，对应单位分别为尾/平方米、无单位比值、千克/亩、百分比、元/千克。文档多为PDF格式，部分包含表格内嵌的结构化数据，少量为纯文本纪要。

## 这些特征在「工作流编排」这一环带来什么约束
周度高频更新的特性要求工作流配置定时触发节点，避免手动调度的滞后性。多维度且带固定单位的字段，要求在数据解析环节开启结构化表格提取，同时配置字段校验规则，确保单位匹配。不同周期研报的维度差异，要求工作流设置分支判断节点，根据报告周期路由至对应知识库的检索环节。内嵌表格的PDF文档，要求解析模块开启表格识别开关，避免丢失结构化数据。此外，水产养殖的地域属性较强，部分研报仅覆盖特定区域，需在检索环节配置区域过滤参数，缩小召回范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 水产养殖研报单篇多包含多组监测表格，过长的上下文会触发模型截断，该区间可覆盖多数单篇研报的核心内容 |
| `parse_table_enable` | `开启` | 水产养殖研报内嵌结构化表格占比高，关闭解析会丢失养殖密度、单产等核心字段 |
| `recall_top_k` | `前 8–12 条` | 水产养殖数据维度丰富，少量召回会遗漏病害发生率、饲料成本等关键指标 |
| `similarity_threshold` | `0.72–0.78` | 行业术语专业性强，阈值过低会引入无关的通用农业报告，过高则无法召回细分品类的专业内容 |
| `schedule_interval` | `1 天` 或 `7 天` | 周度价格报告需每日检查更新，月度规模报告可按7天间隔调度 |
| `workflow_timeout` | `600 秒` | 多节点检索、解析及模型调用的总耗时需控制在合理范围，避免任务中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：本地测试工作流运行正常，通过公开渠道链接调用时返回“undefined is not valid json”。原因：渠道链接未正确配置`response_format`参数，或工作流中存在未序列化的临时变量，公网环境下无法生成合规JSON响应。
- 现象：工作流无法向指定知识库发起检索，召回结果未覆盖水产养殖相关内容。原因：未在检索节点绑定指定知识库的`knowledge_base_id`参数，或对应知识库未上传有效研报数据。
- 现象：多模型串联的工作流出现上下文溢出，或单模型调用token消耗超出预设限额。原因：未配置`maxContext`参数限制上下文长度，且未开启多模型独立token计数规则，导致跨节点token共享超出模型支持范围。

## 怎么确认配好了
- 触发手动运行工作流，查看各节点的执行日志，确认表格解析节点成功提取了养殖密度、单产等核心字段。
- 核对检索节点的召回结果，确认召回条数匹配配置的`recall_top_k`，且结果均来自水产养殖相关知识库。
- 检查定时调度任务的日志，确认任务按设定的`schedule_interval`周期自动触发。
- 调用公开渠道链接，验证返回内容为合规JSON格式，确认`response_format`参数配置正确。
