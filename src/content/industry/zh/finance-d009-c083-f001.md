# 水务研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
水务研报的数据来源包括水务行业协会公开报告、上市水务企业年度及半年度财报、水务监管部门发布的行业动态与水质监测数据，以及专业水务咨询机构的深度分析文档。更新节奏分为定期与即时两类：季度更新行业运营数据研报，年度更新深度行业分析报告，突发水质调整、管网改造等事件时会即时发布补充文档。文档结构通常包含项目概况、水质监测指标、运营成本明细、管网参数、政策合规要求等模块，字段包含COD、氨氮、总磷等水质指标，单位多为mg/L、μg/L，管网长度单位为公里，供水覆盖人口单位为万人，部分研报还包含项目投资金额、运维周期等数值类字段。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
水务研报包含大量带明确单位的专业水质与运营数据，要求HTTP接口返回的字段需附带单位信息，外部系统对接时需完成单位与业务系统的映射，避免数据误用。研报更新存在定期与即时两种节奏，接口需支持按时间戳增量拉取数据，避免重复拉取全量内容，降低传输成本。文档包含多模块细分内容，接口需支持按模块筛选返回字段，减少无效数据传输量。部分研报包含内嵌的水质监测图表、项目现场图片，接口需保留原始图片链接的完整路径，外部系统需正确解析并加载这些链接。此外，水务研报的专业术语较多，接口返回内容需保留原始表述，不宜自动截断或简化，需配置完整返回原始文本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `responseExtractMode` | `v4.8.12及以后版本使用「按JSON路径提取」模式` | 适配社区反馈的v4.8.12-beta版本HTTP返回值提取逻辑变更，避免旧版提取规则无法正确识别嵌套字段 |
| `requestDynamicParams` | `通过{{变量名}}语法绑定入参，如{{water_project_id}}` | 支持按水务项目ID、监测时间范围等可变参数发起请求，适配不同细分研报的检索需求 |
| `charset` | `UTF-8` | 适配水务研报中的中文专业术语与数据，避免出现乱码问题 |
| `timeout` | `300 秒` | 水务研报数据量较大，包含多模块详细内容，预留足够请求时长避免超时中断 |
| `returnFields` | `指定需返回的字段列表，如["project_name","cod_value","unit"]` | 减少无效数据传输，适配水务研报多字段的特征，提升接口调用效率 |
| `retryOnFailure` | `状态码≥500时重试2次` | 应对水务数据接口可能因服务器负载波动出现的临时故障，提升调用稳定性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置`responseExtractMode`为旧版提取模式时，返回的研报内嵌图片链接无法正常加载或显示为空。原因：v4.8.12-beta及以后版本变更了HTTP返回值的提取逻辑，旧模式无法正确识别嵌套的图片URL字段。
- 现象：调用数据库插件存储水务研报数据时，中文专业术语与数值数据显示为乱码。原因：未将HTTP请求的`charset`配置为`UTF-8`，导致中文编码解析失败。
- 现象：FastGPT调用水务研报接口返回超时错误，但Postman调用可正常获取结果。原因：未根据水务研报的数据量调整`timeout`配置，默认超时时长不足以完成全量研报数据的拉取。

## 怎么确认配好了
- 发起单次测试请求，检查返回的字段是否包含预设的水务专业指标与对应单位，确认`returnFields`配置已生效。
- 查看FastGPT的请求日志，确认动态入参已正确替换为实际的水务项目ID或监测时间范围，验证`requestDynamicParams`配置正常。
- 触发请求后检查返回的内嵌图片链接是否可正常访问，确认`responseExtractMode`适配当前版本的提取逻辑。
- 查看数据库存储的研报内容，确认中文术语与数据未出现乱码，验证`charset`配置正确。
