# 水泥研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
水泥研报数据主要来源于全国建材工业协会月度监测数据、区域建材市场周报、上市建材企业公开财报及第三方行业咨询机构报告。更新节奏以月度为核心周期，区域市场行情类报告更新频率更高。文档结构通常包含行业整体动态、区域供需数据、核心品类价格走势、企业经营参考及后市判断五个部分。字段包含区域名称、熟料产量、水泥均价、库存周转天数，单位分别为省/市、万吨、元/吨、天。单篇报告的内容长度差异较大，区域周报的内容长度建议结合自有样本统计或实测后确定，行业深度报告的内容长度建议结合自有样本统计或实测后确定。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
水泥研报的数据来源分层、更新周期差异大，要求接口支持按报告类型配置不同的同步触发时机，区域数据的批量拉取需适配分页参数以处理多区域的海量数据。字段包含跨区域、跨品类的细分指标，接口请求参数需支持按区域、报告类型过滤，返回字段需支持自定义筛选以减少无效数据的传输开销。单篇报告内容长度差异显著，长文档的解析与上传需平台支持大文件分段处理，同时需设置合理的超时阈值避免请求中断。增量同步机制需适配数据更新频率，仅拉取更新后的报告，不进行全量重传，降低外部系统的资源占用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 水泥研报单篇文件最大可达约900MB，预留合理余量避免上传失败 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 长文本研报的解析、向量化预处理需较长耗时，避免中途超时中断 |
| `RECALL_TOP_N` | `前6条` | 水泥研报的核心供需、价格信息通常集中在前6条相关检索结果 |
| `SYNC_INCREMENTAL_ENABLE` | `开启` | 水泥行业数据以增量更新为主，全量同步会占用过多外部系统带宽与存储 |
| `maxContext` | `7000–9000 字符` | 单篇水泥研报的核心分析段落长度通常不超过7000字符，适配上下文窗口 |
| `SIMILARITY_THRESHOLD` | `0.72–0.85` | 水泥研报的关键词匹配度需达到该区间，才能确保检索结果与查询需求强相关 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用上传接口传入HTML格式的标题和内容后，目标知识库未生成对应文档。未正确设置`UPLOAD_FILE_CONTENT_TYPE`为`text/html`，接口无法识别传入的内容格式，导致解析失败。
- 批量拉取区域水泥研报列表时返回`413 Request Entity Too Large`状态码。未调整`UPLOAD_FILE_MAX_SIZE`配置，批量请求的数据包超出平台默认限制，无法正常传输。
- 离线部署向量模型后发起检索请求，接口返回分词相关报错，日志显示尝试请求外网资源`cl100k.tiktoken`。未配置本地`tiktoken`缓存目录，模型无法加载本地分词规则，被迫向外网发起请求。

## 怎么确认配好了
- 执行curl命令调用文件列表接口，返回的结果中包含对应区域水泥研报的条目数，核对条目数与实际同步的文件数一致。
- 调用上传接口传入一段标准水泥研报的HTML内容，检查知识库中生成的文档字段是否包含区域、价格等核心信息。
- 查看向量模型的运行日志，确认未出现请求外网`tiktoken`资源的报错，分词流程正常完成。
- 发起检索请求，检查返回的检索结果条数与配置的`RECALL_TOP_N`参数值一致。
