# 汽车服务研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
汽车服务研报的数据来源包括汽车行业第三方咨询机构公开研报、主机厂官方技术文档、汽车后市场服务平台的运营数据。新车相关研报随车型上市节点更新，后市场服务类研报按季度发布，行业政策类研报随政策落地同步更新。文档通常包含车型核心参数、服务套餐定价、区域服务数据、供应链成本拆解等模块，字段涵盖「车型识别码」「服务单次收费标准」「供应链供货周期」，单位涵盖「元/次」「天」等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
汽车服务研报的多来源特性要求HTTP接口支持多数据源聚合调用，需兼容不同第三方机构的鉴权协议。不同更新节奏的研报需要差异化的缓存配置，新车类数据缓存时长需适配上市节点，季度类数据可设置更长周期。特定字段如「车型识别码」「服务收费标准」的单位与格式要求严格，接口需内置字段校验逻辑，拦截不符合格式的请求参数。长文档场景下，接口需支持分页返回或内容截断配置，避免单次返回数据量过大导致下游系统超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `recallCount` | 前10–15条 | 汽车服务研报单篇内容较长，过多召回会增加接口响应耗时 |
| `requestTimeout` | 30–60秒 | 研报数据来源多为第三方API，部分机构接口响应较慢 |
| `apiAuthSecureMode` | 密钥托管模式 | 避免硬编码密钥到代码中，符合安全管理要求 |
| `fieldFormatCheck` | 开启 | 汽车服务研报字段包含特定单位与识别码，校验可减少下游解析错误 |
| `cacheExpireTime` | 7–30天 | 按研报类型区分，新车类设为7天，季度类设为30天 |
| `responseTruncateLength` | 8000–12000字符 | 适配下游系统的内容接收上限，避免数据溢出 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：接口调用返回`401 Unauthorized`错误，且日志显示鉴权密钥未正确传递。原因：未使用平台提供的统一密钥托管配置，将密钥硬编码到外部系统中，导致密钥更新后无法同步生效。
- 现象：对接MCP工具时，部分研报文件无法被自动解析。原因：未将`allowedUploadFileTypes`配置为覆盖所有支持的研报格式，仅开放了部分常见类型。
- 现象：配置第三方API密钥后接口返回`500 Internal Server Error`，提示令牌无效。原因：未区分不同模型的调用密钥，将统一令牌直接填入单模型接口配置中，导致鉴权不匹配。

## 怎么确认配好了
- 调用测试接口传入已知的车型识别码，检查返回结果中是否包含对应研报的核心字段。
- 查看平台的鉴权日志，确认接口调用时传递的密钥为托管配置中的密钥，不应采用硬编码值。
- 上传不同类型的研报文件，检查是否全部被自动识别并解析，无格式报错。
- 模拟不同更新节奏的研报数据请求，检查缓存是否按预期生效，过期数据未被召回。
