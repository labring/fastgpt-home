# 涂料油墨研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
涂料油墨研报的数据源涵盖行业公开分析文档、上下游供应链调研记录、专项品类性能测试报告。更新节奏以月度常规更新为主，遇原料调价、环保政策调整时追加临时报告。单份报告包含原料参数、产能分布、成本核算、下游应用分布等内容，字段多为专用化工指标，包括固含量数值、VOC排放量数值、每吨成品原料消耗系数，单份文档篇幅多在5000到15000字区间。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据源分散且包含结构化与非结构化混合格式内容，要求接口支持多类型数据的统一检索与解析。更新频率波动较大，需适配临时报告的实时同步需求，避免缓存过期或过久导致数据滞后。专用字段与术语较多，接口需支持按自定义专业字段过滤检索结果，同时保证分块解析时不破坏术语的上下文关联。文档篇幅较长，分块处理时需平衡语义完整性与检索效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_CHUNK_MAX_SIZE` | 800–1200 字符 | 涂料油墨研报段落内容密集且含大量专业术语，该取值可保留语义完整性，避免分块断裂 |
| `PARSE_CHUNK_OVERLAP` | 150–200 字符 | 专业术语跨段落出现概率较高，重叠分块可保留上下文关联，提升检索准确性 |
| `RECALL_TOP_N` | 前8–12条 | 研报数据维度较多，需召回足够数量的相关片段以覆盖完整分析逻辑 |
| `SIMILARITY_THRESHOLD` | 0.72–0.78 | 过滤低相关性的通用化工表述，精准匹配涂料油墨专用术语 |
| `API_REQUEST_TIMEOUT` | 60 秒 | 研报检索需聚合多源数据，该时长可覆盖常规查询的计算耗时 |
| `CACHE_TTL` | 3600 秒 | 原料与市场数据以月度更新为主，缓存时长适配更新节奏，减少重复请求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用接口返回`400 Bad Request`错误，提示缺少`dataId`参数。原因：未提前获取目标知识库的唯一标识`dataId`，未在请求体中携带正确的知识库参数。
- 检索结果片段语义断裂，无法关联涂料油墨专用的专业术语。原因：分块大小设置过小，未覆盖跨段落的术语组合，破坏了专业内容的上下文逻辑。
- 接口返回`504 Gateway Timeout`错误。原因：API请求超时设置过短，未适配多源研报聚合与专业数据解析的计算耗时。

## 怎么确认配好了
- 调用测试接口，携带目标知识库的`dataId`与涂料油墨相关检索词，核对返回结果中是否包含该品类专属的专业数据字段。
- 查看知识库解析日志，确认分块后的片段长度与重叠参数匹配预设配置，无术语截断情况。
- 发起批量测试请求，核对接口返回状态码均为200，无超时或异常报错。
- 手动比对检索结果与原始研报内容，确认召回片段的语义连贯性符合预期。
