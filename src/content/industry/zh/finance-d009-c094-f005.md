# 炼化研报检索的多轮对话与提示词

## 这个品类的数据长什么样
炼化研报数据主要来自石油石化行业专业研究机构、炼化企业内部工艺与运营文档、行业协会月度或季度监测报告。文档结构包含装置运行参数、原料加工配比、能耗排放指标、产能规划细节等字段，单位多为吨、千克标油、百分比、立方米等工业标准单位。更新节奏因报告类型不同，行业公开报告按季度更新，企业内部运营文档随工艺调整不定期更新。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
炼化研报的专业参数带有专属工业单位，多轮对话需保留单位上下文，避免不同装置的负荷、产能数值混淆。文档按工艺环节分层，多轮对话需按装置、能耗等维度拆分提问，提示词需限定检索范围为对应细分模块。更新节奏差异明显，多轮对话需支持动态指定报告时间区间，避免调用过时数据。专业字段集中度高，提示词需预置行业术语映射规则，降低检索偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 前8000–12000 字符 | 炼化研报单篇文档长度较长，需保留足够上下文支撑多轮追问 |
| `similarityThreshold` | 0.75–0.85 | 炼化专业术语匹配精度要求高，需过滤低相关的通用行业内容 |
| `reRankTopN` | 前6–10 条 | 炼化研报的专业参数需精准匹配，过多召回会干扰多轮对话逻辑 |
| `maxDialogHistory` | 前10–15 轮 | 多轮对话中需保留装置编号、时间范围等关键上下文，避免丢失核心提问条件 |
| `promptTemplate` | 按“装置名称+参数类型+时间范围”格式检索，返回带单位的精准数据 | 炼化研报的字段与单位绑定紧密，需明确提示词约束检索规则 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 炼化研报多为长文档，解析需足够时间完成分段与字段提取 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用外部插件或嵌套应用后，对话日志字段为空。未开启`enableDialogLog`配置项，工作流调用环节未同步对话上下文至日志存储模块。
- 表单输入节点在独立工作流中触发时对话框隐藏，嵌套到其他工作流时对话框仍显示。嵌套工作流的`dialogMode`配置未设置为适配父应用的规则，继承了原节点的默认弹窗触发逻辑。
- 多轮对话中返回的研报数据单位不一致，出现吨与千克标油混用的情况。提示词未明确限定单位匹配规则，导致检索结果未按字段绑定对应工业单位。

## 怎么确认配好了
- 发起包含装置名称、参数类型的多轮提问，核对返回结果是否包含与字段绑定的专业单位。
- 触发工作流调用外部应用，查看日志存储模块是否生成对应对话记录条目。
- 调整`similarityThreshold`等配置项的取值，核对召回结果的专业术语匹配度是否符合预期。
- 嵌套表单输入节点到其他工作流，验证对话框是否按父应用的规则显示或隐藏。
