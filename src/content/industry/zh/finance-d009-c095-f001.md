# 热力研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
热力研报的数据主要来自公用事业行业监管公开文件、热力供应主体的季度经营披露、第三方公用事业行业数据库。更新节奏以季度定期研报为主，搭配突发政策或供需变动后的临时研报。单篇文档结构包含行业整体态势、热力供应核心指标、政策影响分析、市场预测四部分，核心字段包括`供热总量`（单位：吉焦）、`供热覆盖面积`（单位：平方米）、`单位供热成本`（单位：元/吉焦），附带发布机构、发布日期、关联政策编号等元数据。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
热力研报的多来源特性要求外部系统对接时需兼容不同数据源的格式差异，需在HTTP接口中配置格式转换参数。固定更新节奏与临时更新并存的特点，要求接口支持定时拉取与事件触发拉取两种模式，避免无效请求占用资源。核心字段带有明确单位的特性，要求接口返回数据时需携带标准化单位信息，避免外部系统出现单位不匹配的计算错误。文档结构固定的模块划分，要求接口支持按模块定向召回，提升检索效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `rag_recall_fields` | `["供热总量", "供热覆盖面积", "单位供热成本"]` | 匹配热力研报的核心检索字段，覆盖用户对行业关键指标的查询需求 |
| `rag_cache_ttl` | `7 * 24 * 3600 秒` | 适配热力研报以季度更新为主的节奏，平衡数据时效性与请求资源占用 |
| `api_request_timeout` | `30 秒` | 适配多数据源格式转换的耗时需求，避免请求中途中断 |
| `rag_recall_count` | `3–5 条` | 单篇热力研报核心指标集中，少量召回即可满足多数查询场景 |
| `unit_conversion_enabled` | `true` | 热力研报核心字段带有标准化单位，开启转换可适配外部系统的单位要求 |
| `event_trigger_sync` | `["policy_change", "supply_fluctuation"]` | 临时研报多由政策或供需变动触发，按事件触发可及时同步最新内容 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：HTTP接口返回`400 Bad Request`错误，提示字段单位不匹配。原因：未开启`unit_conversion_enabled`配置，直接返回原始单位与外部系统要求不一致。
- 现象：外部系统调用接口后出现无限重试或进程重启。原因：未设置合理的`api_request_timeout`，超时后未正确捕获异常，导致重复发起请求。
- 现象：本地部署后接口调用报错`token encoder not found`，进程反复重启。原因：未正确配置外部系统的鉴权参数，导致接口校验失败后持续重试。

## 怎么确认配好了
- 发起单次HTTP接口调用，检查返回数据的字段是否包含预设的核心指标与标准化单位，核对字段名称与配置的`rag_recall_fields`一致。
- 模拟定时拉取请求，验证缓存周期内的重复调用是否返回相同结果，超出缓存周期后是否自动更新数据。
- 触发模拟的政策变动事件，验证事件触发同步是否能拉取到最新的临时研报内容。
- 调用接口后捕获异常日志，确认超时、鉴权等错误被正确处理，未出现进程重启或无限重试的情况。
