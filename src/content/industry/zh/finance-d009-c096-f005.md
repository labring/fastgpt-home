# 焦炭研报检索的多轮对话与提示词

## 这个品类的数据长什么样
焦炭研报数据主要来自行业协会监测数据、券商专题报告、期货交易所公开行情及钢厂生产公开信息。更新节奏分日度现货价格数据、周度行业库存与开工率报告、月度供需平衡表及季度策略研报。文档结构通常包含核心逻辑推导、供需端核心指标、价格走势复盘、后市展望四部分。核心字段包含产能（单位：万吨/年）、现货价格（单位：元/吨）、港口库存（单位：万吨）、钢厂开工相关统计数值。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
焦炭研报的多源数据口径差异，要求多轮对话中需先校验数据来源与统计口径，避免跨报告混淆指标。日度现货数据与月度供需报告的更新节奏差异，要求多轮对话需支持按时间范围筛选召回的研报，避免陈旧数据干扰。核心字段的单位多样性，要求提示词需明确统一输出单位，避免单位混用导致的误解。单篇专题研报内容较长，要求多轮对话需限制上下文窗口的召回长度，避免超出模型处理上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `recallNum` | 前10-15条 | 焦炭研报核心指标分散在多篇报告中，需召回足够数量覆盖供需、价格、库存等核心维度 |
| `similarityThreshold` | 0.75-0.85 | 焦炭研报存在大量同主题但口径不同的内容，需过滤低相似度的无关报告，保留高匹配度的有效信息 |
| `rerankTopN` | 前5-8条 | 经初召回的研报需重排筛选最相关的核心内容，避免多轮对话中出现冗余信息干扰 |
| `contextWindowSize` | 8000-12000 字符 | 单篇焦炭专题研报内容较长，需限制上下文窗口长度，适配多数大模型的处理上限 |
| `recallTimeRange` | 最近90天 | 焦炭行业供需变化较快，超过90天的研报参考价值较低，可过滤过时内容 |
| `promptTemplate` | 固定加入「需统一标注所有指标单位，优先使用最新日期的研报数据」 | 适配焦炭研报的单位多样性与更新频率要求，明确多轮对话的输出规则 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调试预览界面选择本地部署的大模型，实际调用时切换为其他模型。原因：未在`defaultLLM`配置项中指定本地模型的唯一标识，或第三方中转服务的模型映射配置错误。
- 现象：上传包含焦炭研报的json文件后，对话中出现内容截断或参数报错。原因：未调整`UPLOAD_FILE_MAX_SIZE`或`maxContext`参数，超出默认的字符数限制。
- 现象：关联多个焦炭研报知识库后，召回结果条数未达预期。原因：未设置合理的关联知识库总容量阈值，或`recallNum`配置低于关联知识库的总数量，导致部分知识库未被充分召回。

## 怎么确认配好了
- 发起单轮针对性查询，核对返回结果的指标单位与数据时间范围符合预设配置。
- 启动连续多轮对话，核对上下文信息被正确承接，未出现内容丢失或混淆。
- 调整关联知识库的数量，核对召回结果覆盖所有新增的目标知识库。
- 上传测试用研报文件，核对文件解析与上传流程未出现异常报错。
