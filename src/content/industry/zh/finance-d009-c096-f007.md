# 焦炭研报检索的工作流编排

## 这个品类的数据长什么样
焦炭研报的数据主要来自中国炼焦行业协会、大连商品交易所、大宗商品资讯机构与券商大宗商品研究团队。行业协会的月度运行报告每月固定发布，交易所仓单周报每周更新，券商研报随行业突发事件实时发布，无固定周期但高频场景下每日可产出多篇。文档结构包含行情摘要、供需数据、价格走势与政策解读，内嵌结构化表格与图表，核心字段包括出厂含税价（单位元/吨）、港口库存（单位万吨）、炼焦煤采购成本（单位元/吨）与钢厂日均消耗量（单位万吨/天）。

## 这些特征在「工作流编排」这一环带来什么约束
焦炭研报的多源属性与差异化更新节奏，要求工作流同时配置定时触发与事件触发节点，分别适配固定周期的行业报告与实时突发研报。文档内嵌的结构化数据与图表，要求工作流加入OCR解析与结构化抽取节点，避免遗漏关键数值信息。行业数据与钢铁产业链强绑定的特性，要求添加跨数据源关联节点，联动钢材相关研报做交叉验证，提升回答的完整性。此外，专业术语密集的文本结构，要求调整分段与召回规则，避免语义断裂或无关内容混入。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 焦炭研报常包含多页结构化表格与嵌入图表，解析耗时显著高于通用文档 |
| `分段长度` | `800–1200 字符` | 焦炭行业术语密集且长句较多，该区间可平衡语义完整性与召回精度 |
| `召回条数` | `前 8–12 条` | 焦炭研报数据密度高，过多召回会超出上下文窗口限制，过少会遗漏核心供需数据 |
| `相似度阈值` | `0.72–0.80` | 焦炭行业术语专业性强，需较高匹配精度避免无关行业研报被误召回 |
| `重排返回条数` | `前 4–6 条` | 聚焦最相关的核心研报内容，控制单轮回答的信息密度 |
| `定时任务触发间隔` | `每日 1 次`、`每周 1 次` | 匹配实时行情数据每日更新、行业协会月度报告每周同步的更新节奏 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：执行工具调用节点后流程停滞，无报错日志但无返回结果。原因：未正确配置大宗商品数据源的连接参数，或`TOOL_DB_CONNECT_TIMEOUT`取值过短，无法适配焦炭行业API的常规响应延迟。
- 现象：发布后的分享链接指向本地调试地址，无法通过公网访问。原因：部署环节未替换默认的本地域名配置，误将本地运行地址作为发布链接。
- 现象：召回的研报结果未附带原文件的在线预览入口。原因：未开启知识库的「保留原文件关联」配置，或工作流中未添加原文件链接提取节点，无法将切片内容与源文档绑定。

## 怎么确认配好了
- 执行单次手动触发的工作流，检查工具调用节点是否正常返回焦炭行情与研报数据，根据返回结果调整相似度阈值与召回条数。
- 查看部署配置页面，确认公网域名已正确配置，验证发布后的分享链接可正常访问。
- 进入知识库管理页面，确认「保留原文件关联」选项已开启，随机抽取一条召回结果，检查是否附带原文件预览链接。
- 查看定时任务日志，确认每日与每周的数据源抓取节点按预期触发，无超时或失败记录。
