# 焦煤研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
这个品类的数据主要来自券商煤炭行业研究团队、专业煤炭咨询机构及国内煤炭行业协会。更新节奏分为多个层级，现货挂牌价格数据每日更新，行业供需动态周报每周发布，季度供需平衡分析报告按月更新。单篇文档通常包含发布主体、发布时间、核心研判结论、主焦煤产地挂牌价（单位：元/吨）、主焦煤质量参数、下游焦化与钢铁行业开工动态等内容，字段多围绕焦煤的交易价格、质量指标与行业联动数据展开。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
焦煤研报的数据特征对接口与外部系统带来多重约束。高频更新的现货价格数据要求接口支持短周期拉取，需配置合理的请求频率阈值，避免触发上游数据源的限流规则。多维度的行业分析内容需要接口支持按发布时间、关键词、报告类型进行组合筛选，因此接口参数需覆盖多条件查询能力。焦煤相关字段多绑定质量指标与交易价格，接口需返回结构化的键值对格式，减少外部系统解析成本。单篇报告篇幅跨度较大，接口需支持分页拉取，避免单次返回数据量超出外部系统处理上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `rag_recall_top_k` | 前8-12条 | 焦煤研报的核心数据集中在少量相关段落，过多召回会引入无关内容，提升检索精准度 |
| `api_request_timeout` | 600 秒 | 长文档的解析与召回需要较长处理时间，避免提前超时中断请求 |
| `external_source_filter_keywords` | `["焦煤", "主焦煤", "焦化厂", "煤炭供需"]` | 精准过滤与焦煤细分品类相关的研报内容，减少无效召回的文档数量 |
| `parse_chunk_size` | 800–1200 字符 | 焦煤研报的专业术语较多，适中的分段长度可保留上下文关联，提升检索准确性 |
| `api_rate_limit_per_minute` | 30–50 次 | 适配上游数据源的高频请求限流规则，避免触发访问限制 |
| `global_variable_default` | `{"commodity_type": "焦煤"}` | 固定检索的品类维度，减少外部调用时的重复参数传入 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用外部接口时，界面显示「渠道不可用」，且接口测试返回`401 Unauthorized`状态码。原因：配置的访问令牌未正确关联焦煤研报检索所需的接口权限，或令牌的有效期已过期。
- 现象：检索返回的研报包含大量非焦煤品类的煤炭文档，结果相关性不足。原因：未配置`external_source_filter_keywords`参数，或参数未包含焦煤相关的精准关键词。
- 现象：长文档解析任务提前中断，返回`504 Gateway Timeout`或`500 Internal Server Error`提示。原因：`api_request_timeout`参数设置过短，未适配焦煤研报长文档的解析与召回耗时。

## 怎么确认配好了
- 调用接口传入焦煤专属关键词，核对返回结果是否包含焦煤价格、质量参数等专属字段，确认过滤规则生效。
- 发起短周期连续请求，核对是否触发限流类报错，确认请求频率阈值设置适配上游数据源规则。
- 传入指定发布时间范围的筛选参数，核对返回结果的时间覆盖是否符合配置条件，确认多条件查询功能正常。
- 拉取单篇长文档的完整内容，核对是否能正常解析并返回，确认分页与超时配置适配文档篇幅。
