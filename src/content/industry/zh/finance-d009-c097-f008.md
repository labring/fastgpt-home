# 焦煤研报检索的工具调用与插件

## 这个品类的数据长什么样
焦煤研报数据主要来自中国煤炭工业协会焦煤分会、大连商品交易所、头部券商行业研究团队及上市煤企公开披露的公告。数据更新节奏分为三类：行业供需、价格类数据每日或每周更新，政策动态随发布实时更新，券商专题研报按月度或重大事件节点发布。文档结构通常包含核心供需指标（产量、港口库存、进口量）、价格指数（单位为元/吨）、下游钢铁与火电行业需求测算、政策解读模块，部分研报会附加区域运输成本测算表格。

## 这些特征在「工具调用与插件」这一环带来什么约束
焦煤研报的多源数据更新节奏差异，要求工具调用需支持按数据源类型配置触发时机；价格、供需类字段固定使用元/吨、万吨作为单位，需在插件中预设字段校验规则，过滤非标准单位的返回内容；下游钢铁、火电行业的联动分析，需要工具调用时同步关联对应行业的知识库片段，无法仅依赖焦煤自身数据完成完整分析；单篇研报文本长度较长，需限制单次召回的文本总量，避免超出模型上下文窗口。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前8条` | 焦煤研报单篇核心内容约1000-2000字符，8条召回可覆盖单轮提问的核心信息且不超出模型上下文窗口 |
| `字段校验开关` | `开启` | 焦煤研报的价格、供需字段固定使用元/吨、万吨作为单位，开启后可过滤不符合单位规范的返回内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 部分批量研报解析需要较长处理时间，900秒可覆盖多数大文档的处理流程 |
| `上下文关联召回` | `开启，关联钢铁/火电知识库` | 焦煤下游需求与钢铁、火电行业强相关，需同步召回对应领域的知识库片段完成完整分析 |
| `文本分段长度` | `1000–1200 字符` | 焦煤研报的核心数据段落多为1000字符左右，分段后可提升召回精准度 |
| `触发模式` | `按用户提问触发` | 用户提问多为实时的焦煤价格、供需分析需求，按提问触发可确保返回最新更新的数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用焦煤研报插件后，返回的价格数据单位混乱，部分显示为元/千克。原因：未开启`字段校验开关`，未预设焦煤研报的单位校验规则，导致插件返回非标准单位的内容。
- 现象：在工作流中使用`文本内容提取`插件并配置`聊天记录：6条`时，提取的文本片段未包含下游行业联动分析内容。原因：未在插件配置中开启上下文关联召回，仅提取了焦煤自身的文本片段，未同步关联钢铁、火电领域的知识库内容。
- 现象：调用批量焦煤研报解析时返回`504 Gateway Timeout`错误。原因：配置的`PARSE_FILE_TIMEOUT_SECONDS`取值不足，无法覆盖批量文档的解析时间。

## 怎么确认配好了
- 发起一条焦煤价格相关的提问，查看返回结果中的价格字段单位是否统一，核对字段校验规则是否生效。
- 测试多模态调用焦煤研报附带的图表，确认无格式错误提示，核对图片格式配置是否符合要求。
- 查看工作流运行日志，确认插件触发时机与用户提问同步，上下文关联召回已正常启用。
- 测试批量解析多篇焦煤研报，确认解析耗时未超出配置的超时时间参数。
