# 焦煤研报检索的知识库检索与召回

## 这个品类的数据长什么样
焦煤研报的数据来源涵盖行业协会焦煤分会、期货交易所、券商煤炭行业研究团队、大型焦煤生产企业公开披露信息。常规研报按周、月度周期发布，突发政策调整、供需异动时会生成临时专项研报。文档结构包含研报标题、发布机构、发布日期、核心供需数据表格、价格走势分析、上下游产业链关联内容，附带焦煤的灰分、硫分、胶质层厚度等质量参数。字段包括研报主题、发布时间、核心数据摘要、产业链关联指标等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
焦煤研报的多源分散属性要求检索系统支持跨渠道数据的关联召回，避免出现数据孤岛。更新节奏的差异则要求区分定期与临时研报的索引触发逻辑，保障最新内容及时同步。文档内大量结构化表格的存在，会导致普通文本拆分方式丢失表格内的指标关联语义，因此需要专门的表格解析支持。此外，焦煤研报侧重专业产业链指标，检索时需精准匹配细分术语，避免与其他煤炭品类的研报内容混淆，对召回的相关性过滤提出了更高要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_TABLE_ENABLE` | 开启 | 焦煤研报包含大量结构化供需、质量指标表格，开启后可保留表格内的语义关联信息 |
| `RECALL_CHUNK_SIZE` | 800–1200 字符 | 焦煤研报的分析段落多包含完整的供需逻辑单元，该长度可保留上下文关联 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 单份焦煤研报合集通常包含多份历史报告，需支持较大文件批量上传 |
| `INCREMENTAL_INDEX_INTERVAL` | 6 小时 | 焦煤常规研报以周度更新为主，6小时增量索引可及时同步最新发布的研报内容 |
| `SIMILARITY_THRESHOLD` | 0.72–0.78 | 焦煤研报专业术语密集，该阈值可过滤低相关的通用煤炭行业内容 |
| `RERANK_TOP_N` | 前 8 条 | 焦煤产业链关联数据较多，需通过重排筛选最贴合检索需求的研报片段 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：重启服务器后知识库状态显示「未就绪」，无自动索引进度，仅手动触发索引后才可恢复。原因：未配置`AUTO_REINDEX_ON_RESTART`参数，默认逻辑下重启后不会自动触发重新索引。
- 现象：导入的焦煤研报内的结构化表格内容无法被正常提取，检索时无对应指标字段的结果。原因：未开启`PARSE_TABLE_ENABLE`配置，表格内容被拆分为零散文本，丢失了指标关联语义。
- 现象：调用知识库发起焦煤相关检索时，返回结果耗时超过15秒，部分请求触发`504 Gateway Timeout`错误。原因：召回条数设置过高且未启用增量索引，全量检索大量历史研报导致处理耗时过长。

## 怎么确认配好了
- 上传一份标准焦煤研报，查看解析结果中的表格与字段是否完整，确认`PARSE_TABLE_ENABLE`配置已生效。
- 手动触发一次增量索引，等待配置的`INCREMENTAL_INDEX_INTERVAL`时长后，检查知识库是否自动同步新上传的研报，确认定时索引逻辑正常运行。
- 发起一次焦煤供需或质量指标相关的检索，查看返回结果的相关性与条数，调整`SIMILARITY_THRESHOLD`与`RERANK_TOP_N`直至符合检索需求。
- 模拟服务器重启操作，检查知识库是否自动恢复索引状态，确认`AUTO_REINDEX_ON_RESTART`配置正确。
