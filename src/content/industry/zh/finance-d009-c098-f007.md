# 煤化工研报检索的工作流编排

## 这个品类的数据长什么样
煤化工研报主要来自行业协会官方发布、券商行业研究团队、专业咨询机构报告及上市公司定期公告。更新节奏随行业政策调整、产能数据更新及季度行业复盘动态调整，无固定周期，但核心行业报告多按季度发布。文档结构通常包含行业整体概览、细分工艺路线分析、产能与产量数据、成本测算模型、政策解读及市场展望，字段包含统计周期、产能单位（万吨/年）、成本单位（元/吨）、项目投资金额（亿元）等标准化数值字段，以及报告发布日期、发布机构等元数据。

## 这些特征在「工作流编排」这一环带来什么约束
煤化工研报多源异构的来源要求工作流配置多源数据接入节点，需对不同机构发布的研报做格式统一与去重处理。非固定更新节奏要求工作流支持定时触发与手动触发双模式，保障最新研报及时同步。文档包含多细分工艺分支的内容，要求配置条件分支节点，根据研报的工艺类型（如煤制烯烃、煤制天然气）分流至对应处理环节。多样的数值字段与单位要求配置字段映射节点，统一不同来源的产能、成本等数据的单位与格式，避免后续检索与问答环节出现单位混乱。单篇研报篇幅较长的特点，要求工作流配置文本拆分节点，避免超出模型上下文窗口限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 煤化工研报单篇篇幅多在5000-10000字符，预留足够上下文容纳完整研报片段与提问 |
| `召回条数` | `前8–12 条` | 煤化工细分领域专业度高，核心相关研报数量有限，过多召回会引入无关内容 |
| `相似度阈值` | `0.75–0.85` | 煤化工细分术语多，需过滤低相关的非专业研报，避免检索结果冗余 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 单篇煤化工研报篇幅较长，解析过程需足够时间完成文本拆分与元数据提取 |
| `定时触发间隔` | `7 天` | 核心行业研报按季度更新，每周同步可保障数据时效性，同时避免过度占用资源 |
| `重排返回条数` | `前4–6 条` | 对召回的研报做二次重排后，保留最相关的4-6条用于问答生成，平衡准确性与响应速度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：使用v4.8.10及以上版本的API调用工作流时，返回空响应内容，状态码为200。原因：工作流中嵌套的知识库助手节点未正确关联煤化工研报专属知识库，或未配置数据源同步触发。
- 现象：在工作流中引用知识库字段时弹出`quote type error`报错提示。原因：引用的变量类型与目标节点的输入要求不匹配，例如将数值型的产能数据直接传入文本生成节点，未完成类型转换。
- 现象：尝试将多个上游分支接入同一节点时，链路无法正常连接。原因：未开启工作流节点的多链路接入权限，默认配置下多数节点仅支持单上游链路接入。

## 怎么确认配好了
- 手动上传一篇煤化工研报，触发工作流检索，核对返回结果是否包含该研报的核心内容。
- 查看工作流的日志面板，确认定时触发任务按设定间隔执行，无解析超时或接入失败记录。
- 测试变量引用功能，输入预设的煤化工行业术语，确认无`quote type error`报错。
- 切换多个上游分支触发条件分支节点，确认节点可正确接收并分流不同类型的研报数据。
