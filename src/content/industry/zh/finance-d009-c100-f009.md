# 物业管理研报检索的引用来源与溯源

## 这个品类的数据长什么样
物业管理研报的数据来源包含住建部门发布的物业行业监管文件、全国及地方物业管理协会的行业标准文档、物业公司内部运营台账、第三方物业市场调研报告与公开的物业项目招投标文件。数据更新节奏因来源不同存在差异，监管文件与行业标准按季度或年度更新，内部运营台账随日常服务数据实时同步，招投标文件随项目发布即时更新。文档结构通常包含项目基础信息、运营数据、合规要求三类字段，字段单位多为平方米、元/平方米·月、服务人次等物业领域专用单位，部分内部台账文档存在非标准化的自定义字段。

## 这些特征在「引用来源与溯源」这一环带来什么约束
来源分散的特性要求溯源环节需区分私有知识库（如物业公司内部运营台账）与公共数据源（如住建部门监管文件、行业协会文档），避免混淆不同权限的引用内容。更新节奏的差异则要求配置增量更新与全量更新的触发规则，确保实时数据与静态文档的溯源信息同步准确。文档中的专用字段与非标准化自定义字段，要求溯源环节需匹配原始文档的字段结构，仅依赖文本关键词匹配无法覆盖全部匹配场景。同时，物业研报常被金融机构用于信贷风控评估，需精准到单篇文档的具体条目，仅标注文档整体来源无法满足合规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `相似度阈值` | 0.75-0.85 | 物业管理研报包含大量专业术语与近似数值表述，该区间可平衡召回精度与覆盖范围 |
| `召回条数` | 前8-12条 | 物业研报数据源分散，需足够召回量覆盖不同来源的合规与运营数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300秒 | 大型物业运营台账文档的结构化解析耗时较长，默认时长不足以完成完整解析 |
| `maxContext` | 2000-3000字符 | 单篇物业研报包含多组关联运营数据，足够的上下文可确保引用溯源的关联性准确 |
| `重排返回条数` | 前5条 | 需保留最相关的溯源条目，避免冗余信息干扰业务判断 |
| `ENABLE_SOURCE_CITATION` | 开启 | 物业研报的合规性要求高，必须明确标注每条引用的来源信息 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 将`相似度阈值`设置为1时，仍返回大量非精准匹配的引用内容。原因是部分物业研报的相似字段（如服务面积）存在近似数值表述，系统默认的语义匹配逻辑未严格区分精确数值与近似值，导致低阈值下仍出现模糊匹配结果。
- 导入Notion格式的物业研报后，溯源链接无法正常跳转。原因是未配置Notion数据源的访问权限，系统无法获取公开或授权的文档内容，导致溯源链接失效。
- 解析批量物业台账文档时出现超时报错。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认的解析时长不足以完成批量文档的结构化处理。

## 怎么确认配好了
- 发起针对特定物业项目的研报查询，检查响应结果中是否附带每条引用条目的来源标题、发布时间与访问路径。
- 导入单篇标准化物业研报文档，验证解析后的字段是否与原始文档的基础信息、运营数据项完全匹配。
- 调整`相似度阈值`参数，验证查询结果的引用相关性是否随参数调整发生符合预期的变化。
- 触发单篇大型物业台账文档的解析任务，确认解析过程未出现超时报错。
