# 环境监测研报检索的工具调用与插件

## 这个品类的数据长什么样
环境监测研报的数据主要来自生态环境部门公开监测站点、第三方环境监测机构的公开报告、行业协会发布的行业分析文档。数据更新节奏覆盖实时小时级的单点位监测数据、月度/季度的区域综合分析研报。单篇研报的文档结构通常包含监测点位信息、污染物浓度数值、超标情况说明、成因分析与对策建议。字段包含点位编号、监测时间、污染物类型（如PM2.5、COD）、浓度值、对应单位（如μg/m³、mg/L）、监测仪器型号等。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散的特征要求工具调用需配置多源聚合插件，适配不同数据源的接口格式。小时级的更新节奏要求同步插件的周期需匹配数据更新频率，避免获取过时或未更新的研报内容。复杂的文档结构与特殊字段单位，要求工具调用时需配置精准的字段提取规则与单位转换逻辑，确保提取的信息符合业务需求。多维度的监测字段也要求工具调用的上下文窗口需适配长文本的处理需求，避免截断关键信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `TOOL_SYNC_FREQUENCY` | `3600 秒` | 匹配环境监测研报的小时级更新节奏，确保数据同步频率与数据源更新周期对齐 |
| `PARSE_DOC_FIELD_MAPPING` | `{"监测点位":"site_id","污染物浓度":"concentration","单位":"unit"}` | 适配环境监测研报的标准字段结构，确保工具调用时能精准提取目标业务字段 |
| `max_context_window` | `8000–12000 字符` | 适配环境监测研报单篇较长的文本长度，满足工具调用的长上下文处理需求 |
| `tool_call_timeout` | `120 秒` | 覆盖多源数据聚合时的接口请求耗时，避免因超时中断工具调用流程 |
| `unit_convert_enable` | `开启` | 适配环境监测数据的多单位场景，自动转换为统一单位供工具调用使用 |
| `retrieve_top_k` | `前8条` | 覆盖不同监测维度的研报结果，避免过多冗余信息干扰工具调用逻辑 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用工具时返回`400 Messages with role 'tool' must be a response to a preceding message`错误。原因：工具调用的上下文未正确关联前置的研报检索请求，未按流程完成上下文绑定。
- 现象：工具调用返回的监测数据字段为空。原因：未配置`PARSE_DOC_FIELD_MAPPING`的精准映射规则，导致无法从研报中提取目标业务字段。
- 现象：工具调用的代码模块运行失败，提示缺少依赖库。原因：未提前安装对应环境监测数据处理的Python依赖库，未在部署环境中配置正确的依赖版本。

## 怎么确认配好了
- 查看工具调用日志，确认`TOOL_SYNC_FREQUENCY`的同步周期与环境监测数据的更新节奏匹配。
- 调用测试工具，检查提取的监测数据字段是否与`PARSE_DOC_FIELD_MAPPING`的配置一致。
- 运行本地代码模块，确认依赖库已正确安装且版本符合配置要求。
- 分别发起在线对话与API调用，核对`stream`与`detail`参数的设置是否统一。
