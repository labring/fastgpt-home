# 电商服务研报检索的工作流编排

## 这个品类的数据长什么样
电商服务类研报数据来源为电商平台官方披露的行业分析文档、合规第三方电商数据服务机构的公开研报。更新节奏为每季度发布常规行业研报，大促节点前会发布专项监测报告。单篇文档通常包含行业整体概况、核心类目表现、头部品牌数据、用户消费特征、未来趋势预判等模块，结构化字段包含交易总额、客单价、上架SKU数量、活跃店铺数，对应单位分别为亿元、元、个、家。

## 这些特征在「工作流编排」这一环带来什么约束
电商服务研报的来源分散且更新节奏不固定，导致工作流需支持多源数据拉取的动态触发，无法仅依赖固定定时任务。单篇研报篇幅较长且包含多模块内容，需在工作流中配置分段解析与模块筛选环节，避免大模型上下文溢出。研报包含多维度结构化字段，工作流需支持指定字段提取的节点，确保后续问答环节能精准匹配用户查询。此外，常规报告与专项报告的格式存在差异，工作流需兼容多种文档格式的解析适配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前10-15条` | 电商研报数据量较大，过多召回会导致上下文溢出，过少则无法覆盖用户查询所需的类目信息 |
| `相似度阈值` | `0.75-0.85` | 电商研报包含大量专业术语，需确保召回内容与查询的匹配度足够精准，避免无关数据干扰 |
| `分段长度` | `800-1200字符` | 单篇电商研报篇幅较长，分段后可提升解析效率，同时适配大模型的上下文窗口限制 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300-600秒` | 大型专项研报的解析耗时较长，需预留足够的超时时间避免任务中断 |
| `工作流触发模式` | `按文档更新触发+手动触发双模式` | 电商研报更新节奏不固定，需支持按需触发与定时同步结合的方式 |
| `知识库ID变量绑定` | `按研报类目绑定对应知识库` | 电商研报包含多个类目数据，通过变量绑定可实现精准的知识库召回 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：通过API调用发布后的工作流，未触发用户选择或表单输入的交互提示。原因：未在工作流中配置API触发模式下的交互节点参数，导致接口仅返回结果而不唤起交互环节。
- 现象：将v4.6.7版本的工作流导出文件导入v4.8.10版本时，出现配置丢失或节点异常的报错。原因：不同版本的工作流节点参数结构存在差异，未通过版本兼容转换工具进行导入适配。
- 现象：在工作流中配置知识库ID变量绑定时，输入变量后出现参数校验报错。原因：未按照要求为变量配置合法的知识库ID格式，或未在工作流的全局变量中提前声明该变量。

## 怎么确认配好了
- 上传一篇电商研报文档，触发工作流，查看解析后的分段内容是否符合预设的分段长度参数。
- 调用API测试工作流，检查返回结果中是否包含指定字段的结构化数据，验证知识库ID变量绑定是否生效。
- 模拟不同更新节奏的研报上传，确认工作流是否能按工作流触发模式正常触发解析任务。
- 调整相似度阈值参数，测试不同查询词下的召回结果数量，确认匹配度符合预期。
