# 综合服务研报检索的引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据来自持牌金融机构发布的公开研报、行业研究白皮书、合规理财研究文档。更新节奏随发布方的正式发布时间同步，无固定周期但核心行业研报的更新频次稳定。文档结构通常包含标题页、核心观点、数据支撑章节、附录等层级，字段包括研报唯一标识、发布机构全称、发布日期、文档类型、关键词、内容摘要、章节标题，部分文档附带统计周期单位，如季度、年度。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源为持牌合规机构，溯源环节需验证发布主体的资质，确保引用来源的合法性。研报存在多章节、多层级引用的结构，需实现段落级的精准溯源，不应采用文档级的方式，避免笼统标注文档名称。研报的字段包含唯一标识与统计周期，需通过唯一标识关联对应内容，确保溯源信息可追溯且无歧义。同时，更新无固定周期，需实时校验知识库中研报的有效性，避免返回过期或已失效的研究内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `8-12条` | 研报内容专业且篇幅较长，过多召回会导致上下文冗余，过少无法覆盖核心研究观点 |
| `相似度阈值` | `0.78-0.82` | 研报包含大量专业术语，需较高相似度确保引用内容与提问的匹配精度 |
| `source_display_format` | `{org_name} · {publish_date} · {report_title}` | 综合服务场景需清晰展示研报的发布主体、时间与标题，符合金融行业的溯源习惯 |
| `workflow_knowledge_var` | `dynamic_pass` | 支持通过API传递知识库标识变量，适配多场景下的研报检索需求 |
| `recall_filter_org` | `持牌金融机构` | 过滤非合规来源的研报内容，确保引用来源符合金融行业监管要求 |
| `parse_timeout` | `120 秒` | 研报文档篇幅较长，解析与检索过程需更长的超时时间保障完整处理 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流中配置知识库搜索节点为变量引用后，调用API传递变量无有效检索结果。原因是未启用`workflow_knowledge_var`的动态绑定配置，变量未完成与检索节点的参数映射。
- 现象为chat接口返回的引用列表顺序混乱，且未按预设格式展示来源信息。原因是未配置`source_order_mode`与`source_display_format`参数，默认规则未适配研报的结构化特征。
- 现象为检索返回的引用来源字段完整，但生成的回答未关联对应引用标记。原因是未开启基于引用的回答生成配置，上下文未正确绑定溯源段落，导致回答与引用内容脱节。

## 怎么确认配好了
- 调用API传递自定义知识库变量，核对工作流执行日志中变量映射是否正确完成。
- 发起测试提问，查看返回结果的引用来源格式是否符合预设的`source_display_format`规则。
- 调整`召回条数`配置，验证返回的引用列表数量是否匹配设定值。
- 提交包含非持牌机构关键词的测试提问，确认检索结果自动过滤了对应来源的内容。
