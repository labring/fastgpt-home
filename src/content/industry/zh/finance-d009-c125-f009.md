# 航天装备研报检索的引用来源与溯源

## 这个品类的数据长什么样
航天装备研报的数据来源主要包括国防军工行业专业研报机构、航天院所公开立项报告、官方型号试验公示文件。更新节奏随型号研发节点波动，核心节点如总装、发射前会集中更新，日常以季度/半年度行业复盘文档为主，突发任务相关研报会临时发布。文档结构包含封面页（标注型号代号、发布机构）、核心性能参数章节（含推力、轨道高度、载荷重量等字段，单位多为千牛、千米、吨）、进度节点说明、风险评估模块，部分文档附带试验数据编号作为唯一标识。

## 这些特征在「引用来源与溯源」这一环带来什么约束
航天装备研报的多源分散特性，要求溯源系统需关联多个独立知识库的内容，避免单一数据源的信息缺失。无固定更新周期的发布节奏，使得溯源环节需适配非周期性的文档入库，无法依赖固定周期的同步逻辑。文档中包含型号编号、试验数据编号等唯一标识字段，溯源通常以这些字段作为锚点，仅依赖文件名或发布机构，易出现同品类不同型号的参数混淆。长段落的参数描述与试验数据，要求分割文档时需保留参数与上下文的绑定关系，否则溯源无法定位到具体的参数来源段落。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `recall_top_k` | 前8条 | 航天装备研报参数精准度要求高，过多召回会引入无关型号数据，过少会遗漏关键溯源信息 |
| `similarity_threshold` | 0.75–0.85 | 航天装备研报参数表述严谨，阈值过低会引入非对应型号的内容，过高会遗漏关联度较高的溯源文档 |
| `chunk_max_length` | 1000–1200 字符 | 航天装备研报包含长段落的参数描述与试验数据，过长分割会破坏参数与上下文的绑定，过短会丢失溯源所需的关联信息 |
| `source_field_extract` | 提取发布机构、型号编号、发布日期 | 航天装备研报的唯一标识为型号编号，通常将这些字段作为溯源锚点，不应仅依赖文件名 |
| `sync_mode` | 增量同步（按发布日期） | 航天装备研报更新无固定周期，按发布日期同步可避免重复拉取旧文档，同时保证最新型号研报及时入库 |
| `rag_cite_enable` | 开启 | 航天装备相关决策需明确溯源依据，开启后可直接关联召回块的原始文档与段落位置 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：检索结果中出现非对应型号的航天装备参数，溯源信息显示关联了错误的研报文档。原因：未设置`similarity_threshold`的合理区间，或未开启`source_field_extract`提取型号编号作为过滤条件，导致召回结果混入同品类不同型号的内容。
- 现象：知识库搜索模块返回的引用来源字段为空，无法完成溯源。原因：未配置`source_field_extract`参数，未指定需要提取的溯源字段，导致系统无法生成有效的引用锚点。
- 现象：本地部署的FastGPT磁盘占用持续增长，超出预期。原因：未配置合理的`chunk_max_length`与`recall_top_k`，或未开启文档去重，导致原文件、分割块、嵌入向量的冗余存储量过高。

## 怎么确认配好了
- 输入某款航天装备的型号编号作为检索关键词，核对召回结果的文档是否均包含该型号编号，且引用来源字段显示正确的发布机构与发布日期。
- 查看知识库同步日志，确认仅新增了指定日期范围内的研报文档，无旧文档重复同步的记录。
- 检索包含核心参数的问题，核对返回结果中是否附带了原始文档的段落位置与文件名，可直接跳转至对应文档。
- 查看磁盘占用监控面板，确认新增文档的存储量符合预期，无异常增长。
