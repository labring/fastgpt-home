# 航空装备研报检索的向量模型与索引

## 这个品类的数据长什么样
航空装备研报的数据来源包含券商军工行业研究报告、航空装备产业链上下游企业公开公告、行业协会发布的白皮书及官方披露的型号进展信息。更新节奏分为两类，定期更新为季度、半年度行业跟踪报告，不定期更新为新机型试飞、重大订单签约、行业政策调整时发布的专项报告。单篇文档通常包含核心参数汇总表、技术迭代分析、产业链拆解、市场空间测算模块，字段包含型号名称、列装状态、最大飞行速度（单位：马赫）、最大航程（单位：千米）、单机采购成本（单位：万元/架）等专业参数与非结构化分析文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
航空装备研报的混合内容特征对向量模型与索引环节提出多重约束：首先，文档包含结构化专业参数与非技术文本的混合内容，要求向量模型需同时适配专业术语嵌入与结构化数值字段的向量化处理；其次，更新存在定期与突发两种模式，要求索引需支持增量更新与全量重建的灵活切换，避免无效的全量计算；第三，单篇文档篇幅差异较大，部分包含详细参数表格的文档长度较长，要求分段策略需保留参数表的上下文关联，避免拆分后丢失关键参数信息；第四，数据源格式多样，包括PDF格式研报、结构化表格导出文件、网页格式公告，要求索引构建前的预处理环节需兼容多种输入格式，确保数据完整提取。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunk_size` | `800–1200 字符` | 航空装备研报包含长段落技术分析与结构化参数表，该区间可保留参数与上下文的关联，避免拆分后参数断裂 |
| `chunk_overlap` | `150–200 字符` | 长参数表的跨页拆分需要重叠上下文，确保参数的完整语义传递 |
| `vector_model` | `voyage-large-2` 或 `bge-m3` | 航空装备领域存在大量专业术语，该类模型的专业领域适配性更强，可提升参数与技术文本的嵌入准确性 |
| `retrieval_top_k` | `前8–12条` | 航空装备研报的专业内容集中度较高，过多召回会引入无关信息，过少则无法覆盖关键参数与分析 |
| `max_context_length` | `4000–6000 字符` | 匹配单篇研报核心分析段落的长度，确保召回内容可完整带入大模型上下文 |
| `index_batch_size` | `按实测标定` | 不同部署环境的硬件资源存在差异，需根据实际服务器负载调整单批次处理的文档数量 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用voyage索引接口返回`400 status code no body`。原因：未针对航空装备研报的长文本设置合理的分段阈值，导致向量化请求超出模型接口的内容长度限制。
- 现象：全量重建索引时服务器读写资源耗尽，每日定时触发异常。原因：未配置增量更新策略，每次更新均执行全量索引重建，且未限制单批次处理的文档数量。
- 现象：向量库数据迁移后，检索结果出现专业参数缺失或错位。原因：迁移过程中未保留结构化参数字段的嵌入关联，仅迁移了纯文本内容，导致专业参数的语义匹配失效。

## 怎么确认配好了
- 随机选取3篇航空装备研报的核心参数段落，核对向量模型的嵌入输出，确认专业术语的语义一致性符合预期。
- 触发一次增量更新任务，核对仅新增的研报被纳入索引，未触发全量重建流程。
- 发起检索请求，输入航空装备领域专业术语，核对召回结果包含对应参数或技术分析的相关研报内容。
- 查看索引监控指标，确认内存与磁盘IO占用处于合理区间，未出现异常峰值。
