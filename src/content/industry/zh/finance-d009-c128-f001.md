# 航运港口研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
航运港口研报的数据主要来自各地港口管理机构、国际航运交易所、行业咨询机构及公开政策文件。数据更新节奏分两类：港口运营、船舶动态类数据按日或按周更新，行业趋势研报按月度、季度发布，突发航运事件相关研报即时更新。文档结构包含航线运价、泊位吞吐量、船舶停靠数据、政策解读四个核心模块，字段包含起讫港代码、货物类型、吞吐量单位（TEU或万吨）、运价单位（美元/标准箱），单篇文档长度差异较大，建议按自有样本统计或实测后再确定。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
航运港口研报的数据特征会对HTTP接口与外部系统对接带来三点核心约束。第一，多更新节奏的数据源要求接口支持增量拉取与全量同步两种模式，同时需提供时间范围筛选参数以匹配不同周期的数据需求。第二，标准化的字段与单位要求接口需内置字段校验逻辑，避免传入非标准的货物类型、吞吐量单位等参数导致数据解析失败。第三，单篇文档长度较长的特性要求接口调整分页返回的单页数据量，同时配置合理的超时阈值，防止大文档传输过程中出现连接中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | `800–1200 字符` | 航运港口研报包含大量专业术语与长句，该区间可保证术语不被拆分，同时控制单段文本的语义完整性 |
| `recallTopK` | `前 8–12 条` | 港口研报的核心信息分散在多个段落，召回过多会引入冗余数据，过少则无法覆盖完整业务问题 |
| `apiRequestTimeout` | `60 秒` | 外部数据源接口可能因批量拉取港口运营数据出现响应延迟，该阈值可覆盖多数正常请求的响应时长 |
| `vectorModelEmbedDim` | `1024` | 适配`bge-large-zh-1.5`模型的嵌入维度，保证向量检索的匹配精度 |
| `externalApiAuthType` | `API Key 鉴权` | 多数港口行业数据源接口采用密钥鉴权方式，可有效防止未授权访问 |
| `maxContextWindow` | `16384 tokens` | 适配GPT-4o-mini的上下文窗口上限，避免因输入过长触发模型报错 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用外部数据源接口返回`403 Forbidden`状态码。原因：未正确配置`externalApiAuthType`为对应鉴权方式，或未传入有效的API密钥。
- 现象：向量检索结果匹配度极低，返回的研报内容与问题无关。原因：未将`vectorModelEmbedDim`设置为与嵌入模型一致的维度，导致向量空间不匹配。
- 现象：接口请求超时，返回`504 Gateway Timeout`状态码。原因：将`apiRequestTimeout`设置过短，无法覆盖批量拉取港口吞吐量数据的响应时长。

## 怎么确认配好了
- 调用外部数据源接口，验证返回的字段包含起讫港、吞吐量、运价等核心港口研报字段，且单位符合预设标准。
- 发起向量检索测试，输入包含港口航线、吞吐量的问题，核对返回结果的相关性与召回条数是否符合`recallTopK`的设置。
- 查看接口请求日志，确认单次请求的响应时长未超过`apiRequestTimeout`的设置值。
- 测试大文档分段效果，验证单段文本未拆分专业术语，且分段长度符合`chunkSize`的配置。
