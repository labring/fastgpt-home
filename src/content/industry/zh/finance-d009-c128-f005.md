# 航运港口研报检索的多轮对话与提示词

## 这个品类的数据长什么样
航运港口行业研报主要来自券商交通运输研究团队、港口管理局公开统计报告、国际航运协会行业简报、头部航运经纪机构的市场分析文档。月度吞吐量、泊位利用率等运营数据按月更新，集装箱运价、航线班次等高频数据按周更新，专项研报随行业动态不定期发布。文档结构包含核心数据表格、政策解读、供需分析、未来展望等模块，字段包含TEU（标准集装箱单位）、万吨级泊位数量、航线覆盖区域，运价单位多为美元/FEU（40英尺集装箱单位）。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
航运港口研报的多维度更新节奏要求多轮对话中需明确区分不同时间粒度的数据，提示词需强制指定查询的时间范围，避免混淆月度运营数据与周度运价数据。专业字段与单位的特殊性要求提示词必须保留TEU、FEU等标准标识，不能随意转换表述。文档中结构化表格与非结构化分析混合的结构，要求多轮对话需保留上下文提及的港口名称、数据指标，确保追问时能关联对应内容。高频更新的实时数据与静态研报内容需在对话中区分调用来源，避免返回过时信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 航运港口研报包含多组结构化数据和长文本分析，需保留多轮对话中的港口名称、时间范围、数据指标等关键上下文 |
| `recallTopK` | `前8–12条` | 研报数据分散在多个文档片段中，需召回足够数量的相关片段覆盖不同数据维度，避免遗漏核心信息 |
| `relevanceThreshold` | `0.72–0.78` | 港口研报专业术语较多，需平衡召回相关性和覆盖度，避免因阈值过高过滤掉包含结构化表格的有效片段 |
| `rerankTopK` | `前4–6条` | 结构化数据和分析内容需精准排序，优先返回核心数据指标和行业结论，提升对话内容的实用性 |
| `chunkSize` | `1200–1500 字符` | 研报中的表格和长段落需合理分段，避免拆分破坏数据关联性，确保解析后的片段语义完整 |
| `systemPrompt` | 按实测标定 | 需针对航运港口的专业术语制定定制化提示，明确要求返回时保留标准单位、字段名称和图片链接 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：选择千问模型提交内容后弹出`connection error`提示，开启代理后仍无法解决。原因：未正确配置`PROXY_URL`参数，或参数格式不符合系统要求，导致模型请求无法正常建立连接。
- 现象：自定义对话图标未生效，仍显示默认图标。原因：未在免登录配置模块中上传符合要求的图标文件，或上传的图标格式不符合`PNG/JPG`格式与尺寸限制。
- 现象：知识库返回的研报中包含图片，但大模型仅返回文字描述，未展示图片链接。原因：未在`systemPrompt`中明确要求提取并返回图片的原始链接，或未开启知识库的图片解析功能。

## 怎么确认配好了
- 发起包含具体港口名称、月度吞吐量数据的首轮提问，核对返回结果是否关联了对应研报的核心内容。
- 发起多轮追问，例如先询问某港口的集装箱吞吐量，再追问同比变化，验证系统能否保留上一轮的港口名称和数据维度。
- 上传一份包含表格和图片的测试研报，检查解析后的片段是否保留了表格结构，且提示词触发后返回图片链接。
- 调用配置好的模型，检查控制台输出的请求日志中无`connection error`相关报错，确认网络路由正常。
