# 航运港口研报检索的工作流编排

## 这个品类的数据长什么样
航运港口研报的数据主要来源于全球港口运营机构公开财报、交通运输部水运局公开公报、波罗的海交易所行业报告及港口集团月度运营公告。更新节奏以月度常规更新为主，涉及航线调整、泊位扩容等重大事件时会实时发布补充内容。文档结构通常包含核心运营数据、航线动态、政策解读与市场预测模块，字段包含集装箱吞吐量（单位TEU）、靠泊船舶数量（单位艘次）、装卸效率（单位箱/小时）等，部分研报附带高清泊位平面图、航线运价曲线等附件，单篇文档字数跨度较大。

## 这些特征在「工作流编排」这一环带来什么约束
首先，数据更新节奏存在常规与实时两类，要求工作流支持定时拉取与事件触发的增量同步逻辑，避免遗漏突发的港口运营变动信息。其次，字段带有专属单位与特定业务含义，工作流中的信息提取节点需配置单位校验规则，防止不同港口的吞吐量、装卸效率等数据出现单位混淆。再者，部分研报附带可视化附件，工作流需额外集成图片解析节点，不能仅处理纯文本内容。此外，单篇文档长度差异较大，需配置灵活的分段长度适配不同规模的研报，批量处理多港口研报时还需设置并发控制，避免触发外部数据接口的限流规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 航运港口研报常包含大量图表与长文本，常规解析时长超出基础配置，300秒可覆盖多数长文档解析 |
| `RECALL_TOP_K` | `10-15` | 港口研报的核心业务数据字段集中，过多召回会引入无关内容，10-15条可覆盖核心信息 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 部分研报附带高清泊位平面图、航线热力图，单文档体积可达数百兆 |
| `maxContext` | `8000-12000 字符` | 单篇港口研报的核心论证部分长度较长，需保留足够上下文支撑大模型精准问答 |
| `WORKFLOW_CONCURRENCY_LIMIT` | `5` | 多数港口公开数据接口存在调用频次限制，并发数过高会触发限流报错 |
| `NODE_CONTEXT_SCOPE` | `当前节点上下文` | 港口研报的检索需精准匹配特定港口的运营数据，无需全局上下文干扰 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流解析研报后，泊位平面图等图片内容缺失。原因是未开启`PARSE_IMAGE_CONTENT`配置，或未正确设置图片解析的触发条件。
- 现象为大模型节点返回`500 Gateway forwarding error because service is disconnected`。原因是工作流中调用的外部港口数据接口未配置超时重试机制，或并发数超出接口限制导致服务断开。
- 现象为工作流返回的研报问答结果混杂其他港口的运营数据。原因是未将`NODE_CONTEXT_SCOPE`设置为当前节点上下文，使用全局上下文导致信息干扰。

## 怎么确认配好了
- 上传单篇最长的港口研报，检查解析节点是否在预设时长内完成，且图片内容正常提取。
- 发起单次研报检索请求，核对召回结果的条数符合预设范围，且仅包含目标港口的相关数据。
- 批量提交5篇以上的研报任务，检查节点执行状态是否符合并发限制要求，无异常报错。
- 查看工作流日志，确认大模型节点未出现网关转发类报错，且上下文仅关联当前节点的输入内容。
