# 融资租赁研报检索的文档解析与分块

## 这个品类的数据长什么样
融资租赁行业研报的数据主要来源于中国租赁联盟、各地租赁行业协会发布的行业汇总报告，租赁企业公开的年度、半年度财报，以及第三方咨询机构的专项调研文档。更新节奏以季度行业汇总、半年度专项分析为主，不定期发布头部企业动态研报。文档结构通常包含行业整体投放规模、单项目租赁案例、监管合规指标、租金回款数据等模块，专属字段包括租赁资产余额、售后回租项目占比、项目投放周期，单位涵盖亿元、万元、自然月。

## 这些特征在「文档解析与分块」这一环带来什么约束
行业汇总类研报篇幅较长，单份文档常包含数十个项目案例，对分块的上下文连贯性要求较高。专属字段的关联性强，单一字段常伴随配套的项目数据，分块需保留字段与对应数据的绑定关系。部分研报以扫描件形式发布，包含结构化报表与手写批注，需要同时处理文本与图像内容。更新频率的不确定性要求解析流程支持批量上传与增量更新，避免重复解析旧有数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunk_size` | 800–1200 字符 | 适配融资租赁研报中长案例与结构化数据的长度，避免拆分后丢失项目关联逻辑 |
| `chunk_overlap` | 150–200 字符 | 保留跨块的租金回款周期、项目合同编号等关联信息，保障检索时的上下文完整性 |
| `UPLOAD_FILE_MAX_SIZE` | 200 MB | 适配单份多模块研报的体积上限，避免因文件过大触发上传拦截 |
| `PARSE_FILE_TIMEOUT` | 300 秒 | 处理包含多页扫描件、结构化报表的研报，预留足够的解析与OCR处理时间 |
| `enable_ocr` | 开启 | 覆盖以扫描件形式发布的租赁项目台账研报，提取图像中的专属字段与数据 |
| `recall_topk` | 前 8 条 | 匹配融资租赁研报中多字段关联的检索需求，避免召回结果过少或冗余 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 解析大体积融资租赁研报时触发`413 Request Entity Too Large`错误，原因是未调整`UPLOAD_FILE_MAX_SIZE`参数至适配行业研报的体积阈值。
- 知识库上传含图片链接的融资租赁研报后，问答环节无法调用图片内的租赁项目数据，原因是默认解析配置未开启`enable_ocr`参数，未关联图片链接的文本提取逻辑。
- 分块结果中租赁资产余额等专属字段被截断为空，原因是`chunk_size`设置过小，导致结构化数据被拆分后丢失完整字段绑定关系。

## 怎么确认配好了
- 上传一份标准融资租赁行业研报扫描件，查看解析结果中是否提取出租赁资产余额、项目投放周期等专属字段。
- 测试上传两份相邻篇幅的研报，确认解析生成的分块数量符合`chunk_size`与`chunk_overlap`的配置逻辑。
- 上传体积超过150MB的专项研报，确认解析任务未触发超时或文件大小限制错误。
- 向知识库提问研报中的头部企业租赁项目案例，确认返回结果包含分块中的关联上下文信息。
