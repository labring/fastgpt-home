# 计算机设备研报检索的文档解析与分块

## 这个品类的数据长什么样
计算机设备研报的数据来源包括行业研究机构公开报告、厂商官方技术文档、供应链披露文件。更新节奏随新品发布、季度行业调研及市场动态调整。文档多为PDF格式，包含结构化参数表、技术规格章节、市场分析段落，字段涵盖硬件参数（如显存容量、功耗、核心数）、发布时间、厂商名称、市场定位等，部分文档嵌入硬件性能计算公式。

## 这些特征在「文档解析与分块」这一环带来什么约束
结构化参数表占比高，需保留表格语义完整性，避免拆分跨行列的参数项，否则会导致参数与对应说明分离。文档中存在标准化硬件单位，需在解析时统一单位标识，确保后续问答可准确关联参数与单位。长文档包含多章节技术规格，分块需保留章节上下文关联，避免参数块与说明文本割裂。部分文档嵌入性能计算公式，需保留公式排版结构，确保后续问答可准确调用公式与参数定义。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_TABLE_ENABLE` | 开启 | 计算机设备研报包含大量结构化参数表，需保留表格语义完整性 |
| `MAX_CHUNK_SIZE` | 800–1200 字符 | 平衡单块信息完整性与上下文关联，适配参数与说明混合的文档结构 |
| `PARSE_FORMULA_ENABLE` | 开启 | 研报包含硬件性能计算公式，需保留公式结构用于问答匹配 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持包含多页技术附录的大尺寸研报PDF上传 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大尺寸或含复杂表格的文档解析耗时需求 |
| `CHUNK_OVERLAP_RATE` | 10–15 % | 保留参数章节跨块时的上下文衔接 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：公式解析结果为空或显示乱码，无法在分块中保留公式结构。原因：未开启`PARSE_FORMULA_ENABLE`配置，或使用的解析组件版本不兼容，导致公式无法被正确提取。
- 现象：上传研报PDF时返回`413 Request Entity Too Large`错误，解析流程中断。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，默认限制小于上传文件尺寸。
- 现象：点击分块预览返回“无法读取该文件内容”，后台日志显示解析超时。原因：未延长`PARSE_FILE_TIMEOUT_SECONDS`配置，大尺寸或复杂表格文档解析耗时超出默认阈值。

## 怎么确认配好了
- 上传一份包含结构化参数表与公式的计算机设备研报PDF，查看分块预览中是否保留表格结构与公式排版。
- 核对后台配置项中与解析、分块相关的开关与参数值，确认与预设配置要求一致。
- 上传符合业务场景尺寸的测试文件，验证上传与解析流程无报错。
- 调整分段长度相关配置后，对比不同参数下的分块结果，确认单块信息完整性符合业务需求。
