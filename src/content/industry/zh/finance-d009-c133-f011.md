# 证券研报检索的文档解析与分块

## 这个品类的数据长什么样
证券研报数据来源为持牌金融研究机构、合规的金融信息服务渠道，更新节奏为交易日定期更新，部分突发行业事件驱动的研报会临时发布。单篇文档结构包含标准化的标题、核心观点、行业分析、个股评级、盈利预测表格、风险提示等模块，包含评级字段、目标价字段（单位为人民币元）、行业分类字段、研究员署名与发布机构等元数据，单篇文档长度差异较大，短则数千字符，长则数万字符。

## 这些特征在「文档解析与分块」这一环带来什么约束
证券研报的混合文档结构（文本+结构化表格）要求解析环节保留表格的行列关联，避免拆分时割裂核心信息单元；高频更新的特性要求分块环节同步保留发布时间、发布机构等元数据，便于后续按时间维度过滤召回结果；单篇文档长度差异大的特点，要求分块逻辑适配长短不一的源文档，避免将完整的核心逻辑块拆分为多个独立分块；特定金融术语的使用要求解析环节保留术语的准确性，不能随意拆分专业术语单元。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `分段长度` | 800–1200 字符 | 适配证券研报核心逻辑块的典型长度，避免拆分破坏评级、盈利预测等完整信息单元 |
| `分段重叠率` | 10%–15% | 保留研报中跨段落的逻辑关联，如行业背景与对应个股评级的上下文连贯性 |
| `启用表格增强解析` | 开启 | 证券研报包含大量结构化盈利预测表格，增强解析可保留表格行列结构与单元格关联 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 适配单篇深度研报的解析耗时，避免长文档解析中途中断 |
| `UPLOAD_BATCH_MAX_SIZE` | 500–1000 MB | 适配批量上传单日研报的总容量，满足高频更新场景的批量上传需求 |
| `召回相似度阈值` | 0.75–0.85 | 过滤低相关性召回结果，聚焦研报中与检索关键词匹配度较高的分块 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传包含多列的研报配套Excel表格后，仅识别前两列数据。原因：未开启表格增强解析配置，默认解析逻辑仅提取前两列有效内容。
- 现象：配置mineru API用于PDF增强解析后，解析结果出现大量乱码或缺失表格内容。原因：未正确配置mineru API的访问密钥，或未开启对应解析开关。
- 现象：分块存储后检索到的研报信息不完整，核心评级结论未被召回。原因：分段长度设置过小，将完整的评级逻辑块拆分为多个独立分块，破坏了信息的上下文关联性。

## 怎么确认配好了
- 上传单篇典型长度的研报，查看解析后的分块列表，确认核心信息块未被拆分，根据研报的逻辑块长度调整分段长度配置。
- 上传包含多列结构化表格的文档，查看解析后的文本内容，确认所有列的信息均被完整提取，验证表格增强解析配置是否生效。
- 配置第三方解析API后，上传对应格式的研报，对比解析前后的内容完整性，确认API调用与解析逻辑正常。
- 批量上传多份研报，检查上传任务的执行状态，确认未出现批量解析超时，调整超时配置适配批量任务的耗时。
