# 贵金属研报检索的多轮对话与提示词

## 这个品类的数据长什么样
贵金属研报主要来自专业金融资讯机构、境内外贵金属交易所、券商研究所及行业协会。更新节奏随内容类型区分，每日行情跟踪研报按交易日更新，月度供需、政策解读研报按月度发布，突发市场事件触发临时更新。文档多为结构化+半结构化格式，包含发布机构、发布时间、核心评级字段，行情数据字段多标注纯度（如AU9999）、单位为元/克或美元/盎司，持仓量单位为吨，附带供需测算表格与投资建议模块。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
贵金属研报的多单位字段要求多轮对话中需统一单位转换逻辑，提示词需明确要求模型识别并转换用户提及的价格、持仓量单位，避免跨轮次单位混乱。高频更新的研报内容要求召回环节限定最近的有效时间范围，提示词需加入时间约束，确保返回内容时效性。细分品类与纯度参数的多样性，要求多轮对话中自动关联上下文的品类信息，提示词需引导模型自动提取或要求用户补充当前讨论的贵金属具体类型，避免跨轮次混淆讨论对象。结构化的供需表格与评级字段，要求多轮对话中保留前后轮的分析维度上下文，提示词需明确要求模型关联历史对话中的分析角度，避免重复提问或偏离主题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxHistoryTurns` | `3–5 轮` | 贵金属研报的分析维度覆盖行情、供需、政策等，3-5轮可覆盖完整分析逻辑，避免上下文过载 |
| `召回条数` | `前 8–12 条` | 贵金属研报包含细分品类、单位、评级等多字段，过多召回会导致提示词内容过载，过少则覆盖不全分析维度 |
| `相似度阈值` | `0.75–0.85` | 贵金属研报存在大量专业术语与细分品类，阈值过低会引入无关内容，过高则可能遗漏相关细分品类的研报 |
| `重排返回条数` | `前 3–5 条` | 优先返回与当前对话主题最匹配的核心研报内容，避免冗余信息干扰多轮对话的连贯性 |
| `maxContext` | `8000–12000 字符` | 需容纳多轮对话的历史内容与召回的研报片段，避免关键信息被截断 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 秒` | 部分结构化研报包含大量表格数据，解析需较长时间，避免超时中断召回流程 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 工作流对话显示失败但模型测试正常，且后台有模型响应日志。原因是部署时未正确配置知识库召回的网络访问权限，导致工作流节点无法拉取研报数据，仅模型自身测试可正常返回结果。
- 调用searchTest节点时无法获取历史对话上下文。原因是未在工作流中绑定历史对话变量，或未将上下文参数正确传入searchTest的输入字段。
- 提示词未按预期生效，多轮对话中未关联历史上下文。原因是未正确配置提示词的调用时机，导致模型未在每轮对话中读取历史对话内容。

## 怎么确认配好了
- 发起包含不同单位的测试提问，验证模型是否自动转换为预设基准单位，确认单位转换相关配置生效。
- 发起跨轮次的细分品类提问，验证模型是否能关联历史对话中的品类信息，确认历史轮次配置合理。
- 查看工作流详细日志，确认每次对话轮次都有召回的研报数据与历史上下文记录，确认日志配置正确。
- 调整召回条数参数，验证返回的研报数量是否符合预设取值，确认召回配置生效。
