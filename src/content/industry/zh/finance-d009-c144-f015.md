# 通信服务研报检索的部署与升级

## 这个品类的数据长什么样
金融领域的通信服务研报数据来源主要为券商研究所通信行业专项研报、金融机构内部整理的运营商运营数据、第三方金融数据平台的通信赛道公开报告。更新节奏分为两类：行业整体研报每季度更新，细分赛道（如5G、卫星通信）专项研报不定期发布。文档结构通常包含核心业务数据、行业趋势分析、政策关联解读三部分，核心字段包含用户规模、单用户收入、营收规模，对应单位分别为万户、元、亿元，部分研报附带结构化业务占比表格。

## 这些特征在「部署与升级」这一环带来什么约束
金融领域通信服务研报的多源、差异化更新节奏，要求部署阶段配置多源数据拉取的差异化调度周期，避免因更新滞后影响投资分析决策。研报包含结构化业务数据与长文本分析段落，要求升级阶段适配长文本分段解析与结构化字段提取规则，确保核心投资相关数据的准确映射。细分赛道专项研报的不定期发布特性，要求部署时预留自定义赛道分类的配置入口，升级时可快速新增对应知识库分类与召回权重。带明确单位的数值字段，要求部署阶段配置数据清洗规则，统一单位格式与字段映射逻辑，避免因数据格式不一致影响检索精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300-600 秒` | 通信服务研报多包含长文本分析与结构化表格，该区间可覆盖多数单份研报的解析需求 |
| `maxContext` | `8000-12000 字符` | 研报长文本分段后需保留足够上下文关联，避免关键逻辑断裂影响检索准确性 |
| `RECALL_TOP_K` | `前8-12条` | 通信服务研报的细分赛道数据较为垂直，过多召回会引入无关信息，过少则可能遗漏核心投资相关数据 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 部分专项研报包含多页高清图表与配套数据附件，该上限可覆盖多数合规上传场景 |
| `SYNC_INTERVAL` | `按数据源类型配置：运营商数据每1天同步，行业研报每7天同步` | 运营商数据月度更新、行业研报季度更新，差异化同步可匹配金融投资的及时性需求 |
| `PARSE_STRUCTURED_TABLE` | `启用` | 通信服务研报包含大量结构化业务数据表格，启用后可精准提取字段与数值 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：发布后的助手未设置访问权限，非授权用户可查看全部知识库内容。原因：部署阶段未启用`team_access_control`配置项，未为不同角色分配对应知识库的访问权限。
- 现象：调试预览时调用LLM无响应或返回`400 Bad Request`错误。原因：未正确配置`LLM_API_BASE`与`LLM_API_KEY`参数，或本地部署的LLM服务未开放对应网络端口。
- 现象：批量上传研报时部分文件解析失败，界面显示`解析超时`提示。原因：`PARSE_FILE_TIMEOUT_SECONDS`配置值设置过小，未适配长文本研报的解析耗时。

## 怎么确认配好了
- 进入知识库管理界面，验证多源数据同步任务的调度周期与数据源类型匹配，确认配置的`SYNC_INTERVAL`符合对应数据源的更新节奏。
- 上传一份典型的通信服务研报，查看解析后的结构化字段是否完整，验证`PARSE_STRUCTURED_TABLE`配置是否生效。
- 创建测试应用，配置对应LLM服务地址与密钥，发起调试请求，确认LLM调用链路正常。
- 进入权限管理界面，为不同角色分配指定知识库的访问权限，验证非授权角色无法查看受限内容。
