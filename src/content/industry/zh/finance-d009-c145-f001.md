# 通信设备研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
通信设备研报的数据源包括国内通信设备厂商公开技术白皮书、工信部通信监测数据、运营商集采中标公示、全球通信标准组织规范文档。更新节奏为事件触发，随新品发布、招标周期、标准版本迭代更新，无固定日更周期。文档结构通常包含前言、技术参数章节、组网方案、测试报告，部分包含部署相关内容。核心字段包括设备型号、频段范围（单位为GHz）、传输速率（单位为Gbps）、功耗（单位为W）、发布机构与发布日期。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
事件触发的更新节奏导致无法依赖固定轮询拉取，外部系统需支持按需调用接口或对接数据源的事件回调机制。多结构的文档内容要求接口支持按文档类型、核心技术字段进行精准过滤，避免召回无关内容。专业单位的字段要求接口保留原始单位信息，外部系统不得擅自转换单位，防止参数精度丢失。部分细分技术文档的访问权限差异，要求接口配置细粒度的权限校验规则，区分公开与内部数据源的访问权限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `recall_doc_type` | `["技术白皮书", "集采公示", "标准规范"]` | 匹配通信设备研报的核心数据源类型，过滤无关品类内容 |
| `api_request_timeout` | `300 秒` | 通信设备研报通常包含长文档，解析与拉取耗时较长 |
| `return_field_include` | `["device_model", "frequency_band", "transmit_speed", "publish_org"]` | 覆盖通信设备研报的核心检索与展示字段，保留原始专业单位 |
| `auth_mode` | `api_key` | 适配外部系统集成的通用权限校验方式，保障数据源访问安全 |
| `max_retries` | `2 次` | 应对事件触发拉取的偶发网络波动，降低请求失败率 |
| `content_parse_mode` | `structured` | 适配通信设备研报的结构化技术参数，提升召回精准度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 接口返回`429 Too Many Requests`状态码，原因是未配置合理的请求频率限制，频繁触发数据源的限流规则。
- 召回结果包含非通信设备类的研报内容，原因是未设置`recall_doc_type`过滤参数，召回范围覆盖全品类研报。
- 返回的技术字段缺失单位信息，原因是未在`return_field_include`中保留单位相关字段，或开启了自动单位转换配置。

## 怎么确认配好了
- 调用HTTP接口并传入指定的`recall_doc_type`过滤参数，检查返回结果是否仅包含通信设备相关文档。
- 查看接口返回的字段是否包含预设的`device_model`、`frequency_band`等核心字段，且保留原始专业单位。
- 模拟多次请求，检查是否触发限流报错，确认请求频率符合配置的限制规则。
- 传入包含长文档的研报ID，检查接口响应时长是否符合预设的超时配置。
