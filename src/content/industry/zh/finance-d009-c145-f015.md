# 通信设备研报检索的部署与升级

## 这个品类的数据长什么样
通信设备研报的数据来源包括行业协会公开报告、通信设备厂商官方白皮书、第三方咨询机构的赛道分析文档。更新节奏以季度常规报告为主，搭配新品发布、技术迭代时的临时专项研报。文档结构通常包含核心技术参数、产业链环节分析、市场趋势预判三个核心部分，字段包含设备型号、传输速率、功耗、出货量等，对应单位分别为Mbps、W/kW、万台等。

## 这些特征在「部署与升级」这一环带来什么约束
通信设备研报的多源异构特征要求部署环节配置多源数据导入的权限校验规则，避免未经授权的数据源被接入。不定期的更新节奏要求升级环节支持增量同步，减少全量重建带来的服务器资源占用。文档内大量结构化技术参数的存在，要求解析环节配置专用的字段提取规则，避免通用解析导致的参数字段丢失。单篇研报篇幅较长的特征，要求部署时适配长文本的分段与召回配置，确保核心技术信息不被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 通信设备研报单篇篇幅较长，部分产业链分析章节超万字，900秒可覆盖完整解析流程，避免中途超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 行业研报常以合集形式打包上传，2000MB可容纳多份长文档，适配批量导入需求 |
| `maxContext` | `8000–12000 字符` | 单篇研报内长段落占比高，该取值可适配长上下文召回，避免截断核心技术参数内容 |
| `召回条数` | `前 8 条` | 通信设备研报的技术参数分布分散，需召回足够条目覆盖不同维度的设备指标，避免关键信息遗漏 |
| `SYNC_INTERVAL_HOURS` | `6–24 小时` | 通信设备研报更新以季度报告为主，搭配新品突发研报，6-24小时的同步周期可平衡时效性与服务器资源占用 |
| `相似度阈值` | `0.75–0.85` | 同品类研报的技术参数描述相似度较高，该阈值可过滤无关召回结果，同时保留相关参数的相似文档 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：本地部署后新增模型测试时报`403 status code (no body)`错误。原因：未配置模型接口的访问白名单，或部署时未开放对应端口的入站规则，导致请求被服务器拦截。
- 现象：在管理后台文档界面无法找到升级操作入口，无法查询当前最新版本号。原因：未在部署目录中放置版本更新说明文件，或未开启后台版本同步开关，导致界面未加载升级相关模块。
- 现象：调用上传文件API接口后，无法获取文件解析与索引完成的状态。原因：未启用异步任务回调配置，或未配置任务状态查询接口，导致无法主动获取解析进度与完成标记。

## 怎么确认配好了
- 上传一份通信设备研报合集，检查解析后是否提取出设备型号、传输速率、功耗等结构化字段，确认解析规则适配品类特征。
- 配置定时同步任务后，手动触发一次同步，检查是否有新上传的研报被自动导入，确认定时任务的触发逻辑生效。
- 调用上传文件API接口后，通过任务状态查询接口获取解析进度，确认进度可正常返回并更新至完成状态。
- 新增模型并发起测试请求，检查是否返回正常状态码，确认接口访问权限配置正确。
