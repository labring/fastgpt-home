# 通用设备研报检索的工具调用与插件

## 这个品类的数据长什么样
通用设备研报的数据来源为国内头部券商机械设备行业研究团队、中国通用机械工业协会公开行业报告。更新频率包含月度跟踪报告、季度深度研报及突发政策事件即时报告。文档结构通常包含行业整体供需数据、细分品类产能利用率、重点企业经营指标、核心产品技术参数。字段包含设备产量（单位：台/套）、营收规模（单位：万元）、同比增长率（单位：%）、设备运行效率（单位：%）等结构化信息，部分深度研报还包含细分型号的技术参数细节。

## 这些特征在「工具调用与插件」这一环带来什么约束
通用设备研报的结构化字段多且携带明确单位，要求工具调用时需严格校验参数与字段的单位匹配度，避免返回无效解析结果。多频次的更新类型要求插件支持全量拉取与增量拉取两种模式，适配不同检索场景的时效性需求。单篇深度研报篇幅较长，平均可达8000-10000字符，工具调用需支持分段解析与上下文拼接，防止超出模型上下文窗口。此外，核心分析维度相对固定，工具需支持指定返回字段，减少冗余数据传输与模型处理开销。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MCP_SERVICE_TIMEOUT` | `180 秒` | 通用设备深度研报解析与数据提取平均耗时约120-150秒，预留足够缓冲时间，适配4.9.6版本默认90秒超时的调整需求 |
| `RESEARCH_REPORT_FIELD_FILTER` | `["产量", "营收", "产能利用率", "单位"]` | 通用设备研报核心分析维度为上述字段，过滤非必要字段可降低数据传输开销 |
| `RECALL_TOP_N` | `前 8 条` | 通用设备研报单篇信息密度较高，过多召回结果会超出通用模型的上下文窗口 |
| `PARSE_DOC_MAX_LENGTH` | `12000 字符` | 通用设备深度研报平均篇幅约8000-10000字符，预留合理截断空间避免内容丢失 |
| `MCP_PARAM_TYPE_AUTO_DETECT` | `开启` | 通用设备研报参数包含数值、百分比、单位等多种类型，自动检测可避免固定`string`类型导致的参数解析错误 |
| `INCREMENTAL_UPDATE_SWITCH` | `开启` | 通用设备行业数据更新频率多样，增量拉取可减少重复计算与资源占用 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用MCP服务时，超时时间超过90秒后返回`MC | 是否停止输出的 api 接口可供调用 | chat:LLM_model_response_empty`错误。原因是未调整`MCP_SERVICE_TIMEOUT`配置项，使用默认的90秒超时阈值，无法适配通用设备研报解析的长耗时场景。
- 检索结果中数值字段为空或格式错误。原因是未开启`MCP_PARAM_TYPE_AUTO_DETECT`配置，工具调用参数被强制固定为`string`类型，无法正确解析数值、百分比等结构化字段。
- 召回的研报结果包含大量非核心信息，或超出模型上下文窗口。原因是未配置`RECALL_TOP_N`与`PARSE_DOC_MAX_LENGTH`参数，默认召回条数过多且未截断长文档，导致模型无法有效处理输入内容。

## 怎么确认配好了
- 查看MCP服务的运行日志，确认调用耗时未触发超时错误，根据实际解析耗时调整`MCP_SERVICE_TIMEOUT`配置。
- 发起单次测试调用，检查返回参数的类型是否与实际字段匹配，确认`MCP_PARAM_TYPE_AUTO_DETECT`配置生效。
- 检索指定通用设备细分品类的研报，核对返回字段是否包含预设的核心分析维度，确认`RESEARCH_REPORT_FIELD_FILTER`配置正确。
- 测试长文档解析场景，检查返回内容是否被合理截断，确认`PARSE_DOC_MAX_LENGTH`配置适配当前文档篇幅。
