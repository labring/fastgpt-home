# 钢铁贸易研报检索的向量模型与索引

## 这个品类的数据长什么样
钢铁贸易研报的数据主要来自行业自律组织的公开供需数据、大宗商品资讯机构的采集数据、钢厂及贸易商的公开披露文件。更新节奏覆盖不同周期，短期行情类文档每日或每两日更新，月度分析类文档按月更新，深度行业研报按季度或半年度更新。文档结构跨度较大，短至数百字的成交快报，长至数万字的深度分析报告，多数文档包含核心数据摘要、分品类行情、区域价差、供需平衡分析、后市预判几个模块，核心字段包括交易品种、交易地点、报价金额、库存规模、出货量、发布机构、发布时间，报价金额单位为元/吨，库存规模单位为万吨，出货量单位为吨。

## 这些特征在「向量模型与索引」这一环带来什么约束
文档长度跨度大，短至数百字的成交快报，长至数万字的深度研报，要求索引系统支持自适应文档切分，避免短文档信息丢失或长文档超出向量模型上下文窗口。文档包含结构化数值字段与非结构化分析文本，要求向量模型支持混合字段编码，或需对结构化字段单独做向量化后与文本向量融合。高频更新的短期行情文档占比高，要求索引系统支持增量索引更新，减少全量重建的资源消耗。行业术语密集且存在特定含义，要求向量模型具备行业领域适配能力，或需结合领域词表优化编码效果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunk_size` | 800–1200 字符 | 适配主流向量模型的上下文窗口，平衡单段信息密度与召回完整性 |
| `chunk_overlap` | 100–150 字符 | 弥补文档切分后的上下文断裂，避免专业术语或连续分析内容被截断 |
| `recall_top_k` | 前 8–12 条 | 钢铁贸易研报核心信息集中，过多召回会引入冗余数据，过少可能遗漏关键信号 |
| `similarity_threshold` | 0.72–0.80 | 区分钢铁品类专业术语与通用文本，降低非目标研报的误召回概率 |
| `index_update_strategy` | 增量更新 | 适配钢铁贸易研报高频更新的特性，减少全量索引重建的资源消耗 |
| `embedding_dim` | 768 维 | 适配主流开源向量模型的标准输出维度，平衡向量化精度与存储成本 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用向量模型时返回`401 Unauthorized`错误，控制台显示请求未携带有效认证信息。原因：未正确配置向量模型的API密钥，或密钥权限不足，无法访问向量模型服务。
- 现象：自定义切分文档后，实际索引存储的文档块顺序与自定义切分结果不一致，部分重复块被自动移除。原因：系统默认开启全局文档块去重配置，未关闭该开关导致重复块被过滤，打乱预设顺序。
- 现象：批量上传钢铁贸易研报后，合并索引时部分文档的向量结果为空。原因：未设置适配行业术语的向量模型，或未加载领域词表，导致专业术语无法被正确编码，向量化流程失败。

## 怎么确认配好了
- 上传一份标准格式的钢铁贸易研报，核对解析后的文档块数量与`chunk_size`、`chunk_overlap`的配置计算结果一致，确认分段参数生效。
- 发起针对钢铁品类的检索请求，核对召回结果的数量与`recall_top_k`配置匹配，检查返回结果的相似度评分符合预设的`similarity_threshold`要求。
- 上传一份更新后的研报，验证索引系统仅处理新增或修改的文档，无需全量重建，确认增量更新配置生效。
- 查看向量模型调用日志，确认请求携带有效认证信息，未出现`401 Unauthorized`错误，验证模型接入配置正确。
