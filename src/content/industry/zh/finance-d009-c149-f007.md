# 钢铁贸易研报检索的工作流编排

## 这个品类的数据长什么样
钢铁贸易研报的数据主要来自国内钢铁行业协会发布的供需报告、上海期货交易所的钢铁品种交易数据、国内重点钢厂的产销快报、第三方大宗商品咨询机构的贸易监测报告。更新节奏存在差异：期货交易数据每日更新，钢厂产销快报每周更新，第三方监测报告每双周发布，行业协会报告滞后1至2周更新。单篇研报通常包含核心价格指数、区域现货价差、港口库存数据、贸易流通量统计、下游用钢需求预判几个部分，字段包括价格（元/吨）、库存（万吨）、流通量（万吨）、政策文号、预判周期，部分研报会附带区域贸易路线的具体数据。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的更新频率差异，要求工作流支持按不同周期触发对应节点，避免重复拉取过时数据或遗漏最新行业动态。研报字段多且存在单位差异，部分来源的库存数据以吨为单位，部分以万吨为单位，要求工作流包含字段校验与单位转换节点，确保下游分析的一致性。单篇研报内容较长，部分包含多章节的深度分析，要求工作流配置分段解析与关联召回的节点，避免截断核心的供需数据。钢铁贸易数据的时效性较强，超时未完成的节点会导致数据失去参考价值，要求设置合理的节点超时阈值与重试机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `15–20 条对话上下文` | 钢铁贸易研报分析涉及跨周期的供需数据关联，15-20条可覆盖近2个月的对话历史，避免上下文过载影响分析精度 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单篇钢铁贸易研报通常包含多章节的长文本内容，600秒可完成完整解析，避免因内容过长触发超时报错 |
| `RECALL_TOP_N` | `前8条召回结果` | 钢铁贸易研报的核心信息集中在价格、库存、流向三个维度，8条可覆盖全维度的关联数据，避免冗余结果干扰分析 |
| `SIMILARITY_THRESHOLD` | `0.75–0.8` | 钢铁贸易存在大量专业术语与行业专属表述，0.75的阈值可过滤低相关的通用文本，保留精准的行业数据 |
| `WORKFLOW_TRIGGER_CRON` | `0 9 * * 1,3,5` | 钢铁贸易的核心现货与期货数据更新集中在周中，每周一、三、五早9点触发可获取最新的行业动态 |
| `FIELD_MAPPING_RULE` | `按标准单位统一转换` | 不同来源的研报存在单位差异，统一转换为万吨、元/吨后可确保下游分析的一致性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流解析节点执行超过预设时间后触发超时报错，日志显示`ETIMEDOUT`状态码。原因：未针对钢铁贸易研报的长文本内容调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时间不足以完成完整解析。
- 现象：工作流中配置的网页抓取节点无法加载钢铁行业研报的官方页面。原因：未配置正确的请求头参数，部分行业协会网站会拦截无请求头的自动化请求。
- 现象：工作流编排的研报检索工具无法维持多轮对话，版本为v4.8.10，用户输入后续问题后无法关联之前的研报数据。原因：未将`maxContext`参数设置为大于0的取值，导致每次调用API时未传递历史对话上下文，无法实现多轮关联。

## 怎么确认配好了
- 触发一次完整的工作流，查看各节点的执行日志，确认所有数据拉取节点均获取到对应来源的最新数据，解析节点无文本截断或字段缺失报错。
- 发起多轮测试对话，输入与钢铁贸易研报相关的连续问题，确认工具可关联之前对话中提到的库存、价格等数据，实现连贯的分析。
- 检查工作流的超时配置，确认`PARSE_FILE_TIMEOUT_SECONDS`的取值适配单篇研报的解析时长，可通过单次解析测试调整参数。
- 查看字段映射规则的配置记录，确认所有来自不同研报的单位均被统一转换为标准单位，无格式错误或字段遗漏。
