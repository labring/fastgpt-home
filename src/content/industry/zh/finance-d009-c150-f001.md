# 铁矿石研报检索的HTTP 接口与外部系统

## 这个品类的数据长什么样
铁矿石研报主要来源为行业资讯平台、港口监测机构、钢厂月度报告及期货交易所公开数据。更新节奏覆盖多维度：现货价格数据每日更新，周度供需周报每周发布，月度库存与政策解读报告每月更新，年度行业趋势报告每季度更新。文档结构包含行情速览、供需平衡表、港口库存数据、政策影响分析及套利模型等模块，专属字段包括品位、现货价格、港口库存、成交量，部分研报会附带期货合约价差数据。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
铁矿石研报的多频率更新要求接口支持按时间范围精准拉取增量或全量数据，避免重复同步无效内容。专属字段的标准化需求要求外部系统对接时需完成字段映射，防止单位转换错误影响业务判断。长文档占比高的特点要求接口解析环节具备足够的超时容忍度，同时支持分段检索。多数据源接入的需求则要求外部系统集成模块可配置多源切换，适配不同渠道的研报数据格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `SYNC_FREQUENCY` | 按研报类型配置：现货数据每小时同步，周报每日同步，月报每月同步 | 匹配铁矿石研报的差异化更新节奏，避免无效拉取占用资源 |
| `RECALL_TOP_K` | 前10-20条 | 铁矿石研报内容维度丰富，足够的召回量可覆盖行情、供需、政策等细分查询需求 |
| `SIMILARITY_THRESHOLD` | 0.75-0.85 | 平衡专业术语匹配精度与结果覆盖范围，避免低相关结果干扰专业分析 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 适配长文档研报的解析时长，防止大型报告因超时中断解析 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 支持完整的大型行业研报文件上传，覆盖全量数据同步需求 |
| `API_RATE_LIMIT` | 100次/分钟 | 适配企业级外部系统的常规调用频率，避免接口过载 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用接口返回`413 Request Entity Too Large`错误，原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，超过默认限制导致大型研报文件无法上传或同步。
- 现象：接口返回的研报字段单位混乱，例如价格显示为美元，部分场景下显示为元/湿吨，原因：未配置标准化字段映射，直接对接了多源未统一格式的数据源。
- 现象：数据集长期处于索引中状态，原因：内网部署未配置本地数据源同步依赖，依赖外部网络拉取研报数据导致超时，或`PARSE_FILE_TIMEOUT_SECONDS`设置过短无法完成长文档解析。

## 怎么确认配好了
- 调用测试接口传入铁矿石研报的专属关键词，核对返回结果的字段是否包含品位、港口库存等专属标识，单位是否符合业务需求。
- 查看数据集同步日志，确认按配置的`SYNC_FREQUENCY`完成了对应更新频率的研报拉取，无超时或失败报错。
- 模拟外部系统调用接口，验证返回结果的条数符合`RECALL_TOP_K`的配置范围，无异常状态码返回。
- 测试上传单份超过200MB的铁矿石研报文件，确认接口返回成功，无文件大小超限提示。
