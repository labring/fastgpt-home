# 鞋类研报检索的工具调用与插件

## 这个品类的数据长什么样
鞋类研报的数据来源包括国内鞋类行业协会公开报告、品牌方季度财报、主流电商平台品类销售监测数据、跨境供应链调研文档。更新节奏分为三类：品牌财报按季度更新，电商监测数据每日更新，行业协会报告按月度发布。文档通常包含核心品类销量数据、原材料成本占比、线上线下渠道占比、竞品价格带分布，字段涵盖SKU编码、出货量、客单价、毛利率，单位涉及双、元、%等。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于存在每日更新的电商监测数据，工具调用需支持高频数据拉取与短缓存周期设置，避免使用过时信息。由于包含SKU编码、客单价等精准结构化字段，工具调用需支持按指定字段过滤检索的参数配置，提升检索精准度。由于数据来源包含PDF财报、CSV销售报表等多格式文档，插件需适配多种文件解析规则，兼容不同格式的数据导入与解析。由于细分品类的竞品动态更新频繁，工具调用需支持实时调用外部监测接口补充最新的市场数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | 10–15 条 | 鞋类研报数据字段多，单条研报信息量较大，过多召回会超出上下文窗口 |
| `相似度阈值` | 0.72–0.78 | 鞋类SKU与竞品信息关联性强，阈值过低会引入无关数据，过高会遗漏精准匹配项 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 鞋类研报常包含多页表格与图表，解析耗时较长 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 单份行业研报PDF或CSV文件体积较大，需适配大文件上传 |
| `工具调用触发模型` | 按实测标定 | 鞋类研报检索需精准判断工具调用时机，需根据实际调用日志调整模型选择 |
| `插件缓存时长` | 3600 秒 | 电商监测数据每日更新，缓存时长不宜超过单日，避免使用过时数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用第三方多模态向量模型时，界面返回`Model not supported`错误日志，原因：未添加对应模型的接入配置，仅保留了默认模型的参数设置。
- 现象：高级编排的工具调用环节未自动选择指定工具，返回`No matching tool`提示，原因：未在配置中指定工具调用的触发模型与可选工具范围，导致模型无法识别调用需求。
- 现象：调用DALL·E3生成鞋类款式预览时，接口返回`401 Unauthorized`错误，原因：未正确配置API密钥的区域权限与访问范围，导致接口验证失败。

## 怎么确认配好了
- 上传一份鞋类研报的PDF或CSV文件，查看系统解析任务状态显示为`完成`，无`Parse failed`类日志。
- 发起鞋类SKU检索请求，查看返回结果包含匹配的SKU编码与对应销量数据，召回条数符合配置的`召回条数`取值范围。
- 调用第三方多模态向量模型接口，查看返回的向量数据格式符合预期，无`Model not supported`类错误。
- 从外部浏览器发起API请求，查看返回状态码为`200 OK`，无跨域拦截提示。
