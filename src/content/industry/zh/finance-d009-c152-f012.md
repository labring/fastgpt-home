# 鞋类研报检索的模型接入与配置

## 这个品类的数据长什么样
鞋类研报的来源涵盖国内鞋类行业协会发布的季度分析、头部品牌公开的财报、跨境电商平台的销售监测数据、海关总署的进出口报关数据、专业供应链调研机构的实地报告。更新节奏因数据源而异，品牌财报按季度更新，电商销售数据按周更新，行业调研报告不定期发布，进出口数据按月更新。文档结构通常包含行业整体概况、细分品类销量分析、原材料价格走势、渠道表现、政策影响解读五个部分，部分研报附带单品牌SKU的销售明细，字段包含SKU编码、品类标签、售价区间、库存周转天数等，单位多为元/双、元/千克、万双、天等。

## 这些特征在「模型接入与配置」这一环带来什么约束
鞋类研报的数据来源分散且格式差异显著，不同数据源的字段命名、单位标准不统一，例如部分报告使用“吊牌价”，部分使用“建议零售价”，部分原材料价格以元/千克标注，部分以元/吨标注，这要求配置环节需预设字段映射与单位转换规则。同时，不同数据源的更新节奏差异较大，品牌财报按季度更新、电商销售数据按周更新，需配置差异化的定时拉取周期。此外，单篇研报的长度跨度大，从数百字的细分品类简报到数万字的行业全景分析，需适配不同的文档分段与上下文窗口配置，避免因过长文本超出模型限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–16000 字符` | 适配鞋类研报的长度跨度，覆盖从细分品类简报到行业全景分析的常见内容，避免关键信息被截断 |
| `fieldMapping` | `将“吊牌价”映射为“建议零售价”，统一原材料价格单位为元/双` | 解决鞋类研报中字段命名与单位不统一的问题，确保模型可识别标准化字段 |
| `updateInterval` | `按数据源分类配置：品牌财报为7 天，电商数据为1 天，行业调研为30 天` | 匹配不同数据源的实际更新节奏，避免重复拉取或遗漏最新数据 |
| `segmentLength` | `800–1200 字符` | 拆分鞋类研报的细分内容模块，确保每个分段包含完整的业务逻辑，适配模型的输入长度限制 |
| `apiRateLimit` | `10–15 次/分钟` | 避免触发`429 Request rate increased too quickly`报错，适配公开数据源的接口调用限制 |
| `requestBodyTemplate` | `保留默认请求体结构，仅替换`apiKey`与`endpoint`字段` | 解决手动删除body参数后自动恢复的问题，遵循模型接口的固定请求格式 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：手动删除`requestBodyTemplate`中的自定义字段后，再次打开配置页面仍显示原有内容。原因：系统预设了模型接口的标准请求体结构，未禁用自动补全逻辑，导致删除的配置被自动恢复。
- 现象：调用模型时返回`429 Request rate increased too quickly`状态码。原因：未配置`apiRateLimit`参数，或取值高于数据源的接口调用限制，导致请求频率超出阈值。
- 现象：新建模型配置后，原有同API的配置被覆盖。原因：未为不同应用配置独立的标识绑定规则，系统默认以API endpoint作为配置唯一标识，导致新配置覆盖旧配置。

## 怎么确认配好了
- 查看配置管理页面，确认存在独立的配置条目，无同API配置被覆盖的情况。
- 发起单条测试数据的召回请求，检查返回结果中是否包含标准化的鞋类研报字段，且单位统一。
- 连续发起多次调用，观察是否触发`429 Request rate increased too quickly`报错，确认速率限制配置生效。
- 手动编辑`requestBodyTemplate`的内容，保存后重新进入配置页面，确认修改后的内容未被自动重置。
