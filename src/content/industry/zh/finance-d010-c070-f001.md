# 招标公告竞价的HTTP 接口与外部系统

## 这个品类的数据长什么样
招标公告的数据主要来源于各级政府采购网、公共资源交易中心官方平台，更新节奏随对应招标项目的进度触发，发布后可能伴随补遗、变更公告进行更新。单篇文档结构包含项目名称、招标编号、预算金额、开标时间、投标人资格要求、联系方式等核心字段，预算金额单位为人民币元或万元，时间字段采用ISO 8601标准格式，部分公告包含附件下载链接字段。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于招标公告来源分散，需对接多类官方平台接口，因此外部系统需支持多源鉴权配置；单篇内容长度差异较大，部分公告包含大量附件说明与细节描述，接口返回payload易超出默认限制，需调整分页与分段参数；更新无固定周期，需支持按需拉取，适配项目突发发布的场景；字段包含金额、时间等格式敏感项，接口参数校验需覆盖字段类型与单位校验，避免数据解析错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `HTTP_REQUEST_TIMEOUT` | 600–900 秒 | 招标公告多源拉取需遍历多页内容，避免因默认300秒超时中断拉取 |
| `HTTP_RETRY_MAX_TIMES` | 2 次 | 官方平台接口可能存在临时波动，少量重试可提升拉取成功率 |
| `QUERY_PARAM_MAPPING_RULE` | 按接口返回字段映射 | 招标公告字段较多，需将接口返回的`budget_amount`、`bid_deadline`等字段映射为全局变量 |
| `API_RESPONSE_PAGINATION_ENABLE` | 开启 | 单篇招标公告内容较长，分页返回可降低接口负载 |
| `EXTERNAL_DATA_SOURCE_AUTH_TYPE` | 按对应平台配置 | 不同官方平台采用API Key、OAuth2等不同鉴权方式，需匹配对应配置 |
| `WORKFLOW_LOOP_MAX_DEPTH` | 3 层 | 限制招标公告批量拉取的循环嵌套层级，避免资源占用过高 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：接口调用返回`504 Gateway Timeout`或`请求超时`报错。原因：未调整`HTTP_REQUEST_TIMEOUT`配置，沿用默认300秒取值，无法覆盖招标公告多源拉取的耗时需求。
- 现象：工作流执行时触发`循环嵌套超限`报错。原因：未设置`WORKFLOW_LOOP_MAX_DEPTH`限制，在批量拉取招标公告时无层级约束，导致资源占用过高。
- 现象：全局变量未获取到招标公告的指定字段值。原因：未配置`QUERY_PARAM_MAPPING_RULE`，未将接口返回的`contact_phone`等字段与全局变量绑定，导致参数无法传递。

## 怎么确认配好了
- 调用配置后的HTTP接口，检查返回字段是否包含招标公告的`project_name`、`bid_number`、`budget_amount`等必填项，核对字段映射是否与`QUERY_PARAM_MAPPING_RULE`配置一致。
- 查看工作流执行日志，确认无`504 Gateway Timeout`类超时报错，验证`HTTP_REQUEST_TIMEOUT`配置生效。
- 测试批量拉取招标公告的循环场景，确认未触发`循环嵌套超限`报错，验证`WORKFLOW_LOOP_MAX_DEPTH`配置合理。
- 修改`QUERY_PARAM_MAPPING_RULE`中的映射字段，触发接口调用后检查全局变量是否能正确获取对应字段值。
