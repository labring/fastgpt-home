# 招标公告竞价的工作流编排

## 这个品类的数据长什么样
招标公告的数据来源为各级公共资源交易平台、政府采购官网、行业主管部门的公示渠道。更新节奏随招标项目进度调整，常规项目每日更新多批次，紧急采购项目实时推送。文档结构包含核心元数据字段，如招标编号、采购人主体、项目预算、资质门槛、投标截止时点、开标地点，同时附带配套的招标文件PDF格式附件。字段单位方面，预算以人民币万元为标注单位，时间字段统一采用公历年月日格式，部分项目会附带标段拆分的子项字段。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据源带来适配约束，需配置多格式解析规则匹配不同平台的元数据字段位置。高频更新的特性要求工作流采用定时触发或实时webhook触发模式，避免数据延迟。附带的PDF招标文件附件，要求工作流集成文件解析节点完成文本提取与结构化。字段格式与单位的差异，需配置标准化转换规则统一预算单位、时间格式。单篇文档的内容长度跨度较大，要求工作流适配长文本处理的上下文配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 招标公告附带的PDF招标文件通常页数较多，需预留足够的解析时间避免超时中断 |
| `max_context_length` | `8000–12000 字符` | 单篇招标公告文本长度差异大，适配长文档的上下文处理需求 |
| `workflow_trigger_type` | `定时触发（每30分钟）+ 实时webhook` | 兼顾常规批量更新与紧急项目的实时推送需求 |
| `field_mapping_rule` | `按来源平台预设模板匹配` | 不同招标平台的元数据字段命名差异大，需按来源配置专属映射规则 |
| `form_data_file_field` | `招标附件` | 工作流中调用第三方接口上传招标文件时，需指定对应文件字段的标识名 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 大型招标文件PDF附件通常体积较大，适配常规项目的附件上传限制 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流在运行预览页面可正常生成结果，但在聊天窗口调用时无返回内容。原因：未配置聊天窗口触发的工作流授权规则，或触发时未传递正确的上下文参数。
- 现象：工作流中配置form-data类型的HTTP请求时，无法正确传递招标文件附件。原因：未指定form-data的文件字段标识名，或未绑定正确的文件输入节点。
- 现象：上传招标文件附件至工作流节点时提示Load file error，直接上传至知识库可正常完成。原因：工作流节点的文件解析配置与附件格式不匹配，或临时存储阈值设置不足。

## 怎么确认配好了
- 触发工作流测试，核对元数据字段是否按配置完成标准化转换，确认不同来源的招标公告字段匹配一致。
- 上传测试用的招标文件PDF，检查文件解析节点是否正常提取文本，无报错提示。
- 配置定时触发与webhook触发的测试任务，验证高频更新场景下工作流是否正常启动。
- 调用工作流的聊天窗口触发方式，确认返回结果与预览页面一致，无参数缺失问题。
