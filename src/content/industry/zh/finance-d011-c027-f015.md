# 功能入口终端内自然语言检索的部署与升级

## 这个品类的数据长什么样
功能入口终端内自然语言检索的数据主要来自终端用户的触发交互日志、预配置的检索触发规则、绑定的业务结构化数据集。数据更新节奏分为两类：入口配置项按需更新，关联业务数据随终端业务系统同步。文档结构包含入口唯一标识、触发关键词集合、关联知识库ID、访问权限范围、绑定的业务接口地址。字段均为字符串或布尔类型，无复杂嵌套单位，入口标识以字母加数字组合为单位，触发关键词以单条为单位。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据结构化特征要求部署时需使用标准化的字段映射工具，避免自定义格式导致的配置读取失败。数据同步的节奏约束需在部署阶段配置与终端业务系统对齐的更新间隔，确保检索内容的实时性符合金融场景的合规要求。升级过程中，入口触发规则的调整需同步验证访问权限范围，防止出现跨角色的非法检索。触发关键词的批量更新需先在测试环境完成触发匹配测试，避免影响终端正常交互流程。此外，绑定的业务接口地址变更需同步更新配置，避免出现检索失败的情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DOCKER_ENTRANCE_DEPLOY_PORT` | `8080–8090` | 该端口范围需与终端系统的开放端口规则对齐，避免端口冲突影响部署 |
| `BUSINESS_DATA_SYNC_CRON` | `0 */5 * * *` | 适配金融场景业务数据的准实时更新需求，每5分钟同步一次可平衡性能与时效性 |
| `ENTRANCE_TRIGGER_THRESHOLD` | `0.75–0.85` | 控制检索匹配的相似度阈值，该区间可兼顾召回准确率与覆盖范围，符合金融场景的严谨性要求 |
| `PARSE_ENTRANCE_CONFIG_TIMEOUT` | `120 秒` | 避免批量入口配置解析超时导致部署失败，120秒可覆盖复杂配置的解析时长 |
| `ENTRANCE_PERMISSION_VALIDATE` | `开启` | 强制开启权限校验，适配金融/保险场景的合规要求，防止未授权访问检索内容 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：部署后功能入口无法触发检索，日志返回`400 Bad Request`。原因：未正确配置`DOCKER_ENTRANCE_DEPLOY_PORT`与终端系统的端口映射规则，导致请求无法到达服务。
- 现象：模型调用工具逻辑异常，部分触发词未匹配到对应检索。原因：未按终端交互逻辑排序触发关键词，或触发关键词数量设置超出合理范围，导致匹配冲突。
- 现象：知识库分割出现块丢失，检索结果不完整。原因：未针对功能入口绑定的知识库调整`PARSE_SEGMENT_SIZE`参数，使用默认值导致长文本分割异常，无法完整召回业务内容。

## 怎么确认配好了
- 登录FastGPT后台，进入功能入口管理页面，核对已配置的入口字段与部署文档中的要求一致。
- 在终端内触发预设的检索关键词，查看检索结果是否包含预期的业务数据，验证同步配置是否生效。
- 调用配置的权限测试账号，验证是否仅能访问对应角色范围内的检索内容，确认权限校验配置正确。
- 查看服务日志，确认无`PARSE_ENTRANCE_CONFIG_TIMEOUT`相关的超时报错，验证配置解析正常。
