# 行情数据终端内自然语言检索的表单与交互

## 这个品类的数据长什么样
行情数据主要来自官方证券交易接口、合规行情服务商。更新节奏随交易时段调整，交易时段内高频推送，非交易时段按固定间隔更新。单条行情数据文档结构标准化，包含标的代码、标的名称、最新成交价、涨跌幅、成交量、成交额、更新时间戳等字段。价格字段单位为人民币元，成交量单位为股或交易手数，成交额单位为人民币元。

## 这些特征在「表单与交互」这一环带来什么约束
行情数据的高频更新特征要求交互环节实时展示数据更新时间，避免返回过期信息；标准化的字段结构要求表单检索的筛选条件需对应标的代码、涨跌幅、成交量等固定字段，避免自定义字段导致检索失效。交易时段内的高频推送要求检索结果的缓存时长需适配交易节奏，非交易时段需明确标注数据更新状态。多维度的行情指标要求表单交互提供多条件组合筛选入口，支持按单一或多个指标排序展示结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `topK` | `前10-20条` | 行情数据指标维度多，需覆盖足够多标的供筛选，同时避免结果过载 |
| `scoreThreshold` | `0.75-0.85` | 行情数据标的代码、名称匹配精度要求高，阈值过低易返回无关标的 |
| `cache_ttl` | `30-60秒` | 交易时段内行情高频更新，缓存时长需适配实时性要求 |
| `display_fields` | `["标的代码", "标的名称", "最新价", "涨跌幅", "更新时间"]` | 匹配行情数据标准字段，满足终端用户核心查看需求 |
| `refresh_interval` | `按交易时段调整` | 交易时段内缩短刷新间隔，非交易时段延长至5分钟以上 |
| `filter_rules` | `按标的代码/名称匹配优先` | 行情检索核心需求为定位特定标的，优先匹配标识性字段 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：通过变量引用选择知识库文档时，返回结果与输入的行情查询不匹配，或返回空内容。原因：未明确配置变量引用的匹配字段范围，未限定仅检索行情数据相关的标准化字段。
- 现象：检索结果长时间未更新，显示非实时行情数据。原因：缓存有效时长配置值过大，未根据交易时段调整刷新间隔。
- 现象：输入标的代码后，检索返回大量无关的非标的类数据。原因：相似度阈值配置过低，未过滤掉与行情指标无关的文本匹配结果。

## 怎么确认配好了
- 发起包含具体标的代码的查询，核对返回结果中包含的字段与配置的展示字段完全匹配。
- 等待预设的刷新间隔后再次发起相同查询，核对结果的更新时间是否符合配置的刷新逻辑。
- 调整相似度阈值后，输入模糊的标的名称，核对返回结果的匹配精度是否符合预期。
- 输入非行情类的查询文本，核对系统是否返回无相关结果的提示，避免误匹配行情数据。
