# 专用设备营销内容的HTTP接口与外部系统

## 这个品类的数据长什么样
专用设备的营销相关数据来源于线下网点部署的智能营销终端、自助办理设备等硬件，包含设备运行日志、营销素材投放记录与用户交互数据。数据更新节奏分为两类：营销素材文档按活动周期更新，通常为每周或每月；设备上报的交互与运行数据为准实时更新，每5分钟至1小时上报一次。单份数据文档包含`device_serial`、`material_code`、`interaction_count`、`stay_duration`、`report_timestamp`等字段，其中`device_serial`为16位字符串，`stay_duration`单位为秒，`report_timestamp`遵循ISO8601格式。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
专用设备多部署于线下网点的专网环境，网络延迟高于公网，因此HTTP接口需支持更长的请求超时时间。准实时上报的特性要求接口具备高并发短连接处理能力，可同时接收多台设备的上报请求。营销素材包含高清图片、操作短视频等大尺寸文件，接口需支持大文件分片上传以降低传输失败概率。字段的严格格式要求，如`device_serial`的16位字符串格式、`stay_duration`的秒级单位，要求接口需对请求体进行字段校验，避免无效数据流入后续流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `timeout` | 240 秒 | 专用设备多部署于专网环境，网络延迟高于公网，240秒可覆盖多数上报链路 |
| `max_body_size` | 800–1200 MB | 营销素材包含高清图片、操作视频等大文件，单文件最大可达1200 MB，需匹配上传上限 |
| `validate_schema` | 启用 | 专用设备上报数据需包含`device_serial`、`material_code`等核心字段，启用校验可过滤无效上报 |
| `retry_count` | 3 次 | 专网环境偶发网络波动，3次重试可在不增加过多负载的前提下提升上报成功率 |
| `chunk_mode` | 开启 | 大尺寸营销素材上传易因链路中断失败，分片上传可降低单次传输失败概率 |
| `error_notify_strategy` | 按网点分组配置 | 专用设备分布于不同线下网点，按分组配置可快速定位故障设备所在区域 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用图片分析接口时返回`400 Bad Request`，提示无法下载图片。原因是专用设备的营销素材图片存储于专网私有存储，未配置跨域访问权限，导致外部接口无法拉取图片。
- HTTP节点返回`504 Gateway Timeout`，上报数据无响应。原因是配置的`timeout`值小于专用设备专网的平均延迟，导致请求提前中断。
- 上传的营销素材文件不完整，`material_content`字段为空。原因是未开启`chunk_mode`，大文件上传时链路中断导致数据截断。

## 怎么确认配好了
- 上传一份符合格式的测试营销素材文件，检查FastGPT HTTP节点返回`200 OK`状态码。
- 模拟一台专用设备上报测试数据，核对后台日志中`device_serial`、`material_code`等字段的解析结果与上报值一致。
- 断开测试设备的网络链路，观察是否触发配置的分组告警通知。
- 上传最大尺寸的测试文件，确认分片上传流程正常完成，无数据丢失。
