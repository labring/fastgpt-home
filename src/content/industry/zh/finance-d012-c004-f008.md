# 专用设备营销内容的工具调用与插件

## 这个品类的数据长什么样
专用设备的营销相关数据主要来源于设备本地交互日志、运维上报接口与营销中台关联数据。实时交互数据（如用户停留时长、素材展示次数）每秒更新，设备在线状态每30秒同步，批量营销关联数据每小时批量拉取。数据文档为结构化格式，单条记录包含设备唯一标识、交互时间戳、运行温度、用户停留时长、素材展示次数等字段，字段无额外单位，枚举值仅包含在线、离线、维护三种状态。

## 这些特征在「工具调用与插件」这一环带来什么约束
多维度、多更新频率的数据特征要求工具调用需同时支持实时拉取与批量同步两种模式。实时交互数据的秒级更新要求插件同步间隔不能过长，否则会导致营销内容推送滞后。设备唯一标识字段要求工具调用必须传入合法设备ID，否则无法关联对应数据。枚举型状态字段要求插件需先校验设备在线状态，再触发营销内容生成，避免向离线设备推送无效内容。批量数据的定时拉取要求工具调用需配置定时触发规则，以匹配每小时的批量同步节奏。混合类型的字段要求插件需内置格式校验逻辑，避免因字段类型不匹配导致调用失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_timeout` | `30 秒` | 专用设备数据拉取多为内网环境，延迟较低，超时过久会阻塞营销内容生成流程 |
| `plugin_sync_interval` | `10–30 秒` | 匹配实时交互数据的更新频率，避免营销内容推送滞后 |
| `batch_data_batch_size` | `500 条` | 适配每小时批量同步的数据量级，单次拉取过多会占用内网带宽 |
| `device_id_required` | `是` | 专用设备的营销内容触发必须绑定唯一设备标识，否则无法精准推送对应素材 |
| `tool_call_retry_times` | `2 次` | 内网设备调用偶发中断概率较低，少量重试可提升调用成功率 |
| `mcp_service_enabled` | `按实测标定` | 需根据专用设备厂商提供的MCP协议文档配置，仅当设备接口支持该协议时启用 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用工具时返回`The tool call is not supported`错误，原因是未在插件配置中启用专用设备专属的工具调用权限，或传入的设备ID格式不符合要求。
- 配置MCP服务后无法拉取专用设备数据，原因是未适配设备厂商的MCP协议版本，或未在FastGPT中配置设备接口的内网访问白名单。
- 部署本地m3e模型后调用工具失败，原因是4.8.19版本后openapi接口的认证参数位置发生变更，未同步更新对应配置。

## 怎么确认配好了
- 在FastGPT的插件调试面板中，输入合法的专用设备ID，调用预设的营销内容生成工具，检查返回结果是否包含设备运行参数与营销交互数据。
- 查看插件运行日志，确认每`10–30 秒`的同步任务正常触发，无报错记录。
- 触发模拟的用户交互事件，检查是否能根据设备在线状态自动调用对应的营销内容生成工具。
- 调用openapi接口测试工具，传入正确的认证参数与设备ID，检查返回的状态码为`200 OK`，无认证失败提示。
