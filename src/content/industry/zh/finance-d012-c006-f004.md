# 中药营销内容的向量模型与索引

## 这个品类的数据长什么样
中药营销内容的数据来源覆盖药企官方产品资料、行业炮制规范、学术临床文档、营销推广物料四大类。更新节奏分为批量更新与日常迭代：新品上市、行业标准修订时触发批量更新，日常随营销活动、直播脚本、公众号推文等物料迭代。文档结构包含结构化参数表与非长文本两类，结构化字段包含药品通用名、商品名、性味归经、功能主治、用法用量、禁忌等，单位涵盖克、毫升、日剂量等；非结构化内容则包含产品科普文案、营销话术等。

## 这些特征在「向量模型与索引」这一环带来什么约束
中药营销内容兼具结构化参数与非结构化文本的特征，要求向量索引同时支持字段级语义编码与全文语义检索。内容中密集的中医药专业术语，要求向量模型适配领域语义理解，避免通用模型对专业表述的语义偏差。批量更新与日常迭代并存的更新节奏，要求索引支持增量刷新与全量重建两种模式，平衡实时性与索引系统负载。多维度的业务分类（如品类、剂型、适用人群），要求索引元数据支持多标签分类，便于后续按业务维度检索与导出。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `chunk_size` | 800–1200 字符 | 兼顾中药专业术语的语义完整性与短营销文案的完整提取，避免分段切断连续的专业表述 |
| `chunk_overlap` | 100–150 字符 | 保留分段间的上下文衔接，防止切断“性味归经”“功能主治”这类连续的专业短语 |
| `retrieval_top_k` | 前6–10条 | 中药营销内容的专业相关性较强，过多召回会引入无关信息，过少则无法覆盖完整需求场景 |
| `similarity_threshold` | 0.72–0.80 | 区分相似中药产品的语义相似度，避免将功效相近的药品混淆 |
| `index_incremental_refresh_interval` | 每小时一次 | 适配营销内容的日常迭代节奏，平衡实时性与索引系统的负载 |
| `parse_file_max_size` | 200 MB | 适配中药行业炮制规范、学术论文等大体积文档的批量导入需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：导入飞书文件夹下的excel文件后，解析结果中`功能主治`字段为空。原因：未开启结构化表格的字段提取配置，未针对中药专属业务字段设置映射规则。
- 现象：arm软路由部署外接向量模型时，频繁出现`504 Gateway Timeout`报错。原因：软路由的单核算力不足以支撑向量模型的批量推理，接口超时阈值设置过低。
- 现象：批量更新中药营销内容后，新导入的文档未被纳入向量索引。原因：未配置`index_incremental_refresh_interval`参数，仅依赖全量索引刷新，无法及时同步增量数据。

## 怎么确认配好了
- 上传单份中药产品说明书，检查解析后的分段是否包含完整的`性味归经`、`功能主治`字段，确认分段长度符合预设规则。
- 发起针对中药功效的测试查询，核对召回结果的条数是否与`retrieval_top_k`的设置一致，确认索引刷新已生效。
- 查看向量模型的推理日志，确认外接接口的响应延迟符合业务要求，未出现超时报错。
- 导出部分索引数据，检查是否可按中药品类、文档类型进行分类筛选，确认元数据配置正确。
