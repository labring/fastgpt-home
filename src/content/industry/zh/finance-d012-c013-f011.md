# 保险营销内容的文档解析与分块

## 这个品类的数据长什么样
保险营销内容的数据主要来自代理人培训手册、产品条款文档、合规话术库、客户跟进记录及监管政策文件。更新节奏随新产品上线、监管规则调整不定期波动，单次更新可能覆盖单份或多份文档。文档结构混合结构化字段与非结构化段落，结构化字段包含产品ID、保障责任、保费、保额、缴费年限等，对应单位为元/年、万元、年等；非结构化部分包含场景化营销话术、合规提示，部分文档附带references字段标注引用的监管文件或合作方信息，以及reasoning content字段标注话术的逻辑推导过程。

## 这些特征在「文档解析与分块」这一环带来什么约束
保险营销文档的混合结构要求解析环节同时适配结构化字段提取与非结构化段落保留，避免拆分单条完整的保障责任或合规提示。references字段与reasoning content字段的存在要求解析流程支持关联字段的提取与保留，否则会丢失合规性标注与话术逻辑信息。文档单次更新的批量性可能带来多文件上传的需求，解析环节需支持批量处理且不丢失跨文档的关联关系。较长的产品条款文档则要求分块环节保留上下文连贯性，避免将跨段落的责任关联内容拆分到不同分块中。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `max_chunk_size` | 800–1200 字符 | 保险营销文档混合结构化参数和话术，该区间可保留单条保障责任或完整话术段落的完整性 |
| `chunk_overlap` | 100–150 字符 | 保险产品条款存在跨段落的责任关联，重叠部分可保留上下文连贯性 |
| `parse_references` | 开启 | 保险营销文档常附带监管文件引用、产品合作方资质说明，开启后可完整提取关联字段 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 单份保险产品手册可能包含多页条款与话术，较长解析时长可避免超时失败 |
| `enable_structured_field_extract` | 开启 | 保险文档包含标准化的保费、保额、缴费年限等字段，开启后可提取结构化数据用于精准分块 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 批量上传的营销文档合集可能包含多份材料，该上限可覆盖常规批量上传需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：解析后的文档中references字段为空或未被提取。原因：未开启`parse_references`配置项，或配置项参数设置错误。
- 现象：尝试修改分块最大长度时，无法在界面找到对应设置，或修改后未生效。原因：未在对应配置文件中定位到`max_chunk_size`的默认值定义，或修改后未重启服务。
- 现象：上传保险营销PDF后，系统未触发文档解析流程。原因：未将PDF文件关联到启用了文档解析的知识库，或`UPLOAD_FILE_MAX_SIZE`设置小于当前上传文件的大小。

## 怎么确认配好了
- 上传一份包含references字段的保险营销文档，查看解析后的元数据中是否包含references字段的内容。
- 进入知识库的分块配置页面，确认`max_chunk_size`的设置值与预设配置一致。
- 上传一份超过默认单文件大小的测试文档，查看系统是否提示文件过大或正常完成解析。
- 运行本地调试脚本，调用文档解析接口，传入保险产品条款样本，检查返回的分块结果是否保留了完整的保障责任段落。
