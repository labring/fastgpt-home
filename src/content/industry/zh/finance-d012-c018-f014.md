# 光模块营销内容的表单与交互

## 这个品类的数据长什么样
光模块相关营销内容的数据主要来自原厂规格文档、第三方测试报告及供应链备案台账。数据更新节奏随新品发布、供应链参数调整触发，无固定周期。单份文档以结构化参数表为核心，附带适配场景说明，字段包含型号标识、传输速率、工作波长、额定功耗、接口类型、工作温度范围，单位分别为型号字符串、Gbps、nm、W、接口标准、℃。

## 这些特征在「表单与交互」这一环带来什么约束
光模块的多结构化字段与单位要求，要求表单按参数类别拆分输入模块，为每个字段绑定对应单位提示，避免输入混淆。参数间存在匹配约束，需配置联动校验逻辑，例如选定传输速率后自动限定可选择的工作波长范围。数据来源依赖原厂最新规格，需支持用户上传原厂文档作为参数参考，同时预留动态更新预设参数库的入口，适配无固定周期的参数更新节奏。营销场景下需平衡参数完整性与用户填写成本，优先展示核心获客所需的型号、速率、接口类型字段，隐藏非必要参数直到用户主动展开。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `input_max_length` | `800–1200 字符` | 光模块参数说明的单条输入长度通常不超过该范围，避免过长内容导致页面加载卡顿 |
| `form_collapse_default` | 展开核心字段，折叠扩展参数 | 营销获客场景需优先展示型号、速率、接口等核心字段，降低用户填写门槛 |
| `variable_reference_allow_list` | `光模块型号、传输速率、工作波长` | 营销内容中需引用的核心参数为上述三类，限定可引用变量范围避免无效选项 |
| `database_port_input_enable` | 开启 | 光模块供应链数据需通过数据库存储，需支持端口号输入以建立连接 |
| `sandbox_invalid_param_threshold` | `600 秒` | 光模块参数校验需加载原厂文档，超时阈值需覆盖文档解析与参数校验的完整流程 |
| `form_close_unrequired_input` | 开启 | 营销场景中可预设默认参数，允许用户跳过非必要输入直接提交表单 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：表单提交后出现参数不匹配报错，例如选定100G传输速率后仍可选择850nm以外的工作波长。原因：未配置参数联动校验逻辑，未限定传输速率与工作波长的对应关系，导致输入参数不符合光模块实际规格。
- 现象：在知识库引用环节，选择关联的光模块参数知识库后，引用变量下拉框无可选值。原因：未配置`variable_reference_allow_list`参数，未将光模块核心参数加入引用白名单，导致系统未加载对应变量选项。
- 现象：代码沙箱启动失败，界面提示无效参数输入。原因：未调整`sandbox_invalid_param_threshold`配置项，超时阈值设置过短，导致光模块原厂文档解析与参数校验流程未完成即触发超时报错。

## 怎么确认配好了
- 进入表单配置界面，检查核心参数字段是否绑定了对应单位提示，例如传输速率字段附带Gbps单位标识。
- 在知识库引用环节，选择关联的光模块参数知识库，确认引用变量下拉框中存在型号、速率等预设选项。
- 打开数据库连接配置节点，确认端口号输入框可正常激活并输入内容。
- 上传一份光模块原厂规格文档至测试环境，验证代码沙箱是否可正常完成解析，无无效参数报错。
