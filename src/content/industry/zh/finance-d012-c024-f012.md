# 农化制品营销内容的模型接入与配置

## 这个品类的数据长什么样
农化制品的数据主要来源于企业内部的产品说明书、农药登记备案文件、田间试验报告、经销商反馈文档以及作物适配方案。数据更新节奏随新品上市、合规备案变更或种植技术迭代调整，无固定周期。单份文档通常包含产品通用名、有效成分含量、剂型、适用作物范围、使用剂量、安全间隔期、注意事项等字段，有效成分含量多以质量占比或质量体积比标注，使用剂量以亩/公顷用量为单位，部分文档附带多语言合规说明文本。

## 这些特征在「模型接入与配置」这一环带来什么约束
农化制品数据包含严格合规的备案信息与精确参数，要求模型接入时需保留字段校验逻辑，避免生成超范围的营销内容。文档包含长文本的田间试验报告与合规备案文件，对上下文窗口与分段长度有特定要求，需避免截断关键参数或拆分跨字段内容。营销内容需匹配特定作物的适配方案，且需适配金融端的客户获客营销场景，要求召回环节需关联作物标签字段，确保推荐内容与目标种植场景匹配。此外，部分数据包含多语言合规说明，需配置多语言解析适配逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 字符 | 农化文档包含长文本的田间试验报告与合规文件，需保留足够上下文避免截断有效成分、使用剂量等关键参数 |
| `chunkSize` | 800–1000 字符 | 农化数据的剂量、合规字段多为短段落，分段需覆盖完整字段组，避免拆分跨字段内容导致参数缺失 |
| `recallTopK` | 前6–8 条 | 农化营销内容需结合多维度参数（有效成分、适用作物、剂量），召回过多会增加冗余计算，过少无法覆盖全场景需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 合规备案文件多为多页PDF，需足够时间完成文本提取与字段解析，避免中途超时中断 |
| `similarityThreshold` | 0.75–0.85 | 需精准匹配作物与产品的关联关系，阈值过低会引入无关文档，过高则无法召回足够适配内容 |
| `promptTemplate` | 请基于提供的农化产品合规文档与田间试验数据，生成适配目标作物的金融端农化产业链客户获客营销内容，需严格标注有效成分含量与使用剂量单位 | 明确约束模型输出的合规性与参数准确性，适配金融端的获客营销场景，避免生成超范围或参数错误的内容 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为模型输出的营销内容未标注有效成分含量或使用错误单位，原因是未在提示词模板中明确参数标注要求，仅使用通用模型提示。
- 现象为本地部署模型无法正常启动，提示`modelName`或`apiBase`字段为空，原因是未按平台要求填写模型标识与访问地址，未校验必填字段规则。
- 现象为通过域名访问平台时无法加载已配置的模型，且数据与IP访问不一致，原因是未将模型访问域名加入平台的跨域白名单，导致接口请求被拦截。

## 怎么确认配好了
- 上传一份农化产品合规备案文档，核对解析后的字段是否覆盖产品通用名、有效成分含量、适用作物等预设字段。
- 发起测试提问，验证模型输出内容是否严格匹配文档中的合规参数，未出现超范围推荐或参数错误。
- 查看平台的模型状态面板，确认模型连接状态为正常，无报错日志记录。
- 切换不同的模型接入方式，确认配置参数同步生效，生成的营销内容保持一致。
