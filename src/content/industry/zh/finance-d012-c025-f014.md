# 农商行营销内容的表单与交互

## 这个品类的数据长什么样
农商行营销相关数据主要来源于线下网点客户留资台账、线上小程序/公众号预约表单、本地客群经营与户籍关联数据。数据更新节奏分为两类：线下台账每周批量同步，线上表单提交实时更新。文档为结构化表格格式，包含客户姓名、联系电话、意向营销产品、办理网点、预约办理时间等字段。联系电话字段为11位纯数字，产品名称字段为固定枚举值，金额字段单位为元，时间字段格式为YYYY-MM-DD。

## 这些特征在「表单与交互」这一环带来什么约束
线下台账的批量同步要求表单支持批量导入数据的格式校验，避免字段错位或格式不匹配。线上实时提交的需求要求表单内置实时字段校验，拦截无效格式的输入。本地服务属性要求网点选择字段联动本地行政区域，仅展示对应县域内的营业网点，减少用户选择成本。固定枚举的意向产品字段，要求表单使用下拉选择字段，不允许自由输入，降低后续AI识别的歧义。同时，客群数据的本地化属性，要求表单不收集跨区域的非本地客群信息，避免无效留资。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `FORM_FIELD_VALIDATE_TIMEOUT` | `3 秒` | 农商行营销表单字段数量有限，3秒内可完成所有字段格式校验，避免用户等待过长 |
| `BATCH_IMPORT_MAX_ROWS` | `500 行` | 线下网点单次同步的客户留资数据通常在数百级别，该取值可覆盖多数批量导入场景 |
| `WORKFLOW_GLOBAL_VAR_TYPE` | `枚举类型` | 农商行意向营销产品为固定枚举值，枚举类型可限制输入范围，降低后续AI识别歧义 |
| `PARSE_FORM_CONTENT_TIMEOUT` | `10 秒` | 批量导入的单条表单数据解析需要合理时长，10秒可覆盖多数非极端数据场景 |
| `FORM_SUBMIT_RATE_LIMIT` | `10 次/分钟` | 线上用户提交频率处于合理区间，可避免恶意提交占用系统资源 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中知识库选择全局变量配置后无法正常触发检索，报错提示「变量类型不匹配」。原因：未将全局变量设置为枚举类型，农商行营销场景下产品选项为固定枚举值，自由文本类型的变量无法匹配知识库预设的分类标签。
- 现象：用户提交的意向产品描述无法被AI节点正确识别，返回「未匹配到有效产品信息」。原因：表单未使用下拉选择字段，允许用户自由输入非枚举的产品名称，导致AI提示词无法覆盖所有输入场景。
- 现象：批量导入的线下台账数据出现部分字段为空，导入任务显示「部分数据校验失败」。原因：未配置对应格式校验规则，导致非本地网点或无效手机号的字段被跳过。

## 怎么确认配好了
- 提交一条测试用的表单数据，检查字段校验的完成时长，确认符合预设的校验时间要求。
- 导入少量线下台账测试数据，检查所有字段是否正确映射，无空字段或格式错误。
- 配置工作流的AI节点提示词，使用枚举产品名称作为输入，确认AI可正确识别并返回匹配结果。
- 模拟预设频率的提交操作，检查是否触发限流拦截，确认速率限制逻辑正常。
