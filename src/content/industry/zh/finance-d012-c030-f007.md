# 化妆品营销内容的工作流编排

## 这个品类的数据长什么样
化妆品营销内容的数据主要来自金融机构合作品牌的内部产品管理系统、合规备案平台及电商详情页，用于金融场景下的获客营销。数据更新节奏随新品上线、成分合规调整或营销素材迭代波动，无固定周期。单条数据文档包含`product_id`、`product_name`、`ingredient_list`、`skin_type_suitable`、`specification`、`marketing_copy`等字段，其中成分表字段以成分名称+含量占比的结构化格式存储，规格字段包含净含量、包装单位等信息，宣传文案字段多为多模态混合内容，包含文字脚本、配图描述。

## 这些特征在「工作流编排」这一环带来什么约束
化妆品品类的数据特征对金融场景下的工作流编排带来三点约束：第一，成分表与宣传素材的多模态混合结构，要求工作流需同时配置文本解析节点与图片OCR解析节点，适配不同来源的素材格式；第二，数据更新无固定周期，需支持事件触发式工作流，不依赖固定定时执行；第三，产品字段存在多值属性（如适用肤质包含多种类型），工作流分支节点需支持多条件匹配逻辑，避免营销内容与产品属性不匹配。另外，部分营销素材需关联合规备案数据，工作流需嵌入合规校验环节，确保内容符合金融营销监管要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `10 MB` | 化妆品营销素材多为产品实拍图、成分表截图，单张素材大小通常不超过10MB，超出会触发上传拦截 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 成分表解析需处理多段结构化文本，长素材解析耗时较长，600秒可覆盖绝大多数常规场景 |
| `maxContext` | `8000 字符` | 化妆品营销文案需覆盖成分说明、适用肤质、规格信息，8000字符可承载完整的关联上下文 |
| `PARSE_MULTI_CONDITION` | 开启 | 产品适用肤质、成分类型存在多值属性，需支持多条件分支匹配，确保生成内容与产品属性精准对应 |
| `BATCH_CONCURRENCY_LIMIT` | `3 个并发` | 批量生成营销内容时，单批次并发过高会触发API调用限流，3个并发可平衡执行效率与调用稳定性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用工作流API上传营销素材时返回`413 Request Entity Too Large`错误，原因是未将`UPLOAD_FILE_MAX_SIZE`配置调整至适配化妆品素材的大小阈值，默认阈值通常小于10MB。
- 大模型节点执行后返回`500 Gateway forwarding error because service is disconnected`报错，原因是工作流中未配置上下文隔离，导致大模型服务资源被耗尽，或节点依赖的外部服务未正常连通。
- 批量运行工作流时部分节点执行失败，返回`429 Too Many Requests`状态码，原因是未配置合理的并发限制，单批次并发数量超出API调用的限流阈值。

## 怎么确认配好了
- 上传单张化妆品营销素材，验证上传接口返回正常状态码，确认文件大小符合配置的阈值要求。
- 运行单条测试工作流，检查大模型节点输出是否覆盖产品的完整属性信息，确认上下文配置适配业务场景。
- 开启批量运行功能，观察节点执行状态，确认并发数量未超出API限流阈值，无异常失败节点。
- 触发预设的事件触发规则，验证工作流在对应数据更新后自动启动，确认触发逻辑配置正确。
