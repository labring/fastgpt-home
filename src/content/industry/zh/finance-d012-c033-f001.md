# 化纤营销内容的HTTP 接口与外部系统

## 这个品类的数据长什么样
化纤品类的营销数据主要来源于上游石化原料报价、下游织造订单、现货库存及产品性能检测报告。数据来源包括行业协会公开接口、上游生产企业ERP系统、第三方大宗商品交易平台。更新节奏差异较大：现货报价数据每小时更新，订单数据实时同步，产能与库存数据每日更新。文档结构多为结构化JSON或CSV格式，核心字段包含产品名称、纤度（单位dtex）、断裂强度（单位cN/dtex）、含税单价（单位元/吨）、库存数量（单位吨）、原料类型等，部分非标产品会附带自定义检测参数字段。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
化纤品类的多来源、多更新节奏特征，要求外部系统对接时需适配不同的拉取频率。结构化数据的多字段特性，要求HTTP接口需支持字段白名单配置，避免传输冗余数据。不同的单位体系（如dtex、元/吨）要求接口需统一单位解析或要求调用方携带单位参数，防止数据误用。实时订单与低频产能数据的混合对接，需支持多接口并行调用与优先级调度，确保营销内容能及时获取最新的现货与报价信息。此外，化纤产品SKU数量较多，接口分页参数需支持灵活调整，避免单次返回数据量过大导致超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 前10条对话 | 化纤营销对话需保留近期的产品参数与客户询价历史，避免上下文丢失 |
| `HTTP_REQUEST_TIMEOUT` | 30 秒 | 上游化纤数据接口可能存在网络延迟，30秒可覆盖多数正常响应时长 |
| `RECALL_TOP_K` | 前15条 | 化纤品类SKU数量较多，需召回更多相关产品数据以覆盖客户潜在需求 |
| `PARSE_FIELD_WHITELIST` | ["product_name", "fineness", "strength", "price", "stock"] | 仅保留营销所需的核心字段，减少接口传输量与解析开销 |
| `API_AUTH_TYPE` | API_KEY | 适配行业通用的外部系统对接认证方式，简化跨系统授权流程 |
| `HTTP_RETRY_TIMES` | 3 次 | 应对上游数据接口的临时波动，降低单次请求失败概率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用接口时传入的上下文数量与工作流设置的`maxContext`不符，日志显示额外携带了历史对话。原因：未将`maxContext`与外部接口的上下文窗口参数同步配置，导致双参数冲突。
- 现象：部署后3000端口无法访问，容器日志仅显示启动信息无报错。原因：未开放防火墙的3000端口，或外部系统的访问白名单未添加FastGPT部署节点IP。
- 现象：接口返回的化纤数据字段为空，如`price`字段无值。原因：未在`PARSE_FIELD_WHITELIST`中配置对应字段，导致接口过滤了非白名单字段。

## 怎么确认配好了
- 调用测试接口，传入预设的化纤营销对话历史，检查返回的上下文数量与`maxContext`配置一致。
- 从外部化纤数据接口拉取样本数据，验证接口返回的字段与`PARSE_FIELD_WHITELIST`配置的字段完全匹配。
- 模拟外部系统的访问请求，检查3000端口的连通性与API_KEY认证校验逻辑正常。
- 触发模拟的接口超时场景，检查是否按`HTTP_RETRY_TIMES`配置进行重试，最终返回有效数据。
