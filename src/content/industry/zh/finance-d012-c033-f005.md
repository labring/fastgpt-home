# 化纤营销内容的多轮对话与提示词

## 这个品类的数据长什么样
化纤品类的数据主要来源于上游石油石化原料现货报价平台、下游织造与服装企业的交易台账、行业协会发布的供需监测周报，以及金融机构采集的化纤企业供应链金融相关的经营数据。数据更新节奏存在差异：原料价格数据每日更新，订单与库存数据隔日同步，行业供需报告与企业经营数据按周度或月度发布。文档结构多包含产品牌号、规格参数、当日均价、库存余量、下游应用场景、企业营收与融资需求等字段，单位涵盖元/吨、千克、千米、旦尼尔等精细计量项。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
化纤数据的精细字段与单位要求提示词必须明确指定参数的计量标准，避免金融营销对话中出现单位混淆的错误。金融营销场景下，需结合化纤企业的融资需求与产品参数生成推广内容，多轮对话需保留上下游原料与成品的关联上下文，否则无法准确回答牌号对应价格、企业适配的融资方案等问题。不同更新频率的数据需在对话中区分实时调用与历史查询，否则可能返回过时的报价或经营数据。过长的对话历史会占用上下文窗口，导致关键参数被截断，影响金融营销内容的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 金融营销对话中，客户常关联询问化纤企业的经营数据、产品参数与融资方案，需保留多轮上下文以支持关联查询 |
| `similarity_threshold` | `0.75–0.85` | 化纤产品规格参数相似度较高，需过滤低匹配度的冗余文档，避免金融推广内容混淆不同牌号的产品与融资方案 |
| `maxHistoryTurns` | `10–15 轮` | 化纤企业客户常反复确认产品细节、融资额度与交货周期等内容，过多历史轮次会占用上下文窗口，影响推广内容生成效率 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 化纤金融营销物料常包含长格式的参数表格与企业经营报表，解析耗时高于通用品类，需延长超时时间 |
| `response_max_tokens` | `2000 字符` | 金融营销内容需详细说明产品规格、适配场景与融资方案，用于生成面向化纤企业的推广话术与资料，需保证回答长度足够 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为对话生成的金融推广物料下载链接提示“已过期”，无法调整有效期设置，原因是未配置`log_expire_days`参数，使用了平台默认的短期有效期规则。
- 现象为间隔数月的历史对话无法继续发起，系统返回“上下文不存在”，原因是未开启`persist_history`配置项，对话历史未进行持久化存储。
- 现象为单轮对话响应耗时超过10秒，原因是`recall_top_k`参数设置过高，且未开启`rerank`配置，召回并处理了过多冗余的化纤产品与金融方案相关数据。

## 怎么确认配好了
- 发起包含多个化纤产品牌号、企业经营数据与融资方案的多轮对话，核对系统展示的上下文内容是否包含所有关键字段。
- 上传一份包含长参数表格与企业经营报表的化纤金融营销物料，核对解析后的文本是否完整，无截断情况。
- 测试发起间隔超过7天的对话请求，核对历史上下文是否可正常加载。
- 模拟多轮连续对话，核对单轮响应耗时是否符合金融业务的预期。
