# 医疗器械营销内容的多轮对话与提示词

## 这个品类的数据长什么样
服务于金融/保险/理财场景的医疗器械营销相关的数据主要来自企业内部的产品注册证文件、临床验证报告、官方产品说明书、合规备案资料，以及经审核的临床案例文档。更新节奏随产品迭代与合规变更而定，无固定周期，新机型获批或注册证变更后会触发数据更新。文档结构多包含结构化参数表格、长文本合规说明、单页产品介绍页，字段涵盖产品型号、注册证编号、技术参数（带dpi、秒/张等专属单位）、适用科室、禁忌人群等，需符合国家医疗器械分类目录的规范表述。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
医疗器械营销数据的结构化参数多、合规性要求高且更新无固定周期，会对多轮对话与提示词配置带来多重约束。首先，多轮对话需精准匹配产品型号、注册证编号等带专属单位的技术参数，避免单位混淆或参数错位。其次，长文档合规说明需拆分召回，防止上下文窗口溢出导致关键内容截断。第三，需在提示词中加入合规校验逻辑，确保生成内容不超出备案范围，且定期同步更新知识库以匹配最新合规信息。最后，针对不同科室的适用场景，需在多轮对话中区分参数调用逻辑，避免跨场景误用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 医疗器械营销文档多包含长合规文本与多组技术参数，该区间可完整容纳多轮对话上下文与召回的知识库内容 |
| `recallTopK` | `前 6–8 条` | 医疗器械参数字段较多，需召回足够的结构化数据支撑多轮对话，同时避免冗余信息干扰 |
| `similarityThreshold` | `0.75–0.85` | 需精准匹配产品型号与注册证编号等关键字段，避免低相似度的无关文档被召回 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 医疗器械临床报告与注册证文件多为长文档，需足够时间完成结构化解析 |
| `promptTemplate` | 固定加入合规校验表述，按产品型号分组调用参数 | 医疗器械营销内容需严格合规，多轮对话需按不同型号拆分参数避免混淆 |
| `CORS_ALLOW_ORIGINS` | 私有化部署场景填写对应前端域名 | 前端调用对话接口需符合浏览器跨域安全规范，避免跨域报错 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中配置了联网搜索与AI对话的HTTP请求节点，但对话执行时未触发该节点，直接调用内置AI能力。原因：未将HTTP请求节点接入对话链路的前置触发逻辑，或未配置节点的触发条件与参数传递规则。
- 现象：前端调用对话接口返回`403 Forbidden`或CORS相关报错。原因：未配置`CORS_ALLOW_ORIGINS`参数，或填写的域名与实际前端访问域名不匹配，违反浏览器跨域安全策略。
- 现象：私有化部署后无法准确统计每次对话消耗的token数量。原因：未配置token统计的日志采集规则，或未启用对话过程中的token计数功能。

## 怎么确认配好了
1.  触发一次包含产品型号与技术参数的查询，核对返回结果中是否包含知识库内的准确参数与合规表述。
2.  查看工作流执行日志，确认HTTP请求节点是否在对话触发后正常执行并返回对应数据。
3.  使用前端开发工具发起对话接口请求，确认无CORS相关报错。
4.  模拟多轮对话的参数追问场景，确认系统能准确关联不同轮次的产品型号与对应参数。
