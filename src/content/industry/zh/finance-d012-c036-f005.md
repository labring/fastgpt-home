# 半导体营销内容的多轮对话与提示词

## 这个品类的数据长什么样
半导体营销内容的数据主要来自厂商官方产品手册、晶圆代工报价文档、行业展会公开资料与客户需求调研表。更新节奏分为固定周期与临时调整：产品参数按季度更新，市场动态按月度更新，突发产能调整则实时同步。文档结构通常包含制程节点、封装类型、应用场景、合规认证四大模块，字段包括型号编号、制程（单位纳米）、功耗（单位毫瓦）、供货周期（单位周）及认证编号，长文档会附带详细测试报告附录。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
上述数据特征对多轮对话与提示词环节带来多重约束。首先，专业参数存在单位歧义，需在提示词中明确统一单位格式，避免混淆制程纳米与微米、功耗毫瓦与瓦特的表述，确保多轮对话中参数传递准确。其次，长文档与多轮上下文需适配足够的上下文窗口，否则会丢失前序对话中的应用场景信息，导致后续问答偏离用户需求。第三，动态更新的参数需在提示词中加入版本约束，确保引用最新发布的产品数据，避免使用过时的供货周期或认证信息。第四，细分字段较多，召回环节需精准匹配对应模块，避免无关参数干扰多轮对话的逻辑连贯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 字符 | 半导体营销文档单段测试报告常达3000字符，多轮对话需保留3轮以上上下文，覆盖完整参数与场景信息 |
| `prompt_template` | 需明确标注参数单位为纳米、毫瓦、周，优先引用近一季度更新的产品数据，跟踪用户应用场景追问 | 半导体专业参数存在多单位歧义，需统一输出格式，避免误导用户，同时确保对话紧扣用户需求场景 |
| `recall_top_k` | 前6条 | 半导体营销内容需覆盖制程、功耗、应用、认证、供货周期、合规6类核心字段，每条对应一个召回块 |
| `similarity_threshold` | 0.75–0.85 | 半导体专业术语相似度较高，过低会引入无关参数，过高会遗漏匹配的细分型号 |
| `timeout` | 120 秒 | 长文档解析与多轮参数校验需较长处理时间，避免提前超时中断对话 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为对话响应超时，控制台返回状态码504 Gateway Timeout，原因是未调整`timeout`参数至适配长文档解析的时长，导致多轮参数校验环节提前中断。
- 现象为对话开场白快捷按键未触发预设话术，原因是未配置`prompt_template`与快捷键的绑定逻辑，预设话术未关联至对应按键。
- 现象为无登录状态下对话历史中的产品参数图片无法加载，原因是未开启知识库图片的公共访问权限，临时会话无法拉取存储的图片资源。

## 怎么确认配好了
- 上传一份半导体产品手册，发起包含制程、功耗的多轮对话，验证参数单位统一标注，上下文保留前3轮的场景追问信息。
- 测试`recall_top_k`参数，发起包含6类核心字段的查询，验证返回结果条数符合预设值。
- 退出登录状态，发起对话并上传产品参数图片，验证历史会话中图片可正常加载。
- 调整`similarity_threshold`至0.8，查询细分制程型号，验证返回结果的匹配精度符合预期。
