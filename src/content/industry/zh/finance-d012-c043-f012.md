# 商业地产营销内容的模型接入与配置

## 这个品类的数据长什么样
商业地产营销内容的数据主要来自商圈运营台账、招商手册、活动策划文档、商户合作协议及线下导览资料。数据更新节奏随招商调整、营销活动排期波动，无固定周期，单次更新文档长度差异较大。文档结构多包含商圈核心信息、业态分区详情、租赁报价、活动规则四类核心字段，其中面积、租金等字段固定使用平方米、元/平方米/天作为单位，联系方式字段多为固定电话或手机号格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于商业地产营销内容的文档长度差异大且更新无固定周期，模型接入时需适配可变上下文长度的调用参数，避免长文本截断或资源浪费。因核心字段存在固定单位与格式要求，模型调用前需配置字段校验规则，确保提取的租赁面积、租金数值符合预设单位格式。同时，多商户的个性化营销内容需调用不同模型或调整提示词，需配置模型路由的相关规则，按内容所属商圈或商户分配调用资源。另外，活动类营销内容时效性强，需配置定时触发的模型调用任务，保障内容生成的及时性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–16000 字符 | 商业地产营销文档长度差异较大，覆盖基础商圈信息与活动详情，该区间可覆盖绝大多数物料长度，避免内容截断 |
| `PARSE_FIELD_RULES` | 面积字段校验单位为㎡，租金字段校验单位为元/㎡/天 | 核心业务字段存在固定单位要求，规则可确保模型提取的数值格式合规，减少后续整理成本 |
| `MODEL_ROUTE_RULE` | 按商圈标签分配对应模型密钥 | 不同商圈的营销内容调用量存在差异，该配置可实现多密钥的负载均衡，适配高并发调用场景 |
| `API_REQUEST_TIMEOUT` | 120 秒 | 长文档解析与多字段校验需要较长处理时间，避免中途超时中断任务 |
| `TASK_TRIGGER_MODE` | 事件触发+定时校验 | 营销内容更新无固定周期，事件触发适配临时活动快速更新，定时校验保障遗漏内容的同步 |
| `UPLOAD_FILE_MAX_SIZE` | 200 MB | 招商手册、活动策划文档多包含高清配图与多页内容，该尺寸可覆盖多数物料包大小 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置多个模型密钥后，仍频繁出现`429 Too Many Requests`报错。原因：未配置按调用量分配密钥的路由规则，仅固定使用单个密钥，未实现多密钥的负载均衡。
- 现象：接入第三方模型时出现`Invalid API Key`报错，或无法正常调用模型。原因：未正确填写平台提供的密钥与接入端点，或未配置模型的权限范围。
- 现象：生成的营销内容缺失核心业务字段，如面积、租金数值。原因：未配置`PARSE_FIELD_RULES`对字段格式进行校验，模型未准确识别并提取预设的核心字段。

## 怎么确认配好了
- 上传一份完整的商业地产招商手册，检查解析后提取的字段是否包含预设的核心信息，核对面积、租金的单位是否符合配置要求。
- 发起多轮模拟调用，查看后台请求分配记录，确认不同模型密钥被均衡使用，未出现单一密钥过载的情况。
- 触发一次临时营销内容的生成任务，确认任务按时启动并完成，无超时或报错信息。
- 调用模型接口获取解析结果，检查返回内容的格式是否符合预设的字段规则，无缺失或错误的业务信息。
