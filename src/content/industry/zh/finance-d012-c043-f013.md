# 商业地产营销内容的知识库检索与召回

## 这个品类的数据长什么样
商业地产营销相关数据主要来源于项目内部招商文档、物业运维系统、线下活动物料、商圈运营报表。更新节奏不均，招商调整、新品牌入驻时实时更新，主题活动物料随档期更新，运营报表按月更新。文档类型多为带结构化字段的PDF、Excel，以及标注具体坐标的区位图，字段包含商铺编号、租金单价（元/平方米·日）、业态分类、入驻品牌全称、活动执行周期等，部分文档同时包含文本描述与可视化标注内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据包含结构化的租金、商铺编号等专属业务字段，且存在大量带坐标的区位类文档，检索需同时覆盖语义匹配与结构化字段匹配。文档长度差异较大，短则单页活动通知，长则数十页的招商规划书，需适配不同长度的文本分段规则，避免破坏结构化信息的上下文关联。更新频率不均，运营报表按月更新，招商调整实时生效，需支持增量同步，不采用全量重传，确保召回内容的时效性。部分文档包含非文本的区位标注，需支持结构化元数据与可视化内容的关联检索，提升匹配精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_CHUNK_SIZE` | 800–1200 字符 | 商业地产文档既有长段落的招商规划，也有短的活动通知，该区间可平衡分段完整性与召回精度 |
| `RECALL_TOP_K` | 前 8–12 条 | 营销内容需覆盖商铺、活动、区位等多维度信息，过多会干扰上下文，过少会遗漏有效内容 |
| `SIMILARITY_THRESHOLD` | 0.72–0.80 | 商业地产的租金、业态等术语辨识度高，阈值过低会召回无关的竞品信息，过高会遗漏相似业态的匹配结果 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 大型招商手册合集的体积通常不超过该值，避免上传超时 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 多页PDF的解析耗时较长，该时长可覆盖完整解析流程 |
| `ENABLE_STRUCTURED_PARSE` | 开启 | 商业地产数据包含商铺编号、租金等结构化字段，开启后可保留元数据用于精准检索 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工具调用返回的结果与知识库搜索结果无关联，原因是未开启结构化解析功能，仅基于纯文本语义匹配，无法精准匹配商铺编号、租金单价等业务专属字段。
- 现象为离线环境下上传文件后始终处于加载状态，联网后恢复正常，原因是系统需访问指定外部资源完成文档解析的前置校验，离线环境下无法完成该流程。
- 现象为使用语义检索无法召回目标内容，但全文检索可正常召回，原因是分段参数设置不合理，破坏了长文档中结构化信息的上下文关联，或相似度阈值设置过高，导致有效匹配未达标。

## 怎么确认配好了
- 上传一份包含结构化字段的商业地产文档，检查解析后的分段是否保留了商铺编号、租金单价等关键信息，确认`ENABLE_STRUCTURED_PARSE`配置生效。
- 发起一次语义检索测试，输入包含业态、租金范围的查询词，核对召回结果的条数是否符合预设的`RECALL_TOP_K`范围。
- 调整相似度阈值后发起多次检索，对比召回结果的相关性变化，确认阈值设置匹配业务需求。
- 模拟离线环境上传文档，检查是否触发加载超时提示，确认外部资源访问的依赖逻辑符合预期。
