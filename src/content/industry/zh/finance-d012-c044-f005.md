# 商业物业营销内容的多轮对话与提示词

## 这个品类的数据长什么样
商业物业的营销相关数据主要来源于自持招商手册、在管项目台账、商户租赁合同、活动策划方案及客流统计报表。数据更新节奏随业务节点调整：招商信息按月更新，商户入驻信息随合同变更实时同步，活动信息按季度或活动周期更新。文档结构以结构化条目为主，包含铺位编号、建筑面积、租金单价、业态类型、入驻商户全称等字段，部分文档包含图文结合的活动宣传素材。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
结构化的字段要求多轮对话需精准匹配铺位编号、合同编号等唯一标识，避免混淆不同商户或铺位的信息。高频更新的商户与招商数据，要求知识库同步频率匹配业务节奏，提示词需明确指定模型优先调用最新的在管数据。多类型文档的混合存储，要求提示词区分不同场景的知识库调用规则，例如营销内容生成时优先调用招商手册与活动方案，获客咨询时优先调用台账与租赁合同信息。同时图文结合的素材要求对话流程支持图片内容的识别与展示。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 商业物业数据包含铺位面积、租金说明等长文本内容，该取值可保留足够上下文避免对话断档 |
| `recall_top_k` | `前6–8 条` | 招商与商户信息条目较多，过多召回内容会超出上下文窗口，过少则可能遗漏优质匹配结果 |
| `similarity_threshold` | `0.72–0.80` | 铺位编号、合同编号等精准字段需要较高匹配度，该区间可过滤无关召回结果，同时保留有效匹配内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 秒` | 大型招商手册PDF包含多页图文内容，解析耗时较长，该取值可避免解析任务中途中断 |
| `enable_rag_citation` | `开启` | 营销场景需明确展示知识库来源信息，开启后可让模型输出附带引用的知识库片段标识 |
| `UPLOAD_FILE_MAX_SIZE` | `10 MB` | 活动宣传图片通常为单张2–5 MB，该取值可支持常规图文素材上传 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调大`maxContext`参数至2000以上后，模型输出未引用任何知识库片段。原因：未同步开启`enable_rag_citation`参数，或知识库召回的片段总长度超出模型上下文窗口上限。
- 现象：生成的营销内容中附带知识库片段的内部标识（如铺位编号、合同编号）。原因：提示词未明确要求隐藏非营销类内部标识，或召回规则未过滤无关条目。
- 现象：对话界面无法显示活动宣传图片。原因：未配置知识库图片解析规则，或`UPLOAD_FILE_MAX_SIZE`设置小于图片文件大小。

## 怎么确认配好了
- 发起模拟招商咨询，验证模型输出引用了知识库中的铺位信息，且无内部字段泄露。
- 上传测试用的招商手册PDF，等待解析完成后，检查解析后的文本字段是否包含铺位编号、租金单价等必要信息。
- 调整`maxContext`参数至不同区间，验证模型输出的上下文连贯性符合预期。
- 测试多轮对话场景，验证模型能区分招商咨询、活动咨询等不同营销场景的输出逻辑。
