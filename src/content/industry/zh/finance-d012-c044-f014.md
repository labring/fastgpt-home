# 商业物业营销内容的表单与交互

## 这个品类的数据长什么样
商业物业的营销数据主要来源于内部招商管理系统、租户台账、线下到访登记表单及周边商业配套统计工具。数据更新节奏随租赁状态变更实时同步，营销活动相关数据则随活动周期更新。文档结构分为两类：招商类文档包含商铺编号、建筑面积（㎡）、租金单价（元/㎡/天）、允许经营业态等结构化字段；营销交互类文档包含到访人姓名、联系电话、意向商铺区域、预约到访时间等字段。

## 这些特征在「表单与交互」这一环带来什么约束
商业物业的结构化字段多且附带明确单位，要求表单预设字段单位提示，避免输入格式错误。租赁状态实时更新的特性，要求表单联动实时数据校验，例如预约看房时自动过滤已出租的商铺。营销活动周期内数据动态调整，要求表单支持动态加载可选业态、商铺区域等选项，无需手动修改配置。跨系统的数据来源要求表单支持多数据源字段映射，减少手动录入环节，同时保证提交数据与内部台账一致。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `form_field_unit_switch` | 开启 | 商业物业表单包含面积、租金等带单位字段，开启后可自动附加单位提示，减少输入错误 |
| `dynamic_option_update_freq` | 60 秒 | 租赁状态实时更新，每60秒刷新可选商铺、业态列表，保证数据一致性 |
| `form_data_sync_timeout` | 30 秒 | 对接内部招商系统，30秒超时可避免长时间等待导致的提交失败 |
| `form_validation_trigger` | 实时校验 | 提前校验预约时间、商铺状态，避免提交后因数据过期被驳回 |
| `workflow_node_render_limit` | 50 节点 | 商业物业营销工作流常包含多数据源对接、表单校验节点，限制50节点可避免页面卡顿 |
| `variable_selector_auto_refresh` | 开启 | 动态指定知识库时，自动刷新可用变量列表，解决变量选择空白问题 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：本地部署的工作流配置界面输入文字卡顿，节点超过50个时尤为明显。原因：未限制`workflow_node_render_limit`参数，过多节点导致前端渲染负载过高。
- 现象：知识库搜索节点选择变量引用时，变量列表空白无法选择。原因：未开启`variable_selector_auto_refresh`配置，未自动拉取工作流中定义的变量。
- 现象：工具调用环节无法找到代码运行节点的连线配置入口。原因：未在工作流设置中开启高级工具调用权限，或使用的版本未开放该功能（需确认版本为4.9.10及以上）。

## 怎么确认配好了
- 打开表单配置页面，检查每个带单位的字段是否显示了预设的单位提示，确认配置生效。
- 模拟提交一条预约看房的表单，选择已标记为出租的商铺，校验是否弹出对应的拦截提示，确认实时校验功能正常。
- 进入知识库搜索节点配置，尝试选择变量引用，确认变量列表可正常加载，无空白情况。
- 导入50个以上的工作流节点，测试界面输入文字是否仍存在卡顿，确认渲染限制配置生效。
