# 城商行营销内容的表单与交互

## 这个品类的数据长什么样
城商行营销相关数据主要来源于内部核心业务系统、客户关系管理系统，以及线下网点收集的潜在客户意向数据。产品类数据随产品上架、参数调整同步更新，客户意向数据随表单提交实时生成。文档结构分为两类，一类是结构化的产品元数据，包含产品标识、投资门槛、存续周期等字段，单位分别为编码、元、月；另一类是非结构化的用户提交意向表单，包含用户身份信息、意向产品类型等内容。

## 这些特征在「表单与交互」这一环带来什么约束
结构化产品数据来源固定但更新频繁，要求表单的产品选项需实时拉取，不应静态写入，避免出现已下架产品的选项。客户意向数据随提交实时生成，要求表单提交接口需支持同步校验与落库，避免数据丢失。不同营销场景下的表单必填字段存在差异，例如信贷类营销需额外采集收入证明字段，存款类需采集起投金额，要求表单支持条件显示逻辑。营销表单对接线下网点引流时，需支持扫码后自动填充部分客户已知信息，减少重复填写步骤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `dynamic_form_options` | 绑定行内产品库API，每12小时同步一次 | 适配产品数据更新频率，避免静态选项过期 |
| `form_field_condition` | 按产品类型触发对应必填字段 | 匹配不同营销场景的字段差异需求 |
| `UPLOAD_FILE_ALLOW_EXT` | `["jpg", "png", "pdf", "docx"]` | 覆盖营销场景常见的资质证明、合同文件格式 |
| `MODEL_API_TIMEOUT` | `30 秒` | 适配城商行内部系统的接口响应时长，避免超时报错 |
| `knowledge_retrieve_top_k` | `前3条` | 匹配城商行营销内容的精准推荐需求，避免过多冗余结果 |
| `form_submit_webhook` | 绑定行内客户管理系统接口 | 实现意向数据实时同步落库 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为多层级产品选择表单无法按用户选择动态加载下一级选项，原因是未配置`form_field_condition`的联动逻辑，仅使用静态选项列表。
- 现象为表单上传文件时提示格式不支持，原因是未将`UPLOAD_FILE_ALLOW_EXT`配置为覆盖营销场景所需的资质文件格式，仅开放了少量通用格式。
- 现象为代码运行节点中无法选择知识库引用的变量，原因是未在前置节点中配置知识库召回的输出变量绑定，或未开启变量暴露开关。

## 怎么确认配好了
- 访问表单预览页，选择不同的产品类型，核对对应字段是否按预设规则显示或隐藏。
- 上传预设配置范围内外的测试文件，核对系统的上传校验结果是否符合配置。
- 提交测试表单，核对绑定的webhook接口是否收到完整的意向数据。
- 在代码运行节点中配置知识库召回步骤，核对变量选择面板中是否出现知识库召回的输出字段。
