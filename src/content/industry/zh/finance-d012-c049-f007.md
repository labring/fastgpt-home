# 基建工程营销内容的工作流编排

## 这个品类的数据长什么样
基建工程相关营销内容的数据主要来自公开招投标公告、施工过程日志、企业资质备案文件、区域基建规划方案及过往项目案例文档。数据更新节奏随项目进度触发，中标、开工、竣工阶段会产生新的数据源文件。单份文档通常包含标段编号、工程造价、施工周期、技术参数等结构化字段，部分招投标文件会附带CAD图纸附件，文档长度跨度较大，从数千字的项目说明到数十页的完整施工方案不等。

## 这些特征在「工作流编排」这一环带来什么约束
基建工程数据的多来源、非固定更新节奏，要求工作流支持按需触发机制，适配项目中标、开工等突发更新场景。文档包含CAD图纸附件与长文本内容，要求工作流内置非文本格式解析节点，同时支持长文档分段配置，避免解析超时。结构化字段的多样性，要求工作流配置字段映射规则，将工程造价、施工周期等专属字段直接接入营销内容生成环节。不同项目的文档结构差异较大，要求工作流保留可调整的解析模板，适配不同标段的文档格式要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_SUPPORTED_FORMATS` | `["pdf", "docx", "xlsx", "dwg", "zip"]` | 基建工程常用的文档格式包含CAD图纸dwg、工程清单xlsx、方案文档docx等，覆盖核心数据源类型 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 基建工程的CAD图纸包、完整施工方案包通常体积较大，需适配单文件上传上限 |
| `WORKFLOW_TRIGGER_MODE` | `manual + webhook` | 营销内容生成需随项目进度按需触发，webhook适配API调用场景，manual适配临时编辑需求 |
| `MAX_DOCUMENT_SEGMENT_LENGTH` | `1000–1200 字符` | 基建工程文档包含大量专业术语与长段落，分段长度适配后续内容生成的上下文窗口要求 |
| `FIELD_EXTRACTION_RULES` | 按实测标定 | 不同基建项目的文档字段命名存在差异，需针对具体数据源调整抽取规则 |
| `WORKFLOW_TIMEOUT_SECONDS` | `600 秒` | 长文档解析与多节点编排的执行时长较长，需预留足够的执行时间 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用工作流API时返回`413 Request Entity Too Large`错误，原因是未调整`UPLOAD_FILE_MAX_SIZE`配置，未适配基建工程大体积文档的上传需求。
- 工作流执行后返回的营销内容缺少工程造价、施工周期等专属字段，原因是未配置`FIELD_EXTRACTION_RULES`，未正确抽取基建文档的结构化字段。
- 传入全局变量知识库ID后工作流提示知识库不存在，原因是未通过webhook参数传递知识库ID，错误依赖未生效的全局变量配置。

## 怎么确认配好了
- 上传一份包含CAD附件与结构化字段的典型基建工程文档，检查解析节点是否能正确提取标段编号、工程造价等字段，验证`FIELD_EXTRACTION_RULES`配置是否生效。
- 调用工作流API上传大体积的工程文档包，检查是否能正常触发执行并完成解析，验证`UPLOAD_FILE_MAX_SIZE`配置是否适配。
- 通过webhook触发工作流，检查营销内容生成节点是否能接入抽取后的结构化字段，验证`WORKFLOW_TRIGGER_MODE`配置是否正确。
- 查看工作流执行日志，确认执行时长未超过预设阈值，验证`WORKFLOW_TIMEOUT_SECONDS`配置是否合理。
