# 基建工程营销内容的工具调用与插件

## 这个品类的数据长什么样
基建工程相关金融营销的核心数据来源于项目BIM模型、官方招投标公告平台、施工台账系统、工程财务结算报表，服务于金融机构面向基建主体的获客与营销内容生成。更新节奏分为三类：招投标公告随项目进度实时更新，施工日志每日同步，BIM模型与结算报表随节点里程碑更新。文档结构以结构化字段为主，包含项目编号、标段划分、建筑面积（单位：㎡）、合同总金额（单位：万元）、开工与竣工日期、参与方资质等级、材料规格型号等，部分配套文档如施工方案、图纸说明为长文本格式，单篇可达数万字符。

## 这些特征在「工具调用与插件」这一环带来什么约束
基建工程金融营销的多源异构数据需要工具调用对接多个独立接口，导致配置时需处理不同接口的认证规则与响应格式；字段单位与格式不统一，如部分招投标接口返回的金额以元为单位，部分财务系统以万元为单位，需工具调用环节额外配置格式校验与转换逻辑，确保金融营销内容的数值准确；长文本配套文档需要工具支持分段解析与上下文聚合，避免超出大模型的上下文窗口，影响营销内容的完整性；实时性要求较高的营销内容（如中标公告推送）需工具调用的缓存周期设置较短，确保金融机构向基建主体推送的信息具备时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_max_count` | 2–3 次 | 基建工程金融营销需调用招投标、BIM、财务三类工具，单次轮次调用过多会导致响应超时 |
| `plugin_timeout` | 15–20 秒 | 招投标接口响应通常较慢，且需拉取多页数据，过长会阻塞整体流程，过短会丢失有效结果 |
| `tool_result_parse_mode` | `structured_only` | 基建工程数据多为结构化字段，仅解析结构化结果可过滤冗余文本，提升调用准确性 |
| `plugin_auth_type` | `api_key_based` | 多数工程类开放接口采用API密钥认证，适配现有项目对接的安全规范 |
| `max_tool_context_length` | 8000–12000 字符 | 施工方案、图纸说明类文档较长，需适配长文本解析的上下文窗口要求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调用返回的工程字段为空或格式错误，如`contract_amount`字段显示为字符串，未采用数字类型。原因：未针对基建工程的专属字段配置结果解析规则，大模型无法识别并提取结构化数据，导致营销内容无法生成准确的项目信息。
- 现象：配置多工具调用时仅执行第一个请求，无法同时触发招投标与BIM数据的拉取。原因：未正确设置`tool_call_max_count`参数，或未开启多工具并行触发配置，无法支持同时发起多个工程类接口请求。
- 现象：工具调用返回`request timeout`报错或状态码`504`，或获取的当前时间与工程所在地不符。原因：将`plugin_timeout`设置过短，未适配招投标、BIM平台的长响应延迟；或未校准时区参数，默认时区与工程所在地不符，导致时间插件返回的信息错误。

## 怎么确认配好了
- 发起单次工具调用请求，指定获取某基建项目的`construction_area`与`contract_amount`字段，验证返回结果的格式与单位符合预期。
- 配置多工具并行触发，查看平台日志确认两个及以上工程类接口同时被调用，无遗漏或阻塞情况。
- 调整`plugin_timeout`参数至5秒，模拟超时场景，验证平台返回`request timeout`错误提示，符合预期设置。
- 上传工程图纸至多模态插件，确认图像可被正常解析并提取标注信息，无格式或分辨率报错。
