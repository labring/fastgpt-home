# 基建工程营销内容的知识库检索与召回

## 这个品类的数据长什么样
基建工程的营销内容数据主要来源于项目投标文件、竣工案例库、区域基建规划公示、定制化营销物料。数据更新节奏随项目节点变动，中标、开工、竣工阶段会同步更新核心参数，营销物料每季度迭代更新。文档结构通常包含项目概况、技术参数、造价明细、合作方信息、工期要求等字段，单位涉及立方米、平方米、万元、天等工程专用计量标准，单份完整标书或大型案例文档体积通常超出通用文档范围。

## 这些特征在「知识库检索与召回」这一环带来什么约束
基建工程营销数据的结构化字段多、单文档体积大且更新频率随项目节点波动，这些特征对检索召回环节带来多重约束。首先，带专用计量字段的内容需支持定向字段检索，避免泛化匹配导致结果偏离需求；其次，大型单文档需适配合理的分段规则，防止语义断裂影响召回精度；最后，高频更新的项目数据需支持增量同步，确保检索结果不会包含过期的项目信息。多类型文档混存时还需按文档类型划分检索范围，防止无关内容干扰召回结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | 1500 MB | 适配大型项目标书、完整工程案例等单文件体积需求，避免拆分文档导致语义断裂 |
| `PARSE_FILE_SEGMENT_LENGTH` | 800–1200 字符 | 匹配基建工程文档中段落的平均长度，保留技术参数、项目逻辑的完整语义 |
| `召回条数` | 前6–8条 | 平衡检索覆盖率与结果冗余，适配多参数匹配的工程类内容召回场景 |
| `相似度阈值` | 0.72–0.80 | 过滤低相关性的通用营销内容，精准匹配工程参数、项目需求等核心字段 |
| `field_retrieval_enable` | 开启 | 支持按「项目类型」「造价区间」「工期」等字段定向检索，适配结构化数据的精准召回 |
| `SYNC_INTERVAL` | 每4小时 | 适配基建项目高频更新的节奏，确保检索内容与最新项目状态同步 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传大型工程标书时触发文件大小超限报错，无法完成导入。原因：未调整`UPLOAD_FILE_MAX_SIZE`参数至适配基建文档的取值，默认100MB无法覆盖大型项目文件。
- 现象：导入多份工程案例后，检索结果仅返回1条匹配内容。原因：未开启字段定向检索，或`召回条数`参数设置过低，未覆盖多文档匹配的场景。
- 现象：配置模型后测试提示报错，但正式运行可正常引用知识库内容。原因：测试接口与正式运行接口的上下文参数配置存在差异，未统一对齐`maxContext`取值。

## 怎么确认配好了
- 上传单份体积超过100MB的工程标书，确认可正常完成导入与解析。
- 检索包含多个结构化字段的查询词，确认返回的匹配结果条数符合预期配置。
- 手动触发知识库同步，确认更新后的项目数据可在检索结果中正常出现。
- 对比模型测试接口与正式运行的返回内容，确认二者的上下文参数配置一致。
