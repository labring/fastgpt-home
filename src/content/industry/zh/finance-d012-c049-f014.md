# 基建工程营销内容的表单与交互

## 这个品类的数据长什么样
基建工程相关数据主要来自官方招标平台、企业内部施工台账、设备供应商报价单。更新节奏随项目阶段变化，招标类数据按招标节点或月度更新，施工类数据随项目进度实时同步。文档多为结构化表格搭配段落说明，字段包含项目编号、预算金额（单位：万元）、工期（单位：天）、资质等级要求、工程量（单位：立方米/平方米）等，部分文档包含多标段拆分的分项数据，单份文档内容篇幅较长。

## 这些特征在「表单与交互」这一环带来什么约束
多标段拆分的分项数据要求表单支持多组字段复用，避免单组固定字段无法适配不同标段的需求。带单位的专业字段要求表单预设单位选项，减少用户手动输入的格式错误。数据来源分散且更新节奏不同，要求交互环节支持批量导入结构化数据，同时配置定时拉取数据源的接口以同步最新信息。项目编号作为唯一标识，要求表单自动生成或校验字段唯一性，避免重复提交。长文档类内容的解析与校验，要求表单环节预留足够的处理时间，避免因超时导致提交失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | 基建工程营销内容涉及的招标公告、施工方案等文档体积较大，需支持大文件上传 |
| `similarityThreshold` | `0.75–0.85` | 基建工程专业术语较多，该阈值可平衡召回精准度与覆盖范围，避免无关内容混入 |
| `reRankTopN` | `前3–5条` | 基建工程采购需求多涉及多维度参数，少量精准召回即可满足营销交互的信息需求 |
| `formSubmitTimeout` | `600 秒` | 基建工程表单常包含多组分项字段，提交校验耗时较长，需延长超时时间 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 长文档类基建工程文件解析步骤较多，需足够时间完成文本拆分与结构化处理 |
| `questionClassifyThreshold` | `0.65–0.70` | 基建工程专业术语占比高，降低分类阈值可减少有效问题被误判为无效的情况 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置`similarityThreshold`为0.9以上时，表单交互时召回结果为空，界面显示“未找到匹配内容”。原因：基建工程专业术语较多，过高的相似度阈值过滤了大部分相关的营销内容。
- 现象：通过iframe嵌入FastGPT表单后，前端可正常展示AI交互流程，但后端服务无法获取用户提交的表单数据与AI回答结果。原因：未开启`formSubmitWebhook`配置项，或配置的回调地址未正确接收POST请求。
- 现象：工作流AI节点返回“采购信息不完整”，但用户已提交全部预设的采购字段。原因：系统提示词未明确限定仅校验指定的六项采购内容，且未对字段的单位、格式要求做说明，导致AI误判遗漏信息。

## 怎么确认配好了
- 上传一份基建工程招标文档，检查文件是否可正常上传，解析完成后查看结构化字段是否正确提取。
- 提交一份包含完整采购字段的测试表单，检查后端回调接口是否收到对应的数据与AI回答内容。
- 调整`similarityThreshold`参数，提交包含专业术语的测试问题，确认召回结果的数量与精准度符合预期。
- 触发工作流节点，提交符合要求的采购信息，检查AI节点是否正确判断信息完整性，无误判情况。
