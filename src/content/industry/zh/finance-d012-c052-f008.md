# 多元控股营销内容的工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自旗下各子品牌的内容管理系统、客户营销素材库及线下活动物料归档。更新节奏随子品牌业务类型差异存在波动，部分标准化产品文案按月更新，投教类内容根据业务需求调整。单条数据文档包含素材唯一标识、所属子品牌编码、内容类型标签、发布状态、关联业务产品编号、适配渠道字段。内容长度以字符为单位，素材文件大小以MB为单位，关联产品字段采用标准化业务编号格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
多子品牌分散存储的素材来源，要求工具调用时需携带子品牌编码作为过滤参数，避免跨品牌素材混用以致生成内容偏离品牌定位。波动的更新节奏要求插件支持按时间戳增量拉取素材，减少无效请求占用系统资源。标准化的关联产品编号字段，需在工具调用参数中绑定对应业务场景，确保生成的营销内容匹配关联产品。不同内容类型的文档结构差异，要求插件内置多套解析规则，适配文案、海报说明、短视频脚本的不同处理逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `mcpServerProxyEndpoint` | `https://{sub_brand}.your-platform.com/mcp` | 匹配多元控股多子品牌的独立MCP服务部署，实现各品牌素材的权限隔离 |
| `toolCallFilterTags` | `["sub_brand_code", "product_id"]` | 基于文档的子品牌编码和关联产品编号字段，过滤合规的营销素材 |
| `pluginUpdateCheckInterval` | `1800–3600 秒` | 适配波动的素材更新节奏，按需调整增量检查的频率 |
| `maxToolCallContextLength` | `800–1200 字符` | 适配营销内容的常规生成长度，避免过长上下文引发工具调用异常 |
| `toolCallTimeout` | `60 秒` | 应对跨源拉取多子品牌素材的网络延迟，降低超时失败概率 |
| `pluginAuthStrategy` | `api_key_per_sub_brand` | 为每个控股子品牌分配独立API密钥，实现精细化权限管控 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用绑定子品牌的MCP插件后返回空结果，未携带`sub_brand_code`参数，导致系统无法过滤对应品牌的合规素材。
- 工具调用返回401未授权错误，使用了全局通用API密钥，未使用子品牌专属密钥，未通过多品牌权限校验。
- 工具调用耗时超出预期，将`pluginUpdateCheckInterval`设置为过低的取值，导致频繁触发跨源素材拉取，占用过多网络资源。

## 怎么确认配好了
- 调用测试接口携带指定`sub_brand_code`参数，检查返回结果仅包含对应子品牌的营销素材。
- 查看插件运行日志，确认MCP代理请求携带了对应子品牌的专属API密钥，未出现未授权报错。
- 手动调整`pluginUpdateCheckInterval`取值，观察插件的增量拉取频率符合预设需求。
- 触发完整的工具调用流程，检查生成的营销内容关联了正确的`product_id`字段，匹配目标业务场景。
