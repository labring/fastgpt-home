# 多元控股营销内容的文档解析与分块

## 这个品类的数据长什么样
多元控股的营销内容文档来源覆盖旗下各子品牌的独立营销物料，包括各板块的活动方案、广告文案、合规提示文档、投放渠道规划表等。更新节奏随营销节点波动，常规月度活动物料更新频率稳定，季度整合营销活动期间会出现批量集中上传。文档格式包含docx、pdf、在线文档导出格式，部分跨子品牌的整合物料会混合多格式内容。文档字段包含品牌标识、活动主题、适用客群、投放渠道、合规条款编号等，部分子品牌会自定义专属字段，无统一固定单位体系，仅按物料属性标注对应参数。

## 这些特征在「文档解析与分块」这一环带来什么约束
各子品牌的物料来源分散且格式多样，要求解析工具支持多格式兼容与跨品牌元数据识别，避免丢失专属字段信息。更新节奏的波动要求解析环节适配批量并发与单篇长文档的超时配置，防止批量上传时出现资源过载或单篇长物料解析中断。多字段且存在自定义字段的文档结构，要求分块时保留字段间的上下文关联，避免将关联内容拆分至不同分段。部分物料包含内嵌图片与合规提示，要求解析环节同步提取文本与图片内的关键信息，不遗漏合规内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600-900 秒` | 适配单篇包含多子品牌内容的长营销文档，避免因文档篇幅过长导致解析中断 |
| `chunkSize` | `800-1200 字符` | 平衡营销内容的上下文完整性与分块粒度，防止过长分段丢失逻辑关联，过短分段破坏字段关联 |
| `chunkOverlap` | `100-150 字符` | 保留跨分段的活动主题、投放渠道等关联信息，避免分块后上下文断裂 |
| `ENABLE_IMAGE_PARSE` | 开启 | 适配营销物料中常见的品牌logo、活动海报等内嵌图片，提取图片内的关键文本内容 |
| `MAX_PARSE_CONCURRENCY` | 按服务器CPU核心数的1.2倍 | 适配批量上传多子品牌物料的场景，避免并发过高导致服务器资源过载 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 支持单篇跨子品牌整合的大型营销手册，避免因文件过大被拦截 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：Docker部署4.8.21版本上传包含内嵌图片的docx营销文档时，日志返回`Invalid image file`错误。原因：未开启`ENABLE_IMAGE_PARSE`配置，且未正确挂载容器内的图片临时存储目录，导致图片解析失败。
- 现象：批量上传多子品牌营销文档时，后台日志持续输出`slow operation xxxms`提示。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置过短，且并发解析参数未适配批量场景，引发资源竞争导致解析超时。
- 现象：解析后的分块结果中，品牌合规条款与活动主题被拆分至不同分段。原因：`chunkSize`设置过小，将关联的字段内容强行拆分，破坏了上下文逻辑关联。

## 怎么确认配好了
- 上传单篇包含内嵌图片的品牌营销物料，检查解析结果中是否提取到图片内的文本内容，验证`ENABLE_IMAGE_PARSE`配置生效。
- 批量上传5篇以上不同子品牌的营销文档，查看后台日志是否出现超时或资源过载提示，验证`PARSE_FILE_TIMEOUT_SECONDS`与并发配置合理。
- 随机抽取一段分块结果，检查是否保留了活动主题与投放渠道的关联信息，验证`chunkOverlap`配置生效。
- 查看服务器GPU资源监控面板，确认多张显卡被同时调用，验证多卡并行解析配置生效。
