# 多元金融营销内容的表单与交互

## 这个品类的数据长什么样
多元金融的业务数据主要来源于用户端提交的风险测评问卷、持仓查询接口返回的资产信息，以及营销活动后台的触达日志。数据更新节奏分三类：用户主动提交的风险测评实时生效，持仓数据按自然日T+1同步，营销触达日志随活动执行批量更新。单条用户数据文档包含用户ID、风险等级、可投资资产规模、过往产品咨询记录、近30天触达次数等字段，其中资产规模单位为万元，触达次数为正整数，风险等级为低、中、高三类枚举值。

## 这些特征在「表单与交互」这一环带来什么约束
实时更新的风险测评数据要求表单即时校验输入合规性，联动下游产品推荐逻辑。T+1更新的持仓数据要求表单展示资产信息时标注数据更新时间，避免信息偏差。批量的营销触达日志要求表单支持按触达次数、触达渠道批量筛选用户群体。多字段组合的表单需保证字段联动逻辑正确，比如高风险等级用户的表单需展示高风险产品选项，同时屏蔽低风险产品的勾选。长文本的咨询记录字段需支持折叠展示，避免表单页面过长影响操作。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `json_path_extract` | `$.user_data.*` 或业务专属路径 | 多元金融的用户数据通常嵌套在`user_data`字段下，按业务路径提取可精准获取风险等级、资产规模等目标字段 |
| `custom_form_component_enable` | `开启` | 多元金融营销表单需支持风险等级滑块、可投资资产输入框等定制化控件，内置控件无法覆盖全部业务场景 |
| `form_field_validation_rule` | `风险等级为低/中/高枚举值、资产规模≥0` | 多元金融业务对字段合法性要求严格，提前拦截不合规输入可减少下游流程错误 |
| `workflow_http_timeout` | `30 秒` | 多元金融的持仓数据接口响应延迟较高，30秒可覆盖多数正常请求时长 |
| `knowledge_base_retrieve_length` | `800–1200 字符` | 多元金融营销内容需包含产品条款、风险提示等长文本，过长会超出上下文窗口，过短则信息不足 |
| `form_submit_batch_limit` | `100 条/次` | 多元金融营销触达的批量用户群体通常规模有限，单次提交上限设为100条可平衡接口负载与操作效率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：http请求节点返回状态码400，或下游节点获取的变量为空。原因：未正确配置`json_path_extract`的提取路径，未匹配多元金融数据特有的嵌套字段结构，导致无法提取目标内容。
- 现象：知识库检索结果条数不足，或返回内容被截断。原因：未调整`knowledge_base_retrieve_length`的取值，过长的营销内容文本超出系统默认限制，导致检索时被过滤。
- 现象：表单提交后出现字段校验失败，或自定义控件无法正常渲染。原因：未开启`custom_form_component_enable`开关，或校验规则未覆盖多元金融特有的字段格式，如资产规模的单位校验。

## 怎么确认配好了
- 提交测试表单，查看界面返回的校验提示，确认所有多元金融特有的字段规则已生效。
- 发起模拟http请求，查看响应解析后的变量值，确认`json_path_extract`的提取路径正确匹配目标字段。
- 进入知识库管理页面，调整`knowledge_base_retrieve_length`的取值，验证检索结果的长度符合业务需求。
- 开启自定义控件开关后，在表单编辑器中添加定制化控件，确认控件可正常渲染并提交数据。
