# 小家电营销内容的HTTP 接口与外部系统

## 这个品类的数据长什么样
小家电的营销内容数据主要来源于品牌官方参数库、电商平台商品详情页、官方营销素材中心。数据更新分为两类：新品上线时的批量同步，以及促销活动、合规政策变更时的临时更新。单条营销内容文档以SKU为核心单元，包含商品名称、核心参数、营销话术、活动时效、合规认证编号等字段，字段附带明确单位，例如功率单位为瓦，电压单位为伏特。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
小家电营销内容以SKU为核心更新单元，且包含多维度的参数、时效与合规字段，因此HTTP接口需要支持按`sku_id`、`promotion_period`等多条件筛选查询。由于更新存在批量与实时两种模式，接口需兼容定时同步与实时推送的调用逻辑。合规字段不可脱敏，接口返回需保留原始字段内容，同时需设置分页参数避免单次返回数据量过大。营销内容的时效性要求接口返回数据的延迟需匹配业务需求，否则会导致前端展示的活动信息与实际不符。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunk_size` | `800–1200 字符` | 小家电营销内容多包含短参数与文案，该长度可拆分后保留单条内容的完整性，避免参数拆分断裂 |
| `stream_response_interval` | `1000–2000 毫秒` | 平衡前端展示流畅度与接口负载，适配小家电营销内容的单条回复长度，满足控制返回速度的需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 小家电营销素材可能包含多规格参数文档，解析耗时较长，该时长可覆盖常规解析流程 |
| `max_retries` | `3 次` | 外部系统调用可能因网络波动失败，该重试次数可在不增加负载的前提下提升调用成功率 |
| `train_order_trigger_mode` | `按SKU更新触发` | 小家电营销内容以SKU为核心更新单元，按SKU触发训练订单可避免重复训练，匹配业务更新逻辑 |
| `response_log_detail_switch` | `开启` | 可完整记录对话API的返回详情，排查日志与实际回答不符的问题 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用v4.8.10及以上版本的对话API后，对话日志详情中的内容与实际返回的回答内容不一致，且多次调用后日志内容重复。原因：未开启`response_log_detail_switch`配置，或配置了固定的上下文缓存导致日志未实时更新。
- 现象：流式输出返回间隔固定为4秒，无法调整为1-2秒。原因：未修改`stream_response_interval`配置项，或配置值未生效。
- 现象：执行`create_train_order`接口后，未自动生成知识库索引。原因：混淆了`create_train_order`与集合添加数据的功能边界，未在训练订单中指定关联的知识库集合。

## 怎么确认配好了
- 调用对话API并返回流式结果，观察前端接收数据的间隔，确认符合预期的返回速度。
- 查看对话日志详情，确认日志内容与实际返回的回答内容一致，无重复或缺失。
- 模拟外部接口调用，观察是否返回`do_request_failed`以外的正常状态码，确认接口连通性。
- 触发SKU更新的训练订单，查看知识库是否自动生成对应小家电的营销内容索引，确认配置生效。
