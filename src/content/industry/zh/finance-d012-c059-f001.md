# 工业金属营销内容的HTTP 接口与外部系统

## 这个品类的数据长什么样
工业金属营销相关数据主要来自国内大宗商品交易平台、全球期货交易所及供应链管理系统。数据更新节奏分两类：期货行情按交易日定时推送，现货价格及库存数据每小时更新，月度发布全品类供需报告。文档结构标准化，包含品种编码、标准牌号、产地标识、基准价格、当日成交量、仓库库存总量等字段，单位统一为元/吨、吨、手（期货合约单位），部分细分品类如铝棒、铜丝会额外标注直径、长度等加工参数。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
工业金属数据的多来源属性要求外部系统需支持多接口聚合调用，需配置跨源请求处理规则避免跨域拦截。按小时级更新的现货数据要求HTTP接口设置不超过15分钟的缓存策略，避免频繁请求超出交易所接口限流阈值。标准化字段需在接口返回时强制映射为统一键名，避免不同数据源字段名差异导致的解析错误。期货合约的手数单位与现货吨数单位需在接口转换时明确标注，防止营销内容中出现单位混淆。另外月度供需报告的大体积文件需配置分块下载接口，适配批量营销素材生成需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `API_REQUEST_TIMEOUT` | `600 秒` | 工业金属月度供需报告数据量较大，常规超时时间不足以完成全量拉取 |
| `CROSS_ORIGIN_ALLOW_ORIGINS` | `["https://marketing-platform.example.com", "https://commodity-api.example.com"]` | 对接多数据源平台需开放对应域名权限，避免跨域拦截 |
| `CACHE_TTL` | `900 秒` | 匹配现货数据每小时的更新节奏，缓存时长不超过更新间隔避免使用过期数据 |
| `FIELD_MAPPING_RULE` | 按`{"price":"基准价格","volume":"当日成交量"}`映射 | 统一不同数据源的字段名差异，简化营销内容生成逻辑 |
| `UNIT_CONVERSION_CONFIG` | `{"futures":"手","spot":"吨"}` | 区分期货与现货的单位标准，防止营销素材中出现单位混淆 |
| `BATCH_DOWNLOAD_ENABLED` | `true` | 适配月度供需报告的大体积文件分块下载需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为调用接口返回403状态码，界面提示跨域请求被拦截。原因是未配置`CROSS_ORIGIN_ALLOW_ORIGINS`参数，未开放营销平台的域名权限。
- 现象为调用后返回过期的现货价格数据，字段显示为24小时前的数值。原因是`CACHE_TTL`配置超过1小时，未匹配现货数据的更新节奏。
- 现象为本地部署v4.8.21-fix版本时，对接第三方模型接口调用失败，日志显示API路径错误。原因是未在接口地址后追加`/v1`路径，且未在页面配置中正确填写模型API地址。

## 怎么确认配好了
- 发起一次现货数据接口请求，核对返回字段与`FIELD_MAPPING_RULE`配置的键名是否一致。
- 查看接口日志，确认请求来源域名在`CROSS_ORIGIN_ALLOW_ORIGINS`列表中，无拦截记录。
- 检查模型对接配置，确认接口地址后追加了`/v1`路径，匹配当前部署的FastGPT版本。
- 拉取一次月度供需报告，确认分块下载功能正常触发，文件分段返回无丢失。
