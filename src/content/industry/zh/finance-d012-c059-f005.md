# 工业金属营销内容的多轮对话与提示词

## 这个品类的数据长什么样
工业金属的数据源主要包括全球大宗商品交易所的实时报价、国内行业协会的月度库存报告、供应链企业的现货交易台账。更新节奏分为实时（现货报价）、交易日更新（期货行情）、周/月度（行业分析报告）三类。文档结构通常包含品名、规格牌号、产地、当日成交价、涨跌幅度、库存总量、交货周期等字段，单位多为元/吨、美元/吨、万吨、百分比（纯度）、毫米（规格尺寸），单条文档长度差异较大，建议按自有样本统计或实测后再确定。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
工业金属数据的实时性要求多轮对话必须优先召回最新的交易所报价与库存数据，避免使用过期的知识库内容。多字段与专业单位的组合要求提示词必须明确指定字段的取值范围与单位，防止模型混淆不同品类的参数。多数据源的差异要求多轮对话中需引导用户明确交易所类型与数据类型（现货/期货），同时需配置过滤规则排除无关品类的干扰。此外，长文档的结构要求对话上下文需保留足够的历史信息，确保模型能关联前一轮的品类与规格参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 工业金属营销对话会涉及多轮的品类规格、报价、库存等细节，该区间可覆盖常规多轮交互的信息留存需求，避免关键上下文被截断 |
| `召回条数` | `前 6–8 条` | 单条工业金属知识库文档可能包含多规格报价与参数，召回过多会导致上下文冗余，过少会遗漏关键品类的有效数据 |
| `相似度阈值` | `0.75–0.85` | 工业金属的纯度、规格参数辨识度较高，阈值过低会召回无关品类数据，过高会遗漏相近规格的有效信息 |
| `分段长度` | `1000–1500 字符` | 工业金属的文档包含长段落的规格说明与历史报价，该分段长度可平衡信息完整性与模型提取精度 |
| `指定知识库集合` | `绑定对应工业金属品类的专属集合` | 避免召回黑色金属、贵金属等其他大类的无关数据，精准定位目标品类的营销素材与实时数据 |
| `DATABASE_QUERY_TIMEOUT` | `300 秒` | 工业金属实时数据查询可能涉及多交易所接口调用，该超时时间可覆盖常规接口响应时长，避免查询中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置数据库连接插件后返回「连接超时」报错，原因：未将工业金属数据接口的端口号加入允许访问白名单，或超时时间设置短于交易所接口的响应时长，该问题在V4.9.3版本的数据库插件配置中较为常见。
- 现象：多轮对话中无法召回指定工业金属品类的知识库内容，原因：未在配置中绑定对应品类的专属知识库集合，模型默认召回全量知识库数据导致混淆。
- 现象：将对话模式切换为变量引用后，温度设置按钮消失无法调整参数，原因：变量引用模式下默认继承全局配置的温度参数，未在对话节点中单独配置温度参数。

## 怎么确认配好了
- 发起包含具体工业金属品类与规格的测试对话，核对召回的知识库内容是否来自绑定的专属集合，未混入其他品类数据。
- 发起连续多轮交互，依次询问品类参数、报价、库存信息，核对模型是否能完整保留前一轮交互的关键信息，未出现上下文截断或混淆。
- 触发数据库查询动作，核对返回的数据字段是否包含工业金属的标准单位，未出现单位缺失或混用。
- 调整对话的温度参数后发起测试，核对生成的营销内容是否符合预期的严谨度或灵活度，确认参数配置生效。
