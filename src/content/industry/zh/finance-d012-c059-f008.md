# 工业金属营销内容的工具调用与插件

## 这个品类的数据长什么样
工业金属的数据来源包括公开现货交易平台、行业库存监测数据库及期货交易所行情接口。更新节奏为：现货价格每小时更新，库存数据每工作日更新，期货行情每5分钟更新。文档结构为结构化条目，每个条目包含品种标识（如电解铜、铝锭）、物理规格（如Al99.70）、交易场所、最新交易价格、当日成交量、库存余量，单位为元/吨、吨、手。数据字段需明确对应具体品类与规格，否则无法返回准确信息。

## 这些特征在「工具调用与插件」这一环带来什么约束
高频更新的行情数据要求工具调用需匹配数据刷新节奏，避免使用过期信息。多字段与规格细分的结构要求工具调用必须传入品类、规格、交易场所等参数，否则返回数据会出现混淆。公开API的调用限额要求配置调用频率限制，防止触发限流机制。不同来源的数据格式存在差异，需在插件中配置字段映射规则，确保营销内容能正确调用对应字段生成文案。休市时段数据缺失的情况，需配置空数据的 fallback 处理逻辑，避免生成无效的营销内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolCallTimeout` | 300 秒 | 工业金属行情API的响应时长通常在100-250秒，预留足够缓冲时间 |
| `maxToolRetries` | 2 次 | 应对API临时限流或网络波动，避免重复调用触发更高限额限制 |
| `toolCallFrequency` | 10 次/分钟 | 匹配多数公开工业金属API的调用限额要求 |
| `requiredToolParams` | ["metalType", "specification", "tradingMarket"] | 确保工具调用时传入完整的品类、规格与交易场所参数，避免返回无效数据 |
| `cacheTTL` | 3600 秒 | 匹配现货价格每小时更新的节奏，避免使用过期的行情数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调试时返回“参数缺失”报错，AI未触发工具调用直接生成回答。原因：未在系统提示中明确要求传入工业金属的品类、规格等必填参数，导致AI无法生成符合要求的工具调用请求。
- 现象：调用SQL Server数据库插件时无法读取工业金属库存数据。原因：未在插件配置中指定数据库连接字符串、目标表名`metal_inventory`及字段映射规则，无法匹配工业金属的结构化数据字段。
- 现象：生成的营销文案使用了过期的工业金属价格数据。原因：缓存时长配置过长，未匹配数据更新节奏，导致调用缓存，未调用最新API接口。

## 怎么确认配好了
- 进入FastGPT的工具调试界面，手动传入电解铜、Al99.70、上海金属网参数，检查是否能返回准确的实时行情数据。
- 查看工具调用日志，确认每次调用的参数完整无缺失，且调用频率未超过配置的限制。
- 发起营销内容生成请求，检查生成的文案中是否包含工具返回的最新价格、库存等数据。
- 等待超过3600秒后再次发起相同请求，确认会重新调用API获取最新数据，未使用缓存。
