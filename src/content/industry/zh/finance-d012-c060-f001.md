# 工程咨询营销内容的HTTP 接口与外部系统

## 这个品类的数据长什么样
工程咨询的营销内容数据主要来源于项目可研报告、招投标方案、客户需求函、行业标准文档等。数据更新节奏随项目阶段变化，招投标筹备阶段更新频率较高，项目落地后仅做少量补充调整。文档整体为长文本结构，包含建筑模数、荷载参数、造价指标等专业术语，字段包含项目编号、项目地点、服务周期（单位：月）、预估造价（单位：万元）等，解析后会按前期咨询、设计咨询、施工监理等模块拆分内容。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
工程咨询的长文本专业文档会导致HTTP接口请求体超出默认限制，需要调整接口的上传大小阈值。专业术语密集的内容要求接口在调用解析时启用特定的专业领域解析参数，避免术语拆分错误。字段包含带单位的数值类信息，外部系统对接时需严格匹配字段单位，避免数据映射偏差。项目阶段驱动的更新节奏要求接口采用增量同步逻辑，减少无效请求。同时，部分营销文档为扫描件格式，接口需支持OCR解析配置，适配不同类型的输入文件。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 秒 | 工程咨询文档多为长文本，专业解析耗时较长，默认超时时间不足 |
| `UPLOAD_FILE_MAX_SIZE` | 2000–3000 MB | 单份工程咨询文档可能超过通用大小限制，需适配可研报告、招投标文件的体积 |
| `PDF_PARSE_OCR_SWITCH` | 开启 | 部分营销文档为扫描件格式，需通过OCR提取文本内容 |
| `SYNC_INCREMENTAL_ENABLE` | 开启 | 适配工程咨询随项目阶段变化的更新节奏，减少无效全量同步请求 |
| `FIELD_MAPPING_RULE` | 映射`项目编号`、`预估造价`、`服务周期`字段 | 工程咨询营销内容包含专属业务字段，需严格匹配外部系统的字段规则 |
| `API_REQUEST_TIMEOUT` | 120 秒 | 拉取工程咨询网页营销内容时，长段落和表格内容拉取耗时较长，需延长超时阈值 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用HTTP接口拉取工程咨询网页营销内容时返回`504 Gateway Timeout`状态码，原因是未调整`API_REQUEST_TIMEOUT`配置，默认超时时间不足以完成长内容拉取。
- 创建文件集合时未指定PDF解析参数，导致扫描件格式的营销文档解析失败，返回`Api response error: undefined`，原因是未开启`PDF_PARSE_OCR_SWITCH`配置，无法提取扫描件内的文本。
- 配置`UPLOAD_FILE_MAX_SIZE`为默认值，上传大型可研报告时返回`413 Request Entity Too Large`，原因是未适配工程咨询文档的大体积特征，未调整上传大小阈值。

## 怎么确认配好了
- 上传一份扫描件格式的工程咨询PDF文档，检查解析结果是否包含完整的专业文本内容。
- 发起一次HTTP接口请求拉取工程咨询网页内容，确认请求在设定的超时时间内完成，未触发超时报错。
- 上传一份体积超过1000 MB的可研报告，确认接口返回上传成功状态，未触发大小超限报错。
- 配置增量同步任务，提交一份更新后的项目文档，检查仅该文档被同步至知识库，未触发全量同步。
