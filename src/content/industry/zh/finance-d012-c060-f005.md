# 工程咨询营销内容的多轮对话与提示词

## 这个品类的数据长什么样
工程咨询的数据主要来自项目可研报告、招投标文件、造价核算清单、现场踏勘记录及行业规范标准文档。数据更新随单个项目推进节奏调整，项目启动后按需补充现场数据、政策调整后同步更新规范内容。文档多采用结构化分章节结构，包含项目编号、标段范围、造价金额、工期要求、规范条款编号等字段，单位涵盖平方米、万元、工作日、立方米等工程类标准单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
工程咨询的数据特征对多轮对话与提示词环节带来多重约束。首先，多项目并行的场景下，数据包含项目编号、标段等专属标识，多轮对话需持续跟踪当前会话绑定的项目标识，避免混淆不同项目的造价、工期等数据。其次，文档包含长段落的行业规范与明细清单，提示词需适配长文本上下文，避免因窗口限制截断关键信息。另外，数据随项目推进动态更新，提示词配置需支持动态调用最新上传的项目文件，适配动态更新的业务需求。最后，字段附带工程专业单位，多轮对话中需准确保留单位信息，避免出现数值与单位不匹配的表述。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | 500–1000 MB | 工程咨询上传的文件多为大型造价清单、踏勘记录或规范合集，需适配大文件上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 大型工程文档解析需较长时间，避免因超时中断解析流程 |
| `RECALL_TOP_N` | 前8–12条 | 工程咨询文档多为结构化明细，召回过多条目会增加上下文负担，过少则遗漏关键细节 |
| `SIMILARITY_THRESHOLD` | 0.75–0.85 | 需平衡精准匹配专业术语与覆盖相关项目数据，避免误召回无关标段内容 |
| `maxContext` | 8000–12000 字符 | 工程咨询对话需保留项目编号、标段、造价明细等多轮上下文，避免上下文溢出丢失关键信息 |
| `WORKFLOW_FILE_UPLOAD_ENABLE` | 开启 | 工程咨询营销内容生成需基于项目本地文件，支持工作流内文件上传可实现自动化内容创作 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中配置文件上传节点后，调用文档解析工具时返回超时或格式错误。原因：未将`UPLOAD_FILE_MAX_SIZE`调整至适配工程文档的取值，或未正确配置文件解析的触发路径。
- 现象：通过API发起对话后，生成的回复未关联知识库中的工程规范或项目文档。原因：未在请求参数中正确传入`kbIds`绑定对应工程咨询知识库，或`SIMILARITY_THRESHOLD`设置过高导致未召回相关内容。
- 现象：私有部署环境下运行对话组件时抛出未捕获异常。原因：配置文件中`UPLOAD_FILE_STORAGE`参数未正确指向对象存储服务，或MongoDB连接配置存在格式错误。

## 怎么确认配好了
- 上传符合业务场景的工程文档，检查解析进度是否完成且无报错，核对上传大小配置是否覆盖业务所需的最大文件尺寸。
- 发起包含多轮业务信息的对话，查看上下文是否保留所有关键会话内容，核对上下文窗口配置是否适配会话长度需求。
- 调用API发起关联知识库的对话，检查返回结果是否包含知识库内的专业内容，核对召回相关配置是否符合业务匹配要求。
- 查看部署日志，确认解析超时配置未触发异常，且存储与数据库连接状态正常。
