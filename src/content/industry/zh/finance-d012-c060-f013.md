# 工程咨询营销内容的知识库检索与召回

## 这个品类的数据长什么样
工程咨询的营销内容数据主要来自项目可研报告、投标响应方案、客户成功案例库、行业政策解读文档、标准化营销话术库。更新节奏随内容类型差异调整，中标项目案例随项目交付更新，行业政策文档随监管要求同步调整，营销话术按季度迭代。单篇文档通常包含项目编号、咨询范围、客户名称、交付成果、报价区间、适用场景等结构化字段，部分长文档还包含多章节的技术细节与营销亮点。咨询周期以“工作日”为单位，项目规模以“平方米”“亿元”为单位，报价以“万元/项”为单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
文档结构复杂且包含多结构化字段，固定长度分块容易破坏业务关联，需结合语义与字段关联进行分块；数据更新节奏差异大，静态政策文档与动态项目案例需区分冷热数据，调整召回权重；营销内容面向客户沟通，检索结果需贴合业务场景，避免引入过于技术化的内部文档；字段包含特定单位，检索时需匹配单位相关的语义，避免召回不匹配的咨询内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `分段长度` | 800–1200 字符 | 工程咨询文档多为长文本，包含多段落的项目方案与政策解读，该长度可保留语义完整性，避免拆分破坏业务逻辑。 |
| `chunkOverlap` | 100–150 字符 | 保留相邻分块的重叠内容，避免跨段落的营销话术被拆分断裂，确保召回时语义连贯。 |
| `召回条数` | 前6–8条 | 工程咨询营销内容需兼顾全面性与精准性，过多会导致回复冗余，过少无法覆盖客户可能的咨询场景。 |
| `相似度阈值` | 0.72–0.78 | 匹配工程咨询的专业术语密度，阈值过低会引入无关的通用咨询内容，过高则无法召回细分场景的营销素材。 |
| `重排返回条数` | 前3–5条 | 筛选最贴合用户营销咨询需求的内容，避免非核心的技术细节干扰营销沟通。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 工程咨询文档常包含多页的投标方案与可研报告，较长的超时时间可确保完整解析。 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用`apiCollection`接口上传知识库文件时返回`message: Invalid URL, code: 500`。原因：未正确配置知识库关联的文件存储路径，或传入的文件URL未通过平台的白名单校验。
- 检索结果仅匹配分块的主要内容，未关联辅助字段信息。原因：未开启辅助数据检索的配置项，或分块时未正确提取项目编号、客户名称等辅助字段。
- 生成的回复中保留了知识库源文档的引用链接。原因：未关闭回复中的引用链接输出开关，或配置时未禁用源文档跳转的相关参数。

## 怎么确认配好了
- 进入知识库管理界面，查看已上传的工程咨询文档的分块预览，确认分块保留了完整的业务段落与辅助字段。
- 发起一条模拟营销咨询的测试查询，核对返回的召回结果数量与相似度是否符合预设的配置预期。
- 调用`apiCollection`接口查询知识库列表，确认可正常获取目标知识库的ID参数。
- 生成测试回复，检查是否包含预期的营销内容，且未出现多余的引用链接或无效的报错信息。
