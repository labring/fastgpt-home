# 工程机械营销内容的工具调用与插件

## 这个品类的数据长什么样
工程机械的核心数据来源包括设备厂商出厂标定参数、现场运维采集的工况日志、租赁平台的设备调度记录。出厂参数为静态结构化数据，包含设备型号、额定起重量、最大作业半径、燃油消耗率等字段，单位多为吨、米、升/小时。现场工况数据为动态更新，更新频率从分钟级到小时级不等，单条记录包含作业时长、负载率、位置坐标等字段。文档格式以CSV、JSON和工业协议上报的二进制流为主，部分厂商提供标准化的PDF技术手册。

## 这些特征在「工具调用与插件」这一环带来什么约束
静态出厂参数的固定性要求工具调用时优先缓存已获取的设备数据，避免重复发起请求占用资源。动态工况数据的高频更新特性要求配置定时同步任务，确保调用时获取的是最新状态。单条设备数据字段多且单位差异大，需要在工具调用前完成单位标准化转换，避免大模型生成错误的营销内容。长格式的技术手册文档需要拆分后分批传入工具，防止超出上下文长度限制，同时需标记字段优先级，确保营销内容聚焦用户关心的作业性能参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `mcp_request_timeout` | `300–600 秒` | 工程机械数据包含长文档解析与实时工况查询，超时阈值需覆盖完整数据获取流程 |
| `maxContext` | `8000–12000 字符` | 单台设备的技术手册与工况数据字段较多，需保留足够上下文供大模型关联生成营销内容 |
| `mcp_cache_ttl` | `静态参数 3600 秒，动态工况 60 秒` | 静态出厂参数无需高频更新，动态工况数据需同步现场状态 |
| `tool_call_filter_fields` | `保留额定起重量、作业半径、燃油消耗率` | 工程机械营销内容需聚焦核心作业性能参数，过滤非核心的维修、配件字段 |
| `mcp_input_schema` | `强制绑定单位映射规则` | 不同厂商的参数单位存在差异，需提前将吨、米、升/小时映射为标准输入格式 |
| `max_tool_calls_per_round` | `3–5 次` | 多设备对比类营销内容需控制调用次数，避免流程超时或超出大模型调用限额 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调用返回结果为空或重复触发，日志显示`504 Gateway Timeout`状态码。原因：未针对工程机械的长文档解析调整超时配置，导致请求未完成即被终止。
- 现象：营销内容中嵌入的设备参数图表仅显示部分区域。原因：工具调用时未拆分长文档，导致上下文溢出，大模型未完整提取图表关联参数。
- 现象：添加MCP服务时无法绑定HTTP响应的入参变量，界面提示`invalid input schema`。原因：未按照工程机械参数的字段结构配置输入映射，直接使用通用入参模板。

## 怎么确认配好了
- 发起一次单设备参数查询，检查返回结果的字段与配置的过滤规则一致。
- 查看工具调用日志，确认未触发`request timed out`或`504 Gateway Timeout`类报错。
- 测试多设备对比场景，检查工具调用次数符合预设的上限要求。
- 验证MCP服务的入参映射，确认HTTP响应的单位字段被正确转换为标准格式。
