# 投资平台营销内容的工具调用与插件

## 这个品类的数据长什么样
投资平台的数据主要来自交易系统、实时行情接口、用户持仓数据库与营销活动后台。交易流水、持仓变动数据随用户操作实时更新，产品净值数据每日收盘后同步，用户行为标签数据每日批量更新。单条数据文档结构清晰，交易类数据包含交易时间、标的代码、交易数量、交易金额、手续费字段，单位分别为ISO格式时间戳、6位证券代码、股/份、元、元；用户画像字段包含用户ID、风险等级、投资周期，单位为字符串、等级标识、月/年。

## 这些特征在「工具调用与插件」这一环带来什么约束
投资平台的数据多源且更新节奏差异大，要求工具调用需适配不同数据的更新周期，实时行情类工具需配置短超时以保证营销内容的时效性。多字段组合调用场景下，需先获取用户持仓数据再关联对应标的行情数据，避免使用未更新的静态数据生成内容。不同标的的代码格式存在差异，插件需内置标准化转换逻辑，确保调用参数格式匹配第三方接口要求。同时，营销内容生成常需批量关联用户数据，需配置调用限流规则，避免超出第三方接口的调用限额。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_timeout` | `3–8 秒` | 实时行情接口响应通常在5秒内，过长超时会导致营销内容生成延迟，过短会截断有效数据返回 |
| `parallel_tool_max_count` | `2–3` | 投资平台工具调用常需同时获取持仓与对应标的行情，过多并行会触发第三方接口限流 |
| `plugin_request_rate_limit` | `100–500 次/分钟` | 匹配单平台常规用户量级的合理调用上限，避免触发平台风控拦截 |
| `tool_param_format_validate` | `开启` | 投资标的代码存在多格式（如带交易所后缀、纯数字代码），校验可提前拦截参数错误 |
| `stream_response_enable` | `开启` | 营销内容生成需逐步输出，流式返回可提升内容展示的连贯性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用工具时仅返回单条数据结果，未触发配置的多工具并行调用。原因：未正确设置`parallel_tool_max_count`参数，或调用时未按要求传入多工具参数列表。
- 现象：部分地区调用API返回连接超时或403错误。原因：未配置区域适配的代理节点，或第三方数据接口存在区域访问限制。
- 现象：流式输出的营销内容中嵌入的链接，点击后仅替换当前页面内容，无法打开新页面。原因：返回的链接未配置新窗口跳转属性，或前端渲染脚本未正确处理外部链接的跳转逻辑。

## 怎么确认配好了
- 调用测试工具，传入包含多个标的的用户持仓数据，检查是否同时触发持仓与行情接口的调用。
- 查看平台接口监控面板，确认调用频率未超出预设上限，且无区域拦截日志。
- 发起流式调用请求，检查返回的内容是否分段输出，且嵌入的链接带有新窗口跳转属性。
- 模拟异常参数（如非标准标的代码）调用，检查是否触发参数校验拦截并返回明确错误信息。
