# 旅游景区营销内容的工作流编排

## 这个品类的数据长什么样
数据来源为景区官方运维系统、票务平台接口、线下活动报备文档、游客服务台账。更新节奏为基础信息季度更新，票务、活动信息每日或即时更新，应急预案临时更新。文档结构分为基础信息、票务规则、游览动线、活动公告、服务须知五类，字段包含景区标识ID、票价（单位元）、开放时段、活动起止日期、承载量上限（单位人次）等，单篇文档长度从数百字的票务须知到数千字的活动策划方案不等。

## 这些特征在「工作流编排」这一环带来什么约束
结合金融/保险/理财行业对营销内容的合规要求，基础信息的季度更新要求工作流定期触发元数据同步，避免使用过期的景区等级或地址信息影响营销内容准确性。票务、活动信息的高频更新，要求工作流支持实时调用外部接口拉取最新数据，不能依赖静态缓存。多类文档的拆分结构，要求工作流配置按文档类型分流处理，例如活动公告单独触发合规校验，票务信息用于生成购票引导文案。带单位的字段特征，要求工作流中参数接收环节强制绑定单位校验，避免跨环节调用时的格式错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `知识库召回条数` | 前8-12条 | 景区营销内容需要覆盖基础信息、活动、票务多类数据，召回过多会导致上下文冗余，过少则信息不足 |
| `相似度阈值` | 0.65-0.75 | 景区相关知识库内容多为规则性文本，阈值过低会引入无关的运维日志，过高则无法匹配到相关活动公告 |
| `HTTP请求超时时间` | 30 秒 | 景区票务接口多为内部系统，响应延迟通常在10-25秒之间，超时设置过短会导致拉取失败，过长则阻塞工作流 |
| `工作流触发频率` | 每小时1次 | 票务、活动信息更新频率为每日或即时，高频触发会增加系统负载，低频则无法保证内容时效性 |
| `变量绑定校验开关` | 开启 | 景区数据包含`ticket_price`（单位元）、`visit_duration`（单位小时）等带单位字段，校验开关可避免参数格式错误 |
| `工具调用终止节点` | 强制添加 | 景区营销内容生成需要多工具调用（拉取数据、生成文案、合规校验），未添加终止节点会导致工作流重复执行或输出混乱 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流执行后连续触发多次工具调用，最终输出内容混乱，原因是未在工具调用流程末尾添加`工具调用终止`节点，工作流无法识别执行终点，进入循环执行。
- 现象为知识库为空时直接生成了无内容的营销文案，原因是未配置知识库为空的分支判断逻辑，直接调用了内容生成节点，没有触发兜底流程。
- 现象为自定义HTTP接口无法接收工作流传入的景区ID参数，原因是未在接口中配置与工作流变量名匹配的接收字段，导致参数传递失败。

## 怎么确认配好了
- 手动触发一次工作流，核对输出内容是否包含最新的景区活动信息与票务规则，确认数据时效性。
- 模拟知识库为空的场景，验证工作流是否触发预设的兜底流程，确认不会直接执行生成节点。
- 调用自定义HTTP接口，传入测试用的景区ID参数，确认接口可正常接收并返回对应数据。
- 查看工作流执行日志，确认工具调用节点执行完成后触发了终止流程，无重复执行记录。
