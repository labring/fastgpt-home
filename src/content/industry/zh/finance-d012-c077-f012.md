# 旅游景区营销内容的模型接入与配置

## 这个品类的数据长什么样
数据主要来自景区官方公告系统、票务管理后台、游客服务反馈库及周边配套业态接口，区别于金融品类的产品持仓、交易记录类数据。更新节奏随客流周期调整，节假日及活动筹备期高频更新，日常周期稳定。文档多为结构化与半结构化混合，包含景区名称、开放时段、门票定价、活动细则、导览路线、实时客流预警等字段，单位涉及人次、元、小时、公里等，字段结构与同方向其他品类存在明显差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
景区数据的多源异构特性要求配置多渠道接入适配规则，需同时对接票务、客流、活动等多个接口，区别于金融品类的单一数据源适配逻辑。高频更新的特性要求配置实时或准实时的数据同步参数，避免营销内容滞后，金融品类的产品数据更新频率通常固定，无需频繁调整同步周期。字段包含人次、元等特定单位，要求配置字段映射校验规则，确保模型调用时参数单位匹配，金融品类的字段单位多为收益率、金额等，映射规则逻辑不同。半结构化的活动公告、导览文档，要求配置支持混合格式的文本解析参数，保障内容提取准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `stream模式开关` | 开启 | 景区营销内容常需实时生成活动通知、客流播报，stream模式可实现内容分段输出，提升用户接收体验 |
| `maxContext` | 8000–12000 字符 | 景区数据包含多段活动细则、导览路线，较长的上下文可保障模型生成内容覆盖完整信息 |
| `requestTimeout` | 30–60 秒 | 景区实时客流数据接口可能存在网络延迟，较长超时可避免因临时网络波动导致调用失败 |
| `apiRetryCount` | 2–3 次 | 内网或第三方票务接口偶发波动，有限重试可提升调用成功率，避免频繁报错影响营销内容生成 |
| `fieldMappingRule` | 按景区预设字段映射 | 景区数据字段包含专属单位与标识，按预设规则映射可确保模型调用时参数准确匹配 |
| `dataSyncInterval` | 15 分钟（活动期）/ 1 小时（日常） | 适配景区更新节奏，活动期高频同步保障内容时效性，日常降低同步频率节省资源 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 开启`stream模式开关`后仍无法获取分段输出内容，原因是未在模型渠道配置中同步开启stream兼容参数，导致接口返回格式不匹配。
- 本地切换模型渠道时返回304状态码，原因是本地缓存了旧的模型配置信息，未触发新的接口请求校验。
- 调用模型时报错“获取数据异常”，原因是未配置内网环境下的代理或白名单放行规则，导致无法访问内网部署的大模型接口。

## 怎么确认配好了
- 手动触发一次模型调用，检查返回内容是否包含景区专属字段与单位，验证字段映射配置生效。
- 查看模型调用日志，确认stream模式下返回的内容为分段流式输出，无完整包延迟问题。
- 在内网环境下测试跨服务器的模型接口连通性，确认无防火墙或路由拦截导致的调用失败。
- 调整数据同步间隔参数，观察后台数据更新日志，确认同步频率符合预设的景区更新节奏。
