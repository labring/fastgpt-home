# 普钢营销内容的多轮对话与提示词

## 这个品类的数据长什么样
普钢相关数据主要来自钢厂ERP系统、大宗商品现货交易平台、官方出厂价公示渠道及下游制造业需求调研数据。出厂指导价每日更新，现货交易价格每小时刷新，库存与产能数据按周更新。单份数据文档通常包含钢材品类、规格参数、生产产地、供货钢厂、报价（元/吨）、可售库存（吨）、交货周期（天）等字段，字段格式多为结构化表格或标准化CSV文件。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
普钢品类细分多、规格参数复杂，多轮对话需持续跟踪用户提及的具体钢材品类与规格，避免跨品类混淆。数据更新频率差异大，提示词配置需适配实时或准实时数据源的同步规则，防止返回过时报价。结构化字段包含明确计价与计量单位，多轮交互中需统一单位表述，避免元/吨与其他计价单位混淆。下游用户常关联采购量、交货场景等信息，多轮流程需逐步收集补充参数，支撑精准营销内容生成。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 普钢单份数据文档较长，多轮对话需保留多轮品类、规格、报价相关上下文 |
| `systemPrompt` | 需结合用户提及的钢材品类、规格、采购量等信息，匹配对应数据源的最新报价与库存，输出结构化营销内容 | 普钢营销需精准匹配具体参数，避免泛泛而谈的通用回复 |
| `recallTopK` | `前6–8 条` | 普钢数据源包含多维度参数，适量召回可覆盖品类、规格、报价等核心信息 |
| `contextRefreshInterval` | `每12 小时` | 出厂指导价每日更新，准实时现货数据需定期同步，避免返回过时内容 |
| `workflowAiNodeMaxTurns` | `3–5 轮` | 普钢营销需逐步收集采购需求、交货地点等补充信息，过多轮次会降低交互效率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中配置多个`<ai对话>`节点，调用工作流对话时，所有节点的回复同时展示在聊天窗口。原因：未在工作流中配置上下文传递规则，各AI节点未关联共享对话上下文，导致独立输出结果。
- 现象：未登录状态下发起的普钢营销对话，刷新页面后历史记录丢失。原因：未开启会话持久化配置，或未配置匿名会话存储规则，无法留存未授权用户的对话数据。
- 现象：搭建普钢营销工作流时，仅单次提问后流程结束，无法根据用户回复发起反问以收集采购量、交货地点等补充信息。原因：未在工作流中配置循环触发或多轮追问节点，仅执行了单次AI调用流程。

## 怎么确认配好了
- 发起包含不同钢材品类、规格的多轮对话，检查上下文是否被正确保留，未出现上下文丢失或跨品类混淆的情况。
- 调用配置完成的普钢营销工作流发起提问，验证仅当前交互对应的AI节点回复被展示，无冗余历史节点输出。
- 调整数据源的模拟更新时间，检查对话返回的报价是否随配置的刷新间隔同步更新。
- 测试匿名用户与授权用户的对话隔离性，验证不同用户无法查看彼此的历史对话记录。
