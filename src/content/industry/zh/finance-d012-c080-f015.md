# 服装家纺营销内容的部署与升级

## 这个品类的数据长什么样
服装家纺品类的营销内容数据主要来自品牌内部商品管理系统、面料供应商检测文档、线下门店销售记录与线上用户评价。数据更新节奏随新品上架周期调整，新品上线时批量更新，日常仅更新库存与促销信息。文档多为结构化CSV表格、结构化商品详情页PDF或直播脚本文本，字段包含SKU编码、面料成分占比、洗涤要求、尺码参数、建议售价，单位涉及克/平方米、厘米、元等。

## 这些特征在「部署与升级」这一环带来什么约束
服装家纺品类的营销内容数据特征对部署与升级环节带来多重约束。结构化字段多且单位不统一，部署时需配置字段映射规则，确保不同来源的面料克重、尺码参数等标准化解析。新品批量更新的场景，升级时需保留批量导入接口的兼容性，避免中断日常数据同步。长文本类的直播脚本与搭配文案占比高，部署时需预留长上下文处理的资源空间，升级后需验证长文本解析与召回的稳定性。SKU数量较多，需配置合理的检索阈值，避免检索资源过载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 服装家纺的商品详情页PDF可能包含多页面料检测报告，批量SKU的CSV文件解析耗时较长，需适配长解析时长需求 |
| `maxContext` | `16384–32768 token` | 营销内容包含长文本的直播脚本与搭配文案，需适配长上下文处理需求，避免截断关键信息 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 部分面料检测报告的PDF或批量SKU的CSV文件体积较大，需适配大文件上传需求 |
| `RECALL_TOP_K` | `前8–12条` | 服装家纺营销内容需结合多维度SKU信息，适量召回可确保内容全面且不冗余 |
| `MCP_SERVICE_PARAM_TYPE` | `按字段自动匹配` | 服装家纺字段类型多样，固定为string会丢失面料克重、售价等数值类关键信息 |
| `PARSE_CHUNK_SIZE` | `800–1200 字符` | 长文本的营销内容分段后需保留语义完整性，避免拆分破坏面料成分、搭配建议等关键信息 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置MCP服务时，自定义参数的类型被强制锁定为string，无法保存数值类型的参数。原因：部署时未调整MCP服务的参数类型校验规则，默认强制锁定为string类型。
- 现象：上传批量SKU的CSV文件后，解析过程持续2分钟后显示请求失败，重启服务器未解决该问题。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时间短于批量文件解析所需时长。
- 现象：升级到4.9.6版本后，营销内容生成的回答长度明显缩短，无法完整输出搭配建议与面料说明。原因：升级后`maxContext`参数被重置为默认短上下文值，未适配服装家纺长文本营销内容的需求。

## 怎么确认配好了
- 上传一份包含多页面料检测报告的PDF文件，查看解析后的字段是否完整且单位统一，核对`PARSE_FILE_TIMEOUT_SECONDS`参数是否匹配解析耗时。
- 配置MCP服务时，尝试添加数值类型的参数，确认参数类型可自定义，未被强制锁定为string。
- 生成一条包含面料成分与搭配建议的营销内容，查看回答长度是否覆盖完整需求，核对`maxContext`参数是否符合当前内容长度要求。
- 导入批量SKU的CSV文件，查看批量导入任务是否顺利完成，确认`UPLOAD_FILE_MAX_SIZE`参数适配文件体积。
