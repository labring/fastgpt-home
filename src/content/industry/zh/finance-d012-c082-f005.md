# 水产养殖营销内容的多轮对话与提示词

## 这个品类的数据长什么样
在金融/保险/理财行业的营销获客场景中，水产养殖相关的数据来源包括养殖现场传感器（溶氧、水温、pH值）、投料设备日志、苗种批次档案，以及金融机构留存的养殖户投保、信贷、咨询记录。数据更新节奏依类型区分：养殖传感器数据每5-15分钟更新一次，养殖台账每日更新，客户金融记录实时同步。单份联合文档以养殖批次与客户ID为核心结构，包含投放密度、投料量、病害记录、投保保额、信贷额度等字段，字段需对应明确单位，如密度单位为尾/立方米，投料量单位为kg/亩，溶氧单位为mg/L。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
水产养殖的数据兼具实时性、批次特异性与金融关联属性，要求多轮对话需绑定独立的养殖批次与客户ID上下文，避免不同客户或批次的参数混淆。实时传感器数据的高频更新，要求提示词需支持动态插入最新养殖环境参数，且对话上下文需及时清理过期的非当前批次数据。多字段带专属单位的特征，要求提示词需明确标注单位规则，防止模型输出混淆的参数表述。联合了金融行为数据的文档结构，要求多轮对话需按客户与养殖批次分类召回知识库内容，不能跨客户或批次混用金融与生产数据，确保营销内容的个性化与合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 水产养殖与金融联合数据包含多批次档案、实时环境参数与客户金融记录，过长上下文会导致模型截断关键信息 |
| `recallTopK` | `前6–8 条` | 金融营销场景需同时召回养殖生产数据、客户金融记录与历史对话内容，过多召回会稀释核心营销信息 |
| `similarityThreshold` | `0.72–0.78` | 养殖与金融联合数据字段专业且单位统一，阈值过低会引入无关的其他养殖品类或客户数据 |
| `httpRequestTimeout` | `300 秒` | 部分批量养殖档案解析或跨系统金融数据拉取耗时较长 |
| `分段长度` | `1000–1500 字符` | 养殖与金融联合档案单条记录包含多组参数，分段过长会导致召回时上下文割裂 |
| `systemPromptTemplate` | `按客户ID、养殖批次、实时环境参数、历史金融记录的顺序整合上下文，输出营销内容时需标注对应参数单位` | 金融行业的水产养殖营销需精准匹配当前客户的养殖状态与金融需求，避免参数混淆与合规风险 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：使用HTTP请求编排节点后，对话输出结果中无对应output字段，运行版本为4.6.9。原因：未在HTTP节点配置中开启「将输出写入对话上下文」选项，导致返回的养殖或金融数据未纳入对话链。
- 现象：多轮对话完成AI回复后，自动进入问题分类节点，打断针对养殖户的营销对话流程。原因：工作流未配置对话结束后的跳转规则，默认返回初始分类节点，中断个性化营销内容的生成。
- 现象：一对多对话场景中，不同养殖户的养殖数据与金融记录上下文出现交叉混淆。原因：未为每个对话会话绑定独立的客户ID与养殖批次标识，导致上下文未隔离，引发营销内容的合规风险。

## 怎么确认配好了
- 导入单批次养殖档案与对应养殖户的金融记录文档，发起多轮对话，测试是否能准确召回对应客户的投保、信贷信息与养殖参数。
- 触发HTTP请求编排节点，查看对话历史，确认返回的养殖或金融数据已显示在对话链中，且版本4.6.9下的输出开关已开启。
- 启动一对多对话会话，分别输入不同养殖户的查询，确认各会话的上下文未交叉显示，避免合规风险。
- 调整`similarityThreshold`至0.75，测试召回结果中是否仅包含匹配度符合要求的养殖与金融数据，无无关品类或客户的内容。
