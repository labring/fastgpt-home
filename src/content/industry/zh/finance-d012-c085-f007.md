# 水泥营销内容的工作流编排

## 这个品类的数据长什么样
数据主要来自企业内部生产管理系统、经销商库存台账、线下终端销售记录，以及行业协会发布的区域供需动态。文档多为结构化表格与标准化参数说明，包含标号、强度等级、包装规格、出厂批次、运输半径等字段，单位涉及兆帕、千克、千米等。更新节奏上，生产与库存数据每日更新，终端销售数据按周汇总，行业动态数据按月发布。

## 这些特征在「工作流编排」这一环带来什么约束
结构化字段多且存在批次差异，要求工作流需绑定批次维度的变量触发节点，避免跨批次参数混淆。数据更新频率不一，生产与库存数据需实时同步，终端与行业数据需按周定时拉取，需配置双模式同步节点保障参数时效性。运输半径与区域供需数据强绑定，需加入区域维度的过滤节点，仅调用对应覆盖范围的合规数据。强度等级等参数存在行业合规要求，需在工作流中嵌入参数校验节点，防止错误标号、强度参数的营销内容对外发布。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `batch_dimension_trigger` | 按出厂批次+区域编码触发 | 水泥产品按批次生产，不同批次的强度、库存参数存在差异，需绑定对应批次的营销内容生成 |
| `sync_frequency` | 每日1次+实时增量同步 | 生产库存数据每日更新，行业动态数据按周发布，双模式同步保障参数时效性 |
| `param_check_rule` | 强度等级≥32.5MPa | 水泥强度参数需符合建筑行业合规标准，低于阈值的参数需拦截 |
| `max_context_window` | 8192 tokens | 水泥营销物料多为结构化参数，8192 tokens可覆盖完整的产品参数与区域供需数据 |
| `global_var_increment_trigger` | 绑定AI回答完成事件 | 需在AI生成完整营销内容后触发全局计数器更新，确保统计准确 |
| `debug_show_code_node` | 开启节点调试可见 | 需完整查看代码运行节点的执行日志，排查参数处理异常 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调用节点配置deepseek-r1后，生成的营销内容无法正确匹配对应批次的水泥强度参数，效果差于同等级其他模型。原因：未配置`param_check_rule`对强度参数进行合规校验，模型未绑定水泥品类的专属参数约束逻辑。
- 现象：文本内容提取节点的模型选择下拉框为空，无法选择对应模型。原因：未开启节点的模型权限配置，或未在全局配置中绑定对应模型的调用权限。
- 现象：全局Number类型计数器配置变量更新插件后，无法实现AI回答后自动+1。原因：未将变量更新触发事件绑定至AI回答完成节点，仅配置了手动触发规则。

## 怎么确认配好了
- 触发工作流后，查看工作流节点的执行日志，确认是否加载了对应批次的水泥参数，验证`batch_dimension_trigger`配置生效。
- 查看参数校验节点的拦截记录，确认不符合合规要求的参数被正确过滤，验证`param_check_rule`配置生效。
- 触发AI生成营销内容后，检查全局计数器的数值变化，确认触发规则绑定正确，验证`global_var_increment_trigger`配置生效。
- 进入工作流调试模式，查看代码运行节点的执行日志，确认所有配置项均正常加载，无报错信息。
