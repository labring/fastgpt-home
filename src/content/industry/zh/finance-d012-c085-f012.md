# 水泥营销内容的模型接入与配置

## 这个品类的数据长什么样
水泥相关数据主要来自生产企业的MES系统、质检报告单、销售出库台账，以及线下营销物料库。数据更新按生产批次执行，单批次数据生成后24小时内同步。结构化数据字段包含强度等级（单位MPa）、包装规格（单位吨/袋）、出厂编号、保质期；非结构化数据为产品手册、区域推广话术模板，文档格式多为PDF、Excel与纯文本。

## 这些特征在「模型接入与配置」这一环带来什么约束
水泥数据的结构化字段带明确单位与批次属性，要求模型接入时配置字段映射规则，匹配生产系统的标准字段名，避免单位转换错误。按批次更新的数据需要配置增量同步触发机制，绑定生产批次完成事件。区域化推广话术与工程场景绑定的文档，需要在检索环节添加场景与地域标签过滤，确保召回内容匹配目标客群需求。保质期字段要求在知识库检索时自动过滤超出有效期的产品数据，避免输出过期信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 水泥质检报告PDF多包含多张强度检测图表，解析耗时较长，600秒可覆盖完整解析流程 |
| `maxContext` | `800–1200 字符` | 水泥营销内容多包含工程参数与产品指标，较长上下文可完整承载技术参数与场景说明 |
| `召回条数` | `前 6 条` | 水泥客群咨询多聚焦工程适配性，少量精准召回即可覆盖核心需求，避免冗余信息干扰 |
| `相似度阈值` | `0.75–0.85` | 水泥产品参数的标准化程度高，阈值过低易召回不相关的其他建材数据，过高则可能遗漏同品类适配场景 |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | 单批次水泥质检报告合集PDF体积较大，200 MB可覆盖多数企业的批量上传需求 |
| `重排返回条数` | `前 3 条` | 营销内容需简洁传递核心卖点，重排后保留最相关的3条即可满足客户快速获取信息的需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为当咨询超出知识库水泥产品范围的问题时，模型直接返回无法回答，未触发泛化推理。原因是未配置`enable_rag_fallback`参数，或该参数被设置为`false`，导致仅在知识库内检索到内容时才生成回答。
- 现象为调用外部模型渠道时返回`403 Forbidden`错误，且日志显示鉴权参数缺失。原因是未正确配置`API_KEY`与`BASE_URL`，未按照渠道要求添加专属请求头。
- 现象为上传的水泥质检报告解析后字段为空，无法提取强度等级与出厂编号。原因是未开启`PARSE_STRUCTURED_TABLE`参数，或未指定表格解析的字段映射规则，导致结构化数据未被正确提取。

## 怎么确认配好了
- 上传单份水泥质检报告PDF，查看解析结果中的字段是否完整提取强度等级、出厂编号等信息，核对字段映射规则是否匹配生产系统的字段名。
- 发起包含水泥产品参数的测试提问，检查召回的文档数量是否符合配置的`召回条数`设置，且相似度符合预设阈值范围。
- 发起超出水泥产品范围的测试提问，确认模型是否触发泛化推理，不直接拒绝回答。
- 查看外部模型渠道的调用日志，确认鉴权参数与请求头已正确配置，无`403`或`500`类错误返回。
