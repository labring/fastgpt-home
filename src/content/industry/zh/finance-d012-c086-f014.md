# 汽车服务营销内容的表单与交互

## 这个品类的数据长什么样
汽车服务的营销表单数据主要来源于汽车金融咨询、车险投保、维保套餐预约、试驾申请等用户提交的内容，数据更新节奏从提交即时同步到每日批量更新不等。文档结构包含结构化表单字段与非结构化附件，结构化字段包含17位VIN码、车型、联系电话、到店时间、维保项目、行驶里程（单位公里）等，非结构化附件多为车辆照片、维保记录文档、试驾视频等。

## 这些特征在「表单与交互」这一环带来什么约束
汽车服务表单的结构化字段存在专业格式要求，需强制校验字段合法性，避免无效数据流入。非结构化附件体积差异大，单文件可能超过通用阈值，需针对性调整上传与解析限制。实时同步的需求要求表单提交后即时触发数据同步，避免延迟导致的营销内容滞后。多字段组合的统计需求需要足够的上下文窗口承载完整数据，否则会出现统计结果缺失的情况。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | 适配汽车服务常用的维保照片、试驾视频等附件的常规体积，避免上传失败 |
| `maxContext` | `8000-12000 字符` | 覆盖汽车服务表单多字段组合的完整数据量，保障LLM可完成全量统计总结 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 秒` | 为大体积的非结构化附件解析预留足够时间，避免中途中断 |
| `表单字段校验规则` | 强制校验VIN码17位格式、里程数为正整数 | 匹配汽车服务数据的专业格式要求，减少无效输入 |
| `CONTEXT_WINDOW_LIMIT` | 按部署环境实测标定 | 适配不同大语言模型的上下文窗口差异，满足qwen-max等模型的输入限制 |
| `发布页面渲染配置` | 启用持久化存储 | 避免窗口缩放后表单内容丢失，匹配场景需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传的维保数据未参与LLM统计总结，返回结果未包含表单上传内容。原因：未将上传文件关联到对话上下文，或`maxContext`配置未覆盖上传数据的字符量。
- 现象：提交json格式的表单数据后返回字符超限报错。原因：`maxContext`取值小于输入的json字符数，未根据实际数据量调整参数。
- 现象：发布页面缩小窗口后再放大，表单内容全部消失。原因：未启用发布页面的持久化渲染配置，未绑定表单数据的本地存储逻辑。

## 怎么确认配好了
- 提交包含完整汽车服务表单字段的测试数据，检查LLM返回结果是否覆盖所有输入内容的统计逻辑。
- 上传符合配置上限的测试附件，确认解析完成后的数据可正常被LLM调用。
- 调整浏览器窗口大小，检查表单及展示内容是否可正常恢复显示。
- 输入超出常规字符量的json测试数据，检查是否触发对应超限提示或自动适配的上下文调整。
