# 油服工程营销内容的工作流编排

## 这个品类的数据长什么样
面向金融/保险/理财行业的油服工程营销内容数据主要来自现场作业日报、设备运维日志、招投标技术方案、行业合规文档。数据更新按单个项目周期推进，单项目文档包含结构化作业参数表与非结构化技术说明两类。字段包含井号、作业时段、地层压力、材料型号等，单位涵盖MPa、m³、小时等工程专用单位，部分文档需结合现场手写批注的扫描件进行解析，需额外处理扫描件的OCR识别需求。

## 这些特征在「工作流编排」这一环带来什么约束
多源混合的数据结构要求工作流先执行OCR识别扫描批注，再拆分结构化参数与非结构化说明分别处理。按项目更新的节奏要求工作流绑定单个项目的资源标签，避免跨项目数据混淆。工程专用单位需保留原始格式，工作流需配置单位校验节点，防止参数转换错误。长文档的作业说明需分段处理，避免单次输入超出模型上下文限制，同时需保留专业术语的完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `知识库搜索召回条数` | `前3–5条` | 油服工程技术文档单条内容较长，过多召回会超出工作流上下文承载上限 |
| `maxContext` | `8000–10000 字符` | 单份油服项目的核心作业参数与说明文档的有效内容长度集中在该区间 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 秒` | 扫描件OCR识别与结构化参数提取的平均耗时较长，避免解析中途超时中断 |
| `知识库引用上限` | `3000 字符` | 工作流中需同时拼接工程参数、营销文案与合规提示，需严格控制总输入长度 |
| `分段长度` | `1500 字符` | 油服工程文档的技术说明段落平均长度适配该分段规则，避免拆分破坏专业术语连贯性 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 单份油服项目的归档文档可能包含多页扫描件与高清图纸，需适配大文件上传 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中知识库搜索节点返回结果条数与配置的`召回条数`不符，仅返回1条或超出配置数量。原因：未绑定项目专属的知识库标签，导致召回了无关项目的文档。
- 现象：工作流执行时报错`context length exceeded`，且日志显示输入内容超出限制。原因：未调整`知识库引用上限`参数，直接使用默认值，未适配油服工程文档的长内容特征。
- 现象：通过API调用发布的工作流无法读取上传的图片文件，返回`file not found`错误。原因：未在工作流中配置外部API的文件访问权限，导致外部系统无法访问内部存储的文件资源。

## 怎么确认配好了
- 执行单份油服项目文档的解析测试，核对OCR节点是否提取了扫描件上的手写参数。
- 触发工作流后查看上下文日志，确认召回的知识库内容条数符合配置的`召回条数`。
- 调用API提交测试请求，核对返回的营销内容是否包含了正确的工程参数与单位。
- 调整`知识库引用上限`参数后，再次执行长文档测试，确认未出现上下文超限报错。
