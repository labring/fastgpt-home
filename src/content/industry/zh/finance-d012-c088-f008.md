# 油服工程营销内容的工具调用与插件

## 这个品类的数据长什么样
油服工程的数据主要来源于钻井作业实时监控系统、录井测井平台、设备运维日志系统、现场物资管理系统四类核心数据源。数据更新节奏随作业进度调整，单井施工周期内每日更新3-5次，项目竣工后生成归档台账。单份数据文档以单井作业为核心单元，包含施工日期、井号、钻井深度、钻压、泵压、泥浆密度等字段，其中钻井深度单位为米，钻压单位为千牛，泵压单位为兆帕，泥浆密度单位为克/立方厘米，部分关联文档还包含作业班组、安全巡检记录与物资消耗明细。

## 这些特征在「工具调用与插件」这一环带来什么约束
油服工程的数据来源分散且异构，要求工具调用需支持对接多类API接口，避免单源数据无法覆盖营销所需的全量信息。数据更新频率较高，插件同步与工具调用的时间间隔需匹配作业进度，否则会导致营销内容使用过时的施工数据。单井为核心的文档结构要求工具调用参数必须绑定井号作为过滤条件，否则返回的跨项目数据会干扰营销内容的精准性。字段与单位的固定属性要求工具调用时需强制校验参数单位，避免出现单位不统一导致的内容偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `tool_call_timeout` | 300–600 秒 | 油服工程单井工况数据拉取通常需要120-400秒，超时过短会导致作业数据未完全返回 |
| `max_tool_results` | 前10条单井数据 | 油服营销内容通常聚焦单井或单项目的核心参数，过多条目会超出营销文案的承载量 |
| `tool_param_filter_rule` | 按`well_id`字段过滤 | 油服数据以单井为核心管理单元，需强制绑定井号参数避免跨项目数据混淆 |
| `plugin_auto_update` | 每日2次同步 | 油服设备运维日志每日更新2次，同步频率匹配数据更新节奏 |
| `plugin_auth_scope` | 仅开放作业数据API权限 | 油服数据涉及施工安全与商业信息，需限制插件访问范围仅覆盖营销所需字段 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调用时`q`参数传入全量作业日志内容，未提取营销所需的工况片段。原因：未配置`tool_param_filter_rule`，未对输入内容按营销场景做字段裁剪。
- 现象：插件点击后无响应，界面显示`504 Gateway Timeout`报错。原因：`tool_call_timeout`设置过短，油服数据拉取未完成就超时终止。
- 现象：工具返回的钻井深度同时出现米与英尺单位，导致营销内容出现数据偏差。原因：未在`tool_param_filter_rule`中强制指定单位转换规则，未对齐营销内容所需的统一单位。

## 怎么确认配好了
- 发起一次工具调用测试，检查传入的`q`参数是否仅包含营销场景所需的内容片段，核对`tool_param_filter_rule`是否生效。
- 查看工具调用日志，确认未出现`408 Request Timeout`或`504 Gateway Timeout`报错，超时时间符合油服数据拉取的实际耗时。
- 核对工具返回的字段与单位，确认已按配置完成统一转换，无异常字段混入。
- 测试插件的自动同步功能，确认同步频率与油服数据的更新节奏匹配。
