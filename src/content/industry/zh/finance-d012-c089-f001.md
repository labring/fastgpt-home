# 油气开采营销内容的HTTP 接口与外部系统

## 这个品类的数据长什么样
这个品类的数据主要来自油气开采企业生产管理系统API、大宗商品交易平台行情接口、合规监管公开文档接口、营销素材管理系统元数据接口。生产数据按小时更新，行情数据按分钟更新，合规文档按季度更新，素材元数据每日更新。单条数据为JSON结构，包含唯一标识`api_request_id`、当日开采量`production_volume`（单位：立方米）、实时油价`trading_price`（单位：美元/桶）、合规条款编号`compliance_code`、素材曝光量`impression_count`（单位：次）等字段，时间戳字段标记数据采集时刻。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
生产数据按小时更新、行情数据按分钟更新的特征，要求HTTP接口需适配不同的调用频率，行情接口需设置较短的超时时间以获取最新数据，生产接口可接受适度重试机制。多源数据的字段单位差异，比如油价的美元/桶与开采量的立方米，需在接口调用前完成单位转换。合规文档的静态属性，适合配置缓存规则以降低重复调用成本。营销内容生成需同时调用多类接口，需配置并发请求限流，避免超出外部系统调用限额。另外，不同接口的返回结构差异，需统一映射为平台可识别的字段格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `HTTP_REQUEST_TIMEOUT` | 行情接口`10 秒`、生产接口`30 秒` | 匹配不同数据源的实时性要求，避免超时影响营销内容生成效率 |
| `CACHE_EXPIRE_TIME` | 行情接口`5 分钟`、生产接口`1 小时`、合规文档`7 天` | 对应各数据的更新频率，减少重复调用成本 |
| `PARALLEL_REQUEST_LIMIT` | `前 3 条` | 控制并发请求数量，避免超出外部系统限流阈值 |
| `FIELD_MAPPING_RULE` | 按`external_field → platform_field`格式配置 | 统一多源异构数据的字段结构，适配平台数据处理逻辑 |
| `RETRY_TIMES` | `2 次` | 应对临时网络波动，避免过度重试增加外部系统压力 |
| `UPSTREAM_API_AUTH_TYPE` | `API_KEY 认证`或`OAuth2.0` | 匹配外部系统的认证要求，保障接口调用合法性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：界面返回结果同时包含外部HTTP接口数据和AI生成的问答文本，日志中存在重复输出记录。原因：未正确配置响应模式参数，未启用仅返回外部接口结果的设置，导致AI生成环节未被关闭。
- 现象：HTTP接口调用返回`429 Too Many Requests`报错，调用失败。原因：未设置并发请求限制参数，同时发起的请求数量超出外部系统的限流阈值。
- 现象：营销内容中显示的油价或开采量单位与预期不符，数据逻辑异常。原因：未配置字段映射规则中的单位转换项，未对不同数据源的单位进行统一处理。

## 怎么确认配好了
- 发起单次HTTP接口调用，查看返回结果是否仅包含外部接口数据，无额外AI生成内容，验证响应模式配置是否生效。
- 模拟并发发起3次以上接口调用，观察是否触发限流报错，验证并发请求限制配置是否合理。
- 提取外部接口返回的字段，对照配置的字段映射规则，检查字段名称与单位是否已完成统一转换。
- 等待缓存过期后再次调用接口，确认返回数据为最新采集的内容，验证缓存过期时间配置是否正确。
