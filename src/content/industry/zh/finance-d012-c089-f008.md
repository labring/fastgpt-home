# 油气开采营销内容的工具调用与插件

## 这个品类的数据长什么样
油气开采领域的数据来源包括油气田生产物联网终端、第三方地质勘探数据库、行业公开的开采进度报表。数据更新节奏因类型差异明显：实时监测的井下压力、产量数据每数秒更新，月度生产统计数据每月末集中更新，地质勘探报告每季度更新一次。文档结构分为结构化表格与非结构化文本两类，结构化字段包含井位编号、日产油气当量、地层渗透率、作业状态，对应单位分别为无、立方米/天、毫达西、运行/停产；非结构化内容包含钻井施工日志、试采分析纪要等长文本。

## 这些特征在「工具调用与插件」这一环带来什么约束
实时监测数据的高频更新要求工具调用的响应延迟控制在较短区间内，否则无法支撑实时营销内容的快速生成。结构化字段与多单位混用的特征，要求插件在调用过程中自动完成单位转换与格式校验，避免营销内容出现单位错误或格式混乱。非结构化日志的长文本属性，需要工具调用支持分段拉取与合并处理，避免单次调用超出模型上下文限制。不同数据源的更新频率差异，要求插件支持按数据类型配置独立的缓存时长，平衡数据时效性与调用资源开销。营销内容生成需依赖最新的开采进度数据，因此工具调用需优先拉取实时数据源，同时兼顾历史统计数据的调用需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_timeout` | 8 秒 | 匹配油气开采实时监测数据的更新间隔，避免等待超时导致营销内容延迟生成 |
| `context_window_segment_length` | 1000–1200 字符 | 适配油气开采非结构化日志的平均长度，避免单次调用超出模型上下文限制 |
| `cache_ttl_by_data_type` | 实时监测数据：300秒；月度统计数据：604800秒 | 匹配不同类型数据的更新频率，平衡数据时效性与调用开销 |
| `unit_auto_convert_switch` | 开启 | 解决油气开采领域多单位混用的问题，确保营销内容中压力、产量等字段单位统一 |
| `stream_response_switch` | 开启 | 适配仅支持stream模式的大模型调用需求，符合工具调用的实时输出要求 |
| `max_tool_call_retries` | 2 次 | 平衡调用成功率与重复请求开销，避免因单次API波动导致营销内容生成中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用API时传递`chatId`参数，对话日志中未显示该字段，且无法通过chatId追溯对应对话。原因：未开启`enable_chatid_log`配置项，或工具调用逻辑未将chatId参数注入到请求参数中。
- 现象：全局变量在工具调用中更新后，后续调用未获取到更新后的值。原因：未配置全局变量的缓存刷新逻辑，或工具调用脚本未触发变量更新后的同步操作。
- 现象：调用工具API时返回`{"code":514,"statusText":"unAuthApiKey"}`错误。原因：API密钥配置错误，或密钥未绑定对应工具调用权限，或密钥已超出有效期限。

## 怎么确认配好了
- 发起一次工具调用请求，检查返回结果中是否包含正确的单位转换后的数据，核对缓存时长是否匹配对应数据的更新频率。
- 查看平台后台的工具调用日志，确认`chatId`参数已被正确记录，且未出现514状态码的报错。
- 调用仅支持stream模式的大模型，验证工具调用过程中是否能实时返回流式输出，无卡顿或中断。
- 更新全局变量后，再次发起工具调用，确认返回结果中使用了更新后的变量值。
