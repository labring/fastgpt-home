# 消费建材营销内容的知识库检索与召回

## 这个品类的数据长什么样
消费建材营销相关数据主要来自产品技术手册、终端门店推广物料、电商平台详情页、经销商政策文档及线下活动方案。数据更新节奏随新品上线、促销活动调整及价格变动不定期触发，装修旺季前更新频次更高。单份文档多为图文混合结构，包含产品SKU、适用空间、环保认证等级、涂刷/安装参数、终端指导价等字段，单位涵盖毫米、平方米、升、元等品类专属计量标准。

## 这些特征在「知识库检索与召回」这一环带来什么约束
消费建材数据的多字段专属属性，要求检索环节需支持字段级精准匹配，例如针对`环保认证`、`适用空间`字段定向召回，避免泛化匹配。数据更新的不定期性，要求召回流程支持增量解析与增量索引，避免全量重建带来的资源消耗。营销内容含有时效性的促销参数，需在召回环节加入有效期过滤逻辑，排除过期物料。文档内的专业安装、材质参数需匹配细分领域的语义向量模型，避免通用检索的语义偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份消费建材产品手册或活动方案文本长度较长，避免解析超时后反复重试 |
| `maxContext` | `8000–12000 字符` | 消费建材文档常包含多段技术参数与营销话术，需保留足够上下文关联信息 |
| `召回条数` | `前 8–12 条` | 消费建材产品SKU较多，需召回足够覆盖不同场景的匹配结果，避免遗漏适配内容 |
| `相似度阈值` | `0.72–0.80` | 细分领域专业术语较多，需平衡精准度与召回覆盖率，避免过度过滤有效内容 |
| `PARSE_CHUNK_SIZE` | `800–1000 字符` | 建材文档的技术参数段落长度适中，分段后可保留完整语义单元 |
| `增量更新开关` | `开启` | 消费建材数据更新无固定周期，增量更新可降低服务器负载 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传知识库解析文件时，日志持续报`slow operation xxxxms`，且MongoDB响应延迟。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，单份长文档解析超时后反复重试，导致MongoDB连接堆积。
- 现象：部分文档上传后未生成问答对，直接写入原文。原因：未配置`PARSE_CHUNK_SIZE`，或分段长度与文档结构不匹配，导致专业参数段落被错误拆分，无法触发问答生成逻辑。
- 现象：调用检索接口返回`insufficient_quota 当前分组上游负载已饱和，请稍后再试`。原因：召回条数设置过高，且未限制单请求的召回并发数，导致上游向量库负载过载。

## 怎么确认配好了
- 上传一份典型的消费建材产品手册，检查解析日志中无`slow operation`报错，确认`PARSE_FILE_TIMEOUT_SECONDS`取值适配文档长度。
- 发起一次营销场景的检索请求，核对返回结果中包含`环保认证`、`适用空间`等专属字段的匹配内容，确认字段级检索配置生效。
- 上传一份含有效期的促销文档，检索后检查结果仅包含未过期的内容，确认时效性过滤逻辑正常运行。
- 调整召回条数参数，观察向量库监控指标，确认负载处于合理区间，无过载报错。
