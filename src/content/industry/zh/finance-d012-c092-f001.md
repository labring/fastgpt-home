# 消费电子营销内容的HTTP 接口与外部系统

## 这个品类的数据长什么样
消费电子的营销内容主要来源于品牌官方产品页、第三方电商平台商品详情、新品发布会通稿与社交媒体种草素材。更新节奏随新品发布周期波动，新品上线前会批量更新全量内容，日常促销节点会调整文案与参数细节。文档结构包含结构化字段与非结构化文本，结构化字段涵盖产品型号、屏幕尺寸、电池容量、处理器型号等，单位包含英寸、毫安时、GHz等；非结构化文本包含产品卖点、使用场景描述与促销活动说明。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
来源的多样性要求HTTP接口支持多源鉴权，适配不同外部系统的OAuth、API密钥等验证方式。更新节奏的波动性要求接口支持增量拉取与全量拉取两种模式，应对批量更新与日常微调的不同需求。文档结构的混合性要求接口同时处理结构化字段提取与全文语义解析，避免单一解析逻辑遗漏关键参数。字段单位的不统一性要求接口层增加单位转换预处理逻辑，确保不同来源的参数格式统一。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 消费电子营销内容常包含高清产品图与长参数文档，需适配较大文件上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1200 秒` | 长文档的参数解析与内容拆分耗时较长，避免超时中断解析流程 |
| `maxChunkSize` | `800–1200 字符` | 消费电子参数包含多单位数值，分段长度适配可平衡嵌入精度与接口调用效率 |
| `embedding_batch_size` | `32 条` | 营销内容的文本片段数量较多，批量处理可优化外部嵌入接口的调用效率 |
| `api_request_timeout` | `60 秒` | 适配外部电商、发布会平台API的常规响应时长，避免单次请求超时 |
| `retry_count` | `3 次` | 外部接口偶发波动，重试机制可保障数据拉取的稳定性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：离线部署时上传营销文档后界面显示加载超时，控制台返回`403 Forbidden`错误。原因：未配置本地向量模型的离线调用地址，默认尝试访问外部API接口导致鉴权失败。
- 现象：拉取第三方电商平台的产品数据时，返回字段`battery_capacity`为空。原因：未适配电商API的版本更新，旧版接口已调整该字段的公开访问权限。
- 现象：批量导入促销文案时，返回的召回结果条数未达到预设阈值。原因：未调整`maxChunkSize`参数，长文本被过度拆分导致单批次召回上限被触发。

## 怎么确认配好了
- 上传一份包含产品参数与促销文案的测试文档，核对界面解析后的分段数量是否符合业务预期。
- 调用外部系统数据拉取接口，验证返回的结构化字段（如`product_id`、`launch_date`）是否完整且格式正确。
- 查看接口调用日志，确认当外部接口返回`500 Internal Server Error`时，重试机制正常触发。
- 断开外部网络后再次上传文档，确认离线部署下的解析流程无异常中断。
