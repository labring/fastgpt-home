# 游戏营销内容的多轮对话与提示词

## 这个品类的数据长什么样
游戏营销内容的来源包括游戏官方营销素材库、历史客服互动对话日志、版本更新公告、第三方玩家社区互动内容。更新节奏分为三类：常规营销物料按周更新，版本配套营销内容按月更新，限时活动物料按活动周期更新。单条营销内容的文档结构包含话术文本、目标用户分层标签、触发场景编码、有效期、关联游戏内活动ID，字段包括话术内容、场景编码、用户标签组、生效截止时间，单位为条、字符、小时。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
游戏营销内容的场景细分明确，多轮对话需要精准匹配引导、转化、售后等不同场景，避免泛化话术影响玩家体验。营销物料更新频率较高，提示词需支持动态加载最新内容，无法依赖硬编码的静态话术。关联游戏内活动ID的字段要求多轮对话需携带上下文的活动标识，避免跨活动混淆。用户分层标签的存在要求提示词调用对应字段定制话术，适配不同玩家群体。历史互动日志的积累要求控制上下文窗口长度，避免冗余信息稀释当前场景的有效信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 前8轮对话+最近2条活动上下文 | 游戏营销对话多围绕单次活动展开，过多历史会稀释当前场景信息 |
| `recallTopK` | 前6-8条 | 游戏营销物料按场景细分，过多召回会导致上下文冗余混乱 |
| `knowledgeBaseRefreshInterval` | 每12小时 | 匹配游戏营销物料周更、月更的更新节奏，避免使用过期内容 |
| `globalVariableScope` | 对话全局持久化 | 保留游戏活动ID、用户分层标签等跨对话的固定参数 |
| `knowledgeBaseQueryTimeout` | 30秒 | 避免因知识库检索超时导致对话卡顿，适配游戏玩家即时交互的需求 |
| `promptSceneTag` | 绑定场景编码字段 | 精准匹配游戏营销的引导、转化、售后等不同场景 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：部分对话未触发知识库检索，直接返回通用话术。原因：未配置`promptSceneTag`绑定场景编码字段，系统无法识别当前对话是否需要调用游戏营销物料知识库。
- 现象：对话中设置的活动ID变量在后续轮次中丢失。原因：未开启`globalVariableScope`的全局持久化配置，仅使用临时对话变量，未保留跨轮次的固定参数。
- 现象：同一对话窗口内多轮提问后，知识库检索耗时显著增加，新窗口检索速度正常。原因：未限制`maxContext`的上下文长度，过多历史对话导致上下文窗口膨胀，拖慢知识库检索匹配流程。

## 怎么确认配好了
- 触发对应游戏营销场景的提问，检查返回话术是否包含知识库中最新的活动内容，确认检索逻辑生效。
- 输入包含活动标识的提问，在后续轮次中重复提及该活动，检查活动标识是否保留，确认全局变量配置生效。
- 连续发起多轮相关提问，检查知识库检索耗时是否稳定，确认上下文长度配置适配当前交互需求。
- 查看系统定时任务日志，确认知识库刷新任务按预设周期执行，无过期物料被召回。
