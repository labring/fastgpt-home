# 游戏营销内容的工作流编排

## 这个品类的数据长什么样
游戏营销内容的数据主要来自四个渠道：游戏内用户行为埋点、广告投放后台、游戏社区评论系统、官方活动素材管理库。数据更新节奏差异明显：用户行为与实时互动数据为秒级更新，广告投放效果数据为小时级更新，社区评论与素材版本记录为分钟级更新。单条数据的核心字段包含：广告位标识`ad_slot_id`、单次素材曝光量`ad_impression`（单位次）、用户留存时长`user_stay_duration`（单位秒）、素材投放渠道`channel`、素材版本号`material_version`，字段名与单位均符合各渠道的原生数据格式。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流支持并行拉取不同渠道的数据源，并完成字段映射统一格式，避免因字段名差异导致的数据解析失败。不同数据源的更新节奏差异，要求工作流节点配置差异化的触发频率，同时需内置数据延迟校验逻辑，处理广告后台数据滞后于游戏内实时数据的场景。游戏营销素材存在版本迭代与审核状态的要求，工作流需关联素材版本号字段，仅调用审核通过的最新版本素材。此外，多渠道投放的接口调用限制，要求工作流配置限流与重试节点，适配不同投放平台的调用频率阈值。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `workflow_run_timeout` | `300 秒` | 游戏营销内容生成与投放校验的常规耗时不超过5分钟，避免长耗时任务占用集群资源 |
| `api_request_rate_limit` | `10 次/秒` | 多数游戏投放平台的接口限流阈值为10-20次/秒，适配常规批量投放需求 |
| `form_node_display_mode` | `嵌套场景强制隐藏` | 游戏营销工作流常作为嵌套节点嵌入主流程，无需重复弹出对话框干扰操作 |
| `retry_max_times` | `3 次` | 应对广告接口临时波动导致的调用失败，避免无效重试占用运行资源 |
| `data_mapping_rule` | `按字段别名自动匹配` | 多源数据字段名存在差异，自动映射可减少手动配置工作量 |
| `version_check_switch` | `开启` | 游戏营销素材存在版本迭代，需校验调用最新审核通过的素材版本 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：嵌套工作流中的表单节点在被调用时弹出对话框，单个直接运行的工作流中无此弹窗。原因：未配置`form_node_display_mode`参数的嵌套场景适配规则，默认保留了弹窗逻辑。
- 现象：工作流运行耗时超过预设阈值，页面显示`workflow_timeout`错误码，批量生成营销内容时出现延迟。原因：未开启节点并行执行配置，或未调整`api_request_rate_limit`参数适配多渠道调用需求。
- 现象：升级至4.9.10版本后，工作流的提示词编辑与全局变量配置项数量减少。原因：版本迭代中优化了配置项展示逻辑，需进入高级设置面板开启完整配置展示。

## 怎么确认配好了
- 手动触发单个工作流，检查表单节点是否无弹窗弹出，确认`form_node_display_mode`配置生效。
- 调用嵌套工作流，观察表单节点的弹窗状态，验证嵌套场景的配置是否正确。
- 查看工作流运行日志，核对多源数据的字段映射是否完成，确认`data_mapping_rule`配置生效。
- 核对工作流的唯一标识`workflow_id`是否正确记录，调用时使用发布后的有效ID，避免出现`invalid_workflow_id`错误码。
- 提交批量素材生成任务，检查运行耗时是否符合业务需求阈值，确认`workflow_run_timeout`配置合理。
