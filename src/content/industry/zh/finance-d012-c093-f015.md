# 游戏营销内容的部署与升级

## 这个品类的数据长什么样
游戏营销内容的数据主要来源于版本更新日志、活动规则文档、投放素材源文件、玩家社区反馈整理内容。更新节奏随项目周期调整，版本类内容按季度或月度更新，活动类内容按周或节假日节点更新。文档包含结构化与非结构化两类：结构化内容含活动ID、版本号、投放渠道、素材尺寸等字段，单位多为UTC+8时间戳、像素、MB；非结构化内容含剧情文案、主播口播脚本，以纯文本或富文本格式存储。

## 这些特征在「部署与升级」这一环带来什么约束
结构化字段多且更新频繁，要求部署阶段配置多字段解析规则，升级时需保留已配置的字段映射避免重置。活动类内容按节点快速更新，要求部署时配置定时同步任务的间隔参数，升级过程需支持热重载以避免中断实时内容生成。素材存在固定尺寸与格式要求，部署阶段需限制上传文件的大小与格式范围。内网私有化部署场景下，需配置本地模型调用的网络策略，避免因外网限制导致服务访问异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 游戏营销素材多为高清海报、视频片段，单文件大小通常符合该范围，避免上传超时 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 游戏营销文档常包含长文本剧情或复杂活动规则，300秒可覆盖完整解析时长 |
| `maxContext` | `8000–12000 字符` | 游戏营销内容需关联版本、活动等多字段上下文，该区间可完整承载关联信息 |
| `召回条数` | `前 6–8 条` | 游戏营销内容的关联信息多集中在近期更新，该范围可覆盖核心参考内容 |
| `TOOL_CALL_TIMEOUT` | `60 秒` | 游戏实时活动的工具调用需快速响应，60秒可满足多数实时查询需求 |
| `SYNC_INTERVAL` | `3600 秒` | 游戏版本与活动更新频率多为每日至每周，该间隔可平衡实时性与资源占用 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：内网私有化部署后，访问工作流编辑界面时显示报错`Application error: a client-side exception`。原因：未配置内网环境下的本地模型调用网络白名单，导致前端无法连接后端服务端口。
- 现象：使用Qwen2.5模型通过Ollama部署时，无法触发工具调用。原因：未在配置中开启工具调用开关，或未正确配置模型的工具调用参数映射。
- 现象：升级FastGPT后，原有的活动内容解析规则失效。原因：升级时未保留旧版的字段映射配置，直接覆盖了自定义解析规则。

## 怎么确认配好了
- 上传一份游戏营销素材文件，检查上传进度与解析结果是否符合预期，核对解析出的字段是否与配置的映射规则一致。
- 发起一次工具调用测试，验证模型是否能正确触发预设的查询动作，比如查询当前活动时间。
- 调整并发请求数量，观察服务响应状态，确认资源占用符合预设阈值。
- 执行一次版本升级测试，验证升级后原有配置未被重置，工作流可正常启动。
