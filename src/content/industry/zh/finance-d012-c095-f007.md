# 热力营销内容的工作流编排

## 这个品类的数据长什么样
热力数据来自金融机构合作的公用事业企业计量采集系统，包含楼栋、换热站、终端用户的用热计量信息，用于获客营销场景。更新频率按节点覆盖范围不同，从15分钟到1小时不等，偏远传输节点可能出现最长30分钟的延迟。单条数据为结构化格式，包含设备唯一标识、采集时间戳、瞬时供热量、累计供热量、供回水温度、管网压力字段，单位分别为MW、GJ、℃、MPa，部分数据存在丢包情况。

## 这些特征在「工作流编排」这一环带来什么约束
数据更新频率的差异要求工作流触发节点适配事件驱动模式，避免定时轮询产生的无效执行与数据滞后。多字段与单位要求需在字段映射环节预设校验规则，防止单位不匹配导致的营销内容生成错误。传输延迟与丢包风险要求工作流配置超时重试与数据补全分支，保障输入数据的有效性。设备ID与用户画像的关联逻辑，要求工作流中增加映射校验节点，防止因关联错误导致营销内容匹配偏差，进而影响获客精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `trigger_mode` | `event_trigger` | 适配热力数据按采集事件更新的特性，避免定时轮询产生的无效执行与数据滞后 |
| `field_validation_rules` | `{"temperature": "0-150℃", "pressure": "0-2.5MPa", "heat_flow": "0-10MW"}` | 匹配热力管网常规运行参数范围，过滤异常采集的无效数据 |
| `retry_max_times` | `3次` | 平衡传输延迟场景下的数据可靠性与工作流执行耗时 |
| `cross_system_timeout` | `600秒` | 适配设备ID与用户画像关联的跨系统调用常规响应时长 |
| `context_token_limit` | `8000` | 匹配热力营销内容所需的信息密度，避免上下文过长导致生成内容冗余 |
| `user_info_fetch_switch` | `开启` | 若需在营销内容中展示用户名称，需开启该配置拉取用户信息 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为表单节点无法被其他分支接入，执行时触发`NODE_CONNECT_RESTRICTED`错误码。原因是未开启工作流的节点复用权限，默认配置下节点仅支持单链路绑定。
- 现象为工作流输出中`user_name`字段为空，仅返回`user_id`字段。原因是未配置用户信息拉取节点，默认仅返回系统生成的用户标识。
- 现象为生成的营销内容与当前热力使用状态不符，日志中出现`DATA_OUTDATED`提示。原因是工作流采用定时轮询触发，未使用事件驱动模式，导致调用了过期的采集数据。

## 怎么确认配好了
- 触发模拟热力采集事件，核对工作流执行日志，确认触发逻辑匹配配置的`trigger_mode`
- 传入超出常规范围的热力参数，查看字段校验节点的拦截结果，确认规则生效
- 拉取关联后的用户与设备数据，核对映射关系的准确性，确认无关联错误
- 查看工作流最终输出的营销内容，确认包含预设的热力数据字段与业务信息
