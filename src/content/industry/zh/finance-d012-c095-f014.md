# 热力营销内容的表单与交互

## 这个品类的数据长什么样
热力品类的营销数据主要来源于热力运营系统的用户缴费台账、区域热力站运行日志、线下入户调研表单及线上报修工单。数据更新节奏差异明显：用户缴费台账按自然季度同步，热力站运行日志每小时刷新，报修工单实时生成。单条数据的文档结构包含用户唯一标识、服务区域编码、用热建筑面积、缴费周期、报修类型、响应时长等字段，其中用热面积单位为平方米，缴费金额单位为元，响应时长单位为小时。

## 这些特征在「表单与交互」这一环带来什么约束
不同来源的数据特征对表单与交互环节带来多重约束。多源数据的字段差异要求表单支持自定义字段映射，适配缴费台账、运行日志等不同数据源的导入需求。实时更新的报修工单要求交互环节支持即时提交与状态同步反馈，避免数据延迟。多字段的复杂结构要求表单按业务场景分组，将用户信息、用热参数、服务需求拆分为独立模块，降低填写复杂度。同时，用热面积、区域编码等带有明确业务规则的字段，需要内置格式校验逻辑，减少无效数据提交。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `form_submit_timeout` | `30 秒` | 热力营销表单多包含批量数据导入或多字段提交，30秒可覆盖常规提交场景，避免超时中断 |
| `import_batch_size` | `500 条` | 热力缴费台账数据量适中，单批次500条可平衡导入速度与系统稳定性，避免批量提交卡顿 |
| `ENABLE_SPEECH_RECOGNITION` | `仅移动端启用` | 热力用户多通过线下或PC端提交表单，移动端语音输入需求明确，同时规避浏览器兼容性问题 |
| `SYSTEM_VERSION_LOCK` | `4.9.10-fix2` | 生产环境需稳定运行，锁定当前版本可避免大版本更新带来的功能波动，匹配生产部署需求 |
| `field_validation_mode` | `前端+后端双重校验` | 热力表单字段包含业务规则校验，前端校验可即时反馈，后端校验确保数据合规，避免无效数据进入系统 |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | 热力营销需上传区域热力图、用户台账等文件，100MB可覆盖常规文件大小需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置`ENABLE_SPEECH_RECOGNITION`后，浏览器弹出“浏览器不支持语音输入”提示。原因：未区分终端适配，全局启用语音识别后，PC端浏览器未加载对应语音引擎，导致兼容性报错。
- 现象：表单提交后返回`408 Request Timeout`状态码。原因：未调整`form_submit_timeout`参数，默认超时时间过短，无法覆盖热力批量数据提交的耗时。
- 现象：本地部署后，工作流节点过多时表单输入卡顿。原因：未限制`import_batch_size`参数，单批次导入数据量过大，导致前端渲染资源占用过高，引发卡顿。

## 怎么确认配好了
- 提交一条测试表单数据，核对字段校验逻辑是否触发对应提示，确认`field_validation_mode`配置生效。
- 上传符合配置大小的测试文件，确认上传流程无中断，验证`UPLOAD_FILE_MAX_SIZE`参数匹配业务需求。
- 切换不同终端测试语音输入功能，确认移动端可正常使用，PC端无兼容性报错，验证`ENABLE_SPEECH_RECOGNITION`的适配逻辑。
- 查看系统版本信息，确认当前运行版本与锁定版本一致，验证`SYSTEM_VERSION_LOCK`配置生效。
