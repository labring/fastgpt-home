# 焦煤营销内容的多轮对话与提示词

## 这个品类的数据长什么样
焦煤相关数据主要来自国内煤炭交易中心公开台账、港口装卸记录、下游工业企业采购报备信息及行业协会监测报告。数据更新节奏存在差异：港口库存与实时交易价格每小时更新，月度产能与行业供需数据每月更新。单条数据包含固定结构化字段，涵盖产地标识、干基灰分指标、粘结指数、全水分含量、交易单价、库存总量、运输距离等，其中交易单价单位为元/吨，库存总量单位为吨，运输距离单位为公里，部分字段采用枚举分类形式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
面向金融机构的焦煤营销内容，其数据的多源更新节奏要求多轮对话需区分实时与非实时指标的调用逻辑，实时交易价格类对话需每次调用最新接口获取数据，月度供需数据可通过缓存减少重复请求。固定结构化字段与枚举产地要求提示词需明确限定字段取值范围，避免生成超出枚举的产地信息。明确的单位体系要求提示词强制绑定输出单位，防止出现单位混淆。同时多字段属性要求多轮对话需逐步引导用户明确所需指标维度，避免生成模糊的营销内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `前8–12条` | 焦煤营销对话需保留用户需求与指标偏好的历史记录，该区间可平衡上下文完整性与响应效率，适配FastGPT 4.10.0版本的上下文存储逻辑 |
| `systemPrompt` | 面向金融机构的焦煤营销内容生成时，需严格使用给定的结构化数据字段，输出附带正确单位，优先选用枚举产地值，不得虚构指标 | 焦煤数据存在固定字段与枚举分类，需约束生成内容符合数据规范与金融场景要求 |
| `relevanceThreshold` | `0.78–0.82` | 焦煤细分指标较多，该阈值可过滤低相关的历史对话片段，避免干扰当前生成逻辑 |
| `rerankTopN` | `前4–6条` | 焦煤数据核心指标约5个，重排后保留核心数据可确保营销内容聚焦关键信息 |
| `loopMaxTimes` | `2–4次` | 焦煤营销内容的迭代调整无需过多循环，该区间可平衡内容优化与生成效率 |
| `apiSessionBind` | 绑定唯一会话ID | API渠道调用需保留完整对话上下文，确保多轮对话的需求连贯性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：设置`maxContext`为30条，对话明细仅显示2条上下文，回复无法关联历史需求。原因：未开启对话上下文持久化配置，或上下文缓存阈值被错误调低。
- 现象：提示词中包含带空格的焦煤字段名（如“干基灰分”），生成内容中出现字段名拆分错误。原因：未在提示词中明确要求保留字段空格，或未开启提示词的空格识别开关。
- 现象：配置循环工作流后，仅执行1次就终止，未按预期完成多轮生成与判断。原因：循环判断逻辑未正确绑定对话输出结果，或判断条件未匹配预期的文本分类结果。

## 怎么确认配好了
- 发起测试对话，输入焦煤相关的指标需求，核对对话明细中显示的上下文条数与设置的`maxContext`一致。
- 编写测试提示词，包含带空格的焦煤字段名，发起对话后核对生成内容是否保留字段空格。
- 配置循环工作流，输入不符合要求的测试文本，核对循环是否按预期执行指定次数。
- 通过API调用绑定会话ID，发起两轮对话，核对第二轮回复是否关联第一轮的需求信息。
