# 燃气营销内容的表单与交互

## 这个品类的数据长什么样
数据来源为燃气经营企业的用户管理系统、缴费台账与用气计量设备。更新节奏分为两类：用户基础档案每季度同步更新，缴费与实时用气数据每日更新。单条数据文档结构包含用户标识、用气地址、累计用气量、月度缴费记录、报修工单编号字段。字段单位统一为立方米（用气量）、元（缴费金额）、YYYY-MM-DD（时间戳），无多单位混用的情况。

## 这些特征在「表单与交互」这一环带来什么约束
基础档案的季度更新频率，要求表单交互支持按季度筛选历史数据，用于精准营销触达。多字段与固定单位的结构，要求表单组件预设单位后缀，避免用户输入错误格式。实时用气数据的每日更新要求，交互环节需提供手动刷新按钮，确保获取最新用气状态。批量营销场景下，需支持按用气地址批量拉取用户数据，避免单条查询的延迟问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `session_persist_mode` | `固定流程绑定` | 燃气营销场景需统一触达流程，避免用户重复选择触发不同分支 |
| `chunk_split_max_length` | `800-1200字符` | 燃气业务文档多为台账与规则说明，过长分段会导致拆分报错Invalid array length |
| `speech_token_timeout` | `600秒` | 语音输入需适配燃气营业厅场景的网络波动，超时会触发token validation failed报错 |
| `enable_image_parse` | `仅文本模式` | 燃气业务数据多为结构化台账，图片问答拆分暂不支持结构化字段提取 |
| `batch_query_limit` | `单次50条` | 燃气用户数据量较大，批量查询超出上限会触发接口限流 |
| `form_field_validation` | `启用单位校验` | 燃气业务字段有固定单位，未校验会导致数据格式错误 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为配置`chunk_split_max_length`时出现Invalid array length报错，必现于分段长度超出系统处理上限。原因是未按业务文档长度调整拆分参数，导致数组拆分时维度不匹配。
- 现象为语音输入时弹出token validation failed提示。原因是未配置`speech_token_timeout`参数，或取值过短，导致语音转写超时未完成验证。
- 现象为对话中用户选择一次流程后，后续对话仍触发分支选择。原因是未开启`session_persist_mode`的固定流程绑定配置，会话未持久化用户选择状态。

## 怎么确认配好了
- 发起测试对话，选择指定流程后连续发起多轮提问，确认所有提问均沿用选定的流程分支。
- 上传燃气业务台账文档，检查知识库拆分结果的分段长度是否符合预设范围，无数组报错。
- 发起语音输入测试，等待转写完成后确认无token验证失败提示，根据测试结果调整超时参数取值。
- 配置表单字段校验规则，输入带错误单位的测试数据，确认系统触发格式校验提示。
