# 物业管理营销内容的工作流编排

## 这个品类的数据长什么样
物业管理场景的数据主要来源于内部业主管理系统、缴费台账系统、报修工单系统及社区公告库。数据更新节奏存在差异：业主基础信息、房号绑定数据随业主入住/退租实时更新，缴费数据按月度批量更新，报修工单与社区公告则随事件触发更新。文档结构以房号为核心标识，包含业主姓名、房号、缴费状态、报修类型、服务记录等字段，部分营销配套文档包含户型图、收费标准表等结构化或半结构化内容，字段单位多为栋/单元/室、元、小时等。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散于多个内部系统，要求工作流需配置多源API对接节点，整合不同系统的业务数据。不同数据的更新节奏差异，要求工作流需支持定时触发与手动触发两种模式，适配定期批量生成营销内容与临时针对特定楼栋的营销需求。以房号为核心的字段结构，要求变量引用需严格绑定房号标识，避免出现业主数据张冠李戴的问题。营销配套文档包含结构化表格与图片，要求工作流的文件处理节点需适配多格式文件的解析与拆分。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 物业常用的业主名单、营销海报、公告文档等单文件大小通常不超过该阈值 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 包含多页结构化表格的物业文档，解析耗时通常在该区间内 |
| `workflow_trigger_mode` | 定时+手动触发 | 适配月度缴费通知批量生成、临时楼栋活动通知手动触发的双重需求 |
| `variable_reference_rule` | 按房号+业主ID绑定 | 匹配物业数据以房号为核心的标识规则，降低变量引用错误概率 |
| `API_PLUGIN_REQUEST_TIMEOUT` | 60 秒 | 对接物业内部系统的接口响应时长通常在该范围内，避免请求超时中断流程 |
| `file_parse_chunk_size` | 800-1200 字符 | 适配物业文档的常规段落长度，保证营销内容生成的连贯性与可读性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为调用API插件传递文件类型变量时返回参数格式错误，原因是未按`file`字段类型封装二进制流或文件路径，未匹配插件要求的参数键名。
- 现象为工作流上传文件时提示`Failed to create post presigned url`，原因是4.14.0版本中存储桶配置的跨域规则未允许工作流域名，或存储配额不足。
- 现象为知识库搜索模块返回的营销内容未匹配目标业主，原因是未按房号字段绑定搜索变量，导致变量赋值为空或与目标业主不匹配。

## 怎么确认配好了
- 手动触发工作流上传一份物业常用的业主名单Excel，检查文件解析结果是否包含正确的房号、缴费状态字段。
- 调用测试API传递符合格式的文件参数，查看返回的响应状态码是否为200，无参数校验类报错。
- 查看工作流运行日志，确认`Failed to create post presigned url`类报错已消失，存储配额使用状态正常。
- 触发一次定时工作流，检查生成的营销内容是否正确引用了对应楼栋的业主数据与业务信息。
