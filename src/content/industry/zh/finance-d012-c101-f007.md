# 物流营销内容的工作流编排

## 这个品类的数据长什么样
物流营销内容关联的数据主要来自合作物流企业的运单系统、配送轨迹接口、客户收货反馈同步渠道，由金融机构通过API对接获取。数据更新节奏分为两类：运单基础信息每日批量同步，配送时效、异常状态实时推送。单条数据文档结构包含运单编号、货主联系方式、配送网点编码、当前时效节点、异常类型标识、货物重量等字段，单位涵盖小时、千米、千克等物理计量单位，部分字段存在枚举值约束，如异常类型仅支持延迟、丢件、破损等固定选项。

## 这些特征在「工作流编排」这一环带来什么约束
实时配送数据的更新频率要求工作流触发间隔不超过预设阈值，否则无法匹配最新物流状态生成针对性营销内容。枚举字段的约束要求工作流中大模型节点需绑定固定枚举值校验规则，避免生成不符合业务规范的营销文案。批量运单数据的体量要求工作流支持批量节点并发处理，同时需配置字段映射规则，兼容不同物流企业的字段差异。此外，物流数据包含货主隐私信息，要求工作流中需添加数据脱敏节点，隐藏货主完整联系方式等敏感内容，符合金融行业数据合规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `batchConcurrency` | `10-20 并发线程` | 物流批量运单数据的单条处理耗时较短，并发数过高会触发平台限流 |
| `nodeTimeout` | `300 秒` | 物流数据脱敏、字段映射环节的处理时长通常在2分钟以内，超时会导致节点失败 |
| `fieldMappingEnable` | `开启` | 不同物流企业的字段命名存在差异，开启后可统一映射为标准化字段 |
| `dataDesensitizationSwitch` | `开启` | 物流数据包含货主隐私信息，需隐藏手机号后四位以外的内容 |
| `errorRetryCount` | `2 次` | 部分网关临时断开会导致节点报错，重试可降低失败率 |
| `maxContext` | `前 8000 字符` | 物流数据字段较多，需限定上下文长度避免超出模型窗口 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：大模型节点生成的营销内容混入无关历史对话信息。原因：未配置`maxContext`参数限定仅加载当前物流数据上下文，默认调用了全局对话缓存。
- 现象：大模型节点运行后返回`500 Gateway forwarding error because service is disconnected`报错。原因：未设置`errorRetryCount`参数，且未校验物流数据源接口的连通状态，网关断开时未自动恢复。
- 现象：FastGPT 4.14.3版本中，工作流编辑器内模型节点图标不显示，文件上传节点提示网络错误。原因：未更新本地缓存或未正确部署对应版本的前端静态资源，导致资源加载失败。

## 怎么确认配好了
- 触发单条物流数据的工作流运行，核对输出内容是否仅包含当前输入的物流数据相关信息，无额外历史对话内容，符合数据合规要求。
- 运行批量运单处理节点，查看运行日志，确认并发执行的线程数符合预设配置，无串行执行的记录。
- 查看节点报错日志，确认未出现`500 Gateway forwarding error`相关报错，或重试逻辑已正常触发。
- 检查字段映射配置与数据脱敏节点，确认不同物流企业的自定义字段已被映射为标准化字段，敏感信息已完成脱敏处理。
