# 物流营销内容的文档解析与分块

## 这个品类的数据长什么样
物流营销内容的文档来源包括面向物流企业的金融营销话术库、区域配送价目表、运单模板、时效说明文档、合作承运商的合规文件等。更新节奏随业务调整，配送价目表按月更新，营销话术随促销活动按需更新。文档结构包含结构化表格、长文本说明、带动态占位符的模板文件，字段包含始发地、目的地、重量、体积、收费标准、时效周期等，单位多采用千克、元、公里、小时等通用物流计量标准。

## 这些特征在「文档解析与分块」这一环带来什么约束
结构化表格类文档若采用常规纯文本分块，会拆分单元格内的关联数据，导致价目表、时效表格的逻辑断裂，无法支持精准检索；长文本话术库存在大量场景化重复段落，无明确段落分隔时易出现块内内容混杂，降低检索召回的针对性；带动态占位符的模板文件，若解析时固化占位字段，会导致后续业务调用无法适配动态参数，无法复用模板内容；高频更新的文档若采用全量解析，会浪费计算资源，无法适配快速迭代的业务需求；计量字段附带的单位若与数值分离，会导致检索时无法精准匹配区域、重量等关联条件，影响营销内容的精准推送。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_TABLE_STRUCTURE` | 开启 | 物流营销文档包含大量价目表、时效表格，保留表格结构可避免数据关联断裂 |
| `CHUNK_SIZE` | 800–1200 字符 | 物流文档包含长文本话术与结构化表格，该区间可平衡内容完整性与检索精度 |
| `PARSE_INCREMENTAL_ENABLE` | 开启 | 物流配送价目表、时效文档高频更新，增量解析可减少重复计算资源消耗 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 物流营销文档常包含多页合规文件与批量价目表，该阈值可覆盖常规上传需求 |
| `PARSE_KEEP_PLACEHOLDER` | 开启 | 物流运单模板、活动通知包含动态占位字段，保留占位符可确保后续调用时的参数完整性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型批量文档解析需较长处理周期，该时长可避免中途中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为对话框上传文件后无解析进度反馈，后台无报错日志。原因是未配置`PARSE_FILE_TIMEOUT_SECONDS`参数，使用默认短超时值，大型批量物流文档未完成解析即被终止。
- 现象为启用PDF解析功能后，服务器内存占用骤增，触发资源限制告警。原因是未设置`UPLOAD_FILE_MAX_SIZE`阈值，上传了包含多页附件的物流合规文件，未启用增量解析导致全量加载解析。
- 现象为通过API上传文件后，知识库分块未保留运单模板中的动态占位字段。原因是未开启`PARSE_KEEP_PLACEHOLDER`参数，解析时自动固化了占位字段的默认值，导致后续业务调用无法适配动态参数。

## 怎么确认配好了
- 上传一份包含结构化价目表的测试文档，查看解析后的分块是否保留完整的表格结构，核对分块内容是否包含完整的收费标准与计量单位。
- 查看系统参数配置页面，确认`PARSE_INCREMENTAL_ENABLE`与`PARSE_KEEP_PLACEHOLDER`的开关状态与预设配置一致。
- 上传单份不超过预设`UPLOAD_FILE_MAX_SIZE`阈值的文档，验证解析进度条是否正常加载，无超时中断情况。
- 调用知识库查询接口，检索文档中的动态占位字段，确认分块内容中保留了原始占位符，未替换为固化值。
