# 环境监测营销内容的表单与交互

## 这个品类的数据长什么样
环境监测数据主要来自固定站点传感器、移动监测设备、卫星遥感平台及手持采集终端。更新节奏：固定站点传感器按1-5分钟频次上传实时数据，移动监测设备随采集动作即时上传，卫星遥感数据按日或按旬更新。文档结构：单条数据包含设备唯一标识、采集时间戳、监测因子名称、对应数值、单位及监测点经纬度；批量数据多以CSV或JSON格式打包，包含多组时序记录。字段与单位：监测因子涵盖PM2.5、SO₂、噪声等，对应单位为μg/m³、dB(A)等，所有数值绑定明确计量单位，包含地理位置与时间戳关联字段。

## 这些特征在「表单与交互」这一环带来什么约束
环境监测数据的时序性、多因子属性及单位绑定要求，为表单与交互环节带来特定约束。需支持多因子字段的动态配置，适配不同监测场景；需针对带单位的数值字段配置范围校验，过滤无效输入；需支持地理位置绑定与经纬度格式校验，确保数据空间关联准确；需适配批量数据提交场景，减少单条提交的重复操作；需统一时间戳格式，保障后续数据解析与入库的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_ALLOWED_EXT` | `["csv", "json", "xlsx"]` | 环境监测批量数据的主流存储格式 |
| `BATCH_SUBMIT_MAX_COUNT` | `500 条/次` | 平衡单次提交效率与系统处理负载 |
| `FORM_FIELD_VALIDATION_RULE` | 按监测因子配置对应数值范围 | 匹配环境监测的常规数值区间，过滤无效输入 |
| `LOCATION_PICKER_ENABLE` | 开启 | 绑定监测点的精准地理位置信息 |
| `TIMESTAMP_FORMAT` | `ISO 8601 格式` | 统一数据解析的时间格式标准 |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | 适配批量监测数据的合理文件大小 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：表单提交的批量监测数据文件上传后返回`413 Request Entity Too Large`错误。原因：未调整`UPLOAD_FILE_MAX_SIZE`参数，上传的文件大小超过系统默认限制。
- 现象：调用表单提交后的回调接口时，选择`stream: true`参数后无法获取完整解析结果。原因：未在接口配置中启用流式响应的完整接收逻辑，仅获取了单次返回的片段数据。
- 现象：表单内的监测因子数值字段提交后未被系统收录。原因：未配置对应因子的`FORM_FIELD_VALIDATION_RULE`，用户输入的数值超出预设的合理范围被自动过滤。

## 怎么确认配好了
- 上传符合预设格式的小型测试文件，检查文件是否能正常解析入库，核对解析后的字段与模板是否一致。
- 调用表单提交的回调接口并传入`stream: true`参数，检查是否能获取到完整的解析结果数据。
- 输入超出常规范围的监测数值，检查系统是否会触发对应的校验提示。
- 启用地图选点功能，尝试绑定模拟监测点的经纬度信息，检查是否能正确保存位置数据。
