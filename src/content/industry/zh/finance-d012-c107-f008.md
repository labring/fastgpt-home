# 电力营销内容的工具调用与插件

## 这个品类的数据长什么样
电力营销相关数据主要来源于用电采集终端、电力营销业务系统、客户服务工单及官方电价政策文档。用电采集数据为准实时更新，每15分钟同步一次最新用电量；营销活动数据随活动周期更新，包含投放进度、触达人群标签等字段；政策文档多为PDF或Word格式，包含电价调整、惠民活动细则等内容。数据字段包含唯一用户标识、用电时段、用电量（单位为千瓦时）、缴费状态、活动ID、投放渠道等，部分字段仅在电力场景下存在，无通用业务字段的直接对应项。

## 这些特征在「工具调用与插件」这一环带来什么约束
准实时的用电采集数据要求工具调用设置合理的超时阈值，避免因数据同步延迟导致调用失败。多字段且带专属单位的业务数据，需要插件支持自定义字段映射与单位校验，否则无法正确识别与处理电力专属数据。长文档类的政策文件需要插件支持分段解析，否则会出现内容截断或解析失败。唯一用户标识字段的存在，要求工具调用时必须校验必填字段的完整性，否则无法完成精准的营销内容匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatCompletionTimeout` | 600 秒 | 电力营销数据包含准实时用电采集内容，数据同步存在一定延迟，需放宽超时限制 |
| `pluginCustomFieldMap` | 按「用户ID|用电时段|用电量（千瓦时）」映射 | 电力营销数据字段与通用业务字段差异显著，需自定义映射匹配专属字段 |
| `maxPluginRetries` | 3 次 | 实时用电数据可能因终端离线偶发调用失败，需设置合理重试次数保障调用成功率 |
| `pluginParseChunkSize` | 800–1200 字符 | 电力营销政策文档篇幅较长，拆分至该区间可保证解析完整性与效率 |
| `pluginAllowCustomUnit` | 开启 | 电力数据包含千瓦时、人次等专属单位，需支持自定义单位校验避免识别错误 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用`/api/v1/chat/completions`时返回`400 Bad Request`，提示缺失必填字段。原因：未正确配置`pluginCustomFieldMap`，未将电力专属字段传入请求体。
- 现象：工具调用返回结果为空，且系统日志显示`unit not supported`。原因：未开启`pluginAllowCustomUnit`，导致电力数据的千瓦时单位无法被插件识别。
- 现象：前端直接调用接口后出现超时报错，页面加载无响应。原因：未设置`chatCompletionTimeout`为合理时长，准实时用电数据采集未在默认超时时间内返回。

## 怎么确认配好了
- 发起测试调用，传入包含用户ID、用电时段、用电量（千瓦时）的测试数据，检查接口返回是否正确映射配置的专属字段。
- 上传一份电力营销政策PDF文档，检查插件解析结果是否按`pluginParseChunkSize`的设置拆分，无内容截断或丢失。
- 模拟终端离线场景发起调用，检查是否触发`maxPluginRetries`的重试机制，最终返回有效业务结果。
- 查看系统运行日志，确认无`unit not supported`或`missing required field`类的报错信息。
