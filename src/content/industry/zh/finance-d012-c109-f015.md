# 电子元件营销内容的部署与升级

## 这个品类的数据长什么样
电子元件营销内容的数据主要来自原厂官方 datasheet、授权分销商库存数据库、多数行业通用的元器件手册与项目级BOM清单。数据更新节奏分为两类：原厂技术文档更新周期较长，库存与项目适配数据每日或按需更新。单条数据包含封装类型、额定电压、工作温度范围、引脚间距、阻值/容值等字段，多数字段带有明确物理单位，文档格式以PDF datasheet、CSV库存清单、结构化JSON格式为主。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的数据格式要求部署阶段配置多格式解析插件，适配PDF datasheet、CSV库存清单与JSON结构化数据的解析逻辑。带物理单位的字段，需要在向量入库时保留单位信息，避免语义混淆导致召回偏差。实时更新的库存数据要求配置增量同步机制，降低部署阶段的资源消耗。营销内容需匹配元件参数与下游应用场景，因此部署时需限定召回片段的字段范围，避免无关参数干扰内容生成。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 电子元件原厂datasheet通常页数较多，解析耗时高于通用文档 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 电子元件库存清单、多份datasheet合集的体积通常较大 |
| `分段长度` | `800–1200 字符` | 电子元件参数描述包含单位与技术细节，分段过长会破坏语义完整性 |
| `相似度阈值` | `0.75–0.85` | 需精准匹配元件参数与用户查询，阈值过低会引入无关内容 |
| `重排返回条数` | `前 5 条` | 电子元件营销内容需聚焦核心参数，过多召回会稀释内容针对性 |
| `SYNC_INCREMENTAL` | `开启` | 电子元件库存数据需实时更新，增量同步可降低部署资源消耗 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 启动容器后执行初始化脚本报错，控制台返回`exit code 1`，原因是升级版本（如4.8.18到4.8.20）时未清理旧版挂载的配置文件，导致新老配置冲突。
- 调用检索接口返回`0 条召回结果`，无法检索到历史配置的知识库，原因是未开启字段保留单位的配置，导致带物理单位的参数字段语义被破坏，无法匹配用户查询。
- 检索外部营销素材时返回`无搜索结果`，关联后台返回`500 内部错误`，原因是使用的外部搜索镜像未配置正确的访问节点，导致无法获取元器件行业相关素材。

## 怎么确认配好了
- 上传一份电子元件datasheet，查看解析日志，确认未触发`PARSE_FILE_TIMEOUT_SECONDS`配置的超时限制。
- 发起包含元件参数与对应物理单位的查询，核对召回结果的字段是否保留了原始单位信息。
- 启动增量同步任务，查看同步日志，确认仅同步了新增或更新的数据，未全量重同步所有库存数据。
- 完成版本升级后，检查容器内的配置文件与官方发布的默认配置是否一致，避免自定义配置引发冲突。
