# 白酒营销内容的HTTP 接口与外部系统

## 这个品类的数据长什么样
金融场景下的白酒营销内容数据，主要来自品牌官方渠道、合作酒企的专属素材库、金融机构私行客户的反馈标签三类。更新节奏随金融营销节点波动，季度理财沙龙、高端客户答谢会前会集中更新，日常维护以月度为周期。文档类型涵盖长文本品鉴笔记、短文案海报配文、线下活动邀约话术三类，结构包含基础产品属性字段与金融场景适配标签。专属字段包括`alcohol_content`（单位%vol）、`product_volume`（单位mL）、`flavor_type`，部分素材还包含适配私行客户的品鉴活动场次与对接专员信息。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多渠道来源要求接口需支持对接品牌方、合作酒企、金融机构内部素材库三类外部端点，避免遗漏适配金融场景的专属素材。波动式更新节奏要求接口具备弹性并发能力，高端客户答谢会高峰时段需临时调整请求阈值。专属字段与单位要求接口返回数据需严格匹配预设格式，否则会导致金融系统内的客户标签解析失败。金融合规性要求则要求在推送至外部系统前，需额外对接金融广告合规校验接口，过滤违规宣传内容。同时，线下活动的邀约信息需要对接金融机构的短信推送接口，要求外部系统支持模板化消息生成与发送。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `external_data_source_type` | `multi_endpoint` | 金融场景下的白酒营销数据来自品牌方、合作酒企、金融机构内部素材库三类渠道，需同时对接多端点接口 |
| `api_batch_request_limit` | `12` | 高端客户答谢会批量拉取素材时，12条单次请求可平衡接口性能与外部系统限流风险 |
| `field_mapping_rules` | `{"alcohol_content": "%vol", "product_volume": "mL"}` | 匹配白酒专属字段的单位格式，避免金融系统内客户标签解析出现单位不统一的问题 |
| `external_request_timeout` | `28 秒` | 适配多渠道拉取的延迟情况，预留足够响应时间完成金融场景适配的素材获取 |
| `content_compliance_trigger` | `before_push` | 金融场景下的白酒营销内容受广告法规与金融监管约束，需在推送至外部系统前完成合规校验 |
| `temp_file_storage_expiry` | `7 天` | 线下品鉴活动的临时物料存储时长，匹配金融机构季度营销活动的周期 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：接口返回`429 Too Many Requests`状态码。原因：未配置`api_batch_request_limit`参数，高端客户答谢会高峰时段短时间内发起过多批量请求，触发外部系统限流。
- 现象：金融系统内的客户标签字段为空。原因：未配置`field_mapping_rules`参数，接口返回的白酒专属字段未正确映射至金融系统内部字段，导致解析遗漏。
- 现象：合规校验接口返回`400 Bad Request`报错。原因：未开启`content_compliance_trigger`配置，违规宣传功效的白酒营销文案未被拦截，直接推送至金融机构的客户推送系统触发校验失败。

## 怎么确认配好了
- 发起单次拉取请求，检查返回数据中包含`alcohol_content`、`flavor_type`等白酒专属字段，且单位符合预设规则。
- 模拟5次批量拉取请求，查看接口返回的状态码均为`200 OK`，无限流相关报错。
- 上传一条含“治病”“保健”违规表述的白酒营销文案，确认系统触发合规校验并返回拦截提示。
- 查看金融机构的客户推送日志，确认临时物料的存储时长与`temp_file_storage_expiry`参数匹配。
