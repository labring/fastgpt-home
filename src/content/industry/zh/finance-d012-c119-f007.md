# 综合服务营销内容的工作流编排

## 这个品类的数据长什么样
综合服务营销内容的数据主要来自客户核心业务系统、营销触点后台及客户行为日志。数据源包含客户身份标识、服务等级、过往营销触达记录、理财持仓数据等字段。数据更新节奏为准实时，每日同步频次不低于12次，部分实时触发的营销场景数据更新间隔不超过5分钟。文档结构以结构化表格为主，单条数据字段不超过20个，字段单位包含次、元、条等，无嵌套层级过深的非结构化内容。

## 这些特征在「工作流编排」这一环带来什么约束
由于综合服务的数据来自多系统且需准实时同步，工作流需配置跨系统数据拉取节点，确保每个分支调用的数据源一致，这与单一品类营销内容的工作流存在差异。准实时的更新节奏要求工作流触发模式需匹配数据更新间隔，避免因触发频率过高导致数据未完成同步。结构化字段较多的特征要求工作流需配置字段映射规则，将业务系统字段转换为营销内容生成所需的变量。同时，营销内容需基于客户个性化字段生成，工作流需支持按字段值触发不同内容分支，适配分层运营需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `workflow_trigger_interval` | `10–30 秒` | 匹配综合服务准实时的数据更新节奏，避免因触发间隔过长导致营销内容滞后 |
| `tool_call_max_concurrent` | `5–10 并发` | 适配综合服务多客户并行生成营销内容的需求，避免资源过载导致执行失败 |
| `output_html_escape` | `false` | 允许直接输出原生HTML代码，满足营销内容的自定义展示需求 |
| `branch_trigger_field` | `customer_service_level` | 按客户服务等级触发不同营销内容分支，适配综合服务的分层运营需求 |
| `workflow_timeout` | `600 秒` | 预留足够时间完成多工具调用及营销内容生成，避免因执行超时中断流程 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流执行后未渲染HTML代码，直接进入下一分支。原因是未关闭`output_content_escape`配置，导致HTML标签被转义为纯文本，前端无法识别展示。
- 现象为工作流执行速度过慢，返回`504 Gateway Timeout`状态码。原因是未设置合理的`workflow_timeout`参数，且未开启并行工具调用配置，串行执行多节点任务导致耗时过长。
- 现象为工具调用后的回答中包含知识库搜索的input和response字段。原因是未配置`disable_knowledge_ref`参数，或未在工作流节点中关闭知识库召回开关，导致冗余内容被混入最终输出。

## 怎么确认配好了
- 触发测试工作流，查看输出节点的执行日志，确认输出内容为未转义的原生HTML代码，可直接在前端页面渲染展示。
- 模拟多客户并发触发工作流，查看系统监控面板，确认并发执行的工作流数量未超过配置的`tool_call_max_concurrent`阈值。
- 执行工具调用节点，查看最终输出的回答内容，确认未出现知识库搜索相关的input和response字段。
- 触发工作流后查看执行耗时日志，确认总耗时未超过配置的`workflow_timeout`参数值。
