# 综合服务营销内容的部署与升级

## 这个品类的数据长什么样
综合服务类营销内容的数据主要来源于内部客户管理系统、合规备案的金融产品信息库、过往客服咨询文本及官方营销素材库。数据更新分为常规周度迭代与紧急合规变更两种场景，常规更新频率为每周一次，紧急变更需在24小时内同步。文档以结构化表单为主，包含产品名称、合规备案编号、适用客群范围、营销话术文本、风险提示字段，单位多采用字符数、文件大小（MB）、备案编号格式等标准化标识。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据包含合规备案字段与敏感客户信息，部署环节需严格校验必填字段的完整性，避免未备案内容流入营销场景。紧急合规变更的高频需求，要求升级流程支持无停服热更新，避免影响实时营销内容调用。结构化字段多且更新频率差异大，需配置差异化的召回优先级与缓存策略，确保合规信息优先被检索。同时，数据存储依赖云数据库实例，部署时需配置正确的网络访问权限，防止数据库连接异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_WHITELIST_IPS` | `部署节点公网IP + 容器内网网段172.17.0.0/16` | 确保容器内服务与阿里云RDS实例正常通信，同时符合云服务商的安全访问规范 |
| `CONFIG_FILE_ENABLE` | `v4.8.20及以上版本设为false` | 新版本采用环境变量配置替代本地配置文件，简化部署流程，避免文件权限与版本兼容问题 |
| `PARSE_MARKDOWN_TIMEOUT` | `300 秒` | 综合服务营销素材通常包含多段合规文本与长文档，解析耗时较长，避免超时中断任务 |
| `RECALL_TOP_K` | `前 8 条` | 综合服务营销内容需覆盖多维度产品信息，适量召回确保内容全面且不超出展示阈值 |
| `MAX_CONTENT_LENGTH` | `1200 字符` | 金融营销内容需包含合规提示，过长文本会影响检索效率与合规展示效果 |
| `DOCKER_IMAGE_TAG` | `4.8.20` 或对应稳定版标签 | 确保使用经过验证的功能版本，避免未知bug与兼容性问题 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 连接阿里云RDS时提示权限被拒绝，日志显示连接失败。原因是未将部署节点的公网IP或容器内网网段添加至RDS实例的白名单配置中。
- 升级至v4.8.20后仍出现config.json读取报错。原因是未将`CONFIG_FILE_ENABLE`环境变量设为false，新版本默认保留了旧配置文件的读取逻辑，需手动关闭该配置项。
- docker部署后版本未更新至4.8.20，查看镜像标签仍为旧版。原因是拉取镜像时未指定准确的版本标签，默认拉取了缓存的旧镜像，需在拉取命令中指定对应版本。

## 怎么确认配好了
- 执行数据库连接测试命令，查看返回结果是否包含配置的数据库实例信息，确认白名单配置生效。
- 查看系统日志，确认无config.json相关的读取报错，验证环境变量配置是否正确。
- 上传一份合规营销素材，查看解析任务的状态是否为成功，确认超时与长度配置符合要求。
- 发起一次营销内容召回请求，核对返回的结果条数与配置的`RECALL_TOP_K`参数一致。
