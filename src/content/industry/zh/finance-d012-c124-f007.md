# 自动化设备营销内容的工作流编排

## 这个品类的数据长什么样
数据来源为工业PLC采集模块、生产执行系统（MES）、营销物料投放后台；更新频率为每1至5分钟一次；文档结构以结构化表格或JSON格式为主，包含设备唯一标识、累计运行时长（单位：小时）、实时产能（单位：件/分钟）、单次营销物料的曝光次数（单位：次）、点击次数（单位：次）、转化订单数（单位：单）等字段，部分设备还会附带故障代码，以无单位的数字编码形式记录。

## 这些特征在「工作流编排」这一环带来什么约束
数据更新频率较高，要求工作流的触发间隔不超过1至5分钟的周期，否则将使用过时的设备或营销数据生成内容，导致信息滞后。数据包含多种类型字段，包括数值型、编码型，要求工作流的变量映射环节需明确指定字段类型，避免类型不匹配引发的报错。营销数据与设备数据需通过设备唯一标识绑定，要求工作流中配置关联逻辑，确保生成的营销内容匹配对应设备的投放场景。部分字段为数字编码的故障信息，要求工作流增加编码映射节点，将数字代码转换为可读文本，适配营销内容的展示需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `trigger_interval` | `1-4 分钟` | 匹配自动化设备数据的更新周期，避免使用过时数据 |
| `variable_cast_mode` | `强制类型转换` | 设备数据包含数值型、编码型字段，避免类型不匹配导致内容生成错误 |
| `association_field` | `设备ID` | 绑定设备与对应营销物料的投放数据，确保营销内容匹配对应设备场景 |
| `encoding_convert_switch` | `开启` | 设备故障代码为数字编码，需转换为可读文本用于营销内容 |
| `http_timeout` | `10 秒` | 单HTTP请求耗时约3秒，预留足够超时时间避免中途中断 |
| `max_workflow_runtime` | `30 秒` | 工作流包含HTTP请求、变量映射、内容生成环节，总耗时需控制在合理范围 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：在营销内容的body中引用设备数据变量时，生成内容未显示对应字段值。原因：未将设备数据的字段正确映射到工作流的变量节点，或变量引用格式不符合系统要求。
- 现象：工具调用环节直接报错，返回`504 Gateway Timeout`或`400 Bad Request`状态码。原因：未设置合理的HTTP请求超时时间，或请求参数未匹配设备数据的字段格式，导致调用失败。
- 现象：全局变量设置初始值后，运行工作流时变量未随设备数据更新。原因：未开启全局变量的实时同步配置，或触发逻辑未绑定数据更新事件，导致变量无法刷新。

## 怎么确认配好了
- 手动触发一次工作流，检查生成的营销内容是否包含正确的设备数据字段值，确认变量引用生效。
- 查看工作流的运行日志，确认HTTP请求的返回状态码为`200 OK`，无超时或参数错误提示。
- 等待10分钟后再次触发工作流，检查全局变量是否更新为最新的设备数据，确认变量同步正常。
- 模拟故障代码输入，检查编码转换模块是否将数字代码转换为可读的故障说明文本，确认类型映射正确。
