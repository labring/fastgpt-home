# 自动化设备营销内容的部署与升级

## 这个品类的数据长什么样
自动化设备的营销关联数据主要来源于工业物联网网关、设备本地PLC日志、客户现场的工况采集系统。实时工况数据每1至5秒更新一次，包含设备SN码、运行温度（℃）、工作压力（MPa）、主轴转速（r/min）、在线状态等字段。设备营销素材如参数手册、工况案例视频按季度更新，告警日志随设备异常事件触发更新。单条数据结构包含唯一设备标识、参数组、关联素材ID与更新时间戳，支持多模态数据混合存储。

## 这些特征在「部署与升级」这一环带来什么约束
实时工况数据的高频更新要求部署时需适配低延迟的向量入库流程，避免数据积压。多模态营销素材的体积差异要求上传配置需支持大文件阈值调整。设备SN码作为唯一标识，要求部署时需配置向量库的主键映射规则，确保数据与营销素材的精准关联。升级过程中需兼容旧版设备数据的格式，避免因字段变更导致历史数据无法召回。同时，金融行业的设备数据敏感性要求部署时需同步配置数据加密与访问权限规则，升级时需同步更新加密策略。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 自动化设备的高清工况视频、大型参数手册体积较大，需适配大文件上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 多模态营销素材解析耗时较长，避免因超时导致解析失败 |
| `VECTOR_STORE_BATCH_SIZE` | `50–100` | 适配高频更新的设备工况数据批量入库，平衡入库效率与系统负载 |
| `recall_top_k` | `10–15` | 设备营销内容需结合精准工况参数，过多会导致内容冗余，过少无法覆盖业务需求 |
| `similarity_threshold` | `0.75–0.85` | 设备参数匹配精度要求较高，过低会引入无关营销素材，过高会导致召回不足 |
| `DB_CONNECTION_TIMEOUT` | `60 秒` | 物联网数据库可能存在网络波动，需合理设置连接超时时间 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：部署后出现`2003 Can't connect to MySQL server on '127.0.0.1:3306'`报错，无法加载设备工况数据。原因：未在`docker-compose.yml`中正确配置`MYSQL_HOST`、`MYSQL_PORT`参数，或本地防火墙阻断了数据库通信端口。
- 现象：配置`OPENAI_BASE_URL`时输入错误端口号，仍可正常生成设备营销内容。原因：未开启代理的端口合法性校验，或上游反向代理未强制校验目标服务端口。
- 现象：在v4.8.7版本中，单台设备的工况数据无法关联多组营销素材向量，仅能绑定一个向量模型。原因：未在知识库设置中开启“多向量关联”开关，或未配置向量库的分组映射规则。

## 怎么确认配好了
- 上传一份自动化设备的参数手册，检查解析后的文本是否包含设备SN码、运行参数的字段与单位，确认上传配置生效。
- 模拟批量上传设备工况数据，查看向量入库日志的批量处理记录，确认入库批量大小符合预期配置。
- 发起一次设备营销内容的召回请求，查看返回结果的相似度得分，调整阈值至符合业务需求的区间。
- 执行`docker ps`命令，确认当前运行的镜像版本与`docker-compose.yml`中配置的版本一致，确认升级部署生效。
