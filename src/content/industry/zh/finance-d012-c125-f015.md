# 航天装备营销内容的部署与升级

## 这个品类的数据长什么样
航天装备营销内容的数据主要来自公开的型号参数手册、发射任务通稿、官方宣传海报、装备三视图文档及试验录像素材。数据更新无固定周期，仅在新列装型号发布、重大试验成功或年度性能优化时触发更新。文档结构以长PDF手册、结构化参数表格为主，同时包含大量高清图片与短格式宣传文案。字段多为技术参数类，包含推力、轨道高度、发射窗口等，单位多采用kN、km、秒等国际通用航天计量标准。

## 这些特征在「部署与升级」这一环带来什么约束
长文档占比高的特征要求部署时放宽解析超时限制，避免大型手册解析中断。结构化参数多的特征要求精准配置召回规则，避免泛化召回导致的信息冗余。图片素材占比高的特征要求开启OCR解析配置，确保图片内的参数文字可被检索。无固定更新周期的特征要求升级时支持增量同步模式，减少全量更新的资源消耗。大体积单文件的特征要求调整上传文件大小上限，适配型号手册合集的存储需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 航天装备营销文档多为数十页的PDF手册，解析耗时远超通用场景 |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | 单份型号手册合集文件体积可能超过常规阈值 |
| `分段长度` | 1500–2000 字符 | 技术参数描述多为长句，分段过短会破坏参数关联性 |
| `召回条数` | 前 8–10 条 | 营销内容需覆盖性能、用途、发射流程等多维度信息，过少会遗漏关键内容 |
| `相似度阈值` | 0.75–0.85 | 航天装备参数精准度要求高，阈值过低会引入无关的非官方资料 |
| `IMAGE_OCR_ENABLE` | 开启 | 营销物料包含装备三视图、发射场景截图，需提取图片内文字信息 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 启动时出现`MongoServerError: The dollar ($) prefix is not allowed in field names`报错，原因是v4.13.0版本中使用的插件语法与MongoDB 4.4.29版本的字段命名规则不兼容，未适配低版本MongoDB的限制。
- 跨实例导入知识库后，原多文件分类丢失，仅生成单个CSV文件，原因是备份导出时未启用分卷存储配置，仅导出为单文件格式。
- 部分文档无法识别内嵌图片，原因是v4.15.1版本中未开启`IMAGE_OCR_ENABLE`配置，或索引模型未适配图片解析场景。

## 怎么确认配好了
- 上传一份标准航天装备营销手册，检查解析任务的完成状态，确认耗时符合配置的超时阈值。
- 发起针对装备参数的查询，核对召回结果的字段完整性与单位准确性。
- 导出当前知识库备份，检查文件格式是否符合预期，确认分卷存储或单文件配置生效。
- 上传包含装备三视图的图片文档，确认OCR提取的文字内容完整无误。
- 发起针对OneAPI接口的测试调用，确认接口调用逻辑符合配置要求，无代理配置错误。
