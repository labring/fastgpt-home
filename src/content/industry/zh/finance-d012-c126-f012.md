# 航空机场营销内容的模型接入与配置

## 这个品类的数据长什么样
航空机场的营销内容数据主要来自机场运营管理系统、航班调度平台、航站楼导览数据库及商户合作台账。数据更新节奏因类型不同：航班时刻数据每15分钟同步一次，商户促销信息每日更新，航站楼设施调整信息每周更新。单条数据文档包含航班号、起降时间、航站楼编号、商户名称、服务品类、客流峰值时段等字段，字段单位统一为标准时间格式、数字编号、中文品类名称。

## 这些特征在「模型接入与配置」这一环带来什么约束
航空机场的数据特征对模型接入与配置带来多重约束。航班时刻数据每15分钟同步一次，要求数据源同步频率需匹配该节奏，否则生成的营销内容会出现信息滞后。多源异构数据包含航班、商户、客流等不同类型，需预先配置统一的字段映射规则，避免模型混淆不同数据的语义逻辑。客流峰值时段的区间型字段，要求模型支持非结构化时间区间的解析与适配。频繁更新的商户促销信息，需配置自动触发的知识库刷新机制，确保营销内容始终匹配最新的合作信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `6–10 轮对话 + 最近20条航班数据快照` | 航空机场营销需结合近期旅客咨询的航班信息，过多历史数据会增加模型负载并干扰输出准确性 |
| `DATA_SYNC_FREQUENCY` | `15 分钟` | 匹配航班时刻数据每15分钟的同步节奏，确保营销内容使用最新的航班信息 |
| `FIELD_MAPPING_RULE` | 固定映射格式：`航班号→flight_no, 起降时间→dep_arr_time, 航站楼→terminal_id` | 统一多源异构数据的字段格式，避免模型混淆不同数据的语义逻辑 |
| `PARSE_FILE_TIMEOUT` | `600 秒` | 机场营销文档包含长文本的航班时刻表、商户清单，需足够的解析时间完成内容拆分与结构化 |
| `RECALL_TOP_K` | `前5 条相关数据` | 航空机场营销内容需精准匹配旅客当前咨询的航班或设施信息，过多召回数据会干扰模型输出 |
| `IMAGE_SUPPORT` | `开启` | 航空机场营销内容包含航站楼导览图、商户门店图等素材，需模型支持图片理解以生成完整的营销内容 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为设置`maxContext`为6后，模型无法保留上一个问题的记忆。原因是仅配置了上下文轮数参数，未关联对话历史的存储与自动加载规则，导致模型无法获取过往会话数据。
- 现象为使用`ONE_API`调用通义千问时返回`500 内部服务错误`。原因是未配置正确的模型专属密钥，或未指定符合要求的模型接入地址，导致接口调用失败。
- 现象为修改工作流后，已发布的机场营销内容未同步更新。原因是未配置发布渠道的自动更新触发规则，仅修改本地工作流未同步到发布节点，导致渠道使用旧版本逻辑。

## 怎么确认配好了
- 手动触发一次数据源同步，查看同步日志的状态，核对同步后的数据字段是否匹配预设的映射规则。
- 发起包含航班咨询的测试对话，查看模型输出是否包含最新的航班信息，确认历史对话是否被正确加载。
- 解析机场营销文档，查看结构化后的字段是否符合预期，确认解析超时设置是否适配文档长度。
- 使用模型测试接口发起调用请求，查看返回结果是否正常，确认密钥与接入地址配置无误。
