# 航运港口营销内容的HTTP 接口与外部系统

## 这个品类的数据长什么样
航运港口的营销内容数据主要来自港口官方调度系统、货主货代对接台账、航线宣传物料库。数据更新节奏涵盖实时航线调整、每日货量播报、定期营销物料发布。文档结构包含结构化的航线运价、港口代码（遵循UN/LOCODE标准）等字段，以及非结构化的高清海报、宣传视频等物料。字段包含`PORT_CODE`、`ROUTE_NAME`、`QUOTED_PRICE`（单位为美元/TEU）、`UPDATE_TIMESTAMP`等，部分营销素材附带唯一标识`MATERIAL_ID`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
结构化数据需严格匹配UN/LOCODE等标准字段格式，接口需配置参数校验规则拦截非法格式请求。实时更新的营销数据要求接口支持定时拉取或webhook推送，适配高频数据同步需求。多格式混合的物料数据要求接口兼容multipart/form-data与JSON两种传输格式，同时支持大体积文件上传。批量货盘数据处理可能产生长耗时请求，需适配超过1200秒的执行时长，避免强制超时中断。内部系统对接需严格鉴权，防止敏感营销数据泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 航运港口营销物料常包含高清海报、宣传视频，单文件体积较大 |
| `API_REQUEST_TIMEOUT` | `1800 秒` | 批量处理货盘数据或长流程工作流执行可能超过1200秒，需适配长耗时场景 |
| `AUTH_TYPE` | `API_KEY + IP_WHITELIST` | 港口内部系统对接需严格鉴权，防止未授权访问敏感营销数据 |
| `PARSE_MULTIPART_FILE` | `启用` | 需支持用户上传的图片、PDF营销物料通过multipart/form-data格式传递 |
| `WEBHOOK_RETRY_COUNT` | `5 次` | 港口系统推送营销数据时可能因网络波动失败，需配置合理重试次数 |
| `REQUEST_BODY_ENCODING` | `UTF-8` | 港口数据包含中英文、特殊港口代码字符，需统一编码格式 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用API返回`413 Request Entity Too Large`状态码。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，超过默认限制导致大体积营销物料无法上传。
- 现象：工作流执行超时，界面显示`Task execution timed out`。原因：未将`API_REQUEST_TIMEOUT`配置调高，批量处理货盘数据时超过默认超时阈值。
- 现象：传递图片时接口接收字段为空。原因：未启用`PARSE_MULTIPART_FILE`配置，未以multipart/form-data格式传递文件，导致相对链接无法被正确解析。

## 怎么确认配好了
- 上传单个体积不超过2000MB的营销物料文件，检查接口返回状态码为200且文件解析成功。
- 发起批量货盘数据的API调用，等待超过1200秒后检查工作流是否正常完成，无超时报错。
- 配置IP白名单后，使用非授权IP发起调用，检查返回`403 Forbidden`状态码，授权IP调用正常。
- 上传图片文件并通过multipart/form-data格式提交，检查接口接收的文件字段不为空且可正常解析。
