# 装修装饰营销内容的多轮对话与提示词

## 这个品类的数据长什么样
装修装饰行业的营销内容数据主要来源于装修公司的项目归档档案、设计师方案库、区域建材报价系统与施工进度台账，部分数据来源于合作金融机构的装修贷客户需求台账。数据更新节奏随业务节点变动，新开工项目档案实时同步，建材报价每周更新一次，设计师方案库按新增创作频率迭代，金融客户需求台账按每日申请量更新。文档结构包含项目唯一标识、户型面积、装修风格、建材品牌型号、施工周期、预算明细、客户贷款额度意向等字段，单位涵盖平方米、元/平方米、自然日、万元等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
装修装饰行业的数据特征对多轮对话与提示词环节带来明确约束。项目档案与建材报价的实时性要求，需在多轮对话中优先调用最新数据源，避免生成过时的营销内容。多字段的文档结构要求提示词需明确指定提取与校验的字段范围，防止模型混淆不同业务维度的参数。用户咨询常围绕户型、预算、风格、贷款额度意向展开，多轮对话需按顺序收集前置信息，再结合对应维度生成匹配的营销物料，同时统一单位表述以避免歧义。同时需结合金融机构的合规要求，确保营销内容符合规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 装修装饰业务的上下文需包含户型、预算、风格等多维度信息，避免截断关键参数导致营销内容不匹配 |
| `召回条数` | `前6–8 条` | 需结合多轮对话的历史需求与过往生成的营销内容，过多会增加token消耗，影响响应速度 |
| `相似度阈值` | `0.75–0.85` | 精准匹配用户户型、风格相关的历史营销物料，过滤无关内容，提升营销内容的针对性 |
| `分段长度` | `1000–1500 字符` | 装修类文档（如建材清单、设计方案）篇幅较长，分段处理可提升提示词解析效率与召回准确性 |
| `systemPrompt` | `优先调用最新建材报价与项目数据，按用户提供的户型、预算生成匹配的营销内容，符合金融合规要求` | 明确模型的业务边界与数据调用规则，避免生成过时或不符合规范的内容 |
| `toolCallEnable` | `开启` | 需调用实时数据源接口获取最新建材报价与项目信息，支撑多轮对话的动态内容生成 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：多轮对话中单次交互无法同时发送两条营销内容消息，界面返回“消息数量超限”报错。原因：未配置`maxParallelMessages`参数，或取值设置为1，限制了单次交互的消息输出数量。
- 现象：微信渠道发送的Markdown格式消息保留了#、*等语法符号，未正确渲染为富文本。原因：未针对微信渠道配置`markdownRenderMode`参数，未启用渠道适配的格式转换规则。
- 现象：多轮对话的累计token消耗无法在界面查看，全局日志中无明确的token统计字段。原因：未启用`enableTokenStats`配置项，未开启全局token统计功能。

## 怎么确认配好了
- 进入对话调试界面，发起包含户型、预算、风格的多轮提问，检查对话上下文是否完整保留所有前置交互的关键信息。
- 触发包含工具调用的对话流程，查看日志是否正常获取并使用最新的建材报价与项目数据。
- 核对系统配置项的取值是否符合业务场景的需求，例如上下文窗口长度是否覆盖多轮对话的完整信息。
- 测试微信渠道的消息发送，确认Markdown格式的营销内容可正确渲染，无原始语法符号显示。
