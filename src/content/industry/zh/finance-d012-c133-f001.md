# 证券营销内容的HTTP 接口与外部系统

## 这个品类的数据长什么样
证券营销内容的数据来源为券商内部的产品管理模块、合规审核系统、营销活动管理平台。更新节奏存在差异：产品相关营销内容随产品发行、存续调整或合规修订更新，投教类营销内容按固定周期更新，活动类营销内容随营销活动上线与下线即时更新。文档结构包含固定合规字段与动态业务字段，字段包括合规审核编号、产品代码、风险等级、适用投资者适当性类型、发布日期，其中风险等级采用行业通用的R1至R5分级，产品代码为6位阿拉伯数字组成的标识，发布日期采用YYYY-MM-DD格式。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
证券营销内容的合规属性与字段格式要求，为HTTP接口与外部系统对接带来多重约束。首先需配置强制字段校验规则，拦截缺失合规审核编号、产品代码的请求；其次需实现参数格式校验，确保产品代码为6位数字、风险等级为R1至R5的枚举值；第三需适配不同更新节奏的业务需求，支持高并发实时同步接口与批量同步接口两种模式；最后需记录接口请求的来源、参数与结果，满足合规溯源的审计要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `REQUIRED_FIELDS` | `["compliance_id", "product_code", "risk_level"]` | 证券营销内容必须包含合规审核编号、产品代码、风险等级等强制合规字段，需在接口请求中校验必填 |
| `PARAMETER_VALIDATION_RULE` | `{"product_code": "^\\d{6}$", "risk_level": "^R[1-5]$"}` | 产品代码为6位阿拉伯数字，风险等级为R1至R5的枚举格式，需通过正则校验拦截非法参数 |
| `API_REQUEST_TIMEOUT` | `30 秒` | 证券营销内容的接口请求多为合规校验与数据同步，30秒可覆盖常规校验与批量数据传输的耗时 |
| `UPLOAD_FILE_MAX_SIZE` | `10 MB` | 单篇营销内容文档多为短文本或小幅图文，10 MB可满足批量上传需求且避免资源浪费 |
| `REQUEST_RATE_LIMIT` | `100 次/分钟` | 活动类营销内容的并发请求量适中，该阈值可平衡系统负载与业务需求 |
| `LOG_RECORD_ENABLE` | `开启` | 证券业务需合规溯源，需记录每一次接口请求的参数、来源与结果，用于后续审计 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用HTTP接口上传markdown格式的营销文档时返回`400 Bad Request`，或解析后核心字段（如`product_code`）为空。原因：未配置针对证券营销内容的必填字段校验规则，或未开启markdown文档的字段提取开关，导致合规要求的强制字段未被正确识别。
- 现象：通过HTTP接口对接外部合规系统时返回`500 Internal Server Error`，且日志显示请求体格式不匹配。原因：未按照证券营销内容的固定字段结构组装请求参数，错误省略了`compliance_id`字段，导致外部系统校验失败。
- 现象：配置批量同步营销内容的HTTP接口时，单次请求返回超时错误。原因：未设置合理的`API_REQUEST_TIMEOUT`参数，或未拆分批量请求为单条提交，导致单次请求数据量过大超出系统处理上限。

## 怎么确认配好了
- 发起包含全部强制合规字段的测试请求，核对接口返回的状态码与解析后的字段完整性，确认核心字段无缺失。
- 构造非法参数（如非6位数字的产品代码、超出R1-R5的风险等级），核对接口是否返回参数校验失败的提示。
- 模拟多并发请求，核对系统的请求速率限制是否生效，超出阈值的请求被正常拦截。
- 检查接口日志，确认每一次请求的来源、参数与结果均被完整记录，满足合规溯源的要求。
