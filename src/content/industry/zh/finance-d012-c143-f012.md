# 软件开发营销内容的模型接入与配置

## 这个品类的数据长什么样
软件开发类金融营销内容的数据，主要来源于产品研发文档、功能迭代记录、接口规范说明、客户使用反馈素材。更新节奏随产品版本迭代不定期触发，大版本更新时批量更新，小功能迭代时单次更新。文档多为结构化格式，包含版本号、功能模块、接口地址、请求参数、返回字段等字段。字段如`version`为字符串格式，`max_requests_per_minute`为整数，单位为次/分钟，`interface_url`为符合URL规范的字符串。

## 这些特征在「模型接入与配置」这一环带来什么约束
结构化的字段与JSON格式的请求参数，要求模型接入时需适配结构化数据解析，避免非结构化解析导致的字段匹配错误。更新节奏不定期且随版本变化，要求配置中需支持动态拉取最新的接口参数与版本信息，避免使用过时的配置导致请求失败。字段带有明确单位，要求接入时需校验参数单位一致性，防止因单位不匹配触发接口限流或参数错误。接口地址随功能调整，配置中需预留可修改的接口路径项，便于快速适配版本更新后的接口变更。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `max_requests_per_minute` | `100 次/分钟` | 匹配接口文档标注的限流规则，避免触发限流报错 |
| `model_context_window` | `8192 令牌` | 软件开发营销内容多为结构化短文本，8192令牌可覆盖完整的接口参数与功能说明 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 营销物料的文档解析需处理多段结构化内容，预留足够的解析时间 |
| `retrieval_top_k` | `前 3 条` | 软件开发营销内容的核心信息集中在接口参数与功能特性，无需过多召回条目 |
| `similarity_threshold` | `0.75–0.85` | 需精准匹配接口文档的字段与参数描述，避免召回无关的版本更新内容 |
| `LOCAL_MODEL_API_URL` | 按本地部署的大模型接口地址填写 | 适配本地部署的模型调用路径，确保请求可正常发送 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为本地部署大模型时，接口返回200状态码但无`content`字段值。原因是未正确配置`LOCAL_MODEL_RESPONSE_PATH`参数，导致模型返回的原始内容未被正确提取。
- 现象为上传软件开发营销文档时触发`413 Request Entity Too Large`报错。原因是未调整`UPLOAD_DOC_MAX_SIZE`参数，未匹配文档的实际大小上限。
- 现象为模型召回的内容包含过时的版本信息，无法匹配当前使用的接口参数。原因是未开启动态拉取最新文档的配置，使用了缓存的旧版营销内容数据。

## 怎么确认配好了
- 发起匹配软件开发营销内容的模拟请求，核对返回结果的字段是否与配置的参数定义一致，检查是否包含预期的接口说明与功能描述。
- 上传不同大小的测试文档，验证上传流程是否正常，确认未触发大小限制类报错。
- 修改本地部署大模型的测试参数，发起调用请求，检查是否能正常获取模型返回的内容。
- 触发文档更新动作，确认系统能拉取最新的营销内容数据，避免使用缓存的旧版本信息。
