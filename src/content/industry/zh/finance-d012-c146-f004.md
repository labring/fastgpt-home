# 通用设备营销内容的向量模型与索引

## 这个品类的数据长什么样
通用设备的营销内容数据主要来自金融机构、设备服务商的官方产品手册、技术参数文档、销售推广物料及官网产品详情页。更新节奏随新产品立项、核心参数调整或金融场景适配（如租赁方案更新）触发。文档多按设备型号拆分，单篇内容包含设备型号、额定功率、工作温度、适用工况等字段，参数字段附带明确单位，部分长文档会包含多型号对比表格与安装示意图说明。

## 这些特征在「向量模型与索引」这一环带来什么约束
通用设备的营销内容包含大量带明确单位的技术参数、多型号对比表格，单篇文档长度差异较大，且常伴随金融场景适配的获客类说明（如租赁方案、采购优惠）。带单位的参数若拆分时丢失单位，会导致向量语义偏差，因此向量模型需支持保留单位关联信息。多型号对比的表格会产生跨型号的语义关联，索引分片需兼顾单段内的语义完整性。非固定频率的更新要求索引支持增量同步，适配频繁的产品与获客方案调整，避免全量重建带来的资源消耗。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `分段长度` | 800–1200 字符 | 通用设备营销内容含长参数段落与表格，该区间可保留单段内的技术参数关联语义 |
| `召回条数` | 前8–12条 | 单篇设备文档参数项较多，适量召回可覆盖多型号对比的关联需求 |
| `相似度阈值` | 0.72–0.80 | 技术参数的语义匹配需兼顾精度，过低会引入无关设备型号，过高会遗漏相近参数配置 |
| `增量同步开关` | 开启 | 适配非固定频率的产品文档更新，减少全量索引重建的资源占用 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 长文档的参数解析需预留足够时间，避免因超时导致上传失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量上传的多型号设备手册，避免因单文件过大被拦截 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用索引接口返回400状态码且无响应体，原因是未正确携带通用设备参数的单位信息，导致模型输入格式不符合接口要求。
- 服务器读写资源被撑爆，原因是未开启增量同步开关，对批量设备文档执行全量索引重建，反复触发向量计算与索引写入。
- 知识库上传卡在1组或2组索引中，原因是分段长度设置过小，将带单位的技术参数拆分为多个独立片段，导致索引分片关联断裂。

## 怎么确认配好了
- 上传单篇带参数的设备手册，检查向量召回结果中是否保留了参数与单位的关联语义。
- 触发一次增量同步任务，查看索引更新日志仅包含新增或修改的文档，无全量重建标记。
- 上传超过500MB的设备文档包，确认上传流程未被拦截且解析正常。
- 调整相似度阈值至0.75，测试相近型号设备的参数召回结果是否符合预期。
