# 酒店餐饮营销内容的表单与交互

## 这个品类的数据长什么样
数据主要来自酒店餐饮门店的POS终端、会员管理系统、第三方预订平台API，部分营销触达数据来自金融合作渠道的投放后台。更新节奏分为实时（订单、优惠券核销记录）与每日固定时段（客流统计、营收汇总、投放数据复盘）。文档以结构化表格为主，核心字段包含门店编码、统计日期、到店人次、客单价、优惠券核销张数、关联活动ID，单位分别为编码、日期、人次、元、张、活动编码。部分数据会按门店区域、经营时段分层存储。

## 这些特征在「表单与交互」这一环带来什么约束
结构化字段多的特征要求表单支持多源字段映射，匹配POS、预订平台、金融合作渠道的不同字段命名差异。实时数据更新要求表单交互支持即时校验，拦截提交过时的统计数据。分层存储的数据需要表单提供区域筛选、门店多选的交互控件，适配多门店连锁管理场景。营销素材关联字段要求表单支持活动ID的快速检索与绑定，减少手动输入失误。同时，餐饮门店的表单提交多在移动设备完成，需简化非必填字段的触控操作步骤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `form_field_mapping` | 按来源系统预设字段映射 | 适配酒店餐饮多源数据的字段命名差异，减少手动配置成本 |
| `form_submit_timeout` | 30 秒 | 匹配餐饮门店实时数据的提交时效，避免因网络波动导致提交失败 |
| `form_field_required` | 门店编码、统计日期、到店人次 | 确保核心统计字段完整，满足营销数据的分析基础 |
| `form_search_suggest` | 活动ID前缀匹配，返回前10条 | 快速检索关联营销活动，适配餐饮营销内容的快速绑定需求 |
| `form_device_adapt` | 触控优先布局 | 适配移动设备提交场景，提升门店操作人员的交互效率 |
| `form_error_retry` | 重试2次，间隔5秒 | 应对餐饮门店网络不稳定的常见问题，降低提交失败率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 表单节点返回的HTML内容仅展示静态文本，无法触发交互操作。原因是未开启`form_interactive_enable`配置项，导致返回的表单控件未被宿主环境解析为可交互元素。
- 提交表单时出现`400 Bad Request`报错，提示核心字段缺失。原因是未正确配置`form_field_required`，遗漏了门店编码、统计日期等餐饮营销数据的必填校验规则。
- 表单加载后长时间无响应，最终触发超时错误。原因是`form_submit_timeout`配置值设置不合理，未匹配餐饮门店常见的网络波动场景。

## 怎么确认配好了
- 提交测试表单，检查是否能正确映射多源系统的字段数据，验证`form_field_mapping`配置是否生效。
- 操作表单控件，确认可触发交互动作，验证`form_interactive_enable`配置是否开启。
- 模拟网络波动场景，检查表单是否会按配置的重试规则自动重试提交，验证`form_error_retry`配置是否合理。
- 切换至移动设备打开表单页面，检查控件布局是否适配触控操作，验证`form_device_adapt`配置是否生效。
