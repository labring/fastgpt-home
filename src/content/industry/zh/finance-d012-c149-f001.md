# 钢铁贸易营销内容的HTTP 接口与外部系统

## 这个品类的数据长什么样
钢铁贸易的营销相关数据主要来源于企业ERP进销存模块、区域钢材现货交易平台、客户询价台账。数据更新节奏存在差异：现货报价每1至4小时更新，库存数据随每笔交易或每日同步，客户触达记录随会话实时生成。文档多为结构化表格格式，包含钢材牌号、公称尺寸、产地、含税单价（元/吨）、库存余量、交货地点等字段，营销配套文档含定制化报价函、区域推广素材的元数据。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
现货报价的实时性要求接口支持短间隔轮询或Webhook推送；结构化字段包含带单位的数值型参数，需在接口请求中明确单位与数值范围的校验规则；营销素材与客户交易数据的关联需求，要求接口支持跨系统身份令牌传递；批量拉取库存数据时，需适配分页参数以避免单次请求过载；客户询价记录的实时同步，要求接口支持低延迟的写入请求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `API_REQUEST_TIMEOUT` | `300–600 秒` | 适配钢铁贸易批量库存数据拉取、多字段校验的耗时需求，避免超时中断请求 |
| `UPLOAD_FILE_BATCH_LIMIT` | `20–30 个` | 钢铁贸易营销文档多为带结构化表格的长文档，单次批量过大易触发解析超时，平衡导入效率与稳定性 |
| `IDENTITY_VERIFICATION_MODE` | `基于业务系统令牌的前置校验` | 钢铁贸易客户数据需与FastGPT会话绑定，避免未授权的营销内容触达 |
| `WEBHOOK_PUSH_INTERVAL` | `300–600 秒` | 匹配现货报价数据的更新频率，避免过于频繁的请求占用外部系统资源 |
| `API_FIELD_VALIDATION_RULES` | 校验单位（元/吨）与数值范围 | 钢铁贸易数据包含带单位的价格、库存字段，需确保接口接收数据的格式合规 |
| `MAX_RESPONSE_ENTRIES` | `前 10–15 条` | 营销内容推荐需聚焦高意向客户的常用钢材品类，避免返回过多冗余数据影响加载速度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用FastGPT HTTP接口时返回`401 Unauthorized`，且无法关联业务系统的客户身份。未配置基于业务系统令牌的身份校验规则，未将业务系统的用户ID传入接口请求头或参数中。
- 批量导入营销文档时触发`Payload Too Large`或`maxLength exceeded`报错。单次上传的文档总字节数超过接口限制，且未调整`UPLOAD_FILE_BATCH_LIMIT`与单文件解析阈值。
- 实时拉取现货报价数据时返回`504 Gateway Timeout`。接口请求超时设置过短，未适配钢铁贸易批量结构化数据的拉取耗时。

## 怎么确认配好了
- 发起一次批量导入营销文档的请求，检查接口返回的状态码与导入结果，确认批量数量符合配置的`UPLOAD_FILE_BATCH_LIMIT`。
- 调用身份校验接口，传入业务系统的用户令牌与钢材品类参数，检查是否能正常关联会话并返回对应营销内容。
- 发起单次现货报价拉取请求，监控接口响应时长，确认未超过配置的`API_REQUEST_TIMEOUT`。
- 检查接口日志，确认所有带单位的字段均通过校验，未出现格式错误。
