# 铁矿石营销内容的HTTP 接口与外部系统

## 这个品类的数据长什么样
铁矿石营销相关的数据主要来源于大宗商品现货交易平台公开行情接口、海关进口统计接口及港口装卸调度数据接口。数据更新节奏按类型区分：现货报价每15至30分钟推送增量数据，港口库存数据每日定点更新，钢厂采购招标信息每周更新2至3批次。接口返回的文档为结构化JSON格式，包含基础品类标识、核心参数与时间戳字段，核心字段包括`symbol`（品种代码）、`grade`（品位，如`62% Fe`）、`origin`（产地）、`price`（单位：元/干吨）、`update_time`（ISO 8601格式时间戳）、`port`（交割港口名称），部分接口会额外包含库存数量、装卸量等衍生数据。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
铁矿石数据的多维度细分属性要求HTTP接口必须支持按品位、产地等参数过滤，否则返回的数据集过于庞杂，无法直接用于营销内容生成。不同类型数据的更新频率差异，要求外部系统配置差异化的拉取周期，避免过度拉取浪费资源或延迟获取最新行情。字段单位的标准化需求，要求接口调用时需统一转换外部接口的单位格式，防止营销素材中出现单位混淆。多来源接口的字段命名差异，要求系统配置映射规则，将不同接口的字段统一为内部使用的标准字段，确保营销内容生成的一致性。此外，铁矿石数据的实时性要求较高，接口调用需控制超时时间，且需适配临时波动的重试策略，保障数据拉取的稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `api_request_interval` | `15 分钟`（现货行情）、`1440 分钟`（港口库存） | 匹配对应品类数据的实际更新频率，平衡数据时效性与接口调用成本 |
| `api_filter_params` | `{"grade": ["62% Fe", "65% Fe"], "origin": ["Australia", "Brazil"]}` | 聚焦铁矿石营销中最常见的主流品位与核心产地，缩小返回数据范围 |
| `response_parse_field_map` | `{"spot_price": "price", "update_at": "update_time"}` | 统一不同外部接口的字段命名差异，确保内部数据处理的一致性 |
| `webhook_payload_template` | `{"product": "{{symbol}}", "grade": "{{grade}}", "price": "{{price}}", "update_time": "{{update_time}}"}` | 标准化营销内容的输出格式，适配后续推广素材的生成需求 |
| `api_timeout` | `30 秒` | 预留足够的响应时间以拉取多组铁矿石行情数据，避免因超时导致拉取失败 |
| `retry_max_times` | `3 次` | 应对外部接口的临时波动，少量重试可提升数据拉取的成功率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：启动容器后调用外部接口返回`400 Bad Request`，日志显示`invalid api base url`。原因：未正确填写`ONE_API_BASE_URL`的完整参数，遗漏了接口路径后缀或端口配置。
- 现象：webhook推送的多表格数据仅返回第一行内容，后续行丢失。原因：未配置针对结构化表格的批量解析规则，仅默认提取单条数据。
- 现象：本地调试时调用外部接口失败，返回`403 Forbidden`。原因：未将目标外部接口域名添加至`ALLOWED_EXTERNAL_DOMAINS`配置项，请求被系统拦截。

## 怎么确认配好了
- 发起单次手动接口调用，检查返回的JSON数据是否包含预设的`grade`、`price`等核心字段，且字段单位符合预期。
- 查看定时拉取任务的日志，确认在数据更新周期内成功拉取到新数据，无连续超时或报错记录。
- 触发webhook推送，检查接收端是否能正确解析结构化的营销内容数据，无字段缺失或格式错误。
- 调整`api_request_interval`的配置值，验证系统是否按新的间隔执行拉取操作，无异常触发频率。
