# 铁路公路营销内容的工具调用与插件

## 这个品类的数据长什么样
铁路公路营销相关数据主要来自票务结算系统、客流监测平台、线路运维后台与线下营销活动台账。数据更新节奏分多档：实时票务订单、当日客流数据为准实时更新，月度营销活动报表为日更，线路基础信息为季度更新。单条数据文档结构包含线路编号、途经站点、时段客流、触达渠道、活动标识、客单价等字段，单位涵盖人次、元、分钟、车次编号等，部分字段存在空值可能，比如未开展活动的线路无活动标识字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
不同更新节奏的数据对插件的调用频率与缓存策略提出约束。实时类客流、票务数据需配置短周期缓存或无缓存调用，避免数据滞后；日更、季度更新的基础信息可配置长周期缓存，降低接口调用压力。多字段且存在空值的文档结构，要求插件支持可选字段映射，避免因缺失字段触发调用失败。不同品类的营销字段存在差异，铁路公路的活动标识、触达渠道字段无法直接复用其他行业的插件模板，需单独配置字段映射规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `pluginDataSourceRefreshInterval` | 实时数据源设为`10 秒`，日更数据源设为`86400 秒` | 匹配对应数据的更新节奏，避免缓存过期或冗余调用 |
| `pluginFieldMappingRule` | 按铁路公路数据字段自定义映射，将`线路编号`映射为`route_id`，`时段客流`映射为`passenger_flow` | 适配该品类特有的数据字段命名，避免字段不匹配导致解析失败 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `60 秒` | 铁路公路营销文档多包含多站点客流明细，解析耗时较长，默认超时时长不足 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 营销物料可能包含高清线路图、客流统计报表PDF，需支持较大文件上传 |
| `pluginEnableDynamicField` | `开启` | 部分线路无营销活动数据，开启后可自动跳过空值字段，避免调用报错 |
| `pluginApiRetryCount` | `3 次` | 实时票务接口可能存在临时波动，重试可降低调用失败概率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为安装数据库连接插件时提示`500 Internal Server Error`，原因是未配置铁路票务系统数据库的白名单，导致插件无法访问目标数据源。
- 现象为插件中的PDF增强解析选项呈灰色无法勾选，原因是未开启全局的文件解析增强开关，且未上传符合格式的营销物料PDF。
- 现象为调用自定义API获取营销活动数据时无法提取`dataId`字段，原因是未在字段映射规则中配置`activity_id`到`dataId`的转换，导致插件无法识别目标标识。

## 怎么确认配好了
- 调用插件内置的测试接口，传入测试线路的`route_id`，检查返回结果是否包含预设的客流、客单价字段。
- 上传一份测试用的营销物料PDF，确认插件可正常解析并提取其中的活动名称与触达渠道信息。
- 查看插件运行日志，确认缓存刷新频率与配置的`pluginDataSourceRefreshInterval`参数一致。
- 触发一次数据库连接测试，确认无`500 Internal Server Error`类的报错信息。
