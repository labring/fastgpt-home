# 饰品营销内容的多轮对话与提示词

## 这个品类的数据长什么样
饰品的数据来源包括品牌内部产品管理系统、电商上架台账、供应链交付清单。更新节奏为新品上线集中在季度新品发布、节日营销节点，旧品下架随库存清空，日常更新少量补库存的SKU。文档结构为单SKU一行的结构化表格或JSON条目，包含货号、材质、链长（厘米）、克重（克）、建议售价（元）、适配场景、设计主题等字段，每个字段对应明确的单位与属性定义。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
饰品的字段多且带有明确单位，多轮对话中需避免混淆不同SKU的尺寸、售价等参数，因此提示词需强制要求明确指代目标SKU的货号或属性。SKU更新频繁的特点要求知识库召回需匹配实时数据，多轮对话中需限制历史上下文的保留长度，避免引入过期的库存或售价信息。适配场景与设计主题是营销内容的核心，多轮对话需引导用户逐步明确场景需求，提示词需绑定产品属性与营销场景，避免输出无针对性的通用文案。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `2000–3000 字符` | 饰品单SKU数据约100-200字符，保留2-3条SKU上下文即可避免模型溢出，同时覆盖当前对话的核心需求 |
| `召回条数` | `前 6–8 条` | 饰品品类的产品属性相似度较高，召回过多会导致提示词过长，过少会遗漏匹配的精准SKU |
| `相似度阈值` | `0.72–0.78` | 同材质、同设计的饰品较多，阈值过低会引入无关SKU，过高会无法匹配用户的细分需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 秒` | 批量上传的饰品SKU台账通常包含数百条数据，解析需要较长的处理时间 |
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | 饰品的产品图片与数据台账合并上传时，单文件容量通常不超过该阈值 |
| `promptTemplate` | `“根据用户提供的场景需求，从知识库中匹配对应饰品SKU，输出包含货号、尺寸、适配场景的营销文案，每轮对话仅介绍3个以内的SKU”` | 饰品营销内容需精准匹配场景，且避免信息过载导致用户难以选择 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：多轮对话中，AI输出的最新营销文案会附带之前回复过的SKU信息。原因：未设置`maxContext`的截断规则，导致历史上下文被持续累加，超出模型处理范围。
- 现象：配置了输入引导与词库，但对话界面未显示预设引导问题。原因：未开启对话界面展示输入引导的开关，或词库的关键词未与引导问题绑定。
- 现象：上传XLSX格式的饰品产品台账后，对话中无法读取文件内容。原因：未启用XLSX文件的结构化解析配置，或文件中包含合并单元格、隐藏列等非标准格式，导致解析失败。

## 怎么确认配好了
- 发起包含多个饰品属性的测试提问，核对AI回复是否仅包含当前对话上下文内的SKU信息，无历史冗余内容。
- 进入对话界面预览，确认预设的引导问题已正常显示，输入触发词后能匹配对应词库内容。
- 上传测试用的标准XLSX饰品台账，发起复述文件内容的提问，核对AI能否准确提取字段与单位。
- 调整`maxContext`的取值，测试不同长度的历史对话，确认回复不会出现上下文溢出或信息丢失的情况。
