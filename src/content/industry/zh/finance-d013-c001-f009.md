# IT 服务融资日报的引用来源与溯源

## 这个品类的数据长什么样
IT服务融资日报的数据来源包括全国性企业融资披露平台、地方金融监管备案系统、第三方企业征信数据库及IT服务厂商自主公开的融资公告。更新节奏为每日更新，每日生成当日披露的全量IT服务领域融资动态。文档以结构化表格为核心载体，附带原始公告的永久链接，包含`source_id`、披露日期、融资金额（单位为万元人民币）、融资轮次、投资方列表、服务赛道（如云计算、低代码开发、AI工具服务）、企业主体名称等字段，部分原始文档为PDF格式的官方公告。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源分散的披露渠道要求溯源环节需校验`source_id`的唯一性，避免同一融资案例被多个数据源重复召回。每日更新的属性要求召回范围严格限定在当日披露数据，否则会混入过期信息干扰准确性。结构化字段中包含`service_track`赛道标签，需在溯源时绑定该字段进行过滤，防止召回非IT服务领域的融资数据。PDF格式的原始公告要求解析时保留段落锚点，以便精准定位具体融资条款，仅返回整份文档链接无法满足精准溯源的需求。融资金额的单位统一为万元人民币，需在溯源时校验单位一致性，避免出现单位错误导致的引用偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| :--- | :--- | :--- |
| `recall_recent_days` | `1` | IT服务融资日报为每日更新的品类，仅需召回当日披露的融资数据，避免跨日数据干扰溯源准确性 |
| `source_id_mapping_field` | `source_id` | 该品类数据统一使用`source_id`作为披露公告的唯一标识，与数据库存储字段完全匹配 |
| `parse_anchor_enable` | `true` | IT服务融资原始文档多为PDF公告，启用锚点解析可定位具体融资条款段落，提升溯源精准度 |
| `context_return_fields` | `["disclosure_date", "amount", "investors", "service_track", "original_url"]` | 该品类的核心溯源字段为披露日期、融资金额、投资方、赛道、原始链接，需完整返回供用户核对 |
| `similarity_threshold` | `0.75` | IT服务融资信息的关键词（如轮次、赛道）辨识度高，阈值设为0.75可过滤低相关的非IT服务融资数据 |
| `max_recall_count` | `3` | 融资日报单日内披露的有效IT服务融资案例通常较少，限制召回条数可避免冗余信息干扰 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上下文引用中返回的融资数据为Markdown源码，未以渲染后的格式呈现。原因：未开启`parse_markdown_render`配置，仅返回文档解析后的原始文本内容。
- 现象：溯源时返回的投资方、融资金额等核心字段为空。原因：未将`source_id_mapping_field`配置为数据库中存储的`source_id`字段，无法完成数据源与业务字段的关联匹配。
- 现象：连续会话中未沿用当前IT服务赛道的融资召回规则，误召回其他行业的融资数据。原因：未在会话上下文绑定`service_track`字段的过滤条件，导致会话切换时丢失赛道限定规则。

## 怎么确认配好了
- 上传单份IT服务融资日报的结构化文档，检查解析后返回的字段是否包含预设的`disclosure_date`、`amount`、`service_track`等核心字段。
- 发起测试查询，验证返回的上下文引用是否以可读格式展示融资信息，未返回原始Markdown源码。
- 发起连续会话查询，验证第二次查询时是否保留了首次会话设定的`service_track`赛道过滤规则。
- 查看系统运行日志，确认每次溯源请求均携带`source_id`字段，且未出现跨赛道的融资数据召回记录。
