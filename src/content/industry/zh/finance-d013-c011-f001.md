# 休闲食品融资日报的HTTP 接口与外部系统

## 这个品类的数据长什么样
这个品类的融资日报数据主要来自公开金融披露平台、地方金融监管备案信息及第三方财经数据接口。数据更新节奏为每日凌晨同步前24小时内的全量休闲食品赛道融资事件，历史增量数据按周更新。单条数据文档包含固定字段：`company_name`（企业全称，字符串类型）、`financing_round`（融资轮次，枚举类型）、`financing_amount`（融资金额，单位为万元）、`investors_list`（投资方列表，数组类型）、`disclosure_date`（披露日期，YYYY-MM-DD格式）、`business_scope`（业务范围，标注为休闲食品相关品类）。单条文档字数相关数值差异较大，建议按自有样本统计或实测后再确定，无嵌套层级过深的复杂结构。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的融资日报数据特征对HTTP接口与外部系统环节带来三点核心约束：第一，多数据源对接需求，需兼容不同接口的鉴权方式、请求头格式与返回字段映射规则；第二，固定的日期筛选要求，接口查询参数需支持`disclosure_date`的精准匹配，避免拉取跨日数据；第三，数组类型的投资方字段与数值型融资金额的单位校验，需在接口请求与响应解析环节配置格式校验逻辑，防止非标准格式数据流入系统。此外，每日增量更新的节奏要求定时任务调度需匹配数据更新周期，避免重复拉取或遗漏当日融资事件，同时单条文档的轻量化结构虽降低解析压力，但需适配批量拉取的分页参数配置，确保全量数据同步完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `API_REQUEST_TIMEOUT` | `300 秒` | 休闲食品融资日报单条数据解析耗时通常不超过2秒，批量拉取时300秒可覆盖峰值场景，避免超时中断 |
| `BATCH_SYNC_SIZE` | `50 条/次` | 每日融资事件数量适中，单次拉取50条可平衡接口负载与同步效率，避免单次请求过大触发限流 |
| `FIELD_VALIDATION_ENABLE` | 开启 | 需校验`financing_amount`的单位与`disclosure_date`的格式，防止脏数据进入知识库 |
| `PAGE_SIZE` | `20 条/页` | 多数公开财经数据源接口默认分页大小为20，适配通用接口规范，减少兼容性问题 |
| `AUTH_TYPE` | `API_KEY + 自定义请求头` | 多数公开财经数据源采用API Key鉴权，自定义请求头可携带品类筛选参数，确保仅拉取休闲食品相关数据 |
| `SYNC_SCHEDULE` | `0 3 * * *` | 匹配数据源每日凌晨更新的节奏，避免在业务高峰时段发起同步请求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用API创建知识库并上传融资日报文件后，无法获取解析中、就绪或失败的状态反馈。原因：未配置`WEBHOOK_URL`接收解析状态回调，或未在请求参数中开启`enable_status_notify`开关，导致无法同步解析进度。
- 现象：HTTP接口请求返回`429 Too Many Requests`错误码，同步任务中断。原因：未设置合理的`BATCH_SYNC_SIZE`与请求间隔，单次拉取数据量过大触发第三方数据源的限流规则。
- 现象：拉取到的融资数据混入非休闲食品品类的记录，`business_scope`字段未标注为休闲食品品类。原因：未在自定义请求头中添加品类筛选参数，或鉴权配置错误导致无法访问专属筛选接口。

## 怎么确认配好了
- 发起单次API拉取请求，检查返回数据的字段格式是否与预设的`financing_amount`单位、`disclosure_date`日期格式匹配，确认字段校验配置生效。
- 查看接口请求日志，确认鉴权参数已按配置的`AUTH_TYPE`正确携带，无`401 Unauthorized`或`403 Forbidden`报错。
- 触发一次定时同步任务，检查知识库中新增的融资数据是否均标注为休闲食品品类，确认品类筛选配置生效。
- 模拟多轮批量拉取请求，观察接口返回的状态码，确认请求负载未触发限流规则，验证`BATCH_SYNC_SIZE`配置合理。
