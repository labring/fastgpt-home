# 光模块融资日报的文档解析与分块

## 这个品类的数据长什么样
光模块融资日报的数据来源包括公开产业投融资公告、行业资讯平台的每日融资汇总、交易所披露的上市公司对外投资信息。更新节奏为每日更新，覆盖当日披露的光模块相关融资项目。文档结构多为单篇汇总多篇融资条目，每条条目包含厂商名称、融资轮次、融资金额、投资方、落地光模块品类、披露日期等字段，部分文档附带光模块参数（如传输速率、工作波长）的补充说明，部分格式含结构化表格或纯文本列表。字段单位包含万元、亿元等金额单位，以及Gbps、nm等光模块专业参数单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
来源多样的文档格式要求解析环节适配纯文本、PDF表格、网页排版等多种形态，避免字段提取偏差。每日更新的特性要求解析流程具备较高的时效性，需控制单文档解析耗时。光模块专业参数与融资信息紧密绑定的结构，要求分块时保留完整的上下文关联，不能拆分专业术语或核心融资字段。单篇文档可能包含数十条融资条目，需平衡分块大小与信息完整性，避免出现跨块的字段关联断裂，同时适配模型的上下文窗口限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `chunkSize` | 800–1200 字符 | 光模块融资日报单条条目含专业参数与融资信息，该区间可覆盖单条完整内容，避免上下文割裂 |
| `chunkOverlap` | 100–150 字符 | 保留跨块的光模块专业术语上下文，防止术语被拆分导致语义丢失 |
| `parseMode` | 结构化解析优先 | 适配日报文档中的表格或结构化融资条目，准确提取标准化字段 |
| `maxChunkToken` | 1500 令牌 | 匹配中文分词的令牌换算规则，避免单块超出通用大模型的上下文限制 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 覆盖单篇含数十条融资条目的文档解析耗时，避免中途超时中断 |
| `enableStructuredParse` | 开启 | 自动识别文档中的融资条目表格，减少手动调整分块的工作量 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：解析后的分块中，光模块专业参数（如400G、CWDM）被截断拆分。原因：`chunkSize`设置过小，未预留足够空间容纳带专业术语的完整融资条目。
- 现象：API调用返回`413 Request Entity Too Large`错误。原因：单篇融资日报文档大小超过`UPLOAD_FILE_MAX_SIZE`的限制，未提前调整上传阈值或拆分文档。
- 现象：分块结果中`融资轮次`字段为空。原因：未启用`enableStructuredParse`配置，无法自动识别文档中的结构化融资表格，导致字段提取失败。

## 怎么确认配好了
- 上传一份包含多条光模块融资信息的测试文档，查看解析后的分块列表，确认每个分块包含完整的单条融资条目及关联的光模块参数。
- 调用文档解析API，检查返回的分块数据中是否包含`融资金额`、`融资轮次`等标准化字段，确认结构化解析生效。
- 调整`chunkSize`参数至不同区间，对比分块结果，确认未出现专业术语或核心字段被跨块拆分的情况。
- 上传单篇包含数十条融资条目的测试文档，确认解析未触发`PARSE_FILE_TIMEOUT_SECONDS`的超时错误。
