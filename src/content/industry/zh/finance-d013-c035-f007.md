# 医美融资日报的工作流编排

## 这个品类的数据长什么样
医美融资日报的数据来源为医美机构的财务系统、合作银行的授信接口、地方医美行业协会的融资备案数据。更新节奏为每日凌晨同步前一日的全量数据。单份日报文档按机构维度拆分，包含机构统一社会信用代码、当日融资类型（授信审批、到账、还款）、对应金额（单位：人民币元）、审批状态、合作方名称5个核心字段，部分机构会补充医美项目的融资专项备注字段。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源包含财务系统、银行接口及行业协会备案，工作流需配置多源并行拉取节点，避免串行拉取导致的超时。每日凌晨的同步窗口较短，需将工作流触发周期设为每日一次，且设置数据拉取的超时阈值，防止单源接口延迟影响全量任务。机构维度拆分的文档结构要求工作流需配置循环节点，按机构ID批量处理数据。融资类型的枚举值存在不定期新增，需使用动态分支配置，适配业务变化。金额字段的数值精度要求为两位小数，需在数据清洗节点配置格式校验规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `workflow_trigger_cron` | `0 0 1 * * *` | 匹配医美融资日报每日凌晨同步前一日数据的节奏，避免拉取未完成的当日数据 |
| `api_request_timeout` | `600 秒` | 适配银行授信接口的高延迟特性，避免因超时终止数据拉取任务 |
| `multi_source_parallel_count` | `2-4` | 对接3类数据源，并行拉取可降低总耗时，符合单节点的并发承载能力 |
| `data_clean_field_check` | `开启` | 校验统一社会信用代码格式、金额的两位小数精度，过滤无效数据 |
| `loop_batch_size` | `10-20` | 平衡单机构数据量差异带来的内存占用与处理效率，避免单批次任务过载 |
| `dynamic_branch_max_enum` | `20` | 预留医美融资类型枚举值的扩展空间，适配业务新增的融资场景 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用工作流的API返回`400 Bad Request`，提示`invalid json format`。原因：未正确配置JSON输入框的变量绑定，直接传入未解析的原始JSON字符串。
- 现象：单节点运行时出现`OOM Killed`系统报错。原因：未设置合理的`loop_batch_size`，批量处理的机构数量过多导致内存占用超标。
- 现象：生成的日报中部分机构的融资类型字段为空。原因：未开启`data_clean_field_check`配置，未过滤缺失核心字段的无效数据。

## 怎么确认配好了
- 查看工作流的触发日志，确认每日预设时间的触发记录正常，无`task_timeout`类报错。
- 手动触发一次测试任务，检查数据清洗节点的输出结果，确认核心字段的格式校验通过。
- 调用工作流的API接口，传入合法的机构ID参数，检查返回结果的字段完整性与格式正确性。
- 调整`loop_batch_size`为较小值运行测试任务，确认无内存溢出类报错。
