# 厨卫电器融资日报的知识库检索与召回

## 这个品类的数据长什么样
厨卫电器融资日报的数据来源为公开企业融资公告、行业媒体融资动态汇总及证券交易所披露文件。更新节奏为每日同步当日披露的融资信息，每周生成当周全品类融资汇总文档。单条数据文档结构包含融资主体名称、所属厨卫电器细分赛道、融资金额、融资轮次、投资方、披露日期及关联企业信息。字段单位统一为：融资金额以万元为计量，融资轮次采用创投行业标准术语，披露日期采用YYYY-MM-DD格式。

## 这些特征在「知识库检索与召回」这一环带来什么约束
厨卫电器融资日报的特征对检索与召回环节带来多重约束。分散的多源数据存在字段格式差异，会导致标准化检索时匹配精度下降。每日更新的高频特性要求知识库增量更新流程匹配实时性需求，否则召回信息会滞后于最新动态。细分赛道字段的存在，需要检索逻辑精准绑定赛道标签，避免跨品类的无关融资信息被召回。融资金额的固定单位要求，需在文档预处理阶段完成格式统一，否则数值类检索会出现偏差。长短不一的文档结构，需要适配差异化的分块规则，避免长文档关键信息被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `chunk_size` | 800–1200 字符 | 厨卫电器融资日报单条公告约300-500字，月度汇总文档约2000-3000字，该分块长度可保留完整融资主体、轮次、投资方等核心字段，避免跨块信息丢失 |
| `chunk_overlap` | 150–200 字符 | 长文档分块时需保留相邻块的关联信息，避免融资轮次、投资方等跨块的关键信息断裂 |
| `recall_top_k` | 前8–10条 | 每日融资条目数量适中，该召回条数可覆盖当日及近两日的核心动态，避免冗余信息过多 |
| `similarity_threshold` | 0.72–0.80 | 需精准匹配赛道标签与融资主体关键词，阈值过低会混入无关品类融资信息，过高则会遗漏部分关联主体的融资动态 |
| `parse_file_timeout` | 120 秒 | 月度汇总文档篇幅较长，需预留足够时间完成解析与分块，避免解析超时导致文档无法导入 |
| `UPLOAD_FILE_MAX_SIZE` | 50 MB | 月度汇总文档最大可达30 MB，预留足够空间支持批量导入多份日报文档 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为上传厨卫电器融资日报文档时出现“Request failed with status code 400”报错，原因为文档中包含未转义的半角括号、换行符等特殊字符，或字段格式不符合知识库解析的标准化要求。
- 现象为检索结果中融资轮次、投资方等信息不完整，原因为分块长度设置过小，将完整的融资条目拆分至不同分块中，导致召回时无法关联完整内容。
- 现象为知识库对话响应延迟较高，原因为召回条数设置过高且分块长度过大，导致上下文加载量超出系统处理上限。

## 怎么确认配好了
- 上传单篇月度汇总文档，检查解析后台显示的分块数量与预期一致，确认分块参数的配置生效。
- 输入包含厨卫电器赛道关键词的查询词，核对召回结果的赛道标签是否全部匹配，确认相似度阈值与召回条数的配置生效。
- 导入当日最新的融资公告文档，检查更新后知识库的检索结果是否包含最新披露的信息，确认增量更新流程的配置生效。
- 查看系统日志，确认无文档解析超时或上传失败的报错，确认超时参数与上传大小限制的配置生效。
