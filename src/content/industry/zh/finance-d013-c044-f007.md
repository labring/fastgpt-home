# 商业物业融资日报的工作流编排

## 这个品类的数据长什么样
商业物业融资日报的数据主要来自物业自持运营系统、合作银行的授信审批台账、属地住建部门的商业租赁备案接口。数据更新节奏为每日凌晨同步前一自然日的全量数据，文件格式为固定表头的TXT文档。文档结构包含项目唯一标识、项目名称、租赁业态（如商超、写字楼）、可租赁面积（单位：平方米）、当日实收租金（单位：元）、累计待收租金、当月融资申请额度、审批节点状态、实际放款金额等字段，部分字段需匹配银行授信的标准化编码规则。

## 这些特征在「工作流编排」这一环带来什么约束
固定表头的TXT文档要求工作流的文件解析节点需预设表头匹配规则，避免因表头字段顺序变动导致解析失败。每日凌晨的全量同步要求工作流触发节点需配置定时触发，且需校验当日数据是否已完成同步，避免重复处理旧数据。多来源的数据融合要求工作流添加跨系统数据对齐节点，需匹配项目唯一标识字段进行关联，否则会出现数据错位。单份日报的文件体量通常在500-1500行，要求上传节点配置合理的文件大小阈值，避免因文件过大触发超时限制。不同物业项目的字段完整性差异较大，需配置异常字段捕获节点，标记缺失的审批状态字段，避免后续流程中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `schedule_cron` | `0 0 1 * * *` | 匹配商业物业融资日报每日凌晨的更新节奏，确保工作流处理最新的当日数据 |
| `UPLOAD_FILE_MAX_SIZE` | `20 MB` | 单份商业物业融资日报的TXT文件体量通常不超过15 MB，预留合理缓冲空间避免上传失败 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 多来源数据对齐和字段标准化处理需消耗一定时间，300秒可覆盖常规体量的日报解析流程 |
| `field_match_mode` | `按项目ID精准匹配` | 商业物业融资日报需关联多系统数据，精准匹配唯一标识可避免数据错位 |
| `workflow_timeout` | `600 秒` | FastGPT 4.14.4版本默认工作流超时为120秒，针对多步骤数据处理流程延长至600秒，避免中途终止 |
| `maxContext` | `8000 字符` | 单份日报的解析后文本长度通常在3000-6000字符，预留足够上下文供大模型完成总结与分析 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流运行超过120秒后被强制终止，状态码返回`504 Gateway Timeout`。原因是未调整`workflow_timeout`参数的取值，沿用FastGPT默认的短超时设置，无法覆盖商业物业融资日报的多步骤数据处理流程。
- 现象为工作流节点中无法选择已配置的大模型，界面提示`模型未启用或无权限`。原因是未在工作流的模型配置节点中勾选`允许工作流调用`选项，且未确认当前账号的模型权限范围，4.14.4版本需额外检查全局模型配置的启用状态。
- 现象为本地部署场景下，通过http请求节点接收的融资日报文件无法被后台接口正确解析，接口返回`400 Bad Request`错误码。原因是未在http请求节点中设置请求头`Content-Type`为`application/json`，且未将TXT文件内容封装为JSON格式的字段，导致后台接口无法读取请求body中的文件数据。

## 怎么确认配好了
- 手动触发一次工作流，检查定时触发节点的日志是否匹配预设的`schedule_cron`时间，确认触发时机正确。
- 上传一份标准格式的商业物业融资日报TXT文件，检查文件解析节点的输出字段是否与日报表头完全一致，确认解析规则生效。
- 查看工作流的超时日志，确认运行时长未超过配置的`workflow_timeout`取值，验证超时设置合理。
- 在工作流的模型调用节点中，检查已配置的大模型是否出现在可选列表中，确认模型权限与启用状态配置正确。
