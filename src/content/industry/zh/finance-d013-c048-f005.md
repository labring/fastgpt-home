# 城商行融资日报的多轮对话与提示词

## 这个品类的数据长什么样
城商行融资日报的数据主要来源于城商行内部授信审批台账、同业拆借交易系统、人行金融统计报送模块。数据更新节奏为每日凌晨批量生成前一日的全量融资业务记录。单份日报文档结构按业务日期排序，核心字段包含融资主体全称、融资金额（单位：万元）、融资期限、年化融资利率、资金投向领域、授信批复编号，部分日报附带对应业务的审批状态与经办支行信息。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的数据源要求多轮对话需绑定当日业务日期上下文，避免跨日数据混淆。多字段且带明确单位的结构，要求提示词中需统一字段单位规则，例如将融资金额统一换算为万元单位输出。部分字段存在空值的情况，需在多轮对话中主动询问用户是否需要补充查询对应缺失信息。融资主体需使用全称匹配，多轮对话需保留用户指定的主体名称，避免简称与全称的匹配误差。此外，日报附带的经办支行与审批状态字段，可根据用户需求在多轮对话中切换展示维度，需在提示词中明确可支持的维度范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 前10轮对话上下文 | 城商行融资日报字段较多，10轮上下文可覆盖常规多轮查询需求，避免模型混淆业务主体与日期 |
| `toolCallMaxTurn` | 5次 | 融资日报查询可能需要依次调用数据库工具获取不同字段，5次调用可覆盖常规多字段联合查询需求 |
| `systemPrompt` | 仅基于当日城商行融资日报数据作答，融资金额统一以万元为单位，需明确标注字段单位，若字段为空需主动说明 | 匹配日报的每日更新频率与字段单位要求，避免跨日数据与单位错误 |
| `召回条数` | 按业务场景标定 | 单份日报业务条目数量存在差异，需根据实际数据量调整召回范围以覆盖用户查询需求 |
| `相似度阈值` | 按主体匹配精度标定 | 融资主体全称匹配要求较高，需根据数据中的简称与全称分布调整阈值 |
| `fileParseChunkSize` | 800字符 | 日报字段较多，800字符的分段可保留字段关联关系，避免拆分后丢失业务上下文 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用MySQL工具获取融资日报数据时返回400 status code (no body)。原因：未在工具配置中指定正确的数据库表名与日期过滤字段，导致查询语句语法错误。
- 现象：通过Docker Compose本地化部署后无法清除指定对话记录。原因：未通过环境变量`CLEAR_HISTORY_ENABLED`开启对话记录清理功能，或未指定清理的对话ID参数。
- 现象：通过网页分享应用后无法取回历史对话记录。原因：未开启对话记录持久化配置，或未在分享链接中携带历史对话的关联参数。

## 怎么确认配好了
- 发起单轮查询，输入指定日期的融资日报查询需求，核对返回结果的业务日期与查询要求一致。
- 发起多轮对话，先指定融资主体与资金范围，再追加查询对应业务的审批状态，核对模型是否保留之前的查询条件。
- 调用数据库工具测试查询，核对返回结果的字段与日报文档中的核心字段一致。
- 切换模型后发起多轮查询，核对历史对话上下文是否被正确加载并参与当前作答。
