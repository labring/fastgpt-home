# 基建工程融资日报的工作流编排

## 这个品类的数据长什么样
基建工程融资日报的数据主要来源于项目承建方的内部台账、合作银行的放款明细、地方住建部门的基建项目备案系统及央行企业融资监测平台。数据更新节奏为每日凌晨同步前一日的融资发生额与台账变动。单份日报文档以结构化表格形式呈现，核心字段包含项目唯一编码、项目名称、所属行政区划、总投资额度、当期融资到位额、融资主体类型、合作放款机构，其中金额类字段单位统一为万元，行政区划字段精确到县级行政区。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散且字段命名存在差异，工作流需配置多源数据拉取节点，并预设字段映射规则统一标准化字段。每日更新的节奏要求工作流设置每日凌晨定时触发，同时需配置增量同步逻辑避免重复录入历史数据。金额类字段的单位约束要求工作流内置单位校验规则，防止出现非万元数值混入。项目编码的固定格式要求在数据清洗环节添加格式校验节点，过滤不符合编码规则的异常条目。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `SCHEDULE_CRON_EXPRESSION` | `0 0 1 * * *` | 基建工程融资日报为前一日业务数据，凌晨1点触发可覆盖全量前一日数据，避开当日交易高峰 |
| `MULTI_SOURCE_DATA_MAX_NUM` | `5 个` | 基建工程融资日报的常规数据源不超过5个，超出会增加工作流并发负载 |
| `FIELD_STANDARDIZATION_MODE` | 按行业通用字段映射 | 统一基建工程融资的核心字段命名，降低后续数据清洗与分析的复杂度 |
| `INCREMENT_SYNC_SWITCH` | 开启 | 每日更新的数据仅包含前一日新增条目，增量同步可减少处理耗时与重复数据 |
| `DATA_VALIDATE_TIMEOUT_SECONDS` | `300 秒` | 单份日报的数据条目通常不超过200条，300秒可覆盖全量校验与格式检查 |
| `WORKFLOW_EXPORT_FORMAT` | `JSON + CSV` | 便于后续存档与跨工具调用，满足不同场景的数据使用需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流输出为`Array<Object>`格式的结构化数据，无法直接生成可读文本。原因：未配置文本格式化节点，未将结构化数据转换为自然语言或标准报告格式。
- 现象：添加MCP服务时无法选择HTTP响应的入参变量，界面提示“入参无效”。原因：未提前在工作流中定义对应入参的变量模板，或入参格式不符合MCP服务的校验规则。
- 现象：导出工作流配置后，导入到其他环境时出现节点绑定缺失。原因：导出时未勾选包含依赖的服务配置，导致知识库或MCP服务的关联信息丢失。

## 怎么确认配好了
- 手动触发工作流一次，检查输出的结构化数据是否包含所有预设的标准化字段，字段格式是否符合要求。
- 查看工作流的运行日志，确认定时触发任务是否按预设时间正常启动，无超时或失败记录。
- 测试MCP服务的入参绑定，发起一次模拟调用，确认入参变量能正确传递到HTTP请求中。
- 导出工作流配置文件，导入到测试环境，检查所有节点与依赖服务的绑定关系是否完整。
