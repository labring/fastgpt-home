# 多元控股融资日报的工作流编排

## 这个品类的数据长什么样
多元控股的融资日报数据来源于旗下各业务子公司的融资台账系统、外部监管披露平台及内部资金调拨记录。更新节奏为每日生成T+1日的汇总报表。文档结构采用分层结构化表格，包含主体层级字段，分为合并口径与单体业务板块两个维度。核心字段包括融资主体名称、融资金额（单位：万元）、融资期限（单位：天）、放款日期、资金用途、所属子板块，以及合并汇总后的总融资金额字段。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源包含多套内部系统与外部平台，工作流需配置多数据源并行拉取节点，避免串行拉取导致的耗时过长。由于存在合并口径与单体数据的分层结构，工作流需设置分支节点按主体层级过滤数据，避免字段混淆。由于更新频率固定为每日一次，工作流需绑定定时触发调度，匹配业务报表生成节奏。由于字段维度较多且存在口径区分，工作流需配置字段映射规则，确保合并数据与单体数据的字段定义统一。此外，由于需处理多个子公司的融资数据，工作流需支持循环或并行分支遍历子公司列表，适配多主体的数据处理需求；同时需配置数据校验节点，验证合并汇总字段的计算逻辑与单体数据的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `定时触发周期` | `每日02:00` | 匹配融资日报T+1更新节奏，避开业务高峰时段 |
| `并行分支数` | `3-5个` | 适配多元控股常见的子业务板块数量，避免节点资源过载 |
| `循环迭代范围` | `按控股主体层级遍历` | 适配合并数据与单体数据的分层处理逻辑 |
| `节点超时时间` | `600秒` | 覆盖多数据源拉取与合并计算的整体耗时 |
| `字段映射规则` | `按主体-口径双维度匹配` | 区分合并口径与单体数据的字段定义 |
| `对话日志导出上限` | `按实际对话轮次配置` | 避免长对话记录被截断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置循环节点遍历子公司列表时，仅执行一次循环且无子公司数据输出。原因：未设置`循环迭代范围`为子公司主体列表，默认仅迭代单条空数据。
- 现象：调试模式下工具调用正常，生产模式下返回`504 Gateway Timeout`错误。原因：生产模式下未调整`节点超时时间`参数，默认值不足以覆盖多数据源拉取的耗时。
- 现象：导出工作流对话记录时仅返回最后6条内容。原因：未调整`对话日志导出上限`参数，默认配置截断了长对话记录。

## 怎么确认配好了
- 手动触发配置的定时任务，核对拉取的各子公司融资数据与内部台账的一致性。
- 运行工作流的并行分支节点，查看日志面板是否存在所有分支的执行记录。
- 发起包含多轮对话的测试流程，导出对话记录后确认所有轮次均被包含。
- 调整测试数据量，验证`节点超时时间`参数是否能避免执行中断。
