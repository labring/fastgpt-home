# 家居用品融资日报的工作流编排

## 这个品类的数据长什么样
家居用品融资日报的数据来源包括全国轻工制造行业融资备案台账、地方中小企业融资申报平台的家居品类条目、供应链金融服务平台的家居企业融资记录。数据更新节奏为T+1，即每个工作日更新前一个工作日的申报与放款信息。单条数据为结构化记录，包含「融资主体名称」「融资额度」「融资期限」「抵押物类型」「申报日期」「放款日期」等字段，其中融资额度单位为万元，融资期限单位为自然月，申报与放款日期采用YYYY-MM-DD格式。

## 这些特征在「工作流编排」这一环带来什么约束
家居用品融资日报的多源数据来源导致工作流需要配置多节点拉取与字段对齐，避免不同平台的字段名差异导致数据混乱。T+1的更新节奏要求工作流的定时触发节点需匹配行业数据同步周期，避开高峰时段。细分品类繁多的特点要求工作流必须加入品类过滤与校验节点，仅处理属于家居用品范畴的融资记录，同时统一融资额度、期限的单位格式，防止数据偏差。单条数据的结构化字段较多，工作流的批量处理节点需设置合理分片，避免因单批次数据量过大导致任务超时或节点崩溃。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `定时触发间隔` | 每日 02:00 触发 | 匹配家居用品融资日报T+1的更新节奏，避开行业数据同步高峰 |
| `多源数据拉取超时时间` | 600 秒 | 覆盖多平台数据拉取的延迟，避免因数据源响应慢导致任务中断 |
| `字段校验规则` | 校验「抵押物类型」属于预设家居品类列表 | 过滤非家居品类的融资记录，保证数据准确性 |
| `批量处理分片大小` | 按实测标定（100-200条/分片） | 适配单日报文规模，平衡处理效率与节点稳定性 |
| `空数据处理策略` | 跳过后续节点并记录日志 | 避免在数据源为空时触发不必要的大模型调用 |
| `CHAT_API_KEY` | 在docker-compose.yml的environment字段中配置 | 保证工作流节点调用大模型的权限，解决密钥缺失导致的运行失败问题 |
| `工具调用超时时间` | 300 秒 | 覆盖图表生成、数据导出等工具的执行周期，避免任务超时失败 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流运行后界面提示「无运行结果」，节点日志显示权限报错。原因：未在docker-compose.yml中配置`CHAT_API_KEY`环境变量，或配置格式不符合要求，导致大模型调用节点无法正常拉起。
- 现象：数据源为空时工作流仍触发大模型调用，产生无效计算开销。原因：未设置`空数据处理策略`为跳过后续节点，默认执行了全流程逻辑，触发不必要的大模型搜索与调用。
- 现象：图表工具调用后生成空图，无任何可视化内容。原因：未在工作流中配置「抵押物类型」字段的校验规则，混入了非家居品类的无效融资数据，导致图表生成时无有效绘图字段。

## 怎么确认配好了
- 核对工作流的定时触发配置，确认触发时间与家居用品融资日报的T+1更新节奏一致。
- 运行包含非家居品类融资记录的测试用例，检查日志确认品类校验规则生效，无效条目被过滤。
- 模拟数据源为空的场景，查看工作流是否跳过后续节点并生成对应日志。
- 配置`CHAT_API_KEY`后重启服务，运行节点调用测试，确认无权限报错；调用图表工具节点，传入有效家居品类融资数据，确认图表生成正常。
