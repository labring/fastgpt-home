# 工程机械融资日报的文档解析与分块

## 这个品类的数据长什么样
这个品类的数据主要来自融资租赁公司的每日放款台账、银行工程机械专项融资的日报导出文件，更新节奏为每日一次。文档以Excel格式为主，包含设备型号、设备序列号、融资主体、放款金额（单位：万元）、放款日期、还款周期、担保方等结构化字段，部分配套Word格式的审批备注文档，备注文档多为单页或多页的文字说明。

## 这些特征在「文档解析与分块」这一环带来什么约束
每日更新的Excel文件常包含上万行数据，默认分块规则会合并过多行内容，导致单块数据颗粒度过粗，影响后续RAG分类匹配精度。设备型号、序列号等字段是精准检索的核心，分块时需保留字段与对应融资信息的绑定关系，若拆分不当会丢失关联逻辑。Word格式的审批备注文档存在长文本段落，默认分块可能割裂审批结论与对应设备的关联，导致检索结果无法匹配完整业务逻辑。此外，日报文档的表头格式固定但偶有微调，解析时需适配非刚性的字段识别规则，避免解析错位。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxChunkSize` | 800–1200 字符 | 适配单条完整融资记录的文本长度，避免拆分包含设备型号、放款金额的核心信息块 |
| `chunkOverlap` | 150–200 字符 | 保留跨分段的关键字段关联，防止设备信息与融资主体的绑定关系断裂 |
| `PARSE_EXCEL_USE_HEADER` | 开启 | 适配日报类Excel的固定表头格式，确保解析时正确识别字段名，避免数据错位 |
| `PARSE_EXCEL_MAX_ROWS_PER_CHUNK` | 10–15 行 | 控制单分段内的融资记录数量，避免单块数据过长超出向量模型的输入限制 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 适配包含多设备台账的单日汇总文件大小，防止上传环节中断 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 满足10万行以上Excel文件的解析耗时需求，避免中途终止解析 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传1万行以上的Excel文件后，向量生成环节报错“文本长度超出模型支持上限”。原因：未配置`PARSE_EXCEL_MAX_ROWS_PER_CHUNK`参数，使用默认规则合并了过多行数据，导致单块文本过长。
- 现象：检索结果中出现设备型号与放款金额不匹配的错位内容。原因：未开启`PARSE_EXCEL_USE_HEADER`，解析时未正确识别字段，导致分块时拆分了跨字段的关联信息。
- 现象：长文本Word审批文档的检索结果无法关联设备信息与审批结论。原因：未调整`maxChunkSize`与`chunkOverlap`参数，默认分块长度过短，割裂了完整的审批逻辑段落。

## 怎么确认配好了
- 上传单份1万行以上的Excel测试文件，查看解析后的分块列表，确认每个分块包含的行数符合预设范围。
- 随机抽取一条融资记录，检索对应设备型号，确认检索结果中该设备的融资信息完整且无字段错位。
- 上传单份5万字符以上的Word审批文档，查看分块后的文本片段，确认相邻分块存在重叠的关键字段，无语义割裂。
- 查看解析日志，确认无“文件解析超时”“文本过长”类报错，配置项的实际取值与预设值一致。
