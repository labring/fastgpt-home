# 房建工程融资日报的工作流编排

## 这个品类的数据长什么样
房建工程融资日报的数据主要来源于项目现场资金台账、合作银行的融资到账回执、工程进度款拨付凭证及属地住建部门的项目备案信息。数据更新节奏为每日同步当日资金变动情况，单份日报文档结构固定，包含项目唯一标识、项目名称、融资主体全称、当日融资到账金额、累计融资到位总额、剩余融资缺口额度、对应工程节点的资金需求计划等字段，金额单位统一为万元，工程节点编号采用属地住建部门规定的12位纯数字编码格式。

## 这些特征在「工作流编排」这一环带来什么约束
房建工程融资日报的数据分散来自多个外部系统，要求工作流编排中配置多节点并行拉取不同数据源，且增加数据对账环节校验跨源金额的一致性；每日更新的节奏要求工作流触发周期设置为每日固定时段，需预留银行回执的返回延迟缓冲时间；固定的字段结构要求工作流的信息抽取节点绑定预设的字段映射规则，避免因文档格式变动导致抽取失败；12位工程节点编码的格式要求需配置正则校验节点，过滤不符合属地规范的无效编码数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `workflow_trigger_cron` | `0 0 8 * * ?` | 房建项目的融资日报通常在每日早8点前完成前一日的资金汇总，定时触发可匹配常规报送节奏 |
| `data_source_pull_timeout` | `600 秒` | 合作银行回执的返回延迟通常在5-10分钟区间，600秒的超时设置可覆盖多数延迟场景 |
| `field_extract_mapping` | 按文档固定字段顺序绑定预设映射 | 房建融资日报的字段结构固定，绑定映射可避免因文档排版变动导致的抽取错位 |
| `regex_validation_rule` | `^[0-9]{12}$` | 属地住建部门规定的工程节点编码为12位纯数字格式，该正则可过滤无效编码 |
| `workflow_concurrency_limit` | `1 个/项目` | 单项目的融资日报数据唯一，并发执行会导致累计融资额等字段的重复计算 |
| `llm_error_retry_count` | `2 次` | 大模型返回空或报错多为临时网络波动，重试可降低非永久性失败的概率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：大模型节点返回空内容或返回`500 Internal Server Error`，工作流直接终止。原因：未配置大模型节点的失败重试与兜底分支，仅依赖默认的失败处理逻辑。
- 现象：工具选择节点同时触发多个工具执行，导致系统资源占用过高。原因：未设置工具选择的互斥触发规则，未限定单次仅执行一个工具分支。
- 现象：多工作流场景下，调用指定工作流时触发了错误的工作流实例。原因：未在调用节点中绑定唯一的工作流标识参数，导致触发默认或其他工作流。

## 怎么确认配好了
- 手动触发一次工作流，核对抽取的字段与原始日报文档的字段是否完全匹配，调整`field_extract_mapping`配置直至匹配正确。
- 模拟银行回执延迟的场景，验证`data_source_pull_timeout`的取值是否足够覆盖延迟，避免触发超时失败。
- 提交不符合12位编码的测试数据，确认`regex_validation_rule`会过滤无效数据并抛出明确提示。
- 同时触发多个同项目的工作流实例，验证`workflow_concurrency_limit`是否生效，避免并发执行导致的数据错误。
