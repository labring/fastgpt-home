# 整车融资日报的多轮对话与提示词

## 这个品类的数据长什么样
整车融资日报的数据来源于车企供应链金融系统、合作银行授信台账、经销商融资报备平台。数据更新节奏为每日凌晨完成前一日全量数据同步，生成当日专属日报文档。文档结构包含头部汇总统计区与明细列表区，明细区按经销商分组，核心字段包括整车识别码VIN、经销商统一社会信用代码、放款金额（万元）、融资到期日、授信额度（万元）、回款状态。字段单位统一为万元与YYYY-MM-DD格式，单份日报文档通常包含数十条明细条目。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的特性要求多轮对话上下文必须严格区分当日与历史数据，避免模型混用过期信息。结构化字段多且存在明确单位与格式，提示词需明确指定字段提取规则，防止模型混淆VIN与经销商名称、万元与元等单位。明细条目数量较多，多轮对话中需要逐步引导模型聚焦特定维度，避免一次性返回过多冗余内容。文档结构的分层设计要求提示词先提取汇总信息，再拆分对应明细，确保回答逻辑清晰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 15000–20000 字符 | 单份整车融资日报明细条目较多，加上历史交互上下文，需要足够窗口保留当日最新数据与多轮对话记录 |
| `systemPrompt` | 固定指定「仅基于当日整车融资日报数据作答，字段需严格匹配VIN、放款金额（万元）、融资到期日格式」 | 明确数据范围与字段规则，避免模型调用过期数据或生成不符合格式的结果 |
| `toolCallMaxTurn` | 3–5 轮 | 多轮对话中需依次确认经销商、车型、回款状态等细分查询维度，合理轮次平衡交互完整性与上下文溢出风险 |
| `relevanceThreshold` | 0.75–0.85 | 结构化字段的匹配精度要求较高，该阈值可过滤无关明细，确保召回结果与查询意图高度匹配 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 单份日报包含多页结构化明细，足够的解析时间可完成全量字段提取，避免内容截断 |
| `maxToken` | 8000–10000 | 单轮回答需完整呈现多组融资明细，足够的token数可避免关键内容被截断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用工作流时返回`400 Bad Request`，提示「payload字段格式错误」。原因：未按照FastGPT规范拼接appId参数，错误将工作流ID与应用ID混淆。
- 现象：多轮对话次日查询时，模型仍使用前一日的融资日报数据作答。原因：未设置`maxContext`过滤过期上下文，或系统提示词未明确要求仅使用当日数据。
- 现象：通过API调用上传整车融资日报文件时，返回「文件解析失败」。原因：未调整`UPLOAD_FILE_MAX_SIZE`参数匹配日报文件实际大小，或未在提示词中指定结构化字段的提取规则。

## 怎么确认配好了
- 发起单轮查询，输入「请列出今日所有经销商的放款金额」，核对返回结果是否仅包含当日融资日报中的数据，字段格式是否符合预设要求。
- 发起连续3轮对话，依次查询不同经销商的融资明细、到期日、回款状态，核对上下文是否被正确保留，未出现内容丢失或数据混淆。
- 通过API调用上传一份测试用整车融资日报文件，核对返回的解析结果是否包含所有核心结构化字段，无缺失或格式错误。
- 调整`relevanceThreshold`参数，对比不同取值下的召回结果，选择符合业务场景的阈值区间。
