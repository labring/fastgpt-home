# 文娱用品融资日报的HTTP 接口与外部系统

## 这个品类的数据长什么样
文娱用品融资日报的数据来源于全国企业信用信息公示系统、地方金融监管局公开融资备案、行业垂直媒体公开报道。数据更新节奏为每日凌晨完成前一日披露信息的汇总整合。单条数据文档结构包含以下字段：`corp_name`（文娱用品生产/经销企业全称，字符串类型）、`product_category`（细分品类，如盲盒、办公文具、户外露营装备等，字符串类型）、`fin_amount`（融资金额，单位为万元，数字类型）、`fin_round`（融资轮次，如天使轮、Pre-A轮等，字符串类型）、`investors`（参与投资方列表，数组类型）、`disclose_date`（信息披露日期，格式为YYYY-MM-DD的字符串类型）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
文娱用品融资日报的数据特征会对HTTP接口与外部系统对接带来多维度约束。首先，数据包含`investors`数组类型字段，要求接口支持JSON格式的嵌套数据解析与传输，外部系统需兼容数组类型的响应字段。其次，`product_category`存在多个细分品类，接口需提供按品类筛选的查询参数，且需校验传入的品类值是否属于合规范围。另外，`disclose_date`为每日更新的日期字段，接口需支持YYYY-MM-DD格式的日期查询参数，同时需限制查询日期范围不超过当前日期，避免请求无效数据。最后，`fin_amount`固定以万元为单位，外部系统对接时需统一单位转换逻辑，避免与其他品类的融资数据单位混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `request_timeout` | `30 秒` | 单条融资日报数据量较小，30秒可完成请求与解析，避免任务超时 |
| `response_parse_mode` | `JSON 模式` | 接口返回标准JSON格式数据，包含嵌套数组字段，JSON模式可直接解析所有合规字段 |
| `query_date_range` | `最近1 日` | 数据为每日更新的融资日报，仅需获取前一日披露信息，避免拉取冗余历史数据 |
| `category_filter` | `文娱用品全品类` | 需过滤非文娱品类的融资数据，仅保留匹配`product_category`字段的结果 |
| `field_mapping` | `corp_name→企业名称, product_category→品类, fin_amount→融资金额, disclose_date→披露日期` | 将接口原始字段映射为知识库可识别的标准化字段，便于后续检索与调用 |
| `max_response_size` | `200 KB` | 单日融资条目数据总量较小，200 KB可容纳所有有效数据，避免超出接口响应限制 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用嵌入接口时返回`{"error":{"code":"Invalid"}}`格式的报错。原因：未将融资日报的`fin_amount`字段转换为字符串类型，多模态Embedding模型要求输入字段为统一的文本格式，数字字段未做序列化处理导致参数格式错误。
- 现象：接口请求超时，返回状态码504。原因：配置的`request_timeout`取值过短，单日融资条目较多时，接口响应时间超过预设阈值，导致任务中断。
- 现象：知识库中插入的融资日报数据缺少`product_category`字段。原因：未正确配置`field_mapping`参数，未将接口返回的`product_category`字段映射到知识库的目标字段，导致字段丢失。

## 怎么确认配好了
- 发起一次测试请求，查看接口返回的原始数据，确认`disclose_date`字段为前一日的YYYY-MM-DD格式，且所有条目均属于文娱用品品类。
- 检查知识库中已同步的融资日报数据，确认所有字段均已正确映射，无缺失或格式错误的字段。
- 模拟多次连续请求，确认接口响应时间符合预设的`request_timeout`配置，未出现超时中断的情况。
- 调整`category_filter`参数为指定细分品类，确认接口仅返回对应品类的融资数据，无冗余条目。
