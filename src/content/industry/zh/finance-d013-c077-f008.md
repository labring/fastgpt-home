# 旅游景区融资日报的工具调用与插件

## 这个品类的数据长什么样
旅游景区融资日报的数据来源包含文旅部门公开的景区运营监测数据、地方金融监管局披露的文旅企业融资备案信息、第三方文旅产业服务平台的融资对接数据。数据每日更新，文档以结构化表格搭配简短说明呈现，核心字段包括景区名称、所属区域、当日客流人次、当日营收万元、融资对接主体、融资额度万元、融资方式、披露日期，其中融资方式包含股权、债权、文旅专项补贴等枚举类型。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散，需同时调用政务公开、第三方产业平台等多类接口，工具调用需配置多源聚合逻辑，避免单次调用遗漏关键信息。数据每日更新的属性要求工具触发周期固定为自然日，不宜设置更短间隔，防止重复请求占用接口资源。字段包含带单位的数值项与枚举类型，插件需配置单位校验与标准化转换规则，确保不同来源的数据格式统一。景区名称易出现重名情况，需绑定所属区域字段作为唯一标识，工具调用时需强制传入区域参数，避免数据匹配错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `scheduled_trigger_cron` | `0 8 * * *` | 融资日报通常在每日早间发布，适配业务报送与决策的常规节奏 |
| `plugin_request_max_size` | `10 MB` | 融资日报结构化数据量较小，设置合理上限避免触发413 Request Entity Too Large错误 |
| `model_tool_allowed_types` | `["function_call"]` | 限制模型仅使用工具调用模式，避免qwen3等模型默认触发推理模式干扰工具调用流程 |
| `hide_tool_log` | 开启 | 面向业务人员的输出无需展示内部调用细节，聚焦最终日报内容，同时保护接口敏感信息 |
| `tool_call_max_retry` | `2 次` | 应对政务接口偶发波动，避免过度重试占用接口资源与增加调用成本 |
| `mcp_stream_enable` | 按需求开启 | 当需要流式返回工具调用进度时启用，适配实时更新的业务场景 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用工具接口返回413 Request Entity Too Large错误。原因是未正确配置`plugin_request_max_size`参数，传输的数据量超过接口预设上限。
- 工具调用时qwen3模型仍生成非工具调用的推理内容。原因是未配置`model_tool_allowed_types`参数限制模型调用模式，导致模型未强制遵循工具调用规则。
- 工具返回的景区数据出现跨区域重名混淆。原因是未在工具调用参数中绑定所属区域字段作为唯一标识，仅使用景区名称进行筛选，导致匹配到错误的景区融资信息。

## 怎么确认配好了
- 手动触发一次工具调用，检查返回结果是否仅包含预设的核心字段，无冗余无关信息。
- 查看工具调用日志，确认触发周期符合配置的`cron`表达式，未出现超出预设次数的重试操作。
- 测试传入带重名区域的景区参数，检查返回结果是否正确匹配对应区域的融资数据，未出现跨区域混淆。
- 开启`hide_tool_log`配置后，查看终端输出，确认未展示工具调用的内部请求细节与接口敏感信息。
