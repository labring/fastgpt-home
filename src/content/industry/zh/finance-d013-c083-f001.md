# 水务融资日报的HTTP 接口与外部系统

## 这个品类的数据长什么样
水务融资日报的数据来源包括地方住建部门水务项目备案库、合作金融机构的授信报送接口、公开招投标的融资公告整理。数据更新节奏为自然日更新，每日生成当日全量的水务项目融资记录。单条数据包含项目基础信息、融资核心要素与审批状态三类内容，字段包括项目编号、项目名称、所属区域、融资金额、融资方名称、资金方类型、融资期限、审批状态与发布日期，其中融资金额单位为万元人民币，融资期限单位为自然月。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
水务融资日报的多源数据特征与日更节奏，对HTTP接口与外部系统对接带来明确约束。首先，多源字段的命名与单位差异，要求接口对接时需配置统一的字段映射规则，避免数据解析错误。其次，日更的时效性要求，需限制接口调用频率与重试次数，确保在当日数据窗口期内完成同步。此外，水务项目融资涉及大额资金，接口请求的响应耗时需适配多源数据聚合的场景，同时需匹配外部系统的限流规则，避免触发调用限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `HTTP_REQUEST_TIMEOUT` | `300 秒` | 水务融资日报需对接多源外部系统，聚合数据的响应耗时较长，300秒可覆盖多数常规聚合场景 |
| `FIELD_MAPPING_RULE` | 按「项目ID→项目编号」「融资金额→授信额度」映射单位为万元 | 不同外部系统的字段命名与单位存在差异，需统一为水务融资日报的标准字段与单位 |
| `RETRY_MAX_TIMES` | `2 次` | 日更数据的窗口期有限，避免重试占用过多时间错过当日数据更新 |
| `REQUEST_RATE_LIMIT` | `1 次/分钟` | 多数政务与金融机构接口的调用频率限制为每分钟不超过2次，适配水务融资日报的日更需求 |
| `RESPONSE_STATUS_CHECK` | 校验状态码为200且包含「项目列表」字段 | 确保接口返回有效数据，过滤异常空响应与错误状态 |
| `AUTHENTICATION_TYPE` | `Bearer Token` | 多数政务与金融接口采用标准令牌认证，适配水务融资日报的外部系统对接场景 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用外部接口返回`400 Bad Request`，字段`融资金额`为空或格式错误。原因：未按水务融资日报的标准单位转换外部系统返回的原始数据，导致接口校验失败。
- 现象：通过HTTP接口上传水务项目的融资批复文档时，返回`413 Payload Too Large`。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，默认限制无法覆盖水务项目大额批复文档的上传需求。
- 现象：对接政务接口时返回`429 Too Many Requests`，当日数据未完成同步。原因：未设置合理的`REQUEST_RATE_LIMIT`，调用频率超过外部系统的限制阈值。

## 怎么确认配好了
- 调用测试接口，检查返回数据的字段是否与预设的`FIELD_MAPPING_RULE`匹配，单位是否符合水务融资日报的标准要求。
- 模拟当日数据更新场景触发接口调用，确认在预设的`REQUEST_RATE_LIMIT`下未触发限流报错。
- 查看接口调用日志，确认请求在`HTTP_REQUEST_TIMEOUT`时限内完成，无超时中断。
- 触发一次模拟失败的请求，确认按`RETRY_MAX_TIMES`完成重试后返回有效数据。
