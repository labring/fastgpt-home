# 水务融资日报的部署与升级

## 这个品类的数据长什么样
水务融资日报的数据主要来自区域水务集团内部融资台账、地方公共资源交易中心的水务项目融资公示、合作银行的授信到账回执。更新节奏为每日固定时段同步前一日的融资动态。单篇日报文档包含项目名称、所属行政区域、融资金额、融资主体、融资方式、审批状态、到账日期、关联水务设施类型共8个核心字段，其中融资金额单位为万元，日期采用YYYY-MM-DD标准格式，关联设施类型标注为管网、水厂、污水处理厂等细分类别。

## 这些特征在「部署与升级」这一环带来什么约束
每日更新的数据源要求部署时配置固定时段的增量同步任务，避免全量拉取占用过多系统资源。多字段结构要求在知识库配置中预设自定义分类标签，关联设施类型需提前枚举固定枚举值，确保后续数据解析的一致性。融资金额以万元为单位，需在数据解析环节配置单位归一化规则，统一转换为标准数值格式，避免出现元与万元的单位混淆。多源数据接入需配置去重匹配规则，基于项目名称与到账日期标识唯一记录，避免同一项目的重复入库。升级过程中需保留原有同步间隔、去重规则等核心配置，避免中断日常业务流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `SYNC_DATA_INTERVAL` | `1440 分钟` | 水务融资日报为每日更新，固定每日同步前一日数据，避免间隔过长遗漏业务动态 |
| `PARSE_FIELD_ENUM_MAP` | `{"关联水务设施类型": ["管网", "水厂", "污水处理厂"]}` | 匹配水务融资日报的关联设施分类字段，确保解析时正确识别枚举值 |
| `DATA_DEDUPLICATION_KEY` | `["项目名称", "到账日期"]` | 水务项目的名称与到账日期可唯一标识一条融资记录，避免多源同步时重复入库 |
| `PARSE_AMOUNT_UNIT` | `万元` | 水务融资日报的融资金额统一采用万元为单位，配置后可自动完成数值归一化，避免单位混淆 |
| `DB_INIT_TIMEOUT` | `600 秒` | 水务融资日报的数据源较多，初始化数据库时需足够时间完成多源数据校验与入库，避免超时失败 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 单篇水务融资日报的汇总文档通常不超过500MB，预留合理缓冲空间 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：Windows 11 环境下运行`docker build -f ./projects/`命令（针对v4.39.0版本）时出现`failed to compute cache key`错误，原因：未将水务融资日报的数据源目录纳入docker build的上下文路径，导致构建过程无法读取依赖的解析脚本文件。
- 现象：本地部署完成后无法正常创建数据库，报错`1045 Access denied for user 'root'@'localhost'`，原因：未在部署配置文件中正确填写水务融资日报专属数据库的账号密码，默认root权限未开放对应库的写入权限。
- 现象：配置联网搜索后返回的结果中混入非水务类融资记录，原因：未在搜索配置中指定`关联水务设施类型`字段的过滤规则，导致召回结果未限定水务相关数据。

## 怎么确认配好了
- 运行容器状态检查命令，确认所有FastGPT相关容器处于正常运行状态，无异常退出记录。
- 进入知识库管理界面，核对字段枚举映射是否已包含水务融资日报的关联设施类型选项。
- 上传单份模拟的水务融资日报文档，验证解析后的数据字段完整性与单位归一化效果。
- 触发一次手动数据同步任务，检查数据库中是否生成符合预期的记录，无重复条目。
