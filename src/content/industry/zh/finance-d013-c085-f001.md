# 水泥融资日报的HTTP 接口与外部系统

## 这个品类的数据长什么样
水泥融资日报的数据来源于全国建材流通协会的每日大宗商品监测系统，更新节奏为每日1次，当日数据于次日凌晨完成归集并对外发布。单条日报文档为结构化JSON格式，包含`report_date`（报告日期）、`region`（销售区域）、`cement_spec`（水泥标号规格）、`price_ton`（每吨价格）、`stock_ten_thousand`（区域库存量，单位万吨）、`credit_limit`（区域授信额度，单位万元）、`loan_amount`（当日放款金额，单位万元）、`repayment_days`（平均回款周期，单位天）等字段，无冗余嵌套层级。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
上述数据特征对HTTP接口与外部系统对接带来三点约束。首先，每日固定更新的节奏要求接口调用频率需匹配源数据更新周期，避免频繁拉取触发源接口的限流规则。其次，多维度的区域、规格字段要求接口支持按`region`、`cement_spec`、`report_date`的组合查询，否则无法精准获取目标水泥品类的融资数据。最后，金额、周期类字段的单位一致性要求接口返回数据需做标准化处理，否则对接外部系统时需额外执行单位转换操作，增加数据校验的复杂度。此外，单批次数据量较大的特点要求接口需支持分页拉取，避免单次响应体过大导致传输超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `定时触发间隔` | `86400 秒` | 匹配水泥融资日报每日更新的节奏，避免重复拉取导致源接口限流 |
| `请求超时时间` | `30 秒` | 覆盖源接口常规响应时长，预留足够容错空间避免任务中断 |
| `请求参数过滤规则` | `仅保留region、cement_spec、report_date` | 减少源接口的查询负载，仅传递目标查询条件 |
| `响应体字段映射` | `将price_ton映射为cement_price，stock_ten_thousand映射为cement_stock` | 匹配FastGPT知识库的字段命名规范，便于后续检索与调用 |
| `认证方式` | `Header 认证` | 符合源接口的Bearer Token认证标准，提升接口调用安全性 |
| `分页拉取开关` | `开启` | 适配多区域、多规格的水泥融资数据量，避免单次响应体过大 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为接口调用返回`403 Forbidden`状态码，原因是未将API密钥放入`Authorization`请求头，误将密钥放在请求参数中传递。
- 现象为定时拉取任务频繁触发失败，原因是设置的`请求超时时间`过短，未匹配源接口的实际响应时长。
- 现象为FastGPT应用历史版本同步失败，原因是未在外部系统的数据库同步配置中添加`tmbId`字段的映射规则，导致旧版本数据无法被识别。

## 怎么确认配好了
- 手动触发一次接口调用，查看FastGPT的任务日志，确认存在`接口调用成功`的记录，且响应体包含所有配置的映射字段。
- 查看源接口的访问统计面板，确认每日仅发起1次调用，匹配`定时触发间隔`的设置。
- 向外部系统推送一条测试的水泥融资数据，检查外部系统是否能正确解析所有字段并完成存储。
- 检索FastGPT知识库中的水泥融资日报数据，确认字段单位与源数据一致，无转换错误。
