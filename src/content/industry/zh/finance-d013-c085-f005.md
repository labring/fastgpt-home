# 水泥融资日报的多轮对话与提示词

## 这个品类的数据长什么样
水泥融资日报的数据主要来自全国建材工业协会的每日融资监测台账、国内水泥上市企业的公开融资公告、地方工信部门发布的区域水泥企业授信公示。数据更新节奏为每日更新，次日发布前一日的汇总数据。单篇日报文档结构包含发布日期、区域分类、企业主体类型、融资额度、融资方式、执行利率区间、融资期限七个核心字段，额度单位为万元人民币，期限单位为自然月或自然年。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
水泥融资日报的每日更新属性要求多轮对话上下文需绑定当日最新数据集，避免调用过期历史数据导致结果偏差。核心字段包含明确的单位与分类维度，提示词需强制要求AI输出结果严格匹配字段格式与单位，不得混淆额度单位或遗漏核心字段。多轮交互中需逐步引导用户明确筛选条件，先锁定区域、企业类型等粗维度，再细化融资方式、期限等细维度，避免单次请求参数过载导致匹配失效。同时需保留历史交互的筛选上下文，减少重复提问的成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `前 8–12 轮对话上下文` | 水泥融资日报的多轮交互需保留筛选条件，8-12轮可覆盖完整筛选流程且控制Token消耗 |
| `promptTemplate` | `固定格式模板，要求AI严格匹配字段单位与分类，每次交互仅返回匹配当前筛选条件的日报条目` | 水泥融资日报包含明确的字段与单位，固定模板可避免AI生成不符合格式的结果 |
| `streamOutput` | `开启` | 单份水泥融资日报数据量较大，流式输出可避免单次请求超时，同时优化响应体验 |
| `contextRecallCount` | `前 3–5 条历史上下文` | 多轮对话仅需保留最近的筛选条件，过多历史上下文会干扰当前请求的匹配逻辑 |
| `similarityThreshold` | `0.75–0.85` | 水泥融资日报的筛选条件多为精准匹配，该阈值区间可平衡召回精度与覆盖范围 |
| `apiRequestTimeout` | `600 秒` | 批量匹配水泥融资日报数据时，600秒可覆盖完整数据检索与处理流程 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：多轮对话中第二次请求无法读取第一次输出的筛选条件，返回结果为空。原因：未正确配置`maxContext`参数，未保留历史交互的上下文信息，导致AI无法关联前序筛选条件。
- 现象：调用API流式输出时，返回的结果中链接无法跳转新页面，仅覆盖当前页面。原因：未在前端代码中配置流式输出的DOM挂载节点，默认使用当前页面覆盖模式，未实现新页面跳转逻辑。
- 现象：提示词生成的结果中融资额度单位混淆，出现“元”，未使用“万元”。原因：提示词模板未明确要求匹配字段单位，未约束AI的输出格式，导致单位匹配错误。

## 怎么确认配好了
- 发起两轮连续对话，第一轮输入区域筛选条件，第二轮输入融资方式筛选条件，核对AI是否能关联前序条件返回匹配结果。
- 调用API开启流式输出，核对返回结果是否分批次推送，无整体阻塞情况。
- 调整`similarityThreshold`参数，核对返回结果的匹配精度是否符合业务需求，调整阈值至合理区间。
- 上传测试用水泥融资日报文档，核对提示词模板生成的输出是否严格匹配预设的字段格式与单位要求。
