# 汽车零部件融资日报的HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据来自全国汽车零部件供应链金融监测平台、合作银行对公融资台账系统，更新节奏为每日T+1更新前一自然日的全量融资记录。数据以JSON格式封装，核心字段包含：供应商统一社会信用代码、配套主机厂车型系列、当日新增融资笔数、单户最高融资额、当日融资总规模、融资年化费率。其中融资笔数为整数，融资总规模单位为万元，年化费率以基点为单位，无百分比格式。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据多源分散、字段包含标准化企业标识与行业专属编码，且更新节奏固定为每日T+1，这为HTTP接口与外部系统对接带来多项约束。第一，需支持对接至少两类外部数据源，实现跨系统数据聚合；第二，需针对统一社会信用代码、车型系列编码等字段配置严格的格式校验规则，避免非法数据流入；第三，需固定接口返回的单位规则，确保融资总规模以万元为单位、年化费率以基点为单位，无需下游系统二次转换。同时，每日固定更新的特性要求接口定时拉取任务需适配T+1的更新窗口，避免重复拉取或遗漏数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | 600 秒 | 适配多源外部系统的数据聚合耗时，避免单次调用超时中断任务 |
| `VARIABLE_PARSE_MODE` | `/` 路径模式 | 规避多源变量命名冲突，相比{{}}格式更适合多系统对接场景 |
| `RESPONSE_FIELD_MAPPING` | 按核心字段映射 | 匹配本品类固定的供应商编码、融资规模等字段，避免数据错位 |
| `SCHEDULED_TRIGGER_CRON` | 0 2 * * * | 适配每日T+1的更新节奏，在凌晨2点触发前一日数据拉取 |
| `FIELD_FORMAT_VALIDATE` | 开启 | 针对统一社会信用代码、车型系列编码做格式校验，过滤非法数据 |
| `RESPONSE_UNIT_POLICY` | 保留原始单位 | 严格遵循外部系统返回的万元、基点单位，无需下游二次转换 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：使用{{}}格式引用外部系统变量时，出现部分字段为空或解析错误。原因：多源对接场景下同名变量存在命名冲突，{{}}模式无法精准区分不同系统的变量。
- 现象：调用合作银行融资系统接口时返回403状态码，提示令牌无权使用对应接口。原因：未在接口配置中添加匹配目标系统的鉴权令牌，或令牌未被授权访问汽车零部件专属融资数据。
- 现象：定时拉取任务每日执行后，出现部分供应商的融资数据重复或遗漏。原因：未适配本品类T+1的更新节奏，Cron表达式触发时间早于外部系统的数据更新窗口，导致拉取到未完成归档的旧数据。

## 怎么确认配好了
- 手动触发一次HTTP接口调用，核对返回字段与本品类的核心字段列表完全匹配。
- 检查接口鉴权配置，调用外部系统测试接口，确认返回状态码为200且无无权访问提示。
- 查看定时任务的执行日志，确认每日触发时间与配置的Cron表达式一致。
- 校验返回数据的单位，确认融资总规模以万元为单位、年化费率以基点为单位，无格式转换错误。
