# 消费电子融资日报的工具调用与插件

## 这个品类的数据长什么样
消费电子融资日报的数据源为公开股权融资披露平台、行业第三方监测数据库，每日更新当日披露的消费电子赛道企业融资信息。单条文档为结构化融资记录，包含融资方全称、所属消费电子细分品类（如智能穿戴、智能手机、智能家居）、融资金额、融资轮次、投资方名单、披露日期、注册地区等字段。融资金额单位以人民币万元或亿元为主，融资轮次采用标准化表述，披露日期采用YYYY-MM-DD格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
消费电子赛道细分品类较多，工具调用需配置精准的赛道筛选规则，避免混入其他行业融资数据。每日更新的频率要求工具触发间隔匹配自然日周期，且需支持增量数据拉取避免重复处理。字段中融资金额存在单位差异，需工具内置归一化逻辑统一格式。投资方为数组类型字段，需工具支持多值解析与存储。同时，消费电子融资记录的字段较多，需工具仅提取核心业务字段，减少数据冗余与处理开销。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `trigger_cron` | `0 0 * * *` | 匹配消费电子融资日报的每日更新节奏，每日凌晨触发一次调用 |
| `filter_fields` | `["融资方名称", "融资金额", "融资轮次", "披露日期"]` | 仅提取业务核心字段，减少非必要数据传输与存储 |
| `request_timeout` | `120 秒` | 适配第三方融资数据接口的普遍响应延迟，避免单次调用超时中断 |
| `workflow_nested_call` | `启用独立上下文` | 避免工作流嵌套调用时出现上下文污染，解决工作流执行不完整的问题 |
| `error_retry_count` | `3 次` | 应对第三方接口临时波动，降低单次调用失败的概率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流A调用工作流B后，仅执行部分节点未完成全流程。原因是未在工作流B中配置代码运行节点或指定回复输出，导致执行链路中断。
- 现象为调用第三方融资数据接口时返回`Error: write EPROT`错误。原因是未配置正确的HTTPS证书校验参数，或网络代理设置存在冲突。
- 现象为工具返回的融资记录中融资金额字段单位不一致，部分为亿元部分为万元。原因是未配置字段归一化规则，未对金额单位进行统一转换。

## 怎么确认配好了
- 手动触发工具调用，检查返回的融资记录是否仅包含消费电子赛道的条目，核对筛选规则是否生效。
- 查看工具调用日志，确认触发间隔符合预设的Cron表达式，无异常超时记录。
- 检查工作流嵌套调用的日志，确认工作流B的所有节点均执行完成，无上下文丢失情况。
- 随机抽取多条融资记录，核对融资金额的单位是否统一，确认归一化规则生效。
