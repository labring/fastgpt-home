# 消费电子融资日报的模型接入与配置

## 这个品类的数据长什么样
数据主要来自公开行业监测平台、品牌方供应链披露信息及线下零售终端的回款记录。每日更新前一日的全量数据，文档以结构化CSV或Excel格式交付，包含品牌名称、机型型号、SKU编码、出货量、终端售价、渠道融资额度、回款周期等字段，出货量单位为台，售价与融资额度单位为元，回款周期单位为自然日。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日全量更新的特性要求模型接入时配置定时触发任务，避免频繁调用产生冗余开销。结构化字段与固定单位的要求，需要在模型配置中开启结构化数据解析模式，同时预设字段映射规则，确保提取的数值与单位匹配。SKU编码作为唯一标识的字段，需要配置召回匹配的主键规则，避免跨机型数据混淆。数值型字段的固定单位要求，需在模型提示词中明确单位校验逻辑，防止提取结果出现单位偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `structured_parse_mode` | 强制结构化解析 | 消费电子融资日报为结构化格式，需严格匹配预设字段与单位 |
| `RECALL_PRIMARY_KEY` | SKU编码 | 该字段为消费电子融资日报的唯一标识，可避免跨机型数据混淆 |
| `system_prompt` | 仅提取SKU编码、出货量、融资额度、回款周期字段，数值保留原单位，回款周期以自然日为单位 | 匹配该品类数据的字段与单位要求，明确提取规则 |
| `max_context` | 800–1200 字符 | 单份消费电子融资日报的结构化内容长度适中，该区间可覆盖全量字段信息 |
| `similarity_threshold` | 0.85–0.9 | 需精准匹配SKU编码，避免低相似度的无关数据被召回 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 全量消费电子融资日报数据量较大，需预留足够的解析时间 |
| `temperature` | 0.1 | 保证字段提取的准确性，避免随机偏差 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：模型调用时报错，OneAPI日志中显示请求令牌为「fastgpt」。原因：FastGPT的模型接入配置中，令牌参数未正确填入，或被默认占位符覆盖。
- 现象：模型提取的文本内容正确，但无法将提取值赋值到目标字段。原因：未配置结构化字段映射规则，或系统提示词未明确要求字段赋值逻辑。
- 现象：定时触发的模型解析任务超时失败。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时间不足以处理全量消费电子融资日报数据。

## 怎么确认配好了
- 手动上传单份消费电子融资日报的结构化文件，检查解析结果是否完整提取了预设字段，且单位与原数据一致。
- 发起单次模型调用，验证提取的字段值与原文档中的数值完全匹配，无单位偏差。
- 查看调用日志，确认请求令牌与配置的令牌一致，无异常占位符。
- 运行一次定时任务，检查任务是否在预设时间内完成，无超时报错。
