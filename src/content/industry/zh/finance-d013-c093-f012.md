# 游戏融资日报的模型接入与配置

## 这个品类的数据长什么样
游戏融资日报的数据来源于游戏行业垂直产业数据库、公开融资披露公告及券商行业研报。更新节奏为每个工作日同步最新披露的融资动态。单篇日报文档以结构化条目组织，每条融资记录包含`融资方名称`、`赛道细分标签`、`融资金额（万元人民币）`、`投资方名单`、`融资轮次`、`披露日期`、`关联游戏产品`七个核心字段，其中`披露日期`采用YYYY-MM-DD格式，`融资金额`字段仅记录人民币计价的公开披露数值。

## 这些特征在「模型接入与配置」这一环带来什么约束
游戏融资日报的结构化字段多且包含细分赛道标签，要求模型接入时配置字段映射规则，避免将赛道标签与融资方名称混淆。工作日更新的节奏要求接入链路支持定时增量拉取，避免全量同步占用过多计算资源。`融资金额`字段仅接受人民币计价数值，需配置数值过滤规则，过滤非合规单位的异常条目。`披露日期`存在固定格式要求，需配置日期解析适配逻辑，完成不同数据源的格式转换。单篇日报包含多条融资条目，需配置上下文长度适配参数，避免批量处理时出现上下文溢出。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 单篇游戏融资日报包含多条结构化条目，需适配批量数据处理的上下文长度需求，避免溢出 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 游戏融资日报的结构化条目较多，解析耗时高于通用文档，需预留足够处理时间 |
| `field_mapping` | `按`融资方名称`映射至`融资方ID`、`赛道标签`映射至`赛道细分标签` | 游戏融资日报的核心字段存在固定对应关系，可提升模型对结构化数据的识别准确率 |
| `incremental_sync_interval` | `86400 秒` | 游戏融资日报按工作日更新，每日同步可覆盖最新披露的融资动态 |
| `model_output_language` | `英文` | 匹配用户配置的英文prompt与英文知识库需求，避免出现非预期的中文输出 |
| `value_filter_rule` | `仅保留单位为`万元人民币`的条目` | 游戏融资日报的`融资金额`字段需统一计价单位，确保数据一致性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：模型输出结果为中文，但配置的prompt与知识库均为英文。原因：未正确配置`model_output_language`参数，默认启用了中文输出模式。
- 现象：上传游戏融资日报文档时返回`413 Request Entity Too Large`错误。原因：未调整`UPLOAD_FILE_MAX_SIZE`参数，文档大小超过系统默认限制。
- 现象：解析后的`赛道细分标签`字段出现大量空值。原因：未配置`field_mapping`规则，模型无法准确匹配日报的细分赛道字段与系统预设字段。

## 怎么确认配好了
- 触发一次增量同步任务，查看同步日志中的`披露日期`字段是否与数据源的最新日期一致，根据实际数据源的日期格式调整`date_parse_format`参数。
- 上传单篇游戏融资日报文档，查看解析后的结构化字段是否完整，调整`field_mapping`规则以匹配实际字段对应关系。
- 配置英文prompt并发起测试请求，确认模型输出语言与预设的`model_output_language`参数一致，不符合则调整该参数。
- 检查`value_filter_rule`的生效情况，确认仅保留了符合计价单位的融资条目，调整过滤规则以适配数据源的单位格式。
