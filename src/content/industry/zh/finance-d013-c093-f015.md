# 游戏融资日报的部署与升级

## 这个品类的数据长什么样
游戏融资日报的数据主要来自国内创投数据库、游戏厂商公开披露的融资公告、第三方游戏行业数据机构的赛道监测信息。更新节奏为每日固定时段更新，覆盖前一自然日的全部游戏赛道融资披露内容。单条文档结构包含融资方全称、融资金额、融资轮次、投资方机构、融资披露日期、核心游戏产品、所属赛道等字段，融资金额以人民币或美元为计价单位，核心游戏产品字段标注对应融资方的主力在研或上线游戏品类。

## 这些特征在「部署与升级」这一环带来什么约束
游戏融资日报的数据特征对部署与升级环节带来多项具体约束。首先，数据来源分散且覆盖多平台披露内容，需配置多源拉取校验规则，避免数据遗漏或重复。其次，更新节奏为每日固定时段拉取，需匹配定时任务触发周期，确保每日自动拉取前一自然日的融资数据。此外，数据包含`核心游戏产品`、`所属赛道`等非通用字段，需配置自定义字段映射规则，适配业务检索需求。融资金额存在双计价单位，需配置单位自动转换逻辑，统一展示格式。单日数据量波动范围较大，需配置自适应资源调度参数，应对突发增量压力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `SCHEDULE_CRON` | `0 2 * * *` | 匹配融资日报的每日更新节奏，避开业务高峰时段完成前一日数据拉取 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 单条融资日报文档包含细分赛道、核心产品等多字段，解析耗时高于通用文档 |
| `FIELD_MAPPING_RULES` | 按实测标定 | 游戏融资数据包含非通用字段，需自定义映射适配业务需求 |
| `CURRENCY_CONVERT_ENABLE` | `开启` | 融资数据同时存在人民币与美元计价，需统一单位便于检索与展示 |
| `DUPLICATE_RECORD_THRESHOLD` | `前 7 天` | 游戏融资项目可能跨平台重复披露，设置7天校验窗口避免有效数据被误删 |
| `MONGO_CONNECTION_POOL_SIZE` | `20–30` | 单日融资数据量波动范围较大，适配增量数据的存储与检索压力 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：拉取融资数据时出现`408 Request Timeout`错误。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，单条文档解析耗时超过默认阈值。
- 现象：本地部署启动后出现MongoDB连接失败报错。原因：未正确配置`MONGO_CONNECTION_STRING`参数，或MongoDB服务未开放对应端口权限。
- 现象：检索结果中出现重复的融资记录。原因：未设置`DUPLICATE_RECORD_THRESHOLD`参数，未开启重复数据校验逻辑。

## 怎么确认配好了
- 执行手动触发的定时拉取任务，核对拉取到的融资数据是否覆盖前一自然日的全部披露信息。
- 查看解析后的字段列表，确认包含`核心游戏产品`、`所属赛道`等自定义配置的业务字段。
- 测试检索特定游戏厂商的融资记录，确认结果无重复且计价单位统一。
- 查看部署日志，确认无`MongoDB连接超时`或`文档解析超时`类错误信息。
