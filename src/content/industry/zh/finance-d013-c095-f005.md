# 热力融资日报的多轮对话与提示词

## 这个品类的数据长什么样
热力融资日报的数据来源于公用热力企业的管网监控平台、收费结算系统与能耗上报端口。每日凌晨完成前一日全量数据汇总，更新节奏为日更。文档以结构化表格形式输出，包含换热站编号、供回水温度、管网压力、当日供热量、累计收费金额、异常告警条目等字段。供热量单位为吉焦，压力单位为兆帕，温度单位为摄氏度，金额单位为人民币元。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
热力融资日报的全量结构化字段多且带物理单位，要求多轮对话需跟踪用户指定的换热站、区域等上下文标识，避免重复请求基础筛选条件。日更的批量数据结构要求提示词明确指定字段的单位与统计口径，防止输出混淆。异常告警字段的离散属性，要求多轮对话支持用户追问单条异常的详情，需保留上一轮交互中的异常条目ID。全量数据的体量要求对话上下文窗口需适配中等长度的历史信息，防止关键上下文丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `6000–10000 字符` | 适配单份热力融资日报的内容长度与多轮交互的历史信息存储需求 |
| `maxHistoryTurns` | `3–5 轮` | 满足用户追问换热站参数、异常详情等多轮交互的上下文保留需求 |
| `systemPrompt` | `固定匹配换热站ID/区域名称，明确字段单位与统计口径，关联异常条目ID` | 适配热力融资日报多字段带单位的结构化特征，避免模型输出混淆 |
| `showChatMessage` | `按节点顺序仅展示核心交互节点输出` | 解决多AI对话节点同时输出导致的对话混乱问题 |
| `contextWindowStrategy` | `按会话保留上下文，超出阈值自动截断最早非核心交互` | 防止长上下文导致的模型响应超时或信息丢失 |
| `retryOnError` | `2 次` | 应对数据接口偶尔波动导致的对话中断，提升交互稳定性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：多轮对话中无法保留用户指定的换热站ID，每次交互需重新输入。原因：未配置`maxHistoryTurns`或取值过低，导致历史上下文被自动截断。
- 现象：工作流运行后，所有AI对话节点的回复均展示在聊天面板中。原因：未将非核心节点的`showChatMessage`配置为关闭状态。
- 现象：提示词未指定单位，模型输出的供热量未标注吉焦或混淆温度与压力单位。原因：系统提示词未明确字段的单位与统计口径，未约束模型输出格式。

## 怎么确认配好了
- 发起测试对话，先指定某换热站ID，再追问该站的供热量，核对模型是否能直接返回结果，无需重新指定换热站。
- 配置多AI对话节点的工作流，运行后查看聊天面板，确认仅核心节点的回复被展示。
- 输入包含单位混淆的提问，核对模型是否能正确识别并按指定单位输出结果。
- 发起连续3轮以上的追问，核对模型是否能保留所有上下文信息，未出现上下文丢失的情况。
