# 物流融资日报的部署与升级

## 这个品类的数据长什么样
物流融资日报的数据主要来自物流企业的运单管理系统、合作金融机构的授信台账接口，以及物流节点的实时定位数据。每日凌晨完成当日全量数据的汇总与校验，生成单份日报文档。文档结构以结构化表格为主，包含运单编号、承运方主体名称、货物总价值、核定融资额度、预计到货时间、逾期履约天数等字段。其中货物总价值与融资额度单位为人民币元，逾期履约天数单位为自然日，运单编号为12-18位字母数字组合的唯一标识。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的每日定时更新特性，要求部署时需预留凌晨0-2点的系统资源，避免定时任务与其他业务进程抢占CPU与内存。多结构化字段的设计，要求在部署阶段完成字段映射校验规则的配置，防止外部接口返回字段缺失或格式异常导致的导入失败。多外部数据源的依赖，要求升级过程中需保留旧版接口的兼容调用逻辑，同时新增新版接口的适配配置，避免升级后数据源中断。单日报文档包含的运单条目较多，需配置合理的批量处理分片阈值，防止单次处理超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `CRON_EXPRESSION` | `0 0 0 * * *` | 匹配物流融资日报每日凌晨生成的更新节奏，确保定时任务按时触发 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份日报包含较多运单条目，解析耗时较长，避免提前超时终止任务 |
| `FIELD_MAPPING_VALIDATION` | `开启严格校验` | 结构化字段较多，严格校验可提前拦截字段缺失或格式错误的导入数据 |
| `UPLOAD_BATCH_SIZE` | `50 条/批次` | 单日报的运单条目通常在50-200条区间，分片处理可平衡内存占用与处理效率 |
| `EXTERNAL_API_RETRY_TIMES` | `3 次` | 依赖外部接口获取数据，重试可降低临时网络波动导致的导入失败 |
| `DATA_DEDUPLICATION_ENABLE` | `开启` | 运单编号为唯一标识，去重可避免重复导入同一份运单的融资数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：执行升级脚本后返回`500 Internal Server Error`，原因：未在升级前停止FastGPT的容器进程，导致端口占用冲突。
- 现象：升级至4.9版本后，外部数据源接口调用失败，返回`401 Unauthorized`，原因：升级后未更新外部接口的鉴权密钥配置，导致鉴权失败。
- 现象：配置外部模型后无法正常调用，返回`model_not_found`错误码，原因：升级后未同步更新模型接入的地址配置，导致模型路由错误。

## 怎么确认配好了
- 查看定时任务日志，确认每日预设时间触发的解析任务正常启动，无启动失败记录。
- 上传测试用的物流融资日报文档，核对解析后的字段与原文档的对应关系，无字段缺失或格式错误。
- 调用配置的外部数据源接口，验证返回数据的字段格式符合预设的映射规则。
- 检查系统资源占用情况，确认定时任务执行时的资源使用未超出预设的限制阈值。
