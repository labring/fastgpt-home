# 环境监测融资日报的工具调用与插件

## 这个品类的数据长什么样
环境监测融资日报的数据来源包括生态环境部门公开的监测点位数据、排污企业自行上报的监测数据、第三方监测服务机构的标准化报告。数据更新节奏分为两类：批量站点数据每日凌晨完成全量同步，实时监测点位支持小时级增量更新。单条数据文档结构包含监测点位编码、点位名称、监测污染物类别、监测值、单位、达标判定结果、关联企业融资申请状态、意向融资金额区间等字段。大气污染物监测值单位多为μg/m³或mg/m³，水质污染物多为mg/L，融资相关字段采用文字状态描述，不使用百分比数值。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源的多样性要求工具调用需适配多种接口格式与认证方式，部分数据源需通过API密钥鉴权，部分需通过文件推送获取数据。不同的更新节奏要求定时触发配置支持灵活调整，小时级增量数据需频繁拉取，日级全量数据则需每日同步一次。多类字段的混合结构要求插件配置需同时映射环境监测与融资关联两类字段，避免仅提取单一类型数据。多样的单位要求工具调用时需自动完成单位校验与转换，防止传参错误导致接口拒绝响应。日报的时效性要求工具调用的超时设置需匹配数据接口的响应速度，避免延迟过长影响日报生成。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_timeout` | `300 秒` | 环境监测数据源接口的常规响应时长在200秒以内，300秒可覆盖峰值延迟且避免资源占用过长 |
| `Content-Type` | `application/json`，支持`application/x-www-form-urlencoded`特殊配置 | 多数监测数据源接口支持json格式，部分老旧接口需使用表单格式，可兼容多数业务场景 |
| `plugin_request_method` | `GET`（日级全量数据）或`POST`（批量实时数据） | 日级监测数据通过GET拉取全量接口，批量实时数据通过POST提交上报数据，匹配数据源接口规范 |
| `incremental_sync_interval` | `1 小时`（实时点位）或`24 小时`（批量站点） | 数据更新节奏分为小时级增量和日级全量两种类型，需与数据源特性对齐 |
| `retry_max_attempts` | `2 次` | 环境监测接口偶发网络波动，2次重试可覆盖多数临时故障且避免重复调用产生的数据冗余 |
| `data_field_mapping` | 按「点位编码→污染物类型→监测值→融资关联状态」的顺序映射 | 文档结构中两类字段需绑定关联，确保工具调用后返回的数据可直接用于融资日报生成 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用环境监测数据源接口返回`400 Bad Request`，字段`monitor_value`为空。原因：未正确配置`Content-Type`，将表单格式数据以json格式提交，导致接口无法解析字段。
- 现象：调用环境监测数据源关联的智能问答接口失败，更换域名后仍无响应。原因：未在插件配置中添加目标数据源的域名白名单，且未将接口请求路径与`request_url`参数绑定，导致跨域或路由匹配失败。
- 现象：生成的融资日报仅包含环境监测数据，缺失关联企业的融资进度信息。原因：未正确配置`data_field_mapping`，未将融资关联字段与监测数据绑定，导致工具返回数据仅提取了环境监测类内容。

## 怎么确认配好了
- 进入插件配置页面，查看`Content-Type`参数是否与目标数据源接口的要求一致，若接口文档未明确则优先使用`application/json`。
- 触发一次手动工具调用，查看返回结果的字段是否包含监测点位、污染物类型、融资关联状态三类核心数据，确认`data_field_mapping`配置正确。
- 查看工具调用日志，确认`tool_call_timeout`未触发超时报错，且重试次数未超过预设的`retry_max_attempts`值。
- 调整`incremental_sync_interval`参数，验证定时任务是否按预期频率拉取数据，确认更新节奏匹配数据源特性。
