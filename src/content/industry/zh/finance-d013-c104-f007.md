# 玻璃融资日报的工作流编排

## 这个品类的数据长什么样
玻璃融资日报的数据来源涵盖国内建材大宗商品交易指数平台、区域经销商上报台账、期货盘面结算价及上游原料行业指导价。数据更新节奏为每日17:00前完成当日全量数据整理，部分偏远区域的经销商数据存在1至2小时的延迟。文档结构以分区域结构化表格为主，附带当日价格波动、区域供需变化的非结构化批注文本。核心字段包含玻璃品类、规格尺寸、当日成交价、环比波动、出库量、区域库存、上游原料指导价等，其中玻璃交易以重量箱为通用单位，上游原料指导价多以吨为单位。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据接入的特性要求工作流配置并行调用节点，避免串行拉取导致总耗时过长。不同数据源的单位差异要求插入专用的单位转换节点，统一玻璃交易的重量箱与上游原料的吨之间的口径。数据更新的时间窗口要求定时触发节点设置在17:30之后，确保拉取到当日最新数据，避免拉取前一日的旧数据。混合格式的数据结构要求同时配置结构化数据提取与非结构化内容解析节点，分别处理表格数据与批注文本。核心字段的校验需求要求在工作流中加入字段合法性校验环节，避免无效数据进入后续流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `定时触发时间` | `17:30 每日` | 玻璃融资日报数据在17:00前完成更新，延迟30分钟触发可确保拉取到最新有效数据 |
| `并行调用节点数` | `4 个并行节点` | 需对接交易平台、经销商数据、期货盘面、上游原料数据四个数据源，并行调用可降低总耗时 |
| `单位转换规则` | `按1重量箱=50千克转换` | 符合玻璃行业通用的重量箱与千克的换算标准，统一数据口径 |
| `结构化提取字段` | `指定提取当日成交价、出库量、区域库存等核心字段` | 仅保留融资日报所需的核心数据，减少后续处理负载 |
| `节点超时阈值` | `600 秒` | 多源数据调用存在网络延迟，600秒可覆盖多数异常场景 |
| `工具调用重试次数` | `3 次` | API调用可能出现临时网络波动，重试3次可降低失败率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中配置的API工具调用节点返回空结果，界面显示「工具调用失败」状态。原因：未在工作流的「变量映射」节点中正确绑定API请求参数与上游提取的玻璃数据字段，导致参数为空。
- 现象：「文本内容提取」节点返回空数组，工作流进入指定回复环节后无法触发后续流程。原因：未配置针对玻璃融资日报批注文本的品类专属关键词匹配规则，未指定「浮法玻璃」「重量箱」等特征词，导致提取失败。
- 现象：工作流中调用大模型的节点返回结果未替换预设变量，提示词中的`{glass_price}`未被实际成交价替换。原因：未在大模型节点的「变量注入」配置中开启自动替换，或变量名与上游提取的字段名不一致。

## 怎么确认配好了
- 触发一次手动运行工作流，查看各节点的输出日志，确认所有API调用均返回有效数据。
- 检查「结构化提取」节点的输出结果，确认核心字段均已正确提取且单位统一。
- 验证「变量注入」配置，确认大模型提示词中的变量与上游提取的字段名完全匹配。
- 查看定时触发节点的历史运行记录，确认每日触发时间符合预设窗口。
