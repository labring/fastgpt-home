# 白色家电融资日报的工具调用与插件

## 这个品类的数据长什么样
白色家电融资日报的数据来源包括家电品牌方的经销商融资管理系统、合作银行的对公融资台账、供应链金融服务平台的每日上报数据。数据更新节奏为每日凌晨更新前一自然日的融资明细。单条数据文档包含主体标识、融资明细、关联库存批次三类核心内容，字段包括`经销商名称`、`融资主体统一社会信用代码`、`当日融资到账额`（单位人民币万元）、`融资期限`（单位自然日）、`关联库存批次数量`（单位台）、`授信机构名称`、`数据上报日期`（格式YYYY-MM-DD）。

## 这些特征在「工具调用与插件」这一环带来什么约束
多数据源的来源要求工具调用需支持跨端点鉴权与数据合并，插件需配置多API的联动执行逻辑。每日更新的节奏要求定时触发工具需匹配数据更新窗口，需设置`CRON_EXPRESSION`参数匹配拉取时机。字段包含`关联库存批次数量`等家电专属属性，要求工具调用时需传递SKU元数据作为入参，插件需预设SKU与融资主体的映射规则，避免数据匹配错位。单条数据维度较多，要求工具调用的字段过滤参数需支持指定提取目标字段，减少无效数据传输。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PLUGIN_DATA_SOURCE_LIST` | `["bank_finance_api", "dealer_finance_api", "sku_meta_api"]` | 覆盖三类数据来源系统，保证融资日报数据的完整性 |
| `CRON_EXPRESSION` | `0 0 2 * * *` | 匹配每日凌晨1点的数据源更新窗口，延后1小时拉取避免数据未同步 |
| `UPSTREAM_API_TIMEOUT` | `30 秒` | 适配多数据源调用的总耗时上限，避免单次调用超时中断 |
| `SKU_MAPPING_ENABLE` | 开启 | 启用SKU与融资主体的映射规则，关联家电库存批次与融资数据 |
| `FIELD_FILTER_LIST` | `["经销商名称", "当日融资到账额", "关联库存批次数量"]` | 提取核心融资日报字段，减少无效数据传输 |
| `API_AUTH_TYPE` | `["bearer_token", "api_key"]` | 适配多数据源的不同鉴权要求，保证接口调用权限 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：通过API调用工作流上传融资日报文件时返回`413 Request Entity Too Large`错误。原因：未配置`UPLOAD_FILE_MAX_SIZE`参数，或取值小于上传文件的实际大小。
- 现象：API调用工作流传入知识库后提示参数错误。原因：未将知识库ID作为工作流入参传递，仅配置全局变量但未在调用请求中绑定对应参数。
- 现象：配置MySQL数据库链接的工具执行SQL后无结果返回。原因：SQL语句未过滤白色家电经销商的专属融资数据，或数据库连接用户未开放对应业务表的查询权限。

## 怎么确认配好了
- 发起单次工具调用，检查返回结果是否包含预设的核心字段，字段格式与数据来源的标准一致。
- 手动触发定时配置的工具任务，确认任务在预期的时间窗口内完成执行且无报错日志。
- 调用工作流并传入知识库ID，确认工作流可正常关联对应知识库的文档并完成召回。
- 测试MySQL工具的SQL查询语句，确认可正常返回对应白色家电主体的融资明细数据。
