# 综合服务融资日报的HTTP 接口与外部系统

## 这个品类的数据长什么样
综合服务类融资日报的数据来源涵盖银行间市场交易商协会披露的同业拆借数据、商业银行公开的信贷投放公告、地方政府融资平台官方披露的融资项目信息，以及央行公开市场操作日报。更新节奏为每个交易日18:00后生成前一交易日的完整数据集，单日更新一次。单条数据文档为结构化格式，包含融资主体统一社会信用代码、融资金额（单位亿元）、融资期限（单位自然日）、融资类型、披露机构、发布日期等字段，单份日报包含数十至上百条融资项目记录。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据的特征要求接口需内置标准化映射规则，将不同数据源的原始字段统一为融资日报的标准字段格式，避免外部系统适配多源格式的成本。固定时点更新的节奏要求外部系统配置每日定时拉取任务，且需兼容数据源延迟披露的情况，接口需返回明确的状态码提示数据未就绪。字段包含统一社会信用代码等标识类信息，要求接口支持按主体代码、融资类型等维度的筛选参数。单份日报条目数波动较大，要求接口支持分页查询与单次返回数据量限制配置，防止传输超时或资源占用过高。同时，公开披露的数据来源要求接口需遵守合规调用限制，避免高频无授权请求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `data_source_filter` | `["bank_interbank", "gov_platform", "credit_bank"]` | 覆盖综合服务融资日报的核心数据源类型，统一数据采集范围 |
| `update_fetch_time` | `18:30 每日` | 匹配多数数据源的披露完成时点，避免拉取未就绪的残缺数据 |
| `page_size` | `50 条/请求` | 平衡传输效率与单次数据量，适配多数外部系统的处理能力上限 |
| `field_mapping_strategy` | `按标准字段映射` | 统一多源数据的格式，降低外部系统的适配与解析成本 |
| `request_rate_limit` | `10 次/分钟` | 符合公开数据源的合规调用要求，防止触发访问封禁 |
| `timeout_threshold` | `600 秒` | 覆盖多源数据拉取与格式转换的耗时上限，避免中途中断请求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用接口返回`400 Bad Request`，且报错文案包含`invalid data source`。原因：未正确配置`data_source_filter`参数，传入了未支持的数据源类型。
- 现象：定时拉取后获取的融资日报数据为空。原因：将拉取时间配置早于数据源披露时点，未匹配`update_fetch_time`的建议取值。
- 现象：外部系统无法区分不同用户的融资日报查询结果，返回包含非授权主体的融资信息。原因：未配置基于请求标识的权限校验逻辑，接口未实现用户维度的数据隔离，对应社区中关于多用户管理交互记录的典型问题。

## 怎么确认配好了
- 发起单次拉取请求，检查返回的字段是否与预设的标准融资日报字段清单一致，验证字段映射生效。
- 配置定时拉取任务，在建议的拉取时点后触发，检查返回数据的发布日期是否为前一交易日，验证更新节奏匹配。
- 模拟不同数据源类型的请求，检查接口是否仅返回配置的`data_source_filter`范围内的数据，验证数据源过滤生效。
- 发起超出`page_size`限制的请求，检查接口是否自动分页或返回合理的截断提示，验证分页配置生效。
