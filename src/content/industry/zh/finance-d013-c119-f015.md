# 综合服务融资日报的部署与升级

## 这个品类的数据长什么样
综合服务融资日报的数据来源涵盖国内主要交易场所、监管机构公开接口及持牌金融机构的官方披露信息。更新节奏为每日固定时点完成当日全量数据更新，文档采用结构化表格格式，包含统计日期、市场板块、融资买入总额、融资余额、融券卖出总额、融券余量、标的数量等字段，单位统一为亿元与家。数据以单文件单日汇总或多标的分行的形式存储，无过度嵌套的非结构化内容。

## 这些特征在「部署与升级」这一环带来什么约束
多源数据接入的需求要求部署阶段配置多组数据源校验规则，避免不同渠道的数据格式冲突。每日固定更新的节奏需要匹配定时任务的触发时机，确保同步数据为当日最新内容。结构化字段较多的特性要求部署时配置准确的字段映射规则，保证数据正确入库与检索。升级过程中需兼容旧版字段映射逻辑，防止因数据源字段调整导致检索失败。数据规模的变化要求配置向量数据库的分片策略，平衡检索性能与资源占用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `CRON_EXPRESSION` | `0 18 * * *` | 匹配多数数据源每日17点后更新的节奏，确保获取当日最新数据 |
| `STRUCTURED_DATA_FIELD_MAPPING` | `{"统计日期":"date","融资买入总额":"buy_total","融资余额":"balance_total"}` | 匹配融资日报的标准字段名，确保结构化数据正确解析入库 |
| `VECTOR_DB_SHARD_COUNT` | `2-4` | 适配单日报文的字段数量与数据规模，平衡检索速度与资源占用 |
| `EMBEDDING_BATCH_SIZE` | `64` | 适配结构化数据的字段长度，避免单次嵌入请求超时 |
| `SCHEDULER_MAX_RETRIES` | `3` | 应对数据源接口临时波动，保证数据同步成功率 |
| `CHAT_HISTORY_EXPIRE_DAYS` | `按业务需求设定` | 控制聊天记录的存储周期，避免冗余数据占用资源 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：升级到V4.14.7.1或V4.14.8版本后，知识库检索耗时明显增加，相同知识库与嵌入模型下检索结果返回变慢。原因：未调整`VECTOR_DB_SHARD_COUNT`参数适配新版向量库的分片策略，导致检索时需要遍历更多分片节点。
- 现象：docker部署时出现插件拉取失败的报错日志，容器持续重启无法正常启动。原因：未配置国内镜像源加速插件拉取，海外网络环境下无法正常获取官方插件包。
- 现象：部署后无法限制聊天记录的保存时长，历史聊天数据持续占用存储资源。原因：未修改`CHAT_HISTORY_EXPIRE_DAYS`参数的默认值，或未在部署配置中开启聊天记录自动清理开关。

## 怎么确认配好了
- 执行一次手动数据同步任务，检查同步日志中是否有字段解析失败的提示，确认`STRUCTURED_DATA_FIELD_MAPPING`配置与数据源字段匹配。
- 发起一条针对融资日报的检索请求，查看返回结果的检索耗时，根据业务需求调整`MAX_RECALL_NUM`与`EMBEDDING_BATCH_SIZE`的取值。
- 检查定时任务的执行记录，确认每日固定时点是否成功触发数据同步，验证`CRON_EXPRESSION`的配置正确性。
- 查看容器的存储占用情况，确认聊天记录自动清理功能是否按配置执行，验证`CHAT_HISTORY_EXPIRE_DAYS`的生效状态。
