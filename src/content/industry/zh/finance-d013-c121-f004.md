# 耐火材料融资日报的向量模型与索引

## 这个品类的数据长什么样
耐火材料融资日报的数据来源于行业融资监测平台、企业公开融资公告、地方金融监管部门的公开备案数据。更新节奏为每日更新，覆盖当日发布的耐火材料相关企业融资项目。文档以结构化记录为主，单条记录包含融资主体名称、统一社会信用代码、融资金额、融资方式、放款时间、融资用途、所属耐火材料细分品类、项目所在区域等字段，部分补充公告为半结构化文本，包含企业经营背景说明。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化与半结构化混合的数据特征，要求向量模型同时适配结构化字段的语义编码与半结构化文本的提取，避免单一编码规则导致的信息丢失。每日增量更新的节奏，要求索引支持增量写入与更新，避免全量重建带来的资源消耗与延迟。包含耐火材料细分品类、区域等专属字段，要求索引支持多字段过滤检索，确保检索结果仅覆盖目标品类与区域的融资项目。融资用途等文本字段通常较短，要求嵌入模型适配短文本的语义召回精度，避免因文本过短导致的向量语义偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `EMBEDDING_MODEL` | `bge-small-zh-v1.5` | 适配耐火材料融资日报的短文本与结构化字段编码，资源占用较低，适合每日增量更新场景 |
| `VECTOR_SEGMENT_LENGTH` | `80-150 字符` | 单条融资记录的核心文本（如融资用途、品类描述）长度集中在该区间，过长分段会引入无关语义，过短则丢失上下文关联 |
| `RECALL_TOP_K` | `前10-15条` | 融资日报的检索需求通常为匹配特定品类或区域的项目，过多召回会增加重排压力，过少则遗漏潜在匹配项 |
| `INDEX_INCREMENTAL_UPDATE` | 开启 | 数据每日增量更新，全量重建索引会占用大量计算资源，增量更新可降低运维成本与更新延迟 |
| `FILTER_FIELD_LIST` | `["融资品类", "所在区域", "放款时间"]` | 耐火材料融资日报的常见检索维度为细分品类、区域与时间，提前配置过滤字段可提升检索精度与速度 |
| `EMBEDDING_BATCH_SIZE` | `32-64 条/批` | 平衡单批嵌入的计算耗时与API调用频率，适配每日新增的中等数据量场景 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：创建索引模型后，调用语言模型时出现“未配置语言模型”报错，或检索结果无法关联语义上下文。原因：误将索引模型的配置覆盖了语言模型的绑定关系，未保留语言模型的独立调用链路。
- 现象：本地部署4.9.6版本时，配置外部索引模型后，导入数据时出现“连接被拒绝”报错（状态码502）。原因：未在本地部署的环境变量中配置外部索引模型的API密钥与访问地址，或防火墙限制了内部服务对外部模型端口的访问。
- 现象：将向量存储从PGSQL迁移到Zilliz后，检索结果出现大量不匹配项，或无法召回历史数据。原因：未统一向量嵌入的模型版本与维度，或迁移过程中未保留原有的索引字段映射规则，导致新索引的向量空间与原数据不匹配。

## 怎么确认配好了
- 上传单条耐火材料融资日报的测试数据，查看嵌入任务的运行日志，确认嵌入模型的调用参数与配置项一致。
- 发起检索请求，输入具体的耐火材料品类名称，核对检索结果是否包含对应品类的融资项目，确认过滤字段配置生效。
- 查看索引的更新日志，确认每日增量更新任务自动触发，无失败记录。
- 检查外部索引模型（若使用）的连接状态，确认接口返回的向量维度与配置的`EMBEDDING_DIMENSION`参数一致。
