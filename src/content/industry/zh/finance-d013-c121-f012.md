# 耐火材料融资日报的模型接入与配置

## 这个品类的数据长什么样
耐火材料融资日报的数据主要来自行业协会公开公示、产业园区融资备案系统、企业工商变更公示及大宗商品交易平台的融资相关披露信息。每日更新单条记录，单份日报文档包含数十条融资条目。每条记录固定字段包括：融资主体名称（耐火材料生产或贸易企业）、融资金额（单位：万元）、融资方式（股权、债权或供应链金融）、融资方所在地、融资用途、信息发布日期。文档格式多为结构化表格或带字段标注的文本文件。

## 这些特征在「模型接入与配置」这一环带来什么约束
耐火材料融资日报的数据源特征会对模型接入与配置环节带来多项约束。每日更新的数据源要求配置定时拉取任务的周期不超过24小时，避免数据滞后。固定的融资金额单位为万元，要求接入时配置字段校验规则，对非万元的数值进行转换或过滤，避免数据混乱。固定的业务字段结构要求在模型调用前，将结构化数据对齐为预设字段格式，减少模型解析误差。融资用途多指向耐火材料原料采购、窑炉改造等细分场景，要求配置专属的系统提示词，限定模型输出范围贴合行业语境。单份日报包含数十条条目，要求配置召回条数时适配条目数量，避免召回过多导致上下文溢出。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `定时拉取周期` | `每天0点执行一次` | 匹配融资日报每日更新的发布节奏，确保数据时效性 |
| `字段校验开关` | `开启` | 需校验融资金额单位为万元，避免非标准数值混入数据链路 |
| `maxContext` | `8000–12000 字符` | 单份日报包含数十条融资记录，该长度可覆盖完整条目且不超出主流模型上下文窗口 |
| `召回条数` | `前10条` | 适配单份日报的条目数量，避免上下文冗余或信息缺失 |
| `SYSTEM_PROMPT` | `耐火材料融资日报分析助手，仅基于提供的融资数据回答，聚焦企业融资用途、金额类型等行业相关内容` | 贴合耐火材料融资场景的业务语境，限定模型输出范围 |
| `超时阈值` | `15 秒` | 匹配主流大模型的常规调用耗时，避免因超时中断任务 |
| `变量映射规则` | `将代码运行结果绑定至`{input_result}`字段` | 解决代码运行结果无法传入AI模型的问题，匹配工作流参数传递逻辑 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中代码运行结果传入AI模型时，出现`chat:ai_input_is_e`报错。原因：未正确配置工作流变量映射规则，导致代码输出的result字段未绑定至AI模型的输入参数。
- 现象：非Docker部署的Ollama模型无法正常接入Docker Compose部署的FastGPT实例。原因：未配置正确的模型访问地址与端口映射，导致网络连通性中断。
- 现象：模型召回的融资条目数量与预期不符，出现结果条数过多或过少的情况。原因：未根据单份日报的条目数量调整`召回条数`配置，导致上下文溢出或信息缺失。

## 怎么确认配好了
- 执行一次手动触发的定时拉取任务，查看拉取的融资数据是否包含预设的全部字段，且融资金额单位符合要求。
- 提交测试用的代码运行结果，检查工作流日志中无参数绑定相关报错，确认结果可正常传入AI模型。
- 提交贴合耐火材料融资场景的测试问题，查看模型生成内容是否聚焦行业相关信息，未出现无关话题。
- 查看模型调用日志，确认单次调用耗时未触发超时阈值，且无格式错误日志生成。
