# 造纸融资日报的工具调用与插件

## 这个品类的数据长什么样
造纸融资日报的数据来自全国银行间同业拆借中心、造纸行业第三方数据服务商及各地金融监管备案平台。更新节奏为每日T+1发布前一交易日的全行业融资数据。文档结构分为行业总览、主体分类、类型细分三个板块，核心字段包含融资主体名称、统一社会信用代码、融资类型、融资金额（单位：万元人民币）、融资期限（单位：天或月）、放款日期及所属纸种分类。

## 这些特征在「工具调用与插件」这一环带来什么约束
造纸融资日报的T+1更新节奏要求工具调用的定时触发窗口需避开当日数据生成期，避免拉取未完成的不完整数据集。统一社会信用代码、纸种分类等专属字段，要求工具调用时需配置字段映射规则，将原始数据字段与平台内部字段对齐。融资金额以万元为单位的设定，要求入参需提前完成单位标准化转换，避免与其他行业融资数据的单位混淆。多来源的数据聚合需求，要求工具调用配置超时重试机制，应对单数据源接口波动导致的调用失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `plugin_api_timeout` | `300 秒` | 造纸融资日报的数据接口需聚合多源数据，300秒可覆盖多数正常调用的时长需求 |
| `plugin_request_header` | `{"Content-Type": "application/json", "Authorization": "Bearer ${secret_key}"}` | 多数第三方融资数据接口采用标准JSON格式与Bearer令牌认证，该配置可适配多数数据源 |
| `parse_field_mapping` | `{"融资金额":"amount", "融资期限":"term", "统一社会信用代码":"credit_code"}` | 将原始数据的中文字段映射为平台通用字段，便于后续数据处理与跨工具调用 |
| `plugin_trigger_cron` | `0 2 8 * * ?` | 造纸融资日报通常在每日早8点前完成T+1更新，该时间可确保拉取到完整的前一日数据 |
| `max_retry_times` | `3 次` | 多源数据接口可能出现临时波动，3次重试可在不影响整体流程的前提下提升调用成功率 |
| `data_unit_convert_rule` | `{"amount": "万元转元"}` | 原始数据融资金额单位为万元，转换为平台内部统一的元单位可避免数值计算偏差 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用插件API时自定义入参未生效，配置的纸种过滤条件未执行。原因：未按照`parse_field_mapping`配置的字段名传递入参，使用了原始数据的中文字段名作为入参键。
- 现象：调用部署的ollama模型时返回空结果，其他模型调用正常。原因：未调整模型的上下文窗口参数，造纸融资日报的长文本数据超出模型承载上限，未生成有效输出。
- 现象：调用openapi接口解析造纸融资日报文件时返回成功但无结果，手动上传可正常解析。原因：未在API请求中指定文档的行业分类解析规则，导致平台未触发造纸融资日报的专属解析逻辑。

## 怎么确认配好了
- 查看插件调用日志，确认触发时间与配置的定时表达式匹配，检查拉取到的数据是否包含造纸行业专属字段。
- 手动调用插件API，传入符合造纸融资日报格式的测试入参，确认返回结果的字段与配置的映射规则一致。
- 检查数据处理日志，确认融资金额等字段已按照配置完成标准化转换，无格式异常。
- 模拟数据源接口波动，查看重试日志，确认插件触发了配置的重试机制，未出现直接失败的调用记录。
