# 酒店餐饮融资日报的工具调用与插件

## 这个品类的数据长什么样
数据来源为对接餐饮商户经营流水的地方融资服务平台、连锁餐饮总部的融资台账系统；更新节奏为每日凌晨更新前一自然日的全量数据；文档结构为单条记录包含商户唯一标识、门店名称、经营业态（如正餐、快餐、茶饮）、当日可贷额度、融资申请次数、审批通过金额、到期还款金额、数据上报日期；字段单位包括「当日可贷额度」为人民币元，「融资申请次数」为整数，「数据上报日期」为YYYY-MM-DD格式的日期字符串。

## 这些特征在「工具调用与插件」这一环带来什么约束
每日全量更新的数据源要求工具调用需通过`data_report_date`字段过滤拉取范围，避免重复处理历史数据；经营业态的枚举型字段要求插件参数校验需限定合法取值，防止传入非法业态导致接口报错；部分字段如「到期还款金额」可能为空，需配置空值跳过或默认填充逻辑，避免调用时触发参数错误；单条记录字段较多且数据量级随商户扩张增长，需设置分页拉取参数，控制单次返回数据量，降低超时风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `tool_call_timeout` | `600 秒` | 酒店餐饮融资日报需对接多平台数据源，数据拉取耗时较长，600秒可覆盖分页拉取全量数据的耗时 |
| `tool_call_max_retries` | `2 次` | 融资数据源可能存在临时网络波动，重试可降低单次调用失败概率 |
| `tool_call_page_size` | `50 条` | 酒店餐饮商户数量通常较大，50条可平衡数据完整性与单次调用的响应耗时 |
| `plugin_param_validate` | `strict + allow_empty_fields` | 部分融资日报字段如到期还款金额可能为空，需允许空值通过校验，同时校验必填字段 |
| `plugin_field_mapping` | `{"store_id":"商户门店编号","loan_quota":"当日可贷额度"}` | 融资日报的原生字段名与插件默认字段存在差异，映射后可统一识别业务字段 |
| `auto_sync_trigger` | `每日 02:00` | 匹配数据源每日凌晨更新的节奏，在数据更新后触发工具调用拉取最新日报 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为调用工具时返回`400 InternalError.Algo.InvalidParameter: The tool call input contains invalid field`，原因为未配置`plugin_param_validate`的空值允许规则，当融资日报中存在空字段时触发参数校验失败。
- 现象为首次调用工具时响应延迟超过3秒，后续调用正常，原因为未配置定时缓存机制，首次调用需全量拉取数据生成缓存。
- 现象为时间应用插件获取融资日报数据时报错，原因为插件未正确映射`data_report_date`字段，导致无法按日期过滤融资日报数据。

## 怎么确认配好了
- 手动触发一次工具调用，检查返回结果中是否包含融资日报的核心字段，字段格式是否与业务预期一致。
- 查看工具调用日志，确认每次调用的耗时未超过配置的`tool_call_timeout`值，且重试次数未达到上限。
- 检查定时同步任务的触发时间，确认与数据源更新节奏匹配，次日可查看自动拉取的日报数据是否完整。
- 模拟传入包含空字段的测试数据，确认插件未触发参数校验错误。
