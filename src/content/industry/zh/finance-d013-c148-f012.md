# 酒店餐饮融资日报的模型接入与配置

## 这个品类的数据长什么样
酒店餐饮融资日报数据主要来自商户自有经营系统（PMS、POS收银端）、供应链采购台账及地方餐饮经营报备平台。数据更新节奏为每日晚间完成当日全量数据归集，次日出完整日报文档。单份日报文档按门店维度拆分条目，每条包含门店唯一标识、经营业态、当日营收总额、当日到店客单量、预订间夜数、食材采购成本、上月同期营收对比项、待还款融资金额、当日融资申请进度字段。字段单位统一为：营收、成本、融资金额以元为单位，客单量以人次为单位，间夜数以间为单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据接入要求配置跨系统数据拉取的鉴权与格式适配参数，避免不同系统返回的字段格式不一致导致解析失败。每日更新的节奏要求配置固定定时调度周期，同时设置数据超时等待阈值，应对部分门店系统延迟上传的情况。单份文档按门店拆分多条目，要求配置分段解析的长度阈值，防止单批次处理数据量过大触发限流。不同字段对应多元单位，要求配置字段单位校验规则，确保模型调用时能正确关联数值与单位。融资申请进度的状态字段存在多状态枚举，要求配置状态映射规则，避免模型将非标准状态识别为异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `SCHEDULE_CRON` | `0 22 * * *` | 酒店餐饮当日经营数据通常在21点前完成归集，22点触发可覆盖绝大多数门店数据 |
| `PARSE_SEGMENT_LENGTH` | `800-1200 字符` | 单门店条目约150字符，分段长度适配多门店条目拆分，避免单段数据过长触发模型上下文限制 |
| `FIELD_UNIT_MAPPING` | 预设金额/数量/间夜的单位映射规则 | 日报字段包含多元单位，需提前绑定数值与对应单位，避免模型混淆数值与单位类型 |
| `RATE_LIMIT_QPS` | `5-8` | 单日报文档条目较多，需控制模型调用频率，避免触发限流报错 |
| `API_KEY_ISOLATION` | 按应用维度绑定独立API密钥 | 不同门店的融资日报应用需独立维护密钥，防止配置覆盖导致权限混乱 |
| `BODY_PARAM_CLEANUP` | 自动清理无效body参数 | 部分接口默认携带冗余body参数，需定期清理避免配置异常 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调用节点调用模型时频繁返回`429 Request rate increased too quickly`报错。原因：未根据酒店餐饮日报的多条目数据量调整QPS阈值，默认阈值过低导致请求超限。
- 现象：配置大模型时手动删除body参数后保存，再次进入配置界面参数仍存在。原因：未开启自动清理冗余参数的开关，系统默认保留接口预设的body参数模板。
- 现象：新建融资日报应用的模型配置时，原有同类型应用的API密钥配置被覆盖。原因：未开启API密钥隔离配置，系统默认复用全局密钥配置，未按应用维度绑定独立密钥。

## 怎么确认配好了
- 查看定时调度日志，确认每日预设触发时间的数据拉取任务正常启动，无调度失败记录。
- 随机抽取日报文档执行解析测试，确认字段识别与单位关联符合预设规则。
- 模拟多应用调用同一模型的场景，验证不同应用的API密钥互不干扰，配置不会互相覆盖。
- 触发连续调用，确认未返回限流类报错，QPS配置符合当前数据处理需求。
