# 铁矿石融资日报的多轮对话与提示词

## 这个品类的数据长什么样
铁矿石融资日报的数据主要来自国内大宗商品现货交易平台、大连商品交易所及行业协会公开数据。每日更新一次，通常在当日收盘后2小时内发布。文档结构包含发布日期、标的品种、现货基准价、期货主力合约结算价、港口库存总量、融资融券余额、仓单数量、单日环比变动等字段。其中价格类字段单位为元/吨，融资余额与仓单量单位为吨或亿元，环比变动仅标注涨跌方向与数值幅度。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
铁矿石融资日报的每日更新特性要求多轮对话需限定上下文窗口范围，避免引入过期数据影响准确性。字段多且单位差异大的特征，要求提示词需明确标注各字段的定义与对应单位，防止模型混淆现货价、融资余额、仓单量的统计口径。同时，用户常追问单日环比或跨周期对比，多轮对话需保留最近3轮的交互上下文以关联历史查询，无需保留更早的对话记录，避免数据时效性偏差。另外，不同来源的数据（现货与期货）需在提示词中明确区分，确保模型输出时匹配用户查询的数据源类型。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单篇铁矿石融资日报的token长度，同时保留足够上下文支撑多轮对话的关联查询 |
| `historyMaxCount` | 3 轮 | 适配每日更新的数据特性，避免引入过期历史数据干扰当前查询 |
| `similarityThreshold` | 0.75–0.85 | 过滤低相关的文档片段，确保召回内容与铁矿石融资核心指标强匹配 |
| `recallTopK` | 前 3 条 | 单篇日报数据量适中，少量召回即可覆盖用户所需的核心指标 |
| `promptTemplate` | 「请基于提供的铁矿石融资日报数据，准确回复用户问题，严格使用文档中的字段与单位，若涉及环比变动需标注对应日期」 | 明确数据使用规则与字段单位，避免模型混淆不同统计口径与数据源 |
| `responseMaxToken` | 1500 token | 限制输出长度，确保回复聚焦于铁矿石融资相关内容，避免冗余信息 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：模型输出包含未在铁矿石融资日报中出现的外部数据，或字段单位与文档不符。原因：提示词未明确要求仅使用召回的文档内容，且未标注各字段的标准单位。
- 现象：多轮对话中模型无法关联当前查询与最近一次的铁矿石融资数据，错误调用更早的历史数据。原因：`historyMaxCount`参数设置过大，保留了过多过期的历史对话上下文，干扰当前数据的匹配。
- 现象：同一铁矿石融资查询在不同应用场景下返回结果不一致。原因：未统一配置`similarityThreshold`、`recallTopK`等参数，导致不同环境下的召回规则存在差异。

## 怎么确认配好了
- 发起单轮针对性查询，核对返回结果的字段、单位与知识库中的铁矿石融资日报内容完全匹配。
- 发起两轮关联查询，第一轮询问指定日期的铁矿石融资数据，第二轮询问该数据的环比变动，核对模型能正确关联两轮的交互上下文。
- 查看配置面板中的参数设置项，确认`maxContext`、`historyMaxCount`等参数的取值适配当前数据的更新节奏与文档长度。
- 发起超出当前知识库范围的查询，核对模型无法生成无关内容，仅提示无法获取对应信息。
