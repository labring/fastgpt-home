# 铁矿石融资日报的部署与升级

## 这个品类的数据长什么样
铁矿石融资日报的数据来源包括国内沿海大宗商品现货交易平台、港口货权登记系统、钢厂每日采购申报数据，以及部分跨境铁矿石贸易的结算台账。更新节奏为每日完成前一日全量数据归集，当日8点前生成标准日报文件。文档以结构化表格形式存储，每行对应单品类单日融资交易明细，字段包含报告日期、矿石品类（粉矿/块矿）、原产地、货权持有主体、现货结算价、质押融资额度、当日融资成交总量，单位分别为元/湿吨、万元、万吨。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据需每日全量归集多源平台信息，部署时需配置固定定时拉取任务，升级时需保留原有任务配置避免数据断档。由于字段包含金融相关的融资额度，部署时需配置数据校验规则，升级时需同步更新校验逻辑避免误判。由于数据来源涉及第三方交易平台，部署时需配置接口白名单和超时重试机制，升级时需兼容第三方接口的版本变更。由于单日报文件数据量较大，部署时需调整解析和存储的资源配置，升级时需避免因资源分配变化导致解析失败，同时需确保升级过程不影响当日数据的正常归集。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 铁矿石日报包含多笔交易明细，解析耗时较长，默认值无法覆盖全量解析流程 |
| `CRON_EXPRESSION` | `0 0 3 * * ?` | 每日凌晨3点执行数据拉取，避开业务高峰，匹配日报生成的时间节奏 |
| `KNOWLEDGE_BASE_MAX_DOC_SIZE` | `2000000 字节` | 全量铁矿石日报文件通常超过1MB，默认值会限制完整文档导入 |
| `HTTP_REQUEST_TIMEOUT` | `300 秒` | 多源数据拉取需跨平台请求，300秒可覆盖多数第三方接口的响应时长 |
| `DATA_VALIDATION_RULES` | 校验报告日期、融资额度字段存在 | 确保核心业务字段完整，避免脏数据进入知识库 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：部署运行数天后，知识库文档和工作流配置丢失，接口仍可正常调用。原因：未配置`REDIS_PERSISTENCE`参数，使用默认内存存储导致重启或内存溢出后数据清空。
- 现象：执行`docker compose up`时提示redis镜像拉取失败，开启网络代理后仍无法解决。原因：使用了4.9.1及以上版本，该版本新增redis 7.x镜像，部分网络环境无法直接拉取官方镜像。
- 现象：启动容器时出现`OCI runtime create failed`报错，服务器未配置GPU资源。原因：部署配置中启用了`ENABLE_GPU_ACCELERATION`参数，未添加GPU硬件映射导致容器启动失败。

## 怎么确认配好了
- 执行`docker compose config`命令，核对`CRON_EXPRESSION`、`PARSE_FILE_TIMEOUT_SECONDS`等核心配置项的取值与预设一致。
- 手动触发一次数据拉取任务，查看知识库中是否生成对应日期的铁矿石融资日报文档，核对字段映射是否符合预设规则。
- 重启容器后，检查知识库文档和工作流配置是否保留，确认数据持久化配置生效。
- 查看容器运行日志，确认外部数据源接口请求无超时或权限错误，数据校验规则未拦截正常业务数据。
