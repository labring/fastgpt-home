# 铁路公路融资日报的多轮对话与提示词

## 这个品类的数据长什么样
铁路公路融资日报的数据来源于交通运输主管部门的项目融资公示平台、银行授信台账系统及项目承建方的内部融资台账。更新节奏为每日凌晨更新前一日的融资交易数据。单份日报文档以单个交通项目为基本组织单元，每条记录包含项目编码、项目名称、所属线路/路段、融资主体、合作银行、融资金额、到账日期、资金用途、审批文号共9个字段。融资金额单位为万元，日期字段采用YYYY-MM-DD标准格式，项目编码为12位统一交通项目标识。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
铁路公路融资日报的每日更新特性，要求多轮对话上下文需限定在24小时内的有效数据，避免引入过期融资记录。字段包含项目编码、融资金额等标准化标识，提示词需明确指定字段提取规则，防止混淆项目编码与审批文号。融资金额固定以万元为单位，提示词需明确要求直接使用原始数值，无需额外单位转换。日报按项目维度组织，多轮对话中需关联同一项目的多笔融资记录，部分铁路公路项目存在跨路段的融资拆分情况，提示词需引导对话识别同一项目的不同融资条目，避免重复或遗漏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 铁路公路融资日报单条记录字符量约100，多轮对话需保留最近5条项目融资相关历史，同时容纳当前查询的完整上下文 |
| `systemPrompt` | `请基于提供的铁路公路融资日报数据，按项目维度整理信息，提取指定字段时需使用原始数值与格式，仅回答与当日或指定日期融资相关的内容` | 明确字段提取规则与数据范围，避免无关信息干扰，适配日报的项目化组织形式 |
| `relevanceThreshold` | `0.75–0.85` | 铁路公路融资日报的字段关联性较强，过高阈值会过滤有效项目记录，过低则引入无关数据 |
| `topK` | `前6–8 条` | 单份铁路公路融资日报的有效项目记录通常在5-7条之间，召回过多会增加上下文负载，过少则遗漏关键项目 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 铁路公路融资日报通常包含较多项目条目，解析耗时高于通用文档，需预留足够处理时间 |
| `enableMultiRoundMemory` | `开启` | 多轮对话需关联同一项目的多笔融资记录，开启后可保留上下文关联信息，避免信息断裂 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：提示词配置后未生效，返回结果不符合预期。原因：未将`systemPrompt`与对话流程绑定，或提示词中未明确铁路公路融资日报的专属字段规则。
- 现象：前端对话页面同时展示多个不相关项目的融资数据。原因：未根据日报项目量调整`topK`与`relevanceThreshold`的取值，导致无关项目的融资记录被纳入上下文。
- 现象：对话返回`504 Gateway Timeout`报错。原因：未将`PARSE_FILE_TIMEOUT_SECONDS`配置为符合日报解析需求的时长，导致文档解析超时。

## 怎么确认配好了
- 上传一份真实的铁路公路融资日报文档，发起首次查询，核对返回结果是否包含指定字段且单位符合要求。
- 发起两轮关联同一项目的查询，核对对话上下文是否保留前一轮的项目关联信息。
- 调整`relevanceThreshold`与`topK`的取值，验证召回的融资记录条数是否符合当前日报的项目数量范围。
- 模拟单次查询的超时场景，验证`PARSE_FILE_TIMEOUT_SECONDS`的配置是否能避免解析超时报错。
