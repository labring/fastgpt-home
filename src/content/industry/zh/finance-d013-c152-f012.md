# 鞋类融资日报的模型接入与配置

## 这个品类的数据长什么样
鞋类融资日报的数据来源于鞋类品牌方ERP系统、区域经销商的每日经营上报及供应链金融平台的接口同步。更新节奏为每日凌晨1点完成当日全量数据刷新。文档结构以鞋款SKU为核心维度，包含款号、当日融资发生额、授信剩余额度、当日回款金额、仓储质押对应额度等字段。字段单位统一规范，金额类基础字段以人民币元为单位，授信额度类汇总字段以万元为单位，SKU字段为10位数字加字母组合的款号编码。

## 这些特征在「模型接入与配置」这一环带来什么约束
鞋类融资日报的专属数据特征会对模型接入配置产生多项约束。首先，SKU字段的10位数字加字母编码规则，要求配置专属的字段匹配映射逻辑，避免与其他品类的SKU编码混淆。其次，金额字段同时存在元与万元两种单位，需要配置统一的单位转换规则，防止后续数据分析出现计算偏差。每日凌晨固定刷新的更新节奏，要求配置定时触发任务的时间窗口避开系统高峰时段，同时配置数据完整性校验逻辑，过滤当日未完成上报的缺失数据。另外鞋类SKU数量通常较多，接入时需要配置分页拉取参数，避免单次请求数据量超限导致超时错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `schedule_cron_expression` | `0 0 1 * * *` | 匹配鞋类融资日报每日凌晨1点的更新节奏，确保数据拉取时机与数据源刷新同步 |
| `field_unit_convert` | `将credit_remaining字段从万元转换为元` | 解决金额字段存在元与万元两种单位的差异，统一数据计算基准 |
| `batch_fetch_size` | `500 条/请求` | 适配鞋类SKU数量较多的特征，避免单次请求数据量超限导致超时 |
| `data_validate_rules` | `校验daily_financing_amount≥0` | 过滤融资金额为负的异常数据，保证接入数据合法性 |
| `response_parse_mode` | `strict_json` | 适配结构化融资日报数据的解析要求，避免格式解析错误 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 适配批量数据拉取的耗时需求，防止因数据量大触发超时报错 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工具调用解析报错，日志返回`Tool call Parser n`错误。原因是模型返回的推理内容使用think标签包装并置于content字段，不符合结构化解析的格式要求。
- 现象为调用时返回长串错误代码，接口返回状态码`403`。原因是通过aiproxy转发密钥时未配置正确的权限范围，导致接口鉴权失败。
- 现象为调用流程图时返回`chat：llm—model—response-empty`错误。原因是数据源未正确拉取到当日有效融资数据，导致模型无可用内容生成响应。

## 怎么确认配好了
- 手动触发一次数据拉取任务，核对拉取到的SKU编码格式与鞋类款号的10位数字加字母规则一致。
- 查看数据转换日志，确认金额字段的单位转换逻辑正常执行，汇总类授信额度字段已完成单位转换。
- 提交一条负金额的测试数据，校验异常数据过滤规则是否正常拦截该类无效数据。
- 检查定时任务执行日志，确认每日凌晨的同步任务正常触发并完成全量数据拉取。
