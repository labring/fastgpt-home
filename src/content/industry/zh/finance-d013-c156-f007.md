# 黑色家电融资日报的工作流编排

## 这个品类的数据长什么样
黑色家电融资日报的数据来源包括行业协会公开的每日出货统计、上游面板厂商的官方报价接口、线下经销商的回款台账以及海关进出口报关数据。数据更新节奏为每日T+1更新，即当日业务数据于次日早间完成汇总校验。文档结构为标准化结构化表格，包含报告日期、品类型号、上游原材料单价、厂商出货量、经销商预付款金额、融资授信额度、逾期回款笔数等字段，其中单价单位为元/千克，出货量单位为万台，金额类字段单位为万元。

## 这些特征在「工作流编排」这一环带来什么约束
多源分散的数据来源要求工作流配置多个独立的拉取节点，且需针对不同数据源设置差异化的身份校验规则。每日更新的需求要求工作流绑定固定的定时触发节点，需适配T+1的数据延迟以避免拉取空数据。结构化字段的单位差异要求配置统一的字段映射规则，将不同数据源的格式转换为统一标准。部分数据源需敏感密钥访问，要求工作流通过全局变量存储密钥，避免硬编码导致的信息泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `定时触发周期` | `每日 09:00` | 匹配融资日报早间分发的业务需求 |
| `多数据源拉取超时` | `300 秒` | 覆盖协会、厂商、经销商三个渠道的拉取时长，避免超时中断流程 |
| `字段映射规则` | `统一转换为「YYYY-MM-DD」日期格式` | 统一各数据源的日期字段格式，便于后续数据整合 |
| `全局变量存储` | `加密存储接口密钥` | 避免敏感信息在工作流中硬编码，提升数据安全性 |
| `请求头配置` | `携带固定X-API-KEY` | 满足上游厂商数据源的身份校验要求 |
| `失败重试次数` | `2 次` | 应对网络波动导致的单次拉取失败，减少流程中断概率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：发布渠道执行时返回旧版业务数据。原因：更新工作流后未重新关联对应发布渠道，导致调用的仍是旧版本工作流逻辑。
- 现象：流程执行日志显示「获取全局变量失败」。原因：未在全局变量管理页面配置对应接口密钥，或变量引用路径不符合格式要求。
- 现象：第三方API请求返回401状态码。原因：请求头中未正确引用全局变量存储的API密钥，导致身份校验未通过。

## 怎么确认配好了
- 查看定时触发节点的配置详情，确认触发时间与业务生成需求匹配。
- 执行一次手动触发的工作流，检查各数据源拉取的字段是否与预设的映射规则一致。
- 查看全局变量管理页面，确认所有敏感信息已完成加密存储且引用路径正确。
- 模拟一次网络波动场景，检查失败重试机制是否按配置触发。
