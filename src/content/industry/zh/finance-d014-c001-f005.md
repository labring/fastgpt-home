# IT 服务财报分析的多轮对话与提示词

## 这个品类的数据长什么样
IT服务行业的财报数据主要来自境内外证券交易所公开披露的定期报告、临时公告，更新节奏以季度、年度为固定周期，同时伴随重大合同签订、战略调整等事项的临时披露。文档格式以加密PDF、结构化XBRL文件为主，核心字段包含营收、净利润、研发投入、合同负债、毛利率等，单位多为万元或亿元，细分赛道还会补充人均产出、项目交付周期等运营类字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
财报数据的长文本特性要求多轮对话需保留上下文关联的财报周期、对比基准，避免跨周期数据混淆。结构化字段的明确性要求提示词需精准指定提取字段范围，防止模型混淆非财报类公开信息。临时披露的非周期性要求对话支持动态切换财报版本，同时需限制对话上下文的冗余信息，避免干扰核心数据的提取与分析。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000-12000 字符 | 适配单季度财报文档的平均分段长度，避免上下文溢出 |
| `disable_markdown_output` | 开启 | 匹配用户无需Markdown格式的输出需求 |
| `enable_multi_round_memory` | 开启 | 保留财报周期、对比基准等上下文信息，支持多轮关联提问 |
| `rag_top_k` | 前6-8 条 | 覆盖财报核心字段的召回需求，避免冗余信息干扰 |
| `file_parse_chunk_size` | 1000-1500 字符 | 适配财报段落的自然分段结构，提升解析准确性 |
| `persist_session_memory` | 按会话周期配置 | 支持会话上下文的长期保留，避免每次对话新建会话 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：对话中出现`Unexpected end of JSON input`报错。原因：ChatGLM2模型在处理长财报分段解析时，输出未完成即被截断，导致返回内容不符合JSON格式要求。
- 现象：对话结果需手动在侧边栏打开，无法直接展示在对话区。原因：未开启`inline_message_output`配置项，导致回复内容未直接渲染到主对话窗口。
- 现象：每次对话自动新建会话，无法延续上下文。原因：未配置`persist_session_memory`为开启状态，或会话过期阈值设置过短，导致上下文未被保留。

## 怎么确认配好了
- 上传单季度财报PDF，发起“提取本季度核心营收数据”的提问，检查回复是否直接展示在主对话区。
- 连续发起两次关联提问，比如先询问“2023年全年净利润”，再询问“对应毛利率”，检查上下文是否被保留。
- 发起“用纯文本格式输出财报关键指标”的提问，检查回复是否未使用Markdown语法格式。
- 查看系统返回的日志，确认未出现`Unexpected end of JSON input`相关报错。
