# 专业连锁财报分析的工作流编排

## 这个品类的数据长什么样
专业连锁的财报分析数据主要来自门店POS终端、区域供应链管理系统及总部财务核算系统。数据更新节奏按核算周期划分，内部经营周报每周更新，季度财报、年度财报按固定披露节点更新。单份财报文档包含门店级明细数据、区域汇总数据及整体经营概览，字段涵盖门店唯一标识、经营区域编码、营收金额、货品成本占比、库存周转天数，单位包含元、百分比、天等。

## 这些特征在「工作流编排」这一环带来什么约束
专业连锁的财报数据特征对工作流编排带来多重约束。多源数据需要对接门店POS、供应链、财务系统三类接口，工作流需配置多数据源拉取节点，适配不同系统的返回格式。不同更新节奏要求工作流支持混合触发规则，包含定时触发、手动触发两类模式。单份财报包含上百条门店级明细数据，工作流需支持批量数据分页解析，避免单次处理过载。门店唯一标识与区域编码的关联字段需全程保留，否则无法完成区域维度的汇总分析。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `trigger_type` | `schedule + manual` | 适配专业连锁固定周期财报与临时经营分析的双重需求 |
| `batch_process_limit` | `50–80 条` | 单批次处理门店明细数据量，平衡解析效率与系统负载 |
| `api_request_timeout` | `600 秒` | 多源财务系统接口拉取的超时设置，覆盖慢响应系统的正常请求时长 |
| `text_split_chunk_size` | `900–1100 字符` | 财报文档分段长度，保留字段关联关系，避免拆分破坏结构化数据 |
| `preserve_fields` | `门店ID, 经营区域, 营收金额` | 保留核心关联字段，确保后续区域汇总与门店级分析的准确性 |
| `http_node_timeout` | `30 秒` | 飞书多维表格HTTP调用的超时设置，适配飞书API的常规响应速度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中模型节点无法读取预设的环境变量作为参数，调用时提示参数缺失。原因：未在模型节点的配置中开启环境变量引用权限，或环境变量名称与代码中调用的标识不匹配。
- 现象：对话模型的提示词无法识别多字段间的空格分隔，导致财报解析结果出现字段错位。原因：提示词未明确指定结构化数据的分隔规则，未对字段间的空格做标注说明。
- 现象：工作流执行至批量数据处理节点后停滞，无报错日志且状态持续为运行中。原因：未配置`api_request_timeout`参数，或取值超出系统默认阈值，触发隐性资源占用超时。

## 怎么确认配好了
- 手动触发工作流，导入单门店的测试财报数据，核对输出变量中是否保留了门店唯一标识与经营区域的关联字段。
- 配置单次定时触发，模拟季度财报的拉取流程，检查多数据源节点是否能正常对接门店POS、供应链及财务系统。
- 调用飞书多维表格的HTTP测试节点，传入预设的测试字段，确认接口返回状态符合正常调用要求。
- 查看工作流运行日志，确认批量处理节点未出现隐性停滞，且各超时参数的配置适配对应环节的处理时长。
