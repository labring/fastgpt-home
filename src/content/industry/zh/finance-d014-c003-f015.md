# 专业连锁财报分析的部署与升级

## 这个品类的数据长什么样
专业连锁的财报数据来源涵盖总部财务核算系统、各门店POS收银系统、供应链采购管理系统。更新节奏覆盖周度门店运营数据、月度营收汇总、季度合并财报。文档结构包含单门店营收明细台账、跨门店品类销售汇总表、费用分摊明细表。字段包含门店编码、SKU品类、单位面积营收、单店客流人次、采购成本额等，单位多为元、平方米、人次。

## 这些特征在「部署与升级」这一环带来什么约束
多数据源的接入需求要求部署环节配置跨系统的数据同步适配器，避免因接口格式差异导致数据丢失。不同更新节奏的业务数据，需要设置分层的增量同步调度规则，匹配周度、月度、季度的报表生成节点。长明细结构的财报文件，要求升级环节优化大文件解析的内存占用配置，避免处理多门店汇总数据时出现卡顿。同时，单实例覆盖的门店数量更多，需在升级时适配向量数据库的扩容方案，支撑更大规模的数据集召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 专业连锁财报常包含多门店汇总台账，单文件可能超过通用阈值，需适配大文件上传 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 长周期汇总财报解析需处理大量明细行，延长超时时间避免解析中断 |
| `maxContext` | `8000–12000 字符` | 连锁财报需关联多门店数据，需保留足够上下文以支撑跨门店对比分析 |
| `召回条数` | `前 10 条` | 连锁财报涉及多维度业务字段，需召回足够关联条目支撑全面分析 |
| `相似度阈值` | `0.72–0.78` | 需过滤低关联的门店明细数据，避免冗余信息干扰核心分析结论 |
| `增量同步周期` | `每日 2 次` | 连锁门店的客流、营收数据每日更新，需及时同步最新业务数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：本地部署的开源模型调用时，上传财报附件后无响应，简单应用与工作流应用均无返回。原因：未配置`FILE_PARSE_PLUGIN`适配本地模型的附件解析接口，导致解析环节中断。
- 现象：升级到v4.9版本后，原有openAPI调用出现状态码404报错。原因：v4.9版本调整了openAPI的路由前缀，未同步更新调用地址配置。
- 现象：配置TTS模型后，生成的财报语音播报出现关键字段为空的情况。原因：未将财报解析后的结构化字段映射到TTS模型的输入参数，导致缺失核心业务信息。

## 怎么确认配好了
- 上传一份标准的连锁门店月度财报文件，检查解析后的结构化字段是否包含预设的业务字段，核对字段映射是否符合配置要求。
- 触发增量同步任务，查看数据源同步日志，确认多门店的POS、供应链数据是否按配置周期完成增量拉取。
- 发起财报分析请求，检查返回结果中关联的召回条目数量是否符合配置要求，调整相似度阈值以过滤无关结果。
- 调用openAPI接口测试，确认返回状态码为200，且返回内容包含结构化的财报分析结果。
