# 个护用品财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
个护用品财报相关数据来源包括上市公司公开披露的定期报告、行业零售监测数据集。更新节奏为：定期报告按季度、年度固定更新，零售监测数据按月度更新。文档结构包含营收拆分明细、营业成本构成、费用支出明细、存货周转相关指标等模块。字段包括各细分个护品类的营收金额、原材料采购成本金额、营销投入金额、存货周转天数等，单位分别为人民币元、人民币元、人民币元、天。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据的接入需求带来接口适配压力，既有交易所提供的结构化财报API接口，又有第三方机构提供的非结构化零售数据文件，需同时支持API拉取与文件上传两种数据获取方式。不同更新频率要求接口支持配置多套定时同步任务，分别适配季度财报与月度零售数据的更新节奏。字段单位统一要求严格，需确保所有金额类字段统一使用人民币元，周转类字段统一使用天，因此接口需增加字段校验规则，避免格式不匹配问题。细分品类较多的特点要求接口支持按品类维度过滤数据，返回指定细分品类的财报信息，避免返回冗余数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 个护财报相关的Excel/CSV文件通常包含多品类明细数据，解析耗时较长，需延长超时时间 |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | 行业零售监测数据集的单文件体积通常较大，需适配大文件上传 |
| `SYNC_CRON_EXPR` | `0 0 2 * * 1,3,5` | 按周多次同步季度财报与月度零售数据，避开业务高峰时段 |
| `REQUEST_RETRY_TIMES` | `3 次` | 外部接口调用可能出现临时波动，设置有限重试降低失败率 |
| `FIELD_UNIT_CHECK_ENABLE` | `开启` | 个护财报数据需统一单位为人民币元与天，校验可避免格式错误 |
| `MAX_RESPONSE_ITEMS` | `前 100 条` | 财报细分品类字段较多，限制返回条数避免接口返回数据过载 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：HTTP模块中配置的request body无法正常编辑，保存后内容丢失。原因：未在FastGPT 4.8.15-fix3版本的HTTP节点中启用「自定义请求体」开关，导致编辑状态未被持久化。
- 现象：调用线上对话接口后无返回数据，接口返回状态码400。原因：请求头未正确携带`Content-Type: application/json`，导致接口无法解析传入的财报数据参数。
- 现象：定时同步财报数据时出现超时错误。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`配置项，默认超时时间不足以解析包含多品类明细的个护财报文件。

## 怎么确认配好了
- 进入FastGPT的HTTP节点配置页面，查看request body的编辑内容是否与预设的财报数据拉取参数一致，保存后重新打开页面确认内容未丢失。
- 调用线上对话接口，传入测试用的个护财报数据字段，检查接口返回的状态码为200且包含预期的字段信息。
- 上传测试用的个护财报Excel文件，查看解析后的字段列表是否包含预设的营收、成本等项，确认文件解析正常。
- 查看定时同步任务的日志，确认最近一次同步任务成功执行，无报错信息。
