# 产业园区财报分析的多轮对话与提示词

## 这个品类的数据长什么样
产业园区财报分析作为园区金融服务的核心环节，数据主要来源于园区运营公司的内部财务台账、住建部门的园区运营备案报告，以及入驻企业定期报送的经营数据。数据更新节奏分为两类：园区自身的年度、半年度运营财报按官方披露周期更新，入驻企业的月度营收、纳税等集群数据按月度汇总更新。文档结构包含园区资产负债、租金收缴率、入驻率、入驻企业行业分布等字段，单位涵盖人民币元、平方米、元/平方米/月、入驻户数等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
产业园区财报的数据来源分散、更新周期不一且字段维度较多，会对多轮对话带来多重约束。首先，不同来源的数据对应不同的分析主体，多轮对话中需反复锚定当前查询的是园区整体还是入驻企业集群，避免混淆分析对象。其次，不同更新周期的数据存在时间维度差异，多轮对话中需明确当前使用的是月度、季度还是年度数据，防止跨周期结果混用。最后，多字段的文档会产生较多上下文信息，若未做限制，冗余的历史对话会干扰模型对当前查询的精准判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 字符 | 产业园区单份财报文档常超5000字符，多轮对话需保留3轮内的核心上下文，避免超出模型上下文窗口 |
| `recallTopK` | 前3–5条 | 园区财报字段维度多，过多召回会导致上下文冗余，需精准匹配用户查询的租金、入驻率等特定字段 |
| `similarityThreshold` | 0.75–0.85 | 区分园区整体财报与入驻企业集群数据的查询意图，避免跨主体的结果混淆 |
| `clearContextOnTopicSwitch` | 按财报维度触发 | 当用户切换查询租金、入驻率、纳税额等不同财报维度时，自动清空非相关上下文，避免跨维度混淆 |
| `systemPrompt` | 包含「需明确查询的财报维度、时间范围与分析主体」的前置指令 | 适配园区财报多主体、多维度的特征，减少多轮对话中的歧义 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：多轮对话中连续查询不同财报维度后，模型返回结果出现入驻企业数据与园区整体数据混淆。原因：未配置按财报维度触发的上下文清空规则，导致冗余上下文覆盖了当前查询的核心字段。
- 现象：用户切换查询时间范围（如从季度财报切换为年度财报）后，模型仍返回旧时间范围的数据。原因：未在提示词中强制要求每次查询前确认数据的时间区间，上下文残留了旧的时间参数。
- 现象：手动触发上下文清空操作后，系统未执行清空动作。原因：未绑定手动触发上下文清空的交互节点，或配置的触发条件与用户操作不匹配。

## 怎么确认配好了
- 上传一份产业园区财报文档，发起两轮分别针对园区整体营收与入驻企业纳税额的查询，观察模型是否能准确区分两类数据的差异。
- 触发手动上下文清空操作，发起与上一轮相同的查询，验证模型是否不再依赖之前的对话历史，重新基于当前文档生成结果。
- 调整相似度阈值至0.7以下，测试查询低关联度的问题，观察召回结果是否出现非相关的财报字段。
- 查看实时上下文窗口显示，确认多轮对话中保留的上下文长度未超出配置的`maxContext`值。
