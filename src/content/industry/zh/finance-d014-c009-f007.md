# 产业园区财报分析的工作流编排

## 这个品类的数据长什么样
产业园区财报分析是金融机构开展园区类主体相关业务的重要数据支撑，其数据主要来自园区运营方的月度运营台账、季度经营复盘报表、年度审计报告，以及属地住建部门的园区统计备案数据。更新节奏分为月度（运营台账）、季度（经营复盘）、年度（审计与备案）三类。文档以结构化表格为核心，包含入驻企业清单、各业态租金收入、公共区域能耗、物业运维成本、税收贡献等字段，其中“租金应收总额”单位为万元，“公共能耗总量”单位为千瓦时，“入驻企业数量”单位为家。

## 这些特征在「工作流编排」这一环带来什么约束
产业园区财报的多来源、多更新节奏特征，要求工作流需配置多定时触发节点，分别对应月度、季度、年度的数据拉取任务。结构化表格为主的文档结构，要求文件解析节点需开启表格识别模式，提取单元格内的结构化数值，不提取纯文本。特定字段的单位要求，要求数值提取节点需配置单位校验规则，过滤不符合标准单位的异常数据。数据口径的跨来源对齐需求，要求工作流中增加数据校验节点，核对不同渠道获取的同维度数据的统计口径一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 产业园区财报的结构化表格行数较多，解析耗时超出通用场景 |
| `maxContext` | `8000–12000 字符` | 园区财报单文档通常包含多租户明细与多维度统计，需要足够上下文保留完整结构 |
| `RECALL_TOP_K` | `前 8 条` | 园区财报的核心分析维度集中在租金、能耗、成本等8个关键指标 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 园区财报可能附带多页台账附件，整体文件体积大于通用企业财报 |
| `WORKFLOW_TRIGGER_SCHEDULE` | `每月1次、每季度1次、每年1次` | 匹配园区财报月度运营台账、季度经营复盘、年度审计报告的更新节奏 |
| `API_REQUEST_TIMEOUT` | `300 秒` | 跨渠道拉取属地住建部门的园区统计数据时，响应延迟通常较高 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用工作流时触发`AXIOS_ERROR`报错，现象为接口返回ECONNABORTED或504状态码。原因是未设置合理的`API_REQUEST_TIMEOUT`取值，或拉取园区备案数据时的外部接口响应超时。
- 本地部署的工作流配置界面中，节点数量较多时出现输入卡顿，现象为输入框文字延迟显示或无法输入。原因是前端未启用虚拟滚动渲染节点列表，或未限制单页加载的节点配置项数量。
- 调用指定工作流时返回参数错误，现象为接口返回400状态码，提示`appId不能为空`或参数格式异常。原因是未正确拼接请求payload，遗漏了必填的`appId`字段，或未将布尔类型的`stream`参数设置为正确的格式。

## 怎么确认配好了
- 手动触发一次工作流，查看解析节点的输出结果，核对提取的字段与园区财报的实际字段是否一致。
- 检查工作流的定时触发配置，确认触发周期与对应数据源的更新节奏匹配。
- 调用工作流的测试接口，传入符合规范的payload，确认接口返回正常的分析结果，无报错信息。
- 查看本地部署的前端控制台，确认无节点渲染相关的报错信息，验证界面输入流畅度。
