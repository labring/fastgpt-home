# 休闲食品财报分析的引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据主要来自境内外证券交易所公开披露的上市公司定期报告、行业协会发布的行业运行简报，以及企业官方投资者关系板块披露的经营数据。更新节奏遵循监管要求，年度报告需在每个会计年度结束后4个月内披露，季度报告需在对应季度结束后1个月内披露。文档以结构化PDF或结构化文档形式存在，包含报告期、业务板块营收、营业成本、渠道销售数据、核心产品销量等字段，单位以人民币元或万元计，部分数据会附带附注说明核算口径。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于该品类财报数据来自监管公开披露平台，引用溯源需绑定公告的唯一标识（如披露编号），确保溯源指向官方原始文件。固定的更新周期要求设置按报告期的定时同步规则，避免引用未更新的往期数据。财报中业务板块拆分明确，需配置精准的关键词匹配规则，仅召回与休闲食品相关的段落，防止混入其他业务板块的信息。部分数据附带核算口径附注，需在溯源结果中同步引用对应附注段落，保证数据引用的口径一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `recall_top_k` | `前6–10条` | 休闲食品财报的相关业务段落分布集中，适量召回可覆盖核心信息且避免冗余 |
| `similarity_threshold` | `0.72–0.85` | 需精准匹配休闲食品相关关键词，阈值过低会混入无关业务板块内容，过高则可能遗漏有效段落 |
| `reference_include_note` | `开启` | 休闲食品财报常附带产品核算口径附注，需同步引用附注以保证数据口径一致性 |
| `source_reference_format` | `[文件名] 第X页 第X-X段` | 符合证券监管披露文档的引用习惯，便于使用者核对原始文件 |
| `api_return_reference` | `开启` | 需通过API返回引用的文件名与位置，满足自动化调用的溯源需求 |
| `max_context_window` | `1200–1800 字符` | 休闲食品相关段落通常长度适中，该区间可完整保留上下文信息，避免截断关键溯源内容 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用API时无法获取引用的文件名，返回结果中无相关溯源字段。原因：未开启`api_return_reference`配置项，或未配置正确的溯源格式规则，导致系统未生成文件名提取逻辑。
- 现象：配置引用规则时仅能选择单个变量，无法同时关联多个业务关键词。原因：未开启多关键词匹配的配置开关，或未将多个休闲食品相关关键词配置为并列匹配项，导致系统仅识别单个匹配条件。
- 现象：调用知识库变量引用时返回`quote type error`报错。原因：未按照配置要求传入符合格式的引用变量，例如直接传入原始文件名，未使用预设的知识库引用变量标识，或变量格式未匹配系统要求的嵌套结构。

## 怎么确认配好了
- 上传一份休闲食品上市公司的公开定期报告，触发知识库解析，验证解析后的文本是否仅召回与休闲食品业务相关的段落，无其他业务板块的冗余信息。
- 添加多个休闲食品相关的关键词作为匹配条件，发起测试查询，确认系统可同时匹配多个关键词并召回对应段落。
- 通过API调用测试接口，查看返回结果中是否包含引用文件名、段落位置等溯源字段，确认`api_return_reference`配置生效。
- 生成一份财报分析结果，检查是否附带了符合配置要求的溯源信息，例如文件名、页码和段落范围。
