# 休闲食品财报分析的文档解析与分块

## 这个品类的数据长什么样
休闲食品品类的财报数据主要来自交易所公开披露的年报、季报，以及企业内部经营台账。更新节奏以季度为核心周期，年度财报为完整周期复盘。文档结构多包含营收拆分、原材料成本、SKU动销数据等模块，字段涵盖单品类营收额、渠道占比基数、单位产品生产成本等，单位多采用万元、吨、件等具象计量形式，部分内部台账会增加自定义的SKU编码字段。

## 这些特征在「文档解析与分块」这一环带来什么约束
休闲食品财报的多产品线拆分、SKU明细数据，会让文档内存在大量同结构的细分条目，分块时需保留产品与对应数据的绑定关系，避免跨品类数据混淆。SKU动销数据多为表格化多行内容，部分文档存在合并单元格，解析时需识别行内关联，防止拆分后丢失单SKU的完整信息。部分内部经营台账格式不统一，存在自定义字段，解析时需适配非标准化命名，同时保证分块后的数据字段可追溯，避免后续分析出现字段错位。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `parseTableMergeCell` | 开启 | 休闲食品财报的SKU明细表格常包含合并单元格，开启后可保留单元格内数据的完整关联 |
| `chunkSize` | 800–1000 字符 | 财报包含长段落的行业分析与明细数据，该长度可平衡上下文关联与分块粒度 |
| `uploadFileMaxSize` | 500 MB | 适配单份年度财报PDF或多季度汇总Excel文件的常见体积上限 |
| `parseTimeout` | 900 秒 | 多季度汇总文件的解析耗时较长，避免中途解析失败 |
| `tableRowGroupSize` | 10–15 行 | SKU明细表格的单页行数较多，分组后保留单组SKU的完整数据关联 |
| `enableChunkOverlap` | 开启 | 财报存在跨段落的关联数据，重叠分块可保留上下文连贯性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传包含SKU明细的Excel财报文件后，数据处理完成但解析结果为空。原因：未开启`parseTableMergeCell`配置，合并单元格内的SKU营收数据未被正确提取。
- 现象：执行财报分析提问时，返回结果包含未上传的通用文本内容。原因：未关闭`parse_query_as_document`配置，导致提问文本被误触发文档解析流程。
- 现象：调用解析接口时返回`408 Request Timeout`错误。原因：未调整`parseTimeout`参数，单份多季度财报的解析时长超过默认阈值，请求被中断。

## 怎么确认配好了
- 上传一份包含合并单元格的SKU明细测试文件，核对解析后的表格数据是否保留了单元格内的完整关联信息。
- 执行单份季度财报的解析任务，确认任务未出现超时中断。
- 发起测试提问，确认回答仅基于已上传的财报文档内容，未混入未配置的文本。
- 查看解析日志，确认加载的配置参数与预设方案匹配。
