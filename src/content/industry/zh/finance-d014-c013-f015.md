# 保险财报分析的部署与升级

## 这个品类的数据长什么样
保险财报的数据来源为保险公司公开披露的年度报告、季度偿付能力报告及监管报送的标准化报表。更新节奏为年度完整财报每年披露一次，季度关键财报数据每季度更新，监管报表按月同步。文档多为PDF格式，包含结构化报表附件与文字说明章节，涵盖资产负债、保费收支、赔付支出、责任准备金四大核心模块。字段包含原保费收入、退保金、赔付支出、未决赔款准备金、净资产等，单位多为人民币万元或亿元。

## 这些特征在「部署与升级」这一环带来什么约束
保险财报的结构化PDF格式、多模块专属字段及差异化更新节奏，对部署与升级环节带来多重约束。需适配嵌套表格的解析逻辑，避免核心字段提取缺失。需配置分周期的定时拉取任务，区分年度全量财报与季度/月度更新数据的同步节奏。需针对责任准备金、保费结构等专属字段，配置知识库的关联召回规则。升级时需保留旧版解析模板的兼容入口，避免已部署的历史财报解析任务出现异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 保险财报PDF包含多页嵌套表格与长文本说明，解析耗时显著高于通用文档 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 年度保险财报包含完整偿付能力报告、保费明细等附件，单文件体积较大 |
| `maxContext` | 8000–12000 字符 | 财报核心字段的上下文跨度较大，需保留足够关联信息以准确提取字段 |
| `RECALL_TOP_N` | 前 8 条 | 保险财报分为资产、保费、赔付、准备金四大模块，需召回足够关联段落覆盖核心内容 |
| `SIMILARITY_THRESHOLD` | 0.75–0.85 | 财报字段表述标准化程度高，需过滤低关联的冗余说明文本 |
| `RERANK_TOP_N` | 前 3 条 | 重排后保留最相关的财报模块内容，避免无关信息干扰分析结果 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
-  现象：私有部署后执行版本升级操作，无法找到官方升级指引文档。原因：未将官方升级脚本与部署目录绑定，或未在部署时配置版本更新的本地缓存路径。
-  现象：解析保险财报时出现`未决赔款准备金`字段提取为空的报错。原因：未配置针对嵌套表格的专属解析规则，通用解析模板无法识别保险财报特有的字段层级结构。
-  现象：定时同步财报数据任务触发后，返回`504 Gateway Timeout`状态码。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时间不足以完成大型年度财报PDF的解析与上传。

## 怎么确认配好了
-  上传单页精简版保险财报测试文件，检查解析结果中是否完整提取了原保费收入、赔付支出等专属字段。
-  进入私有部署的服务器，查看升级脚本的版本标识，确认与官方最新发布的版本号一致。
-  触发一次临时的财报数据同步任务，检查任务日志中无`timeout`或`parse failed`相关报错。
-  查看docker容器的日志挂载配置，确认对话日志已配置持久化存储，避免出现批量丢失风险。
