# 储能财报分析的工作流编排

## 这个品类的数据长什么样
储能品类的财报数据来源包括证券交易所披露平台、公司官方公告、行业公开数据库。更新节奏以季度、半年度、年度定期披露为主，同时覆盖中标、产能扩张、并网进展等临时公告。文档结构包含储能系统营收、电芯产能、并网装机量、成本构成等多个业务模块，字段与单位随业务模块不同存在差异，装机容量以GW为单位，营收以万元为单位，产能以GWh/年为单位。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散的特征要求工作流需集成多数据源拉取节点，分别对接交易所平台、公司官网及行业数据库。更新节奏不固定的特征要求工作流需同时支持定时触发与事件监听模式，覆盖定期披露与临时公告的处理需求。文档结构复杂且模块分散的特征要求工作流需按业务模块拆分数据处理节点，避免跨模块数据混淆。字段单位不统一的特征要求工作流需内置单位对齐校验环节，确保不同模块的数据可统一计算与展示。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 储能财报单份PDF通常超过50页，解析耗时较长，需延长超时时间避免中断 |
| `workflow_trigger_mode` | `定时触发+事件监听` | 需覆盖季度/半年度/年度定期披露，以及临时公告的实时处理需求 |
| `text_split_chunk_size` | `1500–2000 字符` | 储能财报包含大量专业术语，较长的分段可保留术语上下文完整性 |
| `global_variable_enabled` | `true（4.9.1及以上版本）` | 需跨工作流复用储能行业基准数据，需开启全局变量配置功能 |
| `api_request_concurrency` | `2–4` | 避免同时调用多个数据源导致接口限流或超时 |
| `error_retry_max_times` | `3` | 应对数据源临时不可用的情况，减少无效重试次数 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为AI问答节点输出结果中未包含文本拼接节点传入的变量内容，API调用时仅返回固定文本。原因是未在工作流中正确绑定文本拼接节点的输出到AI问答节点的输入参数，且未在API调用时携带正确的变量映射。
- 现象为并发调用工作流时，系统前端出现无响应状态，后台容器资源占用未达阈值。原因是未限制工作流的并发调用上限，导致内部处理队列堆积。
- 现象为无法在工作流中复用跨节点的储能财报基准数据，找不到全局变量配置入口。原因是未在系统配置中开启全局变量功能，或使用的版本未内置该配置项。

## 怎么确认配好了
- 触发一次定时工作流，检查解析后的财报数据是否按储能业务模块拆分，字段单位是否统一。
- 调用API测试工作流，检查返回结果中是否包含所有预期的变量拼接内容，验证变量映射是否生效。
- 调整并发调用数量，确认前端界面无异常响应，后台无队列堆积相关告警。
- 查看系统配置页面，确认全局变量功能已开启，可创建并复用跨工作流的基准变量。
