# 光模块财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
光模块财报数据主要来源于境内外证券交易所披露平台、光模块上市厂商的定期报告与临时公告。更新节奏为季度报告每3个月更新一次，年度报告每年更新一次，涉及中标、产能变动等临时公告时不定期更新。文档包含结构化财报数据与PDF格式的完整报告，结构化字段包括报告期、合并营收、光模块业务营收、光模块出货量、单纤双向模块单价、净利润，单位分别为报告期（YYYY-MM-DD、人民币万元、万只、元/只。完整PDF包含技术参数图表与业务说明文档。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
光模块财报的结构化字段包含非通用的光模块业务细分数据，因此HTTP接口需支持自定义字段筛选与拉取；财报PDF包含多模态内容，接口需支持多模态文件的解析与上传；数据更新频率较高且存在临时增量数据，接口需支持增量拉取与定时轮询；光模块财报数据通常存储在MongoDB副本集，需适配副本集主节点切换时的连接稳定性；单份财报PDF体积较大，接口需适配大文件上传与解析的超时设置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 光模块财报PDF通常包含技术图表与详细业务说明，单份文件体积可达数百MB |
| `PARSE_FILE_TIMEOUT_SECONDS` | 180 秒 | 光模块财报PDF的多模态解析包含OCR识别与结构化提取，耗时较长 |
| `MONGO_REPLICA_SET_RECONNECT` | 开启自动重连，重试次数设为5次 | 光模块财报数据存储在MongoDB副本集，主节点漂移时需自动恢复连接 |
| `HTTP_REQUEST_TIMEOUT` | 300 秒 | 单次拉取多厂商财报数据或解析结果的请求耗时较长，需避免超时中断 |
| `FIELD_FILTER_WHITELIST` | 加入光模块业务相关字段 | 过滤非目标字段，仅保留报告期、光模块营收、出货量等字段 |
| `SESSION_KEEP_ALIVE` | 开启，超时时间设为300秒 | 确保同一会话的多次API调用共享上下文，适配财报分析的连贯执行 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 出现`400 InternalError.Algo.InvalidParameter: Multimodal file size is 报错，原因是未调整`UPLOAD_FILE_MAX_SIZE`的配置，未匹配光模块财报PDF的实际体积，超出接口允许的上传限制。
- MongoDB副本集主节点切换后，HTTP接口断连无法自动重连，原因是未启用`MONGO_REPLICA_SET_RECONNECT`的自动重连逻辑，连接断开后未触发重连。
- 插件配置的数值参数无法传递到HTTP请求组件，原因是未将对应参数加入`FIELD_FILTER_WHITELIST`，参数被系统自动过滤。

## 怎么确认配好了
- 上传单份800 MB的光模块财报PDF，调用解析接口，检查接口返回200 OK状态码，无参数错误提示。
- 模拟MongoDB副本集主节点切换，查看接口日志，确认存在自动重连成功的日志记录。
- 配置光模块业务营收、出货量等参数，发起HTTP请求，检查请求体中携带了配置的数值参数。
- 查看接口返回的财报数据，确认仅包含`FIELD_FILTER_WHITELIST`中配置的字段，无多余非目标字段。
