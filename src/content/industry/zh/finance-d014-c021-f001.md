# 其他综合财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
其他综合财报分析的数据来源为企业公开披露的年度、半年度财务报告中的其他综合收益相关模块，更新节奏为年度终了后4个月内披露年报，半年度终了后2个月内披露半年报，部分企业季度报告也会涉及相关明细。文档多为PDF格式，包含合并利润表、所有者权益变动表中的其他综合收益项目及附注说明，字段涵盖其他综合收益各明细项目金额、税后净额、前期调整额等，披露单位通常为人民币元或万元。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于该品类数据单次文档体积较大，且需从公开财报网站拉取或上传本地文件，HTTP接口需支持大文件上传或远程URL拉取能力；数据更新频率固定且周期较长，接口需适配定时触发的调用配置；字段维度多且存在明细层级，接口参数需支持指定提取字段范围；不同企业披露单位存在差异，接口返回需携带单位信息或支持单位转换配置；财报文档格式存在细微差异，接口需集成结构化解析规则以适配不同企业的披露格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 其他综合财报文件通常包含多页结构化内容，解析耗时较长，600秒可覆盖多数场景 |
| `EXTRACT_FIELD_WHITELIST` | `["其他综合收益总额","税后净额明细","前期调整额"]` | 该品类核心关注其他综合收益相关的核心字段，限定可减少无效数据返回 |
| `SOURCE_DATA_UNIT` | `自动识别` | 不同企业披露的财报单位存在元、万元等差异，自动识别可适配多来源数据 |
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | 单份年度财报PDF通常不超过50MB，超出会导致接口超时 |
| `API_RETRY_TIMES` | `3 次` | 财报数据拉取可能因外部财报网站临时波动失败，重试可提升成功率 |
| `WEBHOOK_TRIGGER_MODE` | `按披露周期触发` | 该品类数据更新频率固定，定时触发比实时调用更高效 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用接口返回`403 Forbidden`或`连接超时`，原因是未配置数据源访问代理，导致部分地区无法拉取公开财报数据源。
- 接口返回的财报数据字段缺失或格式错误，原因是未配置`EXTRACT_FIELD_WHITELIST`或字段映射规则与实际财报结构不匹配。
- 配置`ONE_API_LINK`后接口无法正常转发请求，原因是未在FastGPT源码中正确填写代理地址或未完成密钥校验。

## 怎么确认配好了
- 上传一份测试用的财报PDF，查看接口返回的字段是否与配置的`EXTRACT_FIELD_WHITELIST`一致。
- 调用接口拉取公开财报数据源，查看返回结果是否携带正确的单位信息，验证`SOURCE_DATA_UNIT`配置是否生效。
- 模拟定时触发调用，查看接口是否按预设周期执行，验证`WEBHOOK_TRIGGER_MODE`配置是否正确。
- 检查接口调用日志，确认无`413 Request Entity Too Large`或`403 Forbidden`等错误码，验证`UPLOAD_FILE_MAX_SIZE`和代理配置是否生效。
