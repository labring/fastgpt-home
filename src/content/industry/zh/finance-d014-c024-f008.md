# 农化制品财报分析的工具调用与插件

## 这个品类的数据长什么样
这个品类的数据主要来自境内外证券交易所公开披露的定期报告及临时公告，更新节奏为季度、半年度、年度固定披露，重大经营相关临时公告随事项同步发布。文档结构包含合并财务报表、业务分部经营明细、原材料与产成品库存台账，字段涵盖细分农化业务营收、单位产品生产成本、实际产量、设计产能、原材料采购金额，单位多为万元、吨、亿元。

## 这些特征在「工具调用与插件」这一环带来什么约束
农化制品财报的细分业务字段多、临时公告发布频率高，要求插件需支持按业务板块精准筛选数据字段，避免混入非农化业务的经营数据。定期报告与临时公告的混合拉取需求，要求插件配置支持多数据源并行调用，区分固定周期披露与事件触发的拉取任务。细分业务的单位与通用财报存在差异，需插件内置字段映射规则，将原始披露字段转换为统一的分析口径。单份财报的分部数据条目较多，插件请求需支持分页参数配置，避免单次拉取数据超限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `plugin_request_timeout` | `600 秒` | 农化财报包含多分部经营明细，单次拉取数据量较大，需预留充足响应时间 |
| `plugin_custom_field_mapping` | 按披露字段名映射至农化业务口径 | 农化财报存在专属细分业务字段，需将原始披露字段转换为统一分析格式 |
| `plugin_schedule_trigger` | 每日2次（财报披露窗口期每日4次） | 季度、半年度财报有固定披露窗口期，需高频触发临时公告数据拉取 |
| `plugin_pagination_size` | `50 条/页` | 农化财报分部数据条目较多，分页参数适配单页数据量，避免请求超限 |
| `plugin_content_type` | `application/json` 或 `application/x-www-form-urlencoded` | 适配目标接口的格式要求，覆盖不同数据提交场景 |
| `plugin_max_response_size` | `1000 MB` | 农化财报的库存、产能明细数据量较大，需适配单份数据的最大返回体积 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：插件发送POST请求时返回`415 Unsupported Media Type`错误。原因：未正确配置`plugin_content_type`参数，仅限定为单一格式，未兼容`application/x-www-form-urlencoded`格式的目标接口。
- 现象：分析结果中混入非农化业务的经营数据，部分细分业务字段为空或数值异常。原因：未启用`plugin_custom_field_mapping`配置，未按农化财报的专属字段进行筛选，导致拉取到其他业务板块的数据。
- 现象：在外部项目调用智能问答接口时返回`403 Forbidden`或`404 Not Found`错误，本地调试正常但线上环境失败。原因：未配置接口的跨域访问白名单，或线上部署的域名未添加至允许访问的列表中，请求被拦截。

## 怎么确认配好了
- 手动触发插件拉取单份农化财报数据，核对返回的字段是否仅包含农化业务相关内容，无冗余非业务字段。
- 查看插件的定时任务日志，确认在财报披露窗口期按配置的频率触发拉取任务，无遗漏或重复执行。
- 调用智能问答接口，输入农化财报相关的分析问题，核对返回结果是否调用了正确的插件数据，无字段缺失。
- 测试不同格式的POST请求，确认插件能适配`application/json`和`application/x-www-form-urlencoded`两种格式，无报错。
