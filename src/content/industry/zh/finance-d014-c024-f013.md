# 农化制品财报分析的知识库检索与召回

## 这个品类的数据长什么样
农化制品财报数据主要来自国内证券交易所公开披露的定期报告、临时公告，以及专业财经数据终端的行业细分统计。更新节奏集中在每季度末、年度结束后的两个月内，临时公告如产能调整、原料价格波动、新登记证获批时随时更新。文档结构包含农药/化肥板块营收占比、原药产能、制剂销量、环保合规投入等字段，单位多采用吨、公顷、万元人民币，部分细分品类会标注有效成分含量指标。

## 这些特征在「知识库检索与召回」这一环带来什么约束
农化制品财报的多源异构特征，要求知识库召回支持跨公开公告与财经终端数据的关联检索，避免单一数据源的信息缺失。集中式定期更新与临时公告的随机更新并存，要求召回链路支持增量同步触发与全量刷新的双模式切换。细分字段如原药产能、有效成分占比的专业属性，要求检索时保留单位与细分品类的匹配规则，避免跨品类信息混淆。临时公告的时效性要求，需为高频更新的文档设置更高的召回权重。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 农化财报文档包含长表格与细分行业数据，解析耗时高于通用文档 |
| `召回条数` | `前 10–15 条` | 农化财报细分字段较多，需召回足够数量的文档覆盖营收、产能、合规等多维度信息 |
| `相似度阈值` | `0.75–0.85` | 农化细分术语密度较高，需平衡检索精准度与召回完整性，避免遗漏细分品类相关内容 |
| `maxContext` | `800–1200 字符` | 农化财报核心信息集中在单段长文本中，需保留足够上下文用于精准匹配 |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | 单份年度财报及附属附件的总大小通常不超过该阈值，避免上传失败 |
| `重排返回条数` | `前 5 条` | 对前序召回结果做二次排序后返回，保障最终输出的信息相关性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：针对FastGPT V4.8.17版本的API上传含中文文件名的知识库文件时，文件名显示为乱码，或解析后文档标题异常。原因：未在API请求头中正确设置编码参数，导致中文文件名未被正确转码。
- 现象：知识库检索与AI对话响应耗时过长，或召回结果加载出现卡顿。原因：未调整`召回条数`与`maxContext`的合理取值，召回过多文档或过长上下文导致处理负载过高。
- 现象：检索结果中混入非农化品类的财报信息，或召回条数不足时无相关结果。原因：未设置`相似度阈值`的合理区间，或未开启细分字段的匹配规则，导致跨品类信息被误召回。

## 怎么确认配好了
- 上传一份含中文文件名的农化财报文档，检查知识库中显示的文件名是否正常，无乱码字符。
- 发起一次针对农化财报细分字段的检索，核对召回文档的数量与相关性是否符合预设配置。
- 上传一份超过预设上传大小上限的测试文档，确认系统是否触发符合预期的拦截或提示。
- 模拟临时公告的增量更新场景，上传新的农化行业公告文档，确认知识库是否按配置的更新模式完成同步。
