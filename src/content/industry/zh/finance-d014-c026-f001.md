# 出版财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
出版行业财报数据主要来自出版企业公开披露的定期报告，更新节奏为季度、半年度与年度。单份财报文档结构包含核心经营数据板块，如图书出版营收、数字出版收入、版权授权收益、库存周转情况等，字段涵盖营收金额（单位：万元）、发行册数（单位：册）、用户付费人次（单位：千人次）等，部分细分品类财报还会包含教材教辅、专业出版物的专项营收相关字段，数据来源多为企业内部ERP系统与官方披露平台。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
出版财报的多板块拆分与专项字段需求，要求HTTP接口需支持按指定业务字段拉取数据。财报更新节奏的分层特性，要求接口适配批量拉取历史财报与实时同步最新披露数据的两种模式。单份年度财报可达数万字符，要求接口支持分段拉取与增量同步，避免单次请求数据过载。字段单位的多样性要求接口返回数据需携带明确的单位标识，同时外部系统对接时需兼容不同出版企业的字段命名差异，避免跨系统数据处理出错。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 出版年度财报文档较长，需预留足够解析与拉取时间 |
| `external_api_batch_size` | `800–1200 字符` | 适配出版财报分段拉取的长度需求，避免单次请求数据过载 |
| `field_return_with_unit` | `开启` | 出版财报字段单位多样，需携带单位标识避免跨字段计算混淆 |
| `external_api_auth_mode` | `API_KEY` 或 `OAuth 2.0` | 适配出版企业财报披露系统的主流安全认证方式 |
| `stream_response_chunk` | `200–300 字符` | 平衡出版财报分析结果的前端展示效率与传输稳定性 |
| `max_context_tokens` | `12000–15000` | 支持完整加载单份年度财报文档，保障分析完整性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用HTTP接口拉取财报数据时返回`413 Request Entity Too Large`错误。原因：未调整`external_api_batch_size`配置，单次请求数据超出接口限制。
- 现象：流式输出财报分析结果时，内部链接无法跳转新页面，仅覆盖当前页面。原因：未配置流式返回的前端跳转规则，未适配出版财报中版权链接、图书链接的跳转逻辑。
- 现象：对话日志中显示的财报分析内容与实际返回结果不一致。原因：未正确设置`external_api_batch_size`导致分段拉取的数据拼接错误，或缓存配置未及时刷新。

## 怎么确认配好了
- 发起单次HTTP接口请求，拉取单份季度财报数据，检查返回字段是否携带单位标识，核对`field_return_with_unit`配置是否生效。
- 模拟批量拉取年度财报数据，检查接口响应时间是否符合业务需求，确认`PARSE_FILE_TIMEOUT_SECONDS`配置适配当前请求时长。
- 开启流式输出测试，观察返回数据的分段长度是否符合预期，调整`stream_response_chunk`配置直至前端展示流畅。
- 调用对话API生成财报分析报告，检查对话日志中的请求参数与实际调用的外部接口参数是否一致，确认认证配置正确。
