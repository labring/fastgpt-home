# 出版财报分析的部署与升级

## 这个品类的数据长什么样
出版企业财报数据主要来源于公开交易所披露平台、企业官网投资者关系板块。更新节奏以季度报告、年度报告为核心，临时公告则根据业务变动不定期发布。单份财报文档包含结构化主报表与详细附注，主报表涵盖营收、利润、资产等核心指标，附注则拆解细分业务营收、版权资产减值等细节内容。字段包含归母净利润、扣非净利润、各出版品类营收等，单位多为万元或亿元。

## 这些特征在「部署与升级」这一环带来什么约束
财报附注单文件篇幅较长，解析耗时较长，要求延长文件解析的超时阈值。多份财报批量处理时总数据量较大，需调整上下文窗口参数以容纳完整分析逻辑。临时公告的突发更新要求支持灵活的触发机制，适配非固定周期的数据拉取。不同出版企业的财报结构存在差异，需支持自定义字段抽取配置，适配不同主体的披露格式。批量拉取多份财报时，需延长工作流的整体执行时长，避免任务中途中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 秒 | 财报附注单文件常超300页，解析需较长时间 |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | 单份财报含多页附注与相关附件，需支持大文件上传 |
| `maxContext` | 12000–16000 字符 | 财报字段多且需关联上下文分析，需足够的上下文窗口承载信息 |
| `召回条数` | 前8–12条 | 财报关键指标分散在不同段落，需召回足够相关片段支撑分析 |
| `定时任务触发间隔` | 86400 秒（1天） | 季度报更新周期为3个月，每日拉取可及时获取最新公告 |
| `工作流超时时间` | 1800 秒 | 批量处理多份财报时，需延长任务执行时长避免中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：填入`模型API_KEY`后调用报错，提示密钥无效。原因：未在平台密钥管理页面完成权限绑定，或复制密钥时混入了多余空格。
- 现象：选择`GPT-4o mini`模型时输入“350怎么样”触发400错误，更换其他模型后恢复正常。原因：该模型对输入文本的格式要求严格，未正确配置prompt模板的上下文截断逻辑。
- 现象：工作流编排时调试面板不显示`代码运行`步骤。原因：未开启工作流的调试权限开关，或步骤配置中未正确绑定执行节点的运行环境。

## 怎么确认配好了
- 上传单份300页的财报附注文件，查看解析任务是否在`PARSE_FILE_TIMEOUT_SECONDS`设定的时间内完成。
- 发起单次财报分析请求，查看返回结果中是否包含预设的核心字段，且字段单位与财报披露格式一致。
- 测试定时拉取任务，查看指定目录下的新财报文件是否自动触发解析流程。
- 调用模型接口，检查返回的分析结果无密钥报错，且符合预设的财报分析逻辑。
