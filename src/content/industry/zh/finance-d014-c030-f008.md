# 化妆品财报分析的工具调用与插件

## 这个品类的数据长什么样
化妆品品类的财报数据主要来自品牌方公开的年度、季度业绩公告，以及第三方公开的电商销售监测数据。数据更新节奏为季度公告每季度末后30天内更新，年度公告于次年4月前完成披露，电商渠道的实时销售数据可按日同步。文档多以结构化表格呈现，包含营收分类项、单品类营收金额、渠道类型、营销投入金额、研发投入金额、SKU总数等字段，单位多为人民币元，跨境品牌会同步标注美元计价的对应数据。

## 这些特征在「工具调用与插件」这一环带来什么约束
多数据源的特性要求工具调用需同时对接结构化公告解析接口与电商销售API，需支持配置不同数据源的拉取频率。季度公告的固定更新周期要求工具需预设定时触发任务，避免手动拉取的延迟。不同品牌财报的表格字段顺序、命名存在差异，要求工具调用需支持自定义字段映射规则，适配不同品牌的文档结构。多计价单位的存在要求插件需内置汇率转换逻辑，自动对齐统一计价单位。实时电商数据的拉取需配置合理的接口调用阈值，避免超出调用限额。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 化妆品财报PDF通常包含多页结构化表格与长文本描述，600秒可覆盖完整解析流程 |
| `MCP_SERVER_DEPLOY_TYPE` | `remote` | 化妆品财报数据分散在公开公告与电商API，需部署独立MCP服务对接多类数据源，适配4.9.6版本的部署要求 |
| `SYNC_TASK_CRON_EXPRESSION` | `0 0 2 * * *` | 季度公告通常在季度末后30天内披露，每日凌晨2点同步可及时获取最新数据 |
| `TOOL_CALL_MAX_RETRIES` | `2` | 财报数据接口调用可能因网络波动失败，2次重试可在保证成功率的同时避免资源浪费 |
| `TOKEN_CALCULATION_STRATEGY` | `openai_compatible` | 适配主流大模型的token计数规则，满足社区常见的token计算需求 |
| `ALLOWED_LLM_MODELS` | `gpt-4o, gemini-pro` | 覆盖主流大模型，满足社区常见的模型调用需求 |
| `TOOL_KNOWLEDGE_BASE_ENABLE` | `true` | 需同时调用知识库的行业通用数据与工具的品牌专属财报数据，提升分析准确性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用工具时返回`429 Too Many Requests`错误，原因：未配置合理的同步间隔与批量调用阈值，短时间内多次拉取财报数据导致接口限流。
- 现象：工具调用结果中出现字段为空的情况，原因：未配置自定义字段映射规则，未适配不同品牌财报表格的字段命名差异，导致无法正确提取目标数据。
- 现象：配置后无法同时触发知识库搜索与工具调用，原因：未开启`TOOL_KNOWLEDGE_BASE_ENABLE`配置项，或工具流的节点顺序配置错误，未将工具调用节点置于知识库召回节点之后。

## 怎么确认配好了
- 手动触发一次工具调用，查看返回结果中是否包含配置的目标财报字段，核对字段名称与单位是否符合预期。
- 查看定时同步任务的日志，确认是否按配置的Cron表达式按时触发，且无解析超时或接口调用失败的记录。
- 测试多数据源的联动调用，确认知识库数据与工具返回的财报数据可同时被整合到分析结果中。
- 查看token消耗记录，确认token计算规则按配置的策略执行，无异常的计数偏差。
