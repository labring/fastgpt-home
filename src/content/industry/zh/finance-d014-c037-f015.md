# 卫星通信财报分析的部署与升级

## 这个品类的数据长什么样
卫星通信财报的数据来源为卫星通信运营商公开披露的季度、年度财报，以及行业监管机构发布的运营统计数据。更新节奏为每季度一次常规财报更新，临时运营数据更新无固定周期。文档多以结构化表格搭配文字分析的形式呈现，包含核心运营指标、成本项、营收项与现金流数据。字段涵盖转发器实际使用时长、地面站运维成本、带宽租赁营收、新增签约客户数、累计服务时长等，单位分别为小时/季度、万元/季度、万元/季度、个、万小时。

## 这些特征在「部署与升级」这一环带来什么约束
卫星通信财报的数据来源分散且格式存在差异，部署阶段需配置多源数据拉取适配规则，兼容公开财报PDF、结构化报表等不同格式。季度固定更新与临时运营数据并存的节奏，要求部署时支持灵活调整数据同步周期，同时配置增量同步逻辑以避免重复加载。多字段多维度的文档结构，需要预设字段映射模板，确保解析后的财报数据可直接对齐分析模型的输入要求。升级阶段需兼容旧版字段映射规则，避免因版本更新导致已配置的数据源链路中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 卫星通信财报文档通常包含多页表格与长文本，解析耗时较长，900秒可覆盖完整解析流程，适配4.9.11版本的解析逻辑 |
| `DATA_SYNC_INTERVAL` | `86400 秒`（日常同步）、`604800 秒`（季度财报同步） | 常规运营数据按日同步，季度财报仅需在财报发布周同步，灵活调整周期适配更新节奏 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 卫星通信财报可能包含多份附件的合并文档，单文件体积较大，2000 MB可覆盖常见文档规模 |
| `FIELD_MAPPING_TEMPLATE` | 卫星通信财报标准模板 | 该模板预设了转发器使用时长、地面站运维成本等专属字段，可减少手动配置成本 |
| `PARSE_TABLE_ENABLED` | 开启 | 卫星通信财报的核心数据以表格形式呈现，开启表格解析可完整提取结构化指标 |
| `RECALL_CHUNK_SIZE` | `1500–2000 字符` | 财报文档的单段落信息密度较高，适当延长召回块长度可保留完整业务逻辑 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 容器状态显示running但无法访问前端页面：现象为容器启动后端口映射配置完成，但访问宿主机对应端口无响应或返回错误，原因是未正确绑定容器内服务的监听地址，或宿主机防火墙拦截了映射端口。
- 登录或数据同步时返回`code:500`的`URI malformed`报错：现象为界面弹出500错误提示，日志中包含URI格式错误的堆栈信息，原因是配置的数据源URL包含未转义的特殊字符，或拉取的财报文档路径包含非法字符。
- root账号密码周期性重置：现象为root账号密码每隔约24小时被重置为默认值，原因是未关闭默认的初始化重置脚本，或容器挂载的配置目录未持久化存储账号配置。

## 怎么确认配好了
- 执行一次手动数据同步任务，查看同步日志中是否存在解析失败或字段不匹配的提示，根据提示调整字段映射规则或解析参数。
- 访问前端页面，验证是否可正常加载并显示已配置的财报数据源列表，若存在异常则检查端口映射与服务监听配置。
- 触发一次临时数据更新任务，确认增量同步逻辑是否正常生效，无重复数据加载或数据丢失的情况。
- 查看容器运行日志，确认所有配置项的参数值已被正确加载，无参数冲突或未识别配置的提示。
