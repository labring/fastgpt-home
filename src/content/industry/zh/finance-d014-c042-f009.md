# 品牌代运营财报分析的引用来源与溯源

## 这个品类的数据长什么样
品牌代运营场景的财报分析数据，主要来自品牌方提供的月度销售台账、电商平台后台交易明细、第三方营销监测工具的投放数据，以及代运营团队的内部执行报表。数据更新以月度为核心周期，季度财报节点会追加汇总数据。单份文档通常包含投放预算、实际消耗、渠道转化、商品销量、运营成本五大模块，字段含投放ROI、单客获客成本、平台佣金费率、库存周转天数，单位对应人民币元、万元、倍数、自然日。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据的混合接入，要求溯源环节必须清晰标注每一条引用内容的原始数据源类型与采集时间，避免跨台账的数据混淆。月度周期的更新节奏，要求同步配置适配固定的批量更新窗口，避免增量同步遗漏跨周期数据。单份文档模块多且存在长明细条目，要求召回环节需支持按模块精准筛选引用内容，同时需适配单块文本超出常规长度的场景，避免截断关键财报指标。多字段的结构化设计，要求溯源返回的引用数据需完整携带字段名与对应单位，确保分析结果的可读性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `splitChunkSize` | 800–1200 字符 | 品牌代运营财报文档多包含长明细条目，该取值可平衡单块文本完整性与召回精准度，避免单块超出引用上限 |
| `recallTopK` | 前6–8条 | 财报分析需覆盖投放、销售、成本等多模块数据，该取值可确保召回足够的关键条目，避免核心信息遗漏 |
| `similarityThreshold` | 0.72–0.80 | 财报数据字段标准化程度高，该阈值可过滤低相关的非财报类内容，同时保留同指标跨数据源的对比条目 |
| `sourceTagEnable` | 开启 | 多源数据场景下，开启后可自动为每条召回内容附加数据源标识，满足溯源要求 |
| `updateSyncInterval` | 21600 秒 | 适配月度更新周期，每6小时执行一次增量同步，可在保障数据时效性的同时降低服务器负载 |
| `chunkOverlap` | 100–150 字符 | 财报模块间存在关联数据，该重叠长度可避免跨模块的关键指标被截断，确保引用内容的上下文完整 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：设置`maxContext`为1500字符后，仍有超过该长度的知识库块被召回引用。原因：未同步配置`splitChunkSize`参数，长文本未被正确分段，原始块直接参与召回。
- 现象：知识库检索命中目标条目，但对话结果仅返回引用标识无对应内容。原因：未开启`sourceTagEnable`配置，或未在工作流中传递包含`title`、`content`、`sourceUrl`的结构化引用元数据。
- 现象：创建插件后，在工作流中引用插件并接入代码运行节点时，输入框触发报错。原因：未正确配置插件的入参格式，未将检索得到的`sourceList`字段映射至代码节点的输入参数中。

## 怎么确认配好了
- 上传一份包含长明细的代运营月度财报文档，查看分段后的块长度是否符合`splitChunkSize`的配置区间。
- 发起财报相关查询，检查返回结果中是否携带每条引用内容的数据源标识与字段信息。
- 模拟月度数据更新，查看系统是否按照`updateSyncInterval`的配置自动完成增量同步，无遗漏条目。
- 在工作流中接入知识库检索与AI对话节点，确认对话结果中引用的元数据格式符合预期要求。
