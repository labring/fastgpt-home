# 商业地产财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
商业地产财报的数据来源包含项目运营台账、租赁签约系统、财务核算模块三类核心系统。更新节奏分为两类：单项目的月度租赁、能耗数据实时同步，季度合并财报按财季固定更新。文档结构以单项目为基础维度，包含基础信息、收支明细、分摊数据三类模块，字段包含「租赁签约面积」「月度租金应收」「公共能耗分摊额」等，单位分别为平方米、元、元。单份财报文档包含多个项目的合并数据，整体篇幅较长。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据来源要求接口兼容不同系统的鉴权方式与数据格式，需支持自定义请求头与参数映射。分实时与定期的更新节奏，要求接口同时支持同步拉取与异步回调两种调用模式，适配不同业务的时效性需求。多维度的文档结构要求接口入参需支持按项目ID、财季范围、数据类型进行筛选，避免返回冗余数据。专属字段与固定单位要求接口返回的字段需严格匹配业务定义，不得擅自转换单位或遗漏字段。多项目合并数据的特性要求接口支持分页查询，降低单次请求的负载压力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `API_WORKFLOW_TRIGGER_TOKEN` | 为每个外部对接系统生成专属令牌 | 避免单令牌泄露影响全量对接链路 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 商业地产财报包含多项目合并Excel、长PDF报告，单文件体积超出通用场景上限 |
| `WORKFLOW_TIMEOUT` | `900 秒` | 财报分析需处理多维度数据关联、批量计算，执行耗时较长 |
| `KNOWLEDGE_BASE_ID` | 绑定商业地产专属知识库的ID | 区分不同业务场景的知识库数据，避免上下文污染 |
| `API_REQUEST_TIMEOUT` | `120 秒` | 对接外部财务系统时，接口响应存在一定延迟 |
| `PARSE_FILE_FIELD_MAPPING` | 按实测标定 | 商业地产财报存在专属字段如「租赁签约面积」「公共能耗分摊额」，需自定义字段映射 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用工作流接口时返回`400 Bad Request`，提示「知识库未配置」。原因：未在请求体中正确传入`knowledgeBaseId`参数，或传入的ID未绑定当前工作流的全局变量。
- 现象：上传财报文件后返回`413 Payload Too Large`。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，默认配置无法容纳商业地产大体积财报文件。
- 现象：升级到`4.9.0`版本后执行升级脚本时出现`curl: (7) Failed to connect`报错。原因：未检查目标服务器的防火墙规则是否开放了升级脚本所需的端口，或升级脚本的curl命令参数存在格式错误。

## 怎么确认配好了
- 调用工作流触发接口，传入测试用的商业地产项目ID，检查返回结果是否包含业务定义的专属财报字段。
- 上传符合业务常规体积的测试财报文件，确认接口返回成功状态码，无文件过大相关报错。
- 执行升级脚本并查看终端输出，确认无连接类报错，脚本执行进度正常。
- 查看工作流运行日志，确认知识库ID参数被正确读取并用于上下文召回。
