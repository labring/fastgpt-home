# 商业地产财报分析的工具调用与插件

## 这个品类的数据长什么样
商业地产财报数据主要来自自持物业运营台账、租金收缴系统、不动产管理平台与年度审计报告。数据更新节奏分两类：月度运营数据每月末更新，年度合并财报需经第三方审计后于次年第一季度末披露。单份财报文档包含项目级的可出租面积、实收租金、运营成本、空置时长等字段，字段单位多为平方米、元、天，不同项目的字段命名存在差异，无统一标准化模板。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且字段命名不统一，导致工具调用时需适配多套数据接口，需提前配置字段映射规则。月度数据更新频率高，工具调用需支持定时触发的批量任务，避免单次调用延迟过长。单份财报文档长度差异大，从数千到数万字符不等，工具调用的上下文窗口需适配长文本处理，同时需限制单轮调用的文档拆分粒度。部分数据需经审计后披露，工具调用需支持校验数据发布时间，避免调用未公开的财报数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxToolCallRetryTimes` | `2–3 次` | 商业地产财报数据接口偶有临时波动，重试2-3次可覆盖多数异常场景，降低单次调用失败率 |
| `toolCallTimeout` | `600 秒` | 单份年度财报需拉取多类运营台账数据，600秒可覆盖完整的数据拉取、格式转换与分析流程 |
| `toolFieldMapping` | `按项目预设映射规则` | 商业地产项目字段命名无统一标准，提前配置映射可确保工具调用时正确提取目标字段 |
| `maxContextLength` | `12000–15000 字符` | 单份商业地产财报文档长度差异显著，该区间可覆盖绝大多数单文档处理需求，避免上下文溢出 |
| `toolCallMaxParallel` | `2 个/调用` | 适配多项目财报分析场景，限制并行调用数量可避免接口限流，同时满足同时触发多个工具调用的需求 |
| `streamToolResponse` | `开启` | 长周期的财报分析任务需实时返回进度，流式输出可提升任务执行的透明度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：尝试同时触发3个财报数据拉取工具时，仅返回1个调用结果。原因：未配置`toolCallMaxParallel`参数，默认并行调用数量限制为1，无法支持多任务同时触发。
- 现象：工具调用提取的租金数据与实际台账不符，部分字段为空。原因：未配置`toolFieldMapping`，未适配商业地产项目的专属字段命名规则，导致数据提取错误。
- 现象：工具调用在部分国内地域无法正常发起，返回连接超时错误。原因：未配置接口的地域访问权限，导致部分区域的调用请求被拦截。

## 怎么确认配好了
- 发起单项目月度财报分析任务，查看工具调用日志中的重试记录，确认重试次数与`maxToolCallRetryTimes`的配置一致。
- 发起2个以上项目的财报拉取任务，确认接口未返回限流相关报错，符合`toolCallMaxParallel`的配置要求。
- 导入一份完整的商业地产年度财报文档，测试工具调用流程，确认未出现上下文溢出或超时报错。
- 发起长周期的财报分析任务，查看结果输出形式，确认流式输出功能正常启用。
