# 商用车财报分析的工作流编排

## 这个品类的数据长什么样
商用车财报数据主要来自上市商用车企业的年度、季度公开财报，以及行业协会的产销公示数据。数据更新节奏为季度更新核心经营数据，年度更新完整审计报告。文档结构包含合并资产负债表、利润表、现金流量表，以及商用车细分品类产销明细、营运车辆资产明细等专项板块。字段包含单车毛利率、产销辆数、融资租赁余额，单位多为万元、辆、年等，部分专项字段需匹配商用车品类的经营特性。

## 这些特征在「工作流编排」这一环带来什么约束
商用车财报的多数据源特性要求工作流需配置多个HTTP请求节点分别对接企业财报接口与行业数据接口，避免单一数据源缺失导致流程中断。季度更新的节奏要求定时触发节点需设置匹配财报发布周期的运行参数。专项产销字段的存在要求解析节点需配置自定义字段提取规则，匹配商用车品类特有的数据项。单份年度财报文档篇幅较长，要求工作流节点预留足够的解析与处理时长，同时限制单批次处理的文档数量，避免资源占用过高。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 商用车年度财报PDF通常篇幅较长，包含多页专项产销明细，需足够时长完成文本解析 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 完整年度审计报告的扫描件或原生PDF体积可达数百兆，需适配大文件上传需求 |
| `HTTP_REQUEST_BODY_TYPE` | `form-data` | 部分财报数据源接口要求以表单形式提交认证参数与数据请求参数，支持文件类型参数上传 |
| `WORKFLOW_TRIGGER_CRON` | `0 0 2 * * 1` | 商用车财报通常在季度结束后1-2周公开，定时触发需避开公开窗口期的接口压力 |
| `PARSE_SEGMENT_LENGTH` | `1200–1500 字符` | 商用车财报的专项板块文本密度较高，分段长度需适配字段提取的精准度需求 |
| `FILE_PARSE_SPECIFIC_FIELDS` | `["重卡销量", "轻卡产能", "融资租赁余额"]` | 商用车财报的核心分析字段与通用财报不同，需指定提取特定品类相关的字段 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流中HTTP请求节点配置`form-data`类型body时，无法成功发送文件参数。原因是未将文件参数的类型设置为文件流格式，或未正确绑定工作流上游的文件输出节点。
- 现象为工作流的文件解析节点返回`Load file error`报错。原因是配置的`UPLOAD_FILE_MAX_SIZE`参数值小于当前上传的财报文件体积，或文件格式未被解析节点支持。
- 现象为本地部署环境下，工作流的文件解析节点无执行日志。原因是部署时未正确配置文件存储目录的读写权限，导致解析节点无法读取上传的财报文件。

## 怎么确认配好了
- 手动触发一次工作流，查看各节点的执行日志，确认HTTP请求节点成功拉取到财报数据，文件解析节点完成文本提取。
- 核对工作流中自定义字段提取规则，确认已包含商用车品类特有的分析字段，如重卡销量、单车毛利率等。
- 测试`form-data`类型的文件参数配置，上传测试用的小型财报文件，确认请求无报错且返回结果符合预期。
- 检查定时触发节点的配置，确认触发频率与财报更新节奏匹配，未设置在接口负载较高的时段。
