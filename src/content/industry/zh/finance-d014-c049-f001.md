# 基建工程财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
基建工程财报数据主要来自建筑装饰类企业公开披露的定期报告、项目备案台账与结算文件。数据更新节奏随财报周期推进，季度财报每季度更新一次，年度财报年末更新，单个项目的进度数据随施工节点月度同步。文档结构通常包含项目编号、项目名称、合同总金额、已结算金额、累计成本支出、回款进度、施工周期等字段，金额字段单位统一为万元，工期字段以自然月或日历天为单位，单项工程的单位造价字段以元/平方米、元/立方米等工程计价单位标注。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
基建工程财报的数据多源且结构复杂，要求HTTP接口支持多源数据拉取与字段映射适配。季度级别的更新节奏，限制了外部系统同步请求的频率，避免高频调用产生冗余流量。工程专属的计价单位与字段，要求接口参数校验模块支持自定义单位规则与动态字段扩展。长周期项目的财报文档篇幅较长，要求接口的超时设置适配长文本处理需求，同时支持分页拉取大额数据集，避免单次请求超时或数据截断，适配FastGPT V4.9.1版本的接口规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600-900 秒` | 基建工程财报文档包含多项目明细与结算附件，篇幅较长，需足够的解析时间完成内容拆分与字段提取 |
| `UPLOAD_FILE_MAX_SIZE` | `1500 MB` | 基建工程财报通常包含多份项目台账附件，单批次上传文件总大小超出通用文档场景上限 |
| `field_mapping_strategy` | `按工程计价单位标准化` | 基建工程财报包含元/平方米、万元等专属计价单位，需统一映射为标准分析字段单位 |
| `HTTP_REQUEST_TIMEOUT` | `300 秒` | 外部系统拉取大额基建财报数据集时，单次请求耗时较长，需适配长链路请求的超时限制 |
| `enable_dynamic_field_support` | `开启` | 基建工程财报存在项目编号、单项工程造价等自定义字段，需支持动态参数传递以适配不同项目场景 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用`/api/core/dataset/collection/create/localFile`接口时返回404错误。原因：未在管理后台开启对应API的权限开关，或接口路径存在拼写偏差。
- 通过HTTP接口上传基建财报文件后，无法按项目编号、合同金额等字段执行元数据过滤。原因：未在接口请求中携带标准`metadata`参数，或未开启数据集的元数据自动采集功能。
- 解析大额基建财报文档时返回504网关超时错误。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`配置项，默认超时时长不足以处理长篇幅的工程类文档。

## 怎么确认配好了
- 调用目标HTTP接口，查看返回的响应头中是否包含`X-FastGPT-Request-ID`字段，确认接口已正常接入。
- 上传一份测试用的基建工程财报文档，检查返回结果中是否包含解析后的字段与元数据，确认字段映射规则生效。
- 模拟外部系统的同步请求，查看管理后台的接口调用日志，确认请求频率符合预设的同步规则。
- 调用模型对话接口，输入基建财报相关的分析问题，查看返回结果是否包含正确的工程字段信息，确认配置生效。
