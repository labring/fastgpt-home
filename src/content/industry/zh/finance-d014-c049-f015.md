# 基建工程财报分析的部署与升级

## 这个品类的数据长什么样
基建工程财报数据主要来自公开披露的上市公司定期报告、项目业主方报送的进度台账，更新节奏以季度、年度为核心周期，部分在建项目数据按月更新。文档结构包含项目立项批复、合同总价、已完成工程量、累计成本支出、现金流净额等字段，单位多为万元、立方米、施工天数等，单份财报文档篇幅较长，包含多维度的项目明细数据。

## 这些特征在「部署与升级」这一环带来什么约束
基建工程财报数据篇幅较长且包含多维度明细字段，部署时需预留足够的解析与存储资源，避免因单份文档过大导致解析超时。固定周期的更新节奏要求部署时配置定时同步脚本的触发间隔，适配季度、月度的数据源更新频率。多类型字段与特殊单位的存在，要求解析环节配置自定义字段映射规则，避免单位识别错误。升级过程中需保留现有同步任务的断点续传能力，防止数据同步中断导致的报表缺失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 基建财报文档篇幅较长，需预留充足的解析时间 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 单份基建财报及附属项目明细文件体积较大，适配大文件上传需求 |
| `VECTOR_CHUNK_SIZE` | `1500–2000 字符` | 基建财报包含多维度明细字段，该分段长度可保留项目信息完整性 |
| `SYNC_CRON_EXPR` | `0 0 2 * * 1,4` | 适配多数基建数据源按周、月更新的节奏，减少同步冲突 |
| `MONGO_IMAGE_TAG` | `4.4.29` | 兼容不支持AVX指令集的服务器CPU，避免版本兼容性报错 |
| `AUTHENTICATION_ENABLE` | `true` | 自有服务器部署需控制内部财报数据的访问权限 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：启动服务后弹出`mongo version incompatible`报错，日志中包含AVX指令集不支持的提示。原因：使用了依赖AVX指令集的MongoDB高版本镜像，未适配老旧服务器硬件。
- 现象：上传的基建财报文档解析失败，返回`413 Request Entity Too Large`状态码。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置项，默认值不足以承载大体积的财报附件。
- 现象：启用免登录的部署场景下，未授权用户可直接访问内部财报数据。原因：未将`AUTHENTICATION_ENABLE`配置为`true`，未开启身份验证功能。

## 怎么确认配好了
- 登录服务后台，查看MongoDB连接日志，确认使用的镜像版本与配置的`MONGO_IMAGE_TAG`一致。
- 上传一份标准基建财报文档，检查解析后的字段是否包含项目概算、已完成工程量等预设字段，确认字段映射配置生效。
- 手动触发一次定时同步任务，查看同步结果是否覆盖最新的数据源数据，确认`SYNC_CRON_EXPR`配置的触发逻辑正确。
- 测试未授权用户访问服务地址，确认无法直接进入系统，验证身份验证配置生效。
