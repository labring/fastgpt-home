# 多元控股财报分析的工作流编排

## 这个品类的数据长什么样
多元控股的财报数据主要来源于合并财务报表，包含母公司及下属各全资、控股子公司的归集数据。数据更新节奏为年度报告每年度末后固定周期发布，半年度报告每半年度末后固定周期发布。文档结构包含合并资产负债表、合并利润表、合并现金流量表及分部经营明细附件，字段涵盖归母净利润、少数股东损益、各业务板块营收占比等，单位统一采用万元或亿元，部分细分披露项需从多层级子公司报表合并提取。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据需从多层级子公司归集合并，工作流需支持多数据源的关联校验，避免单一层级数据遗漏。由于单份财报文档篇幅较长，工作流需支持分段解析与上下文关联，防止长文本截断导致的分析偏差。由于更新周期固定，工作流可配置定时触发节点，匹配财报发布节奏。由于字段包含多维度经营数据，工作流需预设字段映射规则，将原始报表字段转换为统一分析口径。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份合并财报文档篇幅较长，多层级数据解析耗时较长，600秒可覆盖完整解析流程 |
| `knowledgeSearch.recallCount` | `前8-10条` | 多元控股财报包含多板块数据，需召回足够多的相关片段支撑合并分析 |
| `maxContextWindow` | `8000-12000 字符` | 合并财报的上下文关联紧密，需保留足够多的历史解析片段确保分析逻辑连贯 |
| `WORKFLOW_TRIGGER_TYPE` | `定时触发` | 财报发布周期固定，定时触发可匹配数据更新节奏，无需手动启动 |
| `EXPORT_FILE_FORMAT` | `docx` | 财报分析报告需符合机构内部文档规范，docx格式支持复杂排版与批注 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 合并财报包含多层级子公司数据，单份文档体积较大，500 MB可覆盖常规披露文件大小 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流调用`knowledgeSearch`节点时，动态传入的知识库ID未匹配目标财报文档库，返回结果为空。原因：未将财报文档库单独配置为专属知识库，或动态传值时未绑定正确的知识库变量映射。
- 现象：工作流执行完成后未生成可下载的word文件链接。原因：未在工作流末尾添加文件导出节点，或未配置导出格式为`docx`。
- 现象：从4.8版本旧项目迁移工作流后触发配置报错。原因：未参考官方迁移文档更新工作流节点的参数命名，旧版节点与新版配置项不兼容。

## 怎么确认配好了
- 上传一份测试用的合并财报文档，触发工作流，检查解析节点的日志是否显示完整的字段提取结果。
- 配置动态知识库传值，传入测试知识库ID，发起分析请求，检查返回结果是否包含上传文档的引用片段。
- 触发工作流后，检查流程详情页是否生成`docx`格式的导出链接，可正常点击下载。
- 从4.8版本的旧项目导出工作流配置，导入新版项目后，核对各节点的参数名称是否与新版界面一致。
