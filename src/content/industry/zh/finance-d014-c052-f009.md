# 多元控股财报分析的引用来源与溯源

## 这个品类的数据长什么样
数据来源为上市公司官方披露的年度报告、半年度报告及专项公告，更新节奏为年度报告于会计年度结束后4个月内发布，半年度报告于中期结束后2个月内发布。文档结构包含合并资产负债表、合并利润表、合并现金流量表，以及分部经营数据、关联交易披露、少数股东权益明细等模块。字段包含归属于母公司所有者的净利润、各分部营收占比、关联交易金额等，单位通常以人民币万元或亿元为基准，同时区分合并报表与单体报表数据。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多元控股财报包含合并与分部双重数据模块，且存在大量专业术语与结构化字段，这要求溯源需精准定位到具体披露章节与段落，避免混淆合并与分部数据。其次，财报更新周期固定且披露内容具有严谨性，需配置版本关联机制，确保引用数据与报告发布时间匹配，避免使用过期或未披露的信息。另外，关联交易与分部数据分散在不同章节，需要支持跨段落的上下文关联召回，同时需限制无效来源的召回，确保引用仅来自官方披露的有效模块。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `rag_recall_top_k` | 前10-15条 | 多元控股财报包含合并报表、分部报告等多个数据模块，需足够召回覆盖不同业务板块的披露内容 |
| `segment_max_length` | 800-1200字符 | 财报段落多为结构化披露，该分段长度可保留报表字段的上下文关联，避免破坏披露逻辑 |
| `source_reference_mode` | 段落级+章节锚点 | 财报披露带有明确的章节编号与段落位置，双维度标注可实现精准溯源 |
| `file_parse_chunk_overlap` | 100-150字符 | 合并报表与分部报告的字段存在跨分段关联，重叠分段可保留数据上下文的完整性 |
| `reference_citation_threshold` | 0.75-0.85 | 财报术语专业性强，较高的相似度阈值可过滤无关的非财报类召回内容 |
| `max_reference_count` | 前5条 | 多元控股财报的核心引用来源集中在固定的几个报表模块，过多引用会干扰回复可读性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：回复末尾显示“没有权限操作此对话记录”的权限报错。原因：未配置数据源的访问权限映射，或引用锚点指向了未开放的文档片段。
- 现象：输入`\n`作为引用分隔符时，回复中原文输出转义字符，未实现换行。原因：未在系统提示词中启用Markdown原生换行解析，或未正确绑定渲染参数。
- 现象：无法关闭回复中的引用展示，或返回的引用条数超出设置的`max_reference_count`。原因：未将`enable_citation_display`参数配置为`false`，或未开启`rag_filter_after_rerank`参数过滤冗余来源。

## 怎么确认配好了
- 上传一份多元控股的合并年报PDF，发起包含“分部营收占比”的查询，核对回复末尾的引用是否标注了具体的文档章节与段落位置。
- 调整`rag_recall_top_k`为`前5条`，发起多轮包含不同财报模块的查询，核对返回的引用条数与设置值匹配。
- 测试配置`reference_citation_prefix`为`"来源：\n"`，核对回复中的引用是否正确实现换行分隔。
- 上传一份非授权的非财报文档，发起相关查询，核对该文档未被作为引用来源返回。
