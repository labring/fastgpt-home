# 多元控股财报分析的文档解析与分块

## 这个品类的数据长什么样
多元控股的财报数据主要来自公开披露的年度、半年度及季度报告，包含合并报表、分部经营数据、关联交易明细等附件。更新节奏固定，年度报告每年披露一次，半年度、季度报告按对应周期发布。文档结构通常包含合并资产负债表、利润表、现金流量表，附加分部营收拆分、关联方往来说明等模块，字段涵盖归属于母公司所有者的净利润、各业务板块营收占比等，单位多以元、万元或亿元标注，部分跨境控股企业会包含多币种折算后的数据。

## 这些特征在「文档解析与分块」这一环带来什么约束
多元控股财报的多模块嵌套结构，要求文档解析时保留合并报表与分部数据的上下文关联，避免分块割裂核心逻辑。固定周期披露的大额文档，需要适配长文本处理能力，同时识别不同业务板块的独立信息单元。多币种与多单位标注的字段，要求解析环节同步捕获单位信息，防止后续分析出现数据混淆。附件包含的关联交易明细、高管薪酬等细分内容，需要精准识别模块边界，避免跨模块的无效分块导致信息混乱。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `max_chunk_size` | 800–1200 字符 | 多元控股财报包含合并报表与分部数据，该长度可覆盖单张报表行或单个业务板块的完整信息，避免割裂关键数据 |
| `chunk_overlap` | 150–200 字符 | 保留跨分块的上下文关联，例如分部营收与对应板块的附注说明，防止上下文丢失 |
| `parse_references` | 开启 | 多元控股财报的关联交易、分部数据常附带参考文献标注，开启后可完整提取引用来源，支持后续溯源分析 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 大型年度财报包含多模块附件，解析耗时较长，该时长可覆盖完整解析流程 |
| `enable_pdf_marker` | 开启 | 可精准识别PDF中的表格结构，避免合并报表的单元格错位，提升分块准确性 |
| `retain_original_units` | 开启 | 多元控股财报存在多单位标注，保留原始单位可避免数据转换误差 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：解析后的文档中references字段为空或未提取。原因：未开启`parse_references`配置项，或未适配财报中特殊的参考文献标注格式。
- 现象：尝试修改分块默认最大长度时，无法在界面找到对应设置项。原因：未在源码的`config/parse.js`文件中调整`default_max_chunk_size`参数，或未重新编译部署服务。
- 现象：本地部署pdf-marker功能正常，但FastGPT知识库上传PDF后无解析入口。原因：未在FastGPT的环境配置中启用pdf-marker集成，或容器挂载路径未正确关联pdf-marker服务端口。

## 怎么确认配好了
- 上传一份小型季度财报文档，查看解析后的文本中是否包含完整的references字段内容，核对配置项是否生效。
- 进入FastGPT的知识库配置页面，查看分块长度设置是否与预设的`max_chunk_size`参数一致，确认参数同步正常。
- 启动本地pdf-marker服务并关联FastGPT容器，上传一份PDF文档，检查解析入口是否正常显示，验证集成配置正确。
- 查看解析日志，确认`PARSE_FILE_TIMEOUT_SECONDS`参数对应的超时阈值未触发报错，验证时长配置符合文档体量。
