# 多元金融财报分析的工具调用与插件

## 这个品类的数据长什么样
多元金融财报数据主要来自交易所公开披露的定期报告、临时公告，以及行业自律组织发布的合规数据。更新节奏以季度、年度定期披露为主，伴随重大事项发布临时公告。文档结构包含财务报表、管理层讨论与分析、风险揭示等固定章节，字段涵盖受托资产规模、管理费收入、风险准备金计提等专有内容，单位多为人民币万元或亿元。

## 这些特征在「工具调用与插件」这一环带来什么约束
定期披露的更新节奏要求工具调用的调度配置需匹配财报发布周期，避免高频拉取无效数据。专有行业字段与长文档结构，要求插件内置自定义字段映射规则，适配受托资产规模等非通用财务术语，同时支持长文本分段解析与召回。临时公告的非结构化特征，要求工具调用需优先匹配半结构化数据解析插件，提升财报关键信息的提取精度。合规数据来源要求数据库连接插件需限定可访问的合规数据源范围，避免非法数据调用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 多元金融财报单份文档长度常超5000字符，需容纳完整财报片段与多轮对话上下文 |
| `RECALL_TOP_N` | `前 8–12 条` | 财报数据包含专有财务字段与行业术语，需召回足够相关片段覆盖分析需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 单份财报需解析多章节内容，耗时高于通用办公文档 |
| `plugin_db_allowed_databases` | `添加 MySQL、PostgreSQL、SQL Server，预留 Oracle 配置项` | 多元金融财报数据常存储于上述三类数据库，后续可扩展支持Oracle |
| `email_plugin_template` | `按财报发送格式配置模板` | 财报分析结果需标准化输出，需匹配金融行业报告的发送格式 |
| `tool_call_trigger_mode` | `按知识库召回结果触发` | 需基于财报片段的相关性触发工具调用，避免无效执行 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用对话接口后未返回知识库ID，仅显示空的引用字段。原因：未开启`enable_quote_id`配置项，或知识库配置未启用引用日志记录。
- 数据库连接工具报错提示不支持目标数据库。原因：未在`plugin_db_allowed_databases`中添加对应数据库类型，或未配置扩展支持的Oracle连接参数。
- 邮件发送插件返回`400 InternalError.Algo.InvalidParameter: messages with role "to"`错误。原因：未正确配置邮件接收者字段，或传入的`to`参数格式不符合插件要求，存在空值或非法字符。

## 怎么确认配好了
- 发起包含受托资产规模、风险准备金等专有术语的测试对话，查看返回结果中是否包含`quote_id`字段，确认引用日志配置生效。
- 尝试连接配置的合规数据库，执行简单的财报数据查询语句，验证数据库连接工具是否正常建立连接并返回数据。
- 配置邮件发送插件并传入合法的`to`参数，触发测试邮件发送，确认无参数错误返回。
- 上传一份标准测试财报文档，查看解析后的分段内容是否符合`maxContext`的配置范围，验证上下文设置生效。
