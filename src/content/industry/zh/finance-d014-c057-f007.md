# 小家电财报分析的工作流编排

## 这个品类的数据长什么样
小家电相关财报数据主要来自上市公司定期报告、公开零售监测公开数据。更新节奏为年度、半年度定期披露，月度零售数据随监测周期更新，重大事项临时发布公告。文档结构包含经营板块营收明细、成本构成、渠道占比、研发投入等内容。字段包含小家电品类营收金额、单台产品均价、渠道营收占比数值、单位产品盈利水平数值，单位为人民币万元、元/台、数值单位。

## 这些特征在「工作流编排」这一环带来什么约束
小家电财报数据的多来源、多更新节奏与细分字段特征，对工作流编排带来多重约束。首先，需支持定时触发与事件触发两种模式，适配定期财报披露与临时公告的不同更新节奏。其次，需兼容结构化财报字段与非结构化零售监测文本的拉取，部分数据源返回二进制文件流，需配置文件解析节点。再次，小家电品类细分字段较多，需配置字段筛选与分类聚合节点，精准提取目标数据。最后，财报文件体积存在波动，需调整节点超时与重试策略，避免拉取失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `workflow_trigger_mode` | 定时触发+事件触发双模式 | 适配小家电财报定期披露与临时公告的更新节奏 |
| `PARSE_FILE_MAX_TIMEOUT` | 300 秒 | 小家电财报文件通常包含多板块明细，解析耗时较长 |
| `http_request_timeout` | 120 秒 | 部分零售监测数据源返回大体积文件流，需延长请求超时时间 |
| `enable_env_invoke` | 开启 | 支持调用docker部署时配置的自定义环境变量，适配多数据源密钥管理 |
| `loop_step_increment` | 1 | 避免循环体下标累加后出现空值，匹配批量财报条目处理逻辑 |
| `retry_count_on_fail` | 3 次 | 临时公告推送可能存在网络波动，配置重试降低拉取失败率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：HTTP节点返回二进制文件流后，后续文本提取节点无有效输出。原因：未启用HTTP节点的二进制文件解析配置，默认仅解析JSON格式响应内容。
- 现象：调用docker部署时配置的自定义环境变量，工作流返回空值。原因：未开启`enable_env_invoke`配置项，或针对开源版4.8.17未正确挂载环境变量至运行容器。
- 现象：循环体中执行下标加1操作后，输出结果为null。原因：循环步长参数配置错误，初始下标未匹配批量数据的起始索引，导致累加后超出数据范围。

## 怎么确认配好了
- 手动触发一次工作流，检查HTTP节点返回的文件流是否被正确解析为可处理的内容，根据解析结果调整超时配置。
- 查看工作流配置页面的环境变量调用开关状态，确认`enable_env_invoke`已开启，验证自定义密钥是否能正常拉取数据源。
- 配置循环体测试批量条目，运行后检查每个下标的输出值是否连续且无空值，调整循环步长与初始下标参数。
- 配置定时触发任务，验证是否按设定周期自动启动工作流，临时公告推送后是否能触发事件启动工作流。
