# 工程咨询财报分析的知识库检索与召回

## 这个品类的数据长什么样
工程咨询类财报与项目数据主要来源于项目立项书、竣工结算报告、行业定额标准、企业年度经营报表及招投标文件。数据更新节奏随项目周期调整，单项目数据按进度节点按月或季度更新，年度财报数据按自然年度更新。文档结构包含结构化字段（如项目编号、造价金额、工期）与非结构化文本（如合规条款、进度说明），字段单位多为元、平方米、天等工程领域通用单位，单份文档长度存在较大跨度。

## 这些特征在「知识库检索与召回」这一环带来什么约束
工程咨询数据的混合结构与长文档特性，要求检索环节需同时适配结构化字段与非合规文本的精准匹配。高频更新的项目数据要求索引更新频率与业务节奏对齐，避免数据滞后。长文档的解析与分段需避免截断关键造价信息或合规条款，否则会导致检索结果缺失核心依据。此外，多字段的混合检索需区分不同数据类型的语义权重，防止无关内容干扰精准召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | 前10-15条 | 覆盖工程咨询场景下结构化造价数据与非结构化合规文本的多维度检索需求 |
| `相似度阈值` | 0.72-0.85 | 区分造价数据与合规文本的语义差异，过滤低相关的冗余结果 |
| `分段长度` | 1200-1500字符 | 适配工程咨询文档中单项成本明细、合规条款的标准长度，避免关键信息截断 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 900秒 | 处理大型竣工结算报告等超长文档，避免解析超时导致的链路中断 |
| `INDEX_UPDATE_INTERVAL` | 每6小时 | 匹配工程咨询项目数据按周/月更新的节奏，保证索引时效性 |
| `重排返回条数` | 前5条 | 聚焦高相关结果，适配工程咨询场景下精准决策的核心需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用知识库检索接口时返回502或504状态码，或对话页加载崩溃。原因：未适配工程咨询长文档的解析超时，`PARSE_FILE_TIMEOUT_SECONDS`取值过低，针对FastGPT 4.8.20及以上版本未优化大文件解析逻辑。
- 现象：新建数据索引后无法检索到最新的项目成本数据。原因：未将`INDEX_UPDATE_INTERVAL`调整为匹配项目更新节奏的取值，导致索引更新频率与业务数据更新不同步。
- 现象：生成的财报分析报告中强制包含「知识库」字样，或检索结果未结合当前分析的上下文返回精准内容。原因：未在检索配置中关闭`INCLUDE_SOURCE_TAG`参数，或未将当前财报分析的主题上下文传入召回接口。

## 怎么确认配好了
- 上传一份典型的工程咨询竣工结算报告，检查解析后的分段是否符合`分段长度`的配置，无关键信息被异常截断。
- 发起包含结构化造价字段的检索请求，检查返回结果的条数是否符合`召回条数`的配置，且相似度处于设定区间内。
- 模拟项目数据更新后，检查索引是否按`INDEX_UPDATE_INTERVAL`的配置自动完成刷新，新数据可被正常检索。
- 发起结合上下文的检索请求，检查返回结果是否与当前财报分析的主题匹配，无无关内容混入。
