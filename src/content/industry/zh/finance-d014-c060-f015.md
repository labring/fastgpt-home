# 工程咨询财报分析的部署与升级

## 这个品类的数据长什么样
工程咨询企业的财报数据来源包括内部项目管理系统导出的结构化报表、年度结算审计报告、材料采购台账，以及建筑装饰行业协会发布的行业造价参考数据。更新节奏按项目执行节点推进，月度更新进度类数据，年度决算时更新全量成本与收益数据。文档多为结构化Excel或多页PDF格式，包含项目编号、合同签约额、已完成产值、人力成本、材料单价、管理费费率等字段，单位涉及万元、人天、平方米、元/平方米等。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的数据来源要求部署阶段支持多格式文件上传与结构化解析适配，避免仅支持单一格式导致数据接入失败。大体积、长文档的特性要求配置更长的文件解析超时时间，升级阶段需兼容旧版大文件解析逻辑，避免升级后出现解析中断。字段丰富且单位多样的结构要求部署时配置自定义字段映射规则，升级阶段需保留用户已配置的映射关系，避免数据清洗失效。按项目节点的增量更新要求支持增量索引同步，升级阶段需确保增量同步逻辑不与全量索引冲突，避免重复计算资源浪费。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 工程咨询财报多为多页PDF或结构化Excel，单文件体积常超500MB，预留足够上传空间 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1200 秒` | 大体积财报解析需较长处理时间，避免中途超时中断 |
| `CHUNK_SIZE` | `1000–1500 字符` | 财报包含多字段段落，分块长度适配结构化文本的语义完整性 |
| `RECALL_TOP_N` | `前8条` | 单项目财报关联多份历史项目数据，需召回足够关联条目支撑分析 |
| `SIMILARITY_THRESHOLD` | `0.75–0.85` | 过滤低相关的跨项目数据，保留高匹配度的历史参考信息 |
| `INDEX_SYNC_INTERVAL` | `每小时` | 工程咨询财报按项目节点更新，增量同步频率适配业务更新节奏 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：进入FastGPT容器后执行`npm list mongoose`无返回结果，项目根目录`package.json`中可查看到mongoose依赖声明。原因：容器内仅在项目目录安装了依赖，未切换到项目目录执行npm命令，或未配置npm全局路径。
- 现象：docker-compose部署后，知识库管理界面无法显示已上传的财报索引，搜索结果为空。原因：未在docker-compose.yml的environment字段中添加索引同步相关的环境变量，未将本地索引配置文件挂载到容器对应路径。
- 现象：查看会话详情时弹出报错提示，后端日志返回`500 Internal Server Error`，提示`aiproxy connection failed`。原因：4.9及以上版本默认启用aiproxy，未配置`AIPROXY_URL`环境变量，或未启动aiproxy服务。

## 怎么确认配好了
- 上传一份测试用的工程咨询财报文件，查看上传进度条完成后，在知识库列表中显示该文件，无解析失败提示。
- 执行`docker exec -it [容器名或ID] npm list mongoose`，返回的依赖版本与项目根目录`package.json`中声明的版本一致。
- 访问部署地址的后端日志接口，查看最近的会话日志，无`aiproxy connection failed`类报错。
- 发起一次财报分析请求，等待返回结果后，核对结果中包含的项目字段与上传文件的字段一致。
