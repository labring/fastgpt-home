# 工程机械财报分析的多轮对话与提示词

## 这个品类的数据长什么样
工程机械行业财报数据主要来自上市公司公开披露的年报、季报、临时公告，以及行业协会发布的月度/季度统计报告。年度报告需在每年4月底前完成披露，季度报告于每季度结束后1个月内发布，临时公告如重大订单、产能变动则随时更新。文档以PDF格式为主，结构包含合并财务报表、报表附注、管理层讨论与分析板块，核心字段包括工程机械类主营收入、归母净利润、在手订单金额、产能利用率等，单位多为人民币元或万元。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
工程机械财报包含财务与业务两类数据，且单份文档文本量较大，多轮对话需保留前序查询的企业、时间、报表维度等上下文，避免混淆不同周期或板块的数据。财报更新频率不统一，多轮对话需支持实时拉取最新公告数据，提示词需明确限定数据来源与时间范围。部分字段如在手订单、产能数据属于非标准财务字段，提示词需明确区分业务与财务数据的查询逻辑，同时需统一单位转换规则，避免出现元与万元混用的情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `12000–16000 字符` | 工程机械单份年报文本较长，需保留多轮对话中的报表字段、时间与企业主体上下文 |
| `systemPrompt` | `仅分析工程机械相关财报数据，优先使用公开披露的年报、季报及临时公告，统一单位为万元，多轮对话需保留前序查询维度` | 明确限定分析范围与单位，避免无关信息干扰，统一多轮对话的上下文规则 |
| `HTTP_REQUEST_TIMEOUT` | `60 秒` | 拉取大型财报PDF或行业统计接口时，需预留足够的加载与解析时间 |
| `chunkSize` | `1800–2200 字符` | 工程机械财报的业务板块描述较长，分块时需保留完整的业务逻辑与数据关联 |
| `recallTopK` | `前 5–7 条` | 财报数据关联维度较多，需召回足够的报表片段支撑多轮追问与交叉验证 |
| `corsAllowOrigins` | `按部署域名配置` | 限制跨域请求来源，避免私有化部署场景下的接口安全风险 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中配置了HTTP请求用于拉取财报数据，但对话时未触发请求，日志中无HTTP调用记录。原因：未在提示词中明确要求调用联网接口获取实时财报，或工作流的触发条件未绑定对话环节。
- 现象：前端调用`/api/v1/chat/completions`接口时，浏览器控制台返回`No 'Access-Control-Allow-Origin' header is present on the requested resource`报错。原因：私有化部署时未配置跨域白名单，或白名单未包含前端访问域名。
- 现象：多轮对话返回的财报数据同时出现元与万元的混用情况。原因：未在系统提示词中明确要求统一数据单位，或分块召回时未携带单位限定的上下文信息。

## 怎么确认配好了
- 发起单轮查询，输入指定的财报查询指令，核对返回结果是否包含预设的核心字段与单位，调整配置项直到结果符合预期。
- 发起多轮追问，先查询单季度财报数据，再追加环比变化的问题，核对返回结果是否保留了前序的企业与时间维度，调整`maxContext`直到上下文不丢失。
- 使用前端测试工具调用对话接口，确认无跨域报错，核对跨域配置的取值范围是否覆盖合法访问来源。
- 查看对话日志中的token消耗统计，核对计算逻辑是否符合预设规则，调整相关配置确保统计准确。
- 查看工作流日志，确认每次对话触发时均有HTTP请求的调用记录，调整工作流触发逻辑确保请求被正常唤起。
