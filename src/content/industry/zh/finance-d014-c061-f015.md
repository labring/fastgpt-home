# 工程机械财报分析的部署与升级

## 这个品类的数据长什么样
这个品类的数据主要来自上市公司公开披露的季度报告、年度报告，以及交易所官方披露平台。更新节奏为每季度发布季度报告，每年发布年度报告，临时公告按需发布。文档结构包含核心财务指标、分产品业务数据、在手订单、存货及现金流情况。字段包含产品销量（单位：台）、营业收入（单位：万元）、营业成本（单位：万元）、存货余额（单位：万元）、经营活动现金流净额（单位：万元）等，部分报告还包含细分机型的业务占比相关指标。

## 这些特征在「部署与升级」这一环带来什么约束
分产品业务数据的字段分散且格式差异大，部署时需要配置多套文档解析模板适配不同上市公司的财报格式，升级时需同步更新解析规则避免字段提取失效。季度/年度报告的文档篇幅较长且批量导入需求集中，升级时需调整`PARSE_FILE_TIMEOUT_SECONDS`等参数的取值，避免长文档解析超时。临时公告的按需发布特性，要求部署时配置灵活的定时拉取任务，升级时需兼容不同的任务调度逻辑。此外，财报数据的字段单位统一难度较高，部署前需预设单位转换规则，升级时需同步更新转换逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600-900 秒` | 工程机械财报单份文档篇幅较长，需预留足够的解析时间 |
| `UPLOAD_FILE_MAX_SIZE` | `500-1000 MB` | 单份年度财报文档体积较大，需适配大文件上传需求 |
| `CHUNK_MAX_SIZE` | `800-1200 字符` | 财报文本包含大量专业术语，分段过长会影响召回精度，过短会割裂业务逻辑 |
| `SIMILARITY_THRESHOLD` | `0.75-0.85` | 财报字段匹配需较高精度，避免无关文本干扰 |
| `定时拉取间隔` | `3600-7200 秒` | 适配财报集中发布期与日常的不同拉取频率需求 |
| `ENABLE_MULTI_TENANT` | `开启` | 团队协作处理多公司财报分析需多租户支持 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 执行`docker build`构建镜像时出现报错`ERROR: failed to solve: failed to checksum fi`。原因是本地缓存的依赖包校验值异常，或网络波动导致依赖下载不完整。
- 从4.8.17版本升级到4.9.0版本时，运行官方升级脚本后出现`curl`相关执行报错。原因是升级脚本依赖的网络环境不稳定，或本地未安装`curl`工具。
- 部署后多用户无法实现独立的数据隔离与访问权限控制。原因是未正确配置多租户相关的参数，或未启用对应的权限校验逻辑。

## 怎么确认配好了
- 上传一份测试用的工程机械财报文档，核对解析后的字段提取结果是否符合预设的提取规则。
- 手动触发定时拉取任务，检查是否能成功拉取并解析指定的财报数据源。
- 创建两个测试账号，验证账号间的文档与分析任务无法互相查看或修改。
- 上传一份体积较大的财报文档，确认上传与解析过程未触发超时限制。
