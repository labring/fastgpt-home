# 房建工程财报分析的工具调用与插件

## 这个品类的数据长什么样
房建工程财报相关数据主要来自住建部门项目备案档案、建筑企业公开披露的季度/年度财报中的工程施工科目，以及项目阶段性结算文件。数据更新节奏随企业财报周期同步，同时项目节点数据按月或结算节点更新。单份财报文档通常包含项目清单、单体建筑面积、总造价、主材消耗总量、结算完成率、合同工期等字段，单位多为平方米、元（或万元）、吨、立方米、天。

## 这些特征在「工具调用与插件」这一环带来什么约束
房建工程财报数据分散于多类档案与报表中，要求工具调用插件支持对接住建部门开放接口、企业财报API及内部结算系统三类数据源，需额外配置跨源数据合并逻辑。单份文档包含多项目多维度字段且单位差异明显，插件需内置单位转换规则，将平方米、万元、吨等不同单位统一为分析可用的标准格式。数据更新存在周期与节点双重节奏，插件需支持按财报披露周期定时拉取，同时支持按项目结算节点触发增量拉取。单份财报关联项目数量较多，工具调用时需配置分页参数，避免单次返回数据过载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 房建工程财报常附带大量图纸、结算清单附件，2000 MB可覆盖常规大型文档上传需求 |
| `plugin_request_timeout` | `300 秒` | 房建工程数据接口返回内容较多，300秒可避免常规请求超时 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份大型房建财报文档解析耗时较长，600秒可确保完整解析 |
| `mcp_request_retry_times` | `3 次` | 适配内网环境下接口偶发波动的场景，减少请求失败概率 |
| `plugin_unit_conversion_enabled` | `开启` | 房建工程财报包含平方米、万元、吨等多类单位，开启后可自动统一分析单位 |
| `batch_query_limit` | `20 条/次` | 避免单次请求触发第三方接口限流，适配房建项目多且分散的特征 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用MCP插件时，房建工程财报的多项目参数传递后返回`invalid argument format`。原因：未按插件要求的数组格式传递项目ID列表，导致参数结构不符合预期。
- 现象：上传多张房建工程图纸附件时，上传流程中断，界面显示`file count exceed limit`。原因：未按插件要求的多文件传参格式传递附件，导致参数数量与插件预期不符。
- 现象：部署4.10.0版本后，调用插件时无法拉取房建工程附件，返回`minio access denied`。原因：未按新版本插件系统要求配置minio公网访问权限，内网环境下无法被插件服务访问存储的附件。

## 怎么确认配好了
- 上传一份常规大小的房建工程财报附件，检查上传流程无报错，确认配置的文件上传上限符合当前文档的实际大小。
- 触发一次插件调用，查看接口返回日志，确认参数格式与插件要求的结构匹配，验证请求超时配置适配当前请求耗时。
- 手动输入一组包含多单位的房建工程字段数据，触发插件的单位转换功能，确认转换后的单位符合分析标准，验证转换开关配置生效。
- 调用批量查询插件，查看返回的项目数量是否符合单次请求的限制，验证批量查询配置的合理性。
