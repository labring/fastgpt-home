# 投资平台财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
投资平台的财报数据来自境内外证券交易所公开披露文件、上市公司官方公告及合规第三方数据源。数据按季度、半年度、年度固定周期更新，临时公告触发即时更新。文档包含结构化的资产负债表、利润表、现金流量表等模块，附带非结构化的管理层讨论与分析章节。字段包含归母净利润、总资产、营业收入等，单位多为人民币元或万元，部分跨境数据附带外币折算字段。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
固定周期更新要求接口支持定时触发拉取任务，避免无效频繁请求。结构化与非结构化混合的数据结构，要求同时对接结构化数据查询接口与文档解析接口，拆分处理不同类型内容。多字段与特殊单位的要求，需要在接口请求中携带单位参数或预设字段映射规则。临时公告的即时更新需求，需配置webhook接收数据源的推送通知，实现增量同步。长文档与多字段的解析需求，需调整接口超时时间以保障完整处理。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_CONNECTION_STRING` | `mysql://username:password@host:port/database?charset=utf8mb4` | 投资平台财报数据需稳定持久化，使用标准MySQL连接格式适配官方部署规范 |
| `FETCH_INTERVAL` | `86400 秒`（常规周期）、`300 秒`（临时公告场景） | 匹配财报固定更新周期与临时公告的即时同步需求，避免过度调用接口 |
| `PARSE_DOC_TYPE` | `structured+unstructured` | 财报同时包含结构化表格数据与非结构化文本，需双模式覆盖全量内容解析 |
| `FIELD_MAPPING_RULE` | 按数据源字段名自动匹配，补充单位转换配置 | 适配财报字段多样、单位不统一的特征，统一输出目标系统要求的格式 |
| `WEBHOOK_SECRET` | 按数据源要求生成随机32位字符串 | 保障推送通知的安全性，防止未授权的增量同步请求 |
| `TIMEOUT_SECONDS` | `600 秒` | 财报文档包含大量表格数据，需足够时长完成解析与数据提取 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 请求接口返回`400 Bad Request`，状态码提示字段单位不匹配。未配置字段映射规则，直接使用数据源原始单位与目标系统要求不符。
- docker部署后无法连接MySQL数据库，日志提示`Connection refused`。未正确配置`DB_CONNECTION_STRING`中的host、port或权限参数，与本地部署环境不匹配。
- 调用解析接口返回空结果，未获取到财报表格数据。未开启`PARSE_DOC_TYPE`的structured模式，仅解析了非结构化文本内容。

## 怎么确认配好了
- 执行`curl`命令调用结构化数据接口，检查返回字段包含预设的核心财报字段，且单位符合目标系统要求。
- 查看数据库连接日志，确认无`Connection refused`或`Access denied`报错，验证`DB_CONNECTION_STRING`配置生效。
- 手动触发临时公告推送，检查webhook接口是否接收到通知并完成增量数据同步。
- 查看解析任务日志，确认同时生成了结构化表格数据与非结构化文本内容，覆盖全量财报信息。
