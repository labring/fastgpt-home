# 整车财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
整车品类的财报数据主要来自车企官方披露公告、境内外证券交易所公开平台及合规第三方财经数据源。更新节奏分为季度定期财报、月度销量快报及临时公告三类。单份财报文档结构包含核心经营指标、分车型销量数据、分区域营收占比、研发与制造成本明细等模块。字段包含车型编码、区域代码、销量单位（辆）、营收单位（元/万元/亿元）、同比变动幅度等，部分临时公告仅包含核心销量与营收数据。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
整车品类的财报数据特征直接约束HTTP接口与外部系统的对接逻辑。多数据源对接需求要求接口支持跨平台数据聚合，需兼容不同数据源的字段命名差异，例如部分数据源以`model_code`标识车型，部分以`model_name`直接返回中文名称。不同更新节奏对应差异化的调用模式：季度定期财报需支持批量全量拉取接口，月度销量快报需配置增量同步的断点续传机制，临时公告则需对接webhook推送接口实现实时同步。复杂的字段与单位体系要求接口返回数据需携带明确的单位标识，同时提供字段映射配置项，适配不同业务场景的字段转换需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `external_data_source_type` | `multi_source` | 适配整车财报多数据源的对接需求 |
| `api_request_timeout` | `300 秒` | 覆盖单份批量财报接口的完整返回时长 |
| `field_mapping_strategy` | `custom_mapping` | 兼容不同数据源的字段命名差异，例如`model_code`与`model_name`的转换 |
| `incremental_sync_interval` | `86400 秒` | 适配月度销量快报的每日增量同步需求 |
| `unit_conversion_enabled` | `true` | 统一不同数据源返回的营收、销量单位，避免计算误差 |
| `webhook_signature_secret` | `按实测标定` | 适配临时公告推送的身份校验需求，避免非法请求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用财报分析接口时返回`embedding model initialization failed`错误。原因：未单独配置专属索引模型，默认使用对接的第三方嵌入服务，未针对整车财报的长文本字段调整嵌入参数，对应v4.8.19及以上版本的配置变更。
- 现象：批量拉取季度财报时出现超时错误，日志显示`request timed out after 120 seconds`。原因：未调整`api_request_timeout`配置项，默认超时时长不足以覆盖批量财报数据的返回周期。
- 现象：docker-compose启动后无法调用外部财报接口，查看容器日志显示`invalid api key`。原因：未在启动容器前配置`CHAT_API_KEY`环境变量，或未重建容器使新配置生效。

## 怎么确认配好了
- 调用批量拉取接口，验证返回数据包含车型编码、销量、营收等核心字段，且单位与预设配置一致。
- 触发临时公告同步任务，验证webhook推送请求携带合法的签名校验信息，无非法请求拦截日志。
- 查看增量同步日志，验证仅拉取更新时间晚于上一次同步时间的财报数据，无重复条目。
- 检查模型配置页面，确认索引模型已单独配置，未依赖默认的第三方嵌入服务。
