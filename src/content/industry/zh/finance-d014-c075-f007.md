# 整车财报分析的工作流编排

## 这个品类的数据长什么样
数据来源为境内外证券交易所披露平台、车企官方投资者关系页面。更新节奏为季度终了后45天内披露季度财报，年度终了后60天内披露年报。文档结构包含合并财务报表、管理层讨论与分析、关联交易说明等模块。核心字段包含整车营收、销量、单车平均售价、研发费用占总营收的占比，单位分别为人民币亿元、万辆、万元/辆、比例数值。

## 这些特征在「工作流编排」这一环带来什么约束
财报数据的多来源与格式差异，要求工作流配置适配PDF、Excel、HTML的多格式解析节点，同时添加数据源校验环节，确认拉取的财报为目标车企的官方披露文件。季度/年度的固定更新节奏，要求工作流绑定定时触发规则，避免无效执行。文档的多模块结构，要求拆分数据提取节点，分别处理财务报表、业务数据与管理层分析内容，避免跨模块数据混淆。核心字段的特定单位要求，需要配置字段校验节点，验证提取数值的单位与预设规则匹配，防止后续计算出错。单份财报体量较大，需调整批量执行节点的并发阈值，避免解析超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 900 秒 | 单份整车财报解析内容较多，需预留足够解析时间 |
| `BATCH_EXECUTE_CONCURRENCY` | 3–5 | 整车财报单份数据量较大，过高并发会触发平台限流 |
| `MODEL_SELECTOR` | qwen3.5-plus | 财报分析需要较强的长文本理解与结构化提取能力 |
| `GLOBAL_VAR_APPEND_MODE` | 增量追加 | 需将循环节点内的子任务结果逐次写入全局变量，避免覆盖 |
| `NODE_ERROR_CATCH_SWITCH` | 开启 | 需捕获模型调用、数据解析环节的异常，避免工作流中断 |
| `MAX_CONTEXT_LENGTH` | 8000–12000 字符 | 适配整车财报的长文本解析需求，保留足够上下文用于字段提取 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为调用`qwen3.5-plus`节点时返回429 Request rate increased too quickly错误。原因未配置批量执行节点的并发阈值，或并发数设置过高触发模型限流。
- 现象为工作流中模型请求或数据解析节点出错后，工作流直接终止且无异常日志。原因未开启`NODE_ERROR_CATCH_SWITCH`配置项，未配置异常分支处理流程。
- 现象为批量执行节点完成后，循环节点内的子任务结果仅保留最后一项，其余结果丢失。原因未设置`GLOBAL_VAR_APPEND_MODE`为增量追加模式，默认模式为覆盖写入。

## 怎么确认配好了
- 手动上传一份目标车企的季度财报，触发工作流执行，检查解析节点是否成功提取核心字段。
- 查看工作流日志，确认批量执行节点的并发数未触发平台限流，无429类报错。
- 查看全局变量面板，确认循环节点内的所有子任务结果均被完整追加写入。
- 触发定时触发规则，检查工作流是否按预设的季度/年度周期自动执行。
