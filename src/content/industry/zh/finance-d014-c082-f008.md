# 水产养殖财报分析的工具调用与插件

## 这个品类的数据长什么样
水产养殖财报的数据主要来源于养殖企业内部生产台账、当地水产技术推广站月度统计报表、第三方水产行业监测数据库。数据更新节奏分为三级：月度塘口生产数据每日同步，季度汇总财报每季度末发布，年度完整年报固定在次年1月内更新。文档以结构化表格为核心主体，包含养殖水域面积、苗种投放量、饲料使用量、成品出栏量、单产水平、单位生产成本等字段，字段单位多为亩、万尾、吨、千克/亩、元/亩。

## 这些特征在「工具调用与插件」这一环带来什么约束
水产养殖财报的多源分散数据要求工具调用需同时对接企业内部ERP插件、行业公开数据API与第三方采购数据接口，需配置多节点并行调用。季节性的生产周期特征要求工具支持按养殖批次、季度周期筛选参数，避免拉取无关时段的数据。特定的字段单位与结构化分段格式要求工具调用时需预设字段映射规则，自动将原始数据的单位转换为财报统一格式，同时需校验字段合法性，防止传入错误的面积、重量参数。此外，月度高频更新的数据要求工具调用的触发频率适配业务节奏，避免过度调用或遗漏最新数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MCP_SERVICE_LOG_LEVEL` | `debug` | 水产养殖财报字段数量多且格式特殊，debug级日志可精准定位字段解析、参数传递的异常点 |
| `HTTP_TOOL_ALLOW_FILE_INPUT` | `enabled` | 水产养殖财报常附带塘口照片、水质检测报告等附件，需支持文件类型的入参传递 |
| `WORKFLOW_TRIGGER_INTERVAL` | `86400 秒` | 月度养殖生产数据每日更新，该配置可保证每日拉取最新的塘口生产数据用于财报汇总 |
| `TOOL_CALL_MAX_RETRIES` | `3 次` | 水产行业公开数据接口受网络波动影响概率较高，重试机制可降低调用失败率 |
| `SESSION_ID_PASS_THROUGH` | `enabled` | 多批次养殖数据的会话上下文需要保留，避免重复调用工具时丢失历史参数配置 |
| `RAG_RECALL_CHUNK_SIZE` | `1000–1200 字符` | 水产养殖财报的单条养殖记录长度较长，该配置可适配分段存储的文档长度，避免内容截断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用MCP服务后返回字段为空，状态码为200。原因：未配置水产养殖财报的专属字段映射，工具返回的原始数据字段名与工作流预设的`养殖面积`、`出栏量`等字段不匹配，导致解析失败。
- 现象：HTTP工具调用报错`413 Request Entity Too Large`。原因：未开启`HTTP_TOOL_ALLOW_FILE_INPUT`配置，或上传的水产养殖检测报告文件大小超过`UPLOAD_FILE_MAX_SIZE`的默认限制。
- 现象：工作流运行时无法关联历史会话的养殖数据，LLM返回结果未包含上下文信息。原因：未启用`SESSION_ID_PASS_THROUGH`配置，未在工作流中传递会话标识到LLM工具节点，导致上下文丢失。

## 怎么确认配好了
- 进入FastGPT工作流的调试面板，触发一次MCP工具调用，查看`MCP_SERVICE_LOG_LEVEL`配置生成的详细日志，确认包含水产养殖财报的原始字段解析过程。
- 在HTTP工具节点上传一份水产养殖相关的检测报告PDF文件，确认上传成功且工具返回处理后的文本内容，无格式错误。
- 启动工作流测试，查看LLM工具节点的输入参数，确认会话ID已被正确传递到上下文参数中。
- 调整`RAG_RECALL_CHUNK_SIZE`配置，测试召回的文档片段长度是否符合预设区间，确认无截断或超出长度的情况。
