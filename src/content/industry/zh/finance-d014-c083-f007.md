# 水务财报分析的工作流编排

## 这个品类的数据长什么样
水务行业财报数据主要来自上市公司公开年报、地方公用事业监管平台披露的运营月报及年度行业统计公报。数据更新节奏为月度运营数据每月更新，季度、年度财报按监管要求定期披露。文档结构包含标准化财务报表模块，以及专属运营数据模块，字段涵盖供水总量、售水量、管网漏损率、污水处理量等，单位分别为万立方米、万立方米、百分比、万立方米，另有管网总长度、服务人口等关联字段，文件格式多为PDF或结构化Excel表格。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据来源要求工作流支持多入口接入，需配置对应数据源的授权与同步规则。不同更新节奏的数据集，需拆分设置定时触发任务的周期，区分月度运营数据同步、季度财报解析、年度财报归档等流程。混合的财务与运营字段结构，要求工作流配置字段映射与校验步骤，避免跨模块数据混淆。兼容PDF与结构化Excel的文件格式，需预设两种文档的解析插件调用逻辑。水务运营数据与财务数据的强关联属性，要求工作流嵌入逻辑校验节点，验证数据合理性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 水务财报PDF或结构化Excel文件通常包含多页附表，解析耗时较长，600秒可覆盖多数场景 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 年度水务财报整合了全年运营月报与财务报表，单文件体积通常较大 |
| `recall_top_k` | `前 8–12 条` | 水务财报字段多且运营与财务数据关联紧密，需召回足够上下文支撑精准分析 |
| `workflow_trigger_cron` | `0 0 2 1 * *`（月度）、`0 0 2 1 */3 *`（季度） | 匹配水务行业月度运营数据、季度财报的更新节奏 |
| `field_mapping_rule` | 按财务/运营模块分类映射 | 区分财报中混合的财务报表字段与专属运营数据字段，避免数据混淆 |
| `validate_logic_enable` | `开启` | 水务运营数据与财务数据存在强关联逻辑，需校验数据合理性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中知识库召回测试正常，但最终AI生成结果未引用召回内容。原因：未在工作流的LLM节点中绑定召回后的上下文变量，导致对话环节未加载知识库数据。
- 现象：工作流触发后出现`413 Request Entity Too Large`报错。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，超过平台默认限制。
- 现象：解析后的水务财报字段出现错位，部分运营数据未被正确提取。原因：未配置`field_mapping_rule`，未区分财报中混合的财务与运营字段，导致映射逻辑混乱。

## 怎么确认配好了
- 上传单份年度水务财报文件，验证文件上传与解析流程是否正常，确认解析耗时未超过`PARSE_FILE_TIMEOUT_SECONDS`配置值。
- 触发手动运行的工作流，查看最终生成结果是否包含知识库召回的水务运营与财务数据，确认上下文变量已正确绑定至LLM节点。
- 核对定时触发任务的`workflow_trigger_cron`表达式，确认其匹配水务月度、季度数据的更新节奏，验证任务是否按计划执行。
- 导入包含逻辑矛盾的测试数据，查看工作流是否触发校验提示，确认逻辑校验开关已生效。
