# 汽车服务财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
这个品类的数据主要来自两类渠道：一类是汽车服务企业公开披露的定期财报，包括季度运营报告与年度审计报告；另一类是门店POS系统、供应链管理系统导出的结构化运营数据。数据更新节奏分为三层：企业定期财报每季度、年度固定更新，门店运营数据每日同步，行业公开数据每月更新。结构化文档的字段包含维修服务营收、配件销售数量、救援服务人次、单店运营成本等，单位分别为人民币元、件、人次、人民币元。非结构化文档包含财报附注、服务台账PDF，单份文档长度从数百字到数万字不等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多来源数据的接入要求接口兼容多种认证与数据格式，比如基础令牌认证、XML与JSON格式适配，以对接POS系统、供应链管理系统及公开财报接口。每日更新的门店运营数据需要配置固定间隔的定时拉取任务，避免数据同步延迟或重复拉取。结构化字段的异构性要求接口支持自定义字段映射规则，将不同门店的非标数据统一为标准分析格式。长文档的解析需求需要调整接口超时阈值，避免因单份财报PDF体积过大导致请求中断。财报的固定披露周期要求接口同时支持按需触发的批量拉取，以匹配季度、年度的财报更新节奏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份汽车服务财报PDF可能长达数万字，需要足够的解析时间完成文本提取与结构化 |
| `SYNC_TASK_INTERVAL` | `1440 分钟` | 门店运营数据每日更新一次，匹配日常运营数据的同步节奏 |
| `FIELD_MAPPING_RULES` | 按维修、配件、救援服务分类映射 | 汽车服务财报的核心分析维度围绕三类服务展开，需统一异构字段的标准格式 |
| `API_AUTH_TYPE` | `令牌认证` | 多数外部POS、供应链系统采用令牌鉴权策略，保障数据接入的安全性 |
| `BATCH_PULL_MAX_SIZE` | `1000 条` | 单次拉取过多门店运营数据会导致接口响应超时，该取值平衡了同步效率与稳定性 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 单份年度审计报告的PDF文件体积可能达到数百兆，需适配大文件上传需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用`getPluginGroups`接口返回500状态码，提示未配置商业版链接。原因是开源版本默认启用商业版接口校验逻辑，未对开源部署场景进行适配。
- 部分地域调用财报分析API返回连接超时或403错误。原因是外部系统的网络策略限制了特定地域的出站请求，未配置代理服务器或跨域访问白名单。
- 调用财报生成接口仅返回完整结果，未实现流式输出。原因是未将接口的`stream`参数设置为`true`，或未开启流式响应的配置开关。

## 怎么确认配好了
- 发起单次门店运营数据拉取请求，核对返回字段是否与预设的映射规则匹配。
- 上传单份年度财报PDF，确认解析任务未因超时中断，且返回的文本内容完整。
- 调用批量数据拉取接口，确认返回的数据总量符合配置的上限要求。
- 开启流式响应配置后，调用财报生成接口，检查响应是否以分段形式逐步返回。
