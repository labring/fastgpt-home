# 汽车服务财报分析的工作流编排

## 这个品类的数据长什么样
汽车服务行业的财报数据主要来自两类渠道：企业自主披露的年度、半年度及季度财务报告，以及汽车后市场监管机构发布的行业运营统计报表。数据更新节奏固定，季度财报每季度末后30日内披露，月度运营数据每月5日前更新。文档结构包含合并资产负债表、利润表、现金流量表，以及细分的门店运营字段，如当期维保营收、零部件采购总额、单店日均进厂台次，对应单位分别为人民币元、人民币元、台次。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的口径差异要求工作流配置字段映射节点，将企业财报的「当期总营收」与行业报表的「全业态营收」对齐统一。固定的更新节奏要求定时触发节点设置匹配披露窗口的定时任务，避免无效触发。细分运营字段较多，需拆分数据加载节点分批拉取单店营收、进厂台次等字段，防止节点超时。需配置数据校验节点，过滤披露不全的财报数据，避免后续生成环节出错。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `定时触发表达式` | `0 0 0 28 1,4,7,10 ? *` | 匹配汽车服务企业季度财报的披露时间窗口 |
| `文本分块长度` | `1800–2200 字符` | 适配财报文档较长的特性，避免拆分后丢失关联的财务数据字段 |
| `数据加载并发数` | `2 个/批次` | 避免同时拉取过多门店数据导致接口限流 |
| `字段映射匹配规则` | `精确匹配字段中文名` | 对齐多源数据的命名差异，确保数据整合准确 |
| `节点执行超时时间` | `720 秒` | 覆盖多批次数据加载与多节点编排的总耗时需求 |
| `嵌套工作流调用开关` | `开启` | 拆分财报解析与报告生成的子流程，简化主流程维护 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：文本提取节点返回空内容或报错「字段未匹配」。原因：未针对汽车服务特有的维保营收、进厂台次等细分字段配置自定义提取规则，默认规则无法识别非通用财务字段。
- 现象：嵌套工作流调用后，子工作流的「用户选择」节点执行后无后续节点响应。原因：未在主工作流中为嵌套节点配置等待子流程完成的回调设置，导致主流程提前终止。
- 现象：数据库查询节点返回结果条数异常。原因：未设置合理的分页参数，导致单次拉取的数据量超出接口限制。

## 怎么确认配好了
- 触发一次测试工作流，查看定时触发节点的执行日志，确认触发时间匹配预设的财报披露窗口。
- 导入一份真实的汽车服务企业财报样本，查看文本分块节点的输出内容，确认分块未截断核心财务字段。
- 配置嵌套工作流调用测试，触发子流程并查看回调日志，确认子流程的「用户选择」节点执行后，主流程能接收回调并继续执行后续节点。
- 运行数据库查询节点，查看返回的字段列表，确认与预设的汽车服务财报字段匹配。
