# 油服工程财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
油服工程企业财报数据主要来自境内外证券交易所公开披露的年报、季报及临时公告，同时部分企业会通过官方渠道发布月度运营简报。数据更新节奏遵循监管要求，年度财报于次年4个月内发布，季度财报于季度结束后1个月内发布，临时公告随业务节点实时更新。单份财报文档长度跨度大，短则数千字的运营简报，长则数万字的年度审计报告。核心字段包含钻井服务营收、完井工程成本、油气服务产量、设备作业时长，单位分别为人民币元、元/作业单位、立方米/桶、小时。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
油服工程财报的多长度文档、分批次更新节奏及行业特定字段，会对HTTP接口与外部系统带来多项约束。大跨度的文档长度要求接口支持分段拉取或大文件流式传输，避免单次请求超时。定期财报与临时公告的混合更新模式，需要接口同时支持定时批量拉取与事件触发的实时推送。行业特有的非通用字段，要求接口开放自定义字段映射配置，避免硬编码字段规则。同时跨交易所的披露格式差异，要求接口适配多种结构化数据解析模板。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 油服工程单份年度财报可达数万字，600秒可覆盖全量文档的解析流程 |
| `rag_chunk_size` | `800–1200 字符` | 财报包含钻井、油气开发等专业术语与长句，该区间可保留语义完整性 |
| `api_request_timeout` | `300 秒` | 外部系统批量拉取财报数据时存在延迟风险，该时长可适配多数批量请求场景 |
| `custom_field_mapping` | 按油服工程财报模板配置 | 行业存在非通用字段，需匹配钻井营收、作业时长等特有字段的映射规则 |
| `webhook_trigger_mode` | 定时拉取+事件订阅双模式 | 兼顾定期披露的季报年报与实时发布的临时公告的更新需求 |
| `max_upload_file_size` | `1000 MB` | 覆盖体积较大的年度审计报告文档，避免上传截断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用财报解析接口返回`504 Gateway Timeout`状态码。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`配置，默认超时时长不足以解析长文档。
- 通过外部系统拉取的财报数据字段为空。原因是未配置`custom_field_mapping`，硬编码字段规则无法匹配油服工程特有字段。
- 调用对话接口时无法按知识库标签筛选油服财报数据。原因是未在`chat/completions`接口中传入正确的`collection_tags`参数，或未提前为油服财报集合配置对应标签。

## 怎么确认配好了
- 上传一份油服工程年度财报文档，检查解析后的分段结果是否保留专业术语完整性，调整`rag_chunk_size`至符合业务需求的区间。
- 发起批量拉取财报的API请求，验证请求时长未超过配置的`api_request_timeout`，确认超时配置适配业务场景。
- 调用`chat/completions`接口，传入预设的油服财报标签参数，检查返回结果仅包含对应标签的知识库内容。
- 配置Webhook触发规则，提交临时公告的模拟触发事件，验证接口是否能实时接收并解析数据。
