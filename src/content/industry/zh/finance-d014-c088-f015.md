# 油服工程财报分析的部署与升级

## 这个品类的数据长什么样
油服工程企业的财报数据主要来自公开交易所披露的定期报告、临时公告及行业协会公开数据。更新节奏为季度报告每季度末后1-2个月发布，年度报告于次年4月底前完成披露。文档结构包含板块化营收拆分、作业量统计、成本构成、在手订单及资本开支等模块，核心字段包括钻井服务营收、完井作业米数、设备日均运行时长等，单位涵盖万元、米、小时。

## 这些特征在「部署与升级」这一环带来什么约束
油服工程财报的固定季度更新与临时公告发布节奏，要求部署时配置定时同步任务的超时阈值，避免拉取未完成披露的报告。板块化的文档结构要求调整文档分段参数，避免跨钻井、测井等业务板块的内容被截断，同时需预设适配油服特有的作业量、设备运行类字段的抽取规则。单份财报文件篇幅较长的特点，要求提升上传文件最大尺寸限制与解析超时时间。临时公告的非定期上传需求，需要调整批量解析的并发配置，避免大量文件同时上传导致服务响应延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 油服工程年度财报篇幅较长，部分文件可达数百页，需适配大尺寸文件上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1200 秒` | 长文档解析需足够时间完成内容拆分与字段抽取，避免中途超时中断 |
| `CHUNK_SIZE` | `1500–2000 字符` | 避免跨业务板块的财报内容被截断，保障钻井、测井等板块信息的完整性 |
| `RECALL_COUNT` | `前 8 条` | 油服财报字段细分较多，需召回足够数量的相关片段用于准确抽取营收、作业量等核心数据 |
| `SIMILARITY_THRESHOLD` | `0.72–0.78` | 过滤低匹配度的非财报内容，聚焦油服特有的作业量、设备运行类字段 |
| `CHAT_API_KEY` | `与局域网模型部署地址匹配的密钥字符串` | 适配本地或局域网部署的大模型调用需求，避免跨域访问限制 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：部署时出现`ImagePullBackOff`错误，镜像拉取超时或失败。原因：未配置国内镜像加速地址，油服工程相关的自定义数据集镜像体积较大，拉取耗时超出默认超时限制。
- 现象：启动服务后MongoDB连接报错`Connection refused`。原因：未提前启动MongoDB实例，或配置的`MONGO_URI`参数包含错误的端口号或访问凭证。
- 现象：上传财报后解析结果缺失作业量字段。原因：未调整`SIMILARITY_THRESHOLD`参数，导致低匹配度的非财报内容干扰字段抽取，或`CHUNK_SIZE`设置过小截断了包含作业量的段落。

## 怎么确认配好了
- 上传一份测试用的油服财报文件，检查上传进度条完成且无解析失败提示，核对`UPLOAD_FILE_MAX_SIZE`参数是否适配文件尺寸。
- 运行定时同步任务，查看任务日志中无超时或拉取失败记录，确认`SYNC_TASK_CRON`表达式符合披露节奏。
- 发起财报分析对话，检查返回结果中包含钻井服务营收、完井作业米数等油服特有的字段，确认`CHUNK_SIZE`与`RECALL_COUNT`参数适配内容抽取需求。
- 查看服务监控面板，确认解析并发数未超出配置阈值，无服务卡顿或报错日志。
