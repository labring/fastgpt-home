# 油气开采财报分析的工作流编排

## 这个品类的数据长什么样
油气开采行业的财报数据主要来自境内外证券交易所披露的定期报告、临时公告，以及公司投资者关系板块公开的年报、季报文档。更新节奏遵循证券监管要求，年度报告需在会计年度结束后4个月内披露，季度报告需在季度结束后1个月内披露，临时公告如储量变动、钻井进度公告则随事件触发发布。文档多为多页PDF格式，单份年度报告常包含储量台账、单井产量明细、勘探开发成本、油气销售营收拆分等专业章节，字段包含油气储量（单位为桶或立方米）、日产量（单位为桶/日或立方米/日）、单位开采成本（单位为美元/桶或人民币/吨）、钻井深度（单位为米或英尺）等，不同披露主体的单位格式可能存在差异。

## 这些特征在「工作流编排」这一环带来什么约束
油气开采财报的专业属性与数据特征，对工作流编排提出多维度约束。长文档与密集的专业术语要求拆分参数需适配专业内容完整性，避免拆分后术语断裂影响提取精度。多数据源的接入需求，要求工作流支持交易所PDF、第三方行业数据接口、公司内部报表等多种来源的整合处理。批量处理多份财报的场景，如季度对比、子公司财报汇总，需要配置循环节点实现逐一处理。专业字段的单位不统一，需要在工作流中加入标准化处理环节，统一数据口径。临时公告的非固定更新节奏，要求工作流支持定时或事件触发的执行模式，适配突发的披露需求。此外，跨节点传递专业字段值的需求，需要明确全局变量的绑定规则，确保数据在工作流各环节可被正确调用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 油气开采财报单份PDF常超300页，默认300秒的超时时间无法覆盖长文档解析耗时，延长后可避免解析中断 |
| `workflow_loop_max_times` | 10–20 次 | 常规财报分析需处理4个季度报告、2–3份行业参考文档，设置10–20次可覆盖多数分析场景，避免循环溢出 |
| `global_variable_init_value` | 按财报字段映射配置 | 油气财报包含储量、产量、成本等专属字段，需提前将外部传入的query参数或API返回字段绑定为全局变量，实现跨节点数据传递 |
| `http_request_timeout` | 600–900 秒 | 第三方油气行业数据接口返回的勘探、钻井数据量较大，延长超时时间可避免数据拉取中断 |
| `document_chunk_size` | 1500–2000 字符 | 长文档拆分需保留专业术语的上下文完整性，避免拆分后术语断裂导致提取精度下降 |
| `rag_recall_top_k` | 8–12 条 | 油气财报专业术语密度高，召回更多相关片段可确保分析所需的信息覆盖全面 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：循环节点内嵌套的http请求未按预期执行，循环次数超出预设范围或请求未触发。原因：未设置`workflow_loop_max_times`的合理上限，或未正确绑定循环变量的数据源，导致循环无法按预期终止或执行。
- 现象：工作流后续节点无法读取query参数或API返回的字段值，全局变量显示为空。原因：未在全局变量初始化节点中绑定对应参数的映射关系，未将外部传入的变量正确赋值到全局变量池。
- 现象：工作流执行时频繁出现超时报错，日志显示`PARSE_FAILED_TIMEOUT`或`408 Request Timeout`。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，沿用默认300秒的配置，无法适配长财报的解析耗时。

## 怎么确认配好了
- 上传一份单季度油气开采财报PDF，查看解析节点的执行日志，确认解析耗时未超过配置的`PARSE_FILE_TIMEOUT_SECONDS`值。
- 上传多份不同季度的财报文档，触发循环节点，查看每个循环分支的执行结果，确认每份文档都被逐一处理并生成对应分析内容。
- 在全局变量初始化节点中传入测试用的油气财报字段值，触发工作流后查看后续节点是否能正确读取并使用该变量。
- 配置http请求节点并设置`http_request_timeout`参数，触发请求后查看返回结果是否完整，无超时中断或数据缺失。
