# 油气开采财报分析的部署与升级

## 这个品类的数据长什么样
油气开采领域的财报数据主要来源于企业公开定期报告、行业协会发布的生产运营台账。数据更新节奏分为三类：年度完整财报每12个月更新一次，季度运营数据每3个月更新一次，月度生产监测数据每月更新。文档结构包含管理层讨论与分析、运营数据附表、财务报表附注三部分，其中运营附表包含探明储量、单井日产油量、钻井成本等专业字段，单位分别为百万桶油当量、桶/天、美元/英尺，部分文档还会附带区块勘探的专项评估报告。

## 这些特征在「部署与升级」这一环带来什么约束
多频率的数据源要求部署阶段配置多套定时同步任务，避免不同数据源的同步周期冲突导致数据重复或遗漏。专业字段与特有单位需要配置自定义解析规则，通用解析模型无法准确识别油气行业专属术语，可能导致字段映射错误。长文档与多附件的特性会增加解析与上传的负载，需要调整超时时间与文件大小限制。升级阶段需保留自定义的字段映射与同步配置，否则历史导入的油气财报数据会出现解析失效的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `SYNC_CRON_EXPR` | `0 0 2 * * *` 和 `0 0 1 */3 * *` | 匹配月度生产数据的每日2点同步，季度财报的每季度首月1日同步，贴合油气数据的更新节奏 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 油气财报包含大量专业表格与长文本附件，需要更长的解析超时时间保障完整解析 |
| `VECTOR_CHUNK_SIZE` | `800–1200 字符` | 油气财报的运营数据字段密集，分块长度适配专业术语的上下文关联需求，避免破坏字段逻辑 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 年度财报附带的储量评估报告等附件体积较大，支持更大文件上传避免上传失败 |
| `CUSTOM_FIELD_MAPPING` | 按“探明储量”“单井日产”映射至预设油气行业字段 | 匹配油气财报的专业字段命名规则，避免通用解析模型的字段识别偏差 |
| `RECALL_TOP_K` | `前 8 条` | 油气数据的专业术语占比高，需要足够的召回条数覆盖相关业务上下文 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：跨版本升级后历史导入的油气财报解析失败。原因：未保留旧版`CUSTOM_FIELD_MAPPING`配置，新版解析规则对油气专业字段的匹配逻辑发生变更。
- 现象：服务启动后MongoDB连接报错，错误码`ECONNREFUSED`。原因：使用了MongoDB7版本，当前FastGPT版本未兼容该版本的连接协议，建议使用MongoDB6版本。
- 现象：第三方API配置未生效，返回`401 Unauthorized`。原因：未正确填写`THIRD_PARTY_API_CONFIG`中的接口地址与密钥，或移动第三方服务部署位置后未同步更新配置。

## 怎么确认配好了
- 手动触发一次数据同步任务，核对同步后的数据集条数与数据源的最新更新条目数一致。
- 上传单份测试用油气财报文档，检查解析结果中是否包含预设的专业业务字段。
- 查看服务日志中的MongoDB连接日志，确认使用的数据库版本符合兼容要求。
- 调用测试接口调用第三方视频模型，检查接口返回的状态码与预期一致。
