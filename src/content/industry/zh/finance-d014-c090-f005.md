# 涂料油墨财报分析的多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据主要来自境内外上市主体的定期披露公告、行业协会公开的产业运行简报。更新节奏为年度报告于次年4月30日前公开，中期报告于8月31日前公开，季度报告于对应季度结束后1个月内公开。文档以PDF格式为主，部分附带结构化附注文档，包含核心经营数据、产品分类营收、原材料采购成本、研发投入金额、现金流与负债明细等模块，字段包含产品销量（单位：吨）、营收金额（单位：万元/亿元）、单位生产成本（单位：元/千克）、采购单价（单位：元/吨）等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
不同上市主体的披露口径存在差异，部分企业未单独拆分涂料与油墨业务的营收数据，多轮对话需先引导用户明确目标企业及披露口径，避免数据混淆。财报更新周期固定且跨度较长，多轮对话需支持用户切换分析不同报告期的内容，需保留历史对话中的报告期上下文。财报文档包含多模块细分数据，多轮对话需支持逐步拆解需求，例如先确认分析营收构成再深入追问原材料成本变动。字段单位存在跨企业差异，提示词需加入单位校准规则，自动统一对话中的数据单位，避免计算或对比错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxHistory` | `前6条聊天记录` | 涂料油墨财报的多轮对话通常需要保留报告期、企业口径、核心数据三个核心上下文，6条记录可覆盖完整对话逻辑且不占用过多token。 |
| `similarityThreshold` | `0.75–0.85` | 财报数据的结构化程度较高，该阈值可过滤低相关的文档片段，仅召回匹配财报核心模块的内容。 |
| `recallTopK` | `前3条召回结果` | 涂料油墨财报的细分模块较少，过多召回会导致上下文冗余，3条可覆盖营收、成本、研发三个核心分析维度。 |
| `systemPrompt` | 按涂料油墨行业财报披露口径校准数据单位，先明确目标企业与报告期再展开分析 | 需统一跨企业的披露差异，避免对话偏离用户需求。 |
| `segmentMaxLen` | `1000–1200 字符` | 财报附注中的细分数据段落较长，该分段长度可保留完整的产品营收或成本明细，避免拆分后丢失上下文。 |
| `maxContext` | `8000  token` | 多轮对话需保留历史上下文与召回的财报片段，8000 token可覆盖完整的分析逻辑且适配主流大模型的窗口限制。 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中接入`文本内容提取`插件并配置`聊天记录：6条`后，无法实现多轮对话。原因：工作流节点未绑定全局对话上下文存储，仅在插件内部缓存单轮数据，无法跨节点传递历史对话信息。
- 现象：调用接口获取多轮对话结果时返回`400 Bad Request`。原因：未在请求体中正确携带`history`字段，或字段格式不符合大模型要求的数组结构。
- 现象：多轮对话中出现单位不一致的对比结果，例如将万元与亿元的数据直接相加。原因：提示词未加入涂料油墨财报的单位校准规则，未统一不同企业披露的金额单位。

## 怎么确认配好了
- 发起包含企业名称、报告期的首轮提问，核对系统是否自动提示确认披露口径，确认上下文是否保留首轮信息。
- 发起跨轮次的追问，例如先问营收构成再问原材料成本，核对系统是否能关联前一轮的企业与报告期信息。
- 测试不同单位的财报片段召回，核对系统是否自动统一数据单位后再输出结果。
- 调用接口传入历史对话数组，核对返回结果是否基于完整上下文生成。
