# 消费建材财报分析的工作流编排

## 这个品类的数据长什么样
消费建材财报数据主要来自上海证券交易所、深圳证券交易所的官方披露平台，以及上市公司官方公告。披露节奏为季度报告每季度结束后1个月内公开，年度报告于每年4月底前完成披露。单份财报文档包含经营情况讨论与分析、主要经营数据、合并财务报表等部分，核心字段涵盖营业收入、营业成本、归属于上市公司股东的净利润、经营活动现金流量净额等，单位统一为人民币元，部分文档包含细分产品品类的经营数据模块。

## 这些特征在「工作流编排」这一环带来什么约束
消费建材财报的多源分散来源要求工作流配置多节点对接不同披露渠道，避免单源拉取的局限性；集中的披露窗口期要求工作流设置精准的定时触发逻辑，避免非窗口期空耗资源；文档包含细分品类的独立数据模块，要求解析节点适配结构化段落拆分，避免拆分后丢失品类关联信息；不同上市公司的财报字段命名存在差异，要求配置标准化映射节点统一字段格式；单份文档篇幅较长，要求节点设置足够的超时与上下文参数，避免解析中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 消费建材财报单份文档包含多页财务表格与长文本，常规解析时长较长，600秒可覆盖完整解析流程 |
| `maxContext` | `8000–12000 字符` | 财报核心段落包含细分品类经营数据，适配长上下文的模型调用可保留完整业务逻辑 |
| `PARSE_CHUNK_SIZE` | `1000–1500 字符` | 消费建材财报的细分品类营收段落集中，该分段长度可保留单品类经营数据的完整性 |
| `workflow_trigger_cron` | `0 0 2 * * *` | 财报披露窗口期集中在每月初至中旬，每日凌晨2点触发可在披露后第一时间拉取数据 |
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | 单份年度消费建材财报PDF文件通常不超过该大小，避免节点因文件超限报错 |
| `retry_count` | `3 次` | 披露平台接口在窗口期可能出现临时波动，多次重试可提升数据拉取成功率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 大模型节点返回500 Gateway forwarding error because service is disconnected，原因是未配置适配消费建材财报的解析超时参数，或超时设置短于实际解析时长，导致节点服务断开。
- 批量运行财报分析节点时仅单节点执行，未触发并发执行，原因是未开启工作流的批量并发开关，或并发线程数设置未适配多份财报的并行处理需求。
- 工作流运行日志显示offset 17相关语法错误，或文件上传节点提示网络错误，原因是未设置适配消费建材财报的分段解析参数，导致长文档解析时出现字符偏移异常，或上传文件大小超过节点限制引发报错。

## 怎么确认配好了
- 手动导入一份本地消费建材财报PDF，检查解析后的文本是否完整保留细分品类的经营数据，确认分段与解析参数适配文档结构。
- 配置测试定时触发任务，在非披露窗口期运行工作流，检查节点是否按设定时间启动，确认定时触发参数生效。
- 同时导入多份消费建材财报运行批量任务，检查是否同时启动多个节点执行，确认并发配置正确。
- 查看大模型节点的运行日志，确认无500错误或字符偏移相关报错，确认超时与解析参数匹配文档长度。
