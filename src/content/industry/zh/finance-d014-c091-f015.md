# 消费建材财报分析的部署与升级

## 这个品类的数据长什么样
消费建材财报数据主要来自上市主体公开披露的定期报告、交易所官方公告及行业协会月度运营监测数据。更新节奏以季度报告为核心频次，年度报告为完整周期复盘。单份文档结构包含合并财务报表、主营业务拆解、渠道运营数据三个核心模块，字段涵盖营收、归母净利润、单平米造价、区域铺货占比等，单位多为万元、平方米、百分比，部分细分品类如瓷砖、涂料会附带产品均价波动数据。

## 这些特征在「部署与升级」这一环带来什么约束
消费建材财报的多源分散特性，要求部署阶段需配置多数据源同步适配器，适配公告、协会数据的格式差异。季度/年度的固定更新节奏，使得升级环节需预留增量索引调度的配置位，避免全量重索引占用算力。长文本与结构化表格混合的文档结构，要求升级后需重新校准文本分段与表格解析的阈值。专属字段与单位的存在，需在部署时配置字段映射规则，确保检索时的单位统一匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1000–1500 秒` | 单份消费建材财报文档长度可达数万字符，需适配长文本解析的超时需求 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 单份年度财报包含多页附表与附件，需支持大文件上传 |
| `RERANKER_TOP_N` | `前 3–5 条` | 消费建材财报字段密集，需限制重排结果数量以避免上下文溢出 |
| `VECTOR_SIMILARITY_THRESHOLD` | `0.72–0.85` | 财报专属字段的语义相似度需匹配细分领域的检索精度，避免无关结果混入 |
| `INCREMENTAL_SYNC_INTERVAL` | `每 7 天` | 季度财报的更新周期为3个月，增量同步适配月度/季度的更新节奏 |
| `CHUNK_MAX_LENGTH` | `800–1200 字符` | 消费建材财报包含结构化表格与长段分析，分段长度需覆盖表格行与完整分析段落 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：部署TEI部署的bge-reranker后，检索结果重排标记为false，无重排结果返回。原因：未在FastGPT的`RERANKER_MODEL_PATH`配置项中填写正确的模型部署地址，导致模型调用链路断裂。
- 现象：从v4.9.13升级到v4.10.1后，原有知识库内容未在界面显示，检索无匹配结果。原因：升级过程中未执行数据库迁移脚本，原有向量索引与新系统的元数据结构不兼容。
- 现象：更新版本后原有索引无法支持向量检索，搜索返回空结果。原因：升级后向量数据库的连接配置发生变更，未同步更新FastGPT的`VECTOR_DB_CONN_STR`参数。

## 怎么确认配好了
- 上传一份单份消费建材财报文档，检查解析后文本分段是否覆盖完整表格与分析段落，核对`PARSE_FILE_TIMEOUT_SECONDS`的配置是否匹配解析耗时。
- 发起针对财报专属字段的检索，检查重排结果是否返回标记为`is_relevant`的条目，确认`RERANKER_TOP_N`与`VECTOR_SIMILARITY_THRESHOLD`的配置符合当前检索需求。
- 触发增量同步任务，检查新上传的财报数据是否在预设周期内完成索引，核对`INCREMENTAL_SYNC_INTERVAL`的配置是否与更新节奏匹配。
- 执行数据库迁移脚本后重启服务，检查原有知识库的元数据是否在界面正常加载，确认升级后的配置与旧版本索引兼容。
