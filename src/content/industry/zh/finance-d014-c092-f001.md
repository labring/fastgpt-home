# 消费电子财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
消费电子行业的财报数据主要来自上市公司公开披露的定期报告、交易所官方披露平台。更新节奏以季度报告每3个月更新一次、年度报告每年更新一次为主，临时公告如供应链变动、新品发布信息随事件触发更新。文档结构包含核心财务指标、分品类营收明细、研发投入、供应链占比、单季度出货量等内容，字段涵盖金额类、出货量类等类别，金额类字段多以人民币或美元为单位，出货量字段以万台为单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
消费电子财报的多品类明细、金额与出货量双单位并存的特征，要求HTTP接口支持按品类筛选的参数配置，同时外部系统需统一映射两类字段的单位规则。定期报告与临时公告的双更新节奏，需要接口同时支持定时拉取与事件回调两种调用模式，适配不同的数据更新场景。财报包含图文混排的多模态内容，要求接口支持多模态文件解析，同时需限制单文件与多模态子文件的大小，避免解析超时或失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `800–1200 MB` | 消费电子财报包含多品类明细与图文内容，单文件通常不超过1200MB |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600–900 秒` | 财报解析需处理多维度财务字段与图表，耗时高于通用文档 |
| `API_SESSION_PERSIST` | `开启` | 消费电子财报分析需跨接口调用多期数据，保持会话一致性 |
| `MULTIMODAL_FILE_MAX_SIZE` | `500–800 MB` | 财报内的多模态图表文件通常体积较小，避免解析超时 |
| `MONGO_CHANGE_STREAM_RECONNECT` | `开启，重连间隔30秒` | 对接MongoDB副本集时，主节点漂移可能导致断连，需自动重连 |
| `REQUEST_FILTER_FIELDS` | `按财报披露的核心字段配置` | 消费电子财报字段维度多，仅需筛选目标分析字段减少请求负载 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用`apiCollection`接口时返回`Invalid URL, code: 500`。原因：消费电子财报的数据源URL包含动态披露路径，未正确配置路径参数导致URL无效。
- 解析财报时返回`InternalError.Algo.InvalidParameter: Multimodal file size is`报错。原因：未限制多模态文件上传大小，或上传的财报内图表文件超出预设阈值。
- 配置API会话后，每次调用仍处于独立会话。原因：未开启`API_SESSION_PERSIST`配置，导致会话未持久化。

## 怎么确认配好了
- 上传一份消费电子上市公司的财报文件，核对解析结果包含预设的目标字段，字段单位与财报披露一致。
- 调用`apiCollection`接口传入配置的数据源地址，检查接口返回正常无URL相关报错。
- 启用会话持久化配置后，连续发起两次关联分析请求，检查两次请求共享同一会话上下文。
- 断开MongoDB连接后，检查系统是否自动触发重连并恢复数据同步。
