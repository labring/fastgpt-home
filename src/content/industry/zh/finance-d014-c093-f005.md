# 游戏财报分析的多轮对话与提示词

## 这个品类的数据长什么样
游戏财报的数据来源主要为上市游戏企业的定期公开财报、行业公开监测报告及厂商官方专项公告。更新节奏遵循固定披露周期，季度财报于季后45天内发布，年度财报于次年3个月内完成披露。文档结构通常包含合并财务报表、运营专项章节，字段涵盖月活跃用户数（MAU）、平均每用户月收入（ARPU）、游戏流水、研发投入、分成比例等，单位多为人民币元、万元、百万级用户数，部分字段需结合业务口径明确统计范围。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
游戏财报的数据来源包含公开财报与行业监测数据，多轮对话需支持跨数据源的可信度校验，避免混淆非官方数据。单份财报文档篇幅较长，核心运营章节易突破上下文窗口，需限制单轮调用的召回文本长度。行业专属术语如MAU、ARPU、分成比例无通用统一解释，提示词需提前明确字段定义与统计口径。固定的披露周期要求多轮对话支持按季度、年度筛选数据，需在提示词中嵌入时间范围校验逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 游戏财报单份文档分段后常为2000-5000 token，预留多轮对话上下文空间 |
| `recallTopK` | 前6–8条 | 财报数据字段多，需召回足够相关片段但避免冗余干扰 |
| `relevanceThreshold` | 0.75–0.85 | 过滤低相关的财报片段，避免混入非游戏业务的财务数据 |
| `fileParseChunkSize` | 1500–2000 字符 | 适配游戏财报长文本的分段，平衡上下文完整性与召回精度 |
| `apiTimeout` | 600 秒 | 财报文档解析与多轮召回需较长处理时间，避免超时中断 |
| `promptTemplate` | 固定包含「财报术语定义」「时间范围校验」字段 | 明确MAU、ARPU等术语的统计口径，约束多轮对话的参数合法性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用多模态接口上传财报截图时返回格式错误提示。原因是未遵循平台要求的图片格式与大小限制，仅支持PNG、JPG格式且单文件不超过10MB。
- 发起多轮财报分析对话后，界面持续显示检索状态无响应。原因是召回参数设置不合理，导致系统加载过多冗余的财报片段，延长处理耗时。
- 生成的财报分析结果未符合预设的结构化格式，出现字段缺失或类型错误。原因是未在提示词中明确指定结构化输出的约束规则，或未开启对应格式校验配置。

## 怎么确认配好了
- 上传一份游戏财报文档，查看解析后的分段内容，确认分段长度适配文档结构。
- 发起一轮包含多字段查询的对话，检查返回结果是否包含明确的术语定义说明，验证提示词模板的生效情况。
- 模拟多轮连续对话，查看上下文是否按规则截断，确认上下文窗口的配置合理。
- 调用接口发起多模态图片上传测试，确认返回结果正常，验证图片格式与大小的校验逻辑。
