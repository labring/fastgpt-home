# 炼化财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
炼化财报分析的数据来源为境内外证券交易所公开披露的上市公司定期报告、企业官方发布的年度/半年度经营财报文档。更新节奏遵循定期披露规则，季度财报每季度末后45天内更新，年度财报需在次年4个月内完成披露，临时经营数据公告按需发布。文档结构包含通用财务报表模块，以及炼化板块专项经营数据模块，包含当期原油加工量、成品油产出量、单位加工能耗等字段，其中原油加工量以吨为单位，营收以人民币元为单位，单位加工能耗以千克标准煤/吨原油为单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
炼化财报的多来源多格式特征，要求HTTP接口支持PDF、HTML等多种文档格式的解析适配，同时需兼容不同证券交易所披露文档的差异化排版。固定周期与临时触发的更新节奏，要求接口同时支持定时拉取与手动触发两种调用模式，适配定期财报与临时经营公告的获取需求。炼化板块存在专属经营数据字段，接口需提供自定义字段映射配置能力，将原始文档中的专项数据转换为标准化结构化字段。单份财报文档体积较大时，接口需配置合理的超时阈值与分片处理逻辑，避免单次请求超时中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 炼化财报文档通常包含大量专项经营数据，解析耗时较长，600秒可覆盖绝大多数文档的解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 单份年度炼化财报PDF文档体积可达数百MB，1000 MB可满足常规文档的上传需求 |
| `API_TRIGGER_MODE` | `定时拉取+手动触发` | 财报数据存在固定周期更新与临时经营公告两种场景，双模式可覆盖全量数据获取需求 |
| `CUSTOM_FIELD_MAPPING` | `开启` | 炼化财报包含专属经营数据字段，需自定义映射规则将原始文档中的专项字段转换为标准化输出 |
| `RETRY_MAX_TIMES` | `3 次` | 外部数据接口可能存在临时网络波动，3次重试可提升数据获取的成功率 |
| `EMBEDDING_INPUT_MAX_LENGTH` | `8192 字符` | 炼化财报的专项经营数据文本较长，需适配大模型嵌入接口的输入长度限制 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用多模态嵌入接口时返回格式为`{"error":{"code":"Invalid`的报错。原因：未针对炼化财报的长文本内容调整嵌入输入长度配置，输入文本超出模型支持的最大字符限制。
- 现象：通过HTTP接口上传财报文档后，知识库中未提取到炼化板块的专项经营数据。原因：未开启自定义字段映射配置，默认解析规则无法识别财报中的专属字段，导致数据丢失。
- 现象：定时拉取外部财报数据源时，连续多次请求失败。原因：未配置合理的重试次数，单次网络波动导致请求失败后未自动重试，引发数据获取中断。

## 怎么确认配好了
- 上传一份炼化财报文档，检查接口返回的解析结果中是否包含原油加工量、单位加工能耗等专属字段，确认自定义字段映射配置生效。
- 调用定时拉取接口，验证是否能按预设周期自动获取最新财报数据，确认触发模式配置正确。
- 模拟单次大体积文档上传，检查接口是否在预设超时时间内完成解析，确认超时配置合理。
- 调用嵌入接口处理炼化财报的长文本片段，检查是否返回正常的嵌入向量，确认输入长度配置适配模型要求。
