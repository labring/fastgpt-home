# 煤化工财报分析的引用来源与溯源

## 这个品类的数据长什么样
煤化工品类的财报数据主要来自境内外上市公司定期公告、行业协会月度监测数据及第三方行业研究报告。更新节奏以季度报告、年度报告为固定周期，临时公告如产能扩建、技术改造信息随事件实时发布。文档结构遵循上市公司披露规范，包含合并财务报表、主营业务拆解数据，专项字段包括煤制烯烃、煤制天然气产能，单位产品能耗、原材料采购成本，对应单位多为万吨/年、千克标准煤/吨产品、万元等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
煤化工财报数据源分散且格式差异明显，要求溯源环节需支持关联多来源的原始文件，避免单一数据源的信息偏差。固定周期的定期报告与实时临时公告并存，要求召回逻辑可配置时间范围，优先匹配最新披露的公告内容。专项业务字段与通用财务字段混杂，要求溯源时需保留原始文档的字段标注，避免跨字段的信息混淆。长文档结构带来的切片关联性需求，要求溯源链接可定位到原始文档的具体段落，不定位到整页，以提升信息准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前6-8条` | 煤化工财报专项字段多，过多召回会引入无关信息，过少则无法覆盖核心业务数据 |
| `相似度阈值` | `0.75-0.85` | 煤化工财报术语专业性强，过低阈值会引入不相关的行业泛数据，过高则可能遗漏精准的专项字段内容 |
| `分段长度` | `800-1200字符` | 财报包含长段落的财务明细与业务说明，该长度可保留字段关联性，避免拆分破坏业务逻辑 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 单份煤化工年报文件体积较大，解析耗时较长，需预留足够时间完成切片与索引 |
| `引用片段保留原格式` | `开启` | 煤化工财报包含标准化的财务表格与单位标注，保留原格式可确保溯源时的信息可读性 |
| `重排返回条数` | `前3-4条` | 核心财报数据集中在少量核心公告中，重排后可优先展示最相关的溯源内容 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用知识库问答API时，返回结果中`reference`字段为空，未包含引用文献细节。原因：未开启知识库的返回引用信息开关，或API调用时未携带`with_reference`参数。
- 现象：终端回复中未展示引用片段的原文件预览链接。原因：未配置知识库的切片原文件关联功能，或未在工作流中添加获取原文件详情节点，无法关联切片与原始文档。
- 现象：引用环节抛出红色数字报错，通常为状态码`400`或`500`。原因：使用OneAPI转发模型时，未在FastGPT中配置正确的模型上下文长度参数，导致模型无法处理长文本的溯源请求，或知识库解析超时未完成索引。

## 怎么确认配好了
- 发起单条财报相关的测试提问，检查API返回结果中是否包含`reference`字段，字段内是否包含原始文档的文件名、段落位置与内容片段。
- 在终端测试页面发起提问，确认回复下方是否展示可点击的引用来源链接，点击后可跳转至原始文档的对应位置。
- 上传一份煤化工年报测试文件，等待解析完成后，查看知识库的切片列表，确认每个切片均标注了对应的原始文档与段落范围。
- 使用OneAPI转发模型时，在FastGPT的模型配置页面验证模型连通性，确认无报错后发起测试提问，检查引用环节是否正常返回。
