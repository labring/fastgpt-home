# 物业管理财报分析的工作流编排

## 这个品类的数据长什么样
物业管理财报数据来源于项目日常运营台账、业主缴费记录系统、公共能源管理系统及托管方汇总报表。更新节奏以月度、季度、年度为固定周期，单份文档包含营收、成本、资产三大核心模块。营收模块字段包含应收物业费总额、停车费收入、广告位租金收入，单位均为人民币元；成本模块包含公共水电能耗费用、电梯维保支出、人力薪酬总额，单位为人民币元；资产模块包含公共设施折旧额、场地租赁押金余额，单位为人民币元。文档结构按模块分页，每个模块下附明细条目与汇总数值。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散，工作流需配置多数据源拉取节点分别对接不同系统，避免单节点拉取超时。固定周期的更新节奏要求工作流采用定时触发模式，匹配财报的生成周期。多模块的文档结构要求解析节点按模块拆分内容，避免上下文混淆导致字段识别错误。明确的字段与单位要求需添加单位校验节点，防止不同来源的数值因单位不统一出现计算偏差。单次运行需处理多份项目报表，因此需配置批量上传与解析节点，提升整体处理效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份物业财报汇总文档体积较大，解析耗时高于通用文档 |
| `maxContext` | `8000–12000 字符` | 财报分多模块，每个模块需保留足够上下文以准确识别字段 |
| `RECALL_TOP_K` | `前 8 条` | 财报包含多类核心字段，需召回足够数量的关键信息用于分析 |
| `WORKFLOW_TRIGGER_MODE` | `定时触发` | 财报按固定周期生成，匹配定时运行逻辑 |
| `ERROR_HANDLER_RETRY_TIMES` | `3 次` | 数据源拉取偶发网络波动，有限重试可降低运行失败率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：`4.9.10`版本中，提示词配置页的全局变量选项仅显示2个。原因：该版本优化了全局变量的筛选逻辑，仅展示当前工作流已绑定的变量。
- 现象：调用数据源节点时返回`Key is error`报错。原因：使用账号密钥进行鉴权，未使用应用专属密钥。
- 现象：工作流中指定回复节点配置的HTML代码未在前端展示，直接进入下一分支。原因：未开启指定回复节点的HTML解析开关，默认仅渲染纯文本内容。

## 怎么确认配好了
- 触发单次测试运行，检查各数据源节点是否能拉取到对应模块的财报数据，核对字段名称与预设规则一致。
- 查看解析节点的输出日志，确认每个模块的字段单位符合预设要求，无单位不匹配的情况。
- 手动触发定时任务，确认工作流按预设周期自动启动并完成全流程运行。
- 模拟数据源拉取失败的场景，检查错误处理分支是否触发重试逻辑，以及预设的告警通知是否正常发送。
