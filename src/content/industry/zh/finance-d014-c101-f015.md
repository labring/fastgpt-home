# 物流财报分析的部署与升级

## 这个品类的数据长什么样
物流行业财报分析的数据主要来自企业公开披露的年度、季度报告PDF文档，以及行业协会发布的对标数据集。文档结构包含合并财务报表、业务分部营收明细、运营效率指标说明。核心字段包括单票收入、干线周转量、仓储装载量、网点覆盖数量，单位分别为元/票、吨公里、立方米、个。数据更新节奏为季度财报每3个月更新一次，年度财报每年更新一次，行业对标数据每月更新一次。

## 这些特征在「部署与升级」这一环带来什么约束
物流财报的PDF文档篇幅较长，单份年报可能包含数十页财务与业务明细，因此部署时需要调整文档解析的超时阈值，避免长文档解析中断。业务字段包含细分板块的营收、运营数据，需配置针对性的向量召回规则，确保核心指标被优先检索。季度、年度的定期财报更新需求，要求部署定时同步任务的调度配置，适配固定的财报披露周期。行业对标数据的高频更新，需预留足够的向量数据库存储空间与更新带宽，避免升级时出现数据同步延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 物流财报PDF篇幅较长，需预留足够时间完成全文解析与切片 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 单份年度财报PDF可能超过500 MB，需适配大文件上传需求 |
| `maxContext` | `8000–12000 字符` | 财报文档分段后需保留足够上下文，确保财务指标的逻辑关联完整 |
| `RECALL_TOP_N` | `前 8 条` | 物流财报包含多业务板块数据，需召回足够细分字段支撑对标分析 |
| `SIMILARITY_THRESHOLD` | `0.75–0.85` | 财报字段专业性较强，过滤低相似度的无关文档片段，提升分析精度 |
| `SYNC_CRON_EXPR` | `0 0 2 */3 *` | 适配季度财报的更新周期，定时触发数据同步任务 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：Windows环境用Docker Compose部署后，访问网页返回`502 Bad Gateway`状态码。原因：未正确映射FastGPT容器的80端口到宿主机的对应端口，或容器启动顺序错误导致依赖服务未就绪。
- 现象：内网环境部署时，日志提示`Access denied for user 'fastgpt'@'172.17.0.2'`，但MySQL容器状态显示正常。原因：未在docker-compose.yml中配置与MySQL容器匹配的数据库用户名、密码与访问权限，导致FastGPT无法建立连接。
- 现象：直接调用配置的模型API响应速度正常，但在FastGPT内调用时响应延迟显著升高。原因：未调整`maxContext`参数适配长文档解析后的上下文长度，导致模型需处理过多的召回文本片段。

## 怎么确认配好了
- 上传单份测试用物流财报PDF，确认解析任务无超时报错，解析后的文本片段可正常检索。
- 手动触发一次定时同步任务，核对向量数据库内的文档条目数与上传的财报文件数匹配。
- 发起一次财报分析请求，确认返回结果中包含预设的核心业务字段，无大量无关召回内容。
- 查看容器运行日志，无数据库连接失败、端口映射错误类的异常提示。
