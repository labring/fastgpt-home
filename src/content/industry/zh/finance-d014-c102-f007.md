# 特钢财报分析的工作流编排

## 这个品类的数据长什么样
特钢财报数据主要来自证券交易所披露的定期报告、企业官方年报及行业协会发布的细分品类统计资料。更新节奏分为季度报告、年度报告与临时公告三类，季度报告在季后15个工作日内披露，年度报告在年度结束后4个月内披露，临时公告随特钢产能调整、原材料价格波动等事件同步发布。文档结构包含通用财报模块与特钢专属模块，专属模块包含特种钢材牌号产量占比、合金原材料采购成本、下游风电/汽车/高端装备领域营收占比等字段，单位涵盖万吨、元/吨、亿元等。

## 这些特征在「工作流编排」这一环带来什么约束
特钢财报的专属字段与多更新节奏，对工作流编排提出了针对性约束。首先，需支持自定义字段提取规则，适配牌号占比、原材料成本等非通用财报字段的解析，避免通用解析模板遗漏细分数据。其次，需支持多触发模式组合，既可以通过定时任务触发季度/年度财报的批量处理，也可以响应临时公告的手动触发请求。此外，特钢财报的单文档篇幅通常较长，需适配长文本分段与多节点串行处理的逻辑，避免单次处理超时或上下文断裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_DOC_CHUNK_SIZE` | `800–1200 字符` | 特钢财报包含大量细分字段与长文本成本分析，分段长度在此区间可平衡上下文完整性与解析效率 |
| `WORKFLOW_TIMEOUT` | `1800 秒` | 特钢财报解析需多节点联动处理，包含数据源拉取、字段提取、模型生成等步骤，该时长可覆盖全流程执行 |
| `SCHEDULE_CRON_EXPR` | `0 0 2 * * *` | 财报披露通常在交易日收盘后发布，每日凌晨2点触发可避开交易高峰，适配季度/年度批量处理需求 |
| `召回条数` | `前8条` | 特钢财报的细分字段关联性强，召回过多会引入无关数据，过少则丢失关键信息 |
| `相似度阈值` | `0.75` | 过滤低相关性的知识库内容，仅保留与特钢财报主题高度匹配的参考数据 |
| `NODE_RETRY_TIMES` | `2 次` | 针对数据源拉取、模型调用等易失败节点，设置有限重试可降低单次执行失败概率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流执行后仅返回单模型结果，无法分步展示中间处理结果。原因：未配置多节点串行分支，仅绑定了单个对话节点，未启用中间结果传递逻辑。
- 现象：调试节点进入无响应状态，界面持续显示“调试中”状态，无法通过界面按钮终止会话。原因：未设置`NODE_DEBUG_TIMEOUT`参数，或取值超过`300 秒`，导致调试会话超时机制失效。
- 现象：知识库搜索结果无法关联历史对话中的特钢牌号指代，例如输入“该产品的成本”时无法匹配前文提到的“430不锈钢”。原因：未在知识库搜索节点中开启历史上下文优化配置，未启用指代消除逻辑。

## 怎么确认配好了
- 手动上传一份特钢企业的季度财报PDF，查看解析后的数据面板是否包含牌号占比、原材料成本等专属字段。
- 触发一次工作流运行，查看节点执行日志，确认多节点按预设顺序串行执行，无单个节点强制绑定的报错提示。
- 启动调试模式，等待`NODE_DEBUG_TIMEOUT`设定的时长后，确认调试会话自动终止，界面无卡顿残留。
- 输入包含指代的查询，例如“该季度的合金采购成本同比变化”，确认搜索结果关联了前文提到的特钢牌号数据。
