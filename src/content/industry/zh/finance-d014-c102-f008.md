# 特钢财报分析的工具调用与插件

## 这个品类的数据长什么样
特钢财报数据主要来自境内外证券交易所公开披露文件、行业协会月度调研数据及企业官方公告。更新节奏以季度报告、年度报告为固定周期，同时伴随产能调整、原料价格波动等事件发布临时公告。文档结构包含核心财务指标、细分特种钢材产量（如高温合金棒材、风电用宽厚板）、原料采购占比、研发投入占比等字段，单位多为万吨、元/吨、百分比，部分细分品类会标注合金成分占比参数。

## 这些特征在「工具调用与插件」这一环带来什么约束
特钢财报的多源数据来源要求插件支持跨平台接口聚合，需适配交易所API、行业协会数据接口等不同鉴权规则；固定周期与临时事件的更新节奏，要求工具调用支持定时拉取与事件触发两种模式；细分字段多且不同特钢品类差异显著，要求工具支持动态字段映射，避免通用字段匹配遗漏特钢专属指标；单份年报文件体积较大且含复杂表格，要求插件适配大文件解析与流式处理逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 特钢年报单文件常超500MB，需预留足够缓冲空间适配大文件上传 |
| `tool_call_timeout` | `300 秒` | 特钢财报工具调用需多源数据聚合，超时阈值需适配多接口调用耗时 |
| `mcp_stream_enabled` | 开启 | 4.8版本已支持MCP streamable HTTP，开启后可流式返回大文本解析结果，避免内存溢出 |
| `max_tool_results` | `前 8 条` | 特钢财报细分字段较多，限制返回条数可聚焦核心指标，减少冗余数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 特钢年报含大量专业术语与复杂表格，解析耗时较长，需延长超时阈值 |
| `error_retry_count` | `3 次` | 多源接口调用易受网络波动影响，适配重试机制可提升调用成功率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用接口返回`413 Request Entity Too Large`错误。原因是未调整`UPLOAD_FILE_MAX_SIZE`配置，特钢财报单文件体积超出平台默认限制。
- 使用qwen3模型调用工具时，模型仍触发推理模式无法限制。原因是未在模型配置中开启`tool_call_only`参数，未强制模型仅使用工具调用逻辑。
- 配置MCP插件后无法正常拉取数据。原因是未开启`mcp_stream_enabled`配置，4.8版本已支持MCP streamable HTTP，需同步开启对应开关。

## 怎么确认配好了
- 上传一份本地特钢年报PDF，查看解析后的字段是否包含特种合金产量、原料成本等特钢专属字段，确认文件解析配置生效。
- 触发工具调用测试，查看接口返回的结果条数是否符合`max_tool_results`的配置值，确认结果过滤逻辑正常。
- 查看插件运行日志，确认是否有MCP流式返回的日志输出，验证`mcp_stream_enabled`配置是否生效。
- 调用工具拉取交易所财报数据，确认在`tool_call_timeout`配置的时长内完成拉取，验证超时阈值适配合理。
