# 玻璃财报分析的工具调用与插件

## 这个品类的数据长什么样
玻璃作为建筑材料细分品类，其财报相关数据主要来源于国家统计局建材工业统计月报、上市玻璃制造企业公开定期报告、第三方建材供应链数据平台。数据更新节奏分为两类：上市企业财报按季度、年度披露固定报告，临时公告随市场异动发布；行业监测数据按月度更新生产、流通端数据。文档结构分为生产端、成本端、市场端三个板块，核心字段包含浮法玻璃厚度规格、出厂单价、库存量、原材料采购成本，单位分别为毫米、元/平方米、万吨、元/吨。

## 这些特征在「工具调用与插件」这一环带来什么约束
多数据源分散的特征要求工具调用需同时对接财报接口、行业数据接口与大宗商品价格接口，需配置多套鉴权参数。玻璃细分规格较多的特征，要求插件返回结果需支持按厚度规格过滤字段，避免无关数据干扰分析。固定更新节奏的特征，要求插件需配置定时同步任务，匹配不同数据源的更新周期，确保数据时效性。跨板块数据拼接的特征，要求工具调用需处理不同数据源的字段名差异，需配置字段映射规则，统一数据格式用于后续分析。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `plugin_request_timeout` | 120–180 秒 | 玻璃财报数据需跨三个数据源拼接，单次请求需覆盖多类字段，避免超时截断返回结果 |
| `parse_field_whitelist` | ["厚度规格","出厂单价","库存量","原材料成本"] | 过滤非核心字段，减少大模型上下文占用，匹配玻璃财报分析的核心需求 |
| `sync_cron_expression` | 0 0 2 * * * | 匹配行业数据每日凌晨更新的节奏，同时避开上市企业财报披露的高峰时段 |
| `api_auth_type` | 多密钥轮换 | 对接多个数据源需分别配置鉴权密钥，避免单密钥触发限流限制 |
| `result_filter_condition` | 规格匹配当前分析品类 | 仅返回对应厚度的玻璃数据，避免无关规格的数据干扰分析逻辑 |
| `max_context_tokens` | 8000–12000 | 玻璃财报分析需拼接多数据源的长文本数据，适配大模型的上下文窗口要求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用`/api/v1/chat/completions`接口时返回`invalid_prompt`错误，原因是未在请求体中传入玻璃财报专属的字段过滤规则，导致大模型无法识别分析范围。
- 高并发调用时返回`429 Too Many Requests`状态码，原因是未配置多数据源的API限流参数，未启用密钥轮换策略，导致单密钥触发调用限制。
- 将玻璃数据获取逻辑直接写入工作流，未封装为插件，导致无法跨会话复用该工具调用配置，每次会话需重复配置数据源参数。

## 怎么确认配好了
- 发起模拟调用，检查返回结果是否仅包含配置的白名单字段，且匹配指定的玻璃厚度规格。
- 查看插件调用日志，确认请求超时时间配置生效，未出现请求中断或结果截断情况。
- 测试多并发请求，确认未触发限流错误，鉴权密钥轮换逻辑正常运行。
- 查看同步任务执行记录，确认数据源更新频率与配置的cron表达式一致。
