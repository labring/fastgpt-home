# 生物制品财报分析的工具调用与插件

## 这个品类的数据长什么样
生物制品财报数据主要来自境内外证券交易所披露平台、药企投资者关系板块及官方批签发公告。更新节奏分为固定周期与临时触发：季报、年报按监管要求固定披露，临床试验进展、新药获批等临时公告无固定周期。文档以PDF格式为主，结构包含营收构成（细分疫苗、单抗、血液制品等品类）、研发投入（临床试验阶段、项目数量）、生产产能、批签发量等字段，其中批签发量单位为支/瓶，研发费用单位为万元或亿元，存货明细包含生物制品库存的批次与有效期信息。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散要求调用多源插件，需同时对接交易所公告接口与药企IR页面爬虫插件，增加了插件编排的复杂度。临时公告的无固定更新节奏，需要配置定时拉取与事件触发两种调用模式，适配不同数据更新场景。字段与单位的多样性，要求工具调用时需增加字段映射与单位转换步骤，避免因单位不统一导致分析错误。长文本的财报文档，需要适配大上下文的工具调用配置，防止解析或召回时出现截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1200 秒` | 生物制品财报PDF通常包含多页研发、批签发细节，解析耗时显著高于通用文档 |
| `maxContext` | `16000–32000 字符` | 财报文本量大，需覆盖完整的营收构成、研发管线等核心段落 |
| `recall_top_k` | `前8条` | 生物制品财报字段多且细分，需召回足够数量的相关片段以覆盖分析需求 |
| `similarity_threshold` | `0.75–0.85` | 需精准匹配批签发量、研发费用等特有字段，避免召回无关的通用财报内容 |
| `http_request_timeout` | `600 秒` | 调用第三方存储或协作工具接口时，生物制品财报数据量较大，需更长的请求等待时间 |
| `plugin_auto_retry_times` | `2次` | 临时公告接口偶发波动，有限重试可降低调用失败概率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用飞书多维表格的HTTP接口返回`400 Bad Request`，目标字段为空。原因：未正确将环境变量中的飞书认证密钥注入请求头的`Authorization`字段，导致认证失败。
- 现象：知识库召回结果未包含批签发量等特有字段，召回条数与预期不符。原因：未在`vector_model_config`中指定适配财报文本的向量模型，导致特征提取偏差。
- 现象：调用文件上传API后，无法获取文件索引完成状态。原因：未监听`file_process_status`字段的轮询，未设置合理的轮询间隔与超时阈值。

## 怎么确认配好了
- 运行单份生物制品财报的解析测试节点，检查解析后的字段是否包含批签发量、研发管线等特有内容，核对字段单位是否符合行业规范。
- 触发一次定时拉取任务，查看日志中的`update_timestamp`是否匹配最新披露的财报时间，确认插件按设定频率拉取数据。
- 调用第三方协作工具的测试接口，检查返回的`response_code`是否符合预期，确认环境变量参数已正确加载到请求配置中。
- 上传一份测试用生物制品财报PDF，轮询`file_process_status`字段，确认状态从`processing`切换为`completed`后，检查索引中是否包含该文件的完整内容。
