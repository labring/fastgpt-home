# 电子元件财报分析的多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据主要来源于境内外证券交易所公开披露的上市公司定期报告、行业第三方调研机构发布的产业运行数据。更新节奏为季度报告每季度结束后30日内披露，年度报告于次年4月30日前完成披露。文档结构包含业务板块营收明细、产能与出货数据、成本构成、研发投入及下游应用占比，字段包含具体品类的营收金额、出货量、成本占比等，单位涵盖人民币万元、百万颗等电子元件专属计量方式，部分外销占比较高的企业还会包含汇兑损益相关数据。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
电子元件财报的多源数据特征要求多轮对话需支持跨数据源的上下文关联，确保跨财报与行业数据的提问能连贯响应。专属计量单元要求提示词中需明确统一单位转换规则，避免出货量、营收等字段的单位混淆。高频更新的披露节奏要求对话系统需支持指定报告周期的上下文锁定，避免调用过期数据。细分品类繁多的结构特征要求提示词引导用户明确具体元件类型，减少模糊提问带来的结果偏差，同时多轮对话需支持逐层追问细分维度的细节数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 电子元件财报PDF通常包含多组细分品类图表，单文件体积可达数百MB，需适配大文件上传需求 |
| `UPLOAD_S3_PRE_SIGN_EXPIRE` | `300 秒` | 大文件上传需较长的预签名有效期，避免上传中途触发预签名过期报错 |
| `maxContext` | `8000–12000 字符` | 多轮追问中需保留多组品类、周期的上下文信息，避免上下文溢出导致信息丢失 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型年报的文本解析需较长处理时间，避免中途超时中断解析流程 |
| `召回条数` | `前8–10 条` | 电子元件财报的细分品类信息分布分散，需召回足够数量的相关片段覆盖多维度数据 |
| `相似度阈值` | `0.75–0.85` | 电子元件存在大量专业细分术语，需平衡召回精准度与覆盖范围，避免遗漏相关片段 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：升级至4.14.3版本后，上传财报文件或文本数据集时触发`fail to create post presigned url`报错，模板导入功能可正常上传文件。原因：`UPLOAD_S3_PRE_SIGN_EXPIRE`参数配置值过小，或接口路径未适配新版本的S3上传逻辑，导致预签名URL生成失败。
- 现象：多轮对话中追问细分品类数据时，返回结果未明确对应计量单元，出现单位混淆。原因：提示词未明确要求统一转换电子元件专属计量方式，未在上下文中标注单位规则。
- 现象：解析大型年报后，召回的相关片段数量不足，无法覆盖细分品类的营收数据。原因：`召回条数`配置值过低，或`相似度阈值`设置过高，过滤掉了部分细分品类的相关片段。

## 怎么确认配好了
- 上传一份典型的电子元件年报PDF，检查上传流程无报错，查看上传日志确认预签名URL生成正常。
- 发起多轮对话，先询问总营收，再追问特定细分品类的营收数据，确认上下文被正确保留，返回结果包含明确的品类与周期信息。
- 调整`召回条数`与`相似度阈值`的配置，测试不同取值下的召回片段数量，确认覆盖所有所需的细分品类数据。
- 触发文件解析任务，查看解析耗时，确认未触发`PARSE_FILE_TIMEOUT_SECONDS`对应的超时限制。
