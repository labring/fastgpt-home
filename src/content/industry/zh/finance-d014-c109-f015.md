# 电子元件财报分析的部署与升级

## 这个品类的数据长什么样
电子元件财报数据主要来自公开披露的上市公司年度、季度报告，以及行业第三方统计机构的月度出货监测数据。更新节奏为季度财报每季度末后1至2个月集中发布，月度出货数据每月下旬更新。文档以PDF格式为主，附带结构化Excel附件，内容分为结构化字段与非结构化分析段落，结构化字段包含元件型号、出货量、单位成本、营收占比等，单位多为百万片、元/片、万元。

## 这些特征在「部署与升级」这一环带来什么约束
电子元件财报兼具结构化附件与非结构化PDF的混合格式，部署时需同时配置结构化数据解析与细分领域文本拆分插件，无法仅依赖通用解析能力。季度与月度的批量数据更新频率较高，需预设定时同步任务与大文件处理阈值，避免同步超时。字段包含细分型号维度，向量库需配置按型号分组的索引规则，提升召回精度。长期运行中，累积的历史财报数据会占用较多存储，升级时需同步配置数据归档与清理策略，防止存储资源耗尽。批量同步未分片时，会触发高频硬盘读写，需提前规划存储读写的并发限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 电子元件财报的结构化附件包含多页表格，解析耗时较长，600秒可覆盖完整解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 单份季度财报的PDF与配套附件总大小通常不超过800MB，预留200MB冗余空间 |
| `chunkSize` | `800–1200 字符` | 电子元件财报的非结构化段落包含较多专业术语，该分段长度可保留完整的专业表述逻辑 |
| `RECALL_TOP_K` | `前 8 条` | 电子元件财报的型号维度较多，按型号分组召回后需保留足够的细分数据条目，8条可覆盖常见检索需求 |
| `SYNC_TASK_BATCH_SIZE` | `每批次 50 份` | 批量同步财报数据时，50份的批次可平衡同步效率与硬盘读写压力，避免高频读写触发存储过载 |
| `VECTOR_SIMILARITY_THRESHOLD` | `0.75–0.85` | 电子元件财报的专业术语较多，该阈值可过滤低相关性的检索结果，提升精准度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：docker部署后出现高频硬盘读写，存储资源快速耗尽。原因：未配置`SYNC_TASK_BATCH_SIZE`参数，批量同步财报数据时未限制并发批次，触发大量随机读写。
- 现象：结构化Excel附件解析后部分细分字段为空。原因：未启用针对电子元件财报的结构化解析规则，通用解析无法识别型号、出货量等专属字段。
- 现象：本地非Docker离线部署启动时出现依赖加载失败报错。原因：未提前下载离线所需的行业词库与模型依赖包，离线环境下无法完成初始化加载。

## 怎么确认配好了
- 执行单份季度财报的上传与解析任务，核对解析后的字段完整性，调整对应参数至符合业务需求的取值。
- 发起批量同步任务，监控硬盘读写速率与任务完成时长，调整同步批次参数至平衡效率与资源占用的范围。
- 发起针对元件型号的检索请求，核对召回结果的分组逻辑，调整召回与相似度阈值参数至符合检索精度要求的范围。
- 测试离线环境下的部署启动流程，确认所有依赖包与词库已正确加载，无初始化报错。
