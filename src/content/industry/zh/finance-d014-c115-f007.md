# 种植业财报分析的工作流编排

## 这个品类的数据长什么样
种植业财报相关数据主要来自上市农业企业公开披露的年度/季度报告附件、农业农村主管部门发布的行业统计报表、金融机构授信调研获取的种植基地生产台账。数据更新节奏为年度完整财报更新，季度补充业务进度数据，月度监测数据按需同步。文档结构多包含种植面积、单位产量、农资投入成本、农产品收购均价等字段，单位多采用亩、公斤、元/吨等农业生产通用标准单位，部分细分品类还会包含病虫害发生率、灌溉用水量等专项数据。

## 这些特征在「工作流编排」这一环带来什么约束
种植业财报相关数据来源分散且格式不统一，要求工作流配置多源数据拉取节点，适配公开报表、企业台账、调研数据等不同格式的数据源。数据更新存在年度全量、季度增量、月度监测的分层节奏，需设置定时触发节点的周期参数，区分全量同步与增量拉取逻辑。字段与单位存在细分差异，工作流需配置字段映射规则，将不同来源的同类数据统一为标准单位与字段名，避免后续分析出现单位混淆。部分专项数据需对接特定数据源接口，需在工作流中预留自定义接口配置入口。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `contextRetainCount` | 1 | 种植业财报分析仅需单次调用的上下文，无需多轮历史对话留存 |
| `CUSTOM_READ_FILE_URL` | 按数据源实际地址配置 | 用于拉取公开农业统计报表与企业财报附件，适配多源数据读取需求 |
| `triggerCycle` | 86400 秒（每日）、604800 秒（每周） | 匹配种植业财报季度、年度的更新节奏，按需设置定时触发周期 |
| `fieldMappingRule` | 按亩/公斤/元/吨统一映射 | 解决不同来源数据的单位与字段名差异，确保分析数据口径统一 |
| `apiTimeout` | 300 秒 | 适配种植业财报文档较长、数据拉取耗时较长的场景，避免超时中断 |
| `variableSyncMode` | 按请求参数覆盖 | 支持通过URL参数传递全局变量，匹配外部调用的传参需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中AI节点的输出结果无法通过变量更新节点设置为空值，最终字段仍保留原始输出。原因：变量更新节点仅支持对基础类型变量的赋值操作，未针对AI模型输出的结构化结果配置空值覆盖规则，需额外添加数据清洗节点处理空值逻辑。
- 现象：通过应用链接携带URL参数时，全局变量未被正确赋值，工作流无法读取传入的参数值。原因：未开启工作流的URL参数同步开关，或变量名未与URL参数名完全匹配，导致参数无法映射到全局变量。
- 现象：同一会话ID多次调用工作流时，第一个AI节点的上下文保留条数未按配置生效，仍保留多轮历史对话。原因：未在工作流的AI节点配置中单独设置`contextRetainCount`参数，复用了工作流全局的上下文保留规则，导致不同节点的配置未生效。

## 怎么确认配好了
- 手动触发工作流，拉取一份公开的种植业财报数据，检查数据处理节点输出的字段与单位是否与预设的映射规则一致。
- 调用工作流的测试接口，携带自定义URL参数，查看全局变量是否被正确赋值。
- 配置定时触发任务，等待一个周期后查看工作流执行日志，确认触发时机与配置的`triggerCycle`参数匹配。
- 分别测试两次调用同一工作流，查看两个AI节点的上下文保留条数是否符合各自的配置要求。
