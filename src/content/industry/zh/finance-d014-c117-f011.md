# 纺织制造财报分析的文档解析与分块

## 这个品类的数据长什么样
纺织制造品类的财报数据来源包含上市公司公开年报、季报，内部生产台账、原料采购明细，以及行业协会披露的产能数据。更新节奏覆盖年度、季度及月度，其中公开财报按监管要求固定更新，内部生产数据随订单与生产进度实时更新。文档以PDF格式的标准化财报为主，附带Excel格式的明细表格，结构包含合并财务报表、生产经营数据表、原料库存台账等，字段涵盖纱线产量、面料幅宽、订单交付率、单位生产成本等，单位包含米、千克、件、万元人民币等多类专业计量标准。

## 这些特征在「文档解析与分块」这一环带来什么约束
多来源的混合文档格式要求解析流程同时兼容公开财报的标准化结构与内部台账的非标准化格式；高频更新的多周期数据需要定时同步与分块，避免分块策略无法适配不同更新频率的文档；纺织制造特有的专业字段与多单位计量，要求分块时保留术语与单位的上下文关联，防止拆分后语义断裂；大量明细表格的存在，要求解析时保留列级数据的关联关系，避免仅按行拆分导致的信息丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `分段长度` | 800–1200 字符 | 适配纺织财报中长段落的生产说明与专业术语，避免过短拆分语义、过长丢失上下文 |
| `最大段落深度` | 3–5 | 匹配财报的层级结构（合并报表->子表->明细项），保留跨层级的字段关联 |
| `启用表格多向量支持` | 开启 | 针对纺织财报中大量原料采购、产能明细表格，保留列级数据的关联信息 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 适配大型年度财报的多页表格解析时长，防止默认超时导致任务失败 |
| `API_FILE_SYNC_INTERVAL` | 3600 秒 | 匹配月度生产数据的更新频率，保证同步时效性 |
| `分块重叠字符数` | 100–150 字符 | 保留专业术语的上下文衔接，避免分块断裂导致的语义缺失 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：表格解析后仅返回单列表格数据，列级关联信息丢失。原因：未开启`启用表格多向量支持`配置，仅按行拆分表格内容，无法保留跨列的专业字段关联。
- 现象：大型年度财报解析任务返回`504 Gateway Timeout`错误。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数至合理区间，默认超时时间不足以完成多页表格的解析。
- 现象：通过API调用分块接口后，返回的分块结果中“纱支密度”“幅宽”等专业术语被拆分。原因：`分段长度`设置过小，将完整的专业术语拆分为两个分块，破坏语义完整性。

## 怎么确认配好了
- 上传一份包含明细表格的纺织制造季度财报PDF，查看解析后的表格是否保留了列标题与对应数据的关联，确认`启用表格多向量支持`配置生效。
- 查看API同步日志，确认`API_FILE_SYNC_INTERVAL`参数匹配数据更新频率，无重复或遗漏的同步任务。
- 手动截取一段包含专业术语与单位的财报文本，通过分块测试工具验证拆分结果是否保留了完整的术语与上下文，确认`分段长度`与`分块重叠字符数`配置合理。
- 检查近7天的解析任务日志，确认无`504 Gateway Timeout`类超时报错，验证`PARSE_FILE_TIMEOUT_SECONDS`参数设置合理。
