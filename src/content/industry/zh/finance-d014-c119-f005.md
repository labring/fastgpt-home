# 综合服务财报分析的多轮对话与提示词

## 这个品类的数据长什么样
综合服务类财报数据主要来自公开披露的上市公司定期报告、临时公告及交易所官方文件。更新节奏与披露周期绑定，集中在季度末、年度末的固定时段，临时公告随事件触发发布。单份财报文档包含结构化报表数据与非结构化附注内容，字段涵盖营收、成本、现金流等核心财务指标，单位统一为人民币元或万元，部分细分项标注百分比占比。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
财报数据的周期绑定特性要求多轮对话需保留各报告期的上下文标识，避免跨周期数据混淆。结构化与非结构化混合的文档结构，要求提示词需明确区分结构化报表查询与附注解读的指令格式。固定更新节奏要求提示词中需指定查询最新披露的报告版本，避免调用过期数据。多字段的属性要求提示词需明确限定查询范围，防止返回无关财务项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 财报数据包含多份报表与附注，需保留足够历史上下文关联不同报告期的对比分析 |
| `CHAT_FILE_EXPIRE_TIME` | `7 天`（如需延长可调整为`30 天`） | 财报披露周期以季度为单位，7天过期时长可覆盖常规分析周期，延长需匹配存储资源占用情况 |
| `PROMPT_TEMPLATE` | 「请基于用户指定的财报报告期，先检索对应结构化报表数据，再解读附注内容，多轮对话中需保留已确认的报告期标识」 | 适配混合结构的财报数据，明确指令优先级与上下文规则 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份财报文档可能包含大量附注内容，需足够时间完成完整解析 |
| `RECALL_CHUNKS_NUM` | `前 8–10 条` | 财报字段多且分散，召回适量分段可覆盖核心分析需求，避免冗余信息干扰 |
| `TOKEN_LIMIT_PER_REQUEST` | `15000 令牌` | 单轮对话需处理多份报表数据与附注，需控制单次请求的令牌消耗，避免超出模型上限 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：对话中调用的财报文件提示「文件已过期」，无法读取历史分析数据。原因：未调整`CHAT_FILE_EXPIRE_TIME`参数，默认7天过期时长超出分析周期，或未配置文件永久存储选项。
- 现象：多轮对话中token消耗超出预期，导致对话中断或返回不完整内容。原因：未限制`maxContext`参数长度，保留了过多无关的历史对话上下文，未过滤非分析相关内容。
- 现象：批量执行节点中多AI对话任务串行执行，未实现并行调度。原因：未配置多节点并行触发规则，或未正确设置任务队列的并发上限参数。

## 怎么确认配好了
- 上传单份完整财报文档，发起多轮对话测试，检查上下文是否保留了已确认的报告期信息。
- 进入文件管理界面，查看已上传财报文件的过期时间设置，确认`CHAT_FILE_EXPIRE_TIME`参数符合当前分析周期需求。
- 运行批量任务测试，查看任务执行日志，确认多AI对话节点是否按预期并行执行。
- 查看对话过程中的实时token消耗提示，确认`TOKEN_LIMIT_PER_REQUEST`参数未超出当前使用模型的支持上限。
