# 综合服务财报分析的工具调用与插件

## 这个品类的数据长什么样
综合服务类财报数据主要来自境内外证券交易所公开披露文件、专业财报数据库接口及企业官方年报公告。更新节奏包含年度、季度定期披露，以及重大事项临时公告两类。单份财报文档结构通常包含合并资产负债表、利润表、现金流量表及详细附注，核心字段涵盖营业收入、归母净利润、资产负债率、经营活动现金流净额等，单位多以万元或亿元为基准，部分附注会补充分项业务的明细数据。

## 这些特征在「工具调用与插件」这一环带来什么约束
财报数据的定期与临时更新特征，要求工具调用需支持定时触发拉取新披露财报，或接收外部事件触发增量同步，确保分析数据的时效性。单份财报文档长度较长且包含多层级附注，要求插件需内置长文本分段处理逻辑，避免单次调用超出大模型上下文限制，影响字段提取精度。核心字段的单位差异与明细分项，要求插件需预设字段映射规则，自动完成单位统一与分项数据聚合，减少后续人工处理步骤。同时多数据源对接需求，要求插件支持灵活配置不同数据源的鉴权与请求参数，适配不同财报数据来源的调用格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `max_tool_calls` | 6–8 次 | 综合服务财报包含多层级明细，需多次调用插件提取分项数据，次数过高会增加整体调用耗时 |
| `tool_request_timeout` | 300 秒 | 财报数据接口可能返回大量明细数据，较长超时可避免因数据拉取不完整导致的调用失败 |
| `plugin_request_max_length` | 8000–12000 字符 | 单份财报附注段落较长，需适配长文本传输需求，避免内容被截断 |
| `plugin_auth_method` | API Key 鉴权 | 多数财报数据源采用 API Key 鉴权方式，适配通用数据源对接需求 |
| `auto_context_split` | 开启，分段长度 1500 字符 | 财报文档过长，自动分段可适配大模型上下文窗口限制，提升字段提取准确率 |
| `field_mapping_rule` | 按实测标定 | 不同数据源的字段命名存在差异，需根据对接的具体数据源调整映射规则 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：自定义插件调用后返回结果缺失明细数据，或字段格式不符合预期。原因：未在插件配置中补充数据源的返回字段说明，导致工具调用时无法正确解析返回内容。
- 现象：大模型调用提示欠费，且接口返回 402 状态码，实际API账户仍有剩余额度。原因：未同步更新插件绑定的第三方数据源API Key额度，或未配置插件调用的费用预警机制。
- 现象：工具调用超时，界面显示请求超时提示。原因：配置的`tool_request_timeout`时长过短，未适配财报数据拉取的耗时需求。

## 怎么确认配好了
- 调用测试用的财报数据源接口，核对返回字段与配置的`field_mapping_rule`是否完全匹配。
- 模拟定时触发插件拉取最新财报，检查数据更新时间与对应财报的披露时间是否一致。
- 调整`auto_context_split`的分段参数，验证长文本处理后未出现内容截断或字段提取遗漏。
- 查看工具调用日志，确认每次调用的耗时未超出配置的`tool_request_timeout`阈值。
