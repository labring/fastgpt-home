# 股份制银行财报分析的引用来源与溯源

## 这个品类的数据长什么样
股份制银行财报的数据来源为银保监会官方披露的定期报告与临时公告，更新节奏为年度报告每年披露一次，半年度报告每半年披露一次，重大事项公告随事件触发更新。文档结构包含核心财务报表章节、风险管理章节、经营情况分析章节。字段包含期末总资产、营业收入、不良贷款余额等核心指标，单位统一为亿元或万元，部分指标采用自然数值单位，无额外百分比类标注。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于财报数据均来自官方公开披露渠道，溯源环节需明确匹配具体的披露报告版本与渠道，避免引用非官方或过期内容。固定的更新节奏与不定期的临时公告，要求配置定期同步与增量更新机制，确保知识库内的财报数据与官方披露保持同步。单份财报文档篇幅较长，分段处理时需避免关键财务字段被拆分至不同分段，防止溯源时出现上下文断裂。固定的字段结构与合规性要求，需配置字段级的精准匹配规则，确保引用内容与财报原文完全对应。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 适配股份制银行财报的单段信息密度，避免关键财务字段被拆分至不同分段 |
| `recallTopK` | `前 6–8 条` | 财报分析问题通常需要多段上下文支撑，覆盖核心指标与关联说明 |
| `similarityThreshold` | `0.75–0.85` | 财报字段精准度要求高，过滤低匹配度的无关文档片段 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 单份年度财报解析耗时较长，防止解析过程超时中断 |
| `rerankTopN` | `前 3–5 条` | 溯源展示需精简，同时覆盖核心引用依据，避免界面信息过载 |
| `enableSourceTag` | `开启` | 财报分析需明确披露来源，满足合规性与可读性要求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：知识库已上传股份制银行财报文档，问答环节显示已匹配源数据，但最终回答未展示引用内容或提示无有效结果。原因：未开启`enableSourceTag`配置，或`similarityThreshold`设置超出合理区间，过滤了正确召回的文档片段。
- 现象：使用`text-embedding-3-large`作为索引模型时，服务启动或解析财报文档时长时间无响应。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，长财报文档的嵌入计算耗时超过默认阈值，且未配置重试机制，导致服务阻塞。
- 现象：配置行业问答对知识库后，生成的回答未严格复用知识库中的原文答复，而是生成了新的自然语言内容。原因：未开启`strictReply`配置，或`recallTopK`设置过低，未召回到完全匹配的问答对片段。

## 怎么确认配好了
- 上传单份股份制银行年度财报文档，等待解析完成后，查看解析后的分段内容，确认分段长度适配财报的单段信息密度，无关键财务字段被拆分至不同分段。
- 发起一个针对财报核心指标的查询，查看召回结果的数量与排序，确认召回与重排的取值覆盖了核心引用片段。
- 查看问答结果的溯源模块，确认已展示源文档的名称、段落位置等信息，验证源引用配置已生效。
- 上传一组预设的行业问答对，发起匹配查询，确认返回内容与知识库中的原文答复完全一致，验证严格回复配置已生效。
