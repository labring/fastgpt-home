# 能源金属财报分析的工作流编排

## 这个品类的数据长什么样
能源金属相关上市公司的财报数据，主要来自上海证券交易所、深圳证券交易所、香港联合交易所官方披露平台及企业官方投资者关系页面的PDF文档。年度财报需在次年4月底前披露，半年度财报需在8月底前披露，季度财报需在季后1个月内更新。文档包含管理层经营分析、合并财务报表及附注、产能产量统计等模块，核心字段包括归母净利润、营收总额、碳酸锂产能、单位生产成本，对应单位多为亿元、万吨、元/吨。

## 这些特征在「工作流编排」这一环带来什么约束
能源金属财报的多来源PDF格式、分周期披露的特征，要求工作流需配置适配多格式的文件解析节点，保留财务表格与经营数据的结构化信息。固定披露周期要求工作流支持按季度、半年度、年度触发，适配集中披露时段的任务调度。财报中包含通用财务字段与专属产能产量数据，要求工作流需配置实体抽取规则，精准匹配能源金属相关的经营字段，避免遗漏非标准化的业务数据。单份财报文档篇幅差异较大，要求文件解析节点配置合理的超时阈值，避免大体积文档解析失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 能源金属财报PDF可能包含数百页内容与大量经营数据，600秒可覆盖多数大体积文档的解析需求 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 大型矿业公司的年度财报PDF体积可达500 MB以上，1000 MB可覆盖绝大多数场景 |
| `LOOP_VAR_APPEND_MODE` | `数组追加` | 需收集循环节点内每一家企业的财报分析结果，数组追加可完整保留所有子项的输出数据 |
| `enable_thinking` | `按需配置` | 能源金属财报分析包含财务数据校验与经营逻辑推导场景，复杂分析开启思考可提升准确性，字段提取场景关闭思考可降低耗时 |
| `BATCH_NODE_MAX_PARALLEL` | `3–5 个` | 能源金属财报解析与分析需占用较多计算资源，并行数过高可能触发平台限流，过低则延长批量任务整体耗时 |
| `FILE_PARSE_TABLE_MODE` | `保留原始格式` | 财报中的产能、单位成本等表格需保留行列结构，便于后续精准提取专属业务字段 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流节点运行后弹出`model_request_failed`报错弹窗，流程直接终止。原因：未在工作流中配置错误捕获分支，未设置报错后的重试或日志记录逻辑，导致模型请求出错后流程中断。
- 现象为批量执行节点完成后，汇总节点仅获取到最后一条子项的分析结果。原因：未将循环变量追加模式配置为数组追加，默认的覆盖模式会导致每次循环的输出覆盖前一次的结果。
- 现象为模型节点输出包含大量无关的思考过程文本，未生成规整的财报分析内容。原因：未正确配置`enable_thinking`参数，且未在系统提示词中明确要求屏蔽思考过程，导致思考内容混入最终输出。

## 怎么确认配好了
- 上传单份能源金属财报测试文件，启动工作流后查看解析节点的输出结果，确认核心经营字段与财务数据被正确结构化。
- 配置批量测试任务，传入多份财报文件，运行后查看汇总节点的输出，确认包含所有测试企业的分析结果。
- 分别开启与关闭模型思考开关，运行对应分析任务，确认思考过程的输出符合配置要求。
- 手动触发节点报错模拟，确认错误捕获分支正常触发并生成对应的日志记录。
