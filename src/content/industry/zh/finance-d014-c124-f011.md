# 自动化设备财报分析的文档解析与分块

## 这个品类的数据长什么样
自动化设备财报的数据主要来自上市企业公开年度/季度报告、行业参考文档、设备招投标备案文件。数据更新节奏匹配财报披露周期，季度报告每3个月更新，年度报告每年更新。文档以PDF格式为主，包含结构化参数表格、技术说明段落与营收明细，字段包含设备额定负载、运行速度、订单金额等，单位涵盖kN、m/min、万元等，部分细分品类文档附带Excel格式的零部件采购清单与CSV格式的订单统计数据。

## 这些特征在「文档解析与分块」这一环带来什么约束
多格式混合的数据源要求解析模块同时支持PDF文本提取、Excel单元格结构化读取与CSV字段映射，否则会丢失结构化数据。结构化表格占比高，分块时若按普通段落拆分会割裂表格内的参数关联，需要保留表格作为独立分块单元。字段单位多样且与参数强绑定，分块时需保留字段与单位的上下文关联，避免拆分后参数与单位分离。财报文档篇幅跨度大，从小型厂商报告到集团年报，分块策略需适配不同长度的文档，避免大段文本拆分后丢失逻辑连贯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunk_size` | 800–1200 字符 | 自动化设备财报包含大量技术参数与说明段落，该区间可保留参数与上下文的关联，避免拆分技术逻辑 |
| `table_parse_mode` | `structured_only` | 自动化设备财报中参数表格、营收明细表格占比高，结构化解析可完整保留表格字段与数据关联 |
| `chunk_overlap` | 150–200 字符 | 技术参数说明存在跨块关联的补充内容，重叠区间可保留上下文连贯性 |
| `pdf_parser_version` | `v2.1.0` | 该版本优化了工业设备文档中的复杂嵌套表格解析，修复了参数字段拆分错位的问题 |
| `csv_field_mapping` | 按原始列名映射为标准化字段 | 自动化设备财报的CSV采购清单列名不统一，映射后可避免检索时字段混淆 |
| `max_parse_timeout` | 300 秒 | 大型集团年报包含大量高清图表与参数表格，较长超时可保证完整解析 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为CSV格式的采购清单解析后仅返回部分条目，检索时无法匹配全部条目。原因是未配置`csv_field_mapping`，导致列名不统一的字段被合并或遗漏。
- 现象为调用`/v2/parse/file`接口时返回`500 Internal Server Error`，日志显示解析模块加载失败。原因是升级`pdf-marker`至未开源版本后，缺少核心依赖文件导致接口无法正常启动。
- 现象为多文件上传后仅解析了最先上传的文档，后续文档未生成分块。原因是未正确配置多文件传参的消息格式，导致接口仅读取最先出现的`content`字段的内容。

## 怎么确认配好了
- 上传一份自动化设备财报的CSV采购清单，核对解析后的字段列表与原始文件列名是否匹配，确认字段映射配置生效。
- 上传一份包含嵌套参数表格的PDF文档，查看分块结果中是否完整保留了表格的行列结构，确认表格解析模式配置正确。
- 调用解析接口，查看返回的解析日志中是否包含`pdf_parser_version`为`v2.1.0`的记录，确认解析版本配置无误。
- 上传一份长技术说明段落的文档，检查分块后的文本是否保留了参数与对应单位的上下文关联，确认分块长度配置适配文档特征。
