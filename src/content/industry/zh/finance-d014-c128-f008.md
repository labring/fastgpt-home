# 航运港口财报分析的工具调用与插件

## 这个品类的数据长什么样
航运港口财报相关数据来源为港口运营主体公开披露的定期报告、行业统计机构发布的月度运营数据。更新节奏为年度完整财报每财年结束后1-3个月发布，季度运营数据每季度末后1个月发布，月度吞吐量数据当月末后10天发布。文档结构包含核心运营指标、成本结构、营收构成、资产负债明细等模块。字段包括集装箱吞吐量、散货吞吐量、航线班次、泊位作业时长、营收金额等，单位分别为标准箱、万吨、班次、小时、人民币元。

## 这些特征在「工具调用与插件」这一环带来什么约束
公开财报的更新周期分层，年度财报体量较大，月度运营数据更新频繁，工具调用需支持按时间粒度切换数据源拉取逻辑。多模块的文档结构要求插件内置分块解析规则，精准抽取指定字段。字段单位差异显著，需插件内置单位标准化映射逻辑，避免跨数据源的单位混淆。不同港口的披露格式存在差异，工具调用需适配多种公开文档的解析模板，减少字段抽取偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 航运港口财报单文件体量较大，包含多模块明细，解析耗时较长，600秒可覆盖完整解析流程。 |
| `maxContext` | `8000–12000 字符` | 财报文档分块后需保留完整业务逻辑，该区间可覆盖单模块核心内容，避免上下文截断。 |
| `召回条数` | `前 8–10 条` | 财报字段覆盖多维度，需召回足够数量的关联片段以支撑完整分析，避免关键信息遗漏。 |
| `相似度阈值` | `0.75–0.85` | 需精准匹配财报字段与分析需求，该区间可过滤低相关性片段，同时保留同品类下的字段变体。 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 年度财报包含详细资产负债表、现金流表等附件，该上限可覆盖多数公开披露的完整财报文件。 |
| `工具调用重试次数` | `2 次` | 部分第三方行业数据接口存在临时波动，有限重试可提升调用成功率，避免过度等待。 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用知识库生成财报分析时响应超时，耗时超过10秒。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以覆盖大型财报文件的解析流程。
- 现象：API调用返回的分析结果中，后一个变量的内容叠加了前一个变量的结果。原因：未正确配置`maxContext`参数，导致上下文残留前一次调用的输出内容，引发变量拼接异常。
- 现象：调用MCP工具拉取港口运营数据时，返回连接失败的报错提示。原因：未配置正确的数据源API访问权限，或工具调用的超时设置短于港口数据接口的响应时长。

## 怎么确认配好了
- 上传单份港口财报示例文件，核对解析后抽取的字段与单位是否与预设规则一致。
- 发起单次工具调用测试，根据响应时长调整`PARSE_FILE_TIMEOUT_SECONDS`至适配场景的取值。
- 调用API发起分析请求，检查返回的分析结果中各变量内容是否独立，无拼接残留。
- 验证MCP工具的连接状态，确认数据源访问权限与配置参数匹配业务需求。
