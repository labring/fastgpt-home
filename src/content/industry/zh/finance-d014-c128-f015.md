# 航运港口财报分析的部署与升级

## 这个品类的数据长什么样
航运港口财报数据主要来自港口运营主体的官方定期公告、交通运输主管部门的水运行业统计公报、港口集装箱吞吐量月度快报。数据更新节奏分为月度（集装箱吞吐量、装卸作业量）、季度（营收、成本分项）、年度（完整审计财报）。单份文档长度差异较大，月度快报多为结构化表格，年度财报篇幅不一，包含泊位利用率、堆存周转率、单箱作业成本等字段，单位涉及标准箱（TEU）、万吨货物吞吐量、元/标准箱等，相关内容建议按自有样本统计或实测后确定。

## 这些特征在「部署与升级」这一环带来什么约束
航运港口财报的多更新频率、长文档结构、多字段特征，对部署与升级环节带来多重约束。月度快报的高频更新要求部署时配置增量同步触发机制，避免全量拉取占用过多计算资源。单份年度财报的超长文本，需要在升级时调整文档解析的分段参数，适配大上下文窗口的处理逻辑。多维度结构化字段（如吞吐量、作业成本）要求知识库索引配置支持多标签分类，便于后续分析按维度召回数据。不同更新周期的数据需区分存储周期，升级时需兼容新旧版本的数据归档格式，避免数据丢失或索引失效。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 年度审计财报单文件体积大、内容多，常规超时时间无法完成完整解析 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 年度财报的单文件扫描件或结构化文档可达该体积，需适配长文档上传限制 |
| `maxContext` | `8000–12000 字符` | 财报多字段关联分析需保留足够上下文，避免分段后丢失数据关联逻辑 |
| `RECALL_TOP_N` | `前 8 条` | 财报分析需覆盖吞吐量、成本、作业效率等多维度数据，合理控制召回条数平衡精度与性能 |
| `IMAGE_INDEX_ENABLE` | `开启` | 部分港口财报附带作业现场图像、泊位规划图，需开启图片索引辅助多模态分析 |
| `SYNC_INTERVAL` | `每小时` | 月度快报需高频同步最新装卸作业数据，保障分析结果的时效性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：本地部署更新后，上传单份体积较大的财报文档至知识库，模型无法基于文档生成分析结果，后台日志显示`413 Request Entity Too Large`错误。原因：更新过程中未保留原配置的`UPLOAD_FILE_MAX_SIZE`参数值，默认参数限制了大文件上传。
- 现象：本地部署4.9.0版本的FastGPT，新建知识库或上传文档时，无图片索引相关的配置选项，无法对财报附带的作业图像进行索引。原因：4.9.0版本的`IMAGE_INDEX_ENABLE`环境变量默认关闭，且前端界面未默认展示该配置项，需手动修改配置后重启服务。
- 现象：Docker部署完成后，接入第三方大模型时，调用接口返回`invalid api key`报错，无法完成模型绑定。原因：未正确配置第三方模型的API密钥与接口地址，或未在环境变量中添加对应的模型标识参数。

## 怎么确认配好了
- 上传一份模拟的航运港口财报文档，检查上传流程是否正常完成，无超时类报错，确认文件上传的限制符合配置要求。
- 进入知识库的配置界面，查看是否存在与图片索引相关的设置项，确认其状态与预设配置一致。
- 手动触发一次数据同步任务，检查后台日志中是否存在同步成功的标识，无数据拉取失败的报错信息。
- 向绑定的模型输入财报分析类查询，检查返回结果是否覆盖了财报中的核心字段，无明显的上下文缺失问题。
