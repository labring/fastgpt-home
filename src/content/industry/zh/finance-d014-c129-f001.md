# 融资租赁财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
融资租赁财报数据主要来源于核心业务管理系统、征信对接系统及监管报送平台。更新节奏分为定期与实时：季度、年度正式财报按固定披露周期更新，日常租金回收、逾期台账等业务数据按日同步。文档结构包含租赁资产明细表、应收租金收支表、逾期客户台账、监管合规指标表四类核心文件。字段包含租赁本金余额、应收租金总额、逾期天数、担保物估值，单位分别为万元、万元、自然日、万元。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于数据来源分散，需对接多套外部系统的HTTP接口，不同系统的鉴权协议、请求格式存在差异，需分别配置接口密钥、请求头与响应解析规则。定期财报与实时业务数据的更新节奏不同，需区分配置定时拉取的轮询间隔，以及实时数据的webhook回调地址。多类文档结构对应不同的字段映射规则，需在接口层完成租赁本金余额、逾期天数等字段的标准化转换。部分业务数据的单位需从原始接口的元转换为财报要求的万元，需在接口调用链路中添加单位校准逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `external_api_auth_type` | 按对接系统选择：基础 auth、API Key、OAuth2 | 不同外部系统支持的鉴权协议存在差异，需匹配对应配置 |
| `sync_interval_seconds` | 300–86400 秒 | 覆盖实时业务数据（300秒）与季度/年度财报（86400秒）的同步需求 |
| `field_unit_conversion` | 开启，转换系数设为0.0001 | 将原始接口返回的元单位数据转换为财报要求的万元单位 |
| `response_parse_mode` | 按文档类型选择：结构化JSON解析、半结构化文本提取 | 适配租赁资产明细表、逾期台账等不同格式的接口返回内容 |
| `webhook_callback_url` | 按业务系统配置专属回调地址 | 区分实时租金数据与逾期预警的推送链路 |
| `timeout_threshold` | 60 秒 | 避免因接口响应缓慢导致的整体流程阻塞 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置外部接口地址与密钥后，调用时返回`Invalid API Key`错误。原因：未将密钥正确填入对应鉴权参数位，或未匹配接口要求的请求头格式。
- 现象：同步的财报数据中租赁本金余额字段为空。原因：未配置对应字段的映射规则，原始接口返回的字段名与系统预设字段不匹配。
- 现象：调用接口后出现`504 Gateway Timeout`错误。原因：未设置合理的超时阈值，接口响应时间超过系统默认限制。

## 怎么确认配好了
- 调用测试接口，查看返回的响应头与鉴权参数是否与外部系统要求一致，核对配置项是否匹配。
- 拉取单条业务数据，检查字段映射与单位转换是否符合财报要求，确认租赁本金余额等核心字段的数值正确。
- 触发定时同步任务，查看任务日志中的同步间隔是否符合配置的轮询时长，确认数据更新时间符合预期。
- 测试webhook回调，查看推送的实时数据是否正确触发后续的财报更新流程，确认回调地址配置无误。
