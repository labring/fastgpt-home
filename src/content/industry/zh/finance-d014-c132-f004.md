# 计算机设备财报分析的向量模型与索引

## 这个品类的数据长什么样
计算机设备财报的数据主要来自上市企业公开披露的年度、季度财报附注，以及设备采购的临时公告。更新节奏为每季度末、年度末集中更新，临时采购公告随披露节点发布。文档结构多为结构化表格嵌套附注说明，包含设备原值、累计折旧、账面净值、部署数量、使用年限、单台采购成本等字段，单位以人民币万元、台、年为主，部分披露海外业务的设备数据会附带外币折算说明。

## 这些特征在「向量模型与索引」这一环带来什么约束
计算机设备财报的结构化表格占比高，且字段带明确单位，要求索引环节需支持结构化字段与非结构化附注的混合索引，避免单位与数值的语义混淆。季度/年度集中更新的批量数据，要求索引系统支持并发批量处理，同时控制单批次数据量避免超时。临时公告的增量发布，要求索引支持增量同步，不进行全量重建，减少重复计算资源消耗。部分跨币种折算的数据，要求向量模型需适配多单位语义，确保不同币种的设备成本数据可正确关联检索。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunk_size` | `800–1200 字符` | 计算机设备财报的结构化表格行与附注说明长度适中，该区间可完整保留单条设备明细或单段附注的语义完整性 |
| `embedding_model` | `text-embedding-3-small` 或 `bge-large-zh-v1.5` | 支持多字段语义编码，可准确关联设备数值与单位，适配结构化财报的字段特征 |
| `index_batch_size` | `20–30 条/批次` | 单批次数据量适配8c16G无GPU的宿主机资源，避免内存占用过高导致索引失败 |
| `similarity_threshold` | `0.75–0.85` | 计算机设备财报的设备型号、采购成本等字段语义相似度区分度高，该区间可过滤低相关的检索结果 |
| `incremental_index_enable` | `开启` | 适配临时采购公告的增量更新需求，减少全量索引的资源消耗 |
| `parse_structured_table` | `开启` | 计算机设备财报的结构化表格占比高，开启后可提取字段与值的对应关系，提升检索精准度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为PG数据库docker部署下，知识库索引无法建立成功，宿主机为8c16G无GPU虚拟机。原因是索引批量大小设置过高，单批次数据占用内存超过宿主机可用资源，触发内存溢出或进程终止。
- 现象为向量模型调用报错，提示模型返回维度不匹配或调用超时。原因是未单独配置索引模型，使用了通用调用链路，未适配索引模型的专属接口或速率限制。
- 现象为检索结果中出现大量无关的设备型号数据，召回条数不符合预期。原因是相似度阈值设置不合理，或未开启结构化表格解析开关，未区分字段语义关联。

## 怎么确认配好了
- 上传单份计算机设备财报的结构化表格片段，查看解析后的字段列表，确认结构化表格解析开关已生效，设备原值、使用年限等字段被正确提取。
- 发起批量索引测试，使用预设的单批次数据量配置，查看宿主机内存占用情况，确认资源使用符合预期。
- 输入检索词如「服务器采购成本」，查看检索结果的排序与字段匹配度，调整相似度阈值至符合业务需求的区间。
- 上传一份临时采购公告的文件，确认索引系统自动完成增量同步，未触发全量索引重建。
