# 计算机设备财报分析的工具调用与插件

## 这个品类的数据长什么样
计算机设备财报的数据来源包括公开证券交易所披露的定期报告、厂商官方发布的年度/季度财报、行业监测机构的公开数据。更新节奏为季度财报每季度结束后40至50天更新，年度财报在次年3至5月集中更新。单份财报文档通常包含合并财务报表、经营情况讨论与分析、核心业务数据板块，核心业务数据板块包含设备出货量、单台均价、各产品线营收相关字段。营收类字段以人民币元为单位，出货量以台为单位，研发投入以人民币元为单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
计算机设备财报的数据分散来源与多板块结构，要求工具调用插件需支持多数据源API的批量调用，避免单次调用仅获取单份财报的局限。财报集中发布的时间窗口会带来数据请求量激增，需限制工具调用的并发阈值，防止触发接口限流。文档中包含跨品类字段，需在插件中配置字段映射规则，统一不同数据源的字段命名与单位格式。单份财报文档篇幅较长，需配置分段提取的触发条件，仅提取财报分析所需的核心板块，避免冗余数据占用上下文额度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_max_concurrent` | `2–4 并发` | 适配财报发布窗口期的接口限流规则，避免触发调用限制 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份计算机设备财报文档篇幅较长，常规解析耗时超出基础阈值 |
| `plugin_field_mapping` | `按数据源预设映射规则` | 不同公开数据源的字段命名存在差异，需统一映射为分析所需的标准字段 |
| `api_key_auth_mode` | `全局密钥校验` | 多数据源调用需统一权限管理，避免单密钥权限分散的风险 |
| `stream_mode_enable` | `开启` | 适配仅支持流式模式的大模型调用需求，确保实时获取解析数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用工具时返回`{"code":514,"statusText":"unAuthApiKey","message":"common:code_error.e"}`，原因是未正确配置工具调用的API密钥校验规则，或密钥已过期失效。
- 对话日志中未显示传入的`chatId`参数，或全局变量未随工具调用更新，原因是未在工具调用的请求体中正确绑定`chatId`字段，或未开启全局变量的实时同步配置。
- 工具调用返回的财报数据字段缺失或单位混乱，原因是未配置`plugin_field_mapping`规则，导致不同数据源的字段未统一映射。

## 怎么确认配好了
- 发起单次工具调用，检查返回的响应内容与日志记录，确认传入的`chatId`参数已被正确识别与记录。
- 调用仅支持流式模式的大模型，检查工具调用的输出是否为分段流式返回，无完整块阻塞情况。
- 触发多数据源聚合调用，检查返回的字段是否符合预设的`plugin_field_mapping`规则，无命名或单位混乱。
- 模拟高并发请求场景，检查是否触发接口限流或超时错误，调整配置项至符合业务需求。
