# 调味品财报分析的工具调用与插件

## 这个品类的数据长什么样
调味品企业的财报数据主要来源于证券交易所公开披露的定期报告、行业公开调研数据集。更新节奏分为三类：年度报告每12个月更新一次，季度报告每3个月更新一次，渠道动销类数据月度更新。文档结构包含核心经营数据汇总表格、细分品类营收明细、原材料与包装成本构成、渠道分布明细。数据字段包含各细分品类营收总额、原材料采购金额、包装成本金额、线下渠道营收规模、线上渠道营收规模，单位统一为元。

## 这些特征在「工具调用与插件」这一环带来什么约束
调味品财报的多维度结构化数据、多周期更新特性，对工具调用与插件配置提出明确约束。首先，财报包含多品类营收、多成本项的关联表格，工具调用需支持多表关联的SQL生成，避免遗漏细分维度数据。其次，不同周期的数据源需分别配置调用规则，插件需支持按年度、季度、月度的定时拉取任务，避免数据混淆。第三，财报文档存在文本与表格混合的格式，工具调用需支持结构化解析与字段映射，确保提取的字段与预设参数匹配。第四，分散在不同章节的成本与渠道数据，需工具支持跨章节的精准定位提取，保证数据完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 调味品年度财报PDF包含多页图表与明细表格，需足够时长完成完整解析 |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | 完整年度财报的PDF文件通常超过常规文档大小，需支持大文件上传 |
| `SQL_GENERATE_MAX_TABLES` | `8` | 调味品财报包含营收、成本、渠道等多张关联表，限制关联表数量避免生成无效查询 |
| `WORKFLOW_NESTED_KNOWLEDGE_LIMIT` | `3` | 嵌套知识库调用需控制层级，避免因层级过多导致返回空值 |
| `PLUGIN_API_TIMEOUT` | `60 秒` | 第三方大宗商品价格查询插件需覆盖常规响应时长，适配原材料数据调用需求 |
| `RECALL_CHUNK_SIZE` | `1000–1500 字符` | 财报段落包含多字段关联信息，需保证上下文完整性以支持准确的SQL生成 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为调用v4.8.10（不包含）以上版本的API触发工作流，嵌套知识库助手返回空值；原因是未配置`WORKFLOW_NESTED_KNOWLEDGE_LIMIT`参数的合理取值，导致层级超限。
- 现象为生成的SQL查询结果字段缺失，无法匹配财报细分品类明细；原因是未设置`SQL_GENERATE_MAX_TABLES`参数，关联表数量不足，无法覆盖多维度数据。
- 现象为调用插件时返回`You need to use the app key rather than the account key`报错；原因是插件配置中使用了账号密钥，未使用应用密钥，未正确填写`PLUGIN_APP_KEY`参数。

## 怎么确认配好了
- 上传单份年度财报PDF，检查解析后的结构化字段是否包含预设的细分品类、成本项，核对字段映射是否与配置一致。
- 触发定时拉取任务，检查不同周期的数据源是否按预设频次更新，验证插件调用的返回数据完整性。
- 调用测试SQL生成工具，输入财报相关查询指令，检查生成的SQL是否关联了正确的财报表格。
- 模拟插件调用，使用测试密钥替换实际密钥，验证报错信息是否符合预期配置的认证规则。
