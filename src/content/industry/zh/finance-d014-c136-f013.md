# 贵金属财报分析的知识库检索与召回

## 这个品类的数据长什么样
贵金属财报数据主要来自上海黄金交易所、伦敦金银市场协会的公开行业报告，以及涉贵金属业务上市公司的定期公告。更新节奏包含季度、年度定期财报发布，与每日现货交易行情的实时更新。文档结构包含交易品种、交割标准、成交规模、库存数据、政策调整项等模块。字段单位包含克、千克、盎司，计价单位为人民币或美元，部分数据附带报告周期标识。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多来源的数据存在格式与字段命名差异，要求检索环节前置标准化映射逻辑，统一跨源数据的字段标识。混合更新节奏带来的内容更新频率差异，要求知识库支持按业务类型配置增量同步任务，区分定期财报与实时行情的更新周期。多模块多字段的文档结构，要求检索时可按业务核心度配置召回优先级。多样的单位体系要求检索环节自动完成单位归一化匹配，避免因单位差异导致有效内容无法被召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `PARSE_CHUNK_SIZE` | 800–1200 字符 | 贵金属财报包含长文本的业务描述与结构化数据，800–1200字符的分块可保留完整的业务逻辑单元，同时避免单块过长影响检索精度 |
| `RECALL_TOP_N` | 前10条 | 贵金属数据包含多维度的结构化字段与行情数据，10条召回结果可覆盖核心业务指标的关联信息 |
| `SIMILARITY_THRESHOLD` | 0.72–0.80 | 贵金属数据的字段标准化后相似度区分度较高，该区间可过滤低相关的噪声内容，同时保留有效匹配结果 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 上市公司年度财报文档体积较大，500 MB的上限可覆盖多数单份财报文件的上传需求 |
| `SYNC_INCREMENTAL_INTERVAL` | 每1小时 | 贵金属现货行情需高频更新，每1小时的同步间隔可平衡更新及时性与服务器负载 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 大型财报文档的解析耗时较长，300秒的超时设置可避免大文件解析失败 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传贵金属财报文档时返回“Request failed with status code 400”。原因：未配置适配贵金属财报格式的上传校验规则，或文档内包含未归一化的单位字段触发参数校验失败。
- 现象：知识库检索结果精准度不足，无法命中贵金属专属的交易与库存数据。原因：未使用适配贵金属财报的文档模板导入知识库，未指定核心字段的检索优先级。
- 现象：本地知识库对话响应速度过慢。原因：未调整增量同步间隔与召回条数参数，高频同步实时行情数据且召回过多无关内容导致计算负载过高。

## 怎么确认配好了
- 上传一份标准的贵金属财报文档，检查解析后的分块内容是否保留了完整的业务指标与单位信息，根据结果调整分块长度参数。
- 发起一次针对贵金属库存数据的检索，核对返回结果的字段是否包含专属的交易品种与计价单位，根据匹配结果调整相似度阈值。
- 查看知识库的同步日志，确认定期财报与实时行情的更新周期符合预设配置，根据更新频率调整增量同步间隔参数。
- 发起多轮连续检索，观察响应速度是否符合业务需求，根据负载情况调整召回条数参数。
