# 软件开发财报分析的引用来源与溯源

## 这个品类的数据长什么样
软件开发场景下的财报数据，来源为境内外证券交易所披露的公开财报文件，包含PDF格式的公告文档与XBRL结构化文件，同时覆盖企业官方发布的年报、季报及临时财报。数据更新节奏为季度、年度定期更新，部分临时财报随重大事项公告同步发布。文档结构包含合并财务报表、配套附注、管理层讨论与分析模块，字段涵盖核心财务指标、明细会计科目、会计政策说明，单位多以人民币万元、亿元为基准，跨境披露文件还会附带外币折算相关的补充字段。

## 这些特征在「引用来源与溯源」这一环带来什么约束
财报数据兼具结构化与非结构化混合形态，溯源需同时覆盖XBRL结构化节点与PDF非结构化段落的精准定位；定期批量更新的披露文件需关联最新版本的文件标识，避免引用过期数据；多字段层级关联（如研发投入明细关联附注段落）要求溯源支持嵌套引用的来源回溯；公开披露的合规性要求溯源信息需可直接对应至交易所披露的原始文件页码或节点，无法仅依赖模糊的文件名称完成溯源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `recall_source_type` | `["xbrl_node", "pdf_paragraph"]` | 覆盖结构化XBRL数据与非结构化PDF段落的溯源需求，匹配软件开发财报的混合数据形态 |
| `enable_source_trace` | `true` | 财报分析需严格匹配原始披露文件，合规性要求溯源信息完整可查 |
| `source_display_mode` | `"full_path + page_num"` | 软件开发财报的披露文件需明确对应交易所披露路径与页码，满足合规溯源要求 |
| `max_source_context` | `800–1200 字符` | 财报附注段落较长，需保留足够上下文以准确定位引用来源，同时避免冗余信息 |
| `auto_refresh_source_interval` | `90 天` | 公开财报按季度更新，每季度刷新可确保引用源为最新披露版本 |
| `validate_quote_format` | `"strict"` | 财报字段格式要求严格，可拦截不符合格式的变量引用请求，减少报错概率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为API调用返回结果中未携带引用的文件名与路径，原因是未配置`source_display_mode`参数的文件路径展示项，仅返回了匹配的文本内容，未关联原始披露文件的标识信息。
- 现象为知识库变量引用时触发`quote type error`报错，原因是传入的变量格式未匹配财报字段的结构化规则，未使用官方要求的字段引用格式，未校验变量与财报字段的对应关系。
- 现象为下拉菜单仅支持单变量引用，无法选择多个知识库变量，原因是未开启`enable_multi_quote`参数，默认配置限制单次引用的变量数量为1。

## 怎么确认配好了
- 发起包含单个财报字段的测试请求，检查返回结果中是否包含原始文件的路径与页码信息，确认溯源配置生效。
- 传入多个财报相关的变量进行测试，验证是否支持多变量引用，确认`enable_multi_quote`参数配置正确。
- 故意传入格式不符合要求的变量，检查是否触发`quote type error`报错，确认格式校验配置生效。
- 调整配置界面的引用展示选项，验证是否可以按需隐藏或展示知识库引用信息。
