# 通信服务财报分析的引用来源与溯源

## 这个品类的数据长什么样
通信服务财报的数据来源包括境内外证券交易所公开披露的定期报告、公司官网投资者关系板块发布的公告。更新节奏为每季度终了后1至2个月发布季度经营报告，年度终了后4个月内发布年度财务报告，重大业务变动时同步发布临时公告。文档结构包含合并财务报表、分业务营收明细、移动通信用户规模、ARPU值等字段，单位多为人民币亿元、万户、元/户等。单份文档篇幅较长，部分年度财报可达数十页。

## 这些特征在「引用来源与溯源」这一环带来什么约束
通信服务财报的数据来源分散，需同时校验证券交易所公开文件与公司官网公告的一致性，避免溯源信息出现偏差。季度与临时公告更新频率较高，需支持增量同步与实时溯源校验，确保返回的引用内容为最新版本。财报包含ARPU值、用户规模等专属业务字段，需配置字段级精准匹配规则，避免召回不相关的通用财务数据。单份文档篇幅较长，需实现段落级的引用定位，避免仅返回整页文档作为溯源内容，提升引用的精准性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `recall_top_k` | 前8-12条 | 通信服务财报包含多业务板块数据，需召回足够条目覆盖细分业务的营收、用户等信息 |
| `source_field_match` | 开启字段级匹配 | 财报包含ARPU值、用户规模等专属业务字段，需精准匹配字段名，不能仅依赖关键词匹配 |
| `paragraph_cut_length` | 800-1200字符 | 单份财报文档篇幅较长，该分段长度可保留完整的业务数据段落，避免截断关键信息 |
| `sync_incremental` | 按季度+临时事件触发 | 财报更新以季度报、年报及临时公告为主，增量同步可降低系统资源消耗，提升更新效率 |
| `source_citation_format` | `{company_name}_{report_type}_{publish_date}_{section_name}` | 统一溯源标识格式，便于快速定位具体财报章节与对应业务板块 |
| `timeout` | 600秒 | 单份长文档的解析与溯源需处理多字段与复杂业务数据，预留足够的处理时间 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：召回了财报源数据，但返回结果未附带溯源链接或统一格式的标识信息。原因：未开启`source_citation_format`配置项，或未配置`recall_top_k`的最小召回条数，导致溯源信息被系统自动截断。
- 现象：知识库问答返回结果与知识库原文不符，出现非原文的生成内容。原因：未开启`source_field_match`配置，未强制匹配专属业务字段，导致召回了不相关的财报段落，未召回目标业务板块的数据。
- 现象：解析财报时出现`504 Gateway Timeout`错误。原因：未将`timeout`配置项调整至符合当前文档处理的时长，长文档解析未预留足够的处理时间。

## 怎么确认配好了
- 上传单份通信服务季度财报文档，执行一次财报分析查询，检查返回结果是否附带统一格式的溯源标识。
- 输入包含ARPU值的查询语句，检查召回结果是否精准匹配该业务字段，未混入其他品类的财报数据。
- 提交多份不同发布时间的财报文档，检查增量同步任务是否仅更新新增或修改的文档，未重复同步历史数据。
- 查看系统日志，确认解析长文档时未出现超时错误，`timeout`配置项符合当前文档处理的实际需求。
