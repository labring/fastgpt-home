# 通信设备财报分析的知识库检索与召回

## 这个品类的数据长什么样
通信设备行业的财报数据主要来源于上海证券交易所、深圳证券交易所的公开披露平台，以及上市公司官方投资者关系页面。更新节奏分为定期与实时两类，季度报告于季度结束后45天内发布，年度报告于年度结束后120天内发布，重大事项相关的临时公告随事件实时更新。文档结构固定，包含财务报表正文、经营数据明细、业务板块分析等模块，字段涵盖营业收入、归母净利润、基站出货量、研发投入等，单位包含亿元、万站等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源的数据来源要求检索系统支持跨平台的数据源接入与统一解析；差异化的更新节奏需要配置灵活的增量更新机制，兼顾定期财报与临时公告的实时性需求；固定但多模块的文档结构要求检索结果精准匹配业务板块，避免跨板块的无效匹配；多样的单位与字段类型要求配置字段级的过滤规则，防止单位混淆导致的检索偏差；单篇文档的较大体量要求合理的分块与上下文保留策略，确保关键信息不被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `分段长度` | 800–1200 字符 | 通信设备财报包含多组关联的财务与业务数据，该长度可平衡上下文完整性与分块粒度 |
| `召回条数` | 10–15 条 | 财报分板块数据较多，需覆盖运营商、企业、消费者等多个业务模块的检索结果 |
| `相似度阈值` | 0.72–0.85 | 财报内容专业性强，该区间可过滤低相关的非核心内容，保留细分业务的匹配结果 |
| `重排返回条数` | 5–8 条 | 大模型上下文窗口有限，该取值可保留最相关的核心财报数据，避免冗余信息干扰 |
| `maxContext` | 8000–12000 字符 | 适配通信设备财报的多模块组合内容，确保大模型可获取完整的业务与财务上下文 |
| `增量更新周期` | 1 天，集中发布期可调整为 6 小时 | 兼顾常规更新效率与季度报告、临时公告的实时性需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：开启Rerank模型并完成知识库索引后，在线召回测试结果未应用重排逻辑，返回结果与基础召回一致。原因：未在知识库搜索配置中开启「启用重排」开关，或重排模型未绑定至当前应用的检索节点。
- 现象：将`maxContext`设置为3000字符以上时，大模型接收的上下文为空或内容被截断。原因：配置的`maxContext`超出了当前绑定大模型的上下文窗口上限，或未同步更新应用的上下文限制参数。
- 现象：升级至4.9.0版本后，设置分块重复率阈值或召回文件数后未生效。原因：4.9.0版本中知识库配置的缓存机制未及时同步生效，需重新保存配置项。

## 怎么确认配好了
- 进入知识库的解析设置页面，核对`分段长度`、`分段重复率阈值`的配置，查看解析日志确认分块结果符合业务模块的划分逻辑。
- 进入应用的搜索配置页面，核对`召回条数`、`相似度阈值`、`重排返回条数`的配置，发起在线召回测试，对比重排前后的结果排序差异。
- 调整`maxContext`参数后，查看大模型返回的内容是否包含完整的财报数据片段，确认上下文未被异常截断。
- 进入增量更新配置页面，核对`增量更新周期`的设置，上传测试文件后查看索引更新状态是否正常。
