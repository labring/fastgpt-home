# 酒店餐饮财报分析的引用来源与溯源

## 这个品类的数据长什么样
酒店餐饮财报数据主要来自门店POS交易系统、供应链库存台账、月度营业汇总表及公开工商披露信息。数据更新节奏按核算周期区分，门店级交易数据按日更新，月度/季度财报数据按自然周期滞后3-7个工作日更新。单份文档多为结构化表格形式，包含营收分类、人力成本、食材损耗、坪效、客单价等字段，单位多为元、人次、平方米，部分跨门店汇总文档会附带区域营收明细条目。

## 这些特征在「引用来源与溯源」这一环带来什么约束
酒店餐饮财报数据的分散结构化特征，要求引用溯源环节需精准匹配文档对应的核算周期与门店范围，避免跨周期、跨门店的数据混淆。高频更新的交易类数据，要求溯源时优先召回近7个工作日内的文档，确保数据时效性。多维度的成本与营收字段，要求溯源环节附带字段名与单位标注，防止不同品类的成本项被错误关联。此外，跨门店汇总文档的明细条目较多，需在溯源时明确标注文档的汇总维度，避免溯源信息误导用户。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `RECALL_TOP_K` | `前6-8条` | 酒店餐饮财报包含多维度字段，需足够召回量覆盖营收、成本等多类数据，同时避免冗余结果干扰 |
| `MAX_DOC_AGE` | `7 天` | 门店级交易数据日更，月度财报数据滞后不超过7个工作日，超过该时间的文档不再纳入召回范围 |
| `CHUNK_SIZE` | `800-1200 字符` | 酒店餐饮财报单份文档包含多组明细条目，分段长度需覆盖完整的成本或营收组，避免拆分断裂 |
| `PARSE_FIELD_MAPPING` | `按「营收/成本/坪效/客单价」映射标准字段` | 酒店餐饮财报存在自定义字段，需统一映射后确保溯源时的字段一致性 |
| `SIMILARITY_THRESHOLD` | `0.75-0.85` | 多维度字段易出现语义相似但实际不同的情况，需提高阈值过滤无关召回结果 |
| `CITE_FORMAT` | `保留核算周期与门店标签` | 需在溯源中明确数据的时间与范围，避免跨周期、跨门店的数据混淆 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上下文引用模块展示的文档片段仅显示纯文本，无法还原财报表格的Markdown格式。原因：未开启文档解析的Markdown渲染开关，或知识库上传时未启用格式解析配置，导致结构化财报的表格结构被扁平化处理。
- 现象：针对特定财报维度的提问无法召回对应文档，召回结果条数为0。原因：未配置`PARSE_FIELD_MAPPING`字段映射规则，导致自定义的食材成本、坪效等字段无法被检索逻辑识别，或`MAX_DOC_AGE`设置过短，遗漏了滞后更新的月度财报文档。
- 现象：引用来源未标注对应门店或核算周期，无法确认数据的适用范围。原因：未在溯源配置中添加元数据提取规则，未将门店、核算周期等字段纳入引用展示项，导致溯源信息缺失。

## 怎么确认配好了
- 上传一份标准酒店餐饮月度财报文档，进入知识库解析预览页，确认解析后的分段是否保留了营收、成本等字段的结构化展示。
- 发起包含特定门店名称与核算周期的提问，检查召回结果的文档来源是否匹配查询条件。
- 查看回答下方的引用来源模块，确认是否标注了核算周期、门店范围等元信息，且表格格式正确展示。
- 修改召回条数与相似度阈值配置，验证召回结果的数量是否随配置调整发生对应变化。
