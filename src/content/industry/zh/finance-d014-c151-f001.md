# 铁路公路财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
铁路公路财报与运营数据主要来源于公开交通运输行业统计公报、铁路运输企业年度/半年度财报、公路运营主体的月度运营简报。更新节奏分为两类：月度路网客货运运营数据每月5日前更新，年度完整财报于次年4月前发布。数据文档结构包含路网运营规模、客货运周转量、主营业务收支、资产折旧明细等模块，字段单位多为“万人公里”“万吨公里”“万元”“公里”，部分字段需关联路网等级、运营主体类型等分类标识。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
月度高频更新的运营数据要求HTTP接口支持定时调度拉取的配置项，且接口超时阈值需适配批量数据传输。多维度、多单位的字段结构要求接口参数增加维度筛选与单位校验字段，避免不同路网类型的数据混淆。嵌套式的财报明细字段需要外部系统支持多层级解析映射，仅拉取一级字段会丢失核心分析数据。部分数据按国铁/地方铁路、高速公路/普通公路分类，接口需支持维度筛选参数，否则返回数据冗余且无法精准匹配分析需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `external_data_sync_interval` | `86400 秒` | 适配月度财报的更新节奏，避免频繁拉取占用系统资源 |
| `api_request_timeout` | `300 秒` | 适配批量月度运营数据的传输时长，防止拉取过程中超时中断 |
| `field_unit_validation` | `开启` | 铁路公路数据包含多单位字段，开启校验可避免解析错误 |
| `nested_parse_max_depth` | `3 层` | 财报明细字段多为3层嵌套，适配完整提取核心分析字段 |
| `allowed_dimension_filters` | `["rail_type", "highway_class"]` | 区分国铁/地方铁路、高速/普通公路，精准筛选目标数据 |
| `model_api_base_path` | `http://localhost:8000/v1` | 适配本地部署的向量模型，按要求添加/v1路径前缀 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用模型返回500状态码，日志显示“invalid api path”。原因：未在配置中添加/v1路径前缀，或错误将模型API地址配置在废弃的配置文件，未配置在页面配置项。
- 现象：外部拉取的财报数据部分字段为空。原因：未配置维度筛选参数，拉取了全量冗余数据导致部分字段被系统自动截断。
- 现象：数据同步任务频繁中断。原因：将`api_request_timeout`设置为过低的取值，无法适配批量月度数据的传输时长。

## 怎么确认配好了
- 调用测试接口，检查返回数据的单位字段是否与预期一致，根据实际数据调整`field_unit_validation`的配置。
- 查看同步日志，确认最近一次数据拉取成功且无字段解析错误，根据日志中的超时提示调整`api_request_timeout`。
- 测试模型调用，确认返回结果包含财报分析的核心字段，根据模型响应调整`nested_parse_max_depth`。
- 检查部署版本是否为4.8.20及以上，确认模型API地址已在页面配置，未配置在废弃文件，按官方指引添加/v1路径前缀。
