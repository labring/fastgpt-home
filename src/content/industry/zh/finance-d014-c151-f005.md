# 铁路公路财报分析的多轮对话与提示词

## 这个品类的数据长什么样
铁路公路运营主体的财报数据，来源为运营主体官方披露的定期公告、路网运营统计数据。更新节奏为每季度、每年度，正式文档多为PDF格式。文档结构包含核心经营指标、成本构成、现金流、路网运营数据等模块，字段涵盖客运量、货运周转量、路网里程、单位运营成本等，单位多采用人次、万吨公里、元/车公里等专属计量标准。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
财报数据来源分散，需同时覆盖企业内部财报与公开路网运营数据，多轮对话需先引导用户明确数据主体与报告周期，避免混淆不同统计口径。单份文档长度较长，多轮对话需支持分段召回，提示词需指定提取特定字段，防止遗漏关键运营数据。字段单位具有特殊性，提示词需强制校验单位一致性，避免出现数值与单位不匹配的结果。固定更新节奏支持预设时间范围参数，多轮对话可快速定位用户所需的报告周期。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 字符 | 铁路公路财报单份核心章节长度多在5000-10000字符，该取值可完整覆盖关键数据，避免截断重要信息 |
| `recall_top_k` | 前6–8 条 | 财报数据字段分散，需召回足够分段覆盖营收、成本、运营指标等模块，同时控制冗余信息 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 单份PDF格式财报包含表格与图表，解析耗时较长，该取值可覆盖多数正常解析场景 |
| `system_prompt_template` | 按「先明确数据来源与周期，再逐步回答，返回结果标注对应字段单位」自定义 | 铁路公路财报字段单位具有特殊性，需强制提示词校验单位一致性，避免混淆计量标准 |
| `TOOL_CALL_MAX_RETRIES` | 2 次 | 数据库调用可能因网络波动或SQL语法错误失败，重试可减少对话中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用MySQL数据库工具时返回400 status code (no body)。原因：未正确配置数据库连接的字段映射，导致SQL语句无法匹配铁路公路财报的专属字段（如货运周转量）。
- 现象：对话界面中表单节点显示格式不符合预期。原因：未将表单节点输入项与财报专属字段（如客运量、路网里程）绑定，导致系统无法识别对应数据类型。
- 现象：工作流中无法在新对话加载历史全局变量。原因：未开启全局变量的对话持久化配置，且未在提示词中指定加载历史变量的触发条件，导致变量仅在当前对话生命周期内留存。

## 怎么确认配好了
- 上传单份铁路公路财报文档，发起对话测试，核对系统是否能正确提取指定字段并标注对应单位。
- 发起多轮对话，依次询问不同周期的运营数据，核对系统是否保留历史上下文并逐步细化回答。
- 配置MySQL工具调用节点，输入模拟的财报查询语句，核对工具是否正常返回数据，无400状态码报错。
- 发布免登录链接，删除对话后核对后台日志是否保留操作记录，确认日志留存配置生效。
