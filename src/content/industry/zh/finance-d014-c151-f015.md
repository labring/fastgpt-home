# 铁路公路财报分析的部署与升级

## 这个品类的数据长什么样
铁路公路财报数据主要来自交通运输企业公开披露的年度、半年度财报，以及交通运输主管部门发布的行业统计公报。更新节奏按季度与年度划分，季度财报基于月度运营数据汇总，年度财报覆盖完整财年。文档通常包含总营收、分路段周转量、维保成本、资产折旧等明细模块，字段涵盖总货运/客运周转量、通行费营收、线路里程、单位里程维保成本等，单位多为百万吨公里、人民币元、公里等。

## 这些特征在「部署与升级」这一环带来什么约束
由于铁路公路财报包含多路段的细分运营数据，单份文件体积通常较大，需调整上传与解析的资源配置。字段类型与单位多样，需预设统一转换规则避免分析偏差。财报按季度、年度更新，需配置定时同步任务适配更新节奏。不同运营主体或部门的分析权限需细粒度管控，避免数据泄露。升级过程中需保留原有同步配置与权限规则，避免重置后需重新配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | 1000–1500 MB | 铁路公路财报常包含多路段明细附件，单文件体积超出通用平台默认上限 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 秒 | 大体积财报文件的文本解析与结构化处理需更长时间，避免中途中断 |
| `SYNC_CRON_EXPRESSION` | 0 0 2 * * * | 适配季度财报月度汇总的更新节奏，每日凌晨2点执行同步，不影响业务时段 |
| `FIELD_UNIT_CONVERT` | 按预设规则统一转换 | 财报中存在百万吨公里、元/公里等多单位字段，需转换为标准分析单位 |
| `MULTI_TENANT_ENABLE` | 开启 | 支持不同部门账号分别访问对应权限范围内的财报数据，符合权限管控需求 |
| `RETRIEVE_TOP_K` | 前8–12条 | 财报字段维度较多，需召回足够数量的相关文本片段完成精准分析 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：私有部署后无法创建多账号，登录界面仅显示微信扫码选项。原因：未开启`MULTI_TENANT_ENABLE`配置项，系统默认关闭多账号权限管理功能。
- 现象：上传铁路公路财报文件后解析失败，控制台返回`413 Request Entity Too Large`错误。原因：未调整`UPLOAD_FILE_MAX_SIZE`参数，默认配置无法承载大体积财报附件。
- 现象：本地部署后上传财报文件无响应，分析结果为空。原因：未设置`PARSE_FILE_TIMEOUT_SECONDS`为合理时长，大文件解析超时后未触发异常重试机制。

## 怎么确认配好了
- 上传单份体积超过500MB的铁路公路财报附件，检查上传进度是否正常完成，无报错提示。
- 手动触发一次定时同步任务，查看系统日志确认已拉取最新的财报数据，无同步失败记录。
- 创建两个不同权限的账号，验证是否仅能访问各自权限范围内的财报分析结果。
- 查看结构化解析后的字段列表，确认单位已按预设规则完成统一转换，无单位混乱情况。
