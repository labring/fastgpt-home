# 鞋类财报分析的工具调用与插件

## 这个品类的数据长什么样
鞋类财报数据主要来源于境内外证券交易所公开披露的上市公司财报、品牌方官方发布的季度/年度经营公告，以及行业零售监测数据库。更新节奏为季度财报每3个月更新一次，年度财报每年更新一次，零售端细分数据按月更新。文档结构包含合并财务报表的核心拆分项，以及鞋类品类营收明细、渠道营收金额、库存周转天数、供应链成本明细等字段，单位以人民币元、天数为基准，无标准化的统一格式模板，不同品牌披露字段存在差异。

## 这些特征在「工具调用与插件」这一环带来什么约束
鞋类财报的多源异构数据特征，要求工具调用插件预设多套字段映射规则，适配不同品牌披露的差异化字段命名。不同周期的数据更新节奏差异，要求插件支持按季度、月度动态切换数据拉取范围，避免加载未更新或过期的数据集。品类细分多且文档结构不统一的特点，要求插件集成自定义字段解析逻辑，无法依赖固定的字段提取模板。同时，部分营收明细需从非结构化的公告文本中提取，插件需要集成轻量的文本结构化解析能力，保障数据提取的准确性。另外，鞋类场景下需支持按品类维度筛选数据的参数配置，适配细分分析需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| :--- | :--- | :--- |
| `plugin_field_mapping_strategy` | `custom_multi_source` | 鞋类品牌财报字段命名差异大，需针对不同数据源配置自定义映射规则 |
| `data_fetch_time_range` | `last_3_quarters, last_1_year` | 鞋类财报分析需兼顾短期季度数据与长期年度趋势，支持多周期拉取 |
| `tool_call_timeout` | `600 秒` | 财报数据拉取和结构化解析耗时较长，需设置足够的超时时间避免调用中断 |
| `max_tool_call_retries` | `3 次` | 财报数据接口可能存在临时波动，合理重试次数保障调用成功率 |
| `stream_response_enabled` | `true` | 单份财报数据量较大，流式返回可提升分析响应速度，避免超时 |
| `field_extraction_threshold` | `0.75–0.90` | 需匹配字段提取的置信度区间，平衡提取准确性与召回率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：V4.12.3版本调用工具时频繁出现`500 Bad Gateway`报错。原因：该版本的插件调用链路存在未修复的超时处理漏洞，无法适配长耗时的财报数据拉取。
- 现象：V4.9.6版本部署的工具调用插件，采用SSE协议封装的接口无法被识别，提示仅支持stdio进程。原因：该版本未集成SSE协议的插件适配逻辑，仅支持stdio类型的插件调用。
- 现象：开启`stream_response_enabled`为`true`时，仅接收部分分段结果，无法获取完整的最终分析输出。原因：未配置流式结果的聚合逻辑，未按协议拼接分段返回的数据流。
- 现象：私有部署V4.14.1版本导入插件时提示`internal server error`。原因：插件配置的接口地址未添加至系统白名单，或插件依赖的环境变量未正确加载。

## 怎么确认配好了
- 手动触发单份鞋类财报的工具调用，查看返回结果是否包含预设的品类营收、库存周转等字段，确认字段映射规则生效。
- 查看插件调用日志，确认数据拉取的时间范围与配置的参数一致，未加载非目标周期的数据集。
- 开启流式响应模式，验证分段返回的数据流可被完整拼接，无内容缺失。
- 调整工具调用重试次数，模拟接口临时波动场景，确认重试逻辑正常执行。
