# 饰品财报分析的工作流编排

## 这个品类的数据长什么样
饰品品类的财报与行业数据主要来自境内外证券交易所公开披露的上市纺织服饰企业定期报告，以及行业监测机构发布的终端零售监测数据。数据更新节奏匹配行业披露规则，定期报告按季度、半年度、年度固定周期发布，零售监测数据多为周度更新。上市财报文档包含营收构成、存货明细、供应链成本等结构化章节，零售监测数据则按门店类型、产品细分维度拆分。字段包含直营门店营收、加盟营收、存货周转天数、单位克重饰品出货量等，单位多为人民币元、件、克、天。

## 这些特征在「工作流编排」这一环带来什么约束
饰品品类的数据特征对工作流编排带来多重约束。首先，固定周期的披露要求需要工作流配置匹配的定时触发节点，确保在数据更新后第一时间拉取并分析。其次，特有的非通用财务字段如单位克重出货量，需要在数据清洗环节配置专属的字段映射规则，避免与通用财务字段混淆。另外，多维度的细分数据需要拆分多个解析节点处理，防止单节点负载过高导致解析失败。最后，不同来源的数据格式差异，需要工作流适配PDF、结构化表格等多种格式的解析配置，确保数据完整提取。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `定时触发规则` | `0 0 2 * * 1, 0 0 2 1 */3 *` | 分别适配周度零售数据拉取和季度财报披露窗口，匹配饰品行业数据更新节奏 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 饰品财报包含多页存货明细与营收拆分表格，设置较长超时避免解析中断 |
| `FIELD_MAPPING_RULES` | `映射「直营门店出货量」为`shop_sales`、「单位克重」为`unit_weight` | 匹配饰品财报特有的非通用财务字段，避免数据清洗错误 |
| `API_VAR_ASSIGN_METHOD` | `通过请求参数传入` | 支持动态指定财报报告期，适配不同周期的分析需求 |
| `INTERACTIVE_NODE_STATUS` | `开启` | 允许插入人工校验节点，排查饰品存货数据的异常波动 |
| `WORKFLOW_EXPORT_TYPE` | `JSON + Markdown` | 同时输出结构化数据与可读性报告，适配不同使用场景 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用API触发工作流后，全局变量未被正确赋值，返回状态码400。原因：未按要求配置全局变量的赋值方式，未将目标参数传入指定的请求字段。
- 现象：工作流运行时未触发交互节点，直接完成流程。原因：未开启交互节点的启用开关，或未配置触发交互的触发条件。
- 现象：导出的工作流文件无法在其他项目中导入，或缺失部分配置项。原因：导出时未选择包含关联工具与变量的完整格式，仅导出了流程骨架。

## 怎么确认配好了
- 测试触发工作流，检查拉取的数据是否包含饰品品类特有的字段，如单位克重出货量，核对字段映射是否正确。
- 手动触发定时任务，验证是否按预设规则在指定时间拉取数据，确认定时触发配置生效。
- 调用API传入测试变量，检查全局变量是否被正确加载到工作流节点中，确认赋值逻辑正常。
- 导出工作流文件，导入至测试项目，验证所有配置项是否完整保留，确认导出格式正确。
