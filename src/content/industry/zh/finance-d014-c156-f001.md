# 黑色家电财报分析的HTTP 接口与外部系统

## 这个品类的数据长什么样
黑色家电财报分析的数据主要来自上市家电企业公开季度/年度财报公告、行业监测机构的整机出货监测数据，以及线下零售终端的销售上报数据。财报数据按自然季度更新，行业监测数据为周度更新，零售数据为日度更新。单份数据文档包含企业标识、报告周期、总出货量（单位：万台）、主营业务营收（单位：亿元）、线上渠道营收占比（数值范围0至1）、核心单品均价（单位：元/台）等结构化字段，附带PDF格式的原始财报扫描件作为附件。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
黑色家电财报数据的多源异构特征，要求HTTP接口支持差异化拉取策略：财报数据按季度轮询，行业监测数据按周度轮询，零售数据按小时级轮询。单份数据附带PDF格式的原始财报附件，要求接口支持大文件传输与解析，需预留足够的超时时间与文件大小上限。结构化字段需关联企业标识、报告周期等维度，要求接口支持多维度参数过滤，避免跨数据源的字段映射冲突。高频的日度零售数据请求，需配置接口限流规则，防止外部系统因请求过载出现异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 黑色家电单份财报PDF通常为500-1500 MB，预留足够空间覆盖常规文件体积 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1200 秒` | 大体积PDF解析耗时较长，避免中途中断导致任务失败 |
| `API_COLLECTION_REQUEST_TIMEOUT` | `600 秒` | 跨数据源关联查询需等待多接口返回，需足够超时时间保障完整获取数据 |
| `RATE_LIMIT_QPS` | `50` | 日度零售数据产生高频请求，设置合理限流阈值防止外部系统过载 |
| `MULTI_SOURCE_SYNC_INTERVAL` | 按数据源分类配置：财报数据`86400 秒`、行业数据`604800 秒`、零售数据`3600 秒` | 匹配不同数据源的更新频率，避免无效拉取或数据滞后 |
| `API_VALIDATE_PARAMS` | `启用` | 黑色家电字段包含多维度关联标识，严格校验参数合法性避免映射错误 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用`apiCollection`接口返回`message: Invalid URL, code: 500`报错。原因是未正确配置黑色家电数据源的完整API路径，或URL包含未转义的特殊字符导致解析失败。
- 接口返回`Multimodal file size is [超出阈值]`报错。原因是未将`UPLOAD_FILE_MAX_SIZE`配置为适配黑色家电财报PDF的体积，导致大文件上传被拦截。
- MongoDB副本集主节点漂移后，数据同步任务断连无法自动重连。原因是未配置MongoDB Change Streams的重连参数，或超时阈值设置过短导致连接中断后无法恢复。

## 怎么确认配好了
- 上传一份典型的黑色家电财报PDF文件，检查文件上传进度与解析结果是否正常，确认`UPLOAD_FILE_MAX_SIZE`配置符合实际文件体积。
- 调用`apiCollection`接口拉取黑色家电的零售数据，检查返回结果的字段完整性与关联正确性，确认`API_VALIDATE_PARAMS`配置生效。
- 模拟MongoDB副本集主节点切换，检查数据同步任务是否自动重连，确认Change Streams的重连参数配置合理。
- 配置高频请求模拟工具，向接口发送对应QPS的请求，检查接口是否触发限流，确认`RATE_LIMIT_QPS`配置符合实际业务需求。
