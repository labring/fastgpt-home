# 征信报告风控的工作流编排

## 这个品类的数据长什么样
征信报告数据主要来自央行征信中心、地方征信运营机构及合作征信服务方。更新节奏为固定周期同步，单次报告文档结构包含身份核验区、信贷交易明细模块、公共信息记录区、查询历史清单四大板块。字段包含个人/企业标识字段、信贷余额（单位为元）、逾期期数（单位为次）、查询时间（格式为YYYY-MM-DD HH:MM）等，部分字段存在嵌套层级，如信贷交易明细下分多笔贷款条目，整体文档长度随报告覆盖的信贷记录数量浮动。

## 这些特征在「工作流编排」这一环带来什么约束
征信报告的多源接入、嵌套字段结构、固定格式要求，会对工作流编排带来三类约束。第一，需配置多源适配节点，兼容央行征信中心、地方征信平台等不同数据源的输出格式差异；第二，因字段存在多层嵌套，需设置层级提取规则，精准定位信贷余额、逾期记录等核心风控字段；第三，固定的更新周期要求工作流绑定定时触发规则，按同步节奏批量拉取并处理报告，同时需配置长文档拆分节点，避免单节点处理超大文件超时。另外，字段的单位与格式约束，要求工作流中嵌入格式校验环节，过滤不符合规范的异常数据，保障后续风控逻辑的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300–600 秒` | 征信报告单文件常包含多页信贷明细，解析耗时较长，需适配长文档解析需求 |
| `WORKFLOW_NODE_CONCURRENCY` | `20–50 并发` | 单节点硬件配置为4c16g时，该并发区间可避免资源耗尽，符合社区常见实测结果 |
| `JSON_PARSE_STRICT_MODE` | `开启` | 征信报告字段格式固定，严格模式可过滤格式异常的嵌套JSON字段，提升数据准确性 |
| `WORKFLOW_API_AUTH_TYPE` | `API_KEY 鉴权` | 通过API访问工作流时，API_KEY鉴权可保障授信审核流程的访问安全，符合风控场景的权限要求 |
| `INPUT_JSON_SCHEMA_VALIDATION` | `启用` | JSON输入框需校验输入格式，匹配征信报告解析后的字段结构，避免无效数据流入工作流 |
| `FILE_UPLOAD_MAX_SIZE` | `10–20 MB` | 单份征信报告扫描件或电子档通常不超过20MB，该区间可覆盖常规报告大小，同时避免占用过多存储资源 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：单节点运行工作流时出现OOM报错或服务无响应，状态码返回503。原因：未根据硬件配置调整`WORKFLOW_NODE_CONCURRENCY`参数，并发数设置过高导致资源耗尽。
- 现象：通过API调用发布的工作流返回401或403报错，无法正常拉取征信报告数据。原因：未配置`WORKFLOW_API_AUTH_TYPE`的鉴权参数，或鉴权密钥未正确绑定至工作流发布渠道。
- 现象：JSON输入框中无法选择解析后的征信报告字段变量，流程运行时出现字段为空的报错。原因：未启用`INPUT_JSON_SCHEMA_VALIDATION`，未将变量结构与征信报告字段映射绑定，导致输入框无法识别可选变量。

## 怎么确认配好了
- 运行单份测试征信报告，核对解析后的字段是否与原始报告一致，确认配置的解析超时与文件大小阈值覆盖测试文件的实际情况。
- 模拟多并发请求，观察节点资源占用情况，确认并发配置符合当前硬件的负载承载能力。
- 调用API访问工作流，核对鉴权参数是否生效，确认返回结果包含预期的征信报告处理字段。
- 配置JSON输入框的变量映射，尝试选择预设的征信报告字段，确认输入框可正常加载可选变量列表。
- 查找官方社区渠道的共享工作流交流群组，获取同场景的配置参考。
