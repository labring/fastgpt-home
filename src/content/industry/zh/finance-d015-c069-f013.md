# 担保材料风控的知识库检索与召回

## 这个品类的数据长什么样
担保材料的数据来源包括线下纸质扫描件、电子签约平台导出的合同文件、担保机构内部台账导出的结构化数据。更新节奏为随单笔授信业务提交触发，存量材料仅在担保关系变更时更新。文档结构包含结构化字段与非结构化条款文本两类，结构化字段包括担保金额、抵押物坐落地址、保证人统一社会信用代码、公证编号等，非结构化内容多为担保协议的合规条款。字段单位涉及货币单位、时间周期、地址编码等，部分字段需关联外部核验编号。

## 这些特征在「知识库检索与召回」这一环带来什么约束
混合的结构化与非结构化内容要求检索同时支持语义匹配与字段精准匹配，避免仅依赖语义召回遗漏关键合规条款。单笔触发的更新节奏要求知识库支持增量同步，以适配风控审核的实时性需求。长文本条款与结构化字段并存的结构，要求分段解析时保留上下文完整性，避免拆分后丢失条款的逻辑关联。强校验字段的存在，要求检索环节需同时校验语义相关性与字段匹配度，确保召回结果符合担保业务的合规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前10条` | 担保材料单条文档长度差异大，需保留足够候选范围覆盖结构化字段与条款文本 |
| `相似度阈值` | `0.72–0.85` | 需平衡语义匹配精度与结构化字段的关联召回，避免阈值过高遗漏合规性相关的条款内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 担保材料可能包含多页扫描件或长合同，需预留足够的解析时间 |
| `分段长度` | `800–1200 字符` | 兼顾担保协议条款的上下文完整性与检索精度，避免过短导致语义断裂 |
| `增量同步触发规则` | `按文件上传/更新事件触发` | 匹配担保材料随单笔业务更新的节奏，避免全量同步占用资源 |
| `结构化字段召回开关` | `开启` | 担保材料包含大量需精准匹配的字段，需启用结构化检索能力辅助语义召回 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：导入外部链接格式的担保材料文档时返回导入失败。原因：担保材料多包含结构化元数据与合规条款文本，微信公众号链接导出的内容未保留结构化字段结构，无法被正确解析。
- 现象：提问要求匹配3项担保合规条件时，返回结果仅覆盖部分条件。原因：未开启`结构化字段召回开关`，仅依赖语义召回无法精准匹配字段类约束条件。
- 现象：启用知识库关联后，风控审核接口返回418状态码。原因：未正确配置`结构化字段映射`规则，导致检索时字段校验不通过。

## 怎么确认配好了
- 上传单份典型担保材料文档，查看解析后的文本与结构化字段是否完整匹配源文件内容。
- 构造包含结构化字段约束与语义条件的测试提问，验证召回结果是否同时覆盖两类匹配要求。
- 触发单笔担保材料的增量同步操作，确认知识库更新状态为成功且无报错日志。
- 调用检索接口传入预设的担保合规条件，检查返回结果是否包含符合条件的文档条目。
