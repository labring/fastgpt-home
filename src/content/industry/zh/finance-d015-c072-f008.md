# 授信申请风控的工具调用与插件

## 这个品类的数据长什么样
授信申请场景的数据主要来自申请人主动提交的结构化凭证与非结构化扫描件，以及对接的第三方合规接口。结构化数据包含身份标识、月收入、社保缴纳基数等字段，单位分别为身份证号（无单位）、元、月；非结构化数据多为PDF格式的银行流水、资产证明文件。数据更新节奏为单条申请数据仅在提交时生成并更新一次，复审场景下仅在触发复审流程时重新拉取最新数据。文档结构以单条申请为单位，整合结构化字段与对应附件文件，无批量聚合的默认数据结构。

## 这些特征在「工具调用与插件」这一环带来什么约束
结构化字段的格式合规性要求高，需通过专用工具插件完成格式校验与字段提取，避免无效数据进入审核流程。非结构化附件的解析耗时较长，需配置合理的超时参数保障解析完成。单条申请的工具调用需在单次会话内完成多步骤链路（如征信查询、流水解析、收入核算），无法依赖跨会话的历史数据。同时，数据隐私合规要求需在工具调用环节完成敏感信息脱敏，避免申请人数据泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxToolCallsPerSession` | `3–5 次` | 授信申请需调用征信查询、流水OCR、收入核算等核心工具，3-5次可覆盖完整审核链路且避免超时 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120–180 秒` | 银行流水、资产证明等PDF文件解析需较长时间，该区间可适配多数常规文件的解析需求 |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | 授信申请提交的单份证明文件通常不超过100MB，该取值可覆盖常规提交场景 |
| `similarityThreshold` | `0.75–0.85` | 需精准匹配授信规则相关的知识库内容，该区间可过滤无关召回同时保留有效关联内容 |
| `toolCallRetryTimes` | `2 次` | 第三方工具接口可能因网络波动出现临时失败，重试2次可提升成功率且不增加整体超时风险 |
| `pluginWhiteList` | `["征信查询插件","流水OCR插件","收入核算插件","数据脱敏插件"]` | 授信场景仅需合规专用插件，白名单配置可避免无关插件调用引发的合规风险 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：Docker部署4.8.21版本时，上传知识库文件开始解析后日志持续报`slow operation xxxxms`，且MongoDB响应正常。原因：未配置`PARSE_FILE_TIMEOUT_SECONDS`适配长文档解析，默认超时过短导致解析过程被判定为慢操作。
- 现象：工具调用与知识库搜索无关联结果返回，无法获取授信审核规则参考。原因：未将授信规则知识库关联至工具调用的上下文召回配置，或`similarityThreshold`设置过高过滤了有效关联内容。
- 现象：配置deepseek-r1模型后工具调用效果差，无法完成完整的授信审核链路。原因：未设置`maxToolCallsPerSession`适配多步骤工具调用，或未开启`toolCallRetryTimes`处理接口临时失败，导致模型无法完成全流程调用。

## 怎么确认配好了
- 上传一份授信申请的银行流水PDF，查看解析日志，确认解析耗时未超过`PARSE_FILE_TIMEOUT_SECONDS`设定的阈值。
- 发起模拟授信申请，查看工具调用日志，确认依次调用了白名单内的核心插件，且总调用次数未超过`maxToolCallsPerSession`的限制。
- 调整`similarityThreshold`至0.8，验证知识库召回的内容均与授信审核规则直接相关，无无关条目返回。
- 模拟第三方工具接口超时场景，确认系统自动重试`toolCallRetryTimes`设定的次数后，返回正常的工具调用结果。
