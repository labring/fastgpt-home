# 贷后台账风控的部署与升级

## 这个品类的数据长什么样
贷后台账数据来自核心信贷系统、第三方还款渠道及催收管理模块，更新节奏随还款节点触发，固定每日执行一次全量同步。单台账文档为结构化表格形式，包含客户唯一标识、合同编号、剩余本金、约定还款日、当前逾期天数、催收状态、累计还款金额等字段。金额字段单位为人民币元，逾期天数单位为自然日，合同编号为固定长度字母数字组合。

## 这些特征在「部署与升级」这一环带来什么约束
结构化字段占比高且字段数量固定，部署时需预先配置字段映射规则，避免解析时出现字段缺失。高频率的每日全量同步要求部署时配置合理的任务超时阈值，升级过程中需保证同步任务无中断。数据量随客户数量线性增长，部署阶段需预留数据库读写带宽，升级时需兼容旧版台账数据结构，避免升级后无法读取历史数据。固定的字段格式要求部署时开启格式校验开关，防止异常数据流入风控流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `SYNC_CRON_EXPRESSION` | `0 2 * * *` | 贷后台账每日同步一次，凌晨2点为业务低峰期，可降低同步对核心系统的影响 |
| `PARSE_STRUCTURED_FIELDS` | `开启` | 台账数据为结构化格式，开启后可直接提取指定字段用于风控校验，无需额外解析 |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | 单份全量台账导出文件通常不超过150 MB，预留合理余量以应对临时数据增长 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 大体积台账文件解析耗时较长，默认超时阈值不足以覆盖完整解析流程 |
| `FIELD_VALIDATION_SWITCH` | `开启` | 台账字段格式固定，开启校验可过滤格式异常的数据，避免错误数据进入风控环节 |
| `MODEL_CONTEXT_WINDOW` | `8000–16000 字符` | 风控审核需结合多字段信息，足够的上下文窗口可保证审核逻辑的完整性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为打包完成后使用对应镜像运行，界面未显示自定义的贷后台账风控审核逻辑。原因是未将自定义规则文件正确复制到部署目录，导致镜像构建时未包含更新内容。
- 现象为使用`fastgpt:v4.8.22`镜像部署后，无法加载配置文件中配置的大模型服务。原因是该版本中模型配置的环境变量命名存在变更，需将`MODEL_API_KEY`调整为`FASTGPT_MODEL_API_KEY`。
- 现象为使用SaaS版本调用风控服务时频繁出现请求超时。原因是未根据贷后台账的数据量调整`maxContext`参数，过长的上下文导致模型推理超时。

## 怎么确认配好了
- 执行手动同步任务，核对同步后的台账字段与源数据字段是否一致，校验逻辑需根据业务要求设定。
- 查看容器日志，确认无`PARSE_FILE_TIMEOUT`相关报错，超时阈值需根据实际同步耗时调整。
- 提交测试用的贷后台账文件，检查风控审核结果是否包含预设的字段校验逻辑，审核规则需与配置项匹配。
- 访问部署后的管理界面，确认`SYNC_CRON_EXPRESSION`参数显示为预设值，配置项需与部署脚本一致。
