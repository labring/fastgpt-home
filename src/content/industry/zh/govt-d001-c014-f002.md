# 分单位制度检索的内部制度与数据问答：向量模型与索引

## 这个品类的数据长什么样
分单位制度检索的数据来源于各内部单位的正式制度文件，包括部门规章、流程规范、管理办法等。数据更新无固定周期，随新制度发布、旧制度修订或废止同步更新。单份文档通常包含制度编号、发布单位、生效日期、正文内容等结构化字段，且绑定唯一所属单位标识，文档篇幅差异较大，短则数百字，长则数万字。各单位的制度集合相对独立，检索时需按所属单位隔离结果。

## 这些特征在「向量模型与索引」这一环带来什么约束
各单位制度集合相对独立且绑定所属单位标识，要求向量索引需支持按单位元数据进行检索隔离，避免跨单位结果混淆。数据更新无固定周期，需配置增量索引同步逻辑，减少全量重建带来的资源消耗。单份文档篇幅差异大且结构规整，分块时需保留所属单位的元数据字段，确保检索时可精准关联对应单位。部分制度存在跨段落的关联内容，分块需兼顾上下文完整性，避免破坏语义连贯性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 内部制度文档多为规整文本，该区间可保留完整条款上下文，避免分块断裂 |
| 重叠长度 | 100–150 字符 | 分块重叠可保留跨块的上下文关联，确保检索时条款语义完整 |
| 相似度阈值 | 0.72–0.80 | 内部制度术语严谨，需过滤低匹配度的无关结果，该区间可平衡召回率与准确率 |
| 单次搜索上限 | 前 10 条 | 内部制度检索无需过多结果，少量精准结果可提升检索效率 |
| `maxToken` | 4000 token | 内部制度问答的上下文长度适中，该取值可覆盖多份关联制度的内容 |
| `defaultToken` | 200 token | 内部制度问答的单轮输入长度适中，该取值可覆盖基础查询内容 |

## 容易做错的三处
- 现象：创建索引时返回400状态码且无响应体。原因：未正确关联所属单位的元数据字段，导致索引引擎无法识别单位隔离规则。
- 现象：检索服务持续占用大量服务器资源导致崩溃。原因：未设置合理的分块长度与单次搜索上限，导致向量检索时加载过多文档块，超出服务器内存阈值。
- 现象：知识库上传文件时偶尔卡在1组或2组索引中。原因：部分文档的所属单位字段格式异常，导致索引分组同步中断。

## 怎么确认配好了
- 上传一份包含所属单位元数据的测试制度文档，查看索引生成日志中是否包含对应单位的标识字段。
- 发起跨单位的检索请求，验证返回结果仅包含指定单位的制度文档。
- 发起单份制度的检索，检查返回结果的分块长度与设置的分块长度区间匹配。
- 连续上传多份不同单位的制度文档，观察索引生成过程无卡顿或中断现象。
