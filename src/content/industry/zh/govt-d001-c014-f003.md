# 分单位制度检索的内部制度与数据问答：多轮对话与提示词

## 这个品类的数据长什么样
分单位制度检索的数据来源于各层级公共管理主体、国央企及下属单位的正式制度文件，包括红头文件、管理办法、实施细则等。更新随制度发布流程同步触发，新制度生效后完成入库。文档多为带明确元数据的结构化文本，包含发布单位、文号、生效日期、失效日期、正文章节等字段，部分附件以嵌入文本或关联链接形式存在，按所属单位维度做层级划分。本文所述内容基于FastGPT v4.17.0版本。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
按单位划分的存储结构要求多轮对话中需绑定当前会话的所属单位标识，避免跨单位制度混淆。带明确元数据的文档结构要求提示词需引导模型优先匹配对话绑定的单位、生效日期等字段，减少无关结果返回。制度的层级与更新逻辑要求多轮对话支持用户补充或修正制度的生效范围、版本信息，同时需保留历史会话中的单位与文号上下文，避免重复询问基础信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 会话上下文窗口 | `8000–12000 token` | 内部制度文本普遍较长，需保留多轮对话中的单位、文号等关键元数据 |
| 问题优化开关 | 开启 | 用户提问常省略单位前缀，优化后可自动补充绑定的单位信息以缩小检索范围 |
| `messages` 上下文截断阈值 | 保留最近 15 轮对话 | 避免过长上下文占用模型计算资源，同时覆盖关键的交互上下文 |
| `chatId` 绑定策略 | 绑定当前会话所属单位的唯一标识 | 确保同一会话内的检索仅匹配对应单位的制度库 |
| 单次召回结果上限 | `前 8 条` | 分单位制度库层级清晰，过多结果会降低模型筛选效率 |
| `variables` 全局参数注入 | 自动注入当前会话的单位与生效时间范围 | 进一步缩小检索范围，提升结果精准度 |

## 容易做错的三处
- 现象：工作流执行到AI对话环节后无返回结果，同一条流程针对特定问题可复现。原因：未绑定`chatId`或`variables`中的单位参数，导致检索范围跨单位匹配到无关制度，模型无法生成有效回答。
- 现象：对话返回结果中包含其他单位的制度文件，结果条数不符合配置上限。原因：未开启问题优化开关，或未在`messages`中保留前序对话的单位上下文，导致检索范围未限定到目标单位。
- 现象：对话日志未按预期保留单位相关上下文，后续提问需重复询问单位信息。原因：会话上下文窗口设置过小，截断了包含单位标识的前序对话内容，导致模型丢失关键绑定信息。

## 怎么确认配好了
- 发起包含单位名称的提问，核对返回结果是否仅包含该单位的制度文件，调整检索范围参数直至结果符合预期。
- 发起连续多轮提问，核对`messages`中是否保留了前序对话的单位与文号信息，调整上下文截断阈值以覆盖必要交互内容。
- 调用API时检查`chatId`是否绑定了对应单位的唯一标识，或`variables`中是否注入了正确的单位参数，验证会话绑定逻辑是否生效。
- 触发流式输出请求，核对返回的分块内容是否按制度章节逐步返回，调整召回上限以控制单轮返回的结果数量。
