# 分单位制度检索的内部制度与数据问答：工作流编排

## 这个品类的数据长什么样
分单位制度检索的数据来源于国央企、政府部门各下属单位的内部正式文档，包括管理办法、操作规程、红头文件等。更新节奏由各单位自行把控，新制度发布或旧制度修订后同步更新。文档结构通常包含发布单位、文号、生效日期、正文内容、附件等字段，部分文档会标注所属单位层级与部门编码，数据以结构化元数据搭配非结构化正文的形式存储。

## 这些特征在「工作流编排」这一环带来什么约束
各单位数据分散存储且更新节奏不一致，要求工作流需支持按单位维度划分检索范围，避免跨单位数据混淆。文档包含专属元数据字段，工作流需配置元数据提取节点，将发布单位、生效日期等字段作为检索过滤条件。所属单位层级与部门编码的存在，要求工作流需预先配置单位编码映射规则，确保检索时能精准匹配对应单位的文档。同时，不同单位的文档格式存在细微差异，工作流需兼容多种文档解析格式，避免解析失败。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 变量设置 | 绑定`variables`中的单位编码字段 | 用于传递当前检索的目标单位标识，精准过滤对应单位的制度文档 |
| 节点ID配置 | 填写对应检索节点的`nodeId` | 确保工作流中各节点调用关系准确，避免节点混淆 |
| 单位过滤规则 | 按文档所属单位编码匹配 | 匹配文档元数据中的单位编码字段，实现分单位检索 |
| 检索超时时间 | 300–600 秒 | 适配分单位检索时多文档批量解析的耗时需求 |
| 上下文窗口大小 | 8000–12000 token | 容纳多单位制度文档的元数据与正文内容，避免截断关键信息 |
| 重试次数 | 2–3 次 | 应对网络波动或文档解析临时失败的场景，提升工作流稳定性 |

## 容易做错的三处
- 现象：工作流中嵌套的表单输入节点在独立运行时对话框隐藏，嵌套到其他工作流时对话框仍显示。原因：未在嵌套工作流中配置表单节点的触发条件，导致默认保留了独立运行时的对话框设置。
- 现象：分单位制度检索工作流运行耗时过长，出现超时报错。原因：未配置合理的检索超时时间，或未按单位维度拆分检索任务，导致单次任务加载过多文档。
- 现象：工作流调用后返回的结果包含非目标单位的制度文档。原因：未正确配置单位过滤规则，或未绑定正确的`variables`参数传递单位标识。

## 怎么确认配好了
- 手动触发工作流，输入目标单位的标识，核对返回的文档是否仅覆盖该单位的制度内容。
- 查看工作流运行日志，确认`variables`参数与`nodeId`配置被正确读取并应用。
- 切换嵌套调用与独立运行两种场景，核对表单输入节点的对话框显示状态是否符合预期。
- 模拟不同文档量的检索场景，验证工作流运行状态是否稳定。
