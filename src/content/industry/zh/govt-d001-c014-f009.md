# 分单位制度检索的内部制度与数据问答：模型接入与配置

## 这个品类的数据长什么样
分单位制度检索的数据来源于国央企、政府各下属单位的正式制度文件，包括通用管理办法、专项工作细则、岗位操作规范等。数据更新节奏随单位制度发布或修订不定期触发，无固定周期。单份文档结构包含发布单位、文号、发布日期、适用范围、正文等固定字段，其中“所属单位”为核心区分字段，文档格式多为PDF、Word转写的结构化文本，单份文档长度跨度较大。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且按单位划分，要求模型接入时支持按单位分组的权限隔离检索，避免跨单位数据泄露。文档包含固定元数据字段，需在模型配置中支持元数据过滤，确保检索结果仅匹配目标单位的制度。文档长度跨度大，需配置合理的上下文容纳参数，避免长文本溢出导致模型调用失败。不定期更新的数据要求向量库支持增量同步，模型接入环节需适配轻量化的更新触发逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 分单位制度单份文档较长，需容纳多份关联制度的上下文，避免超出模型上下文窗口 |
| `temperature` | 0.1–0.3 | 制度问答需保证表述严谨，降低随机性以避免出现与制度不符的错误内容 |
| `quoteMaxToken` | 1500 字符 | 制度引用需保留完整条款段落，避免截断关键管理要求或执行细则 |
| 重排序模型选择 | 按实测标定 | 各单位制度文本风格差异显著，需匹配场景的重排序效果以提升检索精准度 |
| `AIPROXY_API_ENDPOINT` | 企业内网代理地址 | 国央企数据需在内网流转，保障敏感制度文档的传输安全 |
| `AIPROXY_API_TOKEN` | 企业专属鉴权密钥 | 隔离不同单位的模型调用权限，防止越权访问其他单位的制度数据 |

## 容易做错的三处
- 现象：QA搜索测试时提示“当前分组 default 下对于模型 gpt-4o-mini 无可用渠道”，原因：未在对应单位分组下配置该模型的API密钥或代理地址，或密钥鉴权权限不足。
- 现象：重排序功能返回结果与制度核心内容不匹配，原因：未开启重排序配置项，或选择的重排序模型未适配制度文本的正式表述风格。
- 现象：检索结果包含非目标单位的制度文档，原因：未正确映射“所属单位”元数据字段，或未开启按单位分组的检索过滤逻辑。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，发起针对特定单位的制度提问，核对返回结果仅包含该单位的制度文档，确认分组过滤配置生效。
- 查看FastGPT后台的模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`配置无格式错误，无鉴权失败报错。
- 调整`temperature`参数值，观察回答的严谨性变化，确认参数配置对模型输出产生预期影响。
- 测试包含长条款的制度提问，核对返回的引用内容未被异常截断，确认`quoteMaxToken`设置符合需求。
