# 查询结果报表的内部制度与数据问答：向量模型与索引

## 这个品类的数据长什么样
查询结果报表的数据主要来自国央企内部制度文档附件、业务台账导出文件、月度/季度经营分析报表，支持的导入文件类型包括Excel表格、PDF格式的报表导出件、结构化文本文件。数据更新节奏以固定周期为主，部分按需生成的临时报表更新频率更高。单份文档多为结构化格式，包含固定字段如报表编号、生成日期、责任部门、统计项名称、对应数值与单位，搭配少量说明性文本。字段与单位绑定紧密，数值类内容需明确对应统计维度，避免歧义。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化字段与单位绑定的特征要求索引构建时需保留字段与数值的关联关系，避免拆分时破坏语义完整性。固定周期更新的特性意味着无需高频增量索引，但单次批量导入的单份文档体积较大，需控制分块粒度避免索引构建超时。同时，报表内的数值类内容与文本类说明需区分编码逻辑，确保检索时能精准匹配统计项与对应数值，混合检索的计算量会随结构化字段数量提升而增加，可能影响响应速度，需针对性调整检索配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配报表内单条统计项+说明的平均长度，避免拆分跨字段的关联内容 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的字段关联信息，防止检索时丢失统计项与数值的绑定关系 |
| `maxToken` | 8192 token | 适配长报表的上下文拼接需求，符合主流大模型API的调用限制 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配度的报表条目，减少无关结果对内部制度与数据查询的干扰 |
| 单次搜索上限 | 前10条 | 控制单次检索返回的报表数量，平衡召回范围与响应速度 |
| `defaultToken` | 4096 token | 适配单条检索结果的上下文展示需求，避免超出前端展示限制 |

## 容易做错的三处
- 检索请求超时，响应时长超过10秒。原因是开启了混合检索且未调整分块配置，导致索引加载与检索计算量过大。
- 系统卡在建索引步骤，无法完成知识库初始化。原因是未针对报表的结构化字段调整分块规则，导致单分块过长超出系统处理阈值。
- 导入非支持的文件类型后无法生成有效索引。原因是未提前筛选仅允许导入Excel、PDF、结构化文本类的报表文件。

## 怎么确认配好了
- 手动上传单份典型查询结果报表，检查FastGPT v4.17.0系统的索引生成进度是否在预设时长内完成。
- 发起模拟检索请求，验证响应时长符合预期，混合检索的开关状态与配置参数一致。
- 随机抽取检索结果，核对返回条目是否包含完整的字段名称、数值与对应单位信息。
- 查看系统后台日志，确认无索引构建失败的报错记录与超时提示，且仅显示支持的文件类型导入成功的记录。
