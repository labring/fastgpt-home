# 查询结果报表的内部制度与数据问答：模型接入与配置

## 这个品类的数据长什么样
查询结果报表的数据来源于国央企内部制度汇编、各业务模块生成的结构化业务报表，更新节奏按业务周期执行，涵盖月度、季度或按需生成。文档以结构化表格为核心主体，搭配简短说明文本，包含报表唯一标识、生成时间、归口管理部门、统计维度、对应数值、计量单位等字段，计量单位包含万元、人次、自然日等明确单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
结构化的报表数据要求模型能准确识别字段与计量单位，避免数值与单位不匹配的错误。定期更新的数据源要求配置中适配增量检索的逻辑，减少全量重复调用。多来源的制度与报表关联需求，要求模型接入环节配置关联检索的触发条件，确保问答能同时匹配制度条款与对应报表数据。内部使用的严谨性要求，需限制模型生成内容的范围，仅基于已配置的数据源输出结果。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxTokens` | 8000–12000 token | 适配报表与制度文本的总长度，避免核心内容被截断 |
| `temperature` | 0.1–0.3 | 保持回答的严谨性，符合内部问答的合规要求 |
| `maxContext` | 6000–10000 字符 | 承载关联的制度文本与报表数据，确保上下文完整 |
| 问题优化 | 开启 | 解决指代不明确与问题扩展需求，适配多源数据的问答场景 |
| `AIPROXY_API_TOKEN` | 按平台分配的专属密钥 | 确保模型接入的身份验证安全，符合内部使用的权限规范 |
| `toolChoice` | auto | 允许模型自主选择是否调用检索工具，适配多源数据的关联问答 |

## 容易做错的三处
- 现象：模型返回的报表数值与单位不匹配，例如将万元显示为元。原因：未配置适配字段与计量单位的校验逻辑，或`temperature`取值过高导致模型生成错误单位。
- 现象：调用模型时返回401未授权错误，或无法正常调用目标模型。原因：`AIPROXY_API_TOKEN`配置错误，或未使用正确的`AIPROXY_API_ENDPOINT`适配目标模型。
- 现象：无法查看模型请求的参数日志，无法排查配置异常。原因：未开启模型调用的日志记录开关，或未配置参数日志的输出路径。

## 怎么确认配好了
- 发起包含报表字段与制度条款的测试问题，核对返回结果是否同时覆盖两类数据源的内容。
- 查看模型调用日志，确认`maxTokens`、`temperature`等配置参数的实际取值与预设一致。
- 输入指代模糊的测试问题，核对模型是否自动完成指代消除与问题扩展。
- 触发模型调用，检查生成结果中的报表数值与计量单位是否匹配。
