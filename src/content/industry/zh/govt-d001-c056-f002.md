# 项目数据自然语言查询的内部制度与数据问答：向量模型与索引

## 这个品类的数据长什么样
数据来源为国央企内部项目台账、正式发布的内部管理制度文档、项目审批流转记录、进度周报与决算报表。更新节奏随项目推进节点触发，立项后随审批、进度变更按需更新，固定制度文档仅在修订时更新。文档结构混合结构化字段与非结构化文本，结构化字段包含项目编号、负责人工号、预算金额、完成占比等，非结构化内容为制度条款、项目说明与审批意见，字段带有明确单位，如万元、自然日。

## 这些特征在「向量模型与索引」这一环带来什么约束
FastGPT v4.17.0 版本下，混合结构化与非结构化的数据，要求分块时需区分字段属性，避免将跨字段的关联信息拆分到不同块中；高频更新的项目数据要求索引支持增量更新，避免全量重建消耗过多资源；带有明确单位的字段，会增加向量建模的精度需求，需保留单位信息以避免同类项目的歧义匹配；长文本的制度条款与项目说明，会影响单块长度的设定，过长的块会增加向量计算负载，过短的块会丢失上下文关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配项目文档混合结构化字段与长文本的结构，平衡上下文完整性与计算效率 |
| 重叠长度 | 100–150 字符 | 保留跨分块的制度条款、项目进度描述的连贯关联 |
| 相似度阈值 | 0.72–0.85，按实测标定 | 项目数据字段特异性强，避免误匹配非关联的项目条目 |
| 单次搜索上限 | 前 10 条 | 核心关联的项目数据通常集中在检索结果前几位，控制返回量降低上下文负载 |
| `defaultToken` | 4096 | 匹配单份项目文档或制度条款的常规上下文长度 |
| `maxToken` | 8192 | 支持整合多份关联项目文档与制度文本的问答需求 |

## 容易做错的三处
- 单个文件持续处于索引中：后台任务列表显示该文件索引进度停滞，状态为“正在重建”。原因是该文件包含超长嵌套的结构化表格，分块时超出单块token上限。
- 知识库优先级设置不生效：问答时优先返回了非指定知识库的内容。原因是未在检索配置中开启知识库优先级开关，或配置顺序有误。
- 索引切换超时：操作后返回60秒超时报错。原因是索引重建时未限制并发线程数，导致服务器资源耗尽。

## 怎么确认配好了
- 上传一份典型的项目制度文档，查看分块预览界面，确认分块长度与重叠长度符合设定值。
- 发起包含项目编号与对应制度条款的查询，核对返回结果的相似度分值是否落在设定的阈值区间内。
- 配置知识库优先级后，发起包含两个知识库关联内容的查询，确认结果优先来自指定的高优先级知识库。
- 上传更新后的项目数据，查看索引重建耗时，确认未出现长时间停滞状态。
