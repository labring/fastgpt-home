# 项目数据自然语言查询的内部制度与数据问答：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源为内部项目管理系统、正式发布的内部制度汇编、月度进度台账及审批流程记录。数据更新节奏随项目推进实时同步，制度文档按修订发布节点更新，月度台账固定周期更新。单条数据包含项目编号、所属部门、预算金额、执行进度、关联制度条款、审批节点记录等字段，其中预算字段单位为人民币万元，进度字段为百分比格式，项目编号为唯一字符串标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据包含长文本制度条款与结构化项目字段，长文本内容可能超出模型单次上下文承载上限，需调整上下文相关配置。结构化字段含明确单位与唯一标识，模型需准确识别单位并关联对应项目，需配置合适参数保障语义理解精度。数据更新频率较高，需确保模型调用的并发与超时配置适配实时查询需求，避免因请求过载导致查询失败。此外，不同项目的关联制度条款差异较大，需保障模型对跨文档关联信息的提取能力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 本品类包含长文本制度条款与多字段关联数据，需容纳较多上下文信息保障关联查询准确性 |
| `maxTokens` | 2000–3000 token | 结构化项目字段与制度条款的解析结果需足够长度输出，避免截断关键信息 |
| `quoteMaxToken` | 1500–2000 token | 需保留足够长度的原始制度文本片段作为引用依据，匹配项目数据的关联查询需求 |
| `temperature` | 0.3–0.5 | 本场景需准确匹配项目数据与制度条款，较低温度可提升回答的一致性与准确性 |
| `toolChoice` | auto | 需自动触发工具调用以提取结构化项目字段的精准信息，适配多维度查询需求 |
| `AIPROXY_API_ENDPOINT` | 按接入的大模型服务商接口地址填写 | 确保模型请求路由正确，适配第三方大模型的接入规范 |

本配置说明基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 现象：调用第三方大模型接口返回429状态码，提示请求超限。原因：未配置并发限制，多项目数据查询请求同时发起时，超出云服务商的接口并发配额。
- 现象：模型无法准确识别项目数据中的单位，如将预算的“万元”误识别为“元”。原因：未开启`toolChoice`自动模式，或`temperature`参数配置过高，导致结构化字段的语义理解精度不足。
- 现象：界面中未显示语音识别模型选项，无法配置语音输入功能。原因：未启用相关语音模块设置，或未加载对应模型的依赖包，导致可选模型列表未正常展示。

## 怎么确认配好了
- 发起包含长文本制度关联的项目查询，核对返回结果的上下文覆盖范围，确认无关键信息截断，调整对应配置项至满足需求的范围。
- 发起多并发的查询请求，验证接口无429等超限报错，调整并发配置至适配服务商配额的水平。
- 测试结构化项目字段的识别准确性，确认模型能正确匹配单位与关联制度，调整`temperature`与`toolChoice`配置至符合需求的状态。
- 核对大模型API的端点与令牌配置，确认格式正确，无输入错误。
