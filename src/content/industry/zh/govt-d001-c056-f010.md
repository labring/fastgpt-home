# 项目数据自然语言查询的内部制度与数据问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来源为内部项目管理系统导出的结构化台账、内部制度汇编电子文档、项目验收审批文件。更新节奏随项目立项、进度变更、制度修订同步更新，更新周期最长不超过7天。文档以单条项目数据为基础单元，包含项目编号、所属业务部门、当前进度节点、预算额度、关联制度条款编号等字段，部分文档附带结构化表格与附件链接。字段单位包含自然日、万元等，单条文档字数跨度较大，从数百字符到数千字符不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类数据兼具结构化字段与非制度文本，且存在强关联属性，要求检索环节同时覆盖字段匹配与语义关联，避免召回无关内容。数据更新无固定周期，需配置自动同步机制确保召回数据的时效性。单条文档字数跨度较大，分块处理需适配不同信息密度，避免关键字段被错误拆分。项目数据与内部制度强绑定，检索时需联动关联字段，确保召回的制度条款与项目场景匹配。部分文档附带附件链接，召回环节需保留关联信息以便后续调用。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写，以下配置项针对该品类的特征定制：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配项目数据与制度文本的语义相关性，覆盖多数内部场景的精准度需求 |
| `limit` | 前8条 | 适配项目关联制度的常规数量，避免上下文过载影响后续生成 |
| `searchMode` | hybrid | 结合关键词与语义检索，兼顾结构化字段与非文本内容的召回效果 |
| `usingReRank` | 开启 | 对初始召回结果重排序，提升高相关内容的展示优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题扩展检索词，覆盖项目编号、制度条款编号等结构化字段 |
| `collectionIds` | 对应目标项目知识库的集合ID | 限定检索范围，避免混入无关知识库内容 |

## 容易做错的三处
- 无法在判断器中配置知识库检索结果作为判断条件。原因是未开启检索结果的变量映射开关，导致检索返回的结构化数据未暴露为可调用的判断字段。
- 调用普通对话节点时意外引入了项目知识库的内容。原因是未在对话节点中关闭自动关联知识库的配置，或全局检索范围未限定至目标项目知识库。
- 检索结果未包含文档内的图片链接或附件信息。原因是知识库导入时未同步提取附件元数据，或检索环节未配置附件关联的召回规则。

## 怎么确认配好了
- 发起包含项目编号的查询，核对检索结果是否包含对应项目的关联制度条款。
- 查看检索日志，确认召回结果的条数符合配置的`limit`参数要求。
- 检查全局配置的`collectionIds`是否仅包含目标项目知识库的集合ID，避免混入无关内容。
- 发起包含附件关键词的查询，核对检索结果是否返回对应的附件链接信息。
