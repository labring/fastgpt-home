# 不动产登记的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
不动产登记场景的业务数据来源包括不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统、电子证照库，更新频率为每日。日常处理的文档涵盖登记申请书、权属证明、测绘成果、税费凭证、不动产权证书、不动产登记簿，数据字段包含权利主体、坐落位置、权利类型、面积、权属状态等，所有字段均遵循政务数据通用规范，无特殊自定义单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于业务数据来自多套异构系统，模型接入时需适配跨源数据的上下文拼接，避免出现权属信息与税费数据不匹配的问题。每日更新的数据要求模型上下文需同步最新的登记状态，不能依赖过时的历史数据。长文本类的测绘成果、登记簿内容会占用较多上下文额度，需合理控制参数阈值以避免截断核心业务信息。同时，政务场景对数据准确性要求极高，模型输出需严格匹配业务字段，不能出现随机偏差，防范登记错误或产权纠纷。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 需容纳多系统同步的权属、测绘、税费等长文本业务文档，避免截断核心业务数据 |
| `maxTokens` | 2000–3000 token | 确保输出的办事咨询答复完整包含权利核验、流程指引等关键信息，避免截断 |
| `vision` | 开启 | 支持解析权属证明、测绘成果等图片类业务文档，适配不动产登记的纸质材料电子化场景 |
| `temperature` | 0.1–0.3 | 降低随机输出，保障权属信息、坐落地址等业务字段的准确性，符合政务场景的严谨要求 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的专属地址 | 适配多系统协同的访问权限要求，保障数据调用的安全性 |
| `AIPROXY_API_TOKEN` | 绑定业务专属密钥 | 限制仅不动产登记相关业务调用，防范未授权访问，符合政务数据安全规范 |

## 容易做错的三处
- 未开启`vision`参数，上传的测绘成果或权属证明图片无法被解析，返回结果缺失材料核验相关内容。原因是未适配不动产登记场景下的图片类业务文档输入需求，遗漏视觉模型配置步骤。
- 未关闭模型自带的思考过程输出开关，返回结果仅包含思考标签与过程，无实质办事咨询答复。原因是未针对政务答复场景调整模型输出格式，保留了训练阶段的调试内容。
- 配置`maxContext`取值过小，多系统同步的权属、税费凭证等长文本被截断，返回的咨询答复缺失关键权利核验信息。原因是未结合不动产登记业务的长文本输入需求调整上下文参数，导致核心业务数据丢失。

## 怎么确认配好了
- 上传一张权属证明图片，检查模型是否能正确识别图片中的权利主体、坐落地址等字段，无解析失败提示。
- 发起包含权属核验需求的咨询，检查返回结果是否仅包含实质答复内容，无额外思考过程或冗余标签。
- 调用接口测试，检查返回结果的响应时长符合业务预期，无安全拦截报错。
- 核对`AIPROXY_API_TOKEN`绑定的权限范围，确认仅允许不动产登记相关业务调用该接口。
