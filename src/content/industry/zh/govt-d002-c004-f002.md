# 主动公开与政策发布的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来自政府门户网站、公文系统、政府信息公开目录、政策文件库及新闻发布会材料。日常处理的文档包括政策文件、政策解读稿、公开目录、信息发布审批单、新闻通稿、网站栏目更新记录。数据更新频率为每日，涉及的主体包括政府办公室、部门办公室、政策法规处及网站运维单位。文档通常包含标题、正文、发布文号、发布日期、公开属性标识等字段，部分审批类文档还包含审核流程记录。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据更新频率为每日，要求向量索引支持每日增量同步或快速全量更新，避免影响公开时效。文档包含审批类流程记录与公开属性标识，索引环节需关联对应字段，确保仅对符合公开要求的内容生成向量。不同文档类型长度差异较大，政策文件正文较长，政策解读稿篇幅较短，分块规则需适配多类文档的长度特征，避免分块破坏语义完整性。同时，需确保索引结果严格匹配公开目录分类，便于后续办事咨询与答复环节精准召回对应公开信息。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配政策文件与解读稿的常见语义单元长度，避免破坏上下文关联 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的语义衔接，减少信息断裂 |
| `maxToken` | 4096 token | 匹配主流大模型的上下文窗口上限，避免截断关键政策内容 |
| 相似度阈值 | 0.75–0.85 | 过滤低关联结果，确保召回内容符合公开信息的相关性要求 |
| 单次搜索上限 | 前 5 条 | 控制返回结果数量，适配办事咨询答复的简洁性需求 |
| `defaultToken` | 1024 token | 设定默认分块的token上限，平衡语义完整性与索引效率 |

## 容易做错的三处
- 导入数据后长期显示「创建索引中」状态。原因是未适配该品类每日更新的批量数据规模，未开启增量索引配置，导致全量索引耗时过长。
- 向量计算得分异常偏大且结果完全一致。原因是未对公开属性字段做前置过滤，将涉密或未公开的文档纳入向量生成范围，导致语义特征匹配逻辑紊乱。
- 向量化任务执行缓慢。原因是分块长度设置超出文档语义单元的合理范围，或未针对政策文件的长文本开启分段向量化优化，导致单条数据处理耗时增加。

## 怎么确认配好了
- 查看数据集的索引进度日志，确认增量同步任务按每日更新频率触发。
- 随机抽取政策文件与政策解读稿，核对分块后的语义完整性，无明显上下文断裂。
- 测试检索公开目录下的政策内容，确认召回结果的相似度值处于预设阈值区间内。
- 验证涉密或未公开文档未被纳入公开索引库，检索结果无敏感内容。
