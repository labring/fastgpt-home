# 主动公开与政策发布的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来自政府门户网站、公文系统、政府信息公开目录、政策文件库及新闻发布会材料，更新频率为每日。日常文档包含政策文件、政策解读稿、公开目录、信息发布审批单、新闻通稿与网站栏目更新记录，文档结构多包含主题分类、发布日期、文号、公开属性等字段，部分审批类文档还包含审核流程节点信息。数据主体对应政府办公室、政策法规处及网站运维单位，核心围绕主动对外发布的政务信息展开，区别于依申请公开的个性化咨询。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的政务公开数据要求对话系统需支持增量同步与实时检索，避免返回过期或未公开的信息。多类文档的混合输入要求提示词需区分政策文件、解读稿等不同文档类型的调用逻辑，确保检索内容匹配用户咨询的场景。公开属性与保密审查相关字段要求对话系统在生成答复前需校验内容的合规性，防止涉密或敏感信息泄露。面向社会的主动发布属性要求答复需保持口径统一，避免出现与公开目录不一致的表述。多轮对话的上下文关联需准确绑定会话主题，避免混淆不同批次的公开信息或审批流程内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按会话生命周期生成唯一标识，绑定当前用户咨询上下文 | 确保多轮对话的上下文准确关联，避免不同会话的历史记录混淆 |
| `messages` | 限制上下文窗口为前20轮对话内容，或按实测标定的长度 | 政务公开咨询的多轮对话通常围绕单一政策主题展开，过长上下文会增加检索负载 |
| `variables` | 注入当前公开目录的主题分类、最新发布日期等预设变量 | 确保对话系统可实时调用最新的政务公开数据，匹配用户咨询的时效性要求 |
| 最大上下文长度 | 8000–12000 字符 | 政务文档的单条内容较长，需预留足够空间用于关联政策解读与原始文件内容 |
| 单次检索上限 | 前10条 | 政务公开数据的检索结果需控制条数，避免过多冗余信息干扰答复生成 |
| 问题优化开关 | 开启 | 政务咨询常包含口语化表述，优化后可提升检索精准度，匹配公开目录的规范术语 |

## 容易做错的三处
- 现象：调用API启动对话后，返回结果附带额外的历史对话记录。原因：未正确传递`chatId`参数，导致系统生成了独立的会话上下文。
- 现象：AI生成的答复无法按照JSON格式输出。原因：未在提示词中明确要求使用标准JSON结构，或未配置对应的格式校验逻辑。
- 现象：用户点击对话界面的点赞或点踩按钮后，系统无响应。原因：未开启对话组件的反馈收集配置，或未绑定对应的回调接口。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的平台发起多轮政策咨询，检查对话上下文是否正确绑定，无跨会话的历史记录干扰。
- 提交测试咨询，确认AI生成的答复可按照指定的JSON格式返回，无格式错误。
- 点击对话界面的点赞和点踩按钮，确认系统记录反馈数据并返回确认提示。
- 检索当日发布的政策文件，确认对话系统可返回最新的政务公开内容，无过期信息。
