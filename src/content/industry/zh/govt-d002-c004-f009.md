# 主动公开与政策发布的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自政府门户网站、公文系统、政府信息公开目录、政策文件库、新闻发布会材料，更新频率为每日。日常文档包含政策文件、政策解读稿、公开目录、信息发布审批单、新闻通稿、网站栏目更新记录。数据字段涵盖文件公开属性、保密审查状态、发布渠道、栏目归属、更新时间等，单位多为字符、条、日期，无自定义特殊计量单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的数据要求配置定时同步任务，确保索引与实际发布内容保持一致。文档包含信息发布审批单等涉密相关文档，要求模型接入时配置敏感信息过滤规则，避免涉密内容被不当引用。不同文档结构差异较大，政策文件为长文本格式，政策解读稿为短文本格式，需适配不同的上下文配额设置。需严格控制输出内容的公开属性，确保政策答复口径与官方文件一致，避免引发误读。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配政策文件长文本与配套解读稿的上下文长度需求，避免截断关键政策表述 |
| `maxTokens` | 2000–3000 token | 满足政策解读与答复内容的输出长度，确保覆盖完整信息 |
| `quoteMaxToken` | 1500 token | 限制引用文档的总长度，避免检索结果占用过多上下文配额 |
| `temperature` | 0.2–0.4 | 降低随机输出概率，确保政策答复口径统一准确 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的官方地址填写 | 适配模型调用的网络路径，确保请求正常转发 |
| `AIPROXY_API_TOKEN` | 按服务商分配的密钥填写 | 完成模型调用的身份验证，保障接口安全 |

## 容易做错的三处
-  无法获取模型请求的参数日志。原因是未开启系统的日志记录开关，或未正确配置日志存储路径。
-  检索返回的政策引用内容条数不符合预期。原因是未合理设置`quoteMaxToken`，导致引用配额被提前占满。
-  生成的答复出现指代不明的问题。原因是未启用问题优化环节，未在检索前完成指代消除与问题扩展，导致无法匹配准确的政策文档。

## 怎么确认配好了
-  发起包含具体政策关键词的测试请求，检查返回结果中是否包含准确的官方文档引用，确认上下文未被过度截断。
-  查看模型调用日志，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置是否被系统正确读取。
-  提交包含指代模糊的测试问题，如“该政策的适用范围是什么”，确认系统自动完成问题扩展与指代消除后返回准确结果。
-  手动触发一次数据同步任务，检查系统是否按设定频率完成文档更新与索引重建，确保数据时效性。
