# 传染病信息报告与监测的办事咨询与答复：向量模型与索引

以下内容基于FastGPT v4.17.0版本的配置逻辑编写。

## 这个品类的数据长什么样
本品类数据主要来自中国疾病预防控制信息系统、医疗机构HIS与传染病报告系统、实验室检测系统。日常文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，数据按日更新。单份文档包含病例唯一标识、诊断时间、报告单位、订正状态、检测结果等字段，部分文档需关联多类系统的跨源数据，字段格式需符合法定传染病报告规范。

## 这些特征在「向量模型与索引」这一环带来什么约束
日更新频率要求索引支持增量同步，避免全量重建的耗时压力。跨源数据关联需求要求索引需保留各系统的原始字段标识，便于后续核对病例关联关系。多类文档的长度差异大，从短报告卡到数千字符的流调报告，需适配不同分块策略。法定报告规则要求索引中需保留病例订正、报告时限等关键字段，确保召回结果可追溯合规性。同时，疫情预警的时效性要求向量召回需控制在合理时长内，避免延误异常信号识别。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配传染病报告卡、流调报告等多类文档的长度，避免单块信息断裂 |
| 重叠长度 | 100–200 字符 | 保留跨块的病例标识等关键信息，防止分块后丢失关联字段 |
| 相似度阈值 | 0.75–0.85 | 平衡召回准确率与召回量，避免漏报关键病例信息 |
| 单次搜索上限 | 前10条 | 控制召回结果的信息量，适配办事咨询的快速答复需求 |
| `maxToken` | 4000 token | 限制单轮上下文的总长度，避免超出模型处理上限 |
| 重排模型开关 | 开启 | 提升高相关结果的排序优先级，优化办事咨询的答复准确性 |

## 容易做错的三处
- 配置Embedding模型连接OneAPI时出现连接报错，界面显示“模型调用失败”，原因是未正确填写OneAPI的模型映射标识，导致向量请求无法被正确转发。
- 开启重排模型配置并在索引阶段勾选对应选项后，在线召回测试结果未按重排优先级展示，现象是召回结果排序与初始相似度排序一致，原因是未在问答调用环节同步开启重排调用开关，仅配置索引阶段的重排未生效。
- 尝试接入通义多模态向量模型时出现接口不兼容报错，现象是返回“不支持指定调用格式”，原因是未调整适配通义多模态向量的专属调用参数，沿用了通用格式的配置。

## 怎么确认配好了
- 手动上传单份传染病报告卡，执行向量索引后，查看索引详情页确认所有预设字段均被正确存储。
- 发起包含病例编号或疫情关键词的咨询测试，核对召回结果中是否包含匹配的文档内容，确认相似度阈值设置生效。
- 开启重排开关后，对比开启前后的召回结果排序，确认重排模型已正常调用。
- 查看系统运行日志，确认向量模型调用的`maxToken`参数未超出设置上限，无超时或连接报错。
