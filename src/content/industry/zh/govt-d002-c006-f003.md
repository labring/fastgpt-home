# 传染病信息报告与监测的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源包括中国疾病预防控制信息系统、医疗机构HIS和传染病报告系统、实验室检测系统，更新频率为每日。日常文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，字段覆盖病例基本信息、诊断结果、报告时限、订正说明、检测数据等，单位涉及日期、病例数、检测指标数值等，所有内容需符合法定传染病报告的格式要求。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的跨系统数据要求多轮对话需支持实时关联不同数据源的病例信息；固定格式的专业文档要求提示词需严格匹配法定报告的字段校验规则；耗时的核对与订正环节要求多轮对话能引导用户逐步补全或校验信息；严格的出错后果要求对话环节需自动规避漏报、迟报风险，确保所有交互内容符合疾控报告规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 问题优化 | 开启，按实测标定 | 适配疾控场景下的专业术语简化，让模型准确理解办事咨询的专业问题 |
| 最大上下文 | 8000–12000 字符 | 匹配多份传染病报告卡、流调报告的拼接长度，覆盖多轮对话的历史交互内容 |
| 单次召回条数 | 前6条 | 匹配每日更新的病例数据规模，避免冗余信息干扰对话逻辑 |
| 超时时间 | 600 秒 | 适配跨系统拉取数据的耗时，避免对话中途中断 |
| `variables` | 绑定法定传染病报告规则变量 | 让提示词自动调用预设的报告字段校验逻辑 |
| `messages` | 按对话轮次追加历史交互内容 | 支持多轮核对病例订正信息的连续交互流程 |
| `chatId` | 绑定当前会话的唯一标识 | 确保多轮对话的历史内容与当前会话正确关联 |

## 容易做错的三处
- 现象：对话返回内容被截断，仅显示部分病例订正记录。原因：未调整最大上下文长度，导致历史对话与当前文档的拼接超出模型支持的字符上限。
- 现象：导入传染病报告卡文档时返回500错误。原因：未正确配置嵌入模型的加载路径，或文档内包含未转义的特殊字符导致解析失败。
- 现象：多轮对话无法关联跨系统的病例数据。原因：未通过`variables`绑定数据源关联规则，导致模型无法调用不同系统的病例信息完成核对。

## 怎么确认配好了
- 发起包含既往病例订正记录的多轮咨询，检查模型是否能连续调用历史对话内容完成信息核对。
- 导入一份标准传染病报告卡文档，确认无500报错且文档内容被正确拆分加载。
- 触发问题优化功能，输入专业疾控术语咨询，检查模型是否能将复杂查询简化为可执行的检索指令。
- 在FastGPT v4.17.0的后台查看对话日志，确认`messages`参数正确追加了每一轮的交互内容，无遗漏。
