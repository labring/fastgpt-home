# 信访事项办理的办事咨询与答复：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源为国家信访信息系统、地方信访系统、12345平台、基层治理平台及历史信访档案，更新频率为每日。日常处理的文档包含信访登记表、受理告知书、转送交办函、办理意见书、复查复核申请、化解方案，核心字段包含信访人标识、诉求事项、受理编号、办理环节、责任单位、政策依据等，数据结构围绕法定办理流程设计，关联多平台流转的诉求与办理痕迹。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据来源要求工具调用适配不同系统的接口规范，避免格式不兼容导致的数据拉取失败。每日更新频率要求插件配置增量同步逻辑，避免全量拉取占用过多资源。多样的文档类型要求工具支持解析信访登记表、办理意见书等不同格式的业务文档，适配精准字段提取需求。法定办理流程关联的核心环节，要求工具调用的结果需严格匹配业务字段，防止因字段缺失或错误引发重复信访或办理意见被复查纠错。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 设为 `auto` 或指定业务工具名 | 适配信访事项办理中按需调用甄别、政策查询等工具的需求，灵活匹配不同办理环节 |
| `functionCall` | 开启并绑定信访业务专属工具集合 | 确保工具调用严格围绕信访法定办理流程，避免无关工具干扰业务逻辑 |
| 插件加载路径 | 指向业务插件部署目录 | 解决社区反馈的插件路径查找困难问题，便于快速部署信访专用插件 |
| 工具调用超时 | 600 秒 | 适配跨多信访系统数据拉取的耗时场景，防止因超时中断办理流程 |
| 召回结果上限 | 前 10 条 | 控制历史信访数据的返回量，避免上下文过载影响工具调用准确性 |

## 容易做错的三处
- 工具模块无法加载，界面显示「未找到对应插件」。原因是插件部署路径配置错误，未指向信访业务专用插件的存放目录。
- 工具调用触发失败，返回「参数不匹配」报错。原因是未正确配置`functionCall`绑定的工具集合，混入了非信访业务的工具。
- 工具调用结果条数超出预期，返回超过20条历史数据。原因是未设置合理的召回结果上限，导致上下文过载影响处理逻辑。

## 怎么确认配好了
- 登录FastGPT v4.17.0的后台，进入插件管理页面，确认信访业务专用插件已显示在已加载列表中。
- 发起测试调用，输入「甄别该信访事项是否属于受理范围」，确认工具自动调用对应业务插件。
- 查看工具调用日志，确认返回的历史信访数据条数符合预设的上限规则。
- 检查`toolChoice`配置项，确认已根据当前办理环节选择对应工具或设置为自动模式。
