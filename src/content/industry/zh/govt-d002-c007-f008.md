# 信访事项办理的办事咨询与答复：文档解析与分块

## 这个品类的数据长什么样
本品类数据来自国家信访信息系统、地方信访系统、12345平台、基层治理平台及历史信访档案，更新频率为每日。日常处理的文档包含信访登记表、受理告知书、转送交办函、办理意见书、复查复核申请、化解方案等，数据字段涵盖信访人基本信息、诉求事项、办理流程节点、政策解释内容，部分文档附带扫描件或多级嵌套的附件结构。

## 这些特征在「文档解析与分块」这一环带来什么约束
本品类的数据来源多样且格式混杂，包含结构化表单、非结构化文书及扫描附件，对解析的格式适配能力提出要求。每日更新的批量数据需求，要求解析流程具备稳定的并发处理能力。文档包含信访受理、办理、复查复核等法定流程节点内容，分块需保留流程关联性，避免割裂关键办理信息。部分转办文档格式不统一，历史档案存在老旧文件格式，需要自定义解析规则适配不同场景。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 信访类文档包含诉求与办理意见，分块长度覆盖完整语义单元，避免割裂政策解释或流程节点 |
| `chunkSplitter` | 按段落+标题拆分 | 信访文档多含层级化办理流程标题，按段落拆分可保留办理逻辑完整性 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量导入的信访档案包，避免大文件解析中断 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 复杂信访档案包含多页扫描件或嵌套附件，预留充足解析时间 |
| `customPdfParse` | 启用自定义解析 | 适配信访类PDF的固定格式表头，提取结构化字段 |
| `chunkSettingMode` | 手动配置 | 针对信访文档的固定结构，手动调整分块规则适配业务需求 |

## 容易做错的三处
- 上传文件解析返回413状态码。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，文件大小超出平台默认限制。
- 导入CSV格式信访登记表仅显示前两列内容。原因：未开启自定义CSV解析配置，平台默认仅读取前两列字段。
- 配置外部pdf-maker解析器时无法找到密钥设置入口。原因：未进入自定义解析模块，未在对应配置项中绑定外部解析器所需密钥。

## 怎么确认配好了
- 上传单份标准信访受理告知书，核对解析后的文本是否完整覆盖告知内容与诉求受理范围，验证分块规则是否适配业务需求
- 导入批量CSV格式信访登记表，确认所有预设字段均被正确提取，验证自定义CSV解析配置是否生效
- 配置外部pdf-maker解析器并绑定密钥，上传测试PDF信访文档，检查解析结果无异常，验证密钥配置是否正确
- 上传包含多级目录的飞书文档包，检查是否覆盖所有子目录内容及内嵌图片、doc文本，验证递归解析配置是否开启
