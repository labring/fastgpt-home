# 信访事项办理的办事咨询与答复：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自国家信访信息系统、地方信访系统、12345平台、基层治理平台及历史信访档案。日常处理的文档包含信访登记表、受理告知书、转送交办函、办理意见书、复查复核申请、化解方案。数据更新频率为每日，文档多为结构化与半结构化混合，包含诉求内容、办理流程节点、责任主体、政策依据等字段，部分文档为扫描件转写的非标准化文本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源多且分散，要求知识库检索链路兼容多格式的信访类文档，需同时支持结构化字段匹配与自由文本语义检索。每日更新的数据要求检索链路支持增量同步，避免全量重导带来的资源消耗。文档无统一固定格式，分块时易出现语义断裂，需调整分块策略适配不同文档结构。信访事项需严格匹配法定办理程序，检索召回的结果需关联对应办理流程的合规性依据，不能偏离法定要求。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 适配信访诉求的语义匹配精度，过滤掉与信访事项关联度较低的历史档案 |
| `limit` | 前8–12条 | 匹配信访办理的单次查询上下文长度，避免超出大模型的上下文限额 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配信访文档中既有结构化字段又有自由文本的混合特征 |
| `usingReRank` | 开启 | 对初始召回结果进行二次排序，进一步过滤语义关联较弱的信访内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户提问自动生成扩展查询词，覆盖信访诉求的同义表述，提升召回覆盖率 |

## 容易做错的三处
- 检索结果遗漏长文档关键内容，现象为分块后的知识库查询不全，原因是分块策略未保留信访文档的上下文关联，导致语义断裂。
- 导入PDF后搜索无结果并显示错误，现象为上传信访类PDF文档后无法检索到内容，原因是未完成PDF文本提取配置，或解析过程出现异常。
- 搜索时报错提示无效配置参数名，现象为返回`{"message": "invalid configuration parameter name \"hnsw.iter\""}`，原因是使用了平台未允许的自定义配置参数，未使用指定范围内的配置项。

## 怎么确认配好了
- 上传单份信访登记表文档，执行检索测试，验证召回结果包含文档内的核心诉求与办理要求。
- 查看配置日志，确认`similarity`、`limit`等配置项的取值与预设一致，无未授权参数。
- 导入多份不同类型的信访文档，执行混合检索，验证`searchMode`为hybrid时能同时匹配关键词与语义内容。
- 测试增量导入当日更新的信访数据，确认检索链路能正常加载新数据，无同步延迟。
