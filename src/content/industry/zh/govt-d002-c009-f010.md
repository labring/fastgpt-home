# 公共数据目录与开放的办事咨询与答复：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据主要来自地方公共数据开放平台、一体化大数据平台、部门业务数据库与电子证照库，更新频率为月度。日常维护的文档包括公共数据资源目录、数据开放清单、数据项说明、脱敏规则、接口文档与更新频率说明。数据以结构化元数据为主，包含数据项名称、开放条件、接口地址、脱敏规则、更新周期等字段，部分文档附带接口调用说明与权限边界说明。

## 这些特征在「知识库检索与召回」这一环带来什么约束
月度更新的频率要求知识库需配置匹配的同步周期，避免出现目录信息与实际开放数据不一致的情况。结构化为主的数据结构，要求检索环节兼顾字段精准匹配与全文语义匹配，确保能召回接口地址、开放条件等关键元数据。数据涉及部门权限边界与脱敏规则，检索需按部门或数据类型限定范围，防止跨权限召回敏感数据。同时，数据的准确性直接影响办事咨询的答复质量，因此检索的精准度与召回片段的完整性需要严格控制，避免出现错误指引。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 公共数据目录的字段匹配需要较高精准度，避免召回不相关的开放数据项 |
| `limit` | `前10条` | 办事咨询的答复需简洁清晰，过多条目会增加信息接收负担 |
| `searchMode` | 混合检索 | 数据包含结构化字段（如接口地址、开放条件）与非结构化文本（如脱敏规则说明），混合检索可兼顾精准匹配与语义匹配 |
| `usingReRank` | 开启 | 公共数据文档数量较多，重排可提升高相关片段的排序优先级，避免关键信息被淹没 |
| `datasetSearchUsingExtensionQuery` | 开启 | 办事咨询的问题常包含模糊表述，扩展查询可覆盖更多相关的目录条目与接口说明 |
| `collectionIds` | 按部门/数据类型划分的集合ID列表 | 公共数据按部门管理，按集合划分可避免跨部门权限的无效检索，确保召回数据符合开放范围 |

## 容易做错的三处
- 现象：检索时返回无权访问提示，或召回了未授权的敏感数据字段。原因：未通过`collectionIds`限定检索范围，导致跨部门或未开放的数据被召回。
- 现象：搜索接口文档时，结果未包含接口地址或更新频率字段。原因：未开启`datasetSearchUsingExtensionQuery`，无法匹配问题中隐含的结构化字段需求。
- 现象：检索结果排序混乱，高相关的目录条目排在低相关条目之后。原因：未开启`usingReRank`，且`similarity`阈值设置不当，导致排序逻辑失效。

## 怎么确认配好了
- 进入FastGPT知识库管理页面，核对`collectionIds`配置的集合是否按部门或数据类型完成划分。
- 发起一条测试查询，如“查询医保数据的开放条件”，确认召回结果包含数据项说明与开放条件字段。
- 查看检索日志，确认`usingReRank`与`datasetSearchUsingExtensionQuery`已生效，返回结果的排序符合预期。
- 触发月度同步任务，确认知识库的更新日志正常，无数据不一致的报错。
