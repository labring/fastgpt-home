# 公路养护与路产路权管理的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
这个品类的典型数据来自公路养护管理系统、桥隧监测系统、路政巡查系统及交通流量监测数据，更新频率为每日。日常文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单等，其中巡查日志包含巡查时间、路段编号、病害类型等字段，涉路施工许可包含施工单位、施工范围、许可有效期等字段，部分文档为结构化表单，部分为非结构化的现场记录文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引系统兼容不同格式的文档解析，避免因数据源格式差异导致的索引失败。每日更新的频率则要求配置增量索引机制，无需每次全量重建索引以节省资源。文档类型涵盖长文本巡查记录与短字段表单，需要适配差异化的分块策略，保障语义完整性。同时，涉路施工许可等带有明确时效性的文档，需要在索引环节关联时间维度的过滤条件，确保检索结果仅包含有效信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配巡查日志、病害处置单等长文本的语义完整性 |
| 重叠长度 | 100–150 字符 | 避免分块后语义断裂，保障跨块信息连贯 |
| 相似度阈值 | 0.72–0.80 按实测标定 | 匹配公路养护场景下的专业术语语义相似度 |
| 单次召回上限 | 前10条 | 控制检索结果信息量，适配办事咨询的短平快需求 |
| `defaultToken` | 4096 | 适配多数大模型的上下文窗口，容纳多份养护工单的关联信息 |
| `maxToken` | 8192 | 应对包含桥隧监测数据的长文档索引场景 |

## 容易做错的三处
- 现象：升级FastGPT v4.17.0后，同一份包含养护工单的CSV文件无法正常分块，原有索引配置未发生变更。原因：新版本对CSV字段的解析规则进行调整，未适配养护工单中包含的多换行符自定义字段。
- 现象：知识库索引任务卡住，未完成的索引数据无法自动恢复执行。原因：未配置增量索引触发机制，全量索引因每日更新的大量巡查日志数据超时中断。
- 现象：办事咨询检索结果中出现已过期的涉路施工许可文档。原因：未在索引配置中添加时间范围过滤条件，导致旧数据未被自动清理或排除。

## 怎么确认配好了
- 上传单份完整的巡查日志文档，检查分块结果是否覆盖全部核心语义，无明显截断或信息断裂。
- 模拟办事咨询提问，验证检索结果包含当前最新的养护计划文档，无过期或无关数据。
- 调整相似度阈值，观察检索结果的匹配精度变化，确认符合业务场景的语义匹配要求。
- 导入当日更新的病害处置单，检查索引是否自动完成增量同步，无需触发全量重建。
