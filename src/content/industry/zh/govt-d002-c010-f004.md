# 公路养护与路产路权管理的办事咨询与答复：工作流编排

## 这个品类的数据长什么样
公路养护与路产路权管理的业务数据通常来自公路养护管理系统、桥隧监测系统、路政巡查系统、交通流量监测数据，更新频率为每日。日常文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单，字段涵盖路段编号、病害类型、位置坐标、施工范围、申请主体信息等，部分文档包含现场照片附件。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的接入要求工作流需适配不同系统的输出格式，需通过`variables`配置统一的字段映射规则。每日更新的数据需要配置定时触发的工作流节点，确保咨询时的文档为最新状态。不同文档的字段差异较大，需针对养护、路政两类业务分别配置提取规则，避免混淆不同类型的业务数据。同时，文档包含的照片附件需适配内部访问的域名格式，避免外部链接无法在内部系统使用。此外，工作流需预留校验环节，确保提取的字段符合业务要求，降低后续出错风险。

## 配置怎么定
本文档适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 问题分类节点 | 按养护、路政两类业务配置分类规则 | 日常文档分为养护、路政两大类别，匹配业务咨询的核心场景 |
| `variables` | 提取路段编号、位置坐标、申请主体信息 | 日常文档包含这些字段，用于精准匹配用户咨询的具体业务 |
| 单次搜索上限 | 前5条 | 每日生成的文档数量可控，过多结果会增加响应延迟 |
| 最大上下文 | 800–1200字符 | 用户咨询的涉路事项、养护问题通常集中在特定范围，过长上下文会干扰匹配 |
| 工作流超时阈值 | 600秒 | 单条业务文档的处理流程通常不超过10分钟 |
| `nodeId` | 绑定每日数据同步节点的id | 需每日更新业务文档，关联对应节点实现自动同步 |

## 容易做错的三处
- 开启图片上传功能后，返回的链接为ip加端口格式，无法在内部系统正常访问。原因是未配置图片上传域名替换的工作流节点，默认使用部署环境的ip端口地址。
- 问题分类节点的匹配结果不符合业务场景，例如将路面病害分类为涉路施工事项。原因是未按养护、路政两类业务配置分类规则，直接使用通用分类逻辑。
- 工作流运行时报错包含`$schema`字段异常提示。原因是未正确配置`variables`的字段结构，导致传入的参数不符合预设格式。

## 怎么确认配好了
- 触发一次涉路施工许可的测试咨询请求，检查返回的匹配文档是否包含对应路段的施工范围信息。
- 上传一张路面病害的现场照片，检查返回的图片链接是否为自有域名格式。
- 运行一次绑定了`nodeId`的数据同步节点，检查`variables`中提取的路段编号字段是否完整。
- 触发一次路面养护的测试咨询，验证问题分类节点的输出结果是否匹配养护类别。
