# 公路养护与路产路权管理的办事咨询与答复：工具调用与插件

## 这个品类的数据长什么样
数据来源包括公路养护管理系统、桥隧监测系统、路政巡查系统、交通流量监测数据，更新频率为每日。日常文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单，数据字段匹配对应业务单据的标准标识与数值单位，包含设施位置、状态参数、审批节点、处置记录等核心内容。

## 这些特征在「工具调用与插件」这一环带来什么约束
每日更新的业务数据要求工具调用需实时拉取最新的巡查日志与病害数据，避免使用过期信息。多系统来源的异构数据需要插件适配不同系统的API接口格式与权限规则。复杂的业务单据结构要求工具调用需按单据类型拆分参数，通过`functionCall`适配不同系统的调用格式，确保传递的字段与系统要求一致。涉路施工与路产损坏的审批流程涉及多节点状态，工具调用需准确传递对应状态参数，否则会导致流程异常。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 设为`auto` | 允许系统自动匹配养护业务场景下的工具 |
| `functionCall` | 按实测标定 | 适配不同养护单据的调用参数格式 |
| 工具调用超时时间 | 600 秒 | 匹配路政巡查数据的常规拉取延迟 |
| 单次工具调用上限 | 前 8 条 | 避免单次拉取过多历史巡查日志导致超时 |
| 工具调用结果缓存 | 按日更新 | 匹配业务数据的日更新频率 |

## 容易做错的三处
- 调用工具时返回`400 InternalError.Algo.InvalidParameter`，原因是未按养护单据的字段格式传递参数，例如遗漏了设施位置的公里桩号标识。
- 工具调用返回结果为空，原因是设置的单次调用上限过低，未拉取到最新的病害处置单或巡查日志。
- 时间关联的工具调用报错，原因是未适配养护工单的日更新时间节点，参数格式不符合目标系统的要求。

## 怎么确认配好了
- 发起模拟调用养护计划的工具请求，检查返回的参数是否匹配目标系统的字段格式。
- 触发工具调用拉取当日巡查日志，确认返回条数符合设置的单次调用上限。
- 查看工具调用日志，确认未触发超时报错，且参数传递符合配置要求。
- 验证涉路施工许可的工具调用，确认审批状态参数传递正确，无格式错误。
