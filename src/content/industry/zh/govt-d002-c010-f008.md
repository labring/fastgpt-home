# 公路养护与路产路权管理的办事咨询与答复：文档解析与分块

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
该品类的日常文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单等，数据来源多为公路养护管理系统、桥隧监测系统、路政巡查系统及交通流量监测工具，每日同步更新业务数据。文档结构混合结构化表格与非结构化文本，字段多包含设施编号、病害类型、处置流程节点、许可编号等标识类与状态类信息，不同系统导出的文档格式存在差异。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于数据来源多系统且每日批量更新，文档格式不统一，解析环节需适配混合格式的批量文档。巡查日志与病害处置单存在强业务关联，分块时需避免拆分同一份工单的关联内容，否则会导致检索时无法匹配完整业务流程。部分文档包含高分辨率巡查图片与复杂表格，解析时需保留原有结构信息，否则会丢失关键数据。批量文档的单次上传量较大，需控制单文件解析时长，避免任务超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配养护日志、病害处置单的单段业务描述长度，避免拆分跨工单的关联内容 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配文档中的养护计划章节、巡查日志条目等结构化结构 |
| `customPdfParse` | 启用 | 适配系统导出的带固定表头的PDF文档，保留表格列对齐与图片标注信息 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 应对批量的桥隧监测PDF和高分辨率巡查图片文档的解析耗时 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单次上传整月的巡查日志批量文档 |
| `chunkSettingMode` | 手动配置 | 针对涉路施工许可、路产损坏赔偿单等不同文档类型调整分块规则 |

## 容易做错的三处
- 上传批量巡查日志后，知识库检索结果仅返回部分文档内容，未覆盖完整业务条目，原因：未调整`chunkSize`参数，默认分块长度过短，导致同一份工单的关联内容被拆分至不同块中。
- 导入含多表格的病害处置单后，表格单元格内容被打散为零散文本，无法匹配完整处置流程，原因：未启用`customPdfParse`，默认解析逻辑未保留表格结构信息。
- 配置文档解析节点后，部分大型涉路施工许可文档未被索引，任务日志显示超时错误，原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认时长不足以完成复杂格式文档的解析。

## 怎么确认配好了
- 上传单份病害处置单文档，查看解析后的文本块，确认表格内容以完整单元格组形式呈现，未被打散。
- 上传批量的月度巡查日志文档，等待解析完成后，检查任务日志中无超时报错与格式解析失败提示。
- 检索包含特定公路设施编号的内容，确认返回的文本块包含该设施对应的完整巡查记录与处置流程。
- 调整`chunkSize`参数至不同区间后，对比检索结果的覆盖范围，确认关联业务内容未被过度拆分。
