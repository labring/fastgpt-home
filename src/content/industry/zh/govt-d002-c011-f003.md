# 养老、工伤、失业待遇核定的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源于社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为每日。日常处理的文档包含待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料，整体结构以表单类填报内容和证明类核验材料为主，字段覆盖缴费时长、待遇核算参数、资格核验条件等，文档长度随申请类型变化，无固定统一标准。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源多系统且每日更新，要求多轮对话需按数据源分类关联上下文，避免跨系统数据混淆。日常文档类型多样，多轮对话需按养老、工伤、失业待遇类型分别引导用户上传对应材料，避免材料错配。字段覆盖缴费时长、待遇核算参数等，提示词需明确要求分步提取对应核验字段，适配最耗时的核算与审核环节，同时需同步提示最新数据的校验逻辑，确保对话过程中调用的是当日更新的数据源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 覆盖多份待遇申请材料的完整内容，避免截断丢失缴费年限、资格核验等关键信息 |
| 问题优化 | 开启 | 将用户模糊的咨询转化为明确的待遇类型核验请求，适配多轮对话的分步引导逻辑 |
| `variables` | 绑定社保经办系统专属变量池 | 区分养老、工伤、失业三类待遇的核算参数，避免全局变量冲突 |
| 单次搜索上限 | 前3条 | 核心数据集中于近期缴费记录与认定材料，过多结果会干扰关键信息提取 |
| `messages` | 保留最近10轮对话上下文 | 关联用户前期提交的材料编号、身份信息，避免重复询问同一内容 |
| 重排 | 按实测标定 | 优先匹配缴费年限、待遇标准类的关键信息，适配业务核心核验需求 |

## 容易做错的三处
- 现象：FastGPT v4.17.0界面中提示词配置或全局变量选项仅显示两个。原因：未正确切换至对应应用的编辑模式，或未开启高级配置开关。
- 现象：对话过程中触发Cannot read properties of null (reading 'q)报错。原因：未正确绑定`chatId`参数，或上下文队列中存在空的对话消息字段。
- 现象：无法在对话中分别上传身份证正面和反面材料。原因：未配置多文件上传的分类入口，未按材料类型设置独立的上传触发规则。

## 怎么确认配好了
- 进入应用的配置页面，检查`variables`参数是否绑定了对应社保系统的专属变量池，确认变量数量符合业务需求。
- 发起模拟咨询，输入养老待遇核定的相关问题，查看对话上下文是否保留了最近10轮的交互内容，确认`messages`参数配置生效。
- 上传多份不同类型的待遇申请材料，查看系统是否按材料类型分类识别，确认问题优化与重排配置适配业务核验逻辑。
- 测试不同权限的密钥调用，确认全局变量与应用专属变量的调用范围符合配置要求，避免出现权限异常。
