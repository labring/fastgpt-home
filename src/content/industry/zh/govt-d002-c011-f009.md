# 养老、工伤、失业待遇核定的办事咨询与答复：模型接入与配置

本文配置基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类数据主要来自社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为每日。日常涉及的业务文档包括待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料。数据字段包含个人参保信息、缴费年限记录、待遇核算依据、资格审核材料等，无统一固定计量标准，需匹配对应经办场景的业务规则。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据来源要求模型接入环节支持跨系统接口对接，避免数据割裂影响咨询答复准确性。每日更新频率要求配置定时同步任务，确保模型调用时使用的是最新的待遇核算与资格审核数据。多样的业务文档结构要求模型适配不同格式的材料解析，准确提取缴费年限、工伤认定结果等核心字段。非标准化的业务字段要求配置环节预留字段映射规则，适配不同经办机构的文档格式差异。待遇错发漏发的风险要求接入环节增加结果校验逻辑，避免模型输出错误的待遇核算结论。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 需承载多份社保经办文档、缴费记录的上下文，避免关键业务信息被截断 |
| `maxTokens` | 2000–3000 token | 确保待遇核算、资格审核的答复内容完整，同时控制单轮响应耗时 |
| `temperature` | 0.1–0.3 | 待遇核定类咨询需要严谨的结果，降低随机性，避免输出无依据的待遇标准 |
| `AIPROXY_API_ENDPOINT` | 内网部署的代理地址 | FastGPT服务器处于内网环境时，通过内网代理对接大模型API，规避公网访问限制 |
| `toolChoice` | auto | 根据用户咨询内容自动选择是否调用工具查询社保数据，提升答复准确性 |

## 容易做错的三处
- 现象：调用大模型API时出现连接超时错误，返回状态码504或“无法访问目标地址”。原因：FastGPT部署服务器处于内网环境，未配置内网代理对接公网大模型API，无法建立通信链路。
- 现象：模型输出的待遇核算结果与社保经办规则存在偏差。原因：未针对缴费年限、工伤认定结果等核心字段配置映射规则，直接提取非标准化文档内容，导致信息解析错误。
- 现象：模型响应未包含思维过程，仅展示最终结论。原因：未开启对应配置项，或选择的大模型未适配思维链返回格式，无法输出中间推理步骤。

## 怎么确认配好了
- 在内网环境下测试调用大模型API，确认无连接超时或域名解析错误。
- 上传一份待遇申领表与缴费年限证明的组合文档，测试模型能否准确提取核心字段并生成符合业务逻辑的答复。
- 调整`temperature`参数至0.2左右，多次测试同一咨询问题，确认答复结果无明显随机偏差。
- 查看模型响应日志，确认已加载的上下文信息完整，未出现关键业务内容截断。
