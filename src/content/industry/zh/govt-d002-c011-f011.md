# 养老、工伤、失业待遇核定的办事咨询与答复：表单与交互

## 这个品类的数据长什么样
本品类的数据来源于社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为每日。日常关联文档包含待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料。数据字段涵盖缴费年限、待遇核算标准、资格审核条件等，单位涉及月、元、人次等，文档结构多为结构化表单与证明材料组合，需关联多系统的跨域数据完成校验。

## 这些特征在「表单与交互」这一环带来什么约束
数据来源多系统跨域，要求表单交互环节需支持多数据源的字段联动校验，避免跨系统数据不一致。更新频率每日，意味着交互界面需实时拉取最新的个人权益记录与待遇核算参数，确保咨询答复的准确性。日常文档包含结构化表单与证明材料，要求表单支持分段上传、字段必填校验，匹配不同待遇类型的专属字段要求。资格条件与待遇标准字段的专业性，要求交互环节提供明确的字段说明与合规提示，减少用户填报错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 表单输入校验规则 | 按业务文档字段设置必填项与格式校验 | 匹配待遇申领表、缴费年限证明等文档的结构化字段要求 |
| `formInput` 触发时机 | 完成上一节点数据校验后触发 | 确保交互环节仅在前置数据合规时启动，避免无效请求 |
| 用户可选数据源 | 限定为已接入的社保系统数据选项 | 减少用户输入错误，匹配跨系统数据来源 |
| 单次搜索上限 | 前5条 | 聚焦核心待遇核算相关的知识库内容，避免信息过载 |
| 上下文窗口 | 1000–1500 token | 承载缴费年限、资格条件等核心业务数据，确保答复的上下文完整性 |
| 表单校验超时 | 600秒 | 覆盖长流程的多字段校验需求，避免中途中断 |

## 容易做错的三处
- 调试预览界面出现`quote type error`报错，提示变量格式异常。原因是未按照业务文档的字段格式配置变量引用，未匹配缴费年限、待遇标准等字段的正确引用规则。
- 表单节点无法被其他业务链路复用，无法实现跨分支跳转调用。原因是未正确配置`userSelect`的节点复用规则，仅设置了单链路绑定，未开放跨分支调用权限。
- 开启输入引导并配置自定义词库后，调试界面出现报错或无响应。原因是自定义词库内容未匹配业务文档的标准术语，导致词库校验失败，触发异常中断。

## 怎么确认配好了
本页面基于FastGPT v4.17.0版本配置。
- 调用表单节点，校验必填字段的提示是否匹配业务文档的要求。
- 触发`formInput`节点，确认跨系统数据联动校验正常生效。
- 导入自定义词库，核对词库内容与业务文档术语的一致性。
- 模拟多分支跳转，确认表单节点可被不同链路正常调用。
