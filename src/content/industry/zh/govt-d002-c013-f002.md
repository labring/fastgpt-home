# 内控评价、审计与整改的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自中央企业内控部门、审计部、财务部、下属企业及外部审计机构的业务系统，涵盖内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明等文档。数据更新以年度为固定周期，临时专项审计项目的数据更新无固定节奏。文档同时包含结构化字段与非结构化文本，结构化字段包含问题编号、整改责任人、完成时限等，非结构化文本包含审计发现细节、整改佐证材料的具体内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来明确约束。年度更新的低频数据无需高频增量索引，可采用全量重建模式降低资源消耗。同时包含结构化字段与非结构化文本的文档，需同时支持文本块向量与结构化字段索引，适配多维度检索需求。多来源系统的异构数据格式，需先完成格式对齐再进行分块处理，避免分块逻辑混乱。审计相关文档涉及敏感业务内容，向量存储需适配企业内部数据安全管控要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配审计工作底稿、整改台账等文档的单段核心内容长度，避免分块过碎丢失上下文或过长导致向量精度下降 |
| 重叠长度 | 50–80 字符 | 保留相邻分块的重叠内容，确保跨分块的审计问题描述能被完整匹配 |
| `maxToken` | 4096 token | 适配多数主流向量模型的输入长度限制，避免因超出阈值导致索引失败 |
| 相似度阈值 | 0.72–0.85 | 匹配审计问题的语义相似度需求，过滤低相关的历史整改记录与问题清单 |
| 单次搜索上限 | 前 10 条 | 控制检索返回结果数量，适配审计整改跟踪的多结果核对场景 |
| `defaultToken` | 1024 token | 作为默认分块的最大token配额，平衡文本完整性与向量存储效率 |

## 容易做错的三处
- 现象：数据集内的索引数量随时间自动增多，原本单组数据对应单组索引，后期变为多组。原因：未关闭增量索引开关，年度全量更新时重复触发增量同步，导致索引重复生成。
- 现象：配置`text-embedding-3-large`后索引任务长时间卡在「索引中」状态，注释模型后重启服务仍未恢复。原因：未配置向量模型的访问密钥或企业内网网络权限，导致模型调用失败后任务未正确终止，残留阻塞进程。
- 现象：问答对提取任务长时间处于「索引中」状态，无法变为已就绪。原因：分块长度设置超出向量模型的最大输入限制，导致分块文本无法完成向量化，任务陷入阻塞。

## 怎么确认配好了
- 查看FastGPT v4.17.0版本下的向量模型调用日志，确认分块文本的token数量未超出`maxToken`限制。
- 手动触发小批量源数据的索引任务，检查任务完成状态是否正常。
- 检索测试用的审计问题，确认返回结果的相似度符合业务场景的匹配要求。
- 核对最终索引数量与源数据数量是否匹配，确认无重复索引生成。
