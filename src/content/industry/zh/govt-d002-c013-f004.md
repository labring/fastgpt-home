# 内控评价、审计与整改的办事咨询与答复：工作流编排

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类的数据来自中央企业内控部门、审计部、财务部、下属企业及外部审计机构的日常业务系统，包括企业内控系统、ERP、财务共享系统、审计管理系统、采购合同项目系统。日常生成的文档包含内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据更新频率为年度，核心字段涵盖审计问题类别、整改时限、佐证材料编号等，无高频实时更新需求，数据结构随年度审计周期调整。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据更新频率为年度，工作流无需高频触发，可按固定审计周期编排节点。多系统数据源要求工作流需配置跨系统对接节点，确保不同来源的文档可统一流转。多样的日常文档结构要求工作流需配置字段映射节点，适配不同文档的字段差异。最耗时的抽取业务样本和凭证、形成审计问题和整改要求、跟踪整改佐证和销号环节，需在工作流中设置独立的长耗时节点，并配置超时与重试机制，避免流程阻塞。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` 作用范围 | 全局存储，不随对话清空 | 业务数据更新频率为年度，需留存全局默认参数如审计周期、整改标准 |
| 节点超时设置 | `600 秒` | 抽取业务样本、凭证核验环节耗时较长，避免流程提前终止 |
| 知识库绑定规则 | 按`nodeId`绑定对应业务系统知识库 | 不同审计环节对应不同数据源，需精准关联对应文档库 |
| 变量映射配置 | 将审计问题清单字段映射至整改台账字段 | 匹配日常文档的字段结构，确保数据流转准确 |
| 重试触发条件 | 节点返回状态码≥500时触发，重试`3次` | 应对跨系统对接时可能出现的异常请求，避免无效重试 |
| 全局变量初始化 | 固定值初始化，如`整改完成率阈值=95%` | 统一业务执行标准，避免单次对话参数不一致 |

## 容易做错的三处
- 现象：配置`variables`时未开启全局存储，对话结束后变量被清空。原因：未将变量作用范围设置为全局，仅作用于单次对话流程，无法留存审计周期等固定参数。
- 现象：将应用变量绑定至知识库节点时出现报错。原因：未按`nodeId`指定对应业务系统的知识库，变量与知识库的关联配置缺失，导致系统无法识别绑定目标。
- 现象：Http请求输出多变量后，无法将指定变量关联至对应知识库。原因：未配置变量与知识库的映射规则，未按日常文档的字段匹配要求绑定，导致变量无法正确触发知识库调用。

## 怎么确认配好了
- 触发一次审计凭证抽取节点，查看`variables`中是否留存了全局默认的审计周期参数。
- 提交测试用的审计通知书，检查知识库节点是否按`nodeId`绑定了对应数据源的文档。
- 模拟节点返回500状态码，验证工作流是否触发重试机制。
- 导入整改台账模板，检查变量映射是否正确匹配了问题清单字段。
