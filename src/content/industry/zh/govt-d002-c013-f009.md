# 内控评价、审计与整改的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本场景面向国央企内控部门、审计部、财务部及外部审计机构的办事咨询与答复需求，数据主要来自企业内控系统、ERP、财务共享系统、审计管理系统、采购合同项目系统。日常处理的文档包括内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据更新周期为年度，核心文档包含问题条目、整改要求、佐证材料等字段，部分文档为非结构化格式，需从文本中抽取关键信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
年度集中更新的业务数据要求模型接入支持批量处理的上下文配额，避免长文档截断导致核心信息丢失。非结构化的审计工作底稿、整改台账需模型精准抽取结构化字段，对参数的严谨性提出要求。数据来源分散于多套内部系统，需确保接入配置兼容多渠道数据调用。整改销号证明需与对应问题清单关联验证，需配置合理的上下文召回逻辑。该品类以发现问题和整改流程为核心，侧重事后检查与证据抽样，出错后果严重，需严格控制模型输出的准确性，防止参数偏差引发审计问题漏判或误判。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配审计工作底稿、整改台账等长文档的上下文需求，避免截断核心业务信息 |
| `maxTokens` | `2000–3000 token` | 满足整改要求、问题清单的结构化输出长度，覆盖完整的整改流程描述 |
| `quoteMaxToken` | `1500 token` | 确保召回的审计证据、整改佐证材料足够支撑问题分析，不超出上下文配额 |
| `temperature` | `0.1–0.3` | 降低输出随机性，保障审计问题、整改要求的抽取准确性，符合内控合规的严谨性要求 |
| `toolChoice` | `auto` | 自动选择调用工具的时机，适配多系统数据的抽取与关联校验需求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应地址 | 适配分散的企业内部系统接入需求，确保数据传输的内部链路合规 |

## 容易做错的三处
- 现象：调用向量模型时提示无可用嵌入能力，或知识库调用返回空结果。原因：未将对应向量模型添加至合规的API渠道配置，且未校验模型与当前业务文档的适配性。
- 现象：测试TTS模型时提示'KokoroModel' object has no attribute 'mode'。原因：接入的模型类型与配置的调用协议不匹配，未正确识别模型的内置属性字段。
- 现象：使用指定模型提取身份证等结构化信息时返回空值。原因：未针对结构化字段抽取调整`temperature`参数，输出随机性过高无法匹配固定格式的业务信息。

## 怎么确认配好了
- 上传单份审计工作底稿，检查模型输出的问题抽取结果是否覆盖文档核心条目，调整参数直至输出符合业务预期。
- 配置多系统数据源的接入地址，验证跨系统数据的调用链路是否正常，无超时或权限报错。
- 触发整改台账的关联校验任务，检查召回的佐证材料是否与问题清单正确绑定，确认上下文关联逻辑生效。
- 查看模型调用日志，确认`maxContext`、`maxTokens`等参数的实际调用值与配置一致，无异常截断。
