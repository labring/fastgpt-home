# 医保基金监管稽核的办事咨询与答复：向量模型与索引

本文适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类数据涵盖稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书、整改报告等文档，数据来源包括医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码、举报线索。数据更新频率为月度，字段包含就医时间、费用明细、医保编码、疑点编号、违规类型、处理意见等，单位涉及金额、人次、耗材追溯码编号等。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新频率决定索引可采用增量更新策略，无需全量重建，降低计算开销。多样的文档类型覆盖结构化结算明细、半结构化工作底稿、非结构化约谈记录，需适配差异化的文本切分规则。多源数据包含短文本追溯码、长文档处理决定书，需平衡切分长度以保留完整语义单元。精准召回稽核疑点相关的规则与历史案例的需求，要求索引的召回精度匹配稽核工作的严谨性要求，避免漏判或误判导致基金损失。嵌入向量生成时需符合`maxToken`的限制，确保语义完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 覆盖稽核文档的语义单元，避免切分后关键违规信息断裂，适配Qwen3-Embedding-8B的上下文能力 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的语义关联，避免跨块的违规线索被割裂，适合月度更新的批量数据处理 |
| 相似度阈值 | 0.75–0.85 | 平衡稽核工作的严谨性与召回效率，避免误召回无关的结算数据或历史记录 |
| 单次搜索上限 | 前 10 条 | 匹配稽核人员的常规调阅范围，避免过多冗余结果增加人工筛选成本 |
| `maxToken` | 8192 | 适配Qwen3-Embedding-8B的最大上下文长度，确保嵌入向量生成时语义完整 |
| `defaultToken` | 按实测标定 | 针对不同来源的短文本（如追溯码、疑点编号）调整默认token分配，优化嵌入效果 |

## 容易做错的三处
- 现象：连接VLLM部署的Qwen3-Embedding-8B模型时出现连接超时或模型不支持的报错。原因：未在FastGPT中正确配置模型的API地址与端口，或未开启模型的嵌入服务端口映射，导致无法正常调用模型生成嵌入向量。
- 现象：知识库检索结果条数与预期不符，或出现无关的历史稽核记录。原因：未根据本品类的多源数据特征调整相似度阈值，阈值设置不合理导致误召回或召回不足，或未设置单次搜索上限导致结果冗余。
- 现象：本地部署的FastGPT磁盘占用超出预期，无法准确统计知识库存储规模。原因：未区分原文件、分割后的文件块与嵌入向量的存储路径，未定期清理过期的月度更新数据，导致磁盘空间被无效数据占用。

## 怎么确认配好了
- 通过FastGPT的模型测试工具发起嵌入请求，选取一段稽核文档文本，确认返回正常的向量数据，无报错信息。
- 选取一条具体的疑点清单样本发起检索，核对召回结果包含相关的稽核规则、历史处理记录与对应结算数据，符合业务场景需求。
- 查看知识库的存储目录，确认原文件、分割后的文本块与嵌入向量分别存储在指定路径，可通过系统磁盘工具查看各部分的占用情况。
- 触发一次增量索引更新，确认仅处理当月新增的稽核文档与结算数据，符合月度更新的节奏要求。
