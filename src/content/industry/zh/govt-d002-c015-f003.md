# 医保基金监管稽核的办事咨询与答复：多轮对话与提示词

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类数据来自医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索，更新频率为月度。日常处理的文档包含稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书、整改报告，核心字段涵盖违规行为类型、涉及费用范围、经办机构信息、定点医药机构资质信息等，数据以结构化结算字段与非结构化文档内容结合的形式存在。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
月度更新的监管规则库要求多轮对话上下文需定期同步最新规则条目，避免引用过期判定标准。数据包含结构化结算字段与非结构化文档内容，提示词需明确区分两类数据的调用逻辑，确保结构化字段的精准匹配与非结构化文档的逐段校验。事后稽核的业务属性要求多轮对话按检查流程逐步推进，需保留疑点清单、约谈记录等历史环节的上下文，同时因违规认定后果直接关联基金损失，对话需固化每一轮的判定依据，防止歧义。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 保留最近12轮历史消息，单轮不超过8000–12000 字符 | 医保稽核流程多为多步骤检查，保留近12轮可覆盖完整检查逻辑，避免上下文过载 |
| `variables` | 绑定月度更新的监管规则ID、定点机构资质字段 | 需动态调用最新规则与机构信息，确保判定标准与当前合规要求一致 |
| 最大上下文长度 | 8000–12000 字符 | 需容纳单份稽核通知书、对应结算数据及疑点清单的完整内容，同时避免超出模型处理上限 |
| 问题优化 | 开启，按实测标定 | 稽核对话需逐步拆解复杂疑点，问题优化可将模糊诉求转化为结构化的疑点排查指令 |
| 单次搜索上限 | 前6条匹配结果 | 需聚焦核心疑点，避免无关数据干扰违规判定 |
| `chatId` | 绑定对应稽核事项的唯一标识 | 确保对话上下文仅关联当前稽核任务，防止跨任务数据混淆 |

## 容易做错的三处
- 现象：对话历史显示“没有权限操作此对话记录”，原因：未通过`variables`绑定对应稽核事项的权限范围，导致上下文调用时触发权限校验拦截。
- 现象：多轮对话中无法召回最新月度更新的监管规则，原因：未配置定时同步绑定的规则库变量，仍使用旧版规则参数。
- 现象：回答末尾自动添加知识库引用且无法取消，原因：未关闭对话场景下的自动引用配置，误将通用知识库引用规则应用于稽核专用数据。

## 怎么确认配好了
- 发起新的稽核对话，输入历史疑点清单关键词，核对返回内容包含对应月度更新的监管规则。
- 查看对话历史，确认仅保留最近12轮以内的`messages`内容，无冗余历史消息。
- 尝试修改绑定的`variables`规则ID，核对对话判定逻辑同步更新。
- 发起违规判定请求，确认回答未自动添加知识库引用条目。
