# 医保基金监管稽核的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索，更新频率为每月一次。日常处理的文档包含稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书、整改报告，字段多涉及定点医药机构信息、参保人员身份、费用明细、违规认定依据等，无统一标准化单一条目格式，需适配多源异构的非结构化与半结构化数据。本页面适配FastGPT v4.17.0版本。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入时需适配不同格式的文档解析，月更的更新节奏决定了知识库同步周期无需过短，需匹配监管工作的月度稽核节奏。涉及的违规认定、费用核算等专业内容，要求配置时需关联内置的基金监管规则库作为知识库来源，避免通用知识偏差。同时，稽核类文档涉及敏感的监管数据，接入配置需优先保障数据权限隔离，且需支持对疑点清单、处理决定书等核心文档的精准召回。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配稽核类文档的长文本上下文需求，覆盖多份疑点清单、检查工作底稿的关联内容 |
| `maxTokens` | 4000 token | 控制单轮答复的输出长度，匹配稽核答复的结构化输出要求，避免内容冗余 |
| `quoteMaxToken` | 2000 token | 限制召回知识库内容的总长度，确保核心监管规则、结算数据片段可完整嵌入上下文 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具，适配稽核中需要核对结算数据、追溯码信息的场景 |
| `temperature` | 0.2–0.4 | 降低答复的随机性，保障稽核结论的严谨性，符合监管业务的合规要求 |
| `AIPROXY_API_ENDPOINT` | 按实测标定 | 适配本地或第三方合规API的接入需求，满足医保数据的本地化部署要求 |

## 容易做错的三处
- 现象：触发人工转接请求后，答复仍为大模型输出，未切换至人工客服通道。原因：未配置触发人工转接的规则条件，或未将转接逻辑绑定至稽核咨询的特定触发词。
- 现象：本地部署的模型答复内容未同步服务器最新的医保监管规则。原因：未配置知识库的自动同步触发时机，或同步周期未匹配月更的监管规则更新节奏。
- 现象：调用API时返回未授权错误。原因：API密钥配置错误，或密钥权限未覆盖稽核数据的访问范围。

## 怎么确认配好了
- 手动上传一份稽核通知书文档，测试模型能否精准召回关联的基金监管规则内容，核对召回的知识库片段是否匹配文档字段。
- 配置测试对话，输入包含违规认定相关的咨询问题，查看答复是否触发工具调用逻辑，验证自动工具选择是否生效。
- 调整`temperature`参数值，对比不同取值下的答复一致性，确认参数对输出严谨性的影响符合业务预期。
- 触发知识库同步任务，查看同步日志是否显示成功更新监管规则库，验证配置的同步周期是否匹配月度更新节奏。
