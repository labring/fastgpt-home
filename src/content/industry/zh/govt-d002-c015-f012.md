# 医保基金监管稽核的办事咨询与答复：部署与升级

## 这个品类的数据长什么样
本品类数据来源包括医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索，更新频率为月度。日常处理的文档包含稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书、整改报告。数据字段涵盖稽核主体、违规事项描述、关联结算单号、追溯码标识等，单条文档内容跨度从数百字符到数千字符不等，结构化数据与非结构化文档混合存在。

## 这些特征在「部署与升级」这一环带来什么约束
月度批量更新的批量数据要求部署环节配置足够的并发连接缓冲，避免单次同步超时中断。多源混合的数据格式需要部署时预设适配不同类型数据的解析规则，确保稽核记录、结算数据等均可正常接入。固定格式的稽核类文档要求升级环节同步更新字段提取模板，避免后续处理缺失关键信息。同时，涉及违规认定的敏感数据要求升级时同步调整权限管控配置，确保数据访问符合合规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `10–15` | 匹配月度批量同步的数据库连接并发需求，避免连接池耗尽 |
| `MONGODB_URI` | `mongodb://用户名:密码@地址:27017/fastgpt` | 存储稽核记录、疑点清单等非结构化文档与结构化元数据 |
| `REDIS_URL` | `redis://:自定义密码@本地地址:6379/0` | 缓存高频访问的基金监管规则库数据，降低重复查询开销 |
| `STORAGE_S3_ENDPOINT` | `http://本地对象存储IP:9000` | 存储药品耗材追溯码相关的二进制文件与扫描件 |
| `FILE_TOKEN_KEY` | 按FastGPT v4.17.0官方指引生成的随机32位字符串 | 加密处理涉及违规金额的敏感文档下载链接 |

## 容易做错的三处
- 现象：本地部署M3E作为索引模型时，界面显示模型未找到报错。原因：未在部署环节配置本地M3E服务的正确调用地址，未绑定对应模型的访问路径。
- 现象：批量同步月度医保结算数据时出现504超时错误。原因：未调整`DB_MAX_LINK`配置，并发连接数不足导致同步任务超时。
- 现象：上传处理决定书后，关联结算单号字段为空。原因：未预设对应文档的字段提取规则，未在部署环节配置文档解析模板。

## 怎么确认配好了
- 执行单次批量同步测试任务，查看数据库连接日志无连接池溢出报错。
- 上传一份标准稽核通知书文档，确认解析后字段完整且可被检索。
- 访问配置的`STORAGE_S3_ENDPOINT`，验证药品耗材追溯码文件可正常上传与下载。
- 调用代码执行节点，测试基金监管规则的本地调用无异常报错。
