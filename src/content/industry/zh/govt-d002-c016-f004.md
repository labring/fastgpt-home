# 医保费用结算审核的办事咨询与答复：工作流编排

## 这个品类的数据长什么样
数据来源包括全国医疗保障信息平台、医院HIS与医保接口、医保目录和编码库、异地就医结算平台，更新频率为日。日常处理的文档包含医保结算清单、费用明细、病案首页、处方、拒付清单、结算对账单，字段涵盖结算单号、参保人身份标识、诊疗项目编码、耗材编码、费用金额、拒付原因等，其中编码类字段为16位数字串，费用金额单位为元，结算单据单份大小通常不超过10 MB。本配置说明基于FastGPT v4.17.0版本。

## 这些特征在「工作流编排」这一环带来什么约束
日更的数据要求工作流需配置定时同步节点，确保每日更新的医保目录与结算数据保持一致。多类型文档结构差异要求工作流需为不同文档配置专属解析规则，避免字段提取错误。单笔或批量结算单的处理需求，要求工作流支持分支判断逻辑，适配单条与批量单据的并行/串行处理。编码匹配与一致性审核的高耗时环节，要求工作流可调用外部医保目录接口，同时配置超时与重试机制，避免流程阻塞。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 预设医保目录接口地址、结算单解析模板、接口密钥 | 统一管理公共数据源配置，避免每个节点重复录入参数 |
| `nodeId` | 按业务流程顺序绑定节点：接收单据→解析单据→编码匹配→费用审核→结果反馈 | 匹配医保费用结算审核的串行业务逻辑，确保流程按顺序执行 |
| 批量处理上限 | 前100条 | 适配单次上传的常规结算单数量，避免单节点过载 |
| 超时阈值 | 600秒 | 覆盖跨区域医保接口调用的正常延迟时长，减少误触发异常流程 |
| 结果渲染格式 | 适配接收端的Markdown精简模式 | 确保不同渠道的消息展示符合规范，避免格式错乱 |
| 异常触发规则 | 按接口返回错误码触发 | 精准捕获编码匹配、接口调用等环节的异常，触发后续申诉对账流程 |

## 容易做错的三处
- 现象：工作流中`variables`未正确绑定，编码匹配节点返回空结果。原因：未在全局变量配置页提前录入接口密钥与基础地址，节点调用时未引用预设的`variables`参数。
- 现象：批量上传多份结算单后仅处理第一条单据。原因：未配置批量分支节点，未按`nodeId`依次绑定每个单据的解析节点，导致流程仅执行一次。
- 现象：微信端收到的审核结果包含冗余Markdown语法标记。原因：未配置结果节点的微信端格式适配规则，直接输出原始Markdown内容，未隐藏非必要的格式标记。

## 怎么确认配好了
- 触发测试用的单条结算单上传请求，检查`variables`参数是否自动带入接口调用环节。
- 批量上传5份测试结算单文档，确认每个单据都进入对应的解析与审核节点，无遗漏。
- 模拟医保接口调用超时场景，确认异常处理节点触发并生成对应的错误日志。
- 生成审核结果并通过测试渠道发送，确认格式符合接收端的展示要求，无冗余标记。
