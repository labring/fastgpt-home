# 医疗机构监督与公共卫生检查的办事咨询与答复：工具调用与插件

## 这个品类的数据长什么样
本品类数据主要来自卫生监督信息系统、医疗机构电子化注册系统、投诉举报平台与执法检查记录，更新频率为月度。日常处理的文档包含监督检查表、医疗机构执业许可证、整改通知书、监督意见书、处罚案卷，单份文档字段涵盖机构名称、许可范围、执法人员信息、整改要求、处罚依据等，无统一固定单位，部分字段需匹配机构注册信息进行校验。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且月度更新，工具调用需对接多系统接口，需适配不同文档格式的解析。日常文档包含资质类与执法类两类，工具需支持结构化字段提取与非结构化文本解析。执法检查记录与处罚案卷是高频调用的合规类数据，需保证调用的准确性，避免遗漏关键资质信息。月度更新的数据需定期同步工具调用的数据源，防止使用过期信息生成答复。办事咨询与答复场景需快速响应，工具调用的响应时长需适配政务场景的等待要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配办事咨询场景下的动态工具调用需求，自动判断是否需要调用工具 |
| `functionCall` | 开启 | 强制模型遵循工具调用规范，避免直接生成答复而不调用工具 |
| 插件超时设置 | `600 秒` | 本品类数据来源多为政务系统，接口响应可能存在延迟，600秒可覆盖多数同步调用场景 |
| 知识库召回上限 | 前8条 | 日常文档字段较多，召回过多会超出上下文限制，前8条可覆盖主要资质与执法信息 |
| 文档分块长度 | `800–1200 字符` | 监督检查表、处罚案卷等文档结构复杂，该分块长度可保留完整字段信息，避免拆分导致的字段断裂 |
| 问题优化 | 开启 | 办事咨询的用户问题可能表述模糊，优化后可更精准匹配工具与知识库内容 |

## 容易做错的三处
- 现象：调用工具时选择工具失败，模型直接生成非工具调用的答复。原因：未开启`functionCall`配置，模型未被强制遵循工具调用规范。
- 现象：知识库聊天返回的<Reference>字段为空。原因：未配置正确的数据源召回上限，或卫生监督信息系统的月度数据未完成同步更新。
- 现象：Doc2x插件处理上传的语料无有效输出。原因：未指定语料对应本品类的文档类型，或未适配文档的格式与字段结构。

## 怎么确认配好了
- 发起一条关于医疗机构执业资质的咨询，查看模型是否主动调用工具获取对应系统的信息。
- 检查工具调用日志，确认`toolChoice`参数为`auto`且`functionCall`处于开启状态。
- 上传一份监督检查表至插件，查看插件是否能正确提取机构名称、许可范围等字段。
- 等待1分钟后发起重复咨询，确认知识库的月度更新数据已同步至工具调用数据源。
