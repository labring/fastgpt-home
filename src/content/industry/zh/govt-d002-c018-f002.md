# 参保登记与缴费核定的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自社会保险经办系统、税务社保费征收系统、市场主体登记信息及公安民政共享数据。日常处理的文档包括参保登记表、缴费基数申报表、人员增减表、社保费核定单与个人权益记录，单份文档包含人员身份标识、缴费基数、增减人员清单等结构化与半结构化字段。数据更新频率为每日，核心字段需与多系统实时对齐，确保参保与缴费信息一致。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源数据接入要求索引需支持结构化与半结构化文档混合解析，避免字段错位。每日更新的特性要求增量索引机制，避免全量重建消耗过多资源。单份文档包含人员身份、缴费基数等敏感且精准的字段，向量分块需保留字段关联性，防止拆分后丢失身份匹配依据。同时，索引的召回逻辑需匹配业务字段的语义关联，确保办事咨询答复的准确性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配单份业务文档的字段组长度，避免拆分后丢失人员身份关联 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的字段重叠，防止跨块的人员信息被割裂 |
| `maxToken` | 8192 token | 适配向量模型的输入上限，确保完整解析缴费核定单的完整内容 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非业务相关文档，避免身份匹配错误 |
| 单次搜索上限 | 前 10 条 | 控制返回结果数量，适配办事咨询的快速答复需求 |
| `defaultToken` | 按实测标定 | 适配基础参保信息的向量生成需求 |

## 容易做错的三处
- 索引过程持续超时，界面显示请求超时提示。原因是未启用增量索引，全量扫描每日更新的社保数据导致耗时过长。
- 向量化后的人员增减表字段为空，导出数据集无有效内容。原因是未开启结构化文档解析开关，导致字段无法被正确提取与向量化。
- Docker Compose部署环境中无法添加索引数据源，平台提示连接失败。原因是未在docker-compose.yml中配置向量数据库的端口映射与环境变量，导致平台无法访问索引服务。

## 怎么确认配好了
- 上传单份参保登记表，检查向量生成后的分块是否保留人员身份号字段的完整性。
- 触发一次增量索引任务，核对任务耗时无明显异常，无全量扫描的系统提示。
- 输入测试咨询问题，比如“某单位近期的缴费核定情况”，检查返回结果是否包含对应文档的关键业务字段。
- 查看向量数据库的存储统计，确认每日仅同步新增的社保数据，未重复处理历史文档。
