# 参保登记与缴费核定的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源于社会保险经办系统、税务社保费征收系统、市场主体登记信息及公安民政共享数据，更新频率为每日。日常文档包含参保登记表、缴费基数申报表、人员增减表、社保费核定单、个人权益记录，字段涵盖人员身份标识、参保单位信息、缴费基数、人员增减状态、核定缴费金额等，单位涉及元、人次、单位统一社会信用代码等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类多源数据来源要求多轮对话需逐步引导用户补充不同系统的关联信息，避免因单源数据缺失导致核定错误；每日更新频率要求对话中需明确提示数据时效性，防止用户使用过期信息办理业务；多类结构化文档要求提示词需指定读取文档的具体类型，避免召回无关的待遇核定类内容；字段复杂度要求多轮对话需按顺序确认每个必填字段，减少信息混淆。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 问题优化 | 开启，按实测标定的触发阈值 | 参保登记场景问题常含模糊表述，需优化后精准匹配知识库文档 |
| 最大上下文 | 前10轮对话上下文 | 参保数据多为结构化字段，过多历史会干扰当前缴费核定的信息核对 |
| 单次搜索上限 | 前6条召回结果 | 避免过多冗余数据混淆人员身份、缴费基数的核对逻辑 |
| 重排 | 开启，按字段匹配度排序 | 优先召回与参保身份、缴费核定直接相关的文档内容 |
| 变量替换 | 开启，绑定`variables`参数 | 自动填充用户提供的单位编号、人员身份证号等结构化字段 |
| 对话ID绑定 | 仅绑定当前会话`chatId` | 避免跨会话数据混淆，保障会话安全性 |
| 对话历史截断 | 按3000 token截断 | 防止上下文过长导致模型推理超时或页面加载异常 |

## 容易做错的三处
- 对话组件报错“出现未捕获的异常”，表现为调用时弹出红色报错弹窗，原因是未正确配置多源系统的数据源关联，导致调用参数缺失。
- 生成的回复未参考知识库文档，表现为参保登记指引未包含本地文档中的人员增减流程，原因是未正确传递`messages`参数绑定知识库召回结果。
- 对话页面崩溃，表现为加载后界面无响应或报错“页面崩溃”，原因是未限制`chatId`关联的上下文长度，导致内存占用过高。

## 怎么确认配好了
- 发起测试对话，输入模糊问题如“怎么给新员工办理参保登记”，检查回复是否包含本地文档中的人员增减表填写要求。
- 查看后台日志，确认`variables`参数已正确传递用户提供的单位信息字段。
- 模拟连续5轮对话，检查是否出现未捕获异常或页面崩溃情况。
- 输入税务系统的缴费核定单号，验证是否能关联召回社保经办系统的参保记录。
