# 参保登记与缴费核定的办事咨询与答复：工作流编排

## 这个品类的数据长什么样
本品类的数据来自社会保险经办系统、税务社保费征收系统、市场主体登记信息、公安民政数据共享，更新频率为每日。日常处理的文档包括参保登记表、缴费基数申报表、人员增减表、社保费核定单、个人权益记录。数据字段包含单位主体标识、人员身份信息、缴费基数、核定缴费金额等，每份文档对应单批次或单单位的参保缴费相关业务，数据结构随业务办理节点动态调整。

## 这些特征在「工作流编排」这一环带来什么约束
每日更新的数据源要求工作流触发频率匹配同步节奏，避免跨周期数据混用。多源异构数据需在工作流中配置跨系统数据拉取节点，确保身份、缴费等信息的一致性。文档类型多样，需在工作流中设置文档格式校验节点，识别参保登记表、人员增减表等不同表单的必填字段。数据关联劳动关系与身份信息，要求工作流中配置身份核验与劳动关系匹配环节，减少后续出错风险。同时，缴费核定结果需与税务征收数据对账，需在工作流末尾添加对账校验节点，确保数据匹配。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量配置 | 绑定`variables`为日更数据的系统标识 | 匹配数据每日更新的同步节奏，避免使用过期数据 |
| 节点顺序编排 | 按`nodeId`依次配置身份核验、缴费核定、对账校验节点 | 遵循业务办理的先后逻辑，确保数据流转顺序正确 |
| 文档格式校验 | 预设参保登记表、人员增减表等表单的必填字段规则 | 适配日常处理的多类业务文档，过滤格式错误的提交内容 |
| 错误重试策略 | 单次调用重试2次，间隔60秒 | 应对跨系统数据拉取的临时网络波动，降低调用失败率 |
| 知识库关联设置 | 绑定全局知识库ID至`variables` | 支持工作流调用知识库内容辅助办事咨询答复 |

## 容易做错的三处
- 现象：调用工作流上传参保登记表时返回字段为空的报错。原因：未在工作流中配置文档格式校验节点，未过滤非预设字段的上传内容。
- 现象：传入知识库后提示无法引用指定资源。原因：未将知识库ID正确绑定至`variables`全局变量，工作流无法获取知识库访问权限。
- 现象：工作流执行超时，状态码返回504。原因：未设置合理的重试策略，跨系统拉取多源数据时未拆分并行节点，导致执行时长超出阈值。

## 怎么确认配好了
- 手动触发工作流，上传一份标准参保登记表，检查节点是否按预设顺序执行。
- 查看工作流日志，确认`variables`全局变量已成功绑定数据源标识与知识库ID。
- 模拟跨系统数据拉取，检查身份核验节点是否能匹配人员身份与劳动关系信息。
- 执行对账校验环节，确认工作流能触发税务数据的比对逻辑。
