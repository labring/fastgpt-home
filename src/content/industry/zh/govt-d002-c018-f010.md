# 参保登记与缴费核定的办事咨询与答复：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源于社会保险经办系统、税务社保费征收系统、市场主体登记信息及公安民政共享数据，更新频率为每日。日常涉及的文档包括参保登记表、缴费基数申报表、人员增减表、社保费核定单、个人权益记录，文档结构以结构化表单为主，包含单位标识、人员身份信息、缴费相关参数、核定结果等字段，单位涉及元、人次等基础计量单元。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的数据要求检索系统支持增量索引同步，避免全量重建带来的性能损耗。多源跨系统的数据来源，要求检索环节需对齐不同系统的字段格式，避免因字段命名差异导致匹配失效。结构化为主的文档类型，要求检索需兼顾语义匹配与结构化字段的权重配置，优先匹配人员身份、单位信息等核心校验字段。出错后果严重的业务属性，要求召回结果需具备较高的置信度，避免遗漏关键核对信息导致后续流程出错。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配参保身份、缴费核定等核心字段的精度要求，平衡召回率与精准度 |
| `limit` | 前8条 | 覆盖人员增减、基数申报、核定单等多类文档的批量核对需求，避免单条结果不足 |
| `searchMode` | hybrid | 结合多源系统的结构化字段与自然语言咨询的语义匹配，适配跨数据源的检索场景 |
| `usingReRank` | 开启 | 对召回的前10条结果重排，修正单纯语义匹配的偏差，优化结构化字段的排序权重 |
| `datasetSearchUsingExtensionQuery` | 开启 | 对用户咨询的社保问题补充单位、人员身份等上下文关键词，提升跨系统数据的匹配度 |
| `collectionIds` | 对应参保登记与缴费核定类知识库的集合ID | 限定检索范围，避免混入待遇核定等其他品类的文档 |

## 容易做错的三处
- 现象：知识库召回结果与用户咨询的参保或缴费问题不匹配，返回无关的待遇核定类文档。原因：未正确配置`collectionIds`，检索范围未限定在本品类的知识库集合内。
- 现象：语义检索得分显示在0-1区间，但部分高得分结果未包含用户所需的人员身份或缴费核定信息。原因：未开启`usingReRank`，单纯依赖原始语义相似度排序，未对结构化字段的匹配权重进行调整。
- 现象：检索返回的结果条数不足，无法覆盖用户咨询的全部关联文档。原因：`limit`参数设置过低，未覆盖多类业务文档的召回需求。

## 怎么确认配好了
- 查看检索预览日志，核对召回结果的来源文档是否属于参保登记、缴费核定类业务范畴。
- 测试包含人员身份证号、单位名称的咨询问题，确认召回结果优先匹配核心身份字段。
- 验证`usingReRank`开启后，高得分结果的相关性符合业务预期，无明显无关文档前置。
- 检查`datasetSearchUsingExtensionQuery`是否自动补充上下文关键词，可通过检索测试界面查看扩展后的查询文本。
