# 双随机、一公开监管检查的办事咨询与答复：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自双随机、一公开监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库。日常生成的文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示。数据更新节奏为月度，核心字段涵盖监管对象统一社会信用代码、执法人员编号、检查事项编码、检查时间、整改完成状态等，字段格式与监管系统原生输出保持一致，无额外自定义字段单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
月度更新的数据源要求工具调用需支持定时同步检查对象与执法人员名单，避免使用过期数据。多类型文档的混合调用需插件支持按文档类型自动匹配对应接口，例如抽查结果公示需对接公示系统API，现场检查记录需关联执法终端数据。字段格式与监管系统一致的要求，需插件在请求参数中严格匹配原生字段名，不得擅自修改字段映射规则。单次调用需覆盖单批次抽查任务的全量相关数据，避免拆分调用导致的任务不完整。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多类型监管文档的自动函数调用需求，无需手动指定调用工具 |
| 会话上下文保留时长 | 3600 秒 | 匹配单批次抽查任务的处理周期，确保同批次检查的咨询与答复处于同一会话 |
| 请求重试次数 | 2–3 次 | 应对监管系统接口偶发的波动，避免单次调用失败导致任务中断 |
| 参数映射校验开关 | 开启 | 确保调用参数与监管系统原生字段格式完全匹配，防止字段不兼容报错 |
| 单次调用数据上限 | 1000 条 | 适配监管系统接口的单次返回限制，避免数据过载导致超时 |
| `functionCall` | 按接口文档定义的参数顺序传参 | 严格遵循监管平台API的参数规则，保证请求合法性 |

## 容易做错的三处
-  同批次监管检查的咨询答复出现会话中断，后续发起的同批次检查咨询无法复用之前的上下文信息。原因是会话上下文保留时长设置过短，未匹配单批次抽查任务的处理周期。
-  执法人员名单字段无法正确传递到HTTP请求组件，请求体中对应字段为空。原因是参数映射校验开关未开启，未对传入字段与监管系统原生格式进行匹配校验。
-  调用监管平台接口返回`Request failed`报错，请求状态码为500。原因是单次调用数据上限设置过高，超出监管系统接口的单次返回限制，导致接口过载报错。

## 怎么确认配好了
-  发起一次针对单条检查对象的咨询请求，查看会话历史中是否保留了本次任务的所有上下文信息。
-  配置参数映射规则后，手动触发一次测试调用，检查HTTP请求体中的字段是否与监管系统原生字段完全一致。
-  设置单次调用数据上限为100条，发起批量调用测试，确认接口返回数据完整且无超时报错。
-  查看工具调用日志，确认`toolChoice`参数被自动识别为调用对应监管系统接口。
