# 国库集中支付与报销审核的办事咨询与答复：工具调用与插件

## 这个品类的数据长什么样
本品类涉及的数据包含支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证等文档。数据来源为国库集中支付系统、预算管理一体化系统、电子发票平台、合同管理系统，每日更新。单份文档包含预算指标编码、经济分类代码、票据金额、合同编号、验收节点信息等字段，字段需匹配财政管理规范的固定格式，无自定义扩展字段的空间。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据来源分散且需每日同步，工具调用需适配多系统接口的鉴权与数据格式转换。文档字段需严格匹配财政规范，工具调用的入参需严格校验预算指标、经济分类等必填字段，避免格式错误导致审核不通过。单笔支付关联的合规校验逻辑复杂，工具调用需覆盖票据、合同、验收链条的联动校验，且需处理退单、支付更正等异常场景的回调处理逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 本品类需根据不同业务场景（如支付申请审核、报销校验）自动选择调用工具，无需固定调用单一函数 |
| `functionCall` | `enabled` | 需强制模型调用指定工具完成合规校验，避免生成非结构化答复 |
| 工具调用超时时间 | `600 秒` | 本品类的支付与报销审核需对接多系统查询数据，600秒可覆盖跨系统数据拉取的常规耗时 |
| 入参校验开关 | 开启 | 本品类文档字段需严格匹配财政规范，开启校验可提前过滤格式错误的入参 |
| 日志输出级别 | 详细 | 本品类出错后果严重，详细日志可快速定位审核失败的环节 |

## 容易做错的三处
- 工具调用节点无法添加连接线，界面无小圆圈：FastGPT v4.17.0中，当`toolChoice`被设置为`none`时，工作流节点无法创建连接线。
- MCP辅助模型思考时间过长：未配置`functionCall`的参数约束，导致模型反复尝试无效的工具调用逻辑。
- 无法查看MCP服务详细日志：未开启工具调用的详细日志输出级别，仅保留了基础日志。

## 怎么确认配好了
- 打开工作流的工具调用节点，检查`toolChoice`的设置是否为`auto`或指定函数，确认节点可正常创建连接线。
- 提交测试用的支付申请数据，触发工具调用，查看是否返回符合财政规范的校验结果。
- 进入工作流运行日志页面，查看是否包含工具调用的详细请求与响应数据。
- 调整`functionCall`的配置，验证模型是否仅调用指定工具完成审核任务。
