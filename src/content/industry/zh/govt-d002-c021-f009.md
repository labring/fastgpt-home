# 国库集中支付与报销审核的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自国库集中支付系统、预算管理一体化系统、电子发票平台、合同管理系统，更新频率为每日。日常处理的文档包括支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，各文档包含预算指标、经济分类、票据金额、合同条款、验收节点等字段，单笔数据关联资金支付的全链条信息，无跨品类的汇总统计类字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源多为业务系统的结构化字段与半结构化文档，且需核对单笔资金的合规性，模型接入需优先保证上下文的精准匹配，避免泛化推理导致的合规风险。每日更新的全量数据需控制批量处理的资源占用，避免超时。单笔数据关联的多类文档需在检索时按业务链条关联，不能仅按关键词匹配。同时，出错后果涉及资金安全，配置需严格限制模型的自由生成范围，确保答复仅基于已有的业务数据。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单笔业务关联的多份文档总长度，避免截断关键的预算指标与合同条款 |
| `maxTokens` | 2000–3000 token | 控制单轮答复的输出长度，确保合规性说明与业务依据清晰完整 |
| `quoteMaxToken` | 1500 token | 限制引用文档的总token占比，优先保留核心的票据与支付凭证内容 |
| `toolChoice` | none | 避免模型调用外部工具，确保答复仅基于配置的知识库内容，防止越权操作 |
| `temperature` | 0.1–0.3 | 降低泛化能力，保证答复严格匹配业务数据，避免生成无依据的合规判断 |
| `AIPROXY_API_TOKEN` | 按平台分配的密钥填写 | 完成模型调用的身份验证，保障接口安全 |

## 容易做错的三处
- 现象为模型直接返回知识库无匹配内容的拒绝话术，未尝试基于已有知识推理。原因是未正确配置`temperature`参数，或误将`toolChoice`设为强制仅检索，导致泛化推理被关闭。
- 现象为模型调用接口返回认证失败的报错。原因是未正确填写`AIPROXY_API_TOKEN`，或使用了过期的密钥信息。
- 现象为检索返回的文档与业务场景不匹配，如混淆预算指标与报销金额的字段。原因是未按业务链条关联多系统数据，仅按关键词匹配导致召回错误。

## 怎么确认配好了
- 提交测试用的支付申请与报销审批单数据，核对模型返回的内容是否包含对应的业务字段，确认匹配逻辑符合预期。
- 触发模型调用，检查接口日志，确认`AIPROXY_API_TOKEN`的连通性正常，无认证报错。
- 调整`temperature`参数的取值区间，对比两次答复的内容差异，确认泛化程度符合合规要求。
- 模拟知识库无匹配内容的场景，检查模型返回的提示是否符合预设的合规话术，无额外生成内容。
