# 国库集中支付与报销审核的办事咨询与答复：表单与交互

## 这个品类的数据长什么样
本品类数据来自国库集中支付系统、预算管理一体化系统、电子发票平台、合同管理系统，更新频率为每日。日常处理的文档包括支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，核心字段包含预算指标、经济分类编码、票据校验码、合同编号、验收单编号等，单笔数据关联多类业务单据，需覆盖支付执行全链条的合规校验信息。

## 这些特征在「表单与交互」这一环带来什么约束
多系统来源的数据要求表单与交互环节支持跨数据源的字段自动匹配与校验，避免人工录入误差。单日更新的预算指标要求交互环节实时拉取最新可用额度，防止超预算提交。多类关联单据的结构要求表单按业务场景分块展示输入项，避免字段堆砌。单笔数据关联多单据的特性要求交互环节支持批量导入与校验，同时需对输入内容做合规性前置检查，防止不符合财经纪律的内容进入流程。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的官方说明。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `formInput` | 按业务单据拆分的多组输入模块 | 适配本品类支付申请、报销单等多类文档的输入结构，避免字段堆砌 |
| 用户输入长度限制 | 800–1200 字符 | 覆盖单笔业务的核心说明内容，防止超长输入导致的解析异常 |
| `userSelect` | 预设财政标准化编码选项库 | 减少人工录入误差，匹配国库系统的字段格式要求 |
| 交互超时阈值 | 600 秒 | 适配多单据关联校验的处理时长，避免中途中断 |
| 单次检索结果上限 | 前5条 | 覆盖核心业务单据的关联信息，避免冗余内容干扰审核 |
| 上下文传递阈值 | 2000 token | 适配多轮对话的财政业务信息传递，避免上下文溢出 |

## 容易做错的三处
- 现象：输出内容中包含「引用标记：［1］」字样。原因：未关闭知识库检索结果的来源标记自动插入设置，导致检索到的文档来源标识被带入最终回复。
- 现象：指定关键词触发后未调用外部接口，仍返回AI原生回答。原因：未正确绑定`userSelect`的触发条件与外部接口回调，未配置拦截规则的生效范围。
- 现象：解析10万中文字word或15000行excel时，返回不完整命令提示。原因：未拆分长文档为适配的输入块，未配置多轮对话的上下文传递规则，导致单次输入超出处理上限。

## 怎么确认配好了
- 提交一笔模拟的支付申请单据，核对输入模块是否按合同、发票、验收单等单据拆分展示，无字段堆砌。
- 输入超出预设长度的测试文本，确认系统触发对应长度限制的拦截提示。
- 触发预设的合规关键词测试，确认系统跳转至绑定的外部接口回调流程。
- 上传大容量测试文档，确认系统自动拆分内容并完成多轮对话的上下文传递。
