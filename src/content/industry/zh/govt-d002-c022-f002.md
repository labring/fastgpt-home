# 土地使用权、矿业权与国有产权交易的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
该品类的典型数据来自全国公共资源交易平台、自然资源交易系统、产权交易所系统及国资监管系统，通常每日更新。日常文档包含出让公告、交易须知、竞买申请、保证金凭证、成交确认书、挂牌结果公告、产权转让说明书等，结构多包含权属说明、交易条件、竞价规则、保证金要求等核心字段，部分文档带有结构化表格，如保证金金额、标的位置、转让底价等内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且更新频繁，要求索引支持增量同步与快速更新；文档包含结构化表格与层级化内容，需适配多向量解析以保留表格字段与层级关联；核心业务字段如权属、限制条件、保证金信息直接影响决策，要求向量召回需精准匹配这些高价值内容；同时交易数据出错后果严重，需避免因分块不当导致核心信息断裂，影响后续咨询答复的准确性。

## 配置怎么定
针对该品类的业务特征，推荐以下向量模型与索引配置：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块最大长度 | 800–1200 字符 | 匹配该品类交易文档的单段核心信息长度，避免拆分破坏权属、竞价规则等完整逻辑 |
| 分块重叠长度 | 100–200 字符 | 保留跨分块的标的关联信息，防止因分块断裂导致的上下文丢失 |
| 最大段落深度 | 3 | 适配交易文档的层级结构，如公告下的子章节、条款分组，符合通用配置经验 |
| `maxToken` | 8192 | 适配主流Embedding模型的上下文限制，平衡单条向量的信息密度与召回效率 |
| `defaultToken` | 1024 | 控制单条分块的token数量，避免超出模型输入限制，同时覆盖核心业务字段的信息长度 |

## 容易做错的三处
常见配置错误及对应原因如下：
- 刷新知识库页面后提示“检测到没有可用的索引模型”，原因是未将对应Embedding模型绑定至该品类的知识库，或模型配置未完成保存生效。
- 表格数据无法正常生成多向量，原因是未在知识库设置中开启表格多向量解析开关，未正确识别保证金凭证、成交确认书中的结构化字段。
- 调用API触发索引创建时返回参数错误，原因是未按界面配置的分块最大长度调整API入参，或`maxToken`设置超出当前绑定模型的支持范围。

## 怎么确认配好了
可通过以下可执行动作核对配置是否生效：
- 进入FastGPT v4.17.0的知识库设置页面，确认分块参数、Embedding模型绑定状态均已保存，无红色报错提示。
- 上传一份典型交易文档（如土地出让公告），触发手动索引，查看分块结果中是否包含标的权属、交易条件等核心字段的完整内容。
- 发起测试对话，输入“某矿业权的转让限制条件”，查看召回的分块是否匹配文档中的对应内容。
- 调用FastGPT的API接口测试索引创建流程，确认返回状态码为200且无无效参数报错。
