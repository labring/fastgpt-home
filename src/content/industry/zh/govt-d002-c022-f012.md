## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据来源分散且每日更新，部署时需适配多系统数据接入与增量同步配置，避免全量拉取占用过多资源。日常文档类型多样，需针对出让公告、产权转让说明书等不同文档结构优化解析规则，保障信息提取准确性。核心字段涉及权属、保证金等敏感内容，部署环节需强化数据校验与权限隔离配置，防止信息泄露或错误调用。交易流程出错后果明确，升级时需配套完善的失败回滚与告警机制，确保异常场景下的业务连续性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150` | 该品类每日增量数据量较大，需保障数据库连接池足够支撑并发查询 |
| `MONGODB_URI` | 带读写分离后缀的专属集群地址 | 交易数据需保障读写隔离，避免查询操作影响写入性能 |
| `REDIS_URL` | 带密码认证的专属缓存地址 | 需缓存高频查询的交易规则与权属信息，降低后端数据库压力 |
| `STORAGE_S3_ENDPOINT` | 本地合规存储服务商的端点地址 | 交易文档涉及国有资产信息，需采用符合合规要求的存储服务 |
| `FILE_TOKEN_KEY` | `32位随机加密字符串` | 需保障文档下载与预览的令牌安全，防止未授权访问 |
| `ROOT_KEY` | 定期轮换的高强度密钥 | 需限制后台管理接口的访问权限，防止越权操作 |

## 容易做错的三处
- 现象：本地部署后无法自行注册账号，界面提示无权限创建新账号。原因：未正确配置`ROOT_KEY`或未开启公共注册开关，导致初始账号权限受限。
- 现象：知识库搜索响应超时，耗时超过30秒。原因：`DB_MAX_LINK`配置过低，数据库连接池耗尽，无法及时处理并发查询请求。
- 现象：Docker部署集成索引模型失败，无法加载交易文档。原因：未正确配置`STORAGE_S3_ENDPOINT`，存储端点地址错误导致文档拉取失败。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`DB_MAX_LINK`配置的连接池可正常支撑预设并发量，调整配置至符合业务峰值需求。
- 触发增量同步任务，检查每日更新的交易文档是否正常加载至知识库，确认多源数据接入配置生效。
- 发起高频搜索请求，验证搜索响应时长符合业务预期，调整缓存配置以优化查询性能。
- 尝试使用测试账号访问文档预览功能，验证`FILE_TOKEN_KEY`配置的令牌有效性，确认权限隔离规则生效。
