# 学生资助与奖补审核的办事咨询与答复：知识库检索与召回

## 这个品类的数据长什么样
本品类服务主体为教育局资助中心、学校学生处或资助办、财政部门，数据主要来自全国学生资助管理信息系统、学校学籍系统、民政低保特困数据及财政支付系统。日常处理的文档包含家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单与公示材料，数据更新以学期为周期，字段覆盖资助资格认定、学籍状态、困难认定信息、发放明细等核心内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源多系统联动，需确保跨源字段的匹配一致性，因此检索需优先关联学籍号、资助申请编号等唯一标识，避免张冠李戴的匹配结果。学期周期的更新节奏要求知识库需定期全量刷新，防止过期的学期内评审或发放数据被召回。文档类型包含结构化表单与非结构化公示文本，需区分两类内容的召回规则，保障资格核验的精准性。资助资格核验依赖精准匹配，召回结果需严格对应申请主体的具体状态，不可泛化匹配无关信息。公示材料的公开属性要求召回结果需符合合规性校验，避免泄露未完成公示的内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配资助资格相关的精准字段，避免低相似度的无关结果干扰资格核验 |
| `limit` | 前8条 | 覆盖单学期内的申请、评审与发放全流程文档，同时控制上下文长度 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配结构化表单字段与非结构化公示文本的混合召回需求 |
| `usingReRank` | 开启 | 对初始召回结果进行重排，优先匹配学生主体的学籍与困难认定关联信息 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展问题关键词，补充学籍号、资助类别等业务专属字段，提升精准度 |
| `collectionIds` | 按学期划分的数据集ID | 按更新周期隔离数据，避免跨学期过期数据被召回 |

## 容易做错的三处
- 现象为导入的家庭经济困难认定表显示「已就绪」但检索时无匹配数据，原因是文档分块时未保留学生学号、家庭收入证明编号等关键字段，或导入时未关联对应业务数据集。
- 现象为检索结果包含跨学期的过期发放名单，原因是未按学期划分`collectionIds`，导致召回了更新周期外的旧数据。
- 现象为检索返回的结果条数超出预期，原因是未设置`limit`参数，或`similarity`阈值设置过低，召回了大量低相似度的无关文档。

## 怎么确认配好了
- 上传单份标准资助申请表文档，触发检索后核对返回结果是否包含申请表内的关键字段信息。
- 调整`similarity`阈值后，验证低相似度的无关文档是否被过滤，高匹配度的资格认定文档是否优先返回。
- 按学期划分数据集并配置`collectionIds`，检索学期内的申请数据，验证是否仅召回对应周期的文档。
- 开启`usingReRank`后，核对重排后的结果是否优先匹配学生主体的学籍与困难认定关联信息。
