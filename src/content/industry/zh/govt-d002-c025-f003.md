# 安全生产隐患排查治理的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据来自安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常涉及的文档包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单。数据字段包含隐患编号、排查时间、责任主体、整改期限、整改状态等，单位涵盖天（整改期限）、条（隐患条目数）等，不同文档的字段结构存在差异，部分文档需关联跨系统的关联数据。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且多系统关联，要求多轮对话需先明确用户查询的具体系统、所属单位及时间范围，避免返回无关数据。更新频率为每日，提示词需引导用户优先使用最新的排查与整改记录，确保查询结果时效性。文档类型多样且字段结构差异大，多轮交互需逐步引导用户明确查询的文档类型，避免混淆排查清单与整改台账的查询逻辑。字段包含明确的时间与责任主体要求，提示词需预设必要的参数字段，减少用户需补充的信息项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 前8轮对话内容+当前查询 | 依据隐患排查数据需追溯排查时间、责任主体等历史信息，避免重复提问 |
| `variables` | 预设隐患排查清单、整改台账、整改通知书的标准字段 | 依据品类文档字段固定，提前绑定变量减少多轮交互的信息获取步骤 |
| `messages` | 按用户查询逐步补充隐患相关参数 | 依据数据来源分散，需多轮获取具体系统、单位、时间范围等信息 |
| 单次匹配记录上限 | 前3条 | 依据隐患数据条目较多，优先返回最新或高优先级的排查与整改记录 |
| 超时时间 | 600秒 | 依据隐患排查流程涉及跨系统查询，耗时较长，避免提前中断对话 |
| 问题优化 | 按实测标定 | 依据不同用户的提问方式存在差异，需适配安全生产领域的专业术语 |

## 容易做错的三处
- 对话返回401 No auth credentials found。原因是未在配置中绑定安全生产监管系统或企业自查系统的访问凭证，导致多轮对话调用外部数据时权限校验失败。
- 多轮对话无法获取完整的隐患整改期限参数。原因是未在`variables`中预设整改期限字段，导致提示词无法引导用户补充必要的查询参数。
- 语音输入后无文字转化结果。原因是未正确配置语音转写的触发逻辑，导致多轮对话链路中语音转写环节未正常衔接，无法将语音内容转化为可处理的文本。

## 怎么确认配好了
- 模拟用户提问“请查询XX园区2024年5月的隐患排查清单”，检查对话是否能逐步引导补充具体单位、时间范围等必要参数。
- 调用FastGPT v4.17.0的接口，验证返回结果是否包含隐患排查清单的标准字段，无缺失或错误的关联数据。
- 触发外部数据调用，检查是否出现401报错，确认权限配置正确。
- 测试语音输入功能，验证转写后的文字是否能正确进入多轮对话链路，参与后续的参数补充与查询逻辑。
