# 工程建设项目审批的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于工程建设项目审批管理系统、施工图审查系统、企业资质库及公共信用平台，更新频率为每日同步。日常处理的文档包含施工许可申请材料、施工图审查合格书、质量安全监督手续、竣工验收备案表等，数据结构涵盖项目唯一标识、参建单位资质信息、审批节点状态、申请材料明细等字段，所有字段均遵循住建领域通用规范，无自定义特殊单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据同步需求要求配置适配不同系统的接口权限与数据格式，每日更新节奏需配置定时增量同步任务，避免数据滞后影响咨询准确性。不同类型的审批文档结构差异较大，需模型具备适配多样文本格式的上下文处理能力。参建单位资质与审批节点的精准匹配需求，对模型的信息抽取精度提出明确要求，错误的答复可能导致无证施工或竣工备案失败，因此配置需优先保障输出的严谨性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 工程审批咨询需覆盖多份审批材料与完整审批流程，足够的上下文可保障答复的连贯性 |
| `maxTokens` | `2000–3000 token` | 办事咨询答复需清晰传递审批步骤与材料要求，避免关键信息被截断 |
| `quoteMaxToken` | `1500 字符` | 需精准引用审批系统内的材料字段与官方要求，控制引用文本长度以提升可读性 |
| `temperature` | `0.2–0.4` | 审批答复需严谨准确，较低的温度参数可降低输出的随机性 |
| `vision` | 关闭 | 业务数据以文本格式为主，无需视觉处理能力 |
| `AIPROXY_API_ENDPOINT` | 填写内部代理服务的访问地址 | 适配内部网络环境，保障大模型接口调用的稳定性 |
| `AIPROXY_API_TOKEN` | 填写代理服务生成的有效认证令牌 | 保障接口调用的安全性，防止未授权访问 |

## 容易做错的三处
- 现象：更换大模型后仍提示指定模型错误，仅`llmModels`列表内第一个模型生效。原因：未在配置文件中正确更新所有关联的模型调用配置，或代理服务未同步切换目标模型。
- 现象：向量模型部署后无法通过OneAPI完成添加。原因：未配置向量模型的正确端口与访问路径，或容器网络策略限制了端口对外暴露。
- 现象：调用代理接口后出现认证失败提示。原因：未正确更新`AIPROXY_API_TOKEN`配置，或令牌已过期未重新生成。

## 怎么确认配好了
- 输入工程审批相关咨询问题，例如「施工许可申请需要哪些材料」，检查返回结果是否包含准确的官方材料清单与办理要求。
- 查看FastGPT v4.17.0的系统日志，确认大模型与向量模型的调用请求均成功返回，无超时或认证报错。
- 手动调整`maxContext`参数值，验证长文档上下文的处理效果是否符合预期。
- 检查每日数据同步任务的运行日志，确认增量数据已正确加载至知识库，无同步失败记录。
