# 工程建设项目审批的办事咨询与答复：表单与交互

## 这个品类的数据长什么样
本品类数据来源为工程建设项目审批管理系统、施工图审查系统、企业资质库、信用平台，更新频率为每日。日常文档包含施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表，核心字段包含项目唯一标识、参建单位资质编号、项目负责人执业资格证号、并联审批节点状态，数据结构围绕项目从立项到竣工的审批全流程搭建，字段格式需匹配官方业务系统的校验规则。

## 这些特征在「表单与交互」这一环带来什么约束
数据来源分散，需在表单中整合多系统的字段入口，避免用户重复录入跨系统信息。每日更新频率要求表单查询结果实时同步最新审批节点状态，确保咨询答复的准确性。日常文档按审批环节分类，表单需支持按环节加载对应字段组，减少无效信息展示。核心字段涉及资质与人员执业信息，需配置严格的输入格式校验，匹配官方库的字段规则。并联审批节点的状态变化会触发表单交互逻辑调整，需关联实时数据更新以同步当前可办理的环节。

## 配置怎么定
本文基于FastGPT v4.17.0版本进行配置说明。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` 字段校验 | 匹配官方审批文档的字段格式，如资质编号校验为18位数字 | 核心字段包含参建单位资质编号、人员执业资格证号，需与官方库格式对齐 |
| `userSelect` 知识库分组 | 按审批环节关联对应数据源知识库，如施工许可环节关联工程建设项目审批管理系统知识库 | 数据来源分散，需按审批环节匹配对应业务数据 |
| 文件上传限制 | 单次上传总大小不超过1000 MB，单文件不超过500 MB | 日常文档包含工程图纸、审批备案表等大体积材料 |
| 上下文窗口大小 | 800–1200 字符 | 审批相关咨询文本长度集中在该区间，避免冗余信息干扰问答逻辑 |
| 超时设置 | 600 秒 | 跨多系统查询数据需预留足够响应时间 |
| 表单字段分组 | 按审批环节拆分，如立项用地、施工许可、竣工验收 | 日常文档按审批环节分类，便于用户按流程填写 |

## 容易做错的三处
- 现象：表单`formInput`组件默认限制仅支持文本输入，用户无法上传施工图审查合格书等附件。原因：未针对工程建设项目审批的大体积文档调整文件上传配置，未开启多文件上传权限。
- 现象：用户输入不同审批环节的关键词后，未触发对应数据源的检索，返回结果与当前审批环节无关。原因：未配置`userSelect`按输入内容自动匹配对应知识库分组，仅固定绑定单一知识库。
- 现象：调用工作流http模块查询审批节点状态时，接口无法接收表单传入的项目编号变量。原因：未在http模块配置中正确映射表单提交的项目编号参数，导致接口接收空字段。

## 怎么确认配好了
- 填写一条符合官方格式的资质编号，校验`formInput`组件是否弹出格式错误提示，确认校验规则生效。
- 选择不同审批环节的关键词测试，确认`userSelect`组件是否自动切换至对应知识库。
- 上传一份符合体积限制的工程图纸，确认文件上传功能正常完成提交。
- 调用工作流http模块传入测试项目编号，确认接口可正常接收该参数并返回对应审批节点数据。
