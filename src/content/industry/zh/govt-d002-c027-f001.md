# 工程建设项目招投标的办事咨询与答复：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据来源于全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常业务文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告等类型，数据结构包含项目基本信息、标段划分规则、资格条件、工程量清单、评标专家记录、中标结果等核心字段，由发展改革部门、住建交通水利等行业主管部门、公共资源交易中心、招标代理等主体生成与维护。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多来源的数据平台要求接口需适配不同的认证规则与响应格式，避免因平台差异导致调用失败。每日更新的频率要求接口调用节奏需匹配数据同步周期，避免频繁请求触发平台限流。多类型业务文档需针对性配置数据提取规则，确保不同文档的核心业务字段均可被精准识别。核心字段的严格校验要求接口返回数据需包含资格条件、工程量清单等必要内容，否则将影响办事咨询的准确性。

## 配置怎么定
本配置指南基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | Bearer令牌格式，携带平台分配的API密钥 | 公共资源交易平台接口普遍要求身份认证，防止未授权访问 |
| `responseData` | 仅保留项目基本信息、中标结果等核心字段，过滤HTML格式代码 | 本品类文档包含多类型业务文件，需精准提取办事咨询所需内容 |
| `variables` | 绑定标段编号、项目名称等业务变量，支持枚举值配置 | 办事咨询需针对具体项目精准匹配数据，避免跨项目数据混淆 |
| 请求超时设置 | 600秒 | 部分地方交易平台接口响应较慢，超时过短会导致正常请求被误判为失败 |
| 重试策略 | 2次重试，间隔30秒 | 公共资源交易平台可能存在临时波动，重试可降低单次请求失败率 |
| 返回数据条数限制 | 前500条 | 本品类单条文档数据量较大，过多数据会占用上下文空间，影响咨询效率 |

## 容易做错的三处
- 现象：HTTP接口调用返回字段为空，无法提取中标结果信息。原因：未针对本品类的中标结果公告文档配置`responseData`过滤规则，导致冗余的HTML格式代码占用了有效数据空间，核心字段未被提取。
- 现象：数据库关联工作流执行时报错，无法查询到对应招标公告数据。原因：未在`variables`中绑定项目编号变量，导致SQL语句未指定具体查询条件，无法匹配到目标项目的数据。
- 现象：自定义工具的参数配置项丢失，无法设置可选变量。原因：未在`variables`中声明可选参数的枚举值范围，导致FastGPT界面未渲染对应的配置控件，无法完成变量可选性设置。

## 怎么确认配好了
- 调用测试接口，使用配置的`Authorization`令牌发起请求，检查返回结果是否包含业务文档的核心字段，无认证失败报错。
- 绑定`variables`中的项目编号变量发起查询，确认返回数据与指定项目的标段、资格条件等信息匹配。
- 触发一次异常请求，例如修改`Authorization`为无效密钥，检查是否触发配置的重试策略，或生成对应的告警记录。
- 查看`responseData`提取结果，确认已过滤冗余格式代码，仅保留办事咨询所需的核心内容。
