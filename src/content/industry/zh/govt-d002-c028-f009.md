# 市场主体登记与许可的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统及住所信息库，每日更新。日常处理的文档包含设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等，字段覆盖主体名称、住所地址、股东信息、许可类型等，文档多为结构化表单与非结构化证明材料结合的格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据每日更新要求模型接入时配置实时同步机制，避免使用过期的登记与许可数据。多类型文档混合处理要求配置适配结构化表单与非结构化材料的解析规则，确保字段提取准确性。多来源数据整合需要明确数据优先级，防止冲突信息干扰咨询答复。同时，业务场景对结果准确性要求高，需限制模型生成内容的随意性，确保答复符合登记许可的法定要求。

以下配置适用于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 需容纳多来源的登记数据、历史咨询记录与业务文档，避免上下文截断 |
| `maxTokens` | 2000–3000 token | 匹配办事咨询答复的长度需求，确保完整输出许可条件、补正要求等内容 |
| `quoteMaxToken` | 1500 token | 限制引用业务文档的长度，保证引用内容精准且不冗余 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保答复符合登记许可的法定流程与固定要求 |
| `toolChoice` | auto | 自动调用工具检索最新的登记数据与许可规则，适配实时更新的业务数据源 |
| `AIPROXY_API_ENDPOINT` | 按厂商提供的专属地址配置 | 确保模型调用的链路稳定，适配多来源数据的实时拉取需求 |

## 容易做错的三处
- 模型厂商图标加载失败：界面中模型节点的品牌图标无法正常显示，原因是FastGPT版本未适配当前厂商的图标资源路径，或本地缓存未及时更新。
- 大模型节点返回500 Gateway forwarding error：调用时出现该报错，原因是模型服务与FastGPT的连接中断，未配置稳定的代理端点或令牌校验失败。
- 工作流模型图标不显示且文件上传报错：界面中模型节点图标缺失，同时文件上传提示网络错误，原因是FastGPT版本与当前部署环境的依赖包不兼容，未正确配置文件上传的超时参数。

## 怎么确认配好了
- 检查模型调用的日志，确认能正常拉取企业登记全程电子化系统、国家企业信用信息公示系统的实时数据。
- 测试咨询答复的内容，确认引用的业务文档片段符合`quoteMaxToken`的配置限制，且无冗余内容。
- 模拟提交咨询请求，验证模型能根据配置的`temperature`参数生成符合业务规范的答复，无过度发散内容。
- 查看工作流界面的模型节点图标，确认所有厂商图标均正常加载，无异常报错提示。
