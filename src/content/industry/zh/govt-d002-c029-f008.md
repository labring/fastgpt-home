# 市容环卫与城管执法案件的办事咨询与答复：文档解析与分块

## 这个品类的数据长什么样
该品类的典型数据主体为城管执法局、街道综合执法队、环卫中心及网格员。日常生成的文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告。数据主要来自城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。文档结构多包含案件编号、责任主体、违法点位、整改要求等字段，部分文档附带图片或结构化表单内容。

## 这些特征在「文档解析与分块」这一环带来什么约束
每日更新的多源多格式数据，要求解析流程支持批量文件处理与格式兼容。现场照片与执法文书混合的文档结构，需要解析环节同时适配文本与图片内容的提取。案件编号、违法点位等核心字段的精准性要求分块策略保留关键信息的完整性，避免关键内容被拆分到不同块中。不同来源的文档格式差异，需要分块规则适配结构化表单与自由文本的不同排版，保障后续办事咨询与答复环节的召回准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 该品类文档包含结构化字段与自由文本，该区间可平衡单块信息密度与召回精度 |
| `chunkSplitter` | 按段落+标题拆分 | 执法文书多有明确章节与段落划分，保留结构可提升分块合理性 |
| `customPdfParse` | 开启 | 该品类的PDF文档多包含现场照片嵌入文本，开启后可同时提取文本与图片内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 单份执法案卷可能包含多张现场照片，解析耗时较长，该时长可避免超时失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 批量上传的巡查记录与照片包可能占用较大存储空间，该上限可适配批量处理需求 |
| `chunkSettingMode` | 手动配置 | 该品类文档格式差异较大，手动配置可针对性调整分块规则 |

本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 上传HTML格式的巡查记录或立案审批表后无解析结果。原因是默认解析配置未适配HTML格式的结构化文档，未启用HTML标签解析规则。
- 解析包含现场照片的PDF文档时，仅提取文本未识别图片内容。原因是未开启`customPdfParse`配置，或配置参数未正确关联图片提取逻辑。
- 批量上传多份执法案卷时出现解析超时。原因是`PARSE_FILE_TIMEOUT_SECONDS`配置值过低，未适配单份文档包含多张照片的解析耗时需求。

## 怎么确认配好了
- 上传单份包含文本与图片的执法案卷PDF，检查解析结果中是否同时包含文本内容与图片提取记录。
- 上传HTML格式的巡查记录文档，检查解析后的文本块是否保留原文档的段落与标题结构。
- 批量上传3-5份不同格式的执法文档，检查所有文件均显示解析完成状态，无异常报错。
- 随机抽取解析后的文本块，确认核心字段如案件编号、违法点位未被拆分至不同块中。
