# 市容环卫与城管执法案件的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
该品类数据来源为城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。日常文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告，核心字段涵盖案件编号、违法地点、违法类型、责任主体、整改要求与处置进度，部分文档附带多媒体取证素材。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类数据来源分散且包含多媒体取证素材，要求模型接入需支持视觉信息解析能力。每日更新的数据集规模稳定，需配置合理的知识库同步周期避免索引过载。多类型文档的结构差异，要求分块逻辑适配不同文档格式。案件核心字段多且关联紧密，需限制上下文长度避免冗余信息干扰模型判断。部分数据来自内网部署的执法平台，需支持自定义API端点配置。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启 | 该品类包含现场照片等多媒体取证素材，需支持视觉信息解析 |
| `maxContext` | 8000–12000 token | 案件关联文档较多，需限制上下文长度避免模型冗余判断 |
| `maxTokens` | 2000–3000 token | 答复需覆盖案件详情与处置建议，预留足够输出空间 |
| `quoteMaxToken` | 1500–2000 token | 需保留足够的原文引用空间用于佐证执法依据 |
| `temperature` | 0.3–0.5 | 执法答复需严谨，降低随机性避免出现不确定表述 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写内网或映射后的外网地址 | 适配该品类多数内网部署的执法平台与模型服务 |

## 容易做错的三处
- 现象：知识库持续处于索引状态无进度。原因：未适配该品类每日更新的数据集规模，同步周期与数据更新频率不匹配，或分块参数设置超出模型处理上限。
- 现象：模型接入提示接入点错误。原因：`AIPROXY_API_ENDPOINT`未填写内网映射后的有效外网地址，或格式不符合模型服务商要求。
- 现象：调用模型后返回网络访问失败报错。原因：内网部署的模型服务未正确映射外网地址，或`AIPROXY_API_TOKEN`配置无效导致身份验证失败。

## 怎么确认配好了
- 查看FastGPT系统日志与模型服务日志，确认无身份验证失败或端点不可达报错。
- 上传一份该品类的典型巡查记录文档，触发模型调用，检查是否能正确解析文档核心内容。
- 开启`vision`配置后，上传现场照片，确认模型能识别照片中的违法场景细节。
- 调整`temperature`参数后，对比两次相同输入的答复内容，验证参数生效逻辑。
