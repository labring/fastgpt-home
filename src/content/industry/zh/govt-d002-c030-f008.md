# 建设工程质量安全监督的办事咨询与答复：文档解析与分块

## 这个品类的数据长什么样
本品类数据主要来自工程质量安全监管系统、施工现场实名制平台、监理日志及各类检测报告。日常处理的文档包含监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告，文档多包含现场参数、整改要求、验收标准等结构化字段与具体数值单位。数据更新频率为周度，单份文档篇幅跨度较大，从几页的整改通知书到数十页的竣工验收监督报告均有覆盖。

## 这些特征在「文档解析与分块」这一环带来什么约束
周度更新的批量文档要求解析流程具备自动化适配能力，避免人工干预。多类型文档结构差异显著，需适配不同文档的排版逻辑，确保结构化字段与非结构化文本均能被准确提取。单份文档篇幅跨度大，分块时需兼顾长文档的上下文完整性与短文档的信息集中度。现场参数与整改要求等核心字段需与文档元数据绑定，避免解析后字段丢失影响后续办事咨询答复的准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 本品类文档包含结构化字段与长文本段落，该区间可平衡上下文连贯性与分块粒度 |
| `chunkSplitter` | 按段落+标题拆分 | 本品类文档多包含明确标题层级的内容，按标题拆分可保留文档逻辑结构 |
| `customPdfParse` | 开启 | 本品类PDF文档多含表格与结构化表单，自定义解析可准确提取内嵌字段 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 单份竣工验收报告篇幅较长，需预留足够解析时间 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 批量上传的监理日志与检测报告总容量较大，需适配大文件上传 |
| `chunkSettingMode` | 手动配置 | 本品类文档结构差异显著，需针对不同文档类型调整分块参数 |

## 容易做错的三处
- 现象为上传PPT文档解析时报错“the argument ‘windows-1252’ is invalid encoding”，原因是未针对多语言混合的工程文档调整编码解析配置，默认编码无法适配部分监理日志或检测报告中的非标准字符集。
- 现象为上传XLSX格式的检查记录表格后，分块结果丢失多行嵌套内容，原因是未配置适配多行表格的分块拆分规则，默认分块逻辑无法识别表格行级关联。
- 现象为PDF文档解析后核心字段为空，原因是未开启`customPdfParse`配置，默认通用解析无法提取本品类文档中内嵌的结构化表单字段。

## 怎么确认配好了
- 上传单份典型文档（如隐患整改通知书），核对解析后的文本块是否保留标题与整改要求的上下文关联，调整分块参数至符合需求的区间。
- 批量上传周度更新的监理日志文档，验证解析时长是否符合配置要求，避免出现解析中断情况。
- 上传包含多行表格的检测报告，确认分块结果是否完整提取表格行内容，调整分块拆分规则适配表格结构。
- 上传竣工验收监督报告，核对解析后的结构化字段是否被正确绑定至对应文本块，确保后续办事咨询答复可准确调用相关内容。
