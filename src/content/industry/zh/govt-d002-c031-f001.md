# 建设项目环评审批的办事咨询与答复：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据主要来自全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台及监测数据，更新频率不定期。日常关联文档包括环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复。数据字段包含项目类别、环评等级、污染防治措施、公众参与情况、审批状态等，无统一固定单位，部分字段需匹配生态环境分区管控的区域要求。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据来源多且更新无固定周期，接口需支持动态拉取不同来源的结构化与非结构化文档，需适配多系统的鉴权规则。文档类型多样，接口请求需兼容不同格式的环评文件上传与解析，需校验项目类别、环评等级等核心字段的合法性。出错后果严重，接口需增加重试机制与错误日志留存，避免因接口异常导致审批流程中断。需严格匹配生态环境分区管控的区域字段，确保请求参数符合区域环评要求。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带 Bearer 前缀的平台令牌，长度 200–500 字符 | 符合外部系统鉴权规范，避免令牌泄露风险 |
| `variables` | 传入项目ID、区域编码等环评专属字段 | 用于匹配对应区域的生态环境分区管控数据 |
| `responseData` | 仅返回审批状态、技术评估意见字段 | 减少数据传输量，适配外部系统的轻量化调用需求 |
| 超时设置 | 600 秒 | 适配环评审批数据校验的复杂计算耗时 |
| 重试次数 | 前 3 次重试间隔 30 秒 | 应对外部系统临时波动，避免单次请求失败导致流程中断 |

## 容易做错的三处
- 现象：调用接口时返回`401 Unauthorized`状态码，且`responseData`字段为空。原因：未正确在请求头中添加`Authorization`参数，或令牌格式不符合外部系统要求。
- 现象：外部系统传入全局变量后，接口无法匹配对应环评项目数据。原因：未通过`variables`参数传递项目唯一标识字段，导致系统无法关联正确的数据源。
- 现象：接口请求后返回大量非环评相关的冗余内容。原因：未限制`responseData`仅返回审批核心字段，导致传输无效数据占用带宽。

## 怎么确认配好了
- 在FastGPT平台发起测试请求，传入合法的环评项目ID，检查返回的`responseData`是否包含审批状态等核心字段。
- 查看接口调用日志，确认`Authorization`参数已正确携带，无令牌格式错误或缺失。
- 模拟外部系统传入自定义`variables`参数，验证系统是否能关联对应区域的生态环境分区管控数据。
- 发起多次重复请求，确认接口重试机制在临时网络波动时正常触发，无异常报错。
