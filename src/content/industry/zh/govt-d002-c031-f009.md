# 建设项目环评审批的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台、监测数据，更新频率不定期。日常处理的文档包括环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复，文档包含项目类别、环评等级、污染防治措施、公众参与内容、审批文号等核心字段，无固定统一的单篇长度标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
针对FastGPT v4.17.0版本的模型接入流程，本品类的数据特征会带来多项约束。多源且不定期更新的数据要求配置需适配不同格式的文档，需预留足够的上下文空间以覆盖完整审批材料。文档结构多样、字段差异大，要求模型配置需支持精准识别审批相关核心内容，避免冗余信息干扰。数据关联项目开工与审批合规性，要求模型输出需严谨准确，同时API调用需保障数据安全。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 环评报告书通常篇幅较长，需覆盖完整申报材料与审批意见，避免内容截断 |
| `maxTokens` | `2000–3000 token` | 办事咨询答复需精准输出审批相关结论，控制单轮输出长度，避免冗余 |
| `quoteMaxToken` | `1500 token` | 需保留审批文件核心引用片段，确保答复内容符合官方审批要求 |
| `temperature` | `0.2–0.4` | 环评答复需严谨准确，降低模型输出的随机性，避免出现不符合规范的内容 |
| `AIPROXY_API_ENDPOINT` | 目标模型官方指定接入地址 | 确保模型调用链路正常，完成合法的模型请求转发 |
| `AIPROXY_API_TOKEN` | 平台分配的有效身份密钥 | 完成模型调用的身份验证，保障调用合法性 |

## 容易做错的三处
- 现象：配置模型后点击测试提示错误，但引用环节可正常运行。原因：未正确配置`maxContext`参数，测试时触发上下文长度限制，而引用环节使用的文档片段未触发完整校验。
- 现象：无法找到模型参数配置入口，错误将重排相关配置放在知识库检索模块。原因：混淆了模型接入与知识库检索的配置边界，未在对应模型专属配置页面操作。
- 现象：调用模型时出现超时错误。原因：未适配环评文档的长文本特性，`maxContext`配置过小导致模型处理超时，或API端点配置错误导致链路延迟。

## 怎么确认配好了
- 进入FastGPT v4.17.0后台的模型管理页面，核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容与目标模型官方文档一致。
- 上传一份环评审批申请文档，发起测试对话，检查模型输出是否包含文档中的项目类别、环评等级等核心信息。
- 调整`temperature`参数至0.2–0.4区间，对比两次输出结果的差异，确认输出保持严谨准确。
- 查看模型调用日志，确认`maxContext`与`maxTokens`的实际使用值符合配置范围，无异常内容截断。
