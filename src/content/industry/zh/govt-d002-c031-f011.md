# 建设项目环评审批的办事咨询与答复：表单与交互

## 这个品类的数据长什么样
本品类的数据来源包括全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台、监测数据，更新频率为不定期。日常处理的文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复。数据字段包含项目类别编码、环评等级判定项、污染防治措施清单、公众参与反馈记录、审批流程节点标识等，随建设项目申报进度动态生成，无统一固定的单次更新数据量。

## 这些特征在「表单与交互」这一环带来什么约束
数据来源覆盖多系统联动，要求表单交互需支持跨系统数据拉取与实时校验，确保申报信息与分区管控成果、监测数据一致。不定期更新的特性要求表单可灵活适配新增的生态环境管控规则，无需重构整体交互逻辑。文档结构包含多页多附件的专业报告，要求表单支持分段上传、附件关联字段绑定，同时提供专业术语辅助输入。字段包含项目类别、环评等级等核心判定项，要求交互时前置合规校验，减少后续人工核对的耗时。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 按项目申报字段分组，每组不超过1200字符 | 日常处理的环评文档包含多类专业字段，分组后可降低填写复杂度，1200字符适配单页表单的展示宽度 |
| `userSelect` | 提供项目类别预选项，覆盖生态环境分区管控的10大类项目 | 项目类别是环评审批中最耗时的核对环节，预选项可减少人工判定误差，匹配现有管控规则的分类标准 |
| 单次上传附件上限 | 10 个/次 | 环境影响报告书通常包含多类支撑附件，10个可覆盖常规申报需求，避免单次上传过载 |
| 字段校验触发时机 | 填写完成后实时校验 | 核心字段如环评等级判定项需提前校验合规性，避免提交后返工，减少后续审批环节的耗时 |
| 交互上下文保留长度 | 前 3 轮交互记录 | 办事咨询场景下的交互通常围绕项目申报的特定环节，短上下文可提升响应精准度 |
| 超时时间 | 600 秒 | 办事咨询场景下的交互响应需在合理时长内完成，600秒适配跨系统数据拉取的耗时 |

## 容易做错的三处
- 现象：工作流填写完所有输入项后运行显示‘Cannot convert undefined or null to object’，原因：表单交互未配置必填字段校验，或跨系统拉取的环评数据为空时未做容错处理，导致流程节点接收未定义参数。
- 现象：办事咨询时无法触发基于项目类别的预设答复，原因：未启用`userSelect`的预选项关联逻辑，或预选项未匹配当前生态环境分区管控的分类标准。
- 现象：检索环评相关文档后仅返回单条结果用于答复，无法选择top2内容，原因：未配置检索结果的返回上限，或未将检索结果与llm处理环节绑定，导致仅调用单条结果。

## 怎么确认配好了
- 打开表单配置页面，核对`formInput`的字段分组是否匹配环评申报的官方字段清单。
- 启用`userSelect`的预选项功能，确认预选项覆盖当前生效的生态环境分区管控分类。
- 设置测试项目，提交表单后检查是否触发实时校验，无异常报错即可进入后续流程。
- 发起两轮以上办事咨询，确认交互上下文被保留并关联到后续答复。
