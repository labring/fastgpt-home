# 投资项目立项与后评价的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来自国资委投资监管系统、企业ERP和项目管理系统、行业市场数据、审计和财务报表，更新频率为季度。日常文档包含年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告、投资后评价报告，数据字段包含项目唯一标识、投资规模、审批节点、后评价核心指标等，文档按项目全生命周期分为立项筹备、实施、后评价三个阶段归档。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源跨多系统且字段口径存在差异，需要多轮对话逐步对齐不同系统的字段格式与单位；季度更新的数据集需要定期刷新上下文，避免调用过时的项目数据；文档按阶段归档的结构，要求提示词按阶段引导用户提供对应环节的材料；涉及国有资产的业务属性，要求对话过程保留完整上下文用于监管追溯；多项目并行的场景下，需要通过唯一标识区分会话上下文，避免跨项目混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 前 8000–12000 字符 | 匹配单季度归档的单项目文档总长度，避免截断关键立项与后评价材料 |
| `chatId` 绑定规则 | 按项目唯一标识绑定 | 确保同项目的多轮对话上下文不混淆，适配跨部门协作的对话场景 |
| 问题优化开关 | 开启并限定国资投资场景 | 针对投资项目的专业术语自动优化提示词，提升可研、后评价相关咨询的准确性 |
| `variables` 初始化配置 | 预设项目类型、所属监管层级变量 | 快速对齐国资监管系统的字段规范，减少多轮对话中重复确认的次数 |
| 单次工具调用上限 | 前 3 条召回结果 | 匹配季度更新的数据集规模，避免过多冗余信息干扰对话逻辑 |

## 容易做错的三处
- 工具调用结果未展示在对话界面，重新进入会话后可查看但未随对话返回结果。原因是`chatId`未绑定当前工具调用的会话上下文，导致结果未挂载到正确对话链路。
- 对话过程中频繁出现Request Time报错。原因是单次调用的上下文长度超出系统处理上限，未按季度归档的文档规模调整参数。
- 未获取到对话的`messages`参数内容，无法实现跨会话数据同步。原因是未正确配置`messages`的存储与提取规则，导致参数缺失。

## 怎么确认配好了
- 发起单项目立项咨询的多轮对话，检查上下文是否包含对应阶段的文档片段，确认`chatId`绑定的项目标识与当前会话一致。
- 触发工具调用后，查看对话界面是否返回对应可研报告、后评价报告的片段，确认单次调用结果条数符合预设上限。
- 调用本地化部署的大模型时，验证对话过程未出现超时报错，确认上下文长度匹配当前项目文档的实际规模。
- 检查iframe接入的界面语言是否为中文，确认本地化配置已生效。
