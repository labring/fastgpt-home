# 投资项目立项与后评价的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类的核心数据来自国资委投资监管系统、企业ERP和项目管理系统、行业市场数据、审计和财务报表，更新频率为季度。日常处理的文档包含年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告、投资后评价报告，各类文档结构差异明显，项目建议书包含项目背景与初步投资估算，可行性研究报告覆盖技术、市场、财务多维度分析，投资后评价报告则包含项目实施复盘与效益评估。数据字段覆盖项目编号、投资主体、立项时间、后评价得分等专有业务字段，无统一标准化格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入环节支持多格式数据的统一解析与适配，避免因文档结构差异导致的解析失败。季度更新频率要求向量库同步周期与数据更新节奏匹配，保障检索内容的时效性。长文档占比高的特点要求上下文配置预留足够的token空间，防止关键信息被截断。本品类不同于政府投资审批场景，更侧重董事会投决、负面清单和投资后评价，因此工具调用需适配投决会材料生成、后评价数据整合等专属业务流程。业务场景的高合规性要求，意味着模型输出需严格匹配国资监管的严谨性标准，避免出现国有资产损失或责任追究风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配可行性研究报告、投资后评价报告等长文档的上下文处理需求 |
| `maxTokens` | 4000 token | 平衡单轮回答长度与系统响应速度，满足投决材料生成的内容量要求 |
| `quoteMaxToken` | 1500 token | 限制单条引用文档的token占比，避免整体上下文溢出 |
| `toolChoice` | auto | 允许模型自主选择工具完成立项审批辅助、后评价数据整合等任务 |
| `temperature` | 0.3–0.5 | 降低回答随机性，确保办事咨询答复的严谨性，符合国资监管的合规要求 |
| `AIPROXY_API_ENDPOINT` | 按企业内网部署地址填写 | 适配国央企内部网络环境，保障敏感业务数据的传输安全 |
| `AIPROXY_API_TOKEN` | 按企业统一身份认证令牌配置 | 符合内部权限管控与数据安全规范 |

## 容易做错的三处
- 现象：知识库搜索返回非标准JSON格式报错。原因：未针对投资项目类文档的结构化字段做适配，导致模型解析时出现格式异常。
- 现象：工具调用无法自动选择对应工具执行任务。原因：`toolChoice`配置为固定模式，或未提供足够的业务场景描述供模型匹配工具。
- 现象：语义匹配结果无法准确关联目标投资项目。原因：未选用适配国资项目专有字段的语义匹配逻辑，或未调整匹配阈值适配项目编号、投资主体等业务字段。

- 调整`temperature`参数，测试不同取值下的回答严谨性，确保输出符合国资监管的合规要求。
