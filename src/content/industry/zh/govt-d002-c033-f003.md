# 招标采购合规管理的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自企业采购平台、公共资源交易平台、供应商库、合同管理系统与审计问题库，每日更新。日常处理的文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单及供应商投诉材料，数据字段覆盖采购主体、预算金额、采购方式、评标规则、履约验收情况等，无统一固定格式，需适配各单位内部采购体系。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类数据分散于多个内部与外部系统，多轮对话需按照采购流程节点逐步调取采购计划、评标记录等不同类型文档，避免一次性加载过多非关联数据。由于文档无统一固定格式，提示词需适配采购计划、招标文件、投诉材料等多种文档结构，分别提取对应合规校验所需字段。数据每日更新，多轮对话需确保每次调用均获取最新版本的供应商库与合同信息。合规校验环节出错后果严重，多轮对话需在每轮交互中明确校验依据，避免遗漏审计与纪检要求的核对项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口大小 | 8000–12000 字符 | 适配招标采购全流程文档的总长度，避免截断关键合规校验内容 |
| 最大对话轮次 | 前 8 轮 | 匹配采购咨询的典型交互节点，覆盖需求确认、合规校验、结果反馈全流程 |
| 上下文绑定变量 | `variables` 绑定采购主体ID | 精准调取对应单位的供应商库与采购制度数据，避免跨主体数据混淆 |
| 对话历史传递 | `messages` 按时间倒序截取 | 优先保留最新的合规校验请求与历史答复，确保交互逻辑连贯 |
| 会话标识绑定 | `chatId` 绑定采购项目编号 | 区分不同采购项目的对话上下文，避免跨项目数据串用 |
| 校验触发阈值 | 按实测标定 | 适配各单位的合规校验严格程度，避免误判或漏判 |

## 容易做错的三处
- 现象：多轮对话流程中插入的中间AI答复被追加到最终输出结果中。原因：未在对话配置中明确过滤中间环节的`messages`，导致所有交互内容均被纳入最终上下文。
- 现象：API调用对话接口时，对话日志中显示未配置的标题内容。原因：未在`variables`中关闭默认标题生成参数，或未清空接口请求中的标题字段。
- 现象：多轮对话无法准确匹配对应采购项目的合规文档。原因：未使用采购项目编号绑定`chatId`，导致上下文跨项目混淆，无法调取正确的招标文件与评标记录。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的平台发起模拟采购咨询对话，检查最终输出结果是否仅包含用户需求与最终答复，无中间环节的AI交互内容。
- 调用API接口提交测试请求，查看对话日志，确认未出现未配置的标题内容。
- 切换不同采购项目的测试数据，核对对话调取的文档是否与对应项目匹配，无跨项目数据串用情况。
- 调整上下文窗口大小的配置，测试加载长文档时的表现，确认取值符合当前业务的文档长度需求。
