# 招标采购合规管理的办事咨询与答复：工作流编排

## 这个品类的数据长什么样
本品类数据来源于企业采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，更新频率为每日。日常文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料，核心字段包括采购方式、预算金额、供应商资质条件、评分细则、履约条款等，部分文档为多页长文本，数据结构随采购项目类型存在差异。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据接入需适配不同系统的格式规范，避免出现数据解析失败的情况。每日更新的数据需在工作流中设置定时同步节点，确保合规审查使用最新的供应商库与审计问题库数据。长文档如招标文件的拆分需匹配业务逻辑，避免割裂关键合规条款。同时，涉及采购方式核对、评分办法审查等耗时环节，工作流需设置分步校验节点，降低出错风险。

## 配置怎么定
以下配置适用于FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配招标文件、评标记录等长文档的内容密度，避免单块内容过载 |
| 重叠长度 | 100–200 字符 | 保障相邻分块间的信息连贯性，防止关键合规条款被拆分在两个分块中 |
| 单次搜索上限 | 前 5 条 | 聚焦核心采购依据，避免冗余信息干扰合规审查判断 |
| 最大上下文 | 8000 token | 按实测标定，适配国央企采购文档的上下文关联需求 |
| 超时设置 | 60 秒 | 满足日常办事咨询的响应时效要求 |
| `variables` | 绑定采购项目专属字段 | 适配国央企采购的个性化数据需求，确保工作流调用精准的项目信息 |
| `nodeId` | 绑定合规校验节点ID | 确保工作流的校验环节执行顺序正确 |

## 容易做错的三处
- 工作流发布后链接显示本地地址：访问链接为`http://localhost:3000/chat/`格式，原因是未配置部署域名，直接使用本地启动环境发布工作流。
- AI输出格式不符合业务要求：返回内容无固定合规审查结构，原因是未在工作流中设置输出格式约束节点，未限定AI输出的内容范围。
- 知识库长文档召回效果不佳：长招标文件的召回关键信息缺失，原因是使用标题层级作为分隔符，未适配招标采购文档的段落与合规条款结构。

## 怎么确认配好了
- 检查工作流发布后的链接是否为正式部署域名，替换本地地址为可公网访问的地址。
- 触发工作流并输入合规审查咨询问题，验证AI输出是否符合预设的结构化格式。
- 上传单份长招标文件，检查召回的分块内容是否覆盖采购方式、预算依据等核心合规条款。
- 查看`variables`参数是否已绑定当前采购项目的专属字段，确保工作流调用的信息准确。
