# 招标采购合规管理的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源包括企业采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，每日更新。日常处理的文档涵盖采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料等，数据字段包含采购主体信息、预算金额、采购方式、评分细则、供应商资质、履约验收情况等，各文档关联对应业务流程节点，形成完整的采购合规链路数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| maxContext | 8000–12000 token | 覆盖采购计划、招标文件、评标记录等多文档的完整合规审查上下文 |
| temperature | 0.2–0.4 | 确保合规答复的严谨性，减少主观偏差 |
| quoteMaxToken | 1500–2000 字符 | 保留核心合规文档的原文引用，满足审计溯源要求 |
| toolChoice | 自动 | 支持自动调用合规校验工具，核对采购方式与预算依据 |
| vision | 关闭 | 本品类核心为文本合规咨询，无需处理图像类业务 |
| AIPROXY_API_TOKEN | 按实测标定 | 确保模型调用的身份验证有效 |

## 容易做错的三处
- 调用ollama模型返回空结果。原因是未正确配置AIPROXY_API_ENDPOINT指向ollama的本地服务地址，或未开启本地端口映射导致无法连通。
- 模型测试时无返回结果。原因是关机重启后未同时启动ollama服务，或FastGPT容器与ollama容器的网络配置不一致导致无法通信。
- 误开启vision参数并选择图像模型。原因是未明确本品类仅处理文本合规咨询，错误启用视觉能力，导致模型无法匹配业务需求。

## 怎么确认配好了
- 检查AIPROXY_API_ENDPOINT与AIPROXY_API_TOKEN的配置是否与部署的模型服务一致。
- 发起单次合规咨询测试，验证模型返回内容关联了采购计划、招标文件等核心文档的引用。
- 测试调用工具校验采购方式与预算依据，确认工具调用流程正常触发。
- 查看模型调用日志，确认返回结果的token数未超过maxContext的配置上限。
