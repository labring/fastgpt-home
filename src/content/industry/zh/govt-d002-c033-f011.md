# 招标采购合规管理的办事咨询与答复：表单与交互

## 这个品类的数据长什么样
本品类数据来自国央企采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，每日更新。日常文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料，字段涉及采购方式、预算金额、供应商资质、评分细则、履约条款等，无固定统一单位，需匹配对应业务文档的字段格式。

## 这些特征在「表单与交互」这一环带来什么约束
本品类数据来源分散且每日更新，要求表单交互支持多源数据的快速调取校验；文档类型多样，需适配不同文档的字段提取与匹配规则；涉及合规审查的敏感内容，交互环节需保障数据权限隔离；需对接采购、审计等多部门的业务系统，表单需支持跨系统数据联动；出错后果涉及串标围标、审计整改等，交互环节需增加合规校验的前置提示。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `formInput`校验规则 | 匹配采购文档字段格式 | 适配本品类采购计划、招标文件等文档的字段结构 |
| `userSelect`选项 | 包含采购方式、预算依据、供应商资格三类 | 覆盖本品类最耗时的核对环节的核心选项 |
| 分块长度 | 800–1200 字符 | 适配单份招标文件的常规篇幅，保障信息完整 |
| 最大上下文 | 6000–8000 token | 容纳多源采购相关文档的拼接内容 |
| 超时阈值 | 300 秒 | 适配跨系统调取采购数据的常规响应时长 |
| 权限隔离开关 | 按部门角色配置 | 匹配本品类涉及采购、审计等多部门的权限要求 |

## 容易做错的三处
- 现象：`formInput`字段提交后无匹配内容返回。原因：未配置对应采购文档的字段校验规则，导致输入内容无法触发数据召回。
- 现象：工作流中调用节点后，最终输出包含非预期的中间步骤内容。原因：未关闭中间节点的输出开关，导致冗余内容被带入最终结果。
- 现象：表单交互时出现超时报错。原因：超时阈值设置过短，未适配跨系统调取采购数据的响应时长。

## 怎么确认配好了
- 提交包含采购计划字段的`formInput`内容，检查是否能召回对应来源的文档数据。
- 选择`userSelect`中的采购方式选项，确认弹出的选项覆盖国央企常用的采购类型。
- 模拟跨系统调取数据的操作，验证交互环节的响应时长符合业务需求。
- 配置部门角色权限后，检查非授权角色无法访问敏感采购文档的交互内容。
