# 招生入学与学籍管理的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来自全国中小学生学籍信息管理系统、地方招生入学平台、户籍和房产数据平台、学校教务系统，更新频率为每日。日常处理的文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表，数据字段围绕学生身份、入学资格、学籍状态展开，结构固定且与学生个体强绑定。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且每日更新，要求多轮对话需绑定唯一会话标识以区分不同学生的上下文，避免跨会话数据混淆。文档结构固定且与学生个体强绑定，提示词需引导用户提供完整的身份核验信息，同时限定模型仅调用当前会话关联的知识库数据。最耗时的核验环节要求多轮对话保留足够的历史交互以追踪用户提交的材料，而严重的出错后果要求模型必须严格基于知识库内容作答，不得生成未验证的信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口 | 8000–12000 字符 | 覆盖学籍、招生相关文档的典型长度，避免截断关键核验信息 |
| 上下文历史保留轮次 | 最近6轮 | 匹配学生身份核验、材料提交的典型交互轮次，确保对话连贯性 |
| 单次召回结果数 | 前5条 | 聚焦最相关的招生、学籍数据，避免冗余信息干扰模型判断 |
| 会话标识绑定 | `chatId` | 区分不同学生的会话上下文，防止跨会话数据混淆 |
| 变量自动填充 | `variables` | 自动带入学生学籍号、报名号等个体信息，减少用户重复输入 |
| 会话超时时间 | 600 秒 | 匹配核验户籍房产的平均处理时长，避免上下文缓存过早清空 |
| 提示词约束规则 | 仅使用知识库内的招生学籍数据作答 | 匹配本品类数据的强合规性要求，避免生成未验证内容 |

## 容易做错的三处
- 不同会话或同一会话不同轮次返回的招生政策内容不一致，现象为模型输出的录取规则存在矛盾，原因是未绑定`chatId`区分会话上下文，导致调用了不匹配当前学生的知识库片段。
- 模型返回知识库外的政策解读或虚构信息，现象为提示词配置后仍出现未收录的内容，原因是提示词未明确限定仅使用本品类的知识库数据，或未开启内容校验开关。
- 核验户籍房产的对话超时后提示字段为空，现象为会话中断后无法恢复历史交互信息，原因是未设置合理的会话超时时间，导致上下文缓存被清空。

## 怎么确认配好了
- 在FastGPT v4.17.0版本下，发起包含学生学籍号的多轮对话，检查`messages`字段中是否保留了历史交互的学生身份信息。
- 输入未收录的非招生学籍类问题，检查模型是否提示无法提供相关回答。
- 查看会话日志，确认每个会话都绑定了唯一的`chatId`标识，无跨会话数据混淆的情况。
- 触发每日同步任务，检查知识库是否更新了最新的招生计划数据，确保模型调用的是当日最新信息。
- 测试变量自动填充功能，确认`variables`中带入的学生信息正确显示在对话中。
