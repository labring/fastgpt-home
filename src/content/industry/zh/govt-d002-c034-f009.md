# 招生入学与学籍管理的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据围绕学生入学与学籍流转生成，日常文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表。数据来源包括全国中小学生学籍信息管理系统、地方招生入学平台、户籍与房产数据、学校教务系统，每日更新。数据字段聚焦学生身份标识、入学资格条件、学籍异动状态、录取结果等核心信息，未包含资金类字段，核心关联户籍、房产等外部公共数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源涉及多系统跨部门同步，每日更新要求模型接入与配置需适配高频数据刷新，确保知识库能同步最新的招生计划与学籍异动信息。核心字段聚焦身份与资格核验，模型需精准匹配户籍、房产等外部数据，避免模糊匹配导致的资格判定错误。文档结构包含表单类结构化数据与政策类非结构化文本，需区分处理不同格式的输入内容，同时需保障数据关联的准确性，防止出现学籍重复或遗漏的出错后果。办事咨询场景下，用户问题多涉及政策解读与进度查询，模型需绑定对应招生计划与学籍状态数据。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配招生政策、学籍档案等长文本上下文，避免截断关键入学资格信息 |
| `maxTokens` | 2000–3000 token | 满足办事咨询答复的完整政策解读与流程说明需求，避免输出不完整 |
| `quoteMaxToken` | 1500 token | 限定引用的学籍文档、招生计划片段长度，确保引用内容精准且不冗余 |
| `toolChoice` | auto | 自动选择是否调用工具核验户籍、学籍数据，适配多场景咨询 |
| `temperature` | 0.3–0.5 | 降低随机性，保障政策解读与资格判定的一致性，符合办事场景的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写本地或第三方代理地址 | 适配多数据源接入需求，确保跨系统数据调用稳定 |
| `AIPROXY_API_TOKEN` | 与代理服务匹配的认证密钥 | 保障数据调用的安全性，防止未授权访问学籍敏感数据 |

## 容易做错的三处
- 调用语音输入相关模型时返回404错误，原因是未正确配置`AIPROXY_API_ENDPOINT`指向本地部署的Whisper服务，或代理服务未开放对应端口。
- 接入百度embedding-v1或ollama部署的bge-large-zh-v1.5时返回404错误，原因是未将模型接入地址与认证密钥正确绑定到FastGPT的代理配置中，导致请求无法正确转发。
- 模型输出的学籍信息出现重复或遗漏，原因是未设置合理的`maxContext`参数，导致上下文截断后丢失部分学籍关联数据，或未正确关联全国中小学生学籍信息管理系统的最新数据。

## 怎么确认配好了
- 发起包含学籍核验、政策咨询的测试请求，检查模型输出是否关联了对应招生计划与学籍数据。
- 查看代理服务日志，确认`AIPROXY_API_ENDPOINT`的请求被正确转发，无404或超时错误。
- 测试不同长度的咨询问题，检查模型输出未出现截断或不完整的情况。
- 模拟高频数据更新场景，确认知识库能同步最新的学籍异动与招生计划信息。
