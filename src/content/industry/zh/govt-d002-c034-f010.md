# 招生入学与学籍管理的办事咨询与答复：知识库检索与召回

## 这个品类的数据长什么样
本品类的核心数据来自全国中小学生学籍信息管理系统、地方招生入学平台、户籍和房产数据、学校教务系统，更新频率为每日更新。日常处理的文档包括入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表，数据字段围绕学生身份、户籍房产信息、学籍状态、招生名额与资格展开，由教育局基础教育科、学校教务处、招生考试机构、街道社区协同窗口维护与更新。

## 这些特征在「知识库检索与召回」这一环带来什么约束
日更的数据要求检索环节需支持近实时的数据同步，避免召回过期的学籍或招生信息。多源异构的数据来源要求检索需支持跨系统数据的关联匹配，确保学生身份、户籍房产等核心字段的一致性。多样的文档结构要求分块与编码需兼顾结构化表单、文本名册与审批表单的不同特征，避免因分块不当导致关键信息断裂。以学生资格为核心的业务逻辑要求检索需优先匹配身份类字段，避免无关信息被召回，同时需保证召回结果的准确性，防止引发学籍重复、录取争议等后果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 学籍与招生数据的字段精准性要求高，阈值过低会引入无关结果，过高可能漏召回有效信息，按实测标定 |
| `limit` | `前6条` | 单次召回的结果数量需控制在合理区间，避免上下文溢出影响答复逻辑，同时覆盖核心相关信息 |
| `usingReRank` | 开启 | 多源异构的文档结构会导致初始检索结果相关性不均，重排可优化排序逻辑，提升咨询答复的准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 招生政策与学籍规则存在固定同义表述，扩展查询可覆盖更多用户提问的同义表达，提升召回覆盖率 |
| `collectionIds` | 对应招生入学、学籍管理的数据集ID | 限定检索范围，避免无关的后勤、资助类数据被召回，聚焦本品类的核心业务数据 |

## 容易做错的三处
- 检索结果中图片无法正常展示。现象：界面返回的咨询结果中图片区域空白或显示加载失败。原因：知识库导入时仅上传图片文件，未配置可公开访问的外链地址，导致检索召回后无法加载资源。
- 语义检索返回的`similarity`得分异常偏高。现象：相似度得分普遍高于0.9，且无关结果也被召回。原因：未针对学籍、招生的结构化字段调整向量编码逻辑，导致身份类关键特征的权重被过度放大。
- 调用检索接口返回权限错误。现象：接口返回权限不足的报错文案。原因：未正确指定`collectionIds`参数，或配置的数据集未开放检索权限，导致无法访问目标知识库数据。

## 怎么确认配好了
- 发起一条测试查询，比如“转学需要提交哪些材料”，检查召回结果是否包含招生计划、转学申请相关文档的有效片段。
- 查看检索结果的`similarity`得分，确认得分分布在预设的0.75–0.85区间内，无异常偏高或偏低的情况。
- 测试包含图片的咨询查询，比如“2024年入学报名表模板”，确认结果中关联的图片可正常加载。
- 调用FastGPT v4.17.0的检索接口传入测试参数，检查返回结果的条数符合`limit`配置的前6条要求，无超出或不足的情况。
