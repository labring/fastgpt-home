# 政务服务事项目录与办事指南维护的办事咨询与答复：向量模型与索引
本文基于 FastGPT v4.17.0 版本编写。

## 这个品类的数据长什么样
政务服务事项目录与办事指南维护的日常文档包含政务服务事项基本目录、实施清单、办事指南、标准材料目录、流程图、常见问题。数据来源为国家政务服务事项基本目录、行政许可事项清单、权责清单及地方政务服务事项库，更新频率为月度。单文档长度差异较大，部分办事指南文本篇幅较长，字段通常包含事项标识、实施主体、受理条件、申请材料明细、办理流程节点等。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的频率要求索引支持高效的全量同步与增量更新机制，避免更新延迟导致索引内容与最新政务事项不符。多类型文档混合的结构要求分块策略适配不同文本长度与语义单元，例如长文本办事指南与短文本常见问题需采用差异化的分块规则。多字段的文档结构要求向量建模重点覆盖核心业务字段，避免非关键字段干扰召回精度，同时需支持基于政务事项专属标识的过滤能力，防止跨区域、跨层级事项的混淆召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配办事指南、实施清单的长文本结构，避免单块内容断裂影响语义关联 |
| 重叠长度 | 100–200 字符 | 保留跨分块的上下文，避免办事流程、申请材料的连续内容被拆分丢失关联 |
| `maxToken` | 4096 token | 匹配多数通用向量模型的输入上限，适配政务文档的核心字段组合 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 区分政务事项的精准匹配与模糊关联，避免不同事项的混淆召回 |
| 单次搜索上限 | 前 8 条 | 覆盖常用办事场景的关联内容，避免过多冗余信息干扰答复准确性 |
| 问题优化 | 开启事项关键词补全 | 匹配政务咨询的固定话术，提升向量召回的匹配精度 |

## 容易做错的三处
- 向量召回结果包含非本级政务事项的内容。原因：未基于地方政务事项库的专属标识字段过滤索引，导致跨区域、跨层级事项被错误召回。
- 无法接入私有化的向量索引存储服务。原因：未按照平台要求配置外部索引的连接参数，导致索引服务无法正常挂载，覆盖本地部署与跨存储迁移的场景需求。
- 办事指南中的申请材料字段未被完整召回。原因：分块长度设置过小，将申请材料的连续条目拆分至多个分块，导致向量关联断裂。

## 怎么确认配好了
- 手动上传单份本级政务办事指南文档，执行向量召回测试，检查返回结果是否包含该文档的核心字段内容。
- 触发月度全量索引更新任务，查看任务日志是否无超时、字段为空等异常记录。
- 模拟政务咨询话术，测试不同相似度阈值下的召回结果数量，确认符合预设的匹配精度要求。
- 检查索引存储的占用情况，确认符合当前政务文档的总数据量阈值。
