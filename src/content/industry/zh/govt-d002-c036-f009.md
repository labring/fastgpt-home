# 政务服务事项目录与办事指南维护的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
数据主要来自国家政务服务事项基本目录、行政许可事项清单、权责清单及地方政务服务事项库，每月更新。日常维护的文档包含政务服务事项基本目录、实施清单、办事指南、标准材料目录、流程图及常见问题，每个事项包含事项编码、名称、受理条件、申请材料、办理流程等固定字段，部分字段需严格匹配上级目录的规范表述，不得随意修改。日常维护中最耗时的环节涉及比对上级目录与本级实施清单、维护受理条件和申请材料、校验办事指南字段完整性。

## 这些特征在「模型接入与配置」这一环带来什么约束
每月更新的数据源要求模型接入时需配置符合政务系统更新节奏的同步触发机制。多类型、多字段的文档结构要求分块处理时需保留事项编码等唯一标识字段，避免不同事项的文档内容混淆。固定字段的校验需求要求模型需针对受理条件、申请材料等核心字段做格式合规性检查，确保输出结果符合政务规范。本场景的配置基于FastGPT v4.17.0版本完成。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配单政务事项完整文档的长度，避免截断事项编码、受理条件等关键字段 |
| `maxTokens` | 2000–3000 token | 满足办事指南校验结果的输出长度，覆盖多字段的合规性说明与参考片段 |
| `temperature` | 0.1–0.3 | 保持校验逻辑的一致性，避免生成随机化的非标准化表述 |
| `AIPROXY_API_ENDPOINT` | 按部署实例填写实际接入地址 | 适配政务内网的网络隔离要求，确保模型调用可达 |
| `AIPROXY_API_TOKEN` | 按平台生成的专属密钥填写 | 保障模型调用的身份合法性，符合政务系统的安全规范 |
| `quoteMaxToken` | 500–800 token | 保留办事指南原文的关键片段，确保校验结果可追溯到原始文档 |

## 容易做错的三处
- 现象：模型调用返回401未授权错误，或提示API密钥无效。原因：未正确填写`AIPROXY_API_TOKEN`，或密钥权限未覆盖政务事项文档的处理范围。
- 现象：索引结果条数不足，无法覆盖全部待校验的办事指南。原因：未调整`maxContext`的取值范围，导致长文档被截断后无法被完整索引。
- 现象：生成的校验结果与上级目录的规范表述不一致。原因：`temperature`取值过高，导致模型生成了非标准化的判断语句，偏离政务事项的固定表述要求。

## 怎么确认配好了
- 执行单政务事项的办事指南校验任务，检查返回结果的字段完整性，确认所有必填项都被覆盖。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置被正确读取，无网络连接错误。
- 触发一次全量同步任务，检查同步进度与更新频率是否符合每月一次的要求，确认数据源的更新被正确触发。
- 随机抽取3-5个不同类型的政务事项，校验结果的表述是否符合政务系统的固定规范，确认`temperature`的取值符合预期。
