# 政府信息依申请公开的办事咨询与答复：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据来源为政府信息公开平台、机关档案系统、公文系统、部门业务台账及政府信息公开相关规范。日常处理的文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料等。数据更新无固定周期，随个案申请及流程推进变化。数据核心围绕特定申请人的单条政府信息公开请求，区别于面向公众的主动公开内容，需精准匹配申请指向的信息条目与公开属性。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据来源要求接口需兼容不同业务系统的调用格式，避免数据格式不匹配。非固定更新周期要求接口支持按需触发数据检索，适配个案申请的实时性需求。多样的业务文档要求接口需支持多字段校验，匹配申请表、答复书等不同文档的必填项。个案化的请求逻辑要求接口需绑定特定申请编号与申请人标识，避免跨申请的数据混淆。同时，需预留标准化错误反馈字段，适配答复超期、公开属性判断异常等场景的问题回溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 接口超时时间 | 600 秒 | 适配多源数据检索的耗时需求，避免因单次检索超时导致申请流程中断 |
| 请求重试次数 | 2–3 次 | 应对临时网络波动或系统短暂不可用，减少人工介入概率 |
| 数据拉取范围 | 按申请编号限定 | 匹配个案请求的精准检索需求，避免拉取无关数据增加处理负担 |
| 身份校验开关 | 开启 | 确保接口调用仅授权政务公开相关系统，防范未授权请求 |
| `responseData` | JSON | 适配多数业务系统的解析标准，简化外部系统对接流程 |
| 日志记录级别 | 详细 | 留存完整请求与响应数据，便于出错后回溯申请流程与问题原因 |

## 容易做错的三处
- 接口调用返回504超时状态码。原因：未合理设置接口超时时间，未针对多源数据检索的耗时场景调整阈值，导致检索未完成即被中断。
- 响应数据中缺少申请编号字段。原因：未配置`variables`参数的字段绑定规则，未将外部系统传入的申请编号同步至接口响应中，导致无法匹配对应申请流程。
- 接口返回无关的主动公开信息条目。原因：未配置按申请编号限定数据拉取范围，拉取了全量公开数据，干扰个案申请的处理判断。

## 怎么确认配好了
- 调用基于FastGPT v4.17.0搭建的测试接口传入模拟申请编号，检查返回数据是否仅包含对应申请的相关文档内容。
- 模拟网络波动场景，检查接口是否按配置的重试次数自动发起重试，未出现直接报错。
- 查看接口日志，确认完整记录了请求参数、响应数据与调用耗时，便于后续问题排查。
- 调用接口时未携带合法`Authorization`凭证，检查接口是否拦截未授权请求，符合身份校验配置。
