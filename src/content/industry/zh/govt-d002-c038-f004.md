# 政府采购项目的办事咨询与答复：工作流编排

## 这个品类的数据长什么样
政府采购项目办事咨询与答复涉及的数据来源包括中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，数据更新频率为每日更新。日常处理的文档包含采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复等，各文档对应固定字段，如采购项目编号、供应商统一社会信用代码、中标金额等，数据结构严格遵循政府采购公开规范，仅公开符合监管要求的内容。本页面配置说明基于FastGPT v4.17.0版本。

## 这些特征在「工作流编排」这一环带来什么约束
多来源的数据接入要求工作流需拆分不同数据源节点，避免跨系统数据混淆。日更的更新频率要求配置定时同步节点，确保咨询时调取的是最新公开数据。多类型文档的差异需要针对不同文档设置专属处理分支，如中标公告与质疑答复的校验逻辑不同。严格的监管要求意味着工作流需添加合规校验环节，避免泄露未公开信息或触发监管处罚。同时，出错后果严重的特性要求配置异常告警与人工介入节点，确保流程出错时可及时干预。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源节点 | 按中国政府采购网、财政一体化系统分别创建独立节点 | 匹配多来源数据的拆分处理需求，避免数据交叉污染 |
| 变量配置 | `variables` 绑定采购项目编号、供应商信用代码字段 | 适配采购文档的固定字段校验与数据调取逻辑 |
| 触发模式 | 日定时触发（每日0点） + 手动触发双模式 | 覆盖每日数据同步更新与临时咨询的双重场景 |
| 请求超时阈值 | 300秒 | 适配政府采购公开接口的平均响应时长，避免超时中断流程 |
| 异常处理节点 | `nodeId` 绑定超时告警与人工介入节点 | 对应政府采购流程的高合规性要求，确保出错时可及时干预 |
| 答复内容长度限制 | 1000字符以内 | 适配政务咨询的答复展示规范，避免内容过长超出展示范围 |

## 容易做错的三处
- 现象：编排中调用政府采购HTTP接口后，对话输出未展示接口返回的中标公告内容。原因：未将HTTP节点的输出结果绑定到对话输出节点的`variables`列表中，导致输出节点无法获取接口返回数据。
- 现象：自定义工具变量未关联采购文档字段，咨询时无法调取对应采购计划或中标公告数据。原因：未在`variables`配置中绑定采购项目编号、供应商信用代码等关键字段，导致数据匹配失败。
- 现象：工作流执行时触发超时报错，未触发预设的告警节点。原因：未将异常处理节点的`nodeId`与超时触发逻辑绑定，导致超时后无对应干预措施。

## 怎么确认配好了
- 手动触发工作流，输入指定采购项目编号，检查是否成功调取对应采购需求、中标公告等公开数据。
- 查看定时任务日志，确认每日0点自动同步政府采购网数据的任务执行状态为成功。
- 模拟接口超时场景，检查是否触发预设的告警与人工介入节点，流程跳转正常。
- 验证输出内容仅包含中国政府采购网公开的信息，未出现未公开的采购计划或评标报告内容。
