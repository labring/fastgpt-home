# 政府采购项目的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
数据来源包括中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统、供应商信用记录，更新频率为每日。日常业务文档涵盖采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复等，文档包含采购项目编号、供应商资质信息、评标分值、质疑事项等字段，同时部分文档附带扫描件、附件等非结构化内容，整体数据兼具结构化字段与半结构化文本特征。

## 这些特征在「模型接入与配置」这一环带来什么约束
日更的数据来源要求配置定时同步任务，确保咨询调用时使用最新的采购公告、质疑答复等内容，避免输出过期信息。多类型的业务文档存在差异化字段，需要针对采购需求、评标报告等不同文档设置专属的召回与索引规则，提升匹配精度。供应商信用记录的合规校验需求，要求模型接入时关联对应数据源接口，保障答复内容符合政府采购监管要求。同时，政府采购文档的监管属性较强，模型输出的咨询答复需严格匹配官方文本的表述规范，不能出现与监管体系冲突的内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 政府采购相关文档篇幅较长，需容纳足够上下文以关联采购需求与咨询问题 |
| `maxTokens` | 2000–3000 token | 办事咨询答复需清晰准确，控制输出长度避免冗余 |
| `quoteMaxToken` | 1500–2000 token | 需引用采购公告、中标结果等官方文档内容，预留足够引用文本空间 |
| `temperature` | 0.1–0.3 | 政府采购答复需严谨合规，降低随机性以保证表述准确 |
| `AIPROXY_API_ENDPOINT` | 按平台提供的官方接入地址填写 | 确保模型调用链路合规，适配政府采购场景的稳定访问需求 |
| `AIPROXY_API_TOKEN` | 按平台分配的专属密钥填写 | 保障接口调用的身份验证安全，避免未授权访问 |

## 容易做错的三处
- 现象：调用模型时返回红色数字报错，原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致接口身份验证失败或地址无效。
- 现象：调用多模态模型时无法识别上传的采购相关图片（如招标文件扫描件），原因：未开启`vision`配置项，未启用视觉识别能力。
- 现象：检索结果未包含最新的政府采购公告，原因：未配置定时同步数据源的任务，导致召回的文档为过期数据。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型配置页面，核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容与官方提供的一致。
- 发起测试咨询，输入政府采购项目的常见问题，检查模型输出是否引用了官方文档的准确内容，且`quoteMaxToken`配置生效。
- 上传采购相关的图片文件，发起多模态咨询，确认模型可以正确识别图片中的文字与关键信息。
- 调整`temperature`参数至0.2，发起多次测试咨询，检查输出内容的表述一致性，确认随机性符合预期。
