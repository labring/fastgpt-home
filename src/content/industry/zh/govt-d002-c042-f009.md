# 法务合规与重大风险管理的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自企业合同管理系统、合规风险数据库、法律法规库、案件管理系统与举报平台。日常生成的文档包括合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告。数据更新频率为月度，文档通常包含主体信息、合规判定依据、风险等级、处理建议等字段，无统一固定单位，字段与单位随文档类型调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据意味着模型接入时需配置定期同步的增量拉取逻辑，避免全量拉取占用过多企业内部存储与网络资源。多来源的异构文档要求配置适配不同格式的解析规则，确保合规审核意见、风险清单等文档的字段提取准确。合规相关内容的准确性要求极高，模型调用的上下文与结果需严格关联原始数据来源，同时需限制单次调用的内容规模，防止超出处理上限。此外，法务场景的高合规要求，需确保工具调用的可追溯性，避免上下文异常中断影响结果连贯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配合规文档的长文本上下文需求，避免因上下文截断丢失关键合规判定依据 |
| `maxTokens` | 4000 token | 控制单次模型输出的长度，确保合规审查意见、风险分析结果的可读性与完整性 |
| `quoteMaxToken` | 2000 token | 限制引用原始文档的长度，保证检索结果与上下文的匹配精度，避免冗余内容干扰模型判断 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具，适配合规审查中需要检索法规库、案件数据的场景 |
| `temperature` | 0.2–0.4 | 降低输出的随机性，确保合规相关答复的准确性与严谨性，符合法务场景的高确定性要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配企业内部网络环境的API访问路径，确保数据传输的安全性与稳定性 |

以上配置基于FastGPT v4.17.0版本的逻辑制定。

## 容易做错的三处
- 现象：调用MCP工具后模型上下文被打断，后续答复无法关联之前的合规审查内容。原因：未正确配置`maxContext`的上下文保留范围，或工具调用后未配置上下文续写逻辑。
- 现象：调用MCP后模型回答速度变慢，单次响应出现超时。原因：`maxContext`设置过大导致模型加载上下文耗时增加，或API端点配置未适配企业内部网络的带宽限制。
- 现象：重排模型返回结果为false，检索结果未按相关性正确排序。原因：未正确配置重排模型的调用参数，或数据源的文档格式不符合重排模型的输入要求，导致模型无法正常解析合规相关文档。

## 怎么确认配好了
- 发起一次包含合规风险清单与合同审核意见的上下文调用，检查模型输出是否完整关联了原始文档的关键内容。
- 调用MCP工具检索法规库，检查工具调用后上下文是否保留了之前的审查对话内容，未出现上下文丢失的情况。
- 提交不同格式的合规文档，检查模型是否能正确提取文档中的风险等级、处理建议等核心字段。
- 测试重排模型的调用流程，确认检索结果能按相关性正确排序，无异常false返回。
