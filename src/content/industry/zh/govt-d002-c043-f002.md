# 特种设备安全监管的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自特种设备安全监察系统、检验检测机构系统、使用单位台账及作业人员证书库，覆盖使用登记证、定期检验报告、维保记录、隐患整改通知书、事故报告、作业人员证书等日常文档。数据更新频率为月度，核心字段包含设备唯一编号、检验周期节点、维保执行日期、隐患整改状态、作业人员资质编号等，未涉及虚构统计数值。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新节奏要求索引配置支持批量全量更新，降低高频增量更新的运维成本。多来源异构文档类型，需适配从短编号类字段到长文本报告的分块规则，避免拆分关键业务信息。设备唯一编号、检验周期节点等核心业务字段，需单独配置索引优先级，确保检索时优先匹配高价值内容。同时，月度批量处理的数据规模需匹配索引服务的负载能力，避免任务超时中断，保障办事咨询的响应效率。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 覆盖设备定期检验报告、事故报告等长文档的核心段落，避免拆分跨页的检验周期、隐患整改等关键业务信息 |
| 重叠长度 | 100–150 字符 | 衔接相邻分块的上下文，确保检验周期、隐患整改状态等跨段落的业务逻辑可被完整检索，避免办事咨询时出现信息断层 |
| `maxToken` | 8192 token | 适配主流向量模型的输入上限，满足长文本事故报告的向量生成需求，避免截断核心业务内容 |
| 相似度阈值 | 0.72–0.80 | 区分相似设备编号、检验周期的检索结果，降低办事咨询中误匹配同型号设备或过期检验信息的概率 |
| 单次搜索上限 | 前10条 | 覆盖监管业务中需核对的多台关联设备或多份相关文档，避免遗漏关键整改或维保信息 |
| `defaultToken` | 1000 | 平衡检索上下文长度与模型响应速度，适配办事咨询场景中短查询的快速响应需求 |

## 容易做错的三处
- 现象：Docker部署环境下，知识库索引任务持续处于运行状态，无进度更新。原因：未根据月度更新的数据规模配置合理的批量处理阈值，导致索引服务内存占用过高，任务阻塞。
- 现象：调用embedding模型时返回503状态码，提示当前分组default下无可用模型。原因：未在向量模型配置中指定专属分组，或分组内的模型实例未正常启动。
- 现象：检索结果与办事咨询的业务需求匹配度较低，核心字段未被优先召回。原因：未针对设备编号、检验周期等核心业务字段配置单独的索引权重，导致向量检索优先匹配非关键文本。

## 怎么确认配好了
- 查看向量模型配置页面，确认已设置`maxToken`为适配业务文档的取值，且`defaultToken`符合短查询的处理需求。
- 执行一次小批量测试索引，检查分块后的文档片段是否包含完整的设备编号、检验周期等核心业务字段。
- 发起一条测试查询，核对检索结果的条数是否符合单次搜索上限的配置。
- 查看任务日志，确认无503状态码的模型调用报错，验证模型连接正常。
