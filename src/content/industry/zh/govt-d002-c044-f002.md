# 环境执法与监测监管的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自生态环境在线监控平台、污染源自动监测系统、执法办案系统及第三方检测机构提交的报告。日常文档包含现场检查记录、采样原始记录、正式监测报告、责令改正决定书与行政处罚决定书。数据按日更新，单份文档包含执法时间、采样点位、污染物浓度、整改要求等结构化字段与非结构化文本内容，字段关联执法流程全环节的操作痕迹与监测结果。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据按日更新且来源分散，向量索引需适配增量更新节奏，避免出现数据滞后。文档包含结构化监测字段与非结构化执法文本，分块时需保留字段关联逻辑，避免拆分后丢失业务关联信息。执法类文书存在固定流程结构，分块边界需匹配文书的逻辑段落，防止破坏证据链的完整性。多来源数据需统一字段映射规则，确保向量索引的元数据一致性，避免后续搜索时出现字段混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配现场检查记录、监测报告的单段落长度，避免拆分执法文书的逻辑单元 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，防止关键监测数据被拆分在两个分块中 |
| 相似度阈值 | 按实测标定 | 适配污染物浓度比对、执法流程匹配的业务场景，避免误匹配或漏匹配 |
| 单次搜索上限 | 前 8–12 条 | 覆盖单执法事项的关联文档数量，确保召回足够的现场记录与监测数据 |
| 最大上下文 | 3500–4000 token | 承载多份执法文书的关联内容，适配FastGPT v4.17.0的上下文承载能力 |
| `defaultToken` | `8192` | 匹配系统默认的token上限，避免内容截断导致执法证据丢失 |

## 容易做错的三处
- 现象：搜索返回结果的相似度数值异常偏高，例如达到10000以上。原因：未配置相似度阈值过滤，或阈值设置超出业务场景的合理区间，导致无关文档被召回。
- 现象：知识库上传文档后无索引进度显示，或索引状态始终为失败。原因：未匹配本品类文档的字段格式，或增量索引的更新频率设置与日更数据节奏不匹配，导致索引任务阻塞。
- 现象：调用向量模型时提示无可用频道。原因：未按官方文档配置对应embedding模型的接入参数，或频道权限未正确绑定至当前工作区。

## 怎么确认配好了
- 上传单份现场检查记录，查看索引进度是否正常完成，确认分块逻辑未拆分关键执法流程段落。
- 输入模拟执法咨询问题，检索关联文档，核对召回结果的业务关联性，调整相似度阈值至符合业务需求的范围。
- 查看向量数据库的元数据日志，确认多来源数据的字段映射规则已正确应用，无字段混淆情况。
- 测试增量索引触发逻辑，确认日更数据能自动触发索引更新，无滞后情况。
