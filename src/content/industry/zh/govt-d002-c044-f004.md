# 环境执法与监测监管的办事咨询与答复：工作流编排

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类涉及的数据来源包括在线监控平台、污染源自动监测数据、生态环境执法系统、第三方检测机构提交的报告。数据更新频率为每日，需同步最新的工况、监测与执法信息。日常文档包含现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书，其中现场检查记录含检查时段与工况数据，采样记录含点位坐标与采样时间，监测报告含监测因子与浓度值，执法文书含违法事实认定依据与整改要求。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据接入的需求要求工作流支持对接不同类型的数据源节点，包括接口与文件存储路径。数据每日更新的特性要求工作流触发时机适配定时同步或实时回调，避免使用过期数据。文档类型多样，包含结构化的执法系统数据与非结构化的PDF报告，要求工作流配置适配不同格式的解析规则。执法流程需严格遵循证据链逻辑，工作流的节点流转需可追溯，参数校验需覆盖执法文档的必填字段，确保答复内容合规有据。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 每日0点定时触发，或接收执法系统更新回调 | 数据更新频率为每日，定时触发可保证咨询答复使用最新同步数据，回调适配实时数据推送 |
| `variables`配置 | 预设执法点位ID、监测因子列表、整改期限字段 | 日常执法文档包含固定业务字段，通过`variables`可统一调用，减少重复配置 |
| 节点标识配置 | 为每个数据源节点设置唯一`nodeId` | 工作流编排需通过`nodeId`区分不同节点，便于日志排查与流转控制 |
| 失败重试配置 | 失败后重试2次，重试间隔60秒 | 在线监控接口可能出现临时波动，重试可降低数据拉取失败概率，参数按实测标定调整 |
| 文件解析配置 | 对PDF格式的监测报告启用结构化解析 | 日常文档包含大量PDF格式的监测报告与执法文书，结构化解析可提取有效字段用于答复 |

## 容易做错的三处
- 工作流在运行预览页面正常运行，聊天页面无内容。原因是工作流节点未正确关联聊天会话的`variables`参数，导致会话上下文无法调用工作流生成的执法数据。
- 上传监测报告文件进行对比时报Load file error。原因是工作流的文件上传节点未配置正确的存储路径权限，或文件大小超出节点预设限制。
- http请求节点设置form-data参数时无法正确传递文件。原因是未在文件参数项中指定本地文件路径或第三方存储的文件访问链接，导致请求无法识别文件内容。

## 怎么确认配好了
- 手动触发工作流，查看运行日志，确认各数据源节点均成功拉取对应数据，无报错提示。
- 测试发起执法相关咨询，查看聊天页面返回内容，确认包含预设的监测数据与执法文书字段。
- 模拟上传监测报告文件，检查工作流节点是否能正确接收并解析文件内容，生成对应数据。
- 查看工作流的权限配置页面，确认仅授权角色可访问对应节点，避免敏感数据泄露。
