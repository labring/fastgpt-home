# 用地预审与规划许可的办事咨询与答复：多轮对话与提示词
本页适用 FastGPT v4.17.0。

## 这个品类的数据长什么样
本品类数据来自国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。日常处理的业务文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，核心字段涵盖项目选址范围、用地规模、规划管控要求、前置审批条件等，数据结构与建设前项目审批流程强绑定，需严格匹配官方审批规则。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类数据来源分散且更新无固定周期，多轮对话需完整保留不同数据源的关联上下文，避免出现跨系统数据不一致的情况。日常文档类型多样，不同文档的字段逻辑差异明显，提示词需精准匹配对应文档的格式与校验规则，确保答复符合规划管控要求。项目审批前置条件涉及多部门协调，对话中需逐步引导用户补充完整前置信息，同时需严格校验用地规模与红线冲突，防止出现不符合管控要求的答复内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 前 12 轮对话或 8000–10000 字符 | 本品类文档字段多、上下文关联强，需保留足够多的历史交互与数据关联信息 |
| `messages` | 按单个项目会话存储 | 用地预审与规划许可的咨询需按单个项目隔离上下文，避免跨项目数据混淆 |
| `variables` | 绑定项目编号与红线坐标字段 | 需将项目专属标识与核心空间数据存入变量，便于多轮对话中快速调用校验 |
| 单次搜索上限 | 前 6 条匹配结果 | 本品类数据需精准匹配规划管控要求，过多结果会干扰对话逻辑 |
| 多模态输入支持 | 开启 | 本品类需支持上传红线图、规划条件等图片与文件格式的业务文档，确保内容提取准确 |
| 超时设置 | 600 秒 | 需等待多源数据同步完成，避免因超时中断关键校验流程 |

## 容易做错的三处
- 现象：多轮对话重启后无法回忆之前提及的项目信息，历史交互字段为空。原因：未正确绑定`chatId`参数，或会话存储配置未按项目维度隔离。
- 现象：文本内容提取的模型选择列表仅显示部分厂商，无法选择已接入的GLM系列模型。原因：未将接入的模型同步至对话模块的模型选择池，或配置未关联文本提取与对话模块的模型参数。
- 现象：工作流执行后仅返回单一步骤结果，无法串联多轮校验逻辑。原因：未配置多步骤的变量传递，或未将前序步骤的输出作为后续对话模块的输入上下文。

## 怎么确认配好了
- 发起包含项目选址、用地规模的多轮咨询，检查对话过程中是否能关联历史提及的项目编号与红线范围。
- 接入指定模型后，在对话模块的模型选择列表中确认该模型是否可见并可选中。
- 配置工作流多步骤后，触发测试会话，检查最终输出是否包含前序步骤校验后的合规性结论。
- 上传用地预审相关文档后，检查对话模块是否能正确提取文档中的核心字段并用于校验。
- 上传红线图等图片文件，检查对话模块是否能正确识别并解析图片中的空间坐标信息。
