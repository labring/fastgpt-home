# 用地预审与规划许可的办事咨询与答复：工作流编排

## 这个品类的数据长什么样
本品类的数据来源包括国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。日常处理的文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件等。数据关联的典型主体为自然资源主管部门用途管制和规划许可处、行政审批局及项目单位，核心字段涉及项目选址范围、用地规模、规划管控要求等，无统一固定的标准化单位字段，需结合具体项目文档的实际需求匹配。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新无固定周期，要求工作流需支持多源数据的实时拉取与增量同步校验。日常文档类型多样，需配置适配不同文档格式的解析节点，确保红线图、规划条件等非结构化文档的字段提取准确性。最耗时的核对环节涉及多部门前置条件协调，工作流需预留跨系统交互节点，减少人工重复核对的工作量。出错后果直接影响项目立项开工，需在工作流中加入前置校验节点，拦截不符合管控要求的申请材料。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 映射用地预审、规划许可的核心业务字段，关联国土空间规划一张图数据 | 确保工作流调用的参数与业务文档字段完全匹配，避免参数缺失或不对应 |
| `nodeId` | 按节点功能命名，如「红线冲突校验节点」「前置条件协调节点」 | 便于快速定位流程节点，排查工作流运行异常 |
| 多源数据拉取触发规则 | 按数据源更新状态触发 | 适配数据源不定期更新的特征，避免固定周期拉取产生的无效请求 |
| 非结构化文档解析阈值 | 按实测标定 | 适配红线图、规划条件等多样非结构化文档格式，提升字段提取准确率 |
| 跨系统交互超时设置 | 600 秒 | 协调发改、住建等部门的前置条件流程耗时较长，预留足够超时空间避免流程中断 |

## 容易做错的三处
- 现象：工作流中调用语音交互节点测试失败，返回连接超时或参数不匹配报错。原因：未将`variables`中配置的文件链接变量正确绑定至语音节点的输入参数，导致节点无法获取待处理的业务文档。
- 现象：http请求节点返回结果为空，或解析后的base64编码格式错误。原因：未正确配置http请求的body参数名与值，参数名未对应业务文档的字段名，参数值未绑定正确的数据源变量。
- 现象：工作流运行后出现红线冲突校验结果不准确。原因：未按数据源更新状态触发数据拉取，使用了固定周期拉取的旧数据，导致校验结果与最新规划管控要求不符。

## 怎么确认配好了
- 检查`variables`配置的字段是否覆盖了用地预审与规划许可的核心业务字段，可通过导出工作流参数清单逐一核对。
- 测试单个节点的运行状态，触发`nodeId`为「红线冲突校验节点」的节点，查看返回结果是否包含最新的生态保护红线数据。
- 模拟跨部门协调流程，触发跨系统交互节点，确认超时设置是否符合业务协调的实际耗时需求。
- 上传一份真实的项目红线图，测试非结构化文档解析节点的输出结果，确认字段提取符合业务要求。
