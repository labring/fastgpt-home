# 社会救助与低保审核的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自低收入人口动态监测平台、居民家庭经济状况核对系统及跨部门共享的公安、人社、医保、住建、税务数据，更新周期为月度。日常处理的文档包含低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料、救助审批表，数据字段围绕家庭收入、财产状况、家庭成员关系、救助资格认定展开，需匹配各来源数据的原始格式与单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的跨部门数据体量较大，需限制单次接入的数据范围，避免上下文溢出。多源异构数据的字段格式不统一，模型需支持动态适配不同数据源的字段结构。家庭经济状况与成员关系的核对依赖精准匹配，对模型的上下文准确性要求较高。入户调查与公示材料的非结构化文本较多，需配置适配非结构化数据的处理逻辑。救助资格判定的结果直接关联资金发放，需严格控制模型输出的合规性边界。

## 配置怎么定
基于FastGPT v4.17.0版本，针对本品类的特征，可参考以下配置项与取值：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配月度跨部门数据源的总上下文长度，避免超出模型处理窗口 |
| `maxTokens` | 2000–3000 token | 控制单轮判定结果的输出长度，适配救助资格说明的文本需求 |
| `quoteMaxToken` | 1500 token | 限制引用源数据的长度，确保家庭收入、成员关系等核心核对信息完整 |
| `toolChoice` | auto | 自动调用工具完成跨部门数据匹配，适配多源异构数据的处理需求 |
| `temperature` | 0.1–0.3 | 降低输出随机性，保障救助资格判定的准确性与一致性 |
| `AIPROXY_API_TOKEN` | 按权限分配生成 | 保障接口调用的身份验证，避免未授权访问敏感民政数据 |

## 容易做错的三处
- 现象：调用接口返回401未授权错误，或工具调用无响应。原因：未正确配置`AIPROXY_API_TOKEN`，或令牌权限未覆盖跨部门数据接口。
- 现象：工具调用失败，返回无法识别function call的报错。原因：未正确配置`toolChoice`参数，或未将跨部门数据核对的工具逻辑与模型绑定。
- 现象：上下文溢出导致处理中断，返回空结果或截断内容。原因：`maxContext`配置值小于月度汇总数据的总长度，未适配本品类的多源数据体量。

## 怎么确认配好了
- 提交月度汇总的测试数据，检查模型输出的上下文长度未超出配置范围。
- 触发工具调用流程，确认模型能自动调用跨部门数据核对工具完成家庭经济状况匹配。
- 调整`temperature`参数，对比多轮输出结果的一致性，确认符合业务判定需求。
- 验证接口调用的响应状态码，确认`AIPROXY_API_TOKEN`配置正确，无未授权报错。
