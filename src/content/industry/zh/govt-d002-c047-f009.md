# 行政处罚案卷办理的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源于行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常处理的文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，数据结构以违法事实、执法流程、处罚决定为核心，包含涉案主体、执法程序、证据关联、法律引用、处罚结果等核心字段，无自定义单位字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征对模型接入与配置带来明确约束。分散且包含非结构化影像的数据源，要求配置支持多模态内容解析；每日高频更新的批量数据，需适配稳定的接口调用参数；多类型执法文档的混合存储，要求配置支持精准召回指定文档的能力；以处罚决定为核心的文档结构，要求模型生成内容需严格匹配原始证据与法律条款，需限制生成自由度与上下文长度，避免出现与执法规范不符的内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 执法案卷包含多份关联文档，需容纳完整的执法流程与证据信息，避免上下文截断导致关键内容丢失 |
| `maxTokens` | `4000–6000 token` | 限制模型单次生成的处罚文书长度，确保内容符合执法文书的规范格式 |
| `quoteMaxToken` | `2000–3000 token` | 确保召回的证据文档内容完整，为模型提供准确的引用依据，支撑处罚决定的合法性 |
| `temperature` | `0.1–0.3` | 行政处罚案卷办理需严格匹配法规与原始文档，较低的温度值可降低生成内容的随机性，提升准确性 |
| `vision` | 开启 | 数据包含执法记录仪影像等非结构化内容，需配置多模态解析能力以提取影像中的执法信息 |
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| `AIPROXY_API_TOKEN` | 填写部署生成的专属令牌 | 保障模型调用的身份验证安全，防止未授权访问 |

## 容易做错的三处
- 调用接口返回结果为空或未召回指定文档。原因：未正确配置支持指定文档召回的关联参数，导致模型无法精准匹配目标执法文档。
- 模型生成内容与原始执法文档偏差较大，出现错误的法律条款引用。原因：`temperature`参数取值过高，导致生成内容随机性超出执法规范要求的范围。
- 处理执法记录仪影像时无法解析内容。原因：未开启`vision`配置项，未启用多模态解析能力，无法识别影像中的执法信息。

## 怎么确认配好了
- 发起包含执法记录仪影像的测试请求，检查模型是否能正确提取影像中的执法信息，确认`vision`配置生效。
- 上传多份执法文档，发起指定某份文档的召回请求，检查返回结果是否仅包含目标文档的内容，确认指定召回配置生效。
- 调整`temperature`参数至0.5以上，发起测试请求，对比生成内容的随机性变化，确认参数配置生效。
- 填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`后发起调用，检查接口返回状态码为200且无身份验证报错，确认接口配置生效。
