# 行政处罚案卷办理的办事咨询与答复：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，以违法事实认定、裁量基准适用、处罚决定内容为核心字段，部分文档含执法人员签名、执法编号等标识性字段，无统一标准化单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的批量数据要求检索环节支持增量同步与高频召回，避免全量扫描占用过多资源。多类型执法文档结构差异较大，需适配不同文本的分块逻辑，确保核心字段被精准匹配。来自多系统的异构数据需统一预处理，消除格式差异对召回精度的影响。以处罚决定与证据链为核心的业务需求，要求检索优先匹配违法事实、法律条款关联内容，保障检索结果贴合办案场景。

## 配置怎么定
本文适配 FastGPT v4.17.0 版本，配置项及建议如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 匹配执法文档中专业术语与违法事实的关联度，避免召回无关的通用行政文书 |
| `limit` | 前8–12条 | 覆盖单份处罚案卷所需的证据、告知、决定类文档数量，确保上下文完整 |
| `searchMode` | vector_search | 针对执法文档的结构化与半结构化特征，优先使用向量检索匹配核心语义 |
| `usingReRank` | 开启 | 对初始召回结果按业务相关性重排，优先返回与处罚裁量、法律适用相关的内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展执法相关的专业术语查询，如将“处罚”扩展为“行政处罚事先告知”“处罚决定书”等 |
| `collectionIds` | 按执法类型绑定对应集合 | 限定检索范围至当前执法机构的行政处罚案卷集合，避免跨品类数据干扰 |

## 容易做错的三处
- 现象：返回结果格式报错，无法识别为标准JSON。原因：未正确配置检索结果的序列化规则，或扩展查询参数导致返回内容超出格式限制。
- 现象：检索结果为空JSON。原因：未绑定正确的`collectionIds`，或`searchMode`配置错误导致无法匹配目标数据。
- 现象：无法通过API完成指定集合的数据增删。原因：未在API请求中携带正确的集合标识参数，或权限配置未开放对应操作。

## 怎么确认配好了
- 发起针对执法场景的测试查询，检查返回结果的格式是否符合预期，无语法错误。
- 查看检索日志，确认`collectionIds`已绑定正确的行政处罚案卷集合，无跨品类数据混入。
- 验证重排功能是否生效，对比初始召回结果与重排后的结果顺序，确认核心业务内容优先展示。
- 测试API增删接口，确认指定集合内的数据可正常添加或删除，操作无权限报错。
