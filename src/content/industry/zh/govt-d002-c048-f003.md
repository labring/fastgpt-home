# 行政许可审批的办事咨询与答复：多轮对话与提示词
FastGPT v4.17.0

## 这个品类的数据长什么样
本品类数据涵盖办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书及许可证照等法定文档，数据来源为全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统及电子证照库，每日更新。数据以法定许可事项为边界，包含事项设定依据、办理条件、申请材料清单、审批流程及证照格式等结构化字段，无额外非法定统计项。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
法定文档的固定格式要求提示词需严格限定答复内容与现有事项库一致，不得新增未经公示的办理条件；每日更新的数据源要求对话上下文调用时优先读取最新同步的事项数据，避免使用滞后信息；结构化的申请材料字段需在多轮对话中自动关联用户提交的材料编号，确保核对环节的准确性；跨部门调取的电子证照数据需在对话中明确权限边界，防止泄露非授权信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 800–1200 字符 | 适配行政许可事项文档的平均长度，避免截断关键法定依据 |
| 问题优化开关 | 开启 | 帮助用户将模糊咨询转化为匹配事项库的精准查询 |
| 单次回复token上限 | 1500–2000 token | 匹配政务答复的标准信息量，符合平台处理阈值 |
| `variables`存储字段 | 申请编号、事项编码 | 用于关联用户历史咨询的具体行政许可事项，确保多轮对话上下文连贯 |
| 会话绑定规则 | 按`chatId`绑定 | 确保同一用户的多轮咨询仅调用该会话内的历史数据，防止跨会话混淆 |

## 容易做错的三处
- 现象：会话中无法查看或统计token消耗。原因：未开启`messages`的token计数配置，或未关联全局统计接口。
- 现象：多轮对话中连续发送两条消息后出现上下文混淆。原因：未按`chatId`绑定会话上下文，导致模型错误关联不同会话的咨询内容。
- 现象：Markdown格式的审批意见在微信渠道发送时无法隐藏。原因：未配置渠道专属的格式过滤规则，未将原生Markdown内容转换为微信兼容的格式。

## 怎么确认配好了
- 发起一条模糊咨询，观察系统是否自动优化为匹配行政许可事项库的精准查询，确认问题优化开关生效。
- 发起两条连续的同一事项咨询，检查会话上下文是否关联了正确的申请编号，确认`variables`存储字段配置正确。
- 触发token计数逻辑，查看会话日志是否生成对应的统计数据，确认`messages`的token计数配置生效。
- 测试微信渠道消息发送，确认Markdown格式的审批意见被正确转换为兼容格式。
