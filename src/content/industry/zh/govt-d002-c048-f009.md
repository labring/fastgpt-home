# 行政许可审批的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统及电子证照库，每日更新。日常文档包含办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书、许可证照，涵盖事项编码、办理条件、申请材料清单、审批流程、证照信息等字段，单份文档内容覆盖法定办理环节与具体要求，无额外冗余业务外信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据每日更新要求模型接入环节配置定时同步任务，确保调用的事项清单、电子证照数据为最新版本。文档类型覆盖结构化表单与非结构化文书，需适配不同格式的解析规则，避免遗漏申请表、补正告知书等关键内容。数据以法定许可事项为边界，模型匹配需严格绑定对应事项的设定依据与办理条件，不得跨事项关联信息。跨部门调取的电子证照数据需配置专属访问权限，确保数据调用符合政务安全规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配行政许可事项的完整办事指南与审批文书长度，避免截断关键法定依据 |
| `maxTokens` | 4000–6000 token | 覆盖审批意见、补正告知书等长文本答复的输出需求，满足法定内容的完整表达 |
| `quoteMaxToken` | 1500–2000 token | 限定引用的办事指南、事项清单内容长度，确保匹配内容精准且不冗余 |
| `toolChoice` | auto | 允许模型自主选择是否调用文档解析工具，适配结构化表单与非结构化文书的混合处理 |
| `temperature` | 0.1–0.3 | 保持答复的严谨性，避免生成不符合法定要求的模糊表述 |
| `AIPROXY_API_ENDPOINT` | 政务内网专属代理服务地址 | 确保调用数据来源符合政务网络安全规范，避免公网传输敏感政务信息 |

## 容易做错的三处
- 现象：在FastGPT v4.17.0中，已在账号模型配置页面启用模型，但工作流节点中无法找到该模型。原因：未在工作流的模型渠道设置中勾选对应模型，或配置的模型渠道未同步至当前工作流空间。
- 现象：本地部署MinerU服务后，调用文档解析返回API无响应报错。原因：本地部署的MinerU服务端口未正确映射，或FastGPT配置的`AIPROXY_API_ENDPOINT`与实际服务端口不一致。
- 现象：模型生成的答复未匹配到对应行政许可事项的办理条件。原因：`maxContext`配置值过小，截断了办事指南的关键匹配字段，导致模型无法检索到对应事项的法定依据。

## 怎么确认配好了
- 进入FastGPT后台模型配置页面，确认目标模型的启用状态为开启，且已填写正确的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`。
- 上传一份行政许可办事指南文档，触发模型调用，检查返回结果是否包含匹配的事项办理条件与申请材料清单。
- 打开工作流编辑界面，进入模型节点配置，确认已配置的模型已加载至可选列表。
- 提交测试申请材料，核对模型生成的答复内容是否匹配对应行政许可事项的法定要求。
