# 规范性文件合法性审核的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源为法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新频率不定期。日常处理的文档包括规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告，文档结构以条款式文本为主，包含文件主体内容、起草依据、征求意见情况等核心字段，单份文档长度跨度较大，从数百字符到数万字符不等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新无固定周期，多轮对话需逐步引导用户明确当前审核文件的版本与关联依据。文档结构复杂且包含专业法条表述，提示词需明确区分上位法依据与本地政策的层级关系，避免混淆适用规则。单份文档长度跨度较大，多轮对话需动态调整上下文长度，避免超出模型处理上限。审核需比对多类依据，提示词需引导模型按审核环节逐步拆解任务，确保覆盖权限、程序、条文合法性等核心审查点。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 8000–12000 token | 适配规范性文件草案与关联依据的总长度，避免截断核心审核内容 |
| 超时设置 | 600 秒 | 适配长文档审核的处理时长，避免因审核内容较多导致任务中断 |
| 问题优化 | 开启，每轮对话触发 | 针对专业法条表述优化用户提问，提升模型对审核需求的理解精度 |
| 单次搜索上限 | 前8条 | 匹配多类依据的检索需求，覆盖常见的上位法与本地政策条目 |
| 重叠长度 | 200–300 字符 | 确保分块文本的上下文连贯性，避免法条条款被割裂 |
| `variables` | 预设审核环节变量（如权限依据、程序要求） | 固定审核的核心规则，减少多轮对话中的重复校验 |
| `chatId` | 绑定当前审核任务的唯一标识 | 确保多轮对话的上下文关联正确，避免不同审核任务的内容混淆 |

## 容易做错的三处
- 现象：知识库回答出现截断，仅返回部分审核意见内容。原因：未合理设置最大上下文长度，超出模型处理上限导致核心依据被截断。
- 现象：导入规范性文件草案时返回500错误。原因：未适配文档的长文本结构，分块配置未覆盖大段条款内容，导致解析失败。
- 现象：工作流中多个AI对话模块执行后输出全部历史结果。原因：未通过`variables`参数配置仅保留当前审核环节的输出结果，未设置结果过滤规则。

## 怎么确认配好了
- 上传一份典型的规范性文件草案，检查分块后的文本是否完整覆盖所有条款，无割裂情况。
- 发起一轮审核对话，确认模型能正确关联上传的文件与预设的上位法依据。
- 测试多轮递进式提问，如先询问权限合规性再询问程序合规性，确认上下文连贯且无内容丢失。
- 查看`messages`参数的日志，确认每轮对话的上下文仅包含当前审核任务的相关内容。
