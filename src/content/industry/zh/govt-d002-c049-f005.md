# 规范性文件合法性审核的办事咨询与答复：工具调用与插件

## 这个品类的数据长什么样
这个品类的核心数据围绕行政规范性文件全流程生成与审核。日常处理的文档包括规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告。数据来源涵盖法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新无固定周期。数据字段包含文件文号、起草单位、审核要点、意见汇总条目等，单份审核相关文档的字符量跨度较大，需兼容结构化与非结构化的文本格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 指定为`function` | 规范性文件合法性审核需固定调用合规校验类工具，避免触发通用问答模式，符合FastGPT v4.17.0的配置规范 |
| 单次插件调用超时 | 300–600 秒 | 审核文档包含草案、上位法条文等多类内容，需预留足够的比对与解析时间 |
| `functionCall` | 指定权限校验、条文匹配的函数列表 | 需精准调用与合法性审核强相关的工具，过滤无关调用逻辑 |
| 上下文窗口大小 | 8000–12000 token | 需完整承载审核所需的草案、上位法依据、意见汇总等全部内容 |
| 结果召回上限 | 前 3 条 | 合法性审核仅需核心上位法与权限依据，过多召回结果会干扰审核判断 |
| 插件触发规则 | 按审核任务类型匹配 | 不同审核场景需调用对应数据源插件，避免跨场景调用导致的匹配错误 |

## 容易做错的三处
- 调用插件接口返回`You need to use the app key rather than the account key`报错。原因：未正确配置FastGPT应用的调用密钥，误将账号密钥作为插件调用凭证。
- 工具调用返回的匹配结果条数超出预设范围。原因：未设置合理的结果召回上限，或配置项被误修改为全量召回。
- 插件调用后返回空的合法性审核结果。原因：未正确绑定法规规章库、上位法数据库等数据源，或上下文窗口配置过小导致核心内容被截断。

## 怎么确认配好了
- 调用FastGPT测试接口，传入单份规范性文件草案，检查是否触发预设的合规校验插件。
- 查看工具调用日志，确认`toolChoice`与`functionCall`的配置参数与预设值一致。
- 核对插件返回的匹配结果，确认仅召回与本次审核相关的上位法与权限依据。
- 测试多源数据接入，检查是否能正常拉取法规规章库与部门政策文件库的内容。
