# 规范性文件合法性审核的办事咨询与答复：表单与交互

## 这个品类的数据长什么样
本品类的数据主要来自法规规章库、上位法数据库、部门政策文件库及行政规范性文件备案系统，更新频率不定期。日常处理的文档包含规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告。数据字段涵盖文件文号、制定主体、条文内容、征求意见范围、审核意见要点等，无固定统一单位，需随具体文件关联对应规范依据。

## 这些特征在「表单与交互」这一环带来什么约束
数据来源分散且更新不定期，要求表单支持多源文件批量上传与实时校验机制，避免引用过期法规。文档结构多样，需配置自定义字段组适配不同审核场景的字段需求。字段无固定单位，需允许用户手动补充单位说明或关联对应规范依据。同时需联动备案系统数据，确保审核结果可同步至备案流程，保障审核流程的完整性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `formInput` | 支持多文件批量上传、单文件上限1000 MB与自定义字段组 | 适配规范性文件草案、起草说明等多类型审核文档，满足灵活字段配置需求 |
| 单次搜索上限 | 前10条 | 匹配单次合法性审核需比对的上位法与政策条目数量范围 |
| `userSelect` | 联动法规规章库、上位法数据库等多数据源勾选 | 覆盖本品类全量数据来源，确保审核依据的完整性 |
| 最大上下文 | 8000–12000 token | 容纳完整审核文件与关联法规的内容总量 |
| 超时阈值 | 600秒 | 适配多源数据检索与条文比对的耗时需求 |
| 问题优化 | 按审核场景预设条文比对规则 | 针对合法性审核的核心审查环节优化查询逻辑 |

## 容易做错的三处
- 选择大模型并开启思考过程输出后，结果未显示思考环节。原因是未在`formInput`的大模型配置中勾选「保留思考过程」选项，或未关联对应模型的权限参数。
- 配置全局变量后，节点调用时提示输入为空。原因是未将全局变量绑定至`userSelect`的数据源参数，导致变量未正确传递至后续审核环节。
- 对话界面复制按钮失效，生成的markdown内容无回车换行，同时弹出提示需手动选择文字。原因是未开启表单的markdown自动换行配置，且未通过`formInput`配置浏览器复制权限校验的适配逻辑。

## 怎么确认配好了
- 上传多类型审核文档，检查表单是否自动识别并加载对应自定义字段组。
- 触发检索后，确认返回结果覆盖法规规章库、上位法数据库等配置的全部数据源。
- 调用大模型生成审核意见，检查输入参数是否包含上传的审核文件与关联法规内容。
- 测试复制生成的审核意见文本，确认markdown格式包含正确的回车换行，且复制权限校验正常。
