# 财政支出绩效评价的办事咨询与答复：文档解析与分块

## 这个品类的数据长什么样
本品类数据主要来自预算管理一体化系统、项目申报材料、资金支付数据、业务台账及满意度调查，更新频率为年度。日常处理的文档包括绩效目标表、自评表、绩效评价报告、佐证材料清单与整改报告，文档多包含结构化字段（如项目编码、资金额度）与大段非结构化的效果描述、佐证说明，字段单位涵盖项目类别、金额单位与数量单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
年度批量更新的文档特性要求解析与分块具备批量处理能力，避免单文件解析超时。多类型文档混合的场景，需要适配结构化表单与大段非结构化报告的不同分块逻辑，防止拆分破坏项目编码、资金额度等关键结构化字段的完整性。多来源的文档格式差异，要求解析规则具备一定的兼容性，同时需保留佐证材料与主报告的上下文关联，确保后续核验资金支出与绩效目标的对应关系时可快速定位关联内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配绩效评价报告的段落长度与结构化字段的信息密度，避免拆分破坏项目关联逻辑 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配文档的标题层级与段落结构，保留绩效目标、佐证说明的上下文关联 |
| `customPdfParse` | 启用 | 针对导出的预算管理一体化系统PDF文档，适配其固定排版的结构化表单内容 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容单批次批量上传的佐证材料包与大型绩效评价报告 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 满足大型多附件文档的解析耗时需求，避免超时中断 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（自评表、报告、佐证清单）调整分块规则，适配业务数据特征 |

## 容易做错的三处
- 执行`docker run --gpus all -itd -p 7231:7231`命令时出现报错，无法启动文档解析服务。原因是本地GPU驱动版本与`marker_images:v0.1`镜像的依赖不兼容，或未正确配置GPU设备挂载参数。
- FastGPT v4.8.12版本中，绩效评价报告内的复杂公式无法正常解析返回结果，而v4.9.0版本可正常处理。原因是不同版本的内置PDF解析引擎对公式提取逻辑存在差异。
- 知识库中部分PDF文档点击分块预览时提示无法读取该文件内容。原因是PDF文件存在加密、损坏或使用了非标准嵌入字体，导致解析引擎无法完整提取文本。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，上传单份典型的绩效评价报告，查看分块预览结果，确认标题与段落未被错误拆分。
- 上传批量的佐证材料包，检查解析任务的完成状态，确认未出现超时报错。
- 针对结构化的绩效目标表，验证分块结果中保留了项目编码与资金额度的完整关联。
- 调整`chunkSize`参数后重新上传测试文档，对比分块长度的变化，确认配置生效。
