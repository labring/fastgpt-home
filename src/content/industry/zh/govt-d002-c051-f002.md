# 道路运输经营许可的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自道路运政管理系统、全国道路运输车辆动态信息公共服务平台、车辆和从业人员数据库。日常处理的文档包含经营许可申请、车辆技术档案、驾驶员从业资格材料、安全生产管理制度、道路运输经营许可证。数据更新频率为每日，核心字段涵盖经营主体信息、车辆资质、从业人员资格、安全管理制度条款、许可证照编号等，仅保留业务办理相关的结构化资质信息与非结构化文本内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据来源分散且每日更新，要求索引支持增量同步以避免重复全量处理；文档包含结构化资质信息与非结构化制度文本，需适配不同内容的分块逻辑，避免长文本截断导致关键资质字段丢失。核心业务字段如许可编号、车辆资质、从业人员资格需精准匹配，因此索引召回需兼顾文本语义与字段关联性，同时需控制单批次索引的数据量以适配每日更新的节奏，防止索引构建超时影响办事咨询的响应效率。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类的非结构化制度文本与结构化资质文档的长度，避免关键资质字段截断 |
| 重叠长度 | 100–150 字符 | 衔接相邻分块的语义，防止跨块的资质关联信息丢失 |
| 相似度阈值 | 0.75–0.85 | 精准匹配资质与许可相关内容，避免低匹配度结果干扰办事咨询 |
| 单次搜索上限 | 前6条 | 平衡召回覆盖率与响应速度，适配办事咨询的实时需求 |
| `maxToken` | 4000 token | 适配本品类文档总长度，确保完整加载许可申请与制度文本的关键内容 |
| 重排 | 开启 | 优化召回结果排序，突出与办事流程、资质要求直接相关的内容 |

## 容易做错的三处
- 现象：索引构建时报错「数据分片异常」，状态码返回500。原因：未适配本品类每日增量更新的节奏，尝试全量索引超大批次的道路运政数据，超出系统缓存阈值。
- 现象：搜索结果中出现无关的交通执法内容，部分业务字段为空。原因：未针对本品类的业务字段设置匹配规则，召回了非道路运输经营许可的关联文档。
- 现象：调用外部索引模型时超时，返回「请求超时」。原因：未调整`defaultToken`参数适配本品类长文档的加载需求，单次请求的token总量超出外部模型限制。

## 怎么确认配好了
- 查看索引同步日志，确认每日增量更新的道路运政数据已成功写入索引，无失败条目。
- 输入测试查询如「道路运输经营许可申请要求」，核对召回结果是否包含经营许可申请、资质要求相关文档。
- 调整相似度阈值后，验证召回结果的匹配度是否符合业务场景的预期，无需固定数值。
- 调用外部索引模型，确认返回的结果条数与单次搜索上限的设置一致。
