## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
年度更新频率要求接口调用频次不宜过高，可配置按年度缓存已拉取的决算数据，减少重复请求。多源数据接入要求接口需兼容不同系统的鉴权方式，需通过`variables`传递系统标识以区分数据源。需汇总下级单位报表的需求，要求接口支持按层级参数拉取数据，单次返回数据量需匹配报表结构的复杂度。数据核对与审计要求接口返回的字段需严格对应决算报表的标准字段，避免字段缺失或口径偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {对应系统专属密钥}` | 不同数据源需独立鉴权，通过该参数区分调用权限，保障数据访问安全 |
| `variables` | `{"dataSource": "预算管理一体化", "reportLevel": "本级+下级"}` | 区分数据来源与汇总层级，适配多系统接入与下级报表汇总的业务需求 |
| `responseData` | `仅返回决算报表核心字段+错误码` | 减少无效数据传输，适配审计核对时的字段精准匹配需求 |
| 单次请求数据上限 | `800–1200 字符` | 匹配部门决算报表单页的平均字符量，避免接口超时 |
| 缓存有效期 | `365 天` | 数据按年度更新，无需频繁刷新缓存，降低接口调用压力 |
| 鉴权超时时间 | `60 秒` | 覆盖多系统数据拉取的平均响应延迟，保障跨系统调用的成功率 |

## 容易做错的三处
- 现象：调用接口后返回`401 Unauthorized`状态码，核心字段为空。原因：未正确配置`Authorization`参数，未使用对应数据源的专属鉴权密钥，导致鉴权失败。
- 现象：查看接口返回的source字段时，仅显示通用标识，无法匹配部门决算报表的具体文档类型。原因：未通过`variables`传递文档分类参数，导致source字段未按决算报表标准填充。
- 现象：接口调用超时，返回超时错误。原因：单次请求配置的数据量过大，超过系统处理上限，未按实测标定调整单次请求的字符数或数据条数。

## 怎么确认配好了
- 调用接口并传入预设的`variables`参数，检查返回的`responseData`是否包含部门决算报表的核心字段。
- 查看鉴权日志，确认不同数据源的调用请求均能通过`Authorization`参数的验证。
- 模拟年度数据更新后调用接口，检查缓存是否自动刷新，返回的最新数据与源系统数据一致。
- 拉取下级单位数据，确认返回的结果条数与预设的下级单位数量匹配。
