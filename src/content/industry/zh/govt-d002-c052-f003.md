# 部门决算与财务报告的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来自预算管理一体化系统、国库集中支付系统、会计核算系统与资产管理系统，更新频率为年度。日常处理的文档包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告，文档包含预算执行数、实际收支、资产负债明细、差异说明等字段，单位多为万元、元，部分字段需匹配国库支付流水的对应编码，单份年度文档的内容规模相对集中。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
年度集中更新的数据与多份文档的组合，会导致单次对话的上下文总长度易超出模型承载上限，需对文档进行合理切片。不同系统导出的文档格式存在细微差异，提示词需明确统一的字段识别与校验规则，避免答复口径出错。本品类的咨询场景发生在年度结束后，区别于预算编制环节的事前规划，需基于实际发生的收支与资产数据进行答复。办事咨询多涉及账表核对、预算执行差异解释，多轮交互需保留历史上下文关联后续问题，确保答复基于完整的年度决算背景。数据需匹配国库支付编码等专属规则，提示词需明确校验逻辑，防止出现公开数据口径错误。

本配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 固定绑定当前会话 | 确保多轮对话的上下文关联到正确的会话实例 |
| `variables` | 预设决算字段常量 | 统一答复中使用的字段名称与单位规则 |
| 分块长度 | 800–1200 字符 | 匹配部门决算文档单页内容长度，避免单块信息断裂影响关联分析 |
| 重叠长度 | 100–200 字符 | 保留跨块的账表关联字段，确保核对国库支付数据时的上下文连贯 |
| 最大上下文长度 | 按实测标定 | 适配年度多份决算文档的总长度，避免超出模型承载上限 |
| 历史消息保留条数 | 前10条 | 覆盖单次咨询的多轮交互，保留预算执行差异解释的历史依据 |

## 容易做错的三处
- 对话返回结果残留工具调用日志：原因是未在提示词中明确隐藏工具执行环节的输出内容，导致工具调用的中间信息被一并返回。
- 上传年度决算文档后触发上下文溢出报错：原因是未设置合理的分块与上下文长度限制，未对多份年度文档进行切片处理。
- 多轮对话后答非所问：原因是未配置`messages`参数关联历史交互内容，或历史消息保留条数设置过少，导致后续问题无法关联前期的决算数据背景。

## 怎么确认配好了
- 发起包含账表核对的多轮对话，检查后续问题的答复是否关联前期的决算数据，确认历史交互被系统正确识别。
- 上传单份年度决算文档，测试对话上下文长度，确认未触发溢出报错。
- 配置提示词后发起咨询，检查返回结果仅包含AI答复内容，未残留工具调用的执行日志。
- 查看系统的历史对话保留规则，确认设置的历史消息条数符合单次咨询的交互需求。
