# 部门决算与财务报告的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自预算管理一体化系统、国库集中支付系统、会计核算系统、资产管理系统，更新频率为年度周期。日常文档包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告，数据字段覆盖实际收支明细、资产负债余额、预算执行差异说明等，单份文档体量从数十页到数百页不等，字段格式遵循财政系统统一规范。

## 这些特征在「模型接入与配置」这一环带来什么约束
年度周期更新的数据决定了知识库无需高频增量同步，仅需在决算周期前完成全量更新即可。单份文档体量较大且包含多类关联字段，要求模型上下文窗口需适配长文本输入，避免截断关键数据。多系统同源同规范的数据需要模型准确关联账表与支付数据，因此需配置稳定的模型调用逻辑，同时因出错后果需严格控制生成内容的准确性，需限制模型的随机生成参数。

## 配置怎么定
本文档适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单批次年度决算文档的总长度，避免长文本关键信息被截断 |
| `maxTokens` | 2000–3000 token | 控制单轮办事咨询答复的输出长度，确保决算说明、预算执行差异解释等内容完整 |
| `quoteMaxToken` | 1500–2000 token | 限制引用源文档的片段长度，保证账表、国库支付数据的引用准确且不溢出上下文窗口 |
| `temperature` | 0.1–0.3 | 降低生成内容的随机性，确保决算数据口径、差异说明符合财政系统统一规范 |
| `AIPROXY_API_ENDPOINT` | 按自建模型部署的实际地址填写 | 适配社区常见的自建模型接入场景 |
| `AIPROXY_API_TOKEN` | 按部署平台生成的专属令牌填写 | 完成模型调用的身份验证，确保接入权限合法有效 |

## 容易做错的三处
- 界面提示“没有可用模型”，排查时发现`AIPROXY_API_ENDPOINT`未正确填写自建模型的部署地址，或`AIPROXY_API_TOKEN`配置错误。
- 重排序模型测试报错，仅在本场景下出现，原因是未将`quoteMaxToken`适配决算文档的长片段引用，导致重排序时上下文长度超出模型限制。
- 模型生成的答复出现数据口径错误，原因是`temperature`取值过高，导致生成内容偏离财政系统统一的决算数据规范。

## 怎么确认配好了
- 调用模型测试接口，输入单份决算说明文档，检查返回结果是否完整且未出现文本截断，确认`maxContext`与`maxTokens`配置适配当前文档长度。
- 提交包含国库支付数据关联查询的测试请求，检查模型是否能正确关联账表与支付数据，确认`quoteMaxToken`配置合理。
- 生成多轮测试答复，检查不同轮次的答复内容是否保持一致，确认`temperature`配置符合准确性要求。
- 验证自建模型的接入地址与令牌，检查模型调用日志是否有成功的返回记录，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确。
