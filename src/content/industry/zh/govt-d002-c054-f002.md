# 防汛防灾与应急值守的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控。日常文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单，字段多包含雨情水情数值、物资编号、避险点位、人员转移台账等。数据更新频率为每日，部分实时监测数据更新间隔更短。数据结构多为结构化字段与非结构化文本混合，部分文档附带时间戳与责任主体标识。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据多源混合且每日批量更新，会对向量索引的写入性能提出要求。结构化字段与非结构化文本并存的文档结构，需要针对性配置向量化规则，避免字段混淆。实时监测数据的时效性要求，需支持增量索引更新，避免全量重算导致的响应延迟。多系统同步的数据存在格式差异，会增加向量化前的预处理成本，若未处理则会降低向量计算的准确性，进而影响办事咨询的答复精度。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类文档中会商纪要、灾情速报的平均长度，避免块内关键信息断裂 |
| 重叠长度 | 100–150 字符 | 保留块间上下文关联，避免跨块的预警或处置信息被拆分 |
| `maxToken` | 4096 token | 匹配多数通用嵌入模型的输入上限，适配应急处置方案的长文本内容 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 区分有效灾情信息与无关内容，避免误召回或漏召回 |
| 单次召回上限 | 前 8 条 | 控制单次检索的返回量，适配应急场景下快速获取核心信息的需求 |
| `defaultToken` | 200 token | 设定默认返回的上下文长度，保障办事咨询时的信息完整性 |

## 容易做错的三处
- 现象：向量计算得分异常，不同文本的相似度分数差距过大且部分结果完全一致。原因：未针对该品类的结构化字段（如雨情数值、物资编号）做单独预处理，导致非语义特征干扰向量计算。
- 现象：批量上传文档后向量化耗时过长，页面加载进度停滞。原因：未配置分块长度与召回上限的适配参数，全量文档一次性向量化未做分片处理，超出系统单次处理上限。
- 现象：批量导入CSV数据后，最终索引数据量少于源文件条数。原因：未过滤源数据中的空值字段或无效行，部分不符合格式要求的条目被自动跳过但未生成明确提示。

## 怎么确认配好了
- 上传单篇典型文档（如当日雨情速报），检查向量化后的分块结果是否覆盖完整内容，无明显信息截断。
- 发起针对灾情关键词的检索，核对返回结果的条数与相关性是否符合业务场景需求，调整相似度阈值直至符合预期。
- 导入批量测试数据，对比源数据条数与最终索引的条目数，确认无异常丢失。
- 查看系统日志，检查增量索引更新时的耗时是否符合日常业务的响应要求，未出现超时报错。
