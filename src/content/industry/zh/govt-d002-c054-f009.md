# 防汛防灾与应急值守的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控。日常产生的文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单。数据更新频率为每日，部分实时监测数据同步间隔更短。文档结构多包含事件时间、地点、等级、处置进展等字段，部分文档附带数值类参数，如降雨量、水位高度等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散且类型多样，包含实时监测数据与批量文档，要求模型接入需支持多源数据的快速整合与解析。文档包含时间、地点、等级、数值参数等结构化字段，需适配不同格式的内容提取逻辑。数据更新频率与业务处置节奏强绑定，需保障模型调用与数据同步流程匹配应急场景的时效性要求。同时，会商材料、灾情速报等文档的篇幅较长，需配置合理的上下文与切片规则，避免超出模型支持上限。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配该品类的应急业务场景需求。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 该品类文档多包含多源监测数据与会商材料，需覆盖至少3天的值班记录与预警信息，避免上下文截断 |
| `maxTokens` | 2000–3000 token | 用于生成预警答复、处置方案等应急文本，平衡响应速度与内容完整性 |
| `quoteMaxToken` | 1500 字符 | 需引用的灾情速报、水文数据等内容篇幅适中，限制引用长度以保障主回复连贯性 |
| `temperature` | 0.2–0.4 | 应急场景需答复内容严谨准确，降低随机性，避免不符合业务规范的表述 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应模型的代理地址 | 适配本地部署的模型调用路径，保障数据传输的安全性与稳定性 |
| `AIPROXY_API_TOKEN` | 填写部署时生成的专属令牌 | 实现模型调用的身份验证，防止未授权访问 |

## 容易做错的三处
- 现象：模型调用失败，返回认证错误或地址无效。原因：未正确填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或代理地址未适配本地部署的模型服务端口。
- 现象：对话中上传的防汛文档被截断，无法完整提取内容。原因：未配置合理的上下文与切片规则，文档长度超出模型支持的上下文上限。
- 现象：生成的答复内容过于随意，包含不准确的灾情等级表述。原因：`temperature`参数取值过高，导致模型生成内容的随机性超出应急场景的严谨性要求。

## 怎么确认配好了
- 发起包含本地水文数据、预警通知的测试对话，检查模型是否能正确提取关键字段并生成对应答复。
- 上传单篇篇幅较长的会商纪要，核对系统是否自动完成切片并正确整合上下文内容。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置已被正确读取。
- 调整`temperature`参数后发起测试，观察答复内容的严谨性变化，确认参数生效。
