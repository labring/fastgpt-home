# 防汛防灾与应急值守的办事咨询与答复：知识库检索与召回

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
通常，该品类的数据来源于气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控。日常文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单，部分文档含结构化字段，如雨量毫米数、流量立方米每秒、物资件数、转移人数等。数据更新频率为每日，且多为实时或准实时的业务数据。

## 这些特征在「知识库检索与召回」这一环带来什么约束
日更且准实时的更新节奏，要求检索环节支持增量同步与快速召回，避免全量扫描拖慢响应速度。多源异构的数据来源与混合结构化、非结构化的文档类型，需要检索同时兼顾语义匹配与关键词精准匹配，适配不同字段的查询需求。应急处置的高时效性要求，意味着检索结果需在短时间内返回核心信息，且需过滤低相关性数据，减少后续处理负担。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75-0.85 | 防汛数据的字段精准度要求较高，该区间可过滤低相关的冗余结果，避免干扰应急研判 |
| `limit` | 前6-10条 | 应急会商与值守场景需快速浏览核心信息，过多结果会增加信息筛选的时间成本 |
| `usingReRank` | 开启 | 多源异构数据下，重排可优化检索结果的相关性排序，提升核心灾情与预警信息的优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 应急咨询的问题常为口语化表达，扩展查询可匹配专业文档中的术语表述，提升召回覆盖度 |
| `collectionIds` | 绑定防汛应急专属数据集ID | 隔离非相关业务数据，避免无关文档混入检索结果，保障研判的准确性 |

## 容易做错的三处
- 现象：csv模板导入后中文显示乱码，英文内容正常。原因：未使用UTF-8编码保存csv文件，或导入时未选择匹配的编码格式。
- 现象：检索返回的结果条数远低于设置的`limit`值。原因：数据集内符合`similarity`阈值的文档块不足，或`collectionIds`绑定了错误的数据集范围。
- 现象：本地部署的知识库磁盘占用统计不准确。原因：未统计嵌入向量存储目录的大小，或误将临时缓存文件计入总占用。

## 怎么确认配好了
- 上传一份测试用的灾情速报csv文件，检查导入后中文内容显示正常，无乱码问题。
- 发起一条包含雨情、水情关键词的测试查询，核对返回结果的条数符合`limit`设置，且相似度处于`similarity`区间内。
- 查看本地部署的系统存储目录，确认原文件、分块文件与向量数据分别存储在对应路径，磁盘占用统计包含三类数据。
- 开启`usingReRank`后，对比开启前后的检索结果排序，确认相关性更高的文档排在检索结果前列。
