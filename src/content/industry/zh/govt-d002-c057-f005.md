# 食品安全监督抽检的办事咨询与答复：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来自食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS及企业台账。日常文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告，核心字段含抽样编号、检验项目、不合格判定结果、处置流程节点。数据更新频率为每月一次，整体以抽样批次为核心关联链路，不同文档间通过抽样编号形成关联关系。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据每月更新的特性要求工具调用的缓存策略需匹配该周期，避免调用过期数据。多类型文档的存在要求插件需支持按文档类型路由调用逻辑，针对检验报告需重点解析不合格项目字段。多数据源接入的需求需配置统一的数据映射规则，将不同系统的字段转换为统一格式。核心字段的复杂性要求工具调用需限定解析范围，仅提取与办事咨询相关的抽样、检验、处置字段，避免冗余信息干扰用户咨询。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | 固定为`{"type":"function","function":{"name":"get_sampling_info"}}` | 明确指定调用抽检信息查询工具，避免模型自主选择无关工具 |
| `functionCall` | 开启强制函数调用模式 | 确保每次咨询调用都执行预设工具，防止模型生成非工具调用的无效内容 |
| 文档分块长度 | 800–1200 字符 | 匹配检验报告、抽样单的单页内容长度，避免分块破坏文档完整结构 |
| 单次工具调用上限 | 前 3 条 | 限定每次咨询返回的抽样批次数量，避免信息过载影响用户判断 |
| 上下文窗口大小 | 4000–6000 token | 适配多文档关联查询的上下文需求，覆盖抽检计划、抽样单、处置报告的关联内容 |
| 超时阈值 | 60 秒 | 匹配市场监管相关系统的接口响应平均时长，避免过长等待导致交互中断 |

## 容易做错的三处
- 现象：工具调用完成后，关联的抽样批次变量未自动更新，界面显示变量字段为空。原因：未配置工具调用后的变量同步规则，未将工具返回的抽样编号、检验项目等核心字段映射到工作流变量。
- 现象：调用文档查询工具时，返回的结果条数超出配置的单次调用上限。原因：未在工具调用配置中开启结果截断规则，或未正确绑定单次搜索上限参数。
- 现象：通过API调用工作流上传抽样单文件失败，返回文件格式不支持的报错。原因：未按照要求使用multipart/form-data格式封装请求，或未正确设置文件字段名与工作流节点的匹配。

## 怎么确认配好了
- 发起模拟咨询，输入已知的抽样编号，核对工具是否返回对应的检验报告、处置状态信息，确认`toolChoice`参数正确触发预设工具。
- 查看工具调用日志，核对返回结果的条数是否符合配置的单次调用上限，确认结果过滤规则生效。
- 调用API接口传入测试参数，核对返回结果是否包含正确的知识库数据，确认知识库ID配置无误。
- 触发工作流执行工具调用，查看变量面板，确认工具返回的字段已自动同步到工作流变量中。
