# 食品安全监督抽检的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS及企业台账，更新频率为月度。日常文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告，核心证据为实验室出具的检验报告，文档字段涵盖抽样编号、检验项目、不合格判定结果、处置措施等内容，典型使用主体为市场监管局食品抽检处、检验机构及基层监管所，部分线下文档以扫描件形式存在。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据源要求模型接入时配置月度增量同步的调度规则，避免高频同步占用计算资源。多来源数据需要适配不同系统的接口格式，需提前配置数据源映射规则以统一数据结构。核心文档为检验报告等半结构化文件，对长文本处理参数有明确要求。不合格食品处置相关文档涉及监管流程，模型输出需严格匹配文档预设字段，不宜生成未包含在源数据中的内容。基层监管所的使用场景需要轻量化配置，减少复杂参数调整步骤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配检验报告等长文本文档，覆盖完整抽样及处置流程的全部信息 |
| `maxTokens` | 2000–3000 token | 控制单轮咨询答复的输出长度，避免超出监管文档的字段展示限制 |
| `quoteMaxToken` | 1500 token | 限定引用源文档的最大长度，确保引用内容与检验报告的核心字段匹配 |
| `toolChoice` | auto | 自动选择工具调用，适配抽样单、检验报告的结构化数据提取需求 |
| `vision` | 开启 | 支持对抽样单、检验报告的扫描件进行内容提取，适配线下纸质文档的数字化处理 |
| `temperature` | 0.2–0.4 | 降低生成随机性，确保答复内容严格匹配监管文档的既定格式与字段要求 |

## 容易做错的三处
- 现象：调用视觉模型时无法识别抽样单的盖章区域，输出内容缺失抽样编号。原因：未开启`vision`配置项，或未配置针对结构化单据的视觉预处理规则。
- 现象：模型调用工具时偶尔中断输出，仅返回部分检验报告内容。原因：未合理设置`maxContext`参数，长文本文档超出上下文窗口导致截断，触发调用中断。
- 现象：接入mineru模型后无法正常调用，工具返回版本不兼容报错。原因：未安装mineru适配FastGPT v4.17.0的特定版本，直接使用官方最新版导致接口不匹配。

## 怎么确认配好了
- 提交单份检验报告的测试文本，核对模型输出的不合格项是否与源文档字段匹配，调整相关参数直至输出符合预期。
- 上传抽样单扫描件，验证视觉模型是否能正确提取抽样编号、检验机构等核心字段，确认配置生效。
- 触发月度增量同步任务，核对数据源接口返回的文档数量与实际更新的抽检计划数量一致，验证数据源配置正确性。
- 调用语音转文本工具上传测试音频，核对转写结果的完整性，确认工具节点与模型配置的关联正确。
