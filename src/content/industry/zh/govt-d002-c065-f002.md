# 勘察设计的办事咨询与答复：向量模型与索引
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
勘察设计的数据来源包括勘察外业观测记录、结构设计计算书、行业工程建设规范、项目变更洽商文件。更新节奏随单个勘察设计项目的推进或行业标准的修订进行调整，单份文档的长度差异显著，短则数百字的点位说明，长则数万字的全套施工图设计说明。文档字段包含项目编号、勘察坐标、材料性能参数、合规性条款编号，单位多涉及米、兆帕、平方米等工程专业计量单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
勘察设计文档的长度跨度大、专业术语密集且存在专属工程单位，要求向量模型需适配工程领域语义特征，避免通用模型的语义偏差。多字段的文档结构要求索引需支持按项目编码、规范文号等字段做精准筛选，缩小召回范围。非固定的更新节奏，要求索引支持增量更新，无需全量重建，减少资源占用。专业文档的长段落占比高，需调整分段逻辑以保留完整专业语义单元，避免语义割裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配勘察设计文档的专业段落长度，保留完整的参数说明或规范条文语义 |
| 重叠长度 | 100–150 字符 | 避免专业段落被截断导致语义断裂，衔接相邻分块的上下文 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配度的非专业关联结果，适配工程术语的语义相似度特征 |
| 单次搜索上限 | 前 8 条 | 平衡召回精度与响应速度，覆盖常见的咨询场景需求 |
| `defaultToken` | `4096` | 适配长文档的上下文承载需求，匹配工程文档的平均长度 |
| `maxToken` | `8192` | 预留足够的token空间用于整合召回的分块与用户问题 |

## 容易做错的三处
- 现象：导入知识库生成的dataset.csv仅包含index字段，无content字段。原因：未开启正文内容提取配置，仅抓取了文档的元数据信息。
- 现象：Docker部署环境中集成向量模型后出现连接超时报错。原因：未配置内网环境下的模型访问权限，或docker-compose.yml中的端口映射参数未正确映射。
- 现象：使用默认分段参数导入文本后，专业设计段落被截断为多个无意义的分块。原因：默认分段长度未适配勘察设计文档的长专业段落，导致语义断裂。

## 怎么确认配好了
- 上传一份典型的勘察报告文档，查看系统生成的分块是否保留完整的专业参数与条款内容。
- 发起一条包含工程专业术语的咨询问题，检查召回结果的相似度分值是否落在设定的阈值区间内。
- 在内网环境中测试向量模型的加载与查询流程，确认无连接超时类报错。
- 导出知识库的dataset.csv文件，验证content字段已包含文档的正文文本内容。
