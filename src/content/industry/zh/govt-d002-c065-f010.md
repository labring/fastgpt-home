# 勘察设计的办事咨询与答复：知识库检索与召回

## 这个品类的数据长什么样
勘察设计的办事咨询数据主要来源于项目全周期的勘察报告、设计施工图说明、国家及行业规范图集、项目变更通知单等。数据更新以单项目增量为主，伴随项目推进按需上传或修改，单次修改后通常在10–30分钟内完成向量索引同步。文档结构包含长文本技术说明（通常在500–5000字符之间）、结构化字段（如项目编号、勘察点位坐标、设计参数、规范编号），单位涵盖米、兆帕、平方米等工程常用单位，部分文档附带图纸扫描件的OCR识别文本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
勘察设计数据的多类型特征与更新模式，对检索召回环节带来多重约束。长文本技术说明需保留专业参数的完整性，分块时需避免过度拆分导致专业参数断裂。结构化字段需支持精准匹配，避免混淆不同项目的坐标或承载力参数。单项目增量更新的模式，要求检索范围可按项目精准限定，避免跨项目数据干扰。同时，规范类短文本与技术类长文本需兼顾召回，确保既覆盖通用规范条文，又匹配项目专属的技术细节。

## 配置怎么定
本文适配FastGPT v4.17.0版本的知识库配置逻辑，具体配置项及建议如下：
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.75–0.85 | 勘察设计文档多专业术语，阈值过低会引入无关的规范条文，过高会遗漏相关的技术说明内容 |
| `limit` | 前10–15条 | 单项目知识库文档数量适中，过多会超出上下文窗口，过少会遗漏关键的分块技术内容 |
| `searchMode` | 语义+精准混合模式 | 需同时召回专业术语的语义匹配结果，以及结构化字段的精准匹配内容 |
| `usingReRank` | 开启 | 勘察设计文档存在大量相似的技术参数描述，重排可提升高相关内容的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可通过扩展专业术语的表述，匹配更精准的规范条文与项目技术说明 |
| `collectionIds` | 按项目ID指定为数组格式 | 勘察设计按项目分类管理，限定召回范围可避免跨项目数据混淆 |

## 容易做错的三处
- 现象：调用知识库检索接口返回参数格式错误，报错提示“invalid collection id”。原因：传入的`collectionIds`参数未使用数组格式，直接传入单个字符串类型的知识库ID。
- 现象：检索结果未包含目标PDF文档的核心内容，条数远少于预期。原因：未开启`datasetSearchUsingExtensionQuery`，且`searchMode`仅设置为精准模式，无法匹配PDF文档中的长文本分块内容。
- 现象：导出的知识库文件未包含近期修改的文档。原因：未等待10–30分钟的向量索引更新完成就执行导出操作，修改后的文档尚未完成入库流程。

## 怎么确认配好了
- 输入包含专业术语的测试问题，例如“某项目桩基竖向抗压承载力设计值”，核对召回结果中是否包含对应项目的勘察报告内容。
- 查看检索结果的排序，确认高相关内容排在前3条，验证`usingReRank`配置是否生效。
- 传入指定的`collectionIds`数组参数，核对召回结果是否仅包含对应项目的知识库文档，无跨项目数据混入。
- 测试传入变量形式的`collectionIds`，确认对话过程中参数解析无报错，验证变量适配是否正确。
