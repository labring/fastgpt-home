# 化工新材料的办事咨询与答复：部署与升级

## 这个品类的数据长什么样
化工新材料的办事咨询数据来源为生产企业内部工艺台账、质检报告单，以及行业协会发布的技术指引文件。更新节奏为每月一次，对应产品批次更新与合规标准微调。文档多为结构化的参数手册与工艺说明，字段包含产品牌号、密度、拉伸强度、热变形温度，单位分别为g/cm³、MPa、℃，单篇文档长度多在5000字至20000字区间，部分包含多页的合规检测附表。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 100–200 连接 | 适配化工新材料文档多字段、高并发查询的连接需求，避免连接耗尽 |
| `MONGODB_URI` | 内网MongoDB服务地址，携带认证参数 | 存储结构化的产品参数与咨询日志，确保数据不流出内网 |
| `REDIS_URL` | 本地Redis服务地址，配置内存上限为2000 MB | 缓存高频咨询的产品参数，降低数据库查询压力 |
| `STORAGE_S3_ENDPOINT` | 内网对象存储内网地址 | 存储长文档的原始文件与分块索引，适配化工文档的大容量存储需求 |
| `FE_DOMAIN` | 内网部署的前端访问域名 | 限定咨询入口仅在内网可访问，符合数据安全要求 |
| `FILE_TOKEN_KEY` | 自定义随机字符串 | 校验文件上传请求的合法性，防止未授权的文档导入 |

## 容易做错的三处
- 现象为Docker构建过程中抛出`EMFILE: too many open files`报错，原因是未调整Docker容器的文件句柄上限，化工新材料的长文档处理会占用更多文件句柄，超出默认限制。
- 现象为向量模型集成后导入文档无匹配结果，原因是未配置`DB_MAX_LINK`适配多字段文档的索引请求，导致连接池耗尽无法完成索引构建。
- 现象为iOS端访问咨询入口后语音输入无法识别，原因是未配置`FE_DOMAIN`为内网可访问的域名，导致语音识别的回调请求无法到达内网服务。

## 怎么确认配好了
- 执行`docker ps`命令查看所有服务容器处于运行状态，无异常退出的日志记录。
- 上传一份化工新材料的工艺文档，等待索引构建完成后，发起包含具体产品牌号的咨询，验证返回结果包含对应产品的参数信息。
- 查看`REDIS_URL`对应的Redis监控面板，确认缓存命中数随咨询发起次数逐步提升。
- 检查`STORAGE_S3_ENDPOINT`对应的内网存储桶，确认上传的文档分块文件已同步完成存储。
