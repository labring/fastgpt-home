# 化肥农药的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
化肥农药的办事咨询数据主要来源于企业内部的产品登记文档、使用说明书、农技推广手册，以及农业农村部门的监管公示信息。数据更新节奏随新农资产品审批、监管政策调整而变动，无固定周期。文档结构包含结构化参数表和非结构化长文本，字段包含产品名称、登记证号、有效成分含量等，单位多为克/亩、毫升/升、天等。

## 这些特征在「向量模型与索引」这一环带来什么约束
上述数据特征对向量模型与索引环节带来三点约束。其一，结构化参数表与非结构化文本并存，需在分块时保留字段与单位信息，避免语义混淆；其二，使用剂量、安全间隔期等字段的单位直接影响咨询准确性，向量索引需适配单位的语义识别；其三，数据更新无固定周期，新数据导入需支持增量索引，减少全量重建的时间成本，且需通过`defaultToken`控制单批次处理的最大字符数，适配不同长度的文档。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配化肥农药文档既有短问答、又有长使用指南的结构，避免分块过碎丢失关联信息或过长导致上下文溢出 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的关键内容，如使用剂量的前后说明，避免跨块语义断裂 |
| `defaultToken` | 4096 token | 匹配多数化肥农药文档的平均长度，保障单批次索引处理的完整性 |
| `maxToken` | 8192 token | 适配长文本的质检报告或政策文件，避免截断核心内容 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的无关结果，适配农资办事咨询对精准性的较高要求 |
| 重排 | 开启，取前3条 | 优先展示与用户问题最相关的产品参数，符合办事咨询的决策逻辑 |

## 容易做错的三处
- 现象：调用知识库接口创建索引时返回超时状态码。原因：未针对化肥农药文档的长度差异调整分块策略，分块过大导致单批次处理负载过高。
- 现象：更换embedding模型后，已导入的知识库无法返回匹配结果。原因：未对原有索引执行重建操作，仍使用旧模型的向量空间进行检索。
- 现象：搜索结果中无关内容排在前列，未优先展示核心参数。原因：未开启重排功能，仅依赖基础向量相似度排序，未结合农资咨询的优先级规则调整。

## 怎么确认配好了
- 导入单份典型的化肥农药产品说明书，查看索引生成日志中的分块数量与预期一致，核对`defaultToken`的设置是否符合文档长度需求。
- 发起包含具体使用剂量的咨询，核对返回结果中是否包含正确的单位信息。
- 更换embedding模型后，执行索引重建操作，验证新模型的向量匹配结果符合预期。
- 调整相似度阈值后，发起测试查询，确认返回结果的数量符合业务需求。
