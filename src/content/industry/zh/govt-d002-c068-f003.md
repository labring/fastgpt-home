# 医药流通的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
医药流通的业务数据主要来源于药品流通备案系统、企业进销存管理系统、冷链运输监控平台及国家药品批准文号数据库。数据分为静态与动态两类：静态数据包含药品通用名、商品名、批准文号、生产企业、流通许可编号等，更新频率为每月一次；动态数据包含实时库存数量、运输温度、批次有效期、出库记录等，更新频率为每5分钟一次。单条数据文档结构固定，字段包含中文名称、数值型单位（如件、盒、摄氏度）、日期型字段，无嵌套复杂结构。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
静态与动态数据的更新节奏差异，要求多轮对话中需区分数据类型并触发对应检索时机，避免使用过期的库存信息。字段包含专业医药术语与标准化单位，提示词需预先映射专有名词，确保检索时精准匹配字段名称。单条数据字段较多，多轮对话需保留上下文关联的药品ID与批次号，避免跨会话混淆检索结果。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 问题优化 | 开启，针对医药专业术语做标准化映射 | 医药流通数据包含大量专有名词，需统一术语格式以提升检索精度 |
| 最大上下文长度 | 8000–12000 token | 医药数据字段较多，需保留多轮对话中的药品ID、批次号等关键信息 |
| `variables` 变量绑定 | 绑定当前会话的药品ID、流通批次号 | 精准匹配对应批次的库存、运输等动态数据 |
| `chatId` 会话关联 | 持久化保存会话上下文 | 确保多轮对话中上下文信息不丢失，避免跨会话检索混淆 |
| 单次检索召回条数 | 前6条 | 平衡检索效率与信息完整性，避免冗余数据干扰大模型输出 |
| 上下文刷新间隔 | 300 秒 | 匹配动态数据每5分钟的更新频率，确保检索使用最新库存信息 |

## 容易做错的三处
- 对话中知识库检索结果为空，但知识库测试可召回，现象为前端展示无匹配内容，日志显示检索参数未携带当前会话的`variables`药品ID，原因是未绑定会话变量导致检索范围覆盖全量数据，无法精准匹配用户询问的特定批次药品。
- 对话报错404 Invalid URL (POST /api/chat/completions)，现象为发起会话请求时返回404状态码，日志显示接口路径未匹配部署配置，原因是未正确配置FastGPT的反向代理规则，导致请求未指向正确的服务地址。
- 工作流执行一半终止，现象为大模型完成回复后，后续结果推送流程无响应，对话直接结束，原因是未开启`messages`上下文持久化，导致工作流无法读取上一步的检索结果，触发流程中断。

## 怎么确认配好了
- 发起包含药品名称与流通批次的多轮对话，查看上下文记录，确认`chatId`与`variables`参数被正确传递。
- 手动修改知识库中的某条医药流通动态数据，发起对应检索请求，确认检索结果实时更新。
- 测试包含医药专业术语的提问，确认问题优化功能正确完成术语映射，检索结果匹配对应字段。
- 模拟工作流执行流程，确认大模型回复后，后续流程可正常读取上下文信息并完成执行。
