# 医药流通的办事咨询与答复：工作流编排

## 这个品类的数据长什么样
医药流通的核心数据来源于企业进销存管理系统、冷链温湿度监控终端、药品监管备案平台。数据按流通批次更新，单批次数据包含药品通用名、批准文号、流通批次号、出库入库时间、冷链温湿度记录、配送节点信息。字段多为字符串、数值型，单位包含℃、%RH、批次编号、时间戳等，部分数据为结构化表格形式，单批次完整数据长度可达数千字符。

## 这些特征在「工作流编排」这一环带来什么约束
医药流通的多源结构化数据、长文本批次记录与时序温湿度数据，对工作流编排带来多重约束。单批次完整数据长度差异大，可能超出大模型上下文上限，需配置拆分与合并节点。冷链温湿度为时序数据，需按时间戳排序后拼接。药品批准文号、流通批次号为核心检索字段，工作流需优先提取并关联对应节点。多源数据更新频率不同，需配置定时同步或实时拉取的触发规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配医药流通单批次数据的常见长度，适配FastGPT v4.17.0版本的节点拆分逻辑 |
| 变量配置 | 按实测标定 | 适配不同企业进销存系统的字段映射规则 |
| 最大上下文 | 12000–16000 token | 覆盖多数拆分后的单批次完整数据，避免截断关键信息 |
| 超时设置 | 600 秒 | 覆盖跨系统拉取温湿度、备案数据的常见耗时 |
| `nodeId` | 按流通批次号关联 | 匹配医药流通多节点数据的关联逻辑 |
| 文件处理节点 | 自动转base64 | 支持冷链监控图片的上传分析需求 |

## 容易做错的三处
- 工作流运行时提示上下文超出限制，返回报错文案“输入文本过长”。原因是未针对医药流通的长批次数据配置分块处理，直接传入完整数据触发大模型上下文上限。
- 上传冷链监控图片后，AI分析结果为空。原因是未配置图片转base64的处理节点，导致图片无法被视觉模型正确识别。
- 通过API调用工作流时返回400状态码。原因是未正确配置`variables`参数的传入格式，未按要求传递医药流通的批次号、温湿度数据等核心字段。

## 怎么确认配好了
- 手动导入单批次医药流通数据，检查工作流是否自动拆分并完成上下文适配。
- 上传冷链监控图片，检查工作流是否自动生成base64编码并传入视觉模型节点。
- 调用API触发工作流，检查返回结果是否包含预期的药品审批状态、温湿度分析结论。
- 查看工作流运行日志，确认节点触发规则按数据更新时间正常执行。
