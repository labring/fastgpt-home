# 医药流通的办事咨询与答复：部署与升级

## 这个品类的数据长什么样
医药流通的办事咨询数据包含两类：一类是结构化的药品流通台账，来源为企业内部仓储、运输、销售系统，更新节奏为每日同步；另一类是非结构化合规文档，包括GSP认证报告、药品说明书、冷链运输记录，来源为国药监公开平台与企业内部归档，更新随药品变更或合规检查调整。文档结构包含药品批准文号、生产厂家、流通批次、运输温度阈值等字段，单位涉及摄氏度、批次号、存储容量等。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 100–150 个连接 | 适配医药流通数据的并发检索与会话请求，避免连接耗尽 |
| `REDIS_URL` | redis://127.0.0.1:6379/1 | 缓存高频咨询的药品信息与检索结果，降低数据库压力 |
| `STORAGE_S3_ENDPOINT` | 按本地合规存储节点配置 | 留存医药流通文档与咨询记录，符合行业数据留存要求 |
| `PG_URL` | postgresql://user:pass@db-host:5432/fastgpt | 存储结构化的药品流通台账与用户咨询数据 |
| `ROOT_KEY` | 自定义32位随机字符串 | 管理平台的最高权限验证，保障部署环境的安全 |
| `FE_DOMAIN` | 部署服务器的公网域名 | 配置前端访问地址，确保用户可正常访问咨询界面 |

## 容易做错的三处
- 现象：执行`docker-compose up`后容器启动失败，返回exit code 1。原因：未根据医药流通数据的存储需求调整`PG_URL`对应的数据库权限，或手动修改配置文件时存在JSON语法错误。
- 现象：知识库检索结果仅返回少量条目，无法覆盖全量药品文档。原因：未调整`DB_MAX_LINK`的取值，导致数据库连接数不足，无法拉取全量结构化数据。
- 现象：接入的大模型未在平台列表中展示。原因：未同步更新`REDIS_URL`对应的缓存配置，导致模型接入信息未被正确加载。

## 怎么确认配好了
- 执行`docker ps`命令，查看所有容器状态均为Up，无异常退出记录。
- 访问`FE_DOMAIN`配置的公网地址，登录平台后进入数据库连接测试页面，确认`PG_URL`与`REDIS_URL`的连接测试通过。
- 上传一份医药流通的GSP认证文档，确认文件上传成功且可在知识库管理页面检索到对应内容。
- 发起一条包含药品流通批次的咨询，确认检索结果包含对应文档的相关信息。
