# 危化品储运的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
危化品储运的数据来源包括企业内部罐区作业记录、装卸台账、属地应急管理部门的合规备案文档，以及行业通用的应急处置手册。更新节奏为作业数据实时同步，备案文件随监管要求调整更新。文档结构包含结构化台账、长文本合规指南、批量Excel作业清单，字段涵盖危化品通用名、UN编号、存储温度阈值、最大存储量、合规要求编号，单位多为立方米、千克、摄氏度。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
结构化台账的字段多且带有明确单位，多轮对话需跟踪用户询问的具体字段，避免混淆不同危化品的存储参数；长文本合规指南篇幅较长，提示词需限定上下文窗口，防止token溢出影响回答准确性；批量Excel作业清单数据量大，多轮对话需支持批量数据的精准查询，提示词需明确指定查询范围；实时同步的作业数据要求对话上下文保持时效性，避免调用过时的知识库内容，影响合规判断。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 适配危化品合规文档、作业台账的单轮查询需求，防止token溢出 |
| 问题优化开关 | 开启 | 梳理用户模糊的储运咨询问题，明确核心诉求如存储条件或合规要求 |
| 单次搜索上限 | 前6条 | 匹配危化品数据的字段密度，避免冗余信息干扰回答 |
| `chatId` | 绑定用户会话ID | 跟踪多轮对话中的危化品品类、存储位置等上下文信息 |
| `messages` | 按会话顺序拼接历史消息 | 保持多轮对话的上下文一致性，确保参数引用准确 |
| `variables` | 注入当前查询的危化品UN编号 | 精准匹配对应存储与合规数据，缩小搜索范围 |

## 容易做错的三处
- 对话后返回token消耗统计为空，原因是未正确配置`variables`注入会话token统计参数，导致无法跟踪单轮对话的token使用量。
- 导入10万中文字word或15000行excel数据后多轮对话无响应，原因是未限定最大上下文长度，导致长文本加载后token溢出，触发系统超时。
- 调用对话接口上传危化品合规文档失败，原因是未正确配置`messages`中的文件元数据字段，导致接口无法识别上传的作业文档。

## 怎么确认配好了
- 发起单轮危化品存储条件查询，检查返回结果是否包含对应UN编号的存储参数，确认`variables`是否正确注入查询关键词。
- 发起连续三轮对话，跟踪上下文是否保留前一轮提到的危化品品类，确认`chatId`和`messages`配置生效。
- 导入批量作业清单数据，发起多轮查询，检查回答是否仅返回匹配当前查询的内容，确认单次搜索上限与问题优化开关配置合理。
- 调用对话接口上传危化品合规文档，检查接口返回状态码是否正常，确认文件元数据字段配置正确。
