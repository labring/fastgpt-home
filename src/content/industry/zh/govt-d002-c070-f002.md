# 发电装备制造的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
发电装备制造的办事咨询相关数据主要来自设备技术手册、运维规程、质检报告、办事流程指南三类来源。数据更新节奏分为两类，新机型量产上线时的突发更新，以及季度更新的办事指南与年度更新的质检台账。文档结构包含设备型号、额定功率、转子转速等带单位的参数字段，还有故障代码、维修步骤、办事审批流程等内容，单篇文档长度从数十字的办事提示到数千字的运维手册不等。

## 这些特征在「向量模型与索引」这一环带来什么约束
首先，数据包含带明确单位的设备参数，向量模型需保留数值与单位的关联语义，避免分块拆分参数单元导致语义断裂。其次，数据更新存在突发与定期两种节奏，索引需支持增量同步与全量重建的灵活切换，适配不同更新频率的需求。第三，单篇文档长度差异显著，分块策略需兼顾短文档的完整性与长文档的语义连贯性。第四，字段包含设备型号、故障代码等精准检索项，索引需关联字段元数据以缩小召回范围，提升检索精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配发电装备文档从短提示到长运维手册的长度差异，保留参数与上下文的完整语义 |
| 重叠长度 | 150–200 字符 | 避免分块拆分连续的设备参数或故障代码，保证语义连贯性 |
| 相似度阈值 | 0.72–0.78 | 平衡发电装备参数匹配的精准度与召回覆盖范围，过滤低相关性结果 |
| 单次搜索上限 | 前 8 条 | 适配单轮咨询涉及的有限设备类型，避免过多结果干扰上下文整合 |
| `maxToken` | 8000 | 适配FastGPT v4.17.0的默认上下文上限，承载长文档召回的内容长度 |
| 最大上下文 | 6000 token | 平衡回答的信息完整性与模型输入的限制要求 |

## 容易做错的三处
- 现象：使用chunk模式调用pushdata API上传文档后，界面长期显示“索引中”状态。原因：分块长度设置超出向量模型的单次处理上限，导致索引任务队列积压。
- 现象：问答拆分后的最后一组索引无法完成构建。原因：最后一组分块的字符数未达到有效嵌入生成的最低要求，或未关联设备型号等核心字段元数据。
- 现象：使用第三方embedding模型时，召回结果与原文档匹配度不足。原因：未针对发电装备的单位化参数调整embedding模型的输入预处理，导致数值语义丢失。

## 怎么确认配好了
- 上传单篇包含额定功率、转子转速等参数的短文档，查看分块后的片段是否保留完整的参数与单位，确认分块长度设置合理。
- 发起一次包含具体设备型号的咨询，查看召回结果的条数是否符合单次搜索上限的配置，确认相似度阈值的生效情况。
- 上传一篇更新后的运维文档，查看索引是否在合理周期内完成同步，确认增量索引配置生效。
- 查看FastGPT v4.17.0的系统日志，确认`maxToken`参数的配置值与实际使用的上下文长度匹配，无溢出报错。
