# 发电集团的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
数据主要来自发电集团内部办事指南库、线下窗口咨询录音转写、工单系统归档记录、上级能源监管政策文件。更新节奏为政策类文档按季度同步，日常咨询记录实时入库。单条文档通常包含咨询问题、标准答复、办理流程、所需材料、责任部门、办理时限等字段，办理时限以工作日为单位，材料清单以项为单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
咨询记录的口语化表述与政策文档的书面化表述差异较大，需针对不同文本类型调整分块逻辑。实时工单的高频更新要求支持增量索引，避免全量重建消耗过多服务器资源。多字段结构中，仅咨询问题、标准答复需生成向量，办理时限等结构化字段无需参与索引，减少无效计算。单条文档长度跨度大，需动态适配分块阈值，避免长文档拆分后语义断裂或短文档信息丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配政策文档与咨询记录的混合文本长度，避免语义断裂 |
| 重叠长度 | 100–150 字符 | 保留分块间的上下文关联，适配口语化咨询内容的语义连贯性 |
| `maxToken` | 8192 token | 匹配主流向量模型的输入上限，兼容长文档拆分后的拼接需求 |
| `defaultToken` | 2048 token | 用于短咨询问题的向量生成，避免超出模型输入限制 |
| 单次索引批次 | 500 条 | 平衡索引速度与服务器资源占用，适配实时工单的增量更新 |
| 超时阈值 | 600 秒 | 避免长文档索引过程中因超时中断任务 |

## 容易做错的三处
- 现象：升级FastGPT v4.17.0后，原可正常分块的CSV文件报错。原因：新版本对CSV文件的字段解析规则调整，未匹配原配置的字段映射关系，导致分块时读取字段失败。
- 现象：知识库索引任务卡住，未完成的数据无法继续执行。原因：增量索引时未跳过已处理的文档ID，重复提交导致任务阻塞，或服务器资源不足无法承接当前索引负载。
- 现象：知识库引用结果未调用预期的向量模型。原因：未在向量模型配置页切换目标模型，或配置的模型接口超时未生效，导致系统回退至默认模型。

## 怎么确认配好了
- 上传单条典型文档，检查分块结果是否符合预期的长度与重叠规则。
- 提交增量索引任务，查看任务日志中是否有字段解析错误或超时提示。
- 切换向量模型后，测试咨询问答的返回结果是否匹配新模型的生成逻辑。
- 查看索引进度面板，确认实时工单的增量更新任务能够正常启动与完成。
