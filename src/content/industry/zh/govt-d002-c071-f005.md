# 发电集团的办事咨询与答复：工具调用与插件

## 这个品类的数据长什么样
发电集团办事咨询与答复的数据主要来源于内部办事指南库、客服工单系统、政策文件公告及线下办事窗口记录。数据更新节奏分为两类：通用办事流程每季度更新一次，并网、电价申报等专属事项的政策文件随行业调整月度更新。文档结构包含事项编号、办理主体、所需材料、办理时限、咨询渠道、常见问题等字段，其中材料单位以“份”“份/套”、办理时限以“工作日”为标准标注。

## 这些特征在「工具调用与插件」这一环带来什么约束
发电集团办事咨询数据的分散来源要求工具调用插件需对接多系统接口，实现跨数据源的信息聚合。高频更新的政策文件要求插件需配置定时同步机制，避免返回过时的办事指引。字段的标准化程度较高但存在行业专属术语，要求工具调用的prompt需嵌入发电集团办事事项的专属词汇，确保大模型能准确识别调用需求。此外，部分办事事项需联动内部审批系统，工具调用需适配内网访问的权限校验规则。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |

| `toolChoice` | `auto` | 适配发电集团办事咨询的多类型工具调用需求，自动匹配可用插件 |
| `functionCall` | 启用 | 适配发电集团办事事项的标准化流程，触发精准的函数调用 |
| 插件同步频率 | 每6小时 | 平衡数据时效性与系统资源占用，适配发电集团月度更新的政策文件节奏 |
| 工具调用超时时间 | 30秒 | 覆盖发电集团内部系统多数响应场景，避免无效等待 |
| 单次工具调用返回条数 | 前3条 | 聚焦发电集团办事咨询的高频问题，减少冗余信息干扰 |
| prompt上下文长度 | 800-1200字符 | 适配发电集团办事事项的文本长度，避免超出模型上下文限制 |

## 容易做错的三处
- 现象：工具调用返回结果为空或字段缺失。原因：未在prompt中嵌入并网申请、电价申报等发电集团专属办事术语，导致大模型无法匹配对应插件。
- 现象：调用Gemini模型时工具调用无响应。原因：未正确配置`functionCall`的兼容模式，导致模型无法触发函数调用。
- 现象：工具调用超时且日志显示连接失败。原因：未适配内网穿透的访问配置，导致插件无法正常调用内部系统接口。

## 怎么确认配好了
- 发起包含并网申请、电价申报等发电集团专属办事事项的咨询，查看大模型是否触发工具调用并返回对应结果。
- 进入插件管理页面，检查数据同步日志，确认插件按配置的频率自动更新办事指南数据。
- 查看工具调用日志，确认`toolChoice`和`functionCall`的参数配置与预设值一致。
- 模拟超时场景，验证工具调用在超过设定的超时时间后是否返回合理的错误提示。
