# 发电集团的办事咨询与答复：知识库检索与召回

## 这个品类的数据长什么样
数据主要来源于发电集团内部办事指南文档、客服历史工单、政务审批备案文件与一线运维问答记录。更新节奏随业务调整，政策类文档每季度同步更新，实时咨询工单每日新增入库。单条数据包含问题文本、标准答复、业务分类标签、生效日期四个核心字段，字段单位分别为字符、字符、分类编码、日期格式。

## 这些特征在「知识库检索与召回」这一环带来什么约束
业务分类标签的存在要求检索时需按业务模块定向召回，避免跨领域无关结果混入。实时新增的咨询工单要求召回环节支持增量数据同步，避免新问题无法被快速检索到。政策类文档的生效日期字段要求检索时需自动过滤已失效的答复内容，确保返回结果合规。专业术语密集的文本特征要求召回后需通过重排环节优化结果排序，提升匹配精度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 匹配发电集团专业文本的语义相似度区间，避免过低导致无关结果、过高导致召回不足 |
| `limit` | 前8条 | 覆盖发电集团办事咨询的常见多步骤答复需求，单次召回数量适配常规上下文窗口 |
| `usingReRank` | 开启 | 针对专业术语密集的发电业务文本，优化排序结果的相关性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 对发电集团的长文本办事指南，通过扩展查询提升召回广度 |
| `collectionIds` | 按业务模块指定 | 定向召回对应业务线的知识库数据，避免跨分类干扰 |
| `searchMode` | 语义召回 | 适配发电集团专业术语密集的文本特征，提升语义匹配精度 |

## 容易做错的三处
- 现象：重排模型运行失败，界面显示模型调用超时或资源不足报错。原因：未按发电集团知识库文本的平均长度配置重排模型的输入限制，导致模型无法处理长文本输入。
- 现象：知识库检索结果覆盖不全，核心办事问题未被召回。原因：未开启`datasetSearchUsingExtensionQuery`，或`similarity`取值过高，过滤掉了部分语义匹配的结果。
- 现象：单次检索返回结果超出工作流预设的上下文窗口。原因：`limit`取值过大，未适配发电集团办事答复的常规上下文长度。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的测试环境中，上传一条发电集团的典型办事问题，检查返回结果的`similarity`分值是否落在0.72–0.80区间内。
- 查看检索结果的来源分类，确认仅包含指定`collectionIds`对应的业务模块数据，无跨分类的无关结果。
- 开启`usingReRank`后，对比开启前后的结果排序，确认相关性更高的结果排在前列。
- 触发`datasetSearchUsingExtensionQuery`后，检查召回结果的数量是否符合预期，无冗余无关内容。
