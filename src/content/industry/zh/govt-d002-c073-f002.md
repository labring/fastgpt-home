# 国有产业基金的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
国有产业基金的办事咨询数据主要来自内部备案档案、投资决策会议纪要、产业扶持政策文件、项目尽调报告、出资人沟通函件等。数据更新节奏为不定期，伴随新基金备案、新增投资项目、政策修订时触发更新。文档结构包含标准化字段与非结构化内容，标准化字段包括基金名称、备案编号、成立日期、出资规模（单位：万元）、投资领域等，非结构化内容多为数千字的尽调报告、流程说明文档。

## 这些特征在「向量模型与索引」这一环带来什么约束
产业基金数据的分散来源要求索引支持混合类型内容的编码，标准化字段与非结构化文本需适配不同的向量编码逻辑。不定期但单次更新量大的特性，要求索引支持批量上传与增量更新的灵活配置。长文本尽调报告与短字段并存的文档结构，需要平衡分块长度与上下文完整性，避免分块过碎丢失专业术语关联，或分块过长超出模型输入限制。办事咨询多围绕审批流程、出资要求、项目范围展开，索引需优先召回关联度高的政策与流程文档。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配产业基金尽调报告、政策文件的单段信息密度，避免分块过碎丢失上下文关联 |
| 重叠长度 | 100–150 字符 | 衔接相邻分块的流程描述与术语关联，覆盖跨块的逻辑链条 |
| 相似度阈值 | 0.72–0.78 按实测标定 | 匹配产业基金专业文档的语义相似度分布，平衡召回精度与覆盖范围 |
| 单次搜索上限 | 前 8 条 | 平衡办事咨询的响应速度与信息完整性，覆盖常见咨询的关联场景 |
| maxToken | 4096 | 适配长文档分块后的上下文拼接，符合通用大模型的输入长度限制 |
| defaultToken | 2048 | 用于备案编号、出资方等短字段的向量编码，优化轻量查询的召回效率 |

## 容易做错的三处
- 现象：索引任务报错提示「分块内容过长超出限制」，原因：未针对产业基金的长文本尽调报告调整分块长度参数，使用了通用场景的短分块配置。
- 现象：使用ollama作为向量模型时，搜索结果匹配度偏低，原因：未根据产业基金的专业术语调整相似度阈值，通用模型的语义适配性不足。
- 现象：发起结构化字段查询（如输入基金备案编号）时无匹配结果，原因：未针对标准化字段配置单独的向量编码参数，导致结构化信息无法被有效召回。

## 怎么确认配好了
- 上传单篇产业基金尽调报告，查看分块预览界面，确认分块长度落在预设区间内，相邻分块存在重叠内容。
- 发起一条关于基金备案流程的咨询，查看搜索结果的返回条数，确认不超过单次搜索上限的设置值。
- 查看FastGPT v4.17.0版本的索引任务日志，确认没有出现分块过长或token超限的报错提示。
- 测试结构化字段查询，输入某基金的备案编号，确认能召回对应文档的完整信息。
