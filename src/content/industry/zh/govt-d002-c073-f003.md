# 国有产业基金的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
国有产业基金的办事咨询数据主要来自国有资产监管机构的备案信息、基金管理人报送的募集与运作报告、项目投资及投后管理的内部台账。数据更新节奏为月度更新投后执行数据、季度更新整体运作数据。文档多为结构化表格格式，包含基金编码、项目编号、投资额度（单位为万元）、到位时间、退出进度、监管评级等固定字段，无高占比的自由格式非结构化文本。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
结构化的多字段文档结构要求多轮对话的上下文必须明确关联指定字段，避免生成无数据支撑的答复。月度、季度的更新节奏要求对话系统需要在每次交互前校验数据的最新更新时间，过滤过期的台账信息。字段附带标准化单位要求提示词需要强制绑定单位校验逻辑，防止数值与单位不匹配的输出。国资备案数据的合规属性要求对话上下文不能泄露未公开的敏感字段，需要在提示词中明确脱敏规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文窗口 | 8000–12000 token | 匹配国有产业基金多字段数据的总字符量，避免截断核心备案信息 |
| 问题优化开关 | 开启 | 针对结构化字段的查询，优化用户提问的字段匹配精度 |
| `chatId`绑定规则 | 绑定单基金主体的对话链路 | 确保多轮对话仅关联指定国有产业基金的专属数据 |
| `variables`参数配置 | 传入基金编码、监管周期 | 限定对话仅调用对应周期内的最新数据 |
| `messages`历史截断规则 | 截断超过1000字符的单条历史消息 | 控制单轮对话的token消耗，避免超时 |
| 上下文数据过滤 | 保留近3次交互的历史记录 | 适配月度更新的数据节奏，避免加载过期台账 |

## 容易做错的三处
- 现象：对话历史中残留其他基金的项目数据，导致答复出现跨主体的错误信息。原因：未通过`chatId`绑定指定国有产业基金的专属对话链路，复用了历史对话的上下文。
- 现象：多轮对话无法复用前一轮生成的项目进度数据，需要重复发起相同提问。原因：未将前一轮的输出结果通过`variables`参数传入后续对话，未建立上下文的变量传递链路。
- 现象：AI对话的完成原因字段无法被下游组件读取，导致无法基于结果触发循环逻辑。原因：未开启对话组件的变量输出开关，未将完成原因字段写入`variables`参数供下游组件调用。

## 怎么确认配好了
- 发起针对指定基金编码的咨询，检查对话上下文仅显示该基金的项目数据，无跨主体信息。
- 发起两轮递进式提问，例如先查询某项目的投资额度，再查询该额度的到位比例，确认第二轮对话自动复用了前一轮的项目信息。
- 查看FastGPT v4.17.0的对话组件变量输出面板，确认`messages`历史记录、`variables`参数的配置项已正确绑定对应字段。
- 触发连续5次交互的测试，确认对话未出现上下文截断或数据过期的情况。
