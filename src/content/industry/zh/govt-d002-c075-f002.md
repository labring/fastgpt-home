# 国有资本投资公司的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
国有资本投资公司办事咨询相关的数据来源包括内部办事流程规范、国资监管部门发布的政策文件、对外公开的办事指南、下属企业及员工的咨询答疑记录。更新节奏为：政策文件按监管要求或季度更新，内部办事流程按需调整，咨询记录实时留存。文档结构包含政策文号、发布单位、生效日期、办事步骤、所需材料、答疑条目等字段，单位包括文号格式为“国资发改革〔年份〕XX号”、生效日期为YYYY-MM-DD、材料清单以项为单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
政策文档多为长文本且包含严谨的层级逻辑，分块长度需适配段落完整性，避免拆分核心办事流程；咨询记录以问答对形式存在，需要保留分块间的上下文关联，因此重叠长度需设置合理区间；元数据字段如生效日期、文号可用于过滤过期或无关内容，索引需支持元数据关联检索；数据更新存在批次性，增量索引需适配按需触发的更新频率，避免全量索引的资源浪费。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配政策文档、办事流程的段落长度，避免拆分完整逻辑 |
| 重叠长度 | 100–200 字符 | 保留跨分块的上下文关联，匹配咨询记录的问答连贯性 |
| 相似度阈值 | 按实测标定 | 适配国资政策的严谨性，避免无关内容匹配 |
| 单次搜索上限 | 前 10 条 | 控制返回结果的信息量，符合办事咨询的精准需求 |
| `defaultToken` | 4000 token | 适配长文本政策的上下文拼接需求 |
| `maxToken` | 8000 token | 覆盖完整的办事流程与政策组合内容 |

## 容易做错的三处
- 现象：向量化请求仅携带单个文本切片，无法触发向量化服务的批处理优化。原因：未调整FastGPT的切片提交逻辑，默认按单条切片发送请求，未适配向量化服务的批量接收要求。
- 现象：搜索召回的结果无法覆盖全部相关办事咨询文档，精准度不足。原因：未根据国有资本投资公司的政策文档特征设置合理的分块长度与重叠比例，导致文档逻辑被拆分断裂。
- 现象：向量检索结果与业务问题的匹配度不符合预期，出现无关内容召回。原因：未结合国资政策的元数据（如文号、生效日期）配置索引过滤规则，仅依赖纯文本向量匹配。

## 怎么确认配好了
- 查看向量化服务的日志，确认请求携带的切片格式符合配置要求，或批量切片配置已生效。
- 提交一条典型的办事咨询问题，检查召回结果是否包含相关的政策文档与办事指南。
- 查看索引构建的进度日志，确认增量更新已按配置的更新频率自动触发。
- 检查`defaultToken`与`maxToken`的配置是否匹配当前业务的长文本处理需求。
