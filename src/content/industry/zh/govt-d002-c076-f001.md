# 国有资本运营公司的办事咨询与答复：HTTP 接口与外部系统

## 这个品类的数据长什么样
国有资本运营公司的办事咨询数据来源为企业内部办事咨询工单系统、国资监管部门公开咨询台账。数据更新节奏为实时接收新提交的咨询工单，每月同步更新存量咨询的答复状态。文档采用结构化JSON格式，字段包含咨询主体编码、咨询事项详情、提交时间戳、答复进度标识、正式答复文本、关联国资监管文件编号，其中编码为字符串类型，时间戳为毫秒级整数，进度标识为固定枚举值，答复文本为不限长文本，文号为标准监管文件字符串格式。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据来源涉及内部工单与国资监管台账，要求接口必须对接内部系统的身份认证体系，确保调用权限合规。实时更新的业务需求，要求接口支持实时回调或长轮询机制，超时设置需适配国资办事的平均流转时长。结构化的字段要求请求与响应必须严格匹配预设格式，不可缺失关联监管文号等敏感字段。此外，月度存量数据同步的批量需求，要求接口支持分页查询，避免单次请求传输过大的数据量，同时需对咨询主体编码进行校验，实现数据隔离。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带国资内部系统颁发的Bearer令牌，格式为`Bearer <token>` | 适配国资系统的身份认证要求，确保接口调用权限合法 |
| `variables` | 传入`{"org_code": "对应运营公司主体编码", "policy_scope": "国资监管范围"}` | 限定接口仅处理本公司及监管范围内的咨询数据，避免跨主体数据泄露 |
| `responseData` | 仅返回`consult_id, submit_time, reply_status, reply_content`字段 | 精简响应内容，符合国有资本运营公司的数据脱敏要求，减少传输开销 |
| 请求超时时间 | 600 秒 | 适配国资办事咨询的平均流转时长，避免因流程审批导致的超时中断 |
| 分页查询上限 | 前 200 条 | 适配月度存量数据同步的批量处理需求，避免单次请求数据量过大 |
| 回调地址 | 配置为内部工单系统的回调接口路径 | 实现咨询状态变更的实时同步，符合实时更新的业务要求 |

## 容易做错的三处
- 现象：接口返回的咨询记录无法区分不同运营公司主体的工单，部分字段为空。原因：未在`variables`中传入正确的主体编码参数，导致接口未做数据隔离。
- 现象：调用接口后返回状态码401，认证失败。原因：未正确配置`Authorization`参数，令牌格式错误或已过期。
- 现象：批量同步接口返回结果条数与预期不符，仅返回少量数据。原因：未设置合理的分页查询上限，或未处理分页偏移量参数。

## 怎么确认配好了
- 调用配置了`Authorization`参数的接口，查看响应状态码为200，确认身份校验通过。
- 传入测试用的`variables`主体编码参数，查询本公司的咨询工单，确认仅返回对应主体的数据。
- 发起超时时间为600秒的请求，模拟较长流程的咨询查询，确认接口未提前中断。
- 配置回调地址后，提交一条测试咨询工单，确认内部系统收到状态变更的回调通知。
