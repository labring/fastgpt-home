# 国有资本运营公司的办事咨询与答复：表单与交互

## 这个品类的数据长什么样
国有资本运营公司的办事咨询与答复数据主要来源于国资监管系统的官方政策库、内部运营台账、下属企业报送的业务表单及监管报表。政策数据按发布单位、文号、生效日期、适用范围结构化存储，下属企业申报数据包含企业名称、注册资本、业务类型、申报金额等字段，注册资本与申报金额单位统一为万元，时间字段采用YYYY-MM-DD格式。监管报表数据按月度或季度更新，政策文件数据实时同步更新，内部台账数据每日更新。

## 这些特征在「表单与交互」这一环带来什么约束
国资监管政策的实时更新要求交互组件必须支持快速拉取最新政策内容，避免返回过期信息。下属企业申报字段的标准化要求表单输入组件必须严格匹配监管报送的字段规则，不得自定义非标准字段。单位统一为万元的要求，需要在交互界面中明确标注单位提示，防止输入数据出现单位混用。多下属企业的申报场景，要求用户选择组件支持批量选择与模糊搜索，提升申报操作效率。跨系统的数据拉取需要合理配置并发与超时参数，避免因接口承载不足导致交互失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 绑定国资监管标准字段，开启字段格式校验 | 确保输入数据符合国资系统的报送规范 |
| `userSelect` | 预设下属企业分类选项，支持模糊搜索 | 适配多下属企业的业务申报场景 |
| 超时设置 | 600 秒 | 覆盖国资系统跨节点数据拉取的合理耗时 |
| 上下文长度限制 | 8000 token | 容纳完整的政策文件与申报历史内容 |
| 知识库关联范围 | 仅限国资监管政策库与内部运营台账 | 确保咨询答复内容符合国资监管合规要求 |

## 容易做错的三处
- 现象：多chat交互页面同时打开时出现connection error报错。原因：未针对国资监管系统的内部接口配置合理的并发限制与超时参数，导致多页面并发请求超出接口承载上限。
- 现象：工具调用时界面出现未格式化的Human <Instruction>指令文本。原因：未在`formInput`组件中配置系统指令过滤规则，导致内部调用指令被直接返回给用户。
- 现象：知识库选择时变量引用无法生效，选择的知识库无法自动关联对应业务字段。原因：未将业务变量与`userSelect`组件的预设选项绑定，导致变量无法正确映射到知识库筛选条件。
