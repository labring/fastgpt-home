# 城市公交的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
城市公交办事咨询与答复的数据主要来自公交运营调度系统、线路运维台账、便民服务平台。实时类数据如当前班次位置、预计到站时间更新频率为分钟级；线路票价、站点设施等静态数据更新周期为季度。数据包含结构化字段与非结构化文档：结构化字段含线路编号、站点名称、首末班时段，票价以元为单位；非结构化内容含线路调整公告、失物招领启事、无障碍服务说明。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时班次数据的分钟级更新要求模型调用需控制响应时长，确保返回信息与当前运营状态同步。静态线路、票价数据的季度更新周期，要求知识库同步配置需匹配该节奏，避免知识库内容滞后。结构化字段含明确单位，模型生成答复时需严格遵循单位规则，防止出现单位匹配错误。非结构化的服务公告、失物招领内容篇幅较短，模型上下文配置需适配短文本处理，避免冗余的长上下文资源占用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配公交咨询以短文本为主的上下文需求，平衡信息完整性与调用成本 |
| `maxTokens` | 2000–3000 token | 确保答复内容覆盖线路查询、票价说明等典型咨询的完整输出 |
| `quoteMaxToken` | 1500 token | 限制引用知识库内容的长度，避免引入冗余的非相关公交运营数据 |
| `temperature` | 0.3–0.5 | 降低随机性，确保线路、票价等 factual 信息答复的准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配FastGPT v4.17.0的代理接口规范，确保模型请求正常路由 |
| `AIPROXY_API_TOKEN` | 按平台分配的密钥填写 | 完成模型调用的身份验证，保障接口访问安全 |

## 容易做错的三处
- 现象：调用模型时返回60000ms超时报错，接口返回状态码504。原因：未针对公交实时数据咨询的延迟需求调整超时配置，默认超时时长不足以覆盖实时班次查询的请求处理。
- 现象：无法通过日志或界面获取模型请求的requestid，无法定位咨询答复异常原因。原因：未开启FastGPT的请求日志追踪配置，未启用requestid的返回与记录。
- 现象：批量执行节点在线调试可完成流程，但通过API调用时无法执行完毕。原因：API调用时未正确配置批量节点的并发阈值，或未传递与在线调试一致的上下文参数，导致批量任务执行中断。

## 怎么确认配好了
- 发起一条典型公交咨询，如“XX路公交首末班时间”，检查答复内容是否匹配当前知识库的最新数据。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置未出现格式错误。
- 测试需要较长处理时间的咨询，如多条线路的换乘查询，验证超时配置是否符合业务需求。
- 检查批量执行节点的调用结果，确认API调用时的参数与在线调试时的配置一致。
