# 城市水务的办事咨询与答复：部署与升级

## 这个品类的数据长什么样
城市水务办事咨询与答复的数据，来源于水务运营方的客服系统、12345政务服务热线转办件、线下办事窗口登记台账。数据更新包含实时增量同步新增咨询与办结记录，以及每周一次的全量历史归档更新。单条数据包含咨询主体、咨询事项、诉求详情、办理环节、回复内容、办结状态、办理时限、责任部门8个字段，字段类型以文本、枚举值为主，部分时间类字段带有标准时间戳单位。

## 这些特征在「部署与升级」这一环带来什么约束
城市水务办事咨询数据来源分散，部署时需要支持多源异构数据的接入配置。数据更新包含实时增量与定期全量两种模式，升级时需保证同步任务不中断当前办理流程，需配置灰度升级的触发阈值。咨询内容包含管网运维、水表检定等专业术语，需关联专属术语词库，避免语义识别偏差。多数水务办事场景部署在内网环境，需支持带用户名密码的HTTP代理配置，确保外部知识库与模型接口的正常访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:port/dbname?authSource=admin` | 存储非结构化的咨询留言与回复话术，适配水务数据的半结构化存储需求 |
| `PG_URL` | `postgresql://user:pass@host:5432/water_affairs?sslmode=disable` | 存储结构化的工单编号、办结时间等字段，保障数据查询效率 |
| `REDIS_URL` | `redis://:password@host:6379/0` | 缓存高频咨询的标准回复与专业术语映射，降低数据库查询压力 |
| `DB_MAX_LINK` | `20–30 个` | 适配水务数据的并发访问量，避免数据库连接耗尽 |
| `STORAGE_S3_ENDPOINT` | 按内网存储服务地址填写 | 存储咨询相关的附件材料，如用户上传的水表照片、管网图纸 |
| `FE_DOMAIN` | 内网访问的前端域名或IP:端口 | 配置办事咨询页面的访问地址，适配水务内网办公场景 |

## 容易做错的三处
- 现象：升级到FastGPT v4.17.0后，配置的专业模型无法生效，聊天时自动切换为其他模型。原因：升级时未保留原应用的模型绑定配置，或配置项`ROOT_KEY`未正确关联应用权限。
- 现象：内网部署时无法访问外部模型接口，提示连接超时。原因：未配置带用户名密码的HTTP代理，或代理参数未同步到所有服务节点。
- 现象：专业咨询（如管网压力异常）的回复不准确，出现术语误解。原因：未关联水务专属术语词库，或词库更新频率未匹配业务变化。

## 怎么确认配好了
- 执行跨系统数据同步脚本，检查是否能正常拉取水务咨询相关数据，确认`MONGODB_URI`与`PG_URL`的连接状态正常。
- 发起一条包含专业术语的测试咨询，查看回复是否调用了预设的水务术语词库，确认缓存配置生效。
- 备份当前应用配置后执行升级操作，升级完成后验证配置项未丢失，确认`ROOT_KEY`的权限关联正常。
- 在内网环境访问配置的前端地址，确认`FE_DOMAIN`配置正确，咨询界面可正常加载与交互。
