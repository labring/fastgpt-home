# 城市燃气的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
城市燃气办事咨询与答复的数据主要来源于燃气经营企业的办事指南文档、用户咨询台账、报修工单记录、营业厅服务日志及官方公开的常见问题库。日常数据更新以每日新增的用户咨询和工单为主，每季度更新标准化办事流程，重大政策调整时即时更新相关文档。单篇文档多为结构化的办事步骤说明，或非结构化的用户口语化咨询记录，包含办理事项名称、所需材料、办理时限、收费标准、咨询渠道等字段，时限单位多为工作日，收费单位多为元/立方米。

## 这些特征在「向量模型与索引」这一环带来什么约束
城市燃气办事数据包含结构化流程字段与口语化咨询内容，长文档如完整办事指南可能超过10M，分块时需避免拆分关键流程步骤；数据更新节奏兼具即时性与周期性，需支持增量索引以适配不同更新频率；字段间存在强语义关联，如办理材料与流程步骤需保持上下文绑定，向量模型需准确识别跨字段的语义关联，否则会导致检索结果匹配度下降。同时，大量标准化问答对与口语化咨询的混合，要求索引配置兼顾语义对齐与上下文保留。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配城市燃气办事指南单段流程的长度，避免拆分开户、报修等关键步骤 |
| 重叠长度 | 100–150 字符 | 保留跨块的流程上下文，确保开户流程的前置材料与后续步骤不会被割裂 |
| `maxToken` | 4096 token | 适配通用嵌入模型的输入长度上限，覆盖完整办事流程块的语义表达 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 区分用户口语化咨询与标准化办事指南的语义匹配度，避免误匹配或漏匹配 |
| 单次搜索上限 | 前 8 条 | 覆盖用户咨询可能涉及的多个相关办事环节，如报修同时涉及故障排查与流程办理 |
| `defaultToken` | 2048 token | 配置基础上下文窗口，适配日常咨询的问答长度需求 |

## 容易做错的三处
- 现象：上传单篇10M以上的燃气办事指南文档时，部分chunk显示向量化失败，界面弹出“嵌入异常”提示。原因：长文档分块时未设置合理的重叠长度，导致关键流程步骤被拆分至不同块，嵌入模型无法生成有效语义向量。
- 现象：因上传大量用户工单文档导致服务器资源耗尽重启后，原有知识库处于“未就绪”状态，无法自动完成索引任务。原因：未配置增量索引自动触发机制，重启后系统未自动扫描待索引的知识库文件，需手动触发索引操作。
- 现象：升级FastGPT至v4.17.0后，原有燃气知识库无法返回检索结果，搜索结果为空。原因：版本更新后嵌入模型的向量维度发生变化，原有索引的向量格式不兼容新模型，导致检索无法匹配有效结果。

## 怎么确认配好了
- 上传一篇10M以上的燃气办事指南文档，检查分块预览界面中是否保留了完整的流程步骤，无明显拆分断裂。
- 模拟用户口语化咨询，比如“燃气表故障怎么报修”，查看检索结果是否匹配对应的报修流程文档，结果条数符合单次搜索上限设置。
- 手动触发一次增量索引，等待任务完成后，检查知识库状态是否变为“就绪”，无异常提示。
- 对比当前嵌入模型的向量维度参数，确认新生成的索引向量格式与平台配置一致。
