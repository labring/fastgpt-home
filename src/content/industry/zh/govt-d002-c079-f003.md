# 城市燃气的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
城市燃气办事咨询的数据主要来自属地燃气经营企业的官方办事指南、用户常见问题库、管网运维规范文档。数据更新节奏随属地政策调整或业务流程变更触发，无固定周期但不超过30天。单份文档多按办事事项拆分，包含事项名称、办理材料清单、办理时限、收费标准、咨询渠道等字段，时限单位多为工作日，收费单位多为元/立方米或元/户。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
办事事项拆分的文档结构要求多轮对话需跟踪当前办理的具体事项，避免上下文混淆导致的答复偏差。非固定周期的更新要求对话系统需在每次调用前校验知识库最新版本，提示词中需加入数据时效性校验的引导。多字段的文档结构要求提示词需明确指定答复需优先匹配对应字段，例如办理材料需单独列出，不得混入收费标准内容。跨属地的燃气数据差异要求对话系统需根据用户所在区域自动匹配对应知识库条目。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 字符 | 匹配单份燃气办事事项文档的常规长度，避免截断办理材料、时限等核心信息 |
| 单次召回条数 | 前 3 条 | 燃气办事的核心咨询内容集中在3份以内的官方文档中，过多召回会增加上下文冗余 |
| `variables` 配置 | 绑定用户属地参数 | 自动匹配对应区域的燃气办事知识库条目，避免跨属地答复偏差 |
| 问题优化开关 | 开启 | 燃气用户咨询多为口语化表述，优化后可更精准匹配知识库中的标准化办事条目 |
| `chatId` 配置 | 绑定用户当前办理事项ID | 跟踪多轮对话的上下文，避免跨用户或跨办理事项的上下文混淆 |
| 知识库版本校验 | 每次会话前执行 | 适配燃气政策非固定更新的节奏，确保每次答复使用最新版的办事指南文档 |

## 容易做错的三处
- 对话框上传燃气办事指南文档时提示503错误，但后台日志显示文件上传成功。原因是对话会话的`messages`参数未正确绑定上传文件的临时存储路径，导致前端校验超时但后台已完成存储。
- 使用严格问答模板时，检索到知识库中的图片地址链接，提示未找到答案。原因是提示词未配置图片链接的识别规则，仅匹配文本类知识库条目。
- 多轮对话中跨办理事项的上下文未被清空，导致答复混淆不同事项的办理材料。原因是未通过`chatId`绑定当前办理事项，导致上下文未按会话隔离。

## 怎么确认配好了
- 发起一次燃气开户的多轮咨询，核对对话上下文是否随绑定的办理事项ID自动隔离，不同会话的上下文不互相干扰。
- 上传一份燃气办事指南文档，检查前端上传提示与后台日志的状态是否一致，无异常报错或不一致的情况。
- 使用严格问答模板检索图片地址类知识库条目，核对是否能正确识别并返回对应内容。
- 调整单次召回条数，核对返回的知识库条目数量是否符合预设的配置要求。
