# 城市燃气的办事咨询与答复：表单与交互

## 这个品类的数据长什么样
城市燃气办事咨询与答复的数据主要来自市政燃气公司的营业管理系统、管网运维平台、用户缴费档案与报装报修工单库。数据来源涵盖用户基础信息、用气地址、缴费记录、故障工单等，更新节奏分为实时（工单状态、缴费到账）、每日（用气统计）、每月（管网巡检数据）。文档结构以结构化字段为主，包含燃气户号、用户姓名、用气性质、故障类型等字段，部分字段附带单位，如用气用量单位为立方米，缴费金额单位为元，同时包含非结构化的咨询描述文本。

## 这些特征在「表单与交互」这一环带来什么约束
结构化字段的唯一性要求表单必须设置必填校验与格式校验，避免无效提交。实时更新的工单数据要求交互环节配置实时拉取逻辑，确保返回的咨询答案与当前状态一致。多场景的咨询类型要求表单预设常用选项，减少用户非结构化输入的成本。带单位的字段要求交互环节统一单位提示，防止用户因单位混淆导致提交错误。同时，燃气办事涉及用户隐私信息，表单需配置数据加密交互的约束，保障用户信息安全。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 添加10位数字格式校验，限制输入长度为12字符 | 城市燃气户号为10位数字格式，可过滤无效输入 |
| `userSelect` | 预设6个场景选项，覆盖报装、报修、缴费、政策咨询、过户、停气通知 | 该品类办事咨询的核心场景集中于此，可降低用户输入门槛 |
| 表单提示语 | 固定提示“请输入10位燃气户号及具体咨询内容” | 明确引导用户提供必填的唯一标识与场景信息 |
| 交互超时设置 | 15-20秒 | 燃气办事数据多为本地系统拉取，超时可避免用户等待过长 |
| 结果展示条数 | 前3条匹配结果 | 城市燃气咨询的答案多集中在常见问题，少量结果可提升阅读效率 |
| 全局变量赋值 | 按实测标定 | 不同企业的燃气系统接口参数不同，需结合实际对接情况调整 |

## 容易做错的三处
- 现象：对话中无法显示配置好的`formInput`组件，交互元素空白。原因：未在工作流中关联表单触发节点，或未开启对话上下文同步配置。
- 现象：开启语音功能后，应用端无法完成语音转文本输出。原因：未在配置中开启语音输入的全局开关，或未配置语音识别的关联参数。
- 现象：提交表单后无工作人员联系跟进。原因：未配置表单提交后的消息推送节点，或未关联企业微信的接收接口。
- 现象：无法通过全局变量赋值指定目标知识库。原因：未按照要求的格式编写全局变量赋值代码，或未绑定对应城市燃气知识库的正确标识。

## 怎么确认配好了
- 打开FastGPT v4.17.0的测试对话界面，输入10位数字的模拟燃气户号，检查表单组件是否正常显示并触发格式校验。

- 提交测试表单，检查是否能触发预设的消息推送或工单流转流程。
- 查看全局变量配置页面，确认已绑定对应城市燃气知识库的正确标识。
