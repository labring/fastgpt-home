# 城投平台的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
城投平台的办事咨询数据主要来源于内部政务服务事项库、历年市民咨询归档台账、市政公共服务办事指南。数据更新节奏分为三类：政策类办事规则每季度同步更新，高频咨询问答每周复盘更新，临时调整的便民服务规则即时更新。文档结构包含结构化事项条目与非结构化历史问答对，字段包含事项编码、办理条件、申请材料、承诺时限、办理地点等，部分文档附带办理流程的步骤说明。

## 这些特征在「模型接入与配置」这一环带来什么约束
城投平台的办事咨询数据特征会对模型接入配置带来多重约束。结构化事项条目包含明确的字段与单位，需确保模型在生成答复时能匹配对应字段的格式与单位，避免混淆工作日与自然日。高频更新的临时办事规则要求配置的上下文窗口可快速加载最新数据，避免返回过时信息。多来源的归档问答对与事项库结合，需限制模型仅调用已配置的知识库内容，不生成超出范畴的答复。部分数据包含跨事项的协同办理说明，需配置模型支持关联不同办事流程的字段信息，确保答复逻辑连贯。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配城投办事知识库的多字段关联内容，避免截断关键事项信息 |
| `maxTokens` | 2000–3000 token | 匹配单条办事答复的长度需求，确保覆盖完整办理流程说明 |
| `quoteMaxToken` | 1500–2000 token | 限制引用知识库内容的长度，避免冗余信息干扰模型生成答复 |
| `temperature` | 0.1–0.3 | 保持答复的准确性，避免生成不符合办事规则的虚构内容 |
| `toolChoice` | auto | 允许模型根据咨询内容选择是否调用知识库工具，适配结构化与非结构化咨询场景 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 适配蒸馏版DeepSeek或Xinference部署的模型接入路径 |

## 容易做错的三处
- 现象：尝试接入蒸馏版DeepSeek时，使用普通DeepSeek的接入配置后返回报错或无有效响应。原因：未正确配置模型的专属API端点与令牌校验规则，蒸馏版模型的接口参数与通用版存在差异。
- 现象：上传办事指南文档后，模型无法解析其中的结构化事项字段，返回空的知识库引用内容。原因：未针对结构化文档配置对应的分块规则，或未启用模型的结构化内容识别能力，导致文档解析不完整。
- 现象：工作流运行时出现未触发的模型调用报错日志。原因：工作流中残留了已删除的模型调用节点配置，或系统缓存了旧的模型调用规则，导致误报调用错误。

## 怎么确认配好了
- 发起单条办事事项的咨询测试，核对模型返回的答复内容与知识库中的结构化字段是否一致。
- 上传最新的临时办事规则文档，发起对应咨询，核对模型返回的内容是否包含最新的规则信息。
- 查看模型调用日志，确认实际调用的模型与配置的模型服务地址、令牌一致。
- 触发工作流中的模型调用节点，核对日志中无未预期的模型调用报错。
