# 城投平台的办事咨询与答复：表单与交互

## 这个品类的数据长什么样
城投平台的办事咨询数据主要来源于属地政务服务网诉求端口、城投自有工单系统及项目审批档案。数据更新以工单办结实时同步、每日批量归档两种节奏为主。单条数据文档包含诉求编号、事项类别、提交时间、诉求内容、办理状态、回复意见、办理时限等字段，字段单位多为“件”“天”“元”，部分项目类数据附带图纸、资质文件等二进制附件。

## 这些特征在「表单与交互」这一环带来什么约束
数据源分散导致表单需支持跨系统数据调用，避免用户重复录入已有信息。事项类别覆盖市政、基建、民生等多类，需通过多级分类简化用户输入。办理时限字段要求表单实时展示倒计时提示，避免超期办理。附件上传需适配图纸、资质文件等大体积文件，同时保障传输稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `userSelect` | 三级分类：市政事项→基建项目→民生服务 | 城投办事事项覆盖多领域，三级分类可降低用户输入误差 |
| `formInput` | 800–1200字符输入上限 | 城投诉求通常包含项目细节，该区间可覆盖完整信息且避免冗余 |
| 超时设置 | 600秒 | 处理跨政务系统的办事数据查询需预留足够响应时间 |
| 结果展示条数 | 前10条 | 过多咨询结果会干扰用户选择，限定条数可提升交互效率 |
| 附件上传限制 | 总大小1000 MB以内，单文件不超过50 MB | 城投办事常需上传项目图纸、资质文件，该设置适配常见文件规模 |
| 表单必填项 | 诉求内容、联系方式、办理地点 | 符合城投办事咨询的核心信息收集要求 |

## 容易做错的三处
- 配置搜索引用上限为2000后，短咨询回答仍超出token阈值。原因是未同步配置上下文token截断规则，引用的知识库内容未按实际可用token裁剪。
- 表单提交后无法正常返回txt格式的处理结果。原因是未正确配置`formInput`的文件传输格式，后端未识别到txt文件流。
- 多级`userSelect`分类切换时出现页面卡顿。原因是未设置分类缓存，每次切换都重新请求全量城投事项数据。

## 怎么确认配好了
- 提交一条测试咨询，检查表单是否自动匹配对应事项的三级分类选项。
- 上传符合大小限制的txt格式附件，确认提交后系统可正常接收并触发后续处理。
- 触发跨系统数据查询，确认响应时间未超过设定的600秒阈值。
- 查看知识库引用日志，确认每条引用内容的token占比符合预期配置。
