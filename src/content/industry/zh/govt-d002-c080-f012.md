# 城投平台的办事咨询与答复：部署与升级

## 这个品类的数据长什么样
城投平台办事咨询与答复的数据来源包括政务服务热线来电、线下办事窗口登记、线上办事大厅留言、12345政务服务热线转办工单。数据更新节奏为实时同步或每小时增量拉取。单条咨询文档包含咨询唯一标识、发起时间、咨询主体类型、事项分类、原始诉求、答复内容、办理节点、用户反馈字段，字段分别采用字符串、ISO8601格式时间、枚举值、分类标签、文本、富文本、状态枚举、星级数值作为单位。

## 这些特征在「部署与升级」这一环带来什么约束
上述数据特征对部署与升级环节带来明确约束。多源数据接入要求配置支持多协议的同步适配器，适配不同渠道的咨询数据拉取。实时增量更新要求部署FastGPT v4.17.0时开启增量索引模式，避免全量重建占用过多资源。字段标准化要求知识库元数据映射严格匹配城投咨询数据的字段名，避免数据解析错误。敏感数据存储要求配置加密存储参数，符合政务数据安全规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://user:pass@host1:27017,host2:27017/chengtao_consult?replicaSet=rs0` | 城投咨询数据需要高可用的副本集存储，支持并发查询与增量同步 |
| `DB_MAX_LINK` | `200` | 覆盖日常峰值并发的咨询数据索引与查询请求，避免连接池耗尽 |
| `REDIS_URL` | `redis://:redis_pass@internal-redis:6379/1` | 缓存渠道状态与咨询会话数据，持久化配置避免重启丢失关键缓存 |
| `STORAGE_S3_ENDPOINT` | `http://s3-internal.chengtou.gov.cn:9000` | 存储咨询附件与文档，使用内部对象存储符合政务数据安全要求 |
| `FE_DOMAIN` | `https://service.chengtou.gov.cn` | 配置前端跨域白名单，确保城投线上服务页面可正常访问知识库内容 |

## 容易做错的三处
- 部署后创建城投咨询知识库时，建索引步骤持续超时无进度，日志显示数据库连接数超限。原因是`DB_MAX_LINK`配置值低于实际并发索引请求数，导致连接池耗尽。
- 在FastGPT中添加One API对接的国内大模型渠道，测试环节显示通过但管理页显示渠道不可用。原因是`REDIS_URL`配置错误，渠道状态缓存无法正常写入，导致状态同步失效。
- 配置城投内部系统的数据源后，无法同步存量咨询数据。原因是`MONGODB_URI`未配置城投数据库的访问白名单，数据库拒绝外部连接请求。

## 怎么确认配好了
- 登录FastGPT v4.17.0的管理后台，进入数据源配置页，测试`MONGODB_URI`对应的数据库连接，确认返回连接成功提示。
- 进入渠道管理页，测试One API渠道，确认状态变为可用，且无缓存相关报错日志。
- 上传一条标准的城投咨询工单文档，触发手动建索引，确认索引进度在10分钟内完成并生成有效向量。
- 访问配置的`FE_DOMAIN`，进入咨询知识库页面，确认可以正常检索并展示已上传的咨询数据。
