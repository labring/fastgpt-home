# 基础化工的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
基础化工办事咨询与答复相关的数据主要来自企业内部工艺手册、质检报告、原料采购标准、政府合规文件，以及飞书等协作工具中的台账excel、多维会议纪要。数据更新节奏存在差异：工艺手册、合规文件按季度或年度更新，批次级质检报告、采购台账每日生成新内容。文档结构包含长文本工艺规程、结构化excel台账（含原料编号、纯度、检测值等字段）、带问答记录的多维文档，字段与单位包含MPa、wt%、ppm等化工专业单位，以及批次号、生产日期等标识字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
基础化工数据的多类型、多更新节奏与专业字段特征，对向量索引环节带来多重约束。长文本工艺规程与短文本质检台账的长度差异，要求分块策略适配不同文本长度，避免破坏语义连贯性或浪费向量模型输入额度。不同更新频率的数据需要区分全量与增量索引配置，避免每日批量更新时重复处理低频率变更的合规文件。专业单位与字段的差异，要求索引环节支持结构化字段的语义映射，防止因单位混淆导致检索结果偏差。办事咨询场景的精准性需求，要求控制召回结果的数量与相关性阈值，避免无关内容干扰答复。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配基础化工长文本工艺规程与短文本台账的混合内容，匹配主流嵌入模型的输入长度限制 |
| 重叠长度 | 100–150 字符 | 避免分块切断工艺步骤、原料配比等连续语义单元，提升检索上下文连贯性 |
| `maxToken` | 8192 | 适配主流嵌入模型的最大token上限，满足长文本工艺手册的向量生成需求 |
| 相似度阈值 | 0.72–0.85 | 过滤基础化工场景下低相关的合规或工艺内容，保障办事咨询答复的精准性 |
| 单次搜索上限 | 前 5 条 | 匹配办事咨询场景的快速答复需求，避免过多冗余结果干扰用户判断 |
| `defaultToken` | 4096 | 适配结构化excel台账的短文本字段向量生成，平衡计算资源与语义覆盖度 |

## 容易做错的三处
- 现象：导入飞书文件夹下的excel文件或多维文档后，索引任务显示「解析失败」，日志返回「字段格式不支持」。原因：未开启结构化字段自动映射配置，基础化工台账的多单位字段（如MPa、ppm）未被正确识别，导致向量模型无法生成有效语义向量。
- 现象：docker部署PG数据库的环境下，索引建立超时，宿主机8c16G无GPU，日志显示内存占用峰值超出虚拟机配置。原因：未限制分块长度与单次处理的文档数量，批量导入基础化工的批次质检报告时，内存占用过高触发超时。
- 现象：接入OneAPI的嵌入模型调用报错，无法正常生成向量。原因：未单独配置索引专用的嵌入模型，复用全局模型配置时触发OneAPI的速率限制或权限校验失败。

## 怎么确认配好了
- 上传一份基础化工的工艺规程excel与多维会议纪要，查看索引任务的运行日志，确认结构化字段被正确解析，无格式报错。
- 发起一条办事咨询类问题，例如「某原料的质检标准是什么」，查看检索结果的召回条数符合单次搜索上限的配置。
- 单独测试索引专用嵌入模型的调用，查看返回的向量维度与模型参数匹配，无连接或权限报错。
- 上传一份更新后的质检报告，查看增量索引任务正常执行，无全量重建的提示信息。
