# 基础电信运营的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
基础电信运营的办事咨询与答复数据，主要来源于线下营业厅工单、全国统一客服热线的对话记录、官方发布的业务办理指南、资费公示文档以及故障报修归档记录。数据更新节奏分为实时与批量两类：客服对话与工单随用户咨询实时生成，业务指南与资费文档则在政策调整或业务更新时批量变更。单份文档的结构包含业务名称、办理条件、资费标准、用户提问、客服回复等字段，部分字段带有固定格式的编号与单位，如办理时长以分钟为单位，资费以元/月为单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
基础电信运营的办事咨询数据存在多字段、长文本、更新节奏差异大的特征，对向量模型与索引环节带来多重约束。首先，多字段结构要求仅选择有语义价值的字段进行向量嵌入，避免无效字段消耗计算资源。其次，长文本的业务文档与多轮客服对话，要求合理设置`maxToken`限制单块文本长度，避免token溢出。最后，实时与批量混合的更新节奏，要求索引支持增量更新与全量重建的灵活切换，适配不同数据的更新需求。同时，字段附带的固定单位与编号，需在预处理阶段完成过滤，确保嵌入向量的语义准确性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配基础电信业务文档、客服对话的单段有效信息长度，避免单块文本超出`maxToken`限制 |
| 重叠长度 | 100–200 字符 | 保留跨分块的上下文关联，避免多轮客服对话的关键信息断裂 |
| 嵌入字段选择 | 用户问题、客服回复、业务办理内容 | 过滤无语义价值的工单编号、流水号等字段，减少冗余向量计算 |
| 最大上下文 | 4000 token | 适配基础电信办事咨询的常见对话轮次与文档长度，符合`defaultToken`的默认配置逻辑 |
| 单次召回上限 | 前10条 | 适配客服知识库的常见召回量级，避免过多结果干扰咨询答复的准确性 |
| 超时设置 | 300 秒 | 适配批量索引的处理时长，避免单次索引任务因耗时过长被中断 |

## 容易做错的三处
- 调用索引接口时返回400状态码且无响应体，原因是未正确配置嵌入字段与基础电信业务数据的字段映射，导致无效字段被传入向量模型。
- 本地部署时服务器内存、磁盘读写占用持续走高，每日触发资源耗尽，原因是未限制分块长度与批量索引的并发数，导致大量长文本同时被拆分、嵌入。
- 知识库文件上传后，部分批次卡在索引构建的1组或2组阶段，原因是未过滤包含特殊字符的业务文档文件名，导致索引分片读取失败。

## 怎么确认配好了
- 上传单份基础电信业务办理指南文档，核对分块后的文本片段长度落在预设的800–1200字符区间内。
- 发起一次模拟办事咨询的检索请求，确认返回的召回结果仅包含预设的用户问题、客服回复等有效字段。
- 执行100条批量索引测试任务，检查任务在预设的300秒超时内完成，无异常中断。
- 查看FastGPT的索引日志，确认无字段映射错误或无效参数的报错提示。
