# 基础电信运营的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
基础电信运营的办事咨询数据来源包括线上营业厅用户咨询记录、线下营业厅工单、客服对话转写文本、计费与套餐规则文档。更新节奏为每日同步，因运营商会定期更新套餐活动、计费规则与服务条款。单条数据包含咨询问题原文、用户终端类型、归属地信息、套餐档位、答复话术、办结时间戳、问题分类标签，字段均为标准文本或时间戳格式，无特殊计量单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
基础电信咨询数据包含用户个性化信息与实时规则，因此多轮对话需保留`variables`中的用户套餐、归属地等上下文，避免重复询问用户已知信息。数据更新频率较高，提示词模板需每日同步最新规则，否则答复内容会出现过时信息。部分咨询涉及长文本的计费规则说明，多轮对话的上下文长度需适配长文本输入，避免截断关键内容。此外，电信咨询常包含跨步骤的业务办理流程，需通过`messages`数组保留完整对话脉络，确保模型理解当前会话的业务场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 基础电信咨询常包含套餐规则、计费明细等长文本，避免上下文截断关键信息 |
| 上下文保留轮次 | 前7轮对话 | 电信咨询多为单场景多步骤流程，保留近7轮可覆盖完整业务沟通脉络 |
| 变量注入开关 | 开启 | 需注入`variables`中的用户套餐、归属地信息，实现个性化匹配答复 |
| 提示词模板更新频率 | 每日同步 | 匹配运营商活动、规则的每日更新节奏，确保答复内容时效性 |
| 对话超时阈值 | 60 秒 | 电信咨询答复需调用多系统数据，避免过长等待影响用户体验 |

## 容易做错的三处
- 现象：升级FastGPT v4.17.0后，模型对话返回结果末尾出现规则追溯符号。原因：系统默认开启了提示词追溯展示配置，未在模板中关闭该开关。
- 现象：高并发调用对话接口时，部分会话返回结果为空。原因：未正确配置`chatId`的会话隔离参数，并发请求覆盖了共享上下文数据。
- 现象：多轮对话中调用MCP工作流，当轮次超过阈值时返回none。原因：未限制`messages`数组的最大长度，上下文溢出导致工作流无法正常解析输入。

## 怎么确认配好了
- 发起模拟用户咨询，连续发送3条关联问题，核对`messages`数组中保留了完整的对话上下文。
- 注入测试用的`variables`参数，比如套餐类型、归属地，核对答复内容匹配注入的变量信息。
- 配置高并发测试脚本，发起1秒2-3次的调用请求，核对会话无上下文覆盖或结果为空的情况。
- 查看提示词模板，确认未开启追溯展示开关，核对返回结果无额外符号。
