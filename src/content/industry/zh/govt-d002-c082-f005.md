# 基础电信运营的办事咨询与答复：工具调用与插件

## 这个品类的数据长什么样
基础电信运营的办事咨询数据主要来自运营商内部业务支撑系统、官方客服工单库及线下营业厅办事指南文档。数据按办卡、销户、套餐变更等业务场景分类存储，包含业务办理编码、申请条件、必备材料、办理时限等结构化字段，单位涵盖工作日、GB、元等。全量数据每日凌晨同步更新，增量变更数据每小时推送，单条文档长度从数百字符到数千字符不等，部分高频业务文档会附带常见问题问答片段。

## 这些特征在「工具调用与插件」这一环带来什么约束
业务分类存储的特征要求工具调用需按业务类型绑定对应数据源，避免跨业务调用混淆数据。每日全量+每小时增量的更新节奏，要求插件缓存更新周期匹配增量推送频率，否则会返回过时的办理规则。结构化字段附带特定单位的特征，要求工具调用时需统一解析单位字段，避免将工作日办理时限误转为自然日。文档长度跨度大的特征，要求工具调用时需配置合理的上下文截取阈值，防止关键办理条件被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动匹配对应业务的工具，适配多场景办事咨询需求 |
| `functionCall` | 按业务类型指定 | 针对办卡、销户等高频业务，固定调用对应工具 |
| 插件缓存更新周期 | 1小时 | 匹配基础电信运营增量数据每小时的推送节奏 |
| 上下文截取阈值 | 800–1200字符 | 适配业务文档从数百到数千字符的长度跨度 |
| 错误重试次数 | 3次 | 应对接口调用偶发的网络波动异常 |
| 错误重试间隔 | 10秒 | 避免短时间内重复调用加剧接口压力 |

## 容易做错的三处
- 现象：调用`/api/v1/chat/completions`接口时，预设的业务提示词未生效，返回结果未匹配基础电信业务规则。原因：未通过`functionCall`参数绑定专属业务提示词配置，工具调用未加载对应业务文档的规则。
- 现象：自定义前端对接时出现401鉴权报错，或iframe嵌入页面无法修改样式。原因：未使用官网验证的token调用方式，直接在前端暴露密钥或未正确携带鉴权头信息。
- 现象：工具调用返回的办理时限字段单位混乱，出现自然日与工作日混用的情况。原因：未配置字段解析规则，未对结构化数据中的单位字段进行统一转换处理。

## 怎么确认配好了
本验证流程基于FastGPT v4.17.0版本。
- 发起单业务场景的测试调用，查看工具是否自动匹配对应业务的数据源，可通过`toolChoice`参数的日志确认调用模式。
- 触发一次增量数据更新，检查插件缓存是否在1小时内完成同步，可通过缓存过期日志验证更新周期。
- 调用接口后查看返回结果的单位字段，确认是否与业务规则一致，可通过字段解析配置验证单位转换逻辑。
- 携带正确的鉴权token发起调用，确认接口返回正常会话结果，无401类鉴权报错。
