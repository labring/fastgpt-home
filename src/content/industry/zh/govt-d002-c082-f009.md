# 基础电信运营的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
基础电信运营的办事咨询数据主要来源于线下营业厅工单、全国统一服务热线的录音转写内容、线上营业厅的在线咨询记录以及业务办理流程文档。数据更新节奏为小时级至实时，部分紧急故障咨询可实现秒级同步。单条咨询文档包含咨询类型标签、用户诉求原文、历史交互记录、办理进度字段与响应话术模板，字段单位多采用字符统计咨询内容长度、秒统计通话时长、条统计当日咨询量。

## 这些特征在「模型接入与配置」这一环带来什么约束
多渠道来源的咨询数据格式差异较大，需配置统一的输入适配规则，避免模型解析异常。实时更新的业务文档要求数据源同步配置支持小时级拉取，确保咨询答复的时效性。固定的业务字段与标准化话术模板，要求模型输出需严格匹配预设字段，无法生成无对应字段的内容。此外，高并发的咨询量要求模型调用配置需适配稳定的并发处理能力，避免请求超时影响用户体验。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 基础电信咨询常包含历史工单、账单明细等长上下文内容，需保留完整业务背景 |
| `maxTokens` | 1500–2000 token | 办事咨询答复需覆盖业务规则、办理步骤与注意事项，输出长度适配标准化话术规范 |
| `quoteMaxToken` | 600–800 token | 需引用的套餐规则、故障排查流程等业务文档，单段引用长度不宜超出模型处理上限 |
| `toolChoice` | auto | 需根据咨询类型自动选择是否调用知识库或工具，适配套餐咨询、故障报修等多场景 |
| `temperature` | 0.3–0.5 | 业务答复需严谨准确，避免生成不符合电信业务规则的非标准化内容 |
| `AIPROXY_API_TOKEN` | 绑定专属权限的密钥 | 保障基础电信业务数据调用的安全性，限制未授权的模型访问 |

## 容易做错的三处
- 现象：模型调用失败，返回401权限错误或请求超时。原因：未正确配置`AIPROXY_API_TOKEN`，或密钥未绑定基础电信场景的业务访问范围，导致无法正常调用模型。
- 现象：知识库检索开启重排模型后，应用内无检索结果但知识库测试正常。原因：重排模型的`maxContext`配置与应用全局上下文阈值不匹配，导致检索结果超出上下文承载上限，无法正常返回。
- 现象：模型分析输出业务规则正确，但无法完成预设字段的赋值。原因：未开启`toolChoice`的强制字段映射模式，或业务文档中的字段命名与模型输出字段规则不匹配，导致字段无法正确绑定。

## 怎么确认配好了
- 输入典型的套餐咨询话术，调用测试接口，检查返回内容是否包含历史工单与套餐规则的引用片段。
- 将`temperature`设置为0.3，多次调用同一咨询问题，确认返回结果的业务表述保持一致。
- 开启重排模型后，在应用内发起多轮咨询，检查检索结果条数与知识库测试页面的结果一致。
- 查看FastGPT v4.17.0的模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的请求参数正确无误。
