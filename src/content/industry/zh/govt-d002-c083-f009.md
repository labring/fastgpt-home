# 基础设施建设的办事咨询与答复：模型接入与配置

## 这些特征在「模型接入与配置」这一环带来什么约束
长文本的施工档案与政务指南会占用大量上下文空间，因此需要严格限制模型的`maxContext`与`maxTokens`参数，避免调用时出现上下文溢出或截断核心内容的问题。数据包含工程类专属单位与结构化字段，要求模型具备领域术语识别能力，因此需选择适配工程领域的嵌入模型与大语言模型。高频更新的现场合规记录要求模型调用的响应时限匹配办事咨询的实时性需求，不宜设置过长的超时阈值。此外，办事咨询场景需保障答复的准确性，因此模型的生成随机性需控制在较低范围，避免生成错误的施工标准或审批流程内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配基础设施建设领域长文档的上下文承载需求，避免截断核心施工标准与审批流程内容 |
| `maxTokens` | 2000–3000 token | 限制单次答复的输出长度，确保办事咨询的答复简洁清晰，符合政务答复的规范 |
| `temperature` | 0.1–0.3 | 降低生成随机性，保障施工规范、审批流程等专业内容的答复准确性 |
| `quoteMaxToken` | 1500 字符 | 限定引用源文本的长度，确保引用的施工日志或审批指南内容完整且不占用过多上下文 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 适配本地或第三方模型的接入需求，支持对接工程领域专用模型 |
| `AIPROXY_API_TOKEN` | 按平台生成的专属密钥填写 | 保障模型调用的身份验证安全，避免未授权访问 |

## 容易做错的三处
- 创建知识库时，已添加的本地Qwen2.5与BGE-M3模型未出现在文本理解模型下拉列表中。原因是嵌入模型的接入配置未关联到知识库的向量库设置，或模型渠道的API端点配置存在路径错误。
- 连接本地DeepSeek模型后，对话界面自动切换为GPT模型导致无法正常对话。原因是默认模型优先级未设置为本地模型，或代理服务的路由规则错误将请求转发至外部公共模型渠道。
- 调用模型时返回401未授权错误。原因是`AIPROXY_API_TOKEN`参数填写错误，或模型渠道的密钥权限未开放至基础设施建设场景的访问范围。

## 怎么确认配好了
- 进入模型渠道管理页面，检查已添加的工程领域模型状态为「已连接」，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`参数填写无误。
- 创建测试知识库，上传一份施工日志文档，查看文本理解模型下拉列表是否包含已配置的嵌入模型，确认向量库索引可正常生成。
- 发起一条测试咨询，例如「某标段的隐蔽工程验收流程是什么」，查看答复是否引用了正确的源文档内容，且未出现模型自动切换的情况。
- 调整`temperature`参数至测试区间，验证答复内容的随机性是否符合预期，确保专业术语未出现错误。
