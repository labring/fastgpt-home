# 大宗商品贸易的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
大宗商品贸易的办事咨询数据主要来源于现货报价单、期货合约、贸易合同、仓储物流单据、海关报关单及行业研报。数据更新节奏差异明显：现货报价与实时行情按分钟或小时更新，贸易合同在交易达成时生成并归档，报关单在通关流程完成后同步入库，行业研报按周或月度发布。文档结构包含结构化表格（如报价单含品名、规格、产地、价格、计量单位）、半结构化合同文本（含条款、金额、交割条款）与纯文本研报，核心字段包含品名、规格型号、产地、计量单位（吨、桶、立方米等）、交易价格与交割地点。

## 这些特征在「向量模型与索引」这一环带来什么约束
大宗商品贸易的数据特征对向量模型与索引环节带来多重约束。结构化字段多且单位多样，要求向量模型需具备对专业术语与计量单位的语义识别能力，需选用支持大宗商品专业术语的嵌入模型，避免匹配时混淆不同规格的商品。数据更新频率差异大，需支持增量索引与分批次同步，避免全量索引占用过多资源。长文本贸易合同与研报需合理分块，不能破坏条款完整性，否则会导致关键交易信息无法被召回。大规模的报价单与合同数据，还要求索引结构具备高效的分片与召回能力，保障检索速度。本配置基于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配大宗商品贸易合同、研报的段落长度，避免拆分核心交易条款 |
| 重叠长度 | 50–100 字符 | 保留跨块的上下文关联，例如合同中跨段落的付款与交割条款 |
| 相似度阈值 | 0.75–0.85 | 区分同品名不同规格、不同产地的大宗商品，降低误召回概率 |
| 单次搜索上限 | 前 10 条 | 覆盖多供应商报价、多交割地点的相关咨询需求 |
| maxToken | 8000 token | 适配长文本的上下文召回，满足完整引用贸易合同条款的需求 |
| defaultToken | 4096 token | 控制单轮回答的输出长度，避免冗余引用历史数据 |

## 容易做错的三处
- 召回结果中出现非目标品类的商品信息，或匹配字段为空。原因：未针对大宗商品的品名、规格、计量单位配置专属的语义匹配规则，导致向量模型无法准确识别专业术语。
- 知识库检索时返回空结果，或无法召回关键交易信息。原因：分块长度设置过长，导致核心条款被拆分遗漏，或相似度阈值设置过高，过滤掉了有效匹配结果。
- 检索结果未显示具体文档来源，无法实现办事咨询的溯源答复。原因：未开启文档溯源配置，或未正确绑定文档的元数据字段（如合同编号、报价单ID），导致无法关联原始文档。

## 怎么确认配好了
- 上传一份大宗商品贸易合同与现货报价单，检查分块后的文本是否保留了完整的条款与报价字段，未出现关键内容被截断的情况。
- 触发针对具体品名与规格的咨询，核对召回结果的相似度是否落在预设的阈值区间内，避免出现无关匹配。
- 查看检索结果的展示区域，确认每条匹配结果都显示了对应的文档名称与元数据信息，实现溯源展示。
- 测试长文本咨询场景，检查回答的上下文长度符合maxToken的设置，未出现内容截断或冗余输出。
