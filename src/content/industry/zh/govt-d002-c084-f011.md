## 这些特征在「表单与交互」这一环带来什么约束
大宗商品贸易的数据字段多且存在单位差异，要求表单需支持多字段绑定与单位校验。不同更新节奏的数据需匹配不同的加载时机，实时报价类数据需动态刷新，静态台账数据可按需批量加载。交易方与商品品类的联动选择需求较高，需避免用户输入错误的组合。同时，业务流程涉及多方确认与单据审核，表单提交的等待时长需适配较长的业务周期，不能过短导致流程中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 绑定合同编号、商品品类、交易数量、计价单位4个核心字段，开启实时校验 | 覆盖大宗商品交易的核心识别信息，实时校验避免错误输入 |
| `userSelect` | 预设8个高频大宗商品品类选项，联动绑定对应专属知识库 | 减少用户输入成本，匹配不同品类的业务文档与知识库关联逻辑 |
| 表单提交超时时间 | 600 秒 | 大宗商品交易流程涉及多方确认与单据审核，耗时较长，避免中途超时 |
| 动态加载触发时机 | 选择商品品类后 300 毫秒内加载对应知识库 | 匹配用户选择节奏，减少等待时长，提升交互流畅度 |
| 字段校验规则 | 按预设单位校验，数量字段允许±0.5%误差区间 | 适配大宗商品计量的合理浮动范围，避免误拦截有效业务 |
| 全局变量赋值 | 将`userSelect`选择的品类绑定到知识库选择变量 | 实现知识库的动态匹配，避免加载无关业务文档 |

## 容易做错的三处
- 配置`userSelect`后，选择商品品类时返回无关业务文档。原因：未将`userSelect`的选项与对应品类的知识库绑定，导致匹配逻辑混乱。
- 表单未开启引用开关，但提交后仍返回引用内容。原因：全局变量中的知识库选择未正确关联表单输入的商品品类，默认加载了全量知识库内容。
- 固定的数据分析操作无法绑定到对应工单。原因：未将`formInput`输出的合同编号作为工作流触发参数，导致操作无法关联具体业务单据。

## 怎么确认配好了
- 进入表单编辑界面，检查`formInput`是否绑定了合同编号、商品品类等核心交易字段。
- 选择`userSelect`中的任意大宗商品品类选项，确认对应品类的知识库自动加载。
- 模拟提交不符合计价单位的输入，检查校验规则是否拦截该错误。
- 触发绑定的工作流，确认表单输出的合同编号正确传递到数据分析环节。
