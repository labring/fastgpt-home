# 工程咨询监理的办事咨询与答复：工作流编排

## 这个品类的数据长什么样
工程咨询监理的数据主要来源于项目执行过程中的报审表、旁站记录、验收报告、变更签证、整改通知单等文件。数据更新节奏随项目进度波动，每次监理活动、审批流转完成后即更新。文档结构包含固定结构化字段与非结构化描述，结构化字段包括项目编号、监理标段、报审内容、整改要求、回复时限、签字栏等，非结构化内容包含现场问题描述、整改方案等。字段单位多为项目编号（字符串）、整改时限（天）、报审金额（万元）等。

## 这些特征在「工作流编排」这一环带来什么约束
监理数据的固定审批流转链路，要求工作流匹配报审、整改、复核的核心节点顺序，避免流程混乱。数据随项目进度非固定更新，要求工作流的数据源拉取适配动态更新的项目文档，无需依赖固定周期的同步。文档包含结构化字段与非结构化内容，要求工作流同时支持结构化字段提取与自然语言问答处理。此外，监理文档涉及项目权限与审批责任，要求工作流关联权限校验节点，确保数据访问符合监理规范。

## 配置怎么定
以下配置适配 FastGPT v4.17.0 版本：
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配监理文档中单段报审、整改内容的长度，避免截断关键审批字段 |
| 重叠长度 | 100–150 字符 | 保留跨分块的整改要求描述，防止上下文断裂 |
| 单次搜索上限 | 前 8 条 | 匹配监理项目单次审批关联的文档数量，覆盖主要关联材料 |
| 最大上下文 | 6000  token | 适配多节点工作流的上下文传递需求，避免超出模型窗口限制 |
| variables | 按项目ID绑定 | 实现多监理项目的数据隔离，确保每个项目的工作流仅访问对应数据 |
| nodeId | 按审批节点配置 | 匹配报审、整改、复核三个核心监理节点，触发对应处理逻辑 |

## 容易做错的三处
- 工作流中配置文件上传节点后，调用文档解析工具返回报错。原因是未正确配置`CUSTOM_READ_FILE_URL`环境变量，导致工具无法获取上传文件的本地路径。
- 工作流的问题分类节点无法选中自定义模型。原因是未在系统配置中开启对应模型的工作流可用权限，仅在简易问答场景中配置了模型可见性。
- 工作流提取的监理文档字段为空。原因是未配置结构化字段提取规则，仅使用通用文档解析，未匹配监理文档的专属字段格式。

## 怎么确认配好了
- 上传一份监理报审表文档，触发工作流，检查是否能正确提取项目编号、整改要求等结构化字段。
- 查看工作流运行日志，确认`variables`中绑定的项目ID与当前监理项目一致。
- 测试不同审批节点的触发逻辑，验证工作流是否按配置的`nodeId`执行对应处理步骤。
- 上传包含扫描件的监理文档，检查解析后的文本是否包含签字栏等关键信息。
