# 工程咨询监理的办事咨询与答复：工具调用与插件

## 这个品类的数据长什么样
工程咨询监理的数据主要来源于项目监理日志、旁站巡检记录、分项工程验收报告、造价核算文件及整改闭环台账。数据更新节奏随项目推进节点调整，单次更新覆盖单项目当周期内的全部变更与验收内容。文档结构固定包含项目唯一标识、监理单位全称、时间戳、整改项清单、验收结论、造价核算值等字段，字段单位包含平方米、万元、工作日等工程类标准单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
工程咨询监理的数据结构固定且包含工程类专属单位，工具调用需精准匹配项目专属字段，避免泛化检索导致的结果偏差。数据随项目节点动态更新，插件需支持按需拉取最新周期内的项目数据，适配非固定频率的更新节奏。嵌套式的整改项与验收结论结构，要求工具调用具备多层级数据解析能力，确保返回结果覆盖完整的项目闭环信息。项目唯一标识作为核心检索字段，工具调用需绑定该标识作为调用参数，避免跨项目数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | 指定具体工具 | 工程咨询监理的工具调用需精准匹配项目数据检索或整改项校验场景，避免模型自主选择工具导致的参数错误 |
| `functionCall` | 开启强制模式 | 工程咨询监理的数据字段固定且格式要求严格，强制模式可确保模型输出符合工具调用格式的响应 |
| 最大上下文 | 8000–12000 token | 工程咨询监理的文档包含多份嵌套报告，足够的上下文可完整传递项目全量信息 |
| 单次工具调用条数 | 前 8–12 条 | 单项目监理数据包含多份巡检与验收记录，合理条数可平衡检索效率与信息完整性 |
| 工具调用超时时间 | 300–600 秒 | 工程数据拉取需跨多个台账系统，较长超时时间可确保完整获取数据 |
| 插件触发时机 | 按项目节点触发 | 监理数据随项目节点更新，节点触发可确保调用的是当前周期内的最新数据 |

## 容易做错的三处
- 现象：Docker部署FastGPT v4.17.0后，插件管理页面显示拉取失败，服务启动异常。原因：未正确配置插件仓库的访问权限，或本地存储目录权限不足导致插件文件无法写入。
- 现象：外部调用工作流API时返回503状态码或请求超时。原因：未设置合理的并发阈值，超过服务健康并发量导致服务过载。
- 现象：AI输出内容未经过滤直接返回，字段中存在不符合行业规范的表述。原因：未开启流式输出控制插件，或插件配置未绑定到对应工具调用环节。

## 怎么确认配好了
- 查看工具调用日志，确认每次调用均指定了预设的具体工具，无自主选择的情况。
- 触发插件拉取动作，确认插件管理页面显示正常加载，无报错提示。
- 提交测试项目数据，确认工具调用返回的内容包含完整的项目字段与对应单位，格式符合要求。
- 模拟外部调用，确认服务可正常响应请求，无超时或状态码异常。
