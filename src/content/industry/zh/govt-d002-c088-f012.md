# 工程咨询监理的办事咨询与答复：部署与升级

本文档基于FastGPT v4.17.0版本编写，适用于国央企建筑施工类工程咨询监理场景的办事咨询与答复功能部署与升级。

## 这个品类的数据长什么样
工程咨询监理的数据主要来源于项目全周期的监理文档，包括监理规划、旁站记录、验收报告、变更签证、整改通知单等。数据更新节奏随项目节点推进，项目实施阶段按周、月生成阶段性文档，竣工后归档永久留存。单份文档长度差异显著，短则数页的整改要求，长则数十页的监理规划，字段包含项目编号、工程部位、责任单位、整改期限、闭环状态等，单位涉及平方米、工期天数、整改时限天数等。

## 这些特征在「部署与升级」这一环带来什么约束
工程咨询监理的数据来源分散于项目文件夹与内部业务系统，部署时需支持多源数据的统一接入，因此需配置`STORAGE_S3_ENDPOINT`对接内部对象存储以统一存储附件。文档长度差异大，分块处理时需适配不同长度的文档，避免分块不合理导致的上下文丢失。数据更新按项目节点进行，升级时需支持增量同步配置，减少全量同步的资源消耗。同时，国央企场景下数据安全要求严格，需通过`FILE_TOKEN_KEY`与`ROOT_KEY`配置鉴权逻辑，防止未授权访问核心监理数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `1000–1500 条` | 适配工程咨询监理单项目关联文档较多的场景，避免数据库连接数耗尽 |
| `MONGODB_URI` | 内部私有部署的MongoDB连接串 | 存储监理项目的结构化业务数据，保障数据不出内网 |
| `REDIS_URL` | 带持久化的内网Redis地址，连接超时`600 秒` | 缓存高频咨询的问题与答复，降低数据库的重复查询压力 |
| `STORAGE_S3_ENDPOINT` | 国央企内部对象存储的接入地址 | 存储监理各类文档附件，符合内部数据安全管理要求 |
| `FILE_TOKEN_KEY` | `32位随机字符串` | 生成文档访问的鉴权令牌，防止未授权用户下载敏感监理文档 |
| `ROOT_KEY` | 仅内部运维人员知晓的密钥 | 管理平台的最高权限密钥，避免越权修改核心配置 |

## 容易做错的三处
- 现象：生成的文档分享链接未触发身份校验，任意访问者可下载监理文档。原因：未正确配置`FILE_TOKEN_KEY`参数，导致鉴权逻辑未生效。
- 现象：调用嵌入模型时出现连接超时报错。原因：未将GPUStack私有化部署的bge-m3接口地址正确填入模型对接配置，导致无法访问私有模型服务。
- 现象：本地部署时无法拉取marker镜像启动服务。原因：未配置内网镜像源或国内镜像加速地址，导致无法下载marker依赖的基础镜像。

## 怎么确认配好了
- 访问生成的监理文档分享链接，输入正确的鉴权令牌后可正常下载，输入错误令牌则返回403错误，确认`FILE_TOKEN_KEY`配置生效。
- 调用嵌入模型接口，返回的向量结果与本地测试的bge-m3模型结果一致，确认GPUStack部署的模型对接配置正确。
- 查看MongoDB连接日志，显示当前连接数在`1000–1500 条`范围内，确认`DB_MAX_LINK`配置符合要求。
- 尝试上传一份超过1000 MB的监理项目文档，可正常存储至内部对象存储，确认`STORAGE_S3_ENDPOINT`配置生效。
