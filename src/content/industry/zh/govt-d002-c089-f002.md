# 工程机械的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
工程机械的办事咨询与答复数据主要来自设备运维手册、故障排查案例库、备件参数清单、官方办事流程文档。数据更新节奏分为三类：新机型发布时同步更新全量手册，季度更新备件参数与合规流程，日常新增单台设备的故障反馈案例。单篇文档包含设备型号、故障现象、排查步骤、解决方法、备件编号、响应时效等固定字段，单位涉及压力值（MPa）、运行时长（小时）、尺寸（毫米）等专业工程单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
专业工程参数与操作步骤的绑定关系要求分块时保留相邻的参数说明与逻辑，避免拆分后语义断裂；多来源的文档类型需要按手册、案例、流程做索引分区，避免跨品类检索干扰；高频更新的故障案例需要支持增量索引触发，避免全量重建带来的资源消耗；字段中的设备型号、故障等级等信息需要作为检索过滤条件，确保召回结果匹配目标咨询场景。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配工程机械办事咨询与答复的向量模型与索引需求：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 工程机械文档包含连续的参数说明与排查步骤，避免拆分破坏语义完整性 |
| 重叠长度 | 100–150 字符 | 覆盖跨分块的故障现象与后续步骤的关联逻辑，提升检索连贯性 |
| `maxToken` | 4096 | 适配专业文档的长文本嵌入需求，避免截断关键参数与步骤 |
| 相似度阈值 | 0.75–0.85 | 匹配专业术语的语义相似度，过滤低相关性的检索结果 |
| 单次搜索上限 | 前10条 | 平衡检索效率与故障案例的覆盖范围 |
| `defaultToken` | 512 | 补充基础上下文的默认token配额，适配短咨询问题的嵌入 |

## 容易做错的三处
- 现象：向量模型配置渠道后无法正常调用，返回超时或参数错误。原因：未适配工程机械文档的长参数块，未正确设置`maxToken`参数，导致嵌入请求被截断。
- 现象：索引更新后旧故障案例无法被检索到。原因：未配置按文档更新时间戳触发增量索引，误开启全量索引导致覆盖冲突。
- 现象：检索结果混入非目标设备的文档。原因：未开启字段过滤配置，未指定设备型号作为检索匹配条件。

## 怎么确认配好了
- 上传一篇包含完整参数的工程机械故障文档，检查分块预览是否保留了连续的参数与步骤。
- 触发一次增量索引，查看索引日志中是否仅同步了更新后的文档，未触发全量重建。
- 输入包含特定设备型号的咨询问题，验证检索结果是否仅返回对应型号的文档。
- 调用向量嵌入接口，检查返回的向量维度与配置的模型维度一致，无截断报错。
