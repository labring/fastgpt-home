# 成品油销售的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
成品油销售的办事咨询数据主要来自加油站POS收银系统、库存管理系统、会员服务系统及官方油价公示平台。数据更新节奏分为实时与定期两类：油价、会员消费记录实时更新，库存台账、业务流程文档按日更新。文档结构包含当日零售价基准、库存吨位台账、会员办卡充值规则、开票指引、投诉处理流程等，字段自带明确单位，如油价为元/升、库存为吨，业务节点配有唯一标识编码。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时更新的油价与会员数据要求模型上下文窗口需限定在最近2小时内，避免使用过期数据生成答复。按日更新的库存与流程文档，要求配置时需设置每日自动同步的触发节点，确保知识库内容与业务系统保持一致。字段自带明确单位的特征，要求模型生成答复时必须匹配对应单位，配置时需在prompt中明确单位校验规则。多分支的业务文档结构，要求模型调用时需精准召回对应业务节点的知识库内容，避免跨分支混淆。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 7200 秒 | 适配实时更新的油价与会员数据，确保上下文仅包含最近2小时的最新业务信息 |
| `maxTokens` | 8000 token | 覆盖当日油价、库存台账、常见办事流程的完整知识库内容 |
| `quoteMaxToken` | 1500 token | 限制单条召回文档的长度，避免超出模型上下文窗口限制 |
| `toolChoice` | auto | 适配办事咨询中可能需要调用不同业务数据源的场景 |
| `temperature` | 0.2–0.4 | 确保答复严谨准确，避免生成不符合业务规则的内容 |
| `AIPROXY_API_ENDPOINT` | 按企业内部API地址填写 | 对接内部成品油业务数据接口 |
| `AIPROXY_API_TOKEN` | 按企业分配的密钥填写 | 保障接口调用的安全性 |

## 容易做错的三处
- 现象：编辑模型配置时删除body相关参数，提交保存后再次打开配置页，参数仍显示为保留状态。原因：未正确完成配置保存的提交流程，或浏览器缓存保留了旧的配置数据。
- 现象：模型请求节点返回500状态码或“模型调用失败”提示，无具体错误详情。原因：未配置错误捕获链路，未将模型调用的报错信息同步至业务监控系统。
- 现象：添加多个供应商的同一基础模型时，无法完成配置并提示ID重复。原因：未为不同供应商的模型配置唯一的标识后缀，导致FastGPT无法区分同名称的模型。

## 怎么确认配好了
- 发起测试请求，输入“今日92号汽油零售价是多少”的办事咨询问题，核对返回结果包含正确的单位与最新的业务数据。
- 模拟模型调用失败的场景，核对是否能捕获到对应的错误信息并生成符合业务规则的提示。
- 配置两个不同供应商的同一类模型，核对系统未提示ID重复且能正常切换调用。
- 调整`maxContext`参数的取值范围，核对上下文数据的更新频率符合业务需求。
