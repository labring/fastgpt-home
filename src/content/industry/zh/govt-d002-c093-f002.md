# 政企信息化服务的办事咨询与答复：向量模型与索引

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
该品类的数据主要来源于政企办事窗口的咨询记录、官方发布的办事指南、政策解读文件以及标准化常见问题库。数据更新节奏随政策调整、窗口流程变更按需触发，无固定周期。单条数据多包含标题、适用场景、办理步骤、咨询回复、联系渠道等结构化字段，部分文档附带文号、办理时限等补充信息，数据长度跨度较大，短则数百字的常见问题，长则数千字的完整办事流程说明。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据跨度大、结构差异明显，部分长文档需要拆分适配向量模型的输入限制，结构化字段如办理时限、文号需单独标记权重。按需更新的特性要求索引支持增量同步，避免全量重建消耗资源。咨询记录多为口语化表述，与政策文件的书面语存在差异，需要索引适配混合文本的向量化一致性。此外，部分数据包含敏感政务信息，索引过程需要符合数据脱敏要求，避免明文存储敏感内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配政企办事文档的平均长度，避免单块过长超出模型限制 |
| 重叠长度 | 100–200 字符 | 保留块间上下文关联，避免拆分后丢失办事流程的连贯信息 |
| `maxToken` | 8192 token | 匹配主流向量模型的输入上限，适配长文档向量化需求 |
| 相似度阈值 | 0.75–0.85 区间 | 过滤低匹配度的非相关办事信息，减少无效召回 |
| 单次搜索上限 | 前 10 条 | 控制召回结果数量，适配政企咨询的精准答复需求 |
| `defaultToken` | 按实测标定 | 适配数据集的平均文本长度，优化索引构建效率 |

## 容易做错的三处
- 数据集导入后长期显示创建索引中，持续数小时未完成。原因：未根据政企办事文档的长度调整分块参数，单块内容过长超出向量模型的输入上限，触发反复重试或超时阻塞。
- 向量计算得分异常偏高且多条结果得分完全一致。原因：未对结构化政务字段如文号、办理时限设置合理权重，导致重复内容或固定字段被过度匹配。
- 上传PDF等长文档后向量化耗时远超预期。原因：未启用分块并行处理配置，单线程处理长文档导致索引构建效率低下。

## 怎么确认配好了
- 查看数据集的索引构建日志，确认分块后的文本长度未超出向量模型的输入上限。
- 随机抽取10条咨询问题，执行召回测试，核对返回结果的匹配度符合预设的阈值区间。
- 导入单条长文档，验证索引构建耗时符合预设的性能要求，无超时报错。
- 检查敏感政务字段的脱敏配置，确认未在向量索引中存储明文敏感信息。
