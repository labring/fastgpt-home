# 有色金属冶炼的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
有色金属冶炼的办事咨询与答复数据主要来自生产过程实时监控系统、月度生产台账、行业合规标准文档及政务办事流程档案。数据更新节奏分两类：工艺参数类每10秒刷新一次，台账与合规文档按月度更新，政务办事档案随审批进度实时更新。文档结构按冶炼工序拆分，包含温度、电流、产量等带单位的工艺字段，以及办事申请单号、审批节点、办结时限等政务类字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
实时工艺参数的高频刷新要求多轮对话必须绑定当前会话的时间戳，避免调用过期的历史数据。政务办事字段的审批节点属性，要求多轮对话跟踪当前办理环节，确保答复不超出当前可操作范围。按工序拆分的文档结构，要求提示词在匹配用户咨询时，自动关联对应工序的数据集，避免跨工序的参数混淆。带单位的字段要求提示词统一输出单位格式，防止出现单位不匹配的答复。同时，政务办事档案的实时更新要求对话上下文需定期同步最新的审批规则，避免答复与当前政策不符。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定用户会话的唯一标识 | 实现多轮对话的上下文隔离，避免会话间数据混淆，适配FastGPT v4.17.0的会话管理规则 |
| `messages` | 保留前20条对话内容 | 覆盖冶炼工艺咨询的完整流程，确保上下文连贯，匹配专业咨询的对话逻辑 |
| `variables` | 绑定当前工序的工艺参数 | 精准调用对应生产数据，实现参数化匹配，贴合有色金属冶炼的专业数据需求 |
| 超时阈值 | 600秒 | 适配实时工艺数据的查询响应时长，避免因等待过长导致会话中断 |
| 上下文最大长度 | 800–1200字符 | 匹配冶炼文档的单段标准长度，避免截断关键工艺信息 |
| 工具调用模型 | 按实测标定 | 适配专业工艺参数的理解与答复要求 |

## 容易做错的三处
- 现象：调用API创建的应用，对话日志显示为空或丢失历史会话内容。原因：未正确绑定`chatId`参数，导致会话上下文未持久化存储。
- 现象：使用配置后的提示词提问，答复的工艺参数单位与实际要求不符。原因：未在提示词中明确统一单位的规则，未通过`variables`绑定带单位的标准参数。
- 现象：多轮对话超时，返回连接失败提示。原因：未设置合理的超时阈值，超过预设的响应时长限制，无法获取实时工艺数据。

## 怎么确认配好了
- 发起一轮工艺参数咨询，核对返回内容是否包含当前会话绑定的`chatId`标识，确认上下文隔离生效。
- 发起连续多轮咨询，核对返回内容是否关联前序对话的工序信息，确认`messages`上下文传递正常。
- 调用变量绑定的工艺参数，核对返回结果是否匹配当前配置的`variables`参数，确认参数替换生效。
- 发起超时测试，核对响应时长是否符合预设阈值，确认超时配置生效。
