# 有色金属冶炼的办事咨询与答复：知识库检索与召回

## 这个品类的数据长什么样
有色金属冶炼的办事咨询数据主要来自生产现场实时监控系统、批次质检报告、工艺规程手册、设备运维日志及行业合规标准。数据更新节奏覆盖多维度：实时监控的炉温、压力等参数为分钟级更新，批次质检数据随生产批次生成，工艺规程与合规标准按季度或年度修订。单篇文档多包含明确字段：冶炼批次号、设备编号、检测参数值（单位含℃、MPa、%等）、工艺步骤说明，部分长文档需拆分保留工艺逻辑完整性。

## 这些特征在「知识库检索与召回」这一环带来什么约束
实时参数的分钟级更新要求检索优先召回最新批次数据，避免返回过期的历史参数；多来源分散数据需要跨数据集召回，需明确绑定对应品类的数据集范围；字段含专属单位与批次标识，检索时需保留单位信息以避免参数匹配错误，同时支持精准匹配批次号、设备编号等标识字段；长文档的工艺步骤结构要求分块时保留上下文关联，防止拆分后丢失工艺逻辑；咨询常关联多维度参数（如炉温对应保温时长），需支持扩展关联检索以覆盖完整咨询场景。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.72–0.85` | 有色金属冶炼的工艺参数精度要求高，阈值过低会引入无关的低匹配度数据，过高会遗漏同工艺不同批次的有效内容，按实测标定 |
| `limit` | `前8–12条` | 冶炼相关的检索需要覆盖同批次、同设备的多维度数据，过多会超出上下文窗口，过少会丢失关键关联信息 |
| `searchMode` | `vector + keyword` | 既有工艺参数的语义匹配需求，又有批次号、设备编号的精准关键词匹配需求，覆盖不同检索场景 |
| `usingReRank` | `开启` | 冶炼数据的字段关联性强，重排可以过滤掉语义相似但参数不匹配的结果，提升召回准确性 |
| `datasetSearchUsingExtensionQuery` | `开启` | 冶炼相关的咨询常需要扩展关联参数，优化问题后可以提升召回范围，覆盖跨参数的关联咨询 |
| `collectionIds` | `绑定生产监控、质检报告、工艺规程三个数据集ID` | 有色金属冶炼的办事咨询覆盖生产、质检、合规全环节，跨数据集召回可以覆盖完整的咨询场景 |

## 容易做错的三处
- 现象：检索结果条数远低于预期，仅返回1-2条内容。原因：`similarity`阈值设置过高，过滤掉了大量符合语义匹配的有效文档。
- 现象：检索结果包含大量无关的通用工业文档，未匹配到冶炼专属参数。原因：未绑定专属的`collectionIds`，召回了非本品类的数据集内容。
- 现象：检索结果中未包含实时批次的生产数据。原因：未开启`datasetSearchUsingExtensionQuery`，无法关联批次号等实时字段的扩展检索。

## 怎么确认配好了
- 针对冶炼批次号的关键词检索，核对返回结果是否包含对应批次的质检数据和生产日志。
- 针对工艺参数的语义检索，核对重排后的结果是否优先匹配当前咨询对应的冶炼环节参数。
- 查看检索日志，确认召回的文档均来自绑定的三个专属数据集，无跨品类无关内容。
- 测试复杂关联咨询的检索，确认重排功能生效后结果的相关性符合预期。
