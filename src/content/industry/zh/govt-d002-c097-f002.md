# 核电运营的办事咨询与答复：向量模型与索引
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
核电运营办事咨询与答复的数据主要来自运行维护规程、应急响应手册、现场巡检记录、运维工单及员工咨询台账。数据更新节奏覆盖实时（运维工单、巡检记录）、月度（咨询台账归档）、季度（规程修订）三类。单份文档多为结构化或半结构化，包含设备编号、巡检时段、问题描述、处置流程、审批标识等字段，单位涵盖时间戳、辐射剂量mSv、设备运行参数单位等。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化与半结构化混合的数据结构，要求索引时需优先对问题相关字段（如问题描述、处置流程）做定向嵌入，避免无关字段干扰向量匹配。实时更新的运维工单要求支持增量索引，避免全量重建的耗时。单份文档长度跨度大，从数百字符的巡检记录到数万字符的应急手册，需要适配不同`maxToken`的截断规则，防止长文本截断关键处置逻辑。敏感字段的存在，要求索引时需先完成脱敏处理再生成向量，避免敏感信息泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配核电运维文档的单块信息密度，避免单块包含跨设备的无关内容 |
| 重叠长度 | 100–150 字符 | 保证相邻分块的上下文连贯性，覆盖跨块的操作流程描述 |
| `maxToken` | 4096 token | 匹配主流嵌入模型的输入上限，适配核电长规程的分段嵌入 |
| `defaultToken` | 256 token | 用于短文本的巡检记录，保证小体量文本的向量生成完整性 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关规程条目，贴合核电操作的严谨性要求 |
| 单次搜索上限 | 前6条 | 控制返回结果的数量，避免冗余信息干扰咨询答复的精准性 |

## 容易做错的三处
- 现象：升级FastGPT版本后，同一份CSV格式的运维工单文件无法正常分块。原因：新版本的分块逻辑调整了半结构化数据的识别规则，未兼容旧版CSV的字段分隔符配置。
- 现象：知识库索引任务卡住，界面显示未完成索引的条目数持续不变。原因：增量索引时未正确配置增量触发条件，导致重复处理已索引的实时工单数据，阻塞索引队列。
- 现象：生成的咨询答复出现无关的设备参数内容。原因：未定向嵌入问题描述字段，将设备编号等非咨询相关字段纳入向量生成，导致匹配到无关文档。

## 怎么确认配好了
- 上传一份标准的巡检记录CSV文件，检查分块预览界面的块长度是否在预设的区间内。
- 触发一次增量索引任务，查看索引日志中是否仅显示新上传的工单条目，无重复的历史数据。
- 测试输入一条具体的核电运维问题，查看返回结果的相似度得分是否落在预设的阈值区间内。
- 查看向量数据库的存储容量，确认未出现因分块过大导致的存储空间溢出问题。
