# 民航机场的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
民航机场办事咨询的数据源来自机场官方问询系统、航站楼运营公告、民航局公开指引。数据更新分为固定周期与临时调整：每年春秋两次航班换季时全量更新核心规则，临时调整如航班延误、新航线开通时实时同步。文档以场景化问答对为核心结构，包含问题原文、标准答案、适用航站楼范围、生效时间字段，生效时间采用YYYY-MM-DD格式标注，金额类内容以人民币元为单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据源的场景化结构要求多轮对话需先明确用户的行程场景，如国内或国际航班、当前所在航站楼，避免返回跨场景的无效答案。固定与实时结合的更新节奏要求对话系统需定期同步知识库，确保临时调整的内容及时生效。多轮上下文需保留用户提及的航班号、出行日期等关键信息，减少重复问询，同时需过滤已过期的规则内容，避免返回失效的答复。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定用户会话的唯一标识，有效期设置为3600秒 | 保持多轮对话的上下文一致性，避免不同会话的内容混淆 |
| `messages` | 保留前10轮对话内容 | 民航咨询场景的上下文集中在单次行程相关内容，过多轮次会引入冗余信息 |
| `variables` | 传入当前航站楼、用户查询的航班日期、行程类型 | 匹配对应场景的精准答复，适配不同航站楼的差异化规则 |
| 最大上下文长度 | 8000–12000 token | 覆盖完整的问询上下文，避免截断关键的航班信息 |
| 问题优化 | 开启自动补全上下文 | 当用户省略之前提及的航班号等信息时，自动补充上下文生成完整问题 |
| 单次搜索上限 | 前3条匹配结果 | 民航咨询的标准答复通常单一精准，过多结果会干扰用户判断 |

## 容易做错的三处
- 调用对话接口返回`unAuthChat`报错，原因是未正确绑定`chatId`，或apikey未配置对话接口的访问权限。
- 对话返回内容包含换行符，导致json请求解析失败，原因是未对返回的标准答案做转义处理，未将换行符替换为`\n`。
- 上传民航相关的问询文档时报错，但文本对话功能正常，原因是上传的PDF或文档存在加密格式，或文件大小超过系统限制。

## 怎么确认配好了
- 发起包含多轮上下文的问询，先询问航班号与出发航站楼，再询问行李托运规则，确认系统能关联之前的信息生成对应答复。
- 调用对话接口时传入正确的`chatId`与apikey，验证返回结果无未授权报错，且内容符合民航机场的标准规则。
- 上传一份民航航站楼指引的PDF文档，确认系统能正常解析并匹配到对应的问询内容。
- 发起多轮连续问询，确认响应耗时符合预期，无明显延迟。
- 检查对话返回的内容，确认换行符已被正确转义，不会导致json请求格式错误。
