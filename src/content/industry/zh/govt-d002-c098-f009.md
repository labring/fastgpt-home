# 民航机场的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
民航机场办事咨询的数据主要来源于机场官方客服话术库、航班实时调度系统、航站楼服务指引文档、安检与登机流程规范。数据更新节奏分为三类：航班动态数据实时同步，常规服务话术每季度更新，临时政策调整即时同步。文档按场景分为航班延误、行李托运、登机指引、特殊旅客服务等模块，每个模块包含问题关键词、标准答复、生效时间、适用航站楼/航线等字段，答复文本以自然语言为主，部分包含航班号、航站楼编号等标准化字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时同步的航班动态数据要求模型调用需控制响应延迟，避免答复滞后影响用户体验。多场景模块化的知识库结构，需要配置足够的上下文容纳量，以拼接跨环节的咨询信息。字段中的生效时间与适用范围，要求模型在生成答复时需匹配当前时间与用户所在航站楼，因此需明确工具调用的触发条件。此外，标准化字段的格式要求，需确保检索与调用环节的输入输出格式统一，避免因格式不匹配导致的调用失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配机场办事咨询多场景的上下文拼接需求，容纳跨环节的问答对与实时航班信息 |
| `maxTokens` | 2000–3000 token | 保障答复长度覆盖完整的流程指引或航班调整说明，避免截断关键信息 |
| `quoteMaxToken` | 1500 字符 | 匹配机场知识库单条标准答复的平均长度，确保引用内容完整无缺失 |
| `temperature` | 0.1–0.3 | 保持办事答复的严谨性，避免生成偏离标准话术的个性化内容 |
| `toolChoice` | auto | 自动判断是否需要调用航班查询、航站楼指引等工具，适配动态变化的咨询场景 |
| `AIPROXY_API_ENDPOINT` | 按私有部署环境填写 | 适配模型调用路径，保障机场敏感服务数据的传输安全 |

## 容易做错的三处
- 现象：调用自定义渠道的rerank服务返回400状态码，无有效结果。原因：未将机场知识库的文本格式适配自定义渠道要求的输入长度，导致请求被拦截。
- 现象：模型答复截断关键流程信息，无法完整说明行李托运的全部要求。原因：`maxTokens`取值过小，未覆盖机场办事指引的完整内容。
- 现象：答复中出现过时的安检政策内容。原因：未定期更新向量库的实时政策数据，导致模型调用陈旧的知识库条目。

## 怎么确认配好了
- 提交测试用的民航办事咨询问题，核对模型返回的答复是否匹配当前生效的知识库内容与实时航班信息。
- 查看FastGPT v4.17.0的模型调用日志，确认`maxContext`与`maxTokens`的实际使用值未超过配置上限，无截断提示。
- 测试自定义渠道的rerank服务调用，确认返回的结果条数符合预期，无400类报错。
- 验证敏感词过滤功能，提交包含机场场景敏感词汇的测试问题，确认内容被正确拦截或替换。
