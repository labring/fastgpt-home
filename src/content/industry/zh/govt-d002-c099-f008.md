# 油气勘探开发的办事咨询与答复：文档解析与分块

## 这个品类的数据长什么样
油气勘探开发的办事咨询与答复相关数据，来源包括野外地震勘探采集报告、钻井作业日志、油气藏评估文档、行政办事审批文件及项目进度台账。数据更新节奏随项目阶段调整，勘探阶段按周同步作业数据，审批类文档随办事流程更新。文档结构包含长文本技术报告、结构化参数表格、零散工单记录三类，字段涵盖井号、作业深度、地层压力、审批文号、办理进度等，单位包含米、兆帕、摄氏度、件等。

## 这些特征在「文档解析与分块」这一环带来什么约束
长文本的地震勘探报告单篇篇幅较大，分块时需避免割裂专业术语组合；钻井日志的结构化表格包含井号、深度、压力等关联字段，分块需保留表格整体结构防止数据断裂；办事咨询工单的字段存在强关联属性，分块需保留上下文逻辑；实时采集的作业数据更新频率较高，解析环节需适配增量同步需求，避免重复解析全量数据。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配油气勘探报告的专业段落长度，避免割裂术语组合 |
| `chunkSplitter` | 按段落+标题分级 | 匹配勘探文档的章节结构，保留逻辑关联 |
| `customPdfParse` | 启用表格识别模式 | 适配钻井日志、评估报告中的结构化表格数据，避免单元格拆分 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对长文档解析的耗时需求，防止超时中断任务 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持大型地震数据PDF或压缩包上传 |
| `chunkSettingMode` | 手动配置 | 针对技术报告、工单、表格等不同文档类型调整参数 |

## 容易做错的三处
- 上传大型勘探报告后解析节点无响应，任务状态显示超时。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认参数时长不足以完成长文档解析。
- 上传钻井日志表格后仅抓取到部分数据，单元格内容出现断裂。原因是未启用`customPdfParse`的表格识别模式，默认解析逻辑会拆分表格结构导致数据丢失。
- 模型输出Markdown格式的勘探数据表格时，展示内容被截断。原因是`chunkSize`设置过小，将完整表格行拆分至不同分块，导致渲染时信息断裂。

## 怎么确认配好了
- 上传单篇500页的勘探报告，查看解析任务的日志，确认未出现超时报错。
- 上传包含结构化表格的钻井日志文档，检查解析后的文本是否保留完整表格结构，无单元格拆分情况。
- 调用分块预览功能，查看专业术语段落是否未被割裂，逻辑关联完整。
- 上传最大允许大小的文件，确认上传与解析流程无异常中断。
