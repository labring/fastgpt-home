# 油气勘探开发的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
油气勘探开发的业务数据主要来源于勘探物理报告、钻井施工日志、试采监测报表、储量评估文档。数据更新节奏随项目阶段变化，预探阶段按单井勘探周期更新，开发阶段按月度试采数据更新。单篇文档多包含区块编号、井号、作业深度、地层压力、流体组分等字段，单位涵盖米、兆帕、立方米、质量百分比等，部分长文档包含多章节的作业参数与历史监测数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
油气勘探开发的多字段多单位专业数据，要求模型接入时需适配专业术语与单位关联逻辑，避免参数解析错误。长文档多章节的结构，要求上下文窗口配置需适配分段后的专业内容，防止截断关键作业参数。按项目周期更新的业务数据，要求知识库同步机制匹配勘探、开发阶段的更新节奏。不同井况的专属数据需通过标签区分，避免跨井况的咨询内容产生混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配油气勘探长文档的多章节内容，避免截断关键作业参数 |
| `maxTokens` | 2000–3000 token | 满足专业咨询的详细答复需求，避免输出内容被截断 |
| `quoteMaxToken` | 1500–2000 字符 | 匹配单篇勘探报告的核心段落长度，确保引用内容完整准确 |
| `temperature` | 0.1–0.3 | 保持专业答复的严谨性，减少无关内容的生成 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配FastGPT v4.17.0的代理接口配置，确保模型调用通路正常 |
| `AIPROXY_API_TOKEN` | 按分配的有效密钥填写 | 完成模型接入的身份验证，保障调用权限合法有效 |

## 容易做错的三处
- 调试界面与外部接入渠道返回内容不一致，原因是未统一配置`maxContext`与`quoteMaxToken`的取值，不同环境的上下文窗口限制存在差异。
- 模型测试环节报错提示身份验证失败，原因是`AIPROXY_API_TOKEN`填写错误或未配置有效密钥，导致无法完成模型调用授权。
- 无法找到模型配置的渠道选项，原因是未在FastGPT后台开启对应模型的接入权限，或代理接口未完成基础配置。

## 怎么确认配好了
- 进入模型调试界面，输入单篇勘探报告的核心片段，检查上下文窗口是否正常加载完整内容，确认配置参数匹配文档长度要求。
- 发起专业咨询测试，检查答复内容是否包含准确的专业术语与单位，确认配置的严谨性适配业务场景。
- 调用外部接入渠道发起相同咨询，对比调试界面的返回结果，确认全链路配置参数保持一致。
- 查看知识库同步日志，确认数据源更新机制与业务周期匹配，验证配置的同步逻辑生效。
