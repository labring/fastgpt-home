# 油田工程服务的办事咨询与答复：文档解析与分块
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
油田工程服务的办事咨询与答复数据主要来自施工方案、井位勘测报告、设备运维日志、办事审批文档，更新节奏随项目周期不定期推进。文档类型以长文本PDF、结构化Excel为主，包含井号、作业日期、施工压力、耗材用量等字段，单位涵盖MPa、m³、小时等专业工程单位，部分文档包含图表与公式。

## 这些特征在「文档解析与分块」这一环带来什么约束
长文本PDF文档占比高，分块需兼顾上下文完整性与嵌入向量精度，避免割裂专业施工步骤；结构化Excel数据包含多字段关联条目，分块时需保留行级数据关联，防止检索时丢失完整信息；办事审批类文档包含连续审批节点，分块不能打断节点逻辑；部分文档含专业图表与公式，解析需保留格式与内容关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配油田工程专业长文本的上下文长度，平衡检索精度与分块效率 |
| `chunkSplitter` | 按段落+固定字符边界 | 匹配施工方案、运维日志的自然分段逻辑，避免割裂专业术语组合 |
| `customPdfParse` | 启用 | 支持解析带专业图表、公式的油田工程PDF文档，保留核心排版与内容结构 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 秒 | 适配大型施工方案PDF的解析耗时，避免触发超时报错 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 覆盖单份大型井位勘测报告的上传需求 |
| `chunkSettingMode` | 手动配置 | 针对PDF、Excel等不同文档类型调整分块规则，匹配办事咨询场景的内容特征 |

## 容易做错的三处
- 上传单份500MB以上的施工方案PDF时，触发平台超时报错。原因是未将`PARSE_FILE_TIMEOUT_SECONDS`调整至适配大型文档的取值区间，导致解析未完成即被终止。
- 检索Excel格式的耗材清单时，返回结果条数少于源文件。原因是未启用结构化数据解析模式，或分块时未保留完整行级数据关联，导致部分条目未被索引。
- 检索施工步骤描述时，出现专业术语关联断裂的情况。原因是`chunkSize`设置过小，割裂了连续的施工流程上下文。

## 怎么确认配好了
- 上传单份800MB的井位勘测报告PDF，检查解析任务无超时报错，且解析进度正常完成。
- 上传包含国外使用地字段的Excel耗材清单，检索后确认返回结果包含所有符合条件的条目，无遗漏。
- 上传带专业公式的钻井设计文档，检查解析后分块保留了公式与前后文的关联，未出现内容断裂。
- 调整`chunkSize`至1000字符，验证分块后的文本未割裂连续的施工步骤描述。
