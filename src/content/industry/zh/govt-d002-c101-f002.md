# 港口航运的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
港口航运办事咨询与答复的数据主要来自港口政务公开的办事指南、通关申报规范、泊位预约流程、危险品管理规则，以及实时更新的口岸通告、船期调整通知、咨询热点汇总。文档以结构化文本为主，包含办理事项名称、办理主体、所需材料、办理时限等固定字段，单位多为工作日、份、泊位数量、船舶吨级等。办事指南类文档更新周期为季度或半年度，口岸通告与船期信息每日更新。

## 这些特征在「向量模型与索引」这一环带来什么约束
港口航运的办事咨询数据特征对向量模型与索引环节带来多重约束。流程类长文本占比高，分块时需避免切断完整的办理步骤，否则会导致检索结果无法提供连贯的办事指引；实时更新的口岸通告与船期信息需要支持增量索引，全量索引会带来不必要的资源消耗；文档包含泊位编号、船型要求等专属字段，需在索引时保留字段语义，避免通用匹配导致的检索结果偏离港口专属场景。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配港口办事指南的流程类长文本，保留单条办理步骤的语义完整性 |
| 重叠长度 | 100–150 字符 | 避免分块切断流程衔接，保障跨块语义连贯性 |
| 相似度阈值 | 0.72–0.80 | 匹配港口办事咨询的精准度需求，过滤低相关的通用政务内容 |
| 单次搜索上限 | 前 8 条 | 覆盖港口办事的多场景关联需求，避免遗漏相关办理指引 |
| `maxToken` | 4096 token | 适配港口咨询的长上下文问答，保障完整返回办理流程与材料要求 |
| `defaultToken` | 2048 token | 作为默认嵌入请求的长度限制，平衡模型性能与嵌入精度 |

## 容易做错的三处
- 现象：Docker部署的知识库显示索引进度停滞，长时间未完成索引。原因：未针对港口实时船期、口岸通告的高频更新配置增量索引策略，重复加载大量历史全量数据。
- 现象：调用嵌入模型时返回503状态码，提示当前分组default下无可用text-embedding模型。原因：未在FastGPT配置中为港口咨询场景绑定专属嵌入模型分组，默认分组资源不足或未配置对应模型。
- 现象：检索结果混杂大量通用政务内容，无法匹配港口专属办事需求。原因：未针对港口文档的专属字段（如泊位编号、船型要求）配置检索过滤，仅依赖全局相似度匹配。

## 怎么确认配好了
- 手动上传一份港口泊位预约办事指南，检查分块后的文本是否保留了完整的预约流程步骤，无中途截断情况。
- 发起一条模拟咨询（如“如何办理船舶进港申报”），核对检索返回的文档与咨询问题的语义匹配度符合预设的匹配规则。
- 模拟新增一条实时口岸通告，检查索引系统是否在设定的更新周期内完成新数据的索引加载，无延迟。
- 查看嵌入模型的调用日志，确认每次请求的token数未超过配置的`maxToken`与`defaultToken`限制，无报错返回。
