# 炼化生产的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
炼化生产的办事咨询数据主要来自生产工艺规程、设备运维日志、岗位巡检记录、原料质检报告、安全合规文件等。数据更新节奏差异明显：岗位巡检记录每班更新，设备运维日志随设备检修周期更新，工艺规程与合规文件按季度或政策要求修订。单篇文档结构包含设备编号、操作参数、异常情况、处理措施等字段，单位涵盖MPa、℃、m³/h、批次号、运行时长等工业标准单位，部分长文档可达数万字符。

## 这些特征在「向量模型与索引」这一环带来什么约束
炼化生产数据的多类型混合特征，对向量模型与索引环节提出多重约束。带单位的数值型字段与专业工业术语混合，要求向量模型具备工业场景语义适配能力，避免专业术语的语义误判。数据长度差异大的特点，要求索引支持灵活的分块配置，适配短巡检记录与长工艺规程的向量生成。增量更新的需求，要求索引支持增量索引构建，适配每班更新的巡检日志数据。QA拆分的文件集合，要求索引优化QA对的检索效率，满足办事咨询的精准召回需求。批量导入的长文档会增加索引构建的负载，需要调整配置平衡效率与召回精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配炼化生产长工艺规程与短巡检记录的混合长度，避免单块包含跨工序的无关信息 |
| 重叠长度 | 50–100 字符 | 保留跨块的工艺关联信息，例如设备启停的连续操作步骤 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 适配工业术语的语义相似度，避免误召回或召回不足 |
| `maxToken` | 8192 token | 匹配主流开源embedding模型的上下文上限，适配长文档的向量生成 |
| 重排 | 开启，取前3条 | 过滤低相关的巡检记录，聚焦核心工艺与办事咨询的匹配内容 |
| `defaultToken` | 1024 token | 统一基础向量生成的token配额，平衡单条数据的向量质量与索引效率 |

## 容易做错的三处
- 现象：调用知识库接口生成索引时返回504超时状态码。原因：未针对炼化生产的长工艺文档调整`maxToken`参数，导致单条数据向量生成耗时超出接口限制。
- 现象：检索结果中出现大量无匹配业务场景的空字段记录。原因：相似度阈值设置过低，误召回语义关联较弱的非目标数据。
- 现象：通过OpenAPI创建的QA拆分文件集合，检索响应时长超出预期。原因：分块长度设置过大，且未开启重排配置，导致索引召回的冗余数据过多。

## 怎么确认配好了
- 上传一篇典型的炼化工艺规程文档，在FastGPT v4.17.0的向量生成日志中查看token消耗，确认`maxToken`取值符合配置要求。
- 输入一条设备异常咨询的标准问题，核对检索结果的条数与重排后的前3条记录是否匹配业务预期。
- 调用OpenAPI接口批量导入100条QA拆分的巡检记录，查看索引构建进度的更新速度是否符合预期。
- 对比不同embedding模型的召回结果，确认工业术语的语义匹配精度符合业务场景需求。
