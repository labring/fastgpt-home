# 煤化工的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
煤化工办事咨询与答复的数据主要来自内部办事指引、审批流程规范、设备运维手册、现场作业记录。数据更新节奏分两类：固定办事文档按季度同步更新，现场作业与实时审批数据每日更新。单份文档结构包含流程步骤、申请材料清单、合规要求、参数指标四类字段，参数指标常附带MPa、℃、吨等工业单位，部分文档包含多页嵌套的流程说明。

## 这些特征在「向量模型与索引」这一环带来什么约束
煤化工办事数据包含大量带工业单位的参数指标与嵌套流程结构，会导致基础分块时出现单位拆分、流程逻辑断裂的问题，要求分块需保留字段完整性。实时更新的作业数据要求索引支持增量同步，避免全量重建带来的性能损耗。多字段文档需区分核心咨询字段与辅助字段，避免无关数据干扰向量召回精度，同时需适配不同长度的咨询问题与文档内容。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配煤化工文档的嵌套流程与参数字段长度，避免拆分后逻辑断裂 |
| 重叠长度 | 100–150 字符 | 保留跨分块的参数单位与流程衔接信息，防止语义断点 |
| 相似度阈值 | 0.75–0.85 | 过滤工业参数匹配的误召回，匹配业务咨询的语义相关性要求 |
| 单次搜索上限 | 前 8 条 | 覆盖煤化工办事流程的多步骤关联信息，避免遗漏关键审批节点 |
| `maxToken` | 4096 token | 适配长文档的向量编码长度，满足嵌套流程文档的完整语义提取 |
| `defaultToken` | 1024 token | 用于短咨询问题的向量匹配，平衡编码效率与语义完整性 |

## 容易做错的三处
- 现象：界面弹出“undefined model must match ^(text”类报错，无法完成向量嵌入。原因：未接入所选向量模型的API服务，或选择了未配置的第三方向量模型。
- 现象：语义检索分数很高，但返回结果未匹配正确的办事流程。原因：分块长度过短，拆分了嵌套流程的逻辑关联，导致语义召回出现偏差。
- 现象：单条业务数据生成多组向量条目，无法正确关联原始文档。原因：未设置合理的重叠长度，或分块参数与文档字段结构不匹配，导致数据被重复拆分。

## 怎么确认配好了
- 上传单份包含设备参数与嵌套流程的煤化工文档，检查分块预览是否保留完整的参数单位与流程衔接步骤。
- 发起一条包含具体设备参数的办事咨询，查看召回结果的相似度分值是否处于设定的阈值区间内。
- 上传一条当日更新的现场作业记录，等待10分钟后发起相关咨询，确认索引已完成同步更新。
- 测试多字段文档的向量召回，确认核心办事流程字段的召回优先级高于辅助参数字段。
