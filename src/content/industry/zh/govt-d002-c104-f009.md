# 煤化工的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
煤化工办事咨询与答复的数据主要来自企业内部的办事指南库、审批流程档案、历年咨询工单归档，以及行业监管部门发布的办事规范。数据更新随监管政策调整、企业内部流程优化同步进行，无固定周期但核心文档更新间隔不超过半年。单份文档对应单一办事事项，包含事项名称、办理条件、申报材料清单、办理流程、咨询渠道、办结时限等字段，字段单位多为工作日、份、元等标准化行政文书格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
煤化工办事咨询数据按单一事项拆分文档，且包含多维度行政字段，要求模型接入时需精准匹配字段关联逻辑，避免跨事项混淆。数据更新无固定周期，需配置支持灵活触发的知识库同步机制，适配临时政策调整后的文档更新。部分办事事项文档篇幅较长，需限制模型上下文承载量，防止长文本超出模型处理阈值导致异常。同时专业术语密集，需调整模型参数适配行业文本的语义理解精度，确保答复的专业性与准确性。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 煤化工办事事项文档多为1000-3000字符，结合上下文关联历史咨询工单，该区间可覆盖完整事项与历史咨询上下文 |
| `maxTokens` | `2000–3000 token` | 办事答复需清晰完整，过长输出易偏离核心，该区间可覆盖常规答复长度 |
| `quoteMaxToken` | `3000–5000 token` | 需召回完整的办事材料清单与流程文档，确保引用内容无截断 |
| `temperature` | `0.2–0.4` | 办事答复需准确严谨，较低温度可减少无关内容生成，适配行政咨询的标准化要求 |
| `toolChoice` | `auto` | 需自动判断是否需要调用知识库或直接答复，适配多样化的煤化工办事咨询场景 |
| `AIPROXY_API_ENDPOINT` | 按部署的私有代理地址填写 | 需将模型请求路由至内部代理，保障煤化工业务数据的安全性 |
| `AIPROXY_API_TOKEN` | 按实际生成的代理密钥填写 | 用于身份验证，确保模型请求的合法性 |

## 容易做错的三处
- 现象：调用模型时出现`Unexpected end of JSON input`报错。原因：未正确配置`AIPROXY_API_TOKEN`或代理地址格式错误，导致请求返回空或不完整的JSON响应。
- 现象：使用长文本办事文档提问时，模型输出答非所问。原因：`maxContext`设置过小，未覆盖完整的办事文档上下文，导致模型丢失关键流程与材料信息。
- 现象：自定义Chat TTS对接后无响应。原因：未将`AIPROXY_API_ENDPOINT`正确指向TTS服务地址，导致请求路由错误，无法完成语音生成与播放。

## 怎么确认配好了
- 提交单条煤化工办事咨询，检查模型输出是否包含准确的办事流程与材料信息，核对输出内容是否与知识库文档匹配。
- 上传一份长篇幅的办事文档，验证`maxContext`设置是否可完整加载文档内容，无截断或加载失败报错。
- 触发知识库同步操作，检查数据更新后模型是否能召回最新的办事规范内容，确保更新生效。
- 调用测试接口，验证`AIPROXY_API_TOKEN`的身份验证是否正常，无权限相关报错。
