# 煤炭运销的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
煤炭运销业务的数据主要来自企业内部运销管理系统，包含过磅单、运销合同、运价结算单、车皮调度记录等类型。数据更新节奏为按每日批次或每趟运输完成后同步。文档结构以结构化表格为主，包含货物品名、发运矿点、目的地、实发吨位、结算单价、运距、结算金额等固定业务字段，字段单位统一为吨、元/吨、公里、元等行业标准格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
煤炭运销的结构化数据特征与更新节奏，对模型接入与配置带来核心约束。固定业务字段与单位要求模型输出必须严格匹配字段格式，接入时需明确字段映射规则，避免生成不符合业务规范的内容。单批次运销数据包含多组明细字段，单次输入的token数较高，需限制上下文与输出长度，防止模型推理资源过载。数据按批次更新，知识库同步周期需匹配业务更新节奏，确保模型调用时可获取最新运销数据。部分咨询需对多批次运销数据排序，需额外配置重排模型的接入参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 煤炭运销单包含多批次货物品类、吨位、运距等字段，单批次数据token数较高，需预留足够上下文容纳历史单据与当前请求 |
| `maxTokens` | 2000–3000 token | 办事咨询需输出标准化答复，过长输出易偏离业务场景，限制输出长度确保答复简洁准确 |
| `temperature` | 0.1–0.3 | 煤炭运销业务需严格匹配数据字段与规则，较低温度确保答复一致性，避免随意生成无关内容 |
| `AIPROXY_API_ENDPOINT` | 对应部署的大模型与重排模型接口地址 | 需匹配煤炭运销场景下的模型调用需求，重排模型需支持rerank接口适配多单据排序 |
| `AIPROXY_API_TOKEN` | 平台分配的专属接口密钥 | 确保模型调用权限合规，避免未授权访问 |
| `quoteMaxToken` | 1500 token | 需引用运销单据内容作为答复依据，限制引用内容的token数避免上下文溢出 |

## 容易做错的三处
- 现象：界面显示Invalid URL (POST /v1/rerank)，重排模型调用失败。原因：未正确配置`AIPROXY_API_ENDPOINT`为重排模型的实际部署地址，或接口路径未包含/v1/rerank端点。
- 现象：上传的运销单据数据未参与答复，答复仅基于通用知识库内容。原因：未将上传数据正确关联至当前会话的输入参数，导致模型无法获取上传的业务数据。
- 现象：部署70B大模型后答复超时，回复速度过慢。原因：未限制`maxContext`的取值，过大的上下文导致模型推理资源占用过高，引发超时。

## 怎么确认配好了
- 调用FastGPT v4.17.0的测试接口，输入单批次运销单据数据，检查答复是否准确引用单据内的字段与数值。
- 提交包含重排需求的咨询，如“按运距排序本周发运的煤炭批次”，检查是否正确调用重排模型并返回排序结果。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置未出现拼写错误或权限异常。
- 上传批量运销数据后发起咨询，检查答复是否包含上传数据的统计内容，确认数据已成功参与模型推理。
