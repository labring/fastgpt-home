# 煤矿生产的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
煤矿生产办事咨询相关的数据主要来自岗位操作手册、安全作业规程、设备维护台账、每日巡检记录、应急处置预案及办事流程文档。数据来源覆盖工区管理、设备运维、现场作业等多个业务环节，更新节奏差异明显：通用作业规程每1-2年定期修订，一线巡检、设备台账类文档每日更新。文档多按工区、设备型号、操作步骤分层结构，包含明确的单位字段，如吨、立方米、帕斯卡、小时等，单篇文档长度跨度较大，从数百字符的巡检记录到数万字符的完整作业规程。

## 这些特征在「向量模型与索引」这一环带来什么约束
不同类型的数据特征对向量模型与索引环节形成多重约束：每日新增的巡检、台账数据要求支持增量索引更新，避免全量重建带来的计算资源消耗；长文档的分层结构需要在分块时保留工区、设备型号等关键元数据，确保召回结果可关联到具体作业场景；多语言的中外文作业指导书需求要求适配多语言embedding模型，保障跨语言办事咨询的召回效果；办事咨询的问题多聚焦具体操作步骤、参数设置等细节，需要索引匹配精准的语义关联。

## 配置怎么定
FastGPT v4.17.0版本下的配置参考如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配煤矿作业文档的常见单段内容长度，避免分块过碎破坏操作步骤完整性 |
| 重叠长度 | 100–150 字符 | 保留跨分块的操作流程上下文，确保召回时可完整呈现连续的办事步骤 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 适配煤矿专业术语的语义相似度区间，过滤无关的非对应岗位内容 |
| 单次搜索上限 | 前 6 条 | 匹配办事咨询的常见结果数量，避免过多冗余信息干扰决策 |
| `defaultToken` | 4096 | 适配单块分块的token限制，覆盖多数煤矿文档分块后的token数 |
| `maxToken` | 8192 | 匹配大模型的上下文窗口上限，确保召回的分块内容可完整传入处理 |

## 容易做错的三处
- 手动上传煤矿办事文档后，界面显示索引中超过4小时未完成。原因：未根据单文档的体积调整分块处理的并发配置，大篇幅的作业规程未拆分适配系统处理上限。
- 更换多语言embedding模型后，原有知识库的跨语言召回效果无改善。原因：未执行全量重新嵌入任务，仅更新了新上传内容的向量，原有数据仍使用旧模型生成的向量。
- 知识库插入新文档后生成的默认索引在数小时后消失。原因：配置了临时索引的自动清理周期，未将办事咨询相关的核心索引设置为持久化存储。

## 怎么确认配好了
- 上传一份典型的煤矿巡检记录文档，查看分块后的内容是否保留了工区、设备型号等关键字段信息。
- 发起一条针对具体岗位的办事咨询问题，核对返回的召回结果是否包含该岗位对应的操作流程内容。
- 更换embedding模型后，执行全量重新嵌入任务，查看任务进度是否按预期完成且无报错。
- 查看索引的持久化配置，确认核心办事文档的索引未设置自动清理规则。
