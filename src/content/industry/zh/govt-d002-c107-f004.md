# 煤矿生产的办事咨询与答复：工作流编排

## 这个品类的数据长什么样
煤矿生产办事咨询与答复的数据主要来源于井下作业台账、安全规程手册、现场问题上报单、办事流程审批记录。数据更新节奏分为实时（现场问题上报单）、每日（作业台账更新）与定期（安全规程修订）三类。文档结构按作业类型、审批节点、问题分类划分，包含作业编号、审批状态、问题描述、处理时限等字段，字段单位多为小时、条、米等业务专属单位。

## 这些特征在「工作流编排」这一环带来什么约束
煤矿生产数据的专属字段要求工作流必须绑定对应业务变量，才能精准匹配知识库内容；实时更新的作业数据要求工作流配置定时同步节点，避免使用过期信息；多分类的文档结构要求工作流按作业类型筛选知识库，缩小搜索范围；长文本的作业记录与规程文档，可能超出AI输入上限，需要在工作流中添加前置校验环节。此外，办事咨询的问题多关联具体作业场景，工作流需支持用户输入后关联对应业务字段，才能输出针对性答复。

## 配置怎么定
本页面基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 800–1200 字符 | 煤矿作业相关文档单篇长度多在500-1000字符，匹配该范围可避免超出AI输入上限 |
| 单次搜索上限 | 前6条 | 煤矿办事咨询的常见问题集中在3-5类，过多搜索结果会干扰答复准确性 |
| `variables` | 绑定作业编号、审批状态变量 | 办事咨询需关联具体作业场景，精准匹配对应业务知识库内容 |
| `nodeId` | 绑定会话提交按钮的节点ID | 实现用户点击按钮后触发后续流程，符合办事提交的交互逻辑 |
| 分块长度 | 300–500 字符 | 煤矿安全规程类文档多为短段落，该分块范围可兼顾上下文完整性与检索效率 |
| 超时时间 | 600 秒 | 煤矿办事咨询的响应需在合理时限内，避免等待过久影响作业效率 |

## 容易做错的三处
- 现象：AI对话节点返回输入长度超限报错，原因：未在工作流前置添加输入长度校验节点，未对超过阈值的内容进行拦截。
- 现象：知识库搜索未按指定变量筛选结果，原因：未正确配置`variables`绑定对应业务字段，变量引用路径错误。
- 现象：会话弹窗按钮点击后未触发后续流程，原因：未将按钮节点与后续工作流节点的`nodeId`正确关联，触发逻辑缺失。

## 怎么确认配好了
- 输入超过预设长度的测试文本，检查是否触发拦截提示。
- 绑定作业编号变量进行知识库搜索，检查返回结果是否仅匹配对应作业类型的文档。
- 点击会话弹窗按钮，检查工作流是否跳转到预设的后续节点。
- 查看工作流运行日志，确认`variables`和`nodeId`的参数调用正常。
