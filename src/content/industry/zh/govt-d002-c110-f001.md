# 矿山采选的办事咨询与答复：HTTP 接口与外部系统

## 这个品类的数据长什么样
矿山采选的办事咨询与答复数据主要来自矿山生产监控系统、选矿流程PLC采集数据、地测勘探台账、安全合规工单系统。实时生产参数如采区产量、通风压力每秒更新，勘探报告与合规工单按月归档。数据文档包含结构化字段：矿山编号、采区名称、作业面ID、咨询类型、答复状态，字段单位涵盖吨、立方米、帕斯卡、小时等，部分字段为枚举值，如咨询类型分为安全咨询、流程咨询、设备咨询。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
实时生产参数的秒级更新要求HTTP接口超时时间不宜过长，避免请求阻塞导致数据丢失。结构化字段的枚举与单位要求接口参数校验需严格匹配字段类型与取值范围，否则会触发数据校验失败。矿山编号作为跨系统关联的核心键，要求外部系统传递该字段作为请求参数，否则无法匹配对应采区的咨询与答复数据。敏感的安全与生产数据要求接口需通过`Authorization`参数完成身份校验，避免未授权访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 接口超时时间 | 600 秒 | 匹配矿山采选实时数据的更新间隔，避免请求阻塞 |
| `Authorization` | 携带 Bearer 令牌 | 符合矿山敏感数据的安全访问规范 |
| `variables` | 传入矿山编号、咨询类型 | 用于关联对应采区的业务数据与咨询工单 |
| `responseData` | 提取答复内容、工单ID | 匹配外部系统的业务字段需求 |
| 单次请求参数数量 | 不超过15 个 | 降低接口负载，避免请求被拦截 |
| 请求重试次数 | 3 次 | 应对矿山网络波动导致的连接失败 |

## 容易做错的三处
- 现象：使用数据库连接插件连接PostgreSQL时，界面弹出“工作流校验失败，请检查是否缺失、缺值，连线是否正常”的报错。原因：未在`variables`中传入矿山编号作为关联参数，插件无法匹配对应采区的业务数据表。
- 现象：API对话响应记录预览中Human字段为null。原因：未将用户原始咨询内容配置到`variables`参数中，导致接口未正确传递对话上下文。
- 现象：配置AIPROXY_API_ENDPOINT后调用失败，返回格式错误的响应。原因：未按照FastGPT官方要求的API格式传递参数，混入了矿山采选业务的冗余字段。

## 怎么确认配好了
- 查看接口请求日志，确认`Authorization`参数已正确携带在请求头中。
- 核对`variables`参数是否包含矿山编号、咨询类型等必填业务字段。
- 预览响应数据，确认`responseData`提取的字段与外部系统的业务需求一致。
- 在FastGPT v4.17.0版本的工作流中，发起模拟咨询请求，检查接口返回的答复内容与预期匹配。
