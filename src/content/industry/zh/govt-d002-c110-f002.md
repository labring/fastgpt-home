# 矿山采选的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
数据主要来自地质勘探档案、采矿月度计划、选矿工艺规程、设备运维日志、安全巡检记录与矿权审批文件。地质勘探档案为静态历史数据，采矿计划按月更新，运维与巡检记录每日生成。文档结构包含钻孔编号、矿层厚度、品位、设备型号、处理量、故障描述等字段，单位涉及米、吨、克/吨、小时等专业计量标准。

## 这些特征在「向量模型与索引」这一环带来什么约束
静态历史地质档案占比高，采矿计划按月更新，运维与巡检记录每日生成，不同类型数据更新节奏差异大，要求索引体系支持静态全量索引与增量索引分离的双模式配置。文档包含专业术语与多类型字段，向量模型需适配矿业专属语料与混合字段的向量化需求。单篇文档长度跨度大，从数页安全规程到数十页地质报告，需要灵活的分块适配规则。数据更新触发时机不统一，需配置按数据更新时间自动触发重索引的逻辑。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配矿山采选文档的长度跨度，兼顾专业术语密度与向量化效率 |
| 重叠长度 | 100–150 字符 | 避免专业术语被分块截断，保障上下文连贯性 |
| maxToken | 4096 token | 适配长文档分块后的上下文拼接需求，符合矿业专业文档的信息密度 |
| defaultToken | 1024 token | 作为默认向量化的token上限，平衡单条向量的信息容量与存储成本 |
| 相似度阈值 | 0.72–0.80 | 匹配矿业专业语料的语义相似度分布，过滤低相关性召回结果 |
| 单次搜索上限 | 前10条 | 控制初始召回的结果数量，适配办事咨询场景的信息筛选需求 |

## 容易做错的三处
- 现象：手动上传地质勘探报告后，界面显示索引生成成功，数小时后索引条目为空。原因：未开启索引持久化配置，临时缓存的索引未被写入向量数据库。
- 现象：更换embedding模型后，多语言矿层品位描述的召回结果大幅减少。原因：未对存量知识库文档执行全量重嵌入操作，仅更新了新上传文档的向量化规则。
- 现象：搜索磨矿流程相关问题时，召回结果中出现“磨矿浓度”“浮选药剂”等术语被截断的片段。原因：分块重叠长度设置不足，专业术语被分块截断，无法保留完整上下文信息。

## 怎么确认配好了
- 上传一篇典型的矿山采选文档，查看分块后的文本片段，确认长度与重叠设置符合预期。
- 触发存量文档的全量重嵌入操作，等待任务完成后，检查向量数据库的存储占用，验证向量化配置的存储开销符合预期。
- 发起一条测试咨询，查看初始召回的结果数量，确认单次搜索上限的设置生效。
- 等待数小时后检查索引状态，确认索引未自动消失，验证持久化配置是否正常。
