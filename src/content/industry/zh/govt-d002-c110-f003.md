# 矿山采选的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
矿山采选的业务数据来源涵盖矿山地测部门的电子勘探档案、选矿厂DCS系统运行日志、生产作业台账及安全巡检记录。基础地质勘探数据按季度更新，生产作业台账每日更新，巡检记录每8小时更新一次。文档结构分为两类：结构化数据表包含作业区编号、设备编号、处理量、作业时间等字段，单位涵盖吨/小时、小时等；非结构化文档为PDF格式的安全规程、作业指导书，单篇篇幅可达数万字符。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
结构化字段多且单位多样，要求多轮对话中需跟踪上下文关联的字段信息，避免参数匹配错误。非结构化文档篇幅较长，要求提示词需限定检索范围，避免冗余信息干扰生成结果。数据更新频率存在差异，要求提示词中明确指定数据集的更新时间范围，确保引用的是最新业务数据。分散的数据源要求多轮对话中需引导用户明确查询的业务类型，缩小检索范围，提升查询精准度。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 矿山采选的业务文档及结构化数据拼接后长度较大，需覆盖多轮对话的历史上下文 |
| `variables`绑定规则 | 按当前作业区实时同步 | 生产数据随作业班次更新，需确保引用的变量为最新状态 |
| 对话历史存储时长 | 30天 | 矿山采选业务的追溯周期通常为月度，需保留足够历史对话用于问题复盘 |
| 提示词模板校验开关 | 开启 | 需确保提示词中包含的业务字段与系统内的字段命名完全一致 |
| `messages`上下文截断阈值 | 保留最近10轮对话 | 避免过多历史信息导致上下文溢出，同时覆盖近期业务场景 |

## 容易做错的三处
- 现象：修改提示词为变量引用后，温度设置按钮消失，无法调整生成参数。原因：未在`variables`配置中开启参数自定义权限，导致系统隐藏非必要设置项。
- 现象：调用接口工作流后，对话日志中的运行数据为空。原因：未在`chatId`配置中绑定对话上下文标识，导致系统无法关联调用日志与对应对话。
- 现象：在文本内容提取模块的提示词中传入代码块参数，完整响应显示代码块为未定义。原因：未在提示词中明确指定代码块的解析规则，导致系统无法识别传入的代码块格式。

## 怎么确认配好了
- 发起多轮对话，输入包含业务字段的查询，核对返回结果是否关联了最新的生产数据。
- 查看`variables`配置项，确认所有引用的业务字段均已绑定到当前作业区的实时数据。
- 检查对话日志，确认每一轮对话的`messages`均被正确存储且未被意外截断。
- 触发文本内容提取操作，核对提取结果是否与输入的代码块格式匹配。
