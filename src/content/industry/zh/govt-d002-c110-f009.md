# 矿山采选的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
矿山采选的业务数据主要来源于地质勘探报告、生产运行台账、选矿流程参数记录、安全监管工单及办事咨询档案。地质勘探报告包含钻孔编号、矿石品位、开采深度等字段，单位为米、克/吨；生产台账记录班次、设备运行时长、选矿回收率等内容。数据更新节奏因类型而异：生产台账每日更新，地质报告随勘探进度阶段性更新，办事咨询档案实时新增。文档结构差异明显，长文本报告多为结构化段落，工单与台账则为键值对格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
矿山采选数据的多类型、长文本特征，要求模型接入时需适配不同格式的文档解析。实时更新的办事咨询档案，要求模型调用延迟控制在合理区间，避免影响咨询答复效率。不同文档的字段单位与专业术语差异大，需确保模型能准确识别并关联对应参数，因此配置时需限制上下文长度以避免无关信息干扰。此外，国央企场景下的数据安全要求，需优先选择私有部署或本地接入的模型渠道，限制外部数据流转。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配矿山采选长文档的引用需求，容纳多段地质报告与生产台账内容 |
| `maxTokens` | 4000 token | 控制办事咨询答复的输出长度，确保信息简洁且覆盖核心诉求 |
| `quoteMaxToken` | 1500 字符 | 匹配矿山采选文档的长片段特征，避免关键参数被截断 |
| `temperature` | 0.3–0.5 | 保持专业答复的严谨性，降低虚构专业数据的概率 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配国央企私有部署需求，支持自定义协议与本地模型接入 |

## 容易做错的三处
- 界面中模型选择下拉框持续跳动，原因是未固定`toolChoice`参数，导致系统反复切换可用模型匹配规则。
- 知识库召回结果条数不符合预期，原因是未正确配置`quoteMaxToken`，导致长文档片段被截断无法完整匹配咨询关键词。
- 本地私有模型接入后协议类型无法自定义，原因是未通过`AIPROXY_API_ENDPOINT`配置私有协议，误用了平台默认的固定协议格式。

## 怎么确认配好了
- 发起一条包含矿山开采深度、矿石品位的咨询，检查答复中引用的文档片段是否包含正确的字段与单位。
- 查看模型调用日志，确认`maxContext`参数未触发上下文截断报错。
- 测试本地私有模型接入，验证答复内容与私有模型的输出格式一致。
- 模拟高频办事咨询请求，检查系统响应延迟符合业务预期。
