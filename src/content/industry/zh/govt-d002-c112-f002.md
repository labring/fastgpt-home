# 粮食储备的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
粮食储备的业务数据来源包括储备粮库存台账、轮换计划文件、质量检测报告、出入库记录与行业政策通知。日常出入库数据实时更新，轮换计划与政策文件按季度或年度同步更新。结构化数据多为Excel格式，包含粮食品类、存储库点、库存数量、入库时间、质检等级等字段，单位以吨、千克为主；非结构化数据多为PDF或Word格式，篇幅跨度较大。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化台账的字段关联要求分块不能破坏行与表头的绑定关系，否则会导致搜索结果出现数据错位；非结构化政策文件与质检报告的长度跨度大，需适配向量模型的token输入限制，避免长文本生成向量失败。实时更新的出入库数据要求索引支持增量更新，否则无法满足办事咨询的实时性需求。海量台账数据的分块颗粒度需匹配业务查询的精准度，颗粒度过大则消耗过多计算资源，颗粒度过细则会导致语义关联断裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配粮食储备政策文件、质检报告的常见段落长度，避免单块超出`maxToken`限制 |
| 重叠长度 | 100–150 字符 | 保留跨分块的上下文关联，确保政策条款、质检数据的完整语义 |
| `defaultToken` | 8192 | 适配主流开源嵌入模型的最大输入token数，匹配粮食储备文档的常见长度 |
| 相似度阈值 | 0.72–0.80 按实测标定 | 区分储备粮库存精准查询与政策咨询模糊匹配的场景需求 |
| 单次搜索上限 | 前10条 | 控制办事咨询返回的结果数量，避免信息过载影响决策 |
| `maxToken` | 2048–4096 | 适配粮食储备长文本文档的分块后长度，避免向量生成失败 |

## 容易做错的三处
- 现象：添加Qwen/Qwen3-Embedding-8B模型后，原有同名称模型配置被覆盖，界面仅显示最新一条配置。原因：系统以模型名称作为唯一配置标识，未支持多实例的重命名管理。
- 现象：导入10000+行的粮食储备Excel台账后，搜索结果出现跨行数据错位，字段关联断裂。原因：未开启结构化表格的按行绑定分块规则，默认按字符长度分块破坏了业务数据的完整性。
- 现象：处理超过2000字符的粮食质检报告生成分块向量时，系统返回参数超限提示。原因：未调整`maxToken`配置以适配长文本长度，沿用了默认的小token限制。

## 怎么确认配好了
- 上传单份粮食储备政策PDF，在FastGPT v4.17.0的分块预览界面中，确认分块长度符合预设的800–1200字符范围，重叠部分保留完整的条款衔接。
- 导入测试用的Excel台账，检查分块预览中是否保留了每行数据与对应表头的关联，未出现跨行拆分的情况。
- 新增Qwen/Qwen3-Embedding-8B模型配置后，查看模型列表，确认可同时显示多个不同名称的嵌入模型配置，无覆盖情况。
- 发起模拟办事咨询，查看召回结果的数量是否符合单次搜索上限的设置，相似度得分分布符合预设阈值区间。
