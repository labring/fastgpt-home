# 粮食储备的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
粮食储备的办事咨询数据主要来自国家及地方粮食和物资储备管理部门的公开台账、储备库日常运营记录与政策文件。数据更新节奏为月度更新库存明细、季度更新储备管理政策，年度更新整体储备规划。文档结构分为三类：库存明细文档包含仓号、粮食品种、存储重量、存储年限等字段；政策文档包含储备轮换规则、安全存储标准等内容；应急调度文档包含调运流程、应急响应要求。字段单位统一为吨、千克、年，部分文档附带仓房编号与粮食品种的标准化编码。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
粮食储备数据的专业术语多、字段细分明确且更新频率不均，对多轮对话与提示词配置带来多重约束。首先，专业术语如轮换周期、安全水分需要在提示词中明确指定提取规则，避免模型混淆相似表述。其次，库存数据月度更新，多轮对话需限制上下文范围，防止调用过期数据。再者，库存与政策两类数据结构差异大，需要在对话流程中区分检索类型，避免跨类返回无关内容。最后，字段单位的标准化要求提示词需统一返回格式，防止出现单位混用的情况。

## 配置怎么定
本文档基于FastGPT v4.17.0版本配置说明。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 800–1200 字符 | 适配粮食储备单份文档的平均长度，避免超出模型上下文限额 |
| `variables` | 预设「储备品种」「存储仓号」「查询类型」三个变量 | 用于提取用户对话中的核心检索字段，统一参数格式 |
| `messages` | 限制历史对话保留前3轮 | 减少冗余数据干扰，聚焦当前咨询的库存或政策问题 |
| 问题优化 | 开启，按实测标定 | 针对粮食储备的专业术语优化用户提问，提升检索准确性 |
| 单次搜索上限 | 前5条 | 匹配储备数据的单批次更新条目数，避免返回过多无关内容 |
| `chatId` | 绑定当前会话ID | 确保跨轮对话的上下文与变量持久化 |
| 会话超时时间 | 600 秒 | 避免长对话导致资源占用过高 |

## 容易做错的三处
- 调用时出现Cannot read properties of null (reading 'q) 报错，原因是未正确配置`messages`参数的历史对话格式，导致系统无法识别用户提问字段。
- 问题分类模型识别准确率低，原因是未针对粮食储备的专业术语调整提示词，通用模型无法匹配细分场景的提问类型。
- 全局变量无法跨轮保持，原因是未正确绑定`chatId`参数到当前会话，导致每次对话重新初始化变量。

## 怎么确认配好了
- 发起模拟咨询，输入“查询XX储备库的小麦库存”，检查返回结果中是否包含预设的`variables`字段内容。
- 连续发起3轮相关咨询，检查全局变量是否保留了上一轮指定的储备库名称。
- 查看对话日志，确认`messages`参数仅保留了最近3轮历史对话，无冗余内容。
- 测试专业术语提问，如“轮换周期”，检查优化后的检索结果是否匹配储备管理相关文档。
