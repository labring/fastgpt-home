# 粮食储备的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
粮食储备的业务数据来源于内部管理系统的结构化报表、仓点巡检日志、批次质检记录与轮换计划文档。核心结构化数据包含仓号、存储品类、存储量、入库时间等字段，存储量单位为吨，入库时间为标准日期格式。非结构化文档多为单篇数千字符的巡检记录与应急处置档案。库存核心数据每日更新，批次质检报告随粮食入库同步生成，轮换计划按季度更新。

## 这些特征在「模型接入与配置」这一环带来什么约束
粮食储备数据的多类型、多更新节奏特征，对模型接入配置带来多重约束。结构化字段多且带明确单位，要求模型调用工具时需准确匹配字段名与单位规则；非结构化巡检记录篇幅较长，要求配置合理的上下文截断与切片参数；数据更新频率差异大，要求适配不同数据源的同步周期；办事咨询常涉及跨仓跨品类的关联查询，要求模型可自动识别需调用的工具类型。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 粮食储备数据包含多仓库存、巡检记录，总上下文长度需覆盖单批次查询的全量关联数据，避免截断关键信息 |
| `maxTokens` | `2000–3000 token` | 办事咨询答复需包含具体库存数值、处置流程，输出长度需满足详细说明需求，同时避免超出模型上限 |
| `quoteMaxToken` | `1500 token` | 需引用的质检报告、轮换计划文档篇幅适中，限制引用token可避免冗余信息干扰模型生成 |
| `toolChoice` | `auto` | 办事咨询需自由识别调用库存查询、数据统计工具，自动模式可适配不同类型的咨询场景 |
| `temperature` | `0.3–0.5` | 办事咨询需准确输出库存数值、流程步骤，较低温度可提升答复的稳定性与准确性 |
| `AIPROXY_API_TOKEN` | `按接入平台生成的专属访问密钥` | 用于身份验证，需严格匹配对应平台的密钥规则 |

## 容易做错的三处
- 现象：调用阿里百炼通义千问-Max时返回401状态码，原因：未正确配置`AIPROXY_API_TOKEN`，或密钥与接入平台不匹配。
- 现象：对话中上传的巡检日志文档超出模型上下文长度后，答复出现关键信息缺失，原因：未调整`maxContext`参数适配长文档，或未开启自动切片配置。
- 现象：调用工具后返回的存储量单位错误，原因：未在配置中明确要求模型匹配粮食储备的单位规则，或`toolChoice`未开启结构化字段校验。

## 怎么确认配好了
- 向测试账号发起包含单仓库存查询的咨询，核对答复中是否准确返回对应仓号、存储量与单位。
- 上传一份篇幅较长的巡检日志文档，发起咨询，核对模型是否能完整提取关键处置信息，未出现截断。
- 查看FastGPT v4.17.0的模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的请求已成功发送，无报错。
- 调整`temperature`参数至0.7，发起两次重复咨询，核对答复是否出现小幅波动，确认参数生效。
