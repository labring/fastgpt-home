# 船舶制造的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
船舶制造领域的办事咨询数据主要来源于企业内部办事流程手册、船舶检验规范文档、订单咨询工单归档、船员办事指南四类。数据更新节奏随船检政策调整与订单变动波动，无固定周期。单份文档多为分章节结构，包含办事事项编号、办理时限、所需材料清单、咨询回复模板等字段，单位多采用工作日、吨位、米等船舶制造专属计量标准，部分文档包含多页技术附件。

## 这些特征在「模型接入与配置」这一环带来什么约束
船舶制造办事咨询数据的长文档结构与专属专业术语，要求模型上下文窗口需适配长内容容纳需求，避免截断关键规范信息。数据更新无固定周期，需定期同步最新的船检政策与办事流程，对应配置需支持快速更新接入的模型数据源。办事咨询的严谨性要求，需限制模型生成的自由度，避免专业术语误用。同时，数据中明确的事项编号与分类字段，要求模型召回时需精准匹配对应办事场景的文档内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 船舶制造办事咨询文档常包含长流程规范与多页申请材料，需容纳完整上下文以覆盖全部关联信息 |
| `temperature` | 0.2–0.4 | 办事咨询需严谨统一的答复风格，避免专业术语偏差，适配船舶制造场景的合规性要求 |
| `maxTokens` | 2000 token | 单条咨询答复需控制在合规长度，匹配办事场景的信息密度与用户阅读习惯 |
| `quoteMaxToken` | 1500 token | 优先引用船舶制造专属的办事规范文档，限制引用内容长度以保证核心信息突出 |
| `toolChoice` | "auto" | 自动判断是否需要调用工具查询实时办事进度或船检政策更新 |
| `AIPROXY_API_ENDPOINT` | 按企业专属接入地址填写 | 适配船舶制造场景的合规数据调用路径，确保数据来源符合行业监管要求 |

## 容易做错的三处
- 现象：调用模型时返回“该令牌无权使用模型：text-embedding-3-large”报错。原因：未在FastGPT中配置专属的船舶制造场景模型接入密钥，或密钥权限未覆盖对应行业专属模型。
- 现象：配置bce-embedding渠道后仍提示无可用渠道。原因：未将船舶制造专属的embedding模型添加到FastGPT的允许模型列表中，或渠道配置未绑定对应数据源。
- 现象：创建应用时无法勾选结果重排的模型选项。原因：未在config.js中正确配置重排模型的可调用范围，或配置项格式不符合FastGPT v4.17.0的要求。

## 怎么确认配好了
- 检查`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的填写是否与企业接入的模型服务一致，无拼写或格式错误。
- 发起一条船舶制造办事咨询的测试请求，查看返回结果是否引用了专属的办事规范文档，确认上下文召回范围符合预期。
- 调整`temperature`参数取值，验证答复的专业术语一致性是否符合预期，确认生成风格适配场景需求。
- 触发工具调用测试，确认系统能自动判断是否需要查询实时办事进度，验证`toolChoice`配置生效。
