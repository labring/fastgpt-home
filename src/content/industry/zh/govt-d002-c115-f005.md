# 轨道交通装备的办事咨询与答复：工具调用与插件

## 这个品类的数据长什么样
轨道交通装备的办事咨询数据主要来自出厂维护手册、在役设备运行台账、行业合规标准文档。数据更新节奏为单台设备随运维周期同步，批量设备按季度批量更新。文档结构按设备型号分类，包含设备编号、运行时长、故障代码、处置流程、合规要求等字段，运行时长单位为小时，故障等级为枚举值，处置时效单位为天，整体文档结构层级清晰，字段与单台设备绑定紧密。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于轨道交通装备数据字段与单台设备绑定紧密，工具调用时必须传入准确的设备编号作为必选参数，无法通过模糊关键词直接匹配对应数据。由于数据按运维周期或季度更新，插件需配置定时拉取机制，避免使用过期的静态缓存数据。由于包含合规要求字段，工具调用需额外校验返回的合规内容是否匹配咨询场景的适用范围，同时文档层级较多，需在插件配置中明确指定提取指定层级的字段内容，避免返回冗余信息。

## 配置怎么定
本文适配 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 自动匹配指定工具 | 轨道交通装备咨询需调用设备数据、合规文档等不同接口，自动匹配可减少配置复杂度 |
| 插件超时时间 | 300–600 秒 | 轨道交通装备数据接口响应受网络、设备状态影响，该区间可覆盖多数查询场景 |
| `functionCall` | 开启参数格式校验 | 确保传入的设备编号、故障代码等参数符合要求，避免无效调用 |
| 工具返回条数上限 | 前 3 条 | 单台轨道交通装备的关联数据条目通常有限，过多返回会增加上下文处理负担 |
| 缓存时长 | 7 天 | 在役设备数据按季度更新，7天缓存可平衡数据时效性与调用效率 |

## 容易做错的三处
- 现象：调用自定义插件查询轨道交通装备数据时返回「参数不匹配」报错，原因：未在配置中指定设备编号作为必传参数，导致接口无法匹配对应设备数据。
- 现象：工具调用后返回字段为空，原因：未开启`functionCall`参数校验，传入了不符合格式的故障代码或设备编号。
- 现象：插件调用超时，原因：未设置合理的超时时间，使用了过短的默认时长，无法覆盖轨道交通装备数据接口的正常响应周期。

## 怎么确认配好了
- 发起针对单台轨道交通设备的咨询，核对工具是否调用了匹配的外部接口。
- 查看工具调用日志，确认传入的参数格式符合预设规则。
- 检查返回结果的字段是否与轨道交通装备数据的标准结构一致，仅包含目标内容。
- 等待缓存更新周期后再次发起咨询，确认数据已同步最新的运维或合规信息。
