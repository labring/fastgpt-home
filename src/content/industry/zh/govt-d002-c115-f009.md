# 轨道交通装备的办事咨询与答复：模型接入与配置

## 这个品类的数据长什么样
轨道交通装备办事咨询与答复的数据主要来自官方运维手册、设备台账、检修规程、行业办事流程文件。数据来源覆盖列车、信号机、道岔等核心装备的技术参数、故障处置步骤、报修流程。更新节奏随装备运维记录、行业标准修订调整，无固定周期但单次更新量较大。文档结构多包含装备型号、故障代码、处置步骤、责任部门、联系渠道等字段，字段单位多为公里、小时、次等工程常用单位，部分文档包含结构化表格数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
轨道交通装备数据的长文档特性要求模型上下文配置需适配较大的内容量，避免截断关键技术参数或标准化处置步骤。多字段结构化数据要求检索匹配时优先匹配装备型号、故障代码等精准字段，降低模糊匹配带来的误差。非固定更新周期要求配置数据同步机制适配增量更新逻辑，避免全量同步占用过多系统资源。办事咨询涉及行车安全类内容，要求模型输出严格匹配文档中的官方表述，避免生成未经确认的处置方案。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配轨道交通长文档的上下文需求，覆盖完整的设备台账与检修流程内容 |
| `maxTokens` | 2000–3000 token | 控制办事咨询答复的长度，确保步骤清晰且不冗余 |
| `temperature` | 0.2–0.4 | 降低生成随机性，保障办事答复的准确性与规范性 |
| `quoteMaxToken` | 1500 token | 限制引用文档的长度，优先保留核心处置步骤与参数信息 |
| `toolChoice` | auto | 自动匹配知识库或工具，适配不同类型的办事咨询需求 |
| `AIPROXY_API_ENDPOINT` | 按专属部署地址填写 | 适配轨道交通装备的专属数据传输需求，保障调用链路安全 |
| `AIPROXY_API_TOKEN` | 按专属密钥填写 | 保障数据传输与调用的安全性，适配轨道交通装备的专属数据要求 |

## 容易做错的三处
- 现象：升级至FastGPT v4.17.0后，简易应用出现未捕获异常，日志显示上下文长度超限。原因：未针对轨道交通长文档调整`maxContext`参数，默认配置的上下文长度不足以覆盖完整的设备台账数据。
- 现象：模型设置禁用思考输出，但答复仍包含think标签。原因：未在系统提示词中明确要求隐藏思考过程，或`temperature`参数设置过高导致生成逻辑偏离预设配置。
- 现象：工作流的问题分类模块无法匹配到知识库中的设备故障分类，检索结果为空。原因：未将知识库的故障代码、装备型号字段配置为检索匹配的优先字段，导致数据来源与问题分类的匹配逻辑不匹配。

## 怎么确认配好了
- 使用FastGPT v4.17.0的测试环境，上传一份轨道交通检修规程文档，发起“如何处理XX型号列车的制动故障”咨询，检查答复中是否准确引用了文档中的处置步骤与参数。
- 查看模型输出内容，确认未包含think标签，验证思考输出的禁用配置生效。
- 测试报修流程、设备参数查询等不同类型的办事咨询，确认`toolChoice`自动匹配对应知识库模块。
- 调用API接口测试，检查日志中是否显示`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无认证报错。
