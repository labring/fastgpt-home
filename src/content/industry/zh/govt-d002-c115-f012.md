# 轨道交通装备的办事咨询与答复：部署与升级

## 这个品类的数据长什么样
轨道交通装备办事咨询与答复的数据，主要来源于现场运维工单、客户服务咨询记录、设备技术手册及运维台账。数据更新节奏随业务场景变化，日常咨询实时录入，技术类文档按季度同步更新。单条数据包含设备型号、故障现象、咨询时间、答复内容、处理结果等字段，字段单位涵盖台、小时、次等，部分文档包含设备参数图表，单页文档长度可达数千字符。

## 这些特征在「部署与升级」这一环带来什么约束
轨道交通装备的咨询数据包含长文本技术文档与结构化工单，部署时需适配大体积数据的存储与检索需求。实时更新的日常咨询内容，要求部署环节配置稳定的同步链路，避免数据延迟。多字段的结构化数据需兼容不同格式的导入，升级时需保留原有字段映射规则，避免业务数据丢失。内网部署场景下，需确保内部用户的访问权限与数据隔离，同时适配反向代理的HTTPS配置，保障访问安全。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150` | 适配轨道交通装备多工单并发的数据库连接需求，避免连接耗尽 |
| `REDIS_URL` | `内网Redis服务地址，连接超时设为60秒` | 缓存高频咨询的检索结果，降低数据库压力，适配内网部署的安全要求 |
| `STORAGE_S3_ENDPOINT` | `内网对象存储服务地址，如192.168.1.100:9000` | 存储轨道交通装备的长文档技术资料与工单附件，保障内网数据存储合规 |
| `FE_DOMAIN` | `内网访问域名，如https://rail-equip.enterprise.local` | 配置反向代理后的访问地址，保障内部用户的HTTPS访问链路正常 |
| `FILE_TOKEN_KEY` | `随机生成的32位字符串` | 加密文件上传的令牌，避免未授权访问轨道交通装备的技术文档附件 |

## 容易做错的三处
- 现象：渠道模型列表仅显示重排模型，无法选择其他语言模型。原因：未配置`ROOT_KEY`权限，或商业版授权未绑定对应语言模型的使用权限。
- 现象：配置渠道后无法连接本地ollama模型，聊天框显示模型不存在。原因：容器网络未与本地ollama服务打通，或`FE_DOMAIN`配置的内网访问地址未覆盖ollama服务的本地请求链路。
- 现象：群辉Docker部署时容器启动失败，日志提示数据库连接错误。原因：`PG_URL`或`MONGODB_URI`配置的内网数据库地址未添加容器网络访问白名单，或数据库版本与FastGPT v4.17.0不兼容。

## 怎么确认配好了
- 访问`FE_DOMAIN`配置的内网地址，确认页面可以正常加载，无证书或域名解析错误。
- 上传一份轨道交通装备的技术文档，确认文件可以正常存储并在聊天框中调用检索。
- 进入渠道管理页面，确认所需的语言模型与重排模型均显示在可选列表中，可正常保存配置。
- 发起一条模拟咨询，确认系统可以返回匹配的轨道交通装备运维答复内容，无数据延迟或报错。
