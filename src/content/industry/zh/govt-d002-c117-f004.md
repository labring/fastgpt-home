# 通信铁塔与基础设施的办事咨询与答复：工作流编排

## 这个品类的数据长什么样
通信铁塔与基础设施的核心数据来自运维管理平台，包含基站基础档案、巡检记录、故障工单、塔体参数等模块。更新节奏为：基础档案每月同步更新，实时巡检数据每日更新，故障工单实时录入。文档结构为结构化表格形式，字段包含基站唯一标识、经纬度坐标、塔体高度、维护周期、故障类型、处理进度，单位分别为无、度、米、天、类、次。数据格式统一为结构化JSON或CSV，无大量非结构化文本内容。

## 这些特征在「工作流编排」这一环带来什么约束
结构化数据占比高，要求工作流节点间的参数传递必须严格匹配字段名，避免参数错位导致的咨询结果错误。数据更新频率存在差异，实时工单数据需要工作流触发时拉取最新数据，不能依赖固定缓存，否则会导致答复内容滞后。字段单位固定，工作流生成的答复内容需严格遵循预设单位，不能随意转换，否则会影响咨询准确性。单条数据量较小但条目较多，工作流的单次数据拉取上限需适配品类的数据分页规则，避免遗漏关键信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| variables | 绑定基站ID、巡检记录ID、故障工单编号 | 匹配通信铁塔品类的核心查询维度，确保调用数据的精准性 |
| nodeId | 按数据来源节点分配固定nodeId | 确保工作流中不同数据调用节点的唯一性，避免节点冲突 |
| 单次数据拉取上限 | 前20条 | 适配通信铁塔运维平台的单页数据展示上限，避免返回冗余内容 |
| 数据缓存时长 | 3600 秒 | 平衡实时性与调用效率，满足运维数据的更新节奏要求 |
| 导出文档格式配置 | 仅保留结构化字段与咨询摘要 | 贴合用户咨询的核心需求，避免非必要内容占用下载资源 |
| 模型输入上下文限制 | 8000 token | 适配本地部署模型的上下文窗口，避免输入溢出 |

## 容易做错的三处
-  工作流生成的咨询答复底部无导出word下载链接，原因是未在`variables`中配置导出格式变量，未绑定文档生成节点。
-  迁移旧版本工作流后出现节点ID不匹配报错，原因是未保留原工作流的`nodeId`配置，直接复制节点导致ID冲突。
-  调用本地QWQ-32B模型时，上传附件后无总结结果，原因是工作流中未配置附件解析节点，直接将原始附件传入模型节点，未完成格式转换。

## 怎么确认配好了
-  在FastGPT v4.17.0版本的工作流编辑器中，查看`variables`配置项，确认绑定了基站ID、巡检记录ID等品类专属字段。
-  触发测试会话，输入包含具体基站标识的咨询问题，检查返回结果是否包含对应字段的准确数据。
-  测试导出功能，确认生成的文档包含咨询所需的结构化内容与下载链接。
-  检查节点ID配置，确认每个数据调用节点的`nodeId`与预设值一致，无重复或冲突。
