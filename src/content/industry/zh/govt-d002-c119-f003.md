# 钢铁冶炼的办事咨询与答复：多轮对话与提示词

## 这个品类的数据长什么样
钢铁冶炼办事咨询与答复的数据主要来自企业内部冶炼工艺规程、设备运维工单、政务办事指南及历史咨询记录。数据更新节奏为工艺规程每季度同步，办事指南每月更新，历史咨询记录实时归档。文档多为结构化表格与段落结合的格式，包含工序编号、工艺温度、办理时限、所需材料清单等字段，单位多采用摄氏度、小时、工作日等行业通用标准。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
结构化表格与带单位字段的存在，要求多轮对话需保留上下文字段信息，避免重复询问工艺温度、办理时限等带单位的参数。分散的多源数据需要整合，要求对话上下文窗口需适配长文本段落与表格内容。办事流程的多步骤特性，要求多轮对话按既定流程逐步引导，不跳过关键环节。历史咨询记录的体量要求提示词需调用相似过往答复，确保答复符合企业内部规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前会话标识 | 保证多轮对话的上下文归属唯一 |
| `messages` | 按会话顺序存储消息序列 | 完整保留多轮对话的上下文信息 |
| `variables` | 存储临时工艺参数与办事进度 | 需适配FastGPT v4.17.0的变量管理逻辑，适配钢铁冶炼咨询的临时变量需求 |
| 分块长度 | 800–1200 字符 | 适配钢铁冶炼工艺规程与办事指南的段落长度 |
| 最大上下文窗口 | 4000–6000 token | 整合多源文档时保留完整的办事流程与专业参数 |
| 上下文保留时长 | 3600 秒 | 适配多数办事咨询的会话周期 |

## 容易做错的三处
- 现象：对话中上传附件时提示`fail to create post presigned url`，或RAG上传文件失败，模板导入功能可正常上传。原因：FastGPT v4.14.3及以上版本中，S3存储配置的跨域规则未适配文件上传路由，或接口路径绑定错误，导致无法生成预签名链接。
- 现象：多轮对话中工艺参数的单位出现混淆，比如温度被误写为华氏度。原因：提示词未明确要求保留字段单位，或上下文窗口未完整保留单位信息。
- 现象：对话召回的历史咨询记录与当前问题不匹配，结果条数超出预期。原因：单次召回上限配置不合理，或分块长度未适配文档结构导致召回精度下降。

## 怎么确认配好了
- 发起一条包含工艺参数的咨询，核对对话上下文是否完整保留了字段信息。
- 上传一份典型的钢铁冶炼办事指南文档，检查分块后的内容是否完整无截断。
- 发起多轮咨询，逐步询问办事流程的不同环节，确认对话未丢失上下文信息。
- 测试文件上传功能，核对上传报错与配置的存储规则是否一致。
