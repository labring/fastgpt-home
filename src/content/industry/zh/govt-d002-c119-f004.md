# 钢铁冶炼的办事咨询与答复：工作流编排
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
钢铁冶炼办事咨询与答复的数据主要来自生产工序台账、设备点检记录、质量异议工单、在线咨询会话四类来源。数据更新节奏分为实时（设备异常咨询、在线会话）、每日（工序台账更新）、每周（质量统计报表）三类。单条数据的文档结构包含咨询唯一标识、咨询发起时间、所属冶炼工序（转炉、连铸、热轧等枚举值）、咨询内容、答复内容、处理人、处理时长等字段，其中处理时长单位为分钟，工序名称为固定枚举字符串，咨询内容长度跨度较大。

## 这些特征在「工作流编排」这一环带来什么约束
多来源异构数据要求工作流配置跨数据源的拉取节点，需将不同系统的字段映射为统一格式；不同更新节奏的数据需要区分触发方式，实时数据需配置按间隔轮询或webhook触发，批量数据需配置定时执行；枚举型工序字段要求工作流增加校验节点，过滤非目标工序的咨询，避免无效处理；咨询内容长度差异大，要求工作流配置上下文截断规则，适配不同长度的输入。同时，`variables`变量的映射需要覆盖多源数据的字段，`nodeId`对应的节点需匹配对应数据的更新周期，确保流程执行的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按实时工单触发 + 每日批量补全 | 适配实时咨询与批量台账数据的更新节奏 |
| 变量映射规则 | 绑定生产系统、工单系统字段到`variables` | 统一多源异构数据的字段格式 |
| 节点执行周期 | 实时节点10秒轮询，批量节点每日2点执行 | 匹配数据的实时、批量更新频率 |
| 上下文截断阈值 | 800–1200 字符 | 适配钢铁冶炼咨询内容的长度跨度 |
| 字段校验规则 | 匹配转炉、连铸等枚举工序值 | 过滤非目标工序的无效咨询 |
| 结果输出格式 | 按咨询编号+工序+处理时长的结构化输出 | 满足办事答复的可追溯要求 |

## 容易做错的三处
- 现象：工作流执行后出现重复的办事工单，日志显示重复触发节点。原因：未在工具调用流程末尾配置终止节点，导致`nodeId`对应的流程循环执行。
- 现象：判断知识库为空时返回通用答复，无法匹配冶炼工序的咨询场景。原因：仅使用通用判断器校验知识库状态，未结合`variables`中的工序字段做关联校验。
- 现象：HTTP自定义接口调用返回参数错误，接口返回400状态码。原因：未将工作流中的`variables`变量正确映射为接口要求的入参字段，导致传递的参数格式不符合接口规范。

## 怎么确认配好了
- 触发一条模拟的转炉工序咨询工单，查看工作流日志，确认`variables`变量正确映射了生产系统和工单系统的字段。
- 进入节点执行记录页面，检查实时节点是否按10秒轮询执行，批量节点是否在每日2点触发。
- 模拟空知识库场景，结合指定冶炼工序的咨询，查看判断节点是否正确返回关联校验后的结果。
- 调用测试HTTP接口，确认工作流传递的入参包含所有配置的`variables`字段，格式符合接口要求。
