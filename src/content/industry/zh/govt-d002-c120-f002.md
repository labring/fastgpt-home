# 铁路运营的办事咨询与答复：向量模型与索引

## 这个品类的数据长什么样
铁路运营办事咨询与答复的数据来源包括铁路官方办事指南、12306客服历史对话库、车站窗口咨询记录、列车运行调整公告、票务退改签规则文档。更新节奏分为三类：运行调整、晚点通知为实时更新，客服常见问答库每周更新，票务规则与办事流程文档每月更新。文档结构包含短文本问答与长文档指南两类，字段包含咨询分类、问题原文、标准答案、生效时间、适用车站或车次范围，单位涉及车次号、车站名、时间、金额。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时更新的运行调整与晚点通知数据，要求索引支持增量同步，避免全量重建占用过多资源；短文本占比高的咨询问答，需避免过度分块导致语义断裂；带适用范围的字段，要求索引支持按车次、车站维度过滤召回，提升检索精准度；长文档类的服务指南，需要设置合理的分块长度以保留上下文完整性；不同更新节奏的数据源，需配置差异化的索引刷新周期，兼顾实时性与资源消耗。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 铁路办事咨询包含短文本问答与长文档指南，该区间可兼顾语义完整性与检索效率 |
| 重叠长度 | 100–150 字符 | 避免分块后上下文断裂，适配跨分块的语义关联需求 |
| `maxToken` | 4096 token | 适配通用向量模型的输入上限，覆盖多数长文档分块的内容长度 |
| 相似度阈值 | 0.72–0.78 | 铁路咨询问题语义区分度较高，该区间可减少误召回与漏召回 |
| 单次搜索上限 | 前 8 条 | 办事咨询的标准答案通常集中在少量结果内，过多结果会增加判断成本 |
| `defaultToken` | 2048 token | 控制检索返回的上下文总长度，适配大模型的输出上下文限制 |

## 容易做错的三处
- 检索调试面板无索引参数编辑按钮，需进入知识库内容管理页修改。原因是FastGPT v4.17.0将索引配置入口迁移至知识库详情页，未保留检索面板的快捷编辑入口。
- 本地部署版本中未显示图片索引模型选项。原因是图片索引功能需依赖额外的商业版插件，开源版本未内置该模块。
- 配置`maxToken`超出对应向量模型的实际上限后，出现检索超时或结果为空。原因是未匹配向量模型的输入token限制，导致分块内容无法被正常处理。

## 怎么确认配好了
- 上传一条测试用的铁路办事咨询文档，查看分块预览是否符合设定的分块长度与重叠长度。
- 输入模拟的办事咨询问题，查看检索结果的相似度分值是否落在预先设定的阈值区间内。
- 调整知识库的索引配置后，触发增量索引更新，等待任务完成后验证检索结果是否同步更新。
- 查看向量模型的调用日志，确认返回的上下文token数未超出`maxToken`的设定值。
