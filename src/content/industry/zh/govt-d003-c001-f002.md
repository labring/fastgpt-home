# 12345热线工单办理的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自12345热线平台、承办单位业务系统、知识库及回访评价数据，更新频率为每日。日常文档包含诉求登记单、派单记录、办理答复、回访记录、延期申请等，每条数据包含诉求编号、群众诉求内容、办理时限、责任单位、答复内容、回访结果等字段，各文档通过诉求编号形成关联闭环，存在结构化与非结构化混合的内容形式。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的特性要求索引支持增量刷新，避免全量重建带来的资源消耗；多类型文档与关联字段的存在，要求分块时需保留关键关联信息，避免割裂工单闭环；结构化与非结构化混合的数据，要求索引配置需适配不同格式的内容拆分；台账汇总需关联多环节文档，要求索引支持多文档的关联召回，同时需过滤低关联的冗余内容。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配12345工单单条内容的平均长度，避免分块割裂诉求与办理的关联信息 |
| 重叠长度 | 50–100 字符 | 保留相邻分块的诉求编号等关键字段，确保检索时可还原完整工单上下文 |
| `maxToken` | 4096 token | 适配台账汇总时多文档拼接的长度限制，避免截断关键的答复或回访内容 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 过滤低关联的非目标工单，避免台账汇总时混入无关内容 |
| 单次搜索上限 | 前10条 | 控制检索返回的文档数量，适配台账生成时的信息筛选需求 |
| `defaultToken` | 2048 token | 配置基础检索上下文长度，平衡召回精度与计算资源消耗 |

## 容易做错的三处
- 现象：文档上传时显示分8段，后续变为13段且出现重复条目。原因：未开启索引的去重校验，分块时重复识别了工单内的重复字段，或上传时触发了重复分片逻辑。
- 现象：从4.9.0升级到4.9.3后，原可查询的工单内容无法检索到。原因：升级后索引格式发生变更，未重新生成对应工单的向量索引，旧索引无法被新版本匹配。
- 现象：Excel格式的诉求统计表格上传后，索引内容错乱。原因：未配置结构化数据的分块规则，直接按文本分块导致表格单元格被割裂，丢失行列关联信息。

## 怎么确认配好了
- 上传单条完整的工单文档，查看分块数量与预期一致，无重复分块条目。
- 检索指定工单的关联文档，验证返回结果包含诉求、办理、回访等全环节内容。
- 执行台账汇总任务，检查返回的文档集合无超出设定检索上限的条目。
- 调整相似度阈值后，对比检索结果的关联度变化，确认阈值符合业务筛选需求。
