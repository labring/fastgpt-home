# 12345热线工单办理的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
该品类数据主要来自12345热线平台、承办单位业务系统、政务知识库、回访评价数据及地方热线管理规范。日常处理的文档包含诉求登记单、派单记录、办理答复、回访记录、延期申请、退回说明及知识库条目。数据更新频率为每日，核心字段包含诉求编号、诉求内容、承办单位、办理状态、回访结果等，整体围绕群众诉求闭环流转。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据每日更新的特性要求模型接入环节配置适配日级增量同步的触发逻辑，避免重复处理历史工单。多来源的数据结构差异，要求模型映射环节需匹配不同系统的字段格式，确保诉求编号、承办单位等核心字段准确对应。核心业务围绕诉求闭环，模型需准确关联派单、答复、回访等环节的关联数据，同时需兼容退单重派、延期申请等异常工单的处理逻辑，避免因字段识别错误导致工单超期或答复被退回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 承载多环节工单的完整上下文，避免因上下文不足丢失派单、答复等关键关联信息 |
| `maxTokens` | 2000–3000 token | 确保台账汇总与报告生成的输出完整覆盖所有工单条目，避免关键统计内容被截断 |
| `temperature` | 0.2–0.4 | 保证汇总结果的格式一致性与数据准确性，降低生成无关内容的概率 |
| `toolChoice` | auto | 让模型自主判断是否需要调用知识库或业务接口补充数据，适配异常工单的处理需求 |
| `AIPROXY_API_ENDPOINT` | 对应服务商的官方接入地址 | 确保模型调用链路稳定，适配政务场景的网络访问规范 |
| `AIPROXY_API_TOKEN` | 经权限校验的专属密钥 | 隔离不同业务系统的调用权限，保障工单数据的访问安全 |

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 容易做错的三处
- 现象：模型映射配置提交后，工单的承办单位、诉求状态等核心字段无法正确映射到报告输出项，字段显示为空。原因：配置的映射字段名与12345热线平台导出的实际字段名不一致，未完成字段匹配校验。
- 现象：调用阿里云百炼或本地部署的Ollama模型时触发报错，镜像为当日拉取版本。原因：未正确填写`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或模型服务商的接口访问权限未完成配置。
- 现象：通过FastGPT API对接的业务系统中，不同用户的工单查询记录出现交叉混淆。原因：未为每个业务用户分配独立的调用密钥，未配置会话级别的用户权限隔离。

## 怎么确认配好了
- 导入12345热线平台导出的单日工单样本，运行台账汇总任务，核对报告中的核心字段是否与原始工单数据一致。
- 调用配置完成的模型接口，发起单次测试请求，检查接口返回状态是否正常，无报错信息。
- 为不同测试主体分配独立的调用权限，发起各自的工单查询请求，确认查询结果仅关联对应主体的工单数据。
- 运行包含退单、延期申请等异常工单的测试样本，检查模型是否能正确识别并纳入汇总报告。
