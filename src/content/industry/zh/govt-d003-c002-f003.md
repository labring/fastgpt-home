# “高效办成一件事”联办的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来源于国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库及各部门审批系统，更新频率为每日。日常涉及的文档包括联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见、办结回执。数据字段包含跨部门事项关联关系、申请材料明细、各环节办理状态、办结时限节点等，格式随联办事项类型灵活调整，无统一固定模板。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的数据源要求对话上下文需及时同步最新的联办事项状态，避免台账数据滞后。多部门文档的格式差异要求提示词能适配不同类型的材料流转单、审批意见，准确提取对应字段。跨部门的事项关联关系要求多轮对话中逐步拆解前后置逻辑，防止遗漏关键节点。同时，台账汇总与报告生成需符合政务规范，提示词需明确指定输出格式与字段范围，避免生成不符合要求的内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定业务系统用户ID与联办事项编号 | 区分不同用户的联办台账聊天记录，避免数据混淆 |
| `messages` | 保留最近 15–25 轮对话内容 | 覆盖联办事项从申请到办结的完整交互流程 |
| `variables` | 预设部门清单、联办时限阈值变量 | 动态适配不同跨部门联办事项的规则 |
| 会话上下文缓存时长 | 86400 秒 | 匹配每日更新的数据源同步节奏，保留当日联办全流程数据 |
| 提示词调用规则 | 按联办事项类型加载对应知识库条目 | 确保生成的台账与报告符合对应事项的政务规范 |

*本文基于FastGPT v4.17.0版本进行配置说明*

## 容易做错的三处
- 现象：系统无法启动对话，界面显示API密钥未配置。原因：未在FastGPT系统的密钥管理模块中绑定政务服务专用的API密钥，导致对话链路无法建立。
- 现象：不同窗口人员的联办台账数据混合显示。原因：未配置`chatId`绑定用户与联办事项的唯一标识，导致会话上下文未正确隔离。
- 现象：生成的台账字段缺失或格式不符合政务要求。原因：未将提示词绑定对应联办事项的知识库条目，导致调用的通用提示词无法适配具体联办场景。

## 怎么确认配好了
- 发起一条模拟联办事项对话，使用两个不同的测试用户ID，检查聊天记录是否通过`chatId`正确隔离，无数据交叉情况。
- 触发对话超时测试，确认会话在86400秒内未被自动断开，且保留完整的交互上下文。
- 切换不同联办事项类型，检查提示词是否自动加载对应知识库的规范内容，生成的台账字段符合预设要求。
- 打开新会话窗口，确认无版本更新说明弹窗弹出，验证设置已生效。
