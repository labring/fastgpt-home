# “高效办成一件事”联办的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
这个品类的数据通常来自国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库及各部门审批系统。日常处理的文档包括联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见、办结回执。数据更新节奏为每日更新，核心字段涵盖联办事项唯一标识、跨部门流转节点状态、申请材料清单、各环节办理时长、办结回执编号，无额外自定义统计单位，仅按政务服务通用字段规范存储。

## 这些特征在「数据库与运维」这一环带来什么约束
每日更新的多源异构数据要求数据库支持高并发批量写入与低延迟实时查询，避免联办流程状态更新滞后影响台账汇总。跨部门文档的字段差异，需要数据库支持灵活的schema适配，避免硬编码字段限制多源数据接入。联办事项的跨部门流转需关联多部门的审批数据，需合理设计多表关联结构以减少查询耗时。政务数据的存储需符合属地监管要求，同时需配置冗余机制保障数据可用性，防止单个节点故障影响联办台账生成。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[用户名]:[密码]@[集群地址]:27017/[政务联办文档库]?authSource=admin` | 存储联办过程中的非结构化文档，如一次性告知单、办结回执等，适配政务服务多源异构文档的存储需求 |
| `PG_URL` | `postgresql://[用户名]:[密码]@[集群地址]:5432/[政务联办业务库]?sslmode=require` | 存储结构化的联办事项流转数据、审批意见等，支持复杂关联查询以生成汇总台账 |
| `DB_MAX_LINK` | `50–80` | 适配每日批量数据导入的并发连接需求，避免连接耗尽导致数据导入失败 |
| `REDIS_URL` | `redis://[密码]@[缓存地址]:6379/0` | 缓存高频查询的联办事项清单、办结状态数据，降低数据库查询压力，提升台账生成效率 |

## 容易做错的三处
- 现象：安装数据库连接插件后测试失败，界面提示服务器内部错误。原因：未在`MONGODB_URI`中配置正确的认证源，或数据库集群的防火墙规则限制了27017端口的外部访问。
- 现象：服务启动时提示MongoDB报错，无法完成初始化。原因：数据库连接数超过`DB_MAX_LINK`配置上限，或数据库集群节点状态异常导致连接超时。
- 现象：导出训练完成的文本时无法定位目标租户的存储表。原因：未在连接字符串中指定正确的租户库名，或未配置跨租户数据访问权限。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本内置的数据库连接测试工具，分别验证`MONGODB_URI`与`PG_URL`的连通性，根据测试结果调整连接参数。
- 导入一条测试用的联办事项文档，检查数据是否能正确写入对应库表，字段映射是否符合政务服务通用规范。
- 查看服务运行日志，确认无数据库连接超时、权限报错等异常信息，根据日志提示调整`DB_MAX_LINK`等配置。
- 触发一次联办台账汇总任务，检查任务执行过程中数据库读写操作是否正常，无阻塞或失败情况。
