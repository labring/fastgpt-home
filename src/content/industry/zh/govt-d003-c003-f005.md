# 不动产登记的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
不动产登记相关数据来自不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统、电子证照库，更新频率为日。日常处理的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书、登记簿，核心字段涵盖不动产坐落、权利类型、权利人信息、登记类型等，单位涉及平方米、宗数等，数据结构随登记业务类型变化，需跨系统对齐多源信息。

## 这些特征在「工具调用与插件」这一环带来什么约束
跨多系统的数据来源要求插件需覆盖多个业务系统的调用接口，日更的更新频率要求插件调用需适配实时数据拉取的节奏，避免因超时导致数据未及时同步。多类型文档与专业字段要求插件返回的信息需严格对齐登记业务的必填字段，避免遗漏核心核验内容。出错后果严重的业务属性，要求工具调用环节需增加结果校验与重试机制，保障数据准确性，防止登记错误或产权纠纷。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | auto | 适配多源数据调用不同业务插件，无需手动指定单个工具 |
| 插件调用超时 | 600 秒 | 应对跨系统数据拉取的延迟，避免任务中途中断 |
| 单次插件调用返回条数 | 前 3 条 | 匹配单条不动产登记业务的核心数据量，减少冗余信息干扰 |
| `functionCall` | 开启 | 强制模型按标准格式调用插件，确保台账字段对齐规范 |
| 插件执行失败重试次数 | 2 次 | 应对临时的跨系统连接波动，保障任务顺利完成 |
| 结果校验触发条件 | 必填字段完整性 | 确保生成的报告包含所有不动产登记的必填信息 |

## 容易做错的三处
- 现象：插件编辑界面始终显示“未保存”状态，点击保存按钮后仍未恢复正常。原因：未完成界面必填配置项的填写，导致保存校验未通过，状态未同步更新。
- 现象：接口调用返回`connect ECONNREFUSED 172.23.0.2:3001`错误。原因：目标插件服务未正常启动，或网络策略限制了跨服务通信。
- 现象：生成的台账报告缺少权属来源核验字段。原因：未开启`functionCall`强制格式调用，模型未正确调用权属数据校验插件，导致核心字段遗漏。

## 怎么确认配好了
- 进入FastGPT v4.17.0的插件管理页面，验证所有配置项的取值与预设一致，检查`toolChoice`和`functionCall`的开关状态。
- 发起单条不动产登记业务的测试调用，查看插件返回结果的条数与配置的单次返回条数匹配。
- 模拟跨系统数据延迟场景，验证插件调用超时设置生效，任务在设定时长内触发重试或中断。
- 检查生成的台账报告，确认包含所有预设的不动产登记必填字段，无遗漏。
