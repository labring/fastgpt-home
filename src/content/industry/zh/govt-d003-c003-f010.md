# 不动产登记的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
本品类数据主要来自不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统及电子证照库，更新频率为每日。日常处理的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书与不动产登记簿。数据以结构化字段与非结构化文档混合形式存在，字段包含不动产坐落、权利人信息、权属来源、限制状态、测绘面积等，字段与格式随文档类型存在差异。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多系统跨源的数据来源要求检索覆盖结构化字段与非结构化文档，需同时匹配系统内结构化数据与上传的各类文档。每日更新频率要求检索链路支持实时或近实时的数据源同步，避免检索到过期数据。文档字段格式差异大，需适配不同文档的字段提取规则，避免因格式不匹配导致召回结果偏差。权属来源与限制状态为核心核验字段，要求检索优先召回包含该类字段的高相关结果，否则可能引发后续登记错误或产权纠纷，也会增加后续核验环节的耗时。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 不动产登记数据需准确匹配权属、坐落等核心字段，该区间可过滤低相关结果，避免错误关联权属信息 |
| `limit` | 前5–8条 | 台账汇总需覆盖主要权属来源与限制状态，该条数可平衡召回完整性与检索效率 |
| `searchMode` | hybrid | 需同时检索结构化字段与非结构化文档，混合检索可兼顾两类数据的召回效果 |
| `usingReRank` | 开启 | 不动产数据字段关联性强，重排可提升核心权属字段匹配结果的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可通过扩展查询补充权属、坐落等专业术语的同义表述，提升跨系统数据的召回匹配度 |
| `collectionIds` | 按业务域划分的专属集合ID | 不动产登记数据需与其他品类数据隔离，专属集合可避免跨品类检索干扰 |

## 容易做错的三处
- 搜索测试返回结果为空，原因是未配置专属业务域的`collectionIds`，或上传的登记类文档未完成解析入库。
- 检索引用条数不符合预设要求，原因是错误使用`similarity`控制返回结果数量，或`limit`参数取值未匹配台账汇总的条数需求。
- 混合检索耗时超出预期，原因是未限制检索范围，或同时开启`usingReRank`且未调整重排的召回上限。

## 怎么确认配好了
- 执行搜索测试，输入包含不动产坐落、权利人的查询词，核对返回结果是否包含对应业务域的文档与结构化数据。
- 调整`limit`参数，验证返回结果的条数是否与预设取值一致。
- 开启`usingReRank`后，对比重排前后的结果排序，确认核心权属字段的结果优先级得到提升。
- 查看文档解析状态，确认上传的登记申请书、权属证明等文档均显示解析完成。
