# 产权、资产与国有资本管理的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类的典型数据来源包括国资监管信息系统、企业资产管理系统、产权交易所系统、第三方评估机构报告与内部财务报表。日常处理的文档包含产权登记表、资产评估报告、产权转让方案、进场交易公告、资产处置审批单，文档字段涵盖资产权属编号、类别、账面价值、评估基准日、交易状态等核心信息。数据更新频率为月度，每次更新包含当期新增或调整的存量资产、交易审批材料，支持向量化的文件类型与上述文档格式匹配，包含各类办公文档、表格与结构化报表。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的批量数据要求索引构建需支持批次拆分，避免单批次任务超时。多来源、多类型的文档意味着需兼容不同格式的文本与表格内容，分块策略需兼顾长段落与短字段的完整性。台账汇总与报告生成需关联资产权属、交易状态等精准信息，因此向量检索的召回精度需满足严格要求，防止误召回非匹配资产。同时，国有资产管理的出错后果直接关联合规风险，索引的稳定性与可追溯性需得到保障。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配产权登记表、资产评估报告的常规段落长度，避免拆分权属编号、评估值等关键字段 |
| 重叠长度 | 100–150 字符 | 保留跨块的核心标识信息，防止检索时出现关键信息断档 |
| 相似度阈值 | 0.72–0.85 | 匹配国有资产权属的精确性要求，降低非目标资产的误召回概率 |
| 单次搜索上限 | 前 8 条 | 兼顾台账汇总的全面性与检索响应速度，避免过多冗余结果 |
| `defaultToken` | 4096 | 适配单份长文档的上下文承载需求，满足报告生成的多段内容引用 |
| `maxToken` | 8192 | 覆盖多份文档合并后的总token数，支持完整台账的汇总生成 |

## 容易做错的三处
- 现象：Docker打包镜像运行后，所有向量检索得分完全一致。原因：未正确配置跨容器环境的向量模型API请求参数，导致所有请求复用了本地缓存的默认嵌入结果。
- 现象：索引构建任务持续停留在最后一组文档的处理环节。原因：未为月度批量更新的索引任务设置批次拆分规则，全量数据未按文档类型拆分，导致单批次任务超出处理上限。
- 现象：混合检索响应时长超过10秒。原因：未关闭非必要的跨系统数据源检索，且单次搜索上限设置超出业务实际需求，产生额外的向量计算开销。

## 怎么确认配好了
- 导入单份产权登记表与资产评估报告，检查分块后的文本是否完整保留了权属编号、评估基准日等核心字段，无跨关键信息的强制拆分。
- 发起台账汇总请求，核对返回的检索结果条数与单次搜索上限的设置值一致，且得分分布符合业务场景的精度预期。
- 查看向量模型API的调用日志，确认`defaultToken`与`maxToken`的配置被正确应用，无token溢出类报错。
- 部署Docker镜像后，发起小型批量索引测试，确认任务可正常完成且无得分一致的异常检索结果。
