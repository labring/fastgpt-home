# 传染病信息报告与监测的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源为中国疾病预防控制信息系统、医疗机构HIS与传染病报告系统、实验室检测系统，更新频率为每日。日常文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，数据字段涵盖法定传染病分类、病例编号、诊断时间、报告时限、订正状态等，单份文档长度跨度较大，短则数百字符的报告卡，长则数千字的流调分析材料。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的数据源要求模型接入环节需支持增量数据拉取与增量汇总，避免重复处理历史数据。多类型文档结构要求配置中需适配不同文本长度与格式的输入，同时需针对法定传染病专业字段做预设对齐。需核对病例诊断、报告时限、订正重卡等耗时核心环节，因此模型的上下文与输出约束需匹配台账汇总的字段校验逻辑，同时需保证输出结果符合疾控报告的规范格式，避免出现不符合监管要求的内容，防止引发漏报迟报、疫情预警延误等后果。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的模型接入界面完成：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配流调报告、疫情分析报告的长文本输入需求，避免截断核心监测数据 |
| `maxTokens` | 2000–3000 token | 匹配台账汇总与报告生成的输出长度，保证完整输出分析结论与台账条目 |
| `temperature` | 0.1–0.3 | 降低随机输出，保证传染病报告数据的准确性与格式规范性 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 对接本地或私有部署的大模型服务，确保数据不流出合规边界 |
| `AIPROXY_API_TOKEN` | 按服务生成的安全凭证填写 | 完成模型服务的身份验证，避免未授权访问 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具完成台账核对与数据汇总，适配多步骤任务 |

## 容易做错的三处
- 现象：配置`AIPROXY_API_TOKEN`时未补充Bearer身份验证前缀，接口返回401未授权错误。原因：直接使用原始凭证发起请求，未按模型服务要求补全身份验证头。
- 现象：通过docker-compose部署的reranker模型未在FastGPT界面的模型列表中显示。原因：未将模型服务端口暴露至FastGPT所在的容器网络，或未在配置中正确填写模型接入的完整地址。
- 现象：配置`temperature`参数高于0.3时，生成的报告出现错误的法定传染病分类条目。原因：温度参数过高导致模型输出偏离疾控报告的规范要求，出现随机错误内容。

## 怎么确认配好了
- 发起一次包含10份模拟传染病报告卡的测试请求，检查FastGPT返回的接口状态码为200，无身份验证或格式错误提示。
- 查看模型服务的运行日志，确认FastGPT发起的请求携带了正确的`AIPROXY_API_TOKEN`凭证。
- 生成一份模拟的台账汇总结果，核对输出内容包含法定传染病分类、病例数量等核心字段，格式符合疾控报告的常规结构。
- 测试增量数据处理流程，确认仅当日更新的病例数据被纳入汇总，无历史数据重复处理的情况。
