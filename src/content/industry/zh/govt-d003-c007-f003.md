# 信访事项办理的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据来源包括国家信访信息系统、地方信访系统、12345平台、基层治理平台及历史信访档案，更新频率为每日。日常产生的文档包含信访登记表、受理告知书、转送交办函、办理意见书、复查复核申请、化解方案。数据字段涵盖诉求主体、事项内容、受理状态、办理进度、责任单位、办结节点等，单位多为事项条目、时间节点、人员标识类。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且每日更新，要求多轮对话需依次拉取不同系统的最新数据，避免信息滞后。文档类型多样，提示词需适配信访登记表、办理意见书等不同文档的字段提取规则。诉求甄别与办理意见形成是核心耗时环节，多轮对话需引导用户补充关键信息，减少人工干预。数据字段包含诉求主体、办理进度等，提示词需明确字段提取的优先级，确保汇总台账的完整性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 上下文窗口大小 | 8000–12000 token | 适配多份信访文档的字段与内容，避免信息截断 |
| `variables` 变量配置 | 绑定信访事项ID、责任单位名称 | 从系统拉取对应台账数据，减少手动输入 |
| `messages` 历史对话传递 | 保留近30天的对话记录 | 覆盖信访事项办理的完整流程，衔接多轮交互 |
| `chatId` 会话标识配置 | 绑定唯一信访事项编号 | 精准关联对应台账，避免会话数据混淆 |
| 多轮对话触发规则 | 按用户输入的事项关键词触发 | 精准定位对应信访台账，避免无关数据加载 |
| 超时设置 | 600 秒 | 适配跨系统拉取数据的耗时，避免会话中断 |

## 容易做错的三处
- 现象：对话环节无法获取代码运行输出的信访事项ID，对应字段为空。原因：未将`variables`变量正确绑定系统传递的参数，未在配置中声明变量来源。
- 现象：调用对话接口返回unAuthChat错误，apikey配置正确但仍失败。原因：未在会话配置中绑定正确的系统级权限参数，导致身份验证失败。
- 现象：多轮对话生成的台账汇总结果遗漏部分信访文档内容。原因：上下文窗口设置过小，截断了长文档的关键字段，导致提示词无法完整提取信息。

## 怎么确认配好了
- 手动输入测试信访事项ID，检查`variables`变量是否能正确拉取对应台账数据。
- 发起包含历史对话的测试会话，确认`messages`参数能完整传递近30天的交互记录。
- 触发多轮对话，检查是否按预设规则拉取对应系统的信访数据，无无关内容混入。
- 运行超时测试，确认会话在600秒内完成数据拉取与汇总，无异常中断。
