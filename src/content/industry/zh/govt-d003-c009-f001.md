# 公共数据目录与开放的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据主要来源于地方公共数据开放平台、一体化大数据平台、部门业务数据库及电子证照库，更新频率为月度。日常维护的文档包括公共数据资源目录、数据开放清单、数据项说明、脱敏规则、接口文档、更新频率说明。数据字段包含数据项名称、数据格式、脱敏规则、开放条件、更新周期、接口地址等，以结构化格式存储，需符合政务数据安全合规要求。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
月度更新的频率要求接口调用需适配定时任务调度，避免频繁请求超出政务平台的调用限制。多来源的数据要求接口需兼容不同的返回格式，需通过配置统一提取结构化字段。脱敏规则的存在要求接口调用时需传递对应的脱敏标识，确保返回数据符合安全要求。数据量的限制要求单次接口请求的拉取数量不宜过大，避免超出响应阈值。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 请求超时时间 | 600 秒 | 公共数据接口的响应延迟普遍较高，该时长可覆盖多数正常请求 |
| 重试次数 | 3 次 | 政务接口存在偶发波动，有限重试可提升调用成功率 |
| 批量拉取数量 | 前 50 条 | 避免单次请求数据量过大导致超时，适配台账汇总的单次处理规模 |
| `Authorization` | Bearer ${secret_key}，密钥从政务数据平台获取 | 符合地方公共数据开放平台的通用安全认证规范 |
| `variables` | 包含数据目录ID、脱敏规则标识，取值区间为 1-10 个 | 适配不同部门的数据目录调用需求，提升配置灵活性 |
| `responseData` | 提取脱敏后结构化字段，过滤非合规数据 | 确保返回数据符合政务开放的合规要求，避免敏感数据泄露 |

## 容易做错的三处
- 现象：调用公共数据开放接口后，返回的内容无法被解析为结构化台账数据，界面显示字段为空。原因：未在`responseData`配置中指定结构化字段提取规则，导致非结构化的返回内容未被正确处理。
- 现象：使用应用API接口访问时，界面提示“Failed to fetch”，日志显示连接超时。原因：未配置合理的请求超时时间，公共数据接口的响应延迟超过预设阈值导致连接中断。
- 现象：调用模型查询数据目录信息时，实际消耗的token与API返回的token不一致。原因：未在`responseData`配置中过滤敏感字段，导致额外的敏感数据被传入模型，增加了token消耗。

## 怎么确认配好了
- 发送单次测试请求，查看返回的`responseData`是否包含预期的结构化数据字段，无敏感信息泄露。
- 检查`Authorization`参数是否携带正确的认证令牌，模拟请求后返回状态码200，认证通过。
- 调整`variables`中的数据目录ID参数，验证不同部门的数据目录返回结果是否符合预期。
- 运行定时调度任务，确认月度自动更新的台账汇总数据是否正确生成并存储。
