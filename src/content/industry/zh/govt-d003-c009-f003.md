# 公共数据目录与开放的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源为地方公共数据开放平台、一体化大数据平台、部门业务数据库、电子证照库。日常维护的文档包括公共数据资源目录、数据开放清单、数据项说明、脱敏规则、接口文档、更新频率说明。数据更新频率为每月一次，文档包含结构化字段，如数据项唯一标识、开放共享范围、脱敏处理方式、接口调用地址、更新周期，部分字段附带单位标注，如接口并发上限、数据存储容量。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据每月更新的特性要求多轮对话中需明确限定查询已完成月度同步的数据集，避免请求未更新的原始数据。多类文档的存在要求提示词需区分公共数据资源目录、接口文档等不同文档的调用场景，引导调用对应来源的信息。多源数据的特性要求多轮对话需逐步确认数据所属部门，避免跨部门数据混淆。结构化字段附带单位的要求，需要提示词强制要求输出结果携带对应单位，如接口并发上限标注为“次/秒”。台账汇总的场景还要求多轮对话逐步收集各部门的数据项信息，确保汇总内容完整。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 公共数据目录与开放的文档数量较多，需容纳多轮对话历史与多份业务文档内容 |
| 问题优化 | 开启，按实测标定 | 需优化用户关于政务数据目录、接口的模糊提问，适配专业术语场景 |
| `chatId` | 绑定当前台账汇总会话 | 确保多轮对话的上下文关联，避免跨会话数据混淆 |
| `messages` | 保留最近20轮对话记录 | 覆盖月度台账汇总所需的多轮确认与信息补充环节 |
| `variables` | 预设数据更新周期为“每月” | 强制约束对话中查询的数据集为已完成月度同步的合规内容 |
| 单次搜索上限 | 前10条数据项 | 匹配公共数据目录的单页展示规范，避免输出过多冗余信息 |

## 容易做错的三处
- 现象：多轮对话输出中包含模型思考过程，未仅保留业务结果。原因：未在提示词中明确要求隐藏思考过程，或未通过`variables`预设隐藏逻辑。
- 现象：调用数据接口时返回结果条数与预期不符，多为超出10条。原因：未设置单次搜索上限，或上限配置超出公共数据目录的单页展示规范。
- 现象：对话中查询到未完成月度更新的数据项。原因：未通过`variables`预设数据更新周期为“每月”，导致模型调用了未同步的原始数据。

## 怎么确认配好了
- 发起一轮关于“本月各部门开放数据项”的提问，核对对话历史是否保留完整上下文。
- 查看输出结果是否携带对应字段的单位标注，如接口并发上限的单位。
- 检查配置项中是否绑定了专属`chatId`，确保会话上下文不与其他任务混淆。
- 触发多轮追问，确认模型能逐步补充台账所需的缺失信息，如脱敏规则、更新频率。
