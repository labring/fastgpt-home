# 公共数据目录与开放的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
本品类的数据主要来自地方公共数据开放平台、一体化大数据平台、部门业务数据库、电子证照库。日常产出的文档包括公共数据资源目录、数据开放清单、数据项说明、脱敏规则、接口文档、更新频率说明。数据更新频率为月度，字段包含数据项唯一标识、所属提供部门、脱敏处理要求、开放使用条件、更新周期、接口调用地址等，均为结构化格式，无大量自由文本内容。

## 这些特征在「工作流编排」这一环带来什么约束
月度更新的频率要求工作流需支持周期性自动触发，无需重复手动配置启动逻辑。多来源的数据需要工作流支持多节点并行拉取，整合来自不同平台、数据库的结构化数据。文档类型多样且字段存在固定格式差异，工作流需配置统一的字段映射节点，将不同来源的内容对齐至标准公共数据目录结构。脱敏规则与开放使用条件需作为固定参数嵌入工作流节点，确保生成的台账符合合规要求。接口调用环节需处理不同平台的响应格式，工作流需内置格式校验节点，过滤无效数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 包含数据来源标识、脱敏规则ID、更新周期参数 | 用于传递各部门数据源的专属参数与合规校验规则 |
| 工作流并行节点数 | 3–5 个 | 同时拉取多来源的结构化数据，避免单节点处理阻塞 |
| HTTP请求超时时间 | 300–600 秒 | 适配多平台接口的响应时长，覆盖原默认300秒的不足 |
| `nodeId` | 对应各数据来源节点的唯一标识 | 用于分支流程的条件判断与跨节点结果汇总 |
| 格式校验匹配阈值 | 80% 匹配率 | 过滤不符合标准公共数据目录字段结构的无效数据 |
| 报告输出格式 | Markdown表格 + 可下载PDF | 适配台账汇总与正式报告的查看、归档需求 |

## 容易做错的三处
- 现象：通过API调用工作流生成公共数据台账时，返回结果为空。原因：未在`variables`中配置正确的部门数据源标识参数，导致工作流无法拉取对应来源的结构化数据。
- 现象：配置知识库关联节点时，出现`quote type error`报错。原因：传入的变量未使用标准格式包裹，导致节点无法识别变量类型。
- 现象：HTTP请求节点执行后，同时触发了下一级分支流程并打印AI回复。原因：未设置分支触发的前置条件，工作流默认同时执行所有后续节点。

## 怎么确认配好了
- 手动触发一次工作流，查看各数据拉取节点的执行日志，确认多来源的结构化数据均被正常拉取。
- 传入预设的`variables`参数调用测试接口，验证工作流是否正确识别并使用传入的数据源标识与合规规则。
- 运行格式校验节点，输入不符合标准公共数据目录字段结构的测试数据，确认无效数据被过滤。
- 调整HTTP请求超时时间至适配区间，验证接口调用无超时报错。
