# 养老、工伤、失业待遇核定的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
本品类的数据来源为社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为每日。日常处理的文档包含待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料，字段覆盖参保人身份信息、缴费年限、待遇核定标准、审核状态等，单位涉及月、元、人次等，单份文档的数据结构随业务类型存在差异。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据来源分散且每日更新，要求工作流支持对接社会保险经办系统、个人权益记录系统等多类接口，定时同步最新业务数据。日常处理的文档类型多样、字段要求严格，工作流需配置统一的数据校验规则，确保不同来源的文档字段格式匹配。待遇核定环节涉及多维度数据比对，工作流需按业务逻辑拆分节点，避免单次处理数据量过大导致超时。同时，由于出错后果直接关联待遇发放，工作流需配置明确的失败告警与重试机制。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写，以下为针对本品类的工作流配置建议：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发周期 | 每日凌晨2:00-4:00 | 匹配社保业务的非高峰时段，避免影响实时经办服务 |
| 批量处理节点数 | 按业务规模调整为50-200条/次 | 平衡处理效率与接口调用压力，适配多系统对接的延迟特性 |
| `variables` 配置 | 预设参保人身份类型、待遇类型等固定参数 | 减少重复录入，统一业务处理规则 |
| 失败重试次数 | 3次，间隔60秒 | 应对临时接口波动，避免单次异常导致流程中断 |
| 节点超时阈值 | 1200秒 | 适配跨系统数据调取的耗时需求，符合业务场景的执行上限 |
| `nodeId` 配置 | 按业务节点顺序标记节点ID | 便于快速定位异常节点，排查流程问题 |

## 容易做错的三处
- 现象：工作流节点返回`premature close`报错。原因：未配置合理的超时阈值，跨系统调取社保数据或待遇材料时，接口响应超时被强制断开。
- 现象：批量处理养老、工伤、失业待遇核定数据时，单节点执行时间超过1200秒。原因：未拆分批量处理节点，单次处理的参保人数或数据量过大，超出系统执行上限。
- 现象：调用包含文件上传功能的工作流API时返回异常。原因：未正确配置文件参数的传递格式，未匹配系统支持的文件大小、格式与类型限制。

## 怎么确认配好了
- 触发一次测试工作流，查看节点日志，确认所有对接的社保系统接口均成功返回匹配的业务数据。
- 模拟批量处理参保人员数据，检查工作流执行时长是否适配业务窗口的处理节奏。
- 上传不同格式的待遇申领材料、工伤认定材料等，验证文件上传与参数传递流程是否正常。
- 模拟节点异常场景，确认失败告警与重试机制能够按配置触发。
