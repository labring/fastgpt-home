# 养老、工伤、失业待遇核定的台账汇总与报告生成：文档解析与分块

本文基于FastGPT v4.17.0版本编写

## 这个品类的数据长什么样
该品类的数据来自社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为每日。日常处理的文档包括待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料，文档多为结构化字段与零散证明内容结合的混合结构，字段涉及申领人身份标识、缴费时段、资格认定结果、待遇核算项，无统一固定格式的批量文件，部分材料包含盖章、页眉页脚等非业务内容。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的多源数据与混合文档结构，要求文档解析需兼容PDF、DOCX等多种格式，同时支持结构化字段提取与零散证明内容的关联。每日更新的数据量要求解析环节需控制耗时，避免影响台账汇总的时效性。文档中身份标识、待遇核算项等关键内容需完整保留上下文，防止分块割裂导致后续核算环节无法关联对应信息。同时，因出错后果直接关联待遇发放与基金安全，解析环节需确保关键字段无遗漏，避免因分块丢失关键证明材料的关联关系。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 文档包含结构化字段与零散证明，该区间可兼顾关键信息完整性与分块粒度，避免单块内容过多或过少 |
| `chunkSplitter` | 按段落+固定字段边界 | 日常文档多以段落与待遇核算项为业务单位，按此拆分可保留业务逻辑的连贯性 |
| `customPdfParse` | 启用 | 社保类PDF多包含盖章、固定页眉页脚，启用自定义解析可过滤无关内容，提升关键字段提取准确率 |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | 单份工伤认定或退休审批材料可能包含多页附件，该上限可覆盖常规业务文件大小 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 多页批量文档解析需充足耗时，避免因超时导致解析失败 |
| `chunkSettingMode` | 手动配置 | 需针对社保文档的混合结构调整分块参数，手动配置可灵活适配业务场景 |

## 容易做错的三处
- 现象：服务器部署后上传文件，文档解析节点返回404错误，无法读取文件内容。原因：本地环境中文件路径为相对路径，部署到服务器后未配置正确的静态文件托管路径，导致解析节点无法访问上传的文件。
- 现象：台账汇总时出现待遇核算项被拆分到两个分块中，无法关联对应身份信息。原因：未按业务字段边界配置分块规则，仅按字符长度拆分导致关键信息割裂。
- 现象：批量上传多份工伤认定材料时，解析任务超时失败。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数至适配批量文档的时长，或未限制单文件大小超出`UPLOAD_FILE_MAX_SIZE`配置。

## 怎么确认配好了
- 上传一份标准的退休审批表，检查解析后分块是否保留了身份信息与待遇核算项的关联关系。
- 调整`chunkSize`参数后，对比不同配置下的分块结果，确认关键字段未被割裂。
- 上传超出常规大小的工伤认定材料，验证解析任务是否在配置的超时时间内完成。
- 检查静态文件托管路径是否正确，确保服务器部署后可正常访问上传的文件。
