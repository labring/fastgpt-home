# 养老、工伤、失业待遇核定的台账汇总与报告生成：模型接入与配置
本页面适配FastGPT v4.17.0版本

## 这个品类的数据长什么样
本品类数据来源于社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为每日。日常处理的文档包括待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料，数据字段涵盖待遇类别、核定金额、申领人身份信息、审核状态、发放周期等，单位涉及金额元、周期月等，单份文档数据量随业务复杂度有所波动。

## 这些特征在「模型接入与配置」这一环带来什么约束
多数据源接入要求配置支持跨系统数据拉取与整合，避免数据割裂。每日更新频率要求配置适配增量同步逻辑，保障台账数据的时效性。多样的文档类型要求配置适配多格式解析规则，确保各类申报与证明材料的字段提取完整准确。涉及待遇金额与身份信息的敏感字段，要求配置开启内容校验环节，避免错误核定。台账汇总需整合多笔业务数据，要求配置预留足够的上下文容纳空间，保障汇总逻辑连贯。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多系统整合的业务数据量，保障台账汇总的上下文完整性 |
| `maxTokens` | 4000 token | 限制单份报告生成的输出长度，避免超出社保业务文档的处理上限 |
| `quoteMaxToken` | 1500 token | 限定引用的原始业务数据长度，确保汇总内容紧扣申报与审核材料 |
| `temperature` | 0.2–0.4 | 降低生成随机性，保障待遇核定与台账数据的准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写官方指定地址 | 适配社保业务的合规性网络要求，保障接口调用稳定 |
| `AIPROXY_API_TOKEN` | 按权限分配的专属密钥 | 保障接口调用的身份合法性，避免未授权访问 |

## 容易做错的三处
- 现象：多轮待遇核定对话中，后续回复未关联前期提及的申领人缴费年限信息。原因：未正确配置`maxContext`参数，导致上下文窗口过小，无法保留前期业务关键信息。
- 现象：调用生成的台账报告中出现重复的思考过程输出。原因：未配置关闭模型内置思考展示的选项，导致冗余内容混入报告。
- 现象：配置`AIPROXY_API_ENDPOINT`为非合规地址后，接口调用返回403状态码。原因：未使用符合社保业务合规要求的代理地址，导致身份校验失败。

## 怎么确认配好了
- 发起单份待遇申领材料的解析测试，核对提取的字段与原始文档一致，确认字段提取配置生效。
- 发起跨系统数据整合的测试，验证多来源数据能否正确汇总为台账条目，确认数据源对接配置正常。
- 生成一份模拟报告，核对输出内容无冗余思考过程，确认内容生成配置符合要求。
- 发起连续10次的接口调用测试，确认接口响应稳定无异常，确认代理与密钥配置有效。
