# 养老、工伤、失业待遇核定的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源为社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为每日。日常处理的文档包含待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料，涵盖结构化表单与非结构化认定文书两类。数据字段包含参保年限、待遇等级、申领资格等核心参数，单位涉及月、年、元等，单份文档内容长度跨度较大。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的数据源要求知识库同步周期匹配日频，避免数据滞后影响待遇核定的准确性。日常处理的文档涵盖结构化表单与非结构化认定文书两类，单一检索模式无法兼顾两类文档的匹配需求，需要同时适配关键词与语义召回。数据字段涉及参保年限、待遇等级等核心判定参数，检索结果的精准度直接关联待遇核定的正确性，因此需要严格控制召回的相关性标准。多系统来源的数据需通过数据集分类管理，避免跨品类的无关内容混入检索范围，保障检索结果的针对性。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配待遇核定相关文档的精准度要求，过滤低相关性内容 |
| `limit` | `前10条` | 控制单次检索返回的文档数量，平衡上下文长度与信息完整性 |
| `searchMode` | `混合检索` | 同时覆盖结构化字段匹配与非结构化语义召回，适配多样的文档类型 |
| `usingReRank` | `开启` | 对初始召回结果进行二次排序，提升高相关文档的优先级 |
| `datasetSearchUsingExtensionQuery` | `开启` | 扩展查询词的同义词覆盖范围，适配不同表述的业务文档 |
| `collectionIds` | `绑定指定待遇核定数据集ID` | 限定检索范围，避免无关数据集的内容干扰检索结果 |

## 容易做错的三处
- 现象：调用知识库接口返回“Request failed with status code 400”，原因：未正确配置数据集绑定的权限，或传入的`collectionIds`参数格式不符合要求。
- 现象：检索结果条数远低于预期，原因：`similarity`阈值设置过高，过滤掉了部分符合业务需求的参考文档。
- 现象：检索结果包含非社保待遇相关的内容，原因：未正确指定`collectionIds`，检索范围覆盖了无关的数据集。

## 怎么确认配好了
- 核对`collectionIds`的配置，确认仅绑定了养老、工伤、失业待遇核定相关的数据集。
- 执行测试检索，查看返回结果的数量和相关性是否符合业务预期。
- 确认`usingReRank`和`datasetSearchUsingExtensionQuery`的开关状态与配置要求一致。
- 检查知识库同步日志，确认每日更新的数据源已完成同步，无异常报错。
