# 养老服务机构监管的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
该品类的数据主要来自养老服务信息平台、民政统计系统、消防检查记录及机构运营台账，更新频率为月度。日常涉及的文档包含养老机构备案材料、运营补贴申请文件、服务质量检查表、安全隐患整改台账、老人入住档案等，数据字段覆盖机构基本信息、床位数量、服务记录、整改情况等，不同来源的数据格式存在差异，需统一对齐后用于台账汇总与报告生成。

## 这些特征在「部署与升级」这一环带来什么约束
月度更新的频率要求部署时配置增量数据同步机制，避免全量同步占用过多资源。多来源、多格式的数据需要在部署阶段配置字段对齐规则，适配备案、补贴、整改等不同类型文档的结构差异。监管类数据的出错后果直接关联机构运营与老人权益，因此部署时需添加数据校验环节，对缺失、异常字段进行拦截。同时，多协同部门的数据源对接需求，要求配置灵活的外部接口适配模块，保障数据同步的稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `10–15 个` | 适配月度批量数据同步的并发需求，避免数据库连接耗尽 |
| `MONGODB_URI` | 内网MongoDB认证地址，格式为`mongodb://user:pass@host:port/db` | 存储非结构化的养老机构备案材料、整改台账等文档 |
| `REDIS_URL` | 本地Redis实例地址，配置缓存过期时间为`600 秒` | 缓存月度更新的机构备案、床位数据，减少重复数据库查询 |
| `STORAGE_S3_ENDPOINT` | 内网对象存储地址，如`http://192.168.1.100:9000` | 存储养老机构上传的安全检查照片、补贴申请附件等文件 |
| `ROOT_KEY` | 长度不低于32字符的自定义字符串 | 配置FastGPT管理后台的最高权限密钥，保障监管数据的访问安全 |
| `FE_DOMAIN` | 部署服务的内网域名或IP地址 | 配置前端页面的访问地址，保障内部监管人员的正常访问 |

## 容易做错的三处
- 修改`config.json`后模型列表未更新，进入容器查看`/app/data/config`目录无配置变更。原因是未重启FastGPT容器，配置变更未同步到运行环境。
- 点击知识库模块触发报错，返回状态码500。原因是未正确配置`MONGODB_URI`或`PG_URL`，数据库连接验证失败。
- 生成的监管报告中床位数据字段为空。原因是未对齐养老服务信息平台与民政统计系统的数据字段格式，月度同步时遗漏部分机构的备案数据。

## 怎么确认配好了
- 进入FastGPT管理后台的系统设置页面，查看数据库连接状态，确认`DB_MAX_LINK`的配置值与预设值一致。
- 上传一份养老机构备案材料的扫描件，验证附件上传与存储路径可正常访问，无报错提示。
- 手动触发一次月度数据同步任务，查看同步日志中无数据库连接超时、数据格式错误等异常记录。
- 生成一份监管报告，确认报告包含备案信息、服务质量检查结果、安全隐患整改情况等所有要求的文档类型内容。
