# 内控评价、审计与整改的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
本品类数据涵盖内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明等文档，数据来源为企业内控系统、ERP、财务共享系统、审计管理系统及采购合同项目系统。数据更新频率为年度周期，核心字段包含问题编号、整改责任主体、整改完成时限、佐证材料编号等，单份文档体量差异较大，部分审计工作底稿含多页凭证扫描件。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且需跨系统拉取，工作流需配置多节点的数据源调用环节，避免单节点超时。年度更新的批量数据需设置分批次处理节点，防止单次请求过载。核心字段需严格映射，工作流需通过`variables`统一传递跨节点的核心业务参数，确保问题编号、整改状态等关键信息无缺失。不同文档格式差异较大，需配置格式适配节点，适配扫描件、表格类文档的解析规则，保障数据抽取准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量配置 | 绑定整改台账ID、审计周期等`variables` | 统一传递跨节点的核心业务参数，避免重复配置 |
| 节点超时设置 | 600–1200 秒 | 适配跨系统拉取审计工作底稿、凭证数据的耗时需求 |
| 数据源调用节点 | 按系统类型拆分节点 | 对应多来源数据的拉取逻辑，降低单节点失败影响范围 |
| 字段校验规则 | 校验问题编号、整改状态字段非空 | 保障核心业务数据的完整性，符合内控审计的合规要求 |
| `nodeId`绑定 | 为每个数据源节点分配唯一`nodeId` | 精准定位失败节点，便于后续排查与重试 |
| 格式适配节点 | 按实测标定 | 适配不同格式的审计文档与扫描件解析需求 |
| 单次拉取条数 | 前 200 条 | 适配审计工作底稿的批量拉取需求，避免单次请求过载 |

## 容易做错的三处
- 现象：工作流执行后生成的整改台账字段为空。原因：未配置`variables`映射环节，未将跨节点拉取的核心字段正确绑定到输出节点。
- 现象：工作流触发后返回504状态码。原因：未拆分跨系统数据源调用节点，单节点拉取多系统数据超时。
- 现象：生成的报告中出现重复审计问题条目。原因：未添加字段去重环节，未基于问题编号对整改台账数据进行去重处理，导致重复问题重复计入报告。

## 怎么确认配好了
- 手动触发单条数据的工作流执行，核对输出的整改台账字段与源数据是否一致。
- 查看工作流节点日志，确认每个`nodeId`对应的数据源调用环节均成功拉取数据。
- 模拟批量数据提交，检查工作流是否按配置的分批次规则执行，无超时报错。
- 验证全局变量的传递效果，确认跨节点的审计周期参数被正确应用到报告生成环节。
