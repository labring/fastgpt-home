# 内控评价、审计与整改的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
本品类数据来自企业内控系统、ERP、财务共享系统、审计管理系统及采购合同项目系统，更新频率为年度。日常处理的文档包括内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明，数据以结构化台账与非结构化文档混合为主，字段包含问题编号、整改责任人、整改时限、佐证材料路径、销号状态等，无固定统一单位，随企业内部管理规则调整。

## 这些特征在「工具调用与插件」这一环带来什么约束
年度更新的低频数据要求工具调用需适配批量历史数据拉取，避免频繁触发高频请求。多源异构数据来源要求插件需兼容不同系统的接口格式，需预设适配各系统的字段映射规则。文档类型多样且包含非结构化内容，需通过`functionCall`触发文本抽取、结构化解析插件，预设针对审计底稿、整改台账的解析模板。整改闭环的跟踪需求要求工具调用需联动销号状态字段，确保生成的报告实时同步最新整改进展。跨系统数据拉取的复杂性要求工具调用需设置合理的超时阈值，避免因单系统延迟导致整体任务失败。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多源系统的动态工具调用需求，自动匹配对应系统的接口 |
| `functionCall` | 按批量任务触发 | 匹配年度批量数据处理的节奏，避免单次调用过载 |
| 工具超时阈值 | 600 秒 | 适配跨系统数据拉取的耗时需求，避免调用中断 |
| 单次调用字符上限 | 800–1200 字符 | 适配插件解析的文本长度限制，避免内容截断 |
| 插件调用批次 | 前 5 条 | 控制单次请求的数据量，适配企业内部系统的接口限流规则 |
| 上下文窗口大小 | 16384 token | 适配大模型处理多源文档的需求 |
| 字段映射规则 | 按实测标定 | 适配不同企业的文档字段差异，确保数据抽取的准确性 |

## 容易做错的三处
-  工具调用返回的内容包含无关字段，现象为返回结果中出现未预设的冗余信息，原因是未配置`functionCall`的输出格式约束，导致插件返回了未映射的字段。
-  调用超时触发报错，现象为界面显示调用超时状态码，原因是未调整工具超时阈值，跨系统拉取年度数据的耗时超过默认限制。
-  生成的报告包含未完成整改的问题，现象为报告中未标注整改销号状态，原因是未联动销号状态字段的插件调用，未实时同步最新整改进展，可能导致审计问题重复发生。

## 怎么确认配好了
-  触发单次工具调用，核对返回的字段是否与预设的字段映射规则一致，无冗余信息。
-  模拟批量调用，检查是否触发系统限流，调整插件调用批次数量至符合接口要求。
-  生成测试报告，核对是否包含最新的整改销号状态数据。
-  查看工具调用日志，确认自动匹配的工具类型符合当前数据来源的要求。
