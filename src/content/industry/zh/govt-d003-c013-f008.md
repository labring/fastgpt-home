# 内控评价、审计与整改的台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
本品类数据主要来自中央企业内控系统、ERP、财务共享系统、审计管理系统及采购合同项目系统。日常处理的文档包括内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据更新频率为年度，文档多包含结构化表格、嵌套附件及多页合规性说明，字段多涉及整改责任主体、问题描述、整改时限、销号状态等，无统一固定单位，随文档业务场景变化。

## 这些特征在「文档解析与分块」这一环带来什么约束
年度批量更新的文档存在格式不统一问题，多页长文档需精准分块以避免割裂整改问题与对应佐证材料的关联；结构化表格、嵌套附件与合规性说明混合的文档结构，要求解析环节兼容表格识别与非文本内容的上下文关联；跨系统导出的文档格式差异大，需支持多格式解析以统一处理不同业务系统输出的台账；整改相关关联字段需保留上下文，分块时需避免拆分后丢失业务关联关系。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配整改台账、审计工作底稿中包含多字段段落的长度，避免拆分后丢失业务关联 |
| `chunkSplitter` | 按段落+标题分级 | 匹配文档中问题清单、整改要求的标题层级，保留上下文关联 |
| `customPdfParse` | 启用 | 适配审计通知书、整改销号证明中嵌入的附件与表格，提升结构化内容识别精度 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 满足多页长审计工作底稿、批量整改台账的解析耗时需求 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容大型年度审计归档文档的上传需求 |
| `chunkSettingMode` | 手动配置 | 适配本品类文档的非标准化结构，灵活调整分块规则 |

## 容易做错的三处
- 现象为配置自定义URL解析节点后，任务无报错但返回空数据。原因是未在文档解析配置中开启自定义源支持，或目标URL对应的文档格式未被当前解析引擎兼容。
- 现象为配置文档解析节点后，导入的文档无法被模型检索读取。原因是解析环节未完成即触发知识库同步，或上传文件超出`UPLOAD_FILE_MAX_SIZE`限制未被提示拦截。
- 现象为导入含多表格与图片的Word文档后，解析结果中表格内容识别不全、图片无关联文本。原因是未启用`customPdfParse`配置，或分块规则未针对结构化表格设置单独的识别逻辑。

## 怎么确认配好了
- 查看文档解析任务日志，确认所有上传的合规文档均完成解析，无超时或格式不支持报错。
- 随机抽取1份整改台账文档，核对解析后的分块内容是否保留了问题与整改措施的上下文关联。
- 测试自定义URL解析功能，确认目标文档的核心字段可被正常抽取并生成分块内容。
- 检查知识库同步记录，确认解析后的文档分片已成功写入向量库，无空分片记录。
