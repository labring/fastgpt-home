# 内控评价、审计与整改的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类的核心文档包括内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据来源于企业内控系统、ERP、财务共享系统、审计管理系统及采购合同项目系统，更新周期为年度。数据结构围绕审计发现问题、整改要求、佐证材料三类核心内容，字段包含问题标识、整改责任主体、整改完成状态等，单位多为条、份、项等审计业务通用单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征对模型接入与配置带来多维度约束。年度集中更新的批量数据要求配置项适配长文本处理，需合理设置上下文与token上限以完整解析多份审计底稿与整改台账。多源异构的数据来源要求配置支持跨系统数据的格式统一，避免因字段差异导致模型解析错误。多样的文档类型需要模型适配不同的输入结构，需通过参数调整保证对不同文档的字段识别一致性。整改销号证明的核验需求，要求工具调用配置与审计流程的节点匹配，确保模型能关联对应佐证材料。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 本品类单批次处理的审计工作底稿、整改台账总长度通常较大，需保证完整上下文输入 |
| `maxTokens` | 2000–3000 token | 台账汇总与报告生成的输出长度需覆盖完整的问题清单与整改进度，避免截断 |
| `temperature` | 0.1–0.3 | 需保证Markdown格式输出稳定，避免随机变化导致的格式错误 |
| `toolChoice` | auto | 需自动触发工具调用以关联整改佐证材料，适配审计流程的多步骤需求 |
| `quoteMaxToken` | 1000–1500 token | 需完整引用审计工作底稿中的问题原文，避免引用内容截断 |
| `AIPROXY_API_ENDPOINT` | 按对接模型服务商提供的地址填写 | 确保模型请求的路由正确，避免连接失败 |
| `AIPROXY_API_TOKEN` | 按服务商分配的有效密钥填写 | 完成模型接入的身份验证，保证请求合法性 |

## 容易做错的三处
- 模型输出的台账汇总格式混乱，未按要求使用Markdown标题与列表。原因是`temperature`参数设置过高，导致输出随机性增强，破坏了格式稳定性。
- 模型调用返回401状态码，无法完成请求。原因是`AIPROXY_API_TOKEN`配置错误，或密钥已过期，未完成有效身份验证。
- 单次处理任务超时，未生成完整报告。原因是`maxContext`或`maxTokens`设置不足，导致模型无法完整解析输入数据，或请求时长超出系统限制。

## 怎么确认配好了
- 提交单份审计工作底稿与整改台账的测试请求，核对输出的Markdown格式是否符合预设结构。
- 使用配置的API密钥发起测试请求，确认返回状态码为200，无身份验证相关报错。
- 提交批量数据测试，核对模型是否能完整解析多源系统导入的文档，无内容截断情况。
- 配置工具调用节点，触发关联佐证材料的测试，确认模型能正确调用对应工具完成核验。
