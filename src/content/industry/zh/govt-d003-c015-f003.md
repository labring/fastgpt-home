# 医保基金监管稽核的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源包括医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索，更新频率为月度。日常处理的文档涵盖稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书、整改报告，数据字段包含结算明细、违规疑点标注、处理依据、整改情况等，无固定统一的标准化字段格式，需根据每次稽核任务的范围调整数据维度，服务主体为医保局基金监管处、医保经办机构、飞行检查组及定点医药机构。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
月度更新的数据体量较大，多轮对话需限制上下文窗口避免溢出，需通过提示词明确限定仅调用当前稽核周期内的数据源。不同稽核文档的字段差异大，提示词需适配不同文档的格式要求，避免生成不符合业务规范的台账内容。事后稽核的流程依赖多轮确认，需支持中断当前生成并切换任务的能力，同时需确保对话记录的权限匹配，防止越权访问不同主体的稽核数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 当前稽核任务专属ID | 确保多轮对话绑定固定稽核任务，避免跨任务混淆数据 |
| `messages` | 保留近20轮对话内容，单轮内容不超过800字符 | 适配月度数据的体量，避免上下文溢出影响生成准确性 |
| `variables` | 传入当前稽核周期的数据源范围、主体类型 | 让提示词精准匹配本次稽核的业务规则与数据来源 |
| 单次对话超时时间 | 600秒 | 月度稽核的台账汇总任务耗时较长，避免中途强制中断 |
| 上下文窗口限制 | 不超过10000字符 | 控制上下文规模，确保生成内容聚焦当前稽核任务 |

## 容易做错的三处
- 现象：发送对话请求后，无法通过新请求打断当前模型的生成过程。原因：未配置对话中断的触发规则，默认锁定`chatId`下的生成流程直至完成。
- 现象：连续发送短间隔的对话请求时，后发请求报错提示“没有权限操作此对话记录”。原因：未正确绑定专属`chatId`，系统将后发请求识别为未授权的跨对话操作。
- 现象：升级FastGPT v4.17.0后，刷新对话页面时原有记录消失，显示为新对话。原因：未在请求中携带固定`chatId`，系统默认每次生成新的对话会话。

## 怎么确认配好了
- 向指定`chatId`发送连续两条对话请求，验证后发请求可正常触发且不触发权限报错。
- 测试中断当前生成请求，验证模型停止输出并可切换新的对话任务。
- 刷新对话页面，验证原有对话记录未丢失，确认`chatId`绑定正确。
- 触发生成台账内容，查看对话底部是否出现下载链接，根据业务需求调整下载节点配置。
