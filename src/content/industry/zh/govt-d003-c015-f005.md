# 医保基金监管稽核的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源包括医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码与举报线索，更新频率为月度。日常处理的文档包含稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书与整改报告，数据字段涵盖稽核对象、违规行为类型、涉及结算批次、处理建议等，单位多为批次、人次等。

## 这些特征在「工具调用与插件」这一环带来什么约束
月度更新的数据源要求工具调用需支持定时触发与批量处理，适配月度稽核的工作节奏。多类文档结构要求插件需适配不同格式的文本读取，准确提取疑点清单、处理决定书等内容的核心字段。多来源数据需要调用多个工具分别调取结算数据、规则库信息与举报线索，避免单一工具的覆盖不全。稽核结果出错会导致基金损失，要求工具调用需配置失败重试与操作日志记录机制，保障数据准确性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` 或 `指定稽核工具组` | 覆盖医保稽核所需的多类数据调取需求 |
| `functionCall` | 开启 | 支持调用外部插件获取医保结算数据与规则库信息 |
| 文件读取分块长度 | `800–1200 字符` | 适配稽核通知书、检查工作底稿的常规文本长度 |
| 单次工具调用上限 | `前6条` | 匹配月度稽核的疑点清单常规数量范围 |
| 超时设置 | `600 秒` | 覆盖跨系统调取医保结算数据的合理耗时 |
| 插件请求大小限制 | `1000 MB` | 适配药品耗材追溯码的批量数据传输需求 |

## 容易做错的三处
- 现象：调用`toolChoice`时返回模型不支持的报错。原因：未确认当前使用模型支持`toolChoice`功能，错误选择了不支持工具调用的模型。
- 现象：发布应用后通过API调用返回空结果。原因：未配置外部系统调用的权限参数，导致无法正常调取医保结算数据与规则库信息。
- 现象：导入HTTP插件后无法触发数据查询。原因：未将插件的请求地址与医保智能监控系统的官方接口匹配，导致请求无效。
- 现象：应用调用返回的结果直接展示在终端。原因：未配置结果仅作为上下文喂给大模型的开关，导致结果直接输出。

## 怎么确认配好了
- 测试调用`toolChoice`，确认能触发指定的稽核数据查询工具，返回对应格式的疑点清单。
- 调用发布后的API接口，确认返回的台账数据字段与预设的稽核文档结构一致。
- 导入HTTP插件后发起测试请求，确认能正常获取医保结算数据与规则库信息。
- 配置应用调用结果不直接输出，确认大模型能正确使用该结果生成稽核报告，无直接输出的原始数据。
