# 医保费用结算审核的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
该品类数据来源为全国医疗保障信息平台、医院HIS与医保接口、医保目录和编码库、异地就医结算平台，按日更新。日常处理的文档包含医保结算清单、费用明细、病案首页、处方、拒付清单、结算对账单，数据字段包含结算编号、参保人身份标识、诊疗项目与药品耗材编码、费用金额、拒付原因、对账状态等，单位涵盖元、人次、编码标准值等。

## 这些特征在「模型接入与配置」这一环带来什么约束
日更的数据规模与更新节奏要求模型接入环节支持高频批量调用，需限制单轮处理的token上限以避免超时。多源异构的数据格式要求配置项需兼容不同文档的字段结构，避免因格式不匹配导致字段解析失败。医保相关文档包含专业编码与合规性要求，模型的提示词需适配医保目录库的标准，同时需预留足够的上下文空间容纳结算明细与对账数据，防止关键信息被截断。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxTokens` | 8000–12000 token | 适配医保结算清单、拒付清单等长文本的完整解析，避免关键审核信息被截断 |
| `maxContext` | 6000–10000 字符 | 容纳批量结算数据的上下文关联，支持多份明细与对账数据的同步处理 |
| `quoteMaxToken` | 2000–3000 token | 限制单条引用数据的长度，防止上下文溢出导致模型输出异常 |
| `temperature` | 0.1–0.3 | 降低随机性，确保编码匹配、费用审核的结果符合医保目录的固定规则 |
| `toolChoice` | auto | 自动选择合适的工具处理编码匹配、对账校验等细分任务，适配多步骤审核流程 |
| `AIPROXY_API_TOKEN` | 按角色权限分配 | 适配医保数据的安全管控要求，限制不同经办机构的接口访问权限 |

## 容易做错的三处
- 调用工作流时返回「无效API Key」报错。原因：使用了全局通用API Key直接调用应用对话接口，未使用对应工作流的专属权限配置。
- 工作流执行后返回的结算审核结果字段缺失。原因：未正确设置`maxContext`参数，批量结算明细的上下文被截断，无法完成编码与费用的匹配校验。
- 问题分类结果不符合医保审核场景的预期。原因：未针对专业场景调整`temperature`参数，或提示词未适配医保目录与结算规则的专业需求。

## 怎么确认配好了
- 调用测试接口，查看返回的API调用日志，确认`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置与部署环境匹配。
- 提交单份医保结算清单与批量明细数据，检查模型输出的台账字段是否覆盖了核心审核内容。
- 触发工作流执行，监控运行时长，确认处理时长符合业务需求，未出现明显超时。
- 调整`temperature`参数并对比输出结果，确保审核逻辑的一致性符合医保规则的固定要求。
