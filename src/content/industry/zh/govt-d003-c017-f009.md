# 医疗机构监督与公共卫生检查的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自卫生监督信息系统、医疗机构电子化注册系统、投诉举报平台及执法检查记录，更新频率为月度。日常处理的文档包含监督检查表、医疗机构执业许可证、整改通知书、监督意见书、处罚案卷，各文档对应机构资质、现场检查情况、整改跟踪及处罚结果等字段，无统一固定单位，字段内容随文档类型变化，需针对不同文档识别专属业务字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度集中更新的多源多类型数据，要求模型上下文容量适配批量文档处理，避免因上下文不足导致信息丢失；不同文档的字段差异显著，要求模型支持差异化的字段提取规则，适配执业许可证、监督检查表等不同文档的识别需求；数据来源分散且关联要求高，要求模型能完成多源数据的交叉核对；业务出错后果涉及执业风险与合规处罚，要求模型输出的台账与报告具备可追溯的原始引用。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配月度批量的多类型文档处理，避免上下文溢出丢失关键业务信息 |
| `maxTokens` | 2000–3000 token | 匹配单份监督台账或报告的标准生成长度，确保输出内容完整 |
| `temperature` | 0.1–0.3 | 保障监督类内容的严谨性，减少主观发散的非合规表述 |
| `quoteMaxToken` | 1500 token | 保留原始文档的关键引用片段，满足合规追溯的信息留存要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应节点 | 适配卫健系统内部的网络访问限制，确保接口调用稳定 |
| `toolChoice` | auto | 自动调用文档解析工具，适配多类型业务文档的格式识别需求 |

## 容易做错的三处
- 现象为生成的台账中机构资质字段为空，原因是未针对不同文档类型配置专属字段提取规则，导致模型无法准确匹配执业许可证、监督检查表的专属业务字段。
- 现象为接口调用返回429状态码，原因是未限制批量处理的并发请求数，月度集中更新的数据批次导致接口触发限流。
- 现象为模型对比实验结果无明确差异，原因是未使用本品类的标注数据（如监督检查表的合规标签）进行测试，仅使用通用数据集开展实验。

## 怎么确认配好了
- 上传单份监督检查表与医疗机构执业许可证，核对模型提取的字段是否与文档内容一致，调整配置项直至匹配业务字段要求。
- 发起月度批量数据的测试调用，检查接口返回状态码是否符合预期，调整并发配置适配系统访问限制。
- 对比不同`temperature`取值下的输出内容，确认严谨性符合业务合规要求，选定合适的参数区间。
- 验证输出的引用片段长度是否符合`quoteMaxToken`的设置，确保合规追溯的信息留存完整。
