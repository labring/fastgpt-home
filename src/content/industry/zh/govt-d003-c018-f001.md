# 参保登记与缴费核定的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据来自社会保险经办系统、税务社保费征收系统、市场主体登记信息及公安民政数据共享接口。数据更新频率为每日。日常处理的文档包含参保登记表、缴费基数申报表、人员增减表、社保费核定单、个人权益记录，核心字段涵盖单位主体标识、人员身份信息、缴费基数、核定缴费金额、参保状态等，单份文档的核心数据条目通常在数十条至数百条区间。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据接入要求HTTP接口适配不同外部系统的鉴权规则，完成字段映射转换。每日更新的频率要求接口支持定时调度或实时触发的调用配置，保障数据时效性。核心字段涉及人员身份与缴费信息，接口传输需符合数据安全要求。单份文档的核心数据条目较多，请求体需支持批量数据传输，同时需配置参数校验规则过滤无效字段。出错后可能影响参保权益记录，接口需返回明确的错误状态码与重试机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {external_system_token}` 按实测标定 | 适配外部社保、税务系统的标准鉴权格式，保障接口调用合法性 |
| `variables` | 包含单位统一社会信用代码、人员身份证号等10-20个核心字段 | 匹配日常处理文档的核心数据结构，减少无效参数传输 |
| `responseData` | 仅返回参保状态、缴费核定金额、更新时间字段，取前100条数据 | 过滤冗余数据，降低接口传输负载，适配台账汇总的批量处理需求 |
| 接口超时设置 | 600秒 | 适配多源数据拉取的耗时需求，避免外部系统响应延迟导致调用中断 |
| 重试次数 | 3次 | 应对外部系统临时波动，提升数据拉取的成功率 |
| 字段校验规则 | 校验身份证号、统一社会信用代码格式 | 过滤无效请求数据，避免错误数据进入台账汇总流程 |

## 容易做错的三处
- 调用外部数据接口后返回`responseData`字段为空，且状态码为200。原因是未在`variables`中配置正确的查询参数，未传递有效的单位统一社会信用代码或人员身份标识，导致外部系统无法返回对应数据。
- 通过API调用编排后的工作流时，未触发预设的用户输入或选择步骤。原因是未在FastGPT v4.17.0的工作流发布配置中开启API调用的交互透传开关，导致交互逻辑未被触发。
- 接口调用返回504 Gateway Timeout状态码。原因是接口超时设置过短，未适配多源数据拉取或批量台账处理的耗时需求，导致外部系统未及时返回响应。

## 怎么确认配好了
- 调用测试接口，检查`Authorization`鉴权头是否正确携带，确认返回状态码符合预期。
- 查看`responseData`返回的字段是否包含预设的核心数据项，验证参数校验规则是否生效。
- 模拟批量数据请求，检查接口返回的数据条目是否符合配置的取值限制。
- 触发临时故障模拟，确认接口会按照配置的重试次数自动发起重试请求。
