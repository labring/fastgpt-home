# 双随机、一公开监管检查的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
该品类的数据通常来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库，更新频率为月度。日常文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示，核心字段涵盖检查对象统一社会信用代码、执法人员编号、检查事项条目、整改完成状态等，单份文档的字段数量与关联关系随检查层级与事项类型有所变化。

## 这些特征在「部署与升级」这一环带来什么约束
月度更新的数据源要求部署环节配置稳定的定时同步任务，确保检查对象、执法人员等核心数据的时效性。多来源的异构文档结构，要求部署时适配不同格式的数据解析规则，避免字段匹配错误。核心数据的合规性要求升级环节需保留数据校验逻辑，防止因配置变更导致检查对象抽取不合规或结果漏公示，同时需兼容原有监管系统的接口调用权限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | 指向监管数据同步库的专用连接地址 | 用于存储检查对象、执法人员等结构化台账数据，需与监管平台数据库权限隔离 |
| `REDIS_URL` | 配置为本地缓存实例的连接地址，缓存有效期设为 7200 秒 | 缓存高频调用的检查事项清单与执法人员名录，降低外部数据源的调用频率 |
| `STORAGE_S3_ENDPOINT` | 绑定本地区块存储服务的端点地址 | 用于存储现场检查照片、整改通知书扫描件等非结构化文档，满足监管档案留存要求 |
| `DB_MAX_LINK` | 20 个并发连接 | 适配多执法人员同时查询台账的并发场景，避免数据库连接耗尽 |
| 定时同步周期 | 每 720 小时触发一次 | 匹配月度更新频率，确保台账数据与监管平台保持同步 |
| 文档解析规则 | 按实测标定的字段匹配阈值 | 适配多来源文档的格式差异，提升台账汇总的字段提取准确率 |

## 容易做错的三处
- 现象为非结构化文档（如现场检查照片）无法被正确解析，字段提取为空。原因是未配置`STORAGE_S3_ENDPOINT`或存储权限不足，导致图片无法同步至解析节点。
- 现象为定时同步任务触发后，检查对象名单更新不及时。原因是定时同步周期设置不符合月度更新节奏，或`PG_URL`指向的数据库权限受限，无法拉取完整数据。
- 现象为生成的抽查结果公示报告中出现重复监管对象条目。原因是未配置数据去重逻辑，或`REDIS_URL`的缓存有效期设置不当，导致重复拉取同一批次的检查对象数据。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的后台数据库管理模块中，测试`PG_URL`的连接状态，确认能拉取测试用的检查对象名单数据。
- 手动触发一次定时同步任务，查看台账数据的更新时间，与监管平台的最新更新时间进行比对。
- 上传一份现场检查记录文档，验证是否能正确提取执法人员、检查事项等核心字段，生成结构化台账条目。
- 生成一份月度抽查报告，核对报告中的监管对象数量与台账数据库中的实际条目数量是否一致。
