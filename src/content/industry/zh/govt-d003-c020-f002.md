# 国土空间规划编制与实施评估的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
这个品类的典型文档包含国土空间总体规划、详细规划、专项规划、规划实施评估报告及公众意见汇总。数据来源涵盖国土空间基础信息平台的空间矢量数据、自然资源调查监测的实地勘测数据、人口经济统计台账与遥感影像元数据。数据更新频率为年度，文档结构包含标准化规划指标、空间坐标字段、部门反馈意见与公众提交的诉求文本，单份文档篇幅跨度较大，从数十页的专项规划到数百页的全域评估报告不等。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据特征要求索引需同时支持文本语义检索与空间属性关联，避免台账汇总时出现数据割裂。年度更新的节奏意味着无需构建实时索引，可采用批量增量更新的方式降低资源消耗。不同文档的篇幅差异要求分块策略需适配长文本与短条目，保障语义完整性。规划指标与空间坐标的强关联属性，要求向量模型需能对齐文本内容与元数据字段，提升报告生成时的关联准确性。出错后果直接影响规划审批进度，因此索引的召回准确率需满足业务校验要求，避免遗漏关键约束指标。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类文档的文本长度与空间元数据的语义完整性，避免单块内容过于零散 |
| 重叠长度 | 100–150 字符 | 减少跨块语义断裂，保障规划文本长句的连贯性 |
| 相似度阈值 | 0.75–0.85 | 精准匹配规划指标与台账条目，过滤低相关的冗余检索结果 |
| 单次搜索上限 | 前 10 条 | 平衡台账汇总的信息完整性与报告生成的响应速度 |
| maxToken | 16000 | 适配FastGPT v4.17.0的模型上下文上限，满足全域规划报告的生成需求 |
| defaultToken | 4096 | 平衡台账条目解析的精度与单次请求的响应效率 |

## 容易做错的三处
- 现象：调用OpenAI接口时出现“invalid api key”或请求超时报错。原因：未正确配置one api的代理地址与密钥绑定规则，导致接口请求无法正常路由至目标模型。
- 现象：索引召回结果为空或条数不符合预期。原因：未针对国土空间数据的空间坐标字段设置专属检索规则，导致元数据与文本内容无法关联，台账汇总时丢失关键关联信息。
- 现象：报告生成时触发上下文溢出错误。原因：未合理调整maxToken参数，导致汇总的多源台账数据超过模型可处理的上下文长度上限。

## 怎么确认配好了
- 上传单份专项规划文档，执行分块解析测试，确认分块长度与重叠长度符合预设配置，无明显语义断裂的内容块。
- 输入包含规划指标与空间范围的检索请求，确认召回结果包含对应文档的相关条目，数量匹配单次搜索上限的设置。
- 测试通过one api调用OpenAI接口，确认返回正常的文本响应，无密钥或路由相关的报错信息。
- 导入年度更新的规划数据，执行批量索引构建，确认索引更新进度正常，无异常中断或报错日志。
