# 国库集中支付与报销审核的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
这个品类的核心数据来自国库集中支付系统、预算管理一体化系统、电子发票平台、合同管理系统，服务于预算单位财务、财政国库支付中心、主管部门财务审核岗的日常工作。日常处理的文档包括支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，数据按日更新。单条数据包含预算指标编码、经济分类代码、支付金额、审批状态、关联合同编号等字段，金额以元为单位，支付记录以笔为单位，台账需汇总多维度的支付与审核明细。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据来源分散且需每日同步，部署时需对接多个外部系统的接口，要求配置多组数据源连接参数。日常处理的文档包含多种格式的票据与审批材料，存储需求较高，需配置稳定的文件存储服务。台账汇总需处理复杂的字段映射与多维度统计，部署时需预留足够的数据库计算资源。由于出错可能导致支付退回、资金错付等合规风险，升级时需执行灰度发布，部署前需完成全量数据备份。内网环境下需避免公网暴露存储服务，保障内部数据安全。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本，适配国库集中支付与报销审核的台账场景：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.200:9000` | 适配内网部署场景，对接内部MinIO存储服务，避免公网暴露风险 |
| `REDIS_URL` | `redis://:securepass@10.0.0.5:6379/1` | 缓存每日同步的台账数据，保障多维度汇总查询的响应速度 |
| `PG_URL` | `postgresql://gsc_admin:dbpass@10.0.0.3:5432/finance_ledger` | 存储结构化台账与审核记录，支持复杂的汇总统计查询 |
| `DB_MAX_LINK` | `20–30` | 适配每日批量同步的数据库连接需求，避免资源耗尽导致同步失败 |
| `FILE_TOKEN_KEY` | 随机生成的32位字符串 | 保障上传的发票、合同等文件的访问权限安全 |
| `FE_DOMAIN` | `https://finance-ai.your-intranet-domain.com` | 配置服务的实际访问地址，保障Webhook回调与插件调用的有效性 |

## 容易做错的三处
- 现象：启动服务后无法访问存储的票据文件，日志显示「access denied」或「invalid endpoint」。原因：未将`STORAGE_S3_ENDPOINT`配置为内网可访问的地址，误使用公网域名导致内网无法解析。
- 现象：手动触发台账同步任务后，日志显示「connection pool exhausted」，同步进度停滞。原因：`DB_MAX_LINK`配置值过低，批量同步时数据库连接不足，无法完成全量数据拉取。
- 现象：Webhook接收的表格数据无法生成对应台账，查看结果为空。原因：未配置`FE_DOMAIN`为服务的实际访问地址，导致回调地址无效，无法接收完整的同步数据。

## 怎么确认配好了
- 执行内置的数据库连接测试工具，验证`PG_URL`、`REDIS_URL`对应的服务均可正常建立连接。
- 上传一张测试用的电子发票图片，通过文件存储模块验证文件可正常上传并返回有效访问链接。
- 触发一次手动台账同步任务，查看同步日志确认无连接错误、数据拉取完整且无字段缺失。
- 进入插件配置页面，确认`STORAGE_S3_ENDPOINT`的配置与内网存储服务的实际地址一致。
