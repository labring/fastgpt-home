# 学生资助与奖补审核的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类数据来源为全国学生资助管理信息系统、学校学籍系统、民政低保特困数据、财政支付系统，更新频率为每学期。日常处理的文档包括家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单、公示材料，数据字段包含学生身份标识、家庭经济状况信息、资助资格等级、发放金额、银行卡信息、公示反馈等，多为结构化表格或带有固定格式的文档，单份文档的内容关联性较强，同一学生的多类材料需交叉核验。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引流程支持跨系统文档的统一向量化处理，避免出现字段映射偏差。学期级的更新频率要求配置可灵活开启增量索引模式，减少全量索引的重复计算开销。文档内字段关联性强的特点，要求分块时需保留核心关联字段，如学生身份标识，避免拆分后丢失上下文关联。结构化的表格文档要求索引配置适配表格列结构，防止分块时割裂表头与对应数据行，同时公示材料与发放名单的核验需求，要求索引召回的精度需满足精准匹配的要求，避免引入无关的学生资助记录。

## 配置怎么定
本配置基于FastGPT v4.17.0版本进行设置。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配本品类文档的字段关联长度，避免拆分后丢失学生身份、资助编号等核心关联信息 |
| 重叠长度 | 150–200 字符 | 保障跨块的核心字段可被完整检索，避免同一学生的跨块资助信息被割裂 |
| 相似度阈值 | 0.75–0.85 | 平衡精准匹配与召回范围，适配资助审核中对资格、金额等字段的精确核验需求 |
| `defaultToken` | 4096 | 满足台账汇总时整合多份关联文档的上下文长度要求 |
| `maxToken` | 8192 | 支持报告生成时拼接多段检索结果的总长度需求 |
| 单次搜索上限 | 前 10 条 | 控制检索结果的冗余度，避免引入过多不相关的学生资助记录 |

## 容易做错的三处
- 现象：上传Excel格式的发放名单后，索引后显示的分块数量与上传时的预估数量不一致，存在重复块。原因：未开启表格列识别配置，导致分块时误将表格行内的换行符作为分块依据，重复拆分了同一数据行的内容。
- 现象：从旧版本升级到FastGPT v4.17.0后，原有可查询的学生资助记录无法检索到。原因：未重新执行索引流程，新版本的分块规则或向量模型参数发生变更，旧索引的分块结果无法匹配新的检索逻辑。
- 现象：知识库搜索结果合并后出现字段混乱，不同学生的资助信息被错误拼接。原因：未配置关联字段匹配规则，导致检索时未按学生身份标识进行分组合并，直接拼接了所有匹配的内容块。

## 怎么确认配好了
- 上传单份家庭经济困难认定表，检查索引后的分块数量与预估一致，无重复内容块。
- 输入特定学生的身份标识或资助申请编号进行检索，确认返回的结果包含该学生的全部关联字段信息，无字段缺失或错位。
- 升级到FastGPT v4.17.0后，重新索引所有存量的学生资助文档，验证原有检索结果可正常返回。
- 开启搜索合并功能后，检索同一班级的资助申请记录，确认结果按学生身份标识分组合并，无跨学生的内容拼接。
