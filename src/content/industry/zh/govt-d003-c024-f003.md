# 学生资助与奖补审核的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自全国学生资助管理信息系统、学校学籍系统、民政低保特困数据、财政支付系统，更新周期为学期。日常处理的文档包含家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单、公示材料，字段涵盖学生身份信息、家庭经济状况、资助申请类别、评审结果、发放金额与银行卡信息，各文档需跨系统交叉核验对应字段，确保数据一致性。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
跨系统多源数据的交叉核验需求，要求多轮对话需逐步调取不同系统的字段数据，避免上下文溢出。学期批量更新的台账数据，要求提示词适配批量汇总逻辑，不能仅处理单条数据。多类文档的字段匹配要求，提示词需明确指定需对齐的字段组合，防止遗漏核验项。公示材料与发放名单的对应关系，要求多轮对话需引导对齐两类文档的学生名单与金额信息，避免出现错发漏发风险。

## 配置怎么定
本配置基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 8000–12000 token | 适配学期批量台账的汇总与报告生成需求，避免截断关键核验信息 |
| 对话超时时间 | 600 秒 | 适配批量数据的处理时长需求，避免因数据量过大导致请求中断 |
| 问题优化 | 开启 | 对用户的核验请求进行拆分，引导逐步调取不同系统的字段数据 |
| 全局变量注入 | 按学期批次配置固定变量 | 统一提示词的字段匹配逻辑，适配跨系统数据的格式差异 |
| 对话上下文绑定 | 绑定学期资助批次唯一标识 | 用于区分不同学期的台账数据，避免跨批次上下文混淆 |
| 输出格式校验 | 强制指定闭合标记规则 | 避免输出时出现未闭合的引用号类乱码 |

## 容易做错的三处
- 现象：AI对话返回内容与提问不匹配，出现无关问题的回答。原因：未按学期批次隔离对话上下文，导致不同批次的资助数据混淆。
- 现象：AI对话节点返回空响应。原因：提示词未明确指定需匹配的字段组合，或全局变量未注入必要的系统映射规则，导致大模型无法生成有效内容。
- 现象：AI输出末尾出现未闭合的引用号乱码。原因：提示词未明确指定输出格式的闭合规则，或上下文截断导致格式标记不完整。

## 怎么确认配好了
- 导入单条学生资助数据，触发多轮对话，核对返回的核验结果是否包含家庭经济状况与学籍状态的交叉匹配信息。
- 查看对话日志，确认对话上下文绑定的批次ID随每次请求正确传递，不同学期的批次无混淆。
- 注入全局变量后，触发提示词调用，核对输出内容是否包含预设的字段映射规则。
- 模拟批量台账汇总请求，确认返回的报告格式符合公示材料的字段要求。
