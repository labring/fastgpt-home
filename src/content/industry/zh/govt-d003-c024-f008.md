# 学生资助与奖补审核的台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
本品类服务主体为教育局资助中心、学校学生处或资助办、财政部门。日常处理的文档包含家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单、公示材料等，数据来源覆盖全国学生资助管理信息系统、学校学籍系统、民政低保特困数据、财政支付系统。数据更新以学期为周期，文档多为固定格式的表单或批量名单，核心字段包含学生身份信息、困难认定等级、资助金额、银行卡号等，需跨系统核对数据一致性。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于文档多为单学生表单或批量名单结构，解析分块需保证每个块对应单学生的完整信息，避免跨学生数据混杂，否则会导致后续台账汇总出现信息错位。多系统来源的文档格式存在差异，需适配不同的解析规则，确保结构化字段准确提取。学期级的批量数据处理需求，要求解析系统支持大文件或批量上传，同时需控制分块粒度以平衡解析效率与信息完整性。资助审核的出错后果直接关联学生权益与审计合规，解析环节需避免字段漏提、内容截断等问题，保障后续台账与报告的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配单学生表单或单条资助名单的内容长度，避免拆分跨学生的完整信息块 |
| `chunkSplitter` | 按标题+段落拆分 | 匹配文档中“学生姓名”“家庭情况”“资助金额”等标题分隔的结构，保证每个分块对应单学生的全部信息 |
| `customPdfParse` | 开启 | 针对家庭经济困难认定表等结构化PDF文档，精准提取固定字段，提升结构化数据的解析准确率 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持批量上传整学期的发放名单或评审材料，避免单文件过大导致解析被拦截 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配批量文档或大文件的解析耗时，防止多文件批量上传时出现超时中断 |
| `chunkSettingMode` | 手动配置 | 针对表单类、名单类等不同文档类型，灵活调整分块参数，满足精准拆分需求 |

## 容易做错的三处
- 上传文件后解析节点无工作，界面显示文件上传成功但解析状态长时间停留在待处理，原因是未正确配置`UPLOAD_FILE_MAX_SIZE`，超过阈值的文件被拦截未进入解析队列。
- 抓取到部分数据，解析后的文档仅提取了部分学生的资助信息，剩余字段为空，原因是`chunkSplitter`配置为按固定字符拆分，导致跨学生的表单内容被错误拆分，未保留单学生的完整信息块。
- 模型输出Markdown表格被截断，对话中展示的解析结果表格末尾显示`...[hide 38432 char]`，原因是`chunkSize`设置过小导致长名单类文档被拆分后未完整拼接，或`PARSE_FILE_TIMEOUT_SECONDS`参数不足导致部分解析内容未完成加载。

## 怎么确认配好了
- 上传单份家庭经济困难认定表PDF，检查解析结果是否完整提取了所有预设字段，无内容缺失或跨学生信息混杂。
- 上传批量的发放名单文档，查看解析队列的处理状态，确认无超时报错或节点无工作的情况。
- 调整`chunkSize`参数后，对比不同取值下的解析结果，确保单学生的完整信息未被错误拆分。
- 查看系统日志，确认解析请求未因`UPLOAD_FILE_MAX_SIZE`或`PARSE_FILE_TIMEOUT_SECONDS`被拦截或中断。
- 确认当前使用的FastGPT版本为v4.17.0，确保配置项的兼容性。
