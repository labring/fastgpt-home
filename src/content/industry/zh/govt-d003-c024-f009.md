# 学生资助与奖补审核的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自全国学生资助管理信息系统、学校学籍系统、民政低保特困数据、财政支付系统，更新周期为学期。日常处理的文档包含家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单、公示材料，字段涵盖学生身份标识、家庭经济认定等级、申请资助类型、审批状态、发放金额、银行卡信息等，数据格式因来源系统存在细微差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入时需适配不同系统的字段格式，避免出现数据映射错误；学期级的更新频率意味着模型无需高频刷新上下文，但需支持批量处理单学期的全量台账数据；多样的文档类型既包含结构化的发放名单，也包含非结构化的公示材料，要求配置兼顾文本解析与结构化输出的能力；同时，资助错发漏发会引发学生投诉与审计问题，因此模型输出的准确性要求较高，需严格控制生成参数的取值范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://192.168.1.100:8000/v1` | 对接本地VLLM部署的Qwen3系列模型，符合实际本地部署的接入场景 |
| `AIPROXY_API_TOKEN` | 本地模型部署生成的访问令牌，无验证需求时留空 | 适配本地非公开部署的模型访问控制规则 |
| `maxTokens` | 8000–12000 token | 处理单学期的批量资助台账数据，包含多份申请表与发放名单，避免核心内容被截断 |
| `temperature` | 0.1–0.3 | 保障台账汇总与报告生成的准确性，降低生成不符合业务规则的内容概率 |
| `quoteMaxToken` | 2000–3000 字符 | 保留足够的原始认定表、公示材料片段，用于报告中的引用与核验依据 |
| `toolChoice` | `auto` | 支持模型自动判断是否调用工具处理跨系统数据的字段映射，适配多源数据的处理需求 |

## 容易做错的三处
- 现象：模型调用返回404状态码或提示无法连接到服务。原因：未正确配置`AIPROXY_API_ENDPOINT`，填写的本地VLLM服务地址格式错误或服务未正常启动。
- 现象：生成的台账报告出现字段为空或数据错位。原因：未适配多源系统的字段格式，模型无法正确映射不同来源的学生身份标识与资助信息。
- 现象：汇总的台账数据出现批量遗漏或重复。原因：未设置合理的`maxContext`参数，导致上下文溢出，模型丢失部分输入的学生记录数据。

## 怎么确认配好了
- 在FastGPT的模型管理页面，选择配置完成的模型，输入一段家庭经济困难认定表的示例文本，执行测试调用，检查是否能正常返回结构化的解析结果。
- 上传单学期的发放名单与公示材料，触发台账汇总任务，查看任务日志中是否显示模型调用成功，无超时或连接错误提示。
- 对比模型生成的报告片段与原始数据的核心字段，确认资助金额、学生身份信息等关键内容的映射正确。
- 运行FastGPT v4.17.0版本的模型健康检查工具，确认与本地部署的Qwen3系列模型的连接状态正常。
