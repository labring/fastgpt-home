# 学生资助与奖补审核的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
本品类数据主体为教育局资助中心、学校学生处或资助办、财政部门。日常文档包含家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单、公示材料。数据来源涵盖全国学生资助管理信息系统、学校学籍系统、民政低保特困数据、财政支付系统。数据按学期节奏更新，核心字段包含学生身份标识、资助资格等级、申请金额、发放卡号与公示批次等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源跨部门的数据来源要求检索链路支持跨字段关联匹配，避免不同系统的数据出现脱节。学期级的更新周期要求配置定期同步机制，确保知识库数据与业务系统的最新状态保持一致。单份文档包含批量学生信息的属性，要求检索召回的粒度适配单学生记录，避免批量结果干扰审核判断。多维度的业务字段要求检索支持多条件组合筛选，保障审核依据的准确性与合规性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，核心参数包括`similarity`、`limit`、`usingReRank`等，涵盖检索匹配、召回控制等维度。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 学生资助数据需保障身份与资格匹配的精准度，避免低相似度的无关结果干扰审核 |
| 单次召回上限 | 3–5 条 | 单学生的匹配结果需控制数量，避免审核时出现冗余信息 |
| 搜索模式 | 向量+关键词混合检索 | 跨源业务数据既有语义关联，又包含明确的字段匹配需求 |
| 开启重排 | 开启 | 多源异构数据的语义相似度需二次校准，提升检索结果的准确性 |
| 开启问题优化 | 开启 | 资助审核的查询常包含多字段组合，优化后可覆盖更多业务场景 |
| 指定知识库集合 | 绑定对应学期的资助文档集合，单集合不超过 1000 个文件 | 按学期隔离数据，避免跨批次的历史数据混淆 |

## 容易做错的三处
- 现象：单文档上传后显示分块数与最终就绪分块数不一致，出现重复索引。原因：未配置合理的去重逻辑，导致同一文档被多次分块入库。
- 现象：检索结果中混杂跨学期的资助数据，无法精准定位当前审核批次的内容。原因：未绑定对应学期的知识库集合，检索范围覆盖了全量历史数据。
- 现象：检索返回的结果条数超出预期，无法快速定位目标学生的信息。原因：未设置合理的单次召回上限，召回了过多无关的记录。

## 怎么确认配好了
- 执行单学生身份的检索测试，核对返回结果的字段是否包含当前审核批次的相关信息。
- 检查知识库集合的绑定配置，确认仅包含对应学期的资助文档与数据。
- 触发一次全量同步任务，核对同步后的分块数与原始文档的分块预期一致。
- 调整检索相关参数的取值，验证检索结果的匹配精度与召回数量是否符合业务要求。
