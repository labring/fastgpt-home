# 安全生产隐患排查治理的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源于安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常处理的文档包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，数据结构包含排查项详情、整改责任人、整改期限、复查结果等字段，不同来源的数据格式存在细微差异，不同文档的字段优先级不同，需统一适配至台账汇总的标准结构。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源异构的数据来源要求多轮对话需关联不同系统的业务数据，避免上下文割裂。每日更新的业务数据要求对话链路需同步最新的台账信息，确保汇总结果的时效性。多样的文档类型要求提示词需适配不同文档的字段规则，例如整改通知书需跟踪闭环状态，重大隐患督办单需标注优先级。同时，隐患治理的闭环属性要求多轮对话需保留历史排查、整改、复查的完整上下文，为后续汇总提供依据。

## 配置怎么定
本配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定单次隐患排查全流程的唯一标识 | 确保多轮对话关联同一排查任务的所有数据，避免会话上下文割裂 |
| `messages` | 保留前20轮对话历史 | 覆盖排查、整改、复查全流程的上下文，避免关键信息丢失 |
| `variables` | 绑定隐患台账的核心字段（排查时间、整改期限等） | 将结构化业务数据直接注入提示词，提升汇总报告的准确性 |
| 最大上下文token数 | 8000–12000 token | 适配多源文档的字段总量，避免上下文溢出导致对话中断 |
| 知识库召回条数 | 前6条 | 匹配隐患排查的多类参考文档，避免冗余信息干扰汇总结果 |
| 数据同步频率 | 按每日更新节奏触发 | 匹配业务数据的更新频率，确保对话使用最新的台账数据 |

## 容易做错的三处
- 现象：知识库返回结果为空或字段缺失。原因：未将隐患台账的结构化字段正确绑定至`variables`参数，导致检索匹配不到对应业务数据。
- 现象：多轮对话后上下文丢失，无法跟踪整改进度。原因：未绑定`chatId`参数，导致每轮对话生成新的会话上下文，无法延续前序任务的状态。
- 现象：流式输出出现卡顿或中断。原因：未配置合理的`messages`历史上限，导致过多历史数据拖慢流式传输速度。

## 怎么确认配好了
- 发起单次隐患排查的多轮对话，查看`chatId`是否在会话过程中保持一致。
- 调用知识库检索接口，确认返回的文档字段与绑定的`variables`参数完全匹配。
- 测试多轮对话传递整改状态，验证第二轮对话能否正确引用第一轮输出的整改结果。
- 开启流式输出开关，查看对话过程中是否持续返回分段内容，无卡顿中断。
