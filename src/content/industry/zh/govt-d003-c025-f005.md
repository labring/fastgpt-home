# 安全生产隐患排查治理的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源于安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常文档包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，字段涵盖隐患标识、整改责任主体、整改完成时限、复查核验结果等，不同来源文档的字段顺序与命名存在差异，无统一固定格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散且格式不统一，工具调用需适配多类数据源的API接口，需配置独立鉴权规则保障不同系统的数据访问安全。每日更新的频率要求工具触发逻辑匹配日级调度，避免数据滞后或重复汇总。多样的文档结构要求插件支持解析不同格式的台账与通知书，需为不同文档类型绑定专用解析工具。本品类以隐患全流程处置为核心，工具调用需覆盖排查、整改、复查全流程，区别于其他场景仅需事后数据汇总。同时，隐患排查相关数据关联安全生产责任，工具调用失败需配置明确的告警与重试机制，防止数据汇总中断影响后续全流程处置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 指定隐患排查工具集 | 精准调用对应数据源接口，避免无关工具干扰 |
| 返回格式配置 | 启用Markdown格式 | 适配前端多模块解析，优化台账与报告的展示效果 |
| `functionCall` | 绑定专用文档解析函数 | 适配不同格式的隐患文档解析需求 |
| 重试机制配置 | 失败后重试2次，间隔60秒 | 应对临时网络波动或接口短暂异常 |
| 定时触发配置 | 每日凌晨2点触发 | 匹配数据日更新节奏，保障汇总数据的时效性 |
| 数据拉取上限 | 拉取前5条最新数据 | 匹配日常排查的批量处理需求，避免数据过载 |

## 容易做错的三处
- 现象：返回内容为纯文本无格式，前端解析后展示单调。原因：未启用Markdown格式输出配置，或未通过`functionCall`约束返回格式。
- 现象：转发中间服务后流数据断开，页面数据固定。原因：未配置流数据的持续转发逻辑，或中间服务超时未完整传递响应内容。
- 现象：Docker部署中无法找到packages/plugins/register目录，无法配置系统插件。原因：FastGPT v4.17.0的插件注册目录结构调整，需通过后台插件管理界面直接配置，无需手动创建该目录。

## 怎么确认配好了
- 调用测试接口，检查返回内容是否包含Markdown格式的标题、表格等元素。
- 查看工具调用日志，确认已触发指定的隐患数据源工具，返回数据字段匹配台账的核心要求。
- 手动触发定时任务，检查是否在设定时间自动生成符合格式的台账报告。
- 断开中间服务连接后重新接入，确认流数据可正常恢复展示或续传。
