# 安全生产隐患排查治理的台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
本品类数据来自安全生产监管系统、企业隐患自查系统、执法检查记录及事故统计系统，更新频率为每日。日常处理的文档包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，文档结构多包含隐患编号、整改责任主体、整改期限、复查结果等字段，部分文档附带现场照片或扫描件。

## 这些特征在「文档解析与分块」这一环带来什么约束
每日更新的多源异构数据要求解析流程具备稳定的批量处理能力，避免因单文件解析超时影响整体台账汇总进度。不同来源的文档格式差异较大，既有结构化表格类台账，也有带扫描件的整改文书，需保证分块时保留字段关联关系，避免将同一隐患的编号、整改期限拆分至不同分块。部分文档附带现场取证照片，需同时完成文本与图片内容的关联解析，确保后续报告生成时可完整呈现隐患场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 本品类文档多包含关联字段，该区间可保证单块包含完整隐患条目或单份整改文书核心信息，避免字段拆分 |
| `chunkSplitter` | 按段落+语义分块 | 隐患台账与整改文书的段落逻辑关联紧密，按语义分块可保留上下文完整性，便于后续汇总时关联隐患与整改记录 |
| `customPdfParse` | 开启结构化解析模式 | 本品类文档多为标准化表单或台账，结构化解析可准确提取表格字段，避免文本乱码或字段错位 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 单份含多页扫描件的整改文书或批量台账文件解析耗时较长，该时长可覆盖多数大文件解析需求 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 部分园区管委会需批量上传月度隐患排查汇总文件，该上限可满足批量处理需求 |
| `chunkSettingMode` | 手动配置 | 本品类文档格式差异较大，手动配置可灵活调整分块规则，适配不同来源的文档结构 |

本配置规则基于FastGPT v4.17.0版本的文档解析与分块模块。

## 容易做错的三处
- 调用知识库创建API后，无法获取解析中、就绪、解析失败的状态反馈。原因：未正确调用状态查询接口，或未配置API状态返回的相关参数。
- 上传含图片的PDF文档后，生成的分块内容未包含图片关联信息。原因：未开启`customPdfParse`的图片解析模式，导致图片内容未被提取。
- 解析通过HTTP接口获取的隐患数据时，响应头中的Set-Cookie字段未被正确处理。原因：未配置自定义解析规则提取响应头中的目标字段，导致数据解析不完整。

## 怎么确认配好了
- 上传单份含多字段的隐患台账PDF，检查解析后分块是否保留了同一隐患的编号、整改期限等关联信息。
- 调用API提交解析任务，通过查询接口确认可获取解析中、就绪、解析失败的状态反馈。
- 上传含现场照片的整改通知书，检查生成的分块内容是否包含图片关联文本及对应标识。
- 上传超出默认大小的批量隐患文件，确认系统未返回文件过大错误，或按配置的`UPLOAD_FILE_MAX_SIZE`正常处理。
