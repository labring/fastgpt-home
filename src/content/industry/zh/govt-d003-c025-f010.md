# 安全生产隐患排查治理的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据覆盖应急管理部门、行业主管部门、生产经营单位安全管理部门、园区管委会的日常业务文档，包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单。数据来源于安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。数据包含隐患等级、整改责任人、整改期限、复查结果等专属字段，核心业务流程围绕隐患排查、整改跟踪、复查销号的闭环管理展开。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据多源且每日更新，要求检索环节需支持实时增量召回，避免遗漏最新的整改记录与排查结果。文档类型涵盖清单、台账、通知书等多种格式，部分文档包含结构化字段与非结构化文本，要求检索需同时支持字段匹配与语义关联。数据来源覆盖监管、企业自查等多系统，需限定检索范围至本品类专属数据集，避免混入无关业务内容。此外，业务出错后果严重，要求检索结果需具备较高的置信度，精准匹配隐患判定标准与整改要求，确保台账汇总与报告生成的准确性。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.75–0.85 | 本品类数据需精准匹配隐患判定标准与整改要求，该区间可过滤低关联结果，避免误纳入非相关隐患条目 |
| `limit` | 前8条 | 台账汇总需覆盖主要隐患项，过多结果会增加大模型上下文压力，过少则可能遗漏关键整改记录 |
| `searchMode` | `vector` | 本品类数据包含隐患等级、整改期限等结构化字段与非结构化描述，向量检索可同时匹配语义关联的专业术语与字段信息 |
| `usingReRank` | 开启 | 多来源数据易出现语义相近但优先级不同的条目，重排可提升高关联结果的排序，确保核心隐患信息优先被召回 |
| `datasetSearchUsingExtensionQuery` | 开启 | 隐患排查术语多为专业表述，扩展查询可补充同义词匹配，提升对专业术语的召回覆盖 |
| `collectionIds` | 绑定本品类专属数据集ID | 需限定检索范围至隐患排查清单、治理台账等专属文档，避免混入非安全生产业务的无关数据 |

## 容易做错的三处
- 现象：检索结果中混入非安全生产隐患类的文档条目。原因：未正确配置`collectionIds`，未限定检索范围至本品类专属数据集。
- 现象：docx文档中的隐患整改记录图片无法被解析并纳入检索。原因：未开启知识库的图片识别功能，未针对docx格式启用图片解析配置。
- 现象：工作流测试时，AI回答末尾固定附带“FastGPT 是一个基于大语言模型(LLM)的知识库问答系统”。原因：未在系统提示词中移除默认的品牌介绍话术，未配置专属的系统提示词覆盖默认内容。

## 怎么确认配好了
- 检索“重大事故隐患判定标准”相关关键词，核对返回结果是否仅包含本品类的排查、整改类文档。
- 上传包含隐患现场照片的docx测试文档，验证检索结果中是否包含图片解析后的文本内容。
- 运行测试工作流，检查AI回答末尾是否存在未被预期的固定附加文本。
- 调整`similarity`参数，观察召回结果的关联度变化，确认参数取值符合本品类业务需求。
