# 工程建设项目审批的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源于工程建设项目审批管理系统、施工图审查系统、企业资质库、信用平台，更新频率为每日。日常处理的文档包括施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表，每份文档包含项目标识、建设单位信息、审批节点状态、对应资质文件编号等字段，部分字段关联单位为平方米、编号类无固定单位，数据结构围绕工程从立项到验收的审批全流程展开。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源数据来源要求多轮对话需明确指定调用的系统范围，避免跨品类数据混入；每日更新的频率要求对话触发时优先获取最新审批节点与材料信息，防止使用过期数据。多类文档与字段要求提示词需严格限定处理的文档类型与提取字段，避免混淆不同审批环节的内容。最耗时的整合与核对环节要求多轮对话需引导用户按审批节点逐步提供材料，提示词需聚焦台账汇总与报告生成的核心任务，不扩展无关业务范围。

## 配置怎么定
本配置适用于FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口大小 | 前 8000–12000 字符 | 匹配工程建设项目审批相关文档的总长度，避免截断关键审批字段 |
| `variables` | 预设项目ID、审批节点类型 | 固定提取特定台账的核心标识，减少多轮对话中的重复输入 |
| `messages` | 按对话轮次追加审批节点记录 | 保留每一轮的审批材料提交情况，用于后续报告生成的上下文关联 |
| `chatId` | 绑定对应项目的唯一会话标识 | 确保同项目的多轮对话数据不混淆，便于后续台账归档与查询 |
| 提示词模板 | 限定仅处理施工许可、施工图审查等指定文档 | 避免处理无关数据，聚焦当前品类的业务场景 |

## 容易做错的三处
- 现象：对话返回结果包含非工程建设审批相关的内容，核心审批字段缺失。原因：未在提示词中明确限定处理的文档类型，导致调用了无关数据源的信息。
- 现象：嵌入的对话页面顶部标题被意外修改，无法通过常规设置恢复。原因：未在嵌入配置中锁定页面标题参数，导致前端渲染覆盖了预设的专属标题。
- 现象：多轮对话生成的报告包含未指定的字段，偏离台账汇总的要求。原因：`messages`参数未按轮次完整追加上下文，导致后续对话丢失之前的提示词约束。

## 怎么确认配好了
- 发起测试对话，输入指定项目的审批查询指令，检查返回结果仅包含工程建设审批相关的文档内容。
- 查看会话的`chatId`参数，确认同项目的多轮对话绑定了相同的标识，台账数据未出现跨项目混淆。
- 触发报告生成动作，检查输出内容仅包含预设的`variables`中指定的字段，未出现额外无关内容。
- 验证数据更新频率，发起对话后查询当日审批节点信息，确认返回的是最新的当日更新数据。
