# 工程建设项目审批的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类服务主体为住建局、行政审批局及工程建设项目审批综合窗口，数据来自工程建设项目审批管理系统、施工图审查系统、企业资质库与公共信用平台，每日更新。日常文档包含施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表，字段涵盖项目编号、参建单位资质、审批节点状态、备案完成情况等，单份文档关联多系统属性，需跨源整合后形成完整台账。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据每日更新的特性，要求模型接入环节适配高频刷新的数据源同步逻辑，避免数据滞后影响台账准确性。多字段关联的审批文档结构，要求限制上下文总长度，防止模型处理冗余信息导致逻辑偏差。跨系统数据格式的差异，要求配置参数适配不同来源的字段映射规则。审批环节出错后果严重，要求配置容错机制，确保异常数据触发校验与重试流程。本页面配置基于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多源审批文档的字段数量与关联内容，避免上下文溢出导致截断关键审批节点信息 |
| `maxTokens` | 2000–3000 token | 匹配单份台账汇总报告的生成长度，确保覆盖全部审批材料的整合结果 |
| `quoteMaxToken` | 1500–2000 token | 限制引用的原始审批文档片段长度，防止引用内容过长干扰模型生成逻辑 |
| `temperature` | 0.2–0.4 | 降低生成随机性，确保台账数据与审批文档的字段一致性，避免出现虚构的审批状态 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的模型服务地址填写 | 适配本地或私有部署的模型接口，脱离公共模型依赖 |
| `AIPROXY_API_TOKEN` | 按申请的私有模型令牌填写 | 确保模型接口调用的身份合法性，防止未授权访问 |

## 容易做错的三处
- 现象：生成的台账中出现默认提示语，如“FastGPT 是一个基于大语言模型(LLM)的知识库问答系统”。原因：未在系统提示词中移除默认初始化文案，导致模型生成时携带冗余内容。
- 现象：调用Qwen3模型时出现非流式调用报错，且Agent节点行为异常。原因：未适配模型的流式调用要求，强制使用非流式请求导致模型接口返回错误，进而影响Agent节点执行逻辑。
- 现象：台账汇总结果出现参建单位资质信息缺失。原因：未配置合适的上下文参数，导致跨系统的资质库数据被截断，无法完整整合到台账中。

## 怎么确认配好了
- 查看系统提示词配置，确认无默认初始化文案残留，触发测试生成后无冗余提示内容。
- 调用私有模型接口，使用`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`发起测试请求，确认接口返回正常无身份验证错误。
- 上传单份施工许可申请文档，触发台账生成，核对生成结果包含全部必填字段，无缺失或错误内容。
- 模拟每日数据更新场景，触发台账重新生成，确认系统可正常拉取最新的审批管理系统数据并完成整合。
