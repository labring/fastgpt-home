# 工程建设项目审批的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来源为工程建设项目审批管理系统、施工图审查系统、企业资质库、信用平台，更新频率为每日。日常文档涵盖施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表，数据字段包含项目唯一标识、参建单位资质信息、审批节点状态、备案材料编号等，遵循政务审批标准格式，无自定义单位字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类数据每日更新，要求知识库同步频率匹配日更节奏，避免召回过期审批材料。多类结构化文档混合，需区分施工许可申请、竣工验收备案等不同类型数据的检索逻辑，防止跨类型结果混淆。数据来自多系统，需通过标签划分各数据集边界，确保检索范围精准。参建单位资质、审批节点状态为核心检索项，需匹配细分字段，提升召回准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 工程审批文档结构规整，该区间可过滤无关结果同时保留有效审批材料，避免台账汇总混入无效信息 |
| `limit` | `前8–12 条` | 台账汇总需覆盖全量相关审批节点，该范围可平衡召回完整性与处理耗时，避免过多结果增加汇总工作量 |
| `searchMode` | 向量+关键词混合 | 政务文档既有结构化字段也有文本描述，混合模式可兼顾精准匹配审批编号、资质名称等字段，与语义召回审批流程描述内容 |
| `usingReRank` | 开启 | 多源数据混合召回后，重排可优化结果排序，确保核心审批材料如施工许可申请、竣工验收备案表靠前展示，便于台账汇总 |
| `datasetSearchUsingExtensionQuery` | 开启 | 审批类问题表述规范，优化后可扩展检索边界，覆盖“竣工备案”与“竣工验收备案”等同义术语，避免遗漏相关文档 |
| `collectionIds` | 绑定工程建设审批类专属数据集ID | 精准限定检索范围，避免混入信用平台的非审批类数据，确保召回结果符合业务需求 |

## 容易做错的三处
- 现象：检索结果包含非工程建设审批类文档，字段为空。原因：未通过`collectionIds`限定检索的数据集范围，未配置对应文档的过滤规则。
- 现象：针对“参建单位资质”的提问召回结果不全。原因：未开启`datasetSearchUsingExtensionQuery`优化检索词，未覆盖资质类同义表述，导致部分相关文档未被召回。
- 现象：本地部署版本下，检索图片类审批材料无结果。原因：未启用对应图片理解模型，未配置对应数据集的图片检索支持。

## 怎么确认配好了
- 登录FastGPT v4.17.0后台，查看数据集配置项，确认`collectionIds`已绑定工程建设审批类专属数据集。
- 发起测试提问，输入“施工许可申请材料清单”，检查返回结果的条数是否符合`limit`设置，相似度是否在`0.75–0.85`区间内。
- 开启`usingReRank`后，核对返回结果的排序是否将核心审批文档放在前列。
- 测试提问同义表述，如“竣工备案表”，确认是否能召回竣工验收备案相关文档，验证`datasetSearchUsingExtensionQuery`是否生效。
