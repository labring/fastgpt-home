# 工程建设项目招投标的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自全国公共资源交易平台、地方交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，字段涵盖资质要求、业绩要求、工程量清单、施工周期等，结构随标段类型、项目规模存在差异。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的数据源要求索引支持增量同步，避免全量重建占用过多计算资源。多类型文档结构要求分块策略适配不同内容特征，评标报告的专家记录需按条目拆分，投标文件的工程量清单需保留单位关联，避免拆分破坏专业内容的完整性。专业字段如资质、工程量清单的精准匹配需求，要求向量模型适配工程建设领域专业术语，降低非专业术语的误匹配概率。多来源数据需先完成格式标准化，否则会导致索引混乱，影响后续台账汇总与报告生成的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配招标公告、投标文件等文档的段落长度，避免拆分破坏专业内容完整性 |
| 重叠长度 | 100–150 字符 | 保留分块间的上下文关联，确保工程量清单、资质要求等连续内容的向量匹配准确性 |
| `maxToken` | 4096 | 适配text-embedding-ada-002模型的输入上限，避免向量生成失败 |
| 相似度阈值 | 0.75–0.85 | 区分不同标段的资质、业绩要求，降低误匹配概率，适配招投标场景的严谨性要求 |
| 单次搜索上限 | 前10条 | 覆盖评标报告、中标公示等高频关联文档，平衡搜索速度与召回完整性 |
| `defaultToken` | 按实测标定 | 适配不同部署环境的资源限制，避免内存占用过高 |

## 容易做错的三处
- 现象：使用知识库时提示“无可检索内容”或索引状态长时间无变化。原因：未正确配置向量模型渠道，或未将模型添加至系统可用列表，导致向量生成流程中断。
- 现象：搜索速度过慢，单次查询耗时超过30秒。原因：未调整分块长度与单次搜索上限参数，导致召回过多冗余文档，或未启用增量索引同步每日更新的招投标数据。
- 现象：接入本地m3e向量模型后，界面持续显示“索引中”状态。原因：未配置模型的调用超时参数，或本地部署的模型响应延迟超出系统默认阈值，导致索引进程挂起。

## 怎么确认配好了
- 上传单份招标公告文档，触发向量生成流程，在FastGPT v4.17.0版本的系统日志中确认无报错且生成对应向量条目。
- 输入包含资质要求或工程量清单的查询词，核对召回文档的数量与相关性，确认符合预设的匹配规则。
- 触发一次增量同步操作，验证每日更新的招投标数据是否成功纳入索引库，无进度挂起情况。
- 检查配置面板中的向量模型渠道信息，确认已完成正确的密钥与地址配置。
