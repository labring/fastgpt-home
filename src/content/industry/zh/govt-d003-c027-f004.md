# 工程建设项目招投标的台账汇总与报告生成：工作流编排

以下配置基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类数据来源为全国公共资源交易平台、地方交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常处理的文档包括招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，数据字段包含标段标识、资格条件、评标专家记录、中标结果等，既有结构化表格数据，也包含非合规格式的文本内容。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散要求工作流配置多源数据拉取节点，每日更新节奏需绑定定时触发规则，避免数据滞后。文档类型多样，需适配结构化表格与非结构化文本的解析配置，保障不同格式的招标文件、评标报告均可正确提取字段。全流程字段覆盖要求台账汇总环节按招标、评标、中标等环节拼接数据，需增加字段校验节点，防止因数据缺失导致后续报告生成异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发间隔 | 1440 分钟 | 匹配数据日更频率，保障每日汇总最新台账 |
| 多源数据关联字段 | 标段编号 | 对应招投标数据的核心关联标识，确保台账数据准确对应 |
| 文档解析模式 | 自动识别+手动指定 | 覆盖结构化表格与非结构化文本的不同文档类型 |
| `variables` | 标段ID、中标金额字段名 | 用于工作流中动态传递核心业务参数，适配不同标段的汇总逻辑 |
| 异常重试次数 | 3 次 | 应对网络波动或临时接口异常，减少工作流中断概率 |
| 字段校验阈值 | 按实测标定 | 适配不同项目的字段完整性要求，避免误判有效数据 |

## 容易做错的三处
- 通过API调用获取工作流执行过程中的MCP工具调用日志为空，原因是未在`nodeId`指定的工具节点中开启日志输出开关。
- 本地部署的代码运行组件执行简单代码报错，原因是部署环境未配置对应运行依赖的基础镜像，与代码本身无关。
- 知识库检索未按标签筛选结果，原因是未在检索节点中开启标签匹配配置，且知识库录入时未正确绑定文档标签。

## 怎么确认配好了
- 手动触发工作流，检查多源数据拉取节点是否返回对应平台的招投标文档，核对数据更新时间与当日一致。
- 运行台账汇总环节，验证生成的台账是否按标段编号关联了招标、评标、中标各环节的字段。
- 触发异常重试逻辑，模拟接口超时场景，确认工作流按设定次数重试后正常完成。
- 开启标签筛选配置后，检索知识库内容，确认仅返回带有指定标签的文档条目。
