# 工程建设项目招投标的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源为全国公共资源交易平台、地方交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，数据结构兼具结构化表格字段与非结构化文本段落，字段涵盖标段标识、资质要求、评标记录、中标信息等，无统一固定格式模板。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据分散且每日更新，要求模型接入需适配多源接口拉取与增量同步逻辑。文档兼具结构化表格与非结构化文本，需配置可兼容混合格式的模型处理规则。字段无统一固定模板，需模型支持灵活抽取非标准化业务字段。核心文档如评标报告、中标结果的识别精度直接关联项目合规性，需严格控制模型输出的字段准确性，避免引发合规风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的模型接入界面制定：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配招投标文档的长文本长度，避免上下文截断导致关键字段丢失 |
| `maxTokens` | 4000 token | 控制单轮响应输出长度，确保台账汇总与报告内容完整且符合格式要求 |
| `temperature` | 0.1–0.3 | 降低随机性，保证资质、标段编号等关键信息的识别一致性 |
| `AIPROXY_API_ENDPOINT` | 按对应模型服务商的官方接口完整路径填写 | 适配多源数据拉取与模型调用的路由要求 |
| `AIPROXY_API_TOKEN` | 按实际申请的调用密钥填写 | 保障模型调用的身份合法性，避免未授权访问 |

## 容易做错的三处
- 配置模型渠道后测试返回"404 page not found"，原因为`AIPROXY_API_ENDPOINT`配置的接口地址错误或未携带正确的路径后缀。
- 上传招投标文档后显示请求失败，原因为`maxContext`配置值超出模型支持的最大上下文上限，导致请求被服务端拦截。
- 资质、业绩字段的识别结果在多轮调用中不一致，原因为`temperature`取值过高，导致模型输出随机性过强，无法稳定匹配固定业务字段。

## 怎么确认配好了
- 调用`AIPROXY_API_ENDPOINT`对应的接口地址，使用配置的`AIPROXY_API_TOKEN`发起测试请求，确认返回符合要求的模型响应格式。
- 上传单份典型招投标文档，触发台账汇总任务，检查模型输出的字段是否覆盖文档核心业务内容。
- 调整`temperature`取值，对比多轮相同文档的输出结果，确认关键字段识别的一致性符合业务校验要求。
- 模拟每日增量数据拉取流程，检查模型接入的增量同步逻辑是否正常触发与执行。
