# 市场主体登记与许可的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
市场主体登记与许可的数据来源于企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统、住所信息库，更新频率为每日。日常处理的文档包含设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等，数据字段涵盖主体名称、统一社会信用代码、登记日期、许可类型、住所信息、股东信息等，其中统一社会信用代码为18位字符格式，登记日期采用YYYY-MM-DD标准格式，各类文档均包含明确的申请主体与材料属性字段。

## 这些特征在「工作流编排」这一环带来什么约束
数据的多源分散特性要求工作流需配置多节点分别拉取不同系统的数据，并适配不同的返回格式；日更的更新频率要求触发节点需设置为每日固定时段执行，避开业务高峰时段以减少系统负载；多样的文档类型要求工作流的文档解析节点需具备通用适配能力，可处理不同格式的申请材料；严重的出错后果要求工作流需配置明确的异常分支，在核验不通过时快速触发补正流程，避免登记驳回或冒名登记等问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工作流节点能力，具体如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发周期 | 每日 02:00–04:00 执行一次 | 匹配数据日更频率，避开业务高峰，降低系统资源占用 |
| 多数据源变量配置 | 按`variables`定义的4类数据源依次拉取 | 统一管理数据源参数，适配企业登记、信用信息等多系统的数据来源 |
| 文档解析阈值 | 按实测标定 | 适配设立登记申请书、章程等多样的业务文档格式 |
| 异常节点关联规则 | 当核验节点返回失败时，关联`nodeId`为补正通知的节点 | 快速触发补正流程，降低出错带来的业务风险 |
| 代码运行超时设置 | 120 秒 | 预留足够时长完成多维度的材料核验与比对 |

## 容易做错的三处
- 现象：工作流调用代码节点时返回参数不匹配报错，日志显示body参数名与预期不符。原因：未通过`variables`定义参数名与值的对应关系，误将文件链接作为参数名传递。
- 现象：知识库搜索节点未正确加载指定的知识库数据。原因：未将传递的知识库ID绑定到`nodeId`对应的搜索节点配置中，参数传递链路断裂。
- 现象：代码节点运行后无流式输出内容返回。原因：未在代码逻辑中配置分块返回规则，未按工作流要求输出流式数据。

## 怎么确认配好了
- 查看工作流的定时触发日志，确认每日固定时段自动启动执行。
- 手动触发多数据源拉取节点，验证获取的字段与业务文档的字段一致。
- 模拟核验失败的测试场景，确认异常分支触发补正通知节点。
- 运行代码节点，验证参数传递与流式输出逻辑正常生效。
