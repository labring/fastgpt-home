# 市场主体登记与许可的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统及住所信息库，更新频率为每日。日常处理的文档类型包括设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等，每份文档包含主体名称、统一社会信用代码、登记日期、许可事项、住所信息等结构化字段，以及股东信息、审批意见等非结构化内容，文档格式多为PDF、电子扫描件及结构化表单。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据的跨系统对齐需求，要求模型接入时需支持不同数据源的统一解析与整合。每日更新的频率，则要求配置需适配增量数据的快速处理流程，避免延迟。多样的文档格式与混合的结构化、非结构化内容，要求模型的上下文处理能力需覆盖不同类型的输入内容。同时，业务出错后果直接关联主体资格与经营准入，因此模型配置需保证输出的严谨性，避免因识别偏差导致登记驳回或许可缺失。此外，不同文档的字段差异，要求配置需支持自定义字段映射，适配台账汇总的统一格式要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多份登记许可材料的完整内容容纳，避免因上下文超限触发报错 |
| `maxTokens` | 4000–6000 token | 满足台账汇总与报告生成的长度需求，平衡输出内容与调用效率 |
| `temperature` | 0.1–0.3 | 保证模型输出的严谨性，符合市场主体登记业务的合规要求，避免生成模糊或偏差内容 |
| `quoteMaxToken` | 2000–3000 token | 限定引用源数据的长度，确保汇总报告仅包含有效业务信息，避免冗余内容 |
| `AIPROXY_API_ENDPOINT` | 按官方提供的接口地址填写 | 确保模型调用指向正确的服务地址，避免连接异常或404报错 |
| `AIPROXY_API_TOKEN` | 按申请获取的密钥填写 | 完成模型服务的身份验证，保障调用权限合法，防止未授权访问 |

## 容易做错的三处
- 测试调用返回"404 page not found"，原因是`AIPROXY_API_ENDPOINT`配置了错误的接口地址，未指向有效模型服务地址。
- 模型对名称、住所等核心业务字段的识别灵活性不足，生成结果偏离业务需求，原因是`temperature`取值过高，破坏了输出的严谨性。
- 上传登记许可材料后解析超时或显示请求失败，原因是`maxContext`设置过小，无法容纳单份材料的完整内容，触发上下文超限报错。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的模型渠道配置页面中，核对`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`与官方提供的参数完全一致。
- 上传一份典型的设立登记申请书，触发模型调用，查看返回结果是否完整解析了文档中的核心业务字段。
- 调整`temperature`至预设区间，测试生成的台账汇总报告是否格式统一、信息准确，无冗余或偏差内容。
- 模拟批量导入日更数据，测试上下文处理流程，确认无超限报错或解析异常。
