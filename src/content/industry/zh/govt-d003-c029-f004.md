# 市容环卫与城管执法案件的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
该品类的数据通常来自城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。日常文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告，核心字段涵盖案件编号、违法类型、责任主体、处置进度、整改结果等，部分数据附带多媒体附件。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流配置多格式数据接入节点，适配文本、图片等不同类型的案件材料。每日更新的批量案件数据，需要设置定时触发的工作流节点，避免手动触发的遗漏。核心字段如责任主体、违法类型的准确性直接关联执法合规性，需在工作流中加入字段校验环节，确保必填项完整。案件与现场照片的绑定需求，要求配置数据关联节点，将取证材料自动关联至对应案件台账。本页面配置说明基于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 每日凌晨2点定时触发，支持手动触发测试 | 数据更新频率为每日，定时触发可保障台账每日更新 |
| `variables` | 预设案件编号、处置状态为全局变量，长度不超过4000 token | 全局变量可简化多节点调用，token限制适配大模型上下文窗口 |
| `nodeId` | 为每个工具节点分配唯一标识，按巡查→立案→整改→结案的顺序配置`nodeId` | 可确保工具按案件流转逻辑依次执行，避免调用混乱 |
| 多源数据接入 | 优先接入结构化执法平台数据，再补充非结构化投诉工单内容 | 该品类结构化数据占比更高，优先处理可提升汇总效率 |
| 字段校验 | 拦截缺失责任主体、违法类型的案件数据，超时阈值设为600秒 | 字段缺失会影响报告准确性，超时阈值保障数据处理不卡顿 |

## 容易做错的三处
- 工作流执行时部分工具未调用，且执行顺序混乱。原因是未为每个工具节点配置唯一`nodeId`，或未按业务逻辑设置节点执行顺序。
- 测试工作流时，生成内容末尾附带固定提示语。原因是未在系统提示词中关闭默认输出后缀，或未清空工作流的额外输出配置。
- 工作流运行后出现数据空白，且接口可正常调用。原因是部署时未挂载持久化存储目录，容器重启后未保留工作流与知识库配置。

## 怎么确认配好了
- 手动触发测试工作流，查看各工具节点的执行日志，确认节点按预设顺序启动并完成调用。
- 导入一条包含完整字段的测试案件数据，运行工作流后核对生成的台账与报告，确认核心字段均已正确提取。
- 检查工作流的触发配置，模拟定时触发或新数据提交，确认工作流自动启动运行。
- 查看系统配置页面，确认持久化存储目录已正确挂载，避免部署重启后配置丢失。
