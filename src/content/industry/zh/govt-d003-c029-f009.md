# 市容环卫与城管执法案件的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
该品类数据来源为城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。日常文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书与结案报告，数据字段通常涵盖案件编号、违法类型、责任主体、整改进度、处罚结果及结案时间，部分文档伴随现场照片等多媒体素材。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的案件数据规模要求模型接入配置适配批量文本与多媒体数据的处理能力，避免单次调用超时。多源异构的文档结构（文本+现场照片）要求配置支持视觉解析能力，适配非结构化素材提取。案件字段不统一的特性，要求配置的信息抽取规则具备灵活性，覆盖不同类型执法案件的字段需求。现场取证类素材的准确性要求，需配置合理的内容校验参数，确保提取的违法类型、责任主体等信息符合业务规范。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxTokens` | 8000–12000 token | 适配单份案件台账汇总与多份案件报告生成的总内容长度，避免输出截断 |
| `vision` | 开启 | 支持现场照片等多媒体素材的内容解析，提取案件关键视觉信息 |
| `temperature` | 0.3–0.5 | 降低生成内容的随机性，确保执法案件的责任认定、处罚依据等内容符合业务严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 按平台实测标定 | 适配城管执法系统的网络访问环境，确保模型调用链路稳定 |
| `AIPROXY_API_TOKEN` | 与对应模型服务绑定 | 保障模型调用的身份合法性，避免未授权访问 |

## 容易做错的三处
- 生成的Markdown表格无法正常渲染，展示内容被截断。原因是`maxTokens`取值不足，无法承载完整的台账表格与报告内容，导致输出被强制截断。
- 模型调用返回空的责任主体字段。原因是未开启`vision`配置，无法从现场照片中提取关联的责任主体信息，导致抽取结果缺失。
- 模型调用超时，返回连接错误状态码。原因是`AIPROXY_API_ENDPOINT`配置的访问地址与实际网络环境不匹配，导致请求无法正常送达模型服务。

## 怎么确认配好了
- 上传单份包含文本与现场照片的典型案件文档，触发台账汇总与报告生成，检查生成内容是否覆盖所有必填业务字段。
- 测试批量案件数据的连续调用，确认模型调用链路无超时或连接错误。
- 调整`temperature`参数，对比生成内容的严谨性，确保生成的处罚依据、整改要求等内容符合业务规范。
- 验证生成内容的Markdown格式，确认表格与文本段落可正常渲染展示，无内容截断情况。
