# 建设工程质量安全监督的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自工程质量安全监管系统、施工现场实名制平台、监理日志、检测报告，更新频率为周。日常文档包含监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告，数据字段包含工程唯一标识、检查时间、整改要求、验收结论等，单份文档篇幅跨度较大，从数百字的检查记录到数千字的竣工验收监督报告不等。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且格式各异，需适配多源数据的预处理流程，避免索引时出现格式混乱。周更的更新频率要求支持增量索引，减少全量重索引的资源消耗。文档篇幅跨度大，短文本与长文本混合，需合理设置分块参数，平衡语义完整性与向量生成精度。同时文档包含结构化字段与自由文本内容，需区分两类数据的索引策略，确保检索时能精准匹配业务关键词。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体参数设置如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配本品类文档跨度大的特征，平衡语义完整性与向量精度 |
| 重叠长度 | 100–150 字符 | 避免分块间语义断裂，覆盖跨块的关键业务信息 |
| `maxToken` | 4096 token | 匹配多数主流向量模型的输入上限，适配长文档分块后的拼接需求 |
| 相似度阈值 | 0.72–0.80 区间 | 过滤低匹配度的无关文档，精准召回质量安全相关内容 |
| 单次搜索上限 | 前 10 条 | 控制检索结果规模，避免冗余信息干扰台账汇总 |
| `defaultToken` | 按实测标定 | 适配不同场景下的上下文长度需求，避免溢出或信息不足 |

## 容易做错的三处
- 现象：Excel格式的监督检查记录上传后，索引状态长时间停留且检索无结果。原因：未配置Excel数据的字段提取规则，向量化时未正确提取业务核心内容。
- 现象：知识库上传的隐患整改通知书显示索引中状态持续超过1小时。原因：未开启增量索引配置，全量索引处理周更的大量文档导致耗时过长。
- 现象：检索结果出现重复的整改通知书内容，无法合并展示。原因：未启用搜索结果合并功能，未配置重复内容的匹配规则。

## 怎么确认配好了
- 上传单份监督检查记录，查看向量生成日志，确认分块参数与配置项一致。
- 发起包含“整改时限”的检索请求，核对返回结果的条数与单次搜索上限设置匹配。
- 导入批量的监理日志文档，查看索引更新状态，确认增量更新逻辑正常运行。
- 调用向量模型接口，验证返回的向量数据与配置的`maxToken`参数匹配。
