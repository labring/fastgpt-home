# 建设工程质量安全监督的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
本品类数据覆盖住建质安站、施工单位、监理单位、建设单位的日常业务文档，包括监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告。数据主要来自工程质量安全监管系统、施工现场实名制平台、监理日志及检测报告，更新频率为每周一次。文档包含检查日期、整改时限、问题描述、验收结论等字段，部分检测报告附带数值型检测结果，需按对应检测项匹配实际单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类数据来源分散，需调用多个不同系统的插件获取数据，对插件的兼容性要求较高。文档类型多样，需适配文本类台账与多模态检测报告的不同处理逻辑。更新频率为每周一次，工具调用需配置固定周期触发，避免过度调用占用资源。部分数据需跨主体流转，工具调用需支持权限校验环节，确保数据访问合规。质量安全相关数据出错会引发严重后果，需配置失败重试与异常告警机制，本配置基于FastGPT v4.17.0版本的插件与工具调用逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配多类型业务文档与多数据源的自动调用需求，无需手动指定工具 |
| `functionCall` | 允许批量调用 | 支持同时拉取多份台账数据，提升汇总效率 |
| 单次搜索上限 | 前 3 条 | 匹配每周更新的台账数据体量，避免冗余信息干扰报告生成 |
| 超时阈值 | 600 秒 | 覆盖跨监管系统、实名制平台的数据拉取最长耗时，避免任务中断 |
| 失败重试次数 | 2 次 | 平衡调用成功率与资源消耗，适配分散数据源的偶发连接问题 |
| 插件调用范围 | 仅允许指定质安监管类插件 | 避免非授权插件访问敏感业务数据，符合行业数据安全要求 |

## 容易做错的三处
- 现象：调用`toolChoice`功能时返回模型不支持的报错，状态码为400。原因：未确认当前使用模型是否适配`toolChoice`功能，部分轻量模型未开放该配置。
- 现象：外部搜索类插件调用后无有效结果，无法补充缺失的台账信息。原因：选用的外部插件未适配国内网络环境，或未配置正确的代理参数。
- 现象：多模态检测报告无法被正确解析，纯文本类台账却能正常汇总。原因：未针对不同类型文档配置差异化的工具调用逻辑，未区分多模态与纯文本数据的处理路径。

## 怎么确认配好了
- 发起一次模拟的台账汇总任务，查看工具调用日志，确认`toolChoice`功能自动触发了对应数据源插件。
- 检查插件调用范围配置，确认仅允许质安监管类插件被调用，无非授权插件被启用。
- 模拟触发一次异常调用，查看是否触发失败重试与异常告警机制，确认重试次数配置生效。
- 分别上传多模态检测报告与纯文本检查记录，确认两类数据均能被正确处理并纳入汇总报告。
