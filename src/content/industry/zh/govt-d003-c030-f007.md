# 建设工程质量安全监督的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
本品类数据主要来自工程质量安全监管系统、施工现场实名制平台、监理日志、检测报告，更新频率为周度。日常处理的文档包含监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告。数据字段覆盖项目编号、参建单位信息、检查时间、隐患等级、整改闭环状态等，单位包含项目工期（天）、整改时限（天）、检测数值（如MPa、m）等，单份文档数据量随项目规模波动。

## 这些特征在「数据库与运维」这一环带来什么约束
周度批量数据更新要求数据库支持高效批量写入与读取，避免单条处理的性能瓶颈。多来源的异构文档，如监管系统结构化数据、监理日志非结构化文本，需要兼容结构化与非结构化存储的混合架构。数据覆盖项目全周期，字段随项目阶段动态调整，要求数据库支持灵活的schema变更。数据关联参建单位、隐患整改状态等多维度信息，需要优化关联查询性能。同时，数据关联质量安全责任，需配置实时备份与异常校验机制，防止数据丢失或错误影响后续验收与事故溯源。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:securepass@db-host:27017/fastgpt_qc` | 存储监理日志、检测报告等非结构化文档及向量化结果，兼容大文本存储与灵活字段扩展 |
| `PG_URL` | `postgresql://admin:securepass@db-host:5432/fastgpt_struct` | 存储监督计划、隐患整改通知书等结构化业务数据，支持多表关联查询 |
| `DB_MAX_LINK` | `20–30` | 适配周度批量数据导入的并发写入需求，避免数据库连接耗尽 |
| `REDIS_URL` | `redis://:securepass@cache-host:6379/1` | 缓存高频访问的项目基础信息、整改状态统计数据，降低数据库查询压力 |
| 批量数据导入并发上限 | `5–10 条/秒` | 匹配周度更新的数据规模，避免单次导入过载影响业务系统运行 |

## 容易做错的三处
- 现象：启动服务后弹出MongoDB连接失败的报错弹窗，日志显示`connection timed out`。原因：使用了存在安全漏洞的`mongo:5.0.18`版本，未更新至合规版本，导致数据库服务无法正常响应连接请求。
- 现象：批量生成竣工验收监督报告时，任务执行超时，返回状态码504。原因：未合理配置`DB_MAX_LINK`参数，连接池被批量写入请求占满，新的数据库请求无法建立。
- 现象：生成的台账中部分隐患整改记录的闭环状态为空。原因：未按周度更新频率同步最新的整改数据，部分滞后提交的记录未写入数据库。

## 怎么确认配好了
- 执行内置的数据库连接测试工具，验证`MONGODB_URI`与`PG_URL`配置的连接是否正常，无认证或地址错误。
- 导入少量测试项目的结构化与非结构化数据，检查`DB_MAX_LINK`参数是否能支撑并发写入，无连接超时或拒绝问题。
- 查看Redis缓存监控面板，确认高频访问的项目基础信息命中缓存，数据库查询次数符合预期。
- 触发一次小型批量数据同步任务，检查同步后台账的字段完整性，无缺失或错误关联的信息。
