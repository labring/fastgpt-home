# 建设工程质量安全监督的台账汇总与报告生成：模型接入与配置

本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类数据来自工程质量安全监管系统、施工现场实名制平台、监理日志、检测报告，更新频率为周。日常文档包含监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告，字段含检查点位、整改时限、验收结论等，部分文档附现场照片与检测数值，无统一通用单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
周度更新的数据规模固定，需限制上下文承载总量以避免加载过期冗余数据。多来源文档格式差异显著，需配置兼容结构化字段与非结构化附件的解析规则。现场检查记录含照片附件，需适配视觉处理能力以提取图片内的隐患描述。隐患整改闭环相关字段需精准匹配，防止混淆不同环节的台账条目，确保汇总数据的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 800–1200 字符 | 适配周度批量台账的汇总长度，避免上下文溢出 |
| `maxTokens` | 4000–6000 token | 覆盖竣工验收监督报告等长文档的生成需求 |
| `quoteMaxToken` | 1500 token | 限制引用台账片段的长度，确保报告排版清晰 |
| `vision` | 开启 | 适配监理日志、检测报告内的现场照片与数值图表提取 |
| `AIPROXY_API_ENDPOINT` | 填写部署节点的专属接口地址 | 确保模型调用的链路合规且稳定 |
| `AIPROXY_API_TOKEN` | 使用专属鉴权密钥 | 隔离不同项目的模型调用权限，保障数据安全 |

## 容易做错的三处
- 生成的报告中出现「引用标记：［1］」字样，原因：未配置`quoteMaxToken`限制引用片段的输出格式，导致系统默认携带引用标识。
- 模型调用返回结果为空，原因：未开启`vision`配置，无法解析检测报告内的现场照片附件，导致非结构化数据无法被处理。
- 单次台账汇总耗时过长，原因：`maxContext`取值过大，超出模型上下文承载上限，触发超时限制。

## 怎么确认配好了
- 上传单份监督检查记录与检测报告，验证模型能否正确提取检查点位与检测数值，确认`vision`配置生效。
- 输入周度台账汇总需求，观察生成报告是否包含指定的文档条目，确认`maxContext`适配批量数据加载。
- 检查模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`无配置错误，无调用失败记录。
- 生成包含引用片段的报告，验证是否未携带额外的引用标记文本，确认`quoteMaxToken`配置合理。
