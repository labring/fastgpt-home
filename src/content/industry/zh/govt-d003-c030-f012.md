# 建设工程质量安全监督的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
本品类的数据来自工程质量安全监管系统、施工现场实名制平台、监理日志、检测报告，更新频率为周。日常文档包含监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告，字段涵盖项目唯一标识、检查时间、整改要求、闭环确认标识、验收节点等，无额外自定义单位，数据结构围绕施工现场监督全流程展开，覆盖计划制定、过程检查、隐患闭环、验收管理各环节。

## 这些特征在「部署与升级」这一环带来什么约束
数据来源多且分散，部署时需预留多系统接口对接的配置空间，需保障`PG_URL`、`REDIS_URL`等存储配置的扩展性。周度更新频率要求部署时合理配置定时任务触发周期，避免数据同步超时。文档字段关联紧密，升级时需保证新旧版本字段映射兼容，防止台账数据丢失。监督全流程的文档涉及施工敏感信息，部署时需配置`FILE_TOKEN_KEY`保障文档访问权限，避免敏感数据泄露。跨版本升级时需验证旧版台账字段与新版配置的匹配性，防止因字段变更导致报告生成异常；生产环境部署需优先保障数据持久化配置的稳定性，避免因存储配置变更影响台账汇总。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://user:pass@host:5432/quality_supervise` | 存储台账与报告的结构化数据，使用标准PostgreSQL连接格式，端口默认5432 |
| `REDIS_URL` | `redis://:password@host:6379/0` | 缓存临时同步的现场检查数据，使用标准Redis连接格式，数据库0用于业务缓存 |
| `FILE_TOKEN_KEY` | 按实测标定 | 加密施工现场文档的访问令牌，需匹配存储服务的加密规则，保障敏感资料访问权限 |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.volces.com` | 对接工程文档存储服务，需与实际使用的对象存储服务端点一致 |
| `ROOT_KEY` | 随机生成32位字符串 | 生成系统全局权限令牌，保障后台配置与数据访问的安全性 |

## 容易做错的三处
- 现象：跨大版本升级后，全局变量配置项缺失，提示词编辑区域仅显示少量预设选项。原因：未按照版本升级文档执行配置迁移，新旧版本的全局变量存储结构发生变更，未映射旧版配置到新格式。
- 现象：部署后台账汇总任务频繁超时。原因：未根据周度数据更新频率调整缓存服务的过期时间，导致临时同步数据堆积占用资源，影响任务执行效率。
- 现象：生成的竣工验收监督报告缺失部分检查记录数据。原因：未正确配置`PG_URL`对应的数据库关联关系，未建立检查记录与验收报告的字段关联，导致数据无法正常汇总。

## 怎么确认配好了
- 执行数据库连接测试，验证`PG_URL`配置可正常读写台账与报告数据，确认连接有效性。
- 上传一份测试用的隐患整改通知书，通过`FILE_TOKEN_KEY`生成访问链接，确认文档可正常访问且无权限问题。
- 触发一次周度数据同步任务，检查`REDIS_URL`对应的缓存服务是否正常接收同步数据，确认缓存功能正常。
- 确认当前运行版本为FastGPT v4.17.0，验证版本与部署配置无兼容性冲突。
