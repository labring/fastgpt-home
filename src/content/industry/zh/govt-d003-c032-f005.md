# 投资项目立项与后评价的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源包括国资委投资监管系统、企业ERP和项目管理系统、行业市场数据、审计和财务报表。数据更新频率为季度，日常涉及的文档包含年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告、投资后评价报告。数据字段包含项目编号、立项审批文号、计划投资额、实际投资额、投产时间、后评价得分，对应单位为个、万元、天。

## 这些特征在「工具调用与插件」这一环带来什么约束
多数据源来源要求插件支持对接异构系统的API，需配置统一的字段映射规则以整合不同系统的数据格式。季度更新频率要求工具调用的定时同步任务周期匹配季度节奏，避免频繁拉取超出系统负载。多样的文档类型要求插件支持解析不同格式的立项与后评价相关文档，需配置对应的文档解析适配器。严重的出错后果要求工具调用环节配置失败重试与数据校验逻辑，确保台账数据的准确性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多类型工具调用需求，自动选择合适的插件执行台账汇总与报告生成任务 |
| `functionCall` | 开启 | 支持结构化输出报告所需的字段信息，便于后续数据整理与分析 |
| 定时同步周期 | 90 天 | 匹配本品类季度更新的数据频率，平衡数据时效性与系统负载 |
| 数据源拉取上限 | 前 1000 条 | 适配单次台账数据拉取的合理规模，避免超出接口调用限制 |
| 接口超时阈值 | 600 秒 | 适配大型项目台账数据的接口响应时间，避免因数据量过大导致调用中断 |
| 失败重试次数 | 3 次 | 应对单次接口调用的偶发异常，保障数据同步的稳定性 |

## 容易做错的三处
- 配置模型插件后响应延迟明显高于直接curl调用，原因是未关闭FastGPT内置的上下文预处理环节，额外增加了数据处理耗时。
- 调用API未输出R1思维链过程，原因是未开启`functionCall`对应的思维链输出开关，导致结构化调用时未保留推理过程。
- 台账数据检索耗时过长，原因是未配置数据源的分页拉取参数，单次拉取全量数据超出接口响应阈值。

## 怎么确认配好了
- 查看插件日志，确认数据源返回的字段与预设映射规则一致，无缺失或格式错误。
- 测试定时同步任务，确认任务按90天周期自动执行，同步结果符合季度更新的数据范围。
- 调用API接口，确认返回结果包含`functionCall`标记的结构化字段，且`toolChoice`配置生效。
- 模拟接口调用失败场景，确认系统触发预设的失败重试机制，重试后任务正常完成。
