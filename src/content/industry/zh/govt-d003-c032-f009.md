# 投资项目立项与后评价的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自国资委投资监管系统、企业ERP与项目管理系统、行业市场数据、审计财务报表。日常涉及的文档包括年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告、投资后评价报告。数据更新频率为季度，字段覆盖项目立项编号、投资额度、实施周期、投后绩效指标等，部分文档为半结构化的评审意见、会议纪要，台账数据需关联多系统的跨域字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
季度更新的数据决定了模型调用无需高频触发，可按季度批量处理全量台账数据。多来源的跨域字段要求模型需支持关联多文档上下文，避免割裂数据。半结构化的评审材料与结构化台账的混合输入，要求模型配置需兼顾长文本理解与结构化字段提取的平衡。投后评价涉及国有资产相关内容，模型调用需确保数据合规性，配置时需限制无关数据泄露。项目数量较多时，批量处理的稳定性会影响整体流程，需合理设置上下文与调用参数。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置逻辑编写，以下为适配本品类的配置项建议：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 本品类文档多为多份可研报告、评审材料组合，需容纳跨系统的关联字段上下文 |
| `maxTokens` | 4000–6000 token | 台账汇总与报告生成需输出结构化表格与分析文本，需平衡输出长度与内容完整性 |
| `temperature` | 0.3–0.5 | 投后评价与立项报告需保持内容严谨性，避免生成无关发散内容 |
| `AIPROXY_API_ENDPOINT` | 按接入模型的官方端点填写 | 确保模型请求路由正确，适配不同厂商的模型接入规范 |
| `AIPROXY_API_TOKEN` | 按平台分配的密钥填写 | 完成模型调用的身份验证，保障接口访问安全 |
| `quoteMaxToken` | 1500–2000 token | 需从多份行业报告、财务报表中提取有效引用片段，避免截断关键数据 |

## 容易做错的三处
- 现象为批量执行节点在线调试可完成全流程，但通过API调用时返回部分任务失败或未完成的状态码。原因是API调用未携带批量循环的上下文参数，而在线调试保留了会话缓存的中间变量。
- 现象为调用视觉模型时返回格式错误或无视觉分析结果。原因是未在配置中开启`vision`参数，或未正确配置模型的视觉推理端点。
- 现象为应用的token消耗统计数据为空或与实际调用不符。原因是未开启模型调用的token追踪配置，或统计逻辑未关联到本品类的台账汇总与报告生成的批量任务。

## 怎么确认配好了
- 调用测试接口，输入单份项目建议书与台账数据，核对输出的汇总内容是否包含正确的跨系统字段关联。
- 查看模型调用日志，确认`maxContext`与`maxTokens`参数的实际使用值与配置一致。
- 检查token消耗统计页面，确认已生成对应批次的消耗数据。
- 发起批量API调用，核对返回结果的数量与待处理项目数量匹配。
