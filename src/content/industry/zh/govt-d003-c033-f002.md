# 招标采购合规管理的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类的数据覆盖国央企采购中心、招标办、业务需求部门、审计纪检部门等主体的日常采购全流程文档，包括采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料。数据来源涵盖企业采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，更新频率为每日。文档包含采购方式、预算依据、评分办法、供应商资格条件等核心字段，兼具结构化表单与半结构化文本特征。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的日更新数据量随采购业务频次波动，需适配增量索引机制以避免全量索引的资源占用过高。多类型的采购文档结构差异显著，需支持对不同格式内容的统一向量化处理。核心字段如采购方式、预算依据等为合规审核的关键信息，向量检索需精准匹配此类内容，避免无关文档被召回。审计与纪检的高合规要求，决定了索引的召回准确率需满足严格的业务校验标准，且需保留原始文档用于后续溯源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配本品类采购文档、评标记录等半结构化文本的常规长度，避免关键合规条款被截断 |
| 重叠长度 | 100–150 字符 | 保留跨块的核心字段信息，如采购方式、预算依据，防止检索时丢失上下文 |
| `maxToken` | 4096 token | 适配国央企采购合同、招标文件等长文本内容，符合通用embedding模型的输入限制 |
| 相似度阈值 | 0.72–0.85 | 精准匹配合规相关的条款内容，降低非相关文档的误召回概率 |
| 单次搜索上限 | 前10条 | 覆盖合规审核所需的多维度历史记录与参考文档 |
| `defaultToken` | 按实测标定 | 适配所选embedding模型的token输出要求，确保向量存储与检索的一致性 |

## 容易做错的三处
- 建知识库时卡在索引步骤，无明确报错信息。原因是未配置增量索引触发规则，采用全量索引处理每日更新的采购数据，导致系统资源占用过高无法完成索引构建。
- 新增embedding模型后可完成索引，但搜索测试返回报错。原因是未校验新增模型的向量输出维度与FastGPT向量库的预设维度匹配，且未在配置中正确指定模型调用参数。
- 向量化后仅在数据库中存储向量数据，原始文档内容缺失。原因是未开启原始文档存储开关，或错误配置了仅保留向量数据的参数，无法满足合规溯源的要求。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本的功能设计：
- 上传单份采购计划文档，验证向量化任务可正常完成，且向量库中可检索到对应文档的向量数据。
- 模拟每日更新的数据同步流程，验证增量索引任务可自动触发且无报错日志。
- 搜索合规审核相关关键词，如“采购方式”“评标办法”，验证召回结果包含本品类的核心文档类型。
- 查看向量库的存储内容，确认原始文档与向量数据同时存在，可用于后续溯源校验。
