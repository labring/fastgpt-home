# 招标采购合规管理的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自国央企采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，每日更新。日常处理的文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料，字段覆盖采购方式、预算依据、供应商资格条件、评分细则、履约验收信息等，涉及金额、数量、时间周期等单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的多源每日更新数据、多样文档类型与差异化字段，对多轮对话与提示词环节带来明确约束。多源数据需通过多轮对话逐步整合不同平台的台账条目，避免数据滞后或不一致；多样文档要求提示词针对采购计划、评标记录、合同等不同文档预设适配规则，精准提取对应字段；全链条合规审查需求则要求多轮对话按采购方式核对、供应商资格审查、履约验收比对等环节分步推进，确保每一步校验都有对应文档支撑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定单次采购项目的唯一标识 | 隔离不同项目的对话上下文，避免数据混淆 |
| `messages` | 按合规环节拆分的对话轮次 | 分步推进采购方式核对、供应商资格审查等环节，确保上下文清晰 |
| `variables` | 绑定采购台账、评标记录等字段变量 | 直接关联业务系统的实时数据，减少手动录入误差 |
| 温度参数 | 0.1–0.3 | 确保合规审查的输出结果严谨一致，符合国央企招标采购的固定规则要求 |
| 最大上下文窗口 | 前 10–15 轮对话内容 | 适配每日更新的多源数据，避免上下文溢出导致合规字段遗漏 |
| 对话日志存储 | 开启全量存储 | 便于回溯审查过程，满足纪检审计的合规追溯要求 |

## 容易做错的三处
- 现象：在FastGPT v4.17.0中，调用多轮对话生成台账报告时，复制输出内容提示无法复制，弹出手动选择文字窗口，且生成的Markdown格式内容无回车换行。原因：未开启对话内容的自动换行配置，或浏览器环境与平台复制功能存在兼容性问题。
- 现象：在变量引用绑定业务字段后，温度参数的设置按钮消失，无法调整模型生成的严谨性。原因：变量引用的配置未正确关联`variables`参数的作用域，导致界面控件被隐藏。
- 现象：通过接口调用工作流生成合规报告后，对话日志中的运行数据字段为空，无法排查审查环节的异常。原因：未在工作流中开启对话日志的全量存储配置，或`chatId`参数未正确绑定到会话标识。

## 怎么确认配好了
- 发起一轮针对采购计划的测试对话，检查对话上下文是否正确关联`chatId`绑定的项目标识，无跨项目的上下文混淆。
- 进入变量引用的配置界面，确认温度参数的设置按钮正常显示，可调整参数取值。
- 触发接口调用工作流生成测试报告，检查对话日志是否生成完整的运行数据，包含每一轮对话的输入与输出内容。
- 复制生成的Markdown格式报告，确认内容带有正常的回车换行，无手动选择文字的弹窗提示。
