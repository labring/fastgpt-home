# 招标采购合规管理的台账汇总与报告生成：工作流编排

本文档基于FastGPT v4.17.0版本的工作流功能编写。

## 这个品类的数据长什么样
本品类数据来源为企业采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，更新频率为每日。日常涉及的文档包括采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料。数据字段包含采购方式、预算依据、评分办法、供应商资格条件、合同履约条款等，无统一固定单位，随单条业务数据匹配对应计量标准。

## 这些特征在「工作流编排」这一环带来什么约束
每日更新的数据源要求工作流配置定时触发节点，避免手动执行的延迟或遗漏。多源不同格式的数据接入需要适配不同平台的接口格式，需在工作流中加入统一的数据解析环节。文档类型多样的特征要求输入节点支持多种文档格式的解析，同时需保留各环节的执行日志以满足审计追溯要求。业务出错后果严重的属性，要求工作流配置明确的失败重试与告警机制，阻断异常流程扩散。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发节点 | 按每日凌晨2点执行 | 匹配业务数据日更频率，避开业务高峰时段 |
| JSON输入框变量绑定 | 允许选择全局变量与节点输出变量 | 适配多源业务数据拼接的需求 |
| 单次AI调用上下文上限 | 8000–12000 token | 覆盖单份招标文件加评标记录的常规文本长度 |
| 失败重试次数 | 2次 | 避免临时网络波动导致流程中断 |
| 工作流输出规则 | 仅展示最后一个AI对话节点结果 | 符合台账汇总报告仅需最终产出内容的要求 |
| `variables` 配置 | 绑定采购计划、评标记录等数据源变量 | 自动拉取最新的每日更新业务数据 |

## 容易做错的三处
- 现象：JSON输入框内无法选择已定义的全局变量，输入框仅支持手动输入JSON文本。原因：未开启工作流的变量绑定权限，或未将对应变量声明为可被JSON输入框调用的类型。
- 现象：工作流运行后展示所有AI对话节点的输出结果，未过滤中间环节内容。原因：未配置工作流的输出过滤规则，默认保留全部节点的执行结果。
- 现象：上传大额招标文件后触发400错误，流程执行中断。原因：未在工作流中加入文件内容截取或预处理逻辑，未处理超出大模型上下文限制的输入文本。

## 怎么确认配好了
- 触发定时触发节点，检查流程是否按设定时间自动启动，无手动干预的情况下完成全流程执行。
- 查看工作流的变量绑定配置，确认JSON输入框可正常调用已声明的采购、评标等数据源变量。
- 模拟超上下文长度的文本输入，验证工作流是否触发预处理逻辑，避免400错误。
- 检查工作流的输出节点配置，确认仅展示最后一个AI对话节点的汇总结果，无冗余中间内容。
