# 招标采购合规管理的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
该品类数据来源于企业采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，更新频率为每日。日常文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料。数据字段覆盖采购主体、采购方式、预算金额、评标结果、合同履约状态、审计整改项等，单位包含人民币元、项目编号、日期等，单条数据的体量随采购项目规模有所浮动。

## 这些特征在「数据库与运维」这一环带来什么约束
每日高频更新要求数据库连接池保障稳定的并发写入与查询，避免业务中断。多源异构的数据格式需要数据库支持结构化与非结构化数据混合存储，适配采购计划、评标记录等不同类型的文档。审计溯源的需求要求数据库开启事务日志与权限审计功能，保障数据可完整追溯。不同部门的访问权限差异需要数据库配合实现细粒度控制，防止敏感采购数据泄露。长文本的采购文档也需要合理配置存储与索引策略，保障后续检索效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 数据库连接池最大连接数 | 15–25 | 适配每日高频的采购数据写入与查询并发，避免连接耗尽 |
| 非结构化数据存储地址 | `mongodb://fastgpt:password@db-host:27017/fastgpt?authSource=admin` | 适配采购文档、评标记录等非结构化数据的存储与全文检索 |
| 结构化数据存储地址 | `postgresql://fastgpt:password@pg-host:5432/fastgpt?sslmode=require` | 存储采购台账、审计整改记录等需强一致性的数据 |
| 缓存服务地址 | `redis://:password@redis-host:6379/0` | 缓存高频访问的供应商库数据、采购规则，降低数据库负载 |
| 数据库连接超时时间 | 30 秒 | 避免因数据库响应延迟导致的业务中断 |
| 数据备份频率 | 每日 1 次 | 保障每日更新的采购数据可完整回溯，符合审计要求 |

## 容易做错的三处
- 现象：部署后出现数据库连接失败日志，包含`retry init root user mongo start connect init root user error`报错。原因：未正确配置`MONGODB_URI`的用户名、密码与数据库地址，或数据库服务未启动。
- 现象：通过外部管理工具操作向量库后，FastGPT无法检索到对应数据。原因：未通过FastGPT内置接口操作向量库，直接修改数据导致索引与元数据不一致。
- 现象：多部门用户无法访问对应采购数据，出现权限报错。原因：未配置数据库细粒度访问控制，或权限规则与采购中心、纪检部门的业务分工不匹配。

## 怎么确认配好了
- 登录FastGPT v4.17.0后台的数据库配置面板，查看各存储地址的连接状态，确认显示为正常。
- 手动触发一次采购数据同步任务，检查对应数据库的表或集合中是否生成了符合预期的采购数据。
- 查看数据库备份日志，确认当日的备份任务已成功执行且无异常报错。
- 切换不同权限角色的测试账号，尝试访问采购台账数据，确认权限规则按预期生效。
