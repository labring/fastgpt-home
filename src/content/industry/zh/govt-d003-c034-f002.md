# 招生入学与学籍管理的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自全国中小学生学籍信息管理系统、地方招生入学平台、户籍与房产数据库、学校教务系统。日常处理的文档包括入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表。数据更新频率为每日，核心字段包含学生身份标识、户籍地址、房产信息、入学资格条件、学籍状态等，单条数据包含结构化表单字段与非结构化说明文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源数据接入要求索引环节支持跨系统数据的格式对齐，避免重复录入与字段冲突。每日更新的特性要求配置增量索引策略，减少全量索引的资源消耗。文档包含结构化表单与非结构化审批文本，分块处理时需保留字段关联关系，避免拆分破坏学籍信息完整性。核心字段以学生身份为唯一标识，向量匹配需优先关联该字段，确保检索结果与目标学生的台账精准对应。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配招生报名表、学籍异动审批表等文档的结构，保留字段关联完整性 |
| 分块重叠长度 | 50–80 字符 | 保留相邻分块的上下文关联，避免拆分破坏学籍异动的审批逻辑 |
| 相似度阈值 | 0.72–0.85 | 区分学生身份的细微差异，避免匹配错误学籍信息 |
| `maxToken` | 4096 | 适配招生与学籍类文档的文本长度，避免截断关键审批信息 |
| `defaultToken` | 2048 | 平衡检索上下文长度与系统响应速度 |
| 单次搜索上限 | 前 10 条 | 控制返回结果的相关性与数量，适配招生台账的批量检索需求 |

## 容易做错的三处
- 现象：替换embedding模型后返回相似度数值异常，出现10000+的结果。原因：未配置相似度阈值的过滤规则，直接使用原始模型输出的分数，未适配新模型的分数区间。
- 现象：知识库上传文件后无索引进度显示，文件状态始终为未索引。原因：未添加对应模型的可用频道，或频道配置参数与系统要求不匹配。
- 现象：部署后向量数据库无法正常连接，检索任务超时。原因：未同时启动sandbox容器与向量数据库镜像，导致检索流程无法执行。

## 怎么确认配好了
- 上传单份入学报名表与学籍信息表，查看索引进度是否正常完成，无报错提示。
- 输入学生身份关键词进行检索，核对返回结果的相似度分数处于预设阈值区间内。
- 测试增量索引功能，上传当日更新的学籍异动数据，确认索引任务自动触发并完成。
- 查看系统日志，确认向量数据库连接状态正常，无超时或连接失败记录。
