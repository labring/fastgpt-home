# 招生入学与学籍管理的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
本品类数据来源包括全国中小学生学籍信息管理系统、地方招生入学平台、户籍与房产数据接口、学校教务系统。数据更新频率为每日一次，日常处理的文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表。数据字段围绕学生身份与入学资格展开，包含身份标识字段、户籍与居住核验字段、学籍异动记录字段、录取批次字段等，无额外非业务关联字段。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据接入要求数据库支持跨系统数据同步与字段映射，避免因数据源格式差异导致数据错位。日更的批量数据更新要求运维环节配置增量同步机制，减少全量拉取带来的资源占用。数据字段聚焦学生身份与资格，需严格保障字段唯一性与准确性，否则可能引发学籍重复、录取争议等问题。结构化台账文档的高频查询与写入，要求数据库集群合理分配读写资源，避免读写冲突影响业务稳定性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 指向挂载至少1000 MB存储的3节点副本集连接串 | 存储学籍异动、录取名册等高频写入的业务数据，副本集保障数据高可用 |
| `PG_URL` | 指向只读实例的连接串 | 存储招生计划、户籍核验结果等只读类结构化数据，降低读写资源冲突 |
| `DB_MAX_LINK` | `20–30 个` | 应对每日批量同步与台账查询的并发需求，避免连接数耗尽 |
| `REDIS_URL` | 指向512 MB内存的专用缓存实例 | 缓存高频复用的核验规则、学籍查重逻辑，降低数据库重复查询压力 |

## 容易做错的三处
- 导出的知识库dataset.csv仅包含index字段无content字段，原因是未正确配置数据源字段映射，未关联MongoDB对应业务表的content字段。
- 高并发场景下查询成功率偏低，返回超时或503状态码，原因是`DB_MAX_LINK`取值过低，连接池无法支撑并发请求。
- 免登录分享链接无法携带用户数据库标识id，原因是未在分享链路中配置数据库标识参数传递逻辑，未绑定对应数据源的连接标识。

## 怎么确认配好了
- 执行每日增量同步任务，检查跨源接入的学籍、招生数据是否完整无遗漏。
- 发起模拟并发查询，监控数据库连接数是否处于`DB_MAX_LINK`的取值范围内。
- 生成免登录分享链接，验证链接中是否包含指定的数据库标识参数。
- 导出知识库数据集，检查导出文件是否同时包含index与content字段。
