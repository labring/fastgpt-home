# 招生入学与学籍管理的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自全国中小学生学籍信息管理系统、地方招生入学平台、户籍与房产核验系统、学校教务系统。日常处理的文档包括入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表，字段包含学生身份标识、户籍房产信息、学籍状态、招生资格审核结果等。数据更新频率为每日，单份文档需跨系统整合多源关联信息，字段格式与业务逻辑绑定紧密。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据每日更新的特征要求模型接入需支持高频稳定调用，避免因令牌过期或接口限流导致数据同步中断。多维度关联字段与跨系统整合需求，要求配置时需预留足够的上下文空间，防止关键学籍、招生信息被截断。不同文档的字段格式存在差异，需确保模型能准确识别并处理入学资格、学籍异动等专属业务字段，避免生成错误的台账内容。单份文档包含的关联信息总量较大，调用时的上下文参数需匹配字段总量，避免上下文溢出影响报告生成。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写对应模型的官方接入地址 | 本品类需对接多源教育系统数据，需稳定的接口地址保障高频调用 |
| `maxContext` | 8000–12000 token | 单份台账整合多份学籍、招生文档，需容纳完整关联字段 |
| `temperature` | 0.2–0.4 | 台账与报告需严谨准确，降低随机生成偏差 |
| `toolChoice` | auto | 需模型自主选择是否调用工具处理学籍异动、招生计划等专属业务逻辑 |
| `quoteMaxToken` | 2000–3000 token | 需保留足够的源文档引用内容，保障报告的可追溯性 |
| `vision` | 关闭 | 本品类核心数据为结构化文档，无需视觉模型处理 |

## 容易做错的三处
- 现象为接入国内模型时显示无效令牌，oneapi接口测试正常。原因是未正确配置`AIPROXY_API_TOKEN`，或令牌权限未覆盖招生入学与学籍管理所需的模型调用范围。
- 现象为在渠道添加智普、千问2模型后，创建知识库与应用时不显示对应模型。原因是未在FastGPT的模型接入配置中同步刷新渠道列表，或配置的模型名称与渠道中定义的名称不一致。
- 现象为调用reranker模型时提示rerank error，日志显示上传成功但功能按钮无法使用。原因是配置的`maxTokens`超出了reranker模型的支持上限，或未正确配置接口超时参数。

## 怎么确认配好了
- 调用测试接口，传入单份入学报名表与学籍信息表的结构化数据，核对返回结果是否包含正确的字段关联逻辑。
- 查看FastGPT v4.17.0的模型接入日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置无格式错误，无连接超时记录。
- 模拟每日数据更新的高频调用场景，确认接口调用无令牌过期或限流报错。
- 生成一份模拟招生报告，核对引用的源文档字段是否完整，无截断或错误生成内容。
