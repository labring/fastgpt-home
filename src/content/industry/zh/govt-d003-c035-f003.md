# 排污许可管理的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类涉及的数据来自全国排污许可证管理信息平台、企业环保台账、在线监测系统、环境统计系统，更新频率为季度。日常处理的文档包括排污许可证申请表、执行报告、自行监测方案、台账记录、变更申请、许可证副本，核心字段包含许可限值、排放口编号、监测周期、排放浓度等，数据以结构化台账和非结构化文档混合形式存在，覆盖排污单位证后监管到执行报告提交的全流程合规数据。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
季度更新的数据源要求对话流程需按周期触发，避免频繁拉取全量历史数据导致资源占用过高。多类型文档与混合数据结构要求提示词需明确区分不同文档的字段规则，避免混淆台账记录与执行报告的填报要求。多源数据来源要求多轮对话中需逐步对齐不同系统的数据，确保汇总结果符合全国排污许可证管理信息平台的规范格式。合规相关的出错后果要求对话环节需内置校验逻辑，提前核对许可限值与实际排放数据的匹配性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 上下文窗口大小 | 8000–12000 token | 匹配单季排污台账与执行报告的总字符量，避免截断关键合规字段 |
| 多轮对话历史保留条数 | 前20条对话 | 覆盖单次台账审核的完整沟通流程，避免上下文丢失导致校验逻辑断裂 |
| 提示词变量配置 | `variables` | 注入季度周期、企业许可编号等专属参数，适配季更数据的个性化汇总需求 |
| 知识库召回匹配阈值 | 0.75–0.85 | 区分排污许可规范文档与其他环保资料，精准召回合规依据 |
| 接口超时时间 | 120 秒 | 适配多源数据拉取与汇总的耗时，避免任务中途中断 |

## 容易做错的三处
- 调用Java接口时返回403状态码，且无法获取对话上下文。原因是未正确配置`chatId`参数，或未绑定合法的应用访问密钥，也未通过`messages`传递有效对话历史。
- 生成的台账汇总报告术语不规范，未适配英文合规场景。原因是未通过`variables`将提示词模板中的中文合规术语替换为英文表述。
- 上传的排污许可证副本未被知识库正确召回。原因是未配置对应文档类型的分块规则，导致长文档被截断后丢失关键许可限值信息。

## 怎么确认配好了
- 调用接口时传入`chatId`参数，检查返回结果中是否包含对话上下文标识。
- 上传单季排污台账文档，验证知识库召回结果中是否包含许可限值、排放口编号等核心字段。
- 修改提示词模板，注入`variables`变量，检查生成的报告是否自动填充了对应企业的专属参数。
- 设置接口超时时间为120秒，提交多源数据汇总任务，验证未出现超时中断。
