# 政务服务事项目录与办事指南维护的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据围绕政务服务事项全生命周期维护生成，日常文档包含政务服务事项基本目录、实施清单、办事指南、标准材料目录、流程图及常见问题。数据来源为国家政务服务事项基本目录、行政许可事项清单、权责清单与地方政务服务事项库，更新频率为月度。单条事项数据包含事项名称、受理条件、申请材料、办事流程等核心字段，部分字段需严格匹配上级目录的命名规范，数据结构以层级关联的文本记录为主。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
月度更新的频率要求接口调用需适配低频批量同步场景，避免高频请求占用数据源资源。多文档层级关联的结构，要求接口支持按事项ID关联拉取实施清单、办事指南等关联文档。字段需匹配上级目录要求的特性，需要接口返回字段完整性校验能力，同时支持自定义字段映射适配不同地区的事项库差异。单条事项的多字段文本结构，要求接口支持分页返回数据，避免单次返回内容过大。比对上级目录与本级实施清单的高耗时特性，要求接口支持增量同步逻辑，仅拉取更新后的事项数据。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带应用级API Key，前缀为`Bearer ` | FastGPT官方要求调用应用接口需使用应用级密钥，区别于账户级密钥，避免权限越权 |
| 单次请求最大条数 | 前20条 | 适配月度批量同步的低频场景，避免单次请求超时 |
| `variables` | 传入`{ "updateTime": "上月最后1天" }` | 用于指定同步上月更新的事项数据，匹配月度更新频率 |
| 超时时间 | 300 秒 | 适配多文档关联拉取的响应时长，避免批量请求中途断开 |
| `responseData` | 仅返回`itemId, itemName, applyMaterials`字段 | 减少无效数据传输，适配台账汇总的核心字段需求 |
| 字段映射规则 | 按地方事项库的字段名映射至通用台账字段 | 适配不同地区政务服务事项库的字段差异，提升数据通用性 |

## 容易做错的三处
- 接口返回`400 do request failed`报错，且日志显示密钥校验失败。原因是使用了账户级API Key，未使用应用级API Key，未正确配置`Authorization`头的密钥类型。
- 批量同步时返回结果条数不足预期。原因是未设置合理的单次请求最大条数，或未传入`variables`中的更新时间参数，导致仅拉取了部分更新数据。
- 接口返回的字段包含大量冗余内容。原因是未通过`responseData`配置指定需要返回的核心字段，导致返回了非台账所需的关联文档字段。

## 怎么确认配好了
- 调用接口后检查`Authorization`头是否携带正确的应用级密钥，确认未使用账户级API Key。
- 查看接口返回的`responseData`字段是否仅包含台账汇总所需的核心事项字段，无冗余内容。
- 传入测试用的`updateTime`变量，确认接口返回的数据更新时间匹配传入的参数。
- 发起批量请求测试，验证接口响应时长未超过配置的300秒，确认无超时中断情况。
