# 政府信息依申请公开的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自政府信息公开平台、机关档案系统、公文系统及部门业务台账，更新频率不定期，随申请办理进度新增或更新。文档类型包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料等，单份文档字段包含申请编号、申请人信息、申请事由、答复内容、公开属性、办理状态等，多为半结构化文本，部分文档附带电子签章与唯一编号标识。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来多重约束。多源异构的数据来源要求索引支持跨系统数据接入与统一格式转换；不定期更新的特性需要配置增量索引机制，避免全量重建带来的资源消耗；半结构化的文档类型要求分块策略兼顾语义完整性与索引粒度，避免拆分破坏申请事由、答复内容等核心字段的关联性；以个案请求为核心的业务逻辑要求相似度判定精准匹配申请内容，避免无关文档干扰检索结果。同时，政务文档的严谨性要求索引过程保留原始文档的编号、办理状态等元数据，为后续台账汇总与报告生成提供可靠依据。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置逻辑，针对本品类的业务特征给出以下配置建议：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配政务半结构化文档的语义单元，避免拆分破坏申请事由、答复内容等核心字段的关联性 |
| 相似度阈值 | 0.75–0.85 | 匹配政务文档的语义相似度判定标准，过滤无关检索结果，同时覆盖核心相关文档 |
| `maxToken` | 4096 | 适配m3e等主流embedding模型的输入长度限制，确保文档内容完整传入 |
| 单次搜索上限 | 前 5 条 | 符合个案申请的检索需求，避免返回过多无关文档增加台账汇总的工作量 |
| `defaultToken` | 1500 | 满足台账汇总时的上下文拼接需求，确保检索结果与申请内容的关联逻辑完整 |
| 向量数据库存储空间 | 按实测标定 | 随申请办理量波动，避免预留过多资源造成浪费 |

## 容易做错的三处
- 替换embedding模型后出现相似度数值异常偏高，原因是未调整相似度阈值适配新模型的输出范围，导致原本的阈值无法正确过滤低相关性结果。
- 知识库上传后显示无索引状态，原因是未配置对应embedding模型的调用频道，或上传文档的格式不符合系统支持的类型要求。
- 搜索返回结果条数与预期不符，原因是单次搜索上限设置过低，未覆盖申请涉及的全部相关业务台账与文档。

## 怎么确认配好了
- 上传单份政府信息公开申请表，查看系统索引状态是否显示为已完成，无报错提示。
- 输入模拟的申请事由，查看返回的搜索结果是否包含匹配的文档内容与元数据字段。
- 检查embedding模型的调用日志，确认无超时、权限不足或格式错误等报错信息。
- 调整相似度阈值后，验证搜索结果的相关性变化符合预期，无明显的误判或漏判情况。
