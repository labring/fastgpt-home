# 政府信息依申请公开的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据主要来自政府信息公开平台、机关档案系统、内部公文系统、部门业务台账及相关公开规范。日常处理的文档包括政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料。数据更新无固定周期，随每条依申请公开事项的办理进度同步更新。每条数据包含申请人信息、申请事项、检索范围、公开属性判断结果、答复内容、救济途径说明等字段，以单条申请事项为最小处理单元。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据特征对多轮对话与提示词配置带来明确约束。首先，数据分散于多个业务系统，多轮对话需通过`chatId`绑定单条申请的全流程上下文，避免不同申请的信息混淆。其次，文档类型多样且字段要求严格，提示词需针对申请表、答复书等不同文档分别定义信息提取、校验规则。再者，数据更新无固定周期，多轮对话需支持实时同步最新办理进度的上下文内容。另外，办理出错会触发行政救济，提示词需强制校验法定救济途径、公开属性判断等关键内容，确保答复合规。

## 配置怎么定
本文配置基于FastGPT v4.17.0版本，具体参数与设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定单条申请的唯一编号，固定使用`{申请编号}`作为标识 | 确保每条依申请公开事项的多轮对话上下文独立，避免跨申请的信息混淆 |
| `messages` | 保留最近15轮对话内容 | 覆盖申请办理全流程的沟通记录，同时避免上下文过长导致的推理延迟 |
| `variables` | 预设`申请人信息`、`申请事项`、`答复状态`三个全局变量 | 快速调用各业务系统同步的最新数据，减少重复录入操作 |
| 提示词模板分组 | 按文档类型分为申请表解析、答复书生成、台账汇总三类 | 适配本品类多样的文档结构与处理环节，提升信息提取与生成准确性 |
| 上下文保留时长 | 30天 | 覆盖多数依申请公开事项的办理周期，确保历史沟通记录可追溯 |
| 工具调用后输出过滤 | 仅保留AI生成的最终内容与台账条目 | 避免工具调用过程中的调试信息干扰内部审核与答复输出 |

## 容易做错的三处
- 现象：工具调用完成后，对话结果中包含工具调用的日志与参数内容，未仅展示AI生成的答复。原因：未配置工具调用后的输出过滤规则，未在提示词中明确要求隐藏工具执行过程信息。
- 现象：使用同一全局标识发起多条不同申请的对话，出现申请信息混淆、答复内容错位。原因：未为每条申请绑定专属`chatId`，导致多轮对话上下文未按申请隔离。
- 现象：导入Markdown格式的文档时，图片链接丢失域名前缀，对话中无法正常加载图片。原因：未在文档预处理环节配置图片链接补全逻辑，未通过`variables`同步固定域名参数。

## 怎么确认配好了
- 发起一条测试申请的多轮对话，检查不同轮次的上下文是否仅关联当前申请的信息，无跨申请的内容混杂。
- 切换文档类型，验证提示词是否能正确提取对应文档的专属字段，如申请表的申请人信息或答复书的救济途径内容。
- 触发工具调用操作，检查输出结果是否仅保留AI生成的最终内容，无工具执行的冗余日志。
- 查看上下文保留时长配置，确认测试申请的历史对话记录在办理周期内可正常检索。
