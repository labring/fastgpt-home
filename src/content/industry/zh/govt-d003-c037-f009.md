# 政府信息依申请公开的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于政府信息公开平台、机关档案系统、公文系统、部门业务台账及政务公开相关规范文档。数据更新节奏为不定期，随申请人提交的依申请公开请求触发。日常处理的文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料，字段涵盖申请人信息、申请内容、办理进度、答复结果、救济途径记录等，无统一标准化格式，需适配多类文档结构。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散且格式不统一，要求模型接入配置支持多源数据的统一解析与抽取。不定期的更新节奏使得批量处理任务需支持按需触发，适配临时的台账汇总需求。政务文书的严谨性要求生成内容需符合官方规范，对模型生成的随机性有严格限制。同时，出错后果直接关联行政合规，需配置完善的错误捕获与重试机制，保障台账与报告的准确性。此外，依申请公开的个案属性要求模型配置支持单条申请的精准关联，避免跨申请数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖多份政务文档的上下文内容，保障台账汇总时可关联完整的申请与办理流程 |
| `maxTokens` | 2000–3000 token | 适配政务答复书、台账报告的标准篇幅要求，避免生成内容过长或过短 |
| `temperature` | 0.1–0.3 | 降低生成内容的随机性，确保政务文书的格式与表述符合官方规范 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或云端模型的调用路径，支持本地Ollama部署的模型接入 |
| `AIPROXY_API_TOKEN` | 按授权信息填写 | 保障模型调用的身份合法性，避免未授权访问 |
| `toolChoice` | 自动 | 自动触发多文档的抽取与关联，适配依申请公开全流程的台账数据汇总 |

## 容易做错的三处
- 现象：调用模型返回`401 Unauthorized`报错，API密钥与端点配置均无误。原因：未将模型接入配置绑定到政务台账专属的知识库权限，导致跨知识库调用受限。
- 现象：本地部署的重排模型请求失败，界面显示连接超时。原因：未在FastGPT配置中添加本地Ollama模型的网络访问权限，且未指定正确的本地端口。
- 现象：并发请求量上升时，台账生成任务出现超时报错。原因：未调整`maxContext`适配并发下的上下文加载逻辑，导致模型调用与数据库查询的资源竞争加剧。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型管理页面，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置与实际部署环境一致。
- 上传单份政府信息公开申请表与配套答复书样本，触发台账汇总任务，检查生成结果包含所有必填字段。
- 模拟3-5个并发请求，观察任务执行日志中无超时或权限报错，且数据库查询耗时无明显波动。
- 调整`temperature`参数至0.2，生成测试答复书，检查内容表述严谨，无冗余或随意内容。
