# 政府信息依申请公开的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
本品类的典型数据主体为政府办公室、部门政务公开办、法规处、档案室。数据来源包括政府信息公开平台、机关档案系统、公文系统、部门业务台账及政府信息公开条例相关规范。日常处理的文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料。数据更新频率为不定期，字段主要涵盖申请人信息、申请事项、公开属性判断依据、答复内容、送达记录等，无固定批量更新节奏。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源分散的数据来源要求检索环节适配不同格式的政务文档，需支持跨系统文档的语义匹配。不定期的更新节奏意味着知识库同步需按需触发，避免冗余的全量更新。个案导向的文档结构要求检索精准匹配申请人的具体申请事项，无法依赖泛化的关键词匹配。台账汇总与报告生成的业务需求要求召回的文档需覆盖申请全流程的关联材料，确保汇总信息完整。同时，政务办理的严格要求使得检索结果的准确性直接影响后续答复质量，需严格控制无关召回内容。

## 配置怎么定
本页的配置建议适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配政府信息依申请公开的精准事项描述，过滤无关召回内容 |
| `limit` | `前10条` | 覆盖个案申请涉及的多份关联文档，同时控制上下文长度符合业务需求 |
| `searchMode` | `embedding` | 适配多源异构的政务文档，优先通过语义匹配定位相关内容 |
| `usingReRank` | `开启` | 提升答复书、补正告知书等特定政务文档的召回排序准确性 |
| `datasetSearchUsingExtensionQuery` | `关闭` | 避免扩展查询偏离申请人的具体申请事项，确保检索精准性 |
| `collectionIds` | `按部门专属知识库配置` | 实现部门数据隔离，符合政务数据安全管理要求 |

## 容易做错的三处
- 现象：检索时返回`invalid configuration parameter name "hnsw.iter"`报错。原因：误用了FastGPT官方未支持的配置参数名，未使用指定的参数列表。
- 现象：非授权账号可访问本部门专属知识库内的文档。原因：未通过`collectionIds`配置部门专属的知识库集合，未实现数据隔离。
- 现象：检索结果条数不足，无法覆盖申请涉及的全部关联文档。原因：`limit`参数取值过低，未覆盖个案所需的多份政务文档。

## 怎么确认配好了
- 进入FastGPT知识库检索配置界面，确认使用的参数名称均属于官方支持的范围。
- 使用测试账号发起模拟申请检索，核对召回的文档仅来自当前部门绑定的专属知识库集合。
- 模拟提交多类政务申请，检查检索结果是否覆盖申请表、答复书等相关文档类型。
- 查看检索日志，确认未出现非法配置参数的报错提示。
