# 政府信息依申请公开的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
政府信息依申请公开的台账数据，来源为政府信息公开平台、机关档案系统、公文系统、部门业务台账及政府信息公开相关规范。日常处理的文档包括政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料。每条数据对应单个依申请公开个案，包含申请标识、申请人信息、申请内容、办理环节记录、相关文件等字段，更新频率不定期，无固定批量同步节奏。

## 这些特征在「部署与升级」这一环带来什么约束
数据来源分散且涉及政务内部系统，部署时需配置多数据源的鉴权与访问白名单，避免未授权访问；文档类型多样且格式不统一，升级时需新增对应文书格式的解析适配规则；更新频率不定期，部署时需预设增量同步触发逻辑，避免全量拉取占用政务系统资源；每条数据对应单个个案，台账汇总需按申请编号、办理周期等维度聚合，部署时需预设字段映射规则；涉及行政复议材料，数据存储需符合政务数据安全要求，升级时需同步更新存储加密配置。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本，适配政府信息依申请公开场景的部署与升级需求：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://gov-admin:securePass@internal-mongo:27017/gov_apply?authSource=admin` | 对接政府部门内部档案系统、公文系统的台账数据，配置对应数据库的访问地址与鉴权参数 |
| `REDIS_URL` | `redis://:redisPass@internal-redis:6379/0` | 缓存申请办理状态、临时文件校验信息，过期时间按实测标定 |
| `STORAGE_S3_ENDPOINT` | `https://gov-storage-cloud.example.com` | 存储答复书、送达回证等电子文件，适配政务云存储节点地址 |
| `FILE_TOKEN_KEY` | `32位随机字符串` | 加密存储申请相关文件的访问令牌，避免未授权访问 |
| `ROOT_KEY` | `按政务内部安全规范生成的密钥` | 配置系统管理员鉴权，限制仅政务公开办工作人员可访问台账汇总功能 |
| `DB_MAX_LINK` | `10–15 个连接` | 限制数据库连接数，避免同时拉取多份申请数据时占用过多政务系统资源 |

## 容易做错的三处
- 现象：部署后执行台账汇总任务时返回 MongoDB 连接超时，日志显示 11000 状态码。原因：未配置政务内网的数据库访问白名单，部署节点无法访问内部业务系统的 MongoDB 实例。
- 现象：生成的报告中部分申请的答复书内容缺失。原因：未正确配置`FILE_TOKEN_KEY`导致无法读取加密存储的答复文件，或字段映射规则遗漏了答复内容字段。
- 现象：升级后无法触发增量数据同步。原因：未更新`REDIS_URL`的鉴权参数，导致缓存的同步标记无法正常写入。

## 怎么确认配好了
- 执行数据库连接测试命令，验证`MONGODB_URI`配置的数据库可正常读写申请台账数据。
- 上传一份模拟的政府信息公开申请表，检查系统是否能正确解析并提取申请人、申请内容等核心字段。
- 访问配置的`STORAGE_S3_ENDPOINT`存储节点，确认上传的答复书文件可正常读取。
- 使用管理员密钥`ROOT_KEY`登录系统，检查台账汇总与报告生成的权限是否仅开放给指定角色。
