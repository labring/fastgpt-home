# 政府采购项目的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源包括中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统、供应商信用记录，更新频率为每日。日常文档涵盖采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复，涉及主体为采购人单位、财政部门政府采购监管处、采购代理机构、评审专家。各文档包含品类专属字段，如采购预算编号、供应商信用等级、评标委员会成员名单等，结构随文档类型差异明显。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的数据源要求多轮对话需支持实时拉取最新数据，避免使用过期的采购计划或中标公告内容。多类文档结构差异要求提示词需区分不同文档类型的字段规则，例如评标报告需提取评标结果，而质疑答复需聚焦投诉事项的处理结果。多字段的文档内容要求多轮对话需逐步确认字段完整性，避免遗漏采购预算编号等关键信息。不同主体的使用场景要求提示词适配不同角色的需求，例如监管处需关注合规性，采购人需关注采购进度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 会话生成的唯一标识 | 多轮对话需通过`chatId`关联历史交互与当前上下文 |
| `messages` | 保留前20条交互记录 | 政府采购多轮对话需保留足够的历史参数与文档信息，避免上下文截断 |
| `variables` | 绑定采购项目编号、代理机构名称等专属变量 | 多轮对话需通过`variables`传递品类专属字段，提升匹配精度 |
| 最大上下文长度 | 8000–12000 token | 适配政府采购文档与交互内容的总长度需求 |
| 会话过期时间 | 24小时 | 本品类数据每日更新，需每日重置会话以获取最新采购相关信息 |
| 单次召回文档数 | 前5条 | 政府采购相关数据源文档数量较多，优先召回最匹配的内容 |

## 容易做错的三处
- 对话日志未自动清理导致上下文溢出，表现为会话返回“上下文长度超限”报错。原因是未配置会话过期时间，未按每日更新节奏重置`messages`历史记录。
- 线上调用时提示未选择知识库，但调试预览正常，表现为前端界面显示“未绑定知识库”。原因是线上环境未绑定政府采购专属数据源的权限，调试时使用了本地测试的数据源配置。
- 生成的台账字段缺失，表现为采购台账缺少供应商信用等级字段。原因是未通过`variables`传递供应商信用记录的专属变量，提示词未覆盖该字段的提取规则。

## 怎么确认配好了
- 发起包含政府采购专属术语的提问，查看会话详情，确认`chatId`被正确生成并关联当前交互，验证多轮对话上下文关联功能正常。
- 调用配置后的工具，核对返回的知识库内容是否仅包含政府采购类数据源的文档，验证知识库绑定规则生效。
- 发起连续多轮提问，查看`messages`的保留数量是否符合配置要求，验证上下文截断规则生效。
- 等待24小时后发起提问，核对返回的文档是否为最新的政府采购数据，验证会话过期时间配置生效。
