# 政府采购项目的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
政府采购项目相关数据来源于中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常涉及的文档包括采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复等，各文档包含固定字段，如唯一项目编号、采购预算金额、供应商资质信息、质疑答复文号等，不同来源的数据格式存在差异，部分字段需跨系统交叉校验。

## 这些特征在「工具调用与插件」这一环带来什么约束
每日更新的多源数据要求工具调用需设置定时拉取任务，避免使用过期数据。多来源的异构文档需插件适配不同格式的解析规则，保障字段提取的一致性。政府采购项目的合规性要求严格，工具返回的数据需经过字段校验，否则可能引发废标或监管处罚。单次处理的文档数量较多，工具调用需设置合理的并发上限，避免超出系统接口限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `"auto"` | 适配政府采购场景下多类型文档的自动工具调用需求，无需手动指定工具 |
| `functionCall` | `{"parameters": {"required": ["project_id", "budget_amount"]}}` | 强制提取政府采购文档的核心必填字段，保障台账数据完整性 |
| 工具超时阈值 | `600 秒` | 政府采购数据拉取涉及多平台接口，单次请求耗时较长，避免因超时中断任务 |
| 单次调用数据上限 | `800–1200 字符` | 适配政府采购单份文档的常规内容长度，避免超出接口传输限制 |
| 工具重试次数 | `3 次` | 处理质疑答复、评标报告等关键文档时，保障数据拉取的成功率 |
| 插件资源托管路径 | `/data/gov_plugins` | 统一管理政府采购专用的解析插件与资源文件，保障调用稳定性 |
| FastGPT 版本 | `FastGPT v4.17.0` | 保障插件与工具调用功能的兼容性，使用最新稳定版的配置规则 |

## 容易做错的三处
- 现象：调用`api/v1/chat/completions`接口获取流数据后，提取的采购预算金额字段为空。原因：未按政府采购文档的固定字段结构解析流数据，未对提取的字段进行完整性校验。
- 现象：工具调用完成后，输出内容同时包含工具请求参数与AI生成的对话结果。原因：未配置`functionCall`的输出过滤规则，未开启仅返回AI对话结果的设置。
- 现象：在MCP Host上展示工具生成的采购数据折线图时，页面返回404错误。原因：未配置插件的静态资源托管路径，未将生成的HTML文件关联到可访问的公共链接。

## 怎么确认配好了
- 发起模拟调用，传入一份包含项目编号、预算金额的政府采购测试数据，检查工具是否自动触发数据拉取、字段提取与台账汇总操作。
- 查看工具调用日志，确认返回内容仅包含AI生成的汇总报告，无原始工具调用的请求参数或接口响应原始文本。
- 上传一份政府采购招标文件的测试文件，检查工具能否正确提取采购需求、供应商资质要求等核心字段。
- 触发生成汇总台账的工具调用，检查生成的文档格式是否包含项目编号、中标信息等政府采购文档的常规字段。
