# 政府采购项目的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
本品类数据主要来自中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常处理的文档包含采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同与质疑答复等。数据字段涵盖采购项目编号、预算金额、供应商资质、评标结果、合同金额等，不同文档对应专属字段，如评标报告含评审专家签字项，中标公告需标注项目预算与中标金额，不同主体需按各自职责维度汇总台账数据。

## 这些特征在「部署与升级」这一环带来什么约束
每日更新的数据要求部署时配置稳定的增量同步机制，避免全量拉取占用过多系统资源。多类型文档的结构化处理需要适配不同字段的解析规则，升级时需兼容旧版文档的字段映射逻辑，防止历史台账数据无法正常读取。供应商信用记录的实时调用需配置可靠的外部接口权限，升级时需同步更新接口校验规则，避免同步失败。财政监管相关文档的敏感字段需额外配置权限校验，升级时需同步更新权限控制逻辑，防止越权访问。不同主体的台账汇总维度存在差异，部署时需预留自定义汇总模板的配置入口，避免硬编码限制使用场景。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/gov_purchase?authSource=admin` | 存储政府采购项目的全量台账数据，需指定专属数据库名与认证信息 |
| `REDIS_URL` | `redis://:redis_pass@redis_host:6379/0` | 缓存每日同步的增量数据与接口调用结果，降低重复请求开销 |
| `DB_MAX_LINK` | `100–200 连接` | 适配政府采购系统的并发访问量，避免数据库连接耗尽 |
| `FILE_TOKEN_KEY` | 随机生成32位字符串 | 加密存储上传的招标文件、投标文件等附件，防止敏感文档泄露 |
| `STORAGE_S3_ENDPOINT` | `http://s3-compatible-endpoint:9000` | 存储批量导出的台账报告与原始文档，适配合规存储要求 |
| `ROOT_KEY` | 按业务场景生成复杂密钥 | 配置系统管理员的最高权限，用于管理台账汇总的自定义模板 |

## 容易做错的三处
- 现象：Docker容器启动后始终监听3000端口，无法通过配置文件修改端口。原因：未在docker-compose.yml中正确配置端口映射参数，或未覆盖镜像内置的默认端口环境变量。
- 现象：台账汇总结果缺失供应商信用记录字段。原因：未配置供应商信用记录的数据源同步任务，或未在汇总模板中勾选对应字段的展示权限。
- 现象：批量生成报告时出现连接超时错误。原因：未调整`DB_MAX_LINK`的配置值，导致数据库连接耗尽，无法处理并发的台账生成请求。

## 怎么确认配好了
- 执行`docker ps`命令，查看容器状态为正常运行，端口映射与配置文件中设置的参数一致。
- 上传一份测试用的招标文件附件，验证附件可正常存储并通过加密链接访问。
- 触发一次手动数据同步任务，查看系统日志无数据拉取或存储报错，确认数据源配置生效。
- 使用`ROOT_KEY`对应的管理员权限，可正常创建、修改台账汇总的自定义模板。
