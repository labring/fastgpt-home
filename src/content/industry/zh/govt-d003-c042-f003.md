# 法务合规与重大风险管理的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
数据来自企业合同管理系统、合规风险数据库、法律法规库、案件管理系统、举报平台，更新频率为月。日常文档包含合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告，文档字段包含风险类别、审核主体、事项编号、违规情节等，无统一固定单位，随具体文档类型变化。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来自多个分散的内部系统，多轮对话需逐步整合不同来源的台账数据，避免上下文割裂。月更新频率要求提示词需定期关联最新的合规数据库内容，确保风险判断时效性。多样的文档类型要求提示词适配不同字段的提取逻辑，例如从合同审核意见中提取合规条款，从违规调查报告中梳理处理流程。重大风险的出错后果要求多轮对话需明确上下文边界，防止遗漏关键合规信息。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 固定关联当前合规台账的会话ID | 确保多轮对话上下文绑定对应合规项目，避免跨项目数据混淆 |
| `messages` | 保留前10轮对话上下文 | 合规台账数据量较大，过多上下文会增加处理负荷，10轮可覆盖常规合规审查的对话逻辑 |
| `variables` | 传入当前合规事项的编号、文档类型标签 | 让提示词精准匹配对应台账的字段规则，适配不同文档的提取需求 |
| 问题优化 | 按实测标定 | 合规类问题需明确业务场景，优化后可提升风险识别的精准度 |
| 最大上下文 | 8000–12000 token | 合规文档包含多类字段，足够的上下文可确保提示词完整获取台账信息 |
| 单次搜索上限 | 前5条 | 合规风险数据需优先匹配高优先级条目，5条可覆盖常规检索需求 |

## 容易做错的三处
- 现象：对话节点返回空内容或报错提示。原因：未传入合规事项专属的`variables`参数，提示词无法匹配对应台账的字段规则。
- 现象：删除对话记录后仍保留历史内容。原因：未正确调用`chatId`对应的会话清理接口，导致上下文残留。
- 现象：飞书在线文档链接无法被正常读取。原因：未配置文档读取的权限适配，或提示词未指定飞书文档的解析逻辑。

## 怎么确认配好了
- 手动传入测试用的合规事项`variables`参数，检查对话是否能正确提取对应台账的字段信息。
- 调用会话清理接口，验证`chatId`绑定的对话记录是否被完全删除。
- 上传飞书在线文档链接，检查系统是否能正常解析文档内容并纳入上下文。
- 开启问题优化配置，发起合规相关提问，检查是否生成对应业务场景的问题建议。
