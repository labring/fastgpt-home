# 法务合规与重大风险管理的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
数据来源为企业合同管理系统、合规风险数据库、法律法规库、案件管理系统、举报平台。日常处理的文档包括合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告，单条数据包含风险类别、涉事主体、审核意见、处理进度、关联合同编号等字段，更新频率为月度。

## 这些特征在「工作流编排」这一环带来什么约束
月度更新的频率要求工作流支持定时触发配置，无需高频实时响应。多数据源接入的需求，要求工作流中配置多个数据拉取节点，适配不同系统的接口格式与文档结构。单条数据包含多维度字段的特性，要求工作流中配置字段提取节点，精准抽取合规风险等级、处理状态等关键信息。耗时环节较多的业务特性，要求工作流拆分节点并支持并行或串行编排，同时配置超时与重试机制，避免单节点卡顿影响整体流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 问题优化 | 前置到数据拉取节点之后 | 针对合规风险清单、审核意见等长文本，优化后可提升关键词提取精度 |
| 最大上下文 | 8000–12000 token | 适配合规类文档的长文本长度，避免截断关键审核意见 |
| `variables` | 绑定月度更新时间、风险等级枚举值 | 适配月度更新的频率要求，统一流程中的变量参数 |
| `nodeId` | 为每个数据拉取节点分配唯一标识 | 便于追踪不同数据源的执行状态，排查流程错误 |
| 超时设置 | 600 秒 | 覆盖合规审查、风险识别等耗时环节的执行时长 |
| 重试次数 | 2 次 | 避免单次接口调用失败导致流程中断，同时防止重复提交引发数据冗余 |

## 容易做错的三处
- 现象：工作流运行后返回的合规风险条目为空，原因：未在`variables`中配置数据源字段的映射规则，导致节点无法从合同管理系统拉取的文档中提取有效信息。
- 现象：智能体节点运行时报错提示“节点未找到”，原因：未为每个数据拉取节点分配唯一的`nodeId`，导致流程调度无法定位对应执行节点。
- 现象：工作流执行超时，状态码显示504，原因：未设置适配合规审查环节的超时阈值，默认时长不足以完成长文本的风险识别与审核。

## 怎么确认配好了
- 手动触发工作流，核对拉取的文档数量与数据源的月度更新条目数一致。
- 查看流程日志，确认每个节点的`nodeId`均已正确绑定且无重复。
- 检查`variables`中的参数配置，确认已覆盖合规风险的关键字段与更新周期。
- 模拟异常触发，验证超时与重试机制是否按配置生效。
