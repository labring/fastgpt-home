# 环境执法与监测监管的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自生态环境在线监控平台、污染源自动监测系统、生态环境执法办案系统及第三方检测机构提交的报告。日常生成的文档包括现场检查记录、采样原始记录、正式监测报告、责令改正决定书与行政处罚决定书，字段包含监测点位编号、污染物浓度值、执法时间、整改要求、处罚事由等，单位涉及mg/m³、mg/L、小时等。数据按日更新，单份文档的内容体量存在差异。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源数据的混合接入要求索引系统兼容结构化自动监测数据、半结构化执法记录与非结构化正式报告，需支持多格式数据的统一向量化处理。按日更新的频率要求索引支持增量同步，避免每日全量重建带来的资源消耗。单份文档内容跨度差异大，需适配灵活的文本分块规则，确保关键信息如超标浓度、执法时间不被拆分或截断。执法证据的关联性要求索引保留字段级关联，召回结果需可追溯至对应监测点位或执法环节，支撑后续台账汇总与报告生成的逻辑关联。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 本品类文档既有短的现场检查记录，也有长的正式监测报告，该区间可平衡信息完整性与向量匹配精度 |
| 重叠长度 | 100–150 字符 | 避免跨块的关键信息如监测点位编号、执法人员姓名被拆分丢失 |
| 相似度阈值 | 0.75–0.85 | 需精准召回对应执法时段或监测点位的相关数据，避免无关内容混入台账汇总环节 |
| `defaultToken` | 4096 token | 多数执法与监测核心文档的总token数在此范围内，可完整加载单份关键文档 |
| `maxToken` | 8192 token | 台账汇总需整合多份关联文档内容，该取值可支撑跨文档的上下文关联 |
| 单次召回上限 | 前 8 条 | 执法场景需精准匹配，过多召回会增加后续人工筛选的成本 |

## 容易做错的三处
- 现象：索引建立失败，后台日志显示文件解析异常。原因：未开启多格式数据解析适配，本品类包含excel格式的监测台账与多维文档格式的执法记录，未配置对应解析规则。
- 现象：向量召回结果条数与预期不符，部分关键监测数据未被召回。原因：相似度阈值设置未结合本品类数据的字段特征进行实测标定，过高或过低都会影响召回精准度。
- 现象：embedding模型调用报错，无法生成向量。原因：未单独配置索引专用模型，直接通过跨服务接入调用通用embedding接口，导致调用链路超时或权限校验失败。

## 怎么确认配好了
- 上传单份现场检查记录与监测报告，查看索引生成进度，确认无解析报错提示。
- 输入“2024年5月10日XX点位COD浓度”类的精准查询，核对召回结果包含对应时段与点位的相关数据。
- 进入索引配置页面，确认`defaultToken`与`maxToken`的取值与预设配置一致。
- 导入批量日更数据，验证增量索引可正常同步，未触发全量索引重建。
