# 环境执法与监测监管的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
本品类的核心数据来自在线监控平台、污染源自动监测数据、生态环境执法系统及第三方检测报告，更新频率为每日。日常产出的文档包含现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书，单份文档包含采样点位、监测因子、浓度值、执法时间、整改要求等固定字段，部分监测数据带有微克/立方米、毫克/升等专业单位，执法文书则包含执法主体、相对方名称、违法事实等标准化字段。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据多源异构且每日更新，要求工作流需配置日级定时触发节点，确保同步最新的在线监控、执法系统及第三方检测数据。不同类型文档的字段结构差异较大，现场检查记录侧重执法场景字段，监测报告侧重监测参数，工作流需按文档类型配置差异化的字段提取规则。专业监测数据带有专业单位，工作流需保留单位信息，避免数据解析失真。执法文书的标准化字段要求工作流精准匹配固定字段，确保生成的报告符合监管要求。多源数据的格式差异也要求工作流配置数据清洗环节，统一不同来源的数据结构。

## 配置怎么定
本页面基于FastGPT v4.17.0版本配置。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 定时触发频率 | 每日凌晨2:00至4:00 | 避开执法、监测业务高峰，减少系统冲突 |
| 数据源节点类型 | HTTP请求节点、本地文件导入节点 | 覆盖在线监控平台API、第三方检测报告上传两类数据来源 |
| `variables` | 按文档类型预设监测因子、执法时间、整改要求 | 匹配不同文档的固定字段，便于报告生成时调用 |
| 节点执行超时时间 | 600秒 | 适配多源数据同步、报告生成的平均耗时 |
| 文件预览关联配置 | 绑定原文件存储路径 | 支持引用片段对应的原文件在线预览 |
| `nodeId` | 按数据流转顺序配置唯一标识 | 明确工作流各节点的执行顺序，便于排查异常 |
| 单次召回结果上限 | 前10条 | 适配执法、监测文档的字段提取需求，避免冗余数据 |
| 单文件上传上限 | 1000 MB | 适配第三方检测报告的大容量文档需求 |

## 容易做错的三处
- 现象：工作流生成的报告关联的文件链接无法打开原文档，仅显示知识库切片片段。原因：未通过`variables`绑定原文件的实际存储路径，仅调用了切片后的片段信息。
- 现象：工作流测试时返回状态码500，节点执行失败。原因：未针对多源异构数据配置格式转换环节，导致不同来源的数据无法统一解析。
- 现象：HTTP请求节点调用本地脚本接口时无返回内容。原因：未正确设置节点的请求超时参数，或未开放对应端口的网络访问权限。

## 怎么确认配好了
- 触发一次工作流，检查各数据源节点是否成功拉取对应类型的文档，核对数据更新时间与当日时间一致。
- 查看工作流的`variables`配置，确认已预设对应文档类型的固定字段，可在测试节点中调用验证。
- 点击报告中关联的文件链接，确认可跳转至原文件的在线预览页面。
- 查看工作流的`nodeId`配置，确认各节点的执行顺序与数据流转逻辑一致，无节点遗漏或顺序颠倒。
