# 用地预审与规划许可的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据来源为国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。日常核心文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，数据字段涵盖项目名称、选址坐标、用地规模、许可编号、前置审批节点状态等，单位涉及平方米、公顷、项目编号等，单条数据关联多类前置审批文件与空间管控数据。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源异构的数据来源要求接口需兼容不同格式的返回结果，不定期更新的特性要求接口支持按需触发。日常文档包含空间坐标类与文本审批类两类数据，接口需适配两种字段的解析逻辑，避免混淆空间数据与文本字段。单条数据关联多类前置审批文件，接口调用需携带项目唯一标识作为参数，确保拉取的数据与对应项目精准绑定。同时，数据出错会导致项目立项受阻，接口需返回明确的状态标识与错误信息，便于后续排查。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | 从`variables`读取动态令牌 | 适配不同项目的接口访问权限，避免硬编码令牌导致的安全风险 |
| `variables` | 存储项目ID、接口地址、数据类型参数 | 便于多项目调用时快速调整参数，无需修改接口配置 |
| `responseData` | 提取指定字段并转换为结构化表格 | 适配台账汇总的批量数据整理需求，便于后续报告生成 |
| 超时设置 | 30-60秒 | 考虑到空间数据拉取的耗时，避免因请求超时导致数据不完整 |
| 重试策略 | 失败后重试2次 | 应对临时网络波动或接口短暂不可用的场景 |
| 响应数据缓存时长 | 24小时 | 避免重复拉取相同的非实时数据 |
| 单次请求数据量上限 | 500条 | 避免单次请求数据量过大导致接口响应缓慢 |
| 字段映射规则 | 按业务文档字段匹配 | 确保提取的数据与台账字段一一对应，便于报告生成 |

## 容易做错的三处
- 接口请求被自动添加额外的Bearer令牌，导致身份校验失败。原因是未关闭FastGPT内置的自动令牌补充逻辑，导致请求头中出现重复的身份校验字段。
- 台账数据字段为空或与实际业务文档不符。原因是未按业务文档配置字段映射规则，导致提取的字段与台账要求不匹配。
- 接口调用超时或返回数据不完整。原因是超时设置过短，未适配空间数据拉取的耗时需求。

## 怎么确认配好了
- 调用测试接口，查看请求头中`Authorization`的取值是否与配置一致，无额外自动添加的令牌。
- 传入测试项目ID，检查接口返回的字段是否包含项目名称、用地规模等业务文档要求的字段。
- 模拟网络波动场景，确认接口在失败后会执行预设的重试策略。
- 查看响应解析后的结构化数据，确认已按业务文档字段完成映射，可直接用于台账汇总。
