# 用地预审与规划许可的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
本品类涉及的数据来源包括国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据。日常文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，字段涵盖项目编号、用地范围坐标、用地规模、管控要求等。数据更新无固定周期，随项目审批进度或国土空间规划调整同步更新。数据以结构化表单和空间矢量文件两种格式存在，需跨系统整合多来源信息完成台账梳理与报告生成。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新无固定周期，要求工作流需支持动态拉取跨系统数据，需配置`variables`存储临时整合的项目信息。多格式数据需统一结构化处理，工作流需加入格式转换节点适配矢量文件与表单字段的映射。台账需覆盖全审批节点的进度，工作流需按项目节点触发台账更新，避免遗漏前置条件核对环节。报告需关联空间数据，工作流需预留空间数据引用入口，确保生成的报告包含合规性校验依据。跨系统拉取需设置合理超时限制，防止因外部平台响应延迟导致工作流中断。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按项目维度创建，包含项目编号、用地范围、前置条件清单 | 统一存储跨系统整合的项目信息，避免节点间数据传递丢失 |
| 数据拉取超时 | 600 秒 | 匹配跨系统数据拉取的平均响应时长，避免工作流无限制等待 |
| text2sql配置 | 关联国土空间规划一张图的结构化字段 | 从项目审批数据中提取合规性校验所需的字段，生成对应SQL语句 |
| AI会话节点 | 温度开关关闭，或温度开关打开且设置为0 | 确保报告生成的内容符合固定合规表述，减少随机性 |
| 文本导出组件 | 去除开头换行符，输出格式为Markdown | 适配台账和报告的排版要求，避免生成内容出现格式偏差 |
| `nodeId` | 为每个审批节点分配唯一标识 | 快速定位工作流中异常节点，便于排查失败问题 |

## 容易做错的三处
- 现象：导出工作流和关联JSON文件后，导入其他环境时，工作流中引用的插件无法正常加载。原因：导入时未同步配置插件的本地部署路径，仅复制工作流配置文件导致引用失效。
- 现象：文本导出组件返回的字符串开头带有换行符，不符合排版要求。原因：未在配置中关闭自动添加前置换行的默认设置，导致生成内容出现额外格式偏差。
- 现象：AI会话节点的配置中，同时使用温度开关关闭和温度开关打开且设置为0时，生成的报告内容无明显差异。原因：FastGPT的AI会话节点中，温度开关关闭时默认使用0温度，与设置为0的效果一致，未按业务需求区分固定表述和灵活调整的场景。

## 怎么确认配好了
- 检查`variables`中存储的项目字段是否覆盖了用地范围、前置条件清单等核心信息，核对字段与业务文档的一致性。
- 触发一次工作流测试，查看文本导出组件返回的内容是否存在开头换行符，确认配置生效。
- 导入工作流到测试环境，查看关联插件是否正常加载，无缺失报错提示。
- 运行text2sql节点，查询项目审批监管平台的数据，确认返回的字段与本品类的业务数据结构匹配。
