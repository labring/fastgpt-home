# 社会救助与低保审核的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自民政局救助科、街道乡镇民政办、社区居委会及核对中心的日常业务文档，包括低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料与救助审批表。数据来源于低收入人口动态监测平台、居民家庭经济状况核对系统及公安、人社、医保、住建、税务的跨部门共享数据，更新频率为月度，核心字段包含家庭人员信息、收入财产明细、审批流程节点与公示结果。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度批量更新的数据规模要求索引支持增量同步机制，避免全量重建占用过多系统资源；多源异构的跨部门数据格式差异，要求索引适配不同文档的字段解析规则；家庭经济状况相关的长文本内容，要求向量模型能准确捕捉收入财产、人员关系等细粒度语义；台账汇总需关联多类文档，索引需支持跨文档关联检索，确保报告生成时可完整调取对应审批、公示等佐证材料。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 本品类核心文档多为1000-2000字符的业务表单与核对报告，分块长度覆盖完整语义单元，避免语义割裂 |
| 重叠长度 | 100–200 字符 | 长文本分块后需保留上下文关联，确保跨块语义连贯，适配家庭收入明细等长段落内容 |
| 相似度阈值 | 按实测标定 | 本品类数据需严格匹配家庭信息与救助资格的关联度，阈值需结合实际业务场景调整 |

## 容易做错的三处
- 现象：索引构建过程卡滞无响应，日志显示超时状态。原因：未针对月度批量更新的大规模数据配置增量同步机制，全量索引重建占用过多系统资源。
- 现象：检索结果中关联文档缺失，字段为空。原因：未适配跨部门共享数据的异构格式，索引未正确解析非标准字段的内容。
- 现象：配置索引模型后语言模型调用失败，返回模型不存在提示。原因：误将索引模型与语言模型的配置入口混淆，未保留语言模型的独立配置项。

## 怎么确认配好了
- 查看索引构建日志，确认增量同步任务可按月度更新节奏自动触发，无超时报错。
- 测试检索家庭收入明细文档，确认返回结果的字段完整度符合业务需求，可按需调整相似度阈值。
- 验证索引模型与语言模型的配置独立存在，切换不同模型时无冲突报错。
- 调取单份低保申请表的关联佐证材料，确认跨文档关联检索可正常返回对应审批表与公示记录。
