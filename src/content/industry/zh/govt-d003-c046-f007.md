# 社会救助与低保审核的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
本品类数据涵盖低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料、救助审批表等日常业务文档。数据来源包括低收入人口动态监测平台、居民家庭经济状况核对系统，以及公安、人社、医保、住建、税务的跨部门共享数据。数据以结构化字段为主，包含家庭收入、财产数额、人员身份关系、审批状态等内容，更新频率为月度，部分线下入户调查材料需手动录入补充。

## 这些特征在「数据库与运维」这一环带来什么约束
跨部门多源数据接入的特性要求数据库支持多格式数据对接与字段映射，避免因数据格式不统一导致的入库失败。月度更新的频率带来周期性数据写入峰值，需配置合理的连接池参数应对并发访问。日常文档包含纸质材料扫描件等附件，需预留足够的非结构化数据存储容量。数据出错会引发错保漏保、资金追回等后果，要求运维环节具备数据校验、备份与回滚机制，保障数据一致性与可追溯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 包含认证信息的专属连接字符串，指向副本集节点 | 用于存储非结构化的佐证材料与流程记录，适配FastGPT v4.17.0版本的非结构化数据存储需求，副本集可保障数据高可用 |
| `PG_URL` | 配置为支持JSONB字段的实例连接地址 | 用于存储结构化的低保申请、核对报告等带复杂字段的业务数据，JSONB可灵活存储扩展的业务字段 |
| `DB_MAX_LINK` | 50–80 个 | 应对月度数据更新的并发写入峰值，避免连接耗尽导致的入库失败 |
| `REDIS_URL` | 指向专属缓存实例的连接地址 | 用于缓存跨部门共享数据的查询结果，减少重复调用跨系统的延迟 |

## 容易做错的三处
- 现象为MongoDB连接超时报错，使用mongosh可正常连接。原因是未在FastGPT配置中添加跨源访问白名单，或配置的`MONGODB_URI`未包含正确的数据库名称。
- 现象为工作流画布拖动延迟，节点加载缓慢。原因是`DB_MAX_LINK`配置过低，导致并发连接耗尽，工作流节点的状态查询无法及时响应。
- 现象为台账汇总结果缺失部分入户调查材料。原因是未配置非结构化数据的存储路径，导致附件数据未正确入库。

## 怎么确认配好了
- 执行本地连接测试，使用配置的`MONGODB_URI`与`PG_URL`连接对应数据库，验证读写权限正常。
- 触发一次月度数据更新的模拟任务，查看数据库连接池的监控指标，确认连接数未达到配置上限。
- 导入一份标准的低保申请文档，验证结构化字段与附件均能正确存储与检索。
- 查看系统日志，确认跨部门数据的同步任务未出现超时报错。
