# 社会救助与低保审核的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于低收入人口动态监测平台、居民家庭经济状况核对系统，以及公安、人社、医保、住建、税务等跨部门共享数据。数据更新频率为月度，核心文档包含低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料、救助审批表。数据字段涵盖家庭收入、财产状况、家庭成员信息、救助申请状态等，单位匹配对应文档的标准格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
跨部门多源数据的接入需要模型支持多格式文档的上下文整合，避免数据割裂。月度更新的低频特性无需配置超长上下文窗口，可减少模型计算资源消耗。多类佐证文档的完整引用要求严格控制token分配，防止核心核对数据被截断。数据准确性直接关联救助资格判定，因此模型生成的严谨性要求高于通用场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配月度跨部门数据的总上下文长度，避免窗口溢出 |
| `maxTokens` | `2000–3000 token` | 匹配台账汇总与报告生成的常规输出长度，控制单轮生成成本 |
| `quoteMaxToken` | `1500 token` | 保留家庭经济状况核对报告、入户调查表等核心佐证文档的完整引用 |
| `toolChoice` | `auto` | 支持模型自主选择是否调用工具整合跨部门共享数据 |
| `temperature` | `0.1–0.3` | 保障低保资格判定、台账内容的严谨性，降低生成偏差 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的代理地址填写 | 适配国内大模型接入需求，兼容非OpenAI生态的模型 |
| `AIPROXY_API_TOKEN` | 按代理平台生成的有效令牌填写 | 完成模型接入的身份验证，解决无OpenAI密钥的场景 |

## 容易做错的三处
- 现象：界面显示令牌无效，接口返回401状态码。原因：未正确配置`AIPROXY_API_TOKEN`，或代理平台未开放对应模型的调用权限。
- 现象：生成的报告缺失核心核对数据片段。原因：`quoteMaxToken`取值过小，家庭经济状况核对报告等佐证文档被截断。
- 现象：单轮生成任务超时。原因：`maxContext`取值超出模型原生上下文窗口限制，或代理接口未配置合理的超时阈值。

## 怎么确认配好了
- 测试接入指定的国内大模型，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的连通性，查看接口返回状态码为200。
- 上传单份家庭经济状况核对报告，检查生成的上下文片段是否完整包含文档核心字段，无明显截断。
- 调整`temperature`参数，对比两次生成的低保资格判定结果，确认差异符合严谨性要求。
- 在FastGPT v4.17.0版本中，模拟月度数据更新的批量处理任务，验证配置组合不会导致生成失败。
