# 社会救助与低保审核的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
本品类的核心数据来自低收入人口动态监测平台、居民家庭经济状况核对系统及公安、人社、医保、住建、税务等跨部门共享数据，日常文档包括低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料、救助审批表。数据更新频率为每月一次，文档多包含家庭收入、财产数额、人员关系、审批进度等字段，单位涉及金额、人口数量、居住面积等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
跨部门数据来源分散且更新频率固定为每月一次，要求知识库检索与召回环节需支持定期全量同步或增量更新，避免数据滞后影响审核准确性。文档类型涵盖结构化表单与非结构化佐证材料，既有标准化字段也有手写或扫描的原始材料，要求检索模式兼顾精准匹配字段与模糊匹配佐证内容。审核环节出错后果直接关联错保漏保、资金追回及群众信访，因此检索召回的准确率与结果相关性需严格匹配业务要求，同时台账汇总与报告生成需快速调取相关材料，对检索效率有明确约束。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 社会救助审核需要高匹配度的佐证材料，避免低相关内容干扰审核流程，符合FastGPT v4.17.0的参数调整范围 |
| `limit` | 前8条 | 台账汇总需覆盖主要的家庭经济核对、入户调查相关材料，过多结果会增加上下文处理负担，影响报告生成效率 |
| `searchMode` | 向量检索+关键词混合 | 跨部门数据来源多，既有结构化字段也有非结构化佐证，混合模式能兼顾精准匹配字段与关键词召回 |
| `usingReRank` | 开启 | 审核场景对召回准确性要求高，重排功能可过滤低相关结果，降低错保风险 |
| `datasetSearchUsingExtensionQuery` | 开启 | 用户提问可能省略专业术语，扩展查询可覆盖文档中的专业字段描述，提升召回覆盖度 |
| `collectionIds` | 绑定民政救助专属知识库集合 | 隔离其他品类数据，避免无关文档干扰低保审核的检索结果，保障数据针对性 |

## 容易做错的三处
- 现象：上下文引用中未正确渲染Markdown格式，仅显示分隔符。原因：知识库文档的分块配置未保留原始格式标记，或检索时未启用格式保留参数。
- 现象：切换知识库索引时出现60秒超时错误。原因：跨部门数据源同步未配置增量更新，全量重建索引时数据量超出单次处理阈值，导致超时。
- 现象：部分提问无法引用知识库中的文件。原因：检索模式未覆盖关键词匹配，或文档的字段与用户提问的关键词不匹配，导致召回失败。

## 怎么确认配好了
- 发起包含家庭收入、入户调查关键词的测试提问，核对返回的上下文是否包含低保申请表、家庭经济状况核对报告等专属文档。
- 检查检索结果的排序，确认高匹配度文档排在前列，验证重排功能是否生效。
- 手动触发一次索引更新，观察更新状态是否在合理时间内完成，确认无超时报错。
- 查看知识库的集合绑定情况，确认仅关联民政救助专属数据集，无无关数据混入检索结果。
