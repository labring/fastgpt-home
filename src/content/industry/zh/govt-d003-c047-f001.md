# 行政处罚案卷办理的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
行政处罚案卷办理品类的数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日一次。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证等，核心字段包括执法主体、违法事实认定、法律适用条款、处罚裁量结果、文书编号及归档状态，各类文档需形成完整的处罚证据链，数据结构随执法流程节点动态变化。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据来源要求接口支持跨系统数据拉取与整合，需适配不同系统的数据格式与权限规则；日更新频率要求接口支持定时同步或增量拉取，避免重复拉取全量数据占用业务系统资源；多样的文档类型要求接口参数需支持不同文书的字段映射与合法性校验；严格的出错后果要求接口具备重试机制与异常捕获能力，确保台账汇总与报告生成的准确性，同时需兼容执法机构现有办案系统的调用频次限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `Authorization` | 从FastGPT应用密钥页面获取的Bearer令牌，格式为`Bearer sk-xxxxxx` | 符合FastGPT API鉴权规范，确保外部系统请求的合法性 |
| `variables` | 传入执法机构ID、数据同步起始时间、关联案卷ID等自定义参数，取值为JSON格式键值对 | 适配多执法主体的台账汇总需求，实现数据与案卷的精准匹配 |
| `responseData` | 指定返回字段为执法主体、文书编号、处罚决定、归档状态 | 仅返回台账汇总与报告生成所需的核心字段，减少无效数据传输 |
| 请求超时时间 | 600 秒 | 行政执法案卷数据量较大，需预留足够的接口响应与数据处理时间 |
| 文件上传大小限制 | 1000 MB | 支持执法记录仪影像、批量证据材料的上传与关联 |
| 同步触发方式 | 每日凌晨2点定时触发 | 匹配业务数据日更新的节奏，避开业务系统高峰时段 |

## 容易做错的三处
- 调用接口返回404 Not Found：未正确配置FastGPT应用的API访问路径，或使用了不支持外部接口调用的FastGPT版本。
- 调用`/api/core/dataset/update`接口返回500 Internal Server Error：该接口未在FastGPT开放API文档中公开，仅支持前端页面内部调用，外部系统无法直接发起请求。
- 上传本地执法文件后台账字段为空：未通过`variables`参数传入文件关联的执法案卷ID，导致接口无法匹配对应台账数据。

## 怎么确认配好了
- 在FastGPT v4.17.0及以上版本的应用管理页面，复制`Authorization`令牌，在API测试工具中携带该头部发起请求，确认返回200 OK状态码。
- 传入预设的`variables`参数，发起测试请求，检查返回的`responseData`中包含预设的核心业务字段。
- 上传测试用的执法笔录文件，核对接口返回的台账数据与本地文件的关联信息匹配一致。
- 模拟日更新场景，发起定时同步请求，确认接口能正常拉取最新的行政执法案卷数据并完成台账汇总。
