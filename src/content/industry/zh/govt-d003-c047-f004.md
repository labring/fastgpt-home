# 行政处罚案卷办理的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
本品类的数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常处理的文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证等，数据字段涵盖违法主体、违法事实、适用法律条款、处罚决定、送达状态等，每份案卷关联多份结构化与非结构化材料，需按执法环节顺序关联归档。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据来源分散且包含多类型文档，要求工作流需对接多个异构数据源节点，统一采集不同系统的案卷信息。每日更新的执法数据要求工作流需按日触发调度，确保台账汇总的时效性。多份关联文档的结构差异，要求工作流需包含格式转换与字段标准化环节，适配不同文档的提取规则。同时，案卷办理出错会导致处罚被撤销、行政复议败诉或案卷评查不合格，要求工作流需配置失败重试与异常分支处理节点，保障流程稳定性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量设置 | 将案卷存储路径、执法记录仪影像地址绑定至`variables` | 统一管理台账汇总所需的全量数据源地址，避免硬编码导致的维护成本增加 |
| HTTP请求节点超时 | `600 秒` | 行政执法案卷材料多为大体积影像或结构化文档，需预留充足的请求处理时间 |
| 失败重试配置 | 重试`3 次`，间隔`10 秒` | 数据来源包含执法记录仪等不稳定的外接设备，重试可降低临时连接失败的影响 |
| 分支判断节点 | 按`variables`中的案卷状态字段触发 | 需根据案卷是否完成固定证据、法制审核等环节，分流至不同的台账汇总分支 |
| 节点ID设置 | 为每个业务环节节点配置唯一`nodeId` | 便于排查工作流执行异常时的具体环节，快速定位问题 |

## 容易做错的三处
- 现象：工作流执行后台账字段为空，无法生成汇总报告。原因：未将案卷相关文档的链接正确绑定至`variables`，导致节点无法获取数据源地址。
- 现象：HTTP请求节点返回超时错误（状态码504）。原因：未根据案卷材料体积调整超时设置，行政执法的影像类材料传输耗时较长，默认超时时长不足。
- 现象：AI对话节点无法获取初始用户输入的案卷编号信息。原因：未在判断分支节点后将用户输入信息通过`variables`传递至后续对话节点，导致上下文丢失。

## 怎么确认配好了
- 手动触发工作流，查看各节点的执行日志，确认`variables`中绑定的案卷地址、执法记录仪影像路径均能正常加载。
- 模拟临时断开数据源连接，验证失败重试配置是否按设定的次数和间隔触发，工作流最终能正确标记异常环节。
- 调整HTTP请求节点的超时时长，测试大体积案卷材料的请求是否能正常完成，无超时报错。
- 在判断分支节点后插入日志节点，确认用户输入的案卷编号等信息通过`variables`正确传递至后续对话节点。
