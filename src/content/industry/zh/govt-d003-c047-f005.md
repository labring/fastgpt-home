# 行政处罚案卷办理的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
本品类数据来自市场监管、生态环境、交通运输、应急管理、城管等执法机构的行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，核心字段覆盖违法主体信息、违法事实认定、法律适用条款、处罚决定内容与送达状态，单份案卷数据结构随执法环节递进逐步完善。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源异构的数据来源要求工具调用适配不同格式的数据源，执法记录仪影像需搭配转写插件提取文本内容，行政执法办案系统的结构化数据需配置同步插件完成实时拉取。每日更新的频率要求工具调用触发逻辑绑定数据同步周期，避免使用过期的案卷信息。核心文档随执法环节递进完善的结构，要求插件支持动态识别当前环节的文档类型，提取对应字段完成台账汇总。处罚撤销、复议败诉等出错后果，要求工具调用环节配置结果校验与失败重试机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | auto | 适配多工具调用场景，自动选择对应案卷处理的工具，无需手动指定 |
| `functionCall` | enabled | 支持结构化提取案卷字段，生成规范的台账与报告 |
| 工具调用超时时间 | 600 秒 | 适配执法案卷多工具调用的平均耗时，避免因同步执法记录仪数据或拉取监管数据库内容导致超时 |
| 插件端口暴露控制 | 仅内部网络可访问 | 防止外部未授权访问执法敏感数据，符合政务数据安全规范 |
| 上下文窗口大小 | 8000–12000 token | 容纳单份完整案卷的文本内容与历史处理记录，避免截断关键处罚决定信息 |
| 工具调用重试次数 | 2 次 | 平衡调用成功率与处理耗时，应对执法数据库临时响应延迟的场景 |

本配置基于 FastGPT v4.17.0 版本。

## 容易做错的三处
- 现象：工具调用时仅返回本地知识库内容，无法拉取国家企业信用信息公示系统的最新企业信息。原因：未配置外部数据源同步插件，或`toolChoice`被设置为仅检索本地知识库。
- 现象：markdown转文件插件生成的文档缺失部分案卷字段。原因：未正确配置函数调用开关，未指定需要提取的核心字段。
- 现象：插件调用后返回超时错误，无重试机制触发。原因：未设置合理的工具调用超时时间与重试次数，导致执法数据拉取耗时超出阈值。

## 怎么确认配好了
- 触发一次工具调用，查看返回结果是否包含执法办案系统、国家企业信用信息公示系统的最新数据，核对数据更新时间是否符合每日同步的要求。
- 尝试从外部网络访问插件端口，验证是否无法建立连接，确认端口访问控制配置生效。
- 提交一份完整的案卷数据，检查生成的台账是否覆盖所有核心字段，确认函数调用开关配置正确。
- 模拟执法数据库临时响应延迟的场景，验证工具调用是否触发重试机制，确认超时与重试配置生效。
