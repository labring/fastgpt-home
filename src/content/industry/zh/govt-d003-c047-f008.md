# 行政处罚案卷办理的台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
本品类数据来自市场监管、生态环境、交通运输、应急管理、城管等执法机构的行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常处理的文档包括现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，包含执法主体、违法事实、处罚依据、处罚内容、送达对象等业务字段，部分文档附带影像或图片关联材料。

## 这些特征在「文档解析与分块」这一环带来什么约束
执法文书兼具结构化表头与自由文本内容，且需保留完整的证据链关联，因此解析时需区分固定字段与自由段落，避免拆分核心业务信息。多来源的数据格式存在差异，需兼容不同类型的上传文件。每日更新的业务数据要求解析流程具备足够的响应速度，避免影响台账汇总的时效性。同时，案卷办理出错后果严重，解析环节需保障准确率，减少因分块错误导致的关键信息丢失。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配执法文书的单段文本长度，避免拆分违法事实、处罚决定等核心业务内容 |
| `chunkSplitter` | 按段落+语义分块 | 匹配执法文书的段落结构，保留笔录、告知书的逻辑完整性 |
| `customPdfParse` | 启用结构化解析模式 | 适配行政处罚决定书等带固定表头的文档，提取执法编号、处罚内容等关键字段 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对多页案卷的解析耗时，避免因超时导致解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 适配单批次上传的多份执法案卷文档大小 |
| `chunkSettingMode` | 手动配置 | 针对执法文书的固定结构调整分块规则，适配业务字段需求 |

## 容易做错的三处
-  复制功能提示异常且PDF下载失败。现象：界面弹出“无法使用浏览器自动复制，请手动复制下面内容”，调用PDF生成接口返回超时。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，执法案卷文档较大导致解析超时，无法生成下载文件。
-  特定格式影像文件解析失败。现象：上传执法记录仪导出的影像文件时，解析状态显示失败，查看日志返回服务连接错误。原因：未配置对应执法影像格式的解析适配器，仅启用了通用文档解析模式。
-  知识库图片无法被检索。现象：上传的现场检查笔录附带图片链接，问答测试中未返回图片相关内容。原因：未启用图片解析配置，分块时未提取图片的文本描述或链接信息。

## 怎么确认配好了
-  上传单份行政处罚决定书文档，查看解析后的分块结果，确认核心字段如执法编号、违法事实未被拆分。
-  上传多份连续编号的执法案卷，检查分块后是否保留了案卷的关联标识。
-  触发复制或PDF下载功能，确认提示信息不再出现，下载文件可正常打开。
-  上传包含图片的现场检查笔录，确认解析结果中包含图片的文本描述或链接字段。
