# 行政处罚案卷办理的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
行政处罚案卷办理的数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、处罚决定书等，单份案卷包含执法主体、违法事实、处罚依据、文书编号、执法日期等字段，其中影像类数据为二进制格式，结构化字段多为字符串或日期型。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源包含多模态影像与结构化数据库内容，模型接入需同时支持文本与多模态解析；每日更新的执法数据要求配置实时同步的触发机制；多样的案卷文档结构要求模型能自动识别不同文书的字段规则；处罚案卷的出错后果直接影响行政合法性，需配置结果校验环节以确保输出的台账与报告符合执法规范。

## 配置怎么定
本配置说明基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 行政处罚案卷单批次总内容量较大，需容纳多份文书与影像元数据 |
| `maxTokens` | 2000–3000 token | 台账汇总与报告生成的输出长度需覆盖核心执法信息，避免截断 |
| `vision` | 开启 | 需解析执法记录仪影像等多模态数据，提取固定证据内容 |
| `temperature` | 0.1–0.3 | 需保持处罚依据匹配的稳定性，减少随机偏差 |
| `AIPROXY_API_ENDPOINT` | 填写对应厂商的专属接入地址 | 支持跨厂商模型调用，适配不同执法机构的选型需求 |
| `AIPROXY_API_TOKEN` | 填写从模型厂商获取的有效密钥 | 完成模型调用的安全验证，避免访问被拦截 |

## 容易做错的三处
- 调用模型后返回乱码或无效内容，原因是未启用`vision`参数，无法解析执法记录仪影像等多模态数据。
- 渠道配置列表中无火山方舟选项，原因是未正确填写`AIPROXY_API_ENDPOINT`为火山方舟的专属接入地址。
- 多模态模型调用后无图片分析结果，原因是`maxContext`参数设置过小，无法容纳图片编码后的上下文内容。

## 怎么确认配好了
- 上传单份执法记录仪影像，触发模型调用，检查返回结果是否包含影像相关的事实描述。
- 查看模型调用日志，确认`AIPROXY_API_TOKEN`验证状态为通过。
- 输入包含多份案卷的查询，检查返回的台账汇总结果是否覆盖所有输入文档的核心字段。
- 调整`temperature`参数至不同区间，对比两次输出结果的一致性，确认稳定性符合需求。
