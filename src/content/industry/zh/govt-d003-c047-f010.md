# 行政处罚案卷办理的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
本品类的典型主体为市场监管、生态环境、交通运输、应急管理、城管等执法机构，日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证。数据来源包括行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。文档多为结构化执法文书，包含违法事实、执法程序、处罚依据等固定字段，无额外自定义单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源数据来源要求检索范围需严格限定在行政执法案卷专属数据集，避免混入其他品类的无关文档。每日更新的频率要求检索链路支持实时或近实时召回，确保台账汇总的时效性。结构化执法文书的固定字段特征，要求检索需精准匹配违法事实、处罚依据等核心内容，避免泛化匹配无关内容。同时，案卷办理的出错后果直接关联行政合规性，要求召回结果的相关性与准确性需达到较高标准，确保不遗漏关键证据或引入无关内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.75–0.85 | 行政处罚案卷需高匹配度，避免引入无关执法记录或非核心文书内容 |
| `limit` | 3–5条 | 控制召回结果的数量，减少上下文冗余，确保台账汇总与报告生成的内容聚焦核心证据与处罚决定 |
| `searchMode` | hybrid | 结合语义向量与关键词匹配，适配执法术语的多样性与结构化文书的字段特征 |
| `usingReRank` | 开启 | 对召回结果按相关性重新排序，确保违法事实、处罚依据等核心内容优先被提取 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展执法相关同义词，适配“现场检查”“勘验”等同义执法术语，提升匹配覆盖度 |
| `collectionIds` | 行政执法案卷专属数据集ID | 严格限定检索范围，避免混入其他品类的文档数据，确保召回内容仅与行政处罚案卷相关 |

## 容易做错的三处
- 现象：检索结果包含非行政执法品类的无关文档，原因：未配置`collectionIds`参数限定检索范围，导致跨品类数据被召回。
- 现象：检索结果未携带文档的章节标题或元数据信息，原因：未正确传递metadata参数关联文档属性，或未启用`datasetSearchUsingExtensionQuery`提取文档结构信息。
- 现象：回复内容中包含知识库文档的引用链接，原因：未关闭检索结果的引用链接输出配置，导致台账汇总与报告生成中混入冗余的链接信息。

## 怎么确认配好了
- 检查`collectionIds`参数是否仅包含本品类行政执法案卷的专属数据集ID，确认无其他品类的数据集被纳入检索范围。
- 发起针对“某类违法案件的处罚依据”的测试检索，验证返回结果包含现场检查笔录、处罚决定书的核心内容。
- 确认检索结果的条数符合`limit`参数的设置，无过多冗余内容。
- 验证`usingReRank`已启用，查看召回结果的排序是否以违法事实、处罚依据等核心内容优先。
- 确认FastGPT v4.17.0版本的检索链路已适配本品类的文档特征。
