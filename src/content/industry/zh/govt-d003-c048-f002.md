# 行政许可审批的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类服务主体为政务服务中心、行政审批局及行业主管部门审批处室，数据来自全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统与电子证照库，更新频率为每日。日常处理的文档涵盖办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书及许可证照，数据字段包含事项编码、申请主体信息、办理进度、审批结果等，无统一固定单位，随具体事项类型调整。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且每日更新，要求索引支持增量同步以避免重复处理全量历史数据，降低同步耗时。文档类型覆盖申请材料、审批文书等多类，不同文档的内容长度差异显著，需适配灵活的分块规则。数据字段随事项类型变化，需保留字段级元信息以支撑精准匹配。法定审批流程的严谨性要求索引召回结果需严格匹配事项设定依据与办理条件，避免无关内容干扰审批判断。

以下配置基于FastGPT v4.17.0版本制定。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配办事指南、审批决定书等常见文档的内容密度，避免单块内容过载或过碎 |
| 重叠长度 | 100–200 字符 | 保留跨分块的上下文关联，确保审批流程的步骤信息不被截断 |
| 相似度阈值 | 按实测标定 | 需匹配行政许可事项的精准匹配要求，避免召回无关事项的材料 |
| 单次搜索上限 | 前 10 条 | 控制返回结果的数量，聚焦核心审批依据与材料要求 |
| defaultToken | `4096` | 适配多数审批相关问答的上下文长度需求，避免超出模型处理上限 |
| maxToken | `8192` | 支持长文档的完整索引与问答，覆盖含多页附件的申请材料 |

## 容易做错的三处
- 界面显示索引中长时间无进展：原因是未适配政务数据的日更频率，未配置增量索引触发规则，全量同步大量历史数据导致超时。
- 知识库调用时报错无可用向量模型：原因是未将text-embedding-ada-002正确绑定至政务审批专属的知识库渠道，或配置文件中未指定对应模型的调用路径。
- 召回结果包含非当前事项的审批材料：原因是相似度阈值设置过低，未结合事项编码元信息进行二次过滤，导致无关数据被召回。

## 怎么确认配好了
- 检查知识库的数据源配置，确认已关联全国一体化政务服务平台事项库、电子证照库等指定来源，且同步频率设置为每日。
- 测试单条审批文书的索引过程，查看分块后的内容长度与重叠设置是否符合预期，无明显内容截断或过载。
- 发起针对特定行政许可事项的检索，核对召回结果是否包含该事项的办事指南与审批依据，无跨事项的无关内容。
- 查看模型调用日志，确认text-embedding-ada-002的调用请求已正常发起，无格式错误或权限异常。
