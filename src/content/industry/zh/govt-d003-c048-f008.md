# 行政许可审批的台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
本品类的典型数据来自政务服务中心、行政审批局、行业主管部门审批处室等主体，日常文档涵盖办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书、许可证照等制式文书与结构化表单。数据来源包括全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统及电子证照库，更新频率为每日。文档多包含固定字段，如事项编号、申请人信息、审批结论等，部分补正告知书、审批意见包含自由文本内容，格式混杂且需按法定许可事项分类归集。

## 这些特征在「文档解析与分块」这一环带来什么约束
每日更新的高频数据要求解析流程具备稳定性与时效性，避免因解析延迟影响台账汇总进度。制式文档与结构化表单并存的特征，要求分块逻辑兼顾固定字段提取与自由文本语义完整性，防止割裂事项关联信息。跨系统、跨部门的数据源带来文档格式差异，需适配PDF、Word、表单导出文件等多种格式，同时需确保解析结果可按许可事项分类，满足台账汇总的归集需求。此外，解析错误可能导致后续核对环节耗时增加，甚至引发超期办结或审批合规风险，因此分块环节需保留足够的上下文关联信息。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置逻辑编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 行政许可文档多为制式文书，该长度可覆盖单份材料的核心内容，避免将关联字段拆分至不同块中 |
| `chunkSplitter` | 按段落+固定分隔符 | 适配行政许可文档的固定排版结构，按段落拆分可保留审批意见、申请理由等语义完整的内容单元 |
| `customPdfParse` | 启用结构化解析模式 | 针对电子证照、正式批文等PDF文档，提取表单字段信息，避免纯文本解析丢失结构化数据 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 覆盖政务场景下批量导入的多份许可文档包，适配日常台账汇总的批量处理需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 预留充足时间处理多页电子证照或长表单，避免因超时导致解析任务失败 |
| `chunkSettingMode` | 手动配置 | 针对不同类型的行政许可文档（如申请表、决定书）调整分块参数，适配多样的文档格式 |

## 容易做错的三处
- 传入政务公开链接后仅返回链接文本，无法解析文档内容，原因是未开启远程文档解析权限，或链接指向的文档需登录权限无法公开访问。
- 分块后电子证照的统一编号与签发日期被拆分至不同块中，原因是`chunkSize`设置过小，破坏了结构化字段的关联完整性。
- 上下文引用中未保留审批意见的Markdown格式，原因是未开启文档解析的格式保留开关，导致原始排版标记被过滤。

## 怎么确认配好了
- 上传单份制式行政许可决定书PDF，检查解析后分块是否保留事项名称、审批结论等核心字段，无内容缺失或割裂。
- 批量上传多份不同格式的行政许可文档，确认解析任务无超时报错，整体完成率符合预期。
- 查看上下文引用结果，确认分块内容的语义连贯性，无跨许可事项的内容混叠。
- 测试公开政务链接的解析功能，确认办事指南等文档可正常提取完整文本内容。
