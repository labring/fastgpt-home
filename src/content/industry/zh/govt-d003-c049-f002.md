# 规范性文件合法性审核的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类涉及的文档主要包括规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告，数据来源为法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统。数据更新无固定周期，随审核任务推进不定期产生。文档结构多包含条文内容、制定主体、生效时间、审查要点等字段，无统一固定单位，部分文档附带多轮修改痕迹与跨部门意见反馈记录。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源分散的数据来源要求索引需支持跨库关联检索，适配不同系统导出的格式差异。不定期的更新节奏要求索引配置需兼容增量同步逻辑，避免全量重建带来的资源消耗。文档包含条文、意见、审核意见等多类型内容，需针对不同字段设置差异化的切片规则，确保审查相关的核心内容不被截断。同时，需保障上位法条文的精准召回，避免因索引精度不足导致合法性审核出现偏差，引发文件备案纠错等后果。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 规范性文件条文多为规整段落，该区间可保留单条条文或相邻关联条文的完整语义，避免跨块截断关键审查依据。 |
| 重叠长度 | 100–200 字符 | 保障相邻分块间的语义衔接，避免在条文衔接处出现语义断裂，影响上位法条文的精准匹配。 |
| 相似度阈值 | 按实测标定 | 需适配本品类对上位法条文匹配的高准确性要求，避免误召回或漏召回相关依据。 |
| 单次搜索上限 | 前 5 条 | 匹配审核工作中优先检索核心上位法依据的需求，减少非相关结果的干扰。 |
| `maxToken` | 4000–6000 token | 可承载单条审核任务所需的上位法、政策文件等关联数据的总长度，满足上下文拼接需求。 |
| `defaultToken` | 1500 token | 适配单条分块的常规长度，平衡语义完整性与模型输入成本。 |

## 容易做错的三处
- 现象：检索结果中出现与当前审核文件无关的上位法条文，或核心审查依据被遗漏。原因：未针对规范性文件的条文结构调整分块与相似度阈值设置，导致语义匹配偏差，引发合法性审核失误。
- 现象：索引同步任务超时，后台显示连接异常或超时报错日志。原因：未适配多源数据库的访问频率限制，全量同步时未设置合理的分批间隔，超出系统负载阈值。
- 现象：生成的审核报告中出现字段为空的内容，如征求意见汇总的关联数据缺失。原因：索引配置未覆盖征求意见汇总类文档的字段索引，导致检索时无法召回对应内容。

## 怎么确认配好了
- 上传单份规范性文件草案与对应上位法条文，执行检索核对，确认核心条文的召回顺序与匹配度符合审核需求。
- 触发增量同步任务，核对新增文档的索引状态，确认无同步失败的报错信息。
- 查看索引配置的分块长度与重叠长度参数，确认与本品类文档的段落长度匹配。
- 生成测试性的审核报告，核对关联数据的召回条数与内容完整性，调整相关配置直至符合预期。
