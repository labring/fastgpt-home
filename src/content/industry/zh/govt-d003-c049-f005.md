# 规范性文件合法性审核的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
本品类的数据主要来自法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新频率不定期。日常处理的文档包括规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告，文档字段包含文件编号、起草单位、审核结论、意见征集情况、备案流转节点等，无统一的标准化字段格式，需结合各部门内部系统的字段定义适配。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于本品类数据来源分散且更新频率不定期，工具调用需支持按需或定时同步多类数据源，避免因数据滞后引发合法性审核偏差。日常处理的文档类型多样，插件需适配不同格式的文件解析，确保文本提取的完整性。字段无统一标准化格式，工具调用环节需支持自定义字段映射，将不同来源的文档字段对齐至审核台账的标准结构。此外，合法性审核涉及上位法比对等核心步骤，工具调用需限定在合规的官方数据源范围内，防止访问非授权的数据源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 选择 `functionCall` 模式 | 本品类需精准调用指定工具完成合法性比对与台账聚合，该模式可明确指定工具调用的触发逻辑 |
| 工具调用超时阈值 | 600–900 秒 | 合法性审核需比对多份上位法与政策文件，单次调用耗时较长，按实测标定合理区间 |
| 批量文档拉取上限 | 前 20 条 | 适配单次审核流程的文档数量规模，避免单次拉取数据过多导致超时 |
| 插件触发时机 | 按审核节点触发 | 匹配合法性审核的流程节点，仅在需要比对数据或生成汇总时调用插件 |
| 结果聚合规则 | 按文件编号分组 | 对齐台账的标准字段结构，确保汇总数据的可追溯性 |

## 容易做错的三处
- 现象：配置插件后界面提示调用失败，查看日志返回参数不匹配错误。原因：FastGPT v4.17.0 中`functionCall`模式的参数校验规则更新，未同步更新本地模型的调用参数格式。
- 现象：调用搜索类插件后返回结果为空，无任何报错信息。原因：未将行政规范性文件备案系统的数据源添加至插件的可访问范围，导致插件无法拉取对应数据。
- 现象：图表工具调用后生成的台账图表为空。原因：未配置结果聚合规则按文件编号分组，导致工具无法识别有效聚合字段，无法生成可视化内容。

## 怎么确认配好了
- 手动触发一次工具调用，查看日志中是否显示`functionCall`模式已启用，无参数校验报错。
- 上传一份测试用的规范性文件草案，触发插件调用，确认可从指定数据源拉取到对应的上位法比对数据。
- 运行台账汇总流程，查看生成的汇总文档是否包含预期的字段分组，无空字段或乱码。
- 检查插件触发时机是否与审核流程节点对齐，确认仅在需要时触发工具调用。
