# 规范性文件合法性审核的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类的服务主体为司法行政部门、部门法规处、政府办公室政策法规岗。数据来源包括法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新频率不定期。日常处理的文档涵盖规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告，文档包含条文内容、制定主体、权限依据、意见征集结果等字段，单批次审核涉及的文档数量与内容规模随事项变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新无固定周期，要求接入配置支持多源数据的动态拉取与格式适配。日常文档包含专业法律条文与行政流程记录，单条审核涉及的文本长度较长，需配置适配长上下文的模型参数。台账汇总需整合多类文档的字段，要求模型能准确识别并对齐不同文档的标准化内容字段。备案相关文档需严格符合合规要求，模型输出需可追溯，因此需配置支持上下文引用记录的参数。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配规范性文件草案、起草说明等长文本审核场景，覆盖单批次审核的全部核心文档内容 |
| `maxTokens` | `2000–3000 token` | 控制单轮审核报告的输出长度，确保内容完整且符合台账汇总的格式要求 |
| `quoteMaxToken` | `1500 token` | 限定引用的上位法条文、政策文件等参考内容的长度，避免上下文过载 |
| `toolChoice` | `auto` | 允许模型自主选择是否调用检索工具，适配多源数据的合法性比对需求 |
| `temperature` | `0.1–0.3` | 降低输出随机性，确保合法性审核结论的严谨性与一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 对接合规的大模型服务，确保数据传输符合政务网络安全要求 |
| `AIPROXY_API_TOKEN` | 按服务商提供的密钥填写 | 完成模型服务的身份验证，保障接入安全 |

## 容易做错的三处
- 测试时返回`404 status code (no body)`，原因是`AIPROXY_API_ENDPOINT`配置的地址无法正常访问，或`AIPROXY_API_TOKEN`填写错误导致身份验证失败。
- 本地部署模型后无法基于文档内容生成回答，原因是`maxContext`配置值过小，无法加载解析后的文档内容，或未正确配置多源数据的召回逻辑。
- 模型测试时报`Message field is required`错误，原因是未正确配置`maxTokens`或`temperature`参数，导致请求体格式不符合模型服务要求。

## 怎么确认配好了
- 核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置，发起一次测试请求，确认无身份验证或地址错误。
- 调整`maxContext`与`maxTokens`的取值，使用单份规范性文件草案进行测试，确认模型可完整加载并处理文档内容。
- 查看模型输出结果，确认包含引用的参考文档片段，验证`quoteMaxToken`的配置是否符合需求。
- 模拟多文档台账汇总场景，测试模型能否对齐不同文档的字段，生成符合格式的汇总报告。
