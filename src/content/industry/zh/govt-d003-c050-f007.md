# 财政支出绩效评价的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
本品类的数据覆盖财政支出绩效全流程，来源包括预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账、满意度调查。日常文档包含绩效目标表、自评表、绩效评价报告、佐证材料清单、整改报告，单条数据关联单个项目的全周期绩效信息，字段涵盖项目标识、绩效指标项、资金使用记录、佐证材料关联信息，更新频率为年度批量更新。

## 这些特征在「数据库与运维」这一环带来什么约束
年度批量更新的特性要求数据库支持高效的批量数据导入与增量校验，避免重复录入或遗漏数据。多源异构的数据来源需要统一字段格式，确保不同系统导出的台账、报告能够被正常解析入库。多样的文档类型既包含结构化的指标表格，也包含非结构化的报告附件，需要兼顾结构化查询与非结构化存储的能力。数据出错会直接影响项目评分与预算分配，因此数据库运维需重点监控数据完整性与一致性，保障核验环节的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://user:pass@host:5432/finance_perf` | 存储结构化的绩效目标、自评评分、资金支付等关联数据，支持复杂关联查询 |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/perf_docs` | 存储非结构化的绩效评价报告、佐证材料、整改报告等文档数据 |
| `DB_MAX_LINK` | `10–15 个` | 匹配年度批量数据导入时的并发连接需求，避免高并发场景下连接耗尽 |
| `REDIS_URL` | `redis://:pass@host:6379/0` | 缓存高频访问的项目基础信息、绩效指标库，降低数据库的重复查询负载 |

## 容易做错的三处
- 开启问题优化和结果重排后消息返回超时，日志显示`ETIMEDOUT`。原因是未调整`DB_MAX_LINK`的配置值，批量拉取多源绩效数据时数据库连接耗尽，导致请求阻塞。
- 本地部署后无法创建数据库，界面提示「数据库连接失败」。原因是未正确配置`PG_URL`或`MONGODB_URI`，未开放对应数据库端口的访问权限，或数据库账号权限不足。
- 生成的台账汇总出现重复条目，工具选择出现并发重复结果。原因是未通过`REDIS_URL`配置的缓存服务添加分布式锁，多实例同时写入绩效台账时出现数据重复写入。

## 怎么确认配好了
- 使用FastGPT v4.17.0内置的数据库连通性测试工具，验证`PG_URL`和`MONGODB_URI`的连通性，确认无连接超时或权限报错。
- 导入单条年度绩效项目的结构化数据与非结构化附件，检查数据库中对应字段是否完整匹配，无格式错误或字段缺失。
- 模拟5个并发的台账查询请求，通过数据库监控面板确认当前连接数未超过`DB_MAX_LINK`的设定值。
- 查看Redis缓存监控，确认高频查询的绩效基础信息缓存命中率达标，无频繁穿透数据库的情况。
