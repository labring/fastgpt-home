# 道路运输经营许可的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自道路运政管理系统、全国道路运输车辆动态信息公共服务平台及车辆和从业人员数据库，每日更新。日常文档包含经营许可申请材料、车辆技术档案、驾驶员从业资格材料、安全生产管理制度、道路运输经营许可证等，数据字段涵盖经营主体信息、车辆资质、从业人员资格、安全制度条款及许可状态等，单份文档篇幅跨度较大，部分台账需整合多系统跨数据源的分散信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 容纳多系统整合的台账与许可文档，避免关键资质、制度条款被截断 |
| `maxTokens` | `2000–3000 token` | 覆盖台账汇总与合规性说明的输出需求，控制报告篇幅符合审批文档规范 |
| `quoteMaxToken` | `1500–2000 字符` | 保留车辆、从业人员资质的完整原文引用，确保核验环节可追溯 |
| `toolChoice` | `auto` | 自动触发多系统数据拉取工具，适配跨数据源整合的台账生成需求 |
| `temperature` | `0.1–0.3` | 保持报告严谨性，避免生成非标准化、不符合合规要求的表述 |
| `AIPROXY_API_ENDPOINT` | 按部署环境实测标定 | 适配私有部署或本地模型的接口地址，保障调用连通性 |

## 容易做错的三处
- 现象：模型测试返回请求错误，或接口调用返回格式不匹配报错。原因：未按模型要求的标准格式传入台账数据，或跨系统拉取的原始数据字段未做标准化处理。
- 现象：生成的报告未整合跨系统数据，或提取的车辆、从业人员资质信息缺失。原因：未配置`toolChoice`为自动触发工具调用，或未正确配置多数据源拉取的权限与接口参数。
- 现象：生成的报告出现非合规表述，或许可状态判断错误。原因：将`temperature`设置过高，导致模型生成随意性较强的内容，不符合许可审批的严谨要求。

## 怎么确认配好了
- 执行内置的模型测试功能，确认接口连通性与返回格式符合预设要求。
- 选取单份完整的经营许可申请材料作为输入，触发台账汇总任务，核对输出结果是否覆盖所有业务要求的文档字段。
- 查看系统日志，确认跨数据源拉取工具调用无异常报错，数据整合流程正常。
- 调整`temperature`参数并对比输出内容，确认报告严谨性符合许可审批的业务规范。
