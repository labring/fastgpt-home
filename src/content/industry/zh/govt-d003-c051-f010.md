# 道路运输经营许可的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据主要来自道路运政管理系统、全国道路运输车辆动态信息公共服务平台、车辆和从业人员数据库。日常文档包含经营许可申请材料、车辆技术档案、驾驶员从业资格材料、安全生产管理制度、道路运输经营许可证件。数据更新频率为每日（24小时），文档结构以结构化审批表单、非结构化制度文本、动态车辆与人员的关联数据为主，字段包含许可编号、车辆号牌、从业人员资格证号、安全制度条款等内容，无统一固定单位，随文档类型变化。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据分散来源与高频更新特性，要求知识库检索需支持增量同步机制，确保召回内容与每日更新的运政系统数据一致。文档类型混杂结构化审批表单、非结构化制度文本与动态关联数据，检索需兼顾字段精准匹配与语义理解，避免仅召回单一片面内容。车辆与从业人员数据存在强关联，检索时需联动召回相关联的档案信息，防止返回孤立无效的单一数据项。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配混合结构化与非结构化文档的检索匹配精度，平衡召回率与准确率 |
| `limit` | 前10条 | 覆盖道路运输经营许可相关的多维度文档类型，避免单条结果片面 |
| `searchMode` | hybrid | 结合关键词匹配与语义检索，适配字段与文本混合的文档结构 |
| `usingReRank` | 开启 | 对召回结果进行重排序，优化非结构化制度文本的检索相关性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展检索范围，覆盖关联的车辆与从业人员档案数据 |
| `collectionIds` | 按业务域绑定对应知识库集合 | 隔离不同运输企业或审批部门的文档数据，避免跨域干扰 |

## 容易做错的三处
- 现象：语义检索无法命中包含指定业务关键词的文档块，例如“经营范围变更”相关内容未被召回。原因：`similarity`阈值设置过高，过滤掉了语义匹配度达标但关键词不完全一致的内容。
- 现象：使用严格问答模板时，检索到图片格式的文档地址后提示未找到答案，切换模板后可正常返回内容。原因：仅配置了文本内容的召回解析规则，未适配图片类文档的检索逻辑。
- 现象：复杂台账汇总请求仅召回单一条目，无法覆盖关联的车辆、驾驶员与安全制度文档。原因：`limit`参数设置过低，未召回足够数量的关联文档。

## 怎么确认配好了
- 执行单次检索测试，输入典型业务查询，核对召回结果包含的文档类型与数量是否符合业务需求。
- 查看知识库同步日志，确认每日增量更新任务正常执行，无数据同步失败的报错记录。
- 切换不同检索模板，测试包含图片地址的文档块是否能被正确召回与解析，验证非文本内容的适配逻辑。
- 检查`collectionIds`配置，确认仅绑定了当前业务域的知识库集合，无跨域文档被误召回。
