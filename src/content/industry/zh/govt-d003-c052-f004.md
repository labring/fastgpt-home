# 部门决算与财务报告的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
本品类数据来自预算管理一体化系统、国库集中支付系统、会计核算系统、资产管理系统，更新频率为年度。日常生成的文档包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告，数据字段涵盖收支科目明细、预算执行差异项、资产负债余额、下级单位汇总数据等，单位多为元、万元，部分字段需匹配财政统一编码规则。

## 这些特征在「工作流编排」这一环带来什么约束
年度更新的频率决定工作流无需高频触发，可按年度周期启动，且仅在年度结束后运行。多系统数据源的差异要求工作流配置跨系统数据拉取节点，统一数据格式后再进行汇总。复杂的多文档结构需要拆分报表、说明等不同模块，分别配置数据提取与校验规则。下级单位报表汇总的需求，要求工作流包含层级化数据遍历节点，处理不同单位的格式对齐问题。数据出错会导致决算被退回或审计问题，因此需在关键环节配置数据校验与失败告警。本品类工作流聚焦实际收支与资产负债数据的汇总，不同于预算编制类工作流，无需覆盖预算编制环节的配置。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源节点 | 对接四类财政系统接口 | 匹配本品类数据的官方来源渠道 |
| 定时触发规则 | 365天触发一次 | 贴合年度更新的频率要求 |
| `variables` | 预设收支科目、单位层级参数 | 减少重复配置，适配固定字段 |
| 最大上下文 | 8000 token | 容纳多张决算报表的完整数据内容 |
| 单次拉取上限 | 前5000条 | 控制年度数据拉取的规模，避免超时 |
| `nodeId` | 绑定下级单位拉取节点ID | 实现层级化报表汇总的流程跳转 |
| 问题优化 | 按决算报表字段优化查询词 | 提升多系统数据提取准确性 |

## 容易做错的三处
- 现象：创建工作流模板后进入编辑界面报错，界面弹出配置缺失提示。原因：未绑定下级单位数据拉取的`nodeId`，导致层级化报表汇总的流程跳转环节缺失必要配置。
- 现象：使用问题优化节点处理多系统数据时，提取结果与预期字段不符。原因：混淆了问题优化节点与数据源提取节点的功能边界，未使用`variables`预设的财政统一科目参数完成格式对齐。
- 现象：工作流运行后出现「数据校验失败」告警，日志显示收支明细与国库数据不一致。原因：未在数据校验节点配置国库支付数据的核对规则，导致账表不符的问题未提前拦截。

## 怎么确认配好了
- 核对数据源节点的配置，确认已对接所有要求的财政系统接口，配置项与系统官方文档一致。
- 核对`variables`参数的预设值，确认包含收支科目、单位层级等本品类的固定字段。
- 核对`nodeId`的绑定关系，确认下级单位数据拉取节点的ID与流程跳转逻辑匹配。
- 核对数据校验节点的规则，确认已覆盖账表核对、口径校验等关键环节。
