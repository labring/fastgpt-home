# 部门预算编制的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的典型数据来自财政局预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知，更新频率为年度。日常处理的文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复，核心字段包含单位编码、预算年度、项目类别、经费额度、绩效目标值，单位多为万元、人月。数据需整合多系统的跨部门信息，单次汇总的台账数据体量覆盖单部门全年预算相关的全部申报与测算材料。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
年度更新的特性决定接口调用频次较低，但单次请求需承载多系统的跨部门数据，因此需要支持批量数据拉取与合并。多来源的数据格式差异要求接口需兼容不同系统的返回结构，需配置统一的字段映射规则。文档类型包含结构化表格与非结构化文本，接口需支持多种文件格式的上传与解析。不同于决算环节的事后核算，本环节为事前资金申报安排，数据校验与失败处理的严谨性要求更高，需针对接口异常配置重试与告警机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | `Bearer 前缀的平台签发令牌` | 符合FastGPT v4.17.0版本的接口鉴权规范，保障外部系统调用的安全性 |
| `variables` | 绑定预算年度、单位编码、项目类别等固定参数 | 匹配部门预算编制的固定业务字段，减少重复配置成本 |
| `responseData` | 提取预算数据、台账条目、报告摘要字段 | 聚焦台账汇总与报告生成的核心需求，过滤无效返回内容 |
| 单次请求文件大小上限 | 1000 MB | 适配部门预算相关文档的常规体量，避免大文件传输失败 |
| 请求超时时间 | 600 秒 | 覆盖多系统数据拉取与汇总的常规耗时，避免中途中断 |
| 重传重试次数 | 3次 | 应对外部系统偶发的波动，保障数据拉取的成功率 |

## 容易做错的三处
- 调用指定API接口时返回`Invalid URL, code: 500`，现象是接口调用后返回该报错信息，原因是未将外部系统的域名加入允许访问白名单，或传入的数据源URL格式不符合系统校验规则。
- 上传预算相关多模态文件时返回`InternalError.Algo.InvalidParameter: Multimodal file size is`，现象是上传文件后触发参数错误提示，原因是未提前校验文件体量，直接上传了超过配置上限的文档。
- 汇总台账数据时核心字段缺失，现象是`responseData`返回结果中缺少项目经费或绩效目标字段，原因是未在`variables`中配置对应业务字段的映射规则，导致系统无法提取目标数据。

## 怎么确认配好了
- 调用测试接口传入模拟的预算单位编码与预算年度，检查`Authorization`鉴权是否通过，返回状态码为200。
- 上传符合常规体量的部门预算草案文件，验证接口未触发文件大小相关的报错提示。
- 查看`responseData`返回结果，确认包含项目申报书、人员经费测算表的核心业务字段。
- 模拟下属单位数据上传至接口，检查系统是否能正确汇总生成台账条目，无字段遗漏或格式错误。
