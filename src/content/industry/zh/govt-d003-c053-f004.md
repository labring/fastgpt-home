# 部门预算编制的台账汇总与报告生成：工作流编排

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且来自多个独立系统，要求工作流配置跨系统数据拉取节点，统一各来源数据的格式后再进行汇总。年度更新的节奏要求工作流仅在预算编制窗口期运行，避免非周期的无效触发。文档字段多且涉及财政专业规范，工作流的`variables`需预设对应专用字段，减少手动映射的误差。下属单位台账的批量汇总需求，要求工作流支持数组类型输入的循环处理，适配多条目数据的合并逻辑。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发时机 | 年度预算编制窗口期启动，仅在每年10月至次年2月运行（按实测标定） | 匹配该品类年度更新的频率要求，避免非周期无效运行 |
| 输入变量`variables` | 预设人员经费、项目支出、绩效目标、单位编制数4类字段 | 贴合该品类文档的标准字段结构，减少数据映射误差 |
| 循环节点配置 | 单次循环处理1-5条下属单位数据 | 适配下属单位台账的批量汇总需求，避免单节点负载过高 |
| 目标节点`nodeId` | 绑定预算报告生成节点的唯一ID | 确保工作流节点间的调用链路正确，避免节点匹配错误 |
| 失败重试次数 | 2次，重试间隔60秒 | 应对跨系统拉取数据时的临时网络波动 |
| 结果导出格式 | 按部门预算批复模板的Excel格式 | 匹配下游审核环节的文档要求 |

## 容易做错的三处
- 循环节点输入数组格式错误，导致单条数据处理失败。现象为循环节点输出结果为空或仅处理部分条目，原因是未将下属单位台账数据正确转换为数组格式的输入参数，未匹配循环节点的数组输入要求。
- 未配置结果导出节点，导致生成的台账与报告无法提交审核。现象为工作流运行完成后无可用输出文件，原因是未添加结果导出环节，未将汇总数据转换为部门预算编制要求的标准格式。
- 未结合预算编制上下文调用AI生成内容，导致报告不符合规范。现象为生成的预算报告缺少绩效目标或项目支出明细，原因是未在工作流中预设预算编制的专用规则，未使用`variables`中的历史决算数据作为上下文补充。

## 怎么确认配好了
- 触发工作流测试运行，检查循环节点是否按预期处理所有下属单位的台账数据，确认输入的数组格式参数被正确识别。
- 查看数据源校验环节的日志，确认所有输入数据均通过字段格式校验，无格式错误提示。
- 导出工作流生成的报告，对照部门预算编制的标准文档结构，确认所有预设字段均已填充。
- 调用测试模型生成单份报告，确认输出内容符合预算编制的通用规范，无缺失关键字段。
