# 部门预算编制的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
该品类的数据主要来自预算管理一体化系统、部门人员编制系统、以前年度决算数据、项目库及财政部年度预算编制通知。日常产出的文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复文件。数据更新频率为年度周期，字段多涉及单位编码、人员编制数、项目经费额度、绩效目标参数等，需关联多系统的结构化与半结构化数据，保障台账汇总的完整性。

## 这些特征在「数据库与运维」这一环带来什么约束
年度周期的更新要求需批量导入多来源的结构化与半结构化数据，对数据库的批量写入与关联查询能力提出明确要求。多系统数据源的字段格式存在差异，需在数据库运维环节完成标准化清洗，避免脏数据进入台账流程。汇总下属单位预算数据的高频操作，要求数据库支持并发查询且具备缓存适配能力。数据出错会导致预算退回或审核不通过，需配置完整的数据备份与回滚机制，保障数据一致性与可追溯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://budget_user:secure_pass@internal-db:5432/budget_main?sslmode=require` | 对接预算管理一体化系统的结构化台账数据，sslmode=require保障跨系统传输的安全性 |
| `MONGODB_URI` | `mongodb://project_user:secure_pass@internal-mongo:27017/project_pool?authSource=admin` | 存储项目库的半结构化申报数据，适配非固定字段的项目信息与绩效目标表内容 |
| `DB_MAX_LINK` | `20–30 个连接` | 适配年度预算编制期间的批量下属单位数据汇总查询，避免连接耗尽导致任务中断 |
| `REDIS_URL` | `redis://cache_user:secure_pass@internal-redis:6379/0` | 缓存高频查询的下属单位预算台账数据，降低核心数据库的负载压力 |
| 数据库连接超时阈值 | `600 秒` | 适配多系统数据关联查询的耗时场景，避免中途中断批量汇总任务 |

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 容易做错的三处
- 出现`connect ETIMEDOUT`报错，本地可访问数据库但线上部署后无法连接。原因是线上环境的安全组或防火墙未开放数据库对应端口，或`PG_URL`/`MONGODB_URI`配置的访问地址未适配内网域名。
- 数据库查询返回结果条数与预期不符，出现遗漏或重复的台账条目。原因是未在SQL查询中添加正确的下属单位编码过滤条件，或多系统数据关联时未处理重复的预算数据条目。
- 调用DB节点后返回JSON格式结果，无法直接用于报告生成的文本拼接。原因是未配置结果格式化规则，需通过代码节点解析字段后再拼接，或未选择适配的结果映射方式。

## 怎么确认配好了
- 测试批量导入100条下属单位的预算数据，检查数据库写入无报错且字段完整匹配。
- 查看数据库连接池监控面板，确认当前活跃连接数未超过`DB_MAX_LINK`的配置值。
- 发起一次年度预算汇总的模拟查询，确认返回结果包含所有下属单位的台账数据且格式符合要求。
- 验证Redis缓存的命中情况，确认高频查询的下属单位预算数据可被快速读取。
