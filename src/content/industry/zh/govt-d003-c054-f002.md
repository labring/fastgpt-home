# 防汛防灾与应急值守的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类的日常文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单等，数据来源涵盖气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控。数据更新频率为每日，字段包含雨情水情数值、物资数量、避险人数等，对应单位为毫米、立方米、件、人等，部分文档为结构化表格格式，部分为非结构化文本格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
FastGPT v4.17.0版本的向量索引功能可适配该场景的配置需求。多源实时数据要求索引支持增量更新以适配每日更新节奏，避免全量重建带来的资源消耗。文档格式混合结构化表格与非结构化文本，要求分块策略同时适配表格字段关联与长文本语义完整性。特定单位字段的存在，要求向量建模时保留单位信息以避免匹配偏差。应急场景的快速响应需求，要求索引检索控制单批次返回结果数量，减少处理延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配混合格式的文档，兼顾长文本语义完整与分块粒度合理性 |
| 重叠长度 | 100–200 字符 | 避免跨分块的语义断裂，保留关键上下文关联 |
| `defaultToken` | 4096 | 适配多数本地部署的embedding模型的默认上下文窗口 |
| `maxToken` | 8192 | 支持长文档如会商纪要的完整索引构建 |
| 相似度阈值 | 0.75–0.85 | 过滤无关内容，保留与应急场景强相关的检索结果 |
| 单次搜索上限 | 前 5 条 | 适配应急场景的快速响应需求，避免过多结果延迟处理 |

## 容易做错的三处
- 部署本地M3E模型后索引构建失败，提示模型加载超时。原因是未在FastGPT中正确配置本地embedding模型的访问端口与容器映射规则。
- 重复配置Qwen/Qwen3-Embedding-8B模型时，原有配置被覆盖且无法同时启用索引与重排功能。原因是FastGPT默认仅允许同一模型名称配置一次，未通过添加模型别名区分不同用途。
- 导入Excel格式的物资调拨单后，分块包含冗余表头且跨行数据不完整。原因是未设置分块时保留表头关联，且默认分块粒度过大导致颗粒度不符合业务需求。

## 怎么确认配好了
- 上传单份灾情速报文档，查看分块预览界面的语义完整性，确认分块长度符合预设取值区间。
- 调用知识库搜索接口，输入“今日雨情”，检查返回结果条数符合单次搜索上限设置。
- 尝试添加同名embedding模型，查看界面是否提示重复配置，验证模型别名功能生效。
- 导入测试Excel文件，查看分块是否保留表头关联，且数据块粒度符合业务预期。
