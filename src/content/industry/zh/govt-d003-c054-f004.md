# 防汛防灾与应急值守的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
本品类的数据通常来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控，更新频率为每日，部分实时预警数据更新频次更高。日常文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单，字段涵盖雨情水情数值、灾情等级、转移安置人数、物资存量与调拨量等，部分文档需关联具体时段与责任主体。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据来源分散且类型多样，工作流编排需配置多节点分别对接不同系统拉取数据。实时预警数据与日常台账更新节奏差异大，需区分触发规则，部分节点支持按实时事件触发，部分按固定周期执行。不同文档需关联对应知识库，工作流需支持按文档类型路由至不同知识库节点。字段包含多类数值与标识信息，需在`variables`中定义标准化映射规则，避免数据格式不匹配导致流程中断。同时跨部门流转的文档需配置校验节点，确保数据符合业务要求。

## 配置怎么定
本页面基于FastGPT v4.17.0版本编写，以下为适配本品类的配置参考：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 变量映射 | 在`variables`中定义雨情数值、灾情等级、转移人数3类核心输入变量，每个变量绑定对应系统的返回字段 | 适配本品类台账的核心字段结构，统一数据流转格式 |
| 触发规则 | 按固定周期（每日凌晨2点）与实时事件（预警推送）双模式触发 | 兼顾日常台账汇总与突发灾情的快速响应需求 |
| 知识库路由 | 按文档类型分配至对应知识库：值班记录用内部制度库，灾情速报用应急处置库，物资调拨单用物资管理库 | 匹配本品类不同文档的业务关联要求 |
| 超时阈值 | 设置为600秒 | 避免多系统并行拉取数据导致流程阻塞 |
| 异常分支配置 | 当`nodeId`匹配失败时，触发预设的固定回复节点 | 覆盖非知识库匹配的异常场景 |
| 回复长度限制 | 限定为800-1200字符 | 适配应急报告的规范篇幅要求 |

## 容易做错的三处
- 工作流中`variables`未定义标准格式，导致http接口无法正确接收输入参数，表现为接口返回400错误或返回空数据。原因是未按本品类的核心字段结构映射变量，导致参数键名不匹配。
- 未配置知识库路由规则，导致不同类型文档全部进入同一知识库节点，表现为输出结果混杂业务制度、专家解读与合规校验内容，无法按需求分类展示。原因是未按文档类型设置路由分支，未利用工作流的节点分流能力。
- 未配置异常分支与超时阈值，当提问内容与所有知识库无关时，仍进入知识库查询节点，表现为流程超时或返回无关AI回答。原因是未覆盖非匹配场景，且未设置合理的超时时间。

## 怎么确认配好了
- 手动触发一次工作流，查看各节点的输入输出参数，确认`variables`中的核心变量已正确映射至对应系统数据。
- 上传不同类型的测试文档，验证工作流是否按文档类型路由至预设的对应知识库节点。
- 模拟与知识库无关的测试提问，验证流程是否跳转至预设的异常回复节点。
- 查看工作流的运行日志，确认未出现超过600秒的阻塞情况。
