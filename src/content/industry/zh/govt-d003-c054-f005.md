# 防汛防灾与应急值守的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控。日常需处理的文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单。数据更新频率为每日，部分实时监测数据更新间隔更短。文档字段包含雨情水情数值、险情等级、物资数量、转移安置人数等，对应单位通常为毫米、立方米每秒、件、人等，不同来源文档的字段格式存在差异。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源异构的数据来源要求工具调用需支持多数据源的并行拉取与格式统一，否则无法完成跨系统的台账汇总。每日更新的频率与部分实时数据的短间隔要求，需配置定时触发与实时触发结合的插件调度规则，避免数据滞后。文档字段的差异要求插件需内置字段映射规则，将不同来源的文档转换为统一的台账格式。同时，该品类出错后果直接关联应急处置效率，需为工具调用配置失败重试与告警机制，确保关键数据不丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配应急场景中多变的任务类型，自动选择匹配的工具完成数据拉取与汇总 |
| 工具调用超时时间 | `600 秒` | 多源数据拉取需跨系统交互，预留充足时间完成水文、气象等数据的整合 |
| 工具调用重试次数 | `2–3 次` | 应对网络波动或系统临时响应延迟，避免单次调用失败导致台账生成中断 |
| `functionCall` | `strict: true` | 严格匹配应急文档的预设字段格式，确保生成的台账与报告符合规范 |
| 插件上下文窗口 | `前 8 条聊天记录` | 保留近期会商纪要与灾情速报的关键信息，支撑连续的应急处置报告生成 |
| 插件触发时机 | 按数据更新节点触发 | 匹配水文、气象数据的更新节奏，确保台账内容与实时灾情同步 |

## 容易做错的三处
- 现象：调用工具接口时返回状态码400，响应体提示参数格式错误。原因：未正确绑定工具调用的字段映射，导致请求体与应急文档的字段要求不匹配。
- 现象：插件的文本内容提取节点返回空字段。原因：未针对应急场景的特定文档类型配置字段规则，无法识别值班记录、物资调拨单中的目标字段。
- 现象：连续对话中工具调用的上下文丢失。原因：未设置合适的上下文窗口大小，导致早期的会商纪要与灾情信息被清理，无法支撑后续的报告生成。

## 怎么确认配好了
- 手动触发工具调用，检查是否能从指定的水文监测系统拉取对应时段的雨情数据，并完成格式转换。
- 模拟包含多轮应急会商的对话，确认工具调用时保留了前8条聊天记录中的关键信息。
- 断开模拟的数据源连接，验证工具调用是否触发超时重试机制，并生成对应的错误日志。
- 查看FastGPT v4.17.0的后台配置日志，确认`toolChoice`和`functionCall`的参数已按配置生效。
