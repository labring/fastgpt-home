# 防汛防灾与应急值守的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
该品类的数据主要来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控。日常生成的文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单。数据更新频率以日为基准，关键灾情数据会实时同步。文档字段包含雨情水情的降雨量、水位数值，灾情的人员转移数量、物资调拨量，以及预警发布、处置完成等时间戳，部分文档需关联跨部门的协同信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/fastgpt?authSource=admin` | 存储台账与历史会商数据，需配置正确的认证与数据库指向，适配应急场景的高频写入需求 |
| `DB_MAX_LINK` | `100–150 个连接` | 该品类包含实时同步的雨情水情数据，需限制数据库连接数避免资源耗尽，保障服务稳定性 |
| `STORAGE_S3_ENDPOINT` | `按实测标定` | 存储灾情速报与视频监控截图，需适配本地或云存储的端点地址，确保文件可正常上传与下载 |
| `REDIS_URL` | `redis://:password@host:port/0` | 缓存实时同步的雨情水情数据，降低重复查询压力，提升台账汇总的响应速度 |
| `FILE_TOKEN_KEY` | `32 位随机字符串` | 保护台账与报告的下载链接，防止未授权访问，符合应急数据的安全要求 |
| `PG_URL` | `postgresql://username:password@host:port/material` | 存储结构化的物资调拨与人员转移数据，适配关系型查询需求，便于快速统计调度信息 |

## 容易做错的三处
- 现象：通过API调用工作流生成台账时，拼接的变量字段为空，调试阶段可正常拼接。原因：未在API请求中正确携带与工作流变量匹配的参数，或变量绑定未关联到对应数据源。
- 现象：Docker容器启动后一直处于启动转圈状态。原因：未正确配置`MONGODB_URI`或`REDIS_URL`参数，导致依赖服务连接失败，服务无法正常初始化。
- 现象：查看mongoose版本时，在package.json可找到但npm list无法查询到。原因：未在当前项目目录下执行依赖查询命令，或全局npm环境与项目依赖的安装路径未关联。

## 怎么确认配好了
- 登录FastGPT管理后台，核对`MONGODB_URI`、`REDIS_URL`等核心连接参数的配置内容，验证依赖服务的连通性。
- 导入单条模拟灾情数据，触发台账汇总工作流，检查生成的报告是否匹配预设的文档结构与字段单位。
- 调用测试API接口，传入符合格式的参数，确认返回结果包含所有配置的变量内容。
- 执行容器重启操作，确认服务启动流程无异常报错日志。
