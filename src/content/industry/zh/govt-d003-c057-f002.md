# 食品安全监督抽检的台账汇总与报告生成：向量模型与索引
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类数据主要来自食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS系统及食品生产经营者台账。日常文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。数据更新频率为月度，单份文档字段包含抽样点位、检验项目、结果判定、处置措施等，无统一固定单位，需按文档类型匹配对应字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的批量数据要求索引支持批量导入与增量更新逻辑，避免重复处理历史数据。多类型文档结构差异较大，需适配不同字段的向量提取规则，确保专业检测术语、抽样编号等关键信息被完整编码。来自多系统的数据格式不统一，需在索引前完成基础格式对齐，确保向量生成的一致性。台账汇总需关联多份关联文档，索引需支持跨文档的关联检索能力，保障汇总数据的完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配单份抽检报告的字段密集度，避免块内关键信息断裂 |
| 重叠长度 | 100–200 字符 | 保留跨块的抽样编号、检验项目等关联信息，确保检索时的上下文完整性 |
| `defaultToken` | 8192 | 匹配Qwen3-Embedding-8B模型的最大输入token限制 |
| `maxToken` | 16384 | 支持汇总多份关联文档的上下文长度，满足台账汇总的关联检索需求 |
| 相似度阈值 | 0.72–0.85 | 区分合格与不合格检验结果的语义相似度，过滤低关联度的检索结果 |
| 单次搜索上限 | 前10条 | 覆盖月度抽检批次的典型关联文档数量，保障汇总数据的完整性 |

## 容易做错的三处
- 界面显示索引结果条数不足。现象为检索特定抽检项目时返回结果少于预期。原因：未按月度批量数据调整单次搜索上限，默认取值未覆盖当月抽检批次的关联文档数量。
- 配置同名嵌入模型后覆盖原有设置。现象为本地部署的M3E模型配置被Qwen3-Embedding-8B的配置覆盖。原因：未为不同部署的模型创建唯一标识，使用系统默认的模型名称作为配置键。
- 向量检索结果包含大量无关文档。现象为检索不合格食品处置信息时，返回大量合格检验报告。原因：未针对抽检报告的专业术语调整相似度阈值，导致低语义相似度的非关联文档被误召回。

## 怎么确认配好了
- 上传单份抽样单文档，检查分块后的向量存储状态，确认块长度符合预设区间。
- 导入月度批量抽检数据，验证索引更新进度，确认支持增量更新逻辑。
- 检索特定检验项目关键词，核对返回结果的文档类型与来源系统是否匹配。
- 测试同名模型的多实例配置，确认不同部署的模型不会互相覆盖。
