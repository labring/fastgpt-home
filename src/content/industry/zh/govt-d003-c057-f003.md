# 食品安全监督抽检的台账汇总与报告生成：多轮对话与提示词
本文适配FastGPT v4.17.0版本的多轮对话与提示词配置，针对食品安全监督抽检场景的台账汇总与报告生成需求提供具体指引。

## 这个品类的数据长什么样
该品类的数据来源包括食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS系统、食品生产经营者台账。数据更新频率为月度，日常文档涵盖抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。数据字段包含抽样标识、检验项目、不合格判定结果、处置措施等，单位涉及批次、项次、检测数值等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
月度更新的批量数据要求多轮对话需支持分批次加载文档，避免单次上下文溢出。多源数据来源要求提示词明确区分抽检计划、抽样单、检验报告等不同文档类型的字段规则，确保汇总时的字段对齐。不同业务主体的台账格式差异，要求提示词预设统一的输出模板。数据关联的严格合规性要求，需在对话中强制校验原始数据与生成报告的一致性，避免出现错误关联。同时需适配不同调用场景的上下文长度限制，确保关键抽检信息不被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前抽检批次的唯一标识 | 确保多轮对话关联同一批次的所有文档，避免数据混淆 |
| `messages` | 保留最近15–20条对话记录 | 聚焦近期抽检相关的交互信息，避免历史冗余内容干扰生成结果 |
| `variables` | 预设抽样编号、检验项目、处置措施三类变量 | 统一不同来源文档的字段映射规则，确保台账汇总的格式一致性 |
| 最大上下文长度 | 8000–12000 字符 | 匹配月度批量抽检相关文档的总字符量，避免核心抽检信息被截断 |
| 单次回复token上限 | 1200–1500 token | 匹配单份检验报告的典型输出长度，确保完整呈现检测结果 |

## 容易做错的三处
- 现象：调用AI对话节点后偶尔出现空响应，无任何生成内容。原因：未设置上下文兜底逻辑，当批量抽检文档超出`messages`配置的上下文长度时，触发模型空输出。
- 现象：生成的报告末尾出现未闭合的引用符号，后续交互后自动修正。原因：提示词未明确要求输出格式的闭合规则，未对检验报告的引用字段做强制校验。
- 现象：尝试调用超过7天的历史抽检文档时，系统提示文件不存在。原因：未调整文件过期时间配置，默认7天的设置与月度数据更新节奏不匹配，导致历史数据被提前清理。

## 怎么确认配好了
- 调用预设的`variables`变量，检查是否能自动映射不同来源的抽检文档字段，验证字段对齐效果。
- 上传多份不同类型的抽检文档，验证最大上下文长度设置是否能完整加载所有文档内容，无截断情况。
- 模拟多次多轮对话交互，检查`messages`的历史记录保留数量是否符合预期，无冗余或缺失的交互内容。
- 调整文件过期时间后，验证超过设置时长的抽检文档是否能正常被调用，匹配业务更新节奏。
