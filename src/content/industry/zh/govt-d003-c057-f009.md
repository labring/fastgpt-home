# 食品安全监督抽检的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类服务主体包括市场监管局食品抽检处、检验机构、基层监管所及食品生产经营者，数据主要来自食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS系统及食品生产经营者台账，更新频率为每月一次。日常文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告，各文档含抽样批次、检验项目、不合格项、处置措施等专属字段，数据结构随监管要求与检验流程固定。

## 这些特征在「模型接入与配置」这一环带来什么约束
每月固定更新的批量数据要求模型接入需支持批量任务调度与增量同步，避免重复处理历史数据；多来源异构文档需配置适配不同格式的解析规则，防止字段提取出现偏差；不合格项、处置措施等核心监管字段的高置信度要求，需限制模型生成内容与源数据的匹配精度；监管公示文档的固定格式要求，需锁定模型输出的排版与官方模板一致，避免格式错误影响后续公示流程。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写对接的模型服务接口地址，使用中转服务时填写对应中转地址 | 完成模型调用的路径配置，适配批量任务的接口调用需求 |
| `AIPROXY_API_TOKEN` | 填写模型服务分配的访问密钥 | 完成身份校验，确保接口调用权限合法有效 |
| `maxContext` | 8000–12000 token | 覆盖单月抽检全量文档的上下文长度，避免截断核心抽样与检验数据 |
| `maxTokens` | 4000 token | 限制单份报告生成的输出长度，适配监管文档的固定篇幅要求 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保不合格项、处置措施等核心字段的输出与源数据高度匹配 |
| `toolChoice` | auto | 自动选择工具处理批量文档解析，提升台账汇总的处理效率 |

## 容易做错的三处
- 界面提示接口调用失败，且OneAPI单独测试正常。原因是`AIPROXY_API_TOKEN`配置错误，或接口地址未正确指向中转服务的有效路径。
- 应用内设置指定模型后，实际调用仍返回其他模型的结果。原因是未在配置中锁定目标模型的标识，或中转服务的模型映射配置有误。
- 生成的报告出现核心字段缺失。原因是`maxContext`取值过小，导致源文档上下文被截断，无法完整提取全部必要字段。

## 怎么确认配好了
- 调用FastGPT内置的测试接口，返回正常的身份校验通过提示，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确。
- 上传单份抽检报告，验证模型提取的抽样批次、检验项目等字段与源文档一致，确认`temperature`与`maxContext`取值适配字段提取需求。
- 发起单份报告的生成任务，检查输出格式与官方监管模板对齐，确认输出约束配置生效。
- 配置批量任务触发规则，按每月更新频率测试同步流程，确认批量调度功能正常运行。
