# 仓储物流的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
仓储物流的台账数据主要来源于仓储管理系统（WMS）、运输管理系统（TMS）、出入库单据、运输调度单等业务系统。数据更新节奏分为两类：出入库、运输状态等实时操作数据随业务节点更新，月度汇总台账、季度分析报表按周或月度周期更新。单份台账文档为结构化表格形式，包含物料编码、入库时间、出库数量、存储仓位、运输单号、配送地址等字段，字段单位涵盖件、箱、吨、公里等业务专属单位。本文档基于FastGPT v4.17.0版本编写。

## 这些特征在「工作流编排」这一环带来什么约束
仓储物流台账的数据来源分散，要求工作流需配置多节点分别拉取不同系统的数据源，避免单一节点的数据过载。数据更新节奏的差异，要求工作流支持定时触发与手动触发两种模式，适配实时汇总与周期报表的不同需求。结构化字段与专属单位的特征，要求工作流中的`variables`需严格匹配台账字段名与单位，避免格式转换错误导致汇总结果异常。跨数据源的聚合需求，要求工作流需设置数据流转节点，完成不同系统数据的对齐与整合。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定物料编码、存储仓位、运输单号3个核心字段 | 仓储物流台账的核心统计维度为物料、仓位、运输链路，需将这些字段作为工作流全局变量 |
| `nodeId` | 为WMS数据拉取、TMS数据拉取、汇总计算、报告生成节点分别配置唯一ID | 工作流编排中需精准控制节点执行顺序，唯一ID可避免节点混淆 |
| 触发方式 | 每日0点定时+手动触发 | 仓储台账包含周度汇总报表与实时出入库数据，双触发模式适配不同业务场景 |
| 循环控制 | 100-200条/次 | 仓储物流单批次台账数据量通常在百级到千级，分批次处理可避免超时 |
| 超时设置 | 600秒 | 跨系统拉取数据并完成汇总的操作通常需要数分钟，预留足够时长避免中途中断 |
| 最大上下文长度 | 8000 token | 工作流需保留完整的对话与操作记录，足够的上下文长度可避免早期数据被截断 |

## 容易做错的三处
- 现象为工作流中循环调用数据节点时，仅处理部分台账条目，原因是未配置循环终止条件，或循环触发的`variables`未绑定正确的分页参数。
- 现象为运行模式下工具调用报错，调试模式正常，原因是运行模式下未绑定生产环境的数据源密钥，或节点权限配置与调试环境不一致。
- 现象为导出的工作流对话记录仅显示最后6条问题，原因是导出配置中未开启全量记录拉取，或上下文长度限制截断了早期对话内容。

## 怎么确认配好了
- 手动触发工作流，查看各节点的日志输出，确认`variables`绑定的字段均能正确拉取到对应数据。
- 模拟单次批量数据处理，检查循环节点的执行次数与台账条目数量匹配。
- 触发报告生成节点，确认导出的台账文件字段与单位与原始数据一致。
- 切换到运行模式，执行一次完整工作流，验证无报错且输出结果完整。
