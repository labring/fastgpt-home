# 勘察设计的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
数据主要来自现场勘察原始记录、岩土试验报告、施工图设计文件、项目报审台账等。更新节奏跟随项目阶段推进，初步设计阶段更新一次，施工图设计阶段完成二次更新。单份文档包含结构化字段与附件两部分，结构化字段含项目编号、勘察点位坐标、岩土力学参数、设计荷载值等，单位涵盖米、兆帕、千牛等工程专用单位，附件多为CAD图纸或PDF格式的正式报告。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
勘察设计台账与报告的结构化字段包含工程专用单位，HTTP接口请求的参数需准确匹配字段名与单位格式，避免解析错误。附件多为CAD、PDF格式，接口需支持二进制流传输与大文件分片处理。数据更新跟随项目阶段动态调整，接口需支持按项目唯一标识拉取最新版本数据，避免返回过时内容。单份文档内容较长，接口单次返回条数需限制，防止超时或带宽占用过高。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer 内网部署的大模型API密钥` | 适配内网环境下的身份校验，避免`unAuthApiKey`报错 |
| `variables` | `映射勘察设计台账的结构化字段，包含项目编号、岩土参数等，保留工程专用单位` | 准确传递业务数据，避免字段解析错误 |
| `responseData` | `仅返回结构化字段与附件元数据，大文件通过单独接口拉取` | 减少单次接口传输的带宽占用，避免超时 |
| 请求超时时间 | 600 秒 | 适配勘察设计文档的长时处理需求 |
| 大文件传输模式 | 分片传输，每片 800–1200 千字节 | 适配CAD、PDF格式附件的大小特征 |
| API调用模式 | stream模式 | 适配仅支持stream的大模型调用需求 |

## 容易做错的三处
- 现象：返回`code:514`，状态文本`unAuthApiKey`。原因：未正确配置`Authorization`参数，或密钥与部署环境不匹配。
- 现象：调用大模型时返回格式错误，无法正常生成报告。原因：未开启stream模式，调用了仅支持stream的大模型。
- 现象：接口返回304状态码，未获取到最新台账数据。原因：接口缓存配置未关闭，或请求未携带最新的项目版本标识。

## 怎么确认配好了
- 调用测试接口，检查`Authorization`参数是否被正确携带，返回的身份校验结果为通过。
- 发起包含勘察设计专用字段的请求，检查`responseData`返回的字段是否与预设的台账结构一致。
- 触发大模型调用，确认返回的内容为流式输出，或匹配仅支持stream的大模型的返回格式。
- 上传大体积CAD附件，检查接口是否能正常分片传输并完成解析。
