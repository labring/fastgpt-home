# 勘察设计的台账汇总与报告生成：工作流编排
本文基于FastGPT v4.17.0版本的功能逻辑编写。

## 这个品类的数据长什么样
勘察设计的台账与报告数据主要来源于现场勘察日志、专业设计图纸、项目进度签证、材料进场记录等多类文档。数据更新节奏随项目推进不定期触发，单次更新的数据量波动较大。文档结构包含结构化字段与长文本附件两类，结构化字段包括项目编号、勘察点位坐标、设计变更次数、材料用量等，单位涵盖米、立方米、人次、批次等；长文本附件包含勘察技术说明、设计方案细则等内容。

## 这些特征在「工作流编排」这一环带来什么约束
多源分散的数据来源要求工作流需支持跨模块数据拉取与字段映射，避免人工整理的误差。数据量波动大的特性要求批量执行节点需适配动态子任务数量，防止资源过载。结构化与非结构化数据混合的文档结构，要求工作流需分别处理字段聚合与长文本解析环节，适配不同类型的内容提取与格式转换需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 全局变量`variables` | 按项目台账字段映射配置 | 适配勘察设计多源结构化字段的聚合与传递 |
| 节点超时时间 | 600–1200 秒 | 适配长文本解析与跨数据源的查询耗时 |
| 批量执行节点`nodeId` | 按子任务类型分组配置 | 区分勘察、设计、签证等不同类别的台账子任务 |
| 错误捕获节点 | 绑定对应`nodeId` | 精准定位模型调用或数据拉取的失败环节 |
| 上下文窗口 | 8000–12000 token | 适配勘察报告、设计方案等长文本内容的处理 |

## 容易做错的三处
- 调用大模型时出现429 Request rate increased too quickly报错，原因是未配置请求频率限制节点，未根据勘察设计项目的台账数据量调整并行执行数量。
- 批量执行节点完成后，循环内生成的子项结果无法传递到循环外部，原因是未正确使用`variables`追加子项数据，未在循环结束节点配置全局变量合并逻辑。
- 前序节点报错后流程直接终止，原因是未添加错误捕获分支，未绑定对应`nodeId`的失败回调配置。

## 怎么确认配好了
- 触发测试工作流，查看执行日志中是否包含对应`nodeId`的节点执行记录，确认全局变量`variables`的字段映射与实际台账数据一致。
- 模拟单条勘察台账数据执行，检查生成的报告是否包含所有配置的结构化字段与长文本内容。
- 触发批量执行任务，确认所有子项完成后，全局变量中包含所有子任务的结果数据。
- 模拟模型调用报错场景，确认流程是否进入错误捕获分支并生成对应报错日志。
