# 勘察设计的台账汇总与报告生成：数据库与运维

本配置适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
勘察设计的台账数据来源包括项目立项文件、勘察外业记录、设计图纸元数据、审批流转单据等。数据更新节奏随项目阶段推进调整，初设阶段、施工图阶段、竣工阶段分别触发批量更新，日常变更则实时推送。单份台账文档包含项目编号、勘察点位经纬度、材料规格参数、审批节点时间等字段，单位涵盖十进制经纬度、毫米、兆帕、YYYY-MM-DD格式时间等，部分文档附带多页的勘察报告附件，数据结构兼具结构化字段与非结构化文本。

## 这些特征在「数据库与运维」这一环带来什么约束
勘察设计台账的多类型字段要求数据库同时支持结构化关系存储与非结构化文档存储，增加了数据库选型与配置的复杂度。高频的阶段性批量更新与实时变更推送，会导致数据库连接请求峰值波动，需要合理配置连接池参数避免连接耗尽。附带的大体积勘察报告附件，会提升数据库的存储容量需求，需预留符合项目规模的磁盘空间。空间坐标字段的关联查询，也要求数据库配置对应的空间索引以保障查询效率。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://fastgpt:{{password}}@localhost:27017/fastgpt?authSource=admin` | 勘察设计台账包含非结构化的勘察报告附件、审批单据元数据，MongoDB适合存储灵活的非结构化数据 |
| `PG_URL` | `postgresql://fastgpt:{{password}}@localhost:5432/cems?sslmode=require` | 结构化的项目编号、点位坐标、材料参数等数据需要关系型数据库保障事务一致性与关联查询效率 |
| `DB_MAX_LINK` | `20–30 个连接` | 勘察设计项目的台账更新频率较高，该区间可覆盖峰值连接需求，避免请求排队 |
| `REDIS_URL` | `redis://:{{password}}@localhost:6379/0` | 可缓存重复的台账汇总查询请求，减少数据库重复查询压力，对应重复查询优化需求 |

## 容易做错的三处
- 启动后出现“unsupported wire version”或“AVX instruction set not found”报错，容器无法正常启动。原因是使用了MongoDB 5.x版本镜像，而宿主机CPU不支持AVX指令集，未更换为兼容的低版本镜像。
- 重复发起相同的台账汇总请求时，响应时间无明显缩短，数据库日志显示多次执行相同的查询语句。原因是未配置`REDIS_URL`或缓存规则未生效，未启用重复查询缓存机制。
- 台账中的图纸链接无法正常跳转，或关联查询返回空结果。原因是误将链接存储在MongoDB的非结构化集合中，未在PostgreSQL的结构化表中建立关联字段，导致关联查询失败。

## 怎么确认配好了
- 执行`docker ps`命令，确认MongoDB、PostgreSQL、Redis容器均处于运行状态，无异常退出或重启记录。
- 连续发起3次相同的台账汇总查询请求，观察第二次及第三次请求的响应时间是否较第一次有明显缩短。
- 登录PostgreSQL数据库，查看结构化台账表的字段与数据，确认项目编号、点位坐标等字段存储正确。
- 登录MongoDB数据库，查看附件元数据集合，确认勘察报告附件的关联信息存储完整。
