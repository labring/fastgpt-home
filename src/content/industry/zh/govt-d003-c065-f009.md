# 勘察设计的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
勘察设计的台账数据主要来源于项目勘察报告、施工图设计文件、现场施工日志、阶段性验收表单等。数据更新节奏随项目阶段动态调整，在初步设计、施工图审查、竣工验收等节点集中更新。文档结构包含结构化字段与非结构化文本两部分，结构化字段包括项目编号、勘察点位坐标、材料规格用量、工程造价等，附带米、平方米、立方米、千克等专业单位；非结构化内容包括勘察批注、设计变更说明、现场问题记录等。

## 这些特征在「模型接入与配置」这一环带来什么约束
勘察设计台账的混合结构与专业属性，要求模型接入配置需适配多类型数据处理需求。结构化字段的专业单位与专属术语，需要模型具备准确的格式解析能力，因此上下文长度配置需预留足够空间以容纳完整的台账数据。动态更新的节奏意味着模型调用的上下文刷新机制需支持非固定的数据加载，避免因数据截断导致分析偏差。同时，多源分散的文档来源，要求API接入配置需兼容不同的数据源路由路径，确保请求能正确传递至目标模型。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 勘察设计单项目台账通常包含数十条结构化字段与数页非结构化记录，需容纳完整的历史数据与当前查询上下文 |
| `maxTokens` | 2000–3000 token | 台账汇总与报告生成的输出需包含完整的字段统计与分析结论，预留足够的生成空间 |
| `temperature` | 0.2–0.4 | 需保证专业术语与数据格式的一致性，避免生成错误的单位或字段值 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务商地址填写 | 适配不同第三方LLM的接入路径，确保请求正确路由至目标模型 |
| `AIPROXY_API_TOKEN` | 填写服务商提供的有效密钥 | 完成模型接入的身份验证，避免请求被拦截或拒绝 |
| `toolChoice` | auto | 允许模型根据查询需求自动选择是否调用工具处理结构化台账数据 |

## 容易做错的三处
- 配置Ollama挂载的LLM模型后，返回结果与勘察设计台账的知识库内容无关。原因是未正确配置`maxContext`参数，导致模型无法加载完整的台账数据，仅依赖通用知识生成内容。
- 尝试通过OneAPI渠道接入Ollama部署的模型时无法正常调用。原因是未正确填写`AIPROXY_API_ENDPOINT`为OneAPI的中转地址，直接填写了Ollama原生的本地地址。
- 尝试添加rerank功能时找不到对应配置入口。原因是未在模型配置页面的高级设置区域查找对应选项，或未确认当前FastGPT版本支持该功能。

## 怎么确认配好了
- 发起一次针对单条勘察设计台账的查询，核对返回结果中是否包含正确的字段名称与单位。
- 测试调用接入的模型，查看返回的响应状态码是否为200，且无身份验证相关报错。
- 调整`temperature`参数的取值，观察生成内容的专业术语一致性是否符合预期。
- 提交包含多字段的台账汇总请求，核对生成的报告是否覆盖了所有指定的统计维度。
