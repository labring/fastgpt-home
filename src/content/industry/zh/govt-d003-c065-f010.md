# 勘察设计的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
勘察设计领域的台账与报告数据主要来自现场勘察原始记录、阶段性设计图纸、项目变更台账、审批批复文件。数据更新节奏随项目推进动态调整，初勘、详勘、施工图设计等关键阶段分别触发数据更新。文档包含结构化字段与非结构化内容，结构化字段含项目编号、勘察点位坐标、材料强度参数、审批节点等，单位涵盖米、兆帕、平方米、工作日等；非结构化内容为完整勘察报告、设计说明PDF。

## 这些特征在「知识库检索与召回」这一环带来什么约束
勘察设计数据的多字段结构化特征，要求检索需同时匹配业务字段与语义内容，避免仅依赖语义召回导致的字段匹配偏差。长文档占比高，分块时需保留相邻字段的上下文关联，防止拆分后丢失参数关联信息。数据更新随项目阶段动态调整，需在检索时优先召回近期更新的内容，避免使用过期的勘察或设计数据。多单位共存的场景下，检索需关联字段与单位的绑定关系，防止混淆不同参数的计量标准。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配勘察设计参数的精准度要求，过滤低相关性的非业务文档 |
| `limit` | 前8条 | 覆盖台账的多字段关联信息，避免召回条数过少导致参数缺失 |
| `searchMode` | hybrid | 结合结构化字段匹配与语义检索，适配多字段结构化的勘察设计数据 |
| `usingReRank` | 开启 | 对初始召回的结果进行二次排序，修正长文档分块后的语义偏差 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展业务术语，比如将“抗压强度”关联至“MPa”单位的参数检索 |
| `collectionIds` | 按项目绑定的数据集ID | 符合FastGPT v4.17.0的数据集限定规则，限定检索范围至当前项目的勘察设计台账与报告，避免跨项目数据干扰 |

## 容易做错的三处
- 现象：检索结果与业务问题不匹配，例如查询“某项目的施工图台账”却召回了无关的勘察点位记录。原因：未使用`searchMode`的混合检索模式，仅依赖纯语义召回忽略了结构化字段匹配。
- 现象：语义检索得分显示为0.9以上，但结果中包含过期的勘察数据。原因：未根据项目阶段调整数据集更新频率，未优先召回近期更新的内容。
- 现象：检索结果中单位混淆，例如查询“钢筋抗拉强度（MPa）”却召回了以psi为单位的参数记录。原因：未开启`datasetSearchUsingExtensionQuery`，未关联参数与对应单位的检索规则。

## 怎么确认配好了
- 查看检索配置面板，确认`collectionIds`已绑定当前项目的勘察设计数据集，无跨项目数据集被纳入。
- 发起测试查询，验证检索结果是否同时匹配业务字段与语义内容，例如查询“某点位的勘察坐标”时，结果包含对应的坐标数值与点位说明。
- 检查检索得分与结果条数，确认`similarity`阈值与`limit`条数符合当前项目的业务精度要求，可根据测试结果调整。
- 开启`usingReRank`后，对比排序前后的结果，确认二次排序修正了长文档分块后的语义偏差。
