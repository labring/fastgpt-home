# 化工新材料的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
这个品类的数据主要来自生产投料日志、质检报告单、仓储出入库单据、研发配方存档。数据更新节奏为单批次生产完成后实时同步，或每日批量拉取。文档分为结构化台账表格与非结构化附件两类，结构化字段包含批次号、原料牌号、投料量、反应温度、产品纯度指标、入库时间、存储条件，单位分别为唯一标识字符串、牌号编码、千克、摄氏度、纯度指标、日期、温度区间。

## 这些特征在「工作流编排」这一环带来什么约束
结构化字段多且带有专属单位，工作流编排需严格匹配字段映射规则，避免字段错位导致的台账汇总错误。非结构化附件占比高，需单独配置文档解析节点，且需规避历史文档重复加载的问题。数据更新分为实时同步与每日批量拉取两种模式，工作流需支持对应触发条件。批次号作为唯一标识，需通过`variables`关联上下文，确保不同批次的数据独立处理，避免跨批次数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发条件 | 按批次完成事件触发，或每日凌晨2点批量触发 | 匹配化工新材料台账的实时/批量更新节奏 |
| 字段映射规则 | 按批次号、投料量、反应温度等字段一对一映射 | 匹配结构化台账的专属字段与单位 |
| `variables` | 绑定批次号作为上下文键 | 确保不同批次数据独立处理，避免混淆 |
| 文档解析节点 | 仅解析当前上传的附件，排除历史文档 | 规避历史文档重复加载的问题 |
| `nodeId` | 为文档解析节点设置唯一标识 | 便于工作流编排时精准调用该节点 |
| 失败重试次数 | 3次，间隔60秒 | 应对单次数据拉取或解析的临时异常 |

## 容易做错的三处
- 现象：工作流运行时返回字段为空或格式错误。原因：未严格按照化工新材料台账的专属字段与单位配置映射规则，导致字段错位。
- 现象：文档解析节点每次运行都加载历史上传的所有附件。原因：未配置仅解析当前上传附件的规则，未通过`nodeId`锁定当前解析节点的上下文。
- 现象：调用工具时无法触发预设逻辑。原因：触发条件未匹配化工新材料台账的更新节奏，或`variables`绑定的上下文键未正确关联批次号。

## 怎么确认配好了
本核对流程基于FastGPT v4.17.0版本执行：
1. 手动触发单批次台账的工作流，检查结构化字段是否完整映射，无错位或缺失。
2. 上传单份非结构化附件，确认仅当前附件被解析，历史附件未被加载。
3. 模拟异常触发场景，检查工作流是否按预设次数重试并记录失败日志。
4. 验证`variables`绑定的批次号是否在不同批次的运行中独立生效，无跨批次数据混淆。
