# 化工新材料的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
这个品类的台账数据主要来自企业内部生产执行系统、质检管理系统、仓储物流系统的结构化记录，以及研发部门的半结构化测试报告。数据随生产批次实时更新，或每日完成批量同步。单份台账文档多为表格形式，包含材料牌号、批次号、投料重量、质检指标、出入库时间等字段，单位涵盖千克、吨、兆帕、摄氏度等专业化工计量标准。部分研发台账还会附带扫描版的原始测试图谱，属于半结构化混合数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的多源结构化与半结构化混合数据特征，对模型接入配置带来三点约束。其一，台账包含大量专业化工计量字段与单位，要求接入的模型具备专业领域术语识别能力，配置时需确保上下文窗口可承载完整的单批次台账字段信息。其二，数据随生产批次实时更新，批量汇总时单次处理的数据量较大，需合理限制单次请求的token上限以避免接口超时。其三，部分研发台账附带原始测试扫描图谱，需配置支持视觉识别的模型参数，适配混合数据的解析需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单批次台账与关联质检数据的总字段长度，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 限制单轮生成的报告长度，匹配化工台账汇总的输出需求 |
| `vision` | 开启 | 适配附带测试图谱的研发台账，支持视觉数据解析 |
| `temperature` | 0.1–0.3 | 保持台账数据汇总的准确性，避免生成偏离原始数据的内容 |

| `AIPROXY_API_TOKEN` | 填写企业申请的专属密钥 | 保障模型调用的身份验证安全 |

## 容易做错的三处
- 点击模型属性配置后弹出参数校验报错，原因是未正确填写`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`的格式，导致接口身份验证失败。
- 尝试识别台账附带的测试图谱时生成空结果，原因是未开启`vision`配置项，模型无法调用视觉识别能力解析扫描图片。
- 批量汇总多批次台账时出现超时错误，原因是未合理设置`maxContext`与`maxTokens`的取值，单次请求的数据量或生成长度超出模型接口限制。

## 怎么确认配好了
- 测试调用单份结构化台账数据，检查模型返回的汇总内容是否完整包含所有预设字段，字段数值与原始数据匹配。
- 上传一份带测试图谱的台账文档，验证模型是否能识别图谱中的关键质检指标并纳入汇总内容。
- 发起批量台账汇总请求，检查接口返回状态是否正常，无参数校验或超时类报错。
- 查看系统日志，确认模型接入的接口地址与密钥配置已被正确加载。
