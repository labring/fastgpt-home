# 化肥农药的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
化肥农药的台账数据主要来自企业内部的ERP生产系统、质检实验室系统、销售出库系统，以及农业农村部门的监管备案平台。生产台账每日更新，记录单批次的原料投入、工艺参数与成品产出；销售台账随出库操作实时更新，包含流向、数量与客户信息；监管备案数据按季度同步，涵盖产品登记与合规检测信息。单条台账文档多为结构化记录，包含生产批次编号、原料名称、投入量、质检指标数值、出库日期等字段，部分附带有质检报告的全文文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源数据的格式差异要求索引层支持跨系统字段对齐，避免因字段名或单位不一致导致的嵌入偏差。不同数据源的更新频率差异，需要配置分层的索引刷新策略，区分实时更新的销售台账、每日更新的生产台账与季度更新的备案数据。结构化字段与非结构化文本的混合存在，要求向量模型同时适配数值特征与文本描述的嵌入，确保汇总报告能关联质检结果与生产记录。单条台账的长度集中在较短区间，需避免过度分块导致的上下文断裂，同时保证长文本的质检报告能被完整嵌入。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 单条生产台账与质检报告的文本长度多在500-1000字符，该区间可覆盖完整业务信息 |
| 重叠长度 | 100–150 字符 | 避免跨块的生产批次、质检项信息断裂，保证关联字段的上下文完整性 |
| `maxToken` | 4096 token | 适配单批次台账汇总报告的文本长度，匹配主流向量模型的输入限制 |
| 相似度阈值 | 0.72–0.78 | 区分同品类原料台账与相似批次记录，减少非目标台账的误匹配 |
| 单次搜索上限 | 前 10 条 | 覆盖近7天的生产与销售台账，满足常规汇总报告的数据源需求 |
| `defaultToken` | 2048 token | 作为默认嵌入上下文的基准长度，适配台账字段的平均文本长度 |

## 容易做错的三处
- 现象：调用向量模型时返回503状态码，提示当前分组default下对于模型text-embedding-v3无可用渠道。原因：未配置对应模型的渠道权限，或default分组的资源配额耗尽。
- 现象：检索结果中出现单位不一致的原料台账记录。原因：未在索引预处理环节统一原料投入量、成品产出量的单位，导致数值特征的向量嵌入出现偏差。
- 现象：增量索引更新后，部分近期的销售台账未被检索到。原因：未设置与销售台账实时更新节奏匹配的索引触发规则，仅按固定周期执行全量索引。

## 怎么确认配好了
- 上传单条生产台账与质检报告，检查向量嵌入后的文本块是否覆盖完整字段，无关键信息截断。
- 触发增量索引，核对更新后的检索结果是否包含最新的销售出库记录，匹配预设的更新时间范围。
- 调整相似度阈值，验证检索结果的匹配精度是否符合台账汇总的业务需求。
- 查看FastGPT v4.17.0的模型调用日志，确认`defaultToken`与`maxToken`的配置未超出所选向量模型的输入限制。
