# 化肥农药的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
化肥农药的台账数据主要来自农资进销存系统、农业技术推广备案平台、田间作业记录与农药登记数据库。数据更新节奏分两类：进销存类随每日交易实时更新，备案类按季度同步更新。单份台账文档包含批次号、生产厂家、有效成分含量、进货量、出货量、库存、使用地块与对应面积等字段，单位涵盖吨、千克、毫升、公顷等。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的分散存储要求工作流需配置多个数据库连接节点对接不同系统，需通过`variables`统一管理跨节点的字段映射规则。不同更新节奏的数据源，需设置差异化的触发周期，进销存数据触发间隔可设为`1 天`内，备案数据可设为`7 天`。字段与单位的多样性，要求工作流需包含数据清洗节点，对不同来源的含量、数量字段做单位转换与格式校验，避免后续汇总出现统计错误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 映射台账核心字段 | 统一管理跨节点的批次号、有效成分等数据 |
| 数据库连接超时时间 | 600 秒 | 适配多源数据拉取的延迟特性 |
| 触发节点 | `nodeId` 绑定数据更新事件 | 精准控制工作流启动时机 |
| 上下文复用开关 | 开启 | 保留历史对话中的汇总参数配置 |
| 错误重试次数 | 3 次 | 应对临时的数据库连接波动 |

## 容易做错的三处
- 工作流运行后全局变量未生效，表现为单选变量字段为空。原因是未将`variables`中的值正确绑定到单选节点的选项映射中。
- 数据库连接节点报错提示权限不足，表现为返回Access denied相关内容。原因是未配置对应数据源的正确访问账号与权限范围。
- 工作流调用API后无法复用历史上下文，表现为每次调用都丢失之前保存的台账汇总参数。原因是未开启上下文复用开关，或未正确设置上下文保存周期。

## 怎么确认配好了
- 触发一次测试工作流，核对拉取的数据源字段与预设的`variables`映射是否一致。
- 模拟数据库连接异常场景，检查是否触发预设的错误重试机制。
- 保存工作流配置后重新加载，确认上下文复用开关的状态是否保留。
- 查看工作流运行日志，确认触发条件与预设的`nodeId`绑定事件匹配。
