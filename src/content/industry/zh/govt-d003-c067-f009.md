# 化肥农药的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
化肥农药的台账数据主要来自生产投料记录、批次质检报告、仓储出入库单据及销售流向档案。生产台账每日更新，质检报告随生产批次同步生成，仓储与销售数据随业务节点实时更新。单份台账文档以批次为单位，包含生产批次号、原料名称、有效成分占比、投料重量、生产时间、质检编号、出入库数量、流向主体等字段，重量单位多为千克或吨，占比以百分比标注，时间格式统一为年-月-日。

## 这些特征在「模型接入与配置」这一环带来什么约束
化肥农药台账的多字段结构化特征、专业术语属性及分批次更新的节奏，对模型接入配置带来多重约束。首先，台账包含有效成分占比、投料重量等带单位的专业字段，要求模型输出严格匹配字段名与单位，需限制生成随机性并配置格式校验。其次，多批次台账汇总需容纳较多上下文数据，需合理设置上下文长度参数。再次，化工领域专业术语较多，需适配专用的索引模型，支持非通用的模型接入。最后，业务链路涉及多数据源同步，需配置失败重试与多模型 fallback 机制，应对单模型不稳定的情况。

## 配置怎么定
本配置说明基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `temperature` | 0.1–0.3 | 台账汇总需严格匹配字段名与单位，低温度可降低生成随机性，避免出现错误的单位或非预设字段值 |
| `maxContext` | 8000–12000 token | 多批次台账汇总需容纳多份单据的上下文数据，该区间可避免截断关键批次关联信息 |
| `maxTokens` | 2000–3000 token | 单份汇总报告的输出长度符合业务需求，可避免生成内容被提前截断 |
| `toolChoice` | auto | 台账汇总需关联批次、质检、出入库等多个数据节点，自动选择工具可提升数据整合的准确性 |
| `AIPROXY_API_ENDPOINT` | 填写适配化工领域的国产模型代理地址 | 针对化肥农药的专业术语优化语义理解，替代通用大模型的适配短板 |
| `AIPROXY_API_TOKEN` | 填写对应代理平台的有效授权令牌 | 完成模型接入的身份验证，确保调用权限正常 |

## 容易做错的三处
- 现象：调用模型时出现503服务不可用报错，或生成结果为空、格式错误。原因：未配置多模型 fallback 机制，单模型不稳定时无法自动切换备用模型。
- 现象：专业术语（如“戊唑醇”“氮磷钾15-15-15”）的召回准确率低，检索结果不相关。原因：未配置适配化工领域的国产索引模型，仍使用通用嵌入模型，无法准确匹配专业语义。
- 现象：生成的汇总报告未按预设字段输出，出现多余字段或单位错误。原因：未限制`temperature`参数的取值，生成随机性过高，未强制匹配台账的固定字段与单位规则。

## 怎么确认配好了
- 发起单批次台账的汇总测试，核对生成内容的字段与单位是否与预设台账规则匹配，调整对应参数直至符合要求。
- 模拟模型调用失败的场景，验证是否自动切换至备用模型，完成汇总任务无中断。
- 接入国产索引模型后，检索化工专业术语相关的台账数据，核对召回结果的相关性是否满足业务需要。
- 查看系统日志，确认模型接入相关的配置项已生效，无调用权限报错或地址错误提示。
