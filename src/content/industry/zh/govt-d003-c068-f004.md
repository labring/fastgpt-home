# 医药流通的台账汇总与报告生成：工作流编排
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
医药流通的台账数据主要来自企业进销存管理系统、物流配送终端系统及药监报备平台。数据更新按每日业务批次触发，单次更新覆盖当日全量流通单据。单份台账文档为结构化表格格式，包含药品通用名、批准文号、入库数量（单位：盒/箱）、出库时间、流通批次、验收合格状态、供应商统一社会信用代码等字段，字段类型涵盖文本、日期、数值三类。

## 这些特征在「工作流编排」这一环带来什么约束
医药流通台账多系统来源的特征，要求工作流编排中配置跨系统数据拉取节点，分别对接进销存、物流及药监平台接口。按日更新的节奏，限定工作流触发周期需匹配业务批次频率，避免重复拉取过期数据。结构化字段包含药监要求的合规字段，要求工作流中增加字段校验环节，确保批准文号、流通批次等必填项无缺失。单份文档字段数量较多，需合理配置数据聚合节点的合并规则，避免字段冲突导致的报告错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 数据源节点 | 分别对接进销存、物流、药监平台接口 | 医药流通台账数据来自三类业务系统，需分别拉取对应数据源 |
| 触发周期 | 每日凌晨2点 | 匹配业务当日数据的次日更新节奏，避开业务高峰时段 |
| `variables` | 配置custId、batchDate、supplierId参数 | 用于传递业务标识与时间范围，精准拉取对应台账数据 |
| JSONPath提取规则 | 提取`$..data.list`下的字段 | 匹配医药流通台账结构化数据的嵌套格式，精准提取业务字段 |
| HTTP请求超时时间 | 300秒 | 适配药监平台接口的响应延迟，避免超时中断流程 |
| 工作流导出配置 | 按YYYY-MM-DD命名文件，存储至合规存储路径 | 匹配台账归档的合规要求，便于后续溯源与查询 |

## 容易做错的三处
- 现象：工作流运行后下游节点拉取数据为空，全局变量未生效。原因：未在`variables`配置中正确绑定query参数的custId值，或未将变量传递至对应数据源节点。
- 现象：HTTP请求节点返回状态码504，工作流执行失败。原因：HTTP请求超时时间配置过短，未适配药监平台或物流系统的响应延迟。
- 现象：导出的台账报告存在字段缺失或重复。原因：JSONPath提取规则未覆盖全量必填字段，或数据聚合时未处理字段冲突。

## 怎么确认配好了
- 手动触发工作流，查看各数据源节点的拉取日志，确认返回数据包含药品通用名、批准文号等台账必填字段。
- 配置测试用的全局变量参数，运行工作流后检查下游节点是否正确使用该变量拉取对应业务数据。
- 查看HTTP请求节点的响应日志，确认JSONPath提取结果与预期的台账字段一致。
- 导出工作流配置文件，核对节点顺序与参数设置与预设配置一致。
