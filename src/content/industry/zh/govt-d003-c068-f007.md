# 医药流通的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
医药流通的台账数据来源包括内部进销存管理系统、冷链温湿度监测终端、药品监管报备接口。更新节奏分为实时（冷链环境温湿度数据）、每日（出入库台账）与定期（批次汇总报表）。单条台账数据结构包含药品通用名、批准文号、批次号、出入库数量、库存余量、环境温湿度、操作时间、关联单据号等字段，单位涵盖盒、支、℃、%RH、件等，单条数据长度较短，但批量汇总后的单任务数据集可达数万条。

以下内容基于FastGPT v4.17.0版本的数据库组件与工作流配置规范。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构数据的接入要求同时兼容关系型与非关系型数据库存储；高频实时的温湿度数据会产生大量小规格写入请求，对数据库连接池的并发处理能力提出要求；药品批次、操作时间作为高频查询字段，需要建立针对性索引以提升汇总效率；批量台账汇总任务常涉及数万条数据的关联计算，会占用较多数据库资源，需合理分配并发额度；医药流通数据需符合监管留存要求，需配置定期全量备份与增量同步机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://med_user:med_pass@db-host:5432/med_trade` | 医药流通进销存台账、批次数据存储于PostgreSQL，使用标准PostgreSQL连接格式 |
| `MONGODB_URI` | `mongodb://temp_user:temp_pass@mongo-host:27017/med_env?authSource=admin` | 冷链温湿度等非结构化时序数据存储于MongoDB，指定认证数据库以保障访问安全 |
| `DB_MAX_LINK` | `20–30 个连接` | 单批量汇总任务并发查询峰值约15个，预留冗余连接应对临时峰值场景 |
| `REDIS_URL` | `redis://:redis_pass@redis-host:6379/1` | 用于缓存高频查询的药品基础信息与台账汇总中间结果，使用独立数据库编号避免数据干扰 |

## 容易做错的三处
- 现象：大模型接口返回429状态码，或工作流执行时提示调用频率受限。原因：未配置并发限流规则，批量台账汇总任务同时触发大量大模型调用，超出接口调用限额。
- 现象：PostgreSQL查询返回结果为空或查询耗时显著增加。原因：未为药品批号、操作时间字段建立索引，批量汇总时触发全表扫描，占用过多数据库资源。
- 现象：数据库连接组件调试时返回`Access denied for user`报错。原因：配置的`PG_URL`或`MONGODB_URI`中用户名、密码或认证数据库参数错误，未授予对应数据库的读写权限。

## 怎么确认配好了
- 执行单条台账汇总测试任务，查看数据库连接日志，确认`PG_URL`、`MONGODB_URI`的连接状态为正常。
- 调整`DB_MAX_LINK`的取值，模拟并发查询场景，观察数据库资源占用情况，确认连接数配置适配当前任务峰值。
- 运行批量汇总任务，检查Redis缓存的中间结果是否生成，确认`REDIS_URL`的读写功能正常。
- 查看大模型调用日志，确认并发请求数符合接口限额要求，限流配置生效。
