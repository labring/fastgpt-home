# 医药流通的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
医药流通的台账数据主要来源于进销存管理系统、物流配送单据、入库出库凭证及药监备案文件。数据更新节奏为单笔交易实时同步，月末需完成全周期台账的汇总更新。单份台账文档通常包含药品通用名、批准文号、生产批号、入库数量、出库数量、库存结余、配送单号、经手人、交易日期等字段，单位涵盖盒、支、千克、件等多种规格。

## 这些特征在「模型接入与配置」这一环带来什么约束
医药流通台账的多字段与多单位特征，要求模型接入配置需适配精准的格式校验需求。单笔交易的实时同步特性，使得模型调用需支持高频请求，因此需合理设置上下文长度参数避免溢出。月末汇总的全量数据量较大，需确保模型输出的token长度足够覆盖完整的汇总报告。同时，药监相关字段的格式要求严格，需限制模型生成的随机性，避免出现不符合规范的字段内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 医药流通单批次台账汇总数据的token占用量通常处于该区间，避免上下文溢出导致模型调用失败 |
| `temperature` | 0.1–0.3 | 台账汇总与报告生成需要严格匹配药监字段格式与业务数据规则，较低的温度值可减少生成偏差 |
| `maxTokens` | 2000–3000 token | 单份月度汇总报告的输出长度需求覆盖常规台账条目统计、结余计算等内容的完整输出 |
| `toolChoice` | auto | 支持模型自主判断是否调用文件解析工具处理批量上传的台账CSV或Excel文件，适配多场景输入 |
| `AIPROXY_API_TOKEN` | 按服务商提供的有效密钥填写 | 满足模型调用的身份验证要求，确保接入权限合法有效 |
| `AIPROXY_API_ENDPOINT` | 按服务商指定的API地址填写 | 确保模型调用的路由正确，避免因地址错误导致的连接报错 |

## 容易做错的三处
- 现象：模型映射关系在配置保存后未生效，调用时仍使用默认模型。原因：未将配置同步至部署集群，或映射配置的保存路径有误。
- 现象：模型测试时返回API密钥无效或连接失败报错，使用第三方云服务商的模型API密钥与本地开源模型镜像均出现该问题。原因：未正确填写`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`，或本地开源模型服务未开放对应端口。
- 现象：正常对话可正常响应，但上传台账文件后模型无有效返回或输出格式混乱。原因：未将`toolChoice`设置为auto或required，或`maxContext`取值不足以容纳文件解析后的上下文数据。

## 怎么确认配好了
- 进入模型接入配置页面，核对`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的填写内容与服务商提供的官方信息一致。
- 运行内置的模型测试工具，输入单条标准台账数据，检查返回结果是否匹配预设的字段格式与业务逻辑。
- 上传批量台账文件，确认模型可自动识别并调用文件解析工具，生成符合要求的汇总内容。
- 调整`temperature`、`maxTokens`等参数后，验证不同配置组合下的模型调用稳定性与输出准确性。
