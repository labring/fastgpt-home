# 危化品储运的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
数据主要来自危化品储运管理系统的入库出库记录、现场巡检表单、第三方检测报告、应急处置台账。更新节奏为实时生成单次运输或存储记录，每日汇总全量存量数据。文档包含结构化字段与非结构化文本：结构化字段包括危化品名称、CAS号、存储仓位、存量（单位为吨或升）、运输批次、检验日期；非结构化内容为巡检描述、隐患整改说明等。单份结构化台账长度从数百到数千字符，非结构化检测报告最长可达上万字符。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化字段的精准性要求索引环节保留字段关联关系，避免分块破坏CAS号、存储仓位等关键信息的完整性。非结构化文本长度跨度大，需适配不同长度的分块策略，防止过短丢失语义关联或过长超出模型处理上限。高频实时更新的数据要求配置增量索引机制，避免全量索引占用过多资源。存量、批次等数值型字段需与文本向量协同处理，不能仅依赖语义检索匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配危化品巡检报告、台账记录的典型长度，保留完整语义单元 |
| 重叠长度 | 100–200 字符 | 避免分块截断关键字段关联，保障跨块信息连贯性 |
| `maxToken` | 8192 token | 匹配长文档检测报告的处理需求，符合FastGPT v4.17.0的主流配置标准 |
| `defaultToken` | 2048 token | 适配单批次储运台账的常规上下文长度，平衡检索效率与信息完整性 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关台账，精准命中危化品名称、CAS号等关键查询 |
| 单次搜索上限 | 前 10 条 | 兼顾检索召回范围与结果展示效率，适配台账汇总的批量处理需求 |

## 容易做错的三处
- 现象：索引任务长时间处于「索引中」状态无进度。原因：未配置增量索引触发规则，每次启动索引均全量扫描每日更新的海量储运数据，导致资源占用过高。
- 现象：检索结果中CAS号匹配度不符合预期，部分正确结果未被召回。原因：未针对结构化字段单独配置向量映射，仅对全文本进行分块处理，丢失了精准字段的匹配权重。

## 怎么确认配好了
- 查看索引任务的详细日志，确认分块后的文档保留了CAS号、存储仓位等结构化字段，无强制截断情况。
- 输入包含特定危化品CAS号的查询词，核对返回结果的字段匹配度是否符合预设的相似度阈值范围。
- 检查FastGPT v4.17.0的系统配置页面，确认`defaultToken`与`maxToken`的取值与表格建议一致。
- 模拟导入单批次新增的储运台账，确认索引任务可在预设时间内完成，无超时报错。
