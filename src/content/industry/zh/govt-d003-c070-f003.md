# 发电装备制造的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
发电装备制造的台账数据主要来自设备运维管理系统、生产执行系统、备件管理系统。实时运行数据每15分钟更新一次，维护记录随维护完成即时上传，月度汇总台账每月5日前完成更新。单台设备台账包含结构化字段与非结构化备注，字段包括设备编码、生产厂商、投运日期、累计运行时长、单次维护时长、备件更换批次，对应单位分别为台、天、小时、批次。批量汇总的台账文档由多台设备的单台台账合并而成，单份文档长度从数百到数千字符不等，部分包含设备运行异常的手写备注。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散在多个系统，导致多轮对话需逐步引导用户明确筛选条件，避免一次性请求全量数据引发上下文过载。字段包含明确的单位与设备唯一标识，提示词需严格指定字段提取规则，防止大模型混淆不同设备的参数。实时与历史数据的更新节奏差异较大，多轮对话中需先确认用户所需数据的时间范围，否则返回内容的时效性不符。批量文档长度不一，提示词需明确汇总粒度，同时兼顾结构化字段与非结构化备注的提取，确保关键运维信息无遗漏。此外，不同机组类型的台账字段存在细微差异，提示词需预先指定机组类型对应的字段优先级，提升汇总准确性。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 预设设备编码、时间区间、汇总粒度三个变量，设备编码取值区间为指定范围，时间区间可选近7天/近30天，汇总粒度可选单台/按机组类型 | 发电装备台账的筛选维度固定，预设变量可减少用户输入误差，提升筛选准确性 |
| `messages` | 历史对话上下文保留前20轮，单轮消息长度不超过2000字符 | 批量台账文档长度较长，过长的上下文会导致大模型混淆筛选条件，限制单轮长度可优化上下文纯度 |
| 最大上下文 | 8000–12000 token | 单台设备台账文档平均约1500字符，批量汇总10台设备的文档约15000字符，对应token数符合该区间，按实测标定 |
| 单次搜索上限 | 前8条 | 发电装备台账按机组类型分组，每组最多8台同类型设备，过多搜索结果会导致上下文过载 |
| 问题优化 | 开启 | 用户输入的模糊表述如“最近的维护记录”可被优化为明确的“近30天的维护记录”，提升提取精度 |
| 分块长度 | 1000–1500字符 | 单台设备台账的平均长度约1200字符，该分块长度可确保完整提取单台设备的核心信息，避免字段被截断 |

## 容易做错的三处
- 现象：调用模型时出现connection error报错，开启代理后仍无法恢复。原因：未在FastGPT的模型配置中正确配置代理地址或代理端口，导致无法与模型服务建立稳定连接。
- 现象：知识库中上传的设备结构图纸图片无法在对话结果中展示。原因：未在提示词中明确要求大模型引用图片的标注信息，或未配置图片提取的触发规则。
- 现象：无法在对话中发送设备图片进行提问，或无法准确提取台账中的累计运行时长、备件更换批次等关键词变量。原因：未开启FastGPT的图片上传配置，或提示词未明确指定需要提取的字段名称与对应格式，导致大模型混淆不同字段的含义。

## 怎么确认配好了
- 发起包含设备编码、时间区间的测试对话，核对返回的台账数据是否与预设`variables`的筛选条件一致，查看`chatId`对应的上下文是否符合配置要求。
- 查看模型调用日志，确认`messages`参数保留的上下文轮次符合配置要求，无冗余消息。
- 上传单台设备的台账文档，测试问题优化功能是否将模糊表述转换为明确的筛选条件。
- 检查配置中的最大上下文取值，确保单轮对话的token数不超过配置上限，无上下文溢出报错。
- 测试图片上传功能，确认可在对话中发送设备图片并获取基于图片的台账查询结果。
