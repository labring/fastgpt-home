# 发电集团的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
发电集团的台账数据主要来源于生产运行系统、设备维护工单、燃料消耗报表、环保监测台账。数据更新节奏为每班更新单台设备的实时运行记录，每日更新班组级汇总数据，每月生成月度运营报告。单条文档包含设备唯一标识、时间戳、运行参数值、维护操作记录、异常代码等字段，涉及兆瓦、吨、摄氏度、运行小时数等单位，文档长度差异显著，单条运行记录约数百字符，月度汇总报告可达数万字符。

## 这些特征在「向量模型与索引」这一环带来什么约束
高频更新的台账数据要求索引支持增量更新，避免全量重建带来的耗时与资源消耗。多字段带单位的结构化数据，要求向量模型能同时编码文本内容与元数据语义，检索环节需支持按设备ID、时间戳等元数据进行过滤。文档长度差异大的特点，要求分块策略能适配短记录与长报告的不同长度需求。合规性要求下，需保证检索结果的精准性，避免混入非目标设备的台账数据影响汇总质量。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配发电台账单条记录的平均长度，避免单块包含过多无关字段 |
| 重叠长度 | 100–150 字符 | 保留跨块的关键参数关联，比如设备运行的连续时段数据 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配度的无关台账，避免汇总时混入非目标设备的数据 |
| 单次搜索上限 | 前 20 条 | 覆盖单批次台账的检索需求，同时控制检索耗时 |
| `defaultToken` | 8192 | 适配月度汇总报告的上下文长度，符合FastGPT v4.17.0的默认上限 |
| `maxToken` | 16384 | 支持大型年度报告的向量检索与上下文拼接 |

## 容易做错的三处
- 检索时返回503 Service Unavailable错误，原因是未启用元数据过滤，检索范围覆盖全量历史台账，超出向量数据库的并发处理上限。
- 向量数据导入时触发token超限报错，原因是未根据发电台账的文档长度调整分块长度，单块内容超出模型支持的token上限。
- 汇总报告的关键异常数据未被召回，原因是相似度阈值设置过高，过滤掉了符合条件的低匹配度异常台账记录。

## 怎么确认配好了
- 导入单台设备的3天运行台账，执行按设备ID和时间范围的检索，检查返回结果的设备标识与检索条件完全匹配。
- 查看向量数据库的连接日志，确认无频繁的超时或断开报错，验证配置的连接参数生效。
- 导入一份月度汇总报告，检查FastGPT v4.17.0的上下文截断提示未触发，验证`defaultToken`与`maxToken`的配置合理。
- 手动统计导入的台账总条数，对比检索返回的总结果数，确认单次搜索上限的配置覆盖了常规检索需求。
