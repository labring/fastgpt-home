# 国有产业基金的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
国有产业基金的台账数据主要来源于国资监管系统、基金出资台账、投后管理系统及项目尽调文档。数据更新节奏包含月度定期更新、重大项目实时更新两类。单条台账文档包含项目名称、出资主体、认缴规模、实缴金额、出资节点、投后评级等结构化字段，以及项目背景、投后情况等非结构化备注内容，单条内容长度跨度较大，无固定格式标准。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源导致字段格式存在差异，需先完成字段对齐才能进行向量表征。更新节奏包含月度定期更新与重大项目实时更新两类，要求索引系统支持增量触发与全量重建的灵活切换，避免重复计算全量数据。结构化字段与非结构化备注的混合内容，要求分块时保留字段与内容的关联，避免检索时上下文断裂。单条内容长度跨度大，需调整分块参数适配不同长度的内容，保障向量表征的准确性。台账需关联项目全量信息，要求索引支持多文档间的关联检索，提升汇总逻辑的完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配国有产业基金台账的平均内容长度，兼顾向量表征精度与检索效率 |
| 重叠长度 | 100–150 字符 | 保留分块间的上下文关联，避免跨块的字段信息断裂 |
| 相似度阈值 | 0.72–0.85 | 按实测标定，适配结构化字段与非结构化备注的混合匹配需求 |
| 单次搜索上限 | 前 10 条 | 控制检索返回量，避免冗余信息干扰台账汇总的逻辑 |
| 最大上下文 | 6000 token | 适配台账汇总时多文档拼接的需求，符合通用大模型的输入长度限制 |
| defaultToken | 1000 | 保障基础检索的上下文完整性，适配单条台账的平均token消耗 |
| maxToken | 4096 | 匹配所选向量模型的最大输入token限制，避免请求溢出 |

## 容易做错的三处
- 现象：切换向量模型后界面显示无进度且无法切回原模型，原因：未在索引管理页面执行增量索引重建，仅修改了全局配置未触发模型重新计算向量。
- 现象：测试豆包embedding配置时报"404 page not found"，原因：未正确配置豆包embedding的API访问域名与接口路径，导致请求无法被目标服务接收。
- 现象：上传新台账数据后检索结果未更新，原因：未设置匹配数据更新频率的增量触发规则，仅依赖全量索引导致新数据未被抓取。

## 怎么确认配好了
- 进入FastGPT v4.17.0的向量模型管理页面，确认当前激活的模型与配置的参数一致。
- 上传一条标准测试台账数据，执行检索测试，查看返回结果的条数不超过设定的单次搜索上限，匹配度符合相似度阈值范围。
- 执行一次增量索引更新，查看索引进度页面显示正常，无报错日志与异常状态。
- 核对检索结果中是否包含台账的核心字段，确认分块长度与上下文设置符合预期的内容拆分逻辑。
