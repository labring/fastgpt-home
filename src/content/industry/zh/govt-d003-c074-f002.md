# 国有资产管理公司的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
国有资产管理公司的台账数据主要来源于国资监管报送系统、内部财务核算系统、资产实物管理卡片系统。数据更新节奏包含日常新增资产登记、月度盘点调整、季度财报报送三类场景。单条台账文档包含资产唯一编号、名称、规格型号、入账日期、使用部门、账面原值、累计折旧、存放地点、年度维护记录等字段，单位涵盖元、平方米、台/套、公里等，部分条目附带纸质扫描的维护单据图片。

## 这些特征在「向量模型与索引」这一环带来什么约束
台账数据的多字段结构与混合格式，要求向量化环节兼顾结构化标识与非结构化文本内容，避免因分块过碎丢失资产编号、账面原值等关键关联信息。日常高频新增的资产数据，要求索引支持增量更新以降低重复计算成本。部分条目附带的纸质维护单据扫描件，要求向量模型支持多模态输入，适配不同格式的台账补充材料。同时，台账汇总与报告生成的下游需求，要求检索结果需按资产编号聚合，避免重复返回同一资产的多份分块数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配台账单条目的平均文本长度，避免单块包含过多无关字段 |
| 分块重叠长度 | 100–200 字符 | 保留跨分块的资产编号、账面原值等关键标识，防止检索时丢失关联信息 |
| 单次召回上限 | 前15条 | 匹配台账汇总时的多条目检索需求，避免召回过多冗余数据 |
| `maxToken` | 8192 | 适配主流向量模型的上下文窗口，支持完整的台账长文本向量化 |
| `defaultToken` | 1024 | 作为基础向量化的默认上下文配额，平衡计算精度与资源消耗 |

## 容易做错的三处
- 向量化任务耗时过长，API返回结果条数不符合预期。原因是未开启批量向量化配置，仅单条提交文本切片，未利用向量化服务的batch批处理能力。
- 检索时无法获取到指定文档块的关联内容，返回结果缺少跨分块的关键字段。原因是未配置分块重叠长度，导致跨块的资产编号、使用部门等标识未被保留。
- 添加阿里multimodal-embedding-v1模型后无法正常向量化台账图片附件。原因是未在向量服务配置中开启多模态支持，或未正确配置模型适配的输入参数。

## 怎么确认配好了
- 查看FastGPT v4.17.0的向量服务日志，确认是否存在批量提交的文本切片请求，检查请求体中是否包含多个文本条目。
- 检索指定资产编号的台账文档，确认返回结果包含跨分块的关键字段信息，且结果按资产编号完成聚合。
- 在向量模型配置页面验证阿里multimodal-embedding-v1模型的API密钥与参数是否正确填写，测试上传单张资产维护图片附件的向量化任务。
- 测试向量化单条长台账文本，确认返回的向量维度与`maxToken`配置的上下文窗口匹配，无明显截断或格式错误。
