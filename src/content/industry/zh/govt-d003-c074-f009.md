# 国有资产管理公司的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
国有资产管理公司的台账数据主要来自国资监管平台推送、自有业务系统录入及财务核算模块。更新节奏为每日同步新增资产、权属变动等增量数据，每月生成全量台账快照。单条台账为结构化条目，包含资产唯一标识、所属一级企业、入账日期、账面原值、存放地点、使用状态、归口管理部门等字段，账面原值单位为人民币万元，使用状态为固定枚举值。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源更新的台账数据会带来批量处理需求，要求模型接入时配置足够的上下文承载能力。结构化字段多且单位固定，要求模型输出需严格匹配字段格式与单位，避免格式偏差。月度全量快照数据体量较大，需限制单次调用的token消耗，防止超时。不同业务模块的台账字段存在细微差异，需在配置中适配多套字段映射规则，确保汇总逻辑与业务定义一致。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配月度全量台账快照的拼接需求，避免上下文溢出 |
| `maxTokens` | 4000 token | 限制单批次报告生成的输出长度，匹配台账汇总的内容体量 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保结构化字段与单位的一致性 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具处理批量台账数据 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属地址 | 适配国有资产管理公司的私有部署或专线接入需求 |
| `AIPROXY_API_TOKEN` | 按权限生成专属令牌 | 保障数据调用的安全性，符合国资监管的权限要求 |

## 容易做错的三处
- 现象为调用非OpenAI的索引模型时返回不支持的报错。原因是未在模型接入配置中正确填写国产模型的专属接入端点与权限令牌，未完成模型类型的适配配置。
- 现象为调用ollama接入的向量模型时被拒绝访问，但curl直接测试接口正常。原因是模型接入配置中未正确传递请求头或身份校验参数，导致FastGPT的请求未通过目标模型的权限验证。
- 现象为批量台账汇总时生成的报告字段格式混乱，未匹配预设的台账结构。原因是`temperature`配置值过高，导致模型输出随机性过大，无法严格遵循结构化输出要求。

## 怎么确认配好了
- 调用模型接入测试接口，输入单条结构化台账数据，检查返回结果是否匹配预设字段与单位。
- 上传月度全量台账快照，验证上下文拼接是否正常，无溢出报错。
- 配置国产模型接入端点后，发起模型调用请求，确认返回结果无格式错误。
- 调整`temperature`参数后，对比多次调用结果的一致性，确认输出随机性符合业务需求。
