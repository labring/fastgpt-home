# 国有资本投资公司的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
国有资本投资公司的台账数据来源于集团本级及下属各级子企业的投资项目管理、财务核算、股权监管等内部业务系统。数据按单个投资项目或经营主体聚合，单条台账文档包含项目编码、所属集团、投资金额、资金流向记录、监管层级编码等字段，投资金额以万元为单位。数据更新节奏为每日接收业务系统推送的增量更新，每月底触发全量归档，归档数据需符合国资监管部门的统一台账规范要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | `Bearer {企业专属令牌}` | 台账数据属于敏感国资数据，需使用令牌鉴权避免未授权访问 |
| `variables` | `{"start_time": "2024-01-01T00:00:00Z", "entity_id": "group_001"}` | 按时间范围与企业主体ID拉取对应台账数据，符合多源数据过滤需求 |
| `responseData` | 分页返回，每页1000条 | 月度全量归档时数据体积较大，分页可避免接口超时 |
| 接口超时时间 | 600 秒 | 台账数据拉取涉及多子企业，单次请求耗时较长，避免提前超时 |
| 响应字段校验 | 按台账规范映射核心字段 | 确保接收的数据包含项目编码、投资金额等必填内容 |
| IP白名单配置 | 仅允许集团内部业务系统IP段 | 防止外部非法调用敏感台账数据 |

## 容易做错的三处
- 现象：不同外部系统调用接口后返回的台账数据混淆，不同请求返回的内容包含其他子企业的信息。原因：未在`variables`参数中指定企业主体ID，接口未做数据隔离，导致返回跨主体数据。
- 现象：调用接口后出现504 Gateway Timeout状态码。原因：未配置分页拉取规则，单次请求拉取超过10000条的台账数据，超出接口承载上限。
- 现象：`responseData`字段返回为空数组或无内容。原因：未配置响应数据的过滤规则，接口返回的原始数据包含大量无关字段，未按台账汇总要求提取有效内容。

## 怎么确认配好了
- 发起携带指定企业主体ID的测试请求，检查返回的台账数据仅包含对应主体的项目与资金信息。
- 发起单次1000条的分页请求，确认接口在600秒内正常返回数据，无超时报错。
- 检查`Authorization`参数携带的令牌可正常通过鉴权，接口返回200 OK状态码。
- 查看响应数据的字段，确认包含项目编码、投资金额等台账所需的核心字段。
