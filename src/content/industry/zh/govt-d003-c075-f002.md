# 国有资本投资公司的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
国有资本投资公司的台账数据主要来源于内部财务核算系统、项目投资管理平台、产权登记数据库，更新节奏随业务节点调整，月度结算、季度复盘时批量更新，日常新增台账即时同步。单份台账文档多为结构化表格形式，包含项目编号、投资金额（单位万元）、出资主体、资金到位时间、审批文号、风险等级等固定字段，汇总类报告则由多份台账数据整合生成，篇幅较长且常嵌套明细表格。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化字段占比高且包含固定单位的数值类字段，要求索引配置需支持字段级语义区分，避免数值单位差异导致的向量匹配偏差。长篇幅的汇总报告需要适配长文本分块策略，防止语义断裂。多批次的批量更新数据，要求索引支持增量同步，减少全量重建的耗时。固定的字段结构，可通过预设字段映射优化向量模型的输入格式，提升检索召回的准确性。同时，单份数据的结构化特征，也要求索引在构建时兼顾结构化元数据与非结构化文本的混合索引，适配台账汇总与报告生成的多场景需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配国有资本投资公司的台账数据特征：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配国有资本投资公司台账及汇总报告的文本密度，避免单块内容语义断裂 |
| 重叠长度 | 100–150 字符 | 衔接相邻分块的语义，防止关键信息被截断 |
| `defaultToken` | 2000 token | 覆盖单份台账的核心字段信息，平衡向量计算精度与耗时 |
| `maxToken` | 4000–6000 token | 适配长篇幅汇总报告的分块上限，保留完整的分析逻辑 |
| 相似度阈值 | 0.72–0.80 | 匹配国有资本投资台账的字段语义一致性，过滤低相关的检索结果 |
| 单次搜索上限 | 前8条 | 兼顾汇总报告的多维度信息召回，避免冗余数据过多 |

## 容易做错的三处
- 现象：导入台账数据后，数据集状态长期停留在创建索引中，耗时超过4小时。原因：未针对长篇幅汇总报告调整分块长度，导致单分块token数超出模型上限，触发多次重试或超时。
- 现象：向量计算得分异常偏高且多份数据得分一致。原因：未区分结构化字段与非结构化文本的向量映射，固定单位的数值字段未做语义归一化，导致模型无法识别字段差异。
- 现象：上传PDF格式的台账附件后，向量化过程卡顿。原因：未开启PDF文本结构化解析配置，导致大量嵌套表格被识别为无结构文本，增加向量计算的负载。

## 怎么确认配好了
- 查看数据集的索引构建日志，确认分块长度与`maxToken`的匹配度，无token溢出报错。
- 随机抽取3份台账数据执行检索，核对召回结果的相似度分布，符合预设的阈值区间。
- 执行一次增量更新测试，确认索引仅同步新增数据，未触发全量重建。
- 检查结构化字段的向量映射配置，确认已关联对应字段的语义标签。
