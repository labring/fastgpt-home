# 国有资本运营公司的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
国有资本运营公司的台账数据主要来自国资监管报送系统、内部财务核算平台、产权交易登记系统、投资项目档案库。更新节奏为日常逐笔录入单笔业务台账，月度汇总全口径运营数据，季度更新年度报告底稿。文档结构包含标准化业务字段：项目编号、投资主体名称、交易对价、持股比例、审批文号、权属状态、更新日期，配套专业单位：万元、百分比、平方米等，部分台账附带扫描件或PDF格式的审批附件。

## 这些特征在「向量模型与索引」这一环带来什么约束
国资台账的多字段结构化属性要求向量嵌入时需保留字段关联关系，避免分块切分破坏业务逻辑；日常逐笔更新与批量汇总并存的节奏，要求索引支持增量更新与全量重跑两种模式；单条台账长度差异较大，从几十字符的基础条目到数千字符的完整报告，要求分块参数具备灵活适配能力；专业术语如“国有股权划转”“资本金注入”等，要求向量模型具备国资领域的语义理解能力，避免通用模型的语义偏差。同时数据规模随新增项目持续增长，要求索引架构具备横向扩展能力，适配不同量级的台账数据处理。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配单条台账加关联字段的平均长度，避免切分破坏项目编号、交易主体等核心关联信息 |
| 重叠长度 | 100–150 字符 | 保留跨块的字段关联内容，确保检索时能完整匹配跨分块的业务逻辑 |
| `maxToken` | 8192 token | 适配主流开源向量模型的输入上限，同时覆盖多数汇总报告的长度需求 |
| 相似度阈值 | 0.72–0.80 | 匹配国资台账的专业术语匹配精度，过滤低相关的检索结果 |
| 单次索引上限 | 5000 条/批 | 适配docker部署的资源限制，避免单次索引任务超时或内存溢出 |
| `defaultToken` | 1500 token | 匹配单条基础台账的平均嵌入token数，保证核心业务字段的完整嵌入 |

## 容易做错的三处
- 出现503状态码，界面或日志提示当前分组下的embedding模型不可用，原因是未配置专属的embedding模型分组，或分组的调用配额耗尽
- 索引任务持续处于运行状态无进度，原因是分块长度设置超出向量模型的输入限制，或docker部署的内存配额不足导致进程阻塞
- 向量数据库连接失败，无法完成索引初始化，原因是未开启数据库的向量扩展功能，或访问地址、认证信息配置错误

## 怎么确认配好了
- 查看FastGPT v4.17.0的向量嵌入任务日志，确认单条台账的嵌入token数未超过`maxToken`设置值
- 执行单次500条以内的小批量索引测试，确认任务完成后可检索到对应台账条目，检索结果的相似度符合预设阈值区间
- 检查向量数据库的索引分片配置，确认与单次索引上限匹配，无数据堆积情况
- 测试embedding模型的调用流程，确认无503报错，模型调用返回正常的向量数据
