# 城市公交的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
城市公交的台账数据主要来自车载智能终端、调度指挥系统、票务结算系统与客流采集设备。数据更新节奏分两类：实时运营点位数据为秒级更新，单日运营台账、客流统计、能耗记录为日结更新。单条台账文档包含线路编号、车辆唯一标识、当日运营时长、载客总人次、站点停靠次数、百公里能耗等字段，单位分别为分钟、人次、次、千瓦时/百公里。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据接入带来的约束：需同时配置离线数据库查询节点与实时流数据接入节点，适配不同更新节奏的数据源。字段类型与单位不统一的特征，要求工作流中加入标准化字段映射节点，统一载客量、能耗等字段的单位与数据格式。通过`variables`预设的线路编号变量，可以精准筛选目标线路的台账数据。日结台账数据的批量特性，要求工作流支持单次处理800–1200条的批量数据，避免单次请求超时。实时点位数据的秒级更新要求，需将工作流的触发间隔设置为不大于60秒，保障数据时效性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，使用`variables`预设自定义参数，通过`nodeId`标记节点便于排查问题。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 数据源节点 | 配置为多数据源聚合节点 | 适配车载终端、调度系统等多源数据接入需求 |
| 触发方式 | 同时配置日触发与分钟级定时触发 | 匹配实时点位数据与日结台账的不同更新节奏 |
| 字段映射规则 | 统一载客量、能耗的单位与数据格式 | 适配台账字段类型杂、单位不统一的特征 |
| 单次处理数据量 | 800–1200条 | 适配日结台账的批量处理规模，避免请求超时 |
| 超时阈值 | 600秒 | 适配多数据源联合查询的耗时需求 |
| nodeId | 为每个工作流节点分配唯一标识 | 便于定位运行异常的具体节点 |
| variables | 预设线路编号、日期范围变量 | 支持按需筛选特定线路与时间段的台账数据 |

## 容易做错的三处
- 工作流本地测试正常，但通过渠道链接调用时返回“undefined”is not valid json。原因是未对多数据源返回的嵌套字段做标准化处理，导致输出格式不符合渠道要求的JSON结构，同时未通过`variables`校验输出字段的合法性。
- 工作流无法获取指定公交台账数据。原因是未正确配置指定数据库的连接参数，或未在工作流中添加数据库查询节点。
- 误将插件当作工作流使用，无法完成多步骤台账汇总流程。原因是未明确工作流用于串联多步骤操作，插件仅为单一功能调用单元。

## 怎么确认配好了
- 手动触发工作流，检查输出的台账数据是否包含预设的线路编号、车辆ID等核心字段。
- 配置定时触发任务，核对触发时间是否与对应数据源的更新节奏匹配。
- 调用渠道链接，检查返回内容的JSON格式是否符合预期，无未定义字段报错。
- 查看工作流运行日志，确认单次处理的数据量未超出预设的合理范围。
