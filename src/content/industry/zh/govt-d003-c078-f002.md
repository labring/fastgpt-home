# 城市水务的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
城市水务的台账与报告数据来源包括管网监测节点的实时压力、流量数据，水厂中控系统的每日运行报表，排水泵站的巡检日志，以及用户报修工单与纸质台账扫描件。数据更新节奏差异明显：实时监测数据每秒生成新记录，工单与巡检报表按日汇总，月度台账则每月更新。文档结构混合结构化字段与非结构化附件，结构化字段包含管网ID、监测点位名称、压力值（单位MPa）、流量（单位m³/h）、报修时间、处理结果等，非结构化附件包括巡检照片、手写台账扫描件与Excel汇总表。

## 这些特征在「向量模型与索引」这一环带来什么约束
混合数据类型要求索引同时支持文本、数值与图片的向量编码，否则无法完整关联监测数据与附件信息。不同更新节奏的数据需要适配不同的索引策略：实时数据需启用增量索引以避免全量更新的延迟，批量报表则可按日触发全量索引。需通过`defaultToken`调整上下文窗口，适配混合数据的编码需求。结构化字段中的单位信息会影响向量语义，未做前置清洗的单位会导致相似查询的匹配偏差。长文本的巡检报告与短文本的工单记录，需要适配差异化的分块规则以保留完整语义。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `defaultToken` | 4096 | 匹配多数开源嵌入模型的默认上下文窗口，适配单条水务数据的语义编码 |
| `maxToken` | 8192 | 容纳月度台账汇总时的多段关联数据，满足长文档的生成需求 |
| 分块长度 | 800–1200 字符 | 适配巡检报告的段落长度与工单记录的字段总量 |
| 重叠长度 | 100–150 字符 | 避免跨块的监测数据逻辑断裂，保留相邻记录的关联关系 |
| 相似度阈值 | 0.72–0.78 | 区分水务压力异常波动与正常运行数据的语义相似度区间 |
| 单次搜索上限 | 前10条 | 覆盖单份台账关联的监测节点数量，满足汇总报告的信息需求 |

## 容易做错的三处
- 现象：本地部署FastGPT v4.17.0后，新建知识库时无图片索引模型选项。原因：未启用商业版的图片嵌入插件，默认仅加载文本嵌入模型。
- 现象：台账汇总报告的关联数据匹配偏差过大。原因：未针对水务数据的单位字段做前置清洗，向量编码时丢失单位信息导致语义混淆。
- 现象：实时监测数据的索引更新延迟过高。原因：未配置增量索引触发规则，仍使用全量索引更新流程。

## 怎么确认配好了
- 上传单份包含巡检照片的台账文档，查看索引任务日志，确认存在图片嵌入任务记录。
- 输入包含“压力0.2MPa”的查询词，查看召回结果的匹配字段是否包含对应单位的监测数据。
- 测试实时推送单条管网监测数据，查看索引队列的更新进度是否在预设时间内完成。
- 查看知识库配置面板，确认已启用的嵌入模型包含文本与图片类型。
