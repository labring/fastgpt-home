# 城市水务的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
城市水务的台账数据来源包含市政管网监测节点的PLC采集数据、水厂中控系统日志、排水泵站巡检记录、用户缴费记录四类。数据更新节奏存在差异：管网压力、瞬时流量等实时监测数据为分钟级更新，巡检记录与月度汇总台账为日级更新，缴费数据为实时更新。单条台账文档包含设备ID、监测时间、瞬时流量（单位m³/h）、管网压力（单位kPa）、巡检人员、检修状态、月度累计供水量等字段，部分跨节点汇总台账需关联多设备的历史数据。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源异构的数据来源要求工具调用需支持并行调用多个专用插件，分别拉取不同类型的台账数据。更新节奏的差异则要求为不同数据源配置差异化的触发周期，避免高频拉取实时数据导致接口过载，或低频触发错过日级更新的台账文件。字段自带明确单位的特性，要求插件需自动校验字段格式与单位，防止汇总时出现单位不统一的错误。跨节点的汇总需求则要求工具调用支持按设备ID、监测时间为关联键的批量数据拼接逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动适配多源数据的拉取与拼接逻辑，无需手动指定单个工具函数 |
| `functionCall` | 按数据源分组调用 | 区分实时监测数据、巡检数据两类调用组，适配不同的更新节奏 |
| 触发周期 | 10–60 秒（实时数据）、1 天（巡检与汇总数据） | 匹配城市水务不同类型数据的更新频率，平衡接口负载与数据时效性 |
| 单次拉取数据量 | 10000 条 | 避免单次调用数据量过大导致接口超时或响应延迟 |
| 字段映射规则 | 以设备ID、监测时间为关联键 | 保障跨源台账数据的准确拼接与汇总 |
| 结果校验阈值 | 按实测标定 | 适配不同水务节点的数据波动范围，过滤异常监测值 |

## 容易做错的三处
- 现象：无法找到文件加工插件，无法导入巡检台账的Excel文件。原因：未在FastGPT v4.17.0版本中启用公用事业类插件仓库。
- 现象：Java调用API时持续处于等待响应体的状态，无返回结果。原因：未适配城市水务多源数据的批量拉取逻辑，默认超时阈值不足以覆盖跨节点数据汇总的耗时。
- 现象：使用JS代码运行插件提取台账JSON中的元素时无法获取目标值。原因：未配置水务台账JSON的字段路径前缀，导致插件无法定位到对应数据节点。

## 怎么确认配好了
- 触发工具调用，查看系统日志中是否存在对应水务数据源的拉取记录，确认触发周期匹配数据更新节奏。
- 调用`toolChoice`为`auto`的测试函数，检查返回结果是否自动拼接了多源台账的核心字段，如瞬时流量、管网压力等。
- 导入一份模拟的水务巡检台账Excel文件，确认插件可正常识别设备ID、监测时间等预设字段。
- 完成工具调用后，查看对话界面是否即时显示汇总结果，无延迟或缓存遗漏问题。
