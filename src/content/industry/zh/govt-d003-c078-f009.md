# 城市水务的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
城市水务的台账数据主要来自管网SCADA监测系统、智能水表计量终端、污水处理厂在线监测设备以及人工巡检上报。监测类数据更新频率为每15分钟至1小时，巡检与报表类台账为每日或每周更新。数据以结构化表格形式存储，包含站点ID、监测时间、瞬时流量、COD浓度、氨氮浓度、巡检人员、异常标记等字段，流量单位为立方米每小时，水质指标单位为毫克每升。

## 这些特征在「模型接入与配置」这一环带来什么约束
水务台账的结构化特征要求模型接入时需适配固定字段与单位的识别，避免生成不符合水务行业规范的内容。高频更新的监测数据会带来较大的上下文长度需求，需限制模型的上下文与输出token规模，防止请求超时。多来源的数据格式差异，需在配置中统一数据对齐规则，确保模型可正确读取不同终端的台账内容。语音输入的水务数据需匹配专属字段，若配置不当会导致转写内容无法关联到系统台账。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 水务台账单批次汇总需保留多站点的历史监测数据，避免关键信息被截断 |
| `maxTokens` | 4000–6000 token | 单份水务报告需包含多维度汇总数据与分析结论，匹配常规输出长度 |
| `quoteMaxToken` | 2000–3000 token | 需保留足够的原始台账片段用于报告佐证，确保引用内容完整 |
| `toolChoice` | auto | 支持模型自动判断是否调用台账知识库，适配不同的汇总请求场景 |
| `temperature` | 0.2–0.4 | 水务报告需严谨准确，降低生成内容的发散性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境配置专属代理地址 | 适配国内网络环境，确保模型调用的稳定性 |

## 容易做错的三处
- 模型生成水务报告时未默认调用台账知识库输出内容，仅输出泛泛的通用结论。原因是`toolChoice`配置为none，关闭了自动工具调用开关。
- 语音输入转写的水务数据无法匹配系统表模型，报错提示“字段未定义”。原因是未针对水务专属的站点ID、流量单位等字段配置模型的字段识别规则。
- 调用模型时出现请求超时，状态码504。原因是`maxContext`配置超出当前部署模型的最大上下文限制。

## 怎么确认配好了
- 提交一份包含多站点水务台账的汇总请求，检查生成的报告是否包含原始台账的引用片段。
- 测试语音输入水务监测数据，确认转写内容可正确匹配系统内的水务台账字段。
- 查看FastGPT v4.17.0的模型调用日志，确认`AIPROXY_API_TOKEN`的验证状态为成功。
- 调整`temperature`参数至0.3后，检查生成报告的严谨性，无过度发散的主观表述。
