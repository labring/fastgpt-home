# 城市燃气的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
城市燃气的台账数据主要来源于SCADA监控系统、一线巡检移动终端、企业内部台账管理系统。巡检记录每日更新，月度片区汇总台账每自然月生成，年度专项报告按季度分批提交。单条结构化台账记录包含巡检点位编号、设备编码、燃气压力值、巡检时间、巡检人员编号等字段，压力值单位为千帕（kPa），时间格式为YYYY-MM-DD HH:mm:ss。部分巡检记录附带现场设备照片，为非结构化多模态数据，与结构化文本一一绑定。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化字段多且带明确单位，要求向量模型编码时需保留字段元数据，避免不同点位的相似文本混淆。多模态数据与结构化文本并存，要求索引系统支持混合向量存储与召回。数据更新节奏差异大，实时巡检数据需增量索引，月度汇总台账需全量重建索引，索引分片需按片区划分以避免单索引负载过高。长文本台账记录较多，需适配模型的最大输入长度限制，防止分块时丢失关键关联信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 单条燃气台账含多关联字段，过长分块会割裂点位与设备的对应关系，过短则丢失上下文信息 |
| 重叠长度 | 100–200 字符 | 保留相邻巡检记录的点位与设备关联信息，避免跨块丢失关键数据 |
| 相似度阈值 | 0.75–0.85 | 燃气台账对数据精准度要求较高，阈值过低会引入无关记录，过高则无法召回有效数据 |
| 重排 | 开启 | 巡检记录的语义相似度易受点位名称干扰，重排可修正初始召回的排序偏差 |
| `maxToken` | 4000 token | 适配燃气台账汇总报告的长文本生成需求，避免上下文被截断 |
| `defaultToken` | 按实测标定 | 适配不同片区台账的平均文本长度，防止模型调用超时 |

本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：调用多模态向量模型时返回格式错误，提示不支持当前输入类型。原因：未单独配置多模态嵌入模型，混用了文本嵌入模型的调用链路，导致模型无法识别图片输入。
- 现象：索引召回的结果条数远低于预期，部分巡检记录未被索引。原因：分块长度设置超过模型的最大输入限制，导致长台账记录被自动截断丢弃。
- 现象：生成的汇总报告中出现字段混淆，将A点位的压力值归到B点位。原因：未保留字段元数据进行向量编码，导致不同点位的相似文本被错误关联。

## 怎么确认配好了
- 上传单条完整的燃气巡检台账记录，检查索引生成状态是否显示成功，无截断或格式报错。
- 输入具体的巡检点位查询词，核对召回结果中是否包含该点位的所有相关记录，且排序符合预期。
- 尝试上传一张燃气设备现场照片，确认索引库中生成了对应的多模态向量数据，无格式错误提示。
- 查看知识库配置面板，确认`maxToken`与`defaultToken`的设置与当前使用的嵌入模型支持参数匹配。
