# 城市燃气的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
城市燃气台账数据来源于场站SCADA系统、现场巡检终端上传日志、用户服务工单系统。更新节奏分为三类：管网运行压力数据每15分钟同步，日常巡检台账每日归集，月度汇总报表每月5日前生成。单条台账文档为结构化表格，包含管网点位编码、检测时间、介质压力、泄漏告警等级、巡检人员ID、用户地址字段，单位分别为16位字符、YYYY-MM-DD HH:MM、千帕、1-5级、工号、详细地址。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
城市燃气台账的多源异构更新节奏与结构化字段特征，对多轮对话配置带来三点约束。其一，不同数据源的更新频率差异，需要在对话上下文中标注数据的时间属性，避免将实时巡检数据与月度汇总报表混淆。其二，字段包含特定单位与编码规则，提示词需明确要求输出匹配字段单位，例如压力值需标注千帕，点位编码需遵循16位字符格式。其三，台账关联管网节点与用户信息，多轮对话需保留历史询问的点位ID或用户编号，确保后续查询的上下文一致性，避免出现跨对象的无效结果。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定对应燃气场站的专属会话ID | 确保多轮对话的上下文仅关联当前业务场景，避免跨项目数据混淆 |
| `messages` | 保留最近20条历史对话内容 | 覆盖单次巡检周期内的完整询问链条，同时控制上下文总长度 |
| `variables` | 预设管网点位编码、统计周期两个全局变量 | 快速调用对应业务数据，减少重复输入步骤 |
| 最大上下文长度 | 12000 token | 匹配城市燃气台账单批次查询的数据总量，避免截断关键字段信息 |
| 上下文清理阈值 | 8000–10000 token | 按实测标定，避免上下文溢出 |
| 响应超时设置 | 600秒 | 按实测标定，避免长查询被强制中断 |
| 问题优化 | 开启自动精简用户提问 | 过滤冗余表述，聚焦台账字段与时间范围，提升响应精度 |

## 容易做错的三处
- 现象：多轮对话中后续提问无法关联之前询问的管网点位，返回结果匹配错误的用户地址。原因：未绑定专属`chatId`，导致会话上下文被重置或跨场景串扰。
- 现象：对话日志中显示大模型的思考过程，但前端页面未隐藏该内容。原因：未配置`messages`参数过滤思考过程字段，或代理设置未正确屏蔽输出中间步骤。
- 现象：输入台账查询请求后返回空结果。原因：未通过`variables`预设业务参数，导致大模型无法匹配正确的管网点位编码或统计周期字段。

## 怎么确认配好了
- 发起包含历史提问的多轮对话，确认后续回复自动关联之前提及的管网点位，核对结果匹配对应业务数据。
- 查看对话记录，确认仅展示用户提问与大模型最终回复，无中间思考过程内容。
- 输入未预设的业务参数查询，确认系统提示需补充必要的点位或周期信息，验证`variables`的预设逻辑生效。
- 调整对话长度，确认当历史对话超过设定保留条数时，旧内容自动被清理，不会触发上下文溢出报错。
