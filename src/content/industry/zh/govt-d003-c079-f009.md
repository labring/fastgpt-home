# 城市燃气的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
城市燃气的台账数据来源包括场站SCADA运行系统、管线巡检APP、用户安检档案、调压设备监测终端。实时运行数据每5分钟刷新归档，巡检记录每日完成提交，月度汇总台账于自然月结束后3个工作日内生成。单条台账文档包含场站编号、巡检时间、设备压力值、泄漏检测结果、巡检人员ID等字段，压力值单位为千帕，泄漏检测结果单位为ppm，场站编号为6位数字编码。

## 这些特征在「模型接入与配置」这一环带来什么约束
城市燃气台账的多源数据更新节奏差异，要求模型接入需支持分批次同步不同类型的数据，避免单次请求过载。带固定单位的数值型字段与标准化编码字段，要求模型调用时需明确指定解析格式，防止输出结果与实际数据格式不匹配。月度台账的单批次数据量较大，需适配大模型的上下文窗口限制，避免数据截断。实时运行数据的高频更新，要求模型调用的响应延迟需控制在合理范围内，保障汇总报告的时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 城市燃气月度台账单批次数据量较大，需容纳完整的场站、巡检、安检等多类数据，避免上下文截断 |
| `maxTokens` | `2000–3000 token` | 台账报告生成的输出长度需覆盖汇总数据与分析结论，同时控制单次调用的资源消耗 |
| `temperature` | `0.1–0.3` | 台账汇总需保持数据准确性，避免生成偏离实际数据的分析内容 |
| `AIPROXY_API_ENDPOINT` | `http://[xinference部署地址]/v1` | 对接Xinference部署的本地大模型，需匹配其API接口路径格式 |
| `AIPROXY_API_TOKEN` | `用户自行生成的访问密钥` | 保障模型调用的身份验证安全，避免未授权访问 |
| `quoteMaxToken` | `500 token` | 提取台账中的关键巡检记录作为引用依据，控制引用内容的长度 |

## 容易做错的三处
- 界面提示“没有可用模型”，原因是未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，导致代理服务无法连通Xinference部署的模型实例。
- 重排序模型测试返回空结果或500状态码，原因是未匹配Xinference部署的重排序模型的正确名称，或未在配置中指定重排序模型的专属接入路径。
- 单次台账汇总触发上下文超限报错，原因是未调整`maxContext`参数，导致月度台账的完整数据无法被模型加载。

## 怎么确认配好了
针对FastGPT v4.17.0版本，执行以下核对动作：
- 调用FastGPT内置的模型连通性测试工具，检查是否能返回Xinference部署模型的基础信息，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确。
- 上传单条城市燃气巡检台账数据，触发模型调用，检查输出结果是否包含正确的场站编号、压力值单位等字段信息，确认参数适配数据格式。
- 导入月度批量台账数据，触发汇总任务，检查是否出现上下文截断或输出不完整的情况，确认`maxContext`与`maxTokens`参数设置合理。
- 触发重排序模型测试，检查是否能返回指定条数的排序结果，确认重排序模型的接入配置与Xinference部署的模型匹配。
