# 城市燃气的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
城市燃气的台账数据来源包括管网压力监测终端、场站巡检表单、用户缴费记录、报修工单系统。数据更新节奏分实时（管网压力监测）、每日（场站巡检与用户缴费）、工单触发式（报修工单）。单条台账文档包含场站编号、监测时间、压力值、巡检人员ID、工单编号等字段，压力值单位为kPa，巡检时长单位为分钟，汇总类文档则按区域、月度维度整合多维度的台账数据。

## 这些特征在「部署与升级」这一环带来什么约束
城市燃气台账的多源异构数据特征，要求部署时支持多数据库类型对接，避免单一数据源限制数据接入。实时压力监测的高频更新，要求数据库连接池配置适配高并发写入，防止连接耗尽。按区域月度汇总的需求，要求升级时保留历史数据的增量同步能力，避免全量重算导致服务中断。字段单位的差异化（如kPa、分钟），要求部署时配置统一的单位转换规则，避免汇总数据出现单位混乱。

## 配置怎么定
本配置项说明适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 100–150 个 | 适配燃气台账多源数据的高频写入与查询，避免连接池耗尽 |
| `MONGODB_URI` | 指向燃气台账历史归档库的连接串 | 存储非结构化的工单与巡检文档，支持灵活的维度查询 |
| `PG_URL` | 指向结构化监测数据的关系型数据库连接串 | 存储带明确字段的压力、缴费等结构化台账数据，保障事务一致性 |
| `REDIS_URL` | 本地Redis实例或托管Redis服务地址 | 缓存高频查询的区域汇总数据，降低数据库负载 |
| `STORAGE_S3_ENDPOINT` | 企业对象存储服务的接入端点 | 存储台账生成的PDF报告与原始文档备份，满足合规存储要求 |
| `FE_DOMAIN` | 企业公网域名或内部访问地址 | 配置台账生成界面的访问入口，保障内部与外部用户的正常访问 |

## 容易做错的三处
- 现象：使用Docker部署时配置`PG_URL`未添加数据库名称后缀，部署后无法读取结构化监测数据，台账汇总结果为空。原因：未校验连接串的完整格式，仅填写了主机与端口信息。
- 现象：配置`STORAGE_S3_ENDPOINT`时误修改端口号，系统仍显示连接正常但无法生成可下载的报告文件。原因：部分存储服务允许无效端口的空连接，未触发即时报错，但实际无法完成数据写入。
- 现象：在配置多源台账数据的向量映射时，仅选择单向量模型，导致不同字段的台账数据无法正确生成匹配的向量表示，检索结果条数异常。原因：未在部署阶段配置多向量模型的映射规则，受限于界面默认仅支持单模型选择的限制。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`DB_MAX_LINK`配置的连接池是否能同时承载多源数据的并发请求，连接数不超过配置上限。
- 上传一条测试台账数据，触发汇总任务，检查`STORAGE_S3_ENDPOINT`是否能正常存储生成的报告文件，无上传失败日志。
- 访问`FE_DOMAIN`配置的地址，验证界面能正常加载台账配置与生成功能，无资源加载报错。
- 查看`REDIS_URL`的监控指标，确认高频汇总数据的缓存命中率符合预设要求。
