# 城投平台的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
城投平台的台账数据主要来自内部财务系统、项目管理平台、地方政府融资监管系统三类数据源。更新节奏分为月度全量更新与周度增量更新，全量更新覆盖全量台账条目，增量更新仅同步新增或变更的项目、债务数据。单条台账为结构化文档条目，包含唯一标识、项目名称、所属行政区、总投资额、已拨付资金、累计完成投资额、计划竣工日期、责任部门、对应债务余额等字段，单位统一为万元、自然日。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据接入要求数据库支持异构数据源同步，避免数据冗余与重复录入。月度全量与周度增量的混合更新模式，要求运维环节区分全量与增量同步的触发规则，防止全量同步占用过多服务器资源。多类业务字段的关联需求，要求数据库设计多表关联结构，避免单表字段过多导致查询效率下降。数据涉及财务与债务敏感信息，要求数据库配置严格的角色级访问权限，防止敏感数据泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://城投台账业务用户:自定义密码@数据库主机地址:5432/城投台账库?sslmode=disable` | 城投台账数据多为结构化关联数据，PostgreSQL适配多表查询与事务处理 |
| `DB_MAX_LINK` | `20–30` | 适配8核64G的服务器硬件配置，避免数据库连接耗尽影响业务 |
| `REDIS_URL` | `redis://:Redis访问密码@Redis主机地址:6379/0` | 缓存增量同步的标记数据与报告生成的中间结果，降低数据库重复查询压力 |
| `MONGODB_URI` | `mongodb://MongoDB业务用户:自定义密码@MongoDB主机地址:27017/城投报告附件库?authSource=admin` | 存储非结构化的报告模板、附件等非关系型数据 |

## 容易做错的三处
- 现象：跨版本升级FastGPT v4.17.0从v4.6.7到v4.8.10后，台账数据无法加载，报错提示“目标表不存在”。原因：未完整迁移原数据库的表结构与字段映射关系，跨度过大的版本升级未兼容旧版数据格式。
- 现象：执行台账搜索时返回结果条数异常，仅返回少量条目或无匹配结果。原因：未为数据库的核心字段创建索引，或使用shaw/dmeta-embedding-zh向量模型时未匹配向量存储的维度参数，导致召回逻辑失效。
- 现象：定时生成的台账报告中部分财务字段为空。原因：增量同步任务未正确配置更新触发条件，导致部分变更的台账数据未同步到数据库中。

## 怎么确认配好了
- 使用FastGPT v4.17.0内置的数据库连接测试工具，验证`PG_URL`、`MONGODB_URI`、`REDIS_URL`的配置可以正常建立连接，无认证或地址错误。
- 手动触发一次增量同步任务，查看数据库中是否新增了对应时间段内的台账条目，且字段完整无缺失。
- 触发一次台账报告生成任务，检查生成的报告包含所有配置的台账字段，无异常空值。
- 调用搜索接口，验证当输入包含台账相关关键词时返回对应知识库内容，无相关内容时返回预设的指定回复。
