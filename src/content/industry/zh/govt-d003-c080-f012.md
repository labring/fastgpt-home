# 城投平台的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
数据主要来自城投平台的项目管理系统、债务监测平台、财务核算系统，更新节奏为每日同步项目进度增量、每周更新财务核算数据、每月生成完整台账快照。文档以结构化表格为主，包含项目编号、项目类型、投资总额、到位资金、还款计划节点、所属行政区等字段，单位涵盖万元、亿元、自然日等，单份台账文档长度通常在数千到数万字符区间。

## 这些特征在「部署与升级」这一环带来什么约束
城投平台台账数据多源且更新节奏差异大，每日增量同步与全量快照更新并存，要求部署环节支持多数据源并行接入。单份文档长度较长，对存储的读写带宽有要求，升级时需提前评估存储节点的IO负载。结构化字段包含多单位数值类型，部署时需配置统一的字段解析规则，避免单位转换错误。多区域项目台账的跨节点存储需求，要求升级时同步调整集群分片策略。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本的部署规范：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | `15–25 个连接` | 城投台账数据多源接入，需同时维护财务、项目、债务三个数据库连接池，避免连接耗尽 |
| `MONGODB_URI` | `mongodb://城投台账管理员:已加密的访问密码@内网存储节点:27017/城投台账库?authSource=admin` | 存储非结构化的台账快照与历史版本，适配多来源的半结构化数据格式 |
| `REDIS_URL` | `redis://:缓存服务密码@内网缓存节点:6379/0` | 缓存每日增量同步的台账增量数据，降低数据库重复查询压力 |
| `STORAGE_S3_ENDPOINT` | `https://内网对象存储节点地址` | 存储单份数万字符的长文档，避免本地磁盘空间不足 |
| `PG_URL` | `postgresql://业务库管理员:已加密的访问密码@内网业务节点:5432/城投业务库?sslmode=disable` | 存储结构化台账的字段映射规则与统计指标配置 |
| `FE_DOMAIN` | `https://城投平台台账服务域名` | 配置前端回调地址，确保报告生成后的推送链路正常 |

## 容易做错的三处
- 现象：部署后尝试连接城投业务数据库时，返回`Access denied for user 'xxx'@'xxx'`报错，日志显示数据库进程正常启动但连接被拒绝。原因：未配置数据库连接的内网访问白名单，城投平台的数据库通常部署在内网独立节点，未开放对应端口的访问权限。
- 现象：Windows环境下docker部署完成后，前端页面无法正常加载，返回`502 Bad Gateway`状态码。原因：未将容器端口映射到主机的正确端口，且未关闭本地防火墙对对应端口的拦截，导致前端无法访问FastGPT服务。
- 现象：升级后生成的台账报告缺失部分字段的数值内容。原因：未提前配置结构化字段的单位转换规则，城投台账包含万元、亿元等多单位数值，未统一解析导致字段无法正常展示。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`DB_MAX_LINK`配置的连接池是否能同时建立指定数量的数据库连接，连接成功后读取结构化台账的核心字段。
- 上传一份城投平台的真实台账文档，触发报告生成任务，检查存储路径是否与`STORAGE_S3_ENDPOINT`配置的地址一致。
- 访问`FE_DOMAIN`配置的域名，验证前端页面能否正常加载并调用后端接口。
- 查看`REDIS_URL`对应的缓存节点日志，确认增量同步的台账数据已被正确缓存。
