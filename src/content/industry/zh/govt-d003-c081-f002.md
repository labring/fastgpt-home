# 基础化工的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
基础化工的台账数据主要来自生产班组日报、原料入库出库单、设备巡检记录、月度质量检验报表。数据更新以每日班次为节奏，部分关键指标如物料库存、设备运行参数实时同步。文档以结构化表格为主，包含物料编码、批次号、库存量、检验值等字段，单位涉及吨、千克、百分比、运行小时等，部分长文档为跨页的月度汇总台账。

## 这些特征在「向量模型与索引」这一环带来什么约束
基础化工台账的结构化字段多且带有固定单位，会要求索引过程中保留字段与单位的关联信息，避免嵌入时丢失语义关联。高频更新的实时数据要求索引支持增量同步，避免全量重建带来的性能消耗。长文档的跨页汇总台账，需要分块时保留上下文连贯性，防止拆分后破坏指标与批次的对应关系。多维度的检验指标数据，会让向量召回时需要兼顾数值与文本语义的匹配精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 基础化工台账多为结构化表格与长文本结合，该区间可保留单批次物料的完整指标信息 |
| 重叠长度 | 100–150 字符 | 避免跨块的批次号、物料编码被拆分，保证语义连贯性 |
| 相似度阈值 | 0.72–0.85 | 适配台账字段的精准匹配需求，过滤低相关性的历史台账数据 |
| 单次搜索上限 | 前 8 条 | 平衡召回范围与上下文长度，适配基础化工台账的多字段检索需求 |
| `defaultToken` | 4096 token | 匹配基础化工月度汇总台账的平均长度，保证完整嵌入 |
| `maxToken` | 8192 token | 覆盖FastGPT v4.17.0版本下多知识库合并后的上下文长度需求，避免截断关键指标 |

## 容易做错的三处
- 现象：单个大型月度台账文件长时间停留在索引中，进度条无变化。原因：台账包含嵌套表格与超长文本行，分块时触发了重复校验逻辑，导致索引阻塞。
- 现象：切换知识库索引时弹出60秒超时报错提示。原因：未配置增量索引策略，全量同步多批次台账文件时超出默认超时限制。
- 现象：检索结果中混杂了非指定知识库的台账数据。原因：未正确配置知识库优先级规则，召回时未优先读取目标知识库的索引内容。

## 怎么确认配好了
- 上传单份标准台账文件，查看索引进度条是否在合理时间内完成，根据实际文件大小调整分块配置。
- 检索包含特定物料编码的台账数据，核对召回结果是否包含目标字段与单位信息，调整相似度阈值至匹配需求。
- 配置双知识库优先级规则，发起跨知识库检索，确认结果优先来自指定知识库，验证优先级设置生效。
- 查看向量嵌入日志，确认`defaultToken`与`maxToken`的配置未触发截断告警，匹配台账文档的实际长度。
