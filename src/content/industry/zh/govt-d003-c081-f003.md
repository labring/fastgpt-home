# 基础化工的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
基础化工的台账数据主要来自生产控制系统、实验室质检系统、仓库管理系统，更新节奏多为每班或每日。文档格式以多工作表Excel、结构化Word为主，包含物料编码、批次号、反应温度、压力、收率、质检合格率等固定字段，单位涵盖℃、MPa、%、吨等。单份台账文件常包含上万行数据或十万级中文字符，字段间存在明确的业务关联逻辑。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多系统来源导致字段命名存在细微差异，提示词需先完成字段对齐才能准确汇总。大体积的Excel与Word文件，要求多轮对话能拆分处理任务，避免单次加载全部数据超出模型上下文。高频更新的台账数据，要求对话过程中可实时拉取最新条目，适配台账的高频更新节奏。多轮交互中需跟踪特定批次号，避免混淆不同生产周期的台账数据，同时控制上下文长度防止响应变慢。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 字符 | 基础化工台账字段较多，单轮对话需覆盖至少2个批次的完整数据，避免截断核心信息 |
| 单次对话token上限 | 16000 token | 适配15000行Excel的分块处理需求，防止超出主流大模型的上下文限制 |
| 文件分块大小 | 500–800 行（Excel） | 平衡解析效率与单块数据的处理复杂度，适配基础化工台账的行数量级 |
| 会话绑定参数 | `chatId` | 绑定当前会话的台账批次号，确保多轮对话中跟踪的业务对象一致 |
| 历史消息保留 | 前10条 `messages` | 控制上下文长度，避免过多历史对话导致响应延迟 |
| 变量传递规则 | `variables` | 传递当前查询的核心字段范围，简化提示词的字段匹配逻辑 |

## 容易做错的三处
- 现象：上传15000行Excel台账后，对话返回结果条数不符预期。原因：未配置合适的文件分块大小，导致部分数据块未被正确加载。
- 现象：调用对话接口传文件后，返回字段为空。原因：未通过`variables`配置字段映射规则，未将Excel列名与台账标准字段对齐。
- 现象：多轮对话响应超时，状态码返回504。原因：未限制单次对话token上限，处理大体积台账数据时超出模型上下文限制。

## 怎么确认配好了
- 上传预设的15000行Excel台账，查看对话界面的解析进度，确认分块处理的块数符合预期。
- 发起多轮对话，指定查询某一批次的收率与质检数据，检查返回结果是否包含该批次的全部核心字段。
- 调用对话接口，传入`chatId`参数发起两次连续对话，验证第二次对话可继承第一次的查询上下文。
- 查看token消耗统计面板，确认每次对话的token数未超出配置的单次上限。
