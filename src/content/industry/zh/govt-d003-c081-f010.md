# 基础化工的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
基础化工的台账数据主要来源于生产执行系统（MES）、中央控制室DCS日志、质检部电子报告单、仓储管理系统。更新节奏为每日每班同步或月度汇总，文档以结构化表格为核心载体，字段包含物料编码、批次号、投料重量、产出量、能耗值、质检指标，单位多为吨、千克、千克标准煤，部分月度汇总报告附带工艺流程图附件，单份文档页数可达5至20页。

## 这些特征在「知识库检索与召回」这一环带来什么约束
基础化工台账的结构化字段多、单位体系复杂，要求检索时需精准匹配字段名称与对应单位，否则会召回无关的物料数据。高频更新的台账数据需要定期同步知识库，避免检索到过时信息。长文档式的月度汇总报告分块后易丢失跨行的字段关联，导致检索结果无法覆盖完整的物料衡算逻辑。此外，批次号、物料编码作为核心标识，要求检索时优先匹配唯一标识字段，减少召回歧义。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 适配基础化工台账的精准检索需求，平衡召回精度与覆盖范围 |
| `limit` | 前10条 | 覆盖月度汇总报告的多字段关联信息，避免单次召回条数不足 |
| `searchMode` | 语义检索+精准匹配 | 兼顾物料名称的语义关联与物料编码的精准匹配，适配结构化台账的检索特点 |
| `usingReRank` | 开启 | 对召回结果按相关性重排，修正单一语义检索的字段匹配偏差 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展物料编码、批次号的同义检索词，补充台账中常用的简称与全称关联 |
| `collectionIds` | 按台账专属知识库配置 | 限定检索范围仅覆盖基础化工台账与报告数据集，避免混入其他品类数据 |

## 容易做错的三处
- 现象：确认插件时出现MongoServerError: The dollar ($) p报错，插件加载失败。原因：FastGPT v4.17.0的台账插件与MongoDB 4.4.29版本存在兼容性冲突，未适配该版本的查询语法规则。
- 现象：csv格式台账导入后，AI检索结果条数不足预期，例如标注50项的表格仅召回30余项。原因：未开启`datasetSearchUsingExtensionQuery`，未自动扩展字段与批次号的检索词，导致部分带特殊格式的条目无法被匹配。
- 现象：导入PDF格式的台账文档后，知识库无法检索到有效表格数据。原因：默认PDF解析未保留表格的结构化字段关联，仅提取纯文本导致字段信息丢失，配置mineru解析后未调整检索参数适配长表格结构。

## 怎么确认配好了
- 手动检索已知的物料编码，核对召回结果是否包含该编码对应的完整台账条目，调整`similarity`取值直到匹配结果符合业务预期。
- 导出单次检索的结果条数，确认覆盖范围满足台账的字段数量要求，调整`limit`取值适配业务场景。
- 导入测试用的PDF台账文档，验证检索结果是否包含表格内的核心字段数据，调整解析与检索参数确保结构化信息被完整保留。
- 检查知识库的数据集配置，确认`collectionIds`仅指向基础化工台账与报告的专属数据集，避免检索到无关内容。
