# 基础电信运营的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
基础电信运营的台账数据主要来源于运营支撑系统、计费系统、网络性能监控平台三类核心业务系统。数据更新节奏为每小时增量同步当日运行数据，每日完成全量汇总归档。文档结构以结构化CSV或JSON格式为主，包含基站ID、运行时长、流量使用量、故障时长、用户服务次数等字段，各字段对应明确单位，如运行时长以分钟为单位、流量使用量以GB为单位。本页面基于FastGPT v4.17.0版本编写。

## 这些特征在「部署与升级」这一环带来什么约束
多数据源的接入要求部署阶段配置多个独立的数据连接参数，适配不同业务系统的接口规范。高频的增量更新节奏要求定时同步任务的间隔适配小时级更新，避免数据延迟影响运营决策。结构化字段与固定单位的要求，需要在部署时开启数据格式校验环节，保障后续汇总报告的字段一致性与可读性。大体积的台账数据量，要求配置足够的存储资源与并发连接数，防止同步过程中出现资源耗尽。升级阶段需兼容旧版台账的数据格式，避免中断日常运营的汇总任务。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/telecom_ledger?authSource=admin` | 存储台账的非结构化原始数据与历史归档文件，适配高频读写需求 |
| `PG_URL` | `postgresql://username:password@host:port/telecom_stat?sslmode=require` | 存储台账的结构化统计字段与汇总报告元数据，保障事务一致性 |
| `REDIS_URL` | `redis://:password@host:port/0` | 缓存高频查询的台账摘要数据，降低数据库的重复读写负载 |
| `DB_MAX_LINK` | `200–300` | 适配每小时增量同步的并发连接需求，避免同步过程中连接耗尽，符合FastGPT v4.17.0版本的并发配置要求 |
| `STORAGE_S3_ENDPOINT` | `按本地对象存储服务商提供的地址填写` | 存储台账导出的PDF报告与原始数据备份，适配大文件存储需求 |
| `ROOT_KEY` | `自定义32位随机字符串` | 保障系统后台操作的权限安全，符合国央企数据安全合规要求 |

## 容易做错的三处
- 现象：首次部署后登录界面无注册入口，无法创建管理员账号，后台日志返回`403 Forbidden`状态码。原因：未正确配置`ROOT_KEY`参数，导致系统初始权限校验失败。
- 现象：接入外部大模型时返回认证失败，日志显示`invalid api key`。原因：未按照国央企安全要求配置模型接入的密钥校验规则，未正确匹配外部平台的认证格式。
- 现象：台账同步任务执行失败，任务日志显示字段缺失。原因：未校验`PG_URL`连接的数据库权限，无法读取台账的完整字段数据。

## 怎么确认配好了
- 执行内置的数据库连接测试脚本，验证`MONGODB_URI`与`PG_URL`的连接状态，确认无连接超时或权限报错。
- 启动预设的定时同步任务，查看任务日志中是否有增量数据同步成功的记录，确认同步频率符合台账的小时级更新节奏。
- 尝试生成一份单基站的台账汇总报告，检查报告中包含的字段与单位是否与基础电信运营的台账格式一致。
- 访问`FE_DOMAIN`配置的域名，验证登录界面可正常加载，使用`ROOT_KEY`创建初始管理员账号，确认权限配置生效。
