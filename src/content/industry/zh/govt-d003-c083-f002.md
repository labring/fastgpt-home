# 基础设施建设的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
基础设施建设的台账数据主要来自施工日志、材料进场验收单、进度报审表、竣工验收报告等项目文件。数据更新随项目推进节奏，单次项目周期内按周或按施工节点批量新增，单份文档多为结构化表格形式，包含项目编号、施工区段、材料规格、进场数量（单位为吨、立方米或平方米）、验收人员、验收时间等固定字段，部分附件会附带非结构化的现场照片说明文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
基础设施建设台账的结构化字段多且带明确单位，会要求向量索引在编码时保留字段语义关联，避免单位混淆导致的匹配偏差。按项目节点批量更新的数据，要求索引支持增量更新，减少全量重建的计算开销。单份文档长度差异大，短则数十行表格，长则包含多页现场说明，需要索引适配不同长度的文本块，同时避免长文本块超出向量模型的处理上限。台账数据多关联项目唯一标识，索引需支持按项目ID进行分组召回，提升精准匹配度。FastGPT v4.17.0 版本针对此类场景优化了相关配置逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配台账结构化表格与短文本说明的混合长度，避免单块包含过多关联字段导致语义断裂 |
| 重叠长度 | 100–150 字符 | 保留相邻块之间的字段关联信息，防止跨块的材料型号、项目编号等关键信息丢失 |
| 相似度阈值 | 0.75–0.85 | 匹配台账数据的结构化语义特征，过滤低相关的非项目类匹配结果 |
| 单次搜索上限 | 前 10 条 | 控制单轮召回的结果数量，适配台账汇总时多维度信息的快速整合需求 |
| 最大上下文 | 6000 字符 | 容纳单项目下多份台账的关联信息，满足报告生成时的上下文填充需求 |
| `defaultToken` | 4096 | 匹配通用向量模型的输入上限，避免长文本块触发截断错误 |
| `maxToken` | 8192 | 适配长文档台账的向量编码需求，覆盖多数项目文件的文本长度 |

## 容易做错的三处
- 现象：调用接口时出现60秒超时报错。原因：未针对台账批量更新的场景配置增量索引，全量索引重建时占用过多计算资源，导致请求超时。
- 现象：知识库状态长时间显示“训练中”或“重建中”，耗时超过一天。原因：未按项目节点调整索引重建频率，全量重建覆盖了多份高频更新的台账文件，导致任务积压。
- 现象：批量添加索引的请求返回格式错误。原因：未按照台账的结构化字段格式传递请求参数，遗漏了项目编号、材料规格等必填字段的映射配置。

## 怎么确认配好了
- 上传单份典型的台账文件，查看分块预览界面，确认分块长度与重叠长度符合预设配置。
- 发起针对特定项目的台账汇总查询，查看召回结果的数量与项目标识是否匹配预设的单次搜索上限。
- 测试增量更新单份台账文件，确认索引重建的耗时符合预期，无全量重建触发的超时风险。
- 查看向量模型的日志输出，确认`defaultToken`与`maxToken`参数未触发文本截断报错。
