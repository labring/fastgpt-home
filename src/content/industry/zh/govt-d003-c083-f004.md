# 基础设施建设的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
基础设施建设的台账数据主要来自施工日志、材料进场验收单、进度周报、监理旁站记录等一线施工文档。数据更新随施工推进节奏，单次施工段完成后批量更新，日常巡检数据每日同步。单份文档长度跨度大，短则数百字符的巡检记录，长则数万字符的进度专项报告。字段包含项目唯一标识、施工区域编号、材料品类、进场数量、验收日期、监理签字状态，单位涵盖立方米、吨、工作日、平方米等。本文档适用于FastGPT v4.17.0版本。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的台账数据来源要求工作流需配置多文档接入节点，支持批量导入不同格式的施工文档。数据更新无固定周期，需绑定施工节点事件作为工作流触发条件，适配非固定周期的更新需求。单份文档长度跨度大，需适配不同长度的文本解析，避免长文档截断导致关键信息丢失。字段包含多类单位的数值型内容，需在变量提取环节配置单位识别规则，确保台账汇总时数值与单位正确匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次搜索上限 | 前30条 | 基础设施建设台账单批次接入文档多，单次召回过多会导致上下文溢出 |
| 最大上下文长度 | 8000–12000 字符 | 单份长文档进度报告解析后文本较长，需适配长上下文处理 |
| `variables` | 提取项目编号、材料数量、验收日期三类核心字段 | 台账汇总需聚焦核心业务字段，避免冗余信息干扰 |
| `nodeId` | 绑定施工节点触发节点的ID | 工作流需按施工完成节点触发，适配非固定周期的更新需求 |
| 问题优化 | 开启 | 台账汇总的提问需明确指向字段提取与数值统计，优化后可提升召回精准度 |
| 重排 | 按实测标定 | 不同项目的文档结构差异大，需根据实际召回效果调整 |

## 容易做错的三处
- 工作流中知识库搜索的单次引用上限显示为3000，与独立应用配置的13000上限不一致。原因是工作流节点的搜索上下文配额与独立知识库应用的配额规则分离，未针对长文档台账场景单独调整。
- 编排工作流后通过API调用，返回的台账数据字段为空。原因是未在`variables`配置中声明需要提取的核心字段，导致工作流未返回对应数据。
- 工作流执行后显示超时，界面提示执行时长超过600秒。原因是未配置单次接入的文档数量上限，多份长进度报告同时解析超出系统默认超时阈值。

## 怎么确认配好了
- 进入工作流编辑页面，核对`variables`配置项，确认已声明需要提取的台账核心字段。
- 触发模拟施工节点事件，查看工作流执行日志，确认所有节点按预期顺序执行且无报错。
- 调用测试接口，验证返回的工作流结果包含预设的台账汇总字段与正确单位。
- 调整单次搜索上限参数，对比不同取值下的召回结果，确认符合业务场景的召回需求。
