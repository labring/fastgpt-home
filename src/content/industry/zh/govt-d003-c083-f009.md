# 基础设施建设的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
基础设施建设的台账数据来源为现场施工台账系统、材料进场验收单、进度周报、监理归档文件，更新节奏为每日更新施工进度、每周汇总材料消耗与节点完成情况。单份台账文档包含结构化字段与附件扫描件，字段涵盖项目唯一标识、施工区段名称、材料品类、进场数量、验收状态、工序节点编号，单位多为吨、立方米、工时等工程计量专用单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
基础设施建设台账的结构化字段与专属计量单位，要求模型调用前需完成字段映射规则配置，避免单位识别或数值匹配错误。每日更新的动态数据带来上下文长度波动，需适配多批次台账的汇总需求。纸质归档的扫描件附件，要求模型支持视觉解析能力。多工序关联的台账内容，需限制工具调用的冗余逻辑，确保汇总结果的严谨性。这些特征直接约束了模型接入时的上下文长度、视觉配置、工具调用规则等核心参数的取值范围。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 覆盖单批次5-10份结构化台账与关联附件的文本长度，适配多日汇总需求 |
| `maxTokens` | 3500–4000 token | 限制单份工程报告的输出篇幅，符合基础设施建设台账报告的常规格式要求 |
| `quoteMaxToken` | 1200–1500 token | 限定引用的台账字段与数值内容，避免无关文本干扰汇总逻辑 |
| `vision` | enabled | 支持解析材料进场单、验收单的扫描件附件，适配纸质归档数据的数字化处理 |
| `temperature` | 0.2–0.4 | 保持工程数据的数值与字段一致性，避免出现不符合计量规则的偏差 |
| `AIPROXY_API_TOKEN` | 填写私有部署专属密钥 | 保障接口调用的安全性，适配国央企与政府场景的合规要求 |

## 容易做错的三处
- 现象：附件扫描件无法被正确解析，模型输出未提及附件中的验收数量。原因：未开启`vision`配置项，或配置参数未正确同步到模型调用链路。
- 现象：多次调用生成的台账汇总结果数值不一致，出现材料数量偏差。原因：`temperature`取值过高，导致模型对工程计量数值的判断出现随机波动。
- 现象：OneAPI转发的模型请求返回401未授权错误。原因：`AIPROXY_API_TOKEN`填写错误，或密钥权限未覆盖当前部署环境的访问范围。

## 怎么确认配好了
- 上传一份包含结构化字段与扫描附件的基础设施建设台账样本，查看模型是否能正确提取材料品类、进场数量等核心字段。
- 连续调用3次相同的台账汇总请求，核对输出的数值与字段是否保持一致。
- 检查OneAPI日志，确认模型请求的接口地址与密钥匹配，无401或超时类错误。
- 查看模型调用的上下文长度统计，确认未超出`maxContext`的配置范围，无关键台账内容被截断的情况。
