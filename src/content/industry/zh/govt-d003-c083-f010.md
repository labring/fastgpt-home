# 基础设施建设的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
基础设施建设的台账数据主要来源于施工日志、材料进场验收单、进度周报、竣工验收报告等业务系统。数据更新节奏随施工节点推进，单项工程验收后生成完整台账条目，日常施工中每日更新进度与材料消耗数据。文档以结构化为主，包含项目编号、施工段、材料规格、进场日期、验收人、合格状态等固定字段，单位涉及立方米、吨、天、平方米等工程常用计量单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化多字段的台账数据要求检索需精准匹配特定字段内容，避免泛化召回无关条目；高频更新的施工数据要求检索节点可动态绑定项目范围，确保返回最新的台账内容；工程专业术语多且存在中英文对照的文档，要求检索需优化查询词以匹配专业表述；长文档的验收报告与进度报表，要求召回结果需经过重排以优先返回最相关的内容片段。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75-0.85 | 基础设施台账包含大量专业术语，较高的相似度阈值可过滤无关召回结果，确保匹配准确性 |
| `limit` | 前8条 | 台账字段数量较多，过多召回结果会超出上下文长度限制，影响大模型对有效信息的提取 |
| `searchMode` | vector | 需精准匹配台账的结构化字段内容，确保召回结果与提问高度相关 |
| `usingReRank` | 开启 | 长文档的验收报告与进度报表内容较多，重排可将最相关的内容片段排在前列，提升检索效率 |
| `datasetSearchUsingExtensionQuery` | 开启 | 台账存在中英文对照的专业术语，优化查询词可提升专业表述的匹配成功率 |
| `collectionIds` | 按项目ID列表填写 | 需限定检索范围为特定项目的台账知识库，避免召回其他项目的无关数据 |

## 容易做错的三处
- 现象：工作流中仅第一个问题触发知识库召回，后续问题无知识库引用。原因：未开启全局变量持久化配置，或知识库检索节点未绑定动态的`collectionIds`参数，导致后续请求切换了数据集范围。
- 现象：导入中英文对照的台账翻译文档后，大模型未调用知识库内容。原因：未开启`datasetSearchUsingExtensionQuery`参数，且未针对专业术语优化检索词，导致专业表述匹配失败。
- 现象：模型提示未提供具体知识库内容。原因：`similarity`阈值设置过高，导致符合要求的召回结果条数为0，或`collectionIds`填写错误，未关联到目标台账数据集。

## 怎么确认配好了
- 查看FastGPT v4.17.0中知识库检索节点的返回日志，确认召回结果的条数符合`limit`设置的区间。
- 输入台账中的专业术语，验证检索结果是否包含对应字段的内容片段。
- 切换不同项目的`collectionIds`参数，确认检索结果仅包含对应项目的台账数据。
- 测试多轮对话，确认每一轮提问都能触发知识库召回并引用相关内容。
