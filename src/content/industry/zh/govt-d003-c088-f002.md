# 工程咨询监理的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
工程咨询监理的台账数据主要来源于现场监理日志、材料报验单、进度款报审表、整改闭环记录等项目文档，更新节奏随监理周期推进，日常台账每日更新，项目竣工类台账随单项目进度阶段性汇总。文档以结构化字段为主，包含项目编号、监理单位、检验批次、合格率、整改完成时间等字段，附带少量非结构化的手写或电子批注，单位涉及平方米、吨、工作日等工程常用单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化字段占比高的特征要求分块时保留字段关联，避免拆分单条报验单的核心信息，防止向量编码丢失业务关联。更新节奏的多样性要求索引支持增量触发与全量刷新两种模式，适配日常台账的高频更新与项目竣工后的批量汇总。文档长度跨度大的特征要求向量模型适配不同长度的文本编码，兼顾短字段报验单与长文档监理月报的编码准确性。台账数据的项目关联性强要求索引召回时优先匹配目标项目的关联文档，减少无关历史数据的干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 工程咨询监理台账单份文档长度多在500-2000字符，分块过长会丢失字段关联，过短会破坏单条报验/日志的完整性 |
| 重叠长度 | 100–150 字符 | 避免跨分块的监理整改项、进度数据被拆分，保证业务逻辑的连续性 |

| 相似度阈值 | 0.72–0.85 | 区分合格的台账关联数据与无关的历史项目数据，适配监理台账的精准召回需求 |
| 单次搜索上限 | 前 8 条 | 覆盖单项目下常用的3-5份核心台账，避免冗余召回影响检索效率 |
| `defaultToken` | 1024 | 配置单次向量编码的基础token配额，平衡长文档编码与索引任务的执行效率 |

## 容易做错的三处
- 现象：升级版本后同CSV文件无法正常分块，报错提示「分块文本超出编码上限」。原因：未调整`maxToken`参数适配新的向量模型编码规则，导致原分块长度的文本无法被正确编码。
- 现象：知识库索引卡住，未完成的索引任务无进度更新。原因：未配置增量索引触发规则，全量索引时大量历史台账数据重复加载，导致任务阻塞。
- 现象：搜索结果中混入非目标项目的台账数据，召回准确率低。原因：相似度阈值设置过低，将不相关的历史项目数据误召回。

## 怎么确认配好了
- 上传单份监理报验单CSV，执行分块测试，查看分块结果是否保留完整的报验编号、检验批次字段。
- 启动全量索引任务，观察后台日志是否出现`defaultToken`相关的配额警告，确认参数配置生效。
- 输入「XX项目2024年3月整改台账」的检索词，核对召回结果是否仅包含目标项目的相关文档。
- 等待索引完成后，增量上传新的监理日志，确认索引任务可正常触发并完成更新。
