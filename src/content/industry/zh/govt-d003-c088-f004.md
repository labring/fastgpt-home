# 工程咨询监理的台账汇总与报告生成：工作流编排

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
工程咨询监理的数据主要来源于现场旁站记录、材料送检台账、工序验收单、监理日志等原始文档。数据更新随工程进度推进，单工序验收完成后即时更新，月度汇总节点批量更新全周期台账。单份台账文档包含监理单位、工程名称、分项工序、验收时间、合格判定、整改项清单、整改闭环时间等字段，字段单位涵盖项、天、平方米、立方米等工程类标准单位。

## 这些特征在「工作流编排」这一环带来什么约束
原始数据分散在纸质单据、现场巡检系统、材料管理平台等多个渠道，工作流需支持跨源数据拉取节点，避免手动录入误差。数据更新节奏随工程节点波动，工作流需同时支持定时触发与验收完成事件触发两种模式。台账字段包含工程类专属单位，参数提取环节需匹配字段格式，避免单位识别错误。单份整改项文本长度可达数千字符，工作流需支持长文本切割与分段处理，适配后续报告生成的格式要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定工程ID、分项工序类型 | 精准过滤对应工程的台账数据，避免跨项目数据混淆 |
| 节点触发规则 | 每日22:00定时+验收完成事件触发 | 适配月度汇总与即时整改台账的更新需求 |
| `nodeId` | 绑定材料送检节点、验收节点的ID | 定向拉取对应环节的原始数据，减少无效数据加载 |
| 数据拉取批次 | 每批次50条 | 适配监理台账单批次数据量，避免内存溢出 |
| 长文本切割长度 | 800–1200字符 | 适配报告生成模块的单段文本承载上限，避免截断关键整改信息 |
| 字段映射规则 | 按监理台账标准字段映射 | 确保汇总数据的字段与报告模板格式匹配，减少后期整理工作量 |
| 异常处理超时 | 600秒 | 覆盖跨系统拉取数据的最大响应时长，避免因网络延迟触发无效失败 |

## 容易做错的三处
- 现象：工作流运行后全局变量未获取到系统侧传递的工程ID参数，字段为空。原因：未在`variables`配置项中声明系统内置参数的绑定规则，仅绑定了用户对话传入的参数。
- 现象：HTTP API返回的长整改文本被一次性传入报告生成节点，导致格式溢出报错。原因：未配置长文本切割参数，未对返回内容进行分段处理。
- 现象：内容提取节点运行失败，返回模型不支持指定调用格式的报错。原因：未确认内容提取节点的内置模型适配范围，强行使用自建模型接口接入。

## 怎么确认配好了
- 手动触发工作流，查看节点日志，确认所有绑定的`variables`参数均正常加载，无空值字段。
- 导入一份模拟的监理台账数据，运行工作流后检查生成的中间台账汇总文件，确认字段映射与原始数据一致。
- 模拟长度符合要求的整改文本，运行工作流后查看分段输出结果，确认切割逻辑符合预设规则。
- 模拟跨系统拉取数据的延迟场景，确认工作流在设定的超时时间内完成重试或触发失败告警。
