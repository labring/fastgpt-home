# 工程咨询监理的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
工程咨询监理的台账数据主要来源于现场监理日志、旁站验收记录、材料报验单、进度款报审表等一线文档。数据更新节奏为每日提交当日现场记录，每周汇总周度台账，月度形成阶段性报告。单份台账文档包含结构化字段与非结构化备注，结构化字段包括监理标段、材料批次、验收合格率、整改闭环状态，非结构化字段包含现场问题描述、整改方案，字段单位涵盖平方米、吨、工作日等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据特征对模型接入与配置带来明确约束。混合结构化与非结构化的文档内容，要求模型能同时完成结构化字段提取与非结构化语义理解，避免格式转换偏差。月度累计的台账文档量较大，要求配置适配长上下文处理的参数，避免截断关键整改记录与验收数据。多样的字段单位要求模型准确识别并保留单位信息，防止数据失真。每日更新的实时数据要求调用延迟匹配业务节奏，避免超时影响汇总流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配月度台账累计的文档总长度，避免关键整改记录与验收数据被截断 |
| `maxTokens` | 2000–3000 token | 匹配单份报告生成的内容长度，确保汇总结果完整覆盖所有台账条目 |
| `quoteMaxToken` | 1500 字符 | 保留足够的原始台账片段作为引用依据，满足监理报告的溯源要求 |
| `temperature` | 0.3–0.5 | 降低生成随机性，确保结构化字段的提取结果与台账数据严格一致 |
| `toolChoice` | auto | 自动选择合适的工具完成字段汇总与格式整理，适配多样的台账文档结构 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 匹配本地或云端部署的模型服务地址，确保调用链路正常 |

*注：本页面适配 FastGPT v4.17.0*

## 容易做错的三处
- 调用模型后返回空内容，排查发现`AIPROXY_API_TOKEN`配置错误，未正确填写平台分配的密钥，导致鉴权失败。
- 生成的报告字段单位丢失，原因是未配置合适的`maxContext`参数，导致原始台账的单位信息被截断。
- 单次调用超时，原因是`maxTokens`设置过大，超出模型服务的单次请求上限，导致请求被中断。

## 怎么确认配好了
- 上传单份标准监理台账文档，触发模型调用，检查返回结果是否完整包含所有结构化字段与非结构化备注。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置匹配当前部署环境，无鉴权报错。
- 调整`temperature`参数至0.3，生成多份同类型台账的汇总报告，检查结果的字段一致性，无随机偏差。
- 批量上传月度累计台账，检查`maxContext`参数是否适配总文档长度，无内容截断现象。
