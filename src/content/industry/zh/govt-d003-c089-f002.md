# 工程机械的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
工程机械台账数据来源包括设备出厂合格证、月度维保报告、现场巡检电子台账、租赁结算单据。更新节奏分为实时（运行数据同步）、每日（巡检信息录入）、每月（维保档案归档）三类。文档以结构化字段为核心框架，附带非结构化备注与附件。字段包含设备唯一编号、额定载荷（单位吨）、累计运行时长（单位小时）、下次维保日期、故障编码，部分文档附带设备铭牌照片、故障现场实拍图。

## 这些特征在「向量模型与索引」这一环带来什么约束
工程机械台账的结构化字段与非结构化附件并存的特征，要求索引环节需同时支持结构化元数据关联与非结构化内容向量化。多更新节奏的场景，要求索引支持增量更新与全量重索引两种模式。设备唯一编号作为核心标识，需作为元数据索引字段，避免重复关联同设备的多份文档。附件图片占比高的情况，需适配图片向量化的索引配置。不同台账文档长度差异显著，需灵活调整分块规则适配长短文本。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配工程机械台账单条记录的平均文本长度，避免单块内容过载导致向量化偏差 |
| 重叠长度 | 50–80 字符 | 保留分块间的设备编号、运行时长等关键上下文，防止跨块的关联信息断裂 |
| 相似度阈值 | 0.72–0.85 | 区分同设备不同巡检记录的相似度，避免无效的台账条目关联 |
| 单次召回上限 | 前 10 条 | 匹配台账汇总查询的单次关联文档数量需求，避免结果冗余 |
| `defaultToken` | 4096 | 适配台账汇总报告的基础上下文长度要求 |
| `maxToken` | 8192 | 容纳多份跨周期台账文档的汇总内容，满足长文本生成需求 |

## 容易做错的三处
- 现象：创建知识库时文本理解模型下拉框无可选模型，已添加的模型未出现在列表中。原因：未将模型绑定至文本理解模型权限组，仅完成了渠道添加步骤。
- 现象：单份文档上传后显示分块数与最终就绪后分块数不一致，出现重复分块。原因：未设置设备唯一编号作为元数据索引键，系统误将同设备的重复字段识别为新文档片段。
- 现象：触发批量重索引后任务中断或仅部分文档完成更新。原因：未调整`maxToken`适配批量索引的上下文上限，导致大体积文档触发超时中断。

## 怎么确认配好了
- 进入知识库设置页面，查看向量模型下拉列表，确认已添加的目标模型均显示为可选状态。
- 上传单份典型工程机械台账文档，查看分块预览界面，确认分块长度与重叠长度符合预设配置。
- 发起一次台账汇总查询，查看召回结果的数量，确认与预设的单次召回上限匹配。
- 触发全量重索引任务，等待任务完成后，检查所有文档的分块数无异常重复。
