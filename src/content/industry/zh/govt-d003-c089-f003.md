# 工程机械的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
工程机械台账数据主要来源于设备管理系统、IoT运行传感器、现场运维工单三类数据源。基础台账字段包含设备编号、型号、出厂日期、额定功率、维保周期，运行数据字段包含实时油耗、累计运行时长、故障次数，单位多为小时、升、台。基础台账数据每日同步更新，实时运行数据按秒级频率上传，单条完整台账文档长度多在500至1500字符。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据源分散导致对话需关联多类数据的上下文，多轮交互中需持续追踪当前会话对应的设备标识，避免混淆不同设备的台账数据。更新频率差异要求提示词需明确指定检索数据的时间范围，确保获取的运行数据与基础台账匹配。字段数量较多且包含层级结构，提示词需限定检索范围与输出格式，防止大模型混淆跨字段的统计逻辑。长文档特征则要求对话上下文需合理截断，避免超出模型的上下文窗口限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 字符 | 适配工程机械台账单条文档的长度，容纳多轮对话的设备标识与查询条件 |
| 单次检索条数 | 前 8 条 | 平衡检索效率与数据完整性，避免过多冗余字段干扰大模型的统计逻辑 |
| `chatId` | 绑定会话唯一设备标识 | 区分不同设备的对话上下文，确保每次检索仅匹配当前会话指定的设备数据 |
| `variables` | 绑定统计周期、输出字数 | 限定检索的数据时间范围，同时约束大模型的输出格式与长度 |
| `messages` | 按角色传递上下文 | 规范多轮对话的内容格式，确保大模型可正确识别历史查询与当前需求 |
| 提示词模板 | 按实测标定 | 适配台账字段的固定统计逻辑，明确要求先列设备编号再输出汇总结果 |

## 容易做错的三处
- 对话中返回的台账数据为空，但知识库测试可检索到对应内容。原因是未绑定`chatId`参数，导致会话上下文混淆，检索时匹配到了其他设备的台账数据。
- 调用时返回404 Invalid URL (POST /api/chat/completions)。原因是未正确配置`messages`参数的角色与内容格式，或接口路径未关联当前设备的唯一标识。
- 工作流执行至大模型处理环节后直接结束，未生成汇总报告。原因是未通过`variables`绑定工作流后续节点的触发条件，导致会话上下文未传递至汇总步骤。

## 怎么确认配好了
- 发起针对单台指定设备的台账查询，检查返回结果是否仅包含该设备的字段数据，无其他设备的冗余信息。
- 调用接口并查看日志，确认`chatId`参数随每次会话请求正确传递，无空值或重复值。
- 配置提示词约束输出格式，发起测试请求，检查返回内容是否符合预设的字段顺序与统计要求。
- 模拟多轮对话，依次查询不同设备的台账，检查会话上下文是否正确区分不同设备的检索结果。
