# 工程机械的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
工程机械台账数据主要来自设备IoT采集终端、企业设备管理系统、现场运维工单。数据更新节奏分两类：运行参数类每15分钟同步一次，维保、油耗类每日更新。单台设备台账文档包含设备唯一标识、额定功率、累计作业时长、月度维保记录、燃油消耗数据等字段，字段单位统一为kW、小时、升等标准工业计量单位，单份台账文档长度通常在500-1500字符。

## 这些特征在「工作流编排」这一环带来什么约束
IoT采集的实时运行数据要求工作流触发节点间隔不超过15分钟，否则无法匹配现场实时工况。多源数据融合需求要求工作流需先对齐设备管理系统与IoT终端的设备ID映射规则，避免数据张冠李戴。单台设备台账包含多类字段，工作流需配置字段校验节点，过滤缺失单位的异常数据。多台设备台账批量处理时，需通过`variables`绑定设备ID作为全局参数，通过`nodeId`为每个设备分组分配独立链路，确保流程按设备分组执行。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定设备唯一标识、统计周期为全局入参，取值区间为`1 个`至`10 个`设备ID | 匹配单批次可处理的设备台账数量，避免节点资源耗尽 |
| 批量处理节点 | 按设备ID分组执行，单次处理`1–5 台设备` | 工程机械台账单批次数据量较大，分组处理可降低超时风险 |
| 字段校验规则 | 过滤缺失单位的字段，校验`累计作业时长`为非负数值 | 匹配工程机械台账字段的工业计量规范，避免无效数据进入汇总流程 |
| 超时设置 | 配置为`300 秒` | 适配单台设备台账的解析与汇总耗时，避免流程中断 |
| `nodeId` | 为每个设备分组节点绑定唯一标识 | 确保多设备并行处理时的流程链路不混淆 |
| Markdown输出格式 | 启用表格化展示字段汇总结果 | 符合工程设备台账报告的通用阅读习惯 |

## 容易做错的三处
- 现象：工作流启动后全局`variables`参数未加载，核心字段显示为空。原因：未在工作流的启动配置页绑定设备ID、统计周期等全局入参，导致后续节点无法获取必要数据。
- 现象：批量上传多台设备的台账文档后，仅首份文档完成汇总，其余文档无处理结果。原因：未启用批量节点的循环触发逻辑，未通过`nodeId`为每个文档分配独立的处理链路。
- 现象：工作流执行超时，返回状态码504。原因：单批次处理的设备台账数量超出配置阈值，汇总耗时超过预设的`300 秒`上限，触发节点超时。

## 怎么确认配好了
- 启动工作流时手动输入测试用的设备ID，检查`variables`参数是否正确传递至后续节点的输入配置面板。
- 上传单台设备的台账文档，验证流程是否完整执行，字段校验节点是否过滤了异常数据。
- 调整单批次处理的设备数量，确认流程耗时未超过预设阈值，无超时报错。
- 在FastGPT v4.17.0版本中，查看工作流执行日志，确认`nodeId`绑定的每个处理节点均正常触发并返回结果。
