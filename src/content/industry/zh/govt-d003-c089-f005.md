# 工程机械的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
数据来源为企业内部设备管理系统、车载物联网终端、维保工单系统。更新节奏随终端上报频率变化，单次作业完成后或每日固定时段同步。文档以单台工程机械为单条数据主体，包含设备唯一标识、型号参数、累计作业时长、维保周期、实时工况、油耗统计等字段，字段单位涵盖小时、升、公里等物理量单位。部分台账还包含租赁方信息、作业区域记录，数据格式多为结构化表格或标准化JSON报文。

## 这些特征在「工具调用与插件」这一环带来什么约束
工程机械台账的结构化字段多且带物理单位，工具调用时需严格匹配字段名与单位，避免汇总时出现单位混淆。数据更新节奏不固定，插件需支持按需拉取最新上报数据，不依赖固定周期缓存。单台设备数据条目较多，批量汇总时单次工具调用的数据量上限需适配设备管理系统的接口限制，避免触发调用超时。部分台账包含跨系统关联数据，工具调用需支持跨数据源联动，确保租赁、作业区域等关联信息同步拉取。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `functionCall` | 预设结构化参数模板，包含设备编号、统计周期、需汇总字段 | 工程机械台账数据结构化程度高，明确参数边界可避免调用歧义 |
| `toolChoice` | `auto` | 可根据用户提问自动匹配工具，适配多样化的汇总需求 |
| 单次工具调用返回数据条数 | 前15-25条 | 适配单批次设备管理数据量，避免超出上下文窗口限制 |
| 工具调用超时时间 | 300-600秒 | 设备管理系统接口响应受网络与数据量影响，预留足够时间完成批量拉取 |
| 参数校验开关 | 开启 | 台账字段带有物理单位，校验可避免单位不匹配导致的汇总错误 |
| 插件触发关键词 | 包含“汇总”“报告”“台账” | 精准触发工具调用，过滤非相关对话请求 |

## 容易做错的三处
- 现象：调用台账汇总工具时返回514状态码。原因：工具调用超时时间设置过短，设备管理系统批量拉取数据时未完成响应，触发平台限流规则。
- 现象：工具调用结果混入非台账的无关信息。原因：未开启`functionCall`的参数校验，或插件触发条件未精准匹配关键词，导致平台自动调用了知识库召回功能。
- 现象：单次对话中多次尝试调用工具，仅第一次调用返回有效结果。原因：未正确配置`toolChoice`参数，对话上下文未保留工具调用的状态标识，后续请求无法正确匹配插件。

## 怎么确认配好了
- 发起包含“汇总指定周期设备作业数据”的测试提问，检查工具调用是否按配置的触发条件自动启动。
- 查看工具调用日志，确认返回的数据字段与工程机械台账的标准结构一致，无字段缺失或单位异常。
- 模拟连续发起两次工具调用请求，检查两次调用均能正常获取对应批次的设备数据，无调用失效。
- 发起包含大量设备编号的测试提问，确认平台按配置的单次调用上限处理返回内容，未超出上下文限制。
