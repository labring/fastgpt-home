# 工程机械的台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
工程机械台账与报告的数据主要来源于设备出厂参数文档、月度运维巡检记录、租赁采购合同附件、年度设备盘点报表。数据更新节奏随业务节点变化：采购入库时新增设备基础台账，运维日志按每日或每周更新，年度盘点报表按月度或季度生成。文档格式涵盖可编辑PDF、结构化Excel表格与扫描版纸质报告，字段包含设备唯一编号、型号、额定运行小时数、燃油消耗量、使用地点、维保时间等，单位涉及小时、升、台次等工程专用计量标准。本页面适配FastGPT v4.17.0版本。

## 这些特征在「文档解析与分块」这一环带来什么约束
工程机械台账的多源异构格式要求解析环节同时支持可编辑文本与扫描图片提取，否则会丢失运维记录中的关键参数。设备编号与使用地点等字段的强关联属性，要求分块时不能破坏单条数据的完整性，否则检索时会出现字段匹配缺失。长文档与大体积打包文件会拉长解析耗时，若未适配超时设置易触发解析失败。Excel台账中的筛选类字段（如使用地）若在分块时被截断，会导致后续检索无法召回完整匹配结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `customPdfParse` | 开启OCR模式 | 适配FastGPT v4.17.0版本的自定义OCR解析设置，工程机械台账常包含扫描版运维报告与出厂参数页，原生解析无法提取图片内嵌的文本内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 秒 | 单台设备年度台账PDF可达数十页，OCR解析耗时较长，默认超时设置易触发报错 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 部分大型工程的批量台账打包文件体积较大，需适配多文件批量上传的存储与解析需求 |
| `chunkSize` | 800–1200 字符 | 工程机械台账单块需覆盖单台设备的连续运维记录或完整参数组，避免拆分破坏数据关联 |
| `chunkSplitter` | 按设备ID+段落分隔 | 台账按设备分组，按纯段落拆分易跨设备，按设备ID分隔可保证块内数据归属统一 |
| `chunkSettingMode` | 手动配置 | 需针对不同格式的台账文档（PDF/Excel）调整分块规则，自动模式无法适配细分字段结构 |

## 容易做错的三处
- 现象：上传大型打包台账文件时触发超时报错，返回连接超时状态码。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，沿用默认短超时设置，无法完成多文件批量解析。
- 现象：检索Excel台账中的国外使用地设备时，返回结果条数远少于实际录入量。原因：分块时未保留`使用地`字段的关联元数据，或分块截断了包含该字段的完整数据行。
- 现象：扫描版设备出厂参数上传后，提取的文本缺失设备型号与额定运行小时数字段。原因：未开启`customPdfParse`的OCR模式，无法识别图片内嵌的台账参数。

## 怎么确认配好了
- 上传单份500页的年度运维台账PDF，等待解析完成后查看系统解析日志，确认无超时报错记录。
- 上传包含国外使用地设备的Excel台账，检索指定使用地字段后，核对返回的结果条数与实际录入条数一致。
- 上传扫描版设备出厂参数页，查看提取的文本中是否包含设备型号、额定运行小时数等核心字段。
- 调整`chunkSize`参数后，拆分长文档，检查分块结果是否未跨设备拆分连续的运维记录。
