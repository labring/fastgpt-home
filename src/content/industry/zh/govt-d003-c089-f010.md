# 工程机械的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
工程机械的台账数据主要来源于企业内部设备物联网平台、维保工单系统及原厂出厂参数手册。更新节奏为单次维保完成后实时同步，日常工况数据每小时更新一次。文档以结构化字段为主，包含设备唯一编码、型号规格、出厂日期、累计工作时长、单次维保内容、故障排查记录，单位涉及小时、升、台次等，部分长文本记录包含现场工况分析与故障根因描述。

## 这些特征在「知识库检索与召回」这一环带来什么约束
工程机械台账数据的结构化字段多且包含唯一设备编码，要求检索召回需同时支持语义匹配与精准字段匹配，避免模糊匹配导致的设备混淆。数据更新频率较高，要求知识库同步周期与设备运维节奏对齐，防止召回过期的维保记录。单条台账文档包含长文本的工况分析与故障记录，需合理设置分块规则，避免跨设备内容被错误关联。时序类数据如累计工作时长需支持按时间区间过滤，缩小召回范围，提升检索效率。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配工程机械台账的结构化字段与语义描述，平衡召回精准度与覆盖范围 |
| `limit` | 前10条 | 单设备台账数据条目较多，限制召回条数避免上下文溢出 |
| `searchMode` | hybrid | 同时支持语义检索与字段精准匹配，适配结构化台账的多维度查询 |
| `usingReRank` | 开启 | 对召回的台账条目按相关性重排，提升高匹配度设备数据的展示优先级 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 台账数据结构固定，无需扩展查询词，避免引入无关内容 |
| `collectionIds` | 指定对应设备台账的知识库集合ID | 隔离不同设备组的台账数据，避免跨组召回 |

## 容易做错的三处
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
- 现象：检索结果混入其他型号工程机械的台账内容。原因：未通过`collectionIds`配置限定目标知识库集合，导致跨分组数据被召回。
- 现象：单次检索返回的台账条目数量不足，无法覆盖汇总需求。原因：`limit`参数设置值过低，未匹配台账汇总所需的召回条数。

## 怎么确认配好了
- 进入FastGPT知识库管理页面，核对`collectionIds`配置的集合ID与目标工程机械台账知识库一致。
- 发起一条包含具体设备型号的测试查询，检查返回结果是否仅包含对应设备的台账数据。
- 查看检索结果的相关性排序，确认高匹配度条目优先展示，验证`usingReRank`功能生效。
- 复制任意chunk ID，确认页面已显示复制按钮，验证交互配置正确。
