# 房建工程总承包的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
房建工程总承包的台账数据来源涵盖BIM协同平台、现场巡检终端、材料采购系统及分包商报送表单。更新节奏为分包商每日报送当日材料进场、人员考勤数据，总包方每周汇总形成项目总台账。文档结构为按项目编号归档的结构化表格，包含项目编号、楼栋号、材料批次、进场日期、验收人、签证金额、工期节点等字段，单位涵盖立方米、吨、工作日、人民币元等，部分字段需关联现场验收照片作为佐证。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流需配置多节点的格式转换逻辑，适配不同系统导出的CSV、Excel、JSON格式。按项目编号归档的结构要求工作流需通过`variables`传入唯一项目编号作为过滤参数，避免跨项目数据混淆。高频更新的数据源要求工作流需设置固定触发周期，确保数据汇总的时效性。字段包含工程专用单位与精度要求，要求工作流配置字段校验节点，对数值型字段设置合理误差范围，避免无效数据进入汇总流程。在FastGPT v4.17.0版本的工作流编排中，需针对这些特征进行针对性配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发周期 | 每日 02:00 触发 | 房建台账数据由分包商每日报送，需在次日凌晨完成初步汇总，避免影响当日现场工作 |
| 数据源匹配规则 | 按`variables`传入的项目编号匹配对应数据源 | 房建项目台账按唯一项目编号归档，需精准关联对应项目的多源数据 |
| 数值字段校验阈值 | 允许±0.5%误差 | 工程台账的材料用量、签证金额允许合理的计量误差，符合行业通用标准 |
| 工作流超时时间 | 600 秒 | 单项目台账数据量较大，需预留足够的格式转换、数据合并与报告生成时间 |
| `nodeId`配置 | 使用24位十六进制字符的工作流节点ID | 需固定调用已验证的格式转换与汇总节点，避免节点配置变动影响汇总结果 |
| 报告模板绑定 | 绑定房建工程台账专用报告模板 | 确保生成的报告符合行业文档格式要求，包含所有必填字段 |

## 容易做错的三处
- 现象：调用工作流时返回「参数非法」错误，原因：未使用24位十六进制字符作为`nodeId`参数值，不符合FastGPT工作流节点ID的格式要求。
- 现象：代码节点执行时出现axioserror报错，原因：未配置正确的数据源接口访问密钥与地址，或接口响应时间超过预设阈值。
- 现象：本地部署的工作流配置界面在节点较多时出现输入卡顿，原因：未启用前端渲染优化，大量表单节点同时加载导致内存占用过高。

## 怎么确认配好了
- 手动触发配置完成的工作流，查看输出的台账汇总文件是否包含所有配置的必填字段。
- 传入测试用的项目编号，确认工作流仅匹配对应项目的数据源，未混入其他项目的数据。
- 查看工作流执行日志，确认所有节点均执行成功，无报错信息。
- 导出生成的报告，核对格式与字段是否符合房建工程台账报告的行业标准。
