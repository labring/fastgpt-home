# 政企信息化服务的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
政企信息化服务的台账数据主要来源于通信政企客户的运维工单、服务响应记录、资源使用报表等内部系统。数据更新节奏以每日同步为主，部分紧急工单支持实时更新。单份台账文档为结构化格式，包含工单编号、客户归属单位、故障类型、处理时长、办结状态等字段，字段单位涵盖小时、次、条等，部分字段存在多级分类嵌套。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
结构化的台账字段存在多级分类，多轮对话中需明确限定字段匹配规则，避免模型混淆不同层级的分类项。数据更新频率较高，多轮对话的上下文需限制有效时间范围，防止调用过时的台账数据。单份文档字段较多，提示词需明确指定仅提取对话指定的字段，避免冗余信息干扰报告生成。同时，政企台账涉及客户敏感信息，多轮对话中需过滤非必要的敏感字段，确保输出符合数据安全规范。

以下配置基于FastGPT v4.17.0版本适配。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 前8轮对话 + 最近7天台账数据 | 政企台账每日更新，限定时间范围避免调用过时数据，保留必要历史对话逻辑 |
| 单次召回条数 | 前5条匹配台账 | 台账字段层级复杂，限制召回条数避免冗余信息干扰模型字段匹配 |
| `messages` | 截断至12000 token | 结构化台账数据字段较多，过长的`messages`会分散模型注意力，影响报告生成精度 |
| `variables` | 开启 | 政企台账存在固定格式的字段变量，开启后可确保报告中字段值准确对应实际数据 |
| `chatId` | 绑定当前对话的唯一标识 | 确保多轮对话的上下文与指定台账数据集关联，避免跨对话数据混淆 |
| 问题优化 | 开启 | 多轮对话中用户可能重复提及台账字段，优化后可提炼核心查询需求，提升召回效率 |

## 容易做错的三处
- 现象：在线对话与API调用返回结果差异明显，API开启`stream`为false、`detail`为true时返回内容偏差较大。原因：在线对话默认保留完整上下文缓存，API调用未正确传递历史`messages`参数，导致模型无法关联已查询的台账数据。
- 现象：迁移知识库后，对话时提示知识库为空但页面可查看所有内容。原因：知识库迁移后未重新生成向量索引，或对话配置中未关联新的知识库ID，导致模型无法读取迁移后的数据集。
- 现象：工作流AI对话组件的回复注释触发时机不符合预期，提前或延迟触发。原因：未正确配置组件的触发逻辑，注释触发依赖于完整回复输出的信号，若组件绑定的变量未正确传递回复状态，会导致触发时机异常。

## 怎么确认配好了
- 发起包含指定台账字段的多轮对话，核对返回的报告中是否准确提取了对应字段的数值与单位。
- 切换在线对话与API调用模式，传入相同的`messages`参数与提示词，核对两次返回的报告内容是否一致。
- 迁移知识库后，重新生成向量索引并在对话配置中关联目标知识库，发起查询核对模型是否能召回对应台账数据。
- 测试工作流组件的注释触发时机，发送完整对话后观察注释是否在回复输出完毕后执行。
