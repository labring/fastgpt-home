# 政企信息化服务的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
政企信息化服务的台账数据来源于内部业务支撑系统、运维日志归档库与项目管理平台。数据更新节奏分为每日批量同步与实时接口推送两类，单份台账文档为结构化表格形式，包含台账唯一标识、所属主体、业务分类、发生时段、量化数值、经办信息等字段，量化数值的单位涵盖元、台、人次、工时等细分品类专属标识。

## 这些特征在「工作流编排」这一环带来什么约束
政企信息化服务的台账结构化特征与多来源更新节奏，为工作流编排带来多重约束。多字段多单位的台账数据，要求工作流需配置字段映射与单位标准化节点，确保后续汇总与报告生成的准确性。不同数据源的更新节奏差异，要求触发节点适配每日批量同步与实时接口推送两类触发条件。单份台账数据量跨度较大，需配置节点的单次处理上限，避免单次执行超时。同时，报告生成环节需匹配台账的业务分类，确保生成内容与对应字段的业务逻辑一致。

## 配置怎么定
本页面内容适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源节点 | 按台账来源配置2-3个数据源关联 | 政企台账多来自不同业务系统，多数据源关联可覆盖全量数据 |
| 知识库关联 | 绑定专属政企台账知识库，限定文件集合为近30天归档台账 | 避免检索无关数据，确保汇总数据的时效性 |
| 批量执行节点 | 设置单次处理100-200条台账数据 | 适配政企台账的批量处理需求，避免执行超时 |
| `variables` | 映射台账的核心字段（台账ID、业务类型、量化数值） | 确保大模型生成报告时可精准调用对应业务数据 |
| 温度参数 | 设置为0.1-0.3 | 台账报告需保持严谨性，较低温度可提升输出的一致性 |
| 超时配置 | 设置为600秒 | 适配政企台账批量处理的时长需求，避免执行中断 |

## 容易做错的三处
- 现象：通过API调用工作流时，批量执行节点仅完成部分台账的循环调用，在线调试可正常完成全流程。原因：API调用时未正确配置`variables`的分页参数，导致单次传入的台账数据量超出节点默认处理上限。
- 现象：知识库搜索节点返回的结果包含非指定文件集合的台账数据。原因：未在搜索配置中启用限定文件集合的选项，或所选文件集合未包含目标归档台账。
- 现象：AI对话节点切换为变量引用模式后，界面的温度设置按钮消失，无法直接调整生成参数。原因：变量引用模式需通过`variables`字段自定义温度参数，未配置该字段时界面控件会自动隐藏。

## 怎么确认配好了
- 触发工作流后，查看节点日志，确认数据源节点成功拉取对应业务系统的台账数据。
- 检查知识库搜索节点的返回结果，确认仅包含限定文件集合内的台账内容。
- 调用API测试工作流，确认批量执行节点完成全部预设台账的循环处理，无中途中断。
- 查看AI对话节点的输出结果，确认报告内容匹配台账的业务分类与字段信息。
