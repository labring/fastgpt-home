# 新能源开发的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
新能源开发的台账数据主要来源于项目立项文件、并网验收报告、日常运维日志、补贴申报材料等。数据更新节奏随项目阶段变化，建设期每周更新核心参数，运维期每日记录工况，竣工后每月汇总归档。单条文档包含项目编号、场址经纬度、装机容量（单位MW）、并网时间、运维周期、耗材更换记录等结构化字段，同时伴随非结构化的扫描件与现场照片，部分汇总报告类文档长度可达数千字符。

## 这些特征在「向量模型与索引」这一环带来什么约束
新能源开发的台账数据分散在结构化字段与非结构化资料中，要求索引系统同时支持字段级匹配与全文语义关联；不同阶段的数据更新频率差异大，需适配增量索引与全量重索引的灵活切换；装机容量、场址经纬度等字段存在明确业务权重，需避免低关联内容的误召回；单条文档长度差异显著，需避免因分块不合理破坏业务上下文的完整性。同时，多来源的异构数据需统一嵌入格式，确保向量空间的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配新能源台账的单条字段长度与关联内容总和，避免拆分破坏业务逻辑 |
| 重叠长度 | 100–150 字符 | 保留跨分块的运维周期、并网关联信息，避免上下文断裂 |
| 相似度阈值 | 0.72–0.85 | 区分新能源项目的装机容量、场址等核心匹配字段，降低误召回 |
| `defaultToken` | 4096 token | 适配汇总报告的上下文长度要求，覆盖多台账条目拼接后的内容量 |
| `maxToken` | 8192 token | 限制单次索引处理的最大内容，避免资源溢出 |
| 重排 | 按实测标定 | 适配新能源数据的字段权重，优化搜索结果排序逻辑 |

## 容易做错的三处
- 索引任务耗时过长：现象为调用知识库接口创建索引时，任务状态持续超过300秒未完成，原因是分块长度设置超出系统单次处理上限，导致单批次内容过多。
- 嵌入模型变更后旧数据失效：现象为已导入的知识库搜索结果为空或匹配度异常，原因是未对已导入的文档重新生成向量嵌入，仅更新了当前配置的嵌入模型。
- 搜索结果排序不符合业务逻辑：现象为低关联的场址模糊匹配结果排在高关联的装机容量精准匹配结果前，原因是未配置适配新能源核心字段的重排规则。

## 怎么确认配好了
- 上传单条新能源台账测试数据，查看分块预览界面是否完整保留项目编号、装机容量等核心业务字段。
- 切换嵌入模型后，执行批量索引任务，查看任务日志是否显示向量生成进度正常且无报错。
- 发起包含装机容量、场址经纬度的搜索请求，核对结果排序是否符合业务匹配优先级。
- 查看系统资源监控面板，确认单次索引处理的内容量未超出FastGPT v4.17.0的预设阈值。
