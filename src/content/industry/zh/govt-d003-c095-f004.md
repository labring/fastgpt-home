# 新能源开发的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
新能源开发的台账数据主要来源于项目管理系统、现场施工日志、设备监控平台、政府并网审批回执等多类渠道。数据更新节奏随项目阶段变化：立项筹备期按月更新，施工建设期按周更新，并网运营后按日更新。文档结构包含结构化台账表格与非结构化验收报告两类，核心字段包括项目编号、装机容量（单位MW）、并网时间、月度发电量（单位MWh）、设备运维时长（单位小时），部分台账还包含设备型号、供应商信息等专项字段。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流需适配不同格式的数据源拉取，避免出现数据格式不兼容的问题。差异化的更新节奏需要工作流支持按项目阶段配置拉取周期，无法使用统一的固定间隔。核心字段的专属单位要求工作流内置单位校验逻辑，防止出现MW与kW混用、发电量单位不统一的错误。跨台账的关联需求要求工作流必须包含按项目编号匹配设备、施工、发电等多类数据的环节，确保汇总数据的关联性准确。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源拉取周期 | 按项目阶段设置：立项期7天/次、施工期3天/次、运营期1天/次 | 匹配新能源开发台账的分阶段更新节奏 |
| 字段校验规则 | 校验装机容量单位为MW、发电量单位为MWh，过滤缺失项目编号的条目 | 匹配新能源行业台账的标准字段与单位要求 |
| 异常数据拦截阈值 | 过滤发电量低于0的记录、运维时长超过设备额定寿命的条目 | 避免无效数据进入后续汇总环节 |
| 关联匹配节点 | 按项目编号关联设备台账、施工日志与发电量数据 | 解决多源台账数据的关联性约束 |
| 变量配置 | `variables` 存储项目专属编号规则、统计周期参数 | 适配不同新能源项目的个性化配置需求 |
| 节点超时设置 | 600秒 | 应对多源数据拉取的网络延迟与数据量较大的场景 |

## 容易做错的三处
- 现象：工作流运行后生成的报告缺失核心字段，例如并网时间或装机容量。原因：未在`variables`中配置核心字段的映射规则，导致拉取数据时遗漏必填台账项。
- 现象：不同新能源项目的工作流运行结果格式不一致，部分字段缺失或单位混乱。原因：未使用`variables`配置项目专属的统计规则，通用配置无法适配不同项目的台账结构差异。
- 现象：工作流运行超时，界面显示节点执行失败。原因：未设置合理的节点超时时间，或拉取周期与数据源的实际更新节奏不匹配，导致数据拉取未完成。

## 怎么确认配好了
- 手动触发一次工作流，查看拉取的原始数据是否包含项目编号、装机容量等核心字段，且单位符合新能源行业的标准要求。
- 模拟输入一条异常数据，例如发电量为-100 MWh的记录，确认工作流是否自动拦截该条目并生成对应提示。
- 检查`variables`中存储的项目专属参数，例如统计周期、项目编号前缀，是否与当前项目的实际规则一致。
- 查看各节点的超时设置是否符合数据源的响应时长，避免运行时出现超时报错。
