# 新能源开发的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
新能源开发的台账数据主要来自风机、光伏电站的SCADA实时运行系统、月度运维巡检日志、并网验收纸质文档与电子档案。数据更新节奏分为实时（单台设备运行功率、发电量）、按天（运维时长、故障次数）、按项目周期（投资明细、并网日期）。单份台账文档包含设备编号、发电功率（单位kW）、运维时长（单位小时）、项目名称、投资金额（单位万元）等结构化字段，同时附带设备运行曲线、验收报告等非结构化附件。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的数据来源要求部署阶段需适配不同格式的数据源接入，因此需提前规划存储与索引策略。实时数据的高频更新要求部署时配置高并发的缓存与数据库连接池，避免因连接数不足导致服务卡顿。结构化字段的单位校验需求要求升级时需配置字段格式验证规则，防止错误数据流入台账库。合规性要求的纸质档案扫描件存储，需适配合规存储服务的接入配置，确保数据留存符合监管要求。本内容基于FastGPT v4.17.0版本适配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | 200–300 | 新能源开发台账数据量较大，需支持多并发的数据库读写请求 |
| `MONGODB_URI` | mongodb://ne_user:ne_pass@db-host:27017/ne_operation?authSource=admin | 存储实时运行数据与非结构化运维台账附件 |
| `PG_URL` | postgresql://ne_project:pg_pass@db-host:5432/ne_project | 存储结构化项目台账、并网验收与投资明细数据 |
| `REDIS_URL` | redis://:redis_pass@cache-host:6379/0 | 缓存高频查询的当日发电数据，降低主数据库的访问压力 |
| `STORAGE_S3_ENDPOINT` | https://s3-cn-north-1.example.com | 存储符合合规要求的纸质台账扫描件与报告模板 |
| `FE_DOMAIN` | https://ne-report.enterprise.com | 配置前端访问域名，用于生成报告下载的合法链接 |
| `ROOT_KEY` | 按企业内部安全规范生成的32位随机字符串 | 配置系统管理员初始访问权限与密钥关联规则 |

## 容易做错的三处
- 现象：启动容器后，平台模型列表为空，调用模型时返回404错误或密钥无效提示。原因：未将模型密钥正确关联到`ROOT_KEY`对应的权限配置，或未重启容器使修改后的配置生效。
- 现象：执行docker-compose up命令后，容器启动失败，日志显示数据库连接超时。原因：`DB_MAX_LINK`配置值过低，无法满足多设备台账数据的并发读写需求，或数据库连接字符串中的账号密码有误。
- 现象：生成的报告附件无法正常下载，点击后提示权限不足。原因：未正确配置`STORAGE_S3_ENDPOINT`对应的访问密钥，或`FE_DOMAIN`未加入存储服务的跨域访问白名单。

## 怎么确认配好了
- 执行docker ps命令，确认所有部署的容器均处于运行状态，无异常退出的条目。
- 访问配置的`FE_DOMAIN`对应的前端地址，登录系统后查看内置的数据库连接检测面板，确认`MONGODB_URI`、`PG_URL`与`REDIS_URL`的连接状态均为正常。
- 上传一份小型光伏项目的运维日志扫描件，通过系统生成的下载链接验证附件访问功能是否正常。
- 调用系统内置的模型测试接口，验证已配置的模型密钥是否能正常返回响应内容。
