# 核电运营的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
核电运营的台账数据主要来源于反应堆实时运行采集系统、设备巡检手持终端、辐射监测站、燃料管理系统四类数据源。核心台账分为实时参数台账、月度设备运维台账、辐射剂量台账三类，更新节奏分为实时、每日、每月三类。单条台账文档包含设备唯一标识、采集时间戳、数值字段、工况标签、异常标记字段，其中数值字段带有专属单位，如堆芯温度单位为开尔文、辐射剂量率单位为微希沃特每小时。

## 这些特征在「数据库与运维」这一环带来什么约束
实时参数的高频写入要求数据库连接具备低延迟与高并发能力，避免数据丢包或延迟。月度台账的批量导入会产生大体积数据事务，需数据库支持分片写入与事务回滚机制，防止单次写入超时。字段的专属单位要求数据库建立格式校验规则，避免不同单位的数值混存。核电数据的合规性要求所有数据库连接必须开启加密传输，同时留存完整的操作审计日志，满足核安全监管部门的数据留存要求。此外，台账数据的敏感性要求数据库具备细粒度的权限控制能力，限制非授权访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb+srv://<username>:<password>@<cluster-url>/nuclear_ops?ssl=true&authSource=admin` | 适配非结构化的巡检记录与辐射监测数据，开启SSL加密符合核电数据安全合规要求 |
| `PG_URL` | `postgresql://<username>:<password>@<database-host>:5432/nuclear_equipment?sslmode=require` | 存储结构化的设备台账与运行参数，强制SSL保障数据传输安全 |
| `DB_MAX_LINK` | `20–30 条连接` | 应对实时参数写入与月度批量台账导入的并发需求，避免连接池耗尽 |
| `REDIS_URL` | `redis://:<password>@<redis-host>:6379/0` | 缓存高频查询的设备工况标签，降低主数据库的负载压力 |

本配置基于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：调用FastGPT内置的数据库查询插件时返回400状态码，日志片段包含`Messages with role '`内容，原因是未正确配置数据库连接的身份验证参数，导致请求携带的角色信息不符合接口校验规则。
- 现象：本地部署FastGPT后调用数据库连接工具无任何输出，原因是`REDIS_URL`未配置或参数错误，导致缓存层无法正常工作，阻断了工具调用链路。
- 现象：并发执行台账汇总任务时出现连接超时，原因是`DB_MAX_LINK`设置值小于并发请求数，连接池耗尽后新请求无法获取可用连接。

## 怎么确认配好了
- 运行FastGPT v4.17.0内置的数据库连接测试工具，分别验证`MONGODB_URI`与`PG_URL`的连通性，确认返回测试成功提示。
- 提交一条模拟的核电设备巡检台账数据，写入对应数据库后执行精准查询，确认数据可正常读取且字段格式与单位符合预期。
- 发起25个并发的台账查询请求，确认无连接超时或报错，验证`DB_MAX_LINK`的配置适配并发需求。
- 查看Redis监控面板，确认高频查询的设备工况标签已被缓存，主数据库的查询负载出现明显降低。
