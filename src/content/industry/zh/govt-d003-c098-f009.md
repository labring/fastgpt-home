# 民航机场的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
民航机场的台账数据来源为运行管理系统、航班调度系统、地勤保障系统、安检统计系统等内部业务系统。核心保障台账按小时刷新，日汇总运行台账每日凌晨更新。文档以结构化表格形式存在，单文件对应单日运行数据，字段包含航班号、起降时间、保障节点、地勤班组、行李吞吐量、安检人次，对应单位分别为无、时分、无、无、千克、人次，无嵌套层级。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源结构化台账的字段存在跨系统同名差异，需在配置阶段明确字段映射规则，避免模型识别错误。单日汇总台账数据量较大，需调整上下文相关参数适配全量数据读取。实时更新的保障台账需确保模型调用时拉取最新数据，需配置合理的数据源拉取周期。字段包含民航专用单位，需在模型提示词中明确单位要求，避免生成报告时出现单位错误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxTokens` | 8000–12000 token | 适配单日全量台账数据的文本长度，避免关键信息被截断 |
| `temperature` | 0.1–0.3 | 保障台账报告的严谨性，降低生成内容的随机性 |
| `AIPROXY_API_ENDPOINT` | 机场内网代理地址 | 隔离外部模型调用与内部数据源，保障数据访问安全 |
| `AIPROXY_API_TOKEN` | 绑定内网权限的专属令牌 | 限制仅授权内部系统可发起模型调用请求 |
| `quoteMaxToken` | 2000–3000 token | 保留核心台账字段的完整上下文，确保报告引用数据准确 |
| `maxContext` | 按实测标定 | 适配多源台账数据的总长度，避免上下文溢出 |

## 容易做错的三处
- 现象：模型调用返回完整的思考过程文本，与预期的纯报告结果不符。原因：未在模型配置中关闭中间思考输出，或提示词未明确要求仅返回最终报告内容。
- 现象：无法通过aiproxy对接模型渠道，提示连接失败。原因：未正确配置`AIPROXY_API_ENDPOINT`为机场内网可访问的地址，或未授权内网访问代理服务。
- 现象：生成的台账报告缺少部分核心字段数据。原因：`maxTokens`取值过小，导致部分台账条目被截断，无法完整传入模型。

## 怎么确认配好了
- 发起单次单日台账的报告生成请求，检查返回结果是否包含所有预设的台账字段，且单位符合要求。
- 查看模型渠道的调用日志，确认`AIPROXY_API_TOKEN`的验证请求通过，无403类报错。
- 调整`maxTokens`取值后，对比不同配置下的返回结果长度，确认无关键数据被截断。
- 测试多源台账数据的接入，确认模型能正确映射跨系统的同名字段，无识别混乱。
