# 油气勘探开发的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
油气勘探开发的台账数据来源于钻井现场日志、测井扫描件、试油分析报告、储量测算文档等一手资料。数据更新节奏随勘探环节调整，钻井阶段按作业班次更新，试油与储量评估环节按单井或区块批次更新。单份文档包含井号、作业深度、岩性描述、孔隙度、渗透率等固定字段，单位涵盖米、毫达西、立方米等专业计量标准，文档长度跨度大，短则数百字符的现场记录，长则数万字符的综合评估报告。

## 这些特征在「向量模型与索引」这一环带来什么约束
文档长度跨度大的特征，要求向量编码与分块策略适配从短记录到长报告的不同文本体量，避免短文本编码冗余或长文本语义割裂。专业字段的固定单位与术语，要求向量模型具备油气勘探领域的语义对齐能力，确保井号、渗透率、孔隙度等专业表述的向量映射符合领域共识。差异化的更新节奏，要求索引支持按作业班次、区块批次的增量刷新，降低全量重建的资源消耗。结构化字段与非结构化文本并存的数据源，要求索引同时兼容结构化属性匹配与非结构化向量检索的混合查询逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配油气勘探台账从短记录到长报告的文本跨度，保证语义完整 |
| 重叠长度 | 100–150 字符 | 避免分块截断专业术语，维持跨分块的上下文关联 |
| 相似度阈值 | 0.72–0.80 | 匹配领域专业语义的相似度区间，过滤无关勘探数据 |
| 单次搜索上限 | 前 8 条 | 平衡检索精度与响应速度，适配多字段关联的台账查询 |
| `maxToken` | 8000 | 适配长文档的向量编码与上下文拼接，符合FastGPT v4.17.0的参数上限 |
| `defaultToken` | 1024 | 控制单轮报告生成的内容长度，符合台账汇总的输出边界 |

## 容易做错的三处
- 检索结果未返回关联文档的井号、报告名称等溯源信息，原因是未开启向量索引与结构化元数据的绑定配置，仅存储了文本向量未关联原始文档字段。
- 向量检索结果与专业术语语义不匹配，原因是使用了通用领域的向量模型，未针对油气勘探专业术语进行适配，导致专业表述的向量映射出现偏差。
- 长评估报告的向量编码被截断，生成的汇总报告缺失后半部分内容，原因是分块长度设置过小或`maxToken`参数取值不足，导致长文本的语义信息未被完整编码。

## 怎么确认配好了
- 上传单份短台账记录与长评估报告，检查分块后的文本块数量是否符合预期，确认分块长度与重叠长度的配置生效。
- 输入专业查询词，比如“某井的孔隙度数据”，检查检索结果的相似度评分是否落在预设区间内，确认相似度阈值的配置合理。
- 发起批量增量索引任务，检查索引刷新的速度与资源占用是否符合作业节奏，确认增量刷新策略的配置正确。
- 查看检索结果的元数据字段，确认井号、报告名称等溯源信息是否随向量结果一并返回，确认结构化元数据绑定配置生效。
