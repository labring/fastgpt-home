# 油气勘探开发的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
油气勘探开发的台账数据来自钻井作业记录、测井分析报告、试油测试文档、储量计算表单等多类业务产出。更新节奏按单井项目节点触发，完井阶段批量更新，日常按周增量同步单井动态。单份台账文档包含井号、井深、层位、岩性、孔隙度、渗透率等专业字段，单位分别为米、%、%、毫达西，部分文档附带扫描件附件。数据格式涵盖结构化表格与非结构化文本两类，单文档长度差异较大。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构的数据来源要求数据库同时支持结构化数据存储与非结构化文档索引，增加运维复杂度。按项目节点的批量更新与日常增量同步并存，需要数据库连接池能够应对突发的高并发写入请求，避免连接耗尽。专业字段的精准查询需求，要求为孔隙度、渗透率等核心字段创建专属索引，否则全表扫描会大幅降低查询效率。长文档的存储与检索，需要数据库适配大字段存储，避免数据截断或检索异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[username:password@]host1:port1,host2:port2/[authSource=admin]` | 支持油气勘探开发多源结构化台账的分布式存储，适配批量数据导入 |
| `PG_URL` | `postgresql://user:pass@host:port/dbname?sslmode=require` | 存储非结构化文档的元数据与专业字段索引，保障精准查询 |
| `DB_MAX_LINK` | `200–300` | 应对完井阶段的批量数据导入峰值，避免连接耗尽 |
| `REDIS_URL` | `redis://:password@host:port/0` | 缓存高频查询的专业字段统计结果与会话上下文，降低数据库负载 |
| 问题优化 | 开启，按实测标定轮次 | 适配长台账文档的上下文关联，避免连续提问时答非所问 |
| 最大上下文 | 按单台账文档长度的2倍设置 | 覆盖完整的业务上下文，保障多轮提问的语义连贯性 |

## 容易做错的三处
- 现象：连续发起多轮提问后，后续问题无法关联上下文，出现答非所问。原因：未配置`REDIS_URL`缓存会话数据，或`DB_MAX_LINK`设置过低导致会话数据被提前清除。
- 现象：批量导入单井台账数据时，数据库返回连接超时错误（状态码504）。原因：`DB_MAX_LINK`设置数值小于并发导入的连接请求数，连接池无法分配足够资源。
- 现象：针对专业字段的查询耗时过长，界面显示加载超时。原因：未为孔隙度、渗透率等核心字段创建索引，数据库执行全表扫描操作。

## 怎么确认配好了
- 登录FastGPT v4.17.0后台的数据库管理页面，查看`MONGODB_URI`、`PG_URL`的连接状态，确认显示正常。
- 模拟单井台账的批量导入操作，观察数据库连接数变化，确认未触发连接耗尽告警。
- 发起包含专业字段的查询，查看响应时长，确认符合业务预期。
- 发起连续多轮提问，确认上下文被正确关联，无答非所问情况。
