# 油气勘探开发的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
油气勘探开发的台账数据来源包括单井勘探作业记录、测井曲线报告、试油分析文档、开发动态月报等。更新节奏随作业节点变动，单井完钻后立即更新对应台账，月度汇总类台账按自然月更新。文档结构以结构化字段为主，包含井号、井深、渗透率、孔隙度等核心指标，附带非结构化的扫描版报告、原始测井数据文件。字段单位涵盖米、毫达西、立方厘米每秒、兆帕等专业勘探单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化字段多且单位专业，要求检索需支持字段精准匹配与单位校验，避免召回单位不符的无效数据。非结构化文档篇幅较长，需合理控制分块长度以保留上下文语义。更新节奏不固定，需支持增量式知识库同步，避免全量重复导入。多源异构数据并存，需明确召回范围，防止跨品类文档被误召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.88 | 油气勘探台账的结构化字段语义相似度要求较高，该区间可过滤低相关性结果，同时保留精准匹配的有效数据 |
| `limit` | 前8–12条 | 单份台账报告内容较多，少量召回结果即可满足台账汇总与报告生成的上下文需求，避免超出上下文窗口限制 |
| `usingReRank` | 开启 | 非结构化测井报告的语义相似度区分度较低，重排可优化结果排序逻辑，提升核心文档的召回优先级 |
| `searchMode` | hybrid | 兼顾结构化字段的精准匹配与非结构化文档的语义检索，适配多源异构的台账数据特征 |
| `datasetSearchUsingExtensionQuery` | 开启 | 勘探开发术语多为专业缩写，扩展查询可补充同义词与相关术语，提升检索召回的覆盖度 |
| `collectionIds` | 填写指定油气勘探开发台账集合ID | 明确召回范围，防止其他品类的文档被误纳入检索结果 |

## 容易做错的三处
- 检索结果包含非油气勘探开发的台账文档，结果条数超出预期。原因是未配置`collectionIds`，导致检索范围覆盖全知识库。
- 线上环境导入的勘探报告出现乱码，本地部署导入则正常。原因是线上服务器的文件编码未设置为UTF-8，未处理测井报告中的希腊字母、专业符号等非通用字符。
- 无法检索到指定井号的台账数据。原因是`similarity`阈值设置过高，导致结构化字段的语义匹配无法通过，或未开启针对结构化字段的精准检索模式。

## 怎么确认配好了
- 登录FastGPT v4.17.0的知识库管理界面，查看已关联的集合列表，确认`collectionIds`对应的油气勘探开发台账集合已正确选中。
- 发起单井号的测试查询，核对返回结果的文档均属于油气勘探开发范畴，无跨品类文档混入。
- 调整`similarity`参数值，验证检索结果的相关性随参数变化符合预期，无明显误召回或漏召回情况。
- 开启`usingReRank`后，查看重排后的结果排序，确认核心相关文档的优先级得到提升。
