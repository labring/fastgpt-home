# 油田工程服务的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
油田工程服务的台账数据主要来源于现场施工日志、设备巡检记录、材料领用单据、工序验收报告四类核心文档。数据更新节奏随施工节点推进，单次作业完成后即时录入，每日汇总生成项目级台账。单份台账文档包含施工编号、设备型号、作业时长、材料用量、验收结果等字段，单位涵盖小时、立方米、吨、合格/不合格等，字段随作业类型动态调整，无统一固定模板。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
油田工程台账的多字段与动态格式要求多轮对话必须锁定当前作业项目的上下文，避免跨批次数据混淆。高频更新的实时数据要求对话上下文需及时同步最新录入的台账内容，避免引用过时信息。不同作业类型的字段差异要求提示词需明确指定当前对话关联的作业环节，否则易出现字段匹配错误。长文档的拆分与召回需保留字段关联，否则会丢失设备型号与对应巡检记录的绑定关系。多轮对话的`messages`数组需按顺序存储每一轮的提问与回复，确保上下文传递的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 单份项目级台账可达数千字符，需保留多轮对话的作业批次与设备信息 |
| 变量预设 | 绑定施工项目ID、作业类型变量 | 区分不同项目的台账数据，避免跨项目数据干扰 |
| 问题优化开关 | 开启 | 油田台账字段复杂，优化提问可明确指向所需的具体字段与文档类型 |
| 单次对话召回条数 | 前6条 | 匹配同项目下的最新台账记录，控制上下文冗余度 |
| 知识库分块重叠长度 | 200–300 字符 | 拆分长台账文档时保留设备型号与巡检记录的关联信息，避免字段断裂 |
| 单次对话超时设置 | 300 秒 | 避免长台账汇总与报告生成时会话中断 |

## 容易做错的三处
- 对话返回401 No auth credentials found错误。原因是未在`variables`中传入项目专属的授权标识，导致知识库访问权限校验失败。
- 生成的报告混入其他施工项目的台账数据。原因是未预设施工项目ID变量，多轮对话未锁定当前会话关联的作业批次。
- 生成的报告缺失关键字段如作业时长或材料用量。原因是未开启问题优化开关，用户提问未明确指定所需的台账字段，导致系统召回的文档未覆盖目标字段。

## 怎么确认配好了
- 发起包含指定施工项目ID的提问，检查对话上下文是否始终关联该项目的台账数据。
- 触发多轮追问，确认系统能正确跟踪上一轮提到的设备型号与作业时长字段。
- 通过`chatId`锁定当前会话的专属上下文，验证会话内的提问与回复关联逻辑正常。
- 查看配置界面的变量预设项，确认已绑定油田工程服务专用的项目标识变量。
- 测试长文档拆分后的召回，确认关键字段未被截断或丢失关联关系。
