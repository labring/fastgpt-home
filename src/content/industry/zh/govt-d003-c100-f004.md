# 油田工程服务的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
油田工程服务的数据主要来自现场施工终端、井场传感器、项目ERP系统，覆盖钻井、固井、压裂等工序的日常台账。数据更新节奏从实时上报的施工参数到每日汇总的班组台账不等。单条台账文档包含井号、施工工序、作业时间、班组信息、材料消耗量、作业压力值等字段，其中材料用量以吨、立方米为单位，施工时长以小时为单位，汇总报告则按月度、季度整合多工序台账数据，形成结构化报表文件。

## 这些特征在「工作流编排」这一环带来什么约束
油田工程服务的多源异构数据特征，要求工作流编排支持多节点并行拉取不同数据源的台账数据，避免串行拉取导致的流程延迟。字段单位不统一的情况，要求工作流内置标准化转换环节，将不同来源的材料用量、时长数据统一为预设单位。实时施工参数的高频更新，要求工作流支持定时触发与事件触发两种模式，匹配不同台账的更新节奏。汇总报告的文件体积通常较大，要求工作流节点支持分块处理与大文件传输配置，避免传输超时或解析失败。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配油田工程服务台账汇总与报告生成的工作流编排需求。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 包含井号、作业周期两个核心变量 | 油田工程服务台账以井号和作业周期为核心筛选条件，可在工作流启动时动态传入 |
| 触发方式 | 定时触发+事件触发双模式，定时触发设为每24小时 | 匹配实时施工参数与每日汇总台账的不同更新节奏，覆盖全量与增量数据的拉取需求 |
| 文件上传节点大小限制 | 1000 MB | 油田工程服务的月度汇总报告通常体积较大，预留足够空间避免传输中断 |
| 参数标准化规则 | 按实测标定的单位映射规则 | 适配不同来源数据的吨、立方米、小时等单位差异，确保汇总数据的一致性 |
| `nodeId` | 为每个数据源节点分配唯一标识 | 便于工作流调试时定位异常节点，快速排查多源数据拉取的问题 |
| 请求重试次数 | 3次 | 应对现场网络波动导致的传感器数据拉取失败，避免单次请求异常中断流程 |

## 容易做错的三处
- 现象：工作流HTTP请求节点配置form-data类型参数时，无法成功发送现场采集的施工台账文件。原因：未将对应参数的类型设置为文件流格式，仅传入了本地文件路径。
- 现象：工作流执行文件汇总环节时，界面弹出Load file error报错。原因：传入的台账文件格式不符合结构化要求，或文件在跨节点传输过程中出现损坏。
- 现象：本地部署环境中，上传月度汇总台账文件后，文件解析节点无执行记录。原因：部署环境的文件存储目录权限配置不足，导致节点无法读取上传的文件，或解析节点的触发规则未绑定对应文件上传事件。

## 怎么确认配好了
- 手动传入预设的井号和作业周期变量，检查各数据源节点是否能正确拉取对应台账数据。
- 触发工作流执行，查看各节点的运行日志，确认文件传输、参数标准化环节无异常报错。
- 对比工作流输出的汇总报告与原始台账数据，确认字段单位、数据条目均符合预期。
- 模拟现场传感器上报事件，检查事件触发模式下的工作流是否能自动启动并拉取实时数据。
