# 港口航运的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
港口航运台账数据来源于港口生产调度系统、船舶代理系统、海关通关系统及港作作业记录。更新节奏分为三类：船舶靠泊台账实时更新，装卸作业台账按单批次作业完成更新，堆场统计台账每日汇总更新。文档以结构化表格或数据库表形式存在，核心字段包括船舶识别号、泊位编号、作业箱量（单位TEU）、作业起止时间、堆场箱区号、拖轮作业时长（单位小时）、货物品类代码，部分配套扫描件为纸质作业确认单。

## 这些特征在「向量模型与索引」这一环带来什么约束
港口航运台账的多源更新节奏要求索引支持增量更新与全量更新并行，避免高频实时数据与低频汇总数据的索引冲突。结构化字段多且带明确业务单位，向量模型需适配混合类型数据的向量化转换，避免数值单位干扰业务语义关联。单条台账条目长度较短但总数据量较大，索引分片需适配高频写入与批量检索的平衡，同时需保留船舶编号、作业时间等核心业务字段的关联索引，确保检索时可按业务维度快速过滤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配港口台账单条作业记录的典型长度，避免拆分核心业务字段 |
| 重叠长度 | 100–180 字符 | 保留相邻分块的关联业务信息，确保检索时完整匹配作业链路 |
| 相似度阈值 | 0.72–0.82 | 过滤低相关性条目，提升汇总报告的精准度 |
| 单次搜索上限 | 前 15 条 | 平衡检索性能与台账汇总的覆盖范围 |
| `defaultToken` | 3584 token | 适配单批次台账检索的上下文长度，符合FastGPT v4.17.0的上下文长度限制 |
| `maxToken` | 7168 token | 支持生成包含多时段台账汇总的完整报告 |

## 容易做错的三处
- 现象为索引任务长时间停留在「待处理」或「处理中」状态，无进度日志输出。原因是未针对港口台账的分批次更新配置增量索引规则，全量索引扫描全量历史数据导致耗时过长。
- 现象为检索结果出现语义偏差，无法匹配同船舶、同泊位的关联台账条目。原因是未使用阿里通义千问emb3模型进行数据向量化，通用向量化模型无法适配港口业务字段的语义特征。
- 现象为生成的汇总报告包含大量无关作业记录，结果条数远超预期。原因是未启用检索结果的重排过滤，或未设置合理的相似度阈值，导致低关联条目被纳入汇总范围。

## 怎么确认配好了
- 查看索引任务的进度日志，确认增量索引仅处理更新时间晚于上次索引的台账数据，无全量重复扫描的记录。
- 测试包含船舶编号、作业时间的查询语句，确认返回结果均为对应业务范围内的台账条目。
- 检查向量模型配置项，确认已指定适配港口业务的向量化引擎，无错误配置的模型参数。
- 验证单次搜索上限的配置，确认检索返回的条目数量符合预设的业务覆盖范围要求。
