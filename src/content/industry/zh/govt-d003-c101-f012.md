# 港口航运的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
港口航运的台账汇总与报告生成所涉及的数据，主要来源为港口作业管理系统、船舶调度平台、海关申报端口三类系统。数据更新节奏按单次航次或每日固定时段触发，单次航次的台账包含船舶靠泊、装卸货、集装箱调度等全流程记录。文档结构以结构化字段为主，包含船名、IMO编号、装卸货量、靠泊时间、泊位编号、标准箱（TEU）数等专用字段，部分伴随半结构化的作业照片、调度指令附件。

## 这些特征在「部署与升级」这一环带来什么约束
港口航运台账数据的多源接入、高频更新与专用字段特征，对部署与升级环节带来多重约束。多源异构数据需要配置多存储连接适配不同系统的接口格式，部署时需提前规划数据源的访问权限。高频更新的作业数据要求数据库连接池配置适配高并发场景，升级时需保留原有连接参数的兼容性。专用字段的元数据需要在知识库解析环节保留，升级知识库插件时需确保字段映射规则不被覆盖。此外，港口数据的合规性要求，部署时需配置本地合规存储介质，避免数据跨区域传输风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://port_admin:secure_pass@internal-mongo:27017/port_ledger?authSource=admin` | 港口台账数据多为半结构化作业记录，MongoDB适配非固定字段的存储需求 |
| `DB_MAX_LINK` | `200–300` | 港口数据更新频率高，并发连接需求高于通用场景，按实测标定 |
| `STORAGE_S3_ENDPOINT` | `http://internal-s3.port.com:9000` | 港口作业数据需存储在本地合规存储介质，避免跨区域传输风险 |
| `REDIS_URL` | `redis://:redis_pass@internal-redis:6379/0` | 高频更新的台账缓存需要低延迟的键值存储，适配实时汇总需求 |
| `FILE_TOKEN_KEY` | `随机生成的32位加密字符串` | 港口作业文件需防止未授权访问，保障敏感作业数据的安全 |

## 容易做错的三处
- 现象：Docker部署FastGPT v4.17.0后，解析港口集装箱台账文件时，日志持续报`slow operation xxxxms`，MongoDB本身响应延迟升高。原因：未调整`DB_MAX_LINK`参数，并发连接数不足以支撑高频作业数据的写入请求。
- 现象：在知识库管理界面配置数据源时，无法拉取海关申报的台账数据。原因：未正确设置`STORAGE_S3_ENDPOINT`指向港口内部合规存储，导致跨系统数据拉取被安全策略拦截。
- 现象：更新船舶靠泊台账后，生成的汇总报告未显示最新作业数据。原因：未适配港口数据的更新频率调整缓存逻辑，导致旧缓存未及时失效，报告读取的仍是缓存中的历史数据。

## 怎么确认配好了
- 执行`docker logs fastgpt`命令，检查是否存在数据库连接超时或存储服务报错的日志。
- 上传一份港口集装箱台账的CSV文件，确认解析后字段完整包含船名、装卸货量、TEU数等专用字段。
- 触发一次台账汇总任务，等待任务完成后检查生成的报告是否包含最新的作业数据。
- 访问`FE_DOMAIN`配置的域名，确认知识库管理界面可以正常加载并关联已配置的数据源。
