# 炼化生产的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
炼化生产的台账数据来源为分布式控制系统（DCS）、罐区计量系统、化验室信息管理系统（LIMS）。更新节奏分为单参数实时推送与批次数据每小时同步两种。单条台账文档结构包含装置编码、物料名称、操作参数（流量、温度、压力）、化验指标、班次标识、生成时间。字段单位包含m³/h、℃、MPa、t等，无嵌套复杂层级，单条数据长度多在200-500字符区间。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
实时参数推送的需求要求接口支持短连接高频调用，避免数据延迟。批次数据每小时同步的需求要求接口支持批量数据接收与分页返回，防止单次传输过载。结构化的固定字段要求接口请求体需严格匹配预设字段，避免字段缺失导致解析失败。统一的单位标识要求接口在接收或返回数据时需携带单位信息，防止跨系统单位转换错误。多装置台账汇总的场景要求接口支持按装置编码、班次等维度筛选数据，提升汇总效率。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 请求超时设置 | 600 秒 | 匹配炼化台账数据同步的平均响应耗时，避免因网络波动导致请求中断 |
| 请求头配置 | Bearer ${token} | 符合FastGPT API的认证规范，确保接口调用权限合法 |
| 全局变量映射 | { "deviceId": "${vars.device}", "shift": "${vars.shift}" } | 匹配炼化台账的装置编码与班次字段，实现参数动态绑定 |
| 响应数据解析规则 | 提取根节点下的data数组 | 适配炼化台账接口的标准返回结构，快速定位有效数据 |
| 批量请求上限 | 100 条/次 | 平衡数据传输效率与接口负载，防止单次提交数据量过大 |
| 字段校验开关 | 开启 | 确保接收的台账数据字段完整匹配预设结构，减少后续汇总错误 |

## 容易做错的三处
- 现象：调用接口后返回结果为结构化JSON格式。原因：未在响应配置中指定文本提取规则，直接返回了原始接口的结构化数据。
- 现象：台账汇总后部分装置的参数字段为空。原因：未在请求变量中配置对应装置的编码参数，导致接口无法匹配到对应数据。
- 现象：通过OpenAPI接口创建的QA拆分文件集合，索引耗时过长。原因：未配置批量请求上限，单次提交的文档数量超出接口处理能力。

## 怎么确认配好了
- 发起单次台账数据同步请求，检查接口返回的响应状态码为200。
- 查看FastGPT的知识库索引日志，确认已创建的QA拆分文件集合正在按预期进度生成索引。
- 调用汇总接口，检查返回的台账数据字段与源系统的字段结构一致。
- 模拟多装置并发请求，确认接口未出现超时错误。
