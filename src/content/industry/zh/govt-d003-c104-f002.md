# 煤化工的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
煤化工台账数据主要来自生产过程控制系统（DCS）、制造执行系统（MES）、现场巡检终端、环保监测上报系统。数据更新节奏覆盖多个维度：设备运行参数每15分钟更新一次，班组物料消耗台账每班更新，月度生产汇总报告每日生成后归档。单条台账文档包含设备编号、巡检时间、参数数值、操作人员、异常标记等字段，参数单位统一为℃、MPa、吨等标准工业单位，单条短文本记录约50-200字符，月度汇总报告可达3000-5000字符。

## 这些特征在「向量模型与索引」这一环带来什么约束
煤化工台账的多更新频率与数据结构对向量索引环节带来多重约束。高频实时参数数据要求索引支持增量更新，避免全量重建占用过多资源；多长度文档（短巡检记录与长汇总报告）要求分块策略具备灵活性，同时保证上下文完整性；字段包含结构化数值与文本描述，需将数值参数转换为带单位的文本片段后再向量化，确保语义匹配准确性；月度汇总报告的批量归档要求索引支持批量快速重建，适配周期性数据汇总需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配煤化工台账中长文本汇总报告与短巡检记录的混合长度，避免分块过碎导致语义断裂或过长超出模型限制 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的上下文关联，确保巡检记录的连续描述不会被分块截断 |
| `defaultToken` | 8192 | 匹配主流大语言模型的默认上下文窗口，承载煤化工台账汇总时的多段分块内容 |
| `maxToken` | 16384 | 支持月度汇总报告的完整向量化与后续报告生成环节的上下文需求 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关台账数据，聚焦煤化工生产相关的有效记录 |
| 单次搜索上限 | 前20条 | 覆盖班组级生产台账的数量范围，避免返回过多冗余数据影响报告生成效率 |

## 容易做错的三处
- 调用知识库接口生成索引时速度过慢，现象为接口返回504超时状态码或索引任务队列堆积超过2小时。原因是未针对煤化工台账的高频更新开启增量索引配置，每次生成索引都执行全量数据扫描。
- 更换embedding模型后，已导入的QA拆分文件集合无法快速重建索引，现象为界面提示“索引模型不匹配”且无批量重建选项。原因是创建文件集合时未开启“保留原始文本”开关，导致无法直接基于原始数据重新生成向量。
- QA拆分的台账搜索结果条数不符合预期，现象为返回结果远少于配置的单次搜索上限。原因是未将煤化工台账中的数值参数转换为带单位的文本片段，向量模型无法正确识别语义关联的查询内容。

## 怎么确认配好了
- 查看索引任务日志，确认增量更新仅处理了新增或修改的台账数据，未重复扫描历史全量数据。
- 发起一次测试查询，输入包含煤化工生产场景的关键词，核对返回结果的分块长度与配置的分块长度一致。
- 更换embedding模型后，执行批量重建索引操作，确认无需重新上传原始台账文件即可完成向量更新。
- 检查FastGPT v4.17.0的向量库监控面板，确认索引的查询延迟符合生产场景的响应要求。
