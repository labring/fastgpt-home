# 煤化工的台账汇总与报告生成：数据库与运维
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
煤化工的台账与生产数据来源覆盖三类系统：生产装置的分布式控制系统（DCS）、煤质化验室的检测设备、仓储与安全巡检系统。更新节奏分为三类：实时生产参数每秒更新，煤质检测数据每班生成批次数据，台账汇总数据每日完成统计。单条数据结构包含设备唯一标识、采集时间、物理参数、检测人员标识、异常状态标记，物理参数字段涵盖温度、压力、灰分等，分别对应摄氏度、兆帕、质量分数单位。

## 这些特征在「数据库与运维」这一环带来什么约束
实时参数的秒级高频写入要求数据库连接池支持高并发连接，避免连接耗尽；批次检测数据的批量提交需要调整事务提交阈值，防止单次事务过大导致超时；每日台账汇总的大查询需要在设备标识、采集时间字段建立联合索引，缩短查询耗时；多类型数据的混合存储需要区分冷热数据，将实时参数存入时序存储，历史台账存入关系型数据库；异常状态标记的快速筛选需要为对应字段建立索引，提升报告生成的筛选效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 200–300 个连接 | 适配煤化工实时数据的高频并发写入，避免连接池耗尽 |
| `PG_URL` | postgresql://[账号]:[密码]@[数据库地址]:5432/coal_chemical_report | 存储结构化台账与汇总报告数据，支持复杂关联查询 |
| `REDIS_URL` | redis://[账号]:[密码]@[缓存地址]:6379/0 | 缓存高频查询的台账汇总结果，降低数据库负载 |
| `MONGODB_URI` | mongodb://[账号]:[密码]@[实时数据地址]:27017/coal_real_time?authSource=admin | 存储秒级更新的生产实时参数，支持高并发写入 |

## 容易做错的三处
- 现象：每秒2-3次调用工作流时，数据库查询结果返回为空。原因：`DB_MAX_LINK`配置值过低，连接池被并发请求耗尽，无法处理后续连接请求。
- 现象：从数据库节点获取的查询结果格式不符合台账字段要求，需额外编写代码转换。原因：未开启数据库节点的结果格式化开关，默认返回的原始数据结构未对齐预设的台账字段命名规则。
- 现象：批量插入台账数据时出现部分记录丢失。原因：未设置合理的批量提交阈值，单次提交数据量过大导致数据库事务超时，部分数据未完成写入。

## 怎么确认配好了
- 运行单次台账汇总任务，核对数据库连接日志中的活跃连接数，根据日志表现调整`DB_MAX_LINK`的配置值。
- 调用数据库节点查询历史生产参数，确认返回的字段与煤化工设备的采集字段完全匹配。
- 发起批量数据插入请求，检查数据库事务提交是否正常，无数据丢失或报错提示。
- 查看缓存服务的监控数据，确认高频汇总的台账结果已被正确缓存，减少重复数据库查询。
