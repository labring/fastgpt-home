# 煤炭运销的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
煤炭运销的台账数据主要来源于煤矿过磅单、公路/铁路运单、购销合同、月度结算报表四类。数据更新节奏分为每日（过磅单、实时运单）、每周（结算明细台账）、每月（全量汇总报表）。单份文档多为结构化表格形式，包含矿点编码、车皮/车牌号码、装运吨位、运输里程、收货单位、结算单价、运费金额等字段，单位涵盖吨、元、车次、公里等，部分单据存在扫描件格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
多格式混合的单据来源要求索引环节适配扫描件OCR、Excel结构化提取与PDF文本解析的组合能力。每日批量生成的过磅单与运单，会带来高频次的索引写入请求，需要限制单批次处理的文档数量，避免索引节点负载过高。字段中包含大量带单位的数值类信息，要求向量模型能够准确编码此类带单位的结构化文本，防止相似语义的不同单位字段被误判为关联。月度汇总报表的长文本结构，要求索引分块策略适配表格类长文本的完整性保留。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配煤炭运销单据的结构化表格行长度，避免截断关键数值与关联字段 |
| 重叠长度 | 100–150 字符 | 覆盖跨分块的表头与数据关联，防止分块后丢失上下文关联 |
| 相似度阈值 | 0.72–0.78 | 匹配煤炭运销单据的语义分布，区分同矿点不同批次的运单，避免误匹配 |
| 单次搜索上限 | 前 8 条 | 平衡月度汇总报告的召回精度与响应速度，覆盖常用关联单据数量 |
| `defaultToken` | 4096 token | 适配单份结算报表的文本长度，保证完整加载汇总数据 |
| `maxToken` | 8192 token | 覆盖台账汇总与报告生成的全量上下文需求，避免截断关键合计信息 |

## 容易做错的三处
- 尝试在同一知识库中混用不同的向量模型，导致召回结果出现语义偏移。原因：煤炭运销单据中的带单位数值字段，不同模型的编码逻辑存在差异，混用会破坏语义一致性。
- 直接接入graphRAG工具进行索引构建，导致结构化字段的关联关系被错误拆解。原因：FastGPT的索引默认针对扁平化实体设计，未适配graphRAG的关系型索引逻辑，直接接入会丢失台账的结构化关联。
- 开启自动生成补充索引后，扫描件单据的OCR结果出现大量乱码，导致索引召回失败。原因：未配置适配煤炭运销单据的OCR参数，扫描件中的磅秤数字、车皮编号等关键信息无法被准确识别。

## 怎么确认配好了
- 上传单份过磅单文档，查看索引生成后的分块内容，确认分块长度与重叠长度符合预设配置，未截断关键字段。
- 输入包含矿点名称与吨位的查询语句，核对召回结果的相似度分值，确认阈值调整后未出现误匹配或漏匹配。
- 批量上传3-5份不同日期的运单与月度报表，查看索引生成的状态日志，确认单批次处理量未触发节点负载告警。
- 调用台账汇总与报告生成的接口，查看返回的上下文长度，确认`maxToken`配置可覆盖全量关联文档的文本内容。
