# 煤炭运销的台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
煤炭运销的台账数据主要来自过磅单、煤质检测报告、购销合同、结算单等文档，更新节奏按单日车次、周度汇总、月度结算推进。文档格式包含电子签章PDF、扫描件PDF与系统导出的CSV表格，结构以固定表头的结构化表格为主，附带少量说明性文本。核心字段包含车号、毛重、皮重、净重（单位均为吨）、煤种、热值（单位为大卡/千克）、运输单位与购销方信息，部分文档还包含电子签名与骑缝章。

## 这些特征在「文档解析与分块」这一环带来什么约束
多格式的文档来源要求解析工具需同时支持原生PDF与扫描件解析，避免遗漏非电子文档的台账数据。高频更新的单日大量车次数据要求分块不能过大，否则会增加后续汇总与检索的耗时。固定表头的结构化表格要求分块工具需保留表格结构，不能强行拆分单元格内的字段与单位关联。电子签章与骑缝章则要求解析过程中不破坏文档的完整性标识，避免影响后续审核环节。

以下配置基于FastGPT v4.17.0版本制定，适配煤炭运销台账的解析与分块需求：
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `customPdfParse` | 开启 | 煤炭运销台账PDF多包含固定格式的结构化表格与签章，自定义解析可完整保留表格结构与字段关联 |
| `chunkSize` | 800–1200 字符 | 单条完整台账记录约300-500字符，该取值范围可容纳1-2条完整记录，避免拆分单条台账的核心字段 |
| `chunkSplitter` | 按段落+表格拆分 | 煤炭运销文档以结构化表格与说明段落混合为主，按此拆分可保留数据的关联性与可读性 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单批次上传月度汇总的多份台账文件，适配批量导入的业务需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型月度台账PDF解析耗时较长，延长超时时间可避免批量解析任务中途中断 |
| `chunkSettingMode` | 手动配置 | 需针对煤炭运销的固定字段规则调整分块逻辑，手动配置比自动模式更贴合业务场景 |

## 容易做错的三处
- 现象：对话框上传PDF后无解析进度，后台无报错日志。原因：未开启`customPdfParse`配置，默认通用解析无法识别煤炭运销台账的固定表格结构，导致解析失败无有效提示。
- 现象：启用解析功能后服务内存占用突增。原因：未限制`UPLOAD_FILE_MAX_SIZE`，上传了超过服务器承载能力的超大批量台账文件，触发内存资源耗尽。
- 现象：分块结果中煤种、净重等核心字段被拆分到不同块中。原因：`chunkSize`设置过小，且未开启按表格拆分的分块规则，导致单条完整台账记录被强行拆分。

## 怎么确认配好了
- 上传单份典型煤炭过磅单PDF，查看解析后的文本是否保留了过磅时间、车号、毛重皮重等完整字段与表格结构。
- 批量上传月度台账文件，检查解析任务是否在`PARSE_FILE_TIMEOUT_SECONDS`配置的时间内完成，无超时中断提示。
- 调用API上传文件后，验证知识库分块列表中是否包含完整的台账条目，无字段拆分异常的情况。
- 调整`chunkSize`参数后，对比不同取值下的分块结果，确认分块未拆分单条完整的台账记录。
