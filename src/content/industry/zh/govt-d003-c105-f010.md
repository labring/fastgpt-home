# 煤炭运销的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
煤炭运销的台账与报告数据主要来自过磅计量系统、购销合同管理模块、煤质化验报告、铁路/公路运输单据。数据按单批次交易或每日更新，单份台账文档通常包含煤种标识、发运量、收到基低位热值、全水分、购销双方主体信息、结算单价与总金额、运输起止里程等字段，单位涵盖吨、千卡/千克、元、公里等。汇总报告类文档则整合多笔交易数据，包含周期统计项与趋势分析内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
煤炭运销数据按交易批次高频更新，要求知识库检索需支持增量同步以保证数据时效性。多字段且带专业单位的文档结构，要求检索需精准匹配字段语义与单位标识，避免跨煤种、跨结算周期的结果混淆。单份台账文档篇幅较短但汇总报告类文档篇幅较长，切分与召回环节需保留字段关联完整性，防止专业信息被拆分丢失。同时，涉及购销主体与结算数据的内容，需严格限定检索范围，避免无关数据混入。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 煤炭运销台账字段专业且精准度要求高，避免低匹配度的无关数据混入检索结果 |
| `limit` | 前10条 | 单份台账数据量小，过多召回会增加上下文冗余，影响报告生成准确性 |
| `searchMode` | 专业语义匹配 | 适配煤炭运销的热值、发运量等专业术语，提升语义匹配精度 |
| `usingReRank` | 开启 | 对初步召回的结果按相关性重新排序，确保高匹配度的台账数据优先被调用 |
| `datasetSearchUsingExtensionQuery` | 开启 | 将用户的台账汇总查询转化为更贴合煤炭运销专业场景的检索词，覆盖更多相关文档 |
| `collectionIds` | 绑定煤炭运销台账与报告的集合ID | 限定检索范围，避免混入其他品类的知识库数据 |

## 容易做错的三处
- 知识库管理页面可查看所有上传的文档，但对话时模型返回“未检索到相关知识库内容”。原因是未将当前对话绑定的`collectionIds`指定为煤炭运销台账知识库的集合ID，检索范围未限定到目标知识库。
- 上传的单份汇总报告文档切分后块数超过3000，对话时检索结果条数远低于预期。原因是未调整`limit`参数或未对超长文档进行合理拆分，导致检索时超出系统默认的块数限制，无法召回完整数据。
- 检索结果中混入非煤炭运销品类的文档，导致报告生成出现无关内容。原因是未配置`collectionIds`限定检索范围，或绑定了错误的知识库集合。

## 怎么确认配好了
- 进入知识库管理页面，确认已绑定的`collectionIds`指向煤炭运销台账与报告的专属集合。
- 发起测试查询，输入贴合业务场景的问题，比如“2024年第三季度煤炭发运量汇总”，查看检索返回的文档是否均属于煤炭运销台账或报告范畴。
- 调整`similarity`参数的取值，观察检索结果的匹配度变化，确认参数生效。
- 开启`usingReRank`后，对比开启前后的检索结果排序，确认重排功能正常运行。
