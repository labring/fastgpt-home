# 煤电一体化的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
煤电一体化的台账数据来源于煤矿生产端与电厂运行端的实时采集系统、每日调度日志与月度结算报表。数据更新节奏分为三类：生产参数如采掘进度、入炉煤量为实时更新，设备运维台账为每日更新，月度能耗与营收台账为周期更新。文档结构分为煤矿子台账（采掘、运输、洗选环节）与电厂子台账（锅炉、汽轮机、脱硫脱硝环节），字段包含原煤产量（单位吨）、入炉煤热值（单位MJ/kg）、发电负荷（单位MW）、单位煤耗（单位g/kWh）等，部分台账附带设备现场照片、工艺图纸，以URL格式存储于知识库中。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
跨端的数据源结构要求多轮对话需明确区分煤矿与电厂的场景边界，避免上下文混淆。多更新频率的差异要求提示词需指定数据的时间范围参数，确保汇总的台账周期符合需求。特定的字段与单位要求提示词需内置校验规则，强制统一输出格式，防止单位混乱导致的报告错误。附带的图片型台账数据，要求对话流程支持URL格式图片的解析与展示，需在提示词中明确图片调用的规则。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的界面与API逻辑，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口长度 | 8000–12000 token | 煤电台账数据关联度高，足够的上下文可保留跨环节对话的逻辑连贯性 |
| 最大对话轮次 | 前8轮 | 台账汇总通常围绕固定周期展开，过多轮次易引入无关历史数据干扰结果 |
| 提示词模板变量 | 按实测标定 | 适配不同煤矿或电厂的专属字段前缀，避免混淆跨主体的台账数据 |
| 知识库召回条数 | 前6条 | 台账数据条目集中且关联度强，少量召回即可覆盖核心汇总需求 |
| 图片处理开关 | 开启 | 设备台账常包含现场照片与工艺图纸，需支持URL格式图片的展示 |
| 超时时间 | 120 秒 | 跨系统台账汇总需调取多源数据，预留足够的响应时长 |

## 容易做错的三处
- 对话中无法展示知识库内的图片：未开启图片处理开关，或知识库文档中的图片URL未遵循标准格式要求。
- API调用返回空的台账汇总结果：未在`messages`参数中传入历史对话上下文，或未通过`variables`传递当前场景的专属台账字段前缀。
- 多轮对话输出的台账数据单位不一致：提示词未明确要求统一字段单位，未关联当前对话对应的煤矿或电厂主体。

## 怎么确认配好了
- 上传一份包含设备图片URL的煤电台账文档，发起包含图片展示要求的对话，确认图片正常显示。
- 发起跨环节的多轮对话，先查询煤矿月度台账，再查询电厂关联能耗数据，确认对话上下文被正确保留。
- 调用对话API时传入`chatId`参数，发起两次连续的台账查询请求，确认两次结果属于同一对话上下文。
- 发起包含多源数据调取的测试对话，确认未出现超时报错，且输出的台账数据单位统一。
