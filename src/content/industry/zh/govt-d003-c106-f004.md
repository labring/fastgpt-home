# 煤电一体化的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
煤电一体化的台账数据主要来源于煤矿采掘班组台账、电厂运行日志、燃料入厂质检记录与环保监测系统。数据更新节奏分多档：采掘与运行参数按班次更新，燃料结算数据按自然日更新，环保监测数据按小时更新。单份台账文档包含设备编码、作业时间、核心参数、异常标注等字段，核心参数单位包括大卡/千克、千瓦时、毫克/立方米等，无统一固定格式模板，需按业务模块拆分提取。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流需配置多个独立的数据拉取节点，分别对接煤矿、电厂、燃料与环保系统的接口。不同数据源的更新节奏差异，要求工作流的定时触发节点需支持按不同周期轮询拉取数据，避免重复拉取或遗漏更新内容。字段单位不统一的特征，要求工作流中需嵌入参数转换环节，对不同来源的同类参数做单位对齐。无固定格式的台账文档，要求工作流需支持动态配置报告的模块顺序与内容填充规则。本页面内容基于FastGPT v4.17.0版本的工作流编排功能编写。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发周期 | 按数据源类型分档配置：班次数据设为`8 小时`，结算数据设为`1 自然日` | 匹配煤矿采掘、电厂运行的班次更新与燃料结算的日更节奏 |
| `variables` | 绑定入炉煤热值、发电量、污染物浓度等核心台账字段为全局变量 | 适配多源异构数据的统一调用，避免重复提取字段 |
| `nodeId` | 为数据拉取、参数转换、报告生成节点分配唯一标识 | 便于工作流调试与异常节点快速定位 |
| 提示词模板配置 | 按报告模块拆分编写，预留对应全局变量的占位符 | 适配无固定格式台账的动态内容填充 |
| 异常重试次数 | 设为`2 次` | 应对接口拉取或大模型调用的偶发失败 |
| 参数转换规则 | 按单位对齐要求配置，例如将不同来源的热值统一转换为大卡/千克 | 解决多源数据单位不统一的问题 |

## 容易做错的三处
- 工作流运行后台账数据字段为空，查看日志发现未正确绑定`variables`参数。原因是未将数据源提取的字段映射到全局变量中，导致后续节点无法调用对应数据。
- 配置提示词时无法调用全局变量，界面提示变量未定义。原因是未在工作流的变量配置节点中提前声明需要使用的全局变量，或占位符格式不符合系统要求。
- 工作流触发后返回`chat:LLM_model_response_empty`报错，大模型响应为空。原因是未配置异常重试机制，或触发节点的超时时间设置过短，导致大模型调用未完成即被中断。

## 怎么确认配好了
- 手动触发工作流一次，查看各数据拉取节点的输出日志，确认已成功提取对应数据源的台账字段。
- 检查`variables`参数的配置页面，确认所有需要使用的台账字段已正确绑定为全局变量，占位符与提示词模板一致。
- 模拟大模型调用失败的场景，验证异常重试节点是否按配置触发重试，确认报错日志能正确定位到异常节点的`nodeId`。
- 查看工作流的运行历史记录，确认定时触发节点按预设周期执行，无重复或遗漏的运行记录。
