# 煤电一体化的台账汇总与报告生成：模型接入与配置
本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
数据来源于煤矿采掘、电厂发电、输煤储运的工业控制系统与企业ERP台账系统。更新节奏分为实时工况数据与每日/每班汇总台账记录。单份台账文档包含设备编号、运行时长、煤耗量、发电量、检修记录等结构化字段，辅以非结构化的检修报告附件。字段单位包括小时、吨、兆瓦时、克/千瓦时等，不同业务环节的台账字段存在差异，需按业务模块分类整理。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时工况数据的高频更新要求模型调用的响应延迟控制在合理区间，需限制单次上下文的最大长度以避免超时。多字段混合的台账结构要求模型能够准确识别不同业务模块的字段单位与含义，需配置合适的工具调用规则适配结构化数据解析。非结构化检修报告的存在，要求模型能够同时处理文本与结构化信息，需调整温度参数平衡准确性与灵活性。不同业务环节的台账字段差异，要求配置可切换的上下文模板，避免跨模块数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配煤电一体化台账的多字段混合上下文长度，避免超出模型支持范围 |
| `maxTokens` | 2000–3000 token | 满足单份台账报告生成的内容长度需求，同时控制单次调用成本 |
| `toolChoice` | auto | 适配结构化台账与非结构化检修报告的混合处理，自动触发工具调用解析数据 |
| `temperature` | 0.3–0.5 | 平衡台账数据解析的准确性与报告生成的规范性，避免过度发散 |
| `AIPROXY_API_ENDPOINT` | 本地部署的大模型服务地址 | 适配企业内部网络环境，避免数据外流 |
| `AIPROXY_API_TOKEN` | 企业内部生成的访问密钥 | 保障模型调用的安全性，限制未授权访问 |

## 容易做错的三处
- 模型调用返回报错信息，提示上下文长度超限。原因是未根据煤电一体化台账的多字段特征调整`maxContext`参数，导致传入的上下文超出模型支持上限。
- 生成的报告中字段单位混乱，例如将煤耗量的单位混用为千克与克/千瓦时。原因是未配置`toolChoice`为auto模式，模型无法自动识别不同业务模块的字段单位规则。
- 部署后调用模型时出现连接超时。原因是未正确配置`AIPROXY_API_ENDPOINT`为本地大模型服务地址，导致网络无法连通。

## 怎么确认配好了
- 上传单份煤电一体化台账文档，检查模型是否能准确提取设备编号、运行时长等核心字段，核对字段单位是否符合业务要求。
- 触发一次台账汇总报告生成，检查生成内容是否包含所有指定的业务模块数据，无明显格式混乱。
- 查看模型调用日志，确认响应时间符合业务需求，无频繁超时现象。
- 配置不同业务模块的上下文模板，切换后检查模型是否能正确适配对应模块的字段规则。
