# 煤电一体化的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
煤电一体化台账的数据来自煤矿采掘、发电运行、设备运维、燃料管理等业务系统，包含综采面推进记录、机组运行日志、煤质检测报表、设备检修台账等。更新节奏分日度（运行日志、巡检记录）、月度（检修台账、燃料采购台账）、季度（年度成本台账）。文档同时包含结构化字段与非结构化附件，结构化字段如设备编号、发电量、煤耗量，对应单位为兆瓦时、吨、小时；非结构化附件包含现场巡检照片、检修报告PDF等，部分台账包含专属行业字段如综采面推进度、机组负荷率。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化字段多且语义精准，要求检索需兼顾字段匹配与语义匹配，避免通用检索的模糊性；非结构化附件包含图片，要求检索环节需支持图像解析，否则无法覆盖图片内的设备标识、检修记录等信息；数据更新频率不一，要求召回策略需支持增量同步，避免全量检索浪费资源；单条台账文档长度较长，要求分块参数需适配长文本，避免截断关键信息；专属行业术语多，要求检索需支持术语扩展，提升召回覆盖范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.72–0.85` | 煤电台账的结构化字段语义精度要求高，过低会混入无关设备台账，过高会遗漏匹配的检修记录，按实测标定调整 |
| `limit` | `前8–12条` | 单条煤电台账文档较长，过多会超出上下文窗口，过少会遗漏同设备多时段的关联数据 |
| `searchMode` | `vector+keyword` | 台账同时包含结构化字段和非结构化文本，混合检索可兼顾精准匹配字段和语义匹配内容 |
| `usingReRank` | `开启` | 煤电台账数量多且相似度分布分散，重排可过滤低相关的跨机组冗余数据 |
| `datasetSearchUsingExtensionQuery` | `开启` | 台账术语多为行业专属，扩展查询可补充同义词（如“机组负荷”与“发电负载”），提升召回覆盖 |
| `collectionIds` | `对应煤电业务知识库的专属集合ID` | 隔离不同业务线的台账数据，避免混入非煤电的无关文档 |

## 容易做错的三处
- 现象：本地部署模型添加知识库后触发报错，日志显示向量入库失败或超时。原因：煤电台账单文档体积偏大，未调整分块参数导致向量入库时数据量超出本地模型的embedding批次上限。
- 现象：生成的报告中检索内容占比不符合预设要求，出现冗余数据或关键信息遗漏。原因：未联动配置`similarity`阈值与`limit`参数，仅单一调整其中一项无法精准控制召回内容的权重与数量。
- 现象：知识库无法解析台账中的设备巡检图片，仅提取到空文本内容。原因：未开启图像解析插件，煤电台账中的现场照片、检修图纸等图片数据未被转换为可检索的文本信息。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理页面，查看已上传的煤电台账文档的解析状态，确认所有结构化字段与图片均已完成解析。
- 发起测试查询，输入“2号机组3月检修台账”，核对检索结果的条数与`limit`参数设置一致，且相似度得分在`similarity`预设区间内。
- 开启应用调试模式，查看检索召回的上下文内容，确认仅包含煤电业务相关的台账数据，未混入其他业务线的文档。
- 上传一份新增的月度检修台账，测试增量更新功能，确认系统仅同步新增数据，未重复召回旧文档。
