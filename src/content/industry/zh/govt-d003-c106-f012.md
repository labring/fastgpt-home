# 煤电一体化的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
煤电一体化的台账数据来源覆盖煤炭开采、洗选、运输、发电全流程的生产监测系统、设备运维日志、能耗统计报表、采购入库单据等。更新节奏为每班一次或每日一次，部分关键设备运行台账实时更新。文档结构包含多维度结构化字段与非结构化内容，结构化字段如煤炭发热量、发电量、耗煤量、设备运行时长等，附带对应计量单位，非结构化内容包括巡检报告、检修记录、月度汇总报表等。

## 这些特征在「部署与升级」这一环带来什么约束
煤电一体化台账数据覆盖全流程且字段复杂，要求部署时配置足够的数据库连接池与存储资源，支撑多维度查询。多频次更新的台账需要近实时的索引同步，升级时需保证知识库索引机制与现有数据更新节奏兼容，避免出现索引滞后。大型非结构化文档的解析与存储，要求配置适配大文件的上传与处理参数，防止上传中断。跨环节的台账关联查询，需要稳定的缓存服务支撑高频访问，避免升级过程中出现服务中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150` | 煤电台账的多环节查询频繁，避免数据库连接池耗尽 |
| `MONGODB_URI` | 本地MongoDB实例的完整连接地址，包含用户名与密码 | 存储台账的结构化元数据与索引信息，保障查询效率 |
| `REDIS_URL` | `6379端口的本地Redis实例地址` | 缓存台账的高频查询结果与用户会话信息，降低数据库负载 |
| 分块长度 | `800–1200 字符` | 适配煤电台账多字段的长文本结构，保留上下文关联 |
| 单次搜索上限 | `前10条` | 煤电台账字段关联度高，前10条即可覆盖所需汇总信息 |
| `FILE_TOKEN_KEY` | 随机生成的32位字符串 | 保障上传的台账文件访问安全，防止未授权访问 |

## 容易做错的三处
- 现象：docker部署后访问`FE_DOMAIN`对应地址无响应，返回连接超时。原因：未正确配置`MONGODB_URI`或`REDIS_URL`，导致后端服务无法启动依赖的数据库连接。
- 现象：每次打开新对话都弹出版本更新提示弹窗。原因：部署时未在配置中禁用版本更新提示开关，或升级后未同步更新前端静态资源。
- 现象：新建知识库时，无图片索引模型的可选配置项，上传图片类台账后无法生成对应索引。原因：本地部署的FastGPT未加载图片索引相关的扩展依赖，或未正确配置`STORAGE_S3_ENDPOINT`以支持图片文件存储。

## 怎么确认配好了
- 执行FastGPT v4.17.0自带的数据库连接测试命令，验证`MONGODB_URI`和`REDIS_URL`配置的地址、端口、权限是否正确。
- 上传单张10MB以内的煤电设备图片台账，确认上传成功且可在知识库中预览。
- 发起一次台账汇总查询，确认返回结果的条数符合配置的单次搜索上限。
- 打开新对话窗口，确认不再弹出版本更新提示弹窗。
