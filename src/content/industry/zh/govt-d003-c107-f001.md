## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据来源分散导致需对接多个异构系统的HTTP接口，不同接口的鉴权规则与响应格式存在差异，需针对性配置请求参数。实时数据的短更新间隔要求接口调用频率匹配，避免数据滞后或重复拉取。固定的字段与单位要求接口请求需明确指定返回字段，防止冗余数据干扰台账汇总逻辑。月度汇总台账的数据量较大，单次接口调用不宜返回过多记录，需通过分页参数控制负载。此外，煤矿生产数据属于敏感国资数据，接口传输需符合国央企安全规范，鉴权与加密配置需严格合规。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | Bearer {国央企统一API密钥} | 煤矿生产数据属于敏感国资数据，标准Bearer令牌鉴权符合国央企接口安全规范 |
| `variables` | `{"device_type": "underground_pump", "time_range": "last_7_days"}` | 用于指定拉取的设备类型与时间范围，适配台账汇总的分批次拉取与筛选需求 |
| `responseData` | 仅返回`device_id, run_hours, gas_concentration, inspection_date`字段 | 过滤冗余数据，减少接口传输负载，匹配台账汇总的核心字段需求 |
| 接口超时时间 | 15-60秒（实时数据接口）、300-600秒（月度汇总接口） | 不同更新频率的数据接口响应时长差异大，避免超时或等待过长 |
| 分页条数 | 100-200条/页 | 月度台账数据量较大，分页可降低单次接口负载，提升调用稳定性 |

## 容易做错的三处
- 现象：调用接口后返回的响应头中Set-Cookie字段无法被提取，`responseData`中无相关cookie信息。原因：未在HTTP请求配置中开启cookie持久化，FastGPT默认不自动捕获响应头中的Set-Cookie字段。
- 现象：调用创建应用接口时返回401未授权状态码，接口调用失败。原因：未正确配置`Authorization`参数，密钥格式不符合国央企API鉴权要求。
- 现象：第三方系统调用后无法显示知识库上传的图片，返回的图片链接无法直接访问。原因：未将FastGPT生成的图片链接配置为允许跨域访问，且未在接口响应中添加正确的访问权限头。

## 怎么确认配好了
- 调用测试接口，查看返回的`responseData`是否包含预设的核心字段，无冗余数据。
- 检查`Authorization`参数是否正确，调用接口后返回200状态码，无鉴权失败提示。
- 模拟第三方系统调用，验证返回的图片链接可正常访问，无跨域或权限问题。
- 针对月度汇总数据，调用分页接口，验证返回的记录数符合预设的分页条数，无数据截断或丢失。
