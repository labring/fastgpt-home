# 煤矿生产的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
煤矿生产的台账数据主要来源于综采、掘进、通风等生产系统的监控终端、设备巡检终端与调度指挥平台。数据更新节奏覆盖实时、每小时、每班与月度四类：实时数据为设备运行状态，每小时更新为时段汇总台账，每班（8小时）生成巡检台账，月度末生成全矿生产汇总台账。单条台账文档结构固定，包含设备编号、运行时长、故障次数、巡检人员、时间戳等字段，单位统一为小时、次、台与标准时间格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时与高频更新的台账数据要求索引支持增量更新，避免全量重建带来的资源消耗与延迟。固定结构的字段与统一单位，要求向量模型适配结构化文本，需优先选择支持短文本编码的模型。多设备产生的海量台账数据，要求索引的召回上限与分块策略适配批量查询场景，同时需支持按设备编号、时间戳进行元数据过滤，缩小召回范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 煤矿生产台账单条记录字段集中，过长分块会混入无关信息，该区间适配结构化短文本 |
| 重叠长度 | 50–100 字符 | 避免跨块的设备运行数据被割裂，保证上下文连贯 |
| `maxToken` | 4096 token | 适配多数开源向量模型的输入上限，避免截断关键的时间戳与设备参数 |
| 相似度阈值 | 0.72–0.85 | 区分正常生产台账与异常记录的向量匹配度，过滤低相关性的历史数据 |
| 单次搜索上限 | 前20条 | 平衡召回效率与覆盖范围，适配煤矿台账的多设备批量查询场景 |
| `defaultToken` | 1024 token | 控制单轮生成报告的基础上下文长度，避免超出平台资源限制 |

## 容易做错的三处
- 现象：本地部署向量模型时，日志显示显存不足，或第二张3090显卡无法被调用。原因：未在FastGPT v4.17.0及以上版本的配置文件中指定可见显卡，或未开启多显卡负载均衡。
- 现象：添加索引模型后界面弹出404报错，或接口请求返回404状态码。原因：未正确配置模型访问地址，或版本升级后模型路由路径发生变更。
- 现象：无GPU环境下尝试添加向量模型失败，容器内m3e服务运行但无法关联。原因：未在配置中关闭GPU强制依赖，或未正确映射容器端口与本地服务地址。

## 怎么确认配好了
- 上传单条煤矿生产台账样本，查看分块结果是否保留了设备编号、运行时长等核心字段，无明显内容割裂。
- 发起台账汇总查询，检查返回的上下文条数是否符合单次搜索上限的设置，无超出或不足的情况。
- 查看向量模型的运行日志，确认已加载指定的模型参数，无显存溢出或连接超时报错。
- 触发报告生成任务，核对生成内容是否包含了预设的字段范围，无关键信息缺失。
