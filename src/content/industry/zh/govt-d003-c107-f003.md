# 煤矿生产的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
煤矿生产的台账数据主要来自井下环境传感器、综采设备运维系统、地面调度指挥平台及月度安检报表。数据更新节奏分三类：环境参数每1-5分钟刷新一次，设备运行数据随操作实时同步，月度汇总台账于次月3日前完成归档。单条台账文档包含设备唯一编号、连续运行时长、故障触发次数、巡检执行时间、瓦斯浓度值、当日出煤吨数等字段，单位涵盖小时、次、ppm、吨等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源异构的台账数据更新节奏差异，要求多轮对话流程中需实时调用对应数据源接口，避免使用缓存的过期数据。专业字段与非标单位的存在，要求提示词需明确限定字段名称、统计口径及单位，防止模型生成不符合煤矿生产规范的结果。跨时间维度的台账（实时参数、月度汇总）混合查询场景，要求多轮对话中需记录用户指定的时间范围参数，确保每次调用都能匹配对应更新频率的数据集。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配煤矿生产场景。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前对话会话ID | 确保多轮对话上下文与用户会话绑定，避免跨会话数据混淆 |
| `messages` | 保留最近20条对话历史，单条内容不超过1500字符 | 适配煤矿台账数据的专业文本长度，避免上下文溢出 |
| `variables` | 预设时间范围、设备编号两类全局变量 | 匹配用户高频查询的台账筛选条件，减少重复输入 |
| 最大上下文 | 8000–12000 token | 覆盖单批次设备台账的汇总文本，支持多轮关联查询 |
| 超时阈值 | 600秒 | 适配煤矿数据跨系统拉取的延迟情况，避免请求中断 |
| 问题优化 | 开启 | 自动补全用户未明确的时间或设备参数，符合煤矿台账查询的专业习惯 |

## 容易做错的三处
- 现象：对话回传内容耗时超过600秒，接口返回超时错误。原因：未配置适配煤矿跨系统数据拉取的超时阈值，默认超时时长不足。
- 现象：同一对话中修改全局变量后，后续组件调用未同步更新变量值。原因：未在多轮对话流程中绑定`variables`参数的实时更新逻辑，仅初始化时读取变量。
- 现象：无法在多轮对话中获取用户每一次的独立提问内容，仅能获取汇总上下文。原因：未启用`messages`参数的单条提问提取配置，错误拼接了全部历史上下文。

## 怎么确认配好了
- 发起包含设备编号、时间范围的多轮查询，核对每次回复是否匹配对应数据源的最新台账数据
- 手动修改全局变量值，验证后续对话调用是否使用更新后的变量内容
- 查看对话历史记录，确认每条用户提问都被单独记录并关联到对应查询请求
- 测试跨系统数据拉取请求，确认请求时长未超过预设的超时阈值
