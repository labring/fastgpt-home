# 煤矿生产的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
煤矿生产的台账数据来源包括井下环境传感器、综采设备运行日志、班组巡检报表、调度中心生产报表四类。数据更新节奏分为三类：井下传感器数据每10秒更新一次，班组巡检报表每班提交一次，月度生产台账于每月5日前汇总完成。单条台账文档包含工作面编号、设备ID、运行时长、瓦斯浓度、吨煤能耗、故障次数、巡检时间、耗材领用数量等字段，其中瓦斯浓度单位为%VOL，吨煤能耗单位为千克标准煤/吨，运行时长单位为小时。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源异构的数据来源要求工具调用插件同时支持流式实时数据拉取与批量历史数据导入，否则无法覆盖全量台账的汇总需求。字段与单位的特殊性要求工具调用的参数映射必须严格匹配预设字段，否则会导致数据格式错误，无法生成合规的生产报告。不同更新频率的数据混合调用时，会增加上下文窗口的负载，若未限制调用轮次与上下文长度，容易触发上下文溢出问题。分散的井下设备数据接口需要插件配置多工具路由，避免单次调用请求超时。

## 配置怎么定
本文基于FastGPT v4.17.0版本的工具调用与插件功能编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配多工具调用场景，自动选择设备数据拉取或报告生成工具 |
| 单次工具调用超时时间 | 300–600 秒 | 应对井下数据接口的网络延迟与设备响应时长 |
| 上下文窗口长度 | 8000–16000 token | 容纳多班次的台账数据与关联的安检报告内容 |
| `functionCall` | 强制开启 | 确保模型输出符合工具调用的格式要求，避免解析错误 |
| 最大工具调用轮次 | 3–5 轮 | 限制重复调用，避免上下文溢出与无效计算 |

## 容易做错的三处
- 工具调用返回的内容被think标签包裹，出现Tool call Parser error报错。原因是模型输出的content字段包裹了思考内容，导致工具调用的参数无法被正确提取。
- 工具调用过程中触发上下文溢出，返回结果为空或提示上下文长度超限。原因是未限制工具调用轮次，或未裁剪过长的历史台账数据。
- 通过aiproxy连接的模型无法正常转发工具调用请求，返回较长的错误代码。原因是未正确配置代理的工具调用转发规则，或密钥权限未开放工具调用权限。

## 怎么确认配好了
- 发起包含指定工作面编号与班次的测试请求，检查是否能正确调用对应的数据拉取工具并返回匹配的字段内容。
- 查看工具调用日志，确认`toolChoice`与`functionCall`的配置被正确加载，无参数解析相关的错误提示。
- 模拟包含多班次台账数据的测试请求，检查是否触发合理的上下文裁剪或轮次限制，未出现上下文溢出报错。
- 测试代理连接场景，确认工具调用请求能正常转发至目标模型，无异常错误代码返回。
