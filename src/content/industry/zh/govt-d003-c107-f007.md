# 煤矿生产的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
煤矿生产的台账数据来源于综采、掘进工作面的传感器系统、生产调度平台与安全监管系统。数据更新节奏分为两类：实时类的设备运行、瓦斯浓度数据为秒级更新，每日或每班的汇总类台账为固定周期更新。单条台账文档包含工作面编号、生产时长、出煤量、设备运行时长、瓦斯浓度值、统计周期等字段，字段带有明确单位，例如出煤量以吨为单位，生产时长以小时为单位，统计周期以班次或自然日为标识。数据结构相对固定，但单批次导入的数据量随统计周期延长而增加。

## 这些特征在「数据库与运维」这一环带来什么约束
多来源的数据接入要求数据库支持混合负载，既要处理秒级的实时数据写入，也要应对批量的汇总类数据导入。不同更新节奏的数据源需要配置差异化的写入策略，避免抢占数据库资源。字段带有明确单位的特性要求数据库在存储时需保留字段元信息，避免数据解析错误。单批次数据量较大的场景下，数据库需要支持高效的批量写入与关联查询，同时需建立针对性的索引以加速汇总统计。此外，煤矿系统的内网环境限制了外部访问，数据库运维需适配内网部署的网络规则。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://coal_user:secure_pass@internal-db-host:27017/coal_ledger?authSource=admin` | 适配煤矿生产台账的结构化与非结构化混合存储需求，支持批量写入与关联查询 |
| `PG_URL` | `postgresql://coal_admin:db_pass@internal-pg-host:5432/coal_standard` | 存储标准化台账字段，支持复杂条件的汇总查询与统计分析 |
| `DB_MAX_LINK` | `20–30 个连接` | 匹配煤矿系统单批次数据量与并发请求量，避免连接池耗尽导致服务中断 |
| `REDIS_URL` | `redis://redis_pass@internal-redis-host:6379/0` | 缓存高频查询的台账汇总结果，降低数据库的重复计算负载 |
| 数据库超时时间 | `600 秒` | 适配煤矿系统批量数据导入的耗时需求，避免因超时中断写入流程 |

## 容易做错的三处
-  连接数据库时提示服务器内部错误，日志显示连接超时。原因是未配置正确的`MONGODB_URI`或`PG_URL`，未开放煤矿内网数据库的访问端口。
-  服务启动后提示MongoDB连接失败。原因是数据库连接池配置`DB_MAX_LINK`取值过低，或MongoDB服务未正常启动。
-  台账汇总结果条数与实际统计结果不符。原因是未按工作面编号与统计周期字段建立数据库索引，导致查询遗漏部分数据。

## 怎么确认配好了
-  执行FastGPT内置的数据库连接测试工具，输入`MONGODB_URI`与`PG_URL`后无报错，即为配置正确。
-  导入单班次的煤矿生产台账数据，查看数据库写入日志，确认所有数据均成功写入。
-  发起一次台账汇总请求，对比手动统计的结果与系统生成的报告数据，确认字段与数值一致。
-  查看Redis监控面板，确认高频查询的缓存命中次数随请求增加而上升，证明缓存配置生效。
