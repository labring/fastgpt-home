# 煤矿生产的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
煤矿生产的台账数据来源包括井下采掘设备运行日志、通风与瓦斯监测传感器数据、调度排班台账、安监巡检记录、物料领用单据。实时类台账每15分钟同步更新，日报类台账每日凌晨完成批量同步，月度汇总台账每月初生成。单条台账文档包含设备唯一标识、运行时长、能耗数值、巡检时间、异常状态标记等字段，单位涵盖小时、千瓦时、人次、吨等。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时数据流的高频更新要求模型接入时适配短周期上下文调用，避免因上下文溢出导致超时。多字段多单位的台账结构要求配置阶段明确字段映射规则，防止模型混淆不同类别的数值单位。月度汇总类台账的长文本体量，需要调整模型调用的上下文参数上限，确保完整读取历史数据。不同台账的更新节奏差异，要求配置支持按数据类型切换调用频率，避免无效请求占用资源。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配月度汇总台账的长文本读取需求，避免截断关键历史数据 |
| `maxTokens` | 4000 token | 控制单轮报告生成的输出长度，匹配台账汇总的文本体量 |
| `quoteMaxToken` | 2000 token | 限制检索到的台账片段总长度，确保模型能聚焦有效信息 |
| `temperature` | 0.2–0.4 | 降低生成随机性，保证台账数据汇总的准确性与格式一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的专属地址填写 | 适配煤矿内网环境的访问限制，确保模型调用链路合规 |
| `toolChoice` | auto | 允许模型自动选择是否调用检索工具，适配不同类型台账的汇总需求 |

## 容易做错的三处
- 现象：调用DeepSeek Code模型时返回代码解析错误，无法正确格式化台账数据。原因：未调整`maxContext`参数适配长文本输入，导致月度台账被截断后解析失败。
- 现象：配置支持联网的模型后，生成报告仅调用知识库内容，未纳入最新实时设备数据。原因：未将`toolChoice`参数设置为允许联网调用，强制模型仅使用静态知识库数据。
- 现象：尝试通过MCP接入第三方AI工具时返回协议不兼容报错。原因：未适配FastGPT生成的SSE格式MCP服务，与第三方工具要求的调用协议不匹配。

## 怎么确认配好了
- 提交单条实时台账测试，检查模型返回的汇总结果是否包含完整的设备运行时长与能耗数值，核对字段匹配度。
- 触发月度台账汇总任务，查看输出报告的长度是否符合预期，确认未出现文本截断情况。
- 调整`temperature`参数后对比两次生成结果，确认输出格式与数据准确性未出现无意义波动。
- 检查模型调用日志，确认请求链路与API密钥配置无误，无权限类报错。
