# 煤矿生产的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
煤矿生产的台账数据来源包括井下传感器采集系统、班组交接班台账、设备点检日志、安全巡检报表。更新节奏分为实时（传感器运行参数）、每班结束后（班组作业记录）、每日汇总（安全检查报表）三类。单条台账文档包含作业地点、设备编号、运行参数、检查结果、责任人、时间戳等字段，其中设备编号为6位数字格式，运行参数包含压力、温度等带法定计量单位的数值，文档长度从数十字符到上千字符不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
实时更新的传感器数据要求知识库支持增量同步，避免全量刷新带来的延迟，确保最新的设备运行记录可被检索。结构化的字段与固定格式的设备编号，要求检索支持精准匹配模式，避免模糊匹配引入无关的跨设备记录。文档长度差异大的特点，要求分块策略适配不同长度的台账条目，避免过短丢失上下文或过长超出模型上下文窗口。多源数据的混合存储，要求通过专属数据集隔离台账数据，防止跨场景检索的干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.72–0.85` | 煤矿台账的字段精准度要求高，过低会引入无关的设备记录，过高会遗漏同设备的关联记录，按实测标定 |
| `limit` | 前8–12条 | 单条台账关联的设备记录较多，需要足够的上下文支撑汇总，同时避免超出模型上下文窗口 |
| `searchMode` | 精准匹配优先 | 煤矿台账的设备编号、作业地点等字段需要精准召回，避免模糊匹配带来的无效结果 |
| `usingReRank` | 开启 | 多维度的台账记录需要按相关性排序，确保核心设备的记录优先被召回 |
| `datasetSearchUsingExtensionQuery` | 开启 | 台账的查询需求常包含设备编号的扩展匹配，比如输入设备名称时自动关联编号查询 |
| `collectionIds` | 绑定煤矿生产台账专属数据集ID | 隔离不同业务场景的知识库数据，避免跨场景的检索干扰 |

## 容易做错的三处
- 现象：检索时返回结果符合配置，但生成台账报告时无内容输出。原因：未开启`datasetSearchUsingExtensionQuery`，导致模型无法获取扩展后的关联台账数据，或召回的文档未正确映射到报告所需的字段。
- 现象：本地测试检索正常，但外部发布渠道无法引用检索结果。原因：未将台账数据集的访问权限配置为公开，或发布渠道未绑定正确的`collectionIds`参数。
- 现象：检索结果中混杂了非目标设备的台账记录。原因：`similarity`阈值设置过低，或未开启精准匹配模式，导致模糊匹配引入无关数据。

## 怎么确认配好了
- 进入FastGPT v4.17.0的数据集管理页面，查看台账专属数据集的配置参数，确认`similarity`、`limit`等参数与预设值一致。
- 输入包含设备编号的查询词，执行检索，核对返回结果的设备编号与查询词匹配度符合预期。
- 切换到外部发布渠道，发起台账汇总请求，查看返回结果是否包含检索到的台账内容，无空值或缺失字段。
- 开启`usingReRank`功能后，再次执行检索，核对返回结果的排序与相关性匹配度符合业务需求。
