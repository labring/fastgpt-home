# 煤矿生产的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
煤矿生产的台账数据主要来自井下传感器、生产调度系统、安全巡检终端与设备运维日志。传感器数据实时推送，巡检记录按班次每日更新，设备运维日志在故障处置或定期保养后生成。单份台账文档包含设备编号、运行时长、故障次数、巡检项达标率等字段，单位涵盖小时、次、吨、兆帕等，部分长文档会包含连续多班次的汇总数据。

## 这些特征在「部署与升级」这一环带来什么约束
煤矿生产台账的实时性与长文档特征，对部署与升级环节提出明确约束。实时传感器数据的高频推送会增加数据库读写压力，需预留足够的连接资源以避免读写阻塞。长班次汇总文档的上传与解析，容易触发界面超时，需调整相关超时配置。升级过程中需避免中断正在运行的台账同步任务，否则会导致数据断档。多字段的台账数据需提前完成字段映射配置，否则会导致后续检索与汇总结果出现偏差。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，针对煤矿生产台账场景优化。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 100–200 个 | 应对高频的实时传感器数据读写请求，避免连接池耗尽 |
| `STORAGE_S3_ENDPOINT` | 按本地存储节点的内网地址填写 | 适配煤矿内网的存储服务，保障大文档上传速度 |
| `REDIS_URL` | 内网Redis集群地址，连接超时设为60秒 | 缓存高频查询的台账汇总结果，降低数据库压力 |
| `FILE_TOKEN_KEY` | 随机生成的32位字符串 | 保障上传令牌的安全性，防止未授权的大文件上传 |
| `MONGODB_URI` | 带读写分离配置的内网连接地址 | 分离实时数据写入与历史数据查询，提升系统稳定性 |
| `ROOT_KEY` | 按部署手册生成的安全密钥 | 初始化系统管理员权限，保障部署后的权限管控 |

## 容易做错的三处
- 上传长班次汇总台账时界面显示timeout，但后台显示上传成功。原因是未调整大文件上传的超时配置，默认超时时长不足以覆盖长文档的解析与传输耗时。
- 工作流无法触发多轮台账汇总对话。原因是未正确配置`REDIS_URL`，导致对话上下文无法被持久化缓存，每次请求都重置为初始状态。
- 修改系统密码后无法正常重启服务。原因是未停止所有关联的FastGPT容器进程，直接重启会导致配置文件未被正确加载，同时密码变更未同步到所有运行实例。

## 怎么确认配好了
- 上传一份标准的煤矿班次台账文档，观察界面上传状态与后台解析日志，确认上传无超时且解析完成。
- 发起一次多轮台账汇总对话，观察对话上下文是否被保留，确认`REDIS_URL`配置生效。
- 查看数据库连接池状态，确认当前连接数未超过`DB_MAX_LINK`的设定值。
- 登录系统后台，确认`ROOT_KEY`对应的管理员权限正常，可正常创建与编辑台账汇总工作流。
