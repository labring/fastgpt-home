# 电网企业的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
数据来源为电网企业内部的SCADA调度系统、营销业务应用系统、设备资产管理系统。核心设备台账按季度同步更新，运营类台账每日更新。数据为结构化JSON格式，包含设备唯一标识、设备名称、额定容量、投运日期、所属线路节点、累计运维记录数等字段，单位涵盖千伏安、天、条等，单条台账数据长度普遍在800-1200字符区间。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多系统来源要求接口需支持多端点对接，需通过`Authorization`头统一管理跨系统鉴权。不同更新节奏要求配置差异化的轮询触发规则，核心设备台账接口触发间隔设置为不短于1天，运营类台账接口可设置为1小时。单条数据长度较大，要求HTTP请求超时时间不低于600秒，避免因传输超时导致数据截断。结构化字段要求接口返回的`responseData`需按预设字段映射，避免全量解析带来的性能损耗。

## 配置怎么定
本配置基于FastGPT v4.17.0版本制定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization`头配置 | 携带Bearer格式的系统专属令牌 | 适配多外部系统的统一鉴权要求 |
| 请求超时时间 | 600-900秒 | 匹配单条台账数据的传输长度 |
| `variables`映射规则 | 按台账字段名与应用变量一一绑定 | 实现结构化数据的精准字段传递 |
| `responseData`解析规则 | 仅提取预设的核心业务字段 | 降低接口响应的解析开销 |
| 轮询触发间隔 | 核心设备台账1天，运营类台账1小时 | 匹配不同类型台账的更新节奏 |

## 容易做错的三处
- 调用接口返回connection error，原因是未正确配置`Authorization`头的令牌格式，或外部系统接口未开放对应访问权限。
- 调用接口返回的结果未包含预设的台账匹配内容，原因是未将台账数据源参数绑定到`variables`中，导致接口请求未携带正确的数据源触发条件。
- 平台测试与接口返回结果不一致，原因是接口请求的上下文设置未匹配平台测试的上下文规则，或未同步更新外部系统的台账数据源。

## 怎么确认配好了
- 发起一次测试接口请求，检查返回的`responseData`是否包含预设的核心业务字段。
- 查看接口调用日志，确认`Authorization`头已正确携带且未被拦截。
- 在平台测试环境发起相同业务的请求，对比接口返回与平台测试结果的字段一致性。
- 等待预设的轮询间隔后，再次发起请求，确认数据已按更新节奏同步更新。
