# 电网企业的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
电网企业的台账数据主要来源于输电巡检、变电运维、营销缴费等业务系统，更新节奏涵盖按天生成的巡检日报、按月更新的设备运维月报、按季度归档的年度运营台账。单条台账包含结构化字段如设备ID、额定电压、运行时长、缺陷等级，以及非结构化的巡检照片摘要、故障排查记录，字段单位包含kV、A、小时、台套等专业计量标识，文档长度从数百字符到数千字符不等。

## 这些特征在「向量模型与索引」这一环带来什么约束
电网台账的结构化字段与专业计量单位，要求向量模型需具备领域语义适配能力，避免通用模型对专业术语的误匹配。多更新节奏的数据源，要求索引需支持增量更新与全量更新两种模式，适配不同台账的更新频率。长文本台账与多字段组合的特征，要求分块策略需保留关键上下文，防止跨分块的设备关联信息丢失。同时，台账条目数量庞大，需平衡索引召回效率与检索精度，避免资源浪费。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配电网台账单条结构化记录加附件摘要的文本长度，避免语义断裂 |
| 重叠长度 | 150–250 字符 | 保留相邻分块的设备ID、运行参数等关键上下文，防止信息割裂 |
| `maxToken` | 8192 token | 匹配FastGPT v4.17.0支持的主流开源embedding模型上下文上限，适配长台账报告 |
| `defaultToken` | 按实测标定 | 适配系统默认的token分配规则，避免索引过程中内存溢出 |
| embedding模型 | 电网领域微调的开源向量模型 | 适配电网专业术语如kV、缺陷等级、台区编号的语义匹配需求 |
| 相似度阈值 | 0.70–0.75 | 区分同类型设备台账的相似程度，避免检索结果冗余 |

## 容易做错的三处
- 现象：调用OpenAPI接口创建的QA拆分文件集合，检索响应耗时超过30秒。原因：未配置合理的分块长度与重叠长度，导致分块数量超出系统阈值，索引加载与检索耗时增加。
- 现象：界面显示索引模型从`text-embedding-ada-002`变为其他版本，检索结果出现专业术语匹配错误。原因：未指定领域适配的embedding模型，系统默认更新后使用通用模型，无法适配电网专业语义。
- 现象：检索结果返回的台账条目字段为空，如设备ID缺失。原因：分块时未保留结构化字段的完整信息，导致向量嵌入丢失关键标识字段。

## 怎么确认配好了
- 登录FastGPT v4.17.0的知识库管理页面，查看当前索引的配置项，确认分块长度、重叠长度、embedding模型与预设值一致。
- 上传一条包含专业术语的变电设备台账文档，执行检索测试，核对返回结果的相似度是否在预设阈值区间内，无冗余相似条目。
- 查看索引生成的后台日志，确认无`maxToken`溢出报错，且`defaultToken`分配符合系统资源限制。
- 对比启用与未启用领域embedding模型的检索结果，确认专业术语匹配精度符合业务预期。
