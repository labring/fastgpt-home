# 电网企业的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
电网企业的台账数据来源覆盖SCADA监控系统、电网营销系统、设备运维管理系统等多个业务系统。数据更新节奏分为两类：设备基础台账按季度同步更新，营销计量、运维记录类台账按日或实时更新。单份台账文档包含多表关联结构，核心字段包括设备编号、电压等级（单位：kV）、额定运行电流（单位：A）、安装位置、运维周期、用户编号、用电量（单位：kWh）等，部分台账附带巡检照片、杆塔航拍图等视觉附件。

## 这些特征在「模型接入与配置」这一环带来什么约束
多表关联的台账结构要求模型接入时需配置字段映射规则，确保跨系统的设备、营销、运维数据能正确关联汇总；带单位的核心字段要求配置中保留原始单位解析逻辑，避免数据精度丢失；实时或高频更新的台账数据需限制单次请求的上下文长度，防止超出模型处理上限；附带巡检照片、航拍图等视觉附件的台账需开启视觉识别能力，确保图片类台账内容能被正确提取。此外，电网企业业务数据需符合内网访问安全要求，接口配置需适配企业内网域名与专属认证规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启 | 台账中包含设备巡检照片、杆塔航拍图等视觉类附件，需识别图片内的设备编号、缺陷描述等内容 |
| `maxContext` | 8000–12000 token | 电网台账单条记录字段较多且存在多表关联，需保留足够上下文以确保数据关联正确 |
| `maxTokens` | 4000 token | 单份汇总报告的输出长度需控制在合理范围，避免超出模型输出限制 |
| `temperature` | 0.1–0.3 | 台账汇总与报告生成需保持数据准确性，降低生成内容的随机性 |
| `AIPROXY_API_ENDPOINT` | 按企业内网部署地址填写 | 适配电网企业内网数据访问的安全要求，避免公网暴露 |
| `AIPROXY_API_TOKEN` | 按企业分配的专属密钥填写 | 保障接口调用的身份认证安全，防止未授权访问 |

## 容易做错的三处
- 现象：新建模型配置后原有同类型配置被覆盖；原因：未为不同应用分配独立的`AIPROXY_API_TOKEN`，复用同一密钥导致配置冲突。
- 现象：调用模型时频繁返回429 Request rate increased too quickly报错；原因：未限制单次请求的台账数据量，未合理设置`maxContext`参数，导致请求速率超出模型限制。
- 现象：删除body参数后再次进入配置页，参数仍存在且无法彻底清除；原因：未保存配置修改操作，或FastGPT v4.17.0版本的页面缓存机制导致参数重置。

## 怎么确认配好了
- 传入单条设备台账的结构化数据与对应巡检照片，检查模型是否正确提取设备编号、电压等级等字段，且视觉附件内容被准确识别。
- 发起多台账汇总请求，查看返回结果是否包含跨系统关联的数据，无字段缺失、单位错误或格式混乱问题。
- 连续发起10次以上的批量汇总请求，确认无429报错，接口调用状态稳定。
- 为不同应用创建独立的模型配置，检查各配置的`AIPROXY_API_TOKEN`互不相同，无配置覆盖情况。
