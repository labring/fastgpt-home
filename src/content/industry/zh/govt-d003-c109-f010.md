# 电网企业的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
电网企业的台账数据主要来自PMS2.0生产管理系统、营销业务应用系统、调度SCADA系统，涵盖设备运维台账、电量统计台账、线路巡检台账三类核心文档。数据更新以每日增量同步为主，每周执行一次全量刷新。文档包含标准化结构化字段与非结构化附件，结构化字段含设备编号、运行电压、巡检日期、缺陷等级，对应单位为千伏、千瓦时、千米等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多来源的结构化字段与非结构化附件并存，要求检索链路需同时支持结构化字段匹配与全文语义召回，覆盖设备编号、电量数值等不同类型的检索需求。每日增量更新的特性要求召回流程需对接实时数据同步接口，确保检索结果包含最新的台账条目。单条台账文档可能包含长文本巡检报告附件，需限制单条召回文档的上下文长度，防止超出模型输入上限。标准化的字段与单位要求检索时需关联字段语义与对应单位，避免出现单位不匹配的无效召回结果。

## 配置怎么定

| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 匹配电网台账的结构化字段与语义内容，过滤低相关性的召回结果 |
| `limit` | 前12条 | 覆盖单份台账报告的关联数据量，避免单次召回过多导致上下文溢出 |

| `usingReRank` | 开启 | 对初始召回结果进行重排序，提升高相关台账条目的展示优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题生成扩展查询词，覆盖巡检报告、电量统计等不同场景的检索需求 |
| `collectionIds` | 按实测标定 | 绑定专属的电网台账知识库集合，隔离不同业务线的检索数据 |

## 容易做错的三处
- 现象：检索结果中出现乱码的设备台账字段，界面返回字段值为“��”。原因：未配置适配电网台账文档的编码解析规则，无法正确处理GBK编码的巡检报告附件。
- 现象：调用检索接口时返回400错误，提示“未找到匹配的向量数据库集合”。原因：未正确绑定专属知识库集合的`collectionIds`参数，未匹配自建Qdrant实例的访问权限与数据映射规则。
- 现象：巡检报告的分段内容割裂，同一章节的内容被拆分到不同召回结果中。原因：未启用基于Word文档目录的分段逻辑，仅使用固定长度分段规则，导致章节语义被打断。

## 怎么确认配好了
- 输入设备编号“10kV-001”执行精准检索，核对返回结果的字段与单位是否与源台账一致。
- 触发每日增量数据同步后，检索新增的线路巡检台账，确认结果包含最新更新的条目。
- 查看检索结果的重排得分，确认高相关的台账条目排在结果列表的靠前位置。
- 测试长文本巡检报告的检索，确认返回的上下文长度未超出模型输入限制。
