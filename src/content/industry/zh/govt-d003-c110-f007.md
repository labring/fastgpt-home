# 矿山采选的台账汇总与报告生成：数据库与运维

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
矿山采选的台账数据来源包括采矿设备实时传感器、选矿流程PLC控制系统、地磅称重系统、安全巡检表单等。数据更新节奏差异明显：设备运行参数为秒级实时更新，地磅称重数据为班后批量上传，安全巡检台账为每日更新。单条台账文档包含设备ID、测点名称、采集时间、数值、单位、巡检人、异常标记等字段，其中单位包含吨、立方米、小时、百分比等特定行业格式，无统一的固定字段结构，部分非结构化数据需单独存储。

## 这些特征在「数据库与运维」这一环带来什么约束
秒级实时数据的高频写入要求数据库连接池具备足够容量，避免连接耗尽导致服务中断。多源数据的异构格式要求数据库同时支持结构化与非结构化存储，需兼顾查询效率与写入灵活性。每日更新的巡检台账需要定时批量处理，需配置稳定的定时任务调度机制。字段附带的特定单位要求写入时增加合法性校验，防止脏数据进入数据库。单台账表的长期累积会导致数据量快速增长，需规划分表策略以保障查询性能，同时需为高频查询的测点字段建立索引。

## 配置怎么定

| 配置项               | 建议取法                                  | 这样取的依据                                                                 |
|----------------------|-------------------------------------------|------------------------------------------------------------------------------|
| 数据库连接池大小     | 20–30                                     | 匹配矿山采选每秒数十条的实时数据写入请求，避免连接耗尽                         |
| MongoDB 连接地址     | `mongodb://user:pass@host:27017/mine_collect` | 存储非结构化的传感器原始数据与半结构化巡检记录                                 |
| PostgreSQL 连接地址  | `postgresql://user:pass@host:5432/mine_report` | 存储结构化的台账汇总字段，支持复杂统计查询                                     |
| Redis 连接地址       | `redis://:pass@host:6379/0`                | 缓存高频查询的测点数据，降低数据库查询负载                                     |
| 定时任务执行间隔     | 86400 秒                                  | 适配每日更新的巡检台账汇总流程                                                 |
| 缓存过期时间         | 300 秒                                    | 适配实时测点数据的更新频率，平衡缓存命中率与数据新鲜度                         |

## 容易做错的三处
- 现象：本地部署后无法创建数据库，界面提示数据库连接失败。原因：未正确填写`MONGODB_URI`或`PG_URL`参数，或数据库服务未启动、对应端口未开放防火墙权限。
- 现象：并发请求上升时，模型回答延时显著增加，日志显示MongoDB写入操作耗时过长。原因：数据库连接池大小配置不足，无法支撑矿山采选多源数据的并发写入与查询请求。
- 现象：并发超过阈值时返回429状态码，无法正常生成报告。原因：未在应用配置中设置并发限流，直接调用外部模型接口超出服务商的并发限制。

## 怎么确认配好了
- 登录数据库管理工具，输入`MONGODB_URI`对应的连接地址，验证能否成功连接并查看已创建的矿山采选相关集合。
- 执行结构化台账的查询语句，验证`PG_URL`对应的数据库能否正常返回包含设备ID、采集时间等字段的记录。
- 发起10个并发的台账汇总请求，查看数据库连接池的使用情况，确认连接数未超过配置的上限。
- 查看Redis监控面板，确认高频测点数据的缓存命中率符合预期，无大量重复数据库查询。
