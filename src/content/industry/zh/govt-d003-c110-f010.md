# 矿山采选的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
矿山采选的台账数据来源于生产执行系统（MES）、设备PLC控制系统、现场巡检记录本、选矿流程参数报表等。更新节奏：设备运行日志每小时更新，巡检记录按班次每日更新，月度汇总台账按自然月归档。单篇文档对应单台设备或某班次的生产记录，包含设备编号、运行时长、出矿量、选矿品位、异常工况记录等字段，单位涵盖小时、吨、克/吨等专业单位。单篇文档长度从数百字符的单次巡检记录，到数千字符的月度生产汇总不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源数据的更新节奏差异，要求知识库向量更新需按数据类型分批次执行，避免全量更新占用过多资源。专业字段与单位的存在，要求检索时需匹配语义与字段格式，避免将不同设备的参数混淆。长文档占比高，分块时需保留专业术语的完整性，防止拆分后破坏生产流程的逻辑关联。台账数据的业务关联性强，单次检索需召回多段关联数据，以支撑汇总与报告生成的需求。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 矿山采选台账包含大量专业术语与相似字段，阈值过低会混入无关的设备日志，过高会遗漏相关参数段落，按实测标定 |
| `limit` | 前8条 | 单篇台账文档较长，单次召回过多会超出上下文窗口，过少无法覆盖关联的生产环节数据 |
| `searchMode` | hybrid | 结合关键词与向量检索，匹配台账中的设备编号、出矿量等明确字段与语义关联的流程描述 |
| `usingReRank` | 开启 | 矿山采选数据的专业关联性强，重排可以过滤掉语义相似但业务无关的召回结果 |
| `datasetSearchUsingExtensionQuery` | 开启 | 针对用户的台账汇总请求，自动扩展为关联的生产参数查询，覆盖更多业务相关的数据 |
| `collectionIds` | 绑定矿山采选专属台账集合 | 避免检索到其他品类的文档，确保召回范围精准 |

## 容易做错的三处
- 现象：回答中未显示引用的文档来源，仅返回纯文本内容。原因：未开启知识库的文档溯源配置，或未在生成环节配置引用字段的展示逻辑。
- 现象：检索结果中未包含原文档中的内嵌图片内容。原因：未启用知识库的图片向量化与召回配置，仅对文本内容进行了向量存储。
- 现象：指定appId后无法检索到已上传的台账文档。原因：未将对应知识库集合ID绑定到指定appId，或上传的文档未归入该专属集合。

## 怎么确认配好了
- 发起包含具体设备编号与生产参数的查询，检查返回结果中是否包含对应的文档来源标识。
- 上传包含内嵌图片的台账文档，发起相关查询，检查结果中是否正确展示图片相关内容。
- 调用指定appId的检索接口，传入矿山采选专属关键词，检查返回结果是否仅包含该品类的台账数据。
- 调整`similarity`参数值，观察召回结果的相关性变化，确认阈值设置符合业务需求。
