# 矿山采选的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
矿山采选的台账数据主要来自采矿调度系统、选矿流程DCS控制系统、磅房称重终端、现场安全巡检设备。数据按生产班次更新，每班结束后完成批量同步，关键生产节点数据实时推送。单条台账文档包含作业区域编号、开采量、设备运行时长、物料输送量、巡检记录编号等字段，对应单位为吨、小时、立方米、次。文档以结构化表单为主，单条条目数据量稳定，批量汇总时单批次数据量随生产规模波动。本页内容适配FastGPT v4.17.0版本。

## 这些特征在「部署与升级」这一环带来什么约束
矿山采选的台账结构化特征与混合更新节奏，对部署环节带来多重约束。批量同步的大批次数据需要适配足够的数据库连接池，避免写入阻塞。实时节点数据与班后批量更新的混合场景，要求配置合理的缓存过期与数据库超时参数。矿山多部署在内网环境，需适配内网专属的存储与数据库连接配置。台账字段随生产流程调整的可能性，要求升级环节保留旧字段兼容逻辑，避免强制变更导致业务中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30` | 适配矿山采选批量台账同步的大连接需求，避免连接池耗尽 |
| `MONGODB_URI` | `mongodb://内网Mongo地址:端口/矿山台账库` | 存储非结构化巡检记录与历史台账备份，适配内网部署场景 |
| `REDIS_URL` | `redis://内网Redis地址:端口/0` | 缓存实时生产节点数据，降低数据库查询压力 |
| `STORAGE_S3_ENDPOINT` | `内网MinIO地址:端口` | 存储台账导出的PDF、Excel报告文件，适配内网无公网访问的环境 |
| `ROOT_KEY` | `按企业内网安全规范自定义密钥` | 保障系统内部接口调用的身份验证安全，符合矿山内网安全要求 |

## 容易做错的三处
- 部署后数据库连接报错，提示`Access denied for user 'xxx'@'xxx'`。原因是未将FastGPT容器网络与数据库网络配置为互通，或数据库未开放对应内网端口。
- 调用台账生成接口响应缓慢，curl直接调用模型接口正常。原因是未配置`REDIS_URL`缓存实时数据，导致每次请求都重复查询全量台账数据库，或`DB_MAX_LINK`设置过低导致连接等待超时。
- 升级后无法生成台账报告，导出字段为空。原因是升级时未保留旧台账字段的兼容映射，新配置覆盖了原有字段定义，导致系统无法读取原有台账数据。

## 怎么确认配好了
- 执行`docker-compose logs`查看数据库与FastGPT容器日志，确认无数据库连接超时或拒绝报错。
- 发起单条台账汇总请求，等待响应后检查生成的报告文件是否包含对应作业区域的字段数据。
- 在内网环境通过curl调用FastGPT的内部接口，确认返回的台账数据字段与源系统一致。
- 触发批量台账升级同步任务，检查存储服务是否生成对应批次的备份文件。
