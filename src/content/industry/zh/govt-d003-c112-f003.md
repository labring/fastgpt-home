# 粮食储备的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
粮食储备的数据主要来自库区日常巡检记录、出入库凭证、月度盘点报表、质检报告。数据更新节奏随业务动作变化，出入库操作实时生成新条目，月度盘点完成后更新全库库存汇总。单份台账文档包含粮食品类、入库批次、出入库数量、当前库存余量、质检等级、存储仓位编号等字段，单位统一使用吨、公斤、批次号与仓位编码，时间字段采用标准公历日期格式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源分散的数据来源要求多轮对话按业务逻辑分步调取数据，先获取出入库明细再整合盘点结果，避免一次性加载超出处理能力的冗余信息。实时更新的出入库数据要求提示词明确指定时间范围参数，确保调用最新的台账条目。字段与单位的标准化要求提示词固定输出格式，强制匹配吨、批次号等指定单位，防止出现单位混淆。结构化的台账字段需要在对话中逐一校验，确保每个字段的取值符合库区业务规则，避免生成错误的汇总报告。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `messages` | 按业务步骤拆分的多轮对话序列，每轮包含用户提问与AI回复 | 适配多轮校验台账数据的交互逻辑，避免单次请求过载 |
| `variables` | 包含粮食品类、时间范围、库区编号的键值对 | 精准定位目标台账数据，缩小查询范围，提升调用效率 |
| `chatId` | 唯一会话标识，每轮对话生成新值 | 确保每个会话的上下文被正确隔离，避免不同会话的变量互相干扰 |
| 上下文窗口限制 | 8000–12000 token | 适配台账汇总所需的多轮数据加载，避免截断关键字段信息 |
| 单次调用输出上限 | 前200条台账条目 | 控制单轮返回的数据量，防止并发场景下的资源占用过高 |
| 并发调用阈值 | 1秒1–2次 | 匹配实际业务的调用频率，避免触发工作流限流 |

## 容易做错的三处
- 并发调用量达到1秒2-3次时，工作流节点返回空值。原因：触发了工作流最大运行次数限制或批量输入长度阈值，导致请求被限流丢弃。
- 生成的汇总报告中，最后一个变量的结果会叠加前一个变量的内容。原因：未在`variables`配置中明确隔离不同轮次的对话上下文，导致变量缓存未被清空。
- 配置了输入引导与词库后，对话界面未显示预期引导问题。原因：未开启对话界面的引导功能开关，或词库的匹配规则未绑定到当前会话场景。

## 怎么确认配好了
- 发起单轮测试请求，传入已知的库区台账数据，核对返回的汇总报告是否包含所有指定字段与单位。
- 模拟1秒1–2次的并发请求，检查工作流节点的返回结果是否均为有效内容，无空值情况。
- 查看对话界面的引导区域，确认是否显示配置的输入引导问题与词库匹配项。
- 检查`chatId`参数的配置，确保每个会话的上下文被正确隔离，避免不同会话的变量互相干扰。
- 确认当前使用的FastGPT版本为v4.17.0，确保配置项的兼容性。
