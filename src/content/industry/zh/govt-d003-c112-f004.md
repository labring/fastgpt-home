# 粮食储备的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
粮食储备的数据来源包括粮库出入库管理系统、仓储环境监测终端、粮油质检档案、轮换执行台账。数据更新节奏分为实时、每日、月度：出入库数据随作业完成实时更新，每日库存盘点数据当日汇总，月度轮换台账在当月执行完毕后更新。文档结构分为结构化台账文件与非结构化质检报告，结构化字段包含粮食品类、入库批次、库存体量、存储仓号、质检日期，单位为吨、批次、仓号。非结构化质检报告包含仓储环境记录、粮食品质检测项，无固定格式。

## 这些特征在「工作流编排」这一环带来什么约束
结构化与非结构化数据混合的特征，要求工作流先配置结构化数据提取节点，再关联非结构化质检报告的关键词提取环节。实时更新的出入库数据，要求工作流配置触发式启动节点，匹配实时更新的节奏。多字段关联的需求，要求工作流中设置`variables`存储入库批次、存储仓号等关键标识，用于跨节点的数据联动。不同更新节奏的数据对应不同的业务场景，实时出入库数据触发单次台账更新流程，月度轮换数据触发季度汇总报告流程，需为不同场景配置独立的工作流分支。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按第三方API回调触发 | 匹配粮食储备出入库数据实时更新的节奏，实现即时台账更新 |
| `variables` | 存储入库批次、存储仓号 | 用于跨节点联动同一批次的出入库、质检与轮换数据 |
| `nodeId` | 绑定至数据拉取节点 | 用于精准定位跨工作流的数据联动节点 |
| 问题优化 | 开启 | 减少台账多字段带来的检索冗余，优化后续AI处理逻辑 |
| 单次请求数据上限 | 前100条 | 适配单批次出入库作业的常规数据体量 |
| 超时设置 | 600秒 | 覆盖跨系统拉取数据、文档处理与报告生成的平均耗时 |
| 节点执行顺序 | 数据拉取→变量存储→问题优化→报告生成 | 遵循数据处理的先后逻辑，避免未获取数据即执行后续环节 |

## 容易做错的三处
- 现象：工作流执行至第三方API调用节点后无后续反馈，状态显示为超时。原因：未配置超时设置，或超时阈值设置过短，无法覆盖跨系统拉取粮食储备数据的耗时。
- 现象：工作流执行至特定节点后中断，无法稳定复现全流程。原因：未使用`variables`存储关键标识，跨节点无法联动同一批次的台账数据，导致特定批次数据缺失时流程中断。
- 现象：模型生成的报告内容无法传递至后续处理节点，仅能在AI对话窗口显示。原因：未配置节点间的变量传递规则，仅依赖AI对话节点的默认输出，未将处理结果绑定至指定输出节点或`variables`。

## 怎么确认配好了
- 触发对应业务场景的工作流，核对是否能自动拉取匹配的粮食储备数据，确认触发逻辑生效。
- 查看工作流中的变量存储节点，核对`variables`存储的入库批次、存储仓号等标识是否能在跨节点间正常传递。
- 执行完整工作流流程，核对各节点的执行状态均为成功，无异常报错或中断提示。
- 调整测试数据的体量，确认单次请求数据上限的配置适配当前测试数据的规模。
