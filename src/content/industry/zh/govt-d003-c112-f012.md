# 粮食储备的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
粮食储备的台账数据来源于粮库仓储管理系统的入库出库称重记录、库存盘点报表、季度质检报告。数据更新节奏分为实时（入库出库操作即时生成单条记录）、每日汇总（当日库存异动统计）、月度上报（全仓库存台账与分析报告）。单条台账文档包含粮食品类、批次号、入库时间、出库数量、库存余量、质检等级、存储仓号等字段，重量单位为吨，数量单位为袋或公斤，文档长度从几十字符到数千字符不等。

## 这些特征在「部署与升级」这一环带来什么约束
粮食储备台账数据的多源接入需求，要求部署时同时配置结构化与非结构化数据的存储连接。不同更新节奏的数据源需要匹配对应的数据同步周期配置，避免实时数据积压或月度数据生成延迟。文档长度跨度大的特性，要求存储配置适配从短文本到长文档的读写性能，同时多字段的台账结构需要提前规划数据库索引策略，避免检索时性能下降。升级过程中需保留原有批次号、质检等级等核心字段的映射规则，防止台账数据解析异常。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的部署规范制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 20–30 个并发连接 | 适配每日汇总的批量数据写入与实时单条记录的并发请求 |
| `MONGODB_URI` | 对应粮库仓储系统的非结构化台账文档库地址 | 存储批次号、质检报告等非结构化台账数据 |
| `PG_URL` | 对应粮库结构化库存统计数据库地址 | 存储入库出库数量、库存余量等结构化字段数据 |
| `REDIS_URL` | 本地私有网络内、内存不低于2048 MB的缓存服务地址 | 缓存实时入库出库的临时数据，降低数据库读写压力 |
| `STORAGE_S3_ENDPOINT` | 企业内部对象存储服务的接入端点，单文件上限设为1000 MB | 存储完整的月度报告PDF、质检扫描件等大体积文件 |
| `ROOT_KEY` | 按企业内部权限规则生成的32位随机字符串 | 配置平台管理员的初始访问权限，保障部署安全 |

## 容易做错的三处
- 访问OneApi页面返回502状态码，且日志显示数据库连接超时。原因是未配置`DB_MAX_LINK`的合理取值，导致并发连接数超出数据库上限，服务无法正常响应前端请求。
- 多账号无法加入同一团队，且团队管理页面无用户添加入口。原因是未正确配置`ROOT_KEY`对应的管理员权限，未开启团队成员管理功能，导致普通账号无法完成团队关联。
- 台账数据导入后字段为空，且生成的报告无库存余量数据。原因是未将`PG_URL`与粮库结构化数据库的正确表名绑定，导致数据读取时无法匹配库存余量字段。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的系统内置数据库测试工具，分别验证`MONGODB_URI`与`PG_URL`的连通性，确认可以读取预设的测试台账数据。
- 触发一次临时的台账汇总任务，检查生成的报告是否包含所有预设字段，且数据与源系统的统计结果匹配。
- 查看缓存服务的监控指标，确认`REDIS_URL`的连接数处于正常区间，无频繁的连接断开或超时情况。
- 使用管理员账号创建新团队并添加测试账号，确认团队成员管理功能可以正常启用。
