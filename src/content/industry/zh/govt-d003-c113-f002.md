# 船舶制造的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
船舶制造的台账数据来源为分段建造工序记录、物料领用单、质检报告、分段装配台账等。更新节奏按建造节点划分，工序台账每日更新，物料台账每周汇总，月度提交完整质检台账。单条文档结构包含分段编号、工序名称、作业时间、作业人员、物料型号、检验结果、合格判定等字段，单位涵盖毫米、吨、小时等标准化工业计量单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
单条台账数据长度跨度较大，短工序记录仅数十字符，长物料汇总可达数千字符，会影响分块后的向量编码一致性。按节点的增量更新特性，要求索引支持按需触发的增量同步，避免全量重建的资源消耗。字段包含带单位的结构化数值，向量模型需适配这类带单位的字段编码，否则会降低检索匹配精度。多工序台账存在跨文档的关联关系，索引需支持跨分段的关联召回，避免生成孤立的局部结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 平衡船舶制造台账的长文本与短条目，避免分块破坏工序逻辑 |
| 重叠长度 | 50–100 字符 | 保留跨分块的连续作业描述，确保关联工序的上下文完整 |
| 相似度阈值 | 0.72–0.80 | 过滤带单位的结构化数据的低匹配度结果，提升检索精准度 |
| 单次搜索上限 | 前 10 条 | 适配台账汇总报告的核心数据量，避免超出上下文窗口限制 |
| `maxToken` | 4000 token | 适配FastGPT v4.17.0的默认上下文窗口，覆盖单份完整台账的汇总需求 |
| 重排模型 | 按实测标定 | 不同私有化部署的重排模型适配性存在差异，需结合本地数据验证效果 |

## 容易做错的三处
- 现象：启动外部索引同步时报错“连接超时”，状态码返回504。原因：未配置船舶制造台账的增量拉取接口权限，导致索引服务无法正常获取源数据。
- 现象：向量检索返回的结果仅覆盖单个分段，无法关联同一船舶的其他工序台账。原因：未开启跨文档关联召回配置，未匹配船舶制造台账的多工序关联特性。
- 现象：重排模型返回的结果中物料单位混淆，出现“千克”与“吨”的错误匹配。原因：未对台账中的单位字段做标准化清洗，导致向量编码丢失单位关联信息。

## 怎么确认配好了
- 查看索引同步日志，确认每日增量更新与全量重建任务均正常触发，无报错记录。
- 输入特定工序的检索关键词，核对返回结果的分段编号、作业时间等字段与源台账一致。
- 调整相似度阈值与单次搜索上限，验证返回结果的数量与匹配度符合业务需求。
- 测试跨分段的关联检索，确认能召回同一船舶的多工序台账数据。
