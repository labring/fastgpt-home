# 船舶制造的台账汇总与报告生成：多轮对话与提示词

以下配置基于FastGPT v4.17.0版本适配。

## 这个品类的数据长什么样
船舶制造的台账数据来源于生产管理系统（MES）、物料管理系统（WMS）、质检系统的日常导出文件，更新节奏随单船建造进度调整，单船建造周期内按每日或每周更新。单份台账文档包含单分段或单船的多维度条目，字段涵盖船籍港编号、分段工序节点、物料规格型号、检验合格率、累计工时等，单位涵盖米、吨、小时、%、件等，结构为结构化表格形式，每个条目绑定唯一的分段编号与建造批次标识。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
船舶制造台账的多维度字段与混合单位要求多轮对话需先明确查询的船名、分段编号等核心标识，避免跨船数据混淆。多系统来源的台账数据格式存在细微差异，提示词需预设字段映射规则，确保不同来源的数据可统一识别。单船台账条目数量较多，长文档会占用大量上下文空间，需限制每次召回的条目范围，避免超出对话上下文承载上限。高频更新的台账数据要求每次对话都拉取最新数据集，不宜依赖过期的上下文缓存。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定单船建造的专属chatId | 实现不同船型、不同分段的对话上下文隔离，避免数据串扰 |
| `variables` | 预设船名、分段编号、统计周期三个变量 | 快速定位目标台账条目，减少用户重复输入的信息 |
| 最大上下文长度 | 8000–12000 字符 | 适配单船多分段台账的总条目长度，避免上下文溢出 |
| 问题优化 | 开启 | 将用户口语化的船舶工序描述转换为标准化的台账字段查询条件 |
| 单次召回上限 | 前20条 | 控制每次传入对话的台账数据量，保证响应速度 |
| 会话持久化 | 按实测标定 | 适配免登录链接的会话存储需求，避免误删操作影响日志留存 |

## 容易做错的三处
- 调用工具获取台账数据后，下一轮对话无法读取返回结果。原因：未将工具输出写入`messages`参数的assistant角色内容中，导致上下文未保留工具执行结果。
- 配置`chatId`后，后台对话日志未显示该参数。原因：未在API请求的请求体中正确携带`chatId`字段，或前端界面未绑定对应会话标识。
- 免登录链接生成的对话，删除单条会话后后台日志同步消失。原因：未配置会话存储的持久化规则，免登录会话默认使用临时存储逻辑。

## 怎么确认配好了
- 发起一次针对特定船名和分段的台账查询，核对对话日志中是否携带`chatId`参数，确认上下文隔离配置生效。
- 测试多轮对话流程，先请求单类台账的明细数据，再请求该类数据的汇总统计，核对返回结果是否关联前一轮的查询条件。
- 生成免登录链接并发起会话，执行删除会话操作，核对后台日志是否保留该会话的完整记录，确认持久化配置正确。
- 测试表单接点提交功能，核对对话界面是否生成可交互的输入控件，确认渲染配置正确。
