# 轨道交通装备的台账汇总与报告生成：工作流编排

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
轨道交通装备的台账数据来源于设备运维管理系统、无损探伤检测系统、零部件出入库系统。单台设备台账包含设备编号、维保日期、探伤合格状态、更换部件型号、累计运行时长等字段，单位为台、次、小时。批量汇总台账以Excel格式存储，单设备台账为结构化JSON文件，每次维保、探伤作业完成后即时更新，批量台账每日凌晨完成跨系统同步。

## 这些特征在「工作流编排」这一环带来什么约束
轨道交通装备台账的多系统异构来源，要求工作流编排中配置跨数据源拉取节点，适配运维、探伤、出入库三个系统的不同数据接口格式。不同更新节奏的台账数据，需要同时支持事件触发（单次作业后即时触发）与定时触发（每日凌晨批量同步）两种启动模式。台账字段包含带单位的运行时长、部件型号等信息，要求工作流内置字段映射与单位标准化节点，避免汇总时出现单位不统一的问题。批量Excel台账存在合并单元格、空行等格式问题，需要配置数据清洗节点预处理原始数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源节点类型 | 多源拉取组合节点 | 适配运维、探伤、出入库三个系统的不同数据接口 |
| 触发方式 | 事件触发+定时触发双模式 | 覆盖单设备即时更新与批量每日同步的需求 |
| 字段映射规则 | 按设备编号关联匹配，统一运行时长单位为小时 | 解决多系统字段命名差异与单位不统一问题 |
| 数据清洗阈值 | 过滤空行、合并单元格拆分阈值为800–1200字符 | 适配批量Excel台账的常见格式异常 |
| `variables` | 预设设备编号、统计周期变量 | 支持按指定设备或周期生成定制化报告 |
| 报告生成模板 | 按台账字段预设标准模板 | 确保报告结构与轨道交通装备台账格式一致 |

## 容易做错的三处
- 现象：工作流执行后输出中夹杂知识库搜索的input和response片段。原因：未在工作流节点中关闭上下文引用开关，导致工具调用时携带了知识库检索内容。
- 现象：工作流中使用问题分类节点时，轨道交通装备的专业术语（如“轮对探伤”）识别准确率低。原因：未针对轨道交通装备领域调整分类模型的提示词，通用模型无法适配专业字段。
- 现象：接入外部MCP插件后工作流出现超时报错。原因：未配置`nodeId`对应的超时阈值，插件调用时长超过默认限制。

## 怎么确认配好了
- 手动触发单设备台账拉取，核对数据源节点返回的字段与实际台账的字段名称、内容一致。
- 调整`variables`中的统计周期变量，运行工作流后确认报告仅包含对应周期内的台账数据。
- 导入带有合并单元格的批量Excel台账，检查数据清洗节点是否完成格式修复与内容提取。
- 禁用知识库上下文引用开关，运行工作流后验证输出中未出现检索相关的片段。
