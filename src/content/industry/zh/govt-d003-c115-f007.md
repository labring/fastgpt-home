# 轨道交通装备的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
轨道交通装备台账数据主要来自车载运行传感器、线下检修工单系统与设备出厂档案。传感器数据实时上传，检修工单数据每日同步归档，出厂档案为静态批量导入。单条台账文档包含设备唯一编号、车型型号、检修执行时间、更换部件清单、累计运行时长、触发故障代码等字段，累计运行时长单位为小时，故障代码由大写字母加4位数字组成，单条文档平均包含12个核心字段。

## 这些特征在「数据库与运维」这一环带来什么约束
实时上传的车载传感器数据会产生高频小批量写入请求，要求数据库连接池支持高并发低延迟的连接分配。每日批量同步的检修工单数据体量较大，需要数据库支持批量插入事务以避免导入超时。字段包含固定单位的数值与格式固定的故障代码，需要在数据库层面配置校验规则，防止无效数据写入。设备唯一编号作为核心主键，要求数据库支持唯一索引约束，避免重复台账录入。静态出厂档案的批量导入需要数据库支持大文件读取与批量存储。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[账号]:[密码]@[主机地址]:27017/rail_equipment?authSource=admin` | 适配轨道交通装备台账的非结构化与半结构化数据存储，指定专属数据库名与认证源 |
| `PG_URL` | `postgresql://[账号]:[密码]@[主机地址]:5432/rail_maintain?schema=public` | 用于存储格式固定的检修工单与设备档案，支持复杂查询与事务操作 |
| `DB_MAX_LINK` | `200–300 个连接` | 平衡实时传感器数据的高并发写入需求与数据库连接资源占用，避免连接耗尽 |
| `REDIS_URL` | `redis://[主机地址]:6379/0` | 用于缓存高频访问的设备基础信息，降低数据库查询压力 |

## 容易做错的三处
- 现象：编排流程中连接MongoDB时返回`Failed to connect`报错，后台Mongo状态检查显示失败。原因：未在`MONGODB_URI`中指定正确的认证源与专属数据库名，或账号密码配置有误。
- 现象：批量导入检修工单数据时出现连接超时错误。原因：未调整`DB_MAX_LINK`参数至适配高并发批量写入的取值，数据库连接池耗尽导致请求超时。
- 现象：尝试使用数据库连接工具连接Oracle数据库时，界面提示不支持的数据库类型。原因：当前版本仅内置MongoDB、PostgreSQL、SQL Server三类数据库驱动，未集成其他数据库的连接驱动。

## 怎么确认配好了
- 登录数据库管理工具，使用配置的连接地址与账号密码尝试连接，验证连接是否正常。
- 导入一条模拟的轨道交通装备台账数据，检查数据库中是否成功写入且字段格式符合预设规则。
- 查看FastGPT后台的数据库监控面板，确认连接数处于配置的`DB_MAX_LINK`取值范围内，无连接耗尽提示。
- 触发一次台账汇总与报告生成流程，检查是否能正常读取数据库中的设备数据并生成对应报告。
