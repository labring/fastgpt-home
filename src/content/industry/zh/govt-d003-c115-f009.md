# 轨道交通装备的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
轨道交通装备的台账数据来源于车载运行传感器、线下检修系统、零部件寿命数据库与运维管理平台。数据更新节奏分为两类：车载实时运行数据每秒更新，离线检修台账按每日或每周同步。单份台账文档包含结构化字段与非结构化附件，结构化字段包括设备编号、累计运行时长（单位：小时）、检修周期（单位：天）、故障代码、更换时间，非结构化附件为PDF格式的检修报告与故障排查记录。数据多源异构，既有关系数据库存储的结构化记录，也有文本格式的手工填报内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
车载实时数据的高频更新要求模型调用需控制上下文长度，避免因数据量过大导致超时。多字段的结构化台账与特定单位的参数，要求模型准确识别语义与格式，防止生成错误的SQL语句。非结构化检修报告的长度差异较大，需适配长文本处理逻辑。跨系统数据源的接入需求，要求配置统一的模型代理地址。合规性要求下，需优先选择国内部署的大模型，避免数据跨境传输风险。

## 配置怎么定
本页面配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 覆盖多台轨道交通设备的历史台账与实时运行数据，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 完整输出台账汇总与报告生成的结果，防止关键统计信息被截断 |
| `toolChoice` | auto | 自动触发SQL生成与文本提取工具，适配多源数据的混合处理场景 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保SQL语句格式与台账字段匹配的稳定性 |
| `AIPROXY_API_ENDPOINT` | 填写国内模型代理的标准地址 | 适配国内部署的大模型，符合数据合规要求 |
| `AIPROXY_API_TOKEN` | 填写对应模型的访问密钥 | 完成模型接入的身份验证，保障调用权限 |

## 容易做错的三处
- 生成的SQL语句执行失败，查看日志发现关键字与字段间无空格，仅移除了换行符。原因是未针对轨道交通台账的多字段结构调整`temperature`参数，导致模型简化了格式输出。
- 长文本检修报告生成被截断，查看任务状态显示输出长度超出限制。原因是未根据单份报告的预估长度调整`maxTokens`取值。
- 无法接入指定的国内模型，界面提示API鉴权失败。原因是错误使用了海外模型的访问密钥，未替换为对应国内模型的`AIPROXY_API_TOKEN`。

## 怎么确认配好了
- 发起一次针对单台设备台账的测试调用，查看返回的SQL语句是否包含正确的空格分隔关键字与字段。
- 提交包含多台设备的批量台账数据，确认生成的汇总报告完整覆盖预设的统计维度，无内容截断。
- 调用配置的国内模型代理地址，验证是否能正常返回模型响应，无鉴权或连接报错。
- 调整`temperature`参数至0.2，发起三次重复测试，查看生成的SQL语句格式是否保持一致。
