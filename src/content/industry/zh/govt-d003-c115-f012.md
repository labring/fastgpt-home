# 轨道交通装备的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
轨道交通装备的台账数据来自车载运行传感器、线下检修系统、备件管理模块，更新节奏为实时采集运行参数、每日同步检修记录、每月更新备件库存。单条台账文档包含设备唯一编号、型号规格、累计运行时长、上次检修日期、备件更换明细等字段，单位涵盖运行小时、检修次数、备件尺寸毫米、润滑油升等，部分文档附带高清检修照片与运行日志附件。

## 这些特征在「部署与升级」这一环带来什么约束
轨道交通装备台账的数据来源分散、更新频率不均，部署时需支持多数据源对接与并发写入，因此数据库连接池配置需适配高并发场景。升级过程中不能中断实时数据同步，需采用滚动升级策略，避免因服务重启导致的运行参数丢失。结构化字段与附件混合存储的特性，要求知识库同时支持关系型与非结构化数据的索引，升级时需兼容旧版数据格式，避免迁移失败。此外，台账数据的字段与单位存在行业专属规则，部署时需确保知识库的字段映射规则与行业标准一致，避免数据解析错误。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 150–200 个 | 轨道交通装备台账数据来源多、更新频率高，需支持并发连接与批量写入 |
| `MONGODB_URI` | mongodb://mongodb:27017/fastgpt | 存储检修报告附件、历史对话记录与非结构化台账片段 |
| `REDIS_URL` | redis://redis:6379/0 | 缓存高频访问的设备台账快照，降低关系型数据库的查询压力 |
| `FE_DOMAIN` | https://your-gpt-domain.com | 用于配置前端嵌入页面的访问地址，适配已有系统的域名规则 |
| `FILE_TOKEN_KEY` | 32位随机字符串，按实测标定 | 保护台账附件的下载权限，避免未授权访问 |
| `STORAGE_S3_ENDPOINT` | http://minio:9000 | 存储批量导出的月度台账汇总报告，适配本地对象存储服务 |

## 容易做错的三处
- 现象：启动容器时出现`connection refused`报错，无法连接数据库。原因：`MONGODB_URI`或`REDIS_URL`填写的地址未正确指向本地部署的服务容器，或防火墙未开放对应端口。
- 现象：执行Docker Compose重启后，历史对话记录与设备台账缓存未被清除。原因：未配置`REDIS_URL`对应的持久化卷，会话缓存数据未随容器删除而清空。
- 现象：生成的台账报告附件无法正常下载。原因：`FILE_TOKEN_KEY`配置错误，导致附件下载权限校验失败，无法生成有效访问链接。

## 怎么确认配好了
- 执行`docker ps`命令，确认MongoDB、Redis、前端服务与API服务容器均处于运行状态。
- 调用台账同步接口，传入模拟的轨道交通装备设备编号，检查返回的字段是否包含设备型号、运行时长等必填项，无空值。
- 上传一份轨道交通装备的检修报告PDF，触发台账汇总任务，确认任务状态显示为完成，且生成的报告包含正确的汇总数据。
- 访问`FE_DOMAIN`配置的地址，确认前端页面能正常加载，且能调用API获取设备台账数据。
