# 通信工程建设的台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
通信工程建设的台账数据主要来自工程管理系统、现场巡检终端、物料采购与验收系统，更新节奏随工程节点推进，单次工程周期内每日或每周更新。文档形式包含单份10万中文字以上的验收报告、15000行以上的物料台账excel，结构按标段划分，核心字段包括标段编号、物料名称、规格型号、进场数量、验收日期、施工班组、监理签字状态，单位涵盖米、套、吨、工作日等工程专用计量单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
通信工程台账的大体积与专业字段特征，对多轮对话与提示词配置形成多重约束。首先，单份文档体量较大，直接传入全量数据会超出模型上下文上限，需通过分块解析与会话状态管理拆分数据。其次，专业字段与单位容易引发歧义，提示词需明确指定字段定义与计量单位，避免生成错误汇总结果。再次，数据更新频率较高，多轮对话中需每次调用最新数据源，提示词需包含拉取最新数据的指令。最后，多轮对话中用户可能切换标段、查询不同类型物料，需通过会话标识保留历史查询状态，确保上下文连贯。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 通信工程台账包含多字段与长文档，需足够上下文容纳历史对话与解析数据 |
| 会话状态保存 | 自动生成持久化`chatId` | 多轮对话中需保留标段切换、数据查询的历史上下文，确保会话连贯 |
| 提示词模板变量 | 传入当前标段编号、数据更新时间 | 精准匹配对应台账数据源，避免调用过期或错误数据 |
| 对话消息历史保留条数 | 前15–25条 | 平衡上下文完整性与token消耗，防止超出模型上限 |
| 文件分块长度 | 1500–2000 字符 | 适配通信工程台账的excel行数据与word段落结构，减少关联数据拆分 |
| 超时时间 | 90–150 秒 | 适配大文件解析与多轮数据查询的响应需求，避免中途中断 |

## 容易做错的三处
- 现象：调用对话接口上传15000行的通信工程台账excel后，返回结果的物料数量与原始数据不符，原因：未配置适配工程台账的文件分块参数，导致数据拆分时丢失相邻行的关联信息。
- 现象：对话输出延迟超过设定阈值，界面显示超时状态，原因：未调整超时时间配置，大文件解析与多轮数据查询未适配通信工程台账的体量，未优化分块与查询逻辑。
- 现象：会话token消耗统计出现偏差，部分对话的token用量未被正确记录，原因：未开启会话token统计功能，或未将`messages`数组中的历史消息与分块文件的token消耗纳入计算。

## 怎么确认配好了
- 上传一份15000行的通信工程台账excel，发起多轮对话查询指定标段的物料总数量，核对返回结果与原始数据的统计结果一致。
- 查看会话详情页面，确认`chatId`随对话自动生成且持久化存储，每次切换标段后会话状态正确更新，返回对应标段的数据。
- 发起包含10万中文字验收报告的对话，查看接口返回的token消耗数据，与实际解析的字符数换算结果匹配。
- 调整超时时间为90秒，发起包含大文件的对话，确认响应时间未超过设定阈值，无超时报错。
