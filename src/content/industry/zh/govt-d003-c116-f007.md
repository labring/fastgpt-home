# 通信工程建设的台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
通信工程建设的台账数据来源于施工现场记录系统、监理单位提交的验收文档、材料出入库凭证与设备调试档案。数据更新节奏随项目节点完成实时同步，月度完成全项目台账汇总。单条台账文档包含项目唯一标识、工程阶段分类、物料规格型号、使用数量、安装部位、施工班组信息、验收日期、监理确认状态，字段单位涵盖米、平方米、千克、天等工程常用单位，部分字段需关联项目合规性审核状态。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构的数据来源要求数据库支持跨系统数据拉取与格式适配，避免因数据源字段差异导致的入库异常。实时节点更新与月度汇总的双重节奏，需要配置增量同步脚本与全量备份任务，平衡数据时效性与存储资源占用。工程专属的字段与单位要求数据库表结构预留扩展字段，适配后续新增的验收维度，同时需建立数据校验规则，确保单位转换与数值合法性。台账数据关联项目合规性，运维环节需开启数据审计日志，留存所有修改操作轨迹，保障数据可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/fastgpt_communication?authSource=admin` | 适配通信工程台账的多文档存储需求，符合FastGPT v4.17.0版本的文档型数据库配置规范 |
| `PG_URL` | `postgresql://user:pass@host:5432/communication_report?sslmode=require` | 存储结构化台账字段与合规审计日志，保障数据事务一致性与访问安全性 |
| `DB_MAX_LINK` | `20–30` | 通信工程台账单次汇总需处理多批次数据，避免连接数不足导致的写入超时，同时控制数据库负载 |
| `REDIS_URL` | `redis://:pass@host:6379/0` | 缓存实时更新的节点台账数据，降低高频查询对主数据库的压力 |
| 数据校验规则 | 按工程字段单位预设校验模板 | 适配物料数量、工期等专属单位的合法性检查，避免入库数据格式错误 |

## 容易做错的三处
- 现象：升级FastGPT版本后，原有通信工程台账数据未在知识库中同步显示。原因：未执行完整的数据库迁移脚本，未将PG库中的结构化台账字段正确映射至文档存储集合。
- 现象：月度全项目台账汇总任务触发超时，返回504状态码。原因：`DB_MAX_LINK`配置值低于并发写入请求数，导致数据库连接池耗尽，写入请求排队超时。
- 现象：新建问题分类节点保存或运行报错，切换AI模型后恢复正常。原因：数据库连接池配置不足，默认AI模型调用时触发连接耗尽，切换模型后重新建立连接。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`与`PG_URL`配置的连通性，确认无认证或地址错误。
- 提交单批次小型台账数据入库，检查数据校验规则是否按工程单位自动过滤非法数值。
- 触发一次实时节点台账同步任务，确认增量数据同步完成且无格式转换异常。
- 查看REDIS缓存日志，确认实时更新的台账数据被正确缓存，降低主数据库查询压力。
