# 通信工程建设的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
通信工程建设台账数据来自施工管理、物资领用、竣工验收等多个内部业务系统，更新节奏随施工节点推进，每日或每周同步一次。单份完整台账文档包含工程编号、项目名称、施工区域、材料规格、领用数量、验收状态、负责人等数十个字段，单位涵盖米、立方米、套、工时等，部分字段存在多单位混用的情况。

## 这些特征在「模型接入与配置」这一环带来什么约束
通信工程建设台账的多源、高频更新与多字段特征，对模型接入与配置带来三点约束。第一，多系统拼接的台账文本长度波动较大，需严格限制上下文窗口大小，避免模型因输入过长导致推理失败。第二，字段单位不统一且数量较多，需模型在生成报告时自动对齐单位，因此需配置合适的随机性参数。第三，数据更新频率较高，需合理配置缓存策略，避免调用过时的台账数据影响报告准确性。本指南适用于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 通信工程建设台账单份文档长度可达数千字符，需适配长上下文输入 |
| `maxTokens` | 2000–3000 token | 台账汇总报告需包含多字段整理与结论，需足够的输出长度 |
| `quoteMaxToken` | 1500 字符 | 需保留足够的原始台账片段作为报告引用依据 |
| `temperature` | 0.2–0.4 | 台账数据需准确对齐字段与单位，需降低生成结果的随机性 |
| `AIPROXY_API_ENDPOINT` | 按云平台服务商提供的接入地址填写 | 适配私有化部署的云大模型推理地址 |
| `AIPROXY_API_TOKEN` | 按云平台生成的密钥填写 | 完成模型调用的身份验证 |

## 容易做错的三处
- 测试模型时返回404错误。原因是模型ID填写与云平台中配置的模型标识不一致，未匹配实际可用的模型名称。
- 容器报错Api response error: /api/core/ai/model/test?model=Doubao-l。原因是`AIPROXY_API_TOKEN`配置错误，或云平台未开放对应模型的调用权限。
- 生成的报告出现字段单位混乱的情况。原因是`temperature`取值过高，模型生成时未严格对齐台账的原始单位字段。

## 怎么确认配好了
- 进入模型提供商配置页面，填入`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`后，点击测试按钮，确认返回正常响应。
- 上传一份典型的通信工程台账文档，触发模型调用，检查生成的报告是否完整包含所有核心字段。
- 调整`temperature`参数后，多次调用同一台账文档，确认生成结果的字段与单位一致性符合预期。
- 切换不同的云平台模型，验证聊天对话框中模型切换功能正常，且各模型调用均能返回有效结果。
