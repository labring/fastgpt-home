# 通信铁塔与基础设施的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
数据来源包括基站运维管理系统、现场巡检终端上报、动力环境监控设备、铁塔权属登记档案。更新节奏分三类：基础权属台账按季度更新，巡检记录随每次现场作业提交，告警与运行状态数据实时同步。单条台账文档包含铁塔唯一编号、经纬度坐标、建设时间、维护责任人、巡检记录列表、告警日志、配套电源与天线参数等字段，单位涵盖米、小时、次、十进制度等，单份完整台账包含多段长文本内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据的更新节奏差异要求模型调用需适配不同数据的时效性，实时告警数据的突发量可能导致上下文溢出。结构化字段多且单位各异，要求模型输出需严格匹配字段格式与单位，避免数据混淆。长文本巡检记录与多条目告警日志的拼接，会大幅增加上下文总长度，需限制单次加载的上下文范围。不同铁塔的台账数据相互独立，需避免跨任务的数据混入，保证报告仅包含指定范围的铁塔信息。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多源台账的长文本拼接需求，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 满足单份结构化报告的生成长度，适配台账汇总的输出要求 |
| `temperature` | 0.2–0.4 | 降低随机生成概率，保证台账数据的准确性与格式一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的地址填写 | 适配国内大模型代理服务的访问路径，解决跨区域访问延迟问题 |
| `AIPROXY_API_TOKEN` | 与代理服务绑定的专属密钥 | 保障模型调用的身份验证安全，避免未授权访问 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具处理结构化台账数据，提升汇总效率 |

## 容易做错的三处
- 现象：配置多个名称相同的大模型时，调用时出现密钥不匹配报错或返回结果不符合预期。原因：未为每个模型分配独立的`AIPROXY_API_TOKEN`与专属标识，系统无法精准区分不同模型实例。
- 现象：工作流节点生成的报告混入其他铁塔的台账数据。原因：未限定上下文仅加载当前任务关联的铁塔数据，默认使用全局上下文导致无关信息被纳入。
- 现象：界面中模型厂商图标显示为灰色占位符。原因：未正确配置`AIPROXY_API_ENDPOINT`的资源访问路径，前端无法拉取对应厂商的图标资源。

## 怎么确认配好了
- 提交单份指定铁塔的台账数据进行测试，核对生成的报告是否包含该台账的全部核心字段，无无关数据混入。
- 配置多个同名模型并发起多次调用，核对每次调用是否使用了指定的`AIPROXY_API_TOKEN`对应的模型，返回结果符合预期。
- 检查前端界面的模型图标是否正常显示，确认资源路径配置无误。
- 模拟批量导入多份台账数据，核对模型调用是否在设定的上下文范围内正常处理，无上下文溢出报错。
