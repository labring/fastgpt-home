# 金属材料加工的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
数据主要来自生产执行系统（MES）、原材料入库台账、在线质检设备与成品出库系统。更新节奏随生产批次触发，单批次加工完成后生成对应台账条目。文档结构包含炉批号、加工工序参数、原材料牌号、在线检测数值、成品规格、流转节点记录。字段包含字符型的炉批号、数值型的加工温度、时长，以及日期型的流转时间，单位分别为无标识、摄氏度、分钟、天。单份台账文档长度随加工工序复杂度浮动，通常处于300-800字符区间。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
台账按生产批次生成且来源分散，接口需支持按炉批号、流转时间范围作为查询参数，避免全量拉取引发的资源占用过高。字段包含多类型数据，接口需兼容数值型、字符型与日期型参数的传递与解析。单份文档长度适中但批次间数据量波动较大，接口需支持分页返回，防止单次请求负载超限。数据来自多个内部系统，接口需配置多源数据聚合逻辑，确保台账信息完整。同时，因内部系统访问受限，接口需适配内网部署的访问规则，避免跨域或权限校验失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {专属API密钥}` | 用于接口身份校验，适配内网访问的权限控制 |
| `variables` | `{"batch_no": "目标炉批号", "start_date": "加工完成日期"}` | 传递台账查询的过滤参数，匹配按生产批次拉取的需求 |
| `responseData` | 仅返回炉批号、加工参数、质检结果字段 | 过滤冗余数据，聚焦台账汇总的核心信息 |
| 请求超时时间 | 30-60 秒 | 金属材料加工的台账需聚合多系统数据，该时长可覆盖多数场景 |
| 单次返回条数 | 前 10 条 | 单批次台账数据量适中，过多条目会增加后续处理负载 |
| 多源数据聚合配置 | 按实测标定 | 不同内部系统的接口格式存在差异，需根据实际对接情况调整 |

## 容易做错的三处
- 调用接口时返回401 Unauthorized报错，或自定义连接测试直接失败。未正确配置`Authorization`参数，或密钥格式未添加`Bearer `前缀，导致身份校验失败。
- 接口调用超时，或返回空的台账数据。请求超时时间设置过短，未匹配金属材料加工多系统数据聚合的实际耗时，导致请求提前中断。
- 内网通过nginx反向代理访问后，上传关联数据或调用接口出现异常。未在nginx配置中转发必要的请求头，未适配内网部署的权限控制规则，导致服务无法正常接收请求。

## 怎么确认配好了
- 执行预设的curl测试命令，检查返回的响应状态码与预期一致，且包含核心台账字段。
- 在FastGPT的接口调试界面中填入正确参数后发起测试，确认无报错且返回数据符合预期的批次范围。
- 查看系统运行日志，确认接口请求的参数被正确解析，无格式错误或权限拦截记录。
- 触发台账汇总与报告生成的流程，检查生成的报告中包含的字段与配置的`responseData`参数一致。
