# 金属材料加工的台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
金属材料加工的台账数据主要来自生产设备实时采集的工艺参数、离线质检报告、仓库出入库单据。数据更新节奏按生产批次触发，单批次加工完成后同步更新。单份台账文档包含结构化字段与非结构化附件，结构化字段包括炉号、批次号、抗拉强度（MPa）、硬度（HRC）、入库日期，非结构化附件包含金相显微照片、工艺参数记录单。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化字段与非结构化附件混合的数据特征，要求向量模型同时支持文本与图像嵌入，避免拆分后丢失字段关联。按生产批次的更新节奏，要求索引支持增量同步，避免全量重建带来的资源消耗。多单位混合的数值字段，需要在分块时保留字段标识，确保检索时能匹配对应工艺参数。单份文档的多类型内容，要求索引的分块策略兼顾文本与附件的关联关系，防止信息断裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配单份台账的结构化字段与非结构化文本的平均长度，避免分块过碎丢失关联 |
| 重叠长度 | 50–100 字符 | 保留相邻分块的字段关联，防止跨块的工艺参数信息断裂 |
| `maxToken` | 8192 | 适配主流多模态向量模型的输入上限，覆盖单批次台账的完整分块内容 |
| 相似度阈值 | 0.75–0.85 | 区分金属材料的工艺参数相似度，避免将不同批次的炉号数据误匹配 |
| 单次搜索上限 | 前 10 条 | 匹配台账汇总的批量处理需求，兼顾检索效率与召回完整性 |

## 容易做错的三处
- 现象：界面弹出“多模态向量模型不兼容当前索引配置”报错，原因：未同时配置文本与图像嵌入模型，仅适配单类型向量输入，无法处理台账中的金相照片附件。
- 现象：检索结果返回条数远少于预期，仅返回个位数条目，原因：相似度阈值设置过高，过滤掉了符合业务要求的批次数据。
- 现象：检索结果混入非目标品类的材料数据，原因：混用了其他行业的向量模型与索引配置，未针对炉号、批次号等专属字段设置过滤规则。

## 怎么确认配好了

- 上传单份包含金相照片与工艺参数的标准台账文档，检查向量嵌入任务是否正常完成，无报错提示。
- 模拟检索“抗拉强度”“炉号”等专属字段关键词，核对返回结果的字段是否包含对应标识。
- 新增一份测试批次的台账数据，检查索引是否自动同步更新，无需手动触发全量重建。
- 对比不同分块长度下的检索召回范围，确认当前配置的召回结果符合业务需求。
