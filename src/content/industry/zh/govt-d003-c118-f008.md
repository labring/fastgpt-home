# 金属材料加工的台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
金属材料加工的台账数据主要来自生产车间的质检记录、投料台账、成品出库单及设备运行日志，更新节奏随生产批次推进，每日或每班生成新文档。文档多为固定格式的表格类PDF、Word或PPT，包含炉号、批次号、材质牌号、力学性能指标、单重、总重量等字段，单位涉及兆帕、千克、吨等工业常用单位，部分文档会附带现场拍摄的工艺照片作为附件。

## 这些特征在「文档解析与分块」这一环带来什么约束
固定格式的表格类文档要求解析时保留单元格结构，避免字段错位导致台账汇总错误。单份文档长度差异较大，短则几行表格，长则包含多批次数据的数十页内容，分块时需避免拆分完整的单批次数据条目。工业专用单位较多，解析环节需保留单位信息，防止后续报告生成时出现单位混淆。部分文档附带工艺照片，需同步提取图片内嵌文本，避免关键工艺参数遗漏。批量上传的高频需求要求解析环节具备稳定的并发处理能力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 金属材料加工台账单批次数据条目长度适中，该区间可完整包含单批次所有指标字段，避免分块拆分关键数据 |
| `chunkSplitter` | 按表格与段落混合拆分 | 文档包含固定格式表格与少量说明性段落，混合拆分可保留表格结构完整性，同时适配段落类说明文本 |
| `customPdfParse` | 开启 | 固定格式的工业台账PDF需启用自定义解析规则，精准提取表格字段，避免通用解析导致的单元格错位 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 部分批次汇总的PPT文档包含多张工艺照片，需支持较大文件上传，同时避免过大文件导致解析超时 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 多页长文档的解析需充足时间完成表格识别与文本提取，600秒可覆盖绝大多数单份文档的解析需求 |
| `chunkSettingMode` | 手动配置 | 金属材料加工台账格式固定，手动配置分块规则可适配专属文档结构，提升解析准确性 |

## 容易做错的三处
- 现象为上传Word或PPT文档解析时报错“the argument ‘windows-1252’ is invalid encoding”，原因是未启用适配工业文档编码的解析配置，通用解析引擎无法识别老旧文档使用的非UTF-8编码格式。
- 现象为批量上传多份台账文档时部分任务显示超时状态，原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以完成多页长文档的表格识别与文本提取。
- 现象为工作流中调用文档解析工具传入本地文件地址后返回空结果，原因是未正确配置自定义文件读取环境变量，或传入的文件地址未开放平台访问权限。

## 怎么确认配好了
以下核对动作适配FastGPT v4.17.0版本。
- 上传一份标准格式的金属材料加工台账文档，查看解析后的文本是否完整保留了炉号、材质牌号等核心字段，无单元格错位情况。
- 调整`chunkSize`参数后，查看分块结果是否未拆分单批次完整数据条目，可通过对比原始文档与分块后的文本内容验证。
- 上传包含多张工艺照片的PPT文档，确认解析结果中包含照片内嵌的工艺参数文本，无关键信息遗漏。
- 测试批量上传多份台账文档，确认解析任务均能在预设时长内完成，无批量超时报错。
