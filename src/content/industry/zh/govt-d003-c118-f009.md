# 金属材料加工的台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
金属材料加工的台账数据主要来自生产设备的实时传感采集、质检部门的电子报告单、物料仓储管理系统以及生产调度日志。数据更新节奏随加工批次完成触发，日常台账按每日或每班次同步。单条完整台账包含炉号、批次号、材质牌号、加工工序参数（如加热温度、轧制压力、保温时长）、核心质检指标（硬度、拉伸强度）、出入库数量与流向等字段。字段单位遵循工业标准，温度为摄氏度，压力为兆帕，时长为分钟，强度为兆帕，数量为吨。

## 这些特征在「模型接入与配置」这一环带来什么约束
首先，多源异构的数据格式差异要求配置字段对齐规则，避免模型混淆不同系统的同名字段，例如设备采集的“硬度”与质检系统的“硬度值”需统一映射为同一字段名。其次，数据更新分为批次触发与定时同步两种模式，需要匹配模型调用的触发时机参数，适配不同的汇总频率需求。再者，台账包含长文本质检报告与短数值字段，需调整上下文窗口参数以适配不同长度的输入内容，避免长文本被截断或短输入浪费上下文资源。最后，金属材料加工的专业术语如牌号、热处理工序等，需模型具备领域识别能力，因此需配置适配专业场景的模型参数，提升汇总报告的准确性。

## 配置怎么定
本文适配FastGPT v4.17.0版本，以下为针对该场景的配置建议：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配长文本质检报告与多批次台账汇总，避免截断核心工序数据 |
| `maxTokens` | 2000–3000 token | 控制单份报告生成的输出长度，匹配台账汇总的常规输出规模 |
| `quoteMaxToken` | 1500 token | 限定引用的台账原始数据长度，确保模型聚焦有效加工参数与质检结果 |
| `temperature` | 0.1–0.3 | 降低生成随机性，保证专业数值与字段的输出一致性 |
| `AIPROXY_API_ENDPOINT` | 本地部署的vllm/ollama服务地址，如`http://192.168.1.100:8000/v1` | 适配内部部署的金属材料领域微调模型，减少公网调用延迟 |
| `AIPROXY_API_TOKEN` | 对应部署服务的访问密钥 | 完成模型接入的身份验证，保障调用权限安全 |

## 容易做错的三处
- 现象：调用ollama模型时返回空内容，无报错日志。原因：未正确配置ollama服务的端口映射，或FastGPT容器与ollama容器未处于同一网络，导致请求无法正常送达模型服务。
- 现象：模型管理页面仅显示系统默认模型，无法找到配置的外部模型。原因：未启用AIPROXY功能，或未在配置项中填写正确的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`。
- 现象：选择标注为图像模型的接入项后，无法启用视觉输入选项。原因：未将`vision`配置项设置为启用状态，或接入的模型本身未开放视觉处理能力。

## 怎么确认配好了
- 进入FastGPT的模型管理页面，确认配置的外部模型已出现在可用模型列表中。
- 上传单份金属材料加工台账的测试数据，发起模型调用，检查返回的汇总内容包含完整的工序参数、质检指标与汇总结论。
- 查看模型调用日志，确认请求成功发送至配置的API端点，无连接超时或身份验证错误提示。
- 调整`temperature`参数的取值，观察生成的报告内容是否保持专业数值的一致性，验证参数配置生效。
