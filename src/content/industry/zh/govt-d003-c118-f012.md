# 金属材料加工的台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
金属材料加工的台账数据主要来自生产设备采集的工艺参数、质检部门的检验报告、仓储系统的出入库记录。数据按生产班次或批次更新，单份台账文档包含批次号、材料牌号、炉号、各工序加工参数、尺寸偏差、硬度值、合格率、出入库时间等字段，字段单位多为毫米（mm）、兆帕（MPa）、维氏硬度（HV）等行业通用标准单位，部分文档附带工艺流程图的扫描附件。

## 这些特征在「部署与升级」这一环带来什么约束
金属材料加工台账的数据来源分散，部署时需配置多数据源对接参数，确保不同系统的工艺、质检、仓储数据可同步汇总至知识库。按班次或批次的更新节奏，要求部署时设置合理的增量同步周期，避免全量同步占用过多服务器资源。字段包含专业工业单位，升级时需保留原有字段映射规则，避免知识库导入时单位识别错误导致数据异常。单份文档及附件的数据量较大，需调整存储与数据库的容量阈值，防止数据溢出影响服务稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt_metal?authSource=admin` | 存储台账的批次、工艺等结构化数据，需指定认证源与对应业务数据库名，适用于FastGPT v4.17.0及以上版本 |
| `REDIS_URL` | `redis://:custom_password@host:6379/1` | 缓存增量同步的批次标记与用户会话，使用1号库隔离业务数据避免与其他服务冲突 |
| `STORAGE_S3_ENDPOINT` | `http://s3-cn-beijing.aliyuncs.com`（或本地对象存储端点地址） | 存储大体积的质检报告扫描件与工艺参数日志，需匹配存储服务的访问端点 |
| `DB_MAX_LINK` | `20–30 个` | 金属材料加工台账的并发读写请求较多，限制数据库连接数避免资源耗尽 |
| `FE_DOMAIN` | `https://metal-processing-doc.your-domain.com` | 配置前端访问域名，确保台账生成后的报告链接可正常被访问 |
| `FILE_TOKEN_KEY` | `按实测标定的随机32位字符串` | 生成文件访问的临时令牌，保证唯一性与访问安全性 |

## 容易做错的三处
- 上传台账文件时提示`Failed to create post presigned url`，原因是未正确配置`STORAGE_S3_ENDPOINT`或对应的存储访问密钥，导致无法生成文件上传的预签名链接。
- 迁移服务器时未导出原有`MONGODB_URI`、`REDIS_URL`等核心配置信息，导致数据库与缓存服务无法正常连接。
- 部署在arm架构的银河麒麟Linux系统时，未使用对应arm架构的FastGPT docker镜像，导致容器启动失败或运行异常。

## 怎么确认配好了
- 执行数据库连接测试命令，验证`MONGODB_URI`与对应数据库的连通性。
- 上传一份小型金属材料台账样本文件，检查是否能正常生成上传链接并完成文件存储。
- 查看缓存服务的运行状态，确认`REDIS_URL`配置的服务可正常读写数据。
- 访问`FE_DOMAIN`配置的前端地址，检查台账汇总与报告生成功能的页面是否可正常加载。
