# 钢铁冶炼的台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
钢铁冶炼的台账数据来自生产执行系统（MES）、过程控制系统（PLC），包含冶炼批次标识、工艺节点参数、物料消耗数据、成品产出数据。更新节奏分三类：实时节点数据每30秒更新，班结数据每8小时更新，日结数据每日凌晨更新。数据以结构化格式存储，单条记录包含批次号、炉温、吨钢能耗、成品重量等字段，其中炉温单位为摄氏度，能耗单位为千克标准煤每生产单位，成品重量单位为吨。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
实时节点数据更新频率高，接口需要支持高频拉取或流式传输，避免单次请求超时。数据更新节奏存在差异，接口需要支持按不同周期配置轮询任务，适配实时、班结、日结三类数据的拉取需求。字段与单位存在行业特殊性，接口返回的字段名称与本地台账系统的字段无法直接复用，需要配置映射规则。批量日结数据体量较大，接口需要支持分页或分块传输，避免单次请求数据量超限。生产系统的接口通常需要鉴权，因此需要配置合法的`Authorization`参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 鉴权方式 | Bearer token | 匹配钢铁冶炼生产系统的通用接口鉴权规范 |
| 变量映射规则 | 配置批次号、炉温、能耗、产出量的字段映射 | 适配接口返回字段与本地台账系统的字段差异 |
| 响应数据处理 | 按`responseData`配置字段过滤与格式转换 | 确保返回数据符合本地系统的解析要求 |
| 轮询间隔 | 15–30 秒（实时数据）、8 小时（班结数据）、24 小时（日结数据） | 匹配对应类型数据的更新频率 |
| 批量数据阈值 | 1000 MB | 适配日结台账数据的最大体量 |
| 接口超时时间 | 600 秒 | 预留足够的批量数据传输耗时 |

本配置适用于FastGPT v4.17.0。

## 容易做错的三处
- 调用接口返回405状态码，现象为界面提示“请求方法不被允许”，原因是未使用生产系统要求的请求方法，例如使用GET请求批量下载接口，而该接口仅支持POST请求。
- 处理流式返回的实时数据时出现字段缺失，现象为生成的报告缺少部分工艺参数，原因是未配置分块数据的拼接规则，仅接收了最后一个分块的内容。
- `Authorization`配置错误导致鉴权失败，现象为返回401状态码，原因是使用了未授权的token，未采用生产系统分配的专用鉴权凭证。

## 怎么确认配好了
- 调用配置完成的接口，检查返回的HTTP状态码为200，且`Authorization`鉴权通过。
- 手动比对`variables`配置的字段映射关系，确认接口返回字段与本地台账系统的字段一一对应。
- 拉取单批次实时数据，检查`responseData`处理后的格式符合本地系统的解析要求。
- 发起批量日结数据请求，确认传输耗时未超过配置的超时时间。
