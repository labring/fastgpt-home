# 铁路运营的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
铁路运营台账的数据来源包括列车运行实时日志、票务销售记录、设备巡检档案、调度指令单、营收结算单据等。数据更新节奏差异明显，调度类日志实时更新，票务数据按小时同步，设备维保台账按日归档，营收报表按月生成。单份台账文档包含车次编号、时间戳、设备编码、运营里程、故障代码、营收金额等字段，单位涵盖公里、人次、小时、元等，字段类型包含字符串、数值、枚举值三类。

## 这些特征在「工具调用与插件」这一环带来什么约束
铁路运营台账的多源分散特性要求插件支持对接不同协议的数据源，包括实时流接口、批量文件存储、内部业务系统API。字段与单位的多样性要求工具调用的参数校验环节需匹配铁路台账的专属字段规则，避免参数类型不匹配或单位转换错误。不同更新频率的台账数据需要插件配置差异化的定时触发规则，确保汇总与报告生成的时效性符合业务要求。合规性要求工具调用的每一次操作都需留存调用日志，便于后续审计与溯源。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配铁路台账汇总与报告生成的多场景调用需求，自动匹配预设工具函数 |
| `functionCall` | `["generate_railway_summary", "generate_railway_report"]` | 对应铁路运营台账的两个核心工具函数，明确限定调用范围 |
| 插件密钥校验 | 开启并绑定内部系统白名单 | 符合铁路系统的身份验证要求，避免未授权访问 |
| 插件超时时间 | 300–600 秒 | 铁路单批次台账数据量较大，处理耗时较长，按实测标定 |
| 单次调用返回条数 | 前 20 条 | 控制单次上下文长度，避免超出模型处理上限 |

## 容易做错的三处
- 调用工具时返回401状态码，原因是未正确配置插件的密钥校验规则，导致FastGPT无法通过铁路内部系统的身份验证。
- 工具调用未触发预设的台账汇总函数，原因是将`toolChoice`和`functionCall`配置为禁用状态，导致无法调用自定义工具函数。
- 无法拉取铁路内部系统的台账数据，原因是未配置插件的内部网络代理，导致无法访问受保护的内部数据源。

## 怎么确认配好了
- 查看FastGPT的插件运行日志，确认工具调用请求携带了正确的内部系统密钥与身份标识。
- 传入模拟的铁路运营台账数据，调用测试工具，检查返回的汇总结果是否包含预设的字段与单位。
- 调整`toolChoice`配置为指定函数，验证是否能精准触发对应的台账生成工具。
- 检查插件的数据源连接状态，确认可以正常拉取铁路系统的实时或批量台账数据。
