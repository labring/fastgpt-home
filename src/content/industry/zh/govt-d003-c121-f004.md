# 高速公路运营的台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
数据主要来自收费站收费系统、路段监控平台、养护巡检终端、路政执法台账系统，按班次或自然日更新。单条台账包含结构化字段与非结构化附件，结构化字段含收费金额（元）、通行车次（辆）、养护作业里程（公里）、巡检时间（YYYY-MM-DD HH:MM）、设备故障编码，非结构化附件为现场照片、巡检笔录PDF。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据格式要求工作流先完成结构化字段提取与非结构化附件解析，避免格式混乱导致汇总错误。按班次/日的高频更新要求工作流支持定时触发或事件回调触发，确保台账数据能及时汇总。字段附带专属单位的特征，要求工作流在参数传递时保留字段标识与单位信息，防止统计时出现单位混淆。非结构化附件的长文本内容，要求工作流支持长文本切割与分段处理，适配下游节点的内容长度限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 定时触发周期 | `15–30 分钟` | 覆盖高速公路早、中、晚班的台账更新节奏，确保汇总时效符合运营要求 |
| `variables` | 包含源数据标识、字段单位的自定义变量 | 传递系统侧拉取的数据源路径与字段元信息，解决全局变量识别失效的问题 |
| `nodeId` | 绑定数据解析、汇总、报告生成节点的唯一标识 | 确保工作流按预设顺序执行，避免节点执行顺序混乱 |
| 长文本切割长度 | `800–1200 字符` | 适配高速公路巡检笔录、收费明细的单段处理上限，符合FastGPT v4.17.0版本的节点内容限制 |
| HTTP请求超时时间 | `60 秒` | 匹配多源数据拉取的平均响应时长，防止超时中断汇总流程 |
| 内容提取模型 | 按实测标定 | 适配高速公路台账的结构化提取需求，覆盖不同类型的非结构化附件解析 |

## 容易做错的三处
- 工作流运行时系统参数未正确传递，表现为全局变量中数据源路径字段为空。原因是未通过`variables`配置项显式声明系统侧传递的参数，仅依赖隐式调用导致识别失败。
- HTTP API返回长文本后未分段发送，表现为下游节点返回内容超出限制报错。原因是未配置长文本切割规则，直接将完整长文本传入发送节点。
- 内容提取节点调用失败，表现为节点返回空结果或报错提示不支持自定义模型。原因是未在节点配置中正确指定模型来源，或未按平台要求开启对应调用权限。

## 怎么确认配好了
- 手动触发一次工作流，查看运行日志中`variables`参数是否包含系统传递的数据源标识与字段单位。
- 模拟长度超过1000字符的巡检笔录文本，检查工作流是否按配置的切割长度自动拆分内容并分段发送。
- 查看内容提取节点的配置界面，确认已选择正确的模型来源并开启对应调用权限。
- 导出工作流输出的测试报告，与原始台账数据对比，确认所有字段与单位均被正确汇总。
