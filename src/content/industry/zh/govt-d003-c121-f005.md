# 高速公路运营的台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
高速公路运营的台账数据主要来自收费结算系统、路面养护巡检系统、路网监控系统三类数据源。收费台账按每15分钟为周期更新，记录站点编码、通行车辆数、实收金额、车道编号；养护台账按每日更新，记录养护路段、巡检时间、病害类型、修复状态；监控台账按实时推送，记录设备在线状态、流量峰值。所有台账文档均以结构化格式存储，字段包含统一的时间戳、区域编码，单位涵盖辆次、元、公里、百分比等。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据的同步周期差异要求插件调用需匹配各自的更新节奏，避免调用未完成更新的数据源。字段与单位的多样性要求工具调用时需预设字段映射规则，统一输出格式以适配报告生成。单站点月度台账数据量较大，批量调用时需分页处理，防止单次请求超出接口负载。跨系统的数据关联需求要求插件需支持多数据源的并行调用，确保汇总报告的完整性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 指定台账汇总专用工作流 | 明确绑定预设的高速公路运营台账处理逻辑，避免调用无关功能 |
| API密钥配置 | 绑定专属工作流密钥 | 隔离不同运营区域的台账数据访问权限，符合数据安全规范 |
| 批量调用间隔 | 10–15 秒 | 适配收费数据每15分钟的同步周期，避免重复调用未更新的数据源 |
| 超时时间 | 600 秒 | 覆盖单站点月度台账的汇总计算时长，防止中途中断任务 |
| 结果过滤规则 | 按站点ID、时间范围过滤 | 匹配高速公路运营按区域、周期生成报告的核心需求 |

## 容易做错的三处
- 调用工作流返回`401 Unauthorized`错误，原因是未配置正确的API密钥，或密钥未绑定对应台账汇总工作流的访问权限。
- 流数据接收中断后页面数据固定但后端任务仍在执行，原因是未配置流中断回调机制，未主动终止未完成的工具调用任务。
- Docker部署的FastGPT中无法找到`packages/plugins/register`文件，原因是该版本的插件注册路径已调整为`data/plugins`，需手动创建对应目录或通过后台界面完成插件配置。

## 怎么确认配好了
- 调用测试接口，传入指定站点的时间范围参数，检查返回结果是否包含站点ID、通行车辆数、实收金额等核心台账字段。
- 查看插件运行日志，确认`toolChoice`参数被正确设置为绑定的台账汇总工作流。
- 模拟流数据接收中断，检查后端是否触发任务终止逻辑，无残留后台进程。
- 核对配置的超时时间与实际数据处理时长，确保无超时报错提示。
