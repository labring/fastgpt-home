# 高速公路运营的台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
高速公路运营的台账数据主要来自收费结算系统、日常养护巡检平台、路政事件管理系统与路段监控系统。数据更新节奏分两类：实时类包含通行量、收费流水、临时路政事件，按分钟级更新；周期性类包含月度养护统计、季度通行趋势台账，按自然周期更新。单条台账文档包含路段编号、通行辆次、收费金额、巡检部位、事件等级、处置时长等字段，单位涵盖辆次、元、公里、小时等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
实时类数据的分钟级更新要求知识库索引的增量更新频率适配，否则召回结果滞后于最新运营数据。台账字段多且包含路段编号、事件等级等元数据，若未配置元数据过滤，检索结果会混入无关路段的台账，无法精准匹配指定路段的汇总需求。单条台账文档长度差异较大，短则百余字符，长则上千字符，会影响分块后的召回匹配精度。台账需按时间维度聚合指标，检索时需优先召回指定周期内的文档，这要求检索环节支持时间范围的元数据筛选。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 匹配高速公路台账的字段密度与术语专业性，过滤低相关性的非运营类文档 |
| `limit` | 前12条 | 单条台账文档长度差异大，限制召回条数避免上下文溢出，适配台账汇总的批量处理需求 |
| `searchMode` | hybrid | 结合关键词匹配与语义召回，覆盖收费术语、养护专有名词的精准匹配与语义关联检索 |
| `usingReRank` | 开启 | 对初始召回的台账文档按相关性与时间权重重排，优先返回近期的运营数据 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展台账汇总的检索词，补充“通行量汇总”“养护台账统计”等场景化查询词 |
| `collectionIds` | 绑定运营台账专属集合ID | 隔离其他品类的知识库数据，避免检索结果混入非高速公路运营的文档 |

## 容易做错的三处
- 检索结果混入非目标路段的台账文档，现象是返回的台账包含其他地市的路段编号字段，原因是未绑定专属集合ID或未启用元数据过滤规则，导致跨品类数据被召回。
- 生成的汇总报告未包含当日实时通行数据，现象是召回的台账最后更新时间早于24小时，原因是未配置增量索引的分钟级更新频率，且未通过`usingReRank`按时间权重排序。
- 应用仅召回知识库内的台账数据，无法调用联网搜索补充外部信息，现象是生成的报告未包含临时交通管制、路段施工等外部实时数据，原因是知识库检索环节默认限定数据源范围，未配置允许跨源检索的相关设置。

## 怎么确认配好了
- 进入知识库集合管理界面，核对绑定的专属集合ID是否仅覆盖高速公路运营台账数据。
- 发起包含路段编号与时间范围的测试查询，检查返回结果的字段是否符合高速公路运营台账的标准结构。
- 查看检索日志，确认初始召回条数与重排后的排序逻辑符合配置要求。
- 触发应用调用联网模型，验证是否能获取知识库外的外部信息，确认数据源限制配置正确。
