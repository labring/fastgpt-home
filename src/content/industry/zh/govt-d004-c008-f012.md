# 健康诊断报告的巡检监测与告警研判：部署与升级

## 这个品类的数据长什么样
健康诊断报告的数据来源于工业巡检终端采集的设备运行参数、人工巡检录入的状态台账，以及后端告警系统触发的异常日志。更新节奏随巡检任务触发，单次巡检生成的单份报告为一次性更新，批量巡检场景下按每日或每周固定周期同步。文档结构包含设备唯一标识、巡检时间戳、核心监测指标（温度、压力、电流等，带对应工程单位如摄氏度、兆帕、安培）、异常阈值匹配结果、自动研判的告警等级、人工复核意见字段。

## 这些特征在「部署与升级」这一环带来什么约束
多源数据接入要求部署时配置兼容工业协议的存储适配器，避免数据格式不兼容导致入库失败。高频更新的巡检报告与告警日志会产生大量写入请求，需调整数据库连接池参数适配并发负载。固定字段结构要求提前创建带索引的数据库表，避免升级时字段变更引发的写入异常。时效性要求高的告警研判数据，需配置合适的缓存过期策略，确保查询响应符合业务要求。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `150–250 个连接` | 适配多巡检终端并发写入的数据库连接需求，避免连接耗尽 |
| `MONGODB_URI` | 填写本地私有云MongoDB实例的完整认证连接串 | 健康诊断报告的告警日志与历史巡检详情适合用MongoDB存储非结构化数据 |
| `PG_URL` | 填写PostgreSQL实例连接串，配置连接超时为`60 秒` | 存储设备ID、巡检时间等结构化元数据，保障关系型查询稳定性 |
| `REDIS_URL` | 配置本地Redis实例地址，设置缓存键过期时间为`300 秒` | 缓存高频查询的巡检报告摘要，缩短告警研判的响应延迟 |
| `STORAGE_S3_ENDPOINT` | 填写私有对象存储的端点地址 | 存储巡检报告的原始附件与传感器原始采集数据 |
| `FILE_TOKEN_KEY` | 生成32位随机加密字符串 | 加密文件上传访问令牌，避免未授权访问报告文件 |

## 容易做错的三处
- 启动后出现`connection refused`报错，无法加载历史巡检数据。原因是未正确配置`MONGODB_URI`或`PG_URL`，指向了未启动或公网不可达的数据库实例。
- 上传的巡检报告附件无法被系统读取。原因是未配置`STORAGE_S3_ENDPOINT`指向私有对象存储，或`FILE_TOKEN_KEY`生成的密钥与上传接口不匹配，导致文件访问被拒绝。
- 升级后部分巡检报告的研判结果为空。原因是升级时未同步更新数据库的结构化索引，导致新的报告字段无法被检索和解析。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`与`PG_URL`的配置可以正常建立连接，无超时或拒绝错误。
- 上传一份测试用的巡检报告附件，验证`STORAGE_S3_ENDPOINT`配置正确，附件可正常存储并在系统内预览。
- 发起一次模拟巡检任务，生成健康诊断报告，验证`REDIS_URL`的缓存配置生效，报告查询响应时间符合预期。
- 检查`DB_MAX_LINK`的配置值，通过数据库监控工具确认当前连接数未超过设定的阈值，无连接耗尽情况。
