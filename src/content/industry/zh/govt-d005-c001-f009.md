# 12345热线工单办理的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自12345热线平台、承办单位业务系统、官方政策知识库、回访评价数据及地方热线管理办法，更新频率为每日。日常处理的文档包含诉求登记单、派单记录、办理答复、回访记录、延期申请、退回说明及政策知识库条目。数据围绕群众诉求闭环流转，涵盖诉求发起、派单、办理、反馈全流程的关联信息，需适配多源异构数据接入。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的数据源要求配置定时同步任务，确保政策与工单数据的时效性。多源异构的文档结构需要模型适配不同字段的解析逻辑，避免因格式差异导致的信息提取错误。围绕诉求闭环的业务逻辑，要求模型答复需严格匹配政策依据与工单历史，同时需控制响应时效以避免影响工单办理进度。此外，该品类无需生成法定审批结果，仅需提供合规的政策解释与办理指引，因此模型配置无需过度追求法定格式校验，重点保障内容的准确性与合规性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖工单历史、政策条目等多源上下文，匹配12345工单办理的多文档关联需求 |
| `maxTokens` | 2000–3000 token | 确保答复能完整呈现政策依据与办理指引，符合工单答复的篇幅要求 |
| `temperature` | 0.1–0.3 | 保持政策问答的严谨性，避免生成非标准口径内容 |
| `quoteMaxToken` | 1500–2000 token | 优先引用官方政策条目与工单历史数据，保证答复的合规性 |
| `AIPROXY_API_ENDPOINT` | 填写本地部署的代理地址 | 适配12345热线系统的内部网络访问限制 |
| `AIPROXY_API_TOKEN` | 填写分配的专属访问密钥 | 保障接口调用的安全性，防止未授权访问 |

## 容易做错的三处
- 现象：调用三方大模型接口返回403错误或连接超时，原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或内部网络策略限制了接口访问
- 现象：更换嵌入模型后，原有工单数据无法匹配政策条目，原因：未重建上下文索引，直接使用新模型处理旧数据导致向量空间不匹配
- 现象：答复内容被截断且不完整，原因：未合理设置`maxTokens`参数，超出模型输出的最大长度限制

## 怎么确认配好了
- 发起一条包含政策类诉求的测试工单，检查模型返回的答复是否准确引用了相关政策条目与历史工单信息
- 查看接口调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无连接报错或权限异常
- 测试更换嵌入模型后，重新导入历史工单数据，验证政策匹配结果无异常波动
- 调整`temperature`参数至合理区间后，检查答复内容的严谨性，无随意发挥或非标准口径表述
