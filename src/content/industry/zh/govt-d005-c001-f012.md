# 12345热线工单办理的政策与制度依据问答：部署与升级

## 这个品类的数据长什么样
该品类的数据通常来自12345热线平台、承办单位业务系统、官方知识库、回访评价数据及地方热线管理办法，更新频率为每日。日常处理的文档包含诉求登记单、派单记录、办理答复、回访记录、延期申请、退回说明及标准化知识库条目，数据字段涵盖诉求编号、承办单位、办理时限、答复内容、评价结果等，围绕群众诉求闭环形成完整业务链路。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[用户名]:[密码]@[地址]:27017/[业务库名]?authSource=admin` | 该品类的工单、知识库等非结构化业务数据需持久化存储，MongoDB适配此类数据的存储需求 |
| `REDIS_URL` | `redis://:[密码]@[地址]:6379/0?connect_timeout=30` | 用于缓存高频查询的政策条目与工单上下文，30秒的超时设置可避免会话中断影响问答流程 |
| `DB_MAX_LINK` | `100–200` | 该品类每日产生的工单与知识库数据量较大，控制连接池规模可避免数据库资源耗尽 |
| `STORAGE_S3_ENDPOINT` | `s3.[政务区域].aliyuncs.com`（或本地存储适配地址） | 用于存储工单附件、政策文档等大文件，匹配业务区域可降低数据访问延迟 |
| `ROOT_KEY` | 按企业内部安全规范生成的随机字符串 | 用于管理系统级权限，防止未授权访问部署配置 |
| `FE_DOMAIN` | `https://[政务服务专属子域名]` | 用于配置前端访问地址，适配政务场景的域名合规要求 |

## 容易做错的三处
- 现象：调用模型时返回「API密钥无效」或请求超时，日志显示模型调用失败。原因：未正确配置模型服务商的密钥信息，或未在部署时指定符合区域要求的模型调用地址，导致无法获取政策依据问答所需的模型响应。
- 现象：问答结果仅返回最底部的引用条目，无法关联工单具体业务内容。原因：未配置正确的上下文拼接规则，未将工单字段与知识库政策条目进行关联匹配，导致上下文缺失业务细节。
- 现象：部署后无法同步当日更新的工单数据。原因：未设置定时同步任务的执行频率，或未正确获取承办单位业务系统的接口访问权限，导致数据更新滞后。

## 怎么确认配好了
- 执行数据库连接测试命令，确认`MONGODB_URI`与`REDIS_URL`配置可正常建立连接，检查连接池连接数是否符合预设规模。
- 触发一次工单数据同步任务，核对同步后的工单数量与业务系统当日产生的工单数量一致，确认更新频率符合要求。
- 发起一条模拟群众诉求的政策问答请求，检查返回结果是否包含关联的知识库条目与工单上下文，确认配置的字段关联规则生效。
- 访问配置的`FE_DOMAIN`地址，确认系统界面可正常加载，且权限配置可拦截未授权的系统访问请求。
