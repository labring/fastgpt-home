# “高效办成一件事”联办的政策与制度依据问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的日常文档通常包含联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见、办结回执。数据来源通常为国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库、部门审批系统，更新频率为每日。文档通常按联办事项分类，包含跨部门事项关联规则、材料复用要求、并联办理节点要求等字段，无统一固定格式，随地方政务服务规范调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且格式不统一，会导致检索时出现字段缺失、语义偏差问题；每日更新的频率要求知识库同步链路具备增量更新能力，避免数据滞后；联办事项包含跨部门关联规则，单一文档的语义片段无法完整覆盖办理逻辑，容易出现召回结果割裂的情况；材料复用相关的内容分散在多个文档中，需要精准匹配用户问题对应的复用场景，否则会导致建议材料不完整。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 匹配联办政策文本的语义相似度阈值，该区间可过滤低相关性的跨部门无关内容，同时保留跨事项关联的弱匹配结果 |
| `limit` | 前12条 | 联办事项涉及多部门文档，单次召回足够覆盖关联规则与材料要求的最小条数，避免上下文过载 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配联办文档中既有明确规则条目又有模糊关联说明的内容结构 |
| `usingReRank` | 开启 | 对召回结果按与用户问题的相关性重新排序，解决跨部门文档语义分散导致的排序偏差问题 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展用户问题的同义表述，覆盖联办事项中常见的地方化表述差异 |
| `collectionIds` | 按联办事项分类绑定的数据集ID | 限定检索范围仅为当前联办事项对应的政务文档，避免无关数据干扰 |

## 容易做错的三处
- 召回结果无法覆盖完整的联办事项关联规则，部分关键内容缺失。原因：分块时未保留跨部门规则的上下文关联，导致关键语义片段被拆分，检索时仅召回部分片段。
- 检索结果包含大量与当前联办事项无关的单项审批文档。原因：未通过`collectionIds`限定检索的数据集范围，导致其他政务文档被误召回。
- 用户使用地方化表述提问时，无法匹配到对应政策内容。原因：未开启`datasetSearchUsingExtensionQuery`，无法自动扩展问题的同义表述，导致语义匹配失败。

## 怎么确认配好了
- 上传一份联办事项清单测试文档，发起对应问题查询，核对召回结果是否仅包含该联办事项的相关内容，确认`collectionIds`配置生效。
- 调整`similarity`的取值区间，验证召回结果的相关性变化，确认阈值设置符合业务需求。
- 发起包含地方化表述的查询，比如使用“多部门联合办理”替代“联办”，验证是否能召回正确内容，确认`datasetSearchUsingExtensionQuery`配置生效。
- 查看检索结果的排序，确认高相关性的文档优先展示，验证`usingReRank`配置生效。
