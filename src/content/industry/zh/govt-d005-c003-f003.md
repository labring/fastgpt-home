# 不动产登记的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据主要来自不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统与电子证照库，更新频率为每日。日常处理的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书及不动产登记簿。数据字段涵盖权利主体、坐落位置、权利类型、登记类型、权属状态等，采用政务服务统一标准格式，无特殊自定义单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源数据来源要求对话流程需追踪不同系统的权属信息关联关系，避免跨系统数据冲突。每日更新频率要求对话需实时调用最新数据，禁止依赖过期缓存内容。多样的文档类型需要提示词明确区分登记申请书、权属证明等不同文档的字段对应规则，确保问答匹配准确。同时，不动产登记的出错后果直接关联行政责任，多轮对话需在每一轮校验信息一致性，防止出现权属状态判断错误。此外，单轮对话涉及的地籍、交易、税务数据体量较大，需限制上下文长度，避免超出模型处理上限，通过多轮追问明确用户的具体查询场景。

## 配置怎么定
本配置适用于 FastGPT v4.17.0。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文最大长度 | 8000–12000 字符 | 不动产登记相关数据包含多份文档片段，需覆盖典型递进式查询的上下文需求 |
| `messages` | 自动保留最近10轮对话消息，截断更早内容 | 不动产查询多为递进式，保留最近轮次可确保信息时效性，避免冗余数据干扰 |
| 提示词模板 | 固定包含数据来源说明、字段校验规则、登记类型区分要求 | 需明确告知模型需从指定政务系统数据中提取信息，避免混淆非登记类数据 |
| `variables` | 预设权利主体、坐落位置变量，供对话动态填充 | 可简化多轮对话中的场景切换，快速适配不同登记业务的查询逻辑 |
| 单次调用超时时间 | 300 秒 | 不动产数据查询需跨多个关联系统，需预留足够的响应时间 |
| `chatId` | 绑定用户会话ID，跨工具调用时保留上下文 | 确保同一用户的多轮对话信息连贯，避免跨会话数据混淆 |

## 容易做错的三处
- 现象：工具调用完成后，对话卡片中同时显示工具调用日志与AI回复内容。原因：未配置工具调用结果的隐藏规则，导致非业务交互内容被直接输出。
- 现象：上传的不动产登记文档超过上下文上限后，出现部分权属字段缺失或查询结果不准确。原因：未启用文档自动切片配置，未按登记文档的结构拆分内容导致关键信息丢失。
- 现象：导入的测绘成果文档中的图片无法正常显示，链接显示为本地路径或无域名的相对路径。原因：未配置markdown图片的域名自动补全规则，导致图片无法被正常访问。

## 怎么确认配好了
- 发起一次递进式的不动产查询，核对对话上下文是否自动保留最近10轮的有效交互内容。
- 上传一份包含图片的测绘成果文档，核对图片是否正常加载，链接带有合规的访问前缀。
- 发起两次独立的用户会话，核对两次会话的上下文互不关联，未出现信息串扰。
- 触发工具调用流程，核对最终回复仅包含业务相关内容，未展示工具调用的内部日志。
