# 不动产登记的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源为不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统及电子证照库，更新频率为每日。日常文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书及登记簿，核心字段涵盖不动产坐落、权属主体、权利类型、限制状态等，采用政务标准格式，无自定义特殊单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据多源且每日更新，要求接入环节支持多系统接口拉取并完成增量同步，避免全量拉取带来的资源消耗。核心字段涉及权属来源、限制状态等敏感政务信息，配置时需严格限定上下文仅调用合规数据源。文档类型多样，需适配不同文档的分块逻辑，确保政策依据问答时能准确关联对应材料。同时因出错后果涉及行政纠纷，需强化召回结果的精准性，避免模糊匹配带来的错误结论。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多源政务文档的上下文长度，覆盖登记申请、权属证明等多类材料的完整关联内容 |
| `maxTokens` | 2000–3000 token | 控制单轮问答输出长度，避免政策依据内容被截断，符合政务问答的完整展示需求 |
| `quoteMaxToken` | 1500 token | 限定引用文档的最大长度，确保召回的政策依据内容精准且不超出上下文限制 |
| `temperature` | 0.1–0.3 | 降低随机生成概率，保障政策依据问答的内容准确性，贴合政务场景的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 按政务云环境配置专属端点 | 适配不动产登记场景的网络隔离要求，保障数据传输安全 |
| `toolChoice` | auto | 允许模型自动选择工具调用，适配多源数据的关联查询需求 |

## 容易做错的三处
- 现象：模型输出的政策依据表格无法正常渲染，内容被截断至末尾显示`...[hide X char]`。原因：未合理设置`maxTokens`或`quoteMaxToken`参数，导致输出长度超出限定阈值。
- 现象：接入后仅能获取单系统数据，无法关联地籍调查与税务系统的信息。原因：未配置多源数据的接入链路，仅对接了单一不动产登记系统接口。
- 现象：问答结果出现权属状态匹配错误，与实际登记簿内容不符。原因：`temperature`参数设置过高，导致模型生成了偏离原始政策依据的内容。

## 怎么确认配好了
- 发起包含不动产权属状态、测绘数据关联的测试提问，核对召回结果是否覆盖配置的数据源范围。
- 触发包含多段政策依据的长文本问答，检查输出内容是否完整，未出现截断或隐藏标记。
- 验证多系统接入链路，确认可同时调取不动产登记信息系统与地籍调查数据库的相关内容。
- 调整参数后对比同类型提问的输出结果，确保结果的严谨性符合政务场景要求。
