# 主动公开与政策发布的政策与制度依据问答：向量模型与索引

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类数据来源包括政府门户网站、公文系统、政府信息公开目录、政策文件库、新闻发布会材料。日常处理的文档涵盖政策文件、政策解读稿、公开目录、信息发布审批单、新闻通稿、网站栏目更新记录，部分文档包含多级政策关联信息，如上级文件引用、配套执行细则等。数据更新频率为每日更新，需同步至多平台渠道。文档包含文件编号、发布机构、发布时间、公开属性、涉密等级等字段，部分文档附带图文附件与解读关联信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的高频数据要求索引支持增量更新，避免全量重建耗时过长。多类型文档结构差异大，需适配不同字段的向量提取逻辑，避免非政策文本干扰检索结果。公开属性与涉密字段的存在，要求索引环节增加元数据过滤规则，防止敏感信息进入检索范围。多渠道来源的数据格式不统一，需在索引前完成标准化清洗，确保向量生成的一致性。此外，政策文本的长段落特征，需合理控制分块与重叠参数，需根据文档长度调整`defaultToken`的取值，适配向量模型的输入要求，避免语义断裂或冗余匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配政策文件的常规段落长度，避免语义断裂与向量生成冗余 |
| 重叠长度 | 100–200 字符 | 保留政策文本跨段落的逻辑关联，提升检索上下文完整性 |
| `maxToken` | 8192 | 适配主流向量模型的输入上限，避免截断核心政策内容 |
| 相似度阈值 | 0.75–0.85 | 匹配政策文本的语义相似度特征，过滤低相关性检索结果 |
| 单次搜索上限 | 前10条 | 控制检索结果数量，简化后续上下文拼接与审核流程 |
| 元数据过滤 | 按公开属性与涉密等级筛选 | 关联文档元数据，排除不应公开的内容进入检索范围 |

## 容易做错的三处
- 现象：执行索引切换后，检索结果长时间无更新或返回旧数据。原因：未关闭旧索引的自动同步任务，或增量索引配置未绑定最新的数据源路径。
- 现象：批量添加索引时返回参数错误，无法完成入库。原因：未按要求携带文档元数据字段，或请求体格式未匹配系统要求的结构。
- 现象：检索结果同时返回单文档的多个分块条目，或出现重复匹配的政策文件。原因：未配置统一索引的去重规则，或分块重叠长度设置过大导致语义重复匹配。

## 怎么确认配好了
- 上传一份测试用的政策文件，查看索引生成日志，确认分块长度与重叠长度符合预设配置。
- 发起模拟政策问答请求，检查检索结果的元数据过滤是否生效，排除涉密或未公开的文档。
- 执行增量索引同步，对比同步前后的检索结果数量，确认更新逻辑正常运行。
- 批量上传多份同类型文档，检查索引入库的完整性，确认无格式错误导致的入库失败。
