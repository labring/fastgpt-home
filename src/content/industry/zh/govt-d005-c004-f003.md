# 主动公开与政策发布的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源为政府门户网站、公文系统、政府信息公开目录、政策文件库、新闻发布会材料。更新节奏为每日更新。文档包含政策文件、政策解读稿、公开目录、信息发布审批单、新闻通稿、网站栏目更新记录，包含文件编号、公开属性、保密等级、发布栏目、更新时间等字段，需严格遵循政务公开的格式规范。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且每日更新，要求多轮对话上下文需关联最新发布的政策文件，避免引用过时内容。文档包含内部审批单等非公开文档，需在提示词中明确过滤未通过公开属性审核的条目。字段包含保密等级，需在对话环节自动屏蔽涉密相关内容。多轮对话需匹配公开目录的栏目信息，确保回答符合对应发布渠道的规范。文档结构多样，需在提示词中统一解析不同文档的格式，避免回答出现格式混乱。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 与当前对话会话绑定 | 确保多轮对话上下文关联同一会话的政策查询记录，避免跨会话数据混淆 |
| `messages` | 保留前10轮对话内容 | 适配政务政策问答的多轮追问场景，同时控制上下文长度避免超出模型限制 |
| `variables` | 注入公开属性过滤规则 | 自动排除未通过审核的内部文档，确保回答仅包含可公开的政策内容 |
| 单次召回上限 | 前8条 | 政务政策文档数量较多，限制召回条数可避免冗余信息干扰，提升回答精准度 |
| 最大上下文 | 8000–12000 token | 适配多轮政策问答的上下文长度需求，避免信息截断 |
| 问题优化 | 按实测标定 | 政务政策问题常包含简称与全称对应关系，优化后可提升召回准确率 |

## 容易做错的三处
- 现象：回答段落末尾显示“没有权限操作此对话记录”的报错文案。原因：未正确配置`variables`中的权限过滤规则，导致引用了未公开的内部文档。
- 现象：多轮对话上下文丢失，无法关联上一轮的政策追问。原因：未绑定`chatId`，导致每轮对话生成独立会话，上下文无法延续。
- 现象：回答中包含涉密或敏感内容。原因：未在提示词中加入保密等级过滤逻辑，导致召回了标注为涉密的政策文件。

## 怎么确认配好了
- 发起一轮基础政策查询，核对回答是否仅包含可公开的政策内容，无内部审批单等未公开信息。
- 发起两轮连续追问，核对对话上下文是否正确关联上一轮的查询内容，无上下文丢失情况。
- 检查回答末尾的引用标记，确认可根据需求调整显示状态，无强制显示的报错文案。
- 模拟更新后的政策查询，核对回答是否包含最新发布的政策文件，无过时内容。
