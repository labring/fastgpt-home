# 产权、资产与国有资本管理的政策与制度依据问答：工作流编排

## 这个品类的数据长什么样
本品类的核心数据来自国资监管信息系统、企业资产管理系统、产权交易所系统、评估机构报告与财务报表，日常文档包含产权登记表、资产评估报告、产权转让方案、进场交易公告、资产处置审批单。数据以结构化表单与非结构化报告结合的形式存在，包含权属编号、资产原值、处置审批单号等专属字段，更新频率为月度，每月同步存量与新增资产的最新状态。

## 这些特征在「工作流编排」这一环带来什么约束
品类数据来源分散且格式多样，要求工作流需支持跨系统拉取不同格式的业务数据，需配置专属数据源绑定规则。月度更新频率要求工作流的知识库同步周期需匹配月度节奏，避免过度同步占用资源。核心业务环节耗时较长，要求工作流需拆分为权属核对、评估备案、转让审查等独立节点，便于分步校验。出错后果严重，要求工作流需配置异常处理分支，对大模型报错、数据缺失等情况进行拦截与提示。

本配置适用于FastGPT v4.17.0。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 变量设置 | 绑定国资监管系统、资产管理系统的专属`variables`字段 | 依据品类数据来源多系统，需精准拉取产权、资产相关业务字段 |
| 节点ID | 按业务环节命名，如`nodeId:asset_verify` | 依据多工作流调用需精准定位节点，避免不同业务环节混淆 |
| 单次搜索上限 | 前10条 | 依据品类文档多为结构化表单与规范报告，少量精准结果即可覆盖政策匹配需求 |
| 最大上下文 | 8000 token | 依据政策与制度文档篇幅较长，需保留足够上下文供大模型完成比对与依据提取 |
| 超时阈值 | 600秒 | 依据跨系统拉取资产、权属数据耗时较长，需预留足够响应时间 |
| 分块长度 | 800–1200 字符 | 依据品类文档既有结构化字段又有非结构化文本，适配不同格式的内容拆分 |

## 容易做错的三处
- 现象：对话节点返回空字符串或系统报错，界面无任何提示。原因：未配置`variables`绑定的异常处理分支，未设置报错触发的校验或回退流程。
- 现象：工具选择节点同时触发多个并行任务，导致国资系统接口调用超限。原因：未设置工具选择的互斥规则，未限定单节点执行顺序。
- 现象：调用不同业务环节的工作流时，出现参数串用、节点执行错误的情况。原因：未为每个工作流配置独立的`nodeId`标识，未绑定专属数据源变量。

## 怎么确认配好了
- 触发资产权属核对节点，检查是否能拉取对应系统的产权登记表、资产评估报告等字段，确认数据源绑定正确。
- 模拟大模型报错场景，检查是否触发预设的异常处理流程，确认异常分支配置生效。
- 调用不同业务环节的工作流，检查是否仅执行对应节点，确认`nodeId`标识生效。
- 查看知识库同步日志，确认月度同步周期配置正确，符合品类数据更新频率。
