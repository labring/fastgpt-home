# 传染病信息报告与监测的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自中国疾病预防控制信息系统、医疗机构HIS和传染病报告系统、实验室检测系统。日常处理的文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，数据更新频率为每日。文档字段包含病例基本信息、诊断结果、报告时限、订正状态、实验室检测结果等，单位多为病例数、日期、机构编码等，无额外自定义单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据每日更新，要求模型接入配置需匹配日级数据同步节奏，避免召回过时信息。多类结构化与半结构化文档混合，需适配不同文档的字段规则，配置时需明确不同文档的召回权重。数据来源覆盖多套业务系统，配置需兼容多源数据的格式转换。因涉及法定传染病报告规则，模型输出需严格匹配政策依据，需限制生成的灵活性，避免偏离法定要求。同时，数据字段包含病例诊断、报告时限等关键信息，配置需确保召回内容准确关联政策条款。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配每日更新的多文档批量召回，避免截断关键政策依据与病例数据 |
| `temperature` | 0.1–0.3 | 确保政策问答的严谨性，降低生成内容的随机性，符合法定报告规则要求 |
| `AIPROXY_API_ENDPOINT` | 按部署的合规大模型服务地址填写 | 对接符合卫生健康数据安全要求的模型服务 |
| `maxTokens` | 2000–3000 token | 限制单轮问答输出长度，确保政策条款与病例信息的整合结果清晰可追溯 |
| `toolChoice` | 自动 | 启用政策条款匹配工具，精准召回对应传染病报告的法定条文 |
| `AIPROXY_API_TOKEN` | 按服务提供的密钥填写 | 保障模型调用的身份验证与数据传输安全 |

## 容易做错的三处
- 调用第三方模型服务时返回404错误，原因是未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或模型服务地址与密钥不匹配。
- 启用自定义模型后无法正常加载问答功能，原因是未在平台支持的模型接入清单中完成对应模型的配置，或接入格式不符合平台要求。
- 政策问答的分类结果差异过大，原因是`temperature`取值过高，导致模型生成内容随机性过强，无法稳定匹配政策依据与病例信息的对应规则。

## 怎么确认配好了
- 发起单条政策问答测试，核对返回结果中是否包含匹配的传染病报告法定条款与对应病例数据。
- 查看平台的模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的调用请求无异常报错。
- 测试每日增量数据的召回效果，确认召回的文档数量与更新频率匹配每日同步的要求。
- 调整`temperature`参数至0.1–0.3区间，核对连续三次问答结果的一致性，避免随机波动过大。

> 问题素材取自公开社区提问（2026-09-11 去重 4,834 条）。文中的配置项名称与取值区间需以所用版本的实际界面与文档为准；本页核验日 2026-09-28，当时的最新发布版本为 FastGPT v4.17.0。
