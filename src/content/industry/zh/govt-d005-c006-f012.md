# 传染病信息报告与监测的政策与制度依据问答：部署与升级

## 这个品类的数据长什么样
本品类的数据来源为中国疾病预防控制信息系统、医疗机构HIS和传染病报告系统、实验室检测系统，更新频率为每日。日常处理的文档包括传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，数据字段包含病例基本信息、诊断结果、报告时限、订正状态、报送机构编码等，所有字段需符合法定传染病报告的统一格式要求，无额外自定义统计指标。

## 这些特征在「部署与升级」这一环带来什么约束
本品类的数据来源分散且每日更新，部署环节需对接多套异构系统接口，升级时需保证接口兼容性，避免中断每日数据同步。日常文档类型多样，不同文档的字段结构差异较大，部署时需针对不同文档类型配置适配的检索规则，确保政策依据问答的匹配精度。法定报告要求严格，部署环节需内置符合规则的校验逻辑，升级时需同步更新校验规则版本，防止出现漏报迟报风险。同时，数据更新频率高，部署时需配置合理的增量同步机制，避免全量同步占用过多系统资源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:password@host:27017/fastgpt?authSource=admin` | 存储每日增量的传染病报告卡、订正记录等结构化数据，需配置正确的认证源与端口保证稳定读写 |
| `REDIS_URL` | `redis://:auth@host:6379/1` | 缓存检索到的政策依据问答结果，降低重复查询开销，缓存过期时间按实测标定 |
| `DB_MAX_LINK` | `15 个连接` | 适配本品类每日同步的多源数据并发请求，限制数据库连接数避免资源耗尽 |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.aliyuncs.com` | 存储流调报告、疫情分析报告等大体积非结构化文档，需配置兼容的对象存储端点 |
| `ROOT_KEY` | `自定义高强度随机字符串` | 保护FastGPT管理后台的访问权限，防止未授权修改部署配置 |

## 容易做错的三处
- 现象：部署后无法正常创建数据库，报错提示连接超时或权限不足。原因：未正确配置`MONGODB_URI`或`PG_URL`的认证信息，或数据库服务未开放对应端口。
- 现象：检索政策依据时结果条数异常偏少，无法匹配到完整的制度文件。原因：未调整`DB_MAX_LINK`配置，导致数据库连接数不足，无法拉取全量索引数据。
- 现象：检索结果无法关联到最新的订正记录，问答内容滞后。原因：未配置每日增量同步任务，或同步任务的触发频率未匹配本品类的日更新节奏。

## 怎么确认配好了
- 针对FastGPT v4.17.0版本，执行内置的数据库连接测试脚本，验证`MONGODB_URI`和`REDIS_URL`的配置可正常读写数据，确认连接稳定性符合要求。
- 触发一次增量同步任务，核对同步的文档数量与当日新增的法定报告数据数量匹配，确认同步逻辑正常。
- 访问FastGPT管理后台，使用`ROOT_KEY`完成认证，确认可正常修改部署配置，无权限拦截问题。
- 发起一条政策依据相关的测试提问，核对检索结果包含正确的文档类型与字段信息，确认索引配置适配本品类的数据结构。
