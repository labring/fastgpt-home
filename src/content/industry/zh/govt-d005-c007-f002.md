# 信访事项办理的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
本品类的数据主要来自各级信访局、部门信访办、街道乡镇及责任单位办公室，包含信访登记表、受理告知书、转送交办函、办理意见书、复查复核申请、化解方案等标准化文档。数据来源覆盖国家信访信息系统、地方信访系统、12345平台、基层治理平台及历史信访档案，每日更新，文档结构固定，包含诉求内容、办理流程、政策依据等核心字段，无额外自定义非标准字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据来源分散且每日增量更新，要求索引环节支持增量同步与批量更新，避免全量重建带来的性能损耗。标准化文档的字段固定但来源系统格式存在细微差异，需在分块前统一文本格式，确保向量生成的一致性。政策依据为核心问答内容，需优先保障政策文本的向量召回精度，同时需控制索引的单批次数据量，避免因数据过载导致索引超时。此外，信访数据的出错后果直接关联重复信访与越级信访，需确保向量召回的准确性，避免遗漏关键政策依据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配信访类文档的段落长度，覆盖完整政策依据片段 |
| 重叠长度 | 100–200 字符 | 避免政策依据被分块截断，保留上下文语义关联 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 平衡信访政策问答的召回准确率与覆盖范围 |
| 单次搜索上限 | 前 5 条 | 匹配信访办理中需参考的有限政策依据数量 |
| `maxToken` | 4000 token | 适配FastGPT v4.17.0的上下文窗口限制，避免超出模型处理上限 |
| `defaultToken` | 1500 token | 保障单条政策依据的向量生成完整性，适配通用嵌入模型的输入要求 |

## 容易做错的三处
- 界面显示知识库持续处于索引中，无进度更新。原因：未配置增量索引规则，全量同步每日更新的信访数据时占用大量资源，导致索引进程阻塞。
- 调用嵌入模型时返回503状态码，提示当前分组default下模型text-embedding不可用。原因：未在FastGPT平台绑定可用的嵌入模型接口，或接口请求频率超出限额。
- 生成的向量结果与政策原文语义偏差较大。原因：分块长度设置过小，将完整的政策依据片段截断，导致向量无法准确匹配语义关联。

## 怎么确认配好了
- 手动上传一份信访办理意见书文档，查看分块后的文本片段是否完整保留政策依据内容。
- 发起一条政策相关的测试查询，核对返回的搜索结果条数与单次搜索上限的设置一致。
- 查看嵌入模型调用日志，确认`defaultToken`与`maxToken`的参数取值符合配置要求。
- 等待1个自然日，检查增量索引任务是否自动完成，无异常报错日志。
