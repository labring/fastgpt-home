# 信访事项办理的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
本品类数据主要来自国家信访信息系统、地方信访系统、12345政务服务平台、基层治理平台及历史信访档案，更新频率为每日。日常文档包含信访登记表、受理告知书、转送交办函、办理意见书、复查复核申请、化解方案等，字段包含信访编号、受理主体、办理意见、政策依据条目、诉求内容等，单份文档多为结构化业务内容与政策条文的组合。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源覆盖多级政务系统且每日更新，要求引用溯源环节支持增量同步与多源数据关联校验，避免旧数据或非官方来源被引用。文档包含结构化业务表单与政策条文两类内容，需精准识别政策依据字段，确保引用的政策条文与业务办理意见一一对应。信访事项办理对溯源准确性要求极高，错误引用可能引发重复信访或复查纠错，因此需严格限定引用的来源范围与可信度等级。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次搜索上限 | 前 3 条 | 信访政策依据多为精准匹配的官方文档，过多召回会引入无关内容 |
| 相似度阈值 | 0.75–0.85 | 匹配信访事项的政策条文与业务文档，避免低相关内容被引用 |
| `quoteMaxToken` | 800–1200 token | 覆盖信访办理意见书与政策依据的完整内容，确保引用无截断，适配FastGPT v4.17.0的配置逻辑 |
| `responseData` | 仅返回关联的官方信访与政策文档 | 聚焦政策与制度依据问答需求，过滤非必要业务字段 |
| `detail` | 开启 | 展示引用文档的完整字段，包括信访编号、政策依据条目等核心信息 |

## 容易做错的三处
- 现象：配置引用上限时仅提供100与900两个档位，无法选择300左右的中间值。原因：当前版本的配置界面未开放自定义区间的输入框，仅预设了固定档位。
- 现象：尝试引用外部http返回内容时出现报错提示，无法正常调用。原因：未正确配置外部数据源的调用规则，未添加合法的访问权限或请求头参数。
- 现象：设置最低相关度为1后，响应中仍出现大量非目标引用内容。原因：未限定召回的数据源范围，未关联专属的信访知识库，导致无关内容被召回。

## 怎么确认配好了
- 发起一条信访政策相关的测试问题，检查响应中引用的文档是否来自指定的信访系统与政策来源。
- 查看引用内容的字段完整性，确认是否包含信访编号、政策依据条目等核心信息。
- 调整引用token的配置值，验证响应中引用内容的截断情况是否符合预期。
- 检查配置的数据源同步状态，确认每日增量更新已正常开启。
