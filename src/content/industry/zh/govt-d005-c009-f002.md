# 公共数据目录与开放的政策与制度依据问答：向量模型与索引

本文基于 FastGPT v4.17.0 版本编写。

## 这个品类的数据长什么样
本品类的数据主要来自地方公共数据开放平台、一体化大数据平台、部门业务数据库、电子证照库，由大数据局、政务服务数据管理局等主体维护。日常文档包含公共数据资源目录、数据开放清单、数据项说明、脱敏规则、接口文档、更新频率说明，字段涵盖数据项名称、开放条件、脱敏要求、接口地址、更新周期等，更新频率为每月一次。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的频率要求需配置定时增量索引任务，避免全量索引占用过多资源。文档包含结构化数据项、接口说明与非结构化规则文本，需区分不同字段的分块策略以保证向量生成的准确性。开放条件、脱敏规则等敏感字段需在索引前完成预处理，防止敏感信息随向量存储泄露。多来源数据格式存在差异，需统一字段映射后再生成向量，避免索引混乱。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配单条公共数据项说明、接口文档的常规长度 |
| 重叠长度 | 100–150 字符 | 保证相邻数据块的上下文连贯性 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度结果，确保政策依据的准确性 |
| 单次召回条数 | 前 10 条 | 政策与制度依据通常集中在少量相关文档中 |
| `maxToken` | 8000 token | 承载多条数据项说明与政策条款的上下文内容 |
| `defaultToken` | 200 token | 控制单条溯源文本的输出长度 |

## 容易做错的三处
- 现象：搜索结果无法关联到具体的公共数据目录文档，返回空的来源字段。原因：未在分块时保留文档的来源标识字段，或索引时未加载来源元数据。
- 现象：向量生成任务频繁超时。原因：未按月度更新频率配置增量索引，直接对全量公共数据目录执行全量索引。
- 现象：返回结果包含未脱敏的敏感数据项。原因：未在索引前对脱敏规则字段做预处理，直接将原始敏感数据生成向量。

## 怎么确认配好了
- 上传一条公共数据项说明文档，发起对应政策依据查询，检查返回结果是否附带文档来源信息。
- 手动触发一次索引任务，查看任务耗时是否在合理区间，无超时报错。
- 输入包含敏感数据项的查询词，检查返回结果是否未包含未脱敏的原始数据。
- 等待月度更新周期结束，查看索引是否自动完成增量更新。
