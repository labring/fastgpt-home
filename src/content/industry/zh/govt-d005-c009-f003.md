# 公共数据目录与开放的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据主要来自地方公共数据开放平台、一体化大数据平台、部门业务数据库与电子证照库，更新频率为每月一次。日常管理的文档包括公共数据资源目录、数据开放清单、数据项说明、脱敏规则、接口文档及更新频率说明。数据字段包含可开放数据项名称、开放条件、脱敏要求、对应接口地址、更新周期等，所有内容围绕公共数据的共享与开放边界展开。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
月度更新的特性要求多轮对话中需明确提示数据的最新更新节点，避免传递过时的开放信息。多类型结构化文档的存在，要求提示词需引导对话聚焦数据项、开放条件、接口规则等明确字段，避免模糊查询。多来源的数据资产需在对话中区分不同部门的开放权限边界，防止越权查询。同时，公共数据的脱敏规则需嵌入提示词，确保对话输出符合数据安全要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按对话会话生成唯一标识 | 用于区分不同用户的公共数据查询会话，避免上下文混淆 |
| `messages` | 保留前3轮对话上下文 | 适配月度更新的数据特性，避免引入过时的历史信息 |
| `variables` | 预设「数据更新时间」「开放部门」变量 | 匹配品类文档的固定字段，提升查询结果的准确性 |
| 最大上下文长度 | 800–1200 字符 | 适配公共数据单条文档的内容长度，避免上下文溢出 |
| 单次召回上限 | 前5条匹配结果 | 公共数据目录条目数量可控，过多结果会干扰对话逻辑 |

## 容易做错的三处
- 现象：对话返回「没有权限操作此对话记录」。原因：未正确绑定`chatId`参数，导致会话上下文无法关联到对应的数据权限校验逻辑。
- 现象：多轮对话中出现过时的开放数据项。原因：未限制上下文轮次，旧对话中的过期数据被带入新查询。
- 现象：返回的开放接口地址与实际目录不符。原因：未在提示词中明确要求匹配数据项与接口的对应关系，导致召回错误条目。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本。
- 发起单轮公共数据目录查询，核对返回结果是否包含当前地区的最新更新数据项。
- 发起两轮连续查询，核对`chatId`参数是否随会话生成，上下文是否正确关联。
- 触发非开放数据项查询，核对是否返回符合规则的权限提示。
- 检查提示词是否包含对数据更新时间、脱敏规则的明确引导。
