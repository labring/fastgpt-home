# 公路养护与路产路权管理的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自公路养护管理系统、桥隧监测系统、路政巡查系统、交通流量监测数据，更新频率为每日。日常处理的文档包括养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单。文档字段通常包含路段标识、事件发生时间、处置流程节点、关联许可编号等，部分字段使用公里、天、条等单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来自多套异构系统，模型接入时需适配不同数据源的格式规范，避免出现字段不匹配的问题。每日更新的数据量需适配FastGPT平台的增量更新逻辑，避免全量同步占用过多资源。文档类型包含计划类、日志类、许可类等多种结构，需针对不同文档设置适配的分块规则，确保检索时能精准匹配政策依据关键词。同时，因出错后果涉及道路安全与合规问题，模型配置需优先保障检索结果的关联性与准确性。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写，以下为针对该品类的配置建议：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 该品类的政策与业务文档关联度高，需保留足够上下文以匹配完整的制度依据 |
| `temperature` | 0.1–0.3 | 政策问答需严格匹配原文表述，避免生成偏离实际的内容 |
| `quoteMaxToken` | 2000–3000 token | 需保留足够长度的原文片段作为问答的引用依据，确保合规性 |
| `toolChoice` | auto | 自动触发检索工具，匹配与当前问题相关的路产养护政策文档 |
| `AIPROXY_API_ENDPOINT` | 部署的大模型服务地址 | 指定模型接入的服务入口，完成与外部大模型的连接 |
| `AIPROXY_API_TOKEN` | 对应服务的访问密钥 | 完成模型接入的身份验证，保障接口调用的安全性 |

## 容易做错的三处
- 现象：GPU资源未被调用，CPU单核占用率持续100%。原因：未正确配置大模型的加速后端，或未指定使用GPU的部署参数，导致模型仅在CPU侧运行。
- 现象：检索结果条数与预期不符，无法匹配到对应的政策文档。原因：未根据该品类的文档结构调整上下文匹配规则，或分块设置不合理导致关键信息被截断。
- 现象：配置`AIPROXY_API_ENDPOINT`后无法连接模型服务。原因：填写的服务地址未包含正确的端口路径，或访问密钥`AIPROXY_API_TOKEN`权限不足。

## 怎么确认配好了
- 查看FastGPT后台的模型连接状态面板，确认显示为已连接，无报错提示。
- 发起一条针对该品类的测试问题，如「路产损坏赔偿的制度依据是什么」，核对返回结果中是否包含对应品类的文档片段。
- 检查系统的资源监控面板，确认GPU资源被正常调用，CPU占用率处于合理区间。
- 验证返回结果的引用来源是否正确关联到该品类的文档类型，如巡查日志、涉路施工许可等。
