# 养老、工伤、失业待遇核定的政策与制度依据问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据来源为社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为每日一次。日常处理的文档包括待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料，数据字段覆盖缴费累计时长、待遇计发相关规则、资格审核判定依据等，无固定统一的统计口径或预设数值，所有字段均围绕待遇核定的核心业务逻辑生成。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据来源分散且每日更新，要求HTTP接口需适配多系统鉴权与数据同步逻辑，避免返回过期或跨区域的错误政策依据。日常文档类型多样，接口需兼容不同格式的业务材料解析，保障字段提取的准确性。同时，待遇核定的出错后果直接关联基金安全与群众权益，接口需增加多层参数校验，拦截不符合业务规则的调用请求，避免因参数错误导致的待遇错发漏发。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {服务端生成的接口密钥}` | 符合HTTP接口鉴权标准，保障外部系统调用的安全性，防止未授权访问社保业务数据 |
| `variables` | 传入社保经办区域编码、查询日期范围、待遇类型 | 精准匹配对应区域的政策条款与业务数据，缩小查询范围，提升返回结果的针对性 |
| `responseData` | 返回政策原文片段、资格判定依据、关联业务材料编号 | 贴合政策问答的核心需求，提供可追溯的官方依据，便于后续人工复核 |
| 单次搜索上限 | 前8条 | 覆盖常用的政策条款与业务材料，避免返回冗余信息，降低接口响应负载 |
| 接口超时时间 | 600秒 | 适配社保数据查询的多系统对接与复杂计算耗时，避免因超时中断查询流程 |
| 知识库分块长度 | 800–1200 字符 | 适配政策文档的段落结构，保障语义完整性，提升问答的准确性 |

## 容易做错的三处
- 现象：调用接口创建知识库后，对话接口无法关联新建的知识库。原因：未在接口请求参数中传入正确的知识库关联标识，或未完成知识库与目标应用的绑定配置。
- 现象：图片上传链接时返回400状态码，日志包含`message": "400 do request failed: Post "https://xxx stre`。原因：上传链接的格式不规范，或未配置图片资源的公开访问权限，导致接口无法正常拉取图片内容。
- 现象：同一应用、模型、知识库下，在线对话与API调用返回的结果差异较大。原因：API调用时未正确设置`stream`和`detail`参数，或上下文窗口配置与在线对话场景不一致。

## 怎么确认配好了
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
- 调用鉴权接口，传入配置的`Authorization`参数，验证返回结果包含合法的会话令牌，确认鉴权配置生效。
- 传入测试用的社保查询参数，检查`responseData`返回的内容是否包含政策依据原文与业务材料的关联信息，确认数据提取逻辑正确。
- 模拟批量查询请求，确认接口响应时间未超过预设的超时配置，无超时报错。
- 对比在线对话与API调用的返回结果，确认参数配置一致时输出的政策依据与业务判定内容匹配。
