# 养老、工伤、失业待遇核定的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为每日。日常处理的文档包含待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料，多为结构化字段与非结构化证明材料结合，字段涉及缴费年限、待遇核算标准、资格审核条件等，仅使用国家人社部统一规范的字段与单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据接入要求配置支持跨系统数据拉取的适配规则，避免数据格式不兼容导致的问答偏差。每日更新频率要求配置自动同步任务，确保知识库内容与最新政策、经办数据一致。混合结构化与非结构化文档的处理，要求模型支持对表单字段与证明材料的关联校验。待遇核算相关字段的严谨性要求，需配置严格的上下文引用规则，避免脱离政策依据生成结果。同时，出错后果的严重性要求配置失败告警与回滚机制，防止错发漏发待遇引发基金风险或群众投诉。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 字符 | 需覆盖多份待遇申请材料、缴费记录与对应政策原文，避免截断关键核算依据 |
| `quoteMaxToken` | 3000–5000 token | 确保引用的政策条款、证明材料内容完整，支撑待遇核定的逻辑推导 |
| `temperature` | 0.1–0.3 | 降低输出随机性，保证待遇核算结果与政策依据的一致性 |
| `maxTokens` | 2000–3000 token | 控制单轮问答输出长度，适配经办人员的信息阅读习惯 |
| `toolChoice` | auto | 允许模型自动触发知识库检索，匹配当前问题对应的政策与经办规则 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接入地址 | 适配本地或云端部署的模型调用链路，确保请求正常转发 |

## 容易做错的三处
- 现象：本地部署的大模型添加知识库后出现调用报错，日志显示上下文长度超限或格式不兼容。原因：未针对本品类的多源混合文档调整`maxContext`配置，导致加载知识库时超出模型支持的上下文阈值。
- 现象：配置多个模型后，无法在系统中选中指定的本地部署模型。原因：未正确填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，导致模型注册信息未同步至平台调度层。
- 现象：问答结果未引用对应政策依据，仅给出泛泛的核算结论。原因：未开启`toolChoice`自动检索配置，或`quoteMaxToken`取值过小导致引用内容被截断，无法支撑政策匹配。

## 怎么确认配好了
FastGPT v4.17.0版本下可通过以下步骤核对配置效果：
- 发起包含具体待遇核算需求的测试问题，检查模型输出是否自动关联对应政策条款与经办材料。
- 查看平台调度日志，确认模型调用请求能正常转发至指定的部署节点，无连接报错。
- 手动调整配置项取值，验证上下文截断、输出长度等行为是否符合预期。
- 触发知识库同步任务，检查数据更新后的问答结果是否同步体现最新政策或经办规则。
