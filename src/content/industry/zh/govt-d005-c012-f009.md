# 养老服务机构监管的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
通常数据来源于养老服务信息平台、民政统计系统、消防检查记录及机构运营台账，更新节奏为月度。日常处理的文档包括机构备案材料、运营补贴申请单、服务质量检查表、安全隐患整改台账与老人入住档案，文档字段多包含机构主体信息、床位数据、检查项结果、补贴申请明细与整改记录，无统一固定格式模板。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的批量数据要求配置支持增量同步逻辑，避免重复处理历史数据；多类型非标准化文档需要适配不同文档结构的解析规则，防止核心字段提取偏差；跨部门协同的多数据源需要配置校验逻辑，确保不同渠道的机构信息一致；高风险的补贴、安全整改相关问答，需要限制上下文范围，减少无关信息对政策依据匹配的干扰。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配政策文档与机构台账的拼接长度，避免截断核心依据 |
| `maxTokens` | 2000–3000 token | 控制单轮问答输出长度，确保政策条款与监管要求的完整呈现 |
| `quoteMaxToken` | 1500 token | 限制引用文档的片段长度，聚焦政策原文与机构数据的关键内容 |
| `temperature` | 0.1–0.3 | 降低随机生成概率，保证政策依据问答的准确性与一致性 |
| `AIPROXY_API_ENDPOINT` | 按平台提供的官方地址填写 | 确保模型调用链路正常，适配跨区域部署需求 |
| `AIPROXY_API_TOKEN` | 与对应渠道绑定的专属密钥 | 保障模型调用的安全性，防止未授权访问 |

## 容易做错的三处
- 上传Word文档后模型识别为空：未开启文档解析模块的Word格式适配开关，导致非结构化文档无法正确提取文本内容。
- 提示分组default下无可用模型渠道：未在对应分组中绑定已配置的模型渠道，或渠道配置的`AIPROXY_API_TOKEN`无效，导致模型调用失败。
- 问答结果偏离政策依据：设置了过高的`temperature`参数，导致模型生成内容偏离预设的政策原文匹配逻辑，出现错误解读。

## 怎么确认配好了
- 上传单份养老机构备案材料，核对模型返回的文本提取结果是否包含机构名称、床位数量等核心字段。
- 调用测试问答，输入“某养老机构的备案要求”，核对返回内容是否关联政策文档片段，且引用来源正确。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置未出现格式错误。
- 模拟月度批量数据导入，检查增量同步逻辑是否仅处理新增的机构台账数据，无重复处理记录。
