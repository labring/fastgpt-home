# 内控评价、审计与整改的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
本品类的数据主要来自中央企业内控系统、ERP、财务共享系统、审计管理系统及采购合同项目系统。日常生成的文档包括内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据更新频率为年度，文档包含结构化字段与非结构化文本，部分文档关联业务凭证编号、整改责任人、销号时间等具体信息，整体内容偏向事后检查与整改闭环相关的业务记录。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散于多套异构系统，需适配不同格式的文档导入与解析规则；年度更新的特性意味着索引无需高频刷新，但需支持全量重索引以覆盖最新的政策与整改内容；文档包含结构化字段与非结构化文本，需兼顾字段匹配与语义召回以支撑精准查询；整改台账、销号证明等文档关联具体业务标识，索引需保留关联关系以避免召回无关的历史记录；审计类问答对溯源准确性要求高，需确保召回内容与当前审计项目直接相关。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配审计工作底稿、整改台账的文本长度，避免单块内容跨业务逻辑 |
| 重叠长度 | 100–200 字符 | 保留跨块的业务关联信息，如整改问题的前后说明与政策依据 |
| maxToken | 4000–6000 token | 匹配国央企政策文档的长文本上下文需求，避免截断关键制度条文 |
| 单次搜索上限 | 前8条 | 覆盖单轮问答所需的政策依据与整改案例，同时控制返回冗余内容 |
| 重排 | 开启语义重排 | 提升审计问题相关的政策依据召回准确性，过滤无关文档 |
| defaultToken | 按实测标定 | 适配不同规模的知识库上下文调用，避免超出模型调用限制 |

## 容易做错的三处
- 现象：搜索结果中出现与当前审计项目无关的历史整改记录。原因：未配置基于业务标识的过滤规则，仅依赖语义召回导致冗余结果。
- 现象：索引模型选择界面无法正常加载可选列表，显示加载失败提示。原因：未正确配置本地索引模型的部署路径，导致FastGPT无法拉取模型列表。
- 现象：长文本问答返回结果截断关键政策条文。原因：未调整maxToken参数至适配长文档的取值区间，导致上下文被强制截断。

## 怎么确认配好了
- 上传一份典型的审计通知书与对应整改台账，发起“该审计项目对应的政策依据有哪些”的问答，核对返回结果是否包含对应文档的核心内容。
- 进入FastGPT v4.17.0的索引管理页面，触发一次全量重索引，检查任务状态是否在合理时长内完成，无报错日志生成。
- 测试包含业务编号的查询，如“查看XX项目的整改销号证明”，确认返回结果仅关联该项目的文档，无无关内容混入。
- 查看模型调用日志，确认maxToken参数的实际取值符合配置的区间，无异常截断情况。
