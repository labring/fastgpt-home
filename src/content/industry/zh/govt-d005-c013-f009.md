# 内控评价、审计与整改的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自企业内控系统、ERP、财务共享系统、审计管理系统及采购合同项目系统。日常文档包含内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据更新频率为年度。文档结构包含问题描述、责任主体、整改要求、佐证材料关联等内容，部分以结构化表格形式呈现，部分为非结构化文本，无统一固定格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据来源分散且覆盖多套企业内部系统，配置时需适配不同系统的导出格式，避免因数据格式不兼容导致导入失败。文档包含结构化表格与非结构化文本，需合理设置上下文与召回参数以覆盖两类文档的信息密度。数据更新频率为年度，知识库同步频率可设置为年度触发，无需高频更新。由于业务涉及审计问题闭环与监管要求，配置需保障召回内容的准确性与合规性，避免遗漏关键政策依据。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖多份审计底稿、整改台账的关联内容，确保问答上下文完整 |
| `quoteMaxToken` | 2000–3000 token | 保障每条引用的政策文档内容完整，避免截断关键合规依据 |
| `temperature` | 0.1–0.3 | 政策依据问答需保持严谨，降低生成内容的随机性 |
| `maxTokens` | 4000 token | 控制单次回答长度，确保输出符合合规文档的格式要求 |
| `toolChoice` | auto | 允许模型自主选择是否调用知识库检索政策依据 |
| `AIPROXY_API_ENDPOINT` | 填写合规的模型接口地址 | 适配企业内部合规的模型调用链路 |
| `AIPROXY_API_TOKEN` | 填写与模型绑定的密钥 | 完成模型调用的身份验证 |

## 容易做错的三处
- 现象：导入文档时报500错误。原因：未适配审计工作底稿的混合格式，导致解析过程中出现格式异常。
- 现象：提问后无响应。原因：`AIPROXY_API_TOKEN`配置错误或接口地址无法访问，未完成模型链路验证。
- 现象：回答中包含未处理的`<think>`标签。原因：未对模型返回内容做标签过滤，直接拼接至最终回答中。

## 怎么确认配好了
- 测试导入单份审计通知书文档，确认无报错且解析后的文档片段可在知识库中检索到。
- 调用配置好的模型，提问已知关联政策的审计问题，确认返回内容包含对应的政策依据片段。
- 检查`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置，模拟模型调用并确认返回结果正常。
- 测试使用带`<think>`标签的模型，确认已完成标签过滤，回答中无冗余标签内容。
