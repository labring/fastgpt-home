# 医保基金监管稽核的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类核心数据来自医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索，更新频率为每月一次。日常处理的文档包含稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书、整改报告，各类文档围绕稽核流程形成结构化与非结构化结合的内容，字段涵盖稽核编号、违规类型认定依据、整改反馈内容等，整体数据规模随月度稽核任务动态变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求配置适配不同格式的解析规则，确保结算数据、规则库文本等均可被正确识别。月更的更新节奏要求知识库同步周期与数据更新频率匹配，避免模型使用过期的监管规则。文档类型多样且部分内容存在非结构化特征，要求模型上下文处理能力适配长文本拼接需求。同时，稽核工作的出错后果直接关联基金安全，要求模型调用参数需严格控制生成精度，避免错误解读政策依据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配月度多源稽核文档拼接后的总长度需求，确保完整覆盖监管规则与业务数据 |
| `maxTokens` | 2000–3000 token | 匹配政策问答的标准回答长度，避免截断违规认定依据与整改要求 |
| `quoteMaxToken` | 1500–2000 字符 | 保障可完整引用单条监管规则或稽核文书的核心内容，确保回答的准确性与合规性 |
| `toolChoice` | auto | 支持自动触发文档召回与规则匹配工具，适配稽核场景下的多步骤问答需求 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保政策解读与稽核结论的严谨性，符合监管场景的合规要求 |
| `AIPROXY_API_ENDPOINT` | 对应模型的官方接入地址 | 确保模型调用链路的稳定性与兼容性，适配FastGPT的代理调用规范 |
| `AIPROXY_API_TOKEN` | 对应平台分配的有效令牌 | 完成模型调用的身份验证，保障接口调用的安全性 |

## 容易做错的三处
- 现象为上传稽核相关的PDF或Word文档时返回“文件格式不支持”或“上传失败”报错，原因是未配置对应文档类型的解析适配规则，或上传文件大小超出系统预设上限。
- 现象为配置ollama部署的模型并开启工具调用开关后，无法触发文档召回或规则匹配流程，返回空的工具调用结果，原因是模型版本对`toolChoice`参数的支持存在兼容性问题，未正确映射工具调用的请求格式。
- 现象为通过第三方代理接入模型时返回400错误，原因是请求参数中`AIPROXY_API_TOKEN`未正确配置，或请求头未携带符合要求的身份验证信息。

## 怎么确认配好了
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
- 提交一条已知政策依据的测试问题，核对模型返回内容是否准确关联配置的知识库内容。
- 上传品类内的标准文档，检查上传进度与解析结果是否符合预期格式。
- 触发工具调用测试，核对模型是否能正确触发文档召回或规则匹配流程。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的调用链路无异常。
