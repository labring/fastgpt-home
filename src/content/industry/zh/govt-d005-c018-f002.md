# 参保登记与缴费核定的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
本品类的核心数据来自社会保险经办系统、税务社保费征收系统、市场主体登记信息、公安民政数据共享渠道，更新频率为每日。日常涉及的文档包括参保登记表、缴费基数申报表、人员增减表、社保费核定单、个人权益记录，数据主体涵盖社保经办机构、人社局、税务部门及用人单位人事财务部门。文档多为结构化表格形式，包含人员身份、劳动关系、缴费基数、核定金额等字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的数据要求索引需支持增量同步，避免全量索引占用过多集群资源。结构化文档的字段密集特性，要求分块时需保留关键信息的完整性，避免拆分跨块的关联字段。多源数据的字段对齐需求，要求索引需支持按业务维度分组，确保检索时仅调用对应品类的数据集。同时，本品类数据直接关联个人权益与缴费合规性，要求检索结果的置信度需匹配业务标准，不可出现字段缺失或匹配错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配本品类结构化文档的字段密度，避免拆分关键关联信息 |
| 重叠长度 | 100–150 字符 | 保留跨块的人员身份、缴费基数等关联字段，提升检索连贯性 |
| `defaultToken` | 1024 token | 适配单条文档块的平均长度，平衡嵌入精度与调用成本 |
| `maxToken` | 8000 token | 匹配政策问答的上下文长度需求，覆盖完整的制度依据内容 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的无关文档，确保检索结果与政策依据的相关性 |
| 单次搜索上限 | 前 8 条 | 控制返回结果的数量，避免过多冗余信息干扰业务判断 |

## 容易做错的三处
- 索引任务长时间处于排队状态。原因是未配置增量索引触发规则，每日全量同步多系统数据时占用大量集群资源，导致新任务无法及时执行。
- 检索结果中出现无关品类的文档内容。原因是未按参保登记与缴费核定的业务维度创建专属索引分组，导致检索时调用了全量数据集。
- 嵌入模型调用返回报错。原因是未正确配置阿里multimodal-embedding-v1的调用参数，未校验`defaultToken`的设置与接口权限。

## 怎么确认配好了
- 查看FastGPT v4.17.0的索引任务日志，确认增量索引触发频率与数据日更节奏匹配。
- 发起针对参保登记或缴费核定的政策咨询测试，检查检索结果是否仅包含本品类的文档字段。
- 调整相似度阈值，观察检索结果的匹配精度变化，确认阈值设置符合业务需求。
- 验证嵌入模型的调用链路，确认阿里multimodal-embedding-v1的返回结果正常。
