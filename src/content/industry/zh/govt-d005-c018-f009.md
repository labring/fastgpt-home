# 参保登记与缴费核定的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源包括社会保险经办系统、税务社保费征收系统、市场主体登记信息及公安民政共享数据。日常处理的文档涵盖参保登记表、缴费基数申报表、人员增减表、社保费核定单、个人权益记录。数据更新频率为每日一次，核心字段包含人员身份信息、劳动关系状态、缴费基数、核定金额等。典型使用主体为社保经办机构、人社局、税务部门及用人单位人事财务部门，数据处理核心环节涉及身份核对、人员增减与基数申报、跨系统对账。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入配置需支持跨系统数据召回，避免单一数据源的局限性。每日更新的数据频率要求知识库同步任务需配置为增量更新，确保模型可获取最新的参保、缴费数据。不同业务文档的结构差异，要求分块策略需适配表单类文档的字段结构，避免上下文碎片化。核心字段的严谨性要求模型回答需严格匹配政策依据，降低随机性以减少出错可能。跨系统对账的需求要求模型需具备关联不同系统数据的能力，避免回答仅依赖单一数据源。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，针对参保登记与缴费核定的政策问答场景定制：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 参保登记与缴费核定的政策问答需关联多份表单与跨系统数据，需足够上下文承载关联信息 |
| `maxTokens` | 2000–3000 token | 政策依据回答需完整引用核定规则、缴费标准相关文本，需足够输出长度 |
| `quoteMaxToken` | 1500–2000 token | 需从参保登记表、缴费核定单等文档中截取有效政策依据片段，控制引用片段长度 |
| `temperature` | 0.1–0.3 | 政策依据问答需严格匹配制度条文，降低随机性以保证回答准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地部署或云服务的模型接入地址，满足政务场景的网络访问要求 |
| `AIPROXY_API_TOKEN` | 按权限配置 | 保障模型调用的访问安全，符合政务数据保密规范 |

## 容易做错的三处
- 现象：系统无法选择已通过openapi配置的本地模型，默认调用通用模型。原因：未在模型接入配置中绑定`AIPROXY_API_TOKEN`与对应模型实例，导致系统无法识别已配置的模型。
- 现象：本地部署的14b模型添加社保知识库后调用报错。原因：未调整`maxContext`参数适配本地模型的上下文限制，且未配置内网访问权限，导致知识库数据无法正常加载。
- 现象：回答中混入无关的待遇核定内容，偏离参保缴费场景。原因：未限定召回数据源为社保经办系统、税务社保费征收系统，误召回相邻品类的知识库数据。

## 怎么确认配好了
- 检查模型接入配置项，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`与部署的模型实例匹配。
- 触发知识库同步任务，核对同步日志中是否包含参保登记表、缴费基数申报表等品类专属文档。
- 发起测试提问，验证模型返回的回答仅关联参保缴费阶段的政策依据，未混入其他业务场景内容。
- 调整`temperature`参数后，验证回答的一致性，确认政策引用的准确性未受随机性影响。
