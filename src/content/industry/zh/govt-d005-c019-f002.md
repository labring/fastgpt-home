# 双随机、一公开监管检查的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库。日常文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示等，包含结构化字段与非结构化文本混合的内容，更新频率通常为月度。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的数据特征要求索引支持增量同步机制，避免全量重建带来的冗余计算。多类型文档混合的结构，需要适配结构化字段与非结构化文本的分块逻辑，确保检查事项、对象名单等内容能被精准拆分索引。高频调用的执法人员名录库数据，需限制索引资源占用，保障检索响应速度。政策问答场景需匹配监管政策的语义召回精度，避免无关检查记录或公示内容干扰结果。

## 配置怎么定
FastGPT v4.17.0 版本支持以下配置项的精准调整：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配日常文档的段落长度，覆盖检查事项清单、现场检查记录等典型内容 |
| 最大段落深度 | 3 级 | 匹配自动段落识别的常规使用场景，避免过度拆分或遗漏关键信息 |
| 索引大小 | 128 维 | 符合该品类高频检索的召回需求，平衡语义精度与系统资源占用 |
| `defaultToken` | 按实测标定 | 适配多模态Embedding模型的输入格式要求，避免Token超限报错 |
| `maxToken` | 8192 token | 匹配主流大模型的上下文窗口上限，保障政策问答的完整召回 |
| 相似度阈值 | 0.75–0.85 | 保障监管政策问答的语义匹配精度，过滤低相关的检索结果 |

## 容易做错的三处
- 现象：调用多模态Embedding模型测试时，返回`{"error":{"code":"Invalid"}}`格式报错。原因：未正确配置`defaultToken`参数，导致模型输入格式不符合要求。
- 现象：知识库检索返回的结果条数远少于预期。原因：未将索引大小调整至适配该品类数据的取值，导致召回范围过窄，无法覆盖全部相关政策文档。
- 现象：全量重建索引耗时过长，无法按时完成月度数据更新任务。原因：未启用增量同步配置，对历史数据重复执行索引生成流程，浪费系统资源。

## 怎么确认配好了
- 上传单份检查事项清单文档，验证分块结果与设置的分块长度、最大段落深度匹配。
- 调用测试接口输入监管政策相关问题，核对返回结果的条数与索引大小配置一致。
- 执行增量同步操作，验证仅新增的月度数据被纳入索引，历史数据未重复处理。
- 接入多模态Embedding模型后发起测试请求，确认无格式报错返回。
