# 双随机、一公开监管检查的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的典型数据来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库，更新频率通常为每月一次。日常涉及的文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示，各文档字段包含统一社会信用代码、执法证号、抽查批次号、检查事项条目等，部分字段需匹配监管对象的属地编码。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源包含多个监管系统，不同系统导出的文档格式存在差异，引用溯源环节需适配多源异构数据的解析规则。每月一次的更新频率要求知识库同步机制需匹配该节奏，避免引用过期的抽查计划或检查对象名单。检查事项清单、现场检查记录等文档的字段专业性强，需精准匹配监管执法的特定条目，不能泛化引用通用政策内容。抽查结果公示作为核心输出文档，需确保引用内容与公开信息完全一致，防止出现与监管口径不符的回复。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置逻辑编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大引用token数 | 800–1200 token | 双随机监管相关文档单篇长度多在数百到千余token，该区间可覆盖单篇核心检查记录或公示内容，避免截断关键信息 |
| 引用数据源配置 | 返回匹配文档的标题、来源系统、更新时间 | 监管类文档需明确溯源到具体系统和更新时间，便于核查合规性，符合执法公示的公开要求 |
| 详情返回开关 | 开启 | 双随机检查的引用需包含具体检查事项、对象信息，开启该配置可返回文档的完整字段内容，避免仅返回摘要 |
| 知识库同步周期 | 每月一次 | 匹配该品类数据的常规更新频率，确保引用内容为最新的抽查计划或检查结果 |
| 单次召回文档数 | 前3–5条 | 双随机监管的政策依据多集中在少数核心文档，过多召回会干扰回复准确性，同时控制上下文长度 |
| 引用格式校验 | 开启 | 监管类引用需严格匹配公开公示的内容格式，避免出现字段缺失或信息错误 |

## 容易做错的三处
- 现象：长文档引用时关键检查事项被截断，或回复内容不完整。原因：`quoteMaxToken`配置取值过小，未覆盖单篇文档的核心内容长度。
- 现象：调用时出现`quote type error`报错。原因：引用变量的格式未匹配监管文档的字段类型，例如将字符串类型的统一社会信用代码配置为数值型变量。
- 现象：回复中未展示引用文件的地址或来源信息。原因：未开启`responseData`配置中的来源地址展示开关，或配置项取值未包含来源路径字段。

## 怎么确认配好了
- 上传一份抽查结果公示文档，发起包含“抽查结果”的查询，核对回复中是否包含文档标题和来源系统信息。
- 调整最大引用token数的取值，验证长文档的引用内容是否被完整保留或合理截断。
- 模拟每月一次的知识库同步操作，检查更新后的文档是否能被正常召回并展示最新内容。
- 输入包含监管字段的查询，核对返回的引用内容是否匹配文档的原始字段信息，无额外错误格式。
