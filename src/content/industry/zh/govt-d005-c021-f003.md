# 国库集中支付与报销审核的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来源为国库集中支付系统、预算管理一体化系统、电子发票平台、合同管理系统，更新频率为每日。日常处理的文档包含支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，核心字段涵盖预算指标、经济分类、支付金额、审批流程节点等，单笔数据对应单次资金支付的全链条合规材料。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源数据来源要求对话系统需整合多平台的结构化与非结构化数据，确保政策依据匹配的完整性。每日更新的数据源要求对话上下文需同步最新的预算指标与支付额度，避免引用过期信息。多类型审批文档的链条属性，要求多轮对话需保留前序审批节点的信息，支撑合规性回溯。核心字段的合规校验需求，要求提示词需明确限定经济分类、预算指标的核对规则，确保回答符合财政管理要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口 | 10轮对话+3条系统提示 | 覆盖单笔支付的全流程审批回溯，避免上下文丢失 |
| 单次召回结果上限 | 前6条 | 覆盖支付申请、发票、合同等多类关联文档，确保合规依据全面 |
| 问题优化开关 | 开启 | 针对财政专业术语调整提问表述，提升政策匹配准确率 |
| 最大响应token数 | 2000–3000 token | 适配政策条文与审核流程的完整输出需求，避免截断关键内容 |
| 变量绑定配置 | 开启`variables` | 动态调用国库系统、电子发票平台的实时数据，保证回答时效性 |
| 上下文标识配置 | 绑定`chatId` | 确保多轮对话的上下文关联正确，避免跨会话混淆 |

## 容易做错的三处
- 调试预览界面对话出现报错，现象为开启输入引导并配置自定义词库后无响应或弹出异常提示，原因是自定义词库的文件格式未符合系统要求，导致词库加载失败。
- 特定问题的最大响应token自动降至200，现象为回复内容被强制截断，长度远低于预设的3000以上上限，原因是系统触发了专业场景的输出长度兜底规则，或上下文超限触发自动截断。
- 无法在对话过程中新增知识库内容，现象为执行添加操作后知识库未更新，原因是未开启对话式知识库的动态写入配置，或未绑定对应数据源的读写权限。

## 怎么确认配好了
- 进入调试预览界面，输入包含预算指标、经济分类的测试问题，检查回复是否关联对应文档的合规依据。
- 发起多轮对话，依次询问前序审批节点、当前支付额度等问题，检查上下文是否被正确保留。
- 查看系统统计面板，确认`messages`的上下文轮次符合配置要求，无异常截断。
- 查看对话的`chatId`字段，确认跨会话的上下文未发生混淆。
- 输入超过2000 token的政策相关问题，检查回复是否完整输出，未被强制截断。
