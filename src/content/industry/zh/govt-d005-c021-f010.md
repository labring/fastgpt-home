# 国库集中支付与报销审核的政策与制度依据问答：知识库检索与召回

## 这个品类的数据长什么样
本细分品类的数据来源为国库集中支付系统、预算管理一体化系统、电子发票平台、合同管理系统，更新频率为每日。日常处理的文档包含支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证等，文档结构覆盖审批流程记录、资金凭证、业务合同三类，字段包含业务编号、预算指标编码、经济分类代码、金额、审批节点状态等，单份文档长度从数十字符到数千字符不等。本内容基于FastGPT v4.17.0版本的知识库功能实现。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源系统接入的特性要求检索链路支持跨数据源的统一索引，每日更新的节奏需要配置定时同步机制以保证政策与业务凭证数据的时效性。不同类型文档的结构差异，要求分块策略适配审批单、合同、发票等不同文档的语义单元。单笔支付审核需精准匹配对应政策条款，避免无关内容干扰，因此检索召回的相关性阈值需严格控制，同时需覆盖全部关联业务数据源的政策依据，防止出现合规性漏判。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 需精准匹配政策条款与业务场景，避免低相关性结果干扰审核判断 |
| `limit` | `前10条` | 国库审核需覆盖多维度政策依据，同时控制单轮上下文长度以保证响应速度 |
| `searchMode` | `vector + keyword hybrid` | 政策文本兼具精准关键词匹配需求与语义关联需求，混合搜索可兼顾召回完整性与相关性 |
| `usingReRank` | `开启` | 多源召回的文档需进一步校准排序，确保核心政策条款优先返回 |
| `datasetSearchUsingExtensionQuery` | `开启` | 可补全用户问题中省略的政策限定词，扩大有效检索范围 |
| `collectionIds` | `国库支付与报销审核专属数据集ID` | 隔离不同业务场景的知识库数据，避免无关文档干扰审核流程 |

## 容易做错的三处
- 现象：单次搜索耗时超过30秒，返回结果延迟。原因：未配置`usingReRank`或`similarity`阈值设置过低，导致召回过多低相关性文档参与重排与排序。
- 现象：检索结果仅返回单个知识库的内容，无法同时展示两个关联知识库的政策依据。原因：未正确配置`collectionIds`，仅指定了单个数据集ID，未覆盖全部关联业务数据源。
- 现象：通过API插入文档后无法在知识库中检索到。原因：未指定目标`collectionIds`参数，或插入操作未触发数据集同步更新。

## 怎么确认配好了
- 发起包含具体政策场景的测试查询，核对返回结果的相关性是否符合审核要求。
- 调用API执行单次检索，记录耗时并确认符合业务响应预期。
- 向指定`collectionIds`的数据集插入测试文档，验证检索结果中包含该测试内容。
- 开启`usingReRank`后对比关闭状态下的结果排序，确认重排逻辑生效。
