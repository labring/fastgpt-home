# 土地使用权、矿业权与国有产权交易的政策与制度依据问答：工具调用与插件

## 这个品类的数据长什么样
本品类数据主要来自全国公共资源交易平台、自然资源交易系统、产权交易所系统及国资监管系统，更新频率为每日。日常处理的文档包含出让公告、交易须知、竞买申请、保证金凭证、成交确认书、挂牌结果公告、产权转让说明书等，核心字段涉及交易标的权属、限制条件、估值标准、保证金要求与成交确认规则，数据围绕土地使用权、矿业权及国有产权的交易全流程生成。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散于多个官方系统，工具调用需适配多源数据的权限校验与接入逻辑；每日更新的特性要求插件触发频率匹配数据更新节奏，避免调用过期或未同步的政策内容；文档类型多样，需插件支持解析不同格式的公告、申请书与交易凭证；核心字段涉及权属与限制条件等敏感内容，工具调用需严格遵循参数校验规则，防止错误匹配不适用的政策依据。由于交易合法性直接关联标的权属与规则匹配度，工具调用需确保检索的政策内容与当前交易标的的区域、类型完全对应，避免跨场景调用无关规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配本品类多类型政策文档的检索与调用需求，自动匹配对应工具函数 |
| `functionCall` | `{"name": "query_policy_db", "parameters": {"topic": ["土地使用权", "矿业权", "国有产权"]}}` | 限定工具调用的主题范围，避免检索无关政策内容，贴合本品类的细分业务场景 |
| 单次调用最大文档条数 | 前8条 | 本品类核心文档数量适中，过多条目会超出上下文窗口，过少则无法覆盖完整政策依据 |
| 上下文窗口上限 | 8000–12000 token | 本品类政策文档包含较多专业术语与权属说明，需要足够上下文确保检索准确性，按实测标定 |
| 工具调用超时时间 | 60秒 | 多源数据检索需同步访问多个交易系统，60秒可覆盖多数常规检索场景，避免长时间等待导致的流程阻塞 |

## 容易做错的三处
- 调用工具时返回`400 InternalError.Algo.InvalidParameter: The tool`报错，原因是未正确限定`functionCall`的参数主题，导致工具尝试调用不匹配本品类的政策检索函数。
- 插件调用返回结果为空或条数不足，原因是未设置合理的单次调用最大文档条数，或未适配本品类每日更新的数据节奏，调用了过期的历史数据。
- 流程中无法调用已创建的线上插件，原因是未在FastGPT流程节点中正确绑定对应工具的权限与触发规则，未将插件与政策检索的业务逻辑关联。

## 怎么确认配好了
- 手动触发工具调用，检查返回的政策文档是否包含本品类的出让公告、产权转让说明书等类型内容。
- 查看工具调用日志，确认`toolChoice`参数为`auto`且`functionCall`的参数主题匹配本品类的三类交易标的。
- 模拟每日更新的数据场景，触发工具调用，确认结果的更新时间符合当日数据的要求。
- 测试流程节点中绑定插件的触发逻辑，确认插件可正常被流程调用并返回有效结果。
