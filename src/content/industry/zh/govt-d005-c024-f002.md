# 学生资助与奖补审核的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自全国学生资助管理信息系统、学校学籍系统、民政低保特困数据、财政支付系统。日常处理的文档包括家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单、公示材料。数据更新以学期为周期，文档多包含学籍标识、家庭经济状况描述、资格判定字段与发放明细条目，无额外自定义统计类字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
多系统联动的数据来源要求索引需支持跨字段关联匹配，确保学籍、低保、财政数据的一致性校验。学期级的更新节奏意味着索引需适配批量增量更新，避免全量重建带来的额外耗时。文档包含结构化表单与非结构化政策文本，需针对两类内容分别适配分块策略，保障政策条款的完整性与表单字段的关联性。资格判定相关的政策文本需精准召回，避免模糊匹配导致的审核偏差，发放名单类数据需设置合理的检索权重，确保关联检索的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 本品类文档包含政策文本与结构化表单，该区间可平衡政策条款完整性与表单字段关联性 |
| 重叠长度 | 100–150 字符 | 政策文本存在跨段落的逻辑关联，重叠长度可避免关键信息被分块截断 |
| 单次搜索上限 | 前 5 条 | 审核场景需精准匹配政策条款与申请材料，过多召回结果会增加人工核验负担 |
| 最大上下文 | 3000–4000 token | 政策依据问答需整合多份政策文本片段，该区间可覆盖完整的政策逻辑链 |
| 超时阈值 | 600 秒 | 适配多系统数据调取的耗时需求，避免因调用超时导致索引中断 |
| 重排优先级 | 按政策文本权重优先 | 政策依据问答需优先匹配政策条款，保障审核依据的准确性 |

## 容易做错的三处
- 手动插入知识库后生成的默认索引数小时后消失：未配置索引持久化存储，系统临时生成的索引未被写入持久化目录，重启或定时清理后丢失。
- 接入qwen3-embedding-8b后文件状态持续显示“索引中”：未在FastGPT v4.17.0版本中正确配置嵌入模型的调用地址与密钥，或模型响应超时。
- 检索结果包含无关政策条款：分块重叠长度设置不足，导致跨段落的政策关联逻辑被拆分，向量召回时无法匹配完整语义。

## 怎么确认配好了
- 手动插入一份政策类文档，查看索引列表中是否生成对应条目，确认持久化配置生效。
- 调用嵌入模型接口，返回向量数据格式符合FastGPT要求，确认模型兼容性。
- 提交一条与资助资格相关的审核问题，查看检索结果的召回条数符合单次搜索上限配置。
- 等待一个学期更新周期后，查看增量更新后的索引是否包含新导入的学期数据，确认更新逻辑正常。
