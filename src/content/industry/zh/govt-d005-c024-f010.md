# 学生资助与奖补审核的政策与制度依据问答：知识库检索与召回
本文档基于 FastGPT v4.17.0 版本编写。

## 这个品类的数据长什么样
本品类的核心数据来自全国学生资助管理信息系统、学校学籍系统、民政低保特困数据及财政支付系统。日常文档包含家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单及公示材料，字段覆盖学生身份、家庭经济状况、学籍状态、资金发放信息等。数据更新以学期为周期，单次更新覆盖全量学期内的政策文档与业务数据。业务核心环节围绕困难认定、学籍核验、名单核对展开，数据准确性直接关联资助发放的合规性。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源数据与固定更新周期要求检索系统需支持跨系统文档的统一索引，且需按学期周期完成全量知识库同步，避免新旧数据混淆。文档类型覆盖业务表单与政策文本，需同时匹配精准字段与语义关联的查询需求，不能仅依赖单一检索模式。数据更新周期较长意味着检索系统无需实时同步，但需在更新窗口内完成全量数据的重新索引，保障检索结果的时效性。业务环节的高合规性要求，决定了检索结果需具备高置信度，避免无关或错误的政策依据被召回。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 政策与制度依据的检索需较高匹配精度，该区间可过滤低相关性的非政策类文档，保障召回内容的合规性 |
| `limit` | 前10条 | 政策依据的核心条款通常集中在少量文档中，10条结果可覆盖完整的政策参考范围，避免冗余信息干扰审核流程 |
| `searchMode` | hybrid | 兼顾语义匹配与关键词匹配，可同时适配专业政策术语的精准查询与口语化业务问题的语义检索 |
| `usingReRank` | 开启 | 政策文档数量较多时，重排可优化结果排序逻辑，将最相关的政策条款优先返回，提升审核效率 |
| `datasetSearchUsingExtensionQuery` | 开启 | 业务人员常使用口语化表述提问，该配置可自动扩展查询词，匹配政策文本中的专业术语，提升召回准确率 |
| `collectionIds` | 绑定本品类专属的政策与业务文档集合 | 限定检索范围至学生资助相关的知识库集合，避免其他品类的文档干扰检索结果，保障合规性 |

## 容易做错的三处
- 搜索时提示“当前分组 default 下对于模型 gpt-4o-mini 无可用渠道”，未配置对应模型的知识库检索渠道，或未将检索任务绑定到正确的分组。
- 使用变量引用选择知识库时无法明确参数填写规则，未提前定义知识库集合的标识规范，未在变量配置中说明需传入合法的`collectionIds`参数值。
- 知识库中上传的图片链接在AI回复中显示为“input an image”，未开启知识库图片的可访问链接渲染配置，或检索时未正确提取图片的可展示地址。

## 怎么确认配好了
- 上传本品类对应的家庭经济困难认定表、奖助学金政策文本等文档至FastGPT知识库，检查`collectionIds`是否包含对应集合的唯一标识。
- 发起测试查询，输入“家庭经济困难学生资助申请条件”，检查返回结果的`similarity`得分是否符合预设区间，结果条数是否与`limit`设置一致。
- 开启`usingReRank`后，对比开启前后的检索结果排序，确认相关性更高的政策文档优先返回。
- 测试包含口语化表述的查询，输入“家里经济困难怎么申请助学金”，检查`datasetSearchUsingExtensionQuery`是否能正确匹配到对应的政策文档。
