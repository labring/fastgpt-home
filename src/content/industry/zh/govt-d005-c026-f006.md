# 工程建设项目审批的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据来自工程建设项目审批管理系统、施工图审查系统、企业资质库、信用平台，更新频率为每日。日常文档包含施工许可申请材料、施工图审查合格书、质量安全监督手续、竣工验收备案表等，数据字段围绕审批节点、参建单位资质、项目合规性展开，无统一固定单位，随单份文档的业务属性调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的数据来源分散，覆盖工程审批、施工图审查、企业资质、信用等多个系统，引用溯源需明确关联各数据源的唯一标识，避免混淆不同系统的同类信息。每日更新的特性要求同步频率匹配业务节奏，确保引用内容为最新审批状态。文档类型多样，包含申请材料、合格书、备案表等不同格式，需适配各类文档的结构识别逻辑，保证引用片段的精准性。字段无统一固定单位，需保留原始文档的字段标注，确保溯源时的信息完整可追溯。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配工程审批类文档的单段有效信息长度，避免截断关键合规条款 |
| `responseData` | 包含来源字段的结构化格式 | 确保返回内容中包含数据源标签、文档ID等溯源信息，符合住建系统的合规要求 |
| `detail` | 开启 | 完整展示引用片段的上下文，便于核对审批依据的完整性 |
| 数据源绑定规则 | 按系统分类关联 | 匹配本品类多数据源的特性，确保溯源时可直接定位到工程审批管理系统等对应来源 |
| 单次召回上限 | 前5条 | 控制返回结果的冗余度，聚焦最相关的审批政策与项目依据 |

## 容易做错的三处
- 现象：返回结果显示引用了知识库文档，但生成的回答未包含知识库中的审批政策内容。原因：`quoteMaxToken`取值过小，导致引用片段被截断，无法提取有效合规依据。
- 现象：知识库中的施工图审查合格书、竣工验收备案表等非文本数据未被召回。原因：未配置适配多类型文档的召回规则，仅启用了文本数据集的召回逻辑。
- 现象：动态传入搜索参数后，生成的回答未关联对应审批项目的依据文档。原因：未将搜索参数与数据源绑定规则关联，导致搜索范围未匹配到目标审批系统的文档。

## 怎么确认配好了
- 查看生成回答的末尾，确认存在标注数据源、文档名称的引用条目，可根据业务场景调整引用展示规则。
- 传入特定审批项目的参数，验证召回结果包含该项目对应的施工许可申请、资质审核等文档。
- 检查`quoteMaxToken`的取值，确保覆盖单段审批政策的有效长度，可根据实测结果调整。
- 查看响应数据的结构化字段，确认包含数据源标签、文档ID等溯源信息。
