# 工程建设项目招投标的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据来源为全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，核心字段涵盖标段标识、资格要求、评标细则、异议投诉内容及公示更正信息，数据结构随项目类型略有差异。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的招投标数据要求索引支持高频增量同步，避免政策依据问答出现数据滞后。多类型非标准化文档结构，要求索引适配灵活的文本分块逻辑，适配招标公告、评标报告等不同文档的段落差异。招投标专属的资质、业绩、评标细则等专业字段，需确保向量模型可精准捕捉术语关联。异议投诉与公示更正的时效性需求，需压缩索引构建延迟，同时避免标段拆分错误导致的问答匹配偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配招投标文档的段落长度，避免资质、业绩等专业术语被拆分断裂 |
| 重叠长度 | 100–150 字符 | 保留跨分块的标段信息、关联要求等内容，提升问答匹配准确性 |
| `maxToken` | 4096 token | 匹配FastGPT v4.17.0中bge-large模型的输入上限，适配长文本政策依据问答 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 过滤低关联的文档片段，避免返回无效的招投标政策内容 |
| 单次搜索上限 | 前 8 条 | 平衡响应速度与结果完整性，覆盖核心政策依据与相关文档 |
| `defaultToken` | 2048 token | 控制单轮问答的上下文长度，避免超出模型处理能力 |

## 容易做错的三处
- 现象：导出的知识库dataset.csv仅包含index字段，无content字段。原因：未正确配置索引关联的MongoDB表与字段，导致源文档内容未被正确提取。
- 现象：使用bge-large模型导入文本时，未调整分块参数导致长文本被过度拆分。原因：默认分块长度未适配招投标文档的专业段落结构，丢失关键资质或业绩关联信息。
- 现象：本地部署索引模型时出现显存不足报错。原因：未指定模型加载的显卡设备，多张3090显卡未被正确分配，导致单卡显存无法承载大模型。

## 怎么确认配好了
- 登录FastGPT后台查看索引同步日志，确认每日增量同步任务无报错。
- 输入与招投标资质要求相关的查询，核对返回结果是否包含对应项目的官方文档内容。
- 导出知识库的dataset.csv文件，确认文件同时包含index与content字段。
- 查看模型运行日志，确认指定的向量模型已成功加载至目标设备。
