# 工程建设项目招投标的政策与制度依据问答：工具调用与插件

## 这个品类的数据长什么样
本品类数据主要来自全国公共资源交易平台、地方交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常处理的文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，文档结构多包含标段划分、资格条件、评标专家记录、异议投诉记录等字段，无统一固定单位，随文档类型变化。

## 这些特征在「工具调用与插件」这一环带来什么约束
每日更新的数据源要求工具调用需配置高频同步逻辑，确保检索语料的时效性。多类型文档的混合调用，需要插件适配不同格式的解析规则，适配招标公告的结构化字段与评标报告的非结构化文本。跨系统数据源的调用需配置平台认证参数，避免权限限制导致的检索失败。文档中分散的标段、资格条件等字段，要求工具调用支持精准字段匹配，避免无关内容干扰问答结果。第三方API的接入需配置对应平台的认证参数，避免依赖平台积分消耗。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ------------ |
| `toolChoice` | `auto` | 适配多类型招投标文档的自动工具选择，覆盖结构化与非结构化数据检索 |
| 单次工具调用超时时间 | 600 秒 | 匹配跨多个公共资源交易平台的常规响应时长，避免平台延迟导致调用失败 |
| `functionCall` 触发阈值 | 前 8 条 | 覆盖招标公告、评标报告等核心文档的必要信息，避免结果冗余 |
| 文档格式适配插件 | 支持PDF、DOCX、XML、1000 MB以内文件 | 匹配本品类日常使用的招标、评标、中标类文档格式与大小限制 |
| 溯源信息展示开关 | 开启 | 满足政策依据追溯的业务要求，符合招投标合规检查的需求 |
| 第三方API接入配置 | 绑定对应公共资源交易平台的官方API密钥 | 支持使用第三方平台接口拉取招投标数据，避免依赖平台积分消耗 |

## 容易做错的三处
- 现象：工作流中调用公共资源交易平台API后，返回结果为空。原因：未配置对应平台的API权限认证参数，导致无法拉取招投标相关文档。
- 现象：AI生成的政策依据问答未附带原始文档溯源信息。原因：未开启溯源信息展示配置，或未将API返回的文档ID与位置字段绑定到回答内容中。
- 现象：工具调用时使用的模型与预设不符，出现参数不兼容报错。原因：未在对话配置中指定工具调用绑定的模型，默认模型不支持招投标文档的结构化解析。

## 怎么确认配好了
- 发起一次针对某招标公告的政策依据问答，检查返回结果是否包含对应文档的名称与具体位置。
- 查看工具调用日志，确认是否成功拉取了公共资源交易平台的最新文档数据。
- 上传不同格式的招投标文档，确认插件可以正常解析文本内容并提取关键字段。
- 调整工具调用的召回数配置，验证返回结果的条数是否符合预设要求。
