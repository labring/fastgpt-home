# 工程建设项目招投标的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来源为全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常文档涵盖招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，数据字段包含标段划分规则、资格条件要求、评标专家记录、异议投诉处理流程及公示更正内容，未包含虚构统计数值。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多平台数据来源要求溯源环节需关联对应公共资源交易平台、工程审批系统的原始文档链接，确保来源可追溯；每日更新频率要求配置增量同步机制，避免引用过期内容；多样的文档类型需针对招标公告、评标报告等不同文档的字段结构，建立标准化的溯源字段映射规则；高风险的出错后果要求溯源结果需关联原始文档的具体段落，确保引用精准无误。

## 配置怎么定
本配置指南适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 工程招投标政策文档的单段引用内容通常覆盖完整条款，该区间可容纳多数场景的引用需求 |
| `responseData` | 包含原始文档URL与段落位置 | 需明确关联对应公共资源交易平台的原始文档位置，满足溯源合规要求 |
| `detail` | 开启 | 需展示引用内容的上下文，便于核对政策依据的适用场景 |
| 单次搜索上限 | 前5条 | 招投标政策依据多集中在官方发布的核心文档，过多召回会导致上下文冗余 |
| 增量同步间隔 | 12小时 | 匹配每日更新的数据源频率，确保引用内容为最新版本 |

## 容易做错的三处
- 现象：知识库原文链接经nginx代理后无法正常下载，返回404或超时错误。原因：未配置代理的路径重写规则，导致原始文档的相对路径无法正确映射到代理后的访问地址。
- 现象：调用post请求接口后返回空content字段，无任何引用内容。原因：未开启`responseData`配置项，或未正确关联数据源的原始文档链接，导致系统无法提取有效引用内容。
- 现象：生成的引用格式杂乱，或出现乱码字符。原因：未针对招投标文档的多字段结构配置标准化的溯源格式，或未正确处理文档中的特殊字符编码。

## 怎么确认配好了
- 发起测试查询，输入与工程招投标政策相关的问题，核对返回结果中是否包含对应公共资源交易平台的原始文档链接。
- 查看系统的同步日志，确认每日增量同步任务正常执行，无失败记录。
- 检查引用内容的格式，确认无乱码字符，且标注的段落位置与原始文档一致。
- 调用post请求接口，验证返回的content字段包含有效引用内容及来源信息。
