# 工程建设项目招投标的政策与制度依据问答：模型接入与配置
本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类数据来自全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常业务文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，涉及标段划分、资格条件、评标专家记录、异议投诉及公示更正等核心业务字段，均为标准化生成的业务文档，无额外自定义统计数值。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的数据源要求模型接入环节需支持增量数据同步，避免全量拉取带来的资源占用与同步延迟。多类结构化业务文档混合存在，需适配招标公告、评标报告等不同文档的字段结构，确保资格条件、评标记录等核心信息准确提取。招投标场景的合规性要求问答结果必须严格匹配官方发布的文档原文，不得生成无依据内容。中标结果相关问答需严格关联对应标段与公示公告，避免跨项目或跨标段的错误关联，防止引发合规风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 招投标文档多为长文本，需覆盖完整的招标文件、评标报告等上下文 |
| `maxTokens` | `4000–6000 token` | 政策问答需生成完整合规的回复，避免截断关键内容 |
| `quoteMaxToken` | `2000–3000 token` | 需保留足够的官方文档原文引用片段，确保问答合规性 |
| `temperature` | `0.1–0.3` | 政策问答需严格匹配原文，避免生成发散或无关内容 |
| `AIPROXY_API_ENDPOINT` | 按实测标定 | 适配不同云服务商的专属API接入地址 |
| `AIPROXY_API_TOKEN` | 按实测标定 | 用于身份验证，需与服务商提供的密钥一致 |

## 容易做错的三处
- 现象为Azure OpenAI模型接入后返回协议不兼容报错，状态码为400。原因是未正确配置`AIPROXY_API_ENDPOINT`为Azure专属的API地址，未适配非标准OpenAI协议的请求格式。
- 现象为模型返回的政策问答内容与官方文档不符，引用片段为空或不完整。原因是未合理设置`quoteMaxToken`参数，导致引用片段被过度截断或未提取到有效内容。
- 现象为系统提示上下文不足，无法处理长招标文件或评标报告。原因是`maxContext`参数设置过低，未覆盖完整的业务文档上下文长度。

## 怎么确认配好了
- 接入指定云服务商的API后，调用测试接口返回正常响应，核对`AIPROXY_API_TOKEN`与服务商提供的密钥一致。
- 上传单份招标文件，测试问答功能返回的结果包含文档内的资格条件、标段划分等字段，确认配置适配该类文档的上下文长度。
- 上传多份不同类型的招投标文档，测试解析后提取的字段符合对应文档的业务结构，确认配置适配多文档类型。
- 触发增量同步任务，核对仅新增的当日文档被加载，确认适配每日更新的数据源要求。
