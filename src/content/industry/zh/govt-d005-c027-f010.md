# 工程建设项目招投标的政策与制度依据问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来源为全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告等，数据字段覆盖项目标段、资格条件、评标标准、中标信息等行业通用内容，无自定义专属单位，字段均符合招标投标领域的标准规范。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的数据源要求检索系统支持增量同步机制，避免全量索引重建占用过多系统资源。多类型文档结构覆盖长短文本，长文本如招标文件需合理拆分避免核心信息丢失，短公告需保证召回完整性。字段聚焦标段、资格条件、评标规则等专业内容，检索需匹配行业专属术语，同时需兼容多平台来源的格式差异，防止数据解析错误影响召回结果。业务出错后果直接关联检索准确率，需严格控制召回结果的精准度，避免错误政策依据影响项目流程。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.88 | 匹配工程招投标政策的专业术语，过滤无关检索结果同时保留核心政策依据 |
| `limit` | 前8–12条 | 覆盖单项目招标关联的多份政策文档，避免上下文长度超出模型限制 |
| `searchMode` | 全文检索 | 适配招标公告、招标文件等长短混合的文档结构，支持分段内容的关联召回 |
| `usingReRank` | 开启 | 对召回结果按相关性重新排序，优先展示资格条件、评标规则等核心政策内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充工程招投标领域的同义术语扩展，提升政策依据的召回覆盖率 |
| `collectionIds` | 按业务场景绑定专属数据集 | 隔离不同项目的政策文档，避免跨标段、跨项目的无关内容干扰检索 |

## 容易做错的三处
- 知识库拆分文档分段后出现查询结果不全。原因是未针对长文档设置合理的分段重叠长度，导致相邻分段的关联信息丢失，无法跨分段召回完整政策依据。
- 上传PDF文档后搜索无结果且显示错误。原因是未完成文档的文本提取预处理，或文档格式存在解析异常，导致系统无法生成有效向量索引。
- 检索时报错`invalid configuration parameter name "hnsw.iter"`。原因是错误配置了非允许的索引参数，误将其他平台的索引配置项导入当前系统，导致参数校验失败。

## 怎么确认配好了
- 上传单份招标公告文档，执行检索测试，核对召回结果是否包含文档内的核心政策条款，调整`similarity`配置区间至符合业务需求的精准度。
- 导入多份同项目关联文档，验证`limit`配置的召回条数是否覆盖所有相关政策文件，无上下文溢出问题。
- 触发增量同步任务，确认每日更新的政策文档能自动纳入检索范围，无同步延迟或遗漏。
- 模拟异议投诉类查询，验证`usingReRank`是否能优先召回评标规则、资格条件等相关政策依据。
