# 市场主体登记与许可的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
数据来源为企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统、住所信息库，更新频率为每日。日常文档包含设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等，文档结构多包含主体标识字段、许可事项字段、材料核验字段，字段均遵循政务市场监管领域标准格式，无自定义特殊字段单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且每日更新，要求配置时需适配增量同步逻辑，确保知识库数据与政务系统实时对齐，避免出现内容过时或不一致的情况。日常文档多为表单与证明类，字段结构固定，检索时需优先匹配主体标识、许可事项等精准字段，减少无关内容对精准检索的干扰。问答需严格基于政策与登记规范，要求模型输出不能脱离知识库内容，同时需适配政务场景下的严谨性要求，避免出现模糊或不符合流程的表述。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的标准逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–16000 token | 适配政务文档的长文本检索需求，覆盖多份登记材料与政策条文的上下文关联内容 |
| `maxTokens` | 2000–3000 token | 满足政策依据问答的完整输出长度，避免截断关键流程说明与合规要求 |
| `quoteMaxToken` | 1000–1500 token | 限定知识库引用的单段内容长度，确保检索结果与问答的匹配精度 |
| `temperature` | 0.1–0.3 | 适配政务场景的严谨性要求，降低模型自由生成比例，优先返回知识库内的标准内容 |
| `AIPROXY_API_ENDPOINT` | 按政务专线实际地址填写 | 适配政务网络环境的访问限制，确保模型调用链路合规可控 |
| `AIPROXY_API_TOKEN` | 按团队分配的专属密钥填写 | 保障模型调用的权限安全，避免非授权访问与数据泄露风险 |

## 容易做错的三处
- 现象：检索后台显示匹配到登记材料与政策条文，但模型返回未找到相关依据。原因：`maxContext`参数设置过小，无法加载完整的上下文关联内容，导致模型无法识别匹配结果。
- 现象：团队管理后台无法查询到特定成员的模型调用记录。原因：未开启调用日志的全量采集配置，或权限配置未覆盖目标成员的操作范围。
- 现象：模型输出内容超出预期长度且出现截断。原因：`maxTokens`参数设置未匹配问答场景的输出需求，或知识库引用的总token超过系统限制。

## 怎么确认配好了
- 执行单份登记材料的检索测试，核对检索结果与知识库内的文档内容是否一致，调整匹配规则直至符合预期。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置未出现格式错误，调用状态码处于正常范围。
- 触发一次完整的政策问答测试，验证输出内容未脱离知识库的政策与登记规范，且长度符合预设要求。
- 查看知识库同步记录，确认每日增量同步任务正常执行，数据更新时间与政务系统的更新频率对齐。
