# 市容环卫与城管执法案件的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据通常来自城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。日常文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书与结案报告，字段涵盖案件编号、违法地点、责任主体、整改要求及处置进度，无固定统一的标准化单位字段，部分文档附带多媒体附件。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类数据来源分散且包含文本与多媒体附件，多轮对话需支持跨类型文档的上下文关联。每日更新的案件数据要求对话上下文需限定有效时间范围，避免引用过期信息。文档字段无统一标准，提示词需引导系统从非结构化内容中提取案件编号、违法地点等核心字段。现场取证的多媒体内容需在对话中可被关联引用，同时需约束提示词仅基于官方文档生成依据，防止生成无依据结论。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 800–1200 字符 | 适配日常案件文档的单条内容长度，避免超出模型处理上限 |
| 历史消息保留条数 | 前15条 `messages` | 该品类案件数据每日更新，限定近期对话可减少过期信息干扰 |
| 预设变量 | 案件类型、责任主体、违法地点 | 引导提示词聚焦城管执法核心字段，适配多轮追问场景 |
| 会话绑定规则 | 按`chatId`绑定单案件 | 避免跨案件数据被错误关联，符合执法场景的单案件处理逻辑 |
| 输出过滤配置 | 仅保留结论与依据内容 | 过滤冗余的中间处理信息，适配执法人员的快速阅读需求 |

## 容易做错的三处
- 现象：不同案件的对话上下文被混淆，返回结果包含无关案件信息。原因：未配置按`chatId`绑定单案件会话的规则，跨案件数据被错误加载。
- 现象：Markdown格式导入的现场照片无法正常显示，图片链接缺失完整域名。原因：未配置变量自动补全图片域名的规则，仅在Word导入时生效，未适配Markdown导入场景。
- 现象：工具调用后仍输出工具执行日志，干扰执法人员阅读。原因：未设置输出过滤规则，未明确提示词要求仅返回政策依据与结论内容。

## 怎么确认配好了
- 发起单案件的连续追问，检查对话上下文是否仅包含该案件的相关信息。
- 上传Markdown格式的案件文档，验证图片链接是否自动补全完整域名。
- 调用工具获取政策依据后，确认输出内容仅包含结论与依据，无工具执行日志。
- 切换中英文输入，检查对话开场白是否按预设配置正确切换。
