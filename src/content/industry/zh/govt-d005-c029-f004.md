# 市容环卫与城管执法案件的政策与制度依据问答：工作流编排

## 这个品类的数据长什么样
该品类的数据通常来自城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。日常关联文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告。数据字段通常包含案件编号、违法类型、责任主体、整改状态、处置时限等，部分关联非结构化内容如现场影像、纸质文书扫描件。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据接入要求工作流配置多类型数据拉取节点，适配结构化表单与非结构化影像、文书内容。每日更新的数据源要求工作流触发周期匹配日级更新节奏，避免重复处理未更新的过期数据。混合文档结构要求工作流拆分结构化字段提取、非结构化内容解析两个独立环节，分别适配不同的处理逻辑。现场处置相关的核心环节需设置独立校验节点，前置验证证据完整性与主体匹配性，降低后续执法争议风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发节点 | 每日定时触发 | 匹配数据源日级更新频率，确保处理最新的案件数据 |
| `variables` | 绑定案件编号、违法类型字段 | 适配日常文档的核心字段，为政策依据问答提供精准检索条件 |
| `nodeId` | 关联现场取证节点ID | 绑定核心处置环节的执行状态，用于后续流程校验 |
| 单次召回结果上限 | 前5条 | 控制检索范围，避免无关内容干扰政策匹配判断 |
| 超时阈值 | 600秒 | 适配多源数据拉取与非结构化内容解析的耗时需求 |
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 容易做错的三处
- 现象：工作流运行超时，返回504状态码。原因：未根据多源数据拉取与解析的耗时调整超时阈值，设置的阈值过短。
- 现象：嵌套在其他工作流中的表单输入节点弹窗持续显示。原因：未在表单节点配置中关闭嵌套场景的弹窗自动隐藏逻辑。
- 现象：政策问答召回结果过多，无法快速定位有效依据。原因：未设置合理的单次召回结果上限，导致检索内容冗余。

## 怎么确认配好了
- 触发工作流，检查是否按每日定时自动启动，无手动触发的冗余执行。
- 查看`variables`绑定的字段是否与当前案件的核心信息一致，无缺失或错误关联。
- 模拟嵌套场景调用表单节点，确认弹窗自动隐藏，无重复显示问题。
- 运行工作流并查看超时日志，确认流程未因阈值设置过短出现中断。
