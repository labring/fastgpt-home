# 市容环卫与城管执法案件的政策与制度依据问答：文档解析与分块
本文基于 FastGPT v4.17.0 版本编写，面向市容环卫与城管执法领域的政策与制度依据问答场景，聚焦文档解析与分块环节的落地配置。

## 这个品类的数据长什么样
该品类的典型数据来自城管执法平台、城市运行网格平台、视频监控与群众投诉工单，更新频率为每日。日常处理的文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书与结案报告，常见字段包括案件编号、违法点位描述、责任主体信息、处罚依据与整改要求，部分文档附带现场取证的图片或视频截图。

## 这些特征在「文档解析与分块」这一环带来什么约束
多来源的数据格式差异较大，既有结构化的执法文书，也有非结构化的巡查记录与现场图片，要求解析环节支持多格式适配。每日更新的批量数据需要稳定的解析效率，避免因解析超时影响案件流转。文档中的关键信息如处罚依据与对应案件主体绑定紧密，分块时需保留上下文关联，防止拆分后无法支撑完整的政策与制度依据问答逻辑。同时，现场取证的图片与文字说明需关联提取，避免丢失关键证据信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 该品类文档包含长文本的违法事实描述与处罚依据，分块过长会导致上下文关联模糊，过短会割裂关联信息，按实测标定 |
| `chunkSplitter` | 按段落+标题拆分 | 该品类执法文书有明确的标题与段落结构，按此规则拆分可保留单条处罚依据或整改要求的完整性 |
| `customPdfParse` | 启用结构化解析 | 该品类常用PDF格式的处罚决定书、立案审批表，结构化解析可提取表格字段与内嵌文本内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 部分案件关联的现场照片、视频截图打包文件较大，需足够时长完成解析 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持批量上传多份巡查记录、案件卷宗，满足日常办案数据导入需求 |

## 容易做错的三处
- 上传Word格式的案件卷宗后，问答测试中无法回答内嵌图片对应的现场说明。原因是未启用针对Word文档的图片元数据提取配置，仅解析了纯文本内容。
- 批量上传多份执法文书时出现解析超时报错。原因是`PARSE_FILE_TIMEOUT_SECONDS`设置值低于实际解析所需时长，未考虑打包文件的体积差异。
- 分块后将责令改正通知书的整改要求与对应案件编号拆分到不同块。原因是`chunkSize`设置过小，导致单块无法容纳完整的关联信息。

## 怎么确认配好了
- 上传1份典型的处罚决定书PDF，检查解析结果是否包含完整的违法事实、处罚依据与整改要求。
- 批量上传3-5份巡查记录与现场照片打包文件，确认所有解析任务均在`PARSE_FILE_TIMEOUT_SECONDS`内完成。
- 查看分块后的文本块，确认每个块内的信息关联完整，未出现单条处罚条款或整改要求被拆分的情况。
- 测试上传Word格式的巡查记录，确认内嵌的文本内容与图片说明被正确提取并关联。
