# 市容环卫与城管执法案件的政策与制度依据问答：模型接入与配置

本文基于FastGPT v4.17.0版本的配置逻辑编写。

## 这个品类的数据长什么样
该品类的数据通常来自城管执法局、街道综合执法队、环卫中心及网格员的日常工作产出。数据来源包括城管执法平台、城市运行网格平台、视频监控、群众投诉工单，更新频率为每日。日常文档覆盖巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告，通常包含案件编号、执法主体、现场描述、整改要求、处罚结果等字段，部分文档带有多媒体内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且包含文本、图片等多模态内容，每日更新的特性要求模型接入时适配高频数据刷新节奏。多类型文档的字段差异较大，需要配置适配非标准化文本的召回与解析逻辑。现场照片等多媒体内容的存在，要求模型支持视觉信息处理。同时，执法场景对回答准确性要求较高，需避免因配置不当导致的证据缺失或判断偏差，影响案件处置流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配该品类多文档拼接的上下文需求，避免因上下文截断丢失案件关键信息 |
| `maxTokens` | 2000–3000 token | 平衡回答长度与执法场景下政策依据引用的完整性，避免输出过长影响现场使用 |
| `vision` | 开启 | 支持对现场照片、执法文书扫描件等多媒体内容的解析，匹配品类内多模态数据特征 |
| `temperature` | 0.2–0.4 | 降低随机性，确保政策依据引用的准确性，避免执法场景下的判断偏差 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写实际接口地址 | 适配本地或私有部署的模型调用需求，确保数据不流出合规边界 |
| `AIPROXY_API_TOKEN` | 配置专属访问密钥 | 保障模型调用的安全性，避免未授权访问执法相关数据 |

## 容易做错的三处
- 尝试选择细分模型时无法选中目标模型：原因是未在`AIPROXY_API_ENDPOINT`配置中绑定对应模型的部署地址，或密钥权限未开放对应模型调用权限。
- 启动OneAPI容器时出现`build/model/main.go:79`报错：原因是配置的`AIPROXY_API_TOKEN`无效或接口地址无法正常访问，需检查密钥与端点配置的正确性。
- 部署rerank模型后未生效：原因是未配置关联的重排调用逻辑，或未将rerank模型的接口地址正确填入对应配置项，导致无法调用重排服务提升召回准确性。

## 怎么确认配好了
- 上传单份执法文书与现场照片，测试模型是否能同时解析文本与图片内容，验证`vision`配置是否生效。
- 发起政策依据问答请求，检查返回结果的上下文长度是否符合预设的`maxContext`范围，无明显截断情况。
- 查看模型调用日志，确认请求地址与密钥匹配配置的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，无调用失败记录。
- 发起多轮问答测试，观察回答的随机性是否在`temperature`设定的区间内，避免出现过于发散的内容。
