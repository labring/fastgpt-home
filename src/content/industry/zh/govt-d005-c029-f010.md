# 市容环卫与城管执法案件的政策与制度依据问答：知识库检索与召回

本文基于FastGPT v4.17.0版本的配置逻辑编写。

## 这个品类的数据长什么样
该品类的日常文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告等。数据主要来自城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。数据字段多包含执法场景描述、违法行为界定、整改要求、处罚依据等，部分关联现场影像与位置信息，单条文档长度跨度较大，从数百字符的简易记录到数千字符的正式处罚文书不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的执法数据要求检索系统支持增量同步，避免全量重扫占用过多服务器资源。多类型文档混合的结构需要检索模型适配文本与非文本字段的关联召回，优先匹配执法场景与政策依据的对应关系。现场照片等非结构化数据的关联，要求检索环节支持跨模态关联，同时需保证政策条款与案件场景的精准匹配，避免召回无关处罚案例。执法场景的强关联性要求召回结果需覆盖具体执法环节的依据，不能仅返回泛泛的通用条款，否则会影响案件判断的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 匹配城管执法政策条款的精准度要求，避免召回无关场景的法规 |
| `limit` | 前10条 | 覆盖案件处理所需的全部政策依据，同时控制上下文长度 |
| `searchMode` | hybrid | 结合文本语义与关键词匹配，适配执法场景中既有语义关联又有精准条款号的需求 |
| `usingReRank` | 开启 | 对初始召回结果重新排序，优先返回与执法场景最相关的政策条款 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展用户问题，补充执法场景相关的关键词，提升召回覆盖率 |
| `collectionIds` | 绑定城管执法专属知识库集合 | 隔离其他品类的文档，避免无关数据干扰召回结果 |

## 容易做错的三处
- 现象：检索到知识库文档但大模型回答仅泛泛提及，未引用具体条款内容。原因：未开启`datasetSearchUsingExtensionQuery`，未将问题关联到具体条款的关键词，导致召回的条款未被完整纳入上下文。
- 现象：单次搜索耗时超过60秒，服务器资源占用偏高。原因：未设置合理的`limit`参数，召回过多无关文档导致上下文过长，同时未开启`usingReRank`增加了模型处理负担。
- 现象：同一问题每次召回结果不一致。原因：未固定`collectionIds`绑定专属知识库集合，召回范围包含其他业务线的文档，且未调整`similarity`阈值导致边缘结果随机匹配。

## 怎么确认配好了
- 提交包含具体执法场景的测试问题，核对召回结果是否包含对应政策依据的完整文档片段。
- 查看检索日志，确认`searchMode`为hybrid模式，`usingReRank`处于开启状态。
- 对比多次提交同一问题的召回结果，确认结果一致且未包含非城管执法品类的文档。
- 测试增量更新场景，确认新上传的当日执法文档可在1小时内被检索到。
