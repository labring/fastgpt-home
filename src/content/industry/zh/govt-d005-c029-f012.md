# 市容环卫与城管执法案件的政策与制度依据问答：部署与升级

## 这个品类的数据长什么样
该品类的数据通常来自城管执法局、街道综合执法队等主体的城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。日常文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告，数据字段多包含案件编号、违法地点、责任主体、处置进度等，涵盖结构化表单、图片及非结构化文档类型。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据来源分散且包含多类型文档，部署时需适配多源数据对接与多格式解析配置。每日更新的频率要求部署定时同步任务，升级时需确保同步逻辑不中断，避免数据滞后。文档覆盖执法流程全环节，需配置针对性的字段提取规则，避免解析偏差影响后续问答准确性。同时，执法数据的严肃性要求部署阶段完成权限校验配置，防止未授权访问，升级时需保留原有权限设置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `1000 条` | 适配该品类每日新增的案件数据量，避免数据库连接耗尽 |
| `MONGODB_URI` | 按本地部署的MongoDB实例地址填写 | 存储案件相关的非结构化文档与历史问答日志，符合数据本地化部署需求 |
| `REDIS_URL` | `redis://:自定义密码@本地IP:6379/0` | 缓存高频查询的政策依据内容，降低重复解析与数据库查询压力 |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` | 存储现场照片、处罚决定书等执法文件，适配多格式数据存储需求 |
| `FE_DOMAIN` | 部署服务器的内网或公网域名 | 配置前端访问地址，确保问答界面可正常调用后端服务 |

## 容易做错的三处
- 现象：调用PDF解析接口返回超时，解析服务后台日志显示解析任务已完成。原因：未配置`REDIS_URL`导致任务状态无法同步，前端判定超时。
- 现象：Docker部署环境中，系统每30分钟触发异常告警，重启FastGPT容器后告警消失。原因：`DB_MAX_LINK`参数设置过低，数据库连接池在固定周期后耗尽，重启后连接池重置。
- 现象：完成版本升级后，系统仍显示旧版本号。原因：未拉取最新的镜像版本，或未重启容器加载新镜像，本地缓存的旧镜像未被覆盖。

## 怎么确认配好了
- 登录FastGPT后台知识库管理页面，确认已添加城管执法平台、城市运行网格平台等对应数据源。
- 上传一份案件立案审批表，执行解析测试，查看解析结果是否包含案件编号、违法地点等核心字段。
- 执行容器版本查询命令，确认当前运行的镜像版本为FastGPT v4.17.0。
- 发起一条政策依据相关的查询，查看返回结果是否引用了上传的执法文档内容。
