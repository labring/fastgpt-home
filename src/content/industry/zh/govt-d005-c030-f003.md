# 建设工程质量安全监督的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
建设工程质量安全监督场景的数据覆盖住建质安站、施工单位、监理单位、建设单位的日常业务文档，包括监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告。数据来源为工程质量安全监管系统、施工现场实名制平台、监理日志、检测报告，更新频率为每周一次。单份文档包含监督范围、检查节点、整改要求、验收条件等字段，不同来源的文档格式与字段排布存在差异，需按业务场景分类调用。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
周更的数据更新节奏要求多轮对话的上下文仅保留最近7天内的业务内容，避免引用过时的监督记录。多类来源的文档格式与字段差异，要求提示词需明确指定不同文档的调用规则，确保返回内容匹配对应业务场景的字段要求。日常文档的字段复杂度较高，多轮对话中需限制上下文总长度，防止超出模型处理上限。同时，该场景出错后果严重，提示词需强制要求返回内容关联具体文档来源，避免无依据的政策解读。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 匹配日常文档的总长度与周更数据的上下文需求 |
| `messages` 上下文截断规则 | 保留最近10轮对话 | 避免冗余历史干扰当前政策查询 |
| `variables` 绑定字段 | 绑定监督项目ID、工程类型 | 精准关联对应项目的政策与文档数据 |
| 流式输出开关 | 开启 | 实现政策依据的实时分段返回 |
| 流式输出速率 | 1–2 秒每段，按实测标定 | 适配前端交互的流畅性要求 |
| `chatId` 会话绑定规则 | 绑定当前监督项目的唯一标识 | 确保多轮对话的上下文一致性 |

## 容易做错的三处
- 现象：调用对话API使用流式输出时，返回内容中的文档链接点击后仅覆盖当前页面，无法跳转至新页面。原因：未在流式返回的内容中嵌入符合前端规范的跳转标识，导致前端渲染逻辑未正确识别并处理链接跳转指令。
- 现象：FastGPT v4.17.0 版本中，多次发起同一监督项目的对话后，对话日志的详情页始终显示首次对话的回答内容。原因：`chatId` 未绑定当前监督项目的唯一标识，导致不同会话的上下文被错误覆盖，日志关联的会话ID不一致。
- 现象：流式输出返回间隔固定为4秒，无法调整为预设的1–2秒。原因：未配置流式输出速率参数，使用了系统默认的固定返回间隔。

## 怎么确认配好了
- 发起包含多轮监督政策查询的对话，检查`messages`字段是否正确保留了最近的对话历史，未包含过期的监督记录。
- 调用流式输出接口，验证返回内容的分段间隔符合预设的1–2秒每段的要求，无固定4秒的间隔问题。
- 查看对话日志，确认`chatId`与当前监督项目的唯一标识一致，日志内容与实际返回的回答内容完全匹配。
- 测试政策依据查询，验证返回内容是否关联了对应监督项目的文档字段，未出现无具体来源的政策解读。
