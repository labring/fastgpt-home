# 建设工程质量安全监督的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自工程质量安全监管系统、施工现场实名制平台、监理日志、检测报告，更新频率为周。日常生成的文档包含监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告，文档字段多包含项目编号、现场点位、整改要求、验收结论等，无统一固定的跨项目字段格式，单份文档篇幅从数百字到数千字不等。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据来源分散且更新周期固定，要求模型接入需支持定时批量同步多源数据。日常文档无统一字段格式，需配置适配非结构化文本的解析与召回逻辑，避免因字段缺失影响检索结果。单份文档篇幅跨度大，从数百字到数千字不等，需限制单轮上下文的最大处理长度，防止超出模型承载上限。政策与制度依据问答需精准匹配监管条款，要求配置需优先保障检索召回的精准度，确保返回内容与监管依据直接对应。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配本品类单轮对话需关联多份周更文档的需求，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 保障政策依据问答的输出长度足够覆盖监管条款细节，同时控制单轮响应耗时 |
| `quoteMaxToken` | 1500 token | 限制召回文档的总长度，确保检索内容与当前问题高度相关，避免冗余信息干扰 |
| `temperature` | 0.1–0.3 | 保障政策回答的严谨性，避免生成不符合监管条款的内容 |
| `AIPROXY_API_ENDPOINT` | `http://127.0.0.1:8000/v1`（按实测标定） | 适配离线部署场景，确保数据不向外泄露 |
| `AIPROXY_API_TOKEN` | 本地模型生成的访问密钥 | 保障模型接入的安全性，防止未授权访问 |

## 容易做错的三处
- 现象为点击模型测试弹出“请求错误”提示，curl调用模型接口返回连接超时。原因是未正确配置`AIPROXY_API_ENDPOINT`为本地离线模型的实际服务地址，或未开放模型服务的端口权限。
- 现象为知识库查询返回结果无整理，直接输出原始文档片段。原因是未配置`maxTokens`或取值过大，导致模型无法完成对召回内容的整合梳理。
- 现象为向量模型接入失败，无法生成文档向量。原因是未正确配置向量模型的访问参数，或使用了不兼容的向量模型格式。

## 怎么确认配好了
- 执行模型测试功能，观察界面无报错提示，返回结果包含合规的政策依据文本。
- 上传单份监督检查记录文档，触发知识库检索，确认召回的文档与当前查询问题相关。
- 调整`temperature`参数，观察回答的严谨性变化，确认参数配置生效。
- 查看FastGPT v4.17.0的后台日志，确认无模型接入相关的报错信息。
