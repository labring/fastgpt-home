# 建设项目环评审批的政策与制度依据问答：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源包括全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台及环境监测数据。日常文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复五类核心文件，单项目对应一套完整审批关联文档。数据更新节奏为不定期，随项目审批进度及政策调整同步更新。文档核心字段包含项目类别、环评等级、污染防治措施、公众参与情况、审批意见等内容，无统一固定单位字段，随文档类型变化调整。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据来源要求工具调用需配置跨系统对接插件，确保能同步获取申报系统、分区管控成果等不同平台的信息。单项目文档体量较大且结构多样，工具调用需限定单次召回的文档范围与调用工具数量，避免上下文过载。数据更新无固定周期，插件需支持动态拉取最新数据，保障信息时效性。核心字段关联紧密，工具调用需确保参数匹配不同文档的字段格式，防止出现字段不兼容导致的信息提取错误。同时，审批环节出错后果严重，工具调用需配置失败重试与明确的异常提示机制，保障调用过程的严谨性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工具调用功能制定：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 工具调用触发条件 | 按项目环评等级与所属生态分区匹配 | 匹配本品类核心业务逻辑，仅在涉及政策依据查询时触发工具调用 |
| `toolChoice` | auto | 适配多源数据调用需求，自动选择合适的工具对接不同系统 |
| `functionCall` | 限定单次调用3个工具 | 避免上下文过载，符合本品类单项目文档的体量特征 |
| 单次召回文档上限 | 前8条 | 匹配日常文档的单项目规模，防止上下文溢出 |
| 调用超时阈值 | 600秒 | 适配跨系统数据拉取的耗时需求，避免因等待过久导致流程中断 |
| 上下文窗口限制 | 8000 token | 适配本品类单项目文档的总字符量，保障信息完整 |

## 容易做错的三处
- 现象：工具调用返回结果中额外出现无关数字或乱码，且与预设的指定回复内容不符。原因：未正确配置`functionCall`的约束规则，导致工具调用逻辑与指定回复的触发条件冲突，触发了未预期的工具调用。
- 现象：工具调用返回的文档字段为空，无法提取有效政策依据。原因：未匹配本品类文档的字段格式，插件无法识别不同类型文档的核心内容字段，导致信息提取失败。
- 现象：工具调用超时，审批流程中断。原因：未设置合理的调用超时阈值，跨系统拉取数据的耗时超过预设阈值，触发超时中断。

## 怎么确认配好了
- 触发一次项目环评政策依据查询，检查工具调用是否仅在匹配环评等级与生态分区时触发。
- 查看工具调用日志，确认`toolChoice`自动选择了对应系统的对接插件，无异常调用记录。
- 模拟跨系统数据拉取，验证调用超时阈值的设置是否符合实际拉取耗时，调整至合理区间。
- 检查上下文窗口的配置，确保单项目文档的总字符量未超过预设限制，无上下文溢出提示。
