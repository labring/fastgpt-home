# 建设项目环评审批的政策与制度依据问答：文档解析与分块

## 这个品类的数据长什么样
本品类的数据主要来自全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台及监测数据。日常文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复等，文档结构包含项目类别、环评等级、污染防治措施、公众参与内容、审批文号等固定字段，更新频率不定期，部分大型报告书篇幅较长，单份文件容量差异较大。

## 这些特征在「文档解析与分块」这一环带来什么约束
多来源的数据导致文档格式不统一，既有标准PDF格式的正式批复与报告书，也有Word格式的审批申请与说明，对解析工具的兼容性提出要求。不定期更新的特性意味着分块配置需适配不同版本、不同篇幅的文档，无法依赖固定格式模板。文档中包含大量环评专业术语与长段落，若分块过细则会割裂专业逻辑，过粗则会导致检索时无关信息过多，同时需确保项目类别、污染防治措施等核心字段的上下文完整保留，避免因拆分丢失关键审批依据。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 匹配环评文档的常规段落长度，避免拆分核心审批条款或项目信息 |
| `chunkSplitter` | 自定义分隔符+语义分段 | 适配环评文档的章节分隔习惯，结合“一、”“（一）”等层级标题与换行符进行分块 |
| `customPdfParse` | 开启 | 准确提取环评PDF中的文本与格式信息，避免因原生PDF排版错乱导致的文本丢失 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容单份大型环评报告书的上传需求，适配行业内常见的大体积文档 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 为长文档的完整解析预留足够时间，避免因耗时过长触发解析中断 |
| `chunkSettingMode` | 手动模式 | 允许针对环评文档的专业结构调整分块参数，适配特定业务场景的检索需求 |

## 容易做错的三处
- 上传Excel格式的环评相关文件后解析失败。原因：默认配置未适配Excel格式的文档解析，仅支持环评常用的PDF、Word格式文件。
- 自定义分隔符设置后分块长度仍不符合预期，出现段落合并或拆分过度。原因：`chunkSettingMode`未切换为手动模式，或`chunkSize`取值未匹配文档的实际段落长度。
- 上传3MB的环评PDF文件时触发解析超时报错。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值低于该大型文档的实际解析耗时，导致任务中断。

## 怎么确认配好了
- 上传一份标准环评PDF文档，查看解析后的文本是否完整提取了章节标题与核心审批内容。
- 手动设置`chunkSize`为1000字符，上传一段测试环评段落，验证分块结果未拆分关键条款或专业术语。
- 上传一份超过500MB的环评报告书，确认上传与解析过程未触发大小限制或超时错误。
- 尝试上传Word格式的环评审批申请，查看是否能正常解析并生成符合要求的分块结果。
