# 建设项目环评审批的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台及监测数据，更新频率不定期。日常处理的文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复，文档多包含项目类别、环评等级、污染防治措施、公众参与情况等字段，无统一固定单位，随项目具体情况调整。典型处理主体为生态环境部门环评处、行政审批局、建设单位及环评机构。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据分散且更新无固定周期，要求模型接入环节需支持多源异构数据的批量接入与增量同步，适配不同格式的环评文档结构。文档字段无统一固定单位，需保留灵活的字段提取逻辑，避免硬编码单位或固定字段。数据体量随项目规模差异显著，需配置合理的上下文与token限制，防止单项目数据过载导致调用失败。同时，政策依据问答需精准匹配项目类别与环评等级，要求接入配置需关联对应数据源的分类规则，确保问答结果符合业务要求。

| `maxTokens` | 2000–3000 token | 满足政策依据问答的输出长度需求，同时控制单次调用的资源消耗 |
| `quoteMaxToken` | 1500–2000 token | 确保引用的环评文档片段足够覆盖政策依据相关内容，不截断关键审批依据信息 |
| `temperature` | 0.1–0.3 | 保证政策问答的准确性，避免生成偏离业务规则的主观内容 |
| `AIPROXY_API_ENDPOINT` | 按所选用模型的官方接口地址填写 | 适配FastGPT的代理调用规则，完成模型接入的地址配置 |
| `AIPROXY_API_TOKEN` | 填写模型平台分配的有效密钥 | 完成身份验证，实现模型调用的权限校验 |

## 容易做错的三处
- 现象：部分第三方模型无法在配置界面选中，或选中后调用报错。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或模型未在代理服务中完成接入注册。
- 现象：生成的政策依据问答结果被截断，无法完整展示所需的审批依据内容。原因：`maxTokens`或`quoteMaxToken`取值设置过低，导致输出或引用的文档片段被强制截断。
- 现象：调用后出现无限重启或token编码报错。原因：代理服务的接口地址配置错误，或密钥未正确匹配对应模型的权限范围。

## 怎么确认配好了
- 核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置内容，确保与所选用模型的官方接口及权限密钥一致。
- 输入典型建设项目的环评类别与申请信息，发起测试问答，确认返回结果包含对应政策依据内容。
- 查看调用日志，确认单次调用的上下文与token取值未触发模型的限制规则。
- 调整`temperature`取值并发起多次测试，确认生成结果的一致性符合业务准确性要求。
