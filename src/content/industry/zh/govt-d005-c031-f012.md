# 建设项目环评审批的政策与制度依据问答：部署与升级

本页配置适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的数据来源包括全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台及监测数据，更新频率不定期。日常处理的文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复，文档结构覆盖项目基本信息、污染防治措施、公众参与情况、审批流程结果等字段，无统一固定单位，字段随项目类型与审批环节动态调整。

## 这些特征在「部署与升级」这一环带来什么约束
数据来源分散且更新无固定周期，部署时需配置多源数据同步适配逻辑，避免数据滞后或缺失。文档结构动态且字段不固定，升级时需支持灵活的文档解析与字段映射，无法依赖固定分块规则。审批相关文档的合规性要求高，部署环节需强化权限控制与数据溯源能力，升级时需同步更新合规校验逻辑。同时，多源数据的格式差异较大，部署阶段需配置统一的数据标准化处理模块，降低后续维护成本。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:yourpass@localhost:27017/fastgpt?authSource=admin` | 适配环评审批业务的多文档存储需求，保障审批申请、报告等数据的持久化存储 |
| `REDIS_URL` | `redis://:yourredispass@localhost:6379/0` | 用于缓存高频查询的政策条文与审批规则，降低数据库的重复查询负载 |
| `DB_MAX_LINK` | `20–30 个` | 匹配环评审批业务的并发查询峰值，避免数据库连接耗尽导致查询失败 |
| `STORAGE_S3_ENDPOINT` | `http://localhost:9000` | 用于存储环评报告、批复文件等大型文档，适配本地部署的对象存储服务 |
| `FE_DOMAIN` | `http://localhost:3000` | 配置前端访问地址，方便内部人员访问政策问答界面 |
| `FILE_TOKEN_KEY` | `随机32位字符串` | 用于生成环评文档的访问令牌，保障敏感审批文件的访问安全 |
| `ROOT_KEY` | `自定义复杂密钥字符串` | 用于配置后台管理权限，防止未授权访问审批数据与系统配置 |

## 容易做错的三处
- 启动`aiproxy`容器后短时间内出现curl类执行报错，原因是未正确配置`STORAGE_S3_ENDPOINT`或关联的存储服务未正常启动，导致代理无法获取环评文档资源。
- 升级版本后无法加载历史审批数据，原因是未正确迁移`MONGODB_URI`对应的数据库配置，导致新实例无法连接原有数据存储。
- 部署后查询结果条数不符合预期，原因是未调整`DB_MAX_LINK`的取值适配并发请求，导致部分查询因连接不足被截断。

## 怎么确认配好了
- 执行`docker-compose ps`命令，确认数据库、缓存、代理等所有依赖服务的运行状态均为Up。
- 上传一份测试环评报告文件，通过界面触发政策依据问答，验证文件可正常解析并返回相关结果。
- 访问`FE_DOMAIN`配置的前端地址，登录后台管理界面，验证权限配置可正常生效。
- 模拟多用户并发查询，检查`DB_MAX_LINK`的配置是否可支撑并发请求，无连接报错。
