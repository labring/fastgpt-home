# 招标采购合规管理的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据来源包括企业采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，更新频率为每日。日常文档涵盖采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料，包含采购方式、预算依据、评分办法、供应商资格要求、履约条款等字段，无统一固定单位，字段随文档类型动态变化。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的数据要求索引支持增量同步，避免全量重建带来的耗时与资源占用。多类型文档的结构差异，需要适配不同的分块策略，保障合规相关核心内容（如采购方式、预算依据）不被截断。字段覆盖范围广的特点，要求向量模型编码时优先对齐合规审查的关键词维度，同时需限制单批次索引的数据量，避免内存溢出。跨平台来源的数据格式不统一，需要前置做格式标准化处理，否则会影响向量检索的准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 覆盖单份合规相关核心内容的完整语义，避免截断关键条款 |
| 重叠长度 | 100–200 字符 | 衔接相邻分块的语义，防止合规条款被拆分后丢失上下文 |
| `maxToken` | 8192 | 适配主流大语言模型的上下文窗口上限，保障召回内容可完整带入问答 |
| 单次搜索上限 | 前10条 | 控制检索返回量，避免冗余内容占用上下文空间 |
| `defaultToken` | 2000 | 限定单条向量编码的最大token数，平衡语义完整性与索引效率 |
| 重排 | 按实测标定 | 针对招标采购的合规关键词权重调整重排规则，提升精准度 |

## 容易做错的三处
- 检索响应耗时过长，界面显示请求超时。原因：未启用增量索引策略，每次检索触发全量数据扫描，占用大量计算资源。
- 问答对提取任务持续显示「索引中」状态，无法进入就绪环节。原因：分块长度设置超出单文档处理上限，且未配置分块超时阈值，导致任务阻塞。
- 数据集自动生成多组重复索引，数据量随时间异常增长。原因：增量同步时未开启文档去重配置，同一数据源的重复内容被多次写入索引。

## 怎么确认配好了
- 手动上传一份典型的招标文件，查看分块结果是否覆盖核心合规条款，无明显截断。
- 提交一条合规相关的查询，核对检索返回的结果条数与单次搜索上限的配置一致。
- 等待1个完整的每日增量同步周期，检查索引更新是否仅包含新增数据，无重复条目。
- 查看向量模型调用日志，确认`maxToken`和`defaultToken`的配置被正确加载。
