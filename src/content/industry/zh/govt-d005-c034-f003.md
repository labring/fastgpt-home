# 招生入学与学籍管理的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类服务主体包括教育局基础教育科、学校教务处、招生考试机构、街道社区协同窗口，数据覆盖招生入学与学籍管理全流程，日常文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表。数据来源为全国中小学生学籍信息管理系统、地方招生入学平台、户籍与房产数据、学校教务系统，更新频率为每日。数据字段以学生身份、入学资格、学籍状态为核心，关联户籍地址、房产证明编号、学籍异动类型等专属标识，无跨品类的资金补助类字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的实时数据要求对话上下文需同步拉取最新学籍与招生信息，避免引用过期数据导致政策解读偏差。多类关联文档需在多轮对话中按用户提问逐步召回，不能一次性加载全部数据导致上下文溢出，影响对话响应速度。学生身份与学籍状态的专属字段要求提示词需明确限定检索范围，仅调用招生入学与学籍管理相关文档，避免混淆其他教育品类数据。单轮对话需处理户籍核验、学籍异动等复杂逻辑，需保留历史对话上下文以承接用户的追问，例如用户先询问转学政策再追问异地转学材料，需关联前一轮的政策前提。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 本品类文档字段较多，需容纳多轮对话与召回的学籍、招生文档内容，避免上下文截断 |
| 单次召回文档数 | 前3–5条 | 本品类数据关联紧密，少量精准文档即可覆盖用户关于招生政策、学籍异动的提问 |
| 上下文保留时长 | 24 小时 | 本品类数据每日更新，需同步刷新当日最新的学籍与招生信息，确保对话引用的内容实时有效 |
| 变量绑定规则 | 绑定学生ID、招生批次字段 | 本品类数据以学生身份为核心，需通过`variables`参数精准匹配对应学籍与招生数据 |
| 对话ID关联方式 | 绑定`chatId` | 需将多轮对话的上下文与专属用户的学籍查询请求绑定，避免混淆不同用户的查询 |

## 容易做错的三处
- 现象：提示词中引用多轮对话上下文时，返回结果为空或提示字段未定义。原因：未通过`variables`或`messages`参数绑定历史对话的上下文变量，导致提示词无法调用已有的对话内容。
- 现象：批量删除对话记录时，关联的系统日志同步被大量清除。原因：未配置对话与日志的独立存储关联规则，将日志与对话记录绑定在同一存储路径下。
- 现象：批量调用文本内容提取模块时，代码块参数返回`undefined`。原因：在提示词的代码块中未正确指定数据源字段，错误使用未绑定的`any`参数，导致系统无法识别提取目标。

## 怎么确认配好了
- 发起包含前置提问与后续追问的测试对话，验证系统能关联历史提问的上下文并召回对应学籍或招生文档。
- 检查配置的上下文保留时长，手动触发数据同步后，确认对话能加载当日更新的学籍信息。
- 绑定`chatId`与用户会话，验证不同用户的对话上下文不会互相混淆。
- 测试删除单条对话记录，确认系统日志仍保留完整的交互记录。
