# 招生入学与学籍管理的政策与制度依据问答：工作流编排

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类数据来源包括全国中小学生学籍信息管理系统、地方招生入学平台、户籍与房产数据平台、学校教务系统。日常处理的文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表。数据更新频率为每日，核心字段覆盖学生身份标识、户籍与居住信息、学籍状态、招生资格核验结果等，围绕学生入学资格与学籍流转展开。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源涉及多个跨部门系统且每日更新，工作流需配置定时数据同步节点，确保政策问答所用的学籍、招生数据为最新版本。日常文档多为结构化表单，工作流的`variables`需对应学籍、户籍、招生计划等固定字段，避免非结构化输入导致的匹配偏差。核验环节耗时占比高，工作流需拆分核验、问答、审批三个核心节点，避免单节点负载过高。同时需配置校验节点，防止重复学籍或错误资格判定引发的合规问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量设置 | 配置`variables`为学籍ID、户籍地址、招生计划编号，取值为从同步接口获取的结构化字段 | 本品类核心数据为学生身份、户籍房产、招生计划，固定变量可确保问答调用数据准确 |
| 数据库同步配置 | 设置同步时段为每日凌晨2:00-4:00，单次同步数据量不超过1000条 | 数据更新频率为每日，低峰时段同步可避免占用业务系统资源 |
| 工作流节点拆分 | 将流程拆分为数据校验、政策问答、结果输出三个独立`nodeId`节点 | 拆分节点可降低单节点负载，适配核验、问答等耗时环节的处理需求 |
| 超时阈值设置 | 配置数据库查询超时为30秒，AI问答超时为600秒 | 核验户籍房产环节耗时较长，合理阈值可避免工作流异常中断 |
| 结果过滤设置 | 配置仅输出最终政策问答结果，隐藏中间AI对话内容 | 避免终端用户收到冗余的中间步骤内容，符合政务服务的简洁输出要求 |

## 容易做错的三处
- 现象：数据库连接插件执行耗时远超旧版，单条查询触发超时。原因：未配置合理的同步频率与超时阈值，新版FastGPT对数据校验逻辑做了优化，未适配本品类高频同步的需求。
- 现象：classify节点无法选择AI模型，但发布后的工作流可正常运行。原因：未在编辑态正确绑定模型配置，发布时自动继承应用默认模型，导致编辑态无选项但运行正常。
- 现象：无法将应用token传递到工作流全局变量中。原因：未在应用设置中配置全局变量的token注入权限，未将token绑定到`variables`参数中。

## 怎么确认配好了
- 查看全局变量列表，确认`variables`已绑定学籍ID、户籍地址、招生计划编号三个核心字段。
- 触发测试工作流，查看数据库同步节点的执行日志，确认同步时段与单次数据量符合配置要求。
- 发起测试问答，确认输出仅包含最终政策解答，无中间AI对话的冗余内容。
- 模拟缺失户籍数据的异常场景，确认工作流会触发校验节点并返回明确提示。
