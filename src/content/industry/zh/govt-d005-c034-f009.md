# 招生入学与学籍管理的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据覆盖招生入学与学籍管理全流程，日常文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表等结构化表单与政策文本。数据来源包括全国中小学生学籍信息管理系统、地方招生入学平台、户籍与房产数据、学校教务系统，更新频率为每日。数据字段包含学生身份标识、户籍房产信息、学籍状态、招生批次、录取结果等，严格遵循官方标准格式存储，无额外自定义统计数值。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征对模型接入与配置带来多重约束。多来源且每日更新的数据集，要求配置时需启用实时数据拉取逻辑，禁用固定缓存模式，确保政策与学籍信息的时效性。结构化表单与政策文本并存的文档结构，需针对性设置不同的召回权重，优先匹配政策文本的关键词以准确解答制度依据类问题。涉及学生身份与户籍房产的敏感字段，需严格限制上下文召回的范围，避免泄露隐私信息。同时因出错后果直接影响学生升学与录取，配置时需增加结果校验步骤，确保召回数据与业务场景完全匹配。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配招生政策与学籍文档的长文本上下文需求，避免截断关键政策条款 |
| `maxTokens` | 2000–3000 token | 确保回答包含完整的政策依据与学籍核验逻辑，同时控制单轮响应长度 |
| `quoteMaxToken` | 1500 token | 限制召回的引用文本总长度，聚焦核心政策条款与学籍数据，避免冗余信息干扰 |
| `temperature` | 0.1–0.3 | 保持回答的严谨性，符合政策解释的标准化要求，避免生成不确定的自定义内容 |
| `AIPROXY_API_ENDPOINT` | 按官方部署地址填写 | 适配国内合规的API调用链路，确保数据传输符合教育系统的网络安全要求 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具，用于核验学籍数据或查询最新招生政策，提升回答准确性 |

## 容易做错的三处
- 现象：工具调用后返回结果中多出无关的数字前缀，且与原始模型回答不符。原因：未限制`toolChoice`的触发范围，导致模型误调用无关工具或拼接了非预期的系统日志内容。
- 现象：召回的政策文本包含过期的招生批次信息，与当前执行的招生周期不符。原因：未启用实时数据拉取配置，使用了本地缓存的旧数据，未按每日更新频率刷新数据源。
- 现象：回答中未包含对应的学籍数据字段，无法准确说明入学资格的判定依据。原因：未设置`quoteMaxToken`的合理取值，导致召回的学籍表单内容被截断，关键字段缺失。

## 怎么确认配好了
- 触发测试用的政策问答请求，核对返回结果中引用的政策文本是否与当前数据源的最新内容一致，可通过对比数据源的更新记录确认。
- 查看工具调用的日志，确认返回结果中无无关的冗余内容，验证`toolChoice`的配置是否符合预期。
- 调整配置参数后，对比不同批次的问答结果，确保回答的严谨性符合政策解释的要求，验证`temperature`的取值是否适配业务场景。
- 核对敏感字段的召回情况，确保未泄露学生的隐私信息，验证上下文召回范围的配置是否合规。
