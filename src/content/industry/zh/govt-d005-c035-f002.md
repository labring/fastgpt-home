# 排污许可管理的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据覆盖排污许可管理全流程文档，包括排污许可证申请表、执行报告、自行监测方案、台账记录、变更申请及许可证副本。数据来源为全国排污许可证管理信息平台、企业环保台账、在线监测系统与环境统计系统，更新节奏为季度级。文档包含许可限值、排放边界、监测指标、台账周期等专属字段，所有内容均围绕排污合规管理要求生成，无额外非业务类统计数值。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据的多源异构特征要求向量索引需兼容不同系统导出的文档格式，避免因格式差异丢失合规类关键信息。季度级的更新节奏要求索引配置适配批量增量更新，避免全量重建带来的资源消耗。文档多为合规条款、监测数据与台账记录，长文本占比高，分块需保留条款完整性，避免拆分许可限值、排放边界等核心字段。同时，合规类问答的准确性要求高，检索环节需确保核心字段的向量匹配精度，避免错误信息输出。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配排污许可类文档中合规条款、台账记录的自然分段长度，避免拆分核心合规字段 |
| 重叠长度 | 100–150 字符 | 保留跨分块的许可限值、排放边界等关联信息，确保检索时不丢失上下文 |
| `maxToken` | 4096 token | 匹配多数开源向量模型的上下文窗口上限，适配长文档的向量生成需求 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非合规类文档，确保检索结果聚焦于政策与制度依据相关内容 |
| 单次搜索上限 | 前 6 条 | 控制返回结果数量，避免冗余信息干扰合规问答的准确性 |
| `defaultToken` | 按实测标定 | 适配不同环境下的向量生成请求超时场景，避免因 token 限制导致索引失败 |

## 容易做错的三处
- 现象为调用向量模型时返回401状态码，curl测试可正常生成向量。原因是未在FastGPT配置中正确填入向量模型的API密钥，或密钥权限未覆盖索引生成请求。
- 现象为知识库中出现重复文档块，自定义切分的文档顺序与实际存储的索引顺序不一致。原因是未关闭知识库的自动去重功能，或切分逻辑未与索引生成的去重规则匹配。
- 现象为向量索引生成超时，任务状态始终处于待处理。原因是分块长度设置过大，超出向量模型的`maxToken`限制，导致生成请求被中断。

## 怎么确认配好了
- 上传单份排污许可执行报告，手动触发索引生成，查看FastGPT v4.17.0的系统日志，确认无向量生成失败的报错。
- 输入政策相关问题，检索返回结果，核对返回文档的字段是否包含许可限值、排放边界等核心合规内容。
- 调整相似度阈值后重新检索，观察返回结果的数量变化是否符合预期配置。
- 模拟高token向量生成请求，确认`defaultToken`的配置可覆盖请求需求，无超时报错。
