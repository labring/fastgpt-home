# 排污许可管理的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据涵盖排污许可证申请表、执行报告、自行监测方案、台账记录、变更申请及许可证副本等文档，数据来源为全国排污许可证管理信息平台、企业环保台账、在线监测系统与环境统计系统，更新频率为季度。数据字段包含许可排放限值、排放边界、监测要求、台账填报规范等，随行业类别与许可事项存在差异，无统一固定格式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且覆盖多类业务文档，要求多轮对话需逐步明确用户咨询的具体文档类型与许可事项，避免因信息模糊生成不准确答复。季度更新的特性要求提示词中明确标注数据的时效性范围，防止引用过期内容。不同文档的字段逻辑存在差异，多轮对话需区分场景引导用户补充必要信息，例如区分执行报告审核与变更申请咨询的不同问询逻辑。同时，该领域出错会引发合规风险，提示词需加入合规性校验的引导，确保答复符合排污许可管理的相关要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 预设`{许可事项类型}`、`{文档类型}`、`{企业行业类别}`三类专属变量 | 用于在多轮对话中绑定用户咨询的具体排污许可场景，避免上下文混淆，精准召回对应业务数据 |
| `messages` | 保留前10轮有效对话上下文 | 排污许可相关咨询的上下文关联性较强，保留足够轮次可确保对话逻辑连贯，同时避免过长导致资源占用 |
| 单次搜索上限 | 前6条 | 排污许可相关文档的关联信息较为集中，过多召回结果会干扰大模型对专业内容的判断 |
| 分块长度 | 1000–1500字符 | 排污许可文档的专业内容长度适中，该分块范围可确保单块包含完整的许可限值或填报要求信息 |
| 最大上下文窗口 | 8000–12000 token | 排污许可文档包含较多专业术语与固定格式，足够的上下文窗口可确保大模型完整引用相关数据 |
| 问题优化 | 按实测标定 | 排污许可咨询的问题常包含行业专属术语，优化后的问题可提升知识库召回准确率 |

## 容易做错的三处
- 现象：对话返回结果未引用用户上传的排污许可台账数据，仅调用通用知识库内容。原因：未将上传的文件绑定到`variables`变量中，导致大模型无法识别上传数据的关联关系。
- 现象：对话超时，返回504状态码。原因：单次召回的文档条数过多，且上下文窗口设置过大，导致大模型处理超时。
- 现象：答复中出现过期的许可限值内容。原因：提示词未明确标注数据的季度更新频率，大模型引用了未同步的旧数据。

## 怎么确认配好了
- 发起包含具体排污许可事项的多轮对话，检查对话上下文是否保留了前10轮有效内容。
- 上传一份排污许可执行报告，发起统计总结请求，检查结果是否引用了上传文件中的内容。
- 发起包含“最新许可限值”相关的咨询，检查答复是否明确标注数据的更新频率。
- 测试不同文档类型的咨询，检查`variables`变量是否正确绑定了对应的场景。
