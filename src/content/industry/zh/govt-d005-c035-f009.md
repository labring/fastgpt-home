# 排污许可管理的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据包含排污许可证申请表、执行报告、自行监测方案、台账记录、变更申请及许可证副本等日常文档，数据来源为全国排污许可证管理信息平台、企业环保台账、在线监测系统与环境统计系统，更新频率为季度。数据字段包含对应行业的许可限值、排放边界、监测周期、台账记录周期等，不同排污类型的细分规则存在专属条目。

## 这些特征在「模型接入与配置」这一环带来什么约束
季度更新的特性要求知识库需按固定周期完成全量数据同步，避免数据滞后影响问答准确性。多类型文档结构要求模型接入时需适配长文本、表格类内容的解析逻辑，保障关键信息提取完整。多来源数据需统一格式接入，需配置对应的数据转换规则以消除平台间的格式差异，避免不同来源的字段命名不一致导致召回错误。细分字段与行业专属规则要求召回环节需精准匹配对应条目，避免泛化问答偏离排污许可的具体要求。

## 配置怎么定
本配置适配FastGPT v4.17.0版本，以下为针对排污许可管理场景的推荐配置：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配排污许可类文档的长文本上下文需求，避免截断关键许可限值与台账规则 |
| `maxTokens` | 2000–3000 token | 保障政策问答的回复长度覆盖完整的制度依据说明，避免关键内容被截断 |
| `temperature` | 0.1–0.3 | 降低问答的随机性，确保政策与制度依据的回复准确匹配原文内容 |
| `quoteMaxToken` | 1500 token | 限定召回文本的长度，确保引用的文档内容精准对应问题指向的许可条款 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具完成多来源数据的核对，适配排污许可多平台数据的校验需求 |

## 容易做错的三处
- 现象：调用后返回的问答结果未引用排污许可的具体文档条目，仅泛泛说明政策，未提及对应许可限值或台账要求。原因：`maxContext`配置值过小，导致召回的上下文未覆盖对应许可条款，无法精准匹配问题指向的内容。
- 现象：界面显示的模型运行时间仅为首token耗时，未显示完整总运行时长。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的对应关系，导致平台无法获取离线模型的完整运行数据。
- 现象：调用API时返回「使用了错误的API Key」报错。原因：误将全局通用Key直接用于应用对话调用，未使用应用专属的API Key配置。

## 怎么确认配好了
- 发起一条指向具体排污许可条款的测试问题，核对回复是否准确引用对应文档的字段与规则，调整匹配阈值以优化召回精度。
- 查看知识库同步日志，确认按季度周期完成全量数据更新，无格式报错或数据缺失。
- 测试不同类型的排污许可文档提问，核对模型是否能正确区分不同行业的专属许可细则，避免跨行业规则混淆。
- 检查API调用日志，确认无密钥错误或超时异常，返回结果符合预期的问答格式与内容范围。
