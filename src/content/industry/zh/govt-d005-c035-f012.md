# 排污许可管理的政策与制度依据问答：部署与升级

## 这个品类的数据长什么样
该品类的核心文档包括排污许可证申请表、执行报告、自行监测方案、台账记录、变更申请及许可证副本。数据来源于全国排污许可证管理信息平台、企业环保台账、在线监测系统与环境统计系统，更新频率为季度。数据字段包含许可排放限值、监测点位、排放口信息、执行报告填报周期等，单位涉及浓度、流量、排放量等标准环保计量单位，文档结构多为结构化填报表单与非结构化文本结合的混合格式。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据多源混合且按季度更新，部署时需配置适配季度同步的定时拉取任务，避免数据滞后影响问答准确性。结构化表单与非结构化文本并存的文档结构，要求预处理环节适配多格式解析逻辑，确保不同类型文档均可被正确索引。固定字段如许可排放限值、排放口信息的一致性校验，需在知识库配置中绑定专属映射规则，保障问答内容的准确性。升级环节需保留证后监管所需的行业技术规范与许可限值核对逻辑，避免破坏原有校验链路的稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PG_URL` | `postgresql://fastgpt:securepass@db-host:5432/pollution_qa` | 存储排污许可相关的结构化文档与用户问答日志，匹配环保数据的结构化存储需求 |
| `REDIS_URL` | `redis://:redispass@redis-host:6379/1` | 缓存高频问答的政策条款与数据查询结果，降低重复调用的延迟 |
| `FILE_TOKEN_KEY` | `32位随机十六进制字符串` | 对排污许可文档的上传与下载链接进行加密，保障敏感环保数据的访问安全 |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-north-1.example.com` | 存储批量上传的自行监测方案、执行报告等非结构化文档，适配多源数据的存储需求 |
| `ROOT_KEY` | `按企业内部权限规则配置` | 管控系统管理员的操作权限，避免非授权人员修改排污许可相关的知识库配置 |

## 容易做错的三处
- 执行`docker build -f ./projects/app/Dockerfile`命令时出现`archive/tar: unknown file mod`报错，原因是构建镜像时未正确处理排污许可文档的特殊文件权限，导致打包过程中出现不兼容的文件模式。
- API请求返回`404 - 未找到资源`报错，原因是未正确配置`FE_DOMAIN`或`PG_URL`参数，导致系统无法加载对应政策问答的知识库资源或数据库连接失效。
- 升级至FastGPT v4.17.0后，政策问答结果出现许可限值字段缺失，原因是未适配季度更新的数据同步逻辑，原有知识库的字段映射规则未同步更新。

## 怎么确认配好了
- 执行`docker ps`命令，确认FastGPT相关容器处于运行状态，且挂载的存储路径包含排污许可的核心文档。
- 调用内置的知识库测试接口，输入「排污许可的自行监测方案要求」，检查返回结果是否包含来自全国排污许可证管理信息平台的官方内容。
- 查看系统日志，确认每15分钟触发一次数据同步任务，无连接超时或解析失败的报错。
- 登录系统后台，检查`FILE_TOKEN_KEY`配置项是否已生效，上传测试的排污许可证副本后可正常生成加密下载链接。
