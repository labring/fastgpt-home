# 政府信息依申请公开的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自政府信息公开平台、机关档案系统、内部公文系统、部门业务台账及相关公开规范。日常处理的文档包括政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证与行政复议答辩材料。数据更新无固定周期，随个案申请与内部流程变动产生新内容。文档多包含文号、发文日期、申请人主体、申请事项、答复意见等结构化字段，部分文件为无固定格式的转写文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来多重约束。数据来源分散且更新无固定周期，需支持增量索引与按需同步，避免全量重传带来的资源消耗。文档包含结构化字段与非结构化答复内容，分块时需兼顾字段完整性与语义连贯性，防止拆分破坏申请事项与答复意见的关联。部分文件无固定格式，需确保向量模型能准确捕捉申请事由与对应文档的语义匹配关系。另外，个案申请的查询具有强针对性，需限制召回范围以避免无关内容干扰。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 本品类文档包含结构化字段与非结构化答复，该区间可保留语义完整性且避免单块内容过长 |
| 重叠长度 | 100–150 字符 | 衔接相邻分块的语义关联，防止申请事项被拆分在两个分块中 |
| `maxToken` | 8192 | 适配主流中文嵌入模型的上下文窗口，匹配本品类文档的平均长度 |
| 相似度阈值 | 0.75–0.85，按实测标定 | 过滤低匹配度的无关文档，确保召回结果与申请事项的相关性 |
| 单次搜索上限 | 前 10 条 | 本品类需精准匹配特定申请，过多召回结果会增加后续筛选成本 |
| `defaultToken` | 2048 | 控制单轮问答的上下文长度，避免超出模型处理上限 |

## 容易做错的三处
- 现象：向量模型切换后，原有索引文档无法正常匹配查询。原因：未使用与原模型嵌入维度一致的新模型，或未重新生成对应文档的向量嵌入。
- 现象：单个文件长时间处于索引中，无进度更新。原因：文件格式不符合系统支持的类型，或文件大小超出单文件处理上限，导致解析流程阻塞。
- 现象：问答召回结果包含无关知识库的内容。原因：未配置知识库优先级规则，或优先级设置未按预期生效，导致多知识库检索时未优先匹配指定知识库。

## 怎么确认配好了
- 上传单份典型文档（如政府信息公开答复书），验证分块后的内容是否保留完整的申请事项与答复意见，无明显语义断裂。
- 切换向量模型后，重新生成文档向量，使用同一份测试查询验证匹配结果的一致性，确认嵌入维度与模型兼容性符合要求。
- 配置知识库优先级规则后，向包含重复内容的两个知识库发起查询，验证召回结果优先来自指定的高优先级知识库。
- 提交单个大文件，查看索引进度是否在合理时间内完成，确认未出现长时间阻塞的情况。
