# 政府信息依申请公开的政策与制度依据问答：工具调用与插件

## 这个品类的数据长什么样
本品类的核心数据来自政府信息公开平台、机关档案系统、公文系统、部门业务台账及《政府信息公开条例》相关文本，更新频率不定期。日常处理的文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料等，每个个案对应独立的材料集合，包含申请编号、申请人信息、申请内容、答复意见、救济途径等专属字段，无统一的批量数据格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散在多个独立系统，要求工具调用需支持多源接口对接，避免依赖单一数据源导致的信息缺失。更新频率不定期，要求插件无需固定周期同步，可按需触发数据拉取。个案专属的文档结构要求工具调用需按申请编号、申请人信息等精准定位目标数据，无法通过泛化关键词检索覆盖。同时，出错后果直接关联行政救济，要求工具调用返回的结果需明确关联来源，避免生成无依据的答复内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动选择适配政务数据检索的工具，无需手动指定调用项 |
| `functionCall` | `required` | 强制调用工具获取政策与业务数据，避免生成无依据的答复内容 |
| 调用超时时间 | `600 秒` | 多源检索需足够时间拉取档案、公文系统的分散数据 |
| 多源数据同步触发方式 | 按需触发 | 适配本品类数据更新不定期的特征，避免无效同步 |
| 检索结果返回上限 | 前 3 条 | 每个依申请公开个案的政策依据相对集中，过多结果会干扰回答准确性 |
| 上下文窗口长度 | `8000–12000 字符` | 容纳多份申请材料、答复书等文档的完整内容 |

## 容易做错的三处
- 现象：工具调用后无法在界面查看调用日志，原因：未在FastGPT v4.17.0系统设置中开启工具调用日志的存储功能。
- 现象：API调用返回空结果，原因：未配置对应政务系统的访问权限，无法拉取机关档案系统或公文系统的数据。
- 现象：生成的回答未附带答案出处，原因：未开启工具调用的溯源配置，未绑定检索结果的来源字段。

## 怎么确认配好了
- 发起包含具体申请编号的依申请公开相关问答，验证系统是否触发工具调用动作。
- 进入工具调用记录页面，确认每次调用的请求参数与返回数据均被完整存储。
- 检查生成的回答是否关联检索到的文档来源信息，确保可追溯数据来源。
- 模拟包含多份文档的检索场景，验证调用未超出设定的超时时间。
