# 政府信息依申请公开的政策与制度依据问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据主要来自政府信息公开平台、机关档案系统、公文系统、部门业务台账及《政府信息公开条例》等官方文件。日常处理的文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证与行政复议答辩材料。数据更新无固定周期，随业务办理与法规修订变动。文档多为结构化表单与制式公文，包含申请人信息、申请事项、答复内容、救济途径等固定字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且制式多样，要求检索需适配结构化表单与非结构化公文两种文本结构，避免单一分块规则导致关键信息丢失。不定期更新要求召回逻辑支持增量同步，无需全量重建索引，降低运维成本。固定字段与制式文档意味着需优先匹配申请事项、答复依据等核心字段，避免无关内容干扰检索结果。同时，业务办理存在时效要求，检索响应需控制在合理范围，避免影响答复流程与合规性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 适配制式公文与表单的语义匹配精度，过滤低相关的非业务文档 |
| `limit` | 前8条 | 覆盖单个申请可能涉及的多份依据文档，同时控制上下文总长度 |
| `searchMode` | 语义检索 | 适配非结构化的法规条文与结构化的表单内容，提升跨类型匹配效果 |
| `usingReRank` | 开启 | 对初始召回结果二次排序，优先匹配申请事项与公开依据的关联度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于申请事项自动生成扩展查询词，覆盖同义词与政务公开相关表述 |
| `collectionIds` | 绑定当前品类专属集合ID | 限定检索范围仅覆盖政府信息依申请公开的业务数据，避免混入其他数据集 |

## 容易做错的三处
- 现象：调用`pushData`接口批量上传数据时返回失败，返回状态码400。原因：单次上传的条目数超过200组，未按要求拆分批次提交。
- 现象：检索结果混入非政务公开相关的文档，导致匹配精度下降。原因：未配置`collectionIds`限定检索范围，绑定了其他品类的知识库集合。
- 现象：配置联网搜索工具后返回空结果。原因：未针对政务场景调整搜索规则，或未配置内网可访问的检索源，导致外部搜索无法获取有效政务内容。

## 怎么确认配好了
- 上传单份政府信息公开答复书与对应法规条文，执行检索核对返回结果是否包含目标文档。
- 调用`pushData`接口分批提交200组以内的数据，确认接口返回成功状态。
- 查看知识库集合的配置参数，确认`collectionIds`仅绑定当前品类专属的数据集。
- 开启调试模式，查看检索过程中的召回条数与重排结果，确认符合预设配置参数。
