# 政府采购项目的政策与制度依据问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
这个品类的数据来源包括中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常涉及的文档覆盖采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复等全流程文件。数据结构围绕政府采购项目生成，包含项目编号、项目名称、监管主体、执行主体、文档关联ID等字段，需根据对接的外部系统适配具体数据格式，无统一固定的标准化字段模板。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
每日更新的数据源要求接口需配置定时拉取任务，避免频繁调用超出外部系统限制。多来源的数据格式差异要求接口需适配不同的返回结构，需通过`responseData`参数灵活提取对应字段。全流程文档的多样性要求接口需支持按项目ID筛选特定文档，避免返回无关数据。政府采购项目的监管属性要求接口调用需携带合法认证信息，确保数据访问合规，同时需严格控制请求参数的准确性，防止因参数错误导致的监管处罚风险。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | Bearer Token 格式，从财政一体化系统获取的有效令牌 | 政府采购相关外部系统均要求身份认证，避免请求被拦截 |
| 请求超时时间 | 30–60 秒 | 适配政府采购接口的常规响应时长，避免长时间等待导致任务阻塞 |
| `responseData` 提取规则 | 提取返回内容中的公告正文、关联项目字段，保留前 1000 字符 | 匹配政策问答的核心需求，控制上下文长度符合FastGPT处理上限 |
| `variables` 绑定 | 绑定采购项目ID、监管部门ID为上下文变量 | 实现按特定项目拉取对应政策文档，避免返回全量无关数据 |
| 定时拉取频率 | 每日 1 次，每日凌晨 2 点执行 | 匹配数据源的日更频率，减少对外部系统的请求压力 |
| 单次请求条数 | 前 200 条 | 控制单次返回数据量，避免超出FastGPT的处理阈值 |

## 容易做错的三处
- 接口调用返回`403 Forbidden`报错，原因是未正确配置`Authorization`参数，使用了过期的财政系统认证令牌，或未携带合法的授权信息。
- 发起请求后返回的政策文档为空，原因是未正确绑定`variables`中的采购项目ID变量，导致请求参数缺失，无法定位到对应项目的政策依据。
- 定时拉取任务执行失败，原因是未设置合理的请求超时时间，超过政府采购接口的响应限制，导致请求被外部系统中断。

## 怎么确认配好了
- 调用测试接口，检查返回的`responseData`包含预期的政府采购政策文档片段，且字段与绑定的项目变量匹配。
- 查看FastGPT的接口日志，确认`Authorization`参数已正确携带，格式符合Bearer Token规范。
- 验证定时拉取任务的执行记录，确认每日凌晨的拉取任务成功完成，无报错信息。
- 绑定不同的采购项目ID发起请求，确认返回的文档内容与对应项目的政策依据一致。
