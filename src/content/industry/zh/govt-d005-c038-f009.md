# 政府采购项目的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常文档包含采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同与质疑答复等，覆盖采购全流程各环节。文档字段多包含项目编号、采购内容、资格要求、评审标准等，遵循政府采购相关文本的固定规范，无自定义特殊单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据每日更新的特性，要求接入配置需支持增量同步机制，避免全量重复拉取占用计算资源。文档类型多样且结构差异较大，需配置适配多格式的文本解析规则，确保不同采购文档的内容均可被正确提取。数据源均为官方公开或内部合规内容，需保证模型调用时可关联对应数据源的溯源信息，避免引用非合规内容。数据字段多涉及合规性相关要求，需限制模型输出仅引用官方文档内容，不可生成未验证的规则。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配政府采购文档的长文本上下文需求，避免截断关键政策条款 |
| `maxTokens` | 2000–3000 token | 控制单轮回答的输出长度，确保政策依据说明清晰且符合文本规范 |
| `quoteMaxToken` | 1500–2000 token | 限制引用文档的总长度，保证引用内容精准匹配查询的政策条款 |
| `temperature` | 0.1–0.3 | 降低回答的随机性，确保政策依据的表述与官方文本保持严谨一致 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应模型的接入地址 | 适配国内模型的接入路径，规避跨区域访问限制 |
| `AIPROXY_API_TOKEN` | 按平台生成的专属令牌填写 | 验证模型调用权限，确保仅授权用户可使用接入的模型 |

## 容易做错的三处
- 现象：调用重排模型后GPU显存占用快速增长且多GPU均出现占用。原因：未配置`maxContext`限制上下文长度，导致大量政府采购文档文本被加载至显存。
- 现象：接入国内模型时提示无效令牌，通过测试工具验证正常但直连失败。原因：未正确匹配`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的对应关系，直连路径未适配国内模型的认证规则。
- 现象：添加国内模型后，创建知识库与应用时无法显示对应模型。原因：未在模型接入配置中开启对应模型的可见权限，或配置的模型名称与平台识别规则不匹配。

## 怎么确认配好了
- 发起单次政策依据查询，核对返回结果的引用来源是否与官方政府采购文档一致。
- 查看GPU资源占用情况，确认重排模型的显存占用符合部署环境的可用范围。
- 检查模型接入配置的令牌与端点，通过测试工具验证调用链路是否正常。
- 创建测试知识库并导入政府采购招标文件，确认模型可正常召回相关政策条款。
