# 政府采购项目的政策与制度依据问答：部署与升级

## 这个品类的数据长什么样
本品类数据来自中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常文档涵盖采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复等，覆盖政府采购全流程的政务与交易文件。数据主体涉及采购人单位、财政部门政府采购监管处、采购代理机构及评审专家，文档结构围绕项目全周期节点形成标准化的政务交易档案。

## 这些特征在「部署与升级」这一环带来什么约束
本品类数据来源分散，涵盖公开政务网页与内部业务系统，部署时需适配多源数据的认证与接入规则。每日更新的频率要求部署增量同步任务，避免全量拉取占用过多资源。文档包含敏感政务交易信息，升级时需强化权限校验与数据脱敏配置。全流程文档的关联属性要求部署时配置关联索引，保障问答时的上下文准确性，同时需适配采购业务的专属文档字段规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://gov_user:secure_pass@internal-host:5432/gov_purchase_db` | 存储政府采购项目的结构化业务数据，适配政务系统常用的PostgreSQL数据库 |
| `REDIS_URL` | `redis://:redis_pass@internal-host:6379/1` | 缓存每日增量同步的文档元数据与用户会话，降低数据库查询压力 |
| `FILE_TOKEN_KEY` | 随机生成32位无特殊字符的字符串 | 加密政府采购文档的访问链接，防止未授权访问敏感政务文件 |
| `ROOT_KEY` | 随机生成64位强复杂度字符串 | 管理系统级权限，限制仅授权运维人员可修改政府采购问答的知识库配置 |
| `DB_MAX_LINK` | `20–30` | 适配政府采购数据的每日增量更新量，避免数据库连接耗尽 |
| `FE_DOMAIN` | `https://gov-purchase-intranet.example.com` | 保障问答界面仅在授权政务内网访问，符合政务系统安全规范 |

## 容易做错的三处
-  添加政府采购知识库后触发`403 该令牌无权使用模型`报错，原因是未在模型调用配置中绑定场景专属的访问令牌，或令牌权限未覆盖政务数据的检索范围。
-  本地部署模型添加知识库后无法正常响应，原因是未配置`PG_URL`或`REDIS_URL`导致知识库元数据无法正常存储与检索，或增量同步任务未按每日频率执行。
-  解析政府采购招标文件PDF附件时触发解析失败报错，原因是未配置`STORAGE_S3_ENDPOINT`或存储权限不足，无法读取上传的文档文件。

## 怎么确认配好了
-  执行知识库全量或增量同步任务，查看同步日志中无连接报错与数据解析失败提示，确认数据库与缓存配置生效。
-  尝试生成政府采购政策相关的问答内容，检查返回结果是否包含正确的文档来源与匹配内容，确认模型调用与权限配置正确。
-  点击知识库内的文档链接，验证是否需要输入有效令牌才能访问，确认`FILE_TOKEN_KEY`配置生效。
-  查看系统监控面板，确认数据库连接数未超过`DB_MAX_LINK`的配置值，避免资源耗尽影响服务稳定性。
