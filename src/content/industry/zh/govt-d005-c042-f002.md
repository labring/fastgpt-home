# 法务合规与重大风险管理的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自企业合同管理系统、合规风险数据库、法律法规库、案件管理系统与举报平台。日常文档包含合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告。数据更新频率为月度，文档多为结构化表单或半结构化文本，包含风险等级、审批状态、关联事项等字段，无统一固定单位，需按文档类型适配字段提取规则。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度批量更新的数据要求索引支持增量同步，避免全量重索引带来的额外耗时。半结构化文档的字段差异较大，分块时需保留关键元数据，防止合规等级、审批状态等影响匹配精度的信息丢失。多来源数据的格式不统一，需在索引前完成格式适配，否则会导致向量计算偏差。单次处理的文档规模较大，需控制单批次索引的上限，防止任务超时中断。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配半结构化合规文档的字段长度，避免切割关键审批节点或风险描述 |
| 重叠长度 | 100–200 字符 | 保留跨分块的合规关联信息，防止政策依据的上下文断裂 |
| `maxToken` | 4096 token | 匹配主流大模型的上下文限制，适配合规文档的长文本审核需求 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 区分合规风险的匹配精度，避免误判低关联度的政策条文 |
| 单次搜索上限 | 前10条 | 控制检索结果规模，适配法务人员快速定位核心合规依据的需求 |
| `defaultToken` | 1024 token | 设定基础向量生成的上下文窗口，平衡计算效率与文本完整性 |

## 容易做错的三处
- 现象：数据集导入CSV文件后，向量完成后总条数少于源数据条数。原因：未配置空值过滤规则，源数据中缺失合规风险等级或审批节点的字段被自动跳过。
- 现象：向量化任务长时间处于索引中状态，无进度更新。原因：未设置合理的`maxToken`参数，长文本合规文档超出模型支持上限，导致向量生成超时。
- 现象：向量计算得分异常偏高且多条结果得分一致。原因：相似度阈值设置过低，且未启用重排环节，导致低关联度的政策条文被误判为高匹配项。

## 怎么确认配好了
- 查看索引任务日志，确认每条源文档均生成对应向量条目，无批量丢失情况。
- 手动输入一条合规相关问题，检索返回结果的数量与排序符合预期，无明显异常得分。
- 调整相似度阈值后，观察检索结果的匹配精度变化，确认阈值设置适配业务需求。
- 验证增量索引功能，新增一条月度更新的合规文档后，索引任务可正常完成并同步至检索库。
