# 法务合规与重大风险管理的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自企业合同管理系统、合规风险数据库、法律法规库、案件管理系统与举报平台。日常处理的文档包含合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告。数据更新频率为每月一次，单份文档多包含合规条款、风险等级、审核意见、处理结果等结构化字段，部分文档附带案件编号、合规事项名称等识别字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且多为内部业务系统沉淀的结构化与非结构化内容，需适配多源数据接入的格式兼容规则。每月固定更新的特性要求配置自动同步机制，避免数据滞后影响实时合规判断。文档类型覆盖清单、审核意见、调查报告等多样形态，需适配不同文档的分块与召回逻辑。合规内容的准确性要求极高，模型调用需严格控制输出边界，同时支持召回内容的溯源验证，防止错误引用导致合规风险。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配合规文档的长文本上下文需求，避免截断关键合规条款或政策原文 |
| `maxTokens` | 4000–6000 token | 保障合规问答的完整输出，覆盖政策解读、风险分析的完整内容 |
| `quoteMaxToken` | 2000–3000 token | 限制召回文档的引用长度，确保引用内容精准且不冗余 |
| `toolChoice` | auto | 支持自动调用工具完成政策文档检索与合规校验，适配多源数据召回需求 |
| `temperature` | 0.1–0.3 | 降低输出随机性，保障合规问答的准确性与严谨性 |
| `AIPROXY_API_ENDPOINT` | 按模型服务商提供的官方地址填写 | 适配合规场景下的模型调用稳定性要求，避免自定义端点导致的连接异常 |
| `AIPROXY_API_TOKEN` | 按模型服务商分配的密钥填写 | 确保模型调用的身份验证有效，防止未授权访问或调用失败 |

## 容易做错的三处
- 现象：模型可正常处理聊天问答，但加载合规文档后出现解析失败或输出为空。原因：未针对合规文档的结构化格式配置`toolChoice`参数，导致无法触发文件解析工具。
- 现象：本地部署后新建知识库无图片理解模型选项。原因：未开启视觉模型相关的配置开关，且合规场景下的文档多为文本格式，易忽略该配置的前置校验步骤。
- 现象：模型调用测试报错，无法连接指定大模型。原因：`AIPROXY_API_TOKEN`配置错误或端点地址未适配合规场景下的网络限制，导致无法正常调用模型。

## 怎么确认配好了
- 执行模型调用测试，验证是否能正常召回合规数据库内的政策文档并生成对应回答。
- 上传一份合规风险清单文档，检查解析后的文本内容是否完整，无明显截断或乱码。
- 调整`temperature`参数后对比两次回答的一致性，确认输出随机性符合合规场景的严谨性要求。
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置，通过接口调试工具验证连接是否正常。
