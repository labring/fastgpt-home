# 特种设备安全监管的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
本品类数据涵盖特种设备使用登记证、定期检验报告、维保记录、隐患整改通知书、事故报告、作业人员证书等文档。数据来源于特种设备安全监察系统、检验检测机构业务系统、使用单位设备台账、作业人员证书库。数据更新频率为每月一次，单条数据包含设备唯一编号、检验周期节点、维保单位资质编号、作业人员持证编号等结构化字段，部分文档为带签章的扫描件格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类数据的月更新节奏要求知识库同步任务需匹配监管业务的月度报表周期，避免过期数据被召回。结构化字段与扫描件混合的文档结构，要求溯源环节同时支持结构化元数据匹配与非结构化文档文本溯源。设备唯一编号、检验周期等核心字段的强关联性，要求引用溯源需绑定具体设备的全生命周期数据，不能泛化匹配。隐患整改、事故报告等文档的严肃性，要求溯源结果必须明确指向原始系统的录入时间与存储路径。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配本品类单份核心文档（如定期检验报告）的平均文本长度，确保完整引用关键监管内容 |
| `responseData` | 包含原始文档ID、录入时间 | 满足监管场景下溯源需明确数据来源与更新时间的合规要求 |
| `detail` | 开启 | 支持返回非结构化文档的原文片段与结构化元数据，适配混合格式的数据溯源 |
| 单次召回上限 | 前6条 | 匹配每月更新的单类文档总量，避免召回过多无关数据干扰监管相关回答 |
| 知识库同步周期 | 每月1次 | 匹配本品类数据的官方更新频率，确保召回数据的时效性 |

注：本文配置基于FastGPT v4.17.0版本

## 容易做错的三处
- 现象：回答未包含本地知识库的合规正文内容，仅显示了第一条正确的知识库条目元数据。原因：未开启`detail`配置，系统仅返回了文档基础信息未提取正文片段。
- 现象：知识库同步任务失败，系统提示同步超时。原因：未设置匹配月度更新节奏的同步周期，单次同步数据量超出系统处理上限。
- 现象：溯源结果未关联设备唯一编号，无法绑定具体监管对象。原因：未配置`responseData`返回结构化元数据字段，导致无法关联核心监管标识。

## 怎么确认配好了
- 发起包含具体特种设备编号的查询，核对回答中是否包含对应设备的检验周期、维保记录等相关内容。
- 查看回答的溯源模块，确认是否显示原始文档的ID与录入时间。
- 触发一次知识库同步任务，检查同步完成状态是否在按实测标定的时长内完成。
- 测试扫描件格式的隐患整改通知书查询，确认是否返回原文片段与结构化元数据。
