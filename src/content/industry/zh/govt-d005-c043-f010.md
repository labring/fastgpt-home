# 特种设备安全监管的政策与制度依据问答：知识库检索与召回

## 这个品类的数据长什么样
本品类服务于市场监管局特种设备科、检验检测机构等主体，数据来源为特种设备安全监察系统、检验检测机构系统、使用单位台账、作业人员证书库。日常文档包含使用登记证、定期检验报告、维保记录、隐患整改通知书、事故报告、作业人员证书，核心字段含设备唯一编号、检验有效期、维保周期、作业人员资质编号、隐患整改状态等。数据更新频率为每月一次，覆盖设备全生命周期的登记、检验、维保、整改全流程关联文档。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且绑定设备唯一标识，需精准匹配设备编号与对应政策要求，因此检索需绑定设备标识作为关联条件，避免跨设备的无关文档被召回。月更频率要求检索结果需同步最新的检验、整改数据，需配置定期同步数据源的触发机制，确保召回内容的时效性。核心文档涉及强监管属性的资质、周期类信息，检索召回需保证结果的唯一性，不能混入过期失效的文档内容。同时，监管场景需快速定位合规性依据，检索结果需优先展示与当前问题直接相关的政策条款与设备对应记录。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配政策与设备关联的强语义关联需求，过滤低相关的通用监管文档 |
| `limit` | 前6条 | 覆盖设备全流程的登记、检验、维保等多类文档，避免单条结果信息不足 |
| `searchMode` | 语义检索+关键词混合 | 适配政策条款的精准关键词与设备标识的语义匹配需求 |
| `usingReRank` | 开启 | 对初始召回结果按相关性二次排序，优先展示与当前监管问题最匹配的内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展监管相关的同义词，覆盖政策文本中的不同表述，比如将「维保」扩展为「日常维护保养」 |

## 容易做错的三处
- 对话框上传文件提示503错误，知识库上传正常：原因是上传文件时未适配特种设备文档的格式校验规则，系统对单份超过10 MB的doc格式维保记录触发了服务限流，而知识库批量上传时采用了分段校验机制规避该问题。
- 语义检索未命中含指定关键词的知识块：原因是未开启`datasetSearchUsingExtensionQuery`配置，未对关键词进行同义词扩展，导致政策文本中「定期检验」与检索词「年检」无法匹配。
- 复杂监管问题无法得到准确回答：原因是仅召回单条文档，未关联设备全生命周期的多类记录，无法形成完整的合规性依据链。

## 怎么确认配好了
- 上传一条包含设备编号与检验周期的维保记录文档，发起包含该设备编号的监管问题，确认检索结果包含该文档内容。
- 调整`similarity`参数值，观察检索结果的相关性变化，验证阈值设置是否符合业务需求。
- 开启`usingReRank`后，对比开启前后的检索结果排序，确认重排功能生效。
- 测试上传单份doc格式的隐患整改通知书，确认无503错误，验证格式适配配置生效。
