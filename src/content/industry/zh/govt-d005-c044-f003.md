# 环境执法与监测监管的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类的核心数据来自在线监控平台、污染源自动监测数据、生态环境执法系统及第三方检测报告，更新频率为每日。日常处理的文档包含现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书，文档结构涵盖现场工况记录、采样点位信息、污染物浓度数值、执法文书编号等字段，单位涵盖浓度、体积、时间类，不同文档的字段格式存在差异，部分文档需关联多类数据源进行交叉验证。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据每日更新，且包含多类格式不同的文档，这要求多轮对话需优先调用最新的在线监控与执法系统数据，避免引入过期信息。不同文档需对应不同的业务场景，提示词需明确区分现场检查记录、监测报告等文档的使用规则。多类数据源的交叉验证需求，要求多轮对话支持逐步拆解比对步骤，引导用户明确指定数据来源。执法流程的可追溯性要求，需为每轮对话绑定唯一标识，确保上下文不混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| chatId | 绑定单次执法任务的唯一标识 | 确保同一场执法的多轮对话上下文不混淆，符合执法流程的可追溯要求 |
| messages | 保留前7轮对话上下文，超出部分自动截断 | 日更数据时效性强，过长上下文会引入过期信息，7轮符合单次执法的常规沟通轮次 |
| variables | 预设执法主体类型、数据来源类型2个变量 | 适配现场检查、采样监测等不同业务场景，快速切换提示词模板 |
| 最大上下文长度 | 800–1200 字符 | 该品类单份文档多在500字符以内，该长度可容纳2-3份核心执法文档，符合FastGPT v4.17.0的配置规范 |
| 单次召回上限 | 前4条 | 执法相关文档需精准匹配政策依据，过多召回会干扰判断 |

## 容易做错的三处
- 现象：对话过程中出现token超限报错，返回状态码413。原因：未限制`messages`的上下文轮次，引入了多日的过期执法数据，超出模型token承载上限。
- 现象：调用历史监测报告时提示文件已过期。原因：默认`CHAT_FILE_EXPIRE_TIME=7`未调整，而执法监测报告需长期留存参考，7天过期无法满足业务需求。
- 现象：批量执行节点中多AI对话任务执行结果混乱，无法按分工完成。原因：未为每个对话任务绑定独立`chatId`，导致上下文互相干扰，无法实现并行任务的分工执行。

## 怎么确认配好了
- 发起模拟执法对话，连续提问3轮关于同一份采样记录的问题，确认回答始终匹配该文档内容，无上下文丢失。
- 上传一份30天前的监测报告，测试调用时是否能正常获取，验证文件过期时间配置是否符合业务需求。
- 查看对话日志，确认每个任务的`chatId`唯一，无跨任务的上下文混杂情况。
- 调整`variables`变量，切换执法主体类型，确认提示词模板自动适配对应业务场景。
