# 用地预审与规划许可的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
这个品类的日常文档包括用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，数据来源于国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。文档结构多包含项目主体信息、选址范围、用地规模、管控要求、审批节点等内容，部分文档为CAD、PDF格式的空间矢量或栅格文件，无统一固定的标准化字段格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源包含空间矢量与栅格文件，模型接入时需配置支持多格式文档解析的模块，适配非结构化文本与空间坐标数据的提取。因更新频率不定期，需配置可灵活调整的同步机制，确保政策与审批数据的时效性。文档字段无统一标准，模型配置时需支持自定义字段映射，避免因格式差异导致的信息提取偏差。同时，业务需核对选址与管控要求的匹配性，需配置工具调用的触发逻辑，支持跨数据源的信息校验。

## 配置怎么定
FastGPT v4.17.0 版本下的配置参考如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 需容纳多份规划审批文件、国土空间管控数据的完整上下文，避免核心政策依据被截断 |
| `quoteMaxToken` | 1500–2000 token | 需完整引用规划条件、红线范围等关键政策文本，确保回答中的政策依据引用准确完整 |
| `toolChoice` | auto | 需自动触发跨数据源校验工具，核对项目选址与生态保护红线、土地利用现状的匹配性 |
| `vision` | 开启 | 用于解析红线图、规划条件等带可视化空间内容的文档，提取准确的用地范围信息 |
| `temperature` | 0.1–0.3 | 需保持回答的严谨性，避免生成不符合自然资源管控政策的非标准化内容 |
| `AIPROXY_API_ENDPOINT` | 按私有化部署的实际节点填写 | 适配内部网络环境的模型调用地址，确保数据传输合规 |

## 容易做错的三处
- 回答中附带冗余的模型思考过程片段，影响政策问答的可读性。原因是未合理设置`quoteMaxToken`参数，保留了模型内部的非必要推理内容。
- 解析红线图、规划条件等文档时出现乱码或空间坐标提取失败。原因是未开启`vision`配置，无法正确解析带可视化内容的文档格式。
- 升级平台版本后无法连接指定模型。原因是未同步更新`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`配置，与新版平台的接口校验规则不匹配。

## 怎么确认配好了
- 上传一份用地预审与选址意见书文档，检查模型是否能正确提取项目主体、选址范围等核心信息。
- 发起包含政策依据校验的查询，确认模型是否自动触发跨数据源的合规性校验，输出对应结果。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`配置正确，无连接报错。
- 调整`temperature`参数后，测试多次相同查询，确认回答内容保持一致，无明显偏差。
