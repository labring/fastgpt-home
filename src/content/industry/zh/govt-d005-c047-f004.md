# 行政处罚案卷办理的政策与制度依据问答：工作流编排
FastGPT v4.17.0 适用版本

## 这个品类的数据长什么样
本品类数据来源于行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统、部门监管数据库，更新频率为每日。日常涉及的文档包括现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，数据字段包含执法主体、违法情形描述、处罚依据条款、文书编号、生成时间等，整体兼具结构化字段与半结构化文本内容。

## 这些特征在「工作流编排」这一环带来什么约束
每日更新的数据需要配置定时同步节点，确保政策依据与执法数据的时效性。多类型执法文书的混合输入，要求工作流需按文书类型做前置分类，避免无关内容干扰政策匹配。固定证据与笔录环节的高耗时属性，需在工作流中加入前置校验节点，确保输入数据完整。处罚案卷需形成可追溯证据链，工作流需关联证据与处罚依据的对应关系，避免出现证据与条款不匹配的情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75-0.85 | 精准匹配执法相关政策条款，过滤无关内容，符合行政处罚案卷的严谨性要求 |
| 单次搜索上限 | 前10条 | 执法政策文档量相对可控，前10条即可覆盖常用处罚依据，避免冗余信息 |
| 最大上下文长度 | 8000-12000字符 | 覆盖多份执法文书与政策条款的总长度，确保回答逻辑完整 |
| 节点超时时间 | 600秒 | 适配大模型处理复杂执法政策问答的耗时需求，避免中途中断 |
| 变量映射 | 关联`variables`中的执法主体与案件ID | 实现工作流内动态调用案件专属信息，适配不同执法场景 |
| 问题优化开关 | 开启 | 将执法人员的口语化问题转化为标准政策查询语句，提升匹配精度 |

## 容易做错的三处
- AI会话节点开启温度开关并设置为0时，回答仍存在随机差异，原因是温度参数仅控制生成随机性，关闭温度开关才会固定输出逻辑。
- 指定回复节点无法实现连续多行换行，输入多行内容后输出仍为单行，原因是未在换行处添加标准换行标记或未开启富文本编辑模式。
- 问题分类节点处理速度过慢，触发后超过10秒无响应，原因是未配置`nodeId`对应的分类规则集，或关联的知识库数据未做合理分块。

## 怎么确认配好了
- 运行测试用例，验证AI输出未携带未配置的系统提示内容，如未出现预设外的平台声明语句。
- 提交多组不同执法场景的问题，确认问题分类节点的匹配结果符合预期，如市场监管类问题匹配对应监管政策。
- 查看工作流日志，确认`variables`中的执法主体与案件ID被正确映射到对应配置项。
- 检查节点超时日志，确认未出现节点超时报错。

> 问题素材取自公开社区提问（2026-09-11 去重 4,834 条）。文中的配置项名称与取值区间需以所用版本的实际界面与文档为准；本页核验日 2026-09-28，当时的最新发布版本为 FastGPT v4.17.0。
