# 行政处罚案卷办理的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，以违法事实与处罚决定为核心，需形成可追溯的处罚证据链与决定文书，字段覆盖执法主体、执法程序、违法情形、裁量依据、处罚结果等核心内容。

## 这些特征在「引用来源与溯源」这一环带来什么约束
每日更新的高频数据特征，要求引用溯源环节需支持实时调用最新行政执法办案系统、公示系统数据，避免引用过期失效的执法依据。多类结构化与非结构化文档混合的特征，要求溯源需区分笔录类文本、执法记录仪影像等不同类型素材的引用标识，确保格式统一可识别。以完整证据链为核心的业务要求，溯源需关联违法事实、裁量依据、处罚决定的全链路数据，确保引用内容符合合规逻辑。执法案卷的严格合规要求，溯源环节需保留原始数据的完整采集路径，确保可追溯至原始来源节点。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前5条 | 匹配执法案卷的证据链关联逻辑，避免过多无关内容干扰核心依据展示 |
| 最大上下文token数 | 800–1200 token | 适配单份执法文书的典型长度，确保核心政策与裁量依据完整加载 |
| 引用来源展示开关 | 开启 | 满足执法案卷合规性要求，需明确展示引用的原始文档节点与采集信息 |
| `detail`参数 | 开启详细模式 | 完整返回引用数据的元信息，支持溯源至原始采集路径与文档版本 |
| `responseData`格式 | 保留原始字段结构 | 适配执法文档的结构化特征，便于后续案卷归档与合规校验 |
| `quoteMaxToken` | 200–300 token | 限定单条引用的展示长度，避免正文过于冗长影响查阅效率 |

## 容易做错的三处
- 现象：知识库回答正文未显示引用来源内容。原因：未开启引用来源展示开关，导致系统未加载引用元数据。
- 现象：配置`quoteMaxToken`超过1500 token后，大模型无法接收上下文内容。原因：超出系统预设的上下文传输阈值，导致上下文截断未传递至大模型。
- 现象：上传的csv格式执法数据下载后显示正常，但在知识库中出现字段乱码。原因：未正确配置数据编码格式，导致原始结构化数据的中文字段解析异常。

## 怎么确认配好了
- 发起一条政策依据类查询，检查回答正文末尾是否带有明确的引用来源标识，包含文档类型、采集节点等信息。
- 调整`quoteMaxToken`至200–300 token区间，测试大模型是否能正常接收完整上下文内容，无截断或丢失。
- 上传一份标准执法文书样本，验证引用来源可追溯至原始数据的采集系统与上传时间。
- 查看知识库配置界面的引用展示开关状态，确认已处于开启状态。
