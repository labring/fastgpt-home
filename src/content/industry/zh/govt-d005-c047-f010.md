# 行政处罚案卷办理的政策与制度依据问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证等全流程办案文件，数据字段涵盖执法主体信息、违法事实描述、裁量基准引用、处罚决定内容、送达记录等，所有数据围绕违法事实与处罚决定形成可追溯的证据链，无额外自定义单位字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散的特点要求检索环节支持跨多数据源的知识库关联召回；每日更新的节奏要求知识库同步机制匹配执法办案的实时数据更新需求；多类型办案文档的结构差异，要求检索配置针对不同文档的字段特征调整召回规则；以违法事实和处罚决定为核心的业务逻辑，要求检索结果必须精准匹配法律条款、裁量基准等政策依据，避免出现引用错误；同时，案卷办理的可追溯要求，要求召回的文档需可关联至具体执法环节，便于后续法制审核。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配政策依据与办案文档的精准度要求，避免低相关性结果混入 |
| `limit` | 前8条 | 覆盖行政处罚案卷办理所需的多类文档，同时控制上下文长度 |
| `searchMode` | 语义检索+关键词检索混合模式 | 兼顾政策条款的关键词匹配与办案文档的语义关联 |
| `usingReRank` | 开启 | 提升高相关性结果的排序优先级，适配精准检索需求 |
| `datasetSearchUsingExtensionQuery` | 开启 | 优化政策依据类问题的扩展查询，匹配法律条款的标准表述 |
| `collectionIds` | 绑定行政执法办案专属知识库集合 | 限定检索范围，避免无关数据干扰 |

## 容易做错的三处
- 现象为对话触发知识库检索的状态不稳定，部分会话未执行检索直接返回预设内容。原因是未在工作流中强制绑定知识库检索节点，或未配置强制检索的触发规则。
- 现象为知识库搜索返回空结果，工作流节点未触发后续逻辑。原因是未配置搜索为空时的 fallback 分支，且`similarity`阈值设置过高过滤了有效结果。
- 现象为调用知识库检索时传入自定义变量报错，返回字段为空。原因是未正确绑定知识库ID变量的作用域，或变量格式不符合系统要求。

## 怎么确认配好了
- 输入某类行政处罚的政策依据问题，核对返回结果的相关性，调整`similarity`阈值至符合业务要求。
- 开启`usingReRank`后，确认高匹配度的政策与法律文档排序位置靠前。
- 验证检索范围仅覆盖行政执法办案专属知识库，排除无关数据干扰。
- 配置`datasetSearchUsingExtensionQuery`后，输入简化的政策问题，确认能召回准确的依据文档。
