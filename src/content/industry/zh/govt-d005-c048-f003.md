# 行政许可审批的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来自全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统及电子证照库，更新频率为每日。日常处理的文档包含办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书、许可证照等，每个许可事项的文档包含事项唯一标识、法定设定依据、办理条件明细、申请材料清单等字段，需严格匹配法定要求开展问答。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来源覆盖多套政务系统且每日更新，多轮对话需明确区分不同来源的文档上下文，避免跨系统数据混淆。法定文书类文档的字段严格对应法定要求，提示词需强制要求回答时标注引用的具体文档来源及条款。行政许可审批的问答结果直接关联审批流程，多轮对话需逐步引导用户确认申请材料与法定清单的匹配度，避免遗漏法定办理条件。每日更新的数据也要求定期刷新知识库向量库，确保问答内容始终匹配最新的行政许可事项调整。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口 | 前 10 轮对话 + 最近 8000 字符的知识库召回内容 | 匹配行政许可事项的多轮补正沟通场景，避免上下文溢出 |
| `variables` | 预设「行政许可事项编码」「申请材料清单」变量 | 用于快速绑定用户提交的具体事项信息，减少重复输入 |
| `chatId` | 绑定用户会话的唯一标识 | 确保多轮对话的上下文隔离，不同用户的审批咨询互不干扰 |
| 多轮对话触发逻辑 | 按`messages`序列逐步补全上下文 | 确保每一轮对话都基于历史交互和当前问题生成答案 |
| 单次召回上限 | 前 5 条匹配文档 | 控制单轮问答的信息负载，符合法定文书的精准匹配要求 |
| 超时阈值 | 600 秒 | 适配跨部门调取电子证照的等待时长，避免会话中断 |

## 容易做错的三处
- 现象：配置提示词后，AI回答未遵循预设的法定依据引用规则。原因：提示词未绑定至行政许可审批的细分知识库场景，仅配置在全局问答模块。
- 现象：会话历史无法导出，或导出内容缺少关键的补正告知环节交互。原因：未开启`chatId`的会话日志存储配置，导致历史对话数据丢失。
- 现象：用户上传申请材料附件后，AI无法基于附件内容开展后续问答。原因：未启用多模态交互功能，或未配置对应文件格式的解析规则。

## 怎么确认配好了
- 发起一条针对已知行政许可事项的测试提问，检查回答是否标注了引用的具体文档来源及条款。
- 发起多轮交互，依次提交不同的申请材料信息，检查上下文是否正确关联历史对话内容。
- 上传一份标准申请表模板，检查AI是否能基于附件内容生成对应的材料核对清单。
- 模拟跨部门调取证照的等待场景，检查是否在600秒内完成响应或给出合理的等待提示。
