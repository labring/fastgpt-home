# 行政许可审批的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据覆盖政务服务中心、行政审批局等主体的日常审批文档，包括办事指南、申请表、受理通知书、补正告知书、准予行政许可决定书、许可证照等。数据来源为全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统、电子证照库，更新频率为每日。文档通常包含事项编码、法定设定依据、办理条件等标准化字段，无自定义单位，字段均遵循政务服务相关规范。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据每日更新的特性要求溯源环节需实时关联最新生效的官方数据源，避免引用过期政策。多类型审批文档对应不同的引用标识规则，如电子证照需关联电子证照库编号，办事指南需绑定全国一体化政务服务平台事项库的具体条目。法定依据的严谨性要求溯源信息必须明确指向具体事项或官方文件，无法模糊关联。跨部门数据源的调取需求，要求溯源环节支持关联多个来源的校验逻辑，确保引用来源的合规性。

## 配置怎么定
本文档基于 FastGPT v4.17.0 版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配行政许可政策依据的段落结构，避免拆分法定依据的完整条款 |
| 单次搜索上限 | 前 5 条 | 行政许可的法定依据通常集中在官方清单或事项库的少量条目，过多结果会干扰溯源 |
| 重排 | 开启 | 优先匹配法定设定依据、办理条件等核心字段，提升引用准确性 |
| `quoteMaxToken` | 1200–1800 token | 保留足够的引用内容用于精准溯源 |
| `detail` | true | 返回详细的引用来源元数据，满足合规校验与审计需求 |
| `responseData` | 包含知识库id、事项编码 | 确保接口返回可直接用于溯源的关键标识 |

## 容易做错的三处
- 现象：对话接口返回结果未包含知识库id或事项编码。原因：未正确配置`responseData`参数，未开启元数据返回开关。
- 现象：返回的引用文件与实际审批事项不匹配。原因：分块长度设置不合理，导致拆分后的文档片段关联错误的事项编码，或搜索上限过高引入无关文档。
- 现象：流式返回结果无法解析溯源细节。原因：未将`detail`参数设为true，导致返回内容未包含详细的元数据字段。

## 怎么确认配好了
- 发起针对具体行政许可事项的政策问答，核对返回结果中是否包含可溯源的官方来源标识。
- 调用接口并查看返回的元数据字段，确认是否包含所需的溯源信息。
- 手动触发一次数据源更新模拟，验证系统是否能正确关联最新版本的政策依据。
- 检查流式返回的内容，确认是否包含详细的引用细节。
