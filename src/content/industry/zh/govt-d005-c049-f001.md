# 规范性文件合法性审核的政策与制度依据问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类处理的数据主要来自法规规章库、上位法数据库、部门政策文件库及行政规范性文件备案系统。日常处理的文档包括规范性文件草案、起草说明、合法性审核意见、征求意见汇总与备案报告。数据更新无固定周期，需随上位法修订、政策调整实时同步。数据字段包含文件文号、制定主体、生效日期、条文内容、审核意见等，无统一固定单位，需按单份文件的实际内容提取。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 固定前缀加合法令牌，格式为`Bearer {token}` | 对接外部法规库与备案系统接口的身份校验要求 |
| `variables` | 预设审核场景变量，如`{"target_doc_type": "规范性文件草案"}` | 限定接口处理的文档类型，过滤非目标数据 |
| `responseData` | 仅返回审核结果、匹配依据文号 | 减少无效数据传输，适配备案系统的接收格式 |
| 超时时间 | 600 秒 | 适配大文本比对与多源数据拉取的耗时需求 |
| 单次文件上传上限 | 1000 MB | 适配完整规范性文件草案与配套说明的存储需求 |
| 最大匹配条目数 | 前 10 条 | 控制返回的上位法依据数量，避免上下文溢出 |

## 容易做错的三处
- 现象：离线环境下调用文件上传接口后界面持续显示加载状态，无返回结果。原因：接口依赖外部法规库与备案系统的访问，离线环境下无法完成身份校验与数据拉取。
- 现象：调用匹配接口后`responseData`返回字段为空。原因：未正确指定`variables`中的目标文档类型，接口过滤了有效数据。
- 现象：上传的规范性文件草案解析后字段缺失。原因：未在配置中启用正确的文档解析规则，接口未提取目标审核所需的字段内容。

## 怎么确认配好了
- 调用配置了`Authorization`的接口，返回200状态码，确认身份校验逻辑生效。
- 上传一份测试用规范性文件草案，查看`responseData`返回的结果是否包含匹配的上位法依据文号。
- 模拟离线网络环境，调用接口后确认返回明确的访问失败提示，确认依赖服务校验逻辑正常。
- 导入预设的审核工作流模板，确认页面显示的节点与配置项匹配，无缺失内容。
