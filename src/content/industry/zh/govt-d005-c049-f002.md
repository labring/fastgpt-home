# 规范性文件合法性审核的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自法规规章库、上位法数据库、部门政策文件库及行政规范性文件备案系统，更新频率不定期。日常处理的文档包含规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告等，文档结构多包含条文编号、制定主体、生效日期、权利义务条款、审核依据等字段，无统一固定的单位标识，内容多为抽象政策规则文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且更新无固定周期，需支持多源数据的增量同步与增量索引，避免重复处理历史文档。文档包含多类结构化与非结构化内容，条文编号、制定主体等元数据需关联至索引，提升检索精准度。日常审核需比对上位法与权限依据，对长文本的分块逻辑要求严格，需避免拆分破坏核心条款的上下文连贯性。检索结果需匹配审核严谨性要求，需严格控制误召回与漏召回比例，确保政策制定的合法性。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 规范性文件条文多为连续逻辑文本，避免拆分破坏权利义务、制定依据等核心内容的完整性 |
| 重叠长度 | 100–200 字符 | 覆盖相邻分块的关联内容，确保上位法依据检索时的上下文连贯性 |
| 相似度阈值 | 按实测标定 | 需匹配政策文本的语义相似度特性，避免误召回无关上位法条文或漏召回有效依据 |
| 单次搜索上限 | 前 10 条 | 合法性审核需比对多类依据，限制返回条数确保审核效率与信息聚焦 |
| maxToken | 4000–6000 token | 需承载审核所需的上位法、起草说明等多份文档的上下文内容，符合模型输入限制 |
| defaultToken | 2000 token | 适配单份核心文档的常规检索与比对需求，平衡上下文长度与计算资源 |

## 容易做错的三处
- 知识库导入文本数据集后状态长期显示为索引中。原因：未配置增量索引触发规则，或多源数据同步时未跳过已处理的历史文档，导致重复索引任务堆积。
- 切换向量模型后语义相似度数值超出常规区间。原因：未调整相似度阈值的匹配逻辑，部分模型输出的相似度分值范围与默认配置不匹配，导致阈值设置失效。
- 检索结果无法精准匹配上位法依据。原因：分块长度设置过短，拆分了关联的条文与制定主体信息，导致语义关联断裂，检索召回精度下降。

## 怎么确认配好了
- 导入单份典型规范性文件草案，检查分块后的文本是否保留完整的条文编号与核心条款内容。
- 输入一条合法性审核的查询，查看检索结果的条数是否符合单次搜索上限的设置。
- 切换测试向量模型，验证相似度分值的范围是否符合预期，调整阈值匹配当前模型的输出特性。
- 模拟不定期更新数据，触发增量索引任务，检查新数据是否能正常完成索引流程。
