# 规范性文件合法性审核的政策与制度依据问答：工作流编排
本文基于FastGPT v4.17.0版本的工作流编排功能编写。

## 这个品类的数据长什么样
本品类的数据来自法规规章库、上位法数据库、部门政策文件库与行政规范性文件备案系统，更新频率不定期。日常处理的文档包含规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告，文档字段涵盖发文主体、条文内容、起草依据、审核意见编号、报送单位等，单份文档篇幅跨度较大，从数百字符到数万字符不等。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散要求工作流配置多源召回节点，覆盖法规规章库、上位法数据库等不同数据源；文档篇幅跨度大，需支持自定义分块参数适配不同长度的政策文件。更新不定期则要求工作流可按需触发数据同步，无需固定周期拉取。审核需逐条比对条文与上位法，因此需设置循环校验节点覆盖全部条文内容，需通过`variables`变量传递文档的条文总数等元数据。审核结果需关联起草说明与备案报告，要求工作流保留字段映射关系，确保关联数据准确。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 多源数据源配置 | 关联法规规章库、上位法数据库、部门政策文件库三个数据源，单次搜索上限 前5条 | 本品类需覆盖核心政策依据，前5条可覆盖主要关联内容，避免冗余数据干扰审核 |
| 分块长度 | 800–1200 字符 | 规范性文件条文多为数百到数千字符，该区间可保证单块内容完整且上下文连贯 |
| 循环校验节点绑定 | 绑定`variables`中的「条文总数」变量 | 确保循环次数与待审核条文数量一致，覆盖全部审核内容 |
| 节点跳转配置 | 通过`nodeId`指定下一个处理节点的ID | 可按审核结果自动流转至对应环节，如依据比对完成后进入权限审查 |
| 最大上下文窗口 | 8000 token | 需完整携带草案、上位法对比内容，避免关键依据丢失 |
| 节点超时时间 | 600 秒 | 审核比对环节耗时较长，600秒可保证完成多源召回与比对 |
| 数据同步触发 | 按需手动触发 | 本品类数据更新不定期，固定周期同步会造成资源浪费 |

## 容易做错的三处
- 现象：开启图片上传节点后，返回的图片链接显示为IP加端口格式。原因：未配置域名映射规则，工作流默认调用本地服务地址，未替换为官方域名。
- 现象：工作流运行时报错包含`$schema`字段异常提示。原因：未正确配置工作流的元数据结构，导致字段格式不符合FastGPT的校验规则。
- 现象：循环校验节点未按预期执行，仅校验了部分条文。原因：未正确绑定`variables`中的条文总数变量，循环触发条件未覆盖全部审核条目。

## 怎么确认配好了
- 检查多源数据源配置，确认已关联所有要求的政策与法规数据库，核对数据源列表与业务需求一致。
- 运行单份小型规范性文件测试，查看分块后的内容完整性，确认分块参数适配文档长度。
- 触发循环校验节点，核对循环次数与文档条文总数匹配，确认`variables`变量绑定正确。
- 测试数据同步功能，确认可按需触发数据源更新，无固定周期限制。
