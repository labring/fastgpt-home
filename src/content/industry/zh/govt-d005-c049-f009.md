# 规范性文件合法性审核的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自法规规章库、上位法数据库、部门政策文件库及行政规范性文件备案系统，更新频率不定期。日常处理的文档包含规范性文件草案、起草说明、合法性审核意见、征求意见汇总与备案报告。数据字段涵盖文件标题、发文单位、生效日期、条文内容、审核意见等，无统一固定单位，随文件类型动态变化。处理过程中需关联跨来源的法规条文与政策依据，数据体量随政策更新及审核任务量波动。在FastGPT v4.17.0版本中，该品类的数据源配置已支持批量导入备案系统数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新无固定周期，要求配置支持多数据源的增量同步与索引构建，避免全量重复拉取占用资源。文档类型多样，包含草案、说明、审核意见等非标准化文本，需配置适配多格式的文本解析与分块规则，确保核心内容完整提取。需跨库比对上位法与权限依据，要求模型上下文关联逻辑适配跨源数据关联，配置需保证检索召回的精准性。审核出错后果直接影响政策发布与执行，需配置结果溯源与校验环节，确保依据来源可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配跨库法规条文与政策文件的长文本关联需求，避免截断核心依据内容 |
| `maxTokens` | 4000–6000 token | 控制单次审核回答的输出长度，确保合法性审核意见的完整性与可读性 |
| `quoteMaxToken` | 1500–2000 token | 限定引用依据的文本长度，保证引用内容精准且不冗余，符合审核文档的格式要求 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保审核结论的严谨性，符合政策与制度依据的确定性要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写实际接口地址 | 适配本地或云端部署的模型接入需求，确保模型调用链路正常 |
| `AIPROXY_API_TOKEN` | 按平台分配的密钥填写 | 保障模型调用的身份验证安全，符合政务系统的数据安全规范 |

## 容易做错的三处
- 模型调用时返回仅支持stdio进程的报错，无法使用sse协议封装的MCP。原因是接入配置未遵循平台默认的进程通信规范，误启用了非标准的通信协议。
- 工作流界面模型图标不显示，文件上传触发网络错误提示。原因是配置的`AIPROXY_API_ENDPOINT`地址未正确指向部署节点，或节点间的网络访问权限未开放。
- 索引召回的依据条数与实际数据源不匹配。原因是未适配品类数据不定期更新的特性，未配置增量同步规则，导致索引与最新政策文件不同步。

## 怎么确认配好了
- 执行模型调用测试，验证是否能正常返回合法性审核相关的依据关联结果，核对调用链路的日志无报错。
- 检查索引配置，确认已关联品类指定的法规规章库、上位法数据库等数据源，验证数据同步状态正常。
- 调整测试用的`temperature`参数，观察生成结果的严谨性是否符合审核需求，确认参数配置适配业务场景。
- 检查网络与密钥配置，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的有效性，确保模型调用无身份验证或网络问题。
