# 规范性文件合法性审核的政策与制度依据问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据主要来自法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新频率不定期。日常处理的文档包含规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告，单份文档内容跨度从数条条文到数十页完整文件，字段包含文件标识、发布主体、生效节点、条文原文、审核关联记录，无固定统一的单位字段，仅随文件所属行政层级对应不同的管理权限范围。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征对检索与召回环节带来明确约束。多分散数据源要求配置跨集合召回能力，覆盖法规规章库、上位法数据库等多类来源；不定期更新节奏要求适配非固定周期的数据源同步逻辑，避免遗漏最新政策文件；文档跨度差异大的特点，要求分块策略适配从数条条文到数十页完整文件的不同文本长度；数据包含审核关联的历史记录，要求检索时可关联上下文辅助验证；核心比对上位法的需求，要求召回结果优先匹配上位法层级的依据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 规范性文件合法性审核需严格匹配条文合法性，阈值过低会引入无关内容，过高则遗漏合规依据 |
| `limit` | `返回前10条结果` | 单次召回过多会超出上下文窗口，过少则无法覆盖多维度的合法性审查依据 |
| `searchMode` | 语义检索与关键词检索混合模式 | 需同时匹配条文语义和精准文号、发布主体等元数据，提升合法性审查的检索精准度 |
| `usingReRank` | 开启 | 需对召回结果按合法性相关性重排，优先返回上位法、核心政策等关键依据 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可通过扩展查询补充政策制定的背景依据，辅助完成合法性验证 |
| `collectionIds` | 按审核场景绑定对应数据集ID | 仅召回当前审核任务对应的法规、政策数据集，避免无关数据干扰审查流程 |

## 容易做错的三处
- 现象：调用数据集集合创建接口时返回Query read timeout报错。原因：未配置合理的接口超时逻辑，或数据源同步未完成导致检索请求等待超时。
- 现象：外部传入知识库ID后，检索无返回结果。原因：未正确绑定对应数据集的`collectionIds`参数，或传入的ID不属于当前应用授权的数据集范围。
- 现象：工作流中无法获取有效知识库ID用于检索。原因：未在工作流节点中配置数据集关联逻辑，或未正确引用已创建的集合ID变量。

## 怎么确认配好了
- 确认当前使用FastGPT v4.17.0版本，查看检索配置面板，确认`similarity`、`limit`等参数已按标定取值完成设置。
- 发起模拟检索请求，传入规范性文件草案的核心条文，核对返回结果是否包含上位法依据及相关政策文件。
- 检查工作流节点配置，确认已正确引用目标数据集的`collectionIds`变量，无空值或无效ID。
- 测试接口调用，验证返回结果条数符合`limit`参数的设定，无超时报错。
