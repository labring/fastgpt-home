# 财政支出绩效评价的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查。日常处理的文档包括绩效目标表、自评表、绩效评价报告、佐证材料清单、整改报告。数据更新频率为年度。文档多为结构化表格与半结构化文本混合，字段包含项目编号、资金额度、绩效指标、完成情况等，无统一固定单位，需随对应项目场景匹配具体单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
年度更新节奏决定索引无需高频增量同步，定期全量构建即可满足业务需求。混合结构化与半结构化的文档结构，要求分块策略兼顾表格完整性与文本连贯性，避免拆分跨表格的绩效指标关联。多源异构的数据格式差异，需统一预处理流程后再生成向量，防止语义偏差。字段无固定单位，需保留原始字段名与语义关联，确保向量匹配的准确性。佐证材料与主文档的绑定关系，需在索引中保留关联逻辑，便于检索时联动调用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配绩效类文档的段落与表格单元长度，避免拆分关键绩效指标关联 |
| 重叠长度 | 100–150 字符 | 保留跨分块的政策条款与绩效目标的上下文关联 |
| `defaultToken` | 2000 token | 匹配单条政策文件与项目数据的总语义长度 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的政策条款，确保检索结果与绩效评价依据的相关性 |
| 单次搜索上限 | 前 8 条 | 覆盖多维度绩效评价所需的政策依据与项目佐证 |
| `maxToken` | 4000 token | 限制检索结果的总上下文长度，避免超出FastGPT v4.17.0的模型输入上限 |

## 容易做错的三处
- 出现503状态码提示无可用模型渠道。原因是未单独配置向量模型渠道，仍依赖全局的OneAPI配置，导致模型调用失败。
- 启动容器后无法正常调用模型，提示API密钥无效。原因是未在docker-compose.yml中正确配置CHAT_API_KEY环境变量，且未重建容器使配置生效。
- 知识库检索测试页面无法调整索引参数。原因是误将索引配置入口定位到检索测试页面，需进入知识库内容管理模块完成参数调整。

## 怎么确认配好了
- 进入FastGPT知识库管理页面，查看向量模型配置项，确认已单独设置embedding模型渠道，未依赖全局OneAPI配置。
- 执行一次全量索引构建，查看构建日志，确认无格式报错或文本截断提示。
- 发起一条政策依据相关的测试查询，核对返回结果的条数符合单次搜索上限配置，且相似度符合阈值要求。
- 检查索引分块长度配置，随机抽取分块后的文本，确认未拆分关键绩效指标与政策条款的关联。
