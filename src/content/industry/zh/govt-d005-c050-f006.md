# 财政支出绩效评价的政策与制度依据问答：引用来源与溯源

本页面适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的数据来自预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查结果。日常处理的文档包括绩效目标表、自评表、绩效评价报告、佐证材料清单与整改报告。数据更新频率为年度周期，文档结构多包含项目编号、绩效指标、资金明细、佐证材料关联字段，无统一固定单位，字段随项目类型略有差异。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的数据来源分散且关联具体项目，要求溯源环节需精准绑定项目编号与对应政策、业务数据，避免泛化引用。年度更新的特性要求定期刷新知识库的政策与业务数据，确保引用内容未过期。文档类型多样，需区分绩效评价类文档与政策依据类文档，保证溯源时能准确识别来源类别。佐证材料与绩效目标的强关联要求溯源结果需关联到具体的资金支出环节，与实际业务的政策条目绑定。不同主体提交的文档格式存在差异，需保证溯源环节能兼容多种文档格式的元数据提取，确保引用来源的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索引用上限 | 前3–5条 | 本品类文档与具体项目强关联，过多引用会超出模型上下文限制 |
| `quoteMaxToken` | 800–1200 token | 匹配绩效评价类文档的平均长度，完整保留核心政策与业务依据 |
| 引用详情展示 | 开启 | 需向使用者展示政策与业务数据的具体来源与关联项目 |
| `responseData` | 包含来源元数据 | 确保正式发布页面能携带引用出处，满足溯源需求 |
| `detail` | 开启详细溯源 | 展示文档的具体章节与关联的项目编号、绩效指标等信息 |
| 知识库刷新周期 | 按年度标定 | 匹配本品类数据的年度更新频率，避免引用过期内容 |

## 容易做错的三处
- 现象：正式发布的聊天页面未显示引用来源，仅调试页面可见。原因：未开启`responseData`配置项，或未正确配置响应数据的元数据携带规则。
- 现象：设置引用上限为2000后，单条回答token超出阈值被截断。原因：未结合本品类文档的平均长度调整`quoteMaxToken`，过高的引用上限导致聚合内容超出模型上下文限制。
- 现象：溯源结果未关联具体项目信息，仅展示政策名称。原因：未开启`detail`配置项，未提取文档中的项目编号、绩效指标等关联字段，导致溯源信息泛化。

## 怎么确认配好了
- 进入正式发布的聊天页面，发起与财政支出绩效评价相关的政策咨询，检查回答末尾是否显示引用来源的条目。
- 查看知识库配置页面的`quoteMaxToken`取值，确认其匹配本品类文档的平均长度范围。
- 触发调试模式，查看完整响应数据，确认`responseData`字段包含来源文档的元信息。
- 提交更新后的政策文档，验证溯源结果是否能正确关联到最新的政策版本。
