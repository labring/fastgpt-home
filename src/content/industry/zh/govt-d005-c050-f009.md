# 财政支出绩效评价的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查，更新频率为年度。日常文档包含绩效目标表、自评表、绩效评价报告、佐证材料清单与整改报告，数据字段覆盖项目绩效指标、资金使用明细、产出效果记录及整改情况，无统一固定单位，需随具体项目匹配对应字段规则。

## 这些特征在「模型接入与配置」这一环带来什么约束
年度更新的特性意味着知识库的同步周期可以设置为年度，无需高频更新，但单次召回的文档数量可能较多，需限制上下文长度以适配模型处理能力。多来源数据包括结构化的预算管理数据与非结构化的佐证材料，需配置适配不同数据源的解析规则，确保各类格式的内容都能被正确召回。多类型文档的存在要求明确召回范围，避免无关文档干扰政策依据问答的准确性。项目关联字段无统一单位，需确保模型召回的内容能匹配具体项目的字段定义，同时需限制单条引用的文档长度，避免超出模型的处理上限。FastGPT v4.17.0的配置界面需对应调整这些约束下的参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配财政支出绩效评价场景下多文档召回后的上下文长度，避免超出FastGPT v4.17.0支持的主流大模型上下文限制 |
| `maxTokens` | 2000–3000 token | 确保生成的政策依据问答回复足够完整，同时控制单轮调用的成本 |
| `quoteMaxToken` | 1500–2000 token | 限制单条引用文档的长度，避免引用内容过长干扰模型对政策依据的精准提取 |
| `temperature` | 0.1–0.3 | 降低生成内容的随机性，确保政策依据问答的回复符合官方文档的严谨性要求 |
| `toolChoice` | auto | 自动选择是否调用检索工具，适配多文档召回的财政支出绩效评价场景 |
| `AIPROXY_API_ENDPOINT` | 按平台提供的官方地址填写 | 确保模型接口调用的连通性，避免配置错误导致调用失败 |
| `AIPROXY_API_TOKEN` | 按平台分配的密钥填写 | 完成模型接口的身份验证，确保调用权限正常 |

## 容易做错的三处
- 现象为模型召回多个无关文档，无法精准定位指定的绩效评价报告。原因是未配置针对特定文档的召回规则，导致召回范围覆盖全部知识库。
- 现象为接口返回429状态码，并发调用时触发限流报错。原因是未适配财政支出绩效评价场景的调用频率，未在配置中设置合理的并发控制。
- 现象为生成的回复出现政策依据偏差，表述不够严谨。原因是`temperature`取值过高，导致模型生成内容偏离官方文档的严谨要求。

## 怎么确认配好了
- 发起针对特定绩效评价报告的查询，核对召回结果是否仅包含目标文档的相关内容。
- 发起多并发测试，确认接口调用未触发限流报错。
- 生成测试回复，核对内容的严谨性是否符合政策依据的要求。
- 检查`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置是否与平台提供的官方信息一致。
