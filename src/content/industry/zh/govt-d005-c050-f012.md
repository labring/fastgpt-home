# 财政支出绩效评价的政策与制度依据问答：部署与升级

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
该品类的数据主要来自预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查。日常处理的文档包括绩效目标表、自评表、绩效评价报告、佐证材料清单与整改报告，文档包含项目编号、资金额度、绩效指标、完成情况、佐证材料编号等字段。数据更新频率为年度，单次处理的文档体量随项目数量变化，无固定周期内的高频更新。

## 这些特征在「部署与升级」这一环带来什么约束
数据来源涉及多套业务系统，部署时需配置跨系统数据同步的权限与接口适配规则；年度更新的低频特性要求部署时设置合理的增量同步触发机制，避免全量拉取占用过多系统资源；文档类型多样且包含结构化字段与非结构化佐证材料，需适配多格式数据的解析与存储逻辑；项目关联的字段需与业务系统字段严格对齐，部署时需校验字段映射规则，防止数据错位影响绩效评价的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `10–15` | 适配年度批量数据拉取与实时问答的并发需求，避免数据库连接耗尽 |
| `MONGODB_URI` | 指向存储绩效文档与评价记录的专属MongoDB实例 | 隔离业务数据与其他系统数据，保障绩效评价数据的安全性与可追溯性 |
| `PG_URL` | 关联预算管理一体化系统的PostgreSQL数据库地址 | 直接获取预算、支付等结构化业务数据，减少数据同步环节的误差 |
| `REDIS_URL` | 部署在本地私有网络的Redis实例地址 | 缓存高频查询的政策条文与绩效指标数据，降低数据库访问延迟 |
| `STORAGE_S3_ENDPOINT` | 适配内部对象存储服务的端点地址 | 存储佐证材料等非结构化文档，统一管理绩效评价全流程文件 |

## 容易做错的三处
- 工作流中无法调用数据库工具，返回连接超时或权限不足错误。原因是未正确配置`PG_URL`或`MONGODB_URI`指向非业务系统数据库，或`DB_MAX_LINK`设置过低导致连接池耗尽。
- 所有模型调用均报错，返回500状态码。原因是`REDIS_URL`配置错误，导致缓存服务无法正常启动，影响模型调用的上下文管理与数据缓存。
- 官网示例流程无法复用，出现字段不匹配提示。原因是未按照品类专属的字段映射规则配置数据导入，直接使用通用流程模板，未适配绩效目标表、自评表的专属字段。

## 怎么确认配好了
- 执行单次数据同步测试，验证从预算管理一体化系统拉取的结构化数据与本地存储的字段完全对齐。
- 发起一次针对绩效政策的问答请求，确认返回结果包含对应文档的准确内容，且缓存命中情况符合预期配置。
- 上传一份绩效佐证材料，确认文件可以正常存储并在问答流程中被正确调用。
- 运行完整的工作流测试，验证工具调用、数据拉取与问答生成的全流程无报错。
