# 道路运输经营许可的政策与制度依据问答：文档解析与分块

## 这个品类的数据长什么样
这个品类的核心数据来自道路运政管理系统、全国道路运输车辆动态信息公共服务平台、车辆和从业人员数据库，更新频率为每日。日常处理的文档包含经营许可申请、车辆技术档案、驾驶员从业资格材料、安全生产管理制度、道路运输经营许可证等，文档多包含结构化字段，如车辆号牌、从业资格证号、安全制度条款等，部分文档以表格形式呈现申请材料与档案内容。

## 这些特征在「文档解析与分块」这一环带来什么约束
每日更新的数据要求解析流程具备较高的时效性，避免因解析延迟影响审批进度。结构化的文档与表格内容要求分块规则需保留业务字段的完整性，不能将跨业务模块的内容合并为单一分块。大体积的车辆技术档案与多页申请材料会增加解析耗时，需适配单文件的处理能力。同时，解析错误会直接导致政策问答的置信度下降，引发许可审批失误，因此需保证分块的准确性与一致性。

## 配置怎么定
本文适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配道路运输许可文档的字段长度，避免拆分跨业务模块的内容 |
| `chunkSplitter` | 按段落+自定义分隔符 | 适配包含表格、申请单的文档，按换行和许可申请的字段分隔符拆分 |
| `customPdfParse` | 开启结构化解析 | 提取车辆技术档案、从业资格材料中的表格字段，避免内容混乱 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 适配单份企业提交的多页许可申请材料大小 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对10余MB的Word文档解析耗时，避免超时失败 |
| `chunkSettingMode` | 手动模式 | 针对道路运输文档的结构化特征自定义分块规则 |

## 容易做错的三处
- 上传Excel格式的经营许可申请表格后，单条知识库条目合并了多行内容。现象是检索时出现跨申请单的冗余信息，原因是未配置自定义分隔符匹配Excel单行的换行规则。
- 上传10余MB的Word格式车辆技术档案时，解析任务超时失败。现象是界面显示解析超时状态，原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数至适配大文件的时长。
- 上传CSV格式的从业人员数据库文件时无法完成解析。现象是文件上传后无解析结果，原因是未确认支持的文件类型覆盖范围。

## 怎么确认配好了
- 上传单份10MB左右的Word格式车辆技术档案，检查解析耗时是否符合预期，未出现超时提示。
- 上传Excel格式的经营许可申请表格，检查分块结果是否按单行内容生成独立条目。
- 开启结构化解析开关，验证车辆技术档案中的表格字段是否被正确提取为独立分块。
- 测试检索某条驾驶员从业资格信息，确认检索结果未出现跨业务模块的冗余内容。
