# 道路运输经营许可的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来源于道路运政管理系统、全国道路运输车辆动态信息公共服务平台及车辆和从业人员数据库，更新频率为每日。日常处理的文档包含经营许可申请材料、车辆技术档案、驾驶员从业资格材料、安全生产管理制度文件、正式道路运输经营许可证件。数据字段涵盖经营主体基本信息、车辆技术参数、从业人员资质等级、安全管理制度条款、许可有效期限等，采用政务服务标准格式，无自定义单位或特殊字段格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据每日更新的要求，需确保模型接入链路支持实时同步政务系统数据，避免使用过期缓存内容。政务文档字段分散且关联度高，需保证模型能准确关联不同文档间的资质、许可信息，防止出现信息割裂。数据来源为政务系统，需保证接入链路的合规性，不得泄露敏感字段。日常处理的文档包含交通运输专业术语，需模型具备对专业表述的准确理解能力，避免产生歧义。每日更新的数据量需适配模型的上下文处理上限，防止因数据过载导致调用失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配政务文档的批量关联查询，避免因上下文不足丢失许可申请与资质材料的关联信息 |
| `maxTokens` | 4000 token | 匹配单条政务文档的平均长度，确保完整输出政策依据问答的完整结论 |
| `quoteMaxToken` | 2000 token | 限制引用文本的长度，保证引用的道路运输法规、许可条款清晰可读，不冗余 |
| `temperature` | 0.1–0.3 | 降低回答随机性，确保政策依据的表述准确匹配官方规范，避免出现歧义性内容 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写合规节点 | 适配政务系统的网络访问要求，确保数据传输链路合规 |
| `toolChoice` | auto | 允许模型自动选择调用工具，适配多文档关联查询的场景 |

## 容易做错的三处
- 调用时返回「无可用渠道」报错，request id包含20240911开头的标识。原因是未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`参数，导致模型调用链路中断。
- 问答结果仅返回部分政策条款，未关联完整的经营许可申请要求。原因是`maxContext`取值过低，未加载足够的关联文档，导致上下文信息缺失。
- 部署源码版本的微信项目时，无法连接docker部署的FastGPT实例。原因是未正确配置容器间的网络互通规则，导致服务访问链路不通。

## 怎么确认配好了
- 调用模型测试接口，输入「道路运输经营许可的申请材料要求」，检查返回结果中是否包含经营许可申请、车辆技术档案等对应文档的关联信息。
- 查看FastGPT v4.17.0版本的模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`参数已正确加载，无调用失败的报错记录。
- 模拟每日数据更新后的查询请求，验证模型是否能实时获取最新的车辆和从业人员资质信息。
- 调整`temperature`参数至0.2，检查政策依据的回答是否保持官方表述的一致性，无明显偏差。
