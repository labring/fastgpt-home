# 部门决算与财务报告的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来自预算管理一体化系统、国库集中支付系统、会计核算系统、资产管理系统，更新频率为年度更新。日常文档包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告，整体结构以财政统一规范的标准化字段为主，包含收支、资产负债、预算执行差异说明等核心模块，字段与单位严格遵循财政部门统一要求，无自定义非标准统计项。

## 这些特征在「模型接入与配置」这一环带来什么约束
年度更新的特性要求知识库同步周期与财政决算年度保持一致，避免使用高频更新的数据源配置。多系统来源的数据需整合跨维度上下文，模型接入时需适配多系统数据的字段对齐逻辑，确保模型能正确关联不同系统的决算信息。标准化的报表与说明文档结构，要求上下文窗口需预留足够长度以承载完整报表内容，避免因上下文不足导致的信息缺失。政策依据问答的高准确性需求，需限制模型生成的随意性，同时确保工具调用时能准确匹配财政政策条款与决算数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配部门决算完整报表与说明的长文本上下文需求，覆盖多系统整合的全部核心数据 |
| `maxTokens` | 2000–3000 token | 满足政策条款解释与差异说明的完整输出长度，避免截断关键结论与依据 |
| `quoteMaxToken` | 4000 token | 锁定来自决算文档的引用内容长度，确保引用数据的完整性与准确性 |
| `temperature` | 0.1–0.3 | 适配政策问答的高准确性需求，降低生成内容的随机性，避免出现与政策不符的表述 |
| `AIPROXY_API_ENDPOINT` | 按接入平台提供的官方地址填写 | 确保模型请求的路由正确，适配多密钥负载均衡的业务场景 |
| `toolChoice` | auto | 支持自动识别政策依据与数据校验的工具调用需求，匹配业务场景的工具调用逻辑 |

## 容易做错的三处
- 现象：模型调用返回429状态码，或请求被平台触发限流。原因：未配置多API密钥负载均衡，单密钥的请求频率超出平台限制，未通过多密钥提升并发处理能力。
- 现象：接入第三方模型平台时弹出认证失败提示。原因：未正确填写`AIPROXY_API_TOKEN`与对应平台的接入密钥，或`AIPROXY_API_ENDPOINT`配置的地址存在格式错误。
- 现象：生成的政策依据与决算数据无法对应。原因：`maxContext`取值过小，未加载完整的决算说明与政策文档上下文，导致模型无法关联正确的依据信息。

## 怎么确认配好了
- 发起包含部门决算核心字段的测试查询，核对模型返回的政策依据与官方文档内容是否一致。
- 配置多API密钥后，查看FastGPT v4.17.0的请求日志，确认不同密钥被交替调用，无单密钥持续占用的情况。
- 检查模型输出的引用片段，确认引用内容未被异常截断，符合`quoteMaxToken`的配置要求。
- 调整`temperature`参数后，验证相同测试查询的输出结果无明显随机性偏差，符合业务准确性需求。
