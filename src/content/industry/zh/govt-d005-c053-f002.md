# 部门预算编制的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知。日常产出的文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等。数据更新节奏为年度周期，仅在新一年预算编制启动时批量更新存量数据与新增政策文件。文档结构多为结构化表格与政策条文混合，字段包含项目编码、经费额度、绩效指标、编制单位等，无统一跨部门格式标准。

## 这些特征在「向量模型与索引」这一环带来什么约束
年度更新的批量数据与政策条文混合结构，要求索引系统支持周期性全量重索引与增量更新结合的模式。结构化字段与非结构化政策文本并存，需要同时适配结构化数值字段与非结构化政策文本的语义编码，避免单一模型适配导致的信息丢失。跨部门文档格式不统一，要求分块策略适配不同文档长度，避免长文本截断导致的政策条款断裂。数据量随预算层级扩大而增长，需限制单批次索引的资源占用，防止系统过载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配部门预算文档中政策条文与表格混合的长度，避免截断关键条款 |
| 重叠长度 | 100–150 字符 | 保留跨分块的上下文关联，防止政策条款被分块割裂 |
| `maxToken` | 4096 token | 匹配bge-m3模型及FastGPT v4.17.0版本的输入上限，适配长文本政策文件的语义编码 |
| `defaultToken` | 200 token | 控制单条检索结果的返回长度，避免上下文过载 |
| 相似度阈值 | 0.72–0.78 按实测标定 | 区分政策条文的语义相关性，过滤低匹配度的无关文档 |
| 单次搜索上限 | 前 8 条 | 适配预算编制审核的多参考来源需求，避免过多结果干扰判断 |

## 容易做错的三处
- 现象：检索结果中仅返回向量数据，无原始文档内容。原因：未配置原始文档与分块的映射存储，仅将向量嵌入存入数据库，未保留源文件路径、分块位置等关联信息。
- 现象：使用bge-m3模型时检索得分普遍偏高。原因：未针对预算文档的结构化表格做格式预处理，语义编码时混入了无意义的表格分隔字符，导致相似度计算异常。
- 现象：索引任务持续处于运行状态但无数据生成。原因：未设置合理的分块长度上限，超长文档的分块处理超时，导致索引流程无法推进。

## 怎么确认配好了
- 检查向量数据库存储内容，确认同时存在向量嵌入与原始分块的元数据，包含源文件路径、分块起始位置等信息。
- 导入一份典型的财政部预算编制通知文档，执行语义检索测试，核对返回结果的相似度得分是否在预设区间内。
- 触发一次增量索引任务，查看任务日志是否在`maxToken`限制内完成分块编码，无截断类报错。
- 验证年度批量更新任务的触发逻辑，确认仅在预算编制周期启动时执行全量重索引，无异常重复执行。
