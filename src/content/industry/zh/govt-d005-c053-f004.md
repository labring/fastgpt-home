# 部门预算编制的政策与制度依据问答：工作流编排

## 这个品类的数据长什么样
本品类数据主要来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部年度预算编制通知，更新频率为年度。日常处理的文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等，字段多涉及预算科目编码、人员编制数、项目支出额度、绩效指标值等，无统一固定单位，需结合具体业务场景匹配。

## 这些特征在「工作流编排」这一环带来什么约束
年度更新的特性要求工作流需适配年度周期内的固定节点触发，避免重复或遗漏流程。多源数据的整合需求，要求工作流需支持对接不同系统的接口，统一数据格式。文档类型多样且字段复杂，要求工作流需能识别不同文档的结构，提取对应字段用于政策匹配。同时，数据来源的权威性要求工作流需对输入数据的合规性做初步校验，避免无效内容进入问答环节。

## 配置怎么定
FastGPT v4.17.0 版本下的配置逻辑适用于本场景。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` 引用范围 | 仅绑定当前工作流节点输出 | 防止跨节点无关数据干扰政策问答的准确性 |
| `nodeId` 触发顺序 | 按数据预处理→政策匹配→结果输出 | 符合预算编制审核的常规逻辑 |
| 单次对话上下文上限 | 8000–12000 token | 匹配部门预算文档的平均长度，避免超出大模型限制 |
| 工作流超时阈值 | 600 秒 | 适配多源数据拉取和文档解析的耗时需求 |
| 最大召回结果数 | 前 10 条 | 平衡问答的全面性和响应速度 |
| 文档预处理开关 | 开启分段截取 | 避免大型预算文档超出上下文长度导致报错 |

## 容易做错的三处
- 工作流执行后展示多个子节点的AI对话结果：原因是未在工作流中配置结果聚合节点，导致各子节点的输出直接暴露。
- 上传超过12000字符的预算文档时返回400错误：原因是未在工作流中开启文档预处理的分段截取功能，未对超出上下文长度的内容进行处理。
- 配置`variables`时仅绑定模型名称，未设置MaxToken、温度等参数：原因是未在模型节点的配置面板中补充对应参数，仅引用变量名未关联具体设置。

## 怎么确认配好了
- 触发工作流后，检查输出面板仅包含最后一个AI节点的结果，无中间节点的冗余对话内容。
- 上传超过12000字符的部门预算草案文档，确认工作流可正常解析并返回政策匹配结果，无400报错。
- 调整`variables`的引用范围为跨节点，验证后续节点无法调用无关节点的输出，确认范围限制生效。
- 通过`nodeId`修改节点触发顺序，模拟跳过数据预处理环节，确认工作流会触发对应异常提示。
