# 部门预算编制的政策与制度依据问答：工具调用与插件

本页面基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类的日常业务文档包含部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等，数据来源为预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知。数据更新频率为年度，仅在新年度预算编制周期内完成全量更新。文档结构包含结构化表格与政策条文，字段涵盖单位编码、人员编制数、项目预算额度、绩效目标等，单位包含元、万元、人等。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据来源涉及多个内部系统与官方政策文件，工具调用需适配多数据源对接需求。年度更新频率决定知识库无需高频同步，仅需在编制周期前完成全量更新即可。日常文档包含结构化表格内容，工具调用需配置专用解析插件提取精准字段。政策与预算数据的强关联要求工具调用需同时覆盖知识库检索与实时数据查询，且需保障召回信息的准确性，避免因信息不全导致预算审核不通过。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 支持自动匹配工具调用与直接问答，适配政策依据查询和预算数据检索的混合需求 |
| 知识库召回上限 | 前8条 | 部门预算相关文档规模适中，过多会超出上下文承载能力 |
| `functionCall` | 开启 | 需要调用专用工具获取预算管理一体化系统中的实时编制数据 |
| 结构化文档解析开关 | 开启 | 日常业务文档包含人员经费测算表、项目申报书等结构化内容，需提取精准字段 |
| 上下文窗口长度 | 8000–12000 token | 需同时承载政策条文、预算报表数据与用户问题，保障信息完整 |

## 容易做错的三处
- 现象：调用知识库时返回结果条数不足，无法覆盖全部政策依据。原因：知识库召回上限设置过低，未匹配部门预算文档的实际数量。
- 现象：上传的pdf格式预算文档无法正确解析为可用文本。原因：未配置pdf转结构化文本的插件，或未开启对应解析规则。
- 现象：并发调用时出现请求超时或被拒绝，或无法调用本地部署的大模型。原因：未调整并发限制参数，或未配置本地大模型调用的网络代理设置。

## 怎么确认配好了
- 发起包含政策条文查询和预算数据请求的测试问题，查看工具调用日志确认`toolChoice`自动触发了对应工具。
- 上传一份部门预算草案文档，检查解析结果是否提取了人员编制数、项目额度等核心字段。
- 发起批量测试请求，确认并发调用时无明显超时或报错。
- 查看知识库召回结果条数，确认符合预设的召回上限。
