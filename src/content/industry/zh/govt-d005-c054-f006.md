# 防汛防灾与应急值守的政策与制度依据问答：引用来源与溯源

本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的日常文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单。数据主要来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控，更新频率为每日。文档字段多包含雨情水情数据、险情等级、物资调拨数量、避险转移人员信息，单位涉及毫米、立方米、人数等，部分文档需关联实时监测数据与历史处置记录。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据特征对引用溯源环节带来多重约束。多源异构的数据来源要求溯源环节可关联气象、水文、应急指挥等不同系统的元数据，避免溯源范围受限。每日更新的频率要求溯源需快速匹配最新发布的政策与制度依据版本，确保引用内容时效性。文档包含雨情水情、物资数量等带单位的具体数值，溯源需精准绑定对应字段的原始出处，避免数值与来源脱节。应急处置的短节奏要求溯源环节需控制耗时，平衡溯源准确性与回复生成速度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1500 token | 该品类常用知识库切块为5000token，该取值可完整保留政策条文与实时监测数据的核心内容，避免截断关键溯源信息 |
| `responseData` | 开启来源展示 | 应急值守需明确引用的政策与制度依据出处，便于快速核对合规性 |
| `detail` | 完整元数据 | 需展示来源文档的发布机构、更新时间、关联的水文/气象监测字段，满足精准溯源要求 |
| 单次召回来源数 | 前5条 | 控制溯源信息总量，避免过多内容占用回复空间，适配短节奏的应急处置场景 |
| 来源展示格式 | 标注系统名称+文档标题 | 符合该品类数据来源分散的特征，便于快速定位对应系统的原始记录 |

## 容易做错的三处
- 现象：调用知识库问答插件时出现`quote type error`报错。原因：输入的引用变量格式不符合系统要求，未正确绑定对应来源文档的元数据字段。
- 现象：回复中未展示知识库的引用来源。原因：未开启`responseData`对应的来源展示开关，或配置的`detail`参数未启用元数据返回。
- 现象：设置了`quoteMaxToken`为1500token，但仍召回超出长度的切块内容。原因：知识库切块设置为5000token，召回的切块未经过截断处理，或系统未按配置的`quoteMaxToken`对召回内容进行二次校验。

## 怎么确认配好了
- 发起包含防汛政策关键词的测试提问，检查回复中是否附带了可溯源的来源信息。
- 查看返回结果的元数据字段，确认包含来源系统、发布时间等必要信息，验证`detail`参数配置生效。
- 调整`quoteMaxToken`的取值，测试不同长度的召回内容，确认系统按配置限制引用内容的总token数。
- 输入格式错误的引用变量，验证是否触发`quote type error`报错提示，确认错误处理配置生效。
