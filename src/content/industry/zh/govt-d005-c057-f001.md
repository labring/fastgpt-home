# 食品安全监督抽检的政策与制度依据问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据围绕食品监督抽检全流程生成，日常文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。数据来源为食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS及食品生产经营者台账。数据更新频率为月度，核心字段包含样品编号、抽检批次、不合格项目、处置进度等，所有字段均采用官方业务系统的标准单位，无额外自定义统计单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
月度更新的频率要求接口的知识库同步机制适配低频批量同步，避免高频调用占用资源。多来源的数据格式差异要求接口需支持标准化参数映射，将抽检监测系统、LIMS等不同系统的文档统一转换为可索引格式。政策与制度依据问答的场景要求接口返回的结果需关联对应文档来源，便于监管人员核实原始依据。核心字段的固定性要求接口参数需严格匹配抽检相关的标准字段，避免因字段不匹配导致检索失效。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {自定义API密钥}` | 符合HTTP接口鉴权标准，保障外部系统调用的安全性，适配监管业务的权限管控要求 |
| `variables` | 按实际业务场景填充，例如`{"sample_type": "预包装食品", "inspection_batch": "202403"}` | 传递业务上下文参数，缩小政策依据问答的检索范围，精准匹配抽检相关的政策与文档 |
| `responseData` | `{"include_source": true, "source_fields": ["sample_id", "document_title"]}` | 返回关联的知识库文档信息，便于调用方追溯原始政策与抽检依据 |
| 单次搜索上限 | 前5条 | 匹配监管人员查阅少量核心依据的使用习惯，避免过多信息干扰判断 |
| 最大上下文长度 | 800–1200字符 | 适配本品类政策文本与抽检文档的常规长度，避免上下文溢出影响问答准确性 |
| 接口超时时间 | 600秒 | 等待批量文档检索与拼接完成，适配月度更新的数据处理节奏 |

## 容易做错的三处
- 调用对话接口后未返回关联的知识库ID或文档信息。原因是未在`responseData`参数中开启来源返回配置，导致接口仅返回问答结果，未携带依据出处。
- 编排数据库连接时出现`Failed to connect to jyfkk:1433 - 38BBDDC3AF7F0000`报错。原因是未正确配置外部数据库的访问地址与端口，或未开放对应网络权限，无法连接检验机构LIMS系统的数据库。
- 接口检索结果条数与预期不符。原因是未设置合理的单次搜索上限参数，或未传递正确的业务变量缩小检索范围，导致检索范围覆盖无关的政策文档。

## 怎么确认配好了
- 发起包含抽检批次参数的测试调用，检查返回的问答结果是否关联对应抽检计划或检验报告的文档信息。
- 配置`Authorization`参数为合法的API密钥，发起调用，确认接口返回状态码为200且无鉴权失败提示。
- 调整单次搜索上限的设置值，发起两次测试调用，确认返回的依据文档条数与设置值一致。
- 验证外部数据源的同步配置，确认月度更新的文档已正确同步至FastGPT知识库，可通过检索命中。
