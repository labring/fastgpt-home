# 勘察设计的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
勘察设计领域的政策与制度依据数据，主要来源于住建部、各省市住房和城乡建设主管部门的官方公开文件，以及行业协会发布的规范性指引。数据更新节奏随新政策出台、旧政策修订同步调整，无固定更新周期。单份文档通常包含政策文号、发布单位、生效日期、条款内容、适用场景等字段，条款按条、项层级拆分，部分文件附带工程勘察设计资质标准、审查要点等附件。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
勘察设计政策文档的长文本、层级化结构，要求多轮对话中需保留足够上下文以关联前后提及的政策条款与文号。政策生效日期、适用区域的差异，要求提示词需明确限定查询范围，避免跨时段、跨区域政策混淆。单份政策的条款拆分特性，要求对话过程中需精准定位用户提及的具体条款层级，防止检索结果泛化。同时，官方政策的权威性要求召回内容需严格匹配原文表述，提示词需明确禁止对政策内容进行主观改写。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定项目专属ID | 区分不同勘察设计项目的政策对话上下文，避免跨项目信息混淆 |
| `messages` | 保留前5轮对话内容 | 平衡上下文负载与多轮追问的语义连贯性，适配政策查询的递进式提问 |
| `variables` | 预设政策生效时间、适用区域变量 | 限定查询范围，避免跨时段、跨区域政策混淆 |
| 单次召回上限 | 前10条 | 勘察设计政策单份文档条款较多，召回过多会超出上下文窗口，过少则无法覆盖相关条款 |
| 上下文窗口长度 | 8000–12000 token | 存储多轮对话历史与召回的政策条款内容，适配长文本政策文档 |
| 引用内容展示格式 | 带文号与条款号 | 匹配勘察设计政策的文档层级结构，便于用户核对政策原文的具体位置 |

## 容易做错的三处
- 现象：将单次召回上限调整为2000或3000后，大模型生成的回答未附带任何政策引用内容，虽可在后台查看召回的政策段落。原因：未在提示词中明确要求绑定召回内容与回答，或上下文窗口超出承载上限导致召回内容被截断。
- 现象：检索返回的政策段落附带内部ID字段，被一并发送给大模型。原因：未在提示词中过滤非必要字段，或知识库分块时保留了段落ID。
- 现象：对话框无法显示政策文件中的附件图片。原因：未配置知识库图片资源的托管路径，或图片链接未开放公网访问权限。

## 怎么确认配好了
- 发起多轮对话，连续追问同一政策的不同条款，检查上下文是否保留前期提及的政策文号与条款。
- 调整单次召回上限为15条，查看大模型回答是否附带对应数量的政策引用内容。
- 检查对话界面的引用内容，确认仅展示政策文号、条款号与原文内容，无额外字段。
- 输入预设生效时间以外的政策查询，检查检索结果是否符合限定范围。
