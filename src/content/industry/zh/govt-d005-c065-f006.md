# 勘察设计的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
勘察设计领域的政策与制度依据数据，主要来源于住建部、各省级住建厅及地方住建主管部门的官方公开文件。数据更新节奏随政策出台同步调整，新政策发布后1-3个工作日内完成知识库同步。文档结构为标准红头文件格式，包含文件编号、发布单位、生效日期、章节条款等核心字段，单篇文档长度从数百字到数万字不等，部分行业规范类文件会附带技术参数、计算标准等细节内容。

## 这些特征在「引用来源与溯源」这一环带来什么约束
勘察设计政策文件的长文本特性，要求引用溯源环节需支持完整读取单篇核心条款，避免截断关键依据；多来源的政策可能存在新旧版本冲突，需在溯源时明确标注文件生效时间与文号，确保引用的时效性与准确性；字段包含技术参数与行政条款两类内容，需准确区分并提取对应元数据，避免溯源信息混淆；高频更新的政策要求知识库同步机制及时，否则会出现引用旧版失效文件的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 8000–12000 token | 勘察设计政策文件单篇核心条款长度多在数千字，该区间可完整覆盖常用引用范围 |
| `responseData` | 开启原文直接返回 | 满足用户直接输出知识库原文、不加修饰的需求，确保溯源内容的原始性 |
| `detail` | 开启文号与生效日期展示 | 提取文件编号、发布时间等字段，增强溯源信息的可信度与可追溯性 |
| 多知识库关联 | 绑定3个以内政策类知识库 | 适配勘察设计领域多层级政策的查询需求，避免召回无关内容 |
| 上下文窗口 | 15000–20000 token | 抵消大模型处理长文本的延迟，适配政策文件的长上下文检索场景 |

## 容易做错的三处
- 现象：AI回复仅包含大模型改写的内容，未附带知识库原文。原因：未开启`responseData`对应的原文返回设置，系统默认使用大模型生成的摘要内容。
- 现象：单次查询仅返回单篇政策文件的结果，无法覆盖多维度政策依据。原因：未配置多知识库关联，仅绑定了单个政策知识库。
- 现象：检索请求超时或返回内容被强制截断。原因：`quoteMaxToken`设置超出系统处理上限，导致请求无法正常完成。

## 怎么确认配好了
- 发起包含具体政策文号的咨询，查看回复末尾是否附带对应文件的编号与生效日期。
- 对比回复内容与知识库原文，确认无额外改写或润色，仅保留原始文本内容。
- 发起跨部门政策的咨询，验证返回结果同时来自住建部与地方住建厅的知识库。
- 调整`quoteMaxToken`参数，观察返回内容的长度是否随配置发生对应变化。
