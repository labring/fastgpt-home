# 勘察设计的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
勘察设计领域的政策与制度依据数据，主要来源于住建部、各省市住建主管部门及行业协会发布的正式规范、审批文件、监管要求。数据更新随新政策发布同步进行，无固定周期。文档多为带文号、发布日期、生效条款的结构化文本，部分包含项目适用范围、资质要求、审批流程等字段，单位多以“条”“款”“项”或文号年份、地域代码标识，部分规范附带设计图纸类附件。

## 这些特征在「模型接入与配置」这一环带来什么约束
政策文档的结构化特征要求召回结果需精准匹配条款层级，避免无关内容混入，影响回答准确性。非固定更新节奏要求知识库同步更新时，需校验模型接入的数据源一致性，确保调用的是最新版本文件。部分规范包含附图类附件，要求配置支持视觉内容解析。官方文件的权威性要求模型输出需严格引用原文片段，需配置合适的上下文与引用限制，避免生成无依据的解读内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，表格如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 勘察设计政策文档多为长文本，需容纳足够的原文片段以支撑精准回答 |
| `maxTokens` | 2000–3000 token | 单轮回答需覆盖完整政策条款解读，避免截断关键内容 |
| `quoteMaxToken` | 1500 字符 | 要求严格引用政策原文片段，限制引用内容的总长度 |
| `temperature` | 0.1–0.3 | 政策解读需保持严谨，降低随机性以确保内容符合官方表述 |
| `vision` | 开启 | 部分设计规范包含附图，需支持图片内容解析 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写实际接口地址 | 适配模型调用的网络路径要求 |
| `AIPROXY_API_TOKEN` | 填写对应模型的访问密钥 | 完成模型接入的身份验证 |

## 容易做错的三处
- 现象：聊天界面显示的模型与配置的模型不一致，或提示API密钥无效。原因：未正确填写`AIPROXY_API_TOKEN`，或密钥权限与配置的模型不匹配。
- 现象：回答未引用政策原文，或引用内容超出条款范围。原因：未配置`quoteMaxToken`或取值过大，导致模型生成无依据的内容。
- 现象：包含附图的政策文档无法被正确解析。原因：未开启`vision`配置，或未部署支持图片解码的模型依赖。

## 怎么确认配好了
- 进入模型配置页面，核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`与部署文档中的参数一致。
- 发起包含具体政策条款的测试提问，检查回答是否引用了知识库中的原文片段，且引用长度符合预期。
- 上传包含附图的政策文档，验证模型是否能正确识别并解读图片中的内容。
- 调整`temperature`参数后发起测试，确认回答的严谨性随参数变化符合预期。
