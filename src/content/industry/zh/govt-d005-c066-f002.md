## 这些特征在「向量模型与索引」这一环带来什么约束
化工新材料政策文档的长短差异、结构化字段特征与非固定更新节奏，会对向量模型与索引环节带来多重约束。长政策文档存在数万字的完整条款，分块时需兼顾语义完整性，避免拆分后丢失跨段落的政策逻辑。文档包含文号、生效日期等结构化字段，索引时需保留字段关联规则，防止检索时混淆同领域不同文号的政策内容。部分政策附带附件数据，需单独拆分索引并与主文档建立关联，确保检索时可同步返回相关附件。非固定的更新节奏要求支持增量索引模式，减少全量重建的资源消耗。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配化工新材料政策文档的单段语义完整性，避免跨条款拆分导致语义断裂 |
| 重叠长度 | 100–200 字符 | 弥补分块后的语义断层，确保长政策条款的上下文连贯性 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关政策内容，聚焦核心合规依据 |
| 单次搜索上限 | 前 10 条 | 控制返回结果的数量，避免上下文过载影响模型推理 |
| `maxToken` | 4096 token | 适配主流向量模型的输入长度限制，确保索引时的处理稳定性 |
| `defaultToken` | 按实测标定 | 适配本地部署的向量模型参数，匹配硬件资源与索引精度需求 |

## 容易做错的三处
- 现象：索引后检索结果中出现无关的旧版政策文号，原因：未在索引环节绑定政策文号字段，导致不同批次的政策内容被混淆匹配。
- 现象：调用索引工具时出现token超限报错，状态码返回413，原因：未设置`maxToken`参数，未限制单条分块的token输入长度。
- 现象：本地部署ollama时检索结果条数不足，无法匹配到完整政策依据，原因：单次搜索上限设置过低，且未开启关联附件的索引配置。

## 怎么确认配好了
- 上传单篇化工新材料政策文档，查看分块预览界面，确认分块长度符合设定区间，无过度拆分或过长分块。
- 输入测试问题，比如“化工新材料的准入标准有哪些”，查看检索结果的字段是否包含政策文号与发布日期，确认结构化字段关联生效。
- 上传更新后的政策文件，查看索引任务的增量更新状态，确认无需全量重建即可完成同步。
- 测试调用向量索引接口，确认返回的分块token数未超过`maxToken`设定值，无报错返回。
