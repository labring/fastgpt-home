# 医药流通的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
医药流通领域的政策与制度依据数据，主要来源于国家药品监督管理局、商务部、各省市医保局及行业主管部门的官方公告、规范性文件。数据更新节奏随政策出台动态调整，常规同步周期为每周一次。单份文档包含文号、发布单位、发布日期、条款内容、适用场景等固定字段，条款内容按章节编号拆分，单位统一采用中文规范表述，如文号格式为国药监发〔年份〕序号，日期采用YYYY-MM-DD标准格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
官方发布的政策文档存在明确的文号、发布单位与日期标识，溯源环节需完整提取这些字段作为验证依据，避免仅展示正文内容无法追溯合规性。动态更新的政策要求系统需配置按发布日期筛选最新版本的规则，防止返回过期失效的政策条款。按章节拆分的文档结构，要求引用时需精准匹配具体条款编号，避免笼统引用整份文件导致信息范围模糊。同时，官方数据源的域名固定，需配置仅收录指定官方域名下的文档，确保来源权威性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 适配单份医药政策文档的平均内容长度 |
| 知识库最大引用 | 前3–5条 | 医药流通政策文档的权威来源集中，过多引用会增加阅读负担 |
| 最大响应tokens | 2000–3000 token | 预留足够空间展示政策条款与完整溯源信息 |
| `quoteMaxToken` | 1500–2000 字符 | 限定单条引用的内容范围，避免截断关键政策条款 |
| `detail` | 开启 | 强制返回完整的文档元数据，包括文号与发布日期 |
| `responseData` | 包含来源URL | 确保溯源链接指向官方数据源，符合合规要求 |

## 容易做错的三处
- 现象：调用API返回的结果强制携带引用内容，无法通过配置关闭。原因：未将`responseData`配置为仅返回纯问答正文，或误开启了全局强制引用展示的开关。
- 现象：配置知识库最大引用参数后，召回的政策文档条数不符合预期。原因：参数取值超出了当前数据源的有效文档数量，或未按政策文档的发布日期进行排序筛选。
- 现象：引用内容未显示政策文号与发布日期，溯源信息不完整。原因：未开启`detail`配置，导致未返回文档的元数据字段。

## 怎么确认配好了
- 发起一条针对具体医药流通政策的查询，检查返回结果中是否包含完整的来源URL与文档元数据。
- 调整`quoteMaxToken`的取值，验证单条引用的内容长度是否符合预期设定。
- 调用API接口，检查返回结果是否可通过配置选择是否携带引用内容。
- 查看知识库的数据源配置，确认仅收录了官方指定域名下的政策文档。
