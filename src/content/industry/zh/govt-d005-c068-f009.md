# 医药流通的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
医药流通领域的政策数据主要来自国家药品监督管理局、商务部、各省市药品监管部门的官方公开公告，随新监管政策出台、流通规范调整不定期更新。文档多为多章节正式公文，包含发文编号、发布主体、生效日期、适用场景条款、罚则、附件清单等，字段包含政策唯一标识、适用区域、执行周期、合规要求条目，单位多为序号、金额元、标准日期格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
官方政策数据的权威性要求接入模型需具备合规内容的准确输出能力，长文本公文结构要求模型需支持长上下文处理以完整保留政策条款间的关联关系；不定期更新的特性要求知识库同步配置需适配灵活的触发机制，适配政策临时发布的更新需求；多字段的结构化文档要求检索环节需精准匹配政策标识、适用区域等字段，避免跨场景的政策误匹配。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 医药流通政策文档多为长文本，需完整保留上下文关联以准确关联政策条款 |
| `maxTokens` | 2000–3000 token | 政策问答需完整输出条款内容，避免截断关键合规信息 |
| `quoteMaxToken` | 1500 字符 | 需精准引用政策原文片段，控制单条引用长度以保障回答清晰度 |
| `temperature` | 0.1–0.3 | 政策问答需严谨准确，降低随机性输出以避免合规风险 |
| `AIPROXY_API_ENDPOINT` | 本地化部署的模型接口地址 | 保障政策数据的本地处理符合监管合规要求 |
| `AIPROXY_API_TOKEN` | 自定义的安全访问令牌 | 限制未授权的接口访问，保障政策数据的访问安全 |

## 容易做错的三处
- 现象：调用模型接口返回401 unauthorized报错，原因：未正确配置`AIPROXY_API_TOKEN`或令牌权限未覆盖当前访问场景。
- 现象：工作流中AI模型下拉列表为空，原因：未完成模型接入配置或接口地址填写存在格式错误。
- 现象：模型输出的政策内容出现条款截断，原因：`maxTokens`取值过低，未覆盖完整政策条款的长度要求。

## 怎么确认配好了
- 核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容，确认与本地部署的模型接口参数一致。
- 上传单篇医药流通政策文档，发起针对性问答测试，查看模型是否能准确返回对应政策条款。
- 调整`temperature`参数后发起多次测试，确认输出内容的严谨性符合预期。
- 触发知识库同步操作，查看同步日志无异常报错，验证更新流程正常。
