# 危化品储运的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
危化品储运的政策与制度依据数据，主要来自应急管理部、交通运输部、生态环境部发布的官方规范与监管细则，更新节奏随新政策出台、监管要求调整同步更新。单篇文档多包含文号、发布主体、生效日期、条款分类、适用储运场景、违规判定标准等字段，部分文档附带存储量阈值、运输距离限制等量化指标，文档结构层级清晰，专业术语密度较高。

## 这些特征在「向量模型与索引」这一环带来什么约束
危化品储运政策文档的生效日期字段要求索引支持按时间过滤检索范围，避免过期政策被召回；单篇文档字符数较高，需适配长文本分块逻辑以保留完整语义；文档中存在的量化指标，要求向量模型可准确编码数值类语义以保障检索精度；政策更新无固定周期，需支持增量索引构建以降低更新成本；专业术语密度较高，需确保向量模型对细分领域语义的编码能力达标。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 危化品储运政策单篇文档字符数较高，该长度可平衡语义完整性与检索精度 |
| 重叠长度 | 100–150 字符 | 避免跨分块的政策条款被割裂，确保检索时覆盖完整监管要求 |
| 相似度阈值 | 0.72–0.78 | 政策文本存在大量专业术语与固定表述，该区间可过滤低相关结果同时保留合规内容 |
| 单次搜索上限 | 前8条 | 危化品储运政策关联条款较多，该数量可覆盖主要监管场景 |
| maxToken | 8000 token | 政策文档分块后需整合多条款内容，该取值可承载足够检索结果 |
| defaultToken | 按实测标定 | 不同部署环境下的token消耗与模型负载存在差异，需结合实际情况调整 |

## 容易做错的三处
- 现象：检索返回了匹配的政策文档，但大语言模型输出“未找到相关内容”。原因：maxToken参数设置不足，导致检索到的文档片段未被完整纳入模型输入范围。
- 现象：索引构建过程中出现内存溢出报错。原因：分块长度设置过大，单分块字符数超出向量模型的编码上限。
- 现象：检索结果中低相关的过期政策占比过高。原因：未配置按生效日期过滤的检索规则，导致旧政策被优先召回。
