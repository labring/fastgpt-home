# 危化品储运的政策与制度依据问答：工作流编排

## 这个品类的数据长什么样
危化品储运的政策数据主要来自应急管理部危化品监管司、交通运输部发布的官方标准与公告，以及《危险化学品安全管理条例》《危险货物道路运输规则》等国家级法规。更新节奏为重大政策修订后1-2周内同步更新。文档结构按储运环节拆分，包含政策文号、发布主体、生效日期、适用场景、量化管控要求等字段，量化字段多采用吨、立方米、公里等单位。本文适配FastGPT v4.17.0版本的工作流编排功能。

## 这些特征在「工作流编排」这一环带来什么约束
因为政策数据带有明确的生效日期与文号，工作流需要加入时效性校验环节，避免调用过期政策内容。因为文档按储运环节细分，工作流需要配置分支判断节点，匹配不同场景的政策要求。因为数据来源为官方权威渠道，工作流需要配置可信数据源校验，过滤非官方内容。因为字段多为量化指标，工作流需要配置数值匹配规则，确保返回的管控要求与问题场景一致。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源配置 | 仅绑定应急管理部、交通运输部官方公开的危化品政策文档 | 匹配危化品储运政策的权威来源要求 |
| 分支触发规则 | 按仓储、道路运输、码头装卸拆分节点 | 对应政策文档按储运环节细分的结构 |
| 时效性校验 | 过滤生效日期早于当前日期的政策内容 | 避免调用过期政策文件 |
| 变量绑定 | 绑定`variables`中的政策文号、生效日期字段 | 匹配政策文档的结构化字段 |
| 单次搜索上限 | 前3条 | 对应单一场景的政策条目数量有限 |
| 上下文长度 | 800–1200 字符 | 适配单篇政策文档的核心内容长度 |

## 容易做错的三处
- 现象：工作流执行后返回“Access denied for us”类报错。原因：未配置数据库连接的可信数据源白名单，直接调用非官方危化品政策文档导致权限校验失败。
- 现象：全局变量在工具调用中未更新政策生效日期。原因：未在`variables`配置中开启变量同步开关，导致工作流节点无法读取最新的政策时间参数。
- 现象：分支节点未正确匹配储运场景。原因：未按政策文档的细分环节配置触发条件，导致分支判断逻辑与政策要求不符。

## 怎么确认配好了
- 运行工作流，输入特定储运场景的问题，核对返回结果的政策文号与生效日期是否与官方文档一致。
- 查看工作流日志，确认分支节点按输入的储运环节正确触发对应政策内容。
- 测试全局变量更新，在工具调用后查看`variables`中的政策参数是否同步更新。
- 检查数据源配置，确认仅包含官方授权的危化品政策文档链接。
