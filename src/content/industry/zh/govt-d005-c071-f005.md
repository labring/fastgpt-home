# 发电集团的政策与制度依据问答：工具调用与插件

## 这个品类的数据长什么样
发电集团的政策与制度依据数据来源包括国家能源局、国务院国资委发布的能源行业政策文件，以及集团总部及下属电厂的内部管理制度文档。更新节奏随政策正式发布、内部制度修订实时同步。文档结构通常包含文号、发布单位、生效日期、适用范围、核心条款等字段，条款按条、款、项层级划分，单篇文档长度从数千到数万字符不等，部分历史政策仅保留扫描件需先完成文字识别转换。

## 这些特征在「工具调用与插件」这一环带来什么约束
政策文档的层级化结构要求工具调用时需精准匹配条款编号与生效时间，避免返回过期或不适用的内容。多源数据的混合调用，需要插件配置不同的接口鉴权与访问权限，区分公开数据源与内部私有文档库。文档长度差异较大，工具调用时需限制单次返回的字符量与文档条数，防止上下文溢出。政策更新无固定周期，插件需支持手动触发或定时拉取最新政策文档，确保问答内容的时效性。

## 配置怎么定
本页面配置基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` 或指定政策解析专属工具 | 发电集团政策问答需固定调用政策解析能力，`auto`可自动匹配对应工具，指定工具可避免误调用其他无关功能 |
| `functionCall` | 开启，限制调用政策查询、条款解析两类插件 | 聚焦政策与制度依据问答场景，限制工具调用范围以提升结果准确性 |
| 单次返回文档条数 | 前3条 | 发电集团政策文档单篇长度较大，过多返回会占用上下文窗口，导致核心内容被截断 |
| 单次返回字符数 | 2000–3000 字符 | 政策条款单段内容较多，限制返回字符数可避免上下文溢出 |
| 上下文窗口限制 | 8000–12000 token | 适配大模型处理长文档的能力，避免因上下文过长导致生成失败 |
| 接口超时时间 | 30–60 秒 | 集团内部文档库接口存在内网延迟风险，超时时间需适配内网访问的平均响应时长 |
| 插件鉴权方式 | 按集团内网token鉴权 | 内部政策文档属于敏感信息，需通过专属鉴权方式确保非授权用户无法访问 |

## 容易做错的三处
- 现象：调用工具时触发了无关的代码执行或通用文档搜索插件，返回非政策相关内容。原因：未正确配置`toolChoice`参数，未限制工具调用范围，导致模型调用了未授权的功能。
- 现象：调用内部政策文档接口时返回403 Forbidden，或无法获取私有文档内容。原因：未使用集团内网专属的token鉴权方式，直接使用公开接口的鉴权规则，未匹配内部系统的校验逻辑。
- 现象：调用HTTP接口后无法解析响应中的Set-Cookie字段，导致后续接口调用鉴权失败。原因：未开启HTTP请求模块的会话Cookie自动存储与携带功能，仅完成单次接口调用未保留会话凭证，无法延续访问权限。

## 怎么确认配好了
- 发起一条包含具体政策文号的查询，检查工具调用是否返回对应条款的准确内容，确认鉴权配置与文档拉取功能生效。
- 查看工具调用日志，确认仅调用了政策查询、条款解析两类插件，无其他无关工具被触发，验证`toolChoice`与`functionCall`的配置效果。
- 手动触发一次政策文档同步，检查内部文档库的最新政策是否被成功拉取到问答知识库中，确认更新机制正常。
- 模拟接口延迟场景，确认工具调用在30–60秒内返回响应，未出现超时报错，验证超时时间配置合理。
