# 发电集团的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
发电集团的政策与制度依据数据主要来源于集团内部红头文件、上级能源主管部门的政策通知、集团规章制度汇编。数据更新节奏为上级政策发布后1-3天内完成同步，内部制度修订即时更新。文档结构包含文号、发布部门、生效日期、分章节条款等内容，字段包括政策编号、发布主体、适用范围、条款原文，章节号采用阿拉伯数字加小数点的格式，生效日期采用YYYY-MM-DD标准格式，单篇文档长度差异较大，部分汇编类文档总字数可达数十万。

## 这些特征在「模型接入与配置」这一环带来什么约束
发电集团政策数据的长文本特性要求模型接入配置需适配大上下文窗口，避免截断关键政策条款。数据时效性强的特点，要求配置中需设置合理的数据源同步周期，确保最新政策能及时被索引。结构化的字段设计，要求模型调用时需能准确提取政策文号、生效日期等元数据用于引用校验，同时需限制模型生成内容的随意性，避免偏离合规的政策依据。此外，发电集团的政策涉及安全合规要求，对模型输出的准确性有较高标准，需严格控制生成参数的取值范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 12000–16000 token | 适配发电集团政策文档的长文本特性，避免截断完整政策条款 |
| `temperature` | 0.1–0.3 | 政策问答需严谨合规，降低模型生成内容的随机性 |
| `quoteMaxToken` | 2000–3000 字符 | 确保返回结果中能完整引用政策原文，满足合规校验要求 |
| `maxTokens` | 4000–6000 token | 覆盖政策解答的完整逻辑，避免生成内容被中途截断 |
| `toolChoice` | auto | 允许模型自主判断是否调用文档检索工具，匹配精准的政策依据 |
| `AIPROXY_API_ENDPOINT` | 按部署的专属代理地址填写 | 符合集团数据安全规范，确保模型调用链路合规 |

本页面基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 现象为调用模型后返回的政策引用内容不完整，部分条款被截断。原因是未正确配置`quoteMaxToken`参数，导致系统自动截断了过长的政策原文。
- 现象为rerank模型调用后显存占用持续攀升，最终触发内存不足报错。原因是未对`maxContext`设置合理上限，长文本处理时占用过多显存资源。
- 现象为配置模型后无法正常发起调用，OneAPI页面显示无可用渠道。原因是未正确填写`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`参数，或密钥权限不符合集团安全要求。

## 怎么确认配好了
- 手动输入一条针对集团内部政策的查询，查看返回结果中是否包含完整的政策文号和生效日期。
- 查看模型调用日志，确认`maxContext`、`quoteMaxToken`和`temperature`的参数值与配置一致。
- 测试连续发起10次以上的查询，观察系统显存占用是否保持稳定，未出现持续攀升的情况。
- 验证数据源同步任务是否按配置周期自动执行，检查最新发布的政策文档是否已被成功索引。
