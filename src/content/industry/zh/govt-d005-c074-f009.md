# 国有资产管理公司的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
国有资产管理公司的政策与制度依据数据主要来源于国务院国资委、财政部发布的官方监管文件，以及公司内部制定的国有资产运营管理细则、风控合规手册。数据更新随国家新政策出台或内部制度修订调整，无固定周期，但核心监管文件与内部制度的更新频率不低于每年一次。单份文档通常包含发布文号、发布单位、生效日期、条款正文、适用主体、罚则说明等字段，部分关联文件会附带政策解读附件。

## 这些特征在「模型接入与配置」这一环带来什么约束
政策与制度依据文档结构规整但单份长度较长，且对内容准确性要求极高，因此模型接入时需适配长上下文处理能力，避免因上下文截断丢失关键条款。数据字段包含明确的生效日期与适用范围，模型需精准匹配对应场景的政策内容，因此需限制模型生成的随机性，同时调整上下文召回的匹配逻辑，优先匹配生效日期最新的政策内容。此外，政策文件更新无固定周期，需确保模型配置支持知识库的定期同步校验，避免调用过时的制度内容。本页面基于FastGPT v4.17.0版本配置说明编写。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单份政策文档的完整内容与关联文件拼接，避免关键条款被截断 |
| `maxTokens` | 4000–6000 token | 保证模型生成合规性问答的完整回复，覆盖政策解读、适用场景说明等内容 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保政策解读与原文条款一致，避免出现与制度依据不符的内容 |
| `quoteMaxToken` | 2000 token | 限制单条引用的文档片段长度，保证引用内容精准且便于用户核对 |
| `AIPROXY_API_ENDPOINT` | 按本地或云端部署的大模型服务实际访问地址填写 | 对接模型服务，确保请求路径正确 |
| `AIPROXY_API_TOKEN` | 按模型服务生成的访问密钥填写 | 验证模型服务的访问权限，保障调用安全 |

## 容易做错的三处
- 现象：调用模型后返回结果与政策原文不符，或出现未在制度中提及的自定义条款。原因：将`temperature`参数设置过高，导致模型生成内容偏离政策条款。
- 现象：配置`AIPROXY_API_ENDPOINT`后无法调用模型，页面提示连接超时或权限不足。原因：未正确填写模型服务的实际访问地址，或本地防火墙限制了请求端口，或`AIPROXY_API_TOKEN`配置错误。
- 现象：工作流中前一个AI模型的输出无法更新为空值，变量始终保留历史内容。原因：未在变量更新步骤中选择覆盖原值选项，或未触发变量刷新的执行节点。

## 怎么确认配好了
- 测试调用单份政策文档的问答请求，检查回复中是否包含文档中的关键条款内容。
- 查看模型调用日志，确认请求参数中的`maxContext`、`temperature`等配置项与预设值一致。
- 手动更新知识库中的政策文件后，发起测试调用，确认返回内容使用的是最新版本的制度依据。
- 使用配置的`AIPROXY_API_TOKEN`发起独立的模型请求，确认可正常获取模型响应。
