# 国有资本投资公司的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
数据来源包括国务院国资委官网发布的国有资本投资运营监管文件、各试点国有资本投资公司内部印发的业务管理制度、地方国资配套细则。更新节奏随上级国资监管文件发布频率调整，核心政策文件更新周期随监管要求动态调整。文档结构统一包含发文主体、文号、生效日期、适用层级、条款分类、合规要求等字段，单份文档长度从数百字到数万字不等，字段均为标准文本格式，无自定义非标字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
官方及内部政策文件的固定字段要求多轮对话需保留发文主体、生效日期等元数据作为溯源依据，避免混淆新旧监管要求。文档按条款分类的结构，要求提示词需引导模型逐条款匹配查询，不应脱离文件框架生成答案。更新周期不固定的特性，要求多轮上下文需自动过滤过期文件内容，避免引用失效的监管条款。单份文档长度跨度大，需要限制单轮上下文的总长度，防止超出模型处理上限，同时确保关键条款不被截断。

## 配置怎么定
本页面的配置方案适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 会话唯一标识 | 绑定对话历史，确保多轮追问的上下文连贯 |
| `messages` | 按时间倒序保留前10轮对话 | 限制上下文长度，避免超出模型处理上限 |
| `variables` | 仅注入当前查询的合规场景参数 | 缩小匹配范围，提升政策匹配精度 |
| 最大上下文长度 | 9000–11000 token | 适配国有资本投资公司政策文档的平均长度 |
| 提示词格式校验 | 强制返回文号+条款内容 | 确保答案符合国资监管的溯源要求 |

## 容易做错的三处
- 现象：自定义JSON格式的回复未被正确解析，返回格式混乱。原因：未在提示词中明确指定JSON的schema结构，导致模型生成的字段与系统要求不匹配。
- 现象：同一任务的对话工作流运行速度比工作流内调试慢。原因：未限制上下文召回的条数，导致每次调用都加载过多冗余的政策文档，增加了模型处理耗时。
- 现象：第二次打开历史对话时，自动回复内容为空。原因：未通过`chatId`正确绑定对话历史，导致会话上下文未被持久化存储。

## 怎么确认配好了
- 发起一次合规查询，查看回复中是否包含对应的政策文号和生效日期，确认提示词的溯源要求已生效。
- 发起多轮追问，检查后续回复是否基于前一轮的查询意图展开，确认`chatId`绑定的上下文功能正常。
- 导入一份过期的国资政策文件，发起相关查询，确认系统自动过滤了过期内容，未返回失效的监管条款。
- 查看对话历史页面，确认所有会话的上下文均按`chatId`分类存储，可正常加载之前的对话内容。
