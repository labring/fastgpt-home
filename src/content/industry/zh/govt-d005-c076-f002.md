# 国有资本运营公司的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
国有资本运营公司的政策与制度依据数据主要来源于国务院国资委、地方国资监管机构发布的官方文件，以及公司内部制定的国资运营管理制度、年度工作报告与监管合规文档。数据更新节奏无固定周期，随新的国资监管政策出台、内部制度修订或年度运营复盘同步更新。单份文档包含文号、发布单位、发布日期、正文内容与附件说明等字段，单份文档字数跨度从数百字的监管通知到数万字的运营管理办法。

## 这些特征在「向量模型与索引」这一环带来什么约束
官方与内部政策文档的元数据字段明确，索引时需同步关联文号、发布日期等信息以实现政策溯源的精准性。文档长度跨度大，从短监管通知到长管理办法的差异要求分块策略具备灵活性。无固定更新周期的特性，要求索引系统支持增量更新，避免全量重复索引消耗资源。同时，国资政策的严谨性要求检索结果需严格匹配政策原文，对相似度阈值与召回规则提出了更高要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配国有资本运营政策文件的常规段落长度，避免单块内容跨多个政策主题 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，防止政策条款被错误割裂 |
| 相似度阈值 | 0.75–0.85 | 匹配国资政策的严谨性要求，过滤无关表述，聚焦核心政策依据 |
| `maxToken` | 8000 | 适配主流大模型的上下文窗口限制，承载多份关联政策文件的完整内容 |
| `defaultToken` | 按实测标定 | 适配专属服务的调用权限与速率限制，避免超出服务额度 |
| 单次召回上限 | 前3条 | 聚焦核心政策依据，避免冗余信息干扰问答的准确性 |

## 容易做错的三处
- 批量上传chunk模式的政策数据后，界面持续显示「索引中」状态无进展。原因是未启用增量索引模式，对全量存量政策文件执行重复全量索引，导致任务队列积压。
- 调用embedding服务时返回「该令牌无权使用模型」的报错。原因是未将专属服务的调用权限绑定到`defaultToken`配置中，使用了未授权的密钥发起请求。
- 问答时返回的政策依据不完整，缺失关键监管条款。原因是分块长度设置不符合政策文档的结构特征，导致政策条款被错误拆分或合并，上下文关联断裂。

## 怎么确认配好了
- 在FastGPT v4.17.0环境中，上传单份典型的国资监管政策文件，查看索引完成时间是否符合预期，无长期挂起状态。
- 使用内部测试密钥调用embedding测试接口，确认无权限报错，接口返回正常的向量数据。
- 输入测试问题，核对返回的政策依据是否包含完整的条款内容，无明显的内容割裂或缺失。
- 查看索引任务日志，确认仅针对新增或修改的政策文件执行索引，无全量重复索引的记录。
