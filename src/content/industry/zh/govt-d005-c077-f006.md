# 城市公交的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
城市公交的政策与制度依据数据，主要来源于交通运输部、各地市级交通主管部门的官方公开文件。更新节奏随新政策出台、地方性运营条例修订触发。文档多为正式公文结构，包含政策文号、发布单位、生效日期、条款条目等字段，内容按章节、条款层级划分，单份文档篇幅跨度较大，部分区域性运营规范文档可达数十页。

## 这些特征在「引用来源与溯源」这一环带来什么约束
城市公交政策文档的长篇幅与层级化结构，要求引用溯源时需保留条款级的精准匹配，避免跨条款的错误关联。官方文件的固定文号与发布单位字段，要求溯源结果需同步展示对应标识，便于运维人员核对政策来源。区域性政策的更新随机性，要求知识库同步机制需支持按政策文号增量更新，避免全量重新导入的冗余操作。长文档的切片需匹配原文的章节层级，防止因分割不当导致引用片段脱离原政策上下文。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块重叠长度 | 80–120 字符 | 城市公交政策文档多为层级化条款，重叠长度可保留相邻条款的上下文关联，避免切片割裂政策逻辑 |
| `quoteMaxToken` | 1500–2000 token | 城市公交政策单条条款内容较长，该取值可完整保留引用片段的完整语义，同时控制上下文长度 |
| `responseData` | 开启引用详情模式 | 需返回引用的原文档片段与元数据，满足政策溯源的核对需求 |
| `detail` | 返回完整元数据字段 | 城市公交政策需展示文号、发布单位等元信息，便于运维与公众核对政策来源 |
| 召回匹配阈值 | 按实测标定 | 不同城市的政策文档用词风格存在差异，需根据实际召回效果调整阈值，确保精准匹配 |

## 容易做错的三处
- 现象为终端回复未展示引用片段，原因是未开启`responseData`对应的详情配置，导致接口未返回引用元数据。
- 现象为引用片段与原政策条款内容不匹配，原因是分块时未保留政策的章节层级结构，导致切片割裂了条款的上下文关联。
- 现象为调用API返回报错状态码，原因是`quoteMaxToken`取值超出模型支持的最大上下文限制，导致请求参数非法。

## 怎么确认配好了
- 调用FastGPT v4.17.0的知识库问答API，检查返回结果中是否包含引用片段与元数据字段。
- 进入知识库管理页面，查看切片详情，确认切片已保留政策文号、发布单位等元信息。
- 模拟查询某条具体的城市公交运营政策条款，核对返回的引用片段与原文档内容是否一致。
- 触发知识库的增量更新任务，确认后续查询可关联到最新版本的政策文件。
