# 城市公交的政策与制度依据问答：部署与升级

## 这个品类的数据长什么样
城市公交的政策与制度依据数据主要来源于交通运输部行业管理规范、各省市交通主管部门运营细则、公交集团内部执行文件及地方性法规。数据更新无固定周期，新票价调整、补贴政策、运营规范发布时同步更新。文档多为正式公文格式，包含文号、发布单位、生效日期、适用地域、具体条款、执行要求等字段，部分扫描件需OCR解析，字段单位多涉及元/人次、元/票次等公交行业专用单位。

## 这些特征在「部署与升级」这一环带来什么约束
由于政策来源覆盖部级、地方级多层级且较为分散，部署时需配置多源数据导入路径，支持批量导入不同渠道的政策文件。因政策更新无固定周期，升级时需调整增量同步机制，支持手动触发或按政策发布节点触发同步，无需固定周期调度。同时公文文档结构统一但字段要求严格，部署时需配置专用字段提取规则，适配文号、生效日期等专用字段，避免通用分块逻辑破坏条款完整性。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15 个` | 城市公交政策文档规模适中，避免数据库连接资源耗尽 |
| `REDIS_URL` | `redis://localhost:6379` | 用于缓存政策元数据与检索结果，内网部署优先本地实例 |
| `STORAGE_S3_ENDPOINT` | `按本地对象存储服务端点配置` | 存储批量导入的政策原文文件与解析后的文本块 |
| `FE_DOMAIN` | `http://localhost:3000` | 配置内网部署的前端访问域名，适配本地测试场景 |
| 文件上传大小限制 | `50 MB 以内` | 适配单份公交政策文档的扫描件或长文本体积 |

## 容易做错的三处
- 现象：Windows 环境通过 Docker 部署后，访问前端页面无法加载或返回连接错误。原因：未正确配置`FE_DOMAIN`参数，或主机端口映射与本地服务端口冲突。
- 现象：内网 docker-compose 部署时，日志提示数据库连接被拒绝，且数据库服务状态正常。原因：FastGPT 容器与数据库容器未配置在同一自定义网络中，或数据库连接字符串参数配置错误。
- 现象：直接调用政策问答的模型 API 响应正常，但在 FastGPT 中调用时响应延迟显著增加。原因：未配置`REDIS_URL`启用缓存，导致每次问答都重复执行全量政策文档检索与解析。

## 怎么确认配好了
- 执行容器状态检查命令，确认所有 FastGPT 相关服务容器均处于正常运行状态。
- 访问配置的前端访问地址，验证页面可正常加载且无资源加载失败提示。
- 导入一份本地城市公交政策测试文件，发起测试问答，验证可返回对应政策条款内容。
- 查看系统日志，确认数据库与缓存服务的连接请求均无报错信息。
