# 城市水务的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
城市水务的政策与制度依据数据主要来自住建部、水利部及各省市水务局的官方红头文件，包含地方供水排水条例、节水管理办法、管网运维标准等。文档更新无固定周期，新政策发布或旧条款修订时同步更新。单份文档多为带文号、发布机构、生效日期、条款编号的结构化文本，部分包含附件定额、收费标准等内容，字段包含文件编号、适用区域、执行单位等。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化的条款编号与适用区域字段要求索引需保留语义上下文，避免拆分跨条款内容，否则会破坏政策条款的完整语义。无固定更新周期的文档，需支持增量索引触发机制，按需同步新增政策文件。带单位的执行标准内容，需统一向量编码的单位表述，避免因单位歧义导致召回错误。长文本文档的分块需兼顾语义完整性与向量窗口限制，防止单块内容过长超出模型承载范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 1000–1500 字符 | 适配城市水务政策文档的条款长度，避免拆分单条完整政策条款 |
| 重叠长度 | 150–200 字符 | 弥补分块后的语义断层，确保跨块的政策上下文连贯 |
| `defaultToken` | 8192 | 适配主流开源向量模型的默认上下文窗口，满足多数政策块的token承载需求 |
| `maxToken` | 16384 | 处理包含附件的完整政策文档，避免截断关键执行标准内容 |
| 相似度阈值 | 0.72–0.78 按实测标定 | 区分政策条款的语义相关性，过滤无关的跨区域水务政策 |
| 单次搜索上限 | 前8条 | 控制召回结果的信息量，适配政策问答的精准溯源需求 |

## 容易做错的三处
- 现象：召回结果包含跨省市的不适用水务政策，原因：未配置区域维度的索引过滤规则，仅按全局语义召回相关内容。
- 现象：向量索引构建失败，后台报错提示token超出限制，原因：未调整`maxToken`参数，直接使用默认值处理包含附件的完整政策文档。
- 现象：不同索引模型的召回结果无法正常合并排序，原因：混用不同训练数据集的索引模型，未统一向量维度，违反向量空间一致性要求。

## 怎么确认配好了
- 上传单份城市水务政策文档，查看分块预览界面，确认单块内容未跨越多条正式条款。
- 输入包含区域限定的查询语句，核对召回结果的发布区域与查询要求一致。
- 查看索引构建的后台日志，确认无token超限的截断提示。
- 测试调用索引接口，确认返回的召回结果数量符合单次搜索上限的配置。
