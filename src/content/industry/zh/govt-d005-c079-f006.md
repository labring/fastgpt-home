# 城市燃气的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
城市燃气的政策与制度依据数据主要来自住建部、各省市燃气管理办公室的官方公开文件，更新频率为每季度同步行业新规范，每年更新地方执行细则。文档以标准公文格式存储，包含发文文号、发布单位、生效日期、条款编号、适用区域、具体要求等字段，单位涉及MPa、立方米、小时等燃气行业专用计量与规范单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
城市燃气政策数据的专属特征，对引用溯源环节带来明确约束。公文式的条款编号字段要求溯源必须精准定位到具体条款，避免模糊匹配段落。适用区域字段要求在召回时需结合用户所在城市筛选对应本地细则。高频更新的特性要求知识库同步周期不超过季度，避免引用过期条款。专用计量单位则要求召回结果需保留原文单位，不可随意转换。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配单条燃气政策条款的平均长度，避免截断关键规范内容 |
| `responseData` | 开启原文引用 | 保留政策原文的文号、条款编号等溯源必需信息 |
| `detail` | 开启详细溯源 | 展示引用条款的发布单位与生效日期，符合行业合规要求 |
| 单次召回上限 | 前3条 | 城市燃气政策单场景下核心规范不超过3条，避免信息过载 |
| 知识库同步周期 | 每季度 | 匹配行业规范更新频率，确保引用内容时效性 |
| 知识库存储上限 | 1000 MB | 适配城市燃气政策文件的总存储规模，避免溢出 |

## 容易做错的三处
- 现象：返回的引用内容出现乱码。原因：未正确配置知识库上传时的编码格式，城市燃气政策文件多为GBK或繁体编码，未转换为UTF-8导致解析异常。
- 现象：引用的思考过程格式杂乱，包含大量冗余的公文标记。原因：未开启`detail`配置，导致模型直接拼接原始分块文本，未提取规范的引用格式。
- 现象：召回的引用条款与用户所在城市不匹配。原因：未配置按适用区域筛选的召回规则，导致跨区域政策被错误引用。

## 怎么确认配好了
- 上传一条本地燃气政策文件，查看知识库解析后的分块是否保留文号、条款编号等关键字段。
- 发起燃气政策相关提问，检查返回结果中是否包含引用来源的发布单位与生效日期。
- 模拟调用对应接口，确认返回的`responseData`字段包含完整的原文引用内容。
- 等待一个季度后，检查知识库是否自动同步了最新的行业规范文件。
