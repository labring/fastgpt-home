# 城市燃气的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
城市燃气领域的政策与制度依据数据，主要来源于住建部、各地住建部门、城市燃气经营主体的官方公开渠道，以及国家及地方发布的燃气行业标准文本。数据更新随政策文件正式发布动态调整，无固定周期。文档多采用条款式结构，包含政策名称、文号、发布主体、生效日期、适用范围、核心执行条款等字段，字段格式统一，生效日期采用标准日期格式，文号遵循官方公文规范。

## 这些特征在「模型接入与配置」这一环带来什么约束
城市燃气政策数据的特征对模型接入与配置带来多项约束。由于政策文档长度跨度大，短则数百字的通知，长则数千字的行业标准，模型接入需适配不同长度的上下文输入，避免超出模型上下文窗口。政策数据的字段格式要求严格，需确保模型能准确识别文号、生效日期、适用区域等关键字段，避免生成错误的政策引用。数据更新无固定周期，配置需预留灵活的知识库同步入口，适配动态更新的政策文件。同时不同地区的政策适用范围明确，配置需支持按区域过滤召回的政策内容，确保问答结果符合属地要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 城市燃气政策文档单篇最长可达数千token，该区间可覆盖多数单篇政策的完整内容，避免截断关键条款 |
| `maxTokens` | 2000–3000 token | 政策问答需生成详细的条款引用与解释，该区间可确保回答内容完整且符合输出长度要求 |
| `quoteMaxToken` | 1500 token | 需在回答中引用政策原文片段，该取值可保留足够的原文上下文，确保引用内容的语义完整 |
| `temperature` | 0.1–0.3 | 政策问答需严格遵循原文内容，较低的温度值可减少模型生成无关或偏离原文的内容，确保回答的准确性 |
| `AIPROXY_API_ENDPOINT` | 填写部署的OneAPI官方API地址 | 适配多模型调用需求，统一管理城市燃气政策问答所需的模型资源 |
| `AIPROXY_API_TOKEN` | 填写OneAPI生成的有效令牌密钥 | 用于身份验证，确保模型调用的合法性 |

## 容易做错的三处
- 现象：界面提示“没有可用模型”或调用时报空值错误。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或令牌密钥填写错误导致身份验证失败。
- 现象：模型生成的回答偏离政策原文核心条款。原因：`temperature`取值过高，模型过度生成自由内容，未严格遵循政策原文。
- 现象：回答中引用的政策片段不完整。原因：`quoteMaxToken`取值过小，截断了政策原文的关键内容，导致引用语义不完整。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型配置页面，查看`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容，确认与部署的OneAPI信息一致。
- 输入一条城市燃气政策相关的测试问题，触发模型调用，查看返回结果中是否包含正确的政策文号、生效日期等字段。
- 上传一篇测试用的城市燃气政策文档，触发知识库召回，确认召回的文档数量与内容符合预期。
- 调整`temperature`取值为0.2，测试生成的回答是否严格遵循政策原文，无明显偏离内容。
