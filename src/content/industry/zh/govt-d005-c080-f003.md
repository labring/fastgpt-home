# 城投平台的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
城投平台的政策与制度依据数据主要来自地方国资委、住建部门及属地政府公开的规范性文件，包含专项债管理、城市基建投融资、平台转型等细分领域。数据更新随地方政策调整节奏同步，无固定周期但核心政策每季度会完成一次梳理归档。单份文档结构包含发布文号、发布单位、生效日期、适用区域、条款细则等字段，条款按条、款、项分层标注，部分跨区域政策会附带适用边界说明。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
政策文档篇幅较长且条款分层明确，多轮对话时若上下文过长会导致模型无法聚焦核心政策条款，需严格控制上下文长度。其次，政策数据包含生效日期、适用区域等时效性字段，多轮对话中需确保模型能关联当前提问的时间与地域维度，避免引用过期政策。另外，不同属地政策存在差异，提示词需明确指定匹配当前会话的地域参数，防止跨区域政策混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 前 6 轮对话 + 关联政策文档片段 | 城投政策文档篇幅较长，6轮对话可覆盖常规多轮交互的上下文需求，避免冗余信息稀释模型注意力 |
| 单次搜索上限 | 前 8 条匹配结果 | 城投政策条目较多，8条结果可覆盖核心匹配内容，同时降低模型处理负载 |
| 问题优化 | 开启 | 用户提问常省略政策文号或地域信息，优化后可补充关键参数，提升检索精准度 |
| 超时阈值 | 30 秒 | 政策检索需跨多个数据源，30秒可覆盖多数检索场景，避免长时间无响应 |
| 上下文拼接长度 | 1000–1500 字符 | 单条政策条款核心内容集中在该区间，可完整保留关键信息且不超出模型上下文上限 |

## 容易做错的三处
- 现象：对话持续处于搜索状态，最终返回无结果或超时错误。原因：未设置合理的超时阈值，或单次搜索上限过高导致检索耗时超出预期。
- 现象：模型无法识别上一轮对话的上下文，即使配置了聊天记录轮数。原因：未正确绑定`messages`参数，或上下文拼接长度超出模型支持的最大token范围。
- 现象：生成的政策依据格式混乱，未按要求提取文号、生效日期等字段。原因：提示词未明确指定输出字段要求，或未启用`variables`参数绑定会话上下文变量。

## 怎么确认配好了
- 发起包含具体政策文号的提问，核对模型是否能精准匹配对应文档的条款内容。
- 发起连续3轮关联提问，核对模型是否能正确引用上一轮对话中的政策信息与地域参数。
- 查看系统会话日志，确认`chatId`参数正常生成，且每轮对话的上下文未被提前清空。
- 模拟高并发iframe嵌入场景，确认系统负载无异常波动，无会话卡死情况。
