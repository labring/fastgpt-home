# 城投平台的政策与制度依据问答：知识库检索与召回

## 这个品类的数据长什么样
城投平台的政策与制度依据主要来自内部运营管理制度、地方财政/住建部门印发的城投专项政策、上级国资监管机构的规范性文件。更新节奏为政策正式发布后1-3个工作日内完成导入，按需增量更新。文档结构包含文号、发布单位、发布日期、适用范围、正文内容等字段，文号采用“XX财预〔202X〕XX号”类标准格式，日期采用YYYY-MM-DD格式，正文多为数千字符的长文本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
城投平台的政策数据特征对检索召回环节带来多重约束。官方来源要求召回结果必须严格匹配原文内容，避免泛化偏差；长文本正文要求分块时保留上下文关联性，防止割裂政策逻辑；结构化字段（文号、发布单位）要求检索时优先匹配关键标识，提升精准度；不定期更新节奏要求检索配置支持动态筛选当前有效知识库，避免召回过时失效的政策文件。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配城投政策的严谨性要求，避免无关政策混入召回结果 |
| `limit` | 前8条 | 控制单轮问答的上下文长度，适配长政策文档的展示需求 |
| `searchMode` | 精准匹配 | 适配政策文号、发布单位等结构化字段的精准检索需求 |
| `usingReRank` | 开启 | 优化长文档分块后的相关性排序，提升核心政策片段的展示优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充政策相关的关键词，扩展检索的覆盖范围 |
| `collectionIds` | 绑定城投政策专属知识库ID | 隔离其他品类的知识库数据，避免检索结果混杂 |

## 容易做错的三处
- 现象：聊天窗口触发问答后，界面弹出“没有选择知识库”的提示。原因：未在会话配置中绑定城投政策专属的知识库集合，或绑定的`collectionIds`参数指向了错误的知识库ID。
- 现象：输入未收录的政策相关问题时，直接返回无法回答，未触发模型泛化推理。原因：未开启`datasetSearchUsingExtensionQuery`配置，或`searchMode`设置为仅精准匹配，未保留泛化推理逻辑。
- 现象：导入政策文件时无法按文号或发布部门分类管理。原因：未正确使用知识库中的文件夹功能，未将同批次或同类型的城投政策文件归类到对应文件夹中，导致检索时无法精准筛选目标文件。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理页面，检查`collectionIds`对应的知识库是否仅包含城投政策相关文件，无其他品类的冗余数据。
- 发起测试问答，输入已知的城投政策文号，确认召回结果包含对应文件的准确片段，且相似度符合预设阈值。
- 调整`similarity`参数至0.8，输入模糊表述的政策问题，确认召回结果的相关性符合预期，无无关条目混入。
- 开启`usingReRank`后，对比重排前后的结果排序，确认长文档的核心政策片段被优先展示。
