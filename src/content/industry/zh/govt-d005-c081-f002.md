# 基础化工的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
基础化工的政策与制度依据数据主要来自生态环境部、应急管理部、工业和信息化部发布的官方公告、行业规范与部门规章，更新节奏随新政策出台不定期调整。文档结构统一包含政策文号、发布单位、生效日期、适用范围、核心条款等字段，单篇文档长度差异较大，短则数百字符，长则可达数千字符，部分规范性文件还包含附件表格与处罚细则。

## 这些特征在「向量模型与索引」这一环带来什么约束
基础化工政策文档的长度差异与字段多样性，要求向量分块需兼顾上下文完整性与检索精度，避免单块内容过碎导致条款逻辑断裂。不定期的更新节奏要求索引支持灵活的增量更新与手动触发机制，适配政策发布的无规律特性。多字段的元数据结构要求索引需支持按发布主体、生效日期等字段进行过滤召回，缩小检索范围，提升政策问答的精准度。长文本的存在也要求向量模型的输入长度配置需适配大模型的上下文窗口限制。

| 分块长度 | 800–1200 字符 | 基础化工政策单条款长度多在300–800字符，该范围可保留条款完整上下文 |
| 重叠长度 | 100–150 字符 | 避免长条款被拆分后上下文断裂，保障政策逻辑连贯性 |
| 相似度阈值 | 0.75–0.85 | 政策问答需精准匹配条款，该区间可过滤低相关的非目标政策 |
| 单次搜索上限 | 前8条 | 基础化工政策条目相对集中，过多结果会超出大模型上下文承载能力 |
| `maxToken` | 4000 token | 适配通用大模型的上下文窗口，确保拼接后的政策内容完整可读 |
| 元数据过滤 | 按发布主体、生效日期 | 匹配政策的适用范围，缩小召回范围，提升检索效率 |

## 容易做错的三处
- 现象：尝试通过MongoDB直接管理向量库时，向量数据与元数据的绑定关系出现异常。原因：基础化工政策的元数据包含文号、生效日期等关键关联信息，直接操作MongoDB会破坏预设的向量库与元数据绑定规则，导致召回时无法正确过滤有效政策。
- 现象：调用ollama接入的向量模型时，FastGPT返回请求被拒绝，curl测试却可正常返回结果。原因：ollama的API请求未携带FastGPT要求的身份验证参数，或输入内容超出配置的`maxToken`限制，导致接口被拦截。
- 现象：知识库索引合并后未实现去重，出现重复的政策条款。原因：合并时未开启基于政策文号的去重规则，未对元数据进行重复校验，导致同一份政策的不同分块被多次召回。

## 怎么确认配好了
- 上传一份本地基础化工政策文档，触发向量索引构建，查看分块日志确认分块长度符合预设范围。
- 发起一条政策相关查询，查看召回结果的元数据是否包含正确的发布主体与生效日期。
- 执行索引合并操作，检查合并后的文档数量是否与原始去重后的文档数量一致。
- 调用向量模型接口，确认返回的响应状态码为200，且内容符合政策问答的预期。
