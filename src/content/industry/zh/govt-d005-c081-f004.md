# 基础化工的政策与制度依据问答：工作流编排

## 这个品类的数据长什么样
基础化工行业的政策与制度依据数据，主要来自应急管理部、生态环境部、工业和信息化部发布的安全生产、环保、产能调控相关文件，以及行业协会发布的标准文档。数据更新无固定周期，新政策出台时实时同步，行业标准每季度或年度更新。单篇文档多包含文号、发布单位、发布日期、适用范围、核心条款、罚则等字段，长度多在5000–10000字符，条款中涉及的产能、排放参数单位多为吨/年、mg/m³等。

## 这些特征在「工作流编排」这一环带来什么约束
基础化工政策文档长度较长且结构复杂，要求工作流不能一次性加载全部内容，需分批次召回相关条款。政策更新无固定周期，要求配套的知识库同步机制支持灵活调整周期，避免遗漏最新合规要求。政策包含文号、发布日期等结构化元数据，且常出现简称、跨部门关联条款，要求工作流需同时支持结构化字段提取与指代消除处理。此外，政策多为合规审查依据，要求工作流节点顺序需遵循“召回-整理-验证-回答”的逻辑，避免遗漏关键合规信息。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次召回上限 | 前8条 | 基础化工政策文档单篇较长，过多召回会超出上下文窗口，过少则无法覆盖多条款关联的合规需求 |
| 上下文窗口限制 | 8000–12000 token | 政策条款密集且长度较长，需保留足够空间承载召回的政策内容与用户提问 |
| 问题优化开关 | 开启 | 基础化工政策常出现简称、文号指代，开启后可优化消除指代，提升召回准确性 |
| 知识库同步周期 | 每7天 | 新政策发布无固定周期，定期同步可覆盖大部分更新需求，同时避免同步频率过高占用资源 |
| 元数据提取范围 | 全文本+元数据字段 | 政策包含文号、发布日期等结构化字段，需同时提取以满足合规依据的展示要求 |
| 节点超时设置 | 600秒 | 大型政策文档的召回与整理耗时较长，设置超时可避免任务无限制运行 |

## 容易做错的三处
- 现象：工作流执行后仅返回单条政策片段，无法覆盖完整合规依据。原因：单次召回上限设置过低，未匹配基础化工政策多条款关联的合规审查场景。
- 现象：调试节点进入运行状态后无法终止，界面显示节点无响应。原因：未配置`nodeId`对应的超时参数，长文档处理任务未设置强制终止机制。
- 现象：回答中出现“该文件”“上述规定”等无明确指代的表述，无法清晰对应具体政策条款。原因：未开启问题优化配置，未处理用户提问中的简称与指代，导致召回结果匹配不准确。

## 怎么确认配好了
- 上传单篇基础化工政策文档，触发工作流执行，核对召回结果条数与单次召回上限设置一致。
- 输入包含政策简称的提问，核对返回结果中是否包含完整的政策文号与发布日期等元数据。
- 进入调试模式运行工作流，等待10分钟后查看节点状态，确认无卡死或无响应情况。
- 输入指代模糊的提问，核对返回结果中是否明确关联了具体的政策条款与文号。
