# 基础化工的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
基础化工领域的政策与制度依据数据，主要来自应急管理部、生态环境部、工信部及国资委发布的公开官方文件，更新随新政策出台或修订触发。文档结构包含政策文号、发布主体、生效时间、核心条款、适用场景等模块，字段涵盖政策分类、合规要求、罚则条目，部分文档附带行业标准编号与量化指标说明，单篇文档长度差异较大，部分专项政策文本篇幅较长。

## 这些特征在「模型接入与配置」这一环带来什么约束
基础化工政策文档长度差异大且专业术语密集，要求模型上下文配置需适配长文本解析需求，避免出现上下文溢出或截断关键条款的情况。政策字段分散且更新无固定周期，需配置知识库同步机制以保证模型调用的内容时效性。不同政策的合规要求与罚则存在差异，模型调用的随机性需控制在合理范围，避免生成不准确的政策引用内容。部分政策附带量化指标，需模型准确识别单位与数值，对应模型的上下文解析精度配置。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配基础化工专项政策的长文本长度，避免上下文溢出导致关键条款丢失 |
| `maxTokens` | 2000–3000 token | 保证回答长度覆盖政策条款拆解与合规依据的完整说明 |
| `quoteMaxToken` | 1500 token | 限制单条引用的政策文本长度，过滤冗余信息干扰 |
| `temperature` | 0.1–0.3 | 降低模型回答的随机性，保证政策条款引用的准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型网关实际地址填写 | 对接模型网关的统一调用入口 |
| `AIPROXY_API_TOKEN` | 按网关生成的专属密钥填写 | 完成模型调用的身份验证 |

## 容易做错的三处
- 现象：知识库检索完成后模型持续占用显存，重启服务后才释放。原因：未配置检索后自动卸载模型的触发逻辑，基础化工政策文档篇幅较长，模型加载后未及时释放显存资源。
- 现象：测试调用返回`status code 404`错误。原因：`AIPROXY_API_ENDPOINT`配置错误，未指向模型网关的有效接口路径，或Ollama渠道配置时端口与服务路径不匹配。
- 现象：多CHAT_API_KEY无法按业务分组调用模型。原因：未按业务场景划分模型密钥组，直接在全局配置中堆叠密钥导致调用混乱。

## 怎么确认配好了
- 执行单次基础化工政策条款查询，查看返回结果是否包含准确的政策文号与对应条款内容。
- 查看模型网关的调用日志，确认每次查询都携带正确的`AIPROXY_API_TOKEN`身份标识。
- 上传一篇新发布的基础化工政策文档，触发知识库同步后，测试查询新政策相关问题，验证模型可返回最新内容。
- 观察系统显存使用情况，确认检索完成后模型占用的显存自动释放至初始水平。
