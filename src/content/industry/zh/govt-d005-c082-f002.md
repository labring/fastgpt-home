# 基础电信运营的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
数据来源为工信部、国资委发布的行业监管文件、基础电信业务管理规范、运营商内部合规制度文档。更新节奏随国家及行业监管政策调整同步推进。文档多为规范性长文本，包含条款编号、生效日期、适用范围等固定字段，单篇内容长度跨度较大，无统一固定格式。部分文档包含跨章节的关联条款，需结合上下文才能完整理解政策要求。

## 这些特征在「向量模型与索引」这一环带来什么约束
基础电信政策文档的特征，对向量模型与索引环节带来多重约束。长文本多且跨度大的特征，要求分块时需保留条款完整性，避免拆分独立监管条款，防止出现语义断裂。包含生效日期、适用范围等字段的文档结构，要求索引需支持按字段过滤检索结果，仅返回当前生效的政策内容。非固定更新节奏的特征，要求支持增量索引机制，仅对新增或修改的文档进行向量化更新，避免全量重处理带来的资源消耗。规范性文本的特征，要求向量模型需适配公文类文本的语义理解，确保政策条款的语义匹配准确性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本进行设定：

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配基础电信政策文档的条款长度，避免拆分独立监管条款 |
| 重叠长度 | 100–200 字符 | 保留相邻条款的上下文关联，确保语义连贯性 |
| `maxToken` | 8192 token | 适配政策文档的长文本输入，满足完整条款的向量化需求 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非政策类结果，确保检索内容相关性 |
| 单次搜索上限 | 前10条 | 控制检索结果数量，避免上下文过载 |
| 最大上下文 | 4000–6000 字符 | 限制传入大模型的上下文长度，平衡回答准确性与响应速度 |

## 容易做错的三处
- 现象：设置分块长度为3000字符时出现文本块丢失。原因：长文本拆分时未适配基础电信政策文档的条款边界，超出分块处理的临界阈值导致部分内容未被正确拆分收录。
- 现象：向量化过程中触发速率限制报错。原因：未调整并行处理线程数，同时对大量长文档进行向量化操作，超出接口调用限额。
- 现象：问答对提取任务长期处于索引中状态，无法就绪。原因：未配置增量索引机制，全量索引处理大量历史政策文档时占用资源过高，任务阻塞。

## 怎么确认配好了
- 执行单篇长政策文档的分块测试，检查拆分后的块数是否符合预期，未出现内容丢失。
- 模拟多文档向量化请求，观察是否触发速率限制报错，确认线程数配置合理。
- 发起针对特定生效日期的政策查询，验证检索结果仅返回符合时间范围的内容。
- 对比调整配置前后的检索响应表现，确认配置适配业务场景需求。
