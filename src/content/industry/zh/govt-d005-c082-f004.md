# 基础电信运营的政策与制度依据问答：工作流编排

## 这个品类的数据长什么样
基础电信运营的政策与制度依据数据主要来源于工业和信息化部规章、国务院国资委国央企合规文件、通信行业标准及运营商内部合规手册。数据更新以行业政策发布节点为准，重大政策调整后1-3个工作日完成同步。文档结构包含统一文号、发布单位、生效日期、条款编号、适用业务场景字段，文号采用“工信部令第XX号”或“工信部通〔XXXX〕XX号”格式，生效日期采用YYYY-MM-DD标准格式。

## 这些特征在「工作流编排」这一环带来什么约束
数据的统一文号与生效日期字段要求工作流需配置字段过滤节点，仅召回当前生效的政策内容，避免引用失效条款。适用业务场景字段要求工作流需绑定基础电信运营的业务分类标签，确保召回内容匹配当前咨询的通信服务类型。高频更新的政策要求工作流的知识库同步周期设置符合行业更新节奏，保障内容时效性。固定的文档结构则要求分块节点按条款粒度拆分，保留条款编号与关联文号的上下文关联，避免信息割裂。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配基础电信运营政策问答的工作流需求。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配政策文档的单条款平均长度，保留条款上下文完整性 |
| 重叠长度 | 100–150 字符 | 衔接相邻条款的关联信息，避免跨块内容断裂 |
| 知识库同步周期 | 1–3 个工作日 | 匹配行业政策的更新频率，保障内容时效性 |
| 字段过滤规则 | 仅召回生效日期晚于当前日期的文档 | 基于数据中的生效日期字段，过滤失效政策内容 |
| `variables` | 绑定业务场景标签与当前咨询的通信服务类型 | 匹配数据中的适用业务场景字段，精准召回相关政策 |
| 节点超时时间 | 60 秒 | 适配政策文档的召回与解析耗时，避免工作流中断 |

## 容易做错的三处
- 现象：工作流调用RAG知识库与MCP工具时返回空结果。原因：未配置`variables`绑定业务场景标签，导致召回的政策文档与当前咨询的通信服务不匹配。
- 现象：工作流分享配置中无法找到身份鉴权选项。原因：未在工作流编辑页面开启「高级配置」面板，鉴权设置隐藏在该面板内。
- 现象：数据库连接插件执行耗时远超旧版。原因：未设置合理的节点超时时间，或未配置字段过滤规则导致召回了大量无关政策文档，增加解析耗时。

## 怎么确认配好了
- 手动触发工作流，检查返回的政策文档的生效日期是否晚于当前日期，确认字段过滤规则生效。
- 查看工作流的节点日志，确认`variables`绑定的业务场景标签被正确传递到RAG召回节点。
- 测试不同通信服务类型的咨询，验证召回的政策文档是否匹配对应业务场景。
- 查看知识库同步记录，确认最近一次同步的时间符合预设的同步周期。
