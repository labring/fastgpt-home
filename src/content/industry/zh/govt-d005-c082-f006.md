# 基础电信运营的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
基础电信运营的政策与制度依据数据，主要来自工业和信息化部、省级通信管理局、国有资产监督管理机构发布的官方规范性文件、行业监管要求与技术标准。数据更新随对应政策发布节奏同步，新监管条款出台后完成入库。文档均为正式红头文件格式，包含文件文号、发布单位、生效日期、分章节条款内容，字段包含文件唯一标识、发布主体、生效时间、条款原文，以“条”为条款计量单元、“份”为文件计量单元。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源为官方正式红头文件，条款具备明确的文号、生效时间与层级结构，溯源时需精准绑定文件唯一标识与对应条款，避免混淆不同文件的同序号条款。红头文件的章节划分清晰，需保留条款所属的章节层级信息，确保溯源结果可完整展示文件原文的上下文。数据更新随政策发布同步，需在溯源时校验文件的生效状态，确保引用的是当前有效版本。官方文件的计量单元以条款为基础，需按条款维度拆分与召回，保证溯源结果的颗粒度匹配基础电信运营的业务监管需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 基础电信运营政策文件的单条款长度多在500-1000字符，该区间可完整覆盖单条款内容，避免跨条款拆分 |
| `quoteMaxToken` | 1500–2000 token | 官方政策条款原文较长，该区间可保留足够内容用于完整溯源展示 |
| 详情模式 | 开启 | 需展示条款所属的章节层级与文件文号，提升溯源精准度 |
| `detail` | 开启 | 需返回条款的层级归属与文件元数据，确保溯源信息完整可追溯 |
| `responseData` | 开启 | 需绑定原始文件的唯一标识与生效时间，避免溯源时混淆不同政策文件 |
| 召回条数上限 | 前3–5条 | 基础电信政策的关联内容多集中在3-5份核心文件，该上限可避免冗余信息干扰 |

## 容易做错的三处
- 现象：生成的回答中引用的政策条款未按文件章节层级展示，仅统一罗列在底部引用区。原因：未开启详情模式或`detail`配置未启用，未保留条款所属的章节层级信息，导致溯源展示不符合业务场景需求。
- 现象：回答引用的政策文件已失效，但仍被召回并作为问答依据。原因：未配置文件生效时间校验逻辑，未同步更新知识库中的政策元数据，导致引用了过期监管条款。
- 现象：上传政策文件后，问答结果未显示任何引用来源。原因：分块长度配置超出系统单块处理阈值，或未开启`responseData`配置，未绑定文件元数据导致溯源信息缺失。

## 怎么确认配好了
- 上传一份基础电信运营的官方政策红头文件，发起包含政策条款查询的对话，检查返回结果中是否包含文件文号与生效时间。
- 调整`quoteMaxToken`的取值，验证返回的引用条款原文长度是否随配置变化，确认参数生效。
- 测试多份政策文件的问答召回，检查召回的引用条目数量是否符合配置的上限要求。
- 查看FastGPT v4.17.0的知识库元数据列表，确认上传的政策文件的生效时间字段已正确录入。
