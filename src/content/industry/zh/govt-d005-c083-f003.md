# 基础设施建设的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
基础设施建设的政策与制度依据数据，来源为国家住建部、交通运输部、各省级住房城乡建设主管部门发布的官方公开政策文件，更新节奏为新政策发布后1-7个工作日内完成同步。文档结构包含政策标题、发文文号、发布主体、生效日期、条款编号与具体内容，字段无特殊单位，单篇文档长度差异显著，短则数千字符，长则数万字符。本页适配FastGPT v4.17.0版本。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
政策文档长度差异大且包含多条款，多轮对话中若直接传递全量历史上下文，易超出模型上下文窗口上限，需对历史对话做针对性裁剪，仅保留与当前问题强关联的内容。政策字段包含发文文号、生效日期等信息，提示词需明确要求模型在回答时标注对应政策的文号与生效时间，确保回答的合规性。不同区域的基建政策存在差异，多轮对话初始环节需引导用户明确适用的行政区域，避免跨区域政策混淆。政策更新频率固定，提示词需限定模型仅使用当前已同步的最新政策数据，不引用未更新的旧内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 适配基建政策单篇文档的常见长度，避免超出模型处理上限 |
| 历史对话保留条数 | 前3条 | 基于`messages`数组的裁剪逻辑，平衡上下文信息量与窗口占用 |
| 提示词变量绑定 | 绑定`variables`参数 | 确保用户输入的区域、项目类型等自定义参数被正确传递到提示词中 |
| 上下文召回上限 | 前5条匹配内容 | 匹配基建政策的条款密度，避免召回过多无关政策片段 |
| 对话超时时间 | 60 秒 | 适配长政策文本的召回与生成节奏，避免请求中断 |

## 容易做错的三处
- 对话日志中运行数据为空，原因是未开启`chatId`关联的日志存储开关，导致接口调用的运行过程未被记录。
- 文本内容提取模块中输入any参数到提示词代码块后返回undefined，原因是提示词代码块未正确绑定`variables`参数，导致自定义参数未被正常传递。
- 用户删除对话后关联日志同步消失，原因是对话与日志的绑定逻辑设置为随对话删除同步清理，未独立存储日志数据。

## 怎么确认配好了
- 发起一轮包含基建政策查询的对话，核对模型回答中是否标注了对应政策的文号与生效时间。
- 发起连续多轮对话，查看对话窗口的上下文占用情况，确认未出现超出限制的提示。
- 检查`chatId`关联的日志存储开关状态，确认运行数据是否被正常记录。
- 测试删除单条对话，确认关联日志是否按预设逻辑保留或清理。
