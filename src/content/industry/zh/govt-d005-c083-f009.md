# 基础设施建设的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
基础设施建设的政策与制度依据数据主要来自住建部、各省市住建主管部门公开的行业规范、项目审批文件及行业协会标准文档。数据更新无固定周期，新政策出台、标准修订或项目备案信息更新时同步更新。文档多为结构化文本，包含文号、发布单位、生效日期、适用范围、核心条款等字段，字段单位多为标准公文格式，如生效日期采用YYYY-MM-DD格式，条款标注为“第X条”，涉及项目参数以平方米、万元等行业通用单位呈现。

## 这些特征在「模型接入与配置」这一环带来什么约束
基础设施建设政策文档多为长文本且包含专业公文术语，要求模型接入时需适配足够的上下文长度以完整加载单份政策文件。数据更新无固定周期，需配置可灵活触发的知识库同步机制，避免模型使用过期政策内容。结构化的文档字段要求模型能精准匹配文号、生效日期等元数据，配置时需明确模型对公文格式的识别权重。涉及项目参数的单位匹配需求，需确保模型输出的参数与文档中使用的单位保持一致，避免出现单位转换错误。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 基础设施建设政策文档多为长文本，需完整加载单份文件的核心内容，避免截断关键条款 |
| `maxTokens` | 2000–3000 token | 模型输出政策解读内容需覆盖足够的条款细节，同时避免输出冗余信息 |
| `quoteMaxToken` | 1500 token | 引用政策原文片段时需保留足够长度，确保引用内容的完整性与可读性 |
| `temperature` | 0.1–0.3 | 政策解读需保持严谨性，降低随机性，避免出现与原文不符的解读内容 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的官方接口地址填写 | 确保模型请求能正确路由至指定的大模型服务，适配基础设施建设场景的高准确性需求 |
| `AIPROXY_API_TOKEN` | 与部署服务商分配的专属令牌一致 | 验证请求合法性，防止未授权访问，保障政策数据的调用安全 |

## 容易做错的三处
- 现象：平台模型列表无可用模型显示，仅修改BASE_URL后未生效。原因：未同步配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`的参数校验逻辑未通过，导致接口调用失败。
- 现象：模型输出的政策解读与原文条款存在偏差，引用片段不完整。原因：`quoteMaxToken`配置值过低，导致引用的政策原文被截断，无法完整呈现核心内容。
- 现象：模型输出结果出现非官方的政策解读内容，与实际文件不符。原因：`temperature`配置值过高，模型生成内容的随机性超出可控范围，偏离严谨的政策解读需求。

## 怎么确认配好了
- 发起一条针对公开基础设施建设政策的测试查询，核对模型返回的结果中是否包含正确的文号、生效日期等元数据。
- 查看知识库同步日志，确认最新的政策文档已成功加载至模型上下文范围内，无截断报错。
- 调用模型接口，检查返回结果的格式是否符合公文解读的规范，无单位或参数匹配错误。
- 验证`AIPROXY_API_TOKEN`的合法性，通过模拟请求确认接口能正常返回模型响应，无认证失败报错。
