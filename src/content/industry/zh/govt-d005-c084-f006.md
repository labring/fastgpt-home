# 大宗商品贸易的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
大宗商品贸易的政策与制度依据数据，来源为国家及地方发改、商务、海关等部门官方公告、全国性大宗商品行业协会自律规范。更新无固定周期，新政策发布即同步入库。文档多为条款式正文，附带明确的政策文号、发布单位、生效日期字段，内容涉及贸易品类范围、关税税率、监管要求等，单位包含吨、元/吨、百分比、监管代码等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于政策来源分散在多部门官网，不同平台的页面结构存在差异，需适配多源抓取逻辑以完整提取文档内容。由于更新无固定周期，需采用触发式更新，避免定时全量同步带来的冗余存储或遗漏最新政策。由于文档包含明确的文号、生效日期等标识字段，溯源环节需优先提取这些字段作为核心溯源依据，仅依赖文本匹配无法满足精准溯源需求。由于政策按贸易品类细分，需按品类做向量分块，避免跨品类的无效召回干扰。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 大宗商品贸易政策文档多为条款式长文本，需保留完整政策条款用于溯源 |
| `responseData` | 仅返回文号、发布单位、生效日期 | 贸易政策的核心溯源标识为官方文号与生效信息，冗余内容可省略 |
| `detail` | 开启 | 需展示政策原文片段与官方来源链接，满足溯源要求 |
| 单次搜索上限 | 前6条 | 覆盖多部门发布的同品类政策，避免遗漏关键依据 |
| 分块长度 | 1500–2000 字符 | 适配政策文档的条款长度，避免拆分破坏政策逻辑 |
| 重排 | 按发布时间倒序 | 优先展示最新政策，符合贸易政策时效性要求 |

## 容易做错的三处
- 现象：聊天回答的知识库引用模块弹出“溯源信息无效”报错。原因：未配置`responseData`返回政策文号、发布单位等必填字段，系统无法生成合规的溯源链接与标识。
- 现象：回答中出现“知识库搜索input”“知识库搜索response”的冗余内容。原因：未在工作流搜索节点关闭中间步骤输出，或未通过`detail`参数过滤非核心展示内容。
- 现象：代码运行插件调用时提示依赖缺失。原因：未在FastGPT的代码运行环境中配置大宗商品贸易政策分析所需的第三方库依赖，导致执行失败。

## 怎么确认配好了
- 发起一条针对具体大宗商品品类的政策咨询，检查回答下方的溯源模块是否展示政策文号、发布单位与官方来源链接。
- 进入工作流配置页面，确认搜索节点的“输出中间步骤”开关处于关闭状态，避免冗余引用内容展示。
- 调整`quoteMaxToken`参数为较小值，验证回答中引用的政策文本长度是否符合预期，确认参数生效。
- 上传一条测试政策文档，触发知识库更新，确认新文档在搜索结果中正常展示，验证更新配置正常。
