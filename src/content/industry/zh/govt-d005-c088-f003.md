# 工程咨询监理的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
工程咨询监理的政策与制度依据数据，来源为国家住建部、省级住建主管部门发布的工程监理规范、行业标准、地方监理实施细则，以及项目监理归档的专属制度文件。国家级规范每2至3年修订一次，地方细则随区域政策更新同步调整，项目级制度随项目立项同步生成。文档多为章节式结构，包含总则、术语、监理范围、工作程序、专业细则等模块，字段包含文件编号、发布单位、生效日期、适用范围、具体条款内容，条款编号以“第X条”为标准格式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
工程咨询监理的政策数据存在国家级、地方级、项目级的层级差异，且分属房建、市政等不同专业领域，多轮对话需跟踪用户提问的地域、项目类型、生效时间等上下文，避免返回跨层级或不匹配的政策条款。单篇政策文档长度较大，需限制上下文窗口容量，防止超出模型处理上限。监理领域专业术语较多，提示词需引导用户补充必要的场景信息，减少歧义。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定用户会话唯一标识 | 区分不同用户的多轮对话上下文，避免会话内容混淆 |
| `messages` | 保留最近10轮对话内容 | 跟踪用户之前提及的地域、项目类型等关键信息 |
| `variables` | 传入地域编码、项目专业、生效日期 | 精准匹配对应层级、领域和时效的政策文档 |
| 单次召回条数 | 前3条 | 减少冗余政策条目干扰，聚焦核心条款内容 |
| 问题优化 | 开启 | 处理监理专业术语的歧义，优化用户提问的表述精度 |
| 最大上下文长度 | 8000–12000 字符 | 适配单篇工程监理政策文档的常规长度范围 |

## 容易做错的三处
- 现象：多轮对话中返回的政策条款与之前提问的地域、项目类型不匹配。原因：未正确绑定`chatId`参数，未隔离不同会话的`messages`上下文内容。
- 现象：无法并行执行多个AI对话节点的政策查询任务。原因：未配置并行工作流节点，未正确设置节点触发规则。
- 现象：无法直接在AI对话模块中上传jpg格式的监理政策扫描件。原因：未启用多模态输入配置，未配置文件解析工具适配jpg格式。

## 怎么确认配好了
- 发起包含地域、项目类型的多轮提问，检查返回的政策条款是否匹配预设的`variables`参数内容。
- 查看FastGPT v4.17.0的会话日志，确认每条对话都绑定了唯一的`chatId`标识。
- 上传jpg格式的监理政策截图，检查AI是否能正确解析图片中的条款内容。
- 测试并行调用多个AI对话节点，确认各节点的上下文互不干扰，返回结果独立准确。
