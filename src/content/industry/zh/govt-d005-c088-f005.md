# 工程咨询监理的政策与制度依据问答：工具调用与插件

## 这个品类的数据长什么样
工程咨询监理的政策与制度依据数据，主要来源于住房和城乡建设部、各省级住房和城乡建设主管部门发布的监理行业规范、招投标管理办法、现场监理规程，以及国央企内部的监理项目管理制度。数据更新节奏为：国家级规范每3至5年修订一次，地方配套细则每半年至一年更新一次，内部管理制度按季度同步调整。单篇文档结构包含文号、发布单位、生效日期、适用范围、核心条款、罚则等字段，文档长度从数百字的通知到数万字的综合管理办法不等，字段均带有明确的标准格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于政策数据来源分散，包含国家级、地方级及企业内部三类数据源，工具调用需配置多源检索插件以覆盖全部数据范围；文档字段包含明确的生效日期与文号，工具调用需支持按这些字段进行筛选，避免返回过时或不适用的政策内容；单篇文档长度差异较大，工具调用需适配长文本的分段解析与提取，确保核心条款完整返回；不同数据源的更新节奏不同，插件需定期刷新索引以保证调用数据的时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 自动选择适配监理政策检索的工具，适配多源数据调用场景 |
| `functionCall` | `["retrieve_policy", "filter_by_effective_date"]` | 指定调用政策检索与按生效日期筛选的工具函数，匹配监理政策的字段需求 |
| 单次搜索上限 | 前10条 | 工程咨询监理政策文档数量适中，前10条可覆盖核心依据，避免冗余结果 |
| 问题优化 | 开启 | 将用户的监理场景问题转化为标准政策检索关键词，提升检索准确性 |
| 最大上下文长度 | 8000 token | 政策文档通常较长，8000 token可容纳完整的核心条款内容，适配工具调用的上下文需求 |
| 插件响应超时 | 60秒 | 多源检索需要跨数据源拉取数据，60秒可覆盖大部分检索场景，避免过早超时 |

## 容易做错的三处
- 现象：首次发起工具调用时等待3秒以上，后续调用响应速度正常。原因：首次调用时插件需加载多源政策索引，未配置预加载机制导致冷启动延迟。
- 现象：调用工具返回`400 InternalError.Algo.InvalidParameter: The tool call i`报错。原因：未正确指定`functionCall`的参数格式，缺少必填的检索条件字段。
- 现象：检索结果包含已废止的政策文档。原因：未配置定期刷新数据源索引，插件调用的是旧版本的政策数据。

## 怎么确认配好了
- 发起包含具体监理政策检索需求的测试对话，查看工具调用日志是否显示正确的数据源和参数配置。
- 检查`toolChoice`与`functionCall`的配置是否符合FastGPT v4.17.0版本的语法要求，无语法错误。
- 发起首次和后续的工具调用，对比响应时间，确认冷启动延迟符合预期。
- 检索包含生效日期的政策文档，确认结果已按日期筛选，无过时内容。
