# 工程咨询监理的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
工程咨询监理的政策与制度依据数据，来源为住房和城乡建设部、各地方住建主管部门发布的行业规范、监理规程、项目审批政策文件，以及国家层面的工程建设相关法律法规。更新节奏为新政策发布、旧政策修订时同步更新，无固定周期。文档结构包含文件文号、发布单位、生效日期、适用场景、条款正文、附件清单等字段，单份文档长度从数百字到数万字不等，字段以文本类为主，部分包含表格化的条款细则。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源为官方权威文件，要求返回结果必须附带准确的来源引用，因此模型接入需配置支持溯源绑定的参数。文档长度跨度大且存在嵌套条款结构，部分文档包含表格化细则，接入时需适配长文本解析，避免截断关键条款内容。更新无固定周期，需支持灵活的数据源同步配置，确保政策文件更新后能及时同步至知识库。同时，字段以文本类为主，部分包含结构化表格，需配置支持表格内容的精准提取与还原。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 工程咨询监理政策文档多为长文本，需容纳完整的政策条款与上下文，避免关键信息截断 |
| `maxTokens` | `2000–3000 token` | 单轮问答需输出政策解读与对应条款，输出长度需覆盖完整答复且不超出模型限制 |
| `quoteMaxToken` | `1500 token` | 为溯源引用保留足够配额，确保引用的政策原文完整展示 |
| `temperature` | `0.1–0.3` | 政策问答需严格遵循原文表述，较低温度可减少无关生成，提升回答准确性 |
| `toolChoice` | `auto` | 根据用户问题自动选择是否调用检索工具，适配不同问答场景 |
| `AIPROXY_API_TOKEN` | `部署生成的专属安全令牌` | 用于接口身份验证，保障调用安全性 |
| `AIPROXY_API_ENDPOINT` | `对应部署环境的专属接口地址` | 用于指定模型请求的路由地址，保障调用链路正确 |

## 容易做错的三处
- 现象：调用模型后返回空内容，或检索到的政策条款未正常展示。原因：未正确配置`maxContext`或`quoteMaxToken`参数，导致长文本被截断，无法提取完整政策内容。
- 现象：问答结果格式混乱，嵌套条款无法正确拆分。原因：未适配工程咨询监理政策文档的嵌套结构，未开启长文本解析配置，导致条款层级丢失。
- 现象：接口调用频繁超时或失败。原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致身份验证失败或路由错误，无法正常连接模型服务。

## 怎么确认配好了
- 上传一份本地存储的工程咨询监理政策文件，发起针对文件内容的问答，核对返回结果是否包含准确的原文引用。
- 调整`temperature`参数并发起多轮相同问题的问答，观察回答内容是否保持一致，验证参数配置的稳定性。
- 更换测试用的政策文档，验证模型能否正确解析不同长度、不同结构的文件内容。
- 检查接口调用日志，确认`AIPROXY_API_TOKEN`和`AIPROXY_API_ENDPOINT`的配置未出现格式错误，调用链路正常。
