# 工程机械的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
工程机械领域的政策与制度依据数据，主要来源于国务院、工信部、各省市国资委发布的装备制造业扶持政策、行业标准规范、项目审批文件等，格式多为PDF或官方网页文档。文档结构包含政策文号、发布机构、生效日期、适用范围、具体条款、奖惩规则等字段，单篇文档长度差异较大，更新随政策出台节奏调整，无固定发布周期。

## 这些特征在「向量模型与索引」这一环带来什么约束
工程机械政策文档的专业术语多、单篇长度差异大，且包含明确的元数据字段，这要求索引环节需保留完整元数据以区分不同政策条款。单篇文档过长会超出向量模型输入限制，需合理设置分块参数避免语义割裂。政策更新无固定周期，需支持增量索引以减少重复计算。专业术语的语义匹配需要适配行业特征的向量模型，避免通用模型的匹配偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 工程机械政策文档单条款长度较长，分块过短会割裂政策逻辑，过长会超出向量模型输入限制，按实测标定 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的语义关联，避免政策条款被截断后无法完整匹配问题 |
| 相似度阈值 | 0.75–0.85 | 政策内容专业性强，需过滤低匹配度的无关结果，避免混淆不同文号的政策条款 |
| 单次搜索上限 | 前 3–5 条 | 政策问答需精准匹配对应条款，过多结果会增加上下文处理负担 |
| `maxToken` | 4096 token | 适配主流开源向量模型的输入上限，确保政策分块的语义特征完整被提取 |
| `defaultToken` | 按文档实际长度调整 | 针对超长政策文档，预留足够token空间存储元数据与分块内容 |
| 向量模型 | 适配专业领域的开源向量模型 | 工程机械政策包含大量行业专属术语，通用向量模型无法准确捕捉政策条款的语义特征 |

## 容易做错的三处
- 现象：知识库索引进度停滞，未完成的文件状态显示为“处理中”超过预设时长。原因：未针对工程机械政策文档的长文本特性配置合理的分块与超时参数，导致全量索引任务超时未完成。
- 现象：向量模型返回的匹配结果与政策条款的专业表述不符，出现语义偏差。原因：未切换适配专业领域的向量模型，使用通用向量模型无法准确捕捉工程机械行业政策的专属术语。
- 现象：调用上传文件API后无法通过接口判断索引是否完成。原因：未启用FastGPT v4.17.0的索引状态回调机制，未配置文件处理完成后的状态标记字段。

## 怎么确认配好了
- 上传一篇测试用的工程机械政策文档，查看分块预览界面，确认核心政策条款未被割裂。
- 发起一条政策相关的测试问题，查看检索结果的匹配条数，确认符合预设的单次搜索上限。
- 调用文件上传接口后，通过系统提供的状态查询接口验证索引完成状态，确认回调逻辑正常。
- 更换向量模型后，对比不同模型返回的匹配结果，确认语义匹配符合政策专业场景需求。
