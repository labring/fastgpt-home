# 工程机械的政策与制度依据问答：文档解析与分块

本文基于FastGPT v4.17.0版本的配置逻辑编写。

## 这个品类的数据长什么样
该品类的数据主要来自住建部、工信部及各地住建部门发布的工程机械监管政策、行业技术标准、施工许可规范等公开文件，以及行业协会编制的设备运维指南。文档以Word、PDF格式为主，部分配套定额以Excel形式发布，包含文件文号、发布单位、生效日期、章节条款及附录参数表格等结构。文件更新随国家政策修订、行业标准迭代进行，单次文件大小跨度较大。

## 这些特征在「文档解析与分块」这一环带来什么约束
工程机械政策文档的多格式混合、章节层级清晰且含大量参数表格的特征，对文档解析与分块带来多重约束。Word格式的大型标准汇编文件体积较大，直接解析会消耗较多计算资源，导致处理速度变慢；Excel格式的配套定额文件常以单行为一条独立政策条目，默认分块逻辑易将多行内容合并为单个分块，破坏条目独立性；文档内的参数表格若被拆分至不同分块，会导致后续问答无法关联完整的设备参数与政策要求；部分长文档的章节标题与正文绑定，分块时需保留上下文关联，避免条款断裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `15 MB` | 适配工程机械政策文件的常见体积范围，允许大型标准汇编文件导入，避免上传拦截 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 覆盖大型Word格式政策文件的完整解析耗时，避免未完成解析即触发中断 |
| `chunkSplitter` | 按段落+自定义分隔符 | 匹配政策文档的章节、条款分隔逻辑，同时适配Excel单行单条的条目结构 |
| `chunkSize` | `800–1200 字符` | 保证每个分块包含完整的政策逻辑，避免拆分过细导致上下文断裂，或过长导致语义模糊 |
| `chunkSettingMode` | 自定义模式 | 支持针对Word、PDF、Excel等不同格式文件分别配置分块规则，适配该品类的混合文档特征 |
| `customPdfParse` | 开启 | 保留PDF格式政策文件内的参数表格结构，避免默认解析导致的表格内容错乱 |

## 容易做错的三处
- 现象：上传10余MB的Word格式行业标准文件时，解析进度停滞超10分钟后弹出超时报错。原因：未调整`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`的配置，默认参数不足以支持大型文件的完整解析。
- 现象：导入Excel格式的设备定额文件后，分块预览显示连续3行的政策条目被合并为一个chunk。原因：未将`chunkSplitter`配置为按行或自定义分隔符，默认分块逻辑按段落拆分，无法适配Excel单行单条的条目结构。
- 现象：上传多份工程机械政策PDF文件后，无法准确提取每份文件对应的适用设备范围。原因：未开启`customPdfParse`，默认解析逻辑无法保留每份文件的独立元数据，导致分块时混淆不同文件的内容。

## 怎么确认配好了
- 上传单份10MB左右的Word格式行业标准文件，查看上传进度与解析日志，确认未出现超时或上传失败提示。
- 导入Excel格式的设备定额测试文件，查看分块预览界面，确认每条政策条目对应一个独立的chunk。
- 开启`customPdfParse`后上传带参数表格的PDF政策文件，查看解析后的内容，确认表格的行列结构完整未被打乱。
- 配置`chunkSize`为800–1200字符后，查看分块预览，确认每个分块包含完整的政策条款，未出现章节标题与正文拆分至不同块的情况。
