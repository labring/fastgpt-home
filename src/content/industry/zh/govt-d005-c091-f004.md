# 房建工程总承包的政策与制度依据问答：工作流编排

## 这个品类的数据长什么样
房建工程总承包的政策与制度依据数据，主要来自住建部、各省级及市级住房和城乡建设主管部门的官方公开文件。更新节奏随新政策发布、旧政策修订或地方细则出台调整，无固定周期。单篇文档通常包含发文文号、发布单位、生效日期、适用范围、承包资质要求、计价规则、工期管控条款等字段，内容结构层级分明，部分地方细则会补充本地专属的资质备案、资金监管要求，单位涉及平方米、万元、工作日等。本页面基于FastGPT v4.17.0版本编写。

## 这些特征在「工作流编排」这一环带来什么约束
房建工程总承包的政策数据来源分散于国家及地方多层级主管部门，要求工作流支持多源知识库召回，需通过`variables`绑定用户输入的项目属地参数，精准匹配对应区域的政策文件。单篇政策文档内容较长，工作流需限制单次召回的文档数量与上下文长度，避免超出大模型处理上限。政策更新无固定周期，工作流需配置定时刷新机制，确保检索结果为最新版本。政策字段包含资质、工期等细分项，需通过`nodeId`关联表单节点与检索节点，实现参数的精准传递。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次召回上限 | 前8条 | 房建政策文档单篇内容较长，过多召回会超出上下文限制 |
| 最大上下文 | 8000–12000 token | 适配政策文档的长文本结构，避免截断关键条款 |
| 超时时间 | 60 秒 | 应对多源政策数据的跨区域检索延迟 |
| `variables` | 绑定项目属地、承包资质字段 | 精准匹配对应区域与资质要求的政策文件 |
| `nodeId` | 关联表单节点与知识库检索节点 | 实现用户输入的参数自动触发政策检索 |
| 重排开关 | 开启 | 按政策层级（上位法优先）排序检索结果 |

## 容易做错的三处
- 现象：工作流运行时出现未触发的gpt-4o-mini报错日志。原因：未正确配置`variables`的触发条件，导致工作流在未匹配到政策数据时误调用大模型接口。
- 现象：全局变量中的历史政策记录无法更新。原因：未在工作流中添加`variables`的历史记录刷新步骤，导致缓存旧版政策数据。
- 现象：用户上传的资质证明文件无法被工作流关联检索。原因：未在表单节点配置文件上传字段，无法通过`nodeId`将文件信息传递至知识库检索环节。

## 怎么确认配好了
- 手动输入房建项目的属地与承包范围，检查工作流是否召回对应区域的总承包政策文档
- 查看工作流运行日志，确认`variables`中的项目参数被正确传递至知识库检索节点
- 模拟政策更新场景，检查知识库是否按设定的刷新周期更新数据
- 触发无匹配政策的场景，确认工作流仅返回无相关政策的提示，无冗余的大模型调用报错
