# 房建工程总承包的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
房建工程总承包的政策与制度依据数据，主要来自住建部、各省市住建主管部门的官方公开文件，以及行业协会发布的合规指引。数据更新随新政策出台触发，无固定周期。单份文档通常包含政策文号、发布单位、生效日期、适用场景、具体条款内容等字段，条款以章节、条、款的层级结构呈现，部分文件附带工程计价、资质要求等量化说明字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
政策文档的层级结构复杂，长文本占比高，需模型适配长上下文处理能力，避免截断关键条款。不同省市的政策存在地域差异，需配置可灵活切换数据源的召回逻辑。政策更新无固定周期，需支持增量数据接入的快速配置流程。部分政策附带工程计价、资质要求等量化字段，需模型能准确关联字段与问答场景，因此语义匹配的参数需适配长文本的语义识别精度。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配房建政策文档的长文本结构，避免关键条款被截断 |
| `maxTokens` | `2000–3000 token` | 平衡回答长度与政策条款的完整引用 |
| `quoteMaxToken` | `1500–2000 字符` | 匹配单份政策文档的核心条款长度，确保引用内容完整 |
| `temperature` | `0.1–0.3` | 降低回答的随机性，确保政策引用的准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署的代理地址填写 | 适配本地或私有部署的模型调用链路 |
| `AIPROXY_API_TOKEN` | 按平台分配的密钥填写 | 保障模型调用的身份验证安全 |

## 容易做错的三处
- 尝试切换向量模型时未正确绑定专属数据集，导致召回的政策文档与房建工程总承包场景不匹配。原因是未将住建部发布的政策数据源与向量模型调用配置关联。
- 测试模型调用时返回403 status code (no body)，原因是未正确配置`AIPROXY_API_TOKEN`或代理地址，导致身份验证失败。
- 对话提示词无法准确识别政策文本中的空格分隔条款，导致问答结果出现条款层级混乱。原因是提示词未明确要求模型保留文本中的空格格式以区分条款层级。

## 怎么确认配好了
- 上传单份长文本房建政策文档，触发召回测试，检查返回的引用内容是否完整无截断。
- 调用模型测试政策问答，检查返回结果是否准确引用政策条款的层级与文号。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置已生效，无身份验证报错。
- 调整`temperature`参数后，测试多次问答，确认结果的一致性符合预期。
