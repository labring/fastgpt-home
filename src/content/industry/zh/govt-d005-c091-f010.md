# 房建工程总承包的政策与制度依据问答：知识库检索与召回

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
房建工程总承包的政策与制度依据数据，来源为住建部发布的官方管理办法、各地住建部门出台的属地配套细则及行业标准规范。更新节奏随国家及属地住建领域政策发布频次调整，无固定周期。文档为正式公文格式，包含政策文号、发布单位、生效日期、条款层级（条/款/项）等固定字段，单篇文档长度跨度较大，短则数百字的专项通知，长则数万字的综合管理办法。

## 这些特征在「知识库检索与召回」这一环带来什么约束
房建工程总承包政策数据的特征会对检索召回带来多重约束。政策条款按条、款、项划分明确层级，需精准匹配条款编号才能满足业务查询需求，泛化召回易返回无关条款或不完整的政策片段。单篇文档长度跨度大，长公文分块时需避免拆分破坏条款逻辑，否则会导致模型无法关联完整政策要求。政策存在明确生效日期，过时政策需被过滤，需支持按发布时间或生效日期限定召回范围。部分属地政策仅适用于特定区域，需支持按地域维度缩小召回范围，避免跨区域政策干扰查询结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 房建政策文本严谨专业，该区间可过滤低匹配度的无关内容，平衡召回精准度与覆盖范围，按实测标定后可适配不同查询场景。 |
| `limit` | 前10条 | 单篇政策条款数量较多，单次召回过多内容会超出上下文窗口，10条可覆盖多数业务查询的核心政策依据，避免冗余信息干扰。 |
| `searchMode` | `embedding` | 房建政策包含大量专业术语与固定格式，基于向量的匹配可精准识别条款语义，优于关键词匹配的泛化结果。 |
| `usingReRank` | 开启 | 政策条款语义相近的情况较多，重排可基于查询意图对召回结果二次排序，提升核心条款的展示优先级。 |
| `datasetSearchUsingExtensionQuery` | 开启 | 业务查询常包含工程场景描述，扩展查询可将场景描述转化为政策关键词，提升召回的相关性。 |
| `collectionIds` | 对应房建总承包政策数据集的ID | 需限定检索范围仅包含房建工程总承包相关政策，避免混入其他建筑品类的政策文档，确保检索精准性。 |

## 容易做错的三处
- 现象：调用业务系统集成的FastGPT检索接口，返回空结果或与房建政策无关的文档，且已通过接口完成知识库数据同步。原因：未通过`collectionIds`配置限定检索范围，导致检索覆盖了非目标政策数据集，或未开启`datasetSearchUsingExtensionQuery`适配业务场景类的查询文本。
- 现象：在FastGPT后台添加房建政策知识库时，界面弹出配置失败提示，无法完成数据集导入。原因：上传的政策文档未遵循官方公文格式，或未正确配置元数据字段与政策文号、生效日期的映射规则，导致系统无法解析文档内容。
- 现象：输入超过2000字符的长文本查询时，检索结果条数不足或相关性降低，部分查询出现超时。原因：未设置合理的`similarity`参数与`limit`条数，导致召回过多冗余内容超出系统上下文窗口，或未启用`usingReRank`优化排序逻辑。

## 怎么确认配好了
- 上传1篇典型房建总承包政策文档，检查知识库解析结果是否正确识别文号、生效日期与条款层级。
- 输入包含具体条款编号的查询，核对检索结果是否精准返回对应条款内容，且未混入无关政策文档。
- 输入业务场景类查询，如“总包项目的安全管理要求”，检查检索结果是否覆盖相关政策条款，且排序符合业务需求。
- 查看FastGPT后台数据集的更新日志，确认通过接口同步的政策数据已成功导入并标记为有效状态。
