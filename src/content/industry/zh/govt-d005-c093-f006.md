# 政企信息化服务的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据来源于国家及地方政务公开平台、行业主管部门官方网站发布的正式政策文件与制度规范。更新节奏随政策发布动态调整，新政策生效后1至7个工作日内完成入库。单份文档包含文号、发布单位、发布日期、生效日期、正文、附件等固定字段，其中正文为无格式或基础格式的长文本，附件多为PDF或Word格式，单份文档大小区间按实测标定。

## 这些特征在「引用来源与溯源」这一环带来什么约束
政策文件的官方来源属性要求溯源时必须匹配发布单位与文号字段，确保引用的权威性。动态更新节奏要求溯源环节需定期同步增量政策数据，避免返回已废止或未生效的文件。固定的文档结构支持按字段自动提取引用元数据，无需额外解析非标准格式。长文本与附件格式则要求溯源时需支持跨文档关联，且对大体积附件的解析耗时需做适配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前3-5条 | 政策文档多为权威来源，单条引用信息足够支撑溯源，过多会增加响应耗时 |
| 最大上下文 | 8000-12000 token | 政策文本较长，需保留足够上下文以准确匹配关联政策 |
| `quoteMaxToken` | 1000-1500 字符 | 限制引用内容长度，避免响应内容冗余，适配政策文档的引用片段长度 |
| 知识库最大引用 | 前2-4份文档 | 政企政策多分散在多份文件中，少量精准文档即可覆盖查询需求 |
| `responseData` | 包含元数据字段 | 需返回完整的政策引用信息，包括文号、发布单位等内容 |
| `detail` | 开启 | 需返回详细的政策溯源信息，覆盖文号、发布单位、生效日期等全部元数据字段 |

## 容易做错的三处
- 现象：响应内容中引用片段被截断，或出现引用内容过长的提示。原因：`quoteMaxToken` 设置值过小，无法容纳完整的政策引用元数据与正文片段。
- 现象：返回结果中未携带任何引用来源信息。原因：未开启`detail`配置项，或未绑定包含政策文档的知识库。
- 现象：返回的引用来源包含非目标政策的文件。原因：单次搜索上限设置过高，召回了大量不相关的政策文档，导致溯源匹配混乱。

## 怎么确认配好了
- 发起一条针对已知政策文号的查询，检查返回结果中是否包含对应文号、发布单位等元数据。
- 查看FastGPT v4.17.0版本的知识库同步日志，确认最新政策文档已完成入库，且溯源配置关联了该知识库。
- 调整`quoteMaxToken`的取值，验证响应内容的引用片段长度是否随配置发生变化。
- 调用接口并查看`responseData`字段，确认其包含完整的政策引用溯源信息。
