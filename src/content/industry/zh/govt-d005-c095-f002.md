# 新能源开发的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
数据主要来自国家发改委、国家能源局及各地方能源主管部门发布的官方政策文件、行业标准文本与合规指引。更新无固定周期，随新政策出台、行业规范修订触发更新。单份文档通常包含文号、发布单位、发布日期、条款正文、配套附件等结构，字段涵盖政策层级、适用区域、执行周期等，部分附件包含量化指标，单位涉及元/千瓦时、万千瓦装机容量等。

## 这些特征在「向量模型与索引」这一环带来什么约束
官方政策文档多为长文本结构，且包含格式各异的附件内容，对文本切分的连贯性与结构保留提出要求。更新无固定周期，需支持增量索引与定期全量更新的灵活配置。政策层级与适用区域的差异，要求索引环节能够区分不同政策的优先级与覆盖范围，避免跨层级政策混淆。部分文档包含量化指标，向量匹配需兼顾条款语义与指标精度，防止模糊匹配导致的合规风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 新能源政策文档多为长文本条款，该区间可保留单条政策逻辑的完整性，避免语义割裂 |
| 重叠长度 | 100–200 字符 | 弥补长文本切分后的语义断层，确保跨块政策条款的连贯性 |
| 相似度阈值 | 0.75–0.85 | 政策合规类问答需精准匹配条款，该区间可过滤低相关性结果，避免误用非适用政策 |
| 单次搜索上限 | 前 8 条 | 覆盖新能源政策的多条款关联场景，同时控制上下文长度避免溢出 |
| `maxToken` | 4000 token | 匹配FastGPT v4.17.0内置的上下文长度限制，适配政策问答的多条款整合需求 |
| 重排 | 开启 | 优化向量召回结果的排序逻辑，优先匹配与问题直接相关的政策条款 |

## 容易做错的三处
- 现象：本地使用的向量模型与服务器端不一致，上传文档后检索结果不符合预期。原因：不同向量模型的嵌入维度与语义映射逻辑存在差异，未统一配置导致向量空间不兼容。
- 现象：单份政策文件持续显示「索引中」状态，无进度更新或报错提示。原因：文件包含格式复杂的嵌套表格或超大附件，超出分块处理的默认处理能力，导致索引进程阻塞。
- 现象：多知识库混合检索时，无法优先调用指定知识库的政策内容。原因：未配置知识库优先级规则，或规则未绑定至当前问答场景，导致检索时随机调用各知识库结果。

## 怎么确认配好了
- 上传单份典型政策文件，查看索引进度日志，确认分块数量符合预期取值区间。
- 输入一条针对性政策问题，核对召回结果的相似度得分与排序，调整阈值与搜索上限至符合业务需求。
- 导入两个测试知识库，配置优先级规则后发起问答，验证结果优先匹配预设高优先级知识库的内容。
- 检查向量模型配置项，确认本地与服务器端使用的模型参数一致，避免嵌入空间不匹配。
