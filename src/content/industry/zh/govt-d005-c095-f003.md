# 新能源开发的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据主要来自国家能源局、各省市发改委公开的新能源开发政策文件、行业标准与项目备案规范。数据文档多为正式公文格式，包含政策文号、发布主体、生效日期、适用区域、核心条款及关联文件等字段。更新无固定周期，国家级政策随行业发展不定期修订，地方政策结合区域开发进度调整，核心政策发布后24小时内完成同步更新。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
正式公文格式的长文本数据，要求多轮对话需保留政策文号、生效日期等关键字段的上下文，避免模糊引用。无固定更新周期的特征，要求对话中需主动校验当前政策的时效性，当用户提及旧政策条款时，需提示最新版本内容。适用区域字段的存在，要求提示词需引导用户明确项目落地区域，以匹配对应地方政策。长文本结构导致单次召回的内容较多，需限制上下文窗口的有效长度，避免冗余信息干扰对话逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 与用户项目ID绑定，保持会话唯一性 | 用于关联当前对话的历史上下文，确保多轮对话中政策引用的连贯性 |
| `messages` | 保留前20轮对话的政策引用片段 | 新能源政策文档多为长文本，过多历史会占用上下文窗口，20轮可覆盖用户完整咨询逻辑 |
| `variables` | 存储当前适用政策的生效日期、区域编码 | 用于在多轮对话中传递全局参数，快速匹配用户所在区域的地方政策 |
| 最大上下文窗口 | 8000–12000 token | 新能源政策文档多为长文本，FastGPT v4.17.0版本支持该窗口上限，可覆盖单次召回的核心政策条款与历史对话内容 |
| 单次召回上限 | 前3条 | 新能源政策相关文档关联性强，前3条可覆盖用户所需的核心条款与关联文件 |
| 问题优化 | 开启，针对区域+政策类型优化查询 | 用户提问常省略区域或政策文号，优化后可精准召回对应文档 |

## 容易做错的三处
- 现象：调用数据库工具查询政策数据时返回400 status code (no body)。原因：未在`variables`中配置数据库连接的全局参数，导致对话调用时无法传递正确的连接信息。
- 现象：多轮对话中无法加载之前保存的全局变量。原因：未绑定`chatId`到用户会话，导致系统无法关联对应会话的变量存储。
- 现象：对话返回的政策条款未标注生效日期。原因：未在提示词中要求引用政策的生效日期字段，且未开启区域与日期匹配逻辑。

## 怎么确认配好了
- 发起包含区域与政策类型的多轮对话，检查对话上下文是否保留了之前引用的政策文号。
- 调用数据库工具查询政策数据，确认返回结果匹配当前会话绑定的区域参数。
- 调整上下文窗口长度，验证长文本政策文档可正常召回且无截断。
- 触发历史对话加载，确认`variables`中的全局参数可正常恢复。
