# 新能源开发的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
新能源开发的政策与制度依据数据主要来自国家发改委、国家能源局及各地方能源主管部门的官方公告、行业标准文件。数据更新节奏无固定周期，新的并网要求、补贴政策、项目审批细则出台时同步更新。文档结构包含政策文号、发布单位、发布日期、生效范围、核心条款及附件说明，字段涵盖适用区域、装机容量要求、审批流程节点，单位包含千瓦、兆瓦、年度等，单篇文档长度差异显著，短则数百字的通知，长则数万字的完整管理办法。

## 这些特征在「模型接入与配置」这一环带来什么约束
新能源政策数据的多源分散特性要求配置多知识库关联同步，确保覆盖中央及地方的全部有效政策。文档长度差异大的特点，要求配置适配长文本的上下文保留参数，避免关键条款被截断。字段包含明确的功率单位与生效时间，要求配置参数支持单位校准与时间范围过滤，确保模型识别的政策内容符合区域与时效要求。政策更新无固定周期，要求配置定期触发的知识库同步机制，确保数据始终为最新有效版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 新能源政策文档单篇长度差异显著，长文件可达数千字，需保留足够上下文确保政策条款完整关联 |
| `maxTokens` | 2000–3000 token | 政策问答需输出完整合规依据，避免截断关键条款内容 |
| `temperature` | 0.1–0.3 | 政策内容需保持严谨准确，降低生成随机性防止出现错误解读 |
| `vision` | 关闭 | 该场景核心依赖文本类政策文件，无需视觉模型辅助处理 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的专属地址填写 | 保障模型调用链路的连通性 |
| `AIPROXY_API_TOKEN` | 按分配的专属密钥填写 | 验证调用权限，保障数据交互安全 |

## 容易做错的三处
- 现象：模型调用时偶尔出现输出中断，未完成政策条款的完整引用。原因：`maxContext`配置取值过低，长文档的上下文被提前截断，模型无法获取完整政策依据后终止生成。
- 现象：尝试上传音频文件后无转写结果。原因：该场景未绑定语音转写工具，且未开启对应音频处理配置，无法完成音频到文本的转换。
- 现象：接入mineru模型后调用报错。原因：未使用适配FastGPT v4.17.0的mineru版本，官方最新版可能存在接口兼容问题，导致调用失败。

## 怎么确认配好了
- 提交一条包含具体政策文号的查询，核对返回结果中是否包含对应文号的完整条款内容。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置未出现格式错误。
- 测试不同长度的政策文档查询，确认输出未出现强制截断的情况。
- 触发一次工具调用测试，确认工具调用链路无权限或地址配置错误。
