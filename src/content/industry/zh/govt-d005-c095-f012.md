# 新能源开发的政策与制度依据问答：部署与升级

## 这个品类的数据长什么样
新能源开发的政策与制度依据数据，主要来自国家发改委、国家能源局及各省市能源主管部门的官方公开文件。数据更新随新政策出台触发，无固定周期。单份文档包含政策标题、文号、发布单位、发布日期、正文条款、配套附件等字段，部分文件附带适用区域、行业类别、有效期等补充信息，文档篇幅跨度较大，从数千字的管理办法到数百字的通知不等。

## 这些特征在「部署与升级」这一环带来什么约束
政策文档篇幅跨度大，长文档的分块与向量编码会占用更多服务器资源，需匹配合理的存储与计算配置。多来源的政策格式差异，要求部署时配置统一的预处理规则适配不同文号、结构的文件。无固定更新周期的特性，需支持增量同步的升级逻辑，避免全量重建导致服务中断。部分政策附带区域、行业类别的补充字段，部署时需预留对应字段的索引空间，保障检索过滤的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/fastgpt?maxPoolSize=50&retryWrites=true` | 适配新能源政策数据的批量读写需求，maxPoolSize设置为50可平衡并发与服务器负载，避免连接池耗尽 |
| `DB_MAX_LINK` | `800–1200 字符` | 覆盖多数新能源政策文档的正文篇幅，避免单块过长导致向量编码失败，同时控制单块数据的存储与传输开销 |
| `STORAGE_S3_ENDPOINT` | `按本地对象存储服务实际地址配置` | 新能源政策附带大量配套附件，需通过对象存储统一管理，保障附件检索与导出的稳定性 |
| `REDIS_URL` | `redis://:password@host:6379/1` | 缓存高频查询的政策条目，降低数据库读写压力，适配新能源政策问答的日常查询场景 |
| `ROOT_KEY` | `自定义复杂度不低于16位的密钥串` | 保障系统后台操作的安全性，避免未授权的知识库配置修改与数据导出 |
| `FILE_TOKEN_KEY` | `自定义32位随机字符串` | 用于加密知识库附件的访问链接，保障附件下载的安全性 |

## 容易做错的三处
- 服务器内存持续升高，每日固定时段触发OOM报错。原因：未根据新能源政策文档的篇幅特征调整`DB_MAX_LINK`参数，导致单批次导入的文档数量过多，数据库连接池耗尽。
- 插件加载阶段抛出`MongoServerError: The dollar ($) p`报错，无法完成插件确认。原因：使用了与FastGPT v4.17.0不兼容的MongoDB 4.4.29版本，部分语法解析存在冲突。
- 跨实例导入知识库时，仅生成单个CSV文件，无法保留原有的多文件分类结构。原因：未正确配置`FILE_TOKEN_KEY`与对象存储的关联参数，导致附件文件未随知识库同步导出。

## 怎么确认配好了
- 批量导入10份不同篇幅的新能源政策文件，检查服务器内存占用稳定，无OOM报错触发。
- 连接配置的`MONGODB_URI`，验证数据库连接池连接数未超过设定的maxPoolSize值。
- 导出当前知识库，检查附件文件随知识库条目同步生成，无缺失或格式异常。
- 修改`ROOT_KEY`后尝试访问后台管理界面，验证未授权访问被成功拦截。
