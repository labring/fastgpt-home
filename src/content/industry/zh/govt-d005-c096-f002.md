# 有色金属冶炼的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
有色金属冶炼的政策与制度依据数据，主要来自工信部、生态环境部、应急管理部等官方政务公开平台，以及中国有色金属工业协会发布的正式行业文件。更新节奏随政策修订不定期调整，文档多为长文本结构，单篇篇幅跨度较大，字段包含政策标题、发布日期、适用冶炼环节（如铜冶炼、铝冶炼）、核心条款、量化指标及适配地域要求。

## 这些特征在「向量模型与索引」这一环带来什么约束
长文本占比高的特征要求分块策略兼顾语义完整性与token上限，避免单块内容过长超出模型处理范围，或过短导致语义割裂。政策的时效性与分类属性要求索引需绑定发布日期、适用冶炼品类等元数据，支持按条件过滤检索结果。不定期更新的特性要求配置增量索引规则，减少全量重建的资源消耗。量化指标与专业术语的准确性要求分块时保留完整字段与单位，避免语义匹配偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配有色金属冶炼政策文档的长段落结构，避免条款语义割裂 |
| 重叠长度 | 100–150 字符 | 保留跨分块的政策上下文，确保完整条款被正确检索 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配结果，聚焦有效政策依据 |
| 单次搜索上限 | 前 8 条 | 适配政策问答的多条款参考需求，避免冗余结果 |
| `maxToken` | 4000 token | 匹配大语言模型的上下文窗口限制，承载多份政策文档内容 |
| `defaultToken` | 按实测标定 | 适配FastGPT v4.17.0版本的向量模型显存占用，避免内存溢出 |

## 容易做错的三处
- 现象：知识库检索耗时超过60秒，界面显示加载超时。原因：分块长度设置过大，导致单批次向量生成量超出模型处理上限，任务队列堆积。
- 现象：向量索引任务卡滞，即使注释了索引模型配置仍无法恢复。原因：未清理旧的索引缓存队列，残留任务占用系统资源，导致新任务无法启动。
- 现象：数据集内的索引条目无规则自动增多。原因：未开启去重配置，且分块重叠长度设置过高，导致同一段政策文本被拆分为多份重复分块，重复生成索引。

## 怎么确认配好了
- 上传一篇典型的有色金属冶炼环保政策文档，检查分块后的文本是否保留了完整的条款与量化指标。
- 发起一次政策关键词检索，查看返回结果的匹配度是否符合预设的相似度阈值范围。
- 查看系统日志，确认向量生成任务的耗时稳定在合理区间，无持续堆积的队列。
- 手动触发一次增量索引，检查数据集内的索引条目数量未出现无规则增长。
