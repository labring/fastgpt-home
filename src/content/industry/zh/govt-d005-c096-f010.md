# 有色金属冶炼的政策与制度依据问答：知识库检索与召回

## 这个品类的数据长什么样
有色金属冶炼的政策与制度依据数据，来源于国家及地方工信、生态环境、应急管理部门公开的政策文件、行业强制标准、监管细则，更新随新政策发布调整，无固定周期。文档多为多章节文本，包含政策文号、发布主体、生效日期、适用冶炼细分环节、合规要求、罚则等字段，部分文件附带量化指标与操作流程说明，文本长度跨度较大，从数百字的专项通知到数万字的行业发展规划均有覆盖。

## 这些特征在「知识库检索与召回」这一环带来什么约束
政策文档按适用冶炼环节分类，部分包含特定数值要求，检索时需按环节精准过滤，避免返回不相关的电解铝政策给铜冶炼场景。无固定更新周期要求知识库支持按需同步或定期全量更新，确保召回内容与现行政策一致。多章节结构导致长文档分块需保留章节关联，避免拆分后丢失上下文关联，影响检索相关性。部分文件附带监管处罚条款，召回时需关联对应合规要求，确保问答内容完整。长文本文档的分块长度需适配政策条款的完整性，避免拆分后单个分块丢失关键合规信息。

## 配置怎么定
本文基于FastGPT v4.17.0版本配置，具体参数配置如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配有色金属政策的专业术语密度，过低会引入无关政策，过高会遗漏相近合规要求 |
| `limit` | 前10条 | 单轮召回结果数量适配政策文档的章节密度，避免上下文过长超出模型处理范围 |
| `searchMode` | semantic | 针对政策文本的语义关联需求，优先匹配合规要求与场景的语义相关性 |
| `usingReRank` | 开启 | 对召回结果二次排序，修正单一语义匹配的偏差，突出高优先级的监管政策 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于原问题生成扩展查询，覆盖政策文件中同义词表述的合规要求 |
| `collectionIds` | 按冶炼环节指定集合 | 过滤非目标环节的政策文档，缩小检索范围提升精准度 |

## 容易做错的三处
- 现象：知识库解析文件时日志报slow operation xxxxms，mongodb响应正常。原因：未按冶炼环节拆分政策集合，单集合包含过多跨环节政策文档，导致检索时扫描范围过大。
- 现象：部分政策文件未生成问答对，直接写入原文。原因：未针对政策文档的章节结构调整分块规则，长章节未正确拆分，导致分块长度超出处理上限。
- 现象：返回insufficient_quota 当前分组上游负载已饱和报错。原因：未限制单轮检索的召回条数，同时开启了扩展查询与重排，导致单次请求的token消耗超出配额。

## 怎么确认配好了
- 手动输入一条针对特定冶炼环节的合规问题，核对召回结果是否仅包含对应环节的政策文档。
- 查看检索日志，确认`usingReRank`与`datasetSearchUsingExtensionQuery`均正常触发，无报错信息。
- 模拟查询不同生效日期的政策，确认召回结果仅包含已生效的政策内容。
- 调整`similarity`阈值，验证召回结果的相关性变化符合预期调整方向。
