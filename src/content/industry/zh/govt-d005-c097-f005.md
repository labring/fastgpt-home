# 核电运营的政策与制度依据问答：工具调用与插件

## 这个品类的数据长什么样
核电运营的政策与制度依据数据，主要来源于国家核安全局、国家能源局发布的官方安全规程、运营管理办法，以及核电企业内部的标准化作业文件。数据更新节奏为重大政策修订、年度合规检查后同步更新。文档结构包含文件文号、发布主体、生效日期、章节条款、合规要求等字段，单份文档长度跨度较大，部分附件包含表格、流程图类结构化内容。

## 这些特征在「工具调用与插件」这一环带来什么约束
核电政策文档的长文本特征，要求工具调用时需限制单次召回的内容长度，避免超出上下文窗口导致信息截断。结构化的字段要求，意味着工具调用需精准提取文号、生效日期等元数据，无法仅返回无标识的文本片段。动态的更新节奏，要求插件支持动态加载最新的政策库，不能依赖静态缓存。同时核电运营的合规性要求，工具调用的结果必须可溯源至具体政策文件，否则无法满足使用需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `functionCall` | 定义提取字段为「文件文号、生效日期、合规条款」 | 核电政策文档需精准溯源合规依据，需工具返回结构化元数据 |
| `toolChoice` | `auto` | 允许系统根据问题复杂度自动选择是否调用政策知识库插件 |
| 单次召回上限 | 前3条政策片段 | 核电政策文档单份较长，过多召回会超出上下文窗口 |
| 上下文窗口限制 | 8000 token | 匹配通用大模型的上下文窗口上限，适配核电政策长文本的召回需求 |
| 上下文保留时长 | 1200秒 | 匹配核电运营问题的响应时效，避免过期上下文干扰 |
| 超时处理时长 | 60秒 | 匹配核电政策查询的响应时效要求 |
| 插件触发条件 | 问题包含「政策、规程、合规」关键词 | 精准定位需要调用政策知识库的用户提问 |
| 重排排序依据 | 匹配度+生效时间倒序 | 优先返回最新生效的合规政策，符合核电运营的时效性要求 |

## 容易做错的三处
- 现象：调用工具后返回的结果未携带文件文号字段，原因：未在`functionCall`中定义需要提取的结构化字段，导致工具仅返回无溯源的文本片段。
- 现象：连续发起两个相关提问时，工具调用的知识库范围发生重置，原因：未配置会话上下文绑定插件的逻辑，导致后续提问未沿用当前会话的政策库范围。
- 现象：调用文本内容提取插件时触发格式报错，原因：未按照核电政策文档的章节结构设置分段规则，导致插件无法识别结构化条款。

## 怎么确认配好了
- 发起包含「核电安全规程」的提问，检查返回结果是否携带文件文号、生效日期字段。
- 连续发起两个相关政策提问，检查两次调用的知识库范围是否保持一致。
- 上传一份核电政策文档，触发文本内容提取插件，检查返回的结构化字段是否符合预设要求。
- 模拟超时场景，检查工具调用是否触发了预设的异常处理逻辑。
