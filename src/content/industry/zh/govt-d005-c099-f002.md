# 油气勘探开发的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
油气勘探开发领域的政策与制度依据数据，主要来源于国家能源局、自然资源部及行业主管部门发布的正式规范文件，也包含油气企业内部的勘探开发作业规程。数据更新节奏随新政策出台不定期调整，日常无固定更新周期。文档多为结构化正式文本，包含文号、发布单位、生效日期、条款编号、适用场景、术语定义等字段，单份文档长度跨度较大。

## 这些特征在「向量模型与索引」这一环带来什么约束
政策文件的正式性要求检索结果必须精准匹配条款层级，因此分块时需保留条款编号等元信息，避免割裂核心政策逻辑。不定期更新的特性要求索引支持增量更新，无需全量重新导入所有历史文档。多字段的结构化特征可用于构建元数据过滤规则，缩小检索范围。长文本跨度则要求分块与token限制需适配文档长度，避免截断关键政策内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配油气勘探政策文件的条款长度，保留单条政策的完整核心信息 |
| 重叠长度 | 100–150 字符 | 弥补长文本分块后的上下文断层，确保检索时可关联相邻条款 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 匹配政策文件的严谨性要求，过滤低相关结果 |
| 单次搜索上限 | 前 10 条 | 覆盖政策多条款关联的业务需求，同时控制上下文总长度 |
| maxToken | 4096 token | 适配主流embedding模型的输入限制，避免截断核心政策内容 |
| defaultToken | 1024 token | 作为默认分块的token基准，平衡检索精度与计算开销 |

## 容易做错的三处
- 更换embedding模型后无法直接复用已有索引，需重新生成向量。现象：导入的知识库搜索结果无变化，或系统提示模型不匹配。原因：向量索引与embedding模型强绑定，不同模型生成的向量空间不一致，无法直接兼容。
- 知识库创建时未指定合规embedding模型导致报错。现象：界面弹出“undefined model must match "^(text”报错。原因：未选择符合要求的embedding模型，或模型名称输入格式不符合系统规范。
- 检索结果排序不符合业务预期，未按关联优先级展示。现象：高语义匹配的政策条款排在低匹配结果之后。原因：未启用重排环节，或重排参数配置错误，导致基础排序逻辑异常。

## 怎么确认配好了
- 上传单份油气勘探专项政策文件，检查分块后的片段是否保留了完整的条款编号与核心内容。
- 更换embedding模型后，执行重新生成索引操作，验证搜索结果是否随模型变更发生合理变化。
- 手动输入一条政策相关的查询，核对返回结果的相似度是否符合预设阈值区间，且排序符合业务需求。
- 查看FastGPT v4.17.0的系统日志，确认索引生成过程中无token超限或模型不兼容的报错。
