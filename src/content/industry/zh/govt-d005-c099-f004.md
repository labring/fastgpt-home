# 油气勘探开发的政策与制度依据问答：工作流编排

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
油气勘探开发的政策与制度依据数据，来源为自然资源部、国家能源局发布的官方监管文件，以及石油央企内部合规手册。更新节奏为官方政策每季度同步修订，内部制度随业务调整不定期更新。文档结构包含发布文号、生效日期、适用勘探开发环节、条款编号、合规要求原文，字段包含合规条款ID、适用区块范围、处罚阈值，单位为条款字符数、适用区域平方千米。

## 这些特征在「工作流编排」这一环带来什么约束
油气勘探开发的政策数据来源分散，包含官方监管文件与企业内部合规手册，不同数据源更新节奏差异明显，且文档按勘探开发环节、区块范围划分层级条款。这些特征要求工作流必须支持多数据源的增量同步配置，按项目所属区块筛选匹配政策条款，同时需针对层级化文档调整分块逻辑，避免跨环节条款的无效召回，还要区分官方政策与内部制度的调用优先级。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 油气勘探政策条款多为段落式，按此长度拆分可保留条款完整性，避免跨条款召回 |
| 重叠长度 | 100–200 字符 | 政策条款间存在关联逻辑，重叠可保留上下文关联，提升召回准确性 |
| 数据源同步周期 | 每日增量同步 | 官方政策每季度更新、内部制度不定期调整，每日增量可兼顾时效性与同步效率 |
| 节点超时时间 | 600 秒 | 政策文档检索需跨多数据源拉取，较长超时可避免中途中断请求 |
| `variables` 绑定 | 绑定勘探项目区块ID、业务环节字段 | 需按项目所属区块筛选匹配政策条款，精准召回对应内容 |
| 节点ID | 按业务环节命名（如「区块政策匹配」） | 工作流调试时可快速定位异常节点，提升排障效率 |

## 容易做错的三处
- 现象：工作流节点超时报错，日志显示请求未完成。原因：未针对多数据源同步配置合理超时时间，仅使用通用短超时阈值，无法覆盖跨官方与内部数据源的拉取流程。
- 现象：召回的政策条款与当前勘探项目区块不匹配。原因：未通过`variables`绑定项目区块ID，仅使用全局关键词检索，导致无关区块的政策被召回。
- 现象：工作流中全局历史记录无法更新。原因：未在`variables`中配置历史记录的存储与更新节点，导致会话上下文无法同步。

## 怎么确认配好了
- 手动触发工作流，输入某勘探区块的合规咨询，检查召回的政策条款是否包含该区块的专属要求。
- 查看数据源同步日志，确认每日增量同步任务正常执行，无失败记录。
- 修改`variables`中的项目区块ID，验证工作流召回的政策条款自动更新为对应区块的内容。
- 查看工作流节点的超时日志，确认无超过600秒的未完成请求。
