# 港口航运的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
港口航运的政策与制度依据数据，来源为交通运输部水运局公开文件、各直属港口管理局官方公告、国际海事组织公约官方译本。更新节奏为政策正式发布后即时同步，常规行业公告按周更新。单篇文档多包含文号、发布主体、生效时间、适用港区范围、条款细则等内容，字段涵盖政策编号、发布日期、覆盖港区、核心约束条件，单位涉及集装箱标准箱（TEU）、船舶载重吨、航行时段等专业参数。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
港口航运政策数据的适用港区、生效时间与专业单位特征，对多轮对话与提示词配置带来明确约束。政策的适用范围需结合用户指定的港区进行匹配，多轮对话需保留上下文内的港区与提问时间信息，避免跨区域政策混淆或引用过期条款。专业单位的统一匹配需在提示词中预设校验逻辑，避免单位转换误差。政策条款存在层级化细则，多轮对话需支持用户逐层追问，需预设上下文回溯的触发规则。同时，政策更新频率较高，提示词需明确要求调用最新同步的知识库条目，确保回答时效性。

## 配置怎么定
本配置方案基于FastGPT v4.17.0版本，具体如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 港口航运政策单篇文档多为1000-5000字符，该分块长度可保留条款完整性，避免跨条款拆分 |
| 重叠长度 | 150–200 字符 | 政策条款包含前后关联的适用范围说明，重叠分块可保留上下文连贯性 |
| 最大上下文 | 6000–8000 字符 | 可覆盖3-5轮对话的关键信息，包括港区、提问时间等核心参数 |
| 上下文消息存储 | 保留`messages`数组的前10条 | 可完整存储用户与系统的交互历史，确保多轮对话的连贯性 |
| 全局变量绑定 | 绑定`variables`中的港区代码字段 | 可自动传递用户指定的港口信息，避免重复输入 |
| 会话标识绑定 | 绑定`chatId`作为唯一标识 | 可关联会话专属上下文，实现跨轮次的信息同步 |

## 容易做错的三处
- 现象：多轮对话中AI仅能获取当前轮次的用户问题，无法回溯初始提问的港区或时间信息。原因：未在编排流程中配置`messages`数组的上下文传递逻辑，导致判断器无法将历史问题传递至后续AI对话环节。
- 现象：调用本地政策知识库时出现响应超时，或单次问答耗时超出合理范围。原因：未设置合理的最大上下文长度，导致系统加载过多政策文档分片，占用过多计算资源。
- 现象：对话返回的政策条款适用范围错误，例如将上海港的政策应用于宁波港。原因：未绑定`variables`变量传递用户指定的港口信息，导致系统无法匹配对应港区的政策文件。

## 怎么确认配好了
- 发起包含指定港区与政策类型的提问，核对系统是否匹配对应港区的政策条款。
- 发起多轮连续交互，核对系统是否保留前一轮的关键信息，无需重复输入相同参数。
- 查看会话日志，核对`chatId`是否绑定当前会话，`variables`变量是否正确传递用户输入的参数。
- 触发连续多轮问答，核对系统响应时长是否符合预设的合理范围。
