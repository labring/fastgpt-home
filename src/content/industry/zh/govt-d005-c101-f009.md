# 港口航运的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
港口航运政策与制度依据的数据，主要来源于交通运输部、各直属海事局、海关总署及地方港口管理局的官方公开渠道。更新节奏为新政策发布即时同步，旧政策修订或废止时同步下架。文档多为PDF或结构化Word格式，包含政策编号、发布主体、生效日期、适用港区、核心约束条件、执行标准等字段，部分文档附作业流程或量化指标表格，涉及单位包括自然吨、标准箱（TEU）、作业时长、费率百分比等。

## 这些特征在「模型接入与配置」这一环带来什么约束
港口航运政策数据的特征会对模型接入与配置带来多项约束。首先，政策文档存在明确的生效日期与适用港区范围，需配置召回规则过滤非目标港区的政策内容，避免返回无效信息。其次，政策条款多为结构化内容，包含唯一编号与生效时段，模型需准确提取并引用这些信息，因此需调整上下文匹配的精度。另外，政策更新无固定周期，需配置支持手动触发知识库更新的机制，确保问答内容始终匹配最新政策。最后，部分政策附量化指标，需模型能准确识别单位类型，避免匹配错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 港口航运政策文档多为长条款，需保留足够上下文确保模型匹配完整政策范围 |
| `quoteMaxToken` | 1500–2000 token | 政策引用需准确返回完整条款内容，避免截断关键的编号与生效日期信息 |
| `maxTokens` | 2000–3000 token | 限制单次模型输出的最大长度，确保政策解读内容简洁且完整 |
| `toolChoice` | "auto" | 需模型自主判断是否调用知识库召回政策文档，适配不同港区的政策差异 |
| `temperature` | 0.1–0.3 | 政策问答需严谨，降低随机性以确保返回内容与原文高度一致 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应接口地址 | 适配本地或云端部署的模型调用路径，确保请求正常路由 |
| `AIPROXY_API_TOKEN` | 按实际生成的密钥填写 | 验证模型调用权限，避免未授权访问导致的请求失败 |

## 容易做错的三处
- 现象：调用模型后返回`model response empty`报错，或无任何输出内容。原因：未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，导致模型请求未成功建立连接。
- 现象：召回的政策文档未按适用港区过滤，返回了跨港区的无效政策内容。原因：未配置按适用区域的召回过滤规则，或规则参数设置错误。
- 现象：模型返回的政策引用未包含完整条款编号或生效时间。原因：`quoteMaxToken`取值过小，截断了条款中的关键标识字段。

## 怎么确认配好了
- 手动触发知识库更新，检查更新日志中是否显示政策文档成功同步，无报错提示。
- 输入测试问题（如“某港区的集装箱装卸收费标准是什么”），检查返回结果中是否包含准确的政策条款编号与生效时间。
- 查看模型调用日志，确认请求头中携带了正确的`AIPROXY_API_TOKEN`，接口地址匹配部署环境。
- 调整测试问题的港区范围，检查召回结果是否仅返回对应港区的政策内容。
