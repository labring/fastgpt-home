# 炼化生产的政策与制度依据问答：知识库检索与召回

## 这个品类的数据长什么样
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这些特征在「知识库检索与召回」这一环带来什么约束
政策文档的生效日期与文号要求检索时需精准匹配有效版本，避免召回过期失效的条款。部分合规文档为扫描件格式，纯文本提取存在乱码或缺失，需要额外的OCR预处理环节。条款按条、款、项分级的结构，要求检索召回时保留上下文关联，避免拆分后丢失条款层级逻辑。多源数据的来源差异，需要在召回时区分官方政策与内部细则的适用场景，避免混淆执行标准。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.75–0.85 | 炼化政策文本多为严谨的规范表述，该区间可平衡召回精度与覆盖范围，避免引入无关条款或遗漏有效合规依据 |
| `limit` | 前8–12条 | 单轮政策检索需覆盖足够多的条款以匹配复杂生产场景，同时避免过多冗余信息干扰决策 |
| `usingReRank` | 开启，保留前5条重排结果 | 政策文本语义相似度较高，重排可过滤掉字面匹配但实际不适用的条款，提升召回精准度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 政策问题常包含专业术语，扩展查询可补充同义词与行业术语，覆盖更多相关条款 |
| `searchMode` | vector | 炼化政策的语义关联较强，向量检索可精准匹配专业术语，比关键词检索更适配规范文本的语义查询 |
| `collectionIds` | 绑定专属政策知识库集合 | 炼化生产的政策数据与其他品类完全隔离，需指定专属集合ID避免召回无关文档 |

## 容易做错的三处
- 界面返回`invalid configuration parameter name "hnsw.max_scan_tuple`报错，原因是错误使用了FastGPT官方支持清单外的参数，未采用指定的配置项进行设置。
- 知识库搜索耗时过长，原因是未设置合理的`limit`参数，召回过多冗余条款导致检索计算量增加，或未开启重排功能放大了无效结果的处理开销。
- 扫描PDF格式的政策文档检索结果出现乱码或无匹配内容，原因是未对扫描件执行OCR预处理，直接提取的图像文本无法被正确索引，导致匹配失败。

## 怎么确认配好了
- 查看配置页面的参数列表，确认仅使用FastGPT官方支持的配置项，无自定义的非清单参数。
- 发起单轮政策检索测试，核对返回结果的条数符合`limit`参数的设置，且结果中包含有效政策条款。
- 上传扫描件格式的政策文档，执行OCR预处理后验证索引结果无乱码，可正常匹配检索。
- 发起多问题批量检索测试，确认每个问题的检索结果独立隔离，无跨问题的结果干扰。
