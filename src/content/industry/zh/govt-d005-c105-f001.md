# 煤炭运销的政策与制度依据问答：HTTP 接口与外部系统
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
煤炭运销的政策与制度依据数据主要来自国家能源局、省级能源监管部门及行业协会公开文件，以及煤炭运销企业内部的运销管理规范。数据更新无固定周期，新政策发布或内部制度修订时同步更新。文档多为结构化公文格式，包含政策文号、发布单位、生效日期、适用运销环节、量化要求等字段，单位涵盖吨、车次、结算周期等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
煤炭运销政策数据来源分散，需通过HTTP接口对接多类官方及企业内部数据源，接口需支持按区域、运销环节、发布时间筛选查询。数据更新无固定周期，接口需配置触发式同步或按实测标定的轮询间隔，避免数据滞后。结构化的政策文档字段明确，接口返回参数需匹配政策文号、生效日期等字段，确保下游系统可直接提取关键信息。单篇政策文本长度差异较大，接口需支持返回完整文本或按需截取分段内容，适配不同场景的内容调用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 请求超时时间 | 600 秒 | 煤炭运销政策文档多为长文本，接口返回数据量较大，需预留足够响应时间 |
| `Authorization` | 按对接数据源分配的专属密钥填写 | 用于对接官方政策数据源的身份验证 |
| `variables` | 传入区域编码、运销环节类型参数 | 适配不同省市、不同运销环节的政策查询 |
| `responseData` | 提取政策文号、生效日期、核心条款字段 | 匹配下游系统的结构化数据调用需求 |
| 数据源同步间隔 | 24 小时 | 政策更新频率较低，每日同步可平衡时效性与资源占用 |
| 结果返回上限 | 前 5 条 | 避免单次返回过多数据超出对话上下文承载能力 |

## 容易做错的三处
- 调用接口返回 403 Forbidden 状态码，无法获取政策数据。原因是未正确配置`Authorization`参数，或密钥权限未覆盖目标官方数据源范围。
- 调用已配置的外部代理接口时返回 404 状态码，无法触发查询。原因是未正确匹配接口地址与FastGPT的外部系统配置格式，导致路由无法解析。
- 外部系统接收的政策数据字段不完整。原因是未在`responseData`参数中指定需要提取的字段，默认返回全量原始文本导致下游解析失败。

## 怎么确认配好了
- 手动触发接口调用，检查返回的`responseData`字段是否包含预设的政策文号、生效日期等关键信息。
- 查看外部系统的调用日志，确认`Authorization`参数已正确携带，无身份验证失败记录。
- 调整`variables`参数中的过滤条件，验证接口返回的政策数据是否符合指定的区域或运销环节要求。
- 测试连续调用接口，确认请求超时时间配置可覆盖多数场景的响应时长，无持续超时报错。
