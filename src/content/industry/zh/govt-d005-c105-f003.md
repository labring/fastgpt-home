# 煤炭运销的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
煤炭运销的政策与制度依据数据，来源为国家能源局、地方煤炭行业监管部门公开政策文件、煤炭运销企业内部合规制度。文档多为结构化条款式，包含政策文号、生效周期、适用运销环节、量化指标要求等内容，字段涉及运销主体资质、运力匹配标准、税费缴纳规则、跨区域运销审批要求等。数据更新频率随政策发布节奏调整，无固定周期，单篇文档长度多在数千字符范围。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
煤炭运销政策文档的结构化条款与多字段特征，要求多轮对话中需精准匹配用户指定的场景参数，避免跨区域、跨品类的政策混淆。政策文档长度较长，需限制对话上下文的窗口大小，防止模型因上下文过载混淆不同条款。用户常通过多轮追问获取具体条款、量化指标或审批流程，因此需保留最近数轮的交互信息，确保模型能关联历史提问的关键条件。同时，政策的生效周期与适用范围存在差异，需在对话初始阶段引导用户补充区域、运销品类等关键变量，缩小问答范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 匹配单篇煤炭运销政策文档的常见长度，适配FastGPT v4.17.0的上下文处理上限 |
| `messages` 参数配置 | 保留最近8–12轮对话内容 | 适配煤炭运销政策问答的多轮追问场景，无需保留冗余的前期交互 |
| `variables` 配置 | 绑定区域、运销品类、生效时间变量 | 用于精准限定问答的政策适用范围，过滤不相关的政策条款 |
| 对话历史自动清理阈值 | 720 秒无交互触发 | 避免长时间未交互的会话上下文占用系统资源 |
| `chatId` 配置 | 按用户会话生成唯一标识 | 区分不同用户的咨询会话，防止上下文串扰 |
| 提示词模板变量填充 | 自动替换`{{region}}`、`{{coal_type}}` | 确保问答始终基于用户指定的具体场景，提升匹配精度 |

## 容易做错的三处
- 对话返回结果末尾出现未预期的规则展示符号：现象为模型输出的政策问答内容末尾附带未配置的追溯展示标记，原因是未在提示词中关闭模型的默认规则输出配置，或模板中残留了默认的规则提示内容。
- 并发调用时出现请求失败或返回空结果：现象为会话返回结果为空或状态码异常，原因是未配置合理的对话历史保留条数，导致上下文长度过大，超出并发处理的资源限制。
- 多轮对话中政策条款匹配错误：现象为模型返回的政策条款与用户指定的区域、运销品类不符，原因是未在`variables`中绑定用户指定的场景变量，导致模型调用了不相关的政策文档。

## 怎么确认配好了
- 发起测试会话，输入包含区域、运销品类的具体问题，查看返回结果是否仅包含匹配该场景的政策条款，无无关内容。
- 发起两轮连续追问，查看模型是否能关联历史提问的关键条件，正确延续问答范围。
- 等待配置的无交互阈值时长后再次发起会话，查看是否重新加载初始提示词，无历史上下文残留。
- 发起多个独立会话，查看不同会话的返回结果互不干扰，无上下文串扰情况。
