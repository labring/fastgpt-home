# 煤炭运销的政策与制度依据问答：部署与升级

本页面适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
煤炭运销的政策与制度依据数据，主要来源于国家能源局、各地煤炭行业监管部门、国央企内部运销管理部门发布的正式文件。数据更新节奏不固定，新政策出台或内部制度修订时同步更新。文档多为带结构化元数据的长文本，包含文件文号、发布单位、生效日期、适用范围、运量运价合规条款等字段，部分附件包含运销指标表格，单位涉及万吨、元/吨、运输公里等。

## 这些特征在「部署与升级」这一环带来什么约束
由于政策数据来源分散且更新无固定周期，部署时需支持多源数据批量导入与定时同步配置；长文本与结构化元数据并存，要求知识库支持元数据字段映射与大分块存储；运销相关字段的单位具有行业特殊性，部署时需预设字段匹配规则，避免检索时出现单位混淆；国央企场景下的数据安全要求，需配置权限隔离与访问令牌机制，保障内部政策文档不被非授权访问。升级时需注意保留原有元数据映射规则，避免因版本更新导致字段配置失效。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150 秒` | 煤炭运销政策文档多为长文本，长连接可减少重连开销，适配大文件检索场景 |
| `REDIS_URL` | `本地 Redis 实例 6379 端口` | 用于缓存政策检索的元数据与用户会话信息，降低数据库查询压力 |
| `STORAGE_S3_ENDPOINT` | `按企业自建对象存储地址填写` | 适配批量上传的大容量政策文档存储需求，保障数据持久化 |
| `FILE_TOKEN_KEY` | `按实测标定` | 为上传的政策文档生成唯一访问令牌，实现内部文档的权限隔离 |
| `ROOT_KEY` | `仅用于初始管理员配置` | 限制非授权用户修改知识库核心配置，符合国央企数据安全规范 |

## 容易做错的三处
- 现象为本地部署后无法解析上传的煤炭运销政策文档，界面显示“文件解析失败”。原因是未正确配置`FILE_TOKEN_KEY`，导致上传的文档无法被系统读取。
- 现象为多账号创建后无法分配不同的知识库权限，界面显示“权限配置无效”。原因是未通过`ROOT_KEY`完成管理员权限初始化，未搭建账号权限体系。
- 现象为检索政策文档时返回结果条数与预期不符，日志显示数据库连接超时。原因是`DB_MAX_LINK`取值过小，长文本检索时连接提前断开。

## 怎么确认配好了
- 上传一份煤炭运销政策PDF文档，检查是否能正常解析并生成带结构化元数据的知识库条目。
- 访问配置的`FE_DOMAIN`前端地址，使用初始管理员账号登录，验证多账号创建与权限分配功能正常。
- 执行一次政策关键词检索，检查返回结果包含正确的文号、生效日期等行业专属字段。
- 查看`REDIS_URL`对应的实例监控，确认连接数处于稳定运行区间。
