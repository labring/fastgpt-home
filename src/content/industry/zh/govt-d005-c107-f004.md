# 煤矿生产的政策与制度依据问答：工作流编排

## 这个品类的数据长什么样
煤矿生产的政策与制度依据数据，主要来源于国家能源局、国家矿山安全监察局、省级煤矿监管部门的公开官方文件，以及煤炭行业协会发布的行业规范、企业内部的安全生产规程。数据更新节奏无固定周期，国家级政策随监管要求调整发布，企业内部规程通常在重大政策出台或年度安全检查后更新。单份文档通常包含政策文号、发布主体、生效日期、失效日期、适用作业场景（井工/露天煤矿）、条款编号与具体内容等字段，条款内容以千字左右的段落或分条项形式呈现，无统一的固定字数要求。

## 这些特征在「工作流编排」这一环带来什么约束
由于政策数据来源覆盖多层级监管主体与企业内部规范，工作流需支持多源知识库的分类检索，避免不同层级政策的混淆。政策生效与失效日期的字段要求工作流在检索环节加入时间过滤，仅返回当前有效的政策条款。文档按作业场景分类的结构，要求工作流配置场景匹配的检索条件，过滤非适用煤矿类型的政策。无固定更新周期的特点，要求工作流支持按需触发的知识库同步，同时可配置定期同步作为补充。长文本的条款内容，要求工作流在检索后按条款拆分片段，避免超出大模型的上下文限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 知识库分类 | 按国家级/省级/企业级煤矿政策分类存储 | 匹配政策发布主体层级，便于精准检索对应层级的监管要求 |
| 检索过滤条件 | 加入「生效日期≤当前日期」且「失效日期≥当前日期」 | 确保仅返回当前有效的政策文件，避免引用失效条款 |
| 变量引用格式 | 使用`{{}}`格式 | 兼容FastGPT v4.17.0的变量调用规范，避免解析错误 |
| 单次检索上限 | 前10条 | 覆盖主要政策条款，避免冗余信息超出大模型处理范围 |
| 上下文长度 | 800–1200 字符 | 适配煤矿政策条款的常规长度，保障大模型能完整理解政策内容 |
| 上下文变量传递 | 绑定`variables`中的检索结果字段 | 确保工作流各节点间的数据正确传递 |
| 节点超时时间 | 600 秒 | 避免长文档检索或大模型处理时出现超时中断 |
| 同步触发规则 | 按需手动同步+每月自动同步 | 匹配政策不定期更新的节奏，保障数据时效性 |

## 容易做错的三处
- 现象为工作流中`{{}}`格式的变量未被正确替换，提示词中的模板字符直接暴露在回答中。原因是混用了旧版/模式取变量与`{{}}`格式，未遵循FastGPT的变量调用规范。
- 现象为工作流执行至判断器环节后停止，无后续流程触发，对话直接结束。原因是未为判断器配置默认分支，或全局变量的知识库选择类型未关联正确的检索结果字段。
- 现象为工作流执行至大模型节点后直接终止，未完成后续的对话收尾或结果返回。原因是未在大模型节点后绑定对话收尾节点，或未正确传递`variables`中的检索结果上下文。

## 怎么确认配好了
- 手动触发一次工作流，查看知识库返回的文档是否均为当前生效的煤矿政策，核对检索过滤条件的配置是否正确。
- 在工作流的大模型提示词中插入测试变量，调用`{{}}`格式的变量，确认返回结果中变量已被正常替换，无未解析的模板字符。
- 运行包含判断器的测试流程，验证不同条件分支均能触发对应后续节点，确认判断器的分支配置完整。
- 查看工作流执行日志，确认所有节点均完成执行，无中途终止的异常记录。
