# 煤矿生产的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
煤矿生产的政策与制度依据数据，主要来源于国家能源局、应急管理部、属地煤炭监管部门的公开政策文件、行业安全规程及企业内部合规文档。文档包含政策编号、发布主体、生效日期、适用矿区类型、核心条款原文等字段，按条、款、项划分层级结构，格式涵盖PDF、Word及扫描件，单份文件篇幅从数百字符到数千字符不等，新政策发布后1-3个工作日内完成同步更新。

## 这些特征在「模型接入与配置」这一环带来什么约束
多来源的政策文档格式不统一，要求接入配置适配PDF、Word及扫描件等多种格式，在FastGPT v4.17.0版本中需启用通用文档解析与OCR模块，否则无法提取有效文本内容。政策文件带有明确的生效与失效日期，需在检索配置中加入时间范围过滤规则，避免返回过期政策。文档的层级化条款结构要求配置保留文本层级关系，否则模型无法准确引用条款编号。单份政策文档篇幅较长，要求配置的上下文窗口适配长文本输入，避免截断关键合规内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 煤矿单份政策文档可达数千字符，长上下文可覆盖多份关联政策的检索与引用 |
| `quoteMaxToken` | 2000–3000 token | 需完整保留政策条款原文，避免截断核心合规内容 |
| `temperature` | 0.1–0.3 | 政策问答需保持严谨性，降低随机生成偏离原文的概率 |
| `maxTokens` | 4000 token | 回答需清晰覆盖政策解读要点，控制输出长度符合业务需求 |
| `AIPROXY_API_ENDPOINT` | 部署节点的专属API地址 | 统一管理跨模型调用，适配多场景的模型切换需求 |
| `AIPROXY_API_TOKEN` | 对应代理的认证密钥 | 保障API调用的身份合法性，防止未授权访问 |

## 容易做错的三处
- 现象：在OneAPI渠道中添加向量模型后，实际请求仍触发大语言模型生成。原因：未区分向量模型与LLM的配置链路，将向量模型绑定到了通用LLM调用渠道。
- 现象：设置`maxContext`为6后，模型无法保留上一轮对话的上下文。原因：误将`maxContext`的单位理解为对话轮次，实际该参数单位为token，设置值过小无法承载对话上下文。
- 现象：调用模型测试时返回401未授权错误，无法正常发起请求。原因：`AIPROXY_API_TOKEN`配置错误，或代理地址未正确关联对应模型的访问权限。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型配置页面，查看向量模型与LLM的渠道绑定关系，确认向量模型未被绑定到通用LLM调用链路。
- 发起多轮对话测试，输入包含上下文关联的问题，验证模型可正确引用前一轮的提问内容。
- 发起API调用测试，检查返回结果中包含政策条款的引用，且未出现截断或偏离原文的内容。
- 查看调用日志，确认`AIPROXY_API_TOKEN`的认证请求返回200状态码，无未授权报错。
