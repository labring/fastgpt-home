# 电网企业的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
电网企业政策与制度依据问答的数据，来源为国家能源主管部门发布的行业政策、电网企业总部及各层级的正式制度文件、行业标准规范。更新节奏随政策修订、内部流程优化不定期调整，重大政策发布后需同步完成更新。文档多为章节式正文结构，包含文号、发布单位、生效日期、条款细则等字段，单位以条款项、章节号、日期格式为主，单篇文档长度跨度较大。

## 这些特征在「向量模型与索引」这一环带来什么约束
电网政策文档的章节式结构与较长篇幅，要求向量分块需适配条款粒度，避免将单一条款拆分至多个块中，影响匹配精度。多字段的文档结构要求索引需指定核心字段，避免非政策类辅助字段被纳入向量计算。不定期的更新节奏要求索引支持增量更新，无需全量重建向量库。政策内容的权威性与刚性要求，需严格控制向量匹配的阈值，确保返回结果与查询的政策依据高度相关，避免无关内容干扰决策。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配电网政策文档的章节段落长度，避免单块内容跨核心条款 |
| 重叠长度 | 100–150 字符 | 保留相邻条款的上下文关联，防止关键依据被分块截断 |
| `defaultToken` | 按实测标定 | 适配本地或调用的向量模型输入长度限制，避免分块超出模型阈值 |
| `maxToken` | 4096 token | 匹配主流中文向量模型的最大输入长度，平衡上下文完整性与计算效率 |
| 相似度阈值 | 0.75–0.85 | 筛选精准匹配的政策条款，避免无关内容干扰政策依据的准确性 |
| 单次搜索上限 | 前10条 | 控制返回结果数量，确保用户能快速定位核心制度依据 |

## 容易做错的三处
- 搜索结果包含非政策类辅助文档，原因是未配置仅索引政策核心字段，将辅助数据纳入了向量库。
- 同一条政策条款返回多个重复匹配结果，原因是分块重叠设置不合理，或未对同一条款的多版本分块做去重配置。
- 向量查询返回空结果或报错，原因是不同向量模型的嵌入维度不一致，分块后的文档未适配服务器端模型的输入要求。

## 怎么确认配好了
- 上传单条典型政策条款，检查分块后的文本长度是否符合预设的分块设置，无明显截断核心条款的情况。
- 发起政策相关查询，检查返回结果的相似度分值是否符合预设阈值区间，无过低或过高的异常值。
- 测试更新单条政策文档，检查向量库是否自动完成增量更新，旧版本内容不再被检索到。
- 切换向量模型后，调整`defaultToken`与`maxToken`参数，验证查询结果的准确性符合预期。
