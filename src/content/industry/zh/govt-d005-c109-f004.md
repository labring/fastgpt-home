# 电网企业的政策与制度依据问答：工作流编排

## 这个品类的数据长什么样
电网企业的政策与制度依据数据主要来源于国家能源局、国家电网公司及各省级电力公司发布的正式官方文件，更新节奏随重大政策发布或年度制度修订调整。文档多为带统一文号、发布单位、生效日期的结构化PDF或Word文件，内部按章节划分条款，包含适用场景、执行标准、违规条款等字段，字段单位多为条款编号、日期格式、百分比（合规率类），单篇文档长度多在5000至20000字符之间。

## 这些特征在「工作流编排」这一环带来什么约束
上述数据特征对工作流编排带来三点约束：其一，结构化文档的章节与条款结构要求工作流需支持按条款精准匹配检索，需在检索环节绑定政策文号、生效日期等字段；其二，文档长度较长，需限制单次检索返回的上下文长度，避免超出模型处理上限；其三，更新频率不固定，需配置定期同步知识库的触发逻辑，确保检索数据为最新版本。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量 | `variables` 配置为政策文号、生效日期 | 用于精准定位目标政策条款，避免跨政策匹配混淆 |
| 工作流节点ID | `nodeId` 绑定主问答节点 | 确保外部调用时触发正确的政策问答工作流 |
| 知识库选择 | 仅绑定电网企业专属政策知识库 | 过滤非电力行业无关政策内容，提升检索精准度 |
| 单次搜索上限 | 前10条 | 电网政策条款集中，过多返回结果会增加模型处理负担 |
| 最大上下文长度 | 8000字符 | 适配单篇政策文档的平均长度，避免上下文溢出 |
| 超时时间 | 600秒 | 适配大尺寸政策文档的检索与解析耗时 |
| 并发量限制 | 10-15 并发/分钟 | 匹配电网政策知识库的文档体量与检索复杂度 |

## 容易做错的三处
- 现象：在知识库搜索环节选择引用变量时，界面无可选值。原因：未在工作流的`variables`配置中声明政策文号、生效日期等检索依赖变量。
- 现象：外部调用工作流API时返回状态码400，提示节点不存在。原因：未在API请求中传入`nodeId`参数，或传入的节点ID与工作流实际节点不匹配。
- 现象：工作流执行后返回的开场白为空，无法在前端展示。原因：未将开场白生成节点与主问答节点绑定，导致API调用时未触发预设开场白逻辑。

## 怎么确认配好了
- 进入工作流配置页，检查`variables`配置项是否包含政策文号、生效日期等必填字段。
- 调用工作流API时传入`nodeId`参数，验证返回结果与预设的政策问答流程一致。
- 发起单条测试请求，检查返回结果中是否包含预设的开场白内容。
- 模拟2-3次并发请求，观察API返回状态码是否稳定在正常范围。
