# 电网企业的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
电网企业的政策与制度依据数据，主要来源于国家能源局、省级能源监管机构及企业内部正式发布的官方文件。数据更新节奏包含年度常规修订与临时政策通知同步两类。文档结构统一包含文号、发布单位、发布日期、条款内容、适用范围等字段，单份文档长度差异明显，短则数百字符的通知类文件，长则数万字符的管理办法，字段单位以字符、页码为主要标识。

## 这些特征在「引用来源与溯源」这一环带来什么约束
电网政策数据的长文本特性，要求溯源环节需适配单块内容超出常规阈值的情况，避免截断关键政策条款。多来源的官方文件属性，要求溯源必须关联文号、发布单位等官方标识，同时完整展示对应文本片段。不定期的更新节奏，要求溯源环节需同步最新的政策版本，避免引用过期失效的文件。文档字段的标准化程度有限，要求检索与召回环节需优先匹配核心标识字段，提升溯源的准确性与可信度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1800 token | 电网政策文件单块内容多为1000-2000字符，对应token数适配业务需求 |
| `responseData` | 包含文号、发布单位、发布日期 | 电网政策的核心溯源标识为官方文号与发布信息，需在引用中完整展示 |
| `detail` | 开启 | 政策条款需完整展示原文片段，确保回答的依据可追溯 |
| 单次搜索上限 | 前6条 | 电网政策相关问题通常关联2-3份核心文件，过多结果会超出上下文承载能力 |
| 最大上下文长度 | 8000 token | 适配多份政策文件的拼接需求，符合电网政策问答的上下文长度要求 |

## 容易做错的三处
- 现象：设置`quoteMaxToken`为1500 token后，仍有超过该token数的知识库块被引用。原因：未开启块长度校验逻辑，系统仅按检索匹配度召回，未对单块token数做过滤。
- 现象：知识库检索到匹配内容，但仅返回引用提示无有效回答。原因：未开启`detail`配置，仅召回了元数据未加载原文片段，无法生成基于政策内容的回答。
- 现象：工作流中传递检索结果后，AI对话无法正确关联对应溯源信息。原因：未按要求配置`responseData`，未传递文号、发布日期等必需的溯源字段。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库配置页，查看`quoteMaxToken`的设置值是否符合业务需求
- 发起电网政策相关的测试提问，查看返回结果中是否包含政策文件的文号、发布单位等溯源信息
- 提交包含超长政策条款的测试问题，检查是否按配置的token数做合理截断或完整保留
- 查看工作流的运行日志，确认检索结果传递的字段包含`responseData`中指定的溯源内容
