# 电网企业的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
电网企业政策与制度依据问答的数据主要来源于国家能源局官方发布的电力行业政策、电网企业内部印发的运维管理、安全生产、招投标等规章制度，以及行业公开的电力标准文档。数据更新节奏随政策修订、新文件发布动态调整，文档多为结构化的分章节文本，包含政策文号、发布单位、生效日期、具体条款等字段，条款内容以规范书面语为主，部分包含表格化的执行细则。

## 这些特征在「模型接入与配置」这一环带来什么约束
电网企业政策文档多为长文本结构，单篇内容常超过万字，会对模型接入的上下文承载能力提出明确约束。文档包含政策文号、生效日期、条款编号等结构化字段，要求模型召回的上下文需精准匹配字段关联逻辑，避免混淆不同政策条款。政策文本专业术语密度高，且更新节奏随行业政策动态调整，需要配置的知识库同步机制适配非固定周期的更新，同时模型的生成逻辑需贴合官方政策的严谨表述风格。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配电网政策文档的长文本结构，避免截断核心政策条款 |
| `maxTokens` | 2000–3000 token | 匹配政策问答的回复长度需求，保证单条回复覆盖完整条款解释 |
| `temperature` | 0.1–0.3 | 适配政策文本的严谨性要求，降低生成内容的随机性 |
| `vision` | 关闭 | 电网政策文档多为纯文本格式，无需图片解析能力 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接口地址 | 确保模型调用链路正常连通 |
| `quoteMaxToken` | 1500 token | 限制召回的上下文片段总长度，避免超出模型上下文上限 |

## 容易做错的三处
- 调用模型时返回超时错误，日志显示耗时超过600秒。原因是未针对长文本政策文档调整`maxContext`参数，导致模型加载上下文耗时过长。
- 配置模型时无法找到温度参数的设置入口。原因是未在对应模型的接入配置页中定位`temperature`参数的配置项，误将其他环节的设置项当作温度调整入口。
- 自定义文档解析服务调用超时，平台返回报错。原因是未调整适配长政策文档的解析超时配置，默认超时阈值不足以处理大型政策文件。

## 怎么确认配好了
- 上传一篇电网企业内部政策文档，发起对应条款的问答测试，检查回复内容是否完整引用了对应条款的文号与生效日期。
- 查看模型调用日志，确认`maxContext`参数生效，上下文加载时长未超出合理范围。
- 调整`temperature`参数至0.2，发起多条测试问答，检查回复内容是否保持严谨的官方表述风格，无冗余或发散内容。
- 验证知识库同步功能，上传新的政策文件后，确认问答内容可覆盖新文件的条款内容。
