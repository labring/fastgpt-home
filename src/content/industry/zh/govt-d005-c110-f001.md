# 矿山采选的政策与制度依据问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
矿山采选领域的政策与制度依据数据，主要来源于国家矿山安全监察局、自然资源部及地方矿山监管部门的公开官方文件。数据更新随政策正式发布同步触发，无固定周期。单篇文档以政策文号、发布单位、生效日期、适用矿种、条款细则为核心结构，字段包含政策编号、发布主体、生效时间、适用场景、条款原文，单位以字符为统计基准，单篇文档长度跨度较大。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 接口超时时间 | 600 秒 | 矿山采选政策文档多为长文本，接口拉取需足够时间完成完整数据传输 |
| `Authorization` | Bearer 官方公开API密钥 | 对接国家矿山安全监察局等部门公开政策接口的身份验证要求 |
| 字段映射规则 | 政策编号→唯一标识、适用矿种→分类标签 | 匹配矿山采选政策的核心业务字段需求 |
| 单次请求返回上限 | 前 20 条 | 避免单次请求数据量过大引发超时或截断 |
| `variables` | 配置矿种、生效时间范围参数 | 实现按业务场景精准过滤政策数据 |
| `responseData` | 仅提取条款原文、发布主体字段 | 精简接口返回内容，降低下游系统的处理开销 |

## 容易做错的三处
- 现象：外部嵌入接口调用失败，提示模型不兼容。原因：未确认嵌入接口的嵌入维度与业务需求匹配，未按矿山采选政策文本的长度调整请求参数。
- 现象：接口调用返回401或403状态码，无法获取政策数据。原因：未正确配置`Authorization`参数，或使用了无权限访问对应政策接口的密钥。
- 现象：接口返回的政策内容片段与预期不符，出现内容截断或冗余。原因：未配置合理的单次请求返回上限，或未按政策文档的结构设置内容提取规则。

## 怎么确认配好了
- 调用测试接口，检查`responseData`返回的字段是否与配置的提取范围一致。
- 查看接口请求日志，确认`Authorization`参数已正确携带，无身份验证相关报错。
- 传入预设的矿种变量，检查接口返回的政策数据是否仅包含对应矿种的内容。
- 模拟长文本请求，验证接口超时时间设置，确认无超时截断问题。
