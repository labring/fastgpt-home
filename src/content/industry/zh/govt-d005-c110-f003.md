# 矿山采选的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
矿山采选的政策与制度依据数据，来源为自然资源主管部门、矿山安全监管机构发布的官方文件、行业标准及地方矿山管理细则，更新节奏随政策发布节点调整。文档按文件编号、发布单位、生效日期、条款内容、适用矿区类型结构化存储，字段包含文件编号、发布主体、生效时间、适用场景、处罚与合规条款，单篇文档长度从数百字符到数万字符不等，部分临时通知仅包含数十条合规要点。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
政策文件的长度跨度大，部分合规条款文档长达数万字符，多轮对话的上下文处理需基于`messages`参数传递历史对话内容，避免截断关键合规条款。政策层级包含国家、省级、市级监管要求，多轮对话需通过`chatId`绑定当前会话的政策查询上下文，避免跨层级规则混淆。文档包含结构化字段，提示词需明确要求返回对应字段的精准内容，避免泛泛回答。矿山采选政策存在专属术语，多轮对话需通过`variables`传递前置的矿区类型等参数，保留术语上下文确保后续提问的一致性。数据更新无固定周期，提示词需引导用户确认查询内容的生效时间，避免引用过期政策。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 字符 | 适配矿山采选政策文档的长文本长度，保留多轮对话的前置上下文 |
| 单次搜索上限 | 前8条 | 覆盖国家、省级、市级不同层级的政策文件，避免遗漏跨层级规则 |
| 问题优化 | 开启 | 针对矿山采选政策的专属术语优化提问，提升检索精准度 |
| 输入引导 | 开启，预设「请说明需查询的政策文号或具体合规场景」 | 引导用户明确查询范围，减少模糊提问 |
| 自定义词库 | 导入矿山采选政策专属术语表 | 统一政策术语的语义理解，避免术语歧义 |
| 响应token上限 | 2000–3000 token | 适配长政策条款的完整回复，避免截断关键内容 |

## 容易做错的三处
- 现象：调试预览时输入引导配置未生效，界面无预设提示文案。原因：自定义词库导入后未同步刷新输入引导配置，或输入引导的触发逻辑未绑定对应会话。
- 现象：部分复杂政策问题的响应长度仅200 token，与设置的3000以上上限不符。原因：多轮对话的`messages`参数未正确截断过期上下文，导致上下文占用过多token配额，剩余配额不足支撑长回复。
- 现象：无法将对话过程中的政策条款添加到知识库。原因：未开启对话内容的自动归档开关，或归档路径未绑定矿山采选政策的专属知识库分类。

## 怎么确认配好了
- 进入调试预览界面，查看输入框是否显示预设的引导文案，确认输入引导配置生效。
- 发起包含多层级政策查询的提问，检查返回内容是否覆盖不同层级的监管要求，确认单次搜索上限配置合理。
- 查看会话的`variables`参数是否包含当前矿区类型等前置信息，确认上下文绑定逻辑正确。
- 发起长文本政策查询，检查响应长度是否符合设置的token上限，同时查看`messages`参数是否正确传递了历史对话内容，确认上下文处理正常。
- 检查自定义词库是否已导入矿山采选专属术语，确认术语识别逻辑生效。
