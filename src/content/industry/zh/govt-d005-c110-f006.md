# 矿山采选的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
矿山采选领域的政策与制度依据数据，主要来源于自然资源部、应急管理部及各省市矿山监管部门的官方公开文件。数据更新随新政策出台、旧政策修订同步进行，无固定周期。文档结构包含政策文号、发布单位、发布日期、生效条款、附件清单等固定字段，处罚金额以人民币元为单位，开采限额以吨为单位。文档格式多为PDF、Word或网页公示版，长度差异显著，短则数百字的通知类文件，长则数万字的安全规程类文档。

## 这些特征在「引用来源与溯源」这一环带来什么约束
矿山采选政策数据的官方文号、发布主体等固定字段，要求溯源环节必须精准匹配文档标识，不能仅展示文本内容。文档长度差异大，长文档需合理分块避免信息断裂，短文档需防止过度拆分导致语义丢失。政策存在时效性与区域差异，检索时需过滤失效政策、匹配属地监管要求。附件类政策文档需关联主文档进行溯源，进一步增加了引用匹配的复杂度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 矿山采选政策多为条款式结构，800–1200字符可覆盖单条完整款目，避免拆分断裂 |
| 重叠长度 | 100–150 字符 | 政策条款间存在逻辑关联，重叠可保留上下文衔接，防止跨块信息丢失 |
| `quoteMaxToken` | 2000–3000 token | 政策引用需完整展示文号、发布单位等核心信息，该区间可覆盖单份政策核心内容 |
| 重排 | 按发布时间倒序 | 矿山采选政策时效性强，新发布政策优先于旧政策，符合当前监管要求 |
| `detail` | 开启 | 需展示政策文号、发布单位等溯源元数据，开启后可返回完整文档信息 |
| `responseData` | 返回元数据+原文片段 | 用户需核对政策来源，需同时展示文档标识与引用内容 |

## 容易做错的三处
- 现象：上下文引用中无法渲染Markdown格式的政策条款。原因：政策文档中的Markdown标记未在知识库预处理阶段正确转义，或配置未开启原生文本渲染。
- 现象：部分提问无法匹配到知识库中的政策文件。原因：分块长度设置过大，导致政策条款未被完整切分，或相似度阈值设置过高，过滤了符合要求的匹配文档。
- 现象：引用结果未显示政策文号等溯源字段。原因：`detail`配置项未开启，仅返回了文本片段，未携带元数据信息。

## 怎么确认配好了
- 上传一份标准矿山采选政策文档，在FastGPT v4.17.0版本的知识库后台执行分块预览，确认单块长度符合设置范围，无条款拆分断裂情况。
- 发起一条针对具体政策文号的提问，查看返回结果中是否包含政策发布单位、文号等元数据，确认`detail`配置生效。
- 发起多条不同时效性的政策相关提问，确认返回结果按发布时间倒序排列，新发布政策优先展示。
- 检查引用模块的展示内容，确认Markdown格式的条款已正确渲染，无未转义的标记字符。
