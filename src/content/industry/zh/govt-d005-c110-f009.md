# 矿山采选的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
矿山采选的政策与制度依据数据，来源为国家及地方自然资源、应急管理部门公开公文，以及行业协会发布的规范性文件。文档以正式公文为载体，包含文件编号、发布单位、生效日期、条款层级（条/款/项）、适用矿种与开采方式等字段，内容按监管环节（开采、选矿、环保、安全）分类。数据更新随国家及地方监管政策调整，无固定周期，新增或修订政策会同步覆盖全量相关条款。

## 这些特征在「模型接入与配置」这一环带来什么约束
政策文档的层级化结构与细分场景标签，要求检索时需匹配矿种、开采方式等元数据，避免跨场景引用错误。单篇政策公文内容较多，需控制上下文加载的有效范围，防止超出模型上下文限制。政策更新无固定周期，需支持快速增量同步配置，同时确保检索逻辑与最新政策字段对齐。条款的严谨性要求输出必须关联原文片段，不可生成无依据内容，因此需严格配置引用相关参数。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的模型接入逻辑制定：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 矿山采选政策文档单篇常包含数十条款，需完整加载单份公文上下文，避免截断关键监管要求 |
| `maxTokens` | 2000–3000 token | 回答需覆盖政策条款细节，同时控制输出长度符合问答场景，按实测标定输出阈值 |
| `quoteMaxToken` | 1500 token | 需精准引用政策原文片段，限制引用片段长度以保证上下文连贯性，同时不超出模型支持范围 |
| `temperature` | 0.1–0.3 | 政策问答需严谨准确，降低随机性以避免生成不符合监管要求的内容 |
| `AIPROXY_API_ENDPOINT` | 对应平台专属接入地址 | 需匹配FastGPT官方提供的代理地址，保证模型调用链路稳定 |
| `AIPROXY_API_TOKEN` | 绑定专属密钥 | 确保调用权限唯一，防止未授权访问，符合国央企数据安全要求 |

## 容易做错的三处
- 现象：模型调用耗时显示异常，在线场景仅展示首token耗时，离线场景展示总运行时间，无法统一查看首token耗时。原因：未调整统一的耗时统计配置，FastGPT默认按部署模式区分耗时展示逻辑，未针对政策问答场景设置统一的统计维度。
- 现象：回答引用的政策条款与目标矿山的开采方式不匹配。原因：未配置元数据过滤规则，检索时未筛选适用露天/地下矿的政策内容，导致跨场景引用错误。
- 现象：模型生成的政策解读超出原文范围。原因：`temperature`设置过高，模型生成了无原文依据的扩展内容，不符合政策问答的严谨性要求。

## 怎么确认配好了
- 发起针对特定矿种、开采方式的政策问答，核对回答中引用的政策条款是否与目标场景匹配。
- 查看模型调用日志，确认上下文加载的token数量未超出配置的`maxContext`阈值。
- 检查耗时统计面板，确认所有场景下的耗时展示维度保持一致。
- 验证生成内容是否附带原文引用片段，确认`quoteMaxToken`配置生效。
