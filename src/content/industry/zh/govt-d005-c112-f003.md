# 粮食储备的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
粮食储备的政策与制度依据数据，主要来自国家粮食和物资储备局官方发布的规范性文件、地方储备粮管理条例、年度储备轮换计划公告。数据更新节奏随政策修订触发，无固定周期。文档结构统一包含文号、发布单位、生效日期、条款内容、适用区域、执行标准等字段，字段单位明确，如储备规模以万吨为单位，轮换周期以年为单位，补贴标准以元/吨为单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
粮食储备政策文档篇幅较长，单份文件可能包含数十条条款，多轮对话中需保留上下文以关联用户追问的具体条款，因此需要限制过长的历史消息避免干扰当前查询。字段单位明确的特征要求提示词必须强制对齐单位表述，避免出现单位混淆。数据更新无固定周期，提示词需明确要求仅使用当前绑定的本地知识库文件作答，不得依赖训练数据中的过时内容。多轮对话中用户可能追问政策的适用区域、生效时间等细分信息，需通过`messages`参数保留历史交互内容，确保回答的关联性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 适配单份粮食储备政策文件的常见篇幅，避免截断关键条款内容 |
| 历史对话保留轮次 | 前5–10 轮 | 覆盖用户多轮追问的常见范围，避免过多历史消息占用上下文空间 |
| `variables`参数配置 | 绑定用户查询的区域、粮食品类等参数 | 实现动态代入用户的具体查询条件，提升回答的针对性 |
| `messages`参数配置 | 按对话轮次追加历史消息 | 保留上下文关联，确保多轮对话中能关联之前提及的政策条款 |
| `chatId`参数配置 | 作为对话与日志的独立标识 | 区分不同用户的对话记录，避免删除对话时连带清除系统日志 |
| 提示词模板配置 | 固定包含“仅使用当前绑定的粮食储备政策文件作答” | 确保回答来源合规，避免引用外部无关内容 |

## 容易做错的三处
- 现象：文本内容提取模块中，代码块返回undefined。原因：未通过`variables`参数正确绑定提取的代码块变量，导致上下文未传递目标参数。
- 现象：用户删除对话后，系统日志同步消失。原因：错误将`chatId`同时作为对话和日志的唯一标识，删除对话时连带清除了关联日志。
- 现象：多轮对话中无法关联之前提及的政策条款编号。原因：未启用`messages`参数的历史消息追加配置，仅保留当前单轮查询内容，丢失上下文关联逻辑。

## 怎么确认配好了
- 发起单轮查询，检查回答是否仅引用当前绑定的粮食储备政策文件，未出现外部无关内容。
- 发起两轮连续追问，检查系统是否能关联第一轮提及的政策条款，无需重复说明背景。
- 测试删除单条对话记录，检查系统日志是否仍保留该对话的交互数据。
- 输入带区域、粮食品类参数的查询，检查回答是否正确代入了`variables`绑定的参数内容。
