# 船舶制造的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
数据来源为船舶工业行业主管部门、海事管理机构发布的法定造船规范、国央企造船业务的内部合规制度文件。更新节奏随行业政策调整、新造船标准出台不定期更新。单篇文档多为结构化文本，包含文号、发布单位、生效日期、条款编号、具体技术要求等字段，涉及的单位包括船舶吨位、主机功率、建造周期相关的标准计量单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据的结构化属性要求索引需支持按条款编号、生效日期等元数据进行过滤召回，确保精准定位对应政策条款。专业术语（如船舶吨位、主机功率）的存在要求向量模型适配工业领域语义，避免语义偏差。不定期更新的特性要求索引支持增量同步，避免全量重建带来的资源消耗。单篇文档篇幅较长，分块时需保留语义单元的完整性，防止政策条款被割裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配船舶制造政策文档的结构化篇幅，保留单条款完整语义 |
| 重叠长度 | 200–300 字符 | 避免分块后语义断裂，确保跨块政策条款的上下文连贯性 |
| `maxToken` | 4096 token | 适配多数开源向量模型的输入上限，覆盖单条政策条款的核心内容 |
| `defaultToken` | 模型最大输入的 70% | 预留模型处理冗余空间，避免截断关键政策信息 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性结果，确保召回政策条款的精准性 |
| 单次搜索上限 | 前 10 条 | 控制召回结果规模，避免上下文过载影响回答质量 |

## 容易做错的三处
- 现象为配置百度embedding-v1时返回404报错，原因是未正确配置模型的调用密钥与接口地址，导致无法正常请求模型服务。
- 现象为无GPU环境下部署向量模型后无法在平台添加，原因是未开启模型的CPU兼容运行模式，或未正确安装模型运行所需的系统依赖。
- 现象为本地部署的索引模型添加后出现启动超时报错，原因是模型初始化所需的资源不足，或Docker容器的内存配额设置过低。
