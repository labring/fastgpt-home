# 船舶制造的政策与制度依据问答：多轮对话与提示词

## 这个品类的数据长什么样
船舶制造领域的政策与制度依据数据，主要来自工业和信息化部、交通运输部海事局、中国船级社发布的官方规范文件、行业标准与监管要求。数据按年度或专项修订更新，单份文档多为结构化格式，包含文件文号、发布单位、生效日期、适用船型、技术参数阈值等字段，字段单位多涉及总吨、千瓦、米等船舶行业专用单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
船舶制造政策数据的专用单位、多来源层级属性与长文档结构，会对多轮对话带来三重约束。第一，专用单位要求提示词中明确标注需匹配总吨、千瓦等行业术语，避免参数混淆导致回答偏差。第二，多部门发布的政策存在优先级差异，多轮对话需在上下文记忆中区分发布主体与生效时间，确保回答符合最新监管要求。第三，单份政策文档篇幅较长，多轮对话的上下文窗口需适配长文本召回，避免关键政策条款被截断遗漏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | `8000–12000 字符` | 适配船舶政策文档的单份篇幅，避免关键条款被截断 |
| 问题优化 | 开启 | 自动拆解船舶行业专业提问，匹配多轮对话的上下文逻辑 |
| 输入长度限制 | `1000 字符` | 提前拦截超长提问，避免触发无提示报错 |
| `chatId` | 按会话生成唯一标识 | 区分不同多轮会话的上下文，防止会话数据混淆 |
| `messages` | 按会话历史拼接完整上下文 | 传递前序提问与政策引用信息，支撑多轮逻辑关联 |
| `variables` | 传入船舶类型、生效日期等行业变量 | 精准匹配对应船型的政策条款，提升回答准确性 |

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 容易做错的三处
- 现象：多轮对话中无法保留拆解后的子问题，下一轮回复未关联初始提问。原因：未按`messages`要求拼接完整会话上下文，仅传递当前单次提问内容。
- 现象：对话请求接口返回结果无cite引用id字段。原因：未在`variables`中传入政策文档的元数据标识，未配置关联引用的参数逻辑。
- 现象：输入文本超出上限后直接抛出报错无拦截提示。原因：未设置输入长度校验规则，未提前截断超长内容或引导调整提问。

## 怎么确认配好了
- 发起包含船舶专用术语的多轮提问，验证下一轮回复是否关联前序问题的拆解内容。
- 查看接口返回结果，确认包含cite引用id字段。
- 输入超出预设长度的提问，验证系统是否提前拦截并给出调整提示。
- 验证指定会话的对话记录可通过`chatId`标识完成删除操作。
