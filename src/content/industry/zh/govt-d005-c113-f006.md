# 船舶制造的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
船舶制造领域的政策与制度依据数据，主要来自工业和信息化部、交通运输部、国家海事局的官方公开文件，以及中国船舶工业行业协会发布的行业规范。数据更新随新政策发布触发，无固定周期，单份文档多包含政策文号、发布单位、生效日期、适用船型范围、核心条款内容等字段，部分技术类政策会附带总吨、载重吨、建造周期等量化指标，文档结构层级清晰，条款分章节标注。

## 这些特征在「引用来源与溯源」这一环带来什么约束
官方多部门来源要求溯源环节需验证引用内容的发布主体合规性，仅允许调用公开官方文件片段。无固定更新周期则要求配置定时同步机制，确保知识库内政策始终为最新生效版本。文档附带文号、生效日期字段，要求溯源结果需同步展示对应政策编号与生效时间，避免引用过期条款。适用船型、量化指标等专属字段，要求召回时需绑定船型、总吨等筛选条件，避免召回不匹配的政策内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配单份船舶制造政策核心条款的平均长度，避免截断关键合规要求 |
| 最大引用条数 | 前3–5条 | 船舶制造政策文档内容密集，过多引用会导致回答冗余 |
| `detail` | 开启完整溯源信息 | 要求展示政策文号、发布单位与生效日期，匹配文档固有字段 |
| `responseData` | 仅返回官方来源片段 | 过滤非官方的政策解读内容，确保引用合规性 |
| 单次召回上限 | 前10条 | 覆盖同生产场景下的多份关联政策，避免遗漏合规依据 |
| 溯源响应超时 | 60秒 | 保障官方文件检索的稳定性，避免因等待过长导致流程中断 |

## 容易做错的三处
- 现象：回答未优先引用知识库中综合排名第一的政策文档。原因：未配置按生效时间倒序的重排规则，仅按初始召回相似度排序，导致旧政策优先被选中。
- 现象：回答中引用的政策文档数量超出预期。原因：未设置合理的最大引用条数，或召回上限配置过高，导致冗余内容被纳入回答。
- 现象：溯源结果未展示政策文号与生效日期。原因：未开启`detail`配置项，或未绑定文档字段提取规则，无法匹配政策类数据的专属溯源字段。

## 怎么确认配好了
- 上传一份最新的船舶制造政策文档，发起相关提问，检查回答中展示的溯源信息是否包含政策文号与生效日期。
- 调整最大引用条数配置，发起多次同类提问，核对回答中引用的文档数量是否符合预期。
- 模拟旧政策与新政策的召回场景，检查回答是否优先展示生效时间更近的政策内容。
- 查看系统日志，确认每次溯源请求均能成功获取到对应政策文档的元数据，无缺失字段。
