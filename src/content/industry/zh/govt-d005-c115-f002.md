# 轨道交通装备的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
轨道交通装备的政策与制度依据数据，主要来源于国家铁路局、工业和信息化部及中国轨道交通装备行业协会的官方公开文件，以及企业内部合规管理文档。政策文件随国家监管要求不定期更新，行业通用标准每1-2年完成一次修订，企业内部文档随产品迭代同步调整。文档多为结构化条款形式，包含发布文号、生效日期、适用场景、具体要求等字段，涉及的单位包括公里、小时、台、批次等。

## 这些特征在「向量模型与索引」这一环带来什么约束
轨道交通装备政策文档的多来源属性，导致数据格式存在差异，部分文件为扫描版PDF，需额外配置OCR解析流程，且不同来源文档的字段命名不统一，索引前需完成字段标准化处理。政策更新无固定周期，增量索引需支持按发布日期触发同步，避免全量索引重复消耗资源。文档多为长结构化条款，分块时需保留条款完整性，防止拆分后语义断裂。专业术语如“走行公里”“检修周期”的存在，要求向量模型适配轨道交通装备领域的专业语义嵌入。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配轨道交通装备政策文档的条款长度，避免拆分单个完整条款 |
| 重叠长度 | 100–150 字符 | 保留跨分块的上下文关联，确保长条款的语义连贯性 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 过滤低匹配度的非相关政策条款，适配专业术语的语义匹配精度 |
| 单次搜索上限 | 前 8 条 | 平衡召回范围与上下文窗口限制，适配政策问答的精准性需求 |
| `maxToken` | 4000 token | 适配FastGPT v4.17.0的上下文窗口上限，确保召回内容可完整带入推理 |
| `defaultToken` | 200 token | 控制单条召回内容的输出长度，避免冗余信息干扰问答逻辑 |

## 容易做错的三处
- 现象：本地部署FastGPT后，新建知识库时未显示图片索引配置选项，上传含图片的政策文档后无法提取图片文本。原因：未在部署配置中启用图片索引相关模块，或本地镜像未包含该功能的依赖组件。
- 现象：召回的政策条款与查询问题匹配度偏差较大，出现与轨道交通装备无关的通用政策内容。原因：相似度阈值设置不合理，且未针对专业术语调整匹配精度。
- 现象：批量上传年度政策文件时，索引任务出现超时报错，任务状态显示失败。原因：分块长度设置过大，超出`maxToken`对应的处理上限，导致单次处理耗时过长触发超时。

## 怎么确认配好了
- 上传一份含扫描件图片的轨道交通装备政策文档，查看知识库解析结果中是否包含图片内的文本内容，确认OCR与图片索引配置生效。
- 发起一条针对具体政策条款的查询，核对召回结果的条数是否符合单次搜索上限的设置，确认搜索配置生效。
- 调整分块长度与重叠长度参数后，上传长条款文档，查看分块结果是否保留了单个条款的完整性，确认分块配置生效。
- 查看FastGPT v4.17.0的系统日志，确认向量模型加载正常，无专业术语嵌入失败的报错信息。
