# 轨道交通装备的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
轨道交通装备领域的政策与制度依据数据，主要来源于国家铁路局、工业和信息化部发布的行业标准、行政规范性文件及装备准入公告。数据更新随政策发布节奏不定期调整，单份文档多为结构化长文本，包含政策文号、发布主体、生效日期、适用装备类型、条款细则等字段，其中条款细则部分常包含多段技术要求与执行规范，单位多采用国标统一标注的毫米、千米/小时、吨等计量标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
轨道交通装备政策数据的长文本结构，要求模型接入时需适配长上下文处理能力，避免因单段输入过长触发截断。政策文档的结构化字段要求配置时需明确召回规则，仅提取与装备类型匹配的条款内容。不定期的更新节奏，要求配置中预留数据同步的灵活调整空间，适配新增政策的快速接入。同时，政策条款中的专业计量单位，要求模型输出需严格遵循国标标注习惯，需在配置中指定专业术语的识别规则。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配轨道交通政策文档的长文本结构，避免核心条款被截断 |
| `maxTokens` | 2000–3000 token | 匹配单段政策条款的输出长度，确保完整返回技术要求 |
| `quoteMaxToken` | 1500–2000 字符 | 限定召回引用的政策文本长度，避免上下文过载 |
| `toolChoice` | auto | 适配政策问答中需要调用知识库召回的场景，自动选择工具调用 |
| `temperature` | 0.1–0.3 | 保持政策内容的准确性，避免生成不符合规范的解读 |
| `AIPROXY_API_ENDPOINT` | 按部署的OneAPI地址填写 | 对接本地部署的大模型接口，确保请求路由正确 |

## 容易做错的三处
- 调用HTTP API接入政策数据源时，返回的长政策文本被一次性传入模型触发上下文溢出。未配置长文本分段处理逻辑，未按单段适配的长度拆分后逐段发送。
- 创建知识库时无法选择本地部署的ChatGLM2模型，界面显示无可用模型选项。未在FastGPT配置中正确关联OneAPI的接入密钥与端点，或模型未按要求注册到OneAPI服务中。
- 配置`toolChoice`为auto后，模型未自动触发知识库召回，返回泛泛的回答。未在系统提示词中明确指定政策问答需优先调用知识库，或`toolChoice`的配置未与模型能力匹配。

## 怎么确认配好了
- 上传一份轨道交通装备政策文档到知识库，执行单次问答，检查返回内容是否包含文档中的准确条款。
- 查看模型调用日志，确认`maxContext`和`maxTokens`的参数值符合配置要求，无上下文截断报错。
- 测试调用本地部署的模型接口，确认请求能正常发送并返回有效响应，无认证或路由错误。
- 调整`temperature`参数后，检查回答的严谨性变化，确认参数生效。
