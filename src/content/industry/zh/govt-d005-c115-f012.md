# 轨道交通装备的政策与制度依据问答：部署与升级

本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
轨道交通装备领域的政策与制度依据数据，主要来源于国家铁路局、交通运输部、工业和信息化部发布的官方公告、行业强制标准及企业内部合规手册。数据更新无固定周期，新国标落地、行业监管要求调整时同步更新。单份文档多包含政策文号、发布单位、生效日期、适用装备类型、技术参数阈值、合规判定条款等字段，字段单位多涉及公里/小时、兆帕、额定功率等工程类计量标准。

## 这些特征在「部署与升级」这一环带来什么约束
轨道交通装备政策数据来源分散，包含官方公开文档与企业内部合规材料，部署时需适配多源数据接入配置，且需满足内网部署的合规要求。文档包含固定格式的政策字段，部署时的文档解析模块需保留文号、生效日期等关键信息，避免分块破坏核心识别单元。数据更新无固定周期，升级环节需配置可调整的同步触发规则，适配内网环境下的离线数据更新流程。同时工程类单位的标准化解析，需预设匹配规则避免参数识别偏差。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@192.168.x.x:27017/fastgpt?authSource=admin` | 适配内网部署场景，存储轨道交通装备政策文档的结构化元数据与向量库索引 |
| `REDIS_URL` | `redis://:自定义密码@192.168.x.x:6379/0` | 缓存高频查询的政策问答对，降低重复计算开销 |
| `DB_MAX_LINK` | `1000 条` | 限制单批次导入的政策文档数量，避免内网数据库连接过载 |
| `STORAGE_S3_ENDPOINT` | `http://192.168.x.x:9000` | 适配内网存储需求，存储上传的政策文档原始文件与解析后片段 |
| `ROOT_KEY` | `自定义高强度随机字符串` | 保障内网部署的后台操作权限安全，符合国央企内部安全规范 |
| `FE_DOMAIN` | `http://内网服务域名:3000` | 配置内网可访问的前端访问地址，确保内部用户正常使用问答服务 |

## 容易做错的三处
- 现象：启动后后台服务持续重启，日志提示数据库连接失败。原因：未配置内网可访问的`MONGODB_URI`参数，使用了公网数据库地址导致内网环境下无法建立连接。
- 现象：上传轨道交通装备政策文档时，界面提示embedding error。原因：未预设工程类单位的解析匹配规则，文档中的专业参数无法被正确提取，导致向量生成失败。
- 现象：尝试配置外部搜索插件后服务无法正常响应。原因：内网环境下未关闭外网依赖的插件配置，导致服务尝试连接公网资源被阻断。

## 怎么确认配好了
- 执行内网环境下的数据库连接测试，验证`MONGODB_URI`与`REDIS_URL`配置的连通性，确认无超时或权限拒绝报错。
- 上传一份标准轨道交通装备政策文档，触发解析与向量生成流程，检查解析后文档的字段完整性，确认无关键信息丢失。
- 配置内网访问地址，通过内部终端访问前端页面，验证问答服务可正常加载并响应基础查询。
- 手动触发一次数据同步任务，检查存储路径下的文档备份是否正常生成，确认`STORAGE_S3_ENDPOINT`配置生效。
