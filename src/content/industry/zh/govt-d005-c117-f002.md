# 通信铁塔与基础设施的政策与制度依据问答：向量模型与索引

## 这个品类的数据长什么样
通信铁塔与基础设施的政策与制度依据数据，主要来自工业和信息化部、住房和城乡建设部发布的通信基础设施建设、运维、安全相关政策文件，以及通信铁塔运营主体的内部运维、建设制度文档。数据更新节奏随正式政策发布周期调整，无固定固定周期。文档多为章节式结构，包含政策文号、发布主体、适用范围、条款细则、实施要求等字段，字段以文本型为主，单位多为“项”“条”“区域”等，文档长度跨度较大，从数百字的专项通知到数万字的完整制度汇编。

## 这些特征在「向量模型与索引」这一环带来什么约束
政策文档的长文本跨度要求向量索引的分块逻辑需兼顾完整性与语义连贯性，避免截断核心政策条款，部分文档包含嵌套的子条款，分块时需保留层级关联。文档中包含政策文号、发布主体、适用范围等元数据字段，要求索引同时支持内容语义召回与元数据精准匹配，提升问答的针对性，避免召回无关政策。无固定更新周期的特征，要求索引支持增量更新能力，避免每次更新都全量重建索引，降低计算资源消耗。文本型字段为主的结构，要求向量模型适配通用文本语义理解，无需针对结构化数值字段做特殊适配，可直接基于文本内容生成向量。

## 配置怎么定
本页面配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 政策文档多为长文本，该区间可保留条款完整性，避免截断核心政策表述 |
| 重叠长度 | 150–200 字符 | 减少分块间的语义断层，提升长政策条款的召回连贯性 |
| 相似度阈值 | 0.72–0.78 | 政策文本语义严谨，需平衡召回精度与覆盖范围，按实测标定 |
| 单次搜索上限 | 前8条 | 政策问答需精准匹配条款，过多结果会干扰答案生成 |
| `maxToken` | 16000 token | 支持召回多段政策片段拼接后的上下文长度，适配完整条款引用需求 |
| `defaultToken` | 4096 token | 匹配常规政策问答的单轮输入输出长度，避免上下文溢出 |

## 容易做错的三处
- 索引后召回的政策条款不完整，仅返回片段开头内容。原因是分块长度设置过小，截断了完整的政策条款细则。
- 调用时返回“上下文长度超限”报错。原因是`maxToken`设置未匹配召回片段的总长度，超出模型支持范围。
- 上传更新后的政策文档后，新内容无法被正常召回。原因是未配置适配政策文档非固定更新节奏的增量索引逻辑，错误使用全量索引触发规则。

## 怎么确认配好了
- 上传一段典型的政策长文档，查看分块预览界面是否保留完整条款，无强制截断情况。
- 输入政策相关的具体问题，查看召回结果条数是否符合单次搜索上限的设置。
- 发起一次完整的问答调用，确认无上下文长度超限的报错信息。
- 上传更新后的政策文档，验证增量索引是否正常生效，新上传的政策内容可被正常召回。
