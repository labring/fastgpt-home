# 通信铁塔与基础设施的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
通信铁塔与基础设施领域的政策与制度依据数据，主要来源于工业和信息化部、住房和城乡建设部等官方部门的公开规章、行业标准及地方配套文件。数据更新节奏以季度为单位，伴随新的行业规范出台同步更新。文档采用标准公文格式，包含政策文号、发布单位、生效日期、适用范围、具体条款等字段，条款内容以章节编号为单位拆分，单位多采用“第X条”“第X款”的格式，单条条款长度多在500至800字符区间内。

## 这些特征在「引用来源与溯源」这一环带来什么约束
官方来源的固定字段要求溯源时必须精准匹配政策文号、发布单位等标识，否则无法完成有效溯源。季度级的更新节奏要求知识库同步周期需匹配该频率，避免引用过期失效的政策内容。标准公文的章节结构要求引用分块时需保留章节编号与条款归属，否则溯源结果无法对应到具体政策条款。单条条款的长度限制要求引用token预留足够空间，避免截断关键内容导致溯源信息不完整。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 字符 | 通信铁塔领域政策文档单条条款长度多在500-800字符，预留足够空间保留完整引用内容 |
| `responseData` | 包含政策文号、发布单位、生效日期、条款原文 | 政策溯源需明确来源标识，需返回指定核心字段用于快速定位政策依据 |
| `detail` | 开启 | 政策条款需展示具体原文内容，开启后可返回完整引用片段供用户核对 |
| 引用召回上限 | 前3条 | 单条政策咨询通常关联2-3项相关条款，召回过多会导致上下文冗余，影响回复清晰度 |
| 知识库同步周期 | 7天 | 通信铁塔领域政策更新频率多为每季度一次，7天同步周期可及时覆盖新发布的政策内容 |
| 引用展示开关 | 按需开启 | 可根据业务需求控制是否在回复中展示引用来源的具体信息 |

## 容易做错的三处
- 现象：调用后返回`quote type error`报错；原因：未正确配置`responseData`指定的引用字段格式，输入了非允许的字段名或字段格式不符合要求。
- 现象：引用来源下拉菜单仅显示单条选项；原因：未开启`detail`配置，仅返回单条核心字段，未展开多条款的引用内容。
- 现象：回复中自动展示非政策类的冗余引用内容；原因：未限定`responseData`的召回范围，导致召回了非通信铁塔政策领域的文档内容。

## 怎么确认配好了
- 发起一条针对通信铁塔政策的测试提问，查看回复中是否包含政策文号、发布单位等溯源字段。
- 检查回复中引用的内容长度是否符合`quoteMaxToken`的配置范围，未出现截断情况。
- 查看引用来源下拉菜单是否显示多条相关政策条款，覆盖测试提问涉及的政策范围。
- 验证是否可以通过配置调整引用展示的开启与关闭，符合业务需求。
