# 通信铁塔与基础设施的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
通信铁塔与基础设施的政策数据主要来源于工业和信息化部、住房和城乡建设部发布的通信基础设施建设、运维相关规范性文件，以及中国铁塔相关内部政策手册与行业运维规程。文档多为章节式结构，包含政策编号、发布单位、生效日期、适用场景、执行要求等字段，涉及建设高度、覆盖范围、运维周期等单位。数据更新节奏随国家政策调整或行业标准更新同步进行，无固定周期。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「模型接入与配置」这一环带来什么约束
政策文档的长文本结构要求模型接入时需适配大上下文处理，避免截断关键政策条款；结构化字段（如政策编号、生效日期）要求配置支持精准字段匹配的逻辑，保障回答的准确性；无固定更新节奏要求配置支持灵活的知识库同步机制，及时更新最新政策内容；多类单位（如米、千瓦、运维周期）的存在要求模型具备单位识别与校验能力，避免回答出现单位混淆问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 通信铁塔政策文档多为长文本，需容纳完整政策条款与多轮对话的历史上下文 |
| `maxTokens` | `2000–3000 token` | 政策问答需覆盖条款细节，同时控制输出长度 |
| `quoteMaxToken` | `1500 字符` | 需保留政策原文片段的完整语义，避免截断关键依据内容 |
| `temperature` | `0.2–0.4` | 政策问答需严格匹配原文，降低随机性，保证回答准确性 |
| `toolChoice` | `auto` | 需根据用户问题自动选择是否调用知识库或工具，适配多场景政策查询 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写官方指定端点 | 确保模型调用的网络路径正确，避免连接失败 |
| `AIPROXY_API_TOKEN` | 填写对应模型的有效密钥 | 完成模型调用的身份验证，保障访问权限 |

## 容易做错的三处
- 现象：本地部署的FastGPT环境中，新增模型后测试时返回403 status code (no body)，原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致身份验证失败或路径错误。
- 现象：使用API发布渠道访问工作台创建的应用时，多轮对话上下文丢失，回答无法延续之前的查询逻辑，原因：未正确设置`maxContext`参数，导致上下文窗口不足以容纳多轮交互的历史内容。
- 现象：通过Function CALL调用数据后，无法引用数据库原文片段，仅返回概括性内容，原因：未配置`quoteMaxToken`参数以保留原文长度，或未开启工具调用后的原文引用逻辑。

## 怎么确认配好了
- 发起通信铁塔建设政策的单轮查询，验证模型返回的内容包含准确的政策条款与原文片段，核对`quoteMaxToken`的保留效果。
- 发起连续多轮政策查询，验证上下文被正确加载，回答延续之前的查询逻辑，核对`maxContext`的配置效果。
- 提交错误的API密钥或端点，验证系统返回对应错误，核对`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置正确性。
- 调整`temperature`参数至0.1，验证回答的严谨性，确认参数对回答随机性的控制效果。
