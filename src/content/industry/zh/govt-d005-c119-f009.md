# 钢铁冶炼的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
钢铁冶炼的政策与制度依据数据，主要来源于国务院国资委、工信部、生态环境部及中国钢铁工业协会发布的正式文件与行业标准。更新节奏随政策修订不定期，行业通用标准每半年更新一次。文档结构包含政策文号、发布单位、生效日期、核心条款、适用冶炼环节（烧结、炼铁、炼钢等），字段包含能耗限额、污染物排放指标、产能管控要求，单位多采用千克标煤/吨钢、毫克/立方米等行业专用单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
钢铁冶炼政策数据的专业单位、分环节条款结构，要求模型接入时需适配行业专用术语识别。长文本政策条款需要配置足够的上下文容纳量，避免截断核心管控要求。官方数据源的不定期更新节奏，要求知识库同步与模型上下文刷新机制匹配，确保问答内容时效性。多字段的政策结构，要求召回环节优先匹配冶炼环节与政策条款的对应关系，避免无关内容干扰问答准确性。同时，本地部署模型的接入需求，要求配置项需兼容非公有云的API接口与身份验证规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配钢铁冶炼政策长文本条款，避免截断核心管控要求 |
| `maxTokens` | 2000–3000 token | 保证政策问答的完整回复长度，覆盖多条款解释 |
| `quoteMaxToken` | 1500–2000 字符 | 限定单条引用的政策文本长度，确保引用精准且不冗余 |
| `temperature` | 0.1–0.3 | 降低随机性，保证政策解读的准确性 |
| `AIPROXY_API_ENDPOINT` | 本地部署模型的API地址 | 适配本地化模型接入需求，符合FastGPT v4.17.0的配置规范 |
| `AIPROXY_API_TOKEN` | 本地模型生成的访问密钥 | 完成身份验证，避免未授权访问报错 |

## 容易做错的三处
- 现象：接入本地部署的重排模型后测试返回401 unauthorized报错。原因：未正确配置`AIPROXY_API_TOKEN`，与本地模型生成的访问密钥不匹配。
- 现象：模型回复截断长政策条款，无法覆盖完整管控要求。原因：`maxContext`配置值过小，未适配钢铁冶炼政策的长文本特征。
- 现象：召回的政策条款与目标冶炼环节不匹配，出现无关行业的政策内容。原因：未针对钢铁冶炼的分环节字段配置精准召回规则，导致召回范围过大。

## 怎么确认配好了
- 访问配置的`AIPROXY_API_ENDPOINT`，使用配置的`AIPROXY_API_TOKEN`发起测试请求，确认返回正常响应码。
- 导入单条长政策文档，触发政策问答测试，检查回复未出现文本截断，确认`maxContext`与`maxTokens`配置合理。
- 针对特定冶炼环节（如炼铁）发起政策问答，检查召回的条款均对应目标冶炼环节，确认召回规则生效。
- 调整`temperature`参数，发起两次相同问题的测试，检查两次回复的一致性，确认参数配置生效。
