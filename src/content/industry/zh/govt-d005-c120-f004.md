# 铁路运营的政策与制度依据问答：工作流编排

## 这个品类的数据长什么样
铁路运营的政策与制度依据数据主要来源于中国国家铁路集团有限公司官方发布的规章、铁路行业标准TB/T系列文件、各铁路局的运营实施细则及临时管控通知。数据更新节奏为常规政策按季度同步，临时管控要求随发布实时更新。文档结构固定包含发布文号、发布单位、生效日期、条款正文、适用运营场景字段，字段以条、款、项为层级划分单位，单份文档长度从数百字符到数万字符不等。

## 这些特征在「工作流编排」这一环带来什么约束
铁路运营政策文档的长度跨度大、场景细分多且存在明确生效时效限制，为工作流编排带来多重约束。长文档需适配合理的分块规则，避免拆分后上下文逻辑断裂。多场景政策覆盖客运、货运、调度、安全监管等多个运营环节，需配置场景过滤节点匹配当前执行的运营任务。政策生效日期要求嵌入时间校验环节，仅调用处于生效期内的政策内容。多源数据的格式差异，需配置统一的文档解析节点标准化文号、生效日期等核心字段。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 文档分块长度 | 800–1200 字符 | 适配铁路政策文档的平均长度，避免分块导致上下文逻辑断裂 |
| 场景过滤节点 | 匹配前3条场景标签结果 | 覆盖客运、货运、调度等核心运营场景的精准匹配需求 |
| 生效时间校验开关 | 开启 | 确保仅调用生效期内的政策内容，规避过期政策的干扰 |
| `variables`参数配置 | 传入用户问题、运营场景、当前时间、知识库ID | 实现动态匹配适用政策、校验时效及绑定指定知识库 |
| `nodeId`绑定规则 | 绑定场景过滤节点、时间校验节点至知识库搜索节点 | 确保工作流按顺序执行校验与匹配逻辑 |
| 单次结果返回上限 | 前5条 | 控制上下文长度，避免超出AI对话的token限制 |

## 容易做错的三处
- 现象：工作流返回的政策结果与当前运营环节不匹配，例如为客运调度场景返回货运管理政策。原因：未将用户问题、运营场景作为`variables`传入工作流，未配置场景过滤节点。
- 现象：工作流返回已废止的旧政策内容，或提示无匹配结果。原因：未开启生效时间校验开关，未校验政策的生效日期与当前时间的对应关系。
- 现象：知识库搜索节点无法读取指定的铁路政策知识库，返回空结果。原因：未将知识库ID作为`variables`绑定到搜索节点的配置项中，导致节点无法识别目标知识库。

## 怎么确认配好了
- 上传一份标注了生效日期的铁路客运政策文档，触发工作流，检查返回结果是否包含当前时间处于生效期内的内容。
- 传入不同的运营场景参数，如“货运调度”“客运安检”，检查返回结果是否仅匹配对应场景的政策条款。
- 查看FastGPT v4.17.0的工作流日志，确认`variables`参数已正确传入场景过滤、时间校验及知识库搜索节点。
- 传入已废止的政策文号，检查工作流是否自动过滤该文档，返回无匹配结果的提示。
