# 铁路运营的政策与制度依据问答：引用来源与溯源

## 这个品类的数据长什么样
铁路运营的政策与制度依据数据主要来自国家铁路局、中国国家铁路集团有限公司官方发布的规章、规范性文件及各铁路局运营细则。数据更新随官方政策发布同步调整，无固定周期。单份文档通常包含文件文号、发布单位、生效日期、条款编号、适用场景、具体条款内容等字段，字段单位统一为“条”“项”“款”，生效日期采用标准公历格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
铁路运营政策的文号、生效日期是溯源的核心标识，检索时需精准匹配才能保证引用合法性。不同文件的条款层级（条、项、款）格式固定，需保留层级关联以还原完整依据。政策更新无固定周期，需同步调整知识库的数据源范围，避免引用失效文件。铁路运营政策涉及安全、运输等强监管领域，引用溯源需明确关联原始发布主体，不可仅依赖内容匹配，否则无法满足合规性要求。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 铁路政策单份条款内容长度适中，该区间可完整覆盖核心依据 |
| `responseData` | 结构化来源+原文 | 需包含文号、生效日期等溯源必要字段 |
| `detail` | 开启 | 需返回条款原文以支持人工溯源校验 |
| 单次召回上限 | 前5条 | 铁路政策问题通常关联1-3份核心文件，避免冗余结果 |
| 来源匹配规则 | 按文号+生效日期匹配 | 匹配铁路政策的唯一标识，避免内容重复导致溯源错误 |

## 容易做错的三处
- 现象：知识库检索节点引用全局变量datasetid时返回空结果，或出现红色报错。原因：未在工作流的知识库选择环节绑定变量映射，导致变量未被正确传递。
- 现象：多轮问答中仅第一轮可显示知识库引用来源，后续轮次无引用内容。原因：未开启对话上下文的溯源缓存开关，导致后续轮次未关联历史知识库结果。
- 现象：检索结果的引用来源显示为无文号的模糊内容。原因：未配置按文号+生效日期的匹配规则，仅按内容关键词匹配导致重复或无效来源。

## 怎么确认配好了
- 发起一条铁路政策相关问题，检查返回结果是否附带文件文号、生效日期等溯源字段。
- 测试多轮问答，确认每一轮结果都显示对应的引用来源。
- 手动核对返回的条款原文与官方政策文件，确认匹配度符合预期。
- 调整`quoteMaxToken`参数，验证返回的引用内容长度是否符合配置区间。
