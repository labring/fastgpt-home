# 铁路运营的政策与制度依据问答：模型接入与配置

## 这个品类的数据长什么样
铁路运营的政策与制度依据数据，主要来源于国家铁路局、中国国家铁路集团有限公司官方规章库，以及各铁路局集团公司发布的内部运营细则。数据更新节奏为新政策发布后7个工作日内完成同步，文档结构固定为规章编号、发布单位、生效日期、适用范围、条款正文五个核心部分。字段包含规章文号、发布主体、生效时间、适用运营区段、条款序号，单位以公里、年月日、条款条数为核心标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
铁路运营政策文档的固定结构与明确字段，要求模型接入时需精准匹配字段提取逻辑，避免泛化理解导致的规章编号、适用区段等核心信息错位。适用范围的运营区段与公里单位，要求配置时需保留地理与里程相关的实体识别权重，提升问答准确性。文档更新节奏要求知识库同步机制支持增量更新，避免全量重拉带来的资源占用。条款正文长度差异较大，长条款可能超出模型上下文限制，需在接入时设置合理的上下文截断规则。

## 配置怎么定
本页面基于FastGPT v4.17.0版本编写，配置项与建议取法如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 铁路政策文档单篇最长可达数千token，需覆盖单轮问答的上下文与引用内容 |
| `maxTokens` | `2000 token` | 控制单轮回答长度，避免输出超出铁路运营问答所需的政策条款范围 |
| `quoteMaxToken` | `1500 token` | 限制单条引用文档的长度，适配铁路政策文档的条款拆分需求 |
| `toolChoice` | `auto` | 允许模型自主选择是否调用知识库工具，适配政策问答中需引用具体规章的场景 |
| `temperature` | `0.1–0.3` | 降低回答随机性，确保政策条款引用的准确性与一致性 |
| `AIPROXY_API_ENDPOINT` | 按私有部署模型的实际接口地址填写 | 适配铁路行业常用的私有部署大模型合规要求 |
| `AIPROXY_API_TOKEN` | 按私有部署模型的认证规则配置 | 保障模型调用的身份合法性 |

## 容易做错的三处
- 现象：调用私有部署大模型时返回连接超时或401未授权错误。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或私有部署模型的接口认证规则与FastGPT要求不匹配。
- 现象：问答结果未引用匹配的政策文档，或引用内容不完整。原因：`maxContext`配置值过小，无法加载完整的政策知识库上下文，或`quoteMaxToken`设置限制了引用文档的长度。
- 现象：问答结果中未包含政策文件的关联URL。原因：未开启知识库的元信息提取功能，导致模型无法获取上传文件的URL字段，无法在回答中返回对应链接。

## 怎么确认配好了
- 调用测试接口，输入“《铁路旅客运输规程》的生效日期是什么”，核对回答是否包含准确的生效时间与对应规章文号。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置值与部署环境一致，无格式错误。
- 触发知识库增量同步任务，查看同步日志确认新发布的政策文档已被正确加载。
- 调整`temperature`参数至0.2，多次调用同一测试问题，确认回答结果无明显差异，符合政策问答的准确性要求。
