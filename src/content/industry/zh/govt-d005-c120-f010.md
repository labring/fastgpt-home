# 铁路运营的政策与制度依据问答：知识库检索与召回

## 这个品类的数据长什么样
铁路运营的政策与制度依据数据主要来自国家铁路局、中国国家铁路集团有限公司发布的官方规章、行业标准与内部运营规范。数据更新随新政策出台实时同步，文档多为结构化格式，包含政策文号、发布单位、生效日期、适用场景、具体条款等字段，部分文档附带附件表格与执行细则，单篇文档长度跨度较大，从数百字到数万字不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
官方来源的政策数据要求检索结果需优先匹配权威发布渠道的文档，避免非官方解读干扰。更新频率随政策出台动态调整，要求知识库同步机制可按需触发增量更新，防止召回失效政策。单篇文档长度跨度大，长文档需拆分适配检索分块规则，避免因分块过长丢失关键条款，或分块过细导致语义割裂。多字段的文档结构要求检索支持按政策文号、生效日期等字段进行精准过滤，缩小召回范围。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 铁路政策文本语义相似度较高，过低会召回无关政策，过高会遗漏相近条款，按实测标定 |
| `limit` | 前8条 | 铁路政策文档数量适中，8条可覆盖主要相关条款，避免结果过多干扰后续处理 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配政策文档既有明确条款关键词又有复杂语义逻辑的特征 |
| `usingReRank` | 开启 | 铁路政策存在相近表述的条款，重排可提升高相关结果的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 政策问题常包含行业术语，扩展查询可覆盖同义词与简称，提升召回覆盖度 |
| `collectionIds` | 绑定铁路政策专属知识库集合 | 区分其他品类的政策文档，避免召回跨行业无关内容 |

## 容易做错的三处
- 检索结果为空或仅返回少量无关内容。原因：未绑定铁路政策专属的`collectionIds`集合，误召回其他品类的知识库数据。
- 检索返回结果条数远低于预期。原因：`similarity`阈值设置过高，导致系统过滤掉大量相关但未达到阈值的政策条款。
- 无法召回最新发布的政策内容。原因：未配置增量同步机制，未及时更新知识库中的政策文档。

## 怎么确认配好了
- 进入FastGPT知识库管理页面，查看已绑定的`collectionIds`是否为铁路政策专属集合。
- 提交包含铁路政策文号的测试查询，验证检索结果优先返回官方发布的政策文档。
- 触发一次增量同步任务，确认新发布的政策文档可被成功导入知识库。
- 调整`similarity`阈值至0.75，提交测试查询，验证返回结果的相关性符合预期。
