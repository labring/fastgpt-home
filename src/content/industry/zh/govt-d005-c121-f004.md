# 高速公路运营的政策与制度依据问答：工作流编排

## 这个品类的数据长什么样
高速公路运营的政策与制度依据数据主要来自交通运输部官方网站、各省交通运输厅及属地高速公路运营管理机构的公开公告。数据更新随政策修订、地方细则出台触发，无固定周期。文档结构包含政策文号、发布单位、生效日期、条款正文、适用路段范围等字段，部分文档附带收费标准、养护规范等附件，字段单位涉及公里、元、工作日等。

## 这些特征在「工作流编排」这一环带来什么约束
政策文档来源分散且覆盖国家、省市、属地三级，要求工作流配置多源召回节点，确保覆盖全层级政策。政策更新无固定周期，要求工作流中加入定期同步源的环节，避免使用过期条款。部分政策附带路段范围限定，工作流需配置变量过滤节点，按`variables`中的运营路段匹配对应政策条款。长文本政策文档存在多章节条款，要求工作流提前完成文本拆分与关键字段提取，避免上下文溢出影响问答准确性。

## 配置怎么定
本页面内容适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 多源召回源 | 指定交通运输部、本省交通厅、属地运营机构官方源 | 高速公路运营政策覆盖国家、省市、属地三级层级 |
| 变量过滤规则 | 按`variables`中的运营路段ID匹配政策适用范围 | 多数政策条款附带特定路段的适用限定 |
| 上下文窗口长度 | 8000–12000 token | 单篇政策文档平均长度较长，需保留完整条款上下文 |
| 节点超时时间 | 300–600秒 | 多源召回需跨多个官方站点拉取数据 |
| 结果过滤条件 | 保留前3条匹配度较高的政策条款 | 政策问答需精准对应具体条款，避免冗余信息 |
| 分支触发节点 | 按`nodeId`为“政策召回”的节点返回结果触发 | 需按政策召回结果执行后续问答生成环节 |

## 容易做错的三处
- 现象：工作流中配置了指定回复节点输出HTML代码，运行时未显示内容且直接进入下一分支。原因：未开启指定回复节点的允许原始HTML输出配置，导致内容被自动过滤。
- 现象：工作流运行耗时超出预设阈值，整体响应缓慢。原因：未限制多源召回的源数量，且未设置结果过滤条件，拉取了过多冗余的政策文档数据。
- 现象：工具调用后的最终回答中出现知识库搜索的input和response引用内容。原因：未在问答生成节点中关闭显示检索上下文的配置，导致原始检索信息被带入最终输出。

## 怎么确认配好了
- 手动触发工作流，输入带有特定路段编号的政策咨询问题，检查召回结果是否包含对应路段的政策条款。
- 查看工作流运行日志，确认多源召回节点成功拉取了指定层级的官方源数据，无超时报错。
- 启用测试分支，配置测试路段ID，验证变量过滤节点是否正确筛选出匹配的政策条款。
- 调用工具节点后，检查最终回答是否仅包含政策条款内容，未出现检索相关的冗余字段。
