# 12345热线工单办理的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自12345热线平台、承办单位业务系统、知识库、回访评价数据及地方热线管理办法，更新频率为每日。日常处理的文档包含诉求登记单、派单记录、办理答复、回访记录、延期申请、退回说明及知识库条目，字段通常包含诉求编号、承办主体、诉求内容、答复口径、回访结果等，无统一固定格式，部分为业务系统导出的结构化数据，部分为人工录入的非结构化文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且格式多样，既包含结构化的业务系统导出数据，也有非结构化的人工录入文本，要求索引配置需兼容多类型数据的向量提取。每日更新的工单数据随业务量波动，需配置增量索引以避免全量重建的资源消耗。文档覆盖诉求全流程，向量召回需精准匹配不同环节的关键信息，如诉求类型判断需关联登记单内容，答复生成需参考办理记录与知识库条目。同时，工单处理的时效性要求向量检索的响应速度适配业务流程的时间窗口，避免因检索延迟导致工单超期。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配12345工单类文档的常规长度，避免单块内容过多丢失语义关联 |
| 重叠长度 | 100–200 字符 | 衔接相邻分块的上下文，确保诉求与答复的完整语义被向量覆盖 |
| 相似度阈值 | 0.75–0.85 | 按实测标定，平衡诉求类型匹配的准确率与召回量，避免误判或漏判 |
| 单次搜索上限 | 前 5 条 | 聚焦最相关的工单历史与知识库内容，减少无关信息对答复生成的干扰 |
| `maxToken` | `4096` | 适配通用大模型的上下文长度限制，确保召回的文档内容可完整纳入生成窗口 |
| `defaultToken` | `1024` | 平衡答复生成的内容完整性与响应速度，适配工单答复的常规篇幅 |

## 容易做错的三处
- 点击启用豆包Doubao-embedding-large索引模型，填写自定义请求地址和apikey后测试直接报错。原因是未确认自定义请求地址的网络连通性，或apikey未被授权访问向量模型服务。
- 刷新知识库页面后报“检测到没有可用的索引模型”。原因是未将配置好的向量模型关联至当前知识库，或模型服务的健康检查未通过。
- 为表格数据开启多向量支持后，召回结果未匹配到表格字段信息。原因是未针对工单类表格的结构化字段配置专属的向量提取规则，导致表格内容未被正确向量化。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库设置页面，查看向量模型配置项，确认已启用的模型状态显示为正常。
- 上传一条典型的诉求登记单文档，执行向量召回测试，查看返回的匹配条目数量符合预期范围。
- 新建对话agent，输入工单相关的查询语句，确认可正常调用索引获取上下文内容，无报错提示。
- 查看索引服务的监控日志，确认无连接超时、参数错误或权限异常的记录。
