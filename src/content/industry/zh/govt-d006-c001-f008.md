# 12345热线工单办理的文书与材料起草：文档解析与分块

## 这个品类的数据长什么样
这个品类的日常文档包含诉求登记单、派单记录、办理答复、回访记录、延期申请、退回说明、知识库条目。数据来源为12345热线平台、承办单位业务系统、知识库、回访评价数据、地方热线管理办法。数据更新频率为每日，文档多包含固定业务字段与自由文本内容，部分文档来自跨系统的异构格式，涵盖结构化表单与非结构化文本两类形式，单份文档的内容长度跨度较大。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于数据来源包含跨系统的异构格式，文档解析环节需适配不同的文件类型与字段提取规则，避免丢失关键业务信息。每日更新的批量工单数据要求解析与分块流程具备较高的处理效率，避免延误工单闭环处理。文档中固定字段与自由文本混合的结构，要求分块规则需保留字段与对应内容的逻辑关联，否则会影响后续诉求类型判断与答复生成环节的准确性。同时，工单处理的时效要求，使得解析与分块流程不能出现过长的超时情况，否则可能引发工单超期等后果。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配12345工单类文档的诉求内容、答复文本的常规长度，既保留上下文关联，又避免单块内容过长影响检索效率 |
| `chunkSplitter` | 按段落+语义分割 | 匹配工单文档按办理环节划分段落的结构，可保留诉求与对应答复、延期申请等内容的逻辑关联 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配包含多附件的批量工单文档解析需求，预留足够时间完成格式转换与字段提取，避免因超时导致工单处理中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持承办单位上传较大体积的历史工单批量文件，满足批量导入与解析的业务需求 |
| `chunkSettingMode` | 自定义模式 | 适配不同类型工单（如咨询类、投诉类）的文档结构差异，可灵活调整分块规则与字段提取逻辑 |
| `customPdfParse` | 启用 | 准确提取工单PDF文档中的固定表单字段，避免结构化信息丢失 |

## 容易做错的三处
- 现象：上传工单附件时出现`net::ERR_INCOMPLETE_CHUNKED_ENCODING`报错，页面加载中断。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，当前配置无法承载大体积的工单附件文件。
- 现象：检索工单相关文档时，出现关键诉求内容被拆分到多个分块的情况。原因：`chunkSplitter`配置仅使用固定字符分割，未结合语义与段落划分，破坏了诉求与答复的逻辑关联。
- 现象：调用API无法获取分块索引的内容，返回结果为空。原因：未在`chunkSettingMode`中开启索引生成配置，或使用的FastGPT版本未支持对应参数设置。

## 怎么确认配好了
- 上传一份标准的诉求登记单文档，查看解析后的分块列表，确认分块长度符合预设的`chunkSize`范围。
- 上传1000 MB以内的批量工单文件，测试上传与解析流程，确认无超时或上传失败报错。
- 调用FastGPT的文档解析API，验证返回结果包含分块索引字段与对应分块内容。
- 调整`chunkSplitter`配置为仅字符分割，对比解析结果，确认语义分割可更好保留工单文档的逻辑关联。
