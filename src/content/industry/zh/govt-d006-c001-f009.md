# 12345热线工单办理的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自12345热线平台、承办单位业务系统、政务知识库、群众回访评价数据及地方热线管理规范。数据更新频率为每日更新，日常处理的文档包含诉求登记单、派单记录、办理答复、回访记录、延期申请、退回说明及知识库条目。数据字段通常包含诉求编号、诉求内容、承办主体、办理进度、答复口径及群众评价标签。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源分散且每日更新，模型接入需支持多源数据的权限隔离与增量同步配置。日常文档多为结构化字段搭配非结构化诉求内容，模型输入需优先匹配工单核心字段，避免冗余信息干扰。同时工单办理存在明确的时效要求，模型调用需设置合理超时阈值，防止因响应延迟导致工单超期。另外，答复内容需符合地方热线规范，模型输出需可溯源至知识库条目，避免生成不符合要求的内容。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配工单核心字段加关联文档的总长度，避免截断关键诉求与答复内容 |
| `maxTokens` | 1500–2000 token | 满足办理答复、延期申请等文书的输出长度需求，符合日常工单回复的常规篇幅 |
| `temperature` | 0.2–0.4 | 降低生成随机性，确保答复内容符合政务规范，避免出现不符合要求的表述 |
| `AIPROXY_API_ENDPOINT` | 对应模型服务商提供的官方API接入地址 | 确保模型调用的稳定性，避免因地址配置错误导致无法访问 |
| `AIPROXY_API_TOKEN` | 从模型服务商获取的有效访问密钥 | 完成模型接入的身份验证，防止未授权调用 |
| `toolChoice` | none | 无需调用工具，专注于文书起草与内容生成，避免引入无关逻辑 |

## 容易做错的三处
- 现象：调用AWS Claude3模型时提示找不到渠道。原因：未正确配置`AIPROXY_API_ENDPOINT`为AWS官方接入地址，或未在FastGPT中添加对应模型的渠道映射。
- 现象：在One API接入GLM模型后，文本提取模块的模型选择列表仅显示GPT系列模型。原因：未在FastGPT的模型接入配置中同步刷新模型列表，或未将GLM模型归类至文本生成类任务。
- 现象：工单答复生成后出现不符合政务规范的内容。原因：`temperature`参数设置过高，导致生成内容随机性过大，偏离既定答复口径。

## 怎么确认配好了
- 进入FastGPT的模型管理页面，查看已接入的12345工单专用模型，确认目标模型已显示在列表中。
- 上传一条测试工单数据，触发文书起草功能，检查生成内容是否包含工单核心字段且符合政务规范。
- 调用模型接口，查看返回的响应时长是否符合预设阈值，未出现超时报错。
- 检查模型接入的密钥与地址配置，确保无拼写错误，可通过简单测试请求验证连通性。
