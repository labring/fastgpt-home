# “高效办成一件事”联办的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
数据来源包括国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库及各部门审批系统，更新频率为每日。日常文档包含联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见、办结回执，字段涵盖事项编码、联办部门清单、所需材料明细、前后置办理关系、办理节点要求等，单份文档长度差异较大，从数百字符的告知单到数千字符的审批意见不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多来源的每日更新数据要求检索系统支持增量同步与权限隔离，避免跨部门文档混淆。多样的文档结构需要适配不同的分块与召回规则，确保结构化的事项清单和非结构化的审批意见都能被精准匹配。跨部门的字段关联要求检索结果需覆盖多部门的材料与流程要求，单一召回结果无法满足联办需求。同时，联办事项的办理逻辑依赖前后置关系，召回的文档需准确关联各部门的办理节点，否则会导致文书材料缺失或流程错误。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 匹配联办事项的精准度要求，避免低相关的跨部门文档混入检索结果 |
| `limit` | 前8条 | 覆盖联办所需的多部门材料、流程文档，同时控制上下文长度避免超出模型限制 |
| `searchMode` | hybrid | 结合关键词检索与语义检索，适配结构化的事项清单和非结构化的告知单、审批意见 |
| `usingReRank` | 开启 | 对初始召回结果重排，修正跨部门文档的语义偏差，提升关键信息的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展问题表述，匹配联办事项的同义表述，比如“并联办理”“联合办理”等，提升召回覆盖率 |
| `collectionIds` | 按联办部门绑定的数据集ID | 限定检索范围，仅召回当前联办事项涉及部门的文档，避免无关数据干扰 |

## 容易做错的三处
- 现象：检索结果返回与当前联办事项无关的文档，原因：未通过`collectionIds`绑定专属数据集，召回了其他部门的非关联文档。
- 现象：相同问题的检索耗时差异显著，从1秒到20秒不等，原因：未设置`limit`参数导致召回过量文档，或未开启`usingReRank`引发额外的重排计算。
- 现象：生成的文书材料遗漏跨部门材料要求或流程节点，原因：未开启`datasetSearchUsingExtensionQuery`，无法识别用户问题中的联办同义表述，导致召回的材料清单不完整。

## 怎么确认配好了
- 查看检索日志，确认返回的文档均来自绑定的联办部门数据集，验证`collectionIds`配置生效。
- 测试相同问题多次检索，确认耗时波动在合理区间内，验证`limit`和`usingReRank`的配置效果。
- 输入同义表述的联办问题，确认召回的材料清单覆盖所有跨部门要求，验证`datasetSearchUsingExtensionQuery`生效。
- 调整`similarity`阈值，测试不同问题的召回精准度，确认匹配结果符合联办事项的实际要求。
