# 不动产登记的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统及电子证照库。日常处理的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书与不动产登记簿。数据更新频率为每日更新，文档结构多包含不动产坐落、权属人身份信息、测绘面积、税费金额等固定字段，不同系统导出的文档格式存在一定差异。

## 这些特征在「向量模型与索引」这一环带来什么约束
多系统异构数据导致向量建模时需兼容不同字段格式，每日更新的频率要求索引构建支持增量同步，不使用全量重建流程。非标准化的文档结构使得分块时需保留业务上下文，避免拆分破坏权属来源、测绘数据等核心关联信息。同时，数据关联需覆盖房地测绘比对、权属核验等核心环节，索引召回需精准匹配不动产坐落、权利状态等关键字段，否则会影响后续文书起草的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配不动产登记文档中权属证明、测绘成果的单段核心信息长度，避免拆分破坏业务关联 |
| 重叠长度 | 100–200 字符 | 保留跨分块的不动产坐落、权属人等关键上下文，防止召回时丢失关联信息 |
| 相似度阈值 | 0.75–0.85 | 匹配不动产字段的强关联特性，控制误召回比例 |
| 单次搜索上限 | 前 5 条 | 控制核验环节的信息体量，适配不动产登记文书起草的精准匹配需求 |
| `maxToken` | 8000–12000 | 覆盖单份完整登记申请材料的向量召回上下文长度，满足文书拼接的信息需求 |
| `defaultToken` | 按实测标定 | 适配本地部署的模型显存限制，避免超出硬件承载范围 |

## 容易做错的三处
-  界面中无法选择指定的Embedding模型，原因是当前版本未集成该模型的接口适配配置，需通过FastGPT v4.17.0的自定义模型接入流程补充。
-  本地部署时提示向量模型调用失败，原因是未正确配置模型的访问令牌与接口地址，或转发链路存在端口映射错误。
-  导入知识库时生成的索引与预期内容不符，原因是分块长度设置过大或过小，破坏了不动产测绘数据、权属来源等核心业务段落的完整性。

## 怎么确认配好了
-  检查`maxToken`的配置是否符合预设范围，上传单份不动产登记申请书至知识库，验证分块内容的完整性。
-  输入包含不动产坐落的测试查询词，核对召回结果的条数是否符合单次搜索上限的配置。
-  启动本地部署的测试环境，调用向量模型接口，确认接口返回正常无报错。
-  手动触发一次增量同步任务，检查索引是否更新了新增的登记材料数据。
