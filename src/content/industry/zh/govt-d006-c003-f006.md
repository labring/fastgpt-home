# 不动产登记的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
不动产登记场景的核心文档包括登记申请书、权属证明、测绘成果、税费凭证、不动产权证书、登记簿等，字段涵盖权利人信息、不动产权证号、坐落位置、面积等。数据来源为不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统、电子证照库，更新频率为每日一次。文档包含结构化字段与非结构化附件两类，需关联各系统的唯一标识以避免数据混淆。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多系统数据源要求引用时需明确关联各系统的唯一标识，防止跨系统数据张冠李戴；每日更新的频率要求配置每日增量同步任务，确保引用的权属信息为最新状态；文档类型多样的特点要求按登记文书类型配置不同引用规则，例如测绘数据需比对坐标字段，权属证明需核对权利人信息；出错后果严重的属性要求溯源链路必须完整保留，不可省略任何来源环节，确保每一处引用都可追溯至原始数据源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 不动产登记相关文档的字段与附件内容较长，需保留足够长度以完整展示原始引用内容 |
| `responseData` | 开启 | 需返回原始数据源的具体字段信息，满足登记文书的溯源与核验要求 |
| `detail` | 完整 | 登记文书需准确呈现权属来源细节，不可省略权利人、坐落位置等关键信息 |
| 数据源范围 | 不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统、电子证照库 | 仅使用该品类合法合规的官方数据来源 |
| 同步频率 | 每日增量同步 | 匹配数据源的日更新频率，确保引用内容的时效性 |
| 引用条数上限 | 前3条 | 单份登记文书的权属来源关联数据通常不超过3项，避免冗余内容干扰生成 |

## 容易做错的三处
- 现象：生成的登记文书未附带数据源原文片段，仅显示概括性描述。原因：未开启`responseData`配置，未绑定对应数据源的返回规则。
- 现象：知识库引用上限无法调节，导致引用内容不足无法覆盖完整权属信息。原因：未调整引用条数上限，或错误限制了`quoteMaxToken`的取值范围。
- 现象：生成的文书出现上下文溢出报错。原因：未限制`quoteMaxToken`的取值，或取值超出系统允许的最大token阈值。

## 怎么确认配好了
- 登录FastGPT v4.17.0的管理后台，进入对应知识库的配置页面，检查`quoteMaxToken`、`responseData`、`detail`的配置是否与预设值一致。
- 发起测试查询，输入「生成某坐落位置的不动产登记申请书」，查看返回结果是否包含原始数据源的字段信息，如不动产权证号、权利人姓名等。
- 查看系统同步日志，确认每日增量同步任务已正常执行，无失败记录。
- 调用绑定的数据源接口，验证返回的原文片段能正确嵌入生成的登记文书中，无缺失或错误。
