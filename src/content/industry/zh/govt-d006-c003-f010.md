# 不动产登记的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统与电子证照库，更新频率为每日。日常处理的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书与不动产登记簿。单份文档包含宗地编号、权利主体信息、测绘面积、权属限制状态等结构化字段，以及配套的扫描件等非结构化内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源要求检索环节支持跨系统数据的统一字段映射与关联召回；每日更新频率要求索引支持增量同步，避免全量重建带来的性能损耗；文档同时包含结构化权属字段与非结构化扫描件，需要兼顾语义检索与精确字段匹配的混合模式；权属信息的准确性直接影响登记结果，因此检索召回的结果需要具备可追溯的来源标识，确保核验环节可核对原始数据。

## 配置怎么定
FastGPT v4.17.0版本下，以下配置项为官方支持的检索与召回配置：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.88 | 不动产登记的权属信息准确性要求高，需过滤低相似度的无关文档，该区间可平衡召回率与准确率 |
| `limit` | 前8–12条 | 不动产登记文书的关联项较多，需覆盖足够的权属、测绘与税费数据，该范围可满足核验需求 |
| `searchMode` | hybrid | 文档同时包含结构化字段与非结构化扫描件，混合模式可兼顾精确字段匹配与语义召回的效果 |
| `usingReRank` | 开启 | 多源数据可能存在冗余，重排可提升高相关结果的排序优先级，降低核验成本 |
| `datasetSearchUsingExtensionQuery` | 开启 | 登记文书的表述存在标准化格式，扩展查询可覆盖同义表述的检索需求，提升召回覆盖度 |
| `collectionIds` | 按业务域绑定2–4个专属数据集 | 多系统数据需按地籍调查、登记申请、税费凭证等业务模块隔离检索范围，避免跨域干扰 |

## 容易做错的三处
- 现象：知识库搜索返回报错，提示`invalid configuration parameter name "hnsw.iter"`。原因：在检索配置中写入了FastGPT官方清单外的参数名称，未使用指定的配置项。
- 现象：添加了语言模型与索引模型后，创建知识库时文本理解模型下拉框无对应选项。原因：未将模型关联至当前使用的数据集集合，或模型加载状态未完成初始化。
- 现象：非授权用户可访问未授权的不动产登记知识库内容。原因：未启用FastGPT的权限隔离功能，未按业务角色划分知识库的访问范围。

## 怎么确认配好了
- 执行一次测试检索，输入登记申请书的核心字段，核对返回结果的来源是否覆盖对应业务系统的数据。
- 查看检索配置的参数列表，确认仅使用FastGPT官方支持的配置项，无额外非指定参数。
- 为测试角色分配有限的知识库访问权限，验证该角色无法访问未授权的数据集内容。
- 触发一次增量同步任务，确认索引更新耗时符合业务处理节奏，无全量重建触发。
