# 传染病信息报告与监测的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
本细分品类的数据来自中国疾病预防控制信息系统、医疗机构HIS与传染病报告系统、实验室检测系统，每日更新。日常生成的文书包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，文档结构固定，包含病例编号、诊断时间、报告时限、订正记录、聚集性疫情关联信息等字段，字段需符合法定报告规范。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本细分品类的数据每日更新，文书字段固定且需符合法定报告规范，日常需频繁进行病例订正、时限核对、异常信号汇总等操作。多轮对话需保留近期病例数据与订正记录，避免上下文过载影响模型处理。提示词需强制校验法定报告字段，确保输出符合规范。每日更新的数据需实时关联当前任务，同时需限制单次对话返回的信息条数，避免干扰核心数据溢出。

## 配置怎么定
本页面基于FastGPT v4.17.0版本配置，具体配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前疾控监测任务的固定ID | 确保同任务下的对话上下文关联，避免跨任务数据混淆 |
| `messages` | 保留前12-18条历史对话 | 匹配每日病例数据的对话上下文长度，避免超出模型处理上限 |
| 最大上下文长度 | 8000 token | 匹配单篇传染病报告文档的字符量，按实测标定 |
| `variables` | 绑定法定报告字段清单变量 | 确保提示词校验文书需包含所有必填报告字段 |
| 单次对话返回条数 | 前5条最新病例数据 | 避免上下文过载，聚焦当前任务的核心信息 |
| 对话超时阈值 | 600秒 | 匹配疾控数据查询的常规响应时间，避免长时间等待导致任务中断 |

## 容易做错的三处
- 现象：对话仅能响应第一轮请求，后续交互无反馈。原因：`chatId`未绑定固定任务ID，导致上下文无法关联。
- 现象：对接本地部署的模型后，实际调用的模型与配置不符。原因：未在配置中指定正确的模型标识，导致默认模型被调用。
- 现象：对话输入的json病例数据后，模型无响应或报错。原因：最大上下文长度设置不足，超出模型处理上限。

## 怎么确认配好了
- 在FastGPT v4.17.0的调试预览界面，输入测试病例数据，检查`chatId`是否绑定当前任务。
- 触发多轮对话，验证历史对话是否保留了前12-18条记录。
- 检查`variables`中的字段是否包含所有法定报告必填项。
- 测试输入包含多字段的json病例数据，验证是否能正常处理，确认最大上下文长度设置符合需求。
