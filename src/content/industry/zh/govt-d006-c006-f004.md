# 传染病信息报告与监测的文书与材料起草：工作流编排

## 这个品类的数据长什么样
本品类的数据来自中国疾病预防控制信息系统、医疗机构HIS与传染病报告系统、实验室检测系统，更新频率为每日。日常生成的文书与材料包括传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，文档结构包含病例身份信息、诊断详情、报告时限、订正说明等固定字段，部分文档需关联实验室检测结果数据，单份报告卡字段数量固定，疫情分析报告按监测周期汇总多份病例数据。

## 这些特征在「工作流编排」这一环带来什么约束
每日更新的数据要求工作流需配置定时触发节点，确保当日病例数据及时处理。固定字段的文档结构要求工作流中加入字段校验环节，避免漏填报告时限、病例诊断信息等法定必填项。多系统数据来源需设置多节点并行拉取，整合来自HIS、实验室系统的关联数据。法定报告规则要求工作流中嵌入时限校验逻辑，对超出报告时限的病例触发预警，防止迟报漏报导致的监管风险。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次搜索上限 | 前8条 | 匹配单日病例数据的召回需求，避免冗余信息干扰校验 |
| 最大上下文 | 7000–11000 字符 | 承载多份报告卡、订正记录与汇总分析的完整内容 |
| 变量 | `variables` | 存储每日异常病例数、报告时限超时数等动态监测数据 |
| 节点ID | `nodeId` | 标记定时触发、多系统数据拉取、字段校验等核心节点 |
| 超时设置 | 500–700 秒 | 适配多系统数据整合的耗时，防止流程意外中断 |
| 知识库搜索引用上限 | 3000 字符 | 符合工作流场景下的上下文长度限制，与应用端配置区分开 |

## 容易做错的三处
- 现象：工作流中多模态数据无法正确调用多模态模型，纯文本任务被分配至仅支持文本的模型。原因：未在节点配置中按数据类型划分模型调用规则，未设置`variables`标记数据模态属性。
- 现象：工作流执行后返回的知识库引用条数与配置的单次搜索上限不符。原因：误将应用端的知识库引用上限参数套用到工作流节点，未使用工作流专属的引用上限配置项。
- 现象：工作流运行时提示文本内容触发文档解析逻辑。原因：未在节点中关闭非文档类文本的自动解析开关，导致病例报告的纯文本描述被错误分块。

## 怎么确认配好了
- 查看工作流的定时触发配置，确认触发频率设置为每日，与数据更新频率匹配。
- 运行测试工作流，检查拉取的数据源是否包含中国疾病预防控制信息系统、HIS系统两类核心来源。
- 触发字段校验节点，输入缺失报告时限的测试数据，确认是否触发对应预警。
- 查看节点日志，确认`variables`中存储的动态数据与当日监测的病例数一致。
