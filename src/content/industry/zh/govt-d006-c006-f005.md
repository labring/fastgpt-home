# 传染病信息报告与监测的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
本品类服务主体为疾控机构、医疗机构、公卫科、卫生健康委疾控处，数据来源为中国疾病预防控制信息系统、医疗机构HIS与传染病报告系统、实验室检测系统，更新频率为每日。日常产出的文书包括传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，核心字段包含病例唯一标识、诊断时间、报告单位、订正状态、检测结果等，需严格遵循法定传染病报告的格式规范。

## 这些特征在「工具调用与插件」这一环带来什么约束
多系统跨源的数据来源要求工具调用需支持对接多类业务接口，完成不同系统间的字段编码与格式统一映射；每日更新的业务节奏要求插件触发频率匹配日更周期，避免重复拉取过期历史数据；法定格式的文书要求工具生成的内容严格匹配固定字段顺序与填报规则，不可随意调整结构；核心耗时的核对环节需通过工具调用自动完成校验，减少人工干预带来的误差。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的插件系统开发。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具触发时机 | 每日凌晨2点执行全量同步，实时响应异常数据推送请求 | 匹配业务日更节奏，优先处理突发疫情信号 |
| `toolChoice` | `{"type": "function", "function": {"name": "validate_report"}}` | 强制调用指定校验工具，确保报告符合法定填报规则 |
| 单次拉取数据上限 | 前800条记录 | 避免单次请求过载，适配疾控信息系统的数据返回限制 |
| 请求超时时长 | 600秒 | 适配疾控系统接口的平均响应周期 |
| 结果格式化规则 | 按法定报告模板拼接字段 | 匹配日常文档的固定结构要求 |

## 容易做错的三处
- 现象：调用MCP服务时返回400 <400> InternalError.Algo.InvalidParameter: Range of i，原因：未按疾控报告的字段范围传入参数，例如病例编号格式不符合系统要求。
- 现象：工作流中谷歌搜索返回array<object>格式结果，无法直接填入报告模板，原因：未配置专用的数组转文本格式化工具，直接使用通用处理逻辑导致字段错位。
- 现象：线上应用API调用频繁失败，原因：未根据疾控系统的接口限流规则设置并发阈值，盲目调高并发参数导致触发限流。

## 怎么确认配好了
- 触发一次全量同步任务，检查拉取的数据条数与系统预设的单次拉取上限匹配，确认数据来源对接正常。
- 传入模拟的异常病例数据，校验工具是否触发`toolChoice`指定的校验函数，确认工具调用逻辑生效。
- 查看工作流输出的报告格式，确认是否匹配法定文档的字段顺序与结构，确认格式化规则生效。
- 模拟多并发请求，检查接口返回状态码，确认并发设置符合系统限流要求。
