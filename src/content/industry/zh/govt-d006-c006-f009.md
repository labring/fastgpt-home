# 传染病信息报告与监测的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自中国疾病预防控制信息系统、医疗机构HIS与传染病报告系统、实验室检测系统。日常生成的文书包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，数据按日更新。文档结构包含病例基本信息、诊断分类、报告时限、订正说明等固定字段，所有内容需匹配官方模板格式，无自定义扩展字段，字段取值需严格遵循法定报告规则。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散且需同步多系统的日度更新内容，要求模型接入的代理通道需支持稳定的批量请求。文档字段固定且需严格匹配官方模板，要求配置的模型输出不得生成未定义的额外字段或内容。数据更新频率为日度，需确保配置的上下文窗口可承载单日全量病例数据的处理需求，避免单次请求过长导致超时。同时，法定报告的准确性要求极高，需限制模型的自由生成空间，确保输出内容符合官方规则。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本的参数逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 承载单日全量病例数据与历史报告的上下文需求，避免因上下文溢出导致处理中断 |
| `maxTokens` | 2000–3000 字符 | 匹配单份传染病报告卡或疫情分析报告的标准输出长度，确保完整生成文档内容 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保输出内容严格符合法定报告的固定格式与规则要求 |
| `toolChoice` | none | 禁用工具调用，避免模型生成超出预设文档范围的额外操作内容 |
| `AIPROXY_API_ENDPOINT` | 按平台提供的专属地址填写 | 确保模型请求通过合规代理通道，适配疾控场景的数据安全与访问权限要求 |
| `AIPROXY_API_TOKEN` | 按平台分配的专属密钥填写 | 验证请求合法性，保障数据传输与调用的安全性 |

## 容易做错的三处
- 出现`401 Unauthorized`报错或模型调用无响应。原因是未正确配置`AIPROXY_API_TOKEN`，或混淆了通用代理与AIPROXY专属通道的配置，将其他密钥填入了专属代理配置项。
- 生成的文档包含未定义的额外字段或偏离官方模板格式。原因是`temperature`取值过高，导致模型生成超出预设要求的自由内容。
- 批量处理多份报告时出现超时中断。原因是`maxContext`取值过小，无法承载批量数据的上下文需求，导致请求被截断。

## 怎么确认配好了
- 调用测试接口，输入单份传染病报告卡的示例数据，检查返回结果的字段是否与官方模板完全匹配。
- 查看代理通道的调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置项被正确加载，无空值或错误字符。
- 设置`maxTokens`为较低取值，测试生成简短的病例订正记录，确认输出长度符合预期且无格式错误。
- 模拟日度批量请求，检查系统是否能稳定处理多份病例数据，无超时或报错。
