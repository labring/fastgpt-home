# 信访事项办理的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自国家信访信息系统、地方信访系统、12345平台、基层治理平台及历史信访档案，每日更新。核心文档包含信访登记表、受理告知书、转送交办函、办理意见书、复查复核申请、化解方案，字段覆盖诉求主体、事项内容、办理进度、政策依据、责任单位等，单份文档长度覆盖数百至数千字符。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散导致不同渠道的诉求字段格式不统一，多轮对话需先完成跨系统字段对齐，避免信息错位。每日更新的诉求数据要求对话上下文支持增量加载，确保实时调用当日最新事项。多类固定格式文书要求提示词绑定对应文档的必填字段，例如办理意见书需包含责任单位、办理结果、答复口径。信访事项的法定办理流程约束对话逻辑，需强制覆盖受理甄别、责任协调、政策解释等环节，防止遗漏关键步骤引发重复或越级信访。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 预设`信访事项来源`、`诉求主体`、`办理进度`、`责任单位`4个变量，单变量输入上限`800 字符` | 覆盖信访事项核心识别字段，简化多轮对话的信息提取流程 |
| `messages` | 保留最近`前 20 条`对话历史 | 信访办理对话包含诉求、核实、答复等多轮环节，保留足够历史可确保上下文连贯，避免信息断层 |
| 最大上下文长度 | `4000–8000 字符`，按实测标定 | 适配从受理告知书到化解方案的多类文书长度需求，平衡模型响应效率与上下文完整性 |
| 文件上传解析 | 开启文档解析工具，支持导入PDF、DOCX格式的信访档案 | 需调用历史信访档案作为办理参考，匹配业务数据来源 |
| `chatId`绑定 | 为每个信访事项分配唯一`chatId`，关联存储完整对话记录 | 信访事项需全程留痕，便于复查复核时回溯办理过程，符合法定归档要求，该功能在FastGPT v4.17.0版本中优化了多事项隔离逻辑 |
| 对话导出 | 支持导出为PDF或结构化文本格式，存储上限`1000 MB`单事项 | 满足信访档案的归档与查阅需求，适配业务场景 |
| 超时阈值 | `600 秒`，按实测标定 | 避免长对话因上下文过长导致模型响应超时，适配信访事项办理的常规对话轮次 |

## 容易做错的三处
- 现象：对话历史导出时出现字段为空或格式错乱。原因：未在`variables`中配置信访事项的核心字段，导致对话提取的信息未绑定对应业务字段。
- 现象：本地部署后上传信访档案报错，无法解析文件内容。原因：未正确配置文档解析工具的依赖环境，或上传文件的格式超出支持范围。
- 现象：多轮对话超时，响应时间超过预设阈值。原因：未限制`messages`的保留条数，导致上下文过长超出模型处理阈值，或未配置合理的超时参数。

## 怎么确认配好了
- 发起模拟信访事项对话，检查`variables`是否自动填充对应业务字段，确认信息提取准确。
- 上传测试用信访档案，验证文档解析工具能否正常读取内容并关联至对话上下文。
- 查看`chatId`是否为每个测试事项生成唯一标识，确认对话记录与事项绑定无误。
- 触发对话导出功能，验证导出格式符合信访档案的归档要求。
