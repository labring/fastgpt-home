# 信访事项办理的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
本品类数据主要来自国家信访信息系统、地方信访系统、12345平台、基层治理平台及历史信访档案，每日同步更新。日常生成的文档包含信访登记表、受理告知书、转送交办函、办理意见书、复查复核申请、化解方案，数据字段包含诉求主体、事项详情、办理单位、答复口径、诉求分类等，各文档需匹配法定格式要求的固定字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据源的多平台属性要求插件需支持多种鉴权方式，适配不同系统的接口规范。固定格式的文档要求工具调用需绑定对应文书模板，确保生成内容符合法定要求。每日更新的频率要求插件需配置定时同步任务，避免使用过期数据。字段的标准化要求需从数据源中精准提取对应字段作为插件输入，防止生成内容缺失关键信息引发重复信访或越级信访。

## 配置怎么定
本配置适用于FastGPT v4.17.0
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 需自动匹配信访文书生成的工具调用逻辑，无需手动指定 |
| 鉴权配置 | 按对应信访系统接口文档配置专属密钥与请求头 | 数据源来自多个官方信访平台，需独立完成鉴权校验 |
| 单次调用文档上限 | 前6条 | 每日同步的历史档案量适中，过多内容会超出上下文承载范围 |
| 超时阈值 | 300 秒 | 信访事项核查需协调多部门，预留足够的接口响应时间 |
| `functionCall` | `enabled` | 需启用函数调用能力，生成符合法定格式的标准化信访文书 |
| 文档模板匹配规则 | 按事项类型匹配对应文书模板 | 信访文书有明确的法定格式要求，需按诉求分类调用对应模板 |

## 容易做错的三处
- 现象：接口返回401未授权错误。原因：未按信访系统的鉴权格式配置专属密钥与请求头，导致平台拒绝请求。
- 现象：工具未自动触发文书生成逻辑，生成内容不符合法定格式要求。原因：将`toolChoice`设置为`none`，关闭了自动工具选择功能，无法匹配信访文书的生成规则。
- 现象：生成的办理意见书缺少责任单位字段。原因：未从数据源中提取对应字段作为插件输入参数，导致生成内容缺失关键信息。

## 怎么确认配好了
- 发起模拟信访诉求的测试调用，检查工具是否自动触发对应文书生成的函数，确认`functionCall`与`toolChoice`配置生效。
- 查看接口请求日志，确认携带了与对应信访系统匹配的鉴权密钥与请求头，验证鉴权配置正确。
- 生成测试文书，核对是否包含信访登记表、受理告知书等法定文档的必填字段，确认模板匹配规则生效。
