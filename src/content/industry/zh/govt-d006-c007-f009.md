# 信访事项办理的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
信访事项办理的数据源包含国家信访信息系统、地方信访系统、12345平台、基层治理平台及历史信访档案，每日更新。日常处理的文档涵盖信访登记表、受理告知书、转送交办函、办理意见书、复查复核申请、化解方案，单份文档包含诉求主体、事项详情、办理节点、复核状态等字段，无额外自定义统计类字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且每日更新，需整合多平台的同源数据，因此配置时需确保上下文聚合逻辑可匹配不同系统的输出格式。单批次处理的历史档案与实时诉求数据量较大，需限制传入模型的上下文总长度，避免出现上下文无法传递的问题。不同业务文档的字段结构存在差异，需配置对应的数据映射规则，确保生成的文书字段与系统存储字段对齐。信访办理的法定流程要求文书内容严格匹配办理节点，因此模型输出需绑定预设的文档模板，不能脱离既定结构生成内容。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 字符 | 适配信访业务单批次整合的历史档案与实时诉求总长度，避免上下文超限导致无法传递 |
| `maxTokens` | 4000–6000 token | 匹配信访文书的标准生成长度，确保受理告知书、办理意见书等文档可完整生成 |
| `quoteMaxToken` | 1500–2000 token | 限制引用的历史信访档案总token数，避免引用内容挤占主生成上下文 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保文书内容严格匹配信访办理的法定格式与既定字段 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写本地或云端接口地址 | 适配信访业务的本地大模型部署需求，确保数据不出域 |
| `toolChoice` | none | 信访文书生成无需调用外部工具，仅需基于预设文档与上下文生成内容 |

## 容易做错的三处
- 配置`maxContext`取值过大时，对话界面无法加载上下文内容，日志显示「context not send to LLM」，原因是未结合信访业务的单批次数据整合量调整参数上限，导致传入模型的上下文超出平台限制。
- 调用本地部署的大模型时频繁出现「Request Timeout」报错，原因是未适配信访业务多源数据整合的处理耗时，默认超时参数不足以支撑完整请求。
- 生成的信访文书缺少法定必填字段，界面显示生成内容不完整，原因是未将`temperature`调整至合规区间，导致模型生成内容偏离预设的文书结构。

## 怎么确认配好了
- 上传单份信访登记表与历史档案样本，检查上下文是否完整加载且未超出预设长度，确认`maxContext`取值适配当前业务数据量。
- 发起受理告知书生成测试，检查生成内容是否匹配预设的文档结构与字段要求，确认`temperature`与`toolChoice`参数配置正确。
- 调用本地大模型发起3次连续生成测试，检查是否出现超时报错，确认接口超时参数适配信访业务的处理耗时。
- 检查知识库引用的历史档案是否按预设规则被正确截取，确认`quoteMaxToken`取值符合业务需求。
