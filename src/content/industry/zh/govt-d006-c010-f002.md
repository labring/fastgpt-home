# 公路养护与路产路权管理的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来自交通运输局、公路事业发展中心等主体的多套业务系统，包括公路养护管理系统、桥隧监测系统、路政巡查系统及交通流量监测数据。日常生成的文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单等，部分文档包含时间戳、路段桩号、病害类型、处置状态等字段，单位涉及公里、平方米、立方米等，数据更新频率为每日。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引支持跨系统数据的统一向量化与关联检索；每日更新的频率要求索引配置适配增量更新逻辑，避免全量重索引带来的资源消耗与时间延迟；文档类型跨度大，短如单条巡查日志仅数十字符，长如涉路施工许可可达数千字符，要求分块策略兼顾短文本的语义完整性与长文本的局部关联性；包含路段桩号等空间标识的字段，需要与文本向量结合以提升检索的精准匹配度，避免无关路段的文档被召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配该品类下巡查日志、病害处置单等短文本与涉路许可等长文本的混合场景，避免语义断裂或局部关联丢失 |
| 重叠长度 | 100–150 字符 | 弥补分块边界的语义割裂，保障跨块的上下文连贯性，适配公路养护文档的流程性描述 |
| 相似度阈值 | 0.72–0.80 | 匹配路产相关文档的语义相似度特征，过滤低关联的巡查记录或养护计划，提升检索精准度 |
| 单次搜索上限 | 前 8 条 | 平衡检索召回效率与文书起草的上下文充足性，避免冗余信息干扰生成 |
| `maxToken` | 4000–6000 token | 适配涉路施工许可等长文档的向量化与检索后上下文拼接，保障文书起草的信息完整性 |
| `defaultToken` | 1500–2000 token | 适配日常巡查日志、病害处置单等短文档的向量化需求，避免计算资源浪费 |

## 容易做错的三处
- 现象：调用知识库接口时出现「训练订单创建失败」报错，状态码返回 400。原因：未区分全量索引与增量索引的创建逻辑，误将日更数据的增量更新提交为全量训练订单，未匹配数据的更新节奏。
- 现象：上传包含图片的涉路施工许可文档后，检索结果未返回关联图片信息，检索返回字段为空。原因：未开启多模态向量化配置，仅对文档内的文本内容生成向量，未关联图片的OCR识别结果与路段桩号等空间标识。
- 现象：在模型选择界面无法找到指定的Embedding模型或大语言模型。原因：未在配置中心录入对应模型的API密钥与服务端点，或未使用FastGPT v4.17.0及以上版本以适配最新模型接口。

## 怎么确认配好了
- 查看知识库的索引更新日志，确认每日增量更新任务已按设定频率触发，无失败记录。
- 输入一段包含路段桩号与病害类型的关键词，核对检索返回的文档类型与字段是否匹配该品类的日常文档结构。
- 测试不同长度的文档向量化任务，确认`maxToken`与`defaultToken`的配置未触发文本截断报错。
- 检查多模态配置项是否开启，上传带图片的文档后确认检索结果包含图片关联的文本与空间信息。
