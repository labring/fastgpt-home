# 公路养护与路产路权管理的文书与材料起草：多轮对话与提示词
本文基于FastGPT v4.17.0版本进行配置说明。

## 这个品类的数据长什么样
该品类的数据主要来自公路养护管理系统、桥隧监测系统、路政巡查系统、交通流量监测数据，更新频率为每日。日常产出的文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单，单份文档通常包含设施编号、巡查时间、病害类型与位置、处置措施、施工范围、赔偿事由等字段，部分文档涉及长度、面积等物理量单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的数据要求提示词明确引导模型调用最新的知识库内容，避免使用过期信息。多类型文档的混合召回，需要配置适配不同文档结构的检索规则，确保专业字段被优先识别。多源系统的数据整合，要求对话流程中需确认数据来源的一致性，防止跨系统信息冲突。单份文档的字段密度较高，提示词需明确指定需提取的字段，避免返回冗余内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配巡查日志、病害处置单的单条内容长度，确保信息完整 |
| 重叠长度 | 100–150 字符 | 避免分块后上下文断裂，保障多轮对话的内容连贯性 |
| 单次搜索上限 | 前 5 条 | 匹配单份文档的有效召回量，避免冗余信息干扰 |
| 最大上下文 | 4000 token | 承载多轮对话的历史`messages`记录，保留完整交互上下文 |
| 问题优化 | 开启 | 优化对公路养护专业术语的理解，提升检索准确性 |
| 知识库关联 | 按指定文件触发 | 确保对话仅调用目标xlsx等文档，避免无关数据干扰 |

## 容易做错的三处
- 对话中要求复述知识库内xlsx文件内容时，返回无法读取该文件的提示。原因是未在知识库配置中启用电子表格格式的解析规则，或未将目标文件正确关联至当前对话应用。
- 调用知识库后返回的结果与指定文件内容不符，返回条数远少于预期。原因是单次搜索上限设置过低，未覆盖文件内的全部有效内容。
- 多轮对话中后续提问无法关联历史上下文，返回内容与前期交互无关。原因是未正确配置`variables`参数存储对话上下文，或最大上下文设置过小导致历史记录被截断。

## 怎么确认配好了
- 上传目标xlsx文件至知识库，查看文件解析状态是否显示成功，确认格式解析无异常。
- 在对话界面输入针对知识库内文件的指定查询，核对返回内容是否包含文件内的字段信息，验证数据调用正确。
- 发起两轮及以上的连续提问，验证后续提问是否能关联前期交互的上下文，确认多轮对话逻辑正常。
- 检查接口调用参数，确认`chatId`已正确传递，确保对话会话的唯一性与连贯性。
