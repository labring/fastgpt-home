# 公路养护与路产路权管理的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自公路养护管理系统、桥隧监测系统、路政巡查系统、交通流量监测数据，更新频率为日。日常生成的文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单。文档字段通常包含设施编号、路段范围、检测数据、处置时限、涉事主体等，不同文档的字段结构差异明显，巡查日志侧重实时巡查记录，涉路施工许可侧重审批流程相关内容，单位涉及路段长度、面积等具体度量单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源的多样性要求工具调用需适配多数据源的鉴权配置，不同系统的鉴权格式存在差异，需分别配置。日更新频率要求工具调用的触发节奏需匹配数据更新周期，避免调用过时数据。文档结构的差异要求工具调用需适配不同文档的字段映射规则，避免生成文书时匹配对应字段。数据准确性要求工具调用需校验必填字段的完整性，防止生成的文书不符合业务规范。同时，该品类的出错后果涉及道路安全、资金使用争议等，要求工具调用的结果需经过合规性校验。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配养护计划、巡查日志等多种文档类型的工具调用需求 |
| `functionCall` | 按文档类型分组 | 匹配不同文档的字段结构差异 |
| 鉴权配置 | 按数据源分别配置 | 公路养护管理系统、路政巡查系统等数据源的鉴权格式存在差异 |
| 超时设置 | 600 秒 | 处理日更新的全量数据需足够的响应时间 |
| 单次调用上限 | 前 5 条 | 控制工具调用的返回数据量 |
| 字段提取长度 | 800–1200 字符 | 适配巡查日志等文档的字段提取长度 |
| 结果校验 | 必填字段非空 | 确保生成的文书包含必要的业务信息 |

## 容易做错的三处
- 现象：`toolChoice`被设置为固定值，无法适配多种文档类型的工具调用。原因：未配置自动选择工具的规则，导致工具调用仅能处理单一文档类型。
- 现象：工具调用返回401鉴权失败报错。原因：未按数据源分别配置鉴权信息，导致无法访问路政巡查系统或桥隧监测系统。
- 现象：生成的文书缺失路段编号字段。原因：未配置字段映射规则，导致工具调用提取的字段未匹配文书的必填字段。

## 怎么确认配好了
- 测试调用工具，检查`functionCall`的返回结果包含对应文档的字段，比如巡查日志的巡查时间、路段编号等信息。
- 查看鉴权配置通过后，工具调用返回正常数据，无401或403报错。
- 测试生成的文书包含所有必填字段，比如设施编号、路段范围等业务信息。
- 检查工具调用的超时设置符合业务需求，未出现超时报错。
