# 养老、工伤、失业待遇核定的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来自社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为日。日常产出的文档包括待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料。文档字段包含参保人身份标识、缴费时长、待遇核定结果、资格审核结论等，部分字段需匹配系统生成的唯一溯源标识，字段单位涵盖年、元、月等业务常用单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据来源要求引用溯源需关联不同业务系统的内容，跨系统引用需明确对应数据源的标识。日更频率要求引用内容需匹配最新的系统数据，保障时效性。文档结构复杂且字段多样，引用时需保留具体业务字段的完整信息，不能丢失关键业务细节。以参保人信息为核心的业务逻辑，要求引用内容需精准匹配对应参保人的数据，避免混淆不同参保人的待遇核定结果，防止错发漏发风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 1000–1500 token | 匹配本品类单份待遇核定材料的内容长度，避免截断关键溯源信息 |
| `responseData` | 绑定社会保险经办系统、个人权益记录等数据源 | 对应本品类多来源数据的结构，确保引用内容来自指定业务系统 |
| `detail` | 开启 | 保留待遇申领表、工伤认定材料等文档的字段细节，保障溯源内容准确匹配业务字段 |
| 单次引用条数 | 前3–5条 | 控制引用内容的合理长度，避免冗余信息干扰业务审核 |
| 参保人标识匹配规则 | 按参保人身份标识关联 | 匹配本品类以参保人信息为核心的业务逻辑，精准匹配对应参保人的数据 |

本页面基于FastGPT v4.17.0版本的配置逻辑。

## 容易做错的三处
- 现象：返回结果中引用内容过多导致界面显示杂乱。原因：未配置`quoteMaxToken`，导致引用内容超出合理长度。
- 现象：引用内容出现红色报错提示。原因：未正确绑定数据源，无法匹配本品类的社保经办系统数据。
- 现象：多轮工作流测试时，仅第一个问题加载知识库引用，后续问题无引用内容。原因：未配置跨问题的参保人标识匹配规则，后续环节无法关联对应参保人的数据。

## 怎么确认配好了
- 发起单参保人身份的查询，核对返回结果中的引用内容是否匹配该参保人的缴费年限、待遇核定结果等字段。
- 查看引用内容的来源标识，确认是否来自社会保险经办系统、个人权益记录等指定数据源。
- 调整`quoteMaxToken`的配置，验证返回的引用内容长度是否符合设定范围。
- 测试多轮业务流程，确认后续工作流环节是否能正常加载并显示引用内容。
