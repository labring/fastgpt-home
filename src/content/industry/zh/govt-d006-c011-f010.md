# 养老、工伤、失业待遇核定的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源于社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台。日常生成与使用的文档包括待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料，文档多为结构化表单或证明类文件，包含参保人身份标识、缴费年限、待遇核算依据、资格判定条件等字段，字段单位涉及年、月、元等，数据更新频率为每日。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征对知识库检索与召回环节带来多重约束。数据每日更新，要求知识库需每日同步最新的社保经办、个人权益记录等系统数据，确保召回内容与当前业务数据一致。文档包含结构化表单与证明类文件，且字段带有年、月、元等特定单位，检索时需精准匹配字段单位，避免因单位不符导致检索结果偏差。跨多系统的数据来源要求检索需关联不同来源的文档，确保召回的缴费年限、工伤认定材料等数据来自对应业务系统的准确信息，保障待遇核定的准确性。同时，待遇核定的出错后果直接影响基金安全与群众权益，要求检索结果需具备较高的置信度，避免召回错误或过时的信息。

## 配置怎么定
基于FastGPT v4.17.0版本的配置参考如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配社保业务场景的精准度要求，过滤低相关性的文档 |
| `limit` | 前8条 | 覆盖常用的待遇核定相关文档，控制上下文长度 |
| `searchMode` | 混合检索 | 结合向量检索与全文检索，适配结构化与非结构化文档 |
| `usingReRank` | 开启 | 提升召回文档的相关性，过滤无关内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 优化业务问题的表述，匹配社保专业术语 |
| `collectionIds` | 指定对应社保待遇文档集合 | 限定检索范围，避免召回无关文档 |

## 容易做错的三处
- 现象：部分PDF文档无法被知识库识别，原因：未正确配置PDF解析依赖或文档格式不符合规范，导致向量生成失败。
- 现象：配置了text-embedding-ada-002但知识库报错“无可”，原因：未正确配置数据集的嵌入模型参数，或数据集未完成向量生成流程。
- 现象：使用不同模型进行嵌入与查询，导致检索结果相关性下降，原因：嵌入与查询使用的模型不一致，向量空间不匹配，无法有效召回相关文档。

## 怎么确认配好了
- 手动输入养老待遇核定、工伤认定材料、失业保险金申领相关的业务问题，检查召回的文档是否包含缴费年限证明、退休审批表等品类内的日常文档。
- 查看知识库的同步日志，确认数据集是否完成每日更新，确保召回数据的时效性。
- 检查配置项的参数值，确认`similarity`、`limit`等参数符合设定的取值范围。
- 测试检索流程，确认返回结果的相关性符合业务场景的要求。
