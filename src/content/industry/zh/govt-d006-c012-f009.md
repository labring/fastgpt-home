# 养老服务机构监管的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
养老服务机构监管的业务数据主要来自养老服务信息平台、民政统计系统、消防检查记录、机构运营台账。日常处理的文档包含机构备案材料、运营补贴申请、服务质量检查表、安全隐患整改台账、老人入住档案，文档结构兼顾结构化字段与非结构化说明内容，数据更新频率为月度，单次处理的数据覆盖单机构周期内的运营与检查记录。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据的跨系统来源导致字段格式存在差异，需要在模型配置中定义统一的字段映射规则，确保不同系统的机构信息、检查数据可被模型识别。月度更新的特性意味着单次处理的数据量相对稳定，无需设置过高的并发调用上限。监管文书涉及机构备案、补贴审核等敏感内容，需要限制上下文与生成内容的token数量，避免敏感信息泄露。同时，文档包含结构化数据与非结构化文本，需要模型同时支持结构化字段提取与合规文本生成。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配月度更新的养老监管文档总长度，避免截断核心备案、检查与补贴数据 |
| `maxTokens` | 2000–3000 token | 满足单份监管文书（如整改台账、补贴申请）的生成长度需求 |
| `temperature` | 0.2–0.4 | 保障监管文书的格式规范与数据准确性，降低生成偏差 |
| `toolChoice` | auto | 适配多源数据调用工具提取机构床位、补贴金额等结构化字段 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接口地址 | 适配本地或私有部署的模型调用链路，确保数据链路可控 |
| `AIPROXY_API_TOKEN` | 按平台生成的专属密钥填写 | 保障模型调用的身份验证安全，防止未授权访问 |

## 容易做错的三处
- 出现429 Request rate increased too quickly报错。原因是未适配养老监管数据月度更新的低并发场景，设置了过高的模型调用频率。
- 配置大模型时删除body参数后，再次进入页面仍保留该参数。原因是平台配置表单存在临时缓存，未完成保存操作即刷新或退出页面。
- 不同供应商下配置相同模型时无法保存。原因是未为每个供应商的模型配置唯一的标识ID，导致平台识别冲突。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的平台发起一次模拟调用，检查返回的请求链路是否匹配配置的`AIPROXY_API_ENDPOINT`。
- 生成一份测试用的养老机构备案材料草稿，核对生成内容的token长度未超出`maxTokens`设置范围。
- 模拟符合月度数据处理规模的调用频次，确认未触发速率限制类报错。
- 刷新配置页面，确认修改后的参数未恢复为初始值，验证配置保存生效。
