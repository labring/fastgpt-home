# 养老服务机构监管的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
这个品类的日常文档通常包含备案材料、运营补贴申请、服务质量检查表、安全隐患整改台账、老人入住档案，数据一般来自养老服务信息平台、民政统计系统、消防检查记录、机构运营台账，更新频率为月度。文档多为结构化格式，包含机构备案编号、床位数量、检查日期、整改时限等字段，单位涉及张、天、人次等，部分文档带有层级化标题结构。

## 这些特征在「知识库检索与召回」这一环带来什么约束
跨来源的月度更新数据要求知识库同步周期匹配数据更新频率，避免数据滞后影响监管准确性。结构化文档的字段与单位差异，要求检索时支持按特定字段过滤，比如按机构属地或检查类型筛选结果。层级化标题结构若被破坏，会导致语义关联偏差，影响召回精准度。文档总量较大，无限制召回会导致上下文溢出，引发回答截断问题。同时监管场景要求结果关联元数据，确保文书核对时可追溯来源与依据。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配监管文书的严谨性要求，过滤低相关的冗余内容 |
| `limit` | 前6–8条 | 避免召回过多内容导致上下文溢出，防止AI回答中途截断 |
| `searchMode` | 语义检索 | 适配跨系统文档的语义关联，比如关联备案材料与整改台账 |
| `usingReRank` | 开启 | 对召回结果按相关性重排，确保高优先级的监管核心文档优先返回 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展监管相关的同义表述，提升跨文档关联召回能力 |
| `collectionIds` | 按监管范围指定 | 限定检索范围为民政、消防相关的数据集，排除无关数据干扰 |

## 容易做错的三处
-  检索结果条数过多导致AI回答中途截断，原因是未限制`limit`参数的取值，召回的文档块超出上下文窗口上限。
-  检索结果未携带关联元数据，无法直接用于核对机构备案或检查信息，原因是未配置元数据绑定逻辑，未将文档块与机构ID、检查日期等字段关联。
-  传入Markdown格式的监管文档后，检索结果出现跨章节混淆，原因是未保留标题层级分块，将不同类别的内容混为一谈，破坏了文档的逻辑结构。

## 怎么确认配好了
-  发起针对养老机构备案材料的检索，检查返回结果的条数是否符合预设的`limit`取值范围。
-  查看检索结果的元数据字段，确认是否包含机构备案编号、检查日期等监管场景所需的关联信息。
-  上传一份包含层级标题的Markdown格式监管文档，验证检索时是否能按标题层级匹配相关内容。
-  运行一次全量数据集的检索测试，确认响应时间符合业务要求，未出现异常报错。
