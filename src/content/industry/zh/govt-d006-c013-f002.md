# 内控评价、审计与整改的文书与材料起草：向量模型与索引

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类涉及的文档主要包括内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据来源覆盖企业内控系统、ERP、财务共享系统、审计管理系统及采购合同项目系统。数据更新频率为年度，文档结构多为结构化字段与非结构化段落结合，包含问题描述、整改要求、佐证材料编号等字段，部分文档附带凭证编号、项目编号等专属标识，无统一固定的单位标准。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来多项约束。跨系统分散的数据来源要求索引支持多格式文档的统一解析，避免结构化字段与非结构化段落的信息丢失。年度低频更新的特性意味着索引构建以全量更新为主，需保障全量索引的稳定性与执行效率。文档包含问题描述、整改要求、佐证编号等强关联内容，向量模型需重点对齐问题与整改措施的语义关联，同时适配短文本字段的向量化效果。此外，跨系统字段命名差异需提前完成基础映射，确保向量化时语义维度的统一。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 本品类文档包含长段落的问题描述与整改要求，该区间可平衡语义完整性与索引密度 |
| 重叠长度 | 100–150 字符 | 避免跨块语义断裂，适配整改台账中跨段落的关联内容 |
| 相似度阈值 | 0.72–0.78 | 需区分审计问题的相似性与差异性，避免误判同类问题或遗漏关联整改项 |
| 单次召回上限 | 前8条 | 审计类文档的关联项多集中在少量同类问题与整改记录，过多召回会增加上下文冗余 |
| `defaultToken` | 4096 | 适配本品类文档的平均长度，确保单批次向量化的内容完整性 |
| `maxToken` | 8192 | 支持整合多份关联文档（如审计工作底稿与整改台账）的上下文输入 |

## 容易做错的三处
- 索引构建过程耗时过长。原因：未针对年度低频更新的数据集调整分块参数，分块长度设置过小导致分块数量激增，或未开启批量索引优化。
- 创建知识库时文本理解模型下拉框无可选模型。原因：仅配置了嵌入模型与语言模型，但未在系统设置中完成对应模型的权限绑定，或模型部署路径未正确映射至FastGPT容器内。
- 向量化后的数据集出现字段为空的情况。原因：未提前完成跨系统字段的格式校验与映射，部分文档的专属字段（如凭证编号）未被正确解析，导致向量化时丢失对应内容。

## 怎么确认配好了
- 上传单份审计工作底稿，查看分块后的文本片段是否覆盖完整的问题描述段落，无明显语义截断。
- 发起一次关联检索，验证召回结果的数量与相似度是否符合预设的阈值区间，无过多冗余或过少匹配项。
- 检查系统日志，确认全量索引任务的执行时长符合预期，未出现持续超时的报错。
- 进入模型管理页面，确认已配置的嵌入模型与语言模型均显示为可用状态，无配置报错。
