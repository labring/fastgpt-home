# 内控评价、审计与整改的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类涉及的文档包括内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据来源于企业内控系统、ERP、财务共享系统、审计管理系统、采购合同项目系统，更新频率为年度。文档结构包含固定业务字段，如问题编号、整改措施、责任主体、完成节点等，部分文档附带结构化量化指标与非结构化佐证材料。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征对模型接入与配置带来明确约束。多系统数据源要求配置兼容不同输出格式的内容解析规则，避免数据格式不兼容导致的提取错误。年度更新频率无需高频增量同步，可采用全量更新的向量库更新策略，降低同步成本。文档包含固定业务字段与佐证材料，需模型能区分结构化字段与非结构化内容，避免信息混淆。核心耗时环节涉及业务样本与凭证抽取，需模型具备结构化信息提取能力，减少人工整理工作量。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配本品类多类文档的上下文长度需求，涵盖内控自评报告、整改台账等内容 |
| `maxTokens` | 2000–3000 token | 满足审计工作底稿、问题清单等文档的输出内容长度要求 |
| `temperature` | 0.1–0.3 | 确保输出内容的准确性，避免随机性过高导致的审计问题描述偏差 |
| AIPROXY_API_ENDPOINT | 按实际部署的模型接入地址填写 | 适配第三方模型接口的路径要求 |
| `AIPROXY_API_TOKEN` | 按实际生成的密钥填写 | 保障模型接口调用的身份验证有效性 |
| `toolChoice` | auto | 允许模型根据任务类型自动选择处理逻辑，适配多文档混合处理场景 |

## 容易做错的三处
- 现象：模型调用后响应为空，日志显示`模型流响应为空`。原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致接口请求无法正常连通。
- 现象：提取的审计问题与原文档的业务字段不匹配。原因：未配置适配本品类固定业务字段的解析规则，导致模型无法识别专属字段标识。
- 现象：向量库召回内容缺失整改台账的佐证材料。原因：`maxContext`取值过小，未纳入足够的历史文档上下文，导致召回范围受限。

## 怎么确认配好了
- 执行curl命令调用模型接口，验证接口连通性与基础响应是否正常。
- 上传单份整改台账文档，核对模型提取的问题编号、整改措施等字段是否与原文档一致。
- 查看系统日志，确认`maxContext`、`maxTokens`等配置参数的实际调用值与预设值一致。
- 模拟年度全量数据同步流程，验证向量库更新是否能正常完成且无格式报错。
