# 内控评价、审计与整改的文书与材料起草：部署与升级

## 这个品类的数据长什么样
该品类的数据来自企业内控系统、ERP、财务共享系统、审计管理系统、采购合同项目系统。日常生成的文档包括内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明，数据更新频率为年。文档结构多包含业务主体信息、问题描述、整改要求、佐证材料关联项，字段涵盖责任部门、整改时限、验证结果等，单位多以项目、批次、份为统计维度。

## 这些特征在「部署与升级」这一环带来什么约束
数据来源分散且需对接多套企业内部系统，部署阶段需适配不同系统的接口格式，需预留多数据源对接配置项。数据更新频率低但单批次数据量较大，升级阶段需保障批量数据导入的稳定性，避免中断。文档字段多且关联关系复杂，部署时需配置字段映射规则，确保抽取的信息准确对应到文书模板。整改闭环相关的佐证材料需关联存储，升级时需确认存储服务的兼容性，避免关联关系丢失。审计流程的事后抽样特性要求文书生成时需关联业务样本凭证，部署阶段需配置样本数据的关联索引。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 企业审计管理系统MongoDB实例地址 | 该品类核心的审计工作底稿、问题清单等数据存储于审计管理系统的MongoDB库，需直接对接获取 |
| `PG_URL` | 企业ERP与财务共享系统PostgreSQL实例地址 | 业务样本、凭证数据存储于ERP与财务共享系统的PostgreSQL库，用于抽取审计所需的业务数据 |
| `STORAGE_S3_ENDPOINT` | 企业内部合规对象存储服务接入地址 | 整改销号证明等佐证材料需存储于企业合规的对象存储，需配置对应接入端点保障文件关联 |
| `REDIS_URL` | 企业内部缓存服务地址 | 用于缓存高频访问的审计问题模板、整改台账数据，降低内部系统的查询压力 |
| `DB_MAX_LINK` | 10–15 条 | 适配多数据源同时连接的场景，避免连接数过多导致内部系统负载过高 |
| `FE_DOMAIN` | 企业内部办公域名 | 用于生成文书的访问链接，确保仅内部授权人员可访问生成的文档 |

## 容易做错的三处
- 执行升级命令时返回POST /api/admin/initv4818 404状态码，耗时76ms。原因是未正确配置`ROOT_KEY`，或部署目录下的初始化脚本路径与命令参数不匹配，导致接口未正确加载。
- 部署完成后登录界面提示用户名或密码无效，无法查询初始凭证。原因是未执行初始化脚本生成用户凭证文件，或未配置`FILE_TOKEN_KEY`用于加密存储用户凭证信息。
- 生成的审计工作底稿缺少业务样本关联字段。原因是未正确配置`DB_MAX_LINK`的连接数阈值，导致无法拉取全部业务样本数据，或字段映射规则配置错误。

## 怎么确认配好了
- 执行数据库连接测试命令，验证`MONGODB_URI`与`PG_URL`的配置可正常连接对应数据源，无连接超时或权限错误。
- 上传一份整改销号证明的示例文件，检查`STORAGE_S3_ENDPOINT`配置的存储服务可正常接收并存储文件，无上传失败提示。
- 查看Redis服务日志，确认`REDIS_URL`配置的缓存服务可正常读写数据，无连接异常报错。
- 访问`FE_DOMAIN`对应的内部地址，确认前端界面可正常加载，且文书生成模块显示适配该品类的模板选项。
