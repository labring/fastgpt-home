# 医保基金监管稽核的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据主要来自医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索，更新频率为月度。日常产出的文书包括稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书、整改报告，单份文书包含被检查主体名称、违规事项明细、处理依据、整改要求等字段，数据字段多为结构化编码类与文本描述类结合。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
月度更新的频率决定接口无需高频调用，适合配置定时批量触发任务。多源数据对接需求要求接口支持多外部系统的参数传递与数据拉取，需兼容结构化编码字段与长文本描述内容。文书字段覆盖被检查主体、违规明细等多维度，接口需支持完整参数的序列化传输。同时，稽核环节出错会引发基金损失，接口需配置明确的失败重试与异常告警机制，保障任务执行的可靠性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {FastGPT 平台分配的API密钥}` | 符合HTTP接口鉴权规范，确保调用链路的合法性与安全性，适用于FastGPT v4.17.0版本。 |
| `variables` | 传入被检查单位编码、违规类型标签、月度稽核周期等参数，参数值按实测标定 | 传递业务专属的筛选与生成条件，匹配医保基金监管稽核的固定任务逻辑。 |
| `responseData` | 返回生成的文书文本、校验通过标记、生成耗时三个字段 | 满足稽核文书的归档、合规校验与性能监控需求，明确返回内容结构。 |
| 接口超时时间 | `600 秒` | 月度批量拉取多源医保数据并生成全套文书，需预留充足的处理与传输时长。 |
| 失败重试规则 | 接口返回非200状态码时触发3次重试，间隔30 秒 | 应对网络波动或外部监管系统临时不可用的场景，提升任务执行的稳定性。 |

## 容易做错的三处
- 现象：调用接口时传入的上下文关联参数未被识别，生成的文书未包含本次稽核的历史疑点数据。原因：未在`variables`中正确配置上下文关联的业务参数，或工作流内的上下文触发逻辑未绑定外部接口传入的参数内容。
- 现象：接口返回的文书字段缺失，如未包含违规费用明细或被检查单位名称。原因：未在`responseData`中指定需要返回的文书字段，或外部系统拉取的结算数据未正确传入生成流程。
- 现象：接口调用超时，返回504状态码。原因：未配置合理的超时时长，或批量拉取的医保数据量超出接口预设的处理上限。

## 怎么确认配好了
- 调用测试接口，查看返回的HTTP状态码为200，确认`Authorization`鉴权参数已被正确识别。
- 传入预设的测试业务参数，检查生成的文书是否包含传入的`variables`中的业务字段，确认参数传递生效。
- 模拟外部系统临时不可用的场景，确认接口触发重试机制，验证失败处理逻辑。
- 查看接口返回的`responseData`字段，确认包含预设的文书、校验标记等内容，确认返回结构正确。
