# 医保基金监管稽核的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
该品类的日常文档包含稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书、整改报告，数据来源包括医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索。数据更新频率为月度，文档多包含监管规则条目、结算明细、疑点标注、违规认定依据等字段，无统一固定单位，字段内容随文档类型灵活调整。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的批量数据要求索引支持批量导入与增量更新，避免单次全量索引耗时过长。多类型文档结构差异显著，需适配不同字段的分块逻辑，避免关键监管信息被拆分。结算数据与追溯码包含大量结构化数值与编码，需确保向量模型能兼容混合字段的语义提取。稽核相关文档的违规认定依据需精准匹配，索引召回的精度直接影响后续文书起草的准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类文档中长段落的监管规则、结算明细内容，避免拆分关键违规认定依据 |
| 重叠长度 | 100–200 字符 | 确保跨块的语义连贯，避免分割疑点清单、约谈记录中的连续逻辑 |
| 相似度阈值 | 0.75–0.85 | 精准匹配监管规则与医保结算疑点数据，降低误召回概率 |
| 单次搜索上限 | 前 8 条 | 聚焦核心稽核疑点，避免过多检索结果干扰处理决定书、整改报告的起草 |
| `defaultToken` | 4096 | 适配基金监管规则库的长文本内容，确保完整提取规则语义 |
| `maxToken` | 8192 | 支持整合多份文档的稽核依据，满足文书起草的上下文需求 |

## 容易做错的三处
- 现象：界面显示索引任务长时间处于运行状态，无进度更新。原因：未针对月度批量的医保结算数据配置增量索引，采用全量重复索引方式，导致任务耗时远超预期。
- 现象：检索结果返回的文档块与稽核疑点不匹配，或出现部分字段为空的情况。原因：分块长度设置过小，拆分了约谈记录、处理决定书中的连续违规认定内容，导致语义断裂。
- 现象：调用指定向量模型时出现配置报错，无法生成向量。原因：未正确配置模型的API访问参数，或未适配该模型的`maxToken`输入限制，导致请求被拦截。

## 怎么确认配好了
- 查看索引任务的进度日志，确认批量导入的月度数据已完成分片处理，无报错信息。
- 发起针对稽核疑点的检索测试，核对返回结果的文档类型与业务场景匹配度，调整相关配置项至符合业务需求。
- 验证向量模型的调用状态，确认模型能正常生成对应文档块的向量，无连接或参数报错。
- 检查分块与重叠参数的配置，确保长文档未被过度拆分，关键监管字段未被分割。
