# 医保基金监管稽核的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据覆盖医保基金监管全流程相关文档与业务数据，日常产出文档包括稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书、整改报告。数据来源为医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索，更新频率为每月一次。单份文档包含业务主体信息、违规疑点描述、对应数据溯源标识、处理建议等字段，部分文档关联多维度的医保结算与追溯数据，需结合多源信息完成稽核流程。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源要求检索模块需兼容结构化结算数据、非结构化文档与规则文本，适配不同字段的匹配规则。月度更新频率意味着知识库需配置定期同步任务，确保监管规则与结算数据的时效性。单份文档关联多溯源标识的结构，要求检索需支持多字段联合匹配，精准关联疑点与对应业务数据。稽核流程的严谨性要求召回结果需附带明确的数据来源与匹配依据，支撑后续文书起草的合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.72–0.85 | 匹配稽核疑点描述与业务数据的语义相似度，区间覆盖监管规则与疑点的匹配精度，按实测标定 |
| `limit` | 前8条 | 单次检索返回的关联文档数量，适配稽核文书起草需参考多份合规文档与历史案例的需求 |
| `searchMode` | hybrid | 混合检索模式，兼顾结构化医保结算数据与非结构化文档的召回效果，适配多源数据特征 |
| `usingReRank` | 开启 | 对初始召回结果重排，提升与稽核疑点高度相关的文档排序优先级，优化文书起草的参考质量 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户查询扩展相关监管规则与结算数据关键词，覆盖更全面的关联业务信息 |
| `collectionIds` | 传入对应医保基金监管知识库的集合ID | 限定检索范围为专属业务知识库，避免混入无关的非医保监管类数据 |

## 容易做错的三处
- 调用`/api/core/dataset/collection/create/apiCol`接口时触发Query read timeout报错，原因是检索范围未限定为专属医保基金监管知识库，导致系统加载过多冗余数据，超出接口处理阈值。
- 外部传入知识库ID后未返回任何搜索结果，原因是`collectionIds`参数配置错误，或传入的集合ID未关联医保基金监管相关的业务数据源。
- 工作流中无法获取到可用的知识库ID，原因是未在FastGPT平台完成医保基金监管专属知识库的创建与同步，或未正确提取已创建集合的ID信息。

## 怎么确认配好了
- 进入FastGPT v4.17.0版本的知识库管理页面，查看对应集合的配置项，确认`similarity`、`limit`等参数已按预设值配置。
- 发起模拟稽核疑点查询，检查返回结果的数量与排序是否符合预期，验证`usingReRank`与`searchMode`的配置生效。
- 调用外部API传入正确的`collectionIds`参数，验证是否能返回关联的医保基金监管相关文档，确认接口调用逻辑正确。
- 查看知识库同步日志，确认月度更新任务已正常执行，数据源未出现异常。
