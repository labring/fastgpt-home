# 医保费用结算审核的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
数据来源包括全国医疗保障信息平台、医院HIS与医保接口、医保目录和编码库、异地就医结算平台，更新频率为每日。日常处理的文档包含医保结算清单、费用明细、病案首页、处方、拒付清单、结算对账单，字段涵盖诊疗项目编码、药品耗材编码、费用金额、参保人信息、诊疗时间等结构化内容，同时关联非结构化的病历文本与处方图片。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的医保目录编码库要求模型接入配置能同步加载最新的编码数据，避免因使用过期编码导致基金多付或拒付争议。多类文档的混合处理需要配置的上下文窗口能容纳批量结算明细与关联的病历、处方文本，防止核心审核字段被截断。结构化字段与非结构化文本的结合，要求模型请求格式适配同时解析编码匹配与文本校验的需求，而批量审核的场景则需要配置支持稳定的请求处理，保障多笔结算单的审核效率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的功能逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配批量结算清单、关联处方与病案首页的总文本长度，避免截断核心审核字段 |
| `maxTokens` | 2000–3000 token | 覆盖单条审核结果的文书起草长度，满足拒付申诉材料的输出要求 |
| `temperature` | 0.1–0.3 | 降低随机生成概率，保障编码匹配、费用核对的结果一致性 |
| `toolChoice` | auto | 自动调用内置的编码匹配工具，适配医保目录与结算数据的关联校验 |
| `vision` | 开启 | 支持解析处方、结算单等图片类材料，适配非结构化的图片文档场景 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写实际接口地址 | 适配国内大模型或自定义部署的模型调用路径 |
| `AIPROXY_API_TOKEN` | 由部署方生成的鉴权密钥 | 保障模型调用的安全性，避免未授权访问 |

## 容易做错的三处
- 现象为模型返回空值，原因是未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或请求格式未适配自定义部署的模型（如vllm）的输入要求。
- 现象为无法选择通义千问等国内大模型，原因是未在部署配置中添加对应模型的接入路径与鉴权信息，导致平台无法识别可选模型列表。
- 现象为图片类结算材料解析失败，原因是未开启`vision`配置，或传入的图片数据格式不符合模型要求（如未使用base64编码）。

## 怎么确认配好了
- 发起单条结算单的测试请求，核对模型返回的审核文书是否包含对应诊疗项目的编码匹配结果，确认上下文配置未截断核心内容。
- 切换至国内大模型选项，检查平台可选模型列表是否包含目标模型，确认API端点与密钥配置正确。
- 传入包含图片的处方或结算材料，检查模型是否能正确解析图片中的关键信息，确认`vision`配置已开启。
- 查看模型调用日志，核对请求格式与返回结果的字段完整性，排查空返回或格式异常的问题。
