# 医保费用结算审核的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来自全国医疗保障信息平台、医院HIS与医保接口、医保目录和编码库、异地就医结算平台。日常处理的文档包含医保结算清单、费用明细、病案首页、处方、拒付清单、结算对账单，单笔文档多包含诊疗项目编码、费用金额、参保人身份标识等字段，更新频率为每日，需覆盖单笔或批量的医疗费用支付相关文书与材料。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据每日更新要求知识库需配置自动同步机制，确保医保目录、结算规则等核心数据实时可用，避免审核时使用过期标准。文档包含诊疗项目、药品耗材编码等强校验字段，要求检索需精准匹配编码，否则可能导致费用审核错误。单笔或批量结算文书的结构差异，要求检索需支持按文档类型过滤，同时需控制召回结果的格式适配不同审核场景的文书起草需求。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配医保编码等强校验字段，需保证相似度阈值足够过滤无关结果，同时覆盖合规的编码变体 |
| `limit` | 前8–12条 | 结算审核需同时参考多份关联文档，如处方、结算清单、医保目录，8–12条可覆盖常见关联场景 |
| `searchMode` | 精确匹配优先 | 适配医保编码、费用规则等需精准匹配的业务场景，避免泛化召回导致审核错误 |
| `usingReRank` | 开启 | 对召回结果按相关性重新排序，提升高匹配度的医保目录、结算规则文档的展示优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展查询词，补充医保编码的同义词、常用别名，适配不同渠道上报的编码表述差异 |
| `collectionIds` | 绑定医保目录、结算规则、本地结算文档专属集合 | 隔离业务数据，避免无关知识库内容干扰结算审核的检索结果 |

## 容易做错的三处
- 长文档（如月度结算对账单）被错误切割为无意义的片段，导致检索无法匹配完整的费用明细。原因是未针对医保文档的字段结构调整分块规则，使用了通用的分块参数。
- 检索结果仅返回2条以内，无法覆盖处方、结算清单的关联内容。原因是未调整`limit`参数，使用了默认的低召回条数配置。
- 检索结果中出现与医保编码无关的泛化内容，导致审核错误。原因是未将`searchMode`设置为精确匹配优先，启用了泛化检索模式。

## 怎么确认配好了
- 手动上传一份医保结算清单文档，检查检索时是否能召回对应的医保目录编码数据。
- 调整`similarity`参数后，验证召回结果的匹配度是否符合业务校验要求。
- 触发一次自动同步任务，检查知识库数据的更新时间是否与源数据更新时间一致。
- 切换`searchMode`为精确匹配模式，验证编码类字段的检索准确率是否提升。
