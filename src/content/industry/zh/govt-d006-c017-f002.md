# 医疗机构监督与公共卫生检查的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自卫生监督信息系统、医疗机构电子化注册系统、投诉举报平台与执法检查记录，日常文档包含监督检查表、医疗机构执业许可证、整改通知书、监督意见书与处罚案卷。数据更新频率为月度，文档多包含机构资质标识、检查项详情、整改要求与处罚相关字段，部分为结构化表单，部分为半结构化执法记录。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新频率要求索引支持增量同步与定期全量刷新，避免全量重建占用过多资源。多类型文档包含结构化表单与半结构化执法记录，需要适配不同长度的文本分块逻辑。数据聚焦机构资质、整改要求等合规相关字段，向量模型需要准确捕捉这类语义关联。长文本执法记录可能带来token消耗过高的问题，需要合理限制单条文本的向量生成长度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类的结构化表单与半结构化执法记录的文本长度 |
| 重叠长度 | 100–150 字符 | 保留跨分块的机构资质、整改要求等上下文关联 |
| 相似度阈值 | 0.72–0.80 | 精准匹配合规相关的资质、检查项语义，避免误匹配 |
| 单次搜索上限 | 前 8–12 条 | 聚焦高相关的监督与合规数据，适配执法场景的查询需求 |
| `maxToken` | 8000–10000 token | 适配长文本执法记录的向量生成需求，避免截断关键合规信息 |
| `defaultToken` | 按实测标定 | 适配不同embedding模型的token限制，支持归一化配置 |

## 容易做错的三处
- 现象：切换知识库向量模型后界面显示无进度，且无法回退到原模型。原因：仅修改模型参数未触发向量重生成，未启动增量索引任务，导致索引任务卡住。
- 现象：单次查询消耗超过预设的`maxToken`，导致查询超时或返回空结果。原因：未限制单条文本的分块长度，长文本执法记录被直接送入向量模型，超出token上限。
- 现象：向量匹配结果与合规资质无关，匹配精度不足。原因：相似度阈值设置过低，引入了大量不相关的投诉或非执法类数据，干扰检索结果。

## 怎么确认配好了
- 手动导入一份本品类的典型文档，查看分块后的文本长度是否符合预设的分块长度配置。
- 发起一次针对机构资质的查询，检查返回结果的条数是否符合单次搜索上限的设置。
- 查看向量模型的归一化配置是否开启，匹配FastGPT v4.17.0版本的更新要求。
- 触发一次增量索引任务，确认任务进度条正常更新，无卡住情况。
