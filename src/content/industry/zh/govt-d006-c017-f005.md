# 医疗机构监督与公共卫生检查的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
本品类数据主要来自卫生监督信息系统、医疗机构电子化注册系统、投诉举报平台与执法检查记录，更新频率为月度。日常处理的文档包含监督检查表、医疗机构执业许可证、整改通知书、监督意见书与处罚案卷，单份文档字段包含机构统一社会信用代码、许可有效期限、检查点位、整改要求、执法人员签名等，无额外自定义单位，字段格式多为结构化文本与表单类内容。

## 这些特征在「工具调用与插件」这一环带来什么约束
月度更新的数据需要工具调用适配批量拉取的节奏，避免高频请求触发接口限制。结构化与表单类文档要求工具调用需支持字段提取与结构化校验，确保提取的许可编号、整改项等字段格式合规。多来源数据的整合需要插件支持跨系统数据关联，将执法记录与机构注册信息匹配。文书生成需调用对应模板，工具调用需关联特定文档类型的预设字段，确保生成的监督意见书、整改通知书符合业务格式。

## 配置怎么定
本页面基于FastGPT v4.17.0版本编写，以下为适配本品类的工具调用与插件配置建议：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `functionCall` 模式开关 | 开启 | 适配结构化字段提取与标准化文书生成需求，确保输出的监督意见书、整改通知书格式合规 |
| 单次工具调用上限 | 前8条 | 匹配月度批量处理的单批次数据规模，避免跨系统数据拉取过载 |
| 上下文窗口长度 | 8000–12000 token | 容纳执法记录、机构注册信息与模板内容，保障文书生成的信息完整性 |
| 超时阈值 | 600秒 | 适配卫生监督信息系统等数据源的响应延迟，避免因数据拉取缓慢触发调用失败 |
| 结果排序规则 | 按合规优先级排序 | 优先提取医疗机构资质有效、无历史违规的记录，确保文书生成的核心信息准确 |

## 容易做错的三处
- 调用日志显示获取数据异常，伴随error报错，原因是未配置卫生监督信息系统、医疗机构电子化注册系统的数据源访问权限，导致工具无法拉取月度更新的机构资质与执法记录数据。
- 文本提取工具返回`400 Invalid JSON payload received. Unknown name`报错，原因是调用时传入了品类文档未预设的非标准字段，例如额外添加了未在监督检查表中定义的自定义字段。
- 调用PgVector插件时出现兼容性报错，原因是未升级到适配当前FastGPT版本的插件最新版本，导致无法正确存储与检索结构化的监督文档数据。

## 怎么确认配好了
- 执行单机构资质数据提取测试，核对提取的字段与数据源中的实际内容一致。
- 触发批量工具调用，确认返回结果的条数与设置的单次调用上限匹配。
- 模拟跨系统数据拉取，验证调用超时阈值适配数据源的响应速度，无超时报错。
- 生成标准监督意见书模板，确认生成内容包含预设的执法人员签名、整改要求等必填字段。
