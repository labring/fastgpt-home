# 参保登记与缴费核定的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
该品类的典型数据主体涉及社保经办机构、人社局、税务部门及用人单位人事财务部门。日常生成的文档包括参保登记表、缴费基数申报表、人员增减表、社保费核定单、个人权益记录。数据来源涵盖社会保险经办系统、税务社保费征收系统、市场主体登记信息及公安民政共享数据，更新频率为每日。文档多为结构化表单，包含人员身份信息、劳动关系标识、缴费基数、单位注册信息等字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的结构化表单文档字段密集且存在跨系统关联数据，要求向量分块需保留关键字段的上下文完整性。每日更新的数据量需适配增量索引策略，避免全量重建带来的性能损耗。多源异构数据的统一嵌入需要兼容不同系统的字段格式，同时需保证检索结果的准确性，防止因匹配偏差导致漏缴少缴或权益记录错误。

## 配置怎么定
本配置基于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配参保登记类表单的字段长度，避免截断关键身份信息 |
| 重叠长度 | 100–150 字符 | 保持跨分块的上下文关联，确保人员信息的完整匹配 |
| `maxToken` | 8192 | 适配主流嵌入模型的上下文窗口限制，避免嵌入失败 |
| `defaultToken` | 0 | 统一缺失字段的嵌入基准，减少异构数据的嵌入偏差 |
| 重排模型 | Qwen3-Rerank | 适配本地ollama部署环境，提升结构化文档的排序精度 |
| 相似度阈值 | 按实测标定 | 适配社保数据的相似度分布，平衡召回率与准确率 |
| 单次搜索上限 | 前 10 条 | 符合业务审核的常规查看范围，减少无效结果 |

## 容易做错的三处
- 现象：pgvector索引查询出现超时报错，原因：未针对每日更新的数据配置增量索引策略，频繁执行全量索引重建导致性能不足。
- 现象：检索结果遗漏人员增减表的关键人员信息，原因：分块长度设置超出表单字段的合理范围，截断了核心字段内容。
- 现象：token统计数值与实际文档内容不符，原因：未正确配置`maxToken`的边界限制，导致长文档的token计数出现溢出偏差。

## 怎么确认配好了
- 查看嵌入任务的运行日志，确认所有目标文档均完成分块与嵌入，无截断或失败提示。
- 执行模拟检索测试，核对返回结果包含参保登记表、缴费基数申报表等该品类的核心文档类型。
- 验证token统计功能，确认单文档的token计数与实际内容长度匹配，无异常溢出。
- 触发一次日增量更新任务，确认新生成的社保数据能正确同步至索引中。
