# 参保登记与缴费核定的文书与材料起草：工作流编排

## 这个品类的数据长什么样
本品类的数据来自社会保险经办系统、税务社保费征收系统、市场主体登记信息库及公安民政共享数据，每日更新全量同步。日常产出的文书包含参保登记表、缴费基数申报表、人员增减表、社保费核定单、个人权益记录，结构多为结构化表单，字段涵盖统一社会信用代码、人员身份标识、缴费基数、增减变动类型等，需严格匹配各数据源的字段格式要求。

## 这些特征在「工作流编排」这一环带来什么约束
每日更新的数据源要求工作流需支持定时触发同步最新数据，避免使用过期的人员身份、缴费基数等信息。多类跨系统数据源的字段格式差异，要求工作流需配置跨源数据校验节点，确保各来源字段的一致性与合规性。固定结构的文书表单，要求工作流需预设对应字段的自动映射规则，减少手动录入的格式错误。核心耗时的人员增减、基数申报环节，要求工作流可串联数据拉取、校验、表单生成、审核全流程节点，优化单环节处理效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `variables` | 全局参保人员库、税务征收数据快照、单位登记信息 | 覆盖本品类核心数据源字段，满足文书生成的基础数据需求 |
| 节点触发规则 | 每日02:00定时触发 + 人员变动事件触发 | 匹配数据每日更新频率，及时响应人员增减变动的业务需求 |
| 超时设置 | 300-600 秒 | 覆盖跨系统数据拉取、文书生成的常规处理时长，避免因系统延迟触发失败 |
| 上下文长度 | 1000-2000 token | 覆盖本品类文书的常规内容长度，避免模型生成时出现上下文溢出 |
| `nodeId` | 按业务环节命名（如data_check、form_generate） | 便于后续排查工作流异常节点，快速定位问题 |
| 表单生成节点 | 绑定预设的参保登记/缴费核定模板 | 匹配本品类固定的文书格式要求，确保输出文档符合业务规范 |

## 容易做错的三处
- 现象：调用工作流时返回「Key is error. You need to use the app key rather than the account key」报错。原因：未使用工作流应用专属密钥，误将平台账号密钥填入调用配置中。
- 现象：FastGPT v4.17.0版本中，工作流配置页面的全局变量选项仅显示两个预设项，无法添加自定义变量。原因：新版本对全局变量的配置入口进行了调整，需通过应用设置页完成自定义变量创建后再在工作流中调用。
- 现象：通过前后端接口调用工作流时，无法正确匹配目标工作流，返回空结果或404状态码。原因：未正确绑定工作流的唯一`nodeId`，或使用了已删除的工作流节点ID。

## 怎么确认配好了
- 检查工作流的触发配置，确认定时触发的时间与数据更新频率匹配，事件触发的规则覆盖核心业务场景。
- 调用测试接口，传入模拟的单位登记信息与人员数据，核对生成的文书字段是否与预设模板一致。
- 查看工作流运行日志，确认各节点的执行时长在合理区间，无连续超时或报错记录。
- 验证跨系统数据拉取节点，确认返回的字段与配置的`variables`参数完全匹配，无缺失或格式错误。
