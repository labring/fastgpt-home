# 双随机、一公开监管检查的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
该品类的数据通常来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库，更新频率为每月一次。日常生成的文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示。数据字段包含检查对象统一社会信用代码、监管类别、执法人员资质编号等，文档通常按行政区域、监管批次划分存储。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据每月更新的要求，通常使得工具调用需配置定期同步数据源的逻辑，避免使用过期的检查对象或执法人员信息。多类型文档的需求，要求插件需适配不同模板的字段填充规则，例如抽查计划通常需填入批次号、行政区域，现场检查记录需关联检查事项清单。数据来源分散的特点，通常需要插件统一拉取多系统数据，同时需校验字段完整性，防止因信息缺失导致检查结果漏公示或抽取不合规。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 自动匹配业务插件 | 依据：需自动调用执法人员匹配、检查对象抽取等专属插件，减少手动配置误差 |
| `functionCall` | 开启字段强制校验 | 依据：需校验检查对象统一社会信用代码、监管事项编码等必填字段，确保文书格式合规 |
| 数据源同步周期 | 7 天 | 依据：匹配数据每月更新的频率，兼顾数据时效性与调用资源消耗 |
| 插件调用触发时机 | 按监管批次生成节点触发 | 依据：匹配双随机、一公开监管工作按批次推进的业务流程，避免无效调用 |
| 工作流唯一ID绑定规则 | 关联监管批次号 | 依据：便于按批次追踪工作流执行状态，符合监管档案的可追溯要求 |
| 调用重试次数 | 3 次 | 依据：应对单次调用时的网络波动或数据源临时不可用，提升调用成功率 |

## 容易做错的三处
- 现象：生成的检查对象名单包含已注销主体或存在重复条目，监管对象抽取不合规。原因：未配置数据源同步逻辑，使用了过期的企业信用信息数据，且未开启重复项校验。
- 现象：工作流调用外部Python代码函数后无返回结果，日志显示参数传递失败。原因：未按业务字段格式配置参数传递规则，例如未将检查对象的统一社会信用代码转换为标准字符串格式。
- 现象：插件调用后未生成抽查结果公示文档，且无法追溯调用过程。原因：未开启工作流日志记录开关，或未配置日志存储路径，导致无法排查检查结果漏公示的问题。

## 怎么确认配好了
- 手动触发一次测试监管批次的工作流，核对生成的检查对象名单是否与本地同步的数据源一致。
- 查看工作流执行日志，确认`toolChoice`自动调用了对应业务插件，且`functionCall`校验了所有必填字段。
- 检查工作流的唯一ID是否与测试批次号绑定，可通过该ID检索对应执行记录。
- 模拟一次插件调用失败的场景，确认系统会按配置的重试次数尝试重新调用。
