# 双随机、一公开监管检查的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自双随机、一公开监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库，更新频率为月度。日常文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示，包含统一社会信用代码、执法人员证件编号、检查事项条目、整改要求等结构化字段与非结构化说明内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据源要求知识库同步周期匹配月度更新节奏，避免数据滞后影响抽查计划生成。多类型文档的混合处理，要求模型同时支持结构化字段提取与非结构化文书生成。多来源数据对接需要配置适配不同系统的接入规则，避免数据格式不兼容。现场检查记录与整改通知书的格式合规性要求，需在模型配置中加入格式校验关联逻辑，防止生成不符合监管要求的文书内容。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 该品类文档包含多份关联材料，需完整加载抽查计划、检查名单等上下文内容 |
| `maxTokens` | `2000–3000 token` | 现场检查记录、整改通知书等单份文书的生成长度需求 |
| `temperature` | `0.2–0.4` | 监管文书需保持严谨规范，不宜过度发散 |
| `AIPROXY_API_ENDPOINT` | 部署节点的专属接口地址 | 需隔离不同监管部门的业务数据调用链路 |
| `AIPROXY_API_TOKEN` | 绑定专属权限的令牌 | 需限制仅授权的监管系统可调用模型接口 |
| `toolChoice` | `auto` | 需自动选择是否调用知识库检索检查事项清单等关联数据 |

## 容易做错的三处
- 现象：模型生成的抽查结果公示出现漏填检查对象字段。原因：未配置`maxContext`适配多份检查名单的上下文加载，导致部分数据被截断。
- 现象：配置外部接入链路时提示接收消息地址校验失败。原因：未配置公网可访问的接口地址，或未在无有效SSL证书场景下禁用证书校验。
- 现象：生成的整改通知书出现非规范表述。原因：未将`temperature`设置在合理区间，导致文书内容偏离监管要求的严谨风格。

## 怎么确认配好了
- 运行月度数据源同步任务，核对同步后知识库内的检查对象名单、检查事项清单数量与源系统一致。
- 提交单份抽查计划生成请求，核对模型返回内容包含所有必填字段且格式符合监管文档规范。
- 调用模型接口测试，确认返回结果的token消耗处于配置的`maxTokens`区间内。
- 检查接口权限配置，确认仅授权的监管系统IP可访问模型接入地址。
