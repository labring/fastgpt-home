# 国土空间规划编制与实施评估的文书与材料起草：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来源于国土空间基础信息平台、自然资源调查监测数据、人口经济统计及遥感影像，更新频率为年度。日常产出的文档包括国土空间总体规划、详细规划、专项规划、规划实施评估报告、公众意见汇总等，文档结构通常包含空间范围划定、约束指标清单、布局方案说明、多源数据佐证材料及反馈意见整理模块，字段涉及空间坐标、人口规模、设施布局等，部分字段带有平方公里、公顷、万人等单位。

## 这些特征在「工作流编排」这一环带来什么约束
多源跨平台数据的年度更新特性，要求工作流配置定时同步节点，确保输入数据为最新版本。文档包含多模块复杂结构，需拆分不同内容节点分别处理，避免上下文过载。数据汇总、布局协调等环节耗时占比高，需设置并行处理节点优化流程。文档涉及空间约束指标，需配置字段校验节点，确保数据单位与格式符合要求。一旦环节出错将引发规划审批延误，需配置失败回退与重试节点，保障流程稳定性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按规划文档的固定字段预设初始值，如三区三线约束指标、年度更新数据版本 | 该品类文档需固定引用年度更新的国土空间数据，预设变量可减少重复录入 |
| `variables` | 绑定工具返回的最新空间数据，用于更新文档中的动态字段 | 该品类数据为年度更新，需通过变量同步最新的调查监测结果 |
| `nodeId` | 为数据同步、文档生成、校验环节分别配置唯一标识 | 该品类工作流包含多环节串行或并行处理，唯一nodeId可精准定位节点状态与失败位置 |
| 失败重试次数 | 2–3 次 | 该品类数据同步环节可能因平台接口波动出错，有限重试可降低流程中断概率 |
| 超时时间 | 600 秒 | 该品类空间数据处理环节需加载多源遥感影像与统计数据，需预留足够处理时长 |
| 变量引用长度 | 1000–1500 字符 | 匹配该品类单模块文档的平均长度，避免上下文过载 |

## 容易做错的三处
- 工作流发起数据同步请求后，工具调用环节直接返回超时报错。原因是未配置符合该品类数据处理需求的超时时间，空间数据加载耗时超出预设阈值。
- 全局变量未按预期更新，规划文档中的约束指标未显示最新年度数据。原因是未在定时同步节点后配置变量更新触发逻辑，或变量引用未绑定正确的`variables`参数。
- 文书正文无法正确引用预设变量，公众意见汇总模块内容为空。原因是未在正文编辑环节正确配置变量引用路径，或初始变量未按品类文档结构预设正确内容。

## 怎么确认配好了
- 检查`variables`参数是否绑定了该品类文档所需的年度更新数据字段，核对变量初始值与模板结构匹配。
- 查看每个工作流节点的`nodeId`是否唯一，确认节点状态可被精准追踪。
- 模拟数据同步环节，验证失败重试与超时配置是否符合该品类数据处理的实际耗时。
- 生成测试文档，检查变量是否正确引用到正文各模块，确认公众意见、约束指标等字段显示正常。
