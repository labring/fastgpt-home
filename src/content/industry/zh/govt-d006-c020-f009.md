# 国土空间规划编制与实施评估的文书与材料起草：模型接入与配置
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类的数据主要来自国土空间基础信息平台、自然资源调查监测数据、人口经济统计数据与遥感影像，更新频率为年度。日常产出的文档包含国土空间总体规划、详细规划、专项规划、规划实施评估报告及公众意见汇总，文档结构包含空间坐标字段、约束指标参数、人口经济统计项与设施布局说明，无固定统一的单文档长度标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入环节需适配不同格式的空间与统计数据，年度更新的频率则无需配置高频数据同步逻辑。长文本结构的规划文档会占用较多上下文窗口，需调整上下文与输出长度参数。空间坐标与约束指标等专业字段需要模型具备准确识别与关联的能力，因此需配置合适的工具调用规则，避免生成内容脱离规划专业规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配长文本规划文档的上下文容纳需求，避免关键数据被截断 |
| `maxTokens` | `4000–6000 token` | 匹配单份规划材料起草的常规输出长度，满足完整文书生成需求 |
| `temperature` | `0.2–0.4` | 保障规划文书的严谨性，降低生成内容的发散程度 |
| `toolChoice` | `auto` | 自动触发工具调用，实现空间数据与规划文本的关联处理 |
| `quoteMaxToken` | `2000–3000 token` | 保留足够的原文引用片段，支撑规划论证的依据完整性 |
| `AIPROXY_API_ENDPOINT` | 填入Azure官方提供的API端点地址 | 适配Azure OpenAI与标准OpenAI的协议差异 |
| `AIPROXY_API_TOKEN` | 填入Azure OpenAI服务密钥 | 完成Azure模型的身份验证与接入 |

## 容易做错的三处
- 调用Azure OpenAI模型时返回400 Bad Request错误，原因是混淆了标准OpenAI与Azure的API端点格式，未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`。
- 生成的规划文书中空间约束指标缺失或错误，原因是`maxContext`取值过小，无法完整容纳多源空间数据的上下文信息。
- 输出的规划文本逻辑松散且专业表述不严谨，原因是`temperature`取值过高，导致生成内容偏离规划文档的规范要求。

## 怎么确认配好了
- 测试调用配置的模型，检查是否能正常返回规划相关文本，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置无误。
- 导入一份典型的规划文档片段，查看模型是否能准确识别空间坐标与约束指标字段，确认上下文参数适配文档长度。
- 生成一份测试用的规划材料，检查输出内容的严谨性，调整`temperature`至符合专业需求的区间。
- 触发工具自动调用流程，确认`toolChoice`配置可正确关联空间数据处理逻辑。
