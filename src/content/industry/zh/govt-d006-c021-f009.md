# 国库集中支付与报销审核的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类涉及的核心数据来自国库集中支付系统、预算管理一体化系统、电子发票平台与合同管理系统，更新频率为每日。日常处理的文书与材料包含支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，各类文档均包含预算指标编码、经济分类代码、支付金额、审批节点状态等标准化字段，且需关联对应业务系统的唯一标识以完成全链路校验。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据分散于多套业务系统，模型接入时需适配多源数据的格式与权限要求，需配置合理的上下文窗口以承载跨系统关联的完整文档内容。每日高频更新的业务数据要求模型调用延迟匹配日常审核节奏，避免拖慢整体流程。文档字段标准化但业务链路复杂，需限制单次处理的上下文长度，防止冗余信息干扰预算指标与经济分类的精准匹配。单笔支付的合规性要求严格，需调整模型生成的严谨性参数以降低出错风险，避免出现支付退回或资金错付等问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配本品类多系统关联的文档总长度，避免截断包含预算指标、审批链路的关键信息 |
| `maxTokens` | 2000–3000 token | 控制单份审核文书的生成输出长度，匹配单笔支付审核的信息密度需求 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保合规性表述的一致性，适配财政审核的严谨要求 |
| `AIPROXY_API_ENDPOINT` | 本地部署的FastGPT代理地址，端口设为11434 | 适配本地部署的业务数据安全要求，避免敏感财政数据外发 |
| `quoteMaxToken` | 1000–1500 token | 限制引用的原始文档片段长度，聚焦核心的发票、合同校验信息 |
| `vision` | 关闭 | 本品类核心处理文本类文书，暂无需视觉模型能力，降低调用复杂度 |

## 容易做错的三处
- 现象：调用本地部署的模型时返回404 no body错误。原因：未正确配置`AIPROXY_API_ENDPOINT`参数，代理地址指向错误的模型服务端口或未启动本地模型服务。
- 现象：生成的审核文书出现预算指标与实际支付金额不匹配的错误。原因：`maxContext`参数取值过小，截断了包含预算指标的关键上下文片段。
- 现象：语音输入转文本环节出现unmarshal_resp报错。原因：未关闭`vision`配置，模型尝试解析非图片输入的语音转写文本，导致响应格式解析失败。

## 怎么确认配好了
- 检查`AIPROXY_API_TOKEN`参数是否与本地模型服务的密钥一致，核对FastGPT v4.17.0版本配置页面的密钥字段。
- 触发单笔支付申请的文书起草测试，查看生成内容是否包含完整的预算指标、经济分类等核心字段。
- 查看模型调用日志，确认上下文窗口未出现截断提示，且响应格式符合预期。
- 模拟多文档关联场景，验证配置的上下文承载能力是否能覆盖所有关联的合同、发票信息。
