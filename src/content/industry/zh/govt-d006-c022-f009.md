# 土地使用权、矿业权与国有产权交易的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档包含出让公告、交易须知、竞买申请、保证金凭证、成交确认书、挂牌结果公告、产权转让说明书等，数据主要来自全国公共资源交易平台、自然资源交易系统、产权交易所系统、国资监管系统，更新频率为每日。文档多为结构化格式，包含标的权属、限制条件、交易流程、保证金规则等字段，部分文档涉及跨系统的关联数据，整体篇幅跨度较大。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的多源数据要求配置定时同步机制，确保模型调用时使用最新的权属与交易信息。结构化文档的固定字段需要模型准确识别，因此需限制生成内容的严谨性。跨系统数据关联会增加上下文长度，需调整参数适配长文本输入。同时，文书出错会导致成交无效、资产流失等后果，配置需包含数据校验环节，避免生成错误内容。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxTokens` | 8000-12000 token | 产权转让说明书、成交确认书等核心文档篇幅较长，需覆盖完整标的信息 |
| `temperature` | 0.2-0.4 | 文书需保持严谨规范，避免生成随意或不符合交易规则的表述 |
| `quoteMaxToken` | 3000-5000 token | 需引用交易系统的权属数据与历史交易记录，限制引用内容的有效长度 |
| `AIPROXY_API_ENDPOINT` | 填写本地部署的模型服务地址 | 适配私有部署的FastGPT与本地模型的调用链路 |
| `AIPROXY_API_TOKEN` | 配置私有模型的访问密钥 | 保障模型调用的身份验证安全，防止未授权访问 |
| `toolChoice` | auto | 按需调用内置工具完成标的权属校验、格式对齐等辅助操作 |

## 容易做错的三处
- 模型测试时返回404 no body：原因是未正确配置`AIPROXY_API_ENDPOINT`，或私有部署的模型服务未开放对应访问端口。
- 语音输入转文本时触发unmarshal_resp报错：原因是未针对产权交易文档的结构化字段做适配，导致模型解析多段式数据时格式异常。
- Docker私有部署后无法接入本地Ollama模型：原因是未在容器配置中开放模型服务的端口，或未正确填写`AIPROXY_API_ENDPOINT`为容器内的模型访问地址。

## 怎么确认配好了
- 调用`AIPROXY_API_ENDPOINT`对应的模型接口，返回有效响应且无身份验证错误，确认API配置正确。
- 生成一份出让公告草稿，核对是否包含标的权属、交易条件等核心字段，确认`maxTokens`与`quoteMaxToken`配置适配文档长度。
- 提交批量测试数据，观察模型输出的格式与产权交易文书规范一致，确认`temperature`参数的严谨性符合要求。
- 检查私有部署的FastGPT容器日志，无参数解析异常报错，确认整体链路配置无误。
