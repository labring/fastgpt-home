# 安全生产隐患排查治理的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据主要来自安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常生成的文书包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，数据字段包含隐患唯一标识、排查主体、排查时间、隐患类型、整改责任人、整改期限、复查结果等，字段均为政务与安全生产领域通用标准格式，无额外自定义单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据来源多且每日更新，需要接口支持批量拉取不同系统的结构化数据，避免单源数据缺失导致生成的文书内容不全。文档类型多样，接口需兼容不同格式的请求与返回，适配清单、台账、通知书等不同字段结构。更新频率高，接口响应时长需匹配日常业务节奏，避免延迟影响当日排查整改流程。数据关联链路要求，接口需支持隐患从排查到整改再到复查的全链路字段联动，确保生成的文书数据前后一致。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| API 调用密钥 | `Authorization` 头携带 Bearer 令牌 | 符合外部系统接口的通用鉴权规范，保障数据传输安全 |
| 请求超时时间 | 30–60 秒 | 匹配每日批量拉取隐患数据的业务节奏，避免因系统延迟导致接口调用失败 |
| 返回数据格式 | JSON 结构化格式 | 适配隐患排查清单、整改通知书等多类型文书的字段解析需求，便于后续文书生成调用 |
| 上下文变量绑定 | 按`variables`参数传入隐患ID、整改期限等字段 | 实现接口返回数据与文书模板的精准关联，确保生成的文书内容准确对应具体隐患 |
| 响应数据处理 | 提取`responseData`中的核心字段 | 过滤冗余信息，仅保留生成文书所需的隐患编号、整改责任人等关键内容，提升生成效率 |
| 批量调用上限 | 前 100 条/次 | 匹配每日数据更新的规模，避免单次调用数据量过大导致接口超时 |

以上配置基于 FastGPT v4.17.0 版本的界面逻辑编写。

## 容易做错的三处
- 现象：调用接口返回 404 Page Not Found 报错。原因：未正确配置外部系统的接口地址，或接口路径与实际服务路径不匹配。
- 现象：接口返回数据为空，生成的文书缺少核心内容。原因：未正确绑定`variables`参数，未将接口返回的隐患字段传入文书生成流程。
- 现象：批量调用时返回结果条数与预期不符。原因：未设置合理的批量调用上限，或接口分页参数配置错误，导致部分数据未被拉取。

## 怎么确认配好了
- 调用配置好的接口，查看返回的状态码，确认鉴权与地址配置正确。
- 提取接口返回的`responseData`字段，核对是否包含生成文书所需的核心内容。
- 传入测试用的隐患相关字段，通过`variables`参数绑定后生成测试文书，确认内容与接口数据一致。
- 模拟批量调用场景，调用接口查看响应时长，调整超时时间配置以匹配业务需求。
