# 安全生产隐患排查治理的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
本品类的核心文档包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单。数据来源于安全生产监管系统、企业隐患自查系统、执法检查记录及事故统计系统，更新频率为每日。单份文档通常包含隐患编号、隐患类型、排查时间、整改责任人、整改期限、复查结果等固定字段，部分执法类文档还会附带现场照片关联字段，所有数据围绕隐患闭环管理流程生成。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的高频数据要求索引支持增量同步，避免全量重建耗时过长。多类型文档混合存储，需要针对不同文档结构设置差异化分块规则，确保隐患整改期限、复查结果等关键字段被完整捕获。执法类文档附带的非结构化附件，会增加向量提取的复杂度。隐患数据的严谨性要求高，索引召回的结果需严格匹配业务字段，避免无关内容干扰排查判断，同时需限制召回结果的数量，防止文书起草时信息过载。

## 配置怎么定
本配置方案适用于FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配隐患排查清单、整改通知书等文档的段落长度，保留关键字段的完整语义 |
| 重叠长度 | 100–200 字符 | 避免隐患整改期限、复查结果等跨段落的关键信息被截断 |
| 相似度阈值 | 按实测标定 | 匹配本品类数据的语义相似度分布，过滤无关召回结果 |
| 单次搜索上限 | 前 8 条 | 控制文书起草时的信息输入量，避免内容冗余 |
| defaultToken | 4096 | 适配大模型的上下文窗口，容纳多份隐患文档的合并内容 |
| maxToken | 8192 | 支持长文档的向量索引与召回后的完整上下文输入 |

## 容易做错的三处
- 向量索引构建进度停滞，长时间无更新。原因是未配置增量同步规则，全量重建每日更新的海量隐患数据耗时过长。
- 知识库召回结果与提问无关，返回大量不匹配的隐患记录。原因是相似度阈值设置过低，或分块长度未匹配文档结构，导致无关语义被错误关联。
- 向量模型调用超时，索引任务失败。原因是未调整合理的超时参数，处理执法类文档的非结构化附件时超出预设等待时长。

## 怎么确认配好了
- 查看索引任务日志，确认增量同步任务每日自动触发，无全量重建的异常耗时。
- 输入典型隐患排查问题，核对召回结果的文档类型与业务字段是否匹配预设的隐患数据。
- 测试导入导出配置包，确认向量模型与索引的关联设置未丢失。
- 查看向量数据库的存储统计，确认单批次索引的文档数量符合分块长度的预设范围。
