# 安全生产隐患排查治理的文书与材料起草：工作流编排

以下配置基于FastGPT v4.17.0版本的工作流功能制定。

## 这个品类的数据长什么样
本品类数据主要来自安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常生成的文档包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，文档结构通常包含隐患标识、排查主体、整改责任方、时限要求、复查结果等字段，不同文档的字段需匹配对应监管要求的格式规范，确保符合上报与存档的标准。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且需跨系统调取，要求工作流配置跨节点数据拉取环节，适配不同系统的接口格式。每日更新的隐患数据规模要求工作流设置批量处理节点，避免单节点过载影响执行效率。对照重大事故隐患判定标准的排查环节要求工作流配置标准校验节点，确保排查结果符合监管要求。不同文档的字段差异要求工作流配置变量映射环节，将跨系统提取的原始数据自动对齐到对应文档的必填字段。隐患整改的全流程要求工作流设置状态流转节点，跟踪隐患从排查、整改到复查的全流程状态，确保监管要求的全流程跟踪落地。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量映射规则 | 按文档类型预设字段对齐模板 | 匹配隐患排查清单、整改通知书等不同文档的必填字段要求 |
| 批量处理阈值 | 每日 5000 条数据 | 适配每日更新的隐患数据规模，避免单节点过载 |
| 节点超时设置 | 600 秒 | 保障跨系统调取监管数据时的响应稳定性 |
| 状态流转触发条件 | 按整改完成标记触发复查环节 | 匹配隐患排查治理的全流程要求 |
| `variables` 配置 | 绑定隐患等级、整改期限等核心字段 | 确保生成的文书材料包含监管要求的必填信息 |

## 容易做错的三处
- 工作流执行后生成的整改通知书字段为空。原因：未配置`variables`绑定对应系统提取的隐患责任主体字段，导致核心信息缺失。
- 循环处理隐患数据时触发超时报错。原因：批量处理阈值设置过高，超出节点承载上限，且未调整节点超时参数。
- 工作流中调用Mermaid生成流程图失败，无法获取图片链接。原因：未配置Mermaid节点的输出格式为可访问的图片链接，且未校验接口调用权限。

## 怎么确认配好了
- 手动触发单条隐患数据的工作流执行，检查生成的文档是否包含所有预设的必填字段。
- 模拟每日批量数据导入，观察工作流节点的运行状态，确认无超时报错。
- 测试隐患整改完成后的状态流转，检查是否自动触发复查环节的工作流节点。
- 调用Mermaid节点生成流程图，确认返回的链接可正常访问并匹配隐患治理流程。
