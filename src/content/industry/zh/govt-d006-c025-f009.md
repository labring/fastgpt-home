# 安全生产隐患排查治理的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常处理的文档包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单。各类文档的核心字段包含隐患点位、排查时间、责任主体、整改期限、复查结果、判定依据等，不同文档类型的字段顺序与必填项存在差异，需根据具体文档适配字段提取与生成逻辑。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求接入配置需兼容不同系统的API格式与鉴权规则，避免数据提取失败。日更的更新节奏要求上下文加载与生成速度匹配日常办公节奏，避免因加载过慢影响每日排查、整改的流程推进。多类文档的结构差异要求模型配置支持动态适配不同文档的字段规则，确保生成的文书符合监管要求。同时，隐患排查与整改的出错后果严重，要求配置需严格控制生成内容的准确性与规范性，避免因幻觉导致的监管风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单日内多份隐患排查、整改类文档的批量加载，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 匹配单份整改通知书、复查记录的生成长度，满足文书完整输出需求 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保隐患排查清单、台账的字段格式符合监管规范 |
| `toolChoice` | auto | 自动调用工具提取系统内的隐患数据，减少人工录入误差 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接入地址 | 适配安全生产监管系统的API调用链路，保障数据传输安全 |
| `AIPROXY_API_TOKEN` | 绑定专属权限的加密令牌 | 限制仅授权的安全管理部门节点可调用模型，符合政务数据安全要求 |

## 容易做错的三处
- 现象：调用Basic Auth认证的模型时返回401未授权错误。原因：未在模型渠道配置中正确填写Basic Auth的用户名与密码参数，导致鉴权失败。
- 现象：更新aiproxy后，原有模型调用链路失效。原因：未同步更新FastGPT中的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置，导致新旧代理地址不匹配。
- 现象：配置Xinference模型时页面提示连接失败，或使用oneapi渠道调用指定模型时返回渠道不支持报错。原因：未将对应模型的API地址、权限参数正确填入配置项，或未开放对应端口的访问权限。

## 怎么确认配好了
- 手动触发一次隐患排查清单的生成任务，检查生成的文书是否包含正确的隐患点位、整改要求字段
- 进入FastGPT的模型渠道管理面板，确认对应渠道显示为「已连接」且无报错日志
- 导入一份历史隐患治理台账，测试模型能否正确提取台账中的责任主体、整改期限字段
- 调用测试接口，验证返回的token数量未超出配置的`maxTokens`上限，且格式符合文档规范
