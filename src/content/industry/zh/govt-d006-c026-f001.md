# 工程建设项目审批的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类涉及的日常文档包含施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表等。数据来源为工程建设项目审批管理系统、施工图审查系统、企业资质库、信用平台，更新频率为每日。数据围绕工程建设项目从立项到验收的审批流程，包含项目标识、参建主体信息、审批节点状态等核心内容，不同文档的字段结构随审批环节差异有所区分。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多数据源的接入需求要求接口需支持对接多个外部系统，适配不同的接口规范。每日更新的数据要求需配置定时拉取或同步机制，确保数据时效性。多样的文档结构要求接口需能适配不同的字段提取规则，精准获取所需的文书内容。审批环节的严格要求使得接口调用需匹配审批流程节点，同时需具备容错机制以避免因接口异常导致审批延误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | Bearer {外部系统颁发的接口密钥} | 满足工程建设项目审批管理系统等外部系统的身份校验要求 |
| `variables` | 绑定项目编号、参建单位资质、审批节点状态等业务字段 | 适配不同审批环节的文书模板填充需求 |
| `responseData` | 提取文档正文、审批状态、关联资质信息等目标字段 | 精准获取用于文书与材料起草的核心数据 |
| 接口超时时间 | 600 秒 | 适配工程审批系统接口可能存在的较长响应延迟 |
| 数据拉取频率 | 每 24 小时 1 次 | 匹配本品类数据每日更新的业务节奏 |
| 重试次数 | 3 次 | 应对临时网络波动或接口短暂异常的场景 |

## 容易做错的三处
- 调用外部接口时提示“消息接收地址校验失败”，原因是未配置公网可访问的接口地址，或未正确处理SSL证书校验要求。

- 接口返回的目标数据为空，原因是未正确提取`responseData`中的指定字段，或请求参数与外部系统的接口要求不匹配。

## 怎么确认配好了
- 发起单次测试请求，核对接口返回的`responseData`是否包含预设的业务字段。
- 检查`Authorization`参数的格式是否符合外部系统的身份校验规则，验证身份校验是否通过。
- 触发手动数据拉取任务，确认流程正常执行且数据同步完成。
- 模拟审批节点变更，验证`variables`绑定的参数能否正确嵌入文书模板。
