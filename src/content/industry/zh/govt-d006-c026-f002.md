# 工程建设项目审批的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据来源于工程建设项目审批管理系统、施工图审查系统、企业资质库及公共信用平台，更新频率为每日同步。日常文档包含施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表等制式审批表格与技术说明文件，字段包含项目编号、参建单位资质信息、审批状态、材料提交时间等，无统一固定单位，部分文档包含结构化编号与非结构化技术描述内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
跨多系统数据源导致数据格式不统一，需适配制式表格与非结构化技术文档分别做分块与向量化处理；每日更新频率要求索引支持增量同步，避免全量重建带来的耗时问题；审批类文档包含资质编号、项目编号等关键结构化字段，需结合字段属性调整向量召回的匹配逻辑；文书起草环节依赖历史审批材料的上下文关联，需保留长跨度的索引关联关系，确保召回内容贴合当前审批需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类制式审批表格与技术文档的平均长度，避免分块过碎丢失上下文或过长导致向量化偏差 |
| 重叠长度 | 100–200 字符 | 保障相邻分块的上下文连续性，避免跨块的审批节点信息断裂 |
| `defaultToken` | 按实测标定 | 适配本品类文档的基础向量化需求，匹配text-embedding-v3的输入规范 |
| `maxToken` | 4000 token | 覆盖最长审批文档的向量化长度需求，符合FastGPT v4.17.0的默认上限调整范围 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非审批类无关数据，聚焦与当前审批材料相关的历史文档 |
| 单次搜索上限 | 前 20 条 | 覆盖并联审批涉及的多类材料需求，避免召回结果过多导致上下文过载 |

## 容易做错的三处
- 出现503报错提示default分组下text-embedding-v3无可用渠道，原因是未配置对应大模型的渠道权限或未将模型绑定至default分组。
- 无法通过检索页的编辑按钮直接调整索引配置，需进入知识库内容页修改参数，原因是v4.9.0及以上版本移除了检索页的快速编辑入口。
- 索引召回结果条数不符合预期，原因是未根据审批文档的字段权重调整召回参数，或未开启重排环节过滤无效的非审批类内容。

## 怎么确认配好了
- 查看模型渠道绑定状态，确认text-embedding-v3已关联至default分组，无报错提示。
- 提交一份施工许可申请文档测试，检查分块后的向量存储是否完整，无字段缺失或截断情况。
- 发起与审批材料相关的检索请求，核对召回结果与当前起草文书的业务需求匹配度。
- 上传一份新的竣工验收备案表，验证增量同步功能是否生效，索引自动更新最新内容。
