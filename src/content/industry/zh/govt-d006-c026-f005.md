# 工程建设项目审批的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
本品类数据主要来自工程建设项目审批管理系统、施工图审查系统、企业资质库及公共信用平台。日常处理的文档包含施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表等，文档结构多包含审批节点字段、参建单位资质信息、材料编号与提交时限。数据更新频率为每日，字段严格匹配住建城建审批流程的标准化节点，无自定义扩展字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据来源分散且需跨系统调取，要求工具调用插件支持对接多类住建相关业务系统。文档字段严格匹配审批流程节点，工具调用的参数需严格对应标准化字段，不可随意调整。数据每日更新，工具调用的触发频率需适配更新节奏，避免调取过期数据。参建单位资质信息来自外部信用库，插件需支持跨数据源校验，同时需配置明确的失败处理逻辑，防止因资质核对错误导致审批延误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定，适配工程建设项目审批场景的工具调用需求：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多插件联动场景，自动匹配文书生成所需的住建审批相关工具 |
| `functionCall` | `enabled` | 强制触发工具调用逻辑，确保审批材料生成时调用必要的资质校验与数据调取插件 |
| 工具调用超时阈值 | `600 秒` | 本品类跨系统调取审批数据与资质信息的平均耗时区间 |
| 单次调用返回结果上限 | `前 8 条` | 单份审批材料需关联的参建单位与审批节点数量上限 |
| 上下文窗口长度 | `8000–12000 字符` | 单份完整审批申请材料的平均字符量 |
| 历史对话传递设置 | 开启 | 需关联过往审批节点信息生成连贯的申请文书 |

## 容易做错的三处
- 现象：调用工具时历史对话参数为空，无法关联过往审批节点信息。原因：未开启历史对话传递配置，或未在工具调用参数中配置上下文关联字段。
- 现象：工具调用返回超时提示，无法完成审批材料生成。原因：工具调用超时阈值设置低于本品类跨系统数据调取的平均耗时。
- 现象：工作流对话日志为空，无法追溯审批材料生成的完整过程。原因：未开启日志持久化配置，或日志存储周期设置不符合业务需求。

## 怎么确认配好了
- 发起模拟施工许可申请生成请求，检查工具调用日志中是否包含资质校验与数据调取的相关记录。
- 查看工具调用超时阈值设置，确认其取值适配本品类跨系统数据调取的耗时。
- 测试历史对话传递功能，确认过往审批节点信息被正确带入当前工具调用参数。
- 验证工作流日志功能，确认每次工具调用后均生成对应可查看的记录。
