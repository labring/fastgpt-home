# 工程建设项目审批的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于工程建设项目审批管理系统、施工图审查系统、企业资质库、信用平台，更新频率为每日。日常处理的文档包括施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表，文档结构包含项目编号、参建单位资质信息、人员信息、审批节点、办理要求等字段，字段类型涵盖字符串、日期、等级标识等，不同系统导出的文档格式存在细微差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据的分散存储与格式差异要求配置支持跨系统数据的精准召回与格式适配，每日更新的节奏需要配置适配增量同步逻辑。文档字段的专业性与唯一性要求模型输出严格匹配官方文书格式，不能随意修改字段内容。参建单位资质与审批节点的准确性直接影响审批结果，因此配置需要保障召回内容的精准性，避免无关或错误数据混入生成内容。同时，单份审批文书的长度较长，需要配置适配较大的上下文容纳空间。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 工程审批类单份文书长度较长，需容纳多份关联审批材料的完整内容 |
| `quoteMaxToken` | 1500–2000 token | 需召回足够的审批材料片段用于参考，避免截断关键资质或审批节点信息 |
| `temperature` | 0.1–0.3 | 审批文书需严格匹配官方格式与数据，保持输出一致性 |
| `toolChoice` | auto | 按需调用工具补充审批节点或资质信息，适配多数据源整合需求 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的地址填写 | 适配国内大模型调用的代理配置，保障数据传输合规 |
| `AIPROXY_API_TOKEN` | 按部署要求生成的密钥 | 保障接口调用的安全性，避免未授权访问 |

## 容易做错的三处
- 调整`quoteMaxToken`至2000后，生成的审批申请文书未包含召回的施工图审查合格书内容。原因是未同步提升`maxContext`参数上限，导致整体上下文超出阈值，召回的材料片段被提前清理。
- 应用界面显示的模型与配置的模型不一致。原因是代理配置未正确绑定目标模型，或环境变量未覆盖默认模型参数。
- 本地部署模型生成的审批文书缺失参建单位资质字段。原因是知识库召回的资质库数据未正确映射到文书对应字段，且未开启精准匹配逻辑。

## 怎么确认配好了
- 发起施工许可申请文书生成测试，查看输出内容是否包含召回的企业资质库数据与审批节点信息。
- 检查接口调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置已生效，无401或404报错。
- 调整`temperature`参数至0.2，多次生成同一份文书，确认输出格式与字段内容保持一致。
- 验证`quoteMaxToken`的配置，查看生成内容中引用的材料片段长度符合设定的token范围。
