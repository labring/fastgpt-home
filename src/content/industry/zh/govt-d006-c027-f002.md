# 工程建设项目招投标的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
本品类服务主体包括发展改革部门、住建交通水利等行业主管部门、公共资源交易中心、招标代理，核心文档包括招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告。数据来源为全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，按日更新，覆盖不同层级的工程建设项目。文档结构包含标段划分、资质要求、工程量清单、评标规则等核心字段，无统一固定的单位格式，部分文档含表格化的参数内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
日更的数据要求索引支持增量更新，避免全量重建消耗过多资源。多类型文档的混合索引，需要适配不同文档的字段结构，确保标段、资质等核心信息被准确分块。文档中含工程量清单等长文本段落，要求分块规则需平衡上下文完整性与索引效率。数据来源分散导致文档格式差异，需兼容非标准化的文本结构，同时需保障索引稳定性，避免因文档异常导致索引失败，进而引发中标结果暂停、项目开工延误等风险。

## 配置怎么定
本配置方案适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 覆盖标段、资质等核心字段，避免长文本截断导致信息丢失 |
| 重叠长度 | 100–150 字符 | 保留跨块的资格条件关联，确保检索时能完整匹配资格要求 |
| `defaultToken` | 8192 | 适配多数招投标文档的单块文本长度，平衡分块效率与上下文完整性 |
| `maxToken` | 16384 | 处理含工程量清单的超长文档，避免分块溢出 |
| 相似度阈值 | 0.75–0.85 | 区分招标要求与投标响应的文本差异，提升评标环节的检索准确性 |
| 单次搜索上限 | 前 10 条 | 覆盖多份投标文件的关联内容，满足评标核对的需求 |

## 容易做错的三处
- 现象：升级后索引服务报400状态码且无响应体。原因：未适配招投标文档的长文本分块规则，导致索引请求的token参数超出模型上限。
- 现象：本地部署后服务器内存持续被撑爆，每日定时触发。原因：未限制批量索引的文件数量与分块大小，日更的多份招投标文档批量处理超出服务器内存阈值。
- 现象：知识库上传文件卡在1组或2组索引进度中。原因：使用m3e-large模型时未调整分块长度，导致分块的token数超出模型支持上限，触发索引阻塞。

## 怎么确认配好了
- 核对索引任务的执行时间，匹配数据的日更新频率，确认增量索引能按时完成。
- 测试检索特定资质、工程量清单关键词，确认召回结果包含对应文档的核心片段。
- 验证分块参数，检查长文档的分块结果无截断或过度拆分的情况。
- 查看索引请求的日志，确认无400类报错或阻塞状态。
