# 工程建设项目招投标的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类的核心数据来自全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常处理的文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，文档包含标段划分、资格条件、工程量清单、评标专家履职记录等结构化字段，以及对应公示类的非结构化文本内容。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据每日更新要求多轮对话需实时关联最新的官方招投标数据，避免使用过期信息。文档结构包含多类专业字段，提示词需明确区分不同文档类型的生成规则，确保输出匹配对应环节的要求。最耗时的标段拆分、评标记录核对等环节，需支持多轮分步交互，逐步确认参数与校验结果。出错后果需通过对话流程前置校验，避免生成不符合规范的文书内容。不同于政府采购场景，需严格匹配资质、业绩、工程量清单等专业字段，提示词需适配招标投标法体系的合规要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 匹配单份招投标核心文档的平均长度，避免上下文截断导致信息丢失 |
| 单次匹配结果上限 | 前3条 | 对应评标报告、中标公示等单类文档的核心条目数，避免信息过载影响生成效率 |
| 对话历史保留时长 | 24 小时 | 匹配数据日更频率，确保对话使用的是当日最新的官方交易数据 |
| 变量绑定参数 | 预设`chatId`、`messages`、`variables` | 支持多轮对话的上下文传递与参数绑定，适配分步校验招投标文书的交互逻辑 |
| 知识库数据源过滤 | 限定公共资源交易平台类数据源 | 确保调用的是官方合规的招投标数据，避免非授权信息干扰生成结果 |
| 上下文校验开关 | 开启 | 对生成的文书内容与知识库数据进行匹配校验，降低合规风险 |

## 容易做错的三处
- 正式发布后对话提示未选择知识库，调试预览正常。现象为正式环境发起对话时界面显示未关联知识库，预览阶段无异常。原因是未将知识库绑定到正式发布的应用节点，或配置的数据源过滤规则未覆盖正式环境的请求来源。
- 多轮对话上下文丢失。现象为跨轮次调用时之前确认的标段划分、项目名称等参数未被保留。原因是未正确配置`chatId`参数传递，或对话历史清理规则设置时长过短。
- 生成的文书包含非合规字段。现象为生成的招标文件包含未在绑定知识库中出现的工程量清单条目或资格条件。原因是提示词未明确限定仅使用绑定知识库内的结构化数据，或未开启上下文校验开关。

## 怎么确认配好了
- 发起测试对话，输入「生成某项目的招标公告」，查看返回结果是否仅包含绑定知识库内的官方招投标文档内容。
- 发起跨轮次对话，先确认标段划分参数，再请求生成对应标段的资格预审文件，查看后续对话是否保留了之前的标段信息。
- 检查应用日志，确认`chatId`、`messages`参数在每轮对话中均被正确传递。
- 触发知识库重新拉取当日数据，验证对话中调用的是最新版本的交易数据。
