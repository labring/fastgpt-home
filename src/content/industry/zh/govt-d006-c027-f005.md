# 工程建设项目招投标的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来自全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常处理的文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，文档中包含标段划分、资格条件、资质业绩要求、工程量清单、施工周期等特有字段，服务主体涵盖发展改革部门、住建交通水利等行业主管部门、公共资源交易中心及招标代理机构。

## 这些特征在「工具调用与插件」这一环带来什么约束
多数据源的来源要求工具调用需支持跨平台数据的拉取与整合，避免数据割裂；日更的更新频率要求配置定时同步规则，保证知识库内数据的时效性。招投标文档的结构化字段较多，工具调用需具备精准提取标段、资格条件等特定字段的能力，否则会影响文书起草的准确性。同时，该品类出错后果严重，工具调用的结果校验环节需强化，确保提取的字段符合招标投标相关业务规范。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配招投标文书中既有通用文本生成又有结构化字段提取的需求，自动选择调用工具或直接生成内容 |
| `functionCall` | `enabled` | 需结构化提取标段、资格条件、工程量清单等特有字段，启用函数调用可保证输出格式符合业务要求 |
| 单次工具调用超时时间 | `600 秒` | 招投标文档通常包含多标段、多页内容，处理耗时较长，预留充足时间完成数据提取与校验 |
| 工具调用返回结果上限 | `前 3–5 条` | 招投标文档的核心字段集中，过多结果会增加上下文负担，影响生成效率与准确性 |
| 知识库绑定范围 | 按数据源分类绑定 | 数据来自多个公共资源交易平台，分类绑定可避免跨源数据混淆，提升字段提取精度 |

## 容易做错的三处
- 现象：调用工具处理招投标文档时返回资质、业绩等字段为空。原因：未绑定对应数据源的知识库，导致无法获取招投标业务的特有数据，无法完成结构化字段提取。
- 现象：通过API调用工作流上传文件后提示参数错误。原因：未按照要求传入知识库id作为全局变量，或代码格式不符合系统规范，导致工作流无法触发对应工具调用环节。
- 现象：使用graphRAG工具时无法正确关联投标人与中标项目的关系。原因：未针对招投标文档的特有字段配置实体关系提取规则，导致通用关系提取无法适配招投标业务的专属逻辑。

## 怎么确认配好了
- 上传一份标准的招标文件，检查工具调用是否自动提取标段、资格条件等字段并生成对应内容。
- 查看知识库绑定列表，确认已按数据源分类绑定了全国公共资源交易平台、地方公共资源交易平台等来源的数据。
- 调用测试API，传入测试用的招投标文档，检查返回结果是否包含结构化的字段信息。
- 查看工作流日志，确认文件上传后自动触发了工具调用环节。
