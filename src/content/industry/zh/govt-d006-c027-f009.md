# 工程建设项目招投标的文书与材料起草：模型接入与配置
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类涉及的文档涵盖招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告等全流程文书，数据来源为全国公共资源交易平台、地方交易平台、工程审批系统、招标投标监管系统，更新频率为每日。文档结构包含标段划分、资格条件、工程量清单、施工周期等专业字段，由发展改革部门、住建交通水利等行业主管部门、公共资源交易中心、招标代理作为典型主体产生与流转。

## 这些特征在「模型接入与配置」这一环带来什么约束
全流程文书的长文本属性要求模型上下文配置适配多环节连贯内容；多来源的日更数据要求知识库同步机制匹配更新频率；专业字段的存在要求向量模型与检索配置精准匹配工程建设领域术语；文书的严谨性要求输出参数需控制随机度，避免出现不符合招投标规范的内容；同时，出错后果涉及中标暂停、项目延误等风险，要求接口权限与配置校验更加严格。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配招投标全流程文书的长文本上下文需求，覆盖多环节连贯内容 |
| `maxTokens` | 2000–3000 token | 满足单份起草文书的输出长度要求，避免超出模型限制 |
| `temperature` | 0.2–0.4 | 保障招投标文书的严谨规范，降低随机输出风险 |
| `AIPROXY_API_ENDPOINT` | 部署节点专属接口地址 | 确保模型请求路由正确，匹配部署环境的访问路径 |
| `AIPROXY_API_TOKEN` | 平台发放的专属密钥 | 保障接口访问权限，避免未授权访问问题 |
| `toolChoice` | auto | 支持模型自动调用工具处理标段拆分、资格条件核对等专业任务 |

## 容易做错的三处
- 接入向量模型时提示401未授权错误，原因：未正确填写`AIPROXY_API_TOKEN`或密钥未开通对应模型的访问权限。
- 部署的oneapi容器持续无限重启，原因：`AIPROXY_API_ENDPOINT`配置错误或端口绑定冲突。
- 添加whisper模型后界面提示浏览器不支持语音输入，原因：未配置语音模型的前端调用参数或浏览器麦克风权限未开启。

## 怎么确认配好了
- 发起一次招标公告的文书起草测试，检查输出内容是否包含正确的标段划分与资格条件字段。
- 查看接口调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的请求返回状态码为200。
- 调整`temperature`参数后，对比两次输出的严谨性差异，确认参数生效。
- 测试知识库同步功能，确认日更的招投标文档能按时更新到向量库。
