# 工程建设项目招投标的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源包括全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常覆盖的文档类型涵盖招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，文档包含标段划分、资格条件、工程量清单、施工周期等专属字段，内容兼具结构化与半结构化特征，无统一通用格式。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的数据源要求检索系统需支持增量同步与定时全量刷新，避免召回过时的招投标信息。多平台来源的数据集需单独绑定，防止混入政府采购类无关文档。文档的混合结构特征要求检索需兼顾关键词匹配与语义理解，精准匹配资格条件、评标报告等核心业务字段。同时，业务出错后果严重，需保障召回的完整性与排序合理性，避免遗漏关键依据引发合规风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配招投标文件的专业术语密度，过滤无关的通用文本，保障召回内容的相关性 |
| `limit` | 前8条 | 覆盖单份招标文件的核心条款数量，同时控制上下文总长度，符合大模型输入限制 |
| `searchMode` | hybrid | 结合关键词检索与语义检索，适配招投标文档的结构化字段与专业文本混合的内容结构 |
| `usingReRank` | 开启 | 修正单纯语义排序的偏差，优先将资格条件、评标报告等核心业务文档排在前列 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充标段、主管单位、施工周期等关联术语，提升跨文档的召回完整性 |
| `collectionIds` | 绑定专属招投标数据集 | 限定检索范围，避免混入政府采购类无关数据，精准匹配业务场景 |

## 容易做错的三处
- 召回结果条数不足，界面显示返回结果少于配置的`limit`值。原因是未开启`datasetSearchUsingExtensionQuery`，且未配置跨平台数据集同步，导致仅检索到部分本地存储的招投标文档。
- 排序结果不符合业务预期，评标报告的相关内容排在招标公告之后。原因是未开启`usingReRank`，单纯依赖语义相似度排序，未对核心业务字段进行加权优化。
- 检索接口返回超时错误。原因是未限定`collectionIds`为专属招投标数据集，检索范围覆盖了过多非相关文档，导致加载耗时超出阈值。

## 怎么确认配好了
- 查看FastGPT v4.17.0的数据集同步日志，确认每日增量更新任务已正常触发，覆盖最新的中标结果公告数据。
- 输入待起草招标文件的核心业务问题，核对召回结果包含资格预审文件、评标报告等指定文档类型。
- 调整`similarity`阈值，验证返回结果的相关性符合业务审核的基本要求。
- 开启`usingReRank`后，对比排序前后的结果，确认核心业务字段的优先级得到有效提升。
