# 市场主体登记与许可的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档包含设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等，均为固定格式的政务申请材料，包含主体名称、住所地址、股东信息、许可类型等必填字段。数据来源为企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统、住所信息库，更新频率为每日一次，数据结构统一，字段需严格匹配政务登记规范，无自定义内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据多源且每日更新，要求模型接入环节需支持多数据源的增量同步配置，避免全量同步占用过多政务云资源。固定格式的申请材料要求模型能够精准识别结构化字段，生成的文书必须严格匹配必填项，不能出现字段缺失或格式偏差。政务敏感数据的属性要求接入配置需绑定专属安全代理，保障数据不流出政务网络。同时，登记许可的出错后果直接影响市场主体准入，要求模型生成内容需具备高度严谨性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖设立登记申请书、参考规范等全部上下文内容，确保模型可获取完整的登记要求与参考数据 |
| `maxTokens` | 2000–3000 token | 匹配单份申请文书的标准起草长度，避免生成内容过长超出政务系统的提交限制 |
| `temperature` | 0.1–0.3 | 降低生成内容的发散性，确保文书格式与字段严格匹配政务登记规范，减少不必要的自定义内容 |
| `AIPROXY_API_ENDPOINT` | 政务云专属部署的代理地址 | 保障所有请求数据不流出政务网络，符合政务数据安全管理要求 |
| `AIPROXY_API_TOKEN` | 加密存储的专属访问令牌 | 限制仅授权的政务系统可调用模型，防止未授权访问导致的敏感数据泄露 |

## 容易做错的三处
- 向量库同步进度条长时间无变化，且检索政务系统历史数据时返回空结果。原因是未配置对应数据源的访问权限，或知识库向量模型的格式与政务系统导出的文档格式不匹配。
- 生成的申请文书仅包含开头部分，未完成全部必填字段的填写。原因是`maxTokens`配置值过低，或更新FastGPT v4.17.0版本后默认参数被重置，导致生成长度被限制。
- 切换向量模型后无法回退到原有配置，界面显示切换成功但检索结果仍使用旧模型。原因是未保留原有模型的配置快照，或强制切换未清除旧模型的缓存索引。

## 怎么确认配好了
- 调用`AIPROXY_API_ENDPOINT`对应的测试接口，验证返回状态码为200，确认API连接正常。
- 上传一份标准的设立登记申请书样本，生成对应文书，检查是否包含所有必填字段，格式与政务要求一致。
- 调整`maxContext`参数值，上传包含多份参考文档的测试集，验证模型可完整加载所有参考内容。
- 手动触发一次增量同步，确认同步进度正常完成，符合数据更新频率要求。
