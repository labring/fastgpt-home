# 市场主体登记与许可的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
本品类的核心文档涵盖设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等标准化表单类文书。数据主要来自企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统及住所信息库，每日更新。文档结构固定，包含主体名称、住所、股东信息、许可事项等明确字段，无复杂嵌套内容，所有字段均对应市场主体登记的法定要求。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据每日更新要求知识库同步机制需适配高频增量更新，避免召回过期的登记数据。固定表单类文档的结构要求检索需精准匹配字段关键词，避免模糊召回无关内容。多来源数据的格式统一度较高，但需区分系统导出的原始数据与标准化文书模板，防止混淆检索范围。单次检索需覆盖登记许可的前置后置条件、补正要求等关联内容，确保检索结果能支撑材料核验环节的判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 适配表单类文档的关键词匹配精度，过滤低相关的非登记类文书 |
| `limit` | 前8条 | 覆盖登记许可所需的模板、前置条件、补正要求等多类结果，避免遗漏关键信息 |
| `searchMode` | 关键词匹配优先 | 适配固定字段的精准检索需求，优先召回匹配法定字段的文档 |
| `usingReRank` | 开启 | 对初始召回结果按业务相关性重排，确保许可前置后置条件等核心内容排在前列 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展登记相关的同义表述，比如将“住所证明”关联至“经营场所证明”，覆盖不同表述的文档 |
| `collectionIds` | 绑定总容量不超过1000 MB的专属登记许可知识库集合 | 限定检索范围至本品类的专属数据，避免混入其他市场监管类文档 |

## 容易做错的三处
- 检索结果为空，页面返回无匹配内容提示。原因是`similarity`阈值设置过高，过滤了所有符合业务要求的文档，对应知识库无法检索类问题。
- 检索结果混入非登记类文档，比如其他市场监管业务的材料。原因是`collectionIds`未绑定专属数据集，误检索了其他业务的知识库内容。
- 检索结果缺失最新的许可申请模板，无法匹配当前业务需求。原因是知识库增量训练任务未正常触发，对应知识库训练异常类问题。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理页面，核对`collectionIds`是否绑定了专属的市场主体登记与许可数据集。
- 发起包含“住所证明”关键词的检索，核对返回结果的条数是否符合`limit`配置的取值。
- 测试检索“前置许可条件”，核对`usingReRank`是否开启，核心业务相关结果排在前列。
- 触发一次增量同步任务，核对系统日志中的数据更新时间与业务数据的更新时间一致。
