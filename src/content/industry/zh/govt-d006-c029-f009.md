# 市容环卫与城管执法案件的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
市容环卫与城管执法案件的日常数据涵盖巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告等文档。数据主要来自城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。单份案件数据通常包含案件编号、巡查时间、现场点位、违法行为描述、涉事主体信息等字段，部分数据附带带位置信息的现场图片，整体格式因来源不同存在一定异构性。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入需支持多格式数据的统一解析，包括结构化表格、文本记录与图片内容。每日更新的案件数据需要配置定期同步机制，避免数据滞后影响文书起草时效性。现场照片与巡查记录的混合输入要求模型具备视觉理解能力，同时需保障上下文长度足够覆盖完整案件信息。执法文书的严谨性要求模型输出需匹配城管执法的通用格式，避免出现不符合业务规范的内容，同时需保障数据调用的安全性，防止敏感执法信息泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 该品类案件包含大量现场照片类非结构化数据，需通过视觉能力提取图片中的关键信息 |
| `maxContext` | 8000–12000 token | 单份完整案件数据包含巡查记录、立案审批表、现场照片OCR文本等内容，需足够的上下文支撑模型理解案件全貌 |
| `maxTokens` | 2000–3000 token | 单份执法文书如处罚决定书的输出长度通常在该区间内，可保障完整生成文书内容 |
| `temperature` | 0.3–0.5 | 执法文书需保持严谨规范，较低的温度参数可降低生成内容的随机性，符合业务要求 |
| `toolChoice` | auto | 模型需自主判断是否需要调取历史案件数据或关联工单信息，自动模式可适配多样化的案件处理场景 |
| `AIPROXY_API_ENDPOINT` | 填写合规代理地址 | 适配城管系统的数据安全要求，通过代理中转调用大模型，避免直接暴露内部接口 |
| `AIPROXY_API_TOKEN` | 填写专属认证令牌 | 保障接口调用的安全性，防止未授权访问执法相关数据 |

## 容易做错的三处
- 批量上传网格工单数据时，仅前十几条处理正常，后续无有效输出。原因：未针对城管案件的多源异构数据配置合理的上下文截断规则，导致上下文溢出，模型无法完整处理后续批次数据。
- 接入Casdoor后无法完成身份校验，调用模型接口时报错401。原因：未按照Casdoor的OAuth2配置要求填写回调地址，导致认证流程无法正常完成。
- 使用Qwen2-72B-Instruct-Int8进行函数调用生成执法文书时，判断的违法类型与实际案件不符。原因：未针对城管执法的违法类型库配置专属prompt约束，模型未准确匹配业务场景的判断标准。

## 怎么确认配好了
- 上传单份包含现场照片与巡查记录的案件数据，触发文书起草测试，核对生成内容是否覆盖案件核心信息。
- 配置工具调用测试任务，确认模型可自主调取关联的历史执法数据，完成上下文补充。
- 运行批量数据处理任务，监控FastGPT v4.17.0的运行日志，确认无上下文溢出或超时报错。
- 验证Casdoor接入的登录流程，确认可正常完成身份校验并成功调用模型接口。
- 触发函数调用测试，确认模型生成的违法类型判断符合城管执法的业务规范。
