# 建设工程质量安全监督的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
建设工程质量安全监督的核心数据来自工程质量安全监管系统、施工现场实名制平台、监理日志、检测报告，更新频率为周度。日常产出的文书与材料包括监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告。文档结构覆盖项目基础信息、现场检查内容、隐患整改要求、验收判定标准等字段，例如整改通知书包含隐患编号、责任主体、闭环时限，检测报告包含检测项目、数值、合格判定结果，无额外虚构统计数据。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
周度更新的数据源要求对话工具定期同步最新监管系统与现场平台数据，避免使用过期信息导致文书准确性下降。多类文档的差异化字段要求提示词精准匹配对应文档的格式与字段要求，避免混淆整改通知书与竣工验收报告的内容。长文档如完整监理日志、批量检测报告超出模型上下文长度，需要配置切片处理以适配模型限制。多轮监督流程的连续性要求对话保留历史上下文，关联前期检查记录与整改闭环情况，确保生成的文书符合项目全流程进度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 覆盖单周更新的多类文档总长度，适配建设工程文档的平均篇幅，符合FastGPT v4.17.0的参数上限 |
| 文档分块长度 | 1000–1500 字符 | 适配检测报告、监理日志的单块信息完整性，避免单块内容过于零散 |
| 文档分块重叠长度 | 200–300 字符 | 保留分块间的上下文关联，避免切片后关键信息断裂 |
| 隐藏工具调用输出 | 开启 | 仅向监督人员展示AI生成的最终文书内容，减少冗余的工具调用日志 |
| `chatId` | 启用会话绑定 | 绑定单项目的多轮对话上下文，关联历史监督记录与整改情况 |
| `messages` | 保留最近20条对话 | 平衡上下文长度与历史信息的关联性，适配建设工程监督的多轮流程需求 |
| `variables` | 绑定项目编号、监督站编号 | 实现多项目对话的上下文隔离，避免不同项目的信息混淆 |

## 容易做错的三处
- 发起工具调用生成隐患整改通知书后，界面同时显示工具调用的原始请求与响应内容。原因是未开启隐藏工具调用输出的配置，导致冗余信息干扰监督人员阅读。
- 上传单份完整监理日志后，对话返回上下文溢出的报错提示。原因是未配置文档分块参数，未对超长文档进行切片处理，超出模型支持的上下文长度。
- 发起第二轮关于整改闭环的追问时，AI未关联前期检查记录中的隐患内容。原因是未启用`messages`上下文保留配置，或上下文长度设置过小，无法加载历史对话信息。

## 怎么确认配好了
- 发起包含工具调用的测试对话，验证返回结果仅包含AI生成的文书内容，无工具调用的原始日志。
- 上传单份长度超过10000字符的监理日志，查看系统自动生成的分块日志，确认分块数量与长度符合配置要求。
- 发起两轮关联的监督对话，例如先查询某项目的监督检查记录，再追问对应隐患的整改情况，验证AI能关联历史对话内容生成准确回复。
- 查看系统日志存档配置页面，确认存档时长与存储上限符合业务需求，可执行手动清理操作。
