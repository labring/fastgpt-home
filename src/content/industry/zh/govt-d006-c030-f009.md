# 建设工程质量安全监督的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自工程质量安全监管系统、施工现场实名制平台、监理日志、检测报告，更新频率为周。日常文档包含监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告，字段涵盖工程编号、隐患点位描述、整改要求、参建单位名称、验收节点等，单份文档长度差异较大，短则数百字的整改通知，长则数千字的竣工验收监督报告。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据来源分散且格式各异，需配置适配多源数据的接入规则；周度更新频率要求知识库同步周期匹配业务节奏，避免数据滞后影响文书时效性。文档长度跨度大，需灵活调整上下文承载参数，适配短通知与长报告的处理需求。官方文书有固定格式要求，需通过prompt约束模型输出符合住建监管规范的内容，同时因出错可能引发质量或安全事故，模型生成的严谨性参数需严格设置。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 填入部署的代理服务公网地址 | 指定模型调用的服务入口，适配跨平台模型接入需求 |
| `AIPROXY_API_TOKEN` | 填写申请的访问密钥 | 完成模型调用的身份验证，保障接口调用权限 |
| `temperature` | 0.1–0.3 | 本品类文书需保持官方格式与严谨性，降低随机性输出 |
| `maxContext` | 8000–12000 token | 适配长文档如竣工验收监督报告的上下文处理需求 |
| `quoteMaxToken` | 2000–3000 token | 限制召回的参考文档长度，避免冗余内容干扰模型生成 |
| `maxTokens` | 1500–2000 token | 控制单份文书的生成长度，匹配监管文档的标准篇幅 |

## 容易做错的三处
- 现象：界面提示模型调用失败，OneAPI测试正常。原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致身份验证失败或服务地址错误。
- 现象：应用设置指定模型，但实际调用其他模型。原因：未在FastGPT界面完成模型绑定配置，或代理服务的模型映射规则配置错误。
- 现象：第三方对接工具提示地址校验失败。原因：未将FastGPT部署的公网地址正确配置到对接工具的回调地址，或端口未对外暴露。

## 怎么确认配好了
- 发起模型测试对话，输入监管文档片段，检查返回内容的严谨性与格式是否符合监管文书要求。
- 查看知识库同步日志，确认周度数据更新任务正常执行，无异常报错。
- 在应用设置中查看模型配置，确认当前绑定的模型与预设一致。
- 检查接口调用日志，验证`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的请求参数正确无误。
