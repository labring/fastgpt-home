# 建设项目环评审批的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台、监测数据，更新频率不定期。日常文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复，文档包含项目类别、环评等级、污染防治措施、公众参与内容等字段，单份文档长度差异较大。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据来源多且更新无固定周期，要求向量模型与索引适配跨源数据的关联检索；文档长度差异大，部分报告书内容较长，需合理设置分块规则以保留专业术语的上下文；最耗时的核对项目类别、污染防治措施等环节，要求检索召回的结果精准匹配项目专属数据；出错后果严重，需保证检索结果的置信度，避免误召回无关内容，干扰项目审批流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配环评文档的长段落结构，避免专业术语被截断 |
| 重叠长度 | 100–200 字符 | 保留跨分块的项目类别、污染防治措施等关键上下文 |
| 相似度阈值 | 0.75–0.85 | 匹配环评文档的专业术语密度，降低误召回概率 |
| 单次搜索上限 | 前 20 条 | 覆盖跨源数据关联检索的需求，避免冗余数据量 |
| `defaultToken` | 1000 token | 适配单份环评报告表的核心内容长度 |
| `maxToken` | 8000 token | 容纳多源跨文档的检索结果上下文 |

## 容易做错的三处
- 现象：检索响应超时，界面显示响应时长超过60秒，或控制台返回超时报错。原因：分块长度设置过大，未适配环评文档的长段落，导致单批次检索数据量过高。
- 现象：检索结果中出现大量与当前项目无关的环评批复内容，字段匹配度不符合预期。原因：相似度阈值设置不当，未适配环评专业术语的语义匹配精度。
- 现象：Docker部署后索引模型无法加载，控制台报错缺少模型调用依赖。原因：未按FastGPT v4.17.0 版本的配置要求，未正确配置embedding模型的调用路径，或未完成oneapi的api配置。

## 怎么确认配好了
- 上传单份环评报告表，执行分块处理，查看分块后的文本长度符合设置的分块长度与重叠长度参数。
- 发起包含项目类别的检索请求，检查返回结果的相似度分值处于设定的阈值区间内。
- 触发跨源数据索引更新，确认排污许可、生态环境分区管控成果的索引状态为已完成。
- 执行多次检索请求，查看响应时长处于业务场景可接受的范围。
