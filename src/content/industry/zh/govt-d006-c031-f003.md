# 建设项目环评审批的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来自全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台及监测数据，更新节奏不定期。日常处理的文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复，文档结构包含项目类别、环评等级、污染防治措施、公众参与情况、审批要求等固定字段，无统一固定单位，需结合项目实际场景匹配。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散的特点要求多轮对话需引导用户提供对应系统的项目标识或参数，关联多源数据完成校验。文档字段固定且覆盖项目全流程的特点，要求对话需按审批环节逐步确认缺失信息，避免一次性加载过多内容导致交互混乱。更新不定期的特点要求提示词中加入核对最新生态环境分区管控成果的步骤，确保审批依据准确。同时，出错后果严重的特点要求对话环节嵌入字段校验逻辑，提前拦截不符合要求的内容，避免项目无法开工、批复被撤销等问题。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定项目唯一标识 | 关联全国建设项目环评统一申报和审批系统的已有项目数据 |
| `messages` | 保留前 15–20 轮交互记录 | 覆盖多轮审批确认的完整对话流程，避免关键信息丢失 |
| `variables` | 绑定项目类别、环评等级变量 | 用于动态触发对应环评审批的校验规则 |
| 单次响应字符上限 | 3000–5000 字符 | 匹配单份环评文书片段的输出长度，避免内容截断 |
| 对话超时时间 | 600 秒 | 避免长时间等待导致交互中断 |
| 提示词触发规则 | 按用户输入的审批环节切换 | 聚焦当前环节的文书起草，避免跨环节信息混淆 |

## 容易做错的三处
- 现象：工作流中配置的表单输入字段在对话界面未显示，交互内容为空。原因：未将表单变量正确绑定至`variables`配置项，导致对话模块无法读取预设输入项。
- 现象：配置的文件链接未在对话中加载参考内容，无法调用对应环评文档数据。原因：未将文件链接变量绑定至对话模块的数据源配置，或链接指向的系统权限未开放。
- 现象：对话角色未按审批流程切换，生成的文书不符合审批环节要求。原因：提示词中未明确绑定不同`messages`轮次的角色规则，导致角色逻辑混乱。

## 怎么确认配好了
- 触发测试对话，输入项目类别与审批类型，核对对话是否自动弹出预设的表单输入字段。
- 上传对应环评文档的测试链接，确认对话模块是否能加载并引用文档内容。
- 发送多轮交互指令，核对`messages`历史记录是否按配置保留指定轮次的内容。
- 调整`variables`绑定的变量值，确认对话是否触发对应环节的校验规则。
