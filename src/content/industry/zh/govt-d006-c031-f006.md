# 建设项目环评审批的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
本品类的日常文档包括环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复等，数据来源涵盖全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台、监测数据。数据更新无固定周期，随项目申报进度与政策调整同步更新。文档结构包含项目基本信息、环评等级判定、污染防治措施、公众参与情况等专业字段，不同来源数据的字段格式存在细微差异。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来自多个跨部门系统，不同来源的字段命名与格式存在细微差异，需在溯源环节完成统一映射，避免引用内容与真实审批数据不匹配。无固定更新周期的特性要求溯源系统支持增量同步与版本校验，确保引用的监测数据、生态环境分区管控成果为最新有效版本。复杂的文档结构与专业字段要求溯源召回的内容需精准对应环评等级、污染防治措施等核心环节，避免冗余或缺失影响文书合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配环评文档中核心引用段落的长度，避免内容截断或上下文溢出 |
| `responseData` | 返回匹配源的系统标识、更新时间与项目编号 | 满足环评审批文书的溯源要求，明确引用数据的来源与有效性 |
| `detail` | 开启 | 展示引用内容的完整上下文，便于核对污染防治措施的合规性 |
| 单次搜索上限 | 前6条 | 覆盖主要数据来源的核心匹配结果，避免冗余信息干扰文书起草 |
| 重排规则 | 按匹配度降序 | 优先展示与当前环评项目最相关的审批数据与管控成果 |
| 上下文窗口时长 | 600 秒 | 适配跨系统数据调取的延迟，确保完整获取引用源数据 |

## 容易做错的三处
- 未正确绑定知识库变量，导致生成的文书无法关联全国建设项目环评统一申报系统的真实项目数据。原因是配置变量引用时未选择对应品类的专属知识库，仅调用了通用文档库。
- 未设置`quoteMaxToken`的合理取值，导致长段落的引用内容被截断，无法完整展示公众参与说明的核心内容。原因是默认取值过小，未适配环评文档的篇幅特征。
- 未定期清理过期的嵌入向量文件，导致知识库磁盘占用超出预期。原因是未配置自动清理策略，保留了原文件、分割块与嵌入向量的全部历史数据。

## 怎么确认配好了
- 生成一份环评审批申请文书，检查引用内容下方是否标注了来源系统、更新时间与项目编号。
- 进入FastGPT v4.17.0的知识库管理页面，确认已添加全国建设项目环评统一申报系统、生态环境分区管控成果等指定数据源。
- 测试调用工具生成引用片段，验证`quoteMaxToken`的取值是否限制了引用内容的token数量。
- 查看本地部署的FastGPT磁盘占用统计，确认仅包含原文件、分割后的文件块与嵌入向量三类数据。
