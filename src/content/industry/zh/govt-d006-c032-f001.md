# 投资项目立项与后评价的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据来源包括国资委投资监管系统、企业ERP和项目管理系统、行业市场数据、审计和财务报表，更新频率为季度。日常产出的文档包含年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告、投资后评价报告，整体分为项目基础信息、可行性分析、投决支撑材料、后评价数据四个部分，字段涵盖项目编号、投资额度、建设周期、评估结论等，涉及的单位包括万元、年等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据来源分散、文档长度较长且更新频率固定，为HTTP接口与外部系统对接带来多重约束。需对接多套外部系统获取不同维度的业务数据，不同系统的`Authorization`参数校验规则存在差异。长文档内容需要拆分后分批传输，避免单次请求超出接口限制。季度更新的数据需合理配置调用周期，避免频繁请求触发系统限流。同时，核心业务字段的完整性校验需嵌入接口调用流程，防止缺失关键信息影响文书质量。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 按对接系统的认证规则配置，例如Bearer 令牌格式 | 不同外部系统的鉴权要求存在差异，需匹配对应接口的认证规范 |
| 单次请求文本长度 | 800–1200 字符 | 适配多数外部接口的文本传输限制，避免请求超时或被截断 |
| `responseData` 字段过滤规则 | 仅提取项目编号、投资额度、建设周期字段 | 聚焦本品类文书所需的核心业务信息，过滤冗余数据 |
| 接口调用超时时间 | 600 秒 | 适配长文档处理与多系统数据聚合的耗时需求 |
| 失败重试次数 | 不超过3次 | 应对临时网络波动或接口短暂不可用的场景，避免过度占用系统资源 |
| `variables` 传参格式 | 以JSON结构传递项目ID、周期范围参数 | 标准化外部接口的请求参数格式，提升兼容性 |

## 容易做错的三处
- 现象：HTTP接口返回长文本后，未拆分直接发送导致请求超时或被接口拒绝。原因：未针对本品类长文档的特性配置文本分块规则，超出接口单次传输限制。
- 现象：尝试接入自建国内模型时，接口调用返回认证失败。原因：未正确配置`Authorization`参数，或未完成模型与对应路径的对接配置。
- 现象：调用外部接口后返回的`responseData`字段为空，无法生成文书内容。原因：未配置正确的字段过滤规则，或请求参数中未传入`variables`指定的核心业务标识，导致接口无法返回有效数据。

## 怎么确认配好了
- 发起单次测试请求，检查`Authorization`参数是否被正确携带，确认接口返回状态码为200。
- 查看`responseData`返回的字段是否包含预设的核心业务信息，确认字段过滤规则生效。
- 模拟长文本请求，检查系统是否自动拆分内容并分批发送。
- 触发临时失败场景，确认系统会按照配置的重试次数执行重试操作。
