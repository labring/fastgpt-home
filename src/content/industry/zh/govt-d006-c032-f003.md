# 投资项目立项与后评价的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类涉及的核心数据来自国资委投资监管系统、企业ERP和项目管理系统、行业市场数据、审计和财务报表，更新频率为季度。日常产出的文档包含年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告、投资后评价报告，文档多为多章节带结构化表格的正式公文，字段涉及项目投资额、立项时间、投后营收、风险等级等，包含万元、百分比、季度/年度周期等单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多异构的数据来源要求多轮对话逐步对齐不同系统的字段，避免数据冲突；季度更新的频率要求提示词必须明确限定时间周期，防止跨周期数据混入；复杂的文档结构需要通过多轮拆解指定章节，确保输出内容符合投决会或监管要求；国有资产相关的合规字段要求提示词严格约束输出格式，规避潜在的责任追究风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 前10–15条对话历史 | 匹配季度数据的周期范围，避免冗余历史干扰检索 |
| `messages` 处理逻辑 | 按会话维度拼接上下文 | 遵循`messages`参数的会话绑定规则，确保对话上下文连贯 |
| `variables` 预设值 | 绑定季度、项目ID变量 | 依托`variables`参数实现动态字段注入，适配多项目并行场景 |
| `chatId` 绑定规则 | 按会话ID隔离数据 | 确保不同项目的对话上下文互不干扰，符合国资数据安全要求 |
| 单次召回上限 | 前8–12条文档片段 | 匹配单份可研报告的章节数量，避免召回无关数据 |
| 上下文过滤阈值 | 按实测标定 | 适配国资监管系统数据的字段关联性，降低误召回概率 |

## 容易做错的三处
- 现象：发起对话后无法检索到对应项目的立项数据，返回空结果。原因：未通过`variables`参数绑定项目ID，导致检索范围覆盖全量数据，无法精准匹配目标项目。
- 现象：提示词无法提取本年、本月的项目数据，输出结果包含跨周期内容。原因：未在提示词中明确限定数据的时间周期字段，或未通过`messages`参数传递当前会话的时间上下文，导致模型无法锚定目标周期。
- 现象：设置工作流上下文数量为0后，仍出现冗余历史干扰输出。原因：误解上下文数量的传递逻辑，该参数实际控制传入API的聊天历史条数，设置为0仅不传递显式历史，但部分场景下仍会加载会话默认上下文。

## 怎么确认配好了
- 发起测试对话，输入指定项目ID与时间周期，核对检索结果是否仅覆盖目标项目与对应周期的数据。
- 查看工作流日志，核对传入API的`messages`参数是否包含预期的对话历史条数，验证上下文配置是否生效。
- 调整提示词中的时间限定字段，观察模型输出是否能准确提取本年、本月的项目字段，验证提示词配置合理性。
- 调用接口访问应用，核对返回结果是否与平台内测试对话的结果一致，验证接口配置正确性。
