# 投资项目立项与后评价的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
本品类涉及的日常文档包含年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告、投资后评价报告等。数据来源为国资委投资监管系统、企业ERP和项目管理系统、行业市场数据、审计和财务报表，更新频率为季度。文档结构涵盖项目基本信息、投资测算、风险评估、后评价指标等模块，字段涵盖项目编号、投资额度、建设周期、投产效益、风险整改情况等，无统一固定的单位标准，需匹配对应文档的业务规范。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源涉及多个内部管理系统与外部数据源，工具调用需支持多数据源的对接与数据拉取，避免因系统权限或接口格式差异导致数据缺失。单篇文档篇幅较长且结构复杂，工具调用需适配分块处理逻辑，避免超出上下文限制。季度更新的频率意味着无需高频同步数据，可设置合理的缓存周期以提升效率。同时，该品类的操作失误可能引发国有资产损失等严重后果，工具调用需配置失败重试与校验机制，确保数据准确性与流程合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配多类型工具调用需求，自动选择对应数据源或文档处理工具 |
| 单次工具调用上限 | 前6条 | 匹配单篇可研报告的核心章节数量，避免过多冗余数据导致上下文溢出 |
| 失败重试次数 | 3次 | 应对跨系统访问的短暂波动，平衡成功率与响应速度 |
| 最大上下文长度 | 8000–12000 token | 适配单篇完整可研报告的内容长度，覆盖核心业务字段 |
| 工具调用超时时间 | 600秒 | 适配跨系统数据拉取的延迟，避免因数据量大导致请求中断 |
| 知识库召回阈值 | 按实测标定 | 匹配本品类文档的相似度特征，避免召回无关的历史项目数据 |

## 容易做错的三处
-  调用工具时出现connection error报错。原因是未正确配置多数据源的对接密钥，或跨系统访问权限未开放。
-  API调用返回的内容未包含知识库中的项目数据。原因是未在应用配置中绑定对应品类的专属知识库，或召回阈值设置过高导致未匹配到相关文档。
-  平台测试正常但API调用结果不一致。原因是API请求未携带正确的上下文参数，或未指定使用绑定的知识库。

## 怎么确认配好了
-  在FastGPT v4.17.0的应用调试页，输入项目立项或后评价相关的查询，查看返回结果是否包含预设的知识库文档片段。
-  调用API接口，检查返回的`functionCall`参数是否包含正确的工具调用指令，且参数匹配当前品类的文档结构。
-  模拟工具调用失败的场景，查看系统是否触发预设的重试机制，且日志中记录了重试次数。
-  调整API请求的上下文参数，对比平台测试和API调用的返回内容，确认两者参数一致时结果匹配。
