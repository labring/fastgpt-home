# 投资项目立项与后评价的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据主要来自国资委投资监管系统、企业ERP和项目管理系统、行业市场数据、审计和财务报表，更新频率为季度。日常处理的文档包括年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告、投资后评价报告，文档多包含项目核心参数、财务测算、风险评估、投后绩效等字段，需符合国资监管的报送规范，无统一固定格式但字段覆盖投资全流程节点。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且需对接国资监管、企业内部系统等多渠道，要求模型接入环节支持多数据源的上下文整合，避免数据割裂。季度更新的频率决定了向量库同步周期需匹配业务节奏，不宜过于频繁或滞后。文档结构不统一且覆盖投资全流程字段，要求上下文窗口配置需适配长文本处理需求，同时需兼容不同文档的字段差异。此外，业务出错后果严重，要求模型生成内容需符合国资监管规范，需对生成逻辑做针对性约束。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配可行性研究报告、后评价报告等长文本文档，覆盖核心业务字段与历史数据 |
| `maxTokens` | 2000–3000 token | 满足单份文书起草的输出长度要求，符合国资报告的常规篇幅 |
| `temperature` | 0.2–0.4 | 降低生成随机性，确保内容符合国资监管的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应节点 | 适配多数据源对接的代理配置，保障内部系统访问安全 |
| `AIPROXY_API_TOKEN` | 填写部署时生成的代理密钥 | 确保模型调用的身份验证有效，避免无权限报错 |
| `toolChoice` | auto | 自动调用工具整合多系统数据，提升文书起草的准确性 |

## 容易做错的三处
- 现象：添加第三方模型API密钥后，界面提示无可用渠道，default分组下无法加载模型。原因：未在代理配置中添加对应模型的渠道白名单，或分组权限未开放第三方模型调用。
- 现象：对话与工作区的模型列表出现不一致，部分配置的模型未同步显示。原因：未在系统配置中开启模型同步缓存刷新，或工作区的模型权限配置与全局配置不匹配。
- 现象：生成文书的耗时过长，硬盘IO占用较高，单次处理速度不理想。原因：`maxContext`设置过大，未对长文本做合理分块，导致模型加载过多上下文数据，增加存储与计算压力。

## 怎么确认配好了
- 检查`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置值与部署文档一致，可通过调用测试接口返回正常响应。
- 验证`maxContext`与`maxTokens`的取值适配当前处理的最长文档，可上传单份完整可行性研究报告测试生成流程无中断。
- 核对`temperature`的取值，可生成两份同主题的后评价报告，对比内容一致性符合业务严谨性要求。
- 查看系统日志，确认多数据源对接的代理请求无超时报错，模型调用的返回格式符合国资报告的字段规范。
