# 招标采购合规管理的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
本品类涉及的文档包括采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料等，数据来源涵盖企业采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，更新频率为每日。文档包含采购方式、预算依据、评分办法、供应商资格条件等结构化字段，以及评审意见、投诉说明等非结构化内容，单份文档长度跨度较大，部分评标记录和投诉材料存在碎片化片段。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源数据来源要求索引支持多数据源接入与增量同步，避免重复导入同一文档。每日更新频率要求配置轻量的增量索引流程，避免全量重建占用过多资源。文档类型多样且长度跨度大，要求分块策略适配不同内容长度，避免割裂采购方式、评分办法等关键合规条款。结构化字段与非结构化内容混合，要求索引同时支持字段级匹配与语义匹配。审计追责相关的文档要求高置信度匹配结果，需严格控制匹配阈值，减少误判风险。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配多数招标采购类文档的单份内容长度，避免分块割裂关键条款 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的重叠内容，确保关键合规信息不被分块截断 |
| 相似度阈值 | 0.75–0.85 | 按实测标定，平衡合规审查的召回率与精准度，减少无关匹配结果 |
| 单次搜索上限 | 前 10 条 | 适配国央企采购文档的常规检索需求，避免返回过多冗余内容 |
| `defaultToken` | 4096 | 适配多数招标文书的上下文长度需求，确保检索时能完整调用关联文档 |
| `maxToken` | 8192 | 支持长文档的完整索引与检索，覆盖评标记录、投诉材料等较长内容 |

## 容易做错的三处
- 现象：调用ollama接入的向量模型时FastGPT返回拒绝，curl测试正常。原因：未配置正确的向量模型接口地址或认证参数，或存在接口调用频率限制未调整。
- 现象：无法通过MongoDB直接管理向量库的增删操作，仅root用户拥有权限。原因：未开启FastGPT与外部数据库的同步映射配置，或未开放非root用户的数据库操作权限。
- 现象：知识库索引合并后未实现去重，出现重复的评标记录或供应商信息。原因：未开启索引去重开关，或分块规则导致重复内容的片段差异过大，无法被去重逻辑识别。

## 怎么确认配好了
- 导入单份完整的招标文件，检查分块后的片段是否完整保留采购方式、预算依据等关键合规信息，无明显割裂。
- 发起采购方式合规性查询，验证返回的匹配文档数量符合单次搜索上限的设置值。
- 尝试通过外部MongoDB工具新增一条供应商投诉材料，检查FastGPT知识库是否同步更新该内容。
- 导入两份内容高度相似的评标记录，验证合并后的索引是否自动过滤重复条目。
