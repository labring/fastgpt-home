# 招标采购合规管理的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
本品类数据主要来自国央企采购中心、招标办、业务需求部门、审计和纪检部门、招标代理等主体，覆盖企业采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库等来源。日常文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料，数据按日更新，文档多包含采购方式、预算依据、评分办法、供应商资格要求等核心合规字段，格式兼具结构化表格与非结构化文本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据按日更新的特性要求配置增量同步规则，避免全量刷新占用计算资源。混合结构化与非结构化的文档格式，需要适配分块逻辑以保留核心合规字段的完整性。涉及采购方式、预算依据等敏感合规内容的检索需求，需优先召回高匹配度的合规依据文档。多部门协同使用的场景，要求知识库支持协作共享模式，同时需根据采购周期的数据波动调整召回上限，适配不同阶段的请求压力。此外，合规类检索需避免召回无关内容，需设置合理的匹配阈值。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.75–0.85 | 匹配招标采购合规相关的核心字段，过滤低相关性的非合规文档 |
| `limit` | 前8–12条 | 覆盖单次起草文书需参考的多类合规依据，避免上下文过载 |
| `searchMode` | hybrid | 适配结构化与非结构化混合的文档格式，兼顾关键词与语义匹配 |
| `usingReRank` | 开启 | 对召回结果重新排序，优先匹配采购方式、评分办法等核心合规项 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展查询词，补充合规相关的同义词或关联表述 |
| `collectionIds` | 按业务部门绑定指定集合 | 隔离不同采购场景的合规数据，避免跨部门数据干扰 |

## 容易做错的三处
- 现象：检索结果中包含大量与招标采购合规无关的通用文档。原因：未设置`similarity`阈值或阈值设置过低，未过滤低匹配度内容。
- 现象：知识库分割时无法按实际换行分割包含"\n"字符串的文档。原因：未配置正确的分块规则，未识别文本中的实际换行符。
- 现象：工作流中无法自动获取目标知识库ID。原因：未在系统设置中开启知识库ID暴露功能，或未调用正确的节点配置参数。

## 怎么确认配好了
- 发起包含采购方式、预算依据的查询，核对召回结果是否包含对应合规文档。
- 查看知识库同步日志，确认每日增量更新任务正常执行。
- 邀请多个测试账号访问同一知识库，确认可正常检索与编辑内容。
- 在工作流中调用知识库检索节点，确认可自动获取目标知识库的ID。
