# 招生入学与学籍管理的文书与材料起草：文档解析与分块

## 这个品类的数据长什么样
本品类涉及的文档主要包括入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表等。数据来源为全国中小学生学籍信息管理系统、地方招生入学平台、户籍和房产数据、学校教务系统，更新频率为每日。文档多具备固定字段结构，包含学生身份证号、学籍号、户籍地址、录取批次等标准化内容，部分文档嵌套多段审批流程说明与资格核验要求。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于数据来源分散且每日更新，不同地方平台生成的文档格式存在自定义变体，需适配多源异构的表格与文本混合结构。文档中的固定字段如学籍号、身份证号需精准提取，避免分块时拆分关键身份标识。嵌套审批流程的文档需保留段落逻辑，不能割裂审批节点与申请内容。同时，单份文档可能包含多份学生批次数据，分块时需避免跨学生的内容合并，保障后续检索时的资格核验准确性。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 文档包含固定字段与审批流程，该区间可保留单份学生申请或单条学籍异动的完整逻辑，避免拆分关键身份信息 |
| `chunkSplitter` | 按换行符与段落分隔 | 适配招生类文档的段落式结构，保留用户手动划分的审批节点与资格说明 |
| `customPdfParse` | 启用Marker解析模式 | 处理多源异构的PDF文档，保留表格与嵌套文本的原始排版，避免字段错位 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量招生计划与录取名册的大体积文档，满足日常批量上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 处理包含多批次学生数据的长文档，预留足够解析时间避免超时报错 |
| `chunkSettingMode` | 手动配置模式 | 允许针对学籍类文档调整分块边界，避免自动分块合并跨学生的批次数据 |

## 容易做错的三处
- 上传体积较大的PDF文档后触发报错，提示解析超时。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以处理包含多批次学生数据的长文档。
- 手动设置自定义分隔符后，分块结果要么合并多个学生的申请段落，要么拆分单条学籍异动的完整流程。原因是`chunkSettingMode`未切换为手动配置，或`chunkSize`取值区间未适配文档的固定字段长度。
- 部署Marker后处理PDF报错，返回包含错误信息的JSON响应。原因是未正确配置`customPdfParse`的关联环境变量，或部署版本与FastGPT版本不兼容。

## 怎么确认配好了
- 上传单份包含100条学生学籍信息的PDF文档，检查解析后的分块结果是否每条对应单条学生数据，无跨学生内容合并。
- 查看系统上传限制，确认`UPLOAD_FILE_MAX_SIZE`设置为1000 MB或符合本地文档体积的需求阈值。
- 触发一次长文档解析，等待`PARSE_FILE_TIMEOUT_SECONDS`设置的时长后，检查解析任务是否成功完成，无超时报错。
- 手动调整`chunkSize`为800字符，上传单份转学申请文档，确认分块结果保留完整的申请理由与审批栏内容。
