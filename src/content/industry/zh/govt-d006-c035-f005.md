# 排污许可管理的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源包括全国排污许可证管理信息平台、企业环保台账、在线监测系统、环境统计系统。日常生成的文书包含排污许可证申请表、执行报告、自行监测方案、台账记录、变更申请、许可证副本。数据按季度更新，文档核心字段包含许可排放限值、排放口编码、监测点位、台账记录周期等，部分字段需匹配对应行业技术规范与许可要求。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散的特点要求工具调用需适配多系统接口对接，确保能拉取全量台账、监测与许可数据。季度更新的节奏决定了数据源缓存周期需匹配季度节点，避免调用过期数据。专属字段与行业规范的绑定要求工具调用时需携带对应校验逻辑，自动核对许可限值与排放要求。出错后果的严重性要求工具调用结果需经过二次校验，防止生成不合规文书。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本进行设置，适配排污许可管理的专属业务需求。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `functionCall` | 开启强制模式 | 确保工具调用返回结构化数据，匹配排污许可文书的标准化字段要求 |
| 工具调用触发时机 | 按文书生成节点触发 | 匹配排污许可文书的起草流程，仅在需要填充数据时调用外部系统 |
| 数据源缓存时长 | 70–80天 | 匹配季度更新频率，避免缓存过期或过长占用资源 |
| 行业规范校验绑定 | 关联对应行业技术规范 | 确保调用数据与许可限值自动核对 |
| 调用超时设置 | 600秒 | 覆盖多系统拉取数据的耗时，防止调用中断 |
| 结果校验阈值 | 按实测标定 | 适配不同排污单位的行业差异 |

## 容易做错的三处
- 现象：使用API调用工具时，对话日志可显示标题内容，但生成的文书中对应字段为空。原因：未正确配置`functionCall`的返回格式，导致结构化数据未被正确解析到文书模板中。
- 现象：工具调用耗时过长触发504状态码。原因：数据源缓存时长设置不符合季度更新节奏，频繁拉取全量数据导致耗时超标。
- 现象：生成的自行监测方案中监测频次不符合要求。原因：未关联对应行业技术规范的校验规则，未自动核对监测周期与许可要求。

## 怎么确认配好了
- 手动触发一次工具调用流程，核对返回的结构化数据是否包含许可限值、排放口编码等核心字段。
- 查看工具调用日志，确认调用时机与文书生成节点匹配。
- 验证生成的执行报告是否自动核对了监测数据与许可限值的一致性。
- 模拟季度数据更新，检查数据源缓存是否按预设周期刷新。
