# 排污许可管理的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自全国排污许可证管理信息平台、企业环保台账、在线监测系统、环境统计系统。日常处理的文档包含排污许可证申请表、执行报告、自行监测方案、台账记录、变更申请、许可证副本。数据更新频率为季度。文档字段包含许可限值、排放数据、监测记录、申请变更事项等，涉及浓度、流量、时间周期等单位，结构以固定格式的填报表格与结构化记录为主。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散，需整合多系统的结构化与非结构化内容，模型接入环节需支持多源数据的上下文拼接与格式对齐。季度更新的批量文书处理需求，要求配置适配大批次内容的生成逻辑，需控制单次处理的上下文总长度。文档字段与单位有明确规范，模型输出需严格匹配许可要求，因此配置需兼顾生成效率与输出准确性，避免出现合规性错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配排污许可类文档的多源数据拼接需求，避免上下文溢出导致生成中断 |
| `maxTokens` | 2000–3000 token | 匹配单份排污执行报告或变更申请的生成长度，控制单批次处理耗时 |
| `temperature` | 0.1–0.3 | 降低随机生成概率，确保输出的字段与单位符合排污许可的规范要求 |
| `quoteMaxToken` | 1000–1500 字符 | 限制引用的排污台账、监测数据的长度，确保上下文聚焦核心合规字段 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应节点 | 适配多源数据调用的路由需求，确保模型调用的稳定性 |
| `AIPROXY_API_TOKEN` | 按实际分配的密钥填写 | 保障模型调用的身份验证安全，避免未授权访问 |

## 容易做错的三处
- 模型调用后返回空内容，原因是未正确拼接多源的排污数据上下文，导致模型无法获取许可限值等核心信息。
- 升级FastGPT v4.17.0后，生成的文书末尾出现规则追溯符号，原因是未关闭内置的规则引用展示配置，导致输出混入配置提示内容。
- 本地部署模型时无法正常解析环保台账数据，原因是未配置适配排污许可文档的格式解析规则，导致字段识别错误。

## 怎么确认配好了
- 导入单份排污执行报告的模板数据，触发文书生成，检查输出是否包含完整的许可限值、排放数据字段。
- 调用模型接口查看返回的日志，确认`maxContext`、`maxTokens`等参数的实际生效值与配置一致。
- 模拟多源数据拼接的场景，测试批量生成3份变更申请文档，检查生成结果的格式是否符合排污许可的规范。
- 验证模型调用的密钥与端点配置，确认接口返回的状态码为200，无身份验证报错。
