# 政务服务事项目录与办事指南维护的文书与材料起草：工作流编排
本文档适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的数据主要来源于国家政务服务事项基本目录、行政许可事项清单、地方政务服务事项库。日常维护的文档包含政务服务事项基本目录、实施清单、办事指南、标准材料目录、流程图及常见问题。数据更新频率为每月一次，需同步上级最新目录并梳理本级实施细节。文档字段包含事项唯一标识、实施主体、受理条件、申请材料明细、办事流程节点等，单条事项关联的材料数量与文档篇幅差异较大。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源的官方属性要求工作流需内置合规校验环节，确保生成的文书与上级目录口径一致。每月更新的频率要求工作流支持定时触发或按需触发的批量维护模式。多类型关联文档的特征要求工作流需配置跨节点的`variables`传递，实现事项基本信息、办事指南、申请材料的联动更新。字段校验的需求要求工作流中嵌入判断器节点，对必填字段进行完整性检查，避免出现空值或格式错误的内容。同时，由于维护工作不涉及单个办件，工作流需隔离单用户交互逻辑，专注于规则库的批量更新。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 判断器触发条件 | 按`variables`中的Boolean类型状态触发 | 需基于全局变量的事项校验结果控制流程走向 |
| 多模态节点图片识别开关 | 开启，置信度阈值设为0.7–0.9按实测标定 | 适配办事指南中流程图、材料样例的图片文字提取需求 |
| 工具调用输出控制 | 关闭工具调用结果的前端展示 | 仅保留校验与更新结果用于内部维护，无需暴露工具执行细节 |
| 文件解析超时时间 | 600 秒 | 单份办事指南文档通常包含多段流程与材料描述，需足够时间完成全量解析 |
| 全局变量绑定 | 绑定`nodeId`为当前事项节点的上下文 | 确保同一事项的多环节工作流共享统一的事项标识与关联数据 |
| 批量更新批次大小 | 前20条事项为一批次 | 匹配每月更新的事项总量，避免单次请求过载 |

## 容易做错的三处
- 现象为调用多模态节点后返回“无法提供图片内容”，原因为未正确开启节点的图片识别开关，或未将上传的图片关联至对应工作流节点。
- 现象为工具调用结果仍展示在前端界面，原因为未正确配置工具调用输出控制项，或错误添加工具调用结束节点但未绑定至对应执行链路。
- 现象为服务器部署后文件解析节点返回404错误，原因为未配置服务器端的文件存储路径映射，或前端上传的文件路径未同步至工作流的`variables`中。

## 怎么确认配好了
- 手动触发单条政务服务事项的工作流，检查全局`variables`中的校验状态是否正确触发判断器节点的分支流程。
- 上传包含流程图的测试图片至多模态节点，确认返回的图片文字内容可被正常提取并写入对应文档字段。
- 配置工具调用环节后，查看工作流执行日志，确认前端界面未展示工具调用的原始输出内容。
- 在服务器部署环境上传测试文件，确认文件解析节点可正常读取文件内容，无404类报错。
