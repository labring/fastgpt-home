# 政务服务事项目录与办事指南维护的文书与材料起草：文档解析与分块

本文基于FastGPT v4.17.0版本的配置逻辑进行说明。

## 这个品类的数据长什么样
通常由审改办、政务服务数据管理局等主体维护，数据来源为国家政务服务事项基本目录、行政许可事项清单、地方政务服务事项库。日常文档包含政务服务事项基本目录、实施清单、办事指南、标准材料目录、流程图及常见问题，多为带结构化表头的表格文档或长文本文档，更新频率为每月一次。

## 这些特征在「文档解析与分块」这一环带来什么约束
结构化表格与长文本混合的文档特征，要求解析时需保留字段与内容的对应关系，避免拆分破坏事项受理条件、申请材料等核心关联信息。月更且单文档规模较大的特性，要求分块不能过大，防止超出模型上下文限制，同时需适配批量解析的超时与文件大小约束。政务事项字段多且关联紧密，分块需保留相邻事项的上下文关联，避免分类匹配时出现口径偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配政务事项单条核心信息的长度，避免拆分破坏事项关联逻辑，同时控制单块token消耗 |
| `chunkSplitter` | 按段落与表头分组 | 针对结构化表格与长文本混合文档，保留表头与对应行数据的绑定关系，避免拆分后字段错位 |
| `customPdfParse` | 开启结构化解析模式 | 适配政务办事指南的多格式排版，准确提取字段与表格内容，减少解析后信息丢失 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配单份10万中文字或15000行excel的文档规模，避免上传环节拦截有效数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配批量政务文档的解析耗时，避免因超时中断解析流程 |
| `chunkSettingMode` | 手动自定义 | 针对政务事项的结构化特征，灵活调整分块规则，适配不同类型的事项文档 |

## 容易做错的三处
-  解析excel文档时返回不完整请求提示，原因是未针对结构化表格调整分块规则，单块数据过大超出模型处理范围。
-  大体积文档解析超时，原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数至适配批量政务文档的时长，导致解析流程被强制中断。
-  知识库分类匹配出现口径偏差，原因是分块时未保留事项与对应受理条件的上下文关联，拆分后字段与内容脱节。

## 怎么确认配好了
-  上传单份15000行excel文档，检查上传环节未被拦截，确认`UPLOAD_FILE_MAX_SIZE`配置生效。
-  解析单份10万中文字的办事指南文档，查看解析后分块数量与单块长度符合预设的`chunkSize`范围。
-  测试结构化表格解析结果，确认表头与对应行数据绑定完整，未出现字段错位情况。
-  发起分类匹配测试，检查匹配结果未出现事项口径不一致的情况，确认分块规则适配业务数据。
