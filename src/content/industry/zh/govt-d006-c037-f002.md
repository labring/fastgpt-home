# 政府信息依申请公开的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
本品类的服务主体为政府办公室、部门政务公开办、法规处及档案室。日常处理的文档包括政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证及行政复议答辩材料。数据来源涵盖政府信息公开平台、机关档案系统、内部公文系统、部门业务台账及政务公开相关规范。数据更新频率为不定期，随具体申请案件及档案归档进度变动。文档结构包含申请人信息、申请内容、公开属性判断、救济途径说明等固定字段，单份文档长度差异较大，短则数百字符，长则数千字符。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且多为内部系统，要求索引支持多源异构数据的统一接入与向量化。文档长度差异显著，需适配短段落与长文本的分块规则，避免语义割裂。核心业务为匹配申请内容与已有档案，要求向量模型的语义匹配精度贴合政务文书的严谨性，不能过度放宽或收紧匹配阈值。不定期更新的数据需支持增量索引，避免全量重建带来的资源消耗。固定字段与可变内容的混合结构，要求索引保留字段级的语义关联，确保检索结果与申请内容的匹配度符合政务办理标准。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配政务文书既有短段落（如申请表）又有长文本（如答复书）的结构，避免语义割裂 |
| 重叠长度 | 100–150 字符 | 保留跨块的上下文关联，确保申请内容的完整语义匹配 |
| `maxToken` | 4096 token | 匹配主流开源向量模型的输入上限，适配长文档的向量化处理 |
| 相似度阈值 | 0.72–0.80 | 过滤低匹配度的无关档案，符合政务文书的严谨语义判断标准 |
| 单次搜索上限 | 前10条 | 兼顾检索效率与召回完整性，避免过多冗余数据干扰答复起草 |
| `defaultToken` | 200 token | 适配短文档的向量化请求，避免token资源浪费 |

## 容易做错的三处
- 接入本地m3e向量模型后界面一直显示索引中。现象为索引状态长时间停留无更新，原因是未配置模型的请求超时参数，导致分块向量化的请求无法在预设时间内完成响应。
- 使用`defaultToken`设置不当导致向量化报错。现象为返回token超限的错误提示，原因是未根据所使用的向量模型实际输入上限调整`defaultToken`的取值，超出模型承载能力。
- 自定义索引配置无预期效果。现象为检索结果与自定义描述无关，原因是未将依申请公开的公开属性判断逻辑嵌入索引的语义匹配规则，导致检索结果未贴合业务需求。

## 怎么确认配好了
- 上传单份政府信息公开申请表，检查FastGPT后台的索引生成日志中无token超限或连接超时报错。
- 输入模拟的申请内容，检索返回的结果中包含对应档案的关键字段，且结果数量符合单次搜索上限的配置。
- 调整相似度阈值，验证检索结果的匹配度变化符合预期，高匹配度结果优先展示。
- 启用增量索引功能，上传新的归档档案，确认索引可在短时间内完成更新且无异常报错。
