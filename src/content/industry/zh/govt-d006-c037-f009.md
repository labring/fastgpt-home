# 政府信息依申请公开的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自政府信息公开平台、机关档案系统、公文系统、部门业务台账及《政府信息公开条例》相关规范。日常处理的文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证与行政复议答辩材料。数据更新无固定周期，随个案申请与归档流程变动。文档多为结构化表单与制式公文，包含申请人信息、申请事项、信息指向范围、公开属性判断、救济途径说明等字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散且格式不统一，要求模型接入需支持多源异构数据的上下文整合，避免出现信息缺失。文档包含第三方权益判断等敏感内容，需严格约束模型的输出范围与上下文长度，防止敏感信息泄露。个案办理的时效性要求，需限制模型调用的响应时长，避免超出法定办理周期。制式公文的固定结构要求，需约束模型输出的格式与必填字段完整性，确保符合官方文书规范。不定期更新的数据需支持动态接入最新的政策与档案内容，保证答复依据的时效性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 覆盖政府信息公开答复所需的申请原文、档案检索结果与政策依据，避免上下文截断导致信息缺失 |
| `maxTokens` | 2000–3000 token | 匹配制式答复书的标准字数，确保输出包含完整的救济途径与格式要求 |
| `temperature` | 0.1–0.3 | 降低随机输出概率，保证答复内容符合官方公文的严谨性 |
| `toolChoice` | auto | 自动触发工具调用以检索对应档案与政策数据，适配个案的信息检索需求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接口地址 | 适配本地或私有部署的大模型调用链路，确保政务敏感数据不泄露 |
| `AIPROXY_API_TOKEN` | 按实测标定的安全阈值 | 限制接口调用权限，防止未授权访问内部政务数据 |

## 容易做错的三处
- 调用本地部署的大模型时出现工具调用无响应：现象为工具调用环节返回空结果或状态码400，原因是未正确配置`toolChoice`参数为auto，或代理服务未开放工具调用权限。
- 多模态向量模型调用失败：现象为接口返回格式错误或字段为空，原因是未适配通义多模态向量的专属调用规则，未在配置中补充对应模型的标识参数。
- 上下文长度超限导致输出截断：现象为答复书缺少末尾的救济途径说明，原因是`maxContext`参数设置过小，未覆盖全部检索到的档案与政策内容。

## 怎么确认配好了
- 导入1份真实的政府信息公开申请表与关联档案，触发模型生成答复书，核对输出是否包含制式公文的必填字段。
- 查看模型调用日志，确认`toolChoice`参数触发了自动检索工具，且返回的上下文包含正确的政策与档案内容。
- 测试本地代理服务的调用链路，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无连接超时或权限报错。
- 调整`temperature`参数为0.2，生成3份答复书，核对输出内容的一致性，确认严谨性符合官方公文要求。
