# 政府采购项目的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常处理的文档包含采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复等，文档结构多包含项目编号、采购内容、预算金额、供应商资质、评审标准等字段，无统一固定格式，部分文档需关联跨系统的资质与预算数据。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的数据源要求索引支持增量同步，避免全量重建占用过多服务器资源。多来源跨系统数据格式不统一，索引需支持自定义字段映射以兼容不同文档结构。文档覆盖采购全流程，需区分不同类型文档的检索权重，保障核心业务文档如招标文件、评标报告优先召回。供应商信用记录需与项目维度强绑定，索引需支持按项目ID等字段精准过滤，避免跨项目数据混淆。合规性要求下，检索结果需严格匹配采购相关业务规则，减少无关内容召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配政府采购文档的段落长度，避免单块包含跨章节的业务内容 |
| 重叠长度 | 100–200 字符 | 保障跨分块的上下文连贯性，尤其是评分办法、资质要求这类连续文本 |
| `defaultToken` | 4096 | 适配多数大语言模型的输入限制，保障检索后拼接的上下文可完整传入 |
| 单次搜索上限 | 前 8 条 | 覆盖政府采购项目的核心关联文档数量，避免过多冗余结果干扰业务判断 |
| `maxToken` | 8192 | 适配检索后上下文拼接的总长度要求，满足复杂评标报告等长文档的处理需求 |
| 重排开关 | 开启 | 提升政府采购相关文档的检索相关性，过滤低匹配度的非业务文档 |

本配置基于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：知识库搜索响应超时，界面显示“请求处理超时”。原因：未配置增量索引，全量重建索引时占用过多内存与CPU资源，未适配政府采购每日更新的数据源采用增量同步策略。
- 现象：检索结果中混入非本项目的供应商信用记录。原因：未配置按项目ID等字段的过滤规则，索引未绑定业务维度的关联字段，导致跨项目数据被召回。
- 现象：问答拆分处理未返回符合采购业务规则的内容。原因：混淆了向量模型与大语言模型的分工，未使用指定的embedding模型对采购文档进行向量化，导致检索匹配度不足。

## 怎么确认配好了
- 查看索引同步日志，确认每日增量同步任务正常触发，无异常中断记录。
- 输入特定项目的采购编号，检索结果仅返回该项目关联的文档，无跨项目数据混入。
- 测试长文本如评标报告的分块效果，确认重叠部分的上下文连贯，无内容截断。
- 核对配置项中的分块长度、`defaultToken`、`maxToken`等参数，与预设的取值一致。
