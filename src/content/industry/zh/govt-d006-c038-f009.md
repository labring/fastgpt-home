# 政府采购项目的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常处理的文档包含采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同与质疑答复，各文档有固定结构字段，例如采购需求需明确采购内容与预算，招标文件需包含评标办法条款，供应商信用记录需关联统一社会信用代码与信用状态。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征对模型接入与配置带来明确约束：多来源且每日更新的数据集，要求配置需支持批量同步不同系统的文档，避免手动导入的延迟与错误；多样的文档结构与字段，要求配置需适配不同文档的格式解析，确保关键字段被准确提取；高风险的出错后果，要求配置需严格控制生成内容的合规性，避免生成不符合政府采购规则的文书。同时，不同使用主体的场景差异，要求配置可灵活调整生成的文书侧重点。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 4000–6000 token | 政府采购类单篇关联文档总长度多在2000–4000字符，需预留足够上下文容纳多份参考文档与生成结果 |
| `maxTokens` | 8000–12000 token | 单篇政府采购文书需覆盖完整条款，需足够token支持长文本生成与细节填充 |
| `temperature` | 0.3–0.5 | 政府采购文书需严格符合固定规则，需较低的随机性以确保内容合规、格式统一 |
| `AIPROXY_API_ENDPOINT` | 与本地部署的大模型服务地址一致 | 需将请求指向自建或合规的大模型服务，避免使用公共接口导致敏感数据泄露 |
| `AIPROXY_API_TOKEN` | 按实际部署的代理服务密钥填写 | 用于身份验证，确保接入的大模型服务仅接收授权请求 |
| `toolChoice` | auto | 需根据文书类型自动调用对应工具，例如生成招标文件时自动关联评标办法参考数据 |

## 容易做错的三处
- 现象：部署后调用大模型返回500状态码，日志显示代理连接失败。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，导致请求无法到达目标大模型服务。
- 现象：生成的采购需求文档缺失预算字段，关键信息不完整。原因：未调整`maxContext`参数，导致导入的预算系统数据被上下文截断，模型无法提取完整字段。
- 现象：生成的质疑答复出现格式混乱，未符合政府采购文书的固定排版要求。原因：未针对政府采购文档的结构配置生成规则，导致模型生成的内容不符合行业通用格式。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置项，发起测试请求确认大模型连接正常，无认证或地址错误。
- 导入一份标准政府采购招标文件与对应采购需求文档，测试生成投标文件模板，核对关键字段是否完整。
- 调整`temperature`参数，对比两次生成的评标报告内容，确认随机性符合合规要求。
- 导入多份每日更新的供应商信用记录，测试批量生成资格审查文档，确认同步与解析无延迟。
