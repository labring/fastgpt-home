# 法务合规与重大风险管理的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
本品类的核心数据来自企业合同管理系统、合规风险数据库、法律法规库、案件管理系统及举报平台。日常产出的文书包括合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告。数据更新周期为月度，单份文档通常包含事项主体、合规依据、审核结论、关联标识等字段，不同文书的格式与字段存在差异，但均需关联具体业务场景与合规条款。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的数据来源分散且关联业务合规风险，引用溯源需精准匹配原始系统的条目，避免关联错误的合规依据或案件信息。月度更新的频率要求知识库同步策略需覆盖增量数据的定期拉取，防止出现合规依据过期的问题。多样的文书类型对应不同的字段结构，需确保召回的内容与当前起草的文书场景匹配，无法直接复用通用的字段映射规则。同时，合规类文书的引用错误可能引发重大法律风险，溯源环节需保留完整的引用链路，便于后续合规审查与追溯。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大引用token数 | 800–1200 token | 合规文书需完整引用法规条款与审核意见，避免截断关键合规依据 |
| 返回引用详情 | 开启 | 需在生成的文书中展示引用来源的核心信息，便于合规审查 |
| 返回原始数据 | 开启 | 溯源环节需关联原始系统的文档条目，匹配合规风险数据库的内容 |
| 单次召回上限 | 前6条 | 合规类文书引用不宜过多，避免混淆不同合规事项的依据 |
| 知识库同步周期 | 月度 | 匹配本品类数据的月度更新频率，确保引用的合规依据为最新版本 |
| 引用匹配阈值 | 0.75–0.85 | 合规依据需具备较高匹配度，避免召回无关的合规条款 |

## 容易做错的三处
- 调用外部API生成合规文书后，返回结果的`detail`与`responseData`字段为空。原因：未开启返回原始数据与引用详情配置项，或发布渠道未启用引用数据返回功能。
- 调整`quoteMaxToken`至2000以上后，生成的合规文书未包含任何引用内容，且召回日志显示已成功匹配到合规文档。原因：token阈值过高导致模型无法有效整合引用内容，或召回的合规文档超出系统处理上限。
- 生成的合规文书引用了已失效的合规依据。原因：知识库同步周期设置过长，未按月度频率更新合规风险数据库与法律法规库内容。

## 怎么确认配好了
- 手动触发一次合规文书起草流程，检查生成结果中是否包含引用来源的标题与核心内容。
- 调用外部API接口，查看返回数据中是否包含`detail`与`responseData`字段，确认引用数据已正常返回。
- 临时调整知识库同步周期为每日，验证新增的合规数据是否能被正常召回并关联至生成结果。
- 调整`quoteMaxToken`至区间内的边界值，检查生成内容是否未出现关键合规条款被截断的情况。
