# 法务合规与重大风险管理的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自企业合同管理系统、合规风险数据库、法律法规库、案件管理系统、举报平台。日常文档包括合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告。数据更新频率为每月一次。文档混合结构化与非结构化内容，包含业务场景描述、合规依据、风险提示、处理建议，无固定标准化单位，字段围绕经营合规相关的合规性内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配本品类合规类文档的平均长度，避免截断关键合规依据与风险分析内容 |
| `maxTokens` | 2000–3000 token | 满足合规文书起草的输出长度需求，覆盖完整审核意见、风险提示的输出要求 |
| `quoteMaxToken` | 1000–1500 token | 确保引用的合规数据库、合同条款的总长度，保留足够的合规依据细节 |
| `temperature` | 0.1–0.3 | 降低生成内容的随机性，确保合规输出的严谨性，符合经营合规的要求 |
| `AIPROXY_API_ENDPOINT` | 企业内部部署的API地址 | 适配国央企内部数据不出境的合规要求，保障数据安全 |
| `toolChoice` | `none` | 避免调用外部工具，确保所有生成内容严格基于内部合规数据 |

## 容易做错的三处
- 现象：模型无法读取上传的合规文档，或上传后无响应。原因：未配置文档解析节点的适配规则，或`maxContext`设置过小，导致文档内容被截断，无法完整解析上传文件。
- 现象：知识库匹配结果仅返回1个文本块，无法返回多个文本块。原因：未正确配置`quoteMaxToken`的引用长度限制，或检索匹配规则未设置多文本块的返回数量，导致仅返回单条匹配内容。
- 现象：本地部署模型后，聊天窗口上传附件无响应。原因：未配置`AIPROXY_API_ENDPOINT指向本地模型的正确地址，或接入超时参数未适配本地部署的延迟情况，导致请求无法正常发送。

## 怎么确认配好了
- 上传一份合规风险清单，检查模型能否提取风险等级与触发场景，验证解析后的内容与原文档匹配。
- 触发知识库检索，检查返回的文本块数量符合预期，验证是否匹配`quoteMaxToken`的配置规则。
- 调用API接口，检查返回的合规审核意见格式符合合规文档的标准结构，确保内容严谨。
- 配置每月数据同步任务，检查数据同步逻辑正常，验证更新后的合规数据是否被正确加载至知识库。
