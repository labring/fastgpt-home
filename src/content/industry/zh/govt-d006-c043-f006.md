# 特种设备安全监管的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
本品类数据主要来自特种设备安全监察系统、检验检测机构系统、使用单位台账及作业人员证书库。数据更新频率为月度。日常使用的文档包含使用登记证、定期检验报告、维保记录、隐患整改通知书、事故报告、作业人员证书，各文档均包含设备唯一标识、检验有效期、作业人员资质编号、使用单位名称等结构化字段，部分文档附带扫描件附件。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的数据分散在多个独立系统中，跨系统关联设备、资质、维保等信息的需求，要求溯源环节需支持多数据源的关联匹配。月度更新的频率决定了知识库同步周期需匹配更新节奏，避免引用过期数据。文档包含结构化字段与扫描附件，溯源需同时覆盖结构化字段匹配与附件内容校验。此外，监管类文书出错会导致设备停用、行政处罚等后果，要求溯源环节需明确标注来源的系统与文档类型，确保信息可追溯验证。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配特种设备文档的结构化字段与附件文本长度 |
| 最大上下文召回数 | 前6条 | 匹配月度更新的知识库数据量，避免冗余信息干扰 |
| `quoteMaxToken` | 300–500 token | 控制引用内容的长度，确保监管文书引用信息完整且不溢出 |
| `responseData` | 启用结构化字段输出 | 便于关联设备编号、检验有效期等关键监管字段 |
| `detail` | 开启溯源详情展示 | 标注来源系统与文档类型，符合监管溯源要求 |
| 知识库同步周期 | 按月执行 | 匹配本品类数据的月度更新频率 |

## 容易做错的三处
- 现象：生成监管文书时出现红色报错提示。原因：未配置`responseData`启用结构化输出，导致溯源时无法匹配设备编号字段引发校验失败。
- 现象：工作流中仅第一个提问触发知识库引用，后续提问无引用结果。原因：未配置`detail`开启全局溯源配置，导致上下文未保留数据源关联规则。
- 现象：引用的检验报告内容过长，干扰监管文书排版。原因：未设置`quoteMaxToken`限制引用长度，导致附件文本被直接插入文书。

## 怎么确认配好了
- 触发一次定期检验报告相关的文书生成请求，检查返回结果是否附带明确的数据源标注与文档类型说明。
- 查看系统同步配置，确认知识库更新周期与本品类的月度更新节奏一致。
- 测试多轮连续提问场景，确认每轮提问均能关联到对应的特种设备数据。
- 调整引用相关参数后，验证生成的文书中引用内容的长度符合排版需求。
