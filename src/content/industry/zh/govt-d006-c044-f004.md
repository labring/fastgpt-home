# 环境执法与监测监管的文书与材料起草：工作流编排

## 这个品类的数据长什么样
本品类的数据来源包括在线监控平台、污染源自动监测数据、生态环境执法系统、第三方检测报告，更新频率为每日。日常产出的文档包含现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书，字段涵盖执法时间、监测点位编号、污染物浓度值、整改要求、处罚依据等，部分文档需匹配法定格式与固定字段顺序。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据来源分散且每日更新，要求工作流支持对接多类外部系统拉取实时数据。日常文档需严格匹配固定格式与字段，要求工作流包含字段校验节点确保信息完整。核心耗时环节为多源数据比对、超标判定与执法文书生成，要求工作流可拆分长耗时节点避免执行超时。同时需支持第三方检测报告等文件的上传与参数传递，满足执法证据归档需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 包含执法时间、监测点位、污染物浓度的结构化字段 | 匹配品类核心执法文书的必填字段，确保生成内容符合格式要求 |
| 超时设置 | 1200–1800 秒 | 覆盖多源数据比对、文书生成的最长耗时场景，适配FastGPT v4.17.0的基础执行时长限制 |
| 文件上传节点 | 允许上传PDF、CSV格式文件，单文件上限1000 MB | 匹配第三方检测报告、执法影像等常见归档文件的格式与大小要求 |
| 单次调用数据条数 | 前10条 | 匹配生态环境执法系统的单次数据返回上限，避免接口过载 |
| 触发节点 | 表单提交后触发 | 确保所有执法信息填写完整后才启动工作流，避免缺失关键字段 |
| `nodeId` | 绑定在线监控平台数据接口的节点ID | 实时拉取当日更新的污染源监测数据，满足执法数据的时效性要求 |

## 容易做错的三处
- 工作流执行超时，界面显示执行状态异常或返回504状态码，原因是未拆分多源数据比对、文书生成的长耗时节点，整体执行时长超出配置阈值。
- 上传的检测报告无法作为参数传入工作流，表现为后续文书生成节点的文件字段为空，原因是未在工作流配置中开启文件变量传递权限。
- 表单未填写完整就触发工作流，生成的执法文书缺失必填字段，原因是未配置表单提交触发节点，误将输入组件的变更事件作为触发条件。

## 怎么确认配好了
- 触发测试工作流，查看执行日志中的`variables`字段，确认包含预设的执法时间、监测点位等结构化字段。
- 上传符合格式的第三方检测报告文件，确认后续节点可读取文件内容并作为参数调用。
- 测试表单未填写完整时，确认无法触发工作流执行。
- 查看工作流超时设置，确认阈值匹配品类的最长耗时场景。
