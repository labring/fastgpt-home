# 环境执法与监测监管的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
本品类的数据主要来自在线监控平台、污染源自动监测数据、生态环境执法系统、第三方检测报告，更新频率为每日。日常生成的文档包含现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书。现场检查记录包含检查点位、检查时间、工况参数等字段；采样记录包含采样点位编号、采样时间、污染物样本信息；监测报告包含污染物浓度数值及对应检测单位；各类执法文书包含违法事实描述、整改要求等标准化字段，数据单位涵盖环境监测常用的mg/m³、吨等。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且每日更新，要求工具调用需适配多类系统的接口权限与数据格式，避免因数据源不兼容导致文书生成错误。不同文档的字段结构差异显著，工具调用需按文书类型匹配对应的数据提取规则，无法统一适配所有文档。实时同步的日更数据要求工具调用需配置定时触发逻辑，避免使用过期数据生成执法文书。数据关联逻辑复杂，需同时匹配在线监控数据与现场执法记录，工具调用的参数配置需覆盖多源数据的关联校验，否则可能出现证据不足的情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动匹配不同类型的执法数据与文书生成需求，适配多源数据的调用逻辑 |
| `functionCall` | 按文档类型触发 | 针对现场检查记录、监测报告等不同文书，调用对应的数据提取与生成函数 |
| API调用超时设置 | `600 秒` | 拉取在线监控平台与第三方检测报告的历史数据耗时较长，需预留足够同步时间 |
| 多模态数据处理开关 | 启用 | 适配现场执法照片、采样记录附件等多模态数据的处理需求 |
| 模型绑定规则 | 纯文本数据绑定Qwen2，多模态数据绑定多模态专用模型 | 区分处理不同类型的输入数据，适配执法场景下文本与图片混合的业务需求 |

## 容易做错的三处
- 现象：API调用返回的执法数据字段为空，原因：未配置对应生态环境执法系统或在线监控平台的插件权限，无法拉取所需的现场检查记录或监测数据。
- 现象：工具调用触发后出现超时报错，状态码504，原因：设置的超时时间短于拉取第三方检测报告的耗时，导致数据未完全加载就终止调用。
- 现象：多模态执法照片无法正确生成对应监测报告的附件说明，原因：未区分配置纯文本与多模态数据的模型绑定规则，导致多模态数据被分配至仅支持纯文本处理的模型。

## 怎么确认配好了
- 手动触发工具调用，查看是否能成功拉取对应数据源的现场检查记录或监测数据，确认字段完整且符合业务格式。
- 上传多模态执法照片与纯文本执法文本，分别测试模型调用结果，确认多模态数据由多模态模型处理，纯文本数据由Qwen2处理。
- 调用发布后的API接口，传入指定的执法文书类型参数，查看返回结果是否匹配对应的数据提取与生成逻辑。
- 查看FastGPT v4.17.0的工具调用日志，确认`toolChoice`与`functionCall`参数按配置的规则生效。
