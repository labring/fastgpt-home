# 环境执法与监测监管的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来自在线监控平台、污染源自动监测数据、生态环境执法系统及第三方检测报告，更新频率为每日。日常产出的文档包含现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书，单份文档包含监测点位、污染物浓度、执法时间、采样人员、检测仪器型号等固定字段，数据格式多为结构化表格与结构化文本混合形式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
每日更新的实时监测数据要求溯源环节能快速关联最新执法与监测记录，避免引用过期数据。多源数据混合的文档结构，要求溯源时需精准匹配文档类型与对应数据源，防止混淆现场记录与第三方检测报告的字段。固定字段的存在，要求溯源结果需明确标注对应数据的来源系统、生成时间与检测主体，保障执法文书的证据合法性。多源数据的分散存储，要求溯源环节需打通不同系统的数据关联路径，确保引用的监测数据与现场检查记录一一对应，避免出现证据脱节的问题。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前5条 | 该品类执法文书需关联现场记录、监测报告等核心数据源，前5条可覆盖核心证据，避免冗余结果干扰 |
| `quoteMaxToken` | 800–1200 token | 执法文书单份核心文档的内容长度多在该区间，可完整保留溯源原文的证据细节 |
| `responseData` | 开启 | 需将知识库检索到的原文直接作为答复内容，保障执法文书的原始证据效力 |
| `detail` | 开启 | 需在溯源结果中明确标注数据源类型、生成时间等字段，满足执法证据的合规要求 |
| 最大上下文 | 按实测标定 | 适配多源数据混合的文档结构，避免上下文过长导致检索偏差 |

## 容易做错的三处
-  生成的执法文书未关联检索到的监测数据。未开启`responseData`配置，导致系统未直接调用知识库原文内容，而是生成了泛化答复。
-  工作流节点中无法选择知识库引用变量。未在知识库配置中开启数据输出开关，或工作流节点未绑定对应知识库数据源。
-  检索结果条数超出预设范围。单次搜索上限配置值设置过高，导致返回过多非核心的历史数据，干扰执法文书的证据选取。

## 怎么确认配好了
-  执行一次现场检查记录起草测试，查看生成内容是否直接复用知识库中对应文档的原文内容，无额外泛化表述。
-  检查溯源结果的标注信息，确认包含数据源系统、生成时间等对应字段，符合执法证据的合规要求。
-  调整单次搜索上限参数，验证检索结果条数是否与配置值一致。
-  查看工作流节点的变量选项，确认知识库引用变量已可正常选择并调用。
