# 用地预审与规划许可的文书与材料起草：向量模型与索引

本页面适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类数据主要来自国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据。日常文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，涵盖项目选址范围、用地规模、管控要求、红线坐标等字段。数据更新不定期，无固定周期，单份文档同时包含结构化审批信息与非空间文本描述内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据包含空间坐标类内容与结构化审批字段，分块时需避免割裂关联的空间范围与审批要求，防止向量索引丢失关键关联信息。数据来源分散且更新不定期，需配置支持增量更新的索引逻辑，避免全量重建带来的资源消耗。单份文档同时包含文本描述与数值类指标，向量模型需适配混合格式内容的编码，确保不同类型字段的语义关联被准确捕捉。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 本品类文档包含空间描述与审批文本，该长度可保留单条审批逻辑的完整性 |
| 重叠长度 | 100–150 字符 | 避免分块后空间坐标与关联文本被拆分，确保关联信息完整 |
| `defaultToken` | 1024 | 适配基础嵌入模型的默认token设置，避免初始检索异常 |
| `maxToken` | 8192 | 适配主流嵌入模型的最大token限制，避免内容截断 |
| 相似度阈值 | 0.72–0.80 | 按实测标定，区分项目选址的相似性与合规性差异 |
| 单次搜索上限 | 前 6 条 | 本品类审批需核对多份前置条件文档，适量结果可覆盖关联信息 |

## 容易做错的三处
- 现象：知识库索引完成后搜索响应超时，耗时超过30秒。原因：未针对本品类的大体积空间文档调整分块策略，导致单批次向量检索的token过载。
- 现象：配置`text-embedding-ada-002`后调用知识库仍返回嵌入模型错误。原因：未将嵌入模型正确关联至FastGPT的API渠道，或本地部署时未完成模型容器的端口映射。
- 现象：搜索结果中出现大量无关的红线图数据。原因：相似度阈值设置过低，未过滤非关联的空间文档，导致检索精度不足。

## 怎么确认配好了
- 上传单份用地预审意见书，执行分块测试，检查分块结果未割裂空间坐标与审批要求。
- 调用嵌入模型接口，验证返回的向量维度与配置参数一致，无截断报错。
- 模拟项目审批查询，核对搜索结果包含对应前置条件文档，结果条数符合单次搜索上限设置。
- 上传一份更新后的规划条件文档，执行增量索引测试，确认新数据可被正常检索。
