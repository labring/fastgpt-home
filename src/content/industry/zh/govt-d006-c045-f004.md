# 用地预审与规划许可的文书与材料起草：工作流编排
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
该品类的核心数据来自国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。日常文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，其中结构化文档包含项目基本信息、选址范围、用地规模、管控要求等字段，矢量图纸包含坐标点位、边界范围等矢量数据，无固定统一的文档格式，需适配多类型数据源解析。

## 这些特征在「工作流编排」这一环带来什么约束
多来源且不定期更新的数据，要求工作流需设置定时拉取节点，确保每次执行时调用最新的规划管控与审批数据。文档类型多样，包含结构化表单与非结构化矢量图纸，要求工作流需配置不同的解析节点，分别处理文本信息与坐标数据。该品类最耗时的环节为核对项目选址与规划管控、审查用地规模和红线冲突，要求工作流需将该环节拆分为多个子节点，分步完成校验。该环节发生在建设前的项目审批阶段，需与发改、住建等前置审批环节联动，要求工作流需配置跨部门数据拉取节点。出错后果严重，要求工作流需增加校验回退节点，避免错误数据流入后续审批环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按审批环节拆分，包含项目ID、红线坐标、管控要求 | 用地预审与规划许可需校验多维度项目参数，拆分变量可精准匹配对应数据源，避免检索范围过大 |
| `nodeId` | 按数据拉取、合规校验、文书生成、审批提交拆分节点ID | 多环节工作流需精准定位每个执行节点，确保流程按审批顺序流转，避免节点混乱 |
| 单次搜索上限 | 前10条 | 该品类核心数据条目规整，过多结果会增加人工校验负担，前10条可覆盖主要合规校验需求 |
| 超时时间 | 600秒 | 需等待跨平台拉取审批监管平台数据与解析矢量图纸，预留足够的执行时长 |
| 知识库选择 | 绑定国土空间规划一张图库 | 该品类的合规校验核心数据来自该平台，绑定后可精准召回规划管控条款与红线限制 |

## 容易做错的三处
- 工作流生成的文书未匹配项目红线范围，返回结果为空或与预设不符，原因是未正确配置`variables`，传入的项目参数未绑定到知识库检索环节，导致检索数据与当前项目不匹配。
- 调试时显示超时错误，返回状态码504，原因是未设置合理的超时时间，跨平台拉取审批监管平台数据或解析矢量图纸未预留足够时长，导致流程中断。
- 工具调用环节无返回结果，节点状态显示未执行，原因是未正确配置`nodeId`，节点间的流转触发逻辑未按审批顺序绑定，导致流程无法按预期推进。

## 怎么确认配好了
- 手动传入测试用的项目ID与红线坐标参数，检查检索环节是否召回对应项目的审批数据与规划管控条款。
- 查看工作流日志，确认每个`nodeId`对应的节点均按顺序执行，无中断或报错信息。
- 触发文书生成节点，检查输出的文书是否包含预设的规划管控条款与项目基本信息。
- 模拟异常数据输入，检查合规校验节点是否触发拦截逻辑，提示异常信息。
