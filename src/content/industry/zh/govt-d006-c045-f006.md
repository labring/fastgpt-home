# 用地预审与规划许可的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
本品类涉及的核心数据来自国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。日常产出与使用的文档包括用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，文档字段包含项目选址范围、用地规模、规划管控要求、前置审批条件等，部分图纸类文档带有空间坐标与边界参数。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且更新无固定周期，要求溯源环节必须精准关联每条引用内容对应的具体数据源批次，避免引用过期或错误的规划数据。文档包含文本与空间图纸两类，引用时需区分文本字段与空间边界参数的溯源路径，确保两类内容的来源标注完整。行政审批类场景对溯源准确性要求高，需避免出现引用来源与实际审批依据不匹配的情况，同时需支持快速定位单条引用的原始数据入口。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配用地预审与规划许可类文档的引用内容长度，避免截断关键审批依据与空间参数 |
| `responseData` | 开启 | 用于返回引用内容对应的原始数据源标识，匹配行政审批场景的溯源需求 |
| `detail` | 完整模式 | 保留引用内容的完整上下文，便于核对项目选址与红线的匹配情况 |
| 引用展示位置 | 段落末尾 | 符合本品类行政审批文档的通用标注习惯 |
| 单次召回数据源上限 | 前 5 条 | 避免过多冗余数据干扰审批判断，聚焦核心前置审批依据 |
| 超时阈值 | 60 秒 | 适配本品类数据源的加载节奏，避免因等待过久导致流程中断 |

## 容易做错的三处
- 现象为回答段落末尾未显示引用来源标识，原因是未开启`responseData`配置项或引用展示位置未设置为段落末尾，对应此前反馈的新增引用功能未正常展示的场景。
- 现象为回答返回超时错误，原因是超时阈值设置过短，未适配本品类国土空间规划一张图等数据源的加载节奏。
- 现象为引用内容被截断，丢失关键用地规模或红线参数，原因是`quoteMaxToken`设置值过小，无法容纳完整的引用上下文。

## 怎么确认配好了
- 上传一份用地预审与选址意见书的示例文档，发起测试提问，查看回答段落末尾是否显示引用来源标识。
- 查看回答中引用内容的上下文，确认是否包含完整的规划管控要求与用地规模参数。
- 确认运行环境为FastGPT v4.17.0及以上版本，确保所有配置项可正常生效。
- 发起包含多个前置审批条件的测试提问，确认召回的数据源数量符合单次召回上限设置。
