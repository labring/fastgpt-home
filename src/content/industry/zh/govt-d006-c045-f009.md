# 用地预审与规划许可的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类涉及的数据来自国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。日常处理的文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，文档包含项目选址范围、用地规模、管控要求、审批节点等固定字段，部分文档为可视化格式，包含坐标标注、边界线条等内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
多来源的不定期更新数据要求配置需适配可变长度的上下文内容，避免因数据加载不全导致文书遗漏关键审批依据。固定字段的文档结构要求模型需精准匹配字段要求，避免生成内容偏离审批规范。可视化的红线图、规划条件等文档，要求配置需支持视觉解析能力，提取图纸中的坐标、边界等关键信息。跨部门的前置协调数据需纳入上下文，要求配置需承载足够的上下文容量，确保所有关联信息被充分利用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多来源的国土空间规划、项目审批等历史数据，避免上下文溢出 |
| `maxTokens` | 3000–4000 token | 满足用地预审与规划许可文书的完整输出长度，覆盖审批意见、红线说明等内容 |
| `vision` | 开启 | 支持解析红线图、规划条件附图等可视化文档，提取坐标、管控边界等关键信息 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保用地规模、管控要求等核心字段输出的一致性 |

| `toolChoice` | auto | 自动调用关联工具核对用地冲突，无需手动指定调用逻辑 |

## 容易做错的三处
- 生成结果仅包含思考过程，无正式文书内容。原因是提示词未明确区分思考与输出环节，或`temperature`设置偏离合理区间。
- 无法解析红线图等可视化文档，生成内容缺少图纸提取的关键信息。原因是未开启`vision`配置，或未选择支持视觉能力的模型。
- 生成文书被截断，关键审批要求未完整呈现。原因是`maxTokens`设置过小，无法承载完整的文书输出内容。

## 怎么确认配好了
- 上传单份红线图与规划条件文档，验证模型能否提取用地边界、管控指标等核心字段。
- 提交包含多来源数据的测试用例，检查生成的文书是否覆盖所有关联审批要求。
- 查看模型调用日志，确认`maxContext`、`vision`等配置项被正确加载。
- 核对生成内容的字段完整性，确认无项目选址范围、用地规模等关键信息遗漏。
