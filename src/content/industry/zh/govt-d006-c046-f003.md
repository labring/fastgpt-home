# 社会救助与低保审核的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的服务主体包括民政局救助科、街道乡镇民政办、社区居委会与核对中心。日常生成与使用的文档包含低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料、救助审批表，核心字段覆盖家庭人口、收入财产明细、成员关系、审批流程节点。数据来源于低收入人口动态监测平台、居民家庭经济状况核对系统及公安、人社、医保、住建、税务的跨部门共享数据，更新频率为月度，每份申请的材料需匹配对应周期内的最新共享数据。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
月度更新的跨部门数据要求多轮对话需同步最新的核对规则与数据来源，避免使用过期信息生成文书。固定格式的申请文档要求提示词需精准匹配必填字段，避免遗漏家庭收入、财产明细等核心内容。跨部门数据的调取需通过多轮对话逐步确认，防止单次对话加载过多信息导致上下文溢出。同时，错保漏保的风险要求多轮对话需对关键信息进行二次校验，确保生成的文书与实际情况一致。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本的功能规则。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口长度 | 8000–12000 字符 | 该品类文书包含多段家庭信息与跨部门核对数据，需完整加载历史对话与材料片段 |
| `variables` 绑定字段 | 申请编号、家庭地址、人均收入 | 每份低保申请的专属信息需动态插入生成的文书，确保内容精准匹配 |
| 知识库召回上限 | 前 3 条 | 该品类核心文档为固定的5类申请材料，无需过多召回冗余内容 |
| 对话历史保存时长 | 30 天 | 匹配业务数据月度更新的周期，保留对应申请周期内的完整对话记录 |
| `messages` 参数配置 | 追加工具返回的核对数据片段 | 确保工具调用结果同步至对话上下文，避免重新进入页面才显示结果 |
| `chatId` 关联规则 | 绑定对应申请的唯一标识 | 确保每份申请的对话记录与专属材料关联，便于后续复核与归档 |

## 容易做错的三处
- 现象：工具调用结果未在对话框内展示，仅重新进入页面后可见。原因：未在`messages`参数中正确追加工具返回的跨部门核对数据片段，导致对话上下文未完整同步。
- 现象：提示词无法从知识库动态加载使用。原因：未将提示词模板与`variables`参数绑定的申请专属字段关联，或未配置知识库的召回触发条件。
- 现象：生成的救助审批表缺失家庭财产明细字段。原因：未在多轮对话中触发收入财产信息的补全环节，导致上下文未覆盖全部必填字段。

## 怎么确认配好了
- 发起模拟低保申请对话流程，调用跨部门数据核对工具，检查工具返回的结果是否完整展示在对话历史中。
- 调用知识库查询预设的低保申请文书模板，确认提示词是否能动态替换`variables`参数绑定的专属字段并生成对应格式的文档。
- 配置iframe接入参数，检查界面是否切换为中文显示，确认语言配置生效。
- 提取当前对话的链接，确认`chatId`参数正常携带并关联对应模拟申请的唯一标识。
