# 行政处罚案卷办理的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证。单份文档包含执法主体标识、时间戳、当事人信息、违法事实描述、法律条款引用、文书编号等固定字段，影像类数据附带拍摄设备标识与拍摄时长参数。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来明确约束。多来源的结构化、半结构化与非结构化数据混合，要求索引支持多类型内容的统一嵌入适配。每日批量更新的业务数据，需支持增量索引逻辑以避免全量重建带来的计算资源占用。单份文档存在固定关联字段，例如处罚决定书与对应证据清单需绑定关联，索引需支持跨文档关联检索。非结构化的执法记录仪影像需先完成文本转写，才能接入向量嵌入流程，需配置转写后自动触发索引的适配规则。唯一标识类字段需作为元数据存储，用于后续溯源与去重操作。

## 配置怎么定
本配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxToken` | `8192 token` | 本品类核心文书如处罚决定书的平均文本长度在3000-5000字符，预留足够上下文空间 |
| 分块长度 | `800–1200 字符` | 笔录类文档的单段逻辑长度适配该区间，避免语义割裂 |
| 重叠长度 | `100–150 字符` | 保障相邻分块的语义连续性，防止关键信息被截断 |
| 相似度阈值 | `0.75–0.85` | 过滤低关联的执法数据，保留高匹配的违法事实与证据关联 |
| 单次搜索上限 | `前10条` | 案卷办理需精准匹配关联证据，过多结果会增加审核负担 |
| 嵌入模型选择 | 支持国产向量模型 | 本品类执法数据涉及政务信息，需选用符合合规要求的国产模型 |
| `defaultToken` | `2048 token` | 平衡日常检索的上下文需求与计算成本 |

## 容易做错的三处
- 现象：尝试通过mongodb直接管理向量库，执行增删操作后出现索引同步失败或权限报错。原因：FastGPT的向量库管理需通过官方内置接口完成，直接操作底层存储会破坏元数据与向量的绑定关系，导致检索逻辑异常。
- 现象：接入ollama部署的向量模型时，FastGPT返回连接拒绝错误，但使用curl工具测试可正常获取嵌入结果。原因：FastGPT的向量模型调用需适配平台指定的请求格式与认证规则，ollama的默认端口或路径未匹配平台的嵌入请求要求，导致校验失败。
- 现象：执行索引合并操作后，检索结果仍出现重复的证据清单或处罚决定书条目。原因：未配置基于唯一标识字段的去重规则，仅通过文本相似度去重，无法识别同编号的不同文档副本。

## 怎么确认配好了
- 上传单份处罚决定书与关联的证据清单，执行检索操作，验证结果可同时返回对应文档，确认跨文档关联配置生效。
- 触发增量索引任务，查看后台日志显示仅处理当日新增的执法数据，确认增量索引逻辑正常运行。
- 调整相似度阈值后执行检索，观察返回结果的数量变化，确认阈值配置生效。
- 调用向量模型嵌入接口，输入执法记录仪影像转写后的文本，验证返回的嵌入结果无格式错误，确认多模态适配配置正确。
