# 行政处罚案卷办理的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类涉及市场监管、生态环境、交通运输等执法机构的行政处罚全流程数据，日常产出现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、处罚决定书等固定格式文档。数据主要来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，按日更新。核心数据围绕违法事实与处罚决定展开，需形成可追溯的证据链，出错将导致案卷评查不合格或处罚被撤销。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
执法文书的固定格式要求提示词必须匹配现场检查笔录、处罚决定书等文档的字段结构，需明确关联证据类数据。多源数据的实时更新要求对话上下文需绑定当前执法案件的唯一标识，避免跨案件混淆。证据链的可追溯要求多轮对话需保留每一轮的执法信息，确保生成的文书可对应到原始证据。同时，出错后果的严重性要求提示词需覆盖法制审核、送达归档等环节的校验规则，减少合规风险。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 用户问题 | 固定话术模板，包含违法事实、证据类型、目标文书类型 | 匹配执法文书的固定字段与业务逻辑 |
| 上下文窗口大小 | 8000–12000 字符 | 容纳多轮执法对话、多份笔录及证据清单内容 |
| 关联文件范围 | 当前执法案件的全部关联文档 | 确保调用的证据与办案信息仅来自目标案件 |
| 对话角色设置 | 执法办案人员、法制审核人员双角色 | 覆盖办案全流程的不同权限与校验需求 |
| `chatId` 配置 | 绑定当前执法案件的唯一标识 | 确保多轮对话的上下文关联同一案件，避免混乱 |
| 错误重试次数 | 2–3 次 | 应对临时网络或资源波动，不中断办案流程 |
| 对话超时时间 | 600 秒 | 避免因执法文档解析过久中断办案流程 |
| 生成文书最大长度 | 5000 字符 | 符合执法文档的常规篇幅要求 |

## 容易做错的三处
- 对话页上传执法文档时返回503状态码，后台日志显示文件上传成功。原因是上下文窗口配置超出系统承载阈值，文件解析环节触发资源限制。
- 多轮对话生成的处罚决定书缺少证据清单字段。原因是用户问题模板未明确要求关联证据类文档，导致提示词未覆盖证据引用规则。
- 多轮对话上下文丢失，生成的文书与之前的执法信息不匹配。原因是未绑定`chatId`，导致对话流转时未保留案件唯一标识。

## 怎么确认配好了
- 发起包含现场检查笔录引用的测试对话，查看生成的询问笔录是否正确关联该证据。
- 绑定执法案件的唯一标识，发起连续三轮对话，验证`messages`参数随对话流转保留历史信息。
- 验证`variables`参数是否正确传递了案件编号、违法主体等自定义办案变量。
- 上传一份执法相关文档，验证关联文件范围仅加载当前案件的文档，未混入其他案件数据。
