# 行政处罚案卷办理的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常处理的文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，均为固定格式的执法类文书，字段包含违法事实、执法主体、处罚依据、裁量标准、送达信息等，数据结构与执法流程强绑定。

## 这些特征在「模型接入与配置」这一环带来什么约束
执法文书的固定格式要求模型输出必须匹配预设的字段与结构，否则会影响案卷合规性。多源数据的接入需要兼容不同格式的输入，包括结构化办案系统数据、非结构化执法影像转录文本。每日更新的数据要求配置同步机制，确保模型调用时能获取最新的监管与企业信用信息。执法案卷出错会导致处罚撤销、行政复议败诉等严重后果，因此模型输出的严谨性要求较高。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 覆盖单份完整执法案卷的上下文信息，避免因上下文截断丢失违法事实与处罚依据 |
| `maxTokens` | 2000–3000 token | 匹配单份执法文书的生成长度，确保所有必填字段均能完整输出 |
| `temperature` | 0.3–0.5 | 降低生成随机性，保障执法文书的严谨性与格式一致性 |
| `AIPROXY_API_ENDPOINT` | 按接入模型的官方文档配置 | 匹配模型的标准API调用路径，确保请求能正常送达 |
| `AIPROXY_API_TOKEN` | 填写平台分配的有效密钥 | 完成身份验证，避免因认证失败导致调用失败 |
| `vision` | 开启 | 支持执法记录仪影像的转录与内容提取，辅助生成现场检查笔录等依赖影像信息的文档 |

## 容易做错的三处
- 调用知识库时出现`invalid configuration parameter name "hnsw.max_scan_tuple"`报错。原因是配置了非标准的向量库参数，未使用FastGPT兼容的参数命名规则。
- 选择qwen-plus模型开启输出思考后无思考过程返回。原因是未正确配置模型的思考输出触发参数，或预设的输出格式未匹配模型要求。
- 接入oneapi后无法获取模型列表。原因是调用了`/v1/model/list`作为API端点，正确的接口路径应为`/v1/models`。

## 怎么确认配好了
- 发起单份执法文书起草测试，检查输出内容是否包含现场检查笔录、处罚决定书等要求的文档结构与必填字段。
- 查看FastGPT v4.17.0的API调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`配置无格式错误，无401或404类报错。
- 测试知识库召回功能，确认召回的国家企业信用信息公示系统数据与执法办案系统的违法事实匹配度符合要求。
- 调整`temperature`参数至0.3–0.5区间，检查生成的执法文书是否保持格式统一且无冗余内容。
