# 行政处罚案卷办理的文书与材料起草：部署与升级

## 这个品类的数据长什么样
本品类的核心文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，均具备固定格式字段。数据来源涵盖行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。单份执法案卷包含结构化字段与非结构化音视频、图片附件，字段需关联违法主体、违法事实、裁量依据、处罚内容等核心信息，且需与执法过程中的实时采集数据保持一致。

## 这些特征在「部署与升级」这一环带来什么约束
本品类的多源数据来源要求部署时需配置多数据源的权限隔离规则，避免生产系统与FastGPT实例的业务冲突；每日更新的执法数据要求升级过程中保留增量同步的定时任务配置，防止中断案卷数据的实时获取；固定格式的文书模板要求部署时预设字段映射规则，确保生成的文书符合执法案卷的归档要求；较高的出错后果要求升级时需保留回滚机制，避免因配置变更导致执法流程中断。此外，内网部署的场景要求配置项需适配执法机构的内网访问限制，保障数据安全。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定，适配行政处罚案卷办理的专属业务场景。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–15 个 | 适配每日高频的执法文书查询与生成请求，避免数据库连接耗尽，保障多执法终端同时访问的稳定性 |
| `MONGODB_URI` | 指向行政执法办案系统的专用只读副本集地址 | 用于存储执法记录仪影像、证据清单等非结构化数据，与业务生产库隔离，防止误操作影响执法业务 |
| `REDIS_URL` | 绑定本地缓存实例，配置 600 秒过期时间 | 缓存每日更新的国家企业信用信息公示系统查询结果，减少重复调用的频次与延迟 |
| `STORAGE_S3_ENDPOINT` | 指向执法机构内部对象存储服务地址 | 存储生成的处罚决定书、送达回证等归档文件，符合案卷归档的存储规范与权限要求 |
| `FE_DOMAIN` | 配置为执法内网的访问域名 | 限制前端访问范围，保障执法数据仅在内网环境中流转，符合执法机构的安全管理要求 |

## 容易做错的三处
- 现象：尝试源码部署时因服务器不支持Docker无法完成初始化。原因：未按照非Docker部署的文档配置依赖包与运行参数，缺少必要的系统组件。
- 现象：本地镜像打包时出现 WARNING: current commit information was not captured by the 报错。原因：未在项目根目录初始化Git仓库或未提交当前代码，导致构建脚本无法获取版本元数据。
- 现象：对接funasr进行笔录语音转写时，无法正常识别执法记录仪的音频文件。原因：未配置funasr的模型路径与采样率参数，与执法记录仪的音频格式不兼容。

## 怎么确认配好了
- 执行FastGPT内置的数据源连通性测试脚本，验证`MONGODB_URI`、`PG_URL`等配置的连接状态，确认无超时或权限报错。
- 触发一次模拟执法文书生成任务，检查生成的文档是否包含现场检查笔录、违法事实等预设字段，核对字段映射是否与执法业务要求一致。
- 查看`REDIS_URL`绑定的缓存实例监控面板，确认每日更新的公示系统数据已被正常缓存，过期时间符合配置要求。
- 测试对接funasr的语音转写功能，上传执法记录仪的音频文件，确认转写结果可正常同步至笔录模板中。
