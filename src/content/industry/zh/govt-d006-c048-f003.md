# 行政许可审批的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统、电子证照库，每日更新。日常处理的文档包含办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书、许可证照，文档结构多包含法定依据、办理条件、申请材料清单、审批流程等固定字段，无自定义弹性字段，所有字段均符合法定格式要求。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据每日更新的要求，使得多轮对话需关联实时更新的事项库与审批系统数据，避免使用过时的法定依据或办理条件。固定结构的文档要求提示词需严格匹配办事指南、审批文书的法定字段，确保每段内容对应法定办理要求。跨部门电子证照的调取校验，需要在多轮对话中保留历史申请材料的上下文，避免重复核对同一信息。法定许可事项的边界要求，对话需严格限定在当前审批事项范围内，防止超出许可范畴生成内容。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| chatId | 固定绑定当前审批事项的唯一标识 | 确保多轮对话上下文不混淆不同审批申请 |
| 最大上下文 | 8000–12000 字符，保留前10轮对话 + 最新3份申请材料 | 行政许可文书多为长文本，需覆盖完整申请与审批历史 |
| messages | 按审批流程节点拆分，每轮仅保留当前环节所需上下文 | 避免冗余上下文占用token配额，保障长对话流畅性 |
| variables | 预设法定字段变量，如事项名称、申请主体统一社会信用代码 | 确保生成的文书严格匹配法定必填项 |
| 问题优化 | 开启，按官方办事指南的法定表述优化生成内容 | 行政许可文书需符合官方规范表述要求 |
| 最大响应token | 2000–3000 token | 覆盖行政许可文书的法定依据、办理要求、审批意见等完整内容 |

## 容易做错的三处
- 开启输入引导并配置自定义词库地址后，调试预览界面对话触发报错。原因是自定义词库未适配行政许可事项的法定术语格式，导致词库加载校验失败。
- 设置最大响应token为3000以上，特定审批事项相关问题的回复长度仅为200。原因是多轮对话上下文占用了大部分token配额，剩余额度不足以支撑预设的最大响应长度。
- 对话过程中无法将审批相关信息添加至知识库。原因是未开启知识库的实时内容追加功能，或未在对话配置中绑定对应知识库的变量。

## 怎么确认配好了
- 核对`chatId`的绑定逻辑，确认每个独立审批申请对应唯一的对话上下文标识。
- 生成一份标准行政许可文书，核对生成内容与对应办事指南的法定要求一致。
- 查看对话过程中的token消耗情况，确认响应长度符合预设的token配额要求。
- 测试将新的审批事项数据添加至知识库，确认数据成功同步至指定存储位置。
