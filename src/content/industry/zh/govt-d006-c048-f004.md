# 行政许可审批的文书与材料起草：工作流编排

## 这个品类的数据长什么样
FastGPT v4.17.0 针对本场景的工作流编排提供了标准化适配。本品类的数据覆盖政务服务中心、行政审批局等主体的日常审批相关文档，包括办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书、许可证照。数据来源为全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统及电子证照库，更新频率为每日。文档按法定许可事项分类，包含事项依据、办理条件、申请材料清单等固定字段，电子证照类数据包含统一的证照编号、有效期等标准字段。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据按法定许可事项分类，要求工作流编排需按单个事项绑定对应的数据来源，避免跨事项混用数据。每日更新的频率要求工作流节点需定时拉取最新的事项清单与证照数据，防止使用过期依据。文档包含固定模板字段与动态填充内容，工作流需区分模板生成与动态数据注入的环节。跨部门调取证照的流程需对接多套系统，工作流需配置多节点的权限校验与数据流转规则。高风险的出错后果要求工作流嵌入失败回退与告警节点，确保超期或错误流程被及时拦截。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发节点 | 按法定许可事项分类触发 | 匹配本品类按事项分类的数据结构，避免跨事项数据混用 |
| 定时拉取周期 | 24小时 | 匹配数据每日更新的频率，确保工作流使用最新的事项与证照数据 |
| 变量绑定规则 | 按事项字段绑定`variables` | 确保动态内容准确注入文书模板，匹配文档的固定与可变字段结构 |
| 单次校验上限 | 前10条申请材料 | 按实测标定，避免单轮处理过载 | 匹配核对申请材料与清单的核心环节，控制单轮处理量 |
| 工具调用参数填充规则 | 提取申请内容与事项清单字段 | 匹配行政许可审批需逐项匹配申请材料与办理条件的业务要求 |
| 失败回退节点 | 配置`nodeId`关联告警与回滚环节 | 符合高风险出错后果的约束，及时拦截错误流程 |

## 容易做错的三处
- 现象：工作流节点执行后返回字段为空，原因：未按事项分类绑定`variables`，导致动态数据未正确注入模板。
- 现象：无法导出或导入工作流配置，原因：未正确配置节点间的依赖关系，导致导出时丢失关联数据。
- 现象：循环体节点无法按预期重复执行，原因：未正确关联`nodeId`，导致循环触发条件未匹配业务逻辑。

## 怎么确认配好了
- 触发对应事项的测试申请，检查工作流是否自动拉取该事项的最新办事指南与材料清单。
- 查看定时拉取日志，确认数据更新频率符合设定的周期。
- 模拟流程失败场景，检查是否触发预设的告警与回滚环节。
- 生成审批文书，检查`variables`绑定的动态字段是否正确填充为申请内容与事项数据。
