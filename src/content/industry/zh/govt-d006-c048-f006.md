# 行政许可审批的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
这个品类的日常文档包含办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书、许可证照。数据来源为全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统、电子证照库，更新频率为每日。文档字段包含事项编码、设定依据、办理条件、申请材料清单等法定要求的内容，需严格匹配事项边界与法定依据，确保内容符合政务审批的合规要求。

## 这些特征在「引用来源与溯源」这一环带来什么约束
这些数据与文档特征为引用来源与溯源环节带来明确约束。多源且每日更新的数据要求溯源环节需实时拉取最新的事项清单与证照数据，避免引用过期的法定依据。法定文书的字段要求严格，需精准匹配事项编码与设定依据，不能引入非法定来源的内容。跨部门系统的数据调用需保证稳定性，否则会影响审批文书的生成与溯源核对，进而可能导致超期办结或许可被复议撤销。整体约束要求溯源环节的配置需兼顾合规性、实时性与准确性，确保每一处引用都可追溯至官方数据源。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配行政许可文书中法定依据与申请材料的长度，确保引用内容完整且不超出上下文限制 |
| `responseData` | 仅返回事项库、电子证照库的源数据 | 过滤非法定来源的内容，符合政务审批的合规要求 |
| `detail` | 开启 | 保留引用来源的字段信息，如事项编码、发布日期，便于后续溯源核对 |
| 匹配结果上限 | 前8条 | 覆盖常见行政许可事项类型，避免遗漏关键依据 |
| 上下文缓存时长 | 600 秒 | 匹配数据每日更新的频率，确保调用的是最新的官方数据 |

## 容易做错的三处
- 生成的审批文书中附带无法隐藏的引用链接，原因是未正确配置`responseData`的返回过滤规则，保留了非必要的链接字段。
- 配置变量引用后温度设置控件消失，原因是部分版本中变量引用与模型参数配置的联动逻辑异常，未正确加载参数设置界面。
- 溯源结果条数不足，无法覆盖全部相关法定依据，原因是未调整匹配结果上限参数，默认取值过少导致关键依据被过滤。

## 怎么确认配好了
- 上传一份行政许可办事指南，触发文书起草流程，检查生成内容中是否附带事项编码、发布日期等溯源字段。
- 查看系统配置日志，确认`quoteMaxToken`的取值符合预设的800–1200 token区间。
- 测试跨部门数据调用，验证电子证照库的源数据是否正常返回，无报错或缺失。
- 调整匹配结果上限参数，确认生成的溯源结果条数可随配置变化。
