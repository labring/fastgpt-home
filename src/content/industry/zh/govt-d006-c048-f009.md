# 行政许可审批的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统及电子证照库，更新频率为每日。日常文档包含办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书与许可证照，数据字段涵盖事项编码、申请材料清单、法定依据、办理条件等，需严格匹配法定许可事项边界，关联跨部门的电子证照与证明材料。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源覆盖多部门实时更新系统，需确保模型调用时能同步获取最新政务数据，因此配置需支持高频且稳定的调用链路，避免超期办结。文档结构与内容需严格匹配法定要求，模型生成的文书不可超出许可事项边界，因此需限制生成范围与随机性，防止许可被复议撤销。跨部门电子证照库包含非结构化的图片与文本数据，配置需兼顾文本解析与视觉识别能力，适配不同格式的证明材料。每日更新的数据特性要求配置支持快速上下文刷新，避免因数据滞后导致文书错误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本进行说明
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配政务文书的长上下文需求，覆盖办事指南、申请材料等多份关联文档 |
| `maxTokens` | 2000–3000 token | 满足行政许可文书的标准篇幅，避免生成超出法定格式的内容 |
| `quoteMaxToken` | 1500 token | 限定引用政务事项库数据的长度，确保引用内容准确且不冗余 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具调取电子证照或核对事项清单，适配跨部门数据需求 |
| `vision` | 开启 | 适配电子证照的图片格式解析，满足跨部门调取的视觉材料处理需求 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保文书内容严格匹配法定要求与事项清单 |
| `AIPROXY_API_ENDPOINT` | 对应部署的大模型服务地址 | 用于接入第三方大模型，适配政务场景的合规调用需求 |
| `AIPROXY_API_TOKEN` | 专属鉴权密钥 | 保障模型调用的安全性，符合政务数据的访问管控要求 |

## 容易做错的三处
- 现象：通过API调用批量执行节点时，部分大模型调用任务未完成，在线调试流程可正常执行。原因：API调用未正确配置批量任务的上下文同步参数，或未设置合理的超时阈值，导致任务执行链路中断。
- 现象：无法查询到大模型调用的requestid，无法定位调用异常。原因：未开启模型调用的日志采集配置，或未在接口返回字段中正确提取requestid标识。
- 现象：接入ollama视觉模型时，无法解析图片格式的电子证照材料。原因：未开启`vision`配置项，或未正确配置模型的视觉推理接口地址。

## 怎么确认配好了
- 发起单次模型调用，核对返回的文书内容是否包含对应行政许可事项的法定依据与申请材料要求。
- 查看模型调用日志，确认是否能正常记录requestid并关联至对应任务。
- 测试批量执行节点，通过API与在线调试分别触发，核对任务完成状态是否一致。
- 上传电子证照图片，确认模型是否能正确解析图片内容并关联至对应申请材料字段。
