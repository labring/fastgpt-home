# 财政支出绩效评价的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据来自预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查，更新频率为年度。日常产出的文档包含绩效目标表、自评表、绩效评价报告、佐证材料清单与整改报告。数据字段围绕财政资金使用的绩效目标、实际产出、效果验证及整改情况展开，无统一固定的单位要求，需匹配对应项目的具体申报与执行标准。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
年度更新的低频属性要求接口调用无需高频轮询，可配置固定周期触发。多源异构的数据来源需要接口支持批量拉取不同系统的结构化与非结构化数据。文档类的材料起草需求要求接口返回的数据需包含完整的字段映射，避免缺失关键佐证信息。单次处理的文档体量较大，需预留足够的请求超时时间，防止因数据拉取不完整导致起草失败。同时，数据核验环节依赖接口返回的资金支付与绩效目标的对应关系，接口需保证数据的准确性，否则会引发后续评分偏差或预算调整风险。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` |  Bearer {对接系统专属密钥} | 符合政务系统的身份验证规范，确保接口访问的安全性 |
| 请求超时时间 | 600 秒 | 适配多源数据拉取的低频高体量需求，避免因数据未完全返回导致调用失败 |
| `variables` | 绑定绩效年度、预算单位编码等固定参数 | 简化重复配置，确保每次调用的业务场景匹配当前起草任务 |
| `responseData` |  提取结构化字段与关联佐证材料路径 | 直接映射到文书起草的模板字段，减少二次数据处理的工作量 |
| 代理配置 | 按实测标定的用户名、密码与端口 | 适配内网部署场景下的互联网访问需求，满足代理身份校验的要求 |

## 容易做错的三处
- 现象：调用外部财政系统接口返回502状态码，在其他测试工具中调用正常。原因：未正确配置`Authorization`参数，或请求头的密钥格式不符合对接系统的校验规则。
- 现象：接口调用返回的`responseData`字段缺失，导致文书模板无法填充对应内容。原因：未在配置中指定提取指定业务字段，或拉取的数据与模板字段映射不匹配。
- 现象：内网部署场景下无法访问外部系统，代理配置未生效。原因：未配置代理的用户名与密码参数，仅填写IP和端口导致身份校验不通过。

## 怎么确认配好了
- 发起单次测试调用，确认接口返回的`responseData`包含当前业务场景所需的全部字段。
- 核对`Authorization`参数的配置是否与对接系统的身份校验规则一致。
- 在内网环境下，测试代理配置是否可以正常建立连接，访问外部目标接口。
- 调用接口获取数据后，验证数据与预设的文书模板字段可以正确匹配。
