# 财政支出绩效评价的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查。数据更新频率为年度周期。日常产出文档包含绩效目标表、自评表、绩效评价报告、佐证材料清单、整改报告，文档结构多包含绩效指标明细、资金使用关联条目、佐证材料关联标识、整改事项清单等字段，无固定统一格式模板，需结合项目实际调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
年度更新的数据规模存在波动，需配置适配不同上下文长度的参数；多源异构数据需模型准确关联资金支出与绩效目标，对工具调用的逻辑合理性要求较高；文档格式不统一，需模型具备灵活的文本解析能力；佐证材料的核验需结合多来源数据交叉验证，需配置合理的上下文引用规则；绩效评价报告的正式性要求生成内容需符合官方文档规范，需限制生成的自由度过高。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配年度项目文档的总上下文长度，覆盖多源数据与报告撰写需求 |
| `maxTokens` | 2000–3000 token | 满足单篇绩效评价报告的生成长度需求，避免输出截断 |
| `quoteMaxToken` | 1500–2000 token | 限制引用的佐证材料与业务数据的总长度，确保上下文聚焦 |
| `toolChoice` | auto | 允许模型自行判断是否调用工具获取资金数据或佐证材料，适配多源数据关联需求 |
| `temperature` | 0.3–0.5 | 平衡生成内容的严谨性与灵活性，符合绩效报告的正式性要求 |
| `AIPROXY_API_TOKEN` | 按所选模型服务商提供的有效令牌填写 | 完成模型调用的身份验证，保障请求合法性 |

## 容易做错的三处
- 出现`模型流响应为空`报错。原因是配置的`maxContext`参数设置过小，无法加载完整的年度项目数据，导致模型无法生成有效输出。
- 调用多模态模型处理图片类佐证材料时出现无法下载图片的错误。原因是未配置适配的网络访问参数，导致模型无法获取外部佐证图片资源。
- 固定配置工具调用规则，未设置为`auto`时，模型无法根据实际业务需求灵活关联多源数据，导致绩效评价逻辑僵化。

## 怎么确认配好了
- 提交单份年度项目的完整数据，检查模型生成的绩效自评表内容是否覆盖所有核心字段，无明显截断。
- 触发工具调用测试，确认模型可根据输入的绩效指标，自主调用工具获取对应资金支付数据。
- 查看模型输出的绩效评价报告，确认引用的佐证材料信息与输入数据一致，无逻辑冲突。
- 测试不同规模的项目数据输入，确认`maxContext`参数可适配数据量波动，无上下文溢出报错。
