# 财政支出绩效评价的文书与材料起草：部署与升级

## 这个品类的数据长什么样
本品类数据来自预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查，更新频率为年度。日常产出的文档包含绩效目标表、自评表、绩效评价报告、佐证材料清单与整改报告，文档字段涵盖项目编号、资金额度、绩效指标完成情况、佐证材料关联项等，部分字段采用项目预设的量化单位，如项、人次等。数据多为结构化与非结构化混合格式，部分文档需关联多来源的佐证材料，需适配多源数据的统一解析与存储。

## 这些特征在「部署与升级」这一环带来什么约束
年度更新的特性要求部署时配置支持批量导入的定时任务，适配年度绩效数据的集中上传与处理。多类文档的混合处理需要配置兼容不同格式的文件存储与解析规则，避免不同文档类型的字段映射冲突。绩效评价相关数据涉及财政管理流程，部署环节需确保数据存储的合规性配置，同时升级时需保留历史评价数据的版本兼容性。此外，多主体协同的场景要求配置跨角色的权限控制，适配财政局、预算单位等不同使用方的访问权限，避免敏感数据泄露。

本配置指南适用于FastGPT v4.17.0版本。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://localhost:27017/fastgpt` | 财政支出绩效评价数据量随年度项目规模增长，需稳定的文档型数据库存储绩效报告、自评表等非结构化数据 |
| `REDIS_URL` | `redis://localhost:6379/0` | 用于缓存高频访问的绩效指标数据与用户会话，需低延迟的内存存储 |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` | 用于存储佐证材料、整改报告等大体积文件，需适配本地私有部署的存储节点 |
| `DB_MAX_LINK` | `20–30` | 财政数据批量导入时需维持稳定的数据库连接数，避免连接耗尽导致的导入失败 |
| `FE_DOMAIN` | `http://localhost:3000` | 用于生成文件访问令牌的回调地址，需匹配前端服务的部署域名 |
| `FILE_TOKEN_KEY` | `自定义随机字符串` | 用于签署文件访问令牌，保障绩效相关文档的访问安全 |

## 容易做错的三处
- 现象：导入绩效评价相关插件时提示`internal server error`。原因：未正确配置`MONGODB_URI`或`REDIS_URL`参数，导致数据库连接失败。
- 现象：升级版本后模型厂商图标无法加载。原因：未更新静态资源映射配置，或`STORAGE_S3_ENDPOINT`参数指向的存储服务未正常启动。
- 现象：无法查看本地部署的知识库磁盘占用情况。原因：未开启系统的磁盘监控插件，或未配置`FILE_TOKEN_KEY`参数导致文件存储路径无法被正确读取。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`与`REDIS_URL`参数指向的服务可正常连通。
- 上传一份绩效自评表与佐证材料的压缩包样本，确认`STORAGE_S3_ENDPOINT`配置的存储服务可正常接收并存储文件。
- 访问`FE_DOMAIN`指定的前端地址，确认页面可正常加载且无配置错误提示。
- 执行批量数据导入测试，导入10条绩效项目数据，确认`DB_MAX_LINK`参数的连接数配置可支撑导入流程。
