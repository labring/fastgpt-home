# 道路运输经营许可的文书与材料起草：引用来源与溯源

以下配置基于FastGPT v4.17.0版本的功能逻辑。

## 这个品类的数据长什么样
本品类涉及的业务数据来源包括道路运政管理系统、全国道路运输车辆动态信息公共服务平台、车辆和从业人员数据库，更新频率为每日。日常处理的文档包含经营许可申请、车辆技术档案、驾驶员从业资格材料、安全生产管理制度、道路运输经营许可证，不同文档的核心字段差异明显，如车辆技术档案需包含车辆基本参数，驾驶员材料需标注从业资格相关信息，整体文档结构与业务审批流程强绑定。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散且每日更新，引用环节需确保检索覆盖多系统数据，同时保证内容与最新业务状态一致。不同文档的核心字段差异明显，需精准匹配对应文档的业务场景，避免跨文档的无效引用。审批环节对溯源准确性要求极高，错误引用或过时数据可能导致许可被退回、企业无法运营，因此需严格限定引用范围与更新频率，同时明确标记来源信息以支持核验。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 道路运输经营许可相关的单份文档内容多在800到1200token区间，避免车辆资质、从业资格等关键信息被截断 |
| `responseData` | 开启 | 需直接输出知识库原文片段，满足审批环节核验原始材料的溯源需求 |
| 单次检索上限 | 前10条结果 | 覆盖道路运政、车辆动态平台等多源数据，兼顾召回全面性与上下文长度控制 |
| 数据源同步频率 | 每日更新 | 匹配业务数据日更频率，确保引用内容与最新审批状态一致 |
| `detail` | 开启来源标识 | 在输出中标记文档所属系统、更新时间，符合交通运输审批的溯源核查要求 |

## 容易做错的三处
- 现象：AI输出的起草内容未附带知识库原文片段，仅显示生成的摘要。原因：未开启`responseData`配置项，仅返回大模型生成的加工内容，无法满足溯源核验需求。
- 现象：检索结果仅覆盖单一数据来源，未包含车辆动态平台的信息。原因：单次检索上限设置过低，未覆盖多源数据的召回要求。
- 现象：引用的车辆年检信息与最新状态不符。原因：数据源同步频率设置高于每日更新，导致引用了过时的业务数据。

## 怎么确认配好了
- 发起道路运输经营许可申请材料起草的提问，检查输出内容是否附带知识库原文片段。
- 查看检索结果列表，确认覆盖至少两类及以上的业务数据来源。
- 验证引用内容的更新时间与当前业务数据的日更节奏一致。
- 调整`quoteMaxToken`参数，确认输出未出现核心资质信息被截断的情况。
