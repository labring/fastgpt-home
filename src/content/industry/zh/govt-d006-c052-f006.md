# 部门决算与财务报告的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
本品类的核心数据来自预算管理一体化系统、国库集中支付系统、会计核算系统、资产管理系统，更新周期为年度一次。日常产出的文档包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告，遵循财政系统统一规范，包含收支明细科目、对应金额、资产负债条目、预算执行差异说明等固定字段，单份年度完整文档需关联多系统原始数据完成编制。

## 这些特征在「引用来源与溯源」这一环带来什么约束
年度集中更新的特性导致决算编制阶段需同时处理多系统的历史数据与当期汇总报表，对溯源的批量关联能力提出要求。固定的文档结构与字段规范，要求引用溯源需精准匹配科目、金额等具体条目，避免泛化匹配导致的口径错误。多系统数据源的关联需求，要求溯源环节能同时关联不同系统的原始数据条目，保障账表核对的准确性。出错后果直接关联决算被退回、审计风险等，要求溯源结果的可信度与精准度需满足财政管理的严格要求。

## 配置怎么定
以下为FastGPT v4.17.0版本下的配置建议：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1500–2000 token | 适配决算报告单段引用的长度需求，避免截断关键科目与数据条目 |
| `responseData` | 仅返回关联字段 | 匹配决算报告需精准对应收支、资产等模块的要求，过滤无关内容 |
| `detail` | 开启 | 保障溯源时返回系统来源与具体数据条目，满足审计核对的溯源需求 |
| 单次搜索上限 | 前6条 | 覆盖下级单位汇总后的多份报表引用需求，避免遗漏关联数据 |
| 最大上下文 | 8000–10000 字符 | 容纳年度决算的完整关联数据块，保障多文档联合检索的完整性 |
| 分块重叠长度 | 150 字符 | 避免固定字段被分块截断，确保溯源时能匹配到完整的科目与金额组合 |

## 容易做错的三处
- 现象：检索结果仅返回1条文档引用，界面提示知识库引用(1条)。原因：未调整单次搜索上限配置，默认取值限制了召回数量，无法覆盖汇总后的多份下级单位报表。
- 现象：导入决算报告后引用字段为空，无法匹配对应系统数据。原因：分块长度设置过小，将收支科目与金额拆分至不同块中，导致溯源时无法关联完整字段。
- 现象：模型测试提示错误，强行运行后溯源结果无系统来源说明。原因：未开启`detail`参数，未配置`responseData`的关联字段映射，导致无法提取数据来源信息。

## 怎么确认配好了
- 上传单份年度决算报表，触发引用溯源流程，检查返回的引用列表是否包含对应系统的来源标识。
- 导入多份下级单位的决算报表，核对召回的引用数量是否符合单次搜索上限的设置。
- 调整`quoteMaxToken`至较小取值，验证长段落引用是否被完整保留或按要求截断。
- 查看系统日志，确认检索过程中关联了预算管理一体化系统、国库集中支付系统等对应数据源的字段。
