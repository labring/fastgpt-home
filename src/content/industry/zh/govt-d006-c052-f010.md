# 部门决算与财务报告的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来源为预算管理一体化系统、国库集中支付系统、会计核算系统与资产管理系统，更新频率为每365天一次的年度周期。日常涉及的文书与材料包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告等，单篇文档长度通常为8000字符以内，包含固定格式的收支明细字段、单位金额字段、差异说明文本块，需匹配统一的财政规范字段与单位要求，部分报表需汇总下级单位的对应数据。

## 这些特征在「知识库检索与召回」这一环带来什么约束
年度更新的低频数据要求知识库仅在决算周期内触发全量刷新，避免无效更新占用资源。固定格式的字段与统一财政规范要求检索召回的文档需严格匹配专业术语与字段定义，防止出现口径错误，进而引发决算报表被退回或审计问题。需汇总下级单位数据的场景要求检索结果可按单位维度筛选，确保召回的历史数据与当前主体层级匹配。金额与明细字段的精确性要求检索召回的参考文档需保留原始数值与单位，避免模糊匹配导致的信息偏差。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配财政专业术语与精确字段，避免低相似度的无关文档混入，降低口径错误风险 |
| `limit` | 前10条 | 控制单轮检索的上下文长度，适配部门决算文档的单篇篇幅与系统上下文限制 |
| `searchMode` | 高精度模式 | 针对固定格式的报表字段与官方术语优化匹配逻辑，提升召回准确性 |
| `usingReRank` | 开启 | 对初始召回结果按相关性二次排序，修正模糊匹配带来的偏差 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展财政相关专业术语，匹配决算文档中的标准化表述 |
| `collectionIds` | 绑定本级及下级单位的专属知识库集合，总容量不超过1000 MB | 确保仅检索对应主体的历史决算数据，避免跨单位无关数据干扰 |

## 容易做错的三处
- 触发搜索时出现“当前分组 default 下对于模型 gpt-4o-mini 无可用渠道”报错。原因是未在对应分组中配置该模型的调用渠道，或检索后调用的模型与分组绑定的模型不匹配。
- 本地部署后上传决算文档，数据处理步骤显示为空。原因是未正确配置文档解析的依赖环境，或上传的文件格式未被系统支持的决算文档格式覆盖。
- 检索召回的图片链接在AI回复中显示为“input an image”。原因是未开启知识库图片外链的直接渲染配置，或系统未正确解析图片的可访问路径。

## 怎么确认配好了
- 手动输入一条包含财政决算专业术语的测试问题，核对检索结果的文档来源是否为绑定的专属知识库集合。
- 调整`similarity`参数区间，验证召回结果的相关性是否符合预期，确认无无关文档混入。
- 开启`usingReRank`后对比重排前后的结果顺序，确认二次排序功能生效。
- 上传一份测试用的部门决算报表文档，验证数据处理流程是否正常完成，无空数据情况。
