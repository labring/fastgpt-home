# 部门预算编制的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
通常的数据来源包括预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知。年度更新一次，日常生成的文档包含部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复。文档字段通常包含单位编制数、人员经费标准、项目支出明细、绩效指标值等，单位多为万元、人。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的数据来源分散且涉及财政专用口径，年度更新的节奏要求接口调用需适配年度预算编制的时间窗口。多源数据的字段差异，需要在请求中通过`variables`传递统一的字段映射规则，确保不同系统的数据格式匹配。财政数据的敏感性要求`Authorization`参数需采用符合内部系统规范的鉴权方式，避免权限泄露。汇总类文档的数据量较大，接口单次请求的返回限制需匹配数据规模，防止传输超时或截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 采用财政内部系统指定的Bearer Token格式，有效期匹配预算编制周期 | 符合财政系统的鉴权规范，避免权限失效中断预算流程 |
| `variables` | 传递单位编制数、项目支出明细、绩效指标等字段的映射键值对 | 统一多源异构数据的字段格式，确保生成文书的字段准确性 |
| `responseData` | 仅提取预算草案、绩效目标表的核心字段 | 过滤冗余数据，降低传输与解析的开销 |
| 请求超时时间 | 600–1200 秒 | 适配财政系统内部数据查询的平均响应延迟 |
| 请求重试次数 | 2–3 次 | 应对财政系统临时波动导致的请求失败 |
| 返回数据格式 | JSON 格式 | 适配FastGPT v4.17.0的解析规则，便于后续文书生成调用 |

## 容易做错的三处
- 现象：接口返回401未授权错误，或请求被财政系统拦截。原因：未正确配置`Authorization`参数，采用了不符合财政系统要求的鉴权方式。
- 现象：生成的预算文书字段缺失或数值错误。原因：未通过`variables`传递准确的字段映射规则，导致多源数据的字段不匹配。
- 现象：接口请求超时或返回数据被截断。原因：未设置合理的请求超时时间，且未限制返回数据的字段范围，超出系统传输阈值。

## 怎么确认配好了
- 调用测试接口，查看返回的鉴权状态码，确认`Authorization`参数配置符合目标财政系统的要求。
- 导出请求的`variables`参数，核对传递的字段与财政系统要求的文档字段是否一致。
- 模拟单次请求，检查返回的`responseData`是否仅包含所需的核心文档字段，无冗余数据。
- 观察接口调用的响应时长，确认未超出预设的超时时间范围。
