# 部门预算编制的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
部门预算编制相关的数据通常来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知。日常处理的文档包含部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等，部分文档为结构化表格格式，包含人员编制数、项目经费额度、绩效指标等字段，单位多为万元、人。数据更新频率为年度，仅在年度预算编制周期内完成全量更新与汇总。

## 这些特征在「向量模型与索引」这一环带来什么约束
部门预算编制的数据特征对向量模型与索引环节带来多重约束。年度性的全量更新要求索引流程适配批量数据处理，避免单次索引超时。结构化表格类文档需保障分块不拆分单元格内容，防止字段信息断裂。多源数据的跨库关联需求要求索引支持跨系统数据的统一向量嵌入，同时需避免不同来源的同名称字段混淆。专业术语与固定单位的存在，要求召回结果需匹配语义精度与格式一致性，确保审核环节可直接引用有效内容。

## 配置怎么定
基于FastGPT v4.17.0版本的界面逻辑，以下是针对部门预算编制场景的向量模型与索引配置建议：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配部门预算文档中单个项目或测算项的完整内容长度，避免拆分跨字段段落 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的关联信息，防止预算项目的上下文断裂 |
| 相似度阈值 | 0.75–0.85 | 适配预算编制文档中专业术语的语义匹配精度，减少无关的历史决算或非预算类内容召回 |
| defaultToken | 4096 | 匹配预算文档的平均token长度，保障单轮检索上下文可覆盖完整的项目申报或测算内容 |
| 单次搜索上限 | 前 6 条 | 覆盖下属单位上报的常规预算条目数量，避免遗漏关键申报数据 |
| 重排 | 按实测标定 | 适配预算数据的结构化特征，优化召回结果的排序优先级 |

## 容易做错的三处
- 界面显示分块数与实际索引段数不符，表现为上传时显示8段，后续变为13段且存在重复条目。原因是分块重叠长度设置过高，且未开启文档去重配置，导致同一段内容被多次拆分索引。
- 升级版本后无法检索到原有文档内容，表现为历史查询无匹配结果。原因是新版本的向量模型嵌入维度发生变更，原有索引未重新生成，需重新执行全量索引。
- Excel格式的预算测算表索引结果错误，表现为检索到的内容字段缺失或单位混乱。原因是未开启Excel结构化解析配置，导致表格单元格内容被错误拼接为无意义段落。

## 怎么确认配好了
- 上传单份典型文档（如人员经费测算表），查看分块预览界面，确认每个分块包含完整的单条测算内容，无字段拆分断裂。
- 执行跨源检索测试，输入包含下属单位预算条目关键词的查询，确认召回结果覆盖预设的搜索上限数量，无明显重复条目。
- 升级版本后，对全量历史文档执行重新索引操作，验证检索结果与升级前一致。
- 上传Excel格式的预算文档，查看索引后的片段，确认单元格内容按行列顺序完整保留，无单位或字段混乱。
