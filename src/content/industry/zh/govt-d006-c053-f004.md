# 部门预算编制的文书与材料起草：工作流编排

## 这个品类的数据长什么样
本品类的数据主要来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部年度预算编制通知。数据更新节奏为年度一次，对应文档包含部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等。文档字段通常包含人员编制数、项目经费额度、绩效量化指标、预算周期等，单位多为万元、人、项目个数。

## 这些特征在「工作流编排」这一环带来什么约束
年度更新的数据特征要求工作流每年需同步最新的财政部编制规则，避免适配过时口径。多源数据来源要求工作流配置跨系统调用节点，需明确各数据源的调用权限与格式转换逻辑。多类型文档与固定字段要求工作流保留统一上下文，确保不同环节的文书起草能复用一致的基础数据。耗时环节集中的特征要求工作流拆分测算、审核、汇总等独立节点，便于分步优化与异常处理。本环节发生在年度资金安排前，聚焦申报与资金安排的规划工作，需严格匹配年度预算周期要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定预算管理一体化系统、人员编制系统的指定字段 | 确保工作流各节点复用统一的基础数据，避免数据不一致 |
| `nodeId` | 按“部门预算-测算-审核-汇总”的顺序分配唯一ID | 便于工作流调试与节点间数据流转 |
| 工具调用超时时间 | 600 秒 | 覆盖跨系统调取历史决算、项目库数据的常规耗时 |
| 批量处理下属单位预算上限 | 前 20 家 | 适配多数主管部门的下属单位数量规模，避免单次请求过载 |
| 上下文保留长度 | 800–1200 字符 | 匹配部门预算编制文档的核心字段长度，确保上下文不冗余 |
| 错误重试次数 | 3 次 | 应对临时的系统接口波动，减少无效工作流中断 |

*本配置指南基于FastGPT v4.17.0版本的工作流编排功能制定*

## 容易做错的三处
- 工具调用节点返回Invalid JSON错误：现象为界面弹出报错提示“Invalid JSON: Bad control character”，原因是调用财政系统接口时返回的原始数据包含未转义的换行符或特殊字符，未在节点配置中添加数据清洗步骤。
- 无法复制粘贴工作流组件：现象为选中组件后无法拖拽或复制到其他工作流，原因是未在工作流编辑界面开启全局组件复用功能，仅能在当前工作流内复用组件。
- 工作流上下文未统一：现象为不同节点生成的文书出现数据不一致，原因是未将`variables`配置为绑定统一的数据源字段，各节点独立调用零散数据。

## 怎么确认配好了
- 检查工作流各节点的数据源绑定，确认`variables`配置的字段与预算管理一体化系统的输出字段完全匹配。
- 测试工具调用节点，验证返回数据无未转义特殊字符，且格式符合文书起草的字段要求。
- 复制单个组件到新的测试工作流，确认组件配置与依赖参数完整保留。
- 模拟年度预算编制的完整流程，检查各节点间的数据流转无断层。
