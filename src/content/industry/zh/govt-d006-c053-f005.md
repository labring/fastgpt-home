# 部门预算编制的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
本品类的核心数据来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知，更新频率为年度。日常产出的文书包含部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等，文档结构包含人员编制数、项目经费额度、绩效指标、年度预算周期等字段，单位通常为万元、人、项等。数据通常跨多个系统存储，单份文档包含多类关联字段，需跨数据源整合后才能完成文书起草。

## 这些特征在「工具调用与插件」这一环带来什么约束
年度更新的数据源要求工具调用与插件需适配固定的业务周期，避免频繁触发无效调用。跨系统的数据来源要求插件需支持多数据源对接，确保能从预算管理一体化系统、人员编制系统等获取对应字段。文档的多字段结构要求工具调用需精准提取特定字段，避免冗余数据干扰文书生成。出错后果的严重性要求工具调用需增加参数校验环节，确保生成的预算文书符合审核要求。与决算类场景的差异要求工具逻辑需聚焦资金申报与安排环节。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 自动 | 适配预算编制场景下多步骤工具调用需求，避免手动指定函数遗漏测算、审核等环节 |
| 单次工具调用超时 | 120–180 秒 | 对应预算数据测算、跨系统查询的耗时，按实测标定 |
| 知识库召回上限 | 前 6 条 | 匹配部门预算文档的字段密度，避免冗余数据干扰文书生成 |
| 自定义插件请求超时 | 300 秒 | 覆盖跨系统批量数据查询的耗时，按实测标定 |
| 请求重试次数 | 3 次 | 适配跨系统调用的不稳定场景，减少调用失败概率 |
| `functionCall` | 强制校验参数完整性 | 确保提取的人员编制数、项目经费等字段符合格式要求 |
| 文档溯源开关 | 开启 | 保留工具调用关联的预算文档引用信息，满足审核要求 |

## 容易做错的三处
- 调用工具后返回结果未显示关联的预算文档文件名，原因是未开启文档溯源开关，未绑定对应数据源的文件索引。
- 尝试部署自定义插件失败，原因是未正确配置插件的接口权限与参数映射规则，未匹配预算数据的字段格式。
- 使用应用密钥调用知识库接口返回权限错误，原因是未为应用绑定对应的预算类数据源访问权限，直接调用未授权的知识库。

## 怎么确认配好了
- 发起一次部门预算测算的工具调用，检查返回结果是否附带关联文档的文件名。
- 部署自定义插件后，使用模拟预算数据发起调用，验证接口返回的字段与预算文档格式一致。
- 检查应用的权限配置，确认已绑定对应的预算管理一体化系统、项目库等数据源的访问权限。
- 查看工具调用日志，确认参数校验环节已正常执行，无遗漏字段报错。
