# 部门预算编制的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
该品类的核心文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复，数据来源主要为预算管理一体化系统、部门人员编制系统、以前年度决算数据、项目库及财政部年度预算编制通知。数据更新频率为年度周期，文档字段包含预算科目编码、人员编制数、项目绩效指标、资金测算额度等，单位涉及万元、人、项目个数等，数据结构随年度预算政策微调。

## 这些特征在「引用来源与溯源」这一环带来什么约束
年度更新的固定周期数据要求溯源时仅调用当年度有效数据源，避免跨年度无效数据混入。多类异构数据源需对应匹配不同文档字段，例如人员经费测算需关联人员编制系统数据，项目支出需调取项目库入库信息。文档结构的标准化程度影响分块与召回精度，预算科目编码等精准字段可提升溯源匹配度，跨部门汇总的预算数据需确保溯源范围覆盖所有下属单位的上报数据源，避免遗漏引用依据。同时财政文书的合规性要求引用来源需明确标注数据源类型与具体片段，不可随意省略核心校验信息。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配部门预算文档的单块内容长度，确保引用片段完整包含预算科目与测算依据 |
| `responseData` | 开启 | 用于返回引用来源的数据源标识与文档片段，匹配预算编制溯源的合规要求 |
| `detail` | 完整 | 保留引用来源的原始字段信息，便于核对预算科目编码与资金额度的对应关系 |
| 最大上下文 | 前10条召回结果 | 覆盖年度预算相关的多类数据源，避免遗漏项目库或决算数据 |
| 超时阈值 | 300 秒 | 适配财政系统内部接口的响应时长，避免因系统延迟导致召回失败 |
| 分块长度 | 500–800 字符 | 适配预算文档的段落结构，提升分块召回的精准度 |

## 容易做错的三处
- 现象：生成的预算编制文档中出现跨年度的决算数据引用，且无法溯源到当年度有效数据源。原因：未限制数据源的更新周期为当年度，调用了历史冗余数据。
- 现象：回复内容中附带的引用链接无法正常跳转至财政系统内部文档，或出现非必要的外部链接。原因：开启了非合规的链接展示格式，未匹配内部系统的数据源标识规则。
- 现象：引用片段仅显示资金额度未包含预算科目编码，导致审核时无法核对依据。原因：`detail` 参数设置为精简模式，丢失了核心校验字段。

## 怎么确认配好了
- 发起预算科目测算相关的提问，检查返回内容中是否附带对应数据源的标识信息。
- 查看引用片段是否包含预算科目编码、人员编制数等核心字段，确认`detail`参数配置正确。
- 测试调用不同类型的数据源，例如项目库与决算数据，检查召回结果是否覆盖对应文档类型。
- 检查引用展示格式是否仅标注数据源名称与片段位置，无冗余外部链接。
