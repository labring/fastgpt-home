# 部门预算编制的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
典型主体为财政局预算处、预算单位财务处等，日常处理的文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等。数据主要来自预算管理一体化系统、部门人员编制系统、以前年度决算数据、项目库及财政部预算编制通知，更新频率为年度。文档多为结构化表格与文本结合的格式，包含人员编制数、项目经费额度、绩效指标分值等特定字段，单位涉及万元、人、分等。

## 这些特征在「模型接入与配置」这一环带来什么约束
部门预算编制的数据来源多为内部业务系统，要求模型接入时需支持对接内部接口获取结构化数据。年度更新的频率意味着知识库无需高频刷新，仅需在每年预算编制周期前完成数据同步。文档的结构化特征要求模型需准确识别特定字段与单位规则，避免生成不符合财政规范的内容。不同于决算环节，该环节聚焦年度资金申报与安排，需基于未来规划生成内容。同时，预算编制出错会导致流程退回或资金无法安排，因此模型输出需保持严谨性，配置环节需兼顾上下文容纳能力与内容合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 部门预算编制需同时加载往年决算、项目库、当前草案等多份文档，需足够的上下文容纳量 |
| `maxTokens` | 4000 token | 单份预算文书输出需覆盖测算说明、项目审核意见等完整内容，避免截断关键信息 |
| `quoteMaxToken` | 2000 token | 优先引用预算管理一体化系统的历史结构化数据片段，确保内容来源可追溯 |
| `temperature` | 0.3–0.5 | 需保持预算内容的严谨性，避免模型生成不符合财政规范的发散内容 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 对接本地或第三方模型接口，适配内部网络访问规则 |
| `toolChoice` | auto | 按需调用内部数据查询工具，补充预算编制所需的实时项目库数据 |

## 容易做错的三处
-  配置`AIPROXY_API_TOKEN`时填写错误，导致接口请求返回401或400状态码。原因是未将平台生成的代理令牌正确填入配置项，或令牌未开放预算数据的访问权限。
-  本地部署模型时无法根据预算文档内容生成对应结果，仅输出通用内容。原因是未将预算管理一体化系统导出的结构化数据正确上传至FastGPT知识库，或分块配置未匹配预算文档的字段长度。
-  设置`temperature`参数高于0.5后，模型生成的预算测算结果出现非标准单位或逻辑错误。原因是未根据预算编制的严谨性要求调低温度参数，导致模型偏离财政规范。

## 怎么确认配好了
-  调用模型接口测试，检查返回结果中是否包含部门预算草案的核心字段，如项目经费额度、人员编制数等。
-  查看FastGPT v4.17.0的知识库解析日志，确认预算管理一体化系统导出的历史数据已被正确分块并存储。
-  验证`maxContext`参数设置，测试同时加载3份以上往年预算文档时模型是否能正常关联上下文。
-  检查`AIPROXY_API_TOKEN`的权限配置，确认接口请求能正常返回200状态码。
