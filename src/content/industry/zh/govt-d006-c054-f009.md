# 防汛防灾与应急值守的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控，更新频率为每日，部分实时预警数据的更新间隔更短。日常文书包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单，文档结构多包含时间、地点、数值类字段（如降雨量毫米、水位米、人员数量）与处置措施条目，字段单位多为气象、水文通用标准单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且更新频率较高，要求模型接入时需适配多源实时数据的上下文加载节奏，避免因上下文溢出导致生成中断。日常文书包含大量结构化数值与标准化处置条目，要求配置时需限制生成token的上限，确保输出符合应急文档的格式规范。不同来源的数据字段单位存在细微差异，需在配置中明确数据对齐的处理逻辑，避免生成内容出现单位混淆。同时，应急场景的时效性要求，需调整相关参数平衡生成准确性与响应速度，适配高频更新的业务数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 需加载多源的水文、气象、基层报灾当日数据，该区间可覆盖完整的当日业务数据集 |
| `maxTokens` | 2000–3000 token | 应急文书以结构化条目与处置流程为主，该区间可覆盖标准文书的合理长度，避免冗余输出 |
| `quoteMaxToken` | 1500 token | 需准确引用雨情、水情的具体监测数值，该长度可保留关键数据源的完整信息 |
| `temperature` | 0.3–0.5 | 应急文书需保持严谨准确，较低的温度可减少无关内容生成，确保输出符合业务规范 |
| `AIPROXY_API_ENDPOINT` | 本地vllm部署服务地址 | 适配FastGPT v4.17.0版本的自主部署大模型，确保数据处理符合内部安全要求 |
| `vision` | 关闭 | 该品类核心文书基于结构化文本与数值数据，无需处理图像输入，可降低资源占用 |

## 容易做错的三处
- 启用`vision`参数后，界面无法打开图像上传选项，生成结果未包含图像解析内容。原因：该品类的业务场景无需图像输入，误启用该参数后，系统未适配对应场景的图像处理逻辑，导致功能无法正常触发。
- 配置本地部署的大模型后，测试环节返回connector error报错。原因：未正确填写`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或本地服务未开放对应端口，导致系统无法建立连接。
- 生成会商纪要时出现上下文截断，关键监测数据缺失。原因：`maxContext`取值过小，未覆盖当日完整的水文、气象数据，导致系统无法加载全部必要的业务信息。

## 怎么确认配好了
- 运行本地模型连接测试，确认返回正常的响应内容，核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置是否与本地服务一致。
- 导入一份当日的水文监测数据与值班记录，测试生成灾情速报，检查生成内容是否包含全部关键字段与数值。
- 调整`temperature`参数，对比不同取值下的生成结果，确认输出符合应急文书的严谨性要求。
- 检查`vision`参数的配置状态，确认未启用无关的图像处理功能，避免资源浪费。
