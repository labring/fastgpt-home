# 食品安全监督抽检的文书与材料起草：工作流编排

FastGPT v4.17.0

## 这个品类的数据长什么样
本品类的数据来自食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS及企业台账，更新频率为月度。日常生成的文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告，文档结构固定包含抽样点位、样品信息、检测项目、判定结果、处置流程等标准化字段，无额外自定义非标准字段。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据来源要求工作流需配置跨数据源的变量调用能力，以统一拉取抽检计划、检验报告等不同来源的业务数据；月度更新的数据源要求工作流需设置固定周期的定时触发节点，确保数据时效性；标准化文档结构要求工作流需配置节点间的字段校验规则，避免抽样单、检验报告等文档的字段缺失或格式错误；核心的复核、处置环节要求工作流需支持节点上下文隔离，防止不同抽检任务的数据混淆，影响结果准确性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 变量引用 | 绑定抽检计划、检验报告两个知识库 | 匹配本品类多数据源的业务数据来源 |
| 节点上下文 | 仅使用当前节点上下文 | 避免全局上下文混入其他抽检任务的历史数据 |
| 定时触发 | 每月1日0点执行 | 适配数据源月度更新的业务节奏 |
| 文件上传限制 | 单文件最大1000 MB，单次上传最多5个文件 | 适配检验报告、抽样单等文档的常规大小 |
| API调用参数 | 携带`nodeId`标识当前工作流实例 | 便于排查文件上传、接口调用的异常问题 |
| 重试机制 | 失败后重试3次，间隔600秒 | 应对临时的系统接口波动或网络异常 |

## 容易做错的三处
- 工作流上传检验报告文件时返回Failed to create post presigned url报错，原因是未配置工作流关联的对象存储签名参数，或上传文件大小超出预设限制。
- 知识库变量引用未获取到预期的抽检数据，原因是未将对应抽检知识库绑定到工作流的`variables`配置项，或变量名与文档字段不匹配。
- 调用工作流API时图片参数无法正确解析，原因是未在API请求中正确携带文件流或预签名URL参数，未匹配节点要求的参数格式。

## 怎么确认配好了
- 检查工作流的`variables`配置项，确认已绑定所有需要的抽检相关知识库。
- 触发一次测试运行，查看文件上传环节是否返回正常的预签名URL，无报错信息。
- 查看每个节点的设置，确认已开启仅使用当前节点上下文的选项。
- 调用工作流API，验证图片参数可被正确解析并触发后续节点。
