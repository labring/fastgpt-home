# 食品安全监督抽检的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
本品类数据主要来自食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS系统及食品生产经营者台账。数据更新频率为月度，核心文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。文档多为结构化表格与规范公文模板结合，字段包含抽样编号、检验项目、不合格判定依据、处置措施等，需严格匹配监管部门统一的文书格式要求。

## 这些特征在「工具调用与插件」这一环带来什么约束
月度更新的数据源要求工具调用需适配批量拉取与增量同步逻辑，避免重复处理历史数据。多类结构化文档混合的场景，要求插件需支持识别不同文档的字段映射规则，例如将LIMS导出的检验报告字段对应到核查处置报告的必填项。监管统一格式要求工具生成的文书需严格匹配预设模板，无法随意调整字段顺序与表述方式。同时，不合格处置相关文档需关联对应抽样编号与检验数据，工具调用需保证数据链路的一致性，避免出现字段不匹配或数据错位。此外，需通过`toolChoice`配置自动匹配场景，通过`functionCall`强制结构化输出，确保生成内容符合监管要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动匹配抽检文书起草场景的工具调用逻辑，适配多源文档的混合处理需求 |
| `functionCall` | `enabled` | 强制触发结构化输出，确保生成的文书字段符合监管部门统一格式要求，符合FastGPT v4.17.0的插件加载规则 |
| 单次工具调用时长上限 | `300–600 秒` | 月度批量处理抽检计划时，预留足够时间拉取多源数据并完成字段映射，避免超时中断 |
| 文档解析工具切换配置 | 按插件文档指引修改对应配置项 | 适配不同来源的文档格式，例如处理100 MB以内的LIMS导出文件与市监系统导出的公文模板 |
| 上下文窗口大小 | `8000–12000 token` | 完整承载抽检计划、抽样单、检验报告的关联数据，避免关键信息被截断 |
| 批量处理任务上限 | `前 100 条` | 按实测标定，避免单次处理数据量过大导致平台资源过载 |

## 容易做错的三处
- 现象：调用插件处理上传的抽检报告时返回字段为空，原因：未配置对应文档的字段映射规则，未将LIMS导出的检验数据与文书模板的必填字段绑定。
- 现象：本地WSL+Docker Compose部署环境下，使用Doc2x插件处理抽检语料时出现超时报错，原因：未调整单次工具调用时长上限，Win11环境下硬件资源调度延迟导致处理超时。
- 现象：替换文档解析工具后生成的文书格式不符合监管要求，原因：未同步修改模板匹配规则，新解析工具输出的字段顺序与原有模板不匹配。

## 怎么确认配好了
- 上传一份标准抽样单文件，查看工具调用返回的内容是否包含抽样编号、抽样日期、被抽检单位名称等必填字段。
- 发起批量月度抽检计划处理任务，查看任务状态是否在预设时长内完成，无超时报错提示。
- 修改文档解析工具配置后，上传LIMS导出的检验报告，确认生成的核查处置报告中不合格项目与检验数据一致。
- 调用API接口，查看返回结果中是否包含本次处理所关联的数据源文件名称。
