# 食品安全监督抽检的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类涉及的文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。数据来源为食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS系统及食品生产经营者台账。数据更新频率为月度，单份核心文档含固定字段：抽检计划含批次、抽样点位、时限要求；抽样单含样品编号、生产单位、检验项目；检验报告含检测值、判定依据。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据特征要求模型配置需支持定期同步最新抽检数据，避免上下文包含过期信息。多源数据的接入需求要求配置需兼容工具调用，以整合来自监管系统、LIMS的分散数据。固定字段的文档结构要求模型输出需严格匹配业务字段，不能出现无关或缺失项。出错后果的严重性要求配置需限制模型生成的偏差范围，确保文书内容符合监管要求。不同主体的使用场景要求配置需支持权限隔离，避免数据泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxTokens` | 8000–12000 token | 单份检验报告含多组检测数据，核查处置报告篇幅较长，需覆盖完整文书内容 |
| `quoteMaxToken` | 2000–3000 token | 用于提取检验报告中的关键检测数据与判定依据，避免上下文溢出 |
| `temperature` | 0.2–0.4 | 需保证文书格式与业务字段的一致性，避免生成无关或偏差内容 |
| `toolChoice` | auto | 需调用抽检监测系统、LIMS等数据源获取实时抽检数据与检验结果 |
| `AIPROXY_API_TOKEN` | 绑定专属调用密钥 | 确保数据调用权限仅开放给内部监管与检验机构，防止未授权访问 |
| `maxContext` | 10–15 天的历史数据 | 月度抽检计划的制定需参考近期抽检结果，避免上下文冗余 |

## 容易做错的三处
- 现象：生成的抽样单缺少样品编号、检验项目等必填字段，内容为空或不符合格式。原因：未在配置中限定模型需引用系统预设的固定业务字段，导致生成内容偏离业务要求。
- 现象：开启工具调用功能后，模型未输出中间推理过程。原因：部分模型默认在工具调用模式下关闭思维链输出，未调整对应配置以保留推理步骤。
- 现象：配置本地MCP服务后，无法在模型调用中选择该服务。原因：未正确配置`AIPROXY_API_ENDPOINT`指向本地MCP地址，或密钥未开放至本地服务权限。

## 怎么确认配好了
- 手动触发单份文书生成任务，检查生成内容是否包含要求的全部业务字段，格式是否符合规范。
- 调用工具获取指定批次的抽检数据，验证模型是否能正确拉取并整合来自多系统的数据源内容。
- 查看模型输出日志，确认工具调用流程与思维过程的输出符合预期。
- 模拟月度数据更新，检查上下文配置是否能正确加载近期的抽检数据，未包含过期信息。
