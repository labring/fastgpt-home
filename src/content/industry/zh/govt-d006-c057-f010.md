# 食品安全监督抽检的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS系统及食品生产经营者台账。日常文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告，文档结构多包含固定业务字段，如抽样点位、检验项目、不合格判定依据等。数据更新频率为月度，单份文档长度跨度较大，既有简短的抽样单，也有数千字符的检验报告与处置报告。

## 这些特征在「知识库检索与召回」这一环带来什么约束
月度更新的数据需要定期同步知识库，避免召回过时的抽检计划或旧版检验报告。固定业务字段与混合格式的文档，要求检索需精准匹配抽样点位、检验项目等关键词，避免无关结果混入。长文档与内嵌表格、图片的内容，会增加分块与语义嵌入的难度，导致检索召回的上下文准确性下降。不同业务主体产生的文档格式差异，需要适配多源数据的检索规则，确保监管、检验等场景下的召回结果符合业务需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配本品类业务场景：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.88 | 匹配抽样点位、检验项目等精准业务字段，过滤低相关性的非抽检类文档 |
| `limit` | 前5–7条 | 覆盖单份长检验报告的多段分块，同时控制上下文总长度符合模型输入限制 |
| `searchMode` | 混合检索 | 兼顾关键词匹配与语义关联，适配抽检计划与检验报告的混合文档场景 |
| `usingReRank` | 开启 | 对初始召回结果重新排序，提升不合格食品核查处置报告的召回准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户输入的抽检批次号等关键词扩展检索范围，匹配关联的抽样单与检验报告 |

## 容易做错的三处
- 现象为检索结果中内嵌表格、图片的内容无法被完整召回或语义偏移，原因是未针对抽检报告、抽样单等带混合格式的文档调整分块与嵌入规则，导致模型无法捕获表格内的检验项目与判定依据。
- 现象为系统推荐的扩展问题未匹配食品安全抽检的专属业务场景，仅生成通用类问题，原因是未开启基于本品类知识库专属文档的问题扩展配置，导致扩展内容脱离实际业务数据。
- 现象为检索调用时出现模型相关报错，原因是未配置与本品类数据适配的检索模型权限，或模型版本与知识库嵌入模型不匹配，导致无法正常召回文档。

## 怎么确认配好了
- 手动输入抽检计划中的核心关键词，核对召回结果是否包含对应文档的分块内容。
- 调整`similarity`配置区间，验证召回结果的相关性是否符合业务需求。
- 开启`usingReRank`后，检查长文档的排序是否优先匹配不合格处置相关的核心内容。
- 触发问题扩展功能，确认推荐的扩展问题均来自本品类的专属文档内容。
