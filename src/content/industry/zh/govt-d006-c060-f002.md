# 仓储物流的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
仓储物流的文书与材料主要来源于日常作业单据与合规文档，包括仓储出入库单、运输委托书、货权转移证明、分拣作业日志、年度物流合规方案等。数据更新节奏随作业批次变动，日常作业单据按每日或每批次生成更新，合规文档则按季度或项目节点更新。文档结构以结构化字段为主，附带自由文本备注，包含货物品类、作业数量、计量单位（件、吨、立方米等）、作业时间、承运方信息等固定字段，部分长文档如年度合规方案可达到数万字符，包含完整的作业流程说明与风险条款。

## 这些特征在「向量模型与索引」这一环带来什么约束
仓储物流单据的结构化字段与自由文本混合的特征，要求向量分块需同时保留关联的元数据与业务描述，避免拆分后丢失单位、作业编号等关键信息。高频更新的作业单据要求索引刷新周期匹配作业节奏，防止召回过时或未同步的内容，避免起草的文书使用错误的库存或运输数据。多样的计量单位与固定的作业编号，要求索引过程中需绑定元数据，避免语义召回混淆同类单据的不同作业批次。长文档的存在则要求向量模型的输入长度需适配完整的业务说明，避免截断关键的风险条款与作业要求。

## 配置怎么定
本配置示例基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 仓储物流单据的结构化字段与自由文本备注组合后，单块可容纳完整作业说明与关联参数 |
| 重叠长度 | 50–80 字符 | 避免跨块的作业流程描述被拆分，保留上下文连贯性 |
| `maxToken` | 4096 token | 匹配多数通用嵌入模型的输入上限，适配长运输方案文档 |
| `defaultToken` | 2048 token | 处理常规的出入库单据与运输委托书，平衡召回精度与计算成本 |
| 相似度阈值 | 0.72–0.80 按实测标定 | 区分同类单据的不同作业批次，避免召回无关的历史单据 |
| 单次搜索上限 | 前10条 | 覆盖单批次作业的关联单据数量，避免召回过载 |
| 最大上下文 | 8000 字符 | 整合召回的单据内容，满足起草完整物流文书的需求 |

## 容易做错的三处
- 现象：使用chunk模式调用pushdata API上传单据后，后台任务列表中始终显示「索引中」状态，超过2小时未完成，或返回状态码504网关超时。原因：上传的单据批次未拆分，单批次提交的文档数量过多，超出服务器的并发处理上限。
- 现象：在问答拆分后的索引流程中，最后一组数据始终无法完成索引，返回「向量生成失败」的报错信息。原因：最后一组数据的总文本长度超出了`maxToken`的配置上限，未提前做截断或小分块处理。
- 现象：调用embedding模型时返回空向量，或无法通过one API之外的方式正常调用模型。原因：未正确配置模型的接口地址与密钥，绕过one API后未完成平台的权限校验，导致接口调用被拒绝。

## 怎么确认配好了
- 上传1份测试的仓储出入库单，查看索引任务的完成状态，确认无超时报错或异常状态码返回。
- 输入包含具体货物品类、计量单位与作业时间的查询词，检查召回结果是否包含匹配的单据内容，且无无关的历史单据混入。
- 查看向量块的元数据，确认货物品类、作业单位、作业时间等字段已被正确绑定到对应的向量块中，可在召回结果中同步展示。
- 测试调用embedding模型，确认返回的向量维度与配置的模型要求一致，无空向量或维度不匹配的情况。
- 验证单次搜索上限的配置，确认召回结果的数量不超过设定的条数，避免过多无关内容干扰文书起草。
