# 仓储物流的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
仓储物流领域的文书与材料主要包括入库单、出库单、运输调度单、库存台账、报关单、签收回执等。数据来源主要为仓储管理系统、运输管理系统及线下纸质单据扫描件。更新节奏多为实时或每日定时同步，单份文档长度从数百字符到数千字符不等，部分单据还包含运输路线、报关单号等扩展字段。文档结构固定，包含单据编号、操作时间、货物数量、存放地点、责任人、金额等字段，单位涵盖件、吨、立方米、元等。

## 这些特征在「工具调用与插件」这一环带来什么约束
固定且多字段的文档结构要求工具调用需精准匹配字段规则，避免遗漏关键信息；实时或高频更新的数据要求插件需支持定时拉取或事件触发，确保返回的文书内容为最新状态；多类型单据的差异要求工具调用需根据文书类型自动切换对应的数据接口；长文档占比高的特点要求工具调用需适配大文本处理逻辑，避免因内容过长导致调用失败。此外，线下扫描件与多格式单据的存在要求插件需集成多格式解析能力，适配不同来源的文书数据。

## 配置怎么定
本章节配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动匹配仓储物流文书所需的工具调用逻辑，适配入库单、出库单等多类型单据 |
| `functionCall` | 开启 | 支持主动调用数据拉取工具，获取最新的仓储单据数据 |
| 单次工具调用超时时间 | 30 秒 | 仓储单据数据拉取通常耗时较短，超时设置避免阻塞整体流程 |
| 工具返回结果缓存时长 | 1 小时 | 仓储库存数据更新频率较高，缓存时长平衡数据时效性与调用效率 |
| 单次工具调用最大文本长度 | 800–1200 字符 | 适配仓储单据的常规长度，避免因文本过长导致调用失败 |
| 文档解析工具切换 | 按文档类型选择对应插件 | 适配仓储物流的PDF、Excel、纸质扫描件等多格式单据 |

## 容易做错的三处
- 现象：调用OpenApi接口后返回结果未显示知识库关联的仓储单据文件名，原因是未开启工具调用的文件溯源配置，无法追踪调用过程中使用的原始文档。
- 现象：工具调用返回超时报错，状态码为504，原因是单次工具调用超时时间设置过短，未适配批量仓储单据的拉取耗时。
- 现象：仅输入十几个字的问题却触发完整流式输出，未调用工具，原因是`toolChoice`被错误设置为`none`，关闭了自动工具调用逻辑，直接返回固定结果。

## 怎么确认配好了
- 发起包含“查询今日入库单”的测试请求，查看是否触发工具调用并返回对应单据的结构化数据。
- 查看工具调用日志，确认返回结果包含仓储单据的标准字段，如单据编号、货物数量、入库时间等。
- 测试替换文档解析工具后，能否正常解析上传的PDF格式仓储单据，无解析失败提示。
- 检查配置项`toolChoice`的当前值，确认与预设的自动匹配逻辑一致，未被误设为`none`。
