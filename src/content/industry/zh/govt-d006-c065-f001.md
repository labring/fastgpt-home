# 勘察设计的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
勘察设计的文书与材料起草数据主要来源于项目现场勘察报告、施工图设计文件、报审报批材料、工程变更单等。数据更新节奏随项目进度调整，报审前、变更后会触发高频更新。单份文档多为混合结构，包含固定字段：项目编号、勘察点位坐标、设计参数、报审批次、签署人、生成日期，单位涵盖米、兆帕、平方米等。文档长度跨度较大，小型报审文件约数千字符，大型全套设计说明可达数万字符。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
勘察设计数据包含结构化坐标、参数字段与非结构化文本，要求HTTP接口支持字段校验与多格式数据传输。文档长度跨度大，请求体大小可能超过常规阈值，需适配大流量传输配置。数据更新无固定周期且依赖项目唯一标识，接口需支持动态传入项目编号等自定义参数完成数据匹配。同时，对接的外部报审系统、BIM平台多有专属鉴权与数据格式要求，需严格遵循对应接口规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| API地址 | 填写外部勘察报审系统的官方接口地址，如`https://xxx.com/design/report/submit` | 匹配对接系统的交互路径，确保请求可送达目标服务 |
| `Authorization` | 填写格式为Bearer {oneapi密钥}的鉴权串 | 符合HTTP接口鉴权标准，完成与外部系统的身份验证 |
| 请求超时时间 | 600秒 | 覆盖勘察设计文档上传与外部系统处理的完整耗时，避免提前触发超时中断 |
| `variables` | 传入项目编号、勘察点位坐标等自定义业务参数 | 匹配外部系统的数据匹配规则，实现对应项目文档的精准关联 |
| `responseData` | 配置为提取接口返回的报审编号与审核状态字段 | 捕获外部系统的处理结果，用于后续流程的状态跟踪 |
| 重试次数 | 2次 | 应对临时网络波动导致的请求失败，避免重复提交重复数据 |

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 容易做错的三处
- 配置`Authorization`时仅填写密钥值未添加Bearer前缀，现象为接口返回401未授权状态码，原因是不符合HTTP鉴权的标准格式要求。
- 未在`variables`中传入项目编号字段，现象为外部系统返回空数据或匹配错误的项目文档，原因是勘察设计数据依赖项目编号作为唯一标识，缺少该参数无法定位对应业务数据。
- 请求超时时间设置为30秒等较短数值，现象为大型文档提交时触发超时错误，原因是勘察设计报审文件的处理与传输耗时较长，短超时无法覆盖完整流程。

## 怎么确认配好了
- 发送测试请求，查看接口返回的HTTP状态码是否为200，确认鉴权配置生效。
- 传入测试用的项目编号与小型测试文档，查看外部系统后台是否接收到对应参数，确认`variables`配置正确。
- 查看`responseData`提取的字段是否包含报审编号与审核状态，确认响应处理配置无误。
- 模拟临时网络中断后重试请求，查看是否触发预设的重试机制，确认超时与重试配置生效。
