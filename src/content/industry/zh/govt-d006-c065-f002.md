# 勘察设计的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
勘察设计的文书与材料主要来源于项目现场勘察数据、设计院内部设计文档、变更洽商记录、施工图审批文件等。更新节奏随项目进度与技术变更触发，无固定周期，每次项目节点或调整后均会更新。文档结构包含项目元数据、专业技术内容、附图索引三部分，字段包括项目编号、勘察点位坐标、设计荷载值、图纸版本号等，部分文档附带带单位的技术参数。

## 这些特征在「向量模型与索引」这一环带来什么约束
勘察设计文档兼具结构化参数与非结构化描述，要求向量分块需保留字段边界，避免切断专业术语与技术参数的关联。文档长度差异较大，短则数页的洽商记录，长则数十页的总设计说明，需适配灵活的分块策略。带单位的技术参数要求向量模型适配专业技术文本语义。非固定更新频率则要求索引支持增量同步，避免全量重建带来的资源消耗。

## 配置怎么定
本文适配 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配勘察设计文档的长度差异，平衡语义完整性与索引粒度 |
| 重叠长度 | 100–150 字符 | 避免分块切断专业术语、技术参数的上下文关联 |
| 相似度阈值 | 0.72–0.85 | 区分相似的勘察点位描述与不同项目的设计参数，按实测标定 |
| 单次搜索上限 | 前 8 条 | 勘察设计文书的专业关联度较高，少量结果即可覆盖核心查询需求 |
| `defaultToken` | 4096 | 适配多数开源embedding模型的输入token上限，匹配常规分块长度 |
| `maxToken` | 8192 | 处理包含大量附图标注的总设计说明文档，避免截断关键技术内容 |

## 容易做错的三处
- 现象：大语言模型对话功能正常，但向量索引任务停滞无日志更新。原因：未正确配置`maxToken`，导致分块文本超出embedding模型输入上限，请求被阻塞。
- 现象：搜索结果中出现无关的勘察项目文档，核心字段为空或参数值不匹配。原因：分块时未保留字段边界，导致向量语义混淆，无法准确关联专业内容。
- 现象：增量索引仅部分更新内容被收录，旧内容未被正确覆盖。原因：未按项目变更触发增量同步，仍使用全量索引模式，导致更新逻辑异常。

## 怎么确认配好了
- 上传单份1000字符左右的勘察洽商记录，查看分块预览是否保留了项目编号、变更内容等核心字段，无截断情况。
- 发起包含“某点位勘察数据”的专业查询，查看返回结果的相似度分值是否在设定的阈值区间内，且无无关文档混入。
- 提交一份新的变更文件，触发增量索引，等待10分钟后再次查询，确认新内容已被正常收录。
- 检查`defaultToken`与`maxToken`的配置值，与所用embedding模型的官方输入上限匹配，无超配或低配情况。
