# 勘察设计的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
勘察设计的文书与材料数据主要来源于项目勘察报告、结构计算书、施工图设计文件、变更洽商记录及报审报批文档。数据随项目设计阶段更新，初步设计、施工图、竣工图阶段各有版本迭代。文档多为结构化与半结构化混合格式，包含勘察孔坐标、荷载参数、规范引用编号等专属字段，单位涉及米、千牛、兆帕等工程专业单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
勘察设计的专属数据特征会对模型接入配置带来多重约束。工程专业术语与专属单位占比高，要求模型参数适配工程领域文本理解需求，避免出现单位识别错误或术语误解。文档随项目设计阶段迭代更新，需确保模型调用时可关联对应版本的数据源，避免调用过期内容。单份文书如结构计算书长度较长，需调整上下文窗口参数以完整加载关键段落，防止内容截断导致生成结果不完整。

## 配置怎么定
FastGPT v4.17.0 版本下的配置项如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写工程场景专属模型的部署地址，如企业内部部署的工程大模型接口 | 适配勘察设计专属模型的调用路径，确保请求正确路由 |
| `AIPROXY_API_TOKEN` | 填写对应模型的授权密钥，按企业内部权限规则配置 | 保障模型调用的身份合法性，防止未授权访问 |
| `maxContext` | 8000–12000 token | 适配勘察设计文档较长的特点，完整加载关键段落与历史上下文 |
| `maxTokens` | 2000–3000 token | 控制单轮生成的文书内容长度，避免超出模型输出上限 |
| `temperature` | 0.2–0.4 | 降低生成随机性，确保工程文书的格式与专业表述符合规范 |
| `quoteMaxToken` | 1500 token | 限制引用知识库内容的长度，避免冗余信息干扰文书起草 |

## 容易做错的三处
- 调用模型时返回`401 Unauthorized`报错，检查`AIPROXY_API_TOKEN`配置后仍无法解决。原因是未将企业内部模型的访问白名单配置到FastGPT的授权规则中，导致身份验证失败。
- 模型配置地址测试不通过，返回连接超时提示。原因是未在FastGPT部署环境中开放模型接口的出站端口，或网络策略限制了内部工程模型的访问路径。
- 工作流中多次调用模型后，生成的勘察报告出现单位混淆问题。原因是未配置`temperature`参数为较低区间，导致模型随机输出不同单位的表述，未匹配勘察设计的固定单位规范。

## 怎么确认配好了
- 执行模型接口测试，检查返回结果是否包含工程专业术语与正确的单位格式，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置有效。
- 导入一份典型的勘察设计文档，测试模型生成的文书是否完整加载文档中的关键字段，确认`maxContext`参数适配文档长度。
- 触发多次相同场景的模型调用，检查生成结果的单位与格式是否一致，确认`temperature`参数的取值符合场景需求。
- 查看工作流日志，确认模型调用的上下文轮次与预设配置一致，确认`maxContext`的关联规则生效。
