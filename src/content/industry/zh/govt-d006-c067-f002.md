# 化肥农药的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
化肥农药品类的文书数据主要来自企业内部的生产工艺文档、农药登记备案材料、化肥质检报告、合规性说明文件。数据来源包括农业农村部登记公示平台、企业生产研发部门的内部档案。更新节奏随新登记证获批、生产标准修订按需触发，无固定周期。文档结构包含结构化字段，如有效成分含量（单位为g/L或质量百分比）、登记证号、执行标准编号，以及非结构化的起草类文书，如备案申请函、合规自查报告。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化字段的固定格式与单位要求，会约束分块时不能随意拆分字段关联内容，否则会导致向量检索时丢失字段语义。非结构化起草文书的长度跨度大，短则数百字符的申请函，长则数千字的合规报告，要求索引分块策略适配不同长度的文本。品类特有的专业术语，如农药剂型、化肥养分配比，需要匹配适配农业领域的向量模型，避免通用模型对专业语义的编码偏差。按需更新的数据特征，要求索引支持增量重建与全量重建的灵活切换，适配不同的更新场景。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配品类文书的混合长度，避免拆分破坏专业术语与结构化字段的上下文 |
| 最大段落深度 | 3 | 匹配备案材料的层级结构，保留章节与段落的关联语义 |
| 索引向量维度 | 128 | 平衡专业文本的编码精度与检索效率，适配品类数据的语义特征 |
| `defaultToken` | 1000 token | 限定单条向量文本的最大token数，避免超长文本超出模型编码上限 |
| `maxToken` | 2048 token | 限定单条检索上下文的token上限，适配文书起草时的多参考文本拼接需求 |
| 单次召回条数 | 前5条 | 兼顾检索全面性与响应速度，满足文书起草的多参考需求 |

## 容易做错的三处
- 现象：检索结果中出现有效成分含量与单位分离的内容。原因：分块时未保留结构化字段与单位的关联，将数值与单位拆分至不同分块。
- 现象：调用多模态Embedding模型时返回Invalid错误。原因：未使用适配农业领域的向量模型，或提交的文本包含未转义的化学符号，导致模型解析失败。
- 现象：升级FastGPT版本后，旧向量库检索结果与新配置不匹配。原因：未按照版本适配规则迁移旧索引数据，直接复用旧格式的向量文件。

## 怎么确认配好了
- 上传一份典型的化肥登记备案材料，检查分块后的文本是否保留了有效成分含量与对应单位的关联内容。
- 发起一次文书起草的检索请求，核对返回的结果中是否包含品类特有的专业术语，且语义连贯无断裂。
- 执行一次全量索引重建操作，确认索引更新进度正常，无报错提示。
- 对比新旧版本的向量检索结果，确认升级后的数据匹配逻辑符合预期配置。
