# 化肥农药的文书与材料起草：工具调用与插件

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
化肥农药相关数据主要来源于国家农资登记管理平台、企业生产台账、行业标准文档三类。国家平台数据随行业标准修订更新，企业台账数据按生产批次更新。文档结构包含登记证号、有效成分含量、适用作物、施用剂量、安全间隔期等固定字段，有效成分含量单位多为克/升或质量占比，施用剂量单位多为千克/公顷或亩施用量。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据包含严格的监管必填字段与固定单位，工具调用需精准匹配字段格式，避免生成不符合监管要求的文书。多源数据的更新节奏差异，要求插件需支持定时同步国家平台的最新标准数据，同时兼容企业内部实时更新的生产台账。固定的字段结构也要求工具调用的召回范围需限定在农资专属数据中，避免无关内容干扰文书生成逻辑。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配化肥农药登记证、施用说明等多类文书场景，自动匹配对应工具 |
| `functionCall` | `["generate_fertilizer_spec", "generate_pesticide_label"]` | 限定调用农资专属工具，避免触发无关功能 |
| 流输出开关 | 关闭 | 化肥农药文书需固定格式，流输出会导致分段错乱 |
| 知识库召回上限 | 前10条 | 农资数据字段精准，过多召回结果会增加上下文冗余 |
| 接口超时阈值 | `120 秒` | 对接国家农资平台接口需一定查询耗时，避免提前中断 |
| 输出格式约束 | 严格遵循国标字段顺序 | 符合监管部门对农资文书的格式要求 |

## 容易做错的三处
- 工作流中工具调用模块连接知识库后无法引用有效数据，生成的文书缺少有效成分含量字段。原因是知识库召回上限设置过低，未召回对应农资的核心数据。
- 工具调用模块无触发动作，模块状态显示为未执行。原因是`toolChoice`参数被设置为`none`，未指定需要调用的工具类型。
- 开启流输出后生成的文书分段混乱，无法直接用于监管上报。原因是未关闭流输出开关，实时推送的内容打乱了固定格式。

## 怎么确认配好了
- 生成一份农药登记证文书，检查输出内容是否包含登记证号、有效成分含量、适用作物等必填字段。
- 查看工具调用日志，确认已触发对应农资数据的查询接口，无超时报错。
- 关闭流输出开关后，检查生成的文书为完整的固定分段格式，无实时推送的分段标记。
- 验证`toolChoice`参数设置为`auto`时，能自动匹配当前文书场景的工具调用逻辑。
