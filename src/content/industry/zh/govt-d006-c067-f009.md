# 化肥农药的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
化肥农药相关数据主要来源于国家农业农村部农药登记公告、化肥国家标准汇编、生产企业质检报告与田间试验文档。数据更新节奏为：农药登记公告按月发布，国家标准每年修订，企业生产文档按生产批次更新。文档结构包含登记证号、有效成分含量、施用剂量、安全间隔期等固定字段，单位涵盖g/亩、mL/L、天等，既有单剂使用说明等短文档，也有作物全程用药方案等万字长文档。

## 这些特征在「模型接入与配置」这一环带来什么约束
化肥农药文书起草需精准匹配有效成分、施用剂量等固定字段，且需处理长短不一的文档。长文档的上下文拼接易出现截断，导致关键登记信息丢失；频繁更新的数据要求知识库同步机制适配实时性需求；多单位的字段容易在生成时出现混淆，需要模型具备精准的单位识别能力。此外，登记类文书需严格引用官方发布的登记数据，因此模型接入时需确保检索内容的准确性与完整性，避免生成不符合规范的材料。

## 配置怎么定
本页配置适用于FastGPT v4.17.0及以上版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配作物全程用药方案等长文档的上下文拼接，避免截断关键的登记与剂量信息 |
| `maxTokens` | 3500–4500 token | 匹配单份文书的输出长度需求，确保完整生成登记申请附件或质检报告 |
| `quoteMaxToken` | 1800–2200 token | 限制检索到的知识库内容长度，过滤冗余信息，保障文书起草的精准性 |
| `temperature` | 0.3–0.5 | 降低随机生成概率，确保有效成分含量、施用单位等字段的准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接口地址 | 适配国内网络环境，避免模型调用出现访问延迟 |
| `AIPROXY_API_TOKEN` | 按生成的专属密钥填写 | 确保模型调用的身份验证合规，防止未授权访问 |

## 容易做错的三处
- 调用指定模型时返回404状态码且无响应体，原因是使用的FastGPT版本未适配该模型的接口格式。
- 生成的文书中出现单位混淆错误，比如将g/亩误写为mL/L，原因是`temperature`参数设置过高，导致生成逻辑偏离精准字段匹配要求。
- 知识库检索耗时明显增加，相同知识库下检索效率下降，原因是`maxContext`参数设置过大，导致每次检索的上下文加载开销增加。

## 怎么确认配好了
- 发起一次作物全程用药方案的起草测试，检查生成内容中是否包含正确的有效成分含量与施用单位。
- 调用模型接口，验证返回的响应状态码为200且包含完整的生成内容。
- 查看知识库检索日志，确认返回的文档片段长度符合`quoteMaxToken`的设置要求。
- 检查模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置与部署环境匹配。
