# 医药流通的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
医药流通领域的文书数据主要来源于药品购销合同、冷链运输记录、药品经营合规报告、进销存台账、资质证明文件等。数据更新节奏存在差异：购销合同随交易实时生成，进销存台账每日更新，合规报告按季度或专项检查生成。文档多为结构化与半结构化混合，固定字段包含药品通用名、生产批号、购销方资质编号、运输温度阈值、合规条款编号等，单位涉及件、盒、批次号、摄氏度等。

## 这些特征在「向量模型与索引」这一环带来什么约束
医药流通文书的混合结构化特征要求索引需同时支持字段级精准匹配与全文向量召回，高频更新的进销存数据需要增量索引能力以避免全量重建耗时过长。固定字段的标准化单位与标识需要在分块时保留，防止跨块匹配丢失关键信息。长文档如专项合规报告则需要合理的分块策略，避免拆分关键合规条款。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配医药购销合同、合规报告的单段核心内容长度，避免跨药品批号、合规条款等关键信息拆分 |
| 重叠长度 | 100–150 字符 | 保留跨块的药品批号、运输温度等关键标识，防止向量匹配时出现内容断裂 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的通用文本，确保召回结果聚焦医药合规与交易相关内容 |
| 单次召回上限 | 前 10 条 | 控制返回的上下文数量，避免长文书起草时出现上下文过载 |
| maxToken | 8000 | 适配医药长文书的上下文拼接需求，符合FastGPT的通用参数规范 |
| defaultToken | 500 | 用于单块文本的基础向量生成，平衡向量精度与计算开销 |

## 容易做错的三处
- 现象：索引重建耗时超过24小时，界面显示重建中状态未更新。原因：未针对医药流通的高频更新进销存数据配置增量索引，采用全量索引遍历全部历史文档。
- 现象：批量添加索引时返回参数错误，部分必填字段为空。原因：未按照医药文书的固定字段格式传入药品批号、购销方资质编号等必填参数。
- 现象：向量召回结果条数与预期不符，要么过多要么过少。原因：混淆了单文档独立索引与全局统一索引的配置逻辑，未明确集合内索引的聚合规则。

## 怎么确认配好了
- 上传单份典型医药购销合同，查看分块预览界面，确认分块未拆分药品批号、运输温度等关键字段。
- 发起一次文书起草请求，查看召回的上下文列表，确认匹配结果包含相关的合规条款与进销存记录。
- 新增一条冷链运输记录，等待10分钟后查看索引状态，确认增量更新已完成。
- 查看FastGPT v4.17.0的系统日志，确认`maxToken`与`defaultToken`的配置已生效。
