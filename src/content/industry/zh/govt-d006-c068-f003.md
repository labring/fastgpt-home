# 医药流通的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
医药流通领域的文书与材料主要包括购销合同、入库验收单、出库复核记录、GSP合规台账、冷链运输记录、发票凭证等。数据来源为企业内部ERP、WMS业务系统及药监部门发布的标准模板，随每日业务流转实时更新，合规类文档按季度归档。文档结构固定，包含供方/需方资质信息、药品通用名、规格、批次号、有效期、数量、单价、金额等字段，单位涵盖盒、箱、支、件及元。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
医药流通文书的固定字段多且需符合药监合规要求，因此多轮对话需通过`messages`参数完整保留上下文内的业务字段，避免遗漏批次号、有效期等关键合规信息。实时更新的业务数据要求对话可自动带入最新参数，无需重复录入。多类文书的场景差异（如购销与验收）需明确区分，避免混淆不同文档的字段要求。同时，合规文档的固定排版要求需严格约束输出格式，不得随意使用非标准排版。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 医药流通文书包含多组业务字段，需保留完整多轮对话的上下文信息 |
| 问题优化 | 开启 | 自动合并多轮对话中的业务诉求，减少重复输入，适配复杂合规文档的起草 |
| `variables` | 绑定药品批次号、有效期等业务字段 | 自动带入已确认的业务参数，避免重复录入关键信息 |
| 输出格式约束 | 禁用Markdown语法，使用纯文本分段 | 匹配医药流通监管文档的固定排版要求 |
| 单次召回上限 | 前3条业务文档 | 聚焦核心合规字段，避免冗余信息干扰文书起草 |
| `chatId` | 启用独立会话标识 | 为每个对话会话分配唯一标识，避免多用户上下文串用 |
| 会话超时时间 | 600 秒 | 避免长对话超时中断，适配医药流通复杂文书的起草时长 |

## 容易做错的三处
- 现象：AI返回的文书包含Markdown格式的标题或列表，不符合合规文档排版要求。原因：未在提示词中明确禁用Markdown语法的约束，导致输出格式不符合医药流通文档的固定要求。
- 现象：多轮对话中重复询问已确认的药品批次号或购销金额。原因：未开启问题优化或未绑定`variables`参数，导致上下文未被有效保留。
- 现象：两个独立对话会话的上下文互相干扰，出现跨用户的业务字段混淆。原因：未正确配置`chatId`参数，未为每个会话分配独立标识，导致上下文串用。

## 怎么确认配好了
- 发起一轮包含药品批次号、购销金额的多轮对话，检查返回的文书是否未使用Markdown格式，确认输出格式约束生效。
- 重复提及已确认的业务字段，检查AI是否自动带入该字段，无需重复询问，确认`variables`绑定与问题优化配置生效。
- 发起两个独立的对话会话，检查两个会话的上下文互不干扰，确认`chatId`配置生效。
- 提交一份包含多组业务字段的合规文书起草请求，检查返回内容是否覆盖所有必填字段，确认最大上下文长度配置合理。
