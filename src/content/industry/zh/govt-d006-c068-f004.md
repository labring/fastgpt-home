# 医药流通的文书与材料起草：工作流编排

## 这个品类的数据长什么样
医药流通的文书与材料主要来源于内部ERP、WMS系统以及药监部门的报备接口，涵盖采购订单、药品验收单、冷链运输记录、GSP合规自查表等类型。数据更新节奏随业务交易实时生成单笔单据，批量汇总的月度合规文档每日同步更新。单份文档包含固定字段：药品通用名、生产批号、有效期限、流通企业名称、运输温度区间、合规检查项，字段单位涉及盒、箱、批次号、摄氏度等，结构固定且需符合药监部门的格式要求。

## 这些特征在「工作流编排」这一环带来什么约束
医药流通的文书数据需严格符合GSP合规要求，因此工作流需包含多轮字段校验节点，避免缺失关键信息。冷链运输记录为时序数据，需按生成时间顺序执行温度校验节点，对工作流的节点触发顺序提出明确约束。单笔单据包含多份附属文件，要求工作流支持多文件上传与批量解析。大量批量单据的处理会拉长单工作流执行时长，对超时配置提出更高要求。同时，文书生成需绑定业务系统的实时数据，要求工作流直接关联ERP/WMS的数据源，避免数据滞后。

## 配置怎么定
本配置适用于 FastGPT v4.17.0。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 超时时间 | 600–1200 秒 | 医药流通单据处理包含字段校验、文件解析、合规检查等多环节，取值区间按实测标定 |
| `variables` 绑定 | 绑定药品批号、运输温度等核心字段 | 跨节点传递业务上下文，保障流程数据一致性 |
| `nodeId` 排序 | 按数据生成时间排序节点 | 冷链运输记录需按时间轴校验温度合规性，顺序执行保障逻辑正确 |
| 文件上传限制 | 单次最多上传10个文件，单文件不超过1000 MB | 医药流通验收单常附带多份扫描件与检测报告，限制数量与大小避免节点过载 |
| 表单输入校验 | 开启必填字段校验 | 药品批号、有效期限为GSP合规必填项，校验后阻断异常数据进入流程 |
| 搜索参数关联 | 绑定`variables`中的业务参数 | 调用搜索工具时聚焦医药流通监管场景，避免结果泛化 |

## 容易做错的三处
- 现象：工作流执行超过1200秒后被强制终止，返回状态码504 Gateway Timeout。原因：未针对医药流通多环节校验的单据调整超时配置，沿用默认短超时设置。
- 现象：表单提交后未触发必填字段校验，直接进入后续节点，生成的文书缺失药品批号或有效期限。原因：未配置表单输入的必填校验与提交阻断规则，导致不符合GSP合规要求的文书进入流程。
- 现象：上传的JPEG格式验收单扫描件无法被工作流解析，返回“不支持的文件格式”提示。原因：未在工作流节点中配置允许上传PDF、CSV、JPEG格式的文件，而医药流通的业务单据多为这三类格式。

## 怎么确认配好了
- 手动触发单张医药流通单据的工作流，检查执行时长是否在预设的600–1200秒区间内。
- 填写表单时跳过药品批号或有效期限字段，确认工作流会阻断提交并提示缺失必填信息。
- 上传PDF格式的冷链运输记录文件，确认工作流可以正常解析并提取运输温度字段。
- 在搜索节点前绑定`variables`中的药品通用名参数，触发搜索后检查结果是否聚焦目标药品的监管信息。
