# 医药流通的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
医药流通的数据源主要来自企业内部进销存系统、药品监管部门公示的流通备案信息、合作方资质扫描件。数据类型涵盖结构化的进销存台账、半结构化的购销合同与质量验收记录、非结构化的资质文件。更新节奏为进销存数据每日同步，资质类文件按年度年检周期更新。文档字段包含药品通用名称、生产批号、有效期、购销双方统一社会信用代码、配送地址、交易金额，单位遵循医药流通规范，如人民币元、盒、件等。

## 这些特征在「工具调用与插件」这一环带来什么约束
医药流通数据兼具结构化字段与半结构化合规文档的特征，要求工具调用需精准匹配药品批号、有效期等专属业务字段，无法依赖通用知识库的模糊匹配逻辑。资质类文件需定期校验合规性，工具调用需对接合规校验插件，同步更新资质状态。数据更新频率差异较大，进销存数据每日变动，需配置实时同步的数据源接口。文档长度跨度大，短则数十字符的出库单，长则数千字的购销合同，工具调用的上下文适配需覆盖不同长度区间。字段单位需严格遵循医药流通规范，插件需自动校验药品数量、金额的单位一致性，避免生成错误文书。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配医药流通场景的工具调用与插件需求。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配医药流通文书中既有结构化字段提取又有自然语言生成的混合场景 |
| `functionCall` | 绑定药品信息提取插件 | 用于精准提取进销存系统内的药品批号、有效期等专属字段，提升文书起草准确性 |
| 插件数据源同步周期 | 15 分钟 | 适配进销存数据每日变动的更新节奏，保障工具调用时的数据源时效性 |
| 字段校验开关 | 开启 | 针对药品批号、有效期等专属字段，自动校验格式合规性，避免生成错误文书 |
| 上下文长度上限 | 8000–12000 token | 覆盖购销合同、质量验收记录等不同长度的文档处理需求 |
| 超时阈值 | 300 秒 | 适配医药流通数据对接企业内部系统时的网络延迟情况，避免工具调用中断 |

## 容易做错的三处
- 现象：调用工具起草医药流通文书时，知识库搜索延迟超过600秒，返回结果耗时较长。原因：未配置医药流通专属的数据源过滤规则，知识库包含大量非流通类文档，导致检索范围过大。
- 现象：工具调用返回的药品相关字段为空，无法关联到企业内部进销存数据。原因：插件数据源未绑定医药流通企业的进销存API接口，仅使用通用知识库作为数据源，无法匹配专属业务字段。
- 现象：使用deepseek-r1进行工具调用工作流时，生成的医药流通文书字段错误率较高。原因：未开启`functionCall`模式，模型未被限制调用指定的医药流通字段提取插件，导致生成内容偏离业务规范。

## 怎么确认配好了
- 发起一次药品购销合同的起草测试，核对工具调用是否自动关联进销存系统内的对应药品信息。
- 上传一份过期的资质文件，触发合规校验插件，确认是否返回对应的合规性异常提示。
- 查看插件数据源的同步日志，确认医药流通的进销存数据按设定的周期完成同步。
- 调整`toolChoice`参数，切换不同模式，验证工具调用的响应状态是否符合业务预期。
