# 医药流通的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
医药流通的文书与材料主要来自内部ERP系统、温湿度监控设备、药监备案平台及上下游合作方的资质文件。数据更新节奏分为实时（入库验收单、出库单）、每日（购销台账、温湿度日报）、月度（合规自查报表）三类。文档结构固定，包含购销方资质编号、药品通用名、生产批号、有效期限、储运条件、验收结果等字段，单位涉及件、盒、箱、摄氏度等。

## 这些特征在「模型接入与配置」这一环带来什么约束
医药流通文书需严格符合GSP合规要求，固定字段的格式与内容不可随意调整，因此模型接入时需固定prompt的校验逻辑，避免生成不符合规范的内容。实时更新的入库单与出库单要求模型能快速拉取最新数据，因此上下文缓存的配置需适配高频更新的数据源。冷链运输记录包含带单位的温湿度数值，模型需准确识别并整合这些数据到文书中，因此参数配置需保证对结构化数值的解析精度。此外，部分敏感资质文档需本地存储，模型调用需适配私有部署的环境要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 医药流通文书常包含多份购销合同、冷链运输记录，需保留完整上下文以完成GSP合规校验 |
| `maxTokens` | 4000 token | 单份合规文书起草需覆盖资质、批次、储运要求等固定字段，避免输出内容被截断影响合规性 |
| `temperature` | 0.1–0.3 | 文书需严格符合药监规范，低随机性可保证格式与内容的准确性 |
| `AIPROXY_API_ENDPOINT` | 本地部署节点地址，如`http://192.168.1.100:8080/v1` | 对接私有部署的大模型，适配医药流通敏感数据的本地存储与合规要求 |
| `AIPROXY_API_TOKEN` | 部署生成的专属令牌 | 验证模型调用权限，保障医药数据的访问安全 |

## 容易做错的三处
- 模型测试时返回404 no body，原因是`AIPROXY_API_ENDPOINT`配置的地址未包含正确的API路径后缀，或本地模型服务未正常启动。
- 生成文书或语音转写时出现unmarshal_resp报错，原因是`maxTokens`取值超出模型支持的输出上限，导致响应格式解析失败。
- 接入TTS模型时出现流式输出异常，原因是`maxContext`配置过小，未保留完整上下文数据，导致生成的文本不完整。

## 怎么确认配好了
- 在FastGPT v4.17.0的模型测试界面输入模拟医药购销单，调用后返回正常响应体，无404或解析报错。
- 生成的文书包含所有预设的固定字段，内容与输入的模拟数据一致，无格式偏差。
- 测试语音输入转写功能时，转写的文本可被正确加载到模型上下文，无解析报错。
- 接入TTS模型后，流式输出可正常逐句返回生成内容，无中断或截断。
