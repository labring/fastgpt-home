# 危化品储运的文书与材料起草：文档解析与分块

## 这个品类的数据长什么样
危化品储运的文书数据主要来源于企业内部储运台账、安全生产监督管理部门备案文件、罐区巡检记录、运输调度单及应急处置预案。数据更新节奏依文档类型不同：储运台账每日更新，巡检记录每班更新，备案文件每季度或年度更新。文档结构包含两类：一类是固定格式的结构化表格，包含罐号、危化品品名、存储量、运输资质编号等字段；另一类是长文本格式的应急处置文档，包含处置步骤、防护措施等内容。字段与单位存在特殊规范，存储量以吨、立方米为单位，压力参数以MPa为单位，部分文档包含CAS号、危化品编号等唯一标识字段。

## 这些特征在「文档解析与分块」这一环带来什么约束
结构化表格与长文本混合的文档结构，要求解析工具同时支持表格识别与段落分块，避免强行按字符拆分导致表格内容断裂。特殊字段如CAS号、危化品编号需要保留上下文关联，分块时不能割裂字段与对应属性的联系。不同更新节奏的文档带来解析时长差异：高频更新的巡检记录解析需快速完成，而大体积的年度台账则需要更长解析时长。多来源的文档格式（PDF、Excel、Word）要求解析工具适配多种文件类型，避免因格式不兼容丢失数据。单位规范的特殊性要求解析后保留原始单位，避免因单位转换导致数据歧义。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 危化品储运文档包含长文本预案与结构化台账，该区间可兼顾长文本语义完整与表格内容拆分后不丢失关联 |
| `chunkSplitter` | 按段落+表格识别 | 适配既有长文本应急处置预案又有结构化储运台账的文档结构，避免表格被强行按字符拆分 |
| `customPdfParse` | 开启 | 多数危化品文档为PDF格式，开启后可保留原文档的表格排版与字体层级，提升解析准确性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 单份危化品储运文档可能包含多页台账与预案，该时长可覆盖完整解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 部分企业的年度储运台账文档体积较大，该上限可满足批量上传需求 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（台账/预案）可灵活调整分块参数，适配细分场景需求 |

## 容易做错的三处
- 现象：调用API创建知识库后，仅返回通用成功码，无法获取解析中、就绪、失败的状态反馈。原因：未启用文档解析的状态回调机制，未正确配置状态查询的API调用逻辑。
- 现象：上传的危化品储运PDF中的表格内容被拆分为零散文本，无法还原原表格的行列结构。原因：未开启`customPdfParse`配置，或`chunkSplitter`设置为仅按字符分块，未启用表格识别模式。
- 现象：解析大体积的年度储运台账时，出现超时错误，返回连接超时状态码。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值低于文档解析实际所需时长，未适配危化品台账的大体积、多页面特征。

## 怎么确认配好了
- 上传单份结构化储运台账PDF，查看解析后的文本中是否保留了原表格的行列结构，核对罐号、存储量等关键字段的完整性。
- 调用知识库解析状态查询API，验证是否能实时获取解析进度的更新反馈，覆盖解析中、就绪、失败的各类状态。
- 上传1000 MB以内的大体积文档，确认解析过程未出现超时中断。
- 调整`chunkSplitter`配置后，对比不同分块方式下的长文本预案的语义连贯性，确保关键处置步骤未被割裂。
