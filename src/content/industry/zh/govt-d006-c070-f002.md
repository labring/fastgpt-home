# 发电装备制造的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
发电装备制造的文书数据主要来自整机设计说明书、工艺规程文件、质检报告、招投标技术文件、运维检修手册等。数据更新节奏随项目阶段变化，新机型研发阶段更新频率较高，量产阶段以季度或年度为周期更新。文档结构差异明显，包含数十页的长技术文档、单页的质检表单、结构化的招投标参数表等，字段包含设备型号、额定功率、转速、批次号、质检日期等，配套专用单位如兆瓦（MW）、转每分钟（r/min）。

## 这些特征在「向量模型与索引」这一环带来什么约束
长文本占比高的特征要求分块时需保留专业术语与参数的上下文关联，避免因分块过短切断跨段落的技术描述。专用字段与单位的存在要求预处理时需保留原始字段格式，防止向量模型混淆不同参数的语义。非结构化与结构化文档混合的特征，要求索引环节需适配不同格式的文本解析逻辑。更新节奏波动的特征，要求索引策略可支持增量更新与全量更新的灵活切换，适配研发与量产阶段的不同数据更新需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配发电装备技术文档的长句结构，平衡上下文完整性与模型处理效率 |
| 重叠长度 | 150–200 字符 | 避免分块切断专业参数、设备型号等核心关联信息 |
| `maxToken` | 8192 token | 适配主流开源嵌入模型的token上限，防止长文本截断丢失关键内容 |
| 相似度阈值 | 0.72–0.80 | 过滤低匹配度的非专业文档，聚焦发电装备领域的技术关联结果 |
| 单次搜索上限 | 前 8 条 | 减少冗余结果干扰，聚焦最相关的技术参数与文档内容 |
| `defaultToken` | 4096 token | 作为默认上下文长度，适配常规运维文档的检索需求 |

## 容易做错的三处
- 调用索引接口返回400状态码且无响应体，原因是未适配发电装备长文档的长度，超出模型的token限制导致请求体异常。
- 服务器内存持续占用过高直至崩溃，原因是未限制单次索引的文件数量，且未开启分块缓存，导致批量处理时内存溢出。
- 知识库上传文件后卡在1组或2组索引中，原因是未统一文档的字段格式，部分文档的专业参数字段缺失，导致索引分片失败。

## 怎么确认配好了
- 上传一份典型的发电装备运维手册，在FastGPT v4.17.0中检查分块后的文本是否保留了完整的设备参数与专用单位。
- 发起一次针对特定设备型号的检索，核对返回结果的相似度分值是否落在预设的阈值区间内。
- 批量上传10份不同类型的发电装备文档，检查索引进度是否正常完成无卡顿。
- 验证导出与导入知识库的操作，确认多类型文档的索引结构未发生丢失。
