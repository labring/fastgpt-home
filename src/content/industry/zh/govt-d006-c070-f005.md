# 发电装备制造的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
发电装备制造的核心数据来源于设备设计图纸、运维巡检日志、出厂质检报告、招投标技术文件。数据更新节奏随项目阶段调整，设计阶段文档按周更新，运维日志按班次同步，质检报告随产品批次产出。文档结构包含设备型号、额定功率、运行时长、故障代码、材料牌号等字段，单位涵盖kW、小时、MPa、吨等，单份文档长度跨度较大，从数百字的巡检记录到数万字的全套设计方案不等。

## 这些特征在「工具调用与插件」这一环带来什么约束
发电装备制造的数据跨度大、格式差异显著，要求工具调用插件支持动态适配不同长度的输入文档，避免因单段长度超限导致调用失败。设备参数自带专属单位与字段命名规则，插件需内置字段校验逻辑，确保调用时能识别并验证额定功率、运行时长等字段的格式与单位合规性。不同数据源的文档结构差异明显，插件需支持切换适配设计文档、运维日志、质检报告等不同场景的解析规则，同时需兼容实时拉取运维数据与离线读取归档文档的两种调用模式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 设为`auto`，核心参数场景指定为`function` | 自动模式适配通用文书起草需求，指定函数模式可强制调用工具处理结构化设备参数 |
| 函数调用超时时间 | 300–600 秒 | 适配发电装备长文档解析与多字段校验的耗时需求 |
| 字段校验开关 | 开启 | 确保调用时验证设备型号、额定功率等专属字段的格式与单位合规性 |
| 单块文档最大长度 | 800–1200 字符 | 适配单份文档从数百字到数万字的跨度，避免单块超限导致调用失败 |
| `functionCall` | 按实测标定 | 适配不同项目的文档结构差异，灵活调整函数调用的参数格式 |
| 结果缓存时长 | 24 小时 | 复用同类型文书起草的工具调用结果，减少重复资源消耗 |

## 容易做错的三处
- 现象：使用fetch调用`api/v1/chat/completions`接口时返回跨域错误，出现CORS相关提示。原因：未在后端配置允许的请求源与请求头，未正确处理预检请求。
- 现象：调用流程图执行时，模型返回“chat：llm—model—response-empty”报错。原因：工具调用时未正确传递结构化参数，或数据源字段缺失导致模型无法生成有效响应。
- 现象：工具调用返回的结果字段单位不符，比如额定功率仅显示数值无对应单位。原因：未开启字段校验开关，或校验规则未覆盖发电装备专属的单位格式。

## 怎么确认配好了
- 发起一次针对发电装备运维日志的工具调用测试，使用FastGPT v4.17.0版本的工具调用模块，检查接口是否能正常返回解析后的结构化数据。
- 查看工具调用日志，确认`toolChoice`参数的取值与当前场景匹配，无异常报错信息。
- 手动输入包含专属单位的设备参数，验证字段校验开关是否能正确识别合规格式，拦截不符合要求的输入。
- 调用相同类型的文档两次，确认结果缓存是否按配置生效，无重复的工具调用记录。
