# 国有产业基金的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
国有产业基金的文书数据主要来自内部审批流程文件、项目尽调档案、合规审查报告、出资协议及年度运营总结。数据更新随项目推进与年度复盘触发，单份文档长度差异显著，短则数百字的批复文件，长则数万字的尽调报告。文档统一包含文号、决策主体、涉及金额、决策日期等字段，金额字段以万元为单位，日期字段采用标准公历格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
文档长度差异大，会导致单条文本块的token占用波动明显，对`defaultToken`与`maxToken`的配置提出明确要求。结构化字段包含标准化金额与日期，需与非结构化的描述性文本分开构建索引，避免向量混淆。数据更新无固定批量周期，增量索引的触发逻辑需适配项目级与年度级的更新节奏，不宜采用固定周期的全量重建。合规类文档的高召回精度需求，要求索引的召回规则需匹配业务场景的信息权重。FastGPT v4.17.0的索引模块可支持结构化与非结构化数据的分开构建，适配该类数据特征。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配国有产业基金文档的平均长度，避免单块token超出模型限制 |
| `maxToken` | 16384 | 匹配主流本地化向量模型的最大输入长度，适配长文档分块后的拼接需求 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 区分合规类与描述类文档的召回精度，避免误召回非相关项目材料 |
| 单次搜索上限 | 前10条 | 覆盖单份文书的核心关联信息，避免冗余结果干扰起草 |
| `defaultToken` | 1024 | 作为默认分块的token基准，平衡召回精度与索引存储成本 |
| 重排 | 开启 | 对召回结果进行二次排序，修正向量召回的语义偏差，适配合规文档的精准需求 |

## 容易做错的三处
- 现象：调用向量模型接口返回503状态码，default分组下text-embedding模型加载失败。原因：未根据国有产业基金的文档总量与更新频率调整模型并发配额，导致高并发请求超出节点承载上限。
- 现象：知识库容量估算无明确依据，无法匹配现有文书的存储需求。原因：未区分结构化字段与非结构化文本的向量存储占比，直接按总字符数估算导致结果偏差。
- 现象：本地化向量模型调用后召回结果语义偏差较大。原因：未针对基金文档的专业术语（如出资比例、投决流程、合规条款）调整模型适配参数，导致向量语义匹配不准确。

## 怎么确认配好了
- 上传单份典型的尽调报告，检查分块后的文本块长度是否符合预设的分块配置，无明显过长或过短的块。
- 发起基于合规条款的检索请求，核对召回结果的条数是否与单次搜索上限的配置一致。
- 查看索引存储的实时占用，确认存储成本与`defaultToken`配置的基准匹配。
- 触发增量更新任务，检查新增的基金项目文档是否能被正常索引并召回。
