# 国有资本投资公司的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
国有资本投资公司的文书与材料数据主要来源于内部国资监管报送文件、投资项目全流程文档、集团三会决议、年度经营报告及外部监管政策文件。数据更新节奏随业务场景变化：项目类文书随项目立项、尽调、批复等节点动态更新，年度类报告每年更新，监管政策类随政策发布即时同步。文档结构统一包含文号、发文主体、主题分类、正文内容、附件清单、落款单位与日期字段，字段单位遵循国资系统通用规范，文号采用“国资投〔年份〕序号”格式，正文单篇长度从数百字符到数万字符不等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的文书来源分散于多个内部业务系统与外部监管平台，要求HTTP接口支持多源数据拉取，需适配不同系统的鉴权规则。单篇文档长度跨度大，接口需支持大文本请求与响应，避免传输截断或超时。文书字段需严格遵循国资系统通用规范，接口返回数据需校验文号格式、主题分类字段合法性，不符合要求的内容需拦截处理。不同类型文书的更新节奏差异明显，接口需支持按需触发与定时同步两种模式，适配动态更新与周期性报送的需求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带国资系统统一分配的API令牌，有效期设置为7天 | 适配多源内部系统的鉴权规则，避免频繁刷新令牌干扰文书起草流程 |
| `variables` | 传入文书类型、所属项目ID、发文单位编码三类核心参数 | 匹配国资文书的分类与溯源要求，便于后续归档与监管报送 |
| `responseData` | 仅返回校验通过的正文、文号、附件清单字段 | 过滤无关数据，降低接口传输开销，符合国资文档的报送规范 |
| 超时时间 | 600秒 | 适配长文档的解析与传输需求，避免大体积文书传输时触发超时错误 |
| 重试次数 | 2次 | 应对内部业务系统的临时波动，减少单次接口调用失败导致的文书起草中断 |

## 容易做错的三处
- 现象：调用接口返回403状态码，提示令牌无权使用对应资源。原因：未使用国资系统统一分配的专属API令牌，或令牌权限未覆盖目标内部系统的文书数据接口。
- 现象：接口返回的文书内容中缺少文号或附件字段。原因：未在`variables`中传入发文单位编码等溯源参数，导致接口校验逻辑拦截了不完整的文档数据。
- 现象：长文档传输时触发超时错误。原因：未将接口超时时间设置为符合长文档传输的时长，默认超时配置不足以支撑数万字符的文书数据传输。

## 怎么确认配好了
- 调用配置好的HTTP接口，传入测试用的文书类型与项目ID，检查返回结果中包含预期的核心字段。
- 模拟不符合国资规范的错误格式文书数据调用接口，确认接口返回校验失败提示，符合预期的拦截逻辑。
- 连续调用接口多次，观察接口返回状态码与响应时长，确认无频繁超时或鉴权失败问题。
- 传入不同长度的测试文档，确认接口可正常接收并返回完整数据，适配不同场景的文书需求。
