# 国有资本投资公司的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
国有资本投资公司的文书数据主要来源于国资监管部门下发的规范性文件、集团内部管理制度、投资项目可研报告、股东会董事会决议及年度财务报告。数据更新按季度常规更新，临时项目文件随立项、审批节点同步更新。文档多为结构化格式，包含文号、发文单位、生效日期、条款条目，附带项目编号、监管层级、所属板块等字段，单位多涉及万元、亿元、持股比例等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
结构化的文书字段与专用术语，要求引用溯源时需精准匹配文号、项目编号等标识字段，避免泛化检索匹配到无关文档。按季度加临时节点的更新节奏，要求知识库同步机制需覆盖常规更新与临时新增场景，确保溯源数据的时效性。多类型的文书来源，要求检索范围需覆盖监管文件、内部制度与项目文档三类数据源，同时文书中涉及的国资监管专用表述，需确保检索模型能准确识别字段关联，防止溯源结果出现张冠李戴的情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 8000–12000 token | 国有资本投资公司单篇文书长度多在数千字，需覆盖完整引用的条款片段 |
| `responseData` | 包含文号、项目编号的元数据格式 | 需提取专属字段完成溯源校验，确保引用来源可追溯 |
| `detail` | 启用 | 需精准匹配文书中的国资监管专用术语与结构化字段，提升检索精度 |
| 单次检索召回上限 | 前6–10条 | 该品类数据源分类清晰，过多召回会增加后续筛选负担 |
| 知识库更新触发规则 | 每7天常规同步+临时项目节点触发 | 覆盖季度常规更新与临时项目文件两类数据场景 |

## 容易做错的三处
- 现象：检索结果匹配到无关文书，无法定位到目标项目的可研报告。原因：未启用`detail`参数的精准匹配模式，使用了泛化检索逻辑。
- 现象：知识库上传100个5kb文件后，仅50个显示训练完成。原因：未配置按文件类型过滤的上传规则，部分不符合格式的国资监管文件未被正确识别。
- 现象：设置`quoteMaxToken`为20000 token后，引用片段超出上下文窗口导致生成失败。原因：未结合单篇文书长度调整参数，过度扩大token上限导致上下文溢出。

## 怎么确认配好了
- 发起针对特定项目文号的检索请求，核对返回结果是否包含对应文书的文号、项目编号等专属元数据。
- 查看知识库同步任务列表，确认常规周期同步与临时项目触发的同步任务均正常执行。
- 生成一份文书起草内容，检查引用片段是否附带可追溯的原始文档来源信息。
- 调整检索相关参数后，对比不同配置下的召回结果，确认匹配精度符合业务需求。
