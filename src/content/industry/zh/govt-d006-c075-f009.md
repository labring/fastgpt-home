# 国有资本投资公司的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据主要来自内部办公系统、国资监管平台报送文件、年度经营台账与项目可研档案。更新节奏随业务节点动态调整，重大项目立项阶段实时新增文件，月度经营分析报告按月更新，年度预决算与年报按固定周期发布。文档多为多章节正式公文，包含文号、发文主体、执行条款、量化数据项，字段包含项目编码、出资额度、审批节点、监管要求编号等，单位多为万元、月。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的文书数据多为长章节正式公文，单篇文档长度较长且包含大量结构化量化数据，同时数据来源分散、更新频率随业务节点动态调整。这要求模型接入环节需适配长文本处理能力，避免上下文溢出导致内容截断；结构化数据占比高，需配置匹配结构化信息的召回逻辑，避免量化数据匹配失效；多源数据与动态更新的特性，要求配置灵活的数据源同步规则，保障知识库数据与业务现状一致。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 单篇国有资本投资公司文书多为长章节内容，该取值可覆盖完整文档上下文，避免内容截断 |
| `maxTokens` | 2000–3000 token | 文书起草类任务需生成完整段落内容，该取值可保障生成内容的完整性 |
| `quoteMaxToken` | 1500–2000 token | 需召回的结构化数据与参考文档占比高，该取值可保障召回内容的有效展示 |
| `temperature` | 0.3–0.6 | 文书需保持严谨规范，较低温度可降低生成内容的随机性，保障表述准确 |
| `AIPROXY_API_ENDPOINT` | 对接企业内部AI服务的专属域名 | 保障数据传输的安全性与合规性，符合国资监管的网络安全要求 |
| `AIPROXY_API_TOKEN` | 由企业内部权限系统生成的专属令牌 | 限制未授权访问，保障API调用的安全性 |

## 容易做错的三处
- 现象：知识库搜索响应超时，界面显示超时提示或状态码504。原因：未针对长文档与结构化数据调整上下文与召回配置，导致系统加载过多冗余数据。
- 现象：生成的文书出现专业术语偏差或格式不符合行业规范。原因：未配置匹配国资监管要求的prompt模板，导致模型输出不符合业务场景需求。
- 现象：向量召回结果匹配精度低或召回速度缓慢。原因：选用的embedding模型与结构化数据适配性差，或未根据本地硬件资源调整模型部署配置。

## 怎么确认配好了
- 上传单篇最长的内部文书，测试模型上下文加载状态，确认无内容截断提示，根据测试结果调整对应配置。
- 输入包含结构化数据的起草需求，核对召回结果中是否包含对应业务字段的有效数据，调整匹配规则至符合预期。
- 调用配置的API接口，测试`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的连通性，确认无权限或连接报错。
- 生成多篇不同类型的文书草稿，对比生成内容的严谨性，调整`temperature`参数至符合行业规范要求。
