# 国有资本运营公司的文书与材料起草：向量模型与索引

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
这个品类的数据主要来自国资监管部门下发的规范性文件、集团内部的投资并购协议、年度运营报告、子公司报送的国资划转方案，以及内部共享的飞书多维文档、Excel台账。更新节奏随业务节点调整，正式公文随项目推进更新，月度运营报告按月更新，子公司报送的台账类文档按季度更新。文档多为固定格式，包含文号、主送单位、正文、附件清单，业务文档包含交易主体、持股比例、资金额度等字段，单位涉及万元、百分比。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据包含多格式文档、多更新节奏、固定结构与多业务分类属性。多格式文档要求索引环节需适配飞书Excel、多维文档与结构化台账的解析适配能力；固定结构要求分块时需保留业务字段关联，避免破坏业务逻辑；多更新节奏需支持增量索引以减少全量重索引的资源消耗；多业务分类的文档则要求索引配置需限定召回范围，确保检索结果匹配对应业务场景，避免全知识库导出后检索混杂不同业务类别的内容。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类固定结构的业务文档，保留业务逻辑完整性，平衡向量嵌入效率 |
| 重叠长度 | 100–200 字符 | 保留跨段落的业务关联，避免上下文断裂 |
| 相似度阈值 | 0.75–0.85 | 匹配该品类专业文书的内容相关性要求，避免召回过多无关或过少有效结果 |
| 单次搜索上限 | 前 8 条 | 控制检索结果数量，适配国资运营场景下的上下文长度 |
| `defaultToken` | 2000 token | 适配常规业务文档的向量嵌入需求，平衡计算资源与嵌入精度 |
| `maxToken` | 12000 token | 容纳单轮检索后的完整业务上下文，满足长文书解析需求 |

## 容易做错的三处
- 导出全知识库后导入，检索结果混杂不同业务分类的文档，无法精准匹配当前业务场景。原因是未按业务分类配置索引的召回范围，直接使用全知识库索引，未区分业务分类维度。
- 导入飞书文件夹下的Excel文件和多维文档时，解析后的文档业务字段未被正确提取，向量嵌入时丢失关键业务信息。原因是未开启结构化文档的字段映射配置，未指定需要保留的业务字段关联。
- 外接向量模型API并在ARM软路由部署时，出现检索请求超时，返回报错状态码504。原因是未调整`defaultToken`的合理取值，嵌入计算资源不足，软路由算力有限，无法承载高token数的向量嵌入请求。

## 怎么确认配好了
- 导入飞书文件夹下的Excel和多维文档，检查解析后的文档是否保留了交易主体、持股比例等业务字段，确认结构化文档的解析配置正确。
- 发起指定业务分类的文书检索，查看召回结果是否仅包含对应分类的文档，确认召回范围的配置符合业务需求。
- 在外接向量模型API的ARM软路由环境下，发起向量嵌入请求，查看请求是否未出现超时报错，确认算力适配配置合理。
- 导出指定业务分类的知识库后重新导入，查看导入后的文档是否按业务分类组织，确认索引配置与业务分类匹配。
