# 城市公交的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
数据主要来源于城市公交企业内部的标准化运营手册、安全管理制度、票务服务规范、应急处置预案、公文模板库，以及属地交通主管部门发布的公交运营政策文件。文档以章节式结构化为主，包含适用场景、执行流程、责任主体等字段，涉及班次、客流、维保周期等专用单位。更新频率随政策调整或内部修订，核心文档每季度复核一次。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的文档特征对检索召回带来多重约束。结构化章节式文档要求检索需定向匹配对应场景的章节内容，避免召回无关的运维记录；多字段设计要求支持按责任主体、适用场景等字段精准匹配，提升文书起草的针对性；专用单位如班次、客流、维保周期的存在，要求检索需兼容术语的语义匹配，避免出现单位混淆的错误；非固定更新频率要求召回逻辑优先筛选近季度更新的政策与模板文档，避免使用过期内容。同时，统一的公文模板格式要求检索召回的内容需保留原有结构，确保可直接复用。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写，以下配置项均针对城市公交文书起草场景设置：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 城市公交文档多为专业合规内容，需过滤低相关性结果，同时保留足够候选用于文书起草 |
| `limit` | 前8条 | 文书起草需参考多份模板与政策，8条结果可覆盖常见场景的不同维度，同时控制上下文长度 |
| `searchMode` | 混合检索 | 兼顾语义匹配与关键词匹配，适配结构化文档的章节标题与内容关键词双重检索需求 |
| `usingReRank` | 开启 | 城市公交文档包含大量专业术语，重排可进一步筛选与文书起草场景高度相关的结果 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可自动扩展文书起草的问句关键词，比如将“春运调度”扩展为“春运 应急调度 公交 预案”，提升召回精准度 |
| `collectionIds` | 仅包含公交运营手册、政策文件、公文模板的集合 | 仅召回与城市公交文书起草直接相关的数据集，避免混入无关数据 |

## 容易做错的三处
- 现象：检索结果返回大量车辆维保、驾驶员考勤等非文书类内容，相关性不符合预期。原因：未限定专属数据集集合，召回了与文书起草无关的运营数据。
- 现象：输入“公交春运应急方案”后，仅返回字面匹配的少量结果，未覆盖客流管控、场站调度等相关场景。原因：未开启问题优化功能，未自动扩展问句的语义相关关键词，无法匹配隐藏的关联内容。
- 现象：上传的最新公交票价政策文件无法被检索到。原因：未将文件归类至指定的政策文档集合，或上传时未保留文档原有章节结构，导致关键条款无法被正确召回。

## 怎么确认配好了
- 上传1份城市公交公文模板与1份车辆维保记录，执行检索测试，确认仅返回公文模板相关结果，验证集合限定配置生效。
- 输入包含专业术语的问句，比如“新线路开通的申请文书模板”，确认召回结果包含对应章节的内容，验证问题优化与重排配置生效。
- 查看知识库的集合列表，确认仅包含运营手册、政策文件、公文模板三类数据集，验证指定集合ID的配置生效。
- 调整检索参数后，多次执行同一检索请求，确认返回结果的数量与相关性保持稳定，验证配置的一致性。
