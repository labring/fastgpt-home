# 城市公交的文书与材料起草：部署与升级

## 这个品类的数据长什么样
城市公交的文书与材料数据主要来自内部运营系统、场站管理台账、安全检查档案及对外公示文档。数据来源包括每日生成的班次调度单、月度营收报表、季度安全整改通知书，以及临时发布的线路调整公告。文档多为结构化表格与制式公文，包含线路编号、运营里程、载客人次、整改时限等固定字段，单位涵盖公里、人次、元、天等。数据更新频率差异较大，运营类文档每日更新，公告类按需发布，档案类按季度归档。

## 这些特征在「部署与升级」这一环带来什么约束
城市公交的文书数据特征对部署与升级环节带来明确约束。结构化文档占比高，要求部署时配置支持表格解析的预处理流程，避免非结构化拆分导致的字段丢失。数据更新频率差异大，每日更新的运营类文档需配置增量同步任务，避免全量同步占用过多系统资源。固定字段多且单位明确，要求知识库配置时提前绑定字段映射规则，防止导入时出现字段错位。部分运营文档涉及内部管理信息，部署时需配置分级存储的访问权限，确保数据安全。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定，适配城市公交文书起草的私有化部署场景。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 个并发连接` | 城市公交文书单次批量导入量较大，需适配高并发数据库连接需求 |
| `MONGODB_URI` | 本地私有部署的内网连接地址 | 存储运营档案、整改记录等非结构化文档，内网访问保障数据安全 |
| `REDIS_URL` | `1000 MB 内存配置` | 缓存高频查询的线路数据与实时调度信息，降低核心数据库的访问压力 |
| `STORAGE_S3_ENDPOINT` | 本地对象存储的内网访问地址 | 存储批量导入的月度台账、季度报表等大体积文档，适配批量数据存储需求 |
| `ROOT_KEY` | 自定义32位随机字符串 | 配置系统管理员访问权限，规避默认密钥带来的安全风险 |
| `FE_DOMAIN` | `本地IP:3000` | 私有化部署场景下，通过内网地址访问系统前端，无需公网域名 |

## 容易做错的三处
- 部署时出现`docker pull`镜像超时或`500 Internal Server Error`报错，原因是未配置内网镜像源或未关闭公网代理，导致无法访问官方镜像仓库。
- 生成的公交文书仅输出中文，即使prompt与知识库内容为英文，原因是未在系统配置中指定多语言模型的输出规则，导致模型调用参数未生效。
- 向量数据库连接失败，返回`503 Service Unavailable`状态码，原因是未正确配置内网代理规则，导致无法访问指定的向量数据库服务节点。

## 怎么确认配好了
- 执行`docker ps`命令，确认所有FastGPT相关容器处于运行状态，无异常退出记录。
- 上传一份公交月度营收报表至知识库，检查解析后的字段是否与预设映射规则一致，无字段缺失或错位情况。
- 发起一次文书生成测试，输入调度单生成需求，确认生成结果包含线路编号、班次数量等必填字段，格式符合制式公文要求。
- 访问`FE_DOMAIN`配置的内网地址，确认系统登录页面正常加载，管理员权限可正常启用。
