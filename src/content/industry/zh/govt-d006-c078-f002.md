# 城市水务的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
城市水务的文书与材料主要包括供水调度日志、水质检测报告、管网运维记录、水费催缴通知、应急处置方案等。数据来源涵盖内部业务系统导出的结构化CSV文件、巡检人员上传的PDF巡检报告、Word格式的运维方案文档。更新节奏分为日常实时更新的调度日志、每周或每月更新的水质报告，以及按需生成的应急方案与通知类文档。结构化数据包含巡检时间、管网点位、水质指标等字段，附带pH值、浊度、管径等单位；非结构化文档则有固定的报告表头与连贯的业务逻辑段落。

## 这些特征在「向量模型与索引」这一环带来什么约束
城市水务数据的多结构类型会对向量处理带来多重约束：十万级批量结构化CSV需适配高效的批量向量化流程，避免处理超时；非结构化长文本需严格控制分块规则，防止拆分破坏业务逻辑，比如不能将水质报告的检测项与结论分至不同分块。不同的更新频率要求索引支持增量更新与全量更新的灵活切换，而带单位的字段需保留语义关联，防止向量生成时丢失关键业务信息。同时，批量数据中的空字段与重复记录，会增加向量引擎的过滤与去重成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配城市水务文书的单块语义完整性，避免拆分水质检测报告的检测项与结论 |
| 重叠长度 | 50–100 字符 | 保留分块间的上下文关联，防止长文本的逻辑断裂 |
| 相似度阈值 | 0.75–0.85 | 过滤水务数据中重复的巡检记录与相似的运维方案 |
| 向量任务超时时间 | 600 秒 | 适配十万级CSV数据的向量化处理时长，避免任务中断 |
| `maxToken` | 4000 token | 覆盖城市水务常规文书的长度需求，符合FastGPT v4.17.0的参数边界 |
| `defaultToken` | 按实测标定 | 适配日常文书与批量数据的基础向量生成需求 |

## 容易做错的三处
- 知识库上传十万条CSV数据后，向量化完成后数据总量少了数千条。未过滤CSV中的空字段或重复记录，导致部分数据被向量引擎自动跳过。
- 创建集合显示创建成功，但页面索引一直无法建立。向量任务超时未完成，且未配置自动重试机制，导致索引进程卡住。
- 本地运行向量索引正常，Docker打包镜像后向量得分出现异常波动。Docker容器内未挂载本地的模型缓存目录，导致每次调用都重新下载模型，无法复用本地缓存的向量结果。

## 怎么确认配好了
- 上传单份1000字符的水务运维文档，查看向量生成耗时是否在预设的超时时间范围内。
- 导入十万条结构化CSV数据，核对最终索引的条目数与源数据条目数保持一致。
- 检索水质检测报告中的关键词，查看返回结果的相似度是否落在预设的阈值区间内。
- 重启Docker容器后再次执行向量任务，确认向量结果未出现异常波动。
