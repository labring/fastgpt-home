# 城市水务的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
城市水务的文书与材料起草相关数据，主要来源于水务运营台账、管网巡检日志、水质检测报告、排水许可申请档案、供水调度记录等。数据更新节奏依类型不同：管网巡检日志每日更新，水质检测报告按周或月更新，运营台账实时同步。文档结构多包含点位标识、时间戳、量化指标与执行要求，字段含管径（单位毫米）、水压（单位千帕）、污染物浓度（单位毫克每升）、许可有效期（单位日）等专属水务类字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
水务类数据的专属字段与单位要求，要求工具调用时需精准匹配字段名与单位，避免参数不匹配导致生成的文书出现指标错误。多源分散的数据来源，需要工具调用模块同时对接巡检、水质检测等多个数据源插件，增加了调用链路的复杂度。水务文书存在固定格式与合规要求，工具调用需同步调用格式校验插件，确保生成的材料符合水务行业规范。实时运营数据的更新节奏，要求工具调用的触发时机需与数据同步节点对齐，避免使用过期数据生成文书。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用触发时机 | 数据更新后10分钟内 | 匹配水务实时运营数据的更新节奏，避免使用过期信息 |
| `toolChoice` | auto | 适配多数据源并行调用的场景，自动匹配对应水务数据插件 |
| `functionCall` | 启用多工具并行 | 适配水务多源数据拉取的复杂场景 |
| 格式校验插件 | 开启 | 确保生成的水务文书符合行业合规要求 |
| 单次工具调用超时时间 | 600秒 | 覆盖多源水务数据拉取的耗时需求，按实测标定 |
| 工具调用结果缓存时长 | 30分钟 | 平衡数据时效性与调用链路的资源消耗 |

## 容易做错的三处
- 现象：工具调用后返回结果耗时超过预设阈值，出现超时报错。原因：未匹配水务数据的更新节奏，调用了未及时更新的多源数据源插件，导致数据拉取耗时过长。
- 现象：生成的文书中同时包含前后两次工具调用的结果，字段出现内容叠加。原因：未正确配置`toolChoice`参数，导致工具调用的上下文未正确重置，上一次调用的结果被带入当前流程。
- 现象：工具调用模块持续输出冗余的运行日志，占用界面与日志存储空间。原因：未关闭工具调用的详细日志开关，默认开启了全链路日志输出，不符合水务场景下轻量化查看最终结果的需求。

## 怎么确认配好了
- 手动触发一次工具调用，查看返回结果的字段是否包含水务专属指标与对应单位，核对是否与数据源的字段定义一致。
- 检查工具调用的输出内容，确认仅展示最终生成的文书材料，无冗余的运行记录。
- 对比工具调用的实际耗时与配置的超时时间，确认耗时未超出合理范围，符合水务数据拉取的需求。
- 查看格式校验插件的反馈结果，确认生成的文书符合水务行业的格式规范要求。
