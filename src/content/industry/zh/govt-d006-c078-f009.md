# 城市水务的文书与材料起草：模型接入与配置
本文基于FastGPT v4.17.0版本的配置逻辑编写。

## 这个品类的数据长什么样
城市水务的文书数据主要来自管网监测系统、水质检测实验室、报修服务平台与水厂运行台账。数据更新节奏分两类：实时类包括用户报修记录、管网压力波动日志，批量类包括每日水质检测报告、月度供水调度方案。文档结构多为结构化表格与半结构化文本，核心字段包含采样点位编号、检测指标数值与对应单位（如mg/L、MPa）、报修地址、处理流程节点，部分文档还附带现场拍摄的设备照片。

## 这些特征在「模型接入与配置」这一环带来什么约束
城市水务的文书数据兼具结构化表格、半结构化文本与现场照片三类形态，且包含COD、氨氮等专属检测指标与mg/L、MPa等专用单位。该特征要求模型接入配置需支持结构化字段的精准映射，避免单位识别错误。实时更新的报修与管网数据，要求上下文窗口需适配短周期数据接入，避免冗余旧数据干扰文书生成。部分文档附带现场设备照片，要求配置需开启视觉识别能力以提取图片中的参数信息。多来源数据的格式差异，要求接入配置需兼容不同数据源的字段规则，避免字段错位引发的文书内容偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 水务文书常包含多份检测报告与调度日志，需容纳较多上下文信息以确保生成内容完整 |
| `temperature` | 0.2–0.4 | 水务文书需严谨准确，不宜过度发散，该区间可平衡内容准确性与灵活性 |
| `vision` | 开启 | 部分水务文书附带现场设备照片，需提取图片中的设备编号与参数信息 |
| `AIPROXY_API_ENDPOINT` | 填写对应模型资源的专属接入地址，如Azure OpenAI资源的endpoint | 适配水务场景的模型调用需求，确保请求路径与协议匹配 |
| `maxTokens` | 1500–2000 token | 单篇水务文书的生成长度通常处于该区间，可避免生成内容过长或过短 |
| `quoteMaxToken` | 4000 token | 需保留足够的引用数据用于文书佐证，确保生成内容有可靠依据 |

## 容易做错的三处
- 调用模型时返回400状态码，提示“invalid api version”或“unsupported endpoint”，原因是未将Azure OpenAI的专属接入地址配置到`AIPROXY_API_ENDPOINT`，且未适配Azure的API路径与版本规则。
- 生成的水务文书中出现单位混淆，例如将“mg/L”识别为“g/L”，原因是未针对水务专属检测指标与单位配置模型的术语提示，或`temperature`取值过高导致模型发散。
- 生成的文书缺失核心字段，例如缺少采样点位编号或检测时间，原因是`maxContext`取值过小，未容纳完整的数据源字段信息。

## 怎么确认配好了
- 导入一份标准水务水质检测报告的结构化数据，触发文书生成，核对生成内容是否包含正确的采样点位编号、检测指标与对应单位。
- 上传一张水务管网设备的现场照片，开启`vision`配置后，核对模型是否能准确提取照片中的设备编号与参数信息。
- 配置Azure OpenAI的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`后，发起测试调用，核对返回结果无格式报错，且匹配预期的模型响应。
- 调整`temperature`取值至0.2–0.4区间，生成多篇测试文书，核对内容保持严谨，无过度发散的表述。
