# 城市燃气的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
城市燃气的文书与材料数据主要来自燃气运营管理系统、GIS管网平台、用户报装与通气业务库。数据来源包括日常巡检台账、报装申请单、通气验收报告、管道改造方案等。更新节奏分三类：巡检记录每日更新，报装与通气数据每月更新，管网改造方案按项目周期更新。文档以结构化字段为主，包含管网编号、用户地址、工作压力（单位kPa）、施工日期、整改项等，部分附带现场影像附件。

## 这些特征在「工具调用与插件」这一环带来什么约束
城市燃气的结构化字段与多更新节奏特征，对工具调用与插件配置带来明确约束。带单位的压力值、施工日期等字段，要求插件调用时需强制匹配预设格式，避免单位转换或字段错位错误。多来源数据的更新周期差异，需在插件逻辑中加入时效性过滤规则，仅调用7天内的巡检记录、当月的报装申请数据。附带现场影像的文档，需插件支持多模态解析，否则无法提取附件内的整改文字内容。管网编号关联要求，需在工具调用时加入编号校验，避免跨区域数据混淆。

## 配置怎么定
本章节配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配燃气文书起草的多工具调用场景，覆盖不同业务类型的文档生成需求 |
| `functionCall` | `enabled` | 强制生成结构化的工具调用参数，确保输出符合燃气业务字段的格式要求 |
| 单次工具调用上限 | 前3条 | 燃气业务单条数据体量适中，过多调用会超出上下文窗口限制 |
| 工具调用超时时间 | 60 秒 | 内部业务数据接口响应通常在30秒内，预留合理缓冲时间 |
| 多模态插件开关 | 开启 | 部分燃气文书附带现场影像附件，需支持解析附件内的文字内容 |

## 容易做错的三处
- 导入燃气业务文档时返回500错误。原因是未开启多模态插件开关，无法解析文档附带的现场影像附件，导致系统解析流程中断。
- 调用联网工具时无法获取燃气数据引用。原因是未配置工具调用的数据源过滤规则，未限定仅调用燃气业务库内的合规数据。
- 工具调用后生成的文书字段单位错误。原因是未开启`functionCall`强制格式校验，导致生成的压力值未匹配kPa单位要求。

## 怎么确认配好了
- 上传一份带现场影像的燃气巡检报告，查看系统是否能成功解析附件内的整改文字内容。
- 配置`toolChoice`为`auto`后，发起起草通气验收报告的请求，查看系统是否自动调用对应工具获取管网数据。
- 发起工具调用请求，等待60秒内是否返回正常结果，验证超时时间配置是否生效。
- 生成的文书中检查压力值字段是否带有kPa单位，验证`functionCall`的格式校验是否生效。
