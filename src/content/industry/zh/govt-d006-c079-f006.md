# 城市燃气的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
城市燃气的业务数据主要来源于企业内部运营台账、管网运维档案、用户服务文档、安全规范文件。数据来源覆盖管网巡检、用气报装、安全告知、场站运行、用户缴费等全业务环节。更新节奏分为实时（用气报装、缴费记录）、每日（巡检日志、场站运行记录）、定期（行业安全规范更新）。文档结构包含结构化字段与非结构化文本，结构化字段含管网编号、检测压力值、用户编号等，单位多为兆帕（MPa）、立方米（m³）、户，非结构化文本多为巡检描述、整改方案等内容。

## 这些特征在「引用来源与溯源」这一环带来什么约束
业务数据分散在多类业务系统，溯源需关联不同业务场景的知识库分片，避免召回范围局限。实时更新的报装、缴费数据要求溯源支持实时向量召回，无法依赖固定周期的离线索引。结构化字段与专用单位的存在，要求溯源时需匹配字段标识与单位信息，确保引用内容与业务场景对应。文档长度跨度大，短文本的安全告知需完整保留引用内容，长文本的管网报告需保留上下文关联，防止溯源时丢失关键业务信息。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 覆盖城市燃气短文本安全告知与长文本管网报告的引用片段需求 |
| 引用召回条数 | 前 3–5 条 | 聚焦燃气业务核心引用内容，避免冗余信息干扰生成 |
| `responseData` | 开启结构化元数据返回 | 匹配城市燃气数据的结构化字段与专用单位，确保溯源准确性 |
| 知识库分片匹配 | 按业务场景分组匹配 | 适配燃气数据分散在多业务系统的特征，缩小召回范围 |
| `detail` | 开启完整引用内容 | 满足燃气业务合规要求，完整展示原始引用文档片段 |
| 最大上下文长度 | 4000–6000 字符 | 覆盖长文本运维报告的上下文关联需求 |

## 容易做错的三处
- 现象：调用接口返回状态码200，但content字段为空。原因：`quoteMaxToken`取值过小，导致引用片段被完全截断，无法生成有效内容。
- 现象：生成的引用内容出现乱码或格式混乱。原因：未开启结构化元数据返回，未匹配燃气数据的专用单位与字段标识，导致原始文档的格式信息丢失。
- 现象：生成的文书中未显示知识库引用的来源内容。原因：未配置`detail`参数开启完整引用返回，仅召回了元数据未展示原始片段。

## 怎么确认配好了
- 发起测试请求，查看返回结果中的content字段是否包含生成的文书内容，且包含引用来源片段。
- 核对引用内容的字段与单位，确认与城市燃气业务数据的标准格式一致。
- 检查召回的引用条数是否符合预设的业务场景需求，无冗余或过少的情况。
- 验证实时业务数据（如用气报装记录）的引用是否能在生成的文书中及时体现。
