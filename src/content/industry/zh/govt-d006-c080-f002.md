# 城投平台的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
城投平台的文书与材料主要来自内部项目审批档案、融资申报文件、政府公告公示、日常办公公文。数据更新随项目进度与办公流程推进，项目类文档按季度批量更新，日常公文随审批实时新增。文档统一包含文号、发文主体、成文日期、正文内容、附件标识等字段，部分项目类文档附带项目编号、所属区域、预算金额等结构化字段，金额类字段单位多为万元。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 城投平台文书正文多为连贯段落，该长度可保留完整业务语义单元，避免单块过长导致向量计算偏差 |
| 重叠长度 | 100–200 字符 | 弥补分块后的语义断裂问题，保障跨块内容的上下文连贯性 |
| `maxToken` | 8192 token | 适配主流向量模型的输入上限，匹配城投平台文书的平均内容长度 |
| 相似度阈值 | 按实测标定 | 适配城投文书的业务语义匹配精度，避免召回无关文档或遗漏有效内容 |
| 单次搜索上限 | 前8条 | 覆盖城投项目类文书的主要关联范围，减少冗余结果干扰 |
| `defaultToken` | 4096 token | 设置标准上下文窗口，平衡生成内容的完整性与响应速度 |

## 容易做错的三处
- 现象为切换豆包向量模型后，搜索返回的相似度数值为10000+，无法通过常规0-1范围的阈值过滤。原因是未调整向量模型的归一化配置，导致相似度计算结果未做区间缩放。
- 现象为导入文本数据集后，知识库状态持续显示为索引中，无法完成初始化。原因是批量导入的文档数量超出当前索引节点的并发处理上限，或未配置增量索引的调度阈值。
- 现象为使用对应模型时提示无可用频道，无法启动索引任务。原因是未在平台配置中添加对应模型的API调用频道，或频道权限未开通。

## 怎么确认配好了
- 上传1份城投平台典型文书，核对索引状态是否在合理时间内更新为就绪
- 发起与文书业务相关的查询，检查返回结果的语义相关性是否符合业务判断
- 测试批量导入同类型文档，确认索引任务可自动完成且无异常报错
- 切换至目标向量模型，验证相似度计算结果的区间适配当前配置的过滤规则
