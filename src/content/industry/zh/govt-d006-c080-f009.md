# 城投平台的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
城投平台的文书与材料起草相关数据，主要来源于内部项目管理系统、财政部门推送的官方文件、OA审批归档内容。文档类型包含项目立项报告、债务融资方案、月度运营报表、政府批复文件等，单份文档长度差异较大，部分年度审计报告篇幅较长。每份文档包含统一格式的字段，包括文号、项目名称、责任主体、涉及金额、审批单位、生效日期等，金额字段多以万元为单位，时间字段以公历日期或工作日为单位。数据更新无固定周期，随项目推进、报表提交或政策调整触发更新。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 12000–16000 token | 城投平台文书多包含多份关联文档，需容纳完整的项目背景与批复内容 |
| `maxTokens` | 2000–3000 token | 单份起草文书需覆盖项目核心信息，避免生成内容被截断 |
| `temperature` | 0.3–0.5 | 城投文书需保持官方严谨风格，不宜过度发散 |
| `AIPROXY_API_ENDPOINT` | 填写平台分配的专属接入地址 | 保障城投平台数据传输的合规性与安全性 |
| `AIPROXY_API_TOKEN` | 使用绑定专属场景权限的令牌 | 符合国资监管要求，避免跨品类数据访问风险 |
| `toolChoice` | auto | 根据文书类型自动调用文档检索工具，补充缺失的项目数据 |

## 容易做错的三处
- 调用模型时返回403该令牌无权使用模型错误，原因是未为令牌绑定城投场景专属的模型权限，或未在接入平台中配置对应模型的访问范围。
- 生成的文书缺失项目核心字段，原因是未在提示词中明确要求提取城投文档中的文号、责任主体等必填字段，导致模型遗漏关键信息。
- 知识库召回结果不完整，原因是未根据城投长文档特性调整上下文参数，超出`maxContext`阈值后截断召回内容。

## 怎么确认配好了
- 执行模型接入测试，验证返回结果中无权限相关报错，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确。
- 导入一份典型城投项目文书，触发起草流程，核对生成内容是否包含文档中的核心字段与数据。
- 调整`temperature`参数，对比不同取值下的文书风格，确认符合场景要求的严谨性。
- 查看知识库召回日志，确认召回的文档数量与类型匹配当前起草任务的需求。
