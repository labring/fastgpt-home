# 基础化工的文书与材料起草：文档解析与分块

## 这个品类的数据长什么样
基础化工的文书与材料主要来源于生产台账、原料质检报告、工艺规程、安全合规手册及设备运维记录。数据更新节奏覆盖日常实时更新的生产台账，以及季度或年度修订的合规文件。文档结构包含固定表头的结构化表格、长段落的工艺说明，以及带章节编号的规范文本，字段与单位包含吨、千克、摩尔浓度、MPa等化工专用计量标识，部分文档同时包含纯文本说明与内嵌表格数据。

## 这些特征在「文档解析与分块」这一环带来什么约束
基础化工文档的多类型结构与专用计量特征，对解析分块环节带来多重约束。结构化表格类文档需要保留字段与单位的关联，避免解析后数据错乱；长段落工艺说明无强制换行，仅依赖默认分隔符易导致上下文断裂；大型合规手册PDF体积可达2-3M，易触发解析超时；部分企业数据存储于自有数据库，需支持结构化导入与字段关联解析，同时需适配Excel格式的原料清单等批量文件。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 平衡化工文档中短字段检测数据与长段落工艺说明的上下文连贯性，避免分块过碎或过长 |
| `chunkSplitter` | 自定义分隔符+换行符 | 适配化工文档中“第X章”“检测报告”等章节分隔与自然换行的混合结构，精准拆分独立文档单元 |
| `customPdfParse` | 启用结构化解析 | 保留化工文档内嵌的质检表格、工艺流程图说明的字段与格式，避免纯文本解析丢失结构化数据 |
| `UPLOAD_FILE_MAX_SIZE` | 3000 MB | 覆盖2-3M的大型工艺手册PDF上传需求，避免因文件体积超限报错 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大型PDF文档的解析耗时，防止中途触发超时失败 |
| `chunkSettingMode` | 手动配置 | 针对不同类型的化工文书（如台账、手册、报告）灵活调整分块规则，适配格式差异 |

## 容易做错的三处
- 现象：上传3M的化工合规手册PDF后，界面提示解析失败，后台日志返回超时错误。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认时长不足以完成大型文档的全量解析。
- 现象：自定义分隔符设置为换行符后，分块结果要么合并多个独立的质检段落，要么拆分单个完整的工艺说明。原因：未结合`chunkSplitter`配置混合分隔规则，仅使用换行符无法适配化工文档中长段落无强制换行的结构。
- 现象：尝试导入Excel格式的原料台账时，数据库连接失败，解析后的字段为空或单位丢失。原因：未配置对应数据源的连接参数，且未启用结构化解析逻辑，无法识别Excel中的字段与单位关联。

## 怎么确认配好了
- 上传单份1.5M的化工质检PDF，查看解析后的分块结果，确认每个分块包含完整的检测数据与说明段落。
- 上传Excel格式的原料台账文件，检查解析后的字段是否保留了原料名称、批次、检测值与对应单位。
- 查看系统后台的文件上传与解析日志，确认上传与解析过程未触发超时或格式错误。
- 调整`chunkSize`参数后，对比不同取值下的分块效果，确认分块粒度符合当前处理文档的类型需求。
