# 基础化工的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
基础化工的文书数据主要来自企业内部的工艺操作规程、物料质检台账、安全合规文件、产品配方文档等。数据更新节奏随工艺迭代、合规要求变更不定期触发，无固定周期。文档结构包含多列结构化表格、长文本SOP、合规函件等，字段包含CAS号、浓度、生产批号、检测温度等，单位多为吨、千克、摩尔浓度、摄氏度等。

## 这些特征在「模型接入与配置」这一环带来什么约束
基础化工的结构化表格数据要求分段需按行或字段组拆分，避免跨行拼接导致的语义断裂。专业化工术语与精准参数要求模型需准确匹配数据源中的字段，不能随意改写。不定期更新的数据要求配置可灵活调整的数据源同步路径。长文本文书需适配足够的上下文窗口，避免关键工艺参数被截断。此外，部分文书包含多页拼接的合规文件，需保证分段后上下文的连贯性，防止出现参数前后不一致的问题。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |

| `maxContext` | 8000–12000 token | 基础化工文书常包含多段工艺参数与合规要求，需覆盖完整上下文 |
| `maxTokens` | 2000–3000 token | 文书起草输出需涵盖完整配方、检测步骤等细节 |
| `temperature` | 0.3–0.5 | 需保证化工术语与参数的准确性，避免生成偏差 |
| `quoteMaxToken` | 1500–2000 字符 | 基础化工数据多为结构化表格与长段检测报告，需保留足够引用内容 |
| `vision` | 关闭 | 多数基础化工文书为文本格式，无图片解析需求 |
| `AIPROXY_API_ENDPOINT` | 按企业内部网络环境填写 | 适配企业防火墙限制，确保模型调用链路正常 |

## 容易做错的三处
- 现象：多列化工台账excel导入后自动分段混乱，部分行被拆分到不同数据块。原因：默认自动分段逻辑未识别结构化表格的行结构，未按行粒度拆分数据。
- 现象：调用模型时返回连接超时错误，日志显示API端点无法访问。原因：未配置内部代理地址，直接调用外部模型接口，受企业防火墙限制无法连通。
- 现象：上传化工安全规程的图片后，模型无法解析图片中的文字参数。原因：未开启`vision`配置项，或未按要求上传符合格式的图片文件。

## 怎么确认配好了
- 上传一份标准化工质检excel，触发分段测试，检查数据块是否按行拆分。
- 调用测试接口，输入一段化工工艺起草需求，查看输出是否包含准确的专业术语与参数。
- 查看模型调用日志，确认API请求已通过配置的代理地址发送，无超时报错。
- 调整`temperature`参数并对比输出效果，确认生成内容的严谨性符合业务要求。
