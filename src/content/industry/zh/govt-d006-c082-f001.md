# 基础电信运营的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
基础电信运营的文书数据主要来自内部运营支撑系统、合同管理平台、客户服务工单库与运维日志系统。数据更新节奏覆盖实时（客户工单、故障通报）、每日（运维日报）、季度（制式合同模板）三类。文档结构多为结构化字段加自由文本，字段包含工单编号、业务场景、服务时长、故障等级、客户联系方式等，单位涉及小时、条、元、GB等，部分文档附带附件链接与设备编码。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于数据来自多套内部系统，接口需要支持多源数据拉取与格式转换，需兼容不同系统的认证规则。实时类工单数据要求接口超时设置匹配业务响应阈值，避免延误文书生成。结构化字段多的特征要求接口请求参数需严格对应固定字段名与单位，避免格式不兼容。附带附件的文档需额外配置文件传输相关的接口参数，确保附件正常关联。制式合同模板的季度更新要求接口支持定期拉取最新模板库，保障生成文书的合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {内部系统生成的API令牌}` | 基础电信运营内部系统多采用Bearer令牌认证，保障接口调用安全，FastGPT v4.17.0版本支持该认证格式 |
| `variables` | `{"template_id": "qxd_2024_v1", "service_type": "fault_report"}` | 匹配电信运营文书的制式模板与业务场景字段，确保生成内容符合内部合规要求 |
| `responseData` | `仅返回生成的文书文本与关联附件ID` | 过滤冗余数据，适配电信运营文书的核心输出需求，减少外部系统的数据处理负担 |
| 单次调用模板库更新间隔 | `7 天` | 制式合同模板季度更新，7天同步可兼顾时效性与系统负载 |
| 接口超时时间 | `30-60 秒` | 电信运营文书生成涉及多源数据拉取，30-60秒可覆盖多数业务场景 |
| 附件关联规则 | `按文档字段自动匹配附件链接` | 电信运营文书常附带设备运维附件，自动匹配可减少人工配置成本 |

## 容易做错的三处
- 现象为调用接口后返回的生成文书与预期模板不符，字段缺失，原因是未正确配置`variables`参数对应业务场景字段，导致无法匹配制式模板。
- 现象为接口返回401未授权错误，原因是`Authorization`参数未携带内部系统生成的有效令牌，或令牌过期未及时更新。
- 现象为生成的文书未关联对应附件，原因是未配置附件匹配规则，或附件链接字段与接口参数不对应。

## 怎么确认配好了
- 调用FastGPT v4.17.0版本的测试接口，查看返回的`responseData`是否包含预期的文书文本与附件ID，核对字段是否与内部系统数据一致。
- 检查`Authorization`参数的有效性，通过内部系统的令牌验证工具确认未过期，且格式符合Bearer认证要求。
- 触发模板库同步动作，查看系统日志是否显示最新模板已拉取，匹配当前业务场景的文书生成逻辑。
- 模拟生成包含附件的文书，确认附件链接已正确关联到生成结果，可通过内部系统的附件验证工具确认链接有效性。
