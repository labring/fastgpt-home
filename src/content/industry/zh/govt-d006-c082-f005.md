# 基础电信运营的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
基础电信运营的文书数据主要来自运维工单系统、计费结算系统、客户服务台账与网络质量报表。数据更新节奏分为实时与每日两类，工单与故障记录实时生成，月度计费报表每日同步更新。文档结构包含工单编号、客户主体信息、故障时长、计费周期、网络指标数值等字段，单位涵盖分钟、元、GB、响应次数等，部分文档需关联特定基站ID与带宽参数。

## 这些特征在「工具调用与插件」这一环带来什么约束
实时工单与故障数据要求工具调用的响应延迟控制在合理区间，否则无法支撑即时文书生成。多源异构数据需要插件适配不同系统的API认证与返回格式，避免数据解析失败。字段包含特定单位与专属标识，工具调用时需明确参数匹配规则，防止因单位转换或标识缺失导致生成内容不符合业务规范。批量月度报表处理需限制单次调用的文档数量，避免上下文窗口溢出。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配多类型文书生成场景，自动选择最匹配的工具调用逻辑 |
| `functionCall` | 启用 | 强制结构化返回工具调用参数，适配电信业务字段的标准化要求 |
| 插件超时时间 | 30–60 秒 | 匹配实时工单数据的生成节奏，避免因等待过久导致文书生成中断 |
| 单次调用文档上限 | 前 10 条 | 控制上下文窗口占用，适配月度报表批量处理的场景 |
| 插件请求体大小 | 200–500 KB | 适配基础电信运营系统API的传输限制，避免请求被拦截 |
| 上下文窗口预留量 | 1200–1500 token | 适配电信业务文书的内容长度，避免上下文溢出 |
| 参数格式校验 | 启用 | 匹配电信业务字段的单位与标识规则，防止生成内容出现格式错误 |

## 容易做错的三处
- 现象：插件返回的图片URL无法在生成的文书中显示，仅显示纯文本链接。原因：未在插件配置中启用内容渲染开关，导致工具返回的多媒体链接未被解析为可展示格式。
- 现象：调用本地MCP服务时出现连接超时报错。原因：未在插件配置中填写正确的本地服务地址与端口，或未开放对应端口的网络访问权限。
- 现象：工具调用返回的结果与直接使用LLM function call不一致。原因：未正确配置`functionCall`的参数校验规则，导致FastGPT对工具返回的结构化数据处理逻辑与原生调用存在差异。

## 怎么确认配好了
- 上传一份基础电信运营的真实工单文档，触发文书生成任务，检查工具调用日志中是否显示正确的参数调用记录。
- 查看生成的文书内容，确认其中包含的业务字段与原始数据的单位、标识完全匹配。
- 测试调用本地MCP服务或外部API插件，确认返回结果能正确嵌入文书并按预期格式展示。
- 调整插件超时时间参数，模拟超时场景，检查系统是否能按配置触发重试或报错逻辑。
