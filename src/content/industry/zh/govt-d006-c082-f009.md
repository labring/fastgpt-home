# 基础电信运营的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
基础电信运营的文书数据来源包括运维工单系统、政企客户服务档案、网络建设方案文档、资费政策公示文件、客户投诉反馈函等。更新节奏为日常工单实时更新，季度性规划文档每月更新，年度资费政策每年调整。文档结构分为两类，一类是带标准化字段的结构化文书，包含工单编号、受理时间、故障等级、涉及基站ID等字段；另一类是非结构化的长文本文档，比如网络优化报告、政企合作协议，单篇长度可达数千字符。

## 这些特征在「模型接入与配置」这一环带来什么约束
结构化文书的标准化字段要求模型调用时能精准匹配指定业务字段，避免提取结果偏离业务需求；实时更新的工单数据要求上下文窗口配置适配高频新增的业务内容，防止上下文溢出导致调用中断；长文本类的网络优化报告、合作协议需要模型支持长上下文处理，同时保证关键信息提取的准确度；不同文书的字段差异要求配置时兼容多类型文档的解析逻辑，避免跨场景调用时出现格式不统一的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配基础电信运营的长文本文书，避免上下文溢出导致调用失败 |
| `maxTokens` | 2000–3000 token | 满足政企合作协议、网络优化报告等长文书的起草与内容生成需求 |
| `temperature` | 0.3–0.6 | 平衡文书起草的规范性与灵活性，避免生成内容偏离业务规范 |
| `toolChoice` | 自动模式 | 适配多类型文书的自动字段提取与内容生成需求，无需手动指定工具 |
| `AIPROXY_API_ENDPOINT` | 按部署环境配置的内网专属接口 | 适配基础电信运营的内网部署场景，保障业务数据安全 |
| `AIPROXY_API_TOKEN` | 按权限分配的专属令牌 | 限制模型调用的访问权限，防止未授权的接口调用 |

## 容易做错的三处
- 现象：模型调用返回超时错误或状态码500，生成内容为空或不完整。原因：未适配基础电信运营的长文本文书，`maxContext`配置值过小，导致上下文溢出。
- 现象：FastGPT部署在Windows系统后，设备重启后模型配置与应用配置丢失。原因：未将配置文件存储在系统非临时目录，重启后临时目录被清空。
- 现象：生成的文书字段缺失或格式不符合业务规范。原因：`toolChoice`配置为手动模式，未自动匹配文书对应的业务字段提取规则，导致关键信息未被正确提取。

## 怎么确认配好了
- 提交一篇标准运维工单文档，调用模型进行字段提取，核对提取结果与文档内的工单编号、故障等级等字段一致。
- 调用模型生成一份简易的资费公示草稿，检查输出内容的格式与业务规范匹配，无明显偏离。
- 查看FastGPT v4.17.0版本的模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无连接超时或授权失败记录。
- 调整`temperature`参数至0.5，生成两篇同类型文书，检查生成内容的一致性与灵活性平衡效果。
