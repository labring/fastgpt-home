# 基础设施建设的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
基础设施建设的文书与材料数据主要来源于施工过程中的施工日志、现场签证单、分项工程验收报告、竣工归档资料等。数据更新节奏随施工节点推进，日常施工类文书每日更新，验收类文书随分项工程验收完成后同步更新。文档结构包含固定字段：项目编号、施工标段、作业日期、材料规格型号、验收结论、现场工况描述，字段单位多采用建筑施工通用标准，如米、立方米、吨、工作日等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
基础设施建设文书的固定字段要求HTTP接口请求必须携带项目编号、施工标段等必填工程标识字段，缺失会导致生成内容偏离项目场景。数据更新节奏随施工节点波动，接口调用频次需匹配作业周期，避免高频调用占用系统资源。文档长度跨度大，短则数百字符的施工日志，长则数万字符的竣工资料，接口需支持动态适配请求体大小。工程专属单位要求接口返回的字段单位需严格遵循建筑施工通用标准，避免外部系统解析出错。

## 配置怎么定
本文档适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ------------ |
| `Authorization` | `Bearer {有效CHAT_API_KEY}` | 符合FastGPT接口鉴权规范，确保请求被合法识别 |
| `variables` | `包含项目编号、施工标段、作业日期的JSON对象，字段值按工程标准填写` | 为文书生成绑定专属项目上下文，避免生成脱离实际工程的内容 |
| `responseData` | `仅返回结构化的文书正文与对应字段映射，过滤非必要调试字段` | 适配外部系统的归档与流转需求，减少无效数据传输 |
| 最大上下文 | `8000–12000 字符` | 适配基础设施建设文书的长度跨度，避免截断关键工程数据 |
| 单次搜索上限 | `前 8 条` | 匹配工程类文书的关联数据量，兼顾生成质量与接口响应速度 |
| 问题优化 | `开启` | 对工程类术语进行标准化处理，避免生成不符合建筑规范的表述 |

## 容易做错的三处
- 现象：启动后接口调用返回401 Unauthorized，容器日志显示鉴权失败。原因：未在docker-compose.yml中正确配置CHAT_API_KEY环境变量，且未重建容器使新配置生效。
- 现象：调用文书生成接口后返回内容缺失工程专属字段，或生成内容与项目无关。原因：未在`variables`中传入项目编号、施工标段等必填工程字段，导致生成逻辑缺乏有效上下文。
- 现象：调用知识库文件列表接口返回的结果与实际工程文档数量不符。原因：未正确设置单次搜索上限参数，或未按工程文档的分类字段过滤返回结果。

## 怎么确认配好了
- 发起一次携带工程专属`variables`字段的测试请求，检查接口返回的`responseData`中是否包含贴合项目信息的文书内容。
- 查看接口鉴权日志，确认`Authorization`字段被正确解析，无鉴权失败相关报错。
- 对比外部系统接收的字段与建筑施工文档的标准字段清单，确认所有必填字段均已完整返回。
- 调整最大上下文参数，测试不同长度的工程文档生成请求，确认无强制截断或接口报错。
