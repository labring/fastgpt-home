# 基础设施建设的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
基础设施建设的文书与材料起草相关数据，主要来源于项目管理系统、BIM台账、现场巡检记录、合同附件及过往竣工档案。数据更新节奏随文书类型差异明显：现场周报每周同步更新，工程签证单随现场变更实时提交，竣工类资料则在项目收尾阶段批量归集。单份文书固定包含项目编号、标段代码、签发日期、责任班组、量化事项及附件清单字段，量化字段多采用立方米、平方米、元、天作为单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
基础设施建设文书的数据分散来源与差异化更新节奏，要求多轮对话必须先绑定项目编号与标段作为上下文锚点，避免跨项目数据混淆。实时更新的签证单与周报，要求提示词需明确指定优先调用当前会话绑定项目的最新数据，防止引用过时信息。固定的量化字段与专属单位，要求提示词需强制匹配对应标段的单位格式，确保生成文书的计量规范统一。批量归集的竣工档案，则要求多轮对话支持按关键词批量召回历史文档，同时保留每一轮会话的项目上下文关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前项目的唯一标段编号作为值 | 锚定会话上下文，避免跨标段数据混淆，适配多项目并行的施工场景 |
| `messages` | 每轮会话保留前8条历史消息，自动截断更早内容 | 平衡上下文完整性与响应速度，适配基础设施建设文书多轮沟通的节奏 |
| `variables` | 预设项目编号、标段代码、常用计量单位三个变量 | 强制匹配基础设施建设文书的固定字段，确保生成内容符合项目规范 |
| 单次会话最大上下文长度 | 8000–12000 token | 覆盖单份核心施工文档与多轮沟通的上下文需求 |
| 数据召回优先级 | 优先召回近7天更新的文档 | 适配基础设施建设现场数据实时更新的特点，避免引用过时信息 |
| 文书类型模板绑定 | 按签证单、进度报告、验收资料分类绑定 | 匹配基础设施建设各类文书的固定格式要求 |

## 容易做错的三处
- 现象：调用API发起对话后，生成的回复未引用知识库内的基建文档。原因：未在`variables`中绑定项目编号等专属变量，导致模型无法精准召回对应标段的文档。

## 怎么确认配好了
- 发起测试对话，输入项目编号与标段代码，核对会话绑定的`chatId`是否与预设值一致。
- 调用API发起多轮对话，检查返回的`messages`列表是否保留了指定数量的历史消息。
- 生成一份签证单，核对生成内容是否包含预设的`variables`字段与对应计量单位。
- 触发数据召回，检查返回的文档是否为近7天内更新的基建相关文档。
