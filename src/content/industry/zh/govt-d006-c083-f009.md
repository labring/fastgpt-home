# 基础设施建设的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
基础设施建设的文书与材料主要来源于项目施工过程中的施工日志、招投标文件、竣工报验资料、监理周报等。数据更新节奏随项目进度阶段性更新，单份文档长度跨度大，短则数百字的现场签证，长则数万字的竣工决算报告。文档结构带有固定行业规范字段，包含项目编号、工程部位、材料规格、验收等级等，单位多为米、立方米、吨等工程计量标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
基础设施建设文书的长跨度文档长度，要求模型接入时需适配可变上下文窗口，避免截断工程计量、验收标准等关键内容。固定专业字段与计量单位，要求模型配置需开启专业术语识别逻辑，防止参数或单位解析错误。阶段性更新的数据源，要求配置中需关联定期同步的数据源路径，确保模型调用的文档为最新项目资料。单份文档的专业细节密度，要求配置时需调整模型的输出严谨性参数，避免生成模糊或不符合行业规范的内容。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配基础设施建设文书的长文本特征，避免截断工程计量、验收标准等关键内容 |
| `maxTokens` | 2000–3000 token | 满足工程文书起草时的详细输出需求，覆盖施工方案、签证单等文档的完整生成逻辑 |
| `temperature` | 0.3–0.5 | 降低生成随机性，确保工程数据、单位、字段的准确性，符合行业规范要求 |
| `quoteMaxToken` | 1500 token | 匹配单份工程文档的核心段落长度，确保召回的参考资料能完整覆盖工程细节 |
| `toolChoice` | auto | 允许模型根据文书起草需求自动选择工具，适配招投标文件、竣工报告等不同类型文档的生成 |
| `AIPROXY_API_TOKEN` | 按实际申请的模型服务密钥填写 | 确保模型调用的身份验证合法，避免接入失败 |

## 容易做错的三处
- 现象：升级FastGPT版本后，配置的指定大模型在保存后重新进入聊天界面变为其他模型。原因：未正确绑定模型密钥与部署端点，或升级后配置项未同步保留。
- 现象：接入文档处理工具后，上传工程文书的解析速度明显变慢。原因：未针对长文本工程文档调整工具的分块参数，导致单次处理数据量过大。
- 现象：通过第三方API网关添加模型令牌时，提示Data too long for column 'models'报错。原因：未限制令牌关联的模型列表长度，超出数据库字段的存储上限。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容，确保与部署的模型服务地址、密钥一致。
- 发起一次短文档（如现场签证单）的起草测试，验证生成内容包含正确的工程字段与单位。
- 上传一份长文本工程文档，查看模型调用时的上下文窗口未出现截断提示。
- 调整`temperature`参数后发起测试，确认生成内容的严谨性随参数变化符合预期。
