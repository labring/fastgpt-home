# 大宗商品贸易的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
大宗商品贸易的文书与材料主要来源于内部合同管理系统、仓单管理系统、财务结算系统及外部海关、物流单据。文档包含贸易主体信息、货物品类、计量数量、交易金额、交割条款、合规条款等结构化字段，单位涉及吨、立方米、千克、美元、人民币等。文档形态涵盖结构化表单与长文本合同混合，单笔交易的完整文书长度跨度较大，更新节奏为单笔交易完成后即时生成，日常按周期同步历史归档文件。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化字段多且单位差异大，会导致向量嵌入时的特征对齐难度提升，需适配多类型字段的统一嵌入逻辑。长文本合同的段落跨度较大，分块时容易割裂交易核心条款，影响检索的精准性。实时生成的交易单据需要索引同步延迟控制在合理范围，否则会出现检索内容滞后于业务进度的问题。不同品类大宗商品的文书格式差异明显，需兼容多样化的文档解析与分块规则，避免出现格式适配错误。需合理配置`defaultToken`与`maxToken`以适配不同长度的文档。

## 配置怎么定
本页配置方案基于FastGPT v4.17.0版本的功能逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配大宗商品贸易合同的长文本结构，覆盖完整交易条款且避免分块过碎 |
| 重叠长度 | 100–200 字符 | 保障相邻分块的条款连贯性，避免核心交易信息被割裂 |
| `defaultToken` | 4096 token | 适配多数大宗商品文书的单块内容长度，平衡嵌入效率与信息完整性 |
| `maxToken` | 16384 token | 支持长合同的完整上下文检索，满足复杂交易条款的检索需求 |
| 相似度阈值 | 0.75–0.85 | 区分核心交易条款与无关辅助内容，提升检索结果的相关性 |
| 单次搜索上限 | 前 10 条 | 控制检索结果的冗余度，避免大语言模型被过多无关信息干扰 |

## 容易做错的三处
- 现象：检索结果显示命中目标贸易合同，但生成的回复未提及合同中的交割条款。原因：分块时割裂了核心交易条款，导致关键信息未被完整嵌入向量索引。
- 现象：上传仓单后索引状态显示正常，但检索货物数量时无匹配结果。原因：`defaultToken` 设置过小，导致仓单的结构化字段被截断，关键信息丢失。
- 现象：新生成的结算单无法被检索到。原因：索引同步频率设置为每日批量更新，未匹配实时生成单据的业务需求，导致新单据未及时同步至索引库。

## 怎么确认配好了
- 上传一份标准大宗商品贸易合同，查看分块预览界面，确认核心交易条款未被割裂为多个独立分块。
- 输入包含货物品类、交割时间的查询词，核对检索结果的相似度得分是否落在设定的阈值区间内。
- 生成一笔模拟交易的结算单，等待1分钟后执行检索，确认新单据可被正常命中。
- 查看索引同步日志，确认增量同步的延迟时间符合业务实际需求。
