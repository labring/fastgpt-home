# 工程咨询监理的文书与材料起草：工作流编排

## 这个品类的数据长什么样
工程咨询监理的文档来源为项目现场的监理过程文件，包括旁站记录、分项工程验收单、监理通知单、工程量核验单等。文档更新节奏随项目推进节点触发，如完成分项验收、签发整改通知后更新。文档具备固定结构，包含项目唯一标识、监理单位签章栏、施工部位参数、整改闭环状态等字段，字段多涉及工程类单位，如平方米、立方米、工作日等，单份文档长度跨度较大，从数百字符到数万字符不等。

## 这些特征在「工作流编排」这一环带来什么约束
工程咨询监理的文档特征对工作流编排带来多项约束。首先，文档来源分散在不同项目的专属存储路径，需通过`variables`配置关联对应项目的数据源路径，避免跨项目数据混淆。其次，文档包含工程类专属单位与固定字段，需在工作流中加入字段校验节点，确保提取的单位、项目编号等信息符合规范。再者，单份文档长度跨度大，部分验收报告可达数万字符，需限制单节点处理的字符上限，防止工作流执行超时。最后，文档更新随项目验收节点触发，工作流需绑定项目状态作为触发条件，按项目节点状态启动。

## 配置怎么定
本页面基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 绑定项目验收节点触发 | 匹配监理文档随项目节点更新的节奏，避免无效执行 |
| `variables` | 配置项目编号、施工部位等专属字段 | 匹配监理文档的固定字段结构，实现精准数据提取 |
| 内容处理上限 | 800–1200 字符/节点 | 适配多数监理文档的单段处理需求，避免执行超时 |
| 字段校验开关 | 开启 | 确保提取的工程单位、数值字段符合规范，减少后续文书错误 |
| 超时阈值 | 600 秒 | 适配长文档处理的等待需求，避免任务中断 |
| 召回结果条数 | 前5条 | 过滤冗余的非必要工程内容 |
| `nodeId` | 绑定前序工作流的导出节点 | 承接跨工作流的数据流转，确保中间结果正确传递 |

## 容易做错的三处
- 工作流导入前序导出的配置后，中间结果不符合预期。现象：第二个工作流可正常输出最终结果，但中间提取的工程部位、工程量数值与前序工作流的输出不一致。原因：未通过`nodeId`绑定前序节点的准确输出路径，导致读取了错误的中间数据缓存。
- 工作流配置完成后无法在聊天窗口调用。现象：在FastGPT应用聊天界面发送指令后，无对应工作流执行记录，界面返回空结果或提示未配置工作流。原因：未将工作流绑定至对应应用的触发规则，或未开启应用的工作流调用权限。
- 工作流处理结果出现冗余工程术语。现象：生成的监理文书中包含过多非必要的行业规范内容，干扰核心信息的传递。原因：未配置字段校验节点过滤无关召回内容，或未限制召回的结果条数。

## 怎么确认配好了
- 上传一份监理旁站记录作为测试数据，触发工作流执行，查看中间节点的字段提取结果是否包含项目编号、施工部位等必填信息。
- 手动修改前序工作流的输出内容，验证第二个工作流是否能正确承接并处理修改后的结果。
- 关闭工作流的字段校验开关，检查是否会出现单位错误的中间结果，确认校验功能正常生效。
- 查看工作流的执行日志，确认触发时机与项目验收节点绑定，无无效的自动执行记录。
