# 工程机械的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
工程机械文书与材料起草的核心数据，来源于企业内部的设计图纸、生产工艺手册、合规检验标准、设备维保记录与项目作业文档。数据更新节奏随项目立项、设备迭代或合规标准修订调整，无固定周期。单份文档通常包含设备型号、额定起重量、作业半径、维保周期等字段，单位多为吨、米、小时，文档结构按部件、工序、合规要求分层编排。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
工程机械文档的专业字段多且单位明确，提示词需强制指定参数名称与对应单位，避免生成内容出现单位混淆。多轮对话需持续跟踪用户提及的具体设备型号，确保上下文同步，否则会出现参数张冠李戴的问题。长文档拆分后需保留部件关联关系，因此分块与召回环节需兼顾片段完整性，避免拆分导致专业信息断裂。合规类文档的引用需明确来源，提示词需要求标注引用的标准编号或文档章节。

## 配置怎么定

| 分块长度 | 800–1200 字符 | 工程机械文档多包含连续的工艺或参数描述，该长度可保留单部件的完整信息 |
| 单次召回条数 | 前 5 条 | 避免过多冗余内容干扰大语言模型对专业参数的提取 |
| 最大上下文 | 12000 token | 适配多轮对话中多次提及的设备型号与历史需求 |
| 溯源信息 | 按实测标定 | 需适配工程机械文档的字段结构，确保召回内容可被正确引用 |
| `variables` 参数绑定 | 绑定设备型号、作业场景变量 | 实现多轮对话中动态替换核心参数，避免重复输入 |
| `chatId` 配置 | 绑定会话唯一标识 | 确保多轮对话的上下文在API调用中同步 |

## 容易做错的三处
- 现象：API调用时返回结果与在线对话差异显著，且`messages`字段未包含历史对话内容。原因：未在API请求中正确传递`chatId`参数，导致上下文无法同步。
- 现象：生成的文书遗漏设备的额定起重量等专业参数，且未标注引用来源。原因：提示词未明确要求包含工程机械专属字段与引用合规文档。
- 现象：召回的文档片段与当前起草的文书主题无关，出现无关的通用设备描述。原因：分块长度设置过短，拆分后的文档片段丢失部件关联信息，导致召回精度下降。

## 怎么确认配好了
- 发起一次针对特定工程机械型号的起草请求，检查返回结果中是否包含该型号的额定起重量、作业半径等专属参数。
- 查看API返回的`messages`字段，确认包含完整的多轮对话上下文，且`variables`参数已正确绑定预设的设备信息。
- 对比在线对话与API调用的返回结果，确认配置一致时两者的输出无显著差异。
- 验证引用内容模板是否能正确提取文档中的合规条款，检查生成的文书是否标注了对应的文档来源。
