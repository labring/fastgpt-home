# 工程机械的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
工程机械相关文书的数据来源包括装备制造行业标准文档、企业内部设备档案、运维日志归档、质检合规文件等。更新节奏随新机型量产、年度合规审核完成调整，无固定周期。文档多为结构化文本与长段落结合，包含设备型号、额定起重量、作业半径、维护周期、合规认证编号等字段，单位涵盖吨、米、工作小时、认证有效期等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
结构化字段多且带专属单位，导致引用溯源需精准绑定字段与单位，避免匹配无关设备的参数。单份文档长度差异大，从设备铭牌短文本到年度运维手册长文档，分块时需保留上下文关联，否则溯源会丢失设备型号与参数的对应关系。数据源更新无固定周期，知识库同步需适配非定时更新场景，避免引用过期数据。部分文档涉及合规认证编号，溯源需精准匹配编号字段，否则无法确认引用的合规有效性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 匹配工程机械带单位的结构化参数，需较高阈值避免无关设备匹配 |
| 单次搜索上限 | 前6条 | 单份设备文档字段集中，无需过多召回结果 |
| `quoteMaxToken` | 800–1200 字符 | 覆盖单台设备的核心参数与合规编号，确保溯源信息完整 |
| 重排 | 开启 | 优先召回包含设备型号与核心参数的片段，提升溯源准确性 |
| `responseData` | 开启 | 强制返回完整的引用来源信息，便于溯源核对 |
| `detail` | 开启 | 返回详细的文档片段来源路径与匹配字段，提升溯源透明度 |

## 容易做错的三处
- 现象：返回结果显示引用了知识库内容，但答案与知识库中的设备文档完全无关，未提及目标设备的参数。原因：未设置足够高的相似度阈值，导致召回了无关的设备文档片段。
- 现象：仅文本格式的设备手册被引用，结构化参数文档未被召回。原因：未开启针对结构化字段的匹配配置，仅默认召回文本内容。
- 现象：API调用工作流时返回的引用来源为空，无法绑定指定的工程机械知识库。原因：未将知识库ID配置为工作流的全局变量，导致调用时未指向目标知识库。

## 怎么确认配好了
- 上传单台工程机械的设备手册文档，发起包含该设备型号与额定起重量的起草提问，核对返回结果中引用片段是否包含对应型号与参数。
- 进入工作流配置页面，确认已绑定目标工程机械知识库，发起API调用后查看返回的`responseData`字段是否包含正确的引用来源信息。
- 调整相似度阈值至0.8，发起测试提问，确认召回结果仅包含与提问强相关的设备文档片段。
- 查看系统日志，确认`detail`字段返回了完整的文档来源路径与匹配的字段信息。
