# 工程机械的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
工程机械的文书数据主要来源于整机技术手册、设备维保台账、招投标需求文档、施工日志与合同模板。数据更新节奏因类型不同存在差异，整机参数类文档每季度同步更新，现场维保记录随施工节点实时上传，招投标类文档随项目启动更新。文档结构多包含设备型号、额定载荷、作业半径、维保周期、合同金额等字段，单位涵盖吨、米、小时、万元等，部分长文档还会附带零部件清单与参数对照表。

## 这些特征在「模型接入与配置」这一环带来什么约束
工程机械的专业参数字段多且单位特殊，模型处理时需精准匹配字段语义，避免单位混淆。长文档如整机技术手册、完整合同模板会占用大量上下文token，容易触发`maxContext`或`maxTokens`限制。不同类型文档的结构差异，要求配置需适配不同的文本拆分逻辑，确保关键参数不会被拆分丢失。实时更新的维保记录与招投标文档，要求模型接入时支持动态加载最新数据，同时需限制单次处理的文档体量，避免超时。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配工程机械长文档的上下文需求，避免专业参数拆分丢失 |
| `maxTokens` | 4000–6000 token | 平衡单轮生成长度与响应速度，适配合同、维保报告等文书的起草需求 |
| `quoteMaxToken` | 1500–2000 token | 限制知识库引用的上下文占比，防止整体token超标 |
| `temperature` | 0.3–0.6 | 兼顾文书的规范性与灵活性，避免专业术语生成偏差 |
| `toolChoice` | auto | 自动匹配工具调用需求，适配招投标文件生成时的设备参数查询场景 |
| `AIPROXY_API_TOKEN` | 按账号绑定的密钥填写 | 完成模型接入的身份验证，保障请求合法性 |
| `AIPROXY_API_ENDPOINT` | 按平台提供的专属地址填写 | 确保模型请求的路由正确，避免连接失败 |

## 容易做错的三处
- 现象：生成工程机械文书时提示上下文token数超标，或接口返回413状态码。原因：未根据长文档体量调整`maxContext`参数，导致输入上下文超出模型限额。
- 现象：问题优化环节无法读取预设的环境变量配置。原因：未在模型接入配置中正确绑定环境变量密钥，导致调用权限受限。
- 现象：无法正常调用MCP工具完成设备参数查询，或知识库引用无法切换向量模型。原因：混淆了模型接入与工具、向量模型配置的绑定关系，错误在单一环节修改跨模块参数。

## 怎么确认配好了
- 上传一份完整的工程机械合同模板文档，触发文书起草任务，查看生成结果是否准确匹配设备型号、额定载荷等专业字段。
- 提交包含多类工程机械文档的测试任务，检查是否出现上下文相关报错，按需调整对应配置项的取值。
- 查看模型接入的运行日志，确认API端点与密钥配置已正常生效，无连接异常提示。
- 测试工具调用与知识库引用功能，确认可以正常完成设备参数查询与文档引用，按需调整相关配置。
