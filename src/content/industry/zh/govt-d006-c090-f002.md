# 成品油销售的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
成品油销售的相关数据主要来自加油站运营系统的销售台账、增值税开票记录、油品调价通知、合规质检报告及客户服务工单。数据更新节奏分为三类：销售台账与开票记录每日更新，调价通知随市场调整临时发布，合规文档与工单按单次业务完成更新。文档结构多为结构化表格与制式文书，包含油品编号、销量、单价、营收、站点编号等字段，单位涉及升、元、元/升、批次号等。

## 这些特征在「向量模型与索引」这一环带来什么约束
成品油销售的结构化数据占比高且字段关联紧密，要求索引时需保留字段级关联信息，避免分块破坏业务逻辑。多来源的混合数据（表格与文书）需要向量模型适配不同格式的文本编码，否则可能出现语义对齐偏差。每日更新的销售数据与临时发布的调价通知，要求索引支持增量更新与按需刷新，避免全量重建带来的性能损耗。多单位字段与制式文档结构，需要在索引前完成字段标准化，确保向量编码的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配成品油销售台账与制式文书的单块信息密度，避免分块过短破坏业务逻辑，或过长导致向量编码冗余 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的字段关联信息，避免跨块的业务逻辑被拆分 |
| 相似度阈值 | 0.72–0.85 | 适配成品油销售数据的语义相似度分布，过滤低相关的召回结果，确保召回内容与业务需求匹配 |
| 单次搜索上限 | 前 8 条 | 平衡召回覆盖率与检索效率，适配多来源混合数据的召回需求 |
| `defaultToken` | 4000 token | 适配单份文书起草的上下文长度，覆盖核心业务信息 |
| `maxToken` | 12000 token | 满足批量多文档合并后的上下文长度要求，适配复杂起草场景 |

## 容易做错的三处
- 现象：检索日志显示召回了相关销售台账与调价通知，但大模型输出“未找到匹配内容”。原因：未开启向量模型归一化配置，导致召回的向量与查询编码的向量分布不一致，模型无法正确匹配语义关联。
- 现象：知识库检索响应超时，或单次检索消耗的token量远超预设值。原因：未限制`maxToken`的取值，导致全量召回的文档被直接送入大模型，超出上下文承载上限。
- 现象：索引后的结构化销售数据召回结果混乱，单条记录的字段关联丢失。原因：分块长度设置过小，将单条销售记录的多个字段拆分到不同分块，导致模型无法关联完整业务信息。

## 怎么确认配好了
- 查看FastGPT v4.17.0版本的向量模型配置界面，确认归一化开关已开启，适配当前使用的embedding模型。
- 执行单条销售台账的检索测试，核对召回结果的分块长度与重叠长度符合预设配置。
- 查看检索日志，确认单次召回的文档数量未超过单次搜索上限的设置。
- 测试批量文书起草场景，核对送入大模型的上下文token数未超出`maxToken`的限制。
