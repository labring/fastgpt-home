# 成品油销售的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
成品油销售的文书与材料数据主要来源于内部销售台账、增值税开票记录、标准购销合同模板及行业合规文件。数据更新节奏为每日同步当日销售流水与合同变更信息。文档结构包含销售日期、油品标号、实际销量、结算单价、客户统一社会信用代码、开票金额等字段，单位多为升、吨、元、元/升，部分模板包含合规校验项字段。本页面基于FastGPT v4.17.0版本编写。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的销售流水要求多轮对话调用的数据源必须限定在近24小时内，否则生成的文书会使用过时数据。字段的单位差异（升与吨）容易引发混淆，提示词需要明确指定单位转换规则与校验逻辑。必填的合规字段（如客户统一社会信用代码）需要在多轮对话中逐一确认，避免遗漏导致文书无效。标准化的合同模板要求多轮对话的输出严格匹配预设格式，不能随意调整字段顺序或缺失必填项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文窗口长度 | 8000–12000 字符 | 成品油销售文书包含多组销售数据与字段，过长的上下文会导致模型混淆字段归属 |
| `messages`历史过滤规则 | 仅保留近24小时内的对话历史 | 销售数据每日更新，旧历史中的数据会失效 |
| `variables`字段校验开关 | 开启必填项校验 | 文书包含客户统一社会信用代码、销量等必填字段，需确保所有字段被正确填充 |
| 单次对话回复token上限 | 2000–3000 token | 单份销售文书的内容长度适中，避免超出模型输出限制 |
| 上下文数据刷新频率 | 每12小时同步一次销售台账 | 销售数据更新频繁，延迟同步会导致生成的文书数据过时 |
| 连接超时阈值 | 60 秒 | 匹配销售台账数据接口的常规响应时长，避免频繁触发连接错误 |

## 容易做错的三处
- 现象：工作流中多个<ai对话>节点的回复全部展示在最终聊天界面，无法隐藏指定节点的输出。原因：未在工作流配置中开启节点输出隐藏开关，或未正确绑定`chatId`关联指定对话上下文。
- 现象：生成的销售文书中出现单位混淆，如将升数错误转换为吨数。原因：提示词未明确指定油品单位的转换规则，未在`variables`中绑定单位校验字段。
- 现象：对话过程中出现connection error报错。原因：未配置合理的连接超时参数，或销售台账数据同步接口响应超时超过设定阈值。

## 怎么确认配好了
- 触发一次完整的多轮对话流程，检查聊天界面中仅展示指定的对话历史内容，无多余的<ai对话>节点输出。
- 输入包含油品标号、销量、客户信息的测试内容，检查生成的文书中所有字段的单位与输入一致，无混淆情况。
- 查看工作流配置界面，确认`variables`字段校验开关已开启，必填字段未被设置为可跳过状态。
- 模拟慢速数据同步场景，检查当接口响应超过60秒时，是否触发符合预期的超时提示。
