# 成品油销售的文书与材料起草：工作流编排

## 这个品类的数据长什么样
成品油销售的核心数据来源于加油站POS交易系统、油品进销存管理平台、质检合格证明文件。数据按每日营业批次更新，单份文档包含油品标号、当日销售总量、单笔交易单价、客户类型、交易时间等字段，单位涵盖升、元、吨、车次等。文档多为结构化表格或格式化台账，部分线下场景需结合手写加油凭证补充非结构化内容。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「工作流编排」这一环带来什么约束
成品油销售数据按营业批次更新且字段单位多样，要求工作流需按交易节点拆分执行步骤，避免跨批次数据混淆。结构化台账与非结构化凭证并存的场景，要求工作流需包含OCR预处理节点，统一提取标准化字段。不同油品标号对应不同定价与合规要求，需在工作流中嵌入字段校验环节，确保关联数据匹配正确。同时销售文书需关联客户开票信息，要求工作流中配置跨系统数据拉取的触发条件。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量配置 | `variables` 中绑定油品标号、销售数量、交易时间，同时配置REDIS_URL用于缓存检索结果 | 匹配成品油销售核心字段，同时通过缓存提升检索效率 |
| 节点触发条件 | 按每日营业批次触发 | 对应数据更新节奏，确保工作流处理最新批次的销售数据 |
| 知识库关联范围 | 关联近30天的油品质检报告与定价文件 | 覆盖当前销售周期内的合规与定价依据 |
| 单次数据拉取上限 | 前 50 条交易记录 | 平衡工作流执行效率与数据完整性，避免单次加载过载 |
| 失败重试次数 | 3 次，间隔 60 秒 | 应对POS系统临时波动导致的数据拉取失败，减少人工介入 |
| 上下文长度 | 800–1200 字符 | 适配成品油销售文书的常规篇幅，确保关键信息完整传递 |

## 容易做错的三处
- 现象：代码运行节点中无法选择知识库引用作为输出变量。原因：未在工作流前置节点配置知识库关联参数，导致变量池未加载对应知识库的检索结果。
- 现象：工作流执行时出现字段为空的报错，提示油品标号未匹配。原因：未按营业批次触发工作流，导致跨批次数据混杂，部分交易缺少对应油品标号字段。
- 现象：通过API创建工作流时无法配置节点触发条件。原因：未按API文档要求传入`nodeId`参数，导致节点无法被正确识别。

## 怎么确认配好了
- 查看工作流变量配置列表，确认已绑定成品油销售的核心业务字段与系统环境变量。
- 触发一次测试执行，检查各节点输出是否包含对应批次的销售数据与合规文件。
- 模拟POS系统临时中断的异常场景，验证失败重试机制是否按配置触发。
- 核对工作流触发条件与知识库关联范围，确认与当前业务周期匹配。
