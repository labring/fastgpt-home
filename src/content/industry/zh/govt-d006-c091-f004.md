# 房建工程总承包的文书与材料起草：工作流编排

## 这个品类的数据长什么样
房建工程总承包的文书与材料，主要来源于项目立项审批、施工进度报审、工程款结算、竣工验收备案等环节，数据更新节奏随项目节点推进，报审节点提交时更新、月度结算周期更新、竣工阶段集中归档。文档结构包含项目编号、标段范围、施工单位、报审事项、附件文件链接等固定字段，单位涉及平方米、立方米、工作日、万元等工程专属计量标准，单篇文档长度差异较大，从几页的报审表到数十页的竣工报告不等。

## 这些特征在「工作流编排」这一环带来什么约束
固定字段要求工作流必须绑定项目专属变量，避免手动输入导致的错误。按节点更新的节奏要求工作流需匹配项目触发事件，适配报审、结算、竣工等不同节点的文书生成需求。长文本与多附件的特性要求工作流需支持长文本处理与多文件读取。不同文档类型的差异要求工作流需设置分支逻辑，对应报审表、结算书、竣工报告等不同文书的生成规则。工程文书的属性要求工作流需配置权限校验环节，确保数据访问合规。

## 配置怎么定
以下为FastGPT v4.17.0版本下的具体配置建议：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定项目编号、标段名称、报审类型为预设变量 | 匹配房建工程总承包文书的固定字段，实现自动填充与参数传递 |
| `nodeId` | 对应知识库搜索节点的唯一标识 | 用于将知识库ID关联到对应检索环节，符合参数传递规范 |
| 单次搜索上限 | 前5-8条 | 适配房建工程文书的单篇文档长度，避免冗余召回影响处理效率 |
| 最大上下文 | 8000-12000 token | 适配长文本工程文档的处理需求，确保完整读取核心内容 |
| 超时设置 | 600秒 | 应对大型竣工文档的读取与生成时长，避免任务中断 |
| 附件大小上限 | 1000 MB | 适配工程文档的附件存储与读取需求，限制无效大文件加载 |
| 流式输出开关 | 开启 | 满足代码运行模块的实时返回需求，适配流式输出场景 |

## 容易做错的三处
- 现象：代码运行模块返回“参数缺失”报错，请求body的字段为空。原因：未将`variables`中的预设字段绑定到请求参数名，错误使用文件本地名称作为参数名，未匹配房建工程文书的固定字段。
- 现象：AI对话节点未接收到初始用户问题，无法生成对应文书。原因：判断器的输出未正确连接到AI对话节点的输入参数通道，未完成用户问题的传递链路。
- 现象：知识库搜索节点返回空结果。原因：未将知识库ID通过`variables`传递到搜索节点，导致检索范围未关联到对应标段的工程文档。

## 怎么确认配好了
- 进入工作流的变量配置页面，确认房建工程总承包专属的项目字段已被正确添加为预设变量。
- 手动触发测试节点，检查代码运行模块的请求body参数名与文书固定字段完全匹配。
- 运行知识库搜索环节，确认检索范围已关联到对应标段的工程文档。
- 开启流式输出开关后，测试代码模块的返回是否为逐段实时输出。
