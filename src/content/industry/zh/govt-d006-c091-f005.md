# 房建工程总承包的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
房建工程总承包的文书与材料主要来源于项目招标文件、施工日志、现场签证单、进度款申请单、竣工验收报告等全流程项目文件。数据更新随项目节点推进，施工类文书按周更新，进度款、结算类文书按月更新。文档结构统一包含项目编号、标段名称、参建单位全称、签署日期、核心事项说明、法定签章栏等字段，部分材料需标注建筑面积（单位㎡）、工程造价（单位万元）、施工工期（单位日历天）等量化信息。

## 这些特征在「工具调用与插件」这一环带来什么约束
房建工程总承包的文书特征对工具调用与插件环节带来多项约束。多源异构的项目文件格式差异较大，插件需预设对应不同文书类型的格式校验规则，避免生成内容与模板结构不匹配。按节点更新的数据要求插件调用需关联项目当前进度节点，防止调用过时的模板或非当前阶段的项目数据。带量化字段的文书需要插件能自动识别并填充正确单位，避免出现单位不匹配的合规问题。法定签章栏的固定格式要求插件生成的内容需预留对应签署位置，且不能篡改原有合规排版要求。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 房建工程总承包涉及的文书类型较多，自动选择工具可适配不同模板的调用需求 |
| `functionCall` | `enabled` | 需要插件按预设函数调用填充项目专属的量化字段与合规信息 |
| 插件调用超时时间 | `600 秒` | 部分大型结算、竣工验收类文书的生成需要较长处理时长 |
| 插件输入上下文长度 | `800–1200 字符` | 房建项目文书的核心业务信息通常集中在该字符区间内 |
| 单次返回结果条数 | `前3–5 条` | 房建文书的核心信息条目不宜过多，避免内容冗余 |
| 插件上下文缓存时长 | `7 天` | 房建项目的历史数据通常保留7天内的最新版本，避免调用过时信息 |
| 插件结果重排规则 | 按合规字段优先级重排 | 房建文书需优先展示项目编号、参建单位等法定必填项 |

## 容易做错的三处
- 现象：调用Doc2X插件时返回参数错误或连接超时。原因：未在插件配置中绑定房建项目专属的文档存储路径，导致插件无法读取对应标段的源文件。
- 现象：在工作流中引用插件后连接代码运行节点，点击输入框触发报错。原因：未为`toolChoice`参数设置正确的触发模式，导致输入参数格式与插件预期不匹配。
- 现象：生成的文书中量化字段单位错误，如将㎡替换为其他单位。原因：未开启插件的单位校验规则，或上下文长度配置过短导致未识别到单位字段。

## 怎么确认配好了
- 上传一份房建项目的施工日志模板，触发插件调用，检查生成的内容是否包含项目编号、参建单位等必填字段。
- 查看插件运行日志，确认`functionCall`参数处于启用状态，且未出现格式校验失败的提示。
- 调整项目进度节点标签，触发插件调用，检查生成的文书是否匹配当前进度阶段的模板要求。
- 验证量化字段的单位是否自动填充正确，确认重排规则已按合规要求排序。
