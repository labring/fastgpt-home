# 房建工程总承包的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
房建工程总承包的业务数据主要来源于项目全周期的招投标文件、施工日志、变更签证单、竣工验收报告、标准施工规范及内部合同范本。数据更新随项目进度节点触发，单次项目周期内更新频次随施工阶段调整。文档多为结构化文本，包含项目编号、标段名称、施工部位、材料参数、验收标准等字段，单位涵盖平方米、立方米、吨、工时等工程专用计量标准。

## 这些特征在「引用来源与溯源」这一环带来什么约束
房建工程总承包的业务数据分散于多类项目文档，且按施工部位、标段绑定专属参数，要求引用溯源需精准匹配项目维度关联信息，避免跨标段或跨部位的错误关联。数据随施工进度高频更新，需确保知识库召回的内容与当前施工阶段匹配，防止引用过期的签证或验收标准。文档包含大量工程专用字段与计量单位，需在召回时保留字段关联关系，避免拆分后丢失关键定位信息。

## 配置怎么定
本配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 匹配房建工程专业术语的精准度，避免召回无关的其他标段文档 |
| 单次搜索上限 | 前8条 | 覆盖单个施工部位的多类关联文档，如签证、验收、施工日志 |
| `quoteMaxToken` | 1200–1500 token | 容纳工程文档的长文本片段，保留完整的签证编号或验收结论 |
| 重排 | 开启 | 按内容相关性排序，优先召回与当前起草文书的施工部位直接相关的内容 |
| `responseData` | 仅返回引用源 | 确保输出的引用仅关联房建项目的专属文档，不混入通用知识 |
| `detail` | 开启 | 展示引用文档的项目编号、标段名称等字段，便于快速核对溯源 |

## 容易做错的三处
- 现象：配置开启引用后，界面展示引用文档列表，但AI生成的文书未包含知识库中的专业内容。原因：未正确设置`responseData`参数，或相似度阈值设置过低，召回的文档未被正确关联到生成逻辑中。
- 现象：知识库中上传的图纸、表格类文件未被召回，仅文本数据集可生成引用。原因：未开启对应文件格式的解析开关，或未针对非文本文件生成对应的结构化索引，无法匹配工程文档的字段关联。
- 现象：动态传入知识库搜索变量后，AI未召回对应项目的文档，生成的文书无引用关联。原因：未将动态变量正确绑定到知识库搜索的参数中，或变量传递的项目编号未与知识库文档的字段匹配。

## 怎么确认配好了
- 上传一份包含特定项目编号的工程文档，起草对应标段的文书，核对生成内容是否包含该文档中的专业参数。
- 查看引用溯源面板，确认展示的文档字段包含项目编号、施工部位等专属信息，且与当前项目一致。
- 调整相似度阈值的取值范围，观察召回文档的数量变化，验证配置是否生效。
- 关闭通用知识召回开关，确认生成的文书仅引用上传的房建项目文档，无无关内容。
