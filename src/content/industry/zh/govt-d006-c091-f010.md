# 房建工程总承包的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
房建工程总承包的文书数据主要来源于项目施工过程中的总承包合同、变更签证、施工日志、技术交底、竣工验收报告等文件。数据更新节奏随项目节点推进，施工日志按周更新，签证与验收报告随流程节点实时提交。文档结构包含项目编号、标段、责任主体、施工日期等结构化字段，以及钢筋绑扎、混凝土浇筑等专业施工描述的非结构化内容，单位涉及平方米、立方米、工期天等，单篇文档长度差异显著，短则数百字的施工交底，长则数十页的总承包合同。本文适配FastGPT v4.17.0版本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
房建工程总承包的文书数据特征对检索召回环节带来多重约束。首先，文档长度差异显著，需要适配不同长度的分块与召回规则，避免长文档丢失关键上下文或短文档被过度拆分。其次，结构化字段（如项目编号、标段）要求检索时需按项目维度过滤，避免跨标段的无关结果干扰。再次，专业术语密集，如CFG桩、后浇带、后浇带止水等，需要兼顾语义匹配与关键词精准召回。最后，更新节奏随项目节点波动，需支持增量同步与实时召回最新的签证、验收类文档。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 相似度阈值（`similarity`） | 0.72–0.85 | 房建专业术语多，该区间可过滤低相关结果，避免混淆类似施工工艺表述 |
| 单次搜索上限（`limit`） | 前10条 | 房建文书按标段归档，单标段相关结果集中在10条内，过多会超出上下文承载上限 |
| 搜索模式（`searchMode`） | 向量+关键词混合检索 | 房建文书兼具结构化字段与非结构化专业内容，混合模式兼顾精准度与召回率，可覆盖标题与正文的关键词匹配 |
| 重排开关（`usingReRank`） | 开启 | 房建专业术语语义关联复杂，重排可修正向量检索的语义偏差，提升专业相关结果的排序优先级 |
| 问题优化开关（`datasetSearchUsingExtensionQuery`） | 开启 | 工程文书提问常省略项目编号，优化后可自动补充项目维度关键词，提升同标段文档的召回精准度 |
| 数据集过滤ID（`collectionIds`） | 绑定当前标段的知识库集合ID | 房建项目按标段独立归档，过滤后仅召回对应项目的文书，避免跨标段的无关内容干扰检索结果 |

## 容易做错的三处
- 上传文档同步知识库时返回“Request failed with status code 400”，原因是未正确绑定`collectionIds`对应的标段知识库集合，或上传的签证、验收报告类文档包含未标准化的字段格式，触发接口参数校验失败。
- 配置自定义分块规则时误将理想分块长度设为固定值，未适配房建文书的长度差异，原因是未结合房建项目既有数十页的总承包合同又有单页的施工日志的特征，统一分块会丢失关键上下文关联信息。
- 知识库检索结果未包含文档标题相关内容且响应卡顿，原因是`searchMode`仅设置为纯向量检索，未开启混合检索模式，同时`limit`取值超过15条，导致系统加载过多低相关文档片段。

## 怎么确认配好了
- 上传单篇标段专属的施工日志文档，触发同步后查看知识库同步日志，确认无400类报错，且文档已被正确索引。
- 输入包含项目编号的检索词，查看检索结果的过滤效果，确认仅返回当前标段的文档。
- 开启`usingReRank`后对比开启前后的检索结果排序，确认专业术语相关的结果排名得到提升。
- 输入包含文档标题关键词的检索词，查看检索结果是否优先返回对应标段的文档，确认标题检索功能正常生效。
