# 政企信息化服务的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
政企信息化服务的文书与材料起草数据，主要来源于通信行业政企客户的内部运维手册、合规文件、招投标文书模板及行业标准文档。数据更新节奏为按月或按季度，匹配行业政策与标准的常规调整周期。文档整体为结构化格式，包含文件编号、发布日期、适用范围、条款化正文等字段，条款内容以条、款、项为单位，单篇文档长度从数千到数万字符不等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
结构化的文档格式要求溯源需精准定位到具体条款编号，仅展示文件名无法满足政企文书的合规性审核要求。稳定的更新节奏要求需定期同步数据源，避免引用过期的政策或行业标准内容。文档附带的适用范围字段要求引用前需校验当前起草文书的场景与文档的适用范围匹配，防止出现跨场景引用的合规风险。较长的单篇条款内容要求需预留足够的token空间，确保引用的完整内容被保留，不会因截断丢失关键合规信息。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配政企信息化服务的文书起草溯源需求：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 引用最大token数 | 800–1200 token | 政企文书单段合规条款内容较多，需完整覆盖引用依据 |
| 单次召回结果数 | 前3–5条 | 政企文档结构化程度高，少量结果即可覆盖核心合规依据 |
| `quoteMaxToken` | 800–1200 token | 对应中文配置项的参数化设置，适配长文本引用需求 |
| `responseData` | 仅保留正文与来源标识 | 精简输出内容，避免暴露文档内部冗余字段 |
| `detail` | 开启 | 需展示引用条款的编号与发布日期，满足溯源审核要求 |
| 数据源同步周期 | 按月更新 | 匹配政企通信行业文档的常规更新节奏 |

## 容易做错的三处
- 现象：生成的文书中出现“知识库搜索”“input”“response”等无关字段。原因：未关闭工作流中工具调用的溯源展示开关，默认保留了工具调用的原始输入输出内容。
- 现象：引用的溯源结果未匹配到具体条款编号，仅显示文件名。原因：未开启`detail`配置项，未启用结构化文档的字段提取功能。
- 现象：工作流中无法选择知识库变量作为引用源。原因：未将政企文档数据源添加至全局变量的可引用范围，或未配置变量与数据源的关联关系。

## 怎么确认配好了
- 手动触发一次文书起草任务，检查生成内容中是否包含无关的工具调用日志字段。
- 查看生成文书的溯源模块，确认每条引用都附带了条款编号、发布日期等结构化字段。
- 进入全局变量配置页面，确认政企文档数据源已被添加至可引用变量列表。
- 临时调整`quoteMaxToken`参数的取值，验证生成的引用内容长度是否符合预期设置。
