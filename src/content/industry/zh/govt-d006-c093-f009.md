# 政企信息化服务的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自政企通信类项目的业务管理系统、用户上传的本地文档，包括立项申请、运维报告、合规自查材料等。数据更新随业务流程触发，单次任务生成后归档至政企内部知识库。文档结构固定包含业务主体信息、事项说明、审批节点、落款盖章区域，字段包含项目标识、执行周期、业务范围等，部分文档带有涉密等级标识，单位多为字符、自然日、数值单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据混合结构化业务字段与非结构化文书文本，要求模型接入时同时支持结构化信息抽取与标准化文书生成。随业务流程触发的更新节奏，要求配置的模型调用响应时长适配政企内部审批的常规窗口。固定的文档结构要求模型输出需匹配预设的业务字段与节点，避免生成内容偏离合规审批要求。部分文档的涉密标识，要求配置内容脱敏与权限校验相关参数，防止敏感信息泄露。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 政企文书通常篇幅较长，需保留足够上下文确保生成逻辑连贯 |
| `maxTokens` | 2000–3000 token | 单份政企文书的起草内容通常在该区间内，避免超出调用预算或超时 |
| `temperature` | 0.3–0.5 | 文书起草需保持格式与内容的规范性，不宜过高导致内容发散 |
| `vision` | 开启 | 部分上传的文档为扫描件或HTML转换后的图片，需支持视觉识别提取内容 |
| `AIPROXY_API_ENDPOINT` | 填写政企内部部署的代理地址 | 确保数据传输符合内部安全合规要求，避免敏感信息外流 |
| `toolChoice` | auto | 根据文书类型自动选择合适的工具辅助生成，提升起草效率 |

## 容易做错的三处
- 现象：上传的HTML转换后的图片无法被模型识别，返回空的文本识别结果。原因：未开启`vision`参数，或配置的文件存储目录未开放模型访问权限，导致模型无法读取转换后的图片文件。
- 现象：工作流中接入外部MCP插件后触发调用失败，返回超时提示。原因：未将`AIPROXY_API_ENDPOINT`配置为插件的合法访问地址，或未调整`maxTokens`参数适配插件调用的响应时长。
- 现象：文书分类节点的识别结果与业务场景不匹配，分类偏差较大。原因：`temperature`参数取值过高，导致模型输出逻辑发散，或未针对政企文书的分类规则调整预设提示词。

## 怎么确认配好了
- 上传一份测试用的政企文书扫描件，查看模型是否能正确提取图片中的文本内容，确认`vision`参数配置生效。
- 发起一次文书起草任务，查看模型生成的内容是否匹配预设的文档结构与字段要求，确认`maxContext`与`maxTokens`参数适配当前业务场景。
- 接入外部MCP插件后触发一次测试调用，查看是否能正常返回结果，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确。
- 调整`temperature`参数至不同区间，对比生成的文书格式规范性，确认参数取值符合业务需求。
