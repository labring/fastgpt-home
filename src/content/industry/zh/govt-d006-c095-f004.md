# 新能源开发的文书与材料起草：工作流编排

## 这个品类的数据长什么样
新能源开发的文书与材料数据主要来自项目全周期的审批文件、技术报告与内部管理文档，来源包括自然资源、能源主管部门的批复文件，以及项目可研、环评、并网申请等自制材料。数据更新节奏随项目阶段推进，立项阶段更新项目基础参数，施工阶段同步进度佐证材料，并网阶段补充验收文档。文档结构多为多章节嵌套格式，包含项目编号、装机容量（单位MW）、用地范围（单位公顷）、审批节点状态等标准化字段，部分材料含固定格式的签章与文号信息。

## 这些特征在「工作流编排」这一环带来什么约束
新能源开发的文书数据来源分散且格式差异大，导致工作流编排需配置多数据源接入节点，分别对接政务平台批复文件与项目自制文档。标准化字段带专属单位，要求工作流中增加参数校验节点，对装机容量、用地范围等字段做单位匹配与格式验证。项目阶段驱动的数据更新，要求工作流触发条件绑定项目节点状态，避免固定定时触发，减少无效执行。长文档嵌套结构则要求工作流配置节点支持按章节拆分内容，避免单节点处理超量文本。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工作流编排功能，具体如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配新能源项目文书单章节的平均长度，避免单块内容过载 |
| 触发条件 | 按项目节点状态变更触发 | 匹配项目阶段驱动的数据更新节奏，减少无效运行 |
| variables | 包含项目编号、装机容量字段 | 覆盖标准化字段的校验与调用需求，适配新能源项目的固定参数 |
| 节点超时时间 | 600 秒 | 适配长文档处理与跨部门数据源拉取的耗时需求 |
| nodeId | 按数据源类型分配唯一标识 | 区分政务批复文件与自制文档的处理节点，避免调用冲突 |
| 字段校验规则 | 匹配MW、公顷等单位 | 对应新能源文书的标准化字段单位要求，确保数据格式合规 |

## 容易做错的三处
- 点击工作流中引用的自定义插件后的代码运行节点输入框时出现报错。原因是插件绑定的`variables`未覆盖新能源项目的标准化参数，节点调用时无法读取预设字段。
- 本地部署环境打开工作流编辑页面时，出现Cannot read properties of undefined (reading 'incl' 类报错。原因是工作流的`nodeId`存在重复配置或未完成初始化，导致页面渲染时无法识别节点标识。
- 工作流生成的并网申请材料缺失装机容量的单位信息。原因是未配置字段校验规则，未对新能源项目的标准化字段做单位绑定，导致输出格式不符合要求。

## 怎么确认配好了
- 触发一次工作流，检查各数据源节点是否能正常拉取对应类型的新能源项目文档，确认触发条件与项目节点状态绑定生效。
- 查看工作流的参数校验节点，确认已配置匹配新能源文书字段的单位规则，可通过导入测试文档验证校验逻辑是否触发。
- 检查自定义插件的绑定参数，确认`variables`已包含项目编号、装机容量等新能源项目专属字段，避免调用时出现字段缺失。
- 查看工作流的节点标识列表，确认`nodeId`均为唯一且已完成初始化，避免页面渲染或节点调用报错。
