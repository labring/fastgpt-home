# 新能源开发的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
新能源开发的文书与材料主要来源于项目内部管理系统、政务审批平台及第三方检测机构。数据更新节奏随项目阶段变化，立项阶段每周更新可研报告，并网验收阶段按需更新安全验收文档与并网申请材料。文档结构包含固定章节与动态字段，固定字段包括项目编号、装机容量（单位MW）、建设地点、审批文号，动态字段包含现场检测数据、环评附件链接等。单份文档长度跨度较大，从数千字符的申请函到数十万字的可研报告均有覆盖。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散导致需对接多套接口，工具调用需支持跨系统数据拉取。文档结构复杂且字段带有专属单位，插件提取时需精准匹配特有字段，避免通用提取逻辑出错。单份文档长度差异大，长文本内容需适配分段处理逻辑，防止接口调用超时。数据更新无固定周期，工具调用需实时拉取最新版本数据，无法依赖缓存内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 工具调用超时时间 | 120–180 秒 | 新能源开发文书接口返回数据量较大，包含长文本内容，常规短时长超时无法完成完整数据拉取 |
| 字段提取规则 | 按项目专属字段映射 | 新能源开发文书包含项目编号、装机容量等特有字段，需指定对应映射规则 |
| `toolChoice` | auto | 适配不同类型的文书起草场景，自动选择匹配的工具完成数据处理 |
| 插件请求重试次数 | 3 次 | 应对政务审批接口偶尔的临时波动，保障调用成功率 |
| 上传文件大小限制 | 500–1000 MB | 新能源开发文书附带大量CAD图纸、环评图集等大附件，需适配大容量文件上传需求 |
| `functionCall` | 强制指定 | 针对核心审批字段提取场景，强制触发工具调用，避免大模型自主选择导致的偏差 |

## 容易做错的三处
- 现象：调用MinerU容器接口时返回“413 Request Entity Too Large”报错。原因：启动容器时未配置上传文件大小参数，默认限制为2MB，无法适配新能源开发文书附带的大型附件。
- 现象：HTTP请求组件调用成功但提取的新能源专属字段为空。原因：未配置专属字段映射规则，默认提取逻辑无法识别项目编号、装机容量等特有字段。
- 现象：发布为API接口后调用超时。原因：未调整默认超时时间，新能源文书接口响应时长超过默认阈值。

## 怎么确认配好了
- 发起一次针对新能源开发文书的测试调用，查看工具调用日志，确认指定的专属字段被正确提取。
- 上传一份包含典型附件的新能源开发文书，检查插件是否能正常处理并返回预期结果。
- 调用发布后的API接口，验证超时时间设置符合实际接口响应时长。
- 在FastGPT v4.17.0版本的工具调用模块中，查看重试机制的触发记录，确认异常场景下自动重试正常生效。
