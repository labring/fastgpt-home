# 有色金属冶炼的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
有色金属冶炼的文书与材料主要来源于生产过程中的工艺规程、质检报告单、能耗台账、安全合规文件及技术总结。数据更新按生产班次或每日频次，部分月度总结类文档长度可达数千字符。文档包含结构化字段，如炉号、金属品位、能耗值，搭配非结构化的工艺描述与说明文本，常用单位包括吨、克/吨、摄氏度、帕斯卡等，同时存在大量工业专业术语与固定格式的报表内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
高频更新的生产台账与质检数据要求索引支持增量同步，避免全量重建带来的资源消耗。混合结构化与非结构化的文档类型，需要在分块时兼顾字段完整性与语义连贯性，防止拆分专业术语或工艺步骤。工业专属术语的存在，要求向量模型适配工业语料的语义特征，否则会出现检索匹配偏差。长文档占比偏高的特点，也对向量拼接的上下文窗口提出了明确要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配冶炼文书的典型段落长度，避免跨专业术语拆分 |
| 重叠长度 | 50–100 字符 | 保留分块间的上下文关联，防止工艺步骤或参数描述断裂 |
| 相似度阈值 | 0.72–0.80 | 匹配冶炼专业术语的语义相似度区间，按实测标定 |
| 单次搜索上限 | 前8条 | 平衡检索精度与响应速度，适配工业文书的检索场景 |
| 最大上下文 | `maxToken` 设为 8000 | 适配长文书的召回内容拼接，避免超出模型窗口限制 |
| 重排 | 开启 | 过滤低相关的参数条目，提升检索结果的针对性 |

## 容易做错的三处
- 现象：调用知识库接口创建的QA拆分集合，检索响应超时。原因：未配置合理的分块长度与重叠参数，导致分块数量过多，索引加载与检索耗时超出阈值。
- 现象：界面显示embedding模型变更为embedding-3，原使用ada-002的索引无法匹配新检索请求。原因：未锁定embedding模型版本，新索引与旧索引的向量空间不统一，导致检索结果偏差。
- 现象：检索结果中混入无关的行政文件条目。原因：相似度阈值设置过低，将语义关联度不足的非目标文档纳入召回范围。

## 怎么确认配好了
- 查看FastGPT v4.17.0的索引创建日志，确认分块数量符合预期，无异常报错或截断提示。
- 检索工业专业术语，如“冰铜品位控制范围”，核对返回结果的相关性与条目数量。
- 对比不同embedding模型的检索结果，确认当前使用的模型版本与配置参数一致。
- 模拟批量检索请求，验证响应速度符合业务场景的时间要求。
