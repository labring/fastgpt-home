# 核电运营的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
核电运营的文书与材料起草相关数据主要来源于设备检修规程、日常巡检记录、安全评审报告、运行日志四类。数据更新节奏差异化明显：日常巡检记录每日生成更新，设备检修规程每季度修订归档，安全评审报告按月提交存档。文档结构包含章节编号、设备唯一标识、操作步骤、异常等级等字段，部分专业文档附带压力、温度等量化参数，单位涵盖MPa、小时、次等工业标准单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
上述数据特征对向量模型与索引配置带来多重约束。首先，多更新节奏要求支持增量嵌入与全量嵌入结合的索引更新策略，适配每日巡检记录的高频更新与季度规程的低频修订。其次，结构化字段与专业术语并存，需要分块策略兼顾语义完整性与字段关联性，避免将跨设备的关联内容拆分至不同分块。最后，长文本安全报告与短文本巡检记录的长度差异，要求分块参数具备灵活调整空间，适配不同类型文档的嵌入需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配核电运营规程、检修记录的单段有效内容长度 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，避免专业术语被截断 |
| 相似度阈值 | 0.75–0.85 | 适配核电专业术语的语义匹配精度，过滤低相关召回结果 |
| 单次搜索上限 | 前 20 条 | 覆盖核电场景下多设备、多环节的关联文档召回需求 |
| `maxToken` | 4096 token | 适配主流大模型的上下文窗口，完整承载召回的文档内容 |
| `defaultToken` | 8192 token | 配置向量模型的默认输入长度上限，适配长文本的嵌入需求 |

## 容易做错的三处
- 现象：切换知识库向量模型后，系统显示索引进度停滞，且无法恢复原有模型配置。原因：未执行批量重新嵌入操作，新模型未完成全量数据向量化，原有配置未被系统自动重置。
- 现象：配置豆包embedding接口后测试返回404 page not found错误。原因：未正确配置接口访问域名或密钥权限，导致请求无法被目标服务识别。
- 现象：批量重新嵌入多语言文档后，专业术语召回效果未达预期。原因：未针对多语言场景调整向量模型选型或分块策略，导致语义对齐出现偏差。

- 发起检索测试，输入核电专业术语，查看召回结果的相关性是否符合业务预期。
- 执行批量重新嵌入任务，查看系统进度条是否正常更新，无异常中断提示。
