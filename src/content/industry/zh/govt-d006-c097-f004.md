# 核电运营的文书与材料起草：工作流编排
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
核电运营的文书与材料起草数据主要来源于现场运行日志、安全审评档案、岗位操作规程、应急响应报告及设备维护记录。数据更新按运行班次触发，单次运行事件结束后同步归档。文档结构包含固定文号、事件编号、核心运行参数、审批流转节点等字段，参数单位多采用兆瓦、小时、兆帕等核电行业标准计量标识，单份文档长度跨度较大，从数百字符的巡检记录到数万字符的审评报告不等。

## 这些特征在「工作流编排」这一环带来什么约束
核电运营文书数据的跨度差异，要求工作流支持适配不同长度的文档处理节点，避免短文档冗余分块或长文档截断丢失关键安全信息。固定字段的存在，要求工作流通过`variables`绑定预设的文号、事件编号等字段，减少手动录入误差。按班次触发的更新节奏，要求工作流配置定时触发节点，按运行周期同步拉取最新的现场数据。标准化的参数单位，要求在参数提取环节增加单位校验逻辑，过滤不符合核电行业计量规范的异常值。多级审批的流程要求，还需工作流配置对应流转节点，匹配核电安全审批的层级要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定事件编号、运行班次、设备编号三个固定字段 | 匹配核电文书的必填字段，减少手动录入误差 |
| 定时触发节点 | 每8小时触发一次 | 匹配核电运行的三班倒班次周期，确保新数据及时同步 |
| 单次搜索上限 | 前10条 | 平衡召回精度与处理效率，适配核电参考文档的常规量级 |
| 文档分块长度 | 800–1200 字符 | 适配核电文书的平均长度，避免截断关键安全信息 |
| 参数校验规则 | 校验运行参数单位为兆瓦、小时、兆帕 | 匹配核电行业的标准计量规范，过滤异常输入 |
| `nodeId` | 绑定审批节点的唯一标识 | 确保工作流流转到对应审批环节时触发合规性校验 |

## 容易做错的三处
- 现象：工作流调用知识库搜索时返回「未找到匹配知识库」提示。原因：未通过`variables`绑定知识库的关联标签，导致工作流无法匹配到预设的核电专属知识库。
- 现象：插件参数无法从指定变量获取，直接返回空值。原因：未配置参数 fallback 逻辑，未启用默认值回退机制。
- 现象：工作流处理的文档出现关键安全参数截断。原因：文档分块长度设置过小，导致长文档的核心信息被拆分丢失。

## 怎么确认配好了
- 手动触发一次工作流，确认预设的`variables`字段自动填充至对应节点。
- 查看工作流执行日志，确认知识库搜索匹配到了与当前任务相关的核电文档。
- 提交包含非标准计量单位的测试数据，确认参数校验规则触发拦截逻辑。
- 等待设定的触发周期结束，确认工作流自动拉取了新的现场数据。
