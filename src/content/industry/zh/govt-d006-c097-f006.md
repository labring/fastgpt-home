# 核电运营的文书与材料起草：引用来源与溯源
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
核电运营的文书与材料主要来自核安全监管导则、电站运行规程、事件处置报告、定期试验记录四类数据源。运行规程按年度或重大设备变更后更新，事件报告实时录入归档，定期试验记录按季度汇总存档。单份文档结构包含章节编号、专业操作步骤、安全限值、设备编号与辐射剂量单位，字段固定且严格匹配核电行业标准化格式，无冗余非必要内容。

## 这些特征在「引用来源与溯源」这一环带来什么约束
核电文书的标准化字段与单位要求引用时必须保留原始标识，不能随意修改或简化，否则无法通过监管方的溯源验证。文档更新频率较高，需确保知识库同步节奏与数据源更新周期一致，否则引用旧版文档会不符合当前监管要求。长文档的章节关联紧密，分块处理时需保留足够的上下文重叠，避免拆分后丢失章节编号与操作步骤的对应关系。严格的溯源要求意味着每一处引用都需对应到具体的文档编号与章节，不能使用模糊的来源描述。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大引用token数 | `quoteMaxToken` 设为 2000–3000 token | 核电文书的操作步骤与处置逻辑需完整覆盖，该区间可保留足够上下文用于溯源 |
| 响应数据格式 | 开启`responseData`原生返回 | 需保留原文档的编码格式与专业字段，避免解析后丢失单位或编号信息 |
| 引用详情展示 | 开启`detail`开关 | 需在输出中显示引用文档的编号与章节，满足核电运营的溯源核查要求 |
| 单次召回上限 | 前 3 条 | 核电引用需精准匹配，过多召回会导致上下文冗余且溯源逻辑混乱 |
| 分块重叠长度 | 100–200 字符 | 核电文档章节关联紧密，该重叠长度可确保分块后仍能关联到完整的章节标识 |
| 知识库同步周期 | 按实测标定 | 需匹配运行规程、事件报告的更新节奏，确保引用版本符合当前监管要求 |

## 容易做错的三处
- 现象：调用接口返回结果无关联上下文，或大模型输出未引用知识库内容。原因：将`quoteMaxToken`设为3000以上时，超过系统默认的上下文总长度限制，导致截断后无法完整传入大模型。
- 现象：引用内容显示为乱码或专业单位丢失。原因：未开启`responseData`原生返回配置，导致文档的编码格式被转换，丢失核电专业字符与字段信息。
- 现象：引用的章节编号与实际文档不匹配。原因：分块重叠长度设置不足，导致分块时拆分了完整的章节标识，无法关联到正确的文档位置。

## 怎么确认配好了
- 发起包含具体核电事件编号或运行规程章节的测试提问，查看输出中是否包含引用文档的编号与章节信息。
- 上传一份核电运行规程文档，发起包含章节编号的提问，确认输出中匹配到对应文档的内容。
- 调整`quoteMaxToken`至2500 token，测试大模型是否能接收到完整的上下文内容。
- 下载引用的源文件，确认编码格式与原上传文档一致，无乱码或字段丢失。
