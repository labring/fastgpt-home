# 民航机场的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
民航机场的文书数据来自航班保障调度、安检运维管理、旅客服务规范、航站楼运营等场景的官方文档，包括航班延误通知、安检流程手册、旅客服务指南、机场应急处置预案等。更新节奏分为每日更新的航班动态类文档、季度修订的运维规范类文档、突发情况临时生成的通知类文档。文档结构包含带文号、日期、受众的标准化通知，以及分章节带条款编号的手册类内容，专属字段包含机场三字代码、航班号、航站楼编号、保障时段等，单位涉及分钟、班次、平方米等。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于数据来源覆盖多场景且格式差异较大，需先完成统一的格式标准化处理，避免分块时破坏专属字段的完整性。每日更新的航班动态文档要求支持增量索引，减少全量重建的资源消耗。长段落的运维手册类文档需要合理控制分块长度，确保语义单元完整。专属字段如机场三字代码、航班号需作为元数据纳入索引，提升精准召回的效率。此外，不同类型文档的长度差异较大，需适配不同的分块策略以保证向量化效果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 民航机场文书多为长段落的专业规范文档，该长度可保留完整语义单元且避免分块过碎 |
| 重叠长度 | 100–150 字符 | 避免跨分块的语义信息丢失，适配长文档的连贯表述逻辑 |
| 相似度阈值 | 0.65–0.75 | 民航文书多为专业术语密集型内容，该区间可过滤无关召回同时保留精准匹配结果 |
| 单次搜索上限 | 前 8 条 | 机场文书的检索需求多为精准匹配特定流程或条款，过多结果会增加上下文处理负担 |

| `defaultToken` | 200 token | 控制单条分块的向量存储开销，适配增量索引的性能要求 |

## 容易做错的三处
- 现象为导入机场运维文档数据集后，知识库状态持续显示索引中。原因是未针对每日更新的航班数据配置增量索引策略，全量索引流程无法及时完成大规模文档的向量化处理。
- 现象为向量模型调用返回的语义相似度分值超出0-1区间。原因是误用了非标准的相似度计算参数，未将阈值范围锁定在0-1之间。
- 现象为检索结果仅返回少量条目，无法覆盖所需的机场流程条款。原因是单次搜索上限配置过低，未适配民航文书多条款关联的检索场景。

## 怎么确认配好了
- 查看FastGPT v4.17.0的向量模型调用日志，确认返回的相似度分值处于0-1区间。
- 手动导入一份测试用的机场安检规范文档，验证索引完成时间符合预期配置。
- 检索特定航班保障流程的关键词，确认召回结果的相似度分值符合设定的阈值范围。
- 检查元数据配置项，确认机场三字代码、航班号等专属字段已被纳入索引规则。
