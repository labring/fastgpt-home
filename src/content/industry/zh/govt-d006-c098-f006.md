# 民航机场的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
民航机场的文书数据来源包括内部运行手册、空管协同文件、航班调度日志、旅客服务规范与安全审计记录。更新节奏按文件类型区分，安全合规类文档每季度复审更新，日常调度类日志每日同步更新，旅客服务指引类内容每月微调。文档多为章节式结构，包含文件编号、生效日期、适用场景、操作细则、责任主体等标准化字段，单位涉及分钟、千克、人次等运行相关标准单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源分散的数据来源，要求溯源环节需关联跨系统的文件元数据以确保引用的完整性。固定的章节式结构与标准化字段，要求引用时需精准匹配文件编号、生效日期等标识，避免溯源混淆。不同更新节奏的文档，要求增量同步机制适配每日、每月、每季度的更新周期，防止引用过期内容。运行相关的单位字段，要求溯源时需同步记录单位信息，确保引用内容的场景匹配性。

## 配置怎么定
本配置说明基于FastGPT v4.17.0版本，具体配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 适配民航机场文书的长文本特征 |
| `quoteMaxToken` | 1500–2000 token | 控制单条引用的溯源内容长度 |
| `responseData` | 仅返回文件编号、生效日期 | 匹配民航文档的标准化字段 |
| `detail` | 开启 | 展示完整的溯源元数据 |
| 单次搜索上限 | 前6条 | 覆盖常用的机场文书数据源 |
| 重排 | 开启 | 按相关性排序溯源结果 |

## 容易做错的三处
- 现象：回复内容中出现未解析的`\n`字符，未实现预期换行效果。原因：未在Prompt中配置换行格式适配，或输入的`\n`未经过正确转义处理。
- 现象：引用溯源时弹出“没有权限操作此对话记录”的报错提示。原因：未配置溯源数据的访问权限，或跨环境导入时未同步权限配置。
- 现象：导出工作流并导入其他环境后，工作流中引用的插件无法正常调用。原因：导出工作流时未携带插件的依赖配置，跨环境导入时未重新绑定插件实例。

## 怎么确认配好了
- 生成一份机场安全检查规程的起草内容，核对返回内容末尾是否附带对应文件的编号与生效日期。
- 测试长文本合规文档的引用，确认单条引用的内容长度符合`quoteMaxToken`的预设限制。
- 导出并重新导入工作流，检查引用的插件配置是否完整且可正常调用。
- 输入包含`\n`的测试文本，确认回复内容中的换行效果正常生效。
