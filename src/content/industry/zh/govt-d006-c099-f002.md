# 油气勘探开发的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
油气勘探开发的文书与材料主要来源于勘探项目的正式报告、钻井日志、试采数据分析文档、合规审批文件等。数据更新节奏随勘探项目阶段变动，单次上传规模从单份专业文档到多份批量历史数据不等。文档结构包含长文本段落、结构化参数表格与混合格式内容，核心字段包含井号、勘探区块、井深、渗透率、日产气量等，专业单位包括米、毫达西、立方米每天等。

## 这些特征在「向量模型与索引」这一环带来什么约束
长文本与结构化表格混合的文档结构，要求索引环节同时支持纯文本分块与表格结构化解析，避免拆分破坏专业参数的关联逻辑。专业术语与固定单位的高频出现，要求向量模型具备领域语义适配能力，否则会出现低匹配度的召回结果。不定期且规模波动的上传需求，要求索引支持批量任务拆分与断点续传，适配不同量级的数据处理。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配油气勘探文档的专业段落长度与术语关联范围 |
| 重叠长度 | 100–200 字符 | 保留跨分块的井号、渗透率等核心参数上下文 |
| maxToken | 8192 token | 适配主流专业向量模型的输入长度限制 |
| defaultToken | 1024 token | 作为短文档分块的默认上下文参考值 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关的勘探数据匹配结果 |
| 单次搜索上限 | 前10条 | 平衡专业术语召回的精度与检索速度 |

## 容易做错的三处

- 现象：批量上传80份以上勘探报告时，索引进度卡在90%无更新。原因：未配置断点续传参数，全量索引任务未拆分批次，导致资源耗尽卡住。
- 现象：调用知识库引用时返回非预期的术语匹配结果，比如将“孔隙度”匹配为通用物理孔隙概念。原因：未切换至适配石油石化领域的向量模型，仍使用通用基础模型。

## 怎么确认配好了
- 上传单份10000字符左右的勘探报告，检查分块后的文本片段是否覆盖了完整的专业术语关联段落。
- 调整分块与重叠长度参数后，检索“储层厚度”关键词，核对召回结果的上下文连贯性是否符合业务预期。
- 切换向量模型后，验证检索结果的专业术语匹配精度是否适配油气勘探场景。
- 触发批量索引任务，确认索引进度可正常更新并完成收尾状态展示。
