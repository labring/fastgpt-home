# 油气勘探开发的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
油气勘探开发的文书数据主要来源于野外勘探作业现场、钻井施工日志、试采监测报表、储量评估报告及项目审批文件。数据随作业进度实时生成，勘探阶段更新频率较高，开发阶段随井位调整、储量核算定期更新。文档多为结构化与半结构化混合格式，包含井号、井深、岩性、孔隙度、渗透率等专业字段，单位多采用行业标准的米、毫达西、百分比、立方米每天等。

## 这些特征在「模型接入与配置」这一环带来什么约束
油气勘探开发的文书数据长度较长且专业术语密集，要求模型接入时需保留足够的上下文窗口避免专业内容截断；数据更新频率较高，要求配置环节适配实时或准实时的数据源同步逻辑；结构化字段与专属单位较多，要求模型调用时需严格遵循格式要求，避免生成内容偏离行业规范；多源数据分散存储的特点，要求接入配置支持多路径数据源的统一调用。

## 配置怎么定
基于FastGPT v4.17.0版本的配置逻辑，以下为针对该场景的具体配置建议：

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 油气勘探开发的单篇文书常包含数千字符的专业内容，需保留完整上下文避免截断核心信息 |
| `maxTokens` | 2000–3000 token | 文书起草需生成完整段落与专业结论，避免输出被提前截断 |
| `quoteMaxToken` | 1500–2000 token | 需引用勘探日志、试采数据等原文片段作为生成依据，控制引用内容的长度 |
| `temperature` | 0.3–0.5 | 文书需保持专业严谨的风格，降低随机生成内容的概率，避免偏离行业规范 |
| `AIPROXY_API_ENDPOINT` | 填写国内大模型专属接入地址 | 适配直连国内模型的网络环境，避免跨区域调用导致的延迟与校验问题 |
| `AIPROXY_API_TOKEN` | 填写经权限校验的专属令牌 | 确保模型调用权限合规，避免无效令牌导致的接入失败 |

## 容易做错的三处
- 现象：调用国内模型时返回无效令牌报错，通过oneapi测试正常。原因：未正确配置`AIPROXY_API_ENDPOINT`指向国内模型专属地址，仍使用通用接入地址，导致令牌校验不匹配。
- 现象：bge-reranker模型调用后GPU显存持续占用至6-7G且多GPU均出现占用。原因：未限制`quoteMaxToken`的引用片段长度，导致大量高维度专业文本被送入重排模型，增加显存开销。
- 现象：生成的文书出现专业字段缺失或单位错误。原因：未调整`temperature`参数至合理区间，随机生成内容偏离既定的专业格式与单位要求。

## 怎么确认配好了
- 执行单篇长文档的测试调用，核对输出是否包含完整的专业字段与单位，无提前截断内容。
- 查看模型调用日志，确认`AIPROXY_API_TOKEN`校验通过，无无效令牌报错。
- 监控GPU显存使用情况，确认重排模型调用时显存波动符合预期范围。
- 触发多轮文书起草测试，核对生成内容与源数据的专业术语一致性。
