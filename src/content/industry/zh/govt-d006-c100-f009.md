# 油田工程服务的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
油田工程服务的文书数据主要来源于现场施工台账、钻井工程设计书、油气集输方案、安全合规报审文件等项目全周期产出物。数据更新节奏随单个项目的施工节点推进，单份文档长度跨度较大，短则数十页的施工日志，长则数百页的整体项目方案。文档包含施工点位编号、作业时长、物料用量、合规条款编号等专用字段，单位涉及米、立方米、吨、小时等工程领域专用计量标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
单份文书的长度跨度较大，要求模型上下文处理参数具备灵活调整空间，以适配不同篇幅的文档处理需求。工程类文书包含大量专用字段与单位，要求模型能准确识别并遵循专用术语规范，因此模型接入时需配置适配工程领域的系统提示逻辑。项目周期内文书持续更新，要求配置的索引更新规则匹配项目推进节奏，避免关联文档的时效性偏差。多份关联文书需跨文档整合，因此上下文窗口参数需支持整合不同阶段的工程数据，保证生成文书的逻辑连贯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配油田工程长文档的跨段关联需求，覆盖单项目多阶段文书的上下文整合 |
| `maxTokens` | 4000–6000 token | 限制单轮生成的文书篇幅，匹配工程文档的单章节或单模块输出规范 |
| `quoteMaxToken` | 2000 token | 保留足够的源文档引用片段，确保生成的合规文书可对应到具体施工记录与审批文件 |
| `temperature` | 0.3–0.5 | 降低生成随机性，保证工程文书的格式与术语准确性 |
| `AIPROXY_API_ENDPOINT` | 填写部署节点的完整地址并追加`/v1` | 符合FastGPT v4.17.0的API调用格式要求，兼容代理类模型服务 |
| `AIPROXY_API_TOKEN` | 填写代理服务分配的鉴权密钥 | 完成模型调用的身份验证，确保接口访问权限合法 |

## 容易做错的三处
- 现象：调用模型生成工程文书时界面提示“null未上传”，但后台可正常下载上传的文档。原因：未在`AIPROXY_API_ENDPOINT`后追加`/v1`后缀，导致文件解析接口调用失败。
- 现象：修改docker compose中的模型配置后无生效，页面配置的模型参数无法正常生效。原因：FastGPT v4.17.0及以上版本默认优先使用页面端的模型配置，本地compose配置仅作为备用场景启用。
- 现象：生成的工程文书未关联对应的施工记录，引用内容缺失或不匹配。原因：`quoteMaxToken`参数设置过小，导致源文档的有效引用片段被过度截断。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`是否包含`/v1`后缀，可通过调用代理接口的健康检查接口验证连通性。
- 上传一份典型的钻井日志文档，触发文书生成流程，核对生成内容是否包含正确的工程专用单位与字段。
- 调整`temperature`参数，观察生成文书的术语一致性变化，验证参数是否正常生效。
- 查看后台运行日志，确认模型调用请求的参数与页面配置一致，无异常报错信息。
