# 港口航运的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
港口航运的文书与材料数据主要来源于港口作业管理系统、船舶舱单系统、码头调度平台。数据更新节奏随作业流程推进，单次航次作业完成后生成完整文档，日常调度类文档按每日批次更新。文档结构包含航次标识、船舶信息、泊位编号、货物品类、装卸作业量、作业起止时间等字段，字段单位多采用国际通用的吨、米、小时、TEU（标准集装箱单位），部分内部文档会附加作业权限标识。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
港口航运的文书数据关联多业务系统数据源，且字段包含航次标识、货物装卸量等专属业务参数，因此HTTP接口需支持对接多个外部系统端点以拉取完整的作业基础数据。文档随单次航次作业或每日调度批次更新，接口调用频率需匹配业务更新节奏，避免拉取未完成的临时数据。字段单位与港口作业规范绑定，接口请求参数需严格校验字段格式与对应单位，否则会生成不符合行业标准的起草文书。单份港口文书的内容长度跨度较大，接口返回数据的分页配置需适配不同长度的文档内容，避免截断关键业务信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 接口超时设置 | 60–120 秒 | 适配港口业务系统接口的平均响应时长，避免因作业数据量大导致调用失败 |
| 请求头配置 | 携带`Authorization`令牌 | 符合外部系统的安全校验规范，确保接口调用权限合法 |
| 请求变量配置 | 传入航次编号、泊位编号、货物品类等参数 | 绑定港口文书的专属业务场景，确保起草内容匹配对应作业 |
| 返回数据过滤 | 仅保留文书所需的核心业务字段 | 减少接口传输的数据量，提升调用效率 |
| 重试策略配置 | 失败后重试2次，间隔10–15 秒 | 应对港口业务系统偶尔的网络波动，保障调用稳定性 |
| 上下文长度限制 | 8000–12000 token | 适配港口文书的平均内容长度，避免超出模型处理上限 |

## 容易做错的三处
- 现象：接口调用返回`IPROXY_API_ENDPOINT is not set`报错。原因：未在系统配置中填写港口业务系统的接口地址，导致无法建立外部系统连接。
- 现象：调用接口后生成的文书缺少货物装卸量字段。原因：请求变量配置中未传入对应业务参数，或参数名称与外部系统返回字段不匹配。
- 现象：使用API开启对话后，对话历史中多出一条额外的用户提问记录。原因：未正确配置接口的上下文传递参数，导致重复提交了历史对话内容。

## 怎么确认配好了
- 调用配置好的HTTP接口，检查返回的业务字段是否包含港口文书所需的核心信息。
- 查看接口调用日志，确认`Authorization`令牌已正确携带，且请求头格式符合外部系统要求。
- 发起一次测试调用，对比生成的文书内容与外部系统返回的原始数据，确认字段匹配度符合预期。
- 模拟接口超时场景，检查系统是否触发了预设的重试策略，且未生成重复的文书内容。
