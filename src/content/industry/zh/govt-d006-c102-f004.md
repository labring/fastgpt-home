# 炼化生产的文书与材料起草：工作流编排

## 这个品类的数据长什么样
炼化生产的文书与材料起草涉及多类生产相关文档，数据来源包括装置运行报表、设备巡检台账、工艺操作规程、安全合规文件等。数据更新节奏分为实时（巡检记录）、每日（当班报表）、月度（设备台账更新）三类。文档结构以结构化字段搭配自由文本为主，结构化字段包含装置编号、操作压力、运行温度、巡检时间等，单位涵盖MPa、℃、小时等，自由文本部分则记录异常工况、工艺调整说明等内容。

## 这些特征在「工作流编排」这一环带来什么约束
炼化生产的文书数据特征对工作流编排带来多重约束。结构化字段多且需匹配生产场景，需通过`variables`绑定结构化字段，确保生成内容匹配具体生产场景，要求工作流必须包含字段校验环节，确保生成文书包含装置编号、工艺参数等必填项。长文本占比高，要求工作流对输入文本做合理分块处理，避免超出模型上下文限制。不同文档的更新节奏差异较大，需支持按定时触发或新文档上传触发两种模式。合规性要求严格，工作流需内置合规校验节点，确保生成内容符合石油石化行业规范。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 前800–1200字符 | 炼化文书单段文本较长，避免超出模型上下文承载上限 |
| `variables` | 绑定装置编号、操作压力字段 | 匹配炼化文书的结构化数据特征，确保生成内容关联具体生产参数 |
| 节点超时 | 600秒 | 炼化数据调取可能涉及多系统跨库查询，预留充足响应时间 |
| 触发模式 | 新文档上传触发 | 适配炼化文书按批次或实时更新的发布节奏 |
| 历史对话条数 | 前3条 | 避免冗余历史信息干扰生产相关文书的精准生成 |

## 容易做错的三处
- 工作流执行超时，界面显示状态码504。原因是节点超时设置过短，未预留炼化多系统数据调取的响应时间。
- 工作流调用分支不符合预期，无关知识库内容被返回。原因是未正确配置`variables`绑定专属生产知识库，导致调用通用知识库资源。
- 生成的文书缺少必填的装置编号字段。原因是未在工作流中添加字段校验节点，未强制提取结构化数据中的核心生产信息。

## 怎么确认配好了
- 上传一份包含明确装置编号和工艺参数的炼化测试文书，检查工作流是否自动触发并提取对应字段。
- 模拟长文本输入场景，验证工作流是否按配置的最大上下文长度处理内容。
- 查看工作流日志，确认`nodeId`对应的节点执行状态正常，无报错信息。
- 测试触发分支切换，确认仅调用预设的专属知识库内容，无无关信息返回。
