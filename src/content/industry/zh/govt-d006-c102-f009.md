# 炼化生产的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
炼化生产的文书与材料起草所需数据，主要来源于生产运行日志、工艺规程、设备台账、安全巡检记录与物料平衡报表。数据更新节奏覆盖实时（每小时生成的运行参数）、每日（设备状态台账）与月度（综合报表）。文档以结构化字段为主，包含设备ID、工艺单元号、物料牌号等标识，搭配温度、压力、流量等带固定单位的参数，同时存在非结构化的巡检描述文本，长度从数百字符到数千字符不等。

## 这些特征在「模型接入与配置」这一环带来什么约束
炼化生产数据包含带固定单位的工艺参数、专有工艺术语与长短不一的文档内容，同时存在实时更新的运行日志。这类特征要求配置需确保上下文携带单位规范说明，避免模型随意改写参数格式；需限制上下文窗口大小，适配高频更新的实时数据避免过载；需调整模型生成的随机性，减少专有术语的错误生成；需适配长文档的处理需求，避免内容截断；本地部署需求下，需配置本地模型调用路径，保障数据安全。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配炼化生产的工艺规程、设备台账与实时运行日志的总长度，避免上下文溢出 |
| `maxTokens` | 4000–6000 token | 覆盖长文档类的物料平衡报表、月度安全总结的输出需求，避免截断关键数据 |
| `temperature` | 0.1–0.3 | 减少工艺参数、专有术语的随机改写，匹配炼化生产对格式准确性的要求 |
| `AIPROXY_API_ENDPOINT` | http://localhost:11434/v1 | 适配本地ollama部署的大模型调用，符合炼化场景的数据安全要求 |
| `AIPROXY_API_TOKEN` | 空字符串 | 多数本地ollama部署无需额外验证标识，匹配本地调用的配置规则 |
| `toolChoice` | none | 文书起草场景无需调用工具，避免非必要的逻辑跳转 |

## 容易做错的三处
- 并发请求上升时出现请求超时，现象为接口返回504状态码，原因是未根据实时数据更新频率调整`maxContext`参数，导致上下文加载占用过多资源。
- 模型输出的工艺参数多了多余空格或字母大写，现象为输出文本中“150℃”变为“150 ℃”或“MPA”，原因是未在配置中明确保留原文档格式的要求，同时temperature参数设置过高导致随机改写。
- 本地ollama模型调用失败，现象为测试接口返回“模型未找到”报错，原因是`AIPROXY_API_ENDPOINT`配置的端口与ollama实际监听端口不一致，或未正确添加v1路径后缀。

## 怎么确认配好了
- 基于FastGPT v4.17.0版本，上传一份炼化生产的设备台账文档，发起起草操作，检查输出文本是否保留了原文档的参数单位与专有术语格式。
- 发起3–5个并发的文书起草请求，检查接口响应时间未出现明显波动，无持续超时报错。
- 进入FastGPT的模型测试页面，输入本地ollama部署的模型名称，发起测试调用，确认返回正常的文本结果。
- 查看系统日志，确认模型调用时的上下文token数未超过配置的`maxContext`阈值，无上下文溢出报错。
