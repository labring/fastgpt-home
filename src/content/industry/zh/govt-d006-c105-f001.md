# 煤炭运销的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
煤炭运销的文书数据主要来自内部运销调度系统、合同管理模块与结算台账。数据按单批次运销任务更新，单次任务覆盖1-3个煤种、多段公路或铁路运输链路。标准文书包含合同编号、煤种名称、收到基低位发热量、实际发运量、结算单价、收发货方统一社会信用代码等字段，单位涉及吨、大卡/千克、元/吨等，单份文书字数通常在800-1500字符。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
煤炭运销的文书数据字段包含敏感的企业信用代码、精准的热值与结算参数，要求HTTP接口请求需严格匹配字段名与单位，避免数据解析错误。按单批次更新的特性，要求接口调用需绑定运销批次ID作为查询参数，避免拉取重复或遗漏数据。单份文书字数区间固定，接口返回的`responseData`需适配字符长度限制，支持分页或截断返回。数据更新节奏与运销任务同步，需将接口调用周期匹配任务的更新节点，防止获取过时或未生成的文书内容。同时，内网部署的运销系统要求接口支持局域网访问，需配置对应网络环境的鉴权规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 内网专属Bearer Token，前缀固定为`Bearer `后接64位随机字符串 | 匹配煤炭运销系统的内网鉴权规则，避免外部非法访问，适配FastGPT v4.17.0的鉴权参数格式 |
| `variables` | 绑定运销批次ID、煤种代码两个变量，取值从内部系统的批次接口拉取 | 适配按批次更新的数据特征，确保调用的文书数据对应指定运销任务 |
| `responseData` | 截取前1200字符，超出部分分页返回 | 匹配单份文书的常见字数范围，适配FastGPT的上下文长度限制 |
| 请求超时时间 | 300秒 | 应对大型运销批次的文书数据拉取耗时，避免中途断开连接 |
| 调用周期 | 按运销任务生成节奏，每1-4小时调用一次 | 匹配运销数据的更新频率，确保获取的文书为最新版本 |
| 内网访问配置 | 绑定局域网IP白名单 | 适配煤炭运销系统的内网部署环境，解决跨设备访问异常问题 |

## 容易做错的三处
- 现象：局域网内其他设备访问FastGPT服务时，GET请求返回`net::ERR_INCOMPLETE_CHUNKED_ENCODING`错误。原因：未配置内网IP白名单，接口鉴权规则拦截了非指定网段的请求。
- 现象：定时器触发接口调用后返回的`responseData`为空。原因：未绑定运销批次ID到`variables`参数，接口拉取了全量未分类的原始数据，无法匹配文书起草的指定任务。
- 现象：调用大模型接口失败后，无法查看详细报错日志。原因：未开启FastGPT的接口调用日志存储配置，导致错误信息无法留存排查。

## 怎么确认配好了
- 在内网指定设备上访问FastGPT的接口调试页面，输入绑定了运销批次ID的请求，检查返回的`responseData`是否包含煤种、发运量等核心字段。
- 查看接口调用日志，确认`Authorization`参数携带了正确的内网鉴权Token，无鉴权失败报错。
- 调整定时器的调用周期，核对拉取的文书数据是否与内部运销系统的最新批次数据一致。
- 模拟超出常规字数的文书数据请求，确认接口返回的内容符合预设的截断或分页规则。
