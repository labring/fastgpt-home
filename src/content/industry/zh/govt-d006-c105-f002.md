# 煤炭运销的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
煤炭运销的文书与材料主要来源于运销合同、过磅单、结算单、月度运销计划、铁路/港口发运台账等。数据更新节奏分为三类：单份业务单据生成后即时更新，每日台账数据按发运批次同步，月度结算数据在当月业务结束后汇总更新。单份文档具有固定结构，包含发运方、收货方、煤炭品类、热值、吨位、运价、结算金额、合同编号、发运日期等字段，字段对应单位包括吨、千卡/千克、元、元/吨等。

## 这些特征在「向量模型与索引」这一环带来什么约束
煤炭运销文书的多字段结构与专业术语，要求向量模型需准确识别热值、灰分等行业专属概念，避免语义匹配偏差。不同更新节奏的数据源，要求索引策略需区分增量更新与全量更新的触发时机，适配即时、每日、月度的更新频率。单份文档长度差异较大，短则数十字的过磅单，长则数千字的合同条款，要求索引分块策略需兼顾不同长度的文本，避免拆分专业术语或丢失上下文关联。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 覆盖多数煤炭运销文书的单字段完整内容，避免拆分跨字段的专业术语 |
| 重叠长度 | 100–150 字符 | 保留相邻块的上下文信息，防止热值、运价等关键指标被分块截断 |
| 相似度阈值 | 0.72–0.78 | 煤炭运销文书的专业术语相似度区分度较高，该区间可有效过滤无关匹配结果 |
| 单次搜索上限 | 前 8 条 | 保留足够的候选条目用于后续重排，同时控制检索开销 |
| `maxToken` | 8192 token | 适配FastGPT默认大语言模型的上下文限制，满足长合同文本的处理需求 |
| `defaultToken` | 按第三方渠道提供的密钥填写 | 绑定配置的嵌入模型渠道，确保调用权限正确 |

## 容易做错的三处
- 现象：调用向量模型时返回“该令牌无权使用模型：text-embedding-3-large”报错。原因：未将适配煤炭运销专业文本的嵌入模型配置为默认模型，仍使用了未授权的模型接口。
- 现象：知识库搜索响应耗时超过20秒。原因：分块长度设置过小，导致索引块数量远超实际需求，检索时需遍历过多条目。
- 现象：配置第三方嵌入渠道后仍提示无可用渠道。原因：未正确填写渠道对应的`defaultToken`参数，或渠道名称与第三方平台配置不一致。

## 怎么确认配好了
- 上传一份标准煤炭运销合同，检查索引生成日志中嵌入模型的调用记录是否为配置的目标模型。
- 发起针对运销台账字段的检索请求，核对返回结果的匹配逻辑是否符合煤炭运销文书的专业特征。
- 查看向量数据库的索引统计信息，确认块数量与分块长度的对应关系符合预期。
- 模拟多并发检索请求，检查响应耗时是否处于可接受范围，可根据实际业务场景调整配置。
