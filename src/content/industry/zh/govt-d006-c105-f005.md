# 煤炭运销的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
煤炭运销的业务数据主要来自运销调度系统、合同管理台账、铁路发运凭证、港口装卸记录。数据按单批次运次或每日更新，单份文书关联的核心字段包括合同编号、煤炭品种、收到基低位发热量、全水分、发运吨数、到港时间、收货方统一社会信用代码、结算单价，单位多为吨、千卡/千克、元/吨等行业通用标准单位，单份文书内容通常在800-2000字符区间。本文基于FastGPT v4.17.0版本完成适配。

## 这些特征在「工具调用与插件」这一环带来什么约束
煤炭运销的专业字段与单位要求工具调用需精准匹配行业标准格式，避免参数解析错误。按批次更新的数据要求插件定时拉取最新运次、合同与结算台账，无法依赖静态缓存数据。多数据源关联的文书生成需求，要求工具调用支持跨合同、发运、结算系统的数据拉取，单次调用需整合多类字段。同时，单份文书的字符区间要求插件处理的上下文长度适配800-2000字符的输入输出范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动匹配煤炭运销文书所需的多工具调用场景，无需手动指定工具 |
| 插件数据源刷新周期 | `每6小时` | 匹配煤炭运销运次数据的更新节奏，保障数据时效性 |
| 工具调用超时时间 | `120-180秒` | 跨多系统拉取运销数据需预留足够响应时间，避免中途中断 |
| `functionCall`参数配置 | 强制校验字段格式 | 煤炭运销专业字段需严格匹配单位与数值范围，防止生成错误文书 |
| 文书模板字段映射 | 按实测标定 | 不同企业的运销模板字段存在差异，需适配自有系统的字段命名规则 |

## 容易做错的三处
- 现象：调用工具时日志显示request body字段缺失或格式异常。原因：未按照煤炭运销的专业字段格式配置`functionCall`参数，导致工具生成的请求体不符合行业字段要求。
- 现象：插件调用时无法关联指定的煤炭运销知识库，返回结果为空或无关内容。原因：未配置正确的知识库关联变量，未将运销合同编号作为筛选条件传入插件。
- 现象：插件返回的运销数据陈旧，文书中显示的发运吨数与实际业务数据不符。原因：插件数据源刷新周期设置过长，未及时拉取最新的运次与结算台账数据。

## 怎么确认配好了
- 手动触发一次工具调用，检查返回的运销数据字段是否包含合同编号、收到基低位发热量、发运吨数等必填项，字段单位是否符合行业标准。
- 查看插件运行日志，确认数据源刷新周期按预设频率执行，最新数据的时间戳与当前时间差符合业务更新节奏。
- 测试`functionCall`参数的校验逻辑，输入不符合单位要求的数值，确认工具会返回格式错误提示。
- 调用工具生成一份测试文书，检查生成内容是否关联了指定的运销知识库内容，无冗余或缺失字段。
