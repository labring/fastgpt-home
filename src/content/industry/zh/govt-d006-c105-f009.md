# 煤炭运销的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
煤炭运销的文书数据主要来自运销合同、过磅单、结算单、月度运销计划与发货通知单。数据按业务批次更新，单次单据长度从数百字符的发货通知到数千字符的月度运销总结不等。固定字段包含货物品名、发运量（单位：吨）、收货方全称、运输路线、结算单价（单位：元/吨）、开票主体与税号，部分跨区域运销文档还包含铁路/公路运输许可编号。

## 这些特征在「模型接入与配置」这一环带来什么约束
煤炭运销文书的固定专有字段与行业专属单位，要求模型能精准识别并对齐业务术语，因此模型接入时需确保上下文窗口覆盖完整单据字段。长文档与短单据并存的结构，要求配置可灵活调整上下文与输出token限额。跨区域运销文档包含额外许可编号等非标准化附加字段，需模型能处理自定义字段提取，因此需开启适配自定义工具的配置项。同时，业务数据按单次运销批次更新，需模型能快速适配新批次的单据格式，因此配置需支持快速调整参数以匹配不同类型的文书。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖完整运销合同、月度总结等长文档的上下文需求，避免截断关键业务字段 |
| `maxTokens` | 1500–2500 token | 匹配煤炭运销文书起草的输出长度，涵盖结算明细、运输说明等完整内容 |
| `toolChoice` | auto | 支持自动调用工具提取运单、过磅单中的专有字段，适配跨区域文档的附加信息 |
| `temperature` | 0.3–0.6 | 保持文书格式与业务术语的一致性，避免生成不符合行业规范的表述 |
| `AIPROXY_API_ENDPOINT` | 填写本地部署的OneAPI接入地址 | 适配本地部署的FastGPT环境，确保模型调用链路正常 |
| `AIPROXY_API_TOKEN` | 填写OneAPI生成的有效令牌 | 完成模型接入的身份验证，确保调用权限合法 |

## 容易做错的三处
- 现象：本地部署FastGPT后，OneAPI可ping通模型与向量模型且令牌配置正确，但生成运销文书时返回报错。原因：未将煤炭运销专属的业务字段纳入模型的上下文配置，导致模型无法识别专有术语触发格式错误。
- 现象：模型选择列表可正常展示全部可选模型，但工具调用环节仅能看到少量模型。原因：未开启`toolChoice`对应的模型适配开关，或未将煤炭运销场景的工具权限绑定至对应模型。
- 现象：尝试调用o1-preview模型生成运销文书时失败，返回模型不支持的错误。原因：未在FastGPT的模型配置中开启兼容大上下文的模型开关，或未正确配置`maxContext`适配大模型的上下文要求。

## 怎么确认配好了
- 上传一份标准煤炭运销合同，查看模型生成的起草文书是否准确识别货物品名、发运量等专有字段。
- 在工具调用环节选择已配置的模型，查看是否可正常提取过磅单中的运输路线与许可编号信息。
- 调整`temperature`参数后，生成两份同类型文书，核对业务术语的一致性是否符合预期。
- 检查OneAPI的调用日志，确认无401认证错误或超时错误，且请求参数包含煤炭运销专属的业务字段。
