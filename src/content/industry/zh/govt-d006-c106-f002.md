# 煤电一体化的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
煤电一体化的文书与材料数据主要来自煤炭开采、电力生产全流程的业务文档，包括生产调度报表、安全作业规程、设备运维记录、项目可研报告与合同文件。数据更新节奏覆盖日常实时更新的运维日志、每日固定上报的生产数据，以及月度、季度的合规性报告。文档结构包含固定业务字段，如矿井编号、机组编号、发电量、耗煤量等，部分长文本文档会附带审批流程节点与时间戳。

## 这些特征在「向量模型与索引」这一环带来什么约束
煤炭与电力业务的文档结构差异较大，短文本审批单与长文本可研报告混合存在，要求向量分块策略适配不同长度的文本单元。实时更新的运维日志与定期上报的生产数据并存，要求索引支持增量更新与定时全量刷新结合的机制。文档中包含矿井编号、机组编号等结构化字段与发电量、耗煤量等数值型单位，要求向量模型在编码时保留结构化字段的语义关联，避免数值单位被错误截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配煤电一体化文档中长文本可研报告与短文本审批单的混合结构，避免单块文本过长或过短影响向量编码效果。 |
| 重叠长度 | 50–100 字符 | 保留跨分块的上下文关联，避免长文档的关键逻辑被分块截断，适配生产报表的连续数据段落。 |
| 相似度阈值 | 0.75–0.85 | 匹配煤电业务文档的专业术语密度，过滤低相关性的检索结果，保障文书起草的内容准确性。 |
| 单次搜索上限 | 前 8 条 | 平衡检索效率与内容覆盖度，适配煤电业务文档的专业术语集中的检索需求。 |
| `maxToken` | 8000 | 适配长文本可研报告的向量编码上限，避免超出模型处理边界导致内容丢失。 |
| `defaultToken` | 2000 | 作为默认分块的token上限，适配多数日常运维文档的长度需求。 |

## 容易做错的三处
- 界面提示无法连接外部向量数据库实例，无法完成索引构建。原因是未在FastGPT的知识库配置中正确填写外部向量数据库的访问地址与权限密钥。
- 向量检索返回的结果条数与设置的单次搜索上限不符，检索内容偏离业务主题。原因是相似度阈值设置未适配煤电业务文档的专业术语密度，导致大量低相关性结果被误判。
- 启用索引模型后未生成有效向量数据，检索时返回空结果。原因是未触发知识库的索引刷新任务，或上传的文档未包含可被编码的有效文本内容。

## 怎么确认配好了
- 进入FastGPT的知识库管理页面，查看向量数据库绑定状态，确认显示为已连接。
- 上传一份煤电一体化的运维日志文档，触发手动索引刷新，等待任务完成后查看向量生成进度。
- 输入一段煤电业务相关的检索词，执行向量检索，确认返回结果包含匹配的业务文档片段。
- 查看`maxToken`与`defaultToken`的配置值，确认符合当前使用的向量模型的处理上限。
