# 煤电一体化的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
煤电一体化场景的文书起草数据主要来自煤矿采掘台账、电厂运行日志、煤炭购销合同、电力调度批复及环保排放报表。数据按生产班次或每日更新，文档结构包含作业单号、煤炭热值、发电负荷、审批文号、环保排放指标等字段，单位涵盖千卡/千克、兆瓦、吨、立方米等专业计量标准，文档长度从数十页的月度总结报告到单页的当班调度单不等。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且包含结构化台账与非结构化报告，要求插件支持多数据源的批量拉取与字段对齐。数据更新频率较高，需插件具备定时同步机制，避免调用过期的生产与调度数据。专业字段与单位较多，要求工具调用的参数需明确指定字段名与对应单位，防止AI生成不符合行业规范的请求。文书需符合能源监管合规要求，需额外关联合规校验工具，确保起草内容符合当地电力与煤炭行业的政策标准。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配煤电文书起草的多工具自动调度需求，无需手动指定调用工具 |
| 插件缓存时长 | 8–12 小时 | 匹配煤电数据每班/每日的更新频率，避免调用过期的生产与调度数据 |
| 单次工具调用超时时间 | 30 秒 | 适配煤电实时调度类文书的快速响应要求 |
| `functionCall` | 按煤电专属参数模板生成结构化调用 | 确保生成的数据请求符合煤电专业字段与单位的规范 |
| 数据源拉取条数上限 | 前 20 条 | 控制单次调用返回的数据量，避免上下文过载影响文书生成效率 |

## 容易做错的三处
- 工具调用返回字段为空：未配置煤电专属字段映射，导致AI无法识别热值、发电负荷等专业字段的参数要求。
- 界面无法找到插件导入入口：未在系统设置中开启工具调用模块，或使用的FastGPT v4.17.0未适配插件管理功能。
- 生成的请求包含错误单位：未在插件参数中指定煤电字段的单位规则，导致AI混淆专业计量标准的参数格式。

## 怎么确认配好了
- 进入工具管理页面，确认已上传煤电数据拉取插件并开启启用状态。
- 发起测试调用，输入与煤电调度或文书相关的测试指令，检查工具是否自动调用对应数据源并返回结构化数据。
- 查看工具调用日志，确认参数格式符合煤电字段规范，无字段缺失或单位错误。
- 调整插件缓存时长参数，验证插件数据是否按设定频率自动更新。
