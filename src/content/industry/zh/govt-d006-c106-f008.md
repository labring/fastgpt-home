# 煤电一体化的文书与材料起草：文档解析与分块

## 这个品类的数据长什么样
煤电一体化场景的文书与材料，主要来源为矿井开采台账、电力调度报表、购销合同、安全检查报告等。数据更新节奏覆盖实时调度单、每日运行日志、月度生产报表等多周期。文档形态包含单篇10万中文字的Word合规报告、15000行以上的Excel生产数据表格，字段包含煤炭发热量、机组负荷、供电量、隐患整改编号等，单位涉及吨、千瓦时、兆瓦等专业计量标识。

## 这些特征在「文档解析与分块」这一环带来什么约束
单篇长Word文档的拆分需避免割裂专业段落，如安全整改流程的连续描述被截断，影响后续语义关联。上万行Excel表格的分块需保留表头与对应行数据的绑定关系，防止单独拆分数据行导致字段含义缺失。多周期更新的生产数据，分块需匹配业务查询的时间维度，避免跨周期数据被强制合并。专业计量单位与字段的绑定关系，需在解析时完整保留，防止出现无单位的模糊数值内容，影响后续业务判断。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的参数规则。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配煤电一体化文档的专业段落长度，避免割裂安全报告、调度流程的连续语义 |
| `chunkSplitter` | 按段落+固定字符阈值 | 适配Word文档的自然段落结构，同时限制单块最大长度，避免单块过大导致的资源消耗过高 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配10万中文字Word文档的解析耗时，防止长文档解析超时中断 |
| `chunkSettingMode` | 手动自定义 | 针对Excel上万行数据单独配置分块规则，保留表头与数据行的关联 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单篇10万中文字Word或15000行Excel文件的上传，满足业务文档的存储需求 |

## 容易做错的三处
- 现象：Excel文件解析后返回模糊提示，无法提取完整数据内容。原因：未配置Excel分块的表头绑定规则，导致解析时丢失表头与数据行的关联，触发模型识别异常。
- 现象：10万中文字Word文档解析超时，任务失败。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，使用默认值导致长文档解析未完成即中断。
- 现象：分块后的数据块过大，导致RAG匹配时资源消耗过高。原因：未设置合理的`chunkSize`参数，沿用通用文档的分块长度，未适配煤电一体化文档的专业段落特征。

## 怎么确认配好了
- 上传单篇10万中文字的Word文档，检查解析任务的状态是否为完成，无超时报错。
- 上传15000行的Excel文件，查看解析后的分块内容，确认表头与对应数据行完整绑定。
- 调整`chunkSize`参数后，测试分块后的文本长度，确保专业段落未被割裂。
- 查看解析日志，确认`UPLOAD_FILE_MAX_SIZE`参数未限制目标文件的上传大小。
