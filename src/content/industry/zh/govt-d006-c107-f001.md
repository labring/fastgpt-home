# 煤矿生产的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
煤矿生产的文书与材料起草数据主要来自井下生产调度系统、安全监控平台、机电设备台账库、班组作业记录。数据更新以每班作业结束后汇总为主，部分实时监控参数随作业进程同步更新。文档结构包含工作面编号、班次、作业时长、隐患排查条目数、设备运行时长等固定字段，单位多为米、小时、条、台，单份文书长度通常在500-2000字符，需关联当日作业的具体设备与人员信息。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据来源要求接口需支持对接井下调度、安全监控等多个外部系统，需配置跨系统的字段映射规则，避免数据格式不匹配。实时更新的作业参数要求接口响应时长适配短周期数据同步，不宜过长。单份文书较长且关联多维度信息，接口请求体需预留足够的字符容量，同时需规范传递工作面编号、班次标识等关联字段，确保生成的文书与现场作业信息准确绑定。

## 配置怎么定
本配置说明适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带 Bearer 令牌，令牌有效期设为 7 天 | 适配煤矿内网接口的鉴权要求，避免频繁刷新令牌影响作业流程 |
| `variables` | 传入工作面编号、班次ID、隐患条数等字段 | 匹配煤矿文书的固定关联字段，确保生成内容与现场作业数据绑定 |
| `responseData` | 配置返回字段包含生成文书内容、关联数据ID | 便于外部系统接收并存储完整的文书与溯源信息 |
| 请求超时时间 | 30–60 秒 | 适配多源数据拉取的时长，避免因井下网络延迟导致请求中断 |
| 重试次数 | 2–3 次 | 应对井下网络波动导致的接口调用失败，减少人工干预 |
| 单次请求数据量 | 不超过 1000 字符 | 匹配单份煤矿文书的常规长度，避免请求体过大导致传输失败 |

## 容易做错的三处
- 现象：接口返回429状态码，或提示调用频率超限。原因：未配置合理的请求间隔策略，并发请求超出煤矿内网接口的限流阈值。
- 现象：生成的文书缺少工作面编号等关联字段。原因：未通过`variables`传入对应业务标识参数，导致生成内容无法绑定现场作业数据。
- 现象：接口调用超时，返回504状态码。原因：请求超时设置过短，未适配井下网络延迟与多源数据拉取的耗时。

## 怎么确认配好了
- 调用测试接口，检查返回的`responseData`中是否包含预期的文书内容与关联业务ID，核对字段是否与预设一致。
- 模拟并发请求，观察接口返回状态码，调整请求间隔与重试次数至符合当前接口的限流规则。
- 查看接口日志，确认`Authorization`令牌已正确携带，未出现鉴权失败的报错信息。
- 导入单份煤矿作业数据发起请求，验证生成的文书内容是否完整关联了作业现场的具体参数。
