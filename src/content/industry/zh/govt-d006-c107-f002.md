# 煤矿生产的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
数据主要来自矿井调度日志、掘进施工记录、通风安全报表、班组交班台账与安全规程文档。更新节奏随业务场景变化，班组台账每日更新，调度日志实时生成，月度安全报表按周期汇总。文档多为结构化与半结构化混合，包含矿井编号、班次、作业时间等固定字段，附带瓦斯浓度、通风量、掘进进尺等带单位的数值项，正文多为现场操作描述与隐患整改说明。

## 这些特征在「向量模型与索引」这一环带来什么约束
半结构化与结构化混合的文档结构，要求索引支持多字段关联检索，避免仅对正文做向量编码而丢失矿井编号、班次等关键元数据信息。实时生成的调度日志需要支持高频增量索引，避免全量重建带来的性能开销。带单位的数值项如瓦斯浓度、通风量，若直接嵌入正文会导致向量编码的语义偏差，需要提前将数值与单位绑定处理后再输入向量模型。不同文档的字段格式统一度有限，需要索引支持灵活的元数据过滤，缩小检索范围。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 煤矿生产文书多为现场操作描述与结构化字段结合，该长度可平衡语义完整性与向量编码精度 |
| 重叠长度 | 100–150 字符 | 避免分块后关键信息被截断，保障跨分块的语义连贯性 |
| 相似度阈值 | 0.72–0.85 | 适配煤矿文书的专业术语密度，过滤低相关性的检索结果 |
| 单次搜索上限 | 前 10 条 | 控制检索结果的信息量，避免超出上下文窗口限制 |
| `maxToken` | 8000 token | 适配煤矿长文档的检索结果拼接，符合多数向量服务的输入限制 |
| `defaultToken` | 512 token | 设定单条向量编码的最大长度，适配专业术语较多的文书内容 |

## 容易做错的三处
- 现象：向量化任务耗时过长，接口返回504超时状态码。原因：仅单条文本切片提交请求，未启用批量向量化处理，未适配向量服务的batch批处理逻辑。
- 现象：检索结果相关性偏差较大，部分无关的行政文档被召回。原因：未针对煤矿文书的专业术语密度调整相似度阈值，未启用元数据过滤缩小检索范围。
- 现象：分块索引的内容无法正常获取，接口返回空的分块文本字段。原因：未正确配置分块存储的关联规则，未将结构化字段与向量分块绑定存储。

## 怎么确认配好了
- 查看向量服务的运行日志，确认是否存在批量提交的文本切片请求，验证批处理逻辑是否生效。
- 发起一次煤矿文书的检索测试，核对检索结果的元数据是否包含矿井编号、班次等专属字段，验证元数据过滤是否正常工作。
- 检查分块索引的存储列表，确认每个分块都关联了对应的结构化元数据字段，验证分块配置是否正确。
- 查看系统的参数配置界面，确认`maxToken`与`defaultToken`的取值与预设配置一致，验证参数是否生效。
