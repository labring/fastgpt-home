# 煤矿生产的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
煤矿生产的文书与材料数据主要来源于三类场景：一是班组日常生产记录，包含班次、出勤人数、设备运行时长、隐患排查项等内容；二是月度生产报表、设备运维台账，包含设备编号、检修周期、耗材用量等字段；三是安全生产规程、应急处置预案等规范性文档。数据更新节奏差异明显：班组记录每日更新，运维台账按检修节点更新，规范性文档每年修订一次。单份文档长度从数百字符的班组日志到数十页的规程文件不等，字段包含时间戳、唯一设备编码、隐患等级等，单位涉及小时、台、条等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源异构的数据结构要求溯源时需绑定唯一标识，避免不同文档中同名字段混淆。更新频率差异决定了检索范围需区分实时生产数据与历史规范文档，防止跨周期数据错误关联。长短文档并存的特征要求分块时保留字段关联信息，避免溯源时匹配到不相关的段落。字段包含设备编号、隐患等级等专业属性，要求检索时需开启精准匹配，防止泛化检索返回无关内容。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配煤矿班组日志与规程文档的平均段落长度，避免分块过碎或过长导致溯源偏差 |
| 相似度阈值 | 0.75–0.85 | 匹配煤矿专业术语的语义精度，防止泛化检索返回无关的运维记录 |
| 单次搜索上限 | 前 3 条 | 控制引用来源数量，避免输出内容冗余，符合煤矿文书的严谨性要求 |
| `quoteMaxToken` | 200–300 token | 预留足够空间显示引用标识，防止出现截断乱码 |
| `responseData` | 开启 | 携带文档来源的唯一标识与字段信息，支持精准溯源 |
| `detail` | 开启 | 展示引用文档的核心字段，便于核对生产数据的准确性 |

## 容易做错的三处
- 检索知识库中不存在的煤矿场景问题时，仍返回无关文档的引用。原因是未关闭“无检索结果时调用大模型生成”的开关，导致大模型强制关联已有知识库内容。
- 输出内容末尾出现未闭合的引用标记乱码。原因是`quoteMaxToken`设置过小，导致引用标识被截断未完成闭合。
- 工作流中调用知识库工具后，无法返回引用来源信息。原因是未开启`responseData`参数，导致工具返回结果未携带溯源所需的文档标识数据。

## 怎么确认配好了
- 发起包含已知设备编号的查询，核对输出末尾的引用标识是否匹配对应文档的唯一编号。
- 输入知识库中不存在的煤矿应急场景问题，确认无引用内容返回。
- 在工作流中调用知识库工具，查看返回结果是否包含文档来源的详细信息。
- 发起包含长文本的生产报表查询，确认引用标识未出现截断或乱码。
