# 煤矿生产的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
煤矿生产的文书与材料主要来自现场作业记录、安全检查台账、调度日报、月度总结等内部系统。数据更新节奏覆盖每班、每日、月度，文档分为短表单类（如现场整改单、交接班记录）和长文档类（如安全专项报告）。文档结构多带有固定字段，包括作业区域、设备编号、检测参数、责任人等，部分参数带有专属单位，如瓦斯浓度、掘进进尺、通风量等。

## 这些特征在「模型接入与配置」这一环带来什么约束
现场表单类文书的短文本高频调用，要求模型接入时适配快速响应的参数设置；长文档类报告需要适配大上下文窗口的配置，避免截断关键内容。固定专业字段的准确提取要求模型优先调用专业术语匹配能力，同时需限制虚构参数的生成。多更新频率的数据对应不同的文档处理优先级，需配置对应的上下文刷新规则，避免使用过期数据生成文书。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–16000 token | 覆盖月度安全报告等长文档的完整上下文，避免关键内容截断 |
| `maxTokens` | 2000–3000 字符 | 适配现场整改单、交接班记录等短文书的生成长度，避免输出冗余 |
| `temperature` | 0.2–0.4 | 降低虚构参数概率，保障煤矿专业数据的严谨性 |
| `toolChoice` | auto | 自动适配文书生成所需的专业术语调用，无需手动配置工具 |
| `AIPROXY_API_ENDPOINT` | 按FastGPT v4.17.0平台提供的专属地址填写 | 匹配FastGPT的代理调用规则，保障模型请求正常路由 |
| `AIPROXY_API_TOKEN` | 绑定煤矿生产场景的专属密钥 | 隔离场景权限，避免跨场景数据泄露 |

## 容易做错的三处
- 新建文书生成节点后使用初始化模型保存报错：原因是初始化模型未配置场景专属的上下文参数，无法适配煤矿文书的长文本处理需求。
- 切换为工具调用-claude4模型后出现bedrockruntime相关报错：原因是未正确配置`AIPROXY_API_ENDPOINT`的区域路由规则，导致跨区域请求被拦截。
- 文本提取组件无法正常解析专业字段：原因是未调整`temperature`参数降低随机性，导致模型错误拆分专业参数的单位与数值。

## 怎么确认配好了
- 上传一份标准的煤矿掘进日报，测试生成对应的安全整改建议，核对输出内容是否包含正确的作业区域与参数单位。
- 调用模型生成一份月度安全总结，检查输出长度是否符合预设范围，无内容截断情况。
- 切换不同的专业文书类型，验证`toolChoice`是否自动适配不同的生成逻辑，无固定格式错误。
- 查看API调用日志，确认`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的请求参数无格式错误。
