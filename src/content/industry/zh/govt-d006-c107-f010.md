# 煤矿生产的文书与材料起草：知识库检索与召回

## 这个品类的数据长什么样
煤矿生产的文书数据主要来源于作业规程、安全台账、隐患排查记录、设备运维日志、交接班记录等。日常作业类记录每日更新，规程类文档按季度或年度完成修订。文档结构包含结构化条款与非结构化日志两类，结构化文档含章节、条款编号、适用场景字段，非结构化日志包含设备编号、隐患等级、排查日期、作业班组等字段，单位涉及吨、米、小时、MPa等专业计量标识。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化的规程文档需要精准匹配条款编号与适用场景，避免召回跨场景的无关内容；非结构化的运维日志与排查记录语义关联较强，需要兼顾关键词与语义匹配。每日更新的作业记录要求知识库定期刷新，否则召回内容会滞后于现场作业。多字段的文档结构需要指定检索维度，避免因无关字段干扰召回结果；专业计量单位的差异会导致匹配偏差，需要在检索时统一单位识别逻辑。FastGPT v4.17.0版本针对这类专业场景优化了字段过滤逻辑，需适配该版本的配置规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.72–0.80 | 煤矿生产文书对合规性要求较高，该区间可过滤低匹配度的无关内容，同时保留足够的有效召回结果 |
| `limit` | 前8条 | 煤矿文书的起草常需结合多条款与多场景记录，8条的召回量可覆盖多数起草需求 |
| `usingReRank` | 开启 | 煤矿运维日志与隐患记录的语义关联较强，重排可提升高相关结果的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 煤矿行业存在大量专属术语，扩展查询可覆盖专业表述的变体，提升召回覆盖度 |
| `collectionIds` | 指定煤矿生产文书专属集合ID | 避免检索到其他品类的文档，缩小召回范围至目标数据集 |

## 容易做错的三处
- 现象：GPU显存在知识库检索完成后仍居高不下，重排模型未自动释放资源。原因：未在FastGPT v4.17.0中配置检索后自动卸载重排模型的相关钩子。
- 现象：配置问答拆分时必现Invalid array length报错。原因：拆分的文本块长度超出系统预设的数组边界，或存在未闭合的格式符号。
- 现象：检索召回的结果包含大量非煤矿生产的文书内容。原因：未通过`collectionIds`指定专属的煤矿生产文书数据集集合，导致检索范围覆盖了其他品类的文档。

## 怎么确认配好了
- 上传一份测试用的煤矿隐患排查记录，执行检索后查看返回结果的来源集合，确认仅包含指定的煤矿生产文书数据。
- 查看GPU监控面板，确认检索完成后重排模型的显存占用回落至基线水平。
- 输入煤矿专属术语，比如「综采工作面回撤规程」，查看检索结果的匹配度是否符合预设的`similarity`区间。
- 测试问答拆分功能，输入一段超过常规长度的煤矿作业日志文本，确认无Invalid array length报错。
