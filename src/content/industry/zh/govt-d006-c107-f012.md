# 煤矿生产的文书与材料起草：部署与升级

## 这个品类的数据长什么样
煤矿生产的文书与材料主要来自现场作业班组的日报、调度台账、安全验收单、采掘作业规程文档等。数据更新按作业班次完成后即时提交，每日汇总形成当日生产报表，月度形成安全与生产总结。单篇文档长度跨度大，短则数百字的班前会记录，长则数万字的年度采掘方案。文档字段包含固定的作业地点、作业时间、作业人员、隐患排查项、整改时限等，部分安全类文档带有强制格式的参数项，单位涉及米、%LEL、人次等专业单位。

## 这些特征在「部署与升级」这一环带来什么约束
煤矿生产文书的多长度文档特征，要求部署时需适配不同规模的文件解析流程，避免短文档过度拆分或长文档截断。固定字段与专业单位的要求，需要在数据接入环节保留原始字段格式，避免标准化处理破坏专业参数的准确性。按班次/每日的高频更新节奏，要求服务器具备足够的CPU与内存资源以支撑高频的文书数据处理，同时部署的数据库连接稳定性达标，升级时需兼顾增量同步与全量更新的兼容，避免数据同步中断影响当日作业文书生成。此外，安全类文书的强制格式要求，需在知识库嵌入环节保留原文档的结构标记，避免生成的文书不符合煤矿行业规范。

## 配置怎么定
本文基于FastGPT v4.17.0版本进行以下配置说明。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–15 个 | 匹配煤矿生产文书的高频读写需求，多班组同时提交数据时避免连接耗尽 |
| `MONGODB_URI` | 配置为煤矿内网专用MongoDB实例的连接串 | 存储非结构化的作业文书与归档文档，内网部署保障敏感生产数据安全 |
| `REDIS_URL` | 配置为内网Redis缓存实例，缓存有效期设为3600秒 | 缓存当日作业班组的人员、设备基础数据，减少重复查询数据库的延迟 |
| `STORAGE_S3_ENDPOINT` | 配置为煤矿内网对象存储服务的端点地址 | 存储上传的原始文书扫描件与生成的正式文档，符合企业内网数据存储规范 |
| `FE_DOMAIN` | 配置为煤矿内网的访问域名 | 限制前端访问仅在企业内网范围内，避免外部未授权访问 |

## 容易做错的三处
- 现象：部署后OneApi页面无法加载，控制台返回404状态码。原因：未正确配置`FE_DOMAIN`参数，或前端静态资源部署路径与配置不匹配，导致页面资源无法正常加载。
- 现象：无法创建多账号或团队共享登录失败，无法实现同一团队内多账号共享知识库。原因：未正确配置`PG_URL`连接到支持多租户的数据库实例，或数据库权限配置未开放团队账号的关联权限。
- 现象：生成的文书内容与原始煤矿文档格式不符，专业字段或单位缺失。原因：在数据预处理环节未保留煤矿文书的固定字段格式，或知识库嵌入时未保留专业参数的单位信息，导致生成的文书不符合行业规范。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`DB_MAX_LINK`、`MONGODB_URI`、`PG_URL`、`REDIS_URL`的配置是否能正常建立连接，连接数不超过预设的最大连接限制。
- 上传一篇煤矿生产的原始作业日报，检查文件是否能正常解析并存储到配置的对象存储服务中，验证`STORAGE_S3_ENDPOINT`的配置生效。
- 访问配置的`FE_DOMAIN`地址，确认前端页面能正常加载，无资源加载失败的提示。
- 创建测试账号并加入同一团队，验证多账号登录与团队共享功能是否正常启用。
