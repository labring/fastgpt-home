# 电网企业的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
电网企业的文书与材料主要来自日常调度日志、设备运维记录、安全操作规程、招投标文件及内部行政通知。数据更新节奏随场景变化，调度日志按日更新，安全规程按年度修订，招投标文件随项目不定期生成。文档结构包含结构化字段（如设备ID、电压等级单位kV、运维时长单位小时）与非结构化文本段落，部分长文档单篇可达数万字符。

## 这些特征在「向量模型与索引」这一环带来什么约束
电网企业文书的结构化字段与单位要求，要求向量模型在编码时保留字段语义关联，避免单位信息丢失导致匹配偏差。长文档占比高的场景，需要限制单块文本长度，防止超出向量模型的token上限。多更新节奏的数据源，需要适配增量索引与全量索引的混合策略，区分高频更新的调度日志与低频更新的安全规程。非结构化段落格式不统一，需在分块前统一文本格式，避免冗余符号干扰向量编码。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配电网企业长文书的语义完整性，避免单块内容断裂导致向量编码偏差 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，防止跨块语义丢失 |
| `defaultToken` | 4096 token | 匹配多数开源向量模型的默认输入上限，适配电网企业常规文书的分块编码需求 |
| `maxToken` | 8192 token | 针对超长篇的年度运维总结文档，预留足够的token空间完成完整向量编码 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关文档，适配电网企业文书的专业语义匹配精度 |
| 单次搜索上限 | 前10条 | 控制返回结果的数量，避免上下文过载影响文书起草的准确性 |

## 容易做错的三处
- 现象：升级FastGPT版本后，相同配置的电网文书CSV文件分块失败，界面弹出参数超限报错。原因：新版本优化了分块长度的校验规则，原配置的分块长度超出新的合规区间。
- 现象：知识库索引任务长时间卡住，未完成的数据集显示为未索引状态。原因：未针对电网企业的长文档调整`maxToken`配置，导致超长运维总结文档无法完成向量编码。
- 现象：检索返回的文书材料中混入大量不相关的行政通知，匹配结果不符合专业场景需求。原因：相似度阈值设置过低，未过滤非专业领域的低匹配度内容。

## 怎么确认配好了
- 上传单篇典型的电网长文书（如年度运维总结），检查分块结果是否保留了完整的专业段落，无内容断裂。
- 触发一次全量索引任务，监控任务进度，确认无长时间卡住的节点。
- 输入专业检索词（如“110kV变电站运维规程”），核对返回结果的匹配度是否符合专业场景的预期。
- 查看向量模型的编码日志，确认结构化字段的单位信息未被丢失，向量编码语义一致。
