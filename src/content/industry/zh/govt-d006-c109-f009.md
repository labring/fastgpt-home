# 电网企业的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
电网企业的文书与材料主要来源于内部作业文档、安全管理文件、招投标技术文件及月度运营总结。更新节奏随文档类型差异明显：检修报告随单次作业完成实时更新，安全规程每季度复核更新，招投标文件随项目立项同步生成。文档多包含固定表头，正文分为技术参数区、流程步骤区、责任主体区，部分嵌套设备清单表格，字段包含电压等级（单位kV）、作业时长（单位小时）、设备编号等，部分文书附带电气接线图或设备布局图。

## 这些特征在「模型接入与配置」这一环带来什么约束
电网文书包含大量电力专业术语和长段落内容，部分文书附带图纸类附件，数据更新频率差异较大。这些特征要求模型接入配置需适配长文本上下文，需支持专业术语识别，需兼容视觉解析能力；同时，因部分文书需严格匹配内部格式，需限制模型输出的发散程度，避免生成不符合规范的内容；另外，内网部署的模型服务需正确配置访问端点与密钥，确保数据传输安全，避免敏感信息泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配电网文书中长段落、嵌套表格的内容长度，避免关键专业信息被截断 |
| `maxTokens` | `2000–3000 token` | 满足电网文书起草时输出完整的技术参数、流程说明的需求 |
| `vision` | `开启` | 部分电网文书附带电气接线图、设备布局图，需识别图中信息辅助起草 |
| `temperature` | `0.2–0.4` | 保障起草内容的专业性和格式规范性，避免过度发散 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 对接本地或私有部署的大模型服务，确保请求路径正确 |
| `AIPROXY_API_TOKEN` | 填写对应模型服务的访问密钥 | 完成身份验证，避免请求被拦截 |

本指南基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 现象：调用模型后返回`model response empty`，无有效输出。原因：未正确配置`AIPROXY_API_ENDPOINT`，导致请求无法到达目标模型服务，或`maxTokens`设置过小，输出被强制截断为空。
- 现象：上传的电气图纸类文书无法被正确解析，模型输出未包含图中信息。原因：未开启`vision`配置项，未启用视觉模型的文档解析能力。
- 现象：API上传文件到最后一步失败，返回连接超时。原因：未正确配置`AIPROXY_API_TOKEN`导致身份验证失败，或请求超时阈值设置不合理，未适配内网部署的模型服务延迟。

## 怎么确认配好了
- 向FastGPT平台提交包含电网专业术语的测试文本，核对模型输出是否准确还原术语含义，无明显错译。
- 上传包含电气接线图的测试文书，验证模型输出是否提及图中的设备参数或连接关系。
- 调用API接口提交测试请求，检查返回结果中是否包含有效内容，无`model response empty`类报错。
- 核对`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的填写内容，确保与部署的模型服务参数一致。
