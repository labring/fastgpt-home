# 矿山采选的文书与材料起草：模型接入与配置

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
矿山采选的文书与材料起草相关数据主要来源于采矿设计图纸、选矿流程卡、安全生产规程、每日生产日报、设备运行台账等。数据更新节奏差异较大，生产日报每日更新，设计文档在项目周期内阶段性更新，安全规程随法规修订不定期更新。文档结构多包含工序编号、设备型号、处理量、药剂配比等字段，单位涉及吨、立方米、千克、小时等，部分长文档包含多页流程说明与参数表格。

## 这些特征在「模型接入与配置」这一环带来什么约束
矿山采选相关数据包含大量行业专属专业术语，要求模型接入时需适配这类词汇的语义理解，避免生成内容出现专业错误。长文档占比高，部分选矿流程文档篇幅超过千字，需要配置足够的上下文容纳参数，避免关键生产数据被截断。高频更新的生产日报类数据，要求嵌入流程定期触发，保障检索内容的时效性。同时，文书起草需严格匹配现场作业参数，对模型输出的准确性要求较高，需限制过度发散的生成行为。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 矿山采选的流程文档、生产报告通常较长，需容纳足够上下文以准确关联现场参数 |
| `maxTokens` | 2000–3000 token | 文书起草的输出篇幅通常在千字左右，匹配专业文书的常规长度需求 |
| `quoteMaxToken` | 4000 token | 需完整引用选矿流程参数、设备台账内容，避免截断关键业务数据 |
| `temperature` | 0.3–0.5 | 文书起草需严谨准确，不宜过度发散，保障生成内容符合行业规范 |
| `AIPROXY_API_ENDPOINT` | 部署的代理接口地址 | 适配国内模型访问的网络环境，避免直接调用出现超时或访问受限 |
| `AIPROXY_API_TOKEN` | 分配的专属密钥 | 保障模型接口调用的安全性，防止未授权访问 |

## 容易做错的三处
- 现象：知识库搜索耗时超过40秒，返回结果条数不足。原因：未合理设置`maxContext`导致上下文加载耗时过长，或未匹配行业数据的嵌入参数导致召回效率低下。
- 现象：网页调试与飞书接入的回答内容不一致。原因：不同部署环境下的`temperature`或`maxTokens`配置未统一，或接入时未同步数据源的最新嵌入结果。
- 现象：调用模型接口返回配置错误提示。原因：`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`填写错误，或未在系统中正确关联目标模型渠道。

## 怎么确认配好了
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的调用返回状态码为200。
- 导入一段矿山采选的长流程文档，测试上下文加载，确认文档内容未被截断。
- 调整`temperature`参数后，观察生成的文书严谨性变化，符合预期的控制效果。
- 对比网页调试与正式接入的配置参数，确认所有设置项完全一致。
