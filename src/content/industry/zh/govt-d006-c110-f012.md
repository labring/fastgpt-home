# 矿山采选的文书与材料起草：部署与升级

## 这个品类的数据长什么样
矿山采选的文书与材料主要来源于内部业务系统、现场作业记录、上级合规文件三类。日常随项目进度更新，生产报表类文档每周微调，季度安全检查报告每月更新，年度储量报告每年更新。文档包含结构化报表（如选矿回收率表、生产调度单）、长文本作业指导书、扫描存档的纸质验收单三类结构，字段包含品位、处理量、作业时间等，对应单位为%、吨/日、年-月-日等专业标识。

## 这些特征在「部署与升级」这一环带来什么约束
混合结构的文档要求部署时配置差异化的解析规则，适配结构化报表与非长文本的提取需求；大量扫描件PDF的存在，要求升级时兼容多格式文档解析插件的更新。高频更新的业务文档，需要部署时配置增量同步的触发机制，避免全量重复导入。专业字段与单位的存在，要求知识库配置时保留原始字段标识，防止解析后数据失真。合规类文书的索引稳定性，要求升级时不破坏原有已构建的向量库。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `REDIS_URL` | `redis://:自定义密码@内网redis主机:6379/0` | 缓存解析后的矿山采选文书片段，降低重复解析的资源开销 |
| `STORAGE_S3_ENDPOINT` | `内网对象存储内网地址:9000` | 存储矿山采选的扫描件、PDF原始文档，适配内网部署的安全要求 |
| `DB_MAX_LINK` | `20–30` | 应对批量导入月度选矿报表时的数据库连接峰值，避免连接耗尽 |
| `MONGODB_URI` | `mongodb://用户名:自定义密码@内网mongo主机:27017/fastgpt?authSource=admin` | 存储结构化选矿报表的字段数据，支持按品位、处理量等维度的精准查询 |
| `ROOT_KEY` | `32位以上随机字符串` | 配置超级管理员权限，用于批量管理矿山采选场景下的知识库访问权限 |

## 容易做错的三处
- 现象：启动容器后调用模型接口返回403状态码，提示令牌无权使用模型。原因：未在FastGPT配置中关联正确的模型权限令牌，且未将矿山采选专属的合规类模型加入令牌的可用范围。
- 现象：导入的选矿回收率报表解析后，品位、处理量等字段的专业单位丢失。原因：未配置针对结构化报表的字段提取规则，默认解析规则未保留原始字段的单位标识。
- 现象：批量导入年度储量报告时出现数据库连接超时错误。原因：未调整`DB_MAX_LINK`参数适配大文档批量导入的连接需求，导致连接池耗尽。

## 怎么确认配好了
- 登录FastGPT后台，进入存储配置页面，确认对象存储地址与`STORAGE_S3_ENDPOINT`的配置值一致。
- 上传一份选矿流程卡PDF，执行文档解析测试，确认结构化字段被正确提取且保留了%、吨/日等专业单位。
- 生成一个测试令牌，调用模型接口生成采矿作业指导书，确认返回结果正常无403报错。
- 批量导入10份月度生产报表，查看数据库监控面板，确认连接数未超过`DB_MAX_LINK`的配置阈值。
