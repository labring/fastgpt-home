# 粮食储备的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
粮食储备的文书数据主要来自中央及地方储备库的入库出库台账、轮换计划文件、粮情安全检查报告、月度库存统计报表等。日常入库出库的台账数据实时更新，月度、季度的库存报表与年度轮换方案按固定周期更新。文档结构分为两类：结构化台账包含库点名称、粮食品种、存储数量、质检指标、存储位置等固定字段，单位为吨、公斤、平方米等；长文档如轮换方案则为段落式文本，篇幅跨度从数页到数十页不等。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化台账的固定字段与明确单位，要求向量提取时需保留字段标识与单位信息，避免不同粮食品种的库存数据语义混淆；长文档的篇幅跨度大，要求索引分块需适配不同长度区间，兼顾语义完整性与模型处理效率。实时更新的入库数据要求索引支持增量同步，避免全量重建占用过多计算资源；多来源文档格式不统一，要求预处理流程需统一标准化，确保输入向量模型的内容格式一致。此外，储备领域专业术语如“储备粮轮换”“粮情检测”的精准匹配，要求向量模型需适配农业领域的语义特征。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配粮食储备文书的台账条目与长文档段落的语义完整性，避免块内语义断裂 |
| 重叠长度 | 100–200 字符 | 覆盖分块边界的关键信息，比如库点名称、粮食品种这类跨块的核心字段 |
| 相似度阈值 | 0.72–0.85 | 匹配储备文书中专业术语的语义相似度，过滤场景不符的召回内容 |
| 单次搜索上限 | 前 8 条 | 适配单份文书起草所需的参考数据规模，避免过多冗余信息干扰生成 |
| `maxToken` | 8000 token | 匹配FastGPT v4.17.0的上下文窗口上限，承载多份参考文档的向量内容 |
| 问题优化 | 开启 | 针对储备文书的专业术语优化检索词，提升召回精准度 |

## 容易做错的三处
- 现象：索引任务持续超时，界面显示进度停滞超过30分钟。原因：未针对粮食储备的长文档轮换方案调整分块参数，单块长度超出模型处理上限，导致分块处理耗时过长。
- 现象：向量检索结果无法匹配粮食储备的专业术语，比如将“中央储备粮”误召回为“地方储备粮”的相关数据。原因：未使用适配农业领域的向量模型，或未配置自定义词表扩展专业术语的向量映射。
- 现象：检索返回结果中出现字段为空或单位不匹配的条目，比如“1000”未标注为吨或公斤。原因：未在预处理阶段保留结构化字段的标识与单位信息，导致向量模型无法区分不同品类的库存数据。

## 怎么确认配好了
- 查看索引预处理日志，确认分块后的文档块长度集中在800–1200字符区间，无明显过长或过短的块。
- 执行一次测试检索，输入“2024年储备粮轮换计划”，确认召回结果均为同类型文档，无跨品类的无关数据。
- 检查向量模型配置项，确认已启用`maxToken`为8000 token的设置，匹配当前上下文窗口要求。
- 查看预处理后的文档字段，确认所有结构化字段的标识与单位均被保留，未被遗漏或错误修改。
