# 粮食储备的文书与材料起草：模型接入与配置

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
数据主要来自粮库日常运营产生的出入库登记、轮换作业记录、安全储粮检测表单、政策性收储审批文件。更新节奏为单次作业完成后实时更新，月度盘点后更新全仓库存汇总数据。文档多为结构化表单与正式公文，固定字段包含粮食品类、存储数量、仓房编号、检测项目数值，单位多为吨、公斤、立方米，无百分比类统计字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
结构化表单与固定字段的特征，要求模型生成的文书需严格匹配预设字段格式，避免生成无对应字段的内容，需在配置中限定输出结构。实时更新的库存数据，要求模型调用知识库时获取最新版本的内容，需配置上下文的实时同步规则。多类型文档（表单与公文）的混合输入，要求模型兼容不同格式的内容解析，需调整模型的文档拆分与召回逻辑。统一单位的要求，需要模型在生成材料时严格使用指定的吨、公斤等单位，需在配置中加入单位校验规则。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 粮食储备文书常包含多份历史台账与检测报告，需要足够的上下文来关联跨文档的库存数据 |
| `maxTokens` | 2000–3000 字符 | 单份文书起草的输出长度需匹配粮库内部文档的常规篇幅，避免过长或过短 |
| `quoteMaxToken` | 1500 token | 需召回足够的历史库存数据作为参考，但不能占用过多模型输出额度 |
| `temperature` | 0.3–0.5 | 文书起草需保持严谨性，避免生成过于发散的内容 |
| `AIPROXY_API_ENDPOINT` | 填写粮储系统专属的API接入地址 | 需通过专属通道调用合规的模型服务，确保数据安全 |
| `AIPROXY_API_TOKEN` | 使用粮储系统分配的专属密钥 | 保障接入权限的安全性，避免未授权访问 |

## 容易做错的三处
- 调用模型测试时出现`Api response error`报错，提示接口路径异常。原因是未正确配置`AIPROXY_API_ENDPOINT`参数，使用了非官方的接口地址。
- 生成的文书中混用了非指定单位，例如将吨写为升。原因是未在配置中限定单位校验规则，模型未匹配粮储系统的单位要求。
- 开启模型思考输出开关后，生成的文书中包含`<think>`标签内容。原因是未正确配置模型的输出格式参数，未关闭模型的内部思考过程输出。

## 怎么确认配好了
- 调用FastGPT内置的模型测试接口，检查返回的响应状态码为200，确认接口连通性正常。
- 输入一份粮库检测表单的结构化内容，查看模型生成的文书是否包含预设的固定字段，确认格式匹配规则生效。
- 调用知识库召回功能，查看返回的内容是否为最新的库存数据，确认上下文同步配置生效。
- 生成一份模拟的轮换计划文书，检查输出内容中是否使用了指定的单位，确认单位校验规则生效。
