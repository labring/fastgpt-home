# 粮食储备的文书与材料起草：知识库检索与召回

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
粮食储备的文书与材料起草相关数据主要来源于粮库日常运营的出入库台账、轮换计划文件、质量检验报告、库存统计报表。数据更新分为实时与周期两类，日常出入库数据随业务发生实时更新，月度库存报表、季度轮换计划则按固定周期同步。文档结构多带有固定表头，包含粮食品类、入库时间、存储数量、质检等级、仓位编号等字段，单位多为吨、千克、批次号，文档格式涵盖Word公文、Excel表格、PDF检验报告三类。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化的台账与非结构化的公文混合存在，要求检索系统同时支持关键词精准匹配与语义向量检索，避免仅单一检索方式遗漏对应数据。实时更新的出入库数据需要支持增量同步，避免全量刷新占用过多资源。固定的字段结构要求分块时保留表头信息，防止拆分后语义断裂导致检索偏差。专属的行业术语如“轮换计划”“陈化粮处理”需要专属的语义匹配规则，避免通用检索混入无关内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.72–0.80 | 粮食储备数据多为结构化字段与专业术语，阈值过低会混入无关库存数据，过高会遗漏匹配的质检报告与轮换计划 |
| `limit` | 前12条 | 单批次文书起草需要覆盖轮换计划、库存数据、质检信息等多类内容，12条可兼顾数据完整性与检索效率 |
| `searchMode` | hybrid | 同时支持向量检索与关键词匹配，适配结构化台账的精准字段匹配与非结构化公文的语义检索需求 |
| `usingReRank` | 开启 | 粮食储备专属术语较多，重排可过滤低相关的通用库存数据，提升召回结果的针对性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展轮换标准、质检等级等行业术语，避免因专业术语表述差异导致召回失败 |
| `collectionIds` | 按业务绑定的粮食储备知识库集合填写 | 限定检索范围仅为指定的粮库数据，避免混入其他品类的知识库内容 |

## 容易做错的三处
- 现象：调用检索接口后未返回预期的collectionIds字段。原因：未在API参数中正确指定绑定的粮食储备知识库集合ID，导致接口无法关联指定的业务数据。
- 现象：上传WPS导出的CSV库存台账后，知识库解析出现乱码。原因：CSV文件保存时未选择UTF-8编码格式，导致知识库解析时字符集不匹配，出现乱码。
- 现象：检索结果条数远低于设置的`limit`值。原因：`similarity`阈值设置过高，过滤了大量符合语义的粮食储备相关文档，导致召回数据不足。

## 怎么确认配好了
- 上传一份测试用的粮食储备CSV台账与PDF质检报告，检查知识库解析后是否保留原有的粮食品类、入库时间等字段结构。
- 调用检索接口，传入指定的`collectionIds`参数，查看返回结果中是否包含对应的文件集合ID字段。
- 调整`similarity`阈值，对比不同阈值下的召回结果数量，确认阈值设置符合业务需求。
- 开启`usingReRank`后，检查重排后的结果是否优先展示与粮食储备文书起草相关的内容。
