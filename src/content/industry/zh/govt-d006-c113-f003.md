# 船舶制造的文书与材料起草：多轮对话与提示词
本文基于 FastGPT v4.17.0 版本编写。

## 这个品类的数据长什么样
船舶制造的文书与材料数据主要来源于船舶设计图纸、分段建造工艺卡、船级社规范文档、生产排程表、分段检验报告等。数据更新节奏随建造阶段调整，设计阶段每周更新一次核心参数，如船型、主尺度等；分段建造阶段每日更新生产进度、焊接检验记录等。文档结构包含固定字段：船型编号、船长（米）、吃水深度（米）、钢板厚度（毫米）、检验批次号、工艺工序编号等，部分长文档如总装工艺卡单段内容可达数千字符，且需严格遵循专业船级社的格式要求，不得随意调整字段顺序与单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
船舶制造文书的分散数据源要求多轮对话需逐步对齐不同文档的专业字段，避免出现船型参数与工艺要求不匹配的问题。高频更新的生产数据要求对话过程中可动态拉取最新内容，无法依赖静态知识库缓存，需确保每次对话都能调用最新的生产排程与检验记录。专业单位的严格要求意味着提示词需明确锁定行业标准单位，防止输出混用米与毫米、吨与千克等不规范表述。长文档的存在则要求多轮对话需限制`messages`数组的累计长度，避免超出模型处理上限导致关键参数被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 匹配船舶制造文书单段长度与`messages`数组的累计内容，避免截断专业参数 |
| 单次召回上限 | 前6条 | 适配分散的工艺、规范、图纸数据的召回量，避免冗余信息干扰对话逻辑 |
| 变量绑定开关 | 开启 | 用于绑定船型编号、分段编号等动态字段，通过`variables`参数确保多轮对话的参数一致性 |
| 问题优化 | 按实测标定 | 适配船舶制造的专业术语，优化对话上下文的对齐与理解效果 |
| 上下文缓存时长 | 3600 秒 | 匹配船舶建造阶段的单日作业周期，避免缓存过期导致连续对话中断 |

## 容易做错的三处
- 现象：对话输出内容携带大量#、*等格式符号，无法在外部渠道正常展示。原因：未关闭对话输出的原生Markdown格式开关，导致文档标注符号被直接返回。
- 现象：调用对话接口时未返回关联知识库的标识字段。原因：未在配置中开启知识库引用日志的返回选项，未正确绑定`variables`参数关联对应知识库的元数据。
- 现象：知识库中上传的图片URL无法在对话中正常输出。原因：未将图片URL转换为符合平台要求的绝对路径格式，且未在提示词中明确要求输出可访问的图片链接。

## 怎么确认配好了
- 发起包含船型参数、工艺要求的多轮对话，检查输出内容是否使用统一的工程单位。
- 调用对话接口，查看返回结果中是否包含关联知识库的相关标识字段。
- 上传带图片URL的知识库文档，发起包含图片描述的对话，检查是否能正确返回可访问的图片链接。
- 测试携带`chatId`的连续对话，检查上下文是否能正确保留之前的船型参数与工艺要求。
