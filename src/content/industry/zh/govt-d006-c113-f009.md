# 船舶制造的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
船舶制造的文书与材料起草相关数据，主要来源于船舶设计总图、分段建造工艺卡、船级社规范文档、造船合同附件、分段报验单等。数据更新节奏匹配项目建造节点，如分段报验节点、下水节点、试航节点等。单份文档多为长文本，包含船型、主机型号、焊缝编号、报验批次等专业字段，单位涉及毫米、吨、节等船舶行业专用单位，部分文档包含结构化表格与图纸标注。

## 这些特征在「模型接入与配置」这一环带来什么约束
船舶制造文书的长文本、专业术语密集特征，要求模型接入时需适配更长的上下文窗口，避免截断核心专业内容。按项目节点更新的数据特征，要求知识库同步频率需与项目节奏匹配，避免调用过时的规范或工艺数据。结构化字段与专用单位的存在，要求模型召回的文本需精准匹配字段要求，同时需限制召回文本的总长度，防止超出模型处理上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配船舶制造长文档的上下文需求，避免截断专业内容 |
| `maxTokens` | 2000–3000 token | 匹配单份造船文书的输出长度，确保覆盖完整报验说明 |
| `quoteMaxToken` | 1500 字符 | 限制召回的知识库文本总长度，避免超出模型上下文上限 |
| `temperature` | 0.3–0.5 | 保持专业术语准确性，降低无关发散 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地化或云端模型调用的地址要求 |
| `toolChoice` | auto | 允许模型按需调用工具处理结构化数据，比如提取焊缝参数 |

## 容易做错的三处
- 现象：可用模型列表为空，无法开启对话。原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致平台无法拉取本地或云端模型元数据。
- 现象：流式返回的`detail`字段解析后无内容。原因：未在调用参数中开启`detail`返回开关，或解析逻辑未匹配FastGPT的流式返回格式。
- 现象：调用本地化模型时超时无响应。原因：未调整`maxContext`适配长文档召回，导致模型处理负载过高超出超时阈值。

## 怎么确认配好了
- 检查FastGPT v4.17.0的模型管理界面，确认目标模型已加载到可用模型列表中。
- 发起测试请求，验证流式返回包含`detail`字段的完整内容，确认解析逻辑适配返回格式。
- 上传一份典型的分段报验单，触发模型起草报验说明，检查输出是否包含准确的焊缝编号、报验批次等专业字段。
- 模拟处理长文本的造船工艺文档，确认`maxContext`配置未触发截断报错，模型响应符合预期。
