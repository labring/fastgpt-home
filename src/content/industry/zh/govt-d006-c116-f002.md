# 通信工程建设的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
通信工程建设的文书与材料主要来源于项目立项审批文件、施工组织设计方案、线路勘测记录、监理周报、竣工验收报告等。更新节奏随项目阶段推进，立项阶段更新立项文件，施工阶段每周更新进度日志与材料领用记录，验收阶段生成全套验收文档。文档结构包含项目编号、标段信息、施工范围、设备参数、工期要求、验收标准等固定字段，单位涉及公里、端口数、台套、工期天数等工程专用单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
通信工程文书的结构化字段与专用单位，要求索引过程需保留字段元数据，避免匹配时混淆不同标段的参数。阶段性更新的文档结构，要求索引支持增量更新，避免全量扫描重复处理历史文档。文档长度差异较大，短则数百字符的勘测记录，长则数万字符的施工组织设计，要求分块规则可适配不同长度的文本。专用字段的唯一性，要求索引时优先匹配项目编号、标段等标识字段，提升匹配精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 通信工程文书多包含结构化字段与长段落施工描述，该区间可保留上下文完整性 |
| 重叠长度 | 100–150 字符 | 避免分块后关键施工步骤、项目编号被截断 |
| `defaultToken` | 4096 | 适配多数通信工程文书的单块token承载需求 |
| `maxToken` | 8192 | 处理超长的验收报告或监理日志合集 |
| 相似度阈值 | 0.72–0.78 | 区分相似标段的施工方案与通用工程模板 |
| 单次搜索上限 | 前6条 | 通信工程文书的相关匹配通常集中在同标段或同施工类型的文档 |

## 容易做错的三处
- 现象：界面持续显示“索引中”状态超过30分钟，无进度更新。原因：未启用增量索引模式，全量扫描了项目周期内的所有通信工程文档，数据量过大导致耗时过长。
- 现象：搜索结果为空，或返回与查询无关的非通信工程类文档。原因：分块配置时删除了文档中的项目编号、施工范围等专属字段，导致向量无法匹配到精准内容。
- 现象：接入本地m3e模型后索引失败，控制台返回维度不匹配报错。原因：未将模型生成的向量维度与索引库的存储维度保持一致，导致嵌入向量无法存入索引库。

## 怎么确认配好了
- 上传一份典型的通信工程施工组织设计文档，查看FastGPT v4.17.0的索引进度条在5分钟内完成初始化。
- 输入包含项目编号或标段名称的查询语句，查看返回结果包含匹配的结构化字段内容。
- 调整相似度阈值，观察搜索结果的匹配条数随阈值变化符合预期。
- 查看向量模型的嵌入日志，确认生成的向量维度与索引库配置的维度一致。
