# 通信工程建设的文书与材料起草：模型接入与配置
本文适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
通信工程建设的文书与材料主要来源于项目立项审批文件、施工图纸交底记录、现场监理日志、阶段性进度报表及竣工验收报告。数据更新随项目推进节奏调整，立项阶段生成初始文档，施工阶段按周或月更新进度数据，验收阶段生成最终归档材料。单份文档通常包含项目编号、建设点位、工程量清单、材料型号、传输带宽要求等字段，字段单位涉及米、兆赫兹、工时、立方米等工程专用单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
通信工程建设的文书包含大量专业术语与结构化工程字段，单份文档长度普遍较长，要求模型接入配置需适配长上下文处理能力。数据随项目节点高频更新，调用超时设置需匹配文档解析与内容生成的实际耗时。工程专用单位与参数的准确性要求较高，需限制模型的随机生成幅度，避免出现单位或参数错误。部分文书需关联项目历史数据，配置需支持上下文关联调用，确保生成内容与项目实际情况一致。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配通信工程文书的长上下文需求，避免截断项目编号、工程量清单等关键参数 |
| `maxTokens` | 2000–3000 token | 匹配工程文书起草的常规输出长度，覆盖工期计划、材料清单等核心内容生成 |
| `temperature` | 0.2–0.4 | 降低随机生成幅度，保障工程参数、单位与项目实际情况的一致性 |
| `AIPROXY_API_ENDPOINT` | 部署模型的专属API地址 | 指向已适配工程专业场景的模型服务地址，确保调用链路正常 |
| `AIPROXY_API_TOKEN` | 从模型服务商获取的专属认证密钥 | 完成身份验证，保障API调用的安全性与权限匹配 |
| `toolChoice` | auto | 支持自动调用工具获取实时项目数据，适配需关联历史文档的起草场景 |

## 容易做错的三处
- 现象：直接调用模型API响应速度较快，但在FastGPT中配置后调用文书起草功能出现超时或响应延迟明显。原因：`maxContext`设置过高，导致FastGPT在加载上下文时消耗过多资源，拉长整体调用耗时。
- 现象：添加本地部署的模型后，测试接口返回报错或状态码异常。原因：未正确配置`AIPROXY_API_ENDPOINT`指向本地模型服务地址，或`AIPROXY_API_TOKEN`未匹配模型的认证要求。
- 现象：Docker部署的FastGPT无法正常集成模型服务，或生成的文书无法关联项目历史数据。原因：未在docker-compose配置中正确配置网络互通规则，或未挂载模型数据目录导致服务无法正常启动。

## 怎么确认配好了
- 调用FastGPT内置的模型测试接口，输入一段包含通信工程专业术语的文本，检查返回内容是否包含正确的工程参数与单位。
- 查看FastGPT的系统日志，确认模型调用的`maxContext`与`maxTokens`参数未被截断，且调用耗时符合预期。
- 使用curl命令模拟FastGPT的模型调用流程，输入通信工程文书的上下文文本，对比直接调用模型API的返回结果是否一致。
- 针对长文档起草场景，输入包含多个项目字段的文本，检查生成的文书是否完整关联了上下文信息。
