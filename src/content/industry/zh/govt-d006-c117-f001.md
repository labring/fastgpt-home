# 通信铁塔与基础设施的文书与材料起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
数据主要来自运维管理系统、资产台账平台与现场巡检终端。更新节奏分两类：资产基础信息每季度同步，巡检与隐患数据每日更新。文档结构包含铁塔唯一标识、安装位置、塔高、运维周期、隐患等级字段，单位包含米、摄氏度、百分比，部分字段关联第三方测绘的经纬度数据。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
资产基础信息与巡检数据的更新节奏差异，要求HTTP请求配置区分定时触发周期，基础信息同步使用6小时级触发，巡检数据使用15分钟级触发。字段关联第三方测绘的经纬度数据，要求请求携带`variables`中的铁塔唯一标识作为查询参数，避免跨数据源匹配错误。字段包含特定单位，要求接口返回数据需保留原始单位字段，避免格式转换偏差导致的文书内容错误。数据敏感性要求请求需配置`Authorization`鉴权，防止未授权访问涉密的运维数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 固定Bearer Token格式，值为平台分配的通信运维系统鉴权密钥 | 匹配第三方运维系统的鉴权规则，确保接口调用合法性 |
| `variables` | 携带`铁塔ID`、`巡检周期`参数，铁塔ID取值区间为100000-999999，巡检周期设为`15 分钟` | 精准定位单座铁塔的运维数据，匹配数据源的查询逻辑 |
| `responseData` | 仅保留`铁塔ID`、`隐患等级`、`维护记录`字段 | 过滤冗余数据，降低文书起草时的信息处理量 |
| 请求超时时间 | 600 秒 | 适配第三方系统的批量数据返回延迟，避免请求中断 |
| 重试次数 | 3 次 | 应对临时网络波动导致的请求失败 |
| 触发规则 | 按每日/每小时定时触发 | 匹配资产与巡检数据的更新节奏 |

## 容易做错的三处
- 现象：条件判断组件处理HTTP解析出的boolean类型参数后，参数变为空值。原因：未在HTTP组件中配置`responseData`的类型转换规则，导致布尔值被错误解析为字符串，条件判断组件无法识别非标准格式的布尔值。
- 现象：调用第三方运维接口时返回`getaddrinfo ENOTFOUND`错误，伴随406状态码。原因：请求URL中未正确拼接`variables`携带的铁塔ID参数，导致域名解析失败，同时请求头未匹配第三方系统的内容类型要求。
- 现象：上传的文件相对路径携带token参数，导致外部服务无法正常读取文件。原因：未在HTTP组件中剥离路径中的token参数，直接传递了包含鉴权信息的完整路径，超出外部服务的路径读取权限范围。

## 怎么确认配好了
- 查看FastGPT v4.17.0的HTTP组件请求日志，确认`Authorization`鉴权头已正确携带，`variables`参数已按规则传入。
- 调用测试接口，检查`responseData`返回的字段是否仅包含预设的必要字段，无冗余信息。
- 模拟定时触发请求，确认请求周期与资产、巡检数据的更新节奏匹配。
- 传入测试用的铁塔ID参数，检查第三方系统是否返回对应的数据内容。
