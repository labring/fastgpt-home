# 通信铁塔与基础设施的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据主要来自通信铁塔运维管理系统、基站巡检报告、项目立项审批文件、场地租赁协议等。基础台账类数据按月更新，巡检记录按单次巡检周期更新，文档多为结构化表格搭配非结构化说明。核心字段包含塔型、架设高度、经纬度坐标、运维等级、租赁期限、巡检频次，单位涉及米、平方米、年、次等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
结构化字段与多源更新节奏的差异，要求多轮对话需明确区分结构化参数提取与非结构化内容生成的边界。专业字段如经纬度、高度需在提示词中强制指定单位，避免生成不符合行业标准的内容。多源数据的更新周期差异，要求对话中需引导用户明确指定数据的时间范围，避免混用不同周期的台账与巡检记录。长文档内容的引入，需限制上下文窗口的有效长度，防止冗余信息干扰核心起草任务。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话上下文长度 | 800–1200 字符 | 适配本品类巡检报告与台账的单页内容长度，避免冗余信息干扰 |
| `chatId` 有效时长 | 7200 秒 | 匹配通信铁塔项目的常规协作周期，防止会话意外失效 |
| `variables` 预设字段 | 塔型、架设高度、巡检日期 | 覆盖本品类文书起草的核心必填参数，减少多轮追问 |
| `messages` 历史截断阈值 | 前 10 条对话 | 控制上下文总量，避免超出模型处理上限 |
| 导出关联配置 | 按实测标定 | 适配本品类文档的格式与内容结构，确保导出内容完整 |

## 容易做错的三处
- 现象：生成的内容无法在对话底部创建导出Word的下载链接。原因：未配置工作流的导出节点与当前会话的`variables`参数绑定，导致无法获取起草内容。
- 现象：调用接口时提示“没有权限操作此对话记录”。原因：`chatId`对应的会话未配置共享权限，或调用方未携带正确的会话标识。
- 现象：升级FastGPT v4.17.0后刷新对话页面，对话记录显示为新对话。原因：未正确绑定`chatId`与会话存储路径，导致会话关联失效。

## 怎么确认配好了
- 发起包含塔型、架设高度的多轮对话，检查生成的文书是否自动关联预设的`variables`参数。
- 手动修改`chatId`后发起新对话，确认会话记录不会与原有会话混淆。
- 触发工作流导出功能，检查生成的文档是否包含对话中确认的所有核心字段。
- 连续发送2条不同的起草需求，检查会话是否按`chatId`分别存储对话内容。
