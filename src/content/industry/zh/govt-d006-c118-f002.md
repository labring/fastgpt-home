# 金属材料加工的文书与材料起草：向量模型与索引

## 这个品类的数据长什么样
金属材料加工的相关数据主要来自生产车间的实时采集报表、来料质检报告、工艺规程文件、采购合同与成品出库单据。数据更新节奏覆盖实时、每日、月度与年度，实时数据如炉温、轧制压力每日更新的批次质检记录，年度更新的资质认证文档。文档结构多为结构化表格与长文本段落混合，字段包含炉号、批次号、硬度值、抗拉强度（单位MPa）、加工工序参数等，部分文书包含跨页的合规性说明。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时与高频更新的生产数据要求索引支持增量同步，避免全量重索引的耗时与资源占用。结构化字段与混合文档结构，要求向量分块时保留字段上下文关联，避免拆分破坏工艺参数与对应工序的绑定关系。单文档长度差异较大，短至几行的质检记录，长至数十页的合规文书，需要动态适配分块策略，防止短文本向量冗余或长文本超出`maxToken`限制。字段包含带单位的量化值，需在预处理阶段统一单位格式后再向量化，避免语义偏差影响检索精度。

## 配置怎么定
本配置方案适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配金属材料加工文档的混合结构，平衡单块文本语义完整性与向量化效率 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工序参数与炉号关联信息，避免上下文断裂 |
| `maxToken` | 8192 token | 适配长文档如年度工艺规程的向量化需求，符合通用嵌入模型的输入上限 |
| `defaultToken` | 256 token | 用于短文本如单条质检记录的向量化，避免资源浪费 |
| 相似度阈值 | 0.75–0.85 | 筛选匹配的工艺参数与合规条款，适配金属材料加工的严谨性要求 |
| 单次召回上限 | 前10条 | 控制检索返回的候选结果数量，适配批量质检数据的检索场景 |

## 容易做错的三处
- 现象：上传十万条数据的CSV文件后，向量完成后总数据量仅九万余条，缺失数千条。原因：部分行包含未转义的逗号或换行符，导致CSV解析失败，未被加载进入知识库。
- 现象：创建集合显示成功，但页面索引状态一直显示未建立，无报错提示。原因：未开启自动索引开关，或增量同步的触发条件未匹配数据更新的频率，导致索引任务未被调度。
- 现象：本地运行向量索引结果正常，打包为Docker镜像运行后，所有文本的向量得分完全一致。原因：Docker容器内未正确挂载嵌入模型的缓存目录，或环境变量未正确传递模型路径，触发了默认的占位向量生成。

## 怎么确认配好了
- 上传单条包含炉号、硬度值的短文本质检记录，检查向量化任务的日志，确认分块长度与`maxToken`设置未触发截断警告。
- 导入批量结构化CSV数据，核对导入后的数据条数与源文件一致，确认无解析遗漏。
- 启动增量索引任务，查看调度日志，确认索引任务按预设频率触发，无阻塞或失败记录。
- 对比本地与Docker容器内的向量生成结果，确认得分存在合理差异，无全量一致的异常情况。
