# 金属材料加工的文书与材料起草：多轮对话与提示词
本文基于FastGPT v4.17.0版本编写

## 这个品类的数据长什么样
金属材料加工的文书数据主要来源于企业内部工艺卡、质量检验报告、采购合同模板及对应国标、行业标准文档。数据更新节奏随生产批次调整，同时伴随国标改版同步更新。单份文档结构固定，包含材料牌号、屈服强度、抗拉强度、交货状态、批次编号等字段，单位多采用兆帕（MPa）、毫米（mm）、吨（t）等工程通用单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的文书需符合固定字段与工程单位要求，因此多轮对话需持续保留已获取的参数信息，避免重复询问。不同类型的文书（如工艺卡与检验报告）格式差异明显，提示词需明确区分场景。数据随生产批次动态更新，对话中需允许用户补充最新批次的专属参数，同时需校验参数单位与字段的一致性，防止出现数值与单位不匹配的错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 包含材料牌号、屈服强度、生产批次号3个自定义变量 | 金属材料加工文书需固定核心参数，避免生成内容与实际生产数据脱节 |
| `messages` | 保留最近10轮对话上下文 | 工艺起草过程中需跨轮次传递参数，避免重复询问已获取的字段信息 |
| `chatId` | 绑定生产批次ID | 同批次的文书需统一使用该批次的参数，确保会话内数据一致性 |
| 系统提示词 | 明确指定文书类型与必填字段，例如「生成符合GB/T 700标准的工艺卡，需包含牌号、屈服强度参数」 | 金属材料文书有强制标准与格式要求，引导生成内容符合规范 |
| 会话超时时间 | 3600 秒 | 平衡工艺起草的跨时段需求与服务器资源占用 |
| 上下文截取长度 | 8000–12000 字符 | 保留完整的工艺参数与对话逻辑，避免截断关键生产信息 |

## 容易做错的三处
- 现象：生成的工艺文书未包含指定的屈服强度数值，格式不符合预设模板。原因：系统提示词未明确引用`variables`中配置的自定义变量，导致提示词无法关联实际生产参数。
- 现象：多轮对话中反复询问相同的材料牌号信息。原因：未配置`messages`参数保留最近对话上下文，会话上下文被截断，无法记住已获取的字段信息。
- 现象：生成的检验报告与采购合同内容混淆，字段交叉错误。原因：未通过`chatId`绑定生产批次ID，不同类型的文书共用会话上下文，导致参数冲突。

## 怎么确认配好了
- 输入已知的材料牌号与屈服强度数值，检查生成的文书是否自动填入对应字段，确认`variables`配置生效。
- 发起两轮以上的对话，补充不同的工艺参数，检查后续生成的文书是否保留之前输入的信息，确认`messages`参数配置正确。
- 切换不同的文书类型（如工艺卡、检验报告），检查生成的内容是否符合对应模板，确认系统提示词配置符合需求。
- 等待3600秒后再次发起对话，检查会话是否仍保留之前的上下文，确认`chatId`绑定与超时时间配置合理。
