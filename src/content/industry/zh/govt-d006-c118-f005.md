# 金属材料加工的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
金属材料加工的核心数据来源于企业ERP系统、在线质量检测终端与生产调度平台。数据按生产批次更新，单批次数据包含炉号、金属牌号、化学成分（碳、硅、锰等元素占比）、力学性能指标（抗拉强度、屈服强度，单位MPa）、轧制温度、冷却工艺参数等字段。关联文书类数据包括生产工艺规程、质量证明书模板、交货单格式等，字段需严格匹配钢铁有色行业的标准格式要求。

## 这些特征在「工具调用与插件」这一环带来什么约束
金属材料加工的数据字段多且附带严格单位要求，工具调用时需精准匹配字段名与对应单位，避免参数混淆。数据按生产批次动态更新，插件需支持按炉号、批次号拉取最新数据，无法依赖静态缓存。工具调用需支持`functionCall`模式绑定专属字段与单位规则，文书起草需结合生产工艺参数与行业标准模板，同时需自动校验字段合规性，确保符合钢铁有色行业的文书格式规范。

## 配置怎么定
以下配置示例基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `toolChoice` | `"auto"` | 适配金属材料加工多场景的工具调用需求，自动匹配生产数据、模板生成工具 |
| `functionCall` | `"strict"` | 严格绑定金属材料加工的专属字段与单位规则，避免模型生成无关内容 |
| 数据拉取超时时间 | 60 秒 | 生产数据按批次实时更新，超时会导致拉取过期批次的生产参数 |
| 多源数据联动开关 | 开启 | 文书起草需同时调用生产数据接口与行业标准模板接口 |
| 单次工具调用返回条数 | 前 3 条 | 单批次金属材料加工数据量有限，过多返回会增加上下文处理负担 |
| 文书格式校验规则 | 按GB/T 222-2023标准配置 | 确保生成的质量证明书、工艺文件符合国家钢铁行业标准格式 |

## 容易做错的三处
- 调用工具时返回400 status code (no body)，原因是未在插件配置中正确配置请求header的认证参数，接口无法完成身份校验，未返回有效数据体。
- 生成的文书中力学性能数值与实际生产数据不符，原因是未开启`functionCall`的严格校验模式，模型未严格绑定金属材料加工的专属字段与单位规则，生成了不符合场景的内容。
- 连接带header认证的sse接口时触发报错，原因是未在插件配置中添加自定义认证header，无法通过接口的身份验证流程。

## 怎么确认配好了
- 发起一次工具调用测试，查看返回的生产数据字段是否包含炉号、牌号、力学性能等专属字段，确认数据拉取逻辑正确。
- 生成一份模拟的质量证明书，检查格式是否符合预设的行业标准，确认文书格式校验规则生效。
- 模拟输入错误的单位参数，查看工具是否触发校验拦截，确认`functionCall`的严格校验功能正常。
- 查看插件运行日志，确认多源数据联动时的接口调用顺序符合预期，确认配置的超时时间生效。
