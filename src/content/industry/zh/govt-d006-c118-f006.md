# 金属材料加工的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据多来自企业MES系统生产台账、国家金属材料相关标准文档、现场质检原始记录。生产台账随每批次加工实时生成更新，工艺标准文档每季度更新一次，质检报告随单批次加工完成同步产出。文档分为结构化表格和非结构化手册两类，结构化字段包含批次编号、加工设备编号、工艺参数范围、质检项结果、执行标准编号，单位涉及毫米、米、小时、洛氏硬度单位等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
实时生成的单批次生产数据要求溯源必须精准绑定唯一批次编号，无法仅通过模糊关键词完成溯源，否则会出现跨批次引用错误。结构化与非结构化文档混合的特征，要求溯源环节同时支持结构化字段检索与全文内容匹配，覆盖工艺标准与现场生产记录两类数据源。不同数据源更新节奏差异，要求配置中区分静态标准库与动态生产数据的索引刷新周期，避免引用过时的工艺标准或未同步的生产数据。多类单位的字段设置，要求检索时自动完成单位归一化处理，确保不同单位的参数可以正确匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配金属材料加工文档的单批次数据与标准文档的平均长度，避免截断有效溯源信息 |
| `responseData` | 结构化字段+全文内容 | 覆盖结构化生产台账与非结构化工艺手册的溯源需求 |
| `detail` | 完整来源路径+字段值 | 满足工程师核对批次编号、执行标准编号的精准溯源需求 |
| 单次检索上限 | 前5–7条结果 | 覆盖单批次加工所需的工艺标准、质检记录、设备参数三类核心数据源 |
| 单位归一化开关 | 开启 | 适配多单位字段的检索匹配，解决不同单位参数的引用混淆问题 |
| 索引刷新周期 | 静态库每季度一次，动态库每小时一次 | 匹配不同数据源的实际更新节奏，避免引用过时或未同步的数据 |

## 容易做错的三处
- 调用生成接口后，返回结果中无cite引用id字段，原因是`quoteMaxToken`配置值过小，导致溯源信息被截断，无法生成有效引用标识。
- 点击查看知识库引用详情时，界面弹出参数错误提示，原因是`responseData`配置未同时开启结构化与全文内容检索，导致部分数据源无法被正常加载。
- 在知识库搜索卡片中选择对应知识库后，变量引用无法匹配到目标批次数据，原因是未开启单位归一化开关，导致变量参数的单位与检索数据源的单位不匹配。
