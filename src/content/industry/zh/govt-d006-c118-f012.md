# 金属材料加工的文书与材料起草：部署与升级

本页面适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
金属材料加工的文书与材料文档主要来源于车间MES系统、质量检测系统、ERP生产管理系统，涵盖原材料检验单、工艺规程卡、生产领料单、成品合格证、工序流转单等类型。更新节奏按生产批次触发，每批次对应一套完整的文档集合。文档结构固定，包含材料牌号、规格尺寸、炉批号、抗拉强度、屈服强度、冲击功等字段，单位分别为无单位、mm、无单位、MPa、MPa、J。单份文档长度从数百字符到数千字符不等，部分附带扫描件或检测图像。

## 这些特征在「部署与升级」这一环带来什么约束
固定的字段与单位要求部署时需预先配置与业务系统匹配的数据库连接，避免解析错误导致的字段丢失或单位不匹配。按批次的更新节奏要求升级时需保留增量同步的触发逻辑，不能随意改为全量定时更新，否则会增加系统负载。多来源的文档数据要求部署时配置合理的数据库连接池参数，适配多车间并发的数据请求。附带扫描件的文档要求升级时需保留原有的文件存储路径规则，避免无法读取历史文档。同时，国央企场景下的域名与安全要求，部署时需配置专属的内网或公网域名，符合合规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://metal_user:secure_pass@internal-db:5432/metal_manufacture?schema=public` | 金属材料加工的业务数据多存储在PostgreSQL的专用业务库，匹配ERP与MES系统的存储格式 |
| `REDIS_URL` | `redis://:redis_pass@internal-cache:6379/1` | 缓存生产批次的临时数据与用户会话，适配按批次触发的更新节奏 |
| `DB_MAX_LINK` | `20–30` | 适配多车间并发的数据请求，避免数据库连接池耗尽 |
| `STORAGE_S3_ENDPOINT` | `http://internal-storage:9000` | 存储检验报告扫描件与工艺文档，使用内网对象存储保障国央企场景下的数据安全 |
| `FE_DOMAIN` | `https://metal-docs.enterprise-domain.com` | 绑定专属的文书起草前端域名，符合国央企的域名合规要求 |
| `ROOT_KEY` | 按实测标定 | 控制管理员权限，避免非授权修改金属材料相关的知识库与配置规则 |

## 容易做错的三处
- Docker升级后版本显示异常，现象是执行`docker pull fastgpt/fastgpt:v4.8.10`后，容器启动后显示版本为4.1.16，原因是本地缓存了旧版本镜像，未添加`--no-cache`参数强制拉取最新镜像。
- 钉钉接入时提示接收消息地址校验失败，现象是开放平台发布应用时返回校验失败提示，原因是未配置公网可访问的`FE_DOMAIN`对应的服务端口，或未开放防火墙的80/443端口规则。
- 离线环境下无法更新知识库，现象是无法拉取最新的金属材料加工文档数据，原因是未配置本地镜像缓存或离线同步脚本，依赖公网拉取业务数据与模型文件。

## 怎么确认配好了
- 执行数据库连接测试命令，验证`PG_URL`与`REDIS_URL`的连接状态，确认可以读取金属材料加工的业务表与缓存数据。
- 上传一份标准的金属材料检验报告文档，验证知识库解析后是否正确提取材料牌号、抗拉强度等固定字段。
- 查看Docker容器的启动日志，确认没有版本拉取错误的提示，验证升级后的版本符合预期。
- 配置内网测试环境，模拟公网访问校验，确认`FE_DOMAIN`对应的服务可以正常响应请求。
