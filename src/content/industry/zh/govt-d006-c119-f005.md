# 钢铁冶炼的文书与材料起草：工具调用与插件

## 这个品类的数据长什么样
钢铁冶炼的文书数据主要来源于生产现场的工艺记录、质检报告单、生产调度单、安全操作规程与合规文档。数据按生产批次或每日更新，单份文档长度从数百到数千字符不等。文档结构包含冶炼炉号、批次号、冶炼时长、各阶段温度与压力参数、成分检测值、责任人签字等字段，参数单位多为摄氏度、兆帕、百分比，部分文档附带现场监控的原始数据片段。

## 这些特征在「工具调用与插件」这一环带来什么约束
钢铁冶炼文书的专业参数与固定单位要求工具调用插件必须预设字段校验规则，避免参数单位不匹配导致的生成错误。按生产批次更新的数据特征，要求工具调用需绑定对应炉号、批次号的数据源，防止跨批次调用无效数据。文档长度跨度大的特点，要求工具调用的上下文长度配置适配长文本处理，避免截断关键工艺参数。合规类文书的调用还需限制插件输出范围，仅返回指定字段的生成内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用触发规则 | 按文书分类绑定对应数据源 | 匹配钢铁冶炼文书的专业分类特征，避免跨类型调用无效数据 |
| 上下文窗口大小 | 2000–4000 字符 | 适配钢铁冶炼文书的长度跨度，防止截断关键工艺参数 |
| `toolChoice` | 自动选择 | 适配不同冶炼文书场景的工具调用需求，无需手动指定调用类型 |
| 输出字段限制 | 按预设模板指定必填字段 | 确保生成内容仅包含文档要求的字段，符合合规与格式要求 |
| 超时阈值 | 600 秒 | 适配长文档处理与数据源查询的耗时需求，避免中途中断 |

## 容易做错的三处
- 现象：调用时返回「API Key 无效」报错。原因：误用全局通用Key，未使用绑定对应工作流的应用专属Key。
- 现象：工作流调用失败，返回状态码404。原因：未使用工作流的唯一标识作为调用路径参数，无法定位目标工作流。
- 现象：工具调用结果中附带知识库搜索的input和response字段。原因：未在工作流配置中关闭知识库输出日志，或未限制仅返回工具调用生成的内容。

## 怎么确认配好了
- 发起单批次冶炼文书的测试调用，查看返回结果是否符合预设的文书格式与字段要求。
- 查看调用日志，确认使用的Key为绑定对应工作流的应用专属Key。
- 验证工作流调用路径，确认包含正确的唯一标识参数，可正常触发工作流执行。
- 模拟不同类型的冶炼文书提交，确认工具调用触发规则能正确匹配对应数据源。
