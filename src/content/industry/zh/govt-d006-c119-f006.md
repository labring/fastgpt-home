# 钢铁冶炼的文书与材料起草：引用来源与溯源

## 这个品类的数据长什么样
钢铁冶炼的文书与材料核心数据来自现场生产台账、工艺规程文件、质检报告单、安全合规记录与设备运行日志。数据按生产批次更新，单日可生成多份不同维度文档。单份文档多包含批次编号、冶炼温度、含碳量、出钢量、设备运行参数等字段，单位涵盖吨、分钟、百分比、摄氏度等，部分长文档会拆分多章节标注工艺节点与质检结果。

## 这些特征在「引用来源与溯源」这一环带来什么约束
钢铁冶炼的批次化数据更新逻辑，要求引用溯源必须绑定具体生产批次编号，避免跨批次混淆数据。专业字段带专属单位，引用时需完整保留原始单位与参数格式，防止工艺解读偏差。单日生成的多份文档存在相似参数项，需限定召回的时间范围与批次维度，减少无关内容干扰。合规类文档的溯源需精准匹配条款编号，需在召回时关联文档的合规章节标识。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | 适配钢铁冶炼长文书的参数密度，避免截断关键工艺与质检数据 |
| `detail` | 开启 | 完整返回原始文档的批次编号、设备编号等溯源字段，满足合规与溯源要求 |
| `responseData` | 关联生产台账与质检报告知识库 | 精准召回对应批次的文档数据，避免跨批次混淆 |
| 单次召回文档上限 | 前5条 | 控制上下文长度，避免因过多相似生产数据导致输出混乱 |
| 引用内容格式 | 保留原始单位与字段名 | 匹配钢铁冶炼专业文档的格式规范，防止参数解读偏差 |

## 容易做错的三处
- 现象：生成的文书中引用字段缺失批次编号或原始单位。原因：未开启`detail`配置项，导致召回数据未携带溯源所需的核心字段。
- 现象：界面中选择知识库时，变量引用无可选值。原因：未提前将钢铁冶炼的批次编号、设备编号等字段配置为知识库的自定义变量，或变量未关联到当前召回的知识库。
- 现象：调用时抛出Cannot redefine property: toString报错。原因：在引用配置中混用了未兼容的文档格式，或`quoteMaxToken`设置超出了系统允许的最大token上限，导致参数解析异常。

## 怎么确认配好了
- 手动触发一次文书起草流程，查看生成内容中是否包含原始文档的批次编号、设备编号等溯源字段。
- 进入知识库配置页面，检查自定义变量是否已关联钢铁冶炼的生产台账与质检报告知识库。
- 查看系统日志，确认未出现Cannot redefine property: toString类的参数解析报错。
- 调整`quoteMaxToken`取值后，验证长文书的引用内容未被截断。
