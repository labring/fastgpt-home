# 钢铁冶炼的文书与材料起草：模型接入与配置

## 这个品类的数据长什么样
钢铁冶炼的文书与材料起草相关数据，主要来源于生产车间的工艺台账、质检部门的成分检测记录、销售端的供货合同模板、安全合规内审文档。数据更新节奏随生产节点推进，单炉冶炼完成后更新对应台账，每日汇总更新质检数据，月度生成生产总结文档。文档结构存在明显差异，短文档为单炉检测的单页记录，长文档为月度生产汇总的数十页材料，字段包含炉号标识、冶炼时长、出钢重量、工艺参数阈值，单位多为吨、小时等行业通用计量标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
文档包含结构化表格与专业计量字段，要求模型能准确识别字段含义与对应单位，因此需要配置视觉处理能力以解析扫描件或图片格式的工艺文档。单份文档长度跨度较大，长文档可能超出模型原生上下文限制，需要合理配置上下文与输出token上限以避免截断。数据按生产节点实时更新，需确保模型调用时加载最新的台账数据，因此需要同步配置数据更新的触发规则。部分文书为图片格式，需要支持base64编码的图片解析流程，因此需额外配置视觉模型的接入参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启，适配base64图片解析 | 钢铁冶炼文书常包含工艺流程图、质检表格扫描件，需通过视觉模型解析图片内容 |
| `maxContext` | 8000–12000 token | 月度生产总结类文档长度较长，需适配长上下文处理需求 |
| `maxTokens` | 2000–3000 字符 | 单份文书起草的输出长度适配专业文档的篇幅要求 |
| `temperature` | 0.2–0.4 | 文书需保持专业严谨，降低随机性以确保参数与字段表述准确 |
| `AIPROXY_API_ENDPOINT` | 填写部署的视觉模型接入地址 | 用于解析图片格式的冶炼工艺文档 |
| `AIPROXY_API_TOKEN` | 按FastGPT v4.17.0平台生成的专属密钥填写 | 确保模型调用的身份验证合规 |

## 容易做错的三处
- 现象：调用模型时返回“无法解析图片内容”，原因：未开启`vision`配置项或未将图片转换为正确的base64编码格式。
- 现象：本地部署的FastGPT在模型测试时提示404 no body错误，原因：`AIPROXY_API_ENDPOINT`配置错误或未填写有效`AIPROXY_API_TOKEN`。
- 现象：语音转文本时返回unmarshal_resp报错，原因：`maxTokens`设置过小导致模型输出截断，无法正常序列化返回结果。

## 怎么确认配好了
- 上传一张包含结构化表格的钢铁冶炼工艺扫描件，验证模型是否能正确提取炉号、冶炼时长等业务字段。
- 调用模型接入接口，验证返回状态正常无报错。
- 提交一份长文档测试，确认上下文加载无截断，完整加载文档内容。
- 调整生成参数后生成一份测试文书，验证输出内容符合行业文书的严谨性要求。
