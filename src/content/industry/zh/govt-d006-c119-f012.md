# 钢铁冶炼的文书与材料起草：部署与升级

## 这个品类的数据长什么样
钢铁冶炼的文书与材料数据主要来自生产现场的工艺卡、每炉次质检报告、月度合规文档、客户订单合同。数据来源覆盖冶炼全流程的执行与管理环节，更新节奏随文档类型差异明显：工艺卡随炉次实时更新，质检报告绑定生产批次同步生成，合规文档按季度或年度修订。文档结构包含标准化表头、核心参数字段、审批流程节点，字段多包含冶炼时长、批次编号、物料成分数值、作业区域编号等，文档长度差异较大，短则数百字符的现场记录，长则数十页的合规手册。

## 这些特征在「部署与升级」这一环带来什么约束
钢铁冶炼场景的多源异构数据特征，要求部署环节需配置多数据源连接，覆盖生产现场、管理系统、归档文档等不同来源的接入。实时生成的炉次质检报告与生产日报，要求升级时需避开生产高峰时段，避免中断核心数据链路。长文档合规手册的结构化特征，要求配置的解析规则适配表头与参数字段的提取逻辑，防止拆分破坏关键审批节点信息。内网部署的环境限制下，需正确配置本地服务的访问端点，同时处理升级后权限变更引发的账号异常问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配钢铁冶炼场景的文书起草与数据接入需求。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150 条` | 匹配钢铁冶炼多源数据接入的并发需求，避免连接池过载 |
| `REDIS_URL` | `内网Redis服务地址:6379` | 适配钢铁企业内网部署环境，降低缓存访问延迟 |
| `STORAGE_S3_ENDPOINT` | `企业内网对象存储端点` | 保障冶炼敏感文档存储在内网，规避外网传输风险 |
| `MONGODB_URI` | `绑定生产数据集合的MongoDB连接地址` | 适配炉次质检报告、工艺卡等文档的存储格式 |
| `FILE_TOKEN_KEY` | `按企业安全规范生成的随机字符串` | 保护上传的冶炼文档的访问权限，防止未授权访问 |
| `ROOT_KEY` | `首次部署时配置的强随机密钥` | 保障超级管理员权限的安全性，升级时不可随意修改 |

## 容易做错的三处
- 现象：调用本地MCP工具时返回连接失败，日志显示无法解析服务地址。原因：将本地服务端点错误填写为通用的`localhost:端口`，未使用钢铁企业内网的实际服务地址，导致跨节点访问被阻断。
- 现象：升级后无法登录系统，提示账号或密码校验失败。原因：升级过程中未保留原有`ROOT_KEY`配置，系统权限校验逻辑重置，原有账号的权限关联关系失效。
- 现象：检索冶炼文档时返回空结果，无任何匹配内容。原因：未正确配置`PG_URL`指向专用索引数据库，或数据库连接权限未开放给FastGPT服务。

## 怎么确认配好了
- 执行FastGPT自带的数据源连通性测试工具，验证所有配置的数据库、缓存服务的连接状态，确认无超时或权限报错。
- 上传一份典型的钢铁冶炼工艺卡文档，触发解析与索引流程，检查后台日志是否显示文档结构解析完整，无字段丢失。
- 发起一次本地MCP服务调用测试，确认服务地址配置正确，返回的测试结果与预期的文档处理逻辑匹配。
- 重启FastGPT服务后，使用原有管理员账号尝试登录，确认权限校验逻辑未因配置变更失效。
