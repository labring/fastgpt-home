# 高速公路运营的文书与材料起草：多轮对话与提示词

## 这个品类的数据长什么样
高速公路运营的文书数据主要来自日常运营台账、路政巡查日志、收费结算报表、应急处置档案及行业政策文件。数据更新节奏覆盖实时（巡查记录）、每日（收费日报）、月度（结算报表）及不定期（政策更新）。单篇文档包含文号、生成日期、责任主体、作业里程、涉及车次、金额等字段，单位涵盖公里、车次、元、小时等，部分长文档附带分段处置的现场照片与音频附件。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
高速公路运营的文书数据分散且更新节奏多样，多轮对话需按数据时效性排序调用，提示词需明确指定不同数据源的优先级规则。多字段带专属单位的特征，要求提示词强制校验生成文书的单位匹配性，避免出现混用错误。长文档附带的附件信息，需在多轮对话中按轮次逐步加载，防止单次上下文超出承载上限。实时类数据的更新要求对话上下文自动过滤过期条目，确保每一轮输出都基于最新状态。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | `8000–12000 字符` | 匹配高速公路运营文书的平均长度，避免上下文溢出 |
| `messages` 历史保留条数 | `前 20 条对话记录` | 平衡上下文完整性与响应速度，适配多轮文书起草的轮次需求 |
| `variables` 变量绑定 | 绑定当日作业里程、涉事车次等实时字段 | 确保生成文书的参数匹配当前运营数据 |
| 超时阈值 | `600 秒` | 避免长文书生成时响应中断 |
| 问题优化 | 开启，按文书类型拆分提示词 | 针对路政报告、收费函件等不同文书类型优化提问逻辑 |
| 单次生成上限 | `5000 字符` | 匹配单篇运营文书的常规篇幅，避免输出过长无法校验 |

## 容易做错的三处
- 现象：生成的文书出现单位混用，例如将作业里程的单位写为小时。原因：未在提示词中强制校验字段单位匹配规则，导致AI调用不同数据源的字段时出现偏差。
- 现象：多轮对话的上下文丢失，无法引用上一轮的生成结论。原因：未配置`messages`的历史保留规则，导致每一轮对话的上下文被重置，无法传递前置信息。
- 现象：循环执行时无法读取上一轮AI输出的完成原因字段。原因：未通过`variables`绑定上一轮的输出字段，导致后续组件无法捕获目标值。

## 怎么确认配好了
- 发起测试对话，输入“生成今日路政巡查报告”，核对输出是否包含绑定的实时作业数据。
- 连续发起3至5轮对话，检查输出是否保留前置轮次的关键信息，未出现上下文丢失。
- 尝试生成不同类型的文书，核对输出的单位是否与预设字段匹配，未出现混用。
- 查看会话的`chatId`标识，确认不同测试会话的上下文未发生混淆。
