# 高速公路运营的文书与材料起草：工作流编排

## 这个品类的数据长什么样
高速公路运营的文书数据主要来源于收费稽核系统、路政巡查台账、养护作业记录、应急处置档案。数据更新节奏分三类：收费类数据实时同步，养护类数据每日归档，应急处置类数据随事件闭环完成更新。单份文书通常包含事件编号、事发点位、涉事车辆或人员信息、处置流程、责任认定等字段，单位涉及公里、小时、车次、吨位等。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需对接多个系统节点，需配置跨数据源拉取逻辑。不同数据的更新节奏差异，要求工作流支持定时触发与事件触发两种启动方式。文书字段包含专用单位，工作流的`variables`需预设对应字段的格式校验规则，避免单位混用。单份文书内容体量跨度大，从巡查记录的短文本到应急报告的长文档，需配置分块与上下文长度适配规则。

## 配置怎么定
FastGPT v4.17.0 版本下的配置建议如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按事件触发+定时触发双模式 | 适配实时应急数据与每日养护数据的更新节奏 |
| 变量预设 | 预设事件编号、事发点位、处置时长等字段 | 匹配高速公路运营文书的固定字段结构 |
| 单次召回上限 | 前10条 | 匹配单份文书的关联数据量范围 |
| 上下文长度 | 8000–12000 token | 适配长文档的应急报告与月度总结类文书 |
| 问题优化 | 开启 | 优化针对路政、收费场景的提问准确性 |
| 超时设置 | 600秒 | 适配跨系统拉取数据的响应时长 |

## 容易做错的三处
- 导入其他工作流导出的配置后，工作流输出符合预期但中间结果字段缺失或格式错误。原因是未校验导入配置的字段与当前工作流预设的`variables`是否匹配，导致参数传递失效。
- 工作流配置完成后，在聊天窗口无法触发调用。原因是未将工作流绑定至对应应用的触发节点，或未配置正确的入口规则。
- 开启知识库问题优化后，无法在局部节点关闭该功能。原因是将全局插件设置与局部节点配置混淆，未在对应节点单独调整优化开关。

## 怎么确认配好了
- 手动触发工作流，查看中间节点的变量输出面板，确认所有预设字段均有对应值。
- 调用工作流HTTP接口，检查返回结果的字段结构与预设的`variables`一致。
- 测试不同触发场景，包括定时触发与事件触发，确认工作流均能正常启动。
- 调整局部节点的问题优化开关，验证开关状态对输出内容的影响符合预期。
