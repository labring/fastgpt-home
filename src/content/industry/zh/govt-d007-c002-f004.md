# “高效办成一件事”联办的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
这个品类的数据主要来自国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库及各部门审批系统。日常处理的文档包括联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见及办结回执，字段覆盖事项编号、材料清单、流转状态、部门审批意见、办结标识等，单位多为字符数、状态码、流程节点ID等。数据更新频率为每日，随联办事项调整、部门审批进度同步更新。

## 这些特征在「工作流编排」这一环带来什么约束
多来源的数据要求工作流需支持跨部门系统的节点调用，需配置不同节点的权限与路由规则。每日更新的数据需要定时同步节点，确保工作流使用的是最新的联办事项与材料清单。复杂的文档结构与多样的字段要求工作流中`variables`需适配不同事项的字段差异，避免硬编码固定字段。跨部门并联办理的特性要求工作流需支持分支流转，按`nodeId`匹配各部门审批节点的状态，同时需配置异常处理分支应对部门接口调用失败的情况。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按联办事项清单预定义字段初始化，支持动态赋值 | 联办事项的材料字段随事项类型变化，需适配不同场景的字段需求 |
| HTTP请求超时时间 | `600 秒` | 跨部门审批接口响应延迟较高，避免因超时中断流程 |
| 节点重试次数 | `3 次` | 应对跨部门网络波动或临时接口故障 |
| 分支触发条件 | 按`nodeId`匹配部门审批节点状态 | 精准控制各部门审批完成后的流转逻辑 |
| 变量缓存有效期 | `24 小时` | 匹配数据每日更新的频率，避免使用过期参数 |
| 单份材料解析字符上限 | `800–1200 字符` | 适配一次性告知单的标准内容长度，避免解析溢出 |

## 容易做错的三处
- HTTP节点调用花生壳地址时返回getaddrinfo ENOTFOUND错误，原因是花生壳地址未在FastGPT网络白名单中配置，或内网穿透节点未正确映射端口。
- 工作流中`variables`字段值固定，未随部门审批进度动态更新，原因是未配置变量更新触发条件，仅在初始化时赋值为固定内容。
- 高级编排工具调用节点未触发后续工具执行，原因是所选模型未支持函数调用能力，无法解析工具调用指令。

## 怎么确认配好了
- 导入联办事项清单，检查`variables`是否自动加载对应事项的材料字段与参数。
- 模拟部门审批回调事件，验证工作流是否按`nodeId`正确流转至下一节点。
- 触发HTTP请求测试，确认跨部门接口调用无超时或解析错误。
- 配置变量更新触发规则后，手动触发部门回调，验证`variables`中的流转状态字段是否同步更新。
