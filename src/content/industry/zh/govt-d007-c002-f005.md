# “高效办成一件事”联办的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
本文基于FastGPT v4.17.0版本编写。本品类涉及的数据主要来自国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库及各部门审批系统，更新频率为每日。日常流转的文档包含联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见、办结回执等，各文档对应不同联办环节的字段要求，无统一固定格式，需适配跨部门的字段映射需求。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源覆盖多部门系统且每日更新，工具调用需支持动态拉取最新的联办事项清单与审批状态，避免使用过期数据。文档格式多样且字段不统一，需通过插件完成跨部门数据的格式转换与字段匹配，否则会导致材料复用失败。联办流程的核心耗时环节为跨部门事项拆解与状态跟踪，工具调用需自动匹配前置后置关系，减少人工干预。跨部门接口的不稳定性可能引发调用失败，需配置重试机制与失败告警，防止联办事项卡住。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 自动（auto） | 允许模型根据联办事项的具体需求自主选择调用工具，适配多步骤动态办理场景 |
| `functionCall` | 限定联办工具集 | 限制模型仅调用预设的联办相关工具，避免无关工具调用干扰流程 |
| 超时设置 | 600 秒 | 适配跨部门数据拉取的平均耗时，避免因单部门接口延迟导致流程中断 |
| 错误重试次数 | 2–3 次 | 应对跨部门接口的临时波动，减少人工介入的概率 |
| 多模态工具配置 | 按实测标定 | 适配Qwen2.5-vl等多模态模型的图片分析需求，调整图片拉取的超时参数 |
| 钉钉webhook触发 | 办结回执生成后 | 实现审批状态的实时推送，符合联办流程的通知要求 |

## 容易做错的三处
- 流程无工具调用日志，仅由大模型直接处理申请：原因是未将`toolChoice`配置为自动模式，模型无法自主选择调用工具。
- 钉钉webhook未推送审批状态：原因是未配置正确的webhook地址或触发时机，导致工具调用未触发通知。
- 多模态分析返回图片下载错误：原因是未配置图片拉取的超时参数或权限不足，导致FastGPT无法获取待分析的图片文件。

## 怎么确认配好了
- 触发联办事项的模拟流程，查看FastGPT工作流日志是否包含工具调用的记录。
- 提交测试用的联办申请表，检查钉钉webhook是否收到对应的测试通知。
- 上传测试用的审批图片，查看多模态工具是否成功返回分析结果。
- 模拟跨部门接口的临时延迟，检查是否触发预设的重试机制。
