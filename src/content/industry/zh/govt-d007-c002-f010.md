# “高效办成一件事”联办的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据主要来自国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库及各部门审批系统，更新节奏为每日更新。日常涉及的文档包括联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见、办结回执等，文档结构通常包含事项跨部门关联信息、材料要求、办理流程节点、部门权责划分等字段，无统一固定单位，具体字段单位随联办事项类型调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的数据源要求检索链路支持增量同步，避免全量重建索引消耗过多资源。跨部门的文档结构差异较大，需要适配多格式、多字段的内容解析，无法依赖单一字段完成匹配。联办事项的关联逻辑隐含在文档中，召回结果需同时覆盖事项清单、材料要求和流程节点，避免检索结果碎片化。电子证照库的内容存在权限分级，检索时需匹配对应访问权限，防止越权获取数据。材料流转单和办结回执的时效性强，召回结果需优先返回最新更新的条目。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.65–0.85 | 联办事项的材料要求、流程描述相似度较高，需过滤低匹配度的无关内容 |
| `limit` | 前8–12条 | 联办审核需同时参考跨部门的多个材料要求和流程节点，足够的召回量可覆盖关联信息 |
| `searchMode` | vector + hybrid | 兼顾事项名称、材料清单的精确关键词匹配与跨部门逻辑的语义关联 |
| `usingReRank` | 开启 | 联办事项的关联逻辑复杂，重排可优先返回与审核场景强相关的条目 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可基于用户的审核问题自动扩展关联的部门权责、前置条件等查询词，覆盖隐含的联办逻辑 |
| `collectionIds` | 按联办数据集分组配置 | 需分别关联联办事项清单、材料表单、审批意见等不同类型的数据集，确保召回范围准确 |

## 容易做错的三处
-  知识库导入联办数据集后，超过预设超时阈值仍处于索引中状态。原因：联办数据包含多部门审批系统的非结构化文档，未提前完成格式标准化处理，导致索引解析耗时过长。
-  检索返回的相似度数值异常偏高（如超过1000）。原因：未配置相似度阈值过滤，或使用了未适配的嵌入模型匹配规则，导致语义向量计算偏差。
-  无法检索到电子证照库的相关内容。原因：未指定`collectionIds`来关联电子证照库的专属数据集，或未配置对应数据集的权限映射规则。

## 怎么确认配好了
-  提交一条联办事项的审核问题，查看返回结果是否包含跨部门的材料要求和流程节点。
-  检查检索结果的排序是否优先返回与当前审核场景最相关的条目。
-  验证数据集的更新状态，确认每日增量同步任务正常执行。
-  测试不同权限的账号，确认仅可检索到对应权限范围内的联办文档。
