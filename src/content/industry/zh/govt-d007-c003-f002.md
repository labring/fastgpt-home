# 不动产登记的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
本品类的日常文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书、不动产登记簿等。数据来源涵盖不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统与电子证照库，更新频率为每日。单份文档结构包含权属主体信息、不动产坐落、权利类型、测绘面积、税费缴纳记录等字段，部分电子证照为结构化格式，纸质扫描件则为非结构化文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日增量更新的业务数据要求索引支持增量同步，避免全量重建带来的服务器资源消耗。多源异构数据（结构化电子证照、非结构化纸质扫描件）要求向量模型同时适配文本与结构化字段的向量化表达，确保不同格式数据的检索一致性。不动产登记数据的权属关联性强，需保留字段间的关联关系，避免分块时割裂权利来源、限制状态等关键审核信息。单份文档篇幅差异较大，从数十字的申请摘要到数百页的测绘报告，需适配不同长度的文本分块规则，防止关键信息被截断。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置逻辑编写，以下为针对不动产登记场景的向量模型与索引配置建议：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| maxToken | 4096 token | 适配主流向量模型的输入长度上限，兼容测绘报告等长文本的向量化需求 |
| defaultToken | 256 token | 作为短文本申请材料的默认向量化长度，确保小体量数据的处理效率 |
| 分块长度 | 800–1200 字符 | 适配多数不动产登记文档的核心信息长度，避免割裂权属来源、测绘数据等关键字段 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的关联信息，防止跨块的权利限制描述被拆分 |
| 相似度阈值 | 0.75–0.85 | 匹配权属信息的语义匹配精度，过滤低关联的冗余检索结果 |
| 单次搜索上限 | 前 10 条 | 控制检索返回量，避免过多非核心数据干扰案卷审核的核验流程 |

## 容易做错的三处
- 现象：部署本地向量模型后出现404报错，无法在管理界面完成模型添加。原因：未正确配置模型调用地址，或embedding服务未开放对应端口的访问权限。
- 现象：无GPU环境下尝试部署轻量向量模型失败，无法在管理界面添加模型。原因：未开启CPU运行模式，或容器资源分配不足导致模型加载超时。
- 现象：导出知识库时无法按业务分类单独导出数据，仅能导出全知识库内容。原因：未开启按业务标签分组的索引配置，仅支持全知识库维度的备份导出。
- 现象：索引创建后检索结果出现大量无关案卷，核验效率下降。原因：未设置合理的相似度阈值，或分块长度过短导致关键语义被拆分。

## 怎么确认配好了
- 上传单份测绘成果文档，查看分块预览界面，确认核心字段未被割裂截断。
- 输入权属来源描述的检索词，核对返回结果的相似度分值是否落在预设阈值区间内。
- 手动触发一次增量同步任务，查看系统日志确认无增量数据同步失败的提示。
- 在测试环境中导入单份登记申请书，验证检索结果是否包含对应权属证明的关联信息。
