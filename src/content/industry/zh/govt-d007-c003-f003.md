# 不动产登记的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
不动产登记场景的业务数据来源包括不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统、电子证照库，更新频率为每日。日常处理的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书、登记簿等，核心字段涵盖不动产坐落位置、权属编号、权利人信息、面积数据、限制状态等，单份案卷可能包含多类文档的组合，数据结构兼具结构化表单与非结构化文本。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源数据来源要求对话系统需支持跨系统数据的实时比对，确保核验的权属信息为当日最新状态。多类文档的混合处理要求提示词需适配不同文档的格式与字段要求，避免混淆权属证明与税费凭证的内容。单案卷多文档的组合特征，要求多轮对话需跟踪用户补正材料的全流程，避免上下文丢失。权属核验的高风险属性，要求对话系统需严格匹配数据字段，减少错误召回的概率。每日更新的数据要求对话环节需支持实时拉取最新的地籍与交易数据，确保审核结果的时效性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 前8000 token | 适配多类不动产登记文档的拼接需求 |
| 单次搜索上限 | 前10条 | 覆盖多源系统关联的权属与交易数据条目 |
| 相似度阈值 | 0.75–0.85 | 区分权属类文档与无关材料的匹配精度 |
| 问题优化 | 启用，按实测标定 | 适配申报材料的口语化提问转标准查询 |
| `chatId` | 绑定不动产登记业务流水号 | 关联案卷审核的全流程对话记录 |
| `messages` | 保留最近20轮对话 | 跟踪补正材料的多轮沟通轨迹 |
| `variables` | 预设权属类型、坐落地址变量 | 自动填充业务上下文 |

## 容易做错的三处
- 现象：10M以上Word文档解析耗时超过30秒。原因：未针对不动产登记的结构化文档配置合理的分块长度，单块文本过长导致解析流程阻塞。
- 现象：对话过程中显示大量分隔符|。原因：未在提示词中明确要求隐藏中间思考过程，导致系统输出调试信息。
- 现象：多轮对话中无法关联到对应案卷的历史材料。原因：未将`chatId`绑定不动产登记业务流水号，导致会话上下文与案卷审核流程脱节。

## 怎么确认配好了
- 上传单份10M以上的Word登记材料，验证解析耗时是否符合业务预期。
- 发起包含补正材料请求的多轮对话，检查`chatId`绑定的业务流水号是否同步显示在会话记录中。
- 输入口语化的申报问题，确认系统能自动将其转换为标准的权属核验查询语句。
- 调整相似度阈值后，验证召回结果是否仅包含权属证明、测绘成果等相关文档。
