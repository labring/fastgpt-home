# 不动产登记的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
这个品类的数据来自不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统与电子证照库，更新频率为每日。日常处理的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书及不动产登记簿。数据字段涵盖不动产坐落地址、面积单位为平方米、权利类型、权利人信息、登记事由等，单份核心文档的字符量跨度较大。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的每日更新特性要求工作流节点间传递完整上下文，避免跨系统数据不一致。日常处理的文档类型多样且结构差异明显，工作流需配置适配不同输入格式的解析节点。核心文档的字符跨度较大，需合理设置上下文容纳参数，防止截断权属信息、坐落地址等关键内容。同时，核验权属来源与限制状态的高耗时环节，需要工作流支持并行节点拆分任务，缩短整体处理周期，降低登记错误风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口大小 | `8000–12000 字符` | 核心文档字符跨度较大，需覆盖多数单份文档的完整内容，避免关键信息截断 |
| `variables` | 绑定多系统同步的核心数据字段 | 需传递不动产坐落、权利人信息等跨节点共享的变量，确保上下文统一 |
| 节点重试次数 | `3 次` | 核验环节可能因系统临时波动失败，重试可降低无效中断 |
| 工具调用超时时间 | `60 秒` | 跨系统调取地籍数据、税务凭证的响应周期通常在数十秒内，超时可触发补正流程 |
| `nodeId` | 为每个跨系统节点分配唯一标识 | 便于工作流调试与上下文追踪，避免节点混淆 |
| 输入格式校验规则 | 按文档类型配置必填字段校验 | 确保登记申请书、权属证明等文档的必填项完整，减少后续补正环节 |

## 容易做错的三处
- 工具调用节点返回Invalid JSON报错，界面显示「Invalid JSON: Bad control character」，原因是调用跨系统接口时返回的原始数据包含未转义的换行符或特殊字符，未在节点配置中添加数据清洗步骤。
- 工作流中无法复制粘贴组件，拖拽组件后无法执行复制操作，或粘贴后出现节点冲突，原因是未开启工作流的批量编辑模式，或组件的`nodeId`存在重复，导致系统阻止复制操作。
- 工作流上下文未统一传递，后续核验节点出现权属信息缺失或不一致，原因是未在节点间绑定`variables`参数，导致跨系统调取的数据未同步到后续环节。

## 怎么确认配好了
- 触发一次完整工作流，使用FastGPT v4.17.0的工作流调试面板查看节点日志，确认各节点的`variables`参数同步传递了不动产核心信息。
- 模拟提交一份格式不完整的测试文档，检查输入格式校验节点是否触发拦截，确认校验规则生效。
- 调用工具节点时，查看返回结果的JSON格式是否符合预期，确认数据清洗步骤已处理特殊字符。
- 复制工作流中的单个组件，粘贴到空白工作流中，确认组件的`nodeId`自动更新且无冲突，确认复制功能正常。
