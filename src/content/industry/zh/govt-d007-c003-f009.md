# 不动产登记的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
不动产登记场景的数据来自不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统与电子证照库，每日全量同步更新。日常处理的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书与登记簿，核心字段包括权利人身份信息、不动产坐落位置、界址点坐标、权属限制状态、交易编号与证照编号等，各系统字段格式存在差异，需统一对齐后用于模型推理。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入需支持跨系统数据拉取与格式对齐，每日更新的频率要求配置需适配定时同步的调度逻辑。文档类型多样且单份材料长度较长，需确保模型上下文长度足够覆盖多份拼接后的完整内容。权属核验与数据比对的准确性要求严格，模型输出需保持一致性，避免因随机生成导致的核验偏差。同时，登记数据的敏感性要求接入配置需具备权限管控能力，防止未授权访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多份不动产登记文档拼接后的总长度，覆盖权属证明、测绘成果、税费凭证等核心材料的完整内容 |
| `maxTokens` | 4000 token | 限制单轮模型输出长度，避免生成冗余内容影响案卷审核的处理效率 |
| `temperature` | 0.1–0.3 | 降低随机生成概率，确保权属核验、数据比对的结果保持一致性 |
| `toolChoice` | auto | 自动调用工具对接多源系统数据，无需手动切换配置即可完成跨系统数据拉取 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写本地或云服务端点 | 适配跨系统数据对接的代理需求，保障多源数据同步的稳定性 |
| `AIPROXY_API_TOKEN` | 绑定专属访问密钥 | 限制接口访问权限，避免未授权调用影响不动产登记数据的安全性 |

## 容易做错的三处
- 调试预览界面显示调用的模型为默认通用模型，与配置的本地部署DeepSeek模型不符，无法生成对应推理结果。原因是未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，代理转发链路中断，平台自动 fallback 至预设默认模型。
- 上传多份登记材料后，核验结果中权属限制状态字段为空。原因是未开启`toolChoice`自动调用工具，未对接税务系统与不动产登记信息系统的数据源，无法获取比对所需的权属限制数据。
- 单轮案卷审核任务超时，系统返回连接超时提示。原因是未调整`maxContext`适配长文档拼接后的上下文长度，模型处理负载过高导致超时。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型配置页面，核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`与部署的代理服务参数完全一致。
- 上传单份不动产登记申请书，触发模型推理，检查输出内容包含权利人信息、不动产坐落位置等核心核验字段，无缺失或错误。
- 开启多源数据对接测试，调用工具拉取地籍调查数据库中的界址点坐标，验证返回结果与数据库内存储的原始数据一致。
- 调整`temperature`参数至0.2，连续三次触发同一材料的核验任务，检查三次输出的核验结果完全一致。
