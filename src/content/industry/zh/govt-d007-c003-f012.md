# 不动产登记的申报材料与案卷审核：部署与升级

## 这个品类的数据长什么样
本品类数据来自不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统及电子证照库，每日更新。日常处理的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书与登记簿，字段涵盖不动产坐落、权利类型、权利人信息、测绘面积、税费金额等，部分文档为结构化表格形式，部分为扫描件或结构化电子文件。

## 这些特征在「部署与升级」这一环带来什么约束
多系统联动的数据来源，要求部署阶段配置跨系统的权限对接与增量同步逻辑，避免全量拉取占用生产资源。混合类型的文档结构，需要适配结构化表格与非结构化文本的不同分块规则，防止跨系统字段混淆。每日更新的频率，要求升级时保留增量同步的配置项，避免因全量更新导致业务卡顿。出错后果关联登记错误与行政纠纷，部署与升级环节需强化数据校验与不可篡改的存储配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://admin:securepass@mongodb-host:27017/不动产登记?authSource=admin` | 对接不动产登记信息系统的结构化业务数据，实现案卷信息的持久化存储 |
| `REDIS_URL` | `redis://:redispass@redis-host:6379/1` | 缓存每日增量同步的元数据，降低多系统拉取的重复请求频率 |
| `STORAGE_S3_ENDPOINT` | `http://minio.egov.gov.cn:9000` | 存储扫描版权证与测绘成果文件，适配多格式非结构化文档的持久化需求 |
| 数据源同步频率 | 每日凌晨2点-4点 | 避开业务高峰时段，减少对生产系统的性能占用 |
| 分块规则 | 按文档类型适配：结构化表格逐行分段，非结构化文本按800-1200字符分段 | 匹配不动产登记文档的混合结构，避免跨字段拼接导致的审核错误 |
| 最大上下文窗口 | 前8000 token | 适配单案卷审核的完整上下文需求，避免截断关键权属信息 |

## 容易做错的三处
- 现象：结构化Excel表格导入后分块混乱，跨行拼接字段。原因：未针对不动产登记的结构化表格配置逐行分块规则，使用通用自动分块逻辑导致字段错位。
- 现象：从v4.6.7导出的工作流无法导入FastGPT v4.17.0版本，界面提示格式不兼容。原因：未使用官方兼容的跨版本导出导入流程，跨大版本升级时工作流配置的底层字段发生变更。
- 现象：源码部署后无法连接MongoDB容器，日志提示连接超时。原因：未正确配置`MONGODB_URI`的地址与端口，未在容器网络中开放MongoDB的访问权限。

## 怎么确认配好了
- 执行一次增量同步任务，核对同步的文档数量与当日业务更新量一致。
- 上传一份标准的不动产登记申请书，检查分块结果按规则拆分，无跨字段拼接情况。
- 启动工作流测试，输入模拟的案卷审核请求，确认能调用多系统数据源并返回校验结果。
- 查看Redis监控面板，确认缓存命中率稳定，无频繁全量拉取的日志记录。
