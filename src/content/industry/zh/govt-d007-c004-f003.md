# 主动公开与政策发布的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源为政府门户网站、公文系统、政府信息公开目录、政策文件库、新闻发布会材料，更新频率为每日。日常处理的文档包含政策文件、政策解读稿、公开目录、信息发布审批单、新闻通稿、网站栏目更新记录。文档字段包含政策文号、发布机构、公开属性标识、审批状态、栏目归属等，单篇文档长度跨度较大，覆盖从数百字符的栏目更新记录到数万字符的完整政策文件。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且每日更新，要求多轮对话流程需支持增量数据同步与多源文档的上下文整合，避免遗漏最新发布的政策内容。文档长度跨度较大，需适配从短条目到长文件的输入，多轮对话的上下文管理需设置合理的截断规则，防止超出模型承载上限。文档包含公开属性、审批状态等专属字段，提示词需明确指定对这些字段的校验逻辑，确保审核环节准确识别合规性要求。同时，面向社会发布的属性要求对话生成的内容需严格匹配公开规范，避免出现未审批的信息。

## 配置怎么定
以下配置项适配FastGPT v4.17.0版本

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配政策文件、短条目等不同长度的文档，平衡上下文完整性与检索效率 |
| 重叠长度 | 100–200 字符 | 避免分块后相邻文档片段的上下文断裂，确保检索结果的逻辑连贯性 |
| 单次搜索上限 | 前 5 条 | 控制返回的知识库结果数量，适配政务审核场景下的精准性要求 |
| 上下文窗口 | 按实测标定 | 适配不同模型的承载上限，防止多轮对话中超出模型处理能力 |
| 提示词模板 | 包含公开属性校验、审批状态确认、公开规范说明 | 匹配本品类的审核需求，确保生成内容符合政务公开规则 |
| 对话历史存储 | 开启 | 支持多轮对话的上下文延续，满足案卷审核的回溯需求 |

## 容易做错的三处
- 现象：调用对话接口后，数据库中未查询到`chatId`对应的对话历史记录。原因：未在请求参数中正确携带`chatId`字段，或对话历史存储配置未开启，导致会话数据未被持久化。
- 现象：在工作流中调试知识库搜索返回结果正常，但AI对话环节未引用检索到的知识库内容。原因：提示词模板未明确指定引用检索结果的规则，或`messages`参数中未正确注入检索到的文档片段。
- 现象：输入单条审核相关内容后，未触发预设的多轮连续提问流程，仅返回单轮回答。原因：未在`variables`参数中配置连续提问的触发条件，或提示词未明确要求多轮迭代的逻辑。

## 怎么确认配好了
- 发起包含政策审核、公开属性校验的测试对话，检查返回结果是否引用了知识库中的对应文档内容，验证检索与引用逻辑正常。
- 查看对话历史存储模块，确认`chatId`对应的会话数据已被正确保存，验证持久化配置生效。
- 调整测试文档的公开属性字段，检查对话生成内容是否会根据该字段调整审核提示，验证提示词模板的适配性。
- 发送多条连续的审核相关问题，确认对话上下文能够正确延续，验证多轮对话配置生效。
