# 主动公开与政策发布的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类的核心数据来自政府门户网站、公文系统、政府信息公开目录、政策文件库、新闻发布会材料，更新频率为每日。日常处理的文档包含政策文件、政策解读稿、公开目录、信息发布审批单、新闻通稿、网站栏目更新记录。数据字段涵盖文件编号、发布主体、公开属性、保密等级、发布时限、栏目归属等，不同来源的文档格式存在差异，部分文档包含审批流程节点与签字痕迹。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的特性要求配置定时增量同步任务，确保最新的政策文件与审批单及时接入知识库。多类型、多来源的文档结构要求配置兼容不同格式的解析规则，避免字段缺失或格式错误影响模型调用。严格的出错后果要求模型调用需匹配政务公开的合规要求，需限制模型输出的发散性，同时需配置敏感信息校验环节。主动公开的属性要求模型需优先判断文件的公开合规性，处理流程需遵循主动发布的时限要求。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 覆盖政策文件、审批单等长文本的上下文需求 |
| `maxTokens` | `2000–3000 token` | 适配政策解读、发布文案的常规输出长度 |
| `temperature` | `0.2–0.4` | 限制模型输出的发散性，确保公开口径稳定统一 |
| `AIPROXY_API_ENDPOINT` | `本地私有部署服务地址` | 满足政务数据的安全传输要求 |
| `AIPROXY_API_TOKEN` | `与部署环境匹配的令牌值` | 验证模型调用的合法性，防止未授权访问 |
| `toolChoice` | `auto` | 自动匹配文档类型的校验规则，适配多场景的审核需求 |

## 容易做错的三处
- 调用模型时出现unmarshal_resp报错，原因是未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，导致模型返回格式解析失败。
- 私有部署后无法接入本地ollama模型，原因是未将`AIPROXY_API_ENDPOINT`指向本地ollama服务地址，且未设置匹配的`AIPROXY_API_TOKEN`。
- 通过iframe嵌入政务门户后模型调用失败，原因是未配置跨域白名单，导致前端请求被浏览器拦截。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置值与部署环境一致，发起单次模型调用验证返回格式正常。
- 上传一条包含敏感信息的政策文件，验证模型输出的敏感信息拦截结果符合合规要求。
- 配置每日增量同步任务，查看次日增量数据是否自动同步至知识库。
- 通过iframe嵌入测试页面，验证前端调用模型时无跨域报错。
