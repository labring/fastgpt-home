# 主动公开与政策发布的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来源为政府门户网站、公文系统、政府信息公开目录、政策文件库、新闻发布会材料，更新频率为每日。日常文档包含政策文件、政策解读稿、公开目录、信息发布审批单、新闻通稿、网站栏目更新记录，数据字段涵盖文件标题、文号、发布日期、公开属性、涉密等级、审批状态、关联发布栏目等，单份文档篇幅跨度从数百字到数万字不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的数据源要求知识库同步频率匹配更新节奏，避免召回过时或未完成审批的政策内容。多类型文档的篇幅跨度差异，要求检索分块策略适配不同长度文本，避免短审批单被截断、长政策文件分块失效。公开属性、涉密等级等敏感字段，要求检索结果需关联对应审核节点数据，防止敏感信息被误召回。关联发布栏目的字段要求检索结果需匹配目标发布渠道的类目规则，确保召回内容符合发布场景的合规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 需过滤低相关的政策解读或审批单，同时保留涉密属性标注的关联内容，按实测标定区间 |
| `limit` | 前 8 条 | 适配政务公开文档的批量审核需求，避免过多结果超出案卷审核的处理上限 |
| `searchMode` | hybrid | 兼顾关键词匹配与语义召回，适配政策文件的文号、标题等结构化字段与内容文本的混合检索需求 |
| `usingReRank` | 开启 | 对召回的初步结果进行二次排序，过滤因语义歧义导致的低质量匹配内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题生成扩展查询词，覆盖政策文件的别称、简称等场景，提升召回覆盖率 |
| `collectionIds` | 绑定政务公开专属数据集 | 仅检索本品类的政策文件、审批单等专属数据，避免混入其他品类的无关内容 |

## 容易做错的三处
- 现象：检索结果中出现关联id无法匹配的文档，无法关联对应审批流程。原因：未正确配置`collectionIds`，绑定的数据集未包含关联id字段的政务公开文档。
- 现象：工作流执行时未触发知识库检索环节，直接返回通用回复。原因：未在工作流节点中正确添加知识库检索步骤，或未开启`datasetSearchUsingExtensionQuery`。
- 现象：检索返回的结果条数与配置的`limit`不符，出现过多或过少的结果。原因：未正确设置`similarity`阈值，导致过滤规则异常或召回上限未按预期生效。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理页面，查看绑定的数据集是否为政务公开专属集合，确认`collectionIds`配置正确。
- 提交一条包含政策文号的测试问题，检查检索结果是否优先返回对应政策文件，验证`searchMode`与`similarity`配置生效。
- 运行工作流测试用例，查看日志是否包含知识库检索的返回结果，确认`datasetSearchUsingExtensionQuery`与检索节点已正确添加。
- 触发一次每日同步任务，检查知识库更新日志是否匹配数据源的更新频率，验证同步配置符合要求。
