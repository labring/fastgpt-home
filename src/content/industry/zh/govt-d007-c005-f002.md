# 产权、资产与国有资本管理的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自国资监管信息系统、企业资产管理系统、产权交易所系统、评估机构报告及财务报表，涵盖产权登记表、资产评估报告、产权转让方案、进场交易公告、资产处置审批单等文档。数据更新频率为月度，单份文档包含权属编号、资产原值、评估值、交易进度等结构化字段与大段文本说明，核心围绕存量资产的登记、评估、转让与处置流程生成。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的批量文档需适配高频索引任务，需考虑分块策略适配长文本的资产评估报告与转让方案；多系统来源的数据格式差异，需统一字段映射后再进行向量化；存量资产的权属编号等结构化字段需单独处理，避免与文本内容混淆；审核环节需精准匹配历史案卷，对召回精度要求较高，需调整索引的召回规则；单份文档的字段差异可能导致分块后语义割裂，需优化分块边界的对齐逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配资产评估报告、产权转让方案等长文本的语义完整性，避免单块内容过度拆分 |
| 重叠长度 | 50–80 字符 | 保留相邻分块的语义衔接，防止跨块的关键信息如权属编号、交易条款被割裂 |
| 相似度阈值 | 按实测标定 | 需匹配审核场景下对权属、交易条件的精准匹配需求，避免误召回或漏召回 |
| 单次搜索上限 | 前 10 条 | 平衡审核效率与召回范围，覆盖同类型案卷的参考需求 |
| `maxToken` | 4096 token | 适配大段审批单与公告的上下文整合，符合主流向量模型的输入限制 |
| `defaultToken` | 按知识库单文件平均长度调整 | 统一分块的基础单位，适配月度批量更新的索引任务 |
本配置方案适配FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：使用bge-large-zh-1.5模型时，无法找到官方API，或使用其他嵌入维度不匹配的模型导致检索失败。原因：未确认目标模型与业务文档的嵌入维度匹配，或未使用兼容的向量模型接口。
- 现象：单个文件长时间处于索引中，无进度反馈。原因：单份文档长度超出分块上限，或系统未处理文档内的特殊格式如表格嵌套，导致索引阻塞。
- 现象：检索结果混合两个知识库的内容，无法按预设优先级调用指定知识库。原因：未在检索环节绑定指定知识库的索引规则，或优先级配置未关联到当前问答任务。

## 怎么确认配好了
- 上传单份典型文档如资产评估报告，查看分块预览是否符合预期的长度与重叠范围。
- 发起针对权属编号的检索，验证召回结果的相似度阈值是否符合业务审核的匹配要求。
- 配置双知识库后，指定优先检索知识库A，验证检索结果仅包含A内的相关内容。
- 上传月度批量文档，查看索引任务的完成状态，确认无长时间阻塞的文件。
