# 传染病信息报告与监测的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
本品类数据来源为中国疾病预防控制信息系统、医疗机构HIS和传染病报告系统、实验室检测系统，更新频率为每日。日常处理的文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，核心字段涵盖病例唯一标识、临床诊断信息、报告时限、订正状态、实验室检测结果等，所有数据需符合法定传染病报告管理规范要求。

## 这些特征在「工作流编排」这一环带来什么约束
本品类数据每日更新且来源分散，要求工作流需支持按日定时触发，同时适配多数据源的字段对齐校验，避免不同系统间的病例数据不一致。日常文档类型多样，需针对不同文档预设对应字段提取规则，避免遗漏病例标识、报告时限等核心审核要素。法定报告规则要求严格，工作流需内置标准化校验节点，对异常数据进行拦截，同时需支持异常案卷的人工复核环节，确保符合疾控管理要求。数据更新频率较高，工作流执行需控制整体耗时，避免延迟处理导致疫情预警延误。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发时间配置 | 按日定时触发，每日凌晨2点执行 | 匹配数据每日更新的节奏，避免延迟处理当日病例数据 |
| 超时阈值 | 600秒 | 适配多数据源拉取和多文档解析的平均耗时，防止任务中途中断 |
| 分支触发规则 | 按校验结果分支执行 | 区分正常案卷和异常案卷，分别进入自动审核和人工复核节点 |
| 全局变量赋值 | 从`variables`中读取病例ID前缀 | 统一所有节点的病例标识匹配规则，避免字段不一致 |
| 节点标识配置 | 为每个校验节点设置唯一`nodeId` | 便于日志追踪和异常节点的快速定位 |
| 并行执行上限 | 限制同时执行的文档解析节点数为前3条 | 适配服务器资源负载，避免过载导致任务失败 |

## 容易做错的三处
- 现象：工作流中AI回复生成节点与下一级分支节点同时触发执行，导致资源占用过高或结果冲突。原因：未配置分支触发的前置校验规则，未限制仅在前置节点完成后才执行后续分支。
- 现象：http请求节点执行超时，返回超时报错或任务状态异常，且无法调整超时时长。原因：未修改超时阈值配置项，默认超时时长无法适配多数据源拉取或长文档解析的耗时。
- 现象：多PDF文档上传后，无法实现逐一提取信息，出现批量处理混乱或字段遗漏。原因：未为循环节点配置正确的遍历规则，未通过`nodeId`为每个遍历子节点设置独立标识。

## 怎么确认配好了
- 手动触发一次测试任务，查看任务日志中各节点的执行顺序是否符合预设的工作流逻辑。
- 导入一份标准的传染病报告卡文档，核对节点提取的字段是否与文档内容一致。
- 修改超时阈值后，模拟长耗时任务，确认任务未出现提前中断的情况。
- 检查`variables`中存储的全局变量值，确认是否与query参数或api返回值匹配。
