# 传染病信息报告与监测的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自中国疾病预防控制信息系统、医疗机构HIS和传染病报告系统、实验室检测系统，更新频率为每日。日常处理的文档包括传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，数据字段需严格遵循法定传染病报告规则，包含病例分类、报告时限、订正标识、实验室检测结果等核心项，无额外自定义字段冗余。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的多源数据关联特性要求模型上下文需覆盖病例的全生命周期信息，每日更新的批量数据需要适配定时触发的审核流程，法定报告字段的准确性要求模型输出不能出现偏差，订正记录的回溯需求需要保留完整的上下文关联。因此模型接入环节需优先适配多源数据的上下文长度，配置定时任务的触发规则，同时保证审核结果的合规性，避免遗漏法定报告要求的关键信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖多源疾控文档的关联上下文，包含病例报告卡、订正记录及流调报告的完整信息 |
| `maxTokens` | 1800–2200 token | 满足单份案卷审核的输出长度需求，避免截断法定报告字段或审核结论 |
| `temperature` | 0.1–0.3 | 降低随机生成概率，保证审核结果的合规性与一致性，符合疾控审核的严谨要求 |
| `AIPROXY_API_ENDPOINT` | 按内网部署环境填写 | 适配疾控系统的内网访问限制，避免外部网络无法连接模型服务 |
| `AIPROXY_API_TOKEN` | 按模型服务商提供的密钥填写 | 完成模型服务的身份验证，确保接入权限正常 |
| `toolChoice` | auto | 按需调用工具核对法定传染病报告规则，提升审核准确性 |

## 容易做错的三处
- 现象：模型输出思考内容后无正文，或提示“模型流响应为空，请检查模型流输出是否正常”。原因：`maxTokens`配置值低于当前任务所需的输出长度，或`maxContext`未覆盖多源关联数据导致上下文不足。
- 现象：进入工作台编辑页面报错“未配置语言模型”。原因：未正确填写`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`参数，或代理网络无法访问目标模型服务。
- 现象：工作流的AI模型选项为空。原因：未在系统配置中开启对应模型的接入权限，或未完成模型密钥的绑定配置。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型接入配置页面，核对`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的填写内容与部署环境一致。
- 上传一份测试用的传染病报告卡与订正记录，提交审核任务，检查模型输出是否包含完整的审核结果，无截断或空响应。
- 进入工作流编辑页面，确认AI模型选项已显示可用的部署模型，可正常选择调用。
- 手动触发一次日更数据的审核任务，检查任务执行状态与输出结果符合预期。
