# 公共数据目录与开放的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
本品类的数据主要来自地方公共数据开放平台、一体化大数据平台、部门业务数据库及电子证照库。日常处理的文档包括公共数据资源目录、数据开放清单、数据项说明、脱敏规则、接口文档、更新频率说明。数据更新频率为月度，文档兼具结构化字段与非结构化文本，结构化字段涵盖数据项编码、开放范围、脱敏方式、接口地址等，非结构化文本包含接口调用说明与更新细则，字段格式随部门报送要求调整，无统一固定单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的特性要求索引需支持增量更新与定期全量刷新，避免索引数据与实际开放数据脱节。多来源、多格式的文档需兼顾结构化数据项与非结构化接口文档的嵌入适配，需统一预处理逻辑以保证向量一致性。脱敏规则与开放范围的字段要求需在嵌入环节过滤敏感信息，防止数据泄露风险。同时，需保证索引结果与目录条目一一对应，避免出现搜索结果与实际开放数据不符的情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配数据项说明与接口文档的语义完整性，避免块内语义断裂 |
| 重叠长度 | 100–150 字符 | 保留跨块上下文关联，防止数据项与接口说明的语义被分割破坏 |
| 相似度阈值 | 0.72–0.80 | 过滤低匹配度的非合规数据项，保证搜索结果与开放目录的一致性 |
| `defaultToken` | 4096 token | 适配单批次数据项说明的嵌入长度，平衡计算资源与处理效率 |
| `maxToken` | 8192 token | 支持长文本接口文档的完整嵌入，避免长文本被截断导致语义丢失 |
| 单次搜索上限 | 前 10 条 | 覆盖多部门报送的目录条目数量，满足申报审核的全量匹配需求 |

## 容易做错的三处
- 向量搜索结果中包含未脱敏的敏感字段，原因是预处理环节未剥离脱敏后的敏感数据，直接将原始数据传入嵌入流程，违反数据安全要求。
- 搜索返回的目录条目与公共数据开放平台实时数据不符，原因是未配置按月触发的全量索引更新，仅执行了初始一次性索引，导致索引数据滞后。
- 批量导入数据开放清单时出现嵌入失败，原因是未设置合理的分块长度，导致长文本片段超出模型支持的`maxToken`范围，触发嵌入报错。

## 怎么确认配好了
- 导入一份数据项说明文档，查看知识库存储统计，确认包含原文件、分割后的文件块和嵌入向量三部分，符合FastGPT v4.17.0的存储逻辑。
- 触发一次增量索引任务，等待任务完成后搜索更新后的目录条目，验证新报送的部门数据项能正常出现在搜索结果中。
- 输入包含脱敏规则关键词的查询，检查搜索结果仅返回合规的开放数据项，未包含未脱敏的敏感信息。
- 调整相似度阈值至0.70与0.85分别测试，观察搜索结果条数变化，确认阈值配置生效。
