# 公共数据目录与开放的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
本品类数据主要来自地方公共数据开放平台、一体化大数据平台、部门业务数据库及电子证照库，更新周期为每月。日常处理的文档包含公共数据资源目录、数据开放清单、数据项说明、脱敏规则、接口文档及更新频率说明，文档多包含结构化字段如数据项编码、开放条件、接口地址、脱敏方式，部分文档附带批量数据表格与权限说明项。

## 这些特征在「文档解析与分块」这一环带来什么约束
月度批量更新的特性要求解析分块支持批量任务调度，避免单次处理过载。文档包含结构化字段与表格，分块时需保留字段关联关系，不能拆分跨页的表格单元或完整数据项说明。接口文档中的代码片段与权限条款需完整保留，防止分块截断关键配置内容。不同部门提交的文档格式不统一，需适配多种解析模板，避免因格式差异导致解析失败。脱敏规则文档涉及敏感信息边界，分块需确保权限说明与数据项的对应关系不被破坏。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配包含结构化字段与表格的文档，避免拆分完整数据项或接口说明 |
| `chunkSplitter` | 按标题+段落拆分 | 匹配文档中数据项、规则说明的层级结构，保留上下文关联 |
| `customPdfParse` | 启用表格识别模式 | 准确提取文档中的批量数据表格，避免表格内容被错误拆分 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配部门提交的批量目录清单与接口文档包 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 满足大型批量文档的解析耗时需求，避免超时中断 |
| `chunkSettingMode` | 手动配置 | 针对不同类型的文档（如目录清单、接口文档）调整分块参数 |

## 容易做错的三处
- 现象为上传PDF或目录文档后，数据处理环节显示为空，搜索测试无结果。原因是未启用`customPdfParse`的表格识别模式，批量表格内容未被正确提取。
- 现象为部分PDF文件解析后内容为空，部分可正常识别。原因是文档格式不统一，未切换适配的解析模板，加密或带复杂页眉页脚的文档未被正确解析。
- 现象为本地部署后，训练时数据处理无进度反馈，对话功能正常。原因是未配置`PARSE_FILE_TIMEOUT_SECONDS`的合理时长，批量文档解析超时未触发提示。

## 怎么确认配好了
- 上传单份接口文档，查看解析后的文本是否保留完整的接口地址与参数说明，确认分块未截断关键内容。
- 上传批量目录清单文档，检查解析后的数据是否包含所有结构化字段，无缺失或拆分错误。
- 调整`chunkSize`参数后，重新上传测试文档，对比分块结果的完整性，确认符合业务文档的结构特征。
- 上传最大规格的文档包，验证`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`的配置是否满足上传与解析需求。
