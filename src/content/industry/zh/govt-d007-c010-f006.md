# 公路养护与路产路权管理的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
该品类数据主要来自公路养护管理系统、桥隧监测系统、路政巡查系统及交通流量监测数据，更新频率为每日。日常文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单，字段涵盖巡查时间、路段编号、病害类型、处置结果、许可有效期等，单位涉及公里、平方米、工作日等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
每日更新的巡查日志、病害处置单等业务数据，要求引用溯源时精准关联对应路段、时间的原始记录，避免跨业务维度的无效匹配。细分字段如路段编号、病害类型、许可有效期，需绑定具体业务属性，通用文本匹配无法覆盖细分字段的匹配需求。涉路施工许可、路产损坏赔偿单作为审核核心依据，需完整溯源至原始录入系统的时间戳与操作信息，确保合规性校验的准确性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 该品类文档多为结构化业务单据，单条有效信息长度适中，该区间可覆盖完整溯源依据且避免上下文溢出 |
| 单次搜索上限 | 前6条 | 日常业务单据数量集中，过多搜索结果会增加上下文冗余，6条可覆盖核心溯源材料 |
| `responseData` | 仅返回匹配源文档元数据 | 审核环节需关联原始单据的编号、时间等元数据，无需返回完整文档内容即可完成溯源校验 |
| 最大上下文 | 4000–6000 字符 | 单份案卷涉及的养护计划、巡查日志等材料总长度可控，该区间可承载完整审核所需的溯源信息 |
| `detail` | 开启 | 需展示溯源文档的具体字段如路段编号、处置结果，便于审核人员快速核对业务一致性 |

## 容易做错的三处
- 现象为调用时可选知识库列表为空，原因是未绑定公路养护类业务的数据源目录，系统无法自动识别对应知识库。
- 现象为返回的引用结果条数不足，原因是`quoteMaxToken`设置过小，或单次搜索上限配置偏低，无法覆盖案卷涉及的全部合规材料。
- 现象为引用溯源的文档无法正常下载，原因是未开启溯源文档的元数据访问权限，导致系统无法读取原始存储路径。

## 怎么确认配好了
- 导入对应公路养护业务的知识库后，检查可选知识库列表是否包含目标数据源。
- 发起案卷审核测试，核对返回的引用结果条数是否符合配置的单次搜索上限。
- 点击引用溯源的文档链接，确认可正常访问并读取对应元数据。
- 导出审核相关的溯源数据，检查导出粒度是否支持按养护路段、业务类型拆分。
