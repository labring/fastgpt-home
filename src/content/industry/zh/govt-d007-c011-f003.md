# 养老、工伤、失业待遇核定的申报材料与案卷审核：多轮对话与提示词
本文基于FastGPT v4.17.0版本展开配置说明。

## 这个品类的数据长什么样
本品类数据来自社会保险经办系统、个人权益记录、劳动关系与工伤认定系统、电子社保卡平台，更新频率为每日。日常处理的文档包含待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料，文档多包含身份标识、缴费明细、资格证明等字段，部分为结构化表单，部分为扫描件形式的非结构化材料。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据多源且每日更新，要求多轮对话中需跟踪不同系统返回的身份、缴费、工伤认定等字段的一致性，避免引用过期数据。文档格式多样，包含结构化表单与非结构化扫描件，提示词需适配两种格式的材料提取规则。审核环节聚焦缴费年限核算与资格校验，多轮对话需按业务流程拆解问题，逐步引导补充缺失材料，同时保留历史对话中的材料信息用于上下文关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 前 8 轮对话 + 最近 3 条系统提示 | 适配社保审核的连贯流程，避免上下文溢出导致字段混淆 |
| 问题优化 | 按实测标定 | 适配社保业务专属术语，优化用户提问的表述准确性 |
| 单次搜索上限 | 前 3 条召回结果 | 社保业务相关字段集中，过多结果会干扰审核判断 |
| 对话历史绑定 | `chatId` 绑定会话 | 需跟踪同一项审核的多轮材料提交与核对，确保上下文关联 |
| 变量传递 | `variables` 存储当前审核项的身份ID | 跨轮次调用个人权益记录数据，避免重复提问用户 |

## 容易做错的三处
- 对话请求未返回cite引用id：现象为接口响应中无关联社保材料的引用标识字段，原因是配置中未开启多源数据的溯源绑定，或未关联社保业务系统的文档元数据。
- 多轮对话丢失历史问题关键词：现象为后续回复未关联之前提及的缴费年限、工伤认定编号等内容，原因是未通过`chatId`绑定会话上下文，或最大上下文配置过短导致历史信息被截断。
- 代理运行时输出思考过程但对话记录未隐藏：现象为界面展示的对话中包含模型思考日志，原因是配置中未关闭代理的思考过程输出开关，或未过滤代理返回的非回答内容。

## 怎么确认配好了
- 发起包含缴费年限、工伤认定信息的多轮对话，检查后续回复是否关联历史提及的字段。
- 调用对话接口，查看响应中是否包含关联社保业务材料的溯源标识。
- 配置代理后发起测试对话，确认界面展示的回复仅包含业务回答内容，无额外思考过程。
- 测试不同会话的`chatId`，确认同一会话的对话历史被正确保留，不同会话的上下文互不干扰。
