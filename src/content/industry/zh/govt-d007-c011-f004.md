# 养老、工伤、失业待遇核定的申报材料与案卷审核：工作流编排

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
该品类的数据来自社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，每日更新。日常处理的文档包含待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料，核心字段涵盖缴费年限、待遇核算标准、资格审核条件等，单份案卷材料的字段覆盖参保信息、工伤认定结果、失业登记状态等业务相关内容。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需配置多源数据拉取节点，每日更新的频率要求流程触发节点设置定时调度规则。多类型业务文档需要流程中加入格式校验、字段匹配节点，确保不同材料的核心字段符合审核标准。核心字段涉及待遇核算与资格判定，流程需设置多层校验环节，避免错误数据流入后续环节，同时需保留审核痕迹以满足合规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 系统配置接口地址 | 对应社保经办系统的正式接口地址 | 对接业务系统的必填参数，需使用生产环境可访问的接口地址 |
| HTTP请求节点超时时间 | 600秒 | 社保业务系统接口响应存在一定延迟，需预留足够等待时长 |
| JSON内容提取规则 | 按jsonPath语法配置提取路径 | 用于从接口返回的参保数据中提取缴费年限、待遇标准等核心字段 |
| 单次提取字段上限 | 前10条 | 控制接口返回数据量，避免流程负载过高 |
| `variables` 配置 | 定义待遇核定核心字段变量 | 统一管理流程中复用的审核数据，避免重复配置 |
| `nodeId` 命名 | 按节点功能命名，如「拉取参保数据」 | 便于流程中跨节点引用与调试 |
| 定时触发设置 | 每日1次 | 匹配业务数据每日更新的频率 |

## 容易做错的三处
- 现象：HTTP请求节点返回空字段或报错404。原因：未正确配置接口地址为生产环境可访问的社保系统地址，或未开放接口访问权限。
- 现象：JSON内容提取后无法传递至下游节点。原因：未正确启用`variables`配置，或提取的字段未绑定至流程变量。
- 现象：工作流导出后无法正常导入。原因：未按要求保存完整的流程配置，或导出文件存在损坏。

## 怎么确认配好了
- 执行一次测试流程，查看各节点的返回结果是否包含预期的参保信息、待遇标准等字段。
- 触发定时调度节点，确认流程会在指定时间自动启动，无异常中断情况。
- 核对`variables`配置的变量名称与下游节点的引用名称是否一致。
- 导出工作流配置文件，确认所有节点的参数均已正确保存，无缺失项。
