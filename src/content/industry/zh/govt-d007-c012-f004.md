# 养老服务机构监管的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
该品类的核心数据来自养老服务信息平台、民政统计系统、消防检查记录及机构运营台账，通常日常处理的文档包括备案材料、运营补贴申请、服务质量检查表、安全隐患整改台账与老人入住档案。数据更新节奏为月度，核心字段覆盖机构备案信息、床位数量、服务记录、安全整改情况及补贴申请材料。文档结构随业务场景变化，备案材料多为结构化表单，整改台账则多为非结构化记录。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的整合需求要求工作流需对接不同系统的接口，需通过`variables`统一管理跨节点的字段参数。月度更新的节奏要求工作流需匹配固定周期触发，避免过度执行占用资源。多样的文档类型要求工作流需适配不同的解析规则，需为不同文档配置专属的节点参数。核心审核环节的串联需确保每一步校验的准确性，任何节点的异常都可能影响最终审核结果，需配置失败跳转与重试逻辑。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | `{机构备案号: "", 补贴申请周期: "月度", 安全整改阈值: "1项"}` | 匹配养老服务监管的核心业务字段，统一跨节点的参数传递 |
| 节点触发时机 | 按`variables`中的备案提交时间触发 | 适配月度更新的数据节奏，与业务办理周期对齐 |
| 文档解析节点文件路径 | `/opt/fastgpt/upload/yanglao/` | 适配服务器部署的文件存储路径，解决本地与服务器的路径差异问题 |
| `nodeId` | node_audit_core | 用于标记核心审核节点，方便失败跳转时快速定位 |
| 文件上传大小限制 | 100 MB | 适配养老机构备案材料的常规大小，避免大文件占用过多资源 |
| 工具调用结果缓存条数 | 前3条 | 匹配审核所需的核心材料条目，避免冗余数据干扰校验 |
| 工具调用超时时间 | 600 秒 | 覆盖材料解析、跨系统数据拉取的常规耗时，避免中途中断 |
| 最大上下文长度 | 800–1200 字符 | 聚焦案卷审核的核心字段，过长上下文会降低校验准确性 |

## 容易做错的三处
- 现象：工具调用完成后，审核结果未在工作流界面展示。原因：未在工具节点后连接结果输出节点，或未通过`variables`接收工具返回的结构化数据。
- 现象：服务器环境上传文件后，文档解析节点返回404错误。原因：本地环境使用相对路径解析文件，服务器部署后未同步更新文档解析节点的文件存储路径配置，导致节点无法定位上传文件。
- 现象：全局变量未按预期加载备案信息字段。原因：未在工作流启动时通过`variables`传入养老服务信息平台的对应字段值，导致变量为空无法匹配审核规则。

## 怎么确认配好了
- 上传一份模拟的备案材料，检查文档解析节点是否能正确提取机构名称、床位数量等核心字段。
- 触发一次工作流，查看`variables`中定义的全局变量是否正确加载了预设的审核规则参数。
- 模拟工具调用后，检查输出节点是否能正常接收并展示结构化的审核结果。
- 切换到服务器部署环境，上传测试文件，确认文档解析节点无404报错。
