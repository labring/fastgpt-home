# 养老服务机构监管的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
通常，该品类的数据来源包括养老服务信息平台、民政统计系统、消防检查记录与机构运营台账。日常处理的文档包含备案材料、运营补贴申请、服务质量检查表、安全隐患整改台账、老人入住档案。数据更新节奏为月度。数据字段通常包含机构统一社会信用代码、备案编号、实际床位数量、检查项得分、整改完成状态、补贴申请额度等，对应单位分别为无、编号、张、分、布尔值、元。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据接入带来的约束：需配置支持多数据源的插件，分别对接民政系统、消防检查平台与机构内部台账，避免数据孤岛。月度更新的节奏要求工具调用的触发规则适配月度周期，减少无效调用。多样的文档格式需要插件兼容PDF、Excel、结构化台账等类型，适配不同申报材料的解析需求。特定的字段与单位要求工具调用时需增加字段映射校验环节，确保床位数量、补贴额度等字段的单位与格式匹配业务要求，适配核对备案数据、审核补贴材料等核心耗时环节。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 数据源插件选择 | 依次启用民政数据同步、消防检查记录导入、机构台账读取插件 | 覆盖该品类所有数据来源，确保申报材料与案卷的全量数据调用 |
| `toolChoice` | `auto` | 适配多类型文档的解析需求，自动选择合适的工具调用方式处理备案材料、补贴申请等不同格式的内容 |
| `functionCall` | 开启强制参数校验 | 确保字段映射时匹配机构名称、床位数量等必填字段，避免审核错误 |
| 超时阈值 | 600 秒 | 适配月度批量数据拉取与多文档解析的耗时需求，避免因数据量较大触发超时错误 |
| 插件解析格式 | 按文档类型自动适配 | 兼容PDF备案表、Excel台账、Word检查表等常见文档格式，覆盖日常处理的全部文档类型 |
| 字段映射优先级 | 按业务核心字段排序 | 优先匹配备案编号、床位数量等审核必需的字段，提升核对效率 |

## 容易做错的三处
- 安装数据库连接插件后提示服务器内部错误。原因是插件依赖的数据库驱动版本与FastGPT运行环境不兼容，未配置数据库访问白名单导致权限不足。
- 调用API获取业务数据时无法拿到dataId。原因是未在工具配置中指定对应业务的数据源ID，或调用参数未匹配养老机构备案、补贴申请等业务的字段规则。
- 插件中无法启用PDF增强解析功能。原因是未在全局插件设置中开启PDF解析增强开关，或当前使用的插件未适配增强解析的格式要求。

## 怎么确认配好了
- 进入插件管理页面，确认所有配置的数据源插件均显示为启用状态，无异常报错提示。
- 发起一次测试调用，选择一份典型的养老机构备案材料，检查工具调用后返回的字段是否包含备案编号、床位数量等核心业务字段。
- 查看插件日志，确认近一次调用未出现超时、数据拉取失败等异常记录。
- 配置字段映射规则后，导出一份测试的补贴申请材料，检查映射后的字段单位与格式是否符合业务要求。
