# 养老服务机构监管的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自养老服务信息平台、民政统计系统、消防检查记录及机构运营台账，更新频率为月度。日常处理的文档包含机构备案材料、运营补贴申请、服务质量检查表、安全隐患整改台账、老人入住档案。数据字段多包含机构主体信息、床位数量、隐患等级、整改状态、补贴申请明细等，无统一固定单位，需匹配各文档的原始字段格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据特征要求模型接入环节无需配置高频增量同步策略，仅需按周期完成全量或增量同步即可。多类型文档的存在要求配置环节适配不同文档的字段抽取逻辑，避免出现字段不匹配的问题。字段无统一单位的特点，要求模型在处理审核任务时需结合文档上下文识别单位，不依赖固定映射规则。同时，监管场景的出错后果明确，配置环节需强化结果校验的逻辑，确保审核结果的准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配备案、补贴申请等多文档的长上下文需求，覆盖多份关联案卷的整体信息 |
| `maxTokens` | 2000–3000 token | 满足审核结果的详细输出要求，包含校验细节与整改建议 |
| `quoteMaxToken` | 1500–2000 token | 匹配单份文档的平均长度，确保检索到的案卷内容完整可用 |
| `temperature` | 0.1–0.3 | 降低随机输出概率，提升审核结果的一致性与合规性 |
| `toolChoice` | auto | 自动适配工具调用需求，完成数据核对与字段校验 |
| `AIPROXY_API_ENDPOINT` | 按服务商提供的官方地址填写 | 确保模型API调用的连通性，适配非本地部署的模型调用场景 |
| `AIPROXY_API_TOKEN` | 按服务商生成的密钥填写 | 完成API调用的身份验证，保障调用安全 |

## 容易做错的三处
- 检索环节出现10秒以上的超时响应。原因是未针对养老服务机构的多源异构数据调整检索策略，混合检索的召回范围过大导致耗时增加。
- 部署后工具调用结果出现额外的无关字符。原因是模型输出格式未与FastGPT的工具调用规则匹配，导致额外的格式补全内容被返回。
- 容器部署后管理界面无对应渠道配置项。原因是部署时未正确挂载配置文件，导致渠道信息未被加载。

## 怎么确认配好了
- 发起单次案卷审核测试，检查模型调用的响应时长是否符合业务预期，可根据实际场景调整超时阈值。
- 查看检索结果的召回条数，确认与配置的检索上限一致，验证检索策略是否生效。
- 提交一份模拟的备案材料，检查模型输出的字段校验结果是否与文档内容匹配，确认上下文配置是否正常加载。
- 验证API密钥与端点配置的连通性，确认无身份验证或地址错误导致的调用失败。
