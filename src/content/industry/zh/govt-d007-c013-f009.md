# 内控评价、审计与整改的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
数据来源为企业内控系统、ERP、财务共享系统、审计管理系统、采购合同项目系统。日常处理的文档包括内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据更新频率为年度。文档结构多为结构化表格与非结构化文本混合，包含问题描述、整改要求、佐证材料编号、责任部门等字段，无统一固定格式，随企业内控规范调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
年度更新的数据量较大且结构不统一，要求模型接入需支持多格式文档解析。不同系统的数据字段差异明显，需配置适配非结构化文本抽取的参数。整改台账与销号证明的关联校验需要模型具备上下文关联能力，因此上下文窗口配置需匹配文档长度。数据来源分散，需确保模型接入的API端点可对接多系统导出的文件，同时需处理不同系统的格式兼容性问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 8000–12000 token | 适配内控自评报告、审计工作底稿等单文档的长度需求，确保完整读取案卷核心信息 |
| temperature | 0.1–0.3 | 确保抽取的审计问题、整改要求等内容准确稳定，减少主观偏差 |
| maxTokens | 2000–3000 token | 满足整改台账、销号证明等文本的生成与校验输出长度 |
| AIPROXY_API_ENDPOINT | 按部署环境填写本地模型服务地址 | 适配本地部署的VLLM、Ollama等模型运行环境，支持对接Qwen3系列模型 |
| AIPROXY_API_TOKEN | 按实际生成的密钥填写 | 确保模型服务的访问权限安全可控，避免未授权访问 |
| quoteMaxToken | 1500–2000 字符 | 保留足够的案卷原文片段用于审计问题佐证，提升校验可信度 |

## 容易做错的三处
- 界面显示模型连接失败，状态码为404。原因是未正确填写`AIPROXY_API_ENDPOINT`，本地部署的VLLM、Ollama或其他大模型服务地址未映射到可访问的网络路径。
- 抽取的整改问题字段为空。原因是`temperature`取值过高，导致模型生成的内容偏离既定的审计问题格式，无法匹配预设的字段提取规则。
- 上下文溢出导致处理中断。原因是`maxContext`设置过小，无法容纳单份审计工作底稿的完整内容，导致关键案卷信息丢失。

## 怎么确认配好了
- 手动上传单份内控自评报告，检查模型是否能正确抽取其中的问题清单与整改要求，核对抽取结果与原文的匹配度。
- 调用模型服务的测试接口，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置是否能正常返回响应，无连接超时或权限报错。
- 调整`maxContext`参数，上传最长的审计工作底稿，确认处理过程无中断，输出内容完整覆盖文档核心信息。
- 导入多系统导出的混合格式文档，检查模型是否能正确识别不同文档的字段结构，无格式解析错误。
