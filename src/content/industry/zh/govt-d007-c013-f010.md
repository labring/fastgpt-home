# 内控评价、审计与整改的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
本品类数据主要来自企业内控系统、ERP、财务共享系统、审计管理系统及采购合同项目系统。日常处理的文档包括内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。日常工作中最耗时的环节为抽取业务样本和凭证、形成审计问题和整改要求、跟踪整改佐证和销号。数据更新频率为年度周期，文档多为结构化与半结构化混合，包含问题编号、整改责任人、完成时限、佐证材料编号等字段，单份文档篇幅跨度较大。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散导致跨系统文档格式不统一，需适配多源数据的解析与入库流程。年度更新频率意味着知识库无需高频增量同步，但单次批量入库数据量较大，需配置合理的分块与索引策略。文档包含问题编号、整改责任人、完成时限等结构化字段，检索时需支持精准匹配业务标识。单份文档篇幅跨度大，分块时需兼顾上下文完整性与检索精度，避免分块过碎丢失业务关联，或分块过大导致召回冗余。审计工作出错后果包括审计问题重复发生、监管通报、责任追究或财务报表调整，因此检索结果的准确性直接影响工作质量。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.72–0.85 | 适配审计文档的专业术语匹配需求，避免召回无关的整改记录或自评报告 |
| `limit` | 前10条 | 控制单次召回结果数量，适配审计人员快速浏览的工作习惯，避免信息过载 |
| `searchMode` | `local` | 优先匹配本地知识库中的结构化业务字段，保障检索结果与企业内部数据的一致性 |
| `usingReRank` | 开启 | 对召回结果进行二次排序，提升与审计问题、整改要求的匹配精度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户提问自动生成扩展查询词，覆盖审计相关的同义词与业务简称，比如将“整改销号”匹配为“整改完成证明” |
| `collectionIds` | 按业务模块指定 | 仅检索内控自评、审计底稿、整改台账等专属集合，避免混入其他品类的文档数据 |

## 容易做错的三处
- 检索时返回`text index required for $text query`报错。原因是未完成知识库文本索引的构建流程，或配置参数时未启用对应索引规则。
- 迁移知识库至本地部署环境后，检索结果出现大量无关文档。原因是未通过`collectionIds`指定专属检索集合，导致其他品类的文档被纳入检索范围。
- 单次批量检索耗时超过60秒。原因是未设置合理的`limit`参数，且未开启`usingReRank`，导致系统处理过多冗余数据。

## 怎么确认配好了
- 上传单份审计工作底稿，执行检索测试，核对返回结果是否仅包含与该底稿相关的整改台账与问题清单。
- 查看知识库索引状态，确认所有指定`collectionIds`的集合已完成文本索引构建。
- 模拟审计提问，检查检索结果是否包含结构化字段匹配项，如问题编号、整改责任人。
- 测试批量入库流程，确认无`text index required for $text query`类报错。
