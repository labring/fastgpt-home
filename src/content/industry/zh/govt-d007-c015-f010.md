# 医保基金监管稽核的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
本品类涉及的数据主要来自医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索。日常处理的文档包含稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书、整改报告，文档多包含定点医药机构名称、费用明细、违规判定依据等字段，单位涉及元、人次、药品批次等。数据更新频率为每月一次，整体数据随稽核批次逐步累积。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散，需整合多渠道的结构化与非结构化数据，要求检索覆盖多维度关联字段；月度更新的特性要求知识库同步周期匹配数据更新节奏，避免滞后数据影响违规判定；文档类型多样，既有标准化的规则库文本，也有非标准化的约谈记录，需适配不同文档的检索权重；稽核环节需快速调阅关联案卷，要求召回结果精准匹配疑点清单中的违规线索，避免冗余结果干扰人工审核。

| `limit` | `前8–12条` | 控制单批次检索返回结果数量，适配稽核环节的人工审核效率，避免上下文溢出 |
| `searchMode` | `keyword + vector hybrid` | 兼顾标准化规则库的关键词匹配与非标准化案卷的语义关联，覆盖全类型文档 |
| `usingReRank` | `开启` | 对初步召回结果二次排序，优先匹配疑点清单中的违规判定关键词 |
| `datasetSearchUsingExtensionQuery` | `开启` | 基于稽核疑点自动扩展检索词，覆盖举报线索中的模糊表述 |
| `collectionIds` | `对应本稽核场景的专属知识库集合ID` | 隔离其他品类的文档，避免无关数据干扰检索精度 |

## 容易做错的三处
- 执行检索后返回的结果条数与配置`limit`不符，原因是未正确配置`collectionIds`，导致检索范围覆盖了非本稽核场景的知识库数据。
- 全局变量中“选择知识库”的参数传入后未生效，原因是使用了错误的变量格式，未遵循系统要求的参数结构。
- 上传知识库文件时界面提示格式异常，原因是上传的文档未适配系统支持的格式类型，或文件包含无法解析的特殊字符。

## 怎么确认配好了
- 登录FastGPT v4.17.0管理后台，进入对应知识库的检索配置页面，核对所有配置项的取值与预设方案一致。
- 输入一条典型的稽核疑点，执行检索后核对返回结果的数量与`limit`配置的取值范围匹配。
- 手动触发一次知识库同步任务，确认同步进度符合月度数据更新的周期要求。
- 调用检索接口，查看返回结果的关联字段是否与输入的稽核疑点匹配。
