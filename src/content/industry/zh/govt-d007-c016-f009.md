# 医保费用结算审核的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据来自全国医疗保障信息平台、医院HIS和医保接口、医保目录编码库、异地就医结算平台，更新频率为每日。日常处理的文档包含医保结算清单、费用明细、病案首页、处方、拒付清单、结算对账单，包含诊疗项目编码、药品耗材编码、费用金额、就诊日期、参保人信息等字段，支持单笔或批量的费用审核业务，数据结构统一且需匹配官方编码库完成合规校验。

## 这些特征在「模型接入与配置」这一环带来什么约束
医保费用结算审核的数据来源多样且需每日同步，要求模型接入链路支持多接口数据的格式兼容与定时更新；文档包含多类结构化与半结构化材料，单次批量审核可能产生较大上下文长度，需适配模型的上下文承载能力；编码匹配、一致性校验等核心环节要求输出结果具备高稳定性，避免随机性偏差；拒付对账等批量业务需处理多份关联文档，对模型的上下文整合能力有明确要求，同时需符合医保数据的访问管控规范。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配医保结算清单、明细、病案等多份材料的合并输入长度，覆盖批量审核的上下文需求 |
| `maxTokens` | 4000–6000 token | 平衡审核结果输出长度与模型推理速度，适配单次批量审核的结果输出需求 |
| `quoteMaxToken` | 1500–2000 token | 保留医保目录编码、费用明细等核心参考文本的完整信息，确保匹配准确性 |
| `temperature` | 0.1–0.3 | 降低模型生成随机性，提升编码匹配、一致性审核的精准度，避免审核结果偏差 |
| `AIPROXY_API_ENDPOINT` | 按本地部署的代理服务地址填写 | 适配本地部署的模型调用链路，确保数据流转符合医保数据管控要求 |
| `AIPROXY_API_TOKEN` | 按代理服务生成的密钥填写 | 保障模型调用的身份验证安全，符合医保数据的访问权限管控规范 |

## 容易做错的三处
- 现象：对话中上传的医保结算清单、病案首页等多份文档超出模型上下文上限，触发上下文溢出报错。原因：未调整`maxContext`参数适配多份医疗文档的总输入长度。
- 现象：模型返回的诊疗项目编码匹配结果与医保目录库不符，出现字段为空或匹配错误。原因：`temperature`参数设置过高，导致模型生成结果的随机性超出合规范围。
- 现象：本地部署的DeepSeek模型无法正常调用，返回401认证失败或连接超时错误。原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`参数，未匹配代理服务的密钥与地址。

## 怎么确认配好了
- 上传单份医保结算清单与对应处方，检查模型输出的编码匹配结果是否与医保目录库字段一致。
- 批量上传3-5份结算明细文档，验证`maxContext`参数是否能承载总输入长度，无上下文溢出报错。
- 调用代理服务接口，检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置是否能正常返回模型推理结果。
- 调整`temperature`参数至0.2，多次审核同一份拒付清单，检查审核结果是否保持稳定。
