# 医疗机构监督与公共卫生检查的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据主要来自卫生监督信息系统、医疗机构电子化注册系统、投诉举报平台与执法检查记录，更新频率为月度。日常处理的文档包含监督检查表、医疗机构执业许可证、整改通知书、监督意见书、处罚案卷，数据字段覆盖机构资质信息、现场检查项、整改要求、处罚依据等，包含结构化与非结构化两类内容，无统一固定格式，需适配多类文档的字段提取与校验。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且月度更新，要求多轮对话需支持跨系统数据调用的上下文延续，避免重复拉取历史数据；非结构化文档占比高，提示词需适配检查表、案卷等不同格式的内容，精准提取机构资质、整改情况等核心字段；执法场景对准确性要求极高，多轮对话需保留历史核查记录作为上下文参考，确保整改跟踪的连贯性；月度批量更新的案卷数据，需提示词支持批量校验逻辑，避免单轮处理遗漏跨周期的核查信息。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 适配处罚案卷、多份整改通知书的批量文本长度 |
| 单次对话轮次上限 | 前 8 轮 | 匹配单份案卷的常规核查步骤，避免上下文过载 |
| 变量绑定范围 | 绑定机构资质、检查记录字段 | 从卫生监督信息系统、执法检查记录中提取核心字段供提示词调用 |
| 问题优化触发阈值 | 按实测标定 | 针对非结构化的检查表内容，优化用户输入的核查指令 |
| 超时设置 | 600 秒 | 适配跨系统数据拉取与多文档拼接的处理时长 |

## 容易做错的三处
- 现象为通过HTTP请求编排的对话流程，输出结果未在对话界面展示。原因是未将`variables`参数的返回值同步绑定至对话上下文输出节点。
- 现象为多轮对话无法延续历史核查的上下文，每轮交互均需重复输入机构信息。原因是未配置`messages`参数保留历史交互记录，导致每轮对话重置上下文。
- 现象为批量案卷审核时，返回的结果条数与预期不符，混入非当月的历史数据。原因是未限定对话调用的数据源范围，导致拉取了超过月度更新周期的冗余文档。

## 怎么确认配好了
- 上传单份监督检查表与医疗机构执业许可证，触发多轮对话，核对提示词是否准确提取了机构名称、许可范围等核心字段。
- 调用HTTP编排接口，查看对话界面是否显示返回的output内容，确认`chatId`参数的上下文绑定生效。
- 设置超时测试，模拟跨系统数据拉取，验证处理时长未超过预设阈值。
- 导入月度更新的批量案卷，检查对话是否仅调用当月的检查记录与整改通知书。
