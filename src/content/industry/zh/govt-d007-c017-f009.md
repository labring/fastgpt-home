# 医疗机构监督与公共卫生检查的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自卫生监督信息系统、医疗机构电子化注册系统、投诉举报平台与执法检查记录，更新频率为月度。日常处理的文档包含监督检查表、医疗机构执业许可证、整改通知书、监督意见书及处罚案卷，文档核心字段覆盖机构主体信息、许可资质、现场检查项、整改要求与处罚相关内容，单份案卷文档长度跨度较大，从数百字符的电子记录到多页纸质扫描件均有覆盖。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征对模型接入与配置环节带来多重约束。数据来源分散且月度更新，需配置稳定的增量同步规则以匹配更新节奏；文档类型覆盖结构化证件与非结构化检查记录，需适配多格式的文本提取逻辑；单份案卷文档长度跨度较大，部分处罚案卷内容超出单模型上下文限制，需配置上下文拆分与精准召回机制；核心校验环节涉及机构资质、诊疗行为合规性判断，对模型输出的准确性有较高要求，需调整生成参数平衡严谨性与处理效率。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 匹配多数公开大模型的上下文窗口上限，适配本品类最长达数千字符的处罚案卷与多文档批量审核场景 |
| `maxTokens` | 1500–2000 token | 控制单轮生成输出长度，避免生成内容超出后续处理的合理范围，适配合规判断类任务的输出需求 |
| `quoteMaxToken` | 3000–4000 token | 限定召回参考文档的总长度，确保参考内容与当前审核任务的上下文匹配度，避免冗余信息干扰模型判断 |
| `temperature` | 0.2–0.4 | 降低生成随机性，提升资质核对、合规判断等任务的输出一致性，适配本品类严谨性要求较高的审核场景 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应接口地址 | 适配本地部署或私有部署的模型调用路径，确保模型接入链路正常 |
| `AIPROXY_API_TOKEN` | 填写私有部署模型的授权密钥 | 确保模型调用的身份验证通过，避免未授权的接口访问 |

## 容易做错的三处
-  模型调用返回上下文溢出报错，状态码显示400或参数超限。原因是未配置`maxContext`或`quoteMaxToken`参数，未对超长案卷文档进行合理切片。
-  配置自定义模型图标时，界面显示图标加载失败。原因是直接使用非HTTPS协议的图片链接或未使用符合要求的格式文件，未遵循平台对图标资源的规范要求。
-  生成的审核结果与实际文档内容偏差较大。原因是`temperature`参数设置过高，导致模型生成内容随机性过强，偏离资质核对、合规判断的严谨性需求。

## 怎么确认配好了
-  导入一份本品类典型的处罚案卷文档，查看系统是否自动完成文本提取与切片，确认上下文拆分逻辑生效。
-  发起一次资质核对测试，检查模型返回结果是否准确匹配导入文档中的机构许可信息，验证生成参数的严谨性设置是否符合需求。
-  查看模型调用日志，确认接口地址与密钥配置正确，无调用失败的报错记录。
-  调整`temperature`参数后发起测试，对比不同取值下的审核结果差异，确认参数调整对输出一致性的影响符合预期。
