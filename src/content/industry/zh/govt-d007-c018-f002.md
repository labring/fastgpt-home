# 参保登记与缴费核定的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自社会保险经办系统、税务社保费征收系统、市场主体登记信息及公安民政共享数据，更新频率为每日。日常处理的文档包含参保登记表、缴费基数申报表、人员增减表、社保费核定单、个人权益记录等，结构以结构化表单为主，核心字段涵盖人员身份标识、缴费基数、参保状态、增减人员信息等，数据关联跨多个业务系统，无复杂嵌套内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
日更的数据要求索引需支持增量更新，避免全量重建带来的性能损耗。结构化表单类文档的字段密度较高，向量分块需适配字段边界以保证检索准确性。跨系统来源的数据存在字段格式差异，需在索引阶段完成基础对齐。核心字段如人员身份标识的匹配精度直接影响业务合规性，对向量检索的相似度阈值设置提出明确要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配参保登记表、缴费核定单等结构化表单的字段密度，避免单块包含过多无关关联字段 |
| 重叠长度 | 100–200 字符 | 覆盖人员身份、缴费基数这类跨块关联的关键信息，防止关键内容被分块截断 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 匹配人社系统的身份核验标准，降低非目标案卷的误匹配概率 |
| 单次搜索上限 | 前 10 条 | 适配日均更新的案卷量级，避免检索结果冗余影响后续处理效率 |
| `defaultToken` | 8192 | 适配多源数据拼接后的上下文长度，符合text-embedding-ada-002的输入限制 |
| `maxToken` | 16384 | 预留跨系统数据对账时的长文本处理空间，满足复杂业务场景的上下文需求 |

## 容易做错的三处
- 界面长时间显示“索引中”状态，无进度更新。原因是未按日更新频率配置增量索引触发规则，或本地部署的向量模型资源不足导致索引构建卡顿。
- 调用知识库时返回“无可匹配结果”报错。原因是相似度阈值设置过高，未适配参保登记数据中人员身份字段的细微差异，导致有效匹配被过滤。
- 向量模型调用失败，控制台显示模型未找到。原因是未将text-embedding-ada-002或本地m3e模型正确添加到API渠道，或配置项未正确关联模型标识。

## 怎么确认配好了
- 查看FastGPT v4.17.0的索引构建日志，确认日增量更新任务按设定时间自动触发，无报错记录。
- 输入参保人员身份证号作为检索词，核对返回结果的相似度分值是否在预设阈值区间内。
- 调用向量模型接口，返回格式正确的embedding向量结果，无格式错误或权限报错。
- 检查配置文件中的模型绑定参数，确认已正确关联对应API渠道的模型标识，无配置遗漏。
