# 参保登记与缴费核定的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源于社会保险经办系统、税务社保费征收系统、市场主体登记信息、公安民政数据共享，更新频率为每日。日常处理的文档包括参保登记表、缴费基数申报表、人员增减表、社保费核定单、个人权益记录，核心字段包含参保人员身份证号、单位统一社会信用代码、缴费基数、人员状态等，缴费基数以元为单位，人员数量以人为单位，需严格匹配各系统的接口格式要求。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源覆盖多套政务系统的特性，要求多轮对话需依次对齐不同系统的字段格式，避免出现字段名不匹配的问题。业务数据日更新的频率，要求对话节点需实时拉取最新的参保与缴费信息，无法依赖固定的历史缓存。多样的文档类型要求提示词需适配不同申报材料的必填项校验逻辑，确保每类材料的审核规则准确。同时，审核出错会直接影响参保人员权益与单位缴费合规性，要求多轮对话需增加身份与劳动关系的二次校验环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 覆盖参保登记、缴费核定类多份文档的字段总量，匹配FastGPT v4.17.0的单轮对话token消耗上限，避免关键信息截断 |
| 多轮历史保留时长 | 7 天 | 匹配业务数据日更新频率，确保审核周期内可调用最新的共享数据，同时避免过期数据干扰 |
| variables 传入参数 | 按实测标定 | 用于传递单位统一社会信用代码、人员身份证号等核心查询变量，确保模型可关联对应业务数据 |
| chatId 会话绑定规则 | 绑定唯一经办批次ID | 关联对应批次的申报材料与案卷，确保不同批次的对话上下文互不干扰 |
| 提示词模板校验开关 | 开启 | 针对文档字段的固定格式，自动校验申报材料的必填项完整性，降低人工审核疏漏风险 |

## 容易做错的三处
- 现象：对话返回的人员身份校验结果为空。原因：未在variables中传入参保人员的身份证号作为查询参数，导致模型无法匹配对应业务数据。
- 现象：超过7天的申报案卷材料无法被对话节点加载。原因：默认的CHAT_FILE_EXPIRE_TIME参数设置为7天，未根据业务案卷留存周期调整。
- 现象：批量执行的多轮对话节点出现上下文串扰。原因：未为每个经办批次绑定独立的chatId，导致不同批次的对话历史互相覆盖。

## 怎么确认配好了
- 手动传入测试用的单位统一社会信用代码与人员身份证号，使用FastGPT v4.17.0版本的对话节点进行测试，查看是否能返回对应参保登记与缴费核定的相关信息。
- 调整CHAT_FILE_EXPIRE_TIME参数为30天，上传超过7天的测试案卷，确认可正常加载与解析。
- 配置多个绑定独立chatId的测试会话，并行发起审核请求，确认各会话的上下文互不干扰。
- 检查variables参数的传入逻辑，确认核心业务字段均已作为变量传递至对话节点。
