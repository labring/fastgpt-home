# 参保登记与缴费核定的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自社会保险经办系统、税务社保费征收系统、市场主体登记信息及公安民政共享数据，每日更新。日常处理的文档包含参保登记表、缴费基数申报表、人员增减表、社保费核定单、个人权益记录，核心字段涵盖人员身份标识、劳动关系存续状态、缴费基数、参保状态、税务征收匹配标识等，单份文档字段数量较多且存在跨系统关联校验需求。

## 这些特征在「模型接入与配置」这一环带来什么约束
跨系统多源数据的接入要求模型需支持跨数据源关联校验，每日更新的数据特性要求配置适配高频数据同步的上下文加载逻辑。多字段的文档结构会拉长单份案卷的上下文长度，需限制无效冗余内容的引入以避免上下文溢出。人员身份与劳动关系核对的高准确率需求，要求模型输出需绑定原始文档引用，同时需适配不同文档的字段格式差异，避免解析错位。税务征收数据对账环节涉及多维度数值比对，需模型支持结构化数据校验逻辑，保障比对结果的一致性。

以下配置基于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配多字段文档与跨系统关联的上下文长度需求，避免关键数据被截断 |
| `maxTokens` | 2000–3000 token | 覆盖单份案卷审核的完整输出需求，包含字段校验与对账结果说明 |
| `quoteMaxToken` | 1500 token | 确保模型引用的原始文档片段足够覆盖校验依据，避免引用内容不全 |
| `temperature` | 0.1–0.3 | 降低随机输出概率，保障身份核对、数据对账的结果一致性 |
| `AIPROXY_API_ENDPOINT` | 按平台部署地址填写 | 适配FastGPT的代理调用链路，保障模型请求的正常路由 |
| `toolChoice` | auto | 允许模型自动调用工具完成跨系统数据匹配，提升核对准确率 |

## 容易做错的三处
- 现象：reranker模型启动失败，界面显示模型加载超时。原因：未适配社保场景下的文档分片长度，导致重排模型输入超出阈值。
- 现象：模型输出字段为空，无法返回缴费基数核对结果。原因：`maxContext`设置过小，原始参保登记表内容被截断，模型无法提取关键字段。
- 现象：审核结果与税务数据对账偏差较大。原因：`temperature`设置过高，模型随机生成非标准比对逻辑，导致校验结果不一致。

## 怎么确认配好了
- 上传单份参保登记表与人员增减表，检查模型输出是否完整提取人员身份、参保状态字段。
- 发起跨系统数据对账测试，确认模型是否自动调用关联数据完成校验。
- 调整`temperature`参数前后对比审核结果，确认输出一致性符合预期。
- 查看代理接口日志，确认`AIPROXY_API_ENDPOINT`配置可正常接收并转发模型请求。
