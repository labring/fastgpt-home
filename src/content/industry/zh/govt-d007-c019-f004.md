# 双随机、一公开监管检查的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
本品类的数据通常来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库，更新频率为月度。日常处理的文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示。数据字段通常涵盖检查对象标识、执法人员编号、抽查比例、检查结果状态等，无统一固定的单位要求，部分文档需关联跨系统的主体信息。

## 这些特征在「工作流编排」这一环带来什么约束
多系统数据源的特性要求工作流需配置跨平台数据拉取节点，确保能同步月度更新的检查对象与执法人员信息。多样的文档类型要求工作流设置分支节点，分别处理抽查计划生成、检查记录录入、结果公示推送等环节。月度更新的节奏要求定时触发节点按自然月周期运行，避免频繁拉取占用系统资源。同时，由于部分检查不进入处罚程序，工作流无需关联处罚案卷节点，仅需聚焦抽查与公示流程的校验，防止抽取不合规或结果漏公示的问题。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 定时触发周期 | 自然月首日 0 点 | 匹配月度更新的数据源节奏 |
| 分支判断条件 | 按文档类型分流 | 适配抽查计划、检查记录等多类文档处理 |
| `variables` 配置 | 存储抽查比例、公示模板参数 | 统一复用业务规则，减少重复配置 |
| 数据库连接超时时间 | 30–60 秒 | 适配跨系统数据拉取的响应时长 |
| 文件上传节点大小限制 | 10–20 MB | 匹配现场检查照片等附件的常规尺寸 |
| `nodeId` 配置 | 按业务环节命名，如check-record-02 | 方便工作流节点的调试与管理 |

## 容易做错的三处
- 尝试通过个人微信二维码发布工作流后，无法实现多人扫码接入。原因是工作流的分享权限未配置为全员可访问，仅个人扫码仅支持单次或指定账号接入。
- 数据库连接节点无法输入端口号。原因是未开启高级配置开关，部分数据库连接的端口参数默认隐藏在高级设置中。
- 工具调用节点使用qwen3.5-plus模型时频繁返回429状态码。原因是未配置请求频率限制，未根据模型的调用配额调整节点的并行执行数量。

## 怎么确认配好了
- 手动触发一次工作流，验证是否能拉取到当前月度的检查对象与执法人员数据。
- 上传一份模拟的现场检查照片或记录文档，确认工作流能按文档类型进入对应处理分支。
- 查看工作流运行日志，确认数据库连接请求未出现超时异常。
- 多次调用工具节点，确认未出现频率限制相关的报错。
