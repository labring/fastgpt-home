# 双随机、一公开监管检查的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
这个品类的文档通常包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示等类型，数据主要来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库。数据更新频率为月度，文档结构多包含固定字段，如检查对象统一社会信用代码、检查事项类别、执法人员编号、整改时限等，部分文档存在多列表格或跨页分页格式。

## 这些特征在「文档解析与分块」这一环带来什么约束
月度批量更新的文档要求解析环节支持批量处理，避免单文档解析超时。固定字段与多类型文档混合的场景，需要分块时保留字段关联性，避免拆分执法人员编号、统一社会信用代码这类关键标识。多列排版的检查对象名单、检查事项清单文档，可能导致常规解析工具误拆分列内容，需要调整解析规则适配多列结构。部分文档存在分页或跨页连续字段，分块时需避免跨页截断完整信息。

## 配置怎么定
以下配置基于FastGPT v4.17.0 版本的功能实现。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配检查事项清单、现场检查记录的字段长度，避免拆分关键监管信息 |
| `chunkSplitter` | 按段落+语义分块 | 匹配多类型文档的结构，保留整改通知书、抽查结果公示的语义完整性 |
| `customPdfParse` | 开启多列识别模式 | 适配检查对象名单的多列排版，避免解析时错位合并列数据 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 适配批量上传的月度更新文档，避免因单文件过大触发上传失败 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 覆盖大型现场检查记录的解析耗时，避免中途超时中断 |
| `chunkSettingMode` | 手动配置模式 | 针对不同文档类型调整分块规则，适配抽查计划与公示文档的差异 |

## 容易做错的三处
- 现象：上传的PDF解析后图片未正常关联至知识库内容，或无法检索到解析后的图片资源。原因：未开启`customPdfParse`的图片嵌入配置，导致解析后的图片资源未同步绑定至分块文本。
- 现象：多列排版的检查对象名单解析后出现列错位、字段合并为单段文本。原因：未启用多列识别模式，使用默认分块逻辑误将多列内容合并，破坏字段对应关系。
- 现象：批量上传月度更新文档时出现解析超时报错。原因：`PARSE_FILE_TIMEOUT_SECONDS`配置值低于单份大型文档的实际解析耗时，未覆盖完整处理周期。

## 怎么确认配好了
- 上传一份标准的多列检查对象名单PDF，查看解析后的文本是否保留列对齐的字段内容，验证多列识别配置生效。
- 查看知识库上传日志，确认单份500 MB以内的文档未触发上传失败提示，验证`UPLOAD_FILE_MAX_SIZE`配置合规。
- 提交一份大型现场检查记录文档，等待解析完成后检查是否出现超时报错，验证`PARSE_FILE_TIMEOUT_SECONDS`配置满足需求。
- 随机抽取分块后的文本片段，确认执法人员编号、统一社会信用代码等关键字段未被跨块拆分，验证`chunkSize`与分块规则配置合理。
