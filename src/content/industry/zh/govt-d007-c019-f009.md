# 双随机、一公开监管检查的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据通常来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库。日常文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示，包含统一社会信用代码、执法人员编号、检查事项条目等字段。数据更新频率为月度，核心文档围绕抽查任务生成与结果公示流转。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据源要求模型接入环节支持增量数据同步，避免全量重训带来的资源消耗。多类型文档结构差异要求配置适配结构化名单与非结构化检查记录的混合输入，避免解析偏差。检查对象抽取合规性要求模型匹配逻辑需严格对应监管规则，同时无需额外适配处罚裁量逻辑，简化配置项。日常高频的任务生成与结果录入环节，要求模型调用延迟符合业务流转节奏，避免拖慢整体流程。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配抽查计划、检查记录等单份文档的平均长度，避免截断核心监管信息 |
| `maxTokens` | 2000–3000 token | 满足单条检查结果公示的输出长度需求，同时控制单次调用的显存占用 |
| `quoteMaxToken` | 1500 字符 | 匹配案卷审核中对引用材料的长度限制，确保提取的检查对象信息完整 |
| `toolChoice` | auto | 允许模型根据审核任务自动选择工具，适配抽查匹配、内容提取等多类子任务 |
| `temperature` | 0.1–0.3 | 降低随机性，确保检查对象抽取、事项匹配的结果符合监管规则的严谨性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属地址 | 适配监管部门内部网络的访问限制，确保数据传输安全 |

## 容易做错的三处
- 现象：rerank模型调用后显存占用持续攀升未释放，最终触发内存溢出报错。原因：未配置模型自动显存回收策略，长上下文调用后显存未被及时释放。
- 现象：工作流内的文本内容提取节点无法选择目标模型。原因：未在系统设置中提前挂载适配监管文档解析的专用模型，或模型格式与当前节点不兼容。
- 现象：Ollama挂载的LLM模型输出内容与监管知识库无关。原因：未正确绑定专属监管知识库至模型调用链路，或上下文召回逻辑未匹配业务需求。

## 怎么确认配好了
- 执行单份抽查计划的模型解析测试，检查输出的检查对象列表字段完整且无异常截断。
- 触发批量检查记录的审核任务，查看显存占用峰值符合实测标定的安全区间。
- 查看模型调用日志，确认配置参数如`maxContext`、`temperature`按预设值生效。
- 绑定专属监管知识库后发起查询，验证模型输出的检查结果与系统内公示数据匹配。
