# 国土空间规划编制与实施评估的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
该品类的日常文档包括国土空间总体规划、详细规划、专项规划、规划实施评估报告、公众意见汇总等，数据来源涵盖国土空间基础信息平台、自然资源调查监测数据、人口经济统计数据、遥感影像资料。数据更新频率为每年一次，文档结构多包含空间坐标、规划指标、部门意见等字段，单位涉及公顷、万人、平方公里等空间与统计类标准单位。典型处理主体为自然资源部门规划处、规划院及地方政府，日常需汇总多源空间数据与跨部门意见。

## 这些特征在「引用来源与溯源」这一环带来什么约束
国土空间规划类数据多为区域级多源空间与统计数据，引用溯源需精准匹配每一条规划依据的原始来源，避免出现跨数据类型的混淆。年更新频率要求需定期同步知识库最新数据，否则引用内容会滞后于官方发布的规划调整。文档结构包含大量空间坐标与专业指标，引用溯源需保留字段与单位信息，确保审核环节可验证数据准确性。多源数据的汇总特性也要求溯源环节需区分不同数据来源的标识，便于案卷审核时的交叉核对。同时，规划案卷审核需留存完整的引用链条，确保每一项规划决策都可追溯至原始数据，因此溯源环节的准确性直接影响审批进度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配国土空间规划文档的典型段落长度，避免截断关键引用信息 |
| `responseData` | 返回完整引用元数据 | 适配案卷审核时需溯源至原始数据来源的业务要求 |
| `detail` | 开启 | 展示引用内容的具体字段与来源路径，满足审核验证需求 |
| 单次搜索上限 | 前5条 | 控制返回结果数量，适配多源数据的筛选与核对需求 |
| 最大上下文 | 4000–6000 token | 容纳多源空间数据与规划文档的联合上下文，避免上下文溢出 |

## 容易做错的三处
- 现象：调用接口后返回结果无content字段，或引用来源模块为空。原因：未正确开启`responseData`配置项，仅返回了回答文本未携带元数据。
- 现象：点击引用来源的下载链接无法访问对应文件。原因：未正确配置本地知识库的访问路径，或nginx代理未覆盖原文下载的接口路由。
- 现象：引用溯源结果的条数不符合预期，过多或过少。原因：单次搜索上限设置不合理，未匹配国土空间规划多源数据的召回需求。

## 怎么确认配好了
- 发起测试请求，检查返回结果中是否包含`responseData`字段对应的引用元数据，包括来源名称、路径与字段信息。
- 点击引用来源的下载链接，验证是否能正常访问对应规划文档或数据文件，无访问报错。
- 调整`quoteMaxToken`参数，观察回答中引用内容的截断情况，确认未出现关键规划指标被截断的问题。
- 测试包含多源数据的查询，确认返回的引用来源覆盖国土空间基础信息平台、遥感影像等不同数据类型。
