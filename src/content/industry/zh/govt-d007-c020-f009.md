# 国土空间规划编制与实施评估的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自国土空间基础信息平台、自然资源调查监测数据、人口经济统计数据及遥感影像。日常处理的文档包括国土空间总体规划、详细规划、专项规划、规划实施评估报告、公众意见汇总材料。数据更新频率为年度，文档多包含空间坐标字段、约束指标数值、区域范围描述等内容，结构多为多源数据拼接的综合文档，单份文档的文本与空间数据体量通常较大。

## 这些特征在「模型接入与配置」这一环带来什么约束
年度更新的特性要求模型接入环节无需频繁重建索引，可采用周期性更新策略以降低资源消耗。但单份文档包含多源空间数据、结构化指标与非结构化文本，对模型的上下文承载能力有较高要求，需合理设置上下文长度参数。同时，规划类文档的审核需严格匹配合规性逻辑，不宜过度依赖随机生成内容，需平衡模型的创造性与严谨性。此外，部署环境多为政务云或专属内网，需适配专属的API接入端点与鉴权方式，确保数据传输与存储符合安全规范。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多源规划文档的长文本上下文需求，避免截断核心合规性内容 |
| `maxTokens` | 4000 token | 控制单轮回复长度，确保审核结论清晰完整，适配政务文档的严谨输出要求 |
| `quoteMaxToken` | 2000 token | 限制引用原文的长度，确保审核时能精准关联申报材料的具体条款 |
| `toolChoice` | none | 规划审核需严格基于现有文档内容，无需调用外部工具，避免引入无关信息 |
| `temperature` | 0.2–0.3 | 降低随机生成概率，确保审核结论的一致性与合规性，匹配政务审核的严谨需求 |
| `AIPROXY_API_ENDPOINT` | 按政务云专属API地址填写 | 适配政务云部署的网络环境与鉴权要求，确保数据传输安全 |

## 容易做错的三处
- 现象：Web界面中无法开启DeepSeek R1的思维链功能，配置后无生效反馈。原因：当前版本Web端未开放思维链开关的配置入口，需通过API参数手动配置。
- 现象：本地部署FastGPT后，无法选择本地部署的大模型或非默认列表的模型提供商。原因：未正确填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，导致无法对接自定义模型渠道。
- 现象：后台配置页面中索引模型的下拉选项为空，无法选择对应模型。原因：未正确配置国土空间基础信息平台的数据源同步，导致模型索引依赖的元数据缺失。

## 怎么确认配好了
- 测试调用自定义模型渠道，上传一份规划文档进行审核，检查是否能正常返回结果，无连接超时或鉴权失败报错。
- 查看模型回复的上下文引用内容，确认引用的原文长度未超出`quoteMaxToken`的配置范围，核心条款未被截断。
- 调整`temperature`参数至0.1与0.4，对比两次审核结论的差异，确认参数生效且差异符合预期的严谨性要求。
- 检查FastGPT后台的模型调用日志，确认API端点与鉴权信息与配置项一致，无异常报错记录。
