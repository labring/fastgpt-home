# 国库集中支付与报销审核的申报材料与案卷审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据来自国库集中支付系统、预算管理一体化系统、电子发票平台、合同管理系统，更新频率为每日。日常处理的文档包括支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，覆盖预算指标核对、票据合规校验、支付执行全链条的申报与案卷审核环节，数据字段围绕资金支付的合规性与执行进度展开。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据接入要求接口需适配四类外部系统的不同数据格式与鉴权规则，避免跨系统数据对齐错误。日更的更新频率要求接口调用频次匹配业务处理节奏，不宜过度频繁占用系统资源，也不能滞后导致审核延迟。多类型文档的差异化校验需求，要求接口支持按文档类型加载对应字段校验规则，确保不同材料的审核逻辑准确匹配。同时，资金支付相关的出错后果，要求接口需具备完整的异常捕获与反馈机制，保障审核结果的准确性。

## 配置怎么定
本配置基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | 采用 Bearer Token 格式，令牌有效期设为 3600 秒 | 匹配财政类系统通用的鉴权安全要求，避免频繁刷新令牌影响接口调用效率 |
| `variables` | 配置系统标识、文档类型映射变量，取值区间为 10–20 个 | 适配多系统对接与多类型文档的校验逻辑切换需求 |
| `responseData` | 按文档类型拆分响应字段，返回字段最大长度为 800–1200 字符 | 确保审核系统能准确解析不同文档的核心校验结果，避免字段溢出 |
| 外部系统调用频次 | 设为每5分钟1次，单日调用总量不超过288次 | 匹配业务日更的更新频率，避免超出外部系统的调用限额 |
| 字段校验规则配置 | 按实测标定 | 适配不同文档的差异化校验需求，确保审核逻辑准确 |
| 异常重试阈值 | 设为3次重试，重试间隔为60秒 | 应对临时网络波动或系统响应延迟，降低审核失败率 |

## 容易做错的三处
- 现象：接口返回`responseData`字段为空，审核流程触发支付退回。原因：未针对支付申请、发票等不同文档类型配置对应的响应字段映射规则，导致外部系统返回的格式无法被正确解析，进而无法完成合规校验。
- 现象：调用`Authorization`鉴权时返回401状态码，接口调用中断。原因：令牌有效期设置不符合财政系统的安全规范，或未配置自动刷新逻辑，导致鉴权凭证过期。
- 现象：单次接口调用超时，案卷审核任务失败。原因：未设置合理的单次调用时长限制，同时未配置异常重试机制，导致在外部系统负载较高时无法完成数据拉取。

## 怎么确认配好了
- 发起单文档类型的接口测试请求，确认`Authorization`鉴权可正常通过，`responseData`返回对应文档的校验结果。
- 查看`variables`配置项，确认已覆盖所有对接的外部系统与文档类型。
- 模拟批量调用场景，验证接口返回的字段数量与格式符合业务处理要求。
- 触发鉴权过期、网络波动等异常场景，确认异常重试逻辑按配置生效。
