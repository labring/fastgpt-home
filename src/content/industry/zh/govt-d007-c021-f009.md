# 国库集中支付与报销审核的申报材料与案卷审核：模型接入与配置
本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类涉及的核心数据来自国库集中支付系统、预算管理一体化系统、电子发票平台与合同管理系统，每日更新。日常处理的文档包括支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，各文档需匹配预算指标、经济分类、支付金额等字段，单笔数据关联完整的票据与审批链条，字段需严格对应财政规范的编码与单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据每日更新且来自多异构系统，要求模型接入环节需配置跨系统数据的格式对齐规则，避免字段不匹配导致的校验失败。单笔支付需关联发票、合同、验收单等完整链条，要求上下文配置需覆盖足够的关联文档长度，确保审核逻辑完整。文档类型多样且字段需严格匹配财政规范，要求配置需支持特定字段的精准提取与校验，同时需适配出错后的快速回退机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖单笔支付关联的多份文档总长度，确保完整审核链条的上下文支持 |
| `maxTokens` | 2000–3000 token | 满足单份审核报告的输出长度，避免截断关键校验结论 |
| `quoteMaxToken` | 1500 token | 保留足够的原文引用片段，用于合规性校验的溯源 |
| `toolChoice` | auto | 自动适配工具调用需求，支持多文档的关联校验 |
| `temperature` | 0.1–0.3 | 降低随机性，确保合规校验结果的一致性 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的代理地址填写 | 适配火山引擎豆包模型的调用链路 |
| `AIPROXY_API_TOKEN` | 按平台发放的密钥填写 | 完成模型调用的身份验证 |

## 容易做错的三处
- 模型调用返回`401 Unauthorized`状态码，原因是未正确填写`AIPROXY_API_TOKEN`或密钥权限不足，对应aiproxy渠道配置错误的常见问题。
- 工具调用过程中出现上下文溢出报错，原因是`maxContext`配置值低于单笔支付关联文档的总长度，未覆盖完整审核链条。
- 审核结果未提取到经济分类字段，原因是未配置对应字段的精准提取规则，或`quoteMaxToken`取值过小导致原文片段被截断。

## 怎么确认配好了
- 发起一笔模拟支付审核请求，检查返回结果中是否包含所有关联文档的核心字段，确认上下文配置是否覆盖完整链条。
- 调用模型测试接口，查看返回的令牌使用量是否低于`maxContext`配置值，确认上下文容量适配需求。
- 验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置，发起无参数测试请求，确认身份验证与链路连通正常。
- 调整`temperature`配置值，多次发起相同审核请求，确认结果一致性符合预期。
