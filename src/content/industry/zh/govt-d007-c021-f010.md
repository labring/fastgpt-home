# 国库集中支付与报销审核的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来自国库集中支付系统、预算管理一体化系统、电子发票平台与合同管理系统，更新频率为每日。日常处理的文档包含支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，单份文档通常包含预算指标编码、经济分类代码、金额、审批节点信息等字段，单位涉及人民币元、批次号、合同编号等，文档结构多为结构化表单与非结构化附件结合。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且每日更新，要求知识库支持多系统数据的增量同步，避免全量重建索引带来的延迟。日常文档包含结构化字段与非结构化附件，需同时覆盖结构化元数据与文本内容的检索。单笔审核关联多份文档，需精准召回与当前申报单匹配的合同、发票、验收记录，避免无关结果干扰审核。由于出错后果直接关联资金合规，检索结果的相关性需匹配审核要求，减少误召回引发的合规风险。

## 配置怎么定
本配置基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配国库集中支付审核的合规性要求，平衡召回精度与覆盖范围，按实测标定调整 |
| `limit` | `前 8–12 条` | 适配单笔审核关联的文档数量，避免上下文溢出影响模型理解 |
| `searchMode` | `vector` | 优先匹配语义关联的文档，结合结构化元数据补充检索，符合多来源数据的召回需求 |
| `usingReRank` | `开启` | 对召回结果重新排序，提升高合规性文档的展示优先级，适配审核场景的精准性要求 |
| `datasetSearchUsingExtensionQuery` | `开启` | 自动扩展检索关键词，覆盖经济分类、预算指标等专业术语的同义表述，适配财政业务的专业词汇 |
| `collectionIds` | `指定国库支付审核专属集合` | 隔离财政其他业务品类的知识库数据，避免无关文档干扰检索结果 |

## 容易做错的三处
- 现象：在线对话与API调用返回结果差异显著，API开启`stream: false`与`detail: true`时结果偏差较大。原因：未统一配置知识库检索的全局参数，不同调用链路的参数覆盖规则不一致。
- 现象：调用API时返回`invalid configuration parameter name "hnsw.max_scan_tuples"`报错。原因：误使用了非允许的配置参数名，导致检索引擎无法识别请求。
- 现象：升级FastGPT至4.9-4.10版本后，原索引知识库无法触发向量检索，搜索无结果。原因：旧版本索引格式与新版本向量检索引擎不兼容，需重建索引或更新索引配置。

## 怎么确认配好了
- 进入FastGPT知识库配置页面，核对`similarity`、`limit`等检索参数的取值与预设配置是否匹配。
- 发起一笔与日常审核场景匹配的检索请求，验证返回结果的相关性符合业务审核要求。
- 分别通过在线对话与API调用发起相同检索请求，确认两者返回的检索结果一致。
- 导入一份测试用的结构化文档，确认检索结果可正常关联对应字段与内容。
