# 土地使用权、矿业权与国有产权交易的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自全国公共资源交易平台、自然资源交易系统、产权交易所系统及国资监管系统，更新频率为每日。日常处理的审核相关文档包含出让公告、交易须知、竞买申请、保证金凭证、成交确认书、挂牌结果公告、产权转让说明书等，文档多包含权属编号、交易标的类型、保证金金额、成交确认时间等字段，结构多为制式化模板与自由文本结合的混合格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的数据要求索引支持增量同步，避免全量重建带来的资源消耗。混合格式的文档需要兼顾制式化字段与自由文本的切分合理性，防止将权属编号、交易标的类型等关键信息拆分至不同块中。多系统来源的数据格式存在差异，需在索引前统一标准化处理，确保向量嵌入的一致性。同时，审核场景需精准匹配权属与限制条件，向量模型需对公共资源交易相关专业术语具备稳定的语义识别能力，多源字段差异也可能导致嵌入向量分布不均，需提前完成标准化适配。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配制式文档与自由文本的混合结构，避免关键字段被拆分 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，确保权属信息的语义连贯性 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关材料，适配审核场景的精准性要求 |
| 单次召回上限 | 前 10 条 | 控制检索结果数量，避免冗余信息干扰审核判断 |
| `maxToken` | 4096 token | 适配主流开源向量模型的输入上限，保证嵌入内容的完整性 |
| `defaultToken` | 按实测标定 | 适配不同场景下的默认嵌入参数，兼容多来源数据格式 |

## 容易做错的三处
- 现象：不同环境的向量模型切换后，嵌入结果出现偏差或无法匹配目标权属材料。原因：未统一向量模型的嵌入维度与预处理逻辑，导致跨模型的向量空间不一致。
- 现象：单个大文件长时间处于索引中，界面进度无更新。原因：未设置合理的分块阈值，超大分块导致嵌入计算超时，或文件格式未被正确解析。
- 现象：检索结果未优先返回指定知识库的内容。原因：未配置知识库优先级规则，或规则未与检索逻辑绑定，导致结果随机返回。

## 怎么确认配好了
- 上传一份制式化的出让公告文档，检查分块结果是否保留了完整的权属编号与交易标的信息。
- 切换不同向量模型进行嵌入测试，验证嵌入结果的维度一致性与语义匹配度。
- 配置知识库优先级规则后，发起包含两个知识库关联内容的查询，确认优先知识库的内容被优先召回。
- 提交一份超大文件，检查索引进度是否在合理时间内完成，无卡顿或超时报错。
