# 土地使用权、矿业权与国有产权交易的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
通常服务主体为自然资源部门、国资监管机构、产权交易机构、公共资源交易中心。日常处理的文档包括出让公告、交易须知、竞买申请、保证金凭证、成交确认书、挂牌结果公告、产权转让说明书。数据来源为全国公共资源交易平台、自然资源交易系统、产权交易所系统、国资监管系统，更新频率为每日。文档通常包含权属编号、交易标的类型、保证金金额、竞买资格条件等字段，单位涵盖平方米、万元等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散且每日更新，要求多轮对话需支持实时调用多源知识库，避免使用离线缓存的过时材料。文档结构多样且部分材料篇幅较长，需在对话中精准匹配跨文档的关联字段，比如将竞买申请与保证金凭证绑定校验。字段包含权属、限制条件等关键信息，提示词需明确要求返回完整字段，不能遗漏影响审核的内容。同时，审核出错后果严重，要求多轮对话的上下文记忆需准确关联历史审核意见，避免出现逻辑冲突。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配该品类单份文档的段落平均长度，避免截断权属、限制条件等关键信息 |
| 重叠长度 | 150–200 字符 | 保证跨块的保证金金额、竞买资格等关键字段不被拆分丢失 |
| 单次搜索上限 | 前 6 条 | 覆盖该品类常见的3-5份关联申报材料，避免遗漏关键凭证 |
| `variables` | 配置权属编号、标的类型参数 | 为多轮对话提供固定检索条件，精准召回对应交易标的的材料 |
| 最大上下文 | 12000 token | 适配多轮对话中积累的申报材料摘要、审核意见等完整上下文 |
| `chatId` | 绑定对话会话标识 | 实现跨轮次的上下文记忆，保证审核意见可被后续对话调用 |

本页面的配置说明适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：对话中触发知识库检索时返回422状态码；原因：未在`variables`中配置当前交易标的的权属编号参数，导致检索条件缺失，无法匹配对应文档。
- 现象：多轮对话中无法关联跨系统的当日更新材料；原因：未配置实时数据源触发规则，仅调用了单一本地缓存的材料，未同步最新的挂牌结果公告。
- 现象：长文档分块后出现权属字段截断；原因：分块长度设置过小，未覆盖完整的标的限制条件段落，导致审核时遗漏关键约束。

## 怎么确认配好了
- 上传单份产权转让说明书，验证分块后权属编号、交易标的类型等关键字段未被截断。
- 发起包含竞买申请、保证金凭证的多轮对话，检查检索结果包含两份关联材料。
- 测试`messages`参数的上下文传递，确认历史审核意见能被后续对话正确调用。
- 调整单次搜索上限参数，验证检索召回的材料条数随配置变化。
