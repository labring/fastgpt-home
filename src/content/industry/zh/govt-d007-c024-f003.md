# 学生资助与奖补审核的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源包括全国学生资助管理信息系统、学校学籍系统、民政低保特困数据、财政支付系统，更新周期为学期。日常处理的文档包含家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单、公示材料，核心字段涵盖申请人身份信息、家庭经济状况证明、学籍状态、资助金额与发放账户信息，数据结构以结构化表单为主，伴随少量扫描件类非结构化材料。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多系统交叉核验的数据源要求，多轮对话需依次调取学籍、民政、财政等不同数据源的字段完成交叉核对，规避单源数据偏差。学期级的更新周期，要求对话流程适配批量批次处理逻辑，适配不同年级、不同资助批次的审核场景。结构化表单与非结构化扫描件并存的文档结构，提示词需区分字段规则校验与材料内容解读的不同处理分支。核心字段的准确性直接影响资助发放结果，多轮对话需设置校验环节，对缺失或异常字段触发补充询问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | `8000–12000 字符` | 本品类审核需保留多份表单、交叉数据源字段与多轮对话记录，足够的上下文长度可避免关键校验信息丢失，适配 FastGPT v4.17.0 版本的上下文处理规则 |
| `messages` 历史上下文整理 | 自动截取前 10 轮有效对话 | 学期批次审核的对话流程多为分段校验，过多历史会干扰当前批次的字段校验逻辑，截取有效轮次可提升对话效率 |
| `variables` 变量配置 | 预设家庭经济状况、学籍状态、发放账户三个核心变量 | 本品类审核需固定校验三类核心字段，预设变量可简化提示词编写，便于在多轮对话中直接调用校验逻辑 |
| 图片解析触发规则 | 仅对家庭经济困难认定表扫描件触发 | 本品类非结构化材料以困难认定扫描件为主，避免误触发解析其他文档，减少无效计算资源消耗 |
| `chatId` 会话隔离配置 | 按学校+批次维度生成独立会话 | 学期批次审核需按不同学校、不同资助批次隔离数据，避免不同批次的会话上下文互相混淆 |

## 容易做错的三处
- 上传家庭经济困难认定表扫描件后，返回结果未包含图片解析内容。未配置图片解析触发规则，或触发规则未覆盖该类文档。
- 调大上下文长度后，对话仍无法保留完整审核流程的上下文。未按学校+批次维度配置`chatId`会话隔离，不同批次的会话上下文被覆盖，且未过滤无关搜索知识干扰。
- 对话中调用财政数据时返回超时错误。未拆分多系统调取步骤，单次对话请求包含过多跨系统数据调用，超出处理阈值。

## 怎么确认配好了
- 上传家庭经济困难认定表扫描件，触发对话后检查返回结果是否包含图片内容解析信息。
- 新建两个不同学校的审核会话，分别输入同一份申请信息，检查两个会话的上下文记录不会互相干扰。
- 调整最大上下文长度后，查看对话历史窗口是否保留完整的多轮校验流程记录。
- 在对话中调用预设的`variables`变量，检查提示词是否能正确引用核心字段完成校验。
