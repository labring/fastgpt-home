# 学生资助与奖补审核的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
这个品类的日常文档包含家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单、公示材料，数据来源为全国学生资助管理信息系统、学校学籍系统、民政低保特困数据、财政支付系统。数据更新频率为学期周期，文档结构多为标准化表单、表格清单与公示文本，字段包含学生身份标识、家庭经济状况证明、学籍状态、资助申请金额、银行卡信息等，无额外自定义统计数值。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据的接入需要校验不同系统间的字段一致性，因此配置需支持跨数据源的字段比对逻辑；学期级的更新频率决定知识库无需高频刷新，可按学期周期完成全量同步；多类型文档的混合输入要求配置适配表单、表格与文本的不同分块规则；审核结果的严肃性要求模型输出具备高一致性，需限制生成的随机性。同时，长文档的案卷审核需确保关键信息不被截断，避免影响核验准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配学生资助申报材料集合的总token长度，避免截断跨表单的关键核验字段 |
| `maxTokens` | 2000–3000 token | 满足审核结论、核验说明与案卷溯源内容的输出长度需求 |
| `quoteMaxToken` | 1500 字符 | 保留申报材料中核心核验段落的完整内容，支持案卷审核的溯源校验 |
| `toolChoice` | auto | 自动触发工具调用，适配多数据源的身份、经济状况与学籍状态校验 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保审核结论的一致性，避免出现矛盾的核验结果 |
| `AIPROXY_API_ENDPOINT` | 按私有化部署环境填写 | 适配本地部署的大模型与重排模型调用路径 |

## 容易做错的三处
- 现象：调用模型后出现超时报错，日志显示504或408状态码。原因：未针对多源数据的上下文拼接配置合理的`maxContext`取值，导致上下文过长触发超时限制。
- 现象：重排模型部署测试通过，但每次检索后返回结果重排字段为false。原因：未正确关联重排模型的部署端点，或未在FastGPT v4.17.0的重排配置中开启对应模型的触发开关。
- 现象：知识库检索内容过长后，重排模型未被调用，返回结果未进行排序。原因：未设置长文档的分块阈值，导致检索内容超出重排模型的支持长度，未触发重排逻辑。

## 怎么确认配好了
- 上传单份家庭经济困难认定表，提交审核任务，验证模型响应时间符合业务预期。
- 配置Qwen3-Reranker-8B后，提交批量检索任务，查看返回结果中是否包含重排后的排序字段。
- 上传超过预设长度的申报材料合集，验证是否触发重排模型的调用逻辑。
- 调整`temperature`参数，提交多份同类审核任务，查看审核结论的一致性变化，确认参数生效。
