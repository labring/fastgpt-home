# 安全生产隐患排查治理的申报材料与案卷审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据来源为安全生产监管系统、企业隐患自查系统、执法检查记录及事故统计系统，更新频率为每日。日常处理的文档包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，字段包含隐患编号、整改责任主体、整改期限、复查结果、督办等级等，需关联对应监管系统的唯一标识，无固定统一的单位要求。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的数据多来自多套业务系统且每日更新，要求接口需支持增量拉取与多源数据整合；日常处理的文档类型多样且字段需关联监管系统唯一标识，要求接口需兼容不同文档结构的参数传递；业务出错后果严重，要求接口需具备明确的错误返回与重试机制；整改期限、督办等级等核心字段需精准匹配，要求接口请求需携带完整业务字段，避免参数缺失导致审核流程阻断。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的接口设置逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {{secret_key}}` | 符合HTTP接口标准的身份认证方式，适配多业务系统的权限校验要求 |
| `variables` | 预设隐患编号、整改责任主体、整改期限等业务字段 | 该品类文档需关联监管系统唯一标识与核心业务字段，确保参数传递完整 |
| `responseData` | 返回`code`、`message`、`data`三级结构 | 便于快速识别接口调用结果与错误原因，适配业务出错后果严重的校验需求 |
| 接口超时时间 | 600秒 | 该品类部分文档需整合多系统数据，拉取整合需较长处理时间，避免超时中断流程 |
| 单次请求文档数 | 前50条 | 每日更新的文档量需合理控制单次接口负载，避免外部系统过载 |
| 单次拉取数据量 | 800–1200 字符 | 适配该品类单条文档的平均长度，平衡接口传输效率与数据完整性 |

## 容易做错的三处
- 接口调用返回`Request failed with status code 400`，原因是未携带该品类要求的核心业务字段（如隐患编号、整改责任主体），或字段格式不符合外部监管系统的校验规则。
- 接口代理请求出现持续卡顿，原因是单次请求提交的文档数量超出外部系统的负载上限，未遵循配置的单次请求文档数限制。
- 接口文件上传至最后一步时出现异常，原因是未正确配置`Authorization`的认证参数，导致身份校验失败无法完成上传流程。

## 怎么确认配好了
- 调用测试接口，检查`Authorization`参数是否能通过外部系统的身份校验，返回正常的认证结果。
- 传入预设的业务字段，验证`variables`参数是否能正确传递至外部系统，无字段缺失或格式错误。
- 触发接口调用后，检查`responseData`是否能正确解析返回的三级结构，快速定位调用结果。
- 模拟每日更新的文档量，按配置的单次请求文档数提交，确认外部系统无过载报错。
