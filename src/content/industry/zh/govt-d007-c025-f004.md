# 安全生产隐患排查治理的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
这个品类的数据主要来自安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常处理的文档包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，单条数据通常包含隐患标识、排查主体、排查时间、整改要求、责任主体、整改期限、复查状态等字段，无统一固定单位，随文档类型和业务场景变化。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且类型多样，要求工作流配置多类数据源接入节点与文档解析规则，适配不同系统和文档格式；每日更新的频率要求工作流触发机制适配日级任务节奏，避免干扰日常业务；隐患整改的闭环流程涉及多环节流转，需要通过`variables`传递整改责任人、复查结果等关键信息，确保各节点间数据连贯；不同文档的字段差异要求工作流设置条件分支，根据输入文档类型动态调整处理逻辑，避免数据匹配错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发节点 | 每日凌晨2:00执行 | 适配业务数据每日更新的节奏，避开业务高峰时段 |
| 多数据源配置 | 按实测标定 | 适配安全生产监管系统、企业自查系统等多类数据来源 |
| 条件分支节点 | 按文档类型分支 | 区分隐患排查清单、整改通知书等不同格式的文档 |
| 变量传递配置 | 使用`variables`存储关键信息 | 确保工作流各节点间传递整改责任人、复查结果等数据 |
| RAG知识库调用 | 匹配重大事故隐患判定标准 | 完成隐患等级的自动判定 |
| 数据库连接插件 | 按实测标定 | 适配隐患治理台账的存储与查询需求 |

## 容易做错的三处
- 工作流运行时RAG知识库调用结果条数不符预期，原因是未根据重大事故隐患判定标准的关键词配置检索规则，召回了大量无关内容。
- 配置分享链接鉴权时无法找到对应设置项，原因是未在FastGPT v4.17.0的工作流分享面板中展开高级配置菜单，默认隐藏了鉴权相关选项。
- 数据库连接插件执行耗时显著增加，原因是未针对每日更新的隐患数据调整查询范围，导致每次执行全量数据查询。

## 怎么确认配好了
- 手动触发工作流一次，查看各节点的日志输出，确认`variables`中存储的隐患关键信息传递正确。
- 上传不同类型的测试文档（如整改通知书、复查记录），验证条件分支节点是否正确拆分处理流程。
- 查看定时触发节点的执行记录，确认每日凌晨2:00是否按计划启动工作流。
- 测试RAG知识库调用环节，确认返回的内容与重大事故隐患判定标准相关。
