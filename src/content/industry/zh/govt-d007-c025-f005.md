# 安全生产隐患排查治理的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源为安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常文档包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，核心字段涵盖隐患类别、等级、整改责任主体、整改期限、复查结果等，单份文档内容长度差异较大，从数百字符到数千字符不等。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源每日更新的数据要求工具调用需支持多接口批量拉取与增量同步，避免重复处理旧数据。文档长度差异大的特征，要求工具调用的上下文适配逻辑可灵活调整，适配不同长度的案卷材料。核心固定字段的需求，要求工具调用的参数配置需精准匹配隐患等级、整改期限等字段的提取规则，避免信息错位。同时，因出错后果涉及重大事故与行政处罚，工具调用的失败重试与异常捕获机制需具备高可靠性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配不同长度的案卷材料，自动选择合适的工具调用逻辑 |
| 工具调用超时时间 | `600 秒` | 单份案卷材料处理需覆盖多源数据拉取与字段提取，600秒可覆盖多数场景的处理时长 |
| 批量执行节点循环上限 | `前 1000 条` | 每日更新的隐患数据量通常在千条以内，限制循环上限可避免资源过载 |
| `functionCall` | `强制匹配核心字段` | 需精准提取隐患等级、整改期限等核心字段，强制匹配可提升信息提取准确率 |
| 工具调用结果过滤 | `隐藏 input 和 response 字段` | 案卷审核场景无需暴露工具调用的内部参数，简化输出内容 |
| 失败重试次数 | `2–3 次` | 多源接口调用可能出现临时网络波动，有限重试可降低单次调用失败的影响 |

本配置基于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：配置安全生产监管系统数据库连接插件后，调用时返回连接超时或权限不足报错。原因：未配置对应系统的访问白名单，或超时时间设置过短，未适配多源数据拉取的时长要求。
- 现象：工具调用输出中保留了工具的input和response字段，不符合案卷审核的输出要求。原因：未开启工具调用结果过滤配置，或过滤规则未正确匹配需要隐藏的字段。
- 现象：通过API调用工作流时，批量执行节点未完成全部循环，或对话日志中的运行数据为空。原因：批量执行节点的循环上限配置未匹配实际数据量，或API调用的上下文参数未正确传递工具调用的返回结果。

## 怎么确认配好了
- 发起单份案卷材料的工具调用测试，核对输出内容是否包含所需的隐患字段，无多余的工具内部参数。
- 配置批量执行节点，导入少量测试数据，通过在线调试确认循环执行完整，再调整循环上限匹配实际数据量。
- 调用数据库连接插件，验证是否能正常拉取当日更新的隐患数据，无连接报错。
- 发起API调用，核对对话日志中是否包含工具调用的运行数据，无空值情况。
