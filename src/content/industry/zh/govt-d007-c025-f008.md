# 安全生产隐患排查治理的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
数据来自安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为日。日常文档包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，多为结构化表格与半结构化文本混合的格式，字段包含隐患编号、排查时间、整改责任人、整改期限、复查结果等，无统一固定命名规则，部分文档存在手写扫描件或跨页表格。

## 这些特征在「文档解析与分块」这一环带来什么约束
多源异构的文档格式要求解析适配混合结构，跨页表格与半结构化文本需保留字段关联关系；日更频率要求解析流程高效，避免单文件处理耗时过长；字段分散在不同文档中，分块需保留上下文关联以确保隐患整改全流程追踪的字段完整性；扫描件占比存在一定比例，需适配OCR解析需求；不同文档的字段命名不统一，需避免分块破坏字段语义关联。

## 配置怎么定
本文适配FastGPT v4.17.0版本，配置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 匹配隐患排查清单、整改通知书等文档的单条隐患字段组长度，保留完整的隐患信息上下文 |
| `chunkSplitter` | 按段落+表格拆分 | 适配混合了文本与表格的隐患文档结构，避免拆分破坏表格内的整改责任人、整改期限等字段关联 |
| `customPdfParse` | 开启表格识别+OCR fallback | 覆盖扫描版整改通知书、跨页重大隐患挂牌督办单的解析需求，保留表格字段完整性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配单批次多文件的日更数据处理节奏，避免因文件过大或OCR耗时过长导致任务失败 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（清单/台账/通知书）调整分块参数，满足隐患整改全流程追踪的字段关联需求 |

## 容易做错的三处
- 现象：OCR解析后中文文本出现乱码，核心字段为空。原因：未配置适配中文的OCR fallback参数，或未开启多语言识别模式。
- 现象：单篇PDF文件解析后无法精准匹配提问的隐患条目，返回结果零散。原因：`chunkSize`配置过大或过小，未保留单条隐患的完整上下文，或`chunkSplitter`未按段落拆分导致语义断裂。
- 现象：单篇PDF文件解析后分块丢失表格内容，知识库中显示表格但输出结果不显示表格。原因：未开启`customPdfParse`的表格识别开关，或`chunkSplitter`配置为仅按字符拆分，未保留表格结构。

## 怎么确认配好了
- 上传一份典型的隐患整改通知书扫描件，检查解析结果是否保留了整改责任人、整改期限等核心字段，无乱码或缺失。
- 导入一批同类型日更文档，查看解析任务的耗时是否符合预期，无批量超时报错。
- 对解析后的知识库发起“查询某批次隐患的整改情况”类提问，确认返回结果包含完整的字段关联信息，无分块断裂导致的语义缺失。
- 检查`customPdfParse`的配置状态，确认表格识别与OCR fallback均已开启，适配混合格式文档。
