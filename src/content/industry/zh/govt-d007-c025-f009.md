# 安全生产隐患排查治理的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常处理的文档包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，文档字段包含隐患编号、排查时间、整改责任人、整改期限、复查结果等核心信息，不同系统导出的文档格式存在细微差异，需适配多源异构的案卷与申报材料。

## 这些特征在「模型接入与配置」这一环带来什么约束
本页面基于FastGPT v4.17.0版本的配置逻辑进行说明。多源数据来源要求配置项需适配不同业务系统的接入规则，避免因地址或密钥不匹配导致调用失败。每日更新的海量案卷数据，要求模型调用的上下文与token参数需匹配文档长度，防止解析超时或截断。不同文档的格式差异，要求配置需具备一定的灵活性，同时保障隐患判定、整改跟踪等核心环节的结果稳定性。此外，审核环节的出错后果直接关联安全生产责任，需严格控制参数取值以避免判定偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `AIPROXY_API_ENDPOINT` | 对应业务系统指定的API接入地址，如监管系统专属接入域名 | 保障多源案卷数据的正常接入，避免404类调用错误 |
| `AIPROXY_API_TOKEN` | 使用业务系统分配的专属访问密钥 | 保障数据访问权限，防止未授权调用 |
| `maxContext` | 8000–12000 token | 适配隐患治理台账、重大隐患挂牌督办单等长文档的上下文需求，避免内容截断 |
| `maxTokens` | 2000–3000 token | 控制单轮审核的输出长度，确保案卷字段提取与判定结果完整呈现 |
| `temperature` | 0.2–0.4 | 保障隐患判定、整改期限核对等环节的结果稳定性，避免随机偏差 |
| `quoteMaxToken` | 1500–2000 token | 限制引用文档的最大长度，确保上下文窗口合理分配 |

## 容易做错的三处
- 现象：调用模型返回404 page not found，原因：未正确配置`AIPROXY_API_ENDPOINT`为对应业务系统的接入地址，或`AIPROXY_API_TOKEN`未绑定有效访问权限。
- 现象：模型识别隐患判定标准的结果不灵活，原因：`temperature`取值过高，导致判定逻辑出现随机偏差，未匹配审核场景的稳定性需求。
- 现象：上传案卷文件后解析请求失败，原因：未合理设置`maxContext`适配长文档的内容长度，超出模型上下文限制，或系统资源未匹配日更数据的处理负载。

## 怎么确认配好了
- 提交单份标准整改通知书样本，核对模型输出的整改要求与文档内容匹配度。
- 查看API调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的请求参数无格式错误。
- 发起批量测试，验证每日更新的案卷数据调用成功率符合业务预期。
- 调整`temperature`取值，验证结果稳定性是否符合安全生产审核的要求。
