# 工程建设项目审批的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
本品类数据来源于工程建设项目审批管理系统、施工图审查系统、企业资质库、信用平台，更新频率为每日。日常处理的文档包括施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表，文档结构多包含项目编号、参建单位信息、审批节点状态、材料校验字段，无统一固定格式，部分字段需跨系统关联匹配。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需配置跨系统接口调用节点，每日更新要求工作流触发周期需匹配数据刷新节奏。多类型文档无统一格式，要求工作流需包含格式校验分支节点，适配不同材料的字段提取规则。跨系统关联匹配的需求，要求工作流中需设置变量联动环节，同步跨系统获取的参建单位资质信息。出错后果关联无证施工等问题，要求工作流需配置异常告警节点，拦截不符合要求的申报材料流转。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 按实测标定 | 适配不同审批环节的变量传递需求，覆盖参建单位资质、审批节点状态等业务字段 |
| `nodeId` | 按业务环节命名 | 唯一标识各工作流节点，便于排查异常节点的日志 |
| 分块长度 | 800–1200 字符 | 适配工程类文档的段落长度，避免拆分破坏审批材料的语义完整性 |
| 节点超时时间 | 600 秒 | 匹配跨系统接口的平均响应时长，避免因系统延迟触发工作流中断 |
| 单次召回条数 | 前5条 | 覆盖工程审批文档的核心内容，保障字段提取的准确性 |
| 文件预览关联配置 | 关联原文件存储路径 | 支持直接查看导入知识库切片前的原文档，满足申报材料溯源需求 |
| 请求重试次数 | 3 次 | 应对跨系统接口的临时波动，保障工作流稳定执行 |

## 容易做错的三处
- 工作流测试时文件预览节点返回空白。原因是未配置文件预览关联配置，未关联导入知识库切片前的原文件存储路径。
- 跨系统接口调用节点返回超时报错。原因是节点超时时间设置过短，未匹配跨系统接口的实际响应时长。
- http请求节点调用本地脚本接口无返回结果。原因是未正确配置`variables`参数，未将本地文件路径作为变量传递到脚本接口，导致无法获取base64编码结果。

## 怎么确认配好了
- 触发一次完整工作流，检查各节点的变量传递日志，确认跨系统获取的参建单位资质、审批节点状态等字段已正确映射。
- 上传一份标准施工许可申请文档，触发格式校验节点，确认分支逻辑可根据文档类型自动匹配对应处理规则。
- 点击工作流中的文件预览节点，确认可直接打开导入知识库切片前的原文档。
- 模拟跨系统接口延迟场景，确认工作流在设定的超时时间内未触发中断，且重试机制正常生效。
