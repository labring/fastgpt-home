# 工程建设项目审批的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
本品类数据来自工程建设项目审批管理系统、施工图审查系统、企业资质库及信用平台，更新频率为每日。日常处理的文档包含施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表等，文档多为结构化表单与合规性文件混合，包含参建单位资质、人员信息、审批节点等字段，部分文件附带盖章扫描件与电子签章，无统一固定格式。

## 这些特征在「文档解析与分块」这一环带来什么约束
混合结构化表单与非结构化合规文件的特征，要求分块需兼顾字段精准提取与段落逻辑保留，避免拆分破坏审批材料的关联关系。每日更新的数据量要求解析流程具备稳定的批量处理能力，减少异常中断。参建单位资质、人员信息等核心字段的精准识别需求，限制了分块的最小粒度，防止关键信息被割裂。大体积的施工图审查文件易出现内容偏移，对上传与解析的稳定性提出更高要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配工程审批文件中表单段落与合规说明的长度，避免拆分关键审批节点描述 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配审批文件多标题、多段落的结构，保留材料的逻辑层级 |
| `customPdfParse` | 开启 | 适配带电子签章、扫描件的施工图审查文件，提升非标准PDF的解析准确率 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 覆盖全套竣工验收备案文件的体积需求，适配大文件上传场景 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 为大体积审批文件预留充足的解析时间，避免因超时导致解析失败 |

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 容易做错的三处
- 上传大体积PDF文件至知识库时，进度到90%出现“偏移量超出范围”报错。原因是未调整`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`配置，文件体积超出限制或解析时间不足。
- 通过创建文件集合API上传与平台直接上传的同一份文件，分段结果不一致。原因是API调用未同步`chunkSettingMode`与分块参数配置，导致分块规则不统一。
- 配置自定义URL的文档解析工具后，无返回数据。原因是未验证自定义工具的接口返回格式与FastGPT要求的解析结果结构匹配，或接口未正确返回文档文本内容。

## 怎么确认配好了
- 上传单份100MB以上的竣工验收备案文件，验证解析进度是否完成且无报错，调整`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`至符合文件体积的取值。
- 提取施工许可申请文件中的参建单位字段，核对分块结果是否保留字段完整，调整`chunkSize`与`chunkSplitter`配置至匹配文档结构。
- 对比API上传与平台直接上传的同一份文件，确认分段结果一致，同步`chunkSettingMode`与分块参数配置。
- 调用自定义URL解析工具，验证接口返回的文本内容与原始文档一致，确认配置的自定义工具正常工作。
