# 工程建设项目审批的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类的核心数据来自工程建设项目审批管理系统、施工图审查系统、企业资质库、信用平台，更新频率为每日同步。日常处理的文档包括施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表，每份文档包含项目标识、参建单位资质编号、审批节点状态、材料提交时间等固定字段，部分材料附带图纸类附件。本页面基于FastGPT v4.17.0编写。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据的整合要求模型上下文长度需适配多份材料的拼接总量，避免关键审批信息被截断；固定字段的标准化校验需模型输出格式保持稳定，避免随机性导致的校验偏差；政务系统的数据安全要求需严格管控API访问权限，防止项目、单位等敏感信息泄露；每日更新的材料与资质数据需确保模型调用的时效性，避免使用过期的校验依据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 需整合多份审批材料的完整内容，避免截断项目名称、参建单位资质等关键字段 |
| `maxTokens` | `2000–3000 token` | 单份审核请求的输出长度需覆盖材料合规性校验结果、审批建议等全部内容 |
| `temperature` | `0.1–0.3` | 审核场景需稳定一致的输出格式，避免随机性导致的校验逻辑偏差 |
| `AIPROXY_API_ENDPOINT` | 内部私有部署的OneAPI接入地址 | 适配政务系统的内网访问规则，保障数据传输安全 |
| `AIPROXY_API_TOKEN` | 按系统权限生成的专属令牌 | 限制非授权访问，符合政务数据安全管理要求 |
| `vision` | 启用 | 可校验施工图审查合格书的签章、图纸合规性等视觉类内容 |

## 容易做错的三处
- 现象：Embedding模型调用OneAPI时返回401未授权或连接超时错误。原因：未正确配置`AIPROXY_API_TOKEN`，或接入地址未指向内部OneAPI服务的有效端口。
- 现象：模型输出的审核结果格式混乱，未按要求列出材料校验项。原因：`temperature`参数设置过高，导致输出随机性超出业务预期。
- 现象：启用`vision`功能后，模型无法正常解析施工图图片。原因：未配置适配的视觉分析模型，或未在接入时正确启用视觉处理参数。

## 怎么确认配好了
- 提交一份测试用的施工许可申请材料，检查模型返回的校验结果是否包含所有必填字段的核对记录。
- 查看API调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的请求均返回200状态码，无报错信息。
- 调整`temperature`参数为0.1和0.3，对比两次输出的格式差异，确认输出稳定性符合业务要求。
- 上传一张测试用的施工图图片，检查模型是否能识别图片中的签章信息，验证`vision`功能正常启用。
