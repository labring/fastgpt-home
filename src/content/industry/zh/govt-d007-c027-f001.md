# 工程建设项目招投标的申报材料与案卷审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据来自全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常处理的文档包含招标公告、资格预审文件、投标文件、评标报告、中标候选人公示等，其中投标文件需核验资质、业绩、工程量清单，评标报告需核对专家打分记录与签到信息，数据字段覆盖项目标段、资质条件、评标细则等核心业务项。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
数据来源分散导致接口需兼容多平台的返回格式，需配置统一的请求头适配不同数据源的鉴权规则。每日更新的频率要求接口调度需匹配业务日更节奏，避免重复拉取或遗漏数据。多类型业务文档的处理需求，要求接口请求参数需支持按文档类型切换校验逻辑。同时，该环节出错会导致中标结果暂停、项目延误，接口需配置明确的超时与重试机制，保障数据拉取与校验的稳定性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本梳理。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带业务系统的鉴权令牌 | 适配多数据源的鉴权要求，保障接口调用合法性 |
| `variables` | 配置项目标段、资质条件等业务变量 | 实现不同招投标项目的个性化校验逻辑 |
| `responseData` | 按业务文档类型过滤返回字段 | 仅保留申报材料与案卷审核所需的核心数据 |
| 接口超时时间 | 600 秒 | 匹配业务数据拉取的最长耗时，避免因网络波动中断流程 |
| 重试次数 | 3 次 | 应对临时网络异常，保障数据拉取成功率 |
| 请求频率限制 | 每 10 分钟 100 次 | 符合公共资源交易平台的接口调用频次要求 |

## 容易做错的三处
- 调用接口后`responseData`中未包含知识库关联字段，现象为无法追溯本次审核引用的案卷知识库，原因是未在`variables`中配置知识库绑定参数，未建立接口与对应案卷知识库的关联。
- 接口频繁触发限流报错，现象为返回429状态码，原因是未按公共资源交易平台的频次限制配置请求频率，超出平台允许的调用上限。
- 接口拉取的文档数据不完整，现象为部分标段的投标文件未被拉取，原因是未按业务文档类型配置`variables`中的过滤规则，导致部分标段的申报材料未被识别。

## 怎么确认配好了
- 查看接口返回的`responseData`，确认包含招投标项目的核心业务字段，核对字段与配置的过滤规则一致。
- 模拟临时网络中断或延迟，验证接口在超时后触发重试机制，重试次数符合配置要求。
- 发送携带错误鉴权令牌的请求，确认接口返回401状态码，验证`Authorization`参数的校验逻辑生效。
- 对比拉取的文档与公共资源交易平台的日更数据，确认更新频率符合业务调度要求。
