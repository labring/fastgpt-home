# 工程建设项目招投标的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自全国公共资源交易平台、地方交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，数据字段涉及资质要求、业绩证明、工程量清单、施工周期等，形成结构化与非结构化混合的文档集合，围绕工程项目建设与招标投标法体系形成专属数据链路。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类每日更新的数据特征要求索引支持增量同步，避免全量重建占用过多系统资源。多类招投标全流程文档结构差异显著，需针对招标公告、投标文件等不同文档类型适配差异化分块规则。涉及资质、业绩、工程量清单等专业工程术语，向量模型需适配领域专属语义表达。数据关联标段与评标环节，索引需支持按标段维度分组召回，确保审核时的上下文匹配精准。

## 配置怎么定
以下配置均基于 FastGPT v4.17.0 版本的界面与参数逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配本品类招标文件、投标文件的常规段落长度，避免专业语义断裂 |
| 重叠长度 | 100–150 字符 | 弥补分块导致的上下文割裂，确保资质、业绩等跨块术语语义连贯 |
| `maxToken` | 8192 token | 匹配多数开源嵌入模型的上下文窗口上限，适配评标报告等长文档 |
| `defaultToken` | 按实测标定 | 适配增量同步的批次规模，匹配每日更新的本品类数据量 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的申报材料，聚焦资质、工程量清单等核心审核字段 |
| 单次搜索上限 | 前 10 条 | 控制召回结果规模，适配案卷审核的快速核对需求 |

## 容易做错的三处
- 现象：索引同步完成后，后台显示无对应业务数据。原因：未配置按每日更新频率的增量同步规则，导致全量同步中断或增量批次未正确关联本品类的数据源。
- 现象：拆分申报材料时，最后一个分块无法生成有效向量并进入索引。原因：分块长度设置超出模型支持的`maxToken`上限，或最后一个分块的有效字符数不足预设阈值。
- 现象：搜索申报材料时，召回结果与查询问题的语义匹配度偏低。原因：未适配工程建设领域的语义特征，或相似度阈值设置不合理，导致无关文档被召回。

## 怎么确认配好了
- 查看数据源同步日志，确认每日增量同步任务正常触发，无报错记录。
- 随机抽取一份本品类的招标文件，手动执行分块测试，确认分块长度符合预设规则且无语义断裂。
- 输入一条资质审核相关的查询，检查召回结果是否包含对应标段的资质证明文档。
- 查看索引管理界面，确认本品类的文档数量与实际数据源的更新量匹配。
