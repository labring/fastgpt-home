# 工程建设项目招投标的申报材料与案卷审核：多轮对话与提示词

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
数据来源为全国公共资源交易平台、地方交易平台、工程审批系统、招标投标监管系统，更新频率为每日。日常处理的文档包括招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，文档包含标段编号、资质要求、业绩要求、工程量清单、施工周期等字段，对应单位包含万元、天、平方米等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的数据源要求对话需实时拉取最新文档内容，避免使用过期数据。多类文档的字段差异显著，需在多轮对话中明确当前处理的文档类型，防止混淆审核标准。不同来源的文档格式存在差异，提示词需适配不同文档的结构特征。项目出错后果严重，多轮对话的每一轮回复都需经过严格校验，确保符合招标投标相关规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 按单轮对话上下文不超过10000字符 | 适配招投标文档的单份核心内容长度 |
| `chatId` | 绑定项目标段唯一标识 | 区分不同招投标项目的独立对话上下文 |
| `variables` | 预设资质要求、工程量清单字段 | 快速调用对应品类的结构化数据 |
| 最大上下文长度 | 8000–12000 token | 覆盖单份招标文件的完整审核范围 |
| 单次匹配结果上限 | 前6条 | 避免冗余信息干扰审核判断 |
| 流式输出间隔 | 1–2秒/次 | 适配前端展示的流畅度要求 |

## 容易做错的三处
- 现象：流式输出返回的链接仅覆盖当前页面，无法跳转至新页面。原因：未针对招投标文档中的链接类型配置专属的上下文跳转规则。
- 现象：对话日志详情内容与实际生成的回答完全一致，不受多轮对话次数影响。原因：`messages`参数未正确传递每一轮的用户提问与助理回复，导致上下文未更新。
- 现象：流式输出固定每4秒返回一次数据，无法调整为更短的间隔。原因：未根据前端展示需求调整流式输出的触发间隔配置。

## 怎么确认配好了
- 发起针对某标段投标文件的多轮审核对话，检查`chatId`是否绑定了对应标段的唯一标识。
- 查看对话日志，确认每一轮的`messages`参数都包含当前轮次的提问与历史上下文。
- 测试流式输出，观察返回间隔是否在预设的1–2秒区间内。
- 输入包含资质要求、工程量清单的复杂问题，检查`variables`是否正确调用了预设的结构化字段。
