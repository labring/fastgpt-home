# 工程建设项目招投标的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源为全国公共资源交易平台、地方交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常处理的文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告等，文档结构围绕标段划分、资质要求、工程量清单、评标规则等核心字段展开，字段多包含项目编号、标段信息、资质条件、业绩要求、评标专家信息等，无统一固定单位，随文档类型差异变化。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且每日更新，需调用多平台接口同步最新文档，需适配不同平台的接口格式。文档类型多且结构差异大，需针对不同文档类型配置不同的工具调用规则，避免字段匹配错误。核心字段包含标段、资质、业绩等，工具调用需精准定位对应字段，否则会影响审核准确性。每日更新的数据量较大，工具调用需设置合理的频次限制，避免超出接口调用限额。评标报告、异议投诉相关文档涉及敏感信息，工具调用需配置权限校验，防止数据泄露。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 设为 `auto` | 适配不同招投标文档类型的自动匹配需求，可根据文档标题、内容自动调用对应工具 |
| `functionCall` | 开启 | 强制工具调用返回结构化结果，便于提取标段、资质、业绩等核心审核字段 |
| 单次工具调用数据上限 | 前 8–12 条 | 匹配每日批量更新的文档处理节奏，避免单次调用数据量超出接口承载范围 |
| 工具调用超时时间 | 600 秒 | 适配大型工程建设项目文档的处理时长，防止因文档篇幅较长导致调用中断 |
| 工具调用重试次数 | 3 次 | 适配接口调用失败后的自动恢复需求，减少人工干预 |
| 接口权限校验 | 绑定专属调用密钥 | 符合招标投标监管系统的安全要求，限制未授权主体调用敏感文档数据 |

## 容易做错的三处
- 现象：工具调用返回结果字段为空，原因：未针对招投标文档的核心字段（如标段编号、资质要求）配置工具调用的匹配规则，导致工具无法精准提取对应内容。
- 现象：使用API调用工具时，日志显示标题内容但审核结果异常，原因：未正确设置`functionCall`参数，导致工具返回结果未结构化，无法自动完成案卷校验。
- 现象：添加的自定义密钥无法完成工具调用，原因：未绑定公共资源交易平台的专属授权密钥，未满足监管系统的接口权限校验要求。

## 怎么确认配好了
- 上传单份招投标文档，检查工具调用是否自动触发并返回对应结构化结果，根据返回结果调整`toolChoice`的配置。
- 调用API提交批量文档，检查接口返回状态码是否符合预期，根据返回的错误信息调整超时时间配置。
- 查看工具调用日志，确认是否仅授权密钥可发起调用，验证接口权限配置是否生效。
- 针对评标报告类文档，手动校验工具提取的专家信息、评标结果是否与原文一致，调整字段匹配规则。
