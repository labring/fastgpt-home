# 工程建设项目招投标的申报材料与案卷审核：模型接入与配置

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类数据来源为全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常处理的文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，数据结构以项目编号、标段编号、资质要求、投标报价、评标专家记录、中标信息为核心字段，各文档关联对应项目主体，无统一跨文档全局主键。

## 这些特征在「模型接入与配置」这一环带来什么约束
多平台来源的文档格式差异，要求模型接入时需兼容非标准化的PDF、Word及结构化表格数据，需配置对应解析适配规则。每日更新的海量项目数据，要求模型调用的上下文窗口需适配长文本处理，避免截断核心标段与资质信息。核心字段包含资质、业绩、工程量清单等专业内容，要求模型需准确匹配字段与业务规则，同时需限制生成内容的随意性，避免偏离招标投标相关要求。此外，案卷审核需溯源原始材料，要求模型调用需保留原文引用链路，便于后续核查与追责。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配单项目多文档拼接后的总长度，避免核心标段、资质信息被截断 |
| `maxTokens` | `2000–3000 token` | 控制单轮生成内容的输出长度，适配案卷审核的结构化输出需求 |
| `quoteMaxToken` | `1500–2000 token` | 保留足够的原文引用片段，满足案卷审核的溯源要求 |
| `temperature` | `0.1–0.3` | 降低生成内容的随机性，确保资质、工程量清单等专业内容的准确性 |
| `AIPROXY_API_ENDPOINT` | 按平台提供的接入地址填写 | 对接第三方模型的接口地址，确保模型调用链路正常 |
| `AIPROXY_API_TOKEN` | 按平台分配的密钥填写 | 完成模型调用的身份验证，避免未授权访问 |

## 容易做错的三处
- 第三方模型在中转平台测试通过，但在FastGPT中新建模型后测试报错，原因是未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的对应关系，或中转平台的接口格式与FastGPT的接入要求不匹配。
- 知识库查询时使用的模型与上传文件时使用的模型不一致，导致查询结果异常，原因是未在配置中明确区分文档嵌入与查询的模型参数，未按业务需求绑定对应模型。
- TTS模型测试时提示`'KokoroModel' object has no attribute 'mode'`，原因是FastGPT未针对非文本生成类模型配置专属的调用适配规则，误将文本模型的参数逻辑套用到TTS模型上。

## 怎么确认配好了
- 调用模型测试接口，输入单份招标文件的核心片段，核对返回结果是否包含正确的标段与资质信息，确认上下文与输出长度配置未触发内容截断。
- 查看模型调用日志，核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的取值与平台提供的参数一致，确认身份验证通过。
- 上传一份测试用的投标文件，触发文档解析与嵌入流程，核对嵌入后的文本是否保留了原文的核心字段，确认原文引用配置符合溯源要求。
- 调整`temperature`参数并对比生成结果，确认生成内容的随机性符合业务需求，未出现明显的专业内容偏差。
