# 市场主体登记与许可的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
本品类数据主要来自企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统及住所信息库，更新频率为每日。日常处理的文档包含设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等，文档以结构化字段为主，包含主体名称、股东信息、住所地址、许可事项等明确字段，所有数据均为经营主体准入前或变更时提交的正式业务材料。

## 这些特征在「工作流编排」这一环带来什么约束
本品类数据来源固定且每日更新，要求工作流需对接指定官方系统获取校验依据，不得使用非官方数据源。日常处理的文档类型多样且结构标准化，工作流需适配不同材料的解析规则，针对设立、变更、注销等不同业务场景切换校验逻辑。出错后果直接影响主体经营资格，包括登记被驳回、冒名登记风险及经营受限，工作流需设置多层校验节点，提前拦截不合规材料。耗时集中在材料核验与条件判断环节，工作流需优化节点执行顺序，减少冗余校验步骤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配申报材料的段落长度，确保单块内容包含完整校验逻辑单元 |
| 单次搜索上限 | 前 3 条 | 市场主体登记材料的校验依据多来自官方公示数据，少量精准结果即可覆盖校验需求 |
| 最大上下文 | 4000 token | 需完整加载单份申报材料的核心内容，避免截断关键校验字段 |
| 超时阈值 | 600 秒 | 适配官方系统的接口响应时长，避免因等待过久触发流程失败 |
| 问题优化 | 按实测标定 | 需将材料校验需求转化为适配官方数据源的查询语句，需结合实际校验场景调整 |
| `variables` | 绑定业务场景标识 | 用于在分支节点中区分设立、变更等不同业务类型，触发对应校验规则 |
| `nodeId` | 绑定校验节点唯一标识 | 用于工作流调试与失败回溯，快速定位校验异常节点 |

## 容易做错的三处
- 现象：文本分类提取节点返回空值，所有提取结果均为空。原因：未针对申报材料的结构化字段配置对应提取规则，仅使用通用分类模型适配专用业务字段。
- 现象：工作流运行超时，触发系统报错。原因：未优化节点执行顺序，将耗时的住所核验节点放在流程前端，且未设置合理的超时阈值。
- 现象：平行分支流程未按预期提速，运行耗时与单分支无明显差异。原因：未将并行节点的数据源进行隔离，导致并行请求共享同一官方系统接口，触发接口限流。

## 怎么确认配好了
- 导入多份不同业务场景的样本材料，执行工作流，核对各分支节点是否触发对应校验逻辑。
- 查看FastGPT v4.17.0的工作流运行日志，确认`variables`参数已正确绑定当前业务场景的标识，节点执行顺序符合预期。
- 模拟提交不合规材料，核对校验节点是否拦截异常内容并返回明确提示。
- 测试并行分支流程，确认各分支的数据源请求互不干扰，无接口限流报错。
- 开展基准测试，对比不同配置下的工作流运行效率，验证参数取值的合理性。
