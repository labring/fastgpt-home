# 市场主体登记与许可的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类涉及的日常文档包括设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等。数据来源于企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统及住所信息库，更新频率为每日。文档多为结构化表单与非结构化文本结合，包含主体名称、住所地址、股东信息、许可事项等核心字段，部分审核环节需关联外部公示数据完成交叉核验。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据每日更新的特性要求模型接入后需支持准实时的数据拉取，避免使用过期的公示信息影响审核准确性。多类型文档混合处理的场景，需要配置适配不同格式的解析规则，确保结构化表单字段与非结构化文本内容均可被准确识别。跨系统数据关联的需求，要求配置项需支持多数据源的统一接入，同时需保证不同来源数据的核验一致性。文档字段的标准化程度差异，要求模型的上下文长度配置需覆盖完整的业务字段内容，避免关键信息被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖申报材料中多份文档的完整内容，避免股东信息、住所地址等关键字段被截断 |
| `maxTokens` | 4000 token | 适配单份审核结果的输出长度，确保补正意见、核验结论等内容完整返回 |
| `quoteMaxToken` | 2000 token | 限制引用外部公示数据的长度，避免冗余内容干扰审核判断 |
| `toolChoice` | auto | 支持模型自主选择是否调用外部数据接口完成交叉核验 |
| `temperature` | 0.2–0.4 | 降低审核结果的随机性，确保业务判断的一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境的实际接入地址填写 | 适配内网或外网的模型访问路径，确保连接正常 |

## 容易做错的三处
- 界面显示模型接入点配置错误，无法完成调用。原因是未正确匹配`AIPROXY_API_ENDPOINT`的实际部署地址，内网映射后的外网地址未正确填写。
- 知识库长期处于索引状态，无法完成初始化。原因是数据来源为每日更新的公示系统，未配置合理的增量索引触发规则，导致全量索引反复执行。
- 使用AMD显卡部署ollama大模型时出现驱动报错。原因是未适配AMD显卡的模型量化格式，或驱动版本与大模型运行环境不兼容。

## 怎么确认配好了
- 执行FastGPT v4.17.0内置的模型测试调用功能，输入一份标准的设立登记申请书模板，查看返回的核验结果是否包含所有必填字段的判断。
- 查看知识库索引日志，确认每日增量更新任务正常触发，无超时或失败记录。
- 检查模型调用的返回结果，确认引用的外部数据来自指定的公示系统，无无关内容混入。
- 在内网环境下访问配置的`AIPROXY_API_ENDPOINT`，确认网络连接正常，无超时报错。
