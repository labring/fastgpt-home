# 市场主体登记与许可的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
本品类处理的文档多为固定格式的申报材料与存档案卷，包含设立登记申请书、公司章程、股东决议、住所证明、营业执照、食品经营许可申请等。数据主要取自企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统与住所信息库，每日同步更新。文档结构以结构化表单字段为主，辅以非结构化证明材料，字段覆盖主体名称、住所地址、股东信息、许可申请事项等核心内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
固定格式的申报材料与案卷要求检索需同时匹配结构化字段与非结构化文本，单一检索模式难以覆盖全部文档类型。每日更新的数据来源要求检索链路支持增量同步与高频召回，避免过期数据被误召回。核心字段的精准匹配需求，限制了模糊检索的宽松度，案卷审核需关联多源数据，要求检索结果需覆盖多数据集的关联内容，避免单一数据源的信息缺失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配申报材料的固定格式字段，兼顾精准度与召回覆盖范围 |
| `limit` | 前6条 | 案卷审核需关联最多6份核心证明材料，避免冗余结果干扰审核 |
| `searchMode` | hybrid | 同时匹配结构化字段与非结构化文本，覆盖申报材料的两类文档形式 |
| `usingReRank` | 开启 | 对初始召回结果进行二次排序，提升股东信息、住所地址等核心字段的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展关联国家企业信用信息公示系统等多源数据，补全案卷审核所需的关联信息 |
| `collectionIds` | 按业务数据集分组配置 | 区分申报材料库与案卷审核库，避免跨品类数据干扰 |

## 容易做错的三处
- 现象：发布应用后检索结果无下载链接，调试模式下正常。原因：未配置数据集的公开访问权限，或应用权限未开放文档下载，仅在调试模式下保留临时访问权限。
- 现象：Excel导入申报材料时出现格式报错，无法完成导入。原因：未按照品类文档的固定字段格式整理Excel表格，未匹配申报材料的必填字段要求。
- 现象：知识库向量化任务耗时过长，超出预期。原因：未对大体积的PDF格式案卷进行合理分块，或未配置适配的分块参数，导致单文件向量化负载过高。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的知识库管理界面，进入对应业务数据集的配置页面，查看`datasetSearchUsingExtensionQuery`的开关状态，确认已开启多源数据关联配置。
- 执行单次检索测试，检查返回结果的条数是否符合`limit`的配置值，且排序符合`usingReRank`的预期效果。
- 对比调试模式与发布应用的检索结果，确认下载链接的展示逻辑符合配置要求。
- 查看向量化任务的进度日志，确认大体积文档的分块参数已适配品类文档的长度要求。
