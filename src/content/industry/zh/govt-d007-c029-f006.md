# 市容环卫与城管执法案件的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
该品类数据通常来源于城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。日常文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书及结案报告，数据字段通常包含案件唯一标识、违法点位信息、责任主体记录、处置流程节点标记，部分文档附带多媒体取证材料与时间戳。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据来源分散、更新频率高，要求溯源环节需支持快速同步每日新增的执法数据。文档类型包含文本与多媒体材料，需建立文本片段与对应现场照片、文书文件的关联映射，部分多媒体材料需额外关联时间戳与点位标识。案件核心字段如案件编号、违法点位需作为溯源匹配的关键标识，避免跨案件混淆。同时，执法流程的严谨性要求溯源结果需直接关联原始录入的文档版本，无法仅依赖切片后的文本片段。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配单份执法文书的核心片段长度，避免截断关键证据 |
| `responseData` | 开启 | 用于关联原始文档的存储路径与元信息，支持溯源查看 |
| `detail` | 开启 | 展示引用片段在原始文档中的具体位置，辅助验证取证有效性 |
| 单次召回上限 | 前5–7条 | 覆盖单案件常见的关联文档数量，避免冗余召回 |
| 上下文窗口 | 12000–15000 token | 适配多来源执法数据的拼接长度，防止上下文溢出 |

## 容易做错的三处
- 调用时返回一串红色数字报错。原因是未正确开启`responseData`配置，导致系统无法返回合法的来源元数据字段。
- 无法查看引用片段对应的原文件详情。原因是未关联原始文档的存储路径，或知识库导入时未保留切片前的原文档元信息。
- 召回结果条数与预期不符。原因是单次召回上限设置为前3条，或未按案件唯一标识进行精准过滤，导致召回无关执法文档。

## 怎么确认配好了
- 触发案件审核问答后，检查回复中是否包含引用片段的来源文档标识。
- 点击回复中的来源链接，验证是否能跳转至对应原文档的存储位置。
- 调整`quoteMaxToken`参数至1000 token后，观察引用片段的截断情况是否符合预期。
- 查看知识库导入日志，确认原文档的元信息已完整同步至系统中。
