# 建设项目环评审批的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
本细分品类的数据来自全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台及监测数据，更新不定期。日常处理的文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复等，每份文档包含项目类别、环评等级、污染防治措施、公众参与情况等核心字段，无固定统一单位，需结合项目实际匹配行业规范。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新无固定周期，要求多轮对话需能动态调用不同系统的字段，避免依赖静态知识库。核心文档字段无统一单位，提示词需适配不同项目的行业分类规则，不能预设固定格式。最耗时的核对环节需要多轮对话逐步拆解项目类别、环评等级、污染防治措施等校验点，通过上下文留存前序校验结果，避免重复提问。出错后果严重，需在对话流程中加入合规性校验节点，确保每一轮输出都符合环评审批的法定要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `messages` | 保留前 10–15 条对话历史 | 环评审批需回溯项目前期申报信息，足够的历史上下文可避免重复询问项目基础信息 |
| `variables` | 绑定项目编码、行业类别等固定业务字段 | 可将静态业务数据提前注入提示词，减少重复输入内容 |
| `chatId` | 按审批项目唯一标识绑定会话 | 确保同一审批项目的多轮审核会话不混淆历史信息，避免跨项目上下文干扰 |
| 单次对话最大 token | 8000 token 按实测标定 | 环评文档内容较长，需容纳完整的技术评估意见或报告书摘要 |
| 提示词更新规则 | 每轮对话后追加当前校验结果 | 确保下一轮审核可直接使用前序结论作为输入依据 |
| 分支触发条件 | 按校验结果执行节点跳转 | 可实现合规校验后的流程分支，适配审核纠错或终止需求 |

## 容易做错的三处
- 对话明细中仅显示少量上下文，无法关联历史校验结果。原因是未正确配置`messages`的保留条数，或上下文窗口设置过小，导致早期项目信息被截断。
- 无法将上一轮的校验结论作为下一轮提示词输入。原因是未通过`variables`绑定前序输出字段，未将对话结果注入后续提示词模板。
- 循环流程执行异常，无法按校验结果终止或重启。原因是未正确配置分支触发规则，未将校验结果与节点跳转逻辑绑定。

## 怎么确认配好了

- 发起测试对话，输入项目基础信息后追问历史内容，检查对话明细中是否完整展示前序交互记录。
- 触发一轮校验后，查看`variables`中是否存储了当前校验结果，验证是否可在后续对话中调用该字段。
- 配置循环分支后，输入不符合要求的校验结果，检查是否触发重新生成节点，输入符合要求的结果则终止流程。
- 查看`chatId`是否在同一会话中保持一致，确认不同审批项目的会话未出现上下文混淆。
