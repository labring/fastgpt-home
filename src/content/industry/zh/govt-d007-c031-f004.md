# 建设项目环评审批的申报材料与案卷审核：工作流编排
本文档适用于 FastGPT v4.17.0 版本。

## 这个品类的数据长什么样
本品类的数据来源于全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台、监测数据，更新频率不定期。日常处理的文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复，文档结构按项目类别、环评等级、污染防治措施、公众参与情况等核心字段划分，需适配不同规模的申报材料，无统一固定的单文档长度。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的整合需求要求工作流需配置跨系统数据拉取节点，确保申报材料与分区管控、监测数据的联动校验。文档结构不统一的特点要求工作流需支持灵活的分块与字段提取规则，避免因文档长度差异导致的节点异常。更新不定期的属性要求工作流不可依赖固定定时拉取逻辑，需按需触发数据同步。同时，审核出错会导致项目无法开工、批复被撤销等严重后果，工作流需增设前置校验与失败回滚环节，保障审核流程的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定项目编号、项目类别、申报材料ID | 精准匹配对应环评项目的专属数据，避免跨项目审核混淆 |
| 问题优化 | 启用并设置为「按环评审批专业标准优化提问」 | 适配环评领域专业术语，提升审核节点对复杂文档的理解精度 |
| 单次搜索上限 | 前10条 | 覆盖环评文档的核心参考数据，避免冗余信息干扰审核判断 |
| 重排 | 启用，按相关性排序 | 优先展示污染防治措施、公众参与等核心审核字段，提升审核效率 |
| 最大上下文 | 8000–12000 token | 容纳完整的环评报告书章节与审批历史数据，按实测标定取值区间 |
| 节点超时设置 | 600秒 | 适配长文档的加载与审核时长，避免因超时中断完整审核流程 |

## 容易做错的三处
- 工作流中AI会话节点输出末尾附带固定平台提示语，现象为测试返回“FastGPT 是一个基于大语言模型(LLM)的知识库问答系统”，原因是未在会话节点的系统提示词中配置自定义审核提示，默认加载了平台内置的通用提示。
- AI会话节点的温度开关配置效果混淆，现象为设置温度为0与关闭温度开关后输出结果无明显差异，原因是未明确两种配置的底层逻辑差异，部分节点默认将关闭温度开关等同于限制随机性至最低，与温度为0的逻辑存在细微差异。
- 问题分类节点执行速度较慢，现象为批量处理环评申报材料时节点响应超时，原因是未限制分类节点的输入文本长度，未启用分块处理逻辑，导致单次加载的文档数据量过大。

## 怎么确认配好了
- 进入工作流测试页面，输入模拟的环评项目编号，核对`variables`绑定的项目编号、类别等字段是否正确加载。
- 运行工作流，检查AI会话节点的输出是否包含环评审批所需的核心审核字段，无多余的平台提示语。
- 调整单次搜索上限为前5条与前15条，对比返回结果的相关性与冗余度，确认符合当前审核场景的需求。
- 批量导入3份不同类别的环评申报材料，验证`nodeId`对应的问题分类节点响应时间符合预期。
