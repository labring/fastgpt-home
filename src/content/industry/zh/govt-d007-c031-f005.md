# 建设项目环评审批的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来自全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台、监测数据，更新频率不定期。日常处理的文档包括环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复，文档结构按环评审批流程分为项目概况、污染防治措施、公众参与等固定章节，字段包含项目类别、环评等级、污染防治方案细节等，无统一固定单位，随具体文档内容调整。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源涉及多个独立系统，工具调用需要支持多源数据的并行拉取与整合，避免出现数据不一致的情况。环评文档结构复杂且存在固定章节，工具需要能识别不同文档的章节划分，精准提取对应审核环节的内容。更新频率不定期意味着工具需支持实时或按需拉取最新数据，无法依赖固定周期的缓存。审核环节涉及项目类别核对、污染防治措施审查等核心内容，工具调用需精准匹配专属字段，否则会导致审核失误。同时，出错后果严重，工具调用的参数校验环节需严格配置，避免错误数据进入审核流程。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ----------- |
| `toolChoice` | `auto` | 自动匹配申报材料审核、案卷核对等不同工具场景，适配多环节审核需求 |
| `functionCall` | 开启参数校验 | 对工具调用的参数进行合法性检查，避免错误字段进入审核流程 |
| 工具调用超时设置 | `600 秒` | 环评申报材料内容较多，需足够时间完成文档解析与数据拉取 |
| 单次工具返回结果上限 | `前 10 条` | 案卷审核所需的相关数据条目适中，避免过多冗余信息干扰审核 |
| 文档分块策略 | 按环评文档章节分块 | 环评文档有固定章节结构，按章节分块可精准提取对应审核环节的内容 |
| 上下文窗口配置 | `8000–12000 token` | 环评申报材料整体内容较多，需足够上下文保留完整审核相关信息 |

## 容易做错的三处
- 现象：工具调用返回结果为空，无法提取申报材料中的有效内容。原因：未正确配置多源数据对接的接口权限，导致无法拉取全国建设项目环评统一申报和审批系统中的数据。
- 现象：生成的审核匹配规则无法对应环评专属字段，出现参数不匹配报错。原因：未将申报材料中的项目类别、环评等级等专属字段准确映射到工具调用的参数中，导致工具无法识别对应审核内容。
- 现象：插件配置无法重新导出为schema格式文件，导致后续修改困难。原因：未按照工具配置的标准格式保存插件设置，导致导出的schema文件不符合要求。

## 怎么确认配好了
- 提交一份标准的环评审批申请材料，触发工具调用，检查是否能正确拉取对应的数据来源内容并完成初步审核。
- 手动输入一个已知的项目类别与环评等级，验证工具是否能准确调用对应的审核规则进行核对。
- 查看工具调用日志，确认参数传递正确，无空值或错误字段。
- 模拟一次完整的案卷审核流程，检查工具返回的结果是否覆盖了需要核对的核心环节，如污染防治措施、公众参与说明等。
