# 建设项目环评审批的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台及监测数据，更新频率不定期。日常处理的文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复等，文档结构多为多章节的正式公文格式，包含项目类别、环评等级、污染防治措施、公众参与情况等字段，无统一固定单位，随文档类型变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据来源分散，需对接多系统接口获取信息，不定期更新要求模型支持增量同步。多章节公文格式的长文本、嵌套结构，要求模型具备足够的长上下文处理能力。字段随文档类型灵活变化，要求配置时支持自定义字段抽取规则。审批类文档的严肃性要求模型输出可溯源，需保留引用原文的配置能力。同时，审核失误会引发严重后果，要求配置失败处理机制与日志留存功能。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置规则编写
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配环评文档多章节长文本结构，覆盖完整审批案卷内容 |
| `maxTokens` | 2000–3000 token | 满足单份审核结果的输出长度，避免截断核心审批意见 |
| `quoteMaxToken` | 1500 token | 保留原文引用的合理长度，确保溯源内容完整 |
| `toolChoice` | auto | 支持自动调用工具完成多数据源数据校验与字段抽取 |
| `temperature` | 0.2–0.4 | 降低输出随机性，保障审核结果的严谨性，符合政务文档要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接口地址 | 对接合规的模型调用通道，保障数据传输安全 |
| `AIPROXY_API_TOKEN` | 按平台生成的专属令牌填写 | 验证调用权限，防止未授权访问 |

## 容易做错的三处
- 现象：调用模型时返回认证失败或连接错误，无法查看详细调用日志。原因：未正确填写`AIPROXY_API_TOKEN`，或`AIPROXY_API_ENDPOINT`配置错误，导致无法建立有效连接。
- 现象：模型输出的审核结果与原文引用不符，出现内容偏差。原因：`temperature`取值过高，导致模型输出随机性过大，不符合政务审核的严谨要求。
- 现象：无法调用Qwen3系列模型完成环评审核任务。原因：未将`AIPROXY_API_ENDPOINT`配置为适配Qwen3的专属接口地址，或未确认模型支持的上下文参数范围。

## 怎么确认配好了
- 上传一份标准的环境影响报告表，触发模型审核，检查输出结果是否包含项目类别、环评等级等核心字段，确认字段抽取规则生效。
- 查看模型调用日志，确认`AIPROXY_API_TOKEN`和`AIPROXY_API_ENDPOINT`的配置被正确读取，无认证或连接错误。
- 调整`temperature`参数，对比两次输出结果的差异，确认参数对输出随机性的影响符合预期。
- 测试长文本文档的上传，确认`maxContext`配置可覆盖完整文档内容，无截断情况。
