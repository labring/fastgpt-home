# 建设项目环评审批的申报材料与案卷审核：部署与升级

## 这个品类的数据长什么样
本品类涉及的主体包括生态环境部门环评处、行政审批局、建设单位与环评机构。日常处理的文档包含环境影响报告书、报告表、审批申请、公众参与说明、技术评估意见与环评批复，涵盖项目基本信息、污染防治措施、公众参与内容、审批流程节点等字段。数据来源涵盖全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台与监测数据，更新频率为不定期，无固定同步周期。

## 这些特征在「部署与升级」这一环带来什么约束
本品类的数据来源分散且更新无固定周期，部署时需配置多系统的数据对接逻辑，确保可同步获取最新的环评项目信息与文档。日常文档格式与字段差异较大，需适配不同类型环评文件的解析规则，避免出现解析失败或字段提取不全的情况。同时，审核出错会直接导致项目无法开工、批复被撤销或后续执法追责，部署环节需强化数据校验与权限控制，保障审核流程的准确性与安全性。此外，多主体并行操作的场景较多，需配置合理的数据库连接数与缓存策略，避免服务卡顿或数据不一致。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `jdbc:postgresql://[环评审批系统数据库地址]:5432/epia_db` | 对接全国建设项目环评统一申报和审批系统的结构化数据，获取项目基础信息与审批节点数据 |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.volces.com`（可替换为政务云对象存储地址） | 存储环评申报文档与审批材料，适配多源文件的上传与读取需求 |
| `FILE_TOKEN_KEY` | 随机生成的32位字符串 | 校验环评文件的上传合法性，防止非授权文件接入审核系统 |
| `REDIS_URL` | `redis://:[自定义密码]@[redis服务地址]:6379/0` | 缓存环评项目的分类标签与审批节点状态，降低重复查询数据库的压力 |
| `DB_MAX_LINK` | `20–30` | 适配多部门并行调取环评数据的连接数需求，避免数据库连接耗尽导致服务中断 |
| `FE_DOMAIN` | `https://epia-review.your-gov-domain.cn` | 配置前端服务的访问域名，适配政务内网或外网的部署场景 |

## 容易做错的三处
- 现象：登录页面出现无法点击的蒙版层，前端控制台报跨域错误。原因：未正确配置`FE_DOMAIN`参数，导致前端域名与后端服务域名不匹配，静态资源加载被拦截。
- 现象：调用环评数据接口返回405状态码，日志显示远端WWW服务支持TRACE请求。原因：未关闭远端WWW服务的TRACE请求支持，不符合政务系统的安全合规要求，同时可能被攻击者利用。
- 现象：批量导入环评报告表时出现文件解析失败。原因：仅配置了环境影响报告书的解析规则，未适配报告表的结构化字段，导致非预期格式的文档无法正常提取内容。

## 怎么确认配好了
- 调用数据库连接测试接口，验证`PG_URL`与`DB_MAX_LINK`配置的数据库连接正常，可返回环评项目的基础字段数据。
- 上传一份标准环评公众参与说明文档，验证`FILE_TOKEN_KEY`配置生效，文件可正常存储至配置的对象存储服务。
- 访问前端域名，验证`FE_DOMAIN`配置正确，页面无异常蒙版或跨域报错。
- 发起批量文件解析任务，验证`REDIS_URL`配置生效，解析进度可正常缓存并在前端页面展示。
