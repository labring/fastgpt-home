# 投资项目立项与后评价的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
本品类的数据来源为国资委投资监管系统、企业ERP和项目管理系统、行业市场数据、审计和财务报表，更新频率为季度。日常处理的文档涵盖年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告、投资后评价报告，包含项目编号、投资额度、立项审批节点等结构化字段与技术论证、财务测算、投决会议纪要等非结构化文本，字段与单位匹配对应业务场景的通用规范。

## 这些特征在「工作流编排」这一环带来什么约束
数据按季度更新，要求工作流需支持周期性批量数据同步与校验，避免使用过期的行业市场数据或财务报表。多类型文档混合处理，要求工作流节点适配不同文档格式的自动识别与分块，兼顾结构化字段提取与非结构化文本解析的差异化需求。多系统数据来源需配置跨系统拉取规则，确保立项与后评价环节的数据一致性。全周期文档链条要求工作流串联立项申报、材料审核、投决会议、后评价数据收集等环节，且每个环节保留可追溯的审核节点，满足国资监管的合规要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 问题优化 | 前置在智能体节点之前 | 先处理申报材料的格式、关键词冗余问题，降低智能体解析负荷 |
| 单次搜索上限 | 前8条 | 匹配多来源文档的检索需求，兼顾召回精度与处理效率 |
| 最大上下文 | 12000 token | 适配多份可研报告、尽职调查报告等长文档的上下文承载 |
| variables | 绑定项目编号、投资额度等字段 | 确保工作流调用的字段与业务数据保持一致 |
| nodeId | 按环节顺序配置唯一ID | 实现工作流节点跳转与审核状态的可追溯 |
| 重排 | 开启 | 对召回的审核材料按相关性排序，提升匹配精准度 |

## 容易做错的三处
- 现象：工作流运行显示失败，但模型后台存在响应日志。原因：部署环境的端口配置存在限制，导致工作流节点间的数据传递出现阻断。
- 现象：智能体节点的提示词未按预期处理申报材料。原因：提示词配置未与`variables`绑定的业务字段关联，导致上下文缺失关键业务信息。
- 现象：问题优化组件配置后未改变审核结果的相关性排序。原因：问题优化组件未放置在智能体节点之前，未对原始申报材料做预处理，无法优化后续检索的关键词精度。

## 怎么确认配好了
- 执行单次工作流测试，核对节点日志是否包含`variables`绑定的业务字段，确认数据传递正常。
- 查看工作流节点顺序，确认问题优化组件位于智能体节点之前，覆盖当前处理的文档类型。
- 检查`nodeId`配置，确认每个环节的节点ID唯一且按执行顺序排列，通过节点状态追踪验证跳转逻辑。
- 触发季度数据同步测试，核对拉取的文档是否与业务系统的更新内容匹配。
