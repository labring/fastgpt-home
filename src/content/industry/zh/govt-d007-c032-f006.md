# 投资项目立项与后评价的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
该品类的服务主体包括中央企业战略投资部、项目公司、国资监管部门与外部咨询评估机构。日常产生的文档涵盖年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告与投资后评价报告。数据来源包含国资委投资监管系统、企业ERP与项目管理系统、行业市场数据、审计和财务报表，更新频率为季度。不同来源的文档结构与字段存在差异，核心字段包括项目编号、投资额度、审批节点与后评价指标等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散于多个内部与外部系统，要求溯源环节需支持跨系统的来源标识绑定，确保引用内容可追溯至原始生成系统。季度更新的频率要求索引更新周期与数据同步节奏匹配，避免引用过时的项目信息。文档结构复杂且字段不统一，需适配长文本分片与多字段提取，确保引用内容的完整性。案卷审核的合规要求决定了溯源信息必须包含原始文档的生成时间、来源系统与审核节点，无法仅依赖通用的文档标题标识。出错后果涉及国有资产损失、责任追究等，要求溯源环节需准确关联每一条引用内容的原始依据，避免出现引用与内容不符的情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 适配单份可行性研究报告的平均长度，匹配季度更新的文档总规模 |
| `quoteMaxToken` | 1500–2000 token | 确保单条引用内容完整覆盖项目核心参数，避免截断关键的投资额度或审批节点信息 |
| 引用条数上限 | 前6条 | 匹配投决会材料的常规引用数量，避免过多冗余内容干扰大模型生成 |
| `detail` | 开启 | 展示每条引用的原始文档来源字段，满足案卷审核的合规溯源要求 |
| `responseData` | 开启溯源字段 | 保留原始数据的关联标识，便于后续审计与责任追溯 |
| 跨源绑定开关 | 开启 | 适配分散于不同系统的数据来源，确保溯源信息准确关联至原始系统 |

## 容易做错的三处
- 现象：调大`quoteMaxToken`至2000以上后，大模型回答未引用任何召回内容，仅能在后台查看召回记录。原因：上下文总长度超出系统阈值，导致引用片段被过滤，未纳入生成上下文。
- 现象：回答中显示了符合条件的引用条数，但正文中未出现对应的引用内容。原因：未正确开启`detail`参数，未将引用片段嵌入大模型生成上下文。
- 现象：调用API引用私人知识库时返回空的溯源字段。原因：未开启`responseData`参数，未开放外部调用的溯源权限。

## 怎么确认配好了
- 上传单份年度投资计划文档，触发包含项目编号的提问，检查回答中是否包含该字段。
- 查看问答详情页，确认每条引用内容下方显示了原始文档的来源路径与更新时间。
- 调用API接口，检查返回的`detail`字段是否包含完整的溯源信息。
- 调整`quoteMaxToken`至1800 token，验证回答仍能正确引用符合长度的片段。
- 适配FastGPT v4.17.0版本的配置逻辑，确保所有参数生效。
