# 投资项目立项与后评价的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自国资委投资监管系统、企业ERP和项目管理系统、行业市场数据及审计财务报表，更新频率为季度。日常处理的文档包括年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告及投资后评价报告，每份文档包含项目基本信息、财务测算、风险评估等字段，涉及投资额、项目周期等单位，核心内容围绕资本投向与国资保值展开。

## 这些特征在「模型接入与配置」这一环带来什么约束
季度更新的数据要求定期同步向量库，避免使用过期的项目数据。单份文档篇幅较长，需合理控制上下文与生成token的长度，防止核心业务信息被截断。文档涉及财务、法律、工程等多领域专业内容，需匹配适配专业文本的向量模型与生成参数。国资相关内容需严格限制生成随机性，确保审核结论的严谨性，同时需保障接口调用的身份验证安全。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单份可行性研究报告的总文本长度，避免截断核心业务数据 |
| `maxTokens` | 4000 token | 控制单轮生成内容长度，适配投决会材料的标准化审核输出格式 |
| `quoteMaxToken` | 1500 token | 限定引用原文的长度，确保案卷审核时仅提取关键合规条款与财务数据 |
| `temperature` | 0.1–0.3 | 降低生成随机性，保证国资项目审核结论的严谨性与一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署的大模型服务地址填写 | 适配对接本地部署的大模型的调用链路 |
| `AIPROXY_API_TOKEN` | 按部署生成的密钥填写 | 保障模型调用的身份验证安全 |

## 容易做错的三处
- 现象：部署大模型服务时，GPU功耗和使用率偏低，CPU单核占用率达100%。原因：未将大模型推理任务调度至GPU资源池，仅使用CPU执行推理流程。
- 现象：调用向量模型时，返回的匹配案卷条数与预期不符。原因：未正确配置`quoteMaxToken`参数，导致系统过滤了部分符合要求的文本片段。
- 现象：FastGPT v4.17.0版本配置在线模型时返回401状态码。原因：未正确填写`AIPROXY_API_TOKEN`，或密钥权限未覆盖当前调用场景。

## 怎么确认配好了
- 上传单份可行性研究报告，检查模型生成的审核摘要是否提取了项目核心合规条款。
- 发起批量案卷审核任务，查看GPU资源使用率是否处于合理区间。
- 测试向量模型调用，确认返回的匹配结果与案卷中的关键内容一致。
- 验证`maxContext`参数设置，确保导入的最大文档未出现文本截断提示。
