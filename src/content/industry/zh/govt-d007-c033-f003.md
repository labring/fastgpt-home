# 招标采购合规管理的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源包括企业采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库。数据更新频率为每日。日常涉及的文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料。文档字段涵盖采购方式、预算依据、评分办法、供应商资格要求、履约条款等，格式随项目类型存在差异。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源数据的关联要求对话上下文需绑定对应采购项目的所有数据源信息，避免跨项目的合规校验错误。每日更新的数据要求对话环节可实时调用最新的供应商库与审计问题库内容，确保审核时效性。多类型文档的适配要求提示词需针对不同文档的字段特征调整校验逻辑，同时多轮对话需保留前序审核的关键节点。合规风险要求对话过程需留存完整的审核轨迹，确保可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口大小 | 8000–12000 token | 适配招标采购类文档的长文本与多轮对话上下文 |
| `chatId` | 绑定采购项目唯一ID | 确保同项目下的多轮对话`messages`关联一致 |
| `variables` | 预设采购方式、预算阈值字段 | 让提示词自动调用对应项目的合规校验规则 |
| 最大对话轮次 | 前20轮按实测标定 | 覆盖申报材料审核的完整流程环节 |
| 知识库召回条数 | 前8条 | 匹配该品类单轮对话的文档数量上限 |
| 提示词模板 | 嵌入“结合采购计划与招标文件校验”指令 | 适配该品类的核心审核场景 |

## 容易做错的三处
- 现象：提示词无法切换为英文格式，知识库返回的合规规则仍为中文。原因：未在`variables`中配置语言切换参数，提示词模板未绑定对应语言的调用指令。
- 现象：多轮对话后上下文丢失，无法延续案卷审核流程。原因：未将`chatId`绑定到采购项目的唯一标识，导致不同会话的`messages`未关联到同一审核任务。
- 现象：文本内容提取模块仅显示GPT类模型选项，无法选择配置的GLM模型。原因：未在模块配置中同步开放所有绑定的模型接口，导致文本提取环节的模型选择范围受限。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本。
- 发起一轮针对采购计划的提问，检查对话历史是否保留上一轮的审核要点，确认`chatId`绑定生效。
- 调用知识库查询对应项目的合规规则，检查提示词是否自动带入预设的`variables`字段内容。
- 切换模型选项，确认文本提取与对话模块均可显示配置的GLM模型，检查模型绑定规则是否正确。
- 上传招标采购类文档，确认系统可识别并关联到当前审核项目的上下文，检查知识库关联范围是否配置正确。
