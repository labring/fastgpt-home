# 招标采购合规管理的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
本品类的数据来自企业采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，更新频率为每日。日常处理的文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料，数据字段涵盖采购方式、预算依据、供应商资格条件、评分办法、履约验收标准等，部分文档需关联跨系统的采购流程编号与供应商备案信息。

## 这些特征在「工作流编排」这一环带来什么约束
跨系统数据来源要求工作流需支持跨数据源调用节点，确保采购计划、评标记录等不同文档的字段可跨节点复用。日更的数据更新节奏要求工作流需配置定时触发节点，避免使用过时的供应商库或审计问题库数据。多类型文档的差异校验需求，要求工作流设置分支判断节点，针对招标文件、验收单等不同文档配置专属的合规校验规则。合规风险关联问责机制，要求工作流保留完整的节点执行日志与案卷归档入口。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 定时触发周期 | 每日凌晨2:00-4:00 | 匹配业务数据日更节奏，避开采购业务高峰时段 |
| variables | 绑定采购流程编号、供应商备案ID | 实现跨节点的字段复用，避免重复录入跨系统数据 |
| 分支判断规则 | 按文档类型拆分校验分支 | 适配采购计划、招标文件等多类型文档的差异化校验逻辑 |
| nodeId | 为每个校验节点分配唯一标识 | 便于日志追踪与案卷归档的节点关联 |
| 查看来源开关 | 按节点业务场景配置 | 纪检审计类节点关闭查看来源权限，采购执行类节点保留可见性 |
| 文本提取模型 | 按实测标定 | 适配招标文件、评标记录等长文本的字段提取需求 |

## 容易做错的三处
- 工作流导入模板后无可用节点。现象为导入提示成功，但画布无任何节点。原因是模板内的`nodeId`配置与当前环境的内置节点ID规则不匹配，未完成节点映射。
- 部分节点的查看来源开关配置混乱。现象为敏感校验节点意外开放了原文查看权限，或业务节点被错误关闭。原因是未按节点所属业务场景区分配置可见性，直接套用通用规则。
- 文本提取节点无法选择模型。现象为下拉菜单无可用模型选项。原因是未在系统后台配置对应模型的调用权限，或节点未绑定正确的数据源类型。

## 怎么确认配好了
- 触发一次测试工作流，检查跨节点的`variables`字段是否正确传递，采购流程编号是否匹配源数据。
- 查看节点日志，确认定时触发节点按预设周期执行，无超时或调用失败记录。
- 随机选取不同类型的文档，验证分支判断节点是否正确触发对应校验分支。
- 检查敏感节点的查看来源开关配置，确认纪检审计类节点未开放原文查看权限。
