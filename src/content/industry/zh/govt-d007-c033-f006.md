# 招标采购合规管理的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来源包括企业采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，更新频率为每日同步各系统的最新业务数据。日常处理的文档覆盖采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料等，单份文档包含采购主体信息、标的明细、评审标准、履约记录、处罚记录等字段，不同来源的文档格式存在差异，需按业务环节区分归档以保障审核精准性。

## 这些特征在「引用来源与溯源」这一环带来什么约束
每日更新的数据源要求溯源环节需实时同步最新数据，避免引用过期的采购计划或失效的供应商资质信息，防止审核依据出现偏差。多来源的文档需明确标注来源平台或系统，区分企业内部采购数据与公共资源交易数据，满足国资监管与内部审计的双重合规要求。不同业务环节的文档（如招标文件与评标记录）需精准匹配，防止跨环节文档被错误关联，否则可能引发串标围标风险、审计整改要求或合同无效判定。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 招标采购相关文档单篇核心审核内容多在千字符左右，匹配溯源内容的长度需求 |
| `responseData` | 仅返回知识库匹配结果 | 确保输出仅使用知识库内的原文答复，不生成额外内容 |
| `detail` | 开启 | 需展示溯源文档的具体字段如文档名称、来源平台，满足合规审核的溯源要求 |
| 单次搜索上限 | 前5条 | 招标采购案卷审核需精准匹配，过多结果会干扰溯源判断 |
| 上下文窗口 | 2000–3000 字符 | 覆盖单份招标案卷的核心审核内容，避免截断关键信息 |

## 容易做错的三处
- 现象：输出内容未使用知识库内的原文答复，出现额外生成的内容。原因：未正确配置`responseData`参数，启用了大模型自由生成逻辑。
- 现象：工作流节点中无法选择知识库引用变量。原因：未在知识库配置中开启引用溯源开关，或工作流节点未绑定对应知识库数据源。
- 现象：引用的溯源文档与当前审核的案卷不匹配，出现跨环节文档。原因：未按文档类型设置分块规则，导致不同环节的采购计划与评标记录被混同匹配。

## 怎么确认配好了
- 上传单份招标采购案卷文档至FastGPT v4.17.0知识库，发起对应审核提问，检查输出内容是否与知识库内的原文答复完全一致。
- 查看输出结果的溯源模块，确认展示的文档名称、来源平台与实际上传的文档匹配。
- 在工作流中添加变量输出节点，检查是否可选择知识库匹配的结果字段。
- 调整`quoteMaxToken`参数值，检查输出的溯源内容长度是否随参数变化。
