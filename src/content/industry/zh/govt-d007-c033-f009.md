# 招标采购合规管理的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自国央企采购平台、公共资源交易平台、供应商库、合同管理系统及审计问题库，更新频率为每日。日常处理的文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料，数据字段涵盖采购方式、预算依据、评分办法、供应商资格条件、履约验收信息等，单份文档体量存在差异，案卷类数据按采购批次关联多份文件。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据多源且每日更新，要求模型接入环节需适配企业采购平台、公共资源交易平台等不同数据源的格式规范，保证增量同步的稳定性。文档类型多样且按采购批次关联多份文件，需模型支持跨文档的上下文关联，同时对采购方式、评分办法、供应商资格等关键合规字段的识别精度要求较高。单份文档及案卷整体体量差异较大，模型的上下文处理能力需覆盖不同长度的输入，且配置需适配审计、纪检部门对审核结果的严谨要求，避免出现关键信息漏判或错判。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单采购批次关联的多份文档总长度，覆盖招标文件、评标记录等核心材料的总字符量 |
| `maxTokens` | 2000–3000 token | 保证合规审核的详细输出，包含依据说明与风险提示，避免输出截断 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保合规判断的一致性，适配审计、纪检等部门对审核结果的严谨要求 |
| `toolChoice` | none | 本场景仅需文本合规审核，无需调用外部工具，避免工具调用带来的额外逻辑风险 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的代理地址填写 | 适配多源数据调用的统一代理配置，保证外部模型与本地部署模型的调用链路一致 |
| `quoteMaxToken` | 1000–1500 token | 限制引用原文的长度，保证审核内容聚焦关键合规条款，避免冗余引用干扰判断 |

## 容易做错的三处
- 调用本地ollama部署的模型时返回空内容，或测试时无响应。原因是未正确配置`AIPROXY_API_ENDPOINT`指向ollama的本地服务地址，或重启后ollama服务端口发生变更未同步更新配置。
- 勾选图像输入选项后模型无法加载图像文件。原因是未确认当前使用的模型为多模态模型，或未在模型配置中开启`vision`参数支持图像输入，误将纯文本模型配置为支持图像任务。
- 使用aiproxy接入模型时出现调用报错，提示参数格式异常。原因是在模型配置中混用了非指定的参数名，或未按要求配置`AIPROXY_API_TOKEN`为正确的代理验证密钥。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型测试页面，输入单份招标文件的合规审核问题，核对输出是否包含采购方式、预算依据的核对结果，确认上下文处理正常。
- 切换至不同采购批次的关联数据进行测试，验证多文档关联的审核结果是否符合业务逻辑，确认`maxContext`配置适配当前数据体量。
- 重启FastGPT容器与关联的模型服务，再次执行模型测试，确认配置在重启后仍可正常生效。
- 查看模型调用日志，确认每次调用的参数与配置项一致，无遗漏或错误配置。
