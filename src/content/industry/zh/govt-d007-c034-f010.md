# 招生入学与学籍管理的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据涵盖入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表等文档，数据来源包括全国中小学生学籍信息管理系统、地方招生入学平台、户籍和房产数据、学校教务系统。数据更新频率为每日，字段包含学生姓名、身份证号、学籍号、户籍地址、房产证明编号、招生批次等结构化内容，同时包含招生政策说明、学籍异动规则等半结构化文本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类数据来源跨多个政务与教务系统，需同时匹配结构化字段与半结构化政策文本，对检索的混合召回能力有要求。每日更新的学籍与招生数据要求知识库支持增量同步，避免使用过期的历史批次数据。文档字段涉及学生身份、户籍房产等敏感且关键的审核依据，召回结果的准确性直接影响审核结论，需过滤非目标区域、非当前批次的冗余数据。同时，单份审核材料需关联多类文档，检索召回的上下文长度需适配模型输入限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 招生学籍数据字段精准，需过滤低匹配度的无关文档，确保关键信息如学籍号、户籍地址的召回准确性 |
| `limit` | `前6–8条` | 单份审核需覆盖报名信息、学籍记录、房产证明、招生政策等多类文档，过多条目会超出模型上下文长度 |
| `searchMode` | `keyword + semantic` | 兼顾结构化字段（如学籍号）的精准关键词匹配与招生政策文本的语义召回 |
| `usingReRank` | 开启 | 对多来源召回的结果按相关性重排，确保当前招生批次的核心文档排在前列 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充扩展招生政策相关的同义表述，如“入学资格”对应“报名条件”，提升召回覆盖范围 |
| `collectionIds` | 绑定对应学区、学校的专属数据集ID | 隔离不同区域的学籍与招生数据，避免跨区域数据混淆，确保审核仅使用目标范围的文档 |

## 容易做错的三处
- 现象：尝试导入微信公众号内容至知识库，检索时无对应结果。原因：未配置外部数据源同步插件，未完成公众号内容的结构化转换与数据集导入流程。
- 现象：调大`limit`参数至2000后，模型输出未附带任何引用标记，检索详情显示召回条目完整。原因：召回的总上下文长度超出模型输入限制，关键引用内容被截断，无法被模型识别引用。
- 现象：本地部署后，基于招生政策文档搭建的知识库，生成的审核结论与政策不符。原因：未配置字段级过滤规则，召回了非当前招生批次的历史学籍数据与过时政策文本。

## 怎么确认配好了
- 上传单份入学报名表至对应数据集，检索“学生身份证号”，确认召回结果包含该字段的匹配内容，且相似度处于预设区间内。
- 调整`limit`参数为`前5条`，检索“2024年招生计划”，确认返回的文档条目数符合设置要求。
- 开启`usingReRank`功能后，检索“转学申请”，确认学籍异动审批表的结果排在非政策类文档之前。
- 在FastGPT v4.17.0版本的数据集管理界面查看同步日志，确认每日增量更新的学籍数据已自动同步至知识库。
