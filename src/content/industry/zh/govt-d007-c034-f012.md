# 招生入学与学籍管理的申报材料与案卷审核：部署与升级

## 这个品类的数据长什么样
本品类数据来源包括全国中小学生学籍信息管理系统、地方招生入学平台、户籍与房产数据平台、学校教务系统。日常处理的文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表。数据按日更新，核心字段涵盖学生身份标识、户籍房产关联信息、学籍异动审批状态、招生录取批次等，单份文档通常包含多维度关联字段，审核时需跨系统校验信息一致性。

## 这些特征在「部署与升级」这一环带来什么约束
本品类数据跨多系统获取且按日更新，部署时需保障多源数据对接的稳定性，避免因数据库连接中断导致审核流程阻塞。核心文档包含多维度关联字段，文件存储需适配单份文档的批量关联数据传输。日常审核环节需处理大量结构化与半结构化材料，部署时需预留足够的资源处理并发请求。升级过程中需保留原有学籍数据的校验逻辑，避免因配置变更导致学籍重复或遗漏的风险。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 20–30 个 | 适配每日更新的学籍与招生数据的并发访问需求，避免连接池耗尽 |
| `MONGODB_URI` | 指向本地或专属托管的MongoDB实例 | 存储招生计划、录取名册等批量文档，保障数据读写性能 |
| `REDIS_URL` | 配置为本地Redis服务地址 | 缓存高频访问的学籍校验规则与用户会话信息，降低数据库压力 |
| `STORAGE_S3_ENDPOINT` | 适配本地文件存储或专属对象存储服务的端点地址 | 存储入学报名表、转学申请等上传的纸质扫描件与电子文档 |
| `FILE_TOKEN_KEY` | 按实测标定的随机字符串 | 保障上传文件的访问权限，避免未授权访问敏感学籍材料 |
| `ROOT_KEY` | 配置为强复杂度字符串 | 限制后台管理接口的访问权限，防止未授权修改审核配置 |

## 容易做错的三处
- 调用文件上传API后智能体后端无法访问上传文件，接口返回超时或权限错误。原因是未正确配置`FILE_TOKEN_KEY`导致令牌校验失败，或`STORAGE_S3_ENDPOINT`指向的存储服务未开放对应端口。
- 使用docker-compose部署后，工作流与知识库配置变为空白。原因是未持久化`MONGODB_URI`对应的数据库存储卷，容器重启后数据丢失，且未配置`REDIS_URL`的持久化缓存。
- 无GPU的服务器启动FastGPT时报OCI runtime create failed错误。原因是未正确配置容器的资源限制，或镜像版本与宿主机内核不兼容，未指定正确的启动参数适配无GPU环境。

## 怎么确认配好了
- 执行本地文件上传测试，上传一份模拟入学报名表，检查存储服务是否正常接收文件并返回有效访问路径。
- 连接`MONGODB_URI`对应的数据库实例，验证是否存在招生计划、学籍信息等核心集合与数据。
- 调用后台管理接口，使用`ROOT_KEY`验证权限校验是否生效，拒绝未携带正确密钥的请求。
- 查看Redis连接日志，确认`REDIS_URL`配置的服务已正常建立连接并缓存校验规则。
