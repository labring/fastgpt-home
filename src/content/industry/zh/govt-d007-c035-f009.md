# 排污许可管理的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
该品类数据主要来自全国排污许可证管理信息平台、企业环保台账、在线监测系统及环境统计系统，更新频率为季度。日常处理的文档包含排污许可证申请表、执行报告、自行监测方案、台账记录、变更申请及许可证副本，文档字段包含许可限值、排放口信息、监测数据、变更事项等，单位涉及浓度、排放量、时间周期等，需匹配生态环境行业的标准化格式要求，确保审核时的字段识别准确性。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且需跨系统整合，要求模型接入需支持多数据源的结构化与非结构化数据解析；季度更新的批量文档需适配大批次处理，需限制单批次输入规模；文档字段的行业标准化要求模型需精准识别许可限值、排放口等专业字段，避免匹配错误；不同文档的审核逻辑差异大，需灵活配置模型的任务适配参数，确保审核结果符合生态环境管理的严谨规范。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配排污许可类文档的长文本结构，覆盖多份审核文档拼接后的上下文需求 |
| `maxTokens` | 2000–3000 token | 满足单份审核文档的输出校验长度，避免截断关键合规判定内容 |
| `quoteMaxToken` | 1500 token | 限定引用源文档的片段长度，确保审核依据的准确性与可读性 |
| `temperature` | 0.1–0.3 | 降低审核结果的随机性，保障合规判定的一致性，符合政务审核的严谨要求 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的专属地址填写 | 适配国内模型直连或中转调用的网络环境要求 |
| `AIPROXY_API_TOKEN` | 按获取的有效令牌填写 | 保障模型调用的身份合法性，避免无效令牌报错 |

## 容易做错的三处
- 现象：调用国内模型时返回无效令牌报错，oneapi测试正常。原因：未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，直连时未适配国内模型的接口格式要求。
- 现象：reranker模型调用后显存占用快速升至6-7G且多GPU占用。原因：未限制`maxContext`或`maxTokens`的合理取值，导致模型加载过多上下文数据。
- 现象：配置完成后审核结果出现字段匹配错误。原因：未针对排污许可的专业字段调整模型的上下文范围，导致模型混淆非标准化字段与合规判定字段。

## 怎么确认配好了
- 发起单份排污许可证申请表的审核测试，核对返回结果是否包含许可限值、排放口等核心字段的校验结论。
- 调用通用连通性测试工具测试目标模型的连通性，确认令牌与接口地址配置无误后，再接入FastGPT平台。
- 调整`temperature`参数，对比两次审核结果的差异，确认参数生效。
- 提交批量季度更新的文档，检查模型处理的批次规模是否符合预设配置，无明显超时或内容截断情况。
