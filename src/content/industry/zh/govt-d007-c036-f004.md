# 政务服务事项目录与办事指南维护的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
该品类的核心数据来源于国家政务服务事项基本目录、行政许可事项清单、权责清单及地方政务服务事项库，更新频率为月度。日常维护的文档包含政务服务事项基本目录、实施清单、办事指南、标准材料目录、流程图与常见问题，数据字段涵盖事项编码、事项名称、受理条件、申请材料清单、办事流程等，单份事项文档的字段数量较多，且需与上级目录保持统一口径。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源包含国家级与地方级政务目录，工作流需配置跨源数据拉取步骤，确保本级事项与上级目录的口径一致。月度更新的节奏要求工作流支持定时触发批量任务，减少人工重复操作。多字段且需校验完整性的文档结构，要求工作流嵌入字段校验节点，拦截不符合规范的事项数据。同时，比对上级目录与本级实施清单的耗时环节，需拆分任务为单事项处理单元，防止单节点运行超时影响整体流程。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定工作流全局token与事项编码变量 | 满足MCP工具调用时传递全局参数的需求 |
| 工具调用触发规则 | 按节点输出结果自动触发 | 适配模型自主选择工具调用的业务场景 |
| 单节点超时时间 | 600秒 | 匹配单次比对上级目录与本级清单的合理耗时上限 |
| 字段校验阈值 | 800–1200字符 | 匹配办事指南字段的标准长度要求 |
| 钉钉webhook请求超时 | 30秒 | 避免长时间等待导致工作流阻塞 |
| `nodeId` | 绑定校验节点与数据拉取节点的ID | 精准控制工作流的流转顺序与执行逻辑 |

## 容易做错的三处
- 现象：工作流调用MCP工具时全局变量为空，日志显示「未找到目标变量」。原因：未在`variables`配置项中绑定需要传递的token或事项编码变量。
- 现象：工作流无法自动触发工具调用，始终执行固定流程。原因：未配置按节点输出结果自动触发工具调用的规则，仅设置了手动触发。
- 现象：钉钉webhook未推送异常通知，日志显示「请求成功但无消息」。原因：未配置钉钉webhook的触发条件为节点失败，仅设置了节点完成时触发。

## 怎么确认配好了
- 手动触发单事项维护工作流，查看MCP工具调用日志，确认全局变量的token和事项编码已正确传递。
- 模拟节点校验失败的场景，检查钉钉webhook是否推送了异常通知至指定接收渠道。
- 调整工作流节点的流转顺序，验证`nodeId`配置是否生效，流程是否按预期跳转。
- 触发批量更新任务，查看单节点运行时长，确认未超过预设的600秒阈值。
