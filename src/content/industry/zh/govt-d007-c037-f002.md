# 政府信息依申请公开的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自政府信息公开平台、机关档案系统、公文系统、部门业务台账及《政府信息公开条例》相关规范文档。日常处理的文档包括政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证与行政复议答辩材料，单份文档多包含申请编号、申请内容、答复文号、第三方反馈等固定字段。数据更新无固定周期，随个案申请与归档流程不定期新增或修订。

## 这些特征在「向量模型与索引」这一环带来什么约束
制式文书的字段固定但单份内容长度差异显著，要求向量分块需适配短至百字符、长至数千字符的文本，避免破坏申请内容、答复依据等核心信息的完整性。多来源数据的格式差异，要求索引构建前需统一标准化预处理，消除不同系统导出文档的格式偏差。数据更新无固定周期，需支持增量索引与批量重嵌入操作，适配突发的模型更换或数据修订。个案办理的时效性要求，限制了向量检索的单次耗时上限，需平衡召回精度与响应速度。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配制式文书的平均内容长度，避免核心信息被拆分 |
| 重叠长度 | 100–200 字符 | 保留分块间的上下文关联，保障申请内容的语义连贯性 |
| `maxToken` | 4096 token | 适配主流嵌入模型的上下文窗口上限，避免文本截断 |
| `defaultToken` | 512 token | 适配嵌入模型的默认token输出长度，匹配政务文书的基础文本长度 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 匹配政务文书的语义相似度判断标准，平衡召回准确率与召回量 |
| 单次搜索上限 | 前 10 条 | 控制检索结果的数量，适配个案审核的信息筛选需求 |
| 最大上下文 | 8000 字符 | 限制召回内容的总长度，适配答复书起草的上下文长度要求 |

## 容易做错的三处
- 知识库批量重嵌入后召回率无明显改善。原因是未针对政务文书的专业术语调整嵌入模型的领域适配参数，或未先清理旧索引直接执行重嵌入操作。
- 手动插入的文档生成的索引数小时后自动消失。原因是未开启增量索引的持久化配置，或文档格式不符合平台的制式校验规则，导致系统自动清理异常索引。
- 接入指定嵌入模型后文件长期显示「索引中」状态。原因是未配置模型的访问超时参数，或`defaultToken`设置超出模型支持的窗口上限，导致嵌入任务无法正常完成。

## 怎么确认配好了
- 上传一份标准的政府信息公开申请表，检查分块后的文本片段是否保留了申请人信息与申请内容的核心语义。
- 执行一次批量重嵌入操作，查看任务日志中是否有`maxToken`超限的报错提示，确认参数适配所选嵌入模型。
- 手动插入一份答复书文档，等待索引构建完成后，检索该文档的申请编号关键词，确认检索结果包含该文档且索引未自动消失。
- 调整相似度阈值至区间下限，检查检索结果的召回数量是否符合业务筛选需求，再调整至上限确认精度是否达标。
