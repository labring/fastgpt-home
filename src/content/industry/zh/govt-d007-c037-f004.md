# 政府信息依申请公开的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
本品类数据来源于政府信息公开平台、机关档案系统、公文系统、部门业务台账及《政府信息公开条例》相关规范，更新频率不定期。日常处理的文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料，核心字段涵盖申请人身份信息、申请事项描述、信息指向范围、公开属性判定结果、答复意见及法定救济途径等。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新无固定周期，要求工作流支持多源数据拉取与临时缓存机制，避免依赖单一数据源导致的信息缺失。文档类型多样且结构差异显著，需配置可灵活调整的解析节点适配不同格式的申请材料与案卷。核心字段涉及法定办理要件，工作流需强制校验关键信息完整性，防止遗漏法定内容。单次办理需符合法定时限要求，需设置超时提醒与异常中断节点，避免超期风险。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 批量执行节点循环间隔 | 10–30 秒 | 适配案卷审核的多文档并行处理节奏，避免系统资源过载 |
| 单次循环处理文档数 | 前5条 | 适配政务审核的单批次处理节奏，避免任务积压 |
| `variables` 绑定规则 | 按申请材料字段映射绑定 | 确保核心法定字段（如申请人信息、申请内容）准确传递至大模型节点 |
| 节点超时设置 | 600 秒 | 覆盖检索、判定、答复起草全流程的单次执行时长 |
| `nodeId` 关联配置 | 绑定子工作流的审核节点 | 实现案卷审核的分层校验逻辑 |
| 答复书生成字符上限 | 800–1200 字符 | 符合法定文书的篇幅要求，避免内容冗余或不足 |
| 变量引用温度设置 | 按实测标定 | 适配答复书起草的严谨性要求，避免生成内容偏离法定规范 |

## 容易做错的三处
- 批量执行节点在线调试可完成流程，但API调用时无法执行完整。原因是API调用未正确传递`variables`参数，导致循环触发的上下文未正确加载。
- 变量引用后温度设置按钮消失，无法配置生成参数。原因是部分节点的参数面板在绑定外部变量后默认隐藏模型配置项，需手动展开高级设置面板。
- 接口调用工作流后，对话日志中的运行数据为空。原因是工作流未启用全链路日志开关，或未将核心执行节点的输出绑定至日志存储节点。

## 怎么确认配好了
- 触发一次单条申请的审核流程，核对`variables`参数是否正确绑定了申请材料的核心字段。
- 测试批量执行节点的循环逻辑，确认每个循环步骤的输出均能正确传递至下一节点。
- 检查工作流的超时设置，确认超时阈值符合本品类的法定办理节奏要求。
- 调用API触发流程，核对对话日志中是否生成了完整的运行数据与节点输出。
