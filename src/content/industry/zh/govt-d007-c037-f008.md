# 政府信息依申请公开的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
本品类的数据来自政府信息公开平台、机关档案系统、公文系统及部门业务台账，更新频率不定期。日常处理的文档包含制式化的政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料。文档多为固定结构，包含申请人信息、申请事项、答复内容、送达记录等字段，部分文档附带扫描件形式的纸质材料。本品类的办理对象为特定申请人的个案请求，不同于面向全体公众的主动公开信息。

## 这些特征在「文档解析与分块」这一环带来什么约束
本品类文档的制式化与不定期更新特性，要求解析环节适配多种格式的公文与扫描件。不同文档的长度差异显著，短则数十字的申请表，长则数页的行政复议答辩材料，分块时需兼顾关键字段的完整性，避免拆分申请人信息、申请事项等核心内容。扫描件形式的纸质材料需触发OCR流程，且需处理可能出现的中文识别乱码问题。同时，数据来源分散导致文档格式不统一，需支持批量解析不同来源的文件，且需保留申请事项与答复内容的关联，避免检索时出现信息错位，影响后续的公开属性判断与答复起草工作。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的官方参数说明制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配本品类制式公文的核心内容长度，避免拆分申请人信息、申请事项等关键字段 |
| `chunkSplitter` | 按段落+语义分块 | 保留文书的逻辑完整性，符合政务文档的阅读与检索习惯 |
| `customPdfParse` | 开启 | 适配制式PDF公文的固定格式，准确提取文本与排版信息，减少解析误差 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对长文档如行政复议答辩材料的解析耗时，避免任务中途中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容批量导入的档案扫描件包，满足日常批量处理需求 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型调整分块参数，适配本品类多样的文档结构 |

## 容易做错的三处
- 上传扫描件图片后无法识别内容，现象是上传图片格式文件后解析结果为空或出现中文乱码，原因是未配置适配政务扫描件的OCR参数，未启用中文识别模型。
- 单篇PDF文档检索无匹配结果，现象是针对单篇导入的答复书发起提问时，模型返回未找到相关内容，原因是分块时误拆分了核心答复内容与申请事项的关联。
- 导入结构化表格数据后字段对应失效，现象是检索台账数据时返回无关字段内容，原因是未配置数据集的字段映射规则，未指定需检索的核心字段如申请编号、答复文号。

## 怎么确认配好了
- 上传一份典型的政府信息公开申请表，检查解析结果是否完整提取申请人信息与申请事项字段。
- 导入一份扫描件形式的答复书，检查OCR结果是否无明显中文乱码。
- 针对单篇导入的行政复议答辩材料，发起针对性提问，检查模型是否能返回对应段落的内容。
- 上传最大允许大小的文件包，检查解析任务是否在设定的超时时间内完成。
