# 政府信息依申请公开的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源为政府信息公开平台、机关档案系统、公文系统、部门业务台账及政府信息公开相关规范文件，更新频率不定期。日常处理的文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料，文档字段涵盖申请人信息、申请事项、公开属性判断依据、救济途径说明等，单份文档长度存在明显差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散导致需对接多系统获取申请材料与案卷数据，不定期更新要求配置按需触发的知识库同步机制。多类型文档的字段结构差异，要求模型适配不同文档的解析逻辑，避免字段提取偏差。单份文档长度跨度大，需调整上下文承载参数以适配不同体量的案卷内容。核心业务为判断特定申请信息的公开属性，需将模型任务锚定政务公开相关的合规判断场景，避免泛化处理。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配政务案卷多文档拼接的上下文需求，避免截断核心合规判断依据 |
| `maxTokens` | 4000–6000 token | 匹配单份答复书或申请材料的常规长度，平衡输出内容与处理效率 |
| `quoteMaxToken` | 1500 token | 限定引用案卷原文的长度，确保检索到的依据信息完整且不溢出上下文 |
| `temperature` | 0.1–0.3 | 降低生成随机性，保障政务答复的合规性与表述一致性 |
| `AIPROXY_API_ENDPOINT` | 按本地化部署的代理地址填写 | 实现模型调用的安全中转，适配政务场景的网络隔离要求 |
| `AIPROXY_API_TOKEN` | 按代理服务分配的密钥填写 | 保障模型调用的身份验证，符合政务系统的安全规范 |

## 容易做错的三处
- 模型输出截断关键合规依据，原因是`maxContext`参数取值过低，未适配多案卷拼接后的上下文总长度。
- 流式返回结果与知识库调用参数无法同步解析，原因是未配置统一的上下文传递链路，导致检索依据与生成答复的关联断裂。
- 视觉模型调用失败或无法解析扫描版申请材料，原因是未正确配置`vision`参数与本地化模型的接入路径，未适配政务场景扫描件格式。

## 怎么确认配好了
- 提交单份政府信息公开申请表，核对模型返回的上下文引用是否覆盖申请事项核心内容，无异常截断。
- 多次调用模型生成同一申请的答复书，核对输出内容表述一致性，无明显随机偏差。
- 配置代理地址与密钥后，发起模型调用请求，确认返回状态码正常且无身份验证相关报错。
- 上传扫描版申请材料，核对视觉模型是否能正确提取其中文字信息，无识别缺失。
