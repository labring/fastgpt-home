# 政府信息依申请公开的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来自政府信息公开平台、机关档案系统、公文系统、部门业务台账及政务公开相关规范。日常文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料。数据更新频率不定期，无固定同步周期。文档以结构化表单与非结构化正式文本混合为主，核心字段包含申请人信息、申请事项、答复内容、公开属性认定依据等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源数据来源要求检索需支持跨数据集调用，覆盖不同系统存储的文档内容。不定期更新要求检索配置需适配增量同步逻辑，避免召回过期或未归档的文档。混合结构文档要求检索模型兼顾结构化字段与非结构化文本的特征，保证对申请事项关键词的精准匹配。核心业务目标为确认指定政府信息是否存在，要求召回结果具备高置信度，同时需限制无关结果的干扰，避免影响审核效率与准确性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，适配政务公开场景的知识库检索与召回需求，具体配置项及依据如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配政务文档的关键词密度与语义关联，避免过低导致无关行政文档混入，过高遗漏符合申请事项的有效信息 |
| `limit` | 前 8 条 | 适配单份案卷审核的上下文长度限制，避免超出大模型输入上限，同时保证覆盖足够的相关文档片段 |
| `searchMode` | 语义+关键词混合检索 | 兼顾政务文档的结构化字段与非结构化答复内容，提升申请事项的匹配精度 |
| `usingReRank` | 开启 | 对初始召回结果进行二次排序，过滤低相关性内容，符合审核环节的高置信度要求 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 避免自动扩展查询导致偏离申请人的具体申请事项，保证检索精准匹配核心诉求 |
| `collectionIds` | 按业务场景绑定指定数据集 | 限定检索范围至当前部门的政务公开相关数据集，避免跨部门无关数据干扰审核流程 |

## 容易做错的三处
- 现象：上传政务文档时提示`fail to create post presigned url`报错，文件上传状态显示失败。原因：迁移S3存储后未正确配置跨域资源共享规则，或存储桶写入权限未开放。
- 现象：检索返回结果条数远少于预期，仅返回少量相关文档。原因：`similarity`阈值设置过高，过滤了符合语义关联的有效结果，或`limit`参数取值过低。
- 现象：无法限定检索范围至指定数据集，默认检索全量知识库内容。原因：未正确配置`collectionIds`参数，或未在检索请求中绑定指定数据集ID。

## 怎么确认配好了
- 上传单份政务文档，确认无`fail to create post presigned url`类报错，文件状态显示为已完成。
- 输入典型的政府信息公开申请事项，核对召回结果是否包含对应文档片段，且`similarity`分值处于预设区间内。
- 查看检索配置面板，确认`usingReRank`、`datasetSearchUsingExtensionQuery`等参数设置与预设方案一致。
- 限定检索范围至指定数据集，输入非该数据集内的关键词，确认无无关结果返回。
