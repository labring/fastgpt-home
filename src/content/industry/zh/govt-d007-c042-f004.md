# 法务合规与重大风险管理的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
本品类的核心数据来自企业合同管理系统、合规风险数据库、法律法规库、案件管理系统与举报平台，更新频率为月度。日常处理的文档包含合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告，文档多包含主体信息、风险描述、审核意见、处理结果等字段，部分为结构化表单，部分为非结构化文本。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且月度更新，要求工作流需支持对接多系统接口，且需适配不同数据源的格式差异。文档类型混杂结构化与非结构化，需在工作流中配置适配不同文档的解析节点。出错后果严重，要求工作流需设置前置校验与异常拦截环节，避免错误流程触发。耗时环节集中在风险识别与审查，需在工作流中为高耗时节点配置进度留存机制，同时需支持按业务节点分支流转，适配不同类型申报材料的审核路径。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本适配：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配合规审查表、法律意见书等非结构化文档的语义完整性，避免块内语义断裂 |
| 相似度阈值 | 0.75–0.85 | 匹配合规风险清单、法律法规库中的精准条目，减少无关召回结果 |
| 单次搜索上限 | 前 10 条 | 控制检索返回量，适配法务审核场景下的精准匹配需求，避免信息过载 |
| variables | 按业务场景预设 | 用于存储申报主体、审核节点状态等业务变量，支持工作流分支流转 |
| nodeId | 按审核环节绑定 | 用于标记不同审核节点的唯一标识，便于异常排查与流程回溯 |
| 最大上下文 | 前 3 轮对话 | 适配法务审核中仅需近期申报材料与历史审核意见的场景，减少冗余信息干扰 |

## 容易做错的三处
- 现象：工作流执行至某节点后无报错提示且未进入后续环节。原因：未配置`variables`变量的默认值，导致分支判断条件无法触发，流程卡在当前节点。
- 现象：知识库检索未按预设标签筛选结果，返回无关文档。原因：未在检索节点中绑定对应业务标签的`variables`参数，未将标签作为检索过滤条件。
- 现象：工作流中配置聊天记录上限为1条，仍检索到超过1条的历史对话内容。原因：未限定上下文检索的时间范围，仅限制了返回条数，导致召回历史较早的匹配记录。

## 怎么确认配好了
- 对接企业合同管理系统等数据源后，执行测试工作流，检查是否能正常拉取对应文档，验证数据源配置正确性。
- 触发不同类型的申报材料审核流程，确认工作流能按预设分支进入对应审核节点，验证`variables`与`nodeId`配置有效性。
- 模拟知识库检索场景，输入包含特定标签的查询词，检查返回结果是否符合预设标签过滤要求，验证检索配置正确性。
- 调整聊天记录上下文参数后，验证检索结果仅包含符合时间范围的历史内容，验证上下文配置合理性。
