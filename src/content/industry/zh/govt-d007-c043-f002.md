# 特种设备安全监管的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
特种设备安全监管场景的数据覆盖使用登记证、定期检验报告、维保记录、隐患整改通知书、事故报告、作业人员证书等类型，来源为特种设备安全监察系统、检验检测机构系统、使用单位台账及作业人员证书库。数据更新频率为月度，单份文档包含设备编号、检验周期、维保单位、作业人员资质编号、整改时限等字段，核心字段为结构化与半结构化混合形式，数据体量随监管区域设备数量递增。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的数据集要求索引流程支持增量同步，避免全量重建耗时过长。多类型文档混合的结构，需要针对不同文档类型适配分块规则，避免长文本截断关键字段。设备编号、检验周期等强关联字段，要求索引时保留字段级关联信息，防止检索时跨文档匹配错误。高风险监管属性决定了检索召回的准确性要求高于普通场景，需限制无关内容的干扰，同时需遵循`maxToken`和`defaultToken`的输入限制，适配不同长度的特种设备文档。

## 配置怎么定
本配置基于 FastGPT v4.17.0 版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配单份文档内的设备信息、检验周期等核心字段的完整语义 |
| 重叠长度 | 100–150 字符 | 保留跨分块的检验周期、设备编号等关联信息，避免语义断裂 |
| `maxToken` | 4096 token | 匹配开源嵌入模型的最大输入限制，确保长文档分块后完整嵌入 |
| `defaultToken` | 512 token | 配置短文本（如作业人员证书编号）的默认嵌入长度，避免截断关键标识 |
| 相似度阈值 | 按实测标定 | 结合高风险监管场景的召回精度要求，避免漏检或误匹配 |
| 单次搜索上限 | 前 8 条 | 平衡检索效率与召回完整性，覆盖多份关联文档的检索需求 |

## 容易做错的三处
- 现象为索引任务在控制台显示超时状态，耗时超过预设阈值，原因是未配置增量索引流程，仍执行全量数据集重建，导致月度更新的大量冗余数据被重复处理。
- 现象为检索结果中出现非特种设备类文档，原因是未针对本品类的文档类型设置专属的数据源过滤规则，将其他监管品类的数据集纳入了索引范围。
- 现象为作业人员资质字段无法被精准匹配，原因是分块时未保留证书编号、资质有效期等关键结构化字段，导致向量嵌入丢失了核心标识信息。

## 怎么确认配好了
- 查看索引日志，确认仅同步当月更新的特种设备文档，验证增量索引配置生效。
- 输入包含设备编号或检验周期的查询语句，核对检索结果是否包含对应设备的定期检验报告、维保记录，验证字段关联配置正确。
- 调用嵌入模型测试接口，上传单份作业人员证书文档，确认返回的向量结果与通用领域模型的输出存在差异，验证嵌入模型选型正确。
- 查看索引任务的耗时统计，确认单批次索引未超出合理范围，验证分块与索引流程的效率配置合理。
