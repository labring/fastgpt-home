# 特种设备安全监管的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类的数据覆盖特种设备全生命周期相关文档，包括使用登记证、定期检验报告、维保记录、隐患整改通知书、事故报告、作业人员证书。数据来源为特种设备安全监察系统、检验检测机构系统、使用单位台账、作业人员证书库，更新频率为月度。单份文档包含设备唯一编号、检验有效期、维保单位名称、作业人员证号等结构化字段，部分报告如定期检验报告包含表格化的检验项目与结果数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的业务数据来源分散且格式差异较大，多系统对接要求模型接入需兼容多源数据的统一解析。月度更新频率要求向量库与模型上下文需适配周期性的文档增量更新，避免数据滞后影响审核时效性。核心审核环节需精准提取设备编号、检验周期、资质证件编号等强校验字段，对模型输出的准确性要求较高。高风险监管属性要求模型调用链路需稳定可靠，避免因配置错误导致审核流程中断，引发设备停用或行政处罚风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多份案卷文档拼接后的总长度，避免关键审核信息被截断 |
| `maxTokens` | 2000–3000 token | 满足单份审核报告的完整输出需求，覆盖资质核对与整改结论的全部内容 |
| `quoteMaxToken` | 1000–1500 token | 限制单份引用文档的长度，聚焦核心审核字段 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保设备编号、检验周期等结构化字段提取的一致性 |
| `AIPROXY_API_ENDPOINT` | 云平台大模型提供的专属API地址 | 适配私有化部署下的云大模型调用链路，兼容OneAPI的转发配置规则 |
| `AIPROXY_API_TOKEN` | 与云平台模型提供商生成的密钥完全一致 | 确保模型调用的鉴权通过，匹配OneAPI中已验证的访问参数 |

## 容易做错的三处
- 测试模型时返回404错误，原因是模型ID填写与FastGPT内部识别的标识不匹配，未同步云平台模型提供商的实际模型标识。
- 容器出现`Api response error: /api/core/ai/model/test?model=Doubao-l`报错，原因是`AIPROXY_API_ENDPOINT`配置未包含完整的API路径，或`AIPROXY_API_TOKEN`权限范围不足。
- 模型推理效果与云平台原生调用存在差距，原因是`temperature`取值过高，或`maxContext`未覆盖业务文档的实际拼接长度。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型提供商管理页面，点击已配置模型的测试按钮，确认返回正常的结构化响应内容。
- 导入单份特种设备定期检验报告，触发自动审核流程，检查输出结果中是否准确提取设备编号、检验有效期等核心字段。
- 调整`temperature`参数并对比两次审核结果，确认字段提取结果无明显随机波动。
- 查看FastGPT容器运行日志，确认无模型调用相关的404或鉴权报错。
