# 特种设备安全监管的申报材料与案卷审核：部署与升级

## 这个品类的数据长什么样
该品类的数据来自特种设备安全监察系统、检验检测机构系统、使用单位台账及作业人员证书库，更新频率为月度。日常处理的文档包含使用登记证、定期检验报告、维保记录、隐患整改通知书、事故报告及作业人员证书，文档字段涵盖设备编号、检验周期、维保单位资质、作业人员持证信息等，无统一固定单位，需匹配各文档自身的字段规范。

## 这些特征在「部署与升级」这一环带来什么约束
月度更新的数据要求部署时配置稳定的增量同步机制，避免全量拉取占用过多系统资源。多来源的异构文档需适配不同格式的解析规则，确保各类材料的字段提取准确性。高风险设备的审核容错要求严格，部署环节需预留足够的校验节点。不同主体的台账格式差异，要求升级时保留灵活的字段映射配置，避免适配成本过高。同时，审核环节的耗时痛点，要求部署时优化批量数据处理的效率，减少等待时长。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 指向特种设备监管专属数据库的连接地址 | 隔离敏感监管数据，避免跨业务数据泄露风险 |
| `REDIS_URL` | 部署为3节点高可用集群，连接超时设为300秒 | 支撑月度批量数据同步的缓存读写需求，保障同步过程不中断 |
| `STORAGE_S3_ENDPOINT` | 对接本单位内部合规对象存储服务的端点 | 用于归档申报材料与案卷，符合内部数据存储管理要求 |
| `DB_MAX_LINK` | 设为20–30条 | 适配多来源数据库的并发连接上限，避免单个同步任务占用过多系统资源 |
| `FILE_TOKEN_KEY` | 使用本单位统一的文件访问鉴权密钥 | 限制仅授权审核人员可访问相关文档资源 |

## 容易做错的三处
- 现象：批量同步案卷时出现Request Time报错，日志显示连接超时。原因：未针对批量数据处理调整`REDIS_URL`的超时设置，缓存连接在批量任务未完成时提前断开。
- 现象：工具调用失败，无法完成作业人员资质校验。原因：未正确配置`ROOT_KEY`权限，导致代理工具无法访问监管数据库的校验接口。
- 现象：同步后的案卷数据存在字段缺失或格式错乱。原因：未适配特种设备监管文档的异构格式，直接使用通用解析规则导致字段提取不准确。

## 怎么确认配好了

- 登录`FE_DOMAIN`对应的管理后台，检查数据库连接状态，确认`MONGODB_URI`和`PG_URL`的连接正常。
- 触发一次测试性的增量同步任务，查看同步日志，确认数据拉取、解析、存储流程无报错。
- 发起一次资质校验的工具调用测试，确认请求可正常触发并返回校验结果。
- 验证文件访问权限，使用非授权账号尝试访问案卷文档，确认无法获取相关资源。
