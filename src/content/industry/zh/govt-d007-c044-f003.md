# 环境执法与监测监管的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据主要来自在线监控平台、污染源自动监测数据、生态环境执法系统及第三方检测报告，更新频率为每日。日常处理的文档包含现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书，文档字段涵盖监测点位、检测指标、检测结果、执法时间、整改要求等核心内容，单份文档长度差异较大，从数百字符到数千字符不等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的数据源要求多轮对话流程需实时拉取最新监测与执法数据，避免使用过期信息。多样的文档类型要求提示词需明确区分现场记录、检测报告、执法文书的处理规则，避免混淆字段含义。多字段的文档结构要求多轮对话需按环节逐步引导用户补充或确认信息，减少遗漏。执法与监测的出错后果直接关联合规性，提示词需加入数据比对校验逻辑，确保结果符合监管要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 覆盖单份执法文书及多份关联文档的核心内容 |
| 多轮对话上下文保留规则 | 按对话轮次保留前10轮内容 | 匹配执法审核中逐步递进的信息补充逻辑 |
| `variables` 变量绑定 | 绑定监测点位、执法时间字段 | 快速调用已存储的执法系统基础数据 |
| 提示词模板分段加载 | 开启 | 适配现场检查记录、监测报告等不同类型文档的差异化处理 |
| 对话超时时间 | 600 秒 | 给予充足时间完成多份检测报告的比对与审核 |
| 表单弹窗触发规则 | 按对话节点触发 | 避免嵌套工作流中弹窗异常显示 |

## 容易做错的三处
- 现象：调用外部应用或插件后，对话日志无对应交互记录。原因：未在工作流中开启对话日志同步配置，仅执行了接口调用未绑定对话上下文。
- 现象：嵌套工作流中的表单输入节点弹窗持续显示，无法自动隐藏。原因：表单弹窗触发规则未适配嵌套场景，默认按独立工作流逻辑触发弹窗，未继承父工作流的隐藏规则。
- 现象：对话框内无法渲染可点击的网页内容或直接输出文生图结果。原因：未开启富文本渲染配置，且未配置文生图模型的输出格式适配对话框展示规则。

## 怎么确认配好了
- 触发一次完整的执法案卷审核流程，查看对话日志是否包含所有环节的交互记录，确认`variables`绑定的字段、`chatId`关联的案卷标识、`messages`存储的对话内容是否符合配置要求。
- 将配置好的应用嵌套进测试工作流，触发表单输入节点，确认弹窗自动隐藏，符合预期显示规则。
- 上传多份不同类型的执法文档，测试多轮对话流程，确认提示词能正确区分文档类型并执行对应校验逻辑。
- 等待600秒以上的长流程测试，确认对话未出现超时报错，完成所有数据比对环节。
