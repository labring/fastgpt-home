# 环境执法与监测监管的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类涉及的文档包括现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书。数据来源于在线监控平台、污染源自动监测数据、生态环境执法系统、第三方检测报告，更新频率为每日。文档结构多包含工况参数、监测数值、执法时间、责任主体等字段，部分监测报告需对应采样点位、污染物浓度等带单位的量化数据，单份文档的字符长度差异较大，从数百到数千字符不等。本文档基于FastGPT v4.17.0版本编写。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的实时监测数据要求模型接入支持稳定的高频调用，避免单次请求超时。多类型文档混合处理需配置适配不同格式的上下文参数，确保现场记录的口语化内容与正式执法文书的规范字段均可被准确识别。带单位的量化数据需模型能准确匹配数值与污染物类型，因此需明确上下文的token限制，避免截断关键数据。同时，执法文书的严谨性要求模型输出需关联原始数据来源，需配置相关的引用参数，确保审核结果可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 需容纳多份现场记录、监测报告的完整内容，避免截断关键执法数据 |
| `maxTokens` | 2000–3000 token | 用于生成审核结论或执法文书补充内容，匹配单份文书的常规输出长度 |
| `temperature` | 0.1–0.3 | 审核场景需严谨输出，降低随机性，确保监测数据与判定结果的一致性 |
| `AIPROXY_API_ENDPOINT` | 填写FastGPT部署的代理接口地址 | 适配自建或托管的模型调用链路，确保数据不直接暴露 |
| `AIPROXY_API_TOKEN` | 使用环境变量注入的密钥 | 避免硬编码泄露凭证，符合安全合规要求 |
| `toolChoice` | auto | 自动选择是否调用工具，适配在线数据比对、文档解析等多环节需求 |

## 容易做错的三处
- 现象为调用百度系模型时返回参数不支持错误，原因是未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或代理链路未适配对应模型的协议格式。
- 现象为模型调用无日志输出，无法排查参数异常，原因是未在配置中开启请求日志的打印功能，未添加链路日志中间件。
- 现象为多模态模型调用时返回参数校验失败，原因是未正确设置`maxTokens`或`temperature`的取值区间，超出模型支持的参数范围。

## 怎么确认配好了
- 发起单次测试调用，传入预设的现场检查记录与对应监测数据，核对返回的审核结论是否关联原始数据字段。
- 查看接口调用日志，确认代理接口与密钥的参数已正确携带在请求头中。
- 调整`temperature`参数值，观察输出结果的稳定性变化，验证参数生效逻辑。
- 提交批量测试请求，确认调用链路无持续报错，适配高频数据更新的场景需求。
