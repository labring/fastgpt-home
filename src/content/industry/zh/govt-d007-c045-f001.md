# 用地预审与规划许可的申报材料与案卷审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类业务数据来源为国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。日常产生的文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，数据结构围绕项目选址、用地规模、规划管控要求展开，包含项目唯一标识、坐标范围、许可生效条件等核心字段。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据多源跨部门且更新无固定周期，要求HTTP接口支持多源数据拉取与跨系统格式兼容；文档包含结构化许可文件与非结构化图纸，需接口支持字段级解析与图片内容提取；核心数据直接关联项目审批全流程，接口调用失败会直接影响项目立项与开工，需配置严谨的重试机制与异常告警逻辑，保障审核流程不中断。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `Authorization` | `Bearer {FastGPT 平台分配的 API 密钥}` | 符合自然资源系统接口的鉴权规范，保障数据调用的安全性 |
| 请求超时时间 | 600 秒 | 用地预审数据拉取涉及跨部门接口，单次请求耗时较长，避免因超时中断审核流程 |
| `variables` | 绑定项目编号、红线坐标范围等业务变量 | 适配不同项目的个性化查询需求，精准匹配对应案卷与申报材料数据 |
| `responseData` | 按结构化字段提取业务内容，包含图纸链接与文本信息 | 标准化解析自然资源部门返回的文档数据，便于后续审核校验 |
| 重试次数 | 2–3 次 | 应对跨部门接口的临时波动，减少单次请求失败导致的流程中断 |
| 数据拉取触发时机 | 按项目申报节点触发 | 匹配用地预审与规划许可的审批流程，避免无效数据拉取 |

## 容易做错的三处
- 调用接口后返回空的业务字段。原因：未在`variables`中绑定项目唯一标识参数，无法匹配对应项目的申报材料与许可文档。
- 接口请求持续超时。原因：请求超时时间设置过短，未适配跨部门自然资源系统接口的平均响应时长。
- 对接外部文档系统后无法提取图片内容。原因：未配置`responseData`的图片解析规则，仅提取了文本格式的文档内容。

## 怎么确认配好了
- 发起测试请求，传入预设的项目变量，核对返回的`responseData`是否包含对应品类的核心业务字段。
- 模拟接口延迟场景，验证系统是否触发预设的重试机制，未出现直接报错。
- 对接外部文档系统后，查询包含图纸的文档，确认图片内容可被正常提取。
- 检查`Authorization`参数配置，确认未出现鉴权失败的报错日志。
