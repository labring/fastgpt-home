# 用地预审与规划许可的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
本品类的数据主要来自国土空间规划一张图、项目审批监管平台、土地利用现状库与生态保护红线数据，更新频率不定期。日常处理的文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件等，字段涉及项目选址范围、用地规模、规划管控要求、前置审批条件等。部分图纸类文档需先转写为结构化文本后才可接入索引，单文档长度差异显著，短则数百字符，长可达数万字符。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据来源分散，包含结构化审批表单与图纸转写的非结构化文本，索引需兼容两类数据格式。更新频率不定期，要求索引支持增量同步，避免全量重建耗费过多资源。文档涉及地理空间类专业术语，向量模型需能准确识别选址范围、用地红线等专属表述。文档长度差异显著，分块时需兼顾专业术语完整性与语义连贯性，防止关键管控要求被拆分断裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200字符 | 适配本品类专业术语的语义长度，避免将完整的规划管控要求拆分，确保审核时可精准命中相关条款 |
| 分块重叠长度 | 100–200字符 | 弥补分块可能导致的语义断裂，确保跨分块的红线管控表述可被完整检索 |
| `maxToken` | 4096 token | 适配FastGPT v4.17.0主流向量服务的输入上限，确保长文本转写的红线图内容可完整向量化 |
| `defaultToken` | 512 token | 适配本品类短审批文档的向量化需求，平衡精度与接口调用效率 |
| 相似度阈值 | 按实测标定 | 匹配本品类行政审批的严谨性要求，避免误召回无关的用地管控内容 |
| 单次搜索上限 | 前10条 | 控制返回结果规模，适配精细化审核的核对需求，避免信息过载 |

## 容易做错的三处
- 现象：向量化服务调用频率过高，触发接口限流报错。原因：未配置批量切片处理，仅单条传入文本切片，未利用服务的batch批处理能力。
- 现象：检索结果无法命中精准的规划管控条款，出现大量无关召回。原因：使用通用向量模型未适配地理空间专业术语，或相似度阈值设置不合理。
- 现象：增量更新后索引未同步新的审批文档。原因：未绑定数据源的更新触发机制，仅手动执行全量索引，无法适配本品类不定期的文档更新节奏。

## 怎么确认配好了
- 上传一份典型的用地预审意见书，执行检索测试，核对返回结果是否包含该项目的规划管控要求字段。
- 模拟一次增量文档更新，查看索引系统是否自动同步新上传的审批材料，无需手动触发全量重建。
- 调用向量化服务接口，传入多个文本切片，确认服务是否支持batch批处理，降低调用频率。
- 调整相似度阈值，对比不同阈值下的召回结果，确认符合本品类审批审核的严谨性要求。
