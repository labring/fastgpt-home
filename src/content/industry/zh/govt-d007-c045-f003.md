# 用地预审与规划许可的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据主要来自国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。日常处理的文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，文档包含项目选址范围、用地规模、规划管控要求、前置审批条件等字段，无固定统一格式，需结合项目实际情况提取对应信息。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新无固定周期，要求多轮对话流程需支持定期拉取最新的国土空间规划一张图、土地利用现状库数据，确保审核依据的时效性。文档无统一格式，提示词需适配不同项目的用地预审、规划许可类文档，灵活提取核心字段。审核涉及发改、住建、生态等多部门前置条件，多轮对话需引导用户补充跨部门审批材料，同时实时校验选址与管控要求的匹配度，避免后续审核出现合规问题。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 8000–12000 字符 | 用地预审与规划许可的审核需关联多份文档与对话历史，该长度可覆盖完整的项目审核信息 |
| `chatId` | 绑定项目唯一编码 | 确保同项目的多轮对话上下文持续关联，避免跨项目的审核数据混淆 |
| `variables` | 绑定项目用地规模、红线范围等字段 | 为多轮对话提供固定的审核校验基准参数，避免重复提取文档信息 |
| `messages` | 按对话顺序传递历史交互内容 | 确保多轮对话的上下文逻辑连贯，符合审核的递进校验需求 |
| 单次展示结果条数 | 前 3 条 | 审核过程中仅需展示核心合规性校验结果，避免界面信息过载 |
| 上下文刷新间隔 | 12–24 小时 | 国土空间规划数据更新无固定周期，按周期刷新可确保审核依据的时效性 |

## 容易做错的三处
- 现象：调用对话终止接口时返回`400 Bad Request`报错，无法停止当前会话。原因：未正确绑定`chatId`参数，系统无法定位目标对话会话。
- 现象：工作流运行后展示多轮AI对话结果，未仅保留最终审核结论。原因：未配置工作流的结果过滤逻辑，未指定仅保留最后一个AI节点的输出内容。
- 现象：接入外部对话渠道后，输出内容携带大量`#`、`*`等格式标点，无法正常显示。原因：未关闭对话内容的Markdown格式渲染，导致渠道无法解析格式标记。

## 怎么确认配好了
- 发起包含多份用地预审材料的测试对话，核对上下文是否完整保留项目历史信息。
- 调用对话终止接口，验证当前会话能否正常终止，无报错返回。
- 触发工作流运行，核对最终输出仅保留最后一个AI节点的审核结论。
- 接入外部对话渠道，验证输出内容无冗余的格式标点符号。
