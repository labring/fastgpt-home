# 用地预审与规划许可的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
本品类的核心数据来自国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新不定期。日常处理的文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件等，其中红线图含空间坐标字段，规划条件含用地规模、管控指标等结构化内容，审批案卷则包含项目申报书、前置审批意见等组合文档。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且更新无固定周期，要求检索系统支持增量同步多源异构数据，避免全量重训的资源消耗。文档包含空间坐标、管控指标等结构化字段与矢量图纸、批复文本等非结构化内容，需同时支持文本语义匹配与结构化属性检索。项目选址核对、红线冲突审查是核心耗时环节，要求召回结果需精准关联规划管控规则与项目当前状态，否则易引发审批失误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配规划管控规则的精准度要求，避免低关联结果干扰审核 |
| `limit` | 前10条 | 平衡检索效率与信息完整性，覆盖核心审批依据的召回范围 |
| `searchMode` | 混合检索 | 同时支持文本语义与结构化字段匹配，适配多类型文档特征 |
| `usingReRank` | 开启 | 对初始召回结果二次排序，提升红线冲突、管控要求等关键内容的优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展查询词，覆盖项目编号、规划指标等专业术语的同义表述 |
| `collectionIds` | 对应品类专属知识库集合ID | 隔离不同品类的审批数据，避免跨品类检索干扰 |

## 容易做错的三处
- 现象：结构化审批表格的检索结果无法命中单元格内的用地规模数值。原因：未开启表格数据的多向量支持，仅对整表文本生成向量，无法精准匹配单元格级的专业字段。
- 现象：调用API拉取文档库时返回404状态码。原因：未正确配置collectionIds参数，指向了不存在的知识库集合。
- 现象：长文本规划条件的检索结果丢失上下文关联，无法匹配完整管控要求。原因：分块时未启用模型识别段落，且最大段落深度设置为3、最大分块大小设置为1000字符，导致长文本被错误拆分。

## 怎么确认配好了
- 上传一份包含结构化审批表格与规划条件文本的测试文档，查看知识库分块结果是否保留单元格级字段与管控条款上下文。
- 发起包含用地规模、生态保护红线关键词的测试查询，核对检索结果的排序是否符合二次排序的配置逻辑。
- 调用FastGPT v4.17.0的检索API，传入指定的collectionIds参数，确认仅返回对应品类的知识库内容。
- 检查知识库的同步日志，确认增量更新任务已按不定期更新的节奏自动触发。
