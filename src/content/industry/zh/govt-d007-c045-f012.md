# 用地预审与规划许可的申报材料与案卷审核：部署与升级

## 这个品类的数据长什么样
本品类的数据来源包括国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。日常处理的文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，核心字段涵盖项目选址范围坐标、用地规模参数、规划管控要求等，需关联多源空间与审批数据完成核验。

## 这些特征在「部署与升级」这一环带来什么约束
本品类的多源异构数据来源，要求部署阶段需兼容多种数据接入协议与格式解析规则，避免因数据源变更导致解析失败。不定期更新的数据特性，需支持动态调整同步频率与校验逻辑，无需重启服务即可适配新的业务数据。空间坐标、用地规模等字段的标准化校验需求，需配置针对性的字段规则。政务场景下的案卷审核业务连续性要求，升级时需预留回滚机制与灰度发布路径。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 连接政务内网专用MongoDB实例的完整地址 | 存储案卷审核的历史数据与临时解析结果，需保障内网访问权限与稳定性 |
| `REDIS_URL` | 配置为政务云专属Redis集群地址，连接超时设为300秒 | 缓存高频查询的规划管控规则与红线数据，降低多源数据源的重复调用开销 |
| `STORAGE_S3_ENDPOINT` | 对接政务云对象存储服务的终端地址 | 存储红线图、规划条件等大体积空间文档，适配政务数据存储合规要求 |
| `DB_MAX_LINK` | 80–120 条 | 适配多部门并行提交的案卷审核请求，避免数据库连接耗尽 |
| `FILE_TOKEN_KEY` | 配置为政务统一的安全令牌密钥 | 保障文档下载与解析的权限校验符合政务安全规范 |
| `ROOT_KEY` | 本地部署的管理员专属密钥 | 限制非授权人员修改审核配置，符合政务系统权限管理要求 |

## 容易做错的三处
- 现象：调用外部模型时返回连接超时错误，原因：未配置政务内网的出站代理规则，无法访问外部模型服务。
- 现象：升级后部分历史案卷无法加载，原因：未提前备份`MONGODB_URI`对应的数据库数据，升级过程中配置被意外覆盖。
- 现象：红线图解析失败，原因：未正确配置`FILE_TOKEN_KEY`的密钥参数，无法通过文档权限校验。

## 怎么确认配好了
- 登录FastGPT v4.17.0后台，查看`MONGODB_URI`的连接状态，确认显示为正常连接。
- 上传一份测试用的红线图文档，确认可以正常解析并提取空间坐标与用地规模字段。
- 发起一个模拟的案卷审核请求，确认系统可以调用配置好的模型完成内容校验。
- 检查`REDIS_URL`的缓存指标，确认高频查询的规划管控规则被正确缓存。
