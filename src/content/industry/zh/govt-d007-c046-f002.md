# 社会救助与低保审核的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自民政局救助科、街道乡镇民政办、社区居委会、核对中心等主体的日常工作文档，包括低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料、救助审批表。数据同步自低收入人口动态监测平台、居民家庭经济状况核对系统及公安、人社、医保、住建、税务的跨部门共享数据，更新频率为月度。数据字段围绕家庭经济状况、成员关系、救助资格展开，单份文档包含结构化表单条目与多页半结构化佐证材料的混合内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的批量数据要求索引支持增量同步，避免全量重建占用过多系统资源。跨部门共享数据的字段分散且格式各异，需向量模型适配多字段混合的文本结构，确保家庭收入、财产、成员关系等核心审核字段的语义匹配准确性。单份文档包含短表单条目与长段落佐证材料的混合内容，需在分块时兼顾两种文本的语义完整性，避免出现关键信息断裂。救助审核的出错后果要求索引召回结果具备高置信度，避免低匹配度的无关数据进入上下文，引发错保漏保风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 兼顾低保申请表的短字段与入户调查表的长段落，避免语义断裂或分块过小导致召回分散 |
| 重叠长度 | 100–150 字符 | 覆盖跨字段关联的语义边界，确保家庭收入与财产核对的上下文连贯 |
| 相似度阈值 | 0.75–0.85 | 适配跨部门数据的字段差异，平衡召回完整性与结果精准度，降低错保漏保风险 |
| 单次搜索上限 | 前 10 条 | 控制上下文窗口大小，符合民政审核的核心信息量级，避免冗余数据干扰审核判断 |
| `defaultToken` | `4096` | 适配多数日常审核场景的上下文长度需求，确保完整包含家庭情况与佐证材料的关键内容 |
| `maxToken` | `8192` | 处理包含多份佐证材料的案卷审核场景，满足长文本上下文的传递要求 |

## 容易做错的三处
- 现象：索引模型的可选列表无匹配选项，无法完成向量模型配置。原因：未部署对应向量模型的运行环境，或使用的FastGPT v4.17.0版本未兼容目标模型。
- 现象：召回的文档片段未标注来源文档名称与具体位置。原因：未开启元数据保留开关，分块时未将文档标识字段纳入向量化上下文。
- 现象：批量月度数据同步后出现大量与审核无关的召回结果。原因：相似度阈值设置过低，导致跨部门的低匹配度数据被纳入上下文，引发错保漏保风险。

## 怎么确认配好了
- 上传单份低保申请表与家庭经济状况核对报告，检查分块后的文本是否覆盖核心字段，无明显语义断裂。
- 提交家庭收入核对的查询问题，核对召回结果的来源标注是否完整，确认文档溯源功能正常启用。
- 导入批量月度更新的测试数据，观察索引同步的耗时与状态，确认未出现超时或异常报错。
- 调整相似度阈值的测试参数，验证召回结果的数量变化是否符合场景需求。
