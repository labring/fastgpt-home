# 社会救助与低保审核的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
本品类数据主要来自民政局救助科、街道乡镇民政办、社区居委会及核对中心的日常工作文档，包括低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料与救助审批表。数据来源于低收入人口动态监测平台、居民家庭经济状况核对系统及公安、人社、医保、住建、税务跨部门共享数据，更新频率为月度。数据字段包含家庭收入明细、财产状况、成员关系、申请事由等，无统一固定单位，随具体申报材料的格式调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多部门跨源共享的数据要求检索需支持多数据集关联召回，避免信息割裂导致的审核遗漏；月度更新节奏要求知识库同步任务需按周期触发，保障数据的时效性与准确性；多样的文档类型需适配表单、报告、公示材料的不同结构，优化分块与检索匹配逻辑；核心字段聚焦家庭经济、成员关系等审核关键项，需针对性配置检索权重，提升精准度；出错后果明确，需设置检索结果的校验环节，避免错配数据引发的错保漏保问题。

## 配置怎么定
本文配置基于FastGPT v4.17.0版本，具体配置项及建议如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 聚焦家庭经济、成员关系等核心审核字段，该区间可过滤低匹配度的无关材料，保障审核准确性 |
| `limit` | `前8–12条` | 案卷审核需覆盖申请材料、核对报告、入户调查等多类文档，该数量可平衡召回全面性与上下文长度 |
| `searchMode` | `vector + keyword` | 适配跨部门共享数据的结构化字段与非结构化审核文档，结合向量与关键词检索提升核心字段的匹配精度 |
| `usingReRank` | `开启` | 核心字段匹配权重较高，重排可进一步修正向量检索的偏差，筛选最相关的审核材料 |
| `datasetSearchUsingExtensionQuery` | `开启` | 可自动扩展审核相关的同义查询，比如将「家庭收入」扩展为「家庭经济状况」，覆盖更多相关材料 |
| `collectionIds` | `绑定对应民政救助类专属数据集` | 隔离本品类的专属数据，避免与其他政务数据集混淆，保障检索精准性 |

## 容易做错的三处
- 现象为知识库检索报错`text index required for $text query`，原因是未正确配置关键词检索的索引关联，或数据集分块后未重建索引。
- 现象为检索结果条数远少于预期，原因是`similarity`阈值设置过高，过滤了部分符合要求的跨部门共享数据。
- 现象为检索结果混入社保待遇类无关材料，原因是未通过`collectionIds`绑定专属民政救助数据集，导致检索范围覆盖了其他政务品类的数据。

## 怎么确认配好了
- 手动输入包含家庭经济状况、成员关系的查询词，核对返回结果是否覆盖低保申请表、家庭经济状况核对报告等核心审核文档。
- 查看检索配置面板，确认`usingReRank`、`datasetSearchUsingExtensionQuery`均处于开启状态。
- 触发一次临时数据同步任务，核对系统日志是否显示跨部门共享数据已成功拉取并更新至知识库。
- 测试低匹配度的非审核类查询词，确认`similarity`阈值可有效过滤无关结果。
