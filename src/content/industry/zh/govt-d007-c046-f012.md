# 社会救助与低保审核的申报材料与案卷审核：部署与升级

## 这个品类的数据长什么样
本品类的数据来源为低收入人口动态监测平台、居民家庭经济状况核对系统及公安、人社、医保、住建、税务的跨部门共享数据，更新频率为每月一次。日常处理的文档包含低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料、救助审批表，核心字段涵盖家庭收入、财产总额、家庭成员关系、救助资格判定项，所有数据需关联家庭主体，无跨主体的零散业务数据。

## 这些特征在「部署与升级」这一环带来什么约束
跨部门多源数据的接入要求部署时需配置多类型数据库连接，适配不同系统的接口格式。月级更新节奏要求部署后需配置定期同步任务，确保数据时效性。核心文档的固定字段结构，要求在部署时匹配对应的数据存储规则，避免字段遗漏或关联错误。出错后果需严格管控，因此升级环节需保留回滚机制，且需配置失败告警与日志留存规则，防止敏感审核数据泄露或处理错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 15–25 连接 | 跨部门多源数据接入需维持稳定连接池，避免频繁连接断开影响核对效率 |
| `MONGODB_URI` | 按本地部署的MongoDB实例地址填写 | 用于存储案卷审核的历史记录与临时处理数据，适配多文档的非结构化存储需求 |
| `REDIS_URL` | 配置为本地Redis服务地址，超时时间设为300秒 | 用于缓存高频访问的核对数据与会话状态，月级更新的数据缓存可减少重复调用跨部门系统的次数 |
| `STORAGE_S3_ENDPOINT` | 按本地对象存储服务的端点填写 | 用于存储上传的纸质扫描版申报材料与公示照片，适配大容量非结构化文档的存储需求 |
| `ROOT_KEY` | 按部署环境生成专属密钥 | 用于管理系统权限，确保只有授权人员可访问敏感的救助审核数据 |

## 容易做错的三处
- 上传申报材料时提示上传失败，查看日志显示文件大小超出限制。原因是未调整本地部署的文件上传阈值，默认配置仅支持较小文件，无法适配扫描版入户调查表等文档。
- 升级至FastGPT v4.17.0后，调用第三方模型渠道时出现参数异常。原因是新版本对模型渠道的配置格式做了调整，未同步更新原有关联配置。
- 配置多数据源连接后，跨部门数据同步任务频繁失败。原因是未设置合理的`DB_MAX_LINK`连接数，导致连接池耗尽无法建立新的数据库连接。

## 怎么确认配好了
- 测试上传一份2 MB左右的扫描版申报材料，确认上传成功且存储路径可正常访问。
- 运行一次家庭经济状况核对的模拟任务，查看数据同步结果是否与跨部门系统的数据源一致。
- 检查系统日志，确认数据库连接池的连接数在预设范围内，无频繁断开或耗尽的情况。
- 触发一次回滚测试，确认升级后的配置可正常回滚至之前的稳定版本。
