# 行政处罚案卷办理的申报材料与案卷审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，以违法事实认定、裁量基准适用、处罚决定内容为核心字段，所有文档均需关联对应执法主体与涉案主体信息，无额外自定义单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据特征对HTTP接口与外部系统配置带来多重约束。多源数据来源要求接口兼容不同外部系统的认证方式，适配结构化字段与非结构化影像文件的传输格式。每日更新的频率要求接口设置合理的请求周期，避免频繁调用超出外部系统负载。多样的日常文档结构要求接口传递对应执法主体、涉案主体及文书内容的映射字段，确保数据准确关联。执法案卷的合规性要求严格，接口传输需保障数据完整性与可追溯性，且需留存完整的请求与响应日志用于后续案卷评查。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 请求超时时间 | 600 秒 | 匹配行政执法办案系统的接口响应平均时长，避免长时间等待导致的流程阻塞 |
| 重试策略 | 失败后重试2次，间隔30 秒 | 应对临时网络波动或外部系统短暂不可用的场景 |
| 单次请求最大数据量 | 1000 MB | 适配执法影像文件的常规传输大小限制，避免超出外部系统接收上限 |
| `Authorization` | Bearer {执法系统API密钥} | 符合外部行政执法办案系统的标准认证规范，保障接口访问权限 |
| `variables` | 包含案件ID、证据清单、处罚决定书内容的结构化字段 | 适配行政处罚案卷的核心数据传递需求 |
| `responseData` | 包含审核状态、审核结果、错误信息的固定格式 | 便于后续案卷审核结果的自动化归集与评查 |

## 容易做错的三处
- 现象：接口调用返回`tls: failed to verify certificate: x509: certificate signed by unknown authority`报错。原因：未配置外部系统的可信证书校验规则，或使用了自签名证书未导入信任列表。
- 现象：HTTP接口接收的`variables`字段为空，无法匹配案卷核心数据。原因：未在工作流节点中正确映射行政执法办案系统返回的案件字段，或变量传递格式不符合接口要求。
- 现象：接口调用后未收到预期的审核结果反馈，返回状态码为400。原因：未按照行政处罚案卷的文档结构传递必填字段，如案件ID、证据清单等，导致外部系统无法识别请求内容。

## 怎么确认配好了
- 发起模拟请求，传入符合行政执法案卷格式的测试数据，检查接口是否返回预期的响应结构。
- 查看接口调用日志，确认`Authorization`认证信息已正确携带，请求参数与配置项一致。
- 验证外部系统是否接收到传递的`variables`字段数据，且字段内容与测试数据匹配。
- 模拟接口调用失败场景，检查是否触发预设的重试与日志留存机制。
