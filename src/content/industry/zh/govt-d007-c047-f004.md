# 行政处罚案卷办理的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
本品类数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常处理的文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证等，数据以违法事实认定、处罚依据、文书生成及送达归档为核心字段，不同执法领域的文档格式与必填项存在细分差异。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且包含非结构化的执法记录仪影像，要求工作流需支持多源数据接入与非文本内容的预处理节点。每日批量更新的办案数据要求工作流支持定时触发与批量处理机制，防止单节点执行超时。各类执法文书的固定格式与必填字段要求工作流内置格式校验规则，确保核心信息无遗漏。处罚决定的可追溯要求需保留全链路节点操作日志，同时需适配不同执法领域的文书差异，避免硬编码限制通用性。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 系统配置base_url | 对应行政执法办案系统的官方API接口地址，按实测标定 | 确保工作流节点能正常对接办案系统获取案卷数据 |
| `variables` | 将案卷编号、执法主体名称等核心信息设为全局变量，作用域覆盖全工作流 | 实现跨节点参数复用，减少重复配置成本 |
| `nodeId` | 为每个执法文书处理节点设置唯一标识，按节点功能命名 | 便于在工作流日志中快速定位对应节点的执行情况 |
| HTTP请求节点超时设置 | 设为600秒 | 适配行政执法办案系统的常规接口响应时长，避免执行中断 |
| 批量处理上限 | 设为50份/次 | 适配每日更新的办案数据规模，避免节点负载过高 |
| 非结构化数据上传限制 | 设为1000 MB/份 | 适配执法记录仪影像的常规存储规格 |
| HTTP响应内容提取 | 使用jsonPath语法匹配目标字段，提取范围覆盖响应体全层级 | 从HTTP请求返回的案卷审核结果、企业信用信息中精准提取所需字段，用于下游节点调用 |
| 工作流导出配置 | 选择包含全节点配置与变量映射的导出格式，支持按项目分类存储 | 便于跨团队复用行政执法案卷办理的工作流模板，减少重复配置工作量 |
| 问题分类节点背景知识 | 录入本品类核心执法文书类型、常见违法情形与审核标准的官方文本，单次输入不超过8000字符 | 确保分类节点能准确识别案卷审核中的问题类型，匹配对应处理规则 |

## 容易做错的三处
- 现象为HTTP请求节点配置base_url后返回连接超时或403状态码，原因是未使用行政执法办案系统的官方API地址，或未配置合法的访问权限凭证。
- 现象为JSON提取后下游节点接收的变量为空，原因是未正确使用jsonPath语法匹配响应体中的目标字段，或响应体格式与预期配置不符。
- 现象为问题分类节点无法准确识别案卷审核问题，原因是背景知识录入的文本未覆盖本品类常见审核场景，或输入内容超出字符限制。

## 怎么确认配好了
- 运行单份标准执法文书的测试工作流，检查各节点是否按预期触发并生成符合要求的中间结果。
- 查看工作流节点日志，确认`variables`配置的全局变量已正确传递至下游对应节点。
- 导出工作流配置后导入至测试环境，验证所有节点参数与变量映射关系未发生丢失或错误。
- 模拟批量数据触发工作流，检查是否能按每日更新频率正常执行，无节点超时或执行中断。
