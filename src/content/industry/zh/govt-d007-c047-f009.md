# 行政处罚案卷办理的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
该品类数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，以违法事实认定、处罚依据及决定结果为核心字段，部分文档包含执法记录仪转录的非结构化语音文本内容，单份文档的长度与结构差异较大。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且包含非结构化的语音转录内容，要求模型接入时支持多源数据整合与非结构化内容解析。文档结构多样且核心字段明确，需配置适配不同文档类型的上下文提取规则。每日更新的数据量需适配批量处理逻辑，避免接口调用超时。处罚案卷的可追溯要求，需确保模型输出可关联原始证据文档，同时出错后果严重，需配置严格的结果校验环节，避免出现处罚被撤销等问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配执法案卷多文档拼接的上下文长度需求，避免截断核心处罚依据与证据信息 |
| `maxTokens` | 4000 token | 控制单轮生成的处罚审核意见长度，确保输出符合案卷文书格式要求 |
| `quoteMaxToken` | 2000 token | 限制引用原始文档片段的长度，保证引用内容精准且不冗余 |
| `toolChoice` | auto | 自动选择是否调用工具处理执法记录仪转录的语音转写内容，适配多类型输入 |
| `temperature` | 0.2–0.4 | 降低生成随机性，确保处罚条款与裁量基准的应用符合执法规范 |
| `AIPROXY_API_ENDPOINT` | 按官方提供的专属端点填写 | 适配执法机构内部网络环境的接口调用路径，保障数据传输安全 |
| `AIPROXY_API_TOKEN` | 按实测标定的有效令牌 | 验证接口调用权限，确保仅授权服务可访问模型资源 |

## 容易做错的三处
- 现象：单轮审核生成结果重复且未覆盖全部案卷证据，连续1分钟内发起的相同请求返回结果完全一致。原因：`temperature`参数取值不当，导致模型生成逻辑固化，未结合当前案卷的独有违法事实调整输出。
- 现象：配置完成后接口调用失败，返回权限校验失败的报错文案。原因：`AIPROXY_API_TOKEN`配置错误，未使用对应执法机构的专属有效令牌，导致接口访问被拦截。
- 现象：执法记录仪的影像内容未被正确解析，审核结果未提及相关证据。原因：未开启`vision`配置项，未启用视觉识别能力处理非文本类执法证据。

## 怎么确认配好了
- 上传单份包含现场检查笔录与处罚决定书的典型案卷，触发模型审核，检查生成结果是否关联原始文档的核心证据片段。
- 连续发起2次间隔1分钟内的相同案卷审核请求，对比两次输出结果是否存在合理差异，验证`temperature`参数配置生效。
- 查看接口调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置未出现拼写错误，接口调用路径正确。
- 测试包含执法记录仪转录文本的案卷，确认模型可正确解析转录内容并纳入审核逻辑。
