# 行政许可审批的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档包含办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书、许可证照等。数据来源于全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统、电子证照库，按日更新。数据字段包含法定许可事项边界、申请材料明细、电子证照编号、审批流程节点等，需严格匹配事项设定依据与办理条件，以法定许可事项为业务边界。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源跨部门的数据来源要求模型接入支持多格式文本的上下文拼接，需配置适配长文本的参数。按日更新的数据特性要求配置项支持动态同步阈值调整，避免过期数据参与审核。法定许可事项的边界要求模型必须严格匹配预设清单，不能超出事项范围生成结果。申请材料与案卷的文本长度差异大，需配置合适的上下文参数适配长文本处理，同时需支持对法定文书的格式校验。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配申报材料、案卷的长文本拼接需求，覆盖多源政务文档的总长度 |
| `maxTokens` | 2000–3000 token | 控制单轮审核输出的审批意见或补正内容长度，符合政务文书的规范格式 |
| `quoteMaxToken` | 1500 token | 限定引用的办事指南、事项清单等参考文本的长度，避免冗余信息干扰匹配 |
| `temperature` | 0.1–0.3 | 保持审核结果的严谨性，避免生成不符合法定要求的自由裁量内容 |
| `toolChoice` | auto | 自动调用工具调取电子证照或跨部门数据，适配行政许可的多环节校验需求 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 适配FastGPT v4.17.0版本的模型部署规范，确保数据不流出政务内网 |

## 容易做错的三处
- 现象：模型运行时触发上下文截断报错，返回结果缺失部分申请材料内容。原因：未同步模型部署时的`maxContext`参数与FastGPT平台配置项，导致参数不匹配。
- 现象：开启重排模型后，审核流程出现超时提示。原因：重排模型的调用超时阈值未适配政务文档的长文本处理，或未配置合适的召回条数限制。
- 现象：流式输出中断或无返回结果。原因：未正确配置模型服务的流式支持参数，或`AIPROXY_API_ENDPOINT`的对接配置存在错误。

## 怎么确认配好了
- 上传单份完整的申报材料与对应办事指南，核对模型返回的匹配结果是否覆盖所有要求的申请材料字段。
- 调整`temperature`参数至不同区间，验证输出结果的严谨性是否符合政务审核的要求。
- 查看平台日志，确认跨部门数据调用的响应时长符合预设的业务时限要求。
- 测试重排模型的开启与关闭状态，对比审核流程的耗时变化，确认配置生效。
