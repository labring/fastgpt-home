# 规范性文件合法性审核的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类服务于司法行政部门、部门法规处、政府办公室政策法规岗，数据来自法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新频率不定期。日常处理的文档包含规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告，单份文档包含起草主体信息、条文内容、意见征集记录、备案报送材料等字段，无统一固定的计量单位，仅按文件原文的条文、段落划分内容单元。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散在多个异构数据库，多轮对话需保留当前审核的文件ID、关联上位法条目等上下文，因此需通过会话参数持久化存储对话历史与审核变量。文档结构无统一字段，提示词需适配不同格式的审核材料，无法硬编码固定的字段提取规则。数据更新不定期，每轮审核前需同步最新的法规依据，多轮对话中需引导用户依次提供草案、起草说明等必填材料，避免遗漏审核项。审核需比对制定权限、程序、条文合法性，多轮对话需逐步拆解审查步骤，引导用户补充必要的佐证材料。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 适配单份审核材料加多轮对话的上下文长度，避免截断核心条文内容 |
| 问题优化开关 | 开启 | 自动将用户的模糊审核请求转化为结构化的审查步骤，适配多轮对话的引导逻辑 |
| 单次返回条目数 | 前10条 | 限制每次返回的上位法对照条目数量，避免信息过载影响审核效率 |
| 会话变量绑定 | 绑定`chatId`、`messages`、`variables` | 保留每轮审核的会话标识、对话历史和当前审核的材料参数，确保多轮对话的上下文一致性 |
| 实时数据同步触发 | 按审核启动触发 | 适配数据不定期更新的特征，确保每次审核使用最新的法规依据 |

## 容易做错的三处
- 现象：调试预览中的合法性审查对话可正常渲染法规条文的格式，应用发布的对话框中仅显示原始代码格式。原因：未在发布配置中开启对话内容的富文本渲染规则，仅调试环境加载了对应的格式解析插件。
- 现象：使用docket部署的FastGPT实例在处理多轮案卷审核任务时，对话流程持续无响应。原因：未设置合理的会话资源回收阈值，导致批量审核的上下文堆积占用过多系统资源。
- 现象：工作流中插入的合法性审查节点结果被自动追加到最终的审核意见输出中。原因：未在节点配置中关闭“传递中间结果至下游”的开关，导致中间步骤的内容被纳入最终输出。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本的配置逻辑。
- 发起一次模拟审核请求，检查对话过程中是否自动同步最新的法规库数据。
- 查看会话日志，确认`chatId`、`messages`、`variables`参数被正确绑定并保留完整的对话上下文。
- 触发一次批量审核任务，检查对话流程是否未出现卡顿或超时现象。
- 验证发布后的对话界面是否正确渲染法规条文的格式，无原始代码残留。
