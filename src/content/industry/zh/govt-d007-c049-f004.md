# 规范性文件合法性审核的申报材料与案卷审核：工作流编排
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类的数据来源包括法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新频率为不定期。日常处理的文档包含规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告。文档结构包含完整条文内容、起草依据说明、各环节审核记录、备案相关表单，字段涵盖文件编号、起草主体、条文条款、审核意见条目、备案状态等，单文档内容长度差异较大。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源多样且更新不定期，工作流需要支持动态接入不同数据源节点，确保每次审核调用最新的法规与政策文件。日常文档结构差异大，工作流需配置多文件批量处理节点，适配草案、意见、报告等不同类型的输入内容。比对上位法和权限依据是最耗时的环节，工作流需为该节点单独设置合理的超时阈值，避免整体流程阻塞。出错后果直接影响文件备案与发布，工作流需增加校验环节，确保各节点输出符合合法性审核要求，同时支持异常时的流程回滚。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 超时时间 | `600 秒` | 覆盖上位法比对、意见汇总等最耗时的审核环节，符合本品类常规处理节奏 |
| 批量文件处理上限 | `前 10 条` | 匹配单次审核案卷材料的常规数量范围 |
| `variables` 配置 | 绑定审核材料的元数据字段 | 关联文件编号、起草单位等核心审核信息 |
| `nodeId` 关联节点 | 绑定上位法比对节点与审核意见生成节点 | 确保流程按审核逻辑顺序执行 |
| 全局变量历史记录存储 | `按审核批次存储 7 天` | 兼顾回溯需求与存储资源占用 |
| 节点重试次数 | `2 次` | 处理临时的接口调用异常，避免流程直接失败 |

## 容易做错的三处
- 工作流运行时出现 gpt-4o-mini 调用报错日志，未配置相关模型调用权限。原因是`variables`配置中误绑定了未授权的模型调用参数，导致工作流自动触发未配置的接口。
- 工作流执行超时，界面显示状态码 504。原因是未针对上位法比对节点设置合理的超时时间，该环节耗时超出默认阈值。
- 全局变量历史记录无法修改。原因是未在`variables`配置中开启历史记录编辑权限，默认仅支持只读存储。

## 怎么确认配好了
- 手动上传一份测试用的规范性文件草案，运行工作流，检查是否自动关联对应的上位法数据库节点，且输出包含比对结果。
- 查看工作流的`variables`配置项，确认已绑定审核材料的元数据字段，且全局变量历史记录存储周期符合需求。
- 模拟触发一次临时接口异常，检查节点是否按配置的重试次数执行重试，以及超时时间是否生效。
- 查看工作流的`nodeId`关联配置，确认各节点的执行顺序符合起草、比对、审核、备案的逻辑流程。
