# 规范性文件合法性审核的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
本品类的核心文档包含规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告。数据来源涵盖法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新频率不定期。文档结构以条文、说明、审核结论为核心字段，无统一固定的单位字段，内容多为抽象政策规则类文本，聚焦制定权限、程序与条文合法性审查相关的各类材料。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且更新无固定周期，需确保溯源时能匹配最新的法规政策版本，因此需同步对接多源数据库的实时索引。文档多为抽象规则文本，需精准定位条文对应的上位法依据，因此溯源结果需严格匹配条文层级。备案与审核流程的严肃性要求溯源信息需可追溯至原始系统，不能出现引用为空或权限问题。同时，案卷审核需关联多份材料的交叉依据，需限制单次溯源的结果数量，避免信息过载影响审核效率。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配规范性文件单条条文的上下文长度，确保引用内容完整且不超出模型上下文限制 |
| 重排配置 | 开启，选用通用法律领域微调版，阈值0.75–0.85按实测标定 | 本品类文档多为专业法律文本，开启重排可提升相关片段召回精度，适配专业语义匹配需求 |
| 单次搜索上限 | 前8条 | 避免多源数据返回过多无关内容，适配案卷审核的精准溯源需求 |
| 最大上下文 | 16000 字符 | 容纳多份关联材料的溯源内容，满足交叉审核的信息需求 |
| `responseData` | 开启原始来源字段返回 | 确保溯源信息可关联至行政规范性文件备案系统的原始记录 |
| `detail` | 开启完整引用 | 展示条文原文与依据出处，符合法治审核的严谨性要求 |

## 容易做错的三处
- 现象：开启rerank后出现引用为空、搜索结果无匹配片段。原因：未针对法律专业文本微调重排模型，或重排阈值设置过高，过滤掉了合法的相关依据片段。
- 现象：导出并导入工作流后，引用的插件无法加载。原因：未在新环境中同步配置对应法规数据库的对接密钥与权限，或工作流配置中未保留原始数据源的关联参数。
- 现象：回答段落末尾显示「没有权限操作此对话记录」，无法取消引用显示。原因：未关闭引用强制展示开关，或对话权限配置中限制了溯源信息的编辑权限。

## 怎么确认配好了
- 上传单份规范性文件草案，触发溯源校验，检查返回的引用片段是否匹配对应上位法条文。
- 调整`quoteMaxToken`参数，验证引用内容的截断或完整展示是否符合预期。
- 导入测试工作流，确认关联的法规数据库插件可正常调用并返回溯源数据。
- 查看回答末尾的引用标识，确认是否可根据配置开关控制显示状态。
