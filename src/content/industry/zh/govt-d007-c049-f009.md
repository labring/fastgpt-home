# 规范性文件合法性审核的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自法规规章库、上位法数据库、部门政策文件库及行政规范性文件备案系统，更新频率不定期。日常处理的文档包含规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告，文档以结构化文本为主，包含文件条款、制定主体、权限依据、意见征集内容等字段，仅涉及抽象政策规则的制定合法性审查，不涉及行政执法个案细节。本页面内容基于FastGPT v4.17.0版本编写。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新无固定周期，要求配置需支持动态接入多源异构数据库，避免固定索引导致的内容滞后。文档包含多类关联材料，需配置足够的上下文承载能力以完整覆盖关联审核依据。审查需比对上位法与权限依据，要求模型能精准匹配层级化法规内容，同时需限制无关内容干扰，避免审核偏差。单次审核涉及多份材料，需合理配置上下文与输出长度，确保完整覆盖所有审查环节的信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应节点地址 | 适配多源法规数据库的接入需求 |
| `AIPROXY_API_TOKEN` | 绑定专属访问密钥 | 保障审核数据的访问权限安全 |
| `maxContext` | 8000–12000 token | 覆盖规范性文件草案、征求意见汇总等多份关联文档的完整内容 |
| `maxTokens` | 2000–3000 token | 确保合法性审核意见的完整输出，避免内容截断 |
| `quoteMaxToken` | 1500 token | 精准截取上位法、部门政策的相关条款作为审核依据 |
| `temperature` | 0.1–0.3 | 保持审核结论的严谨性，避免主观偏差 |

## 容易做错的三处
- 尝试直接查看接入数据库的表模型结构时，无法获取有效字段信息。原因是未通过FastGPT的数据源配置模块获取元数据，直接调用底层接口导致权限不足。
- 模型调用返回超时错误，日志显示请求时长超出预设限制。原因是未合理设置`maxContext`与`maxTokens`参数，导致模型处理多份关联文档的耗时过长。
- 配置保存后审核结果出现随机偏差，与法规依据匹配度不稳定。原因是`temperature`参数取值过高，导致模型输出缺乏严谨性。

## 怎么确认配好了
- 测试调用`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的组合，确认接口返回正常状态码。
- 上传一份小型规范性文件草案，检查`maxContext`是否完整加载所有关联材料内容，无截断现象。
- 运行一次审核流程，核对输出结果的严谨性，确认`temperature`取值符合审核需求。
- 检查数据源配置模块，确认已成功同步法规规章库、上位法数据库的元数据信息。
