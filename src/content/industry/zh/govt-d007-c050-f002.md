# 财政支出绩效评价的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查。日常处理的文档包含绩效目标表、自评表、绩效评价报告、佐证材料清单、整改报告。数据更新频率为年度，单次入库数据量随当年申报项目数量波动。文档结构多为结构化表格搭配非结构化佐证文本，字段涵盖项目标识、绩效指标、资金使用明细、整改事项等，部分佐证材料为扫描件转写的零散文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
年度更新的特性决定索引无需高频增量构建，可采用全量重建模式降低运维成本。混合结构化表格与非结构化文本的数据结构，要求分块策略兼顾表格字段完整性与长文本语义连贯性。多来源数据存在格式差异，需在索引前完成标准化预处理，避免字段错位影响向量匹配精度。佐证材料多为项目相关的零散凭证文本，索引召回需优先匹配与绩效指标、资金使用关联的内容，因此索引权重需向核心业务字段倾斜。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配绩效评价报告、自评表等文档的语义单元长度，避免分块过碎或过长 |
| 重叠长度 | 100–150 字符 | 保障跨分块的语义连贯性，防止关键绩效指标被拆分在不同块中 |
| `maxToken` | 8192 | 适配FastGPT v4.17.0支持的主流向量模型上下文窗口，满足年度全量数据的索引长度要求 |
| `defaultToken` | 256 | 匹配单条绩效目标、整改事项等短文本的平均长度，保障单个向量块的语义完整性 |
| 相似度阈值 | 0.72–0.85（按实测标定） | 区分绩效相关佐证材料与无关文本，降低误召回概率 |
| 单次搜索上限 | 前10条 | 覆盖单个申报项目的核心佐证材料数量，平衡召回效率与结果相关性 |

## 容易做错的三处
- 现象：执行全量索引重建后，系统长时间无进度反馈，无法手动切换至新生成的索引。原因：未配置索引版本管理与别名切换逻辑，重建过程中无法平滑替换原有索引，导致业务调用仍指向旧索引。
- 现象：调用批量索引接口时返回参数校验失败，无法完成多份申报材料的批量入库。原因：未正确设置分块参数与批次大小，批次设置超出系统单次处理阈值，导致请求被拦截。
- 现象：检索绩效关联佐证材料时，仅返回单份文档的片段，无法召回同项目下的其他相关材料。原因：采用单文档单索引模式，未将同项目的所有材料统一纳入同一索引集合，导致跨文档语义关联无法被向量模型识别。

## 怎么确认配好了
- 执行单份绩效目标表的索引测试，核对分块后的文本块数量，确认分块参数生效。
- 调用批量索引接口，提交少量测试文档，核对返回结果的状态码与参数提示，确认批量配置正确。
- 输入绩效指标关键词执行检索测试，核对召回结果的覆盖范围与同项目材料的关联度，确认索引集合配置符合业务需求。
- 查看索引管理界面，确认已设置索引版本别名，可在重建完成后快速切换，确认版本管理配置生效。
