# 财政支出绩效评价的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
该品类的数据来自预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查，更新频率为年度。日常处理的文档包含绩效目标表、自评表、绩效评价报告、佐证材料清单与整改报告，数据字段覆盖项目绩效目标、资金使用明细、产出效果佐证、整改措施等，无固定统一的标准化单位，需结合具体项目场景匹配字段含义，单案卷数据体量随项目规模浮动。

## 这些特征在「工具调用与插件」这一环带来什么约束
年度更新的特性要求工具调用仅在申报与审核周期触发，无需持续定时运行，避免无效资源消耗。多源数据来源要求插件需适配预算管理一体化系统、业务台账等不同接口格式，需配置跨系统数据拉取的适配规则。多样的文档类型要求工具调用支持多格式文件解析，且需针对绩效目标与资金支出的关联校验设计专用工具，确保核验逻辑与业务规则匹配。同时，案卷审核需关联多维度数据，工具调用需支持批量数据比对，降低单条数据处理的误差风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 工具调用触发时机 | 按申报周期触发，单次运行时长不超过300秒 | 匹配年度更新的业务节奏，避免无效定时调用，符合财政业务的周期特性 |
| 最大工具调用次数 | 前15次 | 覆盖单案卷所需的多维度数据核验与文档解析需求，避免无限制调用 |
| `toolChoice` 参数 | 固定为`auto` | 适配多类型工具的自动选择，满足绩效评价中数据拉取、文档解析、校验的混合需求 |
| 上下文窗口限制 | 8000 token | 适配单案卷的多文档拼接长度，避免超出模型处理上限 |
| 日志留存时长 | 30天 | 满足财政审核的合规追溯要求，便于排查调用失败问题 |
| 文件解析格式 | 支持PDF、Excel、Word | 覆盖日常使用的主要文档类型，适配绩效评价的各类佐证材料 |

## 容易做错的三处
- 配置定时任务持续触发工具调用。现象为系统持续生成调用日志，无业务触发的规律。原因是未匹配年度更新的业务节奏，错误设置高频定时任务，导致无效调用消耗资源。
- 调用大模型后返回结果与绩效评价的业务需求不符，未达到预期效果。现象为模型未正确关联绩效目标与资金支出数据。原因是未正确配置`functionCall`参数限定工具调用范围，导致模型偏离专用校验逻辑。
- 无法查看大模型或工具调用的失败日志。现象为调用失败后无对应日志记录或日志已被清除。原因是未开启日志留存配置，或留存时长设置过短导致日志被自动清理。

## 怎么确认配好了
- 触发一次工具调用，核对拉取的数据是否来自预算管理一体化系统、项目申报材料等指定数据源。
- 查看工具调用日志，确认触发时机符合申报周期设置，无无效的定时触发记录。
- 测试单案卷的工具调用流程，确认返回的校验结果覆盖绩效目标、资金支出、佐证材料的关联核验环节。
- 检查`toolChoice`与`functionCall`参数的配置，确认其适配当前业务所需的工具类型，无参数错误导致的调用失败。
