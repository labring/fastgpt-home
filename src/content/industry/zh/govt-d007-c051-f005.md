# 道路运输经营许可的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
本场景的数据来源于道路运政管理系统、全国道路运输车辆动态信息公共服务平台、车辆和从业人员数据库，每日更新。日常文档包含经营许可申请文件、车辆技术档案、驾驶员从业资格材料、安全生产管理制度文本、有效道路运输经营许可证副本。数据字段涵盖申请主体统一社会信用代码、车辆号牌号码、驾驶员从业资格证编号、安全管理制度条款、场地证明文件编号等，按申请批次、资质核验、车辆人员、安全管理的逻辑分模块组织。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据每日更新的要求，决定工具调用需配置定时同步机制，避免使用过期的车辆、人员资质数据。多类型文档的存在，要求插件支持结构化表单解析与非结构化文本提取，适配申请表格、技术档案等不同格式的材料。字段与资质强绑定的特征，要求工具调用需精准匹配业务字段，避免泛化检索返回无关内容。出错后果直接影响许可审批，因此工具调用需添加前置校验与失败重试逻辑，确保核验结果准确。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `functionCall` | `enabled` | 支持结构化调用资质核验工具，精准返回可用于案卷审核的字段数据 |
| `toolChoice` | `auto` | 自动匹配道路运输许可审核所需的不同工具，无需手动指定 |
| 工具调用超时设置 | `30 秒` | 适配道路运政管理系统的常规响应时长，避免审批流程阻塞 |
| 单次工具返回上限 | `前 3 条` | 仅保留最新有效核验结果，减少上下文冗余 |
| 问题模板配置 | 按业务场景格式化 | 将通用提问转换为标准化查询，提升工具调用匹配精度 |
| 最大上下文长度 | `8000 token` | 适配多份案卷材料的拼接长度，避免截断关键核验信息 |

## 容易做错的三处
- 现象：工具调用返回无效工具标识，如`{"name":"lBUrk"}`格式的内容，原因：未在插件管理中配置对应道路运输资质核验的工具，或工具名称配置错误。
- 现象：工作流中多次调用工具后，中间步骤的工具调用结果被混入最终会话回复，原因：未配置上下文截断或结果聚合规则，导致冗余内容未被过滤。
- 现象：工具调用返回空核验结果，原因：未配置每日同步数据的定时任务，使用了过期的车辆或从业人员数据，导致无有效匹配项。

## 怎么确认配好了
- 在FastGPT v4.17.0的插件管理页面，确认已添加道路运输资质核验、车辆档案查询的工具，并匹配正确的调用名称。
- 发起标准化测试提问，输入“核验XX车辆的从业资格”，检查工具调用的参数是否符合配置的`toolChoice`和`functionCall`设置。
- 查看工具调用日志，确认返回结果的条数不超过设定的单次返回上限，且未触发超时设置。
- 提交模拟的经营许可申请材料，检查中间步骤的工具调用结果未被混入最终回复。
