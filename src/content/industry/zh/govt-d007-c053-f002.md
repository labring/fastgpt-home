# 部门预算编制的申报材料与案卷审核：向量模型与索引

本页面针对国央企、政府及公共服务领域中，部门预算编制场景下的申报材料与案卷审核环节，讲解向量模型与索引的配置、参数与失败处理逻辑，适配该品类的专属数据特征。

## 这个品类的数据长什么样
本品类的核心文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等。数据主要来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知。数据更新频率为年度周期，文档多包含项目编码、经费额度、绩效指标、编制单位等字段，字段涉及金额、人数、百分比等单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
年度更新的全量历史数据要求索引支持批量加载，避免重复处理往年预算文档；多字段结构化的预算文档，需要向量模型适配结构化字段的语义关联；跨系统来源的数据格式差异，要求索引配置支持多源数据的统一解析与标准化；预算审核的严谨性要求索引召回结果需精准匹配预算核心字段，过滤无关内容以降低审核干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配预算文档中单条项目申报内容的常规长度，避免拆分破坏语义完整性 |
| 重叠长度 | 100–200 字符 | 覆盖跨分块的预算项目关联信息，防止关键审核依据被拆分丢失 |
| `maxToken` | 4096 token | 匹配主流向量模型的输入上限，适配预算文档中长段落的向量化需求 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非预算相关内容，符合审核环节的严谨性要求 |
| 单次搜索上限 | 前 10 条 | 控制召回结果规模，避免冗余信息干扰预算审核的核心判断 |
| `defaultToken` | 按实测标定 | 适配不同预算文档的平均token占比，优化索引加载与检索效率 |

*本页面的配置建议基于FastGPT v4.17.0版本*

## 容易做错的三处
- 现象：创建索引后调用语言模型返回空结果。原因：未正确关联向量索引与语言模型的调用链路，导致检索结果未传入上下文窗口。
- 现象：本地部署版本索引创建超时。原因：未配置外部索引服务，使用内置向量库处理年度全量预算数据时超出内存或时间限制。
- 现象：向量存储迁移后召回结果异常。原因：未对迁移后的索引数据进行字段映射校验，导致结构化预算字段的语义关联丢失。

## 怎么确认配好了
- 上传单份部门预算草案文档，执行索引创建，查看FastGPT界面返回的索引状态为完成。
- 输入预算审核相关的查询词，验证召回结果包含项目申报书、绩效目标表等核心文档类型。
- 对比向量存储迁移前后的索引召回条数，确认数据完整度符合预期。
- 测试调用语言模型时，检索结果自动带入上下文窗口，无空内容报错。
