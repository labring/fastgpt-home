# 部门预算编制的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
该品类的数据通常来自预算管理一体化系统、部门人员编制系统、以前年度决算数据、项目库及财政部年度预算编制通知，更新节奏为年度周期。日常处理的文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复文件，字段包含项目编码、人员编制数、申报金额、绩效指标等，单位涉及万元、人、项目序号等。

## 这些特征在「工具调用与插件」这一环带来什么约束
年度更新的数据源要求工具调用限定当前预算年度的数据集，避免跨年度数据干扰审核结果。多类结构化文档的存在，要求插件支持表格字段提取与校验，确保人员经费、项目支出的数值匹配。多系统来源的数据需要跨源比对，工具调用需配置多数据源联动插件，保证预算申报数据与人员编制、项目库信息一致。案卷审核需关联多份文档，插件调用需支持批量文档的字段聚合与校验，提升审核的准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配部门预算编制的申报材料与案卷审核场景：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多插件的自动选择，匹配预算审核的多环节校验需求 |
| `functionCall` | `enabled` | 支持结构化数据提取，适配预算文档的字段校验与聚合 |
| 单次插件调用上限 | 前 3 条 | 避免过多数据导致上下文溢出，符合单份案卷的审核范围 |
| 插件调用超时时间 | 60 秒 | 预算数据的多源查询通常在该时限内完成，避免长时间等待 |
| 知识库关联范围 | 仅当前预算年度文档 | 贴合数据年度更新的特性，避免跨年度数据干扰审核结果 |
| 插件触发条件 | 检测到预算申报字段缺失时 | 自动触发校验流程，减少人工干预的成本 |

## 容易做错的三处
- 插件点击无响应。原因是未绑定预算管理一体化系统、项目库等对应数据源的插件权限，或配置项`toolChoice`未设置为适配当前场景的模式。
- 半夜持续触发插件调用导致余额耗尽。原因是未配置插件调用的时段过滤规则，且未设置触发条件的精准匹配，导致空请求或无效调用反复执行。
- 单次对话多次弹出插件选择提示。原因是未启用`functionCall`的单次调用限制，或未设置对话内插件调用的最大次数，导致重复触发插件选择流程。

## 怎么确认配好了
- 上传一份年度项目申报书，触发插件调用，检查是否能自动提取项目编码、申报金额等字段，验证`functionCall`的配置生效。
- 查看插件调用日志，确认仅在检测到预算申报字段缺失时触发，验证触发条件的配置正确。
- 测试上传非当前预算年度的文档，检查是否未被纳入关联范围，验证知识库关联范围的配置生效。
- 模拟夜间时段发起调用请求，检查是否被拦截，验证时段限制的配置生效。
