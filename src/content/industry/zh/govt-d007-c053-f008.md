# 部门预算编制的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
该品类的日常文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等，数据来源为预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知，更新频率为年度。文档多为结构化表格与文本结合的格式，包含项目编码、经费金额、人员编制数等字段，单位多采用万元、人等财政核算标准单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
年度更新的批量文档结构差异较大，既有固定格式的预算批复，也有灵活填写的项目申报书，要求分块适配不同格式的内容。文档内结构化字段多，包含关联紧密的经费金额与项目编码，需避免拆分跨表格的关联数据，防止审核时的逻辑断裂。数据来源多为内部系统导出的标准化文件，需适配不同导出格式的解析兼容性。同时单份文档内容跨度大，从人员经费到项目支出覆盖多个核算维度，分块需保留上下文关联以确保审核逻辑完整。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配预算类文档的结构化段落与表格块长度，避免拆分关键经费测算字段 |
| `chunkSplitter` | 按段落+标题拆分 | 保留预算文档中项目标题与对应申报内容的关联，符合审核时的上下文阅读习惯 |
| `customPdfParse` | 开启结构化解析模式 | 适配从预算管理一体化系统导出的PDF表格，准确提取单元格内的经费金额与项目编码 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对单份批量预算文档的解析耗时，避免大文件解析中途中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配年度批量预算文档的上传需求，避免大文件被拦截 |
| `chunkSettingMode` | 手动配置 | 针对不同类型的预算文档（如人员经费表、项目申报书）调整分块参数，适配专项审核需求 |

## 容易做错的三处
- 上传单份年度预算汇总文档后，界面显示解析失败且日志返回超时错误。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，文档解析耗时超过默认阈值。
- 解析后的分块内容出现跨表格的经费字段拆分，导致审核时无法关联对应项目的申报说明。原因是未设置`chunkSplitter`为按标题+段落拆分，误将相邻表格的内容拆分到不同块中。
- 本地Docker部署实例中，上传文档显示未解析且提示服务连接失败。原因是未正确配置`customPdfParse`的本地服务地址，导致FastGPT无法连通解析节点。

## 怎么确认配好了
- 上传一份典型的部门预算草案文档，查看解析后的分块预览，确认每个分块都包含完整的项目标题与对应申报内容。
- 检查解析服务的运行日志，确认无超时报错，且`PARSE_FILE_TIMEOUT_SECONDS`的配置值与实际解析耗时匹配。
- 针对不同类型的预算文档（如人员经费测算表、项目申报书），分别测试分块效果，调整`chunkSettingMode`的参数适配专项审核需求。
- 验证上传文件的大小不超过`UPLOAD_FILE_MAX_SIZE`的配置值，避免因文件过大被系统拦截。
