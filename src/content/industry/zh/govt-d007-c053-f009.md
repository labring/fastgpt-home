# 部门预算编制的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知，更新频率为年度。日常处理的文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复，每份文档包含固定字段：项目编码、单位名称、经费金额、人员编制数、绩效目标等，字段需匹配财政部门统一的格式规范，无额外自定义字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
年度集中更新的特性导致申报材料与案卷审核需在固定周期内处理大量批量数据，对模型的并发处理能力有明确要求。多源数据来源需确保模型能对齐不同系统的字段格式，避免提取偏差。文档结构固定但字段数量较多，需模型精准定位审核所需的关键信息，同时需过滤无关内容。此外，审核结果需符合财政部门的合规要求，模型输出需严格匹配预设字段，不能出现格式或内容偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 部门预算文档单批次内容量较大，需完整加载多份申报材料与案卷的上下文 |
| `temperature` | 0.1–0.3 | 审核场景需稳定输出合规结果，避免随机偏差影响审核判断 |
| `quoteMaxToken` | 1500 字符 | 需精准引用申报材料原文的关键字段，控制引用长度以确保审核逻辑清晰 |
| `AIPROXY_API_ENDPOINT` | 按实际部署节点填写 | 适配本地或云端模型的接入路径，确保连接正常 |
| `toolChoice` | "none" | 审核场景无需调用外部工具，专注于文本提取与审核判断 |

## 容易做错的三处
- 配置本地Ollama模型后调用返回未找到或权限报错：原因是未在`.env.local`中正确添加本地模型的接入配置，或`AIPROXY_API_TOKEN`与模型平台的验证规则不匹配。
- 审核提取的经费字段出现单位错误：原因是未针对预算文档的标准单位做前置校验，模型未匹配到数据来源的统一格式规范。
- 批量处理多份申报书时出现响应超时：原因是`maxContext`设置超出模型支持的上下文上限，导致处理延迟。

## 怎么确认配好了
- 导入单份人员经费测算表，触发内容提取，核对提取的人员编制数、经费金额字段与原文一致。
- 查看FastGPT v4.17.0的模型调用日志，确认`AIPROXY_API_ENDPOINT`与实际部署路径匹配，无连接报错。
- 调整`temperature`参数后测试多份样本，确认输出结果无明显随机波动。
- 批量导入多份同类型申报材料，检查处理流程无中断，上下文加载完整。
