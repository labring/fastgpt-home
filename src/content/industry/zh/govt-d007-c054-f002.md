# 防汛防灾与应急值守的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
应急值守与防汛防灾场景的日常数据覆盖值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单等文档。数据来源涵盖气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控，更新频率为每日更新。文档包含带单位的量化字段，如毫米降雨量、吨级物资量，部分文档为文本与监测截图混合的多模态格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引环节支持跨系统数据的向量对齐，避免不同来源的同类型文档出现语义偏差。每日更新的特性要求配置增量索引模式，避免全量索引带来的资源消耗与过长的索引耗时。文档长度差异显著，短至数十字的值班记录与长达数千字的会商纪要并存，需要灵活的分块策略适配不同文档长度。带单位的量化字段需要在向量编码时保留单位信息，保证检索时的语义一致性，多模态文档则要求向量模型支持文本与图像的混合编码。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配会商纪要、灾情速报等文档的长度，避免单块信息过载 |
| 重叠长度 | 100–150 字符 | 保证跨块上下文连贯，适合滚动更新的值班记录 |
| `maxToken` | 4096 token | 适配主流向量模型的输入上限，支持长文档分块后的拼接 |
| `defaultToken` | 256 token | 平衡单块向量精度与检索召回效率 |
| 相似度阈值 | 0.72–0.78 | 区分有效预警信息与无关历史记录，适配应急场景的高置信度要求 |
| 单次搜索上限 | 前10条 | 快速定位核心灾情数据，避免冗余信息干扰应急决策 |

## 容易做错的三处
- 现象：文档索引耗时超过30分钟，界面显示“索引中”无进度更新。原因：未开启增量索引模式，对全量多源异构的日更数据执行全量重新索引，导致计算资源占用过高。
- 现象：检索结果包含大量非当日的历史预警信息，置信度不符合应急需求。原因：未配置按更新时间过滤元数据，且相似度阈值设置低于0.7，未有效过滤过期数据。
- 现象：调用multimodal-embedding-v1模型时报错“参数不匹配”。原因：未在FastGPT配置中正确填写模型的API调用地址与密钥，或未适配多模态输入的文本长度要求。

## 怎么确认配好了
- 在FastGPT v4.17.0的向量模型配置页面，确认`maxToken`与`defaultToken`的取值与预设配置一致。
- 上传一份测试用的值班记录文档，查看索引完成时间是否在合理区间内，无报错日志生成。
- 输入“今日雨情数据”的检索词，核对返回结果的文档来源是否包含水文监测系统的当日数据。
- 调整相似度阈值，验证检索结果的数量随阈值变化的逻辑符合预期。
