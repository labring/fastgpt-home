# 防汛防灾与应急值守的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
该品类的日常文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单，数据来源为气象预警系统、水文监测系统、应急指挥平台、基层报灾系统、视频监控。数据更新频率为每日，字段涵盖雨情水情数值、受灾人员数量、物资调拨数量等，部分文档为结构化字段搭配自由文本描述，单份文档长度多在500-1500字符区间，不同来源的数据格式存在细微差异。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的多源异构数据要求多轮对话需逐步整合不同系统的信息，避免一次性加载过多内容导致超时。结构化与自由文本混合的文档结构，要求提示词需区分字段提取与材料生成的不同任务，确保审核环节的信息准确性。应急处置的短节奏属性，要求多轮对话上下文不宜过长，需过滤冗余历史信息，聚焦当前值守环节的核心内容。跨部门调度的特性则要求对话需关联对应案卷编号，方便后续回溯与校验。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 800–1200 字符 | 适配单份日常文档的长度范围，避免超出模型处理上限 |
| 多轮对话历史保留轮次 | 前3轮对话 | 匹配应急处置的短节奏，过滤冗余历史信息，聚焦当前值守任务 |
| 变量绑定配置 | 启用`variables`参数 | 自动填充实时更新的雨情、人员、物资等字段，减少人工输入误差 |
| 对话触发校验 | 按`messages`字段完整性触发 | 确保输入包含核心灾情信息后再生成审核材料，避免无效输出 |
| 会话关联配置 | 绑定`chatId`关联对应案卷 | 方便回溯当前值守的所有对话与关联文档，满足案卷审核的溯源要求 |

## 容易做错的三处
- 对话页面或知识库页面崩溃，现象为加载时弹出报错提示或直接无响应，原因是未限制最大上下文长度，加载过多历史文档超出系统内存上限。
- 引导词不起作用，现象为生成的审核材料未按预设逻辑生成，原因是未按时序排列`messages`字段，导致模型无法识别对话上下文逻辑。
- 插件对接失败，现象为无法将对话应用与集成插件完成关联，原因是未绑定`chatId`关联对话与对应案卷，导致插件无法获取对应审核数据。

## 怎么确认配好了
- 上传单份灾情速报，触发对话，检查`variables`绑定的字段是否自动填充到生成的审核材料中。
- 发起多轮对话，依次输入不同系统的雨情、水情数据，检查模型是否按`messages`时序整合信息并生成连贯的会商材料。
- 生成审核材料后，核对是否关联了当前`chatId`对应的案卷编号，确保溯源功能正常。
- 模拟输入缺失核心灾情数据的对话，检查系统是否拦截无效请求并提示补充信息。
