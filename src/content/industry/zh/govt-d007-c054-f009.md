# 防汛防灾与应急值守的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控。日常处理的文档包括值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单。数据更新频率为每日，部分实时监测数据为秒级更新。文档字段包含雨情水情数值、灾情等级、物资数量、转移安置人数等，对应单位为毫米、立方米每秒、吨、人等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据多源异构且更新频繁，部分监测数据为实时推送，要求模型接入配置需适配多格式数据输入。文档包含专业水文、气象字段，需模型支持专业术语解析，因此配置需兼顾上下文承载能力与内容准确性。案卷审核需回溯历史值班、会商记录，要求配置的上下文窗口足够容纳多份历史文档的汇总内容。同时，由于审核结果直接关联应急处置，配置需优先保障输出准确性，避免过度随机化。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 需承载多份灾情速报、会商纪要与历史值班记录的汇总内容，避免截断关键信息 |
| `maxTokens` | 4000 token | 适配单份审核材料的输出长度需求，保障案卷审核的完整响应 |
| `quoteMaxToken` | 2000 token | 需引用灾情数据、预警通知原文作为审核依据，预留足够的原文引用空间 |
| `temperature` | 0.2–0.4 | 保障审核结果的严谨性，避免因随机化导致灾情判断偏差 |
| `vision` | 开启 | 适配视频监控传回的灾情画面审核需求，补充视觉维度的证据 |
| `AIPROXY_API_ENDPOINT` | 本地部署模型的API地址 | 满足本地化部署的合规与数据安全要求 |
| `AIPROXY_API_TOKEN` | 自定义鉴权密钥 | 保障模型接口的访问安全，防止未授权调用 |

## 容易做错的三处
- 测试本地部署模型时返回401 unauthorized，原因是未正确配置`AIPROXY_API_TOKEN`与本地模型的鉴权密钥不匹配。
- 接入中转服务后无法正常调用模型，原因是未确认服务的维护状态，导致接口地址或密钥失效。
- 配置`maxContext`过小导致审核结果截断，原因是未考虑多源灾情文档的总长度，遗漏关键雨情水情数据。

## 怎么确认配好了
- 调用模型接口测试，输入一份标准灾情速报，检查返回结果是否包含完整的审核结论与引用的原文片段。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置未被篡改，无401报错记录。
- 上传多份不同来源的文档（如预警通知、物资调拨单），检查模型是否能正确识别专业字段并完成汇总。
- 开启`vision`配置后，上传一张灾情现场照片，确认模型能返回对应的文字描述与审核意见。
