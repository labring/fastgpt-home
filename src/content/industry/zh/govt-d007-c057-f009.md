# 食品安全监督抽检的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS及企业台账。日常文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。数据更新频率为月度，核心字段覆盖抽样信息、检验结果、处置流程等，不同文档的字段格式由监管系统统一规范，无自定义字段空间。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的批量数据要求模型接入支持批量任务调度，避免单次处理过载。多来源的数据格式差异需要配置统一的文档解析规则，适配抽样单、检验报告等不同文档结构。核心文档如检验报告需保留原始字段的精准映射，不能丢失不合格项、处置进度等关键信息。监管场景的严格合规要求，需要模型输出的审核结果可溯源，需保留引用原文的能力，同时避免篡改原始数据字段。数据体量随月度抽检批次变化，需配置自适应的上下文长度参数，适配不同批次的文档长度差异。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 对接监管系统指定的API地址 | 适配食品安全抽检监测系统的官方数据接口规范 |
| `AIPROXY_API_TOKEN` | 由监管系统分配的专属鉴权令牌 | 保障数据调用的身份合法性，符合监管场景的安全要求 |
| `maxContext` | 8000–12000 token | 适配月度批量抽检文档的总长度，避免上下文溢出 |
| `quoteMaxToken` | 1500 token | 保留检验报告、抽样单等核心文档的完整引用片段，满足审核溯源需求 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保审核结果的一致性，符合监管场景的严谨要求 |
| `maxTokens` | 2000 token | 控制单条审核结果的输出长度，适配案卷审核的标准化格式要求 |

## 容易做错的三处
- 现象：配置`AIPROXY_API_TOKEN`时填入非官方分配的令牌，返回401状态码。原因：未使用监管系统专属鉴权凭证，违反接口安全校验规则。
- 现象：配置`maxContext`取值过大，出现上下文溢出报错。原因：未适配月度批量抽检文档的总长度，超出模型支持的最大上下文上限。
- 现象：配置`temperature`取值过高，审核结果出现不一致的判定结论。原因：未考虑监管场景的严谨要求，过度随机化的输出不符合合规审核的标准。

## 怎么确认配好了
- 调用测试接口，验证`AIPROXY_API_TOKEN`的鉴权有效性，确认返回正常的文档解析结果。
- 上传单份检验报告，核对`maxContext`和`maxTokens`的配置是否适配文档长度，无上下文溢出提示。
- 生成多份同类型文档的审核结果，核对`temperature`配置下的输出结论是否保持一致。
- 配置`quoteMaxToken`后，检查审核结果中是否完整保留了检验报告、抽样单等核心文档的关键引用片段。
