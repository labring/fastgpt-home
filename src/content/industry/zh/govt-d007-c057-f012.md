# 食品安全监督抽检的申报材料与案卷审核：部署与升级

## 这个品类的数据长什么样
本品类涉及的核心文档包括抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。数据主要来自食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS、企业台账。数据更新频率为月度，文档结构以抽样标识、检验项目、不合格判定、处置流程为核心字段，无统一固定单位，随文档类型变化，比如抽样单含抽样日期、检验结果数值等字段。

## 这些特征在「部署与升级」这一环带来什么约束
月度更新的数据要求部署时配置增量同步的触发周期，避免全量拉取占用过多系统资源。多来源的数据格式差异需要配置统一的接入适配规则，确保不同系统的文档可被统一解析。核心文档的字段差异要求在文档拆分时保留抽样标识、不合格判定等关键字段，避免审核所需的核心信息丢失。不合格处置相关文档的敏感性要求配置权限隔离规则，确保仅授权角色可访问敏感材料。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的部署规范。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `REDIS_URL` | `redis://:自定义密码@服务器地址:6379/0` | 用于缓存抽检文档的元数据与临时审核结果，降低重复查询开销 |
| `STORAGE_S3_ENDPOINT` | `oss-cn-hangzhou.aliyuncs.com` | 适配国内云存储的接入地址，用于存储抽样单、检验报告等大体积文档 |
| `FILE_TOKEN_KEY` | `随机生成的32位字符串` | 用于加密文档下载链接，避免未授权访问敏感审核材料 |
| `ROOT_KEY` | `自定义高强度密钥` | 用于初始化平台管理员权限，保障部署后的访问安全 |
| `DB_MAX_LINK` | `20–30 个` | 适配月度批量数据同步的并发连接需求，避免数据库连接耗尽 |

## 容易做错的三处
- 现象：调用检验机构LIMS接口时返回未知错误，提示凭证无效。原因：未使用平台内置的凭证存储规则，误用外部平台生成的凭证导致鉴权失败。
- 现象：docker容器启动后监听端口固定为3000，无法通过自定义配置修改。原因：未通过环境变量覆盖容器内的硬编码端口配置，导致端口设置不生效。
- 现象：批量导入月度抽检数据时出现连接超时。原因：未配置合理的数据库连接池上限，导致并发同步时数据库连接耗尽，任务中断。

## 怎么确认配好了
- 访问配置的`STORAGE_S3_ENDPOINT`对应的存储桶，上传一份抽样单文档，确认可正常读取并生成加密下载链接。
- 启动docker容器后，通过`docker ps`命令查看端口映射，确认自定义端口已正确绑定。
- 触发一次月度增量数据同步任务，查看平台日志确认无鉴权错误与连接超时提示。
- 登录平台管理员账号，使用`ROOT_KEY`对应的权限访问所有审核文档，确认权限隔离规则生效。
