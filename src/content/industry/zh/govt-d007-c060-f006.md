# 仓储物流的申报材料与案卷审核：引用来源与溯源

## 这些特征在「引用来源与溯源」这一环带来什么约束
仓储物流的多类型业务单据与审批案卷特征，对引用溯源带来三点约束。其一，结构化字段占比高，需精准匹配物流单号、库区编号等唯一标识字段，避免溯源结果错位。其二，数据随业务节点实时更新，需确保引用时关联的是当前生效版本的单据，排除历史草稿。其三，审批案卷包含多环节流转材料，溯源需关联完整审批链路的所有支撑文件，覆盖单份提交之外的流转材料。混合格式的单据（扫描件与结构化表格）需分别适配文本提取与字段映射规则，增加溯源匹配的复杂度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 仓储物流单据的审批意见与货物明细较长，需保留足够的引用上下文 |
| `responseData` | 开启结构化字段返回 | 适配仓储单据的标准化字段，直接关联唯一标识提升溯源精度 |
| `detail` | 返回前3条匹配源 | 覆盖单份审批案卷的多份支撑材料 |
| 分块长度 | 800–1200 字符 | 适配仓储单据的中长文本内容 |
| 相似度阈值 | 0.75–0.85 | 平衡匹配精度与召回范围 |
| 最大上下文 | 600 秒 | 适配多轮审核的交互场景 |

## 容易做错的三处
- 对话末尾出现冗余的引用链接且无法关闭：现象为FastGPT返回审核结果后，自动在末尾附加带文件名的引用链接，不符合内部汇报的格式要求。原因为未关闭系统设置中的引用展示开关，或未在提示词中明确要求隐藏引用信息。
- 多轮审核对话中无法关联历史申报材料：现象为后续轮次的审核请求无法匹配第一轮提交的仓储单据，溯源结果仅展示当前轮次的输入材料。原因为未开启上下文保留配置，或上下文窗口设置过小导致历史单据信息被截断。
- 溯源结果匹配到无关的仓储单据：现象为返回的引用材料与当前申报的货物品类、库区编号完全不匹配。原因为相似度阈值设置过高，或未针对仓储单据的标准化字段配置专属检索词。

## 怎么确认配好了
- 提交一份标准的仓储入库单作为测试文档，发起包含入库单号的审核提问，核对返回结果中是否关联该单据的引用信息。
- 发起两轮连续的审核提问，测试第二轮是否能关联第一轮提交的历史材料，确认上下文配置生效。
- 调整相似度阈值后发起相同提问，观察溯源结果的匹配条数变化，确认阈值配置生效。
- 检查系统设置中的引用展示开关状态，确认是否符合业务的格式要求。
