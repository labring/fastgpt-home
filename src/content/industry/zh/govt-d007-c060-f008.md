# 仓储物流的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
仓储物流的申报材料与案卷审核数据，主要来源为通关报关单、出入库台账、运输装箱单、质检报告等业务单证。数据更新节奏随业务流程推进，通关单证随货物通关实时更新，出入库单据每日同步更新。文档格式包含PDF、Word、Excel及扫描件，结构多带有固定表头，包含货物品名、箱号、申报单号、重量、数量等字段，字段附带专用单位如千克、立方米、托盘数，部分案卷会关联多份附属单证。

## 这些特征在「文档解析与分块」这一环带来什么约束
固定表头与专用字段单位的特征，要求解析时需保留字段间的绑定关系，避免拆分同一业务单元的关联数据。多样的文档格式与多附属单证的特征，要求分块规则需适配不同文件类型，且需保留主单与附属单证的上下文关联。高频更新的业务数据特征，要求解析任务需控制耗时，避免因超时导致任务失败。同时，案卷审核需关联多份单证的内容，分块时需确保相关内容处于相近的分块区间内，便于后续检索与审核。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 仓储物流单证包含多组结构化字段，过长分块会丢失字段关联，过短会破坏业务逻辑完整性 |
| `chunkSplitter` | 按自定义规则 | 仓储单证有固定表头和附属单证关联，通用分块会拆分主单与附件的关联信息 |
| `customPdfParse` | 开启结构化解析 | 部分报关单、装箱单为带表单的PDF，开启后可保留字段层级关系 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–120 秒 | 大型报关案卷包含多份附件，解析耗时随附件数量增加而上升，该区间适配多数业务场景 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 仓储物流的案卷可能包含批量扫描件或高清单证，需适配大文件上传需求 |
| `chunkSettingMode` | 手动配置 | 不同类型的仓储单证（如报关单、出入库单）分块规则存在差异，手动配置可灵活调整 |

## 容易做错的三处
- 现象：上传PDF报关单后，知识库搜索测试无法返回包含申报金额的结果。原因：分块时拆分了货物品名与申报金额的绑定关系，导致检索时无法关联对应字段。
- 现象：上传Excel出入库单据后，解析后的分块将同一单据的多行数据拆分至不同块中。原因：未配置`chunkSplitter`为按自定义规则，通用分块逻辑未识别表格的行关联关系。
- 现象：上传超过800 MB的扫描件案卷时，解析任务触发超时错误。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值过低，未适配大型案卷的解析耗时。

## 怎么确认配好了
- 上传单份典型仓储单证（如报关单），查看解析后的分块内容，确认同一业务单元的字段未被拆分。
- 执行知识库搜索测试，输入包含特定字段（如海关编码、箱号）的查询词，确认返回结果包含对应字段的完整上下文。
- 上传符合业务最大尺寸的案卷文件，确认解析任务未触发超时错误。
- 调整`chunkSize`的取值区间，对比不同配置下的分块效果，确认符合当前业务文档的结构特征。
