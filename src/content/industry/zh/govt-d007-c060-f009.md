# 仓储物流的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
仓储物流领域的申报材料与案卷审核数据，主要来源于仓储作业系统生成的入库出库单据、报关通关文件、货权权属证明、资质备案档案等。数据按业务批次更新，单笔业务对应一套独立案卷，文档包含结构化字段与附件内容，结构化字段涵盖货物品类、库存数量、仓储地址、审批单号、时效要求等，单位多为件、立方米、吨、自然日等。

## 这些特征在「模型接入与配置」这一环带来什么约束
仓储物流的申报案卷包含结构化字段与多类型附件，要求模型接入时支持多模态输入处理单据图片、PDF报关单等内容。单笔业务案卷数据量差异较大，需适配不同长度的上下文输入。结构化字段的单位与业务规则绑定紧密，模型需准确匹配字段与对应单位，避免识别偏差。数据按业务批次生成，配置需支持批量任务的上下文隔离，防止跨批次数据混淆。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 仓储物流申报材料包含单据图片、PDF报关单等多模态内容，需支持多模态解析能力 |
| `toolChoice` | 自动 | 需模型自主选择字段提取、附件校验等工具，适配多步骤的案卷审核流程 |
| `maxContext` | 8000–12000 token | 单笔业务案卷包含多份单据与结构化数据，需足够上下文容纳完整业务信息，按实测标定区间 |
| `temperature` | 0.1–0.3 | 审核需严格匹配业务规则与字段要求，降低生成随机性，保证识别一致性 |
| `quoteMaxToken` | 1000 字符 | 提取申报材料中的关键片段时，限制单段引用长度，避免冗余信息干扰审核判断 |
| `AIPROXY_API_ENDPOINT` | 按部署区域填写专属节点 | 适配国内/海外仓储业务的网络延迟要求，保障调用稳定性 |

## 容易做错的三处
- 配置`toolChoice`时误设为固定工具模式，导致模型无法自主选择附件解析、字段校验等适配工具，出现审核步骤遗漏、关键信息未提取的问题。
- 未开启`vision`配置项，导致无法解析报关单、入库单的图片附件，出现结构化字段为空、审核结果缺失的情况。
- `maxContext`取值过小，导致长案卷的上下文被截断，出现字段识别错误、规则匹配失效的报错。

## 怎么确认配好了
- 上传单份仓储报关单图片，验证模型是否能正确提取货物品类、数量、报关单号等字段，确认多模态配置生效。
- 提交包含多份单据的批量案卷，检查模型是否能自主调用对应工具完成各环节审核，确认工具选择配置正确。
- 查看调用日志，确认`AIPROXY_API_ENDPOINT`的配置匹配部署环境，无连接报错。
- 调整`temperature`取值并对比审核结果，确认取值区间符合业务审核的严谨性要求。
