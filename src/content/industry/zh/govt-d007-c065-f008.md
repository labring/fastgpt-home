# 勘察设计的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
勘察设计领域的申报材料与案卷审核数据，来源为项目报审文件与归档案卷，包括施工图审查申报表、勘察成果报告、设计方案文档、项目资质证明文件等。数据更新随项目报审进度按需触发，无固定周期。文档类型涵盖结构化Word报审表、带图表的PDF勘察报告、扫描版图纸说明等混合格式，字段包含项目编号、勘察范围、资质等级、报审日期等，单位涉及平方米、勘察深度（米）、资质级别等专业工程单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
勘察材料中的结构化报审表需精准提取固定字段，避免专业术语被拆分断裂；非结构化的勘察报告段落较长且包含大量专业表述，分块长度需适配内容密度；混合格式的文件可能存在解析格式错乱，需针对性配置解析规则；案卷审核需按项目批次拆分分块，避免跨案卷的内容混淆；大型案卷包含多份附件，需支持批量解析与分块，防止单文件解析超时。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 勘察设计报告专业内容密集，过长会导致语义割裂，过短会丢失上下文关联，按实测标定适配专业文档 |
| `chunkSplitter` | 按段落+标题拆分 | 勘察材料具备明确的章节标题与段落结构，按此拆分可保留专业内容的上下文完整性 |
| `customPdfParse` | 开启结构化提取 | 勘察图纸说明、报审PDF常包含固定格式表格与字段，开启后可准确提取结构化内容 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 单个勘察项目的案卷可能包含多份大型PDF图纸与Word报告，需支持大文件上传 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型勘察报告解析耗时较长，避免因超时导致解析失败 |
| `chunkSettingMode` | 手动配置 | 需针对报审表、勘察报告、图纸说明等不同类型的材料调整分块参数，手动配置更灵活 |

## 容易做错的三处
- 现象：解析后的boolean类型参数在条件判断组件中变为空。原因：未在文档解析环节对非结构化文本中的布尔值字段做标准化提取，导致参数类型被错误转换。
- 现象：解析时报错Cannot redefine property: toString。原因：自定义PDF解析配置中开启了非标准的文本重写规则，与系统内置的toString方法冲突。
- 现象：分块总数超过3000个后检索结果异常。原因：未按项目案卷批次拆分文件，导致单个知识库的分块总数超出系统默认索引上限，未将大型案卷拆分为多个独立文件。

## 怎么确认配好了
- 上传一份典型的勘察报审材料，查看解析后的分块列表，确认每个分块包含完整的专业段落与章节标题。
- 测试单份大型勘察报告的上传与解析，确认上传进度与解析状态无异常，未触发超时报错。
- 输入勘察专业相关的检索词，查看检索结果的分块是否覆盖了对应章节的完整内容。
- 调整分块参数后，对比不同参数下的分块结果，确认符合勘察材料的文档结构特征。
