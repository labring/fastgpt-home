# 勘察设计的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
勘察设计的申报与案卷审核数据主要来源于项目勘察报告、施工图设计文件、报审批次文档及过往合格案卷存档。数据更新随项目报审进度触发，单个项目的文档更新无固定周期，批量归档数据按竣工项目批次同步。文档包含结构化字段与非结构化内容：结构化字段包括项目编号、勘察点位坐标、设计荷载单位（kN/㎡）、勘察深度单位（米）等；非结构化内容为PDF格式的图纸说明、Word格式的报审说明文档。

## 这些特征在「知识库检索与召回」这一环带来什么约束
勘察设计数据的结构化与非结构化混合特征，要求检索需同时覆盖专业术语匹配与语义关联，避免单一检索模式遗漏关键内容。数据随项目进度更新的特性，要求知识库的增量同步需按项目批次触发，避免全量刷新导致检索延迟。专业字段的固定单位要求检索需保留单位关联匹配，防止因单位不符的召回结果干扰审核判断。过往合格案卷的存档格式固定，要求检索需匹配案卷编号、报审批次等结构化字段，提升召回结果的针对性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的知识库检索功能制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 勘察设计文档包含大量专业术语，该阈值区间可过滤无关的通用规范文档，同时保留近似的合格案卷内容 |
| `limit` | 前8条 | 申报材料审核需对比多份过往合格案卷，8条结果可覆盖常见报审场景，且不会超出上下文窗口限制 |
| `searchMode` | semantic+keyword | 勘察设计文档兼具结构化字段与非结构化说明，混合检索模式可同时匹配关键词与语义关联内容 |
| `usingReRank` | 开启 | 勘察设计专业术语较多，重排可过滤语义相似但术语不匹配的低质量结果，提升召回结果的专业性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 申报材料的表述可能与知识库存档术语存在差异，扩展查询可补充同义词匹配，例如「荷载」匹配「载荷」 |
| `collectionIds` | 填入勘察设计专属知识库的集合ID | 避免检索到其他品类的文档，保证召回结果仅覆盖勘察设计相关内容 |

## 容易做错的三处
- 现象：语义检索未召回带有特定专业关键词的知识块，原因：未开启`datasetSearchUsingExtensionQuery`，且专业术语的同义词未被覆盖，导致匹配范围过窄。
- 现象：使用严格问答模板时，检索到图片地址会提示未找到答案，使用其他模板则正常回复，原因：严格问答模板仅匹配结构化文本片段，未对图片类知识库内容做适配处理，通用模板会自动识别非结构化内容并生成对应回复。
- 现象：API调用提示知识库ID错误，原因：未正确配置`collectionIds`参数，或传入的集合ID不属于勘察设计专属知识库，导致检索范围不匹配。

## 怎么确认配好了
- 发起一次模拟申报材料的检索请求，检查返回结果是否仅包含勘察设计品类的文档，无其他品类的无关内容。
- 输入包含专业术语的查询词，确认召回结果的相似度分值落在0.72–0.80区间内，且重排后的结果排序符合专业逻辑。
- 调用API传入指定的`collectionIds`参数，检查返回结果的数量是否符合`limit`参数的设定值。
- 测试包含图片地址的知识库内容，确认在不同模板下的检索行为符合预期。
