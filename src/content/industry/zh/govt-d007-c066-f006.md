# 化工新材料的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
化工新材料的申报材料与案卷数据主要来自企业内部研发备案库、行业合规公示平台及第三方检测机构归档文件。数据更新随项目立项进度实时同步，批量合规申报时按批次完成更新。单份文档通常包含技术指标表、检测报告扫描件、合规证明附件，字段涵盖材料编号、检测日期、合规等级、分子结构参数，单位多为g/mol、℃、MPa等专业化工单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
化工新材料申报材料的专业参数多、单份文档篇幅较长，且案卷归档包含多轮审批记录，导致单条知识库块的token消耗较高。合规审核要求溯源必须精准匹配材料编号、检测日期等字段，对召回精度要求严格。数据更新频率较高，需确保引用的数据源与当前备案状态一致，避免使用过期合规文件。部分检测报告为非结构化扫描件，需先完成OCR转换才能纳入检索，增加了溯源的前置处理步骤。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 12000–15000 token | 适配化工申报材料单份文档的平均token规模，避免截断核心技术参数 |
| `quoteMaxToken` | 2500–3500 token | 限制单条引用的token消耗，防止长检测报告块超出上下文阈值 |
| `responseData` | 启用来源字段 | 强制返回引用材料的编号、检测日期等标识，满足合规溯源的可追溯要求 |
| `detail` | 完整展示模式 | 保留引用内容的全部结构化字段，便于核对专业参数与合规等级 |
| 单次召回上限 | 前6–10条 | 匹配化工案卷的多轮审批记录数量，覆盖主要关联审核材料 |
| 重排排序 | 按匹配度降序 | 优先召回与申报要求匹配的合规材料，避免无关文档干扰审核 |

## 容易做错的三处
- 界面显示的上下文条数与实际发送到模型的条数不符，例如界面显示30条但实际发送310条。原因是未正确配置`quoteMaxToken`与最大上下文的匹配关系，导致系统自动截断逻辑失效。
- 设置了引用上限后，知识库内超过上限的块仍被召回。原因是引用上限未关联到召回过滤规则，仅限制了输出阶段的token消耗，未限制召回阶段的块长度。
- 引用内容未显示来源字段，无法完成合规溯源。原因是未启用`responseData`配置项，系统默认仅返回文本内容未携带标识信息。

## 怎么确认配好了
- 测试调用工具，查看模型返回的引用来源字段，确认包含材料编号、检测日期等标识。
- 调整`quoteMaxToken`取值，验证长文档块是否被正确截断，无溢出报错。
- 上传单份超长度的化工检测报告，测试召回逻辑是否符合配置的上限规则。
- 查看知识库块的索引日志，确认OCR转换后的非结构化文档已纳入检索范围。
