# 化肥农药的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
化肥农药的申报材料与案卷数据主要来源于农业农村部农资登记系统、企业自检报告、地方农资监管平台。数据更新节奏为新登记产品按月同步，存量合规数据按季度校准。申报材料文档结构包含产品基本信息表、有效成分检测报告、田间试验数据、审批流转案卷等，核心字段包括登记证号、有效成分含量（单位为g/L或%）、生产许可证编号、毒性分级、残留量限值，案卷数据包含审核节点、整改记录、审批意见等字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
品类数据来源分散，需对接多个外部监管平台与内部业务系统，插件需支持多数据源的跨库查询。数据更新节奏差异要求插件配置定时增量同步任务，避免全量拉取占用资源。申报材料与案卷的字段单位不统一，工具调用时需内置单位转换逻辑，确保数据匹配准确。长文本的试验报告与审批案卷，要求工具调用支持分块解析但保留字段关联，避免关键信息截断。

## 配置怎么定
以下配置适用于 FastGPT v4.17.0，包含`toolChoice`与`functionCall`等核心参数的设置。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用触发阈值 | 0.7–0.9 | 区分是否需要调用工具的场景，适配化肥农药申报材料的长文本与多字段特征 |
| 单次工具调用最大token数 | 8000–12000 token | 覆盖单份申报材料的核心字段内容，避免截断关键检测数据与登记信息 |
| `toolChoice` | auto | 让模型自主判断是否调用工具，适配审核场景的动态需求 |
| 数据库连接超时时间 | 30–60 秒 | 适配农资监管平台的接口响应延迟，避免工具调用失败 |
| 结果返回条数上限 | 前3条 | 聚焦最相关的登记数据，避免信息过载影响审核判断 |
| `functionCall` | enabled | 开启显式函数调用模式，确保工具调用的参数格式符合化肥农药申报字段的校验规则 |

## 容易做错的三处
- 现象：使用数据库连接插件连接PostgreSQL时提示“工作流校验失败，请检查是否缺失、缺值，连线是否正常”。原因：未正确配置化肥农药申报数据的专属字段映射，例如未指定有效成分含量、登记证号等字段的查询条件。
- 现象：模型调用工具后返回结果条数与预期不符，例如仅返回1条或超过5条。原因：未设置结果返回条数上限，或阈值设置不符合农资数据的关联特征，导致返回信息过多或过少。
- 现象：工具调用耗时超过15秒，触发超时报错。原因：未调整数据库连接超时时间，或未针对长文本申报材料优化工具调用的分块逻辑，导致模型等待时间过长。

## 怎么确认配好了
- 上传单份标准化肥农药申报材料，核对模型是否自动触发工具调用并返回匹配的农资监管数据。
- 查看工具调用日志，确认返回的字段包含登记证号、有效成分含量等品类专属字段。
- 模拟缺失关键字段的申报材料，验证是否触发对应工具进行补全或校验。
- 调整工具调用触发阈值，确认模型能根据文本复杂度自主选择是否调用工具。
