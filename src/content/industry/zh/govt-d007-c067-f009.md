# 化肥农药的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
化肥农药申报材料与案卷审核的数据主要来源于农业农村部官方登记平台、省级农业执法部门归档文件，更新节奏随新登记申请提交、现有登记证续展或合规抽检结果发布调整。单份案卷通常包含申请表单、成分检测报告、生产资质证明三类文档，结构分为结构化字段区与长文本描述区，结构化字段包括有效成分占比、登记证编号、生产许可编号等，对应单位为%、g/L、mg/kg等，长文本部分则包含检测方法说明、合规性自查说明等内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配多份申报文档拼接后的总长度，避免截断核心合规校验信息 |
| `maxTokens` | 4000 token | 控制单轮审核的输出长度，匹配案卷逐页校验的详细程度需求 |
| `quoteMaxToken` | 1500 token | 限定引用的申报材料片段长度，确保仅提取与审核项直接相关的内容 |
| `toolChoice` | auto | 自动触发字段提取与合规校验工具，适配混合结构的文档处理 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保审核结果的一致性，符合合规审核的严谨要求 |
| `AIPROXY_API_TOKEN` | 绑定专属服务的密钥 | 确保调用权限仅用于本场景的审核任务，保障数据安全 |

## 容易做错的三处
- 审核结果中出现有效成分单位识别偏差，例如将“g/100g”错误识别为“mg/kg”。原因是未针对混合结构的文档调整`maxContext`参数，导致单位描述片段被截断，模型无法完整匹配行业标准单位规则。
- 多轮案卷审核时，后续提问无法关联前序已确认的申报材料细节。原因是未配置足够长度的`maxContext`，导致历史对话与已上传的申报文档上下文未被保留。
- 调用接口返回HTTP 403状态码。原因是未正确填写`AIPROXY_API_TOKEN`，或配置的接入节点未适配本场景的合规调用要求。

## 怎么确认配好了
- 上传一份标准的化肥农药登记申请表，检查模型是否能正确提取登记证号、有效成分含量等指定字段，无单位识别偏差。
- 发起两轮连续的审核提问，检查第二轮提问是否能关联前一轮提及的申报材料细节。
- 验证`AIPROXY_API_TOKEN`配置后，调用接口返回正常的审核结果，无权限相关报错。
- 查看模型引用的申报材料片段，确认片段长度符合设定要求，未出现无关内容。
