# 医药流通的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
医药流通领域的申报材料与案卷审核数据，来源为GSP认证申报文件、药品经营许可证年检案卷、冷链运输合规备案文档、供应商资质审核材料等。数据更新节奏随单次申报批次、年度年检周期及日常经营数据变动，无固定周期。文档多为多页PDF或结构化Word，包含药品通用名、批准文号、经营资质编号、冷链温度记录、批次号等固定字段，单位涉及毫克、毫升、摄氏度、批次号等，部分材料附带纸质扫描件的资质文件。

## 这些特征在「模型接入与配置」这一环带来什么约束
多页长文档的特征要求模型上下文配置需容纳完整案卷内容，避免截断审核所需的关键细节；固定字段与格式要求，需精准匹配字段提取的prompt逻辑，保证审核结果的准确性；批量申报文件的高频更新需求，要求向量更新配置适配批量处理流程；不同类型的申报材料（电子文档、纸质扫描件）差异，需适配模型的文本解析与视觉解析配置，覆盖全类型审核材料。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 医药流通申报材料多为多页长文档，需容纳完整案卷内容以覆盖所有审核细节 |
| `maxTokens` | 2000–3000 token | 单条审核结果需涵盖材料细节与合规判断，避免截断关键的资质编号、温度记录等信息 |
| `quoteMaxToken` | 1500 字符 | 需引用申报材料中的具体字段内容，保留足够长度以完整展示原始文档片段 |
| `toolChoice` | auto | 需根据审核需求自动触发工具调用或直接解析材料，适配合规标准查询与文档审核的双重场景 |
| `temperature` | 0.1–0.3 | 审核环节需保持严谨性，降低输出随机性以保证合规判断的一致性 |
| `AIPROXY_API_TOKEN` | 绑定企业专属调用密钥 | 保障医药流通敏感经营数据的传输与调用权限安全 |

## 容易做错的三处
- 现象：测试模型接入时返回404 status code (no body)，原因：`AIPROXY_API_ENDPOINT`配置了错误的端点地址，未绑定医药流通专属的调用路径。
- 现象：部分上传的纸质扫描申报材料未被自动解析，输出结果中资质字段为空，原因：未开启`vision`参数适配图片格式的资质文件，或`maxContext`设置过小无法触发解析逻辑。
- 现象：非工具调用模式下，审核结果未引用网络搜索的最新合规标准内容，原因：未开启工具调用开关，或`toolChoice`被强制设为固定模式，导致无法触发网络搜索接点。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，上传单份完整的GSP申报案卷，核对模型输出是否包含材料中的关键字段，确认引用内容与原始文档匹配。
- 触发批量文件向量更新，检查是否能自动处理所有上传的申报材料，无遗漏报错。
- 发起审核请求，查看返回结果是否带有合规判断依据的引用标记，确认引用内容的长度符合配置要求。
- 测试工具调用模式，检查是否能正常触发网络搜索接点，获取最新的医药流通合规政策内容。
