# 医药流通的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来源于医药流通企业的药品经营许可申报材料、流通追溯案卷、合规自查档案及监管部门反馈的整改文档。数据随单次申办流程实时更新，或按每季度1次的频率完成归档同步。文档包含结构化表单字段与非结构化附件，结构化字段涵盖药品通用名、经营许可证编号、流通批次号，非结构化附件多为扫描件、签字盖章文件，单位涉及批次、件、小时等流通场景专属计量项。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化字段与非结构化附件混合的文档结构，要求检索同时覆盖关键词精准匹配与语义关联召回。流通批次号、经营许可证编号等精准标识字段，需要合理的相似度阈值保障召回准确性。数据随申办流程实时更新的节奏，要求检索数据源同步最新归档的案卷与申报材料，避免召回过期无效内容。非结构化扫描件的OCR识别误差，可能导致关键词匹配失效，需额外适配二次过滤逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 适配医药流通场景中精准字段与语义文本的混合匹配需求，避免低相关结果混入 |
| `limit` | 前8–12条结果 | 覆盖单次申报材料审核所需的关联案卷与参考文档数量，避免上下文过载 |
| `searchMode` | hybrid | 结合关键词匹配与语义召回，适配结构化字段与非结构化附件的混合文档类型 |
| `usingReRank` | 开启，重排召回的Top5结果 | 对召回结果进行二次排序，过滤OCR识别误差导致的低质量匹配结果 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 申报材料与案卷审核场景下无需扩展查询，避免引入无关的流通行业通用文档 |
| `collectionIds` | 绑定专属医药流通合规数据集 | 限定检索范围，排除其他品类的文档干扰，保障审核结果的针对性 |

## 容易做错的三处
- 检索时返回空结果。原因：未绑定专属医药流通合规数据集，检索范围覆盖了无关品类的文档，导致无匹配内容。
- 导入的扫描件附件在知识库中显示乱码。原因：未开启重排功能，未过滤OCR识别产生的错误字符。
- 回答界面强制展示知识库搜索结果模块。原因：未针对审核场景关闭默认的搜索结果展示配置，引入了非必要的界面元素。

## 怎么确认配好了
- 进入FastGPT v4.17.0后台的数据集管理页面，确认已绑定专属医药流通合规的collectionIds。
- 提交一条包含药品流通批次号的测试查询，核对返回结果的相似度是否在0.72–0.85区间内。
- 上传一份扫描版的经营许可附件，查看知识库中是否无乱码展示，且重排功能生效。
- 触发一次审核问答，确认界面未强制展示知识库搜索结果模块。
