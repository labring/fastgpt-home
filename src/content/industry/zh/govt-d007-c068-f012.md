# 医药流通的申报材料与案卷审核：部署与升级

## 这个品类的数据长什么样
医药流通的申报材料与案卷审核数据，主要来源于企业向监管部门提交的药品经营许可、冷链运输备案等申报文件，以及内部留存的GSP检查、批次流通案卷。数据更新随申报与检查流程触发，单次申报材料包含固定字段：申报主体名称、药品通用名、批次号、流通范围、审批状态，附带扫描件、运输记录表格等附件。字段包含字符串、数值单位，如批次号为无单位标识，运输距离以公里为单位，存储温度以摄氏度为单位。文档结构分为结构化元数据与非结构化附件两部分，单份申报材料的附件大小差异较大。

## 这些特征在「部署与升级」这一环带来什么约束
医药流通申报材料与案卷的多格式、突发更新特征，对部署与升级环节带来明确约束。结构化元数据与非结构化附件混合存储的需求，要求部署时配置独立的大文件存储路径，避免本地磁盘过载。随申报批次出现的突发写入峰值，需要适配数据库连接池的弹性配置，防止连接耗尽导致服务中断。旧版案卷格式的兼容性要求升级时需保留字段解析逻辑，避免导入历史数据时出现元数据丢失。同时，特定单位字段的保留需求，要求配置文本提取时不剥离单位信息，保障审核环节的字段准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–150 个 | 适配医药流通申报的突发写入峰值，避免数据库连接耗尽 |
| `STORAGE_S3_ENDPOINT` | 对应企业内部对象存储的访问地址 | 用于存储申报材料的扫描件、案卷附件等大文件，分离本地磁盘负载 |
| `MONGODB_URI` | 独立部署的副本集连接地址 | 存储非结构化的案卷元数据与嵌入向量，保障高可用与读写性能 |
| `REDIS_URL` | 带密码认证的单机或集群地址 | 缓存频繁查询的审批状态与申报批次信息，降低核心数据库压力 |
| `FE_DOMAIN` | 企业内部访问的域名 | 用于生成带权限的文件访问链接，保障敏感医药材料的访问安全 |

## 容易做错的三处
-  现象：Docker镜像拉取超时或失败，提示网络连接错误。原因：未配置企业内部镜像加速地址，或外部网络访问受限，无法拉取官方FastGPT镜像。
-  现象：导入插件时提示`internal server error`，无详细报错日志。原因：`REDIS_URL`配置错误或连接超时，导致插件加载时的缓存校验失败，未正确配置`FILE_TOKEN_KEY`导致权限校验异常。
-  现象：部署后磁盘占用持续增长，无法定位占用来源。原因：未配置`STORAGE_S3_ENDPOINT`将大文件存储到外部对象存储，导致原文件、分割块与嵌入向量全部存储在本地磁盘，未定期清理过期申报案卷。

## 怎么确认配好了
-  执行`docker ps`命令，确认FastGPT容器与关联的数据库、Redis容器均处于运行状态。
-  上传一份医药流通的申报材料扫描件，通过界面测试文件上传与访问功能，验证`STORAGE_S3_ENDPOINT`配置生效。
-  提交一条模拟申报数据，查看数据库连接日志，确认`DB_MAX_LINK`的配置未触发连接耗尽告警。
-  访问`FE_DOMAIN`绑定的地址，验证前端页面可正常加载并展示申报案卷列表。
