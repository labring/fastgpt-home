# 发电装备制造的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
发电装备制造的申报材料与案卷，来自企业内部研发系统、资质申报平台、质检部门归档文件，包含立项申报文件、设计图纸、工艺规程、质检报告、制造许可证等。更新节奏为项目立项阶段批量更新，日常维护仅更新少量变更后的案卷。文档结构包含长文本（单份可达数十万字）、结构化字段（如设备型号、额定热功率、制造日期，单位多为MW、小时、台套），附件格式涵盖PDF、CAD导出文档、Word工艺文件，案卷按项目编号归档，每份案卷包含多份关联文档。

## 这些特征在「向量模型与索引」这一环带来什么约束
发电装备制造的申报材料与案卷特征，对向量模型与索引环节带来多重约束。长文本占比高，单份文档可达数十万字，要求分块策略需避免截断专业参数描述；结构化字段与非结构化文本混合，需针对性配置元数据与正文的索引权重；项目阶段的批量更新特性，要求索引支持增量同步，降低全量重建的资源消耗；多格式附件的存在，要求向量模型兼容不同格式转换后的文本内容；案卷按项目编号归档的强关联性，要求索引支持按项目维度的关联检索，提升审核匹配精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配发电装备制造申报材料中的长文本与专业术语，避免拆分关键参数描述 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的上下文关联，防止工艺步骤、参数序列被截断 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 匹配案卷审核中对相似申报材料的匹配精度要求 |
| `defaultToken` | 4096 token | 适配长文档的向量嵌入上下文长度，覆盖单份设计方案的核心内容 |
| 单次搜索上限 | 前10条 | 控制审核场景下的候选案卷数量，避免信息过载 |
| `maxToken` | 8192 token | 匹配FastGPT v4.17.0的上下文窗口上限，适配多份关联案卷的整合检索 |

## 容易做错的三处
- 现象：上传10M以上的整机设计PDF时，分块后出现部分chunk向量化失败，反复点击重试可恢复部分任务。原因：分块长度未适配文档中的表格与换行结构，导致chunk格式异常触发向量化校验失败。
- 现象：Ubuntu系统部署的FastGPT服务崩溃重启后，已上传的案卷知识库状态卡在「未就绪」，无自动索引触发。原因：未开启增量索引的自动重试配置，且未设置定时索引触发规则，导致离线任务未恢复。
- 现象：升级FastGPT版本后，原有案卷知识库无法返回检索结果。原因：未重新生成对应版本的向量索引，新旧版本的向量模型嵌入维度不匹配，导致检索时无法命中原有向量库。

## 怎么确认配好了
- 上传单份15M左右的整机设计方案PDF，查看分块预览界面，确认每个chunk的内容未截断核心参数。
- 触发批量上传10份历史案卷，查看向量任务队列的进度条，确认无异常失败的chunk计数。
- 执行一次跨案卷的关联检索，输入指定项目关键词，确认检索结果包含关联的质检报告、工艺文件。
- 重启FastGPT服务后，查看知识库列表的状态，确认所有已上传的案卷自动进入索引就绪状态。
