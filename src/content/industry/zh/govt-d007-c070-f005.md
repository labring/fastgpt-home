# 发电装备制造的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
发电装备制造的申报材料与案卷审核数据，主要来源于企业内部的设计图纸、出厂检验报告、并网审批案卷、设备运维台账。数据更新随单项目完成归档后静态存储，运维类案卷随季度巡检周期更新。文档形态以嵌入参数表格的docx、带技术说明的pdf为主，结构化字段包含设备型号、额定功率、出厂编号、检验批次、审批节点，单位涉及kW、MPa、运行小时数等。

## 这些特征在「工具调用与插件」这一环带来什么约束
发电装备制造的申报与案卷数据的多格式、结构化特征，对工具调用与插件带来多重约束。混合格式的文档要求插件适配docx与pdf的结构化解析，避免仅提取纯文本导致参数表格丢失。带特定单位的字段需要插件在解析时保留单位信息，防止后续校验环节出现单位不匹配的问题。单项目归档数据体量较大，工具调用的上下文长度需适配长文档处理，避免截断关键参数。定期更新的运维案卷，要求插件配置可定时拉取更新数据源的触发逻辑。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 文档解析格式 | 优先解析docx内嵌表格，保留单位字段 | 适配发电装备数据的结构化参数表特征 |
| 单次调用上下文长度 | 8000–12000 字符 | 适配单项目归档文档的体量，避免截断关键参数 |
| 单次调用超时时间 | 600 秒 | 适配长文档解析与多字段校验的耗时需求 |
| `toolChoice` | auto | 适配多类型审批节点的动态调用需求 |
| `functionCall` | 开启强制参数校验 | 确保申报字段的单位与格式符合要求 |
| 数据源更新周期 | 按季度触发 | 匹配运维案卷的巡检更新节奏 |

## 容易做错的三处
- 现象：调用插件时无法读取url指向的docx文档，返回连接超时或文件解析失败。原因：未在插件配置中启用docx格式的结构化解析适配，仅支持纯文本格式的文档拉取。
- 现象：审核结果中未包含设备参数的单位字段，导致校验不通过。原因：解析文档时未保留kW、MPa等单位信息，仅提取了纯数值内容。
- 现象：调用`functionCall`工具后返回的审核结果未匹配预设的申报字段要求。原因：未开启强制参数校验，导致非标准格式的字段被纳入审核范围。

## 怎么确认配好了
- 上传一份包含额定功率、出厂编号等结构化参数表格的docx文档，核对解析结果是否保留了字段与对应单位。
- 调用`functionCall`工具，提交不符合格式的模拟申报数据，检查是否触发参数校验提示。
- 配置数据源更新触发规则，验证是否按设定周期拉取最新的运维案卷数据。
- 调整工具调用的触发逻辑，核对是否按申报审批节点触发对应的校验工具。
