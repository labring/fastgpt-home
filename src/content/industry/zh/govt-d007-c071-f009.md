# 发电集团的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
发电集团的申报材料与案卷审核数据主要来自内部机组运行台账、项目审批档案、环保申报文件及案卷归档记录。数据更新节奏随业务流程而定：项目类申报材料按季度或年度批次更新，日常案卷随审核办结实时更新。文档多采用固定模板结构，申报材料包含机组编号、发电量、煤耗率、审批文号等字段，案卷则包含案卷号、涉及项目、审核意见、办结日期等字段，部分字段带有固定格式与单位，如发电量以兆瓦时为单位，审批文号以「XX电审〔年份〕XX号」格式呈现。

## 这些特征在「模型接入与配置」这一环带来什么约束
发电集团的申报材料与案卷审核数据特征，对模型接入与配置带来多项约束。多批次更新的结构化数据要求模型配置支持批量数据召回，避免单次调用遗漏跨批次的案卷对比信息。固定模板但字段较多的文档，要求配置足够的上下文长度以容纳完整的字段信息，防止模型截断关键参数。带有固定格式的字段要求模型配置适配特定提取规则，确保审核结果的字段准确性。内部部署的API节点要求配置专属的访问地址与令牌，保证数据不出域，同时需适配集团内部的时间同步机制，确保输出结果的时间准确性。

## 配置怎么定
基于FastGPT v4.17.0版本的配置逻辑，以下为推荐配置项及取值：

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 申报材料与案卷常包含多页台账、审批文件，需容纳完整上下文片段 |
| `maxTokens` | 2000–3000 token | 单条审核结论需清晰输出，避免超出模型输出上限 |
| `quoteMaxToken` | 1500 token | 需引用的案卷编号、机组参数等内容占比固定，限制引用文本长度 |
| `temperature` | 0.1–0.3 | 审核需严谨，降低随机性以保证字段提取与判断的一致性 |
| `AIPROXY_API_ENDPOINT` | 按集团内部部署节点填写 | 适配私有部署的API节点，保证数据不出域 |
| `AIPROXY_API_TOKEN` | 绑定集团内部IP白名单的专属令牌 | 确保仅授权节点可调用模型接口，提升安全性 |

## 容易做错的三处
- 模型输出的发电量合计数值与台账不符，现象是审核结果中字段计算偏差。原因是未配置足够的`maxContext`，导致模型截断了部分台账数据，遗漏关键参数。
- 本地模型调用后无法获取服务器最新申报时间，现象是结果中时间字段滞后于实际提交日期。原因是未正确配置`AIPROXY_API_ENDPOINT`指向集团内部时间同步节点，或未开启模型的实时数据调用权限。
- 自定义API接入后返回状态码403，现象是模型调用失败。原因是`AIPROXY_API_TOKEN`配置错误，未绑定集团内部允许的IP白名单。

## 怎么确认配好了
- 上传单份完整的机组申报材料，检查模型输出的上下文是否包含全部关键字段，确认`maxContext`配置覆盖了目标文本长度。
- 提交包含历史案卷对比的审核请求，检查模型是否正确引用了相关案卷内容，确认`quoteMaxToken`设置合理。
- 调用配置好的API接口，查看返回结果的时间字段是否与服务器当前时间一致，确认时间同步配置生效。
- 调整`temperature`参数至0.2，多次提交同一份材料，检查输出结果的一致性，确认参数取值符合审核严谨性要求。
