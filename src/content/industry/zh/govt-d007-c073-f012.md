# 国有产业基金的申报材料与案卷审核：部署与升级

本指南基于 FastGPT v4.17.0 版本编写。

## 这个品类的数据长什么样
国有产业基金的申报材料与案卷审核数据，主要来源于申报主体提交的电子申报书、国资监管平台归档的审批案卷，更新节奏随项目申报周期集中触发，日常存在补件更新。文档包含结构化字段（如项目编号、申报主体统一社会信用代码、投资额度（单位：万元））与非结构化内容（如可研报告、合规证明扫描件转写文本），单份案卷文本长度跨度大，最长可达数万字符。

## 这些特征在「部署与升级」这一环带来什么约束
集中申报周期的高并发数据提交，要求部署环节调整数据库连接上限以支撑峰值流量；长文本案卷的跨度差异，要求升级时优化文本拆分逻辑，避免出现块丢失问题；结构化字段与非结构化文本的混合存储，需要配置适配的向量数据库与关系型数据库联动方案；日常补件的增量更新需求，要求部署时预留增量同步的配置入口，避免全量重处理占用过多资源。同时，国资系统的合规要求，需要限定系统访问范围与存储端点，保障数据安全。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 60–120 个连接 | 适配集中申报周期的高并发数据读取请求，避免数据库连接耗尽 |
| `REDIS_URL` | 配置 1000–2000 MB 缓存配额 | 缓存高频检索的申报字段与案卷片段，降低关系型数据库的访问压力 |
| `STORAGE_S3_ENDPOINT` | 绑定国资云合规存储端点 | 满足国有产业基金案卷数据的存储合规要求，保障数据安全可控 |
| `MONGODB_URI` | 部署专用文档型数据库实例 | 存储非结构化的可研报告、合规证明等长文本内容，适配长文本检索需求 |
| `FE_DOMAIN` | 配置内部专网访问域名 | 限定系统访问范围，符合国资系统的网络隔离管理规范 |
| `ROOT_KEY` | 生成符合企业安全规范的随机密钥 | 限制后台操作权限，避免未授权的系统配置修改 |

## 容易做错的三处
- 现象：文本分割后出现块丢失，检索时无法召回完整的可研报告内容。原因：未针对国有产业基金的长文本案卷调整适配的拆分逻辑，沿用通用配置导致长文本被错误截断。
- 现象：docker 部署后出现数据库连接超时，后台返回 504 状态码。原因：`DB_MAX_LINK` 配置值过低，无法支撑集中申报周期的高并发数据请求。
- 现象：模型无法正确匹配申报材料中的结构化字段，审核结果出现字段遗漏。原因：未配置适配的检索召回规则，导致结构化字段未被优先召回。

## 怎么确认配好了
- 发起模拟集中申报的并发请求，观察数据库连接状态，确认`DB_MAX_LINK`配置的连接数可支撑峰值流量。
- 上传单份超过万字的可研报告，检查检索返回的文本块是否完整，确认拆分逻辑适配长文本案卷。
- 访问系统后台，使用`ROOT_KEY`验证权限，确认仅授权用户可执行配置修改操作。
- 上传单份补件文件，检查系统是否仅同步新增内容，确认增量更新机制正常运行。
