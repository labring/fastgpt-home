# 国有资产管理公司的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
国有资产管理公司的申报材料与案卷审核数据，主要来源于内部项目申报系统、国有资产备案台账与外部审批回传文件。数据更新随项目推进触发，单次批量上传量可达数十份至数百份。文档多为混合结构，包含标准化字段如申报主体、资产类别、审批文号，以及长文本的申报说明、审核案卷正文，部分文件附带扫描件转写的纯文本内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
混合结构的文档包含标准化字段与长文本正文，要求索引环节需支持按字段加权召回，避免非核心字段干扰匹配精度。单次批量上传的文档数量较多、长文本占比高，会拉长单批次索引耗时，需适配分块参数与索引队列的调度规则。部分扫描件转写的文本存在格式冗余，会增加向量模型的计算负载，需在索引前过滤无效字符。另外，申报材料的更新周期随项目波动，增量索引的触发逻辑需适配非固定频率的更新节奏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配长文本的申报说明与案卷正文，避免单块超出向量模型输入限制 |
| 重叠长度 | 100–150 字符 | 保留跨块上下文，减少关键审核信息的断裂 |
| `maxToken` | 4096 token | 匹配主流开源向量模型的输入上限，适配国有资产管理公司文档的平均长度 |
| 相似度阈值 | 0.75–0.85 | 区分有效匹配与噪声匹配，适配申报材料的专业术语密度 |
| 单次召回上限 | 前 10 条 | 控制上下文窗口长度，避免超出模型处理能力 |

## 容易做错的三处
- 现象：升级FastGPT v4.17.0后，原csv格式的申报材料索引报错，提示分块失败。原因：新版本对csv文件的字段分隔符校验规则调整，未指定分隔符时默认使用逗号，而部分旧模板使用了分号分隔字段。
- 现象：批量导入百份案卷材料后，索引状态长时间停留在「处理中」，未生成索引进度条更新。原因：未配置索引队列的并发上限，大量长文本分块同时提交导致系统资源耗尽，进程阻塞。
- 现象：切换向量模型后，已索引的历史数据无法被新模型召回，检索结果为空。原因：未重新生成历史数据的向量嵌入，新旧模型的向量空间不兼容，需重建索引。

## 怎么确认配好了
- 上传单份典型的申报材料，触发手动索引，查看分块结果是否按设定的长度拆分，无冗余空块。
- 发起模拟审核检索，输入专业审核关键词，查看召回结果的相似度分值是否落在设定的阈值区间内。
- 批量导入10份测试案卷，检查索引队列是否按配置的并发上限调度，无进程阻塞报错。
- 切换向量模型后，重新生成单份测试数据的向量嵌入，验证检索结果是否正常返回。
