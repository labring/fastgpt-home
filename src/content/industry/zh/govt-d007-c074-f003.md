# 国有资产管理公司的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
数据来源包括国资监管报送系统、企业内部审批台账、项目申报归档库。更新节奏随单次申报批次完成更新，单次申报周期内数据无额外变更。文档分为申报材料与案卷审核两类，申报材料包含项目基本信息表、财务测算表、合规说明文件，案卷审核包含流程节点记录、整改意见清单、最终批复文件。特有字段包括项目编号、国资持股比例、申报金额、审核节点状态，申报金额以万元为单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散导致多轮对话需要跨系统调用不同类型的文档，提示词需明确指定各数据源的字段映射规则，避免模型混淆不同批次的项目数据。长文本结构要求多轮对话的上下文窗口需适配单份申报材料的长度，防止截断核心审核字段。特有国资字段要求提示词固定包含校验规则，确保模型准确识别项目编号、申报金额等关键信息。随批次更新的数据要求对话流程支持临时绑定专属数据集，确保调用的是当前审核批次的最新内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 适配单份申报材料的平均长度，避免截断核心审核字段 |
| 提示词模板 | 固定包含国资项目字段校验规则 | 准确识别项目编号、申报金额、国资持股比例等特有字段 |
| 多轮对话历史保留 | 15–20轮对话 | 覆盖单次申报从提交到终审的完整流程节点 |
| `variables` 配置 | 绑定对应申报批次的专属数据集 | 精准调用该批次的申报材料与案卷数据 |
| `chatId` 配置 | 绑定项目唯一编号 | 区分不同批次的审核对话上下文，避免混淆 |
| 前端文件上传接口 | 支持PDF、Excel格式，最大1000 MB | 适配申报材料的附件类型与大小限制 |

## 容易做错的三处
- 现象：多轮对话中返回其他批次的申报材料，审核结果出现跨项目混淆。原因：未绑定`chatId`与项目唯一编号，导致不同批次的对话上下文未隔离。
- 现象：前端开启文件上传后，对话接口无法读取上传的申报附件。原因：未配置`variables`绑定上传文件的临时存储路径，导致对话流程无法访问附件内容。
- 现象：调整提示词后，审核精度无明显变化，甚至出现字段识别错误。原因：未将国资特有字段校验规则写入`messages`的系统提示部分，导致模型无法聚焦核心审核要求。

## 怎么确认配好了
- 发起单次申报审核的对话，输入项目编号，核对返回内容是否仅包含该批次的申报材料与案卷数据。
- 上传对应批次的申报附件，确认对话流程可读取附件中的核心字段，无缺失或混淆。
- 调整多轮对话的历史保留轮数，测试跨节点对话时上下文是否正常延续。
- 查看`chatId`的绑定配置，确认每个项目的对话上下文与其他批次完全隔离。
