# 国有资本投资公司的申报材料与案卷审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
数据来源为国资监管报送系统、内部项目申报管理平台及案卷归档数据库。更新节奏为年度申报周期内集中更新，日常按需新增或修订单条案卷。文档结构包含主体资质文件、项目可行性分析内容、审批流转记录三类核心模块，字段含统一社会信用代码、申报批次号、案卷归档日期、申报预算金额，单位分别为无、批次、年月日、万元。单条案卷的文档长度多在500-2000字符区间，部分重大项目案卷可扩展至万字级别。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据接入要求接口支持跨系统鉴权，需配置`Authorization`头适配国资监管系统与内部管理平台的不同认证规则。字段的特定单位要求`responseData`映射时保留统一社会信用代码、申报预算金额等字段的原生单位，避免转换误差。集中更新的业务节奏要求接口支持批量提交请求，同时需校验案卷归档日期、申报批次号等必填字段的格式合规性。不同系统的更新延迟差异，要求接口配置合理的超时参数，避免因单系统响应慢导致整体请求失败。单条案卷的长度差异，要求接口支持动态调整单次请求的文档传输上限，适配不同规模的申报材料。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 国资系统使用Bearer Token格式，内部系统使用API密钥 | 适配两类数据源的认证标准，符合国资监管的安全合规要求 |
| `variables` | 传入申报批次号、案卷归档日期作为上下文变量 | 匹配业务数据的核心标识，便于接口按批次筛选请求数据 |
| `responseData` | 映射统一社会信用代码、申报预算金额字段至业务系统的指定字段 | 保留数据原生单位与格式，避免二次转换产生的误差 |
| 请求超时时间 | 60-120秒 | 适配国资系统的响应延迟，避免批量请求超时中断 |
| 批量请求上限 | 前50条案卷单次提交 | 平衡接口负载与业务提交效率，符合单次申报的常规案卷数量 |
| 重试策略 | 失败后重试2次，间隔10秒 | 应对临时网络波动或系统短暂故障，减少批量提交的失败率 |

## 容易做错的三处
- 现象：调用接口后审核结果未按相关性排序，原因：未在接口配置中绑定重排相关参数，未触发重排逻辑。
- 现象：客户端中断接口连接后，提交的案卷数据未存入系统，原因：未配置接口的持久化存储参数，导致未完成的请求数据未落库。
- 现象：调用模型接口时提示密钥无效，原因：混淆了系统级与接口级的认证密钥位置，未在FastGPT v4.17.0的对应配置页面填入正确密钥。

## 怎么确认配好了
- 调用测试接口传入模拟申报批次号，检查`responseData`返回的字段是否包含统一社会信用代码、申报预算金额且单位与原生数据一致。
- 查看FastGPT的接口日志，确认`Authorization`头的Token格式与配置一致，无401未授权报错。
- 提交批量测试数据，检查返回结果的排序逻辑是否符合预期，确认重排功能已正常触发。
- 模拟中断接口请求，检查数据库中是否留存了未完成的案卷数据，确认持久化配置已生效。
