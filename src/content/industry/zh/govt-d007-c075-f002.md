# 国有资本投资公司的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
国有资本投资公司的申报材料与案卷数据来源包括内部项目申报系统、国资监管报送平台、归档的纸质案卷扫描件。更新节奏为季度申报周期内集中批量更新，日常有零星案卷归档或审批节点变更。文档结构包含结构化元数据与非结构化正文，元数据字段包括项目编号、申报主体、投资额度、审批状态、提交日期，单位统一使用万元、亿元等国资统计标准；非结构化正文涵盖可研报告、审计意见书、审批意见函，单篇长度跨度较大。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据包含结构化元数据与长文本非结构化内容，要求索引支持元数据过滤与长文本分块处理能力。集中批量更新的特性要求配置适配批量上传的接口调用频率，避免触发限流。单篇文档长度跨度大，需要动态调整分块参数避免语义断裂或信息截断。国资申报材料的严谨性要求相似度阈值需经过实测标定，过滤低相关的非目标案卷内容。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配申报材料中单篇可研报告的段落长度，避免核心审批节点信息因语义断裂丢失 |
| 重叠长度 | 100–150 字符 | 保留分块间的上下文关联，防止关键项目信息在分块边界处丢失 |
| maxToken | 4096 token | 匹配通用嵌入模型的输入上限，确保长文本分块能正常完成向量化 |
| 相似度阈值 | 0.72–0.80 按实测标定 | 过滤低相关的案卷内容，适配国资申报材料的严谨检索要求 |
| 单次搜索上限 | 前 8 条 | 控制返回结果的数量，避免上下文过载影响检索准确性 |
| defaultToken | 1024 token | 统一短字段元数据的嵌入输入长度，保证元数据检索的一致性 |

## 容易做错的三处
- 界面显示“一直处于索引中”，且上传后无数据条目。原因：未正确配置分块长度，导致超长文本分块时触发嵌入模型截断失败，未生成可被索引的有效向量。
- 搜索返回结果全部相关性极低，且无法命中目标案卷。原因：未根据申报材料的字段配置元数据过滤规则，导致无关系统日志或非目标项目文档混入检索结果。
- 调用pushdata api上传chunk模式数据后，索引进度停滞。原因：未设置合理的maxToken参数，分块文本超出模型输入上限，导致向量化任务超时未完成。

## 怎么确认配好了
- 上传单篇1000字符左右的申报说明文档，查看索引进度是否在1分钟内完成，且生成的向量条目数量与预期分块数匹配。
- 输入包含具体项目编号的检索词，核对返回结果是否仅包含对应项目的案卷材料，无无关内容混入。
- 测试超长文本（超过5000字符）的上传，查看是否生成正确的分块向量，无截断相关的报错提示。
- 查看嵌入模型的调用日志，确认maxToken参数匹配当前使用的模型输入上限，无参数不兼容的报错记录。
