# 国有资本投资公司的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
国有资本投资公司的申报材料与案卷审核数据，主要来源于内部国资申报系统、企业档案库及国资委下发的填报模板。数据更新以年度、季度申报批次为核心节奏，日常伴随新案卷归档同步更新。单份文档包含申报书、财务审计报告、产权证明、项目可行性报告等子文件，核心字段包括项目编号、申报主体、国资占比、审批节点、案卷归档号，财务类字段单位为万元，案卷类字段单位为件。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需支持跨系统拉取不同类型的申报材料，无法依赖单一数据源完成全流程处理。按批次更新的特性要求工作流需适配定时触发或手动触发的启动逻辑，匹配申报周期节奏。文档结构复杂且包含专有审核字段，要求工作流节点需支持定制化的文本提取与分类规则，适配国资相关专有字段的识别需求。单份文档长度差异较大，需工作流具备灵活的分块与处理能力，避免因单条文本过长导致节点失效。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量映射 | 绑定`variables`中的项目编号、国资占比字段 | 国有资本投资公司申报材料的核心审核字段为项目编号与国资占比，需精准映射提取 |
| 节点超时设置 | `300-600秒` | 单份申报材料平均长度较长，需预留足够处理时间 |
| 节点ID绑定 | 绑定`nodeId`为案卷审核专属标识 | 区分不同批次、不同主体的审核流程，避免流程混淆 |
| 文本分块长度 | `800-1200字符` | 适配申报材料中常见的段落长度，平衡提取精度与处理效率 |
| 单次处理上限 | `前20条案卷` | 单批次案卷数量适中，避免单节点处理负载过高 |
| 触发条件配置 | 按新上传案卷触发 | 日常案卷审核以新归档材料为触发源，符合工作流启动逻辑 |

## 容易做错的三处
- 现象为文本分类提取节点返回空结果，原因是未针对国有资本投资公司的专有字段（如国资占比、项目立项文号）配置提取规则，通用提取模板无法匹配专属字段。
- 现象为工作流导入时报错无法识别节点配置，原因是未在FastGPT v4.17.0版本下导出旧版工作流，跨版本导入时节点参数未完成自动兼容。
- 现象为自定义工具变量未生效，原因是未在`variables`中绑定对应案卷的字段参数，变量映射未关联到实际数据源。

## 怎么确认配好了
- 上传单份标准申报材料，触发工作流后查看文本提取节点的返回结果，确认核心字段是否被正确提取。
- 检查`variables`配置项，确认已绑定项目编号、案卷归档号等专属审核字段，无遗漏的必要参数。
- 触发测试流程，验证节点超时设置未触发超时报错，且多批次案卷的流程可独立运行互不干扰。
- 查看工作流日志，确认`nodeId`绑定的专属标识已正确关联到对应批次的案卷审核流程。
