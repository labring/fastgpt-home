# 国有资本投资公司的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
国有资本投资公司的申报材料与案卷审核数据，主要来源于国资监管部门的申报系统、内部项目审批台账、行业政策文件库。数据更新节奏随单个申报项目的推进调整，单次申报周期内可多次修改。文档多为多页PDF、结构化Excel或在线表单，字段包含项目编号、申报主体名称、注册资本、拟投资金额、审核节点、审批意见、完成时限等，单位涉及万元、人次、工作日等。

## 这些特征在「工具调用与插件」这一环带来什么约束
单份申报案卷的内容长度差异较大，部分大型项目案卷可达数十页，因此工具调用需限制单次处理的内容量，避免上下文溢出。结构化字段占比高，需工具调用时精准抽取特定字段，因此需配置自动匹配对应抽取函数的规则。申报数据随项目进度更新，插件需支持按需拉取最新的审批节点数据，避免使用过时信息。部分字段涉及国资敏感信息，工具调用需绑定内部权限校验规则，确保数据访问合规。

## 配置怎么定
本文配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配多类型申报材料的字段抽取需求，无需手动指定单个函数 |
| 单次工具调用上限 | 前3条 | 避免单案卷内容过长导致上下文溢出，符合国有资本申报材料的常规页数 |
| 上下文窗口预留 | 1000–1500 token | 预留空间处理工具返回的案卷审核日志数据 |
| `functionCall` | 严格JSON格式 | 适配国资系统接口的参数校验规则，减少调用失败率 |
| 超时时间 | 600 秒 | 覆盖大型申报案卷的解析与跨系统同步耗时 |
| 分块长度 | 800–1200 字符 | 适配申报材料中结构化表格与文本混合的内容结构 |

## 容易做错的三处
- 现象：调用支持联网的模型时，无法获取最新申报政策信息。原因：仅绑定了知识库检索工具，未配置可触发联网检索的插件规则。
- 现象：工具调用返回的JSON格式不符合系统要求，触发报错。原因：未启用`functionCall`的严格格式校验，生成的参数与国资监管系统的接口规范不匹配。
- 现象：单次工具调用返回的结果条数超出预期，导致上下文溢出。原因：未设置单次工具调用上限，默认拉取了过多的案卷审核节点数据。

## 怎么确认配好了
- 提交一份标准申报案卷，查看工具调用日志中是否按配置的`toolChoice`自动选择对应字段抽取函数。
- 模拟超时场景，验证工具调用是否在600秒内触发超时提示或重试机制。
- 测试跨批次申报数据的拉取，确认插件能同步最新的申报台账与审批节点信息。
- 检查工具调用返回的JSON格式是否符合预设的校验规则，无格式错误。
