# 国有资本运营公司的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
国有资本运营公司的申报材料与案卷数据来源包括国资监管部门备案文件、内部经营台账、项目申报函件、过往审批案卷等。数据更新以单项目申报周期为节点，集中更新后伴随日常补充调整。文档结构包含主体资质文件、财务审计报告、项目可行性研究书、审批流程案卷等模块。字段包含统一社会信用代码、国资备案编号、项目投资额（单位万元）、审批节点时间戳等专属业务标识。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散导致需要跨多系统召回关联信息，增加了溯源的匹配复杂度。单份文档长度较长，要求溯源引用不能过度截断关键合规字段，否则会影响审核判断。专属业务字段的存在要求溯源必须精准匹配对应标识，避免混淆不同项目的材料。集中更新的节奏要求溯源数据需定期同步，保证审核时的信息时效性，否则会出现引用过时内容的情况。

## 配置怎么定
本文档适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 适配国有资本运营公司申报材料单份文档的平均字符长度，避免截断关键溯源字段 |
| `responseData` | 开启 | 要求输出引用内容的原始文本，满足国资审核的合规溯源要求 |
| `detail` | 开启 | 展示案卷审批的完整节点信息，帮助审核人员追溯流程细节 |
| 单次召回上限 | `前5条` | 国有资本运营公司的申报材料关联案卷通常不超过5个关联项，避免冗余信息干扰审核 |
| 知识库增量同步频率 | `每日1次` | 匹配项目申报周期内的集中更新节奏，保证溯源数据的时效性 |

## 容易做错的三处
- 现象：发起接口请求后接口连通，但无content返回值。原因：未开启`responseData`配置项，导致接口仅返回结构化标识而未携带原始引用内容。
- 现象：引用内容排版混乱，字段展示不规范。原因：未开启`detail`配置项，未按文档结构拆分引用片段，导致展示杂乱无章。
- 现象：召回的引用条数与实际关联案卷不符。原因：单次召回上限设置未匹配业务场景，过高会引入无关案卷，过低会遗漏必要溯源信息。

## 怎么确认配好了
- 发起测试请求，检查返回结果中是否包含`responseData`字段对应的原始引用内容。
- 查看引用展示区域，确认是否按文档结构拆分并展示`detail`级别的案卷节点信息。
- 提交一份标准申报材料，核对召回的关联案卷条数是否符合业务预期。
- 检查知识库同步日志，确认增量更新任务按预设频率执行。
