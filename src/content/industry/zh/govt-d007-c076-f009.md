# 国有资本运营公司的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
国有资本运营公司的申报材料与案卷审核数据，主要来源于国资监管内部系统、企业内部申报审批系统、案卷归档存储库。数据更新按年度申报批次、季度专项审核周期推进，单份申报材料包含固定模板结构，涵盖申报主体资质信息、项目投资明细、佐证材料附件清单、多级审批节点记录等内容。字段包含统一的案卷编号、申报金额（单位万元）、注册资本（单位万元）、审批文号等标准化字段，部分材料附带多页扫描件与结构化表格。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散在多个内网系统中，要求模型接入需适配内网环境，无法依赖公网第三方服务。单份案卷材料长度差异较大，部分专项审核案卷可达数十页，对模型上下文承载能力提出明确要求。固定的字段格式与结构化内容，需要模型输出的审核结果严格匹配预设字段，避免格式偏差。内网部署的约束还要求所有模型服务与依赖组件需在企业内网网段内运行，需解决内网环境下的服务连通与权限验证问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数设置逻辑：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 单份申报案卷平均长度较长，需覆盖完整案卷上下文以完成全量审核 |
| `maxTokens` | 2000–3000 token | 审核结果需包含详细的字段校验与合规性判断，输出长度需匹配审核要点的展示需求 |
| `quoteMaxToken` | 1500 token | 需引用案卷内的佐证材料片段作为审核依据，限制引用片段长度避免上下文溢出 |
| `toolChoice` | auto | 需根据申报材料内容自动触发内部字段校验工具，确保审核结果匹配固定字段格式 |
| `temperature` | 0.1–0.3 | 审核需严格遵循国资监管的固定规则，降低模型输出的随机性以保证结果一致性 |
| `AIPROXY_API_ENDPOINT` | 内网部署的ollama服务地址，如`http://192.168.1.100:11434/v1` | 适配国有资本运营公司的内网部署要求，避免公网数据泄露风险 |
| `AIPROXY_API_TOKEN` | 内网模型服务生成的专属访问密钥 | 验证模型访问权限，确保仅授权的FastGPT服务可调用内网模型 |

## 容易做错的三处
- 内网部署测试时出现数据库连接拒绝报错，日志显示数据库正常启动：原因是FastGPT服务与数据库容器未加入同一内网网段，导致网络连通失败。
- 尝试接入ollama部署的模型时无法正常调用：原因是`AIPROXY_API_ENDPOINT`配置错误，未指向正确的内网模型服务端口或未添加正确的API路径后缀。
- 模型返回的审核结果未准确匹配申报材料的佐证内容：原因是`quoteMaxToken`参数设置不合理，导致引用的佐证材料片段不完整或超出范围。

## 怎么确认配好了
- 在FastGPT部署环境的内网中，通过curl命令测试`AIPROXY_API_ENDPOINT`的连通性，确认可正常返回模型服务响应。
- 上传一份标准格式的申报案卷，查看模型返回的审核结果是否包含所有预设的字段校验项与合规性判断。
- 查看模型调用日志，确认`maxContext`与`maxTokens`的实际使用值未超出配置的参数范围。
- 测试内网数据库连接，确认FastGPT服务可正常读取申报材料与案卷的数据源，无权限或连通报错。
