# 城市公交的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
数据来源为城市公交运营管理系统、政务申报平台的归档案卷与申报材料，更新节奏为单次申报完成后即时归档，日常审核案卷按周批量更新。文档结构分为申报表单字段（线路编号、申请主体、运营计划）、附件材料（车辆检测报告、场站图纸）、审批案卷（审核节点、意见批注），字段包含唯一标识编码、时间戳，文件附件大小单位为MB，文本内容多为结构化表单搭配非结构化附件。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的结构化字段与非结构化附件并存的特征，要求工具调用需同时支持结构化表单字段提取与多类型附件解析。单次申报的即时归档数据，要求插件的数据源同步需支持按需触发与定时触发两种模式，适配不同审核节点的时效性需求。唯一标识编码字段的存在，要求工具调用时需指定关联匹配字段，避免跨批次数据混淆。附件大小跨度大的特征，要求插件的文件处理环节需设置合理的大小过滤阈值，防止大文件占用过多调用资源。

## 配置怎么定
以下配置适用于FastGPT v4.17.0

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配申报材料中混合结构化与非结构化内容的识别需求，自动匹配对应工具 |
| 文本内容提取节点的聊天记录范围 | 前6条 | 覆盖单次审核的上下文信息，避免冗余数据占用调用额度 |
| 插件触发时机 | 申报提交后10分钟 或 每周一0点 | 匹配即时归档与批量更新的两种数据更新节奏 |
| 文件解析大小上限 | 100–200 MB | 适配公交申报附件的常见大小范围，按实测标定 |
| `functionCall` | `strict: true` | 确保工具调用返回格式符合审批案卷的字段规范，减少格式错误 |
| 单次工具调用超时时间 | 60 秒 | 适配中等大小附件的解析时长，防止超时中断审核流程 |

## 容易做错的三处
- 现象为插件中配置文本内容提取节点后，工作流运行返回空结果，原因是未指定聊天记录的上下文范围，导致工具调用无法获取历史审核信息。
- 现象为API调用环节返回格式错误提示，原因是未开启`functionCall`的严格模式，导致返回内容不符合审批字段的格式要求。
- 现象为传入文档链接后无法解析内容，原因是未配置对应文件类型的解析插件，公交申报附件常包含CAD图纸与PDF扫描件，需额外加载对应解析工具。

## 怎么确认配好了
- 运行单次模拟申报的测试数据，检查工具调用返回的字段是否包含预设的线路编号、审批状态等内容。
- 查看插件运行日志，确认文件解析环节未触发大小超限或超时报错。
- 对比工具调用返回结果与原始申报材料的字段，检查是否存在匹配错误或遗漏。
- 测试定时触发的插件同步任务，确认周更的批量案卷数据能够正常拉取。
