# 城市水务的申报材料与案卷审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
城市水务的申报材料与案卷审核数据来源为水务报装、排水许可、用水变更等业务的内部审批系统，更新节奏随单份申报流程推进，每份材料提交后实时更新。文档以结构化表单为核心，附带工程图纸、审批扫描件等附件，字段包含项目地址、用水性质、申报主体信息、案卷编号、审批节点等，单位多为米、平方米、立方米等市政工程通用单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的数据包含结构化表单字段与多类型附件，要求HTTP接口同时支持文本参数与文件上传。字段需严格匹配水务业务的固定命名与单位，接口参数校验需覆盖地址、面积、用水量等市政专用字段的格式。实时更新的业务节奏要求接口响应延迟控制在合理区间，避免阻塞审批流程。不同申报场景的字段差异，要求接口可通过`variables`传递动态业务参数，适配多样的案卷审核需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带水务系统专属Bearer Token，有效期2小时 | 适配水务内部系统的鉴权规则，保障接口调用安全，避免频繁刷新令牌 |
| `variables` | 传入项目地址、用水性质等业务字段，单次传递不超过20个 | 匹配申报材料的结构化字段要求，适配不同类型的案卷审核场景 |
| `responseData` | 仅返回审批状态、案卷编号核心字段，过滤冗余附件数据 | 减少接口返回数据量，提升FastGPT处理效率，聚焦案卷审核的核心信息 |
| 超时设置 | 30–60秒 | 覆盖水务业务数据的常规查询延迟，避免阻塞审批流程 |
| 附件上传上限 | 1000 MB | 适配工程图纸、审批扫描件等大附件的传输需求 |

## 容易做错的三处
- 现象：调用接口后返回401未授权，或原有鉴权配置被新配置覆盖。原因：未为不同水务申报场景配置独立的鉴权参数，导致多应用共享同一`Authorization`令牌引发冲突。
- 现象：接口调用超时，返回504网关超时错误。原因：未根据水务业务数据量调整超时设置，使用过短的超时时间无法完成大附件或复杂案卷数据的查询。
- 现象：返回的案卷数据字段缺失或格式错误。原因：未通过`variables`传递正确的业务参数，导致接口无法匹配对应申报材料的字段规则。

## 怎么确认配好了
- 调用配置好的接口，检查返回的`responseData`是否仅包含预设的核心字段，无冗余内容。
- 传入测试用的业务参数，确认接口可正常返回对应申报项目的审批状态与案卷编号。
- 上传测试用的小附件，确认接口可正常接收并处理文件传输请求。
- 查看接口调用日志，确认`Authorization`令牌携带正确，无鉴权失败记录。
