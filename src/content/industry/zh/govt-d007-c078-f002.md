# 城市水务的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
城市水务的申报材料与案卷审核数据，来源为城市水务集团的报装申请、水质检测申报、管网维护审批的电子与纸质材料，以及行政许可、行政处罚的案卷文档。更新节奏包含日常批量提交的运行台账数据，与临时单份的专项申报材料。文档格式涵盖PDF申报书、Word审批表、Excel运行台账，字段包含项目编号、申报单位、设计用水量、审批状态、案卷归档号等，单位涉及立方米、吨、工作日等。

## 这些特征在「向量模型与索引」这一环带来什么约束
多格式混合的数据源，要求索引环节支持跨格式文本解析与统一预处理，避免因格式差异导致向量化偏差。日常批量提交的运行台账与临时专项申报材料并存的更新节奏，要求索引支持增量更新与批量提交配置，适配高频更新场景。长文本案卷与申报书的存在，要求分块参数适配长段落拆分，避免单块文本过长超出模型处理上限。业务专属字段的存在，要求索引保留元数据字段，方便后续检索时按业务维度精准过滤结果。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `defaultToken` | 8192 | 适配水务案卷拆分后单块的token需求，覆盖多数单份申报材料的段落长度 |
| `maxToken` | 16384 | 满足多块拼接后的上下文长度，适配长案卷的检索推理需求 |
| 分块长度 | 800–1200 字符 | 适配水务申报材料的段落结构，避免单块过长或过短影响向量化效果 |
| 重叠长度 | 100–200 字符 | 保证分块间的上下文连贯性，覆盖案卷中跨段落的审批意见内容 |
| 相似度阈值 | 0.72–0.80 | 过滤低匹配度的非业务相关结果，精准匹配申报材料的核心关键字段 |
| 单次搜索上限 | 前 10 条 | 控制检索返回量，适配水务审核的多案卷并行检索场景 |

## 容易做错的三处
- 检索返回结果条数为0，原因是相似度阈值设置过高，过滤了所有匹配的水务申报材料文本。
- 索引任务频繁超时中断，原因是未调整`defaultToken`适配长案卷文本，导致单块解析后token超限触发超时。
- 检索结果混杂非水务业务内容，原因是未按业务专属字段过滤元数据，导致跨品类的无效召回。

## 怎么确认配好了
- 上传单份水务审批案卷PDF，执行索引后查看分块详情，确认分块长度符合预设的800–1200字符区间。
- 提交批量十万条级别的水务台账数据，检查索引任务的完成状态，无超时报错。
- 输入检索词“XX项目申报材料”，验证返回结果的相似度阈值符合预设的0.72–0.80区间，且仅包含水务业务相关内容。
- 查看向量存储的元数据字段，确认项目编号、申报单位等业务字段已被正确索引。
