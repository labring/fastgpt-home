# 城市水务的申报材料与案卷审核：多轮对话与提示词

本页面基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
城市水务的申报材料与案卷审核数据主要来自市政水务审批系统、管网运维档案库以及用户提交的涉水事项申请材料，包括排水许可、用水报装、管网改造等申请的纸质扫描件与结构化表单。数据按审批批次按月度归档更新，单份文档包含项目编号、申请人信息、管网点位坐标、用水量参数、审批节点记录等字段，单位涵盖立方米、毫米、平方米等水务专用计量与空间单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
水务申报材料的结构化字段多且带有专用单位，多轮对话需逐步确认缺失字段的合规性，提示词需明确指定单位校验规则。单批次案卷的关联数据量有限，需限制上下文召回的条数避免信息过载。文档混合扫描件与结构化文本，提示词需区分不同类型附件的解析逻辑。审批流程存在固定节点顺序，多轮对话需按节点逐步推进审核，避免跳过关键校验环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配水务申报材料中常见的表单段落与管网图纸说明长度 |
| 重叠长度 | 100–150 字符 | 保留跨块的审批节点关联信息，避免上下文断裂 |
| 最大上下文窗口 | 6000 token | 匹配单批次案卷的平均文本量，防止超出模型上下文限制 |
| `variables` | 按审批类型预设固定值 | 用于传入项目编号、管网所属区域等固定业务参数 |
| `messages` | 按审批节点顺序填充 | 用于存储多轮对话的审核交互记录 |
| 单次召回条数 | 前3条 | 匹配单份申报材料关联的案卷数量，避免冗余信息干扰 |

## 容易做错的三处
- 现象：配置的提示词未在对话中生效，返回内容偏离审核要求。原因：提示词未挂载到当前会话的`variables`参数中，或配置位置不符合系统规则。
- 现象：无法检索到历史会话的案卷关联记录，对话上下文丢失。原因：未正确传递`chatId`参数绑定会话与审批批次档案，导致会话数据无法持久化关联。
- 现象：上传的水务申报附件无法被正确解析，关键字段未被提取。原因：未在配置中开启多模态对话支持，或未在提示词中指定附件解析的字段提取规则。

## 怎么确认配好了
- 发起模拟申报对话，输入预设的项目编号，检查返回内容是否自动关联对应案卷的审批节点信息。
- 输入不同的审批节点问题，确认对话按预设流程逐步推进，无无关信息干扰。
- 上传一份测试用的水务申报PDF，检查系统是否正确提取表单中的用水量、点位坐标等专用字段。
- 查看会话参数列表，确认`variables`中已传入当前审批的固定业务参数，`chatId`参数已正确绑定会话。
