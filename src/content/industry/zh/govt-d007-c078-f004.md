# 城市水务的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
城市水务的申报材料与案卷审核数据主要来自水务业务管理系统的在线填报表单、线下提交的纸质扫描件，以及水质检测、排水许可等业务的归档数据。数据更新按申报批次触发，每完成一次申报提交即更新对应案卷。文档结构包含申报主体信息、项目地址、水质检测参数、审批节点记录等字段，其中水质参数字段带有mg/L等专业单位，案卷需关联唯一的归档编号与申报批次号，部分材料为非结构化的扫描件格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量 | 存储申报批次号、COD浓度阈值、归档编号 | 用于跨审核节点传递水务业务的核心参数，使用`variables`参数统一管理全局状态 |
| 节点ID关联 | 按审批顺序绑定`nodeId` | 确保案卷审核的流程与水务审批节点一一对应，固定节点执行顺序 |
| 工具调用输出 | 隐藏工具返回的原始日志 | 避免非必要的API调试信息混入正式审核案卷，符合水务案卷的正式输出要求 |
| 布尔判断触发 | 基于`variables`中的审核通过状态触发分支 | 用于判断申报材料的格式校验结果，支持开关式流程分支 |
| 多模态图片识别 | 开启图片识别并设置置信度阈值0.7-0.9 | 用于识别水质检测报告扫描件中的数值，适配水务材料的非结构化内容 |
| 超时设置 | 600秒超时时间 | 适配大体积水务扫描材料的解析时长，避免因解析超时导致工作流中断 |

## 容易做错的三处
- 工具调用模块的输出未隐藏，审核界面显示冗余的API调用日志 | 原因是未配置工具调用的输出隐藏规则，导致调试信息被保留在正式案卷中。
- MongoDB副本集主节点切换后，工作流无法读取新的申报数据 | 原因是未启用MongoDB Change Streams的自动重连配置，导致数据源连接中断后无法恢复。
- 多模态图片识别节点上传图片后无内容返回 | 原因是未开启节点的图片识别开关，或未配置对应多模态模型的权限，导致无法提取图片中的水务材料信息。

## 怎么确认配好了
- 提交一份标准水务申报测试材料，核对工作流节点是否按预设顺序执行，检查全局变量是否正确传递。
- 触发工具调用环节，确认输出仅保留审核结论，无额外的工具调试信息。
- 模拟MongoDB副本集主节点切换，验证工作流是否自动恢复数据源连接。
- 上传非结构化的水务材料图片，确认多模态识别节点可正常返回提取的数值信息。
