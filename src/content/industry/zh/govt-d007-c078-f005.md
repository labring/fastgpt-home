# 城市水务的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
城市水务的申报材料与案卷审核数据主要来自水务政务审批平台、供水企业业务档案库及管网运维案卷系统。数据随审批流程实时更新，单份申报材料多包含结构化申请字段与附件文档，案卷则包含审批节点流转记录、现场勘查照片、水质检测报告等。核心字段涵盖项目编号、申请主体、管网点位坐标、日均供水量、审批状态，单位涉及立方米、毫米、日等水务专业计量标准。

## 这些特征在「工具调用与插件」这一环带来什么约束
结构化字段与混合附件并存的特征，要求工具调用需同时支持结构化字段提取与多格式附件解析，避免遗漏关键审批信息。实时更新的数据源约束工具调用需配置实时同步的数据源接口，无法依赖静态缓存数据。水务专业计量字段的存在，要求工具调用的参数映射需匹配立方米、毫米等专用单位，避免字段解析偏差。多节点流转的案卷结构，要求工具调用需按审批节点触发，避免跨节点数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配申报材料与案卷审核中混合的结构化提取与附件解析任务 |
| `functionCall` | 启用 | 支持按审批节点触发的自定义工具调用逻辑 |
| 工具调用超时设置 | 600 秒 | 匹配水务审批流程中附件解析与数据校验的平均耗时 |
| 附件解析开关 | 开启所有支持格式 | 覆盖水质报告、管网图纸等常见审批附件类型 |
| 专业字段映射规则 | 按水务专业单位映射 | 匹配立方米、毫米等专用计量字段的解析标准 |
| 节点触发配置 | 按审批节点分组调用 | 避免跨节点流转的案卷数据混淆 |

## 容易做错的三处
- 现象：自定义代码调用水务审批数据源时返回AggregateError Code:ETIMEDOUT。原因：未设置适配水务数据拉取的超时参数，导致管网点位、水质数据的拉取耗时超出默认限制。
- 现象：添加MySQL数据库工具调用后对话返回400 status code (no body)。原因：未正确配置水务业务数据库的连接权限，或未指定审批台账的专用查询字段。
- 现象：配置问题分类工作流时，调用API返回的模型执行结果与预期不符。原因：未通过`toolChoice`指定模型的任务类型为申报材料分类，导致模型执行通用问答任务。

## 怎么确认配好了
- 发起单份申报材料的模拟提交请求，核对工具调用返回的字段是否覆盖水务审批所需的核心信息。
- 查看工具调用日志，确认触发的工具任务与当前审批环节匹配。
- 上传常见审批附件，验证工具调用可正确解析附件中的关键内容。
