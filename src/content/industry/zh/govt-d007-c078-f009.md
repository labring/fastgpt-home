# 城市水务的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
城市水务的申报材料与案卷数据主要来源于水务报装申请、水质检测委托、排水许可申报、管网巡检记录等业务场景。数据来源包括业务系统导出的结构化表单、纸质材料扫描件、现场拍摄的水质检测照片与管网踏勘影像。更新节奏随业务提交实时生效，归档后按季度批量整理。文档结构包含固定模板的申报书、资质证明文件、结构化检测报告，字段涵盖项目编号、用水地址、水质指标（如mg/L、MPa）、案卷编号、处置状态等，部分文档附带多格式附件。

## 这些特征在「模型接入与配置」这一环带来什么约束
多格式混合的数据要求模型同时支持结构化字段识别与非结构化内容解析，需针对性配置多模态能力。带特定单位的字段要求模型准确识别并关联单位信息，避免审核偏差。案卷与申报材料的长度跨度较大，从数十字的巡检记录到数十页的检测报告，需合理控制上下文长度避免信息截断。实时提交的业务数据要求模型调用链路具备低延迟特性，需配置合理的参数保障响应速度。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本的界面与参数逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配城市水务申报材料与案卷的平均长度，避免截断关键审核信息 |
| `maxTokens` | 2000–3000 token | 满足审核结果的输出长度需求，覆盖所有审核要点与反馈内容 |
| `vision` | 开启 | 适配申报材料中常附带的水质检测照片、现场踏勘照片等多模态附件 |
| `toolChoice` | auto | 支持模型自主判断是否调用文件读取工具处理上传的PDF案卷 |
| `temperature` | 0.2–0.4 | 保障审核结果的严谨性，降低生成内容的随机性 |
| `AIPROXY_API_ENDPOINT` | 填写对应模型的官方接入地址 | 确保模型调用链路的连通性与正确性 |
| `AIPROXY_API_TOKEN` | 填写与模型绑定的有效令牌 | 完成身份验证，保障模型调用的合法性 |

## 容易做错的三处
- 现象：调用VL模型时返回照片内容解析失败，界面显示不支持多模态输入的提示。原因：未开启`vision`参数，未配置多模态能力，导致无法处理申报材料中的照片附件。
- 现象：批量上传3MB的PDF案卷后触发调用失败，日志返回上下文超限的报错。原因：未将`maxContext`参数调整至适配长文档的区间，导致单批次调用超出模型上下文上限。
- 现象：模型未自动读取上传的申报PDF文件，仅返回文本提示。原因：错误将`toolChoice`参数设为none，限制了模型自主调用文件读取工具的能力。

## 怎么确认配好了
- 上传一张水务水质检测照片，触发模型调用，查看是否返回照片内容的识别结果，确认`vision`参数配置生效。
- 上传一份超过5页的PDF案卷，查看模型是否自动读取文件内容并进行审核，确认`toolChoice`参数配置生效。
- 提交一条包含水质指标的结构化申报数据，查看模型输出的审核结果是否准确识别字段与对应单位，确认参数配置符合业务需求。
- 检查平台的模型调用日志，确认返回的状态码为200，无身份验证相关报错，确认`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`配置正确。
