# 城市燃气的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
数据来源为城市燃气企业的报装申请系统、竣工验收案卷库及市政公用事业监管平台存档文件。更新节奏为申报材料随用户提交实时新增，案卷审核数据随审核节点更新。文档结构包含结构化字段与附件，结构化字段含申请单位名称、用气地址、用气规模、申请日期、审核状态，附件多为PDF格式的施工图纸、资质证明文件，单位包括立方米、日期型字段，部分附件单份内容较多。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据包含结构化字段与多页附件，多轮对话需明确核心查询字段，避免交互冗余。申报材料实时新增的特性要求提示词自动关联最新提交的案卷，避免调用过时数据。案卷审核的节点更新逻辑要求对话流程同步匹配审核状态，已通过的案卷无需重复询问资质材料。同时，附件格式多样，提示词需明确大模型先提取附件内的结构化信息，再结合用户对话生成审核结果，需限定上下文长度避免溢出。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配城市燃气申报材料与案卷审核的多轮对话需求：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 启用自动时序提取 | 适配多轮对话中用户逐步提供的申请信息，减少手动输入成本 |
| `chatId` | 绑定当前案卷ID | 确保多轮对话关联同一申报案卷，避免上下文混淆 |
| `messages` | 限制历史消息保留8条 | 控制上下文总长度，避免资源占用过高 |
| 最大上下文长度 | 8000–12000 字符 | 匹配单份案卷审核材料的总内容长度，避免截断有效信息 |
| 单次对话轮次上限 | 8轮 | 符合燃气申报审核的常规交互流程，避免过长对话导致上下文混乱 |
| 附件处理开关 | 启用PDF文本与图片解析 | 适配资质文件、施工图纸的文本提取与图片关联需求 |
| 关键词召回阈值 | 0.75–0.85 | 过滤低相关的历史申报数据，提升审核匹配精度 |

## 容易做错的三处
- 现象：对话无法展示知识库内的燃气资质文件图片，仅返回文本描述。原因：提示词未明确要求大模型识别并关联附件中的图片信息，未配置图片索引调用的相关规则。
- 现象：提取的关键词变量（如用气地址、申请日期）与用户实际输入的内容不符，出现字段错位。原因：未启用`variables`的时序提取配置，提示词未限定变量提取的优先级，导致混淆历史对话与当前查询的信息。
- 现象：多轮对话超过8轮后出现响应超时或返回空结果。原因：未设置合理的最大上下文长度或`messages`保留数量，超出系统承载上限导致有效上下文被截断，无法匹配对应案卷数据。

## 怎么确认配好了
- 发起包含用气地址、申请日期的多轮对话，核对提取的`variables`是否与输入内容一致。
- 上传一份燃气资质PDF附件，核对对话返回结果是否包含附件内的文本与图片关联信息。
- 发起超过8轮的审核查询对话，核对响应是否正常且未出现上下文截断提示。
- 检查`chatId`是否绑定当前案卷ID，确保多轮对话关联同一申报事项。
- 调整关键词召回阈值，核对返回的案卷数据匹配度是否符合业务需求。
