# 城市燃气的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
城市燃气的申报材料与案卷审核数据，来源为燃气经营企业内部报装系统、安检管理平台及政务共享的用气资质数据库。报装申请材料随用户提交实时更新，审核案卷在审批完成后归档留存。单份申报文档包含申请人身份信息、用气地址、设计用气规模（单位：立方米/日）、燃气设施图纸说明、经营资质证明等字段，案卷则包含审核节点、整改意见、批复结果及归档编号等结构化内容。

## 这些特征在「工具调用与插件」这一环带来什么约束
城市燃气申报材料与案卷审核的特征，对工具调用与插件环节带来多重约束。实时提交的报装材料要求工具调用响应延迟匹配用户提交节奏，避免过长等待。多字段的结构化数据，要求工具调用的函数参数需严格对应用气规模、资质编号等专属字段，避免单位或格式错误。归档案卷的多节点审核记录，要求插件需支持按审核节点筛选数据，同时需处理跨系统的数据源同步延迟问题。单份文档的内容长度差异较大，需适配不同长度的上下文输入。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配城市燃气申报材料的多类型工具调用需求，无需手动指定固定函数 |
| `functionCall` | `enabled` | 支持明确调用预设的燃气数据查询函数，满足案卷审核的结构化数据提取需求 |
| 最大上下文 | `8000–12000 token` | 单份燃气申报材料加案卷的总内容长度通常覆盖数千token，预留足够空间避免上下文溢出 |
| 单次工具调用上限 | `前3条` | 燃气审核通常仅需最新的3份相关案卷或报装记录，过多数据会增加上下文负担 |
| 工具调用超时时间 | `60 秒` | 内部燃气系统的数据查询通常在10-30秒内完成，预留缓冲时间应对峰值负载 |

## 容易做错的三处
- 现象：工具调用解析失败，返回Tool call Parser n报错。原因：推理模型返回的思考内容被think标签包装后放入content字段，不符合FastGPT的工具调用解析格式要求。
- 现象：工具调用返回的结果条数与预期不符，仅返回1条或超出预设上限。原因：未正确设置单次工具调用上限的配置项，或未限定查询的案卷时间范围。
- 现象：工具调用触发上下文溢出，导致请求中断或返回空结果。原因：最大上下文配置未覆盖单份申报材料与案卷的总内容长度。

## 怎么确认配好了
1. 需使用FastGPT v4.17.0及以上版本，发起模拟的燃气报装材料审核请求，检查工具调用是否自动匹配对应的数据查询函数，确认`toolChoice`配置生效。
2. 查看工具调用的返回结果，确认提取的字段（如用气规模、资质编号）格式与内部系统一致，验证`functionCall`的配置合理性。
3. 观察工具调用的响应时长，调整超时时间配置，确保在峰值负载下仍能完成数据查询。
4. 测试输入超长的案卷内容，确认上下文未被截断，验证最大上下文配置的适配性。
