# 城市燃气的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
城市燃气申报材料与案卷审核的数据，主要来自报装、过户、安检等业务的线下纸质材料与线上业务系统。数据更新节奏随单量实时生成，单份材料包含结构化表单（如报装地址、用气规模）、身份证明文件、燃气设施图纸、现场勘查记录等。文档结构不统一，部分为纯文本表单，部分为扫描件格式，字段包含带单位的量化信息，如用气规模以立方米、平方米为单位，审批节点以日期为单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
上述数据特征对模型接入配置带来多重约束：首先，数据包含非结构化扫描件与纯文本表单，需要模型支持多模态输入以解析图片内容；其次，单份案卷的文本长度差异较大，需配置足够的上下文窗口以覆盖完整审核材料；第三，字段包含带单位的量化信息，需模型准确识别单位与数值的对应关系，避免审核误差；最后，数据来源分散且格式不统一，需配置适配多格式文档的处理逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配单份燃气案卷的总文本（含OCR扫描结果）与历史审批记录的长度需求 |
| `maxTokens` | `2000–3000 token` | 控制单轮审核结果的输出长度，避免超出接口返回限制 |
| `quoteMaxToken` | `1500 字符` | 限制引用的案卷原文片段长度，确保模型聚焦关键审核节点 |
| `vision` | `开启` | 支持解析燃气设施图纸、纸质审批单的扫描件内容 |
| `temperature` | `0.2–0.4` | 降低输出随机性，保障审核结果的一致性与合规性 |
| `AIPROXY_API_ENDPOINT` | 按部署的代理服务实际地址填写 | 适配内网访问与接口权限要求 |
| `AIPROXY_API_TOKEN` | 按分配的接口密钥填写 | 确保接口调用的身份验证有效性 |

## 容易做错的三处
- 现象：切换向量模型后界面显示无进度，且无法切回原有模型。原因：未在FastGPT v4.17.0的配置中清除旧模型的缓存关联，导致代理服务仍绑定旧的模型资源。
- 现象：更新平台版本后，审核结果的输出长度明显变短，无法覆盖完整的案卷审核要求。原因：未同步更新`maxTokens`与`maxContext`的配置参数，新版本默认参数阈值被调整。
- 现象：配置完成后模型调用失败，返回接口认证报错。原因：未正确填写`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致身份验证不通过。

## 怎么确认配好了
- 上传一份标准的燃气报装申报材料，调用模型进行测试，检查是否能正确提取报装地址、用气规模等核心字段。
- 查看模型调用日志，确认`maxContext`、`maxTokens`等配置参数的实际取值与设置一致。
- 尝试切换已配置的模型，检查界面是否能正常加载并保存新的模型配置。
- 上传一份带燃气设施图纸的扫描件，检查模型是否能正确解析图片中的文字与图形信息。
