# 城投平台的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
城投平台的申报材料与案卷审核数据，主要来源于项目立项申报文件、土地出让审批案卷、城投债发行申报材料、公用事业运营备案案卷等。数据更新节奏随项目周期波动，项目集中申报期更新密集，日常为零星补充归档。文档包含结构化字段与非结构化文本，结构化字段含项目编号、投资金额、用地面积等，单位涉及万元、亩、平方米等；非结构化内容多为多页的审批说明、佐证材料，单份文档长度跨度较大。

## 这些特征在「向量模型与索引」这一环带来什么约束
城投平台的申报与案卷数据存在结构化与非结构化混合的特征，要求索引支持多类型数据的联合检索。单份文档长度跨度大，需适配长文本分块的灵活配置，避免关键审批信息被分割。更新节奏集中且存在批量归档历史数据，要求索引支持批量初始化与增量更新适配。制式化内容占比高，需调整向量模型的匹配规则以过滤无效模板匹配，保障检索精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配城投申报材料长段落的内容完整性，避免关键审批信息被分割 |
| 重叠长度 | 100–150 字符 | 减少分块后上下文断裂，保障案卷关联内容的检索连贯性 |
| 相似度阈值 | 0.72–0.85 | 过滤城投制式申报模板带来的无效高匹配结果，精准匹配核心审核需求 |
| 单次搜索上限 | 前10条 | 覆盖多份关联案卷的检索需求，避免召回过多冗余内容 |
| `maxToken` | 8000 token | 适配大段申报材料的上下文拼接，符合FastGPT v4.17.0 版本的通用大模型输入限制 |
| `defaultToken` | 按实测标定 | 不同批次申报材料的token分布差异较大，需根据实际导入数据调整基准值 |

## 容易做错的三处
- 现象：建立知识库时未选择ada 002向量模型时，界面弹出报错提示undefined model must match "^(text"。原因：平台默认向量模型校验规则未适配非ada系列的第三方模型，需手动补充模型配置路径。
- 现象：语义检索返回分数很高，但结果与实际申报审核需求不匹配。原因：未针对城投制式申报材料调整相似度阈值，模板化内容导致无效高匹配。
- 现象：搜索召回结果仅包含主申报材料，未包含关联辅助案卷。原因：未开启辅助数据的向量化索引开关，辅助文件未被纳入检索范围。

## 怎么确认配好了
- 上传一份典型的城投项目申报材料，检查分块预览界面的文本片段是否覆盖完整的审批节点说明。
- 触发一次案卷检索，查看返回结果的相似度分数分布，确认过滤后的结果符合审核核心需求。
- 导入一份辅助案卷文件，验证检索结果中是否包含该辅助文件的相关内容片段。
- 查看向量模型配置页面，确认所选模型的版本与导入数据的文本格式匹配。
