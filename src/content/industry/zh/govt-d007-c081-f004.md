# 基础化工的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
基础化工的申报材料与案卷审核数据主要来自企业内部环评报告、安全生产许可申报文档、质检案卷档案，更新节奏随项目申报周期批量更新，日常案卷归档按月更新。文档多为多页PDF格式，包含固定字段：项目名称、设计产能（单位吨/年）、环评批复文号、安全设施验收记录、检测报告编号，附件常附带带数值单位的检测数据表格。

## 这些特征在「工作流编排」这一环带来什么约束
多页PDF的结构要求工作流需配置分页解析节点，避免长文本截断导致字段提取错误；固定字段与单位的要求需预设校验规则，确保申报材料的产能、文号等信息格式合规；批量更新与归档的需求需设置批量处理节点，适配单次申报的多案卷场景；检测数据的单位差异需通过全局变量统一转换，避免审核误差。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |

| 全局变量设置 | `{"project_cap_unit": "吨/年", "archive_cycle": "当月"}` | 匹配基础化工申报材料的固定单位与归档周期 |
| 节点超时时间 | 600 秒 | 适配多页PDF解析与长文本校验的耗时需求 |
| 批量处理上限 | 前 20 条 | 匹配基础化工单次申报的常规案卷数量 |
| `nodeId` 绑定 | 按节点功能分类绑定 | 确保工作流节点的引用关系正确 |
| 字段校验规则 | 按环评申报模板预设必填字段 | 覆盖基础化工安许、环评申报的强制审核要求 |
| `variables` 调用 | 绑定到所有依赖字段的节点 | 实现单位统一与归档信息的跨节点复用 |

## 容易做错的三处
- 现象：打开工作流时弹出Cannot read properties of undefined (reading 'incl')报错，原因：未正确配置`variables`参数导致节点引用的依赖字段未初始化。
- 现象：全局变量更新后，后续工作流组件无法获取最新值，原因：仅在全局设置面板修改变量，未将变量绑定到对应节点的输入参数中。
- 现象：批量审核案卷时返回的结果条数与预期不符，原因：批量处理上限设置与基础化工单次申报的案卷数量不匹配，未结合项目常规规模调整参数。

## 怎么确认配好了
- 上传一份标准基础化工环评申报PDF，检查字段校验规则是否自动识别并标记缺失的必填字段
- 触发一次批量处理任务，查看工作流日志中`variables`参数是否正确加载预设的单位与周期值
- 手动修改全局变量后，触发后续审核节点，确认组件能获取到更新后的变量值
- 模拟长文本解析任务，检查节点超时时间设置是否未触发超时报错
