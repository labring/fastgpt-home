# 基础化工的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
基础化工的申报材料与案卷审核数据主要来自内部安评报告、环评申报书、安全生产案卷、原料质检档案与工艺参数文档。数据更新分为两类，项目申报阶段批量上传临时数据，日常归档案卷按月更新。单份文档长度差异大，短则数百字的审批意见，长则数万字的完整申报方案。文档固定字段包含项目编号、原料规格、工艺参数、审批文号，配套单位多为吨、立方米、MPa等工业标准单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
基础化工申报材料与案卷的文档长度跨度大，会导致单条召回内容的上下文权重差异明显，需调整分块与召回的匹配粒度。固定字段多且带有工业专用单位，会让通用检索模型容易出现单位匹配偏差，需强化字段级的精准召回。批量上传的临时数据与归档数据的更新节奏不同，需在检索时指定对应集合的范围，避免混入过期案卷数据。同时长文档的嵌套附件（如工艺流程图的文字说明）易被遗漏，需开启跨附件关联检索。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.72–0.80` | 匹配基础化工专业术语的精准度，避免过低引入无关案卷，过高遗漏合规申报材料 |
| `limit` | `前 8–12 条` | 平衡检索召回的覆盖范围与上下文长度，适配基础化工长文档的内容体量 |
| `searchMode` | `semantic + keyword` | 兼顾专业术语的语义匹配与固定字段（如项目编号）的关键词精准匹配 |
| `usingReRank` | `开启` | 修正基础化工文档中专业参数的排序偏差，提升高相关内容的展示优先级 |
| `datasetSearchUsingExtensionQuery` | `开启` | 自动扩展申报材料中的原料名称、工艺参数等术语，覆盖同义词与行业别称 |
| `collectionIds` | `按归档集合指定` | 区分临时申报数据与历史案卷，避免召回过期或非目标品类的文档 |

## 容易做错的三处
- 现象：调用API添加或删除集合数据时返回400状态码，提示参数格式错误。原因：未按照FastGPT要求的JSON结构传递文件路径与元数据字段。
- 现象：知识库检索首次发起无结果，第二次可返回对应内容。原因：首次检索时向量数据库尚未完成新上传数据的索引生成，需等待索引同步完成后再发起查询。
- 现象：传入HTTP响应数据作为引用后，检索结果未关联该内容。原因：未将响应数据转换为符合知识库要求的结构化文本，且未开启`datasetSearchUsingExtensionQuery`配置扩展字段关联。

## 怎么确认配好了
- 发起一次模拟申报材料的查询，核对返回结果的集合范围是否与指定的`collectionIds`一致。
- 调整`similarity`参数的取值，验证检索结果的相关度是否符合业务预期。
- 上传一份带工业参数的测试文档，确认`usingReRank`是否调整了高相关内容的排序位置。
- 调用API接口添加一条测试案卷数据，验证检索时能否正常召回该内容。
