# 基础电信运营的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
基础电信运营的申报材料与案卷审核数据主要来自业务支撑系统导出的政企客户申报表单、资质证明扫描件、业务案卷归档文件。数据更新随政企客户申报工单节奏，按批次批量提交，日常审核工单按日更新。文档多为固定格式的结构化表单与长文本业务方案结合，包含申报编号、客户主体信息、业务类型、资质文件清单、审核节点记录等字段，文件格式含PDF、Word及扫描件转的图片格式。

## 这些特征在「工作流编排」这一环带来什么约束
混合结构化与非结构化文档的结构，要求工作流需包含格式识别、OCR转写、结构化提取的串联节点，确保不同类型材料的统一解析。按工单批次更新的数据，要求工作流支持批量触发与并行审核节点，适配多工单同时处理的场景。包含审核节点记录的字段，要求工作流配置节点间的状态流转规则，关联`variables`中的审核状态变量，实现节点间的自动跳转。多格式文件的处理需求，要求工作流中配置文件解析节点的适配规则，避免因格式不兼容导致的解析失败。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写，以下配置项针对基础电信运营场景优化：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 基础电信的业务方案文档多为长文本，该区间可平衡解析精度与上下文容量 |
| 重叠长度 | 100–150 字符 | 避免长文本分块后关键审核信息被截断，保证分块间的上下文连贯性 |
| 变量配置 | `variables`绑定申报编号、审核状态等字段 | 匹配案卷审核的固定字段，实现不同节点间的数据流转与状态同步 |
| 节点触发规则 | 按`nodeId`绑定前置节点输出 | 确保审核节点仅在前序材料解析完成后触发，避免无效执行 |
| 单次触发工单数 | 5–10 条 | 适配基础电信日常审核的工单批量规模，避免系统负载过高 |
| 节点超时时间 | 600 秒 | 覆盖长文本解析、资质校验等操作的合理耗时需求 |

## 容易做错的三处
- 现象：工作流调用文件解析工具时返回调用失败的报错信息。原因：未配置基础电信申报材料的多格式适配规则，无法处理PDF、扫描件等非标准格式文件。
- 现象：发布的工作流访问链接显示为localhost域名。原因：部署时未配置系统对外访问的域名参数，默认使用本地部署的本地地址。
- 现象：长文档分块后关键审核字段丢失。原因：使用标题作为分隔符时，未适配基础电信案卷中嵌套的多级标题结构，导致分块边界错误。

## 怎么确认配好了
- 提交单条测试工单，查看工作流节点的执行日志，确认每个节点的输出与预设的`variables`变量匹配。
- 批量提交多条测试工单，验证并行节点的触发与执行状态，确认适配批次处理的配置生效。
- 上传不同格式的申报材料，检查解析节点的输出结果，确认格式适配规则正常工作。
- 发布工作流并使用外部设备访问链接，确认域名配置正确，无本地地址跳转问题。
