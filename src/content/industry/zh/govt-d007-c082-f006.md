# 基础电信运营的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
基础电信运营的申报材料与案卷审核数据，来源为内部业务系统，包括用户申报工单、资质文件上传库、计费审批流转档案。更新节奏按单次申报批次或每日同步。文档结构包含结构化表单字段（如申报单位统一社会信用代码、项目编号）、非结构化扫描件（如营业执照、组网方案PDF）、审批流转日志。字段包含唯一标识项、审批状态、流转节点，单位多为份、条、次。

## 这些特征在「引用来源与溯源」这一环带来什么约束
结构化表单的唯一标识字段要求溯源必须绑定精准的项目编号，避免混淆不同申报项目。非结构化扫描件需先完成OCR识别并关联结构化字段，才能实现完整溯源。高频更新的业务数据要求知识库同步周期不超过24小时，确保引用内容为最新审批状态。多环节的审批流转日志需要保留上下文关联，否则溯源无法体现完整审核流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 基础电信运营的申报材料包含长文本的组网方案与审批日志，该长度可保留完整上下文 |
| 重叠长度 | 150–200 字符 | 避免跨块的审批流转记录被拆分，确保溯源时能关联连续的审核环节 |
| `quoteMaxToken` | 2000–3000 token | 案卷审核需关联多段审批记录与资质文件，该区间可覆盖完整引用需求 |
| 单次召回条数 | 前6–8 条 | 基础电信的单次申报关联文档数量有限，该范围可避免冗余信息干扰 |
| `detail` | 开启 | 需展示溯源文档的具体字段与来源位置，满足案卷审核的溯源要求 |
| `responseData` | 开启 | 需返回溯源文档的唯一标识，支持外部系统关联原始案卷 |

## 容易做错的三处
- 现象：调用外部API发布的应用生成结果无引用来源字段。原因：未在FastGPT v4.17.0中配置知识库的外部调用权限，导致检索范围仅限本地私有库。
- 现象：调整`quoteMaxToken`至2000以上后，大模型未引用任何召回内容。原因：上下文总长度超出当前绑定模型的支持上限，导致引用片段被自动截断。
- 现象：溯源结果中缺少具体的审批流转记录。原因：分块长度设置过小，导致连续的审批日志被拆分后丢失关联关系。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理页面，查看分块长度、重叠长度的配置是否与预设值一致。
- 发起一条模拟申报审核查询，查看系统日志中是否包含`quoteMaxToken`的实际使用值与召回的文档片段。
- 调用外部API获取生成结果，确认`responseData`字段中包含溯源文档的唯一标识与来源位置。
- 测试调整`quoteMaxToken`的取值，观察生成结果中引用的片段数量是否随配置变化。
