# 基础电信运营的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
基础电信运营的申报材料与案卷审核数据，主要来源于入网审批档案、频谱申报文件、年度年检材料、营业厅业务工单。数据更新随项目立项、年检周期或业务变更触发，无固定统一更新频率。文档类型包含带固定字段的结构化表格、多页长文本申请说明、扫描件转换的PDF文件，字段涉及运营商代码、频段编号、业务许可编号、用户规模等，单位包含MHz、万户、自然年等。

## 这些特征在「文档解析与分块」这一环带来什么约束
结构化表格占比高的文档，会导致通用文本分块工具误将表格行拆分，丢失字段关联性。长文本申请说明包含通信行业专业术语，分块时需避免在术语中间截断。扫描件转换的PDF存在排版偏移、文字识别错位问题，需适配自定义PDF解析逻辑。单份案卷文件体积偏大，会拉长解析耗时，同时多字段关联的文档要求分块时保留上下文关联，避免破坏审批逻辑完整性。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配单份案卷中结构化表格与长文本混合的内容长度，避免拆分专业术语或字段关联 |
| `chunkSplitter` | 按段落+表格边界 | 针对混合文档结构，优先按自然段落拆分，遇到表格时自动整表作为一个分块单元 |
| `customPdfParse` | 开启 | 适配扫描件PDF的文字识别错位与排版偏移问题，优化解析准确率 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对单份大体积案卷的解析耗时，避免因超时导致解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 覆盖单份大型案卷的上传与解析需求 |
| `chunkSettingMode` | 手动配置 | 针对本品类文档的混合结构，可灵活调整分块规则与参数，适配不同类型的申报材料 |

## 容易做错的三处
- 现象：上传单份超过配置上限的案卷文件后，界面显示上传失败或解析超时。原因：未调整`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`参数，超出默认配置的阈值。
- 现象：上传结构化表格类申报材料后，解析结果中部分字段为空或数据缺失。原因：未开启`customPdfParse`，通用解析逻辑无法准确识别表格内的关联字段，导致数据丢失。
- 现象：解析长文本申请说明时，通信专业术语被拆分在两个分块中，导致后续检索语义断裂。原因：`chunkSize`取值过小，且未按段落+表格边界配置`chunkSplitter`。

## 怎么确认配好了
- 上传一份典型的结构化表格案卷，检查解析结果中是否保留了所有字段与表格完整性。
- 调整`chunkSize`参数后，上传一份长文本申请说明，确认专业术语未被中途拆分。
- 上传一份体积接近配置上限的文件，验证解析流程未触发超时报错。
- 开启`customPdfParse`后，上传扫描件转换的PDF案卷，对比识别文字与原文档的排版一致性。
