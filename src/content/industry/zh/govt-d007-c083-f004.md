# 基础设施建设的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
基础设施建设的申报材料与案卷审核数据，主要来源于项目立项、施工、验收全流程的纸质与电子档案，包括施工许可申请表、工程量清单、资质证明文件、进度报告等。数据更新随项目节点分批触发，立项阶段提交初始申报材料，施工阶段同步更新进度案卷，竣工阶段归档最终验收材料。文档以多页PDF、结构化Excel表格、扫描件为主，包含项目编号、施工单位资质等级、预算金额（单位：万元）、工期（单位：天）、材料批次编号等固定字段，部分扫描件需通过OCR识别转换为可检索文本。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的文档格式要求工作流预处理环节支持PDF解析、Excel结构化提取与OCR识别，避免因格式不兼容导致数据丢失。分批更新的项目数据要求工作流支持按节点触发，仅在对应环节提交材料时启动审核流程。固定字段与单位要求工作流的变量校验环节需匹配预设字段格式，防止因单位错误导致审核失败。多级审核的流转逻辑要求工作流配置分支节点，按初审、复核、终审的顺序实现权限隔离与流转控制。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量定义 | 按申报材料字段预设`variables` | 匹配结构化数据的字段格式，确保审核环节可正确读取参数 |
| 节点ID配置 | 为每个审核环节分配唯一`nodeId` | 实现分支流转的精准触发与日志追踪 |
| HTTP请求超时设置 | 600–900 秒 | 基建审核常涉及外部资质核验接口调用，耗时较长 |
| 循环嵌套配置 | 支持嵌套最多3次HTTP请求 | 基建申报材料的批次审核通常不超过3轮 |
| 分支触发规则 | 按审核结果字段触发 | 区分通过、补正、驳回的不同流转路径 |
| 知识库调用绑定 | 关联对应项目档案知识库 | 实现申报材料的自动合规性校验 |

## 容易做错的三处
- 调用API触发嵌套知识库助手的工作流后返回空值，原因是未在`variables`中正确绑定知识库调用的输入参数，导致参数未被传递至对应节点。
- 引用知识库变量时弹出`quote type error`报错，原因是传入的变量格式与知识库检索的要求不匹配，未按预设字段传递结构化数据。
- 工具调用节点同时输出AI回复与启动下一级分支，原因是未正确配置分支触发的依赖条件，导致多路径并行执行。

## 怎么确认配好了
- 提交单份测试申报材料，核对工作流是否按预设步骤流转至对应审核节点。
- 调用API触发配置完成的工作流，检查返回结果是否包含非空的审核结果字段。
- 触发知识库变量引用，确认无`quote type error`报错弹窗。
- 调整HTTP请求超时时间至设定阈值，验证超过时长后是否触发超时处理逻辑。
