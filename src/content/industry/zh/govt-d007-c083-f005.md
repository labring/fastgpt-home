# 基础设施建设的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
基础设施建设的申报材料与案卷审核数据，主要来源于项目立项、施工许可、竣工验收等环节的官方审批档案与项目执行文档，更新节奏随项目节点触发，立项后1个工作日内更新基础信息，竣工验收后归档为静态案卷。文档多为多页PDF或结构化表单，核心字段包含项目编号、建设地点、投资概算（单位：万元）、施工单位资质等级、环评报告编号等，部分案卷包含图纸扫描件与电子签章文件。

## 这些特征在「工具调用与插件」这一环带来什么约束
基建申报材料的字段多且包含资质校验类规则，工具调用需精准匹配专属字段模板，避免泛化提取导致的审核误差。项目数据随节点更新，要求插件支持实时拉取最新的审批状态与档案内容，无法依赖静态缓存。多页案卷与结构化表单混合的文档结构，需要插件支持批量解析与结构化字段提取，确保审核环节的信息完整性。跨团队的知识库关联需求，要求工具调用配置支持跨团队权限授权，解决应用与知识库非同一团队的访问限制问题。本场景的工具调用配置基于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配基建申报材料中多类型字段的自动匹配需求 |
| `functionCall` | 绑定预设的基建审核字段模板 | 确保提取的字段符合项目申报的标准格式 |
| 全局变量传递配置 | 开启并绑定工作流token变量 | 满足将工作流生成的访问令牌传递给MCP工具的需求 |
| 本机MCP调用权限 | 按实测标定 | 适配本地部署的基建数据校验工具调用 |
| 跨团队知识库授权 | 开启 | 解决应用与知识库非同一团队的查询权限问题 |
| 上下文保留时长 | 600–1200 秒 | 覆盖基建项目审核的多轮交互周期 |

## 容易做错的三处
- 调用FastGPT应用API时返回结果无上下文关联，现象是接口返回的回答仅包含单次查询内容，无历史交互上下文，原因是未配置上下文保留时长参数，未保留历史交互的会话信息。
- MCP工具无法获取工作流全局变量，现象是工具调用时token字段为空或返回401权限错误，原因是未开启全局变量传递配置，未将工作流生成的访问令牌绑定至工具调用参数。
- 跨团队知识库查询返回无相关内容，现象是接口返回“未找到匹配内容”，原因是未开启跨团队知识库授权，应用无法访问目标团队的档案知识库。

## 怎么确认配好了
- 发起一次包含历史上下文的测试调用，检查返回结果是否关联历史查询的项目编号与审批状态。
- 在工作流中配置MCP工具调用，传入预设的测试token，查看工具调用日志确认参数已正确传递。
- 关联跨团队知识库后，提交项目相关的测试查询，检查是否能返回匹配的档案内容。
- 查看应用配置面板，确认`toolChoice`与`functionCall`的配置参数已正确加载并生效。
