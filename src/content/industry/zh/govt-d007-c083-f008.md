# 基础设施建设的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
基础设施建设的申报材料与案卷审核数据主要来自项目立项、施工许可、竣工验收各环节的纸质扫描件与电子文档，更新节奏随项目推进阶段变化，立项阶段集中更新，施工及验收阶段按需补充。文档类型包含多页PDF可研报告、结构化CSV材料清单、带签章的扫描文件，字段包含项目编号、投资金额、施工周期、参建单位名称等，部分字段附带万元、天等专用单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
长PDF可研报告内容连贯且章节关联紧密，分块时需保证语义完整性，避免拆分跨章节的审批意见或投资明细。结构化CSV包含多列项目材料数据，需准确识别所有有效列，否则会丢失关键字段信息。带签章的扫描文件无法通过通用OCR直接完成精准解析，需调用自定义解析服务处理。项目申报材料随项目推进阶段更新，格式不统一，分块逻辑需适配多类型文档结构，同时需控制解析时长避免超时。

本文适配 FastGPT v4.17.0 版本。
## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配基建可研报告的章节长度，避免拆分跨章节的关键审批内容 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配基建文档的章节结构，保留内容的语义关联 |
| `customPdfParse` | 开启 | 处理带签章的扫描件PDF，提升解析准确率 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配单份大体积可研报告的上传需求，避免413报错 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 匹配长文档解析的实际耗时，避免自定义解析服务超时 |
| `chunkSettingMode` | 手动配置 | 针对基建文档的特殊格式，灵活调整分块参数 |

## 容易做错的三处
- 上传文件解析提示413错误。原因是未调整`UPLOAD_FILE_MAX_SIZE`参数，超出默认上传限额，docker部署下需同步修改容器挂载的配置文件。
- 导入CSV表格数据后仅显示前两列内容。原因是未正确配置分块逻辑对结构化文档的识别规则，默认分块逻辑未适配多列数据结构，仅提取前两列字段。
- 自定义解析服务调用后出现超时异常。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以完成长基建文档的解析流程。

## 怎么确认配好了
- 上传单份大体积基建PDF文件，检查是否触发413报错，确认`UPLOAD_FILE_MAX_SIZE`参数匹配文件体积需求。
- 上传结构化CSV材料清单，检查是否完整显示所有列数据，确认分块逻辑适配多列文档结构。
- 调用自定义解析服务处理带签章的扫描件，检查解析结果是否包含签章区域的文字内容，确认`customPdfParse`已开启。
- 等待解析完成，检查是否出现超时提示，确认`PARSE_FILE_TIMEOUT_SECONDS`参数匹配解析耗时。
