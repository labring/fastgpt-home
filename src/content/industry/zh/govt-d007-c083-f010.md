# 基础设施建设的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
基础设施建设的申报材料与案卷审核数据，主要来源于项目立项审批文件、招投标文件、施工进度档案、竣工验收报告及预算决算文档。数据更新节奏随项目阶段分批推进，立项阶段上传前期申报材料，施工阶段同步更新进度台账，竣工后归档完整案卷。文档包含结构化字段与非结构化内容，结构化字段含项目编号、施工单位、建筑面积（单位：平方米）、合同工期（单位：天）等，非结构化内容包含Word申报书、PDF审批文件及CAD图纸扫描件等图片格式材料。

## 这些特征在「知识库检索与召回」这一环带来什么约束
基础设施建设的申报材料与案卷审核数据特征，对检索召回环节形成多重约束。首先，混合了结构化字段与图片、长文档的非结构化内容，要求检索同时支持精确字段匹配与多格式内容解析；其次，专业术语密集且存在大量行业缩写，需要扩展查询以覆盖关联术语；最后，项目间数据需严格隔离，避免跨项目检索干扰审核结果。此外，分批更新的数据需要支持增量上传与批次隔离，防止新旧数据混淆。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 基础设施申报材料包含大量专业术语，该区间可过滤低相关结果，同时保留细分场景的有效匹配 |
| `limit` | `前8条` | 案卷审核需对比多份关联材料，8条结果可覆盖常见比对需求，避免过多结果增加审核负担 |
| `searchMode` | `混合检索` | 同时支持结构化字段匹配与非结构化文本检索，适配申报材料的混合数据结构 |
| `usingReRank` | `开启` | 基础设施专业术语多，重排可提升结果的相关性排序精度，优化专业内容的召回顺序 |
| `datasetSearchUsingExtensionQuery` | `开启` | 申报材料中存在大量工程缩写与专业术语，扩展查询可补充关联词汇，提升召回覆盖率 |
| `collectionIds` | `按项目批次绑定专属集合ID` | 不同建设项目的材料互不干扰，按批次隔离可避免跨项目检索干扰审核结果 |

## 容易做错的三处
- 现象：上传的CAD图纸扫描件无法被检索到相关内容，原因：未开启图片格式文件的OCR解析配置，仅索引了纯文本格式的申报材料。
- 现象：检索结果混入其他建设项目的案卷材料，原因：未通过`collectionIds`绑定专属数据集，导致跨项目数据被同时召回。
- 现象：检索返回的相关结果条数远少于预期，原因：`similarity`阈值设置过高，过滤了部分专业术语匹配的有效材料。

## 怎么确认配好了
- 上传一份包含CAD扫描件的测试申报材料，执行包含图纸关键词的检索，确认能召回该测试材料。
- 输入特定项目编号的检索词，确认仅返回对应项目的申报材料，无跨项目结果混入。
- 调整`similarity`阈值至标定区间，检查检索结果的相关度是否符合审核需求。
- 开启`usingReRank`后，对比重排前后的结果排序，确认专业术语相关的结果排名靠前。
