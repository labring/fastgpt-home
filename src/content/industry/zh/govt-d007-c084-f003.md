# 大宗商品贸易的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
该品类的申报材料与案卷数据主要来源于企业内部贸易系统、海关通关端口、第三方检验机构报告。数据随每笔贸易批次生成更新，单笔案卷包含贸易品类、申报数量、单价、通关编号、检验结论等固定字段，单位多为吨、桶、元/单位重量或体积，文档多为结构化表格与扫描件结合的格式，单笔案卷长度从数百字符到数千字符不等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
固定字段与特定单位要求提示词必须明确指定提取字段的标准单位，避免混淆吨与桶、元与美元的识别误差。扫描件与结构化文档结合的格式，要求多轮对话流程支持先识别图片中的关键信息，再结合结构化数据完成校验。单笔案卷长度差异大，需要动态调整上下文截取范围，防止超出对话窗口导致关键信息丢失。多笔贸易批次的关联查询，要求`variables`与`messages`参数能够保留历史会话中的申报主体、通关编号等上下文变量，确保跨轮次的信息关联准确。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 问题优化 | 开启 | 大宗商品申报材料关键词分散，优化后可提升关键信息召回精度 |
| 最大上下文 | 8000–12000 字符 | 适配单笔案卷从数百到数千字符的长度差异 |
| 单次搜索上限 | 前5条 | 避免过多冗余案卷信息干扰审核判断 |
| `variables` | 绑定历史会话中的通关编号、贸易品类 | 支撑多轮对话的上下文关联，确保跨轮次参数准确 |
| `messages` | 保留最近8轮对话内容 | 覆盖多轮审核流程中的历史提问与参数传递 |
| 图片展示开关 | 开启 | 适配申报材料中包含的扫描件、检验报告图片，满足可视化审核需求 |

## 容易做错的三处
- 现象：提取的贸易品类、数量字段单位错误，比如将原油的桶识别为吨。原因：提示词未明确指定对应品类的标准单位，未限定字段提取规则。
- 现象：知识库中上传的检验报告图片无法在对话结果中展示，仅返回文字描述。原因：未开启图片展示配置，提示词未明确要求识别并展示图片内容。
- 现象：跨轮次查询时，历史通关编号丢失，导致无法关联对应案卷。原因：未正确配置`variables`参数，未保留历史会话中的关键上下文变量。

- 上传包含检验报告图片的文档，发起提问，核对对话结果是否展示了图片内容，确认图片展示开关已开启。

- 测试多轮对话的上下文保留情况，发起多轮提问后，核对历史参数是否被正确调用，调整相关配置项的取值。
