# 大宗商品贸易的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
大宗商品贸易的申报材料与案卷数据主要来自企业内部贸易全流程单据，包括报关单、货权凭证、贸易合同、结算流水与通关回执。数据按单笔业务归档更新，单笔业务的案卷包含结构化字段与非结构化文本，结构化字段含货物品类、报关单号、提单号、结算金额，单位多为吨、立方米、元人民币，非结构化文本多为合同扫描件转写的长文档。

## 这些特征在「引用来源与溯源」这一环带来什么约束
大宗商品贸易的申报与案卷数据包含大量长文本贸易合同、结构化通关单据与唯一标识字段，这为引用溯源带来多重约束。长文本合同会占用较多token，需严格控制单次召回的内容总量；报关单号、提单号等唯一标识字段是溯源的核心锚点，需在召回时优先关联对应字段以绑定具体业务案卷，避免跨业务数据混淆；部分单据为扫描件转写的文本，存在格式错乱，需在召回后校验文本完整性，确保溯源内容准确对应原始单据。

## 配置怎么定
本页内容基于FastGPT v4.17.0版本的配置逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 6000–10000 token | 大宗商品贸易的案卷包含长文本合同与多份通关单据，该参数限制单次召回的总token量，避免超出大模型上下文承载上限 |
| 单次召回条数 | 前6条 | 单份业务案卷关联的单据数量通常在3-8份之间，限制召回条数可避免上下文过载 |
| `responseData` | 保留报关单号、提单号、货物品类字段 | 大宗商品贸易的溯源核心标识为报关单号与提单号，需强制保留以绑定具体业务 |
| `detail` | 开启完整内容展示 | 案卷审核需核对原始单据的完整信息，开启后可返回完整的溯源文本与结构化字段 |
| 最大上下文 | 不超过15000 token | 结合单次召回条数与单条内容长度，该参数控制总上下文长度，适配大模型的输入限制 |

## 容易做错的三处
- 现象：工作流中调用知识库模块后，返回结果无关联的溯源字段。原因：未在`responseData`配置中指定需要保留的业务核心字段，导致溯源信息被过滤。
- 现象：单次检索耗时过长，或触发上下文溢出报错。原因：将`quoteMaxToken`设置为50000 token，超出大模型与平台的上下文承载上限，导致处理超时或内容截断。
- 现象：召回结果与目标业务案卷不匹配，出现跨业务的单据内容。原因：未在检索配置中绑定报关单号、提单号等唯一标识字段，导致召回结果混淆不同业务的案卷数据。

## 怎么确认配好了
- 触发一次案卷审核的检索请求，查看返回结果中是否包含报关单号、提单号等预设的溯源字段。
- 查看检索结果的总token量，确认未超出`quoteMaxToken`的设置值。
- 针对单份业务案卷发起多次检索，确认召回结果均来自该业务的关联单据，无跨业务内容。
- 检查工作流中知识库模块的输出，确认溯源内容已正确绑定到当前业务的上下文。
