# 大宗商品贸易的申报材料与案卷审核：模型接入与配置

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
大宗商品贸易的申报材料与案卷数据主要来自贸易合同、报关单、货权凭证、结算单据等业务文件，随单笔贸易流程生成更新，无固定批量更新周期。文档包含结构化多列表格、扫描件PDF及结构化表单，字段涵盖货物品名、规格、数量、单价、产地、报关单号、提单号等，单位涉及吨、立方米、美元、人民币等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多列结构化文档要求配置时需适配多字段拆分，避免自动分段打乱列对应关系；扫描件类案卷需开启视觉识别能力以提取文本；单笔业务单据字段多、信息密度高，要求上下文窗口适配长文本；敏感信息如报关单号、货权信息需额外配置过滤规则；自定义渠道接入时需匹配不同单据的格式校验逻辑，确保参数适配业务数据量。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多字段、长文本的贸易单据上下文需求 |
| `maxTokens` | 2000–3000 token | 控制单条审核结果的输出长度，避免超出接口限制 |
| `quoteMaxToken` | 1500–2000 token | 保留足够的案卷原文片段用于审核依据匹配 |
| `vision` | 开启 | 支持扫描件格式的报关单、货权凭证等案卷的文本提取 |
| `temperature` | 0.1–0.3 | 降低随机度，确保审核结果的一致性与合规性 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的代理地址填写 | 适配自定义渠道的接口调用路径 |
| `AIPROXY_API_TOKEN` | 按分配的密钥填写 | 完成自定义渠道的身份校验 |

## 容易做错的三处
- 调用自定义渠道后返回报错400，提示上下文长度超限。原因是未针对大宗商品长单据调整`maxContext`参数，导致传入的案卷文本超出接口限制。
- 多列Excel文件自动分段混乱，每行对应字段被拆分到不同块中。原因是未适配多列结构化文档的拆分规则，使用默认自动分段逻辑导致列对应关系丢失。
- 敏感词过滤失效，合规类贸易信息被误识别或未过滤。原因是未针对大宗商品贸易的专属敏感词（如报关单号、货权信息）配置专属过滤规则，仅使用通用敏感词库。

## 怎么确认配好了
- 上传单份多列Excel贸易单据，查看分段结果是否保留每行的完整字段组合，无跨行列拆分。
- 上传扫描件格式的报关单，确认模型可提取其中的报关单号、货物品名等关键信息。
- 调用自定义渠道接口，查看返回结果的token数量是否在配置的`maxTokens`范围内，无截断情况。
- 配置敏感词过滤规则后，输入包含敏感信息的测试文本，确认过滤结果符合预期。
