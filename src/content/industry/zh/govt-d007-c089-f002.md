# 工程机械的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
工程机械申报材料与案卷审核的数据来源包括项目立项申报文件、设备出厂合格证、阶段性维保案卷、技术参数表与审批流转单。数据按项目批次阶段性提交，单次项目周期内更新次数有限，文档类型混合PDF文本、Excel结构化参数表与设备实拍图片。核心字段包含设备型号、序列号、额定载重、作业时长、审批节点等，配套使用吨、小时、MPa等专有工程单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
混合的文档类型要求索引系统同时支持非结构化文本分块与结构化表格解析，避免遗漏参数表中的关键数据。单案卷文档长度可达数千字符，分块策略需要适配向量模型的输入长度限制，防止关键审批节点被截断。带专有单位的字段需要保留元数据，确保检索时可精准匹配设备型号、额定载重等特定内容。阶段性提交的数据更新节奏，无需设置高频实时索引，可按项目周期调整刷新频率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配工程机械申报材料的单段文本长度，避免超出向量模型输入上限 |
| 重叠长度 | 100–150 字符 | 保留分块间的上下文关联，避免关键审批节点被截断 |
| `maxToken` | 30000 token | 适配单案卷的总内容量，确保大语言模型可获取完整审核依据 |
| `defaultToken` | 10000 token | 设置基础召回上下文额度，平衡检索精度与资源消耗 |
| 相似度阈值 | 0.75–0.85 | 匹配案卷审核的精准检索需求，过滤低相关冗余材料 |
| 单次搜索上限 | 前6条 | 控制检索调用的资源消耗，避免流量过载 |
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 容易做错的三处
- 现象为检索结果显示匹配到相关案卷，但大语言模型返回未找到相关内容。原因是未开启向量模型归一化配置，导致向量相似度计算偏差，匹配的文档未被正确纳入上下文。
- 现象为单次检索调用耗时过长，或触发资源限流报错。原因是未设置合理的`maxToken`与单次搜索上限，导致单次调用传入过多文档内容，超出系统资源限制。
- 现象为分块后的文本丢失关键单位信息，导致检索匹配错误。原因是分块时未保留字段元数据，将带单位的参数直接截断，无法被精准匹配。

## 怎么确认配好了
- 进入向量模型配置界面，确认归一化选项已开启，匹配FastGPT v4.17.0的新增功能要求。
- 上传单份典型工程机械申报案卷，查看分块预览结果，确认文本未被过度截断且保留关键字段信息。
- 发起一次检索请求，核对返回的上下文总token数是否符合`maxToken`的设置范围。
- 模拟批量检索场景，观察系统响应状态，确认未出现超时或限流报错。
