# 工程机械的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
工程机械申报材料与案卷审核的数据主要来源于出厂检测报告、设备运维档案、资质申报文档三类。数据来源为装备制造企业的生产系统、设备运维平台及政务申报端口。更新节奏按设备批次与运维周期划分，单台设备的基础档案随出厂完成更新，运维档案按月同步更新。文档结构包含结构化字段与附件两类，结构化字段包括设备编号、型号、额定载荷、工作时长等，单位涵盖台、小时、兆帕（MPa）等，附件多为PDF格式的检测报告与合格证扫描件。

## 这些特征在「工作流编排」这一环带来什么约束
工程机械申报与案卷的结构化字段与附件混合的结构，要求工作流需先完成附件解析节点，再匹配对应结构化字段进行校验。设备编号、额定载荷等字段的单位特异性，要求工作流需配置字段格式校验节点，避免因单位不匹配导致审核失败。按批次与周期的更新节奏，要求工作流需支持按设备批次触发、按月同步更新档案的配置。多节点串行的审核逻辑，要求工作流中`variables`的传递需绑定正确的`nodeId`，确保前序节点的输出能被后续节点正确读取。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按设备批次更新触发 | 匹配工程机械档案按批次更新的节奏，避免重复执行审核流程 |
| 全局变量配置 | 绑定`variables`中的设备编号、额定载荷字段 | 覆盖审核所需的核心结构化数据，确保各节点可读取对应参数 |
| 节点依赖绑定 | 绑定前序节点的`nodeId`与所有输出分支 | 确保http请求节点在所有问题分类分支中都被触发，覆盖全部审核场景 |
| http请求节点超时 | 3–5 秒 | 匹配该模块的实际耗时，避免不必要的超时中断 |
| 问题分类节点超时 | 2–4 秒 | 匹配该模块的实际耗时，确保分类逻辑快速完成 |
| 错误重试配置 | 最多重试2次，间隔10 秒 | 应对临时网络波动导致的节点失败，不影响整体审核效率 |

## 容易做错的三处
- 现象：执行工作流时返回「获取全局变量失败」的报错，或节点内字段为空。原因：未在`variables`中配置工程机械的设备编号、额定载荷等必填字段，导致节点调用时无法读取对应参数。
- 现象：修改工作流逻辑后，发布到正式渠道的审核流程未更新。原因：未将更新后的工作流版本重新发布至对应发布渠道，渠道仍调用旧版本逻辑。
- 现象：问题分类节点执行完成后，http请求节点未触发。原因：未正确配置节点依赖关系，未将http请求节点绑定到问题分类的所有输出分支，仅触发了部分分支的流程。

## 怎么确认配好了
- 手动触发测试工作流，传入预设的工程机械设备编号与检测报告附件，检查`variables`中的字段是否被正确传递到每个节点。
- 查看工作流运行日志，确认各节点的耗时符合预设的超时设置，未出现超时报错。
- 修改工作流的节点配置后，重新发布到测试渠道，执行测试用例验证新逻辑正常生效。
- 模拟http请求节点失败的场景，确认错误重试机制按配置触发，流程未直接中断。
