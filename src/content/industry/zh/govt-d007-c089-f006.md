# 工程机械的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
工程机械的申报材料与案卷审核数据主要来自企业设备管理系统、出厂合格证数据库、政府特种设备监管平台。数据更新节奏随业务节点调整：出厂资质数据随设备投产同步生成，日常维保记录按月更新，年度年检报告按自然年刷新。单份文档多为结构化字段加附件形式，包含设备编号、型号、额定起重量（单位吨）、出厂日期、维保单位、年检有效期等字段，部分案卷材料包含多页扫描件与签章信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
工程机械申报材料的结构化字段与附件并存的特征，要求引用溯源时需区分元数据与扫描件文本，避免检索结果混淆不同类型的来源。不同数据的更新节奏差异，要求溯源时需关联数据生成时间与业务节点，过滤过期的年检或维保记录。设备编号作为唯一标识字段，要求溯源逻辑绑定该字段与对应申报案卷，确保单台设备的审核材料不会与其他设备混淆。多页签章扫描件的存在，要求保留附件的存储路径与签章校验信息，作为溯源的核心依据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 工程机械申报材料的字段多为专业术语，需过滤低相关的非设备类检索结果，避免误引用无关案卷。 |
| 单次搜索上限 | 前8条 | 单台设备的申报材料通常不超过7份，保留2条冗余量确保覆盖完整审核依据。 |
| 重排 | 开启 | 混合检索结构化字段与附件文本后，重排可优先匹配核心审核字段，提升溯源准确性。 |
| 最大上下文 | 1200–1500 字符 | 单份申报材料的核心文本通常在1000字符左右，预留冗余避免截断关键签章或参数信息。 |
| `quoteMaxToken` | 800 token | FastGPT v4.17.0 中该参数控制引用片段的总token数，适配工程机械申报材料的平均长度，避免溢出。 |

## 容易做错的三处
- 现象：开启重排功能后检索结果为空，引用来源字段显示为空。原因：重排的相关度过滤阈值设置过高，过滤了所有匹配的结构化字段与附件文本，导致无有效检索片段。
- 现象：调用审核请求时返回超时提示，界面显示504状态码。原因：未调整`quoteMaxToken`参数，引用片段总长度超过系统处理上限，导致请求超时。
- 现象：引用的案卷材料与当前申报的设备型号不匹配。原因：未绑定设备编号作为检索过滤条件，导致跨设备的申报材料被误引用。

## 怎么确认配好了
- 提交单台特定设备的申报审核请求，查看返回结果中的引用来源字段，确认仅包含该设备的相关材料。
- 开启重排功能后，检查检索结果的排序是否优先匹配设备型号、额定起重量等核心审核字段。
- 查看系统日志中`quoteMaxToken`的实际调用值，确认未超过预设的最大上下文限制。
- 查看返回结果中的`responseData`字段，确认引用来源的存储路径与签章信息已完整返回。
- 检查`detail`字段中是否包含设备编号的绑定信息，确保溯源逻辑正确关联。
