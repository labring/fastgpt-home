# 成品油销售的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
数据来源包括加油站每日进销存报表、月度合规案卷、上级主管部门的核验模板；更新节奏为每日申报数据实时更新，月度案卷数据归档后稳定留存；文档多为结构化表单与半结构化案卷，包含加油站编号、油品标号、销量、库存余量、核验节点等字段，单位涉及升、吨、元、日期。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日增量的申报数据要求索引支持低延迟增量构建，避免全量重索引带来的耗时增长；半结构化的表单与案卷混合数据，需要配置适配多格式的向量化拆分规则，确保不同类型文档的语义提取一致；多字段的结构化数据，需明确向量化的核心字段，避免无关信息稀释向量语义，影响审核匹配精度；归档案卷的历史版本留存，要求索引保留版本关联字段，支持按时间范围检索历史案卷。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 成品油申报材料多为短文本段落，该区间可避免分块过碎丢失语义或过长导致`maxToken`超限 |
| 重叠长度 | 100–200 字符 | 衔接相邻分块的语义关联，避免跨块的审核信息断裂 |
| 相似度阈值 | 0.72–0.80 | 按实测标定，区分有效核验信息与无关文本，适配案卷审核的精准匹配需求 |
| 单次搜索上限 | 前 10 条 | 申报材料与案卷的关联条目较少，过多结果会增加审核人员的筛选负担 |
| `maxToken` | 8192 token | 适配FastGPT v4.17.0的主流嵌入模型上下文长度限制，避免截断关键审核信息 |
| `defaultToken` | 4096 token | 适配轻量审核场景的上下文需求，平衡检索精度与响应速度 |

## 容易做错的三处
- 重复提交相同的审核查询时，系统响应耗时未出现明显下降。未配置查询缓存机制，导致每次请求都触发全量向量检索，浪费计算资源。
- 调用知识库接口时，仅使用集合添加数据功能后无法触发索引构建。未通过创建训练订单触发批量索引构建，仅单条添加数据不会自动启动索引任务。
- 向量化图片案卷后检索时未返回关联结果。未配置图片向量化与对应申报文本的元数据绑定，仅单独向量化图片未建立关联索引。

## 怎么确认配好了
- 提交10条重复的审核查询，观察响应耗时变化，确认缓存机制是否按配置生效。
- 上传单条申报数据后，查看索引构建状态，确认训练订单是否正常触发并完成索引。
- 上传带图片的案卷材料，执行检索后查看返回结果，确认是否同时关联展示文本与图片内容。
- 切换嵌入模型选项，确认目标模型可正常加载并完成向量化任务，避免模型选择受限。
