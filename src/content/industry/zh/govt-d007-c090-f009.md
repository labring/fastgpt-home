# 成品油销售的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
成品油销售的申报材料与案卷审核数据主要来源于加油站进销存系统、零售台账、税务申报表单及现场执法案卷归档系统。数据更新按月度、季度申报周期固定触发，单份申报材料包含结构化表单与非结构化附件两类内容。结构化字段包含加油站编号、油品标号、实际销量、申报销售额、应缴税额等，单位对应升、元；非结构化附件多为发票扫描件、现场检查笔录、整改通知书等，单份附件长度可达数千字符。

## 这些特征在「模型接入与配置」这一环带来什么约束
固定周期更新的数据适合配置增量索引逻辑，减少全量同步的资源消耗。结构化字段存在明确枚举值（如油品标号仅支持92#、95#、98#），要求模型输出严格匹配预设规则，避免自定义偏差。长文本附件与多字段关联校验的需求，要求模型能保留足够上下文关联信息，同时控制单条输出的token总量。多模态附件的处理需求，要求配置支持视觉解析的模型能力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 成品油申报材料通常包含多份进销存明细与案卷附件，需保留足够上下文关联校验逻辑 |
| `maxTokens` | 2000–3000 token | 单条审核结果需输出校验项、异常提示与整改建议，避免截断关键信息 |
| `temperature` | 0.1–0.3 | 审核需严格匹配申报规则与数据一致性，不宜过度随机 |
| `toolChoice` | auto | 需根据输入自动选择结构化字段校验或非结构化文本解析工具 |
| `AIPROXY_API_ENDPOINT` | 业务专属代理地址 | 隔离通用大模型调用与成品油审核业务流量，保障敏感数据安全 |
| `AIPROXY_API_TOKEN` | 按代理平台生成的专属令牌 | 验证调用权限，防止未授权访问业务数据 |

## 容易做错的三处
-  界面提示「无效的令牌」，调用模型时返回401状态码。原因是`AIPROXY_API_TOKEN`配置时混入了多余的换行或空格，导致令牌校验不通过。
-  长案卷附件的审核结果被截断，仅显示前半部分内容。原因是`maxTokens`取值低于输出所需的token总量，未适配长文本审核的输出需求。
-  模型误将92#油品识别为95#，校验结果出现偏差。原因是`temperature`取值过高，导致模型生成不符合预设枚举规则的输出。

## 怎么确认配好了
-  提交单条标准成品油申报案卷，检查模型输出的校验项是否覆盖所有必填字段。
-  查看FastGPT v4.17.0的模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置参数与实际调用地址、令牌一致。
-  调整`temperature`至0.2左右，提交多条含枚举字段的测试数据，确认模型输出的油品标号与输入的枚举值一致。
-  上传单份长度约5000字符的检查笔录附件，确认模型输出未出现截断。
