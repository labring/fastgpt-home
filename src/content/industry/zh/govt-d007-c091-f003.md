# 房建工程总承包的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
房建工程总承包的申报材料与案卷数据，来源为施工单位提交的立项批复、施工图设计文件、预算书、资质证明、施工许可申请等官方报审文件，以及各审批环节生成的内部案卷。数据随项目审批进度同步更新，覆盖从立项到竣工验收的全流程。文档结构包含结构化表单与非结构化PDF混合形式，核心字段包括项目唯一编号、施工单位资质等级、预算金额、审批节点状态，涉及的单位有平方米、万元、日历天等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据包含结构化表单与非结构化PDF的混合形式，多轮对话需明确区分结构化字段查询与非结构化内容审核的交互逻辑，避免混淆检索范围。因数据随项目审批进度动态更新，多轮会话需锚定当前审批节点的上下文，防止检索过期的历史材料。核心字段的专属单位要求提示词需明确校验规则，防止出现单位转换错误。案卷材料单份篇幅较长，需限制上下文长度以适配大模型的处理窗口。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 房建单份报审文档常达数千字符，多轮对话需保留3-5个审批节点的历史交互内容 |
| 问题优化 | 开启，按审批节点递进优化 | 申报审核的多轮交互伴随节点迭代，优化后可精准匹配当前环节的案卷内容 |
| 单次搜索上限 | 前6–10 条 | 案卷材料按审批节点分类存储，单次检索无需过多冗余结果 |
| `variables` | 绑定项目编号、施工单位资质等级变量 | 房建报审材料的核心字段需动态代入提示词，确保审核精准 |
| `messages` 历史截断阈值 | 保留最近4 轮交互 | 多轮审核中早期非当前节点的上下文易干扰当前判断，截断后提升检索效率 |
| `chatId` 会话绑定 | 绑定项目唯一标识 | 确保同项目的多轮交互上下文不混淆，符合报审案卷的归档要求 |

## 容易做错的三处
- 现象：多轮对话中知识库检索结果为空，但单独在知识库中测试同一关键词可召回对应内容。原因：多轮会话中`messages`携带了过期的项目上下文，导致检索时过滤了当前节点的有效文档。
- 现象：返回报错404 Invalid URL (POST /api/chat/completions)。原因：未正确绑定`chatId`导致会话路由异常，或接口调用时未携带必填的会话标识参数。
- 现象：工作流执行至大模型处理后中断，后续流程无法继续。原因：提示词中设置了输出字数限制，但未通过`variables`传递截断校验规则，导致大模型输出超出限制后工作流触发异常终止。

## 怎么确认配好了
- 发起单轮测试，输入特定项目的申报材料关键词，核对检索结果包含该项目的专属字段内容。
- 发起多轮交互，依次提交不同审批节点的问题，核对会话上下文未混入过期的历史项目数据。
- 触发报错场景，验证`chatId`绑定后接口调用无404错误。
- 配置提示词限制输出字数后，核对工作流可正常完成后续归档步骤。
