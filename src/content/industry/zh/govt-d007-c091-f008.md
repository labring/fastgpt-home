# 房建工程总承包的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
房建工程总承包的申报材料与案卷数据，主要来自项目立项审批、招投标、施工许可、现场签证、竣工验收等环节，更新节奏随单个项目周期推进，从立项到竣工归档可能持续数月至数年。文档结构包含固定格式的报审表、多页施工图、预算书、资质证明文件、现场签证单等，部分案卷包含扫描版图纸与可编辑文档混合的内容。字段包含项目编号、建筑面积（单位㎡）、工程造价（单位万元）、施工单位资质等级、签证日期等，各字段有明确的建筑行业标准格式。

## 这些特征在「文档解析与分块」这一环带来什么约束
首先，文档包含混合格式的内容，扫描版图纸与可编辑文档共存，要求解析环节支持自定义适配不同格式的内容提取逻辑；其次，单份案卷可能包含数十至上百页的内容，分块长度需要平衡上下文完整性与检索效率，过长会导致检索冗余，过短会破坏工程参数与单位的关联；第三，字段带有特定行业单位（㎡、万元），分块时需避免将参数与对应单位拆分至不同片段；最后，不同环节的文档格式差异较大，需针对报审表、图纸、预算书分别适配分块规则。

## 配置怎么定
在FastGPT v4.17.0版本中，以下配置项均可在知识库管理界面的文档解析模块中完成设置：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 房建项目文档包含大量带单位的工程参数，该长度可保留单份签证或预算的完整逻辑，避免参数与单位拆分 |
| `chunkSplitter` | 按段落+页眉页脚分割 | 房建文档有固定页眉标注项目名称与编号，按段落分割可保留单份报审文件的完整上下文 |
| `customPdfParse` | 开启 | 部分竣工图纸为扫描件，自定义解析可优化图片转文字的精度，适配工程图纸的标注内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型项目案卷可能超过50页，默认超时阈值不足以完成完整解析 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 单个项目的归档案卷可能包含多份大型图纸PDF，需放宽上传上限以支持完整案卷上传 |

## 容易做错的三处
- 上传文件后解析节点无响应，界面显示超时状态。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，大型案卷解析耗时超过默认阈值。
- 部分扫描版图纸PDF无法识别标注文字。原因是未开启`customPdfParse`配置，默认解析逻辑无法适配扫描版工程图纸的内容提取。
- 分块结果中出现“建筑面积”与“㎡”分离的片段。原因是`chunkSize`设置过小，将工程参数与对应单位拆分至不同分块中。

## 怎么确认配好了
- 上传单份50页的竣工图纸PDF，查看解析状态是否在10分钟内完成，无超时报错。
- 上传包含扫描件的案卷PDF，检查解析结果中是否包含图纸标注的尺寸、材质等文字内容。
- 随机抽取10条分块结果，确认每条分块内包含完整的工程参数与对应单位，无拆分断裂的情况。
- 上传超过500 MB的归档案卷，确认上传与解析流程无阻断，无文件大小限制报错。
