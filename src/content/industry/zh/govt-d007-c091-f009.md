# 房建工程总承包的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
房建工程总承包的申报材料与案卷审核数据，主要来源于施工报审表、施工图设计文件、企业资质证明、分部分项验收记录等。数据按项目报审节点更新，单项目周期内累计文档量随施工进度递增。文档格式混合PDF、Word、Excel，结构包含项目编号、施工标段、报审批次、材料明细、验收日期等字段，单位涉及平方米、立方米、万元等工程类标准单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
房建工程总承包申报材料与案卷审核的数据特征，对模型接入配置带来多项约束。混合格式的工程文档要求模型支持多模态解析，对视觉识别能力有明确需求。多字段、带工程专属单位的内容，需要模型在上下文处理中保留足够的字段关联信息，避免解析偏差。按报审节点更新的数据，要求知识库同步节奏匹配施工周期，模型调用频率需与数据更新频率对齐。案卷审核需对比历史报审案卷，召回关联历史文档的需求会限制上下文长度的设置空间。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本的界面与参数规则制定：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| vision | 开启 | 房建工程总承包的申报材料包含大量施工图、报审表扫描件，需识别图片内的工程参数与文字内容 |
| `maxContext` | 8000–12000 token | 需保留多份历史案卷与当前报审材料的上下文，避免字段关联丢失 |
| `quoteMaxToken` | 2000–3000 token | 案卷审核需召回足够的历史报审文档，确保关联信息完整 |
| `temperature` | 0.1–0.3 | 工程审核需严格匹配字段与规范，降低随机性输出 |
| `AIPROXY_API_ENDPOINT` | 按官方指定地址填写 | 确保模型调用链路稳定，适配工程数据的解析需求 |
| `AIPROXY_API_TOKEN` | 按授权获取的密钥填写 | 完成合法的模型调用鉴权 |

## 容易做错的三处
- 现象：模型调用返回工程字段解析错误，如标段编号识别为乱码或单位匹配错误。原因：未开启`vision`配置，无法准确识别扫描版报审材料中的印刷文字与工程参数。
- 现象：渠道链接访问时返回“undefined”is not valid json报错。原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致模型接口调用链路异常。
- 现象：审核结果未匹配最新报审材料。原因：未按项目报审节点调整知识库同步与模型调用频率，导致调用的仍是旧版本知识库数据。

## 怎么确认配好了
- 上传单份扫描版施工图，触发模型解析，确认能提取其中的工程尺寸、标段信息等内容。
- 配置完成后，生成一条测试审核流程，核对模型调用链路无异常报错。
- 对比历史报审案卷与当前材料，确认模型能召回关联的历史文档并完成关联校验。
- 调整`temperature`参数后，核对输出结果的一致性，确认随机性控制符合审核需求。
