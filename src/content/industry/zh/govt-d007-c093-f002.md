# 政企信息化服务的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
数据主要来源于政务申报系统导出的电子文档、线下扫描归档的案卷卷宗，更新按单次申报批次或月度归档节奏进行。文档多为多段落长文本，包含固定结构化字段如申报主体统一社会信用代码、项目编号、审批节点记录，同时混有表格、扫描件附件，字段多为字符型、日期型或数值型单位。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「向量模型与索引」这一环带来什么约束
长文本占比高，要求分块策略适配单块内容的合理长度，避免语义断裂影响检索精度；结构化字段与非结构化文本混合存在，需同时支持结构化元数据索引与非结构化内容向量索引的联动；存在扫描件类附件，需启用多模态解析与对应向量索引能力；按单次申报批次或月度归档的更新节奏，需适配增量索引的触发时机，避免全量索引重复消耗计算资源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配申报材料长文本的语义完整性，避免单块内容过于零散 |
| 重叠长度 | 100–150 字符 | 弥补长文本分块后的语义断层，提升跨块检索的连贯性 |
| `maxToken` | 4096 token | 适配主流向量模型的输入长度限制，避免编码失败 |
| 相似度阈值 | 0.72–0.85 | 过滤低相关的案卷与申报材料检索结果，符合政务审核的严谨性要求 |
| 重排 | 启用前3条结果重排 | 提升高相关内容的排序优先级，适配案卷审核的精准检索需求 |
| `defaultToken` | 按实测标定 | 适配本地部署的向量模型调用配额，避免超出资源上限 |

## 容易做错的三处
- 现象为本地部署FastGPT后，新建知识库上传文档时无图片索引模型选项。原因是未开启多模态解析的功能开关，或部署包未集成对应多模态依赖组件。
- 现象为Embedding模型调用OneAPI时返回报错，且Chat模型运行正常。原因是OneAPI的向量模型接口配置未对齐FastGPT要求的输入格式，或配额限制触发限流。
- 现象为索引生成后检索结果条数远低于预期。原因是分块长度设置过大，导致部分长文本未被正确拆分，或相似度阈值设置过高，过滤了有效匹配结果。

## 怎么确认配好了
- 进入知识库设置页面，核对分块长度、重叠长度的配置与当前品类的文档特征匹配。
- 上传一份包含扫描件的测试案卷，检查解析结果中是否包含图片文本内容。
- 调用向量模型测试接口，验证输入文本的编码结果无报错，且返回的向量维度符合配置要求。
- 模拟一次申报批次的增量索引任务，确认索引更新仅针对新增数据，未触发全量重索引。
