# 政企信息化服务的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
政企信息化服务的申报材料与案卷审核数据，主要来源于国央企、政府的政务申报系统与案卷管理平台。数据更新节奏按政务事项申报批次或案卷办结周期执行，无固定日更频率。单份文档包含结构化字段与附件两部分：结构化字段含申报主体统一社会信用代码、事项类型、提交时间、审核状态等枚举类字段；附件多为图片、PDF、扫描件等格式，单份附件体积通常不超过1000 MB。

## 这些特征在「工具调用与插件」这一环带来什么约束
这些数据特征对工具调用与插件环节带来三点约束。首先，结构化字段与混合附件的组合，要求工具调用需同时支持文本参数校验与文件流解析，无法仅依赖通用的文本接口。其次，按批次更新的数据特征，要求工具调用支持批量触发与批量结果汇总，适配政务审核的批量处理需求。最后，附件格式多样且体积差异大，要求插件需兼容多种文件解析逻辑，同时配置合理的体积上限与数量限制。枚举类字段的存在，要求工具调用需内置参数合法性校验，避免无效的接口调用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 自动选择 | 适配申报材料审核中多类型任务的自动调度，无需手动指定工具，降低配置复杂度 |
| 单次工具调用超时 | 120–180 秒 | 匹配案卷审核的平均处理时长，避免因附件解析耗时过长导致调用失败 |
| 附件处理最大体积 | 1000 MB | 覆盖申报材料中常见的大体积附件需求，避免因体积超限被拦截 |
| 单次工具调用附件数量上限 | 前5 条 | 匹配单批次申报材料的平均附件数，避免单次调用加载过多资源 |
| 环境变量调用权限 | 开启 | 支持读取部署时配置的第三方服务密钥、系统参数等敏感信息 |
| `functionCall` 参数校验 | 开启 | 校验申报材料字段的枚举值合法性，避免向第三方接口传递无效参数 |

## 容易做错的三处
- 现象：调用返回图片流的工具时，工作流输出的结果字段为空。原因：未配置文件流的接收与解析逻辑，仅处理了文本类型的接口响应。
- 现象：接入第三方API并完成应用测试后，API调用返回空响应。原因：未在工作流中正确引用部署时配置的环境变量，导致第三方服务密钥未被加载。
- 现象：包含特定大模型的流程在应用配置测试时正常，但通过API调用时报错。原因：API调用时未携带正确的身份验证参数，或工作流的触发模式与API调用的参数格式不匹配。

## 怎么确认配好了
- 在应用配置的工具调试面板中，上传单份申报材料附件，验证工具是否能正确解析文件流并返回结构化的审核结果。
- 在工作流中插入环境变量调用节点，输入预设的第三方服务密钥变量名，验证是否能正确读取部署时配置的参数值。
- 触发批量申报材料审核的工作流，检查工具调用的日志是否显示正确的参数校验结果与附件解析进度。
