# 政企信息化服务的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来源于政务服务申报端口、内部审批管理系统及归档案卷库。数据随单次申报批次或审核流程更新，无固定周期，单次提交的文档包含结构化申报表单与非结构化附件。结构化字段包含申报主体统一社会信用代码、项目编号、申报金额、提交时间等，附件多为PDF格式的资质证明、承诺书等，单份文档长度差异较大，从数百字符到数十页不等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类混合结构化表单与非结构化附件的数据结构，要求模型同时支持结构化字段提取与非结构化文本解析，需明确配置`maxContext`等参数适配不同长度的文档。数据更新无固定周期且批次差异显著，需适配动态接入的文档源，避免使用静态缓存策略。单份文档长度跨度大，需限制单次处理的最大上下文范围，防止模型调用超时。不同字段存在专属单位与格式要求，需在配置中明确提取规则，降低格式解析偏差。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单份申报材料与案卷的混合文本长度，避免超出模型上下文承载上限 |
| `maxTokens` | 2000–3000 token | 限制单次审核结果的输出长度，确保案卷审核结论清晰完整 |
| `quoteMaxToken` | 1500 token | 限定引用原始材料的字符范围，防止冗余内容干扰审核判断 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具辅助提取结构化字段，适配混合文档场景 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保审核字段提取与格式的一致性，符合政务文档的严谨要求 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 对接本地或云端部署的大模型服务，确保数据传输路径合规 |

## 容易做错的三处
- 现象：模型调用返回空结果或返回500状态码，原因：未在`.env.local`文件中正确配置本地模型的接入参数，导致平台无法识别部署的模型服务。
- 现象：批量案卷审核时出现超时错误，原因：未调整`maxContext`参数适配单份文档长度，导致单请求负载超出模型承载上限。
- 现象：提取的申报字段内容无必要分隔符导致解析失败，原因：未将`temperature`参数设置为较低区间，模型生成的文本未保留合理的语法分隔格式。

## 怎么确认配好了
- 执行本地模型连通性测试，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，测试返回结果符合预期。
- 上传单份典型申报材料，核对模型输出的字段提取结果与原始文档内容一致，调整参数直至格式匹配。
- 发起批量测试任务，观察批量处理的成功率与耗时，调整`maxContext`与`maxTokens`参数适配并发需求。
- 查看系统日志，确认无模型调用超时或参数解析错误的记录，验证配置的稳定性。
