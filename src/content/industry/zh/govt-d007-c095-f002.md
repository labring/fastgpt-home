# 新能源开发的申报材料与案卷审核：向量模型与索引
本文适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
数据主要来自新能源开发项目的申报材料与归档案卷，包括立项申请、环评报告、并网审批文件、现场勘查记录等。更新节奏随项目审批流程推进，单个项目从前期申报到竣工归档的周期跨度较大。文档多为结构化表单与长文本附件结合，字段包含项目编号、装机容量（单位MW）、审批文号、提交日期等，附件多为PDF或Word格式的技术说明材料。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化表单的字段格式固定，需针对数值型字段（如装机容量MW）适配向量编码逻辑，避免单位干扰语义一致性。长文本附件篇幅较长，需合理设置分块规则以保留技术细节。项目审批周期跨度大，数据更新存在阶段性，索引需支持增量同步，无需全量重建。多格式附件的文本提取结果存在格式差异，需统一预处理流程后再进入向量建模环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配新能源技术说明的长文本细节，避免单块信息过载或语义断裂 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，避免技术参数被分块截断 |
| `maxToken` | 4096 token | 适配主流向量模型的输入长度限制，匹配新能源文档的分块文本长度 |
| `defaultToken` | 512 token | 作为分块文本的最小保留单位，避免关键技术信息被截断 |
| 单次搜索上限 | 前 10 条 | 覆盖案卷审核中常见的关联材料数量，避免冗余结果干扰审核 |
| 最大上下文 | 8000 字符 | 整合检索到的相关分块，为审核提供完整的技术参考依据 |

## 容易做错的三处
- 向量化接口调用耗时较长，未达到预期的批处理性能。原因：仅提交单条文本切片进行向量化，未启用批量提交配置，未利用向量化服务的批处理能力。
- 检索结果中无法查看分块的原始文档位置与页码信息。原因：未开启索引元数据的存储开关，导致分块索引信息未被记录。
- 接入指定多模态向量模型后，向量化结果出现格式异常。原因：未针对模型配置正确的输入参数，未匹配模型要求的文本处理逻辑。

## 怎么确认配好了
- 上传一份新能源项目的环评报告附件，查看系统生成的分块结果，确认分块长度与重叠比例符合配置要求。
- 执行一次案卷检索，检查返回结果中是否包含分块的元数据信息，确认索引配置生效。
- 调用向量模型接口提交测试文本，验证返回的向量数据格式与配置的模型要求一致。
- 提交多条文本切片，确认向量化服务的调用流程符合预期的批量处理逻辑。
