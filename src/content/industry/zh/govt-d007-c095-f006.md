# 新能源开发的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
新能源开发的申报材料与案卷数据主要来自项目立项、环评、并网验收等环节的官方备案文件与内部审批档案，更新节奏随项目推进分批同步。文档多为多页PDF或结构化Word文档，包含项目编号、备案文号、装机容量、用地范围等固定字段，单位涵盖千瓦、公顷、万元等，单份文档长度跨度较大，不同项目的案卷页数差异明显。

## 这些特征在「引用来源与溯源」这一环带来什么约束
新能源开发申报材料与案卷的长文档、固定字段属性，要求引用溯源环节需精准匹配官方备案字段，避免泛化引用导致的溯源失效。分批更新的属性要求定期同步最新归档数据，防止引用过期审批文件。单份文档长度跨度大的特点，要求限制单条引用的token占用，避免上下文溢出影响回答准确性。官方备案的属性要求溯源信息需包含明确的归档文号与时间，满足合规性要求。

## 配置怎么定
本配置指南适用于 FastGPT v4.17.0。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 新能源申报案卷的核心引用内容通常包含备案文号、装机容量等信息，该区间可覆盖核心信息且避免上下文溢出 |
| `responseData` | 仅返回核心归档与审批信息 | 过滤非必要的搜索过程数据，简化溯源展示 |
| 单次搜索上限 | 前5条 | 新能源项目的关联备案材料通常集中在5个以内的条目，过多条目会稀释核心信息 |
| 重排 | 开启 | 长文档分块内容需按相关性排序，确保优先召回与申报需求直接相关的备案内容 |
| `detail` | 完整 | 溯源需展示完整的归档信息，包括项目编号与归档时间，满足合规性要求 |
| 最大上下文 | 4000–5000 token | 适配多页案卷的分块整合需求，避免截断核心审批流程信息 |

## 容易做错的三处
- 现象：查看聊天回答的知识库引用时出现报错，或回答中显示与申报需求无关的知识库内容。原因：未正确配置`quoteMaxToken`参数，导致引用内容超出上下文阈值触发报错，或未设置合理的单次搜索上限过滤非核心条目。
- 现象：使用工作流工具调用后，回答中仍显示知识库搜索的input和response引用字段。原因：未在工作流节点中关闭引用展示开关，或未正确配置`responseData`参数过滤非必要输出。
- 现象：召回的引用内容与申报的具体项目不匹配，出现其他区域的新能源项目档案。原因：未开启重排配置，或单次搜索上限设置过高，引入非核心的关联材料。

## 怎么确认配好了
- 上传一份典型的新能源项目申报案卷，发起包含备案文号或项目装机容量查询的提问，核对回答中展示的引用信息是否包含正确的归档字段与时间。
- 查看聊天界面的引用弹窗，确认无报错提示，且仅展示与提问直接相关的案卷内容。
- 切换工作流调用模式，发起提问后检查回答中未出现知识库搜索的input和response字段。
- 调整`quoteMaxToken`参数至不同区间，观察引用内容的长度变化，确认参数生效。
