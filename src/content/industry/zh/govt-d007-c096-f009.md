# 有色金属冶炼的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
本品类的申报材料与案卷数据来源包括生产执行系统MES台账、第三方质检机构出具的检测单、生态环境部门申报表单、安监执法案卷。数据随每批次冶炼产出同步更新，单次申报材料的更新周期不超过7天。文档分为结构化表单与非结构化附件两类：结构化字段包含冶炼批次编号、炉号、目标金属含量数值、单位能耗、排放物浓度数值；非结构化附件包含PDF格式质检报告、监控截图、审批流转记录。

## 这些特征在「模型接入与配置」这一环带来什么约束
有色金属冶炼的申报材料与案卷含带特定单位的结构化数值、多类型非结构化附件，且更新周期短，对模型接入配置带来多重约束。需适配PDF、截图等多格式附件的解析需求，保障模型可准确识别质检报告与监控素材。需绑定数值与对应单位的关联逻辑，避免解析时出现单位混淆。因数据更新频率高，需配置适配短周期上下文的参数，保障最新批次数据的有效调用。案卷审核需比对历史批次数据，需预留足够的上下文引用空间，避免关键历史信息被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 容纳单批次申报材料的结构化字段与关联附件的摘要，避免上下文溢出 |
| `quoteMaxToken` | `3000–5000 token` | 案卷审核需比对最多5份历史批次的案卷内容，预留足够引用空间 |
| `vision` | 开启 | 解析PDF格式的质检报告与监控截图类附件 |
| `temperature` | `0.1–0.3` | 申报材料审核需严格匹配标准格式，降低随机生成内容的概率 |
| `AIPROXY_API_ENDPOINT` | 填写企业私有部署的代理地址 | 保障数据不流出企业内网，符合国央企数据安全要求 |
| `AIPROXY_API_TOKEN` | 使用企业统一分配的鉴权密钥 | 实现细粒度的访问权限管控 |

## 容易做错的三处
- 解析PDF质检报告时出现乱码，原因：未开启`vision`配置或未配置对应模型的视觉解析能力。

## 怎么确认配好了
- 上传一份标准的冶炼批次申报PDF，检查解析结果中是否正确提取了目标金属含量数值与对应单位。
- 提交一份历史案卷比对请求，检查返回结果中是否包含符合要求的历史批次引用内容。
- 测试上传DOC格式的质检附件，确认解析后的文本内容无乱码且字段完整。
- 触发一次完整的案卷审核流程，检查模型输出是否未包含冗余的思考过程展示。
