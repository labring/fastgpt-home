# 核电运营的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
核电运营的申报材料与案卷包括核反应堆运行参数申报单、安全评审案卷、核燃料循环备案文件、应急响应档案等，数据来源为核电场站的运营管理系统、安全监管平台。更新节奏分为定期批量更新（合规性申报批次）与实时触发更新（异常工况下的临时案卷补充）。文档结构包含结构化元数据字段（如机组编号、申报日期、案卷编号、安全等级）与非结构化长文本正文，单位涉及兆瓦、吨、运行小时等专业计量值。

## 这些特征在「向量模型与索引」这一环带来什么约束
核电申报材料与案卷的结构化元数据与长文本并存，要求索引环节同时支持向量嵌入与元数据过滤，避免专业术语匹配偏差。更新节奏的双重性要求索引支持增量更新与全量重索引的切换，适配定期批量与实时变更的需求。文档长度差异较大，短则数页长则数十页，分块策略需兼顾长文本的语义完整性与短文本的处理效率。专业计量字段的存在，要求元数据与向量嵌入绑定，确保检索时可按机组编号、安全等级等维度精准筛选。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配核电案卷的单页文本量，避免块丢失且保留上下文完整性 |
| 重叠长度 | 100–200 字符 | 确保长文本块之间的语义衔接，避免关键信息被分割 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 匹配核电专业术语的精准度要求，过滤无关检索结果 |
| 单次召回上限 | 前 8 条 | 适配案卷审核的多关联文档检索需求，控制上下文拼接长度 |
| maxToken | 8000 | 适配长案卷的上下文拼接，符合FastGPT v4.17.0的参数范围 |
| defaultToken | 1024 | 控制单轮嵌入的token消耗，平衡嵌入精度与资源占用 |

## 容易做错的三处
- 知识库上传后状态持续显示索引中，超过预设处理时长。原因是分块长度设置过大，超出系统默认的分块处理阈值，导致分块任务堆积。
- 分块长度设置为3000字符时，部分文档片段无法在知识库中检索到。原因是长文本分块时未适配核电案卷的段落换行格式，导致关键片段被错误分割或遗漏。
- 向量模型调用返回空结果或报错。原因是未正确配置向量模型的调用路径，错误绑定了非适配的代理服务，导致模型请求无法正常送达。

## 怎么确认配好了
- 上传一份标准核电申报案卷，查看分块预览界面，确认所有文本片段均被正确分割且无缺失。
- 发起一次包含核电专业术语的检索请求，核对返回结果的相似度符合预设阈值范围。
- 查看向量模型调用日志，确认`defaultToken`与`maxToken`参数的取值与配置一致。
- 上传一份新增的临时案卷，等待索引完成后发起检索，确认新文档可被正常召回。
