# 核电运营的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
核电运营的申报材料与案卷审核数据主要来自核电运营单位的安全申报系统与归档案卷库，更新节奏随单次申报任务提交实时更新，归档案卷每季度批量同步至知识库。文档以结构化组合为主，包含申报编号、核电机组编号、申报事项类别、审核进度、附件文件路径、审核意见等字段，字段分别对应字符串、阿拉伯数字、分类标签、状态枚举、文件路径、文本格式，无额外非结构化冗余内容。本内容基于FastGPT v4.17.0版本编写。

## 这些特征在「引用来源与溯源」这一环带来什么约束
核电运营申报材料的结构化字段特征，要求引用溯源需绑定唯一申报编号作为溯源标识，避免不同批次申报的内容混淆。按申报批次的更新节奏，要求知识库同步仅增量拉取新提交的申报文件，避免重复索引旧数据。多格式附件的存在，要求溯源环节支持从PDF、Word等附件中提取结构化字段与正文内容。审核进度与状态字段的分类属性，要求引用结果需同步展示对应审核环节的状态，确保溯源信息完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配核电申报材料的单段正文与结构化段落长度，避免信息拆分混乱 |
| `quoteMaxToken` | 1500–2000 token | 容纳单份核心申报案卷的引用内容，确保溯源信息完整 |
| 单次召回上限 | 前 6–10 条 | 匹配单批次核电申报材料的索引文件规模，控制上下文开销 |
| `detail` | 开启 | 展示完整的申报编号与核电机组编号字段，强化溯源精准性 |
| `responseData` | 开启结构化字段返回 | 提取申报编号、审核状态等专属字段，匹配核电数据的结构化特征 |
| 重排 | 按实测标定 | 优化核电专业术语的召回排序，提升引用匹配精度 |

## 容易做错的三处
- 现象：界面显示引用了知识库内容，但生成的答案未匹配核电申报材料的专业内容。原因：未开启`responseData`的结构化字段匹配，仅使用通用文本召回，无法关联核电专属字段。
- 现象：上传的PDF格式核电案卷未被召回引用。原因：未配置分块长度适配长文档，或未开启`detail`的附件文本提取，导致结构化字段未被完整索引。
- 现象：导入的HTTP请求响应数据未被作为有效引用源。原因：未将响应数据转换为FastGPT支持的结构化格式，或未配置`responseData`开启响应内容的索引。

## 怎么确认配好了
- 上传单份核电申报案卷至知识库，检查分块后的文本是否保留申报编号与核电机组编号字段。
- 发起针对某核电申报事项的提问，查看返回结果中是否展示`detail`字段对应的溯源信息。
- 调用工作流API传入测试问题，确认返回结果中包含指定知识库的引用标记与对应申报字段。
- 检查知识库同步日志，确认仅新提交的核电申报文件被增量索引，无重复同步记录。
