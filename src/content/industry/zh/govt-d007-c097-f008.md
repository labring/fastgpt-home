# 核电运营的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
核电运营的申报材料与案卷审核数据主要来自核安全监管要求的正式申报文件、日常运行台账、检修记录与安全评估案卷。数据更新节奏分为两类：日常专项申报按季度或项目节点更新，归档案卷则在项目完结后一次性入库。文档类型包含固定格式的多列Excel申报表、带内嵌公式与水印的PDF技术报告，以及长文本格式的安全分析文档。字段包含设备编号、辐射剂量、运行参数等，单位多为毫西弗、兆帕、摄氏度等核电专业计量单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
多列Excel申报表的结构化格式会触发默认解析逻辑的适配限制，仅识别前两列数据，导致核心字段丢失；长文本技术报告的专业内容关联性强，分块过短会破坏技术逻辑的完整性，过长则会导致检索上下文冗余。核电文档的专业计量单位与固定字段需要完整保留，分块时不能随意拆分单位与关联参数。大型案卷PDF的单文件体积较大，解析耗时较长，默认超时设置易导致任务中断，日常申报材料的高频更新也对解析效率提出了要求。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `chunkSize` | 800–1200 字符 | 核电申报材料包含长文本技术章节与多列表格，该区间可保留单段专业内容的完整性，避免上下文断裂 |
| `chunkSplitter` | 按语义分块 | 核电文档包含大量专业术语与固定格式的技术参数，按语义分块可保留内容逻辑连贯性 |
| `customPdfParse` | 启用MinerU API | 核电PDF文档多含内嵌公式、多列表格与水印，MinerU API可提升结构化解析准确率 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型核电案卷PDF体积较大，解析耗时较长，该时长可避免中途超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 部分核电归档案卷单文件体积可达数百兆，调整该上限可支持完整上传 |
| `chunkSettingMode` | 手动配置 | 针对不同类型的申报材料（如申报表、技术报告），手动配置可灵活适配分块规则 |

## 容易做错的三处
- 上传多列Excel申报台账后，知识库仅识别前两列数据。原因：未调整解析配置适配多列格式，默认逻辑仅识别标准两列表格，导致核心字段丢失。
- 启用PDF解析后未返回预期的表格内容，且任务状态显示超时。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，大型核电案卷PDF解析耗时超出默认阈值，任务被强制中断。
- 条件判断组件接收HTTP解析出的设备状态boolean参数后返回空值。原因：文档解析环节未保留原始数据类型，分块时将boolean转换为字符串导致格式丢失，无法被条件判断组件正常识别。

## 怎么确认配好了
- 上传单份多列Excel申报台账，检查知识库解析结果是否包含全部预设列，确认解析完整性。
- 上传单份大型核电案卷PDF，查看解析任务状态是否在`PARSE_FILE_TIMEOUT_SECONDS`设定的时长内完成，无超时报错。
- 测试分块后的检索效果，输入专业术语或具体设备参数，确认检索结果与输入内容匹配度符合预期。
- 检查`customPdfParse`配置项是否启用，确认PDF解析日志中显示MinerU API调用记录。
