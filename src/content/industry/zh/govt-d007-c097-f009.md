# 核电运营的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
数据主要来自核电运营的日常运行台账、设备检修案卷、辐射监测报告及合规申报文档，来源覆盖机组全生命周期的运维环节。更新节奏随申报周期而定，常规月度申报每日增量归档，专项案卷按项目完成节点更新。文档均遵循核安全监管的固定模板，包含统一编号、设备型号、运行参数、整改闭环记录等字段，部分监测类文档附带带单位的量化数据，格式多为结构化表格与长文本结合。本内容基于FastGPT v4.17.0编写。

## 这些特征在「模型接入与配置」这一环带来什么约束
核电运营的申报材料与案卷存在固定监管模板，结构化字段与长文本运维记录混合，且包含带单位的量化监测数据，要求模型同时支持结构化信息抽取与长上下文理解。数据随申报周期增量更新，需适配高频同步的数据源接入逻辑，避免因数据源滞后导致审核结果偏差。统一的编号规则与合规字段要求，需模型精准匹配预设字段，减少非预期的字段偏移。部分文档篇幅较长，需限制模型处理的上下文边界，避免超出承载上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配核电申报文档的长文本长度，避免截断核心合规字段 |
| `maxTokens` | 3000–4000 token | 控制单轮审核输出的长度，匹配案卷审核的结构化结果输出需求 |
| `quoteMaxToken` | 1500–2000 token | 限定引用源文档的最大长度，确保审核依据的精准性 |
| `toolChoice` | auto | 支持自动触发工具调用，适配结构化字段抽取与量化数据校验 |
| `temperature` | 0.1–0.3 | 降低随机性，确保合规审核的结果一致性，避免非预期的字段偏差 |
| `AIPROXY_API_TOKEN` | 按内网权限生成专属令牌 | 适配核电内网的安全隔离要求，避免公网数据泄露 |

## 容易做错的三处
- 现象：批量上传申报案卷后，仅前十几条完成审核，后续条目无结果或返回上下文溢出报错。原因：未适配核电文档的长文本长度，`maxContext`取值过小导致上下文承载不足。
- 现象：模型调用函数抽取合规字段时，结果偏差率较高，出现字段匹配错误。原因：`temperature`取值过高，导致模型输出随机性过大，不符合核电审核的严谨性要求。
- 现象：无法直接处理jpg格式的案卷扫描件，无图像解析结果。原因：未开启`vision`配置项，且未配置图像转文本的前置处理流程。

## 怎么确认配好了
- 上传单份标准核电申报文档，核对模型输出的字段是否与文档内的预设字段一一匹配。
- 批量上传多份同类型案卷，检查所有条目均完成审核且无异常报错。
- 调整`temperature`参数后，对比两次审核结果的一致性，确认符合业务严谨性要求。
- 接入内网部署的模型服务，验证`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`配置正确，无访问权限报错。
