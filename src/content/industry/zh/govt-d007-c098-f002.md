# 民航机场的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
民航机场申报材料与案卷审核的数据主要来源于机场运行审批系统、空管申报平台、安全监管案卷库。数据更新随单次审批流程触发，单次申报材料提交后即时更新，归档案卷则按季度批量同步。文档以正式PDF格式为主，包含申请表单、资质证明文件、航班计划、安全应急预案等内容，结构包含申报编号、机场三字代码、申请日期、审批状态、附件清单等固定字段，部分附件含机场平面图、设备参数表等非结构化内容，单位涵盖架次、工作日、平方米等民航专属计量标准。本场景的向量模型与索引配置基于FastGPT v4.17.0版本。

## 这些特征在「向量模型与索引」这一环带来什么约束
民航申报材料的文档长度差异显著，短则数页的资质证明，长则数十页的安全应急预案，部分单页文本量可达数千字符，要求向量分块策略适配混合文本结构。数据包含结构化元数据与非结构化附件，需同时处理文本内容与位图格式的机场平面图等图片附件，对多模态向量模型的兼容性提出要求。申报流程的即时更新需求，要求索引支持增量同步，避免全量重建带来的不必要资源消耗。固定字段如申报编号、机场代码可作为元数据过滤依据，需在索引构建时绑定对应字段以缩小搜索范围，提升审核效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配民航申报材料中既有短文本审批说明又有长文本安全预案的混合结构 |
| 重叠长度 | 100–150 字符 | 避免长文本分块后丢失上下文关联 |
| maxToken | 8192 | 适配多模态向量模型的输入上限要求，符合民航长文本申报材料的处理需求 |
| 相似度阈值 | 0.72–0.80 按实测标定 | 过滤低匹配度的非相关案卷内容，提升审核精准度 |
| 单次搜索上限 | 前 10 条 | 匹配单批次申报材料的审核量规模，避免冗余结果 |
| defaultToken | 按部署环境预留的资源配置 | 控制单批次向量计算的资源占用，适配机场内网的硬件条件 |

## 容易做错的三处
- 现象：配置向量模型时返回参数错误提示，无法完成模型绑定。原因：未按照模型要求的输入格式处理申报材料中的图片附件，直接上传了未提取图片的原始PDF文件。
- 现象：搜索结果中出现大量跨机场的无关案卷，返回条数远超设置上限。原因：未配置元数据过滤规则，未按机场三字代码或申报编号限定搜索范围。
- 现象：首次索引构建耗时过长，超出预设阈值。原因：未开启增量索引模式，对全量历史案卷进行了重复向量计算。

## 怎么确认配好了
- 上传一份标准的民航机场航班时刻申报PDF，检查向量生成任务的状态是否显示为成功。
- 输入模拟的申报审核问题，查看返回的搜索结果是否仅包含同批次的申报材料，无无关案卷内容。
- 查看向量模型的调用日志，确认`maxToken`和`defaultToken`的取值符合配置的参数值，无异常报错。
- 测试增量上传一份新的申报附件，检查索引是否自动更新，无需触发全量重建任务。
