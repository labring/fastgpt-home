# 民航机场的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
民航机场的申报材料与案卷审核数据主要来源于机场运行管理平台、空管协同报备系统及属地民航监管局报送端口。数据更新节奏分为两类：日常航班申报材料按每日批次提交，执法案卷则按检查周期归档更新。单份文档结构包含航班核心信息字段（航班号、起降时段、机位编号）、地面保障方案附件、安全评估报告，字段单位统一遵循民航行业标准，时段采用ISO 8601格式，机位编号为四位数字编码，附件文档多为PDF格式，单份大小按实测标定。

## 这些特征在「工作流编排」这一环带来什么约束
日常航班申报的每日批次更新要求工作流触发节点需配置定时启动规则，避免重复处理当日已提交的申报材料。民航行业统一的字段格式要求工作流内置固定校验逻辑，对航班号、起降时段等字段进行格式合规性校验。多附件PDF文档的长文本特性，要求工作流配置适配长文本解析的节点，确保安全评估报告等附件内容可被完整读取。执法案卷的周期归档特性，要求工作流支持按监管批次批量流转审核节点，实现分组处理。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定机场运行数据库的实时字段 | 动态获取航班号、机位编号等业务数据，避免固定值无法适配每日更新的申报信息 |
| 触发方式 | 按每日定时+表单提交双触发 | 覆盖日常批量申报与临时应急申报的两种场景，适配民航机场的业务节奏 |
| `nodeId`映射规则 | 按审核层级绑定对应节点ID | 确保工作流按民航机场审核的常规顺序流转，依次经过校验、初审、复核环节 |
| 工具调用模型 | 选用支持长文本理解的通用大模型 | 适配安全评估报告等数千字符的长文档审核需求 |
| 上下文窗口 | 前8000 token | 满足多附件解析后的上下文拼接需求，按实测标定 |
| 异常处理配置 | 当校验失败次数超过3次时触发人工节点 | 处理格式错误、内容违规等无法自动处理的案卷，符合民航监管的审核要求 |

## 容易做错的三处
- 现象：工作流中绑定的业务变量始终显示固定静态值，未随机场每日申报数据更新。原因：未将`variables`配置为绑定机场运行数据库的实时字段，仅手动输入了写死的文本内容。
- 现象：工作流内配置的表单输入组件无法在对话界面展示，用户无法提交申报材料。原因：未将表单节点的`nodeId`正确关联至对话触发节点，导致交互链路未正常打通。
- 现象：高级编排的工具调用环节未按审核逻辑选择后续执行节点，出现流程卡顿或错误跳转。原因：未根据民航案卷审核的长文本需求配置适配的模型，导致工具选择逻辑失效。

## 怎么确认配好了
- 手动触发一次临时申报的工作流，检查`variables`绑定的航班号、机位编号等字段是否为实时获取的最新值。
- 提交一份格式不符合民航标准的测试申报材料，确认工作流是否触发格式校验并进入异常处理节点。
- 查看工作流的节点流转日志，确认`nodeId`映射规则是否按审核层级依次跳转，无异常卡顿。
- 配置一份超长文本的安全评估报告，检查上下文窗口是否能完整加载并完成审核流程。
