# 民航机场的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
民航机场的申报材料与案卷审核数据来源包括航班运行管理系统、属地民航监管报备系统、地勤保障台账归档库。数据更新节奏随保障任务和归档周期变动，单次航班申报材料随保障任务实时提交，案卷类材料按月度、季度批量归档。每份材料包含航班标识字段（航班号、起降时段）、申报主体信息、附件文件列表、审核状态字段，部分材料为PDF格式的纸质扫描件，字段单位包括次、件、MB，需严格匹配民航行业报备规范格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据分散分布在不同系统中，增加了模型接入的鉴权和跨系统同步复杂度。文档结构包含固定格式的行业专属字段，要求模型精准识别并提取指定内容，对模型的格式匹配能力有明确要求。部分案卷材料附带扫描件，需要视觉识别能力支持内容解析。申报材料的提交频率随航班班次波动，需适配高并发下的模型调用响应，同时民航敏感数据的合规性要求模型调用全程在私有网络内完成。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖民航单份申报材料的平均上下文长度，避免截断核心审核信息 |
| `maxTokens` | 3000–4000 token | 审核结果无需过长输出，限制token消耗以控制调用成本 |
| `temperature` | 0.1–0.3 | 审核需严谨一致的输出，降低随机性以确保字段提取的准确性 |
| `toolChoice` | auto | 支持自动调用数据库查询工具，补充航班台账的实时关联数据 |
| `vision` | 开启 | 适配PDF扫描件形式的案卷材料，支持视觉内容的解析与提取 |
| `AIPROXY_API_ENDPOINT` | 机场私有部署的模型API地址 | 保障民航敏感数据不流出私有网络，符合行业数据安全要求 |

## 容易做错的三处
- 现象：前端通过iframe嵌入FastGPT聊天窗口后，父页面无法获取模型返回的输出内容。原因：未配置FastGPT的webhook回调地址，未监听前端事件接口，导致返回数据未正确传递到父页面。
- 现象：调用Mongo查询民航台账数据时，模型消耗的token与实际API返回的token不一致。原因：未限制`maxContext`参数，冗余的历史上下文被计入token消耗，导致实际调用token超出预期。
- 现象：使用本地私有部署的Qwen3-32B模型调用MCP MySQL服务时出现连接报错。原因：未将`AIPROXY_API_ENDPOINT`配置为本地模型的访问地址，且未调整`maxTokens`适配本地模型的上下文上限，导致模型调用失败。

## 怎么确认配好了
- 提交一份标准的民航起降许可申报材料，检查模型返回的审核结果是否准确提取了航班号、起降时段、申报单位等核心字段。
- 查看FastGPT的API调用日志，确认实际消耗的token数与`maxTokens`、`maxContext`的配置值匹配，无异常超额消耗。
- 测试iframe嵌入的聊天窗口，通过预设的回调接口获取模型返回的输出内容，确认数据传递正常。
- 调用本地私有部署的模型，提交一份包含扫描件的案卷材料，检查模型是否能正常解析视觉内容并返回审核结果，无报错信息。
