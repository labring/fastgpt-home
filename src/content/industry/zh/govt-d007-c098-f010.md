# 民航机场的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
民航机场申报材料与案卷审核的数据来源包括机场运行管理部的标准化申报模板、空管批复案卷、安检申报单、航班保障备案文件。更新节奏随新民航政策、临时管制通知或季度标准化修订调整，无固定周期但需在政策发布后24小时内完成知识库同步。文档多为结构化表单搭配长文本保障说明，字段包含申报单号、航班号、起降时刻、保障需求、审核节点记录，单位采用民航通用的计时、架次、吨位标准。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化表单与长文本结合的文档结构，要求检索需兼顾精准匹配字段关键词与长文本语义召回，避免拆分破坏保障逻辑。民航字段的唯一性（如申报单号、航班号）要求检索时需前置过滤唯一标识，防止跨航班结果混淆。临时更新的政策文件要求知识库增量同步周期适配临时通知发布节奏，避免召回过时内容。长文本保障方案的段落长度要求分块时需适配民航文档的章节结构，避免关键保障信息被截断。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.72–0.80 | 适配民航申报材料的关键词密度与语义匹配精度，避免召回无关的跨航班案卷 |
| `limit` | 前8条 | 匹配单航班申报材料的关联审核案卷数量，避免上下文过载影响审核效率 |
| `searchMode` | hybrid | 结合关键词匹配与语义召回，适配结构化字段与长文本保障需求的混合检索场景 |
| `usingReRank` | 开启 | 对召回结果按民航案卷的审核优先级重排序，优先返回当前航班的关联申报材料 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动补充民航通用术语（如「起降时刻」「保障备案」）的同义扩展，提升冷门字段的召回率 |
| `collectionIds` | 绑定机场专属申报案卷库ID | 限定检索范围仅为当前机场的申报材料与案卷，避免跨机场数据干扰 |

## 容易做错的三处
- 检索结果中关联的民航pdf案卷无法在平台内直接打开。原因是未配置适配民航专属加密格式的文件解析插件，部分带航司水印或加密的申报文件无法被正常解析。
- 单次检索返回超过10条无关的跨航班案卷。原因是`limit`参数设置过高，或`similarity`阈值低于0.7，导致语义匹配精度不足。
- 召回结果中包含过期的临时管制通知。原因是未按民航临时政策的更新频率调整知识库的增量同步任务，未及时清理过期案卷数据。

## 怎么确认配好了
- 上传一份测试用的机场申报pdf，发起检索后查看返回结果的文件链接是否可在平台内直接预览。
- 输入包含特定航班号的查询语句，确认返回结果中仅包含该航班的关联案卷，无跨航班数据混入。
- 调整`similarity`参数至0.75，发起重复检索，对比前后结果的召回条数与相关性变化，确认参数生效。
- 开启`usingReRank`后，查看返回结果的排序是否优先匹配当前查询的航班审核节点。
