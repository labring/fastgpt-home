# 民航机场的申报材料与案卷审核：部署与升级

## 这个品类的数据长什么样
民航机场的申报材料与案卷审核数据主要来源于机场运行管理系统、空管申报平台及内部审核台账。日常申报数据按每日航班批次更新，专项案卷按项目周期完成更新，春秋换季时段会出现批量申报数据涌入的情况。申报材料为结构化元数据搭配多附件的格式，元数据包含申请编号、航班号、起降时间、申请类别、申请单位等字段；案卷则包含审核节点、整改意见、批复文号、附件列表等内容，附件以MB为单位标注大小，申请类别为固定枚举类型。

## 这些特征在「部署与升级」这一环带来什么约束
民航申报数据的多附件大体积特性，要求存储配置适配内网对象存储以保障数据安全，同时需预留足够的存储空间应对批量申报场景。结构化字段与高峰并发的查询需求，要求数据库连接配置需平衡资源占用与响应速度，缓存服务需适配临时数据的快速读写。民航数据的合规性要求，需通过权限控制配置限制内网访问与文件访问范围，离线部署场景还需适配内网隔离的环境，避免公网依赖导致的部署失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30` | 适配航班高峰时段的并发数据库查询，平衡连接资源占用与查询响应速度 |
| `MONGODB_URI` | 内网MongoDB集群读写分离连接串 | 存储民航申报案卷的结构化数据，保障数据在内网流转符合安全规范 |
| `REDIS_URL` | 带RDB持久化的内网Redis实例地址 | 缓存临时申报批次数据，减少高峰时段的数据库重复查询压力 |
| `FILE_TOKEN_KEY` | 32位随机生成的密钥 | 为申报附件生成临时访问凭证，仅授权用户可获取案卷相关文件 |
| `STORAGE_S3_ENDPOINT` | 机场内网对象存储服务地址 | 适配大体积申报附件的存储需求，避免本地磁盘空间不足 |
| `FE_DOMAIN` | 机场内网二级域名 | 限制服务仅对内网用户开放，符合民航信息安全管理要求 |

## 容易做错的三处
- 现象：执行npm install时出现chakra-ui/react模块缺失或版本不兼容报错。原因：未使用FastGPT v4.17.0要求的Node.js 18+版本，或本地依赖缓存存在冲突导致安装失败。
- 现象：docker容器启动后，通过curl访问返回500内部错误。原因：`REDIS_URL`或`MONGODB_URI`配置的内网地址无法连通，或配置参数存在格式错误，导致服务无法初始化核心依赖。
- 现象：离线部署后无法加载超过阈值的申报案卷数据。原因：未根据机场申报文档的实际总量调整离线部署的资源限制，或未正确挂载本地附件存储目录导致文件读取失败。

## 怎么确认配好了
- 执行npm install命令，检查终端输出是否存在依赖报错，确认本地Node.js版本符合FastGPT v4.17.0的要求。
- 调用服务内置的数据库连通性测试接口，验证`MONGODB_URI`与`REDIS_URL`配置的连接有效性。
- 上传一份标准民航申报附件，检查是否能正常存储并通过生成的临时链接完成访问验证。
- 模拟多用户并发提交申报查询，检查服务响应状态是否稳定无异常。
