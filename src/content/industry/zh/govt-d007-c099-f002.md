# 油气勘探开发的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
油气勘探开发的申报材料与案卷审核数据，主要来源于钻井岩芯分析报告、地震勘探数据文档、项目申报审批案卷、合规审查材料等。数据更新随勘探项目阶段触发，单次更新内容包含单井或区块的完整资料。文档混合结构化表格与非结构化文本，包含项目编号、勘探区块、井号、提交时间、审批状态等字段，单位涵盖平方千米、米、百分比等专业参数，单篇文档长度差异显著，短则数百字符，长可达数万字符。

## 这些特征在「向量模型与索引」这一环带来什么约束
文档长度差异大且单篇内容偏长，要求向量索引的分块策略适配长文本拆分，避免语义信息断裂；混合结构化与非结构化数据，要求索引支持多类型数据的统一编码与检索；专业术语密集且存在行业专属语义关联，要求向量模型的语义编码适配油气勘探领域的专业语境；数据更新随项目阶段阶段性触发，要求索引的增量更新逻辑匹配非实时的同步节奏，不采用高频全量重建的方式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配油气勘探文档中专业段落的常规长度，避免单块内容超出`maxToken`限制 |
| 重叠长度 | 100–150 字符 | 保留专业术语与上下文的关联，避免核心勘探参数被拆分在不同分块中 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 匹配油气领域专业术语的语义相似度区间，过滤无效的低匹配度结果 |
| 单次搜索上限 | 前 8 条 | 平衡检索精度与效率，适配案卷审核中多文档交叉比对的检索需求 |
| `defaultToken` | 4096 | 适配多数开源向量模型的输入长度限制，兼容常规分块后的单块token数 |
| `maxToken` | 8192 | 匹配FastGPT v4.17.0的默认上下文窗口上限，容纳多份案卷的合并检索内容 |

## 容易做错的三处
- 界面添加本地向量模型时提示404错误，原因是未正确配置模型的本地调用端口，或未将模型容器与FastGPT容器接入同一网络。
- 无GPU环境下无法启动向量模型服务，原因是未选择适配CPU的轻量化向量模型，或未在启动参数中关闭GPU依赖。
- 索引构建完成后检索结果条数不符合预期，原因是分块长度设置过大，导致部分长文档未被完整拆分，或相似度阈值设置过高，过滤了有效匹配内容。

## 怎么确认配好了
- 进入FastGPT的向量模型管理页面，确认已添加的模型状态显示为“已就绪”。
- 上传一份典型的油气勘探申报文档，执行分块测试，确认分块后的片段长度符合预设的分块长度范围。
- 提交一份包含专业勘探术语的测试查询，查看检索返回的结果条数与相似度分布符合配置的阈值与上限要求。
- 提交一份新增的案卷材料，执行增量索引更新，确认新增内容可被正常检索到。
