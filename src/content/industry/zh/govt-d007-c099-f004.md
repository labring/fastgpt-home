# 油气勘探开发的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
油气勘探开发的申报材料与案卷审核数据主要来源于现场勘探采集的测井数据、钻井报告、储量评估文件、审批案卷等。数据更新节奏随项目推进阶段调整，单次申报周期内按审批节点批量更新。文档结构包含固定案卷编号、勘探区块编号、井号、申报日期、审批节点记录等字段，附件多为测井图片、岩芯扫描件、技术报告PDF，字段涵盖经纬度（度分秒格式）、储量（吨/立方米）、文件大小、上传时间等专业属性。

## 这些特征在「工作流编排」这一环带来什么约束
由于附件包含大量专业图片与大体积技术文档，工作流需支持按附件类型触发特定处理节点，避免无效资源消耗。专业字段的格式要求需在工作流中嵌入校验规则，确保录入数据符合油气行业标准。申报案卷的版本关联需求要求工作流绑定对应案卷ID，避免数据混淆。全局知识库的专业术语匹配需求，需通过配置项传入知识库ID，确保调用的是油气勘探专属知识库。另外，单次申报的流程节点较多，工作流需设置合理超时时间，适配复杂审核流程。

## 配置怎么定
本配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 文件上传节点最大文件大小 | 1000 MB | 匹配油气勘探申报单份附件的常规上限 |
| 图片转码触发规则 | 仅检测到附件后缀为.jpg/.png/.tif时执行 | 适配测井图、岩芯扫描件等图片附件类型 |
| `variables` 配置 | 传入全局知识库ID、勘探井号字段 | 满足知识库关联与专业字段校验需求 |
| `nodeId` 配置 | 绑定审批节点更新节点ID | 确保工作流按审批流程顺序流转 |
| 工作流超时时间 | 600–1200 秒 | 适配多节点审核的复杂处理时长 |
| 字段校验规则 | 按油气行业标准校验经纬度、储量单位 | 确保录入数据符合专业规范 |

## 容易做错的三处
- 工作流执行时提示“知识库未找到”，现象为调用知识库节点返回404状态码或空结果。原因是未将知识库ID通过`variables`传入工作流，或全局变量未正确绑定对应油气勘探专属知识库。
- 图片转base64节点执行失败，现象为节点状态显示异常，附件内容为空。原因是未配置仅图片类型触发规则，非图片文件被强制执行转码导致格式错误。
- API调用工作流时返回参数错误，现象为接口返回“missing required field”。原因是未按要求将申报案卷ID作为`variables`传入工作流节点。

## 怎么确认配好了
- 上传一份标准油气勘探图片附件，触发工作流，查看节点日志确认base64编码生成成功。
- 调用工作流API，携带预设的知识库ID与案卷ID参数，检查接口返回的工作流实例状态为运行中。
- 进入工作流配置页面，查看`variables`与`nodeId`的绑定配置与预设参数一致。
- 上传一份非图片附件，确认工作流未触发图片转码节点，避免无效执行。
