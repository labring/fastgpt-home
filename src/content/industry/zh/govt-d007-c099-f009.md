# 油气勘探开发的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
油气勘探开发的申报材料与案卷审核数据主要来源于勘探项目的钻井日志、储量评估报告、环评审批文件、井位勘测资料。数据更新节奏随项目推进调整，单次申报周期内完成定稿更新，非申报期无强制更新。文档以多页PDF为主，包含结构化字段如项目编号、井号、勘探区域坐标，以及非结构化的技术描述、图表附件。字段单位包含米（井深）、平方公里（勘探面积）、万吨油当量（储量估算值）等行业标准单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
油气勘探开发申报材料的多页长文档结构，要求模型接入配置适配长上下文处理，避免截断关键技术内容。结构化字段与非结构化技术描述混合的内容形式，要求配置支持同时识别数值单位与专业术语。项目级数据的阶段性更新节奏，要求接入配置支持动态数据源同步，适配申报前的临时修改。不同申报阶段的案卷格式差异，要求配置兼容多种文档导入格式，避免格式解析失败。专业术语与标准单位的准确性需求，需配置模型的行业术语匹配规则，确保审核结果符合合规要求。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本，针对油气勘探开发申报审核场景定制。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 油气勘探申报材料多为多页长文档，需覆盖完整案卷的上下文内容，避免关键信息截断 |
| `maxTokens` | `2000–3000 token` | 单条审核结果需包含完整的合规性判断与核心细节说明，满足审核报告的输出需求 |
| `quoteMaxToken` | `1500–2000 token` | 需保留申报材料中储量、井深等关键引用内容，确保审核依据的完整性 |
| `temperature` | `0.1–0.3` | 申报材料与案卷审核需严格匹配合规标准，较低的温度值可减少主观判断偏差 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接入地址 | 适配本地或云端的API接入路径，确保模型调用的连通性 |
| `AIPROXY_API_TOKEN` | 按授权文档生成的专属密钥 | 确保模型接入的权限安全性，避免未授权访问 |

## 容易做错的三处
- 现象：对话与工作区中模型返回的审核结果不一致。原因：未统一配置全局模型参数与应用级模型参数，导致不同场景调用了不同的模型版本或参数配置。
- 现象：使用第三方代理服务接入时出现`failed to get gpt-3.5-turbo token encoder`报错。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或代理服务未正常同步模型权限。
- 现象：长申报材料导入后被截断，无法完成完整审核。原因：`maxContext`参数取值过低，未覆盖完整案卷的上下文长度。

## 怎么确认配好了
- 上传单份典型油气勘探申报案卷，检查导入的文档内容是否完整无截断，根据结果调整对应上下文参数。
- 发起单次审核请求，核对返回结果是否包含所有关键字段的合规判断，根据需求调整参数配置。
- 测试动态更新数据源后的接入效果，确认配置支持同步最新的申报材料内容，验证接入路径的有效性。
- 分别在对话与工作区发起相同审核请求，确认两次返回结果一致，检查全局与应用级参数的统一性。
