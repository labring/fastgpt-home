# 油田工程服务的申报材料与案卷审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
油田工程服务的申报材料与案卷审核数据，主要来源于油田内部工程审批系统、现场施工记录归档库、企业资质管理平台。数据更新节奏跟随单个项目的申报周期，单次申报周期内按材料提交节点更新。文档结构多为多附件组合，包含施工方案PDF、资质证书扫描件、现场签证单、预算明细表格等。核心字段包括项目编号、施工区域编码、资质有效期、材料提交日期、案卷审核状态，字段格式多为字符串、日期类型与枚举值，无复杂嵌套层级但单份文件体积普遍偏大。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
油田工程服务的申报材料多为大体积文件，要求接口支持多文件上传与大流量数据传输，需设置较高的超时阈值。多字段的标准化传递要求接口参数需覆盖项目标识、材料类型等核心业务字段，避免字段缺失导致的解析失败。数据更新跟随项目周期，接口调用频率需匹配项目申报节奏，避免过高触发外部系统的限流规则。案卷审核状态的字段解析需精准匹配油田系统的返回格式，需通过`responseData`指定提取的目标字段，避免冗余数据干扰后续处理。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {油田系统API密钥}` | 匹配油田工程服务外部系统的鉴权规则 |
| `variables` | 传入项目ID、材料类型编码、集合ID | 关联文件与对应申报案卷，实现精准查询 |
| `responseData` | 提取审核状态、补正清单、file-id | 聚焦核心业务字段，过滤冗余返回内容 |
| 单次请求文件总大小 | 不超过1000 MB | 适配油田工程文件的常规单包上限 |
| 接口超时时间 | 600 秒 | 覆盖大文件上传与复杂审核数据的返回耗时 |
| 请求频率限制 | 每10秒不超过3次 | 符合油田系统的并发调用约束 |

## 容易做错的三处
- 现象：调用接口后`responseData`中未返回预期的file-id字段，原因：未在`variables`中传入文件所属的集合ID参数，无法建立文件与申报案卷的关联。
- 现象：接口调用返回429状态码，原因：请求频率超过油田系统的并发限制，未按配置的频率阈值发起调用。
- 现象：接口返回的审核结果字段缺失，原因：未在`responseData`中指定需要提取的业务字段，仅返回了默认的通用返回内容。

## 怎么确认配好了
- 调用配置好的测试接口，传入已知的有效项目ID与合法测试文件，检查`responseData`中是否包含预期的file-id字段。
- 上传单份体积不超过配置阈值的测试文件，确认接口无超时报错。
- 按配置的频率间隔发起多次请求，确认无429状态码返回。
- 检查`Authorization`头的配置格式，确认符合油田系统的鉴权要求。
