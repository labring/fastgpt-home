# 油田工程服务的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
油田工程服务的申报材料与案卷审核数据，主要来源于项目立项申报书、现场施工日志、竣工验收案卷、资质备案文件等。数据更新随单个项目推进节奏不定期触发，单次提交的文档体量差异较大。文档通常包含项目编号、施工区域、工期参数、设备型号、审批节点记录等字段，单位涵盖长度、体积、作业时长、物料重量等工程类标准单位，部分案卷会附带结构化表单与非结构化图文附件。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据存在单文档体量跨度大、混合结构化表单与非结构化图文的特征，且更新节奏无固定周期。这要求向量索引不能采用固定长度的强制分块，需支持自适应分块逻辑以保留工程参数的完整性。非结构化的施工日志与验收案卷包含大量专业术语，对嵌入模型的领域适配性提出要求。不定期更新的特性则要求索引支持增量同步，避免全量重建带来的资源消耗。多字段混合的文档结构，需要索引能够关联不同字段的向量特征，避免单一维度的检索偏差。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配单份工程文档的参数段落长度，避免拆分专业术语组合 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的上下文关联，防止工程参数被分块截断 |
| `defaultToken` | 8192 | 适配主流嵌入模型的最大输入token限制，兼容长文档分块后的拼接需求 |
| 相似度阈值 | 0.72–0.85 | 匹配工程案卷的审批关键词匹配精度，过滤低相关的非专业文档 |
| 单次搜索上限 | 前 10 条 | 控制检索返回的案卷数量，平衡召回精度与响应速度 |
| `maxToken` | 16384 | 适配检索后上下文拼接的总长度，容纳多份案卷的关联信息 |

## 容易做错的三处
- 现象：配置阿里千问text-embedding-v3模型时，界面提示“没有可用的渠道”。原因：未在对应分组中绑定该模型的有效API密钥，或密钥对应的服务未开通embedding接口权限。
- 现象：知识库问答环节出现检索后重排超时，日志显示响应时长超过30秒。原因：分块长度设置过大导致单批次检索的分块数量过多，或未限制单次搜索上限导致召回的案卷数据量过大。
- 现象：检索返回的结果中包含大量与工程审批无关的通用文档。原因：相似度阈值设置过低，未过滤低匹配度的内容，或未选用适配工程专业术语的嵌入模型。

## 怎么确认配好了
- 进入模型配置页面，检查嵌入模型的API密钥状态是否显示为正常。
- 上传一份典型的工程申报文档，触发分块与索引流程，查看分块结果是否保留了完整的工程参数段落。
- 发起一条针对工程审批节点的测试查询，核对检索返回的结果是否包含相关案卷内容。
- 查看索引同步日志，确认增量更新流程能够正常触发，无全量重建的异常提示。
