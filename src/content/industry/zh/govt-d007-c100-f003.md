# 油田工程服务的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
油田工程服务的申报材料与案卷审核数据，主要来源于项目立项审批单、施工资质备案文件、现场施工日志、中间验收报告、竣工结算单等内部归档文档。数据更新节奏随项目推进节点动态调整，单次项目周期内可能产生数十份不同类型的材料。单份文档结构包含标准化字段，如工程编号、施工单位资质等级、预算金额（单位：万元）、计划工期（单位：天）、现场检测参数（单位：MPa、m³等），部分材料包含长文本施工方案与专业公式类内容。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据包含标准化的工程编号与资质字段，多轮对话需先确认项目标识才能精准调取对应案卷，避免跨项目匹配错误。数据更新无固定周期，对话流程需支持动态拉取最新提交的材料，无法依赖静态缓存。专业参数单位与公式类内容要求提示词需适配石油工程领域的专业术语，避免审核规则泛化。长文本施工方案与多轮审批意见会占用较多上下文空间，需限制无效历史消息的保留长度，防止超出模型处理上限。

## 配置怎么定
本配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | `8000–12000 字符` | 油田单份申报材料常达数千字符，需保留多轮审批的核心对话历史 |
| 变量绑定规则 | 绑定`工程编号`、`施工单位资质等级`字段 | 实现案卷与审核对话的精准匹配，避免跨项目混淆 |
| 对话历史保留条数 | 前10条 | 过滤冗余的闲聊内容，仅保留审批意见与材料补充请求等有效信息 |
| 提示词触发条件 | 按`messages`参数中的项目类型匹配 | 针对钻井、管道铺设等不同工程类型加载对应审核规则 |
| 前端模块指定 | 按`variables`绑定的模块ID关联展示区域 | 区分资质文件、施工方案等不同类型材料的前端展示位置 |
| 会话超时时间 | 600 秒 | 适配复杂案卷审核的多轮沟通时长，避免会话中途中断 |

## 容易做错的三处
- 现象为前端展示的多个模块内容混杂，无法区分资质文件与施工方案，原因是未通过`variables`绑定指定的前端模块ID，导致所有输出内容未按预设区域展示。
- 现象为提示词未按预期执行审核规则，无法匹配对应工程类型的要求，原因是提示词模板未关联`messages`参数中的项目类型上下文，导致调用通用审核逻辑。
- 现象为发布应用后Latex格式仅显示原始代码，无法正常渲染为数学公式，原因是前端渲染模块未启用专业公式解析配置，仅传递了原始文本内容。

## 怎么确认配好了
- 在调试预览界面输入包含目标工程编号的查询，核对是否自动调取对应项目的申报材料与案卷数据。
- 发起多轮审核对话，确认会话过程中历史消息被正确保留，未出现上下文丢失的情况。
- 发布应用后，测试包含专业工程公式的内容输入，核对渲染格式是否符合预期。
- 查看应用配置日志，确认`chatId`参数在会话中持续传递，且`variables`参数已正确关联前端展示模块的标识。
