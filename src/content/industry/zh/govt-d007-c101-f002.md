# 港口航运的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
港口航运的申报材料与案卷审核数据，主要来源于港口单证系统、船舶安检平台、货物报关端口，包含结构化申报单、非结构化案卷附件两类。结构化数据字段包括船名、航次、提单号、货物重量（单位为吨或TEU）、申报品类；案卷则包含多页审核记录、舱单扫描件、检验报告等。数据更新以单次船舶申报或安检批次为单位，单批次数据量从数条到数十条不等，文档长度差异较大，短则数百字符的申报单，长则数十页的审核案卷。

## 这些特征在「向量模型与索引」这一环带来什么约束
这些特征在「向量模型与索引」这一环带来的约束包括：结构化字段与非结构化附件混合的特征，要求索引时需同时保留字段语义与附件内容的关联，避免拆分关键标识如提单号。按批次更新的节奏，要求索引触发需绑定申报批次完成节点，否则会出现批次内数据索引不一致的问题。文档包含固定单位的数值字段，要求向量模型在嵌入时保留单位相关语义，避免因单位缺失导致匹配偏差。长案卷的存在，要求分块逻辑需适配跨页内容的连续性，防止拆分审核记录的完整逻辑链。同时需注意`defaultToken`的配置需匹配港口数据的平均语义嵌入长度，避免溢出。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 覆盖港口申报单的核心字段组合，避免拆分船名、提单号等关键标识 |
| 重叠长度 | 100–200 字符 | 衔接跨页的案卷审核记录，保留上下文语义的连续性 |
| 相似度阈值 | 0.72–0.85 | 匹配港口业务对审核信息的精准度要求，过滤低相关性的冗余内容 |
| 单次搜索上限 | 前 10 条 | 适配单次审核需关联的案卷数量范围，避免返回过多无关数据 |
| `maxToken` | 4000 token | 适配单批次申报材料的总上下文长度，确保完整召回批次内的核心信息 |
| `defaultToken` | 按实测标定 | 适配港口申报材料的平均语义嵌入需求 |
| 重排 | 开启 | 过滤重复或低相关的索引片段，提升审核查询的准确性 |

## 容易做错的三处
- 现象：上传单批次申报案卷后，界面显示分块数从8段变为13段，出现重复索引片段。原因：系统未按申报单证的分页边界截断分块，导致同一份舱单扫描件的内容被重复拆分。

## 怎么确认配好了
- 上传一份标准集装箱申报单，查看分块预览界面，确认船名、提单号等核心字段未被拆分在不同分块中。
- 发起包含货物重量、航次信息的查询，验证召回结果的分块长度符合配置的800–1200字符范围。
- 批量上传同批次的10份申报案卷，检查索引完成后的分块数无异常重复，且批次内数据的关联度符合预期。
- 调整相似度阈值后，验证召回结果的匹配精度符合港口审核业务的实际需求。
