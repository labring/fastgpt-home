# 炼化生产的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
炼化生产的申报材料与案卷审核数据主要来自企业生产管理系统、属地应急管理部门备案档案、设备运维台账与工艺参数记录。数据更新随生产批次或月度备案周期推进，单份案卷文档通常包含申报主体资质文件、装置运行参数表、安全检测报告、环评附件等结构。文档字段包含装置编号、物料流量、运行压力、检测日期等，单位多为立方米/小时、兆帕、吨/天等工业标准单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
炼化生产申报材料的多源分散特征，要求多轮对话需按资质、参数、检测、环评的模块顺序逐步引导用户提交对应内容，避免信息遗漏。单份案卷文档长度较长且包含专业工业字段，提示词需限定上下文截取范围，防止token占用超出模型限制。字段附带专属工业单位，提示词需明确要求输出匹配标准单位的校验结果。申报数据按生产周期更新，多轮对话上下文需自动过滤过期批次信息，避免审核混淆历史与当前申报内容。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 炼化申报案卷单份文档长度较长，适配长文本审核需求 |
| 对话上下文保留条数 | 前12轮对话 | 覆盖从资质提交到参数校验的完整申报流程 |
| 提示词变量配置 | 绑定装置编号、申报批次 | 匹配案卷专属工业字段，确保校验精准 |
| 单次交互token上限 | 3500 token | 控制单轮输入的信息规模，避免模型响应超时 |
| 上下文过滤规则 | 按申报批次自动筛选 | 适配数据按生产周期更新的特征，防止混淆历史数据 |
| 问题优化开关 | 开启 | 提炼用户模糊的参数描述，匹配炼化行业标准术语 |

## 容易做错的三处
- 现象：多轮对话上下文丢失，审核时无法引用前几轮提交的装置参数。原因：未绑定`chatId`到专属申报项目，导致对话上下文被新会话覆盖。
- 现象：模型输出的参数单位不符合工业标准，如将吨/天写成立方米/小时。原因：提示词未明确要求匹配炼化行业专属单位字段，未通过`variables`绑定校验规则。
- 现象：单轮对话超时或无法接收上传的检测报告文件，返回504状态码或参数错误。原因：单次交互输入的token超出预设上限，或未配置文件上传的允许格式与大小限制。

## 怎么确认配好了
- 发起首轮对话提交资质文件，发起第二轮对话提交装置参数，检查`messages`列表是否完整保留两次交互内容。
- 输入包含非标准单位的参数描述，验证模型输出是否自动修正为炼化行业标准单位。
- 切换至不同申报批次的会话，检查不同`chatId`绑定的上下文不会互相串用。
- 提交单份完整案卷的文本内容，验证模型响应未出现token溢出报错。
