# 炼化生产的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
炼化生产的申报材料与案卷审核数据主要来自项目立项申请、安全环保评审备案、生产运行台账及合规案卷。数据更新随项目推进或月度合规巡检节奏，单次申报材料可能包含数十页PDF可研报告、Excel物料平衡表、扫描版工艺图纸与Word审批流程单。文档字段包含装置编号、物料牌号、排放限值、审批文号等，配套使用吨、立方米、兆帕等工业单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
多格式混合的数据源要求解析环节兼容PDF文本、Excel表格与扫描图纸OCR，避免部分格式数据丢失。长文档与专业术语密集的特性，要求分块需保留上下文关联，避免拆分中断工艺描述、物料参数等关键信息。不同申报案卷的结构差异较大，部分按章节编排、部分按审批条目罗列，需适配灵活的分块触发逻辑。批量提交的多文件场景下，需统一解析参数以保证分块结果一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 炼化申报材料包含长段落的工艺描述与参数表格，该区间可保留单组工艺逻辑的完整性 |
| `chunkSplitter` | 按章节+语义分段 | 炼化案卷多按审批章节或工艺节点编排，该分块方式可匹配文档原生结构 |
| `customPdfParse` | 启用 | 部分申报材料为加密或带水印的PDF，自定义解析可适配工业文档的特殊排版 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型可研报告或多页图纸解析耗时较长，该时长可覆盖绝大多数单文件解析需求 |
| `chunkSettingMode` | 手动配置 | 不同申报批次的文档结构差异明显，手动配置可灵活调整分块参数 |

## 容易做错的三处
- 现象：API上传与平台直传的文件分块结果存在差异，部分段落拆分位置不一致。原因：未统一配置`chunkSplitter`参数，API调用默认使用通用分块规则，平台直传可手动调整分块模式。
- 现象：使用自定义URL导入文档后无解析数据返回。原因：未开启`customPdfParse`适配自定义链接的资源权限校验，或链接指向的文件格式不被基础解析支持。
- 现象：配置解析节点后模型无法读取上传文件，日志显示文件解析状态为超时。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，大型炼化图纸或长文档解析超出默认时长导致解析失败。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的平台，上传单份典型炼化申报文档，查看解析后的分块列表，确认工艺描述、参数表格未被异常拆分。
- 分别使用API上传与平台直传同一份文档，对比分块结果，确认`chunkSplitter`配置已统一。
- 导入自定义链接的工业文档，检查解析结果是否包含完整的文本与OCR内容。
- 提交大型可研报告，查看解析日志的耗时记录，确认`PARSE_FILE_TIMEOUT_SECONDS`设置足够覆盖解析时长。
