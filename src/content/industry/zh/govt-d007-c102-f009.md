# 炼化生产的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
炼化生产的申报材料与案卷审核数据，来源包括炼化装置的MES生产台账、物料平衡报表、安监备案卷宗、项目申报可研文档。更新节奏随单次申报项目周期或日常审核流程实时推进。单份案卷文档长度从几十页到数百页，包含装置编号、物料牌号、能耗定额（单位：吨标煤/吨产品）、审批节点状态、合规校验项等结构化与非结构化字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
炼化申报材料与案卷的文档长度跨度大，要求模型上下文配置需覆盖不同长度的输入，避免核心合规校验内容被截断。专业字段的单位与术语（如吨标煤/吨产品、装置开工率）要求模型需具备炼化行业术语的理解能力，避免审核结论出现专业偏差。多来源的结构化与非结构化数据混合，要求配置多类型数据的解析适配规则。单次审核涉及的合规校验项较多，工具调用的触发与返回逻辑需适配多任务的处理要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配炼化案卷数百页的文本长度，避免截断核心合规校验内容 |
| `maxTokens` | 2000–3000 token | 控制审核结论输出长度，确保专业判断清晰完整 |
| `toolChoice` | auto | 自动适配申报材料中的合规校验、数据比对等工具调用需求 |
| `temperature` | 0.2–0.4 | 降低随机输出，确保专业审核结论的一致性 |
| `AIPROXY_API_ENDPOINT` | 企业内网专属节点 | 适配炼化企业的网络安全要求，保障数据传输合规 |
| `AIPROXY_API_TOKEN` | 按角色分配专属密钥 | 区分不同审核人员的操作权限，符合企业数据安全规范 |

## 容易做错的三处
- 现象：工具调用返回结果为空或状态码500，原因：未针对炼化专业字段配置工具调用的参数校验规则，导致模型无法识别合规校验项的输入格式。
- 现象：模型输出的审核结论与案卷中的专业单位不符，原因：`temperature`取值过高，导致模型生成的专业术语出现偏差。
- 现象：部署重启后模型配置丢失，原因：未将模型配置文件挂载至持久化存储目录，导致重启后临时存储的配置被清空。

## 怎么确认配好了
FastGPT v4.17.0 版本下，可通过以下动作确认配置生效：
- 上传一份典型的炼化项目申报案卷，检查模型输入的文本未被截断，确认上下文配置适配文档长度。
- 发起一次合规校验工具调用，检查工具返回的结果与案卷中的数据匹配度符合预设要求，确认工具调用配置生效。
- 重启部署环境，检查原有模型配置与应用设置未丢失，确认持久化存储配置正确。
- 调整`temperature`参数后重新生成审核结论，检查结论的一致性符合预期，确认参数配置生效。
