# 炼化生产的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
数据来源包括炼化装置工艺台账、安全合规案卷、技改项目申报书、环评验收文件、质检与能耗报表。更新节奏为单次项目申报周期内批量更新，日常归档按季度同步。文档多为多页PDF或结构化表单，包含工艺参数、设备编号、审批节点、合规指标等字段，字段单位涉及MPa、℃、t/h、立方米/小时等工业单位，单份文档长度从数百字到数万字不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多字段带工业单位的文档，要求检索时需同时匹配参数数值与对应单位，避免混淆不同工况的工艺数据。长文档占比高，要求分块时保留相邻节点的上下文，确保工艺逻辑完整。异构数据源结构差异大，要求检索前完成字段标准化映射，确保召回结果的一致性。单次项目申报涉及多类文档，要求召回范围限定在当前项目的专属数据集内，避免跨项目数据干扰。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | 匹配炼化专业术语与工艺参数的精准度要求，避免召回无关的通用合规文档 |
| `limit` | 前12条 | 单份申报材料涉及多类工艺节点，需召回足够覆盖的相关案卷，同时控制上下文长度 |
| `searchMode` | semantic | 针对长文本与专业术语的语义匹配需求，替代关键词匹配的泛化召回 |
| `usingReRank` | 开启 | 对召回结果按与查询的语义相关性重排序，优先返回工艺参数匹配度高的结果 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展专业术语查询，比如将“常压塔”扩展为“常压蒸馏塔”“常压装置”，覆盖炼化行业同义词 |
| `collectionIds` | 按实际绑定的炼化合规案卷、工艺台账数据集ID填写 | 确保仅检索当前项目关联的专属数据集，避免跨项目数据干扰 |

## 容易做错的三处
- 现象：启动FastGPT v4.17.0后知识库检索报错`text index required for $text query`，原因：未在数据集创建时启用全文索引配置，或升级版本后未重建向量索引。
- 现象：部署后检索结果包含非授权的跨项目案卷，原因：未正确配置`collectionIds`参数，导致绑定了无关的数据集。
- 现象：迁移知识库后检索结果为空，原因：未正确导出导入数据集的向量索引文件，仅迁移了元数据导致无法匹配查询。

## 怎么确认配好了
- 提交包含具体工艺参数与单位的查询，检查返回结果的字段是否包含匹配的设备编号与对应单位。
- 查看检索日志，确认召回结果的数量符合`limit`配置的取值范围。
- 测试启用`usingReRank`前后的结果排序差异，确认重排功能正常生效。
- 检查数据集绑定的`collectionIds`是否仅包含当前项目的合规案卷与工艺台账数据。
