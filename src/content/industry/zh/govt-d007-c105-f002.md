# 煤炭运销的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
煤炭运销的申报材料与案卷审核数据，来源为运销审批申报单、过磅凭证、运输合同、安监备案文件及月度结算案卷。更新按申报批次与月度结算周期推进，文档包含结构化字段与非结构化附件。结构化字段包括运销单号、矿点名称、煤种、核定吨位、运输路线、审批节点、审核意见等，非结构化附件多为PDF格式的合同扫描件、审批意见书，单位涉及吨、公里、批次编号。

## 这些特征在「向量模型与索引」这一环带来什么约束
运销申报材料包含结构化字段与长文本附件，且更新按申报批次与月度结算周期推进，对向量索引环节带来多重约束。多字段混合的内容需要配置多向量索引绑定元数据，实现精准过滤；长文档附件需要适配可变长度的分块规则，避免截断关键审批内容；增量更新需匹配申报周期，避免索引滞后于业务流程；部分数值型字段需转换为文本嵌入，保证向量检索的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxToken` | 8192 | 适配煤炭运销合同、案卷的长文本内容，匹配FastGPT v4.17.0主流嵌入模型的上下文上限 |
| 分块长度 | 800–1200 字符 | 覆盖单份运销单据的核心内容，避免分块过碎或过长导致检索精度下降 |
| 重叠长度 | 100–200 字符 | 保证相邻分块的上下文连贯性，避免审批节点、合同条款被拆分断裂 |
| 相似度阈值 | 0.72–0.80 | 区分有效审核意见与无关文档，适配煤炭运销案卷的文本相似度分布 |
| 单次搜索上限 | 前 10 条 | 覆盖单批次申报的关联案卷数量，避免检索结果冗余影响查询效率 |
| `defaultToken` | 2000 | 平衡单条嵌入的文本长度与检索效率，适配结构化字段的嵌入需求 |

## 容易做错的三处
- 现象：上传煤炭运销合同后，向量数据库无对应嵌入数据，检索时返回空结果。原因：未针对长文本附件配置合适的分块长度，导致分块超出嵌入模型的token限制，嵌入失败。
- 现象：嵌入环节弹出「m3e无可用频道」提示，无法生成案卷的向量数据。原因：未在FastGPT自定义模型配置页面添加m3e的API频道，未配置正确的接入密钥与地址。
- 现象：批量上传月度结算案卷时，部分文档索引进度停滞。原因：未配置合理的单次上传文档数量上限，导致资源占用过高触发超时。

## 怎么确认配好了
- 上传单份煤炭运销合同，查看嵌入任务日志，确认无token超限报错，检查向量数据库中存在对应嵌入条目。
- 提交包含煤种、运输路线关键词的查询，验证检索结果包含匹配的申报材料，确认相似度配置适配业务场景。
- 上传增量的月度结算案卷，等待索引更新完成后，检索新案卷的编号，确认检索结果包含新上传的内容。
- 进入自定义模型配置页面，确认m3e频道已添加并启用，验证嵌入环节无频道不可用提示。
