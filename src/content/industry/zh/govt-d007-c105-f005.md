# 煤炭运销的申报材料与案卷审核：工具调用与插件

## 这个品类的数据长什么样
数据主要来自煤炭运销调度系统、过磅管理系统、税务申报端口与客户结算台账。更新节奏为每日批次更新，单批次申报材料包含10至50份电子或纸质案卷。文档字段包含煤种编码、运输单号、过磅重量（单位：吨）、结算单价（单位：元/吨）、审批节点状态、申报批次号，部分案卷附带过磅照片与运输合同扫描件，单份文档最大可达200 MB。

## 这些特征在「工具调用与插件」这一环带来什么约束
煤炭运销申报数据分散在多个独立系统，工具调用需配置多源数据聚合插件，同步调取调度、过磅与税务系统的接口。单份案卷最大可达200 MB，工具调用的文件处理模块需适配大体积文档的分片上传与解析。每日批次更新的特性要求工具触发频率匹配运销作业周期，避免重复调用或遗漏当日申报批次。字段包含吨、元/吨等专属单位，工具参数校验需强制匹配对应单位格式，防止录入错误导致的调用失败。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次工具调用超时 | 1200–1800 秒 | 覆盖煤炭运销多源数据聚合、案卷OCR解析的常规耗时 |
| `toolChoice` | auto | 自动匹配申报校验、数据核对等所需工具，适配多环节审核需求 |
| 工具调用重试次数 | 2–3 次 | 应对运销系统接口偶发波动，降低临时网络问题导致的调用失败 |
| 大文档分片阈值 | 80–120 MB | 适配单份案卷最大200 MB的特性，拆分后分批处理避免内存溢出 |
| 定时触发频率 | 每日 1 次 | 匹配运销数据每日批次更新的节奏，确保调用数据为当日最新 |

## 容易做错的三处
- 现象：工具调用返回`504 Gateway Timeout`错误，或工作流执行状态显示超时未完成。原因：未调整单次工具调用超时配置，沿用默认值导致无法覆盖煤炭运销批量案卷处理的耗时。
- 现象：工具调用返回字段格式错误，如重量字段仅显示数值未附带单位。原因：未配置匹配煤炭运销专属单位的参数校验规则，导致数据格式不匹配校验逻辑。
- 现象：知识库调用返回空结果，无法匹配申报材料中的煤种信息。原因：使用通用鉴权KEY，未绑定煤炭运销专属知识库的权限范围，导致无法访问对应业务文档。

## 怎么确认配好了
- 手动触发单次工具调用，检查返回结果是否包含煤炭运销专属业务字段，核对字段单位是否符合业务要求。
- 查看工具调用日志，确认多源数据聚合环节是否成功调取各系统接口，无失败请求或异常报错。
- 配置定时触发任务，等待一个执行周期后，检查生成的审核结果是否包含当日最新的申报批次数据。
- 上传单份最大体积的测试案卷，确认系统可自动分片处理并完成解析，无截断或内存溢出提示。
