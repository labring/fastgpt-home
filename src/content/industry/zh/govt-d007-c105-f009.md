# 煤炭运销的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
煤炭运销的申报材料与案卷审核数据主要来源于购销合同、过磅单、公路/铁路运输单据、增值税专用发票、审批流转记录等。数据随每笔运销业务完成生成更新，单次案卷包含3至5份不同类型的文档，整体结构以结构化表格为主，辅以自由文本说明。核心字段包含煤种名称、发运吨位、运输里程、开票含税金额、审批节点状态等，单位涵盖吨、公里、元等常规计量标准，部分单据存在自定义字段格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
煤炭运销申报案卷的多文档组合特性，要求模型接入环节需适配长上下文处理需求，避免关键信息被截断。结构化字段占比高的特点，要求配置需兼顾文本提取的准确性与格式规范性。单批次审核可能涉及多份案卷的并行处理，需调整并发相关配置以适配业务峰值。部分单据存在自定义格式，需预留参数调整空间以适配非标准化字段的识别，同时需确保国内模型调用链路的稳定性，避免跨境延迟影响审核效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 煤炭运销申报案卷通常包含多份关联文档，总上下文长度较长，需覆盖全部关键审核信息 |
| `maxTokens` | 2000–3000 token | 单份审核结果需包含合规性判断、问题整改建议等内容，控制生成长度以保证可读性 |
| `quoteMaxToken` | 1500–2000 token | 审核过程需引用原始单据的关键字段作为依据，保留足够的原文片段以支撑判断 |
| `temperature` | 0.1–0.3 | 审核场景需稳定的判断结果，避免随机性导致的审核结论偏差 |
| `toolChoice` | auto | 支持模型自主选择是否调用结构化提取工具，适配不同类型的案卷内容 |
| `AIPROXY_API_ENDPOINT` | 按部署的国内大模型专属端点填写 | 适配国内模型的调用链路，避免跨境延迟影响审核速度 |

## 容易做错的三处
- 现象：部署的vllm实例处理批量审核请求时出现超时报错。原因：未根据并发业务量调整模型接入的并发配置，或`maxContext`设置过大导致模型加载延迟过高。
- 现象：模型生成的审核SQL语句中缺少空格，导致执行报错。原因：`temperature`参数设置过高，导致生成的代码格式不规范，未保留必要的分隔字符。
- 现象：调用国内模型时出现接口认证失败。原因：错误配置`AIPROXY_API_ENDPOINT`指向外部服务商，未使用适配国内模型的专属端点。

## 怎么确认配好了
- 上传一份完整的煤炭运销申报案卷，检查模型返回的审核结果是否准确提取了煤种、吨位、金额等核心字段。
- 发起3-5份案卷的批量测试请求，观察接口返回延迟是否符合业务预期，确认并发处理正常。
- 多次上传同一份标准案卷，检查审核结果是否保持一致，验证`temperature`参数的稳定性配置效果。
- 查看FastGPT v4.17.0的接口调用日志，确认请求的`AIPROXY_API_ENDPOINT`和身份验证信息配置正确，无异常报错。
