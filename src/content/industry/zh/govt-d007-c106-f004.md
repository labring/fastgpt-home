# 煤电一体化的申报材料与案卷审核：工作流编排
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
煤电一体化项目的申报材料与案卷审核数据，主要来源于煤炭生产台账、电力调度系统、项目立项审批文件及现场环保检测报告。数据更新节奏随项目推进节点调整，立项报审阶段每日同步新增材料，验收阶段按批次更新归档文档。单份案卷文档通常包含项目备案表、机组产能核算单、环保检测报告、电力并网申请单四类核心文件，字段包含矿井编号、机组容量（单位MW）、煤炭产能（单位万吨/年）、并网电压等级（单位kV），以及各审批环节的流转时间戳与经办人记录。

## 这些特征在「工作流编排」这一环带来什么约束
多源分散的数据来源要求工作流配置跨系统数据拉取节点，分别对接煤炭生产台账、电力调度系统等数据源。随项目节点动态更新的数据节奏，要求工作流触发条件绑定审批节点状态，仅在报审或验收节点启动执行。多类文件混合的案卷结构，要求工作流按文件类型拆分校验环节，分别验证备案表、产能核算单等文档的必填字段。带有特定单位的字段要求，需要在工作流中嵌入单位校验逻辑，确保机组容量、煤炭产能等数值与对应单位匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | `{"coal_capacity_unit": "万吨/年", "unit_voltage": "kV"}` | 匹配煤电一体化项目字段的固定单位要求，避免校验失败 |
| 节点触发条件 | 按审批节点状态触发，延迟600秒启动 | 适配项目报审的流转时间，预留材料上传缓冲 |
| 知识库关联 | 绑定煤电行业审批规范知识库，召回前5条 | 覆盖申报材料的合规校验需求，控制返回结果量 |
| 代码运行节点 | 按实测标定超时阈值 | 适配大型案卷的格式解析耗时，避免中途中断 |
| 外部MCP插件接入 | 配置为按需触发，关联煤炭产能核算接口 | 仅在产能校验环节调用外部工具，降低资源占用 |
| `nodeId` | 绑定校验节点的唯一标识 | 精准定位工作流执行环节，便于日志溯源与异常排查 |

## 容易做错的三处
- 现象：代码运行节点执行后返回状态码500，日志显示“参数格式不匹配”。原因：未将煤电项目的产能数值与对应单位绑定，导致外部核算接口无法解析字段内容。
- 现象：工作流变量选择界面无可选值列表，无法绑定案卷的核心字段。原因：未在全局变量配置中预定义煤电一体化项目的固定字段模板，系统无法加载对应可选参数。
- 现象：通过外部接口调用工作流时返回“无效节点标识”。原因：未使用正确的`nodeId`参数绑定目标执行节点，导致接口无法匹配到对应的工作流环节。

## 怎么确认配好了
- 手动触发工作流，检查各数据拉取节点是否成功获取煤炭生产台账、电力调度系统的对应数据。
- 提交一份标准煤电一体化申报案卷，验证代码运行节点是否能正确解析产能、电压等级等字段的单位与数值。
- 调用外部MCP插件接口，检查是否能正常触发煤炭产能核算逻辑，无权限或超时报错。
- 查看工作流日志，确认`variables`参数已正确绑定煤电项目的固定字段模板，`nodeId`标识与目标节点一致。
