# 煤电一体化的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
煤电一体化的申报材料与案卷审核数据主要来自项目立项审批文件、月度生产台账、安监执法案卷及合规整改记录。数据更新分为两类：项目申报阶段批量导入历史材料，日常案卷随执法与整改进度更新。单份文档结构固定，包含项目概况、产能参数、环保指标、审批文号、整改记录等字段，产能单位为万吨/年，能耗单位为吨标煤，案卷包含统一的执法编号与责任主体信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
固定结构的长文档会占用更多上下文额度，需要限制单轮处理的文本长度，避免超出模型支持范围。数值类字段的精准识别需求，要求模型输出保持稳定，需调整温度参数控制随机性。批量导入的申报材料与动态更新的案卷，要求知识库同步频率适配业务节奏，避免数据滞后或重复加载。案卷的唯一编号与结构化字段，需要模型在召回阶段精准匹配关键词，需调整检索相关配置的阈值。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单份申报材料的平均长度，避免截断核心审批字段与产能参数 |
| `temperature` | 0.1–0.3 | 保障数值字段与结构化信息的识别准确性，降低无关输出的概率 |
| `quoteMaxToken` | 1500–2000 字符 | 匹配案卷中整改记录的典型长度，确保召回的执法内容完整传递 |
| `AIPROXY_API_ENDPOINT` | 对应模型服务商的官方接入地址 | 适配煤电一体化场景所需的大模型算力规格与接口规范 |
| `AIPROXY_API_TOKEN` | 从服务商控制台获取的专属密钥 | 保障模型接入的身份验证安全，防止未授权访问 |
| `maxTokens` | 2000–3000 token | 控制单轮审核结果的输出长度，符合案卷审核的文书规范 |

## 容易做错的三处
- 现象：知识库可检索到数据，但模型输出为空或无关联内容。原因：未正确配置`maxContext`参数，导致召回的案卷内容超出上下文额度被截断，无法传递给模型。
- 现象：模型接入渠道显示异常，无法选择对应供应商。原因：未正确填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，身份验证失败导致渠道无法启用。
- 现象：离线配置重排模型时提示加载失败。原因：未匹配模型的token额度参数，导致重排模型所需的上下文超出预设限制，无法正常加载。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型管理页面，查看对应供应商渠道的状态是否显示正常。
- 上传一份典型的煤电一体化申报材料，触发模型审核，检查召回的案卷内容是否完整出现在上下文预览中。
- 提交一份包含产能数值的测试用例，验证模型输出是否准确识别万吨/年、吨标煤等单位字段。
- 触发知识库同步操作，等待同步完成后，检索测试案卷的执法编号，确认召回结果条数符合预期。
