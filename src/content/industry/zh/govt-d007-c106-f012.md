# 煤电一体化的申报材料与案卷审核：部署与升级

## 这个品类的数据长什么样
煤电一体化项目的申报材料与案卷数据，主要来源于项目立项、产能核验、安全验收等环节的官方填报文档与现场检测报告。数据更新以单次项目申报周期为单位，批量上传核心案卷，日常审核按需同步补充材料。单份案卷包含项目编号、关联矿井与电厂信息、产能参数、审批节点记录等字段，部分附件含多页扫描件与结构化报表，字段单位涵盖兆瓦、吨标准煤、万千瓦时等行业专用计量标识。

## 这些特征在「部署与升级」这一环带来什么约束
煤电一体化申报案卷的批量文档结构与专用计量字段，要求部署时需适配大文件存储与结构化数据关联需求。批量上传的高频场景会带来数据库并发访问压力，升级时需避免中断正在进行的同步任务。专用计量字段的校验逻辑需与FastGPT的文档解析模块匹配，否则会导致字段解析失败。跨环节的案卷关联数据，要求数据库配置支持多表关联查询，升级过程中需保留原有数据结构的兼容性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `200–300` | 适配煤电申报案卷的并发访问量，避免连接耗尽 |
| `STORAGE_S3_ENDPOINT` | 对应对象存储的内网访问端点 | 降低大尺寸案卷附件的上传下载延迟 |
| `REDIS_URL` | 带访问密码的内网连接地址 | 缓存案卷审核状态与同步任务进度，减少数据库重复查询 |
| `MONGODB_URI` | 副本集格式的连接字符串 | 保障案卷元数据的多副本存储与高可用 |
| `FILE_TOKEN_KEY` | 32位随机生成的字符串 | 保护案卷附件的下载链接，防止未授权访问 |
| `PG_URL` | 配置连接池超时为`600 秒` | 适配批量导入申报材料时的长连接需求 |

## 容易做错的三处
- 现象：升级FastGPT v4.17.0后，已上传的煤电申报案卷内容未在检索结果中显示，知识库页面无对应条目。原因：未执行新版要求的数据库迁移脚本，导致旧版知识库的案卷元数据未同步到当前版本。
- 现象：用tei部署的bge-reranker模型测试通过，但每次检索结果的重排标记为`false`，无有效重排结果。原因：未将`REDIS_URL`配置为与重排服务同网段的地址，导致跨节点通信延迟，重排逻辑无法正常触发。
- 现象：docker部署后，批量导入的案卷附件无法正常下载，页面返回403错误。原因：`FILE_TOKEN_KEY`配置的密钥长度不足，导致下载链接的校验逻辑失败。

## 怎么确认配好了
- 运行FastGPT内置的数据库连通性检测工具，验证`MONGODB_URI`与`PG_URL`的连接是否正常，无超时或认证失败报错。
- 上传单份煤电申报案卷的附件文件，确认可以正常生成下载链接并访问对应文件。
- 触发一次批量更新任务，检查`REDIS_URL`对应的缓存服务中是否生成了最新的任务状态条目。
- 调用重排模型测试接口，确认返回结果包含有效重排分值，无空值或异常标记。
