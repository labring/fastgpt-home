# 煤矿生产的申报材料与案卷审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
煤矿生产的申报材料与案卷审核数据，主要来源于煤矿安全生产调度平台、矿井安监档案系统、地方能源监管申报端口。数据更新节奏为单次申报周期内批量同步，日常归档按周更新。文档多为扫描件转PDF或编辑版Word，包含矿井编号、采掘工作面编码、瓦斯检测数据、审批流转记录等结构化字段，单位包含%、吨、立方米、小时等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
煤矿生产的申报材料多为带结构化字段的扫描PDF或编辑文档，单次上传文件体积较大，要求HTTP接口支持大文件阈值配置；固定字段如矿井编号、安监审批文号需随请求同步传递，要求接口支持自定义`variables`参数绑定业务字段；申报周期内批量提交的需求，要求接口支持批量请求适配；数据涉及安全生产监管，接口鉴权需严格匹配企业内部系统的权限规则，确保调用合法性。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {企业内部安监系统的token}` | 匹配煤矿内部系统的鉴权规则，确保接口调用权限合法 |
| `variables` | `{"mineCode": "XXX", "workfaceCode": "XXX", "approvalId": "XXX"}` | 绑定矿井、工作面、审批文号等业务固定字段，匹配申报材料的结构化要求 |
| `responseData` | `["code", "message", "data"]` | 适配煤矿内部系统的返回格式规范，便于解析调用结果 |
| 超时时间 | `600 秒` | 大文件上传及批量审核需较长处理周期，避免提前中断 |
| 文件上传大小限制 | `1000 MB` | 单份煤矿申报案卷可能包含多份检测报告与图纸，整体体积较大 |

## 容易做错的三处
- 现象：调用申报接口返回`Invalid URL, code: 500`。原因：未正确配置目标接口的域名路径，或企业内部系统的防火墙拦截了外部调用请求。
- 现象：直接上传PDF文件时接口返回字段为空。原因：未通过`variables`绑定结构化业务字段，导致系统无法匹配申报材料的审核规则。
- 现象：HTTP工具集调用无响应或超时。原因：未调整超时时间配置，大文件上传或批量审核的处理周期超过默认阈值。

## 怎么确认配好了
- 调用企业内部安监系统的鉴权接口获取有效token，替换`Authorization`参数后发起测试请求，检查返回的鉴权状态码是否为200。
- 传入预设的`variables`参数，发起单条申报材料的测试调用，核对返回的`responseData`是否包含预期的业务字段。
- 上传单份不超过100 MB的测试PDF文件，检查接口是否正常接收并返回处理进度。
- 查看企业内部系统的日志，确认接口请求的源IP和鉴权信息是否被正常放行。
