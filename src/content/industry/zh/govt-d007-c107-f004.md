# 煤矿生产的申报材料与案卷审核：工作流编排

## 这个品类的数据长什么样
煤矿生产的申报材料与案卷审核数据来源包括内部调度系统、井下监测终端、属地安监报备平台。数据更新节奏为单次井下作业完成后即时更新，月度形成完整案卷批量归档。文档结构固定包含作业面编号、瓦斯/粉尘监测参数值、审批流转节点记录、整改反馈单等字段，字段单位涉及ppm、立方米、小时、份等。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散要求工作流配置多节点并行或串行调用不同数据源的工具，避免单节点拉取全量数据的延迟。数据更新即时性要求工作流节点执行间隔匹配作业节奏，不宜设置过长的缓存周期，需实时拉取最新监测数据。案卷的层级审批逻辑要求工作流按节点顺序编排，前一节点校验通过后才能触发下一节点。字段带特定单位的特征要求工作流添加格式校验节点，确保参数传递时单位统一。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量映射 | 绑定作业面ID、监测参数、审批节点ID为`variables` | 匹配煤矿申报材料的固定字段结构，便于跨节点传递数据 |
| 节点触发规则 | 按`nodeId`顺序执行，前节点校验通过后触发 | 符合煤矿案卷审核的层级审批逻辑，避免跳级操作 |
| 知识库关联 | 绑定煤矿安全规程库、作业标准库 | 覆盖合规校验的核心数据源需求，匹配审核场景 |
| 超时阈值 | 600秒 | 适配井下数据采集的网络延迟情况，按实测标定 |
| 分支触发条件 | 按字段合规性判断分支走向 | 区分合格申报材料与需要整改的材料，分流处理 |
| 工具调用终止 | 流程末尾添加终止节点 | 明确流程结束标识，避免循环调用工具 |

本配置说明基于FastGPT v4.17.0版本。

## 容易做错的三处
- 工作流末尾未添加工具调用终止节点，出现循环调用工具的情况，原因是未明确流程结束标识，导致系统重复触发后续节点。
- http模块自定义输入变量未按`variables`格式定义，出现接口接收参数为空的报错，原因是未匹配FastGPT的变量传递规则。
- 未设置知识库匹配关键词阈值，出现无关问题触发对应知识库的情况，原因是未配置分支触发的关键词校验，导致非目标知识库被调用。

## 怎么确认配好了
- 提交测试用的煤矿作业申报材料，检查各节点是否按`nodeId`顺序执行。
- 查看`variables`变量传递日志，确认作业面ID、监测数据等字段无格式错误。
- 触发无关测试问题，确认流程是否按预设分支跳转至指定回复。
- 模拟节点超时场景，确认超时阈值触发后的异常处理逻辑。
