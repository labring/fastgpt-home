# 煤矿生产的申报材料与案卷审核：引用来源与溯源
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
煤矿生产的申报材料与案卷审核数据，来源包括煤矿生产调度系统的每日班组日报、安全监察机构台账档案、瓦斯通风监测报表、掘进采煤工程量记录、企业内部证照审批文件。更新节奏分为实时更新的班组日报与监测数据、每周汇总的安监台账，以及按季度或年度更新的证照文件。文档包含结构化填报字段与非结构化佐证附件，字段带有明确物理单位，如米、%、立方米/分钟，附件多为扫描版审批表或监测截图。

## 这些特征在「引用来源与溯源」这一环带来什么约束
煤矿生产数据的混合结构要求溯源环节同时匹配结构化字段与非结构化附件内容，避免仅检索文本而忽略带单位的量化指标。不同更新频率的数据需要配置差异化的同步触发规则，实时数据需增量同步，定期数据需定时全量更新。带单位的字段要求检索时保留单位匹配逻辑，防止将掘进进尺与瓦斯浓度混淆。非结构化附件需先完成OCR识别并关联原始文件路径，确保溯源时可直接调取原始扫描件。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 煤矿申报材料单篇最长约1000字符，匹配token与字符比例适配 |
| 单次召回上限 | 前6条 | 煤矿案卷审核的佐证材料通常不超过5份，保留合理冗余量 |
| `responseData` | 返回原始文档ID与存储路径 | 需溯源到具体的班组日报或安监台账条目，匹配公共服务领域审计要求 |
| `detail` | 开启结构化字段提取 | 煤矿数据含瓦斯浓度、进尺等带单位字段，需保留字段匹配精度 |
| 溯源日志存储周期 | 90天 | 符合国央企与公共服务领域对审核记录的留存规范 |

## 容易做错的三处
- 现象：知识库搜索节点选择变量应用时，引用变量下拉框为空。原因：未提前将煤矿生产专属的台账、报表知识库配置为可绑定的变量组，或变量组未正确关联对应数据源。
- 现象：大模型输出伪造的引用ID，未匹配实际检索到的文档。原因：未开启`responseData`的原始文档ID校验逻辑，或知识库索引未正确关联煤矿台账的唯一编号字段。
- 现象：输出内容中保留「引用标记：［1］」字样。原因：未关闭FastGPT原生的引用标记前缀输出，或未配置自定义的引用展示规则。

## 怎么确认配好了
- 提交一条包含掘进进尺参数的审核查询，查看返回结果是否关联了对应班组日报的文档ID。
- 进入FastGPT知识库管理界面，确认动态绑定的变量组包含煤矿生产台账、安监报表两类专属数据源。
- 触发一次完整的案卷审核流程，查看系统日志中是否记录了检索到的文档路径与引用ID。
- 检查大模型输出内容，确认引用标记仅以正文标注形式展示，未包含「引用标记：」前缀。
