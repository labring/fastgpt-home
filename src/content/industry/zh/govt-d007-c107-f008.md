# 煤矿生产的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
煤矿生产的申报材料与案卷审核数据主要来自矿井调度系统、安监部门报送端口及内部归档存储。更新节奏随申报周期或案卷归档节点变动，无固定高频更新。文档格式包含docx申报表格、pdf安监报告、excel生产台账等混合类型，单份文件页数跨度大，从几页的临时申报到几十页的年度案卷均有出现。文档包含矿井编号、开采层位、瓦斯监测数据、审批文号等结构化字段，单位涵盖吨、立方米、ppm、工作日等专业计量标准。

## 这些特征在「文档解析与分块」这一环带来什么约束
混合格式的文档要求解析工具同时适配文本型和扫描型文件，否则会丢失部分内容。单份文件页数跨度大，分块规则需兼顾短文件的完整性与长文件的可读性，避免分块过碎或过长。结构化字段与专业计量单位的存在，要求分块时保留字段关联关系，不能单纯按字符长度拆分，否则会破坏数据逻辑。不定期的更新与大型案卷的存在，要求解析环节具备灵活的超时处理能力与适配大文件的配置空间。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 1000–1500 字符 | 煤矿申报材料单页内容较多，避免分块过碎丢失上下文关联 |
| `chunkSplitter` | 按段落+标题拆分 | 申报材料有明确的章节标题与逻辑段落，适配专业文档的结构分块 |
| `customPdfParse` | 启用OCR模式 | 覆盖扫描件形式的案卷文件，提取图片内嵌的文字与数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 秒 | 适配大型案卷的解析耗时，避免因超时导致解析失败 |
| `chunkSettingMode` | 手动配置 | 针对煤矿专用文档结构调整分块规则，适配专业字段与单位的逻辑关联 |

## 容易做错的三处
- 现象：上传docx或excel文件后，检索结果准确率偏低，原因：未针对结构化字段配置元数据提取，分块时破坏了字段与对应数据的关联关系
- 现象：上传扫描件pdf案卷后，无法提取图片内的文字内容，原因：未启用`customPdfParse`的OCR模式，仅使用基础文本解析逻辑
- 现象：解析单份50页以上的年度案卷时，触发解析超时错误，原因：`PARSE_FILE_TIMEOUT_SECONDS`的设置值低于实际解析所需时长

## 怎么确认配好了
- 上传单份典型的月度申报材料，查看解析后的分块结果，确认分块符合文档的章节与段落结构
- 上传一份扫描件形式的井下工况报告pdf，检查解析结果是否包含图片内的文字内容
- 上传单份100页以上的年度案卷，确认解析过程未触发超时报错
- 检索包含矿井编号或审批文号的查询词，确认返回结果附带对应字段的元数据信息
