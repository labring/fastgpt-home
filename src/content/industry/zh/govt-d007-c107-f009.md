# 煤矿生产的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
煤矿生产的申报材料与案卷审核数据主要来源于煤矿安全监察系统、矿井生产调度台账、矿井地质档案库及行政审批申报单。数据更新按单次审批批次进行，单次审批涉及的材料更新周期为1至7天。单篇材料包含矿井编号、开采范围坐标、安全检测报告编号、审批文号、作业人员资质编号等结构化字段，单位涉及米、吨、立方米、小时、人等专业计量标准，部分案卷还包含扫描版的矿井布置图、安全检测原始记录等非结构化内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
单篇材料长度可达数万字符，要求模型接入时配置足够大的上下文窗口，避免截断核心审核依据。专业字段与单位较多，要求模型能准确识别并处理煤矿行业专属术语，否则会导致审核结论偏差。部分案卷包含扫描件格式的非结构化内容，要求模型支持视觉理解能力，才能完成图纸、手写记录的信息提取。数据更新频率不固定，要求向量库同步策略可灵活调整，适配不同批次的材料更新节奏。审核过程需严谨可追溯，要求模型输出的结论能关联到原始材料片段，避免模糊判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 煤矿申报材料单篇可达数万字符，需容纳完整上下文以完成全量审核 |
| `maxTokens` | 2000–3000 token | 案卷审核需输出详细校验结果，避免因输出长度限制截断关键结论 |
| `quoteMaxToken` | 4000 字符 | 需引用完整的检测报告、图纸标注等片段作为审核依据，保障引用内容完整 |
| `vision` | 开启 | 部分案卷包含扫描版矿井布置图、安全检测记录，需识别视觉内容完成审核 |
| `temperature` | 0.1–0.3 | 审核需严谨，避免生成偏离事实的结论，降低随机输出概率 |
| `AIPROXY_API_ENDPOINT` | 本地部署的代理转发地址 | FastGPT v4.17.0 本地部署时，需通过代理转发外部模型调用请求 |
| `AIPROXY_API_TOKEN` | 代理分配的鉴权密钥 | 保障模型接口调用的安全性，避免未授权访问 |

## 容易做错的三处
- 现象：本地部署FastGPT v4.17.0后新增模型，测试时返回403 status code (no body)。原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致接口鉴权失败或请求地址无效。
- 现象：模型输出的专业单位识别错误，例如将“矿井标高+120米”识别为“120吨”。原因：未针对煤矿专业场景调整模型上下文配置，未补充行业专属术语提示，导致模型对专业字段的识别精度不足。
- 现象：工作流中对话模型的提示词无法识别空格分隔的字段，例如“矿井编号 123”无法被正确提取为独立字段。原因：提示词未明确指定空格作为字段分隔规则，或`temperature`设置过高导致模型输出格式混乱。

## 怎么确认配好了
- 上传单篇长度约10000字符的煤矿开采方案文档，测试模型输出未出现上下文截断相关提示。
- 上传包含矿井布置图纸的扫描件案卷，测试模型能正确识别图纸中的标注信息并关联到审核结论。
- 调用模型接口，确认返回状态码为200，且响应内容包含完整的审核结果。
- 输入包含专业单位的测试文本，例如“日产量 500吨”，测试模型能准确提取数值与单位信息。
