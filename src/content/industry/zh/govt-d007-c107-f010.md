# 煤矿生产的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
煤矿生产的申报材料与案卷审核数据主要来源于矿井安监备案文档、生产调度台账、采煤掘进验收案卷、瓦斯与顶板巡检记录。数据更新节奏随业务节点变动：日常巡检记录每日更新，单工作面验收案卷在项目完成后即时归档，年度或季度申报材料集中批量更新。文档结构包含固定字段：矿井编号、作业面ID、申报日期、审核状态、隐患整改闭环记录，数据单位多采用吨、立方米、小时等煤矿行业通用计量标准。

## 这些特征在「知识库检索与召回」这一环带来什么约束
煤矿生产的申报与审核数据来源分散，包含结构化台账、半结构化案卷与非结构化巡检记录，导致检索时需兼容多格式数据的字段对齐逻辑。不同类型数据更新节奏差异大，日常巡检数据需高频增量同步，批量申报材料需定期全量刷新，对知识库的更新触发机制提出约束。单份案卷文档长度跨度大，短则数百字符的巡检记录，长则数千字符的验收报告，要求检索分块策略适配不同长度的文档片段。矿井与作业面的层级关联要求检索时需按业务维度过滤召回结果，避免跨矿井的无效数据返回。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写，适配煤矿生产场景的知识库检索与召回需求。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 适配煤矿案卷中专业术语的语义相似度匹配，避免过低阈值引入无关巡检记录，过高阈值遗漏合规申报材料 |
| `limit` | 前12条 | 覆盖单份申报材料涉及的多作业面数据，同时控制上下文长度不超过模型输入限制 |
| `usingReRank` | 开启 | 对召回的案卷片段进行二次排序，过滤掉与审核主题关联度低的隐患整改记录 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于煤矿专业术语扩展检索词，比如将“瓦斯巡检”扩展为“瓦斯浓度监测记录”，提升召回广度 |
| `collectionIds` | 按目标矿井维度指定 | 限定检索范围为目标矿井的知识库集合，避免跨矿井的无效数据干扰审核流程 |
| `searchMode` | 混合检索 | 结合关键词匹配与语义检索，适配结构化字段与非结构化文本的混合数据 |

## 容易做错的三处
- 现象：添加知识库后调用问答接口返回异常，或界面提示知识库配置错误，但单独测试知识库检索可返回正确结果。原因：未正确配置知识库与主模型的上下文拼接规则，导致超长案卷片段超出模型输入上限。
- 现象：切换向量模型后，界面进度条停滞无更新，且无法通过原有操作恢复到旧模型。原因：未清理旧模型生成的向量索引缓存，且未触发强制重建索引的流程。
- 现象：检索结果遗漏部分目标文档，或包含大量与当前审核矿井无关的案卷数据。原因：未配置`collectionIds`按矿井维度过滤检索范围，或`similarity`阈值设置过高，遗漏低相似度但符合审核要求的文档。

## 怎么确认配好了
- 进入知识库检索测试页面，输入包含目标矿井编号的查询词，核对返回结果仅包含目标矿井的相关文档，且结果数量符合`limit`配置的取值。
- 切换向量模型后，查看向量索引重建进度，确认在10分钟内完成（按实测标定），且可通过界面切换回原模型。
- 调用问答接口输入专业查询词，比如“本工作面2024年隐患整改情况”，确认返回结果包含知识库召回的案卷片段，且无跨矿井的无效数据。
- 开启`usingReRank`后，核对检索结果的排序逻辑，确认与审核主题关联度高的文档排在前列。
