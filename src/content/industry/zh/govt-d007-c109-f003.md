# 电网企业的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
电网企业的申报材料与案卷审核数据，主要来源于营销业务应用系统、输电运检管理系统、安监质量管控系统。数据更新随项目流程触发，申报材料在提交时更新，案卷在审核办结后归档。单份文档包含申报主体资质、项目技术参数、现场勘查记录、审核意见等字段，字段多涉及专业单位，如电压等级（kV）、设备容量（kVA）、审批工作日等，文档长度跨度较大，短则数百字符，长则可达数万字符。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
电网申报与案卷数据的专业字段多、格式固定，要求提示词需明确限定字段匹配与格式输出规则，避免生成不符合审核规范的内容。多轮对话需绑定唯一案卷标识，否则易出现上下文串档，导致审核结果关联错误项目。数据长度跨度大，长案卷内容易超出对话上下文上限，需针对性配置上下文截断策略。实时提交的申报材料需同步至知识库，否则多轮对话将基于旧数据给出审核意见。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定案卷唯一标识作为会话ID | 区分不同申报项目的对话上下文，避免串档关联错误案卷 |
| `messages` | 按会话历史拼接不超过8000 token | 适配电网案卷文档长度跨度大的特征，避免上下文溢出 |
| `variables` | 注入项目编号、申报主体统一社会信用代码等固定字段 | 多轮对话中绑定专属案卷数据，确保审核依据准确 |
| 提示词模板 | 明确要求基于电网申报规范、案卷归档要求作答，限定输出为结构化审核意见 | 匹配电网审核的固定格式与专业要求 |
| 会话超时时间 | 600 秒 | 适配多轮材料核对的耗时，避免中途中断会话 |
| 上下文截断规则 | 保留最近20轮对话与核心案卷字段 | 过滤冗余信息，聚焦当前审核环节的有效数据 |

## 容易做错的三处
- 现象：会话执行到中间步骤直接结束，无报错提示。原因：未绑定`chatId`导致上下文丢失，工作流无法关联后续案卷数据。
- 现象：对话超时，界面显示会话超时提示。原因：会话超时时间设置过短，未适配电网案卷审核多轮核对的耗时。
- 现象：多轮对话中后续提问未参考之前的审核意见，提示词仅单次生效。原因：未正确配置`messages`参数，未保留历史对话上下文，导致后续会话无法关联前期审核结论。

## 怎么确认配好了
- 导入一份真实电网申报案卷，发起首轮提问，核对注入的`variables`是否包含案卷专属字段。
- 发起多轮连续提问，检查会话是否保留历史对话内容，未出现上下文丢失或串档情况。
- 模拟长会话流程，验证会话超时时间是否适配审核所需的操作时长，未出现中途中断。
- 调整提示词模板，检查输出内容是否符合电网审核的固定格式与专业要求。
