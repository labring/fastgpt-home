# 电网企业的申报材料与案卷审核：文档解析与分块

## 这个品类的数据长什么样
电网企业申报材料与案卷审核的数据来源为项目申报系统、档案管理系统，更新节奏随项目进度分批上传，集中审核期批量更新。文档类型包含PDF格式的工程可研报告、Word格式的申报书、Javadoc生成的HTML接口文档，以及部分被修改后缀的文本文件。文档多带有统一格式的页眉页脚，接口文档包含固定的类名、方法名、参数列表，核心字段包括项目编码、电压等级、设备型号，单位涉及kV、MW、A等电力专业单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
文档类型混杂且包含结构化与非结构化内容，要求解析模块适配多种格式，尤其是Javadoc HTML和改后缀的文本文件。部分文档带有固定页眉页脚，会导致重复分块或冗余内容混入，需在解析阶段去除。接口文档的结构化语法要求分块规则保留代码语义单元，避免割裂专业表述。批量上传的文件大小差异显著，从数KB的接口文档到数百MB的可研报告，需适配不同的上传与解析阈值。

## 配置怎么定
以下配置项均基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 电网申报材料多为工程类长段落文档，该分块长度适配专业技术内容的语义单元，避免单块过长影响检索精度 |
| `chunkSplitter` | 按语义分块 | 电网文档包含大量电力专业术语与结构化参数，按语义拆分可保留内容完整性，避免割裂专业表述 |
| `customPdfParse` | 启用 | 电网PDF文档多带有统一格式的页眉页脚，启用自定义解析可去除冗余标识，提升分块准确性 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 电网大型可研报告可达数百MB，需适配大文件上传需求，按实测标定上限 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型PDF与HTML接口文档解析耗时较长，预留充足时间完成解析流程 |
| `chunkSettingMode` | 手动配置 | 电网文档类型多样，手动配置可针对不同文档类型调整分块规则，适配结构化与非结构化内容 |

## 容易做错的三处
- 上传改后缀为TXT的Java接口文件后，解析结果为空。未启用适配代码文本的解析规则，系统默认按纯文本解析时无法识别Java代码的语法结构，导致无法提取有效内容。
- 使用chunk模式调用pushdata api上传后，界面长期显示索引中。未配置合理的`PARSE_FILE_TIMEOUT_SECONDS`，或上传文件超过`UPLOAD_FILE_MAX_SIZE`，导致解析流程超时未完成，索引任务停滞。
- 上传Javadoc生成的HTML接口文档后，无有效解析内容。未启用针对HTML文档的结构化解析，系统默认仅提取纯文本内容，忽略了HTML中嵌入的代码块和结构化参数列表，导致解析结果为空。

## 怎么确认配好了
- 上传单份典型的电网工程PDF申报材料，查看解析后的分块内容，确认页眉页脚已被去除，技术段落被正确拆分。
- 上传一份Javadoc生成的HTML接口文档，验证解析结果中包含类名、方法名和参数列表等结构化内容，无空字段。
- 上传一份改后缀为TXT的Java接口文件，确认解析结果中提取了代码中的核心方法和参数信息，无完全空的解析结果。
- 上传一份接近`UPLOAD_FILE_MAX_SIZE`上限的文件，确认上传和解析流程未触发超时或报错。
