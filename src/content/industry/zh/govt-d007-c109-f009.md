# 电网企业的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
数据来源于电网企业的项目申报系统、营销业务应用平台及案卷归档模块。更新节奏随项目进度或月度归档周期推进，单批次上传材料数量较多。文档分为申报材料与案卷两类：申报材料包含项目申请表、资质证明扫描件、现场勘查记录、用电方案；案卷包含审核流程单、整改通知书、验收报告。字段涵盖项目编号、电压等级、用电容量、审批节点、整改时限等，单位涉及千伏、千瓦时、工作日等。

## 这些特征在「模型接入与配置」这一环带来什么约束
批量多份的文档结构要求配置需支持批量处理，避免单份材料处理超时。扫描件与结构化字段并存的文档，要求模型需具备视觉解析能力，同时能准确识别电网专属字段与单位。多批次归档的数据更新，要求配置的上下文长度可容纳完整单份文档内容，避免关键信息截断。国央企的数据安全要求，需为模型调用配置专属密钥与API端点，隔离不同业务场景的数据访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 申报材料与案卷中包含大量扫描版资质证明、勘查照片，需视觉模型解析非文本内容 |
| `maxContext` | 8000–12000 token | 单份案卷或申报材料的文本长度可达数千字符，需容纳完整上下文以保证审核完整性 |
| `maxTokens` | 2000–3000 token | 审核结果需涵盖多维度判断，输出长度需满足详细反馈要求 |
| `temperature` | 0.1–0.3 | 审核需严格遵循电网业务规范，需降低随机性以保证判断一致性 |
| `AIPROXY_API_TOKEN` | 绑定电网专属密钥 | 符合国央企数据安全要求，隔离不同业务场景的模型调用 |
| `toolChoice` | 自动 | 自动调用工具处理结构化字段提取，减少人工干预并提升字段识别准确率 |

## 容易做错的三处
- 现象：在FastGPT v4.17.0中配置模型后检测失败，界面提示“模型不可用”或返回接口错误。原因：未正确填写`AIPROXY_API_TOKEN`，或使用了与当前部署环境不匹配的`AIPROXY_API_ENDPOINT`。
- 现象：启用`vision`功能后无法解析申报材料中的扫描图纸或照片。原因：未在模型接入配置中开启视觉支持，或上传的文件格式不符合模型支持的类型。
- 现象：配置多个同名不同密钥的模型时，调用时出现密钥匹配混乱。原因：未为每个模型配置独立的标识参数，导致系统无法准确区分不同密钥的模型实例。

## 怎么确认配好了
- 上传单份包含扫描件的申报材料，触发模型审核，查看是否能正确提取扫描件中的资质信息与结构化字段。
- 调用模型接口，传入测试用的案卷数据，检查返回结果是否包含符合电网规范的审核判断与字段提取内容。
- 配置多个不同密钥的模型，分别发起调用，确认每次调用都能匹配到对应的模型实例，无密钥混淆情况。
- 查看模型调用日志，确认`maxContext`与`maxTokens`的参数被正确应用，未出现上下文截断或输出超限的提示。
