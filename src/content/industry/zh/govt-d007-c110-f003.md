# 矿山采选的申报材料与案卷审核：多轮对话与提示词
本文适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
矿山采选的申报材料与案卷审核数据主要来自自然资源部门、应急管理部门要求提交的采矿权申请、选矿生产备案、安全合规案卷等官方文档，以及企业内部生产台账。数据更新节奏随单次申报流程或年度合规核验推进，单次申报周期内完成更新。文档多为多页PDF或结构化表格，核心字段包含采矿权编号、选矿处理量、安全排查记录编号，单位多为千吨、吨/日、批次。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
矿山采选申报材料与案卷的长文档、多字段专业属性，要求多轮对话上下文需覆盖至少单批次申报的完整材料片段，避免关键专业参数丢失。专业单位与专属字段的对应关系，要求提示词需明确绑定采矿权编号、选矿处理量等字段的专属含义，防止参数混淆。单次申报周期内的数据更新节奏，要求对话上下文需保留当前批次的提交节点信息，确保审核环节可关联历史案卷的批次记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 前8–12条对话历史 | 矿山采选单批次审核需关联3-5份案卷，8-12条可覆盖申报说明、案卷补充、审核意见的完整交互，避免上下文溢出导致专业参数丢失。 |
| `chatId` | 绑定当前申报批次ID | 确保多轮对话的上下文仅关联对应批次的案卷，符合矿山采选申报的批次管理规则，防止跨批次数据混淆，影响审核准确性。 |
| 最大上下文 | 8000–12000 字符 | 单份矿山申报案卷的结构化内容约3000-5000字符，该范围可覆盖2份完整案卷加申报说明的内容，适配长文档审核需求。 |
| `variables` | 绑定采矿权编号、选矿处理量字段 | 将企业专属字段作为全局变量传入提示词，确保审核对话中可精准匹配对应采矿权的历史案卷数据，避免字段混淆。 |
| 提示词模板 | 按申报批次分类的审核校验规则 | 矿山采选申报需符合采矿权、选矿流程的专属合规要求，模板需绑定专业字段的校验逻辑，确保审核结果符合行业规范。 |

## 容易做错的三处
- 现象：工作流中设置聊天记录条数为0，多轮对话无法关联历史审核意见。原因：未通过`messages`参数传入历史对话上下文，仅使用当前单次提问的内容，无法关联之前的案卷补充说明。
- 现象：调用接口后返回的审核结果未匹配当前采矿权编号。原因：未通过`variables`绑定专属字段，提示词无法精准定位对应批次的申报材料。
- 现象：文本内容提取节点在工作流中未获取到完整案卷内容。原因：未设置足够的上下文长度，仅提取了前几页的申报摘要，遗漏了选矿处理量等核心参数。

## 怎么确认配好了
- 发起包含历史审核意见的多轮提问，核对回复是否关联了之前提到的案卷编号。
- 查看接口返回的`messages`参数日志，确认传入的对话历史条数符合配置的取值范围。
- 测试绑定专属字段的提问，核对回复是否精准匹配采矿权编号对应的申报材料。
- 检查工作流中的上下文配置，确认未出现上下文长度超出预设范围的提示。
