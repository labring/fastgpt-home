# 矿山采选的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
矿山采选的申报材料与案卷审核数据，主要来源于矿山企业提交的采矿权延续申请、选矿流程检测报告、安监部门留存的现场检查案卷。数据更新节奏随项目流程推进：立项申报阶段集中更新完整材料，日常年检或整改阶段按需更新局部内容。文档结构包含结构化申请表单、审批意见台账，以及非结构化的勘探图纸、矿石品位检测报告。字段包含采矿权编号、开采量、选矿回收率等，单位多采用吨、克/吨等矿业专业单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
结构化与非结构化文档混合的特征，要求模型同时支持文本解析与视觉内容识别，需开启对应视觉配置项。固定格式的申报材料与专业字段单位，要求模型需适配固定抽取规则与专业术语识别，需限制生成的随机性以保证审核严谨性。集中更新的批量数据场景，要求配置足够的上下文窗口与输出长度限制，避免单次处理超出模型能力范围。日常审核的流程化需求，要求模型可自动调用工具完成格式校验与数据抽取，适配多环节的审核任务。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 案卷中包含勘探图纸、现场照片等视觉材料，需模型解析视觉内容完成审核 |
| `maxContext` | 8000–12000 token | 单份申报材料常包含多页报告与完整案卷，适配长上下文的完整文档解析需求 |
| `maxTokens` | 2000–3000 token | 审核结果需输出结构化审批意见，控制输出长度避免冗余内容 |
| `quoteMaxToken` | 1500–2000 token | 需引用案卷中的检测数据、许可条款作为审核依据，限制引用内容的长度范围 |
| `temperature` | 0.1–0.3 | 审核需保持严谨一致，降低生成随机性避免主观判断偏差 |
| `AIPROXY_API_ENDPOINT` | 填写接入模型的官方服务端点 | 完成模型的身份验证与请求路由，保证调用链路正常 |

## 容易做错的三处
- 现象：调用模型后返回405状态码。原因：未正确配置`AIPROXY_API_ENDPOINT`的请求格式，或端点未开放对应接口的调用权限。
- 现象：MCP辅助模型执行任务的耗时超出预期。原因：未限制`maxTokens`取值或`temperature`设置过高，导致模型生成冗余内容延长思考时间。
- 现象：文件提交后长期显示“索引中”状态。原因：未匹配模型的上下文窗口限制，或`maxContext`配置超出模型支持的最大长度，导致索引流程阻塞。

## 怎么确认配好了
- 发起单份标准申报材料的测试请求，检查返回结果包含预设的审批字段与对应引用内容。
- 查看FastGPT v4.17.0的模型调用日志，确认无`AIPROXY_API_TOKEN`验证失败或405类报错。
- 提交包含勘探图纸的测试案卷，检查模型是否能正确识别图纸中的标注信息并输出对应审核意见。
- 调整`temperature`参数至不同区间，对比两次审核结果，确认结果稳定性符合审核要求。
