# 粮食储备的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
粮食储备的申报材料与案卷审核数据，主要来源于基层粮库的轮换申报单、年度储备粮检查案卷、政策性收储凭证三类。数据更新节奏随粮库轮换计划与年度检查周期变动，无固定全量更新窗口，增量更新多为单批次申报文件或单卷归档案卷。文档结构包含结构化字段与非结构化文本两类：结构化字段包含仓号（六位数字编码）、粮食品种（小麦/稻谷/玉米）、存储量（单位为吨）、申报日期；非结构化文本为案卷扫描件经OCR识别后的内容，存在部分格式错乱的字符。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化字段与非结构化文本混合的特征，要求检索同时支持字段精准匹配与语义召回，避免仅依赖单一检索模式导致的漏检或误检。无固定全量更新窗口的特性，要求知识库支持按需增量同步，不宜频繁触发全量索引重建，以免占用过多计算资源。文档中存在格式错乱的OCR文本，要求检索环节具备结果重排能力，过滤语义不相关的召回结果。存储量单位固定为吨，需保证检索时的单位匹配，避免因单位不统一导致的无效召回。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.72–0.80` | 粮食储备申报材料有固定格式，该阈值可过滤无关的日常仓务记录，同时保留格式匹配的有效申报内容 |
| `limit` | `前8–12条` | 单份申报材料涉及的仓号、粮食品种数量通常不超过10个，召回过多内容会超出上下文窗口 |
| `searchMode` | 混合检索 | 兼顾结构化字段匹配与非结构化OCR文本的语义召回，适配本品类混合格式的数据特征 |
| `usingReRank` | 开启 | 案卷OCR文本存在格式错乱，重排可过滤语义不相关的召回结果，提升检索精准度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 申报材料的字段名称固定，扩展查询可补充同义词匹配，例如将“轮换量”关联至“出库量” |
| `collectionIds` | 绑定粮食储备专属数据集ID | 限定检索范围仅覆盖本品类的知识库内容，避免混入其他仓储品类的数据 |

## 容易做错的三处
- 现象：上传申报材料的PDF或CSV时出现`fail to create post presigned url`报错。原因：未正确配置FastGPT的S3存储访问凭证，或未绑定对应数据集的存储路径。
- 现象：检索结果包含非粮食储备的仓储数据，无法精准召回目标内容。原因：未设置`collectionIds`参数，或绑定了错误的数据集ID。
- 现象：本地部署场景下勾选增强PDF解析后，无法正常解析粮食储备的仓单扫描件。原因：未确认minerU服务已正常启动并在FastGPT后台配置关联，或未开启`usingReRank`适配OCR后的乱码文本。

## 怎么确认配好了
- 上传一份测试用的粮食储备申报CSV，检查是否能正常完成上传，无存储相关报错。
- 输入测试查询“2024年第三季度小麦轮换申报材料”，检查召回结果仅包含绑定数据集内的内容。
- 开启`usingReRank`后，输入包含仓号乱码的查询，检查召回结果的语义相关性是否提升。
- 查看知识库后台的数据集同步日志，确认增量更新的频率符合粮库申报与归档的实际节奏。
