# 船舶制造的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
船舶制造的申报材料与案卷审核数据，主要来源于船舶建造各环节的报审文件、船级社检验案卷、生产工艺文档及物料采购记录。数据按建造节点阶段性更新，覆盖分段建造、下水前报审、试航验收等核心环节。单份案卷文档包含船舶识别号（IMO号）、建造批次编号、船型参数、报审日期、审核意见等字段，部分附件文档如工艺规程、检验报告长度可达数万字符，单位涉及载重吨、船长米数、建造周期天数等专属标识。

## 这些特征在「引用来源与溯源」这一环带来什么约束
船舶制造的案卷数据按建造节点更新，且包含专属的船舶识别号与批次编号，要求溯源时必须精准关联对应建造环节的材料，避免跨批次混淆。单份文档长度差异大，长文档的token占用量远超通用场景，需严格控制上下文长度避免溢出。字段中的专属参数如IMO号、载重吨，需作为检索与溯源的核心匹配项，否则无法准确定位原始案卷。阶段性更新的特性也要求知识库同步需与建造节点绑定，确保引用的始终是当前报审环节的有效材料。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 覆盖单批次报审的多份关联案卷，避免截断核心审核内容 |
| `quoteMaxToken` | 15000–20000 token 按实测标定 | 适配船舶案卷长文档的token占用，确保完整展示审核意见与工艺参数 |
| `responseData` | 包含船舶识别号、报审环节、审核结论 | 匹配案卷核心字段，为溯源提供明确的定位依据 |
| 单次搜索上限 | 前8–12条检索结果 | 对应单批次报审的关联材料数量，避免无关信息干扰AI生成 |
| `detail` | 开启完整内容展示 | 确保原始案卷的审核细节可被完整追溯 |

## 容易做错的三处
- 现象：界面展示的模型上下文条数与实际发送到AI的引用条数不一致。原因：未正确配置`quoteMaxToken`与知识库分块长度的匹配关系，导致长文档块被截断后未被正确计入上下文统计。
- 现象：设置了引用上限后，超过上限长度的知识库块仍被引用。原因：未按船舶案卷的建造批次字段进行检索过滤，跨批次的无关材料被召回并计入引用统计。
- 现象：HTTP请求传递的检索结果无法被AI正确关联溯源。原因：未在`responseData`配置中包含船舶识别号、报审环节等核心标识字段，导致溯源信息缺失。

## 怎么确认配好了
- 查看知识库检索预览界面，确认返回结果包含船舶识别号、报审环节等核心溯源字段。
- 触发AI对话并打开上下文弹窗，检查展示的引用来源是否与实际案卷编号一一对应。
- 调整`quoteMaxToken`的取值，验证检索结果的截断逻辑是否符合单案卷的长度特征。
- 模拟工作流传递检索结果，确认HTTP请求携带的溯源数据格式符合AI对话的接收要求。
