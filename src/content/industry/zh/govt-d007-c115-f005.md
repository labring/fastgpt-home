# 轨道交通装备的申报材料与案卷审核：工具调用与插件
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
轨道交通装备的申报材料与案卷数据主要来源于企业研发归档文档、生产质检台账、合规申报系统。数据更新节奏为单次申报周期内随提交进度更新，单份案卷包含转向架、牵引系统、制动装置等子模块的申报文档。字段包含装备型号编号、质检报告编号、合规校验项清单、核心部件尺寸（单位毫米）、生产批次号、材料力学性能参数（单位兆帕），单份完整案卷的文档总字符量波动范围较大。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于单份案卷包含多个独立子模块的文档，工具调用需支持按指定模块定向拉取数据，避免全量拉取导致的上下文溢出。由于字段包含带特定单位的参数，工具需内置单位校验逻辑，自动识别并转换不符合要求的单位表述。由于数据来源于合规申报系统，工具调用需携带合规的身份校验参数，确保仅可访问授权范围内的案卷数据。由于数据更新仅在单次申报周期内触发，工具调用的缓存有效期需匹配申报周期长度，避免调用过期数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | auto | 适配需要动态选择申报材料相关工具的场景 |
| 上下文窗口上限 | 8000–12000 token | 匹配单份完整轨道交通装备案卷的字符量 |
| 缓存有效期 | 7–14 天 | 匹配单次申报周期的更新节奏 |
| 单位校验开关 | 开启 | 适配包含毫米、兆帕等特定单位的字段需求 |
| `functionCall` | 强制必填参数校验 | 确保工具调用时携带型号编号、质检报告编号等核心字段 |
| 模块定向调用开关 | 按子模块开启 | 适配案卷分转向架、牵引系统等子模块的文档结构 |

## 容易做错的三处
- 现象：工具调用完成后，对话界面同时展示工具调用的参数与返回结果，与仅需展示AI审核结论的需求不符。原因：未配置隐藏工具调用日志的参数，或未开启仅返回AI对话结果的开关。
- 现象：调用接口获取流数据时，分段返回的内容出现乱码或字段缺失，无法完整解析工具调用结果。原因：未按照接口规范处理流数据的分段返回，未正确拼接完整的工具调用响应。
- 现象：上传轨道交通装备的申报PDF文件后，接口返回400 Bad Request，提示无法识别文件内容。原因：未配置针对轨道交通装备申报文档的上传白名单，或未正确设置文件上传的参数格式。

## 怎么确认配好了
- 发起一次针对指定轨道交通装备型号的工具调用请求，检查返回的AI对话结果中是否仅包含审核结论，无工具调用的参数或返回日志。
- 调用配置了`toolChoice`为auto的接口，查看返回的流数据是否完整拼接，无字段缺失或格式异常。
- 上传一份轨道交通装备的申报PDF文件，确认接口返回的文件解析结果包含型号编号、质检报告编号等核心字段。
- 查看缓存有效期配置，确认其匹配当前申报周期的长度，无过期数据被调用的情况。
