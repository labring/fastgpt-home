# 通信工程建设的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
通信工程建设的申报材料与案卷审核数据，来源为项目立项、审批、施工、验收全流程的申报文档与归档案卷。更新节奏随项目推进阶段性更新，立项阶段提交可研、预算材料，施工阶段补充进度报告，验收阶段归档最终核验材料。文档包含项目编号、建设范围、预算金额、审批文号、施工资质证明等结构化字段，部分文档附带工程点位坐标、线缆路由图等非结构化附件，字段单位包含万元、基站数量、公里等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
通信工程建设的申报材料与案卷存在多阶段更新、字段结构化与非结构化混合的特征，对引用溯源环节带来多重约束。首先，阶段性更新的材料需关联对应项目周期的版本，避免引用过期的立项材料用于验收审核；其次，结构化字段如项目编号、审批文号需作为溯源的核心标识，确保引用指向具体审批节点的原始材料；最后，非结构化的工程图纸附件需通过文本化处理后关联对应结构化元数据，避免溯源时仅匹配文本内容而丢失图纸类原始依据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大引用token数 | 800–1200 token | 匹配单份申报材料的平均文本长度，适配FastGPT v4.17.0版本的文本截断规则，避免截断核心审批依据 |
| 引用数据源范围 | 仅当前项目关联的知识库 | 限定溯源范围至对应工程案卷，避免跨项目引用无关材料 |
| `quoteMaxToken` | 600–1000 token | 适配案卷审核时的单段文本召回长度，确保覆盖完整审批意见与预算明细 |
| `responseData` | 开启结构化元数据返回 | 提取项目编号、审批文号等核心标识，强化溯源准确性 |
| `detail` | 开启详细溯源展示 | 展示原始文档的具体段落或附件位置，提升审核可信度 |
| 单次召回结果数 | 前3–5条 | 匹配单项目申报材料的关联依据数量，避免过多冗余信息干扰审核 |

## 容易做错的三处
- 现象：检索结果显示引用了案卷材料，但生成的审核意见未包含知识库中的审批文号内容。原因：未开启`responseData`配置，未提取结构化元数据作为关联依据，导致生成内容无法匹配原始字段。
- 现象：仅文本类申报材料被召回，工程图纸附件的文本化内容未被引用。原因：未对非结构化附件进行文本预处理，或未配置关联元数据的召回规则，导致图纸类数据无法被正确识别。
- 现象：调用API传入工作流后，未关联指定项目的知识库，反而调用了全局知识库内容。原因：未在工作流参数中绑定对应项目的知识库标识，导致默认使用全局知识库范围。

## 怎么确认配好了
- 提交一份包含已知审批文号的测试问题，核对生成内容中是否包含该文号，且引用来源标注了对应案卷的项目编号。
- 上传一份工程图纸附件并进行文本化处理，发起相关检索，确认召回结果中包含该附件的文本内容。
- 在工作流配置中查看数据源绑定项，确认仅选中当前项目关联的知识库，未勾选全局知识库选项。
- 查看`detail`配置的返回结果，确认每条引用都标注了原始文档的具体段落或附件位置。
