# 通信铁塔与基础设施的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
通信铁塔与基础设施的申报材料与案卷审核数据，主要来自项目运维管理系统、审批流转台账、现场巡检归档文件。数据更新节奏随申报流程推进，单次申报周期内实时同步最新勘测、审批节点内容。文档结构包含结构化参数表、审批单PDF、现场勘测照片、权属证明扫描件，字段包含固定单位的数值项、唯一审批编号、审核意见文本，部分案卷包含多页拼接的材料包。

## 这些特征在「模型接入与配置」这一环带来什么约束
结构化参数带固定单位的特性，要求模型能准确识别并保留单位信息，需调整上下文匹配逻辑适配字段格式。多类型输入混合的场景，要求开启多模态处理配置，避免遗漏图片类材料的审核。实时更新的申报数据，要求配置足够大的上下文窗口，避免截断核心审批参数。多样的文档结构，要求配置项适配不同长度的材料拼接，防止单次请求超出模型处理上限。

## 配置怎么定
本配置适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配多页申报材料的拼接长度，避免截断核心审批参数与案卷内容 |
| `maxTokens` | 2000–3000 token | 覆盖完整的审核意见输出长度，满足结构化字段的解析与输出需求 |
| `vision` | 开启 | 适配现场勘测照片、权属证明扫描件的图片理解需求，识别照片中的巡检标记与参数 |
| `temperature` | 0.2–0.4 | 保持审核逻辑的严谨性，避免生成不符合行业规范的审核意见 |
| `AIPROXY_API_ENDPOINT` | 填写阿里通义千问专属接入地址 | 匹配官方API调用链路，保障请求的正常转发 |
| `AIPROXY_API_TOKEN` | 填入平台生成的专属密钥 | 完成身份验证，保障调用权限的合法性 |

## 容易做错的三处
- 调用渠道链接返回“undefined”is not valid json，原因是配置的`maxContext`超出绑定模型的上下文窗口上限，导致模型返回格式异常。
- 新建知识库时无法选择图片理解模型，原因是未开启`vision`配置项，且未部署对应多模态模型的依赖包。
- 本地部署后并发调用出现超时，原因是`AIPROXY_API_ENDPOINT`的并发配额未适配实际访问量，未配置合理的请求队列限制。

## 怎么确认配好了
- 上传一份包含铁塔参数、勘测照片的申报材料，检查模型是否能正确识别塔高、承载功率等带单位的字段。
- 发起一次批量案卷审核请求，检查返回结果是否为符合JSON格式的结构化审核意见。
- 查看系统监控面板，确认并发调用时无明显超时或格式报错。
- 验证`vision`参数开启后，模型是否能正确解析现场照片中的巡检标记与手写批注。
