# 金属材料加工的申报材料与案卷审核：向量模型与索引

## 这个品类的数据长什么样
金属材料加工的申报材料与案卷审核数据主要来源于钢铁企业的质检报告、加工工艺单、资质申报文件及内部审批案卷。数据更新以项目申报时的批量上传为主，日常审批环节会产生增量案卷。文档包含结构化字段与非结构化内容，结构化字段包括材料牌号、炉号、屈服强度、抗拉强度等，单位多为MPa、%；非结构化内容包含工艺说明、现场检验照片及审批节点记录。单份申报材料长度从数百字符到数十页的完整案卷不等。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化字段的精确匹配需求要求分块时不能切断关键参数，避免向量检索时丢失关联的参数信息。长文档案卷的存在要求向量模型需支持足够的token上限，防止截断核心工艺说明内容。批量与增量更新的场景要求索引系统支持批量向量化与增量同步，避免重复手动上传操作。多批次同牌号材料的申报容易产生相似数据，需要配置合理的相似度阈值区分不同批次，同时需支持去重机制避免重复索引条目。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配金属材料加工申报材料的字段长度，避免切断力学性能参数等关键结构化信息 |
| 重叠长度 | 100–150 字符 | 防止分块截断连续的工艺描述，确保向量检索时能关联完整的参数上下文 |
| 相似度阈值 | 0.72–0.80 | 区分同牌号不同批次的申报材料，避免将相似参数的不同批次误判为同一内容 |
| 单次搜索上限 | 前 8 条 | 适配案卷审核时需比对多份同类型申报材料的场景，覆盖常见的批量审核需求 |
| `maxToken` | 4096 token | 支持数十页长案卷的向量化，防止截断核心工艺说明内容 |
| `defaultToken` | 1024 token | 平衡单份短申报材料的向量化精度与计算资源消耗 |

## 容易做错的三处
- 现象：上传Excel格式的申报材料后，向量化结果中力学性能参数的单位丢失，索引匹配结果与预期不符。原因：未配置Excel表格的列映射规则，导致结构化字段被错误拆分，单位信息未被正确提取。
- 现象：单份申报材料在上传时显示分8段完成索引，一段时间后界面显示为13段且出现重复的向量条目。原因：未开启自动去重配置，且分块重叠长度设置过小，导致相邻分块的重叠部分被重复识别为独立内容。
- 现象：从FastGPT v4.17.0升级后，原可检索的旧案卷内容无法被命中。原因：升级后默认的向量模型参数发生变更，未重新对历史案卷进行批量向量化更新，导致新旧索引的向量空间不一致。

## 怎么确认配好了
- 上传一份标准的金属材料申报Excel文件，检查向量化后的分块数与预期一致，无重复条目。
- 提交包含多批次同牌号材料的案卷查询，确认检索结果的相似度符合预设阈值区间。
- 执行批量索引操作，验证所有上传的申报材料均完成向量化且状态显示正常。
- 修改`maxToken`参数后上传一份长文档案卷，确认关键工艺参数未被截断。
