# 金属材料加工的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
数据主要来自金属材料加工企业的生产台账、出厂质检报告、项目申报表单及监管案卷。更新节奏随生产批次或申报周期变动，单份文档长度跨度较大，短则数百字符的基础申报项，长则数万字符的完整质检与整改卷宗。文档字段包含批次编号、合金成分占比、屈服强度、断面收缩率、审批节点记录等，单位涉及MPa、%、吨、毫米等工业标准单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
金属材料加工的申报与案卷数据跨度较大的文档长度，要求模型接入时需适配不同长度的上下文输入，避免截断关键质检数据。专业工业字段与单位的存在，要求嵌入模型需支持工业文本语义理解，否则会出现字段匹配偏差。随生产批次变动的更新节奏，要求配置中需匹配数据更新的周期，避免索引与实时数据脱节。单份卷宗的多节点审批记录，要求召回环节需精准关联对应批次的关联文档，避免无关内容干扰审核结果。FastGPT v4.17.0版本的配置逻辑需适配这类多维度的数据特征。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配长卷宗的完整上下文输入，避免截断关键质检与审批数据 |
| `maxTokens` | 2000–3000 token | 控制单轮审核的输出长度，确保案卷结论清晰完整 |
| `quoteMaxToken` | 1500 字符 | 限制召回引用的文档长度，聚焦当前申报批次的核心材料内容 |
| `temperature` | 0.1–0.3 | 降低审核结果的随机性，确保专业判断的一致性 |
| `AIPROXY_API_ENDPOINT` | 企业内部部署的大模型服务地址 | 适配金属材料加工的专业文本处理需求，保障企业数据安全 |
| `AIPROXY_API_TOKEN` | 按企业权限生成的专属令牌 | 限制模型访问权限，避免非授权调用引发的数据泄露风险 |

## 容易做错的三处
- 现象：调用大模型时GPU功耗长期低于30%，CPU单核占用率持续100%。原因：未配置GPU加速的模型调用参数，默认使用CPU推理，导致资源分配失衡。
- 现象：审核结果中出现合金成分单位匹配错误，如将%写成ppm。原因：嵌入模型未针对工业专业字段做适配，无法正确识别金属材料的标准单位与数值关联。
- 现象：批量申报材料审核时出现部分文档未被召回的情况。原因：`maxContext`参数设置过小，截断了长卷宗的关键批次信息，导致模型无法关联完整申报数据。

## 怎么确认配好了
- 查看大模型服务的资源监控面板，确认GPU使用率稳定在合理区间，CPU占用率未出现单核满载的情况。
- 导入一份标准的金属材料质检卷宗，检查审核结果中是否正确识别了屈服强度、断面收缩率等专业字段的单位与数值。
- 提交多批次的申报材料，确认召回的引用文档均属于当前申报批次，无无关卷宗被纳入上下文。
- 查看FastGPT的日志面板，确认所有模型调用均使用了配置的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，无调用失败记录。
