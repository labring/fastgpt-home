# 钢铁冶炼的申报材料与案卷审核：引用来源与溯源

## 这个品类的数据长什么样
钢铁冶炼的申报材料与案卷审核数据，主要来源于炼钢、轧钢工序的生产台账、成分检测报告、项目立项申报书、环保备案案卷。数据按生产批次更新，单批次案卷包含10到20份附件，涵盖结构化数据库字段与非结构化文档。结构化字段包含炉号、冶炼时长、原料批次、检测项目名称、审批流转节点等，非结构化文档多为PDF或Excel格式的检测报告、审批签字页，数据更新节奏匹配生产周期，单批次完成后完成归档与同步。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据的结构化与非结构化混合特征，要求溯源时需同时匹配专属字段与文本片段，避免泛化检索结果偏离具体冶炼批次。按批次更新的特性，要求知识库同步需支持增量更新，防止旧批次数据混入当前审核的溯源范围。单份附件篇幅较长的特征，要求检索与引用环节需适配长文档解析，避免截断关键审批节点或检测数据。专属字段的存在，要求检索关键词需绑定炉号、冶炼时长等标识，提升溯源结果的精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 800–1200 字符 | 适配钢铁冶炼案卷单份附件的平均长度，避免截断关键检测与审批内容 |
| `quoteMaxToken` | 1200–1800 token | 确保引用的溯源内容完整覆盖生产台账与审批流转记录 |
| 单次召回结果数 | 前5条 | 覆盖同炉号相关的所有申报与案卷材料，避免关联信息遗漏 |
| `responseData` | 结构化元数据+非结构化片段 | 同时返回炉号、冶炼时长等专属字段与对应文本内容 |
| `detail` | 开启 | 展示引用内容的具体来源文档路径与页码，方便审核人员溯源 |
| 知识库同步触发规则 | 按生产批次触发 | 匹配钢铁冶炼数据按批次更新的节奏，避免冗余同步 |

## 容易做错的三处
- 现象：配置知识库检索节点时，引用全局变量datasetid后出现红色报错提示。原因：未在工作流的变量配置中为datasetid绑定对应钢铁冶炼专属知识库的ID，导致检索节点无法识别目标数据源。
- 现象：工作流中仅第一个提问触发知识库引用，后续提问无检索结果返回。原因：未配置上下文自动重置规则，前一次提问的引用上下文占用了全部可用token，导致后续提问无法加载新的检索内容。
- 现象：检索返回的引用内容未关联炉号、冶炼周期等专属字段，仅展示泛泛文本片段。原因：未将结构化字段作为检索关键词的绑定条件，仅基于非结构化文本进行检索，导致溯源结果无法匹配具体冶炼批次。

## 怎么确认配好了
- 发起一次针对特定炉号冶炼申报材料的提问，检查返回结果中是否包含`detail`参数对应的来源文档路径与页码。
- 查看知识库同步日志，确认仅当前批次的冶炼数据被同步至检索库，无旧批次冗余数据。
- 测试多轮连续提问，确认每一轮提问都能触发知识库检索并返回对应引用内容。
- 在FastGPT v4.17.0版本中，可通过工作流的变量调试面板验证全局变量datasetid的绑定状态，确认检索节点可正常引用该变量。
