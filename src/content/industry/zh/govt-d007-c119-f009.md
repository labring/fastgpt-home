# 钢铁冶炼的申报材料与案卷审核：模型接入与配置

## 这个品类的数据长什么样
钢铁冶炼的申报材料与案卷审核数据，来源为企业内部ERP系统、质检管理平台与合规归档系统。数据包含两类核心内容：一是结构化申报文件，如产能立项申请、原料采购台账、质检合格证明；二是长文本案卷材料，如生产过程日志、合规检查记录、验收归档文件。文档结构混合表格与段落文本，字段包含冶炼牌号、批次号、单炉产量、单位能耗、合规项编号等，单位涉及吨、千瓦时、立方米等工业标准单位，更新随单个申报项目或月度案卷归档周期完成。

## 这些特征在「模型接入与配置」这一环带来什么约束
钢铁冶炼场景的混合格式数据与专用字段特征，对模型接入配置提出明确约束。长文本生产日志与结构化表格的组合，可能超出通用模型的默认上下文长度，需调整上下文相关参数；工业专用单位与合规字段的精准识别需求，需降低模型输出的随机性；部分案卷包含图像类质检报告，需开启视觉解析能力；本地部署工业专用模型时，需正确配置专属接口信息，避免鉴权或路径错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单份申报材料（含长日志）的总长度，避免截断关键合规字段 |
| `maxTokens` | 2000–3000 token | 控制模型单次输出的审核结果长度，适配案卷审核的逐条判定需求 |
| `quoteMaxToken` | 1500 token | 限制引用源文本的长度，确保结构化表格的字段完整展示 |
| `temperature` | 0.1–0.3 | 降低输出随机性，保证工业合规判定的一致性 |
| `AIPROXY_API_ENDPOINT` | 本地部署模型的http服务地址（如http://192.168.1.100:8000/v1） | 对接本地蒸馏版deepseek或xinference部署的模型 |
| `vision` | 开启 | 支持解析案卷中的图像类质检报告、炉况照片等材料 |

## 容易做错的三处
- 现象：配置`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`后仍无法调用蒸馏版deepseek模型，日志提示接口鉴权失败。原因：未将模型接口路径配置为蒸馏版专属的路由后缀，或未使用对应模型的专属API密钥。
- 现象：FastGPT v4.8.14版本中，上传钢铁冶炼的长日志文档后解析结果为空。原因：默认`maxContext`参数设置过小，截断了文档的关键结构化字段，导致模型无法识别有效内容。
- 现象：FastGPT v4.9.0版本工作流运行时，出现未调用的gpt-4o-mini报错日志。原因：工作流中残留了已删除的GPT模型节点配置，或默认模型调用模板未正确替换为场景专用模型。

## 怎么确认配好了
- 提交一份标准钢铁冶炼申报材料，检查模型输出是否完整覆盖所有合规项，确认无上下文截断提示。
- 调用配置的模型接口，验证`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置可正常返回模型响应，无连接或鉴权报错。
- 上传含图像的质检报告，确认`vision`功能可正常解析图像中的文字与检测数据。
- 针对FastGPT v4.17.0版本，通过系统模型管理页面，核对已配置的参数与当前场景的适配性。
