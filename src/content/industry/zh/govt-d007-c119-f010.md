# 钢铁冶炼的申报材料与案卷审核：知识库检索与召回

## 这个品类的数据长什么样
钢铁冶炼的申报材料与案卷审核数据，主要来源于原料质检台账、冶炼工艺参数日志、成品检验报告、合规申报文件及审批案卷。数据更新节奏匹配申报周期，按单批次项目或月度/季度批量更新。文档类型包含结构化Excel表格（含碳含量、炉温、批次号等字段，单位为%、℃、吨等）、PDF格式的工艺规程、Word格式的审批表单，部分案卷包含关联的跨文档关联数据，如同一批次的原料与成品对应关系。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化Excel表格与非结构化文本混合存在，要求检索系统同时支持精确字段匹配与语义检索；专业术语（如炉号、合金成分）的语义一致性要求高，需避免低质量的误召回；批次关联数据的存在，要求检索能够召回同一批次的多份关联文档；批量更新的特性要求知识库的索引更新适配批次性同步，避免全量重索引的资源消耗。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 钢铁冶炼专业术语较多，阈值过低会混入无关工艺文档，过高会遗漏合格匹配结果，按实测标定 |
| `limit` | 前8–12条 | 案卷审核需关联多份同批次材料，过多会超出上下文窗口，过少无法覆盖关联文档 |
| `searchMode` | hybrid | 兼顾结构化表格的精确字段匹配与非结构化文本的语义检索，适配混合格式的业务数据 |
| `usingReRank` | 开启 | 钢铁专业术语的语义相似度易被基础模型误判，重排可过滤低质量召回结果 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可通过批次号、炉号等字段扩展查询，召回同一批次的关联文档，提升检索完整性 |
| `collectionIds` | 绑定当前业务的知识库集合ID | 限定检索范围，避免混入其他品类的文档，提升检索精准度 |

## 容易做错的三处
- 导入xlsx格式的原料质检表后，检索对应批次的内容无匹配结果，原因是未配置表格解析的字段映射规则，导致Excel中的结构化数据未被正确拆分索引。
- 建立知识库时选择非ada 002的嵌入模型，触发报错文案为`undefined model must match "^(text`，原因是FastGPT v4.17.0版本要求嵌入模型匹配指定前缀，未选择合规模型触发校验报错。
- 检索召回结果中混入非钢铁冶炼的文档，原因是未通过`collectionIds`限定检索的知识库集合，导致跨业务数据被召回。

## 怎么确认配好了
- 上传一份测试用的xlsx原料质检表，执行包含批次号关键词的检索，查看是否能匹配到对应表格内容。
- 进入知识库配置页面，确认嵌入模型选择为ada 002，无模型校验相关报错。
- 查看检索配置中的`collectionIds`是否已绑定当前钢铁冶炼申报案卷的专属知识库集合。
- 开启`usingReRank`后，对比开启前后的召回结果排序，确认低质量的匹配结果被过滤。
