# 高速公路运营的申报材料与案卷审核：多轮对话与提示词

## 这个品类的数据长什么样
数据主要来自高速公路收费系统、路政执法档案、养护运维台账与通行费申报表单。更新节奏随单次申报批次触发，单批次数据量随申报规模浮动。文档包含结构化表单字段（如车辆轴型、收费费率、路政案件编号）与非结构化扫描件（PDF、JPG格式案卷），字段单位涵盖元、车次、自然日等，案卷文档通常包含案件详情、审批流程记录与现场照片附件。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
结构化字段的单位多样性要求提示词需明确校验规则，避免金额、车次等字段的单位混淆。非结构化案卷扫描件的存在，要求多轮对话支持分阶段上传不同类型附件。单次申报批次的数据更新特性，要求上下文窗口需按申报批次划分，避免跨批次数据干扰。审批流程的多节点记录，要求多轮对话保留历史审批意见的上下文，确保审核逻辑连贯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次对话最大上下文 | 8000–12000 字符 | 适配案卷文档与申报表单的混合内容长度，避免上下文溢出 |
| 上下文保留轮次 | 前 10 轮对话 | 匹配申报审核的多节点审批流程，保留历史审批意见与材料校验记录 |
| 全局变量配置 | 按申报类型预设 `variables` 字段 | 快速调用通行费率、路政案件编号等固定字段，减少重复输入 |
| 文件上传入口分组 | 按材料类型拆分2-3个入口 | 区分案卷扫描件、申报表单、佐证材料的上传，避免材料混淆 |
| 对话超时阈值 | 300–600 秒 | 适配案卷文档的解析与多轮校验的耗时需求 |
| 提示词校验规则 | 强制校验字段单位 | 匹配高速公路申报材料的单位多样性，避免字段校验错误 |

## 容易做错的三处
- 现象：对话界面的全局变量选项仅显示2个，无法调用预设的通行费率、路政案件编号字段。原因：未在FastGPT v4.17.0的变量配置页完成对应字段的预设，仅启用了默认内置变量。
- 现象：调用应用时返回API密钥无效的报错。原因：混用了全局通用密钥与应用专属密钥，未使用对应高速公路运营场景的应用专属密钥。
- 现象：无法在同一场对话中分别上传案卷扫描件与佐证材料。原因：未配置按材料类型拆分的文件上传入口，默认入口仅支持单次上传单份材料。

## 怎么确认配好了
- 进入FastGPT v4.17.0的应用配置页，检查全局变量列表是否包含预设的业务字段，确认变量配置已生效。
- 发起测试对话，尝试上传2份不同类型的材料，确认上传入口按材料类型拆分，可分别选择对应材料。
- 输入包含多轮审批节点的测试问题，检查对话上下文是否保留历史校验记录，未出现上下文丢失的情况。
- 模拟单次申报的完整流程，确认对话超时阈值适配解析与校验耗时，未出现中途断开的情况。
