# 12345热线工单办理的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自12345热线平台、承办单位业务系统、官方知识库、群众回访评价数据及地方热线管理规范。日常产生的文档包含诉求登记单、派单记录、办理答复、回访记录、延期申请、退回说明与知识库条目，数据按日更新。文档字段通常包含诉求编号、诉求内容、责任单位、办理进度、答复口径、回访评价结果等，无统一法定格式，随地方热线运营规则调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据按日更新的特征要求知识库同步配置需匹配日更节奏，避免陈旧数据影响工单判断。多源异构的文档结构与字段要求模型需精准识别诉求类型、责任单位等核心字段，因此召回与上下文长度需适配多类文档的信息密度。工单超期、答复退回等出错后果要求超时配置需严格匹配热线办理的响应要求，同时需适配不同承办单位的业务系统数据格式差异，避免字段解析异常。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，具体参数设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多源工单文档的信息总量，避免截断核心的派单、答复与回访记录 |
| `maxTokens` | 4000 token | 匹配热线工单答复的常规长度需求，避免生成内容超出业务沟通范围 |
| `quoteMaxToken` | 1500 token | 限制单条引用文档的长度，确保召回内容聚焦诉求类型、责任单位等核心字段 |
| `temperature` | 0.2–0.4 | 降低生成随机性，保证答复口径符合热线管理规范，避免出现不确定表述 |
| 重排模型开关 | 开启 | 针对工单诉求的短文本特征，提升召回内容与诉求的匹配精度 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写本地或云端接口地址 | 适配12345热线场景下的大模型调用链路，确保数据传输合规 |

## 容易做错的三处
- 开启重排模型后在线召回测试无匹配结果：通常因重排模型的调用链路未正确绑定，或召回的原始条数未达到重排模型的最低输入要求，导致重排环节未触发。
- 配置`quoteMaxToken`或`maxContext`取值过大时，上下文无法正常发送给大模型：因平台对单次请求的总token上限有限制，超出阈值后会自动截断或丢弃上下文内容。
- 本地部署大模型时频繁出现请求超时：因本地硬件资源不足或API超时配置未适配大模型响应时长，导致请求在等待过程中触发超时报错。

## 怎么确认配好了
- 查看知识库索引日志，确认重排模型的调用记录存在且无报错。
- 发起单次工单测试对话，检查上下文面板中显示的召回文档长度与`quoteMaxToken`的配置取值匹配。
- 查看大模型调用日志，确认请求的总token值未超出平台限制，且响应时长符合预期。
- 测试导入多份工单文档组合的上下文，确认未出现截断或丢弃的提示。
