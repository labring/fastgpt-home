# “高效办成一件事”联办的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
该品类的数据通常来自国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库及各部门审批系统。日常处理的文档包括联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见与办结回执。数据更新节奏为每日更新，文档多包含跨部门事项关联关系、材料要求、办理流程等字段，无统一固定单位，需按单份文档的实际内容提取结构化与非结构化信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配联办文档的段落长度，避免单块包含跨部门关联信息导致语义断裂 |
| 重叠长度 | 100–150 字符 | 保留跨块的流程关联信息，确保召回时能获取完整的前后置办理关系 |
| `maxToken` | 4096 token | 匹配常用向量模型的输入上限，避免截断联办事项的完整流程说明 |
| 相似度阈值 | 0.72–0.78 | 过滤低相关的非联办类政务信息，保留与目标事项强关联的内容 |
| 单次搜索上限 | 前 8 条 | 平衡召回信息的完整性与响应速度，避免过多冗余内容干扰流程引导 |
| `defaultToken` | 2048 token | 设置默认上下文窗口长度，适配常见的联办咨询场景的信息长度 |

## 容易做错的三处
- 现象：调用向量模型时返回访问拒绝错误，使用curl工具测试接口却可正常连通。原因：未在FastGPT的向量模型配置中正确填写模型服务的访问地址或端口映射参数，导致平台无法正常发起请求。
- 现象：无法通过MongoDB直接执行向量库的增删操作，提示字段格式不兼容。原因：未使用FastGPT官方提供的向量库管理接口，直接操作MongoDB的向量存储集合时未遵循其内部的向量索引格式要求。
- 现象：召回的联办流程信息缺失跨部门关联内容，返回结果与实际办理要求不符。原因：未在索引配置中保留事项关联字段，仅对单份文档单独生成向量，无法召回跨部门的并联审批关联信息。

## 怎么确认配好了
- 导入一份联办事项清单文档，发起流程引导测试，核对召回的内容是否包含对应事项的跨部门关联信息。
- 查看向量库的更新日志，确认每日增量更新任务正常执行，无异常的全量重建触发。
- 测试不同类型的联办咨询问题，核对返回的相似度结果是否符合预设的阈值范围。
- 检查向量模型的配置参数，确认已正确设置支持的目标模型名称与接口地址。
