# “高效办成一件事”联办的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库及各部门审批系统，更新频率为每日。日常关联文档包含联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见、办结回执，核心字段涵盖事项组合名称、关联部门清单、复用材料条目、办理节点时序、状态流转标识等。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源异构的数据来源要求工具调用需适配不同部门系统的接口格式，每日更新的频率要求插件配置定时同步联办事项清单与办理状态的任务。多样的关联文档结构要求工具需支持解析不同格式的申请材料、流转单据，跨部门组合办理的核心难点要求插件在流程编排中准确识别事项的前后置关联与材料复用规则，同时需配置异常分支处理逻辑，避免因单部门响应异常导致联办流程停滞。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `functionCall` | 强制开启 | 联办流程需严格调用指定工具获取部门审批状态，避免生成无关回复 |
| `toolChoice` | 绑定联办专属工具组 | 仅调用与跨部门办理相关的工具，排除非政务类功能 |
| 单次工具调用超时时间 | 30-60秒 | 适配地方政务平台的接口响应常规时长，避免流程卡顿 |
| 工具调用失败重试次数 | 2次 | 应对临时网络波动或部门接口短暂异常，减少流程中断概率 |
| 插件上下文缓存时长 | 1200秒 | 保留联办流程的材料、节点信息，支持跨步骤的工具调用关联 |
| 工具返回结果展示上限 | 前10条 | 适配联办事项的常规关联部门数量，避免信息过载 |

## 容易做错的三处
- 现象：工具调用返回部门审批结果后，界面仍展示模型生成的自然语言回复，未仅展示工具调用结果。原因：未开启`functionCall`强制模式，导致模型在工具调用后继续生成对话内容。
- 现象：联办流程编排至末尾节点时，未触发工具调用即直接返回办结状态。原因：未在流程节点链的最后环节配置工具调用终止逻辑，导致流程未完成全部门校验即结束。
- 现象：自定义联办材料卡片无法在对话界面展示。原因：未通过插件封装政务平台的材料预览接口，未配置卡片渲染的触发规则。

## 怎么确认配好了
本文档适用于FastGPT v4.17.0版本。
- 发起联办事项查询请求，验证模型仅调用绑定的联办专属工具，无额外自然语言回复，确认`functionCall`与`toolChoice`配置生效。
- 模拟部门接口超时场景，验证工具调用在重试指定次数后触发异常分支处理，确认超时时间与重试次数配置合理。
- 编排完整联办流程，在最后一个节点触发工具调用，验证流程完成后自动终止，确认节点时序配置完整。
- 测试自定义材料查询请求，验证对话界面展示插件封装的政务材料卡片，确认插件渲染规则配置正确。
