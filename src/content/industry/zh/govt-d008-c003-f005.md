# 不动产登记的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源为不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统及电子证照库，更新频率为每日。日常处理的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书及不动产登记簿。数据字段包含不动产坐落、权利人身份信息、权属类型、权利限制状态、测绘面积等，单位涵盖平方米、宗数等标准不动产登记字段单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来自多套异构系统，工具调用需支持对接多源数据接口以完成跨系统数据比对。每日更新的数据要求工具调用需配置实时同步逻辑，避免使用过期的权属或测绘数据。多样的文档类型要求插件需适配登记申请书、权属证明等不同格式的文件解析。数据校验出错会引发登记错误与产权纠纷，因此工具调用环节需增加字段完整性与合规性校验步骤。跨部门协同的数据源要求插件需兼容不同系统的接口认证方式，确保数据拉取权限合规。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 支持模型自主选择合适的工具调用，适配多源数据校验的复杂场景 |
| `functionCall` | `["query_property_status", "compare_survey_data", "verify_tax_info"]` | 覆盖权属状态核验、测绘数据比对、税费信息校验三个核心业务环节 |
| 工具调用超时时间 | `600 秒` | 跨系统数据拉取需预留足够的响应时长，避免因超时中断业务流程 |
| 工具调用结果条数 | `前3条` | 不动产登记数据需精准匹配，过多结果会增加校验负担，影响业务办理效率 |
| 数据同步周期 | `1 天` | 匹配数据源的每日更新频率，确保工具调用使用的始终为最新业务数据 |
| 插件触发节点 | 按业务环节节点触发 | 需在权属核验、数据比对环节调用工具，避免无效调用占用系统资源 |

## 容易做错的三处
- 现象为工具调用模块无法在界面中找到，无对应配置入口。原因是未在应用设置中开启工具调用功能开关。
- 现象为工具调用返回空数据或字段缺失，无法完成权属核验。原因是未配置对应不动产登记系统的接口权限，或调用参数未匹配数据源的字段格式。
- 现象为模型未触发预设的工具调用，直接返回通用文本结果。原因是`toolChoice`参数设置为`none`，或未为模型绑定正确的工具函数列表。

## 怎么确认配好了
- 进入应用的工具配置页面，确认已添加不动产登记数据查询、测绘数据比对等自定义工具。
- 发起模拟业务办理请求，查看工具调用日志，确认对应接口已触发且返回有效业务数据。
- 检查`functionCall`参数配置，确认已绑定业务环节所需的全部工具函数。
- 测试异常输入场景，确认工具调用会触发字段校验逻辑并返回明确提示。
