# 产权、资产与国有资本管理的业务办理流程引导：向量模型与索引

以下配置基于FastGPT v4.17.0版本制定。

## 这个品类的数据长什么样
本品类的数据主要来自国资监管信息系统、企业资产管理系统、产权交易所系统、评估机构报告及财务报表。日常文档包含产权登记表、资产评估报告、产权转让方案、进场交易公告、资产处置审批单，包含权属编号、资产原值、评估值、交易底价等字段，更新频率为月度。数据多为结构化表单与半结构化报告混合，单份文档篇幅跨度较大，部分评估报告篇幅较长。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且包含多系统异构内容，需支持跨源数据的向量入库与关联索引，避免出现字段编码遗漏。月度更新的频率要求索引构建支持增量更新模式，降低全量重建带来的资源消耗与时间成本。文档包含结构化字段与半结构化报告，需针对不同文档类型配置差异化的分块规则，避免破坏业务字段的完整性与关联性。单份文档篇幅跨度大，需限制单文档分块后的token总量，避免超出模型的上下文处理上限。权属编号、交易底价等关键业务字段需单独配置索引权重，提升核心信息的检索精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配本品类半结构化报告与结构化表单的混合内容，避免破坏业务字段完整性 |
| 重叠长度 | 100–200 字符 | 保障跨分块的业务逻辑连贯，避免产权转让方案的条款被拆分断裂 |
| 相似度阈值 | 0.72–0.85 | 适配资产权属信息的强匹配需求，过滤低相关的检索结果 |
| 单次搜索上限 | 前 10 条 | 匹配业务办理中需核对的少量核心资产信息，避免冗余结果干扰 |
| `maxToken` | 8192 | 适配主流开源向量模型的上下文限制，保障长文档分块后的向量生成正常 |
| `defaultToken` | 1024 | 配置单条向量的默认token长度，平衡检索精度与存储开销 |

## 容易做错的三处
- 现象：本地部署向量模型后添加索引时出现报错。原因：未针对本品类的结构化表单配置字段抽取规则，导致部分业务字段未被正确编码。
- 现象：配置百度embedding-v1时返回404报错。原因：未正确填写模型接口的鉴权密钥与请求路径，导致平台无法发起有效请求。
- 现象：无GPU环境下部署m3e向量模型后，无法在平台中添加。原因：未将容器内的模型服务端口映射至本地可访问端口，导致平台无法连通模型服务。

## 怎么确认配好了
- 导入单份产权登记表文档，检查向量生成日志中是否包含所有配置的业务字段编码记录。
- 发起包含资产权属编号的检索请求，核对返回结果的相似度分值是否符合预设的区间范围。
- 执行增量索引任务，检查是否仅对当月更新的文档执行向量入库操作，未触发全量重建。
- 查看向量数据库的存储空间占用，确认单条向量的token长度符合`defaultToken`的配置值。
