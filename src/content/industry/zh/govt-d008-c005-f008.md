# 产权、资产与国有资本管理的业务办理流程引导：文档解析与分块

## 这个品类的数据长什么样
该品类数据来自国资监管信息系统、企业资产管理系统、产权交易所系统、评估机构报告、财务报表，更新频率为月度。日常处理的文档包括产权登记表、资产评估报告、产权转让方案、进场交易公告、资产处置审批单，既有结构化表单类文档，也有数十页的长文本报告，部分文档带有自定义页眉、加密表单或非标准排版，核心字段包含权属编号、评估值、交易底价等业务关键信息。

## 这些特征在「文档解析与分块」这一环带来什么约束
月度批量更新的文档数量多，单份体积差异大，既有几十KB的表单文档，也有数十MB的长文本评估报告，对解析稳定性要求高。多来源的文档格式不统一，部分PDF带有加密表单或自定义页眉，常规解析可能丢失核心字段。核心业务字段需完整保留在分块内，避免检索时割裂权属、交易等关键逻辑。批量上传时需适配不同文件大小的限制，避免超时或解析失败，否则会影响后续流程核对与审计工作。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度（`chunkSize`） | 800–1200 字符 | 该品类文档包含固定表单字段与长文本说明，此区间可平衡上下文完整性与检索精度，避免单块过长影响召回或过短破坏业务逻辑 |
| 分块分割符（`chunkSplitter`） | 按业务文档固定章节标题分割 | 产权、资产类文档多有“评估说明”“转让方案”“审批意见”等固定章节标题，按此分割可保留业务逻辑完整性 |
| 文件解析超时（`PARSE_FILE_TIMEOUT_SECONDS`） | 1200 秒 | 大型资产评估报告解析耗时较长，默认时长不足以完成完整解析，此时长可覆盖多数单份文档的解析需求 |
| 单文件上传上限（`UPLOAD_FILE_MAX_SIZE`） | 500 MB | 月度批量上传的产权交易公告合集、多份评估报告打包文件常达数百MB，此上限可适配常规批量上传需求 |
| 自定义PDF解析（`customPdfParse`） | 开启 | 业务PDF多带有加密表单、自定义页眉页脚，自定义解析可保留核心业务字段与排版结构 |
| 分块设置模式（`chunkSettingMode`） | 手动模式 | 需针对表单类文档与长文本报告分别调整分块规则，手动模式可灵活适配不同文档类型 |

## 容易做错的三处
- 上传10MB以上的资产评估报告时提示`timeout of 360000ms exceeded`错误，原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以解析长文档。
- 上传docx格式的资产处置审批单时解析结果为空，原因是未开启`customPdfParse`适配非标docx的页眉页脚与签字栏字段。
- 分块后检索结果包含无关的产权登记表附件内容，原因是未设置`chunkSplitter`为业务文档的固定章节分隔符，导致跨章节分块破坏业务上下文。

## 怎么确认配好了
- 上传单份10MB左右的资产评估报告，检查解析过程无超时报错，确认`PARSE_FILE_TIMEOUT_SECONDS`设置生效。
- 上传docx格式的资产处置审批单，检查解析结果保留了审批意见、签字栏等核心业务字段，确认`customPdfParse`开启有效。
- 上传包含长评估说明的文档，检查分块结果未将单个评估事项拆分为多个不相关的块，确认`chunkSize`与`chunkSplitter`设置合理。
- 上传批量打包的月度更新文档，确认未触发`UPLOAD_FILE_MAX_SIZE`限制，验证上传上限设置正确。
