# 产权、资产与国有资本管理的业务办理流程引导：模型接入与配置

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类数据主要来自国资监管信息系统、企业资产管理系统、产权交易所系统、评估机构报告与财务报表，更新频率为月。日常处理的文档包含产权登记表、资产评估报告、产权转让方案、进场交易公告、资产处置审批单，数据字段多包含资产权属编号、评估基准日、交易底价、审批节点状态等，部分字段需匹配国资监管的统一格式要求。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的多源异构数据来源，要求模型接入时需兼容国资监管系统、产权交易所系统等不同格式的文档导入，月更新频率则要求知识库同步配置可按固定周期触发。文档包含资产权属编号、交易底价等专业字段，要求模型调用时能准确匹配业务字段含义，避免提取偏差。国有资产数据的敏感性与出错后果的严重性，要求密钥管理需符合合规要求，同时需配置完善的错误捕获与重试机制，保障流程引导的稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配产权转让方案、资产评估报告等长文档的上下文需求，保障模型能完整读取业务流程相关内容 |
| `maxTokens` | 2000–3000 token | 满足业务办理流程引导的回复长度需求，避免超出模型输出上限截断关键流程步骤 |
| `quoteMaxToken` | 1000–1500 token | 精准提取产权登记表、资产处置审批单中的核心字段内容，确保引导信息与实际业务文档匹配 |
| `temperature` | 0.1–0.3 | 降低回复随机性，保障业务流程引导的准确性，避免出现与国资监管要求不符的表述 |
| `AIPROXY_API_TOKEN` | 按业务场景分配独立密钥 | 避免多业务场景共享密钥导致的会话与记录共享，符合国有资产数据的合规管理要求 |
| `AIPROXY_API_ENDPOINT` | 按所选模型服务商的官方节点配置 | 保障模型调用的稳定性与响应速度，适配国资业务流程的实时引导需求 |

## 容易做错的三处
- 模型测试时出现`[] is too short - 'messages'`报错，原因是未正确配置对话上下文的初始消息结构，导致传入模型的消息数组为空或长度不足。
- 对话发起时返回422错误，而模型测试显示成功，原因是业务流程引导的知识库未正确关联对应品类的文档数据，或上下文长度配置超出模型支持范围。
- 公用`AIPROXY_API_TOKEN`导致多用户会话与记录共享，原因是未按业务场景分配独立密钥，违反国有资产数据的访问隔离要求。

## 怎么确认配好了
- 导入本品类的典型文档（如产权登记表、资产评估报告），核对模型提取的字段是否与文档内容匹配。
- 发起模拟业务办理对话，检查模型输出的流程步骤是否符合该品类的业务逻辑。
- 配置独立密钥后，验证不同测试账号的会话记录无法互相访问，确认密钥隔离生效。
- 调整`maxContext`参数后，测试长文档的读取效果，确认未出现内容截断或识别偏差。
