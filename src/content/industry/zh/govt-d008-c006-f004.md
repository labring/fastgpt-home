# 传染病信息报告与监测的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
本品类数据来源为中国疾病预防控制信息系统、医疗机构HIS与传染病报告系统、实验室检测系统，更新频率为每日。日常文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，数据字段包含病例诊断信息、报告时限标识、订正状态、疫情规模参数等，格式需符合法定上报规范，无额外自定义统计字段。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据接入带来统一校验约束，需针对不同系统的字段格式配置标准化校验规则。每日更新的频率要求工作流需配置定时触发节点，确保每日完成全量数据汇总与上报。多类文档格式要求工作流按文档类型分支编排处理逻辑，避免跨类型字段混淆导致的处理错误。法定传染病报告规则约束工作流不可跳过必填校验环节，需强制校验报告时限、病例信息完整性，否则触发异常拦截。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量作用域 | 会话级隔离 | 避免跨API或Web请求的数据污染，匹配多请求并行的业务场景 |
| 定时触发节点周期 | 每日 00:00 执行 | 匹配数据每日更新的频率，确保当日数据按时汇总上报 |
| `variables` 绑定范围 | 绑定 10 个以内核心业务字段 | 减少冗余参数加载，提升工作流执行效率 |
| 分支判断节点匹配规则 | 字段精确匹配 | 符合法定传染病报告的固定校验规则，避免模糊匹配导致的校验偏差 |
| `nodeId` 配置 | 为每个校验节点分配唯一标识 | 便于定位工作流执行异常的具体环节 |
| 异常拦截阈值 | 按实测标定 | 适配不同疾控机构的校验严格程度，灵活调整拦截标准 |

## 容易做错的三处
- 现象：工作流分支判断节点中，使用“等于”“开头为”规则时触发ELSE分支，使用“包含”“结束为”规则时触发IF分支。原因：未正确匹配FastGPT工作流判断节点的规则逻辑，混淆了规则与触发分支的对应关系。
- 现象：全局变量跨API或Web请求出现数据串扰。原因：错误配置全局变量作用域为全局共享，未启用会话级隔离。
- 现象：工作流无法获取系统侧传递的参数，对应字段为空。原因：未在`variables`配置中绑定系统参数与工作流节点的映射关系，导致参数未正确传入。

## 怎么确认配好了
- 查看工作流定时触发配置，确认触发周期与数据更新频率匹配。
- 模拟多请求并行调用工作流，检查全局变量是否出现跨请求数据污染。
- 传入预设的测试业务字段，验证分支判断节点的触发逻辑是否符合预期。
- 查看工作流执行日志，确认`nodeId`标识的各节点均正常执行无异常报错。
