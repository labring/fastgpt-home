# 传染病信息报告与监测的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源包括中国疾病预防控制信息系统、医疗机构HIS和传染病报告系统、实验室检测系统，更新频率为日更。日常产生的文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，文档字段覆盖病例基础信息、诊断结果、报告时限、订正说明、检测数据等，数据以结构化表单和非结构化文档混合为主，无额外自定义统计字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据对接要求工具调用需适配不同系统的接口格式，避免数据同步异常。日更频率要求工具需支持定时拉取或增量同步机制，保障数据时效性。混合格式的文档需要针对性的解析插件，确保结构化字段提取准确。法定报告规则要求工具调用需内置校验逻辑，对报告时限、重卡错卡等内容进行自动核对，否则可能触发监管通报。同时，数据量随疫情波动，工具调用需具备弹性适配能力，避免峰值时段接口过载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | auto | 适配不同类型的业务文档，自动选择对应工具完成解析或校验 |
| 文档解析插件 | pdf-marker v2（需在FastGPT v4.17.0版本下部署） | 支持流调报告、疫情分析报告等多格式非结构化文档的字段提取 |
| 插件调用超时设置 | 600 秒 | 疾控报告数据量较大，处理耗时较长，避免因超时中断任务 |
| 多工具并行调用上限 | 前3条 | 避免同时调用多个系统导致接口限流，保障调用稳定性 |
| 单次工具调用返回数据上限 | 1000 条 | 适配疾控报告的单次数据量要求，避免接口返回数据过大 |
| `functionCall` | 强制指定报告校验工具 | 确保核心的病例诊断核对、时限校验环节调用专用工具，提升准确性 |
| 插件日志存储上限 | 100 MB | 存储每日的疾控报告解析日志，避免磁盘空间溢出 |

## 容易做错的三处
- 调用`/v2/parse/file`接口时返回404错误，原因是未正确部署pdf-marker v2版本的开源插件，或插件目录配置未指向正确路径。
- 使用markdown转docx插件处理疾控报告时输出格式混乱，原因是未针对报告内的表格对齐、字段换行等场景调整插件参数，未匹配文档的固定格式要求。
- 调用FastGPT开源版用于商业场景时触发合规提示，原因是未明确开源协议的商业使用范围，或未按要求保留开源声明。

## 怎么确认配好了
- 上传一份标准传染病报告卡，触发工具调用流程，检查是否正确调用pdf-marker v2插件完成文档解析。
- 查看插件调用日志，确认超时设置生效，无连续600秒内未完成的任务报错。
- 创建两个独立应用，分别配置不同的api key，调用同一模型接口，检查返回结果是否关联对应应用的密钥配置。
- 提交一份超过报告时限的病例数据，检查工具是否触发校验逻辑并返回异常提示。
