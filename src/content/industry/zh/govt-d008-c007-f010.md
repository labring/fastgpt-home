# 信访事项办理的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据主体来自信访局、部门信访办、街道乡镇及责任单位办公室，日常文档包含信访登记表、受理告知书、转送交办函、办理意见书、复查复核申请、化解方案等制式文书。数据来源为国家信访信息系统、地方信访系统、12345平台、基层治理平台及历史信访档案，更新频率为每日。数据字段包含诉求内容、办理进度、复核结果等，整体结构固定，多为制式化的业务文书。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源多且每日更新，需配置增量同步机制保障数据时效性，避免召回过时的办理意见。制式文书结构固定，需适配分块规则保留文书关键段落，防止关键信息被截断。诉求与办理流程强绑定，检索需精准匹配法定程序与对应环节，同时需避免低匹配度内容引发重复信访或越级信访。跨系统数据需统一关联至专属业务数据集，防止非相关文档干扰检索结果。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 信访事项涉及法定办理程序，需保障检索结果与诉求的匹配精度，避免低匹配度内容干扰办理指引 |
| 单次搜索上限 | 前6条 | 信访办理流程需关联多环节文书，单次召回适量结果可兼顾信息完整性与页面加载效率 |
| 重排开关 | 开启 | 制式文书的语义相似度易受格式影响，重排可优化结果排序，提升办理流程指引的准确性 |
| 问题优化开关 | 开启 | 信访诉求表述多样，通过问题优化可扩展检索词范围，覆盖不同表述的办理流程 |
| 数据集绑定ID | 绑定信访业务专属数据集 | 隔离业务数据与其他场景数据，避免非相关文档被召回，保障检索针对性 |
| 自定义分块长度 | 800–1200字符 | 信访业务文档多为制式表单与告知书，该长度可保留完整段落的关键信息 |

## 容易做错的三处
- 现象：调用知识库检索接口后返回的文档阅读链接点击后触发报错，提示仅支持.txt格式。原因：未将信访业务文档统一转换为平台支持的可预览格式，或数据集配置中未开启对应文档类型的预览权限。
- 现象：检索结果中出现过时的办理意见书，导致信访人重复提交诉求。原因：未配置每日增量同步规则，未及时更新历史档案中的办结文书数据。
- 现象：检索返回的结果中丢失信访登记表中的关键诉求字段信息。原因：自定义分块规则时未保留文书的完整段落，导致关键内容被截断。

## 怎么确认配好了
- 查看系统同步日志，确认每日增量同步任务正常完成，无失败记录。
- 输入典型信访诉求发起检索，核对返回结果包含信访登记表、受理告知书等业务专属文档类型。
- 测试不同表述的诉求，验证问题优化开关开启后可覆盖更多关联的业务文档。
- 检查数据集配置，确认仅绑定信访业务专属的数据集ID，无跨场景数据集混入。
