# 公共数据目录与开放的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
本品类的数据主要来源于地方公共数据开放平台、一体化大数据平台、部门业务数据库及电子证照库，更新频率为每月一次。日常维护的文档包含公共数据资源目录、数据开放清单、数据项说明、脱敏规则、接口文档及更新频率说明。数据字段包含数据项名称、开放范围、脱敏要求、接口地址、更新周期、授权边界等，单位多为条、次、MB等结构化标识，无半结构化或非结构化文本类通用字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
每月固定更新的数据源要求工具调用需适配周期性数据同步校验，避免调用过期数据。多来源的结构化数据要求插件需支持多接口聚合调用，按数据项分类匹配请求参数。固定的文档类型要求工具调用时需优先加载最新的接口文档、脱敏规则，确保请求符合开放条件。字段的结构化特性要求插件参数需严格匹配数据项的字段名与单位，避免格式不兼容导致调用失败。同时，`toolChoice`与`functionCall`的配置需适配政务接口的调用特性，避免因参数配置不当导致请求被拦截。

## 配置怎么定
本文档基于 FastGPT v4.17.0 版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配公共数据目录多类型接口调用需求，自动匹配对应工具 |
| `functionCall` | `strict: true` | 强制匹配公共数据目录的结构化字段，避免参数不兼容 |
| 单次工具调用超时时间 | 30–60 秒 | 适配政务接口的常规响应延迟周期 |
| 单次返回数据条数 | 前 10 条 | 符合公共数据目录单次开放数据量的常规范围 |
| 工具调用上下文缓存时长 | 1800 秒 | 匹配每月更新周期内的业务办理窗口时长 |

## 容易做错的三处
- 现象：调用时返回400 InternalError.Algo.InvalidParameter报错，提示工具参数不匹配。原因：未开启`functionCall`严格模式，传入了公共数据目录未定义的字段参数。
- 现象：插件调用返回结果为空或条数不符预期。原因：未设置合理的单次返回数据条数，超出政务接口的单次返回上限。
- 现象：线上创建的插件无法在业务流程中触发调用。原因：未在工具配置中绑定对应的数据开放接口文档，导致流程无法识别插件触发条件。

## 怎么确认配好了
- 传入公共数据目录的标准数据项参数调用测试接口，检查返回结果的字段与条数是否符合配置要求。
- 查看工具调用日志，确认未出现参数不匹配或超时的报错信息。
- 模拟月度数据更新场景，检查插件是否能自动加载最新的接口文档与脱敏规则。
- 模拟政务接口延迟场景，验证工具调用是否在设定的超时时间内完成。
