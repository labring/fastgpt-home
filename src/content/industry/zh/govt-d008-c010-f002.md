# 公路养护与路产路权管理的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
该品类的日常数据主要来自公路养护管理系统、桥隧监测系统、路政巡查系统与交通流量监测数据，更新频率为每日。典型文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单，多为结构化表格格式，表头包含路段桩号、病害类型、处置状态、许可编号等字段，部分文档附带位置坐标、面积等量化单位信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的结构化业务数据体量较大，单表常包含数千行内容，若分块颗粒度过粗会丢失单条工单、巡查记录的关键细节。流程类文档如涉路施工许可、赔偿单包含连续的步骤字段，需保留环节关联信息，不宜过度拆分。同时数据包含位置、面积等量化字段，向量索引需兼容结构化字段与文本内容的混合匹配，避免检索时丢失业务上下文，且需符合`maxToken`的输入限制，避免单块内容超出模型承载范围。大文件上传后分块数量较多，易出现单块向量化异常的问题。

## 配置怎么定
本页面配置说明基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配单条巡查记录、病害处置单的内容长度，避免单块包含过多无关业务信息 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的上下文关联，避免流程类文档的步骤被拆分断裂 |
| `maxToken` | 1024 token | 匹配当前主流向量模型的输入限制，适配多数业务文档的单块内容 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 区分不同病害类型、流程环节的匹配精度，适配路产管理的业务场景 |
| 单次搜索上限 | 前 8 条 | 覆盖单条工单的关联流程步骤，避免检索结果过多干扰业务判断 |
| 重试次数 | 3 次 | 应对单块向量化异常的临时修复，降低大文件上传的失败率 |

## 容易做错的三处
- 现象：导入Excel格式的10000+行业务数据后，分块颗粒度过大，单块包含数十条不相关的巡查记录。原因：未调整分块长度配置，沿用通用默认参数，未适配该品类单条业务记录较短的特征。
- 现象：上传包含数千字的涉路施工许可文档时，向量化环节弹出输入长度超限的提示。原因：未按`maxToken`限制调整单块内容长度，直接拆分长文档未做适配处理。
- 现象：上传10M以上结构化文件后，部分分块显示「向量化异常」状态，反复点击重试按钮后仍未恢复正常。原因：未配置适配大文件分块的重试参数，且未校验分块内容的格式完整性，导致异常分块无法自动修复。

## 怎么确认配好了
- 导入单条巡查日志、病害处置单等典型业务文档，查看分块预览界面，确认单块内容仅包含单条或关联紧密的业务信息。
- 上传包含数千字的涉路施工许可文档，验证向量化过程未出现输入长度超限的提示。
- 上传10M以上的批量Excel文件，查看分块列表，确认异常分块的数量较少，且重试后异常可被修复。
- 模拟业务办理流程的查询请求，验证检索结果能够匹配到对应的流程环节与业务单据。
