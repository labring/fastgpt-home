# 公路养护与路产路权管理的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
该品类的日常文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单，数据来源于公路养护管理系统、桥隧监测系统、路政巡查系统、交通流量监测数据，更新频率为每日。单条数据通常包含路段标识、设施类型、病害等级、处置时限、涉事主体信息等字段，部分文档还关联空间坐标与流量统计数值，数据以结构化表单与日志文本混合形式存储。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据每日更新要求工具调用需实时拉取当日生成的巡查、养护数据，避免使用过期信息影响流程引导的准确性。文档包含结构化表单与非结构化日志，工具调用需同时支持结构化字段提取与非结构化文本解析，适配不同类型的业务数据查询。业务流程涉及跨系统的审批、处置状态查询，工具调用需对接路政、养护内部系统的接口，且需适配不同系统的参数格式。单条数据关联空间坐标，工具调用需支持地理信息相关的参数传递与匹配，确保查询结果与对应路段精准关联。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动匹配当前业务场景下的可用工具，适配流程引导的动态调用需求 |
| `functionCall` | 开启强制调用模式 | 确保业务办理流程引导仅调用预设工具，避免生成不符合业务规范的回答 |
| 单次工具调用超时 | `300 秒` | 公路养护内部系统的接口响应通常在5分钟内，适配常规业务数据查询的延迟 |
| 工具调用上下文条数 | `前 8–12 条` | 业务流程需关联近期的巡查、工单信息，过多历史会增加接口调用的负载与延迟 |
| 工具结果缓存时长 | `1 天` | 该品类数据更新频率为每日，缓存当日数据可减少重复调用 |
| 工具调用参数格式 | 适配结构化表单字段 | 日常文档以结构化表单为主，需严格匹配字段名与数据类型 |

## 容易做错的三处
- 调用MySQL工具时返回400状态码且无响应体，原因是未正确配置工具的数据库连接参数，或字段格式与数据库表结构不匹配。
- 调用FastGPT工作流API时无法获取上下文信息，即使工作流已开启上下文设置，原因是API请求参数未携带会话ID或上下文缓存的过期时长配置过短。
- 调用API时传入`model`参数后无法明确其对应任务类型，原因是未在工具调用配置中绑定模型与业务任务的映射关系，导致模型任务混淆。

## 怎么确认配好了
- 发起包含路产查询、病害处置工单查询的测试调用，核对工具是否返回对应路段的巡查日志或处置单数据。
- 查看工具调用日志，确认`toolChoice`参数的匹配结果与预设工具组一致。
- 检查API请求是否携带会话ID，验证上下文信息是否正常传递至工作流。
- 模拟跨系统接口调用，确认工具调用的超时设置未触发异常中断。
