# 公路养护与路产路权管理的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
本品类的典型数据来自公路养护管理系统、桥隧监测系统、路政巡查系统与交通流量监测数据，更新频率为每日。日常文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单等类型，文档结构涵盖巡查点位坐标、病害类型、处置流程编号、许可有效期等字段，单位涉及公里、平方米、工作日等，不同文档的字段格式存在差异，部分为结构化表单，部分为非结构化日志文本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多系统异构的数据来源要求检索链路支持跨数据源的文档整合，每日更新的频率则要求知识库配置增量同步机制以保证数据时效性。文档类型包含结构化表单与非结构化日志，不同文档的关键词与语义特征差异较大，需要适配混合检索模式。业务办理的核心环节依赖精准的流程指引，召回结果的准确性直接影响作业安全与合规性，因此检索环节需避免无关文档的干扰，同时覆盖关键业务文档。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 平衡召回覆盖率与精准度，适配公路养护类文档的语义匹配要求，避免召回无关的巡查日志或施工许可 |
| `limit` | 前5–10条 | 覆盖日常业务办理的核心参考文档数量，同时控制上下文长度，避免超出大语言模型的处理上限 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配巡查日志、工单等结构化与非结构化混合的业务文档 |
| `usingReRank` | 开启 | 提升病害处置、涉路施工等关键流程文档的排序准确性，确保核心指引文档优先返回 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充涉路施工、路产损坏等业务术语的扩展查询，提升跨文档的召回相关性 |
| `collectionIds` | 按业务模块分组配置 | 分别关联养护计划、巡查日志等专属数据集，避免跨模块的文档干扰检索结果 |

## 容易做错的三处
- 现象：使用知识库时返回“无可匹配结果”报错，且已在OneAPI中注册`text-embedding-ada-002`并添加至配置文件。原因：未在对应数据集的向量模型配置中关联该模型，或配置文件中的模型标识与OneAPI注册名称存在大小写或空格差异。
- 现象：本地部署后关联知识库的内容未出现在回复正文中，但引用列表显示匹配到正确文档。原因：未开启`usingReRank`配置，或`searchMode`仅设置为语义检索，导致关键文档排序靠后被截断。
- 现象：通过API发起对话后，生成的回复未参考知识库文档。原因：未在对话请求中指定`collectionIds`参数，或参数指向的数据集未完成业务文档的上传与索引。

## 怎么确认配好了
- 查看FastGPT v4.17.0的数据集配置页面，确认向量模型为`text-embedding-ada-002`，且与OneAPI中的注册标识完全一致。
- 发起模拟业务查询，例如“路面坑槽的处置流程”，检查返回的召回结果包含病害处置单、养护计划相关文档。
- 调用API发起对话请求，确认请求参数中包含正确的`collectionIds`与`searchMode`配置。
- 查看检索日志，确认召回的文档数量与`limit`参数设置的数值一致。
