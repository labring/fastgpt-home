# 养老服务机构监管的业务办理流程引导：HTTP 接口与外部系统

## 这个品类的数据长什么样
通常，养老服务机构监管的业务数据来自养老服务信息平台、民政统计系统、消防检查记录、机构运营台账四类来源，更新频率为月度。日常涉及的文档包含备案材料、运营补贴申请、服务质量检查表、安全隐患整改台账、老人入住档案，数据以结构化字段为主，包含机构备案编号、床位数量、整改期限、补贴申请信息等核心字段，部分文档附带扫描件等非结构化附件。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
月度更新的频率要求接口调用频率不宜过高，避免触发源系统的限流规则。多来源的数据需要对接多个异构接口，不同接口的鉴权规则存在差异，需针对性配置`Authorization`参数。文档包含结构化与非结构化两类内容，接口需同时支持字段解析与附件上传。监管数据的准确性直接关联补贴发放与安全整改，接口调用需具备失败重试与数据校验能力，避免因单次调用异常导致监管流程中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 机构专属的Bearer令牌 | 对接民政系统、消防检查接口的标准鉴权要求 |
| `variables` | 按备案编号分组的结构化变量组 | 匹配养老监管数据的核心关联字段，适配多变量绑定知识库的需求 |
| `responseData` | 提取status、data、hiddenDanger字段的解析规则 | 统一对接多源接口的数据格式，提取安全隐患等核心监管信息 |
| 接口超时时间 | 600 秒 | 适配月度批量数据接口的响应延迟，避免单次调用失败 |
| 重试次数 | 3 次 | 避免重复提交导致监管数据重复，同时覆盖临时网络波动 |
| 知识库绑定规则 | 按`variables`中的备案编号匹配对应知识库 | 解决多变量对应单知识库的工作流重排问题 |

## 容易做错的三处
- 现象：Http请求返回多变量后，知识库匹配出现混乱，部分机构数据绑定到错误的知识库。原因：未按`variables`中的备案编号字段做关联，直接将全量变量绑定到单一知识库。

## 怎么确认配好了
- 发起单条机构数据的测试调用，查看`responseData`是否正确提取了备案编号、床位数量等核心字段。
- 校验`variables`中的备案编号是否与绑定的知识库条目一一对应，无匹配异常。
- 模拟网络波动场景，触发接口超时，确认系统自动执行重试动作，重试次数符合配置要求。
- 检查接口鉴权日志，无`Authorization`参数缺失或鉴权失败的报错信息。
