# 养老服务机构监管的业务办理流程引导：文档解析与分块

## 这个品类的数据长什么样
通常涉及的主体为民政局养老服务科、养老机构及协同监管部门，日常处理的文档包含备案材料、运营补贴申请、服务质量检查表、安全隐患整改台账、老人入住档案等。数据主要来自养老服务信息平台、民政统计系统、消防检查记录、机构运营台账，更新频率为月度。文档多带有章节标题与结构化字段，如机构名称、床位数量、检查日期等，部分文档包含表格与附件内容。

## 这些特征在「文档解析与分块」这一环带来什么约束
月度批量更新的监管数据要求解析节点可处理多份文档的批量任务，需预留合理的超时与容量上限。不同类型的监管文档结构差异明显，备案材料侧重机构基础信息，检查表侧重检查项与结果，需适配多样的文档格式与逻辑结构。结构化字段与章节标题是监管业务核对的关键信息，分块时需保留这些内容以保障检索时的业务关联性，避免关键信息被拆分丢失。

以下配置基于FastGPT v4.17.0版本的文档解析与分块功能编写。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 养老服务监管文档包含长段落的检查记录与台账内容，该区间可保留单条业务记录的完整上下文，避免床位数量、整改要求等关键字段被拆分 |
| `chunkSplitter` | 按标题+段落拆分 | 监管文档普遍带有明确的章节标题，按标题拆分可保留同一业务模块的完整逻辑，便于后续检索时关联匹配 |
| `customPdfParse` | 开启 | 备案材料、安全隐患整改台账多为带格式的PDF文档，开启自定义解析可保留章节标题与表格结构，避免格式错乱 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 单份养老机构备案材料可能包含多页附件与表格，600秒的超时设置可覆盖多数长文档的解析耗时 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 批量上传机构运营台账时，需支持较大容量的文件批量提交，适配月度批量数据处理需求 |
| `chunkSettingMode` | 手动配置 | 针对备案材料、补贴申请等不同文档类型，可灵活调整分块参数，适配各业务场景的检索需求 |

## 容易做错的三处
- 服务器环境上传文件后，文档解析节点返回404错误，无法读取文件内容。原因是服务器部署时未正确配置静态文件访问路径，导致解析节点无法获取上传的文件地址。
- 知识库检索结果仅返回分块的主要文本内容，未包含章节标题与结构化字段。原因是未配置按标题+段落的分块规则，导致标题与关键字段被拆分至不同分块中。
- 批量上传月度监管台账时，解析任务超时失败。原因是未将`PARSE_FILE_TIMEOUT_SECONDS`调整至符合文档长度的取值，无法完成多页台账的完整解析。

## 怎么确认配好了
- 上传一份养老机构备案材料的PDF文档，查看解析后的分块结果，确认章节标题与正文内容处于同一块中。
- 上传一份大小约800MB的运营台账文件，确认解析任务未触发超时错误，可正常完成解析。
- 调整`chunkSize`至600字符与1000字符区间，对比分块后的内容完整性，确认取值适配业务文档的长度特征。
- 测试服务器环境下的文件上传流程，确认解析节点可正常获取文件地址，无404类报错返回。
