# 内控评价、审计与整改的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
本品类的典型数据来自中央企业内控部门、审计部、下属企业及外部审计机构，日常文档包含内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据来源覆盖企业内控系统、ERP、财务共享系统、审计管理系统、采购合同项目系统，更新频率为年度。数据结构以结构化字段与非结构化文本结合，包含问题编号、整改要求、佐证材料编号等专属业务字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
年度更新的频率无需设置高频增量索引，可采用全量定期更新的索引策略。多类型文档的混合存储要求分块策略适配不同文档长度，避免将审计工作底稿的短段落与整改台账的长条目割裂。多系统来源的数据需统一向量编码格式，确保跨系统文档的检索一致性。审计问题与整改记录的强关联属性，要求向量召回优先匹配问题与整改的语义关联，减少人工筛选成本。严格的出错后果要求检索结果具备较高置信度，需精准控制召回范围与相似度阈值。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配内控自评报告、审计工作底稿的常规段落长度，避免跨块割裂审计问题描述 |
| 重叠长度 | 100–150 字符 | 保留跨分块的整改要求关联信息，确保检索时不会遗漏跨段落的完整整改逻辑 |
| 相似度阈值 | 0.75–0.85 | 匹配审计问题与整改记录的语义一致性，过滤无关的通用文档 |
| 单次搜索上限 | 前 8 条 | 覆盖常见审计问题的关联整改台账与佐证材料，满足审计核查需求 |
| `defaultToken` | 4096 | 适配审计通知书、整改销号证明的单份文档文本长度 |
| `maxToken` | 8192 | 承载多份关联文档的上下文信息，满足审计核查的完整证据需求 |

## 容易做错的三处
- 现象：自定义向量数据库连接失败，系统返回配置错误提示。原因：未按照系统要求配置数据库的访问密钥与端口，误将非向量类型的数据库接入。
- 现象：向量召回结果条数远少于预期，仅返回少量文档。原因：未针对审计问题清单、整改台账的专属字段设置过滤规则，导致召回范围被过度限制。
- 现象：模型调用超时，任务执行失败。原因：未设置合理的`defaultToken`与`maxToken`参数，导致单次处理的文本长度超出系统限制。

## 怎么确认配好了
- 上传单份内控自评报告，触发向量索引任务，查看索引生成日志确认分块参数与实际文本匹配。
- 输入模拟审计问题，调用检索功能，核对返回结果是否包含关联的问题清单与整改台账。
- 测试自定义向量数据库连接，查看系统返回的连接状态提示，确认配置正确。
- 调整相似度阈值，观察召回结果的数量变化，确认阈值符合业务需求。
