# 内控评价、审计与整改的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据主要来自企业内控系统、ERP、财务共享系统、审计管理系统、采购合同项目系统，日常包含内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明等文档。数据更新频率为年度，文档涵盖结构化清单与非结构化工作记录两类格式，包含业务样本标识、问题描述、整改要求、佐证材料编号等字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据特征对模型接入与配置带来明确约束：多源异构系统的数据来源要求配置项支持跨系统数据的统一接入与格式适配；年度更新频率决定知识库同步周期无需高频调整，可按年度触发更新；文档包含长文本底稿与结构化清单两类格式，要求模型上下文处理参数适配不同长度的文本输入；需严格保证输出的严谨性，避免生成不符合内控要求的内容，因此模型参数需偏向稳定输出。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配审计工作底稿、整改台账等长文本文档，避免关键上下文被截断 |
| `maxTokens` | 2000–3000 token | 满足审计问题描述、整改要求的输出长度需求，保证信息完整 |
| `temperature` | 0.1–0.3 | 内控审计需严谨输出，降低随机性，避免生成不准确的整改建议 |
| `toolChoice` | auto | 自动选择工具处理多源数据抽取，适配多系统接入的业务流程引导需求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写内网或云端接口地址 | 适配国央企内部部署的模型访问场景，保障数据安全 |
| `AIPROXY_API_TOKEN` | 按企业安全规范配置专属令牌 | 符合内控要求，保障内部模型调用的身份验证安全 |

## 容易做错的三处
- 现象：调用模型时返回连接超时错误，或接口返回403权限拒绝。原因：未配置国央企内部网络的代理规则，或`AIPROXY_API_TOKEN`未按企业安全规范更新，导致身份验证失败。
- 现象：添加知识库后模型输出空结果或关键字段缺失。原因：未针对审计工作底稿的长文本调整`maxContext`参数，导致上下文被截断，业务样本、整改要求等关键信息丢失。
- 现象：模型生成的整改建议与实际业务场景偏差较大。原因：`temperature`取值过高，导致输出随机性过大，不符合内控审计的严谨性要求。

## 怎么确认配好了
- 访问配置的`AIPROXY_API_ENDPOINT`，验证接口连通性，确认返回符合FastGPT v4.17.0版本的标准响应格式。
- 上传单份审计工作底稿文档，发起测试请求，查看模型抽取的业务样本、问题描述等内容是否完整，无截断情况。
- 发起一次业务办理流程引导的测试请求，确认模型自动调用适配工具处理多源数据，生成符合审计流程的引导内容。
- 检查系统日志，确认`AIPROXY_API_TOKEN`验证通过，无权限报错或连接异常记录。
