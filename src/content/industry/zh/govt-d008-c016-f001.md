# 医保费用结算审核的业务办理流程引导：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据来自全国医疗保障信息平台、医院HIS和医保接口、医保目录和编码库、异地就医结算平台，更新频率为每日。日常处理的文档包含医保结算清单、费用明细、病案首页、处方、拒付清单、结算对账单，字段涵盖诊疗项目编码、药品耗材编码、费用金额、结算单号、参保人身份标识等，单位包含元、日期、标准编码编号等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据来源的多样性要求需适配多套外部接口的格式规范，每日更新的频率需配置定时拉取任务以覆盖全量当日结算数据；多字段编码校验的业务需求，要求接口参数需携带标准化诊疗项目、药品耗材编码；单笔或批量结算的处理规模，需匹配医保平台的接口限流规则，避免触发调用限制；出错可能导致基金争议或回款延迟，要求接口调用需配置异常重试与完整日志留存机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer ${external_token}` | 符合医保外部接口的身份校验要求，避免未授权访问 |
| `variables` | `{"batch_size": 150, "settle_date": "2024-05-20"}` | 适配批量结算审核的日更新数据拉取需求，控制单次请求规模 |
| `responseData` | `$.data.list[*]` | 匹配多数医保接口返回的标准数据结构，提取有效结算明细 |
| 请求超时时间 | `30-60 秒` | 适配医保平台的接口响应负载波动，预留足够的处理时长 |
| 批量请求上限 | `100-200 条/次` | 符合医保平台的接口调用限流规范，避免触发拦截 |
| 变量注入规则 | 按业务参数动态注入 | 适配不同结算批次的动态参数需求，支持批量任务的参数区分 |

## 容易做错的三处
- 接口返回字段为空，无法提取有效结算明细。原因是未正确配置`responseData`的解析路径，导致无法从接口返回结果中提取目标数据。
- 请求返回401未授权错误。原因是未通过`variables`注入动态外部接口token，使用了固定过期的身份凭证。
- 请求头重复携带Bearer令牌。原因是未关闭自动Bearer补充配置，导致手动配置的`Authorization`与系统自动添加的令牌重复，触发身份校验失败。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，调用测试接口，查看返回的`responseData`是否包含结算明细、费用金额等业务字段。
- 触发批量请求任务，检查接口调用日志的`variables`参数是否与预设的业务参数一致。
- 验证`Authorization`头的格式是否符合外部接口的身份校验要求，无重复令牌或格式错误。
- 模拟接口超时场景，确认系统触发了预设的重试机制并留存了完整调用日志。
