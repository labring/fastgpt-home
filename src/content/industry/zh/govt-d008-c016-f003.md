# 医保费用结算审核的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源于全国医疗保障信息平台、医院HIS与医保接口、医保目录和编码库、异地就医结算平台，更新频率为每日。日常处理的文档包含医保结算清单、费用明细、病案首页、处方、拒付清单、结算对账单，数据字段涵盖诊疗项目编码、药品耗材编码、费用金额、参保人身份标识、就诊机构信息等，单份文档长度随结算笔数变化，批量场景下单次处理的数据量存在较大波动。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据来源分散、文档类型多样且更新频率固定，对多轮对话与提示词环节带来多重约束。需通过多轮对话逐步校验不同来源的诊疗项目、药品耗材编码一致性，避免匹配错误引发基金风险；需在提示词中配置实时调用当日更新的医保目录库的逻辑，确保编码匹配的时效性；需引导用户按结算清单、费用明细、拒付清单的顺序提交材料，适配不同文档的字段校验逻辑；批量处理场景下，需通过多轮对话拆分任务，避免单次处理超出上下文承载上限，引发格式或索引错误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前结算审核任务的唯一标识 | 关联多轮对话的上下文，确保不同审核任务的会话隔离，避免数据混淆 |
| `messages` | 按「系统提示+用户输入+中间校验结果」的顺序拼接 | 适配医保审核的多步骤校验逻辑，完整保留每一轮的编码匹配、费用核对记录 |
| `variables` | 注入当日医保目录编码库快照 | 匹配业务数据的日更新频率，确保审核使用最新的医保编码与目录规则 |
| 上下文窗口大小 | 8000–12000 token | 容纳单份或批量结算相关文档的完整内容，避免关键编码、费用字段被截断 |
| 单次对话处理上限 | 50条结算明细/次 | 适配系统接口的承载能力，避免因数据量过大触发异常报错 |
| 错误重试次数 | 3次 | 处理接口调用或编码匹配失败的场景，减少人工介入的概率 |

## 容易做错的三处
- 现象：执行批量结算审核任务时，界面显示任务正常完成但返回`The value of "offset" is out of range`报错。原因：未按批次拆分批量结算单，单次传入的上下文长度超出系统承载上限，导致索引偏移错误。
- 现象：多文件提交审核时，仅部分文档被系统识别处理。原因：未在`messages`参数中按要求格式嵌套多文件的内容标识，导致系统无法完整读取所有提交的结算相关材料。
- 现象：对话过程中出现依赖缺失提示，导致审核流程中断。原因：未在任务启动前配置固定运行环境，每次对话虚拟机重新初始化后缺少医保目录匹配所需的依赖包。

## 怎么确认配好了
- 查看会话上下文记录，确认`chatId`绑定了当前结算审核任务的唯一标识，无跨任务的上下文混淆情况。
- 测试提交单份结算清单，检查`messages`参数是否按系统提示、用户输入、中间校验结果的顺序拼接，无关键字段遗漏。
- 触发批量审核任务，核对变量调用是否实时获取当日的医保目录数据，确保编码匹配使用最新规则。
- 模拟依赖缺失场景，确认任务启动时已加载所需依赖包，无中断报错。
