# 医保费用结算审核的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源包括全国医疗保障信息平台、医院HIS和医保接口、医保目录和编码库、异地就医结算平台。数据更新频率为日度。日常处理的文档包含医保结算清单、费用明细、病案首页、处方、拒付清单、结算对账单，整体为结构化格式，核心字段包含标准化诊疗项目/药品耗材编码、费用金额、参保人信息、结算时间，无自定义非标准化字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源多且涉及公共服务敏感信息，要求模型接入需适配合规的接口节点与权限控制；日度更新的数据源要求配置的知识库同步频率匹配日度更新节奏，避免数据滞后；结构化文档包含大量标准化编码字段，要求模型上下文长度需覆盖多份文档的核心信息，避免截断关键编码与费用数据；单笔或批量结算审核的业务场景，要求模型输出需兼顾单条判定与批量对账的长度需求，同时降低随机偏差以保障审核准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖多份医保结算相关文档的核心上下文，避免截断标准化编码与费用信息 |
| `maxTokens` | 4000–6000 token | 适配单次审核结果的输出长度，包含编码匹配说明、拒付判定依据与对账内容 |
| `temperature` | 0.1–0.3 | 降低随机生成概率，确保编码匹配与费用审核的结果一致性，符合业务严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 按平台提供的专属节点填写 | 适配医保数据传输的合规性要求，避免跨区域接口限制 |
| `AIPROXY_API_TOKEN` | 绑定专属权限的密钥 | 保障医保敏感数据的访问安全，符合公共服务数据安全规范 |

## 容易做错的三处
- 进入工作台编辑页面报错“未配置语言模型”，原因是未正确填写`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`参数，导致平台无法识别可用模型
- 工作流问题分类中AI模型选项为空，原因是未在全局配置中完成模型接入，或配置的模型未适配当前工作流的权限范围
- 提示“模型流响应为空，请检查模型流输出是否正常”，原因是`maxTokens`设置过小，导致模型输出被截断为空，或接口请求超时未返回有效内容

## 怎么确认配好了
- 登录FastGPT v4.17.0版本的全局模型配置页面，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`参数填写无误，无格式错误或空格遗漏
- 上传单份医保结算清单发起测试，查看模型输出是否包含诊疗项目编码匹配结果、费用与处方一致性判定内容
- 导入批量结算清单进行测试，确认模型能正常处理多份文档，无上下文截断报错
- 查看接口调用日志，确认请求返回状态码为200，无超时或权限错误提示
