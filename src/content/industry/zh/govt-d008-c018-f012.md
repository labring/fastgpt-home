# 参保登记与缴费核定的业务办理流程引导：部署与升级

## 这个品类的数据长什么样
本品类的数据来自社会保险经办系统、税务社保费征收系统、市场主体登记信息及公安民政数据共享渠道。日常处理的文档包含参保登记表、缴费基数申报表、人员增减表、社保费核定单与个人权益记录，以结构化表单和报表为主，包含人员身份、劳动关系、缴费基数、单位规模等字段。数据更新频率为每日，需同步多系统的增量信息，支撑业务办理的实时校验与流程引导。

## 这些特征在「部署与升级」这一环带来什么约束
多源数据对接要求部署时配置跨系统的访问权限与数据同步规则，日更的增量数据需要适配高频写入的数据库连接配置。结构化文档的字段关联性强，分段处理时需避免破坏人员身份、劳动关系等关联字段的完整性。离线部署场景下需规避对外部接口的依赖，否则会导致文件上传、数据同步等环节卡顿。同时，参保数据的敏感性要求配置加密与访问控制规则，保障数据合规。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `REDIS_URL` | `redis://:内网数据库密码@内网主机地址:6379/0` | 缓存高频的社保数据查询请求，降低多系统对接的数据库负载，适配内网部署场景 |
| `MONGODB_URI` | `mongodb://用户名:密码@内网主机地址:27017/fastgpt?authSource=admin` | 存储参保人员的增量更新数据，支持每日批量写入的高并发操作 |
| `STORAGE_S3_ENDPOINT` | `内网S3兼容存储服务地址` | 存储参保登记表、缴费核定单等敏感文档，实现离线环境下的文件备份与调用 |
| `DB_MAX_LINK` | `20–30 个连接` | 适配社保业务的并发查询峰值，避免数据库连接耗尽导致的服务中断 |
| `FILE_TOKEN_KEY` | `自定义加密密钥` | 保障参保人员敏感信息的传输与存储安全，符合政务数据合规要求 |
| `FE_DOMAIN` | `内网业务访问域名` | 配置业务办理流程引导页面的访问路径，适配内网用户的访问需求 |

## 容易做错的三处
- Docker 部署后无法启动，日志提示数据库连接超时。未正确配置`MONGODB_URI`或`REDIS_URL`，内网部署时使用了公网数据库地址，导致无法连通。
- 离线部署时知识库上传文件一直处于转圈圈状态，联网后恢复正常。未配置离线可用的存储服务，依赖外部接口校验文件合法性，导致离线场景下任务卡住。
- 文本导入参保登记表时未调整分段，出现人员身份字段与单位信息不匹配的错误。默认分段逻辑破坏了结构化文档的字段关联性，导致后续流程引导无法正确匹配关联数据。

## 怎么确认配好了
- 执行FastGPT内置的数据库连通性测试脚本，验证`MONGODB_URI`与`REDIS_URL`配置的地址可正常建立连接。
- 上传一份模拟的参保登记表，检查文件上传进度是否在120秒内完成，无报错或卡顿。
- 配置日更数据同步任务，查看系统是否能正常拉取社保经办系统的增量数据，无数据丢失或异常提示。
- 访问`FE_DOMAIN`配置的内网域名，确认业务办理流程引导页面可正常加载所有静态资源。
