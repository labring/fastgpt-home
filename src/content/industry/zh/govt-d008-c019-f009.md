# 双随机、一公开监管检查的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库，更新频率为月度。日常业务文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示，各文档对应明确的监管流程节点，字段涵盖监管主体、检查对象基础信息、检查事项明细、执法人员信息、整改要求及公示状态等，无额外自定义扩展字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据需要定期执行向量库同步任务，避免模型调用过时的检查对象或事项清单。检查对象名单、执法人员名录等结构化数据需严格匹配预设字段，防止出现监管对象抽取不合规的问题。抽查结果公示文档需与对应现场检查记录关联绑定，确保生成的流程引导内容与已公示信息一致。单次调用需覆盖多类业务文档，需合理限制上下文长度，避免超出模型负载同时保证执法流程的完整性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 需容纳抽查计划、检查对象清单等多类文档，避免截断关键监管信息 |
| `maxTokens` | 2000–3000 token | 控制单轮回复长度，确保流程引导内容完整且符合执法文书规范 |
| `quoteMaxToken` | 4000 token | 限制引用的业务文档总长度，避免干扰核心流程引导的生成 |
| `temperature` | 0.3–0.5 | 保证流程引导的严谨性，避免生成不符合监管要求的个性化内容 |
| AIPROXY_API_ENDPOINT | 本地监管内网API地址 | 确保数据调用符合保密要求，仅在合规网络内传输 |
| `toolChoice` | none | 当前场景为流程引导，无需调用外部工具，聚焦于现有业务文档的整合生成 |

## 容易做错的三处
- 现象：模型调用超时，返回状态码504或无有效回复。原因：未限制`maxContext`参数，导致上下文过长超出模型处理阈值。
- 现象：生成的流程引导中出现未公示的检查对象信息。原因：未配置月度同步向量库的任务，使用了过时的检查对象名单数据。
- 现象：回复内容包含过于灵活的表述，不符合监管执法的严谨要求。原因：将`temperature`参数设置过高，导致生成内容偏离规范的执法流程引导。

## 怎么确认配好了
- 执行一次业务流程引导测试，核对生成内容中引用的检查对象、检查事项是否与当前最新的月度更新数据一致。
- 查看向量库同步日志，确认月度数据同步任务已按计划完成。
- 调整`temperature`参数并对比多轮回复内容，确保生成的引导内容严谨合规。
- 测试多类业务文档同时输入的场景，确认未出现关键信息被截断的情况。
