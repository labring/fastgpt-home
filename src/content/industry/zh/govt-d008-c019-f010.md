# 双随机、一公开监管检查的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据主要来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统、执法人员名录库，更新频率为月度。日常文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示，覆盖结构化清单类与非结构化记录类两类格式，字段包含监管对象标识、检查事项条目、执法人员信息、检查结果状态等，无统一固定的单文档字段标准。

## 这些特征在「知识库检索与召回」这一环带来什么约束
月度更新的特性要求知识库需支持每30天一次的增量同步，避免全量重新索引带来的资源消耗。多类型文档的结构差异，要求检索机制需兼顾结构化字段匹配与非结构化文本语义理解。数据来源分散且需限定监管专属范围，要求检索需支持指定数据集的精准召回，避免无关数据干扰。同时，监管流程对检查结果公示的准确性要求较高，召回结果的匹配精度直接影响后续执法流程的合规性，需严格控制低匹配度结果的混入。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的功能逻辑制定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配监管对象信息、检查事项的精确性要求，避免低匹配度的无关结果混入 |
| `limit` | 前8–12 条 | 适配单次检查任务的文档调用量，平衡召回完整性与模型上下文承载能力 |
| `searchMode` | 混合检索 | 兼顾结构化清单类文档的字段匹配与非结构化记录类文档的语义检索效果 |
| `usingReRank` | 开启 | 对召回结果进行二次排序，修正单一向量匹配的偏差，确保高优先级检查事项靠前展示 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展检索词范围，覆盖检查事项的同义词、执法场景常用表述，提升召回覆盖率 |
| `collectionIds` | 绑定对应监管专属数据集 | 限定检索范围在双随机监管相关文档库，避免非监管类数据干扰检索结果 |

## 容易做错的三处
- 上传检查对象名单文件时出现`failed to create post presigned url`报错。原因是迁移S3存储后未正确配置跨域资源共享规则，导致生成预签名URL失败。
- 检索结果未命中指定的检查事项清单文档。原因是未通过`collectionIds`绑定专属数据集，检索范围覆盖了非监管类文档。
- 单次召回结果过多导致上下文溢出。原因是未设置合理的`limit`参数，默认召回条数超出模型上下文承载上限。

## 怎么确认配好了
- 上传一份测试用的抽查计划文档，检查是否能正常完成上传与解析，无`failed to create post presigned url`类报错。
- 输入“2024年第二季度市场监管抽查计划”关键词，确认检索结果仅包含绑定数据集内的相关文档。
- 查看检索返回的结果条数，确认与`limit`参数设置的前8–12条取值一致。
- 触发检索后查看结果排序，确认高优先级的检查事项条目排在结果前列，验证`usingReRank`功能生效。
