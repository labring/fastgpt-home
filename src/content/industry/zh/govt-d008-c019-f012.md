# 双随机、一公开监管检查的业务办理流程引导：部署与升级

## 这个品类的数据长什么样
该品类的核心数据来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库，日常文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示。数据更新频率为月度，核心流程中维护检查事项与对象库、匹配执法人员生成任务、录入检查结果并公示为最耗时环节，数据字段多涉及监管主体资质、检查事项细则、检查对象信用信息等。

## 这些特征在「部署与升级」这一环带来什么约束
月度更新的数据需要稳定的批量增量同步能力，部署时需适配多源异构数据的接入配置。检查对象与执法人员名单涉及敏感监管数据，需配置严格的权限隔离与存储加密规则。现场检查记录与公示结果的文档格式多样，部署需预留非结构化数据的解析适配空间。流程中存在多环节数据校验需求，部署需预留足够的数据库连接资源以支撑高频读写，避免因数据同步导致业务中断。同时，监管检查的流程引导需绑定固定的业务字段，升级时需保证配置的兼容性，避免破坏现有业务链路。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写，以下配置项针对双随机、一公开监管检查的业务场景制定：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `200–300` | 该品类月度批量同步监管数据时存在高频数据库连接需求，该取值可平衡连接资源占用与并发处理能力 |
| `STORAGE_S3_ENDPOINT` | 按本地监管内网存储节点实际地址配置 | 该品类的现场检查记录、公示文档多存储于内网存储节点，需匹配对应访问端点以保障数据安全 |
| `REDIS_URL` | `redis://:自定义密码@内网IP:6379/0` | 用于缓存执法人员名录、检查对象名单等高频访问的静态数据，内网部署可保障访问速度与安全性 |
| `MONGODB_URI` | `mongodb://用户名:密码@内网IP:27017/fastgpt?authSource=admin` | 存储抽查计划、检查结果等非结构化业务数据，适配多源文档的存储需求 |
| `ROOT_KEY` | 按政务内网安全策略生成的32位随机字符串 | 用于管理员权限验证，保障监管业务后台的访问安全，符合政务系统权限管理要求 |

## 容易做错的三处
- 现象：Docker部署后出现磁盘读写量异常升高，单月读写量超出存储硬件负载阈值。原因：未限制数据库连接池大小，高频并发同步监管数据时触发大量磁盘读写操作，导致硬件过载。
- 现象：部署compose文件启动失败，提示数据库连接参数格式错误。原因：混用了不同类型数据库的连接配置模板，未针对该品类的多源数据存储需求调整参数，存在低级配置错误。
- 现象：无法在arm64架构服务器上启动服务。原因：未使用适配arm64架构的镜像版本，默认镜像仅支持x86架构，无法适配政务内网常用的国产化服务器硬件。

## 怎么确认配好了
- 查看数据库连接池运行状态，确认`DB_MAX_LINK`的配置值与实际活跃连接数匹配，无频繁连接超时或溢出情况。
- 尝试导入月度更新的检查对象名单数据，验证存储配置可正常写入非结构化文档，无权限报错或写入失败。
- 访问`FE_DOMAIN`配置的访问域名，验证管理员登录功能可通过`ROOT_KEY`完成权限验证，无访问异常。
- 检查`REDIS_URL`配置的缓存服务，确认高频访问的执法人员名录数据可正常缓存，无读取延迟过高情况。
