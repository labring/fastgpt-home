# 国库集中支付与报销审核的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自国库集中支付系统、预算管理一体化系统、电子发票平台、合同管理系统，按日更新。日常涉及的文档包括支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，各文档包含预算指标、经济分类、票据信息、合同条款、验收结果、审批流程等字段，单笔业务数据关联多类业务单据，需匹配多系统的字段一致性。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多系统数据源要求对话需关联国库集中支付、预算管理一体化等多平台的字段，确保指标、票据等信息跨系统匹配。日更新频率要求对话实时拉取当日最新的预算指标数据，避免使用过期信息。多类业务文档需提示词明确区分支付申请、报销审批等不同单据的校验逻辑，引导用户按环节提交对应材料。单笔资金关联多单据的特性要求多轮对话需逐步收集完整的合同、验收、审批链条信息，避免漏项。同时需嵌入合规校验逻辑，防范支付退回、资金错付等风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 上下文窗口大小 | 8000–12000 token | 适配多类业务文档的字段长度，避免截断关键的预算指标、合同条款信息 |
| 变量绑定 | 绑定`variables`中的预算指标ID、发票号码 | 关联多系统的实时数据，确保对话引用的单据信息准确，符合FastGPT v4.17.0的变量调用规范 |
| 对话历史调用 | 开启`messages`全量记录 | 完整保留审核环节的退单、更正记录，便于回溯业务流程 |
| 插件调用日志 | 开启日志存储，保留时长7天 | 匹配业务单据的日更新周期，便于核对支付与报销的执行记录 |
| 最大对话轮次 | 前10轮 | 覆盖从用款计划到支付凭证的完整流程，避免无效长对话 |
| 对话触发规则 | 按用户输入的单据类型匹配 | 对应不同业务文档的校验规则，引导用户按环节提交材料 |

## 容易做错的三处
- 调用关联电子发票平台的插件时，对话日志未记录发票核验结果。未开启插件调用的日志绑定配置，导致`chatId`未关联插件执行上下文。
- 嵌套工作流中的表单输入节点对话框始终显示。未在嵌套配置中设置外部调用时的对话框隐藏规则，与单工作流内的触发逻辑不一致。
- 对话中尝试渲染网页或文生图内容无响应。未配置允许富媒体渲染的节点参数，且未绑定对应模型的调用权限。

## 怎么确认配好了
- 发起一笔模拟支付申请对话，检查对话历史模块是否完整记录每一轮交互与单据信息。
- 调用关联电子发票平台的插件，查看日志模块是否生成对应核验记录。
- 配置嵌套工作流并触发，确认表单对话框仅在单工作流内触发时显示，嵌套调用时隐藏。
- 提交包含完整合同条款的对话，检查未出现内容截断提示，确认上下文窗口配置生效。
