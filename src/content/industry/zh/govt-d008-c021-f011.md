# 国库集中支付与报销审核的业务办理流程引导：表单与交互

## 这个品类的数据长什么样
该品类的日常业务文档包含支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，数据来源为国库集中支付系统、预算管理一体化系统、电子发票平台、合同管理系统，更新频率为每日。文档多兼具结构化字段与非结构化附件，核心字段涉及预算指标、经济分类、票据编号、合同金额等，单位多为元、件、批次等，需关联多系统跨模块数据完成合规校验。

## 这些特征在「表单与交互」这一环带来什么约束
多源数据来源要求表单交互需支持跨系统字段拉取与自动校验，避免人工录入错误；高频日更数据要求表单实时同步最新预算指标与票据状态，确保校验时效性；核心字段的强关联要求表单需保留预算指标与经济分类、票据合同的从属关系，否则会影响合规审核；单笔支付的高合规要求，要求交互环节加入实时校验提示，对不匹配内容及时反馈。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `formInput` | 绑定预算指标、经济分类字段 | 覆盖品类核心校验环节，直接拉取系统内结构化字段值 |
| 单次召回上限 | 前10条 | 覆盖单笔支付关联的票据、合同、验收单等多类文档 |
| 分块长度 | 800–1200字符 | 适配报销审批单、支付凭证等单份文档的平均内容长度 |
| 重排 | 开启 | 优先召回与当前支付申请关联的合规文档 |
| 最大上下文 | 6000 token | 容纳多系统拉取的全流程单据数据 |
| 超时阈值 | 60秒 | 适配国库系统接口的常规响应时长 |

## 容易做错的三处
- 现象：知识库导入报销审批单的markdown文档后，预算指标字段与审批内容的从属关系丢失。原因：直接按段落拆分文档，未通过`formInput`绑定结构化字段，导致核心关联逻辑被破坏。
- 现象：业务办理时需手动点击交互按钮才能触发知识库检索。原因：未配置`formInput`的自动触发规则，未实现表单填写完成后自动唤起检索。
- 现象：检索结果中出现大量不关联当前支付申请的票据文档。原因：未设置按预算指标、经济分类字段过滤召回内容，导致召回范围过大。

## 怎么确认配好了
- 打开FastGPT v4.17.0的表单配置页面，确认`formInput`已绑定预算指标、经济分类等核心业务字段
- 测试填写表单的预算指标与经济分类字段，确认系统自动触发知识库检索，无需手动点击交互按钮
- 输入包含具体经济分类关键词的提问，确认检索结果优先返回对应合同、发票文档
- 导入单份报销审批单的markdown文档，确认字段层级关系未被破坏
