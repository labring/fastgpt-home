# 学生资助与奖补审核的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的核心数据来自全国学生资助管理信息系统、学校学籍系统、民政低保特困数据、财政支付系统，更新周期为学期。日常处理的文档包含家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单、公示材料，字段覆盖学生身份信息、家庭经济状况、学籍状态、资金发放明细等，单份文档包含结构化字段与非结构化说明内容。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据更新周期为学期，对话的知识库无需高频刷新，可按学期周期批量同步。文档类型多样且字段关联多系统数据，提示词需明确引导用户按文档字段提交信息，同时需关联外部系统数据进行核验。多轮对话需覆盖从申请提交到发放确认的完整流程，需保留会话上下文避免重复提问。同时，因出错后果涉及资金发放与学生权益，对话需严格限定检索范围为学生资助相关文档，避免无关信息干扰。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前学生资助申请的唯一会话标识 | 区分不同学生的办理对话，避免上下文混淆 |
| `messages` | 保留前20轮对话上下文 | 适配学期内长周期的完整申请流程，覆盖多轮交互 |
| `variables` | 传入学生学籍号、家庭低保状态变量 | 关联外部系统的固定数据，减少用户重复输入 |
| 单次搜索上限 | 前8条匹配文档 | 覆盖家庭经济情况、学籍、资金发放的多类核心文档 |
| 最大上下文 | 8000–10000 token | 适配多轮对话的完整流程信息，避免上下文溢出 |
| 问题优化 | 开启 | 将用户口语化咨询转化为标准化的资助审核查询条件 |

## 容易做错的三处
- 对话中出现非学生资助类的知识库引用。原因是未在提示词中明确限定检索范围，或未绑定指定的学生资助知识库ID。
- 解析上传文档时自动加载历史已上传的文档。原因是未在会话配置中关闭历史文档关联加载，或未指定仅处理当前上传的附件。
- 传入知识库ID变量后触发系统报错。原因是未正确配置`variables`参数的绑定规则，或变量格式不符合系统要求。

## 怎么确认配好了
- 发起测试对话，输入非学生资助相关的咨询，确认未返回学生资助类文档内容。
- 上传单份资助申请表，触发解析流程，确认仅当前上传的文档被加载处理。
- 传入预设的`variables`参数，查看对话中是否自动调用对应外部系统的固定数据。
- 连续发起多轮咨询，确认上下文未出现混淆，且每次检索都返回指定数量的匹配文档。
