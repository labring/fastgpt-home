# 安全生产隐患排查治理的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
典型主体包括应急管理部门、行业主管部门、生产经营单位安全管理部门、园区管委会。日常生成的文档包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单。数据来源为安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。文档包含排查时间、隐患位置、整改责任人、整改期限、复查结果等字段，单份文档长度差异较大，从几十字符的整改通知书条目到数百字符的排查清单全文不等。本页面配置基于FastGPT v4.17.0版本。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的数据源要求索引支持增量同步，避免全量重建带来的资源消耗。多来源的异构数据需要统一的字段映射规则，确保不同系统导出的文档能被一致处理。文档类型多样且长度差异大，需要适配不同的切分策略以保留关键信息。隐患排查相关内容对准确性要求极高，向量检索的召回结果需严格匹配业务场景的关键词，不能出现无关内容。此外，业务办理流程引导场景下的检索结果需与当前办理的隐患事项强关联，不能返回历史无关的排查记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 600–800 字符 | 适配隐患排查清单、整改通知书等常见文档的长度，保留单条隐患的完整上下文 |
| 重叠长度 | 100–200 字符 | 避免切分后关键信息断裂，确保相邻块的关联内容被完整保留 |
| 相似度阈值 | 0.75–0.85 | 匹配隐患排查的精准检索需求，过滤低相关性的历史记录 |
| 单次搜索上限 | 前 5 条 | 符合业务办理流程引导的单次调用场景，避免返回过多冗余信息 |
| `defaultToken` | 对应向量模型的访问密钥 | 用于验证模型调用权限，确保嵌入请求正常发起 |
| `maxToken` | 8192 token | 适配主流向量模型的输入长度限制，避免嵌入请求因超限失败 |

## 容易做错的三处
- 调用向量模型时返回401未授权错误。原因是未正确配置`defaultToken`，或密钥权限不足，无法发起嵌入请求。
- 知识库自动删除重复文档块，导致自定义切分的索引顺序错乱。原因是默认开启了文档去重配置，且未保留切分时的原始顺序标记。
- 使用自定义渠道添加向量模型时，请求始终被路由为大语言模型调用。原因是未在配置中明确标注向量模型类型，导致路由规则匹配错误。

## 怎么确认配好了
- 上传单份隐患排查清单文档，等待嵌入完成后查看嵌入状态日志，确认无失败提示。
- 进入知识库设置页面，检查文档去重配置项的开关状态，确认是否符合业务需求。
- 发起一次业务办理流程引导的测试查询，验证返回的检索结果条数符合单次搜索上限的设置。
- 查看向量模型的调用日志，确认`defaultToken`已被正确携带，无权限报错信息。
