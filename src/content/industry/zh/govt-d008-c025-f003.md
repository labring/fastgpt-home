# 安全生产隐患排查治理的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源包括安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常文档包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，文档结构包含隐患描述、责任主体、整改要求、闭环状态等字段，各文档间通过统一的隐患编号关联。数据覆盖从排查发现到销号归档的全流程环节，字段对应业务办理的核心节点，为多轮对话提供标准化的业务信息支撑。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源多且分散，要求多轮对话需整合不同系统的字段信息，避免出现信息割裂。每日更新的特性要求对话上下文需同步最新的排查、整改数据，确保回复内容符合当前业务状态。文档类型多且字段明确，提示词需指定提取对应字段，确保对话中不遗漏整改责任人、复查记录等核心信息。最耗时的对照标准排查、跟踪整改、复查销号环节，要求多轮对话需按流程引导用户逐步完成信息录入，同时校验必填字段的完整性，防止流程中断。

## 配置怎么定
在FastGPT v4.17.0版本下，可按以下配置项进行设置：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 多轮对话上下文长度 | 800–1200 字符 | 适配日常隐患排查的对话轮次和业务文档长度，避免上下文过载 |
| `variables` 绑定 | 绑定隐患清单、整改台账的业务字段 | 实现在对话中调用本地标准化业务数据 |
| 会话超时时间 | 600 秒 | 覆盖从隐患排查到复查销号的完整流程耗时 |
| 消息历史保留条数 | 前 5 条核心对话 | 减少冗余信息对响应速度的影响，保留关键流程节点 |
| 变量校验规则 | 校验整改责任人、复查记录字段非空 | 确保业务流程的必填信息完整，避免流程中断 |
| 问题优化 | 开启 | 简化用户输入的非标准化表述，匹配业务文档的字段格式 |

## 容易做错的三处
- 现象：调用对话接口时返回400状态码，提示必填字段缺失。原因：未在请求中正确传入`chatId`或`messages`参数，无法建立或延续多轮对话的上下文关联。
- 现象：生成的回复未关联本地隐患排查清单或整改台账内容。原因：提示词未绑定`variables`对应的业务数据字段，仅依赖通用知识库生成内容。
- 现象：对话流程中断且无法推进整改步骤。原因：未设置变量校验规则，导致未收集整改责任人、复查记录等必填字段就进入下一环节。

## 怎么确认配好了
- 发起测试对话，输入“排查某区域的电气隐患”，查看回复是否自动关联本地隐患清单中的对应条目。
- 测试多轮对话，依次输入“整改责任人是张三”“复查结果合格”，查看系统是否能保留上下文并在后续步骤中引用这些信息。
- 调用接口时传入`chatId`和`messages`参数，检查返回结果是否包含正确的业务字段和上下文关联内容。
- 模拟超时场景，设置短超时时间发起对话，确认是否触发超时提示，验证超时配置生效。
