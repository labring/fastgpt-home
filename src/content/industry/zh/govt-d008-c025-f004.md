# 安全生产隐患排查治理的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
数据来自安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为日。日常业务文档包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，包含隐患唯一标识、排查主体、整改责任人、整改时限、复查结果等核心字段，覆盖隐患从排查到归档的全流程记录。

## 这些特征在「工作流编排」这一环带来什么约束
日更的数据特征要求工作流支持高频调度与实时数据拉取，避免因数据延迟导致流程脱节。多类业务文档的存在要求工作流适配不同节点类型，比如表单节点对应整改通知书的填写，知识库节点对应重大事故隐患判定标准的查询。多源数据接入的需求要求工作流的`variables`配置支持结构化映射，统一不同系统的输入格式。同时，隐患排查、整改跟踪、复查归档是最耗时的环节，需将流程拆分为独立节点，且需配置失败处理分支，应对排查不通过、整改逾期等异常情况，避免引发严重后果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `variables` | 按业务文档字段映射的结构化变量集合，包含隐患ID、整改责任人、整改期限等字段，格式为`{"隐患ID":"string","整改责任人":"string","整改期限":"date"}` | 日常业务文档包含多类核心字段，需统一变量格式以适配全流程节点 |
| `nodeId` | 为每个可复用节点配置唯一标识字符串，例如`"node_review_001"` | 支持跨分支复用已配置节点，避免链路识别冲突 |
| 变量引用规则 | 使用双大括号包裹变量名，例如`{{整改期限}}`，变量名仅包含中文、英文与下划线 | 避免`quote type error`报错，严格匹配变量命名规范 |
| 工具调用分支设置 | 配置为单分支执行模式，仅执行当前选中的节点分支 | 避免工具调用与AI回复同时执行的并行问题 |
| 工作流超时阈值 | 设置为600秒 | 适配多源数据拉取与业务处理的耗时需求，避免流程中断 |
| 触发模式配置 | 配置为按日定时触发+手动触发双模式，定时触发时间设为每日0点 | 匹配数据日更的更新频率，覆盖日常调度与应急处理场景 |

## 容易做错的三处
- 现象：跨分支复用填写表单节点时，流程无法跳转至目标节点。原因：未为节点配置唯一`nodeId`标识，或节点ID重复导致链路识别冲突。
- 现象：API调用嵌套知识库助手的工作流返回空值。原因：未通过`variables`正确传递上下文参数，或使用FastGPT v4.8.10（不包含）以上版本时未适配链路更新逻辑。
- 现象：使用变量引用时弹出`quote type error`报错。原因：变量未使用双大括号包裹，或变量名称包含未转义的特殊字符，未匹配预设的变量命名规则。
- 现象：工具调用与AI回复同时执行，触发多分支并行。原因：未开启单分支执行配置，未限制仅执行当前选中的节点分支。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的平台，手动触发测试工作流，提交一条模拟隐患数据，检查节点是否按预期跳转，跨分支复用节点是否正常调用。
- 调用API触发工作流，检查返回结果是否包含预期的隐患处理节点输出，无空值返回。
- 输入带变量的测试文本，检查是否弹出`quote type error`报错，变量引用是否正常解析。
- 配置工具调用节点并触发流程，检查是否仅执行单分支，无并行执行现象。
