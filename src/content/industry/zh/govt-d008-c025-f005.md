# 安全生产隐患排查治理的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源于安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常涉及的文档包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单。数据字段包含隐患等级、整改责任主体、整改期限、复查结果等，无统一固定单位，部分字段需匹配对应业务表单格式。数据处理需覆盖排查、整改、复查全流程的闭环记录，支撑隐患治理的全环节校验。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源包含多套业务系统，工具调用需适配多源接口的调用格式与权限校验规则。每日更新的频率要求工具调用的同步逻辑需匹配日级数据刷新节奏，避免数据滞后。多类型业务文档的处理需求，要求工具调用支持不同字段的提取与映射规则配置。隐患排查与整改的闭环流程，要求工具调用的结果需关联对应业务台账，确保数据链路完整。高风险的出错后果，要求工具调用需具备状态校验与异常拦截能力，防止错误数据流入后续环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `toolChoice` | 设为 `auto`，允许调用指定隐患排查相关工具 | 适配业务中需要动态选择排查、整改、复查工具的场景 |
| `functionCall` | 开启 | 支持结构化提取隐患台账、整改通知书中的字段，满足业务数据流转需求 |
| 并发调用上限 | 3–5 次/秒，按实测标定 | 适配安全生产业务系统的接口调用频率限制，避免触发限流 |
| 重试次数 | 2 次 | 应对临时网络波动或接口限流导致的调用失败 |
| 工具调用超时时间 | 60 秒 | 匹配隐患排查、整改校验等业务环节的平均处理时长 |
| 最大上下文长度 | 8000–12000 token | 容纳多份业务文档的完整内容，避免截断关键隐患信息 |

## 容易做错的三处
- 触发接口限流报错，返回 429 状态码。原因是未配置合理的并发调用上限，并发请求超出安全生产业务系统的接口限制。
- 工具调用结果无法传递至下一轮对话模块。原因是未开启`functionCall`的结构化输出开关，导致结果为非标准化文本，无法被后续模块解析。
- 全局变量更新后未生效，工具调用时仍使用旧值。原因是未在工具调用配置中绑定全局变量的作用域，导致变量更新仅作用于当前对话上下文，未同步至工具调用链路。

## 怎么确认配好了
- 查看FastGPT v4.17.0版本的工具调用日志，确认`toolChoice`参数的取值与配置一致，无异常切换。
- 发起一次隐患排查的工具调用请求，检查返回结果是否包含结构化的隐患字段，匹配预设的业务文档格式。
- 模拟并发请求，观察接口返回状态，确认未触发限流报错，调整并发上限至符合业务系统要求。
- 修改全局变量后触发工具调用，检查调用参数是否使用更新后的变量值。
