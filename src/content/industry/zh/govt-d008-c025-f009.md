# 安全生产隐患排查治理的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常文档包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，数据字段涵盖隐患等级、整改责任主体、整改期限、复查结果等，无统一固定格式，单篇文档长度差异较大，从数百字符的复查记录到数千字符的治理台账均有覆盖。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源高频更新的数据要求配置支持增量同步与多源数据融合，避免因数据滞后影响排查准确性。文档格式与长度差异大，要求模型接入配置需适配不同长度的上下文输入，避免截断关键排查与整改信息。字段包含明确的业务属性，要求配置需引导模型识别特定业务字段，确保输出符合业务规范。同时业务出错后果严重，要求配置需优先保障输出准确性，避免模糊或错误的排查指引。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配隐患治理台账、挂牌督办单等长文档的上下文容纳需求，避免关键排查信息被截断 |
| `maxTokens` | 2000–3000 token | 覆盖整改通知书、复查记录等文档的输出长度要求，保证完整返回整改与复查细节 |
| `temperature` | 0.1–0.3 | 降低输出随机性，保障隐患排查、整改指引的准确性，符合业务高合规要求 |
| `toolChoice` | auto | 自动触发知识库检索工具，匹配最新的隐患排查清单与治理台账数据 |
| `AIPROXY_API_ENDPOINT` | 按选定模型服务商的官方接入地址配置 | 绑定合法的模型调用端点，保障模型调用的稳定性与合规性 |
| `AIPROXY_API_TOKEN` | 专属调用密钥 | 限制未授权访问，保障模型调用的权限安全 |

## 容易做错的三处
- 现象为部署重排模型后通过测试，但每次检索返回结果的重排状态标记为false，或未显示重排后的排序结果。原因是未配置重排模型的触发条件，或知识库检索内容未达到重排模型的调用长度要求。
- 现象为知识库检索内容超过8000字符后，重排模型未被调用，检索结果未经过排序优化。原因是未调整`maxContext`配置适配长文本检索，导致重排触发逻辑未生效。
- 现象为在线对话与API调用返回结果差异显著，API开启stream为false、detail为true时返回内容缺失或格式异常。原因是未统一配置`maxTokens`与`temperature`参数，或API调用时未传递完整的上下文参数。

## 怎么确认配好了
- 调用FastGPT v4.17.0的API测试接口，检查返回结果中是否包含重排相关字段，确认重排功能正常触发。
- 上传单篇最长的隐患治理台账文档，验证配置是否允许完整输出文档内容，无截断情况。
- 核对`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`配置，确认无连接错误或权限报错。
- 对比在线对话与API调用的返回结果，确认参数配置一致，消除结果差异。
