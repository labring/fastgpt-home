# 安全生产隐患排查治理的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源为安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常文档包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，文档多按条目整理，包含隐患描述、整改要求、责任主体、复查状态等字段，覆盖从隐患排查、整改到销号归档的全流程信息。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据覆盖多系统的结构化与半结构化文档，且更新频率为每日，要求知识库检索需支持增量同步以保证结果时效性，同时需精准限定检索范围，避免混入无关系统的内容。日常文档多按条目整理为清单、台账，若检索拆分不当会破坏单条隐患的完整信息，影响排查与整改的对照参考。此外，本品类出错后果严重，要求召回结果需具备较高精准度，避免遗漏关键判定标准或整改要求，同时需覆盖同类型隐患的历史案例以支撑排查工作。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 安全生产隐患相关内容专业性强，阈值过低会引入无关排查条目，过高可能遗漏相似隐患判定标准 |
| `limit` | `前8–12条` | 单次召回过多会超出上下文窗口，过少可能覆盖不全同类型隐患的历史案例 |
| `searchMode` | `段落优先` | 日常文档多为按条目整理的排查清单、整改台账，段落优先拆分可保留单条隐患的完整信息 |
| `usingReRank` | `开启` | 隐患排查相关内容相似度较高，重排可过滤低相关性召回结果，提升精准度 |
| `datasetSearchUsingExtensionQuery` | `开启` | 业务办理流程中需结合判定标准扩展检索范围，优化召回覆盖度 |
| `collectionIds` | `绑定隐患排查清单、治理台账专属集合ID` | 精准限定检索范围，避免混入其他品类文档干扰结果 |

## 容易做错的三处
- 现象：调用接口创建文本集合时，返回参数错误或无法启用段落优先拆分。原因：未正确传入`searchMode`对应的参数值，或使用了清单外的非标准参数名。
- 现象：绑定飞书数据源后，添加文件时无法获取目标文件列表。原因：未授权飞书文档的读取权限，或未正确配置数据源的同步范围，导致无法拉取文件元数据。
- 现象：通过外部接口上传文件到知识库后，检索时无法召回该文件内容。原因：未在上传接口中指定目标集合的`collectionIds`，或未触发知识库的索引刷新任务，导致文件未被正确编入检索库。

## 怎么确认配好了
- 查看FastGPT v4.17.0的知识库设置页面，确认`searchMode`已设置为段落优先。
- 发起模拟检索，输入“重大事故隐患判定标准”，检查召回结果是否包含完整的判定条目，无内容拆分断裂。
- 调用外部检索接口，传入`usingReRank`为true，检查返回结果的排序是否符合业务相关性。
- 上传一份测试用的隐患排查清单文件，等待索引完成后发起检索，确认该文件的相关内容可被正常召回。
