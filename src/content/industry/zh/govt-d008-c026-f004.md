# 工程建设项目审批的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
本品类数据来源为工程建设项目审批管理系统、施工图审查系统、企业资质库、信用平台，更新频率为每日。日常处理的文档包括施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表，数据字段包含审批节点标识、参建单位资质编号、材料提交校验状态、信用评级标识等，单条数据的字符体量覆盖数十到数百不等。

## 这些特征在「工作流编排」这一环带来什么约束
本品类数据来自多套独立系统，工作流编排需配置跨系统数据拉取节点，确保审批材料、资质信息的实时同步。每日更新的数据要求工作流设置定时触发的同步环节，避免数据滞后。多类型审批文档的存在，要求工作流适配不同文档的解析与校验规则。并联审批节点的业务逻辑，要求工作流支持并行分支编排，同时跟踪各分支的完成状态，确保整体流程的进度对齐。

## 配置怎么定
以下配置项适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 包含审批节点ID、参建单位资质编号、材料校验规则 | 匹配工程建设项目审批数据的核心字段，确保工具调用时参数精准对应业务需求 |
| `nodeId` | 按审批流程节点顺序分配唯一标识 | 确保工作流节点的调用与跳转逻辑清晰，避免节点混淆导致流程中断 |
| 定时同步频率 | 每24小时一次 | 匹配本品类数据的日更新频率，确保同步后的数据时效性符合业务要求 |
| 并行分支数 | 前3个审批分支 | 覆盖工程审批常见的并联审批环节，适配核心业务流程的并行处理需求 |
| 循环体结束条件 | 当材料校验通过时触发 | 适配循环校验审批材料的业务场景，满足循环终止的实际诉求 |
| 单次工具调用参数 | q字段匹配当前审批节点的材料要求 | 解决工具调用时参数精准匹配的问题，避免无效调用或返回无关内容 |

## 容易做错的三处
- 现象：工具调用时返回无关审批材料信息，或无法匹配当前节点的材料要求。原因：未将`variables`中的字段精准映射到工具调用的`q`参数，导致参数匹配不准确。
- 现象：工作流在预览环境正常，但发布免登录窗口后出现节点跳转异常或数据拉取失败。原因：未配置`nodeId`的全局唯一标识规则，导致发布后节点映射关系混乱。
- 现象：循环体无法在满足指定条件时终止，持续执行校验逻辑。原因：未正确设置循环体结束条件的触发规则，或未绑定对应的数据校验节点。

## 怎么确认配好了
- 查看工作流的节点映射关系，确认每个`nodeId`对应唯一的审批环节，无重复或遗漏。
- 触发定时同步任务，核对拉取的数据字段与预设的`variables`是否一致。
- 模拟循环校验流程，验证当材料校验通过时循环体是否正常终止。
- 发布免登录窗口，模拟不同审批节点的调用，确认工具调用参数匹配准确。
