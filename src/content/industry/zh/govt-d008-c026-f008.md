# 工程建设项目审批的业务办理流程引导：文档解析与分块

## 这个品类的数据长什么样
本品类数据来源于工程建设项目审批管理系统、施工图审查系统、企业资质库及信用平台，更新频率为每日。日常处理的文档包含施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表等，文档多为结构化表单与带格式的技术说明结合，字段包含参建单位资质编号、项目立项文号、审批节点状态等，部分文档为扫描件格式，存在手写批注或非标准化排版。

## 这些特征在「文档解析与分块」这一环带来什么约束
数据来源分散导致文档格式不统一，扫描件与电子文档混合，要求解析环节支持多格式适配与OCR能力。每日更新的高频数据需要解析流程具备稳定性，避免超时影响审批流转效率。文档包含资质编号、立项文号等关键关联字段，分块时需保留字段上下文关联性，避免拆分破坏信息完整性，影响后续流程引导的准确性。部分文档存在批注内容，需在分块时保留关联信息，确保后续匹配审批节点时无信息缺失。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配工程类文档的段落长度，避免拆分关键审批字段 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配文档中审批节点、资质信息的层级结构 |
| `customPdfParse` | 开启 | 针对扫描件PDF启用OCR能力，适配施工图审查合格书等扫描文档 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 秒 | 匹配大型竣工验收备案表的解析耗时，避免超时中断流程 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 适配多份审批材料打包上传的场景，满足单次批量提交需求 |
| `chunkSettingMode` | 手动配置 | 针对不同类型审批文档灵活调整分块规则，适配资质文件与项目文档的差异 |

## 容易做错的三处
- 调用文件集合创建API时未正确指定`customPdfParse`参数，导致扫描件PDF解析失败，返回空内容或格式错乱。原因是未在API请求中添加对应配置项，未启用OCR解析能力适配扫描件格式。
- 未调整`PARSE_FILE_TIMEOUT_SECONDS`参数至合理区间，大型竣工验收备案表解析时触发超时错误，返回504状态码。原因是默认超时时长不足以覆盖大型文档的解析流程，导致任务中断。
- 未配置分块规则区分多文件解析结果，导致不同审批材料的字段混淆，无法准确匹配对应审批节点。原因是未开启按文件维度的分块隔离，导致解析结果的上下文关联混乱。

## 怎么确认配好了
- 上传单份扫描件PDF文档，查看解析结果是否包含完整的图纸编号、审查意见等关键字段，确认OCR解析能力生效。
- 上传大型竣工验收备案表，监控解析耗时是否在预设范围内，无超时报错提示。
- 上传多份不同类型的审批文档，核对解析结果的文件标识与原始上传文件的对应关系，确认分块结果按文件区分。
- 调用API创建文件集合，检查请求参数中是否包含指定的分块与解析配置，返回结果无参数缺失提示。
