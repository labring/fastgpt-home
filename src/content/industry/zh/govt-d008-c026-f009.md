# 工程建设项目审批的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源于工程建设项目审批管理系统、施工图审查系统、企业资质库及信用平台，更新频率为每日。日常处理的文档包括施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表，数据字段包含项目唯一标识、参建单位资质信息、审批节点状态、备案材料校验结果等，未使用自定义非标准单位，所有字段均来自官方政务系统的标准化输出。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源与更新节奏，对模型接入与配置带来多项约束。每日更新的数据要求配置支持增量同步触发，避免全量拉取占用政务服务器资源；标准化的政务文档格式与固定字段，要求上下文长度配置适配审批材料的常规篇幅；政务内网场景下无法访问公网，需支持私有API端点配置；审批环节涉及资质核对与节点跟踪，需配置工具调用能力以对接官方系统接口。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数逻辑制定：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配审批材料与历史审批节点的总长度，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 控制单轮回答的输出长度，确保审批流程说明清晰不冗余 |
| `quoteMaxToken` | 1500 token | 限制引用的审批文档片段长度，匹配单份材料的常规篇幅 |
| `toolChoice` | auto | 自动触发工具调用，用于对接资质库与审批系统接口 |
| `temperature` | 0.1–0.3 | 保持审批流程说明的准确性，避免生成非标准化指引 |
| `AIPROXY_API_ENDPOINT` | 内网私有API地址 | 适配政务内网无法访问公网的部署场景 |

## 容易做错的三处
- 现象：切换模型渠道后接口返回304状态码。原因：未正确更新内网API端点配置，前端请求缓存了旧的公网地址。
- 现象：模型渠道调用报错，日志显示获取数据异常。原因：未配置有效的`AIPROXY_API_TOKEN`，或内网防火墙拦截了模型调用流量。
- 现象：未获取到完整的审批流程指引结果。原因：`maxContext`配置值过小，未纳入完整的审批材料与历史节点数据。

## 怎么确认配好了
- 在内网环境下调用模型渠道，检查接口请求是否指向配置的`AIPROXY_API_ENDPOINT`地址，无公网域名残留。
- 上传一份标准的施工许可申请文档，触发流程引导，检查返回结果是否包含审批所需的全部材料清单。
- 查看模型调用日志，确认`toolChoice`已生效，成功对接资质库或审批系统接口。
- 调整`temperature`参数后，验证回答的严谨性，确认参数取值符合业务对指引准确性的要求。
