# 工程建设项目招投标的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源为全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常处理的文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，涉及资质、业绩、工程量清单、施工周期等专属字段，文档结构随标段划分、项目类型存在差异。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配招投标相关多文档组合的长上下文需求，覆盖完整标段的关联文件内容 |
| `maxTokens` | 2000–3000 token | 满足单轮流程引导的回复长度要求，避免超出模型接口的限额 |
| `quoteMaxToken` | 1500 token | 保留足够的原文引用片段，用于支撑资格条件、工程量清单等核心内容的核对 |
| `temperature` | 0.1–0.3 | 降低回复随机性，确保流程引导的步骤准确一致，避免出现歧义性引导 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应接口地址 | 适配本地或云部署的接入需求，确保模型调用的网络连通性 |
| `toolChoice` | auto | 自动选择工具处理标段拆分、专家记录核对等流程化任务，提升引导效率 |

## 容易做错的三处
- 现象：模型接入后返回认证失败，日志显示401状态码。原因：未正确配置`AIPROXY_API_TOKEN`，或密钥与部署环境不匹配。
- 现象：本地部署后无法访问模型配置入口，界面显示空白或无法加载页面。原因：未按部署流程启动服务，未正确绑定API代理的访问端口。
- 现象：添加模型后生成的引导内容未包含工程量清单相关信息。原因：未配置适配招投标文档的`maxContext`取值，导致上下文被截断，丢失核心字段信息。

## 怎么确认配好了
- 检查`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置值，与平台提供的接入信息完全一致。
- 上传一份完整的招标公告文档，触发流程引导测试，确认回复包含标段划分、资格条件、投标要求等核心内容。
- 查看模型调用日志，确认`maxContext`和`maxTokens`的取值符合预设配置，无超限报错记录。
- 模拟异议投诉处理场景，测试模型是否能按流程步骤生成对应的引导内容，无异常跳转或缺失环节。
