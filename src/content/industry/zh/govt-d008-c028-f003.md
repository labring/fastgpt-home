# 市场主体登记与许可的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源于企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统、住所信息库，更新频率为每日。日常处理的文档包含设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等，文档结构以标准化业务字段为主，包含主体名称、住所地址、股东信息、许可类型等固定条目，无自定义非标准化字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据每日更新的特征要求对话需实时调用最新政务数据源，避免返回过期的登记规则或许可条件。标准化业务文档的结构要求提示词需预设固定字段的引导顺序，避免遗漏关键信息。多类数据源的关联需求要求多轮对话需逐步整合不同系统的返回结果，逐步完成核验。最耗时的核验环节要求提示词提前预判可能的驳回点，主动提示用户补全材料，减少后续流程的驳回概率。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 上下文窗口长度 | 8000–12000 token | 业务文档多为多页申请材料，需保留完整对话历史与材料解析片段，避免关键信息丢失 |
| 问题优化开关 | 启用 | 需将用户口语化的咨询转为标准化的登记流程查询，适配政务业务的严谨表述要求 |
| 单次召回知识库条目数 | 前3条 | 登记许可需精准匹配前置后置条件，避免冗余信息干扰判断逻辑 |
| `variables` 配置 | 绑定「企业名称」「住所地址」「许可类型」变量 | 需动态填充业务专属字段，实现对话的个性化引导 |
| `messages` 格式配置 | 按用户-助手轮次拼接 | 多轮对话需保留历史核验进度，避免重复询问已收集的业务信息 |
| `chatId` 配置 | 绑定业务办理流水号 | 关联对应办理环节的上下文，避免跨申请混淆对话内容 |

## 容易做错的三处
- 对话关联知识库接口调用失败，返回空结果或404状态码。原因是未正确配置知识库与对话流程的绑定关系，或未在提示词中指定调用接口的正确参数。
- 大文件文档解析超时，界面显示处理超时状态。原因是未针对政务文档的长文本优化分块配置，导致单块过大或处理时长超限（按实测标定为300秒）。
- 多轮对话中重复询问相同业务字段，比如反复询问股东信息。原因是未在提示词中明确已收集的字段状态，或上下文窗口配置过小导致历史信息丢失。

## 怎么确认配好了
- 发起模拟的企业设立登记咨询，检查对话是否自动提示需提交的业务材料与必填字段。
- 上传一份完整的设立登记申请书文档，验证解析后是否能正确提取核心字段并用于对话引导。
- 查看接口调用日志，确认`chatId`、`messages`、`variables`参数均被正确传递至对话流程。
- 模拟多轮次的咨询交互，检查历史对话信息是否被完整保留，未出现重复询问已确认的业务信息。
