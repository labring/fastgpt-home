# 市场主体登记与许可的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
这个品类的日常业务文档包含设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等，字段覆盖主体名称、住所地址、股东信息、许可类型等核心业务内容。数据来源为企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统、住所信息库，更新频率为每日。文档结构涵盖表单类、决议类、证明类多种格式，无统一固定的单一场景格式，需适配多类文本结构的输入。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据与非统一格式的特征，要求模型接入环节需支持解析表单类、决议类、证明类等多种文档结构，避免因格式不匹配导致核心字段提取失败。每日更新的数据要求配置环节需支持实时或增量同步业务数据，避免使用过期的市场主体信息。核心业务环节的高耗时特性，要求模型需精准调用工具完成名称核验、住所校验等判断，同时需限制输出长度以保证业务引导流程的可读性。出错后果的严重性要求配置优先保证字段提取与规则判断的准确率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 日常业务文档多为多页组合材料，需覆盖完整的业务上下文以保证字段提取准确性 |
| `maxTokens` | 4000–6000 token | 业务办理流程引导需输出完整的步骤提示与校验说明，避免输出内容被截断 |
| `temperature` | 0.1–0.3 | 需保证名称核验、住所校验等环节的输出一致性，减少随机偏差 |
| `toolChoice` | auto | 支持模型自主调用工具完成名称核验、住所信息校验等核心业务环节 |
| `AIPROXY_API_ENDPOINT` | 本地Ollama部署的Qwen2.5 API端点 | 适配自研部署的大模型需求，满足业务数据本地化处理的要求 |
| `AIPROXY_API_TOKEN` | 对应Ollama部署的访问令牌 | 完成大模型接入的身份验证，保证API调用的合法性 |

## 容易做错的三处
- 现象为工具调用无响应，界面显示「工具未触发」日志。原因是未将`toolChoice`配置为auto，或未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`导致API连接失败。
- 现象为大模型输出结果混乱，无法准确提取住所、股东信息等核心字段。原因是未使用结构化格式传入业务文档，或未设置合适的`maxContext`参数导致上下文溢出，模型无法完整读取业务材料内容。
- 现象为配置后召回的业务文档与当前办理需求不匹配，返回无关的历史登记材料。原因是未限定召回范围为市场主体登记类数据，或未根据业务文档的字段特征调整匹配逻辑。

## 怎么确认配好了
- 发起名称核验测试，上传模拟的企业名称申请材料，核对模型是否能准确调用工具返回名称可用状态的判断结果。
- 上传完整的设立登记申请书与章程材料，核对模型输出的业务办理流程是否覆盖所有必填字段与校验要点。
- 查看FastGPT v4.17.0的API调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无连接超时或身份验证失败报错。
- 测试内置时间工具调用功能，发起「询问当前时间」的提问，确认工具能正常返回结果，验证工具调用链路配置完成。
