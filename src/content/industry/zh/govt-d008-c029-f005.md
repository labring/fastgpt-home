# 市容环卫与城管执法案件的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。日常关联文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告。数据字段通常包含巡查点位、问题类型、责任主体、整改状态等，部分关联非结构化数据如现场影像，整体以结构化案件台账与半结构化上报材料结合为主。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散，工具调用环节需支持对接多类第三方API，覆盖执法平台、网格平台及工单系统的数据拉取。因包含现场照片等非结构化数据，插件需适配非结构化内容解析。数据每日更新的特性要求工具调用触发逻辑需匹配业务巡检周期，避免调用过时数据。同时，为避免案件证据不足，工具返回结果需校验核心字段完整性，确保立案、整改等环节的关联信息齐全。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配城管案件多步骤调用工具的场景，自动选择匹配的执法相关工具 |
| 插件调用触发时机 | 案件提交后10秒内 | 匹配网格员上报后的即时处理需求，避免延迟影响执法进度 |
| `functionCall` | 开启强制字段校验 | 确保工具返回的案件数据包含巡查点位、责任主体等核心执法字段 |
| 单次工具调用超时时间 | 30秒 | 覆盖现场定位、跨平台数据拉取的常规耗时，避免过长等待 |
| 全局变量初始化 | 预设执法场景基础值 | 统一案件编号前缀、责任主体分类等通用参数，减少重复配置 |
| 工作流启动触发 | 网格工单推送事件 | 对接城市运行平台的实时上报渠道，实现案件即时触发 |

## 容易做错的三处
- 现象：工具调用后返回空内容，或触发10秒左右的超时报错。原因：未配置合理的单次调用超时时间，或对接的第三方API未设置重试逻辑，导致请求超时或无有效返回。
- 现象：插件初始值无法生效，全局变量更新后未同步到工作流节点。原因：未在工作流启动节点正确绑定全局变量的初始化配置，或变量作用域设置错误，导致参数无法传递。
- 现象：工作流启动后直接报错，未进入工具调用环节。原因：未正确配置工作流的触发事件，或对接的第三方API鉴权参数填写错误，导致前置请求失败。

## 怎么确认配好了
- 触发一次模拟的城管案件上报，查看工作流是否自动启动并调用预设的工具节点。
- 检查工具调用日志，确认返回的字段包含巡查点位、问题类型等核心执法相关信息。
- 调整全局变量的预设值，验证工作流节点内的变量是否同步更新为新的配置值。
- 模拟第三方API超时场景，确认工作流是否触发预设的异常处理逻辑，如重试或告警。
