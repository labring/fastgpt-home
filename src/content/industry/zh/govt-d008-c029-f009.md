# 市容环卫与城管执法案件的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
该品类的数据通常来自城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。日常文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告，数据字段通常涵盖案件编号、违法类型、责任主体、整改执行状态、现场取证信息等，多为结构化表单与非结构化图文结合的格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据混合结构化表单与非结构化图文，且多来自多平台实时更新，因此模型接入时需适配视觉识别能力以处理现场照片类素材；需配置合理的上下文窗口以整合多源工单、巡查记录等信息，避免关键执法信息遗漏；每日更新的案件数据存在波动，需限制单次处理的token上限防止资源占用过高；执法文书的固定字段格式，要求模型能准确识别对应字段以支撑业务流程引导。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 该品类数据包含现场照片等非结构化视觉素材，需开启视觉能力以识别取证内容 |
| `maxContext` | 8000–12000 token | 需整合多源巡查记录、工单及执法文书，该区间可覆盖典型多源信息整合需求 |
| `maxTokens` | 2000–3000 token | 限制单次响应长度，适配执法案件引导的简洁输出要求，避免资源过载 |
| `temperature` | 0.3–0.5 | 降低随机性，确保执法流程引导的内容符合固定业务规范 |
| `AIPROXY_API_ENDPOINT` | 填写对应城管执法场景的模型代理地址 | 适配该品类专属模型的调用路径，确保请求正常路由 |
| `quoteMaxToken` | 1500 token | 限制引用的文档片段长度，确保提取的执法文书、巡查记录信息准确且不冗余 |

## 容易做错的三处
- 现象：调用模型时返回`invalid token`报错，或提示无法连接模型接口。原因：未正确配置`AIPROXY_API_TOKEN`参数，或代理地址与模型实际部署路径不匹配。
- 现象：模型无法识别现场照片中的取证内容，输出结果为空或错误。原因：未开启`vision`配置项，或视觉模型的接入参数未同步配置。
- 现象：处理案件数据时出现上下文溢出报错，服务反复重启。原因：未限制`maxContext`或`maxTokens`的取值，导致单次处理的token总量超出模型承载上限。

## 怎么确认配好了
- 测试调用配置好的模型，上传单份现场照片与巡查记录，确认模型能正确识别照片内容并关联巡查信息。
- 发起模拟案件引导请求，检查返回结果的格式与字段是否符合执法文书的固定规范。
- 连续发起多次批量案件数据处理请求，确认服务无报错且响应稳定。
- 核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`参数，确保与部署的模型代理信息完全一致。
