# 建设工程质量安全监督的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
本品类数据来自工程质量安全监管系统、施工现场实名制平台、监理日志、检测报告，更新频率为周。日常业务文档包含监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告，数据字段覆盖监督主体、检查点位、隐患等级、整改时限、验收结论等，无额外自定义字段，格式多为结构化表格与标准化文档，各来源数据需统一格式后才能进入业务流转环节。

## 这些特征在「工作流编排」这一环带来什么约束
数据按周更新，工作流需适配批量同步周期，避免频繁调用增量接口导致的资源浪费。多源数据来自不同平台，工作流需配置跨系统数据拉取节点，统一格式后再进入流程。日常文档包含多类业务表单，工作流需按环节拆分节点，对应监督计划编制、现场检查、隐患闭环、验收监督等步骤。隐患整改通知书等文档需关联整改闭环状态，工作流需设置状态校验节点，确保数据流转符合业务逻辑，避免出现未整改通过就进入验收环节的情况。本流程以施工现场监督为核心，聚焦过程管控与验收管理，区别于施工许可类的开工门槛审批。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定监督主体、隐患等级、整改时限字段 | 匹配本品类业务文档的固定字段结构 |
| 节点触发顺序 | 按`nodeId`依次编排现场检查、隐患闭环、验收监督节点 | 符合住建质安监督的标准业务流程 |
| 知识库搜索范围 | 指定工程监督类文件集合 | 匹配本品类日常业务文档类型 |
| 单次搜索上限 | 前10条 | 适配单批次现场检查记录的数据量 |
| 节点超时阈值 | 600秒 | 覆盖跨系统拉取监管数据的平均耗时 |
| 文件过滤规则 | 筛选监督计划、隐患整改通知书类文档 | 精准匹配业务场景需求 |

## 容易做错的三处
- 现象为全局变量调试至下游节点时，界面提示输入为空，日志显示`variables`字段缺失。原因是配置`variables`时未绑定周更业务数据的固定字段，导致节点流转时未加载对应业务数据。
- 现象为知识库搜索节点返回大量无关文档，结果条数超出预期。原因是未配置文件过滤规则，未限定搜索范围为工程监督类文件集合。
- 现象为ai对话组件配置大模型时，未找到温度设置入口，无法调整生成结果的严谨性。原因是未进入变量引用模式下的高级配置面板，导致温度参数无法被设置。

## 怎么确认配好了
- 手动触发测试工作流，检查`variables`绑定的业务字段是否完整加载至下游节点。
- 运行知识库搜索节点，核对返回结果是否仅包含本品类的日常业务文档。
- 查看节点运行日志，确认跨系统数据拉取未出现超时报错。
- 进入ai对话组件配置界面，确认可找到大模型温度参数的设置入口。
