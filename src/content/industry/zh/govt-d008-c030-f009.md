# 建设工程质量安全监督的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源为工程质量安全监管系统、施工现场实名制平台、监理日志、检测报告，更新频率为周。日常文档涵盖监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告，数据字段覆盖监督主体、检查事项、隐患内容、整改要求、验收结论等，无额外统计数字或法规条文。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类周更新的多源数据，要求模型接入时配置合适的上下文窗口，避免加载过期数据影响业务判断。多类结构化文档的差异，要求配置参数适配不同文档的字段格式，确保模型能准确提取隐患整改、验收结论等核心信息。监管业务对结果准确性要求严格，需限制模型生成的灵活性，同时保证对现场数据的识别能力，避免因参数设置不当导致的错误判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配周级别的多源文档数据量，避免上下文溢出 |
| `temperature` | 0.1–0.3 | 监管业务对准确性要求高，降低生成随机性，确保结果符合监管规范 |
| `toolChoice` | auto | 自动选择工具调用，适配隐患整改跟踪、验收条件核对等业务环节 |
| `maxTokens` | 2000–3000 token | 控制单轮生成内容长度，避免输出过长影响业务办理引导的可读性 |
| `quoteMaxToken` | 1500–2000 字符 | 限制引用文档的长度，确保模型能聚焦核心监管信息 |
| `AIPROXY_API_ENDPOINT` | 填写对应部署的模型API地址 | 适配自建或外部部署的模型接入路径，确保调用链路正常 |

本页面基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 现象：配置的重排模型在工具调用环节无法启用，知识库测试时正常。原因：未将重排模型的接入参数绑定到工具调用的配置中，仅在知识库检索环节配置了该模型。
- 现象：模型生成的业务引导内容出现冗余字段，不符合监管文档格式。原因：`temperature`参数设置过高，导致生成随机性过大，偏离监管业务的标准化要求。
- 现象：调用外部部署的模型时无法正常加载，返回400状态码。原因：未正确配置`AIPROXY_API_TOKEN`参数，导致API鉴权失败。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`参数是否与部署的模型地址、密钥一致，发起测试调用确认链路正常。
- 配置`maxContext`和`maxTokens`参数后，导入单份监督检查记录进行测试，查看上下文加载是否符合预期。
- 设置`temperature`参数后，生成业务办理引导内容，核对是否符合监管文档的标准化格式。
- 开启工具调用功能，模拟隐患整改跟踪场景，确认模型能自动调用对应工具完成流程引导。
