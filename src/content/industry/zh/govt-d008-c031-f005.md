# 建设项目环评审批的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
本品类的数据主要来自全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台及环境监测数据。日常处理的文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复等，文档结构多为多章节合规文本，字段包含项目类别、环评等级、污染防治措施、公众参与情况等，数据更新无固定周期，随项目申报与审批进度同步更新。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据来源分散且无固定更新节奏，工具调用需支持对接多套外部系统接口以获取实时申报、管控及监测数据。日常处理的文档结构复杂、字段标准化程度不一，插件需适配不同格式的环评文件解析与字段提取。项目审批出错后果严重，工具调用环节需内置参数校验与失败重试逻辑，避免因数据错误导致审批流程受阻。同时需确保工具调用返回的字段与环评审批所需的核心字段严格匹配，避免无关信息干扰审批判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配环评审批中多变的工具调用场景，无需手动指定具体工具 |
| `functionCall` | `enabled` | 启用工具调用能力，支持获取跨系统的环评相关数据 |
| 插件超时阈值 | `600 秒` | 环评数据需跨多系统查询，耗时较长，避免因超时中断流程 |
| 插件重试次数 | `2 次` | 应对临时网络波动或接口响应延迟，降低调用失败概率 |
| 单次工具调用返回条数 | 前5条 | 避免过多冗余数据影响模型处理效率，聚焦核心环评数据 |
| 工具返回字段过滤 | 保留项目类别、环评等级、污染防治措施字段 | 仅提取环评审批必需的核心数据，减少无关信息干扰 |
| 上下文窗口长度 | `8000 token` | 适配环评报告书等长文本的处理需求，保留完整审批相关上下文 |

本文档适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 插件调用返回402状态码，界面提示余额不足。原因是未正确配置外部插件的API密钥额度校验逻辑，当超出预设调用额度后未触发自动重试或告警机制。
- 工具调用返回字段为空，日志中显示无匹配数据。原因是未适配环评文档的字段命名规则，提取规则与实际文档结构不匹配。
- 工具调用超时，系统弹出请求超时提示。原因是插件超时阈值设置过短，无法覆盖跨系统获取环评申报、分区管控数据的耗时。

## 怎么确认配好了
- 手动触发一次工具调用，检查返回数据是否包含项目类别、环评等级等核心字段。
- 模拟跨系统接口调用延迟，验证是否触发预设的重试机制。
- 查看系统配置日志，确认`toolChoice`和`functionCall`参数已按设定值生效。
- 提交一份测试用的环评申请数据，检查工具调用返回的结果格式是否符合审批要求。
