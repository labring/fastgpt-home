# 建设项目环评审批的业务办理流程引导：模型接入与配置

本文档基于FastGPT v4.17.0版本的模型接入与配置流程编写，面向生态环境领域环评审批场景的业务办理流程引导需求。

## 这个品类的数据长什么样
本品类数据主要来自全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台及监测数据。日常处理的文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复等。数据更新无固定周期，由项目申报进度、审批流程推进节奏决定。数据字段围绕项目类别、环评等级、污染防治措施、公众参与情况等核心业务要素展开，无统一固定单位，随文档类型变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据分散来自多套政务系统，且文档结构差异较大，要求模型接入时需适配多源异构数据的解析逻辑。不定期的更新节奏，要求配置的上下文管理规则可灵活调整，避免因旧数据干扰当前审批判断。环评文档的强业务属性，要求模型的参数配置需绑定项目类别、污染防治措施等核心业务字段的识别权重。同时，审批出错后果严重，需配置足够的容错机制与日志记录参数，保障流程可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配环评报告书、审批申请等长文档的上下文需求，避免截断核心项目信息 |
| `maxTokens` | 2000–3000 token | 平衡输出长度与响应速度，确保完整输出流程步骤与核查要点 |
| `temperature` | 0.1–0.3 | 降低生成随机性，保障政务引导内容的准确性与规范性 |
| `toolChoice` | auto | 自动调用工具整合多源业务数据，适配环评审批中多类型文档的解析需求 |
| `quoteMaxToken` | 1500 token | 限制单条引用文档的长度，避免过长引用导致上下文溢出 |
| `AIPROXY_API_ENDPOINT` | 填写部署节点专属接口地址 | 适配私有化部署的网络隔离要求，保障政务数据传输安全 |

## 容易做错的三处
- 出现乱码或输出格式错乱。原因是未适配环评文档中的专业术语、公文格式标记，未配置字符编码兼容规则，导致模型解析时出现编码错误。
- 上传DOC格式的环评文档后无法被分析。原因是未配置对应文档类型的解析适配规则，或未开启对应文档解析配置，导致非结构化文档无法被正确拆分与识别。
- 模型调用失败返回认证或超时错误。原因是`AIPROXY_API_TOKEN`配置错误，或接口地址与部署环境不匹配，导致模型调用链路不通。

## 怎么确认配好了
- 上传单份典型环评报告书，检查模型能否完整提取项目类别、环评等级等核心字段，确认上下文配置可覆盖当前文档长度。
- 模拟多源数据整合场景，检查模型能否自动调用工具获取分区管控成果、监测数据等外部信息，确认工具调用配置生效。
- 调整`temperature`参数至不同区间，对比输出内容的随机性，确认配置符合政务审批的严谨性要求。
- 测试异常输入（如损坏的DOC文件），检查模型是否返回明确的错误提示，确认容错配置已生效。
