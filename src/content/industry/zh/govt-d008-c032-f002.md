# 投资项目立项与后评价的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来源包括国资委投资监管系统、企业ERP与项目管理系统、行业市场数据、审计及财务报表。日常处理的文档涵盖年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告及投资后评价报告。数据更新周期为季度，核心使用者为中央企业战略投资部、项目公司、国资监管部门及外部咨询评估机构，文档多为结构化与半结构化结合的正式业务文件，包含项目编号、投资金额、审批节点等业务字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据多源异构，涵盖系统导出的结构化报表与正式业务文档，需在索引前完成格式统一与字段对齐。季度更新的低频属性决定无需高频增量索引，可采用批量定时更新策略。文档篇幅跨度大，从数页的项目建议书到数十页的后评价报告，分块时需兼顾业务逻辑完整性与文本粒度合理性。专业业务字段如投决节点、后评价指标等，要求向量模型能准确捕捉专业语义，避免语义偏移。同时，数据涉及国资监管相关内容，需确保索引过程的可追溯性与安全性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类文档的业务段落长度，避免拆分破坏投决节点、后评价指标等业务逻辑 |
| 重叠长度 | 100–150 字符 | 衔接相邻分块的业务上下文，防止关键审批流程信息被截断 |
| `defaultToken` | 4096 token | 匹配主流开源向量模型的输入上限，适配后评价报告的长文本分块内容 |
| 相似度阈值 | 0.72–0.85 | 过滤低相关性的非业务文档，确保检索结果聚焦于投资立项与后评价的核心内容 |
| 单次搜索上限 | 前 5 条 | 匹配投决会材料的核心参考文档数量，避免冗余信息干扰业务判断 |
| `maxToken` | 8192 token | 限制检索后拼接的上下文总长度，适配系统的上下文窗口限制 |

## 容易做错的三处
- 现象：上传10M以上的后评价报告或可行性研究报告时，分块后出现部分chunk向量化失败，界面显示「向量生成异常」。原因：未针对长文本配置合适的`maxToken`参数，超出模型输入上限导致向量化中断。
- 现象：因上传大量立项与后评价文档导致服务器重启后，知识库状态显示「未就绪」且无自动索引进度。原因：未开启批量索引的断点续传配置，系统无法恢复未完成的索引任务。
- 现象：升级FastGPT v4.17.0后，原有的立项文档知识库无法返回检索结果。原因：旧版本的索引元数据格式与新版本不兼容，未执行索引重建操作。

## 怎么确认配好了
- 上传单份10M以上的后评价报告，检查分块数量与预期一致，无异常分块标记。
- 发起针对「投决会审批流程」的检索，核对返回结果的相似度分值符合预设阈值区间。
- 触发批量索引任务，重启服务器后检查任务是否自动续传并完成。
- 查看索引日志，确认所有业务字段均被正确向量化，无语义丢失提示。
