# 招标采购合规管理的业务办理流程引导：向量模型与索引

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类数据主要来自国央企采购中心、招标办等主体关联的企业采购平台、公共资源交易平台、供应商库、合同管理系统及审计问题库，每日更新。日常涉及的文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单及供应商投诉材料，各文档包含采购方式、预算依据、评分办法、供应商资格要求等专属字段，数据结构随采购全流程节点呈现分层特征。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的数据要求索引环节支持增量同步，避免全量重建带来的性能损耗。多类型文档的混合存储，要求分块策略适配不同文档的结构特征，例如长文本招标文件需合理拆分，短文本评标记录需保留完整语义。采购方式、预算依据、评分办法等专属字段的语义权重较高，索引时需优先保障关键字段的向量提取精度。跨多数据源的聚合数据，需统一字段映射规则，避免索引出现语义偏移。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配招标文件、合同等长文本的语义完整性，避免跨块语义断裂 |
| 重叠长度 | 100–150 字符 | 保留分块间的上下文衔接，防止关键合规信息被拆分在不同块中 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 平衡招标采购文档的召回精度与检索效率，适配合规审查的严格要求 |
| 单次搜索上限 | 前 8 条 | 覆盖评标记录、供应商投诉等多类型文档的典型召回量，避免冗余数据过载 |
| `maxToken` | 4000–6000 token | 适配招标采购全流程文档的总长度，保障大语言模型可获取完整合规依据 |
| `defaultToken` | 2000 token | 作为默认上下文长度，适配日常采购咨询的常规检索需求 |

## 容易做错的三处
- 现象：检索到相关合规文档，但大语言模型返回未找到匹配内容。原因：未正确设置`maxToken`参数，召回的文档片段超出上下文上限被截断，大语言模型无法读取完整内容。
- 现象：索引更新耗时过长，无法在每日更新周期内完成同步。原因：未配置增量索引规则，每日执行全量索引重建，未适配本品类每日更新的数据特征。
- 现象：检索结果混入非采购类文档或无关供应商材料。原因：相似度阈值设置不合理，未结合招标采购合规审查的精准需求调整参数，导致召回语义关联较弱的非目标内容。

## 怎么确认配好了
- 查看索引同步日志，确认每日增量任务正常执行，无全量重建的异常记录，核对更新节奏是否匹配业务要求。
- 输入采购方式、评分办法等专属查询词，检查检索结果是否包含目标文档类型，确认配置逻辑符合合规审查的业务场景。
- 测试不同长度的查询，查看大语言模型返回的上下文内容是否覆盖完整的合规文档片段，确认上下文参数的设置适配当前业务需求。
- 核对分块长度、重叠长度的配置，确认与本品类常见文档的平均长度匹配，避免语义拆分异常。
