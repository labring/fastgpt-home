# 招标采购合规管理的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自国央企采购平台、公共资源交易平台、供应商库、合同管理系统及审计问题库，每日更新。日常文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料，各类文档分别包含采购方式、预算金额、评分细则、供应商资质、履约条款、审计问题等固定字段，非结构化文本占比高且格式差异显著。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据每日更新且来源分散，要求模型接入环节需支持多源数据的增量同步拉取；文档类型多样且字段差异显著，需配置支持多模态处理的模型适配招标文件、评标记录等不同格式内容；审计问题库的历史合规数据需关联当前流程，要求模型可调用工具查询关联记录；高风险审核环节需严格对齐企业制度，模型输出需保留可追溯的上下文依据。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配招标采购全流程文档的上下文长度需求，覆盖采购计划、招标文件、评标记录等多类文档的总内容量 |
| `maxTokens` | 2000–3000 token | 控制单轮模型输出的合规审核结果长度，避免超出业务办理界面的展示限制 |
| `quoteMaxToken` | 1500 token | 限定引用的采购文档片段长度，确保审核依据清晰且不占用过多上下文空间 |
| `toolChoice` | auto | 支持自动调用合规查询工具，适配招标采购中需要核对预算依据、供应商资格的多步骤流程 |
| `vision` | enabled | 支持处理招标文件中的多模态附件，如图纸、盖章文件等非纯文本内容 |
| `temperature` | 0.2–0.4 | 降低输出随机性，确保合规审核结果的一致性，符合国央企的严谨性要求 |

## 容易做错的三处
- 现象：在单个工作流中无法同时将多模态数据接入多模态模型、纯文本数据接入Qwen2工具调用模型。原因：未正确配置`vision`参数与`toolChoice`参数的联动逻辑，未区分不同数据类型的模型路由规则。
- 现象：配置`toolChoice`后出现模型不支持的报错。原因：未确认所选模型是否兼容`toolChoice`功能，部分轻量模型未开放工具调用能力。
- 现象：QA搜索测试时提示“当前分组 default 下对于模型 gpt-4o-mini 无可用渠道”。原因：未在对应分组中配置gpt-4o-mini模型的API渠道，或渠道配置信息有误。

## 怎么确认配好了
- 测试多模态附件上传，确认模型可正常解析图片、盖章文件等内容，验证`vision`参数配置生效。
- 发起包含合规查询需求的测试流程，确认模型自动调用工具获取历史审计问题库数据，验证`toolChoice`参数配置生效。
- 查看模型输出的上下文引用片段，确认引用长度符合`quoteMaxToken`的限定范围。
- 调整`temperature`参数至不同区间，对比输出结果的随机性变化，确认参数生效。
- 检查对应分组中的模型API渠道配置，确认所选模型的接入信息无误，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置生效。
