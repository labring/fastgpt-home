# 招标采购合规管理的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自国央企采购平台、公共资源交易平台、供应商库、合同管理系统、审计问题库，更新频率为每日。日常文档包含采购计划、需求说明书、招标文件、评标记录、合同、验收单、供应商投诉材料，各文档有专属字段，如采购计划含预算依据、采购方式，招标文件含评分办法细则，评标记录含专家打分与合规判定项，整体数据结构随采购流程节点分层。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的数据源要求检索链路支持增量同步与全量刷新，避免数据滞后影响业务办理。多类型文档混合检索需适配不同文档的字段权重，例如评标记录的合规判定项需优先召回。不同来源的数据格式差异较大，需统一预处理流程以保障检索一致性。采购流程节点分层的文档结构，要求检索能按业务环节精准匹配，例如招标环节优先召回招标文件与采购计划，验收环节优先匹配合同与验收单。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写，以下为适配本品类的检索配置方案：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 适配招标采购文档的专业术语密度，过滤低相关的合规类内容 |
| `limit` | 前6–8条 | 覆盖采购流程中多环节的参考文档，避免单条结果信息不足 |
| `searchMode` | 混合检索 | 同时匹配全文关键词与结构化字段，适配多类型文档的检索需求 |
| `usingReRank` | 开启 | 对初始召回结果按相关性重排序，提升评标记录、招标文件等高权重文档的排序精度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户输入的业务关键词扩展合规相关检索词，覆盖采购计划、合同等文档的隐藏关联 |
| `collectionIds` | 按业务节点绑定对应知识库集合 | 例如招标环节绑定招标文件、采购计划集合，验收环节绑定合同、验收单集合，精准缩小检索范围 |

## 容易做错的三处
- 检索时返回common:core.chat类报错，原因是未正确配置`collectionIds`绑定的知识库集合，或集合内文档未完成全量索引。
- 无法召回多级目录下的文档内容，原因是未开启目录递归解析开关，未将所有层级的文档纳入检索索引范围。
- 检索结果条数与设置的`limit`不符，原因是初始召回的有效结果未达到设置上限，或重排环节过滤了部分不符合合规要求的低相关结果。

## 怎么确认配好了
- 手动输入采购计划相关关键词，检查召回结果是否包含采购计划、采购方式相关文档。
- 切换业务节点标签，验证`collectionIds`绑定的知识库集合是否自动切换，检索结果是否匹配当前节点的文档类型。
- 开启`usingReRank`后，对比初始召回与重排后的结果排序，确认高权重文档如评标记录的排序是否靠前。
- 模拟每日增量更新场景，检查数据源同步是否正常，检索结果是否包含最新的供应商投诉材料或验收单。
