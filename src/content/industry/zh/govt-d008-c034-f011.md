# 招生入学与学籍管理的业务办理流程引导：表单与交互
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
该品类的数据来源包括全国中小学生学籍信息管理系统、地方招生入学平台、户籍与房产数据、学校教务系统，更新频率为每日。日常涉及的文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表，核心字段涵盖学生身份信息、户籍房产关联信息、入学资格证明材料、学籍异动审批状态等，数据围绕学生入学资格与学籍流转展开，不涉及资金补助类内容。

## 这些特征在「表单与交互」这一环带来什么约束
数据来源多且每日更新，要求表单交互环节需实时关联最新的户籍、学籍与招生计划数据，避免因数据滞后导致资格核验错误。日常文档字段覆盖身份、房产、异动审批等多维度，表单需按入学报名、学籍注册、转学申请等业务场景拆分专属字段组，匹配不同业务的信息采集需求。核心数据来自官方系统，交互环节需适配跨系统数据校验逻辑，确保提交信息与官方数据源一致，同时需适配最耗时的户籍房产核验环节，提供分步引导与实时校验提示。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 表单输入组件 | 按入学报名、学籍注册、转学申请拆分3组独立`formInput`组件 | 匹配日常文档的多场景字段结构 |
| 用户输入超时阈值 | 600秒 | 适配户籍房产核验的最长耗时业务环节 |
| 上下文调用上限 | 前10条学籍与招生数据 | 匹配数据来源的每日更新量级 |
| 单文件上传上限 | 100 MB | 适配户籍证明、学籍材料的常规大小 |
| 表单校验触发时机 | 填写完单组字段后实时触发 | 避免多字段混填导致的校验错误 |
| 工作流输入过滤 | 仅传递指定业务字段至后续节点 | 防止冗余数据干扰AI处理逻辑 |

## 容易做错的三处
- 现象：表单提交后返回字段为空的校验报错，原因：未按业务场景拆分`formInput`组件，跨场景的冗余字段未被正确过滤。
- 现象：工作流最终输出包含前置AI对话的冗余内容，原因：未配置输入过滤规则，直接将全量工作流上下文作为后续AI节点的输入。
- 现象：表单提交后触发超时状态码，原因：未设置适配长耗时核验环节的超时阈值，导致系统提前中断交互流程。

## 怎么确认配好了
- 提交模拟的入学报名信息，核对表单采集字段是否与入学报名表、学籍信息表的官方文档字段一致。
- 触发户籍与房产核验环节，确认系统关联的数据源为全国中小学生学籍信息管理系统或地方招生入学平台。
- 运行工作流测试场景，确认最终输出仅包含学籍异动申请的审批结果，无前置AI对话的冗余内容。
- 模拟长耗时的核验操作，确认交互流程未被系统提前中断，超时阈值设置符合业务实际耗时。
