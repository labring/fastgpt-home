# 排污许可管理的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自全国排污许可证管理信息平台、企业环保台账、在线监测系统、环境统计系统，更新频率为季度。日常处理的文档包含排污许可证申请表、执行报告、自行监测方案、台账记录、变更申请、许可证副本，数据字段包含许可限值、排放口编码、监测时段、排放浓度、变更事项等，部分文档包含结构化表头与多行明细内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
不同来源的数据格式混杂，包含结构化表格与非结构化文本，要求索引配置适配多格式分块。季度更新的节奏，要求索引支持批量增量更新，减少全量重建的资源消耗。文档包含多行明细与核心业务字段，分块颗粒度需匹配业务语义单元，避免拆分破坏字段关联性。同时核心业务术语如许可限值、排放浓度需要模型精准捕捉语义，对向量模型的领域适配性提出要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 排污许可文档包含多行明细与核心字段，该长度可保留语义完整性且避免单块过大 |
| 重叠长度 | 100–150 字符 | 避免分块边界切断核心业务术语，提升跨块语义匹配精度 |
| `maxToken` | 8192 | 适配主流嵌入模型的上下文长度限制，避免截断核心业务内容 |
| `defaultToken` | 1024 | 适配嵌入模型的默认token阈值，避免初始化异常 |
| 相似度阈值 | 0.72–0.85 | 核心业务字段匹配需较高语义相似度，过滤低相关性的匹配结果 |
| 单次搜索上限 | 前 5 条 | 排污许可审核需精准匹配多维度业务规则，少量结果可提升审核效率 |
| 重排模型 | 启用 | 过滤低相关性匹配结果，聚焦核心业务字段的匹配效果 |

## 容易做错的三处
- 现象为构建知识库后搜索结果匹配度低，且单条结果包含过多无关明细行。原因是未根据排污许可文档的明细结构调整分块长度，导致分块颗粒度过大，语义关联被稀释。
- 现象为添加本地部署的嵌入模型时，配置无法生效或覆盖原有同名模型。原因是未在FastGPT界面中正确指定本地部署的模型接口地址与端口，且同名模型仅支持单配置项。
- 现象为搜索结果中markdown格式异常，一级二级标题丢失。原因是未正确处理源数据中的结构化表头与换行符，分块时未保留原文档的格式标记。

## 怎么确认配好了
- 上传单份排污许可执行报告文档，触发分块预览，检查分块是否保留核心业务字段与完整语义单元。
- 配置本地嵌入模型后，在测试页面输入业务关键词，验证模型可正常返回匹配结果且无配置报错。
- 调整分块参数后，对比不同参数下的分块结果，确认分块边界未切断关键业务术语。
- 执行批量索引更新，验证季度更新的增量同步功能可正常触发。
