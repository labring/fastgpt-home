# 政务服务事项目录与办事指南维护的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
该品类的日常文档包含政务服务事项基本目录、实施清单、办事指南、标准材料目录、流程图及常见问题。数据来源为国家政务服务事项基本目录、行政许可事项清单、权责清单及地方政务服务事项库，更新频率通常为月度。核心文档包含事项编码、事项名称、受理条件、申请材料、办理流程等字段，部分文档包含跨层级、跨部门的关联事项信息。日常工作中最耗时的环节为比对上级目录与本级实施清单、维护受理条件和申请材料、校验办事指南字段完整性。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的节奏要求索引支持增量同步，避免全量重建带来的时间成本。多类文档混合的结构需要按文档类型设置元数据过滤规则，确保召回结果仅来自目标文档。事项编码等唯一标识字段需作为元数据索引，用于精准匹配官方口径的事项条目。长文本的流程描述和材料列表需要合理的分块策略，避免语义断裂导致向量召回偏差。跨层级关联事项的文本需要模型支持长上下文关联，确保召回的关联事项符合官方逻辑。

## 配置怎么定
本页面适配FastGPT v4.17.0版本，以下配置项基于该版本设置：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配政务办事指南的单段文本长度，避免拆分后语义断裂 |
| 重叠长度 | 100–200 字符 | 覆盖跨分块的流程描述、材料列表等连贯内容 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 区分官方口径与非官方解读，避免召回无关事项 |
| `defaultToken` | 8192 | 匹配bge-large-zh-1.5的嵌入维度适配的上下文长度，确保向量生成完整 |
| 单次召回上限 | 前10条 | 控制返回的事项条目数量，避免接口返回数据量过大 |
| 最大上下文 | 6000 字符 | 适配政务文档的长文本召回后拼接长度，符合模型输入限制 |

## 容易做错的三处
- 单个政务办事指南文件长期处于索引中，未完成向量入库。原因：文件内存在超长未拆分段落，或分块长度设置超出模型支持的最大token限制。
- 切换到政务事项库索引时出现60秒超时报错。原因：索引分片过大，或增量同步时未过滤已更新的历史数据，导致单次同步数据量过高。
- 无法调用bge-large-zh-1.5的向量服务，或召回结果与官方口径偏差较大。原因：未确认嵌入维度匹配，或未配置正确的模型接口地址，导致向量生成不符合预期。

## 怎么确认配好了
- 上传一份标准政务办事指南文档，查看分块后的文本是否连贯，无明显语义断裂。
- 发起一次事项匹配查询，核对召回结果的相似度分值是否在预设阈值范围内。
- 测试增量同步功能，上传一份更新后的政务目录文件，确认索引仅更新新增或修改的条目。
- 查看向量生成日志，确认`maxToken`配置未超出模型支持的最大长度，无截断报错。
