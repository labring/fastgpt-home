# 政府信息依申请公开的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类的业务数据来源包括政府信息公开平台、机关档案系统、公文系统、部门业务台账及政府信息公开条例相关规范。数据更新频率不定期，随具体申请事项产生新的业务文档。日常处理的文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料，各文档有明确的业务字段，如申请表含申请人信息、申请事项，答复书含救济途径说明等。处理主体为政府办公室、部门政务公开办、法规处、档案室等单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且覆盖多系统，要求配置环节支持对接多数据源的文档调取，避免仅关联单一平台导致文档缺失。文档类型多样且字段差异明显，需适配不同文档的结构特征，确保模型能准确识别业务字段与内容。业务处理环节涉及长文本检索与生成，要求模型配置能容纳足够的上下文与生成长度。数据更新无固定周期，需支持动态加载最新的业务文档与规范内容，避免模型调用过时信息。此外，业务出错后果明确，配置需保障调用稳定性，减少超时或错误响应的概率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxTokens` | 8000–12000 token | 适配答复书、行政复议答辩材料等长文档的生成与处理需求 |
| `temperature` | 0.2–0.4 | 保证生成内容的规范性，符合政务文书的严谨性要求 |
| `maxContext` | 15000–20000 token | 容纳多份关联业务文档，如申请表、补正告知书的完整内容 |
| `toolChoice` | auto | 自动选择是否调用工具完成信息检索与文档匹配环节 |
| `AIPROXY_API_ENDPOINT` | 按部署的代理服务实际地址填写 | 适配多模型调用的代理转发配置 |
| `AIPROXY_API_TOKEN` | 与代理平台匹配的有效令牌 | 完成模型调用的权限验证与身份识别 |

## 容易做错的三处
- 界面显示“没有可用模型”或调用返回空值，原因是未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，或令牌未绑定对应模型的调用权限。
- 模型生成的答复内容不完整或被截断，原因是`maxTokens`设置值小于生成内容的实际需求长度。
- 无法调取业务所需的政务文档，原因是未按数据来源配置对应的文档检索路径，未关联政府信息公开平台、机关档案系统等数据源。

## 怎么确认配好了
- 在FastGPT v4.17.0的模型管理页面，验证`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置与部署参数完全一致。
- 发起一次测试调用，输入模拟的政府信息公开申请内容，检查模型是否能正常返回响应，无报错提示。
- 导入一份政务文档样本，验证模型能否正确识别文档中的核心业务字段，如申请人信息、申请事项等。
- 查看模型调用日志，确认`maxTokens`、`maxContext`等参数被正确加载，无参数缺失或异常。
