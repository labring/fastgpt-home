# 政府信息依申请公开的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自政府信息公开平台、机关档案系统、公文系统、部门业务台账及相关规范文档。日常文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料等。数据更新无固定周期，随业务办理进度或政策调整变化。文档多为结构化与半结构化结合，包含申请人信息、申请事项、公开属性判断依据、救济途径说明等字段，无统一标准化单位，需按业务场景匹配对应规则。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散导致召回时需整合多系统的异构数据，需配置跨源检索适配逻辑。文档类型多样，包含表单、函件、答复书等不同结构，需针对不同文档调整分块与检索匹配规则。更新无固定周期，需支持按需增量索引以保证数据时效性。检索需精准匹配申请事项对应的信息存在性、公开属性及第三方权益相关内容，否则会引发办理超时或合规风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 平衡检索精准度与覆盖范围，避免漏检申请相关的政府信息或引入无关内容 |
| `limit` | 前10条 | 适配本品类单申请需检索多类型文档的场景，覆盖必要的历史办理记录与政策依据 |
| `searchMode` | vectorSearch | 针对半结构化与非结构化的政府信息文档，优先使用语义匹配的向量检索模式 |
| `usingReRank` | 开启 | 提升高相关结果的排序优先级，确保最匹配申请事项的信息优先返回 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于申请事项自动扩展检索词，覆盖同义词与相关表述，避免漏检相关政府信息 |
| `collectionIds` | 按业务部门绑定专属集合 | 限定检索范围在对应部门的政府信息公开相关数据，避免跨部门无关数据干扰 |

## 容易做错的三处
- 检索结果条数异常偏少。现象为输入申请事项后返回的匹配文档不足预设数量。原因是`similarity`阈值设置过高，过滤掉了部分相关的政府信息文档，无法覆盖申请所需的全部依据。
- 导入文档时出现前缀字段报错。现象为界面提示包含未识别的`$schema`相关字段错误。原因是未清理文档中的非业务元数据，系统无法兼容自定义的schema字段。
- 索引任务长时间卡住未完成。现象为索引状态长时间停留在中间进度且无进度更新。原因是未设置合理的`limit`参数，单次加载的文档数据量过大，引发系统超时中断。

## 怎么确认配好了
- 输入1条典型的政府信息依申请公开事项，核对检索返回的文档是否包含该事项对应的历史办理材料与政策依据。
- 检查索引任务的运行日志，确认未出现`$schema`相关的字段报错，文档导入流程正常完成。
- 查看知识库内的文档列表，确认重复的政府信息文档已被自动清理或标记。
- 测试增量索引功能，确认新增的政府信息文档可被快速检索到，符合不定期更新的业务需求。
