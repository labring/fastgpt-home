# 政府采购项目的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源包括中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常业务文档涵盖采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同与质疑答复，涉及采购人单位、财政部门政府采购监管处、采购代理机构、评审专家四类核心主体。数据结构随文档类型差异明显，不同文档对应专属字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的数据源要求对话环节需实时同步最新公告与合同数据，避免使用过期信息。多类业务文档的差异化结构，要求提示词需针对不同文档类型适配字段识别逻辑，确保精准提取关键信息。四类核心主体的不同业务诉求，要求多轮对话需通过上下文区分角色，匹配对应流程规则。同时，业务出错后果严重，要求对话生成的流程指引需严格贴合采购相关通用规则，不应出现偏差。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定采购项目编号作为会话标识 | 同一采购项目的多轮对话需保持上下文一致性，避免跨项目的上下文混淆 |
| `messages` | 保留前10轮对话上下文，单轮内容不超过1500字符 | 政府采购相关文档篇幅较长，过长的上下文会干扰模型对核心规则的理解 |
| `variables` | 绑定采购人单位、监管部门ID等专属业务变量 | 不同采购人的采购流程存在细微差异，专属变量可让提示词精准适配具体项目的规则 |
| 问题优化 | 开启问题优化功能 | 采购业务术语专业性较强，可降低非专业用户的提问门槛，将模糊提问转换为标准采购术语 |
| 单次召回上限 | 召回前5条匹配文档 | 政府采购相关文档数量较多，过多召回会导致上下文过载，降低对话响应效率 |
| 最大上下文长度 | 按实测标定为8000–12000字符 | 需覆盖单份招标文件的核心内容，同时避免模型处理超时 |

## 容易做错的三处
- 现象：调用接口时返回「400 知识库未关联」的报错，原因：未将政府采购专属文档库与当前对话应用绑定，仅创建了独立的通用知识库。
- 现象：多轮对话中上下文出现跨项目偏移，原因：未使用采购项目编号作为`chatId`，导致不同采购项目的会话上下文被错误复用。
- 现象：生成的流程指引出现专业术语偏差，原因：未开启问题优化功能，未将用户的模糊提问转换为标准采购术语，导致模型理解错误。

## 怎么确认配好了
- 查看会话详情中的标识字段，确认`chatId`已绑定为采购项目编号。
- 在测试对话中触发变量调用，确认返回内容包含预先绑定的采购人单位、监管部门等专属参数。
- 发起连续提问，先后询问采购需求和招标文件的相关内容，确认对话上下文保持一致，未出现内容偏移。
- 调用接口测试知识库召回，确认返回的文档均为政府采购相关的专属文档，无无关业务内容。
