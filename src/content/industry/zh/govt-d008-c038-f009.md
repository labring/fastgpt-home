# 政府采购项目的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源包括中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常处理的文档涵盖采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同与质疑答复。数据围绕采购人、财政部门政府采购监管处、采购代理机构、评审专家四类主体流转，各文档对应采购流程的不同节点，字段需符合政府采购体系下的规范格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据分散多源且每日更新，要求模型接入环节支持多数据源的批量同步配置，避免数据滞后影响实时流程引导。文档类型覆盖采购全流程节点，不同文档的长度、字段结构差异较大，需配置适配不同文本长度的上下文与token限制参数。涉及供应商信用记录等敏感数据，需配置严格的访问权限校验规则，确保数据合规。流程节点间的文档流转需匹配对应环节的引导逻辑，因此需绑定对应文档类型的模型调用规则。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配政府采购项目的流程引导场景需求：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 政府采购相关文档单篇长度普遍较长，需容纳多份关联文档的上下文 |
| `maxTokens` | 2000–3000 token | 流程引导的输出需清晰覆盖办理步骤，避免过长导致信息冗余 |
| `quoteMaxToken` | 1500–2000 token | 限制引用文档的长度，避免上下文溢出影响模型响应 |
| `temperature` | 0.2–0.4 | 需保证流程引导的准确性与规范性，降低随机生成的偏差 |
| `AIPROXY_API_ENDPOINT` | 部署节点的内网访问地址 | 适配财政系统内网部署的安全要求，避免公网暴露敏感数据 |
| `toolChoice` | 强制绑定流程步骤拆解工具 | 确保模型输出严格对应政府采购办理流程的规范步骤 |

## 容易做错的三处
- 配置完成的模型在工作流节点中无法选中，现象为模型列表为空或无对应条目。原因是未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的对应关系，或渠道绑定未启用该模型。
- 调用模型后返回404或500状态码，现象为流程节点报错。原因是API端点地址填写错误，或密钥权限未开放对应模型的调用权限。
- 模型输出的流程步骤与政府采购规范不符，现象为步骤遗漏或规则错误。原因是未配置`toolChoice`强制绑定流程引导工具，导致模型生成不符合监管要求的内容。

## 怎么确认配好了
- 进入模型管理页面，确认已配置的模型状态为「启用」，且绑定的API端点与密钥匹配当前部署环境。
- 新建一个流程节点，调用该模型，输入一段政府采购招标文件的片段，检查是否能正常返回响应内容。
- 查看系统日志，确认模型调用请求的状态码为200，无报错信息。
- 测试调用配置的`toolChoice`绑定的流程步骤拆解工具，验证是否能拆解出符合采购流程的标准步骤内容。
