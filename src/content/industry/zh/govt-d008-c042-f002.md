# 法务合规与重大风险管理的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自企业合同管理系统、合规风险数据库、法律法规库、案件管理系统与举报平台。日常处理的文档包含合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告。数据更新频率为月度，单份文档多包含业务主体、风险类型、处理进度、合规依据等字段，无统一固定单位，部分文档附带结构化审批节点与关联案件编号。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的月度更新节奏要求索引流程适配周期性全量重建与增量更新结合的模式，避免单次重建耗时过长影响业务支撑。多源异构的文档类型，包含结构化审批表单与非结构化法律文书，要求索引环节支持混合格式的文本拆分与向量映射。多系统来源的数据存在字段差异，需要索引支持自定义字段关联，确保检索时能匹配业务办理的合规审查逻辑。同时，业务出错后果严重，要求索引召回的结果需具备较高的置信度，避免遗漏关键合规依据。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配合规类文档的段落长度，避免单块包含过多无关合规条款 |
| 重叠长度 | 100–150 字符 | 保留跨块的合规关联信息，防止关键审查依据被拆分断裂 |
| 相似度阈值 | 0.75–0.85 | 匹配法务审查对合规依据准确性的要求，过滤低相关的非合规内容 |
| 单次搜索上限 | 前 8 条 | 控制检索结果的信息量，适配业务办理时的快速合规校验场景 |
| `defaultToken` | 4096 token | 适配单份合规文档的平均文本长度，满足基础向量编码需求 |
| `maxToken` | 8192 token | 覆盖多份关联文档的总长度，支持重大事项审查的上下文召回 |

## 容易做错的三处
- 执行全量索引重建后服务器读写资源持续占用过高。原因是未针对月度更新的批量数据设置分批重建策略，单次加载过多合规文档与法规库数据导致内存溢出。
- 调用索引接口返回400状态码且无响应体。原因是未适配法务类文档的特殊字段格式，或向量模型参数配置超出`maxToken`限制，导致请求体格式异常。
- 上传合规审查表后偶尔卡在1组或2组索引环节。原因是本地部署的m3e-large模型未配置足够的显存配额，或分块长度设置过大导致单块向量生成超时。

## 怎么确认配好了
- 手动上传一份典型的合规风险清单，检查索引生成进度是否在预期时间内完成，无卡顿或报错。
- 发起一条合规审查相关的查询，核对检索结果的条数与相似度符合预设的配置范围。
- 触发一次增量索引更新，验证仅新增的月度合规数据被纳入索引，未重复处理历史数据。
- 查看系统日志，确认向量生成环节的资源占用未超过服务器配置的额定阈值。
