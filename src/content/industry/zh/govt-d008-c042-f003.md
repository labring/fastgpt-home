# 法务合规与重大风险管理的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来源于企业合同管理系统、合规风险数据库、法律法规库、案件管理系统与举报平台，更新频率为每月一次。日常文档包含合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告，文档多以结构化表格与非结构化文本结合的形式存在，字段涵盖风险等级、审核主体、事项类型、处理进度等，无统一固定格式，随企业内部管理规范调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且多为内部系统，需通过`messages`参数按轮次传递用户的咨询内容与系统返回的检索结果，逐步引导用户提供对应系统的文档标识或权限范围，避免越权访问。每月更新的特性要求提示词需明确标注数据的最新更新节点，防止引用过期合规条款或风险清单。非结构化文档占比高，多轮对话需通过递进式提问拆解文档内容，提取关键字段。字段无统一格式，提示词需适配多种文档结构，灵活匹配不同字段的提取逻辑。

以下配置基于 FastGPT v4.17.0 版本制定。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配合规类文档的段落长度，避免拆分破坏法律条款的完整性 |
| 重叠长度 | 100–200 字符 | 保留跨块的法律关联内容，防止关键合规条款被分割 |
| 单次搜索上限 | 前 5 条 | 匹配合规审查需聚焦核心风险的场景，避免冗余信息干扰 |
| `chatId` | 按对话会话自动生成 | 用于关联多轮对话的上下文，确保合规审查的历史记录可追溯 |
| 最大上下文 | 4000 token | 适配多轮对话中需回溯的合规审核历史与文档片段 |
| `variables` | 按实测标定 | 用于传递企业合规系统的权限参数，适配不同主体的访问范围 |

## 容易做错的三处
- 现象：对话中调用知识库检索返回空结果，但在知识库单独测试时可匹配到内容。原因：多轮对话中未正确传递`variables`参数携带的合规系统权限范围，导致检索范围受限。
- 现象：本地部署后，对话中上传的合规类文档无法被读取。原因：未配置对应文档格式的解析插件，或上传文件的大小超出系统预设阈值。
- 现象：多轮对话中生成的合规审查意见出现过期法规引用。原因：提示词未明确要求检索最新的月度更新合规数据库，导致调用了过期数据。

## 怎么确认配好了
- 手动触发一次合规风险检索，核对返回结果是否包含当前月度更新的合规文档内容。
- 开启多轮对话测试，上传一份合同审核意见文档，确认系统可逐步提取风险等级、审核主体等字段。
- 调用`variables`参数传递测试权限，验证不同权限主体的检索结果是否符合预设范围。
- 查看对话日志，确认每次检索的上下文片段未被过度截断，保留了完整的法律条款内容。
