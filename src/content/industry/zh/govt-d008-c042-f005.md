# 法务合规与重大风险管理的业务办理流程引导：工具调用与插件

以下配置适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
这个品类的数据主要来自企业合同管理系统、合规风险数据库、法律法规库、案件管理系统、举报平台，更新频率为月度。日常处理的文档包括合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告，文档结构多包含主体信息、事项内容、审核结果三类核心字段，无统一固定单位，字段随文档类型调整，不同来源的数据格式存在差异。

## 这些特征在「工具调用与插件」这一环带来什么约束
月度更新的数据源要求工具调用的缓存周期需匹配更新节奏，避免使用过期的合规数据。多来源且结构差异大的文档，要求插件需适配不同文档的字段解析规则，确保输入输出的一致性。合规类数据对准确性要求极高，工具调用需严格校验返回结果的合规性，防止引入错误内容。涉及重大事项的文档需严格控制访问权限，工具调用的权限分级配置需匹配企业内部的合规管理要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `固定绑定合规类插件` | 法务合规流程需调用指定数据源工具，避免非授权工具介入 |
| `functionCall` | `仅允许调用合规相关函数` | 严格控制工具调用范围，防止无关操作触发合规风险 |
| 单次工具调用超时时间 | `300 秒` | 合规数据查询涉及多系统联动，需预留足够响应时长 |
| 插件数据缓存周期 | `30 天` | 数据源更新频率为月度，缓存周期匹配更新节奏，避免使用过期数据 |
| 输入字段映射规则 | `按合规文档字段一对一映射` | 不同合规文档结构差异大，需精准匹配输入字段，避免解析错误 |
| 结果返回条数上限 | `前 10 条` | 合规审查仅需核心参考数据，过多结果会增加审核负担 |

## 容易做错的三处
- 现象：JSON输入框中无法选择预设变量，提交后字段为空。原因：未开启插件输入框的变量绑定开关，或未在插件配置中声明支持变量替换。
- 现象：调用数据链接工具时SQL语句执行报错，返回参数格式错误。原因：未遵循合规数据源的SQL语法规范，未限定查询范围导致返回数据过载。
- 现象：工具调用后返回结果与合规文档不匹配，出现无关内容。原因：`toolChoice`参数未绑定指定合规插件，调用了非授权工具。

## 怎么确认配好了
- 触发一次合规审查流程，检查工具调用是否仅绑定指定合规插件。
- 提交结构化合规文档，确认输入字段是否正确映射到插件输入框。
- 等待工具调用完成，检查返回结果的格式是否符合预设校验规则。
- 查看插件调用日志，确认未触发超时报错或权限异常。
