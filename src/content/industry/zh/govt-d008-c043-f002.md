# 特种设备安全监管的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
特种设备安全监管领域的业务数据主要来自特种设备安全监察系统、检验检测机构系统、使用单位台账、作业人员证书库。日常业务文档包含使用登记证、定期检验报告、维保记录、隐患整改通知书、事故报告、作业人员证书，各文档包含设备编号、检验周期、维保单位、作业人员资质等固定字段。数据更新频率为月度，需同步最新的检验结果、维保记录与人员资质变动。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的数据源要求索引支持增量同步，避免全量重建带来的计算资源消耗。多类型文档的结构差异，要求分块策略适配不同长度的文本内容，避免长检验报告被过度截断或短证书丢失关键信息。固定字段的存在要求索引需保留元数据关联，确保检索结果能直接关联对应设备的唯一标识。高风险监管属性要求检索结果的精准性，需严格控制匹配阈值，避免无效结果干扰业务判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配特种设备定期检验报告、维保记录等文档的单段内容长度，避免过度截断关键信息 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的上下文关联，防止跨分块的逻辑被打断 |
| `maxToken` | 4096 | 适配通用嵌入模型的token上限，确保长文档的完整向量生成 |
| 相似度阈值 | 0.75–0.85 | 按实测标定，平衡监管业务中检索的召回率与准确率 |
| 单次搜索上限 | 前 10 条 | 覆盖监管业务中需核对的多设备关联需求，避免结果过多干扰人工审核 |
| `defaultToken` | "无有效元数据" | 处理缺失设备编号、检验周期等字段的文档，避免索引任务因空字段失败 |

## 容易做错的三处
- 上传文档后索引任务报错，返回空字段相关的提示。原因是未配置`defaultToken`处理缺失元数据的文档，导致索引流程中断。
- 新建知识库时无图片索引模型选项。原因是当前部署的FastGPT v4.17.0为社区版，图片索引功能仅商业版支持。
- 检索结果仅返回少量条目，无法覆盖相关设备。原因是相似度阈值设置过高，过滤了大部分有效匹配结果。

## 怎么确认配好了
- 上传一份包含完整元数据的定期检验报告，查看索引任务日志，确认生成了对应分块的向量数据。
- 检索已知的设备编号，确认能匹配到对应的使用登记证、维保记录等关联文档。
- 调整相似度阈值，观察检索结果条数的变化，验证阈值对匹配结果的过滤效果。
- 上传一份缺失设备编号的测试文档，确认索引完成后元数据字段显示为预设的`defaultToken`值。
