# 特种设备安全监管的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
特种设备安全监管场景的数据来源包括特种设备安全监察系统、检验检测机构系统、使用单位台账、作业人员证书库。数据更新频率为月度，日常业务文档包含使用登记证、定期检验报告、维保记录、隐患整改通知书、事故报告、作业人员证书。单份文档包含设备唯一标识、检验有效期、维保单位信息、作业人员资质编号等核心字段，不同系统的文档字段格式遵循统一规范，需在交互中精准关联对应设备的全生命周期业务数据。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多系统来源的数据需关联设备唯一标识，要求多轮对话必须绑定设备编号作为上下文锚点，避免不同设备的业务数据混淆。月度更新的频率要求提示词中需明确提醒用户核对数据时效性，避免使用过期的检验或维保信息。多类业务文档的标准化字段，要求提示词需精准指定需提取的字段，减少模型提取偏差。核心业务环节耗时较长的特点，要求多轮对话需按登记、检验、维保、整改的流程逐步引导，避免遗漏关键核对节点。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` 保留条数 | 前6条 | 特种设备监管业务流程包含设备登记、检验、维保、整改多个核心环节，6条对话可覆盖完整交互节点 |
| 上下文窗口长度 | 800–1200 字符 | 日常业务文档单份内容多在该区间，避免上下文溢出影响模型理解 |
| `variables` 绑定配置 | 绑定设备编号、检验有效期字段 | 数据来源包含使用登记证、定期检验报告，需精准关联对应设备的业务数据 |
| `chatId` 锚点设置 | 按设备唯一标识关联 | 确保同设备的多轮交互上下文不混淆，避免跨设备数据错乱 |
| 单次调用超时时间 | 120 秒 | 避免多轮对话过程中出现无响应的情况，符合监管业务的交互时效要求 |
| 格式校验规则 | 启用业务字段匹配 | 监管业务出错后果严重，需强制匹配业务文档的标准字段结构 |

## 容易做错的三处
- 文本内容提取节点返回字段为空。原因是未通过`variables`绑定对应业务文档的变量，未在提示词中明确要求提取设备编号、检验有效期等核心字段。
- 多轮对话过程中出现搜索知识库无响应。原因是上下文窗口配置过长，导致模型处理超时，或未限制单次对话的知识库调用上限。
- 生成的整改回复格式不符合业务要求。原因是未配置强制格式校验，未在提示词中明确要求匹配隐患整改通知书的标准字段结构。

## 怎么确认配好了
- 发起模拟对话，输入设备编号，验证对话历史是否自动关联该设备的登记、检验数据。
- 触发文本内容提取节点，检查返回的字段是否包含设备编号、检验有效期等业务核心字段。
- 输入不符合格式的整改内容，验证模型是否提示格式调整要求，或返回符合业务文档结构的内容。
- 测试连续6轮对话，验证上下文是否正确保留前序交互的设备信息与业务节点。
