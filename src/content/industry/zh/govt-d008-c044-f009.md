# 环境执法与监测监管的业务办理流程引导：模型接入与配置

以下内容基于FastGPT v4.17.0版本的配置逻辑编写。

## 这个品类的数据长什么样
本品类的数据来自在线监控平台、污染源自动监测数据、生态环境执法系统及第三方检测报告，更新频率为每日。日常文档包含现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书，其中现场检查记录包含执法人员信息、检查时间、点位工况等字段，监测报告包含采样时间、污染物浓度、检测方法等字段，执法文书包含流程节点、责任主体等信息，部分监测数据带有浓度单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的高频数据需要适配稳定的模型调用机制，避免因接口超时导致流程中断。多类型文档的差异化字段结构，要求模型具备区分现场检查记录、监测报告、执法文书等不同文档类型的能力，避免内容混淆。在线监控实时数据与第三方检测离线报告的混合输入，需要模型准确关联数据来源与对应业务环节。执法与处罚的严谨性要求模型输出必须引用原文片段，确保内容符合监管要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 按平台分配的专属端点填写 | 适配生态环境系统的内网或公网调用路径 |
| `AIPROXY_API_TOKEN` | 绑定专属权限的令牌 | 确保仅授权主体可调用模型接口，保障执法数据安全 |
| `quoteMaxToken` | `800–1200 token` | 覆盖单份监测报告或执法文书的核心片段长度，满足原文引用需求 |
| `maxContext` | `15000–20000 token` | 容纳多份执法文档与实时监测数据的上下文，避免截断关键信息 |
| `toolChoice` | `auto` | 允许模型自主选择是否调用数据库工具，适配不同业务场景的流程引导需求 |
| `temperature` | `0.1–0.3` | 降低输出随机性，确保执法相关内容的严谨性与一致性 |

## 容易做错的三处
- 现象：模型输出未包含数据库原文片段，仅返回概括性内容。原因：未配置`quoteMaxToken`参数或取值过小，无法容纳单份文档的引用片段。
- 现象：模型选择界面的可选模型持续跳动，无法固定选择目标模型。原因：未固定`toolChoice`参数，或接口返回的模型列表存在重复更新问题。
- 现象：调用数据库工具时出现逻辑混乱，无法正确匹配数据字段。原因：未适配生态环境执法系统的专属字段命名规则，模型无法准确解析关联数据。

## 怎么确认配好了
- 发起一次模拟现场执法流程的测试，检查模型输出是否包含指定文档的原文片段，核对`quoteMaxToken`的配置是否覆盖片段长度。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置未出现格式错误，接口返回状态码正常。
- 调整`temperature`参数后对比输出内容，确认输出的严谨性符合执法场景要求。
- 模拟多文档混合输入的场景，检查模型是否能正确区分不同类型的执法与监测文档。
