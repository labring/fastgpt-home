# 环境执法与监测监管的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
本品类涉及的数据来自在线监控平台、污染源自动监测数据、生态环境执法系统、第三方检测报告，更新频率为每日。日常文档包含现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书，其中现场检查记录包含执法人员、检查点位、工况信息，监测报告包含采样点位、污染物检测数值、检测方法，执法文书包含违法事实认定、整改要求等结构化与非结构化内容。数据按执法流程分类存储，覆盖从现场执法到整改跟踪的全环节。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的多源异构数据要求检索需支持增量同步与增量召回，避免全量拉取占用过多系统资源。多样的文档类型既包含结构化的监测数值，也包含非结构化的执法文书，需兼顾语义匹配与关键词匹配的精度。执法场景需精准关联现场工况、监测数据与执法文书，检索结果需覆盖支撑流程判断的核心依据，同时需隔离非相关文档，避免干扰执法人员的流程引导判断。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 执法场景需精准匹配执法文书、监测数据的核心字段，过滤低相关的历史文档，避免干扰流程判断 |
| `limit` | `前8–12条` | 执法流程引导需覆盖现场检查、文书制作、整改跟踪等多个环节的文档，过多结果会超出上下文窗口，过少则无法覆盖所需依据 |
| `searchMode` | `向量检索+关键词混合` | 数据包含结构化的监测数值和非结构化的执法文书，混合检索可同时匹配语义关联和关键词字段，提升召回覆盖度 |
| `usingReRank` | `开启` | 执法场景对结果排序精度要求高，重排可基于语义相关性重新排序结果，优先召回最新的执法和监测数据 |
| `datasetSearchUsingExtensionQuery` | `开启` | 执法场景的业务术语较多，扩展查询可补充同义词表述，比如将“超标”扩展为“污染物浓度超出限值”，提升召回覆盖度 |
| `collectionIds` | `绑定执法案卷、监测报告两个专属集合` | 需隔离非执法类的知识库数据，确保检索结果仅来自环境执法与监测的专属文档，避免无关内容干扰流程引导 |

## 容易做错的三处
- 部署后工作流和知识库变空白：现象为界面显示知识库集合为空，接口返回空的检索结果，原因是未配置持久化存储，docker-compose部署的临时卷在容器重启后丢失数据。
- 回复中出现固定前缀文案：现象为回复开头带有预设的系统引导语句，原因是未关闭系统默认的回复前缀配置。
- 检索速度慢：现象为单次检索耗时超过10秒，原因是未限制检索的集合范围或未开启重排，导致全量知识库检索占用过多资源。

## 怎么确认配好了
- 检查知识库集合绑定情况，确认`collectionIds`配置的集合已正确关联环境执法与监测的专属文档库。
- 发起模拟执法查询，比如“如何结合采样记录与在线监控数据判断违法事实”，核对返回结果的`similarity`得分是否在配置区间内。
- 测试检索速度，确认单次检索耗时符合业务要求，验证`usingReRank`是否生效，结果排序是否优先展示最新数据。
- 检查系统回复内容，确认未出现预设的固定前缀文案，验证`datasetSearchUsingExtensionQuery`是否正常触发业务术语扩展。
