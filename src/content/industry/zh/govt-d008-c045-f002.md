# 用地预审与规划许可的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据。日常文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件。数据更新无固定周期，随项目审批进度或规划调整同步更新。文档多包含项目选址范围、用地规模、规划管控要求等字段，部分图纸类文件需先提取结构化信息再进行向量化处理。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且类型多样，包含结构化文本与图纸类文件，要求索引环节支持多源数据统一向量化适配。更新无固定周期，需支持增量索引以避免全量重建带来的资源消耗。文档中包含项目选址、红线冲突等强关联字段，对检索召回的精准度要求较高，需匹配业务场景的语义相关性。部分前置审批数据需跨平台调取，索引需支持关联外部数据源的快速检索调用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配本品类文档中项目范围、管控要求等长文本的语义完整性，避免块内信息断裂 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的重叠内容，减少跨块语义关联的丢失 |
| `maxToken` | 4096 token | 匹配主流大模型的上下文窗口限制，确保检索结果可完整传入模型 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的检索结果，聚焦与项目选址、规划管控强相关的文档 |
| 单次搜索上限 | 前 8 条 | 平衡检索效率与召回覆盖范围，避免过多冗余结果影响业务判断 |
| `defaultToken` | 2048 token | 适配本品类常见业务咨询的上下文长度需求，保证基础问答的信息完整性 |

## 容易做错的三处
- 建索引时卡在最后一组步骤，原因是未配置增量索引的断点续传功能，或跨平台数据源的访问权限未正确配置。
- 混合检索耗时超10秒，原因是未关闭非必要的检索分支，或单次搜索上限设置过高导致过多结果参与重排。
- 向量化后返回空结果或字段缺失，原因是导入了未预处理的图纸二进制文件，未先提取其中的结构化文本信息。

## 怎么确认配好了
- 导入1份典型的用地预审与选址意见书，检查分块后的文本是否保留了项目选址范围、用地规模等核心字段的完整性。
- 发起1次业务咨询测试，查看检索结果的返回时间是否符合预期，混合检索可按需调整配置后验证耗时。
- 检查索引配置页面的数据源关联状态，确认国土空间规划一张图、项目审批监管平台等数据源的访问权限正常。
- 查看FastGPT v4.17.0的日志面板，确认无索引构建失败或检索超时的报错信息。
