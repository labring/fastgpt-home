# 行政处罚案卷办理的业务办理流程引导：HTTP 接口与外部系统

## 这个品类的数据长什么样
本页面基于FastGPT v4.17.0版本编写。本品类的数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，每日更新。核心文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，数据以执法流程节点为核心，包含违法事实、裁量基准、处罚决定、送达状态等固定字段，格式与执法办案系统的标准输出一致。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于数据来源包含多类系统，需对接多个外部接口获取或推送数据；文档结构固定且字段明确，接口参数需严格匹配执法文档的字段名称与格式；每日更新的频率要求接口需支持定时同步或实时触发；数据关联到行政处罚的最终结果，接口调用失败或数据错误会直接影响案卷合规性，因此需保障接口的稳定性与数据准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 接口鉴权配置 | 配置专属`Authorization`令牌 | 匹配行政执法系统的鉴权要求，保障调用权限 |
| 请求超时时间 | 300-600秒 | 覆盖笔录上传、数据同步等常规业务耗时 |
| 变量映射规则 | 按执法文档字段一对一绑定 | 适配行政处罚案卷的固定文档结构 |
| 响应数据解析 | 提取`responseData`字段核心内容 | 适配外部系统返回的标准数据格式 |
| webhook触发条件 | 案卷状态变更时触发 | 匹配执法流程的节点更新节奏 |
| 本地调试地址 | 127.0.0.1:8080 | 用于本地开发环境的接口联调 |

## 容易做错的三处
- 现象：docker compose部署后无法连接外部执法系统接口，提示地址未找到。原因：未正确配置目标接口地址参数，未按部署要求填写服务地址。
- 现象：webhook推送的案卷数据字段缺失，返回内容为空。原因：未正确绑定`variables`变量映射规则，未将执法文档字段传递到外部系统。
- 现象：接口调用频繁触发鉴权失败。原因：使用了通用测试密钥，未匹配行政执法系统的专属鉴权要求。

## 怎么确认配好了
- 调用配置好的测试接口，核对鉴权状态是否符合预期。
- 触发一次案卷节点变更，确认webhook是否按配置触发并推送数据。
- 比对外部系统接收的数据与本地执法文档的字段是否一致。
- 查看接口调用日志，确认异常状态的处理逻辑是否生效。
