# 行政处罚案卷办理的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自市场监管、生态环境、交通运输、应急管理、城管等执法机构的行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，核心围绕违法事实与处罚决定形成可追溯的证据链，需满足案卷评查的合规要求。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
执法案卷的固定文档格式与合规要求，要求多轮对话需精准绑定当前案卷的上下文，避免跨案卷信息干扰。数据的日更属性要求知识库同步机制匹配每日更新节奏，确保对话可调用最新的案卷信息。核心证据与文书的有限规模，决定了召回范围需严格限定在当前案卷的文档内，同时需规避历史对话的无关累积导致的效果下降。此外，合规性要求提示词需明确引导模型引用符合执法规范的内容，避免出现不符合裁量基准的表述。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前办理案卷的唯一标识，固定会话ID | 确保多轮对话仅关联当前行政处罚案卷的上下文，避免跨案卷信息混淆 |
| 最大上下文长度 | 800–1200 字符，按实测标定 | 行政处罚案卷核心文档长度集中在该区间，过长会引入无关历史干扰，过短丢失关键笔录信息 |
| `variables` | 传入案卷编号、执法主体类型两个固定变量 | 精准匹配对应案卷的知识库文档，避免召回非当前执法场景的内容 |
| 单次搜索上限 | 前5条 | 执法案卷核心证据和文书数量有限，过多召回会分散模型注意力 |
| 上下文触发规则 | 当`messages`中出现案卷办结标识时触发清空 | 避免已办结案卷的历史对话干扰新的办理流程引导 |

## 容易做错的三处
- 连续多轮对话后问答效果变差，表现为模型对案卷细节的召回准确率下降，回答出现偏差。原因是未通过`chatId`绑定固定案卷上下文，历史对话的无关信息累积干扰了当前请求的召回逻辑。
- 配置上下文清空逻辑后未触发，或触发后仍保留部分历史对话。原因是未关联`messages`的状态字段作为触发条件，或触发条件设置错误。
- 尝试关闭对话中的知识库引用，但仍显示知识库引用的文档片段或链接。原因是未在提示词中明确禁止引用非当前案卷的知识库内容，或配置未生效。

## 怎么确认配好了
- 发起新的案卷办理对话，输入对应案卷的编号，检查模型是否仅召回该案卷对应的文档内容。
- 连续发起多轮关于该案卷的询问，检查模型是否能连贯引用前期对话中提及的笔录细节或证据信息。
- 触发案卷办结标识，检查上下文是否被清空，新发起的对话不再关联旧案卷的历史信息。
- 尝试调用非当前案卷的相关信息，检查模型是否无法召回或明确提示无法获取该内容。
