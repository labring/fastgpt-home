# 行政处罚案卷办理的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
本品类数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常处理的文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证等，核心字段涵盖违法事实描述、裁量基准匹配结果、法律条款引用、法制审核状态及送达归档标记，单份文档字符量跨度较大，从数百到数万字符不等。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源包含非结构化的执法影像、半结构化的笔录文档及结构化的监管数据库条目，工具调用需适配多源数据格式解析，确保不同类型数据均可被正确提取。每日更新的监管数据要求工具调用具备实时同步能力，避免使用过期的企业信用信息。单份文档字符跨度大，工具调用的上下文长度需适配不同规模的案卷内容，同时需确保处罚决定相关字段的提取准确性，避免遗漏法制审核状态等关键标记，防止出现案卷评查不合格的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 设为`"auto"`，触发条件为知识库无匹配结果 | 优先使用内部执法知识库生成引导内容，仅在无相关数据时调用外部工具 |
| `functionCall` | 开启强制工具调用模式，仅允许调用预设的执法数据查询插件 | 确保工具调用仅针对合法的监管数据源，防止调用非授权工具 |
| 全局变量配置 | 绑定执法机构代码、办案日期为固定全局变量 | 匹配本品类数据来源的部门专属监管数据库，避免跨机构数据混淆 |
| 单次工具调用超时 | 设为`60 秒` | 适配执法场景下实时数据查询的响应要求，避免过长等待影响办案效率 |
| 知识库召回上限 | 设为`前 3 条` | 聚焦核心执法相关数据，避免冗余信息干扰处罚决定生成 |
| 工具调用结果缓存 | 开启按日缓存机制 | 匹配本品类数据每日更新的频率，减少重复调用的资源消耗 |

## 容易做错的三处
- 现象：工具调用时未携带预设的全局变量，导致查询到跨机构的错误监管数据。原因：未在全局变量配置中绑定执法机构代码等专属参数，工具调用时无法自动匹配对应数据源。
- 现象：开启指定回复配置后，工具仍自动生成非预设的自然语言回复，未按配置执行工具调用。原因：未正确设置`toolChoice`参数为强制调用模式，导致AI自主选择回复逻辑。
- 现象：调用重排插件后GPU显存快速增长至6-7G且多卡同时占用。原因：未限制单次调用的文档数量，插件加载过多案卷片段导致显存资源溢出。

## 怎么确认配好了
- 登录FastGPT v4.17.0后台，发起模拟办案请求，检查工具调用时是否自动携带预设的全局变量参数。
- 触发无匹配知识库的查询，确认仅输出预设的指定回复，未调用工具。
- 查看工具调用日志，确认仅调用预设的执法数据查询插件，未触发其他非授权工具。
- 启动重排插件并发起批量查询，监控GPU显存占用情况，确认未出现快速增长。
