# 行政处罚案卷办理的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常处理的文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证等，以违法事实认定与处罚决定为核心，需形成可追溯的处罚证据链与完整文书链，字段覆盖执法主体、违法情形、证据材料、裁量依据、处罚内容及送达信息等。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源包含非结构化的影像与文本内容，需适配多模态输入与结构化文档解析。每日更新的批量数据要求配置支持高效批量调用，避免单任务超时。文书类型多样且需严格对应执法流程节点，模型需准确识别不同文档的字段要求。证据链的可追溯性要求模型输出需关联原始数据来源，不能随意篡改或省略关键信息。处罚决定的严谨性要求配置需限制生成随机性，避免出现与裁量基准不符的内容。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 容纳多份执法笔录、证据清单的上下文信息，避免关键证据链内容被截断 |
| `maxTokens` | 2500–3500 token | 覆盖单份行政处罚决定书的完整生成长度，满足文书细节与裁量说明的输出需求 |
| `temperature` | 0.2–0.4 | 降低生成随机性，保障处罚决定与裁量基准、法律条款的匹配准确性 |
| `toolChoice` | auto | 支持自动选择工具调用，适配不同执法场景下的证据调取与文书生成需求 |
| `vision` | 开启 | 解析执法记录仪影像、现场检查笔录扫描件等非结构化视觉数据，补充文本信息的完整性 |
| `AIPROXY_API_TOKEN` | 按平台分配的专属密钥 | 保障接口调用的安全性，避免未授权访问影响执法数据处理 |

## 容易做错的三处
- 现象：知识库搜索返回非标准JSON格式，导致流程引导步骤解析失败。原因：未针对执法文书的结构化字段配置专属的输出格式约束，模型生成的搜索结果混入了非结构化的备注内容。
- 现象：工具调用时无法自动选择对应执法环节的工具，流程中断。原因：未将`toolChoice`配置为auto，或未为工具绑定对应执法场景的触发规则。
- 现象：使用多模型混搭调用时，语义匹配结果无法准确识别执法专有术语，匹配精度不足。原因：未针对执法主体、违法情形等专属字段选用适配的语义匹配模型，通用模型无法准确识别执法场景下的专有表述。

## 怎么确认配好了
- 上传单份现场检查笔录与执法记录仪影像，验证模型是否能同时解析文本与视觉内容，生成完整的证据摘要。
- 触发批量数据处理任务，查看接口调用日志，确认无超时报错，处理效率符合预期。
- 生成一份模拟行政处罚决定书，核对生成内容是否包含执法主体、违法情形、处罚依据等必填字段，且格式符合执法文书规范。
- 查看`AIPROXY_API_ENDPOINT`的接口调用日志，确认接口请求均携带合法密钥，无未授权访问提示。
