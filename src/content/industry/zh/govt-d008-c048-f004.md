# 行政许可审批的业务办理流程引导：工作流编排
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
行政许可审批相关数据取自全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统及电子证照库，更新频率为每日。日常涉及的文档包含办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书及许可证照，数据结构包含事项编码、办理条件、申请材料清单、审批流程节点、证照模板等字段，部分数据为结构化表单，部分为非结构化的规范政务文本。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且每日更新，要求工作流需配置定时同步节点以保证数据时效性。文档类型包含结构化表单与非结构化文本，部分文档存在多页扫描件或图片格式的材料，要求工作流适配不同格式的文件处理节点。最耗时的核对申请材料与清单一致性、跨部门调取电子证照环节需拆分为独立节点，以明确流程节点的职责边界。由于出错后果可能涉及超期办结或行政复议，工作流需配置异常捕获与重试机制，避免单点故障导致流程中断。同时，批量事项数据可能超出AI上下文长度，要求工作流需支持分块处理与上下文裁剪。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 行政许可相关文档多为规范政务文本，该长度可避免超出多数AI模型的上下文限制 |
| 单次处理节点数 | 前 10 个 | 避免并行节点过多占用系统资源，适配政务审批流程的常规节点数量 |
| 上下文窗口上限 | 16000 token | 匹配批量处理行政许可事项材料的常规数据量，平衡处理效率与内容完整性 |
| 触发条件 | 按 `variables` 传入的事项 ID 触发 | 确保工作流仅针对指定行政许可事项运行，避免误触发 |
| 异常重试次数 | 2 次 | 减少因临时网络波动、系统接口短暂不可用导致的流程中断，同时避免重复请求引发资源浪费 |
| 文件上传大小限制 | 1000 MB | 适配电子证照、扫描件等政务文件的常规存储与传输大小 |

## 容易做错的三处
- 现象为工作流运行时弹出上下文长度超限提示，报错文案显示“输入文本超出模型最大支持长度”，原因是未对批量行政许可申请材料进行分块处理，直接传入完整数据。
- 现象为图片转base64节点执行后返回字段为空，原因是未通过`nodeId`关联文件读取节点与编码转换节点，未正确传递文件二进制数据。
- 现象为API调用上传文件后工作流未触发，返回状态码400，原因是未在请求体中传入`variables`参数指定的文件标识，导致流程无法匹配触发条件。

## 怎么确认配好了
- 导入一份标准行政许可办事指南文档，运行工作流查看分块后的文本是否符合预设长度范围。
- 上传一张政务相关的扫描图片，验证编码转换节点是否成功生成base64编码并将结果传入后续AI节点。
- 调用测试API上传小型测试文件，查看工作流是否正常触发并返回符合预期的流程运行日志。
- 检查每日数据同步节点的运行记录，确认数据更新频率符合每日同步的要求。
