# 行政许可审批的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统及电子证照库，更新频率为每日。日常处理的文档包含办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书及许可证照，涵盖结构化事项字段与非结构化文书内容，数据结构随法定事项调整同步更新，仅包含官方规定的标准化字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
行政许可场景的数据多源分散且每日更新，要求模型接入配置需支持多源文档的上下文拼接与增量索引更新。法定文书的严格格式与官方术语要求，需限制生成内容的随机性，避免出现非法定表述。跨部门协同的业务逻辑，要求配置支持工具调用以调取电子证照等外部数据。同时，业务办理的法定时限要求，需控制模型生成与召回的响应时长，确保流程符合法定节点。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 行政许可场景的业务文档包含事项清单、办事指南、申请材料等多源内容，需承载足够长的上下文以匹配完整办理逻辑 |
| `temperature` | 0.1–0.3 | 需严格匹配法定术语与办理要求，降低生成随机性以避免错误引导 |
| `maxTokens` | 2000–3000 字符 | 业务办理引导需清晰明确，控制输出长度以适配政务场景的阅读习惯 |
| `quoteMaxToken` | 6000–10000 token | 需完整引用官方办事指南与事项清单内容，确保引导依据的准确性 |
| `toolChoice` | 自动 | 需支持跨部门电子证照调取等工具调用，适配行政许可的跨主体协同需求 |
| `AIPROXY_API_ENDPOINT` | 按政务合规大模型的代理地址填写 | 适配政务场景的数据安全与合规要求 |

## 容易做错的三处
- 现象：调用大模型生成的办理引导内容出现非法定术语。原因：`temperature`参数取值过高，未限制生成随机性，且未在系统提示词中明确要求使用官方规定的政务术语。
- 现象：知识库召回的文档与当前办理事项不匹配。原因：未正确配置`maxContext`参数，导致上下文窗口不足以覆盖事项清单的完整匹配条件，或数据源未关联最新的行政许可事项清单。
- 现象：尝试调用三方大模型时返回认证失败。原因：`AIPROXY_API_TOKEN`填写错误，或代理地址未适配政务网络的访问限制。

## 怎么确认配好了
- 输入标准化的行政许可办理咨询，核对生成的引导内容是否匹配官方办事指南的法定流程。
- 查看知识库召回日志，确认返回的文档来源覆盖配置的政务数据源。
- 触发增量同步任务，确认索引更新流程按每日频率正常执行。
- 测试三方大模型调用，确认身份验证与接口调用无异常。
