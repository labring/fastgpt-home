# 行政许可审批的业务办理流程引导：表单与交互

## 这个品类的数据长什么样
本品类数据主要来自全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统及电子证照库，更新频率为每日。日常关联文档包含办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书、许可证照。数据以法定许可事项为边界，包含事项设定依据、办理条件、申请材料清单、办理流程等固定字段，无额外自定义统计类字段。

## 这些特征在「表单与交互」这一环带来什么约束
数据的每日更新要求表单需同步匹配最新的事项清单，避免出现已失效的申请字段或办理要求。多类型固定格式的文档要求交互需支持不同文档的结构化提取，例如申请表的必填字段识别、补正告知书的问题项提取。跨部门数据源的一致性要求表单需校验申请材料与事项库清单的匹配度，防止因数据不同步导致的材料不符。法定许可的边界要求表单需严格对应事项的办理条件，不可随意增减字段或调整校验规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 按单事项清单配置10-20个必填字段，附带官方提示文案 | 需严格匹配行政许可事项的法定申请材料要求，确保表单字段与事项一致 |
| `userSelect` | 预设办理部门、办理层级选项，支持按行政区划动态加载 | 适配跨层级审批的业务场景，匹配政务服务的属地管理规则 |
| 单次结果召回上限 | 前5条 | 行政许可事项的申请材料通常为固定清单，无需召回过多结果 |
| 输入校验超时 | 300秒 | 需覆盖跨部门调取电子证照的常规耗时，避免校验中断 |
| 文档拆分阈值 | 800-1200字符 | 适配办事指南、申请表等文档的段落长度，保证拆分后语义完整 |

## 容易做错的三处
- 配置`formInput`时未绑定每日更新的事项库清单，导致提交申请时返回400错误。原因：未启用自动同步配置，沿用了旧版事项清单的字段设置。
- 未限制`userSelect`的工具调用并发，导致多用户同时提交时出现工具调用冲突。原因：未配置互斥触发规则，未限制单会话的工具调用次数。
- 语音输入接入表单校验时出现ssl报错，无法正常提交申请材料。原因：未部署有效SSL证书，或后端服务的SSL端口未对外开放。

## 怎么确认配好了
- 随机抽取不同类别的行政许可事项，核对表单字段与对应事项库的申请材料清单是否一致。
- 模拟多用户同时提交表单，检查工具调用是否出现冲突，确认互斥规则生效。
- 触发语音输入并提交表单，检查SSL连接是否正常，无后台报错。
- 调整表单字段的拆分阈值，验证拆分后的文档语义是否完整，符合业务场景要求。
