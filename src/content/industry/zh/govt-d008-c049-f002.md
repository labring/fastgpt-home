# 规范性文件合法性审核的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
本品类涉及的核心数据来自法规规章库、上位法数据库、部门政策文件库及行政规范性文件备案系统，文档类型包括规范性文件草案、起草说明、合法性审核意见、征求意见汇总与备案报告。数据更新无固定周期，随政策制定、审核及备案流程动态产生。单份文档包含起草背景、条文内容、征求意见细节、审核依据等字段，无统一固定格式，部分文档为多页汇编材料。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且无统一格式，要求索引系统支持多源异构数据的自动适配解析，避免因格式不兼容导致的索引失败。更新频率不定期，需配置增量索引同步机制，避免全量重建索引带来的资源消耗与时间延迟。文档多为政策类长文本，需适配长片段的向量分块逻辑，避免拆分关键法律依据或政策条文。合法性审核需精准匹配上位法依据，要求索引召回的相关性阈值需高于通用场景，确保核心法律依据不遗漏。多份关联文档需保持索引一致性，避免审核时出现依据冲突的情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配规范性文件条文的段落长度，避免拆分关键法律依据 |
| 重叠长度 | 100–150 字符 | 保留相邻块的上下文关联，防止条文拆分导致的逻辑断裂 |
| 相似度阈值 | 0.85–0.9 按实测标定 | 确保召回的上位法依据具备高度相关性，适配合法性审核的严谨性要求 |
| 单次搜索上限 | 前 10 条 | 平衡召回效率与审核所需的依据覆盖范围 |
| `maxToken` | 16384 | 适配长文本审核的上下文窗口需求，避免截断核心审核依据 |
| `defaultToken` | 2048 | 匹配单块向量的编码长度，确保分块数据的向量一致性 |

## 容易做错的三处
-  索引任务长期处于「索引中」状态且无进度更新，原因是未配置增量索引的超时机制，或选用的向量模型编码长文本时超出`maxToken`限制导致阻塞。
-  数据集中的索引条目自动重复增加，原因是未开启重复数据去重开关，或增量同步时未基于文件哈希值做增量判断，导致重复上传的文档生成多组索引。
-  索引模型配置后关联的语言模型无法正常调用，原因是未正确绑定索引模型与语言模型的权限配置，或索引模型的编码参数与语言模型的上下文要求不匹配。

## 怎么确认配好了
-  上传单份测试用的规范性文件草案，查看索引生成进度，确认任务在10分钟内完成且无报错日志，本操作基于FastGPT v4.17.0版本的界面逻辑。
-  手动触发一次增量同步，检查数据集中的索引条目数量仅随新增文档更新，无重复条目出现。
-  输入一条合法性审核的检索请求，查看召回结果的相似度得分均符合预设阈值范围。
-  查看向量模型的调用日志，确认`defaultToken`与`maxToken`的配置参数被正确加载，无参数冲突提示。
