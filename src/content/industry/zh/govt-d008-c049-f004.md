# 规范性文件合法性审核的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
本品类处理的数据主要来自法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新频率不定期。日常流转的文档包括规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告。处理主体为司法行政部门、部门法规处、政府办公室政策法规岗，数据聚焦抽象政策规则的制定合法性审查，与行政执法个案的流程处理存在差异。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新无固定周期，要求工作流支持动态挂载多类数据源节点，适配不同来源的文档拉取。日常文档类型多样，需配置字段映射规则，确保不同文档的审核参数可以精准传递。审查核心环节耗时占比高，工作流需拆分为上位法比对、权利义务审查、意见汇总等独立节点，支持人工介入校验。出错后果直接影响政策发布与执行，工作流需设置前置校验与异常告警节点，拦截不符合要求的流程环节。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工作流功能实现。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 数据源节点配置 | 按法规规章库、备案系统分别挂载 | 数据来源分散，需精准对接不同的官方数据渠道 |
| 变量映射规则 | 绑定`variables`字段匹配文档字段 | 日常流转的文档类型多样，需精准传递审核所需的参数 |
| 人工审核节点 | 设置为上位法比对、意见汇总环节的后置节点 | 核心审查环节需人工介入校验，确保合法性 |
| 异常告警触发 | 触发`nodeId`为异常校验的节点时推送通知 | 流程出错会影响政策发布，需及时响应异常 |
| 单次请求超时阈值 | 600-900秒 | 数据拉取与比对环节耗时存在波动，按实测标定合理区间 |
| 单次文件上传上限 | 1000 MB | 规范性文件草案及附件通常适配该体量，符合业务常规 |

## 容易做错的三处
- 工作流上传文件时出现`Failed to create post presigned url`报错，原因是未正确配置文件存储节点的权限参数，导致无法生成上传预签名链接。
- 知识库搜索模块的变量引用未生效，原因是未绑定`variables`字段与审核文档的对应字段，导致参数无法正确传递至搜索模块。
- 流程节点流转卡住，原因是未设置人工审核节点的触发条件，导致核心审查环节无法进入人工校验步骤。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本的工作流功能实现。
- 测试拉取不同来源的文档，确认数据源节点可以正常接入并读取对应数据。
- 上传一份规范性文件草案，确认文件上传节点可以正常完成上传，无预签名链接报错。
- 触发异常校验节点，确认系统可以推送告警通知。
- 流转核心审查环节，确认人工审核节点可以正常触发并流转至下一环节。
