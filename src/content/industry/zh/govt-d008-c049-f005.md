# 规范性文件合法性审核的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来自法规规章库、上位法数据库、部门政策文件库及行政规范性文件备案系统，更新频率不定期。日常处理的文档包含规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告，文档以条文式、段落式文本为主，部分配套材料包含附件扫描件。数据字段涵盖文件编号、制定主体、条文内容、制定权限依据等，无统一固定的单位计量字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且更新无固定周期，工具调用需适配多源异构数据的接入格式，需支持按需拉取或定时同步的配置逻辑。日常处理的文档包含纯文本与附件扫描件，工具调用需同时适配文本解析与多模态视觉分析能力。核心审核环节需比对上位法与权限依据，要求工具调用需精准匹配条文内容与制定权限规则，需限定调用结果的相关性范围。由于出错后果直接影响政策发布与备案进度，工具调用的失败处理需具备重试与异常告警机制，避免延误审核流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多类型工具调用需求，无需手动指定具体工具，符合审核场景下多源数据比对的灵活调用要求 |
| 工具调用超时时间 | 300-600 秒 | FastGPT v4.17.0 版本下该配置项默认取值为 120 秒，规范性文件审核需比对多份分散数据源，单次调用耗时较长，该区间可覆盖多数数据拉取与比对流程 |
| `functionCall` | `enabled` | 需调用外部法规数据库接口，启用函数调用可实现参数化的精准数据请求，提升审核匹配精度 |
| 附件图片解析配置 | 启用多模态视觉模型，单次解析上限 10 张/调用 | 日常审核材料常附带少量附件扫描件，该配置可适配常规附件解析需求，避免单次调用过载 |
| 工具调用结果过滤 | 按内容相关性排序，取前 3-5 条 | 规范性文件审核需聚焦核心上位法与权限依据，过多冗余结果会增加审核负担，该范围可聚焦有效内容 |
| 异常告警触发条件 | 触发数据拉取失败类报错时触发 | 该类错误多为数据源或接口异常，需及时通知审核人员排查问题 |

## 容易做错的三处
- 现象：调用多模态模型解析附件图片时返回 `Failed to fetch` 报错。原因：未配置图片拉取的访问权限或数据源白名单，导致工具无法从备案系统或本地存储中下载目标图片文件。
- 现象：工具调用返回的结果条数超出预期范围。原因：未正确设置结果过滤规则，或配置项取值不符合审核场景的需求，导致冗余数据被纳入审核流程。
- 现象：调用外部法规数据库接口无匹配结果。原因：`functionCall` 参数未启用，或未正确配置调用接口的权限与参数格式，导致工具无法完成精准数据请求。

## 怎么确认配好了
- 提交测试用的规范性文件草案与配套附件，查看工具调用日志中的图片解析记录，确认图片拉取权限配置已生效。
- 触发工具调用后，核对返回结果的数量是否符合预设的过滤逻辑，确认结果过滤配置已生效。
- 手动调用配置好的外部法规数据库接口，查看是否能返回匹配的法规依据，确认函数调用相关配置已生效。
- 模拟数据拉取失败的场景，确认异常告警机制是否能正常触发，确认告警配置已生效。
