# 规范性文件合法性审核的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源为法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新频率不定期。日常处理的文档包含规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告，文档结构多包含条文内容、制定主体、生效日期、权限依据等字段，单份文档篇幅跨度较大，部分草案类文档可能包含多章节条文与配套说明材料。

## 这些特征在「模型接入与配置」这一环带来什么约束
本页内容适配FastGPT v4.17.0版本。数据来源分散且更新无固定周期，需要配置适配多源异构数据的接入逻辑；文档篇幅跨度大且包含专业法条内容，要求模型上下文承载能力匹配长文本处理需求；审核需严格比对上位法与权限依据，对检索召回的精准度有明确要求；不同场景下的文档字段差异较大，需配置可灵活适配的元数据解析规则，确保审核环节的准确性与合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–16000 token | 匹配规范性文件草案及配套材料的长文本处理需求，避免截断核心审核依据 |
| `maxTokens` | 2000–3000 token | 适配审核意见生成的输出长度需求，确保完整呈现合法性审查结论 |
| `quoteMaxToken` | 1000–1500 token | 限制检索引用的法条原文长度，保证上下文窗口内可容纳多份上位法比对内容 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保审核结论的严谨性与规范性，符合法治审核的确定性要求 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的专属地址填写 | 适配外接API的模型调用链路，确保请求路由正确 |
| `AIPROXY_API_TOKEN` | 按获取的认证密钥填写 | 完成模型调用的身份验证，保障接口访问安全 |

## 容易做错的三处
- 现象：首次发起规范性文件审核请求时等待时间超过3秒，后续请求响应正常。原因：未启用会话缓存配置，每次请求都重新加载模型权重，导致首次调用耗时过长。
- 现象：调用外接模型时出现显存占用过高报错，或arm软路由部署场景下无法流畅运行。原因：未配置多模型加载的显存隔离规则，同时加载多个模型导致硬件资源耗尽，未适配arm架构的模型编译配置。
- 现象：检索返回的上位法条文与审核依据不匹配，结果条数不符合预期。原因：`quoteMaxToken`配置值过小，截断了部分关联法条的引用内容，导致召回结果不完整。

## 怎么确认配好了
- 发起单份规范性文件草案的审核测试，检查上下文窗口是否完整加载所有核心文档内容，无截断提示。
- 调用模型接口，查看返回的审核结果中是否包含明确的上位法引用标记，确认检索召回的内容符合审核需求。
- 验证外接API的认证配置，使用测试工具发起请求，确认返回状态码为200且无认证报错。
- 观察模型加载与调用的日志，确认首次请求后的响应时间符合预期，无异常耗时。
