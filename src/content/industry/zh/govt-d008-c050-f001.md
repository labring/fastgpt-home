# 财政支出绩效评价的业务办理流程引导：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据覆盖财政局绩效处、预算单位、第三方评价机构等主体的日常业务文档，包括绩效目标表、自评表、绩效评价报告、佐证材料清单及整改报告。数据主要来源于预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查，更新频率为年度。数据包含项目绩效指标、资金使用明细、佐证材料关联关系等核心字段，需匹配业务办理中的核验逻辑，无统一的单文档固定格式，需根据业务环节动态调整字段组合。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
年度更新的频率决定接口无需高频调用，需适配批量数据拉取的场景。多来源的数据要求接口需对接多个外部系统，需兼容不同系统的身份校验、数据格式与返回结构。多样化的业务文档与动态字段组合，要求接口请求体需携带灵活的业务参数，避免硬编码固定字段。核验资金支出与绩效目标的对应关系，要求接口返回的数据需包含强关联的项目ID、资金流水与绩效指标字段，确保数据校验的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | 携带 Bearer 前缀的令牌，有效期不超过 7 天 | 适配外部财政系统的身份校验规则，降低令牌泄露后的风险范围 |
| `variables` | 包含绩效项目ID、报告类型、关联单位编码的键值对 | 匹配财政支出绩效评价业务的固定查询与校验参数，避免请求参数缺失 |
| `responseData` | 解析为 JSON 格式的结构化数据，保留原始字段名 | 适配绩效评价业务的字段校验逻辑，便于后续数据整理与核验 |
| 请求超时时间 | 300 秒 | 适配批量拉取年度绩效数据的耗时需求，避免中途断开导致流程中断 |
| 重试次数 | 不超过 3 次 | 应对外部系统临时接口波动，减少单次请求失败对业务流程的影响 |
| 数据格式校验 | 开启图片与文本字段的格式校验 | 适配佐证材料上传与数据核验的业务要求 |

## 容易做错的三处
- 调用接口返回400状态码，日志包含"The request failed because the image format"。未正确配置`variables`传递项目关联参数，或未适配财政佐证材料的图片格式校验规则，导致外部系统拒绝请求。
- 在线对话与API调用返回结果差异显著。未在API请求中配置`variables`传递固定业务上下文，导致模型调用的提示信息与参数不一致，出现结果偏差。
- 接口调用无日志记录，无法排查异常。未开启FastGPT的API调用日志功能，无法定位请求参数错误或外部系统响应异常的具体原因。

## 怎么确认配好了
- 调用接口携带`Authorization`参数，验证返回状态码为200，确认身份校验通过。
- 检查`responseData`返回的字段包含绩效项目ID、资金流水明细与绩效指标，确认数据结构符合业务要求。
- 模拟批量数据请求，验证超时时间设置符合实际耗时，无中途断开情况。
- 对比在线对话与API调用的参数，确认`variables`配置一致，验证结果无显著差异。
- 在FastGPT v4.17.0版本中开启API日志功能，确认请求与响应数据被完整记录。
