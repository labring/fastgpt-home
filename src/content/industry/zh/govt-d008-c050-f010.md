# 财政支出绩效评价的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查，更新频率为年。日常处理的文档包括绩效目标表、自评表、绩效评价报告、佐证材料清单、整改报告，字段多涉及项目编号、资金额度、绩效指标、佐证材料编号等，无统一固定单位，需匹配文档原生字段进行处理。

## 这些特征在「知识库检索与召回」这一环带来什么约束
年更新频率决定知识库无需高频同步，可设置固定周期全量更新。多类文档混合的结构，要求检索时需支持按文档类型过滤召回结果。字段涉及专业度较高的绩效相关内容，需匹配原生字段进行精准召回，避免泛化匹配干扰业务判断。佐证材料清单与绩效报告关联紧密，需支持跨文档关联召回，确保检索结果能覆盖完整的绩效佐证链路。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 本品类文档字段专业度高，需过滤低匹配度的无关内容，避免干扰绩效指标核验 |
| `limit` | 前8–12条 | 绩效评价需覆盖目标、自评、佐证等多类文档，适量召回确保覆盖完整业务环节 |
| `searchMode` | `vector` | 本品类数据多为结构化与半结构化文档混合，向量检索能精准匹配专业字段 |
| `usingReRank` | 开启 | 需对召回结果按业务相关性重排序，确保核心绩效指标、佐证材料优先展示 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可通过扩展查询补充专业术语，提升对绩效评价专属词汇的召回精度 |
| `collectionIds` | 按文档类型配置对应集合ID | 本品类文档分类明确，按集合过滤可减少无关数据干扰 |

## 容易做错的三处
- 导入的绩效评价报告PDF在检索结果中无法打开，原因是未配置知识库文件的外链跳转权限，或未将文档上传至支持直接访问的存储路径。
- 开启`usingReRank`后，检索完成后显存持续占用，原因是未设置检索完成后自动释放重排模型资源的逻辑，导致模型资源未被回收。
- 选择问答拆分功能后报Invalid array length错误，原因是拆分时未过滤空字段或超长文本块，导致数组参数异常。

## 怎么确认配好了
- 上传一份绩效目标表文档至对应知识库集合，发起包含绩效指标关键词的查询，核对召回结果中是否包含该文档的有效片段。
- 查看系统显存占用情况，确认发起检索并获取结果后，重排模型占用的显存自动释放。
- 测试问答拆分功能，输入一份自评表的完整文本，确认无Invalid array length报错。
- 配置`similarity`阈值后，发起低匹配度的查询，确认结果被过滤，仅保留符合阈值的内容。
