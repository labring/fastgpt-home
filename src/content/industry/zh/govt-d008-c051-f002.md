# 道路运输经营许可的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
道路运输经营许可业务办理场景的数据主要来自道路运政管理系统、全国道路运输车辆动态信息公共服务平台、车辆和从业人员数据库三类官方系统。日常处理的文档包含经营许可申请、车辆技术档案、驾驶员从业资格材料、安全生产管理制度、道路运输经营许可证等。数据更新频率为每日一次，核心字段包含经营主体信息、车辆技术参数、从业人员资质、安全管理制度条款等，不同文档的结构差异明显，部分为结构化表单，部分为纯文本制度文件。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的官方数据要求索引环节需支持增量同步，避免全量重复索引带来的资源浪费。多源异构的数据来源需统一字段格式，否则会导致嵌入模型无法正确识别语义关联。文档结构的差异要求分块策略需适配不同类型的文本长度，结构化表单的字段较少，纯文本制度文件则篇幅较长。核心业务环节聚焦车辆人员核验、安全制度审查等内容，索引需优先覆盖这些高权重字段，否则会影响后续的流程引导准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配道路运输经营申请、车辆技术档案等单文档的平均文本长度，避免分块过碎或丢失业务逻辑 |
| 重叠长度 | 50–100 字符 | 保留分块间的上下文关联，避免跨块的资质核验逻辑断裂 |
| `maxToken` | 4096 | 适配主流嵌入模型的输入长度限制，避免截断核心业务字段 |
| 单次召回上限 | 前10条 | 覆盖审批环节需核验的多类材料，避免召回过多冗余数据 |
| `defaultToken` | 1024 | 统一嵌入任务的默认输入token配额，平衡计算成本与文本覆盖度 |
| 超时时间 | 600 秒 | 适配道路运输业务数据的批量索引处理时长，避免因数据量较大触发自动中断 |

## 容易做错的三处
- 界面显示索引任务持续处于运行中无进度：原因是未适配道路运输业务数据的日更新频率，未配置增量索引触发规则，或嵌入模型调用超时未设置合理重试机制。
- 调用嵌入模型返回503状态码：原因是未配置模型调用的分组限流策略，default分组的并发配额不足以支撑道路运政系统的批量数据索引请求。
- 召回结果中缺失驾驶员从业资格材料的匹配项：原因是分块时未保留从业人员数据的核心字段，或相似度阈值设置过高，过滤了弱相关但有效的资质文本。

## 怎么确认配好了
- 查看索引任务日志，确认每日增量索引任务按设定时间自动触发，无批量失败记录。
- 测试嵌入单份道路运输经营许可证文本，检查`maxToken`未触发截断警告，嵌入结果无字段缺失。
- 手动输入“车辆技术档案核验标准”的查询词，核对召回的分块内容包含车辆技术档案、安全生产管理制度的核心条目。
- 验证嵌入模型调用的返回结果数量符合单次召回上限的设置，无异常超时报错。
