# 道路运输经营许可的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
该品类的数据来源于道路运政管理系统、全国道路运输车辆动态信息公共服务平台、车辆和从业人员数据库，更新频率为每日。日常涉及的业务文档包括经营许可申请材料、车辆技术档案、驾驶员从业资格材料、安全生产管理制度文本、道路运输经营许可证件。数据字段涵盖经营主体基本信息、车辆资质编号、从业人员资格等级、安全管理制度细则等，所有字段均对应交通运输行业统一规范的业务条目，无额外自定义统计单位。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源多为政务类业务系统，工作流编排需适配政务数据的安全调用规范，配置必要的身份鉴权与数据脱敏节点。每日更新的数据源要求工作流触发周期与数据同步节奏对齐，避免调用过期的车辆、从业人员资质数据。文档类型覆盖结构化申请表格与非结构化文本档案，工作流需兼容多格式数据解析与字段提取。资质类字段需严格匹配道路运政系统的校验规则，工作流节点需预设字段合规性校验逻辑，防止不合规材料进入后续审批环节。

## 配置怎么定
以下配置项基于 FastGPT v4.17.0 版本的工作流编排界面。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定经营主体ID、车辆资质编号 | 匹配业务办理需关联唯一主体与资质的需求，实现数据精准匹配 |
| 节点超时设置 | 600 秒 | 政务审批类业务的交互周期较长，避免因超时中断流程 |
| 表单数据配置 | 按业务文档字段映射 | 匹配经营许可申请的标准字段，确保提交数据符合政务系统要求 |
| 文件上传校验 | 限制单文件 1000 MB，支持PDF、DOCX格式 | 适配道路运输档案的常见文件大小与格式，避免上传失败 |
| `nodeId` | 绑定资质核验节点ID | 确保工作流流转至对应节点时触发校验逻辑，匹配审批环节顺序 |
| 触发频率 | 每日 0 点同步 | 匹配数据源的每日更新节奏，获取最新的车辆与从业人员数据 |

## 容易做错的三处
- 工作流在运行预览页面正常运行，聊天页面无数据返回。原因是工作流未配置`variables`的会话参数传递，预览阶段使用本地测试数据，聊天页面无法获取业务上下文的关联数据。
- 上传文件时提示Load file error。原因是工作流的文件上传节点未配置匹配道路运输档案的格式白名单，或单文件大小超出预设阈值。
- HTTP请求节点的form-data参数无法正确传递文件。原因是未将文件参数绑定至工作流的文件上传节点输出，仅配置了文本类型的参数值。

## 怎么确认配好了
- 触发工作流，传入预设的经营许可申请材料，核对节点流转是否匹配预设的审批环节顺序。
- 上传符合业务文档格式的测试文件，确认文件上传节点无报错并成功传递至后续环节。
- 调用HTTP请求节点，核对返回数据是否与道路运政系统的校验规则匹配。
- 查看工作流日志，确认`variables`参数与`nodeId`节点的绑定关系正常，无参数缺失。
