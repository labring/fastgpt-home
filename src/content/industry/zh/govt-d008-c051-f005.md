# 道路运输经营许可的业务办理流程引导：工具调用与插件

本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据主要来源于道路运政管理系统、全国道路运输车辆动态信息公共服务平台、车辆和从业人员数据库，更新频率为每日。日常涉及的文档包括经营许可申请材料、车辆技术档案、驾驶员从业资格材料、安全生产管理制度文件、道路运输经营许可证件。数据字段包含经营主体统一社会信用代码、车辆号牌号码、从业人员资格等级、安全管理制度条目等，无统一固定单位，部分字段需匹配政务系统预设的资质编码规则。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源多为政务系统，调用时需遵循接口权限校验规则，每日更新的数据源要求工具调用需设置合理的同步周期，避免频繁请求超出政务接口限流。文档类型多样，需针对不同文档配置对应的解析规则，车辆技术档案、驾驶员材料等需提取特定资质字段。核验环节依赖多源数据交叉验证，工具调用需支持同时调取多个数据源的信息，确保核验的完整性。需通过`functionCall`配置强制校验工具返回的字段格式，确保提取的资质信息符合审批要求。出错后果直接关联许可审批结果，工具调用失败需触发明确的重试机制与异常告警，避免影响审批流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动匹配道路运输经营许可核验所需的工具，适配多数据源调取场景 |
| `functionCall` | 开启强制校验模式 | 确保工具调用返回的字段严格符合审批材料的格式要求 |
| 批量执行工具 | `2 个并行任务` | 可同时调取车辆资质、从业人员资格、安全制度三类数据源，平衡效率与接口限流 |
| 变量更新 | 按分类设置`5 次`调用次数上限 | 记录不同资质材料的核验调用次数，避免重复请求同一数据源 |
| 流式回答配置 | 开启思考内容直接输出，上下文窗口设为`800–1200 字符` | 直接输出模型思考过程与最终结果，无需等待完整响应后再推送 |
| 工具调用重试 | `3 次`重试次数 | 应对政务接口偶发的请求失败，保障核验流程的连续性 |

## 容易做错的三处
- 现象：调用API返回结果不包含模型思考内容，仅展示最终审批结论。原因：未开启流式回答配置中的思考内容直接输出开关，导致响应仅返回最终生成内容。
- 现象：批量执行工具未按预期完成多数据源调取，返回结果条数不足。原因：并行任务数设置超出政务接口的限流阈值，导致部分请求被拦截。
- 现象：变量更新工具未自动更新分类调用次数，对应字段显示为空。原因：未配置变量更新的触发条件与对应分类的映射规则，导致调用记录无法正确写入。

## 怎么确认配好了
- 发起一次模拟的道路运输经营许可申请核验请求，查看工具调用日志中是否自动匹配到对应工具。
- 检查变量更新记录，确认不同资质分类的调用次数是否按预期写入对应字段。
- 查看流式响应的返回内容，确认是否同时包含思考过程与最终审批结论。
- 测试批量执行工具的并行调用，确认返回结果的条数与预期调取的数据源数量一致。
