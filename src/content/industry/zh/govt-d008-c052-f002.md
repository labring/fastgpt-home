# 部门决算与财务报告的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自预算管理一体化系统、国库集中支付系统、会计核算系统与资产管理系统，更新频率为年度周期。日常文档包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告，文档结构多为结构化表格与配套说明文本，字段涵盖收支明细、资产负债余额、预算执行差异说明等，单位多为元、万元等财政核算标准单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
年度更新的低频特性要求索引支持全量重建与增量更新结合，避免重复计算历史数据。多源系统导入的异构数据需统一字段格式，防止向量嵌入偏差。结构化表格与文本混合的文档结构，需要适配分块策略兼顾表格完整性与文本语义。财政核算字段的专业性要求向量模型适配专业术语，避免语义混淆。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配部门决算文档的表格与文本混合结构，避免语义断裂 |
| 重叠长度 | 50–100 字符 | 保留跨分块的上下文关联，防止表格行跨块丢失 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 匹配财政专业术语的语义相似度区间，过滤低相关结果 |
| 单次搜索上限 | 前 8 条 | 覆盖下级单位报表汇总的多文档关联需求 |
| `defaultToken` | 4096 | 适配决算文档的总文本长度，保证完整加载单份报表内容 |
| `maxToken` | 8192 | 支持多份报表合并查询的上下文长度，满足汇总分析需求 |

## 容易做错的三处
- 现象：索引任务报错提示「文本过长无法嵌入」，原因：未设置`maxToken`限制单文档输入长度，导致超大型决算报表超出模型承载上限。
- 现象：不同索引模型混用后搜索结果混乱，原因：未统一向量模型的嵌入维度，混搭不同领域的索引模型导致语义空间不一致。
- 现象：自定义RAG查询返回空结果或层级关联失效，原因：未针对部门决算的上下级汇总逻辑配置关联索引，仅使用扁平化实体索引，无法体现数据间的层级关系。

## 怎么确认配好了
- 上传单份典型决算报表，检查索引分块是否保留表格完整行与核心语义段落，确认分块长度与重叠长度配置符合文档结构。
- 输入财政专业查询词，验证搜索结果的相似度区间是否符合业务预期，调整相似度阈值至合理范围。
- 导入多源异构数据后，检查索引任务是否正常完成，确认数据格式统一后未出现嵌入失败报错。
- 发起跨单位报表的汇总查询，验证搜索结果是否覆盖目标单位的相关文档，确认单次搜索上限配置合理。
