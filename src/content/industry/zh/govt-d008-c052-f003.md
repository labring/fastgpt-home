# 部门决算与财务报告的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来自预算管理一体化系统、国库集中支付系统、会计核算系统与资产管理系统，更新频率为年度一次。日常生成的文档包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告，结构上分为基础填报数据、汇总统计数据与差异分析说明三类，字段涵盖单位编码、收支金额、资产负债余额、填报口径说明等，单位包含金额单位、数量单位等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
年度更新的数据特征要求多轮对话需明确关联对应决算年度的上下文，避免跨年度数据混淆。多源系统的数据来源，要求提示词需引导对话对齐各系统的统一字段口径，防止因字段不匹配导致账表核对错误。复杂的文档结构与多类填报内容，要求多轮对话需逐步拆解业务环节，先确认基础填报项再推进汇总与差异分析。年度决算的办理节奏约束，需限制对话流程的无效跳转次数，避免超出常规办理周期。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 最大上下文窗口 | `8000–12000 token` | 部门决算相关文档与交互记录篇幅较长，需保留完整的历史对话与填报数据上下文 |
| 单次回复token上限 | `3000 token` | 决算说明、差异分析类内容需完整输出，避免被截断导致信息缺失 |
| 知识库召回条数 | 前6条 | 需覆盖部门决算报表、资产负债表、收入支出决算表等多类文档的关键字段与填报规则 |
| 变量绑定 | 绑定决算年度、单位编码 | 精准匹配对应年度与单位的专属决算数据，避免跨主体混淆 |
| 会话id管理 | 启用 | 保留单轮对话的上下文连贯性，对应英文参数`chatId` |
| 消息历史管理 | 启用`messages`参数 | 存储多轮对话的交互内容，确保上下文连贯 |
| 动态变量传递 | 启用`variables`参数 | 实现多轮对话中动态传递决算填报的中间结果，如已核对的收支数据 |

## 容易做错的三处
- 现象为部分特定问题的回复被强制截断为200 token以内，界面显示响应长度不足。原因是未针对决算类长内容调整全局与单轮回复的token上限配置，默认阈值被触发。
- 现象为知识库无法自动同步新增的决算文档内容，查看后发现新上传的文档未被正确索引。原因是未配置文档自动更新触发规则，或未选择对应决算文档的分类标签。
- 现象为多轮对话中无法保留前一轮的单位编码上下文，导致后续问答出现数据匹配错误。原因是未启用`chatId`参数绑定会话上下文，或未绑定单位编码的变量配置。

## 怎么确认配好了
- 发起包含决算年度、单位编码的多轮对话，检查对话历史是否完整保留交互内容，确认`chatId`与`messages`参数生效。
- 上传一份部门决算报表文档，发起查询该文档字段的问题，检查返回结果是否包含对应字段说明与填报规则。
- 发起一段较长的差异分析查询，检查回复长度是否达到预设的token上限，未被强制截断。
- 查看FastGPT v4.17.0的系统设置页面，确认变量绑定与会话管理的配置项已启用。
