# 部门决算与财务报告的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自预算管理一体化系统、国库集中支付系统、会计核算系统与资产管理系统，更新频率为年度周期。日常文档包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告，文档结构以结构化表格字段为主，包含收支金额、资产负债余额、预算执行差异说明等字段，单位多为人民币元，部分字段需绑定预算单位层级与年度标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
年度单次更新的全量数据需批量处理，要求配置适配长上下文的模型调用逻辑；多系统来源的异构数据需统一字段对齐，模型接入时需预设字段映射规则；决算数据的审计追溯要求，需开启模型输出与原始数据的绑定关联；年度周期的更新节奏，要求配置支持定期触发的全量索引与模型校验流程，避免数据过期影响业务办理。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单年度部门决算全量文档的批量处理需求，避免上下文溢出 |
| `temperature` | 0.1–0.3 | 保障决算数据处理的严谨性，降低输出偏差 |
| `toolChoice` | auto | 允许模型按需调用内置工具完成跨系统数据核对 |
| `AIPROXY_API_ENDPOINT` | 部署模型的专属接口地址 | 实现模型的私有云接入，保障财政数据安全 |
| `maxTokens` | 2000–3000 token | 控制单条模型输出的长度，适配决算说明类文档的撰写要求 |
| `quoteMaxToken` | 1500 token | 绑定原始数据引用的长度，满足审计追溯的业务要求 |

## 容易做错的三处
- 向量索引任务显示“未完成”状态且无进度更新：未针对年度批量数据配置合适的`maxContext`参数，导致上下文溢出触发索引阻塞，对应业务中常见的向量索引停滞问题。
- 模型无法调用内置工具完成账表核对：`toolChoice`配置为禁用状态，未允许模型调用系统工具获取跨系统数据，无法完成账表与国库支付数据的核对。
- 模型输出的决算说明出现数值偏差：`temperature`取值超出合理区间，导致生成内容偏离原始数据的严谨性要求，引发审计风险。

## 怎么确认配好了
- 提交单年度部门决算样本数据，核对索引任务的执行状态与结果生成情况。
- 发起账表差异核对的测试请求，确认模型可调用预设工具完成跨系统数据校验。
- 生成单条决算说明草稿，检查输出内容是否关联原始数据来源。
- 调整`temperature`参数并对比输出结果，验证参数对输出严谨性的控制效果。
