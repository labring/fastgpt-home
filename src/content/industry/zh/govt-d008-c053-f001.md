# 部门预算编制的业务办理流程引导：HTTP 接口与外部系统

## 这个品类的数据长什么样
部门预算编制的数据通常来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知，更新频率为年度。日常处理的文档包含部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等，字段多涉及人员编制数、项目经费额度、绩效指标等，单位涵盖万元、人、项目编号等，核心用途为年度资金申报与安排。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
年度更新的特性决定接口调用频率较低，但单次请求需处理多源异构数据，对接口的兼容性要求较高。多数据源对接需求要求接口支持跨系统数据拉取与格式转换，需适配不同财政系统的字段规范。复杂的文档结构与核心字段要求，需在接口请求中传递定制化的解析规则，避免关键预算信息丢失。同时，预算数据的敏感性与出错后果，要求接口具备用户维度的会话隔离能力，防止不同预算单位的数据串扰，保障数据安全与审核准确性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | Bearer 格式的API密钥，每7天轮换一次 | 保障预算数据的访问安全，符合财政部门的敏感数据管理要求 |
| `variables` | 传入预算年度、单位编码、项目类型，参数数量控制在3-5个 | 适配不同部门的预算编制场景，减少冗余请求，提升接口调用效率 |
| `responseData` | 返回结构化的预算字段，包含人员经费、项目额度等核心项 | 匹配预算审核的字段校验需求，简化后续数据处理与审核流程 |
| 用户会话绑定 | 按用户唯一标识区分聊天上下文，单次上下文长度800–1200字符 | 避免不同预算单位的历史记录串扰，符合多用户管理的实际需求 |
| 请求超时设置 | 600秒超时阈值 | 处理大型预算数据的测算与汇总环节，避免请求中断导致的流程阻塞 |

## 容易做错的三处
- 现象：调用`/api/v1/chat/completions`接口时，返回的业务引导未匹配部门预算编制的专属要求。原因：未通过`variables`参数传入定制化的预算编制提示词，仅调用默认通用提示。
- 现象：不同预算单位的用户聊天历史记录出现串扰，无法查看自身专属的预算测算过程。原因：未配置按用户唯一标识绑定会话上下文的规则，会话存储未做用户维度隔离。
- 现象：上传部门预算草案PDF后，转换后的Markdown格式丢失表格字段与项目编号。原因：未针对预算文档的复杂表格结构调整文档解析参数，导致关键字段遗漏。

## 怎么确认配好了
- 调用`/api/v1/chat/completions`接口，传入定制化的部门预算编制提示词，验证返回结果包含专属的预算流程引导内容。
- 切换不同的测试用户ID发起请求，验证聊天历史记录仅展示当前用户的会话内容，无跨用户数据串扰。
- 上传部门预算草案PDF，通过文档解析服务转换后，验证核心字段如项目编号、经费额度均完整保留。
- 查看接口返回的`responseData`字段，确认包含预设的预算编制核心字段，无缺失或格式错误。
