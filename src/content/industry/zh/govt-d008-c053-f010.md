# 部门预算编制的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
通常这类场景的数据来自预算管理一体化系统、部门人员编制系统、以前年度决算数据、项目库及财政部发布的预算编制通知。日常生成的文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复文件。数据更新频率为年度周期，文档多包含经费测算字段、项目编码、绩效指标等，单位涉及万元、人、项目周期等，不同文档的字段结构差异较大。

## 这些特征在「知识库检索与召回」这一环带来什么约束
年度更新的数据意味着知识库需定期全量同步，单次同步数据量较大，需适配批量召回逻辑以提升同步效率。文档包含专业的财政字段与术语，要求检索需保留字段语义准确性，避免泛化召回无关内容。多类型混合文档的关键信息位置差异大，需优化分块策略适配不同文档的结构特征。数据来源多为内部业务系统，需配置专属的数据源对接权限，确保检索数据的合规性与安全性。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置逻辑编写，以下为针对部门预算编制场景的知识库检索与召回配置建议：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配财政专业术语的语义匹配，避免召回非预算类的无关文档 |
| `limit` | 前10条 | 控制单次召回结果数量，适配部门预算编制的多项目并行审核场景 |
| `searchMode` | 混合召回 | 结合关键词与语义检索，覆盖不同类型文档的检索需求 |
| `usingReRank` | 开启 | 对召回结果按相关性重排，优化绩效目标表、项目申报书的精准度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展预算相关的专业查询词，适配财政部通知的政策术语 |
| `collectionIds` | 按业务域绑定 | 仅召回预算编制相关的数据集，避免混入其他财政模块的数据 |

## 容易做错的三处
- 检索时返回`invalid configuration parameter name`报错，原因是使用了非指定的英文参数名，例如误配置未列入清单的参数项。
- 知识库搜索响应缓慢，原因是未设置合理的`limit`取值，单次召回过多文档导致向量库计算负载过高，无法适配年度批量数据的检索场景。
- 扫描版PDF文档无法召回有效内容，原因是未启用图片文本提取能力，仅对可编辑文本进行分块，无法识别扫描内容中的预算编制专业术语。

## 怎么确认配好了
- 提交包含预算专业术语的测试查询，核对返回结果的相关性，确认`similarity`和`searchMode`的配置生效。
- 查看检索日志，确认仅调用了绑定的`collectionIds`对应的数据集，无跨域数据被召回。
- 上传扫描版PDF测试文档，检查是否能提取并召回其中的预算相关内容，验证文本提取配置的有效性。
- 模拟多问题并发查询，检查系统响应状态，确认并发控制与`limit`配置的合理性。
