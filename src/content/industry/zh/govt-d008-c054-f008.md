# 防汛防灾与应急值守的业务办理流程引导：文档解析与分块

## 这个品类的数据长什么样
典型主体为应急管理局、水务局、气象局、街道乡镇及应急指挥中心。日常处理的文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单等。数据来源涵盖气象预警系统、水文监测系统、应急指挥平台、基层报灾系统及视频监控。数据更新频率为每日，文档字段包含雨情水情数据、险情等级、物资数量、避险人员信息等，搭配毫米、立方米每秒、人数等专业单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
多源异构的数据来源导致文档格式差异较大，既有结构化的表格类物资调拨单，也有富文本的会商纪要与带图片的灾情速报，要求解析环节同时支持文本提取、表格结构化与图片内容识别。每日更新的实时数据要求分块边界需匹配文档的时间戳，避免跨批次数据混排影响召回准确性。专业字段与单位的保留需求，要求分块不能破坏单条记录的完整性，否则会导致雨情、水情等关键信息被割裂。此外，应急场景下的文档可能包含较大体积的监测数据文件，对解析超时设置提出了更高要求。

## 配置怎么定
本配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 应急文档包含专业字段与单位，过长分块会丢失上下文关联，过短会破坏灾情数据的完整性 |
| `chunkSplitter` | 按段落+表头拆分 | 应急文档多包含表格、预警标题、会商条目，按段落拆分可保留单条预警或单条灾情记录的完整信息 |
| `customPdfParse` | 启用图片文本提取+表格结构化 | 避免用户上传的灾情现场图片、物资表格被忽略，匹配应急文档的多模态需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 部分水文监测导出的大体积CSV或PDF会商纪要解析耗时较长，预留足够时间避免解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配水文监测导出的大体积CSV与压缩包类文档，避免大文件上传被拦截 |
| `chunkSettingMode` | 手动配置 | 适配不同来源的文档格式（如气象预警的短文本、物资调拨的长表格），避免自动分块破坏专业内容结构 |

## 容易做错的三处
- 上传包含灾情现场图片的PDF文档后，解析后的文本块中无图片相关描述，知识库检索未召回图片内容。原因是未启用`customPdfParse`的图片文本提取配置，默认解析规则仅提取PDF纯文本内容。
- 上传javadoc生成的HTML接口文档后，知识库检索无匹配结果，解析后的文本块为空或仅包含少量无关标签内容。原因是默认解析规则未适配结构化HTML的标签嵌套逻辑，无法提取接口文档中的参数与说明文本。
- 分块结果包含跨日期的冗余数据，召回结果中同时出现3天前的预警通知与当日雨情数据。原因是未按文档的发布时间字段进行分块边界控制，导致跨时段文档被错误合并。

## 怎么确认配好了
- 上传单份包含灾情现场图片的PDF文档，检查解析后的文本块是否包含图片中的现场描述文字。
- 上传一份包含表格的物资调拨单文档，检查解析结果是否保留表格的行列结构与对应字段值。
- 上传一份10MB左右的水文监测CSV文件，检查解析过程未触发超时错误。
- 手动调整`chunkSize`参数后，上传一份短文本预警文档，检查分块长度符合设定的字符区间。
