# 防汛防灾与应急值守的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
该品类的核心数据来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控，更新频率为每日。日常处理的文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单，其中值班记录含值守时段与处置条目，预警通知含预警等级与生效范围，灾情速报含受灾点位与初步损失描述，物资调拨单含物资品类与调拨数量。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且多为实时业务系统，要求检索环节需快速同步最新的水文、气象数据，避免召回过时信息。文档类型涵盖结构化表单与非结构化纪要，需适配不同格式的内容召回逻辑。因核心流程为实时应急处置，召回结果需在短时间内返回，且需覆盖跨部门调度所需的多来源数据，同时需保障召回内容的准确性，避免因信息偏差导致处置失误。每日更新的海量文档需高效索引，避免检索延迟影响应急响应速度。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 应急场景需平衡召回精准度与覆盖度，避免误召回无关灾情信息，同时保障核心处置相关内容被召回 |
| `limit` | `前8–12条` | 应急处置需快速获取关键信息，过多结果会增加一线值守人员的筛选成本，过少则可能遗漏重要参考 |
| `searchMode` | 混合检索 | 需同时匹配关键词与语义，覆盖结构化表单的精确匹配与非结构化纪要的语义匹配需求 |
| `usingReRank` | 开启 | 多来源召回的结果需重排优先级，保障高关联的会商纪要、预警通知等核心内容优先返回 |
| `datasetSearchUsingExtensionQuery` | 开启 | 应急场景下用户提问可能省略专业术语，通过扩展查询覆盖同义词与行业专属表述，提升召回覆盖率 |
| `collectionIds` | 绑定对应应急业务数据集 | 隔离不同部门的业务数据，避免跨权限召回无关内容，保障检索范围仅覆盖当前应急场景所需文档 |

## 容易做错的三处
- 现象为首次输入包含受灾点位的提问无法召回目标灾情速报，二次输入可正常召回。原因为首次检索时未触发扩展查询，或相似度阈值设置过高过滤了低分值但相关的历史会商纪要。
- 现象为手动上传的预警通知文档，数小时后在数据集索引列表中消失。原因为未配置定时增量同步任务，或数据集权限设置导致临时索引未持久化。
- 现象为检索结果包含非应急类的日常办公文档，如行政通知。原因为未通过`collectionIds`限定检索范围，混入了无关数据集的内容。

## 怎么确认配好了
- 上传一份测试用的灾情速报文档，发起包含具体受灾点位的提问，核对召回结果是否包含该文档。
- 调整`similarity`参数至区间边界，验证召回结果的数量是否随阈值变化符合预期。
- 开启`usingReRank`后，对比重排前后的结果顺序，确认高关联的会商纪要、预警通知等内容优先返回。
- 检查数据集绑定配置，确认仅指定的应急业务数据集被纳入检索范围。
