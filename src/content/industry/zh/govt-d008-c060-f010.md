# 仓储物流的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
仓储物流的业务办理流程引导数据主要来自内部仓储管理系统、运输调度日志、出入库电子单据、岗位操作手册。数据更新节奏分为实时与定期，出入库操作数据实时同步至知识库，调度计划、通用流程规范类数据每日更新。文档结构包含结构化字段与非结构化说明，结构化字段包括货位编码、SKU编号、出入库时间、流程节点ID，单位涵盖件、立方米、吨、小时等物流专用单位，非结构化部分为各节点的操作细则与异常处理说明。

## 这些特征在「知识库检索与召回」这一环带来什么约束
仓储物流的结构化字段多且单位多样，要求检索时支持按货位编码、SKU编号等字段精准过滤，避免返回不匹配的流程内容。实时更新的出入库数据需要增量索引机制，防止检索结果滞后于最新业务状态。流程文档长度差异大，短的操作提示仅几十字符，长的异常处理说明可达数千字符，需要适配不同长度的分块策略，确保召回内容完整覆盖业务节点。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 匹配仓储物流流程中专业术语的精准度，避免低相关的通用流程内容混入召回结果 |
| `limit` | 前8条 | 覆盖单个业务办理的全流程节点，同时控制上下文总长度，避免超出模型输入限制 |
| `searchMode` | hybrid | 结合关键词检索与语义检索，适配结构化字段与非结构化操作说明的混合检索需求 |
| `usingReRank` | 开启 | 对初始召回的结果按业务节点相关性重新排序，修正语义检索的无序返回问题 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展流程相关的同义词，比如将「入库」扩展为「商品入库」「物料进仓」，覆盖仓储物流的多称谓场景 |
| `collectionIds` | 按指定仓储区域绑定 | 限定检索范围仅包含对应业务区域的流程文档，避免跨区域的无关内容返回 |

## 容易做错的三处
- 现象：API调用返回的流程节点顺序混乱，在线聊天返回的顺序符合业务逻辑。原因：API调用未开启`usingReRank`配置，仅返回初始语义召回的无序结果，在线聊天默认启用重排功能。
- 现象：检索结果包含无关的SKU品类流程，未过滤指定货位。原因：未正确配置`collectionIds`或元数据过滤规则，未绑定对应仓储区域的数据集集合。
- 现象：检索结果遗漏最新的出入库流程调整内容。原因：未启用增量索引更新机制，知识库未同步最新的业务流程变更数据。

## 怎么确认配好了
- 发起API调用与在线聊天，对比返回的流程节点数量与顺序，确认重排功能已生效。
- 输入包含特定货位编码的查询，检查返回结果是否仅包含对应货位的流程内容，确认元数据过滤规则已加载。
- 提交最新更新的流程文档，等待索引同步后发起查询，确认返回内容包含最新的业务细则。
- 在FastGPT v4.17.0版本中，调整`similarity`参数值，观察检索结果的相关性变化，确认参数配置已成功加载。
