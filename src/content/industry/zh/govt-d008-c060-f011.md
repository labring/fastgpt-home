# 仓储物流的业务办理流程引导：表单与交互

## 这个品类的数据长什么样
仓储物流的业务办理数据主要来自仓储管理系统（WMS）、运输管理系统（TMS）以及现场作业终端。数据更新节奏随作业类型变化：出入库作业实时更新，月度盘点数据每日同步更新。标准数据文档包含货位编码、SKU编号、库存数量、承运商编号、批次号、体积重量等字段，单位涵盖件、箱、吨、立方米等，部分字段需匹配固定格式，如货位编码需符合“区域-巷道-货架-层位”的四段式规则。本内容基于FastGPT v4.17.0版本。

## 这些特征在「表单与交互」这一环带来什么约束
由于数据需匹配固定格式且更新实时性要求高，表单交互需强制校验字段格式，避免无效数据进入系统。批量业务办理场景多，表单需支持批量输入或导入，同时限制单次提交的数据量防止系统过载。部分字段如SKU编号、货位编码为业务核心标识，需设置为必填项并关联后端数据校验，防止遗漏关键信息。实时更新的数据要求表单提交后同步刷新关联数据，避免出现数据不一致的情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 表单输入节点 | `formInput`，开启图片/文件接收 | 适配仓储单据、称重照片等业务输入需求 |
| 表单校验规则 | 按字段类型匹配格式，如货位编码校验“区域-巷道-货架-层位”格式 | 匹配仓储数据的固定格式要求，减少无效提交 |
| 默认值绑定 | 绑定全局变量，取值区间为`1–1000 位` | 匹配仓储物流的固定作业仓库标识，减少重复输入 |
| 批量输入上限 | 前 500 条 | 适配单次业务办理的合理数据量，避免系统过载 |
| 输入超时阈值 | 30 秒 | 匹配实时作业的响应要求，防止长时间等待导致作业中断 |
| 单条输入字符上限 | 800–1200 字符 | 适配业务单据的常规内容长度，避免输入溢出 |

## 容易做错的三处
- 现象：表单提交base64格式的物流单据图片时返回“输入格式不支持”报错。原因：未在`formInput`节点中开启图片类型的输入接收配置。
- 现象：设置表单默认值为全局变量后，实际提交的字段为空。原因：未在FastGPT v4.17.0中开启全局变量与表单默认值的同步绑定开关。
- 现象：批量办理出入库业务时，单次提交超过100条数据后仅部分条目被处理。原因：未调整批量输入上限的配置参数，默认值限制了单次提交的数据量。

## 怎么确认配好了
- 填写测试用的货位编码，校验是否弹出格式错误提示，符合“区域-巷道-货架-层位”规则则校验通过。
- 配置默认值为全局变量后，刷新表单查看默认值是否正确加载为预设的仓库标识。
- 上传base64格式的测试单据图片，确认表单可以正常提交并无报错。
- 批量导入150条测试SKU数据，确认全部条目被系统接收处理。
