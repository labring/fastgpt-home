# 勘察设计的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
勘察设计的业务数据主要来源于项目全周期的勘察报告、现场踏勘记录、设计方案说明、业务流程审批单及配套图纸OCR文本。数据更新随项目节点触发，项目启动时上传初始文档，审批阶段按需修改，项目收尾后归档。文档包含结构化字段（如项目编号、勘察深度、审批时限）与非结构化文本段落，单文档长度跨度较大，短则数百字符的节点说明，长则数万字符的完整勘察报告。

## 这些特征在「向量模型与索引」这一环带来什么约束
勘察设计数据的混合结构要求索引同时支持语义召回与元数据过滤，以便精准定位对应项目的勘察点位或审批流程；文档更新随项目节点触发，需适配增量索引的按需构建逻辑，避免无效索引占用资源；部分图纸OCR识别的文本存在格式噪声，需在索引前做基础的换行与冗余符号清洗；单文档长度跨度大，需支持动态调整分块参数，适配不同长度的文本片段。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配勘察报告、审批说明的常见段落长度，避免单块内容过载 |
| 重叠长度 | 100–150 字符 | 保留跨分块的流程上下文关联，避免关键审批节点被截断 |
| 相似度阈值 | 0.72–0.85 | 按实测标定，过滤低相关的勘察点位或流程描述 |
| 单次搜索上限 | 前 8 条 | 匹配勘察设计项目的常见关联文档数量，避免超出上下文配额 |
| `maxToken` | 16000 | 适配大模型的标准上下文窗口，容纳多份召回的勘察与审批文档 |
| `defaultToken` | 2000 | 配置单轮问答的基础token配额，满足完整流程步骤的复述需求 |

## 容易做错的三处
- 现象：界面无法选择索引模型，弹窗提示参数异常。原因：未完成向量模型的前置绑定，或上传的勘察设计文档格式不符合索引解析要求，导致系统无法加载可用的索引模型。
- 现象：回答流程问题时未返回对应文本块的来源文档信息。原因：未在索引配置中开启元数据提取开关，未将文档名称、项目编号等字段纳入索引的元数据绑定范围。
- 现象：召回结果中出现大量跨项目的无关文档文本。原因：未配置项目编号作为元数据过滤条件，导致索引召回未限定当前业务场景的文档范围。

## 怎么确认配好了
- 上传一份单份勘察报告，发起针对该报告中指定勘察点位的查询，核对召回结果是否包含该报告的对应文本块。
- 查看索引配置界面的元数据列表，确认项目编号、文档名称等勘察设计专属字段已被勾选为过滤条件。
- 发起测试查询，核对返回结果的相似度分值是否落在配置的阈值区间内。
- 检查问答结果的溯源信息，确认是否显示对应文档的名称与段落位置。
