# 勘察设计的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
勘察设计业务的数据主要来源于项目前期踏勘记录、岩土勘察报告、各专业设计图纸、报审报批文件及现场变更单。数据更新随项目阶段推进，初设阶段完成后更新施工图设计数据，变更环节会同步更新对应节点的文件内容。单份文档结构包含项目编号、专业分类、报审节点、提交时限、审批状态等字段，图纸类文件以张为单位，报审文件以MB为单位，文本类文档以字符为单位。

## 这些特征在「工作流编排」这一环带来什么约束
勘察设计多专业并行推进的业务特征，要求工作流支持多分支节点并行配置，同时按专业分类设置变量判断规则。不同文件类型的体积差异大，从数KB的报审表单到数十MB的施工图图纸，要求文档解析节点配置适配不同文件的处理阈值。项目数据随阶段高频更新，要求工作流绑定全局参数实现实时读取。报审环节存在固定审批时限，要求工作流配置超时触发的异常分支，避免流程阻塞。

以下配置适用于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量绑定 | 绑定`variables`中的项目编号、审批状态、提交时限 | 勘察设计项目数据随阶段高频更新，需实时获取最新业务参数 |
| 判断器节点 | 按`variables`中的Boolean类型审批状态判断分支 | 适配勘察设计的审批开关逻辑，匹配业务流程的分支判断需求 |
| 文档解析节点 | 设置单文件处理上限为`1000 MB`，按文件类型启用对应解析规则 | 勘察设计文件包含数十MB的施工图图纸，需适配大体积文件处理 |
| 多模态节点 | 开启图片识别，设置识别超时为`60 秒` | 勘察设计图纸包含大量工程符号，需稳定的图片识别时长 |
| 工具调用节点 | 隐藏工具调用输出结果，配置`nodeId`关联结束节点 | 业务办理流程无需展示工具调用细节，仅需推送最终审批结果 |
| 异常分支配置 | 设置超时阈值为`8 小时`，触发文件上传异常分支 | 勘察设计报审文件上传易因网络或权限问题失败，需配置异常处理 |

## 容易做错的三处
- 现象：判断器节点无法正确识别`variables`中的Boolean类型审批状态，分支触发不符合预期。原因：未将Boolean变量配置为全局可读取参数，或判断条件未匹配布尔值的真假取值逻辑。
- 现象：多模态节点开启图片识别后，仍返回无法提供图片内容的提示。原因：未正确绑定上传文件的节点地址，或未在工作流中启用多模态模型的图片解析权限。
- 现象：工具调用完成后，调用结果仍展示在对话界面，配置工具调用结束节点未生效。原因：工具调用结束节点未正确关联`nodeId`至后续节点，或未关闭工具结果的自动输出开关。

## 怎么确认配好了
- 触发一次模拟的勘察设计报审流程，核对全局`variables`绑定的参数是否随流程节点实时更新。
- 上传一份测试用的工程图纸，确认多模态节点可正常识别图片内容并输出对应解析结果。
- 配置工具调用节点后，查看对话输出界面，确认工具调用的详细结果未被展示。
- 模拟文件上传超时的场景，确认异常分支可正常跳转至预设的异常处理节点。
