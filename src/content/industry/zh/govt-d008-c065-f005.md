# 勘察设计的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
勘察设计的数据主要来自项目全周期的勘察报告、施工图设计文件、项目管理台账。数据更新节奏跟随项目进度，初勘、详勘、施工图出图阶段分别触发更新。单份文档包含项目编号、勘察点位坐标、岩土力学参数（单位kPa、m）、设计荷载限值、图纸版本号、变更记录等结构化字段，部分图纸类文档需先转写为结构化文本后接入知识库。

## 这些特征在「工具调用与插件」这一环带来什么约束
勘察设计的数据特征会从三个维度约束工具调用与插件配置。其一，岩土参数含kPa、m等专业单位，工具调用时需内置单位校验逻辑，避免解析错误；其二，单份结构化文档或转写后的图纸文本较长，工具调用需限制单次返回的有效数据片段长度，防止上下文溢出；其三，项目数据随勘察、设计阶段动态更新，工具调用需关联项目台账的最新版本标识，避免调用过时的勘察或设计参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配勘察设计场景下多工具自动调度的需求 |
| `functionCall` | `[{"name":"query_geotechnical_param"},{"name":"query_design_load"}]` | 绑定勘察设计专属的岩土参数查询、设计荷载查询工具 |
| 单次工具调用返回长度 | 800–1200 字符 | 匹配勘察设计单份参数文档的典型有效片段长度 |
| 工具调用超时阈值 | 60 秒 | 覆盖跨项目台账检索的多数场景耗时 |
| 插件缓存有效期 | 7 天 | 匹配勘察设计项目的阶段更新周期 |

## 容易做错的三处
- 现象：工具调用返回的勘察数据片段过长，触发上下文溢出，重排模型未被触发。原因：未限制单次工具调用返回的文本长度，超出系统上下文上限。
- 现象：控制台报错“400 Messages with role 'tool' must be a response to a preceding message”。原因：工具调用的回复未紧跟对应用户提问，或工具调用顺序出现断层。
- 现象：无法调用地理空间插件获取勘察点位坐标。原因：未绑定对应插件的专属调用规则，或插件配置未关联勘察设计的点位数据字段。

## 怎么确认配好了
- 发起包含岩土参数查询的测试提问，查看工具调用日志中`toolChoice`的返回值是否为预设配置。
- 查看工具调用返回的文本长度，确认是否符合预设区间，可根据实际测试结果调整参数。
- 触发工具调用后，检查控制台是否出现指定的工具调用报错，无报错则配置符合要求。
- 验证地理空间插件的调用结果，确认返回的勘察点位坐标与项目台账中的数据一致。
