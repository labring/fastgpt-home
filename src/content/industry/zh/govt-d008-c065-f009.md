# 勘察设计的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
数据主要来自项目勘察报告、结构设计图纸、现场勘测日志、行政审批流程文档，随项目各阶段交付按需更新版本。文档按专业分为岩土、结构、给排水等子模块，包含项目编号、勘察点位坐标、设计参数值、审批节点状态、文件版本号等字段，单位涵盖米、兆帕、平方米、立方米等工程常用单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
专业字段与工程单位的存在，要求模型接入时配置适配工程术语的prompt，避免单位识别错误。多专业分模块的文档结构，要求配置时按专业划分上下文分组范围，避免跨专业数据干扰。按需更新的特性，要求配置自动同步数据源的触发逻辑，确保模型调用时使用最新版本的勘察设计数据。长文档的存在，要求调整模型上下文与token上限，避免超出模型处理阈值。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | `8000–12000 字符` | 勘察设计文档单模块长度多在数千字符，需覆盖完整专业上下文 |
| `maxTokens` | `4000–6000 token` | 工程文档与审批流程的token消耗较高，避免超出模型输出上限 |
| `quoteMaxToken` | `2000–3000 token` | 需保留足够的勘察设计原文引用片段，确保流程引导的准确性 |
| `toolChoice` | `auto` | 需自动触发工具调用以查询实时勘察数据或审批节点信息 |
| `temperature` | `0.2–0.4` | 业务办理流程引导需保持严谨，避免生成随意性内容 |
| `AIPROXY_API_ENDPOINT` | 私有部署模型的专属接口地址 | 勘察设计数据多为内部敏感数据，需使用私有代理保障安全 |

## 容易做错的三处
- 现象：前端通过iframe集成FastGPT聊天窗口后，无法获取模型返回的业务办理流程结果。原因：未配置iframe的postMessage监听逻辑，未正确绑定窗口间的消息传递事件。
- 现象：调用模型查询内部MongoDB存储的勘察数据时，平台显示的token消耗与实际API调用消耗不符。原因：未正确配置`quoteMaxToken`参数，平台统计的上下文token与模型实际处理的token存在偏差。
- 现象：使用私有部署的Qwen模型调用MCP的MySQL查询服务时返回错误，线上部署的同模型可正常调用。原因：私有部署模型的API端点未配置正确的访问权限，或代理密钥未绑定内部数据源的访问权限。

## 怎么确认配好了
- 发起一次针对特定勘察项目流程的查询，检查模型返回的结果是否包含当前项目的最新审批节点与对应办理要求。
- 查看平台运行日志，确认模型调用的token消耗与配置的`maxTokens`、`quoteMaxToken`参数匹配，无明显超出情况。
- 测试iframe集成的消息传递逻辑，确认前端页面可正常接收模型返回的流程引导内容。
- 切换至私有部署模型，验证MCP服务调用是否可正常返回勘察数据查询结果。
