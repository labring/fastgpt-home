# 勘察设计的业务办理流程引导：表单与交互

## 这个品类的数据长什么样
勘察设计的数据主要来源于项目勘察报告、施工图纸、报审报批文件及现场实测记录，更新节奏随项目阶段推进，初设、施工图等关键节点会同步更新。文档结构通常包含项目唯一标识、勘察点位坐标、结构荷载参数、材料规格等字段，字段单位多为米、kPa、平方米、立方米等专业工程单位，单份文档长度跨度较大，小型项目文档仅数百字符，大型项目图纸文件可达数百兆。

## 这些特征在「表单与交互」这一环带来什么约束
专业字段多且单位要求严格，要求表单需按专业模块拆分输入项，避免非专业人员输入非法格式；数据更新频繁且阶段化，要求表单支持实时校验输入内容的合法性，防止过期或不符合当前阶段的数据提交；单份文档体积差异大，要求交互环节支持大文件上传与分片处理，同时需适配不同长度文档的知识库召回逻辑；多维度的项目分类要求表单需提供精准的筛选选项，确保后续关联的知识库范围匹配当前业务场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 按专业字段分组，每组关联对应专业知识库 | 勘察设计数据按勘察、结构、机电等专业分类，分组后可提升知识库召回精准度，适配FastGPT v4.17.0的分组关联规则 |
| `userSelect` | 预设勘察阶段、项目类型选项，限制可选范围为3–8项 | 减少无效分类输入，避免调用全量知识库导致结果偏差，符合勘察设计项目的常规分类逻辑 |
| 自定义输入项 | 添加坐标格式、荷载值校验规则，单位限定为米、kPa | 匹配勘察设计专业字段的单位要求，防止非法输入导致后续流程异常 |
| 单次提交上限 | 1000 MB | 适配大型施工图文件的单批次提交需求，避免因文件体积过大导致提交失败 |
| 超时时间 | 600 秒 | 覆盖大文件上传、多知识库召回的处理周期，确保流程正常完成 |

## 容易做错的三处
- 现象为调用接口开启stream为true时，仅收到分段数据无法拼接完整结果，原因是未正确配置`formInput`的流式结果接收逻辑，未按事件流规则聚合返回内容。
- 现象为表单提交后知识库召回结果与项目类型不匹配，原因是未通过`userSelect`限定知识库范围，直接调用全局知识库导致非专业数据被召回。
- 现象为自定义输入项无法同步全局变量，原因是未在`formInput`配置中声明变量与表单字段的映射关系，导致变量赋值未生效。

## 怎么确认配好了
- 打开表单配置页面，核对每个专业字段的校验规则与预设单位是否匹配勘察设计数据的专业要求。
- 选择预设的项目类型与勘察阶段，触发知识库召回测试，检查返回内容是否与当前选择的业务场景一致。
- 测试stream模式下的接口调用，确认可以按事件流接收分段数据并聚合为完整结果。
- 填写表单字段并触发变量同步，检查全局变量是否随输入内容正常更新。
