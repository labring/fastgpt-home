# 勘察设计的业务办理流程引导：部署与升级

## 这个品类的数据长什么样
勘察设计的业务办理数据主要来自项目全周期的勘察报告、设计图纸元数据、流程审批表单与现场核验记录。数据更新随项目进度触发，项目启动时上传初始资料，审批环节修改校验内容，项目归档后冻结。单份文档包含项目编号、勘察点位坐标、设计参数、审批节点、经办人信息等字段，点位坐标采用十进制经纬度单位，设计参数以平方米、立方米为单位，审批节点标注工作日时长。

## 这些特征在「部署与升级」这一环带来什么约束
勘察设计数据包含多格式的文档与结构化表单，单项目数据体量较大且更新频率随审批环节波动。部署时需适配大文件存储与高频小数据读写的混合场景，升级过程需保证数据读写不中断，避免项目流程卡顿。由于数据包含经纬度、工程参数等专业字段，数据库迁移需严格保留字段格式与单位一致性，同时需兼容arm架构的运行环境，避免部署后出现兼容性报错。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `200–300 个连接` | 勘察设计项目数据读写频次高，需足够连接池应对并发请求，避免数据库连接耗尽 |
| `MONGODB_URI` | `mongodb://[用户名]:[密码]@[主机]:[端口]/fastgpt?authSource=admin` | 存储勘察设计的非结构化图纸、报告与结构化元数据，需独立数据库实例保障数据隔离 |
| `REDIS_URL` | `redis://:[密码]@[主机]:[端口]/0` | 缓存审批节点与点位坐标数据，降低数据库高频读写的压力 |
| `STORAGE_S3_ENDPOINT` | `按企业对象存储服务商提供的接入地址填写` | 适配勘察设计大体积图纸与报告的存储需求，支持断点续传 |
| `ROOT_KEY` | `随机生成的32位字符` | 保障系统后台访问权限安全，避免未授权操作修改业务流程配置 |
| `FE_DOMAIN` | `https://[企业内网域名]:8080` | 限定前端访问域名，适配国央企内网部署的安全要求 |

## 容易做错的三处
- 现象：执行版本升级后，系统提示数据库连接超时，业务办理流程无法触发。原因：未调整`DB_MAX_LINK`配置，升级后并发连接数超出原有设置，导致数据库请求被拒绝。
- 现象：部署在arm架构银河麒麟Linux系统上时，docker容器启动失败，日志提示镜像架构不兼容。原因：未使用适配arm架构的FastGPT镜像，默认amd64镜像无法在arm环境运行。
- 现象：迁移mongodb数据后，勘察点位坐标字段显示为空或格式异常。原因：迁移过程中未保留字段的十进制经纬度格式，导致数据解析异常，无法正常展示专业参数。

## 怎么确认配好了
- 登录系统后台管理页面，查看版本信息模块，确认显示FastGPT v4.17.0版本号。
- 上传一份勘察设计相关文档，等待存储任务完成后，验证文件可正常预览与下载。
- 发起一次模拟业务流程提交，检查审批节点配置是否正常加载，无字段解析异常提示。
- 连接配置的Redis实例，查看缓存列表，确认存在勘察设计项目的临时审批数据。
