# 化肥农药的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
化肥农药业务办理相关的原始数据，主要来自农资监管备案系统、企业生产台账、农药登记证数据库、化肥质量检测报告。数据更新节奏存在差异：农药登记证信息按年度审批更新，生产台账每日同步，质量检测报告随批次产出。单篇文档通常包含产品名称、登记证号、生产企业、适用作物、使用剂量、禁忌事项、审批状态等字段，使用剂量以克/亩、毫升/升为单位，部分文档附带数千字符的长文本使用指导说明。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据混合了结构化业务字段与非结构化专业文本，包含大量农业专属术语，会对向量嵌入的语义准确性提出更高要求。不同数据源的更新频率差异，需要配置差异化的索引同步规则，避免重复索引或遗漏更新内容。单篇文档的长度跨度较大，从几十字符的登记证信息到数千字符的使用指导，分块处理时需避免截断关键业务参数，同时保证语义上下文的完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配化肥农药文档的专业术语与长文本结构，避免截断关键业务参数 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的语义关联，防止专业术语被分块打断 |
| 相似度阈值 | 0.72–0.85 | 匹配农业专业语料的语义匹配精度，过滤无关检索结果 |
| 单次搜索上限 | 前 20 条 | 覆盖业务办理所需的多维度参考信息，避免结果过多干扰判断 |
| `defaultToken` | 8192 | 适配单篇文档的最大长度，保证专业文本的完整嵌入 |
| `maxToken` | 16384 | 匹配FastGPT的上下文上限，支持长文档的完整检索与调用 |

## 容易做错的三处
- 现象为PostgreSQL向量表查询结果仅显示vector字段，无关联的product_id、document_id等原始文档标识字段，原因是未在向量化流程中配置源文档ID与向量嵌入结果的绑定逻辑。
- 现象为使用bge-m3模型时，语义检索返回结果的相关性评分普遍高于0.9，远高于设定阈值，原因是未针对化肥农药专业语料调整向量模型的语义匹配权重，导致通用语义匹配逻辑失效。
- 现象为索引状态显示同步完成，但检索时无匹配结果，且o1模型无法触发搜索引擎模板的检索逻辑，原因是未配置源文档的更新同步触发条件，同时未适配o1模型的检索上下文格式要求。

## 怎么确认配好了
- 查看向量存储表的结构与数据，确认每条向量记录均关联product_id、document_id等原始文档标识字段，无孤立的向量条目。
- 提交测试检索词，如“小麦田复合肥使用规范”，核对返回结果的相关性评分处于设定的阈值区间内。
- 触发一次源文档的手动更新，确认FastGPT的索引队列能正常同步新提交的文档数据，无同步失败的日志记录。
- 在FastGPT v4.17.0环境中调用o1模型的检索模板，确认能正常返回关联的化肥农药业务文档，无报错信息。
