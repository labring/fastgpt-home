# 化肥农药的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
化肥农药品类的数据主要来源于农资监管公示平台、企业生产台账、农药登记数据库及化肥质量检测报告。数据文档多为结构化表格与规范文本，包含生产批号、有效成分含量、登记证号、适用作物、安全间隔期等字段。有效成分含量单位多为g/L或质量分数，使用剂量以亩施用量为单位。登记类数据更新周期为季度，生产台账数据随生产批次每日更新，检测报告数据随抽检批次实时更新。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的结构化字段多且单位不统一，要求模型接入时需配置适配结构化数据解析的参数，避免单位识别错误。数据更新频率差异大，登记类数据季度更新、生产台账每日更新，需在配置中调整上下文窗口的刷新规则，确保调用时使用最新的登记与生产数据。含图片类检测报告的场景，需开启对应多模态能力，支持图片内容的解析与整合。字段的唯一性要求（如登记证号），需限制模型生成内容的随意性，避免虚构字段信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `vision` | 开启 | 品类包含带图片的质量检测报告，需支持图像内容的识别与整合 |
| `temperature` | 0.1–0.3 | 需保证登记证号、有效成分含量等字段的准确性，避免虚构信息 |
| `maxContext` | 8000–12000 token | 需容纳多份农资登记信息与生产台账数据，避免上下文截断 |
| `quoteMaxToken` | 2000–3000 token | 需提取足够的结构化字段信息用于业务流程引导 |
| `toolChoice` | auto | 需根据业务场景自动选择是否调用工具解析结构化农资数据 |
| `AIPROXY_API_TOKEN` | 对应模型服务商发放的有效令牌 | 完成身份验证，实现合法的模型调用 |

## 容易做错的三处
- 现象：重启设备后，配置的模型渠道与令牌信息丢失，无法直接调用模型。原因：未将配置信息持久化存储，仅保存在本地临时缓存中。
- 现象：在arm架构系统中部署镜像后，模型无法正常加载，提示架构不兼容。原因：使用了仅支持amd架构的镜像文件，未适配arm架构的运行环境。
- 现象：上传含图片的pdf文档后，模型仅输出文本内容，未识别图片信息。原因：未开启`vision`配置项，未启用多模态图像识别能力。

## 怎么确认配好了
在FastGPT v4.17.0版本中执行以下核对动作：
- 调用模型测试解析结构化农资数据，核对有效成分含量、登记证号等字段的识别准确性，调整`temperature`参数至符合预期的严谨度。
- 上传含图片的检测报告pdf，验证模型是否能同时输出文本与图片描述内容，确认多模态配置是否生效。
- 重启部署环境后，检查模型渠道与令牌配置是否仍存在，确认配置已完成持久化。
- 调用包含多份农资数据的上下文，验证上下文窗口配置是否能完整容纳数据，无截断情况。
