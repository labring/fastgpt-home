# 化肥农药的业务办理流程引导：部署与升级

## 这个品类的数据长什么样
化肥农药业务办理流程引导的数据主要来自农资生产企业的生产台账、农业农村部农资备案数据库、地方政务服务平台的办理申请材料。数据更新节奏随企业生产周期与政策备案要求调整，单次办理提交的文档多为结构化业务表单与第三方合规检测报告，包含登记证编号、有效成分含量、生产批次、适用作物范围、安全使用剂量等字段，单位涉及克/升、千克、公顷、亩等农业生产常用计量标准。

## 这些特征在「部署与升级」这一环带来什么约束
化肥农药业务的结构化数据字段包含专业计量参数，部署阶段需确保系统能精准匹配表单字段与业务办理节点，避免流程引导偏差。数据更新随生产与备案节奏调整，部署时需预留可灵活配置的数据源对接逻辑，适配非固定周期的数据同步。单次办理涉及多页合规报告与附件，部署阶段需配置支持多文件批量解析的存储与索引规则。升级阶段需兼容不同批次的备案数据格式变更，避免中断正在办理的业务流程。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `STORAGE_S3_ENDPOINT` | 对应企业自建对象存储的内网访问地址 | 化肥农药备案文档多为合规附件，内网访问可提升解析速度与数据安全性 |
| `PG_URL` | 包含业务办理数据库的连接地址与认证参数 | 业务办理流程需关联历史申请数据，需稳定的PostgreSQL数据库连接 |
| `REDIS_URL` | 配置为本地部署的Redis服务地址，内存配额不低于2048 MB | 需缓存业务办理的会话数据与解析后的文档片段，保障流程引导的实时性 |
| `DB_MAX_LINK` | 300–500 | 化肥农药业务办理的并发量随农忙周期波动，合理的连接数可避免数据库连接耗尽 |
| `FILE_TOKEN_KEY` | 自定义32位随机字符串 | 需保障业务办理附件的上传与下载权限安全 |
| `ROOT_KEY` | 配置为仅内部运维人员知晓的密钥 | 需限制核心配置的修改权限，避免误操作影响业务流程 |

## 容易做错的三处
- 现象为使用VLLM部署Qwen3系列模型时，无法从PDF解析的业务办理文档中提取有效成分含量字段，使用Qwen2.5-14B则可正常提取。原因是Qwen3系列模型对专业农业计量字段的上下文关联逻辑与业务办理表单的结构化匹配规则未适配，需调整模型调用的关联配置。
- 现象为PG容器启动时提示“FATAL: role "postgres" does not exist”报错。原因是升级版本后未初始化PostgreSQL数据库的默认角色，需执行初始化脚本完成基础配置。
- 现象为连接VLLM部署的Qwen3-Embedding-8B模型时出现连接超时报错。原因是未配置正确的模型访问端口与内网安全组规则，导致FastGPT服务无法与本地部署的模型服务建立稳定连接。

## 怎么确认配好了
- 执行docker-compose ps命令，确认所有部署的容器状态均为Up。
- 上传一份化肥农药合规检测报告PDF，测试文档解析功能，确认能提取登记证号、有效成分含量等指定字段。
- 调用业务办理流程引导的测试接口，模拟用户提交申请，确认会话数据能正常写入Redis缓存。
- 修改核心配置项`ROOT_KEY`，确认未授权用户无法访问系统后台配置页面。
