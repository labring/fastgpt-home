# 医药流通的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
医药流通的业务数据来源包括药品采购入库单、出库流转记录、冷链运输日志、经营资质审批文档、医保结算凭证等。数据更新节奏差异明显：采购、出库等业务数据为实时或每日更新，经营资质文件按季度或年度更新。文档结构包含结构化字段与非结构化内容，结构化字段含药品通用名、规格、批号、流向单位、交易时间等，单位涉及盒、箱、摄氏度；非结构化内容为审批流程说明、运输异常报告、资质扫描件等长文本或图文混合内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源混合的结构化与非结构化数据，要求分块策略需区分字段类型，避免向量表征混淆业务属性与文本内容。高频更新的业务数据要求索引支持增量更新，适配实时流转的业务办理流程数据。长文档如年度流通总结、多批次运输记录会占用较多向量模型输入长度，需匹配分块参数与模型token限制。唯一标识字段如批号的存在，要求向量检索需结合精准匹配逻辑，避免无关结果干扰流程引导。图文混合的文档则要求向量模型支持多模态输入，适配资质扫描件等非文本数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配医药流通文档中既有短标识字段又有长流程文本的混合结构，避免单块信息过载 |
| 重叠长度 | 50–100 字符 | 覆盖跨块的流程步骤关联，避免业务办理流程的断点丢失 |
| 相似度阈值 | 0.72–0.85 | 匹配医药数据的字段唯一性要求，过滤低相关的非目标业务内容 |
| 单次搜索上限 | 前10条 | 适配业务办理引导的精准性需求，避免过多冗余结果干扰指引 |
| `defaultToken` | 8192 | 适配主流向量模型的输入长度限制，兼容多数医药业务文档的分块长度 |
| `maxToken` | 16384 | 支持年度流通总结类长文档的完整向量生成，避免截断关键审批信息 |
| 向量模型选择 | 阿里multimodal-embedding-v1 | 支持医药流通场景下的多模态文档（如资质扫描件、运输记录图片）的向量生成 |

## 容易做错的三处
- 现象：API调用时仅返回单条分块结果，无法获取分块索引的完整列表。原因：未开启FastGPT的分块索引存储开关，导致仅缓存单条向量化结果。
- 现象：向量化服务返回参数格式不匹配的报错。原因：误将分块数组作为单文本切片传入，未遵循FastGPT的单条文本向量化配置逻辑。
- 现象：检索结果中出现大量无关的非流通业务文档。原因：相似度阈值设置过低，未过滤低匹配度的无关数据。

## 怎么确认配好了
- 上传一份典型的医药采购流程文档，检查FastGPT v4.17.0的向量生成日志中是否生成了对应数量的分块索引。
- 调用检索接口，传入已知的药品批号关键词，核对返回结果是否包含对应分块的内容。
- 查看FastGPT的模型配置页面，确认`defaultToken`和`maxToken`的取值与所选阿里multimodal-embedding-v1模型的官方参数一致。
- 模拟业务办理查询，检查返回的流程步骤是否连贯，无断点或冗余内容。
