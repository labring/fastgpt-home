# 医药流通的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
数据主要来自医药流通企业的业务系统，包含采购订单、销售出库单、验收入库单、药品资质文件等。更新节奏随业务办理实时触发，每笔交易完成后同步更新。文档分为结构化表单与非结构化附件两类，结构化字段包含药品通用名、规格、生产厂家、批号、交易数量、单位（盒、支、片）、经办人员、交易时间等，非结构化附件多为药品质检报告、GSP合规文件，篇幅差异较大。

## 这些特征在「模型接入与配置」这一环带来什么约束
结构化表单与非结构化附件并存的文档结构，要求模型同时支持字段识别与长文本处理；实时更新的业务数据，要求模型检索与上下文加载的时效性匹配业务办理节奏；字段附带特定单位（盒、支、片），要求模型生成的引导内容需严格匹配单位规范；长篇幅的合规文件，容易超出模型上下文长度限制，引发异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配医药流通业务单据及附件的平均内容长度，避免截断核心审批与流程信息 |
| `maxTokens` | 2000–3000 token | 适配业务办理流程引导的回复长度，确保包含完整的步骤说明与合规注意事项 |
| `quoteMaxToken` | 1500 字符 | 对应医药流通业务文档的单条检索内容长度，避免超出模型上下文限制 |
| `temperature` | 0.3–0.5 | 保障流程引导的准确性，减少非标准业务步骤的生成 |
| `toolChoice` | auto | 允许模型根据业务场景自动选择是否调用工具处理单据校验与资质核对 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或云部署的模型服务地址，确保数据传输符合医药流通行业的合规要求 |

## 容易做错的三处
- 现象：共享页面发起60个以上并发请求时返回无应答，本地模型服务器CPU、内存使用率未达上限。原因：未针对医药流通业务的高频单据检索场景，调整`maxContext`参数以适配并发请求的上下文占用，导致资源耗尽。
- 现象：上传超过上下文长度的医药质检报告时，返回400错误。原因：未在工作流中加入文件内容预处理逻辑，直接上传的内容超出模型支持的上下文范围。
- 现象：模型无法读取上传的药品采购订单内容，且<FilesContent></FilesContent>标签内存在对应文档内容。原因：混淆了模型变量与模型服务配置的入口，未在FastGPT v4.17.0的对应模型服务页面完成参数设置。

## 怎么确认配好了
- 发起模拟的医药业务办理请求，核对回复内容是否包含对应业务的标准流程步骤与字段校验规则。
- 上传不同长度的医药业务文档，验证是否触发上下文截断或异常报错，调整参数至符合业务场景需求。
- 发起多并发请求，监控服务响应状态，确认无异常无应答情况。
- 查看模型运行日志，确认<FilesContent>标签内的文档内容被正确加载并用于生成回复。
- 在模型服务配置页面验证`maxTokens`、`temperature`等参数是否正确生效。
