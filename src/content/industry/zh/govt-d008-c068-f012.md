# 医药流通的业务办理流程引导：部署与升级

## 这个品类的数据长什么样
医药流通的业务办理数据主要来自企业内部进销存系统、药监部门备案平台、物流运单系统及经营资质文档。数据更新随业务批次触发，单次办理流程的单据更新频率为每批次1次，常规资质数据每30天同步一次。单份业务文档包含药品通用名、批准文号、流通批次号、办理节点状态、经手人ID等字段，单位涵盖件、箱、批次有效期（天）、经营资质编号等，部分文档为结构化表格格式，部分为扫描件转写的文本。

## 这些特征在「部署与升级」这一环带来什么约束
医药流通业务数据包含多源结构化与非结构化内容，且涉及经营资质、流通批次等敏感信息，因此部署环节需优先保障数据存储的隔离性。高频次的业务批次更新要求向量索引的增量同步机制适配短周期刷新，避免数据滞后影响流程引导准确性。同时不同格式的业务文档需适配专属解析规则，升级环节需兼容原有数据源的接口格式，避免中断业务办理流程。此外医药流通数据的合规性要求，需确保部署环境符合行业数据存储规范，因此配置环节需优先锁定本地存储或合规云存储选项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 本地部署专用实例连接串，配置读写分离节点 | 医药流通数据包含高频写入的业务单据与静态资质数据，读写分离可降低查询延迟 |
| `REDIS_URL` | 1000 MB 内存规格的本地缓存实例 | 用于缓存高频查询的药品资质与办理节点数据，避免重复调用外部系统 |
| `PG_URL` | 本地关系型数据库连接串，配置连接池上限为 20 | 存储结构化的业务办理流程节点数据，连接池适配多并发的窗口办理场景 |
| `STORAGE_S3_ENDPOINT` | 合规本地对象存储服务地址 | 适配医药流通数据的存储合规要求，保障敏感业务文档的本地存储权限 |
| `ROOT_KEY` | 随机生成的 32 位字符串，通过环境变量注入 | 用于管理系统的最高权限访问，避免硬编码带来的安全风险 |
| `FILE_TOKEN_KEY` | 与存储服务匹配的加密密钥 | 用于加密业务文档的访问令牌，防止未授权访问敏感单据 |

## 容易做错的三处
- 现象：启动后出现 `502 Bad Gateway` 报错，界面无法加载知识库列表。原因：未正确配置`REDIS_URL`，导致缓存服务无法连接，高频业务数据查询超时。
- 现象：迁移知识库到本地环境后，原有业务单据的解析结果为空。原因：未同步更新`STORAGE_S3_ENDPOINT`配置，导致无法读取原存储中的医药流通单据文件。
- 现象：运行升级脚本后，系统无法启动业务办理引导功能。原因：未通过环境变量注入`ROOT_KEY`，直接使用默认硬编码值，触发权限校验失败。

## 怎么确认配好了
- 执行环境变量打印命令，确认`ROOT_KEY`、`MONGODB_URI`等配置项已正确注入，本文档适用于FastGPT v4.17.0版本。
- 发起模拟业务单据上传请求，检查存储服务是否正常接收并返回合法的文件访问链接。
- 启动缓存服务健康检查脚本，确认`REDIS_URL`配置的缓存实例可正常读写数据。
- 运行升级脚本后，查看系统日志，确认无配置项缺失或权限校验失败的报错信息。
