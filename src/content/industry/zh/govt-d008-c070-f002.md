# 发电装备制造的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
发电装备制造的业务办理数据主要来自设备运维日志、生产工艺规程、备件申领表单、业务审批流程记录。数据来源包括现场工控系统、ERP系统、一线运维人员提交的电子文档。更新节奏分为实时（设备运行参数、故障告警）与周更（工艺优化文档、年度备件清单）。单份文档结构包含设备唯一编号、运维时间戳、故障现象、处置步骤、关联备件型号，字段单位涵盖小时、台、兆帕、件等。

## 这些特征在「向量模型与索引」这一环带来什么约束
发电装备制造的业务数据特征对向量模型与索引环节带来明确约束。实时设备告警与运维数据的高频写入，要求索引支持低延迟增量更新，避免数据同步滞后。文档内容跨度大，既有数十字符的故障描述，也有数千字符的工艺规程，需适配灵活的分块规则。多字段携带专属单位的特征，要求索引时保留字段元信息，避免跨字段语义混淆。业务办理流程的步骤存在前后关联，需确保索引能保留流程节点的上下文语义，避免拆分后丢失流程逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配工艺规程与故障描述的混合内容，避免单块过长或过短 |
| 重叠长度 | 100–200 字符 | 保留流程步骤的上下文关联，防止分块切断业务逻辑 |
| 相似度阈值 | 0.75–0.85 | 区分设备故障的相似描述与不同场景的流程步骤，减少误召回 |
| `defaultToken` | 4096 token | 适配长文本的工艺文档索引，满足单次索引的最大长度要求 |
| `maxToken` | 8192 token | 匹配业务办理流程引导的上下文窗口，确保召回内容可完整拼接 |
| 单次搜索上限 | 前 10 条 | 平衡召回效率与结果完整性，覆盖常见业务场景的关联数据 |

## 容易做错的三处
- 现象：知识库索引进度长时间停滞，界面显示「索引中」状态无更新。原因：接入外部大模型时未配置正确的向量模型调用超时参数，导致索引过程中嵌入生成请求超时未响应。
- 现象：搜索结果出现跨字段语义混淆，比如将备件型号与运维时间的描述错误关联。原因：未在索引环节保留字段元信息，导致向量嵌入未区分不同业务字段的语义边界。
- 现象：调用向量服务返回503错误，提示当前分组default下对于模型text-embedding不可用。原因：向量模型的分组配置未正确绑定业务数据的索引分组，导致请求路由失败。

## 怎么确认配好了
- 上传一份典型的发电装备运维文档，检查分块后的文本长度符合预设的分块区间，无明显截断或过短的块。
- 发起一次业务流程相关的检索，核对召回结果的相似度落在预设的阈值区间内，无过度或不足的召回。
- 查看向量数据库的写入日志，确认增量数据的更新频率符合实时业务数据的同步要求。
- 测试不同字段的检索请求，确认结果仅关联对应字段的内容，未出现跨字段混淆。
