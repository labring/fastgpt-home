# 发电装备制造的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
发电装备制造的业务数据主要来源于设备全生命周期运维档案、生产工艺规程、业务办理（备件申领、资质审批、设备报修）的电子单据及出厂检验报告。运维数据实时同步更新，流程单据按业务节点完成后更新，工艺文档每季度修订。文档多为结构化字段（如设备编号、额定功率、办理时限）与非结构化内容（故障描述、审批意见）的混合，字段单位包含千瓦、小时、台套等工业标准单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据的混合结构要求模型接入时需支持结构化字段识别与非结构化内容解析，避免流程引导出现格式偏差。业务流程节点固定且字段有明确单位，要求模型调用时需精准匹配预设字段，防止输出不符合工业业务规范的内容。部分运维与审批数据涉及生产敏感信息，要求优先适配国内合规模型，避免跨区域数据传输带来的合规风险。同时实时运维数据的高频更新，要求模型上下文配置需适配不同长度的业务文档。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配发电装备运维文档与流程台账的混合长度，避免截断关键业务节点 |
| `temperature` | 0.1–0.3 | 业务流程引导需保持输出一致性，降低随机生成的偏差 |
| `quoteMaxToken` | 1500 字符 | 匹配业务单据的单段内容长度，确保召回的流程说明完整无缺失 |
| `toolChoice` | auto | 自动匹配业务办理的多步骤逻辑，适配流程节点校验的需求 |
| `AIPROXY_API_ENDPOINT` | 按部署的国内模型网关地址填写 | 适配直连国内模型的场景，符合数据合规要求 |
| `AIPROXY_API_TOKEN` | 按网关颁发的有效令牌填写 | 确保模型调用的身份校验通过，避免无效令牌报错 |

## 容易做错的三处
- 现象：reranker模型启动时显存占用较低，调用后快速增长并稳定在6-7G，多GPU节点下每卡均出现占用。原因：未通过`maxContext`限制单请求的上下文长度，导致每次调用加载过多关联文档。
- 现象：添加国内模型后创建知识库与应用时不显示对应模型。原因：未正确填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或模型网关未完成同步更新。
- 现象：离线接入reranker模型时提示`rerank error`。原因：未匹配模型的输入格式要求，或模型文件路径配置错误。

## 怎么确认配好了
- 发起一次模拟业务办理流程的调用，检查返回结果是否包含准确的业务节点与对应字段信息。
- 查看FastGPT v4.17.0的模型调用日志，确认无无效令牌报错与连接超时记录。
- 测试reranker模型的调用，查看显存占用稳定在合理区间，无异常增长情况。
- 检查知识库的可用模型列表，确认已配置的国内模型正常显示。
