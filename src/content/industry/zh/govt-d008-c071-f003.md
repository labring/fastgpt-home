# 发电集团的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
发电集团的业务办理流程数据主要来源于内部业务手册、工单流转系统及电力监管部门公开规范。数据按并网申请、电费核算、检修报备等业务大类拆分，每个文档包含业务名称、办理流程节点、所需资质文件、法定办理时限、咨询渠道等内容。字段包含唯一业务ID、环节序号、材料份数、办理时限（工作日）等，更新频率为每季度同步一次，适配业务规范的定期调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
业务数据按大类拆分且包含多环节步骤，导致多轮对话需按流程节点顺序推进，不能直接返回全流程信息，避免用户混淆环节顺序。数据更新频率为季度级，提示词模板需每季度同步更新以匹配最新业务规范。字段中的法定办理时限（工作日）要求对话返回的时限必须严格匹配文档数值，不能随意调整。业务文档中每个环节对应专属材料清单，提示词需根据当前对话环节动态提取对应材料，避免冗余信息干扰用户判断。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本的逻辑制定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–10000 字符 | 发电集团单篇业务文档长度多在5000字符以内，该范围可完整覆盖多轮对话的历史交互与当前业务信息 |
| 问题优化开关 | 开启 | 发电集团业务术语专业性强，优化可将用户口语化提问转换为规范业务表述，提升匹配准确性 |
| 单次返回内容上限 | 前3条环节信息 | 业务办理流程分多节点，单次返回过多会导致信息冗余，优先展示当前环节核心内容 |
| 变量填充规则 | 使用`variables`参数绑定业务专属字段 | 可动态插入业务ID、办理时限等专属数据，避免硬编码内容随业务更新而过时 |
| `chatId`绑定规则 | 绑定用户业务申请编号 | 发电集团业务办理需关联唯一业务ID，避免不同申请的对话上下文混淆 |
| 超时阈值 | 600 秒 | 业务咨询可能涉及多环节查询，预留足够时间完成完整交互 |

## 容易做错的三处
- 现象：调用对话API使用流式输出后，点击返回内容中的链接仅覆盖当前页面无法跳转。原因：未配置对话链接的跳转触发规则，默认流式输出的内容链接未绑定新窗口打开逻辑。
- 现象：对话日志详情内容与实际回答内容不一致，多次对话后仍显示固定内容。原因：未正确处理`messages`参数的上下文更新，每次请求未携带最新的历史对话片段，导致模型复用旧的回答缓存。
- 现象：多轮对话中跳过业务办理环节直接返回最终结果。原因：提示词未明确要求按文档中的流程节点顺序引导，未限制对话必须按环节递进推进。

## 怎么确认配好了
- 发起包含业务环节细节的多轮对话，核对返回的办理时限是否与内部业务文档一致。
- 调用API并携带`chatId`参数发起两次不同的业务咨询，确认两次对话的上下文不会互相干扰。
- 开启流式输出测试，点击返回内容中的链接，确认跳转行为符合预期。
- 查看对话日志，确认每次交互的`messages`参数都包含最新的历史对话内容。
