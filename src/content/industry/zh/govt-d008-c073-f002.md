# 国有产业基金的业务办理流程引导：向量模型与索引

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
国有产业基金的业务办理数据主要来源于官方发布的基金申报指南、审批流程细则、材料提交规范等官方文档，更新随政策调整或业务流程优化同步进行，无固定周期。单篇文档多为结构化内容，包含业务节点名称、办理时限、提交材料清单、责任部门等字段，办理时限以工作日为单位，材料提交要求以份数、格式为具体单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化的业务文档包含多个明确字段，向量分块时需保留字段关联关系，避免拆分后丢失业务逻辑关联。无固定周期的更新要求索引支持按需增量同步，避免全量重建带来的资源消耗。多字段的业务属性要求索引需支持按字段维度过滤检索，确保返回结果匹配业务节点或材料要求。办理时限等带单位的业务内容，需确保向量模型能准确捕捉单位与数值的语义绑定关系。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配国有产业基金业务文档的单节点内容长度，避免拆分破坏字段完整性 |
| 重叠长度 | 50–100 字符 | 保留相邻业务节点的上下文关联，防止分块后流程逻辑断裂 |
| `maxToken` | 4096 token | 匹配bge-m3向量模型的输入上限，适配业务文档分块后的内容长度 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 过滤低匹配度的非业务相关结果，确保检索结果贴合流程节点 |
| 单次搜索上限 | 前10条 | 控制返回结果数量，避免业务办理引导信息过载 |
| `defaultToken` | 2048 token | 配置基础检索上下文的默认长度，适配常见业务问题的语义范围 |

## 容易做错的三处
- 现象：新增embedding模型后执行检索测试返回500状态码或“模型加载失败”报错。原因：未将国有产业基金的业务文档格式适配新模型的输入要求，或模型配置未绑定正确的文档数据源路径。
- 现象：查看pg向量库仅存储向量数据，无法通过原始文档内容关联检索。原因：分块时未保留原始文档的关联ID字段，仅将文本内容转为向量存入库中，丢失了原始数据的映射关系。
- 现象：使用bge-m3向量模型时，语义检索返回的相似度分值普遍偏高，结果冗余且匹配度不符合业务预期。原因：未针对国有产业基金的结构化字段配置字段过滤，导致非业务相关的相似内容被误判为高匹配结果。

## 怎么确认配好了
- 执行单条业务节点的检索测试，核对返回结果的业务字段与原始文档内容一致。
- 执行增量更新测试，确认仅新增或修改的业务文档被同步至索引库。
- 调整相似度阈值，验证返回结果的数量与匹配精度符合业务引导的实际需求。
- 查看向量库存储记录，确认每条向量数据关联有原始文档的ID与对应字段信息。
