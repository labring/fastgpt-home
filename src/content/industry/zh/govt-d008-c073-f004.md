# 国有产业基金的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
这个品类的数据主要来自国有资产监督管理平台备案库、基金管理人项目管理系统、投后运营台账与地方财政拨付凭证。备案类数据每月更新，投后运营数据每日同步，项目申报数据随提交实时更新。单条数据包含项目主体名称、基金认缴规模、实缴金额、申报材料状态、当前审批节点、提交时间等字段，其中认缴规模与实缴金额单位为亿元，申报材料状态为固定枚举值，当前审批节点为对应流程的具体环节名称。

## 这些特征在「工作流编排」这一环带来什么约束
基于FastGPT v4.17.0版本的工作流编排功能，上述特征带来以下约束：数据来源分散且更新节奏差异较大，要求工作流编排中配置多数据源对接节点，完成不同系统字段的统一映射。备案类数据的月度更新节奏，需要设置每月触发的定时同步节点，确保存量数据定期刷新。项目申报数据的实时提交特性，要求配置触发式工作流节点，在新申报数据提交时自动启动流程。枚举型的申报材料状态字段，需要添加条件分支节点，根据不同状态跳转对应处理路径。动态的当前审批节点信息，需要绑定`variables`变量，实时拉取最新节点内容并传递至后续环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按新申报数据提交事件触发，备案数据同步设置为每月1日00:00触发 | 匹配项目申报实时性与备案数据月度更新的节奏 |
| 条件分支节点 | 设置3个分支，对应待审核、已驳回、已通过状态 | 适配枚举型申报材料状态的流程跳转 |
| `variables`绑定 | 将当前审批节点字段绑定至会话变量 | 实时传递动态节点信息至后续环节 |
| 文件传输节点 | 启用二进制流传输模式，单次传输上限设为1000 MB | 适配TXT格式申报材料的传递需求 |
| `nodeId`配置 | 为每个审批节点分配唯一固定ID | 便于流程追踪与日志关联 |

## 容易做错的三处
- 工作流中调用API时未正确绑定`variables`变量，导致实际业务参数未传递至后端，接口返回参数缺失报错。原因：未将业务字段映射至会话变量，直接使用静态参数调用接口。
- 配置文件传输节点时未启用二进制流模式，导致TXT格式申报材料传输失败，返回400状态码。原因：默认文本传输模式无法处理二进制格式的文件流。
- 未区分不同数据源的更新节奏，将备案数据与申报数据设置为相同触发频率，导致存量数据更新不及时或重复触发流程。原因：未匹配数据本身的更新特性，统一配置触发规则。

## 怎么确认配好了
- 触发一次新的项目申报数据提交，检查工作流是否自动启动并完成节点跳转。
- 查看日志收集面板，确认`variables`变量已正确绑定当前审批节点信息，无空值报错。
- 调用测试接口，上传TXT格式申报材料，检查后端是否能正常接收并返回对应处理结果。
- 触发月度定时同步任务，检查备案数据是否完成更新并同步至工作流节点。
