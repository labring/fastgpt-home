# 国有资产管理公司的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
国有资产管理公司的业务办理相关数据主要来源于内部业务流程手册、资产登记台账、国资监管审批模板、跨部门协作通知单。数据更新随国资监管政策或内部流程优化而定，通常每季度或半年度更新一次。文档以结构化节点为主，包含资产编号、审批层级、办理时限（单位为工作日）、提交材料清单、责任主体等字段，单篇文档长度多在2000–5000字符。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 国有资产管理公司的业务流程单段核心描述多在500–1000字符，避免拆分破坏审批节点完整性 |
| 重叠长度 | 100–150 字符 | 保留相邻流程节点的上下文关联，避免跨块的步骤衔接丢失 |
| 相似度阈值 | 0.72–0.80 | 业务流程关键词辨识度较高，阈值过低易匹配无关流程，过高则召回不足 |
| 单次搜索上限 | 前 6 条 | 国有资产管理公司的业务办理流程通常包含3–5个核心节点，召回过多会导致上下文冗余 |
| `maxToken` | 8000 字符 | 匹配后的上下文拼接需容纳完整审批流程与表单要求，避免截断关键信息 |
| `defaultToken` | 按实测标定 | 不同内网部署环境的token处理上限存在差异，需结合硬件资源调整 |

## 容易做错的三处
- 现象为Docker部署后集成索引模型时出现连接超时错误，原因是内网环境未配置镜像加速或端口映射错误，导致模型拉取或调用失败。
- 现象为导出的dataset.csv仅包含index字段无content字段，原因是导入知识库时未勾选“保留原始文本内容”选项，或分块配置时未关联源文档的文本字段。
- 现象为使用bge-large模型时文本导入后无匹配结果，原因是未调整分块长度适配长流程文档，导致关键步骤被拆分后向量匹配失效。

## 怎么确认配好了
- 上传一份标准的业务流程文档，查看分块预览界面是否保留了完整的审批节点，无跨块截断的关键步骤。
- 执行一次流程引导测试，查看召回的结果是否关联了正确的资产编号、办理时限等结构化字段。
- 导出知识库的dataset.csv文件，确认文件同时包含index和content字段，内容与源文档一致。
- 查看硬件资源监控，确认向量模型调用时GPU或CPU资源占用符合预期，无异常峰值。
