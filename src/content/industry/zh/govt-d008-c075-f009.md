# 国有资本投资公司的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
数据主要来源于国资监管报送系统、内部业务审批台账、投资项目档案库及财务核算模块。更新节奏随单条业务办理进度实时同步，月度汇总更新全量业务台账。单份业务办理文档包含项目唯一标识、审批环节序列、申请材料清单、法定办理时限、责任主体部门等字段，字段以文本、枚举值、数字单位为主，无嵌套复杂层级结构。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配单份业务办理文档的全量上下文长度，避免截断审批环节与责任主体信息 |
| `maxTokens` | 2000–3000 token | 覆盖业务流程引导的完整回复内容，确保包含所有办理步骤与材料要求 |
| `temperature` | 0.2–0.4 | 适配标准化业务字段的输出需求，降低随机偏差，保证流程指引的准确性 |
| `toolChoice` | auto | 允许模型按需调用工具获取实时业务数据，适配多源接入的业务办理场景 |
| `vision` | false | 业务办理文档以文本字段为主，无需启用视觉理解能力，减少计算资源占用 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接入地址 | 适配国有资本投资公司内部网络隔离的部署要求，保障数据传输安全 |
| `AIPROXY_API_TOKEN` | 绑定专属权限的加密令牌 | 限制接口调用权限，避免非授权访问内部业务数据 |

## 容易做错的三处
- 现象：多模型编排的业务流程引导工作流中，不同会话的业务数据出现混淆。原因：未为每个会话配置独立的上下文隔离，未正确设置`maxContext`的会话级限制。
- 现象：通过外部渠道链接访问流程引导功能时，返回“undefined is not valid json”报错。原因：未正确绑定`AIPROXY_API_TOKEN`的专属权限，导致接口返回格式不符合预期。
- 现象：业务办理文档中的附件图片无法被模型识别并纳入引导内容。原因：误关闭`vision`配置项，或未配置适配业务图片格式的视觉模型接入参数。

## 怎么确认配好了
- 发起单条业务办理流程的测试调用，检查回复内容是否包含完整的审批环节与材料清单，核对上下文配置是否覆盖测试文档的实际信息长度。
- 调用多模型编排的工作流，验证不同业务会话的上下文不会互相干扰，确认会话级上下文隔离配置生效。
- 访问外部渠道链接，检查接口返回格式是否符合业务数据的标准结构，确认接口令牌的权限配置正确。
- 上传包含图片的业务文档，验证模型是否能正确识别图片内容并纳入流程引导，确认视觉配置项的设置符合业务需求。
