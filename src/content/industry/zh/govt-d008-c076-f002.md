# 国有资本运营公司的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
国有资本运营公司的业务办理相关数据，主要来源于国资监管部门备案文件、内部审批手册、交易申报材料及年度运营报告。数据更新分为月度更新的业务细则、季度更新的监管要求、年度更新的运营总结。文档结构包含审批节点序号、责任部门、材料清单、审批时限等固定字段，单位采用工作日、份、序号。文档以长文本段落为主，单篇包含连续的业务办理步骤说明，长度多在数千字符范围。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于数据包含固定审批节点、责任部门等结构化字段，向量索引需保留字段关联关系，避免分块操作破坏字段完整性。由于更新节奏有月度、季度周期，需支持增量索引同步机制，避免全量重建耗时过长。由于文档多为连续的业务步骤长文本，需限制单块分块长度，防止拆分跨审批节点的内容。由于涉及国资监管相关文档，需选择适配政务合规文本的向量模型，保证语义匹配的准确性。

## 配置怎么定
本文基于FastGPT v4.17.0版本的向量索引配置逻辑编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配业务流程文档的单节点文本长度，避免拆分跨审批步骤 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的语义关联，防止流程节点被割裂 |
| 相似度阈值 | 0.72–0.85 | 匹配国资业务文本的语义相似度分布，过滤低相关的流程规则 |
| 单次召回上限 | 前 10 条 | 控制返回的流程节点数量，避免上下文过载 |
| `maxToken` | 4096 token | 适配主流向量模型的输入长度限制，保证长流程文本的向量化完整性 |
| `defaultToken` | 按实测标定 | 适配本品类文档的特殊字段编码需求，避免字段信息丢失 |

## 容易做错的三处
- 现象：建索引任务卡在最后一组文件的处理步骤，界面显示「索引同步超时」。原因：未配置增量索引同步，全量同步国资年度运营报告等大体积文档时超出`defaultToken`设置的处理上限。
- 现象：知识库创建任务卡在索引构建环节，长时间无进度更新。原因：分块长度设置超出业务文档的单节点长度，导致分块操作耗时过长且无法完成向量化。
- 现象：更换自定义embedding模型后，索引创建成功但搜索测试返回「语义匹配失败」报错。原因：未调整`maxToken`参数适配新模型的输入长度限制，导致长流程文档的向量化截断不完整。

## 怎么确认配好了
- 查看索引创建日志，确认每个分块的长度均落在预设的800–1200字符区间内。
- 触发增量索引同步任务，验证仅更新后的业务流程文件被纳入新索引，未触发全量重建。
- 提交测试问题，核对返回的流程节点与业务文档的审批步骤完全匹配。
- 更换自定义embedding模型后，验证`maxToken`参数已同步调整为适配新模型的取值。
