# 国有资本运营公司的业务办理流程引导：多轮对话与提示词
本文基于FastGPT v4.17.0版本配置说明。

## 这个品类的数据长什么样
国有资本运营公司的业务数据主要来源于国资监管报送系统、内部业务审批台账、产权登记档案及投融资项目文档。数据更新节奏依模块区分：产权划转、投融资项目类数据随流程节点实时更新，薪酬核算、考核评价类数据按月度或季度更新。单份业务文档按审批环节拆分，包含业务编号、责任主体、审批时限、所需材料清单等字段，单位统一采用工作日、万元、编制数等国资系统标准单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
业务数据按审批模块拆分且字段标准化的特征，要求多轮对话的提示词需按业务场景做细分配置，避免跨模块混淆。实时更新的业务数据，要求对话上下文需同步关联最新的流程节点状态，无法依赖静态缓存数据。单文档包含多字段的情况，提示词需明确指定需提取的字段名称，防止大模型遗漏关键信息。业务编号作为核心标识，需在多轮对话中通过`chatId`绑定会话标识，`messages`字段完整保留每一轮对话内容以维持上下文连贯性，`variables`可用于传递动态业务参数如项目编号，确保跨环节的流程追溯准确。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配业务文档的段落长度，避免拆分后破坏审批流程的上下文逻辑 |
| 单次召回条数 | 前 3 条 | 国有资本运营业务文档字段较多，过多召回会超出上下文承载能力，3条可覆盖核心审批节点信息 |
| 上下文窗口 | 4000 token | 适配多轮业务对话的上下文长度，满足跨环节的流程追溯需求 |
| 流式输出开关 | 开启 | 提升长业务流程引导的交互体验，让用户实时获取步骤提示 |
| 上下文记忆时长 | 3600 秒 | 匹配国资业务办理的平均耗时，确保对话期间保留完整流程上下文 |
| 字段过滤配置 | 仅保留业务编号、审批节点、材料清单 | 过滤冗余字段，避免大模型被非必要信息干扰 |

## 容易做错的三处
- 无法启用流式输出：现象为对话界面无流式打字效果，内容一次性加载完成，原因是未在对话配置中开启流式输出开关，或当前使用的大模型接口未支持流式传输。
- 调整引用上限后无匹配引用：现象为将单次召回条数调至2000后，大模型输出未引用任何召回内容，原因是业务文档的字段标识与提示词要求不匹配，大模型无法识别有效引用片段，或召回的文档与当前对话问题的相关性过低。
- 知识库段落ID随结果返回：现象为检索结果中包含业务编号、人才编号等段落ID字段，原因是未配置字段过滤规则，未在提示词中明确要求排除非业务必要的标识字段。

## 怎么确认配好了
- 发起单轮业务咨询，检查对话界面是否出现流式打字效果，确认流式输出配置生效。
- 调整单次召回条数至不同区间，发起跨环节业务咨询，检查大模型输出引用的召回文档片段数量是否符合配置要求，确认引用配置匹配业务需求。
- 上传一份包含业务编号、审批节点的测试文档，发起相关咨询，检查输出结果是否未包含非必要的段落ID字段，确认字段过滤配置生效。
- 发起两次间隔一定时长的同流程对话，检查对话上下文是否保留之前的业务信息，确认上下文记忆时长配置符合业务办理的平均耗时。
