# 国有资本运营公司的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
国有资本运营公司的业务办理相关数据，来源包括内部业务流程手册、国资监管部门下发的合规指引、产权交易操作规范、内部审批节点说明、员工操作指引。更新节奏为核心流程文档每年按需调整，监管政策类文档随监管要求即时更新。文档结构多分为流程步骤、所需材料、审批权限、办理时限、责任部门，字段包含流程名称、节点编号、办理主体、所需材料清单、办理时限（单位为工作日）、咨询渠道，兼具结构化操作指引与非结构化政策解读。

## 这些特征在「知识库检索与召回」这一环带来什么约束
业务办理流程的合规性要求高，检索结果必须精准匹配具体节点的操作要求，不能出现偏差。监管政策类数据更新无固定周期，需要支持增量同步与临时更新机制。文档兼具结构化节点信息与非结构化政策解读，需要兼顾语义召回与关键词匹配能力。不同业务线的办理主体、时限要求差异明显，检索需支持按业务类型定向召回相关文档。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配业务流程的精准性要求，过滤无关的政策解读内容，确保返回结果与查询高度相关 |
| `limit` | 前10条 | 覆盖完整业务流程的所有节点，同时控制上下文长度，避免响应耗时过长 |
| `searchMode` | hybrid | 兼顾结构化的节点字段与非结构化的政策解读，适配混合格式的文档数据 |
| `usingReRank` | 开启 | 对召回结果按业务相关性重排，确保核心流程步骤优先展示，提升用户查找效率 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 业务办理引导需严格匹配原始文档内容，避免模型生成非必要的额外补充信息 |
| `collectionIds` | 按业务分类绑定 | 定向召回对应业务线的知识库文档，避免跨业务的无关内容干扰检索结果 |

## 容易做错的三处
- 现象：知识库检索响应超时，界面显示504状态码。原因：未针对业务文档量配置合理的`limit`参数，召回过多条目导致处理耗时过长。
- 现象：检索结果仅返回1条内容，无法覆盖完整业务流程。原因：错误设置`similarity`阈值过高，过滤掉了相关的步骤节点文档，同时未开启`searchMode`的混合检索模式。
- 现象：检索结果包含模型生成的额外补充内容，不符合业务办理的合规要求。原因：开启了`datasetSearchUsingExtensionQuery`参数，导致系统对检索结果进行了非必要的扩展。

## 怎么确认配好了
- 上传一份国有资本运营公司的业务流程文档，发起对应节点的查询，核对返回结果的`similarity`得分是否在0.75–0.85区间内。
- 发起包含多个流程节点的查询，核对返回结果的条数是否符合`limit`参数的设置。
- 检查检索结果是否仅包含原始文档内容，无额外生成的补充信息，确认`datasetSearchUsingExtensionQuery`参数已关闭。
- 测试不同业务类型的查询，核对是否仅召回对应业务分类的知识库文档，确认`collectionIds`已正确绑定。
