# 城市公交的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
城市公交的业务办理相关数据主要来自公交集团运营管理系统、线路台账库与实时客流监测平台。数据分为结构化与非结构化两类：结构化数据包含线路编号、站点名称、办理材料清单、办理时限、线下窗口地址等字段，单位为公里、分钟、人次；非结构化数据包含站点导览图、办理流程示意图、公告通知等。线路基础信息按季度更新，实时客流与办理排队数据按分钟级更新，线下办理流程的文档格式固定，无复杂嵌套结构。

## 这些特征在「模型接入与配置」这一环带来什么约束
公交业务办理的结构化数据字段固定且更新节奏差异大，需要为不同更新频率的数据源配置适配的召回与上下文长度参数。非结构化的视觉素材需要视觉模型支持，因此需开启`vision`配置项。办理流程的文档无复杂嵌套，适合使用固定长度的上下文窗口，但需避免截断关键的步骤说明与材料清单。实时客流数据的分钟级更新要求模型调用接口具备较低的延迟，因此需合理设置`maxTokens`限制回复长度，避免过长的生成内容占用过多接口资源。同时，部分城市公交的办理指引需严格遵循官方规则，因此模型的生成随机性需控制在合理区间。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配公交办理流程的多步骤文档与多条线路信息，避免截断关键的办理规则与材料说明 |
| `maxTokens` | 1200–1800 token | 控制单条办理指引的生成长度，确保信息完整同时避免占用过多接口资源 |
| `quoteMaxToken` | 1800–2200 字符 | 召回公交线路、站点的结构化数据时，保留完整的字段内容，避免关键信息被截断 |
| `vision` | 开启 | 用于解析公交站点导览图、办理流程示意图等非结构化视觉素材，补充文本信息的直观说明 |
| `temperature` | 0.3–0.5 | 保持办理指引的准确性，避免生成不符合公交运营规则的内容 |
| `AIPROXY_API_ENDPOINT` | 按服务商提供的专属地址填写 | 接入指定的向量或视觉模型接口，确保数据传输路径正确 |
| `AIPROXY_API_TOKEN` | 填写平台分配的鉴权密钥 | 完成模型接口调用的身份验证，保障请求合法性 |

## 容易做错的三处
- 调用Qwen2.5-vl处理公交站点导览图时，返回“无法下载图片”的报错。原因是未配置marker服务用于解析远程图片资源，导致模型无法拉取传入的图片链接。
- 智能体开启语音输入功能后，语音对话无文字转化结果。原因是未正确配置语音模型的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或未开启语音转文字的功能开关。
- 向量模型召回的公交线路信息与实际不符，匹配度偏低。原因是未开启向量模型的归一化配置，导致未归一化的嵌入向量（如Doubao的embedding）与系统默认配置不兼容。

## 怎么确认配好了
- 上传公交办理流程的结构化文档与站点导览图，发起测试对话，检查是否能正确召回线路信息并解析图片内容。
- 查看FastGPT v4.17.0的模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的鉴权请求返回正常状态码。
- 调整`temperature`参数后发起多轮测试，检查回复的一致性是否符合公交业务的官方规则。
- 开启向量模型归一化配置，对比调整前后的召回结果匹配度，确认配置生效。
