# 城市水务的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
城市水务的业务办理数据主要来自水务运营管理系统、线下办理台账与线上用户申报端口。数据分为实时工单数据（报修、报装、过户）、月度账单数据与管网关联业务数据三类，文档以结构化表单为主，包含业务类型、办理节点、所需材料清单、办理时限、申请用户信息等字段，办理时限单位为工作日，材料清单字段以逗号分隔的物品名称列表形式存储，数据更新频率从实时（报修、报装工单）到月度（用水账单）不等。

## 这些特征在「模型接入与配置」这一环带来什么约束
城市水务业务数据的多类型、分时段更新特征，对模型接入配置带来多重约束。实时工单类业务要求模型调用具备低延迟特性，需限定单次请求的超时时长；结构化表单的多字段属性，要求模型上下文窗口需适配包含多节点流程的长文本输入；不同业务场景（报装、缴费、报修）对应差异化的模型调用需求，需支持多API密钥分组管理；月度账单的批量数据处理，需限制模型生成的最大token数量，避免超出API调用限额。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配包含多节点办理流程、用户历史申请信息的长文本输入，覆盖水务业务全流程的上下文需求 |
| `maxTokens` | 1500–2000 token | 限制单次模型生成的回复长度，适配业务办理步骤的简洁引导输出，避免超出API调用限额 |
| `temperature` | 0.2–0.4 | 降低生成内容的随机性，确保业务办理步骤的表述准确统一，符合水务流程的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 对应部署的模型网关地址 | 适配多密钥分组管理的需求，支持将不同业务场景的调用指向对应密钥的网关节点 |
| `quoteMaxToken` | 600–800 token | 限定引用的水务业务文档片段长度，确保模型仅使用有效范围内的流程规则数据 |
| `toolChoice` | auto | 允许模型自动选择是否调用工具，适配不同业务场景下的流程查询需求 |

## 容易做错的三处
- 配置多API密钥时出现调用失败，界面提示密钥无效。原因是未按业务场景分组配置密钥，仅在docker-compose.yml中添加单组密钥变量，未实现批量密钥的动态调用逻辑。
- 测试模型调用返回404状态码。原因是`AIPROXY_API_ENDPOINT`配置的网关地址未正确指向部署的模型服务节点，或版本升级后未同步更新网关配置路径。
- 配置Ollama渠道后测试报错，返回字段缺失提示。原因是未在页面配置中补充Ollama的本地部署地址参数，仅依赖旧版config文件的配置项，导致调用链路断裂。

## 怎么确认配好了
- 进入FastGPT的模型管理页面，查看已配置的API密钥分组，确认每个分组对应正确的业务场景。
- 发起单条业务办理流程的测试调用，查看返回结果的上下文是否包含完整的办理节点信息，无截断或缺失。
- 调用日志中查看单次请求的token消耗，确认未超出`maxTokens`与`maxContext`的配置阈值。
- 测试多密钥分组的切换调用，确认不同业务场景下调用的密钥与网关地址匹配正确。
