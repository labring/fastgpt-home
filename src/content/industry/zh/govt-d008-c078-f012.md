# 城市水务的业务办理流程引导：部署与升级

## 这个品类的数据长什么样
城市水务的业务办理相关数据主要来自水务公司内部业务系统、政务服务一体化平台对接接口，包含报装申请、缴费记录、管网巡检工单、用户报修信息等类型。基础数据如管网分布、收费标准按日或季度更新，业务工单数据按小时或实时同步。单条数据的文档结构包含工单编号、业务类型、办理节点、所需材料清单、办理时限、联系渠道等字段，字段单位包括工作日（办理时限）、份（材料份数）、户（用户编号）等。

## 这些特征在「部署与升级」这一环带来什么约束
城市水务的数据来源包含多套内部系统与政务平台，部署时需配置多个兼容的数据源连接，升级时需保留原有数据源的配置映射，避免业务数据同步中断。实时工单的高频更新要求数据库连接池参数适配高并发场景，防止数据同步延迟。业务字段包含用户隐私信息，部署时需配置加密参数，升级时不得修改加密规则，保障用户数据安全。业务办理的分类固定，知识库的分类配置需与业务类型一一对应，升级时不得随意调整分类结构，防止用户无法找到对应办理引导。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://water_user:secure_pass@db-host:27017/water_biz?maxPoolSize=20` | 存储小时级更新的业务工单数据，高连接池适配高频同步需求 |
| `PG_URL` | `postgresql://water_base_user:base_pass@db-host:5432/water_base?sslmode=require` | 存储结构化的管网、收费标准等基础数据，保障事务一致性 |
| `REDIS_URL` | `redis://redis_pass@cache-host:6379/0` | 缓存高频查询的业务办理节点信息，降低数据库负载 |
| `FE_DOMAIN` | `https://water-service.localdomain` | 对接政务服务门户的统一入口域名，保障业务入口一致性 |
| `FILE_TOKEN_KEY` | `32位随机加密字符串` | 加密用户上传的办理材料，保障隐私数据安全 |
| `ROOT_KEY` | `长度不低于16位的复杂随机字符串` | 管理后台的权限验证，防止未授权访问 |

## 容易做错的三处
- 部署完成后访问OneAPI管理页面，渠道列表为空。原因是未正确配置`MONGODB_URI`或`PG_URL`，导致渠道元数据无法从数据库读取。
- 升级后前端页面显示的办理材料列表缺失。原因是升级时覆盖了知识库的业务分类配置，未保留原有水务业务的分类映射关系。

## 怎么确认配好了
- 访问`FE_DOMAIN`对应的前端入口，检查业务办理引导的分类菜单是否加载完整，核对是否包含报装、缴费、报修等水务专属业务类型。
- 登录FastGPT管理后台，检查`MONGODB_URI`和`PG_URL`对应的数据库中是否存在已同步的水务业务数据，核对字段是否与业务需求匹配。
- 上传一份测试用的办理材料示例，检查是否能正常存储，核对`FILE_TOKEN_KEY`的配置是否生效。
- 调用OneAPI的渠道列表接口，检查返回的渠道数据是否完整，核对数据源连接配置是否正确。
