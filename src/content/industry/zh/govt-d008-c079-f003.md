## 这些特征在「多轮对话与提示词」这一环带来什么约束
业务数据按具体办理事项分类，要求多轮对话需先识别用户当前的业务需求，再匹配对应事项的标准化流程，因此需要绑定唯一的对话标识以追溯进度。数据字段包含明确的格式与单位要求，提示词需严格限定AI输出的内容范围，避免编造非标准化信息。数据更新频率较高，需定期同步知识库，多轮对话的上下文需过滤过期的流程信息，防止引导用户使用已变更的办理规则。此外，用户可能上传jpg格式的材料图片，需支持图片内容的识别与校验。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 800–1200 字符 | 城市燃气单业务办理的对话轮次多为2-3轮，上下文需保留当前业务类型与用户已提供的信息，避免冗余 |
| `chatId`绑定规则 | 按用户办理的唯一业务工单编号绑定 | 确保每笔业务的对话日志可追溯，匹配用户的实际办理进度 |
| `messages`上下文保留规则 | 仅保留当前业务事项相关的对话轮次，丢弃过期的无关对话 | 避免上下文污染，确保AI输出的流程指引与当前业务匹配 |
| `variables`参数配置 | 预设业务事项、所需材料、办理时限三个变量 | 快速调用对应业务的标准化数据，减少提示词冗余 |
| 输入内容上限拦截 | 1000 token，按实测标定 | 避免超出AI模型的输入限制，提前拦截超长输入报错 |
| 图片输入支持 | 开启AI对话节点的图片识别功能 | 支持用户上传jpg格式的办理材料，匹配对应材料的校验规则 |

## 容易做错的三处
- 现象：对话日志无法关联到具体用户或业务工单，原因：未按业务工单编号绑定`chatId`，导致日志无唯一标识。
- 现象：输入超长文本后出现报错或无响应，原因：未配置输入内容上限拦截规则，未提前校验用户输入的长度。
- 现象：AI无法识别用户上传的jpg材料，原因：未开启AI对话节点的图片识别功能，未在提示词中说明可接收图片格式的办理材料。

## 怎么确认配好了
- 发起一笔模拟燃气开户业务的多轮对话，查看对话日志是否绑定了唯一的`chatId`与业务工单编号。
- 输入超过1000 token的测试文本，确认系统提前拦截并提示输入过长。
- 尝试删除当前对话的记录，确认操作可正常执行。
- 上传jpg格式的营业执照图片，查看AI是否能识别并关联到开户所需的材料校验规则。
