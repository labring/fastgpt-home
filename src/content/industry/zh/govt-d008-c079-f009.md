# 城市燃气的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
城市燃气的业务办理流程数据，主要来自线下办理窗口、线上服务端口的工单系统及内部运维台账。数据更新分为两类：用户提交的实时工单在完成校验后10分钟内同步，历史归档数据每日凌晨批量更新。单条业务数据包含办理事项名称、所需材料清单、办理流程步骤、办理时限、办理地点、咨询电话等字段，步骤以序号标注，时限以工作日为单位，材料清单以项数统计。

## 这些特征在「模型接入与配置」这一环带来什么约束
城市燃气业务数据的实时更新要求，模型接入需支持低延迟的增量数据拉取，避免返回过期的办理指引。结构化字段的标准化设计，要求模型输出需严格匹配预设字段格式，避免生成非预期内容。不同办理事项的字段差异，需为模型配置按事项分类的上下文调用规则，确保匹配对应业务的材料、流程信息。地域化的办理地点与咨询电话字段，要求配置地域维度的参数隔离，避免跨区域数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 城市燃气业务数据包含多步骤流程与材料清单，需保留足够上下文确保流程完整性 |
| `temperature` | 0.1–0.3 | 需严格匹配业务字段格式，降低随机输出概率 |
| `toolChoice` | auto | 需根据用户问题自动调用对应业务知识库，适配不同办理事项 |
| `vision` | 关闭 | 业务办理流程引导主要基于文本数据，无需图片理解能力 |
| `AIPROXY_API_ENDPOINT` | 按区域配置专属节点 | 适配不同城市燃气业务的地域数据隔离需求 |
| `quoteMaxToken` | 1500 字符 | 限制单条引用数据的长度，避免上下文溢出 |

## 容易做错的三处
- 现象：调用模型时频繁返回429 Request rate increased too quickly报错。原因：未针对城市燃气业务的高峰工单时段配置合理的请求限流参数，导致短时间内请求量超出阈值。
- 现象：配置大模型时删除body参数后，再次进入配置页仍显示原有参数。原因：未保存配置变更就退出页面，或FastGPT v4.17.0的表单缓存机制未自动清除历史参数。
- 现象：不同应用调用同一API模型时，原有配置被覆盖。原因：未为每个应用配置独立的`AIPROXY_API_TOKEN`，复用同一密钥导致配置冲突。

## 怎么确认配好了
- 发起一条燃气报装业务的测试查询，核对返回结果是否包含对应事项的材料、流程、时限等字段，格式是否与业务数据一致。
- 模拟高峰时段的并发请求，检查是否触发限流报错，调整参数至请求稳定。
- 为不同应用生成独立的API密钥，分别发起调用，确认各自的配置参数互不干扰。
- 检查模型输出是否未包含非业务相关的冗余内容，符合预设的格式要求。
