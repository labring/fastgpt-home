# 城投平台的业务办理流程引导：部署与升级

## 这个品类的数据长什么样
城投平台的业务办理数据主要来源于政务服务窗口台账、线上办事大厅的办结数据与官方发布的办事指南。数据随单批次业务办结完成或季度政务事项调整更新，无固定高频更新周期。单条数据包含事项名称、办理主体、申请材料清单、办理流程节点、时限要求、咨询渠道等字段，材料项以“份”“原件/复印件”为单位，办理时限以“工作日”为单位，流程节点按办理顺序排列为连续文本序列。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 100–200 个 | 城投平台业务办理数据的单次并发查询量较高，该参数限制数据库最大连接数，避免资源耗尽 |
| `MONGODB_URI` | 本地部署使用 `mongodb://localhost:27017/fastgpt`，云部署使用对应云服务商的连接地址 | 城投平台的办事指南与办结记录多为半结构化数据，MongoDB适配此类数据的存储需求 |
| `REDIS_URL` | 本地部署使用 `redis://localhost:6379/0`，云部署使用带认证的云Redis地址 | 用于缓存高频查询的办事流程节点，降低数据库的重复查询压力 |
| `ROOT_KEY` | 自定义32位以上随机字符串 | 用于管理员权限验证，城投平台业务数据涉及政务信息，需保障后台配置的安全性 |
| `STORAGE_S3_ENDPOINT` | 本地部署使用本地对象存储地址，云部署使用对应云服务商的S3端点 | 用于存储办事材料的扫描件或电子文档，适配城投平台的材料存储需求 |
| `FE_DOMAIN` | 本地部署使用 `http://localhost:3000`，线上部署使用正式域名 | 用于配置前端访问地址，保障业务办理引导页面的正常访问 |

## 容易做错的三处
- 修改`ROOT_KEY`后重启服务仍无法生效，日志提示权限验证失败。原因是仅修改了docker-compose.yml中的参数，未同步重启所有关联的服务容器，导致配置未全局生效。
- 启动后出现数据库连接失败报错，日志显示连接超时或认证失败。原因是未正确配置`MONGODB_URI`或`PG_URL`参数，未检查数据库服务是否正常启动，或未配置正确的访问权限。
- Windows本地部署启动后无法加载办事流程数据，界面显示空列表。原因是未正确配置本地文件存储路径，导致办事指南的电子文档无法被系统读取，或未开启对应目录的访问权限。

## 怎么确认配好了
- 执行docker compose ps命令，确认所有服务容器处于运行状态，无异常退出或重启记录。
- 访问`FE_DOMAIN`配置的域名或本地地址，尝试使用`ROOT_KEY`登录后台管理界面，验证管理员权限验证正常。
- 上传一条城投平台的办事指南文档至知识库，执行检索测试，确认能返回正确的流程节点与申请材料清单。
- 查看Redis监控指标，确认高频查询的办事流程节点缓存命中率达到业务场景预设的阈值（按实测标定）。
