# 基础化工的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
基础化工的业务办理相关数据主要来自企业内部生产调度手册、安全操作规程、行政审批办事指南及设备运维档案。数据更新以月度为节奏，部分应急类文档随专项检查结果实时更新。单份文档多为结构化与半结构化结合的形式，包含设备编号、操作参数、审批流程节点等字段，单位涉及兆帕、摄氏度、立方米、吨等工业标准单位，部分流程文档附带有前置条件校验规则。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
专业术语与工业单位的混用，要求多轮对话的提示词需内置基础化工领域术语校验规则，避免参数匹配错误。结构化字段的存在，要求多轮会话需按流程节点逐步引导用户补充设备编号、操作压力等必填项，防止缺失关键信息。月度更新的文档特征，要求多轮对话的上下文召回需限制近30天内的文档范围，避免引用过期规则。审批流程的节点化结构，要求提示词明确各环节的前置校验条件，防止跨节点跳转引发的办理错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 按会话生成唯一字符串标识 | 适配FastGPT v4.17.0的会话隔离机制，用于隔离多轮会话的上下文数据，避免不同用户的办理流程互相干扰 |
| `messages` | 保留近8–12轮对话内容 | 覆盖基础化工业务办理的完整节点流程，防止关键前置信息丢失 |
| `variables` | 预设设备类型、安全阈值区间等固定字段 | 减少用户重复输入专业参数，提升会话填写效率 |
| 最大上下文窗口 | 8000–12000 token | 适配基础化工专业文档的长度，避免截断核心操作规则与审批要求 |
| 问题优化策略 | 开启工业术语校准 | 自动修正用户输入的单位或术语错误，匹配业务数据的标准格式 |
| 单次召回上限 | 前6条匹配文档 | 控制上下文信息量，避免冗余内容干扰多轮对话的逻辑判断 |

## 容易做错的三处
- 现象：AI对话节点的输出直接混入业务办理流程的返回结果中，无法单独获取任务结果。原因：未在节点配置中关闭对话流输出开关，导致节点执行结果直接写入全局对话上下文。
- 现象：多轮会话中出现过期的安全操作规程内容，导致办理流程校验失败。原因：未限制上下文召回的文档更新时间范围，召回了超过1个月的旧版文档。
- 现象：用户输入的设备参数无法匹配业务数据，会话中断。原因：未预设专业变量字段，未开启术语校准，导致参数格式不匹配业务数据要求。

## 怎么确认配好了
- 调用测试接口，传入`chatId`与模拟会话的`messages`，检查会话上下文是否按配置保留指定轮次。
- 输入包含工业单位的测试参数，检查系统是否能自动校准术语与单位格式，匹配业务数据字段。
- 查看AI对话节点的配置，确认是否关闭了直接输出开关，验证任务结果是否仅返回指定内容。
- 传入不同的业务场景变量，检查`variables`预设字段是否自动填充到会话中，减少重复输入操作。
