# 基础电信运营的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
基础电信运营的业务办理流程数据主要来源于官方业务手册、线上营业厅的业务指引页面、线下营业厅的流程规范文档。数据更新节奏分为两类：常规业务流程每月更新一次，新套餐上线、监管政策调整时即时更新。文档按业务大类拆分，涵盖宽带办理、号码销户、套餐变更等类别，每个文档包含办理步骤、所需材料、办理时长、收费标准等字段，字段单位包含分钟、元、次等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
业务大类拆分的文档结构要求检索时需保留同业务下的上下文关联，避免召回的分块断在步骤中间，导致流程指引不完整。字段包含办理时长、收费标准等带单位的数值信息，检索时需确保匹配结果同时关联业务场景与单位信息，防止出现数值与业务不匹配的情况。多来源的数据更新节奏差异，要求召回环节支持增量同步与全量同步的灵活切换，确保新更新的流程数据可及时被检索到。同时，电信业务术语较多，需严格限定检索范围，避免召回与当前业务无关的其他品类文档。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 基础电信业务流程文档的语义区分度较高，该区间可过滤无关的业务说明内容，保留匹配度符合要求的流程步骤 |
| `limit` | 前8条 | 单业务流程的步骤通常不超过10步，召回8条可覆盖完整流程且避免上下文过载 |
| `searchMode` | vectorSearch | 业务流程的语义关联较强，向量搜索可精准匹配用户提问的业务场景 |
| `usingReRank` | 开启 | 流程文档的长文本分块可能存在语义分散，重排可提升高相关分块的排序权重 |
| `datasetSearchUsingExtensionQuery` | 开启 | 电信业务术语较多，扩展查询可补充套餐、销户等常用同义词，提升召回覆盖度 |
| `collectionIds` | 对应电信业务流程的专属集合ID | 避免召回其他品类的文档，确保检索范围仅覆盖基础电信运营的业务办理数据 |

## 容易做错的三处
- 现象：知识库导入静态页面时出现`Validation failed: name: Path `name` is required.`报错。原因：未正确配置导入源的名称字段，静态页面抓取时未提取或映射文档名称参数。
- 现象：回答中强制显示知识库搜索的input和response引用内容。原因：未在FastGPT v4.17.0的工作流配置中关闭引用展示开关，或未配置回答生成时隐藏工具返回的元数据。
- 现象：召回结果条数超出配置的`limit`数量。原因：未正确绑定专属集合ID，检索范围覆盖了无关的业务文档集合，导致额外的文档被召回。

## 怎么确认配好了
- 上传一份测试用的电信业务流程文档，检查知识库导入是否无报错，确认文档名称字段正常映射。
- 发起一个业务办理相关的提问，检查回答中是否仅展示流程步骤，无冗余的工具调用input和response内容。
- 调整`similarity`参数至0.7，检查召回结果是否包含更多无关内容，验证参数生效。
- 查看检索日志，确认仅从指定的`collectionIds`集合中召回数据，无跨集合的文档被返回。
