# 基础设施建设的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
基础设施建设的业务办理数据主要来源于项目立项审批文件、现场施工日志、材料报验单、竣工验收报告等。数据更新按项目执行节点推进，施工类日志按天更新，台账类报表按月更新。文档以结构化字段为主，包含项目编号、施工区域、材料规格、报验时间等字段，单位涵盖米、立方米、吨、工作日等，单篇文档长度跨度较大，短则数百字符，长可达数万字符。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配基础设施建设项目文档的长度跨度，避免长文本被截断丢失关键字段信息 |
| `maxTokens` | 2000–3000 token | 匹配业务办理流程引导的单次回复长度，确保涵盖完整的步骤说明与字段校验要求 |
| `quoteMaxToken` | 1500 字符 | 限制引用的业务文档片段长度，聚焦施工报验、进度确认等核心流程的关键内容 |
| `temperature` | 0.2–0.4 | 降低随机输出概率，保障结构化字段识别与流程步骤的准确性，适配建筑施工的严谨性要求 |
| `toolChoice` | auto | 自动选择工具调用，适配业务办理中需要查询项目台账、材料参数的场景 |
| `AIPROXY_API_TOKEN` | 按平台分配的专属密钥填写 | 确保模型调用的身份验证有效，避免因密钥错误导致的渠道不可用问题 |

## 容易做错的三处
- 现象：配置`AIPROXY_API_TOKEN`后提示无可用渠道。原因：未在对应分组中配置该密钥的访问权限，或密钥填写存在格式错误。
- 现象：对话与工作区的模型配置出现不一致。原因：未在全局配置与应用配置中同步更新模型参数，导致不同场景下调用的模型版本或参数不匹配。
- 现象：流程引导响应速度不理想，硬盘IO占用较高。原因：未合理设置`maxContext`参数，导致每次调用加载过多长文本文档，增加磁盘读取与模型处理负载。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型管理界面，核对`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的填写内容与平台分配的一致。
- 上传一篇典型的施工报验单文档，触发流程引导测试，检查回复中是否准确识别了材料规格、报验时间等结构化字段。
- 调整`temperature`参数后，多次触发同一场景的流程引导，确认输出结果的一致性符合预期。
- 查看模型调用日志，确认每次调用的`maxContext`与`maxTokens`参数匹配预设配置，无超限报错。
