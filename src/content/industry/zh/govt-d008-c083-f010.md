# 基础设施建设的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
基础设施建设的业务数据主要来源于施工日志、招投标文件、现场交底文档、材料报审表、竣工验收规范等。数据更新节奏随项目节点推进，日常每周同步一次现场数据，节点验收后归档周期内的全部文档。单份文档结构包含标段编号、施工日期、验收标准、材料型号等专属字段，单位涵盖米、立方米、吨、工作日等工程类标准单位，部分文档包含扫描版施工图纸与结构化表格。

## 这些特征在「知识库检索与召回」这一环带来什么约束
专属字段与单位要求检索时需精准匹配项目维度，否则会召回无关标段的内容，影响业务办理的准确性。文档长度差异大，从几页的现场交底到几十页的验收报告，拆分时需保留标段编号、施工日期等字段关联，避免破坏业务逻辑。高频更新的现场数据要求定期重新嵌入，防止旧数据与当前项目进度脱节。扫描版图纸与表格文档也需要被纳入检索范围，增加了预处理的复杂度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 基础设施建设文档包含大量专业术语与项目专属编号，阈值过低会引入无关标段内容，过高会遗漏相关节点文档，按实测标定 |
| `limit` | 前8–12条 | 单项目业务办理的相关文档通常集中在10个左右节点，避免上下文超出模型处理上限 |
| `usingReRank` | 开启 | 专业文档的语义相似度区分度低，重排可提升Top3结果的准确率，适配业务流程的精准检索需求 |
| `datasetSearchUsingExtensionQuery` | 开启 | 业务办理流程的问题常包含模糊表述，扩展查询可覆盖同义词与项目缩写，提升召回覆盖率 |
| `collectionIds` | 按当前项目的知识库集合ID传入 | 基础设施项目按标段划分知识库，过滤非目标项目的文档，避免召回干扰内容 |
| `searchMode` | vector | 优先使用语义召回，匹配业务流程的上下文关联，适配专业文档的语义匹配需求 |

## 容易做错的三处
- 现象：在知识库管理界面无法选中表格格式的施工报审文档。原因：未开启表格数据集的自动解析开关，系统默认跳过非文本格式的结构化文档。
- 现象：更换嵌入模型后，多语言业务文档的召回率大幅下降。原因：未对全量历史文档执行批量重新嵌入，导致新旧嵌入向量存在语义空间偏差。
- 现象：调用接口创建文本集合时返回无效参数提示。原因：未按FastGPT v4.17.0版本的要求，在请求中携带段落优先拆分模式的对应参数，导致系统无法识别拆分规则。

## 怎么确认配好了
- 查看知识库的数据集列表，确认目标标段的表格文档已被正确加载。
- 发起一次业务流程查询，检查召回结果的来源是否均为当前项目的知识库集合。
- 对比更换嵌入模型前后的召回结果，确认多语言文档的语义匹配度符合预期。
- 调用接口测试文本集合创建，确认返回结果无参数错误提示。
