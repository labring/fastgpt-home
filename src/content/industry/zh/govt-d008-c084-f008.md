# 大宗商品贸易的业务办理流程引导：文档解析与分块

## 这个品类的数据长什么样
大宗商品贸易的业务数据主要来源于购销合同、仓单、报关单、结算单等纸质或电子文档，更新随单笔业务节点触发，无固定周期。文档多为多页PDF或结构化表格，包含货物品名、批次号、交割数量、单价、结算方式等固定字段，单位多采用吨、立方米、元/吨等行业通用计量标准，部分文档会附带运输、质检等附属附件。

## 这些特征在「文档解析与分块」这一环带来什么约束
大宗商品贸易的长文档结构会带来解析超时风险，多页合同、仓单等文档页数可达数十甚至上百页，单次解析负载较高。固定字段如批次号、交割数量、单价等若被跨块拆分，会导致后续流程引导时信息断裂，无法为业务人员提供连贯的办理指引。附属的质检报告、运输单据等多格式附件，要求解析工具兼容多种文件类型，避免部分附件解析失败导致流程信息缺失。同时行业文档的计量字段单位存在细微差异，需在分块时保留相邻字段的关联关系，确保后续信息调用的准确性。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写以下配置说明。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配大宗商品贸易文档的字段长度，避免拆分关键业务字段 |
| `chunkSplitter` | 按段落+语义分块 | 保留合同、仓单的段落语义完整性，避免割裂业务逻辑 |
| `customPdfParse` | 启用pdf-marker解析 | 适配多页长PDF文档，优化结构化表格提取效果 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容大额仓单、多附件打包文档的上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 秒 | 适配数十页以上文档的解析耗时，避免超时中断 |
| `chunkSettingMode` | 手动配置 | 针对行业文档的特殊字段调整分块规则，避免自动分块的误拆分 |

## 容易做错的三处
- 现象：调用`customPdfParse`解析上百页仓单文档时，长时间等待后返回超时错误。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，使用默认短超时阈值，无法覆盖长文档解析耗时。
- 现象：上传打包了多份质检报告的文档后，部分附件解析结果为空。原因：未启用`customPdfParse`的多附件兼容配置，仅解析主文档忽略附属文件。
- 现象：分块后出现批次号与对应数量拆分至不同块的情况。原因：使用默认语义分块规则，未手动调整`chunkSettingMode`，导致关键业务字段被跨块分割。

## 怎么确认配好了
- 上传一份行业标准的多页购销合同文档，查看解析结果是否完整提取所有业务字段。
- 检查`PARSE_FILE_TIMEOUT_SECONDS`的配置值，确认其适配当前部署环境的解析速度。
- 随机抽取分块后的片段，核对关键业务字段是否保留在同一块内。
- 验证大尺寸打包文档的上传与解析流程，确认无中断或报错。
