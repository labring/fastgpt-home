# 大宗商品贸易的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
大宗商品贸易的业务数据主要来源于内部贸易合同系统、仓单管理平台、物流跟踪系统及业务办理流程手册。数据更新节奏覆盖每日的现货价格行情、每周的合同归档更新、每月的流程节点调整通知。文档形态包含结构化Excel表格（含货物品类、交易数量、单价、交货周期等字段）、PDF格式的标准化办理指南，以及数据库存储的审批流配置信息，字段多涉及吨、元/吨、工作日等专用计量单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化Excel的多列分行数据要求检索时能精准匹配单一行的业务字段，避免跨行混淆；专用计量单位要求检索模型能识别吨、元/吨等行业术语，避免语义匹配偏差。高频更新的现货行情数据要求召回结果的时效性匹配数据更新周期，避免返回过时价格。多来源的文档形态要求检索系统同时支持结构化数据匹配与非结构化文本检索，覆盖合同、指南等不同格式的业务数据。业务办理流程的节点变更频率要求知识库能快速同步更新审批节点信息，确保引导内容与当前流程一致。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配大宗商品贸易的专用术语与结构化字段，避免过低导致无关结果，过高导致召回不足 |
| `limit` | 前8条 | 覆盖单批次业务办理可能涉及的多个审批节点与合同条款，避免召回过少遗漏关键信息 |
| `searchMode` | hybrid | 同时支持结构化字段匹配与非结构化文本检索，适配贸易数据的多形态特征 |
| `usingReRank` | 开启 | 对召回结果按业务相关性重排，优先返回审批流程、合同条款等高频使用的内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展业务问题的行业术语，比如将“提货”关联“仓单出库”，提升检索精准度 |
| `collectionIds` | 绑定贸易流程、仓单、合同三个专属集合 | 限定检索范围，避免混入其他品类的业务数据 |

## 容易做错的三处
- 导入多列Excel贸易数据后，自动分段结果将跨行列的字段混为一段，无法按单行业务条目拆分。未针对结构化表格数据配置按行分段的规则，默认自动分段逻辑未识别表格的行列结构。
- 调用知识库检索功能时返回“undefined model must match "^(text" 报错。未使用FastGPT支持的嵌入模型，或在配置中错误选择了非文本类嵌入模型。
- 检索返回的结果中混入了非贸易流程的行政办公文档。未配置`collectionIds`绑定专属业务数据集，检索范围覆盖了其他无关集合的内容。

## 怎么确认配好了
- 上传一份包含单行业务条目的测试Excel，查看分段结果是否按单行列完整拆分，确认分段规则生效。
- 输入包含行业术语的测试问题，比如“铜材贸易的审批节点有哪些”，查看检索结果是否优先返回贸易流程相关内容，确认重排与扩展查询生效。
- 查看检索日志，确认仅调用了绑定的专属业务数据集，未检索到其他集合的内容，确认`collectionIds`配置正确。
- 调整检索参数的取值范围，测试不同阈值下的召回结果数量变化，确认参数配置符合业务需求。
