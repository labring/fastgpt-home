# 工程咨询监理的业务办理流程引导：HTTP 接口与外部系统

## 这个品类的数据长什么样
工程咨询监理的业务数据主要来源于现场监理台账、工程验收文档、进度管控报表，随项目施工节点更新，核心文档包含结构化元数据与非结构化附件。结构化字段包含项目标段编号、监理单位名称、工序验收项、整改项标识，单位涵盖自然日、单工序、文件份数。非结构化内容关联旁站影像、整改通知书扫描件，单份文档字符量跨度较大，从数百字符到数万字符不等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
结构化与非结构化混合的数据特征，要求HTTP接口同时支持结构化参数传递与二进制附件上传。字段包含项目标段编号、整改项标识等必填项，要求接口配置严格的参数校验规则，避免无效数据流入。单份文档字符跨度大的特点，要求接口设置合理的单次传输上限，同时支持断点续传机制。随项目节点动态更新的数据，要求接口支持按需触发拉取，适配业务数据的非固定更新节奏，匹配工程咨询监理的业务推进节奏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer sk-xxxxxx`（替换为实际平台密钥） | 完成与外部监理系统的身份鉴权，保障数据交互安全，适配FastGPT v4.17.0版本的鉴权逻辑 |
| `variables` | 传入项目标段编号、整改项标识 | 适配结构化业务字段的参数传递，精准拉取对应标段的监理数据 |
| `responseData` | 仅保留该字段内的业务内容 | 过滤接口返回的冗余包装数据，仅提取工程咨询监理的核心业务信息 |
| 超时阈值 | 600 秒 | 适配大附件上传与多字段校验的耗时需求 |
| 重试次数 | 3 次 | 应对临时网络波动，保障数据同步的稳定性 |
| 附件上传开关 | 开启 | 支持关联旁站影像、整改通知书等非结构化业务附件 |

## 容易做错的三处
- 调用接口后附件字段为空，或返回413状态码。原因是未开启附件上传配置，或未正确设置单次传输上限，无法适配工程监理文档的大体积附件。
- 接口返回数据缺失核心业务字段，如整改项标识、验收节点信息。原因是未在`variables`中传入必填的项目标段编号参数，导致拉取的数据范围不符合业务需求。
- 接口返回401鉴权失败状态码。原因是`Authorization`头格式错误，未使用标准`Bearer`前缀或密钥已过期，无法通过外部系统的鉴权校验。

## 怎么确认配好了
- 调用测试接口，检查返回的`responseData`字段是否包含预设的项目标段编号，确认参数传递生效。
- 上传一份小型监理文档附件，检查接口是否正常接收并返回上传成功标识，确认附件配置生效。
- 模拟临时网络中断后重试接口，检查是否自动触发重试机制，确认超时与重试配置生效。
- 查看外部系统的日志，确认接收到的请求头包含正确的`Authorization`鉴权信息，确认鉴权配置生效。
