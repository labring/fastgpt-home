# 工程咨询监理的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
工程咨询监理的业务办理数据主要来源于项目监理日志、旁站检查记录、分项工程验收报告、工程变更签证单等文档。数据更新节奏随项目推进节点调整，分项验收后更新频率提升，日常监理日志按周归档。单份文档结构固定，包含项目编号、监理单位、检查项、整改要求、整改时限、验收结果等字段，部分文档附带工程面积、工期天数等数值型单位字段，文本内容多为流程性描述与现场问题记录。

## 这些特征在「向量模型与索引」这一环带来什么约束
工程咨询监理的多字段结构化文档，要求索引环节需保留字段关联关系，避免分块破坏业务上下文。现场问题记录的长文本内容，要求向量模型适配长文本输入，避免截断关键流程描述。按项目节点的增量更新节奏，要求索引支持按项目批次触发增量重建，避免全量重新生成。数值型单位字段的存在，要求索引环节需补充数值特征的向量化适配，或关联对应文本描述进行联合索引。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配监理文档中单段流程描述、整改要求的常规长度，避免破坏业务上下文完整性 |
| 重叠长度 | 100–150 字符 | 保留监理流程跨分块的前后步骤关联，避免关键流程节点被拆分 |
| 相似度阈值 | 0.72–0.85 | 平衡业务办理流程引导的召回准确性与完整性，适配监理记录的语义相似度分布 |
| 单次搜索上限 | 前 8 条 | 匹配单份业务办理涉及的关联监理记录数量，避免过多冗余信息进入上下文 |
| `maxToken` | 8192 | 适配FastGPT v4.17.0版本主流embedding模型的最大token限制，覆盖监理长文档分块后的总长度 |
| 重排 | 开启 | 结合业务字段匹配度优化搜索结果排序，修正单纯语义相似度的偏差 |

## 容易做错的三处
- 更换embedding模型后导入的知识库无法正常检索，表现为搜索结果为空或语义匹配偏差。原因是原有索引基于旧模型的向量空间生成，未同步更新向量特征。
- 未选择ada 002时出现报错，表现为界面弹出“undefined model must match "^(text”报错文案。原因是部分embedding模型需提前配置专属接口权限或版本适配，未完成前置配置时触发模型校验失败。
- 语义检索分数高但匹配结果无关，表现为搜索结果的分数达标但未匹配业务办理流程的核心要求。原因是未开启重排功能，单纯依赖语义相似度时易混淆流程描述与无关现场记录。

## 怎么确认配好了
- 导入单份典型监理文档，查看分块预览界面，确认分块长度符合预设区间且未截断关键整改要求。
- 触发知识库增量更新，核对更新日志的批次范围，确认仅针对指定项目节点的文档进行索引重建。
- 发起业务办理流程引导的测试查询，查看搜索结果的排序逻辑，确认重排功能生效后结果优先级符合业务预期。
- 更换embedding模型后，手动触发全量索引重建，验证检索结果的语义匹配度无明显偏差。
