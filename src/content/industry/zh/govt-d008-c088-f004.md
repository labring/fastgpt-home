# 工程咨询监理的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
工程咨询监理的数据主要来自旁站监理日志、分项工程验收报告、进度款报审表、现场影像资料四类。数据来源覆盖项目现场监理人员手工填报、施工单位报审上传两类渠道。更新节奏随工程节点推进，旁站日志每日更新，验收报告在分项工程完成后更新，报审表随付款节点提交。文档结构包含项目编号、监理单位、施工单位、分项工程名称、验收节点、整改项数量、整改闭环状态等字段，字段单位包含天、项、万元等工程类专属单位。

## 这些特征在「工作流编排」这一环带来什么约束
工程咨询监理的数据分散在多类异构文档中，要求工作流配置多节点并行拉取不同数据源，避免单节点数据过载。字段包含工程类专属单位，要求工作流配置变量校验规则，确保输入输出单位匹配，避免数据混用。部分数据包含现场影像文件流，要求工作流支持二进制文件流处理节点，适配PDF、JPG等常用格式。数据更新随工程节点触发，要求工作流绑定节点事件作为触发条件，确保数据时效性符合监理业务要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定项目编号、整改项数量、验收时长三类字段，按实测标定单位校验规则 | 监理数据字段有明确工程类单位，需校验避免参数混用 |
| 触发节点设置 | 绑定分项工程验收完成事件 | 监理数据随工程节点更新，事件触发比定时更贴合业务节奏 |
| HTTP请求节点 | 设置超时时间为300秒 | 监理多页PDF文档解析耗时较长，300秒可覆盖多数场景 |
| 文件流处理节点 | 支持JPG、PDF格式，按实测标定最大文件大小为100 MB | 监理现场影像单张不超过20 MB，汇总报审文件不超过100 MB |
| `nodeId` | 为每个数据源节点分配唯一`nodeId` | 避免多节点拉取时数据混淆，确保工作流流转正确 |
| 单次数据拉取量 | 拉取前20条数据 | 监理单节点数据量适中，20条可覆盖单次业务办理的核心信息 |

## 容易做错的三处

- 现象：工作流返回字段为空，无法加载业务数据。原因：未将`variables`绑定到监理数据的对应字段，导致变量未正确加载。
- 现象：HTTP请求节点返回格式报错，无法解析图片文件。原因：未配置文件流处理节点，直接尝试将二进制图片流解析为文本数据。
- 现象：工作流触发后节点流转中断。原因：未为每个数据源节点分配唯一`nodeId`，导致节点ID冲突，无法正常流转。

## 怎么确认配好了
- 进入工作流调试页面，输入测试项目编号，查看`variables`是否正确加载对应字段的结构化数据。
- 上传一份整改报告PDF或现场影像JPG文件，测试文件流处理节点是否正常解析并返回结构化信息。
- 模拟分项工程验收完成事件，查看工作流是否按预期启动并完成多节点数据拉取。
- 检查每个数据源节点的`nodeId`是否唯一，无重复配置项。
