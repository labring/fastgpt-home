# 工程咨询监理的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
工程咨询监理的数据主要来自项目监理台账、报审报验文件、旁站监理记录、分部分项验收报告等。数据随项目推进节点更新，单次报审批次数据量随工程阶段波动。文档包含结构化表单字段与非结构化附件，结构化字段含监理编号、工程部位、报审事项、验收结论等，单位涉及平方米、万元、工作日等。本文档基于FastGPT v4.17.0版本编写。

## 这些特征在「模型接入与配置」这一环带来什么约束
工程咨询监理的结构化字段多且带专属单位，会提升输入token总量，要求配置时严格控制上下文窗口容量。非结构化附件格式多样，需模型适配不同解析后的文本结构，对应配置需兼容多格式输入。数据随项目节点动态更新，要求配置绑定自动同步知识库的触发逻辑。不同报审批次的文档长度差异显著，需配置支持动态调整输出长度的规则。监理数据的严谨性要求，模型输出需严格匹配已有字段与单位，避免随意篡改。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配工程咨询监理多字段表单与附件的总输入长度，避免上下文溢出 |
| `maxTokens` | 14000–16000 token | 覆盖监理报告、验收结论等长输出内容的需求，匹配常见大模型的输出上限 |
| `quoteMaxToken` | 2000–3000 token | 限制引用的监理原始文档片段长度，避免引用内容占用过多上下文 |
| `temperature` | 0.1–0.3 | 保障监理业务输出的严谨性，减少随意性表述，匹配工程数据的准确要求 |
| `toolChoice` | auto | 自动选择是否调用工具处理结构化字段提取与格式校验，适配监理数据的多类型处理需求 |
| `AIPROXY_API_ENDPOINT` | 按平台提供的专属地址填写 | 确保模型请求的路由正确，避免请求无法送达指定大模型服务 |

## 容易做错的三处
- 配置开启思考过程输出后，结果未显示思考内容。原因是未在模型调用参数中正确启用思考输出开关，或所选模型不支持该格式的思考内容返回。
- 配置`maxTokens`为16384时，输出在12288 token处被截断并提示超出回复限制。原因是未区分模型的实际输出上限与全局配置值，部分模型的输出上限低于16384，或输入token占用了过多上下文窗口。
- 模型配置文件未加载成功。原因是未将配置文件存放至FastGPT预设的配置目录，导致系统无法读取对应参数。

## 怎么确认配好了
- 发起一次包含监理报审文档的测试请求，检查返回结果是否包含配置的思考过程内容（若开启）。
- 查看模型调用日志，确认输入输出token的统计值未超出所选模型的实际上限，无截断提示。
- 检查配置文件存放路径，确认与FastGPT部署文档中指定的路径一致。
- 发起包含多字段结构化数据的测试请求，检查返回结果是否严格匹配输入的字段与单位。
