# 工程咨询监理的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
工程咨询监理的业务数据主要来自项目监理规划、旁站监理记录、分项工程验收报告、监理实施细则四类核心文档。数据更新随项目推进节奏，旁站记录按每日巡检批次更新，验收报告随对应工程节点完成后同步上传。文档结构固定包含项目编号、专业工程类别、执行节点、条款原文、监理签字栏，字段包含整改时限（单位为工作日）、验收合格判定项、关联施工工序编号，单篇文档长度从数百字符到数千字符不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
工程咨询监理的数据按专业类别、执行节点分类存储，检索时需限定对应范围以排除跨专业无关结果。单篇文档长度跨度大，条款式结构易出现分块截断关键整改要求，需调整分块逻辑适配条款拆分。字段包含带工作日单位的整改时限、关联工序编号，检索时需保留单位信息以精准匹配用户查询的具体要求。数据随项目节点动态更新，需配置增量同步触发规则，避免全量更新占用过多计算资源。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 匹配监理文档的专业术语密度，避免过低引入无关施工内容，过高遗漏关键整改条款 |
| `limit` | 前6条 | 监理文档单批次检索结果不宜过多，避免上下文溢出影响生成逻辑 |
| `searchMode` | semantic | 匹配专业术语的语义关联，适配监理细则的条款式逻辑，基于关键词匹配难以覆盖专业语义关联 |
| `usingReRank` | 开启 | 对初始检索结果按相关性重排，修正语义检索的偏差，确保核心整改要求靠前展示 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展用户查询的专业同义词，比如将“旁站”扩展为“现场巡检记录”，适配监理行业术语习惯 |
| `collectionIds` | 按项目专业分组的集合ID | 限定检索范围至对应专业的监理文档，避免跨专业结果干扰当前任务 |

## 容易做错的三处
- 现象：生成结果中出现“引用标记：［1］”类字样。原因：未关闭检索结果的引用标识自动附加配置，将检索条目的编号直接写入了生成上下文。
- 现象：检索结果包含跨专业的施工文档，与当前监理任务无关。原因：未通过`collectionIds`限定检索的专业文档集合，触发了全量知识库检索。
- 现象：单次检索返回结果过多导致上下文溢出。原因：未调整`limit`参数，使用了默认的高条数限制。

## 怎么确认配好了
- 进入知识库配置页面，确认`collectionIds`已绑定当前监理项目对应的专业文档集合。
- 输入包含监理专业术语的测试查询，核对返回结果的条目数量与`limit`参数设定一致。
- 查看生成结果预览，确认无“引用标记：［1］”类冗余字样。
- 触发增量同步任务，验证数据更新后检索结果能同步覆盖最新的验收报告内容。
