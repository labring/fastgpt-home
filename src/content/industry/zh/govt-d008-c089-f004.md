# 工程机械的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
工程机械的业务办理相关数据主要来自设备运维系统、作业调度平台与出厂参数库。数据来源涵盖设备实时工况采集、每日作业台账、定期维保记录三类。更新节奏区分场景：实时工况数据每秒更新，作业台账数据每日同步，出厂参数与维保记录为静态更新。单条数据包含设备唯一标识、作业时长、累计油耗、故障代码、作业区域编码、触发时间戳等字段，字段单位分别为小时、升、无代码标识、平方公里、ISO 8601格式时间戳。

## 这些特征在「工作流编排」这一环带来什么约束
实时工况的秒级更新要求工作流触发节点需设置毫秒级间隔监听，避免错过关键工况异动。作业台账的日更属性要求批量处理类工作流需配置每日定时触发节点。设备唯一标识与作业区域编码存在多格式差异，要求工作流前置增加字段标准化节点，统一数据格式后进入后续环节。静态参数的低频更新属性，要求工作流中静态参数的调用节点设置合理缓存周期，避免重复拉取增加系统负载。故障代码的标准化属性，可用于工作流分支判断，但需提前配置故障代码与对应处置流程的映射规则，确保分支逻辑准确触发。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发间隔 | 100–500 毫秒 | 适配工程机械实时工况的秒级更新节奏，避免错过关键异动 |
| 定时触发周期 | 24 小时 | 匹配作业台账的日更更新属性，适配批量数据处理场景 |
| `variables`绑定 | 设备唯一标识、作业时长、故障代码 | 绑定核心业务数据字段，支撑后续流程的分支判断与数据调用 |
| `nodeId`配置 | 按设备作业场景分组设置 | 区分不同作业场景的工作流分支，匹配工程机械多工况业务需求 |
| 字段标准化规则 | 统一作业区域编码格式 | 适配多来源数据的格式差异，确保后续流程的数据一致性 |
| 静态参数缓存周期 | 7 天 | 适配出厂参数的低频更新属性，减少重复拉取带来的系统负载 |

## 容易做错的三处
- 现象：知识库搜索节点在调试界面返回结果正常，但正式调用工作流时未返回匹配的工程机械运维数据。原因：未在`variables`中绑定设备唯一标识作为检索限定参数，导致检索范围未覆盖目标设备的专属数据。
- 现象：实时工况监听节点触发频率过高，导致系统资源占用超出阈值。原因：触发间隔设置低于100毫秒，超过了工程机械实时数据的实际更新频率，产生大量无效触发。
- 现象：故障代码分支逻辑触发错误，匹配了错误的处置流程。原因：未对原始故障代码做标准化转换，直接使用未规范的代码值进行分支判断，导致匹配结果偏差。

## 怎么确认配好了
- 查看工作流触发日志，确认触发间隔符合预设区间，无异常高频触发记录。
- 调用工作流API，检查返回结果中是否包含绑定的`variables`参数对应的设备数据字段，字段格式符合预设标准。
- 模拟故障代码输入，验证分支逻辑是否按照预设规则触发对应处置流程，无匹配错误。
- 检查静态参数缓存节点的刷新记录，确认参数更新后缓存已自动刷新，无过时数据返回。
