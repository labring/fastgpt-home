# 成品油销售的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
成品油销售的业务办理数据主要来自线下加油站POS终端、企业ERP进销存系统及会员管理系统。数据更新节奏分为实时交易数据（每笔加油、充值、开票操作完成后同步）与每日盘库数据（当日营业结束后更新）。单条业务文档结构包含油品编码、油品品类、交易时间、交易金额、加油升数、办理渠道、业务类型（加油、充值、开票、办卡）等字段，单位涉及升、元、吨、人次等。

## 这些特征在「工具调用与插件」这一环带来什么约束
成品油销售的业务数据实时性与字段复杂度，对工具调用与插件环节带来多重约束。实时交易数据要求插件调用延迟不超过2秒，否则无法同步柜台办理进度。多字段的业务文档需要工具调用时明确指定可选参数范围，比如油品品类、业务类型，避免模型生成无效参数。每日更新的盘库数据要求插件调用时需传入查询日期区间，防止返回过期库存信息。涉及会员隐私的字段，需在插件配置中开启权限校验，仅允许授权账号调用，避免数据泄露风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `functionCall` | 强制指定 | 适配成品油业务多参数的结构化调用需求，避免模型生成非预期参数 |
| `toolChoice` | 自动选择 | 适配常规业务办理的灵活调用需求，平衡参数准确性与调用效率 |
| 插件超时时间 | 1.5–2 秒 | 匹配实时交易数据的同步延迟要求，防止柜台办理超时 |
| 参数校验开关 | 开启 | 过滤无效的油品编码、业务类型参数，避免调用失败 |
| 数据时间范围限制 | 当日+前7日 | 适配每日盘库与实时交易的更新节奏，仅返回有效时间范围内的数据 |
| 权限校验配置 | 绑定企业内部账号体系 | 符合成品油业务的会员与交易数据隐私合规要求 |

## 容易做错的三处
- 调用插件时返回401状态码，原因是未正确配置企业内部账号的权限校验规则，导致FastGPT无法通过身份验证。
- 工具调用返回空结果，原因是未指定数据时间范围，插件返回了过期的盘库数据或未匹配到当日交易信息。
- 模型生成的业务参数与实际业务不符，原因是未开启`functionCall`强制模式，模型自主生成了不存在的油品品类参数。

## 怎么确认配好了
- 调用测试用的业务办理接口，传入已知的油品编码与业务类型，检查插件是否返回对应的数据。
- 查看FastGPT v4.17.0的插件调用日志，确认返回的参数与传入的配置项匹配，无无效参数。
- 模拟超时场景，检查插件是否在1.5–2秒内返回结果，未出现超时报错。
- 验证权限校验功能，使用未授权的账号调用插件，确认返回身份验证失败的提示。
