# 成品油销售的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
成品油销售的业务数据主要来自加油站POS交易系统、进销存管理系统、油品质检档案及区域价格公示平台。数据更新节奏覆盖实时（交易记录）、按小时（库存余量）、按自然日（挂牌价格）三类。单条业务文档包含交易时间、油品标号、交易单价、交易量、支付方式、服务网点ID等字段，单位涵盖升、元、元/升、笔等，不同区域的网点会附加本地优惠规则字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
首先，实时更新的库存与价格数据要求模型调用时需能实时拉取最新数据，因此配置中需支持动态上下文引入；其次，多字段且带明确单位的业务数据，要求模型需准确匹配字段与单位，避免引导内容出现标号混淆、单位错误；另外，区域化的优惠规则需按网点维度拆分知识库内容，避免跨区域规则混淆，因此上下文召回需限定对应网点的数据集范围；最后，业务办理流程的引导需严格遵循既定规则，不宜生成随意性内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 成品油业务数据包含近7天的交易记录、区域价格规则、库存明细，需覆盖足够的上下文以支撑准确引导 |
| `quoteMaxToken` | 1500–2500 token | 业务引导需引用具体的库存、价格数据，限制引用token可避免超出模型上下文承载上限 |
| `temperature` | 0.2–0.4 | 业务办理需严格匹配既定规则，不宜生成偏离实际业务的引导内容 |
| `toolChoice` | auto | 可根据查询场景自动调用工具，实时获取当前网点的库存或价格信息 |
| `AIPROXY_API_ENDPOINT` | 按FastGPT平台提供的专属接入地址填写 | 适配成品油业务的大模型调用需绑定专属节点以保障数据传输稳定 |
| `AIPROXY_API_TOKEN` | 与接入节点绑定的专属密钥 | 保障模型调用的权限安全，避免未授权访问业务数据 |

## 容易做错的三处
- 现象：工作流运行返回“上下文超出上限”报错，且模型配置页面显示参数无误。原因：未限制`maxContext`或`quoteMaxToken`的取值，导致单次调用带入的业务数据token超过模型支持上限。
- 现象：业务引导时模型提示“未查询到相关油品信息”，但知识库中已上传对应标号的油品数据。原因：`quoteMaxToken`取值过低，导致无法召回足够的库存、价格明细数据，无法支撑有效匹配。
- 现象：单次业务查询耗时过长，页面出现加载超时提示。原因：未限制`maxTokens`的生成上限，导致模型生成过长的引导文本，或调用时带入过量历史交易数据。

## 怎么确认配好了
- 上传1份包含近7天油品交易、区域价格规则的测试文档，触发业务引导流程，核对FastGPT平台的模型调用日志中带入的上下文token数是否符合配置要求。
- 模拟不同标号、不同网点的油品查询请求，核对模型返回的引导内容是否准确匹配知识库中的对应规则。
- 调整`temperature`参数的取值区间，验证生成的引导内容是否保持规则一致性，无明显偏离实际业务的表述。
- 检查`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的绑定关系，确认无权限错误或连接失败的日志记录。
