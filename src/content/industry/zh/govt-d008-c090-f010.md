# 成品油销售的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
成品油销售的业务办理流程数据主要来源于加油站标准化操作手册、POS系统流程文档、客服工单记录及上级单位合规文件。数据更新节奏分为两类：合规类文件按季度更新，日常操作流程文档按月度更新。文档按业务节点拆分，涵盖加油卡办理、开票申请、异常交易处理等模块，字段包含操作步骤、前置条件、所需证件、办理时限（单位为小时）、系统操作路径等，部分字段包含数字与单位组合的精准描述。

## 这些特征在「知识库检索与召回」这一环带来什么约束
文档中存在大量数字与单位组合的精准描述，如“办理时限2小时”“第3步插入IC卡”，要求检索需精准匹配数字、文字与单位的组合，避免因token拆分错位导致的匹配偏差。文档按业务节点分类存储，要求检索需按节点定向召回，避免跨品类或跨节点的无关结果混入。数据更新频率固定且有明确的增量节点，要求知识库同步需按业务模块增量更新，避免全量同步的资源浪费。字段中包含系统操作路径等短文本内容，要求检索需保留上下文片段，避免截断关键操作信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.82 | 匹配成品油业务中精准的步骤描述与单位信息，降低无关召回的概率，适配FastGPT v4.17.0的嵌入模型精度 |
| `limit` | 前6条 | 覆盖单个业务办理节点的全部相关文档片段，确保完整展示办理流程 |
| `searchMode` | 按业务节点分类召回 | 匹配文档按加油卡、开票、异常处理等节点划分的结构，定向召回对应内容 |
| `usingReRank` | 开启 | 修正数字与文字间的token拆分错位，解决录入无空格内容显示多余空格的问题 |
| `datasetSearchUsingExtensionQuery` | 开启 | 将用户口语化咨询（如“加油卡怎么补卡”）扩展为标准流程查询，提升匹配精度 |
| `collectionIds` | 绑定成品油业务专属知识库集合 | 隔离其他品类文档，确保召回结果仅来自目标业务数据 |

## 容易做错的三处
- 现象：检索返回的文档片段中，原本录入时无空格的数字与文字之间出现多余空格，例如“第3步”显示为“第 3 步”。原因：未启用`usingReRank`重排功能，未修正嵌入过程中的token拆分错位问题。
- 现象：检索召回了非成品油业务的文档，如行政办公类内容。原因：未配置`collectionIds`绑定专属知识库集合，混入了其他品类的文档数据。
- 现象：单次检索返回结果条数不足，无法覆盖完整的办理流程步骤。原因：`limit`取值过低，未覆盖单个业务节点的全部相关文档片段。

## 怎么确认配好了
- 上传一份包含数字与文字组合的测试文档（如“第2步插入加油卡”），发起检索，查看返回结果中是否存在多余空格。
- 查看知识库集合绑定配置，确认仅包含成品油业务相关的文档，无其他品类内容。
- 发起不同口语化咨询（如“加油卡怎么充值”“异常加油怎么处理”），核对召回结果是否匹配对应业务节点。
- 调整`similarity`阈值，验证召回结果的匹配精度是否符合业务需求。
