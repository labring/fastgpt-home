# 房建工程总承包的业务办理流程引导：多轮对话与提示词

本文基于FastGPT v4.17.0版本的配置规则编写。

## 这个品类的数据长什么样
房建工程总承包的业务数据来源于国央企内部项目管理系统、住建部门备案的施工文件、总承包合同及阶段性验收报告。数据更新节奏随项目节点推进，每周更新施工进度与材料报审记录，每月更新结算与验收台账。文档结构分为项目基础台账、流程节点清单、报审表单、验收报告四类，字段包含项目编号、标段划分、报审时间、材料规格、验收结果，单位涵盖平方米、吨、工作日等专业工程计量单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
房建工程总承包的流程节点多、专业术语密集且项目间差异明显，这些特征对多轮对话与提示词配置带来明确约束。首先，单轮对话需承载较多专业信息，过长的上下文窗口易混淆当前流程步骤，需限制历史对话的保留范围。其次，专业术语如CFG桩、静压桩等需在提示词中明确标注，避免分类模块误判流程类型。此外，不同项目的报审流程存在差异，需通过会话参数传递项目专属配置，防止跨项目流程混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定项目唯一标识 | 房建项目流程数据按项目隔离，`chatId`确保同项目对话上下文不跨项目 |
| `messages` | 保留当前流程相关的前6轮对话 | 房建业务办理节点多，过多历史对话会干扰当前流程判断，6轮可覆盖完整流程上下文 |
| `variables` | 传入项目所属标段、报审类型字段 | 房建总承包流程因标段、报审类型差异有不同规则，`variables`可传递专属配置 |
| 单次对话最大字符数 | 1500 字符 | 房建业务办理的表单填写内容较长，限制单轮输入避免上下文溢出 |
| 对话超时时间 | 900 秒 | 用户填写房建报审材料可能耗时较长，超时保留会话状态 |
| 问题分类匹配阈值 | 0.85 | 房建专业术语辨识度高，该阈值可准确区分报审、验收、结算等流程类型 |

## 容易做错的三处
- 对话返回的流程操作与用户输入的业务类型不匹配，如将材料报审请求误导向竣工验收流程。原因是提示词未加入房建专属流程分类词，或`messages`参数混入了跨项目的历史对话片段。
- 对话页面加载失败或返回异常状态码。原因是`chatId`未正确绑定项目唯一标识，导致系统无法加载对应项目的流程数据。
- 使用API开启对话后，对话历史中出现重复的用户或助手消息。原因是`messages`参数未正确过滤初始系统提示词的冗余片段，或重复调用了会话初始化接口。

## 怎么确认配好了
- 发起包含房建专业流程关键词的测试对话，核对对话历史仅保留与当前流程相关的内容。
- 传入不同项目标识的`chatId`，确认对话上下文仅关联对应项目的流程数据。
- 输入较长的业务描述，检查系统是否对输入长度进行合理限制。
- 暂停会话超过设定的超时时间后重新进入，检查会话状态是否正常保留。
