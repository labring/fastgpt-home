# 政企信息化服务的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
政企信息化服务（通信类）的数据来源包括内部业务办理规范文档、通信服务工单系统、政务服务一体化平台的办理指引。数据更新随业务流程调整同步进行，无固定周期。文档结构多为分步骤操作说明、所需材料清单、办理时限说明，字段包含办理节点名称、前置条件、所需材料、咨询渠道，单位多为“步”“个”“工作日”。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据以分步骤的办理流程为核心结构，工具调用需严格绑定当前办理节点的上下文，仅调用对应节点的参数获取工具，避免跨节点调用导致流程混乱。字段包含前置条件、所需材料等结构化内容，插件需支持结构化参数提取，无法仅依赖非结构化文本匹配，否则无法准确校验办理资格。数据更新随业务调整同步进行，工具调用的配置需支持定期同步数据源，避免调用过时的流程指引。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `toolChoice` | `auto` | 适配政企流程的动态节点调用，无需手动指定工具 |
| 参数补全触发阈值 | 当缺失2个及以上必填参数时 | 政企业务办理需明确的材料信息，避免参数不足导致调用失败 |
| 工具调用超时时间 | 30-60秒 | 政企业务办理流程的响应周期通常较长，避免因超时中断上下文 |
| 上下文保留长度 | 8000-12000 token | 政企流程文档较长，需保留足够上下文确保节点衔接 |
| 重排 | 开启 | 知识库检索的流程文档过长时，需重新排序核心节点信息，确保模型调用准确 |
| `functionCall` | 强制匹配当前节点工具 | 政企流程的节点关联性强，避免调用无关工具打乱办理节奏 |

## 容易做错的三处
- 现象为每次调用MCP工具后，模型上下文出现断层，后续回答无法关联当前办理节点。原因是配置中未开启上下文保留开关，或`toolChoice`设置为强制切换工具导致上下文重置。
- 现象为工作流调用MCP时，无法通过问答补充缺失的多参数，导致调用失败。原因是未配置参数补全触发逻辑，仅在首次调用时传递固定参数。
- 现象为知识库检索内容过长后，模型未调用重排工具对内容排序，导致核心流程节点被淹没。原因是未开启重排配置项，或重排的触发阈值设置过高。

## 怎么确认配好了
- 发起模拟业务办理请求，核对工具调用是否仅关联当前办理节点的功能，无跨节点调用。
- 传入缺失部分必填参数的办理请求，确认系统会触发参数补全的问答流程。
- 检索长度超出常规阈值的流程文档，确认系统会触发重排操作整理内容顺序。
- 测试工具调用的响应时长，确认符合业务场景的响应要求。
