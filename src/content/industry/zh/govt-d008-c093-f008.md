# 政企信息化服务的业务办理流程引导：文档解析与分块

## 这个品类的数据长什么样
政企信息化服务的业务办理文档主要来源于内部业务流程手册、政务公开办事指南、审批表单模板及线下纸质归档文件。数据更新节奏随政策调整、流程优化不定期触发，部分高频事项文档每季度同步更新。文档多为固定结构，包含办理条件、所需材料、办理步骤、咨询渠道等模块，部分跨部门协同流程文档篇幅较长，字段包含事项名称、办理时限、材料份数、收费标准等，单位多为工作日、份、元等。

## 这些特征在「文档解析与分块」这一环带来什么约束
固定章节结构要求分块需保留模块完整性，避免拆分跨办理步骤的连续内容，确保流程引导的逻辑连贯。长篇幅跨部门文档需要控制分块粒度，避免单块内容过长导致上下文溢出。字段中包含明确单位的内容需在解析时完整保留，防止后续流程引导中出现参数缺失。不定期更新的文档需配合实时解析配置，避免使用过期缓存内容。部分扫描件格式的业务文档需额外配置OCR解析流程，确保文本提取完整。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配政企业务文档的章节长度，避免单块内容过长或过短 |
| `chunkSplitter` | 按语义分段 | 保留业务流程的逻辑连贯性，符合办事指南的章节结构 |
| `customPdfParse` | 开启 | 适配政企文档中常见的扫描件PDF格式，补充OCR解析能力 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 覆盖大型跨部门流程手册的上传需求，适配政企文档的体积特征 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对长文档解析的耗时需求，避免因超时导致解析失败 |
| `chunkSettingMode` | 手动配置 | 允许针对不同类型的业务文档调整分块参数，适配多样化的政企文档结构 |

## 容易做错的三处
- 现象：PDF解析任务返回超时错误，或解析状态长时间停留在处理中。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以处理大型政企业务文档。
- 现象：上传的文件未被直接传入大模型，仍被系统默认解析为文本后发送。原因：未配置`customPdfParse`相关节点参数，未跳过默认解析流程。
- 现象：调用知识库文件集合创建API时，PDF解析参数未生效，解析结果仍为默认格式。原因：未在API请求中正确指定对应解析配置项，参数名称或取值格式不符合要求。

## 怎么确认配好了
- 上传一份典型的政企业务文档，查看解析后的文本内容是否保留了章节结构与单位信息。
- 查看解析任务的日志，确认`customPdfParse`参数已被启用，未触发默认解析流程。
- 调用知识库创建API，传入指定的PDF解析配置，验证请求参数格式与取值符合要求。
- 调整`chunkSize`参数后上传同一份文档，对比分块结果的长度变化，确认配置生效。
