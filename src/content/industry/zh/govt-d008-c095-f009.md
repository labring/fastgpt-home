# 新能源开发的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
新能源开发的业务办理数据主要来自项目立项审批、电网接入批复、用地预审、环评备案等官方审批文件，以及项目现场勘测的技术台账。数据更新随审批节点推进，每个审批环节完成后同步更新。文档多为结构化表单与非结构化技术报告混合，包含项目编号、装机容量（单位MW）、用地面积（公顷）、并网计划时间等固定字段，部分审批文件存在多页附件嵌套的结构。

## 这些特征在「模型接入与配置」这一环带来什么约束
新能源开发业务的混合结构化与非结构化多附件数据，会大幅占用模型上下文token配额，要求模型接入环节调整上下文相关参数上限。数据中包含带固定单位的技术字段，需要模型严格匹配单位格式输出，避免参数解析错误。审批节点的阶段性更新特性，要求配置的数据源同步逻辑匹配项目推进节奏，确保调用的审批数据为当前最新版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配新能源开发项目审批文件的多附件上下文长度，避免截断关键审批参数 |
| `maxTokens` | 2000–3000 token | 适配业务办理流程引导的回复长度，确保能完整输出审批步骤说明 |
| `quoteMaxToken` | 3000–4000 token | 覆盖新能源项目技术台账与审批文件的核心引用片段长度 |
| `temperature` | 0.1–0.3 | 降低随机输出概率，确保固定单位（如MW、公顷）的格式一致性 |
| `toolChoice` | auto | 按需触发工具调用，补充项目审批节点的实时状态信息 |
| `AIPROXY_API_TOKEN` | 按平台生成的有效令牌 | 匹配国内大模型的调用认证要求，适配OneAPI中转场景 |

## 容易做错的三处
- 现象：调用国内大模型时显示令牌无效。原因：未正确配置`AIPROXY_API_TOKEN`，或OneAPI中转接口的令牌权限未开放对应大模型调用。
- 现象：上下文被截断，关键审批参数（如装机容量、用地面积）丢失。原因：未调整`maxContext`参数至适配多附件文档的长度区间。
- 现象：回复中出现单位转换错误（如将MW写成kW）。原因：`temperature`参数取值过高，导致模型随机篡改固定字段格式。

## 怎么确认配好了

- 上传单份新能源项目审批文件，测试模型回复是否包含完整的审批步骤说明，无截断情况。
- 输入包含装机容量、用地面积等带单位字段的查询，确认回复中单位格式与源数据一致。
- 更换OneAPI中转的令牌与接口地址，验证调用是否正常无报错。
- 触发工具调用测试，确认是否能按需返回项目最新审批节点信息。
