# 有色金属冶炼的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
有色金属冶炼的业务数据主要来源于企业内部生产执行系统（MES）、物料管理系统（WMS）以及质检实验室系统。数据更新节奏分为两类：实时生产参数每2-10分钟刷新一次，批次类质检报告随冶炼批次完成生成，设备运维日志按操作记录实时生成。数据以结构化表格形式存储，包含固定字段：冶炼批次ID、原料配比（单位千克/炉）、熔炼温度（单位摄氏度）、产出金属锭重量（单位千克）、设备运行时长（单位小时），无非结构化冗余字段。

## 这些特征在「工作流编排」这一环带来什么约束
不同数据源的更新节奏差异要求工作流节点配置差异化触发规则，实时生产数据节点需设置短轮询周期，批次质检数据节点需绑定批次完成事件触发。结构化数据的固定字段要求工作流中变量提取规则必须匹配预设字段名，避免变量匹配失败。单批次处理的数据量存在上限，工作流需拆分处理单元，防止单次执行超时。跨系统的数据格式存在细微差异，工作流编排时需加入格式转换步骤，统一字段单位与类型。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发间隔 | 2-10分钟 | 匹配实时生产数据的刷新节奏 |
| `variables`提取规则 | 匹配预设的冶炼批次ID、原料配比字段 | 适配结构化数据的固定字段结构 |
| 批量处理单元大小 | 50条/次 | 避免单次执行超出系统资源限制 |
| 调试节点显示开关 | 开启 | 适配FastGPT v4.17.0版本的调试功能要求 |
| `nodeId`映射规则 | 保留导入工作流的原始节点ID | 确保嵌套工作流的节点调用逻辑正确 |

## 容易做错的三处
- 现象：工作流执行后全局Number类型计数器未按预期+1，变量更新后无变化。原因：未正确配置`variables`的更新触发逻辑，仅调用了变量读取节点未绑定更新操作。
- 现象：FastGPT v4.17.0版本工作流调试面板中，代码运行节点无显示内容。原因：未开启调试节点显示开关，或工作流未保存最新配置。
- 现象：嵌套调用的子工作流输出符合预期，但中间步骤的字段值与父工作流传入的参数不一致。原因：子工作流的`variables`映射规则未正确绑定父工作流的输出字段，导致参数传递错位。

## 怎么确认配好了
- 手动触发一次工作流，查看日志中提取的变量结果是否与数据源的字段完全匹配。
- 调整触发间隔为不同区间，验证工作流是否按设定节奏触发对应数据源的更新数据。
- 执行嵌套工作流调用，核对子工作流的输入参数是否与父工作流的输出字段一致。
- 开启调试模式，确认代码运行节点的执行日志正常显示在调试面板中。
