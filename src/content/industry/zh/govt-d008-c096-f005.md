# 有色金属冶炼的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
有色金属冶炼的业务办理数据主要来自生产现场的PLC控制系统、制造执行系统（MES）以及质检部门的电子检测报告。数据更新节奏分为实时采集的设备运行参数、每小时同步的物料流转数据、每日更新的成品质检结果。文档结构以单条业务办理记录为单位，包含冶炼炉号、当前工序、物料投入量、炉内温度、能耗数据、当前进度节点等字段，部分记录附带工序异常告警标识。

## 这些特征在「工具调用与插件」这一环带来什么约束
有色金属冶炼的业务数据特征对工具调用与插件配置带来多重约束。实时采集的设备运行参数要求插件接口响应延迟控制在合理范围，否则会导致业务办理流程引导卡顿。多字段的结构化数据格式，要求插件的输入输出参数定义需要严格匹配冶炼场景的字段名与单位，否则会出现数据解析错误。每日更新的质检数据需要插件支持定时拉取，避免全量实时同步占用过多系统资源。业务流程节点依赖当前工序状态，插件需要准确读取进度字段触发引导逻辑，字段缺失或格式异常会直接导致引导中断。

本配置适用于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 插件超时时间 | 600 秒 | 匹配冶炼业务实时流程的响应要求，避免引导流程卡顿 |
| `toolChoice` | 自动选择 | 适配多工具并行调用的场景，无需手动指定单个工具 |
| `functionCall` | 开启 | 支持结构化参数传递，匹配冶炼数据的多字段格式要求 |
| 参数校验开关 | 开启 | 校验输入字段的单位与格式，避免数据解析错误 |
| 循环执行阈值 | 前3次 | 适配冶炼流程的异常重试逻辑，避免无效循环占用资源 |
| 定时拉取间隔 | 1 小时 | 匹配每日质检数据的更新节奏，平衡实时性与系统资源占用 |

## 容易做错的三处
- 现象：自定义插件添加到工作流后，输入输出参数栏无内容显示。原因：未按照冶炼场景的结构化字段格式定义插件参数，导致系统无法解析参数结构。
- 现象：调用聊天接口后响应延迟超出预期。原因：插件超时时间设置不合理，或定时拉取间隔配置不当，导致大量数据同步占用接口资源。
- 现象：循环执行插件后未按预期遍历数组元素。原因：循环体的数组输入格式不符合FastGPT要求，未正确匹配冶炼业务的物料列表数据结构。

## 怎么确认配好了
- 手动触发插件调用，查看返回结果的字段是否与冶炼业务的预设参数完全匹配。
- 模拟格式异常的输入数据，验证参数校验开关是否能拦截错误输入。
- 运行循环任务，确认插件会按预设规则遍历输入的数组元素。
- 查看接口日志，确认插件调用的响应时间符合配置的超时要求。
