# 有色金属冶炼的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
数据主要来自冶炼生产执行系统、物料管理系统、质检检测设备输出文件，更新节奏为每班或每日。文档以结构化表格、工业数据库记录为主，包含冶炼批次号、工艺温度、物料重量、质检指标值、操作时间戳等字段，字段单位多为摄氏度、吨、小时、毫克每升等，部分配套工艺文档为带有固定格式的PDF文件，内容围绕单批次冶炼的全流程操作规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 有色金属冶炼的工艺文档和批次数据关联后，单批次上下文长度多在该区间内，适配多数主流模型的上下文窗口 |
| `maxTokens` | `2000–3000 token` | 业务办理流程引导的回复需包含完整步骤，同时避免过长导致接口超时 |
| `temperature` | `0.2–0.4` | 流程引导需保持严谨性，避免生成随机化的步骤偏差 |
| `quoteMaxToken` | `4000 token` | 需保留足够的质检数据和工艺参数作为引用依据，确保流程引导的准确性 |
| `AIPROXY_API_ENDPOINT` | 填写对应模型代理的官方接入地址 | 确保FastGPT与模型代理平台建立正确的调用链路 |
| `AIPROXY_API_TOKEN` | 填写申请到的有效代理密钥 | 完成身份验证，通过模型接入的校验环节 |

## 容易做错的三处
- 现象为在第三方代理平台测试模型正常，但在FastGPT中新建应用后测试报错，原因是未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，导致FastGPT无法与代理平台完成有效身份校验。
- 现象为知识库查询时提示“无可匹配内容”或类似截断报错，原因是配置的嵌入模型与实际调用的模型不匹配，或未正确配置模型接入参数，导致无法正确解析冶炼数据的字段信息。
- 现象为TTS模型测试时出现“KokoroModel object has no attribute mode”类报错，原因是未针对TTS类模型调整`toolChoice`参数，或未在模型接入时指定正确的模型类型，导致框架无法识别对应模型的调用逻辑。

## 怎么确认配好了
- 进入FastGPT的模型管理页面，查看已配置的模型接入信息，核对`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`是否与代理平台提供的信息一致。
- 发起一次单条冶炼批次数据的流程引导测试，查看返回结果是否包含完整的办理步骤，且未出现参数解析错误。
- 上传一份标准的冶炼工艺文档，测试知识库召回与流程引导的联动效果，确认引用内容与实际数据匹配。
- 调整`temperature`参数并发起多次测试，观察回复内容的一致性，确认参数配置生效。
