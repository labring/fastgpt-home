# 核电运营的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
核电运营的业务办理数据来源为核电运行管理系统、设备运维台账、业务审批平台，更新节奏为实时或分钟级同步。单条数据包含业务编号、操作人工号、办理时间、审批节点、关联设备ID、当前状态字段，单位涵盖次、台、小时、分钟等。数据格式为结构化JSON，部分字段需遵循核电行业的标准化编码规则。

## 这些特征在「工具调用与插件」这一环带来什么约束
实时或分钟级更新的数据要求工具调用的响应时长需控制在合理范围内，避免数据滞后影响业务引导的准确性。结构化的固定字段要求插件需预设核电业务的标准解析规则，无法直接适配通用业务字段模板。多节点的线性业务流程要求工具调用需按流程顺序触发，不能跨节点调用。标准化编码规则要求插件在调用外部接口时需自动补全字段格式，避免因编码不匹配导致调用失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配核电业务流程的动态节点变化，自动触发对应工具 |
| `functionCall` | 允许多轮连续调用 | 匹配多步骤业务办理的连贯引导需求 |
| 超时设置 | 600 秒 | 覆盖核电业务流程的平均处理时长 |
| 插件触发频率 | 每 30 秒 1 次 | 匹配数据分钟级的更新节奏 |
| 上下文窗口 | 8000–12000 token | 容纳完整的业务记录与流程节点信息 |
| 插件名称同步 | 按代码标识填写显示名 | 避免管理界面与调用端名称不一致 |

## 容易做错的三处
- 现象：调用`functionCall`时返回参数解析失败，日志显示字段格式不匹配。原因：未遵循核电行业的字段编码规则，传入的设备ID或业务编号未添加标准化前缀。
- 现象：插件管理列表页与系统插件内显示名称不一致。原因：配置插件时仅填写了代码标识，未同步设置显示名称。
- 现象：业务引导未调用知识库返回历史流程数据。原因：未开启`toolChoice`的自动调用开关，仅使用基础问答逻辑生成引导内容。

## 怎么确认配好了
- 发起模拟业务办理请求，查看FastGPT v4.17.0的工具调用日志，确认存在`toolChoice`参数的自动调用记录。
- 提交包含关联设备ID的测试数据，检查插件返回结果是否包含标准化的业务字段与状态信息。
- 进入插件管理页面，确认显示名称与代码标识完全一致。
- 触发超时测试场景，确认调用响应时长符合配置的600秒阈值。
