# 核电运营的业务办理流程引导：表单与交互

## 这个品类的数据长什么样
核电运营的业务办理数据主要来自内部EAM设备管理系统、OA审批系统及现场巡检终端，更新节奏随业务办理节点实时触发，每次提交或审批完成即更新数据。单份业务单据文档包含单据ID、机组编号、作业类型、申请人、审批层级、附件列表、提交时间戳等字段，其中机组编号采用固定格式，附件大小以MB为单位，提交时间戳采用ISO 8601标准格式。本页适配 FastGPT v4.17.0 版本。

## 这些特征在「表单与交互」这一环带来什么约束
由于数据来源涉及多套内部系统，字段格式有严格规范，表单交互需预设针对性校验规则，避免无效数据录入。实时更新的特性要求表单提交后同步触发系统状态更新，不能存在延迟。多审批层级的业务逻辑要求表单需动态展示当前审批节点，限制用户跳过层级提交。附件的固定大小范围要求交互环节限制上传文件的尺寸，防止超出系统存储或传输上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 表单字段校验规则 | 匹配`^[1-2]#[A-Z0-9]{3}$`格式 | 适配核电运营机组编号的固定命名规则，确保字段合法性 |
| 上传附件限制 | 最大 100 MB，单文件上限 50 MB | 适配核电业务附件（如检修报告、辐射检测报告）的常见存储大小 |
| `formInput` 预设值 | 自动带入当前登录用户的工号、所属班组 | 减少手动输入步骤，提升业务办理效率 |
| `userSelect` 可选范围 | 仅当前审批层级的审批人员 | 符合核电审批的层级管控要求，避免选错审批对象 |
| 提交前确认弹窗 | 显示单据核心信息（作业类型、机组编号） | 防止误提交重要业务单据，降低操作失误概率 |

## 容易做错的三处
- 现象：上传核电业务附件时触发通用网络错误提示，未明确说明附件大小超限。原因：未配置专属的附件大小校验报错文案，复用了通用错误提示逻辑。
- 现象：表单模型选择下拉框仅显示通用大模型，无法选择已配置的重排模型。原因：未在细分场景配置中开启核电运营专属模型的可见权限，导致配置的重排模型未被加载。
- 现象：工具调用环节未弹出用户确认弹窗，直接执行审批提交操作。原因：未在`formInput`环节配置调用前的确认步骤，跳过了用户校验环节。

## 怎么确认配好了
- 录入符合`^[1-2]#[A-Z0-9]{3}$`格式的机组编号，检查是否通过字段校验。
- 上传一个大小为120 MB的测试文件，检查是否触发附件大小超限的专属报错提示。
- 查看`userSelect`下拉框，确认仅显示当前审批层级的人员名单。
- 点击提交按钮，检查是否弹出包含作业类型和机组编号的确认弹窗。
