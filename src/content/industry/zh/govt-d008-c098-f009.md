# 民航机场的业务办理流程引导：模型接入与配置
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
民航机场业务办理流程引导的数据源主要来自机场内部运行系统、航司协同平台及公共出行服务数据库。数据分为两类：航班动态类数据实时同步，业务流程规则类数据每日更新。文档结构包含结构化字段与非结构化引导话术，结构化字段涵盖航班号、起降时刻、航站楼、柜台编号、安检通道、登机口等，非结构化内容为各环节的标准引导话术。字段单位统一为：时刻采用24小时制，编号为纯数字或字母组合，时长以分钟为单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
航班动态类数据的实时更新要求模型接入的数据源同步延迟控制在合理区间，否则引导信息会滞后于实际业务状态。结构化字段多且单位规范，要求模型配置支持精准的结构化数据抽取与匹配，避免生成错误的流程指引。业务规则每日更新的节奏，要求知识库同步周期与之一致，防止使用过期的流程数据。多源系统数据的协同需求，要求配置统一的调用入口，避免不同环节的业务数据出现割裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 机场业务流程包含多环节的航班、柜台、通道信息，需保留足够上下文确保引导逻辑连贯 |
| `maxTokens` | 4000 token | 单条业务引导的输出需控制长度，避免超出界面展示范围，同时适配实时数据的处理上限 |
| `quoteMaxToken` | 2000–3000 字符 | 需引用的航班数据、柜台位置信息长度有限，确保引用内容完整且不挤占主上下文空间 |
| `temperature` | 0.1–0.3 | 业务办理引导需准确严谨，避免生成误导性的流程信息 |
| `AIPROXY_API_ENDPOINT` | 机场专属内部代理地址 | 确保敏感业务信息传输的安全性，避免数据泄露 |
| `AIPROXY_API_TOKEN` | 机场运维生成的专属令牌 | 限制未授权的模型调用，保障系统运行安全 |

## 容易做错的三处
- 上传部分航班登机牌、安检凭证图片时返回报错，部分可正常识别。原因：未适配`vision`参数的图片处理阈值，不同分辨率的图片消耗的token与处理逻辑未做区分。
- 配置了较大的`maxTokens`参数后，仍出现图片上传报错。原因：未区分文本token与图片token的消耗上限，图片处理的token占用未被单独限制。
- 生成的业务引导与实时航班数据不符。原因：知识库同步周期未与航班数据的更新节奏对齐，使用了过期的流程规则。

## 怎么确认配好了
- 触发一次值机流程的引导请求，核对返回内容中包含的航班信息与实时系统数据是否一致，调整数据源同步配置直至匹配。
- 上传不同分辨率的业务凭证图片，确认识别结果无报错且字段提取完整，调整`vision`相关配置直至所有测试图片均可正常处理。
- 测试不同航班时段的引导请求，核对生成的流程步骤与当前机场的业务规则一致，调整知识库同步周期直至符合更新节奏。
- 查看模型调用日志，确认`AIPROXY_API_TOKEN`的调用记录均为授权请求，无未授权的访问记录。
