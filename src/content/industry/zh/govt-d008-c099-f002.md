# 油气勘探开发的业务办理流程引导：向量模型与索引

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
油气勘探开发的数据主要来自钻井作业日志、三维地震勘探报告、试采工况记录、储量评估文档及内部审批流程单据。数据更新节奏随项目阶段变化，预探阶段批量生成新文档，开发阶段按单井或月度更新。单份文档通常包含井号、作业深度、地层压力、施工步骤、审批节点等字段，单位涵盖米、兆帕、立方米等专业计量标准，部分文档包含多页图表与参数表格。

## 这些特征在「向量模型与索引」这一环带来什么约束
油气勘探开发的专业文档包含长段落施工流程、带参数的作业表格与结构化字段，分块时需避免割裂井号、作业深度等关联参数，对分块逻辑提出了精准边界的要求。数据更新节奏随项目阶段波动，预探阶段批量新增文档，开发阶段单井增量更新，因此索引需支持按需触发的增量同步。文档内的专业术语与计量单位较多，向量模型需适配行业专属语义的嵌入效果，避免专业语义丢失。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配长段落施工流程与带参数的作业表格，避免割裂关联参数 |
| 重叠长度 | 100–150 字符 | 保留分块间的专业上下文衔接，避免施工步骤被截断 |
| `defaultToken` | 2000 token | 适配长文档的向量嵌入长度，覆盖专业段落的完整语义 |
| `maxToken` | 4096 token | 适配向量嵌入的总长度限制，避免超出模型输入上限 |
| 相似度阈值 | 0.72–0.80 | 匹配油气勘探开发的专业术语语义相似度区间，过滤低相关结果 |
| 单次搜索上限 | 前 8 条 | 适配单份勘探文档的核心节点数量，避免冗余结果干扰流程引导 |
| 最大上下文 | 6000 字符 | 匹配业务办理流程的多步骤关联检索需求，确保引导逻辑连贯 |

## 容易做错的三处
- 界面提示「该令牌无权使用模型」，日志显示embedding模型调用失败。未配置对应模型的专属`defaultToken`，或使用了未授权的第三方令牌。
- 添加了embedding渠道后，检索时提示无可用渠道。未将embedding模型的调用地址与端口配置为可访问状态，或渠道名称与FastGPT内的配置不匹配。
- 检索结果缺失作业深度、地层压力等关联参数。分块长度设置过小，割裂了专业参数与对应上下文的关联。

## 怎么确认配好了
- 上传一份单井钻井日志文档，执行流程引导测试，核对检索结果是否包含对应井号与作业步骤。
- 查看向量索引的同步日志，确认新增文档的索引任务已成功执行。
- 检查embedding模型的调用日志，确认无令牌权限错误或渠道不可用提示。
- 调整分块长度参数，对比检索结果的上下文完整性，确认符合业务需求。
