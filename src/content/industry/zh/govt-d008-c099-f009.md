# 油气勘探开发的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
油气勘探开发的业务办理数据主要来源于钻井施工日志、油气藏分析报告、试采流程记录、项目审批台账等。数据更新节奏随现场施工进度调整，新井投产、流程迭代时会批量更新。单份业务文档通常包含井位坐标、地层物性参数、施工步骤清单、审批节点信息等字段，字段带有明确单位，如孔隙度（%）、井深（米）、渗透率（毫达西），部分流程类文档还会标注办理节点的时限要求。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「模型接入与配置」这一环带来什么约束
油气勘探开发的专业字段与单位要求模型具备领域术语识别能力，避免参数解析错误。长文档如完整钻井日志可能包含数千字符的步骤描述，对模型的上下文承载能力提出要求。数据更新无固定周期，需支持按需触发的向量库同步配置，避免旧数据影响流程引导准确性。流程类文档的多节点审批逻辑，要求模型能够准确匹配当前办理节点与后续步骤的关联关系，需在配置中明确上下文的召回范围，防止遗漏关键流程节点。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配单份完整钻井日志或流程台账的总长度，避免截断关键审批节点信息 |
| `maxTokens` | `2000–3000 token` | 控制单轮交互的输出长度，确保流程步骤的完整展示不溢出界面 |
| `quoteMaxToken` | `1500 字符` | 限定召回的业务文档片段长度，匹配勘探数据中单段流程说明的常规篇幅 |
| `temperature` | `0.1–0.3` | 保持流程引导的准确性，避免专业术语被随机改写 |
| `toolChoice` | `auto` | 根据用户输入自动选择是否调用流程检索工具，适配不同业务办理场景的需求 |
| `AIPROXY_API_ENDPOINT` | 内网部署的FastGPT代理地址 | 适配内网部署的场景，确保数据传输安全 |

## 容易做错的三处
- 现象：Docker部署后导入勘探数据时出现分段异常，召回的文档片段不完整。原因：未调整上下文相关参数的取值，默认分段长度未适配长文档的专业字段结构。
- 现象：在Config.json中配置模型时，未正确设置非流式返回逻辑，导致交互出现流式返回的乱序内容。原因：未按照官方文档要求调整对应参数的配置项，混淆了流式与非流式的触发规则。
- 现象：内网部署时调用模型返回504超时错误，无法完成流程引导。原因：`AIPROXY_API_ENDPOINT`配置错误，未指向正确的内网代理地址，导致接口调用失败。

## 怎么确认配好了
- 上传一份标准钻井日志文档，触发流程引导查询，核对召回的文档片段是否包含完整的施工步骤与参数信息。
- 发起多轮交互，确认模型返回的流程步骤无专业术语错误，且符合业务逻辑。
- 在内网环境下测试模型调用，确认无超时报错，接口返回正常。
- 调整`temperature`参数至0.2，验证生成的引导内容是否保持专业严谨，无随机改写情况。
