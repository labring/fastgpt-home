# 油气勘探开发的业务办理流程引导：知识库检索与召回
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
油气勘探开发的业务数据主要来源于钻井日志、三维地震勘探报告、试采分析文档、油田开发方案等。数据更新节奏因类型而异：日常运维的钻井日志按每日更新，阶段性勘探报告在勘探周期内完成更新，长期开发方案按季度修订。文档结构多包含井号、深度、孔隙度、渗透率等标准化字段，部分专业文档附带图表与采样表格，单位涵盖米、毫达西（mD）、百分比等专业计量标准，单份大型勘探报告的文本长度可达数万字符。

## 这些特征在「知识库检索与召回」这一环带来什么约束
专业字段与单位的存在要求检索时需匹配参数与单位的关联关系，避免无关参数的误召回。长文本类文档会导致单块向量嵌入的上下文覆盖范围有限，需调整检索的上下文匹配逻辑。多区块隔离的业务数据，要求检索时按油田区块绑定数据集，防止跨区块的无关内容被召回。不同更新节奏的文档，也要求向量库同步周期与数据更新节奏对齐，避免检索到过期的勘探结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | 油气勘探文档专业度高，需过滤低相关结果，该区间可平衡召回精度与覆盖范围 |
| `limit` | 前8–12条 | 单份勘探文档内容量大，过多结果会超出上下文窗口，该数量兼顾召回覆盖与上下文长度 |
| `searchMode` | 语义检索+关键词混合 | 油气文档既有专业语义关联，又有明确的井号、参数等关键词，混合模式提升召回准确性 |
| `usingReRank` | 开启 | 长且专业的文档容易出现语义相近但不匹配的结果，重排可优化结果排序精度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 勘探查询常包含缩略术语（如“孔渗”指代孔隙度与渗透率），扩展查询可覆盖更多术语变体 |
| `collectionIds` | 按油田区块配置 | 油气勘探数据按区块隔离，绑定对应区块的collectionIds可避免跨区块的无关召回 |

## 容易做错的三处
- 现象：返回结果未携带文档溯源信息，或溯源字段为空。原因：未开启知识库的文档溯源配置，或检索时未启用关联文档元数据的召回逻辑。
- 现象：检索结果中未包含原文档内的图片内容。原因：默认向量库仅对文本内容生成嵌入，未配置图片转文本或图片关联的检索逻辑，且未在生成环节添加图片引用处理。
- 现象：指定appId调用/api/v1/chat/completions接口时，无法关联到上传的知识库内容。原因：未将目标数据集的collectionIds绑定到对应appId，或接口请求参数中未正确传递dataset相关配置。

## 怎么确认配好了
- 发起包含专业术语的查询（如“XX井的孔隙度参数”），核对返回结果的召回条数是否符合`limit`配置的区间。
- 查看返回结果的元数据字段，确认是否包含文档名称、井号等溯源信息。
- 检查接口请求参数，确认`collectionIds`已正确绑定目标油气勘探数据集，且`similarity`取值在预设区间内。
- 触发包含缩略术语的查询（如“XX区块的孔渗数据”），确认扩展查询是否覆盖了相关变体术语，召回结果是否匹配业务需求。
