# 油田工程服务的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
油田工程服务的业务办理相关数据主要来源于工程施工日志、设备运维记录、业务审批单、现场踏勘报告四类核心文档。数据更新节奏分为两类，单次施工项目的归档文档在项目验收后批量更新，日常运维的巡检记录按天同步。单份文档的结构包含作业区域编号、施工工序步骤、审批节点流转、责任班组、设备运行参数等字段，单位涵盖小时、立方米、兆帕等工程专用单位，部分长文档会包含多页的工序细节描述。

## 这些特征在「向量模型与索引」这一环带来什么约束
上述数据特征对向量模型与索引环节带来三点约束。第一，文档包含大量石油石化专业术语与长文本工序描述，要求向量模型适配行业语料，避免专业语义丢失。第二，数据更新节奏存在批量与实时两类，索引需支持增量同步与批量重建两种模式，保障新旧数据的一致性。第三，核心字段包含作业区域、审批节点等关联信息，向量分块需保留字段间的上下文关联，避免检索时丢失业务逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配单份工序描述的平均长度，保留完整业务逻辑 |
| 重叠长度 | 100–150 字符 | 衔接相邻分块的上下文，避免工序步骤被截断 |
| 相似度阈值 | 0.75–0.85 | 过滤无关的非业务类检索结果，保障核心流程匹配精度 |
| 单次搜索上限 | 前 20 条 | 适配业务办理流程的节点数量，避免返回过多冗余结果 |
| 最大上下文 | 4000 token | 符合油田工程文档的平均长度，满足检索时的上下文召回需求 |
| `defaultToken` | 按实测标定 | 适配当前硬件与业务数据的token消耗上限 |

## 容易做错的三处
- 界面弹出报错提示“该令牌无权使用模型”，原因是未配置适配石油石化专业场景的embedding模型，或调用密钥未绑定对应模型的使用权限。
- 知识库搜索响应超过预设阈值，原因是分块长度设置过大且单次搜索上限过高，导致向量匹配计算量超出硬件负载。
- 检索结果未包含最新提交的业务审批单，原因是未开启增量索引更新，导致新增的业务数据未同步到向量库。

## 怎么确认配好了
- 进入FastGPT v4.17.0的向量模型配置界面，查看已选择的embedding模型是否标注支持专业行业语料。
- 上传一份典型的油田工程施工审批单，执行检索测试，核对返回结果的字段是否包含作业区域、审批节点等核心信息。
- 查看索引更新日志，确认新增的业务办理文档是否按设定的更新节奏完成同步。
- 调整相似度阈值与单次搜索上限，验证检索结果的数量与相关性是否匹配业务办理的实际需求。
