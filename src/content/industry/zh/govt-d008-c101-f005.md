# 港口航运的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
港口航运业务办理数据主要来源于港务局EDI系统、船舶调度平台及线下业务受理系统的结构化台账。数据更新节奏为单业务办结后实时同步，批量数据每日更新。文档结构以业务类型为一级分类，包含业务编码、办理环节序列、所需材料清单、办理时限、受理渠道等字段。字段多为枚举类型或结构化数组，办理时限统一以工作日为单位，材料清单包含材料名称、提交形式、份数要求等细分项。

## 这些特征在「工具调用与插件」这一环带来什么约束
港口航运业务办理数据的结构化枚举字段要求工具调用时必须传入符合规范的枚举值，否则无法返回有效业务信息。实时更新的业务数据要求插件配置实时拉取逻辑，避免返回过期的办理节点或材料要求。多字段嵌套的文档结构要求工具调用的参数解析逻辑支持数组类型的材料清单字段，需按层级提取所需内容。统一的单位规范要求插件在返回结果时自动将办理时限转换为用户易懂的表述，避免直接输出纯数字无单位的内容。业务编码的唯一性要求工具调用时需绑定唯一业务标识，确保返回数据与用户咨询的业务完全匹配。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 港口航运业务类型多样，自动选择工具可适配不同业务的办理流程查询需求 |
| `functionCall` | `{"name":"get_port_business_info","parameters":{"business_code":""}}` | 需绑定港口业务的唯一标识参数，确保返回数据精准匹配咨询内容 |
| 插件缓存时长 | 30 分钟 | 港口业务数据实时性要求较高，30分钟缓存可平衡响应速度与数据新鲜度 |
| HTTP插件超时时间 | 15 秒 | 港务局接口响应通常在10秒以内，15秒可覆盖正常调用的延迟波动 |
| 最大上下文长度 | 8000 token | 港口业务数据字段较多，8000 token可完整承载业务信息 |
| 参数校验开关 | 开启 | 港口业务字段多为枚举类型，校验可过滤无效参数输入，避免返回空结果 |

## 容易做错的三处
- 调用港务局业务接口时返回502状态码。未配置正确的代理地址或接口域名未加入白名单，导致请求被拦截。
- 工具调用弹窗中仅显示部分可选模型。未将港口航运业务专用模型添加至可用模型列表，或模型权限未正确绑定。
- 返回的业务办理流程节点缺失。传入的业务编码不符合港务局系统的枚举规范，导致接口无法匹配到对应业务数据。

## 怎么确认配好了
- 发起一次携带真实业务编码的工具调用，检查返回结果是否包含完整的办理环节与材料清单。
- 查看插件运行日志，确认请求参数与配置的参数规则完全匹配，无无效字段。
- 模拟业务办结后的实时数据更新，检查插件是否能拉取到最新的办理状态。
- 切换不同的业务类型，确认工具调用能正确适配不同的枚举字段要求。
