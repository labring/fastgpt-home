# 港口航运的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
港口航运业务的数据主要来自码头作业管理系统、船公司调度平台、海关通关申报系统及泊位调度日志。数据更新节奏为实时或每15分钟同步一次，单条业务数据包含船名、航次编号、泊位号、货物类型、通关单号、作业起始时间、预计完成时长等字段，字段单位涵盖吨、小时、航次号、泊位编号等，部分文档需关联多环节的历史作业记录。本文档基于FastGPT v4.17.0版本整理。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时更新的港口业务数据要求模型调用的上下文窗口需适配多环节历史数据的长度，避免截断关键信息。多字段的业务文档需要模型严格匹配作业流程规则，因此对生成的准确性要求较高。部分业务场景需结合集装箱照片、泊位作业视频等多模态信息完成引导，需支持多模态模型接入。同时，流程引导需自动调用船期查询、通关状态查询等内部工具，无法仅依赖模型内置知识。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 港口航运业务常需识别集装箱照片、泊位作业视频等多模态信息，完成货物状态、作业场景的识别 |
| `maxContext` | 8000–12000 token | 需关联船期、通关、泊位调度等多环节历史数据，避免上下文截断丢失关键业务信息 |
| `toolChoice` | auto | 需根据用户查询自动调用船期查询、通关状态查询等内置工具，无需强制指定工具类型 |
| `temperature` | 0.2–0.4 | 业务办理引导需准确匹配流程规则，避免生成模糊或偏离规范的指引内容 |
| `quoteMaxToken` | 2000–3000 字符 | 需引用港口作业日志、海关通关文档等长文本内容，确保引用的业务信息完整 |
| `AIPROXY_API_TOKEN` | 按平台分配的专属令牌 | 用于模型调用的身份验证，确保调用权限符合港口业务的合规要求 |

## 容易做错的三处
- 现象：发起业务查询后，未显示工具调用的中间执行步骤。原因：未将`toolChoice`配置为auto或未绑定对应工具，导致模型未触发工具调用流程。
- 现象：配置`AIPROXY_API_TOKEN`后，页面弹出红色数字报错。原因：令牌绑定的域名与`AIPROXY_API_ENDPOINT`配置的地址不匹配，或令牌已超出有效期限。
- 现象：上传集装箱照片后，模型未识别图片中的箱号、封号等信息。原因：未开启`vision`配置项，或上传的图片格式不符合平台支持的类型要求。

## 怎么确认配好了
- 发起包含船舶泊位查询的测试请求，查看模型是否自动调用对应工具获取实时业务数据。
- 上传一张集装箱外观照片，确认模型能提取照片中的关键标识信息。
- 输入包含多段历史船期信息的查询，确认模型未截断上下文内容，能完整关联历史数据。
- 检查`AIPROXY_API_ENDPOINT`的配置地址与令牌的绑定地址一致，确保无连接报错。
