# 炼化生产的业务办理流程引导：HTTP 接口与外部系统

## 这个品类的数据长什么样
炼化生产的业务办理数据来源为装置DCS控制系统、生产调度台账、业务工单系统。实时运行参数每10分钟同步更新，物料消耗、工单办理数据每日更新。数据文档采用结构化字段包，包含装置编码、物料类型、办理节点ID、当前进度、操作人标识、完成时间戳，单位统一使用炼化行业标准的吨、立方米、小时等，无额外自定义单位字段。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
实时运行参数每10分钟更新的特性，要求接口轮询间隔不得超过10分钟，否则无法为业务办理提供最新的进度参考。工单与物料数据每日更新的节奏，适配每日定时批量拉取接口的调用方式。数据字段包含装置编码、物料类型等专属标识，要求接口请求必须携带对应参数才能精准返回匹配的业务办理数据。炼化行业统一的单位体系，要求接口返回的数值字段需附带标准单位，避免跨系统转换误差。同时业务办理流程的节点状态需实时同步，接口需支持按节点ID查询进度的能力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer ${企业专属API密钥}` | 炼化生产外部系统通常要求企业级密钥鉴权，防止未授权访问 |
| 请求超时时间 | `30–60 秒` | 炼化数据接口通常存在一定延迟，过长超时会阻塞业务流程，过短会导致正常请求失败 |
| `variables` | 绑定装置ID、工单ID为全局变量 | 需精准匹配对应炼化装置的业务办理数据，避免返回无关结果 |
| `responseData` | 提取进度字段、完成时间戳 | 业务办理流程引导仅需核心状态数据，无需冗余字段降低传输负担 |
| 轮询间隔 | `8–12 分钟` | 匹配实时参数的更新节奏，避免过于频繁消耗外部系统资源 |

以上配置项基于FastGPT v4.17.0版本设计。

## 容易做错的三处
- 现象为调用接口后业务引导文字输出延迟超过10秒，流程卡顿。原因是轮询间隔设置过短，频繁调用触发外部系统接口限流。
- 现象为接口返回的业务节点数据为空。原因是未在请求中携带装置ID或工单ID参数，无法匹配对应炼化业务数据。
- 现象为接口调用返回403状态码。原因是`Authorization`参数未携带合法的企业密钥，未通过外部系统鉴权。

## 怎么确认配好了
- 调用配置后的接口，检查返回的`responseData`中是否包含业务办理的进度字段与装置编码。
- 调用接口10分钟后再次请求，检查返回的完成时间戳是否更新，匹配数据更新节奏。
- 更换合法的企业密钥，检查`Authorization`参数是否能正常通过鉴权。
- 模拟业务工单节点变更，检查接口返回的进度状态是否同步更新。
