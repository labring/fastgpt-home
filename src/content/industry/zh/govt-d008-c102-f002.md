# 炼化生产的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
炼化生产的业务办理数据主要来源于生产管理系统、设备运维台账、安全作业规程库及作业审批电子流。作业审批记录实时更新，运维台账按班次同步更新，安全规程每季度完成修订。文档包含结构化字段与非结构化文本：结构化字段包括作业票编号、设备ID、作业区域、压力（MPa）、温度（℃）等；非结构化文本涵盖动火、受限空间等作业的操作步骤、风险防控措施及审批流程。

## 这些特征在「向量模型与索引」这一环带来什么约束
混合的结构化与非结构化数据要求分块时保留业务关联，避免拆分作业票编号与对应操作步骤；实时更新的作业审批记录要求索引支持增量同步，无需全量重建索引；特定行业单位的字段要求向量建模时保留语义，防止单位混淆导致匹配偏差；长流程文档则要求分块长度适配业务节点，避免跨块截断完整操作步骤。此外，业务办理涉及安全合规，召回结果的准确性要求更高，需严格控制低匹配结果的引入。

## 配置怎么定
本配置基于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配炼化业务办理文档的业务节点长度，完整覆盖单条作业流程或规程片段 |
| 重叠长度 | 100–150 字符 | 保留相邻业务节点的上下文关联，避免跨块拆分的操作步骤出现语义断裂 |
| 相似度阈值 | 0.75–0.85 | 匹配炼化业务的安全合规要求，过滤低匹配的无关结果，保障流程引导的准确性 |
| 单次搜索上限 | 前 8 条 | 覆盖常见业务办理的关联步骤，避免遗漏关键流程节点 |
| `maxToken` | 4000 token | 适配业务办理文档的总召回长度，确保完整嵌入上下文窗口 |
| `defaultToken` | 200 token | 匹配一线操作人员的阅读习惯，控制单条指引的输出长度 |

## 容易做错的三处
- 现象：界面显示embedding模型配置后返回404状态码。原因：未正确配置百度embedding-v1的接口地址与密钥，或接口权限未开通。
- 现象：无GPU环境下部署的向量模型无法在管理界面添加。原因：未开启CPU模式运行向量模型容器，或容器资源分配不足。
- 现象：导出的知识库数据无法按业务分类拆分。原因：未提前按业务类型（如动火、受限空间）设置知识库分类标签，仅使用全局知识库维度导出。

## 怎么确认配好了
- 上传一条典型的炼化作业票文档，查看分块后的文本是否完整保留作业步骤与设备参数。
- 发起业务办理引导查询，核对返回结果的相似度评分是否落在设定的阈值区间内。
- 测试增量更新功能，提交新的作业票数据，确认索引库自动同步更新。
- 查看向量模型运行日志，确认无连接超时或参数解析错误的记录。
