# 炼化生产的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
炼化生产的业务办理数据主要来源于企业生产执行系统（MES）、设备运维台账、安全合规手册与行政审批流程库。数据更新节奏分为实时与定时两类：装置运行参数、安全阈值为实时更新，月度生产报表、审批节点配置为每日更新。文档结构以结构化流程节点为核心，包含装置编号、操作压力、温度、办理时限、审批权限等字段，单位统一采用炼化生产标准规范，如压力单位为兆帕（MPa）、温度为摄氏度（℃）。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
炼化业务办理数据的结构化特征要求多轮对话需严格匹配字段格式与标准单位，避免出现参数不匹配的问题。实时更新的装置运行参数要求对话上下文需限制历史轮次，防止使用过期数据引导流程。多节点的办理流程要求对话需按步骤递进，每一轮交互仅聚焦当前节点的信息收集与校验，避免跨节点冗余信息干扰。同时，字段的权限约束要求对话需准确识别当前办理环节的可操作字段，防止越权引导。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文轮次 | 前8轮对话 | 炼化业务办理流程通常包含5-7个节点，8轮可覆盖完整办理链路，避免上下文冗余 |
| `variables` | 绑定装置ID、操作压力阈值字段 | 确保对话中调用的业务数据匹配当前办理的炼化生产装置 |
| `messages` | 仅保留当前办理流程的历史交互 | 过滤无关历史消息，聚焦当前业务环节的引导 |
| 输入长度限制 | 1200-1500字符 | 拦截超出大模型处理上限的输入请求，避免触发报错 |
| 提示词模板 | 包含单位校验规则 | 强制对话中使用炼化生产标准单位（MPa、℃） |
| `chatId` | 绑定单次业务办理会话ID | 确保多轮对话关联同一办理流程的上下文 |

## 容易做错的三处
- 现象：提交超出1200字符的业务请求后，界面显示无响应或报错。原因：未配置输入长度限制规则，超长输入直接提交至大模型触发上下文溢出。
- 现象：多轮对话无法记住之前提及的装置参数，导致后续引导出现偏差。原因：未启用`variables`绑定历史参数，或上下文轮次设置过少导致历史参数被清除。
- 现象：返回的业务引导结果未携带关联文档的引用标识。原因：未在提示词中明确要求返回文档关联字段，或未配置变量绑定业务数据源的引用关系。

## 怎么确认配好了
- 提交一段超出1200字符的业务办理请求，确认系统触发输入长度拦截提示。
- 开启两个不同的炼化装置办理会话，分别提交交互内容，确认两个会话的上下文互不干扰。
- 向对话中输入包含非标准单位的参数，确认系统返回单位校验提示或修正建议。
- 查看对话日志，确认每次交互的`chatId`与当前办理流程的ID一致。
