# 炼化生产的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
炼化生产的数据来源包括分布式控制系统（DCS）、装置当班报表、设备运维台账、质检中心检测报告。更新节奏分为实时（工艺温度、压力、流量参数，每秒至每分钟更新）、每日（当班产量、能耗报表）、定期（设备维保记录、季度质检汇总）。文档结构包含装置唯一标识、工艺参数值与对应单位、质检指标数值、设备运行时长等字段，字段命名遵循石油石化行业标准，单位多为摄氏度、兆帕、立方米每小时、毫克每立方米等。

## 这些特征在「工作流编排」这一环带来什么约束
实时性强的工艺参数要求工作流触发节点需匹配高频更新节奏，若触发频率过低会导致数据滞后；多源异构数据需配置多个数据源节点，需通过`variables`严格绑定对应字段，避免跨数据源参数错位；质检报告等文件类数据体积较大，上传环节需适配更长的超时阈值；行业标准字段命名要求工作流变量映射需严格遵循既定规则，不可随意自定义字段名。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables`映射规则 | 严格匹配数据源字段名与工作流变量 | 避免参数错位导致流程执行异常 |
| 触发频率 | `10–60 秒`（按实测标定） | 匹配炼化实时工艺参数的更新节奏 |
| `nodeId`绑定触发节点 | 绑定定时触发或装置状态变更节点 | 按需触发业务办理流程 |
| 文件上传节点超时时间 | `300 秒` | 适配炼化质检报告等大体积文件的上传耗时 |
| 工作流重试次数 | `2–3 次` | 处理临时网络波动或数据源响应延迟 |
| 关联知识库范围 | 仅绑定炼化工艺标准库 | 过滤无关业务数据，提升流程准确性 |

## 容易做错的三处
- 工作流上传炼化质检报告时提示Failed to create post presigned url，原因是未配置对象存储的跨域访问规则，或签名过期时间设置短于文件上传实际耗时。
- 工作流中`variables`绑定的字段为空，导致流程输出缺失关键工艺数据，原因是未校验数据源返回的字段完整性就直接完成映射。
- 工作流触发频率设置低于10秒，导致高频请求超出装置DCS系统的响应上限，引发流程执行失败。

## 怎么确认配好了
- 手动触发一次工作流，查看流程输出中的`variables`绑定字段，确认与数据源返回值一致。
- 上传一份标准炼化质检报告，确认文件上传节点无报错且文件成功存入指定存储路径。
- 观察连续1小时的工作流运行日志，确认触发频率符合设定值且无重复报错。
- 调整触发频率区间，验证流程是否按设定节奏自动执行。
