# 煤炭运销的业务办理流程引导：HTTP 接口与外部系统

## 这个品类的数据长什么样
煤炭运销的业务数据主要来自运销计划管理系统、过磅称重系统、合同结算系统三类内部系统。数据更新以单条运单办理节点触发为主，部分批量统计数据按小时同步。单条业务数据包含运单编号、煤炭品类、发运地、到达地、实发重量、结算金额、当前办理节点状态等字段，重量单位为吨，金额单位为元，时间字段格式为YYYY-MM-DD HH:mm:ss。本页适配FastGPT v4.17.0版本。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
煤炭运销业务数据来源分散，需对接多套外部系统接口，导致请求端点配置需区分不同数据源的地址与鉴权方式。实时更新的业务数据要求接口响应延迟符合业务办理的容忍阈值，避免阻塞流程。字段包含明确的物理量与单位，接口请求参数需严格匹配字段名与单位规则，否则会导致外部系统校验失败。办理节点状态的流转逻辑需通过接口同步，需在请求体中携带当前节点标识与变更时间戳，确保外部系统能正确识别业务进度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带Bearer格式的系统访问令牌 | 符合煤炭运销内部系统的鉴权标准，保障接口调用安全 |
| `variables` | 绑定外部接口返回的运单状态字段 | 实现工作流全局变量与外部业务数据的自动同步 |
| `responseData` | 提取指定字段用于流程判断 | 快速获取外部系统返回的实发重量、结算金额等核心业务数据 |
| 超时时间 | 600秒 | 适配煤炭运销过磅、结算等环节的平均响应时长，避免流程阻塞 |
| 请求字段映射 | 按外部系统要求匹配单位与格式 | 确保传递的重量（吨）、金额（元）等数据符合外部系统校验规则 |
| 重试机制 | 失败后重试2次，间隔30秒 | 应对网络波动或外部系统临时故障，提升接口调用成功率 |

## 容易做错的三处
- 现象：接口调用后工作流全局变量未被赋值，返回结果为空。原因：未正确绑定`variables`配置项到外部接口的返回字段，或字段名匹配错误。
- 现象：调用接口返回400错误，提示参数格式不匹配。原因：未按外部系统要求传递重量、金额的单位与格式，例如未将实发重量以吨为单位传递。
- 现象：接口调用超时，流程中断。原因：超时时间配置过短，未适配煤炭运销结算环节的长响应时长，或外部系统临时负载过高。

## 怎么确认配好了
- 调用测试接口，查看返回的`responseData`是否包含预期的运单核心字段，核对字段格式与单位是否符合外部系统要求。
- 检查工作流全局变量的取值，确认`variables`绑定的字段已正确同步外部接口返回的数据。
- 模拟业务节点触发接口调用，查看是否触发重试机制，确认超时与重试配置符合业务场景的容忍范围。
- 查看接口调用日志，确认`Authorization`头已正确携带令牌，鉴权校验通过。
