# 煤炭运销的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
煤炭运销的业务数据主要来自内部运销调度系统、磅房计量系统、铁路/港口发运台账。数据以单批次运单为核心单元，按运单生成节奏更新，单笔运单完成结算后归档。单份数据文档包含煤种、发运量（单位：吨）、发运时间、收货方、承运方、运费单价（单位：元/吨）、结算状态等固定字段，部分跨区域运单还包含中转节点信息，数据结构相对规整但字段专业性较强。

## 这些特征在「工具调用与插件」这一环带来什么约束
煤炭运销数据的专业性字段要求工具调用必须精准匹配专属字段名，避免通用抽取导致数据偏差。高频更新的运单数据要求插件需设置合理的刷新频率，平衡实时性与系统资源消耗。多系统数据源的特性要求插件需配置跨系统对接参数，确保能同时拉取磅房计量与发运台账数据。此外，用户常需通过折线图展示运量变化趋势，这要求工具返回的图表数据需遵循标准化结构化格式，否则无法在聊天页面正常渲染。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配煤炭运销多工具并行调用的业务场景，自动匹配对应工具处理运单查询、数据统计等需求 |
| 工具调用超时时间 | `300 秒` | 煤炭运销跨系统拉取数据通常需要一定响应时长，避免因超时中断工具调用流程 |
| 返回结果最大条数 | `前 20 条` | 控制单次工具调用返回的运单数据量，避免上下文过载影响模型理解 |
| 插件数据刷新频率 | `每 15 分钟` | 匹配运单日常更新节奏，平衡数据实时性与服务器资源消耗 |
| `functionCall` | `enabled` | 强制启用结构化工具调用，确保模型生成符合要求的调用指令，适配煤炭运销数据的精准抽取需求 |
| 图表渲染格式 | `JSON 结构化数据` | 遵循FastGPT聊天页面的折线图渲染规范，需包含x轴时间、y轴数值的键值对结构 |

## 容易做错的三处
- 现象：调用MCP工具返回折线图后无法在聊天页面展示，原因：返回的折线图数据未包含x轴时间、y轴数值的标准键值对，不符合FastGPT的渲染要求。
- 现象：界面出现`Your model may not support tool_call SyntaxError`报错，原因：未正确配置`functionCall`或`toolChoice`参数，导致模型无法识别合法的工具调用语法。
- 现象：工具调用返回的运单数据缺少煤种、发运量等核心字段，原因：未在插件配置中指定需要拉取的煤炭运销专属字段，导致数据抽取范围不完整。

## 怎么确认配好了
- 发起包含「查询近期煤炭发运量」的测试提问，查看系统是否触发工具调用并返回对应运单数据。
- 导入预设的煤炭运量折线图测试数据，确认聊天页面可正常渲染出可视化图表。
- 查看FastGPT后台日志，确认无工具调用语法错误的提示，验证`toolChoice`与`functionCall`参数配置生效。
- 等待插件刷新周期结束，检查数据是否按预设频率完成更新，确认跨系统拉取逻辑正常。
