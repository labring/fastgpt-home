# 煤炭运销的业务办理流程引导：文档解析与分块

## 这个品类的数据长什么样
煤炭运销的业务数据主要来源于过磅单、购销合同、结算台账、运输派车单等纸质或电子文档。数据更新节奏为每日同步，随每一笔运销业务产生新增记录。电子文档多为固定格式Excel表格与标准PDF合同，Excel字段包含过磅编号、煤种、毛重/皮重/净重（单位：吨）、单价（单位：元/吨）、结算金额（单位：元）、收发货方信息等，PDF合同则包含条款文本与结构化表格。

## 这些特征在「文档解析与分块」这一环带来什么约束
煤炭运销的结构化文档特征对解析分块带来多重约束。固定格式的Excel与PDF文档中，单条业务数据集中在连续的表格行或段落中，分块时需避免拆分同一条运销业务的关联字段，防止语义断裂。每日批量产生的大量业务文档，要求解析环节适配单文件大小上限与超时限制，避免批量上传时出现中断。字段附带明确的物理单位，分块后需保留单位与对应数值的绑定关系，确保后续检索时数据语义完整。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 煤炭运销单条业务的结构化字段总长度多在该区间，避免拆分同一条业务的关联数据 |
| `chunkSplitter` | 按表格行/段落拆分 | 煤炭运销文档多为结构化表格，按表格行拆分可保留单条业务的完整字段关联，避免语义断裂 |
| `customPdfParse` | 开启 | 煤炭运销的PDF合同多为固定格式，开启自定义PDF解析可精准提取表格与条款文本，提升解析完整性 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 单批次批量上传的运销台账Excel文件多不超过该大小，适配批量处理需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型运销台账文件解析耗时较长，该时长可避免批量解析时出现超时中断 |
| `chunkSettingMode` | 手动配置 | 煤炭运销文档结构固定，手动配置分块参数可精准匹配业务数据特征，优于自动分块 |

## 容易做错的三处
- 现象：批量上传大批量运销台账Excel文件时，中途出现解析中断，重启Docker后无法继续解析。原因：未调整`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`参数，单文件过大或解析耗时超出默认阈值导致中断，且未适配批量处理的资源配置。
- 现象：上传过磅单Excel文件后，对话框无解析进度，后台无报错日志。原因：未启用对应结构化文档解析配置，默认解析模式无法识别Excel中的结构化表格字段，导致解析失败。
- 现象：模型回答未引用上传的运销数据，仅返回通用内容。原因：`chunkSize`设置过小，拆分了单条运销业务的完整字段，导致检索时无法匹配完整业务上下文。

## 怎么确认配好了
- 上传单份标准过磅单Excel文件，查看解析后的文本是否完整提取所有结构化字段，核对是否存在跨业务行的拆分或字段丢失。
- 上传10份以内的小型运销文档，检查解析队列是否正常推进，无超时报错，确认参数设置适配当前文档规模。
- 发起包含具体煤种、吨位的检索请求，核对返回结果是否包含上传文档中的对应业务数据，验证分块是否保留了字段关联语义。
- 测试调整分块策略参数，对比不同拆分方式的检索效果，确认匹配当前文档结构的配置方案。
