# 煤炭运销的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
煤炭运销的业务办理数据主要来自内部运销调度系统、合同管理模块与过磅称重系统。数据更新随单笔业务节点触发，单笔运单完成过磅后即时同步，批量业务数据按日更新。单份业务文档包含运单编号、煤种类别、发运地、收货地、核定吨位、审批状态、完成时限等字段，字段单位多为吨、车次、自然日，文档结构固定且字段间关联性强。

## 这些特征在「模型接入与配置」这一环带来什么约束
煤炭运销业务数据的即时更新特性，要求模型接入时需限制上下文缓存时长，避免调用过时业务信息。字段多且关联性强的特点，要求模型需精准匹配字段与业务逻辑，避免生成偏离实际业务规则的内容。单笔业务文档的token量偏高，需合理限制单次输入的最大token数，防止请求超限。同时运销数据涉及内部业务流程，模型接入需优先支持内网API端点配置，保障数据传输合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `72 小时` | 匹配煤炭运销业务的常规审批周期，避免缓存超过业务办理时限的旧数据 |
| `maxTokens` | `8000–12000 token` | 适配单笔运销业务文档的平均token规模，防止请求超出模型处理上限 |
| `quoteMaxToken` | `2000 token` | 限制引用业务数据的token占比，确保核心引导逻辑有足够的token空间 |
| `temperature` | `0.2–0.4` | 保障业务流程引导的准确性，避免生成偏离实际业务规则的内容 |
| `AIPROXY_API_ENDPOINT` | `内网合规API地址` | 适配煤炭运销业务的内网数据对接要求，保障数据传输安全 |
| `AIPROXY_API_TOKEN` | `专属加密调用密钥` | 区分业务专属调用权限，符合内部数据安全管理规范 |

## 容易做错的三处
- 调用时返回422状态码，提示参数格式错误。原因是未按照运销业务字段的固定格式拼接请求参数，导致模型无法识别业务上下文。
- 界面显示模型测试成功但实际业务引导无响应。原因是`AIPROXY_API_ENDPOINT`配置为公网地址，未适配内网数据访问权限，无法拉取实时运销业务数据。
- 工作流调用外部模型时出现超时。原因是未限制`maxContext`的缓存时长，导致请求携带过多历史数据超出模型处理上限。

## 怎么确认配好了
- 登录FastGPT v4.17.0后台，进入模型配置页面，核对`AIPROXY_API_TOKEN`与申请的专属密钥完全一致。
- 发起单笔运销业务的模拟调用，检查返回结果中包含当前业务的准确字段与流程步骤。
- 查看模型调用日志，确认`maxContext`的缓存时长符合预设的72小时阈值。
- 测试跨业务节点的流程引导，验证模型能正确关联不同阶段的运销数据字段。
