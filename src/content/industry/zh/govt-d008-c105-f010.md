# 煤炭运销的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
煤炭运销的业务数据主要来自运销合同、过磅单、结算单、运输计划单四类核心单据，来源为企业内部ERP系统、现场过磅设备与合同管理模块。数据更新节奏随业务办理实时触发，单次业务完成后1小时内完成同步。文档结构包含结构化表格字段与非结构化文本两类，结构化字段包含发站、到站、煤种、计费吨位、运价标准等，单位涉及吨、元/吨、公里、车次等，非结构化内容多为合同条款与业务说明。

## 这些特征在「知识库检索与召回」这一环带来什么约束
煤炭运销数据的结构化占比高且字段专业性强，要求检索需同时匹配关键词与字段属性，避免泛化匹配干扰。实时更新的业务单据要求知识库支持增量同步，避免检索到过期的运销计划。文档长度差异显著，短单据仅数十字符，长合同可达数千字符，需适配不同长度的召回规则。业务术语存在同义词，比如「精煤」与「洗精煤」，需支持术语扩展以覆盖全业务场景。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 煤炭运销业务关键词精准度要求高，该区间可过滤低相关的非业务文档 |
| `limit` | 前6–8条 | 业务办理需关联多份关联单据，过多结果会增加上下文处理负载 |
| `searchMode` | 混合检索 | 同时支持结构化字段匹配与非结构化文本检索，覆盖合同、单据两类数据 |
| `usingReRank` | 开启 | 煤炭运销业务关键词分散，重排可提升关键结果的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 覆盖业务同义词，比如「发运量」与「出货吨位」的匹配需求 |
| `collectionIds` | 绑定运销合同、过磅单、结算单三个集合 | 覆盖全业务办理所需的核心文档类型 |

## 容易做错的三处
- 现象：检索耗时超过10秒，界面显示加载超时提示。原因：未针对煤炭运销的结构化数据优化检索规则，同时加载了过多无关集合的文档，导致向量检索与重排环节负载过高。
- 现象：检索结果中出现非指定煤种的运销单据。原因：未设置合理的`similarity`阈值，或未开启`usingReRank`重排，导致低相关结果前置干扰业务判断。
- 现象：单个知识库无法导入超过预设数量的运销单据。原因：未调整FastGPT对应集合的存储空间上限配置，或未按业务文档的实际平均大小分配配额。

## 怎么确认配好了
- 上传单份煤炭运销合同与过磅单，发起「查询XX煤种的结算流程」的提问，核对返回结果是否包含对应文档的关键字段。
- 查看知识库的存储空间使用统计，确认已导入的运销文档未超过预设配额。
- 模拟高频检索请求，查看检索耗时是否符合业务预期，无明显超时情况。
- 测试使用业务同义词提问，比如将「过磅单」替换为「称重单据」，确认检索结果仍能匹配正确文档。
