# 煤电一体化的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
煤电一体化的业务数据主要来自矿井生产管理系统、电力调度平台与业务审批流程系统。数据更新按生产班次或每日完成，包含结构化的业务审批单据、半结构化的机组运行报表，以及非结构化的现场巡检记录。文档字段包含作业编号、流程节点、煤炭产量、发电量、作业时长等，单位涵盖吨、千瓦时、小时等，单份审批单据通常包含多个流程节点。

## 这些特征在「模型接入与配置」这一环带来什么约束
多系统来源的结构化与半结构化数据，要求模型能准确识别特定业务字段与对应单位，避免业务办理引导出现参数匹配错误。高频更新的业务数据，要求上下文长度需适配实时信息的引入，避免因上下文溢出丢失关键流程节点。非结构化的现场巡检图片数据，要求模型支持视觉识别能力，补充业务办理的现场依据。多节点的审批流程逻辑，要求模型可自动触发工具调用，获取实时流程状态与审批要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配煤电业务办理的多节点审批文档与历史记录，避免上下文溢出 |
| `maxTokens` | 4000 token | 限制单轮响应长度，确保业务办理步骤的引导内容简洁清晰 |
| `quoteMaxToken` | 2000 token | 保留足够的业务单据片段用于引用，确保流程引导的依据准确可追溯 |
| `toolChoice` | auto | 自动触发流程节点查询、设备参数校验等工具调用，适配业务办理的多步骤逻辑 |
| `vision` | 开启 | 支持识别现场巡检图片、审批附件图片中的设备状态，补充业务办理的视觉依据 |
| `temperature` | 0.3–0.5 | 降低响应随机性，确保业务流程引导的步骤符合既定规范 |

## 容易做错的三处
- 调用模型时返回一串红色数字报错。原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致接口鉴权失败或地址无效。
- 配置多模态功能后无法识别上传的图片。原因：未开启`vision`参数，或上传的文件格式不符合平台支持的要求。
- 调用指定模型时返回404错误。原因：`AIPROXY_API_ENDPOINT`填写的地址与模型实际部署地址不匹配，或模型版本未在平台中完成注册。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型接入配置页面，检查`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的填写内容与平台提供的官方信息一致。
- 发起测试调用，输入煤电业务的典型流程查询，查看响应中是否包含准确的流程节点引导内容。
- 上传一张符合格式的设备巡检图片，触发多模态调用，查看是否能正确识别图片中的设备状态信息。
- 调整`temperature`参数至0.2，发起测试调用，确认响应内容的随机性降低，步骤描述更符合既定业务规范。
