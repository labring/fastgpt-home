# 煤电一体化的业务办理流程引导：部署与升级

## 这个品类的数据长什么样
煤电一体化业务的数据来源涵盖矿井生产监测系统、发电调度平台、跨区域煤炭调运台账、设备运维巡检报告等。更新节奏分为实时（如发电负荷、瓦斯浓度数据）、每日（如生产日报）、每月（如能耗统计报表）三类。文档结构包含结构化业务单据（含矿井编号、调度单号、煤耗率等字段）与非结构化报告（含图片、表格的巡检文档），字段单位涵盖兆瓦时、吨、立方米等。

## 这些特征在「部署与升级」这一环带来什么约束
煤电一体化业务的结构化数据多存储于关系型数据库，非结构化文件体积大且多部署在内网环境，实时数据更新频次高，因此部署时需优先对接内网数据库与存储服务。升级时需同步适配数据库连接池配置，避免因连接数不足导致业务办理流程引导功能卡顿。同时需注意内网访问权限的配置，防止系统拦截内部业务请求。此外，不同版本的FastGPT对插件依赖的要求存在差异，升级时需验证文件加工插件的兼容性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://coal_user:secure_pass@internal-db:5432/coal_power` | 煤电一体化业务的审批单据、调度台账多存储于PostgreSQL数据库，需对接内网业务库获取办理流程数据 |
| `REDIS_URL` | `redis://:redis_auth@internal-cache:6379/0` | 需缓存实时发电负荷、矿井监测数据，降低数据库查询压力，保障流程引导的响应速度 |
| `DB_MAX_LINK` | `100–150 个` | 煤电业务实时数据请求频次高，需控制数据库连接池规模避免过载，保障多用户同时发起流程查询的稳定性 |
| `STORAGE_S3_ENDPOINT` | `http://internal-s3:9000` | 需存储巡检报告、设备运维文档等大尺寸非结构化文件，内网节点可保障文件加载速度与安全性 |
| `FILE_TOKEN_KEY` | `由业务系统加密算法生成的专属密钥` | 需对业务办理流程中的敏感文件生成访问令牌，防止未授权访问流程相关文档 |

## 容易做错的三处
- 现象：升级FastGPT v4.17.0后，使用内网业务系统URL创建知识库时提示`cannot fetch internal url`。原因：未配置内网访问白名单，或`FE_DOMAIN`未绑定内网业务域名，导致系统拦截内部请求。
- 现象：后台日志显示找不到文件加工插件。原因：升级时未同步更新插件依赖包，或`STORAGE_S3_ENDPOINT`配置错误导致插件无法加载存储配置。
- 现象：使用阿里云百炼或Ollama模型测试时出现报错，镜像为当日拉取。原因：未正确配置模型API密钥的权限范围，或本地部署的环境变量未正确加载`ROOT_KEY`等认证参数。

## 怎么确认配好了
- 在内网环境下提交业务系统URL，创建知识库并验证能否正常拉取结构化单据与非结构化文档。
- 进入后台插件管理页面，确认文件加工插件状态为已启用，无异常报错提示。
- 提交包含复杂工程公式的查询请求，验证能否正常解析并返回结果。
- 查看数据库连接日志，确认`PG_URL`、`REDIS_URL`配置的连接池无超时或断开报错。
