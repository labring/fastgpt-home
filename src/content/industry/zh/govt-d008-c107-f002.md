# 煤矿生产的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
煤矿生产业务办理流程相关的数据，主要来源包括矿井调度审批台账、岗位作业安全规程、设备运维记录、业务申请单等。更新节奏分为三类：日常作业的申请单与审批记录随业务实时更新，设备运维日志按作业班次更新，通用安全规程与流程文档按季度或年度修订。文档结构包含结构化表单（含申请时间、审批人、设备编号、作业时长等字段）、非结构化规程文本（分章节带条款编号）、半结构化运维日志（带时间戳与设备ID），字段单位多为小时、台次、编号等专业格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
煤矿业务数据的多结构特征，要求向量分块需兼顾结构化字段的关联性与非结构化文本的语义完整性，避免拆分关键审批信息或专业术语。实时更新的业务单据要求索引支持增量同步，避免全量重索引带来的性能损耗。长篇幅的规程文档需适配合理的分块与上下文拼接逻辑，防止跨块语义断裂。专业术语密集的内容要求embedding模型具备领域适配能力，同时索引的召回阈值需匹配业务场景的精准度需求，避免无关数据干扰流程引导。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 覆盖煤矿业务中短审批单与长规程的语义单元，避免拆分专业术语与完整流程步骤 |
| 重叠长度 | 100–150 字符 | 衔接相邻分块的上下文，防止跨块的作业流程描述被割裂 |
| 相似度阈值 | 0.72–0.80 | 过滤无关的设备运维记录，精准匹配业务办理流程的语义相似度 |
| 单次搜索上限 | 前 10 条 | 控制返回结果数量，避免过多冗余信息干扰业务办理引导 |
| `defaultToken` | 8192 | 适配煤矿规程文档的长文本输入需求，容纳完整的专业内容 |
| `maxToken` | 16384 | 支持整合多份审批单与规程的上下文拼接，满足复杂业务查询的输入要求 |

## 容易做错的三处
- 现象：更换embedding模型后，手动插入的知识库文档索引数小时后自动消失。原因：未配置增量索引的持久化存储，全量索引任务覆盖了临时生成的默认索引，未保留历史索引快照。
- 现象：上传煤矿设备运维日志后，文件状态长期显示“索引中”，无进度更新。原因：未调整`defaultToken`参数，超出FastGPT v4.17.0版本模型输入限制导致批量嵌入任务中断，且未设置超时重试机制。
- 现象：搜索“综采工作面安装流程”时，召回了无关的瓦斯抽放记录。原因：分块长度设置过小，将完整的作业流程拆分为多个语义不连贯的片段，导致向量召回出现偏差。

## 怎么确认配好了
- 上传一份标准的煤矿岗位作业规程文档，查看分块预览内容，确认专业术语与完整流程未被拆分。
- 触发一次批量嵌入任务，查看FastGPT v4.17.0版本的任务日志，确认无内存溢出或超时报错，验证`maxToken`设置符合模型要求。
- 模拟业务办理查询，输入典型的流程关键词，查看召回结果的相似度得分是否落在预设阈值区间内。
- 等待12小时后检查知识库索引状态，确认手动插入的文档索引未自动消失，验证增量同步机制正常运行。
