# 煤矿生产的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
煤矿生产的业务办理数据主要来源于井下传感器监测系统、生产调度工单平台、安全监管台账及设备运维日志。数据更新节奏分为实时（如井下设备运行状态）和按班次/日更新（如每日产量统计、检修工单）。单条数据通常包含作业编号、设备唯一标识、作业类型、触发时间、当前状态、关联审批节点等字段，字段单位多为吨、台、小时，文档结构层级清晰，核心字段不可缺失。

## 这些特征在「工作流编排」这一环带来什么约束
煤矿生产的数据特征对工作流编排带来多项约束。实时采集的设备运行状态数据要求工作流节点间的调用延迟控制在合理区间，避免流程卡顿影响业务响应速度；按班次或日更的批量业务数据，需要工作流支持批量节点并行处理，提升整体处理效率；核心字段不可缺失的要求，需要在工作流起始节点配置字段校验环节，过滤缺失关键信息的业务工单；不同作业类型对应差异化的审批、核验流程，需要工作流支持条件分支配置，根据作业类型自动跳转对应处理节点。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 全局变量 | 绑定`variables`中预设的作业编号、设备ID字段 | 匹配煤矿业务数据的核心字段，确保流程各节点可统一调用 |
| 字段校验规则 | 校验作业类型、触发时间字段是否存在 | 规避缺失核心字段的无效工单进入流程 |
| 条件分支触发 | 按作业类型跳转对应审批节点 | 适配不同作业类型的差异化办理流程 |
| 批量处理节点 | 处理单次最多50条的批量工单数据 | 匹配按班次更新的批量业务数据规模 |
| 延迟阈值 | 设置为60–300秒 | 适配实时数据的响应要求 |
| `nodeId` | 指定中间节点的唯一标识 | 精准控制流程节点的调用顺序 |

## 容易做错的三处
- 现象：工作流运行后，中间AI对话节点的输出内容被包含在最终结果中。原因：未配置节点输出过滤规则，默认将所有节点的返回内容整合为最终输出。
- 现象：业务流程中无法正确识别历史对话中的指代内容，出现查询偏差。原因：未开启问题优化配置，未关联历史对话数据到当前处理节点。
- 现象：工作流无法调用预设的全局业务字段。原因：未在`variables`中正确绑定全局变量的字段映射关系。

## 怎么确认配好了
- 触发一条测试业务工单，检查核心字段是否通过校验环节。
- 切换不同作业类型，确认流程自动跳转至对应处理节点。
- 运行工作流后，查看最终输出内容，确认仅保留目标节点的结果。
- 调用全局变量节点，确认可获取预设的业务字段数据。
