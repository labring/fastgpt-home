# 煤矿生产的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
煤矿生产的业务办理流程相关数据，主要来自内部调度系统、安检巡检系统、工单管理系统与设备运维平台。数据更新节奏随业务场景变化，工单类数据实时更新，安检类数据按每班或每日更新，设备运维数据在单次巡检完成后更新。文档结构包含业务类型、办理节点、责任人、时限要求、关联设备编号、安全阈值等字段，字段单位涵盖小时、天、编号字符串、工程百分比等专业单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源系统的异构数据格式，要求接入配置中需统一字段映射规则，避免模型混淆不同来源数据的字段含义与单位。实时更新的业务数据，要求模型上下文窗口的有效期需匹配数据更新频率，避免调用过时的流程信息。专业字段的严格规范，要求模型的提示词需明确指定字段的取值范围与单位，确保生成的办理指引符合煤矿安全规程。此外，敏感业务数据的传输，要求API调用需配置专属的身份验证机制，保障数据安全。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配煤矿业务办理流程的完整上下文长度，避免截断关键的设备编号与时限要求 |
| `maxTokens` | 2000 token | 控制单轮业务指引的输出长度，确保符合煤矿现场的快速查看需求 |
| `quoteMaxToken` | 1500 token | 限制引用的业务数据长度，避免引入无关的历史工单信息 |
| `toolChoice` | auto | 允许模型自动选择是否调用业务数据工具，适配不同的办理场景 |
| `temperature` | 0.2–0.4 | 降低生成随机性，确保业务指引的步骤与煤矿安全规范一致 |
| `AIPROXY_API_ENDPOINT` | 填写煤矿内部部署的代理地址 | 实现内部业务数据的安全调用，避免公网暴露敏感信息 |
| `AIPROXY_API_TOKEN` | 按企业内部密钥规范配置 | 保障API调用的身份验证安全 |

## 容易做错的三处
- 现象：模型提供商页面的调用日志模块为空，无任何请求记录。原因：未开启FastGPT的API调用日志采集配置，或内部代理服务未转发日志信息。
- 现象：知识库检索测试可正常返回结果，但业务办理流程引导环节模型无响应或生成错误指引。原因：未在`toolChoice`配置中开启业务工具调用权限，或上下文窗口未包含业务流程的关键节点。
- 现象：在模型选择列表中未找到指定版本（如DeepSeek V3.1）。原因：未在内部代理服务中同步最新的模型元数据，或配置的`AIPROXY_API_ENDPOINT`未指向正确的模型仓库地址。

## 怎么确认配好了
- 检查`AIPROXY_API_TOKEN`的配置是否与内部代理服务的密钥一致，可通过发送测试请求验证身份验证是否通过。
- 调整`maxContext`为预设的小数值区间，测试是否能正常加载短上下文的业务流程数据，验证窗口配置是否生效。
- 设置`temperature`为0.5，生成测试业务指引，检查输出是否包含正确的设备编号与时限字段，验证字段映射是否正确。
- 查看FastGPT的系统日志，确认模型调用请求已成功发送到内部代理服务，验证API端点配置是否正确。
