# 煤矿生产的业务办理流程引导：部署与升级

## 这个品类的数据长什么样
煤矿生产的业务办理流程数据来源为煤矿内部调度管理系统、安全监管系统、证照办理系统、后勤服务系统等。数据更新按业务办理节点触发，每次流程提交、审批、办结时同步更新。文档结构包含流程唯一标识、节点名称、责任人岗位、所需办理材料类型、办理时限、审批状态等字段，其中材料类型分为电子件与纸质件，办理时限以小时或天为单位。数据存储分散在多个内部数据库中，需通过内网专线对接，无统一对外公开接口。

## 这些特征在「部署与升级」这一环带来什么约束
煤矿业务流程数据分散存储于多个内网数据库，部署时需配置多个数据源的连接参数，且需适配内网无公网访问的环境。数据更新频率随业务办理量波动，高峰时段读写请求密集，需调整数据库连接池参数以保障稳定性。流程数据包含电子与纸质材料，需对接内部对象存储服务存储电子材料，因此需配置专用的存储端点参数。升级时需同步更新数据源的访问权限配置，避免因权限变更导致流程数据读取失败。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://coal_admin:secure_pass@internal-db:5432/coal_business?sslmode=disable` | 对接煤矿内部业务流程的PostgreSQL数据库，禁用SSL适配内网环境 |
| `MONGODB_URI` | `mongodb://internal-mongo:27017/coal_flow_db` | 存储流程节点日志与审批记录的MongoDB实例，适配内网部署 |
| `DB_MAX_LINK` | `20–30` | 适配业务流程高频读写的数据库连接需求，避免连接耗尽 |
| `STORAGE_S3_ENDPOINT` | `http://internal-storage:9000` | 对接煤矿内部对象存储服务，存储办理材料的电子件 |
| `FE_DOMAIN` | `https://coal-proc.internal` | 配置内网访问的前端域名，适配煤矿内网访问场景 |
| `REDIS_URL` | `redis://internal-redis:6379/0` | 缓存流程节点与用户会话数据，提升访问响应速度 |

## 容易做错的三处
- 上传文件或图片时报错，重新部署后仍未解决。原因：未将`STORAGE_S3_ENDPOINT`配置为煤矿内网存储地址，公网存储无法在内网环境访问。
- 本地开发部署时数据库安装步骤跳转至Docker Compose部署流程。原因：未正确配置本地数据库连接参数，安装脚本自动 fallback 至容器化部署方案。
- 公有云版本出现连接超时报错。原因：未将`FE_DOMAIN`配置为公有云绑定的官方域名，导致前端与后端服务地址不匹配，请求无法正常路由。

## 怎么确认配好了
- 访问配置的`FE_DOMAIN`地址，确认前端页面正常加载，无域名解析或连接超时报错。
- 执行内置的数据库连接测试工具，验证`PG_URL`与`MONGODB_URI`配置的数据源可正常建立连接并读取测试数据。
- 上传测试用的电子材料文件，确认文件可正常存储至配置的`STORAGE_S3_ENDPOINT`对应的存储服务，无上传失败提示。
- 查看Redis服务日志，确认`REDIS_URL`配置的缓存服务正常建立连接，无认证或连接报错。
