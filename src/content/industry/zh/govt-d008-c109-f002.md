# 电网企业的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
电网企业的业务办理流程数据主要来源于营销业务应用系统、95598工单归档库、线下营业厅发布的办事指南文档，日常随业务规则更新、电价政策调整、新增服务事项同步更新。数据包含两类结构：一类是带明确表头的结构化表格，字段涵盖业务类型、办理条件、所需材料、办理时限、联系电话等；另一类是非结构化的PDF办事指南，包含完整的流程步骤说明与常见问题解答。单条业务数据的文本长度跨度较大，既有几十字符的简短办理条件，也有数千字符的完整流程说明。

## 这些特征在「向量模型与索引」这一环带来什么约束
电网业务数据的结构化与非结构化混合特征，要求向量索引同时适配表格字段匹配与长文本语义匹配。数据更新频率较高，需支持增量索引刷新以保障流程规则的时效性。部分业务数据存在明确的层级关系，如总业务流程下的子环节、材料清单下的具体要求，分块时需保留层级上下文，避免拆分跨层级的业务单元。同时，单块文本长度差异大，需适配不同长度的文本生成合规向量，避免因token超限导致生成失败。

## 配置怎么定
FastGPT v4.17.0 版本下的配置参考如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配电网业务流程的自然单元长度，避免拆分完整的办理环节或材料清单 |
| 重叠长度 | 100–150 字符 | 保留相邻业务环节的上下文，防止流程步骤被分块截断 |
| `defaultToken` | 1024 token | 匹配多数开源embedding模型的输入token上限，适配电网业务数据的常见分块长度 |
| `maxToken` | 4096 token | 保障检索后的上下文拼接长度，覆盖完整的业务办理流程说明 |
| 相似度阈值 | 0.75–0.85 | 区分相似业务类型的匹配精度，避免误匹配不同的业务办理项 |
| 单次搜索上限 | 前3条 | 聚焦最相关的3个业务流程，避免结果冗余影响办理引导的准确性 |

## 容易做错的三处
- 现象：检索返回的业务流程出现步骤断裂，无法获取完整办理环节。原因：分块长度设置超过业务单元的自然长度，拆分了完整的办理步骤或材料清单。
- 现象：本地部署ollama后，向量生成失败，界面显示token超限报错。原因：未设置`maxToken`适配embedding模型的输入限制，导致长文本块无法生成有效向量。
- 现象：导入Excel业务数据后，匹配结果与查询需求完全不相关。原因：相似度阈值设置过低，将不相关的业务类型误判为匹配项，或未保留表格表头的上下文，导致字段匹配失效。

## 怎么确认配好了
- 导入单条Excel业务数据，查看FastGPT的分块预览界面，确认每个分块包含完整的业务环节与所需材料，无跨业务单元的拆分。
- 发起测试查询，检查返回结果的文本未出现截断提示，确认`maxToken`设置适配上下文拼接需求。
- 调整相似度阈值，验证不同阈值下的匹配结果数量变化符合预期，确认阈值设置合理。
- 上传更新后的业务文档，等待索引刷新后发起查询，确认新的流程规则能被正确检索到。
