# 矿山采选的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
矿山采选的业务数据来源于井下采掘台账系统、选矿车间集散控制系统、安全巡检记录平台及矿权办理流程文档。数据更新节奏覆盖实时（采掘进度、设备运行状态）与每日（选矿回收率、矿石品位统计）两类。文档分为结构化台账字段与非流程化工艺说明两类，结构化字段包含采掘面编号、矿量、选矿设备运行时长，单位为吨、小时、立方米。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
结构化字段分散且关联跨系统数据，多轮对话需按业务节点逐步关联采掘、选矿与审批的对应字段，提示词需明确指定仅调用匹配当前业务节点的字段值。实时更新的设备与进度数据要求对话上下文窗口不能过长，避免调用过期数据。非结构化工艺说明篇幅较长，提示词需限定提取与当前办理环节相关的参数范围，防止无关信息干扰对话逻辑。固定的矿权办理流程节点要求多轮对话按预设节点推进，避免跨节点调用不匹配的业务数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前办理业务的唯一标识 | 确保多轮对话关联同一业务流程，避免上下文混乱 |
| `messages` | 保留前 10 轮对话上下文 | 覆盖矿山采选完整办理流程的历史交互，避免丢失关键审批节点信息 |
| `variables` | 绑定当前采掘面编号、选矿设备ID | 匹配矿山采选的结构化字段，确保对话调用的业务数据与当前办理场景一致 |
| 最大上下文 | 8000–12000 字符 | 覆盖非结构化工艺说明的核心内容，同时避免过长导致上下文冗余 |
| 单次搜索上限 | 前 3 条匹配记录 | 减少无关工艺数据的干扰，聚焦当前办理环节的核心参数 |

## 容易做错的三处
- 现象：对话API流式输出后，点击链接仅覆盖当前页面无法跳转至新页面。原因：未在提示词中明确指定链接的跳转规则，导致流式输出的内容未携带前端可识别的跳转标识。
- 现象：对话API的日志详情与实际返回的回答内容不一致。原因：`messages`参数未正确追加每一轮的交互内容，导致上下文调用了历史错误的对话数据。
- 现象：流式输出的返回间隔固定为4秒，无法调整为1秒或2秒。原因：未通过配置项限定流式输出的分段返回时长，默认参数未适配前端展示的节奏需求。

## 怎么确认配好了
- 发起模拟矿权办理或选矿流程的对话，检查`messages`参数是否保留了前10轮的交互内容。
- 调用对话API查看日志，确认`variables`绑定的字段与当前办理业务的参数一致。
- 测试流式输出功能，查看返回的分段内容是否符合业务节点的需求，调整返回间隔至合适范围。
- 验证流式输出中的链接跳转，确认链接可正常跳转至对应业务页面。
