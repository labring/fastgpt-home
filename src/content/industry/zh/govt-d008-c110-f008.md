# 矿山采选的业务办理流程引导：文档解析与分块

本文适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
矿山采选的数据主要来自生产台账、选矿流程记录、安全合规文档、业务办理审批单。数据按作业班次或自然日更新，文档类型涵盖PDF格式的安全规程、DOCX格式的作业指导书、Excel格式的生产参数台账，部分月度汇总报表体积可达数十兆。文档包含矿石品级、处理量、作业时长等字段，单位多为吨、小时等，存在结构化表格与长文本段落混合的结构。

## 这些特征在「文档解析与分块」这一环带来什么约束
矿山采选文档的混合结构要求解析环节同时支持结构化表格提取与长文本段落解析，避免拆分破坏生产参数、审批节点的上下文逻辑关联。大体积月度报表可能超出常规解析阈值，引发超时错误。工业类字段的专业性要求分块时保留相邻字段的关联性，防止割裂作业流程的逻辑链条。业务办理类文档的固定审批格式，需要精准识别节点文本，避免误拆分审批步骤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 矿山采选文档多包含连贯的作业流程描述与工业参数，该区间可保留单步操作的完整逻辑 |
| `chunkSplitter` | 按自定义分隔符与语义分段 | 文档包含结构化表格与长文本，自定义分隔符可匹配作业指导书的章节分隔，语义分段可避免割裂工业参数的关联 |
| `customPdfParse` | 启用 | 矿山采选的PDF文档多包含内嵌表格与专业图表，启用自定义解析可提升结构化内容的提取准确率 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大体积月度报表的解析耗时较长，该时长可覆盖多数大型文档的解析需求 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 部分月度汇总报表体积可达数十兆，该阈值可满足常规大文件上传需求 |
| `chunkSettingMode` | 手动配置 | 矿山采选文档的格式差异较大，手动配置可灵活调整分块规则适配不同类型的业务文档 |

## 容易做错的三处
- 上传10几M的PDF文档时提示`timeout of 360000ms exceeded`错误，原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数至适配大文档的时长，默认超时阈值不足以覆盖大型报表的解析耗时。
- 个别DOCX文档解析后内容缺失或字段错位，原因是未启用`customPdfParse`配置，默认解析引擎无法准确识别矿山采选文档中的内嵌工业表格与专业格式。
- 导入预设的问答对文档后发起相关业务查询，返回结果未使用知识库原文答复，原因是未将分块规则匹配问答对的分隔格式，默认分块逻辑破坏了问答对的完整结构。

## 怎么确认配好了
- 上传单份10M以上的矿山采选PDF文档，查看解析任务是否在预设的`PARSE_FILE_TIMEOUT_SECONDS`时长内完成，无超时报错。
- 上传包含内嵌表格的DOCX作业指导书，核对解析后的表格内容是否完整，字段未出现错位或缺失。
- 导入预设的问答对文档，发起相关业务问题查询，确认返回结果与知识库原文内容一致。
- 查看分块预览界面，确认长文本段落被合理拆分，未割裂工业参数的上下文关联。
