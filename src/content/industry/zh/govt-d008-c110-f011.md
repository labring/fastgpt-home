# 矿山采选的业务办理流程引导：表单与交互
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
矿山采选的业务数据主要来源于生产台账、选矿流程参数记录、安全巡检日志、业务审批单据。数据更新节奏覆盖实时（现场巡检记录）、每日（生产日报）、每月（结算报表）三类。文档形态包含单份10万中文字的长文本日志、15000+行的结构化Excel生产数据，字段包含原矿品位、选矿回收率、设备运行时长、审批单号等，对应单位为百分比、小时、吨等专业采矿术语单位。

## 这些特征在「表单与交互」这一环带来什么约束
长文本巡检日志与超行Excel数据，要求表单交互环节支持大文件上传与分块解析，避免单次输入溢出。多专业单位的字段要求表单为每个字段标注对应单位提示，防止用户输入混淆。不同更新频率的业务数据，要求表单支持按业务场景选择数据时间范围，适配实时台账与月度结算的不同校验逻辑。现场巡检的图片数据需求，要求表单支持二进制流与base64格式的图片上传解析。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` 输入长度限制 | 8000–12000 字符 | 适配10万中文字档的分块解析需求，避免单次输入溢出 |
| `userSelect` 业务分类 | 采矿/选矿/安全审批三类 | 匹配矿山采选的三级业务场景，减少用户选择成本 |
| 单次上传文件上限 | 1000 MB | 支持15000+行Excel与长文本文档的批量上传 |
| 字段单位提示 | 随字段同步显示 | 避免原矿品位、选矿回收率等专业单位的输入混淆 |
| 交互超时阈值 | 600 秒 | 适配大文件解析与多轮对话的耗时需求 |

## 容易做错的三处
- 上传15000+行的Excel生产数据后，返回“不完整的命令或请求”提示。原因是未配置足够的单次上传文件上限，导致大文件解析时数据截断。
- 输入10万中文字的巡检日志文档后，交互流程无响应。原因是未调整`formInput`的输入长度限制，超出默认阈值导致请求被拦截。
- 上传base64格式的现场巡检图片后，无法触发内容解析。原因是未在表单交互环节开启图片适配配置，未关联对应解析模块。

## 怎么确认配好了
- 上传单份15000+行的Excel生产数据，检查是否能完整解析并进入后续交互环节。
- 输入单份10万中文字的巡检日志，检查`formInput`是否允许完整输入并提交。
- 选择`userSelect`的业务分类选项，检查是否能正确匹配对应的数据校验规则。
- 上传base64格式的现场图片，检查是否能触发对应的解析流程。
