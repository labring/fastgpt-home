# 粮食储备的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
粮食储备业务数据主要来自库区出入库台账、库存盘点报表、粮食品质检报告、轮换计划文件。数据更新随业务节点触发，出入库单据实时生成，库存台账每日更新，质检报告随粮食品批次完成后同步。文档多为结构化表格，包含库区编号、粮食品种、等级、实有数量、入库批次、保质期、存储仓位等字段，单位统一使用吨、公斤、批次号。

## 这些特征在「工作流编排」这一环带来什么约束
结构化数据多且字段维度复杂，要求工作流编排时需通过`variables`绑定不同业务字段，避免遗漏关键参数。实时产生的出入库数据要求工作流节点支持触发式执行，减少数据延迟。粮食品批次与保质期的关联要求工作流中增加分支判断节点，根据入库批次的保质期阈值触发轮换预警流程。不同库区的仓位字段命名存在细微差异，要求工作流配置时支持自定义字段映射规则。单份业务文档长度适中但批量处理时数据量较大，要求工作流支持分页读取节点，避免内存溢出。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按业务事件触发 | 匹配粮食储备业务随出入库、盘点实时产生数据的特性 |
| 变量绑定 | 绑定`variables`中的库区编号、粮食品种字段 | 适配结构化台账的多字段业务逻辑 |
| 分支判断 | 按入库批次保质期阈值触发 | 对应粮食品轮换的业务规则 |
| 字段映射 | 支持自定义库区仓位字段 | 解决不同库区命名差异的问题 |
| 超时设置 | 600秒 | 适配批量库存盘点的处理时长 |
| 最大上下文 | 800–1200字符 | 匹配单份业务台账的平均长度 |
| 文档大小限制 | 1000 MB | 适配单批次粮食品质检报告的最大体积 |
| 单次处理批次 | 前20批 | 适配单轮盘点的最大处理量 |

## 容易做错的三处
- 工作流执行时出现工具调用失败报错，返回字段为空。原因是未通过`variables`绑定出入库单据的必填字段，导致节点无法获取业务数据。
- 工作流处理多批次数据时重复加载历史文档。原因是未配置文档过滤规则，未限定仅读取当前业务批次的关联文件。
- 工作流分支判断后未正确触发后续流程。原因是未将保质期阈值与`variables`中的入库日期字段绑定，导致判断逻辑失效。

## 怎么确认配好了
- 触发测试工作流，上传对应批次的出入库单据，检查节点是否自动启动执行。
- 查看工作流变量绑定面板，确认所有业务字段均已关联到`variables`参数。
- 模拟不同保质期的粮食品批次，验证分支判断节点是否正确触发对应流程。
- 检查文档过滤规则，确认仅当前业务批次的文件会被加载解析。
