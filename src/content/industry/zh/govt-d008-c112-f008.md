# 粮食储备的业务办理流程引导：文档解析与分块

## 这个品类的数据长什么样
粮食储备的业务文档主要来源于国储粮管理系统、地方粮库的业务台账、入库检验报告、轮换审批单等。数据更新节奏随业务流程变动，入库、出库、轮换操作时会实时更新，日常库存台账按周同步。文档结构包含固定业务字段，如粮食品种、储存仓号、实际库存量（单位：吨/公斤）、批次编号、检验结果，同时附带非结构化的业务说明文本，部分历史档案为扫描生成的PDF格式，存在排版偏移问题。

## 这些特征在「文档解析与分块」这一环带来什么约束
固定业务字段要求分块不能破坏批次、仓号等关联信息，避免同一业务单元被拆分到多个分块中。非结构化说明文本与结构化字段混合排版，需要解析时保留两者的对应关系。扫描生成的PDF存在表格错位、文字偏移，需要针对性的解析适配。大型季度储备报表可能包含多页明细，解析时长较长，对超时设置提出要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 粮食储备文档包含结构化字段与长文本说明，该区间可保留批次、仓号等关键信息不被拆分 |
| `chunkSplitter` | 按段落+标题拆分 | 文档存在「入库通知」「检验结果」等标题段落，按标题拆分可保留业务逻辑完整性 |
| `customPdfParse` | 开启 | 部分粮库提交的扫描PDF存在排版偏移，自定义解析可修复表格错位、字段提取错误 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份季度储备报表包含多页明细，该时长可满足全量解析需求 |
| `chunkSettingMode` | 手动配置 | 不同业务文档（入库单/轮换计划）结构差异大，手动配置可适配各场景的分块规则 |

## 容易做错的三处
- 现象：上传扫描版入库检验报告后，解析结果中未提取到批次编号字段。原因：未在自定义解析规则中配置该业务专属字段的提取逻辑，导致解析时遗漏关键信息。
- 现象：通过HTTP组件获取的布尔类型库存状态数据，传入条件判断组件后变为空值。原因：未正确映射HTTP组件的输出字段到条件判断组件的入参，或未兼容布尔值的格式转换规则。
- 现象：单份季度储备台账解析后分块数超过3000，后续检索时无法加载完整内容。原因：未调整分块配置或未将大型文档拆分为多个小文件，导致分块数超出平台限制。

## 怎么确认配好了
- 上传一份标准入库单PDF，查看解析后的分块内容，确认每个分块都包含完整的批次号、仓号等关键业务信息。
- 查看解析任务的运行日志，确认未出现超时报错，验证`PARSE_FILE_TIMEOUT_SECONDS`配置生效。
- 测试对接HTTP组件返回的布尔值数据，确认条件判断组件可正确识别并处理该参数。
- 上传一份大型季度储备报表，查看解析后的分块总数，确认未出现异常截断或丢失内容。
