# 粮食储备的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
粮食储备业务的数据源主要包括国家及地方储备库的日常库存台账、轮换入库出库单据、质量检验报告，以及官方发布的储备管理政策文件。数据更新节奏不固定：日常库存轮换时实时更新台账明细，季度盘点后批量更新整体库存数据，应急储备调整时即时推送最新政策文件。文档结构分为三类：流程类文档包含完整的申请、审批、执行步骤，台账类文档包含储备粮品种、存储数量、所属库点等字段，政策类文档包含管理规范与执行要求。字段与单位明确，数量类字段统一使用吨、公斤作为单位，流程类字段包含审批节点、执行时限等信息。

## 这些特征在「知识库检索与召回」这一环带来什么约束
粮食储备数据的特征对检索召回带来多重约束：首先，数据包含大量带明确单位的数值字段，检索时需精准匹配数值与单位，避免因模糊匹配导致无关的库存数据混入结果；其次，流程类文档篇幅较长，分块后需保留足够上下文以完整传递办理逻辑，避免拆分后丢失关键审批步骤；日常台账与政策文档的更新节奏差异大，召回时需兼顾增量更新与全量数据的时效性，确保返回内容符合当前业务要求；另外不同类型文档的格式差异明显，需适配不同解析规则以完整提取有效信息，避免遗漏台账中的关键数值或流程中的节点要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 匹配粮食储备数据中带单位的库存数值与流程关键词，避免过低引入无关结果，过高遗漏关键办理步骤 |
| `limit` | 前8条 | 单批次召回结果覆盖不同库点的轮换流程与库存台账，避免过多结果超出上下文窗口 |
| `searchMode` | semantic + keyword | 同时匹配语义和关键词，适配混合的政策文本、实操台账与质量检验报告数据 |
| `usingReRank` | 开启 | 对召回结果按与业务办理问题的相关性重排，优先展示靠前的审批节点与执行步骤 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展业务办理中的行业简称，比如将“出库”扩展为“储备粮出库审批流程”，适配储备行业专属术语 |
| `collectionIds` | 指定粮食储备专属数据集ID | 避免召回其他品类的知识库内容，确保检索范围仅覆盖储备业务相关文档 |

## 容易做错的三处
- 现象：导入含本地图片链接的Markdown文件后，检索结果中无法显示图片，或返回报错提示“资源不存在”。原因：未将本地图片上传至FastGPT支持的在线存储服务，直接使用本地路径导致无法加载。
- 现象：导出的知识库文件仅几百KB，远小于实际上传的文档总大小。原因：未开启全量数据导出配置，仅导出了当前会话的缓存数据，或上传的文档未完成解析即执行导出操作。
- 现象：调用API添加内容到知识库分块时，返回“参数无效”报错。原因：未正确指定`collectionIds`对应的专属数据集ID，或未按要求封装业务办理的流程文本为符合格式的分块内容。

## 怎么确认配好了
- 上传一份包含储备粮库存数值（如“500吨小麦”）的测试文档，发起检索请求，验证返回结果中精准匹配数值与单位的内容占比。
- 发起包含行业简称的查询（如“轮换流程”），验证`datasetSearchUsingExtensionQuery`是否自动扩展为完整流程关键词并召回相关结果。
- 查看检索结果的排序，确认`usingReRank`开启后，审批节点类内容优先于非相关的政策文本展示。
- 调用导出接口，验证导出的知识库文件大小与实际上传的文档总大小匹配，无缺失内容。
