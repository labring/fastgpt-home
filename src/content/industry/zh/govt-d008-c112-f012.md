# 粮食储备的业务办理流程引导：部署与升级

## 这个品类的数据长什么样
粮食储备的业务办理流程数据来源于粮库内部业务管理系统、地方粮食和物资储备部门的报送数据。更新节奏为单笔业务办理完成后即时同步，批量报表每日更新。文档结构分为结构化流程字段与非结构化附件两类，结构化字段包括审批单号、库点ID、粮食品类、存储数量、办理节点等，单位涵盖吨、批次号，日期格式为YYYY-MM-DD；非结构化附件包含质检报告、出库凭证等业务材料。

## 这些特征在「部署与升级」这一环带来什么约束
结构化字段多且单位统一要求严格，部署时需配置字段校验规则，避免非标准化数据接入导致检索混乱。非结构化附件占比高，升级时需兼容原有文件存储路径，避免已有附件的检索链路失效。业务数据更新存在即时与批量双节奏，部署时需配置增量同步与全量同步双模式，适配不同场景的数据更新需求。流程节点字段固定，知识库分块需匹配流程节点文档结构，避免分块逻辑与业务流程脱节。

## 配置怎么定
本配置基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150 个连接` | 粮食储备业务包含结构化字段与非结构化附件，连接池上限需适配多任务同步需求，按实测标定 |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/grain_reserve` | 存储结构化流程字段与历史检索日志，需独立数据库实例保障数据隔离 |
| `PG_URL` | `postgresql://user:pass@host:5432/grain_flow` | 存储流程节点的状态变更记录，关系型数据库适配结构化查询需求 |
| `REDIS_URL` | `redis://:pass@host:6379/0` | 缓存校验后的字段数据与临时同步任务状态，降低数据库访问压力 |
| `STORAGE_S3_ENDPOINT` | `http://s3-grain-reserve.example.com` | 存储非结构化的质检报告、出库凭证等附件，适配粮食储备业务的文件存储需求 |
| `ROOT_KEY` | `32位随机字符串` | 用于加密敏感业务数据的访问令牌，保障数据安全 |

## 容易做错的三处
- 现象：容器启动后返回`ROOT_KEY`校验失败的报错，无法访问管理后台。原因：未生成符合要求的随机字符串作为根密钥，直接使用默认配置导致身份验证不通过。
- 现象：检索结果中出现单位不统一的库存数据，同时包含“吨”与“公斤”的表述。原因：接入数据时未配置单位统一校验规则，未标准化结构化字段的单位格式，导致知识库内容不一致。
- 现象：定时同步任务执行超时，部分流程数据未完成同步。原因：未调整`DB_MAX_LINK`参数适配批量同步的并发需求，数据库连接池耗尽导致任务中断。

## 怎么确认配好了
- 查看容器启动日志，确认无数据库连接失败、`ROOT_KEY`校验失败类报错。
- 上传测试用非结构化附件，验证对应存储路径下可正常获取文件。
- 触发一笔模拟业务数据同步任务，确认数据库中生成符合预设格式的结构化记录。
- 登录管理后台查看字段映射配置，确认已关联粮食储备业务的标准流程字段。
