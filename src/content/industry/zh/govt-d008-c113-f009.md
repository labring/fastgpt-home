# 船舶制造的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
船舶制造业务办理流程相关数据，来源包括船级社审批文件、建造工序工艺卡、报验记录表、设备配套技术文档。数据更新节奏为单项目周期内随工序节点阶段性更新，跨新船型项目时按行业标准修订。文档结构多为分章节的工序说明，字段包含工序编号、作业要求、验收标准、所需工装设备，单位多为毫米、吨、小时等工程类单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
多项目分批次的文档结构，要求模型接入时需按建造项目划分独立数据集，避免跨项目数据混淆。工程类字段的单位特异性，要求配置时需在提示词中明确单位校验规则，防止模型混淆不同工序的尺寸、重量参数。文档篇幅较长，要求调整上下文窗口参数以容纳完整工序信息。随项目更新的数据，要求配置定时同步的触发规则，保证模型调用的是最新版本的流程文档。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 船舶制造工艺文档单章节篇幅较长，需容纳完整工序信息 |
| `maxTokens` | 2000–3000 token | 业务办理流程引导的回答需覆盖完整报验步骤，避免截断 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具补充流程细节 |
| `temperature` | 0.2–0.4 | 业务流程需严谨，降低随机性以保证步骤准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署节点填写 | 适配FastGPT v4.17.0的代理配置要求 |
| `AIPROXY_API_TOKEN` | 项目专属密钥 | 隔离不同建造项目的调用权限 |

## 容易做错的三处
- 现象：调用MCP工具后模型上下文丢失，回答出现断层。原因：未将`toolChoice`配置为auto且未在提示词中明确工具调用后的上下文保留规则，导致模型重置上下文窗口。
- 现象：单轮调用耗时超过60秒，回答延迟明显。原因：`maxContext`设置过大，超出模型推理的内存阈值，或未合理配置调用超时参数。
- 现象：重排模型返回结果不符合预期，关键工艺步骤被过滤。原因：未针对船舶制造工程文档的长文本和单位特征调整重排匹配规则，导致单位不匹配的条目被错误排除。

## 怎么确认配好了
- 调用测试数据集内的工艺文档，检查模型返回的流程步骤是否包含完整的工序编号与单位信息。
- 触发MCP工具调用，查看上下文窗口是否保留了前一轮的对话内容，无断层现象。
- 监控调用日志，确认单次调用耗时在设定阈值内，无超时报错。
- 验证重排模型的返回结果，确认包含关键工艺步骤，无明显遗漏。
