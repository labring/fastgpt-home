# 通信工程建设的业务办理流程引导：向量模型与索引

## 这个品类的数据长什么样
通信工程建设的业务办理数据主要来自项目立项审批档案、管线勘测报告、施工许可文件、竣工验收台账等。数据更新节奏随项目进度推进，立项阶段生成基础信息，施工阶段同步更新进度与变更记录，验收完成后归档固化。单份文档多为结构化表单与长文本报告结合，包含项目编号、建设地点、施工周期、预算金额、审批节点等字段，单位涵盖米、平方米、万元、工作日等工程类标准单位。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配长文本勘测报告与审批文档的语义完整性，避免割裂施工流程描述 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，确保审批节点与后续要求的语义衔接 |
| 相似度阈值 | 0.72–0.80 按实测标定 | 匹配工程类文档的专业术语语义相似度，过滤低关联的非项目内容 |
| 单次搜索上限 | 前 8 条 | 适配单项目业务办理的核心信息范围，避免召回过多无关历史项目数据 |
| `maxToken` | 3500 token | 匹配业务引导场景的上下文长度需求，确保完整展示审批流程与材料要求 |
| `defaultToken` | 150 token | 适配结构化字段的短文本编码需求，保留项目编号、建设地点等关键标识的语义 |

## 容易做错的三处
- 现象：知识库显示持续训练中或重建状态超过24小时，无法触发索引切换。原因：单项目文档包含超长竣工验收报告，分块后总token数超出系统默认上限，导致索引构建流程阻塞。
- 现象：切换知识库索引时出现60秒超时报错。原因：未配置增量索引更新，全量同步包含多份历史项目的大型文档集，单次同步耗时超出系统阈值。
- 现象：特定项目文档反复出现在索引召回结果中，无法通过过滤移除。原因：未绑定项目编号作为唯一索引标识，导致同名称文档被重复索引且无法区分。

## 怎么确认配好了
- 上传单份超长勘测报告，检查分块结果是否保留完整的施工流程描述，无关键内容割裂。
- 触发增量索引更新，核对系统日志中是否仅显示新增项目的同步进度，无全量重建提示。
- 发起业务引导查询，检查召回结果是否仅包含当前项目的审批节点与材料要求，无跨项目无关内容。
- 调整相似度阈值后发起测试查询，确认召回结果的关联度随阈值变化符合预期。
