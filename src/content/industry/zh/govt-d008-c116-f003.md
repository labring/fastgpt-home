# 通信工程建设的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
通信工程建设的业务数据主要来源于通信运营商的工程立项审批台账、现场勘测记录、施工许可文件、验收备案报告等官方文档。数据更新节奏随项目进度实时调整，立项后同步更新施工节点信息，验收完成后归档锁定。文档结构以项目唯一编号为核心索引，包含施工地点、材料规格、审批节点、验收标准等字段，单位涵盖米、千瓦、件、工作日等工程专用单位，单份完整项目文档长度通常在数千字符范围。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
通信工程建设的数据以项目唯一编号为核心索引，随项目进度实时更新，要求多轮对话必须精准匹配该编号以定位对应审批信息，避免混淆不同项目内容。文档包含大量工程专用字段与单位，提示词需明确引导用户提供必要的项目标识，缩小大模型检索范围。同时，多轮对话需保留历史审批节点信息，避免重复询问基础施工参数，确保会话连贯性。结构化台账与非结构化勘测文档的混合存在，要求提示词需区分调用不同数据源，提升引导准确性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 通信工程审批文档包含多节点审批意见，过长上下文会稀释核心流程信息，按实测标定合适区间 |
| 自定义变量绑定 | `variables` 绑定项目编号、施工材料规格 | 通信工程数据字段专业且分散，通过变量直接调用结构化台账，减少大模型理解成本 |
| `chatId` 配置 | 绑定项目唯一标识 | 确保同项目多轮对话上下文关联，避免跨项目信息混淆 |
| 历史对话保留数 | 保留最近20轮 `messages` 内容 | 通信工程审批流程节点多，保留历史对话可避免重复询问基础信息 |
| 提示词模板 | 固定包含“请提供项目编号以获取对应审批流程” | 通信工程项目唯一，通过项目编号快速定位数据，减少用户无效输入 |
| 多轮会话超时时间 | 600 秒 | 工程办理流程涉及跨部门审批，需预留足够时间完成信息同步 |
| 单次上传文件上限 | 1000 MB | 工程勘测图纸等文件体积较大，按工程文件通用存储标准设置 |

## 容易做错的三处
- 现象：多轮对话中重复询问相同的工程基础信息，原因：未正确绑定`chatId`，导致每次会话上下文独立，无法保留历史输入。
- 现象：AI对话节点输出内容直接混入业务办理流程引导的返回结果中，原因：未配置节点的输出过滤规则，导致调试日志被带入正式返回，对应社区常见的调试输出残留问题。
- 现象：会话中无法获取指定项目的审批流程信息，原因：未通过`variables`绑定项目编号变量，大模型无法精准定位对应项目数据。

## 怎么确认配好了
- 发起测试会话，输入任意工程相关问题，核对返回内容是否包含绑定的自定义变量字段，确认变量调用正常。
- 发起两次连续会话，使用同一项目编号，核对两次会话是否保留历史对话信息，确认`chatId`配置正确。
- 上传工程相关文件，核对AI是否能解析文件内容并关联至业务流程，确认文件上传功能配置正常。
- 模拟多轮审批节点询问，核对AI是否仅返回与工程办理流程相关的内容，确认提示词约束生效。
