# 通信工程建设的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
通信工程建设的数据主要来源于项目立项审批系统、施工过程台账、验收备案文档及现场巡检记录。数据更新节奏随项目节点推进，立项阶段每周同步基础信息，施工阶段每日更新进度与材料领用数据，验收阶段汇总全流程文档。单份文档包含项目编号、施工区域、材料清单、进度节点、审批状态等字段，部分字段带有专属单位，如施工路段长度以千米为单位，材料用量以吨为单位，审批耗时以天为单位。

## 这些特征在「工作流编排」这一环带来什么约束
通信工程建设的数据来源分散于多个业务系统，工作流编排需配置多数据源对接节点，分别拉取立项、施工、验收阶段的信息。不同阶段数据更新节奏差异较大，需为不同数据源设置差异化的触发周期，避免重复拉取或更新滞后。部分字段带有专属单位，工作流需内置单位转换逻辑，确保跨节点数据格式统一。固定的文档结构要求工作流节点按预设字段顺序处理数据，无法随意调整节点执行顺序，否则会导致数据匹配错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源节点类型 | 按立项、施工、验收系统分别创建节点 | 匹配通信工程建设多阶段分散的数据来源 |
| `variables` 绑定规则 | 绑定项目编号、施工路段长度、材料用量字段 | 确保工作流读取的字段与业务数据结构一致 |
| 触发周期 | 立项阶段：每周1次，施工阶段：每日1次，验收阶段：每3天1次 | 适配不同阶段数据的更新节奏 |
| 单位转换逻辑 | 千米转米：乘以1000，吨转千克：乘以1000 | 统一跨节点数据的单位格式 |
| 节点超时设置 | 600 秒 | 适配通信工程数据拉取的耗时需求 |
| `nodeId` 配置 | 为每个数据源节点分配唯一标识 | 便于工作流排查异常节点与数据流转 |

## 容易做错的三处
- 工作流读取上传的通信工程建设专属Excel文件后返回空内容。原因是未按该品类Excel的固定字段结构配置`variables`绑定规则，无法匹配预设列名。
- 工作流无法获取当前项目关联的施工区域URL参数。原因是未在工作流入口节点配置变量映射，未通过`variables`获取URL参数。
- 工作流调用知识库时无法按变量选择指定的通信工程专属知识库。原因是未配置多知识库变量绑定规则，未设置按项目类型匹配对应知识库的逻辑。

## 怎么确认配好了
- 上传通信工程建设专属的Excel测试文件，核对工作流节点是否读取到预设字段的内容。
- 手动触发不同阶段的数据源节点，查看数据拉取结果是否符合预设的更新节奏。
- 传入测试URL参数，确认工作流能正确获取并映射对应的项目变量。
- 触发单位转换节点，核对数值是否按预设规则完成单位转换。
