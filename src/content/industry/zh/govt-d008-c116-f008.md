# 通信工程建设的业务办理流程引导：文档解析与分块

## 这个品类的数据长什么样
通信工程建设的业务数据主要来自项目报审文件、施工图纸说明、材料清单、验收报告、项目汇报PPT等。数据更新节奏随项目阶段变动，报审阶段更新报审表与预算文件，施工阶段更新施工日志与材料领用记录，验收阶段更新验收文档。文档包含固定格式的多行表格、长文本段落、带注释的PDF图纸，字段包含工程编号、材料型号、施工单位、验收日期等，单位涉及米、平方米、千克、工期天等。

## 这些特征在「文档解析与分块」这一环带来什么约束
通信工程建设的文档特征对解析与分块环节带来多重约束。大量结构化多行表格的材料清单，要求分块时保留单元格的行列层级与字段关联，否则无法支撑业务流程引导的精准匹配。PDF、PPT文档中夹杂非标准编码的工程术语与注释，易触发解析报错。单份文档篇幅跨度大，从几页的报审表到几十页的施工方案，分块阈值需适配不同文档长度。文档关联的项目编号、材料型号等强业务字段，分块时需保留上下文关联，避免拆分后丢失业务逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配通信工程建设文档中长段落施工说明与结构化表格的上下文关联需求，避免拆分后丢失业务逻辑 |
| `chunkSplitter` | 按段落+固定字符边界 | 适配既有长文本说明又有多行表格的文档结构，优先按自然段落拆分，不足时按字符边界补全 |
| `customPdfParse` | 启用编码自动检测 | 解决PDF文档中夹杂非标准编码文本的解析报错问题，适配工程文档中可能出现的多编码混合内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 适配大型施工方案PDF、多工作表XLSX的解析耗时需求，避免因超时中断解析 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配单份大型项目归档文档的上传需求，避免因文件过大无法解析 |
| `chunkSettingMode` | 手动配置 | 适配不同类型工程文档的差异化分块需求，避免通用配置无法匹配结构化数据的拆分要求 |

## 容易做错的三处
- 上传PPT、PDF文档时出现“the argument ‘windows-1252’ is invalid encoding”报错。未启用编码自动检测配置，直接使用默认编码解析工程文档中夹杂的非标准编码文本。
- 知识库分块后返回的结果无法关联到具体来源文档。分块配置未保留文档元数据，拆分时丢失了文档标识与分块的绑定关系。
- 上传多工作表XLSX材料清单后，分块结果出现字段混乱。未针对结构化表格配置分块规则，仅按固定字符拆分，未保留表格的行列层级关联。

## 怎么确认配好了
- 上传一份典型的通信工程施工方案PDF，检查解析后的文本是否保留了段落结构与表格内容。
- 上传一份多工作表XLSX材料清单，核对分块结果是否保留了单元格的行列对应关系。
- 触发一次问答测试，确认返回的结果是否关联到对应的来源文档信息。
- 上传单份符合最大上传限制的大型归档文档，检查解析过程未出现超时中断。
