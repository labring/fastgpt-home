# 通信工程建设的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
通信工程建设的业务办理数据主要来源于项目立项批复、施工图纸、验收规范、运维手册等文件，更新节奏随项目进度或行业标准修订调整，单次项目文档包含项目编号、建设地点、施工单位、审批文号等结构化字段，以及施工流程说明、设备参数、工程图纸等非结构化内容，字段单位包含千米、平方米、天、万元等专业工程单位，单份文档长度从数百字符到数千字符不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化字段与专业单位的存在要求检索环节需匹配字段语义与单位一致性，避免因单位不匹配导致无效召回；非结构化的工程图纸与长文本内容会增加向量嵌入的计算量，需控制召回结果的数量；分项目的独立文档要求检索需限定对应项目的数据集范围，避免跨项目的无关内容干扰；缩略语与专业术语的高频使用要求检索环节需支持扩展查询，覆盖完整专业表述。同时，图片类文档的链接需完整保留，避免召回时出现截断问题。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72-0.85 | 通信工程建设的业务问题多涉及精准的审批文号、施工参数，阈值过低会引入无关内容，过高会遗漏有效结果，按实测标定 |
| `limit` | 前8条 | 业务办理流程的问题通常涉及多步骤的审批节点，8条左右的召回结果可以覆盖主要流程节点，避免过多冗余 |
| `searchMode` | `vector` | 通信工程建设的文档包含大量专业术语与结构化字段，向量检索可以匹配语义相近的专业表述，适配专业场景需求 |
| `usingReRank` | 开启 | 通信工程建设的文档存在大量相似的施工规范内容，重排可以过滤语义关联较弱的召回结果，提升精准度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 业务办理问题常包含专业缩略语，扩展查询可以补充缩略语的完整表述，提升召回覆盖率 |
| `collectionIds` | 按当前办理项目的数据集ID填写 | 通信工程建设的业务办理通常按单个项目开展，限定数据集可以避免跨项目的无关内容干扰 |

## 容易做错的三处
- 现象：知识库返回的图片链接显示不完整，部分字符被截断。原因：导入的文档中图片链接包含未转义的特殊符号，知识库召回环节未对链接进行完整编码处理，导致输出时出现截断。
- 现象：测试工作流时，仅第一个问题能关联知识库内容，后续同类问题无知识库引用。原因：工作流未配置会话上下文传递，后续请求未携带正确的`collectionIds`参数，导致检索范围为空。
- 现象：导入中英文对照的文档后，大模型在遇到中文问题时未调用知识库内容。原因：未开启多语言检索配置，向量模型仅对单一语言的文本生成嵌入，导致中文查询无法匹配到中文对照的文档片段。

## 怎么确认配好了
- 上传一份包含项目编号、施工地点的测试文档，发起包含该编号的查询，核对召回结果中是否包含对应文档片段。
- 发起包含专业缩略语的查询，比如“FTTH施工流程”，核对是否召回包含“光纤到户”的相关内容。
- 导入一张带完整链接的工程图纸，发起包含图纸关键词的查询，核对返回的图片链接是否完整无截断。
- 连续发起3个同项目的业务问题，核对每个请求的返回结果都包含对应项目的知识库内容。
