# 通信铁塔与基础设施的业务办理流程引导：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据主要来自通信铁塔运维管理系统、基站备案登记平台，每日同步运维状态，每周更新备案信息。数据文档包含铁塔唯一编号、经纬度坐标、塔高、占地面积、备案状态、当前运维节点等字段。编号为11位纯数字格式，经纬度采用十进制坐标，塔高单位为米，占地面积单位为平方米，备案状态为待审核、通过、驳回三类枚举值。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
固定格式的铁塔编号要求多轮对话必须内置11位纯数字校验规则，避免无效输入干扰后续流程。枚举型备案状态字段要求对话仅提供预设选项供用户选择，不支持自由文本输入。每日更新的运维数据要求对话提示用户优先提供最新备案的铁塔编号，避免调用过期信息。多字段的文档结构要求多轮对话按备案、运维、审批的顺序依次收集必填字段，确保每个环节的信息完整匹配。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 会话ID绑定 | 绑定`chatId`关联单用户单次办理流程 | 确保铁塔业务办理的进度仅在当前会话内保留，避免跨用户数据混淆 |
| 对话消息顺序 | 按`messages`顺序触发节点 | 匹配业务办理的固定流程，确保用户依次提交必填字段 |
| 全局变量配置 | 绑定`variables`字段按节点分组 | 按备案、运维、审批三个节点分别管理变量，避免字段冲突 |
| 最大上下文长度 | 1200–1500 字符 | 适配铁塔业务的多字段需求，避免过长上下文干扰字段校验 |
| 对话超时设置 | 300 秒 | 预留足够时间让用户逐步输入铁塔相关的位置、编号等信息 |
| 提示词模板长度 | 600–800 字符 | 清晰列出必填字段与格式要求，避免信息过载 |

## 容易做错的三处
- 现象：嵌套工作流中的表单输入节点对话框仍显示，主工作流中则隐藏。原因：未将嵌套节点的`chatId`与主工作流绑定，导致会话上下文分离。
- 现象：对话框中无法渲染自定义网页或文生图结果。原因：未开启对话内容的富文本渲染开关，且未配置专用的图像生成节点。
- 现象：FastGPT v4.9.10版本中全局变量选项缺失。原因：该版本调整了变量管理界面布局，需在应用设置的全局变量页手动添加所需变量。

## 怎么确认配好了
- 发起一次业务办理测试，依次输入11位铁塔编号、经纬度坐标、塔高数据，检查`variables`字段是否正确收集并传递到后续审批节点。
- 切换嵌套与主工作流场景，确认表单对话框仅在非嵌套的主工作流场景下按需隐藏，嵌套场景中正常显示。
- 检查提示词模板是否包含所有必填业务字段，且明确标注字段格式要求，无模糊引导内容。
- 验证会话超时后重新进入流程，确认`chatId`关联的办理进度未丢失，可继续之前的输入步骤。
