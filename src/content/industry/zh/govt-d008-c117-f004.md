# 通信铁塔与基础设施的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
通信铁塔与基础设施的数据主要来源于铁塔运维管理系统、基站巡检台账、产权登记数据库。更新节奏分为两类：巡检记录每日同步更新，产权与站点基础信息月度更新。单条数据包含站点ID、经纬度坐标、维护日期、故障等级、当前流程节点等字段，其中站点ID为16位字符串，经纬度保留6位小数，流程节点字段为枚举类型，取值包含“待审批”“施工中”“验收完成”等。本说明基于FastGPT v4.17.0版本。

## 这些特征在「工作流编排」这一环带来什么约束
站点ID作为唯一标识的字段，要求工作流必须通过`variables`绑定外部传入的站点ID参数，避免跨站点数据混淆。多源数据同步的特性，要求工作流配置多源数据拉取节点，处理不同系统的字段格式差异。流程节点的枚举类型要求工作流的分支判断节点严格匹配系统内的枚举取值，否则会触发分支匹配失败。高精度的经纬度字段，要求数据预处理节点做格式校验，保留6位小数的精度要求。每日更新的巡检数据，要求工作流配置定时触发节点，按日拉取增量数据，避免重复处理当日记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定stationId、faultLevel字段 | 传递外部传入的站点与故障信息，实现流程定制 |
| 定时触发频率 | 每日 02:00 触发 | 匹配巡检数据每日更新的节奏，避免重复拉取当日数据 |
| 数据预处理节点 | 校验经纬度保留6位小数 | 匹配数据字段的精度要求，避免定位误差 |
| 分支判断节点 | 匹配流程节点枚举值 | 确保流程分支与系统内的流程状态对齐 |
| 超时设置 | 600 秒 | 应对多源数据拉取的网络延迟，避免工作流中断 |
| 代码运行组件 | 按实测标定 | 适配本地部署的环境依赖，避免运行报错 |

## 容易做错的三处
- 现象：工作流运行时`variables`绑定的字段为空。原因：未在触发节点配置外部参数映射，导致变量未完成赋值。
- 现象：调试工作流时出现两次思考过程输出。原因：工具调用节点与大模型节点的触发逻辑重叠，导致重复触发思考环节。
- 现象：代码运行组件报错，提示依赖缺失。原因：本地部署环境未安装对应Python依赖包，与代码本身逻辑无关。

## 怎么确认配好了
- 触发工作流并传入指定站点ID，核对`variables`绑定的字段是否正确加载到工作流节点中。
- 运行定时触发任务，核对拉取的数据是否为当日更新的巡检记录，无重复数据。
- 模拟故障等级变更，核对分支判断节点是否正确匹配流程节点枚举值，触发对应分支。
- 运行代码运行组件，核对输出结果与预期逻辑一致，无依赖报错。
