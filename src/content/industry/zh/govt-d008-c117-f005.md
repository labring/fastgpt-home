# 通信铁塔与基础设施的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
通信铁塔与基础设施的数据来源于通信铁塔运维管理平台、基站动力环境监控系统、工程立项审批档案库。实时运维数据每1分钟更新一次，工程类文档按项目建设节点按需更新，审批数据随流程流转实时更新。文档为结构化格式，包含基站唯一标识、部署位置、设备型号、当前负载、关联审批单号、维护记录编号等字段，部署位置采用十进制经纬度格式，当前负载以千瓦为单位，维护记录编号为字符串格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
品类数据的分钟级实时更新要求工具调用需兼顾时效性与资源占用，避免过长的轮询间隔导致数据过时。结构化的字段体系要求工具调用必须精准匹配字段名，不可模糊匹配或省略核心标识字段。审批数据的实时流转特性要求插件必须对接实时系统接口，不可依赖静态缓存。基站唯一标识作为核心定位字段，需在工具调用环节设置校验规则，防止无效请求占用系统资源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | 固定绑定基站运维、审批查询两类工具 | 避免自动选择工具时出现参数与品类数据不匹配的问题，适配FastGPT v4.17.0版本的工具绑定规则 |
| 插件接口超时时间 | 15-20秒 | 适配跨运维、审批系统的接口响应时长，防止超时中断 |
| `functionCall` | 开启严格参数校验 | 确保传入的字段与品类数据结构完全匹配，避免解析错误 |
| 必传参数校验 | 校验基站ID、审批单号字段格式合法 | 匹配品类数据的结构化字段要求，过滤无效请求 |
| 结果缓存时长 | 不超过1分钟 | 适配实时运维数据的分钟级更新节奏，保证数据时效性 |
| 工具调用轮询间隔 | 5分钟 | 平衡数据时效性与系统资源占用 |
| 单次调用返回结果条数 | 前3条 | 匹配品类数据的单页展示习惯 |

## 容易做错的三处
- 调用运维数据工具时返回「缺少必填参数」报错，原因是未在工具调用配置中添加基站ID作为必传校验项，导致请求未携带品类数据的核心标识字段。
- 调用审批进度查询插件时返回空结果，原因是未配置插件对接实时审批系统接口，使用了静态缓存数据，而审批进度随流程实时更新，缓存数据已过期。
- 调用图表工具生成运维负载报表时图表为空，原因是未校验传入的负载数据字段单位，导致数值与预期单位不匹配，图表渲染引擎无法正确解析数据。

## 怎么确认配好了
- 发起携带合法基站ID的工具调用请求，检查返回数据是否包含最新的运维状态字段。
- 触发审批流程节点变更，调用对应插件，检查返回结果是否同步更新为最新节点状态。
- 开启工具调用的调试日志，查看是否有必传参数校验失败的提示，确认校验规则生效。
- 调整工具调用的轮询间隔，观察数据更新时效性与系统资源占用的平衡情况。
