# 通信铁塔与基础设施的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
通信铁塔与基础设施的业务办理数据主要来源于运维工单系统、基站审批平台、巡检归档文档。数据随业务办理节点实时更新，工单类数据随流程推进同步修改状态与附件，巡检记录按周批量同步。单份文档包含基站ID、工单编号、办理环节、申请材料清单、当前进度、法定办理时限等字段，基站ID为纯数字编码，办理时限以自然日为单位，状态字段为固定枚举值。

## 这些特征在「模型接入与配置」这一环带来什么约束
通信铁塔与基础设施的业务办理数据包含固定枚举的办理状态、以自然日为单位的办理时限、精确匹配的基站ID与工单编号，且随业务节点实时更新。这些特征要求模型输出需严格匹配预设枚举值，避免生成非标准业务状态；需明确时间单位规则，防止混淆自然日与其他时间表述；召回环节需优先匹配精确字段，保障业务数据的准确性；同时需支持实时更新的工单数据快速接入，避免调用过时信息，因此配置时需针对性调整模型约束与召回逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配业务办理中完整工单、审批材料与巡检记录的长文本上下文，保障覆盖全流程信息 |
| `maxTokens` | 2000–3000 token | 限制单轮流程引导的输出长度，避免信息冗余，符合业务办理的简洁提示需求 |
| `quoteMaxToken` | 1500–2000 token | 匹配单份业务文档的平均长度，保障召回的参考材料完整且不超出上下文窗口限制 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保业务流程步骤严格匹配预设规则，避免生成非标准办理路径 |
| `AIPROXY_API_ENDPOINT` | 本地docker部署的模型地址或私有云网关地址 | 适配私有化部署的通信铁塔业务系统调用需求，避免公网访问的延迟与安全风险 |
| `AIPROXY_API_TOKEN` | 私有部署模型专属密钥 | 保障接口调用的安全性，防止未授权访问通信铁塔业务系统的敏感数据 |

## 容易做错的三处
- 现象：调用私有部署大模型时返回连接超时，界面显示「504 Gateway Timeout」。原因：未将`AIPROXY_API_ENDPOINT`配置为私有模型的本地或虚拟私有云地址，导致请求无法到达目标模型服务。
- 现象：classify模块配置后无法选择模型，发布后却可正常运行。原因：未在模型接入环节绑定对应私有部署的索引模型与对话模型，仅在工作流发布时才加载了配置信息。
- 现象：本地部署的M3E索引模型调用失败，返回「无效模型路径」。原因：未在FastGPT配置中正确指定私有索引模型的部署路径，导致无法加载本地嵌入模型文件。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本。
- 发起模拟的基站业务办理查询，检查模型返回的流程步骤是否匹配预设的枚举状态与办理时限规则，验证模型输出格式约束生效。
- 查看FastGPT的模型调用日志，确认私有模型的接口请求能正常连通，无连接超时或权限报错，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确。
- 上传一份真实的通信铁塔业务工单文档，测试召回结果是否包含完整的申请材料与办理环节信息，验证`quoteMaxToken`与`maxContext`的配置适配文档长度。
- 调整`temperature`参数并生成多轮回复，观察生成内容的一致性，确认模型输出的随机性符合业务引导需求。
