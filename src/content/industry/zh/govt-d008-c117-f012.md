# 通信铁塔与基础设施的业务办理流程引导：部署与升级

## 这个品类的数据长什么样
通信铁塔与基础设施的业务数据来源包括铁塔运维管理平台、基站状态监测系统、场地租赁台账。数据更新节奏为实时上报基站运行状态、每日同步租赁与运维台账。文档结构包含基站唯一标识、经纬度坐标、场地面积、运维周期、故障类型字段，单位涵盖十进制经纬度、平方米、小时、次。单条业务文档长度通常覆盖100-500字符，包含结构化字段与非结构化运维备注。

## 这些特征在「部署与升级」这一环带来什么约束
多源数据对接要求部署时配置多套数据同步规则，需通过`PG_URL`存储结构化业务数据、`STORAGE_S3_ENDPOINT`对接非结构化运维文件。高频实时数据要求升级时不能中断增量同步链路，否则会导致业务引导的基站信息滞后。字段带特定单位的特征要求部署时统一字段映射逻辑，避免单位转换错误引发引导内容偏差。业务办理需关联精准基站信息，因此升级时需保留原有知识库索引结构，防止全量数据重新索引导致的服务中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://tower_user:secure_pass@db.tower-ops.com:5432/tower_business` | 存储基站ID、场地信息等结构化业务数据，适配通信铁塔业务的结构化存储需求 |
| `STORAGE_S3_ENDPOINT` | `http://s3.tower-ops.internal:9000` | 对接铁塔运维的内部对象存储服务，存储运维日志、故障照片等非结构化数据 |
| `REDIS_URL` | `redis://:redis_pass@cache.tower-ops.com:6379/0` | 缓存高频查询的基站状态数据，提升业务引导的响应速度 |
| `FE_DOMAIN` | `https://tower-guide.enterprise.gov.cn` | 配置业务办理引导页面的访问域名，适配国央企内部访问路径 |
| `FILE_TOKEN_KEY` | `3a7f9d2c5e8b1c4d7a9f3e5b8c2d1a4f` | 生成文件访问令牌，保障基站运维文档的访问安全 |

## 容易做错的三处
- 现象：升级FastGPT v4.17.0后，前端对话窗口刷新后会话记录消失，后台数据库可查询到完整记录。原因：未正确配置`REDIS_URL`，导致会话缓存未持久化，前端会话状态依赖Redis临时存储，升级后缓存被清空。
- 现象：部署后业务办理引导无法返回准确的基站租赁信息。原因：未正确映射`PG_URL`对应的数据库字段，导致经纬度、场地面积等单位不匹配的字段无法被正确检索。
- 现象：调用业务引导接口时出现连接超时错误。原因：未调整`DB_MAX_LINK`参数，数据库连接池配置过低，无法处理高频的基站数据查询请求。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`PG_URL`、`REDIS_URL`配置可正常建立连接，返回连接成功提示。
- 上传一份基站运维文档，通过`STORAGE_S3_ENDPOINT`配置的存储服务验证文件上传与下载功能正常。
- 访问`FE_DOMAIN`配置的前端地址，确认页面可正常加载且无域名解析错误。
- 发起一次业务引导查询，输入已知基站ID，核对返回的字段与单位与实际业务数据一致。
