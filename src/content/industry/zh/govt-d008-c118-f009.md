# 金属材料加工的业务办理流程引导：模型接入与配置

## 这个品类的数据长什么样
金属材料加工的业务数据主要来自生产工单、质检报告、工艺规程与设备运行日志。数据来源覆盖从原料入厂到成品出库的全流程，其中生产工单按加工批次实时生成，质检报告随每炉或每批材料检测完成更新，工艺规程则随生产标准迭代调整。单份文档多包含炉号、批次号、加工工序参数、合格判定结果、异常处理记录等字段，单位涉及吨、毫米、兆帕、小时等工业常用计量标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
全流程多来源的数据特征，要求模型接入配置适配高频实时更新的工单数据，避免上下文刷新延迟导致的信息滞后。批次化的质检与工单数据，需要配置匹配固定字段的召回规则，确保召回结果与对应炉号、批次号绑定。长文档的工艺规程包含大量工业参数，需要限制单轮上下文长度，防止模型因上下文溢出丢失关键工序信息。多计量单位的字段也要求配置能准确识别并关联单位与参数的逻辑，避免跨批次的加工数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配工艺规程、长工单等多字段长文档的上下文承载需求，避免因上下文溢出丢失批次号、工序参数等关键信息 |
| `maxTokens` | 2000–3000 token | 匹配业务办理引导的单次回复长度需求，确保能完整输出工序步骤、异常处理方案等内容 |
| `quoteMaxToken` | 1500 token | 限制召回引用的文档片段长度，确保引用内容与业务办理流程的关联性，避免过长片段干扰核心引导逻辑 |
| `temperature` | 0.3–0.5 | 平衡业务引导的准确性与灵活性，确保模型输出的工序步骤符合工业生产标准，减少无关内容生成 |
| `AIPROXY_API_ENDPOINT` | 对应本地部署模型的接口地址 | 适配本地部署的模型，确保模型调用链路正常 |
| `AIPROXY_API_TOKEN` | 本地部署生成的认证令牌 | 完成模型接入的身份验证，防止未授权调用 |

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 容易做错的三处
- 新增模型配置后，原有同名称的模型配置在列表中消失。原因是仅使用通用模型名称作为配置标识，未结合金属材料加工的炉号、批次等字段区分配置，导致新配置覆盖旧条目。
- 模型输出内容包含「引用标记：［1］」类字样。原因是未关闭知识库引用标记的自动输出开关，导致召回的文档索引标识被直接附加在生成内容中。
- 调用时出现上下文长度超限报错。原因是未根据长文档特征调整`maxContext`参数，导致单轮上下文超出模型支持的最大长度。

## 怎么确认配好了
- 进入模型配置列表，确认所有已添加的模型配置均带有对应金属材料加工批次或炉号的标识，无重复覆盖情况。
- 发起一次业务办理引导测试，检查回复内容中未出现引用标记类字样，确认知识库引用配置已正确调整。
- 上传一份长工艺规程文档，触发模型调用，检查上下文加载正常，无长度超限报错。
- 调用本地部署的模型，确认接口返回结果正常，无认证失败提示，验证认证配置有效。
