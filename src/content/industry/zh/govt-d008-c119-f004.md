# 钢铁冶炼的业务办理流程引导：工作流编排

## 这个品类的数据长什么样
钢铁冶炼的业务办理数据主要来自生产制造执行系统（MES）、炉况监控系统与质检实验室系统。数据按炉次归档，每份文档包含炉号、钢种牌号、冶炼起始时间、目标温度区间、实时炉温、吹氩流量、出钢量、终点碳含量等字段，单位分别为字符串、牌号、ISO时间格式、摄氏度、摄氏度、立方米/小时、吨、毫克每千克。实时炉温数据每10秒更新一次，炉次全量数据在冶炼结束后1分钟内同步，质检数据在取样后4小时内完成更新。

## 这些特征在「工作流编排」这一环带来什么约束
钢铁冶炼业务数据的实时性与强关联特性，对工作流编排带来多项约束。实时炉温的高频更新要求工作流配置合理的变量拉取间隔，避免数据滞后影响流程判断。各字段间的强关联（如吹氩流量与终点碳含量直接相关）要求工作流节点按业务逻辑设置依赖关系，确保仅在上游数据完备时触发下游节点。质检数据的延迟更新特性，要求工作流配置等待节点与异常分支，处理未按时同步的质检结果。多层业务审批的流程结构，要求工作流支持分支式节点触发，适配不同异常场景的处理路径。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定炉号、实时炉温、吹氩流量三类变量，更新间隔设为10秒 | 钢铁冶炼实时数据每10秒更新一次，需同步最新采集值到工作流 |
| 节点触发条件 | 按`nodeId`绑定的上游节点输出结果触发 | 确保工作流按业务逻辑顺序执行，避免无依赖节点提前运行 |
| 超时处理时长 | 4小时 | 匹配质检数据的最长更新延迟，确保等待数据完备后再执行后续审批 |
| 表单字段配置 | 设置炉号、异常类型、处理人字段，开启必填校验 | 明确关联对应炉次，规范异常处理的记录信息 |
| 上下文传递上限 | 前8条历史交互记录 | 适配钢铁冶炼业务的多层交互场景，保留关键节点的上下文信息 |
| 异常分支规则 | 当实时炉温超出目标区间时触发参数调整分支 | 匹配炉况异常的处理逻辑，实现流程的动态分支 |

## 容易做错的三处
- 现象：工作流对外发布接口后，调用时返回“参数缺失”报错，日志显示全局变量未被带入接口入参。原因：未在`variables`配置中绑定需要传递的全局变量，或未指定接口入参与变量的映射关系。
- 现象：工作流运行多层分支流程时，部分分支未触发询问节点，返回的交互结果条数不符合预设的业务路径。原因：未正确配置`nodeId`的触发依赖，导致分支节点未绑定上游输出的条件参数。
- 现象：自定义变量拼接后与业务文档内容不一致，系统提示无法新增该变量。原因：未按钢铁冶炼业务数据的字段格式配置变量，或变量命名未匹配系统识别的规则。

## 怎么确认配好了
- 进入FastGPT v4.17.0的工作流`variables`配置页面，核对绑定的变量是否包含炉号、实时炉温等业务所需字段。
- 发起模拟调用，传入测试炉次的参数，检查工作流是否按配置触发对应节点并正确传递变量。
- 模拟炉温超出目标区间的异常场景，检查是否弹出对应询问节点并生成正确的分支流程。
- 等待4小时后，检查工作流是否自动触发等待质检数据的节点并完成后续流程。
