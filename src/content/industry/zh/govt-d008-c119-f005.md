# 钢铁冶炼的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
钢铁冶炼的业务数据来源于生产现场的PLC控制系统、制造执行系统（MES）以及物料质检台账，更新节奏随生产工序推进实时变动。单条数据包含炉号、冶炼温度、工序时长、成分含量、成品标识等字段，字段单位包含摄氏度、分钟、质量百分比，文档为结构化时序数据表，每条数据绑定唯一的生产批次号。

## 这些特征在「工具调用与插件」这一环带来什么约束
实时采集的生产参数要求工具调用的响应延迟需匹配工序节奏，避免因等待过久打断冶炼流程。结构化的字段格式要求插件输入输出严格绑定指定字段，无法兼容非结构化的自由文本解析。绑定生产批次的设计要求工具调用时需先校验当前批次标识，避免跨批次调用错误数据。高频更新的特性要求插件需配置动态拉取逻辑，防止流程引导使用过期参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配钢铁冶炼多工序的动态流程引导，自动匹配对应业务工具 |
| `functionCall` | 强制字段对齐 | 匹配钢铁冶炼数据的结构化特征，避免输入输出格式解析错误 |
| 工具调用超时时间 | 30–60 秒 | 匹配冶炼工序单次操作的常规时长，防止流程引导中断 |
| 插件数据拉取间隔 | 每 10–30 秒 | 适配实时生产数据的更新节奏，确保使用最新工序参数 |
| 批次关联校验 | 开启 | 绑定当前生产炉号，避免跨批次调用错误数据 |

## 容易做错的三处
- 现象：调用工具时返回空的流程步骤，原因：未开启批次关联校验，调用了其他生产批次的过期数据。
- 现象：导入插件时提示`internal server error`，原因：私有部署环境中插件配置的数据源地址未开放访问权限，FastGPT v4.14.1版本的插件导入缓存未清理。
- 现象：将`stream`选择为`true`后无法接收完整最终结果，原因：未配置流数据的拼接逻辑，仅读取了单次推送的片段数据。

## 怎么确认配好了
针对FastGPT v4.17.0版本，可通过以下步骤核对配置是否生效：
- 发起模拟调用，传入指定炉号的测试参数，检查工具返回的流程步骤是否匹配当前批次的工序逻辑。
- 查看插件日志，确认数据拉取间隔符合配置的10–30秒区间，无频繁拉取或超时报错。
- 开启`stream`模式发起调用，检查是否能完整接收所有推送的流程片段并拼接为最终结果。
- 切换不同生产批次的测试数据，确认批次关联校验生效，不会返回其他批次的流程信息。
