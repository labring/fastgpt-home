# 钢铁冶炼的业务办理流程引导：知识库检索与召回

## 这个品类的数据长什么样
钢铁冶炼的业务数据主要来源于内部工艺规程、设备点检日志、安全操作手册、质检报告与冶炼批次记录。数据覆盖生产全流程，更新节奏随业务调整：工艺规程随技术迭代同步更新，点检日志每日归档，安全规范按季度修订。文档多为结构化与半结构化混合，包含工艺参数（如温度、压力）、操作步骤、异常处理流程等字段，参数附带明确单位，部分文档关联炉号、车间等业务标识。

## 这些特征在「知识库检索与召回」这一环带来什么约束
工艺参数附带精确单位与业务标识，要求检索需支持参数范围匹配与字段限定，避免无关结果混入。每日更新的点检日志与高频迭代的工艺规程，要求知识库支持增量同步与实时更新配置。长文档占比高，分块后需保留上下文关联，防止断章取义。紧急安全流程文档需优先召回，要求检索可配置权重规则。不同车间的冶炼流程差异显著，要求检索可按业务域限定范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配钢铁冶炼工艺参数的精确性要求，过滤低相关检索结果 |
| `limit` | 前8条 | 覆盖单炉冶炼流程的主要环节，避免超出上下文窗口限制 |
| `searchMode` | semantic + keyword | 兼顾工艺描述的语义匹配与炉号、参数等关键词的精确匹配 |
| `usingReRank` | 开启 | 对召回结果按相关性重排，优先展示包含目标工艺参数的文档 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 钢铁冶炼术语严谨，避免扩展查询导致语义偏移 |
| `collectionIds` | 按车间/炉号指定 | 限定检索范围为当前业务对应的冶炼车间知识库集合 |

## 容易做错的三处
- 开启工具调用后无法召回知识库结果，现象为检索返回空列表或界面提示无匹配文档，原因是工具调用模式默认优先调用外部工具，未同步启用知识库检索权限。
- 检索结果包含其他车间的冶炼文档，现象为结果中出现非目标炉号的工艺规程，原因是未正确配置`collectionIds`限定检索范围。
- 检索结果未命中精确工艺参数，现象为返回的文档仅包含模糊描述，未匹配到目标温度或压力值，原因是未启用`searchMode`的关键词匹配模式，仅使用语义检索。

## 怎么确认配好了
- 查看FastGPT v4.17.0的检索配置面板，确认`similarity`、`limit`等参数的取值与预设配置一致。
- 输入包含具体炉号和工艺参数的测试查询，核对召回结果的文档来源是否在指定的车间集合内。
- 开启工具调用模式，同时发起知识库检索请求，确认两类功能均可正常触发并返回结果。
- 对比开启和关闭`usingReRank`后的检索结果排序，确认重排功能已生效。
