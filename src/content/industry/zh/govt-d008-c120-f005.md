# 铁路运营的业务办理流程引导：工具调用与插件

## 这个品类的数据长什么样
铁路运营的业务办理数据来源包括官方调度系统、售票服务接口与车站业务办理日志，更新节奏分为实时（余票、排队进度）与每日固定周期（运行图调整、车次增减）。数据文档结构包含车次标识、出发到达站点、办理时间、业务类型（售票/改签/退票/检票）、剩余额度等字段，其中车次标识为字母加数字组合的字符串，剩余额度单位为“张”，时间格式为YYYY-MM-DD HH:MM，业务类型为固定枚举值。

## 这些特征在「工具调用与插件」这一环带来什么约束
铁路业务数据的实时性要求工具调用的响应延迟不能过高，否则返回的余票、排队进度等数据会失效，导致引导流程出错。枚举类型的业务字段要求大模型调用工具时必须匹配预设值，否则会触发参数校验失败。固定的字段结构要求入参映射必须严格对应预设键名，否则无法正确获取业务数据。同时铁路业务数据存在权限限制，工具调用必须携带合法的身份校验参数，避免越权访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 铁路业务办理流程包含多个步骤，需要大模型自主选择对应工具完成引导 |
| `functionCall` | `仅允许指定函数` | 铁路业务数据存在严格权限限制，避免调用非授权工具引发安全问题 |
| 超时设置 | `10-15 秒` | 匹配铁路实时数据的返回延迟，避免因超时导致数据失效 |
| 入参变量映射 | `按预设铁路业务字段名绑定` | 铁路业务数据字段固定，需严格匹配预设键名才能正确获取数据 |
| 结果校验规则 | `过滤非枚举值的业务类型字段` | 铁路业务类型为固定枚举值，校验可避免返回无效引导信息 |

本文基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 现象：调用MCP返回的票务相关图片显示不全，日志中出现403状态码。原因：未在工具调用参数中携带铁路业务的会话身份校验字段，导致图片资源访问被拦截。
- 现象：MCP调用不稳定，界面频繁显示“工具未响应”。原因：超时设置未匹配铁路实时数据的返回延迟，默认超时过短导致请求被提前终止。
- 现象：无法将HTTP响应的入参变量添加到MCP配置中。原因：未使用系统预设的铁路业务字段名作为入参键，导致配置无法识别有效变量。

## 怎么确认配好了
- 触发模拟的业务办理请求，查看工具调用日志中是否正确携带了预设的铁路业务字段参数。
- 执行一次完整的流程引导测试，确认大模型选择的工具与当前业务节点完全匹配。
- 模拟延迟请求，验证工具调用未出现超时报错，确认超时设置符合要求。
- 查看MCP配置的入参映射列表，确认所有必填的铁路业务字段已被正确添加。
