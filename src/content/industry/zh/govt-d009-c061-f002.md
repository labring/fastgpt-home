# 会议精神摘要的党建学习助手：向量模型与索引

## 这个品类的数据长什么样
数据主要来自各级党组织发布的正式党建会议记录、学习传达文稿、领导讲话全文。更新节奏随重要党建会议的召开节点同步进行，单次文档篇幅跨度较大，多为长文本格式。单篇文档包含会议主题、召开时间、核心讲话内容、决议事项等固定字段，以单篇会议材料为基本数据存储单元，无统一固定计量单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
会议精神摘要的长文本占比高，向量索引时需要支持自适应分块，避免将连续的讲话要点拆分导致语义断裂。更新随会议节点随机触发，增量索引需要支持按文档更新时间精准同步，避免全量重建索引消耗过多资源。文档包含多类结构化字段，需要优先对核心讲话内容字段进行向量化，确保检索时聚焦关键信息。党建领域有专属专业术语，向量模型需要适配中文专业语料，避免语义编码出现偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配会议材料的长文本特性，保留单段讲话的语义完整性 |
| 重叠长度 | 100–200 字符 | 避免分块后相邻段落的语义断裂，保障检索连贯性 |
| `maxToken` | 4096 token | 适配主流中文向量模型的输入长度限制，避免截断核心讲话内容 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 过滤低相关性的检索结果，聚焦核心会议要点 |
| 单次搜索上限 | 前 8 条 | 控制返回结果数量，避免上下文过长超出模型处理范围 |
| `defaultToken` | 2048 token | 配置默认上下文窗口长度，适配党建专业术语的语义编码 |

## 容易做错的三处
- 现象：从旧版本升级到FastGPT v4.17.0后，原有党建会议材料无法被检索到。原因：未执行增量索引或全量重建索引，新版本的索引存储格式与旧版本存在差异，原有索引数据无法被正常读取。
- 现象：上传Excel格式的会议纪要文件后，向量化后的检索结果出现内容错位。原因：未配置Excel文件的列匹配规则，系统默认读取全部单元格内容，导致非核心的会议辅助类字段混入向量化语料。
- 现象：调用m3e向量模型时出现接口连接失败。原因：未正确配置向量模型的调用参数，仅尝试通过oneapi渠道接入，未适配其他代理服务的请求格式。

## 怎么确认配好了
- 上传单篇长文本会议材料，查看分块预览界面，确认分块长度符合预设值，且相邻分块存在重叠内容。
- 发起针对会议核心要点的检索请求，查看检索结果的相似度得分，确认得分落在预设的阈值区间内。
- 上传多份同主题的会议材料，测试搜索引用合并功能，确认重复条目被正确去重。
- 切换向量模型为m3e，发起检索请求，确认接口调用成功并返回有效结果。
