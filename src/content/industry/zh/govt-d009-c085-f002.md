# 学习测验出题的党建学习助手：向量模型与索引

## 这个品类的数据长什么样
党建学习测验出题的数据源来自内部党建学习库、官方公开党建文献、主题教育配套材料。更新节奏随官方政策发布、内部学习计划调整，无固定周期。单条数据对应一套测验题目，包含题干文本、选项集合、正确答案、解析文本，附加所属学习专题标签与发布日期字段。每条数据为独立测验单元，无统一固定长度，字段均为纯文本或分类标签格式，无特殊计量单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
党建测验题目与解析的结构化特征，要求向量建模时需保留题干与解析的语义关联，避免分块拆分破坏题目完整性。非固定更新频率要求索引支持增量更新，避免全量重建带来的资源消耗。专属的党建专业术语，要求向量模型适配中文政务与党建领域的语义特征，否则会出现检索偏差。结构化字段附带的专题标签，可结合向量检索实现精准过滤，但需注意元数据与向量内容的关联匹配逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配党建题目与解析的常规文本长度，避免拆分题干与解析的语义关联 |
| 重叠长度 | 100–150 字符 | 保留分块间的上下文衔接，防止题目关键信息被截断 |
| 相似度阈值 | 0.75–0.85 | 匹配党建专业术语的语义相似度，过滤低相关的检索结果 |
| 单次召回上限 | 前 10 条 | 控制检索结果数量，适配测验出题的选题需求 |
| `maxToken` | 4096 token | 适配党建文本的整体长度，避免超出模型上下文限制 |
| `defaultToken` | 256 token | 控制单条分块的向量化输出长度，平衡检索精度与存储成本 |

## 容易做错的三处
- 现象：索引任务显示完成，但检索时无匹配结果，后台日志显示分块字段为空。原因：未正确关联党建题目与解析的原始文本字段，导致向量化环节无有效内容可处理。
- 现象：使用bge-m3向量模型时，语义检索返回的相似度得分普遍高于0.9，超出正常区间。原因：未针对党建专业术语调整向量模型的归一化参数，导致余弦值计算异常。
- 现象：PostgreSQL数据库中仅存储向量数据，无原始题目文本备份。原因：未开启原始文本持久化配置，仅保留了向量化后的向量字段。

## 怎么确认配好了
- 查看FastGPT v4.17.0的索引管理页面，确认分块统计数量与上传的党建题目数量匹配。
- 执行单次检索测试，核对返回结果的相似度得分处于预设区间，无异常偏高或偏低的情况。
- 检查PostgreSQL数据库，确认同时存储了原始题目文本与向量化后的向量数据。
- 触发增量更新任务，验证新上传的党建题目能被正常索引并纳入检索范围。
