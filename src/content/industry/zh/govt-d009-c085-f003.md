# 学习测验出题的党建学习助手：多轮对话与提示词
本文基于FastGPT v4.17.0版本整理该品类的多轮对话与提示词配置说明。

## 这个品类的数据长什么样
党建学习测验出题的基础数据来源于官方公开的党建学习规范文本、党内政策文件、党史学习资料及主题教育指定读物。更新节奏随党内最新学习要求调整，无固定周期，每次更新覆盖对应主题的知识点条目。文档按主题分类为结构化文本块，每个条目包含主题分类、知识点原文、测验题型要求、标准答案依据四个核心字段，数据单位为条，每条对应一个可生成测验题目的基础知识点单元。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
官方权威数据源要求提示词必须严格对齐官方表述，避免出现与党内政策不符的内容。无固定更新周期要求多轮对话可动态加载最新知识点数据，保证生成的测验题目符合当前学习要求。按主题分类的文档结构要求多轮对话需关联历史对话的主题上下文，避免出题偏离当前学习主题。包含题型要求的字段要求提示词需精准提取字段信息，生成符合指定题型的测验题目，同时需处理多轮对话中题型的延续或调整需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | `8000–12000 字符` | 党建学习资料文本较长，需覆盖多轮对话的上下文记忆，避免知识点断裂 |
| 问题优化 | 开启 | 测验出题需要精准匹配知识点，优化后可减少偏离主题的题目生成 |
| `messages` 参数配置 | 保留前 20 条对话消息 | 党建测验出题需关联历史对话的主题，过多轮次会增加不必要的计算负担 |
| `variables` 参数配置 | 传入 1–3 个党建主题变量 | 精准匹配对应知识点生成符合主题的测验题目 |
| `chatId` 参数配置 | 按用户会话绑定唯一标识 | 实现多轮对话的上下文记忆，保证同一用户的测验出题连贯 |

## 容易做错的三处
- 现象：调用简易应用接口时无法直接输出测验题目，必须通过对话交互才能生成结果。原因：未正确配置对话接口的输出模式，混淆了单次生成与多轮对话的调用逻辑。
- 现象：引用党建知识库时生成的题目使用非中文表述，不符合使用场景。原因：未在提示词中明确指定中文语言要求，或未正确绑定知识库的中文数据源。
- 现象：多轮对话后出现上下文丢失，无法延续上一轮的出题主题。原因：未为每个会话绑定唯一`chatId`参数，导致会话上下文未被正确保存。

## 怎么确认配好了
- 发起连续对话，依次提出不同党建主题的出题需求，核对生成的题目是否与当前对话主题一致。
- 传入`variables`参数后，核对生成的题目是否覆盖指定的党建知识点。
- 保留会话多轮，核对生成的题目是否延续上一轮的对话上下文，未出现主题跳转。
- 查看接口返回的会话数据，确认`chatId`参数被正确绑定，上下文未被重置。
