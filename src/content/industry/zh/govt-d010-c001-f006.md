# 12345热线工单办理的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
通常包含诉求登记单、派单记录、办理答复、回访记录、延期申请、退回说明及知识库条目等文档。数据来源包括12345热线平台、承办单位业务系统、官方知识库、回访评价数据及地方热线管理相关文档。数据更新频率为每日，部分实时流转的工单会随办理进度同步更新。文档多包含诉求编号、承办单位、答复内容、办理进度、回访结果等字段，部分文档为结构化表单格式，部分为半结构化的办理说明文本。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散且每日更新，溯源环节需精准匹配不同数据源的标识规则，避免混淆不同工单的办理记录。结构化的工单文档需提取固定字段作为溯源依据，半结构化文本则需关联对应的诉求编号才能定位原始内容。实时更新的工单数据要求溯源配置支持动态拉取最新内容，否则可能返回过期的办理信息。不同承办单位的文档格式存在差异，溯源逻辑需适配多种字段结构，否则无法准确关联答复内容与原始工单。另外，溯源结果的准确性直接影响工单办理的合规性，错误的溯源会导致答复被退回重办。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配，针对12345热线工单办理场景优化：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配12345工单文档的平均长度，避免截断关键溯源信息 |
| `responseData` | 开启引用溯源开关 | 启用后可生成cite引用id，匹配工单的诉求编号与原始文档 |
| `detail` | 开启详细溯源 | 展示原始文档的完整字段，满足党建学习问答的溯源要求 |
| 单次溯源上限 | 前3条 | 控制返回的溯源条目数量，避免内容过载影响答复可读性 |
| 数据源分类规则 | 按工单归属划分 | 区分12345热线平台数据与承办单位业务系统数据 |

## 容易做错的三处
- 现象：调用对话接口未返回cite引用id字段。原因：未开启`responseData`配置项中的引用溯源开关，导致接口未生成引用标识。
- 现象：查看聊天回答的知识库引用时出现报错。原因：未配置工单数据与知识库条目的关联映射，无法定位原始文档的存储路径。
- 现象：溯源返回的内容被截断，无法显示完整的办理答复。原因：`quoteMaxToken`设置值过小，超出配置的token上限后自动截断了溯源内容。

## 怎么确认配好了
- 发起一条测试工单相关的查询，检查接口返回结果是否包含cite引用id字段。
- 打开聊天界面的引用卡片，确认每个溯源条目都标注了对应的工单编号或知识库条目名称。
- 调整`quoteMaxToken`的取值，验证返回的溯源内容长度是否符合预期，无截断情况。
- 查看后台日志，确认溯源请求成功拉取了对应数据源的最新数据，无超时或匹配失败记录。
