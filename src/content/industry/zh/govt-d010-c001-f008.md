# 12345热线工单办理的党建学习问答：文档解析与分块

## 这个品类的数据长什么样
这个品类的数据通常来自12345热线平台、承办单位业务系统、官方知识库、群众回访评价数据及地方热线管理相关文档。日常处理的文档包含诉求登记单、派单记录、办理答复、回访记录、延期申请、退回说明与知识库条目。数据更新节奏为每日更新，核心字段涵盖诉求编号、承办单位、办理时限、群众诉求内容、答复口径等，部分文档为结构化表格，部分为非结构化文本，无统一固定格式。

## 这些特征在「文档解析与分块」这一环带来什么约束
多源异构的数据来源要求解析模块同时支持结构化表格与非结构化文本的解析，适配不同格式的工单文档。每日批量更新的数据需要控制单文件解析时长，避免整体流程阻塞。不同文档的字段差异要求分块逻辑适配内容结构，例如诉求登记单需按诉求与派单信息拆分，而答复文档需保留完整答复口径的上下文关联。同时工单数据关联性强，分块时需保留相邻工单的责任单位、办理进度等关联信息，避免拆分后丢失关键内容，影响党建学习问答的上下文准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配工单类文档的单条诉求或答复的长度，避免拆分后关键信息断裂 |
| `chunkSplitter` | 按段落+语义边界 | 适配非结构化的答复文本与结构化的登记单字段，保留内容逻辑完整性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 匹配每日批量工单文档的处理时长，避免小文件超时或大文件处理不足 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 兼容批量导出的工单汇总表格与多页答复文档的上传需求 |
| `customPdfParse` | 启用OCR模式 | 部分纸质工单扫描件转为的PDF文档需识别文本内容，适配非可编辑PDF场景 |
| `chunkSettingMode` | 手动配置 | 针对不同类型工单文档（表格/文本）调整分块规则，满足党建学习问答的上下文关联要求 |

## 容易做错的三处
- 上传Excel格式的诉求登记单后，解析结果出现字段缺失或为空。原因是未启用结构化表格解析适配规则，默认分块逻辑未识别表格列与行的对应关系，导致数据无法完整提取。
- 上传批量工单汇总文档后，界面显示请求失败，解析时长超过2分钟。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足，导致大体积文件未完成解析即被终止。
- 上传知识库条目文档后，训练数据缺失部分答复口径内容。原因是`chunkSize`设置过小，将完整答复拆分为多个独立块，导致关联的责任单位、办理时限等上下文信息被拆分至不同块中，训练时丢失关联关系。

## 怎么确认配好了
- 上传单份Excel格式的诉求登记单，检查解析后的文本是否包含完整的诉求编号、承办单位、群众诉求内容等字段，确认结构化解析生效。
- 上传一份500 MB以内的多页PDF答复文档，查看解析进度是否在`PARSE_FILE_TIMEOUT_SECONDS`设定的时长内完成，无超时报错提示。
- 调整`chunkSize`为不同区间，上传同一份答复文档，对比分块结果，确认相邻块之间保留了关联的责任单位与办理进度信息。
- 检查FastGPT v4.17.0的后台上传设置，确认`UPLOAD_FILE_MAX_SIZE`大于待上传的最大文档体积，无文件大小限制报错。
