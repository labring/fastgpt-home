# 12345热线工单办理的党建学习问答：部署与升级

## 这个品类的数据长什么样
该品类的数据来源包含12345热线平台、承办单位业务系统、内部党建与热线管理知识库、回访评价数据及地方热线管理规范。数据更新频率为每日，日常文档涵盖诉求登记单、派单记录、办理答复、回访记录、延期申请、退回说明及知识库条目。数据字段包含诉求编号、承办主体、诉求内容、办理状态、答复内容、评价结果等，不同文档对应不同的结构化或非结构化字段，整体以工单为核心进行关联整合。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据来源分散且每日高频更新，部署时需配置多数据源的同步连接，避免因单连接池过载导致同步中断；文档结构多样，需适配不同字段的分块与索引规则，无法采用统一的分块策略。升级时需兼容旧版的工单数据格式，避免因格式变更导致历史工单无法检索；同时因数据涉及政务服务场景，需保障存储与传输的合规性，部署的存储节点需符合政务数据安全相关要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–20 个连接 | 适配每日高频的工单数据同步请求，避免连接池耗尽影响业务 |
| `MONGODB_URI` | 本地专线加密连接字符串 | 对接12345热线平台的工单存储数据库，保障敏感数据传输安全 |
| `PG_URL` | 承办单位业务系统只读数据库地址 | 同步派单记录、办理答复等结构化业务数据 |
| `REDIS_URL` | 本地高可用缓存地址 | 缓存高频查询的热线管理办法条目，降低数据库访问压力 |
| `STORAGE_S3_ENDPOINT` | 政务云合规存储节点地址 | 存储诉求登记单、回访记录等敏感业务文档，符合政务数据存储规范 |
| `FILE_TOKEN_KEY` | 随机生成的32位字符串 | 生成文档访问令牌，限制非授权用户查看敏感业务文件 |

## 容易做错的三处
- 知识库调用时弹出“无可调用的嵌入模型”报错，原因是未将嵌入模型的对接配置正确写入系统环境变量，导致模型无法被正常加载。
- 升级至FastGPT v4.17.0后，部分政务浏览器无法加载前端页面，原因是新版前端静态资源未适配老旧政务浏览器内核，需调整静态资源的兼容加载策略。
- 关联知识库的正确条目被检索到，但生成的答复未在正文中引用对应内容，原因是上下文窗口的配置范围未覆盖检索到的全部有效工单文档，导致关键内容被截断。

## 怎么确认配好了
- 登录FastGPT后台的数据源管理页面，查看12345热线工单、承办单位业务数据的同步日志，确认同步状态为正常且无报错记录。
- 发起一条模拟群众诉求查询，验证系统能检索到对应知识库中的热线管理办法条目，并将其纳入生成答复的上下文范围。
- 检查系统环境变量中的`MONGODB_URI`、`PG_URL`等配置项，使用数据库连接工具验证连接字符串可正常访问对应数据库。
- 使用政务内网浏览器访问配置好的`FE_DOMAIN`，确认页面可正常加载且无资源加载失败或兼容性报错提示。
