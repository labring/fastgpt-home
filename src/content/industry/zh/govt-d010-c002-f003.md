# “高效办成一件事”联办的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类的日常文档包含联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见及办结回执。数据来源为国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库与部门审批系统，更新频率为每日。数据字段通常包含事项编号、关联部门、所需材料、办理环节、时限节点等，无统一固定单位，具体字段单位随联办事项类型调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据每日更新的要求，要求多轮对话链路需支持实时调用最新数据源，避免返回过期的联办事项信息。多类文档结构的差异，要求提示词需适配清单、表单、审批意见等不同格式的内容，统一提取关键字段。跨部门联办的复杂逻辑，要求多轮对话需逐步引导用户明确事项类型、关联部门与材料清单，避免一次性输入过多信息导致上下文溢出。同时需针对部门分派、材料复用等环节的常见错误，预设提示词引导用户修正。

## 配置怎么定
本配置基于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 联办事项数据包含多部门信息，需容纳完整的事项清单、材料列表与环节说明，避免截断关键内容 |
| 单次对话超时时间 | 60 秒 | 联办事项查询需跨多个系统调用数据，60秒可覆盖多数跨部门数据拉取的耗时，避免用户等待超时 |
| `messages` 上下文管理 | 保留最近 10 轮对话 | 党建学习问答与联办事项结合咨询时，用户通常会逐步补充部门、材料等信息，10轮可覆盖完整的咨询链路，同时避免上下文过载 |
| `variables` 绑定 | 绑定联办事项清单ID、部门权限标识 | 确保对话仅返回当前用户权限内的联办事项数据，避免越权访问信息 |
| 问题优化 | 按实测标定 | 联办事项的表述通常较专业，需根据本地政务平台的常用话术调整优化逻辑，提升问答准确性 |

## 容易做错的三处
- 对话出现超时报错，界面显示“请求超时”或返回空结果，原因是单次对话超时时间设置过短，未覆盖跨部门数据拉取的耗时。
- 无法设置单个对话仅提示一次，找不到对应配置项，原因是未在`variables`绑定中开启单次提示的权限开关，或未正确配置对话链路的提示词触发规则。
- 普通对话调用时意外引入知识库内容，回复中出现联办事项清单外的无关数据，原因是`messages`上下文管理未过滤非目标知识库的内容，或配置时误关联了无关数据源。

## 怎么确认配好了
- 发起一条包含联办事项名称的咨询，检查回复中是否包含最新的联办事项清单内容，确认数据更新符合预期。
- 发起连续多轮咨询，观察上下文是否保留之前的对话信息，确认`messages`上下文管理配置生效。
- 尝试调用超出配置的上下文长度的对话，检查是否出现截断或报错，确认最大上下文长度设置合理。
- 切换不同权限的测试账号，检查回复内容是否仅包含对应权限内的联办事项，确认`variables`绑定配置正确。
