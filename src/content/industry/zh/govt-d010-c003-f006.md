# 不动产登记的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来源包括不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统及电子证照库，更新频率为每日。日常涉及的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书与不动产登记簿。数据字段覆盖权利主体信息、不动产坐落、权利类型、权属限制状态等，单份文档体量从数页至数十页不等，核心字段需与权属登记的法定要素严格匹配。

## 这些特征在「引用来源与溯源」这一环带来什么约束
每日更新的数据源要求引用溯源需同步刷新关联知识库的最新数据，避免出现权属信息滞后的问题。多系统聚合的数据源需明确标注每条引用的原始系统来源，防止混淆不同渠道的权属数据。文档体量差异大的特点要求溯源时需适配不同长度的内容片段，同时需关联到对应登记业务的唯一标识，确保溯源可定位到具体的登记案卷。权属限制状态等敏感字段的引用，需严格匹配原始凭证的字段内容，避免出现信息偏差。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配不动产登记类文档的片段长度，避免截断核心权属信息 |
| `responseData` | 包含引用ID与原始来源路径 | 满足党建学习问答中需溯源至具体登记案卷的业务要求 |
| `detail` | 开启完整内容返回 | 确保引用内容包含完整的权利主体、坐落位置等关键字段 |
| 单次召回上限 | 前5条 | 匹配不动产登记业务的关联数据源数量，避免冗余信息干扰问答准确性 |
| 最大返回字符数 | 1000–1500 字符 | 适配党建学习问答的输出长度要求，避免内容过长 |
| 同步更新周期 | 每日 1 次 | 匹配不动产登记数据的日更新频率，确保引用内容的时效性 |

## 容易做错的三处
- 工作流中的工具调用模块连接知识库后无法输出引用内容。原因是未开启`detail`配置项，导致返回内容未关联原始文档的引用标识。
- 对话输出中出现引用符号乱码，最终显示为普通引号。原因是未正确配置`responseData`的返回格式，导致引用标记的编码未被正确解析。
- 调用知识库检索后，即使问题无匹配内容仍返回引用片段。原因是未关闭无匹配时的自动生成逻辑，且未限制仅召回匹配范围内的引用源。

## 怎么确认配好了
- 发起包含明确不动产权属问题的测试对话，检查输出内容末尾是否带有可追溯的引用标识。
- 查看接口返回的`responseData`字段，确认是否包含引用ID与原始来源路径信息。
- 输入知识库中不存在的问题，验证是否未返回任何引用片段。
- 调整`quoteMaxToken`的取值，测试长文档片段的引用是否被完整保留或合理截断。
