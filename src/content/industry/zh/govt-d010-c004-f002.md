# 主动公开与政策发布的党建学习问答：向量模型与索引
本文基于FastGPT v4.17.0版本的功能逻辑编写。

## 这个品类的数据长什么样
本品类数据来源包括政府门户网站、公文系统、政府信息公开目录、政策文件库、新闻发布会材料。更新节奏为每日同步。日常文档涵盖政策文件、政策解读稿、公开目录、信息发布审批单、新闻通稿、网站栏目更新记录，包含公开属性标注、保密等级、发布时限、所属栏目等字段，单篇文档长度跨度较大，从数百字的新闻通稿到数千字的政策文件均有覆盖。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的特性要求索引支持增量同步机制，避免全量重建带来的资源消耗。多类型文档的长度跨度与结构差异，要求分块策略适配不同内容长度，防止长文本截断或短文本颗粒度过细。文档中的公开属性、保密等级字段，需要在索引环节嵌入对应过滤逻辑，防止敏感或不应公开的内容进入检索范围。跨来源的数据格式差异，需要统一的预处理流程，确保向量生成的一致性。不同文档的字段属性也要求索引元数据能够兼容各类标注信息，保证检索时的精准筛选。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配本品类政策文件、解读稿的常见长度，避免单块超出向量模型限制，保证语义完整性 |
| 重叠长度 | 200–300 字符 | 衔接相邻分块的语义，防止关键信息被截断在分块边界 |
| `defaultToken` | 1024 token | 适配主流嵌入模型的基础输入长度，平衡语义覆盖与计算开销 |
| `maxToken` | 8192 token | 适配Qwen/Qwen3-Embedding-8B的最大输入限制，支持长文档完整语义处理 |
| `defaultToken` | 512 token | 适配短文本类文档如新闻通稿的输入需求，优化小体量内容的向量生成效率 |
| 单次召回上限 | 前5条 | 匹配党建学习问答的精准检索需求，避免过多低相关结果干扰判断 |
| 元数据过滤 | 按公开属性、保密等级筛选 | 匹配本品类文档的元数据要求，防止敏感内容进入检索库 |

## 容易做错的三处
- 现象：重复配置同名嵌入模型时，新配置自动覆盖原有配置，无法保留多个同类型模型的设置。原因：系统以模型名称作为配置的唯一识别标识，未提供自定义别名区分同名称模型。
- 现象：导入数千字的政策文件后，检索结果出现语义断裂或关键信息缺失。原因：分块长度设置未适配长文档，且未开启重叠分块机制，导致核心内容被截断在分块边界。
- 现象：Excel格式的公开目录数据导入后，分块颗粒度过大，检索匹配精度不足。原因：未针对表格类文档调整分块规则，默认分块逻辑直接按行或整表拆分，未结合表头与业务字段优化颗粒度。

## 怎么确认配好了
- 查看嵌入模型配置列表，确认所有需要启用的模型均已添加，无重复覆盖的情况。
- 上传一篇本品类典型的政策文件，手动触发分块预览，检查分块长度、重叠长度是否符合预设配置。
- 配置公开属性与保密等级的过滤规则，上传带有敏感标注的测试文档，验证检索时是否被正确排除。
- 发起党建学习相关的政策类问题，查看检索结果的条数与相关性，确认单次召回上限符合预期。
