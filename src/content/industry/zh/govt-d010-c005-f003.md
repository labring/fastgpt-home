# 产权、资产与国有资本管理的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据主要来自国资监管信息系统、企业资产管理系统、产权交易所系统、评估机构报告及财务报表，更新频率为月度。日常处理的文档包括产权登记表、资产评估报告、产权转让方案、进场交易公告、资产处置审批单，包含资产权属编号、评估基准值、交易审批状态、处置流程节点等字段，单位涉及货币计量、面积、数量等不同类型。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类数据来源分散且更新周期固定，多轮对话需关联不同系统的资产权属、交易进度等上下文，避免跨会话混淆资产编号与处置节点。月度更新的资产台账要求提示词需定期同步最新合规规则与数据版本，确保问答内容匹配当前有效信息。文档包含专业评估术语与审批流程字段，多轮对话需保留历史交互中的关键资产标识，防止上下文丢失导致问答偏差。同时，资产处置相关问答需严格锚定合规流程，提示词需限定问答范围至党建学习与国资资产合规范畴，避免超出业务边界。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 适配产权类文档的长文本与多轮对话历史存储需求 |
| 单次对话历史保留轮次 | 前 10 轮 | 覆盖资产处置全流程的多轮交互场景 |
| 提示词变量绑定 | `variables` 绑定资产权属字段 | 确保问答中自动带入当前会话关联的资产编号等专属信息 |
| 多轮对话会话标识 | `chatId` 绑定会话唯一标识 | 区分不同资产项目的对话上下文，避免跨会话混淆 |
| 对话历史传递 | `messages` 携带完整历史交互内容 | 确保多轮对话中上下文的完整传递 |
| 引用文件展示开关 | 按业务场景开启或关闭 | 适配党建学习场景下无需展示源文件的需求 |
| 最大响应超时 | 60 秒 | 适配复杂资产数据查询的处理时长 |

## 容易做错的三处
- 现象：对话底部展示了未配置的源文件引用内容。原因：未在系统设置中调整引用文件展示开关，导致系统自动挂载源文件链接。
- 现象：多轮对话超出预设轮次后丢失历史上下文。原因：未正确绑定`chatId`参数，导致会话上下文未被持久化存储，跨轮次交互无法关联历史资产信息。
- 现象：问题分类模块匹配错误的资产处置流程。原因：提示词未绑定品类专属的文档字段，导致模型无法区分产权转让与资产处置的不同流程规则。

## 怎么确认配好了
- 发起包含资产编号的首轮提问，发起第二轮关联该资产的后续问题，验证对话上下文未丢失。
- 调整引用文件展示开关，发起提问后查看回复底部是否有对应源文件展示，确认开关生效。
- 配置`variables`绑定资产权属字段，发起提问后验证回复中自动带入了预设的资产专属信息。
- 发起超过预设轮次的对话，验证会话仍能保留历史交互的关键资产标识。
