# 传染病信息报告与监测的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源为中国疾病预防控制信息系统、医疗机构HIS与传染病报告系统、实验室检测系统，更新频率为每日。日常文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，核心字段涵盖病例基本信息、临床诊断结果、报告时限、订正说明、聚集性疫情关联信息等，数据需严格匹配法定传染病报告规则要求。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据每日更新且来源分散，要求模型接入配置需适配日级知识库刷新机制，避免使用过期数据。日常文档包含结构化报告卡与半结构化流调报告，配置环节需支持多类型文档的精准解析与字段提取。数据需严格遵循法定传染病报告规则，模型输出需保留原始数据字段的完整性与准确性，不得随意篡改或省略关键信息。多源数据对接需求也要求配置环节支持多系统接口的统一接入与校验，确保数据同步的一致性。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单日内多份疫情报告与流调报告的总长度，避免截断关键病例与疫情信息 |
| `maxTokens` | 4000 token | 匹配单份传染病报告卡或疫情分析报告的输出长度需求，确保完整呈现报告内容 |
| `quoteMaxToken` | 2000 token | 限制引用文档的单段长度，避免过长引用导致上下文溢出 |
| `temperature` | 0.2–0.4 | 降低随机生成概率，确保党建学习问答与传染病监测内容的输出严谨准确，符合法定报告规则 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写内部网络接口地址 | 适配无公网环境的疾控机构部署需求，确保数据交互在内部网络完成 |
| `AIPROXY_API_TOKEN` | 按实测标定 | 保障接口访问权限安全，仅允许内部系统调用 |

## 容易做错的三处
- 现象为启动oneapi容器时出现`[FATAL] failed to get`类报错，日志指向`build/model/main.go`相关行。原因是部署环境为无网络状态，未配置内部代理或离线部署方案，导致无法拉取模型或接口资源。
- 现象为接入外部对话渠道后，党建学习问答与疾控内容的输出携带大量#*等无意义标点符号，界面显示格式异常。原因是未针对文档解析后的残留标记配置清理规则，导致格式错误被带入输出内容。
- 现象为rerank模型部署后，召回结果与病例报告、党建学习内容的匹配度不符合预期。原因是未针对本品类的核心字段（如病例诊断、报告时限）配置rerank模型的匹配权重，导致召回优先级偏差。

## 怎么确认配好了
- 执行单份传染病报告卡的解析测试，核对输出字段是否覆盖病例基本信息、诊断结果、报告时限等核心内容。
- 触发日级知识库刷新任务，确认在部署环境下可正常完成数据同步与模型更新。
- 发起党建学习相关的问答测试，核对输出内容是否符合规范且未携带冗余标点符号。
- 调用模型接口查看返回日志，确认`AIPROXY_API_TOKEN`验证通过且接口响应符合预期。
