# 传染病信息报告与监测的党建学习问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自中国疾病预防控制信息系统、医疗机构HIS与传染病报告系统、实验室检测系统，更新频率为每日。日常文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，字段涵盖病例标识、诊断信息、报告时限、订正状态、聚集性事件关联信息等，所有数据严格遵循法定传染病报告规则进行结构化存储，无额外统计性加工内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的数据要求知识库检索与召回环节需支持增量同步机制，避免重复全量拉取占用系统资源。结构化文档包含多维度法定报告字段，检索时需保证字段关联信息不被拆分断裂，否则会影响病例订正、时限核对等业务场景的匹配精度。聚集性疫情报告与流调报告内容关联性强，检索需优先召回同事件下的关联文档，同时需过滤已订正的无效旧报告卡，确保召回结果为最新有效数据。法定报告规则要求召回结果需严格对应报告字段，不得出现无关内容干扰业务判断，否则可能引发业务流程错误。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体参数配置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配法定报告字段的精准度要求，避免低相似度的无关文档被召回 |
| `limit` | `前8条` | 覆盖单日内多份报告卡、分析报告的关联信息，同时控制上下文长度 |
| `searchMode` | `keyword + vector` | 兼顾关键词匹配报告编号、诊断信息与向量匹配语义内容，适配结构化文档检索 |
| `usingReRank` | `开启` | 过滤初步召回结果中的低关联内容，提升订正记录、流调报告的匹配精度 |
| `datasetSearchUsingExtensionQuery` | `开启` | 对党建学习相关的查询自动扩展疾控专业术语，适配专业场景的语义理解 |
| `collectionIds` | `指定本品类专属知识库集合` | 限定检索范围，避免混入其他品类的无关数据 |

## 容易做错的三处
- 现象：线上对话持续搜索知识库无响应，无有效返回结果。原因：未配置合理的`limit`与`similarity`取值，召回文档数量超出上下文承载上限，导致请求超时。
- 现象：知识库详情页内的知识库ID、chunk ID无法复制。原因：页面交互逻辑未绑定复制触发事件，或权限配置未开放前端复制操作。
- 现象：专业增强检索功能无法正常启用，无法触发语义扩展匹配。原因：未开启`datasetSearchUsingExtensionQuery`配置，或当前环境未开放对应功能权限，个人自建场景需确认功能开关状态。

## 怎么确认配好了
- 手动触发知识库增量同步，检查同步日志的更新时间与数据来源的每日更新频率一致。
- 输入包含具体病例编号的查询，验证召回结果中包含对应报告卡的完整字段信息。
- 开启`usingReRank`后，对比开启前后的召回结果条数，确认冗余低关联内容被有效过滤。
- 查看知识库集合的`collectionIds`配置，确认仅包含本品类的文档集合，无跨品类数据混入。
