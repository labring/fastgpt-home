# 公共数据目录与开放的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来源于地方公共数据开放平台、一体化大数据平台、部门业务数据库与电子证照库，更新频率为月度。日常管理的文档包含公共数据资源目录、数据开放清单、数据项说明、脱敏规则、接口文档与更新频率说明。数据字段包含数据项名称、唯一标识、开放条件、脱敏方式、接口地址、更新周期等，无额外自定义单位，核心围绕数据资产的可访问性与合规性展开。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
月度更新的特性要求对话系统定期同步最新的公共数据目录与开放清单，避免返回过时的信息。多源数据来源需要提示词明确限定查询范围，区分不同部门提供的数据资产。结构化的文档格式要求对话适配数据项名称、唯一标识、开放条件等固定字段的精准查询。接口文档相关的问答需要严格匹配授权边界与调用规则，脱敏规则的查询则需准确对应预设的脱敏方式，防止违规披露信息。多轮对话中需保留用户此前提及的部门、数据类型等上下文，确保连续查询的一致性。

## 配置怎么定
本章节的配置基于 FastGPT v4.17.0 版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 适配公共数据目录、接口文档等长文本的多轮对话记忆需求 |
| `messages` 格式校验 | 严格按角色与内容字段填充 | 确保对话历史被正确识别，避免上下文混乱 |
| `variables` 绑定 | 绑定当前部门、数据开放周期变量 | 实现基于用户所在部门的定向数据查询 |
| 对话历史保留时长 | 72 小时 | 匹配月度更新的数据同步周期，避免加载过期对话 |
| `chatId` 绑定 | 绑定用户会话唯一标识 | 实现多轮对话的上下文隔离，防止不同用户的对话内容混淆 |
| 单次知识库召回上限 | 前 10 条 | 适配结构化数据目录的条目数量，避免冗余信息干扰 |

## 容易做错的三处
- 对话历史无法正常导出，返回字段为空。原因是未正确绑定`chatId`参数，导致系统无法定位对应会话的存储数据。
- 无法上传附件继续对话，返回报错提示。原因是未开启针对结构化数据目录的附件解析配置，无法适配数据清单、接口文档等附件格式。
- 调用`api/v1/chat/completions`接口时，无法按指定知识库标签筛选数据。原因是未在请求参数中正确绑定`variables`变量，未传递知识库标签的关联参数。

## 怎么确认配好了
- 发起多轮对话，连续询问不同部门的数据开放情况，验证上下文是否被正确保留。
- 调用对话接口，传入指定的知识库标签参数，验证返回结果是否仅包含对应标签下的公共数据目录内容。
- 查看会话存储日志，确认`chatId`参数被正确绑定，不同用户的对话上下文未发生混淆。
- 触发月度数据同步任务，验证知识库是否会自动更新最新的公共数据开放清单与目录信息。
