# 公共数据目录与开放的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来源为地方公共数据开放平台、一体化大数据平台、部门业务数据库及电子证照库，更新频率为每月一次。日常维护的文档包含公共数据资源目录、数据开放清单、数据项说明、脱敏规则、接口文档及更新频率说明，数据字段包含数据项名称、开放范围、脱敏要求、接口地址、更新周期等结构化内容，部分文档附带接口调用权限说明与使用限制。

## 这些特征在「引用来源与溯源」这一环带来什么约束
每月更新的特性要求引用溯源环节需同步匹配数据更新周期，避免引用过期数据。结构化的目录与清单数据需精准匹配字段标识，确保溯源时能定位到具体数据项。多来源的数据资产需统一溯源链路，区分部门提供数据与平台整合数据的归属。接口文档类数据需保留调用权限关联信息，确保溯源时可验证使用合规性。同时，脱敏规则字段需在溯源时同步展示，避免泄露未脱敏的原始数据内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | 匹配公共数据目录文档的平均长度，确保完整引用单条数据项的完整说明与接口信息 |
| `responseData` | 开启 | 需返回原始数据字段与来源标识，满足党建学习问答中对数据出处的溯源要求 |
| `detail` | 完整模式 | 展示数据项的全部关联信息，包括脱敏规则、更新频率与开放条件，符合溯源的详细性要求 |
| 单次召回条数 | 前20条 | 覆盖月度更新的全部数据项范围，避免遗漏最新开放的数据资源 |
| 上下文缓存时长 | 7天 | 匹配月度更新周期，确保溯源时可关联到对应周期的目录数据 |

## 容易做错的三处
- 现象：界面展示的模型上下文条数与实际发送至调用接口的条数不一致。原因：未匹配公共数据目录的月度更新周期配置，召回了过期数据条目。
- 现象：设置了引用上限为1500 token，但超过该长度的知识库数据块仍被纳入引用。原因：未针对品类的结构化文档调整分块规则，未按数据项粒度拆分内容。
- 现象：引用的党建问答内容无法关联到具体的公共数据来源标识。原因：未开启原始数据返回配置，仅返回了加工后的摘要信息。

## 怎么确认配好了
- FastGPT v4.17.0版本下，发起党建学习问答测试，查看回答末尾的来源标识是否包含数据项名称、开放平台与更新时间。
- 调整单次召回条数为10条，验证返回的引用数据数量是否符合设定值。
- 上传一条超过预设token上限的目录文档，验证是否被正确截断或拆分后引用。
- 查看系统日志，确认返回的`responseData`字段包含完整的脱敏规则与接口地址信息。
