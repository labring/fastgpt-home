# 养老、工伤、失业待遇核定的党建学习问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的典型使用主体为社保经办机构、人社局业务科及街道社保服务窗口，日常处理的文档包括待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料。数据来源涵盖社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为每日。文档包含结构化表单字段与非结构化证明文本，涉及缴费年限、待遇核算规则、资格判定条件等核心内容，无固定统一的单文档长度。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的数据要求检索系统的知识库同步频率匹配更新节奏，避免使用过期的待遇核算规则或资格条件。多来源的文档需要按业务场景分类存储，检索时需严格限定范围，防止混入参保登记等其他社保品类的内容。结构化与非结构化混合的文档结构，要求检索兼顾语义匹配与关键词精准召回，确保缴费年限、资格条件等核心字段被优先识别。同时，该品类出错后果直接关联群众待遇与社保基金安全，检索召回的结果必须具备较高的精准度，避免遗漏关键证明材料或政策条款。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 该品类文档涉及资格判定与待遇核算，需较高语义匹配精度，过滤低相关结果 |
| `limit` | 前8条 | 该品类需关联多份证明材料，单次召回过多会增加上下文压力，过少则可能遗漏关键内容 |
| `searchMode` | 语义+关键词混合检索 | 兼顾结构化字段的关键词匹配与非结构化文本的语义理解，覆盖不同类型的文档 |
| `usingReRank` | 开启 | 进一步过滤低相关性结果，将缴费年限、资格条件等核心内容的排序提前 |
| `datasetSearchUsingExtensionQuery` | 开启 | 覆盖党建学习场景下用户提问的隐含关联表述，扩展检索覆盖范围 |
| `collectionIds` | 绑定对应品类的知识库集合ID | 限定检索范围，避免混入参保登记等其他社保品类的文档 |

## 容易做错的三处
- 检索结果包含非待遇核定类文档，原因是未通过`collectionIds`配置限定检索的知识库集合，导致跨品类召回无关内容。
- 执行检索时出现worker terminated due to reaching memory limit报错，原因是未限定`collectionIds`且`limit`参数取值过高，加载过量文档超出实例内存阈值。
- 检索结果未匹配到缴费年限相关内容，原因是未开启`datasetSearchUsingExtensionQuery`，无法覆盖用户提问中隐含的字段关联需求。

## 怎么确认配好了
- 查看FastGPT v4.17.0的知识库配置页面，确认`collectionIds`参数已填入对应待遇核定类文档的集合ID。
- 输入测试提问“失业待遇核定需要提交哪些材料”，检查返回结果是否仅包含失业保险金申领材料、缴费年限证明等品类专属文档。
- 查看检索结果的排序，确认高相关的资格条件、核算规则内容排在前列，验证`usingReRank`与`similarity`配置生效。
- 调整`limit`参数为前5条与前10条，检查返回结果条数是否符合预期，确认参数配置正常生效。
