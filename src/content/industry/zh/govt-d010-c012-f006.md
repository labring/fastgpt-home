# 养老服务机构监管的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
养老服务机构监管的日常数据来自养老服务信息平台、民政统计系统、消防检查记录、机构运营台账，更新频率为月度。日常文档包含机构备案材料、运营补贴申请、服务质量检查表、安全隐患整改台账、老人入住档案等，多为结构化表单或长文本台账，包含机构备案编号、床位数量、检查项、整改记录、补贴申请条件等字段，数据维度覆盖机构运营全流程的监管信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
月度更新的特性要求知识库需定期同步最新的监管数据，避免引用过时的备案或整改信息。长文档台账与多源数据的组合，要求溯源环节需明确区分不同系统、不同机构的文档标识，避免混淆监管对象的档案。多字段的文档结构，要求检索时需精准匹配核心字段，确保引用内容与监管事项直接相关，同时需保证引用内容的完整性，避免遗漏整改要求、补贴规则等关键信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配备案材料、整改台账等长文档的内容块边界 |
| 重叠长度 | 100–200 字符 | 避免分块后丢失跨块的上下文关联 |
| `quoteMaxToken` | 800–1200 token | 确保引用内容完整覆盖整改要求、补贴申请规则等核心信息 |
| `responseData` | 开启 | 配置返回引用来源的完整元数据 |
| `detail` | 开启 | 展示引用文档所属的系统与对应监管机构标识 |
| 单次搜索上限 | 前5条 | 匹配多源监管数据的检索需求，控制返回结果规模 |

## 容易做错的三处
- 现象：调用接口后返回的回答未附带引用来源，或引用字段为空。原因：未开启 `responseData` 配置项，未配置返回引用元数据的开关。
- 现象：长文档检索后引用内容被截断，无法完整展示整改要求或补贴申请条件。原因：`quoteMaxToken` 取值过小，未覆盖完整的核心信息块。
- 现象：动态传入知识库变量后，未匹配到对应养老机构的备案数据。原因：未将知识库变量与机构标识字段绑定，检索范围未限定到目标监管对象的档案。

## 怎么确认配好了
- 手动触发问答流程，检查返回结果是否附带来源系统与机构标识的详情。
- 上传单份养老机构备案材料，验证分块后的检索结果是否覆盖文档核心内容。
- 调用FastGPT v4.17.0的指定接口，确认返回字段中包含 `responseData` 与 `detail` 对应的元数据内容。
- 调整分块长度参数，验证检索结果的上下文关联是否符合预期。
