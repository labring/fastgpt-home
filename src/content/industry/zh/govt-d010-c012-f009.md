# 养老服务机构监管的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
这个品类的业务数据通常来自养老服务信息平台、民政统计系统、消防检查记录、机构运营台账。日常文档包含养老机构备案材料、运营补贴申请材料、服务质量检查表、安全隐患整改台账、老人入住档案。数据更新节奏通常为月度，文档字段多涉及机构主体信息、床位数量、服务记录、整改情况、补贴申请进度等，无固定统一的标准化格式，部分文档为结构化表格，部分为非结构化文本。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据源要求模型关联的知识库需匹配更新周期，避免使用过期的监管数据。多类型、非标准化的文档结构要求模型需支持多格式解析与字段识别，确保能准确提取备案、整改、补贴等核心信息。监管类数据的严肃性要求模型输出需可溯源，需配置参数保留引用来源。同时，由于数据涉及机构运营与老人照护，模型调用的稳定性与准确性直接影响监管流程，需严格配置模型渠道与密钥，避免调用失败影响业务。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 党建学习问答通常需要关联政策文件、机构监管台账等多段长文本，足够的上下文可确保模型准确匹配问题与相关内容 |
| `maxTokens` | 1500–2000 token | 党建相关回答需覆盖政策解读、监管要求与机构情况，该长度可保证回答完整且不冗余 |
| `temperature` | 0.1–0.3 | 党建学习问答需严谨准确，较低的温度可降低回答的随机性，避免生成不符合监管要求的内容 |
| `quoteMaxToken` | 2000–3000 字符 | 需引用足够的监管文档内容作为回答依据，确保回答符合养老服务机构监管的实际要求 |
| `AIPROXY_API_TOKEN` | 对应模型渠道的有效密钥 | 确保模型调用权限合法，避免因密钥无效导致渠道不可用 |
| `toolChoice` | auto | 允许模型根据问题类型选择是否调用知识库，适配党建问答中需引用政策文件的场景 |

## 容易做错的三处
- 渠道显示不可用：在FastGPT云部署中添加第三方模型渠道后，渠道状态显示不可用，但本地接口测试正常。原因是未在FastGPT的分组配置中绑定该模型渠道，导致调用时无法找到对应资源。
- 无可用渠道报错：调用模型时提示“当前分组default下对于模型gpt-4o-mini无可用渠道”。原因是默认分组未配置对应模型的有效`AIPROXY_API_TOKEN`或API端点，或密钥已过期。
- 未配置模型密钥：首次接入时提示无可用模型。原因是未填写`AIPROXY_API_TOKEN`或填入的密钥无效，无法完成模型身份验证。

## 怎么确认配好了
- 执行模型调用测试，输入党建相关问题，如“养老机构安全管理的相关要求”，检查返回内容是否包含监管文档的核心要点。
- 进入FastGPT v4.17.0的模型管理页面，查看已配置的模型渠道状态，确认显示正常且测试通过。
- 调整`temperature`参数至不同区间，对比回答的严谨性变化，确认参数生效。
- 输入包含多段监管文档的复合问题，检查模型是否能正确关联不同来源的内容并生成符合要求的回答。
