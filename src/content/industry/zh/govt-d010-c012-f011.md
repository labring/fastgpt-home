# 养老服务机构监管的党建学习问答：表单与交互

## 这个品类的数据长什么样
该品类的数据通常来自养老服务信息平台、民政统计系统、消防检查记录与机构运营台账，更新频率为月度。日常文档包含备案材料、运营补贴申请、服务质量检查表、安全隐患整改台账、老人入住档案，字段涵盖机构备案标识、床位统计项、检查记录编号、整改条目、补贴申请字段等，数据围绕养老机构运营与监管全流程生成，无固定统一的单文档格式。

## 这些特征在「表单与交互」这一环带来什么约束
月度更新的数据要求表单模块支持按固定周期同步关联的监管数据，避免使用过期信息。多类文档对应的字段差异，要求交互环节支持按业务场景切换表单字段组，减少冗余填写。跨多系统的数据来源，需要表单交互包含数据校验逻辑，核对备案信息与床位统计的一致性。同时，监管环节出错会引发补贴发放错误或安全事故，交互需设置明确的提交确认步骤，降低误操作风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 开启，按业务场景拆分字段组 | 匹配备案、检查、补贴等多类文档的字段差异，简化交互步骤 |
| `userSelect` | 开启，预设10条以内的匹配项 | 减少手动输入错误，适配机构备案编号等固定字段的快速选择 |
| 超时等待时长 | 600 秒 | 适配月度数据同步的处理周期，避免因数据量大导致交互中断 |
| 表单校验触发时机 | 提交前全量校验 | 覆盖所有字段的跨源数据核对，降低监管环节出错概率 |
| 未交互超时提示 | 自定义文案「请完成表单填写或选择对应监管条目」 | 引导未完成交互的用户继续流程，避免链路中断 |

## 容易做错的三处
- 现象：用户未完成`formInput`填写或`userSelect`选择就发送新消息，界面显示流程无法继续的提示。原因：未配置未交互超时引导，系统无法将后续消息识别为补全交互的动作，导致链路卡住。
- 现象：尝试将其他业务分支跳转至表单节点时，链路无法正常流转，保存配置后出现节点不支持跨分支调用的报错。原因：表单节点默认仅支持单链路调用，未开启跨链路复用的相关设置。
- 现象：开启输入引导并配置自定义词库后，调试预览界面出现词库加载失败的报错，无法触发表单交互。原因：自定义词库的内容未匹配养老服务监管的专属关键词，或词库文件超出系统允许的大小上限。

## 怎么确认配好了
- 模拟用户未完成表单交互就发送新消息，查看是否触发预设的未交互超时提示，确认引导文案正常展示。
- 配置跨分支跳转至表单节点，保存后测试链路流转，确认节点可被其他分支正常调用。
- 上传自定义词库后，在调试界面输入监管相关关键词，查看是否能触发对应的表单字段组。
- 模拟填写不符合跨源数据要求的内容，提交表单时确认会触发校验提示，验证全量校验逻辑生效。
