# 内控评价、审计与整改的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自企业内控系统、ERP、财务共享系统、审计管理系统、采购合同项目系统，日常文档包括内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据更新频率为年度，文档多为结构化与半结构化混合，包含整改责任主体、问题描述、佐证材料编号、销号时间等字段，无固定统一的单篇文档长度标准。

## 这些特征在「向量模型与索引」这一环带来什么约束
年度更新的低频数据要求索引构建无需高频增量同步，可采用全量刷新模式，降低系统资源占用。多源异构的文档结构要求分块策略需兼容不同格式的文本与附件内容，避免因字段混杂导致向量表征偏差。审计问题与整改台账的强关联属性，要求索引需支持跨文档关联召回，确保党建学习问答时能联动匹配问题、整改要求与佐证材料。单次处理的样本与凭证数据量较大，需限制单批次分块的token总量，避免超出模型承载上限。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的界面设置逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配审计工作底稿、整改台账等文档的单段落文本长度，避免分块过细导致语义割裂，或过粗超出`maxToken`限制 |
| 重叠长度 | 100–150 字符 | 保留跨分块的上下文关联，确保整改要求与佐证材料的关联信息不被分块截断 |
| 相似度阈值 | 按实测标定 | 适配党建学习问答中问题表述与审计文档的匹配精度，避免误召回无关整改记录 |
| 单次搜索上限 | 前 8 条 | 覆盖单轮问答所需的关联审计问题、整改措施与佐证材料，平衡召回效率与结果相关性 |
| `defaultToken` | 4096 | 适配国央企审计文档的平均长度，确保单轮问答可完整加载关联的整改台账与销号证明 |
| 重排 | 开启 | 优化党建学习问答中审计问题与整改措施的排序逻辑，提升核心信息的召回优先级 |

## 容易做错的三处
- 配置向量模型后出现接口报错，返回状态码400。原因是未针对审计文档中的结构化字段与附件文本做适配预处理，直接传入未清洗的原始数据触发模型格式校验失败。
- 索引构建后搜索结果条数不足。原因是分块长度设置过大，导致部分审计工作底稿未被完整分块入库，丢失部分包含整改要求的语义片段。
- 混淆选择向量模型类型。原因是未明确党建学习问答仅需处理文本类审计文档，错误调用通用多模态向量模型，导致匹配精度不符合业务需求。

## 怎么确认配好了
- 导入单篇典型审计工作底稿，检查分块后的文本片段是否完整保留整改要求与问题描述的核心语义。
- 发起党建学习相关的审计问题查询，核对召回结果是否包含关联的整改台账与销号证明。
- 查看索引构建日志，确认无分块失败或向量生成报错的记录。
- 调整分块长度参数，验证召回结果的相关性是否符合业务预期。
