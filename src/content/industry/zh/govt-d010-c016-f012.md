# 医保费用结算审核的党建学习问答：部署与升级

## 这个品类的数据长什么样
本品类数据来自全国医疗保障信息平台、医院HIS与医保接口、医保目录和编码库、异地就医结算平台。日常处理的文档包含医保结算清单、费用明细、病案首页、处方、拒付清单、结算对账单。数据更新频率为每日，核心字段涵盖诊疗项目与药品耗材编码、费用金额、结算状态、参保人标识等，编码类字段为固定位数数字，金额字段以元为单位，时间字段采用标准时间戳格式。

## 这些特征在「部署与升级」这一环带来什么约束
数据来源多且每日增量更新，要求部署时配置多源数据同步链路，避免全量拉取导致的计算资源占用过高。文档类型包含结构化与半结构化文件，需适配不同解析规则，升级环节需兼容新增的医保结算清单格式。核心审核环节依赖编码匹配与一致性校验，对向量召回的精度有明确要求，部署时需预留足够的计算资源。因涉及医保基金相关数据，部署需符合数据安全规范，升级环节需采用灰度发布避免影响日常结算业务。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://user:pass@host:5432/fastgpt?pool_max_size=20` | 医保数据日均增量较大，设置合理连接池大小可避免数据库连接耗尽 |
| `REDIS_URL` | `redis://:pass@host:6379/0?maxmemory-policy=allkeys-lru` | 用于缓存医保编码匹配结果，LRU策略可避免内存溢出 |
| `STORAGE_S3_ENDPOINT` | `http://minio-host:9000` | 适配医保文档的批量存储需求，兼容S3协议的本地存储服务 |
| `DB_MAX_LINK` | `20–30 个连接` | 匹配日均数据处理量，避免数据库连接被占满导致服务中断 |
| `FILE_TOKEN_KEY` | `自定义随机32位字符串` | 保障文件上传接口的访问安全，防止未授权调用 |

## 容易做错的三处
- 现象：上传医保结算清单、处方等文档后，文件解析节点无工作，界面显示文件处于未解析状态。原因：未正确配置`STORAGE_S3_ENDPOINT`，导致文件存储路径无效，解析节点无法读取目标文件。
- 现象：Docker部署后PostgreSQL容器持续重启，查看容器日志报「could not accept connection: too many clients already」错误。原因：`DB_MAX_LINK`设置值过小，或`PG_URL`未配置合理的连接池参数，导致数据库连接耗尽。
- 现象：构建FastGPT镜像时出现依赖包版本冲突报错，如「npm ERR! could not resolve dependency」。原因：未使用FastGPT v4.17.0的官方依赖清单进行安装，导致版本不匹配。

## 怎么确认配好了
- 执行`docker logs fastgpt-pg`检查PostgreSQL容器无「too many clients already」相关报错，确认`PG_URL`和`DB_MAX_LINK`配置生效。
- 上传一份简化版医保费用明细测试文件，查看应用日志显示诊疗项目编码、费用金额等核心字段提取正常，确认`FILE_TOKEN_KEY`和存储配置无误。
- 访问`FE_DOMAIN`的党建学习问答应用管理页面，验证文件上传功能可正常触发并完成解析，确认`FE_DOMAIN`配置正确。
- 查看Redis监控指标，确认缓存命中率符合业务预期，验证`REDIS_URL`的配置有效。
