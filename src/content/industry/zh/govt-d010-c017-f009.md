# 医疗机构监督与公共卫生检查的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自卫生监督信息系统、医疗机构电子化注册系统、投诉举报平台及执法检查记录，更新频率为月度。核心文档包含监督检查表、医疗机构执业许可证、整改通知书、监督意见书、处罚案卷，数据字段覆盖机构资质、人员资质、院感消毒情况、诊疗行为合规性及整改跟踪记录，未包含额外自定义统计字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据要求模型接入时配置匹配的同步周期，避免数据滞后影响党建学习问答与合规检查的时效性。多类型混合文档的输入，要求配置适配不同文档结构的处理逻辑，确保机构资质、整改记录等核心字段被准确识别。核心任务涉及合规性核对与整改跟踪，要求模型输出需关联具体文档来源，避免生成无依据结论。执法记录与投诉数据的敏感性，要求模型调用需符合公共数据安全规范，确保数据不被泄露。

## 配置怎么定
本指南适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖月度更新的多份监督文档与党建学习材料的上下文需求 |
| `maxTokens` | 2000–3000 token | 适配合规性分析与整改意见生成的输出长度要求 |
| `temperature` | 0.2–0.4 | 确保党建学习问答与合规检查的输出严谨性，避免随意性 |
| `toolChoice` | auto | 自动触发工具调用以关联具体监督文档数据 |
| `quoteMaxToken` | 1500 token | 限制引用文档的长度，避免上下文溢出 |
| `AIPROXY_API_ENDPOINT` | 按所选模型服务商提供的地址填写 | 适配模型调用的网络请求路径 |
| `AIPROXY_API_TOKEN` | 按所选模型服务商提供的密钥填写 | 完成模型调用的身份验证 |

## 容易做错的三处
- 现象：工具调用返回结果与监督文档无关，输出效果差。原因：未配置`toolChoice`为auto，或未关联本品类的监督文档数据集，导致模型无法获取合规检查所需的核心数据。
- 现象：显存占用持续上升直至溢出。原因：未限制`quoteMaxToken`的取值，导致大量长文档被同时加载，未配置显存自动释放的触发逻辑。
- 现象：OneAPI渠道列表为空，无法选择模型。原因：未正确填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或配置的模型未在对应渠道中注册。

## 怎么确认配好了
- 发起党建相关的合规检查提问，核对模型输出是否关联了监督检查表、整改通知书等本品类核心文档的引用信息。
- 查看模型调用日志，确认`maxContext`与`maxTokens`的取值未触发上下文溢出或输出截断报错。
- 测试工具调用功能，确认模型能自动调取对应监督机构的资质数据与执法记录。
- 观察显存占用情况，确认占用量在配置的安全阈值内，未出现持续上升的情况。
