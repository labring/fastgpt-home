# 双随机、一公开监管检查的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
该品类的典型数据来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库。日常生成的文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示，以及党建学习相关的监管政策解读材料等。数据更新频率为月度，需同步维护检查事项与对象库、匹配执法人员并生成任务、录入检查结果并完成公示。文档字段包含检查对象统一社会信用代码、执法人员编号、检查事项类别、整改完成状态、政策关联标签等，不同来源的数据格式存在细微差异。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的特性要求索引支持增量同步，避免全量重建带来的资源消耗。多来源、多类型文档的混合存储，需要针对不同文档设定差异化的分块规则，例如抽查结果公示需保留完整公示字段，现场检查记录可按段落拆分，党建学习相关的政策解读文档需按章节拆分以保障语义连贯性。党建学习问答的语义匹配需求要求索引的召回范围覆盖所有监管政策与执法流程相关的文档，需确保索引的召回逻辑适配党建相关的语义特征。不同文档的字段差异要求索引构建时完成统一的元数据映射，避免后续检索时出现字段缺失或匹配错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配现场检查记录、整改通知书及党建政策解读等长文本的语义完整性，符合FastGPT v4.17.0的默认分块适配范围 |
| 重叠长度 | 100–150 字符 | 避免分块后关键语义被截断，保障跨分块的上下文连贯性 |
| `defaultToken` | 8192 | 适配党建学习问答的长上下文需求，匹配主流开源与商用向量模型的输入上限 |
| `maxToken` | 16384 | 覆盖抽查结果公示、完整检查计划等超长文档的索引需求 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 平衡监管对象检索的精准度与召回率，适配党建学习问答的政策语义匹配需求 |
| 单次搜索上限 | 前 10 条 | 满足执法人员匹配、检查事项检索的基础召回需求，避免返回过多冗余数据 |

## 容易做错的三处
- 界面中索引模型选项无法正常选择，提示加载失败。原因是未正确配置索引模型的调用密钥或网关地址，部分用户使用One API中转时未正确绑定模型权限。
- 混淆索引模型与文本生成模型的配置，误将Ollama的文本生成模型作为索引模型使用，导致检索结果语义匹配度不足。原因是未明确区分两类模型的适用场景，未按照文档要求选择专用的向量索引模型。
- 增量索引更新后出现检查对象抽取不合规的情况。原因是未开启索引的增量同步校验逻辑，未同步更新执法人员名录库的关联数据，导致匹配时出现旧数据残留。

## 怎么确认配好了
- 进入FastGPT的索引管理页面，查看已配置的索引模型列表，确认目标模型已正常加载并显示可用状态。
- 上传一份标准的抽查计划文档，执行分块测试，查看分块后的文本长度与设定的分块长度区间匹配。
- 输入一条党建学习相关的监管检查问题，执行检索，查看返回结果是否包含该品类的专属文档类型，且条数符合单次搜索上限的设定。
- 触发一次增量索引同步，查看同步日志中无报错信息，且更新后的文档可正常被检索到。
