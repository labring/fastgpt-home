# 双随机、一公开监管检查的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
典型主体为市场监管、住建、生态环境等监管部门，日常文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示。数据来源为“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统、执法人员名录库，更新频率通常为月度。文档字段包含检查批次编号、统一社会信用代码、执法人员编号、检查事项条目、整改要求等，不同文档类型的结构差异明显，如抽查计划侧重计划维度，现场记录侧重单次执法细节。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源分散的数据要求溯源环节需关联多个知识库，确保覆盖监管全流程文档；月度更新的节奏要求知识库同步周期匹配更新频率，避免引用过期的抽查计划或整改通知书。不同结构的文档需适配不同的检索逻辑，确保检查对象、执法信息等核心字段被精准召回。监管执法的合规属性要求溯源必须明确标注文档来源与生成时间，否则会引发监管溯源失效的风险，同时需避免引用无关数据引发重复扰企或抽取不合规的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 需精准匹配检查对象名称、执法人员编号等核心字段，避免无关监管数据混入问答内容 |
| 单次搜索上限 | 前8条 | 双随机监管数据条目规整，过多结果会超出上下文长度，影响溯源准确性 |
| 重排 | 开启 | 监管类文档结构清晰，重排可提升高相关片段的召回优先级，适配党建学习问答对政策依据的精准引用需求 |
| `quoteMaxToken` | 1200–1500 token | 匹配单份监管文档（如现场检查记录）的有效内容长度，确保引用片段完整不截断 |
| `responseData` | 开启来源字段展示 | 满足监管执法的合规溯源要求，需在回答中附带文档类型、来源平台等标识 |
| `detail` | 开启完整溯源 | 党建学习问答需明确引用的具体文档生成时间、检查批次等信息，提升溯源严谨性 |

## 容易做错的三处
- 开启重排后引用为空，表现为知识库搜索返回结果条数为0，溯源环节无可用片段，原因是重排阈值设置过高，过滤掉了原本符合要求的低相关但合规的监管数据片段。
- 未匹配文档长度设置`quoteMaxToken`，表现为引用片段被截断，无法完整展示检查事项或整改要求，原因是参数取值未适配监管文档的实际内容规模。
- 未启用`responseData`配置，表现为回答中未附带文档来源标识，无法满足监管溯源的合规要求，原因是未开启来源数据返回的相关设置。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库配置页面，查看相似度阈值、单次搜索上限、重排开关的设置是否与预设值一致。
- 发起党建学习相关的测试提问，查看回答中是否附带对应监管文档的来源平台、文档类型等标识，确认`responseData`配置生效。
- 调整`quoteMaxToken`参数后，验证引用片段是否完整展示，无强制截断的情况。
- 对比开启重排前后的召回片段数量，确认重排功能正常运行，无异常过滤有效数据。
