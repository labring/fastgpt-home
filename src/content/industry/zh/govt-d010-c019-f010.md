# 双随机、一公开监管检查的党建学习问答：知识库检索与召回

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类的典型主体为市场监管、住建、生态环境、文旅、人社等监管部门，日常文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示及党建学习相关的执法规范文件。数据主要来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统、执法人员名录库及内部党建知识库，更新频率为每月一次。核心文档多为结构化内容，包含检查对象统一社会信用代码、检查事项类别、执法人员编号等固定字段，无额外自定义单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
月度更新的节奏使得知识库无需高频同步，采用定时全量更新即可覆盖业务需求。文档以结构化清单、执法记录及党建学习材料为主，包含固定字段，要求检索需支持按指定字段精准匹配，过滤无关内容。单条文档长度跨度大，从短条目到完整执法记录，需适配不同长度的分块规则。同时，需区分党建学习内容与执法业务内容，避免检索结果混淆两类文档，确保内容可信度与针对性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配结构化字段匹配需求，过滤低相关的非执法类或非党建内容 |
| `limit` | 前8条 | 覆盖单次检查任务涉及的对象与事项范围，避免上下文过载 |
| `searchMode` | vector + keyword | 结合语义检索与关键词匹配，适配结构化字段与自然语言查询 |
| `usingReRank` | 开启 | 对召回结果二次排序，提升高相关检查记录与党建学习材料的优先级 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 本品类文档结构固定，无需额外扩展查询词，避免引入无关内容 |
| `collectionIds` | 绑定党建学习+监管业务专属数据集 | 隔离业务数据与其他知识库内容，确保检索范围精准 |

## 容易做错的三处
- 现象：检索结果始终返回固定的前几条内容，无匹配度变化。原因：未正确配置`similarity`阈值，或强制锁定了固定召回条数，未启用语义匹配排序逻辑。
- 现象：检索结果包含大量非执法类的通用文档，无法过滤无关内容。原因：未指定`collectionIds`绑定专属数据集，检索范围覆盖了无关知识库内容。
- 现象：结构化字段如检查事项类别无法被精准匹配，返回大量不相关的记录。原因：未设置`searchMode`为vector + keyword，仅使用纯语义检索无法命中固定字段关键词。

## 怎么确认配好了
- 上传单份检查事项清单文档，输入对应查询词，核对返回结果的匹配字段是否与查询词一致。
- 调整`similarity`阈值至0.7，再次发起相同查询，观察召回结果的条数与相关性是否发生变化。
- 查看检索日志，确认仅绑定了指定的`collectionIds`数据集，未出现跨数据集的检索结果。
- 发起包含执法人员编号的查询，核对返回结果是否包含对应执法记录的内容。
