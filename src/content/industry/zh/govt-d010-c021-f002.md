# 国库集中支付与报销审核的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
本品类的核心数据来自国库集中支付系统、预算管理一体化系统、电子发票平台与合同管理系统，涵盖支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证等日常文档。文档包含预算指标、经济分类、支付金额、审批流程记录等字段，每日更新数据，单笔业务文档关联明确的资金支付与合规审核节点，同时可关联党建学习相关文本内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求向量嵌入环节适配不同格式的业务文档与党建学习文本，避免跨系统数据嵌入偏差。每日更新的频率要求索引支持增量构建与定时同步，避免全量重建带来的资源占用与延迟。文档包含明确的预算指标、经济分类等业务字段，要求索引在召回时关联对应元数据，确保召回结果与业务场景精准匹配。单笔业务关联合规审核节点，也要求索引的召回逻辑贴合合规校验的核心需求，减少无关内容的干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类单笔业务文档与关联党建文本的平均长度，兼顾嵌入精度与召回效率 |
| 重叠长度 | 100–200 字符 | 避免分块后丢失跨块的业务关联信息，如预算指标的连续描述与党建政策的连贯内容 |
| 相似度阈值 | 0.75–0.85 | 贴合本品类合规校验的高置信度要求，过滤无关召回结果 |
| `defaultToken` | 4096 | 适配主流嵌入模型的默认输入长度，覆盖单笔业务文档与关联党建文本的总长度 |
| `maxToken` | 8192 | 满足复杂场景下上下文拼接的最大长度限制，覆盖多份关联文档的完整内容 |
| 单次搜索上限 | 前10条 | 平衡召回精度与系统响应速度，符合日常审核的信息获取需求 |

## 容易做错的三处
- 现象：索引模型下拉选项为空，无法选择对应嵌入模型。原因：未配置本地嵌入模型的环境依赖，或使用的FastGPT版本未适配对应模型。
- 现象：向量召回结果条数远低于预期，无法匹配到相关业务文档。原因：分块长度设置过大，导致部分长文档无法被完整嵌入，或相似度阈值设置过高过滤了有效召回结果。
- 现象：检索结果出现无关的非业务类党建内容，未关联到具体支付审核节点。原因：未在索引时绑定业务字段与党建文本的关联关系，导致召回逻辑未贴合场景需求。

## 怎么确认配好了
- 使用FastGPT v4.17.0的向量嵌入工具上传单份典型业务文档与关联党建学习文本，验证嵌入任务无报错。
- 发起党建学习相关的合规提问，核对召回结果中是否包含对应业务文档与党建内容。
- 查看索引同步日志，确认每日增量更新任务正常执行，无超时或失败记录。
- 调整相似度阈值，验证召回结果的数量变化符合预期调整逻辑。
