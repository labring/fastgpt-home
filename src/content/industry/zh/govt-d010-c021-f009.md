# 国库集中支付与报销审核的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
本品类的业务数据来自国库集中支付系统、预算管理一体化系统、电子发票平台、合同管理系统四类系统。日常处理的文档包含支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，涵盖预算指标、经济分类、支付金额、审批节点等字段，单位包含元、批次号、日期等。数据更新频率为每日，覆盖当日提交的全部支付与报销相关业务内容，单次处理的文档体量随当日业务量波动。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征对模型接入与配置带来多维度约束。多系统来源的文档格式不统一，需配置适配不同数据源的上下文提取规则；每日更新的业务数据要求模型与向量库的同步频率匹配日更节奏，避免数据滞后；单笔支付审核需聚焦预算指标、经济分类等核心字段，模型上下文需优先保留此类关键信息；同时业务出错后果严重，要求模型输出具备高严谨性，避免生成不符合财经规范的内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 覆盖多系统的全链条业务文档，包含支付申请、合同、验收单等审核所需的全部上下文 |
| `maxTokens` | `2000–3000 token` | 控制党建学习问答与审核结论的输出长度，避免过长导致响应延迟 |
| `quoteMaxToken` | `1500 token` | 保留票据、合同等业务文档的关键片段，确保审核结论可追溯具体业务依据 |
| `temperature` | `0.1–0.3` | 降低模型输出的随机性，保障党建学习问答与审核结论的严谨性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接入地址 | 适配内部系统的网络隔离要求，确保业务数据传输安全 |
| `AIPROXY_API_TOKEN` | 填写分配的专属鉴权密钥 | 实现接口访问的身份验证，防止未授权调用 |

## 容易做错的三处
- 现象：接口返回首token时间过长，离线部署场景下总运行时间显示与在线场景不一致。原因：未针对多系统数据源裁剪上下文，`maxContext`取值过大导致模型加载上下文耗时增加，且未正确配置首token统计逻辑。
- 现象：模型输出的审核结论未引用具体业务文档片段，党建学习问答内容偏离财政审核场景。原因：未配置`quoteMaxToken`参数或取值过小，无法提取票据、合同等核心业务字段，同时`temperature`取值过高导致输出随机性增强。
- 现象：模型无法正常响应党建学习相关的审核查询。原因：`maxContext`取值过小，未覆盖必要的业务上下文，导致模型无法获取足够的审核依据。

## 怎么确认配好了
- 调用FastGPT v4.17.0的测试接口，提交包含支付申请、发票的测试数据，查看返回的上下文是否包含至少两类业务文档的核心字段，验证`maxContext`配置生效。
- 提交包含退单场景的测试数据，查看模型输出是否包含对应审核环节的校验逻辑，验证`toolChoice`配置是否正确适配工具调用。
- 调整`temperature`参数至0.1和0.3，对比两次测试回复的差异，确认取值符合业务严谨性要求。
- 检查接口鉴权日志，确认`AIPROXY_API_TOKEN`配置无误，无未授权访问的记录，验证接口鉴权配置生效。
