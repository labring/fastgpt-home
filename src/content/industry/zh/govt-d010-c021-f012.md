# 国库集中支付与报销审核的党建学习问答：部署与升级

## 这个品类的数据长什么样
该品类的数据来自国库集中支付系统、预算管理一体化系统、电子发票平台、合同管理系统，更新频率为每日。日常处理的文档包含支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，覆盖单笔资金支付的全链条合规审核所需的全部材料。数据字段包含预算指标编码、经济分类代码、支付金额、审核状态等，为结构化与非结构化混合存储的特征。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://<db-user>:<db-pass>@<db-host>:27017/fastgpt_fiscal?authSource=admin&replicaSet=rs0` | 品类数据需高可用存储，副本集配置可保障日更数据的并发读写稳定性，适配多系统对接的存储需求 |
| `REDIS_URL` | `redis://:<redis-pass>@<redis-host>:6379/0` | 缓存会话信息与向量索引结果，保障党建学习问答与审核查询的响应速度，适配高频访问场景 |
| `PG_URL` | `postgresql://<pg-user>:<pg-pass>@<pg-host>:5432/fastgpt_metadata` | 存储品类文档的元数据与审核流程记录，适配结构化数据的查询与管理需求 |
| 本地知识库分块长度 | 800–1200 字符 | 品类文档包含长文本合同与结构化发票，该区间可平衡上下文完整性与召回精度 |
| 单次召回结果条数 | 前 5 条 | 审核场景需精准匹配单笔支付的合规依据，过多结果会增加审核岗的筛选负担 |
| 会话缓存有效期 | 7200 秒 | 适配党建学习与日常审核的会话时长需求，避免频繁重新建立连接 |

## 容易做错的三处
- 现象：启动服务时出现MongoDB副本集配置错误日志，提示无法找到副本集成员。原因：未按品类数据存储需求配置副本集，或跳过了副本集初始化步骤，导致日更数据的并发读写失败。
- 现象：本地部署后上传品类文档进行知识库训练，数据处理步骤显示为空。原因：未正确配置`REDIS_URL`导致缓存失效，或`PG_URL`连接权限不足，无法读取文档的元数据信息。
- 现象：将服务打包为Docker镜像运行后，向量检索得分全部一致，无法区分文档相关性。原因：未正确挂载本地向量模型缓存目录，导致每次启动都重新初始化模型，或未适配品类文档的分块长度配置。

## 怎么确认配好了
- 执行数据库连通性测试脚本，验证`MONGODB_URI`、`PG_URL`、`REDIS_URL`的连接状态，无超时或权限报错。
- 上传单份品类文档（如报销审批单）进行知识库训练，确认数据处理步骤生成有效分段，无空值报错。
- 发起与党建学习、财政审核相关的查询，验证向量召回结果条数符合配置的单次召回上限，且结果具备相关性差异。
- 模拟每日数据同步流程，向数据库写入新的品类文档，确认服务可正常读取并处理新增数据，无异常日志。
