# 土地使用权、矿业权与国有产权交易的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据通常来自全国公共资源交易平台、自然资源交易系统、产权交易所系统及国资监管系统，更新频率为每日。日常文档包含出让公告、交易须知、竞买申请、保证金凭证、成交确认书、挂牌结果公告、产权转让说明书等，数据字段多涉及交易标的权属、限制条件、保证金规则、成交流程等，部分文档同时包含结构化标的参数与非结构化的规则说明。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的数据要求索引支持高频增量刷新，避免全量重建带来的性能损耗。混合了结构化参数与非结构化规则的文档，需要向量模型同时适配短字段与长文本的编码一致性。多来源的文档格式差异，要求索引环节具备统一的文本清洗逻辑，确保不同系统导出的内容在向量化前格式统一。需确保单条向量化片段的长度不超过`maxToken`限制，避免编码失败。权属相关内容为核心查询场景，索引需优先保留该类片段的向量权重，避免非核心内容干扰检索结果。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面逻辑制定：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类文档的常见段落长度，兼顾向量编码精度与检索效率 |
| 重叠长度 | 100–200 字符 | 避免关键权属信息被分块截断，确保检索时上下文完整 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 区分核心权属内容与非相关文本，适配党建学习问答中对精准性的要求 |
| 单次搜索上限 | 前 8 条 | 覆盖常见党建学习问答的查询场景，避免过多冗余结果干扰 |
| `maxToken` | 4096 token | 适配BGE-large等主流向量模型的最大输入长度，确保长文档片段可完整编码 |
| `defaultToken` | 2048 token | 平衡单条向量的信息密度与检索性能，符合该品类数据的平均内容长度 |

## 容易做错的三处
- 现象：导入文档后生成的知识库导出文件中仅包含index字段，无content字段。原因：未正确开启文本分段后的内容存储配置，导致仅保留了向量索引元数据，丢失原始文本片段。
- 现象：内网部署环境中调用向量模型时出现超时错误。原因：未配置内网可访问的向量模型服务地址，或未适配内网环境的请求参数。
- 现象：未调整默认分段字数时，长交易公告被过度分块，导致权属相关信息被拆分至多个片段中。原因：默认分段参数未适配该品类长文档的内容结构，未设置合理的分块长度与重叠比例。

## 怎么确认配好了
- 手动导入一份标准的产权转让说明书，查看知识库详情页中是否同时显示原始文本片段与对应的向量索引信息。
- 发起一条包含权属查询的党建学习问答测试，核对返回结果中是否包含交易标的的核心权属内容。
- 检查向量模型服务的日志，确认每日增量更新任务可正常触发并完成索引同步。
- 导出知识库的测试数据集，验证content字段是否完整存在，无缺失情况。
