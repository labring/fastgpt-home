# 学生资助与奖补审核的党建学习问答：表单与交互

## 这个品类的数据长什么样
本品类的核心数据来自全国学生资助管理信息系统、学校学籍系统、民政低保特困数据及财政支付系统，更新节奏为每学期。日常处理的文档包含家庭经济困难认定表、资助申请表、奖助学金评审表、发放名单与公示材料，数据字段覆盖学生身份标识、家庭经济状况、学籍状态、资金发放相关信息，涉及学籍号、金额、发放批次等单位，无额外统计类数字。

## 这些特征在「表单与交互」这一环带来什么约束
多源数据对接要求表单需支持跨系统数据拉取与实时校验，避免人工录入的误差；学期级更新频率要求表单的数据拉取与缓存周期匹配学期节点，防止使用过期数据影响审核准确性；多类型文档的处理要求表单按文档类别分块配置字段，减少用户填写时的信息切换负担；资金发放相关字段需绑定财政支付系统数据，确保信息与官方支付记录一致，同时交互环节需增加核验步骤，防范错发漏发引发的学生投诉与审计问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 表单字段分组 | 按家庭经济困难认定表、资助申请表、奖助学金评审表分为3组 | 匹配日常处理的文档类型，减少用户填写时的信息切换成本 |
| `formInput` 校验规则 | 绑定学籍、低保数据的实时校验，校验超时设置为30秒 | 对应多源数据对接的约束，避免过长等待影响交互体验 |
| `userSelect` 数据源 | 关联全国学生资助管理信息系统、民政低保数据的下拉选项 | 确保选择的用户信息与官方数据源一致，减少录入错误 |
| 单次交互问答上限 | 前5条政策匹配结果 | 匹配党建学习问答的场景，避免过多结果干扰审核流程 |
| 表单提交超时 | 600秒 | 覆盖多系统数据拉取的耗时，避免因超时导致提交失败 |

## 容易做错的三处
- 现象：调用外部系统接口获取的JSON数据在传入表单节点时出现大量反斜杠转义字符。原因：未对接口返回数据做格式化处理，导致特殊字符被二次转义。
- 现象：在知识库搜索配置中选择变量引用时，无可选变量列表。原因：未提前通过`formInput`或工作流节点输出配置变量，变量未进入可选范围。
- 现象：工作流调试阶段的输入结果与前端实际测试的结果存在差异。原因：调试阶段使用的测试数据未匹配正式环境的跨源数据校验规则，或缓存了过期的测试配置。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的系统触发表单字段校验，确认已绑定的外部数据源能正常返回匹配数据。
- 进入知识库搜索配置界面，确认变量引用的可选列表包含已配置的业务变量。
- 提交测试表单，查看系统日志，确认无异常转义或超时报错。
- 对比工作流调试与前端实际测试的输入参数，确保两者的配置规则一致。
