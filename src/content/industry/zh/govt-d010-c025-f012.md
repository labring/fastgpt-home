# 安全生产隐患排查治理的党建学习问答：部署与升级

## 这个品类的数据长什么样
本品类数据来源于安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，每日更新。核心文档包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，数据字段围绕隐患闭环管理生成，包含隐患标识、整改责任主体、整改时限、复查状态等，无额外自定义统计字段，仅记录隐患排查、整改、复查的全流程关联信息。

## 这些特征在「部署与升级」这一环带来什么约束
每日更新的频率要求部署时配置增量同步的定时触发逻辑，避免全量拉取占用过多服务器资源。多来源的系统数据要求对接时适配不同的接口格式与权限校验规则，确保不同渠道的隐患数据可统一接入。多类型的闭环文档要求配置针对性的字段映射规则，确保隐患、整改、复查等环节的数据准确关联。高风险的出错后果要求部署时开启详细日志留存与异常告警配置，便于快速定位问题并止损。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:port/dbname?authSource=admin` | 对接安全生产监管系统、企业隐患自查系统的结构化隐患数据，需配置正确的认证源与数据库权限 |
| `PG_URL` | `postgresql://username:password@host:port/dbname` | 存储整改通知书、复查记录等非结构化文档的元数据，适配关系型数据的查询需求 |
| `REDIS_URL` | `redis://:password@host:port/0` | 缓存每日增量同步的增量数据快照，降低重复查询的资源消耗 |
| `DB_MAX_LINK` | `20–30 个` | 适配每日高频的隐患数据同步请求，避免连接数不足导致的同步中断 |
| `FE_DOMAIN` | `https://your-domain.gov.cn` | 配置党建学习问答的前端访问域名，确保内部用户可正常访问服务 |
| `ROOT_KEY` | `按内部信息安全管理规范生成的随机字符串` | 配置平台的超级管理员权限密钥，保障内部管理操作的安全性 |

## 容易做错的三处
-  现象：启动服务后容器状态为up，但前端3000端口页面无法登录，日志提示MongoDB连接失败。原因：未正确配置`MONGODB_URI`的认证信息，或MongoDB实例未开放对应端口的访问权限。
-  现象：在平台中配置党建问答的关联模型时，无法找到API密钥的配置入口。原因：未在对应环境变量中配置`FILE_TOKEN_KEY`或`ROOT_KEY`，导致权限校验不通过，隐藏了配置入口。
-  现象：每日增量同步隐患数据的任务执行超时，同步进度停滞。原因：`DB_MAX_LINK`配置值过低，无法支撑多来源系统的并发请求，导致数据库连接池耗尽。

## 怎么确认配好了
-  执行数据库连接测试命令，验证`MONGODB_URI`与`PG_URL`的配置是否可正常连接对应数据库实例。
-  访问配置好的`FE_DOMAIN`，确认前端页面可正常加载，无权限报错或资源加载失败提示。
-  触发一次增量同步任务，查看日志中无数据库连接超时或数据映射失败的报错信息。
-  进入平台的超级管理员配置页面，使用配置的`ROOT_KEY`完成校验，确认可正常修改平台基础配置。
