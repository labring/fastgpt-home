# 工程建设项目审批的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自工程建设项目审批管理系统、施工图审查系统、企业资质库与信用平台，更新频率为每日。日常文档包含施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表，文档多为结构化审批表单与非结构化审批文本，字段涵盖审批节点、参建单位信息、资质等级、验收结果等，部分文档附带扫描件附件，无统一固定格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据分散于多个业务系统，每日增量更新要求索引流程适配批量同步逻辑；日常文档包含结构化表单与非结构化扫描件，需支持多格式内容提取；审批节点、参建单位资质等信息关联性较强，索引需保留字段级关联以支撑精准问答；每日更新量稳定，需控制索引构建耗时避免干扰正常审批业务流转。同时党建学习问答场景需关联审批业务与党建相关内容，索引需同时覆盖业务流程与党建政策要求，避免出现内容割裂。需严格控制索引准确性，防止因匹配错误导致的无证施工、开工延误或竣工备案无法通过的问题。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配审批文档的段落长度，避免分块破坏审批节点与党建内容的关联 |
| 重叠长度 | 100–150 字符 | 保留跨分块的审批流程与党建要求信息，提升问答连贯性 |
| `defaultToken` | 4096 | 匹配多数党建学习问答的上下文长度需求，适配常规审批文档的文本总量 |
| `maxToken` | 8192 | 支持包含附件文本的长文档处理，覆盖竣工验收备案表等长表单 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 平衡党建问答的精准度与召回率，避免无关审批内容干扰 |
| 单次搜索上限 | 前 5 条 | 控制返回结果数量，聚焦核心审批与党建相关内容 |

## 容易做错的三处
- 索引构建始终停留在最后一组任务，原因是未适配每日增量更新的批量同步逻辑，导致系统反复重试未完成的增量包。
- 无法正确创建知识库并卡在索引步骤，原因是未正确配置多格式解析模块，无法处理施工许可申请中的扫描件附件。
- 新增嵌入模型后可完成索引但搜索测试报错，原因是未同步更新模型调用的`defaultToken`参数，导致上下文长度超出模型支持范围。

## 怎么确认配好了
- 上传单份竣工验收备案表，检查分块结果是否保留完整的审批节点与党建相关内容，无内容截断。
- 触发一次增量同步任务，查看索引构建进度是否正常推进，无长时间停滞在某一阶段。
- 输入党建相关的审批问答测试，确认返回结果包含正确的审批流程与参建单位资质信息。
- 调用新增的嵌入模型进行搜索测试，检查是否能正常返回匹配结果，无报错提示。
