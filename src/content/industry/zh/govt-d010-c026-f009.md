# 工程建设项目审批的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据来自工程建设项目审批管理系统、施工图审查系统、企业资质库、信用平台，更新频率为每日。日常文档包含施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表等，数据字段涵盖审批节点、参建单位资质、人员信息、材料提交状态等，无额外自定义统计单位，单份文档长度跨度较大，从数页审批表单到数十页的竣工验收备案材料不等，同时需结合党建学习类文本形成混合问答数据源。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且每日更新，要求模型接入时需适配多系统接口的权限校验规则，避免因跨系统调用触发访问限制。日常文档结构差异大，需在配置中预留灵活的上下文处理空间，适配不同长度的审批材料与党建学习内容的混合输入。每日更新的数据需要配置合理的召回刷新机制，确保问答内容匹配最新的审批流程与资质要求。同时，审批相关数据涉及政务合规，需严格限制模型调用的上下文范围，防止敏感信息泄露，这要求配置时需明确上下文的边界与调用权限。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体配置项及依据如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配混合了党建学习文本与工程审批文档的上下文长度，保留多轮对话的完整历史信息 |
| `maxTokens` | `2000–3000 token` | 平衡回答完整性与模型调用成本，避免单次调用超出计费阈值 |
| `quoteMaxToken` | `1500 token` | 保留审批文档与数据库返回内容的原文片段长度，实现类似RAG知识库的引用效果 |
| `temperature` | `0.3–0.5` | 适配政务场景的严谨性要求，降低随机生成内容的概率，确保回答符合官方规范 |
| `toolChoice` | `auto` | 按需触发工具调用，支持调用工程审批数据接口与党建知识库，适配混合问答场景 |
| `AIPROXY_API_ENDPOINT` | 按实际代理地址填写 | 实现模型的安全接入，确保请求转发符合政务网络的访问规则 |
| `AIPROXY_API_TOKEN` | 按实际密钥填写 | 完成模型接口的权限校验，避免访问被拦截 |

## 容易做错的三处
- 现象为本地部署FastGPT后新增模型测试返回403 status code (no body)，原因是未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致代理接口权限校验失败。
- 现象为通过Function CALL调用MYSQL数据后，返回结果未包含数据库原文片段，原因是未配置`quoteMaxToken`参数，未保留数据库返回内容的有效引用长度。
- 现象为通过API发布渠道访问应用时多轮对话内容丢失，原因是未合理设置`maxContext`参数，导致旧对话历史被提前截断，无法延续上下文逻辑。

## 怎么确认配好了
- 提交包含施工许可申请内容与党建学习相关问题的测试输入，验证返回结果中是否包含审批文档的原文片段。
- 调用配置的模型接口，确认返回状态码为200且无异常报错信息。
- 发起连续三轮对话，检查对话上下文是否被正确保留，回答逻辑连贯一致。
- 调整`temperature`参数至不同区间，验证回答的严谨性符合政务场景的合规要求。
