# 工程建设项目招投标的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
本品类的典型主体为发展改革部门、住建交通水利行业主管部门、公共资源交易中心及招标代理。日常处理的文档包括招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示与中标结果公告。数据来源为全国公共资源交易平台、地方交易平台、工程审批系统及招标投标监管系统，更新频率为每日。文档结构常包含标段划分、资格条件、评标专家记录、工程量清单等字段，部分文档涉及多标段关联内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的批量文档要求索引构建支持并发处理，适配多文件批量导入逻辑。不同类型文档结构差异显著，招标公告侧重流程信息，评标报告侧重专家与结果细节，需针对性配置分块规则，避免跨文档语义混淆。文档包含标段、资格条件、工程量清单等结构化字段，向量索引需保留字段关联关系，防止语义拆分破坏业务逻辑。中标结果类文档时效性强，索引更新需匹配日更节奏，避免数据滞后影响问答准确性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配招投标文档的常规段落长度，避免单块语义断裂 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的语义关联，防止关键信息被拆分 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 过滤低关联的召回结果，匹配专业文档的语义匹配标准 |
| 单次召回上限 | 前 8 条 | 适配单轮问答的上下文承载量，避免信息过载 |
| `maxToken` | 4096 | 适配主流嵌入模型的最大输入限制，确保分块合规 |
| `defaultToken` | 2048 | 配置默认分块的token上限，兼容多数中小型招投标文档 |

## 容易做错的三处
- 现象：Docker部署PG数据库时，知识库索引无法建立成功，导入文件后无进度反馈。原因：未正确配置数据库连接参数，或宿主机内存资源未合理分配，导致索引写入环节超时失败。
- 现象：接入OneAPI嵌入模型时持续报错，无法完成索引构建。原因：未单独配置索引专用嵌入模型，默认调用的对话模型不支持嵌入任务，无法生成对应向量数据。
- 现象：调用嵌入模型时返回503错误，提示default分组下无可用渠道。原因：未为索引模型单独配置专属调用分组，默认分组未绑定对应嵌入模型的可用渠道，导致调用请求被拦截。

## 怎么确认配好了
- 导入单份典型招投标文档，检查分块后的文本是否符合配置的分块长度要求，无异常截断提示。
- 发起党建相关的招投标政策问答，核对召回结果的相关性，确保无低关联内容混入。
- 查看索引构建日志，确认每日更新的文档均成功完成向量写入，无失败记录。
- 调整`defaultToken`或`maxToken`参数后，导入不同规模的文档，验证分块逻辑是否符合预设上限。
