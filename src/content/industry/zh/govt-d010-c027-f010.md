# 工程建设项目招投标的党建学习问答：知识库检索与召回

## 这个品类的数据长什么样
数据来源为全国公共资源交易平台、地方公共资源交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常文档包含招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，同时配套党建学习相关的政策文件、应知应会内容。文档多为结构化或半结构化文本，包含标段信息、资质要求、评标细则、党建知识点等字段，无统一固定单位，随文档类型变化。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的数据源要求配置增量同步机制，避免全量重复同步占用资源。多类型混合文档既包含结构化招投标字段，又包含非结构化党建文本，需要兼顾关键词与语义召回的适配性。不同来源的文档格式存在差异，需要统一预处理流程以保证检索一致性。党建学习与招投标业务的内容边界需清晰划分，避免无关内容干扰特定场景的问答准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 平衡党建知识点与招投标业务内容的召回精准度，避免低相关内容混入对应场景 |
| `limit` | 前8条 | 适配混合文档的体量，控制上下文长度，避免超出大模型的上下文限制 |
| `searchMode` | hybrid | 兼顾关键词匹配与语义召回，适配结构化的招投标字段与非结构化的党建文本 |
| `usingReRank` | 开启 | 对初始召回结果重排，优先匹配当前场景的核心诉求，修正单一语义召回的偏差 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于原问题生成扩展查询，覆盖招投标术语与党建表述的同义替换，提升召回覆盖率 |
| `collectionIds` | 按业务与党建数据集分别配置 | 隔离跨品类数据，避免招投标文档与党建学习内容互相干扰检索结果 |

## 容易做错的三处
- 现象：检索结果中混入大量无关招投标业务文档，党建知识点占比不足30%。原因：未配置`collectionIds`按数据集隔离检索范围，导致跨品类数据被同时召回。
- 现象：单次检索返回结果条数不足3条，无法覆盖完整的党建知识点或招投标细节。原因：`limit`参数设置过低，未适配混合文档的检索需求。
- 现象：生成的回答出现术语偏差，比如将“资格预审”误写为“资质审查”，或混淆党建学习的核心表述。原因：未开启`datasetSearchUsingExtensionQuery`，未覆盖场景专属术语的同义表述差异。

## 怎么确认配好了
- 上传单条招投标文档与单条党建学习文档，发起对应场景的提问，核对返回结果仅包含对应品类的文档内容。
- 调整`similarity`参数，验证不同阈值下的召回结果数量与相关性变化，确认取值符合业务需求。
- 开启`usingReRank`后，对比重排前后的结果排序，确认核心相关内容被优先展示。
- 查看检索日志，确认`datasetSearchUsingExtensionQuery`生成的扩展查询覆盖了场景专属术语。
