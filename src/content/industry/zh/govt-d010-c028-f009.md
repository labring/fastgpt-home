# 市场主体登记与许可的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
本品类的核心数据来自企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统与住所信息库，更新频率为每日。日常处理的文档包括设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等，涵盖主体资格申请、经营许可办理等全流程材料，数据字段包含主体名称、住所信息、股东信息、许可类型等，无统一固定的单文档长度标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据来源要求模型接入需兼容不同系统的输出格式，避免出现字段不匹配的召回错误；每日更新频率要求配置增量同步逻辑，确保向量库与数据源保持一致；多样的文档结构需要调整上下文与召回参数，适配不同长度的申请材料与政策问答内容；出错后果直接影响市场主体的准入进度，因此模型的召回准确率与上下文完整性需要严格控制，避免因配置不当导致错误答复。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配党建问答与市场主体登记文档的总上下文长度，避免关键信息被截断 |
| `temperature` | 0.1–0.3 | 确保政策答复与流程指引的准确性，符合监管场景的严谨性要求 |
| `quoteMaxToken` | 2000–3000 字符 | 匹配单份登记申请材料的平均长度，保证召回内容的完整性 |
| `toolChoice` | auto | 自动判断是否需要调用工具核验股东信息、住所信息等，适配登记许可的核验需求 |
| `vision` | 关闭 | 本品类核心数据为文本格式，无需开启视觉处理能力，降低资源消耗 |
| `AIPROXY_API_ENDPOINT` | 按本地部署的模型地址填写 | 对接本地部署的大模型与向量模型，实现私有部署 |
| `AIPROXY_API_TOKEN` | 按模型部署的密钥填写 | 完成模型调用的身份验证，确保接入安全性 |

## 容易做错的三处
- 现象：向量模型接入失败，提示无可用渠道。原因：未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或未匹配向量模型的接口格式。
- 现象：本地模型每秒token数无法获取，导致上下文截断异常。原因：未在FastGPT中正确配置模型的速率参数，依赖默认值导致与模型实际处理能力不匹配。
- 现象：上传纸质登记材料的扫描件后无响应。原因：未确认模型是否支持视觉处理，或未开启`vision`配置项。

## 怎么确认配好了
- 在FastGPT v4.17.0的模型管理页面，发起模型测试调用，确认返回状态码为200。
- 上传一份设立登记申请书，发起向量召回测试，查看返回的关联文档是否来自指定的数据源。
- 输入党建学习相关的登记政策问题，检查模型答复是否符合预设的严谨性要求，无明显偏差。
- 查看系统运行日志，确认无模型接入、向量召回或上下文截断的报错信息。
