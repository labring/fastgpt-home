# 市场主体登记与许可的党建学习问答：分享与嵌入

## 这个品类的数据长什么样
市场主体登记与许可的党建学习问答相关数据，来源为企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统、住所信息库。日常处理的文档包括设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等，数据更新频率为每日。数据字段涵盖主体资格、经营许可相关的结构化与非结构化内容，严格遵循官方系统的字段规范。

## 这些特征在「分享与嵌入」这一环带来什么约束
市场主体登记与许可的党建学习问答相关数据来源分散且每日更新，因此分享与嵌入的知识库需每日同步官方系统的最新数据，否则问答结果无法反映当前有效信息。日常文档包含多种结构化与非结构化材料，嵌入时需限定检索范围，仅覆盖登记许可相关文档与党建学习关联内容，避免混入无关信息。数据处理环节出错会导致登记驳回、经营受限等后果，因此嵌入后的问答结果需严格匹配官方文档内容，确保信息准确。同时，数据体量较大，嵌入时需控制检索结果的数量，避免加载超时或页面卡顿。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `shareId` | 目标知识库的唯一标识 | 用于指定分享与嵌入的专属知识库内容 |
| 单次搜索上限 | 前5条 | 匹配登记许可相关数据的核心检索需求，避免冗余结果 |
| 最大上下文长度 | 800–1200字符 | 适配登记许可文档的常规内容长度，确保信息完整 |
| 知识库同步频率 | 每日 | 匹配官方系统的每日更新节奏，保证数据时效性 |
| 嵌入页面跨域配置 | 允许指定业务域名 | 适配市场监管窗口、企业开办窗口的内部页面嵌入需求 |

## 容易做错的三处
- 现象：iframe嵌入页面后无显示，但后台日志显示接口执行正常。原因：未配置嵌入页面的跨域白名单，浏览器拦截了FastGPT的嵌入请求。
- 现象：提交党建学习相关的登记许可问题后，返回结果未匹配对应文档。原因：未限定检索范围为登记许可专属文档，导致检索范围覆盖了全量知识库内容。
- 现象：嵌入页面加载超时。原因：未设置合理的单次搜索上限，导致加载过多数据，超出页面加载阈值。

## 怎么确认配好了
- 复制FastGPT v4.17.0中生成的嵌入代码，插入到测试页面中，查看页面是否正常加载问答模块。
- 提交一个登记许可相关的党建学习问题，查看返回结果是否包含对应文档的准确内容。
- 检查知识库的同步状态，确认同步频率为每日。
- 验证`shareId`参数与目标知识库的唯一标识一致。
