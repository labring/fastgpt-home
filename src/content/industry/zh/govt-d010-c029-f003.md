# 市容环卫与城管执法案件的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据通常来自城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。日常文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书与结案报告。数据字段通常涵盖案件编号、违法类型、责任主体、现场取证信息、整改或处罚执行状态等，多为结构化与半结构化结合的文档形式，部分伴随非结构化的图片素材。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
日常文档的多类型混合特性，要求多轮对话需支持不同格式内容的上下文关联，提示词需明确区分执法流程与党建学习的场景边界。数据每日更新的特性，要求对话系统的知识库同步频率匹配更新节奏，避免使用过期的案件信息。现场取证与责任主体判断的耗时环节，要求多轮对话可逐步引导补充关键信息，提示词需预设执法场景下的常见问题分支，减少无效交互。案件出错后果的敏感性，要求对话输出需严格对齐已归档的执法文档，避免生成与实际流程不符的内容。

## 配置怎么定
本配置适配FastGPT v4.17.0版本，具体参数设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 800–1200 字符 | 匹配单条执法文档的平均长度，避免上下文溢出导致对话中断 |
| `chatId` 绑定规则 | 绑定单个执法案件的唯一标识 | 确保多轮对话仅关联对应案件的上下文，避免跨案件信息混淆 |
| 提示词模板预设 | 包含党建学习要求与执法流程校验规则 | 对齐城管执法的合规性与党建学习的内容规范 |
| `variables` 传入字段 | 传入案件编号、责任主体、案件状态 | 为多轮对话提供精准的场景上下文，减少无效检索 |
| 单次对话返回上限 | 前3条关联文档 | 控制输出信息量，避免冗余内容干扰执法判断 |
| 工作流触发阈值 | 按实测标定 | 适配1秒2-3次的并发调用需求，避免超出系统运行上限 |

## 容易做错的三处
- 对话返回结果末尾出现规则追溯类符号。原因是未关闭内置的规则展示开关，导致预设的执法合规规则被追加到输出末尾。
- 并发调用工作流时返回空值。原因是未调整工作流最大运行次数配置，超出系统预设的并发处理上限。
- 无法正常展示大模型思考过程。原因是提示词模板未嵌入思考过程引导的固定格式，或未开启对应对话环节的展示设置。

## 怎么确认配好了
- 发起单轮测试对话，输入单条执法案件的基础信息，核对上下文是否仅关联对应案件的文档内容。
- 模拟1秒2-3次的并发调用，检查工作流节点是否正常返回有效结果，无空值或报错。
- 调整提示词模板，验证输出是否包含预设的党建学习引导内容，且无额外的规则追溯符号。
- 传入`variables`参数中的案件编号字段，核对对话过程中是否自动关联对应案件的历史记录。
