# 市容环卫与城管执法案件的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
市容环卫与城管执法案件的日常数据来自城管执法平台、城市运行网格平台、视频监控、群众投诉工单，更新频率为每日。典型文档包括巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告，数据字段通常包含案件编号、违法类型、责任主体、整改要求、处置进度等，多为现场处置相关的结构化与非结构化内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且包含多模态内容，要求模型接入需支持多模态识别与多源数据关联。每日更新的巡查与工单数据需配置自动同步流程，保障知识库内容时效性。现场取证相关的文档需模型能准确识别图片中的执法细节，避免因信息缺失导致案件证据不足。同时，党建学习问答需严格匹配执法规范，模型输出需关联具体执法文书，降低执法争议风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 该品类数据包含现场照片、视频监控素材，需支持多模态内容识别 |
| `temperature` | 0.2–0.4 | 党建学习问答需保持政策表述严谨，避免生成偏离规范的内容 |
| `maxContext` | 8000–12000 token | 需关联巡查记录、处罚决定书等多份执法文档，保障上下文连贯性 |
| `AIPROXY_API_ENDPOINT` | 对应城管系统专属接入地址 | 适配城管部门的网络隔离与权限管控要求 |
| `quoteMaxToken` | 2000–3000 字符 | 需保留足够的执法文书原文作为引用依据，避免证据缺失 |
| `toolChoice` | auto | 需自动调用知识库检索工具匹配党建政策与执法依据 |

## 容易做错的三处
- 现象：调用gpt-4o时返回「当前分组default下无可用渠道」，原因：未为当前场景分组绑定专属模型渠道，或未配置对应模型的API密钥
- 现象：检索结果仅返回模糊匹配的政策摘要，未引用具体执法文书，原因：未限制模型仅使用检索到的知识库内容作答，或未开启强制引用配置
- 现象：上传现场照片后模型未识别相关内容，原因：未开启`vision`配置，或使用了不支持多模态的模型版本

## 怎么确认配好了
- 测试输入党建相关的执法案例问题，检查返回内容是否包含指定知识库的执法文书原文
- 上传现场巡查照片，确认模型能识别照片中的执法标识或违法场景
- 查看模型调用日志，确认`maxContext`、`temperature`等配置参数的实际取值与预设一致
- 模拟导入当日的巡查记录与投诉工单，检查数据同步与检索流程是否正常触发
