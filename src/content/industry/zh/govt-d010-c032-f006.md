# 投资项目立项与后评价的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
本品类数据主要来自国资委投资监管系统、企业ERP与项目管理系统、行业市场数据、审计及财务报表，更新频率为季度。日常文档包含年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告、投资后评价报告，文档结构多包含项目编号、立项审批信息、财务测算数据、投后运营指标等字段，单份文档篇幅跨度较大，从数千到数万字符不等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
季度更新频率要求知识库需按季度完成全量或增量同步，确保引用数据的时效性，避免因引用过期数据导致国有资产损失或责任追究。文档篇幅跨度大，分块处理时需适配不同长度的内容，避免拆分关键审批或财务信息导致溯源缺失。多源数据来自监管系统、ERP等不同渠道，需为每个来源配置专属的标识字段，确保溯源时可精准匹配到对应系统的原始文档。党建学习场景下的项目数据涉及国资监管要求，溯源链路需完整保留来源信息，满足合规审查需求。本品类围绕资本投向与国资保值，与其他经营管理品类不同，需重点保留董事会投决、负面清单等相关文档的溯源信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前6–10条 | 本品类数据覆盖项目全周期文档，需覆盖立项、可研、后评价等多环节内容，避免关键信息遗漏 |
| 相似度阈值 | 0.62–0.78 | 适配多源异构的项目数据，平衡召回精度与覆盖范围，防止召回非投资类的冗余文档 |
| `quoteMaxToken` | 3500–4500 token | 适配单份可研或后评价报告的大篇幅内容，确保引用的完整片段可被完整召回 |
| 上下文窗口 | 11000–16000 字符 | 保留足够的历史对话与文档片段，支持全周期项目数据的溯源查询 |
| `responseData` | 开启 | 确保返回的引用内容包含完整的来源元数据，支持精准溯源 |
| `detail` | 开启 | 确保引用内容展示完整的文档片段与元数据 |
| 来源字段映射 | 按实测标定 | 匹配本品类的国资委监管系统、ERP等多源数据的标识字段，确保溯源时可精准关联原始文档 |

## 容易做错的三处
- 现象：召回的引用内容条数始终固定，无法通过调整参数提升数量。原因：知识库仅同步了季度更新的部分文档，或单次搜索上限被错误限制为固定值，导致召回池无法扩容。
- 现象：输出的引用内容未保留原始文档的格式标识，仅显示纯文本片段。原因：未正确配置内容渲染规则，或分块时丢失了原始文档的格式信息。
- 现象：无法通过sourceid关联到对应原始文档的上传字段。原因：未映射本品类专属的项目编号、文档类型等字段，导致溯源时无法精准匹配原始数据。

## 怎么确认配好了
- 发起一次针对年度投资计划的党建学习问答查询，检查返回的引用来源是否包含对应文档的系统标识与更新时间。
- 调整单次搜索上限的取值，观察召回的引用条数是否发生变化，验证参数配置生效。
- 上传一份测试用的投资后评价报告，发起相关查询，确认引用内容可关联到该测试文档的sourceid与字段信息。
- 查看知识库同步日志，确认已按季度完成全量或增量数据同步，确保引用数据的时效性。
