# 投资项目立项与后评价的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据围绕中央企业投资项目全生命周期产生，日常文档涵盖年度投资计划、项目建议书、可行性研究报告、尽职调查报告、资产评估报告、投资后评价报告等。数据主要取自国资委投资监管系统、企业ERP与项目管理系统、行业市场数据、审计和财务报表，更新节奏为季度级。数据按项目维度归集，包含立项审批、可研论证、投后评价等全流程关联信息，无统一固定字段，需按不同文档类型提取对应业务信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据来源跨多系统，需确保模型接入的数据源适配不同的权限与格式，避免跨系统数据拉取失败。季度更新的频率要求配置的上下文窗口可覆盖季度级的文档集合，避免遗漏近期更新的投资计划与后评价数据。多类型文档的token长度差异显著，需合理设置模型的上下文与输出token限制，适配不同文档的处理需求。数据关联国资监管要求，模型调用需符合合规性配置，确保信息传输与存储符合国资管理规范。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖季度更新的多份投资项目文档总token量，避免截断核心立项与后评价内容 |
| `maxTokens` | 2000–3000 token | 适配投资后评价报告等长文档的输出总结需求，确保完整输出分析结论 |
| `temperature` | 0.3–0.5 | 保持党建学习问答内容的严谨性，避免生成偏离国资监管要求的发散内容 |
| `AIPROXY_API_ENDPOINT` | 私有化部署的云平台模型代理地址 | 适配私有化部署场景下的模型调用链路，解决云模型与FastGPT平台的推理差异 |
| `AIPROXY_API_TOKEN` | 云平台获取的有效访问密钥 | 完成模型身份验证，确保调用权限合法合规 |
| `toolChoice` | auto | 根据党建问答场景自动匹配所需工具，无需手动指定调用规则 |

## 容易做错的三处
- 现象：在OneAPI中测试通过的模型提供商，在FastGPT中添加后测试返回404错误。原因：未正确填写模型ID，或`AIPROXY_API_ENDPOINT`配置的代理地址未正确映射到目标模型路径。
- 现象：私有化部署场景下，云模型推理速度与FastGPT平台存在显著差距。原因：未设置合理的`maxContext`与`maxTokens`参数，或未配置正确的`AIPROXY_API_ENDPOINT`导致链路延迟增加。
- 现象：容器运行时返回`Api response error: /api/core/ai/model/test?model=Doubao-l`报错。原因：模型名称填写不完整，或`AIPROXY_API_TOKEN`配置错误导致身份验证失败。

## 怎么确认配好了
- 在FastGPT平台的模型提供商管理页面，执行模型测试，确认返回结果无报错，且输出内容符合党建学习问答的合规要求。
- 导入单份投资项目建议书，发起党建相关问答，核对模型返回内容是否覆盖文档核心信息，无明显截断或缺失。
- 调整`temperature`参数并验证生成内容的严谨性，确保符合国资监管相关的党建学习要求。
- 查看容器运行日志，确认无模型调用相关的网络报错或身份验证失败提示。
