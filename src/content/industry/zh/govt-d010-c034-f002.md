# 招生入学与学籍管理的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自全国中小学生学籍信息管理系统、地方招生入学平台、户籍房产数据及学校教务系统，涵盖入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表等文档。数据更新频率为每日，核心字段包含学生身份信息、入学资格核验材料、学籍流转记录等，需关联户籍、房产等外部数据完成资格校验。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据包含结构化学籍表格与非结构化政策文档，且需关联多源外部数据，对索引的多模态适配能力提出要求。每日更新的数据量会带来索引刷新的频率约束，需避免全量重建索引带来的资源消耗。同时，数据包含学生身份、户籍房产等敏感信息，向量存储与索引环节需符合公共服务数据安全规范，需对嵌入后的向量数据做权限隔离。此外，招生政策类文档与学籍流转类文档的语义差异较大，需确保索引能区分不同文档类型的语义特征，避免检索混淆。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 本品类文档包含结构化表格字段与非结构化政策文本，该区间可平衡语义完整性与索引密度，适配学籍表与招生计划文档的内容长度 |
| 重叠长度 | 100–150 字符 | 避免分块后语义断裂，确保学籍异动审批流程的上下文连贯，同时控制索引冗余量 |
| 相似度阈值 | 0.72–0.80 | 用于区分招生政策问答与学籍信息核验的检索结果，避免低相关的户籍数据干扰党建学习问答的精准性 |
| 单次搜索上限 | 前 8 条 | 适配党建学习问答的短上下文需求，同时覆盖招生政策、学籍规则的多维度检索结果 |
| `maxToken` | 4096 token | 符合主流嵌入模型的输入限制，适配党建学习问答的长文本政策文档拆分后的最大输入长度 |
| `defaultToken` | 512 token | 用于标准化短文档如入学报名表的嵌入处理，确保不同类型文档的向量维度统一 |

## 容易做错的三处
- 现象：单个文件长期处于索引中，界面显示“索引中”状态无更新。原因：未针对本品类的多源关联数据配置合理的分块重叠长度，导致分块后出现循环依赖的语义关联，引发索引阻塞。
- 现象：页面仅支持选择一种向量模型，但需处理多组不同结构的业务数据。原因：未提前将多组业务数据按字段类型拆分，错误将不同嵌入维度要求的数据集绑定至同一向量模型，导致向量存储格式不匹配。
- 现象：上传本地嵌入的文档后检索结果偏差较大。原因：未统一向量模型的嵌入维度与文本预处理规则，本地与服务器使用的向量模型输出维度不一致，导致向量空间映射错位。

## 怎么确认配好了
- 上传单份学籍信息表，检查分块后的文本是否保留核心字段与流程逻辑，无明显语义断裂。
- 触发每日增量索引任务，查看索引进度日志，确认无长期阻塞的文件。
- 输入党建学习相关的招生政策问题，核对检索结果的相似度阈值是否符合预设区间。
- 切换不同向量模型测试，确认同一文档的向量输出维度保持一致。
