# 招生入学与学籍管理的党建学习问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自全国中小学生学籍信息管理系统、地方招生入学平台、户籍房产数据库及学校教务系统，日常文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表。数据按日更新，核心字段涵盖学籍编号、户籍地址、招生计划数、异动审批状态等，以学生身份与入学资格为核心关联维度。

## 这些特征在「知识库检索与召回」这一环带来什么约束
日更新频率要求知识库需支持增量同步，避免全量刷新带来的耗时问题。多源数据需建立统一的字段映射规则，确保不同来源的学籍号、户籍地址等核心字段格式一致。文档类型多样，需适配不同文档的分块逻辑，确保招生政策、学籍异动审批表等内容均可被精准召回。检索关键词需聚焦学生身份与学籍流转维度，避免混入非本品类的关联数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配招生政策、学籍规则等核心文本的精准度要求 |
| `limit` | 前6条 | 控制召回结果的总字符量，适配党建问答的上下文长度限制 |
| `searchMode` | hybrid | 结合关键词与向量检索，适配多类型文档的召回需求 |
| `usingReRank` | 开启 | 对召回结果进行二次排序，提升政策类文本的相关性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展党建学习相关的检索关键词，覆盖政策解读内容 |
| `collectionIds` | 绑定本品类专属知识库集合 | 限定检索范围，避免混入其他品类的文档 |

## 容易做错的三处
- 现象：检索知识库时出现向量模型调用失败的报错。原因：未在检索配置中正确指定向量模型，或未配置模型调用的环境参数。
- 现象：召回结果包含大量非本品类的学籍或招生无关内容。原因：未通过`collectionIds`限定检索的知识库集合，导致混入其他品类的文档。
- 现象：通过Function CALL调用MySQL学籍数据后，大模型无法引用数据库原文片段。原因：未将MySQL查询结果导入对应知识库集合，且未开启`datasetSearchUsingExtensionQuery`来关联检索结果。

## 怎么确认配好了
- 在FastGPT v4.17.0的检索配置界面，确认`collectionIds`已绑定本品类专属的知识库集合ID。
- 输入党建学习相关的招生政策关键词，查看召回结果的`similarity`分值是否落在预设的0.75–0.85区间内。
- 调用Function CALL导入MySQL学籍数据后，执行检索，确认大模型输出中包含数据库原文的片段引用。
- 查看检索日志，确认`usingReRank`和`datasetSearchUsingExtensionQuery`的状态为开启。
