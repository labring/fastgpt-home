# 招生入学与学籍管理的党建学习问答：对话日志与审计

## 这个品类的数据长什么样
该品类的数据来源包括全国中小学生学籍信息管理系统、地方招生入学平台、户籍和房产数据、学校教务系统，更新频率为每日。日常文档涵盖入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表，核心字段围绕学生身份、入学资格、学籍流转状态，数据关联多部门业务系统，无统一单文档格式，需跨系统校验一致性。

## 这些特征在「对话日志与审计」这一环带来什么约束
由于数据每日更新且关联多部门系统，对话日志需绑定具体业务标识以实现精准溯源。文档涉及学生学籍、入学资格等敏感信息，审计环节需完整记录交互全流程，避免遗漏关键核验步骤。学籍异动、录取结果等操作的出错后果直接影响学生升学，审计需可回溯对话中的政策解释、资格核验环节，确保每一步操作可查。同时，多系统数据的联动要求日志需兼容不同来源的字段格式，便于跨系统审计校验。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话日志关联标识 | 绑定`chatId`与`responseChatItemId`、学籍号、招生批次字段 | 关联业务数据与对话记录，便于按学籍或招生批次快速检索审计日志，基于FastGPT v4.17.0的交互规范实现 |
| 日志详情存储开关 | 开启`detail`参数 | 存储完整对话上下文与响应内容，满足审计对交互细节的核查需求 |
| 日志保留时长 | 180–365 天 | 符合教育公共服务领域的审计追溯周期要求 |
| 敏感信息脱敏规则 | 按实测标定 | 覆盖学生身份证号、房产地址、学籍号等专属敏感字段，避免数据泄露 |
| 日志查询超时阈值 | 600 秒 | 适配教育系统的审计查询响应速度，避免查询超时中断 |
| 审计触发时机 | 每轮对话结束后触发 | 覆盖完整交互流程，避免遗漏关键对话步骤 |

## 容易做错的三处
- 对话历史记录未被加载，上下文关联失效。未正确绑定`chatId`与`responseChatItemId`与对应学籍或招生批次的业务标识，导致历史对话无法匹配。
- 审计日志未完整记录交互细节，关键核验步骤无法回溯。未开启`detail`参数存储完整对话内容，仅保存了简化的响应摘要。
- Docker部署后FastGPT容器无法启动，无有效报错日志。docker compose配置中挂载目录权限未适配本地业务数据存储路径，或资源分配不足。

## 怎么确认配好了
- 发起一次包含学籍信息查询的对话，检查日志中是否存在关联`chatId`与对应学籍号的记录。
- 开启审计日志详情页面，查看是否完整存储了对话的上下文与响应内容，验证`detail`参数已生效。
- 尝试以普通管理员角色登录系统，确认无法查看完整审计日志，验证权限配置已生效。
- 查看docker容器运行状态，确认FastGPT容器无异常退出，验证部署配置无错误。
