# 政务服务事项目录与办事指南维护的党建学习问答：对话日志与审计

## 这个品类的数据长什么样
该品类的数据主要来源于国家政务服务事项基本目录、行政许可事项清单、权责清单及地方政务服务事项库，更新周期通常为每月一次。日常维护的文档包含政务服务事项基本目录、实施清单、办事指南、标准材料目录、流程图及常见问题，字段覆盖事项名称、受理条件、申请材料、办理流程等，字段无统一固定单位，需匹配地方政务服务的实际表述规范。

## 这些特征在「对话日志与审计」这一环带来什么约束
月级更新的数据源要求对话日志需关联对应版本的政务事项目录，避免因目录迭代导致历史对话的办事口径出现偏差。多类文档的混合检索场景，需要审计日志完整记录每一次调用的文档来源、匹配字段及匹配结果，确保事项比对、材料校验等操作可追溯。事项字段的多样性要求日志需完整记录对话中涉及的具体事项编码与名称，便于后续开展口径一致性校验。同时，政务服务的合规要求决定了审计日志需支持不可篡改的存储，以及按事项维度、时间维度的定向导出。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话日志存储周期 | 30 天 | 匹配政务服务事项目录的月更新频率，确保可覆盖完整的月度维护审计周期 |
| `chatId`绑定规则 | 关联对应事项编码 | 便于按具体政务事项检索对应对话记录，匹配业务校验场景 |
| 审计日志详情开关 | 开启`detail`模式 | 完整记录对话中的检索文档、匹配字段及校验结果，满足合规追溯要求 |
| 历史对话加载上限 | 前 20 条 | 适配月度维护的对话量级，避免加载过多数据影响操作效率 |
| 日志导出格式 | CSV 格式 | 便于批量导入校验工具开展口径一致性检查 |

## 容易做错的三处
- 现象：界面提示「没有权限操作此对话记录」。原因：未配置`chatId`与对应政务事项的权限绑定规则，导致非授权用户无法访问关联特定事项的对话日志。
- 现象：刷新对话页面后显示新对话，后台日志仍可查看历史记录。原因：未在FastGPT v4.17.0中开启`responseChatItemId`的本地会话存储配置，导致前端会话缓存丢失，仅后台保留完整日志。
- 现象：导出的审计日志缺失具体匹配字段信息。原因：未开启`detail`模式，仅记录了基础对话时间与用户ID，未覆盖检索文档、匹配字段等关键审计信息。

## 怎么确认配好了
- 登录FastGPT v4.17.0的对应业务账号，尝试检索特定政务事项的历史对话，确认可正常加载对应记录。
- 触发一次政务事项校验操作，查看审计日志详情，确认已记录检索文档、匹配字段等完整信息。
- 导出指定时间段的审计日志，确认导出格式符合业务存档要求。
- 检查日志存储时长，确认可覆盖至少一个月度维护周期的审计需求。
