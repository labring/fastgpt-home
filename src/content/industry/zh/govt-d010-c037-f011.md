# 政府信息依申请公开的党建学习问答：表单与交互

## 这个品类的数据长什么样
该品类的数据来源于政府信息公开平台、机关档案系统、公文系统及部门业务台账，更新频率不定期。日常文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书等，字段涵盖申请人身份信息、申请事项描述、信息获取方式、救济途径提示等，单份文档字符跨度较大，从数百字的申请表到数千字的答复材料不等。

## 这些特征在「表单与交互」这一环带来什么约束
数据来源分散导致表单需支持多源信息调取，不定期更新要求交互环节支持实时校验。多类型文档的字段差异，要求表单具备动态适配能力，可根据不同文档模板调整输入项。特定申请人的个案请求属性，要求交互环节区分公共查询与个体申请场景，避免信息混淆。同时，出错后果关联超期、复议纠错，要求表单具备必填项校验、进度留存功能，确保流程可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 按政府信息公开申请表模板预设字段，必填项标注星号 | 匹配品类日常文档的固定结构，减少手动配置成本 |
| `userSelect` | 限定为政府内部工作人员与法定申请人两类 | 区分个体申请与内部办公场景，避免非授权信息访问 |
| 文件上传格式 | 支持PDF、DOCX、JPG、PNG，默认全选 | 覆盖品类常用文档格式，适配MCP对接需求 |
| 单次提交字符上限 | 800–1200字符 | 匹配申请表单常规填写长度，避免超量输入导致解析异常 |
| 交互超时阈值 | 600秒 | 适配政务办理常规响应周期，防止网络波动导致会话中断 |
| 知识库关联触发 | 按申请内容关键词自动触发 | 精准调取对应公开信息，避免无关内容干扰 |

## 容易做错的三处
- 配置文件上传时未开启全格式默认选项，对接MCP时出现格式校验失败报错。原因是未匹配品类日常文档的通用格式范围，仅开放了有限格式选项。
- 在模型调用配置中仅填入OneAPI令牌密钥，未配置对应模型的API地址，出现空返回报错。原因是未按平台要求完成模型完整链路配置，仅密钥无法完成身份验证。
- 知识问答聊天窗口提示“没有选择知识库”，无法正常发起查询。原因是未在交互环节绑定对应品类的知识库数据源，导致系统无法调取公开信息。

## 怎么确认配好了
- 登录FastGPT v4.17.0平台，进入对应品类的表单配置页面，检查`formInput`预设字段是否包含申请人信息、申请事项、信息获取方式等必填项。
- 上传测试用的政府信息公开申请表、答复书等文档，确认所有预设格式均被默认选中，无格式拦截提示。
- 模拟法定申请人提交测试表单，检查系统是否自动触发知识库关联查询，返回对应公开信息。
- 测试超时场景，手动暂停网络600秒以上，确认会话未出现异常中断，流程进度正常留存。
