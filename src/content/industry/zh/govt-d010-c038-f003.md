# 政府采购项目的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要覆盖政府采购全流程业务文档与关联党建学习内容，来源包括中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统、供应商信用记录，更新频率为每日。涉及的文档包括采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复，服务主体为采购人单位、财政部门政府采购监管处、采购代理机构、评审专家，文档无统一固定字段，需按业务类型区分处理。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每日更新的数据源要求多轮对话系统支持定时同步知识库，避免使用过期的政府采购文档与党建内容。多类文档结构差异大，不同文档有专属业务字段，提示词需能识别并关联对应文档的上下文，比如从采购需求中提取党建相关的采购要求，从评标报告中提取评审合规内容。业务出错后果严重，要求多轮对话的回答必须符合政府采购法体系与党建学习的规范，不能出现错误的政策解读或业务判断。跨主体的对话需求，要求绑定唯一项目标识区分上下文，避免跨项目信息混淆。同时，敏感数据的访问需严格控制，仅允许调用授权范围内的文档。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定采购项目唯一标识 | 区分不同政府采购项目的对话上下文，避免跨项目信息混淆 |
| `messages` | 保留最近20条对话上下文 | 平衡上下文完整性与响应速度，适配政府采购文档的多轮查询需求 |
| `variables` | 绑定项目编号、监管部门名称等预设变量 | 让提示词精准匹配当前项目的业务文档与党建学习内容 |
| 最大上下文长度 | 8000–12000 字符 | 覆盖单篇政府采购文档与关联党建内容的总长度需求 |
| 单次搜索上限 | 前6条 | 平衡检索精度与对话响应速度，避免冗余信息干扰 |
| 知识库更新频率 | 每日凌晨同步 | 匹配业务数据每日更新的节奏 |

## 容易做错的三处
- 现象为对话返回非标准JSON格式内容，原因是提示词未明确指定输出格式约束，导致结合政府采购文档与党建内容时输出混乱。
- 现象为上传政府采购相关文档时提示“fail to create post presigned url”报错，原因是升级FastGPT v4.17.0后S3存储配置未同步更新，或权限配置不符合业务文档存储的合规要求。
- 现象为多轮对话中无法关联历史采购需求文档内容，原因是未正确绑定`chatId`参数，导致上下文无法跨轮次保留。

## 怎么确认配好了
- 发起包含采购项目编号的连续多轮提问，核对对话上下文是否保留前几轮的项目信息与党建相关问题的关联内容。
- 上传当日更新的政府采购文档，确认知识库同步状态正常，无报错提示。
- 测试不同类型的政府采购文档（如招标文件、评标报告）的问答匹配度，调整配置参数至符合业务需求。
- 验证对话返回格式是否符合预设的结构要求，确保输出内容符合政府采购与党建学习的规范。
