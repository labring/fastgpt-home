# 政府采购项目的党建学习问答：知识库检索与召回

本配置基于 FastGPT v4.17.0 版本。

## 这个品类的数据长什么样
本品类的数据来自中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。典型文档包含采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同及质疑答复，同时伴随党建学习相关的配套文本，涉及采购人单位、财政部门政府采购监管处、采购代理机构、评审专家四类主体。数据以结构化采购流程文档为主，单份文档长度多在500–5000字符，字段包含采购编号、项目名称、供应商资质要求等标准化内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的采购及党建数据要求检索系统支持增量同步，同步间隔不超过24小时，避免全量重索引占用过多资源。多类型的采购文档存在严格的环节区分，且党建学习内容需与采购场景隔离，检索需限定在指定采购项目或党建学习材料范围内，防止跨环节文档干扰。标准化的采购字段与固定党建术语要求检索匹配精度较高，避免模糊匹配导致的合规风险。同时，数据来源分散于多个政府采购相关系统，需统一接入知识库，确保检索覆盖所有合规数据源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 政府采购及党建文本术语严谨，需较高匹配度避免无关结果 |
| `limit` | 前 8 条 | 采购及党建文档数量较多，控制返回结果避免冗余 |
| `searchMode` | vector+keyword | 兼顾采购文档的结构化字段与党建文本的语义匹配需求 |
| `usingReRank` | 开启 | 过滤与当前党建学习问答无关的采购流程文档 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 党建问答需严格匹配原文内容，不进行问题扩展 |
| `collectionIds` | 按采购项目分组的数据集 ID | 限定检索范围，防止跨项目数据干扰党建学习问答的准确性 |

## 容易做错的三处
- 现象：后台删除知识库中的问答对后，FastGPT 检索结果仍包含该内容。原因：未触发数据集的增量同步，缓存的嵌入向量未被清理，导致旧数据仍存在于检索索引中。
- 现象：知识库上传文件偶尔失败，且卡在1组或2组索引。原因：使用本地 m3e-large 模型时，模型加载超时或政府采购文档的非标准格式无法被正确解析，导致索引构建失败。
- 现象：检索结果出现大量拼音匹配的无关内容，或包含非指定范围内的文档。原因：未开启`searchMode`的 keyword 匹配，或未通过`collectionIds`限定检索范围，导致系统优先匹配拼音相似的非目标内容。

## 怎么确认配好了
- 发起一条党建学习相关的检索请求，核对返回结果的文档均为党建学习材料或指定范围内的采购文档，且未出现拼音匹配的无关内容。
- 手动删除一条测试问答对，触发数据集同步后再次检索，验证该内容不再出现在结果中。
- 上传一份不符合格式的测试文档，检查上传状态是否返回格式错误提示，验证异常处理逻辑生效。
- 调整`similarity`阈值至0.7，观察检索结果的匹配精度变化，确认配置参数可正常生效。
