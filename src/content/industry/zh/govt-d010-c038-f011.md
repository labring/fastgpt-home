# 政府采购项目的党建学习问答：表单与交互

## 这个品类的数据长什么样
本品类的数据来源包括中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录。日常处理的文档涵盖采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复与变更公告。数据更新频率为每日，涉及的主体包含采购人单位、财政部门政府采购监管处、采购代理机构及评审专家，不同文档需遵循政府采购法体系的字段与格式规范。

## 这些特征在「表单与交互」这一环带来什么约束
多源分散的数据来源要求表单需支持多渠道文档批量导入与元数据绑定，减少手动录入的重复操作。每日更新的频率要求交互环节支持实时同步新上传的采购文档，确保党建问答内容始终匹配最新的项目信息。多样的文档类型要求表单需适配不同文档的字段结构，实现自定义的问答关联规则。严格的出错后果要求交互环节内置校验机制，避免因数据错误引发废标、投诉等合规问题。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配政府采购文档的单段内容长度，避免跨文档块断裂导致问答不完整 |
| 单次问答上限 | 前 10 条召回结果 | 匹配政府采购文档的单次调用数据量，减少冗余信息干扰 |
| 超时阈值 | 60 秒 | 适配财政系统的接口响应节奏，避免因等待过长导致流程中断 |
| 单文件上传上限 | 1000 MB | 适配政府采购大型招标文件的上传需求，满足多页文档的导入要求 |
| `formInput` 配置 | 绑定采购文档元数据字段 | 实现党建问答与采购项目信息的关联调用，确保问答内容贴合项目场景 |
| `userSelect` 组件 | 开放采购人、评审专家两类角色选择 | 匹配政府采购项目的参与主体权限，过滤非授权角色的问答范围 |

## 容易做错的三处
- 现象：问答对提取结果中问题与答案不匹配，原因：未按先拆分文档再应用QA引导词的顺序配置处理流程，导致引导词作用于未拆分的完整文档。
- 现象：配置全局变量存储采购项目编号后，节点调用时提示输入为空，原因：未在`formInput`中绑定全局变量的触发时机，导致变量未完成加载就执行问答逻辑。
- 现象：选择qwen-plus模型并开启思考输出后，结果未显示思考过程，原因：未在`formInput`中配置模型参数的显式提示，导致思考逻辑未被触发。

## 怎么确认配好了
- 上传单份政府采购招标文件，触发党建问答功能，检查返回的问答对是否包含文档内的党建相关内容。
- 切换`userSelect`组件中的角色选项，检查不同角色是否能访问对应权限的问答内容。
- 上传一份超过800字符的采购需求文档，检查分块后的问答对是否完整覆盖文档内容。
- 模拟每日更新的采购公告上传，检查系统是否自动同步新数据并生成更新后的问答对。
