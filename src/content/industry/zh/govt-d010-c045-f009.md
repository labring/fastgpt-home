# 用地预审与规划许可的党建学习问答：模型接入与配置

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类数据来自国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。日常处理的文档包括用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，包含项目编号、用地规模、规划管控要求、红线坐标等字段，单份文本类文档长度差异较大，图纸类文件数据量无固定标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新无固定周期，要求模型接入时支持多源异构数据的批量导入与增量同步。文档包含文本与图纸两类，需配置适配多模态的模型能力。字段专业性强，需确保模型准确识别用地规模、红线冲突等专业术语。单份文档数据量差异大，需合理限制单轮处理的上下文长度，避免超出模型承载上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配本品类多源文档的总长度，避免超出模型上下文承载上限 |
| `maxTokens` | 2000–3000 token | 控制单轮回答的输出长度，匹配党建学习问答的信息密度需求 |
| `quoteMaxToken` | 1500 token | 限制引用的文档片段总长度，确保引用内容与问题的相关性 |
| `vision` | 开启 | 适配红线图、规划条件等图纸类文档的解析需求 |
| `temperature` | 0.3–0.5 | 降低回答的随机性，确保专业政务与党建内容的准确性 |
| `AIPROXY_API_ENDPOINT` | 按平台提供的专属地址填写 | 确保模型请求的路由正确，适配多模型接入场景 |

## 容易做错的三处
- 现象：调用第三方大模型时出现`tls: failed to verify certificate: x509: certificate signed by unknown authority`报错。原因：未配置正确的代理证书或网络环境存在证书校验限制，导致模型请求无法完成安全验证。
- 现象：本地向量模型切分的文档上传服务器后，检索结果异常或无法匹配。原因：服务器使用的向量模型与本地模型嵌入维度不匹配，或文档格式转换时丢失了关键的嵌入向量信息。
- 现象：配置模型重定向规则后，实际调用的模型与预期不符。原因：未正确填写重定向规则的映射关系，或规则优先级配置错误，导致系统未按预期调用目标模型。

## 怎么确认配好了
- 发起一次测试提问，输入党建相关的用地预审政策问题，检查回答是否包含准确的专业术语与合规内容。
- 上传一份红线图文档，检查模型是否能正确识别图中的坐标与规划管控要求。
- 查看模型调用日志，确认请求的API地址、密钥与配置项一致，无证书校验报错。
- 测试多源文档的导入与检索，确认不同类型的文档都能被正确索引与召回。
