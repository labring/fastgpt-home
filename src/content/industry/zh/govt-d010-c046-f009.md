# 社会救助与低保审核的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
本品类的数据覆盖民政救助相关标准化文档与跨部门共享数据，日常文档包含低保申请表、家庭经济状况核对报告、入户调查表、公示材料等。数据来源为低收入人口动态监测平台、居民家庭经济状况核对系统及跨部门共享数据，更新频率为每月一次。数据字段包含家庭收入与财产状况、家庭成员信息、申请资格相关内容，结构贴合民政业务标准化流程。

## 这些特征在「模型接入与配置」这一环带来什么约束
跨部门多源数据的接入需要适配统一格式标准，避免因数据字段差异导致模型识别错误。每月更新的数据同步需求，要求配置项支持定期增量或全量更新的规则。标准化的民政文档与扫描件材料，需要模型具备文本与视觉识别能力，保障材料审核的准确性。家庭隐私与救助资格的严格要求，需要限制模型输出的随机性，确保判断结果的合规性与一致性。

## 配置怎么定
FastGPT v4.17.0 版本下的配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配长文本的家庭经济状况核对报告、多份表单整合内容的上下文需求，覆盖党建学习问答中的政策与材料结合分析场景 |
| `temperature` | 0.1–0.3 | 降低随机输出，保障低保资格判断与政策解读的准确性，避免主观偏差，符合党建学习问答的严谨性要求 |
| `vision` | 开启 | 用于识别入户调查表、公示材料等扫描件的内容，覆盖党建学习问答中的材料审核与政策匹配场景 |
| `quoteMaxToken` | 1500–2000 token | 限制引用的文档片段长度，聚焦家庭收入、成员关系等核心核对字段，同时关联党建学习中的政策要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配国内大模型的接入地址，满足民政场景的数据合规要求 |
| `AIPROXY_API_TOKEN` | 按平台分配填写 | 保障接口调用的权限安全，符合政务数据的访问管控规则 |

## 容易做错的三处
- 现象：界面无法选中通义千问等国内大模型，或调用时返回模型不存在的报错。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或未在平台中绑定对应模型的权限。
- 现象：传入扫描的入户调查表后，模型返回空的识别结果。原因：未开启`vision`配置项，或未使用符合要求的图片传输格式。
- 现象：模型生成的低保资格判断出现偏差，错误匹配家庭收入字段。原因：`temperature`取值过高，或`maxContext`设置不足，未加载完整的跨部门共享数据。

## 怎么确认配好了
- 发起测试调用，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置，确认接口返回正常的模型响应。
- 上传一份标准的低保申请表扫描件，验证`vision`配置是否生效，模型能否正确提取表单中的核心字段。
- 导入一份月度更新的家庭经济状况数据，测试`maxContext`与`quoteMaxToken`的配置是否能完整加载并处理长文本内容。
- 调整`temperature`参数至0.2，发起多次相同问题的调用，确认输出结果的一致性符合预期。
