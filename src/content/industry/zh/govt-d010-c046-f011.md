# 社会救助与低保审核的党建学习问答：表单与交互
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类服务于民政救助全流程，核心参与主体包括民政局救助科、街道乡镇民政办、社区居委会、核对中心。日常业务文档包含低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料、救助审批表，核心字段覆盖家庭收入、财产状况、成员关系、救助资格认定等。数据来源为低收入人口动态监测平台、居民家庭经济状况核对系统，以及公安、人社、医保、住建、税务等跨部门共享数据，更新频率为月度，数据需与线下入户调查、公示记录交叉核验。

## 这些特征在「表单与交互」这一环带来什么约束
跨部门共享数据的月度更新要求，表单需支持定期同步核对数据，避免使用过期信息导致的错保漏保。多类型业务文档的字段差异，要求表单需适配不同环节的输入项，比如入户调查环节需采集现场佐证信息，公示环节需收集群众反馈字段。家庭收入财产等敏感数据的核验需求，要求表单需支持多字段联动校验，同时需保障数据交互过程的合规性。救助审批流程的多主体参与，要求表单需配置分级权限的交互逻辑，确保不同岗位人员仅能操作对应环节的内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 配置为家庭收入、财产状况、成员关系等核心字段的必填项，联动跨部门数据校验 | 本品类需确保核心信息准确，避免错保漏保，保障救助资格认定的合规性 |
| `userSelect` | 按岗位配置权限，仅允许民政局救助科人员修改审批状态字段 | 本品类涉及救助资金发放，需严格权限管控，防止非授权人员篡改审批结果 |
| 单次输入上限 | 800–1200 字符 | 日常业务文档的单条内容长度符合该区间，避免过长内容影响检索与交互效率 |
| 超时阈值 | 600 秒 | 跨部门数据调取需一定时间，保障完整获取月度更新的核对数据 |
| 上下文匹配条数 | 前 3 条 | 本品类需精准匹配家庭经济状况相关信息，避免冗余结果干扰业务判断 |
| 模型输入token长度 | 1000 token | 本品类的党建学习问答内容通常不超过该长度，避免超出模型输入限制 |

## 容易做错的三处
- 现象：首次提交家庭经济状况核对相关的党建学习问答后，系统未返回匹配结果，再次提交相同问题后正常返回。原因：首次查询时未完成跨部门共享数据的实时同步，知识库未加载最新月度更新的核对数据。
- 现象：提交测试表单时，缺少家庭收入字段的校验提示，提交后发现数据缺失。原因：未针对`formInput`配置的核心字段设置必填校验，遗漏了家庭经济状况的关键信息。
- 现象：工作流中classify模块无法选择模型，发布工作流后可正常调用指定模型。原因：未在开发环境中完成模型权限配置，发布后自动继承生产环境的模型权限配置。

## 怎么确认配好了
- 提交包含家庭收入、成员关系字段的测试表单，检查是否触发必填项校验提示，确认`formInput`配置生效。
- 切换不同岗位的测试账号，检查是否仅能访问对应环节的表单交互入口，确认`userSelect`权限配置正确。
- 提交党建学习相关的低保政策问答，检查首次提交即可返回匹配的业务文档内容，确认数据同步与检索配置正常。
- 查看工作流的classify模块，确认开发环境与生产环境的模型选项一致，确认模块配置无误。
