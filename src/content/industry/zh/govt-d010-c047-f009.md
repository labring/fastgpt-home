# 行政处罚案卷办理的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
该品类数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，以违法事实认定、处罚依据及决定文书为核心结构，需形成可追溯的处罚证据链。

## 这些特征在「模型接入与配置」这一环带来什么约束
执法类单份文书内容较长，会占用模型上下文额度，需限制输入输出的token总量；数据每日更新，需配置增量同步逻辑以保证问答内容时效性；处罚案卷需严格匹配证据与决定，模型返回的引用需精准关联原始文档片段，避免无关内容；不同执法场景的文档格式存在差异，需适配多类型执法文书的分块与检索规则，确保问答内容符合执法规范与党建学习的严谨要求。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本进行说明。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单份执法文书的典型长度，避免上下文溢出导致问答中断 |
| `maxTokens` | 2000–3000 token | 控制单轮回答的输出长度，确保处罚相关内容表述完整且符合规范 |
| `quoteMaxToken` | 1500–2000 字符 | 限制引用文档片段的长度，匹配执法文书的标准段落长度 |
| `temperature` | 0.1–0.3 | 降低回答的随机性，确保问答内容严谨，符合执法与党建学习的要求 |
| `AIPROXY_API_ENDPOINT` | 按平台提供的官方地址填写 | 适配模型调用的网络路径要求，确保请求可正常送达 |
| `AIPROXY_API_TOKEN` | 按实际申请的密钥填写 | 完成模型调用的身份验证，避免请求被拒绝 |

## 容易做错的三处
- 现象：调用接入的OpenAPI模型时，系统提示模型流响应为空。原因：未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或模型本身未开启流式响应输出。
- 现象：启用重排功能后，知识库问答响应速度明显下降。原因：未限制检索召回的文档数量，或未调整`maxContext`以适配重排后的上下文负载。
- 现象：系统日志显示问答实际使用的模型与应用配置的模型不一致。原因：未在知识库关联配置中关闭独立模型设置，导致知识库优先使用自身配置的模型。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容，发起一次测试调用，确认无身份验证或网络错误。
- 上传一份典型的行政处罚决定书至测试知识库，发起结合党建学习与执法业务的问答，查看返回结果的引用片段是否匹配原始文档内容。
- 查看系统日志，确认模型调用时使用的参数与配置项一致，无意外的参数覆盖。
- 模拟每日增量数据同步，确认知识库可正常更新新增的执法文档与党建学习内容。
