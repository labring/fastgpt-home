# 行政许可审批的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源为全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统及电子证照库，每日更新。日常文档包含办事指南、申请表、受理通知书、补正告知书等标准化审批类文件，字段涵盖事项编码、法定依据、办理条件、申请材料清单等，每份文档绑定对应行政许可事项的唯一标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据每日更新的特性要求模型接入环节需配置定时同步规则，确保关联的审批事项库、电子证照库数据与业务系统实时对齐；标准化的审批文档结构要求上下文处理需绑定对应行政许可事项的唯一标识，避免跨事项的文档混淆；跨部门调取电子证照的需求要求配置项需预留接口超时与重试参数，保障证照数据获取的稳定性；法定依据与办理条件的严格匹配要求模型的上下文长度需适配长文档处理，避免截断关键审批规则。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配审批类长文档（办事指南、法定依据）的上下文承载需求，避免截断关键审批规则 |
| `maxTokens` | 2000–3000 token | 满足审批意见、补正告知书等标准化文档的生成长度，保障输出内容完整 |
| `quoteMaxToken` | 1500–2000 token | 限定引用的审批文档片段长度，确保引用内容精准且不超出上下文配额 |
| `toolChoice` | auto | 支持自动调用跨系统接口调取电子证照或事项清单，适配行政许可审批的跨部门数据需求 |
| `temperature` | 0.1–0.3 | 保持审批内容的严谨性，避免生成不符合法定要求的表述 |
| `AIPROXY_API_TOKEN` | 按授权凭证填写 | 验证接口调用权限，确保数据调取的安全性 |

## 容易做错的三处
- 现象：调用跨系统审批数据接口时返回401状态码。原因：未正确配置`AIPROXY_API_TOKEN`，导致接口调用权限验证失败。
- 现象：日志中出现`Unexpected end of JSON input`报错。原因：单次请求的上下文长度超出`maxContext`配置上限，导致接口返回不完整的JSON数据。
- 现象：同一问答请求触发两次接口调用，第二次请求的授权字段为空。原因：未正确配置接口重试逻辑，导致重试请求未携带有效`AIPROXY_API_TOKEN`。

## 怎么确认配好了
- 手动发起包含行政许可事项的党建学习问答查询，检查返回结果是否关联对应事项的法定依据与办理条件。
- 查看接口调用日志，确认每次请求均携带有效`AIPROXY_API_TOKEN`，无异常重复请求。
- 上传完整的办事指南文档进行问答测试，确认返回结果未出现关键内容截断。
- 启用定时同步任务，次日检查审批事项数据是否自动更新至模型知识库。
