# 规范性文件合法性审核的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来自法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新频率不定期。日常处理的文档包括规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告，单份文档篇幅跨度较大，从数百字符到数万字符不等。每份文档包含文件编号、起草单位、审核流程记录、征求意见条目等固定字段，无统一的单份文档固定字数标准，需按原始文件格式完整导入。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散且更新不定期，引用溯源环节需确保每次检索都能匹配到最新的备案文件版本，避免引用过期的草案或审核意见。文档篇幅跨度大，需在检索时区分草案原文与配套说明类文档，避免将起草说明误作为合法性审核依据。每份文档的固定字段为溯源提供了唯一标识，需通过字段匹配确认引用文件的真实性，防止出现跨品类的文档混淆。同时，出错后果直接关联政策发布与备案合规，溯源环节需明确标注每条引用内容的原始来源库与文件编号，便于后续核查。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |

| `quoteMaxToken` | 8000–12000 token | 适配规范性文件单份文档的平均篇幅，确保完整引用审核依据原文 |
| `responseData` | 开启来源字段返回 | 用于提取引用文件的编号、来源库等标识，完成溯源标注 |

| 单次召回上限 | 前6条 | 覆盖单次审核所需的上位法与政策依据数量，避免冗余检索 |
| 分块重叠长度 | 200–300 字符 | 匹配规范性文件条文的段落结构，防止跨条文的分块断裂 |
| 文档类型过滤 | 仅保留草案与审核意见类 | 排除非审核相关的征求意见汇总等文档，缩小检索范围 |

## 容易做错的三处
- 现象：部分导入的规范性文件未生成问答对，直接以原文块形式存入知识库。原因：未开启针对长文档的自动问答生成配置，系统仅完成文本分块未生成关联问答对。
- 现象：配置模型后测试提示报错，强行忽略后正式检索环节可运行。原因：测试接口未适配合规类文档的长上下文输入，仅正式检索链路兼容长文本调用。
- 现象：工作台检索时仅返回单条引用结果，系统提示“知识库引用(1条)”。原因：单次召回上限配置设置为1，或未开启多文档关联匹配的溯源开关。

## 怎么确认配好了
- 导入一份标准规范性文件草案，查看知识库分块列表，确认分块按条文拆分，无跨条文的断裂块。
- 发起党建学习问答提问，查看回答下方的引用溯源模块，确认每条引用内容标注了文件编号、来源库与具体段落位置。
- 调整单次召回上限为6，发起涉及多条上位法与政策依据的提问，确认返回的引用结果数量符合配置取值。
- 测试长文档导入后的问答生成，确认系统生成的问答对与原文核心审核依据内容匹配，无关键信息缺失。
