# 财政支出绩效评价的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自财政局绩效处、预算单位、第三方评价机构及主管部门，日常文档包含绩效目标表、自评表、绩效评价报告、佐证材料清单与整改报告。数据来源覆盖预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查，更新频率为年度。数据处理环节中，收集项目产出效果佐证、核验资金支出与绩效目标对应关系、撰写问题及整改建议为核心耗时步骤。

## 这些特征在「向量模型与索引」这一环带来什么约束
年度更新的频率决定索引无需高频增量同步，适合采用全量重建的更新策略。多类型的业务文档要求索引支持多格式解析，且需适配绩效目标表、自评表中结构化字段与文本混合的内容。多系统来源的数据存在格式差异，需要在索引前完成字段标准化映射。核验资金与绩效目标的对应关系为核心业务需求，要求向量检索需精准匹配关联内容，避免召回无关文档。同时，出错后果直接关联预算与问责，需确保检索结果的可信度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配绩效评价报告的段落长度，避免单块包含过多无关内容 |
| 重叠长度 | 100–150 字符 | 保留跨分块的绩效指标关联信息，防止关键内容被截断 |
| maxToken | 4096 token | 适配党建学习问答的上下文长度要求，覆盖单条绩效评价的核心内容 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 确保召回的文档与绩效目标、资金支出的关联度符合业务核验要求 |
| 单次搜索上限 | 前 8 条 | 平衡检索效率与信息完整性，覆盖核心佐证材料与评价内容 |
| defaultToken | 2048 token | 作为默认上下文长度，适配多数绩效相关问答的信息需求 |

## 容易做错的三处
- 现象：检索结果混入大量无关党建通用内容，无法精准匹配绩效相关文档。原因：未为财政支出绩效评价场景创建专属索引，混用通用党建知识库，导致召回范围超出业务需求。
- 现象：索引构建过程中出现结构化表格解析失败，绩效目标表中的指标字段未被提取。原因：未开启多格式解析的结构化字段提取开关，仅对纯文本内容进行分块，丢失表格内的关键关联信息。
- 现象：检索请求超时，界面返回状态码504。原因：未调整`maxToken`与单次搜索上限配置，单批次处理的文档量超出FastGPT v4.17.0的默认处理上限。

## 怎么确认配好了
- 上传单份典型绩效评价报告与党建学习材料，执行检索测试，核对召回结果中与绩效目标直接相关的内容占比，调整相似度阈值至符合业务核验要求的区间。
- 查看索引构建日志，确认PDF、PPT、Word等多格式文档均被正确解析，结构化字段已被提取并纳入向量存储，无解析失败的报错记录。
- 模拟年度数据更新流程，执行全量索引重建，核对重建耗时与预期匹配，确认更新流程无卡顿或中断。
- 调用检索接口，验证返回结果的条数符合单次搜索上限的配置，且无超出业务范围的无关内容被召回。
