# 财政支出绩效评价的党建学习问答：部署与升级

## 这个品类的数据长什么样
本品类的数据来自预算管理一体化系统、项目申报材料、资金支付数据、业务系统台账及满意度调查，更新频率为每年一次。日常处理的文档包括绩效目标表、自评表、绩效评价报告、佐证材料清单与整改报告，文档字段覆盖项目标识、资金拨付节点、绩效指标完成情况、佐证材料关联编号等，单份文档体量差异较大，从数百字符的自评表到数万字符的完整评价报告不等。

## 这些特征在「部署与升级」这一环带来什么约束
数据来源分散且需对接多套内部业务系统，部署时需配置多源数据接入能力，确保不同系统的字段格式兼容。年更新频率要求部署后需支持定期全量或增量数据同步，避免知识库内容滞后。文档体量差异大，需适配不同长度的文本处理，同时需保障绩效指标、佐证材料关联字段的精准提取，避免关联错误影响问答准确性。党建学习问答场景需确保涉密或敏感财政数据不被泄露，部署环节需配置数据脱敏与权限管控规则，符合政务数据安全要求。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:securepass@internal-db:27017/fiscal_perf?authSource=admin` | 存储党建学习问答的知识库元数据、绩效文档关联信息与对话日志，需绑定专属业务数据库 |
| `REDIS_URL` | `redis://:cachepass@internal-cache:6379/1` | 缓存高频查询的绩效指标、党建政策关联内容，降低向量数据库重复调用次数 |
| `STORAGE_S3_ENDPOINT` | `http://10.10.10.5:9000` | 存储绩效评价报告、佐证材料等大容量附件，适配多体量文档的存储需求 |
| `DB_MAX_LINK` | 800–1200 MB | 限制单次批量导入的文档总大小，避免超出系统存储上限 |
| `ROOT_KEY` | 随机生成的36位UUID字符串 | 配置平台管理权限，用于创建并管理财政支出绩效评价专属的知识库 |
| 单次召回上限 | 前6条 | 匹配绩效文档与党建问答的精准度，过滤低相关条目，提升回答准确性 |

## 容易做错的三处
- 启动容器后出现`connection refused`报错，日志显示无法连接`MONGODB_URI`指定的数据库。原因是未正确配置数据库访问权限，或数据库服务未开放对应端口。
- 知识库导入后出现大量空字段的绩效文档条目，无法关联佐证材料。原因是未适配多源数据的字段格式差异，未做字段映射配置。
- 平台容器出现周期性无限重启，无法正常加载党建问答知识库。原因是未配置`REDIS_URL`的访问密码，或缓存服务与主服务的网络隔离策略限制了跨网段通信。

## 怎么确认配好了
- 登录FastGPT管理后台，查看数据库连接状态面板，确认`MONGODB_URI`与`REDIS_URL`的连接状态为正常。
- 上传一份标准绩效自评表作为测试文档，确认系统能正确解析文档中的绩效指标与项目名称字段。
- 发起一条测试提问，如“某项目的绩效自评依据有哪些”，确认返回的结果包含关联的佐证材料清单与自评表内容。
- 检查容器运行日志，确认无数据库连接超时、存储服务访问失败等报错信息。
