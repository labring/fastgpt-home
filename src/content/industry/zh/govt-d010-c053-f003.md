# 部门预算编制的党建学习问答：多轮对话与提示词

本文基于FastGPT v4.17.0版本配置说明编写。

## 这个品类的数据长什么样
该品类的数据主要来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知，部分数据包含党建活动经费测算内容。日常处理的文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复，其中党建相关经费需单独标注。数据更新频率为年度周期，核心字段涵盖人员公用经费、项目支出额度、绩效目标分值、党建活动经费标准等，数据结构围绕年度资金申报与安排逻辑搭建。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
党建学习问答的场景要求多轮对话需同时覆盖财政预算编制规范与党建引领的经费使用要求，因此上下文需同时保留业务与党建相关的历史提问。年度更新的数据特性要求多轮对话需绑定当前预算年度上下文，避免跨年度数据混淆。多源数据来源需要提示词明确区分预算管理一体化系统的执行数据与项目库的储备数据，防止调用错误文档。专业字段较多的文档结构，要求多轮对话中需保留用户提及的具体测算项、申报单位、党建经费占比等信息，避免重复确认。同时，预算编制的出错后果明确，提示词需嵌入审核校验逻辑，确保对话生成内容符合财政与党建相关要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `chatId` | 绑定当前预算单位+年度编制的唯一字符串 | 确保多轮对话上下文与特定预算单位、年度绑定，避免跨批次混淆 |
| `messages` | 保留最近10轮对话内容 | 部门预算编制文档量较大，过多历史会占用上下文资源，过少会丢失审核与党建相关的上下文 |
| `variables` | 传入当前预算年度、单位编制人数、党建活动经费额度上限 | 让提示词能直接调用业务专属参数，减少重复输入，适配党建与预算结合的复合场景 |
| 最大上下文长度 | 8000–12000 token | 部门预算编制相关文档的平均长度，确保能加载完整的年度编制通知与申报模板 |
| 单次搜索上限 | 前3条匹配结果 | 核心数据集中在预算管理一体化系统与项目库，过多结果会干扰提示词对专业与党建复合问题的判断 |
| 问题优化开关 | 开启 | 针对党建与预算结合的专业术语，优化后可提升对话对复合问题的理解精度 |

## 容易做错的三处
- 现象：调用对话接口时`messages`字段为空，多轮对话上下文丢失。原因：未绑定`chatId`参数，导致系统无法关联对应会话的历史记录，无法加载之前的预算与党建相关提问。
- 现象：应用运行时出现参数校验报错，未记录异常日志。原因：未开启对话日志采集配置，无法回溯异常发生时的`chatId`、`messages`等关键参数内容。
- 现象：提示词未按预期覆盖党建经费相关要求，生成内容偏离业务规范。原因：未在`variables`中传入党建活动经费额度上限等专属参数，提示词无法结合党建要求完成校验。

## 怎么确认配好了
- 发起包含历史上下文的测试提问，验证系统能正确关联之前提及的预算年度与党建经费相关要求。
- 触发异常报错，检查是否生成对应日志条目，包含`chatId`与`messages`字段的完整内容。
- 查看提示词配置，确认`variables`中已包含当前预算编制所需的核心业务与党建相关参数。
- 测试多轮对话中，系统能正确调用匹配的预算编制文档，无无关内容混入。
