# 部门预算编制的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
典型主体为财政局预算处、预算单位财务处等，日常生成的文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等。数据主要来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库以及财政部发布的预算编制通知，更新频率为年度周期。文档多为结构化表格形式，包含预算编码、项目名称、支出金额、绩效目标等字段，不同来源的数据格式存在一定差异。

## 这些特征在「引用来源与溯源」这一环带来什么约束
年度更新的频率要求知识库需定期完成全量数据同步，避免出现旧数据与最新政策不匹配的情况。结构化的文档格式要求召回环节需精准匹配字段信息，避免模糊召回导致引用内容偏离业务场景。多来源的数据需要明确标识来源类型，以便在溯源时区分内部业务系统数据与官方通知内容。同时，单份文档的长度较长，需控制召回的上下文总量，防止超出大模型的token限制，影响回答的完整性与准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 8000–12000 token | 部门预算编制类文档单份长度较长，需保留足够上下文以覆盖完整的预算项目信息，同时避免超出模型上下文限制 |
| 召回结果上限 | 前6条 | 该品类核心文档数量集中，过多的召回结果会增加大模型处理负担，且易导致引用冗余 |
| 相似度阈值 | 0.75–0.85（按实测标定） | 需平衡召回的相关性与完整性，避免阈值过高遗漏关键预算数据，或过低引入无关内容 |
| `responseData` | 开启 | 需将引用来源与原始文档的具体字段绑定，确保溯源时可直接定位到对应文档 |
| `detail` | 开启 | 需在回答中展示引用文档的核心字段，便于核对内容的合理性与准确性 |

## 容易做错的三处
- 返回的引用文档数量远超预期。原因是未配置召回结果上限，或相似度阈值设置偏低，召回了大量非核心的预算测算表格。
- 回答未采用知识库中综合排名靠前的内容。原因是未开启重排功能，或未按文档更新时间排序召回结果，导致旧数据优先展示。
- 无法校验引用内容的合理性。原因是未开启`responseData`配置项，未将引用来源与原始文档的预算编码、项目名称等字段绑定，无法提取具体信息进行核对。

## 怎么确认配好了
- 上传一份年度部门预算草案和最新的财政部预算编制通知，发起党建学习相关的预算查询，检查返回结果中是否包含对应的来源标识与核心业务字段。
- 进入FastGPT v4.17.0的知识库配置页面，确认`quoteMaxToken`、`responseData`、`detail`等配置项已按要求完成设置。
- 发起包含具体预算项目名称的查询，核对返回的引用内容是否与原始文档中的对应字段信息一致。
- 模拟年度数据更新流程，重新上传最新的预算编制通知与调整后的草案，发起相同查询，确认新的文档被优先召回。
