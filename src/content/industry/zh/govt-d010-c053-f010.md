# 部门预算编制的党建学习问答：知识库检索与召回

## 这个品类的数据长什么样
该品类数据主要来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部预算编制通知。日常文档包含部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等，通常包含项目编码、预算额度、人员编制数等字段，更新频率为年度，仅在年度预算周期内完成更新与流转，涉及主体多为财政局预算处、预算单位财务处等部门。

## 这些特征在「知识库检索与召回」这一环带来什么约束
年度更新的特性要求知识库仅需在年度预算筹备阶段完成全量刷新，无需高频增量同步，降低日常运维成本。多类型结构化文档混合的特征，要求检索环节需针对不同文档类型配置差异化的字段匹配权重，确保预算额度、项目编码等核心业务字段的召回优先级。跨数据源的内容整合需求，要求检索召回同时覆盖党建学习政策与预算编制规范，需配置跨数据集检索能力，避免检索范围局限于单一文档类型。业务出错后果直接影响资金安排，因此需严格控制召回结果的精准度，避免无关内容干扰审核环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配部门预算编制的结构化字段与党建政策的文本精度，兼顾召回率与精准度 |
| `limit` | 前10条 | 适配年度预算文档的体量，避免过多召回结果导致上下文过载 |
| `searchMode` | 混合检索 | 同时支持结构化字段匹配与非结构化文本召回，覆盖预算草案与党建政策两类内容 |
| `usingReRank` | 开启 | 对初始召回结果进行重排序，提升党建政策与预算编制要求的匹配相关性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 结合历史对话优化问题，解决党建语境下的指代消除问题 |
| `collectionIds` | 预设的预算编制文档库与党建政策库的集合ID | 精准指定检索范围，避免无关数据集的内容干扰 |

## 容易做错的三处
- 现象：调用知识库API时，检索结果未结合历史对话优化，出现指代不明的问题。原因：未开启`datasetSearchUsingExtensionQuery`配置，未启用历史对话扩展查询功能。
- 现象：知识库检索触发后GPU资源无占用，检索任务超时无返回。原因：未正确关联`collectionIds`对应的数据集存储节点，导致检索请求无法调度至GPU计算资源。
- 现象：检索配置保存后，重启FastGPT v4.17.0服务后自动恢复为默认参数。原因：未开启配置持久化存储，或配置提交时未完成集群节点同步。

## 怎么确认配好了
- 进入FastGPT知识库管理界面，查看`collectionIds`配置是否已绑定预算编制文档库与党建政策库的对应集合ID。
- 发起测试检索，输入包含党建政策关键词与预算编制术语的组合问题，检查返回结果是否包含两类内容且排序符合预期。
- 保存配置后重启服务，再次进入配置界面，确认参数未恢复为默认值。
- 调用知识库API，传入包含指代内容的历史对话上下文，检查返回结果是否优化了指代不清的问题。
