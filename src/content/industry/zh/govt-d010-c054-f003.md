# 防汛防灾与应急值守的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来源涵盖气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控，更新频率为每日。日常处理的文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单，数据字段多包含雨情水情数值、险情等级、转移人数、物资品类与数量等，单位涉及毫米、立方米、人次、吨等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且需实时整合，要求多轮对话需完整跟踪会话内的雨情、水情、险情等变量，避免上下文丢失。文档字段细分且带特定单位，提示词需明确指定提取对应字段与单位，防止参数混淆。更新频率为每日，提示词需限定查询近24小时的最新数据，避免调用过时信息。跨部门调度的场景下，多轮对话需支持按不同系统的数据源分类获取参数，确保信息准确。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `variables` | 按会话轮次动态绑定并更新 | 防汛场景需持续跟踪降雨时段、受灾点位、物资余量等可变参数，动态绑定可确保多轮对话的参数一致性 |
| `messages` | 保留近15–20轮对话内容 | 应急值守的对话需回溯近期的雨情通报、险情记录，该轮次范围可覆盖完整处置流程且不占用过多资源 |
| `chatId` | 绑定对应值守任务的唯一ID | 确保同一应急任务的多轮对话上下文不混淆，避免跨任务参数串用 |
| 最大上下文长度 | 8000–12000 token | 需容纳会商纪要、灾情速报等长文本内容，该区间可覆盖典型场景的上下文需求 |
| 语音转文字超时时间 | 30–60 秒 | 语音输入的音频解析需在合理时间内完成，该区间可覆盖多数网络环境下的解析需求 |
| 参数提取规则 | 按实测标定的字段匹配逻辑 | 防汛场景的参数包含降雨毫米数、转移人数等带单位的字段，需针对性配置提取规则 |

## 容易做错的三处
- 现象：提取的降雨时段、受灾区域等关键词变量为空或匹配错误。原因：未在提示词中明确指定需提取的防汛专属字段与单位，导致模型混淆通用参数与场景专属参数。
- 现象：语音输入后无文字转化结果。原因：未配置语音模型的调用参数，或未开启会话内的语音转文字功能，导致音频无法完成解析。
- 现象：多轮对话后关键上下文丢失，无法回溯前期的雨情通报。原因：未正确绑定`chatId`或限制了对话保留轮次，导致会话上下文被提前清空。

## 怎么确认配好了
- 发起包含降雨时段、受灾点位等可变参数的测试对话，验证参数是否正确绑定并更新，核对提取结果与输入内容是否一致。
- 查看会话历史记录，确认保留的对话轮次符合配置要求，无早期冗余或关键上下文丢失。
- 触发语音输入功能，验证音频是否能正常转化为文字，确认配置逻辑符合场景需求。
- 输入包含防汛专属字段的查询，验证参数提取规则是否能准确提取对应字段与单位。
