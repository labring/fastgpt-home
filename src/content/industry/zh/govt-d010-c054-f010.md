# 防汛防灾与应急值守的党建学习问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控。日常文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单，字段多包含雨情水情数值、预警等级、处置时限、物资数量与单位等。数据更新频率为每日，部分实时预警类文档更新频次更高。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源要求检索链路需支持跨系统数据的关联召回，避免信息割裂；文档类型跨度大，从简短预警通知到数千字的处置方案，需适配不同长度的文本分块与召回逻辑；每日更新的频率要求知识库同步机制具备实时性，确保检索结果包含最新预警与处置信息；字段包含数值与单位，检索时需精准匹配单位与数值范围，防止因参数不匹配导致的调度类错误；党建学习问答场景下，需同时召回应急业务文档与党建相关的值守规范内容，满足双重检索需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配防汛数据的精准匹配需求，避免误召回无关的雨情水情信息 |
| `limit` | 前8条 | 覆盖多部门协同的应急文档，同时控制上下文长度 |
| `usingReRank` | 开启 | 针对多源异构的预警与处置文档，优化召回结果的相关性 |
| `datasetSearchUsingExtensionQuery` | 按实测标定 | 适配党建与应急业务的混合检索需求，平衡召回范围与精准度 |
| `collectionIds` | 对应应急值守党建知识库的专属ID | 限定检索范围，避免混入无关品类的文档 |

## 容易做错的三处
- 现象：通过API拉取文档库时返回空结果或权限报错。原因：未正确指定`collectionIds`为对应应急值守党建知识库的ID，导致检索范围超出预设边界。
- 现象：私有化部署升级FastGPT v4.17.0后，点击知识库文件详情显示“Invalid dataset file key”报错。原因：升级过程中未同步更新数据集关联的存储密钥，系统无法匹配原有文件的存储路径。
- 现象：使用段落分块并开启模型识别后，召回结果与党建学习问题的相关性不足。原因：`similarity`阈值设置过低，导致混入大量非相关的水文监测原始数据，或`datasetSearchUsingExtensionQuery`未适配党建语义优化，无法关联应急与党建内容。

## 怎么确认配好了
- 发起测试检索，输入党建相关的应急值守问题，核对召回结果是否覆盖应急文档与党建学习材料。
- 查看知识库同步日志，确认每日更新的预警、会商文档已成功同步至检索库。
- 调用API接口时，检查返回结果的`collectionIds`是否与预设的知识库ID一致。
- 调整`similarity`阈值并对比检索结果，确认召回结果的相关性符合业务需求。
