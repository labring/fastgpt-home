# 食品安全监督抽检的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
数据来源包括食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS、食品生产经营者台账。日常文档涵盖抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。数据更新频率为月度，核心字段包含抽样编号、检验项目、不合格判定、处置措施等，无自定义特殊单位，所有数据均围绕样品检验与不合格处置流程生成。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新节奏决定索引可采用批量全量更新模式，无需配置复杂的实时增量逻辑，降低日常运维成本。多类型文档结构差异明显，抽检计划为结构化表格、检验报告含多组检测数据项，若仅按纯文本固定长度分块，易丢失字段间的语义关联。多系统来源的数据需先完成格式对齐，否则向量嵌入会出现语义偏差，影响后续问答匹配精度。核心数据依赖实验室检测结果，对召回的精准匹配要求高于通用场景，需保留检测项目、不合格判定等关键字段的语义绑定。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 覆盖单份抽样单或检验报告的核心段落，避免跨文档分块丢失语义关联 |
| 重叠长度 | 100–150 字符 | 衔接相邻分块的上下文，保留检测项目的前后逻辑连贯性 |
| 相似度阈值 | 按实测标定 | 匹配不合格项目的语义相似度，避免误召回非对应抽检批次的数据 |
| 单次搜索上限 | 前 5 条 | 适配基层监管所的日常核查需求，控制返回结果的信息密度 |
| `defaultToken` | `2048` | 适配党建问答的上下文长度，同时容纳抽检数据的字段信息 |
| `maxToken` | `4096` | 支持完整的不合格食品核查处置流程问答，避免截断关键处置措施 |

## 容易做错的三处
- 本地部署后无法自动索引图片附件：上传检验报告的图片附件后，知识库索引状态显示成功但检索无结果，原因是未启用FastGPT内置的图文向量解析插件，仅配置了纯文本分块逻辑。
- Embedding模型无法连通OneAPI：界面提示模型连接失败，OneAPI返回调用超时错误，原因是未配置合理的超时参数，或网络策略限制了模型调用的端口范围。
- 开启重排模型后召回测试无生效：在线召回测试返回的结果未按重排模型重新排序，原因是未在知识库索引环节同步开启重排触发开关，或未配置重排模型的正确调用路径。

## 怎么确认配好了
- 上传单份完整的检验报告，触发索引后查看分块日志，确认核心字段如检验项目、不合格判定被完整纳入分块范围。
- 输入党建相关的抽检问题，如“不合格食品的核查处置流程”，查看召回结果的条数是否符合单次搜索上限的配置。
- 验证重排模型功能，上传多份同类型检验报告后，检索不合格项目相关问题，确认结果按相关性重新排序。
- 在FastGPT v4.17.0的模型管理页面，触发Embedding模型的测试调用，确认无超时或报错信息。
