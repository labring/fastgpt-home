# 食品安全监督抽检的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源为食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS系统及企业台账，更新频率为月度。日常文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告，字段涵盖抽样编号、检验项目、检测数值、不合格判定项、处置进度等，数据以实验室检测结果为核心依据。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据要求模型知识库需按月度周期同步更新，避免数据滞后影响问答准确性；多类型文档结构要求配置时需适配不同文档的字段提取逻辑，确保党建学习内容与食品安全抽检的专业数据准确关联；以实验室报告为核心证据的特性，要求模型调用时需严格限定引用来源，不可生成无依据的抽检结论；党建学习问答的场景要求模型需同时覆盖党建规范与抽检业务内容，需配置双源知识库的关联逻辑。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配月度更新的抽检文档与党建学习材料的总长度，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 满足抽检报告、核查处置报告的长文本问答输出需求 |
| `quoteMaxToken` | 1500 token | 限定引用抽检报告、抽样单等核心文档的长度，确保引用内容准确且不冗余 |
| `toolChoice` | auto | 允许模型自动选择是否调用检索工具获取最新抽检数据与党建学习内容 |
| `temperature` | 0.3–0.5 | 兼顾党建问答的规范性与抽检专业内容的准确性，避免生成虚构信息 |
| `AIPROXY_API_TOKEN` | 按当前授权渠道提供的令牌值填写 | 适配非SK/AK鉴权的授权方式，解决百度等渠道的授权变更问题 |

## 容易做错的三处
-  模型渠道配置后点击报错，调用日志显示获取数据异常。原因是使用了SK/AK鉴权方式，未正确填写`AIPROXY_API_TOKEN`参数，与当前授权渠道的鉴权要求不匹配。
-  调用仅支持stream模式的大模型时无法正常返回结果。原因是未适配流式返回逻辑，未在配置中开启对应的stream模式支持，导致接口调用失败。
-  本地前端切换模型渠道时接口返回304状态码。原因是本地缓存未更新，未重新拉取最新的渠道配置信息，导致请求携带的鉴权参数过期或错误。

## 怎么确认配好了
-  进入模型渠道配置页面，核对`AIPROXY_API_TOKEN`与对应接口地址是否与当前授权渠道的官方要求一致。
-  发起一次测试问答，输入抽检相关的党建学习问题，查看返回结果是否包含准确的抽检数据与党建指引内容。
-  开启流式调用测试，确认大模型返回结果为逐段输出的流式格式，无完整内容一次性返回的情况。
-  查看调用日志，确认无数据获取异常或error报错，接口请求状态码为200。
