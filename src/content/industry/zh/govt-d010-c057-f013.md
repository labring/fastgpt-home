# 食品安全监督抽检的党建学习问答：分享与嵌入

## 这个品类的数据长什么样
本品类数据来源包括食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS系统及食品生产经营者台账。日常文档涵盖抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。数据按月度更新，核心字段包含抽样编号、检验项目、不合格判定结果、核查处置进度等，所有内容均围绕样品检验与不合格处置流程生成。

## 这些特征在「分享与嵌入」这一环带来什么约束
月度更新的数据源要求嵌入后的问答系统需定期同步全量或增量数据，避免引用过期的抽检计划或处置结果。多类型文档混合的结构，要求分享嵌入时需配置针对性的文档分块规则，确保检验报告的专业字段与抽检计划的流程信息能被准确召回。核心字段的专业性，意味着嵌入后的问答界面需保留原始文档的引用链接，便于监管人员核对原始凭证，同时需限制单轮上下文长度，避免非相关的历史抽检数据干扰当前问答。数据关联的严谨性要求嵌入功能需支持按`shareId`绑定专属数据池，防止不同监管所的抽检数据混淆，保障业务数据的隔离性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 文档分块长度 | 800–1200 字符 | 适配检验报告、抽样单等专业文档的段落长度，避免拆分关键检测数据 |
| 上下文召回上限 | 前 6 条 | 匹配月度更新的数据量级，防止过多历史数据占用嵌入窗口的加载资源 |
| 引用链接显示 | 开启 | 便于监管人员核对原始抽检报告、处置通告等核心凭证，符合业务严谨性要求 |
| 专属数据池绑定 | 按`shareId`配置 | 区分不同监管所、检验机构的抽检数据，避免跨主体的数据混淆 |
| 加载超时阈值 | 300 秒 | 适配大型检验报告的加载与检索耗时，防止因网络延迟导致嵌入失败 |

## 容易做错的三处
- 现象：嵌入后点击AI回复内容无法触发本地系统跳转。原因：未配置嵌入窗口的回调事件绑定，仅实现了FastGPT内容展示，未对接本地应用的跳转接口。
- 现象：免登录分享链接中未携带专属标识，导致不同监管所的抽检数据无法隔离。原因：未在分享链接参数中添加自定义标识，未通过`shareId`关联对应的数据池配置。
- 现象：嵌入页面加载后未显示引用的原始检验报告或处置通告链接。原因：未开启引用链接渲染配置，或未将核心文档的元数据正确关联到问答结果中。

## 怎么确认配好了
- 复制生成的嵌入代码，部署到本地监管系统的测试页面，查看是否正常加载党建学习问答界面。
- 发起与抽检计划、不合格食品处置相关的问题，确认AI回复中附带了对应的原始文档引用链接。
- 使用不同`shareId`的嵌入链接发起问答，确认仅能访问对应监管所或检验机构的专属抽检数据。
- 等待月度数据更新后，重新加载嵌入页面，确认最新的抽检报告、处置通告已同步到问答库中。
