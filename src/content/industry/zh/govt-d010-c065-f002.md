# 勘察设计的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
勘察设计单位的党建学习问答数据，主要来源于内部党建管理平台、项目临时支部的学习台账、上级国资部门下发的党建政策文件。日常随支部活动每周新增学习简报，季度更新上级最新政策文件，年度归档党员学习档案。单篇文档包含标题、发布主体、正文内容、关联项目编号、发布日期等字段，文件格式以PDF、DOCX为主，单篇长度跨度较大，从数百字符的学习提示到数万字符的政策解读。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于单篇文档长度跨度较大，长文档的分块策略需要适配不同内容密度，避免因分块过长导致语义割裂或过短丢失上下文关联。文档携带的关联项目编号字段，要求索引过程中保留该元数据，用于后续定向关联项目党建场景的问答。多频次的更新节奏，需要配置增量索引规则，区分全量同步与增量同步的触发时机，减少不必要的计算资源消耗。分散的数据源来源，要求统一的元数据校验规则，确保项目编号、发布日期等字段格式一致，避免检索时出现匹配偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配勘察设计党建文档的长度跨度，兼顾语义完整性与分块粒度 |
| 重叠长度 | 100–150 字符 | 避免分块后上下文断裂，确保相邻分块的语义关联 |
| `maxToken` | 8192 token | 适配FastGPT v4.17.0版本下主流嵌入模型的输入上限，匹配文档分块后的字符转token比例 |
| `defaultToken` | 按实测标定 | 适配未明确token上限的自定义嵌入模型，避免截断关键语义 |
| 相似度阈值 | 0.72–0.80 | 过滤低匹配度的党建问答结果，确保检索内容贴合用户提问 |
| 单次召回条数 | 前 8 条 | 覆盖党建问答的常见相关内容，避免遗漏关联项目的党建信息 |

## 容易做错的三处
- 现象：界面显示索引任务一直处于「进行中」状态，无进度更新。原因：未配置增量索引规则，全量索引扫描了大量历史文档，或分块长度设置过大导致单块处理耗时过长。
- 现象：调用嵌入模型时返回503状态码，或日志中出现分组default下的text-embedding模型调用失败。原因：未正确配置嵌入模型的API超时参数，或网络策略限制了FastGPT容器访问外部嵌入模型服务。
- 现象：检索结果中出现大量与项目党建无关的通用党建内容。原因：未在索引时保留关联项目编号元数据，或相似度阈值设置过低，导致低匹配度内容被召回。

## 怎么确认配好了
- 查看索引任务的日志，确认分块后的文档数量与数据源的文档数量匹配，无异常截断提示。
- 手动提交一条党建相关提问，检查检索结果中是否包含关联项目编号的元数据，且匹配度符合预期。
- 测试嵌入模型调用，确认返回的向量数据不为空，且无超时或报错信息。
- 触发一次增量索引，确认仅新增的文档被纳入索引，无全量重复同步的日志。
