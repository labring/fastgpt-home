# 勘察设计的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据主要来自勘察设计单位内部党建管理系统、上级党组织下发的学习文件、项目临时党建学习记录。更新节奏为每月更新上级政策文件，每季度更新支部学习台账与考核记录。文档多为带层级的结构化文本，包含文件标题、发布主体、发布日期、正文内容、适用项目类型字段，单位涉及学习时长（小时）、考核得分（分）等，部分文档附带项目关联的党建活动附件。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
结构化文档绑定项目与支部字段，要求多轮对话通过`chatId`绑定对应项目与支部的上下文，避免跨项目的党建问答混淆。更新频率较高的特性，要求提示词中明确优先使用最新发布的文件内容，规避引用过时政策。文档附带项目类型字段，提示词需适配市政、建筑等不同勘察设计场景的党建要求，不能使用通用化表述。部分文档篇幅较长，多轮对话的上下文窗口需限制合理长度，防止内容溢出导致回答偏差。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按项目+支部组合生成唯一标识 | 绑定对应项目与支部的上下文，避免跨场景问答混淆 |
| `messages` | 保留最近20轮对话内容 | 适配勘察设计党建文档的篇幅，防止上下文溢出 |
| `variables` | 传入项目类型、支部名称2个变量 | 适配不同勘察设计场景的党建问答需求 |
| 用户密钥绑定 | 按用户ID生成专属密钥 | 避免不同用户的对话记录与密钥共享 |
| 最大上下文 | 8000–12000 token | 容纳中长篇党建文档与多轮对话内容 |
| 问题优化 | 开启 | 修正多轮对话中模糊的党建问题，提升回答精度 |
| 单次搜索上限 | 前3条匹配文档 | 匹配勘察设计党建数据量适中的特性，避免冗余内容干扰 |

## 容易做错的三处
- 调用OpenAPI发起对话返回422错误。原因：未正确传入`chatId`或`messages`参数，或参数格式不符合规范。
- 多轮对话上下文出现跨项目的党建内容。原因：未为每个项目与支部组合生成唯一标识，导致不同场景的上下文被共享。
- 对话结果中引用了过时的党建政策文件。原因：提示词未明确优先使用最新发布的内容，或知识库未同步更新最新的党建文件。

## 怎么确认配好了
- 发起单轮测试对话，输入绑定特定项目与支部的党建问题，检查返回结果是否匹配对应内容，确认`variables`与`chatId`配置生效。
- 发起连续多轮对话，依次提问相关联的党建问题，检查回答是否参考了前一轮的上下文，确认`messages`配置生效。
- 触发知识库更新操作后发起对话，检查结果是否包含最新发布的党建文件内容，确认数据更新机制生效。
- 调用OpenAPI接口测试对话，检查返回状态码是否为200，确认参数配置符合规范。
