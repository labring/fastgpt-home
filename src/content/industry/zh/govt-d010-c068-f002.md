# 医药流通的党建学习问答：向量模型与索引

本页面适配 FastGPT v4.17.0 版本。

## 这个品类的数据长什么样
医药流通领域的党建学习数据主要来源于企业内部党建平台的活动纪要、上级党委下发的政策文件、线下主题党日的学习材料，以及内部考核用的题库文档。数据更新节奏为月度新增活动类材料，季度更新行业相关党务政策文件，年度更新标准化学习课件。单条数据包含标题、正文内容、发布部门、发布日期四个固定字段，正文以连续段落形式存储，无预设分段。

## 这些特征在「向量模型与索引」这一环带来什么约束
混合的党务通用文本与医药流通专业政策文本，要求向量模型需同时适配两类语义场景，避免出现专业术语的向量偏移。月度增量更新的节奏，要求索引系统支持周期性增量构建，降低全量重建的资源消耗。无固定分段的正文结构，要求自动分块规则需适配不同长度的文本，避免截断关键信息。发布部门与日期字段可作为元数据过滤条件，要求索引支持按元数据进行精准召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配混合党务与医药政策文本的平均长度，避免截断关键专业术语 |
| 重叠长度 | 100–150 字符 | 弥补分块截断导致的上下文断裂，保障长政策文件的语义连贯性 |
| 单次搜索上限 | 前 8 条 | 匹配党建问答的精准召回需求，避免冗余结果干扰答案生成 |
| `defaultToken` | 4096 | 适配多数党建问答的上下文长度需求，保障政策原文与问答内容的完整加载 |
| `maxToken` | 8192 | 处理包含长段政策文件的复杂问答场景，满足大模型输入的长度要求 |
| 索引更新频率 | 每日增量更新 | 匹配月度新增数据的节奏，平衡索引新鲜度与构建成本 |

## 容易做错的三处
- 现象：后台数据集索引条目数随时间自动新增多组重复条目。原因：未开启增量索引的去重校验，每次更新任务重复导入已有数据并生成新索引。
- 现象：调用text-embedding-3-large时进程长时间无进度更新，注释模型配置后重启服务仍未恢复。原因：向量模型的API请求未设置合理超时限制，且未清理残留的阻塞进程，导致任务卡住。
- 现象：配置索引模型后，预设的语言模型无法正常调用。原因：未正确配置索引与语言模型的关联关系，导致系统加载索引模型时覆盖了语言模型的调用参数。

## 怎么确认配好了
- 上传单篇包含医药流通政策与党务内容的测试文档，查看分块结果是否符合预设的长度区间，无明显截断。
- 发起一条包含专业术语的党建问答，核对召回结果的条目数是否符合单次搜索上限的配置。
- 触发一次增量索引更新任务，查看后台日志中是否有重复数据的去重提示，无异常报错。
- 调用索引模型生成向量后，检查向量存储的元数据是否包含发布部门、发布日期等字段，可正常用于过滤。
