# 医药流通的党建学习问答：多轮对话与提示词
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
医药流通领域的党建学习问答数据，主要来源于企业内部党委的学习台账、上级国资部门下发的政策文件与行业党建指引，更新节奏随上级党建部署与内部学习计划调整。文档包含两种形式：一是完整的政策文本类文件，二是标准化的问答条目库，字段覆盖文件编号、发布单位、发布日期、问答主题、标准答案，数据格式多为结构化的文本文件。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
医药流通党建学习问答的两类数据形式、结构化字段与动态更新特征，对多轮对话与提示词配置带来三点约束。其一，政策文本与问答条目需在提示词中明确分类调用规则，结合文件编号、发布日期等字段，区分通用党建内容与医药流通专属党建要求；其二，动态更新的数据要求提示词预留参数入口，支持随时同步最新政策文件与问答条目；其三，多轮对话需保留上下文的主题关联性，针对用户连续提问需关联之前提及的党建主题与医药流通业务场景，防止出现跨场景的错误匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定企业内部党建账号的唯一标识 | 确保同一医药流通企业的用户多轮对话上下文隔离，避免跨租户数据混淆 |
| `messages` | 保留前5轮对话内容 | 平衡上下文完整性与模型token消耗，适配党建问答的短轮次交互场景 |
| `variables` | 注入医药流通党建专属关键词与最新政策标识 | 让模型自动关联行业党建内容，避免通用党建问答与医药流通场景脱节 |
| 对话历史保留时长 | 30天 | 符合医药流通企业党建学习的月度复盘需求，方便用户回溯历史学习对话 |
| 提示词更新频率 | 每月1次 | 匹配上级党建部署的更新节奏，确保问答内容始终同步最新政策要求 |

## 容易做错的三处
- 调用模型时日志显示令牌字段为“fastgpt”，界面返回调用失败。原因：未正确绑定`variables`中的模型调用密钥参数，导致系统自动填充了默认占位符。
- 多轮对话中连续提问的上下文未被正确关联，出现问答内容脱节的情况。原因：未统一配置`chatId`与`messages`的保留规则，导致不同交互节点的上下文隔离失效。
- 导出的对话历史缺失部分历史问答条目。原因：未开启对话历史的全量存储开关，仅保留了配置的有限轮次内容。

## 怎么确认配好了
- 发起包含2-3轮的党建相关提问，核对对话上下文是否关联之前的提问内容，调整`messages`的保留轮次后验证关联逻辑是否变化。
- 查看模型调用日志，确认`chatId`、`messages`与`variables`参数已正确传入，无异常占位符。
- 导出对话历史，核对导出内容是否覆盖所有交互轮次，与实际对话内容匹配。
- 发起一次涉及时效性的党建提问，核对模型是否关联了正确的发布日期字段内容。
