# 发电集团的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
内部党建资料来源包含上级党委下发的正式文件、各基层支部上报的学习活动记录、集团内部党建手册等。更新节奏为上级政策文件随发布即时更新，内部日常学习资料按季度更新。文档结构多包含标题、正文、发布主体、发布日期，字段包含分类标签、文档归属单位、创建时间，格式以PDF、Word为主。

## 这些特征在「向量模型与索引」这一环带来什么约束
内部党建资料来源分散，包含上级正式文件、基层活动记录等多类数据源，要求索引支持多源数据的统一接入与增量更新。不同来源的文档结构存在差异，部分文件仅含纯文本正文，部分附带格式排版，需确保向量模型可准确提取核心语义内容。分类标签、归属单位等字段的存在，可为索引提供前置过滤维度，缩小检索范围。不同更新节奏的资料，需适配分批次增量索引的逻辑，避免全量重建带来的资源消耗。同时，PDF、Word格式的文档占比高，需确保文本提取环节可完整保留核心内容，无关键信息丢失。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配党建文档的正文长度，避免单块内容过于分散或冗余 |
| 重叠长度 | 100–200 字符 | 确保相邻分块的语义衔接，避免关键信息被截断在块边界 |
| `defaultToken` | 1024 | 匹配多数通用党建文本的语义提取需求，按实测标定后可调整 |
| `maxToken` | 4096 | 适配长文档的向量生成上限，避免超出模型支持范围 |
| 重排 | 开启，取前3条结果 | 过滤初步召回的冗余内容，提升党建问答的精准度 |
| 单次搜索上限 | 前20条 | 平衡检索效率与召回覆盖率，符合内部资料的规模特征 |

## 容易做错的三处
- 现象：调用私有化重排模型时返回500状态码，或结果无排序变化。原因：未在FastGPT配置中正确指定私有化重排模型的部署地址与鉴权参数，导致模型调用失败。
- 现象：检索结果仅返回少量条目，无法覆盖全部相关党建文档。原因：未设置合理的单次搜索上限与相似度阈值，或未开启增量索引导致旧数据未被纳入检索范围。
- 现象：生成的回答偏离党建主题，混入无关内容。原因：未利用分类标签字段做前置过滤，或向量模型未适配党建领域的语义特征，导致召回内容偏差。

## 怎么确认配好了
- 进入FastGPT的知识库管理页面，查看分块后的文档预览，确认分块长度与重叠长度符合预设配置，无明显语义截断。
- 发起党建相关的测试提问，查看检索结果的条数与排序，确认重排功能已生效，结果与提问的相关性符合预期。
- 上传一份新的党建文档，查看索引任务的状态日志，确认增量索引已正常执行，新文档可被正常检索到。
- 检查向量模型的调用日志，确认`defaultToken`与`maxToken`的取值未超出模型支持范围，无调用报错。
