# 国有资本投资公司的党建学习问答：对话日志与审计

## 这个品类的数据长什么样
本页面适配 FastGPT v4.17.0 版本。该品类的数据来源于国有资本投资公司内部党建学习资源库与党务交互系统，包含党委下发的学习文件、支部会议纪要、党员日常问答交互记录。数据更新节奏为每日同步新发布的党建学习资料，每自然周更新全量的问答交互日志。单条数据文档为结构化格式，包含`chatId`、会话创建时间、用户角色、提问内容、AI回复内容、审计标记、所属支部ID、学习主题标签等字段，单位以字符、条、日期时间戳为标准。

## 这些特征在「对话日志与审计」这一环带来什么约束
党建学习内容需符合国资监管的合规要求，因此对话日志必须留存全量交互细节，不能截断或省略关键内容。按支部管理党建工作的模式，要求日志需按`chatId`关联的会话组进行分类存储，便于按部门或支部开展审计。数据同步周期与内部系统的更新节奏绑定，审计时需确保日志的时效性，避免出现数据滞后的情况。同时，字段中的审计标记与支部ID为强制必填项，用于后续的合规溯源与权限管控，缺失任一字段都会导致审计流程无法完成。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 会话日志存储粒度 | 按`chatId`分组存储 | 匹配国有资本投资公司按支部管理党建工作的审计需求，便于按部门快速筛选目标日志 |
| 单会话日志导出项 | 包含`responseChatItemId`关联的所有回复内容 | 确保每条AI回复可独立溯源，符合党建内容的合规审计要求 |
| 上下文存储字段 | 启用`detail`字段存储全量交互 | 避免截断对话内容，满足审计时还原完整学习问答过程的要求 |
| 日志同步周期 | 每 8 小时同步一次内部交互数据 | 平衡审计时效性与内部系统的负载压力 |
| 导出文件大小限制 | 不超过 1000 MB | 适配国资系统内部文件传输的常规限制 |
| 历史记录更新开关 | 开启全局历史记录同步 | 确保修改后的会话内容被纳入审计范围，覆盖用户对历史记录的调整需求 |

## 容易做错的三处
- 修改全局变量中的历史记录后，审计日志中未同步更新。未启用`detail`字段同步修改后的会话内容，导致历史记录变更未被纳入审计范围。
- 导出的对话记录中缺少`responseChatItemId`关联的回复内容。导出配置未勾选关联回复项，导致审计所需的单条回复溯源信息缺失。
- 携带历史记录进行党建问答时，AI未调用历史上下文。未按`chatId`绑定会话历史，导致系统无法识别当前会话的上下文关联。

## 怎么确认配好了
- 发起一条党建学习问答，查看会话生成的`chatId`是否与预设的支部ID关联，确认分组存储配置生效。
- 导出单会话的日志文件，检查是否包含完整的`detail`字段内容，确认全量交互被正常存储。
- 修改会话的历史记录，等待 8 小时同步周期结束后，查看审计日志中是否同步了修改后的内容，确认更新配置生效。
- 发起携带历史记录的问答，确认AI回复中引用了历史对话内容，确认上下文绑定配置生效。
