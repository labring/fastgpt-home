# 城市公交的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
数据来源为公交运营主体的党建工作台账、上级党组织下发的学习文件、内部月度学习简报。更新节奏为每周补充时政类学习内容，每月更新固定主题的党建学习材料。文档结构以结构化文本为主，单篇包含标题、发布主体、发布日期、学习要点四个固定字段，正文内容多为段落式说明，单篇字符数区间稳定，无超大篇幅的碎片化内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
党建数据的固定字段结构要求模型接入时需保留字段映射规则，避免解析时丢失发布主体、发布日期等关键信息。每周补充、每月更新的节奏要求配置的数据源同步周期与更新节奏对齐，避免出现内容滞后或重复同步的问题。党建内容的行业专属术语较多，要求模型配置需适配专业语境的语义识别，同时固定的单篇字符区间需匹配上下文窗口的预设范围，避免截断关键学习要点。此外，党建内容的严谨性要求较高，需限制模型输出的随机性，确保回答符合官方表述规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配公交党建文档的单篇字符长度，避免截断核心学习要点与固定字段 |
| `maxTokens` | 2000 token | 控制单轮回答的输出长度，确保党建问答的回复简洁且覆盖核心内容 |
| `quoteMaxToken` | 1500 token | 匹配公交党建文档的单段引用长度，保留完整的学习段落与上下文 |
| `temperature` | 0.3–0.5 | 降低模型输出的随机性，确保党建问答的内容符合官方表述的严谨性 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的专属地址填写 | 确保模型调用的网络通路正常，避免出现连接失败问题 |
| `AIPROXY_API_TOKEN` | 按生成的专属密钥填写 | 完成模型接入的身份验证，确保调用权限合法有效 |

## 容易做错的三处
- 现象：调用模型时提示「找不到渠道」，模型管理页面的可选列表无对应模型。原因：未正确填写`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或密钥的调用权限未完成配置。
- 现象：问答结果中丢失发布日期、发布主体等预设字段信息。原因：未配置字段映射规则，或`maxContext`取值过小导致字段信息被截断。
- 现象：单轮回答内容过长超出预期，出现冗余表述或偏离主题的内容。原因：`maxTokens`取值过大，未限制模型的输出长度。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型管理页面，查看已接入的模型列表，确认目标模型已显示在可选范围内。
- 上传一篇公交党建的标准文档，触发模型调用，检查返回结果中是否包含文档的发布主体、发布日期等预设字段。
- 输入党建相关的测试问题，观察回答的输出长度是否符合`maxTokens`的预设范围，内容是否符合严谨性要求。
- 手动触发数据源同步，等待同步完成后查看知识库更新日志，确认同步周期与数据更新节奏匹配。
