# 城市水务的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
城市水务的党建学习问答数据主要来自城市水务系统党委发布的内部党建文档，包括三会一课记录、主题党日材料、上级党建指导文件及行业党建实践案例。数据更新节奏随内部党建活动推进，上级文件按季度更新，内部活动记录按月度更新。文档多为结构化格式，包含标题、正文、发布单位、发布日期字段，部分关联供水、排水等水务业务板块，单位以“篇”为统计单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且更新节奏不均，要求向量索引支持增量同步与增量重建，避免全量索引更新占用过多资源。文档关联供水、排水等水务业务板块，分块时需保留业务关联字段，确保向量检索时可关联对应水务党建场景。结构化文档格式要求分块以段落为最小单元，避免跨段落混合内容导致向量语义偏差。长正文文档需限制单块长度，防止单个向量承载过多无关信息，降低检索精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配城市水务党建文档的段落平均长度，避免单块内容过载 |
| 重叠长度 | 100–150 字符 | 保留分块间的语义衔接，防止跨块内容断裂 |
| `defaultToken` | 8192 | 适配主流多模态向量模型的输入上限，兼容党建文档的长文本块 |
| 相似度阈值 | 0.72–0.80 区间 | 过滤低相关检索结果，贴合党建问答的严谨性要求 |
| 单次搜索上限 | 前 8 条 | 控制返回结果数量，平衡检索效率与覆盖范围 |
| `maxToken` | 4096 | 限制单轮问答的上下文长度，避免模型输入溢出 |

## 容易做错的三处
- 现象：向量化请求仅携带单段文本切片，未使用批处理模式。原因：未正确配置FastGPT的分块批量上传参数，导致单条请求仅处理一个分块，浪费向量化服务的批处理能力。
- 现象：检索结果出现空的分块元数字段，无法关联原始文档信息。原因：未开启FastGPT的分块元数据存储开关，导致索引未保留分块的原始位置与关联信息。
- 现象：配置阿里multimodal-embedding-v1模型后，向量生成失败。原因：未将模型的输入格式调整为支持多模态的文本输入模式，或未正确填写模型的API密钥与端点地址。

## 怎么确认配好了
- 查看FastGPT v4.17.0的向量化服务日志，确认`defaultToken`配置是否正确，验证分块批处理配置生效。
- 随机抽取一篇水务党建文档，检索相关关键词，核对返回结果的分块内容与原始文档的语义匹配度。
- 检查模型配置页面，确认已正确填写目标向量模型的相关参数，无报错提示。
- 查看索引管理页面，确认分块元数据已正常存储，可通过检索结果查看关联的文档字段。
