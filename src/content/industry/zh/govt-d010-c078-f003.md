# 城市水务的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
城市水务党建学习问答的数据主要来源于城投水务系统内部的党建台账、上级党委下发的月度/季度学习文件、内部党课课件及党员学习记录。数据更新节奏为：上级文件随政策调整按需同步，内部党课课件按季度更新，党员学习记录实时归档。文档结构多为标准政务文体，包含文件标题、正文、发布单位、发布日期、学时要求等字段，单位涉及小时、份、期等，单份文档长度从数百字符到数千字符不等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据源分散为政策文件、学习课件、台账记录三类，多轮对话需同时关联不同类别的知识库，避免单一数据源的信息局限。文档中包含学时、发布日期等结构化字段，提示词需精准提取这些字段用于回答，否则会出现与水务党建实际要求不符的内容。高频更新的数据源要求对话系统支持实时同步知识库，避免出现过时的学习内容。长文档的存在要求多轮对话需通过`messages`参数保留用户的历史提问与系统回复，上下文窗口需保留足够的语义关联，防止跨轮提问时丢失关键党建主题信息。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 水务党建文档多为连贯的政策解读与学习要求，分块长度适配单份学习材料的段落长度，避免破坏语义完整性 |
| 重叠长度 | 100–150 字符 | 党建文档存在跨段落的学习主题关联，重叠设置可保留跨块的上下文信息，确保召回内容连贯 |
| 单次召回上限 | 前 6 条 | 水务党建问答需覆盖政策、案例、台账三类内容，过多召回会超出上下文窗口，影响回答准确性 |
| 最大上下文长度 | 4000–5000 token | 多轮对话需保留用户提问历史与召回的多份文档内容，该长度可覆盖常规多轮交互的信息需求 |
| `chatId` 配置 | 绑定党员账号唯一标识 | 区分不同用户的对话上下文，避免跨用户的信息干扰，确保党建学习问答的私密性与准确性 |
| `variables` 配置 | 传递知识库类别标识 | 支持在多轮对话中切换不同类别的水务党建知识库，满足定向查询需求 |

## 容易做错的三处
- 现象：对话界面弹出“未上传文件”提示，但已上传水务党建相关知识库文档。原因：系统提示词未正确绑定预设的党建知识库标识，导致召回逻辑无法匹配已上传的文件资源。
- 现象：多轮对话过程中无法切换不同类别的水务党建知识库。原因：未通过`variables`参数传递当前选中的知识库标识，无法定向召回对应数据源。
- 现象：新对话初始化弹窗持续显示，无法通过配置隐藏。原因：错误修改了非对话初始化环节的前端代码，未定位到控制弹窗显示的核心逻辑文件。

## 怎么确认配好了
- 发起包含水务党建主题的单轮提问，核对返回内容是否准确引用知识库中的官方文件原文。
- 发起连续多轮提问，核对`chatId`绑定后，上下文历史会被正确保留，不会出现跨用户的信息混淆。
- 调整分块长度参数后，上传一份长文档的党建课件，核对召回的文档片段是否连贯完整。
- 测试通过`variables`参数切换知识库类别，核对可定向召回对应类别的水务党建知识库内容。
