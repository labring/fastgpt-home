# 城投平台的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
城投平台党建学习问答的数据源来自内部党建管理系统导出的学习资料、三会一课纪要、主题教育活动记录，以及上级党委下发的政策文件。数据更新节奏混合日常与定期：日常随新学习任务发布更新学习材料，每季度同步更新活动台账与历史记录。文档多为带标题、正文、发布主体的结构化文本，部分包含扫描件转写的纯文本，字段包含文档分类标签、发布时间、正文内容，无统一固定的单文档长度范围。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据源的多样性导致文本格式存在差异，需前置完成格式清洗与标准化处理。混合更新节奏要求同时支持增量索引与全量索引两种模式，适配日常新增与定期批量更新的需求。文档自带的分类标签字段可用于索引时的精准过滤，缩小检索范围。部分文档篇幅较长，需适配合理的分块策略避免语义断裂。党建内容包含大量专有名词，需选择适配专业术语的向量模型，同时通过`defaultToken`配置调整单段文本的输入长度，适配模型的处理上限。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配城投党建文档多数单段正文长度，避免语义割裂 |
| 重叠长度 | 50–100 字符 | 保留分块间的上下文关联，防止党建专有名词被截断 |
| `maxToken` | 8192 token | 匹配主流党建类向量模型的输入上限，避免内容截断 |
| 相似度阈值 | 0.72–0.80 按实测标定 | 过滤低匹配度结果，适配党建内容的精准检索需求 |
| 单次搜索上限 | 前 10 条 | 控制检索返回量，平衡检索速度与结果覆盖度 |
| 最大上下文 | 6000 字符 | 限制传入大模型的上下文长度，避免超出模型处理上限 |

## 容易做错的三处
- 现象：向量化任务执行报错，日志包含速率超限相关提示。原因：未限制向量化处理的并发线程数，同时发起的任务数量超出平台接口调用配额。
- 现象：问答对提取任务长期处于索引中状态，无法进入就绪环节。原因：分块长度设置超出对应向量模型的输入上限，任务反复重试无法完成分块处理。
- 现象：指定数据集的索引条目数量在无手动操作的情况下自动增长。原因：未关闭自动增量索引开关，平台定期同步内部党建系统的新增数据，导致重复生成索引条目。

## 怎么确认配好了
- 提交10份典型党建文档进行向量化测试，查看任务日志无速率超限报错，确认线程数配置生效。
- 发起检索测试，输入党建相关问题，核对返回结果的数量与单次搜索上限的配置一致。
- 查看索引库的条目更新记录，确认仅在手动触发或配置的自动同步周期内新增索引，无异常增长。
- 调整分块长度后，重新提交长文档测试，确认分块后的文本未出现党建专有名词截断情况。
