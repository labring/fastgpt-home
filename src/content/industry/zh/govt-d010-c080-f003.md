# 城投平台的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
城投平台的党建学习数据主要来自内部党建档案库、上级党委下发的年度学习指引、三会一课会议记录、主题党日活动资料。数据更新节奏为上级下发材料按季度同步，内部活动记录按月归档。单篇文档结构包含标题、发布单位、发布时间、正文内容、适用党员群体字段，单篇字数跨度较大，字段均为结构化与非混合形式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
城投党建数据的结构化字段与非结构化正文混合的结构，要求多轮对话的提示词需明确区分字段调用与正文检索的逻辑，避免混淆适用群体与学习内容。按月更新的内部活动记录，要求对话上下文窗口不宜超过30天，否则可能调用过时的活动数据。单篇文档字数跨度大的特征，要求提示词需限定每次召回的上下文总长度，防止超出模型token上限导致对话中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `messages` | 保留最近10轮对话内容 | 适配城投党建数据的月度更新节奏，避免过时内容干扰当前问答 |
| 最大上下文token数 | 8000–12000 token | 匹配单篇党建文档的字数跨度，防止召回内容超出模型处理上限 |
| 问题优化开关 | 开启 | 针对结构化字段较多的党建数据，优化用户问题的检索匹配精度 |
| `chatId` | 绑定当前会话的唯一标识 | 确保多轮对话的上下文仅在同一会话内传递，避免跨会话数据混淆 |
| 单次召回条数 | 前3条 | 适配城投党建文档的分类结构，避免过多无关内容占用上下文空间 |
| `variables` | 注入当前党组织所属区域字段 | 结合城投平台的属地属性，让回答匹配本地党建工作要求 |

## 容易做错的三处
- 对话请求直接调用大模型，未触发联网搜索：现象为发起对话后未返回联网获取的党建最新资料，日志中无http请求调用记录。原因是工作流中未将`messages`参数绑定到http请求节点，导致流程直接跳过检索环节。
- 前端请求接口报CORS错误：现象为浏览器控制台返回跨域请求被拦截的报错信息，状态码为403或0。原因是私有化部署的FastGPT服务未配置允许前端域名的跨域规则。
- 上下文超出token上限导致对话中断：现象为多轮对话后返回内容为空或提示上下文过长。原因是未限制`messages`参数的保留轮次，导致旧的党建学习记录占用过多token空间。

## 怎么确认配好了
- 查看FastGPT v4.17.0版本的工作流节点日志，确认http请求节点在对话触发时正常执行，返回的党建数据与当前会话相关。
- 检查会话的`chatId`参数是否唯一，确保不同会话的上下文不会互相干扰。
- 测试多轮对话后，查看上下文总长度是否符合预设范围，未出现token超限提示。
- 验证`variables`参数是否正确注入了属地等结构化字段，回答中匹配本地党建工作要求。
