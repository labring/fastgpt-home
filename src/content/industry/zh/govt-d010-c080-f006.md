# 城投平台的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
城投平台的党建学习问答数据主要来源于内部党建档案系统、上级党委下发的正式文件、支部三会一课记录与内部学习资料。文档按党建主题分类，结构包含标题、正文、发布单位、发布日期等字段，单篇文档字符量跨度较大。数据更新随每月党建工作进度同步完成，无固定批量更新周期，仅在新增党建文件或更新学习资料时触发。

## 这些特征在「引用来源与溯源」这一环带来什么约束
城投平台党建数据的多来源属性，要求引用溯源环节需精准关联文件所属的发布主体，避免混淆不同层级党委下发的同名文件。非固定更新节奏，导致溯源需支持实时匹配最新版本的党建资料，无法依赖固定的缓存时效。文档字段包含发布日期与单位，要求引用内容需同步展示这些元数据，确保溯源信息完整。单篇文档字符跨度大，会影响引用片段的截取长度，需根据内容重要性调整溯源片段的匹配范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 引用最大token数 | 800–1200 字符 | 匹配城投党建文档单段核心内容的长度，避免引用片段过长超出上下文限制 |
| `quoteMaxToken` | 600 token | 控制单条引用的token总量，适配党建文档的内容密度 |
| 返回数据格式 | 包含元数据字段 | 需包含发布单位、发布日期等信息，满足溯源的完整展示要求 |
| `responseData` | 包含source字段 | 确保返回的引用数据包含文档元信息，便于后续溯源展示 |
| 详情开关 | 开启 | 用于返回详细的引用来源路径，匹配党建数据的多来源溯源需求 |
| `detail` | true | 启用详细的引用溯源信息，适配复杂的党建文档溯源场景 |

## 容易做错的三处
- 现象为返回的引用文件与实际检索到的党建文档不匹配，原因是未正确关联文档的发布单位与发布日期字段，导致同名文件混淆。
- 现象为未开启引用开关却返回了引用内容，原因是版本配置中默认启用了`detail`参数的默认值，未手动调整非必要的溯源输出开关。
- 现象为流式返回的引用信息与问答解析结果不同步，原因是未将溯源信息的解析逻辑与流式输出的token流绑定，导致溯源信息延迟或错位。

## 怎么确认配好了
- 发起党建相关的测试提问，核对返回结果中是否附带文档的元数据信息。
- 查看API返回的`responseData`字段，确认是否包含所需的溯源相关内容。
- 手动关闭引用溯源配置，验证返回结果中无额外的引用片段。
- 确认当前使用的FastGPT版本为v4.17.0，确保参数配置的兼容性。
