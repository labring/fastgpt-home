# 城投平台的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
城投平台的党建学习问答数据主要来自内部党建档案库、上级党委下发的学习指引、月度党建活动台账。数据更新节奏为每周同步最新学习材料，每月更新活动参与记录与考核档案。文档多为结构化的文本格式，包含标题、正文内容、发布单位、发布日期、活动主题等字段，部分文档附带参会人员名单、时长等附属信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
城投党建数据包含多段正式书面内容与附属字段，模型接入时需适配长文本处理的上下文限制。定期更新的学习材料要求配置支持定时数据源同步，避免调用过期内容。结构化的文档字段需模型准确匹配主题，因此需明确上下文召回的匹配规则。同时正式文档的严谨性要求模型输出需贴合官方表述，需调整相关参数控制回答的灵活性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配城投党建文档的长文本分段与多字段关联内容，避免截断关键信息 |
| `maxTokens` | 2000–3000 token | 控制单轮回答的输出长度，匹配党建问答的严谨性要求，避免冗余内容 |
| `quoteMaxToken` | 1500 token | 限制单条引用文档的token数量，确保上下文窗口可容纳多条党建学习材料的关联内容 |
| `temperature` | 0.1–0.3 | 降低回答的随机性，保证党建问答的表述符合官方正式风格 |
| `AIPROXY_API_TOKEN` | 填入申请的大模型API密钥 | 完成大模型的身份验证，确保调用权限正常 |
| `AIPROXY_API_ENDPOINT` | 填入官方指定的API接口地址 | 指向正确的模型调用路径，保证请求能正常送达 |

## 容易做错的三处
- 测试时出现`[] is too short - 'messages'`报错，原因是未正确配置对话上下文的初始消息结构，导致传入模型的消息数组为空或长度不足。
- 发起对话时返回422状态码，原因是模型接入的API参数格式错误，或上下文窗口配置超出模型支持的上限。
- 配置API密钥后模型无法正常调用，原因是未正确填写`AIPROXY_API_ENDPOINT`地址，或密钥未开通对应模型的访问权限。

## 怎么确认配好了
- 进入模型接入配置页面，核对`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的填写内容与申请的密钥、接口地址一致。
- 上传一段城投党建的示例文档，测试模型的上下文召回功能，确认能正确提取文档中的主题与关键信息。
- 发起一轮党建相关的测试提问，检查返回结果的表述是否符合正式书面风格，且未出现超出预期的发散内容。
- 手动触发一次数据源同步，确认配置的更新规则能正常拉取最新的党建学习材料。
