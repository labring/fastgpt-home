# 基础电信运营的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
基础电信运营的党建学习数据主要来源于内部党建管理平台的正式文件、支部月度学习纪要、中心组研讨记录，以及上级国资部门下发的党建通知与指导材料。数据更新节奏不固定，常规学习资料按周更新，突发政策通知随下发即时同步。文档多为结构化格式，包含标题、正文、发布单位、发布日期、分类标签等字段，部分材料附带PDF格式的会议实录附件。

## 这些特征在「向量模型与索引」这一环带来什么约束
基础电信运营的党建数据特征对向量模型与索引环节带来多重约束：首先，数据来源分散且格式混合，既有结构化的表格文档，也有非结构化的纯文本纪要，需要适配多格式的分块与编码逻辑；其次，更新节奏不固定且存在突发同步需求，要求索引支持增量更新与断点续传，避免全量重索引带来的资源消耗；第三，文档包含多个字段，需明确区分内容字段与元数据字段，防止无关元数据被纳入向量编码，影响问答匹配精度；最后，部分党建材料存在较长的段落结构，需合理控制分块粒度，避免破坏上下文逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 基础电信党建文档多为千字左右的会议纪要与通知，匹配内容密度与向量编码精度 |
| 重叠长度 | 100–200 字符 | 避免分块切断党建文档的段落逻辑关联，保障上下文连贯性 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配结果，适配党建问答的严谨性要求 |
| 单次搜索上限 | 前 8 条 | 平衡召回覆盖范围与FastGPT v4.17.0的上下文长度限制 |
| 最大上下文 | 6000 字符 | 适配平台默认编码上限，避免超出模型处理能力 |
| `defaultToken` | 512 | 控制单段向量的编码长度，匹配预设的分块粒度 |

## 容易做错的三处
- 现象：索引过程中出现「字段格式不支持」报错，界面显示索引进度停滞。原因：未指定党建文档中仅需索引的正文、标题字段，误将发布单位、附件链接等非内容字段纳入向量编码流程。
- 现象：升级FastGPT版本后，原有CSV格式的党建素材无法正常分块。原因：新版本对CSV的列分隔符校验规则收紧，原文件使用的全角逗号未被正确识别。
- 现象：知识库索引卡住，未完成的任务无法继续执行。原因：增量索引时未启用断点续传配置，中途中断后未保留已处理的文档进度，导致重复加载冗余数据。

## 怎么确认配好了
- 手动上传1份典型党建文档，检查分块结果是否匹配预设的分块长度与重叠长度。
- 提交1条测试问题，查看召回的文档条数是否符合单次搜索上限的设置。
- 查看索引日志，确认仅指定的党建文档字段被纳入向量编码流程。
- 导入1份历史党建素材，验证索引流程在FastGPT v4.17.0版本下可正常完成。
