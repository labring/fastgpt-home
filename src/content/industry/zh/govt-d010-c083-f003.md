# 基础设施建设的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
基础设施建设领域的党建学习数据主要来源于国央企建筑施工单位的党委档案库、项目临时党支部学习台账、上级党委下发的标准化党建学习材料。数据更新节奏为每月同步上级最新政策文件，每季度更新项目一线党建学习记录。文档多为结构化的章节式文本，包含文件编号、发布单位、发布日期、适用施工标段范围等字段，单份文档长度多在5000到20000字符之间。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
文档长度较长且存在标段范围限定字段，要求多轮对话上下文长度需限制在可处理范围内，避免因超长文本触发截断导致信息丢失。数据更新频率较高，需在多轮对话的提示词中加入最新知识库同步的标识，确保回答匹配当前有效的党建政策。适用施工标段的字段要求提示词需绑定对应项目的专属学习范围，避免跨标段的党建内容被错误调用。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体参数如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 前8000–10000字符 | 基础设施党建文档单份长度多在5000到20000字符，限制上下文长度避免截断核心学习内容 |
| `messages` | 按对话轮次保留最近10轮交互 | 多轮党建问答需关联历史提问的标段信息，保留近10轮可覆盖常见上下文需求 |
| `variables` | 绑定施工标段ID与项目党建负责人ID | 党建学习需匹配对应标段的专属学习要求，通过变量过滤非适用内容 |
| 问题优化 | 开启 | 基础设施党建提问多包含专业术语与标段指代，优化后可提升问答匹配精度 |
| 单次搜索上限 | 前6条 | 党建学习问答的有效参考内容多集中在Top5-7条，限制条数避免冗余信息干扰 |
| `chatId` | 按项目临时党支部分组绑定 | 不同标段的党建学习内容独立，分组`chatId`可隔离不同项目的对话上下文 |

## 容易做错的三处
- 现象：调用模型后返回的党建回答未按预设要求输出标准化答案，例如未采用官方指定的表述格式。原因：提示词未配置在对话初始化的`messages`参数中，导致模型未加载预设约束规则。
- 现象：无法查询到历史对话的完整记录，或对话数据存储位置不明确。原因：未正确绑定`chatId`进行分组存储，导致对话数据分散无法统一检索。
- 现象：上传工程党建相关的PPT或文档后，后续对话无法关联附件中的内容。原因：未在提示词中明确附件的处理优先级，未将附件内容与党建知识库进行关联绑定。

## 怎么确认配好了
- 发起包含具体施工标段名称的提问，核对模型回答是否关联对应标段的专属党建学习内容。
- 发起连续多轮关联上下文的提问，核对模型是否能正确引用历史对话中的信息。
- 查看对话分组记录，确认不同项目的对话数据已按`chatId`分组隔离。
- 上传党建相关附件后发起提问，核对模型是否能结合附件内容完成问答。
