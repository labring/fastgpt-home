# 政企信息化服务的党建学习问答：向量模型与索引

本页面配置基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
数据主要来自各级党委发布的党建学习官方材料、内部党课课件、政策解读文件及支部学习记录。更新节奏为每月新增当期学习内容，每季度更新政策类文档。单篇文档结构包含标题、正文段落、发布单位、发布日期字段，以“篇”为单位存储，部分长文档会按章节拆分归档。

## 这些特征在「向量模型与索引」这一环带来什么约束
党建学习类文档包含大量正式政策术语与结构化内容，长文档占比高，对分块的粒度与语义完整性有明确要求。定期更新的文档结构要求索引支持增量刷新，避免全量重建带来的资源消耗。文档附带的发布单位、发布日期等元数据，需要与向量内容绑定，支持按元数据维度过滤召回结果。部分跨部门共享的学习材料存在重复内容，需要在索引前完成轻度去重，避免冗余向量占用存储空间。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxToken` | 4000–6000 token | 适配党建文档的长上下文需求，符合多数开源embedding模型的输入限制 |
| `defaultToken` | 按应用维度统计 | 对应按应用维度拆分token消耗的需求，便于精细化管理 |
| 分块长度 | 800–1200 字符 | 适配党建文档的正式段落长度，避免语义割裂 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的语义衔接，避免关键信息被截断 |
| 单次召回上限 | 前10条 | 覆盖核心相关内容，避免冗余结果过多 |
| 重排阈值 | 0.75 按实测标定 | 过滤低相关性召回结果，提升回答准确性 |

## 容易做错的三处
- 现象：部署向量库时出现容器启动失败，日志提示PostgreSQL相关配置异常。原因：误使用了包含全量组件的Milvus Compose文件，未剥离非必要的PostgreSQL依赖项，导致资源占用超出服务器承载范围。
- 现象：向量召回结果的语义连贯性差，关键政策术语被割裂。原因：分块长度设置超出党建文档的常规段落范围，导致语义分块不完整。
- 现象：token统计结果未按应用维度拆分，混杂多个业务场景的消耗数据。原因：未正确配置token统计的维度参数，导致统计逻辑不符合预设要求。

## 怎么确认配好了
- 查看向量索引的分块日志，确认单条向量的长度符合预设的分块长度范围。
- 执行测试查询，核对召回结果是否包含预设的元数据字段，如发布单位、发布日期。
- 触发token统计任务，确认统计维度与预设的应用维度一致。
- 检查向量库的存储空间占用，确认索引大小符合预设的配置要求。
