# 政企信息化服务的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
政企信息化服务场景下的党建学习问答数据，来源为中央及地方党委组织部官方公开文件、内部党建学习汇编与上级党组织下发的专题材料。更新节奏为每月同步最新政策文件，每季度更新专题学习合集。单篇文档结构包含标题、发布主体、发布时间、正文内容、党建主题标签，字段包含日期型的发布时间、文本型的主题分类标签，单位以“篇”为单篇文档的计数单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
官方权威来源要求多轮对话必须明确标注引用的发布主体与时间，提示词需约束生成内容仅基于召回的文档，避免生成无依据的表述。每月/季度的更新节奏要求知识库同步配置与更新周期对齐，多轮对话上下文需支持按发布时间范围过滤召回结果。结构化的文档字段为提示词提供了精准限定的参数，可通过`variables`传入主题标签参数缩小召回范围。单篇文档内容较长的情况，需在多轮对话中控制上下文窗口的长度，避免超出处理限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 上下文窗口长度 | `8000–12000 token` | 党建文档单篇内容较长，多轮对话需保留足够的历史上下文以支撑连贯问答 |
| 对话ID配置 | 自动生成`chatId` | 多轮对话需唯一标识会话，确保上下文正确关联，避免不同会话的内容混淆 |
| 问题优化开关 | 开启 | 党建问题多为书面化正式表述，优化后可提升关键词召回的精准度 |
| 标签过滤配置 | 按`variables`传入的党建主题标签过滤 | 文档自带主题标签字段，可通过该参数缩小召回范围，提升内容相关性 |
| 历史消息保留条数 | `前10条` | 过多历史消息会占用上下文窗口，10条可覆盖常规党建问答的对话上下文需求 |
| 引用来源展示开关 | 开启 | 党建学习场景需明确内容出处，符合合规管理的要求 |

## 容易做错的三处
- 现象：调用对话接口返回401 No auth credentials found错误。原因：未在FastGPT v4.17.0配置中绑定对应场景的专属API密钥，或密钥未正确关联党建问答知识库的访问权限。
- 现象：小程序嵌入的对话页面顶部标题被自动修改且无法通过常规配置恢复。原因：未在嵌入代码中指定自定义标题参数，默认调用了FastGPT平台的全局标题配置，与党建学习场景的专属标题冲突。
- 现象：多轮对话中召回的知识库内容与当前问题无关，上下文关联失效。原因：未配置`messages`参数的历史消息过滤规则，导致旧的无关对话内容干扰当前的召回逻辑。

## 怎么确认配好了
- 发起包含两轮连续提问的测试对话，核对回复是否关联首轮提问的上下文，根据实际对话场景调整历史消息保留的数量阈值。
- 传入预设的党建主题标签参数，验证召回的文档是否匹配传入的标签，根据场景需求调整过滤配置的匹配规则。
- 检查返回的对话结果是否附带文档的发布主体与时间信息，根据合规要求确认引用来源展示的开关状态。
- 发起测试调用并携带合法认证信息，验证未出现权限错误，根据调用场景调整密钥的权限配置。
