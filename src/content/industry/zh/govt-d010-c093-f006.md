# 政企信息化服务的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
政企信息化服务的党建学习问答数据，主要来源于官方党建出版物、内部培训课件、最新政策文件与行业标准文档。数据更新节奏随政策发布周期调整，核心政策文档每季度同步一次，内部培训文档随培训计划更新。单篇文档结构包含标题、正文段落、发布单位、发布日期四个核心字段，内容以规范书面文本为主，无多媒体附件，字段单位统一为字符数与标准日期格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
党建学习数据的官方来源属性，要求引用溯源必须关联发布单位与发布日期，确保内容权威性。固定更新节奏决定了溯源系统需定期同步最新元数据，避免引用过期文档。文档的结构化字段设计，要求检索时需精准匹配字段维度，不能仅依赖文本相似度，否则可能混入无关分类的党建内容。单篇文档的规范文本结构，让分块后的引用段落可直接对应原始文档的章节位置，为溯源提供明确的定位依据。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 匹配党建资料的专业术语密度，过滤低相关的泛化内容 |
| 单次搜索上限 | 前3–5条 | 党建资料分类明确，过多结果会增加溯源的信息复杂度 |
| `quoteMaxToken` | 800–1200 token | 覆盖单篇党建文档的核心引用段落，避免截断关键政策内容 |
| 重排 | 开启 | 党建资料多为政策类文本，重排可优先匹配问题的核心诉求 |
| `detail` | 开启 | 要求返回引用文档的完整元数据，包括发布单位与发布日期 |
| `responseData` | 仅返回带溯源字段的结果 | 过滤冗余数据，确保溯源信息完整且符合合规要求 |

## 容易做错的三处
- 现象：引用结果仅显示单条文档，无法覆盖问题涉及的多段落内容，原因是单次搜索上限设置过低，未匹配党建资料的多章节引用需求。
- 现象：引用内容未携带发布单位或发布日期字段，导致溯源无法验证权威性，原因是未开启`detail`配置，未要求系统返回完整元数据。
- 现象：新问题的回答未关联历史问题的引用来源，出现答非所问的情况，原因是未开启上下文关联的溯源配置，未保留历史引用的元数据关联逻辑。

## 怎么确认配好了
- 发起包含党建政策关键词的测试问题，查看回答末尾是否显示引用文档的发布单位与日期，确认元数据完整。
- 调整`quoteMaxToken`的取值，观察引用段落的长度是否随配置变化，验证参数生效。
- 开启重排配置后，对比前后两次检索结果的排序，确认重排功能正常运行。
- 检查返回的响应数据是否仅包含带溯源字段的内容，无无关的冗余信息，验证`responseData`配置生效。
