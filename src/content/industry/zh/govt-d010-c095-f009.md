# 新能源开发的党建学习问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自国央企能源电力板块的党建专属资料库，包含上级党委下发的党建学习文件、新能源项目现场的支部活动记录、季度党建考核台账。数据更新节奏为每月同步一次新发布的学习材料与项目党建动态。单篇文档结构固定为标题、正文内容、发布单位、关联新能源项目编号、发布日期，字段包含文档ID、标题字符数、正文长度、关联项目编号，单位分别为条、字符、字符、编号、天。

## 这些特征在「模型接入与配置」这一环带来什么约束
关联新能源项目的专属字段要求检索时需按项目编号过滤匹配内容，避免跨项目党建材料干扰。每月一次的更新节奏降低了实时向量同步的需求，可配置为定时增量更新。固定的文档结构允许在分块时保留关联项目编号作为元数据，便于后续溯源。党建内容的严肃性要求模型输出贴合官方表述，需限制生成的发散程度。部分项目党建文档篇幅较长，需合理限制上下文窗口的占用，避免超出模型承载上限。

## 配置怎么定
以下配置项适配FastGPT v4.17.0版本的模型接入流程：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配新能源党建文档的长文本关联需求，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 控制单轮回答的输出长度，符合党建学习材料的规整输出要求 |
| `quoteMaxToken` | 1500–2000 字符 | 限制引用文档的总长度，确保检索内容不超出上下文窗口 |
| `temperature` | 0.1–0.3 | 降低生成的发散程度，贴合党建内容的严肃、规范要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写实际接入地址 | 确保模型请求的路由正确，避免请求无法送达 |
| `AIPROXY_API_TOKEN` | 填写部署时生成的专属令牌 | 验证请求的合法性，防止未授权访问 |

## 容易做错的三处
-  现象：通过API上传图片后，模型无法识别图片内容，返回无关文本或空结果。原因：未开启`vision`配置项，未启用视觉模型接入能力。
-  现象：检索返回的党建文档分数普遍高于0.95，即使内容与问题关联度较低。原因：未按新能源项目编号配置元数据过滤，导致跨项目的无关文档被召回。
-  现象：通过API调用发布后的工作流，未触发用户选择或表单输入的提示，直接返回固定结果。原因：未在请求中正确开启交互模式配置，导致工作流跳过交互环节。

## 怎么确认配好了
-  传入关联特定新能源项目的党建问题，核对返回结果是否仅包含该项目的相关文档内容。
-  上传测试图片并发起提问，核对模型是否能正确解析图片内容并生成对应回答。
-  查看模型生成的回答，核对是否贴合党建内容的规范表述，无过度发散的内容。
-  验证API请求的令牌与地址配置，确认请求能正常送达并返回有效结果。
