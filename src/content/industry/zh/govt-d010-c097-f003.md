# 核电运营的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
核电运营党建学习问答的数据来源为核电运营企业党委下发的党建文件、班组党建活动记录、上级党委的主题教育材料。更新节奏为每月同步一次上级正式文件，日常班组学习材料随活动开展实时更新。文档结构包含文件标题、发布单位、发布日期、正文内容，附带文件编号、主题分类等专属字段，单篇文档长度跨度较大，涵盖短至数百字符的学习要点，长至数千字符的专题党课材料。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
核电运营党建数据的主题明确绑定核电行业属性，提示词需预设场景限定，避免模型生成泛化的党建内容。文档附带的发布单位、文件编号等字段，可用于多轮对话中的知识点溯源，因此需要保留会话上下文以跟踪用户的提问关联。数据更新节奏非实时，需定期同步知识库，因此多轮对话的配置需支持手动触发知识库刷新。部分文档包含核电运营专属的党建活动术语，提示词需内置领域词汇表，确保模型准确理解行业专属表述。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的逻辑编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 核电党建文档单篇长度跨度大，多轮对话需保留多轮提问与关联知识点，避免上下文溢出 |
| 单次搜索上限 | 前6条 | 核电党建知识库的知识点密度适中，过多召回条目会分散模型注意力 |
| 引用内容上限 | 1200–1800 token | 适配核电党建知识点的表述长度，避免内容冗余导致模型偏离主题 |
| `chatId` | 绑定支部/班组维度 | 区分不同组织的对话上下文，避免跨组学习信息混淆 |
| `messages` | 按会话顺序追加 | 保留多轮对话的上下文历史，适配核电党建学习的连续提问场景 |
| `variables` | 预设「核电运营党建」场景变量 | 自动绑定领域知识，减少重复配置提示词的工作量 |

## 容易做错的三处
- 现象：界面显示“未授权访问”，且已配置知识库对话应用的API key。原因：未将API key绑定至核电党建专属的知识库应用，或应用权限配置未开放党建问答场景。
- 现象：调大引用内容上限至2000 token以上后，模型回答未引用任何召回内容。原因：引用上限设置超出模型上下文承载阈值，或未同步开启关联的强制引用配置。
- 现象：多轮对话中跨会话的上下文未保留。原因：未正确配置`chatId`参数，导致不同对话会话的上下文被混淆或清空。

## 怎么确认配好了
- 发起一次核电党建相关的提问，检查对话界面是否保留上一轮的提问与回答上下文。
- 调整配置项后，发起多轮连续提问，验证`chatId`是否绑定当前会话，避免上下文丢失。
- 查看知识库召回日志，确认引用内容上限的配置与实际召回的条目数量匹配。
- 发起连续三次提问，检查`messages`参数是否按顺序追加上下文，确保多轮对话逻辑生效。
