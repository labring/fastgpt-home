# 民航机场的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
民航机场党建学习问答的数据源主要来自机场党委官方发布的党建文件、民航局党建工作指引、内部党员学习手册。数据更新节奏随官方发文节点调整，党委下发正式文件后1至3天内完成同步。文档多为结构化正式文稿，包含发文单位、文号、发布日期、正文等字段，单份文档字符跨度较大，部分政策解读类文档内容较长，文件存储单位以MB计。

## 这些特征在「引用来源与溯源」这一环带来什么约束
党建文件的结构化字段为溯源提供了明确的标识维度，需在引用时关联发文单位、文号等字段，避免同主题不同时期文件混淆。数据随官方发文节点更新的特性，要求溯源系统支持增量同步的触发逻辑，确保引用内容与最新发布文件一致。单份文档字符跨度大的特点，要求溯源环节在召回时优先匹配核心政策表述，同时避免因长文档分块导致的溯源信息断裂。内部与上级单位来源的区分需求，也要求溯源标记清晰标注来源层级。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 1500–2000 字符 | 民航党建文档多为正式文稿，较长分块可保留完整政策表述，避免溯源信息断裂 |
| 单次搜索上限 | 前6条 | 民航党建相关内容召回量适中，过多会增加上下文处理压力 |
| `quoteMaxToken` | 800–1200 token | 保留足够的原文片段用于溯源，避免关键信息被截断 |
| `responseData` | 返回完整来源字段 | 提取发文单位、文号等结构化字段，满足溯源展示需求 |
| `detail` | 开启 | 需展示来源文档的发布日期等补充信息，增强溯源可信度 |
| 最大上下文 | 4000–6000 token | 适配长文档的溯源需求，保留足够的来源上下文信息 |

## 容易做错的三处
- 现象：配置引用来源后，生成的回答未关联对应知识库内容，界面引用模块显示字段为空。原因：未将HTTP响应数据转换为FastGPT支持的结构化知识库格式，导致系统无法识别来源数据。
- 现象：调用API触发工作流时，无法调用指定的党建知识库。原因：未在工作流配置中传入正确的知识库ID，或未将知识库设置为全局可调用变量。
- 现象：仅文本格式的党建文档被引用，其他格式的文件未被召回。原因：未开启对应格式文档的嵌入处理开关，导致非文本数据无法被检索溯源。

## 怎么确认配好了
- 提交一条党建相关测试问题，查看回答下方的引用模块是否展示发文单位、文号等来源信息。
- 进入知识库管理页面，检查分块长度、搜索上限等配置是否与预设值一致。
- 上传一份测试用的党建政策文件，发起提问后核对引用内容是否与上传文档的原文片段匹配。
- 查看系统日志，确认未出现来源数据解析失败的报错信息。
