# 煤化工的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
煤化工党建学习问答的数据来源为集团内部党建知识库、行业党建指导文件及结合煤化工安全生产的党建专项材料。更新节奏随集团内部文档发布周期调整，无统一固定周期。单篇文档结构包含标题、正文段落、发布主体、发布日期字段，每条数据附带唯一来源标识，用于后续溯源。文档内容多包含行业专属术语与政策表述，整体篇幅跨度较大。

## 这些特征在「引用来源与溯源」这一环带来什么约束
煤化工党建数据的专属发布主体与日期字段要求溯源环节需完整展示这些信息，确保引用的权威性。唯一来源标识的存在要求配置需支持精准匹配单条数据，避免溯源混淆。文档篇幅跨度大的特点要求分块与召回配置需适配长段落内容，避免拆分破坏政策表述完整性。更新节奏随内部发布调整的特性，要求溯源信息需同步知识库的更新状态，确保引用内容的时效性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 煤化工党建文档多包含长段落的行业政策与党建要求表述，该长度可保留完整的表述单元 |
| 最大上下文 | 前 10 条 | 内部党建知识库条目规模适中，前10条可覆盖核心参考依据 |
| `quoteMaxToken` | 1500–2000 token | 确保引用的原文片段可完整展示党建文件的核心政策内容 |
| responseData | 开启来源字段展示 | 需同步展示发布主体、发布日期等溯源必要信息 |
| detail | 开启详细溯源模式 | 匹配煤化工党建文档的多字段溯源需求 |
| 单次搜索上限 | 前 15 条 | 平衡召回精度与溯源信息的完整性 |

## 容易做错的三处
- 现象：页面显示的模型上下文条数与实际发送到推理接口的条数不符。原因：未正确匹配`quoteMaxToken`与最大上下文的配置逻辑，导致截断规则异常。
- 现象：无法在回答中移除或自定义引用标识。原因：误将`responseData`配置为关闭状态，或未在回答模板中正确调用溯源字段。
- 现象：频繁触发引用上限提示。原因：单次搜索上限配置过低，未匹配煤化工党建知识库的实际条目规模，导致召回超出限制。

## 怎么确认配好了
- 发起煤化工党建相关问题测试，查看回答末尾是否附带发布主体、发布日期等溯源字段。
- 查看推理日志，核对传入接口的上下文条数与配置的最大上下文取值一致。
- 调整`quoteMaxToken`的取值，观察回答中引用片段的展示长度是否符合预期。
- 测试切换引用展示开关，确认回答中的引用标识可正常显示或隐藏。
