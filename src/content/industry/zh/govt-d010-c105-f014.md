# 煤炭运销的党建学习问答：对话日志与审计

## 这个品类的数据长什么样
煤炭运销领域党建学习问答的数据来源包括煤炭运销企业党建办归档的岗位专属培训课件、上级国资委党委下发的党建政策文件、通用党建学习材料。更新节奏为上级政策文件随发布同步入库，内部岗位专属课件每季度更新一次，通用学习材料每月更新。单条数据的文档结构包含唯一标识、文件编号、发布主体、发布日期、适用岗位类型（如运销调度、煤炭发运、合同管理）、原文内容、关联党建知识点标签，字段以文本、日期、枚举类型为主，单位涵盖篇、份、条。

## 这些特征在「对话日志与审计」这一环带来什么约束
数据关联具体运销岗位，导致对话日志需绑定岗位标识，避免跨岗位的学习记录混淆，确保审计时可精准匹配岗位对应的学习内容。数据更新节奏存在差异，上级政策文件实时入库，内部课件季度更新，通用学习材料每月更新，审计筛选需支持按发布主体、更新时间分类，便于追溯不同来源的学习材料对应的对话记录。单条数据包含适用岗位标签，日志审计需校验对话发起岗位与文档适用范围的匹配性，确保学习内容符合岗位合规要求。党建内容涉及国资监管的合规要求，日志留存需符合行业监管的周期要求，且需完整记录对话上下文，便于后续溯源核查整改情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话日志留存周期 | 12 个月 | 符合国资监管对党建相关数据的留存要求，匹配煤炭运销企业党建档案的管理周期 |
| `chatId`绑定规则 | 绑定运销岗位ID | 煤炭运销党建问答需区分不同岗位的学习内容，`chatId`关联岗位ID可精准定位岗位相关日志 |
| 日志详情采集开关 | 开启`detail`参数 | 完整记录对话上下文，满足审计时追溯学习过程、核查问答合规性的需求，适配FastGPT v4.17.0的日志采集规则 |
| 历史记录关联源 | 支持`responseChatItemId`关联文档ID | 匹配党建学习资料的文件编号，便于按学习材料溯源具体对话 |
| 日志导出格式 | CSV 格式 | 适配煤炭运销企业内部审计系统的数据导入格式，便于批量审计 |
| 日志筛选维度 | 按岗位、发布时间分类 | 匹配煤炭运销党建数据的分类特征，提升审计效率 |

## 容易做错的三处
- 调用工作流中内嵌的党建问答插件后，对话日志未生成。原因是未将工作流节点的对话接入全局日志采集链路，未绑定`chatId`字段。
- 接口查询历史记录时，仅能获取API来源的日志，无法关联党建学习文档。原因是未配置`responseChatItemId`与党建文档ID的绑定规则，未启用全源日志采集。
- 无法查看工作流中MCP服务的详细日志。原因是未开启`detail`参数，未配置日志的详细采集路径，导致仅记录基础会话信息。

## 怎么确认配好了
- 发起一次针对运销调度岗位的党建学习问答对话，检查日志列表中是否存在绑定对应岗位ID的`chatId`记录。
- 调用历史记录查询接口，验证返回结果中包含`responseChatItemId`字段，且字段值关联党建学习资料的文件编号。
- 导出单条对话的日志文件，确认`detail`参数包含完整的对话上下文、问答内容及关联文档信息。
- 查看日志留存设置，确认超过12个月的党建对话日志未被自动清理，符合监管要求。
