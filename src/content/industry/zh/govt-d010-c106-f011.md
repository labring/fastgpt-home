# 煤电一体化的党建学习问答：表单与交互

## 这个品类的数据长什么样
煤电一体化国央企的党建学习数据主要来自内部党建管理系统的支部会议记录、月度学习台账，以及上级党委印发的党建指导文件。数据更新节奏为每季度批量同步，单篇文档包含学习主题、原文内容、配套思考题、考核要点四个核心结构，字段包含文档ID、所属支部、发布日期、知识点标签，单篇文档长度多在1000至5000字符之间。

## 这些特征在「表单与交互」这一环带来什么约束
党建文档的知识点标签与支部分组属性，要求表单需支持按标签筛选与支部分组的交互逻辑。每季度的批量更新节奏，要求表单的知识库同步配置需支持定时触发规则。单篇文档的较长篇幅，要求`formInput`组件需支持长文本输入，同时需限制单次提交的字符上限，避免嵌入知识库时出现过载。支部维度的分类管理，要求`userSelect`组件需预设对应分组的选项，匹配党建学习的层级管理需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配煤电一体化党建文档的核心段落长度 |
| 重叠长度 | 100–200 字符 | 避免党建知识点被分块截断 |
| `formInput` | 5000 字符上限 | 适配党建学习问答的长文本提问需求 |
| `userSelect` | 按支部预设分组选项 | 匹配党建学习的层级管理逻辑 |
| 单次搜索上限 | 前 6–8 条 | 覆盖单篇党建文档的核心知识点 |
| 最大上下文 | 3500–4500 token | 控制交互时的上下文负载 |

## 容易做错的三处
- 现象：同一问题首次提交无匹配结果，二次提交可返回有效内容；原因：首次提交未触发知识库召回逻辑，表单未绑定正确的召回触发规则。
- 现象：交互时提示上下文溢出报错；原因：未设置合理的最大上下文取值，超出模型支持的token上限。
- 现象：工作流发布后classify模块未按预设运行；原因：发布前未保存模型选择配置，导致部署时参数丢失。

## 怎么确认配好了
- 提交一段党建相关的测试提问，检查表单是否正常接收输入并触发知识库召回。
- 选择`userSelect`组件中的支部选项，确认交互界面仅展示对应分组的党建内容。
- 调整输入文本长度至预设上限，检查表单是否正常限制输入长度并给出提示。
- 发布工作流后，检查工作流模块是否按预设配置正常运行。
