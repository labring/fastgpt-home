# 煤矿生产的党建学习问答：向量模型与索引
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
数据主要来自矿党委下发的党建政策文件、各生产工区的班前会党建学习记录、党员线上学习台账、安全生产与党建融合的专项档案。更新节奏分为按需下发的上级政策文件、每周更新的支部学习记录、实时提交的党员学习反馈。文档结构包含纯文本通知、带表格的学习材料、语音转写的党课纪要，字段包含发布单位、发布时间、适用工区，单位涉及“份”“条”“人次”。

## 这些特征在「向量模型与索引」这一环带来什么约束
文档包含长文本的语音转写党课纪要，会导致单条输入长度超出基础分块阈值，需要适配长文本拆分规则；字段包含适用工区的定向标签，需要基于业务维度构建分层索引，缩小召回范围；实时更新的党员学习反馈数据，要求支持增量索引触发，避免全量重建的资源消耗；带表格的学习材料，需要保留表格语义的向量提取逻辑，避免丢失结构化党建知识点。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配煤矿党建文档的长文本与结构化内容，避免单块信息断裂 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的语义关联，防止党建知识点被拆分遗漏 |
| 相似度阈值 | 0.72–0.80 | 过滤低关联的非党建内容，聚焦核心党建问答结果 |
| 单次搜索上限 | 前 8 条 | 匹配煤矿党建知识库的内容规模，控制召回结果的冗余度 |
| `maxToken` | 4096 token | 适配主流外接向量模型的输入限制，避免截断关键内容 |
| `defaultToken` | 1024 token | 作为默认召回上下文的基础长度，平衡回答精度与资源占用 |

## 容易做错的三处
- 现象：导入飞书文件夹下的Excel文件与多维文档后，索引结果为空。原因：未开启对应文档格式的解析开关，未匹配煤矿党建文档的结构化解析规则。
- 现象：外接向量模型后出现频繁超时报错。原因：未设置合理的`maxToken`参数，超出模型输入限制导致截断重试。
- 现象：全量索引重建耗时过长，服务器资源占用过高。原因：未配置增量索引触发逻辑，对实时更新的党员学习反馈数据执行全量重建。

## 怎么确认配好了
- 上传一份煤矿党建的典型文档，查看分块后的文本长度是否符合预设的分块长度要求。
- 发起一条党建相关的测试提问，核对召回结果的条数是否与单次搜索上限的设置匹配。
- 导入一份带表格的党建学习材料，检查索引结果是否保留了表格内的结构化信息。
- 调整`defaultToken`参数后，查看问答上下文的加载长度是否符合预期。
