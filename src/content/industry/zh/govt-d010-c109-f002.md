# 电网企业的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
电网企业党建学习问答的数据来源于电网企业内部党建学习平台同步的官方文件、党课课件、应知应会手册、党员学习笔记及上级党建通知。更新节奏为每月新增固定学习材料、季度更新党课内容，部分临时下达的党建任务文档会随时上线。文档结构包含长文本课件、短条目知识点、结构化试题三类，字段包含发布单位、发布日期、受众层级、文件类型，统计单位以篇、条、份区分不同类型文档。

## 这些特征在「向量模型与索引」这一环带来什么约束
混合长短文档的结构要求分块策略适配不同内容长度，避免短知识点被过度拆分或长课件超出模型token上限；定期更新的文档要求索引支持增量同步，避免全量重建占用过多资源；元数据字段的存在要求索引关联发布层级、文件类型等标签，支持按权限过滤检索结果；电网党建领域的专有名词较多，要求向量模型适配电网党建的语义场景，减少语义识别偏差；部分结构化试题需单独处理向量生成逻辑，避免破坏试题的语义完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配党建课件、党课讲稿的单块语义完整性，避免长文档超出模型限制 |
| 重叠长度 | 100–150 字符 | 保留分块间的上下文关联，防止党建专有名词被拆分在块两端 |
| `defaultToken` | 8192 token | 适配text-embedding-v3模型的默认token上限，匹配多数党建文档分块后的长度 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的检索结果，保证党建问答的准确性 |
| 单次搜索上限 | 前10条 | 控制检索返回的候选数量，避免上下文过长超出场景承载能力 |
| 重排 | 开启 | 对初始检索结果按语义相关性二次排序，提升党建问答的精准度 |

## 容易做错的三处
- 出现503报错，提示当前分组default下对于模型text-embedding-v3无可用渠道。未在对应分组配置text-embedding-v3的调用渠道，或渠道配额耗尽。
- 检索结果条数不符合预期，无法快速调整索引配置。未进入知识库内容页面进行参数调试，沿用了已下线的快捷编辑入口。
- 长文档的分块出现语义断裂，核心党建专有名词被拆分在相邻块中。分块长度设置过小，未预留足够的语义上下文空间。

## 怎么确认配好了
- 进入FastGPT v4.17.0的向量模型配置页面，确认text-embedding-v3已绑定到default分组，且渠道状态显示正常。
- 上传一篇党建测试文档，查看分块后的结果，确认专有名词未被过度拆分。
- 发起党建相关的测试提问，核对检索结果的元数据标签是否匹配党建文档的分类。
- 检查索引更新日志，确认增量更新任务可正常触发，无报错信息。
