# 矿山采选的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
矿山采选领域的党建学习数据主要来源于企业内部党建档案系统、上级国资监管部门党建指导文件、各车间支部的三会一课与主题党日原始记录。更新节奏为月度更新各支部的日常活动记录，季度更新上级党建部署的最新要求。文档多为带章节编号的长文本，结构包含标题、发布主体、发布日期、所属车间/支部、核心内容模块，仅以字符数、发布日期作为标识字段，无特殊自定义单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
矿山采选党建数据按车间、支部划分的结构，要求多轮对话需在`messages`中绑定对应支部的上下文，避免跨支部的信息混淆；数据月度/季度更新的特性，要求提示词需指定检索最近3个月内的更新文档，确保内容时效性；长文档的章节结构，要求多轮对话拆分片段时保留章节关联，避免断章取义；场景专属的党建内容包含作业现场先锋岗、安全党建结合的模块，提示词需加入场景限定，确保回答贴合采选作业的党建要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 适配矿山采选党建长文档的章节关联内容，保留多轮对话的支部、时间上下文 |
| 问题优化开关 | 开启 | 针对采选场景的党建专业术语，优化用户提问的表述，匹配知识库的文档字段 |
| 单次召回上限 | 前6条 | 匹配支部党建文档的分块数量，避免冗余信息干扰多轮对话 |
| 会话绑定标识 | `chatId` | 确保同一会话的多轮交互保留专属上下文，避免跨会话信息混淆 |
| 提示词模板 | 加入「结合矿山采选作业场景」的限定 | 贴合本品类的党建内容，避免泛泛而谈 |
| 上下文变量 | `variables` 设置为当前支部名称 | 精准检索对应支部的党建数据，提升回答的针对性 |

## 容易做错的三处
- 现象：工作流执行到AI对话环节后无输出，状态码显示上下文超限。原因：未设置合理的最大上下文长度，导致多轮对话的`messages`参数超出系统限制。
- 现象：对话返回的党建内容未结合采选作业场景，出现泛泛的通用党建表述。原因：提示词未加入场景限定，未关联本品类的专属数据字段。
- 现象：会话重启后无法恢复之前的对话上下文。原因：未通过`chatId`绑定会话上下文，导致多轮对话的上下文丢失。

## 怎么确认配好了
- 发起包含采选车间党建内容的多轮提问，查看`messages`参数是否保留了之前的会话上下文。
- 测试提问包含采选场景的党建专业术语，确认问题优化后能匹配到对应的专属文档。
- 检查不同`chatId`的会话是否各自保留独立的上下文，无跨会话信息混淆。
- 触发完整工作流流程，确认从问题优化到知识库搜索再到AI对话的环节完整执行，无中途中断。
