# 粮食储备的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来源为国家粮食和物资储备系统内部党建学习资料，包括上级下发的党建指导文件、储备库支部学习记录、结合仓储业务的党建主题材料。数据更新随上级政策调整与内部学习活动推进，核心党建学习文档每季度同步更新。单份文档结构包含标题、发布机构、发布日期、内容章节，字段标注明确的文件属性与业务关联信息，无复杂嵌套格式，文本内容围绕党建理论与粮食储备业务结合的学习主题。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据包含明确的发布机构与发布日期字段，要求溯源时需同时返回对应字段作为引用依据，避免仅返回文本内容导致溯源模糊。结合粮食储备业务的党建主题内容，需确保召回的文档同时匹配党建学习问题与储备业务场景，否则会出现引用内容脱离业务的情况。非固定周期的更新节奏，要求溯源环节需支持实时校验知识库版本，避免引用过期的旧文档。单份文档结构清晰无复杂嵌套，需确保分块后的内容可精准关联原文档的完整章节信息，防止溯源时丢失文档层级属性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 900–1100 token | 匹配粮食储备党建文档单章节的平均文本长度，避免截断核心引用内容 |
| `responseData` | 包含标题、发布机构、发布日期 | 对应数据中的标准字段，确保溯源信息完整可追溯 |
| `detail` | 开启 | 用于返回引用内容的完整上下文，适配党建学习中结合业务的场景需求 |
| 单次搜索上限 | 前5条 | 覆盖储备党建知识库的常规召回规模，避免过多冗余信息干扰回答 |
| 上下文窗口 | 3200–3800 字符 | 适配单份核心党建文档的内容长度，保证引用逻辑连贯 |

## 容易做错的三处
- 界面弹出`quote type error`报错，且无法保存引用配置。原因是引用的字段未匹配粮食储备党建文档的标准结构，传入了未定义的字段名称。
- 生成的回答中仅返回文本内容，未附带文档标题或发布日期。原因是未正确配置`responseData`参数，未指定需要返回的溯源字段。
- 单次召回的引用条数超出预期，导致回答冗余杂乱。原因是未调整单次搜索上限的取值，沿用了通用场景的默认参数，未适配储备党建知识库的文档规模。

## 怎么确认配好了
- 提交包含粮食储备业务的党建测试问题，查看回答末尾的溯源模块，确认包含标题、发布机构、发布日期字段。
- 触发引用校验流程，检查是否能识别过期文档并提示替换，确认版本校验逻辑生效。
- 调整`quoteMaxToken`参数，验证引用内容不会被截断，确保核心信息完整。
- 测试多变量引用配置，确认可同时关联文档标题、发布日期等多个字段作为溯源依据。
