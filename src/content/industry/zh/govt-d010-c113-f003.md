# 船舶制造的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
船舶制造领域的党建学习问答数据，主要来源为企业内部党建台账、集团党委下发的行业党建指导文件、各分厂支部的学习记录及年度党建考核档案。数据更新节奏为每月同步集团最新党建要求，每季度更新支部一线学习案例。文档结构多为分章节的正式文稿，包含文件编号、发布单位、发布日期、适用支部范围等字段，单位涉及“支部”“学习课时”“文件页码”等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
船舶制造党建问答的数据特征对多轮对话与提示词配置带来明确约束。首先，数据按支部范围划分，提示词需引导对话限定在对应支部的适用内容内，避免跨范围召回无关文档；其次，月度季度的更新节奏要求对话系统匹配知识库同步周期，确保返回内容时效性；第三，正式文稿的结构要求提示词聚焦单章节内容，避免泛泛提问导致的信息过载；最后，一线支部的零散学习记录要求多轮对话保留上下文，关联之前的学习主题，确保提问连贯性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数规则制定：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 每轮会话绑定唯一标识，会话存续7天内复用 | 船舶制造支部党建学习多为连贯场景，需保留上下文关联，避免重复初始化对话 |
| `messages` | 保留前10轮对话上下文，最长不超过8000 token | 党建文档内容正式，过长上下文会稀释核心学习信息，影响匹配精度 |
| `variables` | 传入`{适用支部类型}`、`{当前学习主题}`两个变量 | 不同分厂支部的党建要求存在差异，需精准限定检索范围，匹配专属学习内容 |
| 最大上下文长度 | 800–1200字符 | 党建文档单章节内容集中，过长上下文会干扰核心信息的召回与匹配 |
| 问题优化 | 开启 | 一线工人提问多为口语化表述，优化后可匹配内部党建文档的正式表述，提升召回准确率 |
| 单次搜索上限 | 前3条匹配结果 | 党建学习问答需聚焦核心内容，避免过多冗余信息干扰学习判断 |

## 容易做错的三处
- 首次提问等待3秒以上，后续响应速度正常。原因是首次加载船舶制造党建专属知识库的向量索引，未配置预热缓存机制。
- 对话中每次切换提问主题后，无法沿用之前的学习流程。原因是未绑定`chatId`实现会话上下文复用，每次提问都重置对话状态。
- 工作流中配置自动提问后，无法触发匹配党建文档的检索。原因是未在`variables`中传入预设的学习主题参数，导致检索范围无明确限定。

## 怎么确认配好了
- 发起首次提问，检查响应时长是否符合预期，确认预热缓存机制生效。
- 连续发起3轮关联提问，检查对话上下文是否保留之前的学习主题，确认`chatId`绑定正确。
- 传入`variables`参数并限定支部类型，检查召回的文档是否仅包含对应支部的学习内容。
- 在工作流中配置自动提问，检查是否自动触发党建文档的检索并返回匹配结果。
