# 轨道交通装备的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
轨道交通装备领域的党建学习数据主要来自企业党委下发的理论文件、班组党建学习台账、现场主题党日活动记录、党员学习心得档案。数据更新节奏随党委工作安排调整，日常为月度新增学习材料，季度更新党课课件。单篇文档多为结构化格式，包含标题、正文内容、发布单位、发布日期四个核心字段，单位以“篇”“份”计量，部分长文档包含多级章节结构。

## 这些特征在「向量模型与索引」这一环带来什么约束
多级章节结构要求分块时保留内容逻辑完整性，避免拆分跨章节段落导致语义断裂。月度/季度的增量更新节奏，要求索引配置支持按时间戳或发布单位进行增量同步，减少全量索引的资源消耗。核心字段包含发布单位与日期，索引需支持元数据维度的过滤召回，缩小匹配范围。单篇文档长度差异较大，部分党课课件超过万字，需适配长文本的分块与向量编码规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配党建文档的章节段落长度，避免拆分核心语义单元 |
| 重叠长度 | 100–150 字符 | 保留跨分块的上下文关联，防止语义断层 |
| maxToken | 8192 token | 适配多数党建长文档的编码需求，避免截断核心内容 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的无关党建材料，保证问答精准性 |
| 单次搜索上限 | 前 8 条 | 控制返回结果的数量，适配党建问答的轻量化需求 |
| defaultToken | 1024 token | 设定基础上下文窗口，保证基础问答的内容完整性 |

## 容易做错的三处
- 现象：创建索引后调用党建问答模型返回空结果。原因：未正确建立索引模型与语言模型的调用关联，导致向量召回结果未传入上下文窗口。
- 现象：将向量存储从PGSQL迁移至Zilliz后，旧索引数据无法被正常召回。原因：未按党建文档的元数据字段（如发布日期、发布单位）完成全量数据的重新索引，导致新旧存储的字段映射不匹配。
- 现象：本地部署FastGPT v4.17.0后，外部索引模型调用频繁超时。原因：未配置外部索引模型的访问超时参数，默认超时时长不足以适配本地部署的网络延迟。

## 怎么确认配好了
- 上传一篇包含多级章节的党建测试文档，查看分块后的内容是否保留原有章节逻辑，无跨章节拆分的情况。
- 发起党建相关的测试提问，核对返回结果的相似度得分是否落在设定的阈值区间内。
- 切换向量存储类型，验证已索引的党建数据可正常召回，且元数据过滤功能可正常生效。
- 调用外部索引模型，确认返回的向量结果可正常传入语言模型的上下文窗口，完成问答生成。
