# 轨道交通装备的党建学习问答：表单与交互

## 这个品类的数据长什么样
轨道交通装备领域的党建学习数据，来源为企业内部党建工作台账、行业党建指导手册、属地党组织发布的规范文件。数据更新节奏为按季度同步，单篇文档多为结构化的纯文本内容，字段包含党建主题、发布主体、生效日期、适用岗位类别，单位为字符、标准日期格式，文档会按生产班组、运维岗位、检修岗位等分类归档。

## 这些特征在「表单与交互」这一环带来什么约束
数据按岗位分类归档的特征，要求表单交互需支持按生产班组、运维岗等类别筛选可调用的党建学习内容，避免无关党建内容干扰学习场景。单篇文档的结构化字段，要求表单需支持按主题、生效日期等维度检索匹配数据。季度更新的节奏，要求交互环节需配置定期同步知识库的触发节点，确保调用的党建内容时效性。长文本结构的文档，要求表单的输入控件需适配长文本的解析与展示，避免内容截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 支持多行文本、日期选择器两种自定义控件 | 适配党建学习问答中收集学习心得、标注学习生效日期的场景，匹配轨道交通装备党建数据的结构化字段 |
| `userSelect` | 预设生产班组、运维岗、检修岗3个选项 | 贴合轨道交通装备企业的岗位分类，减少手动输入的操作成本 |
| 单次召回文档数 | 前3条 | 轨道交通装备党建文档单篇长度适中，3条即可覆盖完整学习主题，避免信息过载 |
| 交互超时阈值 | 15 秒 | 党建问答的交互场景需保证响应及时，15秒可覆盖多数网络环境下的文档检索与解析 |
| 表单提交校验规则 | 按实测标定 | 不同企业的党建表单字段要求存在差异，需结合实际提交内容调整校验逻辑 |

## 容易做错的三处
- 聊天对话时显示未选择知识库，但调试预览正常。现象：正式部署后界面提示未绑定知识库，调试阶段可正常调用。原因：部署环节未同步配置知识库的访问权限，或环境变量中的知识库绑定参数未正确更新。
- 工作流中的AI模型下拉列表为空。现象：在问题分类节点的模型选择栏无可选选项。原因：未在平台后台配置可用的AI模型密钥，或模型权限未绑定至当前应用。
- 无法添加自定义输入控件。现象：表单编辑界面仅显示3种内置控件，无自定义入口。原因：未开启应用的自定义表单权限开关，或当前版本未开放该功能（需确认FastGPT v4.17.0支持）。

## 怎么确认配好了
- 进入表单编辑界面，检查自定义控件是否已添加，确认控件类型符合岗位分类的配置要求。
- 发起一次党建问答交互，验证表单提交后是否能正确匹配对应岗位的党建文档，无内容截断或信息遗漏。
- 查看工作流节点的模型下拉列表，确认已显示配置的可用模型选项，无空白状态。
- 模拟常规网络波动场景，验证交互超时阈值是否符合预设配置，无异常报错提示。
