# 通信工程建设的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
通信工程建设领域的党建学习数据来源包括内部党建工作手册、上级党委下发的政策文件、项目临时党建学习材料、三会一课会议纪要、现场党建活动的语音转写文本。更新节奏随内容类型差异较大，上级政策文件按季度更新，会议纪要按项目周期或月度更新，临时学习材料按需生成。文档包含固定元数据字段，如文号、发布单位、会议主题，单篇文档大小从几十KB到数十MB不等。

## 这些特征在「向量模型与索引」这一环带来什么约束
文档格式多样，包含PDF、Word、语音转写文本，向量模型与索引环节需要适配不同格式的文本提取，避免格式残留影响分块效果。文档更新频率差异大，静态政策文件更新周期长，动态会议纪要更新频繁，索引环节需要支持增量更新和全量更新的切换配置。部分文档篇幅较长，如数十页的党建培训手册，分块时需避免割裂完整的学习主题，同时控制单chunk的语义完整性，防止向量化异常。文档包含固定元数据字段，索引环节需要支持基于元数据的精准筛选，提升问答的针对性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配通信工程党建文档的常见语义单元长度，避免割裂政策原文或会议纪要的完整主题 |
| 重叠长度 | 100–200 字符 | 减少相邻chunk的语义断层，确保长文档的上下文连贯性 |
| 相似度阈值 | 0.75–0.85 | 保障党建问答的匹配精准度，过滤低相关的非政策类内容 |
| 单次搜索上限 | 前 10 条 | 控制检索结果的上下文长度，适配通用党建问答的模型输入限制 |
| `defaultToken` | 4096 token | 符合FastGPT默认配置，适配多数党建问答的上下文拼接需求 |
| `maxToken` | 8192 token | 支持处理篇幅较长的党建培训文档，避免超出模型的最大输入限制 |

## 容易做错的三处
- 现象：上传10MB以上的党建培训PDF后，分块生成1000+个chunk，部分chunk向量化后返回空向量或提示向量化失败。原因：未针对长文档调整分块长度，导致单chunk包含过多格式残留或无意义的断句，超出向量模型的输入阈值。
- 现象：服务器因高负载重启后，已创建的党建知识库处于未就绪状态，界面显示“等待索引”但无进度更新，无法自动恢复索引。原因：未开启知识库的自动重试机制，且未配置定时索引任务，仅能通过手动触发恢复。
- 现象：升级FastGPT到v4.9至v4.10版本后，原有党建知识库的向量检索无法返回任何匹配结果。原因：版本迭代后向量模型的嵌入维度或索引存储格式发生变更，原有索引未重新生成，且当前配置未适配FastGPT v4.17.0的索引规则。

## 怎么确认配好了
- 上传一篇10MB以上的党建政策PDF，查看分块后的chunk列表，确认每个chunk的字符长度符合预设区间，无异常报错提示。
- 提交一个针对党建政策原文的测试问题，验证检索返回的结果包含匹配的政策片段，且相似度符合预设阈值。
- 重启FastGPT服务后，检查原有党建知识库的状态是否自动变为就绪，无需手动触发索引操作。
- 调整分块长度参数后重新上传测试文档，对比分块结果与预设长度的匹配度，确认配置生效。
