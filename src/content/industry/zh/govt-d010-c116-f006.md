# 通信工程建设的党建学习问答：引用来源与溯源

## 这个品类的数据长什么样
通信工程建设领域的党建学习问答数据，主要来源于通信央企及行业党委的党建学习平台、项目临时党支部的学习记录与会议纪要。数据更新节奏为季度更新核心政策文件，月度更新最新学习动态与支部活动记录。文档多为结构化正式文稿，包含标题、发布单位、发布日期、内容正文、所属项目组或支部等字段，单篇文档长度多在2000-8000字符区间，存储单位以MB为计量标准。

## 这些特征在「引用来源与溯源」这一环带来什么约束
结构化字段包含所属项目组或支部，要求溯源环节需绑定对应项目的党建上下文，避免跨项目的学习内容混淆。季度更新的核心政策与月度更新的动态内容，需要配置分层同步规则，确保不同时效性的内容被正确纳入引用池。单篇文档长度较长，会导致分块后上下文关联范围扩大，需限制溯源时的上下文长度，避免无关内容被带入。发布日期字段可作为溯源的时间筛选依据，用于限定问答仅引用指定周期内的学习材料。

## 配置怎么定
本页面基于FastGPT v4.17.0版本配置。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 匹配通信工程党建文档的常规单篇长度，避免截断核心政策或学习内容 |
| `quoteMaxToken` | 1500–2000 token | 限制单条引用的展示长度，确保溯源信息清晰不冗余 |
| 引用返回上限 | 前3条 | 适配党建问答的精准性需求，避免过多无关内容干扰学习判断 |
| `responseData` | 包含标题、发布日期、所属项目组 | 匹配结构化数据的字段特征，确保溯源信息完整且可关联对应项目 |
| `detail` | 开启 | 显示完整的引用来源细节，满足党建学习的合规溯源要求 |
| 增量同步周期 | 每日 | 适配月度更新的学习动态与季度更新的核心文件，及时收录最新内容 |

## 容易做错的三处
- 现象：配置引用溯源后，问答结果未展示对应的来源信息。原因：未正确开启`detail`配置项，或`responseData`未包含必要的溯源字段。
- 现象：将`quoteMaxToken`设置为3000以上时，大模型无法获取上下文内容。原因：超出平台预设的总上下文上限，导致上下文被直接截断未传递。
- 现象：上传的党建学习文档在平台内显示乱码，下载后恢复正常。原因：文档原始编码与平台默认编码不匹配，未提前转换为UTF-8格式。

## 怎么确认配好了
- 上传一篇测试用的通信工程党建文档，发起相关问答，查看结果是否附带来源信息。
- 调整`quoteMaxToken`的取值，验证引用内容的展示长度是否符合预期。
- 检查`responseData`的配置，确认返回的字段包含标题、发布日期等必要信息。
- 发起包含项目组关键词的问答，验证溯源信息是否关联了对应项目的党建内容。
