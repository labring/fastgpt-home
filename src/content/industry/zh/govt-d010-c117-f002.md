# 通信铁塔与基础设施的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
通信铁塔与基础设施的党建学习相关数据，来源包括各级党委下发的党建学习资料、运维团队的党建活动记录、站点配套的党建宣传物料电子版、内部党建系统归档文档。更新节奏为：上级配发的学习材料按季度更新，活动记录随党建活动开展实时归档，站点宣传物料每半年更新一次。文档分为纯文本学习文稿、带图片的活动简报、结构化党建考核台账三类，字段包含文件标题、发布单位、发布日期、内容正文、关联站点编号，站点编号为6位数字编码，发布日期采用YYYY-MM-DD格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
包含图文混合的活动简报，要求向量模型支持多模态输入，适配图文内容的联合向量化处理。存在关联站点编号的结构化字段，需要在索引环节单独建立元数据索引，支持按站点维度过滤检索结果。更新频率差异明显，实时产生的活动记录需适配增量索引逻辑，季度/半年更新的批量材料可采用全量索引流程。文档长度跨度大，纯文本学习文稿可达数千字符，简报附带的说明文本较短，需要灵活的分块策略适配不同长度的内容单元。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配纯文本学习文稿的长度，避免单块内容过长导致向量化溢出 |
| 重叠长度 | 100–200 字符 | 覆盖分块边界的上下文，避免党建知识点被拆分丢失 |
| `defaultToken` | 1024 token | 匹配多数党建文本的向量化token限制，适配通用向量模型输入要求 |
| `maxToken` | 4096 token | 支持带图片的简报中较长的说明文本向量化 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的党建学习问答结果，保证检索精度 |
| 单次搜索上限 | 前 8 条 | 控制返回结果数量，适配党建问答的上下文长度要求 |

## 容易做错的三处
- 向量化任务返回token超限报错，界面显示`413 Request Entity Too Large`状态码。原因：未根据党建文稿的实际长度调整`maxToken`参数取值，超出向量模型的输入限制。
- 检索结果中混入大量非党建相关的运维数据，返回条数远高于设置的单次搜索上限。原因：未启用站点编号的元数据过滤，未将结构化字段纳入索引元数据配置。
- 尝试混用文本向量模型与多模态向量模型处理同一批文档，导致多模态向量化流程失败。原因：未统一向量模型的输入格式要求，混搭不同类型的向量模型未做适配处理。

## 怎么确认配好了
- 上传一篇典型的党建学习文稿，查看分块后的内容是否符合预设的分块长度与重叠长度要求。
- 发起一次带站点编号过滤的检索，验证结果是否仅包含对应站点的党建相关内容。
- 测试多模态文档的向量化流程，确认无格式报错后查看生成的向量数据是否完整。
- 调整相似度阈值，观察检索结果的相关性变化是否符合预期配置逻辑。
