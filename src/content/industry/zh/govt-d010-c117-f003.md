# 通信铁塔与基础设施的党建学习问答：多轮对话与提示词

## 这个品类的数据长什么样
数据来源包括通信铁塔运维台账、基站巡检记录、属地党建学习规范文件、铁塔站点党建共建档案。运维类文档多为结构化表格，包含站点编号、巡检日期、维护内容等字段；党建类文档多为非结构化文本，涵盖学习主题、考核要求、活动纪要等内容。数据更新节奏随运维周期与党建活动安排调整，运维数据每周同步，党建学习材料每月更新。文档格式包含Word、PDF及结构化表格文件，单份文档最长可达数十页。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
结构化运维数据包含固定字段，多轮对话需通过`chatId`绑定会话上下文，通过`messages`数组保存历史交互内容，避免跨站点匹配错误。非结构化党建材料存在主题分散、术语统一要求高的特点，需通过`variables`传入站点编号等参数，提示词需明确限定回答范围为党建学习相关内容，防止混入运维技术细节。大体积文档解析耗时较长，多轮对话的上下文窗口需限制冗余信息，避免占用过多计算资源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配党建文档与运维台账的段落长度，避免块内信息割裂 |
| 重叠长度 | 100–200 字符 | 保留跨块的上下文关联，确保党建主题的连贯性 |
| 最大上下文窗口 | 前 4 轮对话 | 限制冗余信息占用资源，适配多轮党建问答的交互节奏 |
| 问题优化 | 开启 | 优化用户的口语化提问，匹配党建学习的规范表述 |
| 单次检索上限 | 前 6 条 | 覆盖单站点的运维与党建关联信息，避免结果过多干扰判断 |
| 接口超时阈值 | 300 秒 | 适配大体积文档的解析与检索耗时，避免提前中断请求 |

## 容易做错的三处
- 现象：界面显示文档解析超时，或对话响应延迟超过预设时长。原因：未针对大体积党建文档与运维台账调整超时阈值，沿用默认的短时长配置。
- 现象：对话返回结果为空，或未匹配到对应站点的党建学习内容。原因：未在对话流程中关联指定知识库，或未通过`variables`传入站点编号等关键上下文参数。
- 现象：回答同时包含党建内容与运维技术细节，超出问答范围。原因：提示词未明确限定回答仅针对党建学习相关内容，未区分运维与党建的场景边界。

## 怎么确认配好了
- 上传一份10M左右的党建文档，查看解析进度是否在合理时间内完成，无超时报错。
- 发起包含站点编号的多轮提问，确认对话过程中保留了站点ID的上下文信息，匹配结果与指定站点的党建内容一致。
- 调整问题优化开关的状态，对比开启前后的回答表述，确认优化功能正常生效。
- 确认当前使用FastGPT v4.17.0版本，查看知识库关联配置页面，确认当前对话流程已绑定对应品类的运维与党建知识库。
