# 钢铁冶炼的党建学习问答：向量模型与索引

## 这个品类的数据长什么样
钢铁冶炼领域的党建学习数据主要来源于上级党委下发的正式文件、厂内三会一课记录、党建活动档案及结合生产岗位的专项学习材料。数据更新节奏分为固定周期与即时触发两类：每月更新上级党委发布的理论学习文件，每两周同步厂内党建活动动态，重大政策发布后24小时内完成同步。文档结构以标题、正文、发布单位、发布日期为核心字段，部分材料包含嵌入式图片或扫描件的OCR文本，单篇文档长度跨度较大，字段包含文档ID、所属党支部、内容分类等标准化标识。

## 这些特征在「向量模型与索引」这一环带来什么约束
钢铁冶炼党建数据的多维度特征对向量模型与索引配置提出了明确约束。首先，文档长度跨度大且包含图文混合材料，要求分块策略需适配不同长度的文本与图文关联内容，避免割裂上下文关联。其次，数据包含标准化元数据字段，需支持按元数据（如所属党支部、内容分类）进行过滤召回，提升检索精准度。此外，即时更新的数据源要求索引支持增量同步，避免全量重建带来的资源浪费。最后，部分材料结合生产岗位的具体要求，需确保向量检索结果与岗位场景匹配，避免召回无关内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配钢铁冶炼党建文档的平均长度，避免割裂正文与生产结合的关联内容 |
| 重叠长度 | 100–150 字符 | 保留分块间的上下文关联，防止跨块的党建政策与生产要求脱节 |
| 相似度阈值 | 0.72–0.85 | 过滤低相关召回结果，适配党建内容的严谨性要求 |
| 单次搜索上限 | 前10条 | 控制返回结果的总长度，避免超出模型上下文窗口限制 |
| `maxToken` | 4096 token | 适配主流Embedding模型的输入长度限制，兼容图文混合文档的向量化 |
| 重排 | 开启，取前3条 | 提升高相关结果的排序优先级，匹配党建问答的精准性需求 |
| API请求令牌 | 填入对应模型的`defaultToken` | 完成模型调用的身份验证，解决模型不可选的问题 |

## 容易做错的三处
- 现象：检索结果未包含带图片的党建宣传材料，仅返回纯文本内容。原因：未开启图文联合向量化配置，仅对文档的纯文本部分生成向量，未关联图片的OCR文本特征。
- 现象：界面中无法选择智谱Embedding-3等最新Embedding模型。原因：未将对应模型的接口地址与密钥填入`defaultToken`配置项，或未使用FastGPT v4.17.0及以上版本。
- 现象：导入知识库后召回的内容包含非党建类的生产文档。原因：未按文档的内容分类字段配置索引过滤规则，导致未筛选出仅党建相关的数据源。

## 怎么确认配好了
- 上传一篇带图片的党建文档，执行检索后查看结果是否包含该文档的图片关联内容。
- 进入模型配置页面，确认目标Embedding模型已出现在可选列表中。
- 上传不同分类的文档，执行检索时添加元数据过滤条件，确认仅召回匹配分类的文档。
- 执行一次完整的增量索引同步，查看索引进度是否正常完成，无报错日志。
