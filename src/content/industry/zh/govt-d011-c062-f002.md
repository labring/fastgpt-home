# 会议纪要整理的公文辅助：向量模型与索引

## 这个品类的数据长什么样
会议纪要的数据来源于政企会议的录音转写结果、参会人员整理的纸质记录电子化文件、会议管理系统导出的标准文稿。更新节奏为单次会议完成后生成单份纪要，或按周/月批量导入历史会议纪要。文档结构固定包含会议主题、召开时间、参会人员清单、讨论议题、决议事项、后续跟进任务等字段，单份文档长度跨度较大，字段均为结构化或半结构化文本，以单份纪要为基本处理单元。

## 这些特征在「向量模型与索引」这一环带来什么约束
会议纪要的多源输入会带来文本格式差异，录音转写内容含口语化冗余表述，结构化导出内容则字段规整，这要求向量模型与索引环节需兼容混合格式的文本输入。单份文档的字段差异明显，短字段如参会人员、决议事项的文本长度多在百字符以内，长字段如讨论议题可长达数千字符，需针对不同字段匹配差异化的分块逻辑。批量导入的历史纪要与单次实时生成的新纪要，对索引的实时更新与批量构建能力提出不同要求，需适配两种更新场景的索引构建节奏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配会议纪要中讨论议题、决议事项的平均文本长度，避免单块内容过载 |
| 分块重叠长度 | 100–200 字符 | 保留跨块的上下文关联，避免会议议题的逻辑被分块切断 |
| `maxToken` | 8192 | 适配主流嵌入模型的最大输入token限制，兼容会议纪要的长文本块 |
| `defaultToken` | 1536 | 匹配多数嵌入模型的输出维度标准，保证向量索引的一致性 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 适配会议纪要中决议事项、跟进任务的语义匹配精度需求 |
| 单次搜索上限 | 前10条 | 覆盖会议纪要中常见的议题与决议数量，避免冗余召回 |

## 容易做错的三处
- 现象为调用pushdata api上传chunk模式数据后，界面长期显示索引中状态。原因是未针对会议纪要的批量导入场景配置批量索引触发规则，导致单块数据反复触发索引构建。
- 现象为嵌入模型调用报错，提示令牌无权使用指定模型。原因是未在FastGPT配置中正确绑定对应模型的访问密钥，或密钥未开通对应嵌入模型权限。
- 现象为向量召回结果与会议纪要的实际议题不匹配。原因是分块长度设置过大，导致单块包含多个不相关的会议讨论内容，语义向量混淆。

## 怎么确认配好了
- 上传一份标准格式的会议纪要测试样本，查看向量索引构建进度在FastGPT v4.17.0版本的系统中5分钟内完成，无长期挂起状态。
- 调用嵌入模型测试接口，验证返回的向量维度与配置的`defaultToken`参数一致。
- 输入会议纪要相关的查询词，查看召回结果的相似度分值落在配置的阈值区间内。
- 批量导入10份历史会议纪要，确认索引构建任务按批量规则完成，无重复索引条目。
