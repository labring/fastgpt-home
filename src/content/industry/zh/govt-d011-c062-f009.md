# 会议纪要整理的公文辅助：模型接入与配置

## 这个品类的数据长什么样
会议纪要整理的数据源主要为会议现场录音转写文本、手写会议记录扫描件、参会人员提交的初稿文件。更新节奏以单次会议为单位，每次会议生成一份独立的纪要文件。文档结构通常包含会议主题、召开时间、参会人员、讨论议题、决议事项、后续跟进事项等固定模块，部分文件会标注参会人数（单位：人）、会议时长（单位：分钟）等单位化字段，内容以自然语言段落为主，夹杂口语化表述与临时补充内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
会议纪要的固定模块结构要求模型精准识别并提取主题、决议事项等特定字段，因此模型输出需遵循明确的格式约束。原始文本中的口语化表述与临时补充内容，要求模型具备文本规范化与纠错能力，避免生成偏离原始内容的冗余信息。单次会议生成的独立文件属性，意味着无需配置增量更新逻辑，仅需针对单份文件完成解析与整理。不同会议纪要的长度差异较大，长会议文件可能超出基础上下文窗口，因此需要适配的上下文容纳参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配多数会议纪要的总长度，容纳原始文本与解析指令 |
| `maxTokens` | 2000–3000 token | 为结构化输出预留足够空间，确保决议事项、跟进事项等内容完整输出 |
| `temperature` | 0.2–0.4 | 保持输出内容的准确性，降低口语化冗余内容的生成概率 |
| `AIPROXY_API_ENDPOINT` | 本地MinerU部署的接口地址，如`http://localhost:3001/api/v1/parse` | 适配会议纪要的PDF、录音转写文件解析需求，确保原始文件可被正常读取 |
| `AIPROXY_API_TOKEN` | 对应接口的认证令牌 | 保障解析接口的调用安全性，避免未授权访问 |
| `toolChoice` | `auto` | 允许模型自主判断是否调用解析工具处理原始会议文件，适配不同格式的输入数据 |

## 容易做错的三处
- 工作流中模型图标不显示，文件上传提示网络错误。原因是未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，导致解析接口调用失败。
- 生成的会议纪要缺少决议事项、跟进事项等核心字段。原因是`maxTokens`取值过低，无法容纳完整的结构化输出内容。
- 模型输出的纪要内容偏离原始会议讨论内容，出现大量无关表述。原因是`temperature`取值过高，导致模型生成超出原始内容的冗余信息。

## 怎么确认配好了
- 使用curl命令调用`AIPROXY_API_ENDPOINT`对应的接口，上传测试用的会议纪要文件，验证接口返回有效解析数据。
- 在FastGPT v4.17.0的工作流中上传一份测试会议纪要文本，查看模型是否正常加载并触发解析流程。
- 调整`temperature`参数至0.2–0.4区间，对比不同取值下的输出内容，确认输出符合纪要规范化要求。
- 检查`maxContext`与`maxTokens`的取值，确保覆盖测试纪要的总长度与输出需求。
