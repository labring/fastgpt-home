# 公文格式校对的公文辅助：HTTP 接口与外部系统

## 这个品类的数据长什么样
公文格式校对的数据来源于国央企、政府部门的正式公文文档，包含上行文、下行文等标准化格式文件。更新节奏随公文流转流程触发，可支持实时单篇上传或批量导入。文档结构固定分为版头、主体、版记三部分，核心字段包括发文字号、标题、主送机关、正文、成文日期、印章位置等，内容以中文字符为主，附带少量标点、数字与格式标记。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
公文的固定结构要求HTTP接口需支持按标准字段解析请求参数，避免非结构化数据的误判。实时流转场景下，接口需兼容低延迟响应，满足单篇公文即时校验的需求；批量导入场景则需支持分页或批量提交参数，避免请求超时。核心字段的校验逻辑需与接口返回结果一一绑定，确保发文字号、成文日期等字段的校验结果可被外部系统直接读取。不同文种的格式规则存在差异，接口需支持传入文种类型参数，匹配对应校验逻辑。

## 配置怎么定
本配置方法适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {API密钥}` | 符合HTTP接口鉴权标准，适配多数公文格式校验服务的鉴权要求 |
| `variables` | `{"doc_type": "上行文", "check_fields": ["发文字号", "成文日期"]}` | 指定校验的公文类型与核心字段，缩小校验范围，提升接口响应速度，取值可根据实际校验需求调整 |
| `responseData` | `前 3 条校验结果` | 公文格式校验的核心问题通常集中在版头、主体、版记的关键错误，返回前3条即可满足外部系统的告警与修正需求，避免冗余数据传输 |
| 请求超时时间 | `30–60 秒` | 单篇公文格式校验需解析完整文档结构，过长或过短的超时时间均会影响校验稳定性，该区间可适配多数场景 |
| 批量请求上限 | `10 篇/次` | 批量提交时需平衡接口负载与传输效率，10篇/次可避免单次请求数据量过大导致的超时或失败 |
| 接口地址 | `按实际部署的校验服务地址填写` | 适配不同部署环境的校验服务，确保请求能正确触达目标接口 |

## 容易做错的三处
- 现象：接口请求返回403 Forbidden状态码，FastGPT测试时报权限错误。原因：未正确配置`Authorization`参数，或传入的API密钥已过期、权限不足。
- 现象：接口请求出现跨域拦截，控制台提示跨域资源共享错误。原因：外部系统的接口未配置允许FastGPT域名的跨域规则，导致请求被拦截。
- 现象：批量提交公文时频繁出现请求超时。原因：单次提交的公文数量超过接口支持的上限，或请求超时时间设置过短，未适配公文解析的耗时需求。

## 怎么确认配好了
- 调用配置好的HTTP接口，传入一份格式合规的标准公文，检查接口返回的校验结果是否显示无错误。
- 查看FastGPT的接口调用日志，确认`Authorization`参数已正确携带，请求参数与配置项一致。
- 向外部系统推送校验结果，检查外部系统是否能正常接收并解析返回的`responseData`内容。
- 模拟一份存在格式错误的公文提交，确认接口返回对应的错误字段与提示信息，验证校验逻辑生效。
