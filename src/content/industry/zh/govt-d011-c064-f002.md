# 公文格式校对的公文辅助：向量模型与索引

## 这个品类的数据长什么样
数据来源为国央企、政府及公共服务部门的正式公文，包括请示、批复、通知、纪要等标准化文档，更新节奏为按需提交或定时批量同步，无固定周期。文档结构包含固定格式元素：发文字号、主送机关、正文段落、附件清单、落款及成文日期，部分文档带有密级、主题词等元数据字段，数据单位以「份」为统计单元，单份文档的正文长度差异较大，从数百字符到数千字符不等。

## 这些特征在「向量模型与索引」这一环带来什么约束
公文的固定格式要求分块时不能破坏关键元数据与正文的绑定关系，否则格式校验会丢失关键依据；部分公文存在大量通用套话，需向量模型区分通用表述与个性化业务内容，避免误判；单份文档篇幅跨度大，索引构建需适配长文本分块与短文本快速召回的平衡；按需更新的场景要求索引支持增量同步，避免全量重建带来的资源消耗。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配公文正文段落的平均长度，避免单块内容过长超出向量模型处理能力 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的上下文关联，防止分块切断关键业务逻辑 |
| 相似度阈值 | 0.72–0.85 | 按实测标定，平衡公文格式校对的精准召回与误召回率 |
| 单次召回上限 | 前 10 条 | 适配公文校对的精准匹配需求，避免冗余结果干扰校验 |
| `maxToken` | 8192 | 适配阿里multimodal-embedding-v1模型的最大输入限制 |
| 索引存储上限 | 500 GB | 适配批量公文数据的存储规模，避免磁盘资源耗尽 |

## 容易做错的三处
- 文档长时间处于索引中：现象是FastGPT v4.17.0的索引任务列表中，对应任务的状态持续显示「构建中」超过12小时，原因是分块长度设置超出当前绑定向量模型的`maxToken`限制，且未开启自动分段处理。
- 分块索引内容无法正常获取：现象是调用分块索引查询接口时，返回的内容缺少公文的发文字号、成文日期等元数据字段，原因是未在分块配置中开启元数据绑定选项。
- 多索引检索结果重复率过高：现象是同一篇公文的多个分块在检索结果中重复出现，原因是分块重叠长度设置超过分块总长度的20%，导致分块边界重叠过多。

## 怎么确认配好了
- 上传一篇测试公文，查看索引构建日志，确认分块长度、重叠长度与配置值一致。
- 进入向量模型配置页面，验证已绑定的阿里multimodal-embedding-v1模型可正常生成测试向量。
- 输入与测试公文内容匹配的查询词，查看检索结果的分块内容是否包含正确的元数据字段。
- 调整相似度阈值，验证检索结果的召回数量随阈值变化符合预期。
