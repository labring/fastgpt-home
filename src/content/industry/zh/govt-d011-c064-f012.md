# 公文格式校对的公文辅助：部署与升级

## 这个品类的数据长什么样
公文格式校对的数据源主要来自国央企、政府及公共服务机构的待校对公文原稿，以及官方发布的党政机关公文格式标准文档。数据更新节奏以单次上传或批量导入为主，单次任务的文档结构严格遵循固定规范，包含版头、主体、版记三大模块，字段涵盖发文字号、成文日期、主送机关、附件说明等，部分字段带有强制格式要求，比如发文字号需符合机关代字+年份+序号的结构，正文字体需为三号仿宋_GB2312。

## 这些特征在「部署与升级」这一环带来什么约束
由于公文数据带有固定格式字段与强制规范，部署时需支持结构化字段的精准校验，同时需适配批量处理场景下的并发请求。本适配方案基于FastGPT v4.17.0版本开发，升级环节需保留用户自定义的格式规则库，避免覆盖原有配置；本地私有化部署时需确保存储与计算资源适配长文本公文的解析需求，防止因资源不足导致校对失败。此外，版本升级需兼容旧版的格式校验逻辑，确保存量公文的校对结果一致性，同时需同步更新内置的格式标准库至最新版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://localhost:27017/fastgpt?maxPoolSize=20` | 公文格式校对需存储大量格式规则与校对日志，本地部署时使用本地MongoDB实例，连接池设置适配批量处理场景 |
| `REDIS_URL` | `redis://localhost:6379/0?maxMemoryPolicy=allkeys-lru` | 缓存常用格式校验规则与用户会话，降低重复计算开销，适配高频校对请求 |
| `STORAGE_S3_ENDPOINT` | `http://localhost:9000` | 存储批量上传的公文原稿与校对结果，本地私有化部署时使用本地对象存储服务 |
| `ROOT_KEY` | `按实测标定` | 配置管理员权限密钥，用于管理格式规则库的更新与版本同步，避免非授权修改 |
| `FILE_TOKEN_KEY` | `随机生成的32位字符串` | 用于加密公文上传的临时令牌，防止未授权访问待校对文档 |
| `FE_DOMAIN` | `http://localhost:3000` | 指定前端访问域名，适配本地部署的访问路径，确保校对结果页面正常加载 |

## 容易做错的三处
- 升级版本后原有自定义格式校验规则丢失，原因是未在升级前备份`MONGODB_URI`对应的格式规则库数据，升级脚本未保留自定义配置。
- docker部署后无法加载格式校验规则库，原因是未正确配置`STORAGE_S3_ENDPOINT`指向本地存储路径，导致规则文件无法正常读取。
- 配置第三方密钥后无法触发校对任务，原因是未将密钥关联至`ROOT_KEY`对应的管理员权限上下文，导致工具调用权限不足。

## 怎么确认配好了
- 进入后台配置页面，核对已配置的数据库、存储、缓存等参数与预设值一致。
- 上传一份符合官方格式标准的公文样本，触发校对流程，确认结果正常输出。
- 执行版本升级脚本后，验证原有自定义格式规则未被覆盖。
- 检查存储服务连接状态，确认公文原稿与校对结果可正常存取。
