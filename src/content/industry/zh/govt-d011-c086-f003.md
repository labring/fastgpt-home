# 工作简报汇编的公文辅助：多轮对话与提示词

## 这个品类的数据长什么样
工作简报汇编的数据来源于国央企内部各职能部门、下属单位报送的专项进展、周度或月度工作汇总。更新节奏随报送周期而定，多为每周或每月更新一次。单篇文档结构固定，包含标题、报送单位、报送日期、核心进展、待协调事项、下一步计划等字段，单篇篇幅多在500-1500字符，无统一单位字段，仅以自然段落承载具体内容。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
固定的文档结构要求多轮对话需精准匹配字段提取逻辑，避免遗漏报送单位、日期等关键信息。不定时的更新节奏要求对话上下文需支持按最新报送数据刷新，无法依赖固定历史语料。单篇篇幅适中但批量汇编时总长度较大，要求多轮对话的上下文窗口需适配长文本处理，避免截断核心内容。多部门报送的分散来源要求对话需支持按报送单位筛选上下文，同时需明确提示词区分不同部门的工作内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 预设开场白变量 | `待核验值、待核验值` | 适配简报的报送单位和周期字段，快速引导用户输入具体汇编需求 |
| 消息历史保留长度 | 前20条对话 | 匹配单篇简报的常规篇幅，避免上下文过长导致模型混淆核心信息 |
| `variables` 配置 | 固定包含常用报送单位列表 | 帮助模型识别不同部门的简报内容，避免跨部门工作内容混淆 |
| 上下文窗口大小 | 8000-12000 token | 适配批量汇编时的总文本长度，防止关键进展或计划被截断 |
| `chatId` 关联规则 | 按单次汇编任务绑定 | 确保同一任务的多轮对话上下文连贯，避免会话中断后数据丢失 |
| `messages` 参数配置 | 携带源文档元数据 | 支持对话接口返回查看来源原文的功能，满足溯源需求，FastGPT v4.17.0 版本支持该参数配置 |

## 容易做错的三处
- 刷新页面后显示“检测到没有可用的索引模型”，原因是未将简报汇编的语料库关联至当前对话agent的索引配置，或索引模型的部署状态异常。
- 对话中返回404 status code（no body），原因是`chatId`参数未正确携带，或会话接口的权限配置未开放对应访问路径。
- 对话开场白未显示预设的多个引导问题，原因是`variables`中未正确配置预设问题列表，或提示词未绑定对应变量参数。

## 怎么确认配好了
- 测试预设开场白，输入不同的报送单位和周期，确认提示词能自动匹配对应字段生成引导问题。
- 发起多轮对话，连续提交3-5条不同的汇编需求，确认`chatId`关联的上下文未被重置，对话逻辑连贯。
- 调用对话接口，检查返回结果中是否包含`messages`参数的历史上下文记录，确认会话状态正常。
- 验证索引配置，刷新页面后检查是否能正常加载简报汇编的语料库，无报错提示。
