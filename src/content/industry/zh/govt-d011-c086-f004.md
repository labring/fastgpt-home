# 工作简报汇编的公文辅助：工作流编排

## 这个品类的数据长什么样
工作简报汇编的数据来源为各业务部门报送的周度、月度工作动态材料，更新节奏以批量汇总周期为准，通常按自然周或自然月更新。单份汇编文档包含报送部门、报送日期、核心工作内容、阶段性成果、下一步工作计划等字段，部分文档附带佐证图片或附件链接，整体结构层级清晰，字段格式相对固定。

## 这些特征在「工作流编排」这一环带来什么约束
多部门分散报送的特性要求工作流需支持多输入节点接收不同来源的简报素材，避免单节点过载。固定的更新周期要求工作流配置定时触发规则，匹配汇总周期，无需手动触发。明确的字段结构要求工作流中设置字段提取节点，精准抓取报送部门、工作内容等核心信息，过滤冗余的非必要内容。附带佐证附件的需求则要求工作流预留关联原文件的环节，满足后续溯源或在线预览的要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工作流功能制定：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 定时触发 | 按自然周/自然月周期，触发时间选业务收尾后1小时 | 匹配工作简报汇编的固定更新节奏，避免遗漏报送材料 |
| `variables` | 预设报送部门、报送日期、汇编编号3个变量 | 对应简报文档的固定字段，便于后续提取与归档 |
| 字段提取节点 | 匹配预设字段的关键词规则 | 精准抓取核心内容，过滤冗余信息 |
| `nodeId` | 为原文件关联节点分配独立标识 | 便于工作流中定位原文件预览环节，避免节点冲突 |
| 超时设置 | 600秒 | 适配多部门材料汇总的处理时长，避免中途中断 |
| 上下文窗口 | 8000–12000 token | 容纳单份汇编的完整内容，确保生成的汇编文本连贯完整 |

## 容易做错的三处
- 发布后的工作流链接指向localhost地址。原因是未配置自定义域名，使用了FastGPT内置服务的默认本地运行地址。
- 工具调用节点执行后流程停滞，无后续输出。原因是未在`variables`中配置数据库连接的必要参数，或参数格式不符合节点校验规则。
- 生成的汇编无法关联原报送文件进行在线预览。原因是工作流中未添加原文件关联节点，未抓取报送材料的附件路径信息。

## 怎么确认配好了
- 触发定时任务，查看工作流运行日志，确认所有报送部门的材料都被正常接收。
- 核对`variables`中的预设变量，确认与简报文档的固定字段一一对应，无缺失或冗余项。
- 运行工具调用节点，确认流程未出现中断，且输出结果符合预期的字段提取格式。
- 验证原文件关联节点，确认可跳转至对应报送材料的在线预览页面。
