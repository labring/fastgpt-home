# 工作简报汇编的公文辅助：模型接入与配置

## 这个品类的数据长什么样
工作简报汇编的数据来源为各业务部门报送的周度/月度工作进展、专项任务台账、现场调研记录等内部公文。更新节奏随报送周期而定，专项任务类简报随任务节点更新，常规类按月度或周度更新。单篇简报文档结构固定，包含报送单位、报送日期、核心进展、待协调事项、下一步计划五个核心字段，涉及的单位包括项、人次、万元等，汇编后为多份同类型简报的整合集合。

## 这些特征在「模型接入与配置」这一环带来什么约束
各部门报送的简报格式统一但来源分散，要求模型接入时需配置统一的文档解析规则，适配多来源的结构化字段提取。更新节奏的差异要求批量处理时支持增量同步配置，避免重复处理已收录的简报。单篇简报与汇编后的整体篇幅跨度较大，需调整上下文相关参数以适配不同长度的输入内容。固定的核心字段要求模型在信息抽取时严格匹配预设字段，不宜过度发散，需限制生成的灵活度。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 工作简报汇编的整体篇幅通常在数千token范围，需容纳多份简报的上下文信息，避免截断核心内容 |
| `maxTokens` | 2000–3000 token | 单份简报的核心内容提取与汇编后的总结输出，需控制生成长度，符合公文简报的篇幅规范 |
| `quoteMaxToken` | 4000 token | 需保留足够的原文片段用于佐证汇编内容，确保生成结果的公文规范性与可信度 |
| `temperature` | 0.2–0.4 | 工作简报需保持内容严谨准确，不宜过度发散，需限制生成的随机性，避免出现不符合公文规范的表述 |
| `AIPROXY_API_ENDPOINT` | 部署节点的专属接口地址 | 需确保模型请求的路由正确，适配国央企内部网络的访问限制，避免跨域或路由错误 |
| `AIPROXY_API_TOKEN` | 与接口绑定的专属密钥 | 需保障接口访问的安全性，避免未授权调用，符合内部系统的权限管理要求 |

## 容易做错的三处
- 批量处理多份简报时出现504超时报错，原因是未根据汇编的整体篇幅调整`maxContext`参数，导致上下文超出模型处理上限，引发请求超时。
- 对话界面与简易应用中调用的模型版本不一致，原因是未在全局配置与应用配置中分别绑定对应模型，导致不同场景下调用的模型未统一。
- 本地docker部署可访问模型，但通过OneApi转发时出现401报错，原因是未正确配置`AIPROXY_API_TOKEN`参数，转发链路中未携带合法的访问密钥，导致身份验证失败。

## 怎么确认配好了
- 上传单篇标准格式的工作简报，核对模型提取的核心字段是否与原文一致，调整参数直至抽取结果符合预设的公文格式要求。
- 发起批量汇编任务，查看任务执行日志中的上下文长度统计，确认参数配置适配当前任务的篇幅范围。
- 配置转发链路后，使用测试工具发起模型调用请求，核对返回结果是否与直接部署调用的结果一致。
- 检查接口访问日志，确认配置项的参数值未出现拼写错误或权限不匹配的情况。
