# 讲话稿与汇报材料起草的公文辅助：模型接入与配置

## 这个品类的数据长什么样
讲话稿与汇报材料起草的数据主要来自内部公文存档库、过往正式文稿模板及日常待起草的需求文档。更新节奏随起草任务触发，单次任务对应单篇文档，归档文稿按项目周期或季度更新。文档结构通常包含称谓、核心论点、数据支撑段落、落款与日期，字段包含主题、发文主体、起草日期、字数统计，单位以字符、页、字数为基础标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的文档结构固定且存在固定格式要求，要求模型输出需匹配称谓、论点分段、落款等规范，因此配置时需明确模型的格式约束参数。文档篇幅跨度较大，短则数百字符长则数万字符，需限制单轮处理的上下文长度避免超出模型阈值。内部数据来源决定需优先使用适配企业内部语料的模型渠道，同时需校验令牌权限避免无权限调用。字段包含明确的业务标识，需模型精准识别并填充对应内容，因此需调整生成温度以平衡创造性与规范性。

| `temperature` | 0.2–0.4 | 需保持公文的规范性与严谨性，避免过度偏离正式文稿风格 |
| `maxTokens` | 2000–4000 token | 单篇起草内容的常规输出长度区间，避免截断核心论证与落款信息 |
| `quoteMaxToken` | 1000–2000 token | 需保留足够的参考文档片段，为内容提供可信的内部数据支撑 |
| `toolChoice` | auto | 自动调用文档检索工具，补充内部存档的合规数据与模板参考 |
| `AIPROXY_API_TOKEN` | 填写企业专属代理令牌 | 确保模型调用的权限合法性与数据传输安全 |

## 容易做错的三处
- 现象：调用时返回「该令牌无权使用模型：text-embedding-3-large」报错。原因：未将对应模型渠道添加至FastGPT的可用分组，或令牌权限未覆盖指定模型类型。
- 现象：配置bce-embedding渠道后仍提示无可用渠道。原因：未将该渠道绑定至当前应用的模型分组，或渠道配置的接口信息未校验通过。
- 现象：创建应用时无法勾选已配置的重排模型。原因：未在全局配置中正确加载重排模型的配置项，或配置的重排模型未通过可用性校验。

## 怎么确认配好了
- 查看模型渠道列表，确认已添加的模型均显示正常可用状态，无红色报错标记。
- 发起一次测试起草任务，检查生成内容的格式是否匹配讲话稿与汇报材料的规范结构。
- 核对`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置值与官方指引一致，无字符遗漏或错误。
- 调整`temperature`参数后，观察生成内容的严谨性变化，确认参数生效。
