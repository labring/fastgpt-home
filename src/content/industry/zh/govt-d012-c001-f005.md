# 12345热线工单办理的内部办公与员工服务：工具调用与插件

## 这个品类的数据长什么样
该品类的数据来源包括12345热线平台、承办单位业务系统、内部知识库、群众回访评价数据及地方热线管理相关文档。日常产生的文档涵盖诉求登记单、派单记录、办理答复、回访记录、延期申请、退回说明与知识库条目。数据更新频率为每日，核心字段包含诉求编号、责任单位、办理时限、答复内容、回访评价等级等，整体围绕群众诉求的闭环流转进行组织。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据围绕群众诉求闭环流转且每日更新，要求工具调用需匹配工单的实时状态，避免调用过期或错误的工单数据。多类文档与字段需精准关联，工具调用需支持按诉求编号、责任单位等特定字段检索，确保数据匹配准确。由于出错会导致工单超期、答复退回或群众重复投诉，工具调用需增加校验环节，避免无效接口请求。同时，需适配不同来源的数据格式，统一处理跨系统的字段差异，保障插件调用后的数据可用性。

| `toolChoice` | `auto` 或指定业务工具名 | 适配12345工单办理中多工具联动的场景，自动匹配需要调用的插件，或指定特定工具处理对应诉求 |
| `functionCall` | 开启强制调用模式 | 确保工单办理流程中关键工具（如派单查询、知识库检索）被触发，避免遗漏必要的业务操作 |
| 超时设置 | `600 秒` | 工单办理涉及跨系统查询与数据校验，需预留足够的接口响应时间，避免因超时导致工单停滞 |
| 单次调用返回条数 | `前 3–5 条` | 工单相关数据量适中，过多会增加上下文处理负担，过少则无法覆盖完整的办理参考信息 |
| 上下文窗口大小 | `8000–12000 token` | 适配工单办理的上下文需求，容纳工具返回的多份工单数据与答复内容 |
| 插件触发规则 | 按诉求类型匹配 | 不同诉求类型需调用不同的业务系统插件，精准触发对应工具，提升处理效率 |

## 容易做错的三处
- 现象：调用飞书多维表格的HTTP插件时返回状态码400或字段为空。原因：未正确配置请求头的认证参数，或未匹配飞书多维表格的API字段格式，导致工单数据无法正确写入。
- 现象：调用MySQL工具后，大模型输出未引用数据库原文片段。原因：未开启工具调用结果的上下文拼接配置，仅返回了工具调用的原始状态，未将查询到的工单数据片段纳入上下文。
- 现象：工具调用超时或返回空结果。原因：未根据工单办理的跨系统特性调整超时设置，或未正确匹配诉求编号等核心检索字段，导致无法定位目标数据。

## 怎么确认配好了
- 发起模拟工单诉求调用，检查工具是否按诉求类型触发对应插件。
- 查看工具调用日志，确认返回的数据字段与工单文档的核心字段匹配。
- 测试异常场景（如诉求编号错误），确认工具调用返回明确的错误提示。
- 验证工具调用结果是否被纳入大模型的回答上下文，确保相关片段被正确引用。
