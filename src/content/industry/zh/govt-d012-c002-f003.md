# “高效办成一件事”联办的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据主要来源于国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库及部门审批系统，更新频率为每日。日常涉及的文档包括联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见、办结回执，数据结构以事项为核心，关联对应办理部门、材料清单、审批节点及流转状态字段，仅包含业务办理所需的标准字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
联办事项跨部门的特征要求多轮对话需完整保留跨部门的交互上下文，避免遗漏不同环节的审批要求；每日更新的业务数据要求提示词需同步拉取当日最新的联办规则与材料清单，确保信息准确性；多类表单类文档的存在要求提示词需具备字段提取与材料复用的引导能力；最耗时的部门关系拆解环节要求多轮对话需逐步梳理事项的前后置逻辑，辅助受理人员完成流程梳理。同时，联办事项的出错后果要求对话需跟踪各部门的办理状态，避免出现事项卡壳或材料重复提交的问题。

## 配置怎么定
本章节配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| :--- | :--- | :--- |
| 最大上下文窗口 | 前 15 轮对话 + 关联的`messages` | 联办事项涉及多部门流程，需保留完整的历史交互记录，`messages`参数可传递全量上下文 |
| 变量绑定规则 | 绑定`variables`中的联办事项ID、当前办理部门 | 确保提示词精准调用对应事项的清单数据，匹配实时办理状态 |
| 会话存储配置 | 按`chatId`绑定对话历史 | 避免跨会话数据混淆，确保联办流程的材料流转记录被完整保存 |
| 提示词更新频率 | 每日同步 | 匹配业务数据的日更新节奏，确保联办规则始终最新 |
| 超时设置 | 600 秒 | 适配跨部门审批的信息查询耗时，避免中途中断流程 |
| 上下文召回阈值 | 按实测标定 | 平衡跨部门数据的召回精度和响应速度 |

## 容易做错的三处
- 现象：对话历史未被保存，第二次打开会话时自动回复内容为空。原因：未正确绑定`chatId`参数，导致会话上下文未关联到对应存储节点。
- 现象：多轮对话处理联办事项时响应速度慢于工作流调试。原因：未限制上下文窗口大小，加载了过多非关联的历史交互数据。
- 现象：提示词中调用平台时间变量未生效，落款时间为空。原因：未在变量配置中指定使用系统提供的当前日期，未正确关联`variables`中的时间变量。

## 怎么确认配好了
- 发起一次联办事项咨询，查看会话界面的历史记录，确认`messages`参数已完整保存全部交互内容。
- 触发跨部门流程查询，检查提示词是否正确调用`variables`中的事项ID和办理部门信息。
- 等待24小时后，确认提示词中展示的联办清单已更新为当日最新版本。
- 模拟长耗时查询场景，验证会话在600秒内完成响应，未出现中断。
