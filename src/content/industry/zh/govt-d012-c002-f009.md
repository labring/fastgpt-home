# “高效办成一件事”联办的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库及各部门审批系统，更新频率为每日。日常处理的文档包含联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见、办结回执等，文档结构涵盖结构化表单、非结构化说明文本及带标识的图片材料，各来源文档的字段命名存在差异，覆盖事项名称、办理部门、材料要求、流转状态等核心信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的多源数据要求模型接入配置需适配跨域数据调用与实时同步需求；多样的文档结构与差异化字段，要求配置需支持多格式内容解析与灵活的结构化提取；拆解跨部门事项前后置关系、合并申请材料的核心耗时环节，要求模型上下文参数需承载足够多的关联信息；政务服务的合规要求，要求模型接入的权限配置需严格匹配数据访问范围，避免敏感信息泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 联办事项涉及多部门的事项清单、流转记录等多源数据，需承载完整的上下文信息以准确拆解办理关系 |
| `maxTokens` | 2000–3000 token | 单条联办事项的处理输出需覆盖材料复用、状态跟踪等完整说明，避免内容截断 |
| `vision` | 开启 | 需解析联办申请表、办结回执等带表单或盖章的图片材料，提取其中的结构化信息 |
| `temperature` | 0.3–0.5 | 需稳定生成联办事项的前后置关系说明与办理步骤，避免生成模糊或不一致的结果 |
| `AIPROXY_API_ENDPOINT` | 政务服务专属代理接入地址 | 适配跨部门政务数据的调用需求，保障数据传输的安全性与合规性 |
| `AIPROXY_API_TOKEN` | 绑定政务数据权限的专属令牌 | 限制模型访问范围，仅允许调用已授权的联办相关数据 |

## 容易做错的三处
- 调用多模态模型时无法解析联办申请表的图片内容，界面提示“无法识别图像内容”。原因是未开启`vision`配置项，或模型未适配政务场景的表单图片格式。
- 通过AI代理添加本地Ollama模型时返回404错误。原因是`AIPROXY_API_ENDPOINT`配置的地址未正确指向本地模型的代理转发路径，或令牌权限未覆盖本地模型调用。
- FastGPT v4.17.0中Chat模型运行正常，但Embedding模型无法连通OneAPI，OneAPI返回连接错误。原因是未针对政务服务的结构化数据调整模型接入参数，导致请求格式不符合OneAPI的校验规则。

## 怎么确认配好了
- 上传联办事项的纸质扫描件，调用多模态模型验证是否能正确提取表单中的办理部门、材料要求等字段。
- 配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`后，发起一次测试调用，验证模型能正常返回联办事项的拆解结果。
- 调整`temperature`参数后，多次调用同一联办事项的处理请求，验证输出结果的一致性。
- 模拟跨部门材料流转的场景，验证模型能正确识别事项的前后置办理关系。
