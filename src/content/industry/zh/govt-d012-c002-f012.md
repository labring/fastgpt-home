# “高效办成一件事”联办的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
该品类的数据主要来自国家政务服务平台“一件事”专区、地方一体化政务服务平台、电子证照库及各部门审批系统，更新频率为每日。日常处理的文档包含联办事项清单、一次性告知单、联办申请表、材料流转单、并联审批意见、办结回执，数据字段通常包含事项关联部门、材料复用要求、办理流转节点、办结状态标识，无额外自定义统计单位。

## 这些特征在「部署与升级」这一环带来什么约束
每日更新的跨部门政务数据要求部署环节配置稳定的数据库与缓存连接，避免因连接中断导致数据同步失败。多类型政务文档的解析需求，要求升级时保留格式兼容的预处理模块，适配清单、表单、回执等不同结构的文件。跨部门数据流转的强关联特性，要求部署时配置统一的权限校验规则，防止非授权访问敏感政务材料。同时，联办事项的办理状态依赖实时数据，升级环节需预留回滚窗口，避免更新后出现流程阻塞，影响办事进度。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | 政务内网专属MongoDB集群连接串 | 存储联办事项清单、审批意见等非结构化政务数据，内网集群可保障数据传输与存储安全 |
| `PG_URL` | 政务云PostgreSQL高可用只读副本组连接地址 | 存储高频查询的联办流程节点数据，只读副本可分担查询压力，适配每日更新的高频访问需求 |
| `REDIS_URL` | 政务云缓存实例内网地址 | 缓存电子证照的临时校验数据，降低数据库查询频次，适配每日更新的实时校验场景 |
| `STORAGE_S3_ENDPOINT` | 政务云对象存储内网端点 | 存储联办申请表、材料流转单等文件，内网访问可提升传输速度并避免公网暴露风险 |
| `DB_MAX_LINK` | `20–30 个` | 适配多部门并行查询的数据库连接需求，避免连接耗尽导致的联办流程阻塞 |
| `FE_DOMAIN` | 政务服务内网域名 | 配置前端访问地址，限定仅政务内网可访问联办办公系统，符合政务数据安全管理要求 |

## 容易做错的三处
- 现象：迁移至新服务器且不使用Docker部署时，无法启动联办办公服务。原因：未正确配置`MONGODB_URI`、`PG_URL`等环境参数，且未手动完成数据库与缓存数据的全量迁移。
- 现象：创建联办事项知识库时出现`worker terminated due to reaching memory limit`报错。原因：联办事项清单包含大量跨部门关联字段，单次加载数据量超出服务进程内存阈值，未调整`DB_MAX_LINK`限制并发连接数。
- 现象：升级至新版本后，工作流上传联办申请表报错`Failed to create post presigned url`。原因：未更新`STORAGE_S3_ENDPOINT`适配新的政务云存储配置，或文件存储密钥权限未同步更新。

## 怎么确认配好了
- 执行内置的数据库连接测试工具，验证`MONGODB_URI`与`PG_URL`可正常访问对应集群，无连接超时或权限报错。
- 上传一份标准联办申请表至系统，确认文件可正常存储并生成预览链接，验证`STORAGE_S3_ENDPOINT`配置生效。
- 启动服务后查看系统日志，确认`DB_MAX_LINK`配置的连接数未被耗尽，无频繁的连接重建或超时日志。
- 访问`FE_DOMAIN`对应的政务内网地址，确认前端页面可正常加载联办事项清单，无资源加载失败提示。
