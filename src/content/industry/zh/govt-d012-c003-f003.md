# 不动产登记的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
本品类的核心数据来自不动产登记信息系统、地籍调查数据库、房屋交易网签系统、税务系统与电子证照库，更新频率为每日。日常处理的文档包含登记申请书、权属证明、测绘成果、税费凭证、不动产权证书与登记簿，文档字段多涉及不动产单元号、权利人信息、权属来源、限制状态等结构化与半结构化内容，单份文档可包含大量关联权属的细节信息。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多系统数据来源要求多轮对话需跨数据源校验信息一致性，避免出现权属状态冲突；每日更新的数据源要求对话需实时拉取最新数据，确保核验结果准确。大体积文档与多字段内容会增加上下文处理压力，需针对性配置对话环节的资源分配。权属核验与测绘比对为核心耗时环节，提示词需聚焦关键字段的校验逻辑，同时需严格控制输出内容的严谨性，避免引发登记错误或产权纠纷。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配不动产登记类文档的字段密度，避免单块信息割裂，保障权属、测绘等关键内容的完整性 |
| 重叠长度 | 150–200 字符 | 保留跨块的不动产单元号、权利人信息等关联内容，确保多轮对话中上下文的连贯衔接 |
| 单次召回条数 | 前6条 | 覆盖日常核验所需的权属证明、测绘成果、税费凭证等核心数据类型，平衡召回效率与信息覆盖量 |
| 文件上传上限 | 1000 MB | 支持10万中文字word文档、15000行excel文件等大体积业务文件的上传与解析 |
| `chatId` 配置 | 绑定登记业务工单ID | 关联具体业务流程，实现多轮对话与工单的绑定，便于回溯与核验 |
| `messages` 参数管理 | 限制历史对话轮次为前10轮 | 控制上下文过载，避免对话输出耗时过长 |

## 容易做错的三处
- 现象：调用MCP时图片显示不全，返回结果仅显示部分内容。原因：提示词未明确指定图片资源的完整关联路径，或未在`variables`中配置图片索引参数，导致资源加载不完整。
- 现象：对话接口传文件后返回结果为空，无有效业务信息。原因：未正确绑定`chatId`与上传文件的业务标识，导致系统无法关联文件数据与当前对话上下文。
- 现象：搜索知识库后AI对话输出较慢，出现超时报错。原因：未限制`messages`参数的历史对话长度，导致上下文过载，系统处理耗时超出阈值。

## 怎么确认配好了
- 上传10万中文字word文档与15000行excel文件，检查是否能正常加载并参与多轮对话。
- 发起包含权属核验、测绘比对的多轮提问，检查返回结果是否关联了对应系统的最新数据。
- 调用对话接口时传入`chatId`参数，检查接口返回是否绑定了正确的业务工单标识。
- 调整上下文相关配置，验证不同长度的历史对话是否能正常处理，无超时报错。
