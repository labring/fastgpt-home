# 传染病信息报告与监测的内部办公与员工服务：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据主要来自中国疾病预防控制信息系统、医疗机构HIS系统、实验室检测系统，更新频率为每日。日常文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，核心字段涵盖病例基本信息、诊断结果、报告时限、订正标识等，数据需严格遵循法定传染病报告规则处理。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据接入要求接口支持适配不同系统的返回格式，每日更新节奏需保障接口调用的稳定性与低延迟。核心字段需严格匹配法定报告要求，接口参数必须覆盖病例基本信息、诊断结果、报告时限等必填项。频繁的病例订正需求要求接口支持增量同步与数据更新能力，法定报告的严肃性要求接口具备完整的错误捕获与上报机制，避免漏报迟报风险。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 请求超时时间 | 600 秒 | 适配每日批量同步疾控数据的耗时需求，避免中途中断 |
| `Authorization` | Bearer Token 格式 | 符合外部系统的身份鉴权规范，保障数据传输安全 |
| `variables` | 包含病例ID、报告日期、订正状态 | 匹配传染病报告卡的核心查询维度，精准拉取目标数据 |
| `responseData` | 结构化JSON格式 | 便于后续核对病例诊断、报告时限等字段，提升办公效率 |
| 重试次数 | 3 次 | 应对临时网络波动，降低数据同步失败概率 |
| 数据同步频率 | 每日凌晨 2 点 | 避开业务高峰时段，减少对外部系统的资源占用 |

## 容易做错的三处
- 现象：HTTP接口返回的阅读链接未携带`http://`前缀，点击后触发访问失败。原因：未在`responseData`的字段处理配置中补全协议前缀，导致链接解析不完整。
- 现象：外部系统支持TRACE请求，接口返回完整请求头信息，存在鉴权信息泄露风险。原因：未关闭外部系统的TRACE请求权限，违反HTTP安全使用规范。
- 现象：通过API调用工作流时，文本拼接后的动态变量未正常返回，仅显示固定文本。原因：未在`variables`参数中正确绑定病例订正记录的动态字段，导致API调用时无法替换变量内容。

## 怎么确认配好了
- 调用测试接口，检查`responseData`返回的字段是否包含传染病报告卡的核心信息，如病例ID、诊断结果、报告时限。
- 验证`Authorization`参数是否正确携带，调用接口后返回200状态码，无鉴权失败报错。
- 触发每日同步任务，检查是否在预设时段执行，无超时或中断日志。
- 模拟病例订正场景，调用API后确认`variables`绑定的动态字段已正确替换到文本内容中。
