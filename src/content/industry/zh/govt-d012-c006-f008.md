# 传染病信息报告与监测的内部办公与员工服务：文档解析与分块

## 这个品类的数据长什么样
本品类的典型数据来自疾控机构、医疗机构公卫科、卫生健康委疾控处的日常工作产出。日常文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，数据来源为中国疾病预防控制信息系统、医疗机构HIS和传染病报告系统、实验室检测系统，更新频率为每日。文档涵盖制式表格、长文本分析、结构化记录三类，核心字段包含法定传染病分类、病例编号、报告时限、订正说明等，无统一的非结构化格式。

## 这些特征在「文档解析与分块」这一环带来什么约束
每日更新的批量文档要求解析环节具备时效性，避免因解析延迟影响当日疫情汇总。多类型文档并存的场景要求解析工具适配制式表格与长文本的不同结构，避免拆分时丢失字段关联。核心字段的准确性直接关联疫情报告的合规性，解析环节需保留字段与文档主体的对应关系，无法容忍关键信息遗漏。不同来源的文档格式存在差异，需支持自定义解析规则以适配疾控上报的制式PDF格式，避免默认解析逻辑无法识别专用字段导致数据丢失。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 覆盖单份病例报告或订正记录的核心字段，避免拆分时切断病例信息的关联关系 |
| `chunkSplitter` | 按段落+标题分割 | 匹配流调报告、疫情分析报告的层级结构，保留报告章节的完整性 |
| `customPdfParse` | 开启 | 适配疾控上报的制式PDF文档，保留表格单元格的字段对应关系，解决制式表格识别异常问题 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对批量日更文档的解析耗时，避免单份长流调报告解析超时导致任务中断 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 容纳单份完整的聚集性疫情报告或多页流调文档 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（报告卡、分析报告）调整分块参数，适配场景需求 |

## 容易做错的三处
- 现象：上传制式传染病报告卡PDF后，解析结果中表格字段为空或错位。原因：未开启`customPdfParse`配置，默认PDF解析未保留疾控制式表格的单元格字段映射。
- 现象：批量上传当日更新的文档时，部分解析任务显示超时失败。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值过低，未适配单份长流调报告的解析耗时。
- 现象：上传多页疫情分析报告后，分块结果零散且无法关联病例订正记录。原因：`chunkSize`设置过小，拆分时切断了跨页的病例信息关联。

## 怎么确认配好了
- 上传一份标准传染病报告卡PDF，检查解析结果中是否保留了病例编号、报告日期、传染病分类等核心字段。
- 上传一份10页以上的流调报告，检查解析任务的耗时是否在`PARSE_FILE_TIMEOUT_SECONDS`设置值范围内，无超时报错。
- 开启`customPdfParse`后，上传疾控制式的PDF表格文档，验证表格单元格内容是否完整提取，无缺失或错位。
- 调整`chunkSize`至800–1200字符区间，上传疫情分析报告，检查分块是否覆盖完整的章节内容，无跨章节拆分。
