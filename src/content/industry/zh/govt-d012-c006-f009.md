# 传染病信息报告与监测的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自中国疾病预防控制信息系统、医疗机构HIS与传染病报告系统、实验室检测系统，按日更新。日常处理的文档包含传染病报告卡、疫情分析报告、病例订正记录、聚集性疫情报告、流调报告，数据字段包含病例基本信息、诊断结果、报告时限、订正状态、实验室检测结果等，每份文档关联唯一的病例标识与报告编号，数据结构需符合法定传染病报告的格式要求。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据按日更新的要求，需配置适配单日数据规模的上下文处理参数，避免因上下文溢出丢失当日汇总信息。多类型文档的结构差异，需针对不同文档预设匹配的召回规则，确保病例诊断、报告时限等核心字段被准确识别。数据来源涉及多个内部系统，需确保模型接入时的权限配置与各系统的访问规则对齐，避免数据拉取失败。法定报告的强制要求，需限制模型输出的字段范围，仅保留符合报告规范的内容，防止违规字段混入最终提交的报告中。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配单日汇总的多份传染病报告文档的总长度，避免上下文溢出 |
| `maxTokens` | `2000–3000 token` | 匹配单份传染病报告卡或流调报告的核心内容长度，确保完整生成分析片段 |
| `quoteMaxToken` | `1500 token` | 限制召回引用的文档片段总长度，避免冗余信息干扰病例核对环节 |
| `temperature` | `0.1–0.3` | 降低生成结果的随机性，确保病例诊断、报告时限等核心字段的输出符合法定报告的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接入地址，例如qwen3-embedding-8b的本地部署地址或Azure OpenAI的专属地址 | 适配不同云环境或私有部署的模型调用路径，确保请求正常路由 |
| `AIPROXY_API_TOKEN` | 按模型服务商提供的密钥与模型ID对应规则填写 | 完成模型调用的身份验证，保障数据传输安全 |

## 容易做错的三处
- 现象：模型召回的病例信息缺失报告时限字段，导致生成的疫情分析报告无法提交。原因：未配置`quoteMaxToken`限制引用片段长度，导致核心字段被截断。
- 现象：调用模型时返回401状态码，无法完成请求。原因：`AIPROXY_API_TOKEN`填写错误或过期，未完成身份验证。
- 现象：单日数据处理超时，任务执行失败。原因：`maxContext`设置过小，无法加载当日全部汇总文档，导致上下文不足触发超时。

## 怎么确认配好了
- 导入单份传染病报告卡文档，检查模型召回的引用片段是否包含病例基本信息、诊断结果与报告时限字段，确认字段覆盖范围符合要求，同时查看FastGPT各存储组件的运行状态，确认数据读写正常。
- 提交单日汇总数据测试任务，查看任务执行日志，确认模型调用请求的响应时长符合预期，未出现上下文溢出报错。
- 模拟订正病例信息的操作，检查模型生成的订正报告是否符合法定报告的格式要求，无违规字段混入。
- 更换测试用的流调报告文档，确认模型对不同类型文档的召回规则均能正常生效。
