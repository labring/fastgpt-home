# 公路养护与路产路权管理的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
公路养护与路产路权管理主体的日常数据通常来自公路养护管理系统、桥隧监测系统、路政巡查系统等多类业务系统。日常文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单，部分文档包含里程、病害等级、处置时限等结构化字段，更新频率为每日。数据结构覆盖文本记录、结构化表格与监测数值，单条文档长度差异较大。

## 这些特征在「向量模型与索引」这一环带来什么约束
多系统异构的数据来源，要求索引环节支持多格式文档的统一解析与嵌入，避免出现格式适配错误。每日更新的数据量与频率，需要配置增量索引的自动触发规则，减少全量索引的资源消耗。文档中包含的结构化数值字段，要求向量模型适配混合数据类型的嵌入，确保语义与数值信息的统一表达。单条文档长度差异大的特点，需要调整分块参数以平衡嵌入精度与索引效率，避免过长分块导致token溢出或过短分块破坏语义完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配巡查日志、病害处置单的常规内容长度，避免分块过碎或丢失语义关联 |
| 重叠长度 | 50–100 字符 | 保留相邻分块的上下文信息，确保病害描述、施工许可条款的连贯性 |
| `defaultToken` | 8192 | 匹配Qwen3-Embedding-8B模型的最大输入token限制，适配多数单文档的嵌入需求 |
| `maxToken` | 16384 | 覆盖单批次索引任务的总token上限，适配每日新增的多系统数据总量 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 区分相似路段的病害记录，避免非目标区域的文档被误召回 |
| 单次搜索上限 | 前10条 | 匹配路政执法与养护调度的快速查询需求，过滤冗余结果 |

## 容易做错的三处
- 现象：索引任务长时间停留在“索引中”状态，无进度更新或报错。原因：未正确配置本地嵌入模型的访问端口与鉴权参数，或`defaultToken`设置超出模型支持上限。
- 现象：新增嵌入模型后，原有同名模型的配置被自动覆盖。原因：仅使用模型名称作为配置唯一标识，未为不同部署实例添加后缀区分。
- 现象：召回结果中包含跨路段的无关病害记录。原因：相似度阈值设置过低，导致语义相似但路段信息不同的文档被匹配。

## 怎么确认配好了
- 上传单份标准巡查日志文档，查看FastGPT v4.17.0的索引状态是否在1分钟内更新为“已完成”。
- 输入包含具体路段编号与时间的查询语句，核对召回结果是否仅包含对应区域的业务文档。
- 查看嵌入模型的运行日志，确认`maxToken`参数被正确加载，无token溢出类报错信息。
- 在平台的模型配置页面，确认已添加的嵌入模型名称唯一，无重复的配置条目。
