# 公路养护与路产路权管理的内部办公与员工服务：工具调用与插件

## 这个品类的数据长什么样
通常涉及交通运输局、公路事业发展中心、养护单位、路政执法机构的日常办公数据，数据来源包括公路养护管理系统、桥隧监测系统、路政巡查系统、交通流量监测数据，更新频率为每日。日常文档包含养护计划、巡查日志、病害处置单、涉路施工许可、路产损坏赔偿单，文档字段包含病害位置（公里桩号）、处置时限、许可编号、赔偿金额等，无固定统一的数值标准。

## 这些特征在「工具调用与插件」这一环带来什么约束
多系统来源的数据要求工具调用需支持对接异构数据源，避免数据割裂；每日更新的特性要求工具调用需适配实时或定时同步的逻辑，保障数据时效性。多类型文档的存在要求文件上传工具需兼容多种格式，文本提取工具需支持匹配品类专属字段。最耗时的巡查识别、工单安排、涉路处理环节，要求工具调用可自动完成文档解析、工单生成等操作，减少人工干预。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，针对工具调用与插件的核心参数`toolChoice`与`functionCall`，结合品类特性制定：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配多工具并行调用的办公场景，无需手动指定单个工具函数 |
| `functionCall` | `enabled` | 支持自定义插件的函数调用逻辑，适配路政工单生成等复杂操作 |
| 文件上传默认格式 | 全部支持的格式 | 适配养护计划、巡查日志等多类型文档的批量上传需求 |
| 单次文件上传上限 | 1000 MB | 适配大体积的巡查视频、桥隧监测数据等文档 |
| 全局变量传递规则 | 绑定外部接口入参 | 满足工作流发布后外部平台传入动态工单编号、巡查日期等参数的需求 |
| 文本提取工具字段匹配 | 按养护文档预设字段映射 | 精准提取病害位置、处置单号等品类专属文档字段 |
| 工具调用重试次数 | 2-3次 | 应对数据同步临时延迟导致的调用失败 |
| 工具调用最大等待时长 | 600秒 | 适配养护数据同步的临时延迟，避免长时间阻塞流程 |

## 容易做错的三处
- 现象：文件上传工具无法识别养护类文档，MCP对接时提示格式不支持。原因：未将文件上传默认格式设置为全部支持的格式，仅勾选了部分文档类型。
- 现象：调用模型时返回空结果或报错“参数为空”。原因：未正确绑定第三方平台生成的令牌密钥，或模型配置的API地址填写错误。
- 现象：文本内容提取工具运行后提示字段提取失败。原因：未按养护文档的预设字段配置提取映射规则，错误使用通用字段匹配逻辑。

## 怎么确认配好了
- 上传一份养护计划、一份巡查日志，检查是否能正常识别并提取文档内容。
- 配置第三方平台的模型密钥后，发起一次简单的文本问答调用，确认无参数空报错。
- 编辑文本提取工具，选择养护文档的预设字段，运行测试提取，确认字段提取结果正确。
- 发布带全局变量的工作流接口，使用外部工具传入动态参数，检查接口返回是否包含传入的参数值。
