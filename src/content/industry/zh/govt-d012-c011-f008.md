# 养老、工伤、失业待遇核定的内部办公与员工服务：文档解析与分块

## 这个品类的数据长什么样
养老、工伤、失业待遇核定的日常业务文档包含待遇申领表、缴费年限证明、退休审批表、工伤认定材料、失业保险金申领材料等，数据来源为社会保险经办系统、个人权益记录、劳动关系和工伤认定系统、电子社保卡平台，更新频率为每日。文档多为制式业务表格或结构化文本，包含缴费年限、待遇标准、申领资格条件等核心业务字段，无额外自定义统计数字或法规条文。

## 这些特征在「文档解析与分块」这一环带来什么约束
每日高频更新的业务数据要求解析流程适配批量文档处理，制式化文档的固定字段结构要求分块不能断裂核心业务信息。不同类型文档的格式差异，需要解析工具兼容系统导出的标准化文本与手工填报的扫描件格式。核心字段的准确性直接关联待遇核算结果，解析分块需保留字段间的上下文关联，避免拆分后导致业务逻辑断裂。同时，批量上传的文档包可能包含多份材料，需支持批量解析的资源合理分配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 文档包含缴费年限、待遇标准等连续业务字段，避免拆分后丢失上下文关联 |
| `chunkSplitter` | 按段落+标题拆分 | 社保业务文档多带有明确的业务节点标题，保留标题与对应内容的绑定关系 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型工伤认定材料可能包含多页附件与图片，需足够时间完成完整解析 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 批量上传的待遇申领材料包可能包含多份不同类型的业务文档 |
| `customPdfParse` | 开启结构化解析 | 制式社保文档多为表格结构，结构化解析可完整提取核心业务字段 |
| `chunkSettingMode` | 手动配置 | 针对不同类型的业务文档，可灵活调整分块参数适配特定格式 |

## 容易做错的三处
- 现象：Markdown格式的待遇核定表格输出后被截断，无法完整展示申领信息。原因：未调整`chunkSize`参数，导致长表格被拆分后丢失上下文关联。
- 现象：上传包含多张工伤认定照片的docx文件后，返回结果提示Invalid image file。原因：未开启`customPdfParse`的图片关联解析，或未适配社保文档中的内嵌图片格式。
- 现象：知识库解析日志持续报slow operation xxxxms，MongoDB响应正常。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置过短，大型缴费年限证明文档未完成解析即超时。

## 怎么确认配好了
- 上传单份制式待遇申领表，检查解析后的文本是否完整保留缴费年限、申领金额等核心字段。
- 上传包含多张内嵌图片的工伤认定材料，确认解析结果中图片关联的文字说明未丢失。
- 批量上传10份同类型文档，检查解析耗时是否符合预设的`PARSE_FILE_TIMEOUT_SECONDS`阈值。
- 查看FastGPT v4.17.0的解析日志，确认无slow operation相关报错。
