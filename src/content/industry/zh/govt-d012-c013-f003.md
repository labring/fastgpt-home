# 内控评价、审计与整改的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据的生成主体为中央企业内控部门、审计部、财务部、下属企业及外部审计机构，数据来源包括企业内控系统、ERP、财务共享系统、审计管理系统及采购合同项目系统。日常产生的文档涵盖内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据更新频率为年，核心字段包含问题描述、整改措施、责任主体、完成时限、佐证材料标识等，文档多为结构化表格与非结构化报告结合的格式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类数据更新频率为年，多轮对话上下文无需频繁触发全量数据刷新，可通过固定上下文缓存降低调用开销。文档包含结构化表格与非结构化报告，提示词需分别适配字段提取（如整改台账的责任主体、完成时限）和文本摘要（如审计工作底稿的问题提炼）。核心耗时环节集中在样本抽取、问题形成与整改跟踪，多轮对话需按业务流程拆分交互节点，避免单次输入过载。数据关联多系统来源，对话中需明确提示用户补充对应系统的文档标识，确保检索范围准确。同时，由于出错后果涉及监管通报与责任追究，多轮对话需增加校验环节，确保输出内容与企业预设数据一致。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 适配年度更新的全量文档总长度，避免超出上下文阈值 |
| 单次对话最大回复token | 2000–3000 token | 匹配整改台账、审计底稿的单段内容长度，确保完整输出整改要求 |
| 变量绑定 | 开启 | 绑定`variables`参数关联系统预设字段，快速调用整改责任主体、完成时限等数据 |
| 多轮对话历史保留时长 | 7天 | 适配审计项目的常规周期，保留历史交互记录用于整改跟踪回溯 |
| 附件上传大小限制 | 100 MB | 匹配审计工作底稿、自评报告的常规文件体积，避免大文件传输报错 |
| 历史消息同步 | 开启 | 启用`messages`参数同步会话历史，确保多轮交互的上下文连贯 |

## 容易做错的三处
- 现象：上传审计工作底稿、整改台账等附件时提示fail to create post presigned url，或RAG上传文件失败，模版导入功能正常。原因：升级版本后S3存储配置的签名参数未同步更新，或附件上传大小限制设置低于当前上传文件的实际体积。
- 现象：多轮对话中无法正确提取整改台账的责任主体字段。原因：提示词未明确区分结构化文档与非结构化文档的提取规则，未绑定`variables`参数关联预设系统字段。
- 现象：多轮对话会话中断后，后续交互无法关联历史上下文。原因：未启用`chatId`参数自动生成会话标识，或历史消息同步配置未开启。

## 怎么确认配好了
- 上传单份100 MB以内的审计工作底稿，确认无上传报错。
- 发起多轮对话，输入提取审计问题清单的指令，核对返回结果包含预设的问题描述、整改措施字段。
- 验证多轮对话的上下文连贯性，确认历史交互记录随会话保留。
- 查看`chatId`参数是否随新会话自动生成，确保每次交互的会话标识唯一。
