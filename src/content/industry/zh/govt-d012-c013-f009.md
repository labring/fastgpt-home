# 内控评价、审计与整改的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
数据来源包括企业内控系统、ERP、财务共享系统、审计管理系统、采购合同项目系统。日常生成的文档包含内控自评报告、审计通知书、审计工作底稿、问题清单、整改台账、整改销号证明。数据更新频率为年，单份文档包含问题标识、整改措施、责任主体、佐证材料关联等字段，不同文档间存在关联关系。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源覆盖多类企业内部系统，接入配置需适配多数据源的接口校验，避免跨系统数据格式不匹配。数据更新频率为年，模型上下文缓存无需高频刷新，可按年度批次配置数据加载。日常文档包含多类结构化与非结构化内容，配置时需适配不同文档的字段解析规则，比如问题清单与整改台账的关联提取。业务最耗时环节涉及长文本抽取与整改要求生成，模型配置需调整相关参数，确保长文档处理的稳定性，避免因参数不足导致关键信息丢失。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多份关联文档的上下文覆盖需求，满足年度更新的内控与审计文档的整体上下文长度 |
| `maxTokens` | 4000–6000 token | 适配整改台账、审计工作底稿等长文档的单轮生成需求 |
| `temperature` | 0.3–0.5 | 平衡问题清单、整改要求的生成准确性，避免过度发散 |
| `toolChoice` | 自动 | 适配审计问题抽取、整改建议生成需要调用工具的场景 |
| `quoteMaxToken` | 1000–1500 字符 | 确保从文档中引用的佐证材料内容完整，不截断关键信息 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的模型服务地址填写 | 适配企业内部模型服务的对接需求 |

## 容易做错的三处
- 调用内置工具“获取当前时间”时，模型流响应为空，界面显示模型流输出为空。原因是未正确配置`toolChoice`参数，或未正确填写`AIPROXY_API_TOKEN`，导致模型服务无法正常返回流输出。
- 配置ollama部署的deepseek模型时，模型思考设置不生效，生成内容未使用deepseek的原生思考逻辑。原因是未正确设置模型接入的参数适配，或未开启模型的思考模式开关，导致平台无法调用模型的思考能力。
- 在工作流中尝试将前一个AI模型的输出更新为空值，变量更新操作未生效，变量值未被清空。原因是未正确配置变量更新的触发时机，或变量作用域设置错误，导致变量无法正常更新。

## 怎么确认配好了
- 发起一次测试调用，输入单份审计工作底稿，查看模型生成的整改建议，确认`maxTokens`和`quoteMaxToken`的取值适配文档长度。
- 调用内置工具，查看工具返回结果是否符合预期，确认`toolChoice`参数配置生效。
- 查看模型上下文加载的文档内容，确认`maxContext`配置覆盖了所需的关联文档信息。
- 检查模型服务的接口返回状态，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`配置正确。
