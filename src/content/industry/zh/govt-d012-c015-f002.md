# 医保基金监管稽核的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
本品类的典型主体为医保局基金监管处、医保经办机构、飞行检查组及定点医药机构。日常处理的文档包含稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书、整改报告等。数据来源涵盖医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索，更新频率为月度。核心业务耗时环节为从结算数据中筛选疑点、调阅病历处方和收费记录、认定违规费用并形成处理意见，操作失误将引发基金损失、追回拒付、暂停协议或行政处罚。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的频率决定了无需构建实时索引，可采用定期全量或增量索引的方式降低资源消耗。多源异构的数据类型，包含结构化结算数据、非结构化文档及追溯码信息，要求向量模型需适配混合格式的文本与编码数据。核心业务耗时环节依赖快速召回关联规则与历史稽核案例，因此索引的召回效率与准确率直接影响整体业务进度。文档长度差异较大，从简短的疑点清单到长篇的检查工作底稿，需合理配置分块逻辑以保留语义完整性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配稽核通知书、检查工作底稿等常规文档的语义完整性要求 |
| 重叠长度 | 100–200 字符 | 避免跨块语义断裂，适配长文档的上下文连贯性 |
| 相似度阈值 | 按实测标定 | 需匹配稽核场景下的疑点关联精度要求 |
| 单次搜索上限 | 前10条 | 平衡召回效率与稽核所需的关联数据量 |
| `maxToken` | 4096 token | 适配医保规则库、结算数据的文本长度限制 |
| `defaultToken` | 2048 token | 满足日常稽核查询的上下文输入需求 |

## 容易做错的三处
- 现象：配置向量模型后出现参数校验报错，原因是未根据稽核场景的文本数据类型选择适配的向量模型，误启用非必要的多模态处理逻辑。
- 现象：索引构建耗时超出预期，原因是未按照月度更新频率设置增量索引任务，直接执行全量索引且未限制单次处理的数据源规模。
- 现象：docker-compose部署环境下无法触发索引任务，原因是未在docker-compose配置文件中开放向量服务的端口映射，导致索引流程无法正常调用模型接口。

## 怎么确认配好了
- 上传一份稽核通知书样本，查看分块后的文本片段是否保留完整的语义单元，无明显断句断裂。
- 发起一条疑点查询，检查返回的搜索结果条数符合单次搜索上限的设置值，且关联内容与稽核疑点高度相关。
- 查看索引任务的日志，确认任务在设定的月度更新周期内正常完成，无超时报错。
- 验证`maxToken`与`defaultToken`的配置是否匹配当前使用的向量模型的输入长度限制。
