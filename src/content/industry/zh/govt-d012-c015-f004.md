# 医保基金监管稽核的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
该品类的数据来源包括医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索。日常生成稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书与整改报告。数据更新频率为月度，核心字段涵盖结算明细、违规疑点标记、监管规则匹配结果，文档以结构化表格与文本附件结合的形式呈现。

## 这些特征在「工作流编排」这一环带来什么约束
月度更新的数据规模较大，工作流需支持批量调用医保结算数据接口，避免单次请求超时。多类型文档的混合处理要求工作流配置支持文本解析与结构化数据提取节点的顺序编排。监管规则的匹配需前置校验，工作流需将规则库加载节点放在疑点筛选环节之前。跨部门协作的流程要求工作流支持节点权限分配与审批环节的串行编排，确保稽核流程符合内部办公规范。同时，针对单环节耗时较长的疑点筛选、病历调阅步骤，需配置节点超时重试机制，防止流程中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 初始值设为「待稽核批次号：空，规则匹配状态：未完成」，后续节点按执行结果更新 | 匹配医保稽核的批次管理需求，为跨节点数据传递提供统一变量容器，符合FastGPT v4.17.0版本的变量使用规范 |
| 节点超时设置 | 300–600 秒 | 匹配医保结算数据调取、病历调阅的平均耗时区间，避免流程因单次请求超时中断 |
| `nodeId` | 按节点功能命名，如「data_filter」「rule_match」「approval_check」 | 便于工作流调试与后续版本迭代时快速定位节点 |
| 疑点结果筛选 | 取前 100 条 | 匹配稽核工作的初步排查需求，避免过多无效数据占用流程资源 |
| 文本解析节点字符限制 | 800–1200 字符 | 匹配医保相关文档的单段平均长度，提升解析效率 |
| 变量更新触发 | 按节点执行完成自动触发 | 确保跨节点的变量传递及时生效，避免因手动更新导致的流程异常 |

## 容易做错的三处
-  现象为工作流中`variables`配置的初始值未加载，全局变量更新后流程节点未读取到更新后的数据。原因是未启用节点的变量自动更新配置，或变量未正确绑定至对应节点的输入参数。
-  现象为工作流发起提问后，工具调用节点直接返回报错，无执行日志。原因是未配置工具调用的前置权限校验，或节点依赖的医保接口未添加至工作流白名单。
-  现象为问题分类分支执行完成后，HTTP请求节点未触发执行，流程直接跳转至结束节点。原因是未配置分支合并节点，未将两个分类分支的输出统一接入HTTP请求节点。

## 怎么确认配好了
-  进入工作流调试界面，手动输入`variables`的初始测试值，运行流程后查看节点输入参数是否正确加载。
-  触发工作流执行，查看节点日志，确认HTTP请求节点的超时时间符合预设区间，无超时报错。
-  修改工作流配置后，重新发布至对应渠道，确认发布渠道的流程逻辑已同步更新。
-  模拟稽核流程的分支场景，确认分类分支执行完成后，HTTP请求节点正常触发执行。
