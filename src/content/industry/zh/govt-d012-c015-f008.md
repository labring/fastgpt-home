# 医保基金监管稽核的内部办公与员工服务：文档解析与分块

## 这个品类的数据长什么样
本品类服务主体为医保局基金监管处、经办机构及飞行检查组，日常处理的文档包括稽核通知书、检查工作底稿、疑点清单、约谈记录、处理决定书及整改报告。数据来源涵盖医保智能监控系统、基金监管规则库、医保结算数据、药品耗材追溯码及举报线索，更新频率为月度。文档包含结构化字段与非结构化文本，部分为扫描件与电子导出数据混合格式。

## 这些特征在「文档解析与分块」这一环带来什么约束
月度更新的批量数据要求解析流程具备稳定的批量处理能力，避免单次解析超时中断。多类型文档的混合场景要求分块逻辑适配不同结构，既需保留稽核通知书的层级标题关联，也要准确提取约谈记录中的口语化疑点表述。扫描版整改报告与追溯码文档的混合格式，需要适配非标准PDF解析逻辑。事后稽核的回溯需求要求分块保留上下文关联，确保单块内容可独立关联具体违规疑点，同时避免冗余分块增加后续处理耗时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配稽核类文档的段落长度，覆盖单条违规疑点或处理意见的完整表述 |
| `chunkSplitter` | 按段落+标题分割 | 匹配稽核文档的层级结构，保留通知书、工作底稿的标题与正文关联 |
| `customPdfParse` | 启用 | 处理扫描版整改报告、药品耗材追溯码导出文档，提升非标准PDF解析准确率 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配单批次专项检查的多份大体积PDF稽核档案，避免上传中断 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 匹配月度批量解析的时长要求，避免大文件解析超时 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（如约谈记录、结算数据导出表）调整分块参数 |

## 容易做错的三处
- 上传大体积PDF至90%进度时出现“偏移量超出范围”报错，原因是未调整`UPLOAD_FILE_MAX_SIZE`配置，或未启用`customPdfParse`处理扫描版PDF的内部偏移问题。
- 调用创建文件集合API上传的文件与平台直接上传的分段结果不一致，原因是未统一配置`chunkSplitter`和`chunkSize`参数，API调用默认分块规则与界面配置未同步。

## 怎么确认配好了
- 上传单份100MB以上的专项稽核PDF，检查上传进度是否完整完成，无偏移量相关报错。
- 分别通过界面和API上传同一份约谈记录文档，对比分块结果的起始和结束位置是否一致。
- 查看解析日志，确认`PARSE_FILE_TIMEOUT_SECONDS`配置未触发超时中断提示。
- 启用`customPdfParse`后，上传扫描版整改报告，检查是否提取到文档内的疑点标注内容。
