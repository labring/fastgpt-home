# 医保费用结算审核的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据来自全国医疗保障信息平台、医院HIS和医保接口、医保目录和编码库、异地就医结算平台，更新频率为每日。日常处理的文档包含医保结算清单、费用明细、病案首页、处方、拒付清单、结算对账单，核心字段覆盖诊疗项目与药品耗材编码、费用金额、参保人身份标识、结算状态与拒付原因等，用于经办支付前后的日常结算审核业务。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据每日更新且来源多样，提示词需定期同步最新医保目录与编码库，避免出现编码匹配失效的情况。多份关联文档需按对话顺序传递，确保审核流程中能依次核对费用明细与处方、结算清单的一致性。单笔或批量结算数据的字段差异，要求多轮对话逐步引导补充缺失信息，比如先确认结算批次编号再调取对应明细。拒付清单的对账需求，要求对话上下文保留历史拒付记录，避免重复审核或遗漏申诉信息。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `messages` 上下文配置 | 按对话顺序传递最新10轮交互内容 | 保留参保人身份、既往拒付记录等审核所需的历史信息，避免上下文截断 |
| `variables` 绑定配置 | 绑定医保目录编码库、结算规则库 | 为多轮对话提供实时匹配的标准化数据，确保编码审核的准确性 |
| `chatId` 会话配置 | 绑定专属会话ID | 区分不同参保人或结算批次的审核流程，避免上下文混淆 |
| 单次输入文档数量 | 前5份 | 匹配日常单笔或批量结算的文档处理范围，避免过载 |
| 超时阈值 | 600秒 | 适配批量结算审核的处理时长，避免因数据调取延迟中断流程 |
| 上下文窗口长度 | 8000–12000 token | 覆盖单批次结算审核的全部关联文档与对话历史，避免截断关键编码与金额信息 |

## 容易做错的三处
- 现象：调用多模态对话接口时返回400 invalid image报错，无有效回答。原因：未对上传的医疗单据图片进行格式校验，或图片分辨率超出接口支持范围。
- 现象：编排的工作流在FastGPT调试界面正常运行，对接外部对话平台后仅能触发第一个对话节点，无法响应后续交互。原因：未正确配置`chatId`的会话传递逻辑，导致跨平台会话上下文丢失。
- 现象：本地部署的FastGPT通过中转接口连接自定义模型后，对话界面自动切换为内置模型，无法正常调用目标模型。原因：未在应用配置中锁定目标模型标识，导致平台默认调用内置模型。

## 怎么确认配好了
- 上传单份医保结算清单与关联处方，测试多轮对话能否依次调取并核对编码与金额信息，确认上下文未被截断。
- 模拟批量结算审核场景，传递多份文档，检查对话流程是否能按顺序处理每一笔费用的审核逻辑。
- 触发超时测试，确认在预设阈值内完成审核流程，无中断报错。
- 核对`variables`绑定的知识库，确认医保目录编码库的更新时间与官方数据来源一致。
