# 医疗机构监督与公共卫生检查的内部办公与员工服务：工具调用与插件

## 这个品类的数据长什么样
本品类数据主要来自卫生监督信息系统、医疗机构电子化注册系统、投诉举报平台及执法检查记录，更新频率为每月一次。日常处理的文档包括监督检查表、医疗机构执业许可证、整改通知书、监督意见书与处罚案卷，数据字段包含机构主体名称、许可编号、检查事项、整改要求、处罚关联信息等，所有字段均为政务合规类标准格式，无自定义单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据更新频率为月度，因此工具调用的缓存有效期需匹配该周期，避免返回过期的机构资质、整改状态等核心信息。政务类文档的标准化格式要求工具调用时需严格对齐官方字段名，防止参数不匹配导致的调用失败。多来源的数据需要工具支持跨系统调取，整合卫生监督、医疗机构注册等不同平台的信息，同时需校验数据来源的合规性，保障调用结果的权威性。现场执法环节的实时需求要求工具调用的响应速度需适配外勤场景的网络波动环境。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `"auto"` | 自动适配多来源数据的调用场景，无需手动指定工具 |
| 工具调用超时时间 | 30–60 秒 | 适配外勤执法的网络波动环境，按实测标定 |
| 单次返回结果条数 | 前 3–5 条 | 聚焦机构资质、整改状态等核心政务信息，避免结果过载 |
| 上下文窗口大小 | 2000–3000 token | 承载执法记录、整改通知书等完整文档内容 |
| `functionCall` 校验模式 | 严格模式 | 确保调用参数与政务文档的标准字段严格对齐 |
| 插件授权范围 | 仅限内部政务系统域名 | 保障数据调用的合规性，防止越权访问 |

## 容易做错的三处
- 现象：工具调用返回`{"result": "Failed to get the VQD for query \"<检索词>\"."}`。原因：未针对卫健监督场景过滤非合规查询关键词，使用了与政务业务无关的内容触发工具。
- 现象：收到`400 <400> InternalError.Algo.InvalidParameter`报错。原因：未开启`functionCall`的严格校验模式，传入的参数与政务文档的标准字段格式不匹配。
- 现象：对话应用调用插件后无响应。原因：未配置插件的授权访问范围，导致外部网络无法调用内部政务系统的接口。

## 怎么确认配好了
- 发起针对医疗机构资质查询的测试请求，核对工具返回的字段与卫生监督信息系统的标准格式是否匹配。
- 触发工具调用，确认返回结果的数量符合预设的取值范围，验证单次调用配置生效。
- 提交测试查询，查看工具调用的响应时间是否在预设的超时范围内，确认超时配置生效。
- 检查插件的授权配置，确认仅允许内部政务系统的域名发起调用，保障合规性。
