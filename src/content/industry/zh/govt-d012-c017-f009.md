# 医疗机构监督与公共卫生检查的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自卫生监督信息系统、医疗机构电子化注册系统、投诉举报平台及执法检查记录。日常处理的文档包含监督检查表、医疗机构执业许可证、整改通知书、监督意见书、处罚案卷。数据更新频率为月度，核心字段覆盖机构资质信息、现场检查记录、整改跟踪情况、处罚案卷详情，文档结构多为结构化表单与非结构化文书结合，需同时适配字段提取与自然语言理解场景。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的批量数据，要求模型接入配置适配批量任务的上下文承载上限，避免单次处理超时。混合的结构化表单与非结构化文书，需要配置兼顾字段提取与自然语言理解的参数，适配不同文档格式的解析需求。执法检查记录等非结构化数据的处理，要求配置支持长文本解析与多模态适配。多来源数据的格式差异，需要配置适配跨系统数据接入的参数，减少格式转换的额外开销。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配月度批量的监督检查表、处罚案卷等长文本数据 |
| `maxTokens` | 2000–3000 token | 满足监督意见书、整改通知书的生成与解析需求 |
| `quoteMaxToken` | 1000–1500 token | 限制引用文档的单段长度，避免上下文溢出 |
| `temperature` | 0.3–0.5 | 保证资质核对、整改跟踪等任务的输出一致性 |
| `AIPROXY_API_ENDPOINT` | http://127.0.0.1:8000/v1 | 适配私有化部署需求，保障卫生健康数据不出本地 |
| `AIPROXY_API_TOKEN` | 本地生成的32位随机密钥 | 限制非授权访问，符合数据安全规范 |

## 容易做错的三处
- 本地部署QWQ-32B模型后，聊天窗口上传附件无响应，简单应用与工作流应用均无效果。原因是未正确配置`AIPROXY_API_ENDPOINT`指向本地模型路径，或未开启`vision`参数适配附件解析。
- 模型输出无法自动转化为文档。原因是未配置对应工具链的触发规则，或未指定输出格式的适配参数。
- TTS模型调用失败，无法生成语音化的监督文书。原因是未配置正确的私有化部署API端点，或密钥权限不足导致无法访问TTS服务。

## 怎么确认配好了
- 上传单份不超过5000字符的监督检查表，验证模型能否准确提取机构名称、执业地址、有效期限等核心字段，核对提取结果与原文档一致。
- 发起月度批量监督数据的处理任务，验证任务未出现超时报错，输出的整改跟踪记录与检查结果匹配。
- 调用本地部署的模型，验证API请求能正常返回响应，无连接超时或权限错误提示。
- 配置TTS模型后，生成单份监督意见书的语音输出，验证语音内容与文本内容完全匹配。
