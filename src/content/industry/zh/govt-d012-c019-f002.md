# 双随机、一公开监管检查的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
通常覆盖市场监管、住建、生态环境等监管部门的内部办公场景，日常文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示。数据主要来源于“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库，更新频率为月度。单份文档的内容跨度较大，既有结构化的名单类条目，也有非结构化的现场记录与公示文本，字段包含检查对象统一社会信用代码、执法人员编号、检查事项细则等。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的频率要求索引需支持增量同步，避免全量重建带来的资源消耗。多类型文档的混合存在，需要适配结构化与非结构化内容的分块策略，确保检查事项、对象信息的语义完整性。多来源的数据需要统一字段映射规则，避免不同系统导出的同类型文档出现索引格式差异。同时，监管场景对召回准确性要求较高，需避免漏索引或重复索引带来的执法合规风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配该品类日常文档（检查记录、整改通知书）的平均内容长度，避免分块过碎破坏语义连贯性 |
| 重叠长度 | 100–200 字符 | 保留跨分块的上下文关联，确保检查对象名称、执法人员信息等关键内容不被割裂 |
| `defaultToken` | 8192 | 适配主流向量模型的输入长度上限，覆盖单份抽查计划的完整内容 |
| `maxToken` | 16384 | 支持批量索引时的长文本处理，满足月度更新的全量文档索引需求 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的关联内容，避免重复匹配同一检查对象的历史记录 |
| 单次搜索上限 | 前10条 | 平衡召回效率与准确性，适配执法人员快速匹配检查任务的日常办公需求 |

## 容易做错的三处
- 现象：索引合并后出现重复的检查对象条目，原因：未针对执法人员名录库、检查对象名单设置全局去重规则，导致同一条目多次被索引。
- 现象：调用向量模型时返回401错误，原因：未正确配置向量模型的访问密钥，或自定义渠道未正确绑定向量模型类型。
- 现象：触发检索后未召回最新的抽查结果公示内容，原因：未按照月度更新频率配置增量索引任务，导致新生成的公示文档未被同步纳入索引库。

## 怎么确认配好了
- 导入单份检查对象名单文档，查看索引列表中是否存在重复条目，验证去重配置是否生效。
- 发起针对“2024年第一季度抽查计划”的检索，确认返回结果包含对应文档的正确分块内容。
- 测试向量模型调用，确认返回正常的嵌入结果，无401类报错。
- 触发月度增量索引任务，查看FastGPT v4.17.0的任务日志确认新生成的整改通知书、公示文档已被成功索引。
