# 双随机、一公开监管检查的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
通常服务于市场监管、住建、生态环境、文旅、人社等监管部门，日常产生抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示等文档。数据主要来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库，更新频率为月度。数据字段包含监管对象统一社会信用代码、执法人员编号、检查事项类别、检查结果状态等，无额外非业务要求的统计字段。

## 这些特征在「工作流编排」这一环带来什么约束
月度更新的数据源要求工作流配置定期同步任务，确保检查对象与执法人员信息为最新版本。多类文档的流转需要明确节点权限，区分计划制定、名单抽取、现场记录、结果公示等环节的操作主体，避免越权操作。不同来源的数据格式存在差异，需要工作流配置统一的格式转换节点，确保各环节可正常读取数据。抽查结果公示需严格遵循流程顺序，前置环节未完成则无法触发后续操作，避免出现漏公示或不合规抽取的情况。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量 | 绑定`variables`为监管对象ID、执法人员编号 | 用于跨节点传递检查核心数据，确保各环节数据一致 |
| 节点触发条件 | 按`nodeId`绑定的上一节点完成状态触发 | 确保工作流按抽查计划、名单抽取、现场检查的顺序执行 |
| 数据同步周期 | 按实测标定，通常为每月1日0点 | 匹配数据月度更新频率，避免使用过期的检查对象与执法人员信息 |
| 操作权限 | 按执法岗位划分节点操作范围 | 区分计划制定、现场记录、结果公示等环节的操作主体，符合内部办公规范 |
| 超时阈值 | 600秒 | 覆盖现场检查记录上传、跨系统数据同步等常规操作的耗时上限 |

## 容易做错的三处
- 工作流执行时出现“字段为空”报错，现象为检查对象名单节点输出无有效数据。原因是未配置`variables`绑定月度更新的监管对象数据源，导致节点无法读取对应数据。
- 工作流节点触发顺序混乱，现场检查记录节点提前于名单抽取节点执行。原因是未按`nodeId`绑定正确的前置节点触发条件，导致流程逻辑颠倒。
- 抽查结果未完成公示流程，出现漏公示情况。原因是未配置结果公示节点的触发条件依赖检查记录完成状态，导致流程跳过必要校验环节。

## 怎么确认配好了
- 核对`variables`绑定的数据源，确认包含监管对象统一社会信用代码、执法人员编号等核心字段，且更新频率与业务要求一致。
- 测试工作流触发逻辑，依次执行计划制定、名单抽取、现场记录等节点，确认每个节点仅在前置节点完成后才启动。
- 模拟输入过期的监管对象信息，确认工作流触发对应校验规则并阻断后续流程。
- 查看节点运行日志，确认所有数据流转环节均能正常读取和处理对应文档内容。
