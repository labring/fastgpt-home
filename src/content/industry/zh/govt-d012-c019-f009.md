# 双随机、一公开监管检查的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
该品类的数据通常来自“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库，更新周期为月度。日常文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书与抽查结果公示，核心字段包含监管对象统一社会信用代码、执法人员编号、检查事项条目、整改完成状态等，单份文档体量覆盖数十到数千字符区间。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据要求模型接入环节支持定期全量数据同步与增量更新，避免因数据滞后导致监管任务偏差。多类型文档的混合输入需要配置适配结构化清单与非结构化记录的解析规则，确保字段提取的准确性。监管对象与执法人员的精准匹配要求模型调用时保留字段级关联逻辑，防止抽取偏差引发检查不合规。抽查结果公示的合规性要求模型输出内容严格对应原始文档字段，不得随意篡改或遗漏关键信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 容纳月度更新的多份监管文档与执法记录，避免上下文截断导致字段关联丢失 |
| `maxTokens` | `4000–6000 token` | 单轮生成检查任务或公示内容时，覆盖完整的检查事项与对象信息 |
| `quoteMaxToken` | `2000–3000 token` | 保留关键文档片段的完整引用，避免截断导致的监管信息缺失 |
| `toolChoice` | `auto` | 支持自动调用工具完成执法人员匹配、数据公示校验等监管流程 |
| `temperature` | `0.1–0.3` | 适配监管场景的严谨性要求，降低随机化输出引发的合规风险 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写官方代理地址 | 适配FastGPT v4.17.0版本的代理调用链路，确保请求正常转发 |
| `AIPROXY_API_TOKEN` | 填写部署生成的专属令牌 | 保障模型调用的身份验证安全，防止未授权访问 |

## 容易做错的三处
- 现象：导入检查对象名单后，模型无法准确匹配执法人员与检查事项。原因：输入文档未采用结构化格式，导致字段解析混乱，无法提取精准关联信息。
- 现象：使用Qwen2.5模型通过Ollama部署时，无法触发工具调用，询问指定监管任务无响应。原因：未正确配置`toolChoice`参数为`auto`，或代理链路未开放工具调用权限。
- 现象：仅升级FastGPT镜像后，原有的月度数据同步任务失败。原因：未同步更新关联组件，导致模型调用链路中断，无法正常拉取监管数据。

## 怎么确认配好了
- 执行单次抽查计划生成测试，核对输出内容是否包含完整的检查对象、执法人员及事项清单，无字段遗漏。
- 触发月度数据同步任务，检查向量库更新日志是否显示所有月度文档均已成功加载，无报错信息。
- 发起工具调用测试，验证模型能否自动匹配执法人员与检查对象，输出结果符合监管业务逻辑。
- 查看模型调用监控面板，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置无异常，请求状态正常。
