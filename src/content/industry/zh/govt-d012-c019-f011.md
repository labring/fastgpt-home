# 双随机、一公开监管检查的内部办公与员工服务：表单与交互
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
该品类的日常文档包含抽查计划、检查对象名单、检查事项清单、现场检查记录、整改通知书、抽查结果公示。数据来源为“双随机、一公开”监管平台、企业信用信息公示系统、行业监管系统及执法人员名录库，更新频率为月度。字段多包含监管对象统一社会信用代码、执法人员编号、检查事项条目、整改时限等，单位多为条、人次、工作日。典型使用主体为市场监管、住建、生态环境、文旅、人社等监管部门。

## 这些特征在「表单与交互」这一环带来什么约束
月度更新的数据源要求表单支持批量导入与增量同步功能，避免重复录入月度更新的检查对象与执法人员数据。多字段的文档结构需要表单按检查准备、现场执行、结果公示三个业务环节分块展示，防止单页表单过长导致操作失误。执法人员名录库的跨数据源调用需求，要求表单集成人员选择组件，确保抽取的执法人员符合监管要求。检查结果公示的必填字段配置，需严格匹配公示要求，避免出现漏公示问题。批量生成抽查任务的高频需求，要求表单支持批量提交与状态批量更新，适配月度监管工作节奏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 按业务环节分块配置，单块不超过10个字段 | 适配多字段的检查文档结构，避免表单过长导致操作失误 |
| `userSelect` | 关联执法人员名录库数据源，开启跨库匹配校验 | 确保执法人员抽取符合监管要求，避免抽取不合规 |
| `formInput` | 开启统一社会信用代码格式校验 | 防止检查对象信息录入错误，避免后续公示出错 |
| 批量导入上限 | 单次导入不超过500条数据 | 适配月度更新的数据源规模，避免导入超时 |
| 状态流转配置 | 按检查准备→现场执行→结果公示设置节点 | 匹配日常业务的工作流程，便于员工跟进任务进度 |
| 消息通知触发 | 任务状态变更时推送通知至内部办公渠道 | 及时提醒执法人员处理待办事项，提升协作效率 |

## 容易做错的三处
- 现象：配置内部办公渠道接入时提示“接收消息地址校验失败”，原因：未将服务部署至公网可访问的环境，或未正确配置SSL证书校验规则。
- 现象：批量导入检查对象名单时出现部分数据未被识别，原因：导入文件的字段顺序与表单预设的映射规则不一致，或存在格式错误的统一社会信用代码。
- 现象：生成抽查任务时出现执法人员匹配失败，原因：未关联执法人员名录库数据源，或名录库数据未完成月度更新导致无可用人员。

## 怎么确认配好了
- 手动导入单条包含正确统一社会信用代码的检查对象数据，校验系统是否触发格式合规提示。
- 调用执法人员名录库数据源，尝试选择2名执法人员并生成测试任务，确认匹配结果无误。
- 模拟任务从检查准备节点流转至结果公示节点，确认内部办公渠道是否收到状态变更通知。
- 测试批量导入50条检查对象数据，确认导入成功且所有数据完整同步至系统。
