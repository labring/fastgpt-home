# 国土空间规划编制与实施评估的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
这个品类的日常文档包括国土空间总体规划、详细规划、专项规划、规划实施评估报告、公众意见汇总。数据主要来自国土空间基础信息平台、自然资源调查监测数据、人口经济统计、遥感影像，更新频率为每年一次。文档多包含空间坐标、约束指标、部门协调意见等字段，兼具文本与空间数据特征。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据兼具文本与空间属性，且更新频率固定为每年一次，向量索引需支持批量加载多源异构数据，适配年度全量更新的节奏。日常文档的文本量差异较大，会影响分块策略的合理性，需平衡分块长度与上下文完整性。多源数据来源分散，需统一数据格式以避免字段缺失导致的索引异常。规划类数据对准确性要求较高，索引召回结果需与原始数据严格对应，避免匹配偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类单份文档的平均文本密度，平衡上下文完整性与分块粒度 |
| 重叠长度 | 100–200 字符 | 避免分块边界截断关键空间指标或约束条款，确保语义连贯性 |
| `maxToken` | 8192 token | 适配主流开源嵌入模型的输入长度限制，匹配规划文档的分块语义长度 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关规划内容，避免检索结果冗余 |
| 单次搜索上限 | 前10条 | 控制内部办公场景下的检索结果数量，适配员工快速查阅的需求 |
| `defaultToken` | 512 token | 用于默认分块的上下文填充，适配短文本类的公众意见汇总数据 |

## 容易做错的三处
- 手动插入的规划文档生成的默认索引数小时后消失：原因是未将手动插入的文档绑定至持久化索引集，系统默认的临时索引缓存周期到期后自动清理。
- 接入qwen3-embedding-8b后文件状态一直显示索引中：原因是未在FastGPT v4.17.0中调整嵌入模型的调用等待时长，该模型推理耗时较长，超出系统默认阈值导致任务挂起。
- 检索结果出现不匹配的空间规划内容：原因是分块长度设置过小，截断了包含空间坐标的关键段落，导致向量嵌入丢失空间语义关联。

## 怎么确认配好了
- 上传一份典型的规划实施评估报告，查看分块后的文本片段是否完整保留了空间坐标与约束指标。
- 等待12小时后检查手动插入的文档对应的索引列表，确认索引未被自动清理。
- 输入包含具体空间范围的查询词，调用检索接口验证召回结果的数量与匹配度符合预设阈值。
- 查看系统日志，确认嵌入模型调用的返回参数中`maxToken`与配置值一致，无调用超时报错。
