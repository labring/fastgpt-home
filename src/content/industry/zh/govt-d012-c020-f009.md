# 国土空间规划编制与实施评估的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自国土空间基础信息平台、自然资源调查监测数据、人口经济统计成果及公开遥感影像。日常处理的文档包括国土空间总体规划、详细规划、专项规划、规划实施评估报告与公众意见汇总。数据更新频率为年度，字段包含空间坐标、约束指标、人口经济统计值等，文档结构通常分为规划目标、空间布局、实施评估等模块，整体数据体量随规划覆盖范围扩大而提升。

## 这些特征在「模型接入与配置」这一环带来什么约束
年度更新的数据需要定期同步，模型接入时需适配批量空间数据的解析逻辑。多源异构数据的格式差异要求配置中预留数据格式适配参数。规划文档的长文本结构需要调整上下文窗口参数，避免截断核心规划指标。公众意见汇总的非结构化文本需适配模型的语义理解配置，同时需预留多密钥管理的配置项以区分不同部门的调用权限。出错后果关联审批延误与资源冲突，因此需配置稳定的报错捕获与重试机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 适配规划文档的长文本结构，避免截断核心指标与空间布局内容 |
| 最大输出token数 | 2000–3000 token | 控制单轮输出长度，适配规划评估报告的分段生成需求 |
| 温度系数 | 0.2–0.4 | 平衡规划内容的严谨性与语义连贯性，降低随机输出风险 |
| 工具调用模式 | auto | 自动适配空间数据解析与规划逻辑推导的工具调用需求 |
| API代理密钥 | 按部门分配独立密钥 | 区分不同业务部门的调用权限，避免配置冲突 |
| API代理地址 | 部署所在的FastGPT代理地址 | 适配内部网络访问的资源路径 |

## 容易做错的三处
- 新建模型配置后原有配置被覆盖：现象为同一API模型下新增配置后，旧配置的密钥与参数丢失。原因是未开启多密钥独立维护模式，默认使用全局配置覆盖。
- 工具调用节点返回429状态码：现象为模型调用时频繁提示请求速率过高。原因是未配置合理的请求间隔与重试阈值，未适配规划数据批量调用的速率限制。
- 配置的body参数无法删除且恢复：现象为删除body参数后再次进入配置页仍存在该字段。原因是前端缓存未清空，或默认参数模板未更新。

## 怎么确认配好了
本说明适用于FastGPT v4.17.0版本。
- 测试多部门密钥切换：使用不同部门的API代理密钥发起调用，验证各自的配置参数生效且互不干扰。
- 触发速率限制场景：发起批量规划数据解析请求，观察是否触发预设的报错与重试机制。
- 验证长文本适配：导入完整的国土空间总体规划文档，检查模型输出未出现核心内容截断。
- 检查body参数状态：删除body参数后退出配置页，重新进入确认字段未恢复。
