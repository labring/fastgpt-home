# 国库集中支付与报销审核的内部办公与员工服务：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源于国库集中支付系统、预算管理一体化系统、电子发票平台与合同管理系统，更新频率为每日。日常处理的文档包括支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证，核心字段包含预算指标编码、经济分类代码、票据校验码、合同履约金额、验收批次号等，所有数据围绕单笔资金支付的合规性与执行进度生成。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来自多个独立系统，工具调用需支持多接口并行拉取对应文档，避免跨系统数据不一致。单笔支付的合规审核依赖精准匹配单条数据，因此工具调用需限定单次处理单份支付或报销单据，不宜同时处理多笔。每日更新的数据集规模稳定，工具调用的超时阈值需适配单份文档的字段解析时长，同时需对拉取的原始数据做格式校验，防止因系统字段差异导致审核失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `toolChoice` | `auto` | 允许模型自主选择调用工具完成合规校验 |
| `functionCall` | 仅指定财政合规校验工具 | 限定模型调用专用工具，避免调用无关功能 |
| 单次工具调用超时时间 | 600 秒 | 适配多系统数据拉取与单据校验的耗时 |
| 工具调用结果返回条数 | 前 3 条 | 匹配单笔审核仅需核心校验结果的场景 |
| 上下文窗口大小 | 8000–12000 token | 容纳单份单据的全量关联文档数据 |

## 容易做错的三处
- 调用工具接口返回413错误：现象为界面提示请求实体过大，原因是未限制工具返回结果的总大小，单次拉取的单据关联数据超出接口允许的传输阈值。
- 使用qwen3模型时无法强制模型不使用推理模式：现象为模型未调用指定工具而是直接生成推理结果，原因是未通过`functionCall`参数锁定工具调用范围，模型自主选择了非工具调用的推理路径。
- 未配置MCP streamable HTTP适配：现象为工具调用无法实现流式返回，原因是未开启对应协议的配置开关，未适配财政系统接口的流式传输要求。

## 怎么确认配好了
- 发起一笔模拟支付申请审核，检查模型是否调用了指定的财政合规校验工具。
- 查看工具调用日志，确认单次返回的结果条数符合配置要求，且未触发超时异常。
- 检查对话界面，确认工具调用的中间请求与返回日志未被展示，仅展示最终审核结果。
- 验证多系统数据拉取功能，确认国库集中支付系统与电子发票平台的数据均可被正常拉取。
