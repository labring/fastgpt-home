# 国库集中支付与报销审核的内部办公与员工服务：表单与交互

## 这个品类的数据长什么样
本品类涉及的核心数据来自国库集中支付系统、预算管理一体化系统、电子发票平台及合同管理系统，更新频率为每日。日常流转的文档包括支付申请、用款计划、发票、合同、验收单、报销审批单、支付凭证。数据字段包含预算指标编码、经济分类代码、支付金额、审批节点状态等，单位多为人民币元、自然天数，部分字段需匹配财政系统统一的编码规则。

## 这些特征在「表单与交互」这一环带来什么约束
多系统数据源要求表单需支持跨源字段联动校验，避免手动录入的编码与财政系统不一致。每日更新频率要求表单的下拉选项、可用预算指标列表需每日同步最新数据，防止使用过期指标。多类型文档与复杂字段要求表单按业务节点分块展示，将支付申请、报销审核等环节拆分为独立交互模块，减少页面复杂度。单笔资金支付的合规要求需表单内置实时校验规则，拦截不符合财经规范的录入内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 必填项校验延迟 800 毫秒 | 避免频繁触发校验影响录入体验，同时及时拦截错误输入 |
| `userSelect` | 前 10 条候选结果 | 本品类涉及的用户群体数量相对固定，少量候选即可覆盖常用审批与经办场景 |
| 表单字段分组 | 按业务环节拆分（预算指标区、票据凭证区、审批节点区） | 本品类文档按业务链条流转，分组后便于审核人员逐环节核对 |
| 上下文同步阈值 | 1200–1500 字符 | 单份支付申请或报销单的核心信息长度多在此区间，完整同步可提升交互连贯性 |
| 错误提示触发规则 | 字段校验失败立即弹出提示 | 本品类字段合规性要求严格，及时提示可减少后续审核退单 |

## 容易做错的三处
- 现象：上传支付申请、发票等附件时弹出上传失败提示，文本对话功能正常。原因：未正确配置表单的附件上传模块与财政系统存储路径的关联规则，导致文件流转异常。
- 现象：表单的用户选择下拉框仅显示旧版审批岗名单，无最新人员信息。原因：未开启`userSelect`的每日同步配置，导致候选数据未随财政系统人员变动更新。
- 现象：输入预算指标编码后未触发联动校验，无法提示编码不匹配。原因：未设置`formInput`的字段联动规则，未对接预算管理一体化系统的编码校验接口。

## 怎么确认配好了
- 进入FastGPT v4.17.0的表单编辑页面，选择预算单位支付申请模板，上传符合格式的发票附件，验证上传流程是否正常完成。
- 在表单中输入不符合财政编码规则的预算指标编码，检查是否触发合规性提示。
- 打开`userSelect`的候选列表，确认包含当前在岗的财务审核岗、预算单位经办人等用户角色。
- 查看表单的字段分组布局，确认已按业务环节拆分为独立的交互区块。
