# 土地使用权、矿业权与国有产权交易的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据通常来自全国公共资源交易平台、自然资源交易系统、产权交易所系统及国资监管系统，更新频率为每日。日常处理的文档包含出让公告、交易须知、竞买申请、保证金凭证、成交确认书、挂牌结果公告、产权转让说明书等，文档多为结构化文本，包含交易标的权属信息、竞价规则、保证金金额、成交确认条款等固定字段，无统一的单位规范，部分字段需结合区域交易规则确认。

## 这些特征在「模型接入与配置」这一环带来什么约束
多数据源的接入需求要求配置需支持对接多个异构系统的API端点，避免数据拉取异常；文档类型多且字段不统一，要求上下文配置需适配不同长度的文本内容，防止关键权属、竞价信息被截断；每日更新的数据需保证向量库同步频率，确保模型调用时使用最新的交易信息；交易场景对准确性要求极高，任何错误的权属判断或流程描述都可能导致成交无效或国有资产争议，因此模型参数需偏向严谨性。

## 配置怎么定
本文基于FastGPT v4.17.0版本，以下为针对该品类的配置建议：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 该品类的交易文档通常包含多段长文本，如产权转让说明书、挂牌结果公告，需覆盖完整上下文以准确提取关键信息 |
| `temperature` | `0.1–0.3` | 交易场景需严格严谨，避免模型生成错误的权属判断、竞价规则或流程描述 |
| `toolChoice` | `auto` | 需根据交易场景自动调用工具，完成权属核对、保证金计算、成交条款校验等任务 |
| `quoteMaxToken` | `2000–3000 token` | 需从多份文档中提取关键字段，如保证金金额、标的位置、成交确认时间，需保证引用内容完整 |
| `AIPROXY_API_ENDPOINT` | 填写对应交易系统或公共资源平台的对接端点 | 核心数据来自该类系统，直接接入自有数据源可保证数据时效性与准确性 |
| `AIPROXY_API_TOKEN` | 填写系统分配的对接密钥 | 用于身份验证，确保可正常拉取交易数据 |

## 容易做错的三处
- 批量上传竞买申请、保证金凭证等文档时，仅前十几条处理正常，后续无返回结果。原因是未调整`maxContext`适配多文档批量输入的上下文上限，导致后续文档超出阈值被截断。
- 配置`toolChoice`为`auto`后，Qwen2-72B-Instruct-Int8的函数调用效果不佳，生成的调用参数出现偏差。原因是未将`temperature`设置在0.3以内，导致模型生成的内容随机性过高。
- 尝试接入Casdoor身份验证时，未正确填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，导致身份校验失败。原因是未按照系统要求配置对接密钥与端点，无法完成身份验证流程。

## 怎么确认配好了
- 导入单份出让公告文档，核对模型输出的权属说明、竞价规则等内容与原文一致。
- 调用工具测试，确认模型能自动提取保证金金额、交易标的类型、成交确认条款等核心字段。
- 检查`AIPROXY_API_ENDPOINT`的连通性，确认可正常拉取最新的交易系统数据。
- 调整`temperature`至合理区间，多次生成相同场景的输出，确认结果一致性符合业务要求。
