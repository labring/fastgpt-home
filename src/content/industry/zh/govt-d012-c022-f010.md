# 土地使用权、矿业权与国有产权交易的内部办公与员工服务：知识库检索与召回

## 这个品类的数据长什么样
该品类的日常文档包含出让公告、交易须知、竞买申请、保证金凭证、成交确认书、挂牌结果公告、产权转让说明书等，数据主要来自全国公共资源交易平台、自然资源交易系统、产权交易所系统及国资监管系统，更新频率为每日。数据字段通常包含交易标的权属信息、限制条件、保证金金额、竞价规则、成交确认条款等，文档结构多为结构化表单与公告类文本结合，部分数据需跨系统同步获取。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多系统同步的每日更新数据，要求检索召回环节支持增量同步与实时更新校验，避免召回过期的挂牌或成交信息。结构化表单与非结构化公告结合的文档结构，要求检索同时适配关键词匹配与语义召回，精准定位权属、限制条件等核心字段。交易标的的权属、保证金等信息直接关联业务合规性，要求召回结果需附带明确的来源标识与数据版本，确保核对环节可追溯。跨系统数据的格式差异，还需统一字段映射规则，避免检索时出现字段不匹配的问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 该品类核心字段（如权属、限制条件）需较高匹配精度，避免召回无关的交易公告，0.75–0.85区间可平衡召回量与精准度，按实测标定微调。 |
| `limit` | 前10条 | 交易类文档单条信息量大，过多召回结果会超出上下文窗口，前10条可覆盖核心标的的关联公告与凭证，满足内部办公的核对需求。 |
| `searchMode` | hybrid | 结合语义召回与关键词匹配，适配结构化表单与非结构化公告混合的文档类型，精准命中权属、保证金金额等关键信息。 |
| `usingReRank` | 开启 | 对召回结果进行重排，优先展示与交易标的权属、竞价规则强相关的内容，解决单一语义召回可能出现的结果排序偏差问题。 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展查询词，补充“权属”“保证金”“竞买申请”等品类专属术语，提升对专业字段的召回效果。 |
| `collectionIds` | 按业务域分组配置 | 区分土地使用权、矿业权、国有产权交易的专属知识库集合，避免跨品类数据混入，确保检索结果精准对应业务场景。 |

## 容易做错的三处
-  检索结果返回的引用字段为空或显示错误的id。未正确配置`collectionIds`参数，导致系统无法关联对应知识库的文件集合id，或引用模板中未正确绑定查询到的单条数据id。
-  XLSX格式的交易须知、竞买申请文档无法识别问答对。文档内的问答对未按FastGPT支持的格式（如问题与答案分行、使用固定分隔符）排版，或单元格内包含合并格式、隐藏内容导致解析失败。
-  单次知识库检索耗时6至7秒。未开启`usingReRank`且召回`limit`设置过高，或知识库内包含大量未压缩的大体积文档，导致向量检索与重排环节耗时过长。

## 怎么确认配好了
-  发起包含“土地使用权权属”“矿业权出让条件”等专属术语的查询，核对检索结果是否包含对应品类的文档，且无跨品类的采购类数据混入。
-  查看检索结果的引用标识，确认每条结果附带唯一的数据id，且可关联到对应文档的来源系统与更新时间。
-  测试XLSX格式的交易须知文档上传，检查是否能正常解析出其中的问题与答案内容，无解析失败提示。
-  统计单次检索的耗时，确认在合理区间内，若耗时过长可调整`limit`参数或压缩大体积文档。
