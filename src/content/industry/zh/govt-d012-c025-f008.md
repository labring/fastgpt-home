# 安全生产隐患排查治理的内部办公与员工服务：文档解析与分块

## 这个品类的数据长什么样
本品类的数据来自安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常处理的文档包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，文档多包含固定字段：隐患具体描述、整改责任主体、整改时限、复查结论、督办层级等，部分文档为结构化表格格式，部分为制式文书格式。

## 这些特征在「文档解析与分块」这一环带来什么约束
日常文档的结构化与制式化特征，要求解析与分块需保留字段关联与文书逻辑，避免拆分破坏整改时限、复查结论等关键信息的完整性。日更的批量文档需要稳定的解析速度，不能因超时导致任务失败。不同文档的格式差异较大，需适配标题层级、表格结构等不同排版逻辑。带数字签名的加密PDF文档，默认解析逻辑可能无法提取完整内容，需额外配置适配。

本页面配置适用于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 匹配隐患台账单条记录的长度，保留整改时限、复查结论等关键字段的完整性，避免关键信息被拆分到不同块中 |
| `chunkSplitter` | 按段落+标题拆分 | 适配整改通知书、督办单的标题层级结构，避免拆分破坏文书的逻辑连贯性 |
| `customPdfParse` | 启用 | 适配带数字签名的加密PDF文档，绕过签名校验提取完整文本内容，解决加密文档无法识别的问题 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对批量上传的日更文档，避免因解析耗时过长触发超时错误，保障批量任务的完成率 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 适配执法检查记录的批量扫描件或长文档，满足单次上传的容量需求，避免因文件过大被拦截 |

## 容易做错的三处
- 现象：调用Doc2x工具时返回读取文件错误，报错包含类似"Only support .txt, .m"的提示。原因：上传的文件格式未被支持，或文件存在损坏、加密导致解析前置校验失败。
- 现象：上传带数字签名的PDF后，解析结果为空或无法识别有效内容。原因：未启用`customPdfParse`配置，默认解析逻辑无法绕过数字签名的加密限制，导致文本提取失败。
- 现象：API返回知识库阅读链接，点击后页面报错，或大模型输出未包含上传文件的图片内容。原因：未配置正确的文件解析参数，导致图片元数据未被提取，或链接的访问权限未正确生成。

## 怎么确认配好了
- 上传单份隐患整改通知书PDF，检查解析结果是否保留标题、整改要求、复查意见的完整段落，无乱码或字段拆分错误。
- 上传带数字签名的PDF文档，验证解析结果是否包含完整文本内容，无空值或缺失关键字段。
- 上传批量文档，检查解析任务的完成时间是否在预设的`PARSE_FILE_TIMEOUT_SECONDS`范围内，无超时失败记录。
- 测试API返回的阅读链接，验证页面可正常访问，且大模型可提取到文档中的文本内容。
