# 安全生产隐患排查治理的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自安全生产监管系统、企业隐患自查系统、执法检查记录及事故统计系统，更新频率为每日。日常处理的文档包含隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，文档多包含隐患编号、整改责任主体、整改期限、复查结果等结构化字段，部分文档附带现场检查的文字描述或照片素材，数据结构随业务流程环节变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的多源数据要求模型接入环节支持批量数据同步，需适配不同系统的接口格式与字段规范。多类文档兼具结构化与非结构化混合特征，要求配置环节兼顾结构化字段提取与自然语言文本理解能力。隐患排查、整改、复查的全流程关联多份文档，要求模型能关联跨文档的同一隐患编号数据，避免信息割裂。整改期限、责任主体等字段的准确性直接影响业务合规性，要求配置时提升关键字段的抽取置信度，限制无关内容的干扰。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多类隐患文档的拼接需求，覆盖单隐患关联的排查清单、整改台账、复查记录等多份文档内容 |
| `maxTokens` | 4000 token | 限制单轮输出长度，避免整改通知书、复查记录等长文档处理时超出模型上下文上限 |
| `quoteMaxToken` | 1500 字符 | 保留足够的原文片段用于隐患溯源，匹配整改通知书等文档的关键内容长度 |
| `toolChoice` | auto | 自动选择是否调用工具，适配隐患排查标准对照、整改期限计算等多场景需求 |
| `temperature` | 0.2–0.4 | 降低随机生成概率，确保隐患编号、整改责任主体等关键字段的输出一致性 |
| `vision` | 开启 | 适配现场检查照片类文档的内容提取，满足执法检查记录的图文结合处理需求 |

## 容易做错的三处
- 现象：配置`AIPROXY_API_TOKEN`时触发「Data too long for column 'models'」报错。原因：令牌内容长度超出系统默认数据库字段存储限制，未使用符合格式的短令牌。
- 现象：批量同步每日更新的隐患数据时出现处理失败。原因：`maxContext`参数取值过大，导致单批次数据拼接超出模型上下文承载阈值。
- 现象：隐患整改责任主体的提取结果出现随机偏差。原因：`temperature`参数取值过高，降低了关键结构化字段的输出一致性。

## 怎么确认配好了
- 导入单份隐患排查清单，执行字段提取测试，核对隐患编号、整改期限等关键字段的提取结果，调整对应参数至结果稳定。
- 配置每日自动同步任务，验证数据更新频率是否匹配业务要求，调整接口调用间隔与批量处理规模。
- 开启`vision`功能后上传执法检查照片，验证图文内容的提取准确性，确认配置生效。
- 测试短文本提问的输出模式，确认是否启用流式返回，调整相关参数匹配业务交互需求。
