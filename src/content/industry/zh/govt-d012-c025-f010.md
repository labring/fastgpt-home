# 安全生产隐患排查治理的内部办公与员工服务：知识库检索与召回

## 这个品类的数据长什么样
本品类数据主要来自安全生产监管系统、企业隐患自查系统、执法检查记录、事故统计系统，更新频率为每日。日常处理的文档包括隐患排查清单、隐患治理台账、整改通知书、复查记录、重大隐患挂牌督办单，文档围绕隐患排查、整改、复查全流程生成，包含隐患标识、责任主体、整改要求、复查结论等核心字段，格式多涵盖docx、pdf等办公文档类型。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的日更数据特征要求检索链路支持增量同步更新，避免全量索引重建占用过多系统资源。多类型办公文档混合存储，不同文档的核心字段差异明显，检索时需要针对隐患编号、整改责任人、整改时限等关键信息配置差异化权重。数据来源分散且覆盖监管、自查、执法等场景，需要统一的检索入口同时保障多源数据的召回一致性。业务风险等级较高，检索结果需精准匹配隐患判定标准与历史整改记录，避免遗漏核心信息影响排查效率。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | `0.75–0.85` | 本品类数据关联业务风险，需过滤低相关性结果，保障核心隐患信息的召回精准度 |
| `limit` | `前10条` | 日常排查与整改场景下，单次检索无需过多结果，避免信息过载干扰决策 |
| `searchMode` | 向量检索+关键词混合 | 兼顾语义理解与精准字段匹配，适配多类型隐患文档的检索需求 |
| `usingReRank` | 开启 | 提升高相关结果的排序优先级，适配业务风险较高的场景，减少漏检可能 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展查询词覆盖隐患判定标准的同义表述，优化对照排查环节的检索效果 |
| `collectionIds` | 按文档类型分组配置对应集合ID | 区分隐患排查清单、整改台账等不同文档类型，实现定向召回，提升检索效率 |

## 容易做错的三处
- 现象：手动插入的知识库文档对应的索引在数小时后自动消失。原因：未配置数据集的增量同步校验机制，或手动插入时未绑定对应集合的持久化存储策略，导致系统自动清理未关联任务的临时索引。
- 现象：批量导入docx、pdf等多格式文件时，检索召回结果条数远低于预期。原因：未开启多格式文件的批量并行解析配置，导致部分文件解析失败未纳入索引库。
- 现象：检索重大隐患判定标准时，结果中未匹配到对应条款内容。原因：未开启`datasetSearchUsingExtensionQuery`配置，未自动扩展查询词覆盖标准的同义表述，导致精准匹配度不足。

## 怎么确认配好了
- 手动上传一份隐患整改通知书，等待索引生成后执行针对性检索，确认文档能被正常召回。
- 配置增量同步任务后，修改一条现有文档的整改时限，等待更新完成后检索，确认检索结果包含最新的时限信息。
- 开启`usingReRank`与`datasetSearchUsingExtensionQuery`后，输入「重大事故隐患判定」，确认检索结果的排序优先级符合业务需求。
- 批量导入多格式文档后，检查数据集的文档数量与导入文件数量一致，确认无遗漏。
