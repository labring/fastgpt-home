# 工程建设项目审批的内部办公与员工服务：表单与交互

## 这个品类的数据长什么样
典型主体为住建局、行政审批局、工程建设项目审批综合窗口等，日常处理的文档包含施工许可申请、施工图审查合格书、质量安全监督手续、竣工验收备案表。数据来源为工程建设项目审批管理系统、施工图审查系统、企业资质库、信用平台，更新频率为每日更新。数据结构包含项目唯一标识、参建单位资质信息、审批节点记录、验收备案字段等，字段与审批流程强绑定，需严格匹配各系统的输出格式。

## 这些特征在「表单与交互」这一环带来什么约束
多数据源的接入要求表单需支持跨系统字段拉取，避免手动录入导致的信息不一致。每日更新的数据频率要求表单需配置自动刷新机制，确保显示的资质、审批节点等信息为最新状态。多类型审批文档的存在要求表单需支持动态切换字段分组，适配不同审批环节的表单结构。最耗时的整合材料、核对资质、跟踪节点环节，要求表单需内置批量导入、资质校验、节点跟踪的交互逻辑，减少人工操作成本。出错后果的严重性要求表单需强化必填项校验，确保提交材料完整，避免后续无证施工、开工延误或备案失败。与公共资源招投标品类不同，本品类聚焦审批许可环节，无需设置承包商选择类的交互模块。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 按审批环节拆分输入分组，每组绑定对应审批文档字段 | 适配施工许可申请、竣工验收备案表等多类型审批文档的字段结构 |
| `userSelect` | 按参建单位类型预设可选范围，关联企业资质库数据 | 减少手动输入错误，快速调用资质库最新更新的资质信息 |
| 表单字段校验规则 | 项目编号、参建单位资质文件、审批节点状态为必填 | 确保提交材料完整，避免开工延误或备案失败 |
| 数据自动刷新周期 | 300–600 秒 | 匹配日更的数据更新频率，保证表单显示最新的审批节点与资质状态 |
| 知识库绑定范围 | 工程建设项目审批管理系统、企业资质库 | 精准调用对应数据源的内容，避免无关信息干扰 |
| 文本输入长度限制 | 800–1200 字符 | 适配审批文档中参建单位说明等常规文本的输入长度 |

## 容易做错的三处
- 调用文本内容提取模块处理审批文档代码块时，响应返回代码块为undefined。未在`formInput`中正确绑定文档原始文本的输入源，导致提取模块无法获取有效上下文。
- 输入“分享”作为交互提示词，调用工具后实际传入内容变为“分交”。未配置输入内容的归一化校验逻辑，未拦截形近字输入错误。
- 配置全局变量绑定知识库后，无法正常赋值调用。未在`userSelect`中配置全局变量的触发条件，导致变量未随表单交互实时更新。

## 怎么确认配好了
- 切换不同审批类型的表单模板，确认`formInput`分组自动适配对应文档的字段结构。
- 触发数据拉取操作，确认表单加载的参建单位资质数据与企业资质库的更新节奏匹配。
- 提交包含空必填字段的测试表单，确认系统触发对应校验提示。
- 调用文本内容提取模块处理审批文档代码块，确认返回结果无undefined字段。
