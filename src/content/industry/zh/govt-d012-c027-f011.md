# 工程建设项目招投标的内部办公与员工服务：表单与交互

本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类数据主要来自全国公共资源交易平台、地方交易平台、工程审批系统及招标投标监管系统，更新频率为每日。日常涉及的文档包括招标公告、资格预审文件、招标文件、投标文件、评标报告、中标候选人公示、中标结果公告，数据字段包含标段信息、资格条件、工程量清单、评标专家记录、中标结果等，无统一固定单位，需根据文档类型匹配对应字段。

## 这些特征在「表单与交互」这一环带来什么约束
每日更新的数据源要求表单支持实时同步最新交易数据，避免使用过期字段。多类型招投标文档对应差异化的表单字段，需支持按文档类别切换表单结构。跨多系统的数据来源要求表单配置兼容不同格式的导入字段。标段拆分、评标记录核对等耗时业务环节，需要表单提供预设字段组、批量编辑等交互优化，提升操作效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 按招投标文档类别配置字段组，支持标段、资格条件、评标记录三类预设 | 本品类文档类型多样，需匹配不同业务场景的字段结构 |
| `userSelect` | 限定为住建、交通、水利行业主管及公共资源交易中心内部角色 | 本品类业务主体明确，需限制操作角色范围 |
| 单次数据导入上限 | 1000 条 | 本品类文档常包含批量标段或投标记录，需适配批量处理需求 |
| 表单超时阈值 | 600 秒 | 评标记录核对等环节操作耗时较长，需预留足够响应时间 |
| 历史数据同步频率 | 按实测标定 | 每日更新的数据源需匹配业务同步节奏，避免数据滞后或重复同步 |

## 容易做错的三处
- 现象：表单导入资格预审文件后部分字段为空，无法自动匹配。原因：未使用`formInput`配置对应文档的预设字段组，直接套用通用表单模板，未适配本品类文档的专属字段结构。
- 现象：通过变量引用选择招投标文档时无匹配结果。原因：未明确配置数据源范围，且未说明变量引用的参数填写规则，导致无法关联对应交易平台的文档。
- 现象：提交评标记录表单后出现超时报错。原因：表单超时阈值设置低于600秒，未适配评标核对环节的实际操作耗时。

## 怎么确认配好了
- 导入一份资格预审文件，核对表单自动匹配的字段是否与文档内容一致。
- 切换不同业务角色，测试是否能访问对应权限内的招投标文档。
- 提交一份模拟评标记录表单，验证操作响应是否符合业务需求，按需调整超时阈值。
- 配置变量引用规则，测试是否能精准筛选对应标段的文档。
