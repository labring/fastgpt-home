# 市场主体登记与许可的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
该品类的日常处理文档包含设立登记申请书、章程、股东决议、住所证明、营业执照、食品经营许可申请等，数据来源于企业登记全程电子化系统、国家企业信用信息公示系统、电子营业执照系统、住所信息库，每日自动更新。数据字段涵盖主体名称、住所地址、股东信息、许可类型等，单份文档内容跨度从数百到数千字符，需关联多系统跨源数据完成核验与校验。

## 这些特征在「部署与升级」这一环带来什么约束
针对该品类的业务特性，每日更新的跨源数据要求部署时配置稳定的多数据源同步链路，避免数据延迟导致核验失效。多类型文档的结构差异要求升级时兼容不同格式的解析适配，防止部分文档字段提取失败。高频的核验操作需要预留足够的计算资源，避免处理峰值时超时。跨系统关联的字段校验需要配置精准的字段映射规则，防止数据匹配错误引发登记驳回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:port/database?authSource=admin` | 该品类需存储多系统同步的企业登记数据，标准MongoDB连接格式适配多源数据存储 |
| `REDIS_URL` | `redis://:password@host:port/0` | 每日更新的跨源数据需要缓存校验结果，降低重复查询开销 |
| `STORAGE_S3_ENDPOINT` | `按云服务商地域配置的存储端点` | 需存储营业执照、住所证明等扫描件，兼容S3协议的对象存储适配大文件上传 |
| `DB_MAX_LINK` | `20–30 个` | 多系统同步数据时需维持稳定的数据库连接池，避免连接耗尽导致服务中断 |
| `FILE_TOKEN_KEY` | `随机生成的32位字符串` | 需对上传的许可申请文档生成访问令牌，保障文件访问安全 |
| `PG_URL` | `postgresql://username:password@host:port/database` | 需存储结构化的登记流程日志，PostgreSQL适配结构化数据的高效查询 |

## 容易做错的三处
- 现象：部署后处理营业执照扫描件时日志显示`ocr error`。原因：未配置图片理解模型的依赖环境，或未在知识库中启用图片解析开关。
- 现象：新部署环境启动后提示数据库连接失败。原因：未正确填写`MONGODB_URI`或`PG_URL`的连接参数，导致无法访问存储数据的数据库。
- 现象：新建知识库时无图片理解模型选项。原因：部署时未安装对应模型的依赖包，或未在环境变量中开启模型加载配置。

## 怎么确认配好了
- 执行内置的数据库连接测试工具，验证`MONGODB_URI`与`PG_URL`的配置可正常建立连接。
- 上传一份标准的设立登记申请书文档，确认解析后的字段可正常提取并存储至对应数据库。
- 手动触发一次跨源数据同步任务，检查数据更新是否符合预设的每日同步节奏。
- 查看系统日志，确认`REDIS_URL`对应的缓存服务未出现连接异常或超时报错。
