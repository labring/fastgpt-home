# 市容环卫与城管执法案件的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据通常来自城管执法平台、城市运行网格平台、视频监控及群众投诉工单，每日更新。日常产生的文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告，数据字段多包含案件编号、违法地点、责任主体、整改要求、处置进度等，部分文档附带多媒体素材，整体结构围绕案件全流程处置节点搭建。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散且覆盖多类格式，多轮对话需跨平台整合案件信息，因此需要稳定的上下文关联能力。日常文档包含非文本素材，提示词需适配多媒体内容解析。案件处置的核心环节依赖精准的文档调用，多轮对话需快速定位对应环节的材料，同时需避免因信息不全导致证据不足或执法争议。每日更新的数据要求对话系统实时同步最新案件状态，避免使用过期信息开展辅助工作。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配市容环卫与城管执法案件的内部办公场景。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages`上下文保留上限 | 8000–12000 token | 该品类案件的对话历史需包含完整的案件交互与文档信息，避免关键处置节点的上下文丢失 |
| `variables`绑定字段 | 案件编号、违法地点、责任主体 | 该品类多轮对话需动态填充案件专属信息，提升检索与回复的精准度 |
| 单次召回文档上限 | 前6条 | 该品类案件的关联文档通常围绕单一案件节点，过多召回会引入无关信息，干扰核心判断 |
| 问题优化功能 | 开启 | 可将执法人员口语化的现场描述转化为标准化检索关键词，适配多轮对话中的快速信息调取 |
| 对话超时时间 | 600秒 | 现场处置的多轮对话通常需要较长的信息梳理周期，避免中途中断影响执法流程 |
| `chatId`会话日志开关 | 开启 | 可留存完整的多轮对话记录，用于后续执法核查与问题追溯 |

## 容易做错的三处
- 现象：上传现场照片等多媒体文档后解析报错，返回文件格式不支持提示。原因：未开启对应多媒体格式的解析开关，或未配置适配该品类文档的分块规则。
- 现象：多轮对话中无法调取当日更新的案件数据，返回结果为空。原因：未设置实时同步数据的触发规则，或数据更新的定时任务未按日执行。
- 现象：对话详情页无法查看应用内部的详细交互记录。原因：未开启`chatId`对应的会话日志存储开关，或日志存储的容量阈值设置过低导致旧记录被自动清除。

## 怎么确认配好了
- 上传一份该品类的典型巡查记录文档，触发检索，核对召回结果是否包含对应案件的立案审批表。
- 发起一段模拟多轮对话，输入现场取证的口语化描述，核对系统是否自动优化为标准化检索关键词。
- 等待24小时后发起对话，核对是否能调取当日更新的案件信息。
- 发起时长超过500秒的模拟对话，核对系统是否正常完成交互未触发超时中断。
