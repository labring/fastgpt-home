# 市容环卫与城管执法案件的内部办公与员工服务：工作流编排

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类的数据来源包括城管执法平台、城市运行网格平台、视频监控、群众投诉工单，更新频率为每日。日常文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书、结案报告，字段通常包含案件编号、责任主体、违法类型、整改状态、处置时限等，部分文档附带现场照片、执法录像等多媒体文件。

## 这些特征在「工作流编排」这一环带来什么约束
多源且每日更新的数据特征，要求工作流支持多数据源接入与定时同步任务；文档包含结构化表格与多媒体文件，要求工作流适配不同格式的文件解析与字段提取；案件处置环节覆盖立案、审批、整改、结案等多步骤，要求工作流串联各节点并关联现场取证等环节的数据；执法合规的出错后果要求工作流增加校验节点，避免证据缺失或流程遗漏。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :--- | :--- | :--- |
| 分块长度 | 800–1200 字符 | 适配巡查记录、处罚决定书等日常文档的文本长度 |
| 重叠长度 | 100–200 字符 | 避免分块破坏案件上下文的关联逻辑 |
| 节点超时 | 600 秒 | 覆盖现场取证定位、责任主体判断等耗时环节的处理时间 |
| 知识库召回上限 | 前 5 条 | 匹配同类历史执法案卷，减少冗余信息干扰 |
| `variables` 触发规则 | 按案件编号匹配 | 关联城管执法平台、网格平台的多源数据 |
| 模型切换 | 按环节按需配置 | 适配案件分类、合规校验等不同任务的模型需求 |

## 容易做错的三处
- 调用API时返回模型参数不匹配报错，原因是未明确`model`字段对应任务类型，误将分类模型用于问答环节。
- 工作流运行整体超时，原因是未设置合理的节点超时时间，未覆盖现场取证等耗时较长的环节。
- 知识库召回结果条数与预期不符，原因是未配置正确的召回上限，或分块长度设置不合理导致上下文断裂。

## 怎么确认配好了
- 上传单份巡查记录与处罚决定书，验证工作流能否正确提取案件编号、违法类型等核心字段。
- 触发多源数据同步任务，检查城管执法平台与网格平台的数据能否按`variables`字段正确关联。
- 模拟完整案件处置流程，逐个校验节点的超时设置与模型调用是否符合环节需求。
- 调用API发起测试请求，确认`model`字段的配置与当前执行的任务类型匹配。
