# 市容环卫与城管执法案件的内部办公与员工服务：模型接入与配置

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
该品类数据通常来自城管执法平台、城市运行网格平台、视频监控及群众投诉工单，更新频率为每日。日常文档包含巡查记录、案件立案审批表、现场照片、责令改正通知书、处罚决定书与结案报告，字段涵盖巡查时间、地点、问题描述、立案编号、责任主体、整改要求等，部分文档附带多媒体文件。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的批量数据要求模型接入需支持增量同步与批量调度，避免全量拉取占用过多资源；多类型文档含文本与多媒体素材，需配置适配的视觉与文本处理参数，确保现场照片等取证材料可被正确解析；字段与专属术语的多样性，要求模型接入时需配置领域专属提示词，提升执法场景的理解准确性；现场处置的时效性要求，需匹配执法流程的时间窗口，避免模型响应超时影响案件流转。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配案件多轮流转的上下文需求，避免截断立案、整改、结案等关键流程信息 |
| `maxTokens` | 4000 token | 匹配单份案件文档的平均长度，确保处罚决定书、结案报告等长文本可完整生成 |
| `vision` | 开启 | 支持解析现场照片、监控截图等多媒体取证素材，满足现场执法环节的模型调用需求 |
| `toolChoice` | auto | 自动触发工具调用，匹配案件处理中查询执法依据、定位责任主体的场景 |
| `temperature` | 0.3–0.5 | 降低随机输出，确保执法文书生成的规范性与准确性 |
| `AIPROXY_API_TOKEN` | 按服务商分配的密钥填写 | 完成身份验证，保障接口调用的安全性 |

## 容易做错的三处
- 调用o1系列模型时出现接口报错，提示参数不兼容。原因是未针对城管执法场景配置专属的系统提示词，导致模型无法识别专属执法术语，触发模型侧校验失败。
- 工具调用环节AI未触发工具，直接自行回答。原因是`toolChoice`配置为固定非自动模式，或未在系统提示词中明确要求调用执法相关工具。
- 接入后出现沟通报错，返回超时状态码。原因是`maxContext`设置过大，导致模型处理时间超出接口超时阈值，或未配置合理的请求重试机制。

## 怎么确认配好了
- 上传单份巡查记录与现场照片，验证模型是否能正确提取地点、问题描述并生成初步立案建议，确认`vision`与文本解析功能正常。
- 触发工具调用测试，输入“查询某路段的违法占道执法依据”，验证模型是否自动调用对应工具，确认`toolChoice`配置正确。
- 查看接口日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置无误，无401或404报错。
- 提交批量案件数据，验证模型处理速度符合每日更新的调度需求，确认`maxContext`与`maxTokens`设置未超出接口限制。
