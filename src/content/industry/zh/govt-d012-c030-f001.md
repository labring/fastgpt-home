# 建设工程质量安全监督的内部办公与员工服务：HTTP 接口与外部系统

本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类的数据来源包括工程质量安全监管系统、施工现场实名制平台、监理日志、检测报告，更新频率为周。日常文档涵盖监督计划、监督检查记录、隐患整改通知书、质量问题处理单、竣工验收监督报告，文档字段包含项目唯一标识、检查日期、整改要求、验收状态等核心业务内容，部分文档关联现场作业人员、设备的实名数据，整体数据结构围绕施工现场的过程监督与竣工验收环节设计。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于数据来自多个独立的外部系统，需配置多组接口分别对接不同数据源，实现全量业务数据的同步。周度更新的节奏决定接口调用频次需匹配业务同步周期，避免高频请求触发外部系统的限流限制。品类文档包含大量业务专属字段，接口请求需携带项目标识、检查日期等结构化参数，确保返回数据与对应监督任务关联。整改闭环的跟踪需求要求接口支持状态回传，响应需包含可识别的业务状态字段，便于后续流程推进。现场实名数据的关联要求接口需传递人员、设备的唯一标识，保证数据的业务关联性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {监管系统API密钥}` | 外部住建类系统通常采用Bearer令牌鉴权，匹配行业标准鉴权方式 |
| `variables` | `{"projectId": "监督项目唯一标识", "checkDate": "周度检查日期"}` | 需传递品类专属的业务参数，关联日常文档的核心标识与时间字段 |
| `responseData` | 提取根节点下的data数组 | 该品类的外部接口通常将业务数据封装在根节点的data字段中，便于后续数据处理 |
| 接口调用超时时间 | `30-60 秒` | 现场数据查询可能涉及多环节核验，需预留足够响应时长，按实测标定可调整区间 |
| 重试次数 | `2 次` | 周度批量同步数据时，偶发网络波动可通过重试恢复，避免单次请求失败导致同步中断 |
| 响应字段校验 | 校验必传字段：projectId、checkResult | 确保接收的数据包含品类业务的核心标识与结果，避免无效数据流入系统 |

## 容易做错的三处
- 调用接口后返回“Model response empty”报错，原因是未正确配置`responseData`提取规则，导致系统无法识别接口返回的有效业务数据。
- 私有部署时提示INITIAL_ROOT配置的密码错误，原因是docker-compose.yml中配置的INITIAL_ROOT参数未正确映射到容器环境变量，或参数包含特殊字符未转义。
- docker部署后访问地址显示转圈圈后失败，原因是本地端口映射配置错误，或宿主机防火墙拦截了3000端口的访问请求。

## 怎么确认配好了
- 调用配置好的测试接口，核对返回的`responseData`是否包含品类业务所需的核心字段，确认数据提取规则匹配接口返回结构。
- 检查部署配置文件，确认`Authorization`参数与外部系统提供的密钥一致，验证鉴权配置正确。
- 查看系统日志，确认接口请求携带了正确的`variables`业务参数，匹配当前监督项目的实际数据。
- 触发单次数据同步任务，确认请求超时与重试配置符合业务场景的响应时长要求。
