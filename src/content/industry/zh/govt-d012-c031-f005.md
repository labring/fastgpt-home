# 建设项目环评审批的内部办公与员工服务：工具调用与插件

## 这个品类的数据长什么样
本品类涉及的主体包括生态环境部门环评处、行政审批局、建设单位及环评机构。日常处理的文档包含环境影响报告书/报告表、审批申请、公众参与说明、技术评估意见、环评批复等，涵盖结构化审批字段与非结构化文本内容。数据来源为全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台及监测数据，更新频率不定期，无固定周期。核心核对字段包括项目类别、环评等级、污染防治措施、公众参与情况等。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源多且更新无固定周期，要求工具调用需支持对接多个异构系统的插件，适配不同格式的数据源输出。日常文档兼具结构化与非结构化特征，需工具具备多格式解析能力，确保能提取审批申请中的项目类别、环评等级等关键字段。最耗时的核对环节依赖跨系统数据比对，需工具自动拉取对应系统的历史数据辅助校验。出错后果直接影响项目开工与合规性，需工具调用配置校验机制与失败重试逻辑，避免错误数据进入审批流程。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配环评审批中需自动拉取系统数据的场景，平衡工具调用与AI回复的触发逻辑 |
| `functionCall` | 开启结构化输出 | 确保工具调用返回的结果符合环评文档的结构化字段格式，便于后续核对 |
| 工具调用超时 | 600 秒 | 对应跨系统拉取环评数据可能需要的较长等待时间，避免因数据源响应慢导致调用中断 |
| 插件触发条件 | 匹配项目类别关键词 | 仅在检测到审批申请、项目基础信息时触发工具调用，减少无效调用次数 |
| 单次调用返回文档数 | 前5条 | 控制工具返回的结果量，避免冗余数据干扰核对 |
| 结果筛选阈值 | 前3条匹配结果 | 聚焦与当前项目最相关的环评数据，提升核对效率 |
| 重排模型配置 | 按实测标定 | 适配环评文档的长文本特征，优化检索结果的排序精度 |
| 插件调用频率限制 | 每小时100次 | 适配环评审批的日常业务量，避免触发系统限流 |

## 容易做错的三处
- 调用工具后同时输出AI生成内容与预设回复：现象为提交审批申请后，界面同时显示模型生成的文本与预先配置的指定回复。原因是未正确配置`toolChoice`参数，未限制仅触发工具调用或仅使用预设回复。
- 重排模型调用后显存占用过高：现象为启动重排模型后，显存占用随调用快速增长至6-7G，且多GPU均出现该情况。原因是未配置模型轻量化加载参数，或未限制单次调用的文本批次大小。
- 工具返回无关环评数据：现象为工具拉取的数据与当前审批项目的类别、等级不匹配。原因是未设置基于项目字段的触发过滤条件，导致工具调用范围过大。

## 怎么确认配好了
- 提交一份测试审批申请，查看工具是否仅在检测到项目类别关键词时触发调用。
- 查看工具调用日志，确认返回结果为结构化格式，且包含环评审批所需的核心字段。
- 模拟工具无匹配数据的场景，确认系统自动输出预先配置的指定回复。
- 查看服务器监控，确认重排模型的显存占用未超过服务器配置阈值。
