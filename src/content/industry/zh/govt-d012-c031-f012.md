# 建设项目环评审批的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
本品类的数据来源包括全国建设项目环评统一申报和审批系统、生态环境分区管控成果、排污许可平台、监测数据，更新频率不定期。日常处理的文档包含环境影响报告书或报告表、审批申请、公众参与说明、技术评估意见、环评批复，单份文档覆盖项目类别、环评等级、污染防治措施、公众参与情况等字段，无固定统一单位，需匹配项目实际参数完成结构化处理。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据来源多为政务系统，接口权限与格式要求严格，部署时需适配跨系统数据同步的兼容性配置。不定期更新的环评政策与项目数据，要求升级后保留历史数据迁移的兼容逻辑，避免审批流程中断。多类型文档的结构化处理需求，需预留足够的存储与计算资源。不同主体（环评机构、审批部门、建设单位）的权限划分差异，需在部署阶段完成细粒度角色配置，防止后续升级破坏现有权限体系。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–200 个` | 环评审批场景下多用户同时发起项目处理请求，该参数控制数据库连接池最大连接数，保障并发访问稳定性 |
| `STORAGE_S3_ENDPOINT` | 按政务云存储服务商提供的 endpoint 配置 | 环评数据属于政务敏感信息，需存储在合规政务云环境，匹配对应存储服务的接入地址 |
| `REDIS_URL` | 使用政务内网专属 Redis 实例，内存规格为 2048 MB | 缓存环评项目的临时会话与文档元数据，通过内网隔离提升数据访问安全性 |
| `FILE_TOKEN_KEY` | `64 位随机字符串` | 用于签署文件上传的临时令牌，保障环境影响报告书等文档上传流程的安全性，防止未授权访问 |
| `ROOT_KEY` | `32 位随机字符串` | 用于配置系统最高权限的访问密钥，保障内部办公后台的权限管控安全性 |
| `FE_DOMAIN` | 配置为内部办公系统的二级域名 | 适配内部员工的访问路径，统一内部办公与环评审批的系统入口 |

## 容易做错的三处
-  工作流上传环境影响报告表等文件时出现Failed to create post presigned url报错。原因是升级后未重新匹配`FILE_TOKEN_KEY`与存储服务的配置参数，导致临时上传令牌生成失败。
-  部署后无法加载历史环评审批文档。原因是未正确配置`MONGODB_URI`或`PG_URL`，数据库连接权限不足或地址配置错误。
-  内部员工无法访问系统后台管理界面。原因是未正确设置`ROOT_KEY`的权限范围，导致角色划分不符合内部办公的权限管控要求。

## 怎么确认配好了
-  执行数据库连接测试，验证`DB_MAX_LINK`配置的连接数可支撑同时发起的环评项目处理请求。
-  上传一份测试用的小型环境影响报告表，确认文件上传、存储流程正常，无令牌生成相关报错。
-  访问配置的内部办公域名，确认`FE_DOMAIN`配置的地址可正常跳转至系统前端界面。
-  查看Redis实例监控，确认`REDIS_URL`配置的实例可正常存储临时会话与文档元数据。
