# 招标采购合规管理的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
本品类的数据覆盖国央企采购中心、招标办、业务需求部门、审计纪检部门及招标代理等主体的日常办公与合规文档，包括采购计划、需求说明书、招标文件、评标记录、合同、验收单及供应商投诉材料。数据来源于企业采购平台、公共资源交易平台、供应商库、合同管理系统与审计问题库，每日更新。文档包含采购方式、预算依据、评分办法、供应商资格条件等结构化字段与非结构化文本内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来多重约束。多数据源每日更新的特性，要求支持增量索引与多源数据同步能力；文档包含结构化字段与非结构化文本，需兼顾语义检索与精准字段匹配能力；单文档体量跨度大，从简短的采购计划到长篇评标记录均有覆盖，需适配不同长度的文本分块规则；合规审查需关联审计问题库的历史案例，需支持跨业务库的索引关联逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面逻辑编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配招标文件、评标记录等长文本的语义完整性，避免块内语义断裂 |
| 重叠长度 | 100–200 字符 | 保留跨块的上下文关联，防止关键合规条款被分块截断 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的供应商信息与历史案例，提升合规审查的精准度 |
| 单次召回上限 | 前 10 条 | 控制检索结果体量，适配招标采购合规审查的快速核对需求 |
| `maxToken` | 4096 token | 适配嵌入模型的输入长度限制，确保长文档分块后可正常生成向量 |
| `defaultToken` | 按实测标定 | 处理无明确语义的空字段或异常文本，避免索引生成失败 |

## 容易做错的三处
- 现象：手动插入的招标采购合规文档对应的索引在数小时后从知识库中消失，界面显示索引为空。原因：未开启增量索引的持久化配置，每日数据同步时覆盖了临时生成的默认索引。
- 现象：文件上传后状态长时间显示“索引中”，无进度更新。原因：未匹配适配的嵌入模型参数，或`maxToken`设置超出模型输入上限，导致向量生成超时。
- 现象：合规检索结果未关联审计问题库的历史合规案例。原因：未配置跨数据源的索引关联规则，仅对单一业务库进行检索。

## 怎么确认配好了
- 上传单份招标文件，等待索引完成后，手动检索合规关键词，核对返回结果的分块长度与设置值是否匹配。
- 查看知识库的索引管理页面，确认已插入的合规文档均显示正常索引状态，无超时或失败标记。
- 配置跨数据源关联规则后，检索历史审计问题，确认结果同时包含采购文档与审计案例内容。
- 触发一次每日增量同步任务，检查新增的供应商库数据是否成功生成索引并加入检索范围。
