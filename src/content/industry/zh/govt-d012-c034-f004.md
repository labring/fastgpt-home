# 招生入学与学籍管理的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
本品类的数据来源包括全国中小学生学籍信息管理系统、地方招生入学平台、户籍与房产数据、学校教务系统，更新频率为每日。日常处理的文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表，核心字段涵盖学生身份证号、户籍地址、房产证明编号、学籍号、异动类型等，数据以结构化文本为主，部分包含附件类证明材料。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源包含多个外部系统，工作流编排需配置跨系统数据拉取节点，确保每日同步的学籍、招生、户籍数据一致性。核心字段涉及学生身份与学籍标识，需在流程中加入字段校验环节，避免重复或错误录入。日常处理的申请类文档需串联审批节点，匹配业务审批逻辑。数据更新频率要求流程具备定时触发能力，保障最新招生与学籍信息被及时调用。同时需针对异动类流程设置分支判断，适配转学、休学等不同场景的流转规则。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 配置学生身份证号、学籍号为全局变量 | 核心身份字段需跨节点复用，避免重复录入与传递错误 |
| `nodeId` | 为每个跨系统拉取节点分配唯一标识 | 便于排查跨系统数据同步时的节点异常 |
| 外部接口调用超时 | 30–60 秒 | 适配户籍、学籍系统的接口响应时长，避免流程中断 |
| 字段校验规则 | 校验身份证号格式、学籍号18-19位 | 匹配日常文档的字段格式要求，减少录入错误 |
| 定时触发配置 | 每日凌晨 2 点触发 | 避开业务高峰时段，完成当日数据同步与流程初始化 |
| 分支判断配置 | 按异动类型划分分支 | 适配不同学籍异动场景的审批与流转逻辑 |

## 容易做错的三处
- 现象：工作流调试时跨节点传递的学生身份字段为空，原因：未正确配置`variables`全局变量，导致核心身份信息未跨节点复用。
- 现象：调用外部招生接口时返回未授权报错，原因：未在`variables`中配置接口调用凭证，或未在接口节点中绑定全局变量参数。
- 现象：上传入学报名表excel附件后无法提取数据，原因：未配置文件解析节点，或未指定excel中对应学生信息的目标列。

## 怎么确认配好了
- 进入工作流调试页面，输入测试学生的身份证号，检查`variables`全局变量是否正确加载该信息。
- 手动触发定时触发节点，查看系统日志是否显示跨系统数据拉取成功，无超时或连接失败报错。
- 上传测试用的入学报名表excel，检查文件解析节点是否提取到学生身份证号、学籍号等核心字段。
- 模拟提交转学申请，检查流程是否自动进入异动审批分支，未触发错误分支。
