# 招生入学与学籍管理的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源包括全国中小学生学籍信息管理系统、地方招生入学平台、户籍与房产数据、学校教务系统，更新频率为每日。日常处理的文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表，数据字段围绕学生身份、入学资格、学籍状态展开，包含学籍号、户籍地址、房产证明编号、入学批次等标识类与状态类字段，无额外非业务类附加数据，所有数据均为官方业务系统生成的合规业务字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据多来自官方业务系统且每日更新，需确保模型调用时能准确关联多源数据字段，避免跨系统数据错位。日常处理的文档包含固定格式的业务表单，模型输入需适配结构化字段与审批流关联逻辑，因此配置需优先保障数据映射准确性。同时因出错后果涉及学生升学与学籍合规，模型调用的稳定性与输出严谨性要求更高，需限制非必要的随机生成参数，避免出现与业务规则不符的输出内容。

## 配置怎么定
以下配置指南适用于FastGPT v4.17.0版本，针对招生入学与学籍管理场景的模型接入与配置需求制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配多份学籍与招生类文档的批量字段拼接，避免上下文溢出导致数据截断 |
| `maxTokens` | 2000–3000 token | 满足学籍异动审批、入学政策解读类输出的长度需求，覆盖完整的业务说明与核验结果 |
| `quoteMaxToken` | 1500 token | 限制引用业务文档的长度，确保核心学籍、招生字段不被截断，保障核验逻辑完整 |
| `temperature` | 0.1–0.3 | 降低随机生成概率，保障学籍核验、政策解释的输出严谨性，避免出现不符合招生规则的内容 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写本地或远程接口地址 | 适配多源模型调用的代理配置需求，支持本地ollama、vllm等部署方式的接入 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具处理结构化数据核验，适配学籍信息的多维度校验需求 |

## 容易做错的三处
- 现象为调用本地ollama模型时返回空内容，状态码为200但无有效输出。原因是ollama服务重启后未正确绑定默认端口，或FastGPT配置的代理地址未指向ollama的实际运行端口。
- 现象为启用图像模型时无法打开图像上传选项。原因是未开启`vision`配置项，或当前使用的模型本身不支持视觉推理能力。
- 现象为配置`AIPROXY_API_ENDPOINT`后，本地vllm模型可正常调用但ollama模型失败。原因是ollama的API路径未正确添加`/v1/chat/completions`后缀，或代理未正确转发ollama的请求路径。

## 怎么确认配好了
- 执行模型测试请求，输入包含学籍号、户籍地址的模拟表单数据，核对输出是否包含对应字段的关联核验结果。
- 查看模型调用日志，确认`maxContext`与`maxTokens`的实际使用值未超过配置上限。
- 检查代理配置项的地址与令牌是否与部署的模型服务一致，验证多源模型调用的连通性。
- 触发批量学籍异动审批的模拟请求，核对输出结果的格式是否符合业务文档的字段要求。
