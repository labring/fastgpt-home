# 招生入学与学籍管理的内部办公与员工服务：表单与交互

## 这个品类的数据长什么样
本品类的日常文档包含入学报名表、学籍信息表、转学申请、招生计划、录取名册、学籍异动审批表等，字段覆盖学生身份标识、居住证明编号、学籍编号、异动申请类型等。数据来源为全国中小学生学籍信息管理系统、地方招生入学平台、户籍和房产数据、学校教务系统，每日更新一次。文档结构多为带固定字段的结构化模板，部分需跨系统拼接数据完成填报。

## 这些特征在「表单与交互」这一环带来什么约束
跨系统的数据来源要求表单需支持多数据源联动校验，避免手动录入的误差；每日更新的频率要求表单的缓存数据需每日同步，确保信息时效性。固定字段的文档结构要求表单需预设必填项与格式校验规则，防止漏填或格式错误。业务出错后果严重的特性要求交互环节增加重复校验与审批确认步骤，避免学籍重复或遗漏。同时，本品类聚焦学籍流转的核心，表单与交互需避免无关字段，聚焦身份与学籍关联的业务逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `formInput` 字段校验规则 | 绑定身份证号、学籍号的格式校验 | 匹配日常文档中身份与学籍标识字段的格式要求 |
| 数据源联动配置 | 关联全国中小学生学籍信息管理系统、地方招生入学平台接口 | 对接指定数据来源完成实时核验 |
| 交互超时设置 | 30–60 秒 | 适配跨系统数据拉取的响应时长 |
| `userSelect` 选项集 | 预设入学申请、学籍异动、政策咨询三类场景 | 匹配日常办公的核心业务场景 |
| 多轮上下文限制 | 前 2–4 轮对话 | 避免冗余数据占用上下文空间，聚焦当前业务流程 |
| 推送触发配置 | 表单提交完成、异动审批通过时触发 | 匹配业务流程的节点要求 |

## 容易做错的三处
- 主动推送消息失败且无法衔接后续问答交互：界面显示推送触发后无响应，问答交互中断。原因是未配置`userSelect`场景的联动触发规则，未绑定业务节点的推送逻辑。
- 上传结构化文档时报错：界面弹出`failed to create post p`类报错。原因是未对入学报名表、学籍信息表等文档做字段拆分预处理，导致文本块生成异常。
- 浏览器不支持语音输入时无法完成信息录入：表单字段无法通过语音完成信息填充。原因是未在`formInput`配置中添加文本快捷输入选项，未适配非语音输入场景。

## 怎么确认配好了
- 测试`formInput`字段校验：输入不符合格式的身份证号或学籍号，确认界面弹出格式错误提示。
- 测试数据源联动：输入已知的学籍号，确认系统自动拉取对应招生平台的关联信息。
- 测试推送触发：完成一笔转学申请提交，确认对应员工账号收到推送消息。
- 测试`userSelect`选项：选择政策咨询场景，确认系统返回对应招生政策的问答内容。
