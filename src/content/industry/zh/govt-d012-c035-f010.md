# 排污许可管理的内部办公与员工服务：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据涵盖排污许可管理相关的全生命周期文档，包括排污许可证申请表、执行报告、自行监测方案、台账记录、变更申请及许可证副本。数据来源为全国排污许可证管理信息平台、企业环保台账、在线监测系统与环境统计系统，更新节奏为季度更新。文档按许可条款、执行限值要求、台账填报规范、变更流程等模块划分，包含排放浓度限值、监测频次、台账留存周期等专属字段，无统一通用单位，部分字段需匹配对应行业的技术规范标准。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据特征对检索召回带来多重约束：多源异构的数据来源，包含实时在线监测数据、季度更新的台账与静态许可文档，需支持多场景的混合召回；季度批量更新的文档需适配增量去重逻辑，避免冗余数据占用存储；文档按许可条款、执行要求等模块划分，需匹配岗位人员的场景化搜索意图；专属字段无通用单位，需规避模糊匹配带来的结果偏差；合规审核的高风险属性，要求召回结果需具备足够的精准度以支撑决策。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.6–0.7 | 排污许可数据的专属字段多，需过滤低相关结果，避免合规审核时的无效信息干扰 |
| `limit` | 前8–12条 | 单条许可文档的内容量较大，过多结果会超出上下文限制，同时保证覆盖不同模块的合规要求 |
| `searchMode` | `vector+keyword` | 数据包含结构化字段与非结构化文档，混合检索可兼顾语义匹配与精准关键词召回 |
| `usingReRank` | 开启 | 多源数据的召回结果需二次排序，提升高合规相关内容的优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 岗位人员的搜索可能使用口语化表述，扩展查询可匹配文档中的规范表述 |
| `collectionIds` | 按文档类型划分集合，如“许可副本”“执行报告”“台账模板” | 可定向检索对应业务场景的文档，缩小召回范围 |

## 容易做错的三处
- 界面搜索测试结果未展示目标自行监测方案文档，原因是`similarity`阈值设置过高，或未开启`datasetSearchUsingExtensionQuery`，无法匹配口语化搜索词与文档内的规范表述。
- 知识库中存在重复的排污许可证副本条目，原因是批量导入季度更新数据时未启用去重校验，导致同一文档的多个版本重复入库。
- 检索返回的结果与查询意图不匹配，原因是`usingReRank`未开启，或`searchMode`仅使用向量检索，未结合关键词匹配结构化的许可限值字段。

## 怎么确认配好了
- 执行单条合规查询，如核对特定行业的排放限值，检查召回结果是否包含对应许可条款的文档。
- 导入季度更新的台账文档后，核对知识库的文档数量变化，确认仅新增未入库的版本，去重逻辑生效。
- 调整`similarity`阈值后，对比不同阈值下的召回结果，确认符合业务场景的精准度要求。
- 查看检索日志，确认混合检索模式与重排功能已正常触发，无报错提示。
