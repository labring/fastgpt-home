# 政府信息依申请公开的内部办公与员工服务：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据来源包括政府信息公开平台、机关档案系统、公文系统、部门业务台账及政府信息公开相关规范。数据更新频率为不定期，随单条申请的办理进度同步更新。日常处理的文档包含政府信息公开申请表、补正告知书、征求第三方意见函、答复书、送达回证、行政复议答辩材料，每份文档包含唯一业务标识、申请人信息、所需信息描述、答复意见、办理状态等字段，以件为基本统计单元。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据来源分散且更新无固定周期，要求HTTP接口支持按需拉取多系统数据，适配临时的申请办理场景。不同类型的业务文档字段差异较大，接口需支持灵活的字段映射规则，适配各类文档的返回格式。由于检索申请所指信息、判断公开属性等环节耗时较长，接口需预留充足的响应时长，避免因超时导致办理超期。同时，接口需具备可靠的身份鉴权能力，保障政务数据的访问安全。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {政务内部系统API密钥}` | 符合政务系统的身份鉴权规范，保障接口访问安全 |
| `variables` | `{"applyId": "{{sys.input.applyId}}", "deptCode": "{{sys.user.deptCode}}"}` | 传递当前申请的唯一标识与处理部门编码，精准匹配对应业务数据 |
| `responseData` | `仅返回申请表、答复书的核心字段` | 减少数据传输量，适配内部办公系统的轻量调用需求 |
| 超时时间 | `600 秒` | 处理依申请公开需跨多系统检索数据，预留充足响应时长 |
| 单次请求数据上限 | `前 20 条` | 单条申请关联的文档数量有限，避免加载冗余数据 |
| 响应数据格式 | `JSON 格式` | 适配FastGPT的上下文解析逻辑，便于后续处理 |

本配置规则适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 调用接口后AI回答未显示答案出处，现象为回答中未附带文档来源的档案编号或申请单号，原因：未将`responseData`中返回的文档来源字段绑定到上下文变量中，无法在回答中追加出处信息。
- 接口调用频繁超时，现象为返回504状态码或超时报错，原因：未设置合理的超时时间，默认时长不足以覆盖跨多系统检索数据的耗时。
- 鉴权失败，现象为返回401未授权状态码，原因：`Authorization`参数格式错误，未使用政务内部系统要求的Bearer令牌格式。

## 怎么确认配好了
- 调用测试接口，检查请求头中是否携带正确格式的`Authorization`参数，确认返回状态码为200。
- 查看`responseData`返回的字段，确认包含当前申请的唯一标识与对应答复书的核心内容，与测试申请单号匹配。
- 验证`variables`参数传递的部门编码是否正确，确认接口返回对应部门的业务数据。
- 模拟超长时间请求，确认接口在`600 秒`内返回有效数据，无超时报错。
