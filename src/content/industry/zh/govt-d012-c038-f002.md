# 政府采购项目的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
本品类数据来源包括中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常处理的文档涵盖采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复等。数据主体涉及采购人单位、财政部门政府采购监管处、采购代理机构及评审专家，文档围绕政府采购全流程产生，包含采购项目编号、预算金额、供应商资质、评审结果等核心字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的数据要求索引支持增量同步，避免全量重建占用过多系统资源。多类型文档覆盖长文本招标文件、短文本中标公告，需适配不同的分块策略以保障语义完整性。政府采购全流程文档需保留项目编号、评审结果等元数据，索引需关联元数据字段用于后续合规溯源。结构化的供应商信用记录与非结构化采购文档混合存储，需统一向量映射规则，确保跨类型数据的检索一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配招标文件、投标文件等长文本的语义完整性，同时避免单块token超出`maxToken`限制 |
| 重叠长度 | 100–200 字符 | 保留分块间的上下文衔接，避免跨块语义断裂 |
| `defaultToken` | 4096 | 匹配多数政府采购文档的平均token量，保障单批次检索的上下文容纳度 |
| 相似度阈值 | 0.75–0.85 | 过滤低关联的非采购类文档，符合政府采购数据的合规检索精度要求 |
| 单次搜索上限 | 前 10 条 | 适配评审专家、监管人员的快速检索需求，避免冗余结果 |
| `maxToken` | 8192 | 适配长评标报告的完整向量存储，保障检索时的上下文完整性 |

## 容易做错的三处
- 现象：上传采购需求、招标文件后，索引列表无对应条目，后台日志显示索引任务超时。原因：未配置适配政府采购文档长度的分块参数，导致单块token超出`maxToken`限制，索引任务中断。
- 现象：调用嵌入模型时提示无可用频道，界面嵌入模型选项为空。原因：未完成对应模型的渠道配置，未在系统中注册合法接入路径。
- 现象：检索供应商信用记录时返回大量无关结果，命中非政府采购类文档。原因：相似度阈值设置过低，未过滤低关联的非目标数据，未关联项目编号元数据进行二次筛选。

## 怎么确认配好了
- 上传单份采购招标文件，查看索引生成状态，确认任务无超时报错。
- 输入采购需求关键词，检索结果中优先命中对应文档，核对返回结果的元数据包含项目编号等核心字段。
- 测试模型接入，确认无可用频道提示消失，模型选项正常显示。
- 模拟每日增量更新，查看索引系统仅同步新增的采购文档，无全量重建日志。
- 确认已部署FastGPT v4.17.0版本，无版本兼容性报错。
