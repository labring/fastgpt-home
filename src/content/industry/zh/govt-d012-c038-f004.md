# 政府采购项目的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
本品类数据主要来自中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常处理的文档包含采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复等，单份文档包含项目编号、供应商资质、评审标准等结构化字段与非结构化文本内容，覆盖采购全流程各环节。

## 这些特征在「工作流编排」这一环带来什么约束
本品类数据来源分散且每日更新，要求工作流需配置多系统对接节点，同步最新的采购文档与供应商信用信息。日常处理的文档类型多样、结构差异明显，需针对采购需求、评标报告等不同文档类型设置专属的解析与分块规则。核心业务环节耗时且出错后果严重，工作流需嵌入校验节点拦截异常数据，避免废标或监管处罚。供应商信用记录需实时获取，需配置定时触发的数据源同步节点，确保资质信息的时效性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次搜索上限 | 前30条 | 政府采购相关文档单份文本量较大，需控制召回结果的冗余度，避免上下文溢出 |
| 最大上下文长度 | 8000–12000 字符 | 匹配政府采购文档的平均文本长度，确保核心评审、合同信息被完整纳入 |
| 节点超时时间 | 600 秒 | 对接财政一体化系统等外部接口时，预留足够的数据拉取与解析时长 |
| `variables` 配置 | 绑定采购项目编号、预算金额字段 | 实现采购流程中各环节的数据自动传递与校验 |
| 重排开关 | 开启 | 对召回的政府采购文档按相关性排序，优先展示核心评审与资质信息 |

## 容易做错的三处
- 现象：工作流中调用知识库搜索时返回结果条数不符合配置，且界面显示上下文长度受限。原因：未针对政府采购文档的长文本特性调整单次搜索上限配置，默认参数限制了召回结果的有效长度。
- 现象：编排应用发布后，通过API调用时返回的业务字段为空。原因：未在`variables`配置中绑定采购项目编号等核心字段，导致数据源无法精准匹配对应项目的文档数据，部分节点`nodeId`与调用参数不匹配。
- 现象：上传采购相关图片或PDF文件后，工作流无法读取解析内容。原因：未开启文件解析节点的对应格式处理开关，未配置文件读取的权限规则，导致外部API调用时无法获取文件内容。

## 怎么确认配好了
- 手动触发工作流的知识库搜索节点，查看返回结果的条数，确认与配置的单次搜索上限一致。
- 对接财政一体化系统接口，测试数据拉取时长，确认未超过配置的节点超时时间。
- 调用API测试接口，检查返回的业务字段是否与`variables`配置的绑定字段一致，核对节点`nodeId`与调用参数是否匹配。
- 上传一份标准采购需求文档，验证工作流是否能正确解析并提取核心采购相关信息。
