# 政府采购项目的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来源包括中国政府采购网、地方政府采购网、财政一体化系统、采购人预算系统及供应商信用记录，更新频率为每日。日常处理的文档包含采购需求、采购计划、招标文件、投标文件、评标报告、中标公告、采购合同、质疑答复等，各文档遵循政府采购法体系的规范格式，包含固定字段，如采购需求含项目预算、采购内容，中标公告含中标供应商名称、中标金额等，数据结构统一且字段明确。FastGPT v4.17.0 版本已适配该品类的数据源同步配置。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日更新的数据源要求模型接入时配置增量同步机制，避免全量拉取占用过多计算资源。政府采购类文档格式规范且字段固定，需配置适配结构化字段的提取逻辑，确保评标报告、中标公告等文档的关键信息准确提取。处理质疑答复、变更公告等高频变动文档时，需限制单次处理的文档数量，防止超时。不同主体的权限差异要求配置角色级的模型调用权限，符合政府采购的监管要求。由于出错后果严重，需配置失败重试与日志留存机制，避免因配置错误导致废标、投诉成立或监管处罚。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 政府采购类文档单批次内容较长，需容纳多份招标文件、评标报告的完整上下文 |
| `temperature` | 0.1–0.3 | 需保证采购相关文本处理的一致性，避免生成不符合监管规范的内容 |
| `toolChoice` | auto | 可根据任务自动选择调用工具或直接生成结果，适配编制采购需求、核对资格等多类场景 |
| `AIPROXY_API_ENDPOINT` | 政府采购数据源专属接口地址 | 用于对接中国政府采购网等官方数据源，保证数据获取的合规性 |
| `quoteMaxToken` | 2000 token | 限制单条引用文档的长度，避免上下文溢出，确保检索结果的可读性 |

## 容易做错的三处
- 现象为开启重排序模型后，知识库检索结果顺序未发生变化。原因是未将重排序模型的调用阈值设置为适配政府采购文档的合理区间，或未在配置中启用重排序的触发条件。
- 现象为本地部署的内容提取模块无法正常提取政府采购文档，而官网在线版本可正常运行。原因是本地部署未同步政府采购文档的专属字段映射规则，或缺少官方数据源的权限配置。
- 现象为工作流执行时仅返回单模型调用结果，无法实现分步处理后的整合输出。原因是未正确配置工作流的节点依赖关系，或未开启多模型调用的相关设置。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，执行一次包含多份政府采购文档的批量检索，核对返回结果的上下文长度是否符合配置的`maxContext`范围。
- 调用重排序模型处理采购需求相关的检索结果，确认结果顺序是否按匹配度重新排列。
- 检查工作流节点的调用逻辑，确认可按需求串联多个模型步骤并隐藏中间结果。
- 验证数据源接口的访问权限，确认可每日同步中国政府采购网的最新公告数据。
