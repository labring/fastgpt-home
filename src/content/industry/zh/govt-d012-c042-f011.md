# 法务合规与重大风险管理的内部办公与员工服务：表单与交互

## 这个品类的数据长什么样
这个品类的日常文档包含合规风险清单、合同法律审核意见、重大事项法律意见书、合规审查表、违规举报调查报告。数据来源为企业合同管理系统、合规风险数据库、法律法规库、案件管理系统、举报平台，更新频率为月度。数据字段涵盖风险类别、审核节点、涉事主体、处理进度等，单位多为条、份、工作日，不同文档的字段结构差异明显，部分文档需关联多系统数据完成完整录入。

## 这些特征在「表单与交互」这一环带来什么约束
月度更新的数据源要求表单的知识库同步周期需匹配更新节奏，避免引入过时的合规数据。多系统关联的录入需求要求表单支持跨数据源的字段联动，比如合同审核表需关联合同系统的唯一编号。不同文档的字段差异要求表单支持自定义字段组，适配合规审查表、举报调查报告等不同场景的录入需求。严重的出错后果要求表单配置必填校验、操作留痕与审核节点确认机制，降低无效录入与误操作风险。最耗时的风险识别与审查环节要求表单简化重复录入步骤，预设常用合规字段，提升录入效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `formInput` 校验规则 | 开启必填项校验，针对风险等级、审核状态等核心字段 | 避免无效的合规表单提交，确保核心审核信息完整 |
| `userSelect` 可选值 | 限定可选值为合规部门、业务部门、外部律所 | 匹配业务主体的固定角色，减少录入时的选项错误 |
| 上下文长度限制 | 8000–12000 字符 | 匹配重大事项法律意见书的典型内容长度，避免截断关键审核信息 |
| 单次召回结果上限 | 前 3 条 | 避免过多无关合规数据干扰大模型的审核判断，聚焦核心风险信息 |
| 重试与超时设置 | 2 次重试，超时阈值为 600 秒 | 应对多源数据调取的延迟，保障跨系统表单提交的稳定性 |
| 数据同步周期 | 月度同步 | 匹配数据源的月度更新频率，确保表单调用的合规数据时效性 |

## 容易做错的三处
- 现象：配置插件单次对话仅提示一次时找不到对应设置项，原因：未在`userSelect`组件的交互规则中配置单次触发锁定，导致插件重复调用。
- 现象：提交合规表单后出现「关联数据未找到」的报错，原因：未在`formInput`组件中配置跨系统字段的联动规则，无法调取合同系统或合规数据库的关联信息。
- 现象：大模型输出的合规意见引入无关背景知识，原因：未设置单次召回结果的上限，召回了超出业务需求的老旧合规数据。

## 怎么确认配好了
- 提交一份测试用的合规审查表，验证必填字段校验是否正常触发，缺失核心信息时能否给出明确提示。
- 查看FastGPT v4.17.0的插件调用日志，确认单次召回的结果条数符合预设的前3条配置。
- 检查数据同步记录，确认同步周期与数据源的月度更新节奏匹配，无频繁同步触发的异常。
- 模拟违规举报线索的录入流程，核对`userSelect`组件的可选值是否与合规部门、业务部门、外部律所一致。
