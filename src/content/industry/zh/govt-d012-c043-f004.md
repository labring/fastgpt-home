# 特种设备安全监管的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
本品类的数据来自特种设备安全监察系统、检验检测机构系统、使用单位台账、作业人员证书库四类核心来源。日常处理的文档包含使用登记证、定期检验报告、维保记录、隐患整改通知书、事故报告、作业人员证书，涵盖设备唯一标识、检验有效期、作业人员资质编号、隐患整改状态等字段。数据更新频率为每月一次，核心业务流程围绕设备生命周期与检验周期展开，需跨多系统整合跨主体的业务数据。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新周期固定，要求工作流需支持跨系统数据源的定时同步配置，确保每月获取最新的设备、人员与整改数据。核心文档字段多且业务关联性强，需在工作流中配置精准的字段映射规则，避免数据错位。最耗时的核对环节占比高，需将自动化校验节点嵌入工作流核心链路，减少人工重复操作。监管场景的出错后果严重，工作流需配置异常告警与校验回退机制，确保错误及时被拦截。

## 配置怎么定
本配置适用于FastGPT v4.17.0
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源同步周期 | 每月1次，每月5日触发 | 匹配本品类数据每月更新的频率 |
| 变量绑定配置 | 绑定`variables`中的设备ID、检验日期、作业人员证号字段 | 覆盖核心文档的必填业务字段 |
| 节点ID配置 | 为隐患整改、资质核对节点分配独立`nodeId` | 确保工作流节点触发逻辑精准匹配业务顺序 |
| 问题分类模型 | 按实测标定 | 适配特种设备监管场景的业务分类标签 |
| 文本提取字段范围 | 前10000字符 | 匹配单份定期检验报告的常规文本长度 |
| 超时阈值 | 600秒 | 适配跨系统数据拉取的合理耗时 |

## 容易做错的三处
-  工作流的问题分类节点AI模型选项为空，无法选择初始化模型。原因是未在系统后台完成特种设备监管场景的AI模型绑定配置。
-  工作流AI对话组件的注释触发时机报错，提示stream回复未完成。原因是未正确配置`nodeId`对应的节点触发逻辑，导致在stream回复过程中触发了后续操作。
-  工作流文本提取结果JSON为空。原因是未正确指定提取字段范围，导致未匹配到有效文本内容。

## 怎么确认配好了
-  进入工作流编辑页面，查看问题分类节点的AI模型下拉选项，确认已加载绑定的特种设备监管场景模型。
-  触发测试运行，查看工作流的运行日志，确认无模型绑定报错或节点触发异常。
-  提交一份模拟的定期检验报告，查看文本提取结果是否生成有效JSON结构。
-  检查数据源同步任务的运行记录，确认每月自动同步任务按配置时间正常触发。
