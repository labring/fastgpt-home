# 环境执法与监测监管的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
生态环境执法支队、监测站等主体的日常数据，来自在线监控平台、污染源自动监测数据、生态环境执法系统、第三方检测报告。日常文档包括现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书，单份文档同时包含结构化字段（如检测点位、污染物浓度、执法时间）与非结构化文本（如工况描述、整改要求），数据更新频率为每日，内容围绕污染物监测、执法流程与整改跟踪展开。

## 这些特征在「向量模型与索引」这一环带来什么约束
每日更新的数据特征要求向量索引支持增量更新，避免全量重建占用过多系统资源。多类型文档的混合存在，需要向量模型同时适配结构化数值字段与自然语言文本的向量化，确保不同类型内容的检索一致性。执法相关文档的证据属性，要求检索结果需具备高可信度，需严格控制检索范围与结果排序逻辑。多来源数据的格式差异，需要在索引前完成统一的字段映射与标准化处理，避免检索时出现格式不兼容问题。

## 配置怎么定
本文适配FastGPT v4.17.0版本，以下配置项均可在知识库管理界面的向量模型与索引模块中完成设置：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配现场检查记录、监测报告的单块文本长度，避免单块内容过于分散导致上下文丢失 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，确保执法流程类文档的逻辑连贯性 |
| `defaultToken` | 按实测标定 | 适配不同嵌入模型的token限制，避免向量化时出现文本截断错误 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非执法相关数据，保障检索结果的证据相关性 |
| 单次搜索上限 | 前10条 | 控制检索结果数量，避免内部办公场景下的信息过载 |
| `maxToken` | 4096 token | 适配执法文书的长文本检索需求，确保完整的证据链上下文可被完整向量化 |

## 容易做错的三处
- 现象：添加阿里千问text-embedding-v3并配置API密钥后，界面提示无可用渠道，default分组下无法调用该模型。原因：未在FastGPT的渠道配置中为该模型指定正确的接入节点，或未开启对应模型的调用权限。
- 现象：知识库问答经过重排后检索速度过慢，单次请求耗时超过60秒。原因：知识库分块长度设置过大，导致单批次检索的向量数据量过高，或嵌入模型的调用延迟较高。
- 现象：检索结果中混杂大量非执法相关的文档，字段为空的比例超出预期。原因：相似度阈值设置过低，未过滤低匹配度的内容，或未完成多来源数据的字段标准化处理。

## 怎么确认配好了
- 上传一份标准的现场检查记录作为检索触发文本，执行检索操作，查看返回结果是否包含同类型执法文档且匹配度符合预期。
- 查看向量索引的更新日志，确认每日增量更新任务正常执行，无失败记录。
- 测试嵌入模型的调用流程，查看是否能正常生成向量数据，无报错提示。
- 调整相似度阈值，验证检索结果的数量是否随阈值变化符合预期逻辑。
