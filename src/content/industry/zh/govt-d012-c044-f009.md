# 环境执法与监测监管的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源为在线监控平台、污染源自动监测数据、生态环境执法系统、第三方检测报告，更新频率为每日。日常文档包含现场检查记录、采样记录、监测报告、责令改正决定书、行政处罚决定书，数据结构包含执法关联标识、监测点位、污染物浓度、工况记录、处罚文号等字段，单位涉及毫克每立方米、采样体积、执法时长等，单份文档内容跨度从数十字的现场短记录到数千字的完整监测分析报告不等。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据每日更新且来源分散，要求模型接入时支持批量拉取不同系统的结构化与非结构化数据，需适配多源数据格式对齐规则。文档类型涵盖短记录到完整报告，上下文长度差异较大，需灵活调整上下文窗口与生成长度参数。执法与监测数据涉及合规判定，模型调用需保证结果可溯源，同时需适配执法文书生成的长文本输出需求。数据关联依赖执法编号等唯一标识，模型工具调用需精准匹配关联字段，避免数据错位影响执法判定结果。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 环境执法场景专属代理地址 | 适配生态环境系统的专属网络访问权限，规避跨域访问限制 |
| `AIPROXY_API_TOKEN` | 绑定执法场景的专属密钥 | 隔离不同业务场景的模型调用权限，保障执法数据访问安全 |
| `maxContext` | 8000–12000 token | 适配从现场短记录到完整监测报告的上下文长度需求 |
| `temperature` | 0.2–0.4 | 降低生成随机性，保证执法文书、合规判定的内容严谨性 |
| `maxTokens` | 2000–3000 token | 控制单轮生成的执法文书长度，避免超出系统输出限制 |
| `toolChoice` | auto | 自动触发工具调用，适配多源数据整合、文书生成的复杂需求 |

## 容易做错的三处
- 现象：调用模型时返回“模型不兼容”或“未找到对应模型”的报错，原因是未在aiproxy中提前配置对应模型的接入权限与参数映射规则。
- 现象：AI对话输出仅显示最终结果，未展示大模型的思考过程，原因是未开启思考过程记录与输出的对应配置开关。
- 现象：docker compose部署后无法调用oneapi服务，日志中显示连接超时或权限不足，原因是未在环境变量中配置oneapi的接入端口与密钥参数。

## 怎么确认配好了
- 传入单份现场检查记录与关联监测数据作为测试输入，验证模型能正确整合数据并生成合规判定内容，调整配置参数后观察结果变化，确认配置生效。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的参数被正确加载，无权限报错或连接失败提示。
- 触发工具调用动作，验证模型能自动调用对应工具获取多源数据，确认工具调用配置生效。
- 调整`temperature`参数区间，观察生成内容的严谨性变化，确认参数对生成结果的影响符合业务需求。
