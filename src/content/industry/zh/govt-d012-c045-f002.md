# 用地预审与规划许可的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据主要来自国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据。日常处理的文档包括用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件。数据更新频率不定期，核心字段包含项目选址范围、用地规模、规划管控要求、红线坐标等，无统一固定的批量更新周期，单次更新数据量随单个项目的审批进度产生波动。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且格式多样，包含结构化审批文档、带坐标的红线图、非结构化规划文本，对索引的多源数据兼容能力提出要求。数据更新无固定周期，需支持增量索引与实时同步配置，避免因审批进度变化导致的索引滞后。核心字段包含空间坐标与管控规则，向量模型需适配地理空间特征的语义提取，同时因出错后果严重，需保障检索召回的准确性与完整性，避免遗漏关键管控条款。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本的界面与参数逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类规划类文档的段落长度，避免拆分破坏管控规则的语义完整性 |
| 重叠长度 | 100–150 字符 | 保障跨分块的管控条款不被割裂，提升检索连贯性 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 匹配规划管控规则的严格匹配需求，避免误召回无关项目数据 |
| 单次搜索上限 | 前 8 条 | 覆盖单个项目审批所需的多份前置文档，平衡检索效率与召回范围 |
| maxToken | 4000 token | 适配大模型上下文窗口，完整承载检索到的规划条款与项目数据 |
| defaultToken | 200 token | 用于短文本字段的向量提取，保障基础字段的检索精度 |

## 容易做错的三处
- 调用chunk模式调用pushdata api上传数据后，界面长期显示「索引中」状态，无进度更新。原因是分块长度设置过大，单批次处理数据量超出系统默认处理上限，导致索引任务阻塞。
- 检索结果中混入大量无关的不动产登记类数据。原因是未针对该品类的空间坐标、规划管控字段设置专属过滤规则，召回范围未限定在用地预审与规划许可相关文档内。
- 最后一组索引任务始终无法完成。原因是未配置合理的maxToken参数，长文本分块超出大模型上下文窗口，导致嵌入生成失败，索引任务无法收尾。

## 怎么确认配好了
- 上传单份典型的规划条件文档，检查分块后的文本是否保留完整的管控条款，无明显语义割裂。
- 发起针对某项目选址范围的检索，确认召回结果包含该项目的前置审批文档与管控规则，无无关数据混入。
- 测试增量上传单份更新后的红线图数据，确认索引进度正常更新，无长期阻塞情况。
- 调用embedding模型接口，验证短文本字段的嵌入结果正常生成，无空值返回。
