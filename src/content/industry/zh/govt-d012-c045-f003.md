# 用地预审与规划许可的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源包括国土空间规划一张图、项目审批监管平台、土地利用现状库、生态保护红线数据，更新频率不定期。日常生成的文档包含用地预审与选址意见书、建设用地规划许可证、建设工程规划许可证、红线图、规划条件，文档结构包含项目编号、选址范围、用地规模、管控要求等字段，字段单位多为公顷、平方米，部分文档附带矢量图层数据。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新无固定周期，要求多轮对话需实时拉取最新的国土空间规划图层与审批数据，避免使用过期信息。文档包含矢量图层与结构化字段，提示词需区分文本检索与空间坐标校验的场景，引导用户补充必要的项目信息。用地预审涉及发改、住建、生态等多部门前置条件协调，多轮对话需逐步引导用户补充材料，避免一次性要求过多内容导致交互中断。内部办公场景下，员工需快速核对项目选址与规划管控的冲突，提示词需预设常见的审批风险点，辅助快速排查。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 用地预审相关文档包含规划条件与红线图文本，该长度可完整覆盖单条管控要求或地块范围描述 |
| 重叠长度 | 150–200 字符 | 避免跨块的管控要求被拆分，确保多轮对话中检索到的内容连贯 |
| 单次搜索上限 | 前 6 条 | 匹配用地预审需核对的多维度管控规则，覆盖主要审批要点 |
| 最大上下文 | 12000 token | 适配多轮对话中需回顾的项目审批历史与前置材料信息 |
| `variables` 绑定 | 项目编号、用地规模字段 | 自动填充对话中的结构化数据，减少人工输入 |
| `messages` 上下文保留 | 最近 10 轮对话 | 符合内部办公中员工需回溯多轮审批沟通的场景 |

## 容易做错的三处
- 调用对话接口返回422状态码。原因是未绑定项目编号、用地规模等专属`variables`参数，接口无法匹配当前处理的用地预审项目数据。
- 多轮对话检索结果出现重复的规划管控条款。原因是分块长度设置不合理，将同一条管控要求拆分为多个独立块，且未配置重叠长度关联上下文。
- 新对话弹窗无法隐藏且无法通过常规配置修改。原因是直接修改前端源码未遵循私有部署的代码规范，未定位到对应组件的入口文件。

## 怎么确认配好了
- 发起包含项目编号的测试对话，核对`variables`参数是否自动填充至对话上下文。
- 输入包含红线范围的查询，检查检索结果是否覆盖完整的管控要求，无重复或截断内容。
- 模拟多轮审批沟通，确认对话历史保留的轮次符合预设配置，且未出现上下文溢出。
- 验证私有部署环境下的代码修改入口，确认新对话弹窗的配置项可正常调整。
