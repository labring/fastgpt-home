# 社会救助与低保审核的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
本品类的典型文档包括低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料、救助审批表。数据来源为低收入人口动态监测平台、居民家庭经济状况核对系统以及公安人社医保住建税务共享数据，更新频率为月。数据字段包含家庭收入财产明细、家庭成员关系、入户调查记录、审批信息等，单位多为金额、人数、日期等，为跨部门异构的结构化与半结构化数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
跨部门异构数据要求模型接入需适配多源数据格式，需配置支持多数据源的模型调用；月更频率无需超高频上下文刷新，可限制上下文更新间隔；复杂字段需精准提取家庭经济状况、成员关系等核心信息，对模型输出置信度要求较高；最耗时的核对环节需配置工具调用能力，支持跨部门数据的自动核对；出错后果严重，需严格控制模型输出的准确性，避免错保漏保。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token | 适配家庭经济核对相关文档的总长度 |
| `temperature` | `0.1–0.3 | 保障核对结果的高置信度，避免主观偏差 |
| `toolChoice` | auto | 支持自动调用跨部门数据核对工具 |
| `maxTokens` | `1000–2000 token per rerank task | 限制rerank模型的输入长度，避免显存溢出 |
| `quoteMaxToken` | `2000–3000 字符` | 保留核心核对报告的原文片段供复核 |
| `AIPROXY_API_ENDPOINT` | 部署的内部API地址 | 对接内部模型渠道 |
| `AIPROXY_API_TOKEN` | 平台分配的鉴权密钥 | 完成模型渠道的身份验证 |

## 容易做错的三处
- 现象：OneAPI页面无可用渠道，渠道列表为空。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或配置内容存在格式错误。
- 现象：rerank模型运行后显存持续占用，最终耗尽显存。原因：未设置`maxTokens`限制rerank任务的输入长度，未开启显存自动回收配置。
- 现象：工作流文本提取节点无法选择模型，下拉框无可选选项。原因：未将已接入的模型正确绑定到工作流节点，或`toolChoice`配置不符合节点的模型接入要求。

## 怎么确认配好了
- 访问FastGPT v4.17.0的OneAPI页面，确认渠道列表中出现已配置的模型渠道。
- 上传一份低保申请表文档，运行解析任务，查看输出的家庭经济状况、成员关系等字段是否完整。
- 启动rerank模型测试任务，查看GPU显存占用在运行后未持续攀升，保持在合理区间。
- 进入工作流编辑页面，打开文本提取节点的模型选择下拉框，确认可选择已配置的模型。
