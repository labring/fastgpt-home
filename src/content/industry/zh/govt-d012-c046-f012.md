# 社会救助与低保审核的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
该品类的数据主要来自低收入人口动态监测平台、居民家庭经济状况核对系统及公安、人社、医保、住建、税务等跨部门共享数据，更新频率为月度。日常处理的文档包含低保申请表、家庭经济状况核对报告、入户调查表、民主评议记录、公示材料、救助审批表，核心字段围绕家庭收入、财产状况、成员关系、救助资格展开，单份文档多为结构化表单与佐证材料结合的格式。

## 这些特征在「部署与升级」这一环带来什么约束
月度更新的跨部门共享数据要求部署时配置定期同步的调度规则，确保审核数据的时效性。多类型结构化文档与佐证材料的处理需求，要求升级环节保留原有表单解析逻辑的兼容性，避免中断日常办公流程。跨部门数据来源分散的特点，要求部署阶段配置多数据源连接参数，保障数据拉取的稳定性。救助审核的严谨性要求，部署时需强化数据校验与备份机制，降低错保漏保风险。同时，月度批量数据更新可能带来的服务器负载波动，要求部署时预留合理的资源配额，避免服务卡顿。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://民政业务用户名:业务密码@服务器地址:27017/fastgpt_mz?authSource=admin` | 用于存储低保审核的结构化文档与核对数据，需指定对应民政业务数据库的认证信息与库名 |
| `PG_URL` | `postgresql://核对业务用户名:业务密码@服务器地址:5432/mz_hedui?sslmode=require` | 存储跨部门共享的结构化核对数据，需启用SSL保障数据传输安全 |
| `REDIS_URL` | `redis://:缓存密码@服务器地址:6379/0` | 用于缓存高频访问的核对数据与会话信息，数据库索引设为0避免与其他业务冲突 |
| `DB_MAX_LINK` | `20–30` | 适配月度数据更新的批量拉取需求，避免连接数过高导致服务器资源耗尽 |
| `STORAGE_S3_ENDPOINT` | `按本地存储或云存储服务商提供的端点地址配置` | 用于存储入户照片、公示材料等佐证文件，需匹配实际存储介质的访问地址 |
| `FILE_TOKEN_KEY` | `按实测标定` | 用于生成图片访问的临时令牌，需保障令牌有效期与审核流程时长匹配 |

## 容易做错的三处
- 现象：Docker容器持续重启，无法正常启动服务。原因：服务器配置为2核8G，未预留足够的内存资源用于加载核对数据与模型，导致进程被系统强制终止。
- 现象：Rerank模型未正常生效，搜索结果排序不符合预期。原因：未在配置中指定rerank模型的部署地址，或未将模型接入FastGPT的检索链路。
- 现象：知识库中配置的图片URL无法在对话中正常展示。原因：未配置`FILE_TOKEN_KEY`生成临时访问令牌，或前端域名`FE_DOMAIN`未正确绑定图片存储地址，导致浏览器无法加载图片资源。

## 怎么确认配好了
- 运行数据库连接校验脚本，验证`MONGODB_URI`与`PG_URL`配置的连接有效性。
- 手动触发一次数据同步任务，确认跨部门共享数据可按配置的调度逻辑完成拉取。
- 上传一份标准低保申请表，确认文档解析后的字段与业务表单结构一致。
- 配置测试图片的存储地址与访问令牌，验证对话中可正常加载图片资源。
