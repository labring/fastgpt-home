# 行政处罚案卷办理的内部办公与员工服务：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，每日更新。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，以违法事实与处罚决定为核心，需形成可追溯的处罚证据链与完整文书链，字段覆盖执法主体、涉案主体、违法情形、裁量依据、文书编号等关键信息。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据来源分散且包含非结构化音视频与结构化文书，接口需支持多类型数据接入。每日更新的频次要求接口具备稳定的批量调用能力，避免因调用延迟导致数据同步滞后。文书数量多且需严格溯源，接口需携带唯一标识关联原始执法数据，同时需兼容不同执法系统的字段格式差异。处罚案卷的合规性要求高，接口返回的字段需完整覆盖执法流程节点，无法遗漏关键环节的记录。

## 配置怎么定
以下配置适用于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带执法系统专属令牌，有效期不超过 7 天 | 匹配行政执法数据的权限管控要求，避免令牌泄露导致敏感案卷泄露 |
| `variables` | 预设执法主体编码、文书类型编码两类固定参数 | 简化接口调用时的重复录入，适配多执法主体的批量调用场景 |
| `responseData` | 仅返回已校验的案卷核心字段，不包含原始采集的冗余影像数据 | 降低接口传输带宽占用，符合执法数据的最小必要传输原则 |
| 超时阈值 | 600 秒 | 适配执法笔录、影像等大体积数据的上传与解析时长 |
| 批量调用上限 | 前 10 条 | 匹配每日更新的案卷处理节奏，避免单次调用过载 |

## 容易做错的三处
- 现象为调用接口返回`401 Unauthorized`状态码，原因是未正确配置`Authorization`参数，或令牌过期未及时更新。
- 现象为接口返回的`responseData`字段缺失送达回证编号，原因是未在调用时传入对应文书类型的参数，导致接口未返回完整案卷字段。
- 现象为批量调用时接口超时，原因是单次调用的案卷数量超过预设上限，且未调整合理的超时阈值。

## 怎么确认配好了
- 调用接口携带`Authorization`参数，验证返回状态码为`200 OK`，确认权限配置生效。
- 查看`responseData`返回字段，确认包含预设的执法主体、涉案主体、处罚决定三类核心字段，核对字段完整性。
- 发起批量调用，检查接口返回的案卷数量符合预设的调用上限，确认批量逻辑正常。
- 等待24小时后，检查接口同步的案卷数据与执法系统的更新记录一致，确认定时调用配置生效。
