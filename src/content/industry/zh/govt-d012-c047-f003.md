# 行政处罚案卷办理的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的典型主体为市场监管、生态环境、交通运输、应急管理、城管等执法机构，日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证等。数据来源包括行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日同步。单案卷数据包含固定证据材料、裁量依据、文书模板、送达记录等，字段覆盖违法主体信息、执法节点状态、证据关联标识等，数据无统一标准化格式，需按单案卷维度隔离。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来源多源异构且需按单案卷隔离，多轮对话需绑定专属标识确保上下文不跨案卷；每日更新的数据源要求知识库支持增量同步，避免旧数据干扰当前办案。核心办案环节依赖准确的证据与文书匹配，提示词需引导调用对应案卷内的文档，避免生成脱离证据的内容。同时，执法合规性要求严格，对话需限制生成未经审核的内容，仅调用已入库的执法文档。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 适配单案卷多份文书的总长度，避免截断关键证据内容 |
| 单次搜索上限 | 前 6 条 | 匹配单案卷核心文档数量，避免引入无关跨案卷材料 |
| `chatId` 绑定规则 | 与办案案卷ID一一对应 | 确保多轮对话仅关联当前办案的专属文档与上下文 |
| `variables` 配置 | 绑定执法主体类型、案卷状态变量 | 引导提示词适配不同执法场景的文书生成规则 |
| `messages` 历史保留 | 保留当前案卷的 20 轮以内对话 | 避免上下文过长干扰当前办案环节的提示逻辑 |
| 问题优化开关 | 开启 | 辅助梳理执法人员的模糊提问，精准匹配对应执法文档 |

## 容易做错的三处
- 现象：调用API返回的答案与平台测试界面的输出存在差异。原因：未在API请求中绑定`chatId`与当前办案案卷ID，导致对话上下文未隔离，调用了非目标案卷的知识库内容。
- 现象：生成的处罚文书遗漏关键证据内容。原因：未限制单次搜索上限，引入了无关的跨案卷文档，导致提示词混淆了不同案件的证据信息。
- 现象：嵌入网页的悬浮对话框无法加载历史对话记录。原因：未正确传递`messages`参数的历史对话内容，导致上下文无法正常加载。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本的功能逻辑。
- 发起平台测试对话，输入当前案卷的违法主体名称，核对返回内容是否仅关联该案卷的已上传文档。
- 调用API时携带`chatId`参数，对比平台测试界面与API返回的答案，确认结果一致。
- 嵌入悬浮对话框后，发送多条连续提问，确认历史对话内容被正确保留并关联当前案卷。
- 检查`variables`配置，确认执法场景变量已绑定，验证提示词是否能引导调用对应执法文书模板。
