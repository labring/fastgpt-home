# 行政处罚案卷办理的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
本品类数据来源于行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常产生的执法文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证等，数据字段涵盖违法主体标识、违法事实详情、裁量基准关联项、文书编号及送达状态等，单份核心文档的数据量随附带的证据影像、附件数量浮动。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据来源分散、文档类型多且更新频率固定，对工作流编排带来多重约束。多源数据需配置跨系统拉取节点完成整合，每日更新节奏要求工作流触发逻辑适配日级调度，避免重复处理或遗漏新增案卷。不同类型执法文书结构固定，需针对现场检查笔录、处罚决定书等分别配置字段校验规则。证据链追溯要求保留节点操作日志，确保处罚流程可溯源，同时出错后果为处罚被撤销、行政复议败诉或案卷评查不合格，需加入前置校验与复核环节降低风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 全局变量配置 | 绑定`variables`中的违法主体、违法事实、处罚依据字段 | 匹配本品类执法案卷的固定数据结构，保障跨节点数据传递准确 |
| 节点触发规则 | 按`variables`中案卷状态字段变更触发 | 适配行政处罚办理的阶段流程，确保节点仅在对应环节执行 |
| 知识库搜索范围 | 指定对应执法领域的专属文件集合 | 限定检索边界，符合本品类精准匹配监管数据的需求 |
| 单次搜索上限 | 前10条结果 | 限定返回数据量，避免节点过载 |
| 大模型调用温度 | 0.6–0.8 | 平衡法律文书生成的严谨性与内容灵活性 |
| 节点超时设置 | 600秒 | 适配多源数据拉取、文书生成的常规耗时 |
| `nodeId`关联配置 | 绑定法制审核节点与文书生成节点 | 确保流程中关键环节的执行顺序与数据关联正确 |

## 容易做错的三处
- 现象为全局变量调试至下个节点时提示输入为空，原因为未将全局变量正确绑定至对应节点的输入参数中。
- 现象为选择变量引用方式指定大模型时无温度设置按钮，原因为未进入大模型节点的高级配置面板，仅在基础配置中选择了变量引用。
- 现象为无法在知识库搜索节点中指定特定文件集合搜索，原因为未提前将目标文件添加至专属知识库并绑定该知识库至搜索节点。

## 怎么确认配好了
- 触发测试案卷的工作流，查看节点日志中全局变量的传递值是否与输入的案卷信息一致。
- 进入大模型节点的配置面板，确认温度参数已设置为对应取值。
- 检查知识库搜索节点的绑定配置，确认已关联指定的执法领域专属知识库。
- 模拟案卷状态变更，验证对应业务节点是否按预期触发执行。
