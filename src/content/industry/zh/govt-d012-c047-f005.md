# 行政处罚案卷办理的内部办公与员工服务：工具调用与插件

## 这个品类的数据长什么样
本品类数据来自行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，每日更新。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，以违法事实与处罚决定为核心，需形成可追溯的证据链与完整文书链，字段覆盖执法主体、涉案主体、违法情节、裁量依据、文书编号等。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且包含非结构化的执法记录仪影像，要求工具调用支持多源数据拉取与格式转换。各类执法文书结构固定但字段要求严格，工具需精准匹配预设的字段提取规则。每日更新的执法数据需高频同步，工具调用需适配高频请求场景。需保证处罚决定与证据链的一致性，工具输出需可追溯，避免出现字段缺失或逻辑矛盾，同时需兼容不同执法部门的文书格式差异。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多环节按需调用工具的场景，覆盖笔录生成、法条匹配、案卷审核等不同办公需求 |
| 单次工具调用超时 | 60 秒 | 匹配执法文书生成的常规响应时长，避免长时间阻塞内部办公流程 |
| 工具返回字段提取规则 | 按执法文书字段映射配置 | 对应现场检查笔录、处罚决定书等固定文档结构，确保提取内容精准匹配业务要求 |
| 插件请求并发数 | 前 3 条 | 适配多数执法系统的接口限流规则，避免触发访问限制 |
| 上下文窗口大小 | 8000–12000 token | 容纳多份执法笔录、证据清单等内容，支撑完整案卷的工具调用分析 |

本页面配置适用于 FastGPT v4.17.0

## 容易做错的三处
- 导入自定义插件时提示 internal server error。原因是插件配置的接口地址未适配执法系统的内网访问规则，或请求头未携带合法的身份校验参数。
- 调用MCP工具时提示仅支持stdio进程。原因是当前版本未启用SSE协议的工具调用适配，需确认版本兼容性。
- 工具调用后提取的接口字段为空。原因是未配置与执法文书字段匹配的提取规则，导致无法定位目标内容。

## 怎么确认配好了
- 导入插件后，使用模拟执法接口发起测试请求，检查返回状态码是否为200。
- 将`toolChoice`设为auto后，发起包含多环节需求的测试，确认工具可按需自动调用对应功能。
- 配置字段提取规则后，上传一份标准现场检查笔录，检查提取的执法主体、违法时间等字段是否匹配预设规则。
- 发起连续测试请求，确认未触发接口限流或超时报错。
