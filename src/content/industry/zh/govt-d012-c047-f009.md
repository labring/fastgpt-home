# 行政处罚案卷办理的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自市场监管、生态环境、交通运输等执法机构的行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，数据字段涵盖违法主体、违法事实、裁量基准、法律条款、处罚决定等，无特殊自定义单位字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
多来源的分散数据要求模型接入支持多种文档格式的解析，避免因格式不兼容丢失笔录、决定书内容。每日更新的业务数据要求配置适配高频同步需求，保障模型调用的实时性。多份文档组成的单案卷要求足够的上下文承载能力，避免关键信息被截断。执法文书的规范性要求限制模型输出的随机性，同时需保证结构化提取的准确性，降低处罚被撤销、案卷评查不合格的风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单案卷包含多份执法文档的总长度，避免上下文溢出导致关键信息丢失 |
| `maxTokens` | 2000–3000 token | 覆盖处罚决定书、询问笔录等长文档的结构化提取与内容生成需求 |
| `temperature` | 0.2–0.4 | 降低模型输出的随机性，保证执法文书生成的规范性与内容准确性 |
| `toolChoice` | auto | 按需启用工具调用，完成现场检查笔录、证据清单的结构化字段提取 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的合规地址填写 | 适配国内执法场景的模型调用链路要求 |
| `AIPROXY_API_TOKEN` | 与部署服务商绑定的专属密钥 | 保障模型调用的身份合法性与链路安全性 |

## 容易做错的三处
- 现象：模型返回结果未包含上传文档的相关信息，但`FilesContent`标签内存在完整文档内容。原因：未正确配置`maxContext`参数，导致上传文档被截断或未纳入模型上下文范围。
- 现象：仅能设置模型名称，无法调整`maxTokens`、`temperature`等参数。原因：模型接入环节仅填写了模型标识，未绑定对应配置项，导致参数无法生效。
- 现象：启用工具调用后，模型未输出前置思维过程，仅返回工具调用结果。原因：工具调用配置与思维过程输出参数未同步启用，导致推理链路省略中间步骤。

## 怎么确认配好了
- 上传单份执法笔录文档，触发内容提取任务，检查模型返回结果是否包含文档中的核心信息。
- 调整`temperature`参数值，观察模型生成内容的变化趋势，验证参数是否生效。
- 配置工具调用后，触发证据清单结构化提取任务，检查是否正确调用工具完成字段提取。
- 测试模型调用链路，核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容，验证连通性。
