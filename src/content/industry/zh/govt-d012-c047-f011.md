# 行政处罚案卷办理的内部办公与员工服务：表单与交互

## 这个品类的数据长什么样
本品类的数据来源为行政执法办案系统、执法记录仪影像、国家企业信用信息公示系统及部门监管数据库，更新频率为每日。日常文档包含现场检查笔录、询问笔录、证据清单、行政处罚事先告知书、听证告知书、处罚决定书、送达回证，以违法事实与处罚决定为核心，需形成可追溯的处罚证据链与完整文书链。数据字段涵盖执法主体信息、违法情节描述、裁量基准匹配结果、法制审核意见等，无额外预设统计指标。

## 这些特征在「表单与交互」这一环带来什么约束
数据来源分散且每日更新，要求表单交互需支持多源数据快速调取与校验。日常文档格式固定且字段明确，需表单组件与现有执法文书字段一一匹配，避免录入偏差。处罚证据链需可追溯，要求交互环节保留完整操作日志与字段填写记录。执法机构内部需遵循法制审核流程，表单需设置分级权限控制，确保不同岗位仅能编辑对应环节字段。出错后果为处罚撤销、复议败诉或案卷评查不合格，要求表单需设置必填项校验与格式自动修正，减少人工失误。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `formInput` 组件配置 | 开启必填项校验、实时格式校验，限定输入长度为100–5000 字符 | 匹配执法笔录的内容长度要求，减少录入偏差 |
| `userSelect` 组件配置 | 限定可选值为执法主体名录与处罚类型清单 | 确保执法主体、处罚类型字段的取值符合监管规范 |
| 表单字段绑定 | 与现场检查笔录、询问笔录等文书字段一一对应 | 匹配本品类固定格式的执法文档，避免字段错位 |
| 知识库调用范围 | 绑定对应执法领域的专属知识库 | 精准匹配市场监管、生态环境等执法场景的法律与监管数据 |
| 超时设置 | 300–600 秒 | 适配多源数据调取与文书生成的耗时需求 |
| 单次召回条数 | 前5–8 条 | 适配多证据链的调取需求，避免信息过载 |

## 容易做错的三处
- 现象：配置了`formInput`的必填项校验后，仍出现空白核心字段提交。原因：未将违法情节描述、执法主体等核心文书字段加入校验绑定范围，导致校验逻辑失效。
- 现象：调用知识库时仅返回单条结果。原因：未调整单次召回条数的配置，默认取值仅匹配单条结果，未适配本品类多证据链的调取需求。
- 现象：文本提取失败后触发指定回复，但流程未等待用户输入新内容。原因：未开启工作流的用户等待节点配置，直接终止了交互流程，不符合执法人员补充信息的操作需求。

## 怎么确认配好了
- 打开表单编辑页面，核对绑定的字段是否与现场检查笔录、询问笔录等执法文书的字段完全一致。
- 测试`formInput`组件的必填项校验，故意留空核心字段后提交，确认触发对应提示。
- 切换不同岗位账号，测试是否仅能编辑对应权限范围内的表单字段。
- 触发文本提取失败的场景，确认流程会暂停并等待用户输入新的内容。
