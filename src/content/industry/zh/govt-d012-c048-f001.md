# 行政许可审批的内部办公与员工服务：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据来源为全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统、电子证照库，更新频率为每日。日常处理的文档包括办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书、许可证照，数据字段包含事项编码、申请主体信息、材料清单、审批状态、证照编号等，每个许可事项对应固定的法定办理条件与设定依据，数据结构严格匹配法定审批流程节点。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据来源包含政务平台事项库与部门业务系统，每日更新的要求决定接口需支持每日全量或增量同步数据，需匹配政务系统的鉴权规则。法定固定的字段结构要求接口返回数据需严格匹配法定字段，不得遗漏或新增非法定字段。跨部门调取电子证照的需求要求接口支持多系统对接，需传递对应部门的系统标识，确保数据格式适配法定办理条件与设定依据的校验逻辑。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 政务系统颁发的服务账号密钥 | 匹配政务部门业务系统的鉴权规则 |
| `responseData` | 仅返回法定字段子集 | 避免非法定字段导致审批校验失败 |
| `variables` | 绑定事项编码与部门标识 | 精准对接对应部门的审批系统 |
| 同步周期 | 每日凌晨 2 点 | 匹配数据日更频率 |
| 接口超时时间 | 600–1800 秒 | 适配跨部门调取电子证照的耗时 |

## 容易做错的三处
- 接口返回401未授权状态码，无法调取政务部门的行政许可事项数据。原因是未使用政务系统指定的`Authorization`参数，鉴权配置不符合政务系统的鉴权规则。
- 接口返回空的文档数据，无法读取本地办事指南、申请表等文件。原因是未使用适配本地文件夹路径的api脚本，未正确配置文档导入路径。
- 部署两套FastGPT实例时，接口无法实现知识库的跨实例调用，导致内部办公流程割裂。原因是未正确配置`variables`参数绑定知识库与接口实例的关联关系，未建立两套实例的参数关联。

## 怎么确认配好了
- 调用配置好的接口，检查返回的`responseData`中包含事项编码、审批状态等法定字段，确认数据格式符合要求。
- 查看接口同步日志，确认每日凌晨2点触发同步任务，数据更新频率符合日更要求。
- 调用接口传递`variables`参数绑定的事项编码与部门标识，确认接口对接了正确的审批系统。
- 测试接口超时请求，确认在600–1800秒内完成跨部门调取电子证照的操作，无超时报错。
