# 行政许可审批的内部办公与员工服务：向量模型与索引

## 这些特征在「向量模型与索引」这一环带来什么约束
数据每日更新的特性要求索引支持增量构建，避免全量重建带来的资源消耗与时间延迟。文档类型涵盖结构化申请表字段、半结构化审批通知书及非结构化办事指南，要求向量模型适配多类型文本的语义对齐能力。行政许可事项边界明确，需严格匹配对应事项的办理条件，因此索引需按事项维度分组，避免跨事项的无效匹配。电子证照的二进制格式关联需求，要求向量生成环节支持少量非文本数据的转换，同时固定字段的特性无需处理动态新增字段的适配逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配办事指南、审批决定书等长文本的语义完整性，避免分块断裂影响匹配精度 |
| 重叠长度 | 100–150 字符 | 覆盖跨分块的关键审批条件表述，减少语义割裂 |
| 相似度阈值 | 0.75–0.85 | 匹配行政许可事项的严格匹配要求，避免低关联的申请材料被误判 |
| 最大上下文 | 8192 token | 支持完整加载单事项的办理条件与关联审批文档，满足内部办公的全流程上下文需求 |
| `defaultToken` | 4096 token | 适配单条审批材料的向量计算标准长度，统一不同文档的向量生成基准 |
| `maxToken` | 16384 token | 覆盖批量处理多份跨部门调取的电子证照文档的向量需求 |

## 容易做错的三处
- 现象：调用上传文件接口后返回200状态码，但等待10分钟以上仍未生成可用向量，或界面显示索引构建失败。原因：未配置每日增量索引的自动触发规则，或数据同步任务未按更新频率执行，导致索引构建任务积压。
- 现象：输入审批事项的办理条件关键词后，搜索结果返回与当前事项无关的文档，且相似度得分处于设定阈值范围内。原因：分块长度设置过小，导致关键办理条件的语义被拆分，向量匹配时丢失核心关联信息。
- 现象：统计应用内的token使用量时，出现数值异常偏高或偏低的情况。原因：未统一使用`defaultToken`作为向量生成的基准长度，或分块时未过滤审批文档中的重复页眉页脚信息，导致无效token被重复计算。

## 怎么确认配好了
- 上传一份标准行政许可办事指南文档，查看向量生成进度，确认索引构建完成后的通知是否正常触发。
- 输入某行政许可事项的办理条件关键词，核对搜索结果的关联文档是否属于对应事项，调整相似度阈值至符合业务匹配要求。
- 导入一份标准化申请表文档，查看生成的向量token数是否符合`maxToken`的设置范围，确认无异常截断或溢出。
- 查看索引更新日志，确认每日增量更新任务按设定频率自动执行，无失败记录。
