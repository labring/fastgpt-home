# 行政许可审批的内部办公与员工服务：文档解析与分块
本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的典型数据来自政务服务中心、行政审批局的日常办公与审批流程，文档类型涵盖办事指南、申请表、受理通知书、补正告知书等。数据来源包括全国一体化政务服务平台事项库、部门业务审批系统与电子证照库，更新频率为每日。文档包含法定事项标识、材料清单条目、审批流程节点等结构化字段，同时存在补正告知书、审批意见等非结构化文本内容。

## 这些特征在「文档解析与分块」这一环带来什么约束
行政许可审批的文档来源多样且更新频繁，每日新增的审批材料与事项更新要求解析环节具备实时响应能力。文档同时包含结构化字段与非结构化文本，分块需避免破坏法定事项与对应材料的绑定关系，确保后续匹配办理条件时的准确性。不同部门的审批文档格式存在差异，需适配表单、盖章页等官方文档的解析逻辑，防止分块丢失关键标识信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 行政许可文档包含短字段与长文本，该区间可兼顾结构化字段完整性与长文本语义连贯性 |
| `chunkSplitter` | 按法定事项标识+段落分割 | 行政许可文档以法定事项为核心，按事项标识分割可确保每个分块对应单一审批事项，避免跨事项混淆 |
| `customPdfParse` | 启用 | 行政许可文档多为带盖章、表单的官方PDF，启用自定义PDF解析可保留表单字段与盖章区域的解析完整性 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 覆盖大型电子证照包、批量审批材料的上传需求，适配政务场景的批量提交场景 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型审批材料解析需要足够时间，避免因超时导致解析失败 |
| `chunkSettingMode` | 手动模式 | 可针对办事指南、审批决定书等不同类型的行政许可文档调整分块参数，适配场景化需求 |

## 容易做错的三处
- 上传PDF文件至90%进度时提示“偏移量超出范围”。原因是未调整`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`，大型文件解析时超时或内存分配不足。
- 通过创建文件集合API上传的文档与平台直接上传的文档分块结果不一致。原因是未统一配置`chunkSettingMode`与`chunkSplitter`参数，不同上传渠道默认参数存在差异。
- 使用自定义URL导入行政许可文档后无解析数据。原因是未确认自定义URL可访问政务内网资源，且未启用`customPdfParse`适配官方PDF格式。

## 怎么确认配好了
- 上传单份100MB以上的官方PDF审批材料，检查解析进度是否完成且无报错。
- 分别通过平台上传与API上传同一份办事指南文档，对比分块结果的条目一致性。
- 启用`customPdfParse`后，检查解析结果是否保留表单中的法定事项编号字段。
- 查看解析日志，确认`PARSE_FILE_TIMEOUT_SECONDS`未触发超时报错。
