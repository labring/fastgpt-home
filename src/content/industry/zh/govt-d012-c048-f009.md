# 行政许可审批的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统及电子证照库，每日更新。日常处理的文档包含办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书及许可证照，数据结构以法定许可事项为边界，包含事项依据、办理条件、申请材料、审批流程及证照字段，无额外自定义统计字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据每日更新的要求决定模型接入需支持定时同步政务事项库数据，避免使用过期的许可依据。多类型审批文档的混合处理，要求配置需兼容结构化表单与非结构化文书的解析逻辑。法定事项边界明确的特性，要求召回的参考文档必须严格匹配当前办理事项，不能跨事项调用无关材料。同时，审批出错会引发行政复议或超期办结，因此模型调用的稳定性与结果可追溯性需纳入配置约束。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配FastGPT v4.17.0版本的上下文处理上限，覆盖行政许可审批所需的办事指南、申请材料、审批文书等多类文档的整合上下文 |
| `maxTokens` | 4000–6000 token | 平衡审批意见生成的内容完整性与模型调用成本，适配单次审批事项的处理规模 |
| `quoteMaxToken` | 1500–2000 token | 确保召回的参考文档片段完整包含事项法定依据与办理条件，避免截断关键合规条款 |
| `toolChoice` | auto | 允许模型自主判断是否需要调用工具调取跨部门电子证照，适配审批流程的动态校验需求 |
| `temperature` | 0.1–0.3 | 保持审批内容的严谨性，降低生成不符合法定规范的模糊表述的概率 |

## 容易做错的三处
- 现象：调用时出现`该令牌无权使用模型`报错，日志显示请求ID包含20240开头的标识。原因：未配置`AIPROXY_API_TOKEN`为政务系统专属绑定的合法令牌，或令牌权限未覆盖当前使用的模型类型。
- 现象：模型生成的审批意见未引用相关办事指南内容，召回结果条数不足。原因：`quoteMaxToken`取值过小，导致召回的参考文档片段被截断，无法匹配事项依据。
- 现象：模型调用超时，界面显示请求未完成。原因：未适配政务系统的数据同步延迟，`maxContext`取值过大导致模型处理耗时超出政务审批的合理响应窗口。

## 怎么确认配好了
- 检查`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置是否与政务代理服务的授权信息一致，确保调用权限合规。
- 验证`maxContext`与`maxTokens`的取值是否覆盖当前处理的审批文档总长度，可通过导入单份典型审批包测试上下文加载情况。
- 触发一次模拟审批校验，查看模型生成的内容是否包含召回的参考文档片段，确认`quoteMaxToken`的取值符合片段保留要求。
- 测试跨部门电子证照调用的工具触发逻辑，确认`toolChoice`配置允许模型自主调用所需工具。
