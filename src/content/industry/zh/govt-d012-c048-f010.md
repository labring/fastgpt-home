# 行政许可审批的内部办公与员工服务：知识库检索与召回

## 这个品类的数据长什么样
本品类的典型主体为政务服务中心、行政审批局及行业主管部门审批处室，日常产生的文档包括办事指南、申请表、承诺书、受理通知书、补正告知书、准予行政许可决定书及许可证照。数据来源涵盖全国一体化政务服务平台事项库、行政许可事项清单、部门业务审批系统与电子证照库，更新频率为每日同步最新数据。文档结构包含结构化字段与非结构化文本，结构化字段如事项编码、办理条件、申请材料清单，非结构化文本如办事流程说明与审批意见模板，每份文档对应单一法定许可事项。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每日更新的数据源要求召回逻辑需同步最新的事项清单与电子证照数据，避免使用过期的许可依据。单一事项对应多类文档的结构，要求检索需同时适配结构化字段与非结构化文本的匹配规则。行政许可需严格匹配法定依据与办理条件，因此检索的精准度要求较高，需过滤无关召回结果。跨部门的证照数据来源，要求召回支持多数据源的关联查询，确保审批人员可快速调取所需的电子证明材料。此外，审批流程中的核对环节依赖精准的材料匹配，召回结果的排序需优先返回最相关的许可依据与申请材料清单。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 行政许可事项需精准匹配办理条件与申请材料，该区间可过滤无关召回结果，避免错配法定许可事项 |
| `limit` | 前 5–8 条 | 审批场景单次需核对的材料与依据条目有限，该范围可控制上下文长度，避免超出模型处理上限 |
| `searchMode` | 混合检索 | 兼顾结构化的事项清单字段与非结构化的办事指南文本，匹配不同类型的业务查询需求 |
| `usingReRank` | 开启 | 对召回结果进行二次排序，修正单一向量检索的偏差，确保最相关的许可依据优先返回 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展查询词，补充事项的法定名称与别名，覆盖不同岗位员工的表述习惯 |
| `collectionIds` | 绑定专属审批知识库集合 | 隔离行政许可相关的办事指南、证照库等数据，避免与其他业务知识库混淆 |

## 容易做错的三处
- 现象：上传多列Excel格式的申请表或事项清单后，自动分段结果打乱了原有行结构，无法按每行作为独立分段。原因：未针对结构化表格文件开启按行分块的适配设置，默认自动分段逻辑会按内容语义合并相邻行数据。
- 现象：本地知识库已删除过期的许可事项文档，检索时仍返回对应内容作为引用。原因：未刷新知识库的向量索引缓存，旧数据仍保留在召回向量库中。
- 现象：检索结果超出预设的引用上限，且低相关度的非许可类内容被优先返回。原因：未设置`similarity`阈值或阈值设置过低，同时未开启重排功能过滤无关结果。

## 怎么确认配好了
- 上传一份测试用的多列行政许可申请表Excel，检查分段结果是否按每行内容作为独立块，无跨行合并的情况。
- 手动输入一个低相关度的非许可类查询词，验证检索结果是否被`similarity`阈值过滤，无无关条目返回。
- 开启`usingReRank`后，对比开启前后的召回排序结果，确认最相关的许可依据与办理条件排在首位。
- 查看知识库集合绑定配置，确认仅行政许可相关的数据集被选中，无其他无关业务数据混入召回范围。
- 触发一次知识库更新同步，验证检索结果是否包含最新的行政许可事项数据。
