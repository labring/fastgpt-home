# 规范性文件合法性审核的内部办公与员工服务：工具调用与插件

## 这个品类的数据长什么样
本品类处理的数据来源包括法规规章库、上位法数据库、部门政策文件库、行政规范性文件备案系统，更新频率不定期。日常处理的文档包括规范性文件草案、起草说明、合法性审核意见、征求意见汇总、备案报告。文档字段包含文件编号、起草主体、条文内容、审核依据、意见汇总条目等，单位涉及文件份数、条文条数、意见条目数等，无固定统一的格式模板，需根据文档类型识别对应字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且更新不定期，要求工具调用支持按需拉取不同数据源，不采用固定定时同步全量数据的方式。文档结构多样且字段不统一，要求工具能自动识别不同文档的字段映射规则，适配草案、审核意见等不同类型文件的检索需求。最耗时的条文比对环节需检索大量上位法内容，要求工具调用优先匹配高相关性的法规库数据源，同时需限制返回内容范围，避免冗余信息干扰审核流程。出错后果直接关联文件备案与发布，要求工具调用返回明确的依据来源与检索路径，确保审核结果可追溯。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配不同审核场景自动选择法规库、上位法等对应工具 |
| 单次工具调用返回条数 | 前10条 | 覆盖核心审核依据，避免过多冗余信息干扰判断 |
| `functionCall` | 启用参数校验 | 确保传入的文件ID、法规库类型等参数准确有效 |
| 工具返回内容过滤 | 仅保留与合法性相关的条文与依据 | 排除非相关内容，聚焦审核所需的权限、程序、条文合法性信息 |
| 工具调用超时时间 | 600秒 | 预留充足时间完成上位法数据库的全量条文比对 |
| 上下文截断阈值 | 按实测标定 | 适配不同规模审核文件的上下文承载需求 |

## 容易做错的三处
- 现象：工具调用返回的内容包含非合法性审核相关的行业动态或内部通知，输出结果冗余。原因：未配置工具返回内容过滤规则，未限制仅检索与规范性文件制定权限、条文合法性相关的数据源。
- 现象：调用工具后返回的审核依据字段为空，无法生成合法的审核意见。原因：未启用`functionCall`的参数校验，导致传入的目标文件ID格式错误，工具无法定位对应文档。
- 现象：工具调用持续触发超时报错，日志显示状态码504。原因：设置的工具调用超时时间过短，无法完成大规模上位法条文的比对检索。

## 怎么确认配好了
- 提交一份测试用的规范性文件草案，核对工具调用返回的数据源是否覆盖法规规章库、上位法数据库等指定来源。
- 查看工具调用日志，确认`toolChoice`自动匹配的工具类型与当前审核场景匹配。
- 检查工具返回的内容是否仅包含与合法性审核相关的条文，无冗余的非审核类信息。
- 模拟高负载检索场景，确认工具调用超时时间的配置符合当前场景的响应需求。
