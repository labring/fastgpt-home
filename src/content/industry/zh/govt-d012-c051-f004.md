# 道路运输经营许可的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
本品类的数据来源于道路运政管理系统、全国道路运输车辆动态信息公共服务平台、车辆和从业人员数据库，更新频率为每日。日常处理的文档包括经营许可申请、车辆技术档案、驾驶员从业资格材料、安全生产管理制度、道路运输经营许可证。文档结构覆盖结构化表单与非结构化文本两类，字段包含经营主体统一社会信用代码、车辆识别代号、驾驶员从业资格证编号、安全制度条款、许可有效期等，不同文档的格式与字段排布存在差异。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源的多系统特性要求工作流配置多数据源对接节点，保障核验数据的完整性。每日更新的频率要求设置定时同步任务，确保车辆、人员信息与许可状态的实时性。多格式的文档类型要求工作流适配不同的文本提取规则，避免出现提取偏差。最耗时的车辆人员核验、制度审查环节需要拆分为独立节点，便于配置校验规则与失败回滚。严重的出错后果要求设置异常告警节点，确保许可被退回、企业无法运营等问题能被及时发现。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 输入变量配置 | 绑定`variables`参数，包含经营主体ID、车辆VIN码、申请材料哈希值 | 匹配道路运输经营许可的核心核验字段，确保工作流能精准获取待处理业务信息 |
| 文本提取规则 | 设置分块长度为800–1200字符，开启多格式文档兼容模式 | 适配车辆技术档案、安全生产管理制度等多类型文档，解决不同大模型提取效果不一致的问题 |
| 定时触发配置 | 设置每日凌晨2:00触发数据源同步任务 | 匹配数据日更新频率，确保每日核验的车辆、人员信息为最新状态 |
| 失败处理配置 | 设置超时阈值为600秒，绑定`nodeId`为error_alert的通知节点 | 保障核验环节超时或失败时，相关人员能及时收到告警，避免流程停滞 |
| 核验节点上限 | 单次核验前10条待处理申请 | 匹配日常业务的处理量级，避免工作流资源过载 |

## 容易做错的三处
- 现象为文本提取节点返回空结果或不同大模型输出差异显著，原因是未针对道路运输经营许可的多格式文档配置兼容提取规则，部分大模型无法适配非结构化的安全制度或车辆档案文本。
- 现象为工作流运行时提示文件未找到，无法读取上传的经营许可申请材料，原因是未明确文件上传节点的存储路径配置，未关联对应道路运输企业的专属存储目录。
- 现象为对话节点无法获取用户提交的经营主体或车辆信息，原因是未正确绑定`variables`参数的字段映射，导致用户输入的内容未被正确传递到核验环节。

## 怎么确认配好了
- 运行一次测试工作流，核对提取的车辆、人员信息是否与道路运政管理系统的数据源一致，调整`variables`参数的字段映射直到匹配。
- 上传一份标准的经营许可申请材料，检查文本提取节点的输出是否包含所有必填字段，确认分块规则适配文档长度。
- 模拟一次核验失败的场景，检查是否触发预设的失败通知节点，确认`nodeId`的绑定正确。
- 查看定时同步任务的运行日志，确认每日凌晨的数据源同步节点正常执行，匹配数据更新频率。
