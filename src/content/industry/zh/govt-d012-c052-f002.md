# 部门决算与财务报告的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自预算管理一体化系统、国库集中支付系统、会计核算系统与资产管理系统，更新频率为年度一次。日常文档包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告，文档结构多为结构化表格与格式化说明文本，字段包含收支科目编码、金额、填报说明等，单位以元为基础核算单元。

## 这些特征在「向量模型与索引」这一环带来什么约束
年度集中更新的数据特征要求索引环节支持批量导入与增量更新适配。结构化表格类文档占比高，要求分块策略保留科目、金额等核心字段的完整性，避免拆分关键行导致语义断裂。多系统来源的数据存在格式差异，需在索引前完成统一格式化处理。精准核对账表、解释差异的业务需求，要求召回结果具备高相关性，对相似度匹配的精度提出约束。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的索引与向量召回逻辑设计，适配部门决算与财务报告的业务数据特征。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配决算报表中科目行与说明文本的组合长度，避免拆分核心核算单元 |
| 重叠长度 | 50–100 字符 | 保留跨分块的科目关联信息，确保账表核对时的上下文连贯性 |
| `defaultToken` | 4000 token | 匹配单份决算说明文档的常规长度，满足基础召回的上下文需求 |
| 相似度阈值 | 0.75–0.85 | 保障账表差异、收支科目等核心查询的召回精准度，避免无关结果干扰 |
| 单次搜索上限 | 前 8 条 | 覆盖下级单位报表汇总时的多维度关联数据需求 |
| `maxToken` | 16000 token | 适配年度决算报告的完整上下文召回，满足差异解释的全量数据参考 |

## 容易做错的三处
- 现象：索引完成后检索相关科目，返回结果为空或提示未找到匹配内容。原因：未针对结构化表格文档调整分块策略，拆分了科目编码与金额的关联单元，导致向量语义断裂。
- 现象：知识库查询耗时过长，超出预设阈值。原因：未限制`maxToken`的实际调用上限，单次召回过量年度数据导致上下文传输压力过大。
- 现象：更新文档后检索结果未同步更新。原因：未开启年度数据的增量索引触发规则，仅执行全量索引导致更新延迟。

## 怎么确认配好了
- 上传单份部门决算报表，查看分块预览界面，确认核心科目行未被拆分。
- 发起账表核对类查询，检查返回结果的相似度分值是否落在预设区间内。
- 模拟年度数据批量导入，验证索引任务的进度条与完成状态是否正常。
- 修改单份决算说明文本，执行增量索引后检索修改内容，确认结果同步更新。
