# 部门决算与财务报告的内部办公与员工服务：工作流编排
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
本品类的数据来自预算管理一体化系统、国库集中支付系统、会计核算系统、资产管理系统，更新频率为年度周期。日常产出的文档包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告，各文档包含收支明细、资产负债余额、预算执行差异说明等字段，单位多为万元、人次，报表需严格遵循财政统一口径填报。

## 这些特征在「工作流编排」这一环带来什么约束
年度更新的固定频率要求工作流需适配批量年度数据的处理，避免单次运行超时。多系统来源的数据需在工作流中完成跨系统拉取与格式对齐，需配置针对性的校验节点。多类型文档的结构差异要求工作流按文档类型配置不同的字段提取规则，确保各报表口径统一。跨层级单位的报表汇总任务需设置节点超时与重试机制，应对不同单位的系统响应延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables`绑定 | 绑定年度决算周期、单位编码参数 | 适配年度触发与多单位数据区分 |
| `nodeId`映射 | 按文档类型绑定对应节点ID | 匹配各报表的专属处理流程 |
| 节点超时设置 | 600–1200 秒 | 应对跨系统数据拉取与多单位报表汇总的延迟 |
| 数据格式校验 | 按报表类型分配置字段校验规则 | 匹配各文档的统一填报口径 |
| 重试机制 | 失败后重试2次，间隔120秒 | 应对临时的系统接口波动 |
| 长文本切割 | 800–1000 字符每段 | 适配决算说明等长文档的分段发送 |

## 容易做错的三处
- 工作流判断节点规则配置错误，出现匹配结果全为ELSE的现象。原因是未明确判断条件与分支的对应关系，将等于、开头匹配规则绑定至ELSE分支。
- 系统侧传递的参数未被正确识别，出现全局变量为空的现象。原因是未在工作流的触发节点中配置系统参数的绑定项，未通过`variables`完成参数传递。
- HTTP API返回的长文本未按规则分段，出现单节点发送超限的现象。原因是未配置长文本切割的具体规则，未按文档长度拆分发送内容。

## 怎么确认配好了
- 触发工作流的年度周期参数，核对触发时间与决算年度的匹配度，确认`variables`绑定的参数正确。
- 运行跨系统数据拉取节点，核对各系统返回的数据格式与预设校验规则的一致性，确认数据格式校验配置有效。
- 调用HTTP API获取长文本数据，测试分段发送功能，确认每段文本长度符合业务文档的传输要求。
- 模拟节点失败场景，核对重试机制的触发与执行情况，确认超时与重试配置生效。
