# 部门决算与财务报告的内部办公与员工服务：表单与交互

## 这个品类的数据长什么样
本品类数据来自预算管理一体化系统、国库集中支付系统、会计核算系统、资产管理系统，更新周期为年度。日常文档包含部门决算报表、资产负债表、收入支出决算表、决算说明、政府财务报告，包含收支明细、资产负债项、预算执行差异说明等固定字段，字段单位遵循财政核算通用规范，多文档间存在联动校验关系。

## 这些特征在「表单与交互」这一环带来什么约束
年度更新的特性要求表单无需高频调整，但需支持年度数据的批量导入与校验；多源系统的数据来源，要求表单交互需支持跨系统数据的自动填充与溯源查看；固定的文档结构与字段要求表单需严格匹配财政报表的必填项与格式；账表核对为最耗时环节，要求交互支持快速关联对应系统的原始数据；出错后果的严重性，要求表单需具备实时校验与错误提示能力。

## 配置怎么定
本配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 表单输入校验规则 | 开启`formInput`必填项校验，匹配财政报表字段规则 | 部门决算报表存在固定必填字段与格式要求，需避免无效提交 |
| 用户选择权限 | 限定为预算单位财务人员、国库经办人员角色 | 数据涉及财政敏感信息，需限制操作范围 |
| 上下文联动配置 | 开启`formInput`历史数据关联 | 决算报表需关联前期核算数据，保留历史核对上下文 |
| 单次交互条数限制 | 前5条历史数据调用 | 年度数据量较大，限制单次调用避免前端负载过高 |
| 超时响应阈值 | 600秒 | 多系统数据拉取需较长响应时间，避免提前中断 |
| 变量分组展示 | 开启`userSelect`分类分组 | 决算报表分类较多，分组展示提升操作效率 |

## 容易做错的三处
- 现象为提交部门决算表单时出现字段为空的报错，原因是未配置`formInput`与多源系统数据的映射规则，未将会计核算系统的收支数据自动填充至对应表单字段。
- 现象为拖拽`userSelect`组件选择报表分类时界面出现明显卡顿，原因是未限制分类层级与展示条数，过多的决算报表分类导致前端渲染负载过高。
- 现象为调用决算核对工具时未出现知识库选择选项，原因是未配置`userSelect`的数据源绑定，未关联对应财政系统的知识库内容。

## 怎么确认配好了
- 提交包含必填字段的测试表单，确认无空值报错且对应字段自动填充多源系统数据。
- 拖拽`userSelect`组件选择报表分类，确认界面无明显卡顿延迟。
- 调用API与在线聊天分别提交相同的决算核对请求，确认返回结果一致性。
- 模拟长时间数据拉取场景，确认在600秒内返回有效结果或明确的超时提示。
