# 部门预算编制的内部办公与员工服务：向量模型与索引

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的数据主要来自预算管理一体化系统、部门人员编制系统、以前年度决算、项目库及财政部发布的预算编制通知，更新频率为年度。日常处理的文档包括部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复，数据同时包含结构化表格字段与非结构化自然语言内容，字段涵盖项目编码、申请金额、人员编制数、绩效目标指标等。

## 这些特征在「向量模型与索引」这一环带来什么约束
年度更新的特性决定索引无需高频增量同步，但单次全量索引的数据量较大，需适配批量处理逻辑。混合结构化与非结构化的文档格式，要求向量模型同时支持表格字段编码与自然语言文本编码。数据字段包含金额、编制数等数值型内容，需确保向量编码保留数值关联语义。部门预算审核的严格要求，使得索引召回的准确率需匹配审核标准，避免遗漏关键预算申报信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配部门预算文档的段落与表格块长度，避免跨语义分块 |
| 重叠长度 | 100–200 字符 | 保留跨分块的预算项目关联信息，防止语义断裂 |
| `maxToken` | 8192 token | 匹配text-embedding-ada-002的最大输入限制，适配长预算文档 |
| `defaultToken` | 按实测标定 | 适配本地部署的m3e等向量模型的输入长度要求 |
| 相似度阈值 | 0.75–0.85 | 过滤低关联的历史预算数据，匹配审核环节的严谨性要求 |
| 单次搜索上限 | 前10条 | 控制返回结果的信息量，适配预算审核的批量处理场景 |

## 容易做错的三处
- 现象：知识库调用时返回“无可”类报错，原因：未正确将text-embedding-ada-002等向量模型添加至开放API渠道，或配置文件未同步生效。
- 现象：使用本地部署的m3e向量模型时，界面持续显示“索引中”状态，原因：未配置批量索引的超时阈值，或本地模型推理速度不足导致任务阻塞。
- 现象：搜索速度过慢，原因：误将搜索速度问题归因于向量模型，未排查语言模型的上下文长度与召回结果的冗余度，导致无效计算占用资源。

## 怎么确认配好了
- 检查向量模型渠道配置，确认已添加目标模型并同步至系统配置文件。
- 发起小批量测试索引，查看界面是否正常完成索引状态流转，无持续阻塞提示。
- 发起测试搜索，验证返回结果的关联度与数量符合预期，无异常报错。
- 调整配置项后，对比搜索耗时与召回结果，确认参数匹配业务需求。
