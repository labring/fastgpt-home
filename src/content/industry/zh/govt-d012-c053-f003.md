# 部门预算编制的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据通常来自预算管理一体化系统、部门人员编制系统、以前年度决算数据、项目库及财政部年度预算编制通知。日常产出的文档包含部门预算草案、项目申报书、绩效目标表、人员经费测算表、预算批复等，字段多涉及人员编制数、项目经费额度、绩效指标值等，单位包含万元、人、项等。数据更新频率为年度，仅在每个预算编制周期内完成一轮核心更新。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
年度更新的特性要求多轮对话需绑定明确的周期上下文，避免跨年度数据混淆。多源异构的数据来源需要提示词明确区分不同系统的字段规则，例如区分预算管理一体化系统的项目编码与项目库的申报编号。多样的文档类型需要提示词适配不同格式的要求，例如人员经费测算表的人均标准需匹配人员编制系统的在编人数数据。汇总下属单位预算的环节需要多轮对话按层级传递数据，确保下级单位的测算结果可被上级调用。同时，固定的业务变量需在对话中明确传递，避免因参数缺失导致数据匹配错误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的功能逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 上下文窗口上限 | 8000–12000 token | 适配多份预算文档的总长度，避免截断核心测算数据 |
| `chatId` 绑定规则 | 按预算单位+年度生成唯一标识 | 隔离不同单位、不同周期的对话上下文，防止跨周期数据干扰 |
| `variables` 绑定参数 | 预算年度、单位层级、项目库来源 | 固定业务变量，确保提示词调用正确的数据源与字段规则 |
| `messages` 格式要求 | 按用户/助手交替格式存储完整历史 | 符合多轮对话的标准解析逻辑，确保模型可复用前一轮的测算结果 |
| 历史记录清理触发 | 按年度预算周期结束触发 | 匹配数据更新频率，避免冗余数据占用存储空间 |
| 单次对话最大轮次 | 15–20轮 | 适配预算编制的多步骤审核流程，避免过长上下文导致模型混淆 |

## 容易做错的三处
- 现象：对话历史中出现跨年度的预算数据，导致测算结果错误。原因：未按预算单位+年度绑定`chatId`，导致不同周期的上下文被混淆。
- 现象：多轮对话无法复用前一轮的测算结果作为当前轮次的输入依据。原因：未在`messages`中按用户/助手交替格式存储完整对话历史，模型无法获取历史结论。
- 现象：调试预览生成的对话历史无法批量清理，占用工作台存储空间。原因：未配置按年度预算周期触发的历史清理规则，仅支持手动删除单条记录。

## 怎么确认配好了
- 生成一条测试对话，输入跨年度的预算数据查询，检查返回结果是否仅包含当前绑定年度的数据集。
- 发起两轮连续的测算对话，检查第二轮对话是否能自动调用第一轮生成的项目经费测算结果。
- 进入工作台的对话管理页面，触发年度周期结束的清理规则，检查对应周期的历史记录是否被批量删除。
- 查看`variables`参数配置页面，确认已绑定预算年度、单位层级等固定业务变量，无缺失项。
