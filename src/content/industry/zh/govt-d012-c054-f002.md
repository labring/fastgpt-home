# 防汛防灾与应急值守的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控。日常产生的文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单。数据更新频率为每日，部分实时监测数据更新间隔更短。文档字段包含雨情水情数值、转移安置人数、物资品类与存量、处置流程节点等，部分文档附带时间戳与责任主体标识。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且包含结构化数值与非结构化文本，要求索引支持多类型内容的向量化适配。每日更新的批量数据需要匹配增量索引的调度节奏，避免全量索引占用过多资源。长文本类的会商纪要、灾情速报需要合理的分块规则，确保上下文语义完整。实时监测类的短数据条目，需要适配高频写入的索引更新逻辑，同时保证召回精度不受高频更新影响。应急场景下的时效性要求，限制了索引检索的延迟上限，需平衡召回条数与响应速度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配会商纪要、灾情速报等长文本的语义连贯性，避免关键信息被拆分 |
| 重叠长度 | 100–200 字符 | 弥补长文本分块后的上下文断层，提升跨块信息召回的准确性 |
| `defaultToken` | 4000 token | 匹配单次检索的基础上下文配额，适配应急场景下的多文档汇总需求 |
| `maxToken` | 12000 token | 允许召回最多12000 token的关联内容，满足复杂会商场景的信息整合需求 |
| 相似度阈值 | 0.75–0.85 | 平衡应急场景下的召回精度与召回条数，避免过多无关内容干扰 |
| 单次搜索上限 | 前10条 | 控制单次检索返回的文档数量，防止超出模型上下文承载上限 |

## 容易做错的三处
- 现象：检索返回相关文档但模型提示未找到匹配内容。原因：`maxToken`配置值小于召回内容的总token数，召回的文档片段被截断，模型无法获取完整信息。
- 现象：知识库检索耗时过长。原因：`defaultToken`设置过高，单次检索加载过多关联内容，增加了模型处理的负载。
- 现象：无法正确索引图片类文档。原因：未使用FastGPT v4.17.0及以上版本，或未开启图片向量化的对应配置。

## 怎么确认配好了
- 上传一份典型的会商纪要文档，查看分块后的片段是否保留了关键的处置流程与责任主体信息。
- 发起模拟检索，查看返回的关联文档数量是否符合单次搜索上限的配置，且总token数未超过`maxToken`的设置。
- 检查向量模型的归一化配置，确认与所使用的embedding模型适配，例如针对Doubao的embedding开启归一化选项。
- 测试图片文档的索引，确认在FastGPT v4.17.0版本下可以正常生成向量并参与检索。
