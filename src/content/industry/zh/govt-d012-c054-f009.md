# 防汛防灾与应急值守的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自气象预警系统、水文监测系统、应急指挥平台、基层报灾系统与视频监控。数据更新频率为每日，核心业务文档包含值班记录、预警通知、会商纪要、灾情速报、应急处置方案、物资调拨单。文档字段涵盖降雨量、流量、险情等级、转移人数、物资品类与数量等，对应单位为毫米、立方米每秒、级、人、件或吨，单份文档的信息密度随应急事件等级提升而升高。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日高频更新的多源数据要求模型能够快速处理实时召回的文档，因此上下文窗口的配置需适配单日多份业务文档的汇总需求。多类型文档与特定业务字段的存在，要求模型接入时需配置适配字段提取的规则，避免无效信息干扰核心应急判断。跨部门调度的业务流程，也要求模型能够调用工具调取多系统数据，因此工具调用的配置需贴合应急处置的实时性要求，避免延迟影响处置效率。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单日多份应急文档的上下文汇总需求，避免超出模型窗口限制导致信息丢失 |
| `maxTokens` | 2000–3000 token | 满足灾情速报、会商纪要的生成长度要求，避免输出内容被截断 |
| `quoteMaxToken` | 1500 字符 | 保留核心预警、灾情数据的引用细节，兼顾召回精度与上下文负载 |
| `toolChoice` | auto | 适配跨系统数据调取的需求，自动选择工具处理雨情、水情等实时数据 |
| `temperature` | 0.3–0.5 | 保持应急信息的准确性，避免生成模糊或不确定的处置建议 |
| `AIPROXY_API_ENDPOINT` | `http://localhost:8000/v1` | 适配本地化模型的网络配置需求，确保FastGPT可连通本地模型服务 |
| `AIPROXY_API_TOKEN` | 按部署生成的专属密钥填写 | 保障本地化模型调用的访问权限，防止未授权访问 |

## 容易做错的三处
- 现象为本地模型部署时出现500端口占用报错，原因是未正确绑定本地模型服务的端口，导致FastGPT无法建立有效连接。
- 现象为模型生成的应急文档缺失核心业务字段，原因是未针对降雨量、险情等级等特定字段配置上下文召回规则，导致模型无法提取关键数据。
- 现象为调用第三方代理模型时出现服务不可用，原因是未更新代理服务的有效密钥，导致访问权限失效，无法正常调用模型。

## 怎么确认配好了
- 提交一份历史值班记录与预警通知的组合文档，检查模型能否正确提取降雨量、险情等级等核心业务字段。
- 调用模型生成一份简短的灾情速报，确认输出长度符合`maxTokens`的设置，无内容截断情况。
- 查看模型调用日志，确认工具调用的触发符合`toolChoice`的配置，可正常调取多系统数据。
- 测试本地化模型的连通性，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无连接报错。
