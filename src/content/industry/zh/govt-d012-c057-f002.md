# 食品安全监督抽检的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS系统及食品生产经营者台账。日常办公与服务相关文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。数据更新频率为月度。核心文档字段含抽样点位信息、检验项目参数、不合格判定依据、处置流程记录等，均围绕样品检验与不合格处置核心环节展开。

## 这些特征在「向量模型与索引」这一环带来什么约束
月度更新的批量数据要求索引支持增量同步，避免全量重建占用过多计算资源。多类型结构化与非结构化文档混合，需要向量模型适配不同格式的文本拆分，尤其是抽样单的表格字段与检验报告的专业监管术语。抽样点位、检验项目等字段的精准匹配需求，要求索引的召回精度需覆盖专业监管术语，同时需控制单批次索引的token消耗，避免超出模型上限。不合格处置报告的时效性要求，需保证索引更新后可快速检索相关历史处置案例，支撑内部复核与处置决策。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写，以下为适配该场景的向量模型与索引配置：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配检验报告、抽样单的单页文本长度，避免单块token超出`maxToken`限制 |
| 重叠长度 | 100–150 字符 | 保留抽样点位、检验项目等关键字段的上下文关联，防止跨块信息断裂 |
| 相似度阈值 | 0.75–0.85 | 匹配监管专业术语的语义精度，过滤低相关的历史抽检数据 |
| 单次搜索上限 | 前 8 条 | 覆盖单份处置报告关联的历史抽样批次，避免结果过多干扰复核 |
| `defaultToken` | 8192 | 适配大模型上下文窗口，容纳多份检验报告与处置记录的拼接内容 |
| 最大上下文 | 600 秒 | 匹配月度批量索引的处理时长，避免单批次任务超时中断 |

## 容易做错的三处
- 现象：配置`text-embedding-ada-002`后使用知识库仍提示“无可”相关报错。原因：未将向量模型正确绑定至FastGPT的embedding渠道，或渠道配置未同步至知识库索引模块。
- 现象：接入本地m3e向量模型时，界面长期显示“索引中”状态。原因：未配置本地模型的调用超时参数，或批量索引的分块设置超出本地部署的计算负载。
- 现象：抽检计划检索时搜索速度过慢，被误归因于向量模型性能。原因：未限制单次搜索上限，导致大量非相关历史数据被加载，额外消耗语言模型的上下文处理时间。

## 怎么确认配好了
- 上传单份检验报告，查看索引生成进度，确认在合理时长内完成基础索引。
- 输入包含专业监管术语的检索词，核对返回结果的匹配度符合预设的相似度阈值区间。
- 检查embedding渠道配置页面，确认已添加的向量模型可正常调用，无报错提示。
- 导入月度批量抽检数据，确认索引任务未出现超时中断，且未触发`defaultToken`超限报错。
