# 食品安全监督抽检的内部办公与员工服务：文档解析与分块

本文适配FastGPT v4.17.0版本

## 这个品类的数据长什么样
典型主体涉及市场监管局食品抽检处、基层监管所、检验机构等，日常文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。数据来源为食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS、企业台账，更新频率为月度。文档结构包含标准化表单与自由文本两类，字段涵盖抽样编号、检验项目、不合格判定结果、处置措施等，单位涉及批次、浓度单位等。

## 这些特征在「文档解析与分块」这一环带来什么约束
月度更新的批量文档要求解析流程具备高效性，避免因单份文档解析耗时过长影响制定抽检计划、复核检验报告等最耗时的业务环节。多类型文档混合的场景要求分块规则具备灵活性，适配表单类抽样单、长文本检验报告的不同结构。核心业务字段（如不合格判定结果）的完整性直接影响后续不合格食品核查处置流程，分块操作不得破坏跨字段的关联关系。同时，文档来源涉及多系统导出格式，解析模块需兼容不同编码与排版的文件，避免因格式不兼容导致字段丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配抽检文档的字段密度，避免拆分检验报告中的检验项目与结果关联对 |
| `chunkSplitter` | 按段落+语义边界 | 匹配抽检文档的章节结构，保留抽样单、处置报告的完整业务逻辑 |
| `customPdfParse` | 开启 | 适配多格式抽检文档，保留表格、表单的结构化信息，避免字段错位 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 覆盖大型批量检验报告、月度抽检计划文档的完整解析耗时 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量抽检文档的上传需求，满足月度汇总文档的存储要求 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型调整分块规则，匹配抽检业务的字段关联要求 |

## 容易做错的三处
- 调用API解析成功但无回传结果：现象为API返回调用成功状态，但返回结果中无解析文本内容。原因是未正确开启`customPdfParse`参数，或`PARSE_FILE_TIMEOUT_SECONDS`设置过短，导致大型检验报告解析中断未完成回传。
- Marker报错提示split异常：现象为解析日志中出现split相关报错提示。原因是`chunkSplitter`配置为固定字符分割，导致抽样单中的表格内容被错误拆分，破坏了抽样信息与检验结果的关联。
- 文档解析模块无文件传入：现象为上传文件后解析模块未读取到文件内容。原因是`UPLOAD_FILE_MAX_SIZE`设置过小，批量抽检计划文档超出上传限制，且未触发明确的超限提示。

## 怎么确认配好了
- 上传单份检验报告，检查解析后的分块是否保留了检验项目、不合格判定结果等核心字段的完整性。
- 调用解析API，验证返回结果中包含解析后的文本块，且无空字段或截断内容。
- 上传批量抽检计划文档，确认上传进度正常，解析耗时符合`PARSE_FILE_TIMEOUT_SECONDS`的设置。
- 调整`chunkSize`参数，测试不同取值下的分块效果，确保抽样单的抽样信息与检验结果未被拆分至不同块中。
