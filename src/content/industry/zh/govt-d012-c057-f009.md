# 食品安全监督抽检的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS系统及企业台账。日常核心文档包含抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告，数据更新周期为月度。数据字段包含抽样点位、检验项目、不合格项、处置措施等，严格遵循业务文档的标准结构，无额外非业务标准字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
月度更新的数据需适配批量处理的上下文长度限制，避免单次加载过多历史数据导致超时。核心文档如检验报告包含结构化字段与文本描述，需配置适配多模态输入的模型能力。抽样点位、不合格项等字段的固定格式要求模型输出需匹配业务字段规范，避免生成不符合监管要求的内容。不同来源的数据格式差异，需在接入时统一预处理逻辑，确保模型可识别统一的输入结构。此外，不合格食品处置相关文档的时效性要求，需确保模型调用的响应速度匹配业务流程节奏，避免延迟影响处置进度。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 月度更新的抽检文档总量较大，需覆盖足够的历史上下文以支撑抽检计划制定与不合格项复核 |
| `maxTokens` | 2000–3000 token | 检验报告、核查处置报告等核心文档的文本长度适中，需确保输出内容完整且匹配业务格式 |
| `temperature` | 0.2–0.4 | 需保证输出内容的规范性，避免生成不符合监管要求的非标准化表述 |
| `vision` | 开启 | 需支持抽样单、检验报告等带图像的文档解析，适配多模态业务场景 |
| `AIPROXY_API_ENDPOINT` | 对应模型服务商的官方接入地址 | 确保模型调用链路正常，避免出现地址错误类问题 |
| `AIPROXY_API_TOKEN` | 从模型服务商平台获取的有效密钥 | 确保身份验证通过，避免调用被拦截 |

## 容易做错的三处
- 调用模型时返回404错误，现象为界面提示「请求资源不存在」或日志显示404状态码。原因是`AIPROXY_API_ENDPOINT`配置的地址与模型服务商的实际接入地址不匹配，或未正确填写接口路径。
- 配置为不输出思考过程但仍生成相关内容，现象为模型回复中包含额外的推理步骤。原因是`temperature`取值过高导致模型生成自由度超出预期，或未正确勾选对应输出控制开关。
- 工作流中调用语音合成工具失败，现象为测试环节返回执行错误。原因是工具接入的API密钥未正确配置，或工具的调用权限未在对应平台开通。

## 怎么确认配好了
- 调用测试接口，检查返回的状态码是否为正常状态，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置有效。
- 输入单份检验报告文本，核对模型输出的内容是否匹配预设的`maxTokens`与`temperature`取值对应的生成长度与风格。
- 上传带图像的抽样单，确认模型可正常解析图像内容，验证`vision`配置是否生效。
- 运行批量文档处理任务，检查上下文加载是否未超出`maxContext`的配置范围，避免出现截断或超时问题。
