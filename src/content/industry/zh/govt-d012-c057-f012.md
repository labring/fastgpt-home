# 食品安全监督抽检的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
本品类的数据来源包括食品安全抽检监测系统、国家市场监管总局抽检结果查询系统、检验机构LIMS、食品生产经营者台账。数据更新频率为月度，日常文档涵盖抽检计划、抽样单、检验报告、不合格食品核查处置报告、风险控制通告。数据字段包含抽样标识、检验项目、不合格判定结果、处置进度等核心信息，核心数据为实验室出具的检验报告与全流程处置记录，适配监管处、基层所等多角色的分级查看需求。

## 这些特征在「部署与升级」这一环带来什么约束
月度更新频率要求部署阶段配置可定时同步的数据源任务，适配多类数据源的拉取规则。核心文档为长文本类的检验报告与处置流程记录，需配置适配大文件存储与索引的参数，避免内容截断。多数据源的接入需求，要求部署时配置差异化的数据库连接参数，区分结构化与非结构化数据的存储路径。多主体使用的场景，需在部署阶段配置分级访问权限，匹配不同角色的操作范围。不合格处置环节的时效性要求，升级时需保留关键操作的审计日志，确保流程可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://admin:password@mongodb-host:27017/fastgpt_sampling?authSource=admin` | 存储检验报告、抽样单等非结构化文档，支持高并发读写 |
| `PG_URL` | `postgresql://user:pass@pg-host:5432/fastgpt_core?sslmode=require` | 存储抽检计划、处置流程等结构化数据，支持复杂查询与统计 |
| `REDIS_URL` | `redis://:redis-pass@redis-host:6379/0` | 缓存高频访问的抽检数据与会话信息，降低数据库压力 |
| `DB_MAX_LINK` | `20–30 个并发连接` | 适配月度批量数据同步的并发需求，避免连接池耗尽 |
| `FILE_TOKEN_KEY` | `随机生成的32位字符串` | 生成文件访问令牌，确保检验报告等敏感文档的访问安全 |
| `STORAGE_S3_ENDPOINT` | `按自建对象存储或云服务商提供的端点填写` | 存储大体积的检验报告扫描件与抽样影像，适配长文本存储需求 |

## 容易做错的三处
- 现象：执行docker run --gpus all -itd -p 7231:7231命令启动marker_images:v0.1镜像时出现依赖报错。原因：未提前配置GPU驱动与容器运行时的适配参数，导致镜像无法调用GPU资源完成文档解析。
- 现象：升级FastGPT v4.17.0后，通过URL导入食品安全抽检系统数据源时提示cannot fetch internal url。原因：未在`FE_DOMAIN`配置项中正确填写内部系统的访问域名，导致内部接口调用被拦截。
- 现象：新部署的系统无法发起AI对话，无法正常调用模型服务。原因：未正确配置`ROOT_KEY`或对应模型的密钥参数，导致AI服务无法完成身份验证。

## 怎么确认配好了
- 执行`docker ps`命令，确认marker镜像容器与FastGPT主容器均处于运行状态，且端口映射配置与预设值一致。
- 登录FastGPT后台，进入数据源管理页面，测试连接抽检监测系统、LIMS等配置的数据源，确认连接状态显示正常。
- 上传一份抽检计划文档，测试系统的文本解析与索引功能，确认文档内容可被正常检索与展示。
- 配置测试用的内部URL，发起知识库创建请求，确认无fetch失败报错，验证`FE_DOMAIN`配置生效。
