# 仓储物流的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
仓储物流的业务数据主要来自仓储管理系统（WMS）、手持PDA终端、物流调度系统三类来源。数据更新节奏分为三类：入库出库操作产生的实时数据、每日库存盘点产生的日更数据、月度运力与成本统计产生的月更数据。标准文档结构包含入库单、出库单、库存台账三类核心文档，入库单包含单号、操作时间、货品SKU、数量、库区编号等字段，字段单位分别为字符串、YYYY-MM-DD HH:mm:ss格式、字符串、件、区域编号格式。

## 这些特征在「工作流编排」这一环带来什么约束
仓储物流的数据多源异构且更新节奏差异大，要求工作流编排支持多源数据接入与多触发规则配置。不同类型数据的字段与单位存在明确规范，要求工作流的变量绑定环节需严格匹配字段格式与单位，避免自动转换导致的异常。实时数据的流转时效要求高，要求工作流节点间的延迟控制在合理区间，同时定时触发节点需适配日更、月更数据的统计周期。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量初始值 | 预设为50 件、1000 千克等仓储业务标准值 | 匹配仓储物流的库存、运力管控的常规阈值 |
| `variables` | 绑定WMS系统的SKU编码、在库数量、库区编号字段 | 匹配仓储物流数据的标准文档结构 |
| 节点触发规则 | 实时事件触发入库/出库节点，每日0点触发库存盘点节点 | 对应仓储数据的实时更新与定时统计节奏 |
| `nodeId` | 按工作流节点执行顺序分配连续编号，例如node_001到node_008 | 便于工作流调试与节点异常定位 |
| 代码运行节点输入 | 仅传入当前节点上下文变量，不包含全局历史记录 | 避免触发输入校验失败，符合FastGPT v4.17.0的节点约束 |
| 插件初始值配置 | 绑定仓储系统的固定参数，例如默认库区为A区 | 减少手动输入的冗余操作 |

## 容易做错的三处
- 代码运行节点输入包含全局历史记录时，界面弹出「输入参数校验失败」提示，无法保存工作流。原因是FastGPT v4.17.0的代码运行节点限制仅允许传入当前上下文变量，不支持全局历史记录作为输入源。
- 插件初始值未绑定业务字段，仅手动输入静态值，导致运行时变量无法随仓储数据更新。原因是未将插件初始值与WMS系统的固定参数绑定，仅静态配置无法适配动态业务变化。
- 未在工作流中添加单位校验环节，混用件与千克等不同单位的字段，导致执行时出现数据异常。原因是未针对仓储数据的单位规范配置校验逻辑，直接映射字段导致单位不匹配。

## 怎么确认配好了
- 查看工作流预览面板，确认全局变量的初始值匹配仓储业务的常规阈值。
- 触发测试节点，验证代码运行节点无校验报错，且输入仅包含当前上下文变量。
- 核对系统日志中的数据上报时间与工作流触发时间，确认触发规则与数据更新节奏一致。
- 打开插件配置面板，确认初始值已绑定仓储系统的对应字段，无未配置的空值项。
