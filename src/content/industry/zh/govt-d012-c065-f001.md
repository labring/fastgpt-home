# 勘察设计的内部办公与员工服务：HTTP 接口与外部系统

## 这个品类的数据长什么样
勘察设计的核心数据来源于CAD施工图、BIM模型文件、岩土勘察报告、项目进度台账与设计变更通知单。数据更新节奏随项目阶段变化：勘察阶段按每日点位检测结果更新，设计阶段按每周版本迭代，变更发生时即时更新。文档包含结构化字段与非结构化内容，结构化字段包括项目编号、勘察点位坐标、岩土抗压强度、版本号，非结构化内容包含勘察现场描述、设计优化说明。字段单位遵循行业规范，坐标采用十进制经纬度，强度单位为MPa，版本号采用「YYYYMMDD-序号」格式。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
大型BIM模型与CAD施工图的单文件体积可达数百MB，要求接口支持大请求体传输与分块上传逻辑。结构化字段存在严格单位规范，接口需对坐标、强度等参数做格式与单位校验，避免无效数据流入。数据更新频率随项目阶段波动，接口需支持增量同步或短轮询机制，适配高频变更场景。同时需兼容文本与二进制混合的响应格式，满足结构化台账与可视化模型的同时传输需求。

## 配置怎么定
FastGPT v4.17.0 下的配置需结合勘察设计业务场景调整，具体如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 接口超时时间 | 600 秒 | 勘察设计文件传输与数据处理耗时较长，避免因超时中断请求 |
| 请求体最大限制 | 1000 MB | 适配BIM模型、大型CAD图纸的传输需求 |
| 全局变量传递 | 按接口调用参数带入 | 匹配外部平台传递项目编号、版本号的业务场景 |
| 认证方式 | 固定密钥校验 | 适配内部办公系统的统一鉴权规则 |
| 响应数据解析 | 按JSON格式提取 | 兼容结构化的项目台账与参数数据 |
| 重试次数 | 3 次 | 应对临时网络波动导致的接口调用失败 |

## 容易做错的三处
- 配置认证信息后调用接口返回空数据或401状态码，原因是未正确匹配内部办公系统的鉴权格式，例如遗漏密钥前缀或未使用`Authorization`头传递令牌。
- 外部平台调用对外接口时无法获取全局变量，原因是未在接口配置中开启`variables`参数带入开关，导致编排的工作流无法接收外部传入的项目编号。
- 上传大型BIM模型时接口报错，原因是未调整请求体最大限制参数，超出系统默认阈值导致请求被拦截。

## 怎么确认配好了
- 调用测试接口，检查返回数据是否包含勘察项目的核心字段，验证参数校验与数据解析是否生效。
- 模拟外部平台传递全局变量，确认接口能正确接收并在工作流中使用该变量，验证全局变量传递配置。
- 上传不同体积的测试文件，验证请求体大小限制是否适配业务需求，确认传输逻辑正常。
- 查看接口日志，确认`Authorization`头与`responseData`解析规则被正确应用，验证认证与数据处理配置。
