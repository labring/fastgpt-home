# 勘察设计的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
勘察设计的业务数据主要来自项目勘察原始记录、地质勘察报告、建筑结构设计图纸转写文本、施工组织设计、变更洽商记录、行业规范条文及工程计算书。数据更新随项目推进实时进行，单项目周期内更新频率较高，项目竣工后归档封存。文档多为长文本，包含大量专业术语、数值参数与坐标信息，字段包含项目编号、图纸版本号、勘察点位坐标、荷载参数等，单位多为毫米、兆帕、平方米、立方米等。

## 这些特征在「向量模型与索引」这一环带来什么约束
长文本占比高的特征要求分块策略兼顾语义完整性与token限制，避免切断专业术语或连续的工程逻辑。实时更新的特性要求索引支持增量更新，以适配项目推进中的频繁修改。专业数值与坐标信息的存在，要求索引同时支持文本向量与结构化数据的混合匹配，确保跨类型文档的关联检索。此外，大量工程专属术语需要适配领域微调的embedding模型，以提升语义召回的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配勘察设计长文本的语义完整性，避免切断专业术语或连续计算逻辑 |
| 重叠长度 | 100–200 字符 | 弥补分块边界的语义断裂，确保跨分块的专业关联被保留 |
| 相似度阈值 | 0.75–0.85 | 匹配工程文档的专业语义相似度区间，过滤低相关的通用匹配结果 |
| 单次搜索上限 | 前10条 | 平衡召回精度与上下文长度，避免超出模型处理上限 |
| `maxToken` | 8000 | 适配工程文档长上下文的处理需求，匹配主流工程领域embedding模型的token限制 |
| `defaultToken` | 按实测标定 | 适配部署的embedding模型的实际token上限，避免分块后文本截断 |

## 容易做错的三处
- 现象：搜索结果中出现大量不相关的通用工程文档，原因：未针对勘察设计的专业语义调整相似度阈值，使用了通用领域的默认阈值参数。
- 现象：索引任务超时失败，日志显示token超限，原因：未配置合理的`maxToken`，将未分块的长文档直接提交至向量模型处理。
- 现象：无法实现跨文档关联检索（如图纸与对应计算书的联动），原因：仅使用扁平化实体索引，未配置关系型索引适配跨文档的专业关联逻辑。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的知识库模块，上传一份典型的勘察报告与设计图纸转写文本，执行专业术语检索，核对返回结果的专业匹配度是否符合预期。
- 查看索引任务的运行日志，确认没有token超限或超时报错，验证`maxToken`配置与实际文档长度匹配。
- 测试跨文档关联检索，验证图纸文本与对应的设计说明是否能被同时召回。
- 调整相似度阈值，观察检索结果的条数变化，确认阈值设置符合业务筛选需求。
