# 勘察设计的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
勘察设计的内部办公数据主要来自项目管理系统、CAD导出的设计文档、内部共享的行业规范与项目变更单。数据更新节奏随项目进度调整，项目变更时实时更新，规范文档每季度同步更新。文档包含结构化字段（项目编号、负责人、抗震烈度、工时）与非结构化内容（设计说明、图纸注释），单位涵盖天、小时、MPa、烈度等级等专业字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
勘察设计的混合结构数据要求多轮对话能区分结构化台账与非结构化设计内容，提示词需适配专业术语与单位校验。高频更新的变更单与项目文档，要求对话上下文需及时同步最新数据，避免使用过期内容。长文本的设计说明会占用较多上下文窗口，需限制无效冗余信息的引入，同时保证专业术语的识别精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 8000–12000 字符 | 适配勘察设计长文本设计说明与项目台账，FastGPT v4.17.0 版本下可稳定承载多轮对话历史 |
| `variables` | 预设项目编号、专业领域变量 | 匹配勘察设计固定业务字段，减少提示词重复编写 |
| 单次搜索上限 | 前6条 | 避免过多检索结果干扰多轮对话上下文清晰度 |
| `messages` | 保留最近10轮对话内容 | 平衡上下文完整性与系统响应速度 |
| 问题优化 | 按实测标定 | 适配勘察设计专业术语较多的场景，调整查询词精度 |
| 重排 | 按专业相关性排序 | 优先返回与当前设计任务匹配的规范与图纸内容 |

## 容易做错的三处
- 现象：调用AI对话时返回422状态码，无法获取检索到的文档内容。原因：未正确配置`messages`参数的上下文格式，导致系统无法识别多轮对话的历史上下文，触发参数校验失败。
- 现象：对话窗口刷新后本地记录消失，但后台可查看完整对话。原因：未开启`chatId`的本地缓存配置，仅依赖后台存储导致前端会话丢失。
- 现象：FastGPT升级版本后，部分历史对话记录在前端窗口无法加载。原因：未同步更新`variables`中的项目关联字段映射，导致上下文匹配失败，无法关联到原有会话。

## 怎么确认配好了
- 发起包含专业术语（如抗震烈度、荷载等级）的多轮对话，检查`messages`参数是否正确传递了每一轮的角色与内容，无格式错误。
- 手动刷新对话窗口，验证前端会话记录与后台存储的一致性，确认`chatId`的缓存配置生效。
- 触发包含预设项目编号的查询，检查`variables`中配置的业务字段是否被正确调用，匹配到对应知识库内容。
- 关闭用户可见输出开关后，发起内部调试用的查询，验证专业提示词不会被普通员工看到。
