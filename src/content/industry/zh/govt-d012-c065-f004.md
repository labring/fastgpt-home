# 勘察设计的内部办公与员工服务：工作流编排
本页面内容基于FastGPT v4.17.0版本

## 这个品类的数据长什么样
勘察设计的核心数据来自项目勘察原始记录、各阶段设计图纸元数据、项目进度台账、变更申请单。数据更新节奏随项目推进实时同步，单次提交的勘察点位数据、设计变更内容会即时更新。单份文档包含项目编号、勘察坐标、设计阶段、审核状态、关联图纸编号等字段，单位多采用米、平方米、工作日等工程通用标准单位。

## 这些特征在「工作流编排」这一环带来什么约束
勘察设计的数据包含结构化工程字段与非结构化图纸文本，要求工作流同时支持结构化字段提取与非结构化内容解析。实时更新的项目数据要求工作流触发节点绑定项目状态变更事件，采用实时触发逻辑。多阶段的审核流转逻辑要求工作流配置分支节点，基于审核状态字段实现不同流转路径。工程专属的单位格式要求工作流的变量处理环节保留米、平方米等单位信息，避免格式丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 绑定项目状态变更事件 | 匹配勘察设计数据实时更新的节奏，避免无效调度 |
| 变量配置 | 提取`variables`中的项目编号、勘察坐标字段 | 勘察设计文档核心标识字段，用于关联上下游流程 |
| 分支节点规则 | 按审核状态字段分流 | 适配多阶段审核的流转需求，符合勘察设计项目的审批逻辑 |
| 单次处理上限 | 前10条待办任务 | 匹配工程项目单批次的任务规模，避免节点过载 |
| 超时阈值 | 600秒 | 覆盖勘察报告解析、图纸元数据提取的常规耗时，按实测标定 |
| 知识库检索筛选 | 关联项目标签 | 限定检索范围为当前项目的知识库内容，提升匹配精度 |

## 容易做错的三处
- 工作流调试时出现双思考过程。现象：工具调用节点调试日志中同时显示两轮思考流程。原因：未通过`nodeId`限定触发节点的输入参数范围，未在`variables`中提取核心字段，导致系统重复触发思考逻辑。
- 代码运行组件报错且代码本身无问题。现象：本地部署环境下代码组件执行失败，返回通用报错状态码。原因：未配置工作流节点的本地运行权限，导致无法访问工程数据的本地存储路径。
- 知识库检索未按标签筛选结果。现象：检索返回的内容包含非当前项目的文档。原因：未将项目标签绑定到检索节点的筛选规则，未关联`variables`中的标签字段。

## 怎么确认配好了
- 触发一次项目状态变更事件，查看工作流是否自动启动并流转到对应节点。
- 检查`variables`中提取的项目编号、勘察坐标字段是否与源数据完全一致。
- 模拟不同审核状态的输入，验证工作流是否按规则分流到对应分支。
- 提交测试任务，确认超时阈值未触发节点中断，且检索结果包含匹配的项目标签内容。
