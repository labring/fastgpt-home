# 勘察设计的内部办公与员工服务：知识库检索与召回

## 这个品类的数据长什么样
勘察设计的核心数据来源于项目全周期的勘察报告、正式设计图纸说明、行业规范图集、项目台账与变更记录。数据更新节奏随项目阶段变化，方案论证阶段更新频率较高，施工图阶段相对稳定，行业规范更新时会同步补充最新版本内容。文档结构包含长文本段落（单份报告可达数十页）、结构化元数据（如项目编号、勘察点位坐标、规范文号），以及关联图纸的元信息，字段涉及长度、面积、荷载等工程单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
长文本占比高的特征要求检索时需保留分块间的上下文关联，避免割裂专业术语的完整语义；结构化元数据的存在要求检索支持按项目编号、规范文号等字段进行精准过滤，减少跨项目文档干扰；更新节奏不固定的特点要求知识库支持增量更新，确保项目变更后的最新内容可快速被检索到；关联图纸的元信息则要求召回结果可同步关联对应图纸的说明内容，提升信息完整性。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写，以下配置项针对勘察设计场景优化：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 勘察设计文档多专业术语，阈值过低会引入无关规范内容，过高会遗漏同专业的关联设计说明，按实测标定 |
| `limit` | 前8–12条 | 单项目文档量较大，过多结果会超出上下文窗口，过少会遗漏关键设计参数 |
| `searchMode` | vector + keyword | 兼顾专业术语的语义匹配和规范编号、项目编号的精确匹配，适配勘察设计文档的混合检索需求 |
| `usingReRank` | 开启 | 长文本分块后容易出现语义偏移，重排可以修正初始召回的顺序，提升相关结果的排名 |
| `datasetSearchUsingExtensionQuery` | 开启 | 勘察设计问题常带有隐含需求，比如询问地基处理时自动关联岩土勘察规范，扩展查询可以覆盖更多相关文档 |
| `collectionIds` | 按项目分组配置 | 避免跨项目文档的干扰，确保检索结果仅来自当前负责的勘察设计项目 |

## 容易做错的三处
- 调用API传入知识库相关参数时提示参数错误，返回字段为空。原因：未正确配置`collectionIds`参数，或全局变量未绑定对应项目的知识库集合ID。
- 上传单份大尺寸PDF勘察报告时，进度到90%后提示“偏移量超出范围”。原因：未适配大文件分块上传逻辑，或分块大小设置超出系统允许的单块处理上限。
- 检索结果召回了无关项目的勘察规范，结果条数不符合预期。原因：未按项目分组配置`collectionIds`，或`similarity`阈值设置过低，引入了跨项目的无关文档。

## 怎么确认配好了
- 调用API传入`collectionIds`参数后，检查返回结果是否仅包含当前项目的勘察设计文档。
- 上传单份100 MB以上的PDF勘察报告，确认上传进度完成后无报错。
- 输入专业问题（如“地基承载力设计参数”），检查召回结果是否包含对应规范和项目内的勘察数据。
- 开启`usingReRank`后，对比初始召回和重排后的结果顺序，确认相关文档排名靠前。
