# 化肥农药的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
数据来源包括企业内部生产销售台账、农业农村部农化产品登记数据库、区域农技推广的田间试验记录。更新节奏为产品登记信息每季度同步更新，田间农事数据随农事周期月度更新，日常销售与库存数据每日更新。文档多为结构化格式，包含产品名称、登记证号、有效成分含量、适用作物、推荐使用剂量、安全间隔期等字段，字段单位多为克/公顷、毫升/亩、天等，部分长文本文档包含完整的产品使用说明书与田间指导方案。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 化肥农药相关文档包含长文本产品说明书与多字段结构化数据，需覆盖完整上下文 |
| `temperature` | 0.2–0.4 | 需要稳定的专业术语解析结果，避免生成无关的非业务内容 |
| `quoteMaxToken` | 1500–2000 字符 | 田间记录与产品台账的单条引用文本长度多在此区间，可保障引用内容完整 |
| `toolChoice` | auto | 需根据任务自动选择是否调用工具处理结构化数据查询，适配多类型业务场景 |
| `AIPROXY_API_ENDPOINT` | 企业自建专属代理地址 | 保障内部农化敏感数据的传输安全，避免外部接口泄露业务信息 |
| `AIPROXY_API_TOKEN` | 企业统一分配的专属令牌 | 实现接口访问权限的精细化管控，防止未授权的模型调用 |

## 容易做错的三处
- 现象为调用时返回“该令牌无权使用模型：text-embedding-3-large”，原因是未在渠道配置中为对应令牌分配化肥农药场景下可用的embedding模型权限。
- 现象为创建应用时无法勾选已配置的重排模型，原因是未在配置文件中正确适配农业化工场景的重排模型参数，或配置的模型未通过有效性校验。
- 现象为提示“当前分组 default 下对于模型 gpt-4o 无可用渠道”，原因是未将gpt-4o渠道绑定到default分组，或渠道配置的令牌权限未覆盖化肥农药业务所需的模型调用范围。

## 怎么确认配好了
- 发起针对农化产品登记信息的查询测试，核对返回结果是否包含正确的业务字段，字段单位识别是否符合要求。
- 查看向量库同步日志，确认不同更新节奏的数据均按配置规则完成同步，无异常中断或遗漏情况。
- 检查接口调用日志，确认`AIPROXY_API_TOKEN`的权限校验通过，无无权访问的报错信息。
- 测试重排模型调用，确认返回的农化文档排序符合业务场景的相关性要求，可根据实际业务调整排序规则。
