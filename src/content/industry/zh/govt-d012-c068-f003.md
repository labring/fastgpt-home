# 医药流通的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
医药流通的业务数据来自企业内部的进销存管理系统、GSP合规档案、员工办公审批系统与考勤台账。更新节奏为每日进销存数据同步更新，合规档案按业务批次归档，办公文档按需上传至知识库。单份文档多为结构化表格与流程审批单，字段包含药品通用名、批次号、库存数量、审批单号，单位涉及盒、件、批次、自然日。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的结构化字段密集且更新节奏差异大，对多轮对话与提示词配置带来三点约束。其一，药品编码、批次号等关键业务字段需在`messages`中精准传递，避免多轮对话中上下文混淆导致查询错误。其二，进销存数据每日同步更新，提示词需绑定实时数据调取规则，确保每次对话返回最新库存信息。其三，办公审批文档格式统一，提示词需预设审批单号的提取规则，减少多轮追问的频次。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 保留最近10条对话内容 | 医药流通多轮对话多围绕药品库存、审批流程展开，10条上下文可覆盖完整业务链路且控制上下文长度 |
| `variables` | 绑定药品编码、批次号为固定变量 | 该品类业务字段标准化程度高，提前配置变量可简化提示词编写，提升多轮对话一致性 |
| 多轮对话超时时间 | 600秒 | 内部办公流程多为跨部门协作，600秒可覆盖完整咨询与审批回复的对话周期 |
| 提示词触发规则 | 按药品、审批等业务关键词触发 | 可精准匹配医药流通核心业务场景，避免无效调用 |
| 上下文敏感数据过滤 | 按员工账号权限过滤GSP数据 | 医药流通合规数据涉及企业敏感信息，需在多轮对话中做权限隔离 |

## 容易做错的三处
- 现象：删除单条对话记录后，系统同步删除关联的操作日志。原因：未配置对话记录与日志的独立存储逻辑，默认将二者绑定至同一条数据条目。
- 现象：提示词无法正确引用多轮对话中的药品批次信息。原因：未在`messages`中携带结构化业务字段，仅保留自然语言对话内容，导致模型无法精准提取关键参数。
- 现象：执行批量删除对话记录的操作时，触发系统报错。原因：未指定`chatId`作为删除条件，导致误删其他账号的对话数据。

## 怎么确认配好了
- 发起包含药品编码的多轮咨询对话，检查返回结果是否匹配预设业务逻辑，确认`variables`与`messages`配置生效。
- 执行单条对话记录删除操作，查看系统日志是否保留，确认存储规则配置正确。
- 输入预设的业务关键词，检查提示词是否触发对应调用逻辑，确认触发规则配置无误。
- 切换不同员工账号发起对话，检查是否仅能查看对应权限内的业务数据，确认敏感数据过滤配置生效。
