# 医药流通的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
医药流通的内部数据主要来自进销存管理系统、员工考勤系统、办公审批流程及药品冷链监控终端。数据更新节奏覆盖即时（审批、冷链告警）、每小时（库存异动）、每日（考勤、销售汇总）。文档包含结构化字段（药品编码、批次号、库存数量、存储温度阈值）与非结构化内容（审批单、员工培训文档），字段单位涉及盒、箱、件、摄氏度，部分文档附带时间戳与权限标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
医药流通的多源异构数据特征，对模型接入配置带来多项约束。结构化字段多且单位复杂，需配置明确的字段映射规则，确保模型能正确关联药品编码、批次号等信息并识别单位转换。多来源数据更新节奏差异大，需设置合理的上下文刷新间隔，避免调用过期的库存或考勤数据。非结构化文档包含审批单与培训内容，需调整上下文长度适配长文本解析。冷链数据的实时性要求高，需限制模型调用的响应时长，确保告警处理及时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 填写OneAPI网关的部署地址，格式为`http://{ip}:{port}/v1` | 适配医药流通内部数据的跨系统调用需求，统一接口入口 |
| `AIPROXY_API_TOKEN` | 填写OneAPI分配的专属令牌，绑定内部办公服务的权限范围 | 确保仅授权的内部系统可调用模型，保障数据安全 |
| `maxContext` | 8000–12000 token | 适配包含药品编码、批次号、库存数据的长上下文解析，避免截断关键结构化字段 |
| `quoteMaxToken` | 2000–3000 token | 限制引用的文档片段长度，适配医药流通的审批单、冷链监控日志等非结构化内容的提取 |
| `temperature` | 0.2–0.4 | 保持内部办公问答的准确性，避免生成不符合药品流通规范的内容 |
| `maxTokens` | 1500–2000 token | 控制单次模型输出长度，适配内部办公的审批意见、员工答疑等短平快的交互场景 |

## 容易做错的三处
- 现象为在FastGPT v4.17.0中配置OneAPI接口后测试报错“Cannot read p”，原因是未正确填写`AIPROXY_API_ENDPOINT`的路径后缀`/v1`，导致接口请求格式不匹配。
- 现象为配置text-embedding-3-large作为索引模型后流程卡住不动，原因是未同步配置对应的模型调用密钥与端点，或上下文长度设置超出模型支持上限。
- 现象为将代码块输出的String类result传入模型后报错“Question is empty”，原因是result中包含不可见的换行符或空字符，未做预处理即传入，导致模型识别为空请求。

## 怎么确认配好了
- 调用模型测试接口，输入包含药品编码与库存数量的测试文本，检查返回结果是否正确关联字段信息。
- 查看系统日志，确认模型请求的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`参数匹配配置值，无401或404状态码。
- 提交包含长文本的审批单测试，检查模型输出未出现上下文截断的提示或错误。
- 模拟冷链告警场景的提问，确认模型响应时长符合预设的实时性要求。
