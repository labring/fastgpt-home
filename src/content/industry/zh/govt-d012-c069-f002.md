# 危化品储运的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
危化品储运的内部办公数据主要来自储运台账、班次巡检记录、设备运维日志、行业安全规范文档、应急处置档案。台账为结构化数据，包含危化品名称、专属编号、存储位置、存量（单位为吨或升）、入库出库时间；巡检记录为半结构化文本，包含巡检点位、设备状态、异常描述、巡检时间；安全规范文档为长格式文档，按章节划分条款。数据更新节奏差异明显：台账与运维日志实时或每日更新，巡检记录按班次更新，行业规范每季度或年度更新。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据格式要求向量建模需兼顾结构化字段的元数据映射与非结构化文本的语义提取，避免因格式差异导致向量偏差。更新频率的差异要求索引策略区分全量与增量更新，实时数据需支持高频增量同步，静态规范文档可采用定期全量更新。字段附带的单位信息（如吨、升）会影响语义相似度计算，需在分块与建模环节保留单位关联，防止同类危化品因单位混淆出现匹配错误。长文档的存在则要求分块策略需平衡上下文完整性与`maxToken`限制下的向量生成效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配危化品安全规范的单段长度与巡检记录的单条内容长度，避免超出`maxToken`限制 |
| 重叠长度 | 100–150 字符 | 保留储运流程、巡检序列的上下文关联，防止分块后语义断裂 |
| 相似度阈值 | 0.75–0.85 | 区分危化品专有术语的语义相似度，减少无关结果的匹配概率 |
| 单次搜索上限 | 前 10 条 | 适配内部办公场景的信息密度，避免过多结果超出上下文窗口 |
| `maxToken` | 8192 | 适配主流本地化向量模型的上下文限制，支持长文档的完整向量生成 |
| `defaultToken` | 2048 | 平衡员工日常查询的信息需求与响应速度，适配单条问题的token消耗 |

## 容易做错的三处
- 导入文档后系统显示的知识库容量数值与预期不符，原因是未按照危化品储运文档的实际字符长度配置分块参数，导致分块逻辑混乱，token统计出现偏差。
- 搜索结果返回条数与设置的单次搜索上限不一致，部分查询无结果返回，原因是未针对危化品专有术语开启语义扩展，导致术语匹配失败。
- 向量生成过程出现超时报错，原因是未在GPU环境下开启模型量化模式，在1080ti显卡下无法高效处理长文档的向量计算。

## 怎么确认配好了
- 导入单篇危化品安全规范文档，查看分块预览界面，确认分块长度落在预设的800–1200字符区间内。
- 发起包含危化品专有术语的查询，查看返回结果的相似度评分，确认评分落在0.75–0.85的预设阈值区间内。
- 批量导入一周的巡检记录，确认增量索引更新过程无超时报错，更新耗时符合预期。
- 查看FastGPT v4.17.0的向量数据库存储面板，确认总存储占用与预估的知识库容量匹配。
