# 危化品储运的内部办公与员工服务：知识库检索与召回

## 这个品类的数据长什么样
危化品储运的业务数据主要来自企业内部的安全技术说明书（SDS）、储运台账、日常巡检记录、应急处置规程四类来源。日常巡检记录每日更新，SDS文档与正式合规规程每季度或应急事件后修订。文档结构包含固定字段：危化品通用名称、CAS登记号、存储温湿度阈值、巡检周期、泄漏处置流程，配套使用的单位包括立方米存储容积、毫克每立方米气体浓度、小时巡检频次等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
固定的结构化字段要求检索同时支持精准字段匹配与语义召回，避免仅依赖语义导致CAS号、存储条件等关键信息匹配失效。每日新增的巡检记录需要实时增量索引，全量更新无法满足应急场景下的检索时效性。长文档如完整SDS需要合理分割以保留上下文，过短的分块会割裂处置流程的逻辑关联，过长的分块则会增加向量检索的计算负载。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 匹配危化品名称、存储条件这类核心语义，阈值过低会混入无关的行政办公文档，过高会遗漏合规的处置规程 |
| `limit` | 前8条 | 单批次召回覆盖多类业务文档，避免单类文档占满结果，适配危化品储运多场景检索需求 |
| `searchMode` | hybrid | 结合关键词匹配与语义召回，适配CAS号、存储条件这类结构化与非结构化混合的业务数据 |
| `usingReRank` | 开启 | 对召回的分块结果进行二次排序，过滤长文档中冗余的非核心内容，提升检索精准度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展危化品术语别名，例如将“液氨”关联“无水氨”“氨溶液”，覆盖不同场景下的术语使用习惯 |
| `collectionIds` | 绑定专属数据集ID | 限定检索范围仅包含危化品储运相关文档，避免混入通用办公知识库的无关内容 |

## 容易做错的三处
- 现象：检索结果中未包含当日新增的危化品储运巡检记录。原因：未启用增量更新同步，仅执行全量索引更新，未覆盖实时新增的业务数据。
- 现象：搜索“液氨泄漏处置”时返回大量无关的行政办公文档。原因：未通过`collectionIds`指定专属的危化品储运数据集，检索范围包含了通用办公知识库。
- 现象：单次检索耗时超过10秒，前端显示超时。原因：未设置合理的`limit`参数，召回过多长文档分块，导致向量检索和重排流程耗时过长。

## 怎么确认配好了
- 上传一份新的危化品SDS文档，等待索引完成后，搜索文档内的核心术语，确认结果包含该文档的分块内容。
- 进入数据集的检索配置面板，查看`similarity`、`usingReRank`等参数的取值，确认与预设配置一致。
- 发起一次包含CAS号的检索，确认结果优先返回匹配该结构化字段的文档。
- 监控检索接口的响应时长，确认单次检索耗时符合业务场景的要求。
