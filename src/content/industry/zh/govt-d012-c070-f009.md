# 发电装备制造的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
发电装备制造的内部办公数据主要来源于设备运维日志、年度检修规程、备件库存清单、工艺参数手册与现场工单记录。运维日志为实时或每日更新的时序数据，检修规程与工艺参数手册每季度或年度修订，备件清单按月度更新。文档包含长文本运维报告、结构化参数表格与零散工单，字段涵盖设备编号、运行电压、检修周期、备件型号，单位涉及伏特、转每分钟、小时、件等。

## 这些特征在「模型接入与配置」这一环带来什么约束
设备运维日志的实时性要求模型接入时适配时序数据的上下文长度，避免截断关键时序节点。长文本运维报告的篇幅较大，需匹配模型的上下文窗口限制，防止关键检修细节丢失。结构化参数表格的字段与单位标准化程度高，需配置模型支持结构化数据的识别与提取。不同数据源的更新频率差异，要求知识库同步策略区分配置，保障数据时效性。备件型号的唯一性要求检索环节提升精准度，避免混淆相似型号的备件信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配长文本运维报告与时序日志的上下文长度，避免截断关键数据 |
| `maxTokens` | 2000 token | 控制单轮回答的输出长度，适配设备参数解释与工单处理的信息密度 |
| `quoteMaxToken` | 1500 字符 | 限制检索引用的文本长度，聚焦核心运维与检修信息 |
| `temperature` | 0.3–0.5 | 降低回答的随机性，保障设备参数与检修流程的表述准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的地址填写 | 适配本地或云端模型的接入路径，保障调用连通性 |
| `AIPROXY_API_TOKEN` | 按授权文档生成的密钥填写 | 完成模型接入的身份验证，保障调用安全性 |

## 容易做错的三处
- 现象：知识库容量计算结果与预期不符，无法准确估算使用成本。原因：未结合发电装备制造数据的长文本特性与结构化字段占比，采用通用计算规则。
- 现象：模型调用时出现上下文截断报错，返回结果缺失关键运维细节。原因：`maxContext`配置取值过低，未适配长文本运维报告的长度需求。
- 现象：针对仅十几个字的短查询，回答未按流式分段，直接一次性返回完整结果。原因：未正确配置模型的流式输出逻辑，或未适配短查询的响应规则，该问题在FastGPT v4.17.0版本的初始部署中易出现。

## 怎么确认配好了
- 上传一份典型的长文本运维报告，发起包含检修步骤的查询，验证模型能否完整提取关键信息，确认上下文长度配置适配数据特征。
- 发起包含设备参数的查询，检查回答中引用的检索内容是否聚焦核心信息，核对引用长度是否符合`quoteMaxToken`的限制。
- 发起多轮短查询测试，验证模型是否按预期流式输出结果，确认响应逻辑符合内部办公的交互需求。
- 核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置，发起测试调用，确认模型接入的连通性与身份验证正常。
