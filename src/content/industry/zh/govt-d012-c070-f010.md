# 发电装备制造的内部办公与员工服务：知识库检索与召回

## 这个品类的数据长什么样
发电装备制造的内部办公数据主要来源于设备运维手册、零部件台账、生产工艺规程、员工培训文档及备品备件清单。数据更新节奏随新机型投产、工艺迭代调整，新机型手册每季度批量更新，工艺规程每月微调，备件清单随库存变动实时更新。文档结构包含长文本运维步骤、带结构化字段的台账内容、带矢量图的PDF作业指导书，字段包含设备编码、物料号、库存数量（单位：件/套）、更换周期（单位：小时）等专业属性。

## 这些特征在「知识库检索与召回」这一环带来什么约束
长文本运维文档的分块长度会直接影响召回的上下文完整性，过长的分块会占用过多token窗口，过短则会割裂专业术语的语义关联。结构化的备件台账包含明确的单位与编号字段，仅依赖向量召回无法精准匹配这些结构化属性，会导致检索结果混入无关单位的备件数据。带矢量图的PDF文档解析后可能存在文本提取不完整的情况，导致部分语义片段无法生成有效问答对。非固定周期的批量更新也要求知识库支持增量同步，避免全量重建带来的耗时问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值（`similarity`） | 0.75–0.85 | 发电装备制造文档专业术语密集，阈值过低会混入无关结果，过高会漏召回关键检修步骤 |
| 单次召回上限（`limit`） | 前8条 | 长文档分块数量较多，过多召回结果会超出上下文窗口，影响最终回答的连贯性 |
| 搜索模式（`searchMode`） | 向量+关键词混合检索 | 兼顾长文本语义匹配与结构化字段的精准匹配，适配运维手册与备件台账的混合数据结构 |
| 开启重排（`usingReRank`） | 开启 | 过滤相似度过高的冗余分块，提升结果的相关性排序 |
| 开启问题优化（`datasetSearchUsingExtensionQuery`） | 开启 | 员工提问多为口语化表述，优化后可匹配专业术语，提升召回精准度 |
| 集合ID（`collectionIds`） | 绑定发电装备专属知识库集合 | 隔离其他业务线数据，避免跨品类检索带来的结果干扰 |

## 容易做错的三处
- 现象：上传大型汽轮机运维PDF时，解析日志持续报slow operation，MongoDB响应延迟。原因：未针对长文档调整分块参数，单块字符数过大导致解析耗时过长。
- 现象：检索备件清单时，返回结果包含「件」与「套」两种单位的同型号备件，字段匹配失效。原因：未开启向量+关键词混合检索模式，仅依赖向量召回无法精准匹配物料号与单位字段。
- 现象：部分带矢量图的培训PPT文档未生成问答对，直接写入原文。原因：未针对带矢量图的PDF/PPT文档开启文本提取优化，仅提取了少量纯文本内容，导致语义片段不完整。

## 怎么确认配好了
- 上传1份典型的汽轮机运维PDF文档，查看解析后的分块数量是否符合预期的单块长度范围。
- 输入「XX型号汽轮机的首次检修周期」，核对返回结果的相似度分值是否落在0.75–0.85区间内。
- 检索「#1机组的备用泵库存数量」，验证返回结果是否同时包含物料号、库存数量与对应单位字段。
- 开启重排功能后，对比开启前后的结果排序，确认冗余结果已被过滤。
