# 国有资产管理公司的内部办公与员工服务：文档解析与分块

## 这个品类的数据长什么样
国有资产管理公司的内部办公数据主要来源于国资监管报送系统、内部资产台账、员工办公文档、网段运维记录表等。更新节奏覆盖实时（如审批单、运维记录）、每日（如考勤数据）、月度/季度（如国资报表）。文档结构包含多列结构化表格（如资产台账、网段记录表）、长文本制度文件、混合格式的审批流程文档，字段涵盖资产编号、账面价值、IP段、使用部门等，单位涉及万元、个、天等。

## 这些特征在「文档解析与分块」这一环带来什么约束
多列结构化表格的存在，要求解析时不能随意拆分单元格关联内容，否则会导致检索时无法匹配完整的字段与数据对应关系。长文本制度文件的长度差异较大，分块尺寸需要适配上下文窗口，过大会超出模型处理范围，过小则会割裂上下文逻辑。批量上传的大型文档包与多sheet Excel文件，对解析时长与文件大小限制提出了更高要求，默认配置可能无法覆盖全量数据的解析需求。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `chunkSize` | 800–1200 字符 | 适配国资制度、审批单等长文本，保留上下文关联，避免拆分过细丢失逻辑 |
| `chunkSplitter` | 按段落+表格识别 | 适配多列结构化表格与混合格式文档，保留字段与内容的绑定关系 |
| `customPdfParse` | 启用mineru API | 解决多列PDF表格（如网段记录表）的识别不全问题，还原完整列数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 适配大型国资报表、多sheet Excel的解析时长需求，避免超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 允许上传批量国资台账、历史文档包，适配内部办公的批量上传场景 |
| `chunkSettingMode` | 手动配置 | 针对多列结构化数据，自定义分块规则，避免默认分块破坏表格关联 |

## 容易做错的三处
- 现象：上传多列Excel文档（如网段记录表）后，仅识别前两列数据，其余列内容缺失。原因：未启用`customPdfParse`或未配置针对多列表格的解析规则，默认解析逻辑仅识别基础列。
- 现象：条件判断组件处理HTTP组件解析出的boolean类型数据后，参数变为空。原因：解析时未保留原始数据类型的序列化格式，分块过程中丢失了boolean值的标识，导致组件无法识别有效参数。
- 现象：线上环境出现Cannot redefine property: toString报错。原因：批量上传超大文件时，未调整`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`的配置，导致解析进程冲突触发底层属性重定义异常。

## 怎么确认配好了
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
- 上传单份多列结构化文档，查看解析后的文本内容，确认所有列的字段与数据均被完整提取。
- 上传一份长文本国资制度文档，拆分后的块内容保留完整的段落与上下文逻辑，无生硬拆分的情况。
- 测试上传超过默认大小的文档，确认上传与解析流程未触发超时或文件大小限制报错。
- 提交boolean类型的解析测试数据，通过条件判断组件验证参数可被正常识别与处理。
