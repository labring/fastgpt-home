# 国有资本投资公司的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
数据主要来自内部OA系统的办公文档、员工手册、集团制度汇编、部门会议纪要、新员工培训材料。更新节奏包含固定周期的制度修订、日常办公文件的即时新增与归档。文档结构统一包含标题、正文内容、发布部门、生效日期字段，部分文档带有密级标识，单份文档包含明确的层级段落划分。

## 这些特征在「向量模型与索引」这一环带来什么约束
文档长度跨度大的特征，要求分块策略具备灵活性，避免短文档过度拆分或长文档块丢失。部分文档带有密级标识，需要在索引阶段同步关联权限字段，确保检索时仅返回对应权限范围内的向量数据。日常办公文件的即时新增与归档，要求索引更新流程支持增量同步，避免全量重建带来的资源占用。统一的文档字段结构，便于在向量化前提取标准化的文本内容，减少预处理的额外开销。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面逻辑制定，涉及`maxToken`与`defaultToken`等核心参数。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200字符 | 适配国有资本投资公司内部文档的语义单元，平衡块完整性与整体索引数量 |
| 分块重叠长度 | 100–150字符 | 避免相邻文本块的语义断裂，同时控制重叠部分带来的冗余向量存储 |
| `maxToken` | 8000 token | 覆盖内部办公场景的典型上下文需求，适配员工咨询的常见内容长度 |
| 单次向量生成线程数 | 2–4 | 适配embedding接口的并发承载能力，避免速率超限报错 |
| 向量召回条数 | 前6条 | 匹配内部员工咨询聚焦明确的特点，减少无效结果的返回 |
| `defaultToken` | 按模型默认值 | 适配基础向量化任务的参数需求，无需额外调整 |

## 容易做错的三处
- 现象：设置分块长度为3000字符时，部分长文档的末尾文本块丢失。原因：分块长度未匹配内部文档的语义分布，且未配置合理的分块重叠长度，导致系统无法正确识别块的起止范围。
- 现象：向量化过程中出现速率超限报错，任务无法正常完成。原因：单次向量生成线程数设置过高，超出了当前embedding服务的并发承载上限，未根据实际服务能力调整线程数。
- 现象：知识库检索响应时长过长，或文档索引任务长期处于未就绪状态。原因：未启用增量索引更新，全量索引重建占用了大量系统资源，且未限制单次索引处理的文档数量。

## 怎么确认配好了
- 上传一份包含长短文本的测试文档，核对分块后的结果，确认无异常的块丢失或过度拆分。
- 运行批量向量化任务，查看运行日志，确认未出现速率超限相关的报错。
- 发起一次针对内部制度的测试检索，核对返回结果的相关性，确认响应符合预期。
- 新增一份测试文档，检查索引更新是否自动触发，无长时间停滞的情况。
