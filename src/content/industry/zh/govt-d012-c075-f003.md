# 国有资本投资公司的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
国有资本投资公司的内部办公与员工服务数据，主要来自集团OA系统、ERP管理平台、国资监管报送系统、员工手册与投资项目档案。其中结构化数据如国资统计报表按季度更新，非结构化数据如内部通知、项目可研报告按业务节点实时更新，员工薪酬与绩效数据按月更新。文档包含结构化字段与单位，如对外投资总额（亿元）、本级企业户数（家），同时混杂长文本类的非结构化文档，整体数据覆盖集团总部与各级子公司的业务与行政范畴。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
内部数据来源分散且结构混杂，多轮对话需在`messages`中维护不同系统的上下文边界，避免跨系统数据混淆。部分数据按季度更新，提示词需明确标注数据时效范围，防止返回过时的国资统计信息。数据包含敏感的未公开投资与财务字段，提示词需限制对话中不泄露未授权的涉密内容。员工数据按层级划分，多轮对话需通过`variables`传入用户所属层级，匹配对应的数据访问权限。长文本类文档占比高，需控制`messages`的上下文长度，避免token溢出影响对话流畅性。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口 | 8000–12000 字符 | 适配内部长文档与国资报表的长度，避免多轮对话上下文溢出 |
| `messages` 单轮输入限制 | 不超过1200 字符 | 控制token消耗，适配国有资本投资公司内部文档的输入场景 |
| `variables` 传入参数 | 包含员工所属层级、数据更新周期 | 匹配国资数据的权限分级与时效要求 |
| `chatId` 绑定规则 | 按员工工号与部门绑定 | 确保多轮对话上下文关联到对应员工的权限范围 |
| 提示词时效标注 | 强制包含数据更新周期 | 明确告知用户数据的时效性，避免误解过时信息 |
| 对话超时时间 | 600 秒 | 适配国资数据检索的耗时需求，避免长查询任务中断 |

## 容易做错的三处
- 现象：调用Java接口时返回参数无效报错，提示`appId`未配置。原因：误将应用ID当作调用密钥，实际需使用平台分配的API密钥，且需绑定对应对话应用。
- 现象：对话直接返回知识库召回的文本片段，未经过AI整理与格式优化。原因：未在对话流程中接入AI对话模块，仅调用了知识库检索接口，未完成多轮对话的意图理解。
- 现象：上传国资相关文件后，对话无法召回文件内的内容。原因：未在对话流程中配置文件解析模块，或未在提示词中明确要求调用文件内容。

## 怎么确认配好了
- 发起包含多轮上下文的测试对话，输入不同层级员工的问题，核对返回结果是否匹配对应权限的数据范围。
- 调整`variables`传入的参数值，验证对话结果是否随参数变化而调整，确认参数生效。
- 上传国资相关的内部文档，发起相关提问，核对召回内容是否包含文档中的关键信息。
- 切换提示词语言参数，验证对话提示语是否同步变更，确认多语言配置生效。
