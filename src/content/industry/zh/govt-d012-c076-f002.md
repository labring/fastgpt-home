# 国有资本运营公司的内部办公与员工服务：向量模型与索引
本页适用FastGPT v4.17.0版本。

## 这个品类的数据长什么样
国有资本运营公司的内部办公与员工服务数据主要来源于内部OA系统、人事管理平台、国资监管报送文档、月度经营会议纪要及员工手册。数据更新节奏覆盖多周期：日常办公通知、员工考勤记录为每日更新，月度经营报表、国资监管报送材料为月度更新，员工手册、组织架构文档为年度更新。文档包含结构化字段，如员工工号、部门编码、国资划转进度编号，半结构化的会议纪要与通知，以及非结构化的长篇调研报告。

## 这些特征在「向量模型与索引」这一环带来什么约束
多周期更新的特征要求索引支持增量同步机制，避免全量重建带来的计算资源占用。包含国资监管专属编码、员工工号等结构化字段，需要在向量索引中关联元数据字段，确保检索结果可按业务维度快速过滤。非结构化的长篇调研报告与月度会议纪要，需要适配长文本分块规则，避免单块内容超出向量模型的token限制。部分涉密或敏感的内部文档，需要在索引阶段完成脱敏标记，确保检索时仅对脱敏后内容生成向量。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配内部会议纪要、调研报告的平均文本长度，避免单块超出多数开源嵌入模型的token限制 |
| 重叠长度 | 50–80 字符 | 保留分块间的上下文关联，避免长文本分块后语义断裂 |
| `maxToken` | 8192 | 适配qwen3-embedding-8b的最大输入token限制，确保分块内容可正常生成向量 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 过滤低相关的检索结果，匹配内部办公文档的语义相似度分布 |
| 单次搜索上限 | 前10条 | 控制返回结果的数量，适配内部员工的信息获取场景 |
| 最大上下文 | 3000–4000 token | 限制传入大模型的上下文长度，避免超出模型的输入限制 |

## 容易做错的三处
- 现象：文件上传后界面长期显示“索引中”状态，无进度更新。原因：未配置适配的`maxToken`参数，长文本分块超出嵌入模型的token限制，导致向量生成过程超时卡住。
- 现象：配置本地M3E作为索引模型后，检索结果为空或相关性极低。原因：未设置匹配的分块长度，导致分块内容与模型训练的文本粒度不匹配，向量语义出现偏差。
- 现象：检索结果包含未脱敏的国资监管涉密内容。原因：未在索引阶段关联元数据过滤规则，未对敏感字段做标记，导致检索时未按业务权限过滤结果。

## 怎么确认配好了
- 上传一份典型的内部会议纪要文档，查看界面显示的分块数量是否匹配配置的分块规则。
- 发起一条模拟员工咨询的查询，查看检索结果的条数是否符合设置的单次搜索上限。
- 检查向量模型的运行日志，确认分块内容的token数未超出配置的限制。
- 针对涉密内部文档发起检索，确认结果中未包含未脱敏的敏感内容。
