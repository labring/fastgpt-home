# 国有资本运营公司的内部办公与员工服务：知识库检索与召回

## 这个品类的数据长什么样
国有资本运营公司的知识库数据主要来源于集团内部制度汇编、国资监管部门下发的规范性文件、各子公司运营手册、员工薪酬福利指南、办公流程SOP等。更新节奏方面，国资政策类文件随监管要求动态更新，内部核心制度按需修订，常规办公文档每半年集中复核更新。文档多采用正式公文格式，包含文号、发布部门、生效日期、适用范围等字段，流程类文档还包含步骤节点、责任岗位等结构化内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
国资政策类文档的权威性要求检索结果需匹配最新生效版本，因此需要对文档的生效日期字段做精准过滤，避免召回过期内容。内部制度存在明确的适用范围，检索时需结合用户所属部门、子公司做范围限定，防止返回跨适用场景的文档。正式公文多为长文本，分块时需保留文号、生效日期等关键元数据，避免破坏文档的权威性标识。结构化字段较多，仅依赖关键词模糊匹配无法满足精准筛选需求，需支持按字段进行定向筛选。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.72–0.85` | 国有资本运营公司文档多为正式文本，语义关联度要求较高，避免低匹配度的无关内容混入结果集 |
| `limit` | `前8–12条` | 内部办公文档按业务线、部门分层管理，过多结果会增加员工筛选成本，过少则可能遗漏适配内容 |
| `searchMode` | `vector + keyword` | 兼顾语义匹配与关键词精准命中，适配正式公文的文号、政策名称等固定字段的检索需求 |
| `usingReRank` | `开启` | 长文本分块后可能存在语义分散，重排可提升结果的相关性排序准确性 |
| `datasetSearchUsingExtensionQuery` | `开启` | 可通过扩展用户问题的同义表述，覆盖国资政策、内部制度的不同称谓，比如“薪酬”与“薪资福利” |
| `collectionIds` | `按业务线、部门划分的集合ID列表` | 可限定检索范围，避免跨部门、跨子公司的不适用文档被召回 |

## 容易做错的三处
- 现象：检索结果仅返回1个文本块，原因是错误将`limit`参数设置为1，未根据业务场景调整合理取值。
- 现象：企微渠道调用知识库时出现授权失败报错，原因是未配置对应渠道的权限绑定规则，且未更新适配的渠道配置参数。
- 现象：检索结果包含过期的国资政策文档，原因是未开启按生效日期字段的过滤逻辑，未限定仅召回生效中的文档。

## 怎么确认配好了
- 发起包含特定国资政策文号的查询，核对检索结果是否包含对应文号的文档且排序靠前。
- 切换不同部门的测试账号发起查询，核对结果是否仅包含该部门适用的文档。
- 调整`similarity`参数的取值区间，观察检索结果的匹配度变化，确认参数生效。
- 上传一份过期的测试文档并发起对应查询，确认该文档未被召回。
