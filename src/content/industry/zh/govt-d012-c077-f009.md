# 城市公交的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
城市公交的业务数据主要来自车载智能终端、调度指挥系统、票务结算平台与场站运维系统。数据更新节奏分为实时、每日与月度三类：实时数据包含车辆当前位置、载客人数、运行状态，每10-30秒更新一次；每日数据为当日票务营收、班次完成率、场站巡检记录，当日24点前完成汇总；月度数据为线路运维成本、客流波动统计，次月5日前生成。单条数据结构包含线路编号、站点名称、车辆识别码、工单编号、处理进度等字段，部分字段带有明确单位，如续航里程（km）、响应时长（秒）。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时客流、车辆位置的高频更新要求模型调用的响应延迟需匹配数据刷新节奏，避免返回过时信息。多源分散的业务数据需要在接入环节配置跨系统数据调用权限，确保调度、票务、运维数据可被统一调用。月度汇总的长文本运维统计报表要求调整模型上下文窗口参数，适配批量数据的分析需求。不同字段的单位差异需在配置中添加格式校验规则，避免单位不匹配导致工具调用失败。公交内部工单涉及运营敏感信息，接入配置需添加数据脱敏的前置校验环节。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配公交多源业务数据的上下文长度，避免因上下文溢出丢失关键调度与工单信息 |
| `maxTokens` | 2000–3000 token | 匹配内部办公场景的回答长度需求，确保工单处理建议、客流分析结果可完整输出 |
| `quoteMaxToken` | 1500 token | 用于引用数据库原文片段时，限制单条引用数据的长度，符合公交运维记录、票务报表的单条内容规模 |
| `toolChoice` | auto | 支持自动选择工具调用，适配调度查询、工单处理等多场景的动态需求 |
| `temperature` | 0.3–0.5 | 降低回答的随机性，确保运维建议、排班调整方案的严谨性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写本地或云服务商的API接入地址 | 适配FastGPT本地部署的模型调用链路，确保数据传输符合内部网络安全要求 |

## 容易做错的三处
- 现象：本地部署FastGPT新增模型后测试时报错403 status code (no body)。原因：未正确配置`AIPROXY_API_ENDPOINT`或对应模型的密钥参数，导致身份校验失败或网络链路不通。
- 现象：渠道配置列表中未显示目标模型，无法完成接入流程。原因：未在FastGPT的模型管理页面添加对应模型的接入地址与密钥，或部署版本未适配该模型的调用协议。
- 现象：通过Function CALL调用MYSQL数据后，大模型回答未引用数据库原文片段。原因：未配置`quoteMaxToken`参数限制引用长度，或未开启工具调用后的原文引用开关，导致模型无法提取并展示数据库原文内容。

## 怎么确认配好了
- 进入FastGPT的模型测试页面，输入公交调度相关的查询，检查返回结果是否包含正确的线路、站点信息。
- 发起多轮对话测试，确认上下文信息可被正确保留，回答内容符合对话逻辑。
- 调用Function CALL工具测试数据库查询，检查返回结果中是否包含数据库原文片段。
- 查看FastGPT的日志面板，确认模型调用请求的状态码为200，无报错信息。
