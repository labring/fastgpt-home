# 城市水务的内部办公与员工服务：HTTP 接口与外部系统

## 这个品类的数据长什么样
城市水务的内部数据来源于市政管网监测节点、水厂自控系统、排水泵站数据平台与内部巡检工单系统。数据更新节奏分为两类：设备运行类数据每10至60秒推送一次，巡检工单与员工排班类数据每日凌晨批量同步。数据文档为结构化JSON格式，包含泵站编号、实时水位（单位米）、管网压力（单位兆帕）、水质浊度（单位NTU）、设备运行状态、工单编号、处理进度等固定字段，无额外动态字段，字段类型与取值范围均由水务系统预先定义。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
实时设备数据的低延迟推送要求接口响应需控制在合理区间，避免数据积压导致调度延迟。固定结构的字段要求请求与响应的参数格式严格匹配，不可随意增减字段，否则会导致下游系统解析失败。巡检工单的批量同步数据量较大，需配置分页参数以避免单次请求过载。此外，水务系统的外部接口通常要求身份鉴权，需正确设置`Authorization`参数，否则无法正常调用，且接口返回的字段单位需与内部业务系统对齐，否则会引发数据异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {水务系统提供的API密钥}` | 水务系统的外部接口通常采用Bearer令牌鉴权，确保调用合法性，符合FastGPT v4.17.0的鉴权配置规范 |
| `variables` | `{"stationId": "001", "dataType": "realTime"}` | 用于向水务系统接口传递固定的查询参数，限定查询范围与数据类型，适配固定结构的请求格式 |
| `responseData` | 仅返回指定核心字段 | 过滤冗余的非业务数据，降低HTTP传输负载，提升接口调用效率 |
| 单次请求数据上限 | `前100条` | 平衡批量工单数据的传输效率与接口负载，避免单次请求过载 |
| 接口超时时间 | `30-60秒` | 适配实时数据接口的低延迟要求，批量接口可适当放宽至60秒，规避网络波动导致的请求失败 |

## 容易做错的三处
- 现象：调用水务接口时返回`messages is empty`报错，原因：未在`variables`中配置必要的查询参数，导致接口无法识别请求范围，返回空数据。
- 现象：FastGPT提示模型流响应为空，原因：未正确设置`Authorization`参数，水务接口鉴权失败后返回空响应体，被FastGPT识别为无效流。
- 现象：批量工单接口返回数据条数与预期不符，原因：未配置分页参数，接口仅返回默认条数的数据，未拉取全量内容。

## 怎么确认配好了
- 调用测试接口，查看返回的响应体是否包含水务系统的核心字段，如泵站编号、实时水位等，确认数据格式与预期一致。
- 检查`Authorization`参数的格式是否正确，可通过接口调试工具验证鉴权是否通过，无401或403报错。
- 模拟批量请求，确认返回的数据条数符合配置的单次请求上限，无截断或溢出情况。
- 查看FastGPT的运行日志，确认接口请求的参数与配置一致，无缺失或格式错误。
