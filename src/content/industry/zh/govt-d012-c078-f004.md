# 城市水务的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
城市水务的业务数据来源于管网监测设备、水厂运行日志、客户报修工单、水质检测报告、员工巡检记录等。数据更新节奏存在差异：管网监测数据为分钟级实时更新，报修工单与巡检记录为实时提交，水质检测报告则按批次每日或每周更新。数据文档结构包含设备ID、时间戳、参数值（如浊度、水压、余氯）、工单编号、处理进度、员工工号等字段，部分字段带有专属单位，例如浊度单位为NTU、水压单位为MPa。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流支持多节点聚合不同类型的业务数据，避免出现数据断层。不同的更新节奏需要工作流适配多样化的触发方式，支持实时事件触发以处理高频监测数据，也支持定时触发以处理周期性报表。带有专属单位的字段要求工作流的变量配置严格匹配对应参数的单位定义，防止参数解析错误。体积差异较大的文件类数据，如大型管网CAD图纸、完整水质检测报告，要求工作流的文件处理节点支持灵活的尺寸适配与分块处理。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |

| 变量配置 | 绑定设备ID、浊度、水压等字段，单位匹配NTU、MPa | 匹配水务数据的固有字段与单位，确保参数解析准确 |
| 触发节点类型 | 事件触发+定时触发组合 | 适配实时监测数据与周期性巡检报表的更新节奏 |
| 上下文窗口大小 | 800–1200 字符 | 适配单条水务工单或监测数据的文本长度，避免冗余上下文干扰 |
| 文件上传阈值 | 1000 MB | 容纳水质检测报告、大型管网CAD图纸等水务场景文件 |
| 重试次数 | 3 次 | 应对网络波动导致的API调用失败，适配水务数据传输的不稳定场景 |
| 超时时间 | 600 秒 | 适配大型文件解析或多源数据聚合的处理时长 |

## 容易做错的三处
- 工作流中配置聊天记录上限为1，但仍返回多条历史记录。原因是未将上下文窗口与`variables`中的历史记录变量绑定，导致系统调用全局上下文配置。
- API调用工作流时上传文件失败，提示Failed to create post presigned url。原因是未在工作流的文件上传节点配置正确的存储路径权限，或文件大小超出预设阈值。
- API调用插件传递文件参数无响应。原因是未将文件变量与插件的输入参数正确绑定，导致参数格式不匹配。

## 怎么确认配好了
- 触发工作流传入一条模拟水务工单数据，检查`variables`中是否正确提取了工单编号与对应字段值。
- 上传一份小型水质检测PDF文件，确认工作流能正常解析并提取文本内容。
- 调整触发节点为事件触发，模拟设备上报数据，检查工作流是否自动执行。
- 查看工作流执行日志，确认重试次数与超时时间的配置在执行中生效。
