# 城市水务的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
城市水务的业务数据主要来自管网监测传感器、水厂中控系统、水质检测实验室、内部工单系统。管网压力、流量等实时数据按秒级更新，水质检测报告每日同步，月度运维工单每月汇总。数据文档分为结构化监测表、半结构化工单记录、非结构化检测报告三类，结构化字段包含点位ID、检测时间、数值与对应单位，工单记录包含报修编号、处理状态、关联区域等信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时监测数据的高频更新要求模型接入适配短间隔同步或流式上下文，防止上下文溢出；结构化数据含专属点位ID、压力kPa、流量m³/h等字段与单位，需在配置中明确字段映射规则，避免单位混淆；非结构化检测报告的长文本占比高，需限制单条输入的token上限；工单系统的关联区域字段需要精准匹配，需调整上下文召回的匹配规则，确保关联信息准确。多源异构的数据特性也要求配置支持多数据源的统一接入格式，避免不同系统的数据格式冲突。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配水务场景多源数据拼接后的上下文长度，避免超出模型承载上限 |
| `maxTokens` | 2000–3000 token | 单轮回复需覆盖水质分析、工单处理建议等内容，避免截断关键信息 |
| `quoteMaxToken` | 4000 token | 召回的监测数据、工单记录等参考内容需完整保留点位、数值等核心字段 |
| `temperature` | 0.3–0.5 | 水务场景需精准的技术建议，不宜过度随机 |
| `AIPROXY_API_ENDPOINT` | 部署模型服务的实际访问地址，如http://B机器IP:11434/v1 | 对接外部部署的模型服务需指定正确的API访问路径 |
| `AIPROXY_API_TOKEN` | 与模型服务匹配的令牌值 | 验证FastGPT与模型服务的访问权限，确保调用合法 |

## 容易做错的三处
- 现象：调用模型时返回令牌验证失败，OneAPI日志显示令牌为“fastgpt”。原因：FastGPT配置的`AIPROXY_API_TOKEN`与OneAPI中设置的令牌不匹配，导致权限校验失败。
- 现象：跨机器部署时模型连接超时，无法获取模型响应。原因：未开放模型服务端口的网络权限，或`AIPROXY_API_ENDPOINT`填写的IP地址或端口错误，导致网络无法连通。
- 现象：模型回复截断了水务数据的关键数值或点位信息。原因：`maxTokens`或`quoteMaxToken`配置取值过小，导致参考数据或回复内容被截断。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置值，与目标模型服务的地址、令牌完全一致。
- 发起一轮针对水务工单或水质分析的测试提问，查看模型是否能正确召回关联的监测数据与工单记录。
- 调整`temperature`等参数后，观察模型回复的随机性是否符合场景需求。
- 查看FastGPT的模型调用日志，确认无令牌错误、连接超时等异常提示。
