# 城市水务的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
城市水务的内部办公数据来自管网压力流量监测设备、智能水表、泵站控制系统、水质检测实验室、内部工单系统与员工巡检记录。更新节奏分为三类：实时监测数据秒级更新，抄表数据按日或周批量更新，巡检报告、水质检测报告按工作周期更新。文档结构包含结构化时序数据（含节点ID、监测值、采集时间、单位）与非结构化文档（含工单编号、处理状态、责任人、附件照片），字段包含专属的水务设备编码、管网拓扑标识等。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `REDIS_URL` | `redis://:自定义密码@内网Redis服务地址:6379/0` | 缓存实时管网监测数据，降低数据库查询压力，适配秒级数据更新需求 |
| `PG_URL` | `postgresql://数据库用户名:数据库密码@内网PG地址:5432/water_office_db` | 存储结构化的抄表数据、工单记录、员工信息，支持复杂的业务查询 |
| `STORAGE_S3_ENDPOINT` | `内网MinIO服务地址:9000` | 存储巡检照片、水质检测报告等非结构化文件，符合内网数据存储合规要求 |
| `DB_MAX_LINK` | `200–300 个连接` | 适配水务系统多并发的实时数据上报与工单处理请求，避免数据库连接耗尽 |
| `FILE_TOKEN_KEY` | 按内部安全规范生成的32位随机字符串 | 加密文件访问令牌，防止未授权访问敏感的水务业务文件 |
| `FE_DOMAIN` | `内网域名:端口` 或 `本地IP:端口` | 适配内网部署场景，避免公网暴露内部办公服务 |

## 容易做错的三处
- 现象：无外网私有化部署后，工作流编辑界面显示客户端异常报错。原因：未配置内网可访问的`FE_DOMAIN`，且前端静态资源未提前离线打包，导致无法加载必要的前端依赖。
- 现象：构建Docker镜像时提示找不到rehype-raw模块，即使已执行安装命令。原因：依赖安装未指定内网离线源，或离线依赖包未完整导入镜像构建目录，导致依赖拉取失败。
- 现象：Docker容器启动后持续重启，无法正常访问服务。原因：`MONGODB_URI`或`PG_URL`配置错误，数据库连接验证失败，服务启动后因无法连接依赖服务自动退出。

## 怎么确认配好了
- 访问配置的`FE_DOMAIN`地址，确认前端页面正常加载，无资源加载失败的提示。
- 执行数据库连通性测试脚本，分别验证`REDIS_URL`、`PG_URL`、`MONGODB_URI`对应的服务均可正常建立连接。
- 上传一份小型的巡检照片文件，确认文件可正常存储，并通过生成的访问链接正常预览。
- 提交一条测试工单，确认数据可正常写入数据库，无超时或写入失败的提示。
