# 城市燃气的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
数据来源包括内部运维管理系统的巡检工单、管网基础台账、安全作业规程、员工服务手册、客户诉求工单归档。更新节奏分为实时（巡检、工单类）、月度（管网参数更新）、季度（安全规范修订）。文档结构多为结构化字段与非结构化文本混合，字段包含管网ID、巡检时间、故障等级、燃气压力（单位MPa）、巡检里程（单位km），部分文档为数千字符的长文本安全操作指南。

## 这些特征在「向量模型与索引」这一环带来什么约束
混合结构化字段与非结构化文本的数据结构，要求索引同时支持字段过滤与向量召回，精准匹配管网ID、故障等级等条件。实时产生的巡检、工单数据，要求索引支持增量更新流程，避免全量重建带来的资源消耗。长文本的安全操作指南存在语义连贯需求，需要适配长文本分块逻辑。字段自带特定单位，嵌入时需保留单位以保证语义匹配精度。多更新频率的数据源，需要配置差异化的同步调度规则，避免索引冲突与数据滞后。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配：
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配长文本的安全操作指南与工单摘要，避免语义断裂 |
| 重叠长度 | 100–150 字符 | 保留分块间的语义衔接，避免关键信息被截断 |
| 相似度阈值 | 0.72–0.78 按实测标定 | 适配燃气行业术语的语义相似度区间，过滤低相关结果 |
| 单次搜索上限 | 前 8 条 | 覆盖管网巡检、工单等多场景的召回需求，避免冗余结果 |
| `defaultToken` | 512 token | 作为短文本嵌入的基准长度，适配工单摘要类数据 |
| `maxToken` | 4096 token | 适配嵌入模型的输入长度限制，保证长文档分块的有效嵌入 |

## 容易做错的三处
- 现象为使用chunk模式调用pushdata api上传数据后，界面长期显示“索引中”状态。原因是未配置增量索引的触发阈值，导致大量分块堆积未完成索引。
- 现象为问答拆分后的最后一组文本无法完成索引，返回空结果字段。原因是最后一组文本长度超出`maxToken`限制，嵌入失败。
- 现象为搜索结果相关性整体偏低，所有结果匹配度无明显差异。原因是未保留字段单位信息，导致嵌入时语义匹配出现偏差。

## 怎么确认配好了
- 上传一条带管网ID字段的巡检工单数据，查看索引日志中是否包含字段过滤规则的生效记录。
- 查看嵌入任务的参数配置，验证长文本分块未触发截断报错。
- 手动输入一条燃气专业术语，检索结果中是否包含相关的安全规程或工单数据。
- 增量上传一条新的巡检记录，确认检索结果中可查询到该新数据。
