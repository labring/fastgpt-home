# 城市燃气的内部办公与员工服务：工作流编排
本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
城市燃气的业务数据主要来源于管网SCADA系统、手持巡检PDA终端、客户服务工单系统与燃气安全检测档案库。数据更新节奏存在差异：管网压力、流量等实时监控数据秒级更新，巡检记录按单次巡检批次更新，客户工单数据实时生成，安检档案按季度同步更新。单条数据文档包含设备编号、采集时间、压力值（单位kPa）、巡检点位、工单编号、检测结果等字段，部分字段需关联唯一设备标识与业务场景标签。

## 这些特征在「工作流编排」这一环带来什么约束
实时监控数据的秒级更新要求工作流节点的调用延迟需控制在合理区间，避免数据过时导致调度决策偏差。巡检记录按批次提交的特征，要求工作流需支持批量数据导入与拆分处理的节点配置，适配日常巡检的提交规模。燃气数据特有的压力值单位kPa，要求工作流的数据校验节点需针对该单位配置格式与范围规则，避免无效数据进入后续流程。季度更新的安检档案，要求全局变量需匹配该更新节奏，避免调用过期档案数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 数据来源节点 | 关联SCADA系统、手持巡检PDA接口 | 匹配城市燃气核心业务数据来源 |
| 批量处理阈值 | 50条/批次 | 适配日常巡检记录的常规提交规模 |
| 数据校验规则 | 校验压力值范围0-1000kPa | 匹配燃气输配设备的正常运行参数区间 |
| 全局变量配置 | 绑定管网巡检更新周期为90天 | 对应安检档案的季度更新节奏 |
| `variables` | 引用预设的设备编号常量 | 简化多工作流节点的设备标识调用 |
| `nodeId` | 绑定SCADA实时数据节点的唯一标识 | 确保工作流节点调用的精准性 |

## 容易做错的三处
- 现象：数据库连接节点配置界面中端口号输入框置灰无法编辑。原因：未先选择对应燃气行业数据库的专属驱动类型，导致端口号配置项未激活。
- 现象：工具调用节点运行时返回429 Request rate increased too quickly状态码。原因：未限制模型调用频率，未配置合理的请求间隔参数。
- 现象：工作流中文件上传节点无法正常接收巡检照片。原因：未设置正确的文件类型白名单，或未配置上传目录的读写权限。

## 怎么确认配好了
- 启动测试工作流，导入一条模拟的管网压力数据，查看节点输出是否包含正确的压力值与设备编号。
- 触发批量巡检记录导入，确认工作流按50条/批次的阈值拆分处理任务。
- 上传一张巡检照片至文件上传节点，确认文件可正常存储并传递至后续节点。
- 查看工具调用节点的日志，确认无429状态码返回，请求频率符合预设要求。
