# 城投平台的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
城投平台的内部办公与员工服务数据，主要来源于OA系统、财务报销系统、项目台账、员工考勤系统及内部会议纪要。日常办公类数据（如考勤、报销）每日更新，项目类文档（如可研报告、运维日志）随项目节点触发更新。数据包含结构化字段与非结构化文本两类：结构化字段包括员工工号、部门名称、审批金额（单位：元）、项目编号等，非结构化文本多为数十页的项目汇报、运维记录。

## 这些特征在「模型接入与配置」这一环带来什么约束
城投平台的办公数据分散在多套内部系统，且包含结构化字段与非结构化长文档，因此模型接入时需支持多源数据的统一对接。日常办公数据实时更新、项目文档随节点触发更新，要求配置的上下文长度适配不同更新节奏的内容。结构化字段带有明确的单位与专属标识，模型调用时需准确匹配字段定义，避免解析错误。长文本类的项目文档占比高，需调整模型的上下文与输出token上限，确保核心内容不被截断。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配城投平台长文档（如项目可研）与多系统上下文拼接需求，避免截断核心内容 |
| `maxTokens` | 2000–3000 token | 满足审批流程说明、项目进度汇报等长文本输出需求，同时控制单次调用成本 |
| `quoteMaxToken` | 1500 token | 匹配城投平台结构化数据字段与引用文档的长度，确保引用内容完整 |
| `temperature` | 0.3–0.5 | 适配办公场景的严谨性需求，避免生成过于随意的审批建议或项目解读 |
| `AIPROXY_API_ENDPOINT` | 填写内部私有模型的完整接口地址，如`http://192.168.xx.xx:3000/v1` | 城投平台多采用内部私有部署模型，需使用内部代理地址对接私有模型 |
| `AIPROXY_API_TOKEN` | 填写私有模型平台生成的访问令牌 | 用于身份验证，确保内部模型调用的安全性 |

## 容易做错的三处
- 调用私有部署模型时返回404状态码。原因：未正确填写`AIPROXY_API_ENDPOINT`的完整路径，或私有模型的接口路径与FastGPT配置的路径不匹配，比如遗漏`/v1`后缀。
- 工作流代码模块调用外部模型时无法实现流式输出。原因：未在代码模块中配置正确的流式响应接收逻辑，未启用模型的流式输出开关，或未匹配FastGPT的流式数据格式。
- 向量模型配置完成后导入城投项目文档报错。原因：未将向量库索引字段与城投平台的员工工号、项目编号等专属字段对齐，导致索引构建失败。

## 怎么确认配好了
- 进入FastGPT的模型测试页面，输入城投平台的典型办公问题，如“查看员工张三的2024年10月报销记录”，查看接口返回状态码为200且无报错信息。
- 导入一份城投项目的可研报告，检查向量库是否成功索引，无字段解析错误或内容截断提示。
- 在工作流中添加代码模块，调用配置好的模型，验证是否能接收流式分段的输出结果。
- 检查`AIPROXY_API_TOKEN`的权限，确认是否允许访问当前配置的模型，无权限相关报错。
