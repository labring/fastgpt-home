# 城投平台的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
城投平台的内部办公与员工服务数据主要来自内部OA系统、财务报销平台、项目管理台账、员工考勤系统四类来源。数据更新节奏存在差异：员工考勤数据按工作日实时同步，报销数据每日同步更新，项目台账则按月完成全量更新。数据结构分为两类：结构化数据包含员工工号、项目编号、考勤时长、报销金额等字段，其中项目编号采用「地区编码+年份+项目序号」的固定格式，考勤时长以分钟为单位；非结构化数据包含办公文档、项目汇报材料等，以PDF、Word格式存储。

## 这些特征在「部署与升级」这一环带来什么约束
城投平台的数据特征对部署与升级环节提出多项约束。首先，结构化与非结构化数据并存的特征，要求部署时同时配置关系型数据库与文档数据库，适配不同类型数据的存储需求。其次，多频率的更新节奏，要求升级脚本支持增量同步逻辑，避免全量同步导致的内部系统负载过高。再次，城投平台的内部系统多部署于政务内网，需严格遵循数据不出网的合规要求，因此部署环节需配置内网专属的访问路径与存储端点。最后，统一的内部编码规则，要求权限配置与员工工号、项目编号等字段强绑定，升级时不能破坏现有权限映射关系。FastGPT v4.17.0版本的部署工具已适配内网环境配置，可直接匹配上述约束。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–20 个连接 | 城投平台内部办公数据并发量较高，需维持足够连接数保障多系统同时访问 |
| `MONGODB_URI` | 政务内网部署的副本集连接地址 | 存储非结构化办公文档与项目台账，符合内网数据存储合规要求 |
| `PG_URL` | 政务内网部署的PostgreSQL连接地址 | 存储结构化员工信息、考勤与报销数据，适配城投内部结构化数据管理习惯 |
| `FE_DOMAIN` | 政务内网域名或政务云负载均衡地址 | 保障内部员工通过政务内网访问前端界面，避免公网暴露风险 |
| `STORAGE_S3_ENDPOINT` | 政务云对象存储内网端点 | 存储办公附件与项目资料，满足数据不出网的合规要求 |
| `ROOT_KEY` | 按城投内部权限规则生成的随机密钥 | 初始化系统管理员权限，匹配内部账号管理体系 |

## 容易做错的三处
- 执行升级脚本时出现`POST /api/admin/initv4818 404`报错。原因是未正确配置`FE_DOMAIN`与内网访问路径，导致升级接口无法被内部网络正常调用。
- 部署完成后无法查询初始登录用户名与密码。原因是未正确生成`ROOT_KEY`并写入配置文件，导致系统未初始化管理员账号。
- 钉钉机器人部署时出现消息接收地址校验失败。原因是未将`FE_DOMAIN`配置为政务内网可访问的地址，且未按提示禁用SSL证书校验（若未配置有效SSL证书）。

## 怎么确认配好了
- 执行数据库连接测试命令，验证`PG_URL`、`MONGODB_URI`与`REDIS_URL`对应的存储服务可正常连通。
- 访问配置的`FE_DOMAIN`地址，确认前端界面可正常加载且无权限拦截提示。
- 上传一份城投内部办公文档，验证`STORAGE_S3_ENDPOINT`对应的存储服务可正常接收并存储文件。
- 执行升级脚本的预检查命令，确认接口路径可被正常调用，无404类报错。
