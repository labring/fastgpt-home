# 基础化工的内部办公与员工服务：向量模型与索引
本页适用 FastGPT v4.17.0 版本。

## 这个品类的数据长什么样
基础化工内部办公与员工服务的数据源涵盖生产工艺规程、设备运维手册、安全操作规范、员工培训资料、供应链台账等。数据更新节奏差异明显：工艺规程随工艺迭代半年至一年更新一次，运维手册随设备改造实时调整，安全规范按监管要求定期修订，员工培训资料则随培训计划不定期更新。文档结构包含长文本（如完整工艺手册可达数十页）、短文本（如岗位安全提示），字段包含文档编号、版本号、生效日期、所属车间、对应设备型号等，单位涉及台、立方米、小时、人次等。

## 这些特征在「向量模型与索引」这一环带来什么约束
基础化工内部办公数据的多类型、更新节奏差异及结构化字段特征，对向量模型与索引环节形成多重约束。长文本占比高，要求分块策略需平衡语义完整性与向量嵌入效率；不同文档的更新频率差异，要求索引需支持增量同步与版本化管理，避免旧数据与新数据混淆；结构化字段如所属车间、设备型号，需与非结构化文本内容绑定索引，提升专业场景下的召回精准度；部分高频更新的运维文档，需缩短向量索引的刷新间隔，保障数据时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 基础化工内部文档多为长格式工艺、运维文本，该长度可保留专业术语与操作步骤的语义完整性 |
| 重叠长度 | 100–150 字符 | 避免长文本分块后语义断裂，适配跨块出现的设备编号、工艺参数等专业内容连贯性 |
| 相似度阈值 | 0.72–0.85 | 化工专业术语辨识度较高，该区间可过滤低相关的召回结果，提升内部服务的精准度 |
| 单次搜索上限 | 前8–12条 | 内部办公场景下核心信息集中在少量高相关结果中，避免冗余数据占用上下文空间 |
| `maxToken` | 4000–6000 token | 适配长文档拼接后的上下文长度，符合基础化工文档的平均信息密度 |
| `defaultToken` | 1500–2000 token | 匹配单条分块的合理向量输出长度，避免嵌入过程中出现超限报错 |

## 容易做错的三处
- 向量化任务报错，日志提示速率超限。原因：未根据文档平均长度调整分块线程数，或分块长度设置过小导致单批次数据量过大，超出接口调用限制。
- 知识库检索响应时长超出合理范围，同模型下其他场景速度正常。原因：单次搜索上限设置过高，导致向量召回的结果量过大，后续处理环节耗时增加。
- 数据集条目数在无手动操作的情况下出现重复增长。原因：未开启版本化索引，或增量同步触发逻辑未过滤已处理的文档版本，导致旧数据被重复索引。

## 怎么确认配好了
- 上传单份典型化工工艺文档，检查分块后的文本长度与设定的分块长度基本匹配。
- 发起一次检索测试，查看返回结果的相似度分值是否落在设定的阈值区间内。
- 查看向量嵌入日志，确认单条分块的token数未超出`maxToken`与`defaultToken`的设定范围。
- 手动触发一次增量同步，检查数据集条目数未出现无规则的重复增长。
