# 基础化工的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
基础化工内部办公与员工服务的数据主要来自生产ERP系统、设备运维工单系统、OA办公平台及员工考勤系统。生产台账数据按班次更新，设备运维日志随工单完成实时同步，OA审批与考勤数据每日刷新。文档结构包含设备编号、班次、产量、能耗（单位为吨、千瓦时）、工号、部门、岗位、审批节点、备件型号等字段，部分长文档包含多段流程说明与参数记录。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
基础化工的多轮对话与提示词配置需适配数据特征带来的约束。生产与运维数据的实时性要求对话可快速调用最新台账与工单信息，提示词需明确指定优先使用当前会话内的最新数据。多字段包含专属单位，提示词需强制要求输出结果保留对应单位，避免参数混淆。长文档包含多段流程与参数，多轮上下文需限制长度，防止因上下文溢出丢失关键流程节点。员工相关数据涉及工号与部门，对话需校验上下文字段的一致性，防止跨会话数据混用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 基础化工内部文档多包含多段流程与参数，该区间可覆盖完整工单或台账片段，防止上下文溢出 |
| 单次召回文档条数 | 前3–5条 | 内部办公数据字段多且关联紧密，少量高相关文档可避免信息过载 |
| 提示词前缀配置 | 固定要求保留设备、能耗的专属单位 | 基础化工数据包含吨、千瓦时等专属单位，需强制对齐输出格式 |
| 会话超时时间 | 300 秒 | 内部办公对话多涉及审批查询、工单跟进，该时长可覆盖常规咨询周期 |
| 变量绑定规则 | 绑定工号、部门变量至会话上下文 | 员工服务场景需关联个人岗位信息，通过`variables`参数实现会话内变量复用 |

## 容易做错的三处
- 现象：发起员工身份查询时，对话日志中未返回飞书用户名，对应字段为空。原因：未在会话中绑定对应身份变量，未通过`variables`参数传递用户身份标识。
- 现象：上传的生产台账或运维工单数据未参与统计总结，输出结果未包含上传内容。原因：未将上传的知识库文件关联至当前会话上下文，提示词未明确要求调用上传数据。
- 现象：使用本地模型与知识库对话时出现卡顿，响应超时。原因：单次召回文档条数设置过高，导致模型处理的上下文长度超出本地算力承载范围。

## 怎么确认配好了
- 发起包含生产数据查询的对话，检查输出结果是否包含指定的单位（如吨、千瓦时），确认提示词配置生效。
- 上传一份测试用的运维工单文档，发起统计总结请求，确认输出结果包含上传文档的内容，验证数据关联正常。
- 查看会话日志，确认`chatId`与当前会话标识匹配，且`messages`参数中包含完整的对话轮次，上下文未出现截断。
- 发起员工身份相关的查询，确认返回结果关联了当前会话绑定的工号与部门信息，验证变量绑定生效。
