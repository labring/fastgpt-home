# 基础化工的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
基础化工的业务数据主要来自生产DCS系统、设备巡检台账、ERP物料管理模块、安全合规档案。数据更新节奏差异明显：生产实时数据每15秒刷新，巡检记录每日归档，ERP物料数据每日同步，合规文档按季度更新。文档结构多为结构化表格或带固定字段的文本，包含设备编号、批次号、原料消耗量、产出吨位、异常报警等级等字段，单位多为吨、立方米、小时、ppm等。

## 这些特征在「工作流编排」这一环带来什么约束
基础化工的数据多源异构且更新节奏差异显著，首先要求工作流支持混合触发模式，兼顾实时生产数据拉取与定时同步的ERP、合规文档。其次，结构化数据字段包含吨、ppm、小时等多类单位，工作流的`variables`提取节点需预设单位匹配规则，避免数值与单位错位。此外，长文本合规文档的非结构化内容，要求工作流集成文本分段与关键词提取节点，适配长文档的处理逻辑。同时，设备巡检记录的批量归档场景，要求工作流支持批量数据导入与校验节点，确保单批次数据的完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按生产数据刷新频率（15秒/1小时/每日） | 匹配基础化工不同数据源的更新节奏，避免无效触发 |
| `variables` 配置 | 预设设备编号、批次号、吨数、ppm等字段变量 | 匹配业务数据的标准字段结构，确保变量提取准确 |
| 知识库关联 | 关联多个业务知识库 | 覆盖内部办公与员工服务的多类场景，满足多知识库引用需求 |
| 批量导入阈值 | 单次导入100-500条记录 | 适配巡检记录、生产台账的批量归档场景，避免单批次数据过载 |
| 错误重试次数 | 2-3次 | 适配网络波动或临时数据读取失败的常见场景 |
| `nodeId` 配置 | 按节点功能命名（如巡检数据提取节点ID） | 便于工作流调试与跨节点变量传递 |

## 容易做错的三处
- 现象：工作流运行时弹出“数据格式不匹配”报错，模型配置检查无异常。原因：未针对基础化工的多单位字段（如吨与千克）配置变量转换规则，导致数值与单位错位。
- 现象：关键词提取节点返回空值，无法从巡检记录或办公申请文本中获取专业字段信息。原因：未预设基础化工业务字段的关键词匹配规则，仅使用通用关键词模型，无法识别设备编号、ppm值、批次号等专业字段。
- 现象：配置的全局批次号变量无法在下游数据校验节点中调用。原因：未在工作流起始节点正确绑定全局变量的数据源，或变量作用域未覆盖下游节点。

## 怎么确认配好了
- 触发FastGPT v4.17.0版本的工作流测试运行，查看节点日志中是否正确提取到预设的`variables`字段值，确认变量匹配规则生效。
- 导入单批次模拟数据，检查批量导入节点是否正常处理，无过载报错。
- 手动修改触发频率，验证工作流是否按设定节奏触发，匹配对应数据源的更新周期。
- 调用跨节点变量，确认`nodeId`对应的节点可正常获取上游传递的参数。
