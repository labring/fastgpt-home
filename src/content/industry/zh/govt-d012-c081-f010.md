# 基础化工的内部办公与员工服务：知识库检索与召回

## 这个品类的数据长什么样
基础化工的内部办公数据主要来自工艺规程、安全操作手册、设备运维台账、原料质检报告与应急处置指南。数据更新随工艺迭代、设备检修或原料标准调整触发，日常运维记录按周同步。文档多为结构化与半结构化混合，包含设备编号、操作参数、安全阈值等字段，单位常涉及兆帕、摄氏度、吨等工业标准单位，单篇文档长度跨度较大，从数百字符到数万字符不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
基础化工的文档特征对检索召回带来多重约束。长文档占比高，需适配长文本分块规则，避免关键参数被拆分丢失。文档包含明确的工业参数与单位，检索时需支持数值范围匹配与单位归一化，否则无法精准召回对应工况的操作指南。数据更新无固定周期，需支持增量同步机制，确保召回内容与最新工艺、运维要求一致。半结构化文档的字段分布不均，需优先召回包含目标设备编号或参数阈值的条目。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 基础化工文档多为专业术语，需较高相似度阈值过滤无关内容，避免误召回非目标工况的规程。 |
| `limit` | `前 8–12 条` | 单篇化工文档较长，过多召回结果会超出上下文窗口，8-12条可覆盖核心工况参数与操作步骤。 |
| `searchMode` | `semantic + keyword` | 兼顾专业术语的语义匹配与设备编号、参数数值的精准关键词匹配，适配半结构化文档特征。 |
| `usingReRank` | `开启` | 长文档分块后易出现语义分散，重排可优先召回包含核心参数的分块内容。 |
| `datasetSearchUsingExtensionQuery` | `开启` | 基础化工术语多为行业专属，扩展查询可补充同义词与单位变体，提升召回覆盖度。 |
| `collectionIds` | `绑定对应工艺、运维类数据集ID` | 隔离不同车间、设备的知识库内容，避免跨场景召回干扰。 |

## 容易做错的三处
- 搜索时返回`invalid configuration parameter name "hnsw.max_scan_tuples"`报错。原因：误用了FastGPT官方未定义的检索参数，需检查配置项是否在指定清单内。
- 误调用非目录创建的API完成知识库目录搭建，导致后续无法正常挂载数据集。原因：混淆了数据集管理与检索配置的API接口，需使用专属的知识库目录创建接口。
- 升级版本后知识库内容可在页面查看，但对话时模型提示知识库为空。原因：未执行版本适配的数据库迁移步骤，或迁移后未重新构建数据集向量索引。

## 怎么确认配好了
- 执行测试检索，输入目标设备编号与参数值，核对召回结果是否包含对应文档的核心内容。
- 检查配置项是否全部启用或设置为符合业务需求的取值，确认无未定义参数。
- 触发一次增量同步，等待索引构建完成后，发起跨场景检索，确认未召回无关数据集的内容。
- 查看检索日志，确认相似度、重排等配置项的参数已生效，无异常报错。
