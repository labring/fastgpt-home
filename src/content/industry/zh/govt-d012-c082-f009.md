# 基础电信运营的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
基础电信运营的内部办公数据主要来自运维监控系统、员工工单平台、营业厅业务台账与网络设备日志。数据更新以分钟级或小时级为主，单条文档多包含工单编号、故障等级、处理节点、客户诉求字段，部分文档附带网络带宽、信号强度等数值类内容，格式多为结构化表格或半结构化文本。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时或近实时的更新节奏要求模型接入时适配动态数据加载，避免固定上下文窗口无法覆盖最新运维与工单数据。结构化的字段内容要求配置中启用工具调用相关参数，支持按字段提取与结构化输出。单条文档的数值类内容较多，需要调整上下文与token限制参数，避免超出模型处理上限。同时多源数据接入的需求，要求配置项支持自定义厂商接入路径，适配内部部署的通信类数据接口。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配基础电信运营多源、长文本的内部办公数据，避免截断关键运维日志与工单详情 |
| `maxTokens` | 4000 token | 平衡单轮回复长度与模型处理效率，适配结构化业务数据的输出需求 |
| `quoteMaxToken` | 2000 token | 精准提取工单、设备日志中的关键字段内容，避免冗余信息干扰模型思考 |
| `toolChoice` | auto | 支持自动触发结构化输出，适配工单分类、故障排查等需要字段提取的办公场景 |
| `temperature` | 0.3–0.5 | 降低随机输出概率，保证运维建议、工单处理流程的输出稳定性 |
| `AIPROXY_API_ENDPOINT` | `https://telecom-internal-api.vpc.local` | 适配基础电信运营内部数据的安全接入需求，避免外部接口泄露敏感业务信息 |

## 容易做错的三处
- 现象：渠道列表中原本配置的通信厂商接口消失，界面显示接口状态异常。原因：未配置适配内部数据的专属API端点，或接口权限未同步至FastGPT部署节点的通信白名单。
- 现象：知识库上传文档后，模型输出内容出现乱码。原因：使用了不支持中文结构化输出的思考模型，且未调整`temperature`参数至合理区间。
- 现象：新建知识库时无图片索引模型选项。原因：未在部署配置中启用视觉模型支持，或使用的FastGPT版本未集成该功能（需确认版本为FastGPT v4.17.0）。

## 怎么确认配好了
- 输入一条运维工单样本至模型，检查是否能正确提取故障等级、处理节点等核心字段。
- 访问接口状态面板，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置的接口可正常连通，无超时或4xx/5xx报错。
- 上传一张包含设备标识的办公图片文档，检查是否可正常生成对应的索引内容。
- 调整`temperature`参数至0.4，生成3轮测试回复，确认输出内容无明显随机偏差。
