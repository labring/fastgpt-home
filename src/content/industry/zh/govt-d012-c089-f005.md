# 工程机械的内部办公与员工服务：工具调用与插件

## 这个品类的数据长什么样
工程机械的内部办公与员工服务相关数据，主要来自设备运行数据采集终端、企业内部生产运维系统、员工考勤与工单平台。数据更新节奏从实时采集的设备运行参数，到每日同步的运维工单、月度汇总的员工服务记录不等。单条数据的结构包含设备唯一标识、运行时长、油耗值、故障代码、关联工单号、员工工号与服务类型，字段单位涵盖小时、升、条、次等，文档多以结构化JSON或CSV格式存储，便于批量读取与解析。

## 这些特征在「工具调用与插件」这一环带来什么约束
工程机械的多源异构数据特征，对工具调用与插件配置带来多重约束。实时采集的设备运行数据更新频率高，要求工具调用接口的响应时长需匹配采集间隔，避免返回数据滞后于业务场景。不同来源系统的字段命名存在差异，需要插件在调用前配置统一的字段映射规则，适配设备终端、运维系统的不同返回结构。设备编号、故障代码等唯一标识字段的强绑定要求，工具调用时需传递准确的关联参数，否则无法匹配对应运维或服务记录。员工服务与设备运维数据的关联逻辑，要求插件调用时需同时携带员工工号与设备标识，确保返回结果与具体业务场景匹配。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用模式 | 选择`functionCall`模式 | 适配工程机械数据的结构化调用需求，可明确指定调用目标插件与参数格式 |
| 插件触发条件 | 按员工发起的服务请求触发，延迟不超过10秒 | 匹配内部办公的实时响应要求，避免员工等待过久 |
| 字段映射规则 | 按设备编号→设备唯一标识、工单编号→关联工单号的规则映射 | 适配多系统的字段差异，确保数据关联准确 |
| 工具调用超时时间 | 30–60秒 | 覆盖设备数据拉取、运维工单查询的常规响应时长 |
| 关联参数校验 | 校验员工工号与设备编号同时存在 | 避免无效调用，确保服务结果与具体场景绑定 |
| 返回结果解析方式 | 按结构化字段提取故障处理建议、运维进度 | 适配工程机械数据的标准化解析需求 |

## 容易做错的三处
- 调用工具时返回401状态码，且Postman调用同一API密钥正常。原因是插件配置中未正确绑定FastGPT的系统密钥，或密钥权限未开放对应插件调用权限。
- 工具调用后返回的结果字段为空，无法匹配对应设备运维记录。原因是未配置字段映射规则，或传递的设备编号等关联参数格式错误。
- 触发插件后出现unAuthChat报错，且已填写API密钥。原因是插件的身份校验逻辑与FastGPT的调用格式不匹配，未正确携带预设的校验参数。

## 怎么确认配好了
- 发起模拟员工服务请求，核对工具调用的参数是否包含设备编号、员工工号等关联字段。
- 查看工具调用日志，确认返回结果的字段与预设的映射规则一致。
- 调用测试插件，验证响应时长符合预设的超时配置要求。
- 检查插件的权限配置，确认FastGPT的调用身份已通过校验。
