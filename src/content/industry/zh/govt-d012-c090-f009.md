# 成品油销售的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
成品油销售的业务数据主要来自加油站进销存系统、员工考勤管理平台、加油卡交易系统与站点巡检档案。数据更新节奏分两类：交易类数据按实时或每日批量同步，巡检、排班类数据按班次更新。单份业务文档结构固定，包含油品型号、交易量（单位：升）、交易单价（单位：元/升）、交易时间、站点编号、员工工号等字段，部分文档附带整改记录的关联ID与状态标签。

## 这些特征在「模型接入与配置」这一环带来什么约束
业务数据的多源同步与字段多样性，要求模型接入时需适配多格式数据的解析逻辑。固定枚举的油品型号字段，需在模型配置中预设枚举值约束，避免生成非标准结果。实时交易数据的高频调用场景，需调整模型请求的超时参数以适配低延迟要求。多文档关联的巡检整改场景，需配置工具调用的上下文关联规则，确保模型能准确匹配站点编号与整改记录。数据更新的实时性差异，要求配置中区分批量与实时数据的检索阈值，避免冗余检索占用资源。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多源业务文档的字段数量与内容长度，避免上下文截断导致信息丢失 |
| `maxTokens` | 2000–3000 token | 匹配成品油销售场景的单轮回复需求，涵盖订单解析、巡检整改建议等典型输出长度 |
| `quoteMaxToken` | 1500 字符 | 限制检索引用的文档内容长度，适配加油站交易、巡检等单份文档的平均字符量 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具处理关联数据，适配多文档关联的业务场景 |
| `temperature` | 0.3–0.5 | 降低生成随机性，确保油品型号、站点编号等枚举字段的输出准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署实际填写，如 `http://localhost:8000/v1` | 适配vllm推理服务的端口配置，与docker compose部署的端口映射规则一致 |

## 容易做错的三处
- 配置`AIPROXY_API_ENDPOINT`时填写错误的端口路径，出现`503 Service Unavailable`报错。原因是未匹配docker compose中vllm服务暴露的8000端口，或未添加正确的API路径前缀。
- 知识库检索响应超时，单轮检索耗时超出业务允许范围。原因是未根据成品油多源数据的字段数量调整`quoteMaxToken`参数，导致检索时加载过多冗余文档内容。
- 接入蒸馏版DeepSeek模型时无法正常调用，返回`invalid api format`报错。原因是未适配蒸馏模型的特殊请求格式，直接沿用通用大模型的接入配置，未调整请求体的参数结构。

## 怎么确认配好了
- 发起一次测试调用，输入包含油品型号与站点编号的业务问题，检查模型输出是否包含预设的枚举字段值。
- 查看检索日志，确认返回的引用文档数量与配置的`quoteMaxToken`限制匹配，无异常的内容截断。
- 验证工具调用功能，输入包含多文档关联的问题，检查模型是否能正确触发工具并返回关联结果。
- 检查API密钥配置项`AIPROXY_API_TOKEN`的有效性，确认调用时无认证失败的日志记录。
