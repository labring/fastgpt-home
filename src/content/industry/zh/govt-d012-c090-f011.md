# 成品油销售的内部办公与员工服务：表单与交互

## 这个品类的数据长什么样
数据主要来自加油站进销存管理系统、员工排班考勤系统、加油卡运营后台。更新节奏分三类：进销存数据实时同步，排班数据每日凌晨更新，月度核算数据每月生成。文档结构包含加油量（单位：升）、单站日销售额（单位：元）、员工当班时长（单位：小时）、油品库存余量（单位：立方米）、加油卡充值记录等字段，部分字段关联油站编号与员工工号作为唯一标识。

## 这些特征在「表单与交互」这一环带来什么约束
实时同步的进销存数据要求表单每次加载时拉取最新数据，避免使用缓存的历史快照，确保提交的业务数据准确。每日更新的排班数据要求员工选择组件的数据源每日刷新，确保可选排班人员为当日在岗员工。多油站的业务场景要求表单支持按油站编号过滤关联数据，避免跨站数据混淆。字段单位的差异要求表单内置单位转换与校验逻辑，统一展示与提交的计量标准。月度核算数据的批量提交需求要求表单支持多行数据批量导入与校验，适配月度汇总的业务流程。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `formInput` 数据刷新策略 | 实时拉取 | 适配进销存数据实时更新的业务特征，避免提交过时的库存或销售数据 |
| `userSelect` 数据源刷新频率 | 每日 0 点同步 | 匹配员工排班数据每日更新的节奏，确保可选人员为当日在岗员工 |
| 表单字段单位校验 | 强制匹配预设单位 | 规避计量单位混淆导致的业务错误，符合成品油销售的国家计量规范 |
| 批量导入支持 | 开启单行校验 | 适配月度核算的批量数据提交需求，提前拦截格式错误的导入内容 |
| 超时阈值 | 600 秒 | 覆盖多油站数据拉取的网络延迟，避免因数据量较大导致请求中断 |
| `userSelect` 过滤规则 | 按油站编号关联 | 区分不同油站的员工与数据，适配多站点的内部办公场景 |

## 容易做错的三处
- 表单提交后返回必填字段为空。原因是未正确关联`formInput`的数据源字段，未携带加油量、油站编号等业务必填参数，导致接口校验失败。
- 员工选择列表未更新当日排班人员。原因是未配置`userSelect`的数据源刷新规则，使用了缓存的历史员工数据，未匹配每日更新的排班节奏。
- 配置了大模型温度参数但未生效。原因是未通过AI对话组件的变量引用方式指定温度参数，或配置项未正确绑定到节点输入，导致参数未被正确加载。

## 怎么确认配好了
- 手动加载表单页面，确认关联的进销存库存、加油卡余额等数据与当前系统展示的实时数据一致。
- 切换油站编号筛选条件，检查`userSelect`组件仅展示对应油站的当班员工名单。
- 提交格式异常的测试数据，如非数值的加油量、超出合理范围的库存值，确认表单触发对应校验提示。
- 调整超时阈值配置，模拟多油站批量数据拉取，确认请求未因阈值过低被中断。
