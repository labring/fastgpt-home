# 房建工程总承包的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
房建工程总承包的内部办公数据主要来自项目管理系统的结构化台账、劳务管理平台的考勤记录、材料采购系统的入库单据，以及现场拍摄的施工影像、扫描的签证单与会议纪要。数据更新按项目执行节奏，日常考勤每日更新，进度报表每周更新，结算资料按月归档。文档包含结构化字段，如项目编号、劳务班组人数、材料型号与单价，单位涉及平方米、工日、元等，同时存在大量非结构化PDF、CAD图纸与扫描件，单份文档长度差异较大，部分签证单仅数行文字，部分施工方案可达数十页。

## 这些特征在「模型接入与配置」这一环带来什么约束
结构化台账的字段规范度高但覆盖维度多，需模型准确匹配项目编号、劳务班组人数等专属字段，避免数据混淆。非结构化文档长度差异显著，部分签证单仅数行，部分施工方案达数十页，需适配长短文本的上下文处理能力，避免长文档截断或短文档占用过多资源。现场施工影像与扫描件需视觉理解能力，需配置对应视觉相关参数。按项目节点更新的数据需保持调用时效性，需限制单次调用的上下文范围，避免加载过期历史数据。多数据源的格式差异需统一接入标准，需配置适配不同系统的接口参数，确保数据同步稳定。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 房建项目文档长度差异显著，需覆盖多份施工方案、考勤台账与结算资料的上下文，避免关键业务信息被截断 |
| `maxTokens` | 2000–3000 token | 内部办公场景以问答、文档总结为主，单次输出无需过长，避免浪费模型调用资源 |
| `quoteMaxToken` | 4000 token | 需保留足够的引用文档内容，确保签证单、进度报表等核心业务数据的引用完整性 |
| `vision` | 开启 | 需处理现场施工影像、扫描的图纸与签证单，支持视觉信息的提取与理解 |
| `temperature` | 0.3–0.5 | 内部办公需准确合规的信息输出，避免生成不符合项目规范的随意内容 |
| `AIPROXY_API_ENDPOINT` | 填写项目专属代理接口地址 | 隔离内部办公数据与公网调用链路，保障项目敏感数据的访问安全 |

## 容易做错的三处
- 现象：界面提示无可用模型渠道，日志显示403或502状态码。原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，或代理服务未完成重启，导致模型调用链路校验失败。
- 现象：部分PDF文件上传后显示内容为空，无法提取文本。原因：未开启`vision`参数，或上传的PDF为纯扫描图像格式，未触发视觉识别流程，导致无法解析图像中的文字内容。
- 现象：发送消息后未默认调用关联知识库，仅返回通用回答，未结合项目内部数据。原因：未配置`toolChoice`参数为自动调用知识库模式，或知识库关联配置未绑定至当前应用，导致模型未触发检索流程。

## 怎么确认配好了
- 发起一条针对项目劳务数据的查询，核对返回结果是否包含配置的关联知识库内容，确认模型调用链路正常。
- 上传一份扫描版施工签证单PDF，检查系统是否能正常解析图像中的文字，验证视觉识别功能生效。
- 查看系统运行日志，确认无整点时段的非预期模型调用记录，验证定时任务与预热配置已正确处理。
- 发起一条需要引用材料台账的查询，核对返回结果是否准确匹配项目专属字段，确认上下文配置符合要求。
