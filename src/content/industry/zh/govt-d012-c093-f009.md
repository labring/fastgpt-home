# 政企信息化服务的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来源于内部办公系统、通信运维工单、员工服务咨询记录、制度文档、会议纪要与业务培训材料。更新节奏以日常增量同步为主，支持按需触发全量更新。文档包含结构化与非结构化两类，结构化文档包含工单号、处理人、事件类型、处理时长等字段，单位涵盖条、小时、字符；非结构化文档多为长文本格式，无固定字段格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的多源混合数据结构，要求模型接入时需兼容结构化字段与长文本的嵌入适配。日常增量更新的资源特征，要求配置环节需支持快速重建索引的能力，避免全量重新导入耗时过长。不同类型文档的字段差异，要求需区分结构化与非结构化数据的处理逻辑，避免嵌入维度不匹配导致的问答偏差。同时，内部文档的合规性要求，需在配置中关联敏感内容校验的参数，确保接入模型的输出符合政企内部规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 内部办公与员工服务的文档多为长文本，需覆盖完整上下文关联以支撑准确问答 |
| `maxTokens` | `4000 token` | 员工服务类问答的单次回复长度需求明确，避免超出模型输出限制 |
| `quoteMaxToken` | `2000–3000 token` | 需保留足够的知识库引用文本，确保问答回复的依据充分 |
| `toolChoice` | `auto` | 内部办公场景需自动调用工具处理工单查询、进度跟踪等任务 |
| `temperature` | `0.3–0.5` | 员工服务需稳定准确的回复，避免过度发散影响内容合规性 |
| `AIPROXY_API_TOKEN` | `填写专属接口密钥` | 保障接口调用的安全性，符合政企数据安全管理规范 |

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 容易做错的三处
- 现象：更换embedding模型后，原有知识库的问答匹配度下降，或无法召回正确文档。原因：未执行索引重建操作，原有知识库索引基于旧的embedding模型生成，与新模型的向量表示逻辑不匹配。
- 现象：Docker部署的代理服务持续重启，容器日志显示接口连接失败或配置校验不通过。原因：未正确填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或部署环境的网络策略限制了容器对外通信。
- 现象：短时间内多次发起模型调用后返回限流报错，状态码显示429。原因：未匹配线上部署的qps阈值设置，未配置合理的请求间隔策略，导致超出接口调用上限。

## 怎么确认配好了
- 核对`maxContext`、`maxTokens`等参数的取值是否匹配当前内部文档的平均长度与问答回复需求。
- 导入单份结构化与非结构化混合的测试文档，发起对应场景的问答请求，确认回复引用的内容准确且格式合规。
- 查看系统运行日志，确认模型接口调用无异常报错，且代理配置的密钥与接口地址有效。
- 发起连续的测试请求，确认调用频率符合预设的管控要求，未触发限流机制。
