# 政企信息化服务的内部办公与员工服务：表单与交互

## 这些特征在「表单与交互」这一环带来什么约束
结构化字段占比高且格式固定，要求表单交互必须绑定预设字段，不能允许随意自定义输入项，避免无效数据进入系统。数据随业务节点实时更新，要求表单提交后需同步触发后端数据更新，不能存在明显延迟。非结构化附件存在大小限制，要求表单交互需添加上传校验规则，防止超限附件占用存储资源。员工工号等核心字段需符合政企内部编码规则，要求表单开启格式校验，拦截不符合规范的输入。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 绑定员工工号、申请类型等固定字段，开启格式校验 | 政企信息化服务的核心数据为结构化字段，需保证输入符合预设规则 |
| `userSelect` | 预设10-20个常用办公申请类型，禁用自定义输入 | 政企内部申请类型相对固定，减少无效输入与数据混乱 |
| 附件上传限制 | 单文件上限1000 MB，总上传上限5000 MB | 匹配政企内部办公附件的常规存储规范与使用场景 |
| 提交触发时机 | 表单填写完成且校验通过后，1000-1500毫秒内触发数据同步 | 平衡交互流畅度与数据同步的实时性 |
| 上下文缓存时长 | 600秒 | 适配政企内部办公会话的常规时长，保证交互连贯性 |

## 容易做错的三处
- 现象：文本内容提取模块中，向提示词代码块传入any参数后，完整响应显示代码块为undefined。原因：政企信息化服务的结构化数据字段未与代码块提取规则正确绑定，参数无法匹配预设字段。
- 现象：输入问题文字为“分享”，工具调用后自动变为“分交”。原因：表单交互未启用政企专属词库校验，同音字识别未做场景化修正。
- 现象：配置知识库选择后，调用时未加载对应知识库数据。原因：全局变量未正确关联到`formInput`配置项，变量赋值未同步到交互逻辑。

## 怎么确认配好了
- 填写表单的必填字段，触发格式校验，确认弹出的提示文案符合预设规则。
- 选择`userSelect`预设的申请类型，确认提交后的数据中对应字段与选择内容一致。
- 上传指定大小的附件，确认上传进度条正常完成且无大小超限提示。
- 触发表单提交，查看后端同步日志，确认数据字段与表单输入完全匹配。
