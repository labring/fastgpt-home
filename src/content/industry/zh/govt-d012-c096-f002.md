# 有色金属冶炼的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
有色金属冶炼的内部办公与员工服务数据主要来自生产实时日志、设备运维台账、工艺操作规程、员工岗位手册与质检报告单。生产日志与实时工况数据每小时更新，工艺规程与岗位手册按季度或重大工艺调整更新，质检报告单随每批次生产完成生成。文档包含长文本操作说明、结构化表格（含设备编号、批次号、能耗数值等字段，单位含千瓦时、吨、ppm）、短文本运维工单。

## 这些特征在「向量模型与索引」这一环带来什么约束
生产实时日志的高频更新要求索引支持增量刷新，避免全量重建带来的资源消耗。长文本工艺规程包含大量连续专业术语，分块时需避免截断专有工艺名称，需保留上下文关联。结构化质检台账与能耗表格包含带单位的数值字段，索引需支持多字段关联的向量提取，避免拆分后丢失数值与单位的绑定关系。短文本运维工单数量大且更新频繁，需优化索引的召回速度，同时保留工单的设备编号与故障类型关联信息。

## 配置怎么定
本指南基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配长文本工艺规程的专业术语连贯性，避免截断关键工艺步骤 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的工艺上下文，防止专业术语被分块割裂 |
| 相似度阈值 | 0.75–0.85 | 匹配工业场景下的专业术语语义相似度，过滤低关联的检索结果 |
| `defaultToken` | 4096 token | 适配多数工业文档的上下文长度需求，覆盖完整工艺说明的核心内容 |
| `maxToken` | 8192 token | 支持长文本质检报告与运维日志的完整向量提取 |
| 单次搜索上限 | 前 10 条 | 平衡检索召回的全面性与系统响应速度 |

## 容易做错的三处
- 现象：点击启用豆包Doubao-embedding-large索引模型，填写自定义请求地址和apikey后点击测试直接报错。原因：未确认自定义地址的端口与接口路径匹配模型调用规范，或apikey的权限未开放向量模型调用。
- 现象：检索结果中出现大量无关联的非目标文档片段，结果条数超出预设范围。原因：未正确设置相似度阈值，或分块长度过短导致语义碎片过多，产生无关匹配项。
- 现象：上传表格数据后，检索无法匹配表格内的数值或字段信息。原因：未开启知识库的多向量支持功能，或分块时未保留表格的结构化字段关联。

## 怎么确认配好了
- 进入知识库的向量模型配置页面，点击测试按钮，确认返回无报错的连接成功提示。
- 上传一份典型的工艺规程文档，检索文档内的专业术语，核对返回结果的分块长度与预设值一致。
- 上传一份结构化表格数据，检索表格内的特定字段值，确认结果包含对应表格的关联信息。
- 查看索引刷新日志，确认高频更新的生产日志按预设频率完成增量刷新。
