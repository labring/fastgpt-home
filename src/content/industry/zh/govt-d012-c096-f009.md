# 有色金属冶炼的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
有色金属冶炼的核心数据来自生产中控系统的实时采集台账、班组巡检日志、批次质检报告与能耗统计报表。数据更新节奏分三类：中控实时采集的设备参数每秒刷新，班组巡检日志每8小时更新一次，批次质检报告随每炉冶炼完成后生成。单份文档包含设备编号、检测时间、检测参数、异常标识、对应炉批号等字段，参数单位多为摄氏度、兆帕、安培、立方米每小时等工业标准单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
高频实时采集的工业参数数据会占用大量上下文token，要求模型接入时限制单轮对话的上下文总长度，避免超出模型支持上限。多字段、带单位的结构化数据需要模型准确识别参数与对应单位，不宜设置过高的随机性参数。批次化的质检报告与炉次绑定的数据，要求模型召回时精准匹配炉批号，需调整上下文召回的匹配精度。不同数据源的更新节奏差异，也要求在模型配置中匹配对应的数据同步周期，避免调用过时的冶炼生产数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配有色金属冶炼多字段结构化数据的上下文承载需求，避免截断关键炉批号与参数信息 |
| `maxTokens` | 2000–3000 token | 限制单轮回复的token消耗，适配内部办公场景的简短指令与数据查询需求 |
| `quoteMaxToken` | 1500–2000 字符 | 确保召回的冶炼台账、质检报告等文档内容完整，同时避免冗余信息干扰模型推理 |
| `temperature` | 0.2–0.4 | 降低回复的随机性，保障结构化参数、炉批号等关键信息的识别准确性 |
| `AIPROXY_API_ENDPOINT` | 对应部署的模型服务地址 | 适配本地部署或私有云的模型调用链路，符合国央企数据不出域的要求 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具处理结构化数据查询，适配内部办公的多类型请求场景 |

## 容易做错的三处
- 现象：调用模型时返回404状态码，无法正常加载嵌入模型或大语言模型。原因：未正确配置`AIPROXY_API_ENDPOINT`指向私有部署的模型服务地址，或`AIPROXY_API_TOKEN`未匹配模型部署的验证密钥。
- 现象：工作流中的分类结果波动幅度大，同一类冶炼异常的分类结果不一致。原因：设置的`temperature`值过高，导致模型推理时随机性过强，无法稳定识别结构化的异常参数特征。
- 现象：问题分类环节响应延迟明显，无法满足实时办公查询需求。原因：未限制`maxTokens`与`maxContext`的取值，导致模型每次调用需处理过量的上下文数据，延长推理耗时。

## 怎么确认配好了
- 发起一条包含冶炼炉批号与设备参数的查询，核对模型返回的内容是否准确匹配输入的字段与单位。
- 查看FastGPT v4.17.0的模型调用日志，确认返回的token消耗未超出预设的配置限制。
- 模拟多次重复查询同一类冶炼异常，核对分类结果的一致性是否符合预期。
- 测试调用不同数据源的冶炼数据，确认模型能正确召回对应炉次的质检报告与巡检日志。
