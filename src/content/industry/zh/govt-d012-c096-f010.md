# 有色金属冶炼的内部办公与员工服务：知识库检索与召回

## 这个品类的数据长什么样
有色金属冶炼的内部办公与员工服务数据主要来自四个渠道：生产现场的PLC采集日志、设备运维台账、安全操作规程与员工培训材料，以及内部办公群的历史问答记录。生产日志按班次生成，更新频率为每4小时一次；运维台账随设备检修实时更新；规程与培训材料每季度更新一次；历史问答记录按提问时间自动归档。数据结构包含结构化字段与非结构化文本两类，结构化字段包括熔炼温度（单位℃）、电流强度（单位A）、物料成分占比、设备编号；非结构化文本包括操作步骤、异常处理说明与口语化问答内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
生产日志的实时更新特性要求检索支持增量召回，避免重复处理全量历史数据，降低检索延迟。结构化与非结构化混合的数据格式，要求检索同时支持关键词匹配与语义匹配，避免仅通过关键词召回无关的文本内容。专业术语与固定单位的字段，要求检索系统能够准确识别单位语义，防止出现温度单位混淆、参数匹配偏差的问题。内部群的口语化问答记录，要求检索能够自动将员工的日常提问转换为专业术语，提升召回的精准度。较长的规程文档则要求合理设置分块规则，确保单块内容的语义完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | 匹配冶炼专业术语的语义相似度阈值，过滤低相关的召回结果，避免无关文档被返回 |
| `limit` | 前8条 | 限定单次检索返回的最大结果条数，适配员工单次查询的上下文承载量，避免结果过多干扰判断 |
| `searchMode` | 混合检索 | 同时匹配结构化字段与非结构化文本，适配冶炼数据的混合格式特征 |
| `usingReRank` | 开启 | 对召回结果按与员工提问的语义相关性重新排序，修正关键词匹配带来的相关性偏差 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展员工的口语化提问为专业术语，比如将“炉温不够”扩展为“熔炼炉温度低于设定阈值”，提升召回精准度 |
| `collectionIds` | 绑定冶炼生产库、运维文档库、内部问答库 | 限定检索的数据集范围，避免召回非冶炼类的行政办公文档 |

## 容易做错的三处
- 现象：内部群内重复出现相同的生产异常咨询提问，未得到复用解答。原因：未将内部历史问答记录纳入检索数据集，未开启`datasetSearchUsingExtensionQuery`复用已有解答。
- 现象：检索返回的结果中出现大量行政办公文档，无法定位到冶炼生产相关内容。原因：未通过`collectionIds`限定检索的数据集范围，将非冶炼类文档纳入召回池。
- 现象：检索返回的专业参数单位匹配错误，比如将“1200℃”召回为“1200K”。原因：未针对冶炼数据的专业字段配置语义匹配规则，导致单位语义混淆。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的控制台中，上传一份冶炼生产日志的测试文档，输入“熔炼炉温度异常”的提问，核对召回结果是否包含该文档的相关内容。
- 查看检索配置面板，确认`usingReRank`和`datasetSearchUsingExtensionQuery`均处于开启状态。
- 输入口语化提问“炉子烧不热”，核对召回结果是否自动扩展为专业术语并匹配到正确的运维文档。
- 检查`collectionIds`是否仅绑定了冶炼生产库、运维文档库和内部问答库，未包含非相关的行政数据集。
