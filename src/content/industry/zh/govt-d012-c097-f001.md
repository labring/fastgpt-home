# 核电运营的内部办公与员工服务：HTTP 接口与外部系统

## 这个品类的数据长什么样
核电运营的内部办公与员工服务数据主要来自企业OA系统、员工考勤终端、安全培训平台、设备运维台账库。数据更新节奏分三类：考勤打卡数据实时同步，运维台账每日凌晨批量更新，培训考核记录随单次培训完成后推送。单条数据文档结构包含员工工号、岗位编码、操作时间、关联设备编号、操作类型五个字段，其中员工工号为8位数字字符串，操作时间采用YYYY-MM-DD HH:MM:SS格式，关联设备编号为12位大写字母加数字组合。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
上述数据特征对HTTP接口环节带来多重约束。首先，员工工号、设备编号存在固定格式要求，接口需在请求校验阶段强制匹配对应正则表达式，避免无效数据流入。其次，实时类考勤数据与批量类运维数据的更新节奏差异，要求接口同时支持单条数据提交与批量数据导入两种请求模式。另外，核电运营数据涉及内部安全合规要求，接口的`Authorization`参数需采用Bearer令牌认证方式，且令牌有效期需匹配数据访问权限的轮换周期。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | Bearer {自定义令牌}，令牌有效期设为7200秒 | 匹配核电运营内部数据的安全合规要求，限制令牌使用周期，降低敏感数据泄露风险 |
| `variables` | 预设员工工号正则`^[0-9]{8}$`、设备编号正则`^[A-Z0-9]{12}$` | 强制校验请求数据的字段格式，过滤不符合核电运营数据规范的无效请求 |
| `responseData` | 仅返回状态码与错误信息字段，不返回原始请求数据 | 符合内部数据保密规范，避免接口响应中携带敏感员工与设备信息 |
| 单次请求最大数据量 | 500条/请求 | 平衡接口传输负载与批量运维数据的处理效率，防止单次请求数据量过大触发超时 |
| 请求超时时间 | 300秒 | 适配批量数据传输的耗时需求，避免因数据量较大导致的请求中断 |
| 请求重试次数 | 3次 | 应对网络波动导致的临时连接失败，提升接口调用的稳定性 |

## 容易做错的三处
- 现象：调用接口时返回400 Bad Request，请求体中包含不符合格式的员工工号或设备编号。原因：未配置`variables`对应的字段校验规则，导致无效格式的数据被提交。
- 现象：批量提交运维数据时返回504 Gateway Timeout。原因：请求超时时间设置过短，未适配批量数据的传输耗时。
- 现象：接口调用返回401 Unauthorized，无法正常获取或提交数据。原因：`Authorization`参数未使用Bearer令牌格式，或令牌已过期未及时更新。

## 怎么确认配好了
- 发送一条格式正确的测试数据，检查接口返回状态码为200 OK，确认`Authorization`校验与字段格式校验通过。
- 提交批量测试数据，检查接口响应时间符合预设的超时阈值要求，确认请求负载配置合理。
- 查看接口日志，确认仅返回状态码与错误信息，未携带原始请求的敏感数据，确认`responseData`配置生效。
- 模拟令牌过期场景，检查接口返回401 Unauthorized，确认授权校验规则正常生效。
