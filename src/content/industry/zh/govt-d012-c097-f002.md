# 核电运营的内部办公与员工服务：向量模型与索引

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
核电运营内部办公与员工服务的数据来源包括设备运维日志、操作规程手册、员工培训课件、设备台账、故障报修记录等。更新节奏差异明显：运维日志为实时更新，操作规程与设备台账每季度更新，员工手册每半年修订。文档结构混合结构化与非结构化内容，结构化字段包含设备编号、运行参数、巡检时间等，单位涉及MPa、小时、次等；非结构化内容多为长段落的操作指引与故障处理说明。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据更新节奏差异大，要求索引系统支持增量刷新与全量刷新结合的策略，避免频繁全量扫描带来的资源消耗。混合结构化与非结构化内容，需要向量模型同时支持结构化字段的语义编码与长文本的向量生成，确保专业术语与参数单位的关联性被保留。专业术语占比高，要求向量模型适配能源电力领域的专业语料，避免通用模型对术语的语义理解偏差。实时更新的运维日志数据量波动大，需要索引系统支持动态扩容以应对突发的数据增长。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 核电运营的规程文本多为长段落，该长度可保留完整操作步骤，避免语义断裂 |
| 重叠长度 | 100–150 字符 | 长文本分块后保留上下文关联，避免跨块的专业术语被拆分 |
| 相似度阈值 | 0.72–0.80 | 核电专业术语多，阈值过低会引入无关检索结果，过高会遗漏相关内容，按实测标定 |
| 单次搜索上限 | 前 10 条 | 内部办公的员工服务问题多聚焦具体操作或设备，少量结果即可覆盖需求 |
| `maxToken` | 4096 | 适配bce-embedding-v1的最大输入长度，满足长规程的向量生成需求 |
| `defaultToken` | 绑定专属调用密钥 | 避免跨场景的令牌权限冲突，符合核电数据的安全管理要求 |

## 容易做错的三处
- 现象：界面提示“无可用渠道”，原因：未在FastGPT的模型管理中正确配置bce-embedding的调用参数，或渠道的启用状态未开启。
- 现象：调用时报错“该令牌无权使用模型”，原因：使用的令牌未被授权访问目标embedding模型，或未跳过one API直接配置原生模型地址。
- 现象：检索结果无法匹配专业操作步骤，原因：分块重叠长度设置不足，导致专业术语被拆分后语义丢失。

## 怎么确认配好了
- 进入FastGPT的模型测试页面，输入核电专业问题，如“反应堆压力容器的巡检步骤”，查看返回的检索结果是否包含对应文档片段。
- 查看embedding模型的调用日志，确认每次调用的令牌和模型名称匹配，无权限报错信息。
- 手动修改分块长度参数，对比两次检索的结果条数差异，确认配置参数生效。
- 导入一份核电运维日志文档，生成向量后查看索引刷新状态，确认更新任务完成。
