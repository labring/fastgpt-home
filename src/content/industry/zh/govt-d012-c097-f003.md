# 核电运营的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
核电运营的内部办公数据主要来自运行日志、设备维修规程、人员资质台账、应急处置预案四类。运行日志按班组每日更新，设备规程与预案每季度复核更新，资质台账随人员变动实时调整。文档结构包含结构化台账字段（如设备编号、运行时长、维修次数）、长文本规程（单篇可达数万字符）、短条目应急指引。数据单位包含功率单位、时长单位、操作次数单位等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
运行日志的每日更新要求对话上下文能实时关联最新工况数据，避免调用过时的班组记录。长文本维修规程与预案的存在，要求多轮对话的上下文窗口需预留足够空间存储完整的历史交互与文档片段，防止关键操作步骤被截断。结构化设备台账的多字段属性，要求提示词需明确指定字段匹配规则，避免在多轮交互中混淆不同机组的参数信息。短条目应急指引的高频调用需求，要求对话流程需快速定位细分场景的指引内容，不占用过多上下文资源。语音交互日志的实时存储需求，要求对话上下文需同时关联文本转写内容与原始语音片段，需单独配置语音数据的存储与调用规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 适配长文本维修规程与多轮交互的历史记录存储，避免关键步骤被截断 |
| 上下文召回条数 | 前 6 条 | 平衡长文档片段与结构化设备台账的信息密度，减少冗余内容占用 |
| 对话上下文绑定 | 绑定`chatId`、`messages`、`variables` | 关联对话唯一标识与实时交互历史，确保不同机组、班组的对话上下文不混淆 |
| 数据源刷新间隔 | 按实测标定 | 适配运行日志、资质台账的更新节奏，确保调用数据的时效性 |
| 引用来源展示 | 默认开启 | 符合核电运营的合规性要求，需明确回答的文档来源与更新时间 |
| 开场白快捷按键 | 预设 3–5 个高频问题 | 覆盖日常巡检、设备报修、资质查询等高频办公场景 |

## 容易做错的三处
- 现象：对话回答末尾强制显示引用来源，无法手动关闭。原因：未调整引用来源展示的配置项，沿用了默认的合规配置。
- 现象：交互时提示“没有权限操作此对话记录”。原因：未绑定`chatId`对应的权限校验规则，导致跨会话的上下文访问被拦截。
- 现象：点击开场白快捷按键无响应。原因：未将按键绑定的问题与`messages`参数的初始对话内容关联，导致触发逻辑未生效。

## 怎么确认配好了
- 发起包含多轮设备参数查询的对话，核对上下文是否保留历史交互的设备编号信息。
- 查看回答内容末尾的引用来源，确认是否符合配置项的设置要求。
- 点击开场白预设的快捷按键，确认是否自动发送对应问题并触发回答流程。
- 测试跨会话的对话访问，确认无权限报错的情况。
