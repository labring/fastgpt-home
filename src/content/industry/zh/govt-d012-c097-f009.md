# 核电运营的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
核电运营的内部数据来源包括反应堆运行日志、设备台账档案、现场巡检记录、安全操作规范、员工培训考核档案。更新节奏依数据类型不同，运行日志按班次生成，设备台账随季度检修维护更新，安全规程按年度修订。文档多为结构化组合形式，设备台账包含设备编号、额定参数、维护周期等字段，巡检记录包含巡检点位、检测数值、异常标记，单位涉及MPa、℃、小时等工程专业单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
核电运营数据包含大量带工程单位的结构化字段与实时生成的时序日志，要求模型能准确识别单位并关联上下文信息。实时运行日志的高频更新要求配置需支持动态加载近期数据，避免上下文溢出。设备台账与安全规程的长文档结构，要求配置需适配长文本拆分与精准引用。多源异构数据的混合输入，要求配置需明确数据关联规则，避免字段混淆导致的回复偏差。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配核电场景多轮对话与近期班次运行日志的上下文保留需求，避免关键信息丢失 |
| `maxTokens` | 4000 token | 保障单轮回复可完整覆盖设备参数、操作步骤等工程内容，避免截断关键说明 |
| `quoteMaxToken` | 2000 token | 支持完整引用巡检记录、设备台账的结构化字段与检测数值，保留原始工程单位与标识 |
| `temperature` | 0.3–0.5 | 贴合核电场景严谨性要求，降低生成内容的随意性，避免不符合工程规范的结果 |
| `AIPROXY_API_ENDPOINT` | 企业内网部署的代理地址 | 保障核电敏感数据不流出内网，符合内部数据安全规范 |
| `AIPROXY_API_TOKEN` | 企业分配的专属访问密钥 | 限制非授权访问内部模型服务，提升接口访问安全性 |

## 容易做错的三处
- 发起测试请求时出现上下文截断报错，回复未包含前期提及的巡检子问题。原因是`maxContext`取值过小，未容纳多轮交互中的历史信息与关联数据。
- 接口调用返回认证失败状态码，无法正常调用模型服务。原因是未正确填写`AIPROXY_API_TOKEN`，或使用了无效的访问密钥。
- 生成的操作建议包含不符合工程规范的参数值。原因是`temperature`取值过高，导致模型生成内容缺乏严谨性。

## 怎么确认配好了
- 发起包含历史对话与设备参数的测试请求，检查回复是否关联前期提及的巡检点位与设备编号。
- 查看接口调用日志，确认请求通过配置的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`完成认证。
- 调整`temperature`参数后发起测试，检查回复的严谨性是否符合工程场景要求。
- 输入长文本格式的安全规程内容，检查`maxContext`与`maxTokens`是否正常容纳完整数据，无截断提示。
