# 核电运营的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
核电运营的内部办公与员工服务数据主要来自内部OA系统、班组运维台账、安全培训档案与员工考勤系统。数据更新节奏分为实时（考勤打卡、即时沟通）、每日（班组日报、运维记录）与月度（安全考核、培训总结）三类。单条数据文档包含员工编号、所属班组、岗位类型、操作时长、合规检查项编号与完成状态，其中时长单位为分钟，操作次数单位为次，未设置统一的聚合统计字段。

## 这些特征在「部署与升级」这一环带来什么约束
实时考勤与即时沟通数据的高并发特性，要求部署时配置足够的数据库连接池参数，避免并发请求导致连接耗尽。多批次的每日班组日报与月度考核数据，要求配置合理的存储分片与单文件大小配置，防止批量导入时存储溢出。结构化的员工与运维字段需要提前建立索引，升级过程中需保留原有数据的关联关系，避免合规检查记录与员工档案的关联断裂。同时核电运营数据的敏感性要求部署时开启内置的数据加密配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `200–300 个连接` | 匹配核电运营班组交接班、日常巡检的并发请求量，满足实时数据的并发连接需求 |
| `MONGODB_URI` | `包含认证参数的集群连接字符串` | 存储员工档案、运维台账等敏感数据，需开启访问认证与集群高可用 |
| `REDIS_URL` | `配置 600 秒缓存过期时间的内网连接地址` | 缓存实时考勤会话数据，减少数据库重复查询的频率 |
| `STORAGE_S3_ENDPOINT` | `符合核电数据合规要求的内网存储端点` | 存储运维日志与培训档案，确保数据存储符合行业合规标准 |
| `ROOT_KEY` | `按企业安全规范生成的 32 位以上强密钥` | 管理系统后台的最高权限管控，满足核电运营的权限审计要求 |
| `FE_DOMAIN` | `内部办公专用内网域名` | 限制系统仅面向内部员工访问，避免外部未授权访问 |

## 容易做错的三处
- 现象：Docker部署的FastGPT运行初期MongoDB连接正常，数小时后出现连接超时报错。原因：未配置`DB_MAX_LINK`的合理取值，并发请求耗尽数据库连接池后未自动释放，导致后续请求无法建立连接。
- 现象：升级到FastGPT v4.17.0后，前端页面显示的版本号仍为旧版本号。原因：升级时未清空前端静态资源缓存，旧版本的版本标识文件未被覆盖，导致前端加载旧缓存内容。
- 现象：FastGPT v4.9.10 fix2升级到FastGPT v4.17.0时出现`Error response from daemon: error from registr`报错。原因：升级过程中未停止原有容器的注册服务，端口冲突导致镜像拉取或容器启动失败。

## 怎么确认配好了
- 查看FastGPT容器启动日志，确认数据库连接日志无报错，连接池参数与配置的`DB_MAX_LINK`取值匹配。
- 上传一条测试运维日志数据，检查存储路径与配置的`STORAGE_S3_ENDPOINT`端点一致，确认数据写入成功。
- 访问`FE_DOMAIN`对应的内网地址，登录后查看系统设置页面的版本信息，确认与升级后的目标版本一致。
- 发起模拟并发请求，确认系统响应无超时，连接池未出现耗尽情况。
