# 民航机场的内部办公与员工服务：HTTP 接口与外部系统

## 这个品类的数据长什么样
民航机场内部办公与员工服务的数据源主要来自航班调度系统、员工考勤管理系统、后勤保障系统、航站楼设备监控系统四类。数据更新节奏分实时与周期性两类：航班动态、设备运行状态按秒级更新，员工考勤、排班信息按班次或每日更新，后勤耗材库存按周更新。数据文档为标准化JSON结构，核心字段包含唯一标识ID、业务类型、时间戳、关联编号，单位统一采用国际通用格式，时间字段使用YYYY-MM-DD HH:mm:ss格式，岗位字段为中文岗位名称，设备状态字段为0-3的数字枚举值。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
民航机场内部办公与员工服务的数据特征对HTTP接口与外部系统环节带来多重约束。实时更新的航班动态、设备状态数据要求接口响应延迟不超过3秒，否则无法支撑实时推送类业务场景；周期性更新的考勤、排班数据允许接口超时放宽至60秒，但需配置自动重试机制。标准化JSON结构要求接口请求与返回字段必须严格匹配预设枚举，避免字段缺失或数据类型不匹配导致解析失败。多数据源接入时需按业务类型划分独立接口路径，避免不同系统的数据混淆。机场内部系统多部署于私有网络，接口需支持私有域名访问与IP白名单校验，同时需兼容HTTPS协议与双向证书认证。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 认证配置 | `Bearer {机场内部接口密钥}` | 匹配`Authorization`参数的Bearer令牌格式，符合机场内部接口安全规范 |
| 请求变量配置 | `{"airportId": "SHA", "dataScope": "internal"}` | 对应`variables`参数，绑定机场专属标识与数据范围 |
| 数据提取配置 | `$.data.list` | 对应`responseData`参数，提取接口返回的核心业务数据数组 |
| 接口超时设置 | 30–60 秒 | 适配机场实时与周期性数据的不同响应要求 |
| 重试次数设置 | 2 次 | 避免单次网络波动导致接口调用失败 |
| 数据保留周期 | 7 天 | 过滤超过7天的冗余数据，减少无效存储 |

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 容易做错的三处
- 现象：接口返回符合标准结构的数据，但界面提示“Model response empty”。原因：未正确配置`responseData`参数，未提取接口返回的核心数据字段，导致系统未获取到有效业务内容。
- 现象：Docker部署后访问页面长时间转圈圈后失败。原因：未正确配置`Authorization`参数中的接口密钥，或私有网络下未开放对应端口的访问权限，导致接口调用超时。
- 现象：启动容器后提示INITIAL_ROOT密码错误。原因：docker-compose.yml中配置的INITIAL_ROOT参数与界面登录时输入的密码不匹配，或参数格式包含多余空格。

## 怎么确认配好了
- 调用配置好的HTTP接口，查看返回的原始数据结构，确认核心业务字段已被正确提取。
- 检查接口认证信息，确认`Authorization`参数的格式与密钥内容与机场内部接口要求一致。
- 模拟业务场景调用接口，验证返回数据的更新频率与机场内部系统的节奏匹配。
- 查看系统日志，确认无接口调用失败或数据解析异常的报错信息。
