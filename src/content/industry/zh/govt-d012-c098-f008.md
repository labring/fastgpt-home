# 民航机场的内部办公与员工服务：文档解析与分块

## 这个品类的数据长什么样
民航机场内部办公与员工服务的文档来源包括内部制度汇编、航班运行保障手册、月度运维日志、员工培训课件、航站楼安全规范等。更新节奏依类型而定，制度类按季度更新，运维日志按自然日归档，航季保障手册每半年更新。文档结构包含长文本流程说明、结构化表格（如排班表、设备参数表）、图文结合的应急处置指南，字段包含航班号、机位号、运维编号、安全等级等，单位涉及小时、人次、米、千克等。

## 这些特征在「文档解析与分块」这一环带来什么约束
民航内部文档的多类型结构对分块逻辑提出明确要求。长文本运行规程需避免拆分关键操作节点，否则会影响员工培训与执行准确性；嵌套表格多的文档，若拆分逻辑不当会破坏表格数据完整性，导致后续检索失效；按时间戳归档的运维日志，需保留相邻日志的上下文关联，便于回溯事件流程；单篇大型归档文档的体积差异较大，需适配不同文件大小的解析与分块流程，避免出现中断或不完整结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配民航文档中流程步骤、设备参数的逻辑单元长度，避免拆分关键信息 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配民航文档的章节层级与流程分段，防止拆分完整的操作说明 |
| `customPdfParse` | 启用 | 保留民航PDF文档中的嵌套表格、水印格式，避免表格内容被打散 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大型运维归档文档的解析耗时，防止任务中途超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容民航年度运维归档的单篇文档体积 |
| `chunkSettingMode` | 手动模式 | 支持针对制度、日志、课件等不同文档类型调整分块规则 |

## 容易做错的三处
- 现象：部分表格无法正确分块，解析后表格内容被拆分至多个独立块中。原因：未启用`customPdfParse`，默认解析引擎无法识别民航文档中的嵌套表格结构，导致表格被按文本拆分。
- 现象：解析PDF文档时报显存溢出或GPU识别失败。原因：部署的PDF解析插件与本地CUDA版本不匹配，或未开启GPU加速配置，导致资源占用超出阈值。
- 现象：Word文档转Markdown导入后图片链接丢失，对话中无法加载图片。原因：文档解析时未保留外链资源的完整域名，导致图片链接被截断。

## 怎么确认配好了
- 上传单篇包含嵌套表格的民航运维规程PDF，检查解析后的分块结果，确认表格完整保留在单个块内。
- 上传100 MB以上的年度运维归档文档，确认解析任务无超时报错，且分块结果覆盖全部文档内容。
- 查看FastGPT v4.17.0的部署日志，确认GPU型号与显存信息被正确识别，无显存溢出相关报错。
- 上传带内嵌图片的员工培训课件Word文档，检查分块后的Markdown内容，确认图片链接保留完整域名。
