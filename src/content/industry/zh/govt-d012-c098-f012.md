# 民航机场的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
民航机场内部办公与员工服务的数据主要来自航班调度系统、员工考勤管理系统、后勤运维工单系统、岗位培训文档库等。数据更新节奏覆盖实时、每日、每周：航班动态实时同步，考勤报表每日生成，运维巡检记录每周归档。文档分为结构化与非结构化两类，结构化字段包含航班号、员工工号、岗位类型、设备ID，单位对应航班号为字母加数字组合、考勤时长为小时；非结构化数据为工单文本、培训PDF等。

## 这些特征在「部署与升级」这一环带来什么约束
实时航班动态数据要求部署时的数据库连接池需支持高频读写，避免连接耗尽导致服务中断。多源异构数据（结构化考勤、非结构化工单）要求存储配置同时兼容关系型与非结构化存储，需提前规划`STORAGE_S3_ENDPOINT`等对象存储参数。不同更新节奏的数据需对应不同的索引策略，实时数据需配置高频索引更新，历史归档数据则可采用批量索引。机场内部办公数据涉及岗位权限分层，部署时需提前配置相关权限校验逻辑，避免跨岗位数据泄露。

## 配置怎么定
本页面适配 FastGPT v4.17.0 版本，以下配置项基于该版本编写：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–150 个 | 适配机场多系统高频读写的数据特征，避免连接池耗尽 |
| `MONGODB_URI` | 指向机场内部结构化数据集群的专属连接地址 | 隔离办公数据与其他业务数据，保障访问权限可控 |
| `STORAGE_S3_ENDPOINT` | 机场内部对象存储服务的接入地址 | 存储运维工单、培训文档等非结构化数据，适配多源数据存储需求 |
| `ROOT_KEY` | 按机场内部权限管理规则生成专属密钥 | 管控平台最高权限，避免越权访问敏感办公数据 |
| `REDIS_URL` | 配置为机场内部缓存集群地址，超时时间设为 300 秒 | 缓存高频访问的航班动态、员工岗位信息，降低数据库读写压力 |

## 容易做错的三处
- 现象：Docker 桌面客户端启动容器时持续显示加载转圈状态，无法完成部署初始化，容器日志提示数据库连接失败。原因：未正确配置`MONGODB_URI`指向可用的数据库集群，容器启动后无法建立数据库连接，导致启动流程阻塞。
- 现象：使用 docker-compose 部署后，无法在平台内添加结构化数据索引，配置界面无对应入口，点击索引管理无响应。原因：未在部署配置中开启多数据源索引适配逻辑，或未提前在`STORAGE_S3_ENDPOINT`关联的存储中完成数据目录映射，导致索引生成流程无法触发。
- 现象：进入 FastGPT 容器后执行 npm list 无法查询到 mongoose 版本，查看项目根目录的 package.json 可确认其存在。原因：容器内未全局安装 npm 依赖的全局查询工具，或未进入项目根目录执行依赖查询命令，导致无法遍历到内嵌的 mongoose 依赖。

## 怎么确认配好了
- 登录 FastGPT 管理后台，查看数据库连接状态面板，确认数据库连接正常。
- 上传一份机场运维工单示例文件，验证非结构化数据的存储与索引生成流程是否正常触发。
- 创建一个测试账号，验证权限校验逻辑是否符合机场内部岗位权限规则。
- 模拟实时航班数据的写入请求，确认数据库连接池未出现异常报错。
