# 油田工程服务的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
油田工程服务的数据主要来自现场施工日志、设备运行传感器、人员考勤台账、物资出入库记录。施工日志按作业班次更新，设备运行数据以分钟级频率上传，物资台账每日更新。单份文档包含作业区域编号、设备序列号、作业时长、参与人员名单、安全检查项等字段，单位涵盖立方米、小时、台、人次等，部分现场记录为非结构化手写或语音转写文本。

## 这些特征在「工作流编排」这一环带来什么约束
现场数据的实时性要求工作流节点需支持事件触发模式，适配设备传感器的实时上传信号。多源异构数据的混合存在，要求工作流需具备跨数据源的`variables`绑定能力，统一字段格式以避免流转错误。非结构化的现场记录需先经过文本提取节点处理，再进入后续流转环节，同时需限定文档处理的范围，避免无关内容干扰流程逻辑。本配置基于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 事件触发 | 适配现场设备传感器的实时上传信号，匹配作业流程的触发场景 |
| 变量绑定 | 通过`variables`关联作业单ID和`nodeId`对应的设备编号 | 实现多源数据（设备、人员、物资）的跨节点关联 |
| 节点超时时间 | 300-600秒 | 覆盖油田现场作业流程的平均执行时长 |
| 文档分块大小 | 800-1200字符 | 适配油田专业文档的篇幅，避免分块过碎或过长 |
| 知识库召回条数 | 前3-5条 | 油田专业文档篇幅较长，过多召回会增加上下文冗余 |
| 上下文长度 | 8000-12000 token | 匹配油田文档的整体篇幅，保证信息完整性 |

## 容易做错的三处
- 工作流调试面板中未显示代码运行节点，原因是未在工作流编辑页开启高级节点权限。
- 导入的外部工作流中间结果不符合预期，原因是`variables`绑定的字段与源工作流导出的字段不匹配。
- 工作流配置完成后无法在聊天中调用，原因是未将工作流绑定到对应聊天机器人的触发规则。

## 怎么确认配好了
- 查看工作流的`variables`配置，确认所有绑定的油田作业单字段均存在且格式正确。
- 触发测试事件，查看工作流运行日志，确认每个节点的输出结果符合预期。
- 检查聊天机器人的触发规则，确认已关联当前配置的工作流。
- 模拟现场作业场景，提交测试数据，验证工作流的完整执行链路。
