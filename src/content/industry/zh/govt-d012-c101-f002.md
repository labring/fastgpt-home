# 港口航运的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
港口航运内部办公与员工服务的数据来源包括船舶调度日志、船员排班表、港口作业单据、设备运维记录、内部OA通知与安全报告。其中作业单据随船舶靠离泊实时更新，船员排班表每日更新，设备运维记录随故障触发生成，OA文档按需提交。数据包含结构化字段与非结构化文本：结构化字段含泊位号（单位：米）、船舶吨位（单位：吨）、作业时长（单位：小时）；非结构化文本包括长文档如月度安全报告、短文本如即时作业通知。

## 这些特征在「向量模型与索引」这一环带来什么约束
混合的结构化与非结构化数据，要求索引支持多字段映射与权重配置，避免泊位号、船舶吨位等结构化字段的语义偏差。实时产生的作业单据与运维记录，要求索引支持增量更新机制，降低全量重建的资源消耗与时间成本。长文本如月度安全报告的篇幅较长，需要适配的分块规则避免语义断裂，影响向量检索的准确性。不同业务场景的数据差异，要求向量模型与索引配置可针对不同文档类型灵活调整，适配船员服务、设备运维等不同查询需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配港口作业单据、安全报告等长文本的语义完整性，避免单块内容断裂 |
| 重叠长度 | 100–200 字符 | 覆盖跨分块的船舶调度、作业流程等上下文，确保语义连贯 |
| `maxToken` | 8192 token | 适配智谱Embedding-3的输入上限，匹配港口长文档分块后的实际长度 |
| 相似度阈值 | 0.72–0.78 | 区分港口设备运维日志的相似故障描述，避免误匹配无关文档 |
| 单次搜索上限 | 前10条 | 覆盖船员服务中常见的多场景需求，如排班查询、设备问题参考，避免返回过多冗余内容 |
| `defaultToken` | 1000 秒 | 适配本地部署时的向量模型请求超时，避免因港口数据量大导致的请求中断 |

## 容易做错的三处
-  界面中无法选择智谱Embedding-3作为向量模型，原因是未在本地部署配置文件中添加该模型的API地址白名单，或配置的`defaultToken`未匹配模型要求的请求头参数。
-  本地部署后提示向量模型请求失败，原因是wsl环境下的端口映射未正确绑定，或`maxToken`设置超出了模型的实际输入上限。
-  导入港口作业单据时生成的索引块内容混乱，原因是未区分结构化字段与非结构化文本的分块规则，直接对所有内容进行无差别分块。

## 怎么确认配好了
-  上传单份港口作业单据，检查生成的向量分块是否覆盖完整的作业流程描述，无语义断裂。
-  发起船员排班查询请求，核对返回的搜索结果条数与单次搜索上限的设置值一致。
-  查看FastGPT v4.17.0的向量模型请求日志，确认`maxToken`的取值未触发模型的输入长度报错。
-  测试导入多份实时更新的设备运维记录，确认索引增量更新功能正常触发，无全量重建提示。
