# 港口航运的内部办公与员工服务：表单与交互

## 这个品类的数据长什么样
港口航运内部办公与员工服务的数据来源包括码头作业系统、船员排班平台、船舶调度系统、物资管理台账。数据更新节奏分为实时（靠泊、装卸进度）、每日（排班、库存异动）、月度（成本核算）三类。文档结构包含结构化作业单（含船名、泊位编号、装卸货种、吨数）、排班表（工班、岗位、出勤人数）、物资台账（物资编码、库存数量、领用时间），部分文档包含长文本作业日志，字段带有专属单位，如吨、小时、泊位号。

## 这些特征在「表单与交互」这一环带来什么约束
实时更新的数据要求表单支持快速同步数据源，避免使用缓存过久的静态数据。多系统来源的字段需要表单做格式校验与映射，确保泊位编号、装卸吨数等字段符合港口业务规范。长文本作业日志作为输入时，表单需适配常规单段文本长度，避免超出处理上限。不同岗位的操作人员需对应不同的表单可见字段，实现权限隔离的交互设计。

## 配置怎么定
本配置项说明基于 FastGPT v4.17.0 版本

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 表单输入组件 | `formInput` 类型 | 适配港口作业单的结构化字段录入，减少手动输入误差 |
| 选项选择组件 | `userSelect` 类型 | 用于预设船舶、泊位等固定选项，匹配港口业务的标准化数据 |
| 上下文窗口 | 800–1200 字符 | 适配港口作业日志的常规单段文本长度 |
| 结果展示条数 | 前5条 | 匹配单批次港口作业的关联数据规模 |
| 交互超时时间 | 60 秒 | 适配港口现场操作人员的日常操作响应节奏 |
| 变量触发时机 | 表单提交后 | 匹配港口作业流程的节点触发逻辑 |

## 容易做错的三处
- 现象：表单提交后知识库关联字段为空。原因：未使用`userSelect`组件预设港口业务相关的知识库选项，导致用户无法精准选择对应知识库。
- 现象：全局变量未完成赋值。原因：未将`formInput`组件的输出作为变量赋值的数据源，未绑定表单提交与变量触发的逻辑。
- 现象：stream模式交互返回结果不完整。原因：未设置合理的交互超时时间，导致实时流接收过程中触发超时中断。

## 怎么确认配好了
- 打开表单编辑器，检查`formInput`和`userSelect`组件是否覆盖了港口作业的核心字段。
- 提交测试表单，验证所选知识库是否能加载对应船舶或泊位的关联数据。
- 触发stream模式的交互，检查是否能完整接收所有返回的结果片段。
- 提交表单后查看全局变量面板，确认变量已按配置完成赋值。
