# 炼化生产的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
炼化生产的核心数据来自分布式控制系统（DCS）、设备台账管理系统、运维工单平台。数据更新节奏分为实时秒级的运行参数，以及按生产班次更新的设备点检、工单记录。单条数据为结构化格式，包含设备唯一标识、运行温度（单位℃）、系统压力（单位MPa）、物料流量（单位m³/h）、工单编号、处理状态、时间戳字段，无嵌套复杂层级。

## 这些特征在「工作流编排」这一环带来什么约束
实时运行数据的秒级更新要求工作流触发节点需匹配数据采集间隔，不宜设置过短的轮询周期。结构化固定字段的特征要求工作流的变量提取需精准绑定设备ID、压力值等指定字段，不可依赖模糊匹配。按班次更新的运维数据则要求工作流的定时触发节点需适配生产班次周期，确保数据同步完整。同时，固定的物理量单位要求工作流内置参数校验规则，避免单位不匹配导致的流程中断。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按数据更新事件触发 | 匹配炼化生产数据的实时/按班次更新节奏 |
| `variables` | 绑定设备ID、运行压力字段 | 对应结构化数据的固定字段结构 |
| 循环体执行间隔 | 600 秒 | 适配分布式控制系统的数据采集周期 |
| 超时阈值 | 1200 秒 | 覆盖常规运维工单的处理周期 |
| 节点重试次数 | 3 次 | 应对临时的系统网络波动 |
| `nodeId` | 指定工单流转节点的唯一标识 | 确保工作流精准跳转至对应环节 |
| 单次查询上限 | 前5条 | 适配炼化数据库的单次返回量限制 |

## 容易做错的三处
- 工作流中调用环境变量时返回空值。界面显示变量值为空，日志提示未找到指定环境变量。未在Docker部署配置中正确声明对应环境变量，或工作流内未正确绑定`variables`参数。
- 循环体中执行下标加1后结果为null。循环节点输出的下标字段为空，流程中断。未在循环初始化时正确配置起始下标，或未将下标变量绑定至`variables`参数。
- 数据库链接工作流无法查询到炼化生产数据。节点返回空结果，报错提示未匹配到数据。未将工作流`variables`绑定至数据库查询的条件字段，或查询条件的单位与生产数据不匹配。

## 怎么确认配好了
- 手动触发一次工作流，查看输出日志中`variables`参数是否包含设备ID、运行压力等预期字段。
- 模拟一次数据更新事件，确认工作流是否按预设间隔自动触发。
- 检查数据库查询节点的条件参数，确认与生产数据的字段、单位完全匹配。
- 查看循环体节点的下标输出，确认每次循环后下标值按预期递增。
