# 炼化生产的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
炼化生产的数据来源涵盖分布式控制系统（DCS）实时运行参数、设备台账、巡检记录、安全操作规程、内部办公通知等。更新节奏分为实时、定期与按需三类：实时运行参数每数秒更新一次，设备台账与安全规程按季度或修订节点更新，办公通知按需发布。文档结构包含结构化的参数表（含温度、压力、运行时长等字段，单位为℃、MPa、小时）、半结构化的巡检日志，以及非结构化的文本文档。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据的多源混合与结构差异要求模型接入时需适配不同类型的内容解析规则。实时运行参数的高频更新要求上下文窗口需容纳足够的最新数据，避免模型调用时缺失关键场景信息。结构化字段的特殊单位与固定格式，要求配置时需明确字段映射逻辑，确保模型能正确识别生产相关参数。长文档与短文本的混合场景，要求调整模型的token限制参数，兼顾内容完整性与调用效率。同时，内部办公与员工服务的场景要求模型需同时关联生产数据与行政流程，因此配置时需兼顾两类数据的召回权重，避免出现偏向某一类的偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 炼化生产场景包含实时运行参数、巡检记录、安全规程等多类内容，需容纳足够上下文以关联生产场景与办公需求 |
| `maxTokens` | 2000–3000 token | 兼顾生产问题响应的完整性与流畅性，避免单次输出过长导致超时 |
| `quoteMaxToken` | 1500 token | 用于召回的生产文档、办公文件需限制单段长度，确保召回内容不占用过多上下文空间 |
| `temperature` | 0.3–0.5 | 生产场景需稳定准确的响应，不宜过高以减少无关内容生成 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接入地址 | 适配炼化企业内部网络隔离的部署需求，确保数据传输安全 |
| `AIPROXY_API_TOKEN` | 按企业权限体系生成专属令牌 | 严格管控模型接入权限，避免未授权访问内部生产与办公数据 |

## 容易做错的三处
- 调用模型后返回空内容，排查发现未将炼化生产专属文档索引与重排模型绑定。原因是配置时未指定召回范围为内部生产与办公数据集，导致模型无法获取有效参考数据。
- 本地部署语言模型后无法通过内网IP访问，排查发现`AIPROXY_API_ENDPOINT`配置未匹配服务器实际监听的内网地址与端口。原因是配置时误使用公网地址或未填写正确端口，导致请求无法到达部署节点。
- 升级FastGPT至v4.17.0后，对话输出末尾出现规则追溯符号。原因是系统提示词的规则展示开关未关闭，默认配置下会将内置规则追加至输出内容末尾。

## 怎么确认配好了
- 向模型发起包含具体生产参数查询的测试请求，检查返回内容是否关联了内部文档的字段与数值。
- 查看模型调用日志，确认`AIPROXY_API_TOKEN`的校验状态为通过，无权限相关报错。
- 调整`temperature`参数至区间边界，验证输出内容的稳定性是否符合生产场景需求。
- 测试长文本输入场景，确认`maxTokens`配置未触发内容截断，输出完整度符合预期。
