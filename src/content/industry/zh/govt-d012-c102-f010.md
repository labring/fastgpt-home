# 炼化生产的内部办公与员工服务：知识库检索与召回

## 这个品类的数据长什么样
数据主要来自炼化生产的内部工艺规程、设备台账、巡检记录、安全操作规范及班组培训资料。数据来源覆盖生产一线的实时运维记录与管理文档，巡检记录每日更新，正式工艺规程修订后同步更新。文档多为结构化长文本，包含设备编号、操作压力、温度阈值、巡检周期等字段，单位多采用国际标准与行业通用的兆帕、摄氏度、小时等，包含大量炼化专属专业术语。

## 这些特征在「知识库检索与召回」这一环带来什么约束
炼化生产的长文本结构化文档与高频更新的一线数据，对检索召回环节带来多重约束。长文本占比高，单块分块过长会导致嵌入向量丢失局部细节，过短则破坏专业术语的语义完整性。专属专业术语密集，通用检索模型难以精准匹配行业语义，需适配专业词表优化召回逻辑。每日更新的巡检记录与实时运维数据，需支持增量同步机制避免数据滞后，同时需支持按设备编号、操作参数等字段定向召回，匹配一线员工的精准查询需求。

| `limit` | 前8–12条 | 覆盖一线员工常见的单轮查询需求，避免过多结果增加筛选成本 |
| `searchMode` | 专业语义匹配 | 针对炼化专属术语优化召回逻辑，适配长文本与结构化数据的检索场景 |
| `usingReRank` | 开启 | 对初始召回结果按语义相关性二次排序，修正通用模型的语义偏差，提升专业内容的匹配精度 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 避免扩展查询引入非专业语义，保留原始查询的精准性，适配炼化场景的专业术语需求 |
| `collectionIds` | 按业务域分组配置 | 仅召回对应生产班组、设备类型的知识库文档，缩小检索范围，提升召回精准度 |

## 容易做错的三处
- 现象：添加知识库文档时返回“Request failed with status code 400”。原因：未正确配置文档来源的API权限范围，或文档链接格式不符合FastGPT的导入校验规则。
- 现象：调用API知识库时自动携带Bearer请求头，无法自定义请求头配置。原因：未在FastGPT的API知识库设置中关闭自动Bearer补充功能，导致请求头格式冲突。
- 现象：检索结果未匹配专业术语，召回大量无关的通用文档。原因：未启用`usingReRank`或设置的`similarity`阈值不符合炼化场景需求，导致语义匹配精度不足。

## 怎么确认配好了
- 发起针对炼化专属术语的查询，核对召回结果是否包含对应领域的文档。
- 查看知识库同步日志，确认每日更新的巡检记录是否按增量同步机制执行。
- 检查API知识库的请求头配置，确认自动Bearer补充功能是否按需开启或关闭。
- 查看检索结果的排序逻辑，确认二次重排后的结果符合语义相关性要求。
