# 炼化生产的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
炼化生产的数据来源覆盖设备运行日志、巡检记录、设备台账、安全操作规程、员工排班与培训文档等。数据更新节奏差异明显，设备运行日志为实时更新，巡检记录按班次提交，台账与规程文档按季度或重大变更更新。文档结构包含结构化字段（如设备ID、运行压力、温度值，单位为MPa、℃）与非结构化文本（如巡检报告、培训课件），单文档长度从数十字符的告警信息到数千字符的完整操作规程不等。

## 这些特征在「部署与升级」这一环带来什么约束
炼化生产多源异构的数据特征，要求部署阶段需适配结构化与非混合数据的存储与检索配置。实时设备数据的高频更新，需要调整向量索引的刷新频率，避免索引滞后。文档长度差异大的特点，要求分块配置需兼顾短告警与长规程的适配，避免分块过碎或过长影响检索效果。国企合规要求下，数据需本地存储，部署时需配置符合安全规范的存储端点，升级阶段需保障历史索引不丢失，避免影响员工日常办公与生产巡检的查询需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30 并发连接` | 适配炼化生产多源数据并发访问需求，避免连接池耗尽 |
| `MONGODB_URI` | `带读写分离的集群连接地址` | 支撑炼化生产海量结构化与非结构化数据的高可用存储 |
| `REDIS_URL` | `主从复制集群地址，内存配置≥1000 MB` | 缓存向量检索结果与员工会话数据，保障高并发响应 |
| `STORAGE_S3_ENDPOINT` | `符合国企安全合规的本地存储端点` | 满足炼化生产数据本地存储的安全合规要求 |
| 分块长度 | `800–1200 字符` | 适配炼化生产巡检记录、操作规程等长短不一的混合文档 |
| 单次搜索上限 | `前10条` | 平衡炼化生产知识库检索的召回范围与响应速度 |

## 容易做错的三处
- 现象：重排模型部署后可通过连通性测试，但每次检索返回结果的重排标记字段始终为false。原因：未在知识库配置中开启重排开关，或未将重排模型绑定至对应数据集。
- 现象：导入csv格式的炼化生产台账文件后出现中文乱码，已确认字符编码设置正确。原因：csv文件采用了GBK编码但导入时未指定对应编码格式，或文件中包含不可见的控制字符。
- 现象：升级FastGPT版本至4.9到4.10后，原索引的知识库无法触发向量检索，搜索无结果。原因：旧版本向量索引格式与新版本不兼容，未执行索引重建或迁移操作。

## 怎么确认配好了
- 登录FastGPT管理后台的数据库监控面板，查看`MONGODB_URI`与`REDIS_URL`的连接状态，确认无异常报错。
- 上传一份炼化生产巡检记录的测试文件，执行向量检索并触发重排操作，确认返回结果的重排字段为true。
- 升级FastGPT v4.17.0版本后，选择一个历史知识库执行手动重建索引，完成后验证检索功能恢复正常。
- 发起10个并发的员工查询请求，确认系统响应无超时，连接数未超过`DB_MAX_LINK`的配置值。
