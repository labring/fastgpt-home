# 煤化工的内部办公与员工服务：多轮对话与提示词
本页面的配置说明基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
煤化工内部办公与员工服务的数据源主要包括设备运维日志、生产运行报表、安全操作规程、员工考勤排班、薪资核算文档等。设备运维日志以单台设备为单位，包含设备编号、故障类型、处理时间、更换备件编号等字段，单位为MPa、℃、小时；生产运行报表按班次生成，包含时间戳、岗位编号、关键运行参数等内容。安全操作规程按岗位分类更新，每季度修订一次；考勤与薪资文档按月度更新，包含员工工号、岗位、出勤天数等字段。文档单条记录长度多在800–1200字符区间，部分长文档需拆分处理。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
煤化工数据的专业术语多、字段关联紧密，多轮对话需精准绑定设备与会话上下文，避免不同设备的运维记录混淆。实时生产数据与定期更新的规程文档需区分调用优先级，提示词需引导优先使用最新的安全与运维数据。单条文档长度较长，多轮对话的上下文窗口需限制规模，避免因加载过长数据导致响应延迟。设备编号、时间戳等字段的关联逻辑需在提示词中明确，确保对话过程中能精准召回对应设备的历史记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配煤化工生产报表与运维日志的单条记录长度，避免截断关键参数 |
| 重叠长度 | 150–200 字符 | 覆盖跨块的设备编号、时间戳等关联字段，保证上下文召回的完整性 |
| 最大上下文 | 10–15 轮对话 | 适配煤化工故障排查的常规多轮流程，避免上下文过载导致响应变慢 |
| `chatId` | 绑定设备编号与对话会话 | 确保同设备的多轮对话上下文精准关联，避免混淆不同设备的运维记录 |
| `variables` | 绑定岗位与设备类型 | 过滤非目标岗位的文档内容，提升煤化工员工服务场景的回答精度 |
| 提示词模板 | 加入「优先使用最新的安全规程与设备运维日志」 | 适配煤化工文档分批次更新的特征，引导调用最新可用知识库内容 |

## 容易做错的三处
- 现象：API调用对话应用时返回结果与平台测试不一致。原因：未在调用时绑定煤化工专属知识库，默认调用通用知识库内容，导致回答偏离业务场景。
- 现象：多轮对话中出现不同设备的运维记录混淆。原因：未通过`chatId`绑定设备编号与会话，导致上下文跨设备关联，召回错误的历史记录。
- 现象：上传的煤化工运维日志文件解析失败。原因：未开启工业日志格式解析配置，默认仅支持通用文档格式，无法识别设备编号、压力参数等煤化工专属字段。

## 怎么确认配好了
- 发起单轮对话测试，输入指定设备的运维问题，核对返回结果中是否包含该设备的专属参数，验证上下文绑定生效。
- 调用API时携带`messages`参数传入多轮历史对话，核对返回结果是否关联历史上下文，验证多轮对话逻辑正常。
- 上传煤化工专属文档至知识库，发起对话询问文档内的专业条款，核对返回内容是否匹配最新更新的文档版本。
- 检查配置项中的分块长度与重叠长度，确认取值区间符合煤化工文档的单条记录长度要求，验证文档拆分逻辑正确。
