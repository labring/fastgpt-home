# 煤化工的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
煤化工内部办公与员工服务的数据主要来自企业内部生产管理系统、人力资源系统、档案库及设备运维平台。生产类数据如设备运行时长、检修记录按作业完成即时归档，人事类文档如岗位手册、考勤规则每季度更新，内部通知按需发布。数据包含结构化字段与非结构化文本，结构化字段包括设备编号、运行参数、煤质检测数值等，单位涵盖小时、吨、摄氏度等；非结构化文本多为培训纪要、作业指导书等。

## 这些特征在「模型接入与配置」这一环带来什么约束
煤化工生产数据实时性强、字段格式固定，且包含设备运行参数、煤质检测数值等专业术语，模型接入需适配高频调用需求，限制单次请求的token消耗以避免超时。非结构化的培训纪要、内部通知篇幅较长，需调整上下文窗口参数以完整加载内容。专属行业术语需在模型配置中适配，避免生成错误解释。人事类数据涉及员工隐私，需配置权限校验参数，确保数据调用合规。本地部署模型时，需适配煤化工专属字段的提取规则，避免结构化数据识别偏差。

## 配置怎么定
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配煤化工长文档如设备运维手册、培训纪要的完整加载需求 |
| `maxTokens` | 4000 token | 限制单次生成的输出长度，避免超出模型原生支持的上限 |
| `quoteMaxToken` | 2000 token | 限定召回的知识库文本总长度，避免上下文过载 |
| `temperature` | 0.3–0.5 | 降低生成随机性，适配专业术语与结构化数据提取的准确性要求 |
| `AIPROXY_API_ENDPOINT` | 按部署模型的实际接口填写 | 适配本地或第三方模型的接入路径，确保请求正确路由 |
| `AIPROXY_API_TOKEN` | 按平台生成的密钥填写 | 完成模型接入的身份校验，保障调用权限合规 |

## 容易做错的三处
- 文本提取身份证信息返回空。原因是未配置结构化数据提取的专属规则，模型无法识别煤化工场景下夹杂生产术语的身份证字段格式。
- 本地部署向量模型后持续显示索引中。原因是未调整`maxContext`参数适配本地模型的加载阈值，或向量数据库连接配置未匹配煤化工数据的字段长度。
- 拦截大模型回答后替换自定义标签仍报错。原因是未在模型配置中开启自定义输出格式适配，或替换的标签未与FastGPT的解析规则完全匹配。

## 怎么确认配好了
- 发起一次包含煤化工生产术语的测试请求，核对模型返回的术语解释是否符合行业规范。
- 导入单篇长文档如设备运维手册，检查模型加载的上下文长度是否符合预期。
- 调用本地部署的向量模型，查看知识库召回的条目数量是否与配置的召回规则匹配。
- 提交包含隐私信息的测试数据，确认权限校验参数已生效，无越权调用提示。
