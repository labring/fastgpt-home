# 煤炭运销的内部办公与员工服务：工具调用与插件
本页适用FastGPT v4.17.0版本。

## 这个品类的数据长什么样
煤炭运销的数据主要来自运销调度系统、过磅磅单系统、煤质检测实验室系统、合同管理平台与运力调度系统。更新节奏分为实时（过磅时生成磅单数据）、每日（更新煤场库存与当日发运计划）、月度（生成结算对账报表）。单条数据的文档结构包含合同编号、发运日期、煤种、收到基低位发热量、实际发运重量、承运方主体、到站站点、结算单价等字段，单位涉及吨、千卡/千克、元/吨等。

## 这些特征在「工具调用与插件」这一环带来什么约束
多数据源且更新节奏差异大，要求工具调用需适配不同的接口超时阈值，实时数据接口需设置较短超时，批量报表接口可放宽时长。核心字段存在特定单位与关联规则，要求插件需内置字段校验与映射逻辑，避免单位不匹配或数据关联错误。单条数据字段量适中但跨数据源关联紧密，要求工具调用支持参数传递与跨插件联动，否则会出现数据割裂。不同场景的数据更新频率不同，要求插件可按需触发调用，适配实时查询与批量统计的不同需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto`，仅指定单一工具时改为`none` | 适配煤炭运销多工具联动的日常办公场景，自动匹配对应业务插件 |
| `functionCall` | 开启并绑定不超过3个运销专用插件 | 避免过多插件导致上下文溢出，符合单条运销数据的字段量范围 |
| 接口超时时间 | 60-120秒 | 适配磅单查询、煤质检测数据拉取等实时接口的响应时长 |
| 参数映射规则 | 按合同编号关联磅单、煤质与结算数据 | 匹配煤炭运销数据的核心关联字段，保障参数传递正确性 |
| 日志记录开关 | 开启全链路工作流日志 | 便于排查跨插件调用的日志丢失问题 |
| 批量调用上限 | 前20条待处理运单 | 避免单次调用数据量过大导致接口超时 |

## 容易做错的三处
- 调用跨应用插件后对话日志字段为空：未开启工作流的全链路日志记录配置，仅启用了单插件的本地日志。
- 工具调用时参数传递失败：未按煤炭运销的核心关联字段配置参数映射规则，导致源插件输出的字段无法被目标插件识别。
- 代码运行插件执行报错：未在插件环境中安装煤炭运销场景依赖的数据分析库，或版本与现有数据格式不兼容。

## 怎么确认配好了
- 触发一次单条运单查询的工具调用，查看插件返回的字段是否包含合同编号、收到基低位发热量、实际发运重量等煤炭运销核心字段。
- 提交参数传递测试请求，确认目标插件能正确接收并使用源插件输出的运单关联数据。
- 查看工作流日志面板，确认跨插件调用的每一步都有完整的对话记录与返回结果。
- 运行代码运行插件测试，确认能正常加载并使用指定的数据分析库处理运销相关数据。
