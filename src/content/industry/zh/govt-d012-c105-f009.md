# 煤炭运销的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
煤炭运销的内部办公数据主要来自内部运销管理系统、地磅称重系统、铁路公路发运台账与结算系统。数据分为结构化字段与非结构化附件两类，结构化字段包含煤种名称、发运吨数、承运车辆ID、发运到达时间、结算单价等，单位多为吨、元/吨。实时同步当日地磅称重数据，每日更新当日发运汇总台账，每月更新全周期结算数据，非结构化附件多为磅单扫描件、发运调度单PDF与结算凭证扫描件。

## 这些特征在「模型接入与配置」这一环带来什么约束
煤炭运销的多来源、分时段更新的数据特征，对模型接入配置带来多重约束。结构化字段多且单位统一但字段数量较多，需限制上下文承载的字段总量避免超出模型token上限。实时同步的地磅数据需保证模型调用可快速获取最新字段，需合理配置接口调用参数适配实时数据拉取。非结构化的磅单扫描件需开启视觉识别能力，适配附件解析需求。月度结算台账的长文本内容，需合理配置上下文截断规则避免内容丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配煤炭运销多字段的结构化数据与月度结算长文本，避免内容截断 |
| `maxTokens` | 2000–3000 token | 匹配内部办公场景的回复长度需求，兼顾员工查询的效率 |
| `quoteMaxToken` | 1500 token | 限制引用的运销台账内容长度，避免占用过多上下文空间 |
| `vision` | 开启 | 支持解析磅单扫描件、调度单PDF等非结构化附件，适配FastGPT v4.17.0版本的视觉识别能力 |
| `temperature` | 0.3–0.5 | 保证运销数据回复的准确性，降低随机输出偏差 |
| `AIPROXY_API_ENDPOINT` | 按企业内部部署的代理地址填写 | 适配企业内部网络环境，规避公网访问限制 |
| `AIPROXY_API_TOKEN` | 按分配的企业专属令牌填写 | 保证接口调用的身份合法性 |

## 容易做错的三处
- 配置`vision`后仍无法解析磅单图片，现象为返回报错提示无法识别附件或返回空结果，原因是未正确开启`vision`配置项，或未将磅单扫描件作为知识库附件绑定至对应数据源。
- 模型仅输出思考过程未返回最终结果，现象为回复仅包含思考步骤无业务结论，原因是`temperature`设置过高，或未配置模型的输出格式约束，部分模型默认优先输出思考过程内容。
- iframe嵌入的对话框显示英文界面，现象为控件文字、提示文案均为英文，原因是未在接入配置中指定中文语言参数，或未同步企业内部的语言适配规则。

## 怎么确认配好了
- 上传一份磅单扫描件至绑定的知识库，发起包含“识别该磅单内容”的查询，检查是否能提取煤种、吨数等结构化字段。
- 发起包含月度结算台账关键词的查询，检查回复是否包含完整的业务内容且未出现内容截断。
- 调用配置后的接口，检查返回结果是否符合设定的`temperature`区间，无过度随机的输出内容。
- 查看接口调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置已生效，无身份验证相关报错。
