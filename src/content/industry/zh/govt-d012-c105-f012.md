# 煤炭运销的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
煤炭运销的核心数据来源于内部运销管理系统、汽车/火车磅单、调度排班日志、购销合同台账。其中运单数据为实时生成，每完成一次发运即更新；合同台账与调度日志按每日班次更新。单份运单文档包含煤种、车皮/车牌号、发运地、到达地、毛重/净重（单位：吨）、发运时间戳等字段；合同文档包含合同编号、履约总量、结算单价（单位：元/吨）、甲乙双方主体信息等字段。部分数据附带扫描件类附件，单份附件大小可达数十MB。

## 这些特征在「部署与升级」这一环带来什么约束
实时运单的高并发写入需求，要求数据库连接池配置需适配峰值流量；多字段结构化数据与附件混合存储的场景，要求对象存储与数据库的配置需分离且兼容大文件存储。不同数据的更新节奏差异，要求增量同步任务需按数据类型配置不同的触发周期。内部办公场景下的部署需适配内网环境，禁止公网暴露核心数据接口。升级过程中需保留原有合同、工单等业务数据的映射关系，避免数据结构变更导致的业务中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `200–300 个连接` | 适配实时运单的并发写入与查询峰值，避免数据库连接耗尽 |
| `STORAGE_S3_ENDPOINT` | 内部对象存储的内网访问端点 | 用于存储磅单扫描件、合同附件等大文件，保障数据在内网流转 |
| `REDIS_URL` | `redis://内网Redis地址:6379/1` | 缓存高频查询的运单状态、员工服务工单数据，降低数据库负载 |
| `PG_URL` | 内网PostgreSQL数据库的内网连接串 | 存储员工服务工单、合同台账等结构化业务数据 |
| `FE_DOMAIN` | `https://内部办公系统域名` | 配置前端访问地址，适配内网办公场景的域名规则 |
| `FILE_TOKEN_KEY` | `32位随机生成的字符串` | 生成文件访问令牌，限制内部文档仅可通过授权链路访问 |

## 容易做错的三处
- 升级后前端页面显示的FastGPT版本与实际部署版本不一致。现象为访问`FE_DOMAIN`后，页面底部的版本标识仍为旧版本号，如部署FastGPT v4.17.0后仍显示v4.13.1。原因是前端静态资源未重新构建，浏览器缓存了旧版本的版本文件。
- 实时运单数据同步出现大量超时报错。现象为数据库日志返回连接超时错误，运单数据无法及时写入系统。原因是`DB_MAX_LINK`配置值过低，无法支撑并发的运单写入请求。
- 员工服务工单的附件无法正常上传。现象为上传磅单扫描件时弹出上传失败提示，后台日志返回存储端点错误。原因是`STORAGE_S3_ENDPOINT`配置错误，未指向内部对象存储的正确地址。

## 怎么确认配好了
- 访问配置的`FE_DOMAIN`地址，查看页面底部的版本标识，确认与部署的FastGPT版本一致。
- 提交一条模拟运单数据，登录对应数据库实例，查看是否成功写入对应数据表，验证`PG_URL`与`DB_MAX_LINK`的配置生效。
- 上传一份测试用的磅单扫描件，确认可以正常存储并通过授权链接访问，验证`STORAGE_S3_ENDPOINT`的配置正确。
- 查看Redis监控面板，确认连接数处于合理范围，验证`REDIS_URL`的配置生效。
