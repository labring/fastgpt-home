# 煤电一体化的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
煤电一体化内部办公与员工服务的数据来源包括班组交接班记录、设备运维手册、安全规程、会议纪要、员工考勤规范、年度安全报告等。数据更新节奏分为日常高频更新、定期更新与修订式更新。文档结构涵盖长文本报告、短条目规范、结构化表单等类型，字段包含文档所属部门、关联设备编号、更新时间、文件格式等，部分字段带有专属单位，如设备编号的六位编码、班组编号的三位标识。

## 这些特征在「向量模型与索引」这一环带来什么约束
煤电一体化内部办公数据包含大量长文本报告与专业术语，单块文本的token占用易超出基础嵌入模型的处理上限，要求切片配置适配长文本的合理长度，匹配`maxToken`的设置上限。高频更新的交接班记录等数据，要求索引支持增量更新以避免全量重建的资源消耗。多维度专属字段要求索引支持元数据过滤，缩小检索范围提升精度。多样的文档格式要求解析后的文本结构适配向量嵌入的标准化处理流程，避免语义丢失。

## 配置怎么定
本文适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配煤电一体化内部文档的信息密度，平衡单块token占用与语义完整性 |
| 重叠长度 | 100–150 字符 | 保留跨块上下文，匹配交接班记录、运维流程这类连贯业务内容的语义关联 |
| maxToken | 8192 token | 适配主流开源嵌入模型的token上限，符合切片后单块文本的处理要求 |
| 单次搜索上限 | 前8条 | 平衡检索召回率与响应速度，适配内部办公场景的多来源文档检索需求 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配度结果，适配安全规程、运维手册这类专业文本的检索精度 |
| 增量索引更新 | 按实测标定 | 适配交接班记录这类高频更新的业务数据，避免全量重建索引的资源消耗 |

## 容易做错的三处
- 现象：本地部署的FastGPT知识库磁盘占用持续超出预估范围。原因：未关闭原文件的持久化存储，导致同时保留原始上传文件、分割后的文本块与嵌入向量三份数据。
- 现象：检索返回结果条数与配置的单次搜索上限不一致。原因：未针对煤电一体化文档的设备编号、班组编号等专属字段配置元数据索引，导致检索范围受限。
- 现象：嵌入任务触发后出现超时报错。原因：未设置匹配文档长度的`maxToken`参数，单块文本超出嵌入模型的处理上限，引发任务中断。

## 怎么确认配好了
- 进入知识库管理页面的磁盘统计模块，查看存储类型分布，确认是否符合预设的留存策略。
- 发起一条针对设备运维手册的检索请求，核对返回结果条数是否与配置的单次搜索上限一致。
- 上传一段长度超过1000字符的班组交接班记录，查看嵌入任务是否正常完成，无超时报错。
- 查看嵌入模型的调用日志，确认`maxToken`参数匹配当前切片后的单块文本长度。
