# 煤电一体化的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
煤电一体化的内部办公与员工服务数据，来源包含生产调度系统、设备运维日志、办公OA系统、员工考勤记录与安全巡检档案。数据更新节奏存在差异，生产类数据为实时或准实时更新，办公类文档为每日批量更新。文档包含结构化的设备参数、能耗报表、考勤台账，以及非结构化的巡检报告、会议纪要、培训资料，字段包含设备编号、机组负荷、煤耗量、班次信息等，对应单位包括千瓦时、吨、人次等。

## 这些特征在「模型接入与配置」这一环带来什么约束
煤电一体化的数据特征对模型接入与配置带来多重约束。混合结构化的设备参数、能耗报表与非结构化的巡检报告、会议纪要并存，要求配置需兼容多类型输入的处理逻辑。实时生产数据的低延迟需求，需要调整模型调用的上下文长度与响应超时设置。大量行业专属术语的存在，需要优化模型的生成精度参数。不同数据源的更新频率差异，要求配置中区分不同数据的同步与调用规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配煤电行业长文档的运维报告、调度记录等内容 |
| `temperature` | `0.2–0.4` | 减少专业术语的生成偏差，保障办公与运维内容的准确性 |
| `vision` | 开启 | 支持处理设备巡检的图片数据，适配内部员工服务的可视化需求 |
| `quoteMaxToken` | `2000–3000 token` | 保留足够的历史办公数据与运维日志上下文 |
| `AIPROXY_API_ENDPOINT` | 填写企业内部模型代理地址 | 适配内网部署的煤电行业专属模型，保障数据安全 |
| `AIPROXY_API_TOKEN` | 填写企业分配的专属密钥 | 保障内网模型调用的权限校验与安全 |

## 容易做错的三处
- 现象：配置`AIPROXY_API_TOKEN`后界面提示无可用渠道，原因：未将当前使用的分组权限与目标模型渠道完成绑定。
- 现象：界面右上角未显示创建模型的入口标识，原因：未配置对应账号的模型管理权限，或未使用FastGPT v4.17.0及以上版本。
- 现象：无法查询本地部署模型的每秒token处理能力，原因：未在模型接入配置中关联本地模型的性能监控接口。

## 怎么确认配好了
- 调用测试接口输入煤电行业专业文档，检查模型返回内容是否包含准确的行业术语与合规的数据逻辑。
- 上传设备巡检图片，验证模型是否能正常识别并返回对应分析结果。
- 查看模型调用日志，确认`maxContext`与`temperature`的实际使用值符合预设配置。
- 测试不同分组下的模型调用权限，确认配置的`AIPROXY_API_TOKEN`能正常通过渠道校验。
