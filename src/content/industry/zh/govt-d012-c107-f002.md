# 煤矿生产的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
煤矿生产内部办公与员工服务的数据来源包括班前会纪要、设备巡检日志、班组交班记录、安全规程文档、员工考勤台账等。更新节奏依文档类型差异明显，班前会纪要、巡检日志按班组班次更新，考勤台账每日更新，安全规程按年度修订更新。文档结构包含班组编号、设备编码、巡检时间、问题描述、处理结果等字段，部分为结构化表格形式，部分为纯文本段落，字段单位包含六位数字编码、标准时间格式、字符型描述文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引支持结构化与非结构化文本的混合嵌入，避免因数据格式差异导致向量表达偏差。更新频率的差异要求配置增量索引逻辑，避免全量重建索引带来的资源消耗。文档长度跨度大的特点要求分块策略具备灵活性，适配从数十字符的考勤条目到数千字符的班前会纪要的不同文本长度。字段包含大量设备编码、安全术语等专业词汇，要求向量模型适配工业领域的专业语义，确保检索的精准性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配煤矿内部办公文档的平均文本长度，匹配主流向量模型的输入token限制 |
| 重叠长度 | 100–200 字符 | 避免分块截断关键关联信息，如设备编号与对应巡检问题的绑定 |
| `maxToken` | `16384` | 适配主流API向量模型的最大输入上限，覆盖长文档分块后的嵌入需求 |
| `defaultToken` | `0` | 避免默认占位符干扰专业字段的向量语义表达 |
| 相似度阈值 | 0.72–0.85 | 匹配煤矿安全相关检索的精准匹配需求，过滤低相关性的巡检记录 |
| 单次搜索上限 | 前 10 条 | 聚焦班组级别的核心检索需求，避免冗余结果干扰员工判断 |

## 容易做错的三处
- 现象为创建集合显示创建成功，但页面索引状态一直无法变为就绪，原因是未配置增量同步的触发条件，全量索引任务因历史数据量较大超时未完成。
- 现象为本地运行向量索引时结果正常，使用Docker打包镜像部署后，相同文本的向量得分完全一致，原因是未固定向量模型API的调用密钥，导致每次请求分配至不同的模型实例，嵌入结果出现偏差。
- 现象为索引构建过程停留在最后一组数据的处理环节，原因是索引分片数设置过大，且未配置分片重试机制，导致最后一批数据提交失败后无法自动恢复。

## 怎么确认配好了
- 上传一段典型的设备巡检日志，检查分块后的文本是否被正确截断，且重叠部分包含关键关联信息。
- 发起一次包含“设备故障”关键词的检索，核对返回结果的相似度得分是否落在预设阈值区间内。
- 触发一次增量索引任务，查看索引更新日志，确认仅当日新增的文档被纳入索引，未触发全量重建。
- 查看FastGPT v4.17.0的向量检索耗时面板，确认单次检索耗时符合业务预期。
