# 煤矿生产的内部办公与员工服务：工具调用与插件

## 这个品类的数据长什么样
煤矿生产场景的核心数据来源包括井下分布式传感器、地面调度系统、员工考勤终端、设备运维台账。传感器数据实时更新，调度日志按每班生成，设备台账与员工考勤数据每日同步。数据文档结构包含固定字段：传感器数据含时间戳、监测参数与单位；设备台账含设备编号、型号、维护周期与部署位置；考勤数据含员工工号、班次、出勤时长。字段单位统一遵循煤炭行业通用规范，如瓦斯浓度用ppm、温度用℃、出勤时长用小时。

## 这些特征在「工具调用与插件」这一环带来什么约束
煤矿生产的数据特征对工具调用与插件环节带来多项约束。实时监测数据要求工具调用支持低延迟请求，适配井下应急响应的时间要求。多源数据分散在传感器、考勤、调度系统中，插件需按数据类型路由调用对应第三方API，避免参数混淆。每班生成的调度日志批量处理时，需限制单次调用的请求总量，防止第三方接口过载。设备台账与考勤数据的固定字段结构，要求插件请求参数严格匹配行业规范字段名，否则无法正确解析返回内容。实时数据的高更新频率，需要设置合理的超时阈值，避免请求堆积影响业务流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用超时时间 | 30–60 秒 | 适配井下传感器实时数据的请求延迟要求，避免请求堆积 |
| 单次请求最大数据量 | 500 条 | 匹配每班调度日志的批量处理规模，防止第三方接口过载 |
| `functionCall` 触发模式 | 按业务流程节点触发 | 适配煤矿内部办公的固定操作流程，确保工具调用时机准确 |
| 响应报文解析规则 | 按行业规范字段匹配 | 遵循煤炭行业数据字段命名规则，避免解析返回内容出错 |
| 插件调用重试次数 | 2–3 次 | 应对井下网络波动导致的请求失败，保障数据获取稳定性 |

## 容易做错的三处
- 现象：HTTP请求模块返回结果中未包含Set-Cookie字段，无法获取会话凭证。原因：未启用响应头解析配置，或未配置对Set-Cookie字段的提取规则。
- 现象：API调用返回的知识库本地图片链接无法在第三方系统正常展示，返回404错误。原因：未将本地相对路径替换为完整API访问地址，导致路径解析错误。
- 现象：API方式调用对话无流式输出，仅返回完整结果。原因：未开启`toolChoice`对应的流式返回配置，未按接口要求传递流式参数。

## 怎么确认配好了
在FastGPT v4.17.0版本中，可通过以下动作核对配置是否生效：
- 发起模拟调用请求，检查工具返回的响应报文是否包含预期的字段与数据格式，核对是否与煤炭行业规范一致。
- 模拟批量数据请求，观察第三方接口的调用频率与返回状态码，确认未出现过载报错。
- 触发预设的业务流程节点，检查`functionCall`与`toolChoice`是否按预期触发工具调用，无延迟或误触发情况。
- 模拟网络波动场景，检查插件是否按配置的重试次数自动重试请求，最终成功获取数据。
