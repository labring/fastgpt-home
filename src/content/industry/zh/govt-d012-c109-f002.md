# 电网企业的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
电网企业内部办公与员工服务的数据主要来源于内部OA系统公文、运维工单系统、员工培训课件、班组运行日志等。数据更新节奏存在差异：运维工单随现场作业实时生成更新，公文按审批流程随时发布，培训课件每季度定期更新。文档结构包含标题、正文、发布部门、发布时间、所属班组、设备编号等字段，部分专业文档附带电压等级、线路名称等电力专属单位与术语字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据的多来源与差异化更新节奏，要求向量模型与索引适配不同的更新频率，高频实时工单需支持增量索引以避免全量索引阻塞。长文本运维日志与公文存在大量专业术语，切分向量块时需保留术语上下文，防止语义断裂。多字段元数据的存在，需要开启元数据过滤能力，支持按班组、设备编号等维度召回相关内容。部分文档的电力专属单位与术语，要求嵌入模型适配能源电力领域的语义特征，避免专业内容的语义丢失。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配电网公文、运维工单的文本长度，避免切分破坏专业术语完整性 |
| 重叠长度 | 100–150 字符 | 保留相邻块的专业术语上下文，防止跨块语义断裂 |
| 相似度阈值 | 0.75–0.85 | 匹配电网内部文档的语义相似度区间，过滤低相关的非业务内容 |
| defaultToken | 按实测标定 | 适配企业内部的令牌权限规则，避免无权调用模型报错 |
| maxToken | 8192 token | 适配bce-embedding-v1的最大输入长度，符合电网长文档的嵌入需求 |
| 单次搜索上限 | 前10条 | 平衡召回效率与内容覆盖，匹配内部办公的信息检索场景 |

## 容易做错的三处
- 现象：调用pushdata API上传chunk模式数据后，界面持续显示索引中状态。原因：未配置增量索引触发规则，全量索引处理大量实时运维工单数据时出现阻塞。
- 现象：控制台返回`该令牌无权使用模型：text-embedding-3-large`报错。原因：未正确配置`defaultToken`参数，使用了无对应模型权限的访问令牌。
- 现象：检索结果中混入大量老旧的非当前业务相关文档。原因：未设置相似度阈值或阈值设置不合理，未过滤低语义匹配的内容。

## 怎么确认配好了
- 上传单篇1000字符左右的运维工单文档，检查嵌入任务的完成时长，确认索引速度符合业务预期。
- 检索包含“10kV线路”的关键词，核对返回结果的元数据是否包含对应班组、设备编号字段，确认元数据过滤配置生效。
- 查看模型调用日志，确认`defaultToken`对应的令牌权限覆盖当前使用的嵌入模型，无权限报错。
- 调整相似度阈值后，检索相同关键词，观察返回结果的相关性变化，确认阈值配置符合业务需求。
