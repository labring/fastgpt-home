# 电网企业的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
电网企业内部办公与员工服务的数据主要来源于内部OA系统、生产调度平台、员工考勤系统、报修工单库与设备运维档案。数据更新节奏覆盖实时（如报修工单）、每日（如考勤统计）、分钟级（如设备运行参数）三类。单份文档多包含工单编号、所属运维班组、关联设备ID、处理时限、关联图纸文件等字段，字段单位多为数字编号、小时、GB等标准化格式，部分运维档案会附带结构化的设备参数表。

## 这些特征在「工作流编排」这一环带来什么约束
电网企业的多来源、多更新节奏的数据特征，对工作流编排带来多重约束。实时报修工单要求工作流支持毫秒级节点触发，避免工单流转延迟。多格式字段（如数字型设备ID、字符串型班组名称）要求工作流的`variables`配置需兼容跨系统字段映射，统一数据格式适配后续检索与流转。分钟级生产参数的数据量较大，工作流节点需预设单批次处理上限，避免超时。关联的运维图纸多为CAD、PDF格式，工作流需预设对应格式的解析规则，确保文件可被正常索引与调用。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体配置项与建议如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量映射规则 | 按内部系统字段对应关系绑定`variables` | 兼容多来源数据的格式差异，统一流转数据标准 |
| 节点超时设置 | 300–600 秒 | 适配电网企业工单流转的常规处理周期，避免超时中断 |
| 文件解析格式配置 | 预设CAD、PDF、TXT三类 | 匹配运维档案与办公文档的常见文件类型 |
| 触发节点配置 | 按工单状态变更触发 | 贴合电网企业工单的标准化流转逻辑 |
| 分支节点标识 | 按业务类型分配唯一`nodeId` | 区分不同班组、工单类型的工作流分支 |
| 知识库关联配置 | 绑定对应运维知识库ID | 精准匹配设备运维场景的检索需求 |

## 容易做错的三处
- 现象：工作流中配置的表单输入字段在对话交互中未显示，或字段值为空。原因：未在`variables`配置中绑定表单字段与工作流变量的映射关系，导致变量未被正确传递到对话节点。
- 现象：AI对话模块配置的文件链接无法正常调取关联文档。原因：未在文件解析配置中添加对应文件格式的解析规则，导致文档无法被正常索引。
- 现象：工作流触发后无响应或弹出超时报错。原因：节点超时设置取值小于工单实际处理所需时长，或`nodeId`配置重复导致分支流转冲突。

## 怎么确认配好了
- 进入工作流预览界面，手动触发测试工单，检查表单输入字段是否在对话界面正常显示。
- 上传对应格式的运维文档，验证文件解析模块是否可正常读取文档内容。
- 配置唯一`nodeId`分支，触发对应业务类型的工单，检查工作流是否按预设分支流转。
- 调整节点超时设置，模拟长耗时任务，验证工作流是否在预设时长内完成流转。
