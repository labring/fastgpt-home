# 电网企业的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
电网企业内部办公与员工服务的数据主要来自内部OA系统、运维工单平台、员工培训文档、电网调度日志与设备台账。数据更新节奏差异明显：运维日志与实时工单为分钟级更新，员工手册与制度文档为季度级更新。文档包含结构化字段（如工单号、杆塔编号、电压等级）与非结构化内容，单位多包含kV、停电时长、班组编号等电力专属标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据结构要求模型接入时需适配结构化字段抽取与非长文本解析的双重需求。实时运维数据的分钟级更新节奏，要求模型调用的响应延迟需匹配业务处理窗口。电力专属的电压等级、杆塔编号等字段，需在模型配置中加入专属提示，避免识别偏差。长文本的电网调度日志，会对上下文窗口参数提出更高要求，防止内容截断影响分析准确性。

本页面所有配置说明均适配FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配电网调度日志、运维报告等长文本内部文档，避免上下文截断 |
| `maxTokens` | 2000–3000 token | 匹配员工服务类对话的回复长度需求，避免单次输出过长影响交互 |
| `quoteMaxToken` | 1500 token | 限制引用的内部文档片段长度，避免引入冗余内容干扰模型输出 |
| `temperature` | 0.3–0.5 | 降低随机度，确保电力专属字段与工单流程的回复准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署的私有模型地址填写 | 适配国央企内部数据安全要求，避免外部接口泄露敏感业务数据 |
| `AIPROXY_API_TOKEN` | 按企业权限管控的密钥填写 | 遵循内部数据安全规范，限制未授权的模型调用 |

## 容易做错的三处
- 现象为工作流仅调用单个模型，无法实现分步处理后仅输出最终结果。原因是未正确配置工作流的节点输出规则，仅开启了最终对话节点的结果展示。
- 现象为模型运行时上下文超出部署设置的10k限制，出现截断或报错。原因是混淆了部署侧与FastGPT配置侧的参数优先级，未按FastGPT配置的参数执行。
- 现象为对话无流式输出，仅返回完整结果。原因是未确认FastGPT的模型调用配置是否开启流式传输，或模型本身未支持流式响应。

## 怎么确认配好了
- 提交包含电力专属字段（如10kV线路故障）的测试文本，检查模型输出是否正确识别字段并生成符合流程的回复。
- 查看工作流运行日志，确认多节点模型调用均被触发，且最终节点结果正常展示。
- 测试长文本输入（如1000字的运维报告），检查上下文未被截断，回复符合预期。
- 发起实时对话，验证输出形式是否符合配置要求，或完整返回结果。
