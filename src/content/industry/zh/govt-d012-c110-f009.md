# 矿山采选的内部办公与员工服务：模型接入与配置

本文基于FastGPT v4.17.0版本的配置逻辑编写。

## 这个品类的数据长什么样
矿山采选相关数据来源于内部生产管理系统、设备物联网平台、地测档案库与办公系统。数据更新节奏分为实时（设备运行参数）、每日（生产日报）、每周（巡检归档）与项目周期（勘探文档）三类。文档结构包含结构化的设备参数表、半结构化的运维日志与排班表，以及非结构化的技术规范与培训材料。字段涵盖设备编号、运行时长、处理量、巡检编号、员工工号、岗位名称等，单位包含小时、吨、条、字符。

## 这些特征在「模型接入与配置」这一环带来什么约束
结构化的设备与员工数据需明确字段映射规则，避免模型混淆不同业务类型的数据。实时设备运行数据要求模型接入接口的延迟控制在合理范围，需适配短超时配置。长篇幅的勘探与运维文档需调整上下文窗口参数，确保完整召回关键信息。多源数据混合调用时，需配置按业务类型分类召回的规则，避免无关数据干扰输出。内部办公场景的员工数据需严格限定访问范围，需配置安全的代理与令牌规则。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 矿山文档包含长篇幅的勘探报告与运维日志，需容纳多源上下文信息 |
| `maxTokens` | 2000–3000 token | 内部办公与员工服务的回复需覆盖设备状态、排班调整等具体内容，避免截断关键信息 |
| `quoteMaxToken` | 1500–2000 token | 需优先召回设备运维记录、员工培训文档等核心参考内容，控制引用片段长度 |
| `temperature` | 0.3–0.5 | 内部办公场景需稳定的信息输出，避免无关发散内容 |
| `toolChoice` | auto | 需根据用户查询自动调用知识库召回或工具，适配设备数据查询、员工考勤咨询等多类场景 |
| `AIPROXY_API_ENDPOINT` | 企业内网部署的代理地址 | 矿山内部数据需保障传输安全，避免外网泄露敏感生产与员工信息 |
| `AIPROXY_API_TOKEN` | 绑定企业内部服务账号的令牌 | 限制仅授权的内部办公系统可调用模型，保障访问安全 |

## 容易做错的三处
- 现象：在线对话与API调用返回结果差异显著，API调用时`stream`设为`false`、`detail`为`true`仍出现偏差。原因：未统一配置在线与API调用的`maxContext`与`temperature`参数，导致不同调用链路的上下文处理逻辑不一致。
- 现象：模型输出仅包含思考过程，无正文内容。原因：`maxTokens`配置值过低，导致正文内容被截断，或`temperature`配置超出合理区间，导致输出逻辑异常。
- 现象：进入工作台编辑页面提示未配置语言模型，工作流问题分类中的AI模型选项为空。原因：未在平台全局配置`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`，或配置的令牌无对应模型调用权限。

## 怎么确认配好了
- 发起设备状态或员工考勤相关的测试查询，核对返回内容是否包含对应业务的字段与单位信息。
- 调用API接口发起相同查询，对比在线对话的返回结果，确认两者的上下文召回范围与输出格式一致。
- 检查工作流配置页面，确认AI模型选项已显示可选择的模型列表，无报错提示。
- 查看模型调用日志，确认`maxContext`、`maxTokens`等配置参数的实际取值与预设一致。
