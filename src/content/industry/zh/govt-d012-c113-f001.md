# 船舶制造的内部办公与员工服务：HTTP 接口与外部系统

## 这个品类的数据长什么样
这个品类的数据主要来源于船舶制造企业的车间MES系统、船员管理平台、企业OA系统与物料管理系统。生产工单数据每15分钟同步一次，船员考勤与排班数据每日凌晨更新，物料库存数据每小时刷新。文档多为结构化JSON格式，包含作业编号、船舶型号、工位ID、任务状态、完成时长（单位：小时）、责任人工号等字段，部分考勤数据额外包含岗位、值班时段等信息。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
以下分析基于FastGPT v4.17.0版本的配置逻辑。多源数据的更新频率差异要求接口支持按自定义时间窗口拉取数据，避免重复拉取或遗漏最新生产与办公信息。船舶型号与工位ID的固定格式要求接口参数需校验字段合法性，过滤无效请求。单次拉取的数据量上限由车间系统的返回限制决定，需适配分页逻辑避免请求超时。内部办公与员工服务涉及敏感的船员与生产数据，需通过鉴权机制保障访问权限，同时需兼容部分接口返回的缺失字段，避免解析失败。另外，船舶制造场景的接口调用多发生在车间内网，需适配不稳定的网络环境，设置合理的超时与重试策略。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | Bearer {内部系统分配的API密钥} | 符合国央企内部接口的鉴权规范，保障生产与员工数据的访问安全 |
| 拉取数据的时间窗口 | 最近15分钟 | 匹配船舶制造生产工单的实时更新节奏 |
| 单次拉取数据上限 | 前180条 | 适配车间MES系统单次返回的数据量限制 |
| `responseData` 字段提取规则 | 提取work_order_id、ship_model、task_status | 匹配船舶制造内部办公数据的标准文档结构 |
| 超时设置 | 60秒 | 避免车间内网波动导致请求长时间阻塞 |
| `variables` 绑定参数 | 传入当前用户的部门ID | 用于按部门筛选员工服务相关的办公数据 |

## 容易做错的三处
- 现象：调用外部生产系统接口返回401 Unauthorized报错，原因：未正确配置`Authorization`参数，或使用了过期的内部API密钥。
- 现象：重启FastGPT服务后，所有外部接口的配置项全部丢失，原因：将接口配置存储在了容器临时目录，未挂载持久化存储路径。
- 现象：拉取的船员排班数据未按岗位筛选，返回全量企业内所有船员的排班信息，原因：未在`variables`中绑定岗位参数，导致拉取范围超出预期。

## 怎么确认配好了
- 手动触发一次接口调用，查看返回的`responseData`是否包含预期的船舶制造相关字段，如ship_model、work_order_id。
- 检查`Authorization`参数的格式是否符合Bearer token规范，可通过内部鉴权系统验证密钥有效性。
- 模拟FastGPT服务重启，确认配置项未丢失，验证持久化存储路径配置正确。
- 拉取指定时间窗口内的数据，确认返回条数符合单次拉取上限的设置，无明显数据截断。
