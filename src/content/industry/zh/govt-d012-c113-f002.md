# 船舶制造的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
船舶制造内部办公与员工服务场景下的数据，来源包括产品数据管理（PDM）系统、企业资源计划（ERP）系统、办公自动化（OA）系统及设备运维台账，还包含员工考勤记录、岗位操作手册等。数据类型包含结构化的生产工单、半结构化的船舶设计文档、非结构化的运维日志与员工培训材料。更新节奏随业务场景差异较大：生产工单随生产班次实时更新，设计图纸随项目节点阶段性更新，员工手册类文档按季度更新。字段包含船舶分段编号、焊缝探伤报告编号、主机型号等专业标识，单位涉及毫米、吨、运行小时等工业常用单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化生产工单的多字段属性，要求索引时需保留字段关联信息，避免分块破坏业务逻辑；半结构化设计文档存在长段落内容，对分块长度与`maxToken`的设置提出明确要求；实时更新的生产工单需要支持增量索引，降低全量重建的资源消耗；非结构化运维日志的文本长度差异较大，需配置灵活的分块规则适配不同长度的内容；专业字段如船舶分段编号的唯一性，需要在索引时设置关联约束避免重复数据入库。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配船舶设计文档的半结构化段落长度，避免切分专业术语 |
| 重叠长度 | 50–80 字符 | 保留分块间的上下文关联，防止长段落的专业信息被截断 |
| 相似度阈值 | 0.72–0.85 | 匹配船舶制造场景下的专业术语语义相似度，过滤低相关结果 |
| 单次搜索上限 | 前10条 | 控制返回结果数量，适配内部办公的精准检索需求 |
| `maxToken` | 4096 token | 适配主流向量模型的输入长度限制，覆盖长文档分块需求 |
| `defaultToken` | 256 token | 处理短文本如员工工单摘要的向量生成，避免冗余计算 |

## 容易做错的三处
- 向量后数据总量比源文件少数千条。原因：分块时未过滤空值字段或无效行，船舶制造的工单数据中存在未填写的设备编号字段，被自动跳过。
- 集合创建成功但页面索引一直无法建立。原因：未配置增量索引的触发规则，实时更新的生产工单数据未同步至向量库，或索引分片配置不足导致超时。
- 本地运行向量索引结果正常，Docker镜像运行后向量得分一致。原因：Docker容器内未挂载正确的向量模型缓存目录，导致每次调用都重新拉取模型，或环境变量配置异常导致模型调用逻辑变更。

## 怎么确认配好了
- 查看向量任务日志，确认分块后的文档数量与源数据的有效行数一致。
- 检索一条已知的专业术语，核对返回结果的相似度分布符合预设阈值区间。
- 上传一份测试用的船舶设计文档片段，验证索引生成的耗时符合预期配置。
- 检查增量索引的触发记录，确认实时更新的工单数据已同步至向量库。
