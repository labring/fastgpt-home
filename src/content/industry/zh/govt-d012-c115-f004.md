# 轨道交通装备的内部办公与员工服务：工作流编排

## 这个品类的数据长什么样
轨道交通装备的业务数据来源包括生产制造执行系统、设备运维台账库、员工考勤排班系统、采购入库管理系统。生产类数据按秒级更新，运维台账按班次更新，考勤与采购数据按日或周更新。数据文档结构包含设备编号、型号、维保周期、上次检修时间、备件库存等字段，员工数据包含工号、岗位、所属车间、排班信息，办公申请数据包含申请单编号、审批节点、提交时间。字段单位包括天、件、小时等，设备编号为字母与数字组合的唯一标识。

## 这些特征在「工作流编排」这一环带来什么约束
生产数据的秒级更新要求工作流支持实时事件触发，无法依赖定时轮询来获取最新信息。不同数据源的更新节奏差异，要求工作流配置多类型触发节点，分别适配实时、日更、周更的数据来源。设备与员工数据的多字段结构，要求工作流的变量提取模块支持按指定字段精准拉取，避免冗余数据干扰流程。跨车间的员工与生产数据分散存储，要求工作流支持按节点划分数据访问范围，保障数据隔离。运维周期的天级单位，要求工作流的时间判断节点匹配天级计算逻辑，确保流程节点触发符合维保计划。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按生产事件触发 | 匹配生产数据秒级更新的节奏，适配实时办公审批需求 |
| `variables` | 绑定设备编号、维保周期字段 | 对应设备台账的核心业务字段，保障流程数据准确性 |
| `nodeId` | 按车间划分节点ID | 匹配跨车间数据隔离的管理要求，保障数据访问权限 |
| 重试次数 | 3次 | 应对生产系统临时波动，减少流程中断概率 |

| 单次调用上限 | 前20条 | 适配设备台账的单批次数据量，避免流程过载 |

## 容易做错的三处
- 工作流调用知识库后返回无匹配结果，原因是未将设备编号作为检索关键词传入知识库检索模块，导致无法关联对应维保文档。
- 工具调用模块无响应，原因是未配置对应生产系统的API访问权限，或触发节点未绑定正确的`nodeId`。
- 代码执行模块报错找不到依赖库，原因是未在FastGPT容器的Python环境中安装指定库，或导入路径配置错误。

## 怎么确认配好了
- 提交一条模拟生产工单，验证工作流是否按预期自动触发。
- 打开工作流变量面板，确认`variables`中已正确提取设备编号、维保周期等业务字段。
- 运行工具调用模块，检查是否能正常拉取生产系统的实时数据。
- 触发代码执行模块，验证指定的依赖库可正常加载使用。
