# 轨道交通装备的内部办公与员工服务：模型接入与配置

## 这个品类的数据长什么样
轨道交通装备的数据主要来自设备运维日志、维保台账、工位考勤系统与生产调度系统。数据覆盖车载、地面运维与生产环节，更新节奏分为实时（运维告警）、每日（维保记录）与月度（设备台账）。文档结构包含设备唯一编号、累计运行时长、故障代码、维保人员工号、工位ID等字段，部分字段带有单位，如运行时长以小时计，维保次数以次计。

## 这些特征在「模型接入与配置」这一环带来什么约束
轨道交通装备的多来源、分节奏更新的数据特征，对模型接入配置带来多重约束。实时运维告警数据的高频写入，要求模型上下文窗口适配短周期数据片段，避免过长上下文占用资源。结构化的设备台账与维保记录包含带单位的字段，要求模型输出需严格匹配字段格式与单位，需调整参数约束生成逻辑。多模态的设备外观故障图片数据，要求视觉模型接入需适配工业场景的高清巡检图输入。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配轨道交通装备多来源的短周期运维日志与结构化台账数据，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 匹配设备故障分析、员工服务咨询的常规输出长度，控制单轮响应资源消耗 |
| `quoteMaxToken` | 1500 token | 保留足够的结构化设备台账与维保记录片段用于上下文引用，兼顾召回精度与响应速度 |
| `temperature` | 0.2–0.4 | 约束生成内容的随机性，确保设备参数、单位等结构化信息输出准确 |
| `vision` | 开启 | 适配设备外观巡检、故障图片识别的内部办公场景需求 |
| `AIPROXY_API_ENDPOINT` | 填写部署节点专属地址 | 实现本地模型或私有部署模型的安全接入，符合轨道交通装备的数据不出域要求 |
| `AIPROXY_API_TOKEN` | 填写对应校验密钥 | 完成私有模型接入的身份校验，避免配置报错 |

## 容易做错的三处
- 点击模型属性后弹出配置失败报错，提示接口参数格式错误。原因是未按照轨道交通装备的数据出域要求配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，导致本地私有模型接入时身份校验失败。
- 尝试启用视觉模型识别设备巡检图片却无结果返回。原因是未开启`vision`配置项，或上传的图片分辨率未匹配工业场景的高清巡检图规格。
- 配置`maxTokens`参数时设置为过大数值，导致单轮响应超时。原因是未结合轨道交通装备的单轮咨询场景调整参数，超出部署节点的资源阈值。

## 怎么确认配好了
- 进入模型管理页面，查看已配置的模型属性，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`字段已正确填写，无空值或格式错误。
- 发起一次设备运维咨询测试，查看响应结果中是否准确匹配设备编号、运行时长等带单位的结构化字段，无明显格式偏差。
- 上传一张设备巡检图片进行测试，确认模型可正常识别并返回对应分析内容，验证`vision`配置项生效。
- 查看系统日志，确认无模型接入超时或参数校验失败的报错记录，验证配置的稳定性。
