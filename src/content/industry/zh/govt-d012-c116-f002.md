# 通信工程建设的内部办公与员工服务：向量模型与索引
仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 这个品类的数据长什么样
通信工程建设的内部办公数据主要来源于施工日志、设备运维台账、工程进度文档、员工工单与现场交底记录。数据更新节奏差异明显：施工日志、运维工单为实时更新，设备台账、工程预算文档按周或月度更新。单篇文档结构固定，包含工程编号、施工区域、GPS坐标、设备型号、处理结果等字段，部分文档附带音频转写的现场交底内容，单位涉及工日、台套、千米等工程专属单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
通信工程建设的内部办公数据的多更新节奏、专属字段与文档类型，对向量模型与索引环节带来多重约束。实时产生的施工日志与运维工单需要支持增量索引，避免全量重建带来的资源消耗。包含GPS坐标、工程编号等结构化字段的文档，需要结合文本向量与元数据过滤能力，实现精准召回。现场交底的长文本转写内容，要求索引支持长文本切分与重叠分段，避免关键信息丢失。不同更新周期的文档需分类索引，防止高频更新数据覆盖低频静态数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配施工日志、工单等文档的单段有效信息长度，避免单块内容过载 |
| 重叠长度 | 100–150 字符 | 覆盖跨块的施工步骤、设备问题描述等关键信息，防止分段断裂 |
| `defaultToken` | 8192 token | 适配多数开源向量模型的输入上限，满足长文本转写内容的嵌入需求 |
| 相似度阈值 | 0.72–0.85 | 区分同类施工问题与不同班组的相似记录，避免误召回 |
| 单次搜索上限 | 前 20 条 | 匹配通信工程建设的工单与日志的常规召回量，平衡召回效率与精度 |
| 最大上下文 | 4000 字符 | 适配内部办公问答的有效信息长度，避免冗余内容干扰模型理解 |

## 容易做错的三处
- 现象：自定义文档切分后，知识库内出现重复索引条目，且索引顺序与原文档不一致。原因：未在切分环节保留文档唯一标识字段，导致索引时无法关联原文档顺序，且未开启自动去重配置。
- 现象：调用向量模型时返回401状态码。原因：未正确配置向量模型的API密钥，或使用OneAPI渠道未正确绑定专属向量模型接口，导致鉴权失败。
- 现象：索引合并组件运行后未生效，无去重结果。原因：未开启索引合并的去重开关，或合并规则未匹配文档的工程编号等唯一字段。

## 怎么确认配好了
- 上传一篇包含工程编号、GPS坐标的测试文档，检查索引后是否保留工程编号、GPS坐标等元数据字段。
- 触发增量索引任务，对比更新前后的索引条目数，确认实时数据被正确添加。
- 输入包含施工区域关键词的测试问题，检查召回结果是否包含对应区域的文档。
- 查看向量模型调用日志，确认返回的嵌入结果无格式错误，且状态码为200。
