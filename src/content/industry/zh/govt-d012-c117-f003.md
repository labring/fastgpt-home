# 通信铁塔与基础设施的内部办公与员工：多轮对话与提示词

## 这个品类的数据长什么样
通信铁塔与基础设施的运维数据主要来源于铁塔巡检无人机、基站动力环境监控系统、线下巡检台账系统。数据更新节奏分为两类：实时巡检数据由巡检设备同步，运维告警数据随触发即时更新，基础台账数据每日同步。单条数据文档包含铁塔唯一标识、安装位置、塔高、巡检时间、设备运行状态、告警等级、维护记录等字段，字段单位统一为米、小时、次等标准运维单位，无自定义非标准单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新节奏差异大，要求多轮对话需区分实时告警与历史台账数据的上下文优先级，避免混淆不同时效的信息。字段包含多类业务标识与状态，提示词需明确指定字段的取值范围与单位，防止返回不符合业务规范的内容。单条巡检记录内容较长，多轮对话的上下文长度需控制在合理区间，避免超出大模型处理上限。品类专属的业务流程如告警分级处理需在提示词中固化，确保对话响应符合运维规范。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文token数 | 8000–12000 token | 通信铁塔巡检单条记录内容较长，避免上下文溢出导致截断 |
| 全局变量绑定 | 绑定铁塔ID、巡检点位、告警等级 | 匹配品类特有业务字段，确保多轮对话关联正确的铁塔数据 |
| 对话历史保留时长 | 7天 | 内部办公场景下员工需回顾近期交互，过长会占用平台资源 |
| `messages`参数配置 | 按时间倒序传入最近10轮对话 | 优先使用最新的巡检请求与响应，避免旧数据干扰当前对话 |
| `variables`参数使用 | 传入动态业务参数 | 自动替换提示词中的品类特有变量，无需手动修改对话内容 |
| `chatId`参数配置 | 绑定会话唯一标识 | 确保同一场景下的对话上下文连贯，避免跨会话数据混淆 |
| 错误重试次数 | 2次 | 应对大模型偶尔响应为空的异常场景 |

## 容易做错的三处
- 现象：调用知识库AI对话后返回与提问无关的内容。原因：未在提示词中限定检索范围为通信铁塔运维、巡检相关的专属文档，导致调用了不相关的知识库条目。
- 现象：工作流中配置的全局变量未被正确代入提示词。原因：未按`variables`参数的格式传入动态业务字段，或未绑定铁塔ID、巡检点位等品类特有变量。
- 现象：大模型输出内容包含未闭合的引用号乱码，输出后变回标准引号。原因：未在提示词中明确指定输出格式，未要求统一使用标准引号包裹内容。

## 怎么确认配好了
- 发起一条针对特定铁塔ID的巡检咨询，检查返回内容是否仅包含该铁塔的相关数据。
- 查看工作流日志，确认`variables`参数中已传入当前业务场景的特有字段值。
- 模拟多次大模型调用，检查是否出现响应为空的情况，确认错误重试机制已生效。
- 导出对话历史，检查是否按时间倒序保留了最近的交互内容，无冗余旧数据。
