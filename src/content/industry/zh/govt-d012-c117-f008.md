# 通信铁塔与基础设施的内部办公与员工服务：文档解析与分块

## 这个品类的数据长什么样
通信铁塔与基础设施的核心数据来源于日常运维日志、季度巡检报告、资产台账与维护工单。数据来源包括基站运维系统、巡检手持终端、资产管理平台。更新节奏分为实时（故障上报、临时巡检）、每日（台账同步）、月度（运维报表生成）。文档结构多为结构化表格与半结构化文本，包含铁塔编号、塔高、负载功率、巡检时间、故障等级、处理结果等字段，单位多为米、千瓦、小时、次等。单篇文档体积跨度较大，小型巡检报告约数十页，大型月度运维报表可达数百页。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档特征对解析分块环节带来多重约束：结构化表格占比高，分块时需保留整行字段的关联完整性，避免拆分跨列的资产信息；半结构化文本的章节划分清晰但字段固定，分块需匹配章节边界防止割裂运维流程；实时更新的故障工单文本较短但批量上传时数量多，需控制单批次解析的文档体积；大型月度报表页数多，解析耗时较长，需调整超时阈值避免中断。此外，不同文档的格式差异较大，需适配PDF、Word、Excel等多种格式的解析规则。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 1000–1500 字符 | 适配巡检报告、运维工单的单段文本长度，避免割裂故障处理的完整流程 |
| `chunkSplitter` | 按标题与换行符分段 | 适配半结构化文档的章节划分，保留铁塔编号、故障类型等字段的上下文关联 |
| `customPdfParse` | 启用表格结构化解析 | 适配资产台账、巡检报告中的多列表格，提取完整字段信息 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 适配单篇月度运维报表的体积上限，避免上传超时 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 适配多页PDF文档的解析耗时，防止长文档解析中断 |
| `chunkSettingMode` | 手动配置 | 针对结构化文档调整分块规则，适配不同类型的运维文档 |

## 容易做错的三处
- 上传巡检PDF后解析结果为空，原因是未启用`customPdfParse`的表格结构化解析开关，导致多列表格无法被正确提取。
- 分块后运维工单的故障处理流程被割裂，原因是`chunkSize`设置过小，未匹配单段完整流程的文本长度。
- 上传大型资产台账时解析超时中断，原因是`PARSE_FILE_TIMEOUT_SECONDS`设置低于实际解析耗时，未适配多页文档的处理时间。

## 怎么确认配好了
- 上传单篇10页的结构化巡检报告，查看解析结果是否包含完整的表格字段与连续的文本段落。
- 上传500 MB以内的月度运维报表，确认上传进度条完成后无报错提示。
- 调整`chunkSize`为1200字符，测试分块结果是否未割裂连续的故障处理描述。
- 查看系统日志，确认解析耗时未超过`PARSE_FILE_TIMEOUT_SECONDS`的设置值。
