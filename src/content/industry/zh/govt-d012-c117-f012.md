# 通信铁塔与基础设施的内部办公与员工服务：部署与升级

## 这个品类的数据长什么样
通信铁塔与基础设施的内部办公数据主要来源于基站运维管理系统、日常巡检记录、员工工单台账、资产盘点系统。数据更新节奏覆盖实时（巡检上报、故障工单）、每日（考勤、排班）、每周（资产盘点）三类。单份文档多为结构化表格形式，包含基站编号（单位：号）、巡检时间、故障等级、处理耗时（单位：分钟）、员工工号、工单状态等字段，部分附件包含现场拍摄的高清巡检照片与故障点位标注文件。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的多源结构化数据与高清附件并存，部署阶段需同时配置关系型数据库与对象存储服务，适配不同格式数据的存储需求。实时更新的巡检与故障工单要求部署低延迟缓存服务，保障数据查询响应速度。多样的更新节奏需要配置灵活的定时同步任务，避免数据滞后。同时，单份附件体积较大，需提前调整文件上传限制，避免部署后出现上传失败问题。员工规模与部门划分明确，需提前配置多账号协同的权限规则，适配内部办公的分级管理需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30 个` | 该品类数据连接请求频繁，需预留足够连接池应对巡检、工单等多并发查询 |
| `MONGODB_URI` | `国内云厂商MongoDB实例连接串，单实例存储容量不低于500 GB` | 存储高清巡检照片等非结构化附件，国内实例可降低跨地域访问延迟，充足容量适配长期数据积累 |
| `REDIS_URL` | `内存容量不低于8 GB的持久化Redis实例地址` | 缓存实时更新的工单状态与基站在线信息，保障低延迟查询，持久化配置避免缓存数据丢失 |
| `STORAGE_S3_ENDPOINT` | `对应国内云服务商对象存储节点地址` | 适配结构化数据与附件的统一存储，简化升级后的迁移流程，降低跨地域访问成本 |
| `FILE_TOKEN_KEY` | `32位随机字符串` | 保障上传文件的身份验证安全，避免未授权访问巡检附件 |
| `ROOT_KEY` | `仅用于初始管理员配置的强随机密钥` | 初始化多账号协同的权限体系，适配内部办公的分级管理需求 |

## 容易做错的三处
- 现象：上传2MB以上的巡检照片附件时显示上传失败，界面返回「文件大小超出限制」报错。原因：未调整默认文件上传阈值，FastGPT v4.17.0默认限制小于2MB的文件上传。
- 现象：在Linux环境拉取FastGPT镜像时提示超时，已配置国内镜像源仍未解决。原因：未将`STORAGE_S3_ENDPOINT`指向国内节点，镜像拉取时的依赖资源请求仍指向境外节点。
- 现象：创建多个员工账号后无法实现部门权限隔离，部分账号可查看非本区域的基站工单。原因：未使用`ROOT_KEY`初始化权限体系，未配置分级账号的访问控制规则。

## 怎么确认配好了
- 执行容器状态检查命令，确认所有关联的数据库、缓存、存储服务容器均正常运行，无异常退出记录。
- 上传对应品类业务所需体积的办公附件，验证上传流程无报错，附件可正常存储与访问。
- 使用初始管理员密钥登录系统，创建测试账号并分配对应权限范围，验证测试账号仅可访问授权范围内的内部数据。
- 调用系统内置的健康检查接口，确认各服务连接参数配置正确，无连接超时或认证失败报错。
