# 钢铁冶炼的内部办公与员工服务：多轮对话与提示词

## 这个品类的数据长什么样
钢铁冶炼的业务数据主要来自工控采集系统、生产执行系统（MES）、设备巡检台账与内部办公系统。工控类数据以秒级或分钟级更新，包含高炉炉温、转炉供氧流量、轧机轧制压力等实时指标，字段含时间戳、设备编号、监测数值，单位对应℃、m³/h、MPa等。生产报表按日更新，记录班次产量、能耗消耗，字段含生产批号、班组、合格件数。办公类数据包含员工考勤、审批单据，字段含工号、部门、提交时间，更新频率为班后或实时。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
钢铁冶炼的多源异构数据特征，对多轮对话与提示词配置带来多重约束。实时工控数据的高频更新，要求对话上下文需自动过滤超时的监测数值，避免调用过期指标。多源数据混合的场景，提示词需明确划分工控、生产、办公类数据的使用规则，防止不同数据源的字段混淆。生产报表与巡检日志的长文本属性，要求提示词限定信息提取的范围与字段，避免输出冗余内容。设备编号、生产批号等标准化字段的存在，要求提示词匹配对应格式的标识，确保查询定位准确。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口长度 | 8000–12000 token | 覆盖单班次的工控日志、生产报表与办公审批的总内容长度 |
| 问题优化 | 开启 | 钢铁冶炼存在大量专业术语，优化后可提升大模型对专业问题的理解准确性 |
| 单次召回文档上限 | 前10条 | 平衡信息完整性与上下文过载风险，适配多源数据的召回需求 |
| 变量绑定 | 按`variables`绑定当日生产指标 | 确保多轮对话可跟踪当日设备运行、产量变化的实时数据 |
| 对话日志存储周期 | 30天 | 满足内部审计与合规查看的基础要求 |
| 提示词模板更新 | 按实测标定 | 适配生产流程的阶段性调整，避免模板与实际业务脱节 |

## 容易做错的三处
- 现象：上传的生产报表、巡检日志未被大模型纳入对话上下文，回答未提及上传数据中的相关数值或内容。原因：未在提示词中明确指定上传数据的引用规则，或未将上传文件绑定至`messages`上下文队列。
- 现象：对话中无法渲染设备监测的折线图、报表截图等可视化内容，仅返回纯文本描述。原因：未开启对话内图片渲染的相关配置，或提示词未包含生成可视化内容的明确指令。
- 现象：对话日志中未显示当前操作人员的飞书用户名，且多轮对话出现响应延迟或超时报错。原因：未绑定员工工号与飞书账号的映射关系，未通过`chatId`关联对话会话与操作人员信息，且未限制单次召回的文档数量导致上下文过载。

## 怎么确认配好了
- 上传一份当日的生产报表，发起包含“提取当日高炉炉温均值”的问题，核对回答是否包含上传文件中的对应数值。
- 发起连续三轮关于同一轧机设备的参数查询，核对每轮回答是否延续前一轮的上下文信息，未出现重复或遗漏。
- 检查对话日志的存储目录，确认已按配置的周期保留对应时长的交互记录。
- 发起包含“生成当日能耗趋势图”的问题，核对对话界面是否返回对应的图片或图表内容。
