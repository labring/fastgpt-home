# 高速公路运营的内部办公与员工服务：向量模型与索引

## 这个品类的数据长什么样
高速公路运营的内部办公与员工服务数据主要来自三类来源：日常内部办公文档，包括收费操作规范、路政事件处理手册、员工培训资料；一线运维与收费的实时记录，包括巡检日志、车道运行数据、收费台账；以及跨部门协作的会议纪要与通知。数据更新节奏差异明显：办公文档按需或按月更新，巡检与收费数据按小时或实时更新，台账类数据每日更新。文档包含结构化与非结构化两种形式，结构化数据含路段编号、车道号、巡检频次、处理时长等字段，非结构化文档多为长文本格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化数据与非结构化文档混合存在，需要针对不同字段设置差异化的向量化权重，避免通用分块导致的信息偏差。实时更新的巡检与收费数据要求索引支持增量更新，无法依赖全量重建，否则会导致检索延迟。长文本的办公文档与短条目式的巡检记录并存，需要灵活调整分块规则，适配不同长度的内容。字段包含路段编号、时间戳等特定单位的内容，需在向量化前完成标准化预处理，确保向量空间的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配高速公路运营的巡检日志、操作手册等文档的常规内容长度，避免分块过碎或过长 |
| 重叠长度 | 100–150 字符 | 保留分块间的上下文关联，覆盖长文档的跨块逻辑，避免关键信息断裂 |
| 相似度阈值 | 0.72–0.85 | 匹配收费规范、路政台账等不同类型文档的精度要求，过滤低质量匹配结果 |
| 单次搜索上限 | 前10条 | 控制返回结果量级，适配内部员工的精准检索需求，避免冗余信息干扰 |
| `maxToken` | 4000 token | 限制单轮上下文总长度，符合FastGPT v4.17.0版本的大模型输入规范 |
| `defaultToken` | 200 token | 设定默认回答生成长度，适配员工日常咨询的简要回复需求 |

## 容易做错的三处
- 现象：Docker打包镜像运行后，所有检索结果的向量得分完全一致。原因：镜像中未正确挂载向量索引的持久化目录，导致每次启动都重新生成初始测试数据，未加载实际业务索引。
- 现象：混合检索耗时超过10秒，单次检索响应超时。原因：未针对高速公路运营的结构化与非结构化混合数据调整检索权重，同时未限制单次搜索的数据源范围，导致全量索引扫描。
- 现象：索引构建过程停滞在最后一组文件，无法完成全部构建。原因：未配置`maxToken`参数，导致超长文档的分块处理超出系统内存阈值，进程挂起。

## 怎么确认配好了
- 上传单份高速公路巡检日志文档，检查分块结果的长度与重叠比例是否符合配置要求。
- 模拟员工咨询路政事件处理流程，核对检索结果的相似度得分是否落在预设区间内。
- 启动Docker容器运行服务，对比本地与容器内的检索结果一致性，确认索引挂载正常。
- 测试混合检索场景，查看响应耗时是否符合业务预期，调整相关配置参数。
