# IT 服务台的员工服务台：多轮对话与提示词

## 这个品类的数据长什么样
IT服务台的数据主要来源于企业内部IT运维工单系统、设备资产台账、员工IT求助记录及官方IT政策文档。数据更新节奏分为三类：工单与求助记录在提交后实时更新，设备台账每日同步至运维平台，政策文档按需更新。单条数据的结构包含工单ID、提交人标识、设备型号、问题描述、处理状态、解决方案、资产编号等字段，其中耗时类字段单位为分钟，标识类字段为字符串格式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
工单与求助记录的分散存储要求多轮对话需关联`messages`中的历史上下文，追踪员工的求助进度与工单状态；设备台账的多字段特征要求提示词需明确指定提取目标字段，避免混淆无关信息；实时更新的工单数据要求对话过程中动态拉取最新信息，无法依赖静态缓存；口语化的员工问题描述则要求对话环节具备自动优化功能，提升与知识库的匹配精度。

以下配置基于FastGPT v4.17.0版本的界面与参数逻辑。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages`上下文窗口 | 8000–12000 token | 覆盖IT服务台多轮交互的完整对话历史与工单信息 |
| 单次召回结果上限 | 前3条 | 聚焦常见IT故障，避免冗余信息干扰对话判断 |
| `variables`数据源触发 | 每轮对话后更新 | 实时同步最新的工单状态与设备台账数据 |
| `chatId`存储时长 | 7天 | 匹配IT求助的常规处理周期 |
| 问题优化开关 | 开启 | 修正员工口语化的IT问题描述，提升匹配精度 |

## 容易做错的三处
- 现象：执行长文本任务时，界面显示任务正常完成但抛出`The value of "offset" is out of range`报错。原因：未限制`messages`上下文窗口的长度，导致加载的历史对话与工单数据超出模型支持的token上限，触发偏移量异常。
- 现象：对话中无法获取指定设备的运维信息。原因：未在`variables`中配置正确的数据源关联规则，无法匹配员工提到的资产编号等关键字段。
- 现象：多文件上传后对话未引用全部文档内容。原因：未按对话接口的参数规范传递多文件关联的上下文，导致部分文件未被加载进对话参考范围。

## 怎么确认配好了
- 发起一条模拟IT求助对话，核对对话过程中是否自动同步最新的工单状态与设备信息。
- 输入较长的IT问题描述，确认未触发偏移量异常类报错。
- 上传多份IT运维相关文档，发起关联查询，确认对话能覆盖全部上传文件的内容。
- 等待7天后再次访问对应会话，确认会话无法获取历史上下文信息。
