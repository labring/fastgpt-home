# IT 服务台的员工服务台：工具调用与插件

## 这个品类的数据长什么样
IT服务台的数据源主要来自企业内部IT资产管理系统、员工工单提交平台、桌面运维日志库三类。数据更新节奏为：工单提交数据实时同步，资产存量数据每日凌晨批量更新，运维日志按小时归档。单条数据文档结构包含工单唯一标识、提交员工工号、问题分类标签、关联设备编号、提交时间戳、当前处理状态六个核心字段，字段单位分别为字符串、数字编号、枚举分类、设备序列号、ISO格式时间、状态枚举值。

## 这些特征在「工具调用与插件」这一环带来什么约束
实时提交的工单数会随办公时段波动，工具调用需适配峰值请求的并发限制，避免触发源系统的限流规则。每日更新的资产数据，插件拉取频率不宜超过每日一次，否则会重复占用源系统的同步资源。工单与设备的关联关系要求工具调用的入参必须包含设备编号字段，否则无法完成关联设备的状态查询。按小时归档的运维日志，插件需支持指定时间范围参数，仅查询对应时段的数据以降低传输开销。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 设为`auto` | 适配IT服务台多类型工具的自动调度需求 |
| `functionCall` | 开启强制模式 | 确保工具调用入参严格匹配工单核心字段 |
| 插件请求超时阈值 | 300秒 | 适配实时工单的快速响应要求 |
| 资产数据拉取频率 | 每日1次 | 匹配资产数据的每日更新节奏 |
| 入参校验开关 | 开启严格校验 | 避免因字段缺失导致的调用失败 |
| 时间范围适配规则 | 按工单提交时段自动设置 | 适配运维日志的按小时归档特征 |

## 容易做错的三处
- 调用智谱多模态工具时报参数错误，且OpenAI协议调用OneApi接口正常。原因是未将多模态工具的入参格式适配FastGPT的`functionCall`强制模式要求，导致参数结构不匹配。
- 插件编辑页面始终显示“未保存”，点击保存后仍未消失。原因是FastGPT v4.17.0版本中，插件配置的关联字段未正确绑定至工单系统，未触发保存校验的成功状态。
- 调用reranker插件返回结果为false。原因是未配置插件的访问白名单，导致源系统拒绝请求，或插件入参的文本长度超出预设阈值。

## 怎么确认配好了
- 提交一条测试工单，触发工具调用，检查是否自动匹配对应IT资产的查询插件。
- 查看插件调用日志，确认入参包含工单核心字段，且超时时间未超过300秒。
- 检查资产数据拉取任务的执行记录，确认每日凌晨自动完成更新。
- 进入插件编辑页面，保存配置后检查页面顶部提示是否消失。
