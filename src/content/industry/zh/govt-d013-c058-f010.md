# IT 服务台的员工服务台：知识库检索与召回

## 这个品类的数据长什么样
IT服务台的数据来源于企业内部IT服务管理系统的工单记录、运维日志、员工求助归档文档、官方软件操作手册。更新节奏为实时同步新提交的求助工单，月度更新运维日志归档，季度同步软件版本更新的文档。文档结构包含结构化字段（如工单号、问题分类、处理时长）与非结构化文本（如问题详情、修复步骤），部分文档附带设备型号、软件版本等属性字段，无统一的固定格式模板。

## 这些特征在「知识库检索与召回」这一环带来什么约束
IT服务台的数据实时性要求，要求检索链路支持增量同步新产生的工单与运维记录，避免全量索引重建带来的检索延迟。混合结构化与非结构化的文档结构，要求检索同时覆盖关键词匹配与语义召回，同时支持按设备型号、软件版本等属性字段过滤召回范围。长文本类的修复步骤文档，需要适配合理的分块规则，避免语义切割导致的召回失效。高频重复的员工求助场景，要求优化召回的去重与排序逻辑，减少冗余结果的干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配IT服务台常见的问题相似度区间，兼顾召回覆盖率与精准度 |
| `limit` | 前8–12条 | 覆盖员工常见的3-5个相似问题场景，保留足够的参考样本 |
| `searchMode` | hybrid | 适配混合结构化与非结构化的文档结构，同时触发关键词与语义检索 |
| `usingReRank` | 开启 | 对召回结果按语义相关性重排，优化长文本文档的排序逻辑 |
| `datasetSearchUsingExtensionQuery` | 开启 | 针对员工模糊的IT求助问题，自动扩展查询词，提升召回覆盖率 |
| `collectionIds` | 绑定IT服务台专属数据集 | 隔离业务数据，避免检索到非IT服务类的文档 |

## 容易做错的三处
- 现象：重排模型部署测试通过，但每次检索返回的`usingReRank`字段为false，重排结果未生效。原因：未将重排模型正确关联到当前IT服务台的数据集，或检索链路未调用已部署的重排服务。
- 现象：检索链路返回块数量超限报错，或召回结果出现语义断裂。原因：未适配IT服务台长文档的特征调整分块规则，导致单文档切分超过3000块，超出检索链路的处理上限。
- 现象：工具调用环节无法选择指定的IT服务台知识库。原因：未将知识库与当前IT服务台的服务链路绑定，或`collectionIds`参数未正确配置为目标数据集ID。

## 怎么确认配好了
- 进入FastGPT v4.17.0的检索调试页面，查看当前配置的`similarity`、`limit`等参数是否与设定值匹配。
- 提交一条典型的IT服务台求助问题，核对召回结果的数量与相关性是否符合预期的检索范围。
- 开启重排功能后，对比召回结果的初始排序与重排后的排序，确认重排逻辑已生效。
- 在工具调用配置界面，检查可选择的知识库列表中是否包含绑定的IT服务台专属数据集。
