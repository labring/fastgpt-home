# 人事政策问答的员工服务台：向量模型与索引

## 这个品类的数据长什么样
人事政策问答的数据源来自内部正式发布的人事管理文档，包括考勤休假制度、薪酬福利规范、入职离职流程、绩效考核规则等。文档更新节奏随企业人事政策调整而定，新政策发布时即时更新，常规季度或年度梳理修订。文档结构多为层级化条款，包含政策编号、生效日期、适用人群、具体执行细则等字段，部分文档附带计算类单位，如工作日、薪资比例、休假天数等。

## 这些特征在「向量模型与索引」这一环带来什么约束
人事政策文档的层级化条款结构要求分块时不能破坏条款完整性，否则会导致语义关联断裂，影响召回准确性。文档更新频率不固定且可能批量新增，要求索引支持增量更新与批量索引构建，避免全量重建带来的资源消耗。字段中的生效日期、适用人群等元数据，需要结合向量召回进行过滤，因此索引需支持元数据与向量相似度的联合检索。文档长度差异较大，短条款仅数十字符，长条款可达数千字符，分块后的文本需控制在`maxToken`的设定范围内，避免超出嵌入模型的输入限制。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配人事政策单条款的常见长度，避免拆分完整条款 |
| 重叠长度 | 100–200 字符 | 保留跨分块的上下文关联，防止条款逻辑被分块打断 |
| `defaultToken` | 1024 token | 设置分块的默认token基数，适配基础嵌入模型的输入要求 |
| `maxToken` | 4096 token | 适配通用嵌入模型的输入上限，匹配多数政策条款的token消耗 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的结果，聚焦核心政策条款 |
| 单次搜索上限 | 前 10 条 | 匹配员工咨询的常见需求范围，避免过多冗余结果 |
| 重排 | 开启 | 修正向量召回的排序偏差，优先展示最匹配的政策内容 |

## 容易做错的三处
- 现象：无法正确导入指定文件类型的人事政策文档，建索引步骤卡住。原因：未配置Word、PDF、Markdown等人事政策常用文档格式的解析插件。
- 现象：创建知识库时卡在索引构建环节，界面显示超时或无进度。原因：分块长度设置过大，导致单批次处理数据量超出系统处理上限。
- 现象：搜索测试返回空结果或报错，向量数据库中仅存储向量数据无原始文档。原因：未开启原始文档存储配置，仅上传了向量化后的特征数据，无法关联原始政策条款内容。

## 怎么确认配好了
- 上传单条完整的人事政策文档，检查分块后的文本是否完整保留条款层级与核心内容，无强制截断或碎片拆分。
- 发起一条具体的人事政策咨询，检查召回结果的相似度分值是否落在预设阈值区间内，且核心条款优先展示。
- 查看向量数据库的存储内容，确认原始文档文本与向量化后的向量数据同时存在，可通过文档ID关联匹配。
- 上传一条新的人事政策文档，触发增量索引构建，检查新文档是否自动完成向量化与索引更新。
