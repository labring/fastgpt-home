# 人事政策问答的员工服务台：多轮对话与提示词

## 这个品类的数据长什么样
人事政策问答的数据来自国央企、公共服务机构内部合规部门发布的正式文件，包括考勤休假、薪酬管理、招聘转正、绩效考核等专项手册。文档采用章节条款式结构，包含政策名称、生效时间、适用人群、执行细则等固定字段，生效时间采用YYYY-MM-DD格式，适用人群按岗位序列、入职年限划分区间。更新节奏随政策调整无固定周期，单份文档长度从数千到数万字符不等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
人事政策问答的数据结构严谨且绑定明确适用场景，更新无固定周期，文档长度差异较大。这类特征要求多轮对话需精准关联条款编号，避免模糊匹配导致的内容偏差；需定期同步最新政策内容，防止上下文引用过期条款；需引导用户补充岗位、入职年限等适用人群信息，缩小政策匹配范围；同时需控制上下文长度，避免超出模型输入上限，确保多轮交互的准确性与稳定性。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按会话生成唯一标识 | 用于绑定用户对话上下文，确保多轮交互的会话一致性 |
| `messages` | 保留最近10–15轮对话内容 | 人事政策文档较长，过多上下文会超出模型输入上限，保留近期交互可精准关联当前问题 |
| `variables` | 注入当前用户的岗位、入职年限字段 | 匹配政策中针对特定人群的条款，缩小搜索范围 |
| 最大上下文长度 | 8000–12000 token | 适配通用大模型的输入上限，避免截断关键政策条款 |
| 问题优化 | 开启自动追问补充信息 | 针对用户未明确的适用场景，引导补充岗位、入职时间等关键信息 |
| 会话过期时间 | 7200 秒 | 确保用户会话在合理时长内保留，避免过期上下文干扰当前交互 |

## 容易做错的三处
- 现象：AI对话节点返回输入长度超限报错，或直接返回无结果响应。原因：未配置上下文长度限制，多轮对话累积的历史内容超出模型输入上限。
- 现象：对话日志中无法关联到发起请求的具体用户。原因：未在工作流中配置`chatId`参数，无法绑定用户会话的唯一标识。
- 现象：搜索返回的政策条款与用户实际适用场景不符。原因：未通过`variables`注入用户岗位、入职年限等关键信息，无法精准匹配对应条款。

## 怎么确认配好了
- 发起包含岗位、入职年限的多轮提问，查看AI是否能精准关联对应政策条款。
- 查看对话日志，确认每条会话都带有唯一的`chatId`标识，可通过标识定位指定用户的对话。
- 模拟输入超出预设上下文长度的历史对话，检查系统是否触发长度限制拦截或自动截断。
- 测试未提供关键场景信息的提问，查看AI是否自动追问补充必要内容。
