# 人事政策问答的员工服务台：工具调用与插件

## 这个品类的数据长什么样
人事政策问答的数据来源于企业内部人事管理系统、官方人事政策文档库、员工手册修订稿。更新节奏随人事政策调整不定期更新，无固定周期。文档结构多为分章节的条款式，包含政策编号、生效日期、适用岗位范围、执行标准、申请流程等字段，生效日期以YYYY-MM-DD为单位，适用岗位范围标注具体岗位名称，单篇文档长度跨度较大，从数百字到数万字不等。

## 这些特征在「工具调用与插件」这一环带来什么约束
人事政策问答的数据分散在多套内部系统与独立文档中，且存在版本差异，工具调用环节需配置多源数据拉取的对接权限，并增加版本校验逻辑，确保返回的政策为最新有效版本。政策文档包含生效日期、适用岗位范围等结构化字段，工具调用需支持按生效日期、岗位参数进行内容过滤，避免返回过期或不匹配的政策条款。单篇政策文档长度差异较大，工具调用的上下文处理需适配不同长度的文本，同时需避免冗余内容干扰问答的精准性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的工具调用模块逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配人事政策问答的多场景调用需求，自动选择匹配的工具 |
| `functionCall` | 按实际调用场景标定 | 针对结构化政策字段的调用需求，按需开启参数校验 |
| 最大上下文 | 8000–12000 token | 适配单篇政策文档的长度范围，避免上下文溢出 |
| 单次搜索上限 | 前3条政策 | 控制返回内容的冗余度，聚焦核心政策条款 |
| 工具调用超时 | 15–20 秒 | 适配人事政策数据的拉取与处理时长，避免过长等待 |
| 问题优化 | 开启 | 优化用户的岗位、生效日期相关查询，提升工具调用的匹配精度 |

## 容易做错的三处
- 现象：工具调用模块持续输出运行日志，对话界面出现大量拉取、处理记录。原因：未关闭工具调用的日志输出配置项，每次工具执行都打印完整流程。
- 现象：工具返回的政策内容出现字段叠加，例如生效日期与适用岗位的内容重复拼接。原因：未针对政策文档的结构化字段配置拆分逻辑，导致多段政策文本未按字段区分拼接。
- 现象：调用工具后超过10秒未返回结果，或返回超时状态码。原因：未设置合理的工具调用超时阈值，或未限制单次搜索的政策文档数量，导致数据拉取与处理耗时过长。

## 怎么确认配好了
- 手动触发一次针对具体岗位的人事政策查询，核对返回的政策是否包含该岗位的适用范围。
- 查看工具调用的配置面板，确认`toolChoice`设置与当前场景匹配。
- 检查工具调用的超时阈值是否匹配数据拉取的实际耗时，按需调整。
- 关闭工具日志输出后，确认对话界面不再出现冗余的运行记录。
