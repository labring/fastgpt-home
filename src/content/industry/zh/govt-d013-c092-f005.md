# 报销规则问答的员工服务台：工具调用与插件

## 这个品类的数据长什么样
报销规则问答的数据来源于企业内部财务管理制度、专项报销细则文档，更新节奏随财务政策调整而定，通常为年度更新或政策变动后即时更新。文档多采用章节式结构，按差旅费、办公费等费用类型划分模块，包含金额上限、票据合规要求、审批层级等字段，单位多为元、张、工作日等，单篇文档长度从数千字到数万字不等，部分包含附件格式说明。

## 这些特征在「工具调用与插件」这一环带来什么约束
报销规则问答的数据按费用类型结构化划分，工具调用需精准匹配对应类别的字段，无法泛化调用通用规则。文档长度较长且包含附件格式要求，工具调用时需限定召回的文档范围，避免无关内容干扰。数据更新频率不固定，插件需支持定期同步最新的财务政策文档，确保问答内容时效性。票据相关字段要求传入图片或扫描件的合规格式，工具调用需适配多图片传参的格式要求。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的界面与参数逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | auto | 自动匹配最适配的报销规则工具，覆盖多费用类型调用 |
| 多图片传参格式 | base64编码，单张或多张依次传入 | 适配报销票据的图片校验需求 |
| 插件同步周期 | 每7天 | 适配财务政策更新节奏，兼顾时效性与资源消耗 |
| 调用超时时间 | 600秒 | 适配长文档召回与多图片处理的耗时需求 |
| `functionCall` 输出格式 | 严格匹配报销字段名与单位 | 确保调用结果对应正确的费用类别与规则 |
| 召回结果上限 | 前3条 | 过滤冗余内容，聚焦核心报销规则 |

## 容易做错的三处
- 现象：工具调用时传入多张报销票据图片后，返回结果为空或提示“参数格式错误”。原因：未将多张图片分别转为base64编码后依次传入，仅传入单张图片或未正确完成编码转换。
- 现象：调用报销规则问答插件时返回“参数校验失败”。原因：未严格按照`functionCall`要求的字段格式传入数据，遗漏了金额、费用类型等必填字段。
- 现象：插件调用返回的规则内容与最新财务政策不符。原因：未按配置的同步周期定期更新关联的知识库文档，导致数据过时。

## 怎么确认配好了
- 上传单张报销票据图片，执行工具调用，核对传入的参数格式是否与配置的多图片传参要求一致。
- 手动触发插件的知识库同步操作，检查关联文档的更新状态是否符合配置的同步周期要求。
- 发起包含具体费用类型的查询，核对`toolChoice`是否自动选择了适配的工具，返回的规则内容是否匹配查询场景。
- 模拟包含多张票据图片的查询，确认工具调用流程能正常处理多图片传参。
