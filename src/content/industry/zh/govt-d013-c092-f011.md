# 报销规则问答的员工服务台：表单与交互

## 这个品类的数据长什么样
报销规则问答的数据来源于企业内部财务制度手册、年度报销合规通知、专项费用执行细则。数据更新节奏随年度财务政策调整，临时补充政策则按需更新。文档结构按费用类型分层，包含差旅费、办公费、业务招待费等分类，每个分类下明确标注费用限额、凭证要求、审批节点与特殊场景规则。字段包含费用类型、报销金额、凭证编号、出行天数等，单位统一为元、人次、天数等标准财务计量单位。

## 这些特征在「表单与交互」这一环带来什么约束
费用类型分层的文档结构要求表单按分类设计输入模块，避免用户混淆不同费用的规则。数据更新频率要求交互环节支持实时拉取最新规则，确保合规性。明确的限额与凭证字段要求表单添加实时校验逻辑，拦截超出限额的输入或缺失凭证的提交。多字段联动的规则逻辑要求用户选择费用类型后，自动加载对应校验规则与输入提示，减少用户手动查询的成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 按费用类型、报销金额、凭证编号拆分输入项 | 匹配报销规则按费用类型分层的文档结构 |
| `userSelect` | 预设差旅费、办公费、业务招待费5个常见选项 | 减少用户输入错误，适配选择式交互逻辑 |
| 上下文窗口 | 800–1200 字符 | 覆盖单类费用的完整规则内容，避免截断关键信息 |
| 输入校验触发 | 离开当前输入字段后延迟300 毫秒触发 | 平衡校验实时性与交互流畅度 |
| 结果展示格式 | 分费用类型展示规则条目 | 与报销规则的文档结构保持一致，便于用户对照 |

## 容易做错的三处
- 现象为表单提交后返回的规则匹配结果为空，原因是未将报销规则知识库正确关联到`formInput`的输入源配置中。
- 现象为用户切换费用类型后未加载对应规则，原因是未配置`userSelect`的联动更新逻辑，未绑定规则加载触发事件。
- 现象为工具调用环节未获取用户确认就直接执行，原因是未在表单交互模块添加用户输入确认弹窗，遗漏了关键的校验环节。

## 怎么确认配好了
- 填写测试用的报销金额与对应费用类型，检查是否实时弹出限额提示或合规校验信息。
- 切换不同的费用类型选项，确认`userSelect`联动加载对应分类的报销规则内容。
- 上传测试用的凭证附件，检查表单是否弹出对应格式与数量的校验提示。
- 查看FastGPT v4.17.0的知识库关联日志，确认报销规则文档已正确绑定到交互模块。
