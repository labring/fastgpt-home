# 新员工入职引导的员工服务台：工作流编排

## 这个品类的数据长什么样
新员工入职引导的数据来源为企业HR管理系统、入职审批流程表单、线下入职材料扫描件。更新节奏为入职前1-3天批量同步全量员工信息，入职当日单次同步新增员工的最新对接人、工位分配等信息。文档结构为结构化字段集合，包含员工姓名、工号、部门、岗位、入职日期、对接人联系方式等字段，字段类型以文本、日期枚举值为主，无复杂嵌套的非结构化内容。本页面适配FastGPT v4.17.0版本。

## 这些特征在「工作流编排」这一环带来什么约束
新员工入职引导的结构化数据特征，要求工作流编排时需优先绑定明确的字段映射规则，无需额外处理非结构化内容的分块与提取。更新节奏的双重特性，要求工作流支持定时触发与事件触发两种模式，适配批量准备和实时同步的场景。固定的字段集合，使得工作流的节点参数可预设通用模板，同时需支持动态替换`variables`字段值，适配不同员工的个性化信息。单批次数据条目有限的特点，允许工作流配置较低的并发上限，避免资源冗余占用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按入职日期前1天定时触发 + 入职当日事件触发 | 匹配新员工入职引导的批量准备和实时同步需求 |
| 变量映射 | 绑定HR系统同步的`variables`字段 | 确保工作流读取的员工信息与企业HR数据一致 |
| 节点超时时间 | 300-600秒 | 适配单批次入职员工数据的处理时长 |
| 重试次数 | 2次 | 避免临时网络波动导致的工作流执行失败 |
| `nodeId`绑定 | 绑定对应审批节点的`nodeId` | 确保工作流节点执行顺序与入职引导流程一致 |
| 全局变量预设 | 预设工号、部门等固定字段的默认值 | 适配部分未同步的临时数据场景 |

## 容易做错的三处
- 现象：工作流调用返回`Key is error. You need to use the app key rather than the account key`报错，原因：未使用应用级密钥，误用账号密钥发起工作流调用。
- 现象：工作流前端可选择的全局变量数量不足，无法匹配入职信息的全部字段，原因：未在FastGPT后台正确配置`variables`参数的同步字段，导致前端可选变量未完全加载。
- 现象：免登录窗口调用工作流时，API消耗超出预期，原因：未配置工作流的调用权限范围，导致用户调用消耗全局API额度。

## 怎么确认配好了
- 查看工作流的触发配置页面，确认定时触发的时间和事件触发的类型匹配入职引导的流程节点。
- 发起一次测试调用，传入模拟的员工信息，检查工作流输出的字段值是否与传入的`variables`参数一致。
- 核对工作流的节点配置，确认`nodeId`绑定的节点顺序与入职引导的审批、通知流程一致。
- 调用免登录测试链接，检查API消耗记录是否符合单次调用的预期额度。
