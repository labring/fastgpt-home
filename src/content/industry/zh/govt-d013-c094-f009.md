# 新员工入职引导的员工服务台：模型接入与配置

## 这个品类的数据长什么样
新员工入职引导的数据主要来源于企业内部HR系统导出的入职清单、办公系统配置指引文档、合规部门发布的入职流程规范、部门专属的对接人信息表。数据更新节奏随新员工入职批次变动，每批次入职前1至3天更新专属信息，年度合规文档每季度同步更新。文档结构包含结构化字段与非结构化文本，结构化字段包括员工工号、所属部门、对接人姓名、工位编号、入职截止日期，单位分别为字母数字组合、部门全称、中文姓名、字母数字组合、日期格式；非结构化文本包括部门职能介绍、培训课程大纲、系统操作指南。

## 这些特征在「模型接入与配置」这一环带来什么约束
结构化与非结构化混合的数据结构，要求模型接入时需同时支持字段提取与全文检索的组合调用。专属信息的高频更新，要求知识库同步频率需匹配新员工批次的更新节奏，避免返回过期内容。多字段的精准匹配需求，要求配置时需明确参数提取的规则，确保模型能准确关联员工专属信息与对应知识库内容。合规文档的严肃性要求，需限制模型的创作性输出，避免虚构流程或权限信息。

## 配置怎么定
本文配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 新员工入职引导数据包含多份文档，需容纳完整的入职流程、专属信息与合规要求，避免上下文截断 |
| `maxTokens` | `4000–6000 token` | 回答入职相关问题时，需覆盖完整的权限说明、流程步骤与截止日期，确保信息无遗漏 |
| `temperature` | `0.1–0.3` | 入职信息需保持高度准确，降低模型的随机创作性，避免返回与实际不符的内容 |
| `toolChoice` | `auto` | 需自动调用知识库检索最新的入职数据与专属信息，无需手动指定工具 |
| 知识库同步频率 | 每日1次 | 匹配专属信息的更新节奏，确保返回内容始终为最新版本 |

## 容易做错的三处
- 现象：模型未引用指定的新员工入职手册文件，反而返回通用的入职流程内容。原因：未将目标文件加入应用绑定的知识库分组，或未开启强制使用绑定知识库的配置项。
- 现象：部署的重排模型请求无响应，返回500状态码。原因：自定义请求地址未包含完整的API路由路径，或未在配置中填入正确的鉴权令牌。
- 现象：新员工提问后，回答截断了关键的工位分配信息。原因：`maxTokens`设置值过小，无法容纳完整的权限与工位说明内容。

## 怎么确认配好了
- 上传一份包含独有信息的测试入职文档，发起包含该独有信息的提问，确认回答直接引用该文档内的内容。
- 填入测试用的重排模型地址与鉴权信息，发起测试请求，确认返回结果包含重排后的排序标记。
- 调整`temperature`参数至0.2，发起3次相同的入职问题提问，确认回答内容一致无偏差。
- 通过官方API调用接口发起测试请求，确认返回结果符合预设的格式与字段要求。
