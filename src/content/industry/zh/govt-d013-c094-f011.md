# 新员工入职引导的员工服务台：表单与交互
以下内容基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
新员工入职引导的数据源主要来自HR管理系统的员工入职档案、公司统一的入职流程模板与部门专属对接文档。数据更新节奏为入职前1至3天由HR完成批量同步，入职当日若有临时岗位调整、设备申领变更等情况，会触发单次增量更新。文档结构固定分为入职须知、部门对接清单、设备申领表、权限开通流程四个模块，字段包含员工工号、所属部门、入职日期、对接人姓名与工号，其中工号为纯数字串，日期采用YYYY-MM-DD格式。

## 这些特征在「表单与交互」这一环带来什么约束
数据源来自HR系统的结构化数据，要求表单与交互环节优先自动拉取已同步的员工工号、部门等字段，避免新员工重复录入已有信息。数据存在临时增量更新的可能，要求表单支持实时刷新对接人、设备申领项等动态内容，防止出现过时信息。文档结构固定为四个模块，要求表单的交互模块与文档结构一一对应，不得随意调整模块顺序或增减可选字段。字段存在固定格式要求，要求表单内置格式校验规则，拦截不符合规范的输入内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 开启自动填充模式 | 匹配HR系统同步的结构化员工数据，减少重复录入 |
| `formInput` | 绑定HR系统员工档案接口 | 确保自动填充的字段与员工实际入职信息一致 |
| 输入字符上限 | 2000 字符 | 适配入职须知、流程说明类长文本输入的需求 |
| `userSelect` | 开启动态刷新选项 | 适配入职当日临时更新的部门对接人、设备清单 |
| 表单提交超时阈值 | 30 秒 | 适配内网环境下HR系统接口的响应时长 |
| 单次检索上限 | 前5条 | 匹配单轮入职流程指引的信息密度需求 |

## 容易做错的三处
- 现象：表单关联的入职知识库返回空结果，或返回与当前员工无关的文档。原因：未将表单触发的知识库调用限定为专属的新员工入职指南知识库，未通过`userSelect`绑定当前员工的部门标签过滤检索范围。
- 现象：提交表单后仅收到单条静态结果，未展示流式更新的进度提示。原因：未启用交互环节的流式输出配置，未正确处理分块返回的内容。
- 现象：表单中自动填充的员工工号、部门等字段为空。原因：未正确配置`formInput`的数据源绑定规则，未关联HR系统的员工入职档案接口。

## 怎么确认配好了
- 打开表单预览页面，输入测试员工工号，检查是否自动填充所属部门、入职日期等字段。
- 模拟临时修改部门对接人信息，刷新表单页面，检查对接人选项是否同步更新。
- 输入不符合格式的工号（如含字母），检查是否弹出格式错误提示。
- 提交测试表单，检查是否收到流式返回的进度提示，以及最终的流程指引结果。
