# 回访记录摘要的热线知识库与工单辅助：向量模型与索引

## 这个品类的数据长什么样
回访记录摘要的数据来源于国央企、政府及公共服务热线的工单闭环环节，由通话自动转写或人工整理生成。更新节奏随工单完成实时触发，每日可生成数万条规模的批量数据。单条文档结构包含工单唯一标识、回访时间、服务对象信息、沟通核心内容摘要、客户诉求分类五个核心字段，部分记录附带回访时长（单位：秒）、满意度评分等辅助字段，单条内容长度多在300-1200字符之间。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时更新的特性要求向量索引支持增量同步，避免全量重建带来的资源消耗与延迟。多字段结构需明确指定嵌入的核心字段，避免无关元数据干扰语义向量的生成。单条内容长度跨度较大，需适配不同长度的文本分块策略。与工单系统的绑定关系要求向量索引关联工单元数据，确保检索结果可直接关联至对应工单流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配回访记录摘要的常见长度，避免单块内容语义断裂 |
| 重叠长度 | 100–150 字符 | 覆盖分块边界的语义关联，避免关键信息被分割在不同块中 |
| 相似度阈值 | 0.7–0.85 | 匹配热线工单的语义匹配精度需求，过滤低相关性的召回结果 |
| 单次召回上限 | 前 10 条 | 适配工单辅助场景的上下文长度限制，避免过多冗余信息干扰 |
| `maxToken` | 4096 | 适配主流开源嵌入模型的token上限，匹配回访记录摘要的总字符转换需求 |
| `defaultToken` | 按模型默认 | 适配未明确指定token长度的场景，保证基础嵌入功能正常运行 |

## 容易做错的三处
- 索引导入后检索结果为空。原因是未指定回访记录摘要的嵌入字段，仅导入了未生成向量的原始工单元数据。
- 本地部署FastGPT v4.17.0时，模型连通正常但向量生成报错。原因是`maxToken`设置超出本地部署模型的支持上限，或未适配回访记录摘要的实际字符长度。
- 增量索引更新延迟过高。原因是未开启增量索引模式，仍使用全量重建策略处理实时生成的回访记录摘要数据。

## 怎么确认配好了
- 上传单条回访记录摘要至知识库，检查嵌入任务日志无报错，且生成的向量数据可在索引面板中查看。
- 输入回访记录中的核心诉求关键词，检索结果应包含匹配的工单ID与对应摘要内容，且召回条数符合单次召回上限设置。
- 查看索引更新监控，确认每小时生成的回访记录摘要可在10分钟内完成增量索引同步。
- 随机抽取10条回访记录摘要，转换为token数后均不超过`maxToken`配置值，无内容截断情况。
