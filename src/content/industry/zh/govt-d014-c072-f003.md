# 回访记录摘要的热线知识库与工单辅助：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据来源于政务热线、国企客服的通话录音转写文本与工单回访原始记录。更新节奏为单次回访完成后生成对应摘要，按每日工单批次批量同步至知识库。单份文档结构包含通话时段、坐席标识、用户核心诉求、处理进度、回访结论、满意度评分等字段，其中通话时段采用YYYY-MM-DD HH:MM:SS标准时间格式，满意度评分为0至5的整数，坐席标识为字符串类型。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据包含口语化的通话转写内容与多字段结构化信息，对多轮对话与提示词环节带来多重约束。首先，口语化转写存在大量冗余表述，提示词需加入前置规整指令，统一表述格式。其次，单份文档包含多类字段，`messages`参数需限制上下文轮次，避免非核心字段干扰对话逻辑。另外，按批次同步的更新节奏，提示词需限定处理范围为当前工单批次的回访记录，防止跨工单数据混淆；字段的单位差异也需在提示词中明确解析规则，避免参数解析错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages`上下文限制 | 仅保留当前工单的前3轮对话 | 依据回访记录摘要的单份文档内容集中，过多上下文会稀释核心诉求信息 |
| 单次对话token上限 | 8000 token | 依据回访记录摘要的单份文档长度多在1000-3000字符区间，按实测标定 |
| 提示词模板 | 包含「先规整口语化转写内容，再提取核心诉求与结论」的前置指令 | 依据数据来源为通话转写，存在大量口语冗余 |
| `variables`参数 | 绑定当前工单ID与回访日期 | 依据需限定处理范围为当前批次的回访记录，避免跨工单混淆 |
| `chatId`关联规则 | 绑定单条回访记录ID | 依据需保证多轮对话仅针对单份回访记录展开，防止上下文串扰 |
| 问题优化开关 | 开启 | 依据FastGPT v4.17.0的对话模块优化规则，可提升口语化内容的解析精度 |

## 容易做错的三处
- 现象：导入回访记录摘要文档时返回500错误；原因：未按每日批次格式上传单份超长度的文档，导致系统解析超时。
- 现象：工作流中多个AI对话模块执行后，所有模块的输出均被返回；原因：未通过`chatId`绑定单条回访记录，导致上下文未隔离，多轮对话结果叠加。
- 现象：首次调用对话模块时等待3秒以上才返回结果；原因：未限制`messages`的上下文轮次，系统每次都加载全量历史对话数据，导致初始化耗时增加。

## 怎么确认配好了
- 上传单份回访记录摘要文档，确认界面无报错提示。
- 发起多轮对话测试，验证仅返回与当前回访记录相关的内容，无跨工单信息。
- 检查`variables`参数是否绑定了当前工单ID与回访日期，确保处理范围正确。
- 测试首次调用对话模块，确认初始化耗时符合预设的实测标定值。
