# 回访记录摘要的热线知识库与工单辅助：工具调用与插件

## 这个品类的数据长什么样
回访记录摘要的数据来源于热线客服的通话转写文本、工单系统的回访环节填写内容，由客服人员或自动语音系统完成回访后生成。更新节奏为单条回访完成后实时同步至知识库。文档结构包含结构化字段与非结构化文本：结构化字段包括回访ID、回访对象编号、回访时间、回访人员工号；非结构化部分为客户反馈详情、整改诉求及初步处理意见，单条内容长度多在200至1500字符区间，部分内容包含口语化表述。

## 这些特征在「工具调用与插件」这一环带来什么约束
结构化与非结构化混合的文档结构，要求工具调用需同时支持结构化字段提取与非结构化语义解析，插件需预设对应字段的映射规则。实时同步的更新节奏，要求工具调用触发逻辑需绑定回访完成的事件钩子，避免延迟同步导致的工具调用数据过时。单条内容的长度区间，要求工具调用需适配200至1500字符的输入规模，避免超出上下文窗口限制。口语化表述的存在，要求工具调用需具备一定的语义容错能力，避免因表述不规范导致解析失败。数据来源于热线与工单系统，要求插件需对接对应系统的开放接口，需配置对应接口的访问权限与鉴权参数。

## 配置怎么定

| `toolChoice` | `auto` | 适配回访记录摘要的混合内容，自动选择工具调用或文本生成 |
| `functionCall` | 仅调用字段提取与语义解析工具 | 针对回访记录的结构化与非结构化内容，限定工具调用范围 |
| 工具触发时机 | 回访完成后实时触发 | 匹配数据实时同步的更新节奏，避免调用过时数据 |
| 上下文窗口阈值 | 16384 token | 适配单条回访记录摘要的长度区间，避免内容截断 |
| 插件鉴权配置 | 配置工单与热线系统的API密钥与权限范围 | 数据来源于两类系统，需对应接口的访问权限 |
| 工具调用超时时间 | 60 秒 | 适配热线场景的实时性要求，避免过长等待影响工单流转 |

## 容易做错的三处
- 现象：工具调用返回的结构化字段为空，原因：未配置回访记录摘要的字段映射规则，导致插件无法识别需要提取的目标字段。
- 现象：工具调用触发延迟超过2分钟，状态码返回408，原因：工具触发时机设置为定时批量处理，未绑定回访完成的事件钩子，导致调用数据未实时同步。
- 现象：调用外部AI模型生成解析代码时，无法正确匹配回访记录的业务字段，原因：未在插件配置中预设回访记录的字段定义，导致生成的代码与业务场景不匹配。

## 怎么确认配好了
- 手动触发一次工具调用，查看返回结果是否包含预设的回访ID、客户反馈等字段，核对字段映射规则是否生效。
- 模拟回访完成的事件触发工具调用，查看调用耗时是否符合业务实时性要求，核对触发时机配置是否正确。
- 检查插件的鉴权配置项，确认已填写工单与热线系统的对应API密钥，核对接口权限是否覆盖目标数据范围。
- 验证工具调用的返回结果长度与输入的回访记录摘要长度匹配，确认上下文窗口阈值设置符合业务需求。
