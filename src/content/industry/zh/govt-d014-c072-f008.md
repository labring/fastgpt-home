# 回访记录摘要的热线知识库与工单辅助：文档解析与分块

## 这些特征在「文档解析与分块」这一环带来什么约束
单份文档对应单条回访工单，且包含结构化元数据与非结构化摘要混合的结构，要求分块时需保留元数据与对应摘要的关联，避免拆分后丢失上下文关联。字段带有明确单位的结构化内容，需识别字段边界，避免将字段值与单位拆分。非结构化内容为口语化片段，需适配语义边界进行拆分，避免固定字符拆分破坏语义连贯性。更新节奏随工单触发，要求解析流程需适配快速响应的需求，避免过长的解析耗时影响工单处理效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 回访记录摘要的非结构化内容多为口语化对话片段，该区间可保留完整语义单元，避免语义断裂 |
| `chunkSplitter` | 按语义分句 | 适配口语化内容的语义边界，避免按固定字符拆分破坏对话逻辑 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–90 秒 | 单份回访记录摘要解析耗时较短，该区间可覆盖正常解析时长，避免超时失败 |
| `chunkSettingMode` | 手动配置 | 需针对单工单的混合结构调整参数，适配结构化字段与非结构化内容的拆分规则 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 单份回访记录摘要文件体积较小，该上限可满足批量导入需求且避免资源浪费 |

## 容易做错的三处
- 解析后分块结果中结构化字段与非结构化内容被拆分，表现为检索时无法关联对应内容，原因是未配置`chunkSplitter`按语义分句，仅按固定字符拆分破坏了语义关联。
- 配置`trainingType`设置错误导致工具调用未触发，表现为日志显示参数解析成功但无工具执行，原因是未将`trainingType`配置为对应场景的类型，该问题对应社区常见的工具调用异常反馈。
- 上传回访记录摘要文件后解析失败，表现为返回文件无法打开，原因是未开启`customPdfParse`配置，无法识别结构化字段的格式，该问题对应社区常见的文档解析失败反馈。

## 怎么确认配好了
- 上传单份回访记录摘要文档，查看解析后的结构化字段是否完整保留，无拆分丢失。
- 调整`chunkSize`配置后，查看分块结果的语义完整性，确认单块内容无语义断裂。
- 测试单份文档的解析耗时，确认未触发超时报错。
- 批量导入多条回访记录摘要，确认解析任务全部完成，无异常失败记录。
