# 回访记录摘要的热线知识库与工单辅助：模型接入与配置

本文档适用于FastGPT v4.17.0版本的政务热线场景配置。

## 这个品类的数据长什么样
回访记录摘要的数据来源于政务热线、国企服务热线的事后回访录音转写文本，以及关联工单的原始沟通记录。数据随工单流转实时更新，单条文档长度多在300-1500字符之间。文档固定包含回访ID、关联工单编号、沟通起止时间、用户诉求原文、经办人反馈、回访结论六个核心字段，其中沟通时长以秒为单位，诉求分类为标准化枚举项。

## 这些特征在「模型接入与配置」这一环带来什么约束
回访记录摘要的实时更新特性要求模型调用链路支持低延迟响应，避免阻塞工单流转流程。单条文档的字符跨度要求上下文配置需预留足够的窗口空间，防止截断核心沟通内容。标准化枚举字段与自由文本混合的结构，要求模型需同时支持结构化信息提取与非结构化内容摘要，需配置对应参数适配两类任务。沟通时长的秒级单位数据，可作为模型调用时的辅助参考字段，需确保参数配置中允许传入自定义元数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 2000–4000 字符 | 适配单条回访记录摘要的300-1500字符长度，避免截断核心沟通内容 |
| `maxTokens` | 1000–1500 token | 控制摘要输出长度，匹配回访记录的核心信息体量 |
| `temperature` | 0.2–0.4 | 平衡摘要的准确性与灵活性，避免自由文本部分出现冗余或偏离原文 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配代理服务的接入地址，解决跨环境调用问题 |
| `AIPROXY_API_TOKEN` | 与代理服务绑定的密钥 | 确保模型调用的身份验证合规，符合政务场景的安全要求 |
| `toolChoice` | auto | 允许模型自动判断是否需要调用工具关联工单信息，适配多任务场景 |

## 容易做错的三处
- 调用时返回503状态码，提示对应模型无可用渠道。原因是未在代理服务中配置对应模型的接入渠道，或分组设置与FastGPT的默认分组不匹配。
- 模型调用超时，返回请求失败日志。原因是未合理设置`maxContext`参数，导致模型处理过长的回访记录时超出链路超时阈值。
- 输出的摘要内容偏离原文核心诉求。原因是`temperature`参数取值过高，导致模型生成的内容过于发散，未贴合回访记录的原始信息。

## 怎么确认配好了
- 手动输入一条真实的回访记录样本，触发模型调用，检查返回的摘要是否包含原文核心诉求与结论。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置值与部署环境一致，无格式错误。
- 调整`temperature`参数后对比输出结果，确认参数变化对摘要风格的影响符合预期。
- 批量导入不同长度的回访记录，检查模型调用是否均能正常完成，无截断或报错。
