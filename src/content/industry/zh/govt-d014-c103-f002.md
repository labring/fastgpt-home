# 热线知识库维护的热线知识库与工单辅助：向量模型与索引

## 这个品类的数据长什么样
数据主要来源于热线平台历史工单归档、官方政策文件、客服沉淀的常见问答库。更新节奏随政策调整与业务迭代，常规每周同步更新，突发政策发布时实时追加。单条数据为结构化条目，包含问题标题、问题详情、标准答案、工单分类标签、受理部门标识、办结时效要求等字段，部分关联历史工单会附带用户反馈标签。每条数据的核心内容为客服应答的标准化文本，附带业务属性元数据，无冗余非结构化附件。

## 这些特征在「向量模型与索引」这一环带来什么约束
结构化字段多且包含分类、部门等业务元数据，需针对主文本与元数据分别配置向量映射规则，避免元数据干扰语义召回的准确性。更新节奏兼具定期批量与实时追加，要求索引支持增量同步与热更新，避免全量重建索引导致服务中断。单条数据关联历史工单与时效要求，召回时需同时匹配语义相似度与业务分类规则，需调整索引的召回权重分配。部分数据附带用户反馈标签，可用于二次过滤召回结果，需在索引层预留元数据关联字段。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配热线知识库单条内容的平均长度，避免块内语义断裂 |
| 重叠长度 | 100–200 字符 | 保留块间语义衔接，避免跨块问题被拆分丢失上下文 |
| `maxToken` | 8192 token | 适配主流中文向量模型的上下文窗口限制，避免截断核心问答内容 |
| 相似度阈值 | 0.72–0.85 区间 | 过滤低匹配度结果，适配热线问题的语义相似度分布 |
| 单次召回上限 | 前 5 条 | 控制返回结果数量，避免工单辅助时信息过载 |
| `defaultToken` | 按实测标定 | 适配本地部署或第三方API的向量输出维度，确保索引兼容性 |

仅作参考；请以目标 FastGPT 发布版本与部署文档核验。

## 容易做错的三处
- 现象：单条知识库文件长时间处于索引中状态，界面进度无更新。原因：未针对结构化字段配置分块参数，导致分块任务超出系统处理上限。
- 现象：上传本地生成的向量数据后，检索结果与预期偏差明显。原因：本地与服务器使用的向量模型嵌入维度不一致，未做维度对齐处理。
- 现象：单条知识库条目仅生成一组向量，无法关联分类、部门等元数据。原因：未开启多向量映射配置，仅对主问答文本生成向量，未覆盖元数据字段。

## 怎么确认配好了
- 上传单条测试知识库条目，查看分块后的片段数量，匹配配置的分块长度与重叠长度参数。
- 输入模拟热线问题，检索返回结果的相似度得分，调整阈值至符合业务匹配需求的区间。
- 提交增量更新的知识库条目，验证索引是否在合理时间内完成同步，无进度停滞情况。
- 查看向量模型的调用日志，确认返回的嵌入维度与配置的模型参数一致。
