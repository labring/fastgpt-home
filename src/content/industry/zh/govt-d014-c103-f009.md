# 热线知识库维护的热线知识库与工单辅助：模型接入与配置

## 这个品类的数据长什么样
热线知识库维护的数据主要来源于历史热线工单、客服标准话术库、官方政策文件及用户咨询记录。数据更新节奏分为按需更新与定期批量更新，当政策调整、新增服务事项或高频咨询问题变化时触发按需更新，每周或每两周完成一次全量同步。单条数据的文档结构包含问题描述、标准答案、工单分类标签、受理部门、办结时效等字段，字段无统一固定单位，部分字段需匹配行政区域或业务条线的专属编码规则。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源混合的数据结构要求模型接入时支持多格式内容的解析与召回，需适配结构化工单字段与非结构化话术的混合输入。高频更新的特性要求模型调用的上下文同步频率与知识库更新节奏匹配，避免出现内容滞后的情况。丰富的业务字段则要求配置阶段需明确指定需要模型调用的字段范围，防止无关信息干扰模型输出。此外，热线服务的专业术语与口语化结合的特点，要求模型参数需兼顾专业性与沟通亲和力，避免输出过于生硬的官方话术。本页面适配FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 15000–20000 token | 容纳热线多轮对话上下文与召回的多条知识库条目，避免上下文溢出，适配热线服务的长上下文需求 |
| `maxTokens` | 800–1200 token | 控制单轮客服回复的长度，适配热线服务的口语化沟通场景，避免输出过长影响阅读 |
| `quoteMaxToken` | 3000 token | 限制单次召回的知识库内容总长度，确保不超出模型上下文窗口上限，防止内容截断 |
| `toolChoice` | auto | 允许模型自主判断是否调用知识库工具，适配工单分类、问题解答、进度查询等多业务场景 |
| `temperature` | 0.6–0.7 | 平衡回复的专业严谨性与口语化亲和力，符合热线服务的沟通风格，避免输出过于刻板或随意 |
| `AIPROXY_API_ENDPOINT` | 按平台提供的官方接入地址填写 | 匹配模型调用的网络请求路径要求，确保请求可正常送达模型服务 |
| `AIPROXY_API_TOKEN` | 按平台生成的专属令牌填写 | 完成模型调用的身份验证流程，确保服务访问权限合法 |

## 容易做错的三处
- 调用模型时返回`403 该令牌无权使用模型`报错，原因是未在模型平台的令牌配置中添加当前FastGPT所使用的模型权限，或令牌绑定的模型版本与配置不匹配。
- 生成的客服回复超出预设长度，原因是未正确设置`maxTokens`参数，或未通过`quoteMaxToken`限制召回的知识库内容总长度。
- 模型未自动调用知识库完成解答，原因是`toolChoice`参数被固定为`none`，未开启自动工具调用能力。

## 怎么确认配好了
- 在FastGPT的模型测试界面输入一条热线常见问题，核对返回结果是否包含知识库中匹配的内容片段。
- 查看模型调用日志，确认`AIPROXY_API_TOKEN`的验证请求返回200状态码，无权限相关报错。
- 调整`temperature`参数后观察回复风格变化，确认参数配置生效。
- 模拟多轮热线对话场景，检查上下文是否被正确加载，未出现上下文溢出提示。
