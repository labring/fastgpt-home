# 热线知识库维护的热线知识库与工单辅助：知识库检索与召回

## 这个品类的数据长什么样
热线知识库维护的数据主要来源于政务热线的历史办结工单、公开的政务政策文件、标准化常见问题库。数据更新随工单办结归档实时同步增量内容，月度完成全量政策文档的更新校验。单条文档包含诉求标题、详细诉求内容、标准化解决方案、工单分类标签、所属区域字段，部分文档附带政策原文附件，字段均带有明确的业务属性与单位，如办结时长以小时为单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
热线知识库的多源数据特征对检索召回带来多重约束。历史工单的实时增量更新要求检索链路支持增量索引同步，避免新办结工单无法被及时召回。多字段属性如所属区域、工单分类，要求检索支持按业务维度过滤召回结果，缩小匹配范围。部分文档附带长文本政策附件，要求检索链路适配长文本分块后的召回逻辑，避免关键政策内容被截断。标准化的解决方案字段要求召回结果的排序优先匹配诉求的业务相关性，结合文本相似度进行综合排序。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本说明。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 适配热线诉求的模糊匹配需求，过滤低相关性的政策或工单内容 |
| `limit` | 前10条 | 控制单次召回结果数量，避免超出工单辅助的上下文窗口限制 |
| `searchMode` | hybrid | 结合关键词匹配与语义匹配，覆盖政策文本的关键词召回和工单的语义匹配场景 |
| `usingReRank` | 开启 | 对初始召回结果重排序，优先返回与当前诉求匹配度较高的标准化解决方案 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于历史对话优化当前诉求，解决指代消除问题，适配热线对话的上下文依赖 |
| `collectionIds` | 按业务分组配置 | 仅检索对应区域或分类的知识库集合，缩小召回范围，提升匹配效率 |

## 容易做错的三处
- 现象：调用知识库API检索时，结果未关联历史对话上下文，指代模糊无法匹配对应工单。原因：未开启`datasetSearchUsingExtensionQuery`配置，未启用基于历史记录的问题优化逻辑。
- 现象：知识库检索触发后，GPU资源占用无变化，检索超时报错。原因：未正确配置检索节点的硬件调度，或未启用对应算力池的访问权限。
- 现象：修改检索配置后，页面刷新后参数恢复默认值。原因：未保存配置至对应知识库集合，或配置项超出当前版本的合法取值范围。

## 怎么确认配好了
- 发起单条热线诉求测试，检查检索结果是否包含与当前诉求匹配的历史工单或政策内容。
- 开启多轮对话测试，连续发起包含指代的诉求，检查检索结果是否自动关联前序对话内容，解决指代问题。
- 查看检索日志，确认召回结果数量符合配置的`limit`取值，相似度过滤符合预期。
- 检查知识库集合的关联配置，确认`collectionIds`仅包含当前业务分组的文档集合，无冗余检索范围。
