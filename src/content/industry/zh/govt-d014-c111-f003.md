# 答复口径推荐的热线知识库与工单辅助：多轮对话与提示词

## 这个品类的数据长什么样
答复口径推荐的数据来源于政务热线的历史工单归档、官方发布的统一答复口径文档、工单办结后的审核记录。数据更新节奏为每周同步一次，紧急口径随政策调整即时更新。单条数据包含工单分类编码、用户提问原文、标准答复文本、关联业务场景、审核状态字段，每条数据对应一个具体的用户咨询场景。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源于历史工单与官方口径，要求多轮对话需保留当前会话的工单分类、用户追问上下文，避免脱离业务场景推荐不匹配的答复。每周同步的批量数据与即时更新的紧急口径，要求提示词配置中需支持动态拉取最新的口径库，确保会话调用的始终是最新版本的答复内容。工单分类编码字段的存在，要求多轮对话的前置提示词需先完成用户问题的分类匹配，再调用对应分类下的口径数据集进行推荐，提升答复的精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 1200–1800 字符 | 匹配单条热线对话的平均长度，避免截断关键业务信息 |
| 问题优化开关 | 开启 | 针对用户口语化的热线提问，优化为标准化分类匹配的查询语句 |
| 单次召回口径上限 | 前 3 条 | 控制单轮对话返回的口径数量，避免信息过载影响坐席判断 |
| 上下文刷新间隔 | 600 秒 | 适配每周同步的口径更新节奏，定期刷新会话内的可用口径数据集 |
| 分类匹配阈值 | 按实测标定 | 适配不同行业的工单分类体系，确保分类匹配的准确率符合业务要求 |

## 容易做错的三处
- 现象：升级FastGPT v4.17.0后，对话中添加附件时提示`fail to create post presigned url`。原因：未正确配置S3存储的签名有效期参数，导致会话内的附件上传请求无法生成有效签名。
- 现象：AI生成的答复未按指定json格式返回。原因：提示词中未明确指定json格式的输出约束，且未在`variables`中配置格式校验规则。
- 现象：对话中的点赞、点踩操作未触发后续口径的优化调整。原因：未开启会话反馈同步配置，导致用户反馈未同步至口径推荐的训练数据集。

## 怎么确认配好了
- 发起一条模拟热线用户的提问，检查返回的答复口径是否匹配当前会话的工单分类。
- 查看配置页面的上下文刷新间隔参数，确认其与口径库的更新节奏保持一致。
- 触发一次附件上传操作，检查是否能正常生成上传链接并无报错。
- 查看`messages`和`chatId`对应的会话历史记录，确认多轮对话的上下文被正确保留。
