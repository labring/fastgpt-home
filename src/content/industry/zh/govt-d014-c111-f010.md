## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据源包含口语化的用户提问原文与标准化答复，检索时需兼顾语义匹配与关键词精准度，避免仅依赖单一匹配模式导致的漏召回或误匹配。数据更新频率较高，需确保检索环节可实时访问最新的增量数据，避免使用过期的答复口径。文档中包含问题分类字段，可通过分类过滤缩小检索范围，减少无关数据的干扰，但需注意分类字段的一致性，避免因分类标注不统一导致的检索偏差。此外，单条答复内容长度差异较大，需配置合理的召回上限，确保检索结果的总上下文长度适配大模型输入限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 热线问题多为同类场景，该区间可平衡召回完整性与相关性 |
| `limit` | 10 | 工单问题重复率较高，10条结果可覆盖主流答复口径 |
| `searchMode` | vector+keyword | 适配热线口语化问题，兼顾语义匹配与关键词精准度 |
| `usingReRank` | 开启 | 过滤低相关性召回结果，提升推荐口径的准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 对口语化问题进行语义扩展，提升匹配精度 |
| `collectionIds` | 填写专属热线知识库ID | 限定检索边界，避免无关数据干扰检索结果 |

## 容易做错的三处
- 现象：工作流中配置了知识库检索节点，但运行时未触发检索，直接进入纯AI对话。原因：未将检索节点的输出正确接入大模型的上下文输入参数，或节点触发条件设置错误。
- 现象：检索返回的知识库内容中保留了未预期的markdown一级、二级标题格式。原因：导入知识库的原始文档未提前清理格式，或未开启分块环节的格式过滤配置。
- 现象：大模型输出的答复中包含“引用标记：［1］”字样。原因：未在大模型提示词中添加移除引用标识的要求，或检索结果的引用字段未被正确剥离。

## 怎么确认配好了
- 手动输入一条热线常见问题，查看检索结果是否返回匹配的标准答复口径。
- 查看工作流运行日志，确认知识库检索节点被正常触发，且返回了预期数量的结果。
- 检查大模型输出内容，确认未出现未预期的格式标记或引用标识。
- 调整`similarity`或`limit`参数，验证检索结果的相关性或数量是否符合预期调整方向。
