# CDN与边缘加速配置的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自CDN控制台、DNS解析记录、实时访问日志与监控告警系统。日常产出的评审关联文档包括域名接入单、缓存规则配置文件、刷新预热操作记录、故障分析报告。数据更新节奏为每日批量同步或随配置变更实时更新，数据字段包含域名唯一标识、缓存策略参数、边缘节点IP、访问流量统计、告警阈值等，字段单位随属性匹配对应计量标准，无统一固定格式。

## 这些特征在「上下文与 token」这一环带来什么约束
CDN与边缘加速配置的评审需关联多源异构数据，以域名、缓存规则为核心关联维度，容易出现跨文档上下文断裂的问题。日更或实时更新的数据要求上下文同步频率匹配数据更新节奏，避免引用过期的配置或日志信息。单条变更涉及的文档长度差异显著，从短规则条目到长篇幅故障报告不等，token消耗波动明显，需严格控制上下文窗口范围。同时，故障分析中的异常节点信息需精准关联对应域名的上下文，token分配需优先匹配核心业务字段，避免无效数据占用token资源。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配CDN单份变更评审文档的平均总长度，避免超出模型token承载上限 |
| `quoteMaxToken` | 2000–3000 token | 优先分配给缓存规则、访问日志等核心评审字段，确保关键配置信息完整 |
| 上下文同步频率 | 每变更触发同步 | 匹配CDN数据随配置变更实时更新的节奏，避免引用过期的域名或缓存配置 |
| 关联上下文条数上限 | 前3–5条关联记录 | 控制单次评审的总token消耗，避免加载过多非核心历史数据 |
| 上下文匹配权重 | 域名>节点>告警时间 | 基于CDN数据的核心关联维度，优先匹配高权重字段的上下文信息 |

## 容易做错的三处
- 现象：评审时返回token溢出报错，状态码为413。原因：未限制`maxContext`参数的取值范围，加载了过多跨文档的CDN访问日志与故障报告，超出模型token承载上限。
- 现象：评审结果中出现已失效的缓存规则配置。原因：上下文同步周期设置为每日固定同步，未匹配CDN配置实时变更的节奏，导致引用了已更新的旧规则。
- 现象：关联的域名备案信息缺失，评审结果不完整。原因：未设置`quoteMaxToken`参数的合理取值，核心备案字段被非核心的节点流量数据挤占，无法完整加载。

## 怎么确认配好了
- 提交一份真实的CDN变更评审任务，检查上下文关联的缓存规则、访问日志是否与当前变更的域名及配置匹配。
- 查看单次评审的token消耗统计，确认用量未超出预设的`maxContext`参数范围。
- 模拟一次CDN配置变更操作，验证上下文是否随变更实时同步，未出现过期数据。
- 调整关联上下文条数上限，检查评审加载的历史记录数量是否符合预期。
