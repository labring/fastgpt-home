# CDN与边缘加速配置的代码与变更评审辅助：工作流编排
本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据主要来自CDN控制台、DNS解析记录、用户访问日志与监控告警系统。日常产出的文档包括域名接入单、缓存规则配置表、刷新预热操作记录、故障分析报告。数据更新频率为每日同步或随每次配置变更触发更新，字段通常包含域名、缓存规则标识、刷新预热量、告警级别与节点状态等，未包含虚构统计数字或百分比。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源分散，工作流需对接CDN控制台、DNS解析系统与访问日志平台的不同接口，需适配各系统的权限校验与返回格式。数据更新随配置变更触发，要求工作流支持按需执行节点，适配实时同步的需求。日常文档结构化程度不一，域名接入单为半结构化表单，需工作流配置文本提取节点处理非标准化字段。最耗时的域名备案核对、缓存规则调试环节，需工作流串联多步校验节点，减少人工重复操作。公网访问出错后果直接，工作流需配置失败告警与回滚节点，确保异常可及时阻断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 定义全局计数器变量，初始值为0，步长为1次 | 适配CDN变更次数的统计需求 |
| `nodeId` | 绑定对应缓存规则校验节点的唯一标识值 | 确保工作流节点调用的准确性 |
| 文本提取模型 | 选择上下文窗口不小于8000 token的通用大模型 | 适配长格式缓存规则、访问日志的文本提取 |
| 工作流超时阈值 | 设置为300秒 | 适配CDN控制台接口的响应时长 |
| 失败触发动作 | 触发告警并暂停后续节点，告警延迟为60秒 | 防止错误配置影响公网服务 |
| 变量作用域 | 限定为当前工作流实例 | 避免跨工作流的变量冲突 |

## 容易做错的三处
- 现象：工作流文本提取节点的模型选择下拉框无可选选项，无法配置提取规则。原因：未在系统全局配置中绑定对应大模型的API密钥，导致节点无法加载可选模型列表。
- 现象：全局计数器变量在AI响应后未自动更新，数值保持初始值。原因：未在工作流中正确绑定`variables`的更新触发节点，或步长配置未设置为1次。
- 现象：导入外部工作流配置后，中间结果与预期不符，如缓存规则参数丢失。原因：未在`variables`配置中指定变量的作用域，导致跨工作流的变量覆盖。

## 怎么确认配好了
- 手动触发工作流一次，验证文本提取节点能否正确解析缓存规则文档中的域名与规则内容。
- 查看工作流日志，确认全局计数器变量在每次AI响应后按设定步长更新。
- 检查工作流调试面板，确认代码运行节点的`nodeId`配置与实际节点一致，且日志正常显示。
- 模拟配置失败场景，验证工作流会触发告警并暂停后续执行步骤。
