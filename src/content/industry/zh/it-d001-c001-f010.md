# CDN与边缘加速配置的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
通常的日常文档包括域名接入单、缓存规则、刷新预热记录、故障分析报告；数据来源为CDN控制台、DNS解析记录、公网访问日志、节点监控告警；更新频率为每日或每次配置变更后。数据字段包含备案编号、源站IP地址、缓存TTL值、刷新任务ID、访问状态码、带宽阈值等，部分字段带有标准网络运维单位，如秒、Mbps、条。所有数据均围绕公网内容分发与缓存配置展开，与其他云服务品类的数据维度存在差异。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源绑定CDN专属控制台与日志，因此引用溯源的数据源需仅对接CDN相关的API或导出文件，无法直接复用其他云服务的数据源配置。更新频率随变更触发，溯源时需关联变更时间戳，确保引用的是当前生效的配置版本，避免引用过期数据。日常文档包含标准化的运维字段，溯源时需保留字段原始单位与标识，例如缓存TTL的秒数、访问日志的状态码，不能随意转换或省略。数据围绕公网分发场景，引用溯源需关联具体域名与节点信息，确保评审时可定位到对应配置的生效范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | `800–1200 token` | 匹配CDN配置文档的平均长度，避免截断关键参数 |
| `responseData` | `包含控制台日志、刷新记录的完整字段` | 覆盖溯源所需的全部变更与运行数据 |
| `detail` | 开启 | 展示具体的变更节点与时间戳信息 |
| 单次召回上限 | 前6条 | 匹配CDN变更记录的典型展示条数 |
| 上下文时间范围 | `600 秒内的变更记录` | 对齐CDN配置的生效周期 |
| 问题优化配置 | 开启 | 对齐CDN运维的常用评审话术 |

## 容易做错的三处
- 现象：调大`quoteMaxToken`至2000以上后，大模型生成结果无引用来源，仅能召回知识库内容。原因：未同步调整上下文拼接的阈值，导致引用数据超出模型可处理的token上限，无法输出引用标记。
- 现象：本地测试引用正常，但通过外部API调用时无引用内容返回。原因：未在API请求参数中开启`detail`配置，仅返回了摘要结果，未包含溯源所需的详细来源信息。
- 现象：缓存规则变更后，溯源引用的文档与实际变更内容不符。原因：未按变更时间戳筛选数据源，引用了旧版本的缓存规则文档。

## 怎么确认配好了
- 提交包含缓存规则、刷新记录的测试文档，查看生成结果是否附带对应来源的文档ID或任务号。
- 调整`quoteMaxToken`至不同取值，验证引用内容的完整性，确认无关键参数被截断。
- 调用外部API时，检查请求参数是否包含`responseData`和`detail`的开启配置。
- 查看FastGPT v4.17.0的系统日志，确认溯源数据的时间范围与变更记录的更新频率匹配。
