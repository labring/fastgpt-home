# IT服务台工单处理的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据来自企业IT服务台依托的ITSM系统、电话或在线聊天记录、资产系统与内部知识库。日常生成的文档包含服务请求单、事件工单、处理记录、用户满意度表，字段涵盖工单编号、提交时间、问题详情、处置步骤、反馈评分等。数据更新频率为日级或实时，随工单流转、用户反馈同步更新。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类多源异构的数据结构，要求上下文拼接时需先过滤冗余的非技术描述与无效字段，避免无效token占用配额。实时更新的工单流转特性，要求上下文窗口需适配动态流入的工单数据，防止因新数据涌入导致token超限。多类型文档的字段差异，要求在提取上下文时需按工单类型匹配对应字段，避免无关信息混入上下文，影响排障效率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口 | 8000–12000 token | 适配IT服务台工单多字段拼接的内容长度，避免token溢出 |
| 引用最大token | 1500–2000 字符 | 匹配单条工单的问题描述与处理记录的典型长度，精准召回相关内容 |
| 上下文更新频率 | 实时 | 匹配工单实时流转的更新节奏，保证上下文的时效性 |
| 字段过滤规则 | 按实测标定 | 过滤工单中的冗余备注与无关字段，减少无效token占用 |
| 历史工单召回数 | 前3–5 条 | 控制上下文总token消耗，同时覆盖排障所需的典型历史参考信息 |

## 容易做错的三处
- 现象：工作流编排多AI模型对话时触发token超限报错。原因：未配置独立的上下文隔离规则，多模型共享全局token配额，超出预设的token上限。
- 现象：无网络环境下启动上下文关联服务时出现FATAL级报错。原因：未启用离线上下文缓存模式，依赖网络的token统计模块无法正常加载。
- 现象：工单上下文召回的字段与预期不符，包含大量冗余内容。原因：未配置字段过滤规则，直接拼接了工单中的所有非必要字段，导致无效token占用过多。

## 怎么确认配好了
- 查看工单处理的上下文预览界面，确认召回的内容与当前工单的问题描述、历史处理记录匹配。
- 模拟多模型编排场景，检查每个模型的token消耗统计是否独立，无跨模型配额共享。
- 测试无网络环境下的上下文加载，确认服务可正常启动且无FATAL级报错。
- 调整字段过滤规则后，对比过滤前后的上下文token消耗数据，确认过滤生效。
