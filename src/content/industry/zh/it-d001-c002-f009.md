# IT服务台工单处理的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源于企业ITSM系统、电话或聊天交互记录、资产台账系统与内部知识库。日常生成的文档包含服务请求单、事件工单、处理记录、用户满意度表，核心字段包括工单唯一标识、提交人信息、问题描述、分类标签、处理状态、耗时记录与满意度评分。数据更新节奏为日级或实时，随工单流转、处理进度同步更新。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据来源分散且更新节奏灵活，要求工具调用环节需适配多格式数据源，包括结构化的ITSM工单字段、非结构化的聊天记录文本。实时或日级更新的数据需要工具支持增量拉取与同步，避免处理过时工单。多字段的文档结构要求工具能精准提取指定字段用于代码与变更评审，同时统一受理的入口属性需要工具支持多渠道工单的聚合调用。此外，出错会导致SLA超时或员工办公中断，要求工具调用的稳定性与容错机制需匹配业务优先级。

## 配置怎么定
以下配置说明基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配IT服务台工单的多样化评审需求，自动匹配代码与变更相关工具 |
| 工具调用超时时间 | 600 秒 | 匹配IT服务台工单的SLA要求，避免长时间等待导致流程中断 |
| `functionCall` | 开启强制函数调用 | 确保工具调用严格按照预设的代码与变更评审逻辑执行 |
| 单工具调用文件上限 | 1000 MB | 适配工单中可能附带的代码包、变更文档的常见大小 |
| 工具调用重试次数 | 3 次 | 应对网络波动或工具临时不可用的情况，保障处理连续性 |
| 结果缓存时长 | 30 分钟 | 匹配IT服务台工单的实时处理节奏，避免使用过时的评审数据 |

## 容易做错的三处
- 现象：工具调用时返回408状态码，或工单处理超时提示。原因：未调整工具调用超时时间，默认超时时长无法匹配IT服务台工单的复杂评审流程。
- 现象：上传代码包或变更文档时提示文件大小超限。原因：未配置单工具调用文件上限，默认限制与工单附带的大文件不匹配。
- 现象：自定义工作流工具调用时，无法提取工单中的变量参数，仅支持传入固定链接。原因：未正确绑定工单字段与工具调用参数，导致变量引用失效。

## 怎么确认配好了
- 登录FastGPT后台，进入对应工作流的工具调用配置页面，检查`toolChoice`与`functionCall`的配置是否与预设要求一致。
- 发起模拟工单调用，验证工具调用的超时、重试等配置是否按预期触发，观察返回结果是否符合业务逻辑。
- 上传不同大小的测试文件，确认工具调用的文件上限配置是否生效，无异常报错。
- 查看工具调用日志，核对提取的工单字段是否与预设的变量绑定关系一致。
