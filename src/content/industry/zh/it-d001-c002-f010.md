# IT服务台工单处理的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来源于企业ITSM系统、电话或在线聊天记录、资产系统及内部知识库。日常生成的文档包括服务请求单、事件工单、处理记录、用户满意度表。数据更新节奏为日级或实时，单条数据包含工单唯一标识、提交人信息、问题描述、处理流程记录、满意度反馈等字段，字段随工单具体类型存在差异，无统一固定单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据来源分散且包含非结构化的聊天记录，要求引用溯源环节可关联多类型来源的信息片段。工单数据实时或日级更新，需确保溯源时引用的知识库内容与当前处理节点的最新版本一致。服务请求单、处理记录等文档结构差异显著，需支持按工单专属字段精准匹配引用来源。此外，工单处理的时效性要求，需避免溯源环节拖慢整体响应节奏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 该品类工单包含较多技术细节与流程记录，需保留足够的引用片段长度，避免截断关键排障信息，适配FastGPT v4.17.0版本的接口逻辑 |
| `responseData` | 包含引用元数据的完整格式 | 需返回知识库引用的来源标识，用于关联工单与对应知识库条目，实现精准溯源 |
| `detail` | true | 需获取详细的引用来源信息，包括条目更新时间、关联字段等，用于验证引用准确性 |
| 单次搜索上限 | 前5条 | 匹配IT服务台工单问题的核心知识库条目通常集中在前序搜索结果，避免冗余信息干扰 |
| 引用缓存时长 | 24 小时 | 适配该品类日级更新的数据同步节奏，平衡溯源准确性与处理效率 |
| 超时阈值 | 60 秒 | 避免溯源环节拖慢工单处理节奏，符合日常处理的时效要求 |

## 容易做错的三处
- 现象：调用对话接口时未返回任何知识库引用的标识信息。原因：未将`responseData`配置为包含引用元数据的完整格式，或未将`detail`设置为true，导致溯源所需的关键字段缺失。
- 现象：返回的引用来源条数与预期不符，过多或过少。原因：`quoteMaxToken`设置不合理，或单次搜索上限未匹配IT服务台工单问题的核心引用条目分布规律。
- 现象：解析`detail`参数返回的内容时，无法关联到对应工单的处理记录。原因：未将知识库引用的元数据与工单的专属字段进行匹配配置，导致溯源关联失效。

## 怎么确认配好了
- 发起一条贴合IT服务台排障场景的测试查询，核对返回结果中是否包含`responseData`字段及引用元数据。
- 调整`quoteMaxToken`的取值后，对比多组测试查询的引用结果，确认符合当前场景的信息完整性需求。
- 确认`detail`参数设置为true，查看接口返回的详细数据，确认包含所需的引用来源信息。
- 模拟工单数据更新的场景，验证引用的知识库条目是否能同步更新相关内容。
