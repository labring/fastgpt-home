# IT资产盘点的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
本品类聚焦IT资产盘点的代码与变更评审辅助场景，数据来源为资产管理系统、采购系统、财务固定资产模块、终端管理平台，更新频率为月、季或年。日常处理的文档包括资产台账、盘点表、领用归还单、报废申请，数据字段包含资产编号、名称、权属归属、存放位置、使用人信息与资产状态标识，无额外定制化统计字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的代码与变更评审辅助场景下，数据特征对多轮对话与提示词配置带来多重约束。多源数据来源导致字段格式不统一，多轮对话需先完成跨系统字段对齐，提示词需明确指定字段映射规则。低更新频率要求多轮对话支持跨周期历史数据对比，提示词需限定仅调用指定周期内的最新数据。多样的日常文档格式需要多轮对话支持不同文档的解析规则切换，提示词需明确每种文档的解析优先级。高风险的出错后果要求多轮对话增加校验环节，提示词需清晰定义错误触发与修正引导逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 每次会话生成唯一标识 | 用于关联IT资产盘点的多轮对话上下文，避免跨会话数据混淆，适配FastGPT v4.17.0的会话管理逻辑 |
| 最大上下文 | `8000–12000 token` | 覆盖月度盘点数据的完整字段内容，避免上下文溢出导致信息丢失，适配代码评审的长上下文需求 |
| `messages` | 保留最近 10 轮对话内容 | 匹配资产盘点的分步核对与代码变更评审流程，减少冗余上下文占用，提升对话响应速度 |
| 单次召回上限 | 前 3 条 | 聚焦核心资产数据与变更相关代码片段，避免无关信息干扰评审逻辑 |
| `variables` | 预设资产字段映射变量 | 统一多源系统的字段格式，降低提示词编写复杂度，适配不同来源的资产数据与代码变更规则 |
| 会话超时 | `600 秒` | 覆盖跨系统数据拉取、账实核对与代码评审的完整流程时长，避免中途中断导致数据丢失 |

## 容易做错的三处
- 现象：调用时弹出“使用了错误的API Key”提示，原因：误用全局通用API Key发起对话请求，未使用应用专属密钥。
- 现象：多轮对话返回的资产数据字段缺失，原因：未在`variables`中配置跨系统字段映射规则，导致提示词无法统一不同来源的资产数据格式。
- 现象：对话框抛出“Cannot read properties of null (reading 'q)”报错，原因：首次会话未正确初始化`messages`上下文数组，导致系统提示词未被正常加载。

## 怎么确认配好了
- 发起首次资产盘点相关代码变更查询，确认会话自动生成唯一`chatId`，且上下文关联正常。
- 进行多轮账实核对与代码评审对话，确认对话历史按配置保留指定轮次的内容，无冗余信息干扰。
- 上传不同来源的资产文档与代码片段，确认字段解析符合预设的`variables`映射规则，格式统一。
- 模拟长耗时的资产核对与代码评审流程，确认会话超时设置符合实际业务时长，无异常报错。
