# IT资产盘点的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
IT资产盘点的数据来源于资产管理系统、采购系统、财务固定资产模块、终端管理平台四类系统。日常产出资产台账、盘点表、领用归还单、报废申请四类文档，核心字段包含资产编号、使用人、存放位置、权属状态、采购日期，单位以台、套、件为主。数据更新频率匹配盘点周期，按月、季或年进行批量更新，单次更新覆盖全量或指定范围的资产条目。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据接入要求工作流需配置多个跨系统拉取节点，确保不同来源的资产数据统一对齐。低更新频率决定工作流触发时机需匹配盘点周期，避免高频无效执行。多字段的文档结构要求`variables`需精准定义资产相关参数，保障跨节点数据传递的准确性。账实核对、使用人确认等耗时环节，需在工作流中插入人工审核节点，降低出错概率。资产流失、审计问题等严重出错后果，要求工作流配置失败告警与重试机制，保障执行稳定性。

## 配置怎么定
本文适用于FastGPT v4.17.0及以上版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 定义资产编号、使用人、存放位置字段 | 匹配资产台账的标准字段结构，确保跨节点数据传递准确 |
| 工作流触发时机 | 按盘点周期（月/季/年）触发 | 匹配数据更新频率，避免无效执行 |
| HTTP请求超时 | 600–1200 秒 | 适配多系统数据拉取的耗时，解决默认超时过短的问题 |
| 分支执行规则 | 单分支串行执行 | 避免工具调用同时触发多分支的执行冲突 |
| 循环嵌套配置 | 允许嵌套HTTP请求节点 | 支持批量处理多台资产的盘点数据 |
| 失败重试 | 重试2次，间隔30秒 | 应对系统接口波动，提升执行稳定性 |

## 容易做错的三处
- 工作流中嵌套知识库助手调用时，API返回空值。原因是未在`variables`中配置正确的资产相关参数，导致知识库助手无法获取有效检索上下文。
- 知识库变量引用时出现`quote type error`报错。原因是传入的变量格式不符合要求，未按资产台账的字段类型传递数据，比如将数字类型的资产编号传入字符串格式。
- 工具调用模块同时打印AI回复并执行下一级分支。原因是未配置分支执行规则为串行触发，导致多分支并行执行。

## 怎么确认配好了
- 触发测试工作流，查看`variables`参数是否正确传递资产台账的字段值，无格式报错。
- 调用工作流API，检查返回结果是否包含预期的资产盘点数据，无空值返回。
- 模拟系统接口超时场景，确认工作流触发失败重试机制，重试次数符合配置要求。
- 调整分支执行规则，验证工具调用后仅执行指定的下一级分支，无并行执行情况。
