# IT采购与供应商管理的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据主要来自采购系统、供应商报价、预算表、合同系统。日常处理的文档包括采购申请、比价记录、合同、验收单，各文档包含采购项、预算额度、供应商资质、到货数量、验收结果等字段，单位涉及元、台、份等。数据更新以单采购单为周期，每完成一单更新一次相关记录，月度内的采购单数据不会频繁变动。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散，多轮对话需要关联不同系统的采购申请、比价记录等上下文，因此需要支持跨文档的上下文调用。数据更新以单采购单为周期，会话需要按采购单隔离，避免不同订单的上下文混淆。各文档有固定字段结构，提示词需要明确指定对应字段的校验规则，避免模型输出偏离业务要求。同时，月度更新频率意味着对话上下文无需过长，但需要准确绑定当前采购单的专属数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 对话上下文窗口大小 | 10000–15000 token | 适配单采购单相关文档的总长度，避免上下文溢出 |
| 会话隔离规则 | 按`chatId`绑定采购单ID | 确保每个采购单的对话历史独立，防止数据混淆 |
| 提示词变量绑定 | 启用`variables`参数 | 动态插入采购单编号、供应商名称等专属字段，提升提示词精准度 |
| 消息历史存储配置 | 存储完整`messages`数组 | 保留完整对话历史以便回溯采购评审过程 |
| 消息历史保留上限 | 前 20 条对话 | 匹配单采购单评审的常规对话轮次，避免冗余内容占用上下文 |
| 文件上传格式限制 | 支持PDF、DOCX、XLSX | 覆盖日常采购类文档的主流格式，减少解析失败概率 |
| 对话超时时间 | 600 秒 | 适配采购评审的常规对话时长，避免中途断开 |

## 容易做错的三处
- 现象：上传采购类文档后无法正常解析。原因：未配置允许的文件格式，仅开放了非日常采购文档的格式。
- 现象：不同采购单的对话历史互相可见。原因：未正确配置`chatId`的隔离规则，未按采购单ID绑定会话。
- 现象：模型响应无流式输出，仅在完成后一次性返回。原因：未开启流式输出配置，或使用的模型未适配流式返回逻辑。

## 怎么确认配好了
- 上传采购申请、比价记录等日常文档，验证是否能成功解析并纳入对话上下文。
- 创建两个不同采购单的会话，发起相同的字段校验请求，验证各自的对话历史不会互相显示。
- 发起包含特定字段校验的提示词请求，检查输出是否严格遵循预设的格式和字段要求。
- 发起超过10轮的长对话测试，验证上下文窗口不会因内容过长导致截断或报错。
