# Issue分拣与响应的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自GitHub或Gitee Issue、代码仓库版本日志、用户提交的环境信息与问题复现说明。日常维护的文档包含Issue提交模板、标签分类规则、历史回复记录与标准化问题说明。数据更新频率为日或周，核心字段包括Issue编号、关联代码模块、优先级标签、复现步骤与响应状态，仅包含与问题分拣、响应相关的结构化与非结构化内容。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源分散于代码仓库与第三方平台，要求工作流配置支持跨源数据拉取节点，适配不同数据源的接入格式。数据更新频率存在日或周的差异，要求工作流可配置灵活的轮询间隔或触发机制，匹配不同数据源的同步节奏。字段的非标准化特征要求工作流内置格式校验与标准化转换环节，确保分拣规则的一致性。Issue的实时响应需求要求工作流支持触发式执行，避免固定周期轮询带来的延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 轮询间隔 | 600–1800 秒 | 适配日更或周更的Issue数据源，避免频繁拉取占用系统资源 |
| 单次拉取上限 | 前 20 条 | 适配单批次Issue的处理规模，避免节点过载 |
| 超时阈值 | 300 秒 | 适配工具调用的平均响应时长，避免流程阻塞 |
| 上下文窗口 | 8000 token | 适配Issue内容的平均长度，避免超出模型处理上限 |
| 触发条件 | 按新Issue创建事件 | 匹配实时响应需求，减少无效的轮询执行 |
| 变量绑定 | `variables` 绑定Issue标签字段 | 直接调用已预设的标签规则，无需重复配置分类逻辑 |
| 节点ID配置 | `nodeId` 绑定分拣核心节点 | 精准控制工作流的执行路径与分支跳转 |
| 格式校验阈值 | 按实测标定 | 适配不同项目的Issue模板差异，避免误判问题分类 |
| 日志输出级别 | 详细模式 | 便于排查工具调用或节点运行异常 |

## 容易做错的三处
- 现象：工具调用节点返回Invalid JSON: Bad control chara报错。原因：未对拉取的Issue内容中的特殊字符做转义处理，导致生成的调用参数JSON格式非法。
- 现象：工作流编辑界面中工具调用节点无连接小圆圈，无法拖拽创建连接线。原因：节点配置未完成必填项校验，或未在FastGPT v4.17.0及以上版本使用该功能。
- 现象：无法查看工作流中MCP服务的详细运行日志。原因：未将日志输出级别配置为详细模式，或未开启对应节点的日志采集功能。

## 怎么确认配好了
- 手动提交一条符合项目模板的测试Issue，检查工作流是否自动触发分拣与响应流程。
- 查看工作流运行日志，确认`variables`绑定的Issue字段已正确传入对应节点，且无Invalid JSON类报错。
- 检查节点连接线是否正常显示，确认`nodeId`配置已生效。
- 在对应节点的高级配置区域查看模型ID信息，确认已绑定正确的服务节点。
- 查看MCP服务的详细日志，确认日志输出级别已配置为详细模式。
