# Pull Request评审的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据主要来自代码仓库、CI流水线、关联Issue链接与贡献者提交记录。日常流转的文档包含PR说明、代码评审意见、CI执行结果与合并记录。数据更新频率通常为日或周，核心字段包含PR编号、变更文件清单、代码diff片段、CI通过率、评审意见条目与合并状态标识。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据分散来自代码仓库、CI流水线等多源渠道，且更新频率为日或周，因此多轮对话需按`messages`的交互轮次逐步拼接异构上下文，避免一次性加载冗余数据。文档包含代码diff、CI结果等不同格式内容，提示词需明确区分代码变更校验与自动化结果核查的逻辑分支。关联的Issue与合并记录需通过`variables`传入固定上下文参数，确保每轮对话能匹配对应PR的关联信息，同时限制历史对话轮次以适配数据更新节奏。FastGPT v4.17.0版本支持该类上下文的精准拼接配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定PR唯一编号 | 确保每轮对话关联固定PR的上下文，避免会话混淆 |
| `messages` | 保留最近3轮对话，最长不超过8000 token | 适配PR数据的日/周更新节奏，避免加载过期或冗余的评审历史 |
| `variables` | 传入PR编号、变更文件列表、CI状态 | 快速注入PR核心元数据，减少重复拉取仓库信息的开销 |
| 最大上下文轮次 | 按实测标定 | 适配不同规模PR的上下文长度，避免超出模型处理上限 |
| 提示词模板 | 按PR评审场景定制 | 匹配代码diff、CI结果的异构数据校验逻辑 |

## 容易做错的三处
- 对话返回400 invalid image错误，且日志显示图片参数异常。未过滤PR中关联的非文本资源，将图片链接直接传入`messages`导致模型接口校验失败。
- 对接外部对话界面后仅能触发首轮对话，后续交互无响应。未正确绑定`chatId`与外部会话标识，导致每轮对话生成新会话上下文。
- 配置本地模型后自动切换为公开模型，无法正常调用。未通过`variables`锁定模型调用参数，导致平台默认加载预设模型。

## 怎么确认配好了
- 发起首轮PR评审对话，检查`chatId`是否与当前PR编号一致，确保会话绑定正确。
- 输入代码变更相关问题，查看返回内容是否包含传入的`variables`元数据，验证上下文注入生效。
- 测试多轮交互，确认`messages`历史轮次未超出预设限制，无冗余旧数据干扰。
- 触发包含图片链接的测试请求，确认非文本资源被过滤，无接口报错。
