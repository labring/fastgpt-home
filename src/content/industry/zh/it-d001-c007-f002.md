# SLA与服务报告的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本品类数据来源于监控系统、工单系统、服务合同及客户沟通记录，更新周期为月度或季度。日常产出的文档包含SLA条款文本、月度服务报告、可用性统计报表、客户复盘纪要。数据字段覆盖服务周期范围、SLA指标完成情况、异常事件关联信息、合同约定的服务标准，无固定统一的单位，随具体统计项适配。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类的数据来源分散，需整合多系统的非结构化文本与格式化文档，会增加上下文拼接的token消耗。数据更新周期为月度或季度，单次汇总的内容总量随周期递增，需限制上下文加载的token上限以避免资源溢出。文档包含SLA条款、复盘纪要等不同格式内容，需区分不同类型文本的token分配规则。字段无统一单位，需在上下文加载时保留原始字段标识，避免无效token占用。

## 配置怎么定
FastGPT v4.17.0 版本下的上下文与token配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配月度汇总报告的文本总量，避免单次加载超出模型上下文限额 |
| `quoteMaxToken` | 1500–2000 token | 限制从SLA条款、合同文本中提取的引用片段长度，平衡信息完整性与token消耗 |
| 上下文刷新周期 | 按月度更新周期标定 | 匹配本品类数据的更新节奏，避免重复加载旧数据占用token |
| 多源文档合并 | 开启 | 整合分散来源的工单、监控数据，减少重复配置的token开销 |
| 上下文清理触发 | 按报告生成周期触发 | 避免历史上下文残留导致的token超额占用 |

## 容易做错的三处
- 现象：界面提示上下文token超限，任务状态显示失败。原因：未根据月度汇总数据的实际总量调整`maxContext`参数，导致加载内容超过预设上限。
- 现象：生成的服务报告中残留历史季度的SLA数据，字段重复出现。原因：未设置上下文刷新周期，保留了过期的历史文档片段，额外占用token资源。
- 现象：合并后的文档中混入非本周期的监控数据片段。原因：未开启多源文档合并配置，导致分散的历史数据被加载，打乱上下文的有效范围。

## 怎么确认配好了
- 查看上下文加载日志，确认加载的文档均为本周期内的SLA条款、月度报告等数据，无过期内容。
- 触发一次测试任务，查看token消耗统计，验证是否符合`maxContext`的预设取值范围。
- 检查生成的服务报告，确认无重复的历史数据片段，字段与当前周期的统计项匹配。
- 进入配置界面，确认上下文刷新阈值的设置匹配月度或季度的更新周期。
