# 专题活动运营的代码与变更评审辅助：工具调用与插件

以下配置基于 FastGPT v4.17.0 版本制定。

## 这个品类的数据长什么样
专题活动运营的数据主要来自内容库、活动后台、流量数据平台及用户反馈。日常产出的文档包含活动方案、资源位排期表、活动页面文案、复盘报告四类，字段包含活动周期（单位：天）、资源位数量（单位：个）、文案字符数、流量统计数值等。数据更新节奏以周为单位，节假日前后会根据活动节奏临时调整更新频率，部分临时活动的文档会在活动结束后归档。

## 这些特征在「工具调用与插件」这一环带来什么约束
专题活动运营的数据分散在多个平台，且更新节奏灵活，要求工具调用需支持跨数据源同步读取，同时需适配临时更新的内容。活动类文档包含明确的周期、资源位等结构化字段，工具调用需精准匹配字段维度，避免混淆跨活动的数据。活动文案存在字符长度限制，工具处理时需适配不同长度的文本输入，同时复盘报告的历史数据需支持批量对比调用，确保评审内容的全面性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` 或 `二选一模式` | 适配专题活动运营需灵活选择工具的场景，支持自动匹配或强制调用指定工具 |
| `functionCall` | `开启` | 支持自定义工具的思考输出，适配多应用调用需求 |
| 工具调用超时时间 | `300-600 秒` | 活动数据分散在多个平台，需预留足够时间完成跨数据源拉取 |
| 上下文窗口长度 | `8000-12000 token` | 活动方案与复盘报告的文本长度较长，需适配长文本处理需求 |
| 结果返回条数 | `前 3-5 条` | 活动相关数据需精准匹配，避免冗余信息干扰评审判断 |
| 自定义工具触发条件 | `按活动周期触发` | 活动数据随周期更新，需匹配活动节奏触发工具调用 |

## 容易做错的三处
- 现象为自定义工具被其他应用调用时，仅返回工具执行结果，无AI思考过程。原因：未开启`functionCall`配置，仅配置了工具执行参数。
- 现象为工具选择环节出现并发调用，同一活动的资源位数据被多次拉取。原因：`toolChoice`未设置二选一限制，默认开启多工具并行调用。
- 现象为通过API调用读取活动文档时，返回内容为空或无法匹配活动字段。原因：未配置数据源与活动字段的映射规则，或超时时间设置过短导致拉取失败。

## 怎么确认配好了
- 发起一次活动文案的工具调用请求，检查返回结果是否包含AI思考过程与工具执行结果。
- 模拟同一活动的两次工具调用请求，确认仅触发一次工具执行，无并发情况。
- 调用API拉取活动文档数据，检查返回内容是否包含活动周期、资源位等预期字段。
- 更换大模型配置，确认工具调用链路无异常报错。
