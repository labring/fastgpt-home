# 个人信息保护合规的代码与变更评审辅助：上下文与 token
本文适用于 FastGPT v4.17.0。

## 这个品类的数据长什么样
这个品类的数据来自业务系统、App权限清单、隐私政策、用户请求记录，更新频率为季或每产品变更。日常使用的文档包括个人信息清单、处理规则、影响评估报告、用户授权文本，文档字段包含个人信息类型、处理目的、存储期限、合法性基础等，不同文档的结构与字段优先级存在差异，例如个人信息清单侧重字段完整性，影响评估报告侧重场景关联性。

## 这些特征在「上下文与 token」这一环带来什么约束
多来源的合规数据要求上下文召回需覆盖不同系统与文档类型，避免遗漏关键合规条目；动态的更新节奏要求上下文窗口需适配文档长度变化，不能固定为单一值；多样的文档结构要求token分配需区分字段优先级，优先保留核心合规内容；个人信息的敏感性要求上下文筛选需排除非必要的敏感字段，防止token溢出时泄露敏感信息。需合理设置`maxContext`与`quoteMaxToken`等参数，平衡上下文召回与token消耗，同时需匹配合规数据的更新节奏调整上下文更新触发条件。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| maxContext | 12000–15000 token | 覆盖个人信息清单、处理规则等多份合规文档的总token需求，适配通用大模型的上下文窗口 |
| quoteMaxToken | 2000 token per document | 限制单份合规文档片段的token占用，避免大量文档同时召回导致上下文过载 |
| 上下文召回条数 | 前5条 | 平衡合规文档的召回精度与token消耗，匹配合规数据的更新频率 |
| 上下文更新触发条件 | 产品变更或季度节点 | 贴合合规数据的更新节奏，减少无效的上下文刷新与token消耗 |
| token溢出处理策略 | 保留最新的3条核心文档 | 优先保障最新的授权文本、影响评估报告等核心合规内容的上下文有效性 |

## 容易做错的三处
- 配置初始化root密码时出现提示错误。原因是未正确匹配docker-compose.yml中的INITIAL_ROOT环境变量值，导致配置不一致。
- 私有化部署时无法通过`/fastgpt`路径访问应用上下文。原因是未在反向代理配置中正确绑定上下文路径，导致请求路由错误。
- 模型token消耗超出预期，出现token溢出报错。原因是未设置`quoteMaxToken`限制单份文档的token占用，导致大量合规文档片段被同时召回。

## 怎么确认配好了
- 上传一份标准的个人信息清单文档，验证上下文召回模块能否正确提取文档中的核心合规字段。
- 触发一次代码变更评审流程，检查上下文窗口中是否包含最新的合规处理规则与授权文本。
- 查看模型调用日志，确认单次请求的token消耗符合预设的上下文窗口限制。
- 测试私有化部署的访问路径，确认应用可通过指定的上下文路径正常加载配置页面。
