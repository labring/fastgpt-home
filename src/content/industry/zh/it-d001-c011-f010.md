# 云主机交付与资源开通的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自云管理平台、订单系统、IAM权限系统与计费系统，更新节奏为每单实时同步。日常产出的核心文档包括资源开通单、实例配置表、账号权限单与交付确认单，字段覆盖实例规格、可用区范围、IAM权限组配置、计费周期等，其中规格字段以vCPU核数、GB内存为单位，权限单会标注账号绑定的资源范围，交付确认单包含客户验收的节点信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于该品类的数据分散在多个独立系统中，引用溯源环节需要关联云管理平台的实例信息、订单系统的交付记录与IAM系统的权限配置，确保评审的代码变更与实际资源配置完全对应。不同于云网络与负载均衡配置类场景，该品类的溯源需同时关联计算、权限、计费三类系统数据。实时更新的特性要求溯源逻辑在评审触发时同步拉取最新数据，避免出现配置与单据不一致的情况。多字段的文档结构要求溯源时精准匹配规格、权限、计费等核心字段，防止因字段错位导致评审失效。同时，不同单据的格式差异需要统一映射规则，确保引用的来源信息可被快速识别，减少评审过程的信息偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配云主机交付类单据的平均文本长度，避免截断核心配置字段 |
| `responseData` | 仅返回关联业务字段 | 过滤非业务关联的系统日志信息，聚焦资源开通单、实例配置表的核心内容 |
| `detail` | 开启完整字段展示 | 覆盖实例规格、权限组配置、计费周期等评审必需的细节 |
| 引用匹配上限 | 前 3 条结果 | 适配云主机交付单的高频关联数量，兼顾准确率与评审效率 |
| 数据拉取超时 | 600 秒 | 适配多系统数据同步的平均耗时，避免评审过程出现超时报错 |
| 字段映射规则 | 按业务单据类型映射 | 统一资源开通单、权限单的字段格式，确保溯源信息可被快速识别 |

## 容易做错的三处
- 评审结果中附带冗余的系统内部日志链接。原因是未正确配置`responseData`参数，未过滤非业务关联的系统数据。
- 回复中附带无法关闭的引用链接列表。原因是未正确配置`detail`参数，强制展示了所有关联单据的完整路径，未调整自动附加引用的默认设置。
- 评审过程出现超时报错。原因是数据拉取超时配置设置过短，未适配多系统同步的平均耗时。

## 怎么确认配好了
- 上传一份标准的云主机资源开通单，触发评审流程，检查返回的引用内容仅包含业务核心字段。
- 查看评审结果的引用溯源部分，确认关联的实例规格、权限组信息与原始单据完全一致。
- 等待评审流程完成，确认未出现超时报错，检查`quoteMaxToken`参数未截断核心配置文本。
- 在FastGPT v4.17.0版本的配置界面中，确认字段映射规则已按业务单据类型完成设置。
