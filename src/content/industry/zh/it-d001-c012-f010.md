# 云网络与负载均衡配置的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据主要来自云平台控制台、网络拓扑图、流量监控报表与客户架构设计文档，日常维护的文档包括VPC规划方案、安全组规则清单、负载均衡配置文件与变更审批单。数据更新频率随单次变更流程而定，每完成一次配置调整或变更审批就会生成新的版本。数据字段包含网段范围、端口映射规则、健康检查阈值、后端服务器组配置等，无统一固定单位，需根据具体配置项匹配对应参数。

## 这些特征在「引用来源与溯源」这一环带来什么约束
云网络与负载均衡配置的数据更新频繁且随变更流程动态生成，要求引用溯源必须绑定最新的变更版本与审批记录，避免引用过时的配置内容。数据来源分散于多个控制台与文档系统，需要统一的关联机制将不同来源的配置条目关联到同一评审任务。字段类型多样且无固定单位，要求引用时需精准匹配字段名称与配置内容，不能泛泛关联。同时配置错误会直接影响网络连通性，要求溯源环节必须保留完整的引用来源与修改轨迹，便于事后排查。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大引用Token数 | 800–1200 token | 匹配单条云网络配置文档的平均长度，避免截断关键规则或字段 |
| 返回数据格式 | 仅返回原文片段 | 确保引用内容为原始配置文档，不添加模型加工后的改写内容 |
| 详细元信息开关 | 开启 | 保留配置的变更编号、更新时间与所属变更单信息，便于溯源时关联审批记录 |
| 单次引用上限 | 前5条 | 匹配单次变更评审的常规配置条目数量，避免信息过载影响评审效率 |
| 引用匹配阈值 | 0.85 | 按实测标定，确保匹配的配置内容与评审需求高度相关，减少无效引用 |

## 容易做错的三处
- 评审结果中出现红色报错提示，提示引用来源无效。排查项：未正确配置`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）或`AIPROXY_API_TOKEN`（AI Proxy管理员Token）服务端环境变量，会导致App/Admin服务启动校验失败，无法正常提供服务；未将云网络配置的数据集与工作流节点绑定，会导致溯源时无法匹配到真实配置条目。
- 工作流中仅第一个评审节点能显示知识库引用，后续节点无引用内容。排查项：未在工作流节点配置中正确绑定云网络配置的数据集ID，且未在后续节点中启用引用溯源功能。
- AI输出的引用内容包含非原始配置的加工文本。原因是未将返回数据格式设置为仅返回原文片段，导致模型对引用内容进行了摘要或改写。

## 怎么确认配好了
- 启动FastGPT v4.17.0的App/Admin服务，检查启动日志中是否存在`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）或`AIPROXY_API_TOKEN`（AI Proxy管理员Token）环境变量缺失的报错，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`已正确配置。
- 新建一个云网络配置评审的工作流，添加知识库检索节点，输入一条真实的负载均衡端口映射规则，检查检索结果是否能匹配到对应的原始文档片段。
- 触发一次完整的变更评审流程，查看评审结果中的引用来源是否显示了正确的文档路径、变更单编号与更新时间。
- 检查工作流节点的配置项，确认最大引用Token数、返回数据格式等参数已按预设值设置。
