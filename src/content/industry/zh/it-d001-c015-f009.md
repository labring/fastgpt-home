# 产品使用数据分析的代码与变更评审辅助：工具调用与插件

本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据来源包括埋点系统、企业内部数据仓库、客户关系管理系统与工单系统。数据更新频率为每日或每周。日常产出的文档包含使用分析报告、埋点方案、指标口径表与看板需求单，数据字段通常涵盖客户唯一标识、功能模块名称、操作频次、访问时长、工单诉求类型等，无统一强制单位，部分指标需结合业务口径定义对应单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散要求工具调用需适配多系统的鉴权规则与数据返回格式，增加插件开发的适配成本。数据更新频率的日/周差异，要求插件支持按需触发数据拉取，避免高频调用占用系统资源。日常文档的多样性意味着插件需兼容埋点方案、指标口径表等多种输入格式，无法依赖固定字段模板。指标口径的非标准化，要求工具调用时需同步传递对应口径说明，防止跨环节的指标解读偏差。客户关联数据需按客户维度聚合，插件需支持按客户ID分组处理数据，适配客户成功运营的分析需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多源数据拉取场景，自动匹配对应工具完成数据采集与处理 |
| 数据拉取超时阈值 | 600 秒 | 适配多数企业内部系统的接口响应时长，避免超时中断数据拉取流程 |
| 插件输入格式支持 | JSON、CSV、Excel模板 | 覆盖埋点方案、指标口径表等日常文档的通用格式 |
| `functionCall` | 开启必填字段校验 | 强制校验客户ID、功能模块等核心字段，防止分析结果缺失关键信息 |
| 数据聚合周期 | 按日、按周可选 | 匹配数据更新的日/周频率，适配不同分析场景的周期需求 |
| 插件日志级别 | 生产模式仅记录错误日志 | 平衡排查需求与系统运行性能，避免日志占用过多存储资源 |

## 容易做错的三处
- 现象：工作流中添加自定义插件后，未显示输入输出参数，无报错日志。原因：未在插件配置中正确声明参数的类型与必填属性，导致前端渲染异常。
- 现象：调用工具后返回结果条数与预期不符，部分客户数据未被聚合。原因：未按客户ID配置分组规则，导致跨客户数据混杂，无法匹配分析需求。
- 现象：工具调用超时，响应延迟明显。原因：设置的超时阈值过短，未适配多系统接口的联合响应时长，或未配置重试机制处理临时网络波动。

## 怎么确认配好了
- 触发一次工具调用，查看返回的原始数据是否包含所有预期的字段，核对字段名称与业务口径表一致。
- 模拟不同更新周期的数据拉取，确认插件能按配置的日/周频率触发数据同步。
- 上传埋点方案、指标口径表等文档，确认插件能正确解析并适配输入格式。
- 检查插件日志，确认无报错信息，核心字段校验规则正常生效。
