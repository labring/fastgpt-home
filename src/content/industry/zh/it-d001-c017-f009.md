# 代码评审与合并管理的代码与变更评审辅助：工具调用与插件
本文档适用于FastGPT v4.17.0版本，面向代码评审与合并管理场景的工具调用与插件配置。

## 这个品类的数据长什么样
该品类的数据主要来源于Git仓库、CI流水线、静态扫描报告与缺陷库。日常关联的业务文档包括合并请求、代码评审意见、提交记录与分支策略说明。数据更新频率为每日或每一次代码提交。数据字段包含合并请求唯一标识、提交哈希值、评审意见状态、关联分支名称、静态扫描缺陷计数等，部分字段为文本标识，部分为数值计数，无统一固定单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且更新节奏与代码提交强绑定，要求工具调用需适配增量拉取逻辑，避免重复处理全量仓库数据。关联文档结构固定但字段多样，要求插件需预设合并请求、评审意见等文档的解析规则，精准提取关键评审信息。数据出错会直接影响代码合并质量，要求工具调用需增加前置校验环节，拦截不符合评审要求的变更请求。同时，数据更新实时性要求高，工具调用需尽量降低延迟，避免延误评审流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具触发时机 | 按代码提交或合并请求创建事件触发 | 匹配该品类数据与提交强绑定的更新节奏，避免无效定时调用 |
| 工具调用超时时间 | 300–600 秒 | 适配Git仓库拉取、CI日志解析的常规耗时，避免超时中断评审流程 |
| `toolChoice` | 设置为`auto` | 让模型自主选择合适的工具处理评审数据拉取与校验，适配多样的文档结构 |
| 评审数据拉取范围 | 仅拉取当前合并请求关联的提交与静态扫描报告 | 减少无效数据加载，符合该品类数据按合并请求聚合的特征 |
| `functionCall` | 开启并限定为代码评审校验类函数 | 确保工具调用聚焦于变更影响判断与评审意见验证，避免无关工具调用 |
| 插件权限范围 | 仅授予指定仓库的只读访问权限 | 符合代码评审场景的安全要求，避免越权访问其他仓库数据 |

## 容易做错的三处
- 现象：工具生成的代码评审统计饼图无法正确渲染，显示为纯文本markdown代码。原因：未正确配置工具的markdown渲染规则，导致饼图的表格格式未被正确解析。
- 现象：工具调用超时报错，返回状态码504，且返回的评审数据字段缺失，如无合并请求关联的提交记录。原因：未正确配置评审数据拉取范围，且将工具触发时机设置为固定定时拉取，导致加载耗时超过预设的超时阈值，未覆盖当前合并请求的关联内容。
- 现象：npx运行的MCP服务无法添加到工具集，临时激活状态很快失效，且通信日志显示连接失败。原因：未按照服务启动日志的格式配置服务参数，未正确配置FastGPT与MCP服务的通信端口，导致无法建立稳定连接。

## 怎么确认配好了
- 手动触发一次指定合并请求关联的工具调用，检查返回结果是否包含该合并请求的唯一标识、提交哈希与评审意见状态。
- 查看工具调用日志，确认触发时机与代码提交或合并请求创建事件匹配，无无效的定时拉取记录。
- 检查插件权限配置，确认仅授予指定代码仓库的只读访问权限，无越权访问的配置项。
- 测试接入npx运行的MCP服务，确认服务状态显示为已激活，且无通信报错记录。
