# 企业软件许可证管理的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本品类的数据来源于软件资产管理系统、采购系统、终端扫描结果及厂商授权文件。日常维护的文档包含许可证台账、软件使用清单、采购合同与合规审计报告。数据更新频率为月或季度，核心字段包含软件名称、授权许可数量、实际安装终端数、授权到期日期、厂商授权编号，无额外自定义统计字段。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类数据更新频率为月或季度，单次变更评审需关联的历史数据跨度匹配当前审计周期，因此上下文召回的时间范围需限定在该周期内，避免引入过期数据干扰评审。不同文档的结构差异明显，结构化台账的字段长度固定，非结构化合同的文本长度波动较大，需针对不同数据源调整token分配上限，防止核心授权信息被截断。同时，授权数量核对为核心耗时环节，上下文需精准召回授权数量、安装终端数等关键字段，过量无关文本会占用token配额，拉长评审耗时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 10000–15000 token | 匹配月度周期内的核心文档总token量，适配多数开源模型的上下文窗口上限 |
| `quoteMaxToken` | 800–1200 字符 | 针对结构化许可证台账的核心字段组合长度，确保授权数量、终端数等关键信息完整召回 |
| `maxContext` | 按审计周期调整 | 季度审计场景下可上调至18000 token，覆盖更多历史采购合同与终端扫描数据 |
| `quoteMaxToken` | 按实测标定 | 针对非结构化的合规审计报告，避免截断关键授权条款 |
| `maxContext` | 过滤过期数据 | 排除早于当前审计周期的文档，减少无效token占用，聚焦当前评审所需的有效数据 |

## 容易做错的三处
- 现象：配置`quoteMaxToken`后，评审结果中未出现授权数量相关的字段。原因：`quoteMaxToken`取值过小，导致核心字段的文本被截断，无法被模型识别。
- 现象：英文场景下触发变更评审任务时返回报错，提示上下文token超出上限。原因：未针对英文文档调整`maxContext`取值，直接复用中文场景的配置，导致英文token折算后超出模型窗口。
- 现象：单次变更评审返回的授权核对结果不完整，存在部分终端的授权状态缺失。原因：`maxContext`取值过低，未能召回足够的历史许可证台账数据，导致模型无法完成全量授权数量核对。

## 怎么确认配好了
- 导入单份完整的许可证台账，使用FastGPT v4.17.0版本的上下文预览功能，确认核心字段未被截断。
- 触发变更评审任务，查看平台日志中的token消耗统计，确认未出现上下文溢出报错。
- 对比导入不同周期的文档，确认仅当前审计周期内的数据被纳入上下文范围。
- 调整`quoteMaxToken`的取值，观察召回文本的长度变化，确认配置参数生效。
