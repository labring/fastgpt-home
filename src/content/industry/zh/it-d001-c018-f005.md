# 企业软件许可证管理的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
数据来自软件资产管理系统、采购系统、终端扫描结果及厂商授权文件，日常维护的文档包含许可证台账、软件使用清单、采购合同与合规审计报告。数据更新周期为月或季度，核心字段包含软件名称、授权数量、安装节点数、授权有效期、厂商信息，单位多为台、套、自然日。该品类聚焦软件授权与安装使用的匹配核对，区别于通用IT资产盘点。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来源分散且更新周期较长，多轮对话需优先调用已同步的本地台账数据，避免重复拉取外部系统导致的延迟。核心字段包含授权数量、安装节点数等，提示词需明确限定字段匹配规则，避免混淆IT资产盘点与许可证核对的差异。数据更新周期为月或季度，会话上下文需保留最近的台账批次标识，确保会话中引用的数据版本一致。合规审计相关文档需严格限定访问范围，提示词需屏蔽敏感合同细节，仅返回合规校验结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定企业软件资产管理系统的资产批次ID | 确保会话始终关联同批次的许可证台账数据，避免跨批次数据混淆，适配FastGPT v4.17.0的会话管理规则 |
| `messages` | 保留最近3轮与许可证核对相关的对话 | 数据更新周期为月/季，过多历史会引入过期数据干扰校验结果 |
| `variables` | 预设授权数量、安装节点数、授权有效期三个业务变量 | 匹配日常文档的固定字段，减少提示词中的重复描述 |
| 最大上下文长度 | 800–1200字符 | 核心业务字段较少，避免上下文溢出导致字段匹配失败 |
| 会话超时时间 | 1800秒 | 合规校验可能需要跨多份文档核对，预留充足处理时长 |

## 容易做错的三处
- 现象：调用接口时返回`invalid chatId`报错，原因：未绑定企业软件资产管理系统的资产批次ID，直接使用默认会话ID，导致无法关联对应许可证数据。
- 现象：发起对话后触发额外的AI生成步骤，无法直接返回结构化的校验结果，原因：未正确配置`variables`变量映射规则，未跳过自动生成环节，强制调用了通用对话流程。
- 现象：将提示词修改为英文后无法匹配国内软件资产管理系统的字段，原因：未将预设变量同步为英文标识，导致字段映射失败。

## 怎么确认配好了
- 发起测试调用，传入绑定企业软件资产管理系统资产批次ID的`chatId`，核对返回结果是否关联对应批次的许可证数据。
- 配置预设业务变量后，发起测试对话，确认返回结果能正确提取预设字段的取值。
- 发起合规校验请求，确认返回结果仅包含授权核对相关内容，未包含未授权的敏感文档细节。
- 发起多轮对话测试，确认会话保留最近3轮与许可证核对相关的历史消息，未触发上下文溢出报错。
