# 众包标注人员管理的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
众包标注人员管理的数据来源包含众包平台的人员注册信息、标注质量抽检数据、线上培训考试记录，以及财务系统的结算清单。数据更新频率分为日更与月更两类：标注质量数据按日更新，人员准入规则、培训材料与结算清单按月更新。日常关联文档包括人员资质准入表、培训考核成绩单、月度绩效排名表与结算明细单，字段覆盖人员唯一标识、资质等级、考核得分、结算金额等基础信息。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据类型多样且更新节奏不均，不同文档的token消耗差异明显：结构化的结算清单与绩效表token占比更高，非结构化的培训材料token占比相对平稳。多来源的数据需要在上下文加载时完成分类筛选，避免无关数据占用过多token配额。日更的标注质量数据需要优先加载最新条目，月更的结算清单则需控制加载频率以降低上下文刷新的token消耗。同时，人员数据的字段数量与长度直接影响单条上下文的token占用，需合理限定单条引用数据的token上限，避免上下文溢出。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 覆盖该品类全部核心文档的总token消耗，避免上下文溢出导致数据丢失 |
| `quoteMaxToken` | `2000 token` | 限定单条引用的标注人员数据的token上限，防止单条结算明细或绩效表过长占用过多上下文 |
| 上下文刷新间隔 | `12 小时` | 适配日更的标注质量数据与月更的结算清单的更新节奏，平衡数据时效性与token消耗 |
| 上下文来源过滤 | 按文档类型筛选 | 仅加载人员准入规则、绩效表、结算清单三类目标数据，排除无关文档的token占用 |
| 单次上下文加载条数 | `前 3 条最新数据` | 控制初始上下文的token消耗，避免加载过多历史数据导致上下文过载 |

## 容易做错的三处
- 现象：模型返回的上下文缺失部分月度绩效数据。原因：未配置按文档类型过滤上下文，导致非目标数据被自动截断。
- 现象：MongoDB查询的token统计与模型API返回的token消耗不一致。原因：未区分内部上下文加载的token消耗与模型推理的token消耗，未单独统计标注人员数据的token占用。
- 现象：AI对话节点的新上下文字段为空。原因：未设置合理的`maxContext`上限，导致上下文数据溢出后被系统清空。

## 怎么确认配好了
- 进入FastGPT v4.17.0的上下文预览面板，确认仅加载了人员准入规则、绩效表、结算清单三类目标文档。
- 触发一次模型调用，对比MongoDB查询日志的token消耗与FastGPT后台的上下文token统计，确认两者差值符合配置预期。
- 手动触发一次数据更新，等待12小时后查看上下文，确认最新的标注质量数据已被加载到上下文中。
- 查看`quoteMaxToken`的配置项，导入一条完整的结算明细单，确认系统未对其进行强制截断。
