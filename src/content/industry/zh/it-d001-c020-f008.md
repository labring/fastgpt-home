# 供应商与设备到货管理的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
通常，供应商与设备到货管理的业务数据主要来自ERP系统、供应商发货单、物流信息平台及设备厂商后台。日常流转的文档包含采购订单、到货验收单、序列号清单、发票资料，核心字段涵盖采购单号、设备型号、序列号、到货日期、验收状态等，单位多为台、套、件。数据更新频率以每单为基准，单次采购流程的全量数据会随节点推进更新，跨项目的汇总数据则按周更新。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源涉及多套系统与外部文档，工作流编排需配置跨源数据拉取节点，确保各环节可自动同步ERP、物流及厂商数据。数据按单/周更新的特性，要求工作流触发条件绑定采购单创建事件或定时任务，避免无效执行。多类型业务文档的存在，需为不同文档分配专属`variables`存储字段，同时需在型号核对、到货验收等核心环节配置校验逻辑，防止设备错配、项目延期等问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables`参数配置 | 绑定采购单ID作为索引，拉取ERP中的设备型号、序列号数据 | 品类核心数据主要来自ERP系统，自动关联可减少手动录入误差，依据FastGPT v4.17.0的跨系统节点配置规则 |
| 触发节点设置 | 按采购单创建事件触发 | 品类数据更新以每单为基准，按业务节点触发可匹配实际业务流转节奏 |
| `nodeId`分配 | 为型号校验、验收登记、数据拉取节点分配唯一标识 | 需精准控制各节点的跳转逻辑与重试规则，保障工作流稳定性 |
| 超时阈值 | 600秒 | 跨系统拉取物流、设备厂商数据的平均耗时区间，按实测标定 |
| 变量存储上限 | 1000 MB | 品类单批次文档包含序列号清单、发票资料等，数据量通常不超过该阈值 |
| 节点重试配置 | 重试次数为3次 | 应对跨系统调用的临时异常，保障工作流不轻易终止 |

## 容易做错的三处
- 工作流运行至中途终止，界面显示节点执行失败，日志返回全局变量为空。原因是未将采购单ID正确绑定到`variables`参数，导致无法拉取ERP中的关联业务数据。
- 第三方API调用返回400状态码，请求头参数格式异常。原因是未按品类业务文档要求拼接全局变量引用格式，导致请求参数无效。
- 型号配置核对环节提示字段为空。原因是未配置跨系统数据拉取节点，未同步供应商发货单中的设备型号数据，导致校验环节无有效输入。

## 怎么确认配好了
- 手动触发一次工作流，查看`variables`参数是否正确加载了采购单关联的ERP设备型号、序列号数据。
- 模拟采购单创建事件，检查工作流是否按预期触发并拉取物流、设备厂商后台的相关信息。
- 校验型号核对节点的输入字段，确认已同步供应商发货单中的设备型号数据，无空值提示。
- 测试全局变量缺失的异常场景，检查工作流是否触发预设的失败处理逻辑，执行异常告警与记录。
