# 供应商与设备到货管理的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
该品类的核心数据来自ERP系统、供应商发货单、物流跟踪信息及设备厂商后台。日常流转的文档包含采购订单、到货验收单、序列号清单与发票资料。数据更新以单批次到货为单位，单次项目周期内每周同步一次。数据字段包含采购关联单号、设备型号、机身序列号、到货日期、验收状态与供应商标识，该品类服务于具体集成项目交付，区别于面向全员的企业IT采购，仅按交付节点更新，无额外自定义统计字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散要求工具调用需分别配置多类接口的访问权限，避免跨系统数据混淆。按单更新的特性要求工具调用需绑定采购单号作为上下文标识，确保每次调用仅关联对应批次的到货数据。文档类型多样的特点，要求工具调用时需指定解析目标文档的类型，防止将序列号清单误解析为发票内容。型号核对为最耗时环节，需在工具调用后实时比对采购订单与到货单的字段，提前拦截错配风险。数据更新不及时可能导致工具返回过期信息，需配置超时重试机制以保障验收环节的时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多类型工具调用场景，无需手动指定具体工具，覆盖ERP、物流、设备厂商等多接口调用需求 |
| 工具调用超时时间 | `60-120 秒` | 数据来源多为内部系统与第三方物流接口，该区间可覆盖多数接口的正常响应时长 |
| 上下文绑定标识 | 采购单号 | 该品类数据以采购单为核心关联维度，可避免跨单数据混淆，确保调用结果精准匹配对应批次 |
| 文档解析类型 | 按文档后缀自动匹配（.xml对应序列号清单、.pdf对应到货验收单） | 日常文档格式固定，自动匹配可减少手动配置成本，提升调用效率 |
| 重试触发阈值 | 前2次调用失败 | 单次接口波动不会影响整体流程，重试可降低数据获取失败概率，适配该品类按单交付的节奏 |
| 结果校验规则 | 比对采购订单与到货单的设备型号字段 | 该品类最耗时的环节为型号配置核对，可提前拦截错配风险，保障交付准确性 |

## 容易做错的三处
- 现象为调用指定文档解析工具时返回空结果，原因是未配置文档类型匹配规则，导致工具无法识别序列号清单的解析目标。
- 现象为配置自定义工具时，可选参数的HTTP调用参数栏消失，原因是未在工具配置界面开启高级参数编辑模式，导致可选参数的配置入口被隐藏。
- 现象为Java调用API时持续处于等待响应体的状态，原因是未设置合理的超时时间，或未配置超时重试机制，导致接口无响应时进程阻塞。

## 怎么确认配好了
FastGPT v4.17.0 版本下，可通过以下动作核对配置是否生效：
- 发起一次模拟调用，传入测试采购单号与对应文档，检查工具是否返回正确的设备型号与序列号信息。
- 查看工具调用日志，确认上下文绑定的采购单号与测试数据一致，无跨单数据混入。
- 触发一次失败的模拟调用，检查是否按配置触发重试机制，重试次数符合预期。
- 比对工具返回的结果与原始采购订单、到货验收单的字段，确认型号核对规则正常生效。
