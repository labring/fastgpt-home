# 供应商与设备到货管理的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
该品类的日常业务文档包含采购订单、到货验收单、序列号清单、发票资料，核心字段包括采购单号、设备型号、序列号、到货日期、验收结果等。数据来源主要为内部ERP系统、供应商发货单、物流跟踪记录、设备厂商后台台账，更新节奏按单或按周触发，每完成一批采购或每周定期同步一次业务数据。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据来源分散且覆盖多类业务文档，引用溯源时需同时关联不同文档的关联字段，避免设备型号、序列号错配导致的业务风险。数据按单或按周更新，需配置匹配该节奏的同步规则，确保知识库内容与实际到货进度一致。不同文档的字段结构差异明显，需针对采购单号、设备序列号等核心字段设置专属的召回匹配逻辑，确保引用的来源与实际业务数据完全对应。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前 8 条 | 匹配该品类单批到货的设备数量范围，覆盖采购订单、到货验收单等核心关联文档 |
| 最大上下文 | 3000–4000 token | 容纳多份关联文档的内容，避免截断关键业务字段 |
| `quoteMaxToken` | 1500 token | 限定单条引用的长度，确保溯源信息清晰不冗余 |
| `responseData` | 开启字段溯源模式 | 强制返回引用来源的原始文档字段，便于业务核对 |
| `detail` | 开启完整溯源 | 展示引用来源的文档类型与具体编号，匹配业务校验需求 |

## 容易做错的三处
- 现象：检索时仅返回1条知识库引用，无法关联多份文档。原因：未调整单次搜索上限的配置，仅召回单条结果，无法覆盖多类关联业务文档。
- 现象：调用知识库时选项为空，需手动选择后才能使用。原因：未配置自动同步规则，未按单或按周更新知识库内容，导致导入的文档未被系统识别。
- 现象：引用内容无法下载，或返回的溯源信息缺失文档编号。原因：未开启`detail`配置，未强制返回完整的来源字段，导致无法提取可校验的溯源凭证。

## 怎么确认配好了
- 提交一批包含采购订单、到货验收单的测试数据，检查检索结果的引用条数是否覆盖对应文档类型。
- 查看返回结果的溯源字段，确认是否包含文档编号、来源类型等核心业务信息。
- 调整`quoteMaxToken`的取值，测试不同长度的引用内容是否被正确处理。
- 在FastGPT v4.17.0环境中触发知识库同步任务，确认系统自动加载导入的文档，无需手动选择即可调用。
