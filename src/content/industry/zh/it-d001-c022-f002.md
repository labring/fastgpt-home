# 信创替代适配的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
信创替代适配的核心数据来自现有系统清单、国产软硬件目录、测试环境与厂商资料，更新节奏为单项目周期或每季度。日常产出的文档包括适配清单、兼容性测试报告、迁移方案与问题台账，其中适配清单包含原系统组件、国产替代组件、兼容性验证结果等字段，测试报告以版本号、测试日期为单位标注验证状态，整体数据结构随项目需求灵活调整，无统一强制格式。

## 这些特征在「上下文与 token」这一环带来什么约束
信创项目的数据来源分散且结构灵活，要求上下文加载需适配不同格式的文档，避免因格式不兼容丢失关键适配信息。更新频率与项目进度绑定，需匹配单项目或季度的文档刷新节奏，防止召回过时的兼容性测试结果。长文本类文档占比高，如迁移方案、完整适配清单，需合理控制token占用，确保上下文窗口能覆盖全量关键内容，同时避免因token溢出导致评审信息缺失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 按项目总文档字符数的1.2–1.5倍（按实测标定） | 适配信创项目多跨系统文档的总长度，覆盖全项目上下文范围 |
| `quoteMaxToken` | 8000–12000 token | 匹配国产大模型的基础上下文窗口，避免召回内容溢出 |
| 最大响应tokens | 4000–6000 token | 用于输出完整的代码变更评审与兼容性评估报告 |
| 单次搜索上限 | 前8条 | 适配项目文档的常规条目数量，避免冗余召回低相关性内容 |
| 知识库刷新频率 | 按项目阶段触发 | 匹配信创项目每季度更新的测试报告与适配清单节奏 |

## 容易做错的三处
- 现象：调用代码评审API时返回413状态码，上下文内容被截断。原因：未调整`maxContext`参数适配当前项目的总文档长度，超出配置的上下文上限。
- 现象：代码变更评审召回的知识库内容包含过时的兼容性测试结果，与当前项目无关。原因：未设置匹配项目节奏的知识库刷新频率，召回了季度前的旧文档。
- 现象：知识库内的适配清单图片链接显示不完整，被截断为短地址。原因：`quoteMaxToken`设置过小，导致长链接在召回时被截断。

## 怎么确认配好了
- 上传单份完整的信创适配清单文档，在FastGPT v4.17.0中测试，确认无内容截断提示，完整加载所有字段。
- 发起代码变更评审请求，核对召回的知识库内容是否包含当前项目的兼容性测试报告与迁移方案。
- 查看应用运行日志，确认API调用时传入的`maxContext`、`quoteMaxToken`参数与配置值一致。
- 测试输出长文本评审结果，确认响应内容未被无故截断，覆盖完整的评估结论。
