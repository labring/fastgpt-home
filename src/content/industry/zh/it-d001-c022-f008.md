# 信创替代适配的代码与变更评审辅助：工作流编排

本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的数据主要来自企业现有IT系统清单、国产软硬件官方目录、项目测试环境输出结果及厂商公开资料。日常产出的文档包含适配清单、兼容性测试报告、迁移方案与问题台账四类，其中适配清单需记录存量系统与替代软硬件的版本对应关系，兼容性测试报告需标注单节点兼容状态。数据更新频率按单项目或季度周期调整，未完成的迁移项目需同步更新存量系统盘点数据。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散且更新周期随项目灵活调整，工作流编排需支持动态接入多源异构数据，避免硬编码固定数据源。日常文档包含多类结构化与非结构化内容，工作流需适配不同文档的字段解析规则，例如从适配清单提取版本字段、从测试报告提取兼容状态标签。迁移风险评估环节依赖实时数据校验，工作流需设置前置校验节点，确保评审前已完成存量系统盘点与兼容性测试数据的同步，否则无法进入评审环节。此外，错误评审结果可能引发业务系统不可用等后果，工作流需增加失败回滚与告警节点，避免错误内容触发后续迁移步骤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量定义 | 关联现有系统清单、国产软硬件目录的数据源 | 适配品类数据来源分散的特征，避免硬编码固定参数 |
| 节点触发条件 | 按`nodeId`匹配评审节点类型 | 确保不同类型的评审（如兼容性评审、版本匹配评审）触发对应处理逻辑 |
| 上下文调用上限 | 前 10 条 | 适配兼容性测试报告的单节点数据量，避免过多冗余信息干扰评审 |
| 超时阈值 | 600 秒 | 匹配存量系统盘点环节的平均耗时，防止评审流程因数据拉取延迟中断 |
| 结果过滤规则 | 仅保留兼容状态为「通过」的条目 | 对应问题台账中的异常记录，过滤无效数据以提升评审效率 |
| 工作流触发方式 | 由`variables`中的项目ID触发 | 按单项目周期更新数据的特征，确保每个迁移项目对应独立评审流程 |

## 容易做错的三处
- 工作流判断器始终返回非空结果：未配置判断器的空值校验规则，直接使用未过滤的数据源作为判断依据，导致无论输入内容如何均触发对应分支。
- 代码运行节点无法选择知识库引用作为变量：未在变量定义环节绑定知识库的工作流调用权限，或未开启知识库的调用开关，导致变量列表无法加载知识库内容。
- 通过API创建工作流时未配置项目隔离规则：未通过API指定`variables`中的项目ID作为触发条件，导致多个迁移项目共用同一套评审逻辑，无法区分不同项目的适配数据。

## 怎么确认配好了
- 登录FastGPT v4.17.0的工作流管理页面，查看当前配置的变量列表，确认包含现有系统清单、国产软硬件目录的数据源字段。
- 提交模拟评审请求，验证判断器仅在匹配对应评审类型的`nodeId`时触发正确分支。
- 查看工作流运行日志，确认超时阈值设置符合单项目周期的耗时范围，未出现提前中断的情况。
- 进入代码运行节点的变量配置界面，确认已绑定知识库的调用权限，可正常加载知识库内容。
