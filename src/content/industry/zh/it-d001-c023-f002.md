# 信息化预算与项目组合管理的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
这个品类的核心数据来自财务系统、项目管理系统、合同台账与业务部门需求，日常产出年度预算表、项目立项书、项目组合看板、投资复盘报告等文档。数据更新节奏多为月、季或年度，单次输入的文档包含预算额度、项目周期、立项状态、收益预估等字段，单位涵盖元、自然日等。不同来源的数据格式存在差异，部分字段存在非标准化命名情况。

## 这些特征在「上下文与 token」这一环带来什么约束
品类数据的多来源与非标准化特性，要求上下文拼接时需先完成字段归一化处理，否则会产生无效token消耗。月度/季度级的更新频率意味着无需高频刷新上下文缓存，但单次评审可能涉及多份跨系统文档，总token量可能超出模型限制。核心字段的精准匹配需求，要求上下文召回需优先关联预算优先级、项目收益等关键信息，避免无关数据占用token配额。超长的年度预算文档可能导致单任务token超限，进而引发超时或截断问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文token数 | `8000–12000 token` | 适配通用大模型输出限制，避免评审结果被截断 |
| `quoteMaxToken` | `3000–5000 token` | 匹配单份核心文档的关键内容长度，避免冗余数据加载 |
| 相似度阈值 | 0.5–0.7 | 过滤低相关的非预算类数据，减少无效token消耗 |
| 单次召回条数 | 前6条 | 适配月度更新的项目数据量，避免上下文过载 |
| `maxContext` | 14000 token | 预留足够空间容纳多份跨系统文档的拼接内容，FastGPT v4.17.0版本支持该配置 |
| 重排开关 | 开启 | 优先召回预算优先级、项目周期等核心字段，提升上下文精准度 |

## 容易做错的三处
- 任务执行超时：现象为任务执行完成前返回超时报错，原因是未根据品类数据更新频率调低上下文缓存刷新间隔，导致拼接过多历史预算数据。
- 输出被截断：现象为大模型输出在12288 token时停止并提示超出回复限制，原因是`maxContext`设置未匹配大模型16384的输出上限，且未过滤合同台账中的冗余字段内容。
- 核心内容召回失败：现象为无法检索到目标预算条目或项目立项信息，原因是相似度阈值设置过低混入无关数据，或未开启重排导致核心字段未被优先召回。

## 怎么确认配好了
- 上传一份年度预算表，查看上下文拼接预览，确认核心字段未被截断或遗漏。
- 发起一次项目组合评审任务，查看任务日志中的token消耗数值，确认未超过预设的`maxContext`配置。
- 调整相似度阈值，验证召回的项目数据是否匹配业务部门的核心评审需求。
- 模拟超长任务执行，检查是否出现超时或截断类报错，确认配置符合场景要求。
