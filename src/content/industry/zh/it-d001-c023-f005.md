# 信息化预算与项目组合管理的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自财务系统、项目管理系统、合同台账与业务部门需求。日常产出的文档包括年度预算表、项目立项书、项目组合看板、投资复盘报告，字段通常包含预算金额、项目编号、优先级标识、收益预期值等。数据更新节奏以月、季或年为周期，单次更新覆盖当期调整后的项目与预算信息，不同周期的文档格式与字段细节保持相对统一。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据多来自多套异构系统，且格式差异较大，多轮对话需保留不同数据源的上下文标识，避免混淆不同系统的项目信息。数据更新周期较长，提示词需明确指定当前统计周期的数据集范围，防止调用过期数据。文档字段包含预算金额、优先级等细分项，多轮对话需逐步引导用户明确字段提取规则，确保统计与评审的准确性。代码变更评审需关联项目预算与变更内容，提示词需预设项目与变更单的关联逻辑，辅助完成匹配校验。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| messages | 按对话轮次保留最近20条交互记录 | 该品类数据更新周期长，过多历史记录会稀释当前项目上下文 |
| variables | 预设「预算周期」「项目类型」「关联系统」3个变量 | 该品类数据按周期更新，变量可快速限定统计与评审范围 |
| 最大上下文 | 8000–12000 token | 日常文档包含多字段的表格内容，需足够上下文容纳完整数据片段 |
| chatId | 绑定项目编号作为唯一标识 | 需区分不同项目的评审对话，避免上下文串扰 |
| 单次对话匹配上限 | 前10条匹配数据 | 该品类文档字段多，过多数据会超出模型处理阈值 |

## 容易做错的三处
- 现象：上传的年度预算表未被对话模型纳入统计范围，返回结果未包含上传数据的对应内容。原因：未在提示词中明确指定上传文件的解析字段与使用规则，模型无法识别上传数据的有效范围。
- 现象：调用多模态接口处理项目看板图片时返回400 invalid image错误。原因：上传的图片格式不符合模型支持的类型，或图片文件大小超出预设阈值。
- 现象：多轮对话中不同项目的评审上下文发生串扰，结果出现跨项目的预算数据混淆。原因：未为每个对话绑定唯一的chatId标识，导致不同项目的上下文被合并处理。

## 怎么确认配好了
- 上传一份测试用的年度预算表，在对话中询问指定字段的汇总内容，核对返回结果是否包含上传数据的对应信息。
- 调用API发起多轮对话，携带chatId参数绑定测试项目编号，检查后续对话是否保留该项目的上下文信息。
- 配置variables变量后，在对话界面调用预设变量，确认系统能正确读取并应用变量值。
- 测试多模态接口上传项目看板图片，检查返回的状态码是否正常，无invalid image类报错。
