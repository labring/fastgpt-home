# 信息化预算与项目组合管理的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据通常从财务系统、项目管理系统、合同台账、业务部门需求采集。更新节奏为月、季或年度，日常文档包含年度预算表、项目立项书、项目组合看板、投资复盘报告。数据字段包含预算金额、项目优先级、立项周期、收益指标等，单位多为万元、季度、项目编号，整体以结构化表格与长文本结合的格式呈现，核心围绕项目预算分配与优先级决策展开。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据采集要求引用溯源需整合不同系统的关联数据，避免单一来源的信息偏差。固定的文档结构要求分块匹配需贴合预算表、立项书的格式，确保字段关联准确。更新频率较低但核心字段固定的特点，要求引用配置需精准锁定核心业务字段，减少无关信息干扰。最耗时的需求收口与优先级排序环节，要求溯源结果需快速定位相关预算与项目数据，避免冗余内容拉长评审周期。一旦溯源出错，可能引发预算错配、项目重复建设等后果，因此需确保引用来源的可追溯性与准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | `2000–3000 token` | 品类文档多为结构化表格与长文本，需覆盖完整预算与项目关联数据 |
| `responseData` | `包含项目编号、预算金额、优先级字段` | 需精准匹配品类核心业务字段，便于溯源时关联具体项目与预算信息 |
| `detail` | 开启 | 需展示引用数据的完整来源路径，包括系统来源与文档节点 |
| 单次搜索上限 | 前10条 | 品类数据条目有限，过多结果会干扰优先级判断与评审效率 |
| 最大上下文 | `8000–12000 字符` | 需容纳多份预算与项目文档的关联内容，避免关键信息截断 |
| 平台版本 | FastGPT v4.17.0 | 确保配置项与平台功能兼容，避免参数不生效 |

## 容易做错的三处
- 现象为配置`quoteMaxToken`为3000后，大模型未收到上下文，原因是部分FastGPT版本对超出阈值的请求会截断上下文传输，导致引用数据无法传入。
- 现象为传入HTTP响应数据作为引用无效果，原因是未将数据转换为FastGPT知识库支持的结构化格式，需包含source、content等标准字段。
- 现象为引用显示但答案未关联知识库内容，原因是未开启`detail`配置或`responseData`未匹配品类核心字段，导致大模型无法识别有效关联信息。

## 怎么确认配好了
- 上传一份年度预算表至知识库，发起代码与变更评审辅助请求，查看引用面板是否展示对应文档的来源与核心字段信息。
- 调整`quoteMaxToken`参数至不同区间，验证上下文长度是否符合预期，无截断报错或上下文缺失情况。
- 调用FastGPT API传入品类结构化数据，检查返回结果是否包含配置的`responseData`字段与溯源路径。
- 使用FastGPT v4.17.0版本进行测试，确保配置项与当前平台功能兼容。
