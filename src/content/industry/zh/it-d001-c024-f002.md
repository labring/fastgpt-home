# 信息流广告创意测试的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的典型使用主体为信息流优化师、创意团队与增长团队，日常产出的文档包含创意脚本、素材测试表、投放数据报告与迭代清单。数据主要来自广告平台、素材库、用户互动数据与转化数据，通常更新频率为日度或周度。文档字段通常包含素材类型、投放时段、变量组合、转化成本等，单份文档的内容长度随测试规模变化，多为碎片化的测试记录与数据汇总。

## 这些特征在「上下文与 token」这一环带来什么约束
碎片化的测试记录与多源数据要求上下文窗口需覆盖完整的变量组合与历史迭代逻辑，避免因上下文截断丢失关键对比信息。高频更新的投放数据与测试结果需要动态调整上下文范围，防止token消耗超出阈值。多类型文档的混合检索需要限制单条引用的token长度，避免冗余内容挤占有效上下文空间。同时，创意测试的出错后果直接关联投放效果，需严格控制上下文与token的配置，防止因内容缺失或超限导致测试结论偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 信息流创意测试需覆盖多组变量组合与历史迭代记录，完整的上下文可确保评审逻辑连贯 |
| `quoteMaxToken` | `1500–2000 token` | 限制单条引用的素材或数据长度，避免因单条内容过长导致整体token溢出 |
| 分块长度 | `4000–5000 字符` | 匹配创意脚本、测试表的单页内容长度，减少碎片化检索带来的token浪费 |
| 单次搜索上限 | 前6条 | 信息流测试的变量组合数量有限，过多检索结果会增加上下文冗余 |

## 容易做错的三处
- 设置`quoteMaxToken`为1500后，仍出现单条引用内容超出限制的情况。原因是未同步调整知识库分块长度，导致检索到的切块本身超过`quoteMaxToken`阈值。
- 工作流中无法按预设条件清空上下文历史记录。原因是未正确绑定上下文触发节点与判断条件，或未使用对应版本的上下文重置配置。
- 无法查看单次问答的token使用情况。原因是未开启全局token统计日志，或未在FastGPT v4.17.0的对应面板中启用统计功能。

## 怎么确认配好了
- 查看FastGPT v4.17.0的全局token统计面板，确认每次问答的token消耗数值与配置的`maxContext`、`quoteMaxToken`范围匹配。
- 发起包含多组创意变量的测试查询，验证检索到的引用内容长度未超出`quoteMaxToken`设置。
- 触发工作流的条件判断节点，确认上下文历史可按预设规则保留或清空。
- 调整知识库分块长度后，验证检索结果的完整性与整体token消耗的合理性。
