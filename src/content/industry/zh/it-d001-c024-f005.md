# 信息流广告创意测试的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
信息流广告创意测试场景的数据主要来自广告投放平台、创意素材库、用户互动与转化数据。日常关联文档包含创意脚本、素材测试表、投放数据报告与迭代清单，更新频率多为日度或周度。数据字段包含素材类型、文案内容、投放时段、点击量、转化成本等，无统一固定单位，需匹配对应业务文档的字段格式。测试操作围绕素材组合对比展开，数据体量随测试频次动态调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散的特点要求多轮对话需支持跨数据源的上下文调用，以整合素材、投放与转化数据。日度或周度的更新频率要求对话上下文需匹配业务数据的时效性，避免使用过时的测试结果。创意变量多、测试结论归纳耗时的需求，要求提示词能结构化梳理多组测试数据的对比结果。素材组合对比的核心场景，要求多轮对话可灵活切换不同素材维度的提问逻辑。不同使用者的测试流程差异，要求对话上下文需按会话隔离，避免数据混淆。

## 配置怎么定
本配置适用于 FastGPT v4.17.0

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| chatId | 绑定当前会话的用户唯一标识 | 实现不同用户的历史对话隔离，避免数据共享 |
| messages | 保留前8–12条对话记录 | 匹配日度更新的数据时效性，避免上下文冗余过载 |
| variables | 绑定创意脚本、测试表的自定义字段 | 直接复用业务文档的字段结构，减少手动输入成本 |
| 最大上下文长度 | 6000–10000 token | 适配多轮创意测试的多维度提问需求 |
| 历史对话召回上限 | 前5条 | 平衡上下文时效性与模型处理效率 |
| 提示词模板 | 按投放数据报告的结构生成 | 匹配业务文档的字段格式，提升测试结论归纳准确性 |

## 容易做错的三处
- 对话界面显示未选择知识库，但调试预览正常。现象为正式会话弹出未选择知识库的提示，调试模式下可正常调用知识库。原因是未通过`chatId`绑定用户会话的知识库权限配置，仅在预览时使用了默认权限。
- 不同使用者无法查看各自的历史对话。现象为任意用户发起的对话，所有使用者均可看到全部历史记录。原因是未正确绑定`chatId`参数，导致所有会话共享同一上下文存储。
- 模型上下文溢出导致测试结论归纳失败。现象为模型输出截断或提示上下文长度超限。原因是未限制`messages`的保留条数，加载了过多历史对话导致超出模型token上限。

## 怎么确认配好了
- 发起两次使用不同`chatId`参数的测试会话，检查两次会话的历史记录互不重叠，确认用户对话隔离生效。
- 输入超过预设最大上下文长度的多轮提问，观察模型是否能正常响应且不出现上下文截断报错，确认上下文配置合理。
- 绑定业务文档的`variables`字段，发起包含创意脚本、测试数据的提问，检查模型输出是否匹配业务字段格式，确认变量绑定生效。
- 进入调试预览模式，验证知识库权限是否正常加载，确认无未选择知识库的提示，确认权限配置正确。
