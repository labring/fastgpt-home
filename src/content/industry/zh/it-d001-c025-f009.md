# 值班排班与交接的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来自排班系统、故障工单、监控告警与组织通讯录，更新频率为日或周。日常产出的文档包含值班表、交接记录、升级联系人清单、值班日报，字段涵盖值班时段、未结待办事项、紧急联系人联系方式、告警响应优先级等，仅记录明确的人员与事项关联信息，无额外统计类量化字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于本品类数据来自多套独立系统，工具调用需配置多源参数映射，避免字段不匹配导致的信息缺失。数据更新频率为日或周，插件触发无需高频轮询，可设置按日同步的触发规则。日常文档结构固定，插件需适配值班时段、未结待办等明确字段，无法灵活适配非标准自定义字段。同时，交接环节需关联故障工单状态，工具调用需支持联动查询工单的未结事项，确保交接信息完整。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 支持自动选择适配值班排班与交接场景的工具，无需手动指定调用目标 |
| 插件触发频率 | `每日 0 点` | 本品类数据更新频率为日或周，每日同步可覆盖日常值班更新需求 |
| 多源参数映射规则 | 按排班系统、故障工单、组织通讯录的字段一一对应 | 本品类数据来源分散，明确映射可避免不同系统间的字段错位 |
| 字段匹配校验 | 开启必填字段校验 | 日常文档包含固定必填字段，校验可防止交接遗漏关键信息 |
| 超时设置 | `300 秒` | 工具调用需同步查询多套系统，预留足够响应时间以覆盖多源数据拉取 |
| 结果返回条数 | `前 10 条` | 值班相关信息无需过多条目，聚焦核心待办与联系人即可满足场景需求 |

## 容易做错的三处
- 现象：工具调用后返回结果耗时超过预设阈值，界面显示超时状态码。原因：未根据本品类多系统数据来源调整超时设置，导致多源查询等待时间超出预留时长。
- 现象：调用插件时仅获取到部分参数，剩余必填字段为空。原因：未配置自动问答补充参数的流程，未在工具调用前触发参数补全环节。
- 现象：知识库检索的值班信息过长，未触发重排逻辑。原因：未开启字段匹配校验或结果返回条数设置过高，导致未按核心字段筛选有效信息。

## 怎么确认配好了
- 手动触发插件调用，检查是否能正确拉取排班系统的值班人员信息与组织通讯录的联系人信息。
- 查看工具调用日志，确认多源参数映射规则已生效，字段无错位情况。
- 等待每日定时触发的插件任务，检查是否生成符合格式的值班日报与交接记录。
- 模拟参数缺失场景，检查是否触发参数补全的问答流程。
