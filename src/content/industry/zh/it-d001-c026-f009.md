# 关卡内容制作的代码与变更评审辅助：工具调用与插件

本页面适配FastGPT v4.17.0版本

## 这个品类的数据长什么样
该品类的数据主要来自关卡编辑器、美术资源库、玩家测试数据与缺陷系统。日常产出的文档包含关卡设计稿、资源需求表、测试反馈单与版本提交记录，字段涵盖路径节点坐标、资源挂载路径、玩家反馈标签、缺陷编号等，更新节奏为每周或每版本迭代一次。数据围绕具体地图与任务落地，区别于侧重规则量化的游戏数值设计品类。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据分散于多个系统且绑定具体地图与任务，要求工具调用需精准关联对应关卡的专属资源与反馈数据。更新频率较高，插件需支持快速拉取最新的版本提交记录与测试数据。日常文档字段类型多样，插件输入需兼容坐标、路径、标签等多格式参数。出错将直接影响关卡交付，工具调用需配置明确的失败重试与告警机制。需避免调用无关品类的资源数据，仅聚焦当前关卡的美术与测试内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 支持自动选择合适的工具处理关卡数据调用需求 |
| `functionCall` | 允许强制指定工具 | 处理固定格式的资源需求表或缺陷单时，可强制调用对应工具 |
| 插件触发时机 | 版本提交后10分钟内 | 匹配该品类每周或每版本的更新节奏，及时拉取最新提交记录 |
| 输入参数校验规则 | 校验坐标、资源路径等字段格式 | 日常文档包含多类型字段，需避免无效参数调用 |
| 失败重试次数与间隔 | 2次，间隔30秒 | 降低网络波动导致的工具调用失败影响，适配分散的数据来源 |
| 最大上下文长度 | 8000–12000 token | 需处理关卡设计稿、测试反馈等多份文档，足够容纳关联数据 |

## 容易做错的三处
- 现象：JSON输入框内无法选择已配置的关卡路径变量，输入框仅支持手动输入原始字符串。原因：未开启插件的变量绑定兼容配置，导致JSON格式输入框无法识别平台内置变量。
- 现象：非工具调用模式下，模型输出未包含网络搜索获取的玩家测试数据内容，搜索接点日志显示已返回结果。原因：未在系统提示词中明确要求非工具调用场景下引用外部搜索结果，导致模型忽略该类数据。
- 现象：上传的自定义插件无法在社区插件市场搜索到，提交发布流程无报错提示。原因：未按照平台要求填写插件的品类标签与适配版本，导致未被分类索引。

## 怎么确认配好了
- 触发一次工具调用，检查返回数据是否包含当前关卡的最新资源路径与测试反馈，核对数据来源与更新时间是否匹配配置的节奏。
- 向插件输入包含坐标、资源路径的测试参数，确认输入框可正常识别并解析格式，无报错提示。
- 模拟工具调用失败场景，确认系统会触发预设的重试次数与告警机制，符合配置要求。
- 检查插件是否可在对应品类的插件列表中找到，确认发布流程已完成分类索引。
