# 关卡内容制作的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据主要来自关卡编辑器、美术资源库、玩家测试数据与缺陷系统。日常产出的文档包括关卡设计稿、资源需求表、测试反馈单与版本提交记录，数据更新频率为周度或每版本发布周期。数据字段包含关卡唯一标识、资源文件路径、测试用例编号、提交人账号、版本号等，部分资源类数据附带文件大小、分辨率等单位信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
关卡内容制作的数据多与具体地图节点、资源绑定，溯源时需要关联到具体的关卡ID与资源路径，无法仅通过通用关键词匹配。周度或每版本的更新节奏要求溯源系统能够快速定位到对应版本的提交记录，避免跨版本数据混淆。测试反馈单与缺陷系统的数据多为非结构化文本，需要精准匹配到对应的关卡调试环节。同时，资源文件的路径与大小信息要求溯源结果中需要明确展示文件的存储位置与版本信息，确保评审人员可以直接定位到原始资源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 1000 token | 匹配关卡设计稿单页的平均内容长度，避免截断核心规则描述 |
| `responseData` | 关联当前关卡ID的前5条记录 | 适配周度更新的历史记录体量，减少冗余数据干扰评审 |
| `detail` | 完整资源路径与版本号 | 满足快速定位原始美术资源或测试数据的需求 |
| 分块长度 | 800–1200 字符 | 覆盖单关卡完整的设计内容，避免关键信息被拆分 |
| 重排规则 | 按关卡版本号排序 | 确保最新版本的评审内容优先展示，便于版本对比 |
| 最大上下文 | 1500 token | 覆盖单关卡全量的资源需求与测试反馈信息 |

## 容易做错的三处
- 现象：调用FastGPT v4.17.0的API返回结果中未携带引用资源的文件名。原因：未配置`detail`参数的完整资源路径展示项，仅返回了文本匹配片段，未关联原始文件的元数据信息。
- 现象：配置引用规则时，仅能选择单个变量关联关卡数据，无法同时引用资源路径与测试反馈内容。原因：未开启多变量关联配置，系统默认限制单次引用的变量数量，导致无法覆盖全链路的溯源需求。
- 现象：评审结果中展示的引用内容并非匹配度最高的历史记录。原因：未按关卡ID进行分组重排，导致不同关卡的匹配结果混杂，优先级被打乱，无法优先展示当前场景的相关内容。

## 怎么确认配好了
- 提交一条包含具体关卡ID与资源路径的测试请求，核对返回结果中是否包含对应的溯源信息
- 配置多变量关联规则后，在下拉菜单中确认可选择的变量数量符合需求
- 触发引用合理性校验工作流，输入包含矛盾内容的测试反馈，核对是否生成对应的异常提示
- 查看FastGPT v4.17.0的系统日志，确认返回的引用数据与当前关卡的版本信息匹配
