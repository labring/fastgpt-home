# 内容审核规则运营的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本品类的核心数据来自内容审核后台、用户举报渠道、公开法规政策文件与内部审核样本库。日常产出与维护的文档包括审核规则条目、违规处置指南、用户申诉记录、月度质检报告。数据更新频率为每日同步，或随行业法规政策调整即时更新。文档结构按审核场景分类，包含规则编号、触发条件、处置阈值、关联样本标识等字段，每个文档条目绑定唯一的审核场景编码与版本号。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类的多源数据与高频更新特性，对上下文与token管理带来多重约束。首先，多源数据包含后台结构化规则、非结构化申诉记录与政策文本，不同格式的内容占用token的比例差异较大，需针对性分配配额。其次，日更或即时更新的审核规则要求上下文能快速拉取最新版本，避免因token配额不足截断关键政策条款。另外，文档绑定的场景编码与版本号字段，需要在上下文检索时精准匹配，避免无效内容占用token额度，影响核心规则的召回效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 本品类核心数据为审核规则、申诉记录与政策文本，该区间可覆盖多场景的完整上下文，避免关键规则被截断 |
| `quoteMaxToken` | `1500–2000 token` | 单条审核规则或处置指南的核心内容通常不超过2000 token，该取值可保证引用内容的精准性 |
| 上下文召回条数 | 前3–5条 | 本品类需匹配特定审核场景，过多召回会占用过多token，过少则可能遗漏关键规则 |
| 上下文更新频率 | 每6小时 | 审核规则随政策或业务调整高频更新，该频率可平衡时效性与token消耗 |
| 最大响应token | `2000–3000 token` | 审核规则解释与申诉复核类问题需要足够的输出长度，满足详细说明的需求 |

## 容易做错的三处
- 现象：配置`maxContext`为10000 token后，部分审核规则解释类问题的输出长度仅约200 token。原因：未同步调整`quoteMaxToken`取值，系统自动限制了单条引用内容的token额度，导致核心规则无法完整加载，最终压缩输出长度。
- 现象：在云空间部署的微信公众号接入FastGPT后，无法找到token相关配置入口。原因：云空间版本的token配置默认隐藏在高级设置模块，需先开启开发者模式才可显示对应字段。
- 现象：知识库切块大小设置为5000 token，引用上限设置为1500 token，仍检索到超出额度的切块内容。原因：切块大小与引用上限的匹配逻辑未对齐，系统优先召回完整切块，未按引用上限截断内容，导致token占用超出预期。

## 怎么确认配好了
- 进入FastGPT v4.17.0的应用配置页面，查看上下文与token相关模块的参数值，确认与预设配置一致。
- 发起一条审核规则解释类测试请求，查看输出内容的长度与token消耗统计，确认符合预设的最大响应token取值。
- 导入一批测试用的审核规则文档，发起检索请求，核对召回的文档条数与匹配精度，确认符合上下文召回条数的设定。
- 查看应用的日志模块，确认上下文更新任务按预设频率执行，无频繁拉取导致的token消耗异常。
