# 内容审核规则运营的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据核心来自内容审核后台、用户举报渠道、公开法规政策与内部审核样本库。日常产出的文档包含审核规则条目、违规处置指南、用户申诉记录与质检报告，字段涵盖规则编号、生效时段、样本标签、处置阈值等。数据更新频率为每日同步或随政策调整即时更新，单条数据体量从数十字符到数千字符不等，无固定统一格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据来源要求引用溯源需标记原始数据的获取渠道，避免混淆内部审核规则与外部政策文本。高频更新特性要求溯源链路支持实时拉取最新版本的审核规则，确保引用内容与当前生效标准一致。非统一格式的文档结构要求溯源配置适配不同字段的提取逻辑，例如从审核规则中提取规则编号，从申诉记录中提取申诉编号。疑难样本与复核场景则要求溯源可快速关联到原始审核样本与质检报告，支撑判定依据的快速验证。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 适配审核规则与样本的单条内容长度，避免截断关键规则条目 |
| `responseData` | 仅返回审核后台、政策文档、申诉记录三类来源 | 限定溯源范围，过滤非合规的外部数据 |
| `detail` | 完整 | 保留原始文档的全部字段，支撑规则解释与申诉复核的细节验证 |
| 最大上下文 | 15000 token | 覆盖多份审核规则与样本的批量引用需求，按实测标定 |
| 单次召回上限 | 前6条 | 匹配日常复核的单轮审核样本数量，避免信息过载 |

## 容易做错的三处
- 现象：配置`quoteMaxToken`时仅可选100或900档位，无法设置300左右的自定义取值。原因：平台默认档位未覆盖中间区间，需通过手动输入自定义参数实现灵活配置。
- 现象：尝试引用HTTP返回的审核后台数据时，系统返回格式错误提示。原因：未配置`responseData`的数据源过滤规则，导致非合规格式的内容被纳入溯源范围。
- 现象：设置最低相关度阈值为1后，仍返回大量无关的引用内容。原因：未限定`detail`的返回字段范围，导致低相关度的冗余字段被纳入溯源链路。

## 怎么确认配好了
- 查看引用溯源的返回结果，确认仅包含审核后台、政策文档、申诉记录三类来源的内容。
- 测试引用单条审核规则，检查返回内容的token数未超出配置的`quoteMaxToken`范围。
- 模拟疑难样本复核场景，验证溯源结果可关联到原始审核样本与质检报告的完整字段。
- 调整`quoteMaxToken`的自定义取值，确认FastGPT v4.17.0版本的平台可保存非默认档位的配置。
