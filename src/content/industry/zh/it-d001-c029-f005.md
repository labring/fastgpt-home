# 内容版权与授权管理的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自合同系统、版权登记信息、内容库与投诉邮箱，日常文档包含授权合同、版权台账、下架通知、侵权投诉材料。数据按每单或月度更新，核心字段包括授权范围、有效期、授权方信息、内容关联ID、侵权事由等，不同文档的字段结构差异明显，授权合同侧重权利边界与使用期限，投诉材料侧重侵权事实与举证材料。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散导致多轮对话需整合多系统内容，提示词需明确指定不同数据源的调用优先级与格式要求。文档结构差异明显，提示词需适配授权合同、投诉材料等不同文档的字段识别规则，避免混淆授权范围与侵权事由等核心字段。按单或月度更新的节奏，要求上下文窗口无需频繁刷新历史数据，可通过固定上下文锚点关联对应业务单的全量材料。同时，多轮对话需保留业务单的关联ID，确保每次交互都能精准匹配对应台账与合同信息，避免跨业务单的数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 最大上下文长度 | 8000–12000 字符 | 本品类核心文档单份授权合同通常不超过3000字符，多轮对话需保留3-4份关联文档与历史交互，该长度符合FastGPT v4.17.0的上下文承载范围 |
| 对话历史保留条数 | 前10条 交互记录 | 本品类业务单的交互通常不超过8轮，保留前10条可覆盖完整业务流程且避免上下文过载 |
| `variables` 变量配置 | `{"authScope": "", "expireDate": "", "contentId": ""}` | 本品类核心处理字段为授权范围、有效期、内容关联ID，需通过变量传递精准匹配业务数据 |
| `chatId` 绑定规则 | 绑定业务单唯一标识 | 需确保每笔版权业务的多轮对话关联同一台账与合同数据，避免跨单混淆 |
| `messages` 初始上下文配置 | 包含授权合同模板与版权台账示例 | 用于快速加载业务场景的初始提示词，减少用户重复输入 |
| 单次工具调用上限 | 3 次 | 本品类核心操作仅需核对授权范围、查询台账、整理投诉材料三类，过多调用会增加交互延迟 |

## 容易做错的三处
- 现象：工具调用结果未在当前对话窗口展示，重新进入后可见但无工具返回标识。原因：未正确绑定`chatId`到业务单标识，导致对话上下文未关联工具调用的缓存数据。
- 现象：无法通过对话url获取参数值用于关联业务单。原因：未启用对话url参数透传配置，或参数命名与预设`variables`变量不匹配。
- 现象：提示词无法动态加载知识库中的模板，调用时返回默认提示词。原因：未开启提示词动态加载配置，或变量传递未匹配知识库模板的占位符规则。

## 怎么确认配好了
- 发起一次授权范围核对的交互，检查对话窗口是否显示关联的授权合同与版权台账内容，确认上下文包含正确的业务单关联数据。
- 触发工具调用操作，检查工具返回结果是否直接展示在当前对话窗口，无延迟或需重新进入才显示的问题。
- 调整iframe嵌入的语言配置，确认界面文本切换为目标语言，验证语言配置生效。
- 提取对话url中的参数，确认可通过`variables`变量获取对应参数值，用于绑定业务单标识。
