# 内部网络与WiFi运维的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据来自交换机控制台、无线控制器、监控系统及用户报障渠道，更新频率为每日或每完成一次变更后。日常产出的文档包含网络拓扑图、变更单、故障记录与无线覆盖巡检表，数据字段包含端口编号、VLAN标识、信号强度值、巡检时间等，无统一强制格式，多为结构化日志与半结构化表格。

## 这些特征在「上下文与 token」这一环带来什么约束
多源异构的数据来源会导致上下文拼接时需兼容不同格式的日志与表格，增加token拆分与对齐的复杂度。高频更新的变更单与故障记录要求上下文需实时同步最新数据，避免评审依据过时。单次评审需关联网络拓扑、历史故障、巡检记录等多份文档，易超出模型输入token上限，导致内容截断或评审逻辑缺失。同时，不同文档的字段差异会导致上下文拼接后token消耗波动较大，难以精准控制整体额度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 12000–16000 token | 适配该品类单次评审需关联多份文档的场景，匹配多数主流大模型的输入token上限，避免内容截断 |
| `quoteMaxToken` | 3000–4000 token | 限制单份引用文档的token占用，防止单条引用过度消耗上下文额度，平衡关联信息完整性与token消耗 |
| 上下文同步间隔 | 每4小时 | 适配该品类数据日更或随变更更新的节奏，平衡实时性与token消耗 |
| 分块长度 | 800–1200 字符 | 适配网络拓扑图、巡检表的单块内容长度，降低上下文拼接时的格式混乱 |
| 单次召回内容上限 | 前6条 | 限制单次加载的关联文档数量，控制总token消耗，避免超出配置的上下文额度 |
本配置方案适用于FastGPT v4.17.0

## 容易做错的三处
- 现象：界面显示输入token超出模型上限，评审结果被截断，且token统计显示输入为31945、输出为12288。原因：未根据该品类多源文档的token消耗调整`maxContext`配置，导致输入token超过模型支持的16384上限。
- 现象：无法通过应用维度准确统计模型的token消耗数量，统计结果与实际评审的文档数量不符。原因：未正确配置上下文关联的文档分类规则，导致token消耗统计未按评审应用维度归集。
- 现象：点击关联文档的查看原始内容按钮后，下载链接无法正常访问，返回错误提示。原因：未正确配置知识库文件的内部访问路径，导致链接指向失效的内部资源地址。

## 怎么确认配好了
- 上传1份完整的网络拓扑图与3份近期故障记录，查看上下文预览区域的token消耗数值，确认未超出`maxContext`的配置值。
- 触发一次变更评审任务，查看token消耗统计面板，确认单份引用文档的token占用未超过`quoteMaxToken`的配置值。
- 等待配置的上下文同步间隔到期后，查看关联的故障记录是否更新为最新版本。
- 点击任意关联文档的查看原始内容按钮，确认下载链接可正常访问且指向正确的内部资源地址。
