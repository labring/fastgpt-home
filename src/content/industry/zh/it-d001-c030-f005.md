# 内部网络与WiFi运维的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自交换机控制台、无线控制器、监控系统及用户报障渠道，更新频率为每日或每完成一次变更。日常关联文档包含网络拓扑图、变更单、故障记录、无线覆盖巡检表，字段涵盖端口编号、VLAN配置、信号强度、故障上报时间等，单位多为无编号、百分比、米等。处理流程中，故障点定位、端口与VLAN核对、覆盖盲区排查为最耗时环节，数据关联变更动作后同步更新。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且绑定单次变更，要求多轮对话需按变更单、拓扑图、故障记录的顺序加载上下文，避免跨变更的无效数据干扰。文档类型多样，提示词需适配不同格式的输入，识别拓扑图中的端口映射、巡检表的信号阈值等专属字段。更新频率随变更触发，需限制上下文窗口大小，避免加载过期的交换机配置数据导致核对错误。故障定位的耗时环节要求多轮对话支持逐步拆解问题，每轮仅聚焦一个核对项，防止上下文过载影响响应速度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前运维变更的唯一标识 | 确保多轮对话上下文与单次变更绑定，避免跨变更的上下文混淆 |
| `messages` | 保留最近20条对话及关联的3份核心文档（拓扑图、变更单、故障记录） | 匹配该品类的核心文档类型与变更关联逻辑，控制上下文长度 |
| `variables` | 预设端口范围、VLAN段、信号阈值变量 | 适配该品类的固定运维参数，减少重复输入 |
| 最大上下文窗口 | 8000 token | 平衡上下文完整性与响应速度，适配每日更新的运维数据量 |
| 单文件上传限制 | 不超过100 MB | 匹配网络拓扑图、巡检表等文档的常规大小 |

## 容易做错的三处
-  在One API接入GLM等第三方模型后，对话模块的模型选择列表仅显示GPT系列，无法选中第三方模型。原因是未在系统配置中开启多模型适配，未将第三方模型的标识与对话模块的选择列表绑定。
-  配置同时支持图片和文件对话时，前端上传正常但接口返回解析失败。原因是未正确配置文档解析的格式规则，未将图片与文本文件的处理逻辑拆分到`variables`中。
-  工作流编排多轮对话后仅返回最终模型结果，无法分步处理中间步骤。原因是未设置`messages`的上下文缓存，未保留中间步骤的处理数据，导致后续步骤无法调用前置结果。

## 怎么确认配好了
-  发起一次变更评审的对话，上传对应拓扑图与变更单，核对对话中是否自动提取了端口编号与VLAN配置。
-  调用模型选择列表，确认已接入的第三方模型是否出现在选项中。
-  触发多轮对话，连续提交3次不同的故障排查问题，确认上下文未丢失之前的变更单信息。
-  上传超过100 MB的测试文件，确认系统返回文件大小超限的提示，验证上传限制配置生效。
