# 内部网络与WiFi运维的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
内部网络与WiFi运维的业务数据主要来自交换机控制台、无线控制器、办公区监控系统及一线用户报障渠道。日常产出的文档包含网络拓扑图、变更单、故障记录与无线覆盖巡检表，数据更新节奏为每日更新或随单次网络变更同步更新。数据字段涵盖端口编号、VLAN配置、无线信号强度、故障上报时间等，无额外标准化统计口径。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源包含硬件控制台与用户报障两类渠道，工具调用需适配多类数据源接口，无法依赖通用文本解析逻辑。数据更新节奏为每日或随变更触发，插件轮询间隔需匹配该节奏，避免过度消耗系统资源。日常文档包含拓扑图、变更单等结构化格式内容，工具需支持解析特定格式的运维文档以提取有效字段。故障定位与VLAN核对为最耗时环节，工具调用需优先触发对应设备数据的拉取，且需配置失败重试机制以应对办公网络中断风险。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，适配内部网络与WiFi运维的代码评审场景：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配交换机、无线控制器等多类运维数据源的自动路由，满足代码评审中多工具联动的需求 |
| `functionCall` | `enabled` | 强制触发工具调用，确保能拉取交换机端口、VLAN配置等核心运维数据 |
| 工具调用超时阈值 | `300–600 秒` | 网络设备数据拉取通常需要较长响应时间，避免过早超时中断评审流程 |
| 插件轮询间隔 | `每 15 分钟` | 匹配数据每日或随变更的更新节奏，避免无效轮询消耗系统资源 |
| 上下文窗口长度 | `8000–12000 字符` | 容纳网络拓扑图、故障记录等长文本运维文档，确保完整解析关键信息 |
| 数据源映射规则 | 按设备类型分组 | 区分交换机、无线控制器等不同数据源，提升工具调用的精准度 |

## 容易做错的三处
- 现象为工具调用按钮置灰，界面提示“未启用工具调用”；原因是将`toolChoice`参数配置为`none`，未开启工具调用权限。
- 现象为调用搜索类插件后返回空结果，无法拉取网络故障相关信息；原因是未配置正确的数据源映射，插件未关联交换机控制台或无线控制器的有效接口。
- 现象为本地部署的模型调用失败，日志显示参数不匹配；原因是FastGPT v4.17.0版本调整了`functionCall`的触发逻辑，未同步更新原有配置参数。

## 怎么确认配好了
- 发起一次模拟网络变更评审请求，查看工具调用日志，确认是否成功拉取到交换机端口或无线控制器的配置数据。
- 进入插件管理页面，检查各运维数据源的连接状态，确认无异常报错或断开提示。
- 上传一份故障记录文档，触发工具调用，确认解析结果中包含对应VLAN配置或故障点定位信息。
- 模拟长文本数据拉取场景，验证工具调用是否在300–600秒内完成响应，未触发超时报错。
