# 创作者激励结算的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
创作者激励结算的核心数据来自内容数据、广告分成系统、财务系统、账号后台，更新频率为月或单次活动周期。日常关联文档包含激励规则、结算明细、申诉记录、付款清单，字段涵盖创作者唯一标识、收益计算口径、结算周期、付款状态等，单位涉及元、条、人次等。数据结构随活动周期更新，单次活动涉及的结算明细条目较多，需关联多系统数据完成校验与溯源。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多数据源的接入要求溯源配置需关联内容、财务、账号等多个系统的标识字段，确保每一条结算记录可追溯至原始生成节点。月/活动级的更新节奏要求引用需锁定对应周期的文档版本，避免跨周期数据混淆。文档结构的差异（如激励规则为文本说明、结算明细为结构化表格）要求溯源配置适配不同格式的内容提取。出错后果关联结算争议与创作者流失，要求溯源信息不可伪造且可快速定位异常条目。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 结算类文档包含多字段的结构化内容，需足够token承载完整的引用溯源信息 |
| `responseData` | 仅返回匹配的结算明细、付款清单字段 | 聚焦业务核心数据，避免无关内容占用上下文 |
| `detail` | 开启全字段溯源 | 覆盖创作者ID、收益金额、结算周期等全部业务字段，满足评审核对需求 |
| 单次搜索上限 | 前5条 | 控制返回结果数量，避免冗余信息干扰代码评审逻辑 |
| 超时阈值 | 600 秒 | 跨系统查询财务、内容数据耗时较长，预留足够响应时间 |

## 容易做错的三处
- 选择知识库搜索节点的变量应用后，引用变量下拉框无可选内容。原因是未在全局变量管理中配置与目标知识库绑定的动态变量项，导致系统无法识别可调用的知识库选项。
- 日志中无法区分不同来源的结算数据。原因是未在溯源配置中添加数据源标识字段，未将内容数据、财务系统数据的来源标签嵌入引用信息。
- 大模型输出伪造的引用ID。原因是未绑定真实的激励规则、结算明细等数据源，仅依赖大模型生成的虚拟内容生成引用标记，未关联实际业务文档。

## 怎么确认配好了
- 触发代码评审流程，查看输出结果中的引用标记是否对应真实的结算文档ID与数据源标识。
- 测试动态指定知识库功能，确认选择变量后可加载对应周期的激励规则或结算明细文档。
- 查看系统日志，确认不同来源的业务数据被正确标记并关联至对应的引用条目。
- 验证大模型输出内容，确认无自动生成的引用标记，仅保留配置的溯源链接与字段信息。
