# 前端应用开发的代码与变更评审辅助：上下文与 token

本文适配FastGPT v4.17.0版本，面向前端应用开发的代码与变更评审辅助场景，以下为该场景下上下文与token配置的详细说明。

## 这个品类的数据长什么样
该品类的数据主要来自代码仓库、接口管理平台、设计稿文件与浏览器兼容性数据库。日常关联文档包含接口文档、组件使用说明、联调记录与版本发布清单。数据更新频率为每日或随版本迭代同步更新，字段覆盖代码行数、接口参数、设计稿尺寸、兼容性兼容版本等，无统一固定格式，随项目技术栈与团队规范调整。

## 这些特征在「上下文与 token」这一环带来什么约束
代码仓库的代码文件体量随项目迭代增长，上下文召回需匹配前端组件、接口调用逻辑的关联关系，避免冗余token消耗。接口文档与联调记录的更新频率较高，需确保召回的上下文为最新版本，否则会导致评审结果偏差。设计稿与兼容性数据的格式差异较大，需适配多类型数据源的上下文拆分规则，防止token超限或召回内容不匹配。前端评审的上下文需覆盖页面状态、终端适配细节，上下文长度约束需匹配单页面代码与关联资源的总token上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 对应`maxContext`参数，匹配前端单页面核心代码与关联文档的总长度，避免超出模型上下文窗口 |
| 单次召回上下文条数 | 前 3–5 条 | 覆盖当前评审变更涉及的组件、接口与联调记录，控制总token消耗 |
| 单段引用token上限 | 1500–2000 token | 对应`quoteMaxToken`参数，适配前端代码片段与文档段落的平均长度，防止单段内容超限截断 |
| 上下文匹配阈值 | 0.75–0.85 | 过滤低关联度的历史联调记录与兼容性数据，提升评审精准度 |
| 上下文更新频率 | 按版本迭代同步 | 匹配前端项目的版本发布节奏，确保召回内容为最新版本 |

## 容易做错的三处
- 配置最大上下文长度超过模型原生窗口上限，触发模型返回token超限报错，或返回不完整的评审内容。原因是未结合前端单页面代码与关联文档的总体量调整参数，盲目拉取全量历史数据。
- 未限定召回的上下文范围，仅返回全量历史联调记录与兼容性数据，导致搜索结果与当前代码变更无关，无法辅助评审。原因是未配置上下文匹配阈值，未关联当前变更的代码仓库路径与接口文档，覆盖用户常咨询的上下文关联配置问题。
- 未设置单段引用token上限，导致长代码片段或设计稿说明被截断，评审遗漏关键页面状态实现细节。原因是未适配前端代码片段的平均长度，未对上下文做合理拆分。

## 怎么确认配好了
- 查看FastGPT后台的上下文召回日志，核对召回的文档类型与数量是否符合当前评审的关联范围，调整配置项直至匹配。
- 测试输入一段前端代码变更的问题，检查返回的评审内容是否包含关联的接口文档、组件说明与联调记录，确认上下文关联逻辑生效。
- 模拟长代码片段的评审场景，检查返回内容是否被完整召回，未出现截断情况，确认单段引用token上限配置合理。
- 查看数据源更新记录，确认上下文召回的内容为当前版本的最新文档，匹配项目的迭代节奏。
