# 办公系统流程配置的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自企业OA系统、组织架构库、内部制度文件及一线用户反馈。日常产出的文档包含流程配置单、审批节点表、表单字段说明与变更记录。数据更新随流程变更触发，每月至少完成一轮全量校验更新。数据字段涵盖审批节点权限、流转路径规则、表单校验逻辑，单位多为节点序号、权限范围、执行周期等业务化表述，无标准化技术单位。

## 这些特征在「上下文与 token」这一环带来什么约束
流程配置类数据的业务关联性强，单份配置单可能关联多个审批节点与权限规则，上下文窗口需覆盖完整的关联逻辑链，避免截断关键流转路径。数据更新频率随变更波动，新增或调整流程时需同步更新知识库，否则上下文会召回过期的规则片段。字段多为业务化表述，需精准匹配节点名称、权限范围等细节，token消耗会随关联节点数量提升。部分变更记录仅留存关键节点调整，上下文召回需区分有效变更与无效备注，减少无效token占用。

## 配置怎么定
本配置方案适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口 | 8000–12000 token | 办公系统流程配置的单份文档通常包含多审批节点与关联规则，需覆盖完整业务逻辑链 |
| `maxContext` | 按业务文档平均token数上浮20% | 适配流程配置类数据的关联复杂度，避免截断关键节点权限信息 |
| 召回上下文条数 | 前3–5条 | 流程配置的关联规则多集中在3个以内的节点组，过多召回会增加token消耗 |
| `quoteMaxToken` | 1500–2000 token | 单条流程配置的核心规则片段通常不超过该范围，避免冗余内容占用上下文 |
| 自动分段长度 | 800–1000 字符 | 匹配流程配置单的单节点描述长度，保证分段内逻辑完整 |

## 容易做错的三处
- 配置后出现审批规则匹配偏差，返回旧版流程节点。原因是未同步更新知识库的流程配置数据，上下文召回了过期的变更记录片段。
- 系统提示上下文溢出，单次请求token超限。原因是未限制`maxContext`窗口大小，直接加载了全量流程文档导致token消耗超标。
- 分段后出现节点逻辑断裂，权限说明被截断。原因是将自动分段长度设置为token单位，而流程配置的字段多为字符化业务描述，导致分段截断了完整的权限说明。

## 怎么确认配好了
- 上传单份完整的流程配置单，检查上下文召回结果是否包含当前生效的审批节点与权限规则。
- 模拟发起变更评审请求，查看系统返回的token消耗数值是否在配置的`maxContext`范围内。
- 对比分段后的片段内容，确认每个分段都包含完整的单节点或关联规则逻辑，无截断情况。
- 上传一份过期的流程变更记录，验证召回结果是否优先匹配最新版本的配置数据。
