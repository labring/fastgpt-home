# 办公系统流程配置的代码与变更评审辅助：多轮对话与提示词

以下配置项适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
办公系统流程配置的核心数据来自OA系统、组织架构、内部制度文件与用户反馈。日常维护的文档包括流程配置单、审批节点表、表单字段说明与变更记录。数据更新节奏随流程变更触发，无固定周期。数据字段包含审批节点标识、权限范围、表单配置项与关联制度条目，无统一的标准化统计单位，仅按流程配置的实际需求定义字段内容。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据随流程变更更新，对话上下文需严格关联当前流程的唯一标识，避免跨流程的无效上下文干扰。分散的文档结构要求提示词需引导模型优先调用品类自有文档生成内容。数据无固定统计单位的特征，要求对话中需明确字段的业务含义，避免生成不符合实际配置的内容。同时，流程配置出错会导致审批阻塞，因此对话的容错与校验机制需适配内部数据的严谨性要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前流程变更的唯一标识 | 关联对应流程的对话历史，避免跨流程上下文混淆 |
| `messages` | 保留最近3次交互+关联流程文档的上下文 | 适配流程配置数据低更新频率的特征，减少无效上下文占用 |
| `variables` | 引用流程配置单、审批节点表的内置字段 | 直接调用品类自有数据生成配置建议，提升内容准确性 |
| 大模型温度 | 0.2–0.4 | 流程配置需严谨，避免生成不符合内部制度的内容 |
| 插件调用超时 | 600秒 | 适配流程配置的测试验证环节耗时，避免提前中断交互 |

## 容易做错的三处
- 多次提问后无法获取历史问题，原因是未绑定`chatId`到流程变更的唯一标识，导致对话上下文未关联对应流程的配置数据。
- 选择变量引用大模型时无温度设置按钮，原因是未通过`variables`绑定模型的可调参配置项，直接调用了固定参数的模型接口。
- 数据库连接插件配置后调用报错，且对话回传耗时超过600秒，原因是未配置插件的权限校验规则，同时未限制单次查询的数据量，导致内部数据请求阻塞。

## 怎么确认配好了
- 发起一次测试提问，检查对话历史中是否保留了前一次的交互内容，确认`chatId`绑定生效。
- 进入大模型配置界面，查看是否出现温度参数的设置入口，确认`variables`关联正确。
- 调用数据库连接插件执行一次流程数据查询，检查是否返回预期结果且耗时符合预设要求。
- 发起多轮连续提问，检查每次回复是否基于当前流程的配置文档，确认上下文关联正确。
