# 办公系统流程配置的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
该品类的典型使用主体为企业信息化管理员、OA管理员、业务流程管理员，日常产出与维护的文档包括流程配置单、审批节点表、表单字段说明、变更记录。数据来源主要为OA系统、组织架构数据、内部制度文件与用户反馈，更新频率随流程变更触发，通常每月至少一次。最耗时的工作环节为审批规则梳理、节点权限配置与测试验证，出错后可能导致审批卡住、权限错误或制度执行偏差。与身份账号与权限管理品类不同，该品类聚焦业务审批路径与表单配置。

## 这些特征在「工具调用与插件」这一环带来什么约束
日常文档的结构化特征要求工具调用参数需匹配审批节点、表单字段等具体配置项，避免调用结果与流程逻辑脱节。数据更新频率较低的特点，决定了插件调用结果的缓存策略需适配变更节奏，减少重复调用的资源消耗。出错后果严重的属性，要求工具调用环节需配置失败重试与异常告警机制，防止流程阻塞。同时，该品类的工作场景多为内部办公系统集成，工具调用的权限范围需严格限定在企业内部资源，避免越权访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 适配办公流程配置的多步骤审批调用需求，自动匹配对应节点的工具类型 |
| `functionCall` | `enabled` | 支持调用自定义插件完成审批规则校验、权限验证等流程配置逻辑 |
| 插件调用超时时间 | `300 秒` | 匹配办公流程审批节点的常规响应时长，避免阻塞整体流程 |
| 插件返回结果缓存时长 | `7 天` | 适配该品类数据每变更/月的更新频率，平衡实时性与资源占用 |
| 单次插件调用结果条数 | `前10条` | 适配办公流程配置的审批节点信息展示需求，避免信息过载 |

## 容易做错的三处
- 调用自定义插件时返回固定域名`api.example.com`无法访问，原因是未在插件配置中替换为企业内部OA系统的实际API域名。
- 调用`/api/core/dataset/update`接口时返回500错误，浏览器访问正常，原因是未配置办公系统流程配置的API调用权限白名单，导致接口被拦截。
- 工作流中调用其他模型时无法实现流式输出，原因是未开启`functionCall`对应的流式回调配置，或未匹配办公流程配置的审批节点输出格式要求。

## 怎么确认配好了
- 发起模拟审批流程，触发插件调用，检查返回结果是否与预设的审批规则、表单字段要求一致。
- 查看FastGPT v4.17.0的插件调用日志，确认`toolChoice`与`functionCall`的配置参数已正常加载。
- 测试接口调用，验证配置的超时时间与缓存时长是否符合预期，无异常报错。
- 提交正式的流程配置变更，观察流程运行状态，确认插件调用未出现阻塞或权限异常。
