# 办公系统流程配置的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
办公系统流程配置的核心数据来源于企业OA系统、组织架构、内部制度文件及用户反馈。日常维护的文档包括流程配置单、审批节点表、表单字段说明与变更记录。数据更新节奏随业务变更触发，通常每月至少更新一次。数据字段包含审批节点权限规则、表单校验逻辑、流程流转路径等，无统一固定单位，仅以配置项名称、节点编号、权限范围作为标识维度。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于核心数据来自OA系统的流程配置类文档，溯源需精准关联到具体的审批节点、表单规则或变更记录，无法仅依赖泛化的文档标题。数据更新频率随业务变更调整，需定期刷新引用的数据源快照，避免溯源信息滞后于最新配置。文档结构以配置项明细为主，引用时需明确对应字段的具体内容，否则会导致审批辅助的溯源参考价值降低。同时，数据关联的权限规则直接影响业务执行，溯源偏差可能引发审批卡住或权限错误，因此需严格匹配数据源的版本与变更时间。

## 配置怎么定
本文适配FastGPT v4.17.0版本的配置逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `1500–2500 token` | 办公系统流程配置的单份文档通常篇幅适中，该区间可覆盖核心配置内容且避免token溢出 |
| `responseData` | 包含文档路径、更新时间、节点编号 | 可直接关联到流程配置单、审批节点表等核心文档，满足溯源需求 |
| `detail` | 开启 | 可展示配置项的具体规则细节，增强溯源的参考性 |
| 引用文档数量上限 | `前3–5条` | 办公系统流程配置的相关文档数量有限，限制条数可避免回答冗余 |
| 提示词语言匹配 | 按源文档语种自动适配 | 可匹配中文或英文的流程配置文档，满足多语种溯源需求 |

## 容易做错的三处
- 现象：知识库页面未展示引用文档的出处信息。原因：未开启`responseData`对应的溯源展示配置，导致响应数据未包含文档路径与更新时间。
- 现象：单轮回答token超过系统限制，甚至超出预设的2000 token阈值。原因：`quoteMaxToken`设置过高，加载的流程配置文档分块后token总和超出当前会话的token上限。
- 现象：引用的文档与当前查询的流程配置无关，出现冗余内容。原因：未限制引用文档的数量上限，导致系统加载过多不相关的审批节点表或配置单。

## 怎么确认配好了
- 发起基于办公系统流程配置文档的查询，查看回答末尾是否展示文档路径、更新时间等溯源信息。
- 调整`quoteMaxToken`参数后，验证回答的token消耗是否在合理区间内，无明显溢出情况。
- 测试不同类型的流程配置查询，确认返回的引用文档均为审批节点表、流程配置单等相关品类文档。
- 检查提示词是否自动匹配源文档的语种，确保溯源文案与文档语言一致。
