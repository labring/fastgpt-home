# 单元测试与组件测试的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本品类数据主要来自代码仓库、测试框架报告、需求说明与接口定义，更新频率为每日或每代码提交一次。日常关联文档包含测试用例、覆盖率报告、Mock说明与缺陷单。测试用例包含用例标识、前置条件、执行步骤与验证规则；Mock说明包含依赖接口定义、模拟返回规则；缺陷单包含关联提交哈希与测试环节标识。数据字段多与代码提交、测试执行动作绑定，无跨环节的冗余关联字段。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类数据的高频更新特性要求上下文同步最新的测试用例、Mock说明与缺陷单，避免使用过期的测试配置或执行记录。数据与代码提交绑定的特性，要求上下文关联对应提交的测试数据，防止跨版本的测试逻辑混淆。分散的文档结构要求限定召回的文档类型，仅纳入单元测试与组件测试相关的测试用例、覆盖率报告与Mock说明，避免无关数据占用token。数据规模随代码提交量增长，需要严格控制召回条数与上下文总token数，防止超出模型承载上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 16000–32000 token | 匹配当前主流大模型的上下文承载上限，适配单元测试与组件测试的多文档召回需求 |
| 单次搜索召回上限 | 前8条 | 控制单轮召回的token消耗，避免超出`maxContext`限制 |
| 分块长度 | 800–1200 字符 | 适配测试用例、Mock说明的单段内容长度，减少分块后的无效关联 |
| 重叠长度 | 100–200 字符 | 保证跨分块的测试逻辑关联不被截断 |
| `quoteMaxToken` | 2000–4000 token | 限定单条召回文档的最大token数，避免单条数据占用过多上下文空间 |
| 相似度阈值 | 按实测标定 | 适配测试数据的语义匹配精度，避免召回无关的测试用例或缺陷单 |

## 容易做错的三处
- 现象：调用时提示Reached the max retries per request limit，原因：未正确关联测试数据的上下文更新频率，导致频繁触发重试校验，超出请求重试上限。
- 现象：单轮对话token消耗超出预期，原因：未设置`quoteMaxToken`限制，召回了过长的覆盖率报告或缺陷单数据，导致token占用超标。
- 现象：测试用例召回结果条数异常，原因：未合理配置单次搜索召回上限，导致召回过多无关数据，或相似度阈值设置过低，召回了非目标测试用例。

## 怎么确认配好了
以下核对动作适配FastGPT v4.17.0版本：
- 查看系统日志，确认每次召回的文档类型均为测试用例、Mock说明、覆盖率报告与缺陷单，无无关数据混入。
- 核对单轮对话的token消耗数据，确认未超出`maxContext`设置的上限，可根据实际测试数据规模调整取值。
- 提交一次代码变更，触发评审辅助流程，确认召回的测试数据与当前提交关联，无跨版本的历史数据。
- 模拟边界条件的测试用例评审，确认召回的相关测试数据覆盖了对应边界场景。
