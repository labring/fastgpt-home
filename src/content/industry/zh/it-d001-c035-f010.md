# 单元测试与组件测试的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自代码仓库的单元测试与组件测试脚本、测试框架生成的覆盖率报告、Mock依赖说明文档，以及需求关联的接口定义文档。更新频率为每日或每次代码提交后。日常关联文档包括测试用例、覆盖率统计结果、Mock配置说明、缺陷跟踪单，每条数据包含测试用例标识、对应代码模块路径、执行结果、关联需求编号等字段，无额外预设统计指标。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且更新频繁，要求溯源环节需支持跨多类文档的元数据关联，同时需适配每日或按提交触发的实时同步节奏。日常文档结构多样，包含脚本、报告、说明单等不同格式，需识别不同文档的专属字段，如测试用例标识、覆盖率指标等。数据直接绑定具体代码模块，溯源结果需精准指向对应代码单元与测试执行记录，不能泛化关联，否则无法支撑工程师定位测试缺口或缺陷根源。

## 配置怎么定
本文档基于 FastGPT v4.17.0 版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 2000–4000 token | 适配单元测试与组件测试文档的单条内容长度，避免截断关键测试用例或覆盖率数据 |
| 召回结果条数 | 前3–5条 | 匹配该品类数据与代码模块的关联密度，避免过多无关测试记录干扰溯源 |
| `responseData` | 开启完整来源字段 | 提取并展示测试文档的元数据，帮助工程师快速定位对应测试脚本或报告 |
| 数据同步触发时机 | 按提交触发 | 匹配数据日更或按提交更新的节奏，保证溯源数据的实时性 |
| 召回相似度阈值 | 0.7–0.8 | 匹配测试文档的语义相似度分布，精准召回对应代码单元的测试数据 |
| `detail` | 开启详细溯源模式 | 精准召回对应代码单元的测试数据，避免泛化关联 |
| 上下文窗口大小 | 按实测标定 | 适配不同规模的测试文档集合，避免上下文溢出影响召回精度 |

## 容易做错的三处
- 现象：AI回答未展示任何引用来源，或引用内容被截断。原因：`quoteMaxToken`设置过小，或未开启`responseData`配置，导致无法提取并展示测试文档的来源信息。
- 现象：召回结果中未出现目标测试用例或覆盖率报告。原因：召回相似度阈值设置不符合当前测试文档的语义分布，导致匹配精度不足。
- 现象：溯源结果指向无关的代码模块或旧测试数据。原因：数据同步触发时机未设置为按提交触发，导致旧的测试数据混入当前代码变更的溯源结果中。

## 怎么确认配好了
- 提交一次测试代码变更，触发FastGPT的知识库同步，查看同步日志确认测试用例、覆盖率报告等文档已被成功索引。
- 输入对应代码模块的测试相关问题，查看AI回答的引用来源列表，核对是否包含目标测试文档的标识与路径。
- 调整`quoteMaxToken`或召回相似度阈值后，重新发起测试查询，对比前后召回结果的数量与相关性，确认配置已生效。
- 开启`detail`配置后，查看AI回答的溯源详情，确认每个引用来源都包含完整的代码路径与测试用例标识。
