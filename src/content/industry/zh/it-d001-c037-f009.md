# 发布管理与版本验收的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
该品类的数据通常来自CI流水线、变更系统、测试报告与监控看板，更新频率为周度或每版本发布周期。日常关联文档包含发布计划、上线清单、验收报告与回滚预案，各文档字段对应发布项名称、变更ID、测试通过率、监控指标阈值等，无统一固定单位，字段随版本发布节奏动态更新。数据围绕从构建到生产发布的全流程控制展开，区别于代码合并评审的代码质量校验环节。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且关联多系统，工具调用需适配多源数据拉取权限，需配置跨系统数据同步触发规则。更新频率随版本周期波动，工具调用需支持按版本节奏触发，适配非固定的更新节奏。日常文档字段无统一格式，工具调用需支持自定义字段映射规则，适配不同团队的发布文档结构。出错后果直接影响生产环境，工具调用需配置失败回滚与告警触发逻辑，确保异常时可快速响应。上线窗口协调依赖跨团队信息，工具调用需支持权限校验与多节点数据聚合。

## 配置怎么定
本配置适用于 FastGPT v4.17.0 版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 工具调用触发时机 | 按版本发布节点触发 | 匹配该品类按版本周期更新的数据特征，避免无效调用 |
| `toolChoice` | auto | 适配多工具按需调用的场景，支持自动选择匹配发布管理流程的工具 |
| `functionCall` | 仅绑定发布管理与变更评审工具 | 限定调用范围，避免无关工具干扰发布流程 |
| 字段映射规则 | 自定义映射发布计划、上线清单字段 | 适配该品类文档无统一格式的特征 |
| 失败重试次数 | 3 次 | 覆盖CI流水线偶发调用失败的场景，按实测标定调整 |
| 告警触发阈值 | 调用超时 600 秒后触发 | 匹配生产环境异常响应的时间要求 |
| 单次拉取数据上限 | 前 100 条 | 适配CI流水线单次返回的数据量，避免系统过载 |

## 容易做错的三处
- 现象：调用第三方API时返回跨域相关报错，状态码包含CORS关键字。原因：未配置FastGPT平台的跨域访问白名单，未允许目标API的调用域名。
- 现象：高级编排工具调用无法自动匹配目标工具，返回无可用执行工具的提示。原因：未将`toolChoice`参数设置为auto模式，或未绑定对应工具的调用权限。
- 现象：工作流调用关联的发布文档数据为空，无法完成检索或校验。原因：未配置自定义字段映射规则，导致CI流水线与变更系统的字段无法正确传递到工具调用流程。

## 怎么确认配好了
- 触发一次模拟版本发布流程，检查工具调用日志是否正确拉取CI流水线与变更系统的对应数据。
- 查看高级编排的工具配置页面，确认`toolChoice`与`functionCall`参数已按需求设置。
- 模拟调用失败场景，检查是否触发预设的告警与回滚逻辑。
- 验证跨域配置，使用浏览器直接调用目标API，确认返回结果正常。
