# 变更管理与发布窗口的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
变更管理与发布窗口的核心数据来源于变更管理系统、CI流水线、监控数据与业务日历，更新频率为周度或单次变更触发。日常关联文档包括变更申请单、风险评估报告、上线窗口计划与回退预案，字段涵盖变更唯一标识、申请时间、窗口时段、风险等级、回退触发条件等，单位包含小时、天与字符串标识，数据随变更流程推进实时或周期性更新。

## 这些特征在「上下文与 token」这一环带来什么约束
多源异构的数据来源要求上下文整合需兼容不同格式的文档片段，避免无效内容占用token。周/单次变更的更新节奏要求上下文需按需刷新，不宜长期缓存过期数据。特定的文档字段结构要求token截取需精准匹配变更评审的核心需求，例如仅提取风险评估与窗口计划内容。FastGPT v4.17.0 针对该场景优化了上下文适配逻辑，需确保配置与数据特征对齐，避免请求超时或内容冗余。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配变更管理多源数据的整合量，避免超出通用大模型的上下文窗口限制 |
| `quoteMaxToken` | 1500–2000 字符 | 覆盖单份变更文档的核心片段，包含风险评估与上线窗口的关键信息 |
| 上下文匹配阈值 | 0.75–0.85 | 过滤低相关的历史变更数据，减少无效token消耗 |
| 单次召回条数 | 前3条 | 匹配周/单次变更的更新频率，避免加载冗余的历史数据 |
| 上下文刷新时机 | 每变更提交后 | 对齐变更数据的更新节奏，保证评审上下文的时效性 |

## 容易做错的三处
- 现象：启动变更评审辅助时提示AIPROXY_API_ENDPOINT or AIPROXY_API_TOKEN is not set；原因：未在App/Admin服务端配置AIPROXY_API_ENDPOINT（AI Proxy服务的根地址）和非空AIPROXY_API_TOKEN（AI Proxy管理员Token）这两个必填环境变量，导致服务启动校验失败。
- 现象：变更评审返回的上下文包含无关的历史回退预案内容；原因：未设置合理的上下文匹配阈值，召回了超出当前变更范围的历史数据。
- 现象：单次变更评审的token消耗超出模型限制导致请求失败；原因：未限制`maxContext`的取值，加载了过多跨周期的变更数据。

## 怎么确认配好了
- 查看系统环境变量配置，确认AIPROXY_API_ENDPOINT与AIPROXY_API_TOKEN已配置。
- 触发一次测试变更评审，检查返回的上下文片段是否覆盖当前变更的核心文档内容。
- 查看token消耗统计面板，确认可按应用维度查看模型token使用情况。
- 上传一份测试变更文档，验证原始内容下载功能正常。
