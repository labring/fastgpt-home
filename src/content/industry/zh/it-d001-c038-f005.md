# 变更管理与发布窗口的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源于变更管理系统、CI流水线、业务监控数据与业务日历。日常关联文档包括变更申请单、变更风险评估表、生产上线窗口计划表、回退执行方案。数据更新节奏为每周或随单次变更触发。文档字段包含变更编号、影响范围、风险等级、窗口时段、回退触发条件等，均为标准化文本与时间格式，无额外自定义单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据来源分散且随单次变更更新，要求多轮对话需绑定`chatId`实现会话隔离，避免跨变更评审数据混淆。文档字段为标准化格式，提示词需固定调用变更编号、窗口时段等字段，避免格式偏差。数据关联生产变更风险，多轮对话需在提示词中加入风险校验规则，确保输出内容符合变更审批要求。同时，由于数据更新随变更触发，对话上下文需支持按会话动态刷新，适配单次变更的评审流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前变更的唯一标识 | 实现多轮对话的会话隔离，避免不同变更的评审数据混淆 |
| `messages` | 存储当前变更的历史交互与关联文档片段 | 支持多轮回溯评审过程中的风险评估、审批意见等内容 |
| `variables` | 预设变更编号、窗口时段、回退条件等标准化字段 | 适配品类文档的固定格式，简化提示词编写 |
| 最大上下文长度 | 8000–12000 token | 覆盖单次变更的完整评审文档与交互历史，防止关键信息截断，符合FastGPT v4.17.0的上下文处理规则 |
| 会话更新触发规则 | 随单次变更提交触发 | 匹配本品类数据按变更更新的节奏，确保上下文与当前变更同步 |

## 容易做错的三处
- 现象：使用通用全局key发起对话时，不同变更的评审数据互相串扰，出现非当前变更的风险评估内容。原因：未绑定`chatId`实现会话隔离，导致不同变更的上下文未正确区分。
- 现象：配置中英文开场白后，工作流中仅加载单一语言的开场白内容。原因：未在工作流变量中绑定中英文触发条件，导致语言切换逻辑失效。
- 现象：工具调用后界面同时显示工具执行日志与AI回复内容，未仅输出AI对话结果。原因：未在提示词中明确要求隐藏工具调用的过程信息，导致冗余内容展示。

## 怎么确认配好了
- 发起一次模拟变更评审对话，检查对话上下文是否仅包含当前变更的相关文档与交互内容。
- 调用预设变量，确认`variables`中配置的变更编号、窗口时段等字段是否正确加载。
- 触发工具调用流程，检查输出内容是否仅保留AI对话结果，无工具执行日志。
- 切换不同变更会话，确认`chatId`绑定的会话数据不会互相串扰。
