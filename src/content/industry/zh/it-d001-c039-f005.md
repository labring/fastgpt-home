# 后端服务开发的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
后端服务开发的代码与变更评审相关数据，主要来源于代码仓库、API网关日志、数据库与配置中心，更新频率为每日或每版本发布周期。日常关联文档包含接口设计文档、数据库变更单、代码评审记录与发布说明，其中接口设计文档包含请求参数、返回码等字段，数据库变更单包含表名、DDL语句内容，代码评审记录包含变更范围与评审意见条目。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源的多样性要求多轮对话需支持关联不同格式的数据源，同时需按项目分支、变更版本筛选有效上下文。高频更新的评审数据需要提示词定期同步最新的变更单与代码片段，避免使用过时信息。接口契约确认、事务边界处理这类耗时环节，需要多轮对话逐步梳理细节，因此需限制上下文的token消耗，防止模型截断关键信息。后端服务出错后果直接影响业务稳定性，多轮对话的提示词需精准关联当前评审的代码与日志数据，避免无关内容干扰判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文token数 | 前8000–12000 token，按实测标定 | 后端服务评审数据包含代码片段、变更单与日志，过长上下文会导致模型截断关键信息 |
| 单次响应token上限 | 3000–5000 token | 覆盖长代码评审与变更说明的回复需求，避免复杂问题被自动限制为低阈值 |
| `chatId`绑定规则 | 绑定单次评审会话的唯一标识 | 确保多轮对话的上下文保持一致，避免会话间数据混淆 |
| `variables`传入参数 | 传入当前变更的项目ID、分支名 | 精准定位当前评审关联的项目数据，提升上下文相关性 |
| 知识库关联范围 | 绑定当前项目的代码仓库、API网关日志库 | 匹配后端服务评审数据的来源，确保召回内容与当前评审场景匹配 |
| 全局token统计查看路径 | FastGPT v4.17.0系统设置的全局监控模块 | 方便实时查看会话token消耗，及时调整配置 |

## 容易做错的三处
- 现象：部分复杂问题的响应token被自动限制为200，回复内容过短。原因：未单独设置复杂问题的响应token上限，默认触发了全局的低阈值限制。
- 现象：无法将对话中的评审意见添加到知识库。原因：未开启对话内容同步知识库的开关，或未指定目标知识库的关联路径。
- 现象：高级编排无法一次发送两条消息。原因：未正确配置`messages`参数的数组结构，未按会话顺序添加两条待发送的消息对象。

## 怎么确认配好了
- 发起包含长代码片段的测试对话，查看响应内容是否完整，未出现提前截断的情况。
- 进入全局监控模块，查看当前会话的token消耗统计，确认与配置的上限匹配。
- 向对话中添加一条评审意见，检查是否可以手动同步到绑定的知识库中。
- 配置`chatId`后发起多轮对话，确认后续消息都被关联到同一会话上下文。
