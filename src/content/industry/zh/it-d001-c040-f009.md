# 售前技术方案的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
本内容基于FastGPT v4.17.0版本。该品类的数据通常来自客户访谈、招标文件、厂商产品资料与历史项目方案，更新频率为每单或每周。日常产出的文档包含技术方案书、客户需求调研表、报价清单与演示脚本，文档字段多包含技术路线、实施边界、报价明细、演示场景等，无统一强制单位，需匹配项目实际需求。典型使用主体为系统集成商售前顾问、解决方案架构师与销售团队，核心文档需围绕客户需求动态调整边界与配置。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源分散的数据来源要求工具调用支持整合不同渠道的信息，快速归集客户需求与厂商产品参数。按单或每周的更新节奏要求插件支持动态拉取最新的招标文件、产品资料，避免使用过时数据。多样的文档结构要求工具调用支持自定义字段映射，适配不同项目的方案格式。严重的出错后果要求工具调用配置校验机制，提前拦截超范围的技术承诺与错误的报价配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用触发时机 | 方案评审节点前24小时 | 匹配售前方案按单更新的节奏，预留校验与调整时间 |
| `toolChoice` 参数配置 | 自动 | 适配售前顾问无需手动选择工具的使用习惯，提升操作效率 |
| 插件数据源拉取间隔 | 每12小时 | 平衡数据时效性与系统资源占用，匹配每周的更新频率 |
| `functionCall` 输出映射规则 | 按数据源类型配置 | 适配不同数据源的返回格式，确保输出符合方案评审需求 |
| 异常结果拦截阈值 | 按实测标定 | 适配不同项目的需求边界差异，避免误拦截有效配置 |

## 容易做错的三处
- 现象：数据源插件返回数据库连接结构，未返回SQL执行结果。原因：未配置`functionCall`的输出解析规则，仅拉取了数据库连接的元数据信息。
- 现象：工作流调用外部接口时无法传入动态变化的token参数。原因：未将token设置为工作流的可传递输入项，参数固定为单项目值，无法适配多场景调用。
- 现象：并发调用工具后出现前端无响应。原因：未配置工具调用的并发控制与超时拦截机制，未匹配售前方案按单更新的节奏导致资源临时过载。

## 怎么确认配好了
- 手动触发一次数据源插件调用，检查返回结果是否包含预期的SQL执行内容，确认`functionCall`的输出映射配置生效。
- 传入动态token参数调用外部接口，检查接口请求头是否携带正确的参数值，确认工作流的参数传递规则配置正确。
- 模拟多并发调用工具，观察系统资源占用与前端响应状态，确认并发阈值与超时机制配置符合项目需求。
- 检查插件拉取的数据源是否为最新的招标文件或厂商产品资料，确认拉取间隔配置匹配更新节奏。
