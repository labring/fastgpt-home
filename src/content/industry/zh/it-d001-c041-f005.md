# 图像标注项目的代码与变更评审辅助：多轮对话与提示词
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
图像标注项目的数据通常来自标注平台产出的图片样本、类别字典、质检报告与返工清单，更新频率为每日或按标注批次同步。日常关联文档包含标注规范、框选样例、抽检结果记录等，数据字段包含目标边界框的像素坐标、标注类别、返工标记等，整体围绕视觉目标的位置与类别信息展开，服务于计算机视觉模型训练的标注环节。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
图像标注项目的数据围绕视觉目标的位置与类别展开，且按批次或每日更新，多轮对话需精准匹配当前标注批次的类别字典与返工清单，避免跨批次数据混淆。视觉类数据的字段包含像素坐标等非文本信息，提示词需明确指定数据格式与检索范围，确保对话返回的内容符合标注规范。频繁的更新节奏要求对话上下文能够实时加载最新的质检报告与返工记录，保障评审环节的信息时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chatId` | 绑定当前标注批次的唯一标识 | 区分不同标注批次的对话上下文，避免跨批次数据混淆 |
| `messages` | 保留最近20条对话与3份最新标注文档 | 控制上下文长度，适配标注数据的批次更新节奏 |
| `variables` | 绑定当前批次的类别字典、返工清单ID | 让对话自动加载当前项目的专属数据，减少手动输入 |
| 最大上下文长度 | 8000–12000 字符 | 覆盖单批次标注文档与多轮评审对话的内容量 |
| 对话历史重置时机 | 每标注批次完成后触发 | 适配标注项目按批次推进的业务节奏，避免冗余数据残留 |
| 提示词模板绑定范围 | 仅绑定当前项目的标注规范 | 确保评审对话始终遵循当前项目的标注规则 |

## 容易做错的三处
- 现象：对话响应时长超出预期，界面显示加载延迟提示。原因：未限制上下文加载范围，引入了过多跨批次的非当前项目标注数据。
- 现象：对话中出现`Unexpected end of JSON input`报错，使用ChatGLM2模型时高频出现。原因：未正确绑定`variables`参数，导致对话尝试加载格式错误的类别字典或返工清单数据。
- 现象：对话结果仅在侧边栏展示，无法直接嵌入主对话框；每次新发起对话需重新绑定项目数据。原因：未通过`chatId`绑定当前批次标识，系统默认生成新的对话会话，未复用当前项目的上下文。

## 怎么确认配好了
- 发起测试对话，输入当前批次的标注类别名称，核对返回内容是否包含该类别的标注规范要求。
- 切换至另一标注批次，查看对话上下文是否自动更新为对应批次的文档与数据。
- 发起多轮连续对话，确认每次回复均基于前一轮的评审内容展开，未出现上下文丢失。
- 检查系统日志，确认未出现格式错误类的报错提示。
