# 备份恢复与灾备演练的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本品类的数据来自备份系统、数据库日志、对象存储及灾备平台，日常产出备份策略、恢复演练报告、灾备切换预案、数据校验记录四类核心文档。数据更新节奏分为日、月、季三类，其中备份系统日志按日更新，演练报告与切换预案随演练周期按月或季更新。文档字段包含备份窗口、恢复点目标、校验哈希值、演练执行时长等，部分字段需结合业务场景匹配计量标准。

## 这些特征在「上下文与 token」这一环带来什么约束
备份恢复与灾备演练的多源数据格式差异大，既有结构化的备份策略参数，也有非结构化的演练报告文本，要求上下文加载需兼顾结构化字段提取与非结构化内容解析。数据更新频率的分层特性，要求上下文缓存需支持按更新周期动态刷新，避免加载过期的旧演练数据。恢复点目标、校验哈希值等核心字段的准确性直接影响业务连续性，上下文token分配需优先保障核心字段的完整加载，防止因token溢出导致关键信息丢失。同时跨系统的灾备数据量通常较大，需限制单次上下文加载的总`maxContext`规模，避免触发平台token上限限制。此外，内网无网络部署场景下，无法调用外部token服务，需配置本地token配额适配本地加载需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配灾备演练报告、备份策略等多文档拼接后的总token规模，避免单次加载溢出 |
| `quoteMaxToken` | 1500–2000 字符 | 对应单份核心文档（如数据校验记录）的有效内容长度，保障关键字段完整提取 |
| 上下文刷新周期 | 24小时 / 7天 | 日更数据设置24小时刷新，月更数据设置7天刷新，适配本品类数据的分层更新节奏 |
| 上下文召回条数 | 前4条 | 匹配本品类最耗时的三个环节对应的核心文档，避免召回过多无关内容占用token |
| 本地token配额 | 按实测标定 | 针对无网络内网部署场景，适配本地加载的文档总大小，避免触发内存限制 |

本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 无网络内网部署后服务持续重启，日志提示failed。原因是未正确配置本地上下文加载的token配额，导致平台尝试调用外部token服务失败，触发重启机制。
- 配置自定义openapi token后，知识库搜索与问题优化仍产生扣费。原因是未将上下文调用的token配额绑定到自定义token，仍使用平台默认计费token池。
- 无法清除当前会话的上下文信息。原因是未找到对应会话的上下文重置入口，或未正确触发token缓存的清空指令，导致旧数据仍被加载。

## 怎么确认配好了
- 上传单份备份策略文档，检查上下文加载后显示的token消耗数值，确认不超过配置的最大上下文限额。
- 触发一次恢复演练评审，查看返回内容中是否包含核心字段（如恢复点目标、校验哈希值），确认引用最大token配置生效。
- 手动触发上下文刷新，等待对应周期后再次加载文档，确认新的更新内容已被加载。
- 在无网络内网环境下启动服务，检查日志无token服务调用失败提示，确认本地token配置正常。
