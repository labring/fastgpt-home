# 安全事件应急响应的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本品类的数据来源为SIEM、EDR、防火墙日志与主机镜像，更新节奏为实时或按单事件触发。日常产出的文档包含应急响应报告、取证记录、处置方案与通报材料，字段涵盖攻击发生时间、涉事IP、异常进程标识、处置执行步骤等，无统一固定单位，随日志与文档类型动态调整。

## 这些特征在「上下文与 token」这一环带来什么约束
实时或按事件更新的数据源会带来上下文同步延迟风险，需确保召回的日志与文档为当前事件的最新版本。长文本类的取证记录、处置方案会大幅提升token占用，若未限制上下文长度，易触发输出截断。多字段的日志数据需精准匹配攻击路径相关内容，避免无关信息占用token配额，同时需平衡上下文覆盖范围与token消耗，防止超出模型限制。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 12000–16000 token | 匹配多数大模型的输出token上限，适配应急响应场景下长日志与报告的上下文召回需求 |
| `quoteMaxToken` | 3000–5000 字符 | 限制单条引用文档的token占用，避免单条长内容过度消耗整体配额 |
| 单次召回条数 | 前4–6条 | 平衡上下文覆盖范围与token消耗，防止无关历史日志占用过多配额 |
| 上下文同步周期 | 10–30 秒 | 适配实时更新的数据源，确保召回内容为当前事件的最新数据 |
| 分块重叠长度 | 100–200 字符 | 避免长文档被割裂导致攻击路径等关键信息丢失 |

## 容易做错的三处
- 现象：输出在12288 token时被截断，界面显示“超出回复限制”。原因：`maxContext`配置未覆盖输入token与输出token总和，导致超出模型预设上限。
- 现象：召回的取证记录内容不完整，攻击路径关键信息缺失。原因：`quoteMaxToken`设置过小，单条长文档被截断导致核心内容丢失。
- 现象：上下文召回的历史日志过多，整体token消耗超出模型限制。原因：未限制单次召回条数，引入大量无关的历史事件数据。

## 怎么确认配好了
- 查看模型输入输出token统计日志，确认输入token与输出token总和未超过配置的`maxContext`值。
- 导入单条长文本取证记录，测试召回效果，确认关键攻击路径信息未被截断。
- 模拟单安全事件的全流程调用，检查最终输出是否完整无截断。
- 核对上下文同步周期，确认最新的防火墙日志与SIEM数据被及时召回。
