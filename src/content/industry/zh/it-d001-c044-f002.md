# 安全产品规则运营的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来源于WAF、IDS、防火墙及威胁情报平台，更新节奏为每日或随防护事件触发。日常产出的文档包含规则变更单、拦截日志、误报分析报告、策略回滚记录，字段涵盖规则唯一标识、变更执行时间、拦截对象、误报触发场景、回滚触发条件等，无统一强制格式，字段随对应防护产品的配置调整。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据来源分散且更新频率波动，会导致上下文关联的数据源复杂度提升，需明确区分不同防护产品的规则与日志数据，避免上下文污染。文档结构无统一格式，字段随产品配置调整，需动态适配字段提取逻辑，增加token消耗的可变性。误报分析与规则灰度发布需要关联近期的变更与拦截事件，上下文需覆盖最近的规则变更周期，但过长的上下文会导致token超限，需平衡信息完整性与资源消耗。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 按防护产品类型划分，单产品上下文保留最近7天的规则与日志数据 | 匹配该品类数据的更新节奏，7天覆盖完整的规则灰度与误报分析周期，避免上下文冗余 |
| `quoteMaxToken` | 12000–15000 token | 单条拦截日志平均长度约1000字符，按平均每条日志占用150 token计算，该范围可覆盖80条左右的近期日志，满足关联分析需求 |
| 上下文自动刷新间隔 | 每6小时 | 匹配该品类数据的更新频率，确保上下文始终包含最新的规则与拦截数据 |
| 单规则上下文提取上限 | 前10条关联日志 | 防止单规则关联过多日志导致token超限，平衡分析精度与资源消耗 |
| FastGPT v4.17.0 | 适配当前版本 | 该版本的上下文与token管理逻辑符合该品类的业务需求 |

## 容易做错的三处
- 界面报错提示`AIPROXY_API_ENDPOINT or AIPROXY_API_TOKEN is not set`，原因是未配置服务端必填环境变量`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址）和`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空），会触发启动校验失败。
- 上下文包含跨防护产品的无关数据，导致代码与变更评审出现错误关联，原因是未按防护产品划分上下文范围，混合了不同防火墙的日志与规则内容。
- 代码评审过程中出现token超限中断，原因是未设置`quoteMaxToken`的合理上限，加载了过多的历史拦截日志与规则数据。

## 怎么确认配好了
- 查看上下文预览面板，确认仅显示当前防护产品的规则与日志数据，无跨产品的无关内容。
- 模拟提交一条测试用的规则变更单，查看token消耗统计，确认未超出`quoteMaxToken`的设置值。
- 等待6小时后刷新上下文，确认自动刷新生效，加载了最新的拦截日志与规则变更记录。
- 检查服务端环境变量配置，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`已正确设置。
