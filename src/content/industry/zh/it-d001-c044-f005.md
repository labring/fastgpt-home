# 安全产品规则运营的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
本品类的典型使用主体为安全运营工程师、WAF或IDS产品管理员、SOC团队，数据主要来自WAF、IDS、防火墙及威胁情报平台，更新节奏为每日或随防护事件触发。日常产出的文档包含规则变更单、拦截日志、误报分析报告、策略回滚记录，各文档字段包含规则唯一标识、变更操作类型、关联拦截事件ID、误报触发频次等，单位多为事件数、字符数、时间戳格式。数据围绕防护策略的全生命周期流转，覆盖从规则创建、灰度发布到回滚的全流程节点，为规则运营的多轮分析提供核心依据。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新频率较高，要求多轮对话需支持关联不同系统的日志与变更记录，避免上下文割裂。日常文档包含多类专属字段，提示词需明确指定提取规则ID、误报频次等特定字段，避免混淆通用数据字段。误报分析与规则复核需回溯历史样本，对话需保留完整的上下文链路，支撑跨轮次的样本对比与策略调优。同时，防护策略的变更会实时影响后续分析，对话上下文需自动纳入最新的规则与日志数据，确保分析依据的实时准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文保留时长 | 1200–1800 秒 | 覆盖单次规则评审或误报分析的完整多轮对话周期 |
| 历史会话绑定 | 绑定当前`chatId` | 确保多轮对话关联同一防护场景的规则与日志数据 |
| 变量注入 | 注入规则ID、拦截事件数 | 对齐品类数据的专属字段，提升提示词精准度 |
| 输入输出token统计 | 开启单独计数 | 满足查看token用量的实际需求 |
| 历史消息上限 | 前8条历史对话 | 避免上下文过载干扰规则分析逻辑 |

本配置项说明适用于FastGPT v4.17.0。

## 容易做错的三处
- 现象：多轮对话中无法直接调用历史拦截日志或规则变更记录，关联字段为空。原因：未绑定当前会话`chatId`，或上下文保留时长设置过短，导致历史数据无法被加载。
- 现象：工具调用返回的对话内容包含未脱敏的敏感信息，无法关闭AI对话的敏感内容输出。原因：未配置变量过滤规则，未将客户IP、策略细节等敏感字段从对话上下文排除，导致敏感信息随对话内容返回。
- 现象：提示词使用markdown语法优化规则描述，但返回结果为带语法符号的原文，未渲染为富文本格式。原因：未在提示词中明确要求将内容渲染为markdown格式，或未开启内容格式化相关配置，导致语法符号未被处理。

## 怎么确认配好了
- 发起一轮包含已知规则ID的对话，检查是否能关联到对应的拦截日志与变更记录，确认上下文绑定生效。
- 配置变量过滤规则后，发起包含客户IP的对话，检查返回内容是否已脱敏，确认敏感内容控制生效。
- 输入包含markdown语法的规则描述提示词，检查返回结果是否渲染为富文本格式，确认格式化配置生效。
- 查看对话统计面板，确认输入与输出token分别显示独立数值，确认token统计配置生效。
