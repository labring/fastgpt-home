# 安全培训与钓鱼演练的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
该品类的核心数据来自员工通讯录、邮件网关、内部培训平台及钓鱼演练点击统计。日常产出的文档包含培训课件、演练方案、钓鱼邮件模板与演练结果报告，字段涵盖演练人群范围、邮件发送记录、员工点击反馈与整改记录。数据更新频率通常为季度或年度，单份文档体量从数十页到数百页不等，核心关联字段为员工ID与演练批次标识。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且关联字段依赖员工ID与演练批次，导致溯源时需匹配多系统的身份标识，无法直接复用通用知识库的统一元数据。更新频率较低导致引用的文档版本需严格绑定演练批次，避免跨批次混淆。文档类型多样，需针对培训课件、邮件模板等不同格式配置专属的提取规则，否则会出现字段缺失。演练结果报告的溯源需关联点击统计数据，若未配置跨源关联逻辑，会导致复盘时无法验证员工的实际参与行为。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | `800–1200 token` | 该品类文档多为培训课件与演练报告，单份引用内容较长，需覆盖完整的演练方案或结果片段 |
| `responseData` | 开启文档标题、演练批次、员工ID字段 | 需绑定演练批次与身份标识，确保溯源时可快速定位对应演练的原始数据 |
| `detail` | 开启完整溯源模式 | 钓鱼演练的溯源需包含点击统计的原始记录，仅摘要无法满足审计要求 |
| 跨源关联匹配规则 | 按员工ID与演练批次双字段匹配 | 数据来源分散，需同时匹配身份与批次才能准确关联邮件网关与培训平台的数据 |
| 文档格式适配 | 针对邮件模板、培训课件分别配置提取规则 | 该品类文档格式差异大，通用提取会丢失关键元数据 |
| 引用展示开关 | 开启正式聊天页的引用展示 | 调试页面可展示引用但正式页面缺失，需强制开启该配置确保溯源信息可见 |

## 容易做错的三处
- 现象：正式聊天页面未展示引用的文档出处，调试页面可正常显示。原因：未开启正式页面的引用展示配置，仅保留了调试模式的展示开关。
- 现象：提取的溯源内容仅包含文本片段，未关联演练批次与员工ID等元数据。原因：未配置`responseData`的元数据提取参数，仅提取了核心文本内容未绑定关联字段。
- 现象：跨源关联的溯源结果为空，无法匹配邮件网关的点击记录。原因：仅使用单一员工ID作为匹配字段，未同时绑定演练批次，导致多批次数据混淆无法精准匹配。

## 怎么确认配好了
- 进入FastGPT v4.17.0正式发布的聊天界面，发起与钓鱼演练相关的查询，检查回复下方是否展示引用的文档标题与批次信息。
- 导出溯源日志，核对提取的元数据是否包含员工ID、演练批次与点击统计的关联字段。
- 针对不同类型的文档（如培训课件、邮件模板）发起查询，确认提取的内容格式符合预期，无关键字段缺失。
- 调整`quoteMaxToken`的取值，验证引用内容的长度是否符合配置要求，无强制截断或内容溢出。
