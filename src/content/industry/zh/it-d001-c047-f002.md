# 安全漏洞披露处理的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据围绕单个漏洞事件生成，来源包括私密漏洞报告渠道、项目代码仓库、CVE编号机构及官方发布渠道。日常产出的文档包含安全公告、漏洞报告、修复补丁、CVE申请材料，单条数据包含漏洞编号、影响范围、修复代码片段、披露时间等字段，更新节奏随单个漏洞事件的全流程推进，每完成一个事件环节即产生新的更新内容。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据包含私密漏洞报告、代码片段及CVE相关字段，因此上下文召回需严格限定授权范围，避免泄露未公开的敏感漏洞信息。单条事件的数据关联度高，上下文需要精准匹配当前漏洞的全流程相关内容，避免混入无关事件数据导致评估偏差。同时，修复代码片段占比高且长度较长，token分配需优先保障代码片段的有效召回，防止因token超限导致关键补丁信息丢失。另外，数据更新随事件推进，上下文需支持动态追加最新的披露协调信息，避免内容过时。

## 配置怎么定
对应FastGPT中的`maxContext`、`quoteMaxToken`等核心参数，具体配置如下：

| 配置项         | 建议取法               | 这样取的依据 |
| ----------------|------------------------|------------------------------------------------------------------------------ |
| 最大上下文长度 | 8000–12000 token       | 该品类单事件数据包含代码片段、CVE申请材料等，需覆盖单个漏洞全流程相关内容，避免token不足导致关键信息丢失，按实测标定适配不同规模的项目代码仓库 |
| 引用最大token数 | 2000–3000 token       | 修复代码片段是核心数据，需保障单段补丁代码的完整召回，避免截断影响补丁验证 |
| 上下文召回条数 | 前6条                  | 该品类数据按事件聚合，召回过多无关事件数据会干扰漏洞影响评估，限定条数可提升上下文精准度 |
| 上下文刷新时机 | 每次漏洞环节更新后     | 数据随事件推进更新，刷新上下文可确保包含最新的披露协调信息与补丁进度 |
| 私密数据过滤开关 | 开启                  | 数据包含未公开的私密漏洞报告，开启过滤可避免敏感信息泄露到公共上下文 |

## 容易做错的三处
- 现象：上下文加载时出现token超限报错，无法完成漏洞影响评估。原因：未根据单事件数据量调整`maxContext`参数，直接使用通用场景的默认值，导致包含长代码片段的漏洞数据无法完整加载。
- 现象：知识库搜索未使用自定义token，仍产生额外扣费。原因：未在上下文配置中绑定对应服务的有效token，私密漏洞报告的召回环节未启用授权校验，导致使用默认token发起请求。
- 现象：上下文刷新后出现冗余数据，包含非当前事件的漏洞信息。原因：未配置上下文召回的事件匹配规则，直接召回所有历史数据，导致不同漏洞的上下文内容混杂。

## 怎么确认配好了
本核对流程适用于FastGPT v4.17.0版本。
- 上传单条漏洞事件的完整数据，检查上下文预览模块是否包含该事件的所有核心文档内容，无冗余的其他事件数据。
- 查看服务日志，确认token使用量未超过配置的最大上下文长度上限，无超限报错信息。
- 手动触发一次漏洞环节更新，检查上下文是否自动追加了最新的披露协调信息。
- 验证私密数据过滤开关，确认未授权的外部请求无法获取到未公开的漏洞报告内容。
- 检查`quoteMaxToken`参数的配置是否适配单段修复代码片段的长度，确保代码完整加载。
