# 安全漏洞披露处理的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源于私密漏洞报告、代码仓库、CVE编号机构及公开发布渠道。日常处理的文档包含安全公告、漏洞报告、修复补丁、CVE申请材料，结构上包含漏洞编号、影响范围、补丁链接、披露时间等字段。数据更新以单次漏洞事件为单位，每完成一次漏洞披露流程即完成一轮更新。最核心的处理环节围绕漏洞影响评估、补丁准备、披露时间协调展开，所有数据均与特定项目的自身漏洞直接相关。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
私密数据来源要求对话上下文必须严格绑定单次漏洞事件，避免跨事件数据泄露或混淆。按事件更新的节奏意味着多轮对话需围绕单一漏洞流程展开，不宜引入无关历史信息。文档中的CVE编号、影响范围等结构化字段，需要提示词引导大模型精准提取，避免模糊抓取。漏洞响应的高风险属性要求多轮对话需分步确认关键参数，防止因信息错误导致补丁抢跑或项目信誉受损。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配安全漏洞披露处理的专属场景。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 会话绑定 | 绑定单次漏洞事件的`chatId` | 确保对话上下文仅关联当前漏洞披露流程，避免跨事件数据混淆 |
| 上下文窗口 | 保留最近`2000 字符`的`messages` | 聚焦当前漏洞的报告、补丁信息，避免冗余数据干扰大模型输出 |
| 变量提取 | 开启`variables`自动提取 | 从漏洞报告、补丁内容中提取CVE编号、影响范围等关键字段 |
| 多轮引导 | 每轮对话仅提示1个待确认参数 | 符合漏洞披露的分步协调节奏，避免信息过载 |
| 会话超时 | 600 秒无响应自动终止 | 匹配漏洞响应的紧急性，防止流程阻塞 |

## 容易做错的三处
-  对话返回结果中未展示关联的补丁截图或安全公告图片。原因是提示词未明确要求将知识库中关联的图片链接转换为可展示格式，未触发图片渲染逻辑。
-  提取的漏洞关键字段缺失或错误，比如CVE编号提取偏差。原因是未通过`variables`配置指定需要提取的字段范围，导致大模型抓取无关信息。
-  多轮对话中重复请求相同参数，比如多次询问漏洞影响范围。原因是未在对话流程中标记已确认的参数，导致上下文丢失。

## 怎么确认配好了
-  手动输入一条模拟的漏洞报告，核对大模型是否能准确提取预设的`variables`字段，比如CVE编号、影响范围。
-  测试会话绑定逻辑，切换不同漏洞事件的`chatId`，确认对话上下文不会互相干扰。
-  发送包含图片链接的测试数据，核对大模型是否能按照提示要求渲染图片展示。
-  模拟多轮参数提取流程，确认每轮仅提示一个待确认参数，无重复请求。
