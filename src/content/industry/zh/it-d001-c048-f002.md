# 安全监控与SOC值守的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自SIEM、EDR、NDR及威胁情报源，更新节奏分为实时与日更两类。日常处理的文档包含告警处置单、值班记录、威胁情报通报、日报周报，其中告警处置单包含告警ID、关联资产、处置步骤、误报标记等字段，值班记录包含值守时段、告警流转记录，威胁情报通报包含威胁类型、影响范围、处置建议等结构化与非结构化内容。变更评审相关数据则包含代码片段、提交日志、评审意见等，整体数据结构复杂且存在大量非结构化文本。

## 这些特征在「上下文与 token」这一环带来什么约束
实时更新的告警数据会带来高频的上下文拼接需求，单条告警关联的资产、处置步骤等信息可能占用大量token。日更的周报、威胁情报通报则可能存在长文本内容，超出基础上下文窗口。多源数据混合输入时，需区分告警字段与情报字段的优先级，避免无关信息挤占有效上下文空间。同时，代码与变更评审辅助场景中，需将评审代码片段、提交日志与告警数据绑定，进一步放大上下文token的占用压力，若未合理配置则易出现上下文溢出、关键信息被截断的问题。

## 配置怎么定
以下配置适用于 FastGPT v4.17.0：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–16000 token | 适配SOC场景下多源告警、变更日志的混合输入长度，覆盖多数主流大模型的基础上下文窗口 |
| `quoteMaxToken` | 2000–4000 字符 | 限定单条告警或变更评审代码片段的引用token占比，避免单条内容挤占整体上下文 |
| 单次召回上限 | 前10条 | 控制实时告警数据的召回数量，防止过多历史数据占用上下文空间 |
| 上下文截断策略 | 保留最新告警与核心变更内容 | 优先保留当前评审关联的最新告警、变更日志，截断过期的历史值班记录 |
| 分块重叠长度 | 200 字符 | 适配告警处置单的短段落结构，避免关键处置步骤被分块截断 |

## 容易做错的三处
- 现象：系统提示上下文长度超出限制，无法完成告警与变更评审的关联分析。原因：未根据SOC场景的多源数据特征调整配置，直接使用默认小窗口参数。
- 现象：AI Proxy报错，日志显示get tiktoken失败。原因：离线部署时未正确配置本地tokenizer依赖，或未将tiktoken缓存路径指向离线存储目录。
- 现象：并发处理多份告警评审任务时，部分任务出现上下文截断。原因：未限制单任务的token占用上限，导致并发场景下整体token池被超额占用。

## 怎么确认配好了
- 导入单份完整的告警处置单与变更日志，查看系统显示的上下文占用量，确认其未超过配置的最大上下文阈值。
- 发起多并发的评审任务，观察任务执行状态，确认无上下文溢出或token占用异常的报错。
- 检查AI Proxy的运行日志，确认无tiktoken相关的连接或解析错误。
- 调整配置项后，重新导入长文本威胁情报通报，验证关键信息未被截断。
