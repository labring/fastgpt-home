# 安全监控与SOC值守的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
SOC值守场景的数据来源为SIEM、EDR、NDR及威胁情报源，更新节奏为实时或每日。日常处理的文档包含告警处置单、值班记录、威胁情报通报、日报周报，字段涵盖告警ID、威胁等级、处置状态、值班人员、处置时长等，所有数据均遵循行业通用的安全运营文档结构，无额外自定义非标准字段。

## 这些特征在「工作流编排」这一环带来什么约束
实时或每日更新的数据要求工作流节点需匹配对应触发节奏，避免延迟处理实时告警。多数据源的接入需求要求工作流需配置多输入节点分别关联不同源数据。日常文档的固定字段结构要求变量绑定需严格对应标准字段，避免读取无效数据。告警研判、误报排除的高耗时环节要求工作流需配置循环校验与阈值过滤，防止真实攻击漏报或误报堆积。值班轮换的定时需求要求工作流需支持定时触发的排班校验节点。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 选择知识库 | 绑定SIEM/EDR告警源专属知识库 | 匹配该品类数据来源的专属文档库 |
| 变量引用 | 绑定`variables`中的告警ID、处置状态字段 | 对应日常文档的标准字段结构 |
| 节点触发时机 | 按实时数据更新触发，间隔600秒 | 匹配实时/日更新的数据节奏 |
| 循环次数上限 | 前10次循环，按实测标定 | 避免误报堆积导致的资源占用 |
| 会话弹窗按钮 | 配置为「提交处置单」，绑定节点ID`nodeId` | 实现用户点击提交的交互需求 |
| Mermaid调用配置 | 传入威胁拓扑数据生成流程图 | 满足告警研判的可视化需求 |

## 容易做错的三处
- 配置变量引用时未绑定`variables`中的对应字段，导致工作流节点读取的字段为空。原因是未匹配日常文档的标准字段结构，未正确关联数据源字段。
- 循环节点未设置次数上限，导致误报堆积时工作流持续运行触发超时。原因是未考虑该品类最耗时环节的误报处理需求，未限制循环次数。
- 调用Mermaid生成流程图时未传入正确的数据源参数，导致返回的图片链接无效。原因是未匹配威胁情报源的拓扑数据格式，未正确配置调用参数。

## 怎么确认配好了
- 触发一条测试告警，检查工作流是否自动读取对应`variables`中的告警数据。
- 模拟10条以上误报，检查循环节点是否在预设次数后停止运行。
- 点击会话弹窗的「提交处置单」按钮，检查是否触发绑定的`nodeId`节点并生成处置单。
- 调用Mermaid节点，检查返回的图片链接是否可正常访问，匹配告警拓扑结构。
