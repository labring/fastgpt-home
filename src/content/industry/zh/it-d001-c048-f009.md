# 安全监控与SOC值守的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源于SIEM、EDR、NDR及第三方威胁情报源，更新节奏为实时或每日。日常产出与使用的文档包括告警处置单、值班记录、威胁情报通报、日报周报。数据字段包含告警唯一标识、处置状态、关联代码变更编号、威胁等级、处置耗时等，字段均为业务场景固定字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据多源且更新节奏差异大，要求工具调用同时支持实时API调用与定时批量拉取两种模式，避免单接口超时或数据滞后。告警处置单等文档字段结构固定，插件需精准匹配字段提取规则，避免无效数据流入上下文。实时告警的研判耗时直接影响响应效率，工具调用需优先拉取关联代码变更的最新评审记录，减少手动检索的操作量。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | FastGPT v4.17.0 版本下该配置项功能稳定，适配多源工具调用的自动路由需求，匹配SOC值守的多数据源对接场景 |
| `functionCall` | 启用 | 支持结构化提取告警处置单与代码变更评审的关键字段 |
| 工具调用超时 | 600 秒 | 适配SIEM等数据源的接口响应延迟，避免单次调用中断 |
| 批量拉取间隔 | 300–600 秒 | 匹配每日更新的威胁情报通报的同步节奏 |
| 字段匹配规则 | 按告警ID、关联变更编号匹配 | 精准提取告警处置单中的核心关联数据 |
| 最大上下文长度 | 8000–12000 token | 容纳多份告警与变更评审的完整内容，避免截断关键信息 |

## 容易做错的三处
- 现象：工具调用执行后无响应，会话状态显示超时。原因：未设置合理的工具调用超时参数，匹配多源数据源的响应延迟不足。
- 现象：输出内容中保留“引用标记：［1］”字样。原因：未关闭知识库引用标记的自动输出配置，导致工具调用返回的知识库关联内容被附加标记。
- 现象：无法通过用户关键词触发自定义接口调用。原因：未配置工具调用的触发规则，未将关键词匹配与工具调用绑定。

## 怎么确认配好了
- 提交包含告警ID的测试请求，查看工具是否自动拉取对应代码变更评审记录。
- 生成测试输出，确认无“引用标记：［1］”类字样。
- 输入预设关键词，验证是否触发自定义接口调用并返回对应内容。
- 查看工具调用日志，确认`toolChoice`和`functionCall`的配置被正确加载。
