# 客户培训与使用手册的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的日常文档包含培训课件、用户手册、培训签到表、问题答疑清单四类，数据来源为产品帮助中心、客户组织架构、培训录屏与工单系统。文档更新频率通常为每单或每版本一次，核心内容围绕角色权限讲解、操作步骤演示、课后问题整理三类环节。数据结构以结构化的操作步骤、非结构化的录屏文本与工单条目为主，无固定统一的字段单位，需根据单份文档的实际长度调整处理逻辑。

## 这些特征在「上下文与 token」这一环带来什么约束
品类数据的多源属性与非结构化占比，要求上下文召回需覆盖帮助中心、工单、录屏等不同类型的内容，同时需匹配每单或每版本的更新节奏，避免召回旧版无效数据。单份文档长度差异较大，培训课件与用户手册可能达到数千字符，而工单与签到表多为短文本，需限制单次上下文的总token数量，避免超出模型上限。此外，核心环节的内容优先级更高，角色权限与操作步骤的召回权重需高于其他数据，否则会导致评审辅助结果偏离用户真实需求，引发后续工单激增。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配培训课件、用户手册等多文档组合的总长度，避免上下文溢出 |
| `quoteMaxToken` | 2000–3000 token | 适配单份用户手册或操作步骤文档的核心内容长度，保证关键信息完整 |
| 上下文召回上限 | 前5条 | 限制单次召回的答疑清单、工单条目数量，降低token无效消耗 |
| 上下文更新触发时机 | 版本发布后1小时内 | 匹配品类每版本的文档更新节奏，保证召回内容时效性 |
| 匹配相似度阈值 | 0.75–0.85 | 区分角色权限讲解、操作步骤等不同类型文档的匹配精度，避免无关内容引入 |

## 容易做错的三处
- 界面显示`AIPROXY_API_ENDPOINT or AIPROXY_API_TOKEN is not set`报错。原因是未在App/Admin服务端配置AIPROXY_API_ENDPOINT（AI Proxy服务根地址）和AIPROXY_API_TOKEN（AI Proxy管理员Token）环境变量，导致服务启动校验失败。
- 召回的上下文内容与当前评审的代码变更不匹配，结果条数远少于预期。原因是未根据品类文档的更新频率调整上下文召回触发时机，使用了旧版培训课件或工单数据。
- 单次评审消耗的token数量超出预期，导致计费异常。原因是未限制`maxContext`的取值上限，将多份冗余的培训录屏、签到表数据纳入上下文。

## 怎么确认配好了
- 进入FastGPT v4.17.0的系统配置页面，检查`maxContext`、`quoteMaxToken`的取值是否符合预设区间，确认保存成功。
- 上传一份新版用户手册，发起代码变更评审辅助调用，查看返回的上下文内容是否包含最新的操作步骤与角色权限说明。
- 查看模型调用日志，确认token消耗统计与预设的`maxContext`取值匹配，无异常超额消耗。
- 触发一次培训文档的更新，确认上下文召回的内容自动同步为最新版本。
