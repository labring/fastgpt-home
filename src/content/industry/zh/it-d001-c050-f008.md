# 客户开通与租户初始化的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
通常，该品类的数据来自CRM系统、合同订单库、身份管理系统与FastGPT产品后台。日常关联文档包含开通申请单、租户配置表、管理员账号清单与交付确认单。数据更新节奏为每单或每日，字段一般包含客户唯一标识、租户ID、管理员账号、权限范围、开通时间等，无固定统一的统计口径，仅按业务办理流程生成对应字段。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散，工作流编排需要对接多个外部系统接口完成信息校验与同步，需配置跨系统数据拉取的节点。数据更新频率随单变动，工作流需支持按需触发，适配单次客户开通的办理节奏。文档结构固定，工作流节点需匹配各文档的必填字段，避免遗漏关键配置。客户信息核对、权限初始化等最耗时环节，可通过工作流设置自动校验节点，减少人工干预的耗时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 包含客户ID、租户ID、管理员账号3个必填字段 | 匹配租户配置表与管理员账号清单的字段要求 |
| `nodeId` | 按开通流程顺序分配唯一标识，如1001、1002 | 便于工作流节点追踪与失败回滚 |
| 触发时机 | 在客户提交开通申请单并审核通过后触发 | 匹配业务办理的标准流程 |
| 超时阈值 | 600 秒 | 覆盖跨系统数据拉取与配置写入的常规耗时 |
| 失败重试次数 | 前 3 次 | 避免重复触发导致的系统资源占用 |
| 上下文缓存时长 | 3600 秒 | 避免缓存过期导致的配置读取失败 |
| 单次同步上限 | 100 条 | 适配身份管理系统的单次数据写入限制 |

## 容易做错的三处
- 工作流节点运行自定义代码时出现`localStorage is not defined`报错。原因是FastGPT工作流的代码运行环境未提供浏览器端的localStorage对象，直接调用会触发异常。
- 工作流无法获取分享应用的URL地址。原因是未在工作流中配置对应节点的上下文参数，或未正确绑定应用分享的权限字段。
- 租户初始化完成后客户无法登录。原因是工作流未同步写入身份管理系统的账号权限，或配置的管理员账号字段与身份系统校验规则不匹配。

## 怎么确认配好了
- 触发FastGPT v4.17.0版本下的测试用开通流程，检查工作流日志是否显示所有节点执行成功。
- 核对CRM系统的开通申请单与FastGPT工作流写入的租户配置表字段是否完全一致。
- 登录测试租户的管理员账号，确认基础权限与配置项已正确初始化。
- 查看FastGPT产品后台的租户列表，确认新增租户的状态为正常启用。
