# 客户数据导入迁移的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自客户历史系统、CSV或Excel模板、数据库导出结果以及产品导入日志。日常维护的文档包括数据模板、迁移方案、字段映射表、迁移验证报告，使用主体为实施顾问、数据实施工程师与客户IT接口人。数据更新频率为每单或不定期，核心处理环节包含字段映射确认、脏数据清洗、导入后抽样核对，涉及的字段多为业务数据字段，无统一固定单位。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据来源多样、格式差异大，且需关联多份文档完成字段映射、脏数据清洗等操作，导致上下文token消耗波动明显。字段映射环节需同时加载字段映射表、迁移方案、客户历史数据等多源内容，容易超出预设上下文窗口上限。超长导入任务的token占用随数据量线性增长，易触发超时限制；脏数据清洗需要保留完整校验逻辑的上下文，进一步压缩可用token空间，提升了上下文配置的复杂度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8192–16384 token | 适配多数客户数据导入任务的多源文档关联需求，匹配FastGPT v4.17.0的基础上下文上限 |
| `quoteMaxToken` | 2048–4096 token | 覆盖单批次导入数据的核心校验与映射逻辑，避免单段内容占用过多上下文 |
| 上下文加载超时时间 | 300–600 秒 | 适配脏数据清洗、多源文档关联的处理时长，避免超长任务提前超时 |
| 上下文召回条数 | 前3–5 条 | 聚焦核心迁移文档，减少无关内容的token消耗 |
| 多源文档合并阈值 | 按实测标定 | 根据迁移方案、字段映射表的总字符数调整，确保关联内容完整加载 |

## 容易做错的三处
- 现象为超长导入任务在执行至12288 token时被截断，显示超出回复限制。原因是未调整`maxContext`参数适配任务的总token消耗，默认上下文窗口不足以承载多源关联的迁移数据。
- 现象为无法基于应用维度统计token消耗。原因是未开启应用级上下文token追踪配置，仅默认统计单轮问答的token用量。
- 现象为设置0.4的相似度阈值、10000 token的引用上限后，仍无法召回所需的字段映射内容。原因是未结合迁移文档的总字符数调整`quoteMaxToken`，导致有效关联内容未被加载。

## 怎么确认配好了
- 导入测试批次数据，查看系统日志中的上下文token占用情况，调整配置至占用量符合任务需求。
- 触发字段映射校验流程，核对返回内容是否覆盖迁移方案、字段映射表的核心业务内容。
- 运行脏数据清洗任务，确认任务执行时长未超出预设的超时限制。
- 统计多轮不同规模的导入任务的token消耗，验证配置可适配不同数据量的导入场景。
