# 客户数据导入迁移的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
这个品类的数据来源包括客户历史系统导出内容、自定义CSV/Excel模板、数据库离线备份、产品端导入日志。日常配套文档包含数据模板、迁移方案、字段映射表、迁移验证报告。数据更新节奏为每单或不定期，单次迁移的数据体量跨度较大，涉及业务字段、映射规则、校验阈值等核心内容，部分自定义字段无统一格式标准。

## 这些特征在「工具调用与插件」这一环带来什么约束
多来源的数据格式要求工具插件具备适配性，需支持CSV解析、数据库连接、日志提取等不同类型的插件调用。不定期的更新节奏要求工具调用流程可灵活调整映射规则，无需重复初始化配置。复杂的字段映射逻辑需要工具调用时携带完整的映射参数，避免字段错位。数据体量跨度大的特点要求工具调用可配置超时与重试机制，适配不同规模的迁移任务。迁移出错会导致严重业务影响，工具调用需保留完整执行日志用于问题溯源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动匹配当前迁移流程所需的工具，适配多数据源的解析需求 |
| `functionCall` | `[{"name":"parse_source_data"},{"name":"match_field_mapping"},{"name":"run_import_check"}]` | 按客户数据迁移的标准分步流程定义工具调用序列 |
| 单次工具调用超时阈值 | `600 秒` | 适配大数据量解析、字段校验与导入操作的耗时需求 |
| 工具调用重试次数 | `2 次` | 避免临时网络波动或临时资源不足导致的迁移失败 |
| 工具调用日志保留时长 | `30 天` | 用于后续迁移验证、问题排查与合规追溯 |

本页面内容基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 现象：工作流中配置的多个工具仅部分被执行，未按预设顺序触发。原因：未正确配置`functionCall`的参数序列，导致工具调用的执行顺序未按迁移流程定义执行。
- 现象：CSV格式的迁移数据解析后返回空结果，字段映射校验失败。原因：未针对客户自定义字段调整`toolChoice`的适配规则，导致工具无法识别非标准格式的模板内容。
- 现象：大规模数据导入任务提前终止，界面返回超时错误提示。原因：未调整工具调用超时阈值，未预留足够的解析与导入时间，导致任务在未完成时被终止。

## 怎么确认配好了
- 查看工具调用配置列表，确认每个迁移步骤对应的工具已被添加到调用序列中。
- 上传小体量的测试数据模板，触发工具调用流程，检查每个工具的执行日志是否完整且无报错。
- 验证`toolChoice`参数的自动适配效果，确认不同数据源的解析工具能正常被调用。
- 模拟临时网络中断的异常场景，检查工具的重试机制是否按配置触发。
