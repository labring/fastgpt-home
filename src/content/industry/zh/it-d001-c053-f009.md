# 客户需求池管理的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
客户需求池管理的数据来自工单系统、客户访谈记录、CRM客户管理系统与产品路线图文档。日常维护的文档包括需求池清单、需求评估表、客户反馈汇总与版本规划说明。数据更新频率为每周或每版本发布周期，字段包含需求来源、关联客户、优先级标签、排期状态与归并标记。数据以结构化清单形式存储，单条记录包含明确的业务属性与关联信息，无冗余嵌套结构。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散且更新节奏固定，工具调用需支持多系统数据拉取与整合，避免单次调用超时。需求池数据以清单形式存储，插件需适配批量处理逻辑，支持按字段筛选与归并。重复需求归并是核心耗时环节，工具调用需内置相似匹配逻辑，减少人工操作。同时，代码变更评审需关联最新的需求池数据，插件触发时机需与更新节奏匹配，避免使用过时的需求信息影响评审结果。

以下配置适用于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用模式 | 批量拉取模式 | 适配需求池清单的批量数据结构，支持一次性拉取多条需求记录 |
| `toolChoice` | `auto` | 自动匹配当前流程的需求池数据，无需手动指定调用范围 |
| `functionCall` | `enabled` | 启用函数调用能力，支持对拉取的需求数据进行归并与排序处理 |
| 单次请求最大条数 | 前10条 | 匹配需求池单页展示的常规条数，避免单次请求数据量过大导致超时 |
| 超时阈值 | 600秒 | 适配CRM与工单系统的数据同步平均耗时，避免因网络延迟触发调用失败 |
| 插件触发时机 | 需求池更新后30分钟内 | 匹配数据更新频率，确保评审环节使用最新的需求池数据 |

## 容易做错的三处
- 调用工具时返回`400 InternalError.Algo.InvalidParameter`报错，原因是未正确配置`toolChoice`参数，导致工具调用的参数格式不符合系统要求。
- 线上创建的插件无法在代码变更评审流程中触发，原因是未将插件绑定到需求池管理的对应流程节点，仅在后台完成了基础配置。
- 插件返回的需求归并结果条数少于预期，原因是设置了过小的单次请求最大条数，导致部分需求记录未被完整拉取。

## 怎么确认配好了
- 登录FastGPT后台的插件管理页面，查看对应配置项的保存状态，确认所有参数已正确存储且无异常提示。
- 手动触发一次需求池更新事件，检查插件是否自动执行并返回符合预期的需求归并与排序结果。
- 进入代码变更评审流程，调用配置好的插件，验证是否能正确拉取当前需求池的最新数据并关联至评审内容。
- 查看系统运行日志，确认工具调用的参数格式符合要求，无报错信息返回。
