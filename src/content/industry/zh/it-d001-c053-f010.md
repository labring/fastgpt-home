# 客户需求池管理的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据通常来自工单系统、客户访谈记录、CRM系统与产品路线图，更新频率为每周或每版本发布周期。日常产出的文档包含需求池清单、需求评估表、客户反馈记录与版本规划说明，字段包含需求编号、关联客户标识、反馈内容、优先级标签与版本关联项，数据以结构化文本为主，部分包含客户语音转写的非结构化内容，通常不包含研发代码本身的内容，仅聚焦于需求相关的业务信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散于多套系统，引用溯源需支持跨数据源的关联校验，确保需求条目与原始反馈、工单记录一一对应。数据更新频率较高，需配置自动同步机制以避免引用过时内容。不同文档的字段格式存在差异，需适配需求池清单、客户反馈记录等不同文档的引用路径规则。由于该品类需处理多客户的反馈归并，溯源时需区分不同客户的关联记录，避免混淆，面向非技术背景的使用主体，溯源逻辑需兼顾准确性与易用性，避免过度复杂的配置步骤。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的界面逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 8000–12000 token | 适配需求池类文档的平均内容长度，避免截断关键需求信息 |
| 知识库最大引用 | 前6条 | 匹配单次评审的关联反馈数量范围，控制信息密度 |
| 最大响应tokens | 2000–3000 token | 覆盖需求评估与溯源说明的完整输出需求 |
| `quoteMaxToken` | 1200–1800 字符 | 限制单条引用的展示长度，避免页面信息过载 |
| `responseData` | 开启 | 保留引用来源的结构化标识，便于后续溯源校验 |
| `detail` | 开启 | 展示引用来源的核心字段，如关联客户标识、工单编号 |

## 容易做错的三处
- 现象：返回结果中强制携带引用来源，无法按需隐藏。原因：未正确配置`responseData`参数的开关状态，导致强制输出引用标识。
- 现象：配置后返回结果出现红色报错提示。原因：未适配需求池多数据源的关联校验规则，溯源时无法匹配原始工单或客户反馈记录。
- 现象：需求评审时引用内容过长导致界面溢出。原因：`quoteMaxToken`取值过高，未限制单条引用的展示长度。

## 怎么确认配好了
- 导入一份典型的需求池清单文档，触发评审流程，核对引用来源是否关联到对应的工单或客户反馈记录。
- 调整配置项的取值范围，验证返回内容的长度与引用数量是否符合当前评审场景的需求。
- 检查界面展示的引用标记格式，确认是否与需求池文档的字段规则一致。
- 模拟更新需求池数据，验证溯源信息是否同步更新为最新版本的内容。
