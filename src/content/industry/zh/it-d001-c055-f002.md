# 容量规划与资源扩缩容的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自云服务商账单、集群监控系统、业务流量预测报告、压测产出的负载数据。日常产出的文档包括容量规划报告、扩容申请单、资源利用率报表、预算测算表，数据更新节奏通常为周度或月度。单份文档包含资源类型标识、峰值负载数值、申请周期、预算测算条目等字段，字段单位对应资源规格与财务核算标准，无统一固定格式。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据更新节奏较慢且来源分散，会在上下文召回环节带来平衡历史数据有效性与token消耗的需求。单份文档篇幅跨度大，从简短的扩容申请到数十页的容量规划报告，需要限制单段召回内容的token上限，避免超出模型上下文窗口。同时部分文档包含敏感财务字段，需要在召回阶段过滤非关联内容，减少无效token占用。此外峰值预测依赖近期压测数据，需限定上下文召回的时间范围，避免引入过时的历史数据干扰评审结果。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的逻辑制定：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 10000–14000 token | 覆盖该品类单份容量规划报告的平均token量，适配主流大模型的上下文承载能力 |
| `quoteMaxToken` | 1800–2200 token | 匹配单份扩容申请单或资源利用率报表的内容长度，避免单条召回内容超出上下文配额 |
| 上下文召回时间范围 | 近28–35天 | 匹配该品类数据的周/月更新节奏，确保召回数据具备时效性 |
| 敏感内容过滤 | 开启 | 过滤预算测算表中的财务敏感字段，减少无效token占用 |
| 提问简化开关 | 开启 | 优化评审人员的输入内容，降低冗余token的消耗 |

## 容易做错的三处
- 现象：配置`quoteMaxToken`后，召回的相关文档片段长度超出预期，导致上下文溢出。原因：未结合该品类单份文档的实际token长度调整取值，直接使用通用配置。
- 现象：系统提示token消耗过高，无法完成评审辅助。原因：未开启敏感内容过滤，将预算测算表中的非关联财务字段纳入上下文，额外占用token配额。
- 现象：英文提问时触发报错，中文提问正常。原因：未针对该品类的英文评审场景调整`maxContext`取值，英文文本的token密度高于中文，导致超出上下文窗口。

## 怎么确认配好了
- 查看上下文召回日志，核对召回的文档片段是否属于该品类的核心文档类型，确认过滤规则生效。
- 模拟评审提问，统计单次输入的token消耗，确认未超出预设的上下文配额。
- 测试不同时间范围的文档召回，确认匹配数据的更新节奏。
- 验证敏感字段过滤功能，确认财务类内容未被纳入上下文片段。
