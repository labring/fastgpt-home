# 容量规划与资源扩缩容的代码与变更评审辅助：工作流编排
本文档适用于FastGPT v4.17.0版本的工作流编排功能。

## 这个品类的数据长什么样
该品类的数据主要来自云服务商账单、基础设施监控系统、业务流量预测报告与压测结果。日常产出的文档包含容量规划报告、扩容申请单、资源利用率报表及预算测算表。数据更新周期通常为周或月，核心字段包含资源类型、当前利用率、峰值阈值、预算额度与预估扩容量，无统一强制单位，需匹配对应云厂商或内部运维规范，不同团队的字段命名与格式可能存在细微差异。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散且更新周期较长，工作流编排需支持跨系统拉取多源数据，避免单次请求超时或权限不足。核心文档的固定字段要求工作流需配置参数校验环节，过滤缺失关键信息的输入。同时，因峰值预测与瓶颈定位环节耗时占比高，工作流需拆分长任务为可并行的子节点，避免整体执行超时。另外，资源配置错误会直接影响生产稳定性，工作流需添加人工评审触发节点，确保变更前的校验合规，同时可添加抄送环节同步至相关业务与财务团队。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发时机 | 每周一凌晨2点 | 匹配资源利用率报表的周度更新周期，避免占用业务高峰时段 |
| `variables` | 包含资源类型、当前利用率、峰值阈值三个核心字段 | 对应容量规划报告的必填项，确保工作流输入参数完整 |
| 节点ID配置 | 为每个数据源节点分配唯一`nodeId` | 明确节点间的依赖关系，避免执行顺序混乱 |
| 重试策略 | 失败后重试2次，间隔60秒 | 应对临时网络波动或接口限流，减少工作流中断概率 |
| 单次请求上限 | 前1000条数据 | 避免拉取过多历史数据导致超时，覆盖常规容量分析的样本需求 |
| 超时设置 | 1200秒 | 覆盖跨系统拉取数据与峰值预测的最长执行时长 |

## 容易做错的三处
- 工作流中配置HTTP请求节点后，执行时直接跳过请求环节进入AI对话：原因是未在`variables`中配置请求的目标URL与请求头参数，导致节点无法正常触发联网请求。
- 配置多节点工作流时，节点执行顺序不符合预期：原因是未正确关联`nodeId`的依赖关系，导致并行节点未按预设顺序串行执行。
- 工作流触发后未生成容量规划报告：原因是未开启参数校验环节，缺失预算额度字段的输入导致流程提前终止。

## 怎么确认配好了
- 手动触发工作流一次，查看节点执行日志，确认HTTP请求节点返回了预期的云账单或监控数据。
- 检查`variables`中是否包含所有预设的核心字段，无缺失或格式错误。
- 模拟缺失预算额度字段的输入，确认工作流触发了参数校验失败的提示。
- 查看工作流的执行历史，确认最近一次运行的耗时未超过1200秒的超时设置。
