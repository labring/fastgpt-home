# 容量规划与资源扩缩容的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自云账单、监控系统、业务预测报告、压测报告，更新频率多为周度或月度。日常产出的文档包括容量规划报告、扩容申请单、资源利用率报表、预算测算表，数据字段包含峰值资源利用率、预留资源核数、内存配额、年度预算额度等，单位通常为CPU核数、GB、元。数据会随业务迭代、资源调整逐步更新，单份文档的核心内容长度集中在数百到数千字符区间，且不同来源的数据格式存在差异。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于该品类数据更新频率较低，引用溯源时需确保关联的数据源为最新版本，避免引用过期的容量规划内容。数据来源分散且格式多样，需对不同类型的数据源做明确区分，防止将压测报告数据与云账单数据混淆。单份文档内容较长，引用时需保留核心字段的完整展示，不能截断关键的峰值预测或资源瓶颈信息。此外，该品类数据直接关联生产资源配置，引用错误会直接影响评审结果，因此溯源信息需包含明确的文档来源、更新时间与对应字段，辅助评审人员快速验证数据有效性。

## 配置怎么定
在FastGPT v4.17.0版本中，可通过以下配置项完成该场景下的引用来源与溯源设置：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 字符` | 容量规划报告的核心段落通常处于该长度区间，可避免截断峰值利用率、资源配额等关键数据 |
| 外部链接导入规则 | 支持Notion、云文档链接 | 该品类的数据源常存储于Notion或云文档平台，需兼容主流外部链接格式 |
| `detail` | 开启 | 需展示引用数据的具体字段与来源文档章节，帮助评审人员快速定位引用依据 |
| 匹配结果上限 | 前3条 | 该品类数据更新频率低，过多的匹配结果会增加评审人员的筛选负担 |
| `responseData` | 仅返回带校验标记的条目 | 过滤未完成更新的临时数据，避免引用过期或无效的容量规划内容 |

## 容易做错的三处
- 现象：导入Notion链接作为数据源后，无法正常检索其中的容量规划内容。原因：未配置外部链接导入规则，未开启对应链接格式的支持权限。
- 现象：评审时发现引用的容量规划数据被截断，无法查看完整的峰值预测数值。原因：未结合该品类文档的内容长度设置`quoteMaxToken`参数，取值过小导致核心信息丢失。
- 现象：提问内容与知识库中的容量规划数据无关，但仍被标记为有效引用。原因：未开启`responseData`的校验标记，允许未匹配到核心字段的内容被返回。

## 怎么确认配好了
- 上传一份存储于Notion的容量规划报告，发起包含“当前服务器资源利用率”的评审提问，查看引用结果是否关联到报告内的对应字段。
- 点击引用卡片，确认展示的溯源信息包含文档标题、更新时间与具体数据字段，无缺失或错误。
- 调整`quoteMaxToken`参数至`1500 字符`，上传一份较长的扩容申请单，验证长内容是否被完整展示，无截断情况。
- 配置仅允许检索云账单数据源，发起提问，确认返回的引用内容仅来自云账单类文档，无其他类型数据混入。
