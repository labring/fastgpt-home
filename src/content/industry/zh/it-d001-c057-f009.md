# 工单受理与问题分级的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来自工单系统、聊天记录、产品日志、客户合同SLA，更新频率为日级或实时。日常文档包含客户工单、问题分级表、处理记录、服务报告。客户工单包含客户标识、问题描述、提交时间字段；问题分级表包含优先级标签、责任团队映射字段；处理记录包含响应时长、解决结果字段；服务报告包含SLA达标统计字段。数据结构随团队的分级规则调整，无固定统一格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且无固定格式，要求工具调用支持动态字段提取，避免硬编码适配单一团队的文档结构。更新频率分为实时与日级，插件触发时机需对应匹配，实时工单需即时调用工具完成分级，日级服务报告可通过批量插件任务处理。数据量随工单峰值波动，工具调用的并发阈值需适配团队的日常负载。部分数据依赖历史处理记录，插件需支持跨数据源的关联查询，同时需处理字段缺失的异常情况，还需适配开源的MCP server类型插件模板。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配本品类动态变化的工单字段，自动选择匹配的工具调用逻辑 |
| `functionCall` | `disabled` | 避免因动态字段导致的调用失败，仅在明确需要固定调用时启用 |
| 工具调用超时时间 | 600 秒 | 匹配常见的超时场景，避免因单次调用过长导致任务中断 |
| 单次调用返回条数 | 前 5 条 | 适配问题分级的核心关联数据量，避免过多冗余信息干扰判断 |
| 上下文窗口大小 | 800–1200 字符 | 适配工单与分级表的典型内容长度，平衡信息完整性与调用效率 |
| 批量任务间隔 | 1 天 | 适配日级服务报告的处理节奏，避免频繁调用占用资源 |
| FastGPT 版本 | FastGPT v4.17.0 | 确保插件配置的兼容性与功能完整性 |

## 容易做错的三处
- 现象：知识库调用返回结果与工单内容不匹配，原因：未关联正确的数据源，错误调用了无关的产品日志或历史记录。
- 现象：单次工具调用耗时超过 600 秒，原因：未设置合理的超时限制，或调用了超出当前配置范围的跨数据源查询任务。
- 现象：第三方模型调用失败，原因：未正确配置模型调用的参数，或未适配模型的接口格式要求。

## 怎么确认配好了
- 提交一条测试工单，查看工具调用日志，确认`toolChoice`的自动选择逻辑正常生效。
- 模拟超时场景，验证插件的超时处理机制是否触发预设的异常告警。
- 调整工单的分级标签，确认插件是否能正确关联对应的历史处理记录。
- 查看FastGPT的插件管理页面，确认配置项的取值与当前设置一致。
