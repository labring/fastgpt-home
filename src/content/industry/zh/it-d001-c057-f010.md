# 工单受理与问题分级的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来源于工单系统、聊天记录、产品日志、客户合同SLA，更新频率为日级或实时。日常处理的文档包含客户工单、问题分级表、处理记录、服务报告，各文档字段包含工单编号、客户反馈内容、分级标签、处理时长、SLA达标状态等，字段多为字符串、时间戳或枚举值，无复杂嵌套结构。数据以工单为核心关联单元，不同来源的数据需通过工单编号完成绑定，确保关联的唯一性。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据分散在多个系统且更新频率差异较大，引用溯源需同时覆盖实时聊天记录与历史工单数据，需保证关联的工单编号与对应内容完全匹配。问题分级表的标签字段需与工单内容严格对应，避免跨工单的错误引用。实时更新的产品日志与服务报告需在短时间内完成索引，否则会导致溯源数据滞后。此外，SLA相关数据的溯源需保证时间戳准确，否则会影响后续的合规校验。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 字符 | 匹配工单内容与分级表的平均长度 |
| `responseData` | 开启 | 用于绑定工单编号与对应处理记录 |
| `detail` | 按实测标定 | 适配多源数据的关联需求 |
| 单次搜索上限 | 前5条 | 避免过载后端工单系统 |
| 语义相似度阈值 | 0.75–0.85 | 匹配工单内容与知识库文档的关联度 |

## 容易做错的三处
- 现象：返回的引用内容未携带工单编号字段，无法完成溯源绑定。原因：未开启`responseData`配置项，仅返回了摘要内容。
- 现象：连续处理多个工单时，后续请求引用了无关工单的内容。原因：未按工单ID隔离上下文，导致跨工单数据混淆。
- 现象：引用溯源环节出现504超时错误。原因：`quoteMaxToken`取值超过系统预设的处理阈值，未匹配工单数据的实际长度。

## 怎么确认配好了
- 发起一条测试工单，查看返回结果中是否包含工单编号、处理记录等原始引用字段。
- 提交多条关联的工单请求，确认每次请求仅引用当前工单的相关数据。
- 调整`quoteMaxToken`的取值，验证引用内容的长度符合设定范围。
- 查看FastGPT v4.17.0的系统日志，确认引用溯源环节未出现字段缺失或超时报错。
