# 广告合规留痕的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
本品类的数据主要来自广告平台后台、客户资质系统、合同管理系统及监管公开规则。日常产出的文档包含广告审查表、资质附件、投放记录、整改通知四类。数据更新节奏随单次广告活动或月度周期触发。文档结构包含基础标识字段、关联业务字段与合规校验字段，单份文档的字符量区间跨度较大，从数十字符的审核标识到数千字符的投放记录不等，无额外统计类附加字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据来源分散，涉及广告平台、客户资质、合同系统等多套独立系统，工具调用环节需支持配置多源访问凭证以拉取对应数据。文档类型多样，包含结构化表格、非结构化文本与图片附件，工具需适配不同格式的解析逻辑。数据更新节奏随单次广告活动或月度周期触发，工具调用需支持按需触发。单份文档字符量跨度较大，工具调用需适配不同长度的内容处理。同时，合规留痕的准确性直接关联监管检查结果，工具调用的执行日志与返回结果需完整留存。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 适配广告合规留痕场景下多类型文档的自动解析需求，无需手动指定调用工具 |
| `functionCall` | `{"name": "parse_compliance_doc", "parameters": {}}` | 针对合规文档的标准化解析需求，指定专用工具函数处理结构化与非结构化内容 |
| 工具调用超时设置 | `600 秒` | 单份合规文档的拉取与解析操作通常覆盖多数业务场景，600秒可满足大部分处理时长要求 |
| 工具调用结果留存 | 全量留存 | 合规留痕要求需完整保存工具调用的输入、执行过程与返回结果，用于后续监管核查 |
| 多源工具凭证配置 | 按数据来源分别配置独立访问密钥 | 本品类数据来自广告平台、客户资质系统等多套独立系统，需分别配置对应访问权限 |
| 工具调用触发规则 | 按广告活动完成或月度节点触发 | 匹配本品类数据随单次广告活动或月度周期更新的节奏 |

## 容易做错的三处
- 现象：工具调用返回`Failed to fetch`错误，状态码为500或404。排查项：检查是否未正确配置服务端环境变量`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token），或配置的地址附加了`/v1`等路径后缀。
- 现象：工具调用拉取的资质附件数据缺失或格式异常。原因：未针对图片、PDF等不同文档类型配置对应的解析工具，或多源凭证配置错误导致无法完整拉取客户资质系统的数据。
- 现象：工具调用执行后未生成合规留痕日志。原因：未开启工具调用结果留存配置，或留存配置仅保存了部分执行步骤，未覆盖完整的输入与返回内容。

## 怎么确认配好了
- 登录FastGPT后台的服务端部署日志页面，检查是否存在`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token）的缺失告警，确认环境变量已正确配置。
- 手动触发一次工具调用，查看返回结果是否包含对应广告活动的投放记录与资质附件数据，核对数据来源与业务场景匹配。
- 查看工具调用的执行日志，确认完整保存了调用输入、执行过程与返回结果，符合合规留痕的留存要求。
- 测试不同类型的合规文档，如PDF资质附件、结构化投放记录的工具调用，确认解析结果符合预期格式。
