# 广告素材审核的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自广告投放平台、落地页资源、商品资质文件与广告法合规条款。日常处理的文档包括广告素材文件、落地页截图、单次审核的意见记录、素材修改历史台账。数据更新频率为日级或实时，核心字段包含素材唯一标识、投放渠道类型、文案内容、关联资质编号、违规标注条目与审核时间戳。与广告账户开户审核品类不同，该品类需逐条检查具体投放的素材内容，聚焦单次投放的合规性校验。

## 这些特征在「上下文与 token」这一环带来什么约束
广告素材审核的单次处理涉及多源文档拼接，素材与落地页的关联校验需要完整的上下文关联，实时更新的资质与条款要求上下文不能过期。多份审核意见与修改记录的叠加会快速消耗token配额，过长的上下文会超出大模型处理上限。同时，素材的多模态元数据（如配图描述）会增加token占用，需要严格控制上下文的有效范围，避免无关字段占用token资源导致处理超时或内容截断。

## 配置怎么定
本文档适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 前20条上下文记录 | 广告素材审核的上下文以单次审核流程的关联记录为主，20条可覆盖完整的审核修改链条 |
| `quoteMaxToken` | 8000 token | 单条素材+落地页+审核意见的总token约为1500-3000 token，8000 token可容纳3-5组完整审核上下文 |
| 最大上下文窗口 | 按实测标定 | 适配广告素材审核的多源数据拼接需求，避免超出大模型原生窗口限制 |
| 上下文召回阈值 | 0.75-0.85 | 过滤低关联的历史审核记录，减少无效token占用 |
| 单次召回条数 | 前5条 | 控制上下文总长度，避免token超标 |

## 容易做错的三处
- 现象：升级后出现`Error response from daemon: error from registr`类报错，或AI回复出现非预期JSON格式。原因：上下文配置未适配广告素材审核的多源数据结构，导致大模型无法正确解析关联字段。
- 现象：设置`maxContext`为30条，但对话明细仅显示2条上下文。原因：未正确关联素材ID与历史审核记录，系统仅召回了直接匹配的少量条目。
- 现象：大模型提示上下文token数超标。原因：未限制`quoteMaxToken`配额，将完整的多份素材与落地页元数据全部纳入上下文，超出token上限。

## 怎么确认配好了
- 导入单条广告素材与关联的3条历史审核记录，检查上下文窗口是否正确加载所有关联条目。
- 上传包含文案、落地页URL的素材包，查看token消耗统计是否在预设的`quoteMaxToken`范围内。
- 模拟多轮审核修改对话，确认AI回复可关联之前的审核意见与素材修改痕迹。
- 调整`maxContext`参数，验证上下文召回条数是否符合预设取值。
