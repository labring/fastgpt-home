# 广告素材审核的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
广告素材审核的数据来源包含广告投放平台、落地页地址、商品资质文件与广告法合规条款。数据更新节奏为日级或实时，覆盖单条投放素材的全生命周期信息。日常处理的文档包含广告素材文案、落地页截图、审核意见表单与修改操作记录，核心字段包括素材内容标识、投放渠道类型、违规类型标签、修改操作时间戳与审核结论。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源且实时更新的数据要求工具调用需支持高频拉取最新素材、落地页与合规条款信息，避免使用过期缓存导致审核偏差。多样的文档类型要求插件需适配文本、图片链接与结构化表单等不同输入格式，确保各类审核数据均可被正确解析。单条素材的审核流程需匹配实时节奏，工具调用的超时与并发设置需适配业务峰值，同时需严格限定工具调用范围，防止触发无关操作引发合规风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配广告素材审核中多工具按需调用的场景，避免强制绑定固定工具 |
| `functionCall` | 按审核场景预设工具列表 | 限定调用范围，防止调用无关工具引发合规风险 |
| 单次工具调用超时时间 | 15-30秒 | 匹配实时更新的素材数据拉取节奏，避免因等待过久导致审核流程阻塞 |
| 工具调用结果缓存时长 | 10-60秒 | 适配日/实时更新的数据源，兼顾数据新鲜度与调用效率 |
| 工具调用结果校验开关 | 开启 | 确保返回的素材合规性检查结果符合广告法条款要求 |
| 单次调用工具数量上限 | 前5条 | 匹配单条素材审核的常规检查项数量，避免调用过多工具拖慢流程 |

## 容易做错的三处
- 现象：应用调用返回的结果直接显示在对话界面中，未作为上下文资料传入大模型。原因：未正确配置`toolChoice`参数为抑制直接输出模式，或未绑定结果上下文传递的关联设置。
- 现象：API调用时携带的chatId无法在后续流程中持久传递，导致审核上下文丢失。原因：未在API请求参数中正确携带chatId字段，或未开启上下文持久化配置。
- 现象：应用调用的查看详情页面中无法展示内部执行的详细步骤与参数记录。原因：未开启调试日志开关，或配置中未启用详细执行记录收集功能。

## 怎么确认配好了
- 发起包含单条广告素材文案的测试请求，检查工具调用是否按预设规则触发。
- 进入应用调用的详情页面，确认内部执行步骤与配置项的设置完全匹配。
- 发起API调用并携带chatId参数，检查后续关联的审核请求是否复用该上下文标识。
- 查看对话界面，确认工具调用返回的结果仅作为上下文传入大模型，未直接显示在对话中。
