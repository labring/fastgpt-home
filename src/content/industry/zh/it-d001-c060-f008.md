# 广告账户开户审核的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
广告账户开户审核场景的数据主要来自广告平台后台、国家企业信用信息公示系统、客户提交的纸质或电子材料，以及公开的行业准入规则。日常处理的文档包含开户申请单、营业执照扫描件、对应行业的专项资质文件、历史开户审核记录。数据更新节奏随开户申请流程推进，单次申请的相关数据仅在申请周期内更新，批量审核场景下按日同步平台后台的主体资质状态。数据字段包含主体统一社会信用代码、行业类目、资质有效期、申请提交时间等，无统一的标准化单位，需按文档类型分别校验字段完整性。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散且需跨系统拉取，工作流需拆分多节点分别对接不同数据源，避免单节点负载过高。数据更新随申请流程触发，工作流需支持按单次申请事件触发执行，适配按需处理的业务节奏。文档字段多且无统一标准，工作流需配置变量映射规则，将不同来源的字段统一为审核所需的标准格式。主体资质核验与行业准入判断为最耗时的环节，需单独设置节点，并配置失败分支用于触发材料补正沟通流程，同时需预留异常处理节点应对资质核验失败的情况。

## 配置怎么定
以下配置项适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流触发时机 | 按开户申请提交事件触发 | 适配该品类按需处理的业务节奏，避免无效执行 |
| 节点超时阈值 | 300秒 | 匹配主体资质核验、行业准入判断的常规处理时长 |
| `variables` | 映射客户提交材料与系统标准字段 | 统一跨来源数据的格式，确保审核节点可读取有效信息 |
| 失败处理分支 | 触发材料补正通知节点 | 对应最常见的审核不通过场景，简化运营补正流程 |
| 上下文窗口大小 | 800–1200 字符 | 适配开户审核相关文档的平均长度，避免上下文溢出 |
| 节点重试次数 | 2次 | 应对临时网络波动导致的数据源拉取失败 |

## 容易做错的三处
- 现象：工作流运行时弹出未捕获异常弹窗，后台日志显示鉴权失败。排查项：检查App/Admin服务端是否已配置必填的AIPROXY_API_ENDPOINT（AI Proxy服务根地址）与AIPROXY_API_TOKEN（AI Proxy管理员Token）环境变量，未配置会触发启动校验失败。
- 现象：AI对话节点返回结果为空，未匹配到开户审核所需的资质信息。排查项：检查工作流`variables`是否已正确绑定客户提交的营业执照、行业资质等数据源字段。
- 现象：工作流执行到资质核验节点后中断，未进入后续流程。排查项：检查节点超时阈值设置是否符合业务实际处理时长需求。

## 怎么确认配好了
- 登录FastGPT的App/Admin服务端后台，检查环境变量配置，确认AIPROXY_API_ENDPOINT（AI Proxy服务根地址）和AIPROXY_API_TOKEN（AI Proxy管理员Token）已配置且非空。
- 生成一条测试用的开户申请数据，触发工作流执行，查看各节点的输入输出日志，确认`variables`中的数据源字段已正确加载。
- 模拟资质核验失败的场景，触发失败分支，验证是否自动启动材料补正通知流程。
- 调整节点超时阈值为符合业务需求的时长，运行测试用例确认节点执行未被提前中断。
