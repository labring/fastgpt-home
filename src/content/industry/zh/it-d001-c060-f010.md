# 广告账户开户审核的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
该细分品类的日常处理文档包含开户申请单、营业执照扫描件、行业资质证明、开户审核记录等，数据来源覆盖广告平台后台、国家企业信用信息公示系统、客户主动提交的材料以及公开的行业准入规则。数据更新频率通常为每日或随每一笔开户申请同步更新，单份审核材料的字段包含主体名称、统一社会信用代码、行业类目、申请时间、审核状态等，文档长度与字段数量随实际提交的材料动态调整，无统一固定标准。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多数据源的混合使用要求溯源功能能够精准区分不同来源的信息，避免混淆客户提交的材料与平台后台的自动核验数据。动态更新的特性要求溯源支持按需拉取最新数据，确保资质核验的时效性。多样的文档结构要求溯源能够适配不同格式的材料，准确匹配字段信息，同时需控制数据量以避免拖慢审核流程。此外，该品类的出错后果直接关联开户合规性，因此溯源的准确性与可追溯性要求较高，需完整展示信息的来源路径与更新时间。

## 配置怎么定
本配置适用于 FastGPT v4.17.0

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 引用来源最大token数 | 800–1200 token | 匹配开户审核单份材料的平均长度，避免截断统一社会信用代码、行业资质编号等关键信息 |
| 返回关联数据范围 | 仅返回关联来源字段 | 聚焦开户申请、资质文件的核心溯源内容，减少冗余数据对审核流程的干扰 |
| 开启溯源详情 | 是 | 支持展示材料提交渠道、审核节点、更新时间等细节，满足资质核验的严谨性要求 |
| 单次溯源召回条数 | 前5条 | 平衡溯源效率与信息完整性，避免过多数据拉长审核时长 |
| 溯源超时时间 | 60秒 | 适配开户审核的实时性要求，避免因等待过久影响业务流转 |

## 容易做错的三处
- 现象：导出工作流和相关配置后，导入其他环境时溯源插件提示未找到指定数据源。原因：导出配置时未同步勾选关联的数据源权限配置，导致导入环境无法识别对应数据源的调用权限。
- 现象：展示溯源内容时弹出“没有权限操作此对话记录”的提示。原因：未配置溯源内容的访问权限规则，未将开户审核专员的角色组加入可访问列表。
- 现象：在溯源提示文案中输入的换行符未生效，直接以原文形式展示。原因：未使用平台支持的富文本换行格式，或在纯文本模式下输入换行符未被正确解析。

## 怎么确认配好了
- 发起一次模拟开户审核请求，检查溯源结果是否关联到正确的数据源，如国家企业信用信息公示系统的查询结果，调整引用来源最大token数以适配不同长度的材料。
- 验证不同角色的专员是否能正常访问溯源内容，根据实际角色权限调整访问范围配置。
- 测试溯源提示文案的换行效果，确认输入的换行符能正确渲染为可见换行。
- 查看工作流导入后的插件状态，确认所有关联的数据源配置已被正确加载，无报错提示。
