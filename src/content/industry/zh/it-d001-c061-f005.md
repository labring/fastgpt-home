# 性能测试与容量评估的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据主要来自压测平台、APM监控系统、数据库慢日志与生产流量基线。日常产出的文档包含压测方案、容量评估报告、压测数据记录与优化建议单，数据更新频率为每月或每重大版本发布时。典型字段包含吞吐率、延迟、资源使用率、容量余量等，对应单位通常为TPS、毫秒、百分比、核数与各类存储容量单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且包含多类专业指标，要求多轮对话逐步对齐不同来源的评审数据；更新频率相对固定但变更后需及时同步最新压测结果，提示词需支持定期拉取更新后的文档内容；文档结构分散且包含专业术语，需通过多轮对话梳理不同文档间的关联逻辑；字段带有特定单位，提示词需明确要求保留单位以避免指标混淆；评审过程聚焦压测模型设计、瓶颈定位与结论复核，多轮对话需引导工程师逐步拆解这些核心环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 性能测试相关文档与对话历史通常较长，需覆盖完整评审上下文，适配FastGPT v4.17.0的上下文处理逻辑 |
| `variables` | 最多绑定5个核心指标变量 | 避免过多变量导致对话逻辑混乱，聚焦吞吐、延迟等核心评审指标 |
| `messages` | 保留最近10轮对话历史 | 代码与变更评审的对话通常不超过10轮即可覆盖完整评审流程 |
| 提示词词库匹配 | 开启并导入压测术语词库 | 提升TPS、延迟阈值等专业术语的识别准确率 |
| 输入引导配置 | 预设「请结合压测数据与容量报告分析变更影响」 | 明确对话方向，引导对齐评审目标 |
| `chatId` | 绑定评审会话专属ID | 区分不同变更的评审对话，避免上下文混淆 |

## 容易做错的三处
- 现象：调用API生成评审结果时，输出的最后一个变量值会叠加前一个变量的计算结果。原因：未在`variables`配置中隔离不同轮次的变量作用域，导致对话上下文未正确重置。
- 现象：配置了输入引导与专业词库后，对话界面未显示预设的引导问题。原因：未开启输入引导的生效开关，或词库未正确关联到当前应用的提示词配置。
- 现象：上传XLSX格式的压测数据文件至知识库后，对话中无法复述文件内的表格内容。原因：未启用XLSX文件的结构化解析插件，或提示词未明确要求读取表格数据。

## 怎么确认配好了
- 发起一轮测试对话，输入「请梳理本次变更的压测影响」，检查回复是否自动关联预设的词库术语。
- 查看应用的配置页面，确认`variables`绑定的指标变量与当前评审场景匹配。
- 上传测试用的XLSX压测文件，发起对话要求复述内容，检查是否能正确读取表格字段。
- 查看工作流运行日志，确认`messages`的历史轮次未超出预设的保留上限。
