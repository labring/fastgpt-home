# 投放效果优化的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本文适配FastGPT v4.17.0版本。该品类的数据主要来自广告平台后台、归因系统、CRM线索库与落地页统计工具，更新节奏多为日级或实时。日常关联文档包含广告投放日报周报、每日调价记录、素材AB测试台账与优化复盘报告，文档字段通常包含曝光量、点击量、转化数、预算消耗额等，单位多为次、元、条，不同广告计划对应独立的数据条目。

## 这些特征在「上下文与 token」这一环带来什么约束
多源实时数据的更新节奏要求上下文需覆盖近期的调价、素材测试结果，否则无法支撑异常指标定位与预算调配。文档结构多样且关联多类业务字段，上下文需要匹配不同文档的格式与核心指标，token消耗会随文档数量和更新频率上升。实时更新的数据会导致上下文缓存过期，需要控制上下文的时间范围与token上限，避免超出模型限制。同时，投放效果优化的核心是关联多源数据，上下文需优先保留广告曝光、转化、预算消耗等核心指标的片段，避免无效内容占用token，影响核心分析的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 12000–15000 token | 匹配投放效果优化多源数据的总token消耗，覆盖单日调价记录、素材AB测试台账与优化复盘报告的核心业务内容 |
| `quoteMaxToken` | 1800–2200 token | 优先保留广告曝光、转化、预算消耗等核心投放指标的上下文片段，避免无关业务内容占用token资源 |
| 最大上下文刷新间隔 | 1小时 | 适配数据日级与实时更新的节奏，避免缓存过期导致上下文与当前投放数据脱节 |
| 关联文档筛选阈值 | 前3条 | 匹配日常文档的平均数量，聚焦最新的调价与素材测试记录，减少非核心内容的token消耗 |
| 上下文过滤规则 | 仅保留近7天数据 | 符合投放优化复盘的常规时间范围，过滤过期数据以降低总token占用 |

## 容易做错的三处
- 现象：调用API发起连续提问时，后续问题出现答非所问的情况。原因：未正确配置`maxContext`参数，未将历史对话与当前问题的关联上下文纳入token范围。
- 现象：工作流已开启上下文设置，但通过API调用时无法保留上下文。原因：未在API请求中携带历史上下文的关联标识，或未绑定对应知识库的上下文配置。
- 现象：上下文片段加载后出现截断或缺失核心指标的情况。原因：`quoteMaxToken`参数取值过小，导致核心的广告数据片段被截断。

## 怎么确认配好了
- 提交包含历史调价记录与当前投放问题的测试提问，检查回复是否关联历史数据与当前问题的逻辑。
- 查看API请求日志，确认请求参数中包含`maxContext`与`quoteMaxToken`的配置值，且取值符合预设标准。
- 连续提交3次以上相关提问，验证每次回复是否始终关联投放相关的历史数据，无答非所问的情况。
- 对比上下文总token数与配置的`maxContext`取值，确保未超出模型的token限制。
