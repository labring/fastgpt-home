# 接口联调与数据对接的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
该品类的数据通常来自客户系统接口、API文档、测试数据、联调日志，更新节奏为日度或每阶段交付周期内。日常维护的文档包含接口清单、联调记录、字段映射表、问题跟踪表，数据字段涵盖接口地址、请求方法、参数定义、返回字段映射、异常状态码等，无统一强制单位，随具体对接场景调整。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据多源且更新频繁，要求工作流支持动态拉取最新接口配置与联调日志；日常文档以结构化表格为主，要求工作流适配读取结构化数据节点，便于自动校验字段映射关系；最耗时的字段口径确认环节，要求工作流加入字段一致性校验节点，减少人工核对成本；由于是持续系统间的实时接口交互，需支持循环调用与批量编排，同时需配置异常捕获与回滚机制，避免数据不同步或业务中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 包含接口地址、请求参数、字段映射规则、文件上传路径 | 用于传递联调所需的动态数据，适配多接口并行联调场景 |
| `nodeId` | 按接口分组分配唯一`nodeId`，标注接口名称 | 用于定位各接口联调节点，便于排查调用链路与日志回溯 |
| 重试次数 | 3次 | 应对接口临时抖动或网络波动，符合联调场景的常规异常恢复需求 |
| 超时时间 | 300秒 | 适配复杂接口的响应时长，避免因等待过长导致工作流中断 |
| 上下文窗口 | 保留当前会话前3条联调日志 | 用于评审时回溯历史操作，避免关联无关的全局历史记录 |
| 文件上传限制 | 支持上传≤1000 MB的接口文档、测试用例文件 | 用于补充联调所需的参考资料，适配常规对接场景的文件大小需求 |

## 容易做错的三处
- 工作流配置仅保留1条聊天记录，但评审时仍关联到久远的历史联调日志。原因是上下文窗口的配置范围未限定为当前联调会话，默认拉取了全局历史数据。
- 通过API调用工作流时无法上传文件，且无法为文件类型变量传递参数。原因是未在`variables`中正确声明文件上传的参数格式，或未绑定对应的文件存储节点。
- 升级到FastGPT v4.14.0后，上传文件时提示Failed to create post presigned url。原因是工作流的文件预签名配置未适配FastGPT v4.17.0的存储规则，需重新校验节点配置。

## 怎么确认配好了
- 触发工作流后，检查`variables`中传递的接口参数是否与当前联调任务的配置一致。
- 查看工作流节点日志，确认各`nodeId`对应的接口调用链路正确，无节点错位或参数遗漏。
- 上传测试文件后，验证工作流是否能正常读取文件内容并参与联调校验环节。
- 模拟接口超时或异常返回场景，确认工作流触发重试机制后能正常恢复执行。
