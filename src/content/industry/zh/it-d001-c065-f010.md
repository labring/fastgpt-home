# 接口联调与数据对接的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
该品类的核心数据来源于客户系统接口、API文档、测试数据与联调日志，日常维护的文档包括接口清单、联调记录、字段映射表与问题跟踪表。接口清单包含接口标识、请求路径、参数规则等字段，联调记录标注调用时间与返回码，字段映射表记录业务字段与接口字段的对应关系，数据更新频率多为每日或每项目阶段，数据结构随接口迭代动态调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散且格式不统一，溯源环节需精准匹配不同数据源的标识字段，避免混淆不同接口的调用记录。数据更新频率不固定，需同步标记数据源的更新时间以保证溯源准确性。日常文档的字段结构多样，需针对接口清单、联调日志等不同文档类型设置专属的关联规则。同时，该品类涉及持续的系统间交互，溯源需覆盖完整的调用链路，单一结果片段不足以支撑排查需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | 1000–1500 token | 适配接口联调场景下的参数、日志与映射表内容长度 |
| `responseData` | 开启 | 需完整保留接口返回的原始数据用于异常排查与口径对齐 |
| `detail` | 全量 | 覆盖调用链路、字段映射、返回码的全部细节 |
| 溯源关联范围 | 接口清单、联调日志 | 匹配该品类日常维护的核心数据源 |
| 来源更新标记 | 按日/按阶段 | 贴合该品类的实际数据更新节奏 |

## 容易做错的三处
- 现象：知识库搜索卡片选择知识库后变量引用失效，原因：未关联接口联调场景专属的数据源（如接口清单、联调日志），仅调用通用知识库。
- 现象：查看聊天回答的知识库引用时出现报错，原因：`responseData` 配置未开启，无法溯源接口返回的原始数据，导致引用链路断裂。
- 现象：回答中强制出现知识库搜索引用内容，原因：未关闭非必要的通用数据源关联，错误绑定了无关的文档库。

## 怎么确认配好了
- 导入接口清单、联调日志等专属数据源，检查引用来源是否自动关联对应文档的标识字段。
- 发起一次模拟接口调用，查看返回结果的溯源信息是否包含调用时间、返回码等关键字段。
- 调整`quoteMaxToken`参数，验证长内容的引用是否被完整保留或按规则截断。
- 确认当前使用的FastGPT版本为v4.17.0，确保配置项兼容当前系统版本。
