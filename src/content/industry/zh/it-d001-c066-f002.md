# 搜索广告关键词管理的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
搜索广告关键词管理的核心数据来自搜索广告后台、搜索词报告、竞价排名数据与落地页数据，日常处理的文档包括关键词清单、否词表、出价记录与搜索词报告。数据字段包含关键词文本、匹配类型、出价金额、搜索量、转化成本等，部分文档以批量结构化表格形式存在。数据更新频率多为每日或每周，由SEM优化师、代理商运营及品牌市场人员日常维护，用于支撑关键词扩展、否词筛选与出价匹配调整等核心工作。

## 这些特征在「上下文与 token」这一环带来什么约束
搜索广告品类的结构化批量数据特征，要求上下文与token配置需适配多字段文本长度与高频更新的特性。单条关键词或搜索词记录的文本加上元数据会占用一定token，批量召回的历史数据会快速消耗上下文额度，若未合理控制会超出模型上限导致评审失败。同时，数据更新频率较高，上下文需定期同步最新的出价、否词信息，否则会使用过期数据开展评审。此外，品类数据的专业性较强，无关的通用知识会干扰评审结果，需严格限定上下文的召回范围，避免无效token占用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文token数 | 8000–12000 token | 适配搜索广告批量文档的总长度，避免超出FastGPT v4.17.0版本的模型上下文上限 |
| 单条引用最大token | 300–500 token | 匹配单条关键词、否词或搜索词记录的文本加元数据的长度，确保引用内容完整 |
| 上下文刷新间隔 | 每日 | 匹配搜索广告数据的日更频率，确保评审时使用最新的出价与否词数据 |
| 召回内容范围 | 仅当前项目的关键词清单、否词表、出价记录 | 限定检索边界，减少无关数据占用token，提升评审精准度 |
| 专业术语优化 | 开启 | 适配搜索广告的专业表述，减少无效token消耗，提升上下文匹配效率 |

## 容易做错的三处
- 调整上下文额度后，评审时未加载当前项目的关键词管理数据，反而引入无关通用知识。原因是未限定召回内容范围，导致检索范围覆盖了非目标品类的文档。
- 配置单条引用token上限后，长关键词的评审内容被截断。原因是单条引用最大token的取值设置过小，未适配关键词加匹配类型、出价等元数据的实际长度。
- 等待超过一周后评审结果仍未更新。原因是上下文刷新间隔设置过长，未匹配搜索广告数据的日更频率，导致使用过期数据开展评审。

## 怎么确认配好了
- 上传一份测试用的关键词清单与否词表，发起评审请求，查看召回的上下文内容仅包含上传的文档数据，无无关通用信息。
- 输入一条包含完整元数据的长关键词评审请求，查看返回内容未被截断，确认单条引用的token占用符合配置的取值范围。
- 等待一个完整的更新周期后，发起包含最新出价调整的评审请求，查看结果中包含最新的出价数据。
- 查看上下文的token占用指标，确认未超出配置的最大上下文token数，无溢出报错。
