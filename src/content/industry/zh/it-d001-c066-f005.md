# 搜索广告关键词管理的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据通常来自搜索广告后台、搜索词报告、竞价排名数据与落地页数据，更新节奏多为日度或周度。日常产出的文档包含关键词清单、否词表、出价记录与搜索词报告，各类文档的字段包含关键词文本、匹配模式、出价金额、展现量、点击量、转化数据等，部分文档需关联对应账户的投放时段与地域设置。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于该品类的数据按投放账户、地域与时段划分，且存在多类独立文档，多轮对话需明确区分不同任务上下文，避免数据混淆。数据更新频率为日度或周度，对话流程需支持定期同步最新的搜索词报告与竞价数据，确保提示词调用的信息时效性。同时，核心任务分为关键词扩展、否词筛选、出价匹配调整三类，多轮对话需按任务节点拆分交互，保留每一步的操作上下文，便于回溯与调整。此外，不同优化师的操作日志需独立存储，需通过标识参数区分对话归属。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 按投放账户+任务类型生成唯一标识 | 区分不同账户与任务的对话历史，避免上下文混淆 |
| `messages` | 按任务节点拆分轮次，每轮传递当前任务相关的文档片段 | 适配多类独立文档结构，减少上下文过载 |
| `variables` | 预设关键词清单、否词表的文件路径或数据ID | 快速调用品类专属业务数据，降低重复输入成本 |
| 单次传递文档长度 | 800–1200字符 | 适配搜索词报告单条内容长度，提升提示词理解效率 |
| 最大上下文长度 | 8000–12000 token | 匹配品类文档总内容量，避免超出模型处理上限 |
| 对话保留时长 | 7天 | 适配周度数据更新节奏，定期清理过期数据 |
| FastGPT版本 | v4.17.0 | 适配当前版本的参数传递与日志存储逻辑 |

## 容易做错的三处
- 调用API时传递`chatId`无预期效果，后台日志未显示对应对话归属。原因是未按投放账户与任务类型生成唯一标识，或参数传递格式不符合要求。
- 免登录链接用户删除对话内容后，后台日志同步被删除。原因是前端对话状态与后台日志存储逻辑未做分离，直接绑定了同一存储路径。
- 新对话无法加载之前保存的全局变量。原因是未通过`variables`参数绑定全局变量的唯一数据ID，导致对话上下文无法关联历史存储的业务数据。

## 怎么确认配好了
- 发起新对话并传递`chatId`，检查后台日志是否显示对应标识，确认上下文关联正常。
- 上传品类专属的关键词清单与否词表，通过`variables`参数调用，确认对话可直接读取对应数据。
- 发起多轮交互，每轮操作后查看对话历史，确认上下文按任务节点拆分，未出现无关数据混杂。
- 测试免登录链接的对话删除操作，确认后台日志未被同步删除，存储逻辑符合预期。
