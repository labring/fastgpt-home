# 搜索广告关键词管理的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
该品类的核心使用主体为SEM优化师、代理商运营与品牌市场人员，日常工作文档包含关键词清单、否词表、出价记录、搜索词报告四类核心文件。数据主要来自搜索广告后台、搜索词报告、竞价排名数据与落地页数据，更新频率按日或周更新。文档字段涵盖关键词文本、匹配模式、单次出价、点击量、转化成本等，单位包含人民币、次、元/转化等，不同数据源的字段命名存在细微差异。

## 这些特征在「工作流编排」这一环带来什么约束
由于该品类数据来源分散且字段命名存在细微差异，工作流编排需配置跨数据源字段对齐节点，统一处理不同搜索广告后台导出的关键词、出价数据。因数据更新频率为日或周，工作流需支持定时触发或文件上传触发两种模式，适配日常批量处理需求。四类核心文档的结构差异要求工作流设置多文件解析分支，分别处理关键词清单、否词表等不同类型的输入文件。带单位的数值字段需额外配置格式校验节点，避免单位不匹配导致的计算错误。同时，作为代码与变更评审辅助场景，工作流还需包含变更前后的关键词对比环节，确保调整内容符合预设规则。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 定时触发（每12小时）/ 文件上传触发 | 适配日/周更新的数据处理节奏，匹配日常批量处理需求 |
| `variables` | 预设关键词匹配模式、出价单位等全局变量 | 统一跨数据源的字段校验标准，减少格式冲突 |
| 多文件解析分支 | 按文档类型分配对应解析节点 | 适配四类核心文档的不同结构要求 |
| 上下文保留轮次 | 前3轮对话 | 平衡AI调用的信息完整性与处理效率，符合短对话处理场景 |
| 节点超时时间 | 600秒 | 适配批量处理大量关键词数据的耗时需求，避免中途中断 |
| 文件上传大小限制 | 单文件不超过1000 MB | 匹配日常导出的广告数据文件大小范围 |

## 容易做错的三处
- 现象：工作流中配置文件上传节点后，调用文档解析工具时返回路径无效报错。原因：未正确配置`CUSTOM_READ_FILE_URL`环境变量，导致工具无法读取上传文件的存储路径。
- 现象：多次使用同一ID触发工作流，AI调用的上下文保留轮次未按预期匹配。原因：未通过`variables`绑定会话标识参数，导致不同调用复用了相同的上下文缓存。
- 现象：批量处理关键词清单时，部分字段的单位校验未生效。原因：未在全局变量中预设单位校验规则，导致跨数据源的字段格式未统一。

## 怎么确认配好了
- 触发测试：手动上传一份测试用的否词表，查看工作流是否自动启动并生成解析结果。
- 变量校验：在应用链接中添加测试参数，查看工作流的`variables`是否正确接收传入值。
- 超时测试：模拟批量处理1000条关键词数据，查看工作流是否在600秒内完成执行无中断。
- 上下文测试：使用同一ID两次触发工作流，查看第二次调用的上下文是否符合预设的保留轮次。
