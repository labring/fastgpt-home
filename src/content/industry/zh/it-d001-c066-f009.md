# 搜索广告关键词管理的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
这个品类的数据主要来自搜索广告后台、搜索词报告、竞价排名数据与落地页数据。日常产出的文档包含关键词清单、否词表、出价记录与搜索词报告，字段涵盖关键词文本、匹配模式、出价单位、搜索量、转化关联标识等。数据更新节奏通常为每日或每周，单份文档的条目数随账户规模变化，核心字段均为文本或数值类型，无复杂嵌套结构。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于该品类数据多为结构化的文本与数值条目，且更新节奏固定，工具调用需适配批量拉取与增量同步的场景，避免单次请求过载。日常文档的字段相对固定，插件需明确匹配关键词、匹配模式、出价等指定字段，无法兼容非标准字段的解析。变更评审环节需对比当前与历史的关键词配置，工具调用需关联历史数据接口，同时需处理广告后台接口的调用频率限制，防止触发账户风控。此外，数据来源的多平台特性要求插件支持不同广告后台的接口适配，避免硬编码单一平台的请求逻辑，同时需适配该品类最耗时的关键词扩展、否词筛选等场景，提升评审效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `{"type": "function", "function": {"name": "keyword_review"}}` | 强制指定调用关键词评审专用工具，避免模型自主选择无关工具 |
| `functionCall` | 开启强制函数调用 | 确保工具调用的返回格式符合变更评审的结构化解析要求 |
| 工具调用超时时间 | 300 秒 | 适配广告后台接口的平均响应时长，避免因接口延迟导致调用失败 |
| 批量请求批次大小 | 前 20 条 | 匹配单份关键词清单的常规条目规模，防止单次请求超出接口容量限制 |
| 插件数据字段映射 | 匹配关键词、匹配模式、出价金额 | 适配该品类文档的标准字段结构，确保解析结果准确 |
| 鉴权方式 | 使用应用 API Key | 遵循FastGPT的鉴权规范，避免混用AIPROXY_API_TOKEN对应的AI Proxy管理员Token |

## 容易做错的三处
- 调用工具时返回模型不支持函数调用的报错，但应用配置的测试环节运行正常。原因是未正确设置`toolChoice`参数，或模型渠道配置未配置支持函数调用的模型。
- 工具拉取的关键词数据缺失匹配模式字段。原因是插件的字段映射配置未覆盖该品类的标准字段，或广告后台接口返回的字段名称与映射规则不匹配。
- 批量调用工具时触发接口限流。原因是批量请求批次大小设置过大，超出广告后台的接口调用频率限制。

## 怎么确认配好了
- 检查FastGPT v4.17.0版本的App/Admin服务端环境变量，确认已正确配置`AIPROXY_API_ENDPOINT`与非空的`AIPROXY_API_TOKEN`，且未在应用配置中重复填写。
- 运行工具调用测试，验证返回结果包含关键词、匹配模式、出价金额等该品类的标准字段，格式符合预设的函数调用要求。
- 模拟变更评审场景，提交批量关键词数据，确认工具调用的响应时长符合预设的超时阈值，无频繁限流报错。
- 查看FastGPT的系统日志，确认工具调用的请求头中使用了应用API Key，不要使用AIPROXY_API_TOKEN对应的AI Proxy管理员Token。
