# 数据安全分类分级的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自数据资产盘点结果、数据库元数据、业务系统说明文档及公开法规文件。日常产出的文档包括数据目录、分类分级规则表、重要数据识别清单与评审纪要。数据更新频率为季度更新或随业务系统变更触发更新，数据字段包含资产标识、敏感等级、归属部门、合规要求等，无统一固定单位，随不同资产类型调整。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新无固定周期，要求工作流支持多源数据拉取与增量同步配置，适配不同数据源的拉取逻辑。文档结构多样，需工作流适配不同格式的规则表与识别清单导入，避免格式校验失败。更新触发场景复杂，需支持定时与事件触发两种启动方式，覆盖季度定期更新与临时系统变更的需求。评审纪要需关联到对应分级配置，要求工作流保留上下文关联节点，确保合规评审流程可追溯。同时，数据治理团队的操作习惯要求工作流节点可配置人工审批环节，适配合规评审的线下流程。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 全局变量绑定数据目录、分类规则表的统一路径前缀 | 匹配多源数据的调用路径，适配不同资产的拉取逻辑 |
| `nodeId` | 绑定前序数据拉取节点的nodeId | 确保工作流节点间的数据流转准确，避免跨节点数据丢失 |
| 触发方式 | 定时触发+事件触发双模式，定时周期设为7天，事件触发绑定数据变更webhook | 适配季度更新与临时变更的双重需求 |
| 上下文保留设置 | 前序数据校验节点保留3轮对话，规则匹配节点保留1轮对话 | 匹配不同节点的功能差异，避免上下文冗余影响匹配精度 |
| 变量更新配置 | 空值更新需绑定节点输出的空字段触发 | 解决变量更新失效的常见问题，确保空值正确传递 |
| URL参数绑定 | 应用启动配置中开启参数映射，绑定data参数到全局变量 | 支持通过应用链接传递自定义全局变量值 |

## 容易做错的三处
- 工作流中变量更新为空值无生效，现象是节点输出字段显示为空，但全局变量面板中对应字段仍保留原有值，原因是未绑定空值触发的条件判断节点，仅直接调用变量更新组件。
- 应用链接传递全局变量失败，现象是打开应用后全局变量未携带指定参数，原因是未在应用启动配置中开启参数绑定开关，未正确配置URL参数映射规则。
- 多轮访问时上下文保留不一致，现象是同一ID多次访问后，前序节点的对话轮次不符合配置，原因是未将对话上下文与用户ID绑定，导致上下文被全局覆盖。

## 怎么确认配好了
- 手动触发工作流，检查数据拉取节点是否正确导入配置的文档内容，核对字段与源数据一致。
- 配置空值更新触发节点，传入测试空字段，查看全局变量是否正确更新为空值。
- 配置URL参数传递测试，访问带`data=1123`参数的应用链接，检查全局变量是否正确接收参数值。
- 模拟多次访问同一ID，查看不同节点的上下文保留是否符合配置要求。
