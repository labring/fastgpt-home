# 数据库云服务运维的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自云数据库控制台、慢日志、监控指标与工单系统，日常关联的文档包括实例变更单、备份恢复记录、性能诊断报告、参数调整记录。数据更新节奏随变更触发或每日更新，字段包含实例ID、变更内容、性能指标数值、工单编号等，单位涉及毫秒、GB、条等，且多与云租户的多服务边界绑定，不同租户的数据需严格隔离。

## 这些特征在「上下文与 token」这一环带来什么约束
数据来源分散导致上下文聚合时需跨多系统拉取，增加token消耗；文档结构多样（单条变更单、批量性能报告），需适配不同长度的上下文片段；多租户边界要求上下文隔离，避免token污染；更新频率高的变更数据需及时纳入上下文，否则影响评审准确性；慢日志的高频率条目可能导致token溢出，超出预设的`maxContext`限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配云数据库运维日常文档的平均总长度，避免token溢出 |
| `quoteMaxToken` | 1500–2000 token | 限制单条关联文档的token占用，防止上下文过载 |
| 上下文刷新时机 | 实例变更提交时 | 匹配数据更新频率，确保评审数据与当前状态一致 |
| 多租户上下文隔离 | 按租户ID分组 | 符合云服务多租户边界要求，避免跨租户上下文污染 |
| 单次召回文档上限 | 前3–5条 | 平衡上下文信息量与token消耗，适配慢日志、变更单的批量数据 |

本文适配FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：调用MCP工具时模型上下文被意外打断。原因：未配置`maxContext`的上下文边界限制，导致工具调用占用过多token触发上下文重置。
- 现象：上传的运维文档路径附带额外token导致无法被Flask处理。原因：未清理文件上传接口返回的临时token参数，将完整带token的路径直接传入业务处理逻辑。
- 现象：AI生成的评审结果出现不符合格式的JSON内容。原因：上下文内混入了格式不规范的工单或日志数据，导致模型输出格式被污染。

## 怎么确认配好了
- 查看上下文聚合日志，确认仅拉取当前租户的云数据库相关文档，无跨租户数据混入。
- 触发一次实例变更评审，检查调用MCP工具时未出现上下文中断报错。
- 上传一份性能诊断报告，确认业务系统能获取到无额外token参数的文件路径。
- 生成评审结果，验证输出格式符合预设的评审报告规范，无异常JSON片段。
