# 数据库运维的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
数据库运维场景的核心数据来源于数据库监控系统、操作审计日志、SQL执行计划文件与工单系统。日常产出的文档包括数据库变更单、慢SQL分析报告、备份恢复记录与权限申请单，其中变更单包含实例标识、变更语句、审批状态与执行时间，慢SQL报告记录查询耗时、扫描行数与阻塞时长。数据更新频率随操作触发，单次数据库变更对应一次更新，日常监控数据按日汇总。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据库运维的数据来源分散且格式各异，要求工具调用插件需适配多类数据源的解析规则，避免因格式不匹配导致数据拉取失败。数据更新随变更或按日触发，工具调用需匹配对应触发时机，确保评审时能获取最新的变更与监控数据。文档字段多且关联紧密，工具调用需精准提取指定字段用于分析，避免冗余信息干扰评审。同时，该场景出错后果直接影响数据库稳定性，工具调用需内置参数校验逻辑，防止非法操作触发。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `["function"]` | 强制锁定工具调用模式，避免AI同时生成直接回复与工具调用请求 |
| `functionCall` | 仅传入数据库相关参数 | 确保工具调用仅处理数据库运维场景的请求，避免无关参数干扰 |
| 工具调用超时时间 | 600 秒 | 匹配数据库变更审核的平均处理时长，防止因超时中断评审流程 |
| 单次工具返回数据条数 | 前 10 条 | 适配慢SQL报告、变更单的单批次数据量，避免上下文过载影响分析 |
| 上下文窗口大小 | 8000 token | 容纳完整的变更单与慢SQL数据，保证工具调用的分析完整性 |
| 数据源插件绑定规则 | 按数据库实例类型匹配 | 适配不同数据库的监控、审计日志格式，确保数据拉取准确 |

## 容易做错的三处
- 配置了固定回复规则后，工具仍自动生成AI直接回复。可排查项包括：未通过`toolChoice`参数强制锁定工具调用模式，导致AI同时触发了直接回复与工具调用逻辑。
- 工具调用返回的慢SQL数据字段缺失。可排查项包括：未匹配对应数据库的审计日志插件格式，导致解析时无法提取指定字段。
- 工具调用频繁超时。可排查项包括：设置的超时时间短于数据库变更审核的平均处理时长，或未配置数据源的连接超时参数。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量，确认`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径）和`AIPROXY_API_TOKEN`（AI Proxy管理员Token，需与AI Proxy服务端配置一致且不能为空）已正确配置且非空，符合FastGPT v4.17.0及以上版本的部署要求。
- 提交一条测试数据库变更单，触发工具调用流程，查看返回的工具结果是否包含预期的慢SQL数据或变更单信息。
- 查看AI Proxy的服务日志，确认工具调用请求已正常发送且返回状态码为200，无报错信息。
- 调整`toolChoice`参数为`none`，验证此时工具不会自动触发，仅按配置的规则返回预设内容。
