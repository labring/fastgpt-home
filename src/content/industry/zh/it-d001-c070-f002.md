# 数据清洗与质检的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
数据清洗与质检的日常文档包含清洗规则、质检抽样表、异常数据清单与交付报告。清洗规则为含字段校验逻辑的文本文件，质检抽样表包含抽样批次号、数据条目数、异常标记字段，异常数据清单记录异常类型与对应原始数据ID，交付报告包含质检通过率与异常占比。数据来源涵盖原始数据集、ETL日志、标注平台导出结果与抽样结果，更新频率为每日或按数据交付批次。

## 这些特征在「上下文与 token」这一环带来什么约束
日常文档多为结构化文本与清单类数据，上下文需关联同批次的清洗规则、抽样结果与异常数据，避免跨批次的上下文污染。数据来源分散导致上下文片段来源多样，需限定上下文的批次范围，防止混入非当前处理数据集的内容。数据更新频率为日/每批，上下文需按批次隔离，避免跨批次的ETL日志与抽样结果混淆。异常数据清单的条目较多，需控制token消耗，防止超出模型上下文上限导致内容截断，影响清洗规则与质检逻辑的正确解析。

## 配置怎么定
以下配置适用于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `10–20 条` | 数据清洗与质检的上下文需按批次隔离，10-20条可覆盖单批次的清洗规则、抽样结果与异常数据，避免跨批次污染 |
| `quoteMaxToken` | `8000–12000 token` | 单批次的异常数据清单、ETL日志片段总token数通常在此区间，可完整加载核心上下文而不超出模型限制 |
| 上下文批次隔离开关 | 开启 | 数据按日/每批更新，开启后可自动过滤非当前批次的上下文内容，避免上下文污染 |
| 最大上下文保留时长 | `24 小时` | 数据更新频率为日/每批，24小时可覆盖当日或单批次的所有关联文档，防止过期上下文干扰 |
| 上下文触发阈值 | 按实测标定 | 不同批次的数据量差异较大，需根据实际单批次数据的token消耗调整，确保上下文完整且不超限 |

## 容易做错的三处
- 现象：上传文件的相对路径附带token，通过HTTP请求提交至Flask处理时返回404错误。原因：FastGPT生成的相对路径包含token参数，直接拼接请求会导致路径解析错误，需先剥离token再拼接文件路径。
- 现象：设置上下文条数为30条，但对话明细仅显示2条上下文，回复无法关联上下文。原因：未开启批次隔离开关，上下文被非当前批次的内容覆盖，或配置的上下文过滤规则未正确生效。
- 现象：AI回复出现不符合格式的JSON内容，或异常数据识别结果混乱。原因：上下文token超出模型上限，导致部分清洗规则或异常数据清单被截断，模型无法正确解析上下文逻辑。

## 怎么确认配好了
- 查看FastGPT的上下文日志，确认仅显示当前批次的清洗规则、抽样结果与异常数据，无跨批次的无关内容。
- 提交测试批次的数据，核对AI返回的异常数据识别结果与本地异常数据清单一致，无遗漏或混入无关条目。
- 调整`quoteMaxToken`参数，观察上下文加载状态，确认未出现上下文截断或token超限报错。
- 测试不同批次的数据提交，确认上下文不会跨批次关联，不同批次的处理结果互不干扰。
