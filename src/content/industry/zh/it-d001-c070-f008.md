# 数据清洗与质检的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
该品类的数据来源包括原始数据集、代码变更触发的ETL运行日志、标注平台输出结果与人工抽样结果，更新频率为每日或按每批任务周期。日常产出的文档包含清洗规则配置文件、质检抽样表、异常数据清单与交付报告，文档字段涵盖数据标识、异常类型、处理状态、抽样比例等，无统一强制单位，随具体业务场景调整。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源与代码变更强关联，且更新周期随代码提交节奏调整，要求工作流编排需支持代码变更触发的自动启动逻辑，避免手动触发的延迟。日常产出的文档类型多样且需随代码变更同步更新，工作流需适配不同文档的解析规则，例如清洗规则需绑定代码变更对应的字段，异常数据清单需自动关联代码变更带来的新增异常。抽样质检环节耗时占比高，工作流需支持并行处理抽样任务，同时需预留异常数据的人工干预节点，应对代码变更导致的数据不可用或指标失真风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `variables` | 绑定清洗规则ID、抽样比例、异常阈值 | 适配不同代码变更批次的数据清洗与质检需求，匹配按代码提交节奏的任务更新 |
| `nodeId` | 关联ETL日志节点、标注结果节点、异常数据清单节点 | 实现代码变更触发的多数据源自动关联，避免手动配置的误差 |
| 工作流触发方式 | 按代码提交事件触发 | 匹配数据随代码变更的更新频率，减少无效运行 |
| 并行任务数 | 2-4 个 | 适配抽样质检环节的并行处理需求，平衡资源占用与处理效率 |
| 异常节点超时时间 | 300-600 秒 | 应对异常数据处理的耗时波动，避免任务因单次异常中断 |
| 文档解析规则 | 按清洗规则、抽样表模板配置 | 适配日常文档的结构特征，确保代码变更关联的数据字段正确提取，适配FastGPT v4.17.0的工作流节点规则 |

## 容易做错的三处
- 工作流发布后无法通过代码仓库触发，后台日志显示变量未定义。原因是未在`variables`配置中绑定代码变更触发的环境变量，导致触发时无法获取必要的调用凭证。
- 工作流运行时提示脚本执行超时，状态码返回504。原因是未设置合理的异常节点超时时间，导致代码变更带来的异常数据处理环节耗时超出预设阈值。
- 代码变更提交后，工作流中的音视频标记无法正常渲染。原因是未启用指定回复节点的富文本解析配置，仅手动插入标签未触发系统的格式转换逻辑。

## 怎么确认配好了
- 检查工作流的触发配置，确认已绑定代码提交事件作为启动条件，匹配业务的代码变更节奏。
- 验证`variables`配置项，确认已绑定清洗规则、抽样比例等必要参数，可通过模拟代码变更触发变量替换。
- 查看异常处理节点的配置，确认已设置合理的超时与干预规则，可手动模拟代码变更带来的异常数据触发流程。
- 调用官方测试接口发起工作流运行请求，确认任务状态更新正常，无参数报错。
