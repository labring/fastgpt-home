# 数据脱敏处理的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本品类的数据来自数据库、数据字典、脱敏工具及访问审批系统，更新频率为每批或每项目。日常产出的文档包含脱敏方案、字段映射表、脱敏验证报告与审批记录，其中字段映射表包含敏感字段标识、脱敏规则编码两类核心字段，脱敏验证报告包含验证批次、合规项匹配结果等内容，所有数据随项目推进或批量任务完成同步更新。

## 这些特征在「上下文与 token」这一环带来什么约束
数据来源分散导致单批次上下文数据量波动较大，每批或每项目的更新节奏要求上下文加载需适配任务周期，避免冗余加载。文档结构多样，字段映射表与验证报告的字段差异明显，需要精准匹配上下文片段的字段类型，防止无效token占用。敏感字段的识别依赖多源数据关联，过长的上下文会导致token消耗超标，影响评审辅助的响应速度。同时审批记录的时效性要求上下文需优先加载最新的合规审批数据，进一步限制了上下文的缓存范围。

## 配置怎么定
以下为适配本品类特征的上下文与token配置方案，基于FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 2000–5000 token | 适配每批或每项目的数据总量波动，避免单次上下文token超限 |
| `quoteMaxToken` | 800–1200 字符 | 匹配字段映射表、脱敏验证报告的单段文档平均长度 |
| 上下文加载优先级 | 优先加载最新审批记录 | 适配数据每批/每项目的更新节奏，保障合规数据优先生效 |
| 单段上下文截断阈值 | 1500 字符 | 过滤非核心冗余字段，降低无效token消耗 |
| token超限处理方式 | 自动截断非核心脱敏方案片段 | 保障代码评审辅助的基础功能正常运行 |

## 容易做错的三处
- 现象：启动代码评审辅助服务时出现token超限报错，日志显示上下文加载失败。原因：未根据每批项目的数据量调整`maxContext`参数，导致加载的脱敏数据总token超出阈值。
- 现象：多模型编排的工作流中，脱敏数据的上下文被重复消耗token。原因：未配置上下文共享规则，导致每个模型独立加载相同的字段映射表数据。
- 现象：脱敏验证报告的核心字段无法正确匹配到评审代码中。原因：未设置单段上下文截断阈值，过长的文档片段占用过多token，导致核心字段被意外截断。

## 怎么确认配好了
- 查看上下文加载日志，确认加载的数据类型与当前项目的脱敏文档类型一致。
- 触发一次代码评审任务，检查token消耗是否符合预设范围，未出现超限提示。
- 核对多模型工作流的token使用情况，确认脱敏数据的上下文未被重复加载。
- 模拟token超限场景，检查是否触发预设的截断处理逻辑，核心敏感字段未被丢失。
