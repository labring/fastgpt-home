# 数据脱敏处理的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据主要来自企业数据库、数据字典、自研脱敏工具及访问审批系统，更新节奏随每批数据处理任务或单个项目推进。日常产出的文档包含脱敏方案、字段映射表、脱敏验证报告与审批记录，其中字段映射表需关联原始字段与脱敏规则，脱敏验证报告需记录敏感字段识别结果与脱敏后数据可用性。核心字段包括敏感字段标识、脱敏规则类型、审批状态等，无统一固定计量单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散导致多轮对话需依次调用不同系统获取字段映射、审批记录等信息，需通过`variables`参数传递批次项目标识以定位对应数据。更新频率随项目变动，要求提示词需适配单次任务的上下文范围，避免跨项目数据混淆。日常文档结构复杂，多轮对话需按文档类型拆分提示词，分别指导敏感字段识别、规则配置验证。敏感字段的唯一性要求对话上下文需保留字段标识与脱敏规则的对应关系，防止上下文溢出导致配置错误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` 绑定 | 绑定当前项目会话 ID | 隔离不同批次的脱敏处理对话上下文，避免数据混淆 |
| `messages` 裁剪规则 | 仅保留当前任务的 2–3 轮对话 | 过滤跨项目文档的冗余信息，减少上下文干扰 |
| `variables` 传参 | 传入项目批次、敏感字段范围 | 定位当前任务对应的数据库、字段映射表等数据源 |
| 最大上下文长度 | 1800–2200 字符 | 适配脱敏方案、验证报告等多份文档的总长度 |
| 超时阈值 | 600 秒 | 适配跨系统获取脱敏工具、审批记录的响应时长 |
| 提示词模板拆分 | 按脱敏环节拆分 | 分别对应敏感字段识别、规则配置、可用性验证环节 |

## 容易做错的三处
- 现象为工作流运行后展示多轮AI对话的全部输出结果，原因是未配置对话历史裁剪规则，保留了全部过往对话上下文。
- 现象为通过外部渠道接入时，对话结果携带大量#*类非必要标点符号，原因是未在提示词中明确要求去除非标准格式标记。
- 现象为调用对话接口时未返回关联的项目数据源标识，原因是未通过`variables`传入当前项目的批次参数，导致模型绑定了错误的数据源。

## 怎么确认配好了
- 触发一次测试项目的脱敏评审对话，检查工作流仅展示最后一轮AI输出结果，确认对话历史裁剪配置生效。
- 调用对话接口后，检查返回结果中包含当前项目的批次标识，确认`variables`传参配置正确。
- 查看多轮对话的上下文日志，确认仅保留当前任务的指定轮次对话，确认`messages`裁剪规则生效。
- 手动触发敏感字段识别环节，检查模型输出的字段与当前项目的字段映射表一致，确认提示词模板拆分配置生效。
