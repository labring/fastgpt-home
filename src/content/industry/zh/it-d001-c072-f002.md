# 数据采集任务设计的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
这个品类的数据围绕采集任务全流程生成，来源包括客户明确的采集需求、公开可用的数据源、现场部署的采集工具及内部沉淀的样本库。日常产出的文档包含采集方案、样本规格说明、数据授权文件与任务排期表，更新频率随单项目推进或按周迭代。数据字段涵盖采集范围、字段定义、合规校验项、执行节点等，无统一固定单位，需根据客户业务场景调整。

## 这些特征在「上下文与 token」这一环带来什么约束
采集任务设计的文档与数据体量随项目复杂度波动，单项目的采集方案、授权说明等累计文本可达数千字符，且需关联客户业务规则。上下文需覆盖项目周期内的需求变更、样本调整记录，若上下文冗余或token超限，会导致大模型无法准确关联最新的采集规则。同时，不同项目的字段规格差异显著，上下文需精准匹配当前任务的字段定义，避免跨项目数据污染，且需严格控制token占用以适配大模型的输入上限。

## 配置怎么定
FastGPT v4.17.0 版本下的配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文条数 | 前10–15条 | 匹配单项目每周更新的任务排期、合规文档数量，避免上下文过载 |
| `maxContext` | 8000–12000 token | 适配采集方案、样本规格等累计文本的总长度，覆盖单项目核心数据 |
| 上下文召回阈值 | 0.75–0.85 | 需区分客户业务字段与通用文本，避免召回无关的历史项目数据 |
| `quoteMaxToken` | 2000–3000 字符 | 限制单条召回上下文的长度，确保单条样本规格说明的关键信息被完整提取 |
| 上下文刷新时机 | 任务排期更新后触发 | 确保最新的采集规则、授权变更被纳入上下文 |
| 上下文过滤规则 | 按项目ID匹配 | 排除其他项目的采集数据，避免上下文污染 |

## 容易做错的三处
- 配置`maxContext`为15条但对话明细仅显示2条：原因是未正确关联当前项目的上下文过滤规则，误召回了历史会话的无关数据，导致有效上下文被过滤。
- 大模型返回不符合格式的JSON回复：原因是上下文包含未格式化的采集方案片段，干扰了大模型的格式输出，需限制`quoteMaxToken`仅召回结构化的样本规格文档。
- 大模型提示上下文token数超标：原因是未设置`quoteMaxToken`，单条召回的采集方案文本过长，导致总token占用超出大模型输入上限。

## 怎么确认配好了
- 查看上下文列表，确认仅包含当前项目的采集方案、样本规格等文档，无其他项目的历史数据。
- 测试触发代码评审辅助，检查返回的上下文条数与设置的`maxContext`取值一致。
- 核对单条召回上下文的长度，确认未超过`quoteMaxToken`的限制。
- 模拟任务排期更新，检查上下文是否自动刷新，包含最新的调整内容。
