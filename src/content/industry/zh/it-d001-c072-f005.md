# 数据采集任务设计的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据围绕数据采集项目的全流程生成，日常文档包含采集方案、样本规格、授权说明、任务排期四类核心文件。数据来源涵盖客户需求、公开数据源、采集工具输出及内部样本库，更新频率以单项目或周为周期。数据字段包含样本范围、字段规格、采集权限、排期节点等，单位多为字符、条、天等，区别于后续的数据清洗与质检环节，该品类的数据直接决定原始数据的获取方式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散且更新周期灵活，要求多轮对话需按项目阶段逐步追问不同来源的细节，避免一次性加载过多无关数据。日常文档的字段结构固定，提示词需精准绑定采集方案、样本规格等文档的核心字段，确保对话输出与实际项目要求一致。单项目周期内的上下文更新频率，要求对话上下文窗口需适配单份文档的长度，避免截断关键信息。最耗时的样本范围定义、字段规格确认环节，要求提示词需聚焦优化这些步骤的交互逻辑，减少重复沟通。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话上下文窗口 | 800–1200 字符 | 适配采集方案、样本规格等单份文档的长度，避免截断关键字段，适配FastGPT v4.17.0的上下文管理规则 |
| `messages` 历史轮次限制 | 前 10 轮对话 | 匹配单项目周更的上下文更新节奏，避免冗余历史信息干扰当前交互 |
| `variables` 绑定范围 | 绑定采集方案、样本规格、授权说明 | 对应日常文档的核心字段，确保提示词调用准确的项目数据 |
| `chatId` 会话隔离规则 | 按项目维度划分 | 匹配每项目/周的更新频率，避免跨项目数据混淆 |
| 提示词触发阈值 | 按实测标定 | 适配样本范围定义、字段规格确认等耗时环节的对话节奏 |

## 容易做错的三处
- 调用对话接口返回 404 status code（no body），原因是未正确绑定`variables`对应的采集方案文档，导致上下文调用失败。
- 刷新页面后弹出“检测到没有可用的索引模型”提示，原因是未按项目维度配置`chatId`隔离规则，导致跨项目索引资源冲突。
- 尝试取消对话文件的下载有效期后仍触发过期提示，原因是未在`messages`中同步更新授权说明的有效期配置参数，导致上下文未同步最新规则。

## 怎么确认配好了
- 新建测试会话，输入“确认本次采集的样本范围”，查看对话是否能自动关联绑定的采集方案字段。
- 模拟多轮追问样本规格细节，检查对话上下文是否保留前10轮内的有效历史信息。
- 切换不同项目的会话ID，验证不同项目的对话上下文不会互相干扰。
- 上传测试用的授权说明文档，检查对话是否能正确调用其中的合法性校验规则。
