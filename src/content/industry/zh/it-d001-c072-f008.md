# 数据采集任务设计的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
这个品类的数据围绕采集任务全生命周期产生，来源包括客户书面需求、公开数据集接口、自研采集工具输出、内部样本库存量数据。日常产出的文档包含采集方案、样本规格表、授权合规说明、任务排期表四类核心文件。数据更新节奏以单项目为周期，单项目内每周同步一次最新的样本范围与字段要求。数据字段包含样本覆盖范围、数据格式要求、合规校验项、执行节点时限，无统一固定单位，需按采集目标匹配。

## 这些特征在「工作流编排」这一环带来什么约束
作为决定原始数据获取方式的品类，采集任务设计的专属数据特征，要求工作流编排必须覆盖合规校验前置环节。多来源的数据输入要求工作流支持多节点并行拉取，避免单数据源中断导致任务阻塞。按项目周期更新的样本范围，需要工作流支持通过`variables`动态调整节点参数，无需重复修改整体流程。字段规格的频繁确认需求，要求工作流内置可编辑的字段校验节点，适配不同客户的格式要求。合规校验环节必须作为前置分支，否则会触发侵权风险或样本无效的后果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按单项目更新，绑定样本范围、字段规格参数 | 适配按项目/周的更新节奏，无需重构工作流结构 |
| `nodeId` | 为每个合规校验、数据拉取节点分配唯一标识 | 便于定位执行异常的具体环节 |
| HTTP请求超时设置 | 300–600秒 | 适配公开数据源拉取的平均响应时长，避免短超时中断有效任务 |
| 循环嵌套配置 | 支持在循环节点内嵌入HTTP请求 | 适配批量拉取多批次数据源的需求 |
| 单次拉取样本上限 | 1000 条 | 适配公开数据源的单次返回限制，避免数据过载 |
| 分支触发规则 | 按单节点执行结果触发后续分支 | 避免多分支并行执行引发的资源冲突 |

## 容易做错的三处
- 现象：API调用嵌套知识库助手的工作流时返回空值。原因：未在`variables`中正确绑定知识库调用所需的上下文参数，导致工作流节点无法获取有效输入。
- 现象：配置变量引用时出现quote type error报错。原因：未按FastGPT v4.17.0的规范使用变量包裹格式，导致参数解析失败。
- 现象：工具调用节点同时输出AI回复与触发下一级分支执行。原因：未正确配置分支触发逻辑，默认启用了双分支并行执行路径。

## 怎么确认配好了
- 手动触发工作流，检查每个节点的执行日志，确认`variables`参数已正确加载绑定的样本范围与字段规则。
- 提交变量引用配置，验证是否出现quote type error报错，确认格式符合FastGPT v4.17.0的要求。
- 调整HTTP请求超时设置至600秒，模拟长时间响应的数据源请求，确认任务不会因超时提前终止。
- 配置循环嵌套节点并嵌入HTTP请求，运行批量拉取测试，确认循环逻辑正常执行且无资源冲突。
