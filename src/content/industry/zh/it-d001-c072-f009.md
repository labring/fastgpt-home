# 数据采集任务设计的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
数据采集任务设计的核心数据来自客户需求、公开数据源、采集工具与样本库，更新频率为每项目或每周。日常产出的文档包含采集方案、样本规格、授权说明与任务排期，其中数据字段涵盖样本范围、字段名称、单位、授权期限、排期节点等，无固定统一的字段格式，需随客户需求灵活调整。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据来源要求工具调用需支持对接不同类型的数据源接口，避免单一调用逻辑适配所有场景。按项目或周更新的节奏，要求插件需支持周期性同步采集配置与数据源信息。多样的文档类型与灵活的字段结构，要求工具调用需关联检索采集方案、样本规格等文档，辅助校验字段合规性。样本不可用与侵权风险的出错后果，要求工具调用需嵌入合法性校验环节，规避采集合规问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多源数据采集的动态调用需求，自动匹配对应数据源的工具调用逻辑 |
| `functionCall` | 按采集任务类型触发 | 区分公开数据源、客户自有数据源等不同场景的调用规则，避免无效调用 |
| 工具调用超时时间 | 600 秒 | 适配多源数据拉取、样本范围校验等采集环节的耗时需求 |
| 上下文窗口长度 | 800–1200 字符 | 适配采集方案、样本规格等文档的检索长度，保留关键配置信息 |
| 流量分流规则 | 按数据源类型分配 | 区分知识库检索与MCP调用的流量，避免资源争抢 |
| 并发调用上限 | 前 3 条单次调用 | 控制单批次采集的并发压力，降低返回为空的概率 |

## 容易做错的三处
- 现象：大模型未触发工具调用，返回结果为空。原因：未正确配置`toolChoice`参数，未指定适配采集任务的触发规则。
- 现象：并发调用量达1秒2-3次时，MCP调用返回`none`。原因：工具调用超时时间设置过短，未适配多源采集的拉取耗时，导致请求中断。
- 现象：工具调用无法关联采集方案文档。原因：上下文窗口长度设置过小，导致采集方案的关键配置信息被截断，无法触发对应工具。

## 怎么确认配好了
- 查看FastGPT v4.17.0的工具调用日志，确认`functionCall`触发规则与当前采集任务类型匹配。
- 发起1秒2-3次的并发测试，验证每次调用的返回结果不为空，无超时报错。
- 检索采集方案文档，确认工具调用能正确关联对应文档片段，提取出样本范围、字段规格等关键信息。
- 运行Python调用脚本，验证接口能正常返回工具调用配置，无参数格式错误导致的报错。
