# 数据采集任务设计的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据围绕数据采集项目全流程产生，来源包括客户需求文档、公开数据源说明、采集工具配置日志、内部样本库记录。日常产出的文档包含采集方案、样本规格表、数据授权说明、任务排期表，字段多包含样本范围、采集字段、合规校验项、交付周期等。数据更新以单个项目为周期，或按周同步最新的采集规则与授权文件，整体文档结构随项目调整，无固定统一格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
这类数据的非标准化文档结构，要求溯源时需支持多格式源文件的元数据提取，无需强制统一的结构化字段。不同项目的更新周期差异，要求溯源链路能绑定项目周期内的所有版本数据，避免引用过期的采集规则。样本范围与合规校验项的强关联性，要求引用溯源时同时关联数据合法性证明文件，确保采集数据的合规性。采集工具配置日志的分散存储，要求溯源环节能跨工具拉取关联的采集执行记录，确保引用来源的完整可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 采集任务的文档多为多段式非结构化内容，该取值可覆盖单份核心采集文档的关键信息，适配FastGPT v4.17.0的上下文长度限制 |
| 引用匹配阈值 | 0.72–0.85 | 采集方案的字段描述多为专业术语，该区间可准确匹配相似的规则内容，避免误关联无关文档 |
| `responseData` | 开启「返回完整源文件路径」 | 采集任务的溯源需关联原始配置文件与授权说明，完整路径可快速定位源数据，便于后续合规校验 |
| `detail` | 开启「提取文档元数据」 | 日常文档包含授权说明、排期表等非文本元数据，开启后可补充溯源的合规信息，完善引用来源的完整性 |
| 单次搜索上限 | 前3条 | 单个采集项目的核心文档数量有限，过多结果会增加上下文冗余，影响AI回答的准确性 |

## 容易做错的三处
- 检索结果仅返回文本类数据集，非文本的样本规格表、授权说明未被引用。现象：知识库搜索结果仅展示文本格式的文档，其他格式的源文件无匹配条目。原因：未配置非结构化文档的分块与索引规则，仅启用了文本数据集的检索能力。
- iframe嵌入FastGPT后无引用内容展示。现象：前端页面未按配置展示引用来源弹窗或列表。原因：未开启`responseData`的前端渲染配置，或未在嵌入参数中开放引用展示权限。
- 动态传参的知识库搜索未返回引用结果。现象：AI回答未关联配置的knowledgeSearch变量对应的知识库内容，无任何引用来源展示。原因：未将动态参数绑定到引用溯源的检索范围，或检索阈值设置过高导致匹配失败。

## 怎么确认配好了
- 上传一份采集方案文档至绑定的知识库，执行检索后查看返回结果是否包含该文档的完整源文件路径。
- 开启`detail`参数后，检查检索结果是否附带数据授权说明的合规元数据标记。
- 配置动态传参后，在工作流中触发检索，确认返回结果与传入的知识库范围一致。
- 查看FastGPT v4.17.0的后台检索日志，确认请求已正确携带配置的`quoteMaxToken`参数。
