# 数据集交付与版本管理的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据通常来自对象存储、数据仓库、标注平台及客户验收反馈。日常维护的文档包含数据集说明、版本记录、交付清单与验收报告，数据以每批交付包或每版本为单位更新。数据字段包含版本号、样本唯一标识、交付包容量、验收状态与交付时间等，不同来源的数据格式存在差异，部分标注平台导出的样本元数据需额外映射至标准交付字段。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散要求检索时覆盖多存储路径，增加溯源的匹配复杂度；按每批交付包或每版本的更新节奏，要求溯源必须绑定对应版本号，避免跨版本数据混用；多类型文档的结构差异，需要检索时匹配对应字段，例如从验收报告提取的客户反馈需关联至对应交付包；不同来源的数据格式差异，要求溯源系统支持元数据映射，确保引用来源的一致性。

本配置基于FastGPT v4.17.0版本的系统逻辑。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 引用上限 | 前5-8条 | 匹配每批交付包的核心文档数量，避免冗余引用 |
| `quoteMaxToken` | 8000-12000 token | 适配单批次交付包的总文档大小，避免截断关键溯源信息 |
| 返回数据详情 | 开启 | 完整返回版本号、交付包路径等溯源字段，满足代码评审的溯源需求 |
| `responseData` | 包含元数据字段 | 提取版本号、样本唯一标识等核心溯源信息，确保引用可追溯 |
| 溯源匹配阈值 | 按实测标定 | 适配不同来源的数据格式差异，避免误匹配或漏匹配 |
| `detail` | 开启详细溯源模式 | 展示具体引用的文档片段与来源路径，符合代码评审的合规要求 |

## 容易做错的三处
- 现象：检索结果无法匹配到指定交付包的文档，引用来源为空。原因：未绑定版本号作为匹配字段，导致跨批次数据混淆。
- 现象：部分上传的交付包显示训练异常，无法生成溯源链接。原因：未正确映射标注平台导出的元数据字段，导致系统无法识别有效溯源信息。
- 现象：引用返回的内容被截断，无法查看完整的交付包溯源信息。原因：`quoteMaxToken`设置值低于单批次交付包的总文档token数，未适配实际交付包大小。

## 怎么确认配好了
- 上传单批次交付包，触发代码评审辅助功能，检查返回结果中是否包含版本号、交付包路径等溯源字段。
- 调整引用上限配置，上传多批次交付包，验证检索结果仅匹配当前评审关联的版本数据。
- 上传标注平台导出的元数据文件，检查系统是否能正确映射至标准溯源字段，无缺失。
- 测试`quoteMaxToken`的不同取值，验证返回的引用内容是否完整，无关键片段被截断。
