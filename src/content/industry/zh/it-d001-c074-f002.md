# 文本标注项目的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
文本标注项目的数据主要来自客户提供的语料、内部标注平台产出的标注结果、专用词表以及质检抽样结果。日常产出的核心文档包括标注规范、样本包、质检报告与问题反馈表。数据更新频率按日或每批标注任务周期调整，每份数据包含语料原文、标注标签、质检标记等字段，无统一固定单位，仅按标注批次或语料长度进行分类存储。该品类聚焦语义边界、实体与意图识别，区别于图像标注项目的视觉特征处理逻辑。

## 这些特征在「上下文与 token」这一环带来什么约束
客户语料与标注样本的长度差异较大，短则数十字符长则数千字符，导致上下文窗口的适配难度提升。每日或每批的高频更新要求上下文处理需支持快速加载最新标注规范与词表数据，避免因数据滞后引发标注偏差。质检抽样结果与问题反馈表包含大量语义歧义案例，需要在上下文召回时优先关联同类疑难样本，同时需控制token消耗，避免超出模型支持上限。标签边界解释与一致性抽检的高频需求，要求上下文保留多轮标注与质检的关联记录，同时支持多轮会话的上下文保持，匹配工作流中的评审流程需求，进一步增加了token管理的复杂度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配文本标注项目的多轮标注记录与质检报告的平均token长度，避免超出主流大模型的上下文窗口上限 |
| `quoteMaxToken` | 1500–2000 字符 | 优先召回与当前标注任务相关的样本包、词表片段，控制单条引用的token消耗 |
| 上下文更新间隔 | 每6小时 | 匹配数据日更或每批更新的节奏，确保上下文关联的标注规范与词表为最新版本 |
| 疑难样本召回上限 | 前3条 | 聚焦标签边界解释与一致性抽检的高频场景，减少无关上下文占用token |
| 自动截断阈值 | 按实测标定 | 适配不同标注任务的语料长度差异，避免超长语料导致的token溢出 |

## 容易做错的三处
- 调用时返回422状态码，提示消息token长度不符合要求。原因是未遵循FastGPT的调用规范，未控制`maxContext`的取值，导致传入的上下文总token超出模型支持范围，未结合文本标注项目的语料长度特征做适配。
- 上下文关联的标注规范与词表过期，导致标注边界解释出现偏差。原因是未设置合理的上下文更新间隔，使用了超过更新周期的旧数据，未匹配文本标注项目的日/每批更新节奏。
- 召回的上下文包含过多无关样本，导致评审结果冗余且token消耗过高。原因是未限制疑难样本的召回上限，未聚焦标签边界解释与一致性抽检的核心场景。

## 怎么确认配好了
- 上传一批典型长度的标注语料与样本包，查看FastGPT v4.17.0的上下文预览界面的token消耗数值，确认未超出预设的`maxContext`范围。
- 修改标注规范后等待预设的上下文更新间隔，验证上下文关联的规范内容为最新版本。
- 提交包含疑难样本的评审任务，查看召回的上下文条目数量，确认符合预设的召回上限。
- 触发超长语料的评审流程，确认系统自动触发截断逻辑，未出现token溢出报错。
