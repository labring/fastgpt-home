# 文本标注项目的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
文本标注项目的核心数据来自客户提供的语料、内部标注平台产出的标注结果、专用词表以及质检抽样结果。日常维护的文档包括标注规范、样本包、质检报告和问题反馈表，数据更新频率为每日或每批标注任务完成后。该品类数据聚焦语义边界、实体识别与意图分类，区别于图像标注项目的视觉特征标注需求，数据字段包含标注内容、标签值、标注人、质检结果等，无额外视觉类字段。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且更新频繁，要求溯源时需精准匹配当前批次或当日的标注文档，避免跨批次数据混淆。文档类型多样，需支持从标注规范、质检报告等不同文档中提取溯源信息，因此需要适配多类型文档的检索规则。数据字段聚焦语义类标签，溯源时需关联标注内容与对应标签的依据，无法依赖视觉类关联逻辑。更新频率高意味着检索范围需限定在最近周期内，防止调用过期的标注数据影响评审准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1500–2000 token | 适配文本标注项目的长文档（如完整样本包、质检报告）的内容截取需求，避免截断关键标签依据 |
| 重排 | 开启 | 文本标注数据的语义关联较强，开启重排可提升溯源结果的相关性，精准匹配标注依据 |
| 单次搜索上限 | 前6条 | 匹配标注项目的单批次样本量级，避免过多冗余数据干扰代码与变更评审的核心逻辑 |
| `detail` | 开启 | 需返回溯源数据的完整字段（标注人、质检结果），支撑变更评审的责任追溯与合规校验 |
| 最大上下文 | 3轮对话 | 适配代码评审中的连续变更说明，避免上下文丢失导致溯源偏差 |
| `responseData` | 仅返回标注相关字段 | 过滤无关文档内容，聚焦标注规范、质检结果等核心溯源源 |

## 容易做错的三处
- 现象：连续发起代码评审相关的变更请求后，溯源结果无法关联前序的标注样本说明。原因：未配置合理的最大上下文参数，导致对话上下文被截断，无法追溯前序的标注依据。
- 现象：溯源结果中缺少标注人、质检状态等关键字段。原因：未开启`detail`参数或未指定需返回的字段范围，仅返回了文档片段未提取核心元数据。
- 现象：检索完整样本包时触发超时报错。原因：`quoteMaxToken`设置超出系统允许的最大阈值，或未限定检索的文档类型，导致加载过多冗余数据。

## 怎么确认配好了
- 发起一次包含多批次标注内容的检索请求，核对返回结果的文档类型是否仅包含标注规范、样本包、质检报告等目标文档。
- 查看检索结果的字段列表，确认包含标注人、质检结果等需要的溯源元数据。
- 发起连续三次变更评审相关的追问，确认溯源结果始终关联当前批次的标注数据，未出现跨批次内容。
- 在FastGPT v4.17.0版本中，验证AI高级配置页面可自定义引用模板，匹配当前配置的溯源规则。
