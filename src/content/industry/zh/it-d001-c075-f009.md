# 文档站维护的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
通常，文档站维护的核心数据来源于代码仓库、文档站构建日志、用户反馈与版本发布记录。日常产出的文档包含安装文档、API文档、迁移指南与FAQ，各文档包含版本号、更新时间、示例代码块、接口路径等字段。数据更新频率多为每周或随版本发布触发，不同类型文档的更新节奏存在差异。最耗时环节多为示例验证、版本差异同步与过期内容清理，出错后可能导致用户无法安装、误用接口或增加Issue数量。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源包含代码仓库与构建日志，工具调用需要支持拉取指定仓库分支的文档内容、解析构建日志中的错误信息。数据更新频率为周或每版本，要求工具触发时机需匹配该节奏，避免频繁拉取冗余数据。文档类型多样且包含代码示例，插件需要适配不同文档的解析规则，自动验证示例代码的有效性。用户反馈与版本记录则要求工具需同步更新过期内容与版本差异信息，减少人工清理成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用触发时机 | 按文档版本发布节点或每周凌晨2点 | 匹配文档周/每版本的更新频率，避免冗余拉取 |
| `toolChoice` | 自动模式 | 适配不同类型文档的解析需求，无需手动指定单个函数 |
| 插件输入参数格式 | 包含文档路径、仓库分支、构建日志ID | 对应数据来源为代码仓库与构建日志的字段要求 |
| 超时阈值 | 600秒 | 覆盖大型文档站的全量拉取与解析耗时，按实测标定 |
| 单次拉取文档上限 | 50条 | 控制工具调用的资源消耗，适配文档站的常规数据规模 |
| `functionCall` | 仅在需要自定义解析逻辑时启用 | 适配复杂文档的定制化处理需求 |

## 容易做错的三处
- 调用HTTP工具时无法传递文件类型入参，返回参数格式错误。原因：未配置插件输入参数的文件校验规则，导致工具无法识别二进制文件流。
- 工作流中RAG知识库与工具调用执行顺序混乱，无法同步获取最新文档数据。原因：未按文档更新频率设置触发时机，导致调用的知识库内容滞后于当前代码版本。
- 单独插件导出失败，导出文件为空或格式异常。原因：未正确配置插件的输出格式参数，或未传递会话ID导致上下文关联丢失。

## 怎么确认配好了
本核对流程适用于FastGPT v4.17.0版本。
- 触发一次工具调用，检查返回的文档内容是否与当前仓库分支的最新提交一致。
- 查看工作流运行日志，确认RAG知识库与工具调用的执行顺序符合预设配置。
- 尝试导出单独插件，检查导出文件的格式与内容是否符合文档站维护的要求。
- 发起一次会话，检查LLM调用时是否正确传递了当前会话ID，确保上下文关联正常。
