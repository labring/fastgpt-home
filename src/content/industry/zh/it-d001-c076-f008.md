# 日志平台与可观测性的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
本品类的数据主要来自日志系统、Trace平台、Metrics系统与应用SDK。日常维护文档包含日志采集规范、链路追踪说明、指标字典与看板配置记录。数据更新频率为每日或每版本发布时。日志数据包含时间戳、服务名、日志级别与上下文关联ID；链路数据包含全局链路ID、节点耗时与调用链路径；指标数据包含指标名称、采样值与统计周期，单位涵盖毫秒、字节、请求次数等。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且格式不统一，要求工作流编排需支持多数据源的格式转换节点，适配不同系统的字段映射规则。更新频率波动较大，需配置动态触发机制，支持按定时或版本发布事件启动流程。数据关联依赖上下文ID与链路ID，工作流需内置字段校验节点，确保关联字段不为空后再执行后续步骤。日志与链路数据的字段命名无统一标准，需在编排中预留自定义字段映射配置项，适配不同业务的采集规范。同时，批量拉取日志与链路数据的耗时存在波动，需预留合理的超时配置空间，避免流程因数据拉取延迟中断。此外，日志与指标数据的字段类型存在差异，需在编排中配置类型转换节点，确保不同数据源的字段可被统一处理，适配代码与变更评审辅助的场景需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 全局共享作用域 | 支持流程与嵌套子流程共享全局变量，适配多环节的数据传递需求 |
| `nodeId` | 按数据源类型命名 | 便于定位多节点执行异常，匹配日志与链路数据的节点关联逻辑 |
| 全局变量作用域 | 跨节点生效 | 适配不同数据源的字段传递，符合日志平台数据关联的业务场景 |
| 多模型token管理 | 独立计数 | 对应不同大模型调用的token消耗独立统计，避免单模型超量触发限制 |
| 超时阈值 | 600 秒 | 适配日志与链路数据的批量拉取时长，覆盖常规数据采集的耗时范围 |
| 单模型token上限 | 8000 token | 符合FastGPT v4.17.0的通用大模型上下文窗口标准 |

## 容易做错的三处
- 现象：流程启动后提示「变量未定义」。原因：未在`variables`配置项中提前声明全局共享变量，导致子流程无法读取主流程传递的参数，对应全局变量配置的常见误区。
- 现象：多模型调用后token计数异常叠加。原因：未开启多模型token独立计数配置，导致不同大模型的token消耗被合并统计，超出单模型上下文限制，对应多AI模型token共享的问题。
- 现象：流程执行后无关联日志数据返回。原因：未配置上下文关联校验节点，导致空的关联ID被传入后续环节，无法匹配到有效日志或链路数据。

## 怎么确认配好了
- 启动测试流程，检查`variables`配置的全局变量是否能在子流程中正常读取。
- 触发多模型调用节点，查看每个模型的token消耗统计是否独立显示。
- 传入空关联ID的测试数据，确认流程会在上下文关联校验节点终止并抛出提示。
- 等待600秒，确认批量拉取数据的流程未因超时被强制终止。
