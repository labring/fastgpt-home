# 机房巡检与环境监控的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自动环监控系统、门禁系统、UPS监控设备与视频巡检工具。日常产出的文档包含巡检表、温湿度记录、告警记录、值班日志，部分场景还包含自动化巡检脚本代码与设备变更申请文档。巡检表记录巡检时间、设备编号、温湿度数值与巡检状态；温湿度记录附带时间戳、测点位置与百分比数值；告警记录包含触发时间、关联设备与告警代码。数据更新频率为日级或实时，随机房运行状态动态变化。通常该品类的核心工作围绕异常告警确认、现场巡检记录与设施状态交接展开。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散、格式差异大，多轮对话需区分动环监控、门禁等不同数据源的上下文，避免跨类数据混淆。实时更新的告警与温湿度数据要求对话环节可即时拉取最新条目，提示词需明确指定调用最新知识库内容。巡检表、告警记录包含设备编号、百分比数值等细分字段，提示词需明确要求提取对应字段，避免泛化回答。值班日志的文本性内容需要保留历史对话上下文，确保多轮交互中可追溯之前的巡检与告警确认流程。针对代码与变更评审辅助的需求，多轮对话需关联巡检脚本代码、设备变更记录与对应运行数据，验证变更的合理性与合规性。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 前 8 轮对话 + 近 24 小时知识库数据（约 12000 字符） | 机房巡检数据更新频率为日级或实时，需保留近期对话上下文与最新巡检、告警记录，避免信息过期 |
| 问题优化 | 开启 | 巡检相关问题多包含设备编号、温湿度数值等细节，优化后可更精准匹配对应知识库条目 |
| 单次搜索上限 | 前 6 条结果 | 巡检与告警记录的关联设备数量有限，过多结果会干扰对话理解 |
| 变量绑定 | 绑定巡检设备编号、告警等级、巡检脚本版本变量 | 该品类数据包含明确的设备、告警与代码字段，通过变量可精准定位对应知识库内容 |
| 对话上下文保留 | 按会话持续保留 7 天 | 值班日志与巡检交接需跨多轮对话追溯，7天保留可覆盖常规值班周期 |

## 容易做错的三处
- 现象：对话回复中未展示知识库内配置的图片URL。原因：提示词未明确要求返回图片的可展示形式，或未开启多媒体内容的解析配置。
- 现象：调用对话接口时无法精准关联指定机房的巡检知识库。原因：未在请求参数中正确绑定`variables`变量，导致搜索范围覆盖全部知识库内容。
- 现象：对话超过设定轮次后历史巡检记录无法追溯。原因：未正确配置`messages`参数的上下文保留规则，超出限制的历史对话被自动清除。

## 怎么确认配好了
- 发起包含具体设备编号的对话，检查回复是否精准匹配该设备的温湿度、告警记录。
- 输入包含图片URL的知识库查询，确认回复中正确展示对应的URL或可点击的图片链接。
- 发起多轮连续对话，检查连续8轮交互后仍可正确追溯之前的巡检确认流程。
- 调用对话接口时传入指定的`chatId`，确认同一会话内的上下文被正确保留。
