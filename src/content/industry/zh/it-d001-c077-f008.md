# 机房巡检与环境监控的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
该品类数据来源为机房动环监控系统、门禁系统、UPS监控设备与视频巡检终端。数据更新节奏分为实时告警推送与每日巡检记录归档两类。日常文档包含巡检表、温湿度记录、告警记录与值班日志，字段包含设备唯一标识、温湿度数值（单位为摄氏度与相对湿度百分比）、告警等级、时间戳、巡检人员编号与设施状态描述。

## 这些特征在「工作流编排」这一环带来什么约束
多数据源接入要求工作流配置多节点并行拉取不同类型数据，实时告警数据需设置短间隔触发节点以保障响应时效。结构化巡检文档与告警记录需通过`variables`节点提取字段，用于后续代码变更评审的关联校验。值班日志的人员与时间字段需映射为工作流全局变量，确保评审环节可追溯操作主体。异常告警确认环节需配置分支判断，根据告警等级触发不同处理分支，避免无效评审流程占用资源。

## 配置怎么定
本文档适用于FastGPT v4.17.0及以上版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 映射巡检表、告警记录的核心字段，如设备ID、温湿度值、告警等级 | 匹配该品类数据的结构化字段特征，便于后续评审环节调用 |
| 触发节点间隔 | 实时告警节点设为30秒，巡检归档节点设为86400秒 | 匹配数据实时更新与日更的节奏，兼顾时效与资源占用 |
| AI对话上下文窗口 | 设为1500–2000字符 | 适配巡检文档与告警记录的平均长度，避免上下文溢出 |
| 分支判断节点 | 按告警等级划分低、中、高三个处理分支 | 适配告警分级处理的业务逻辑，避免无效评审流程 |
| `nodeId` | 为每个数据源接入节点分配唯一标识 | 便于工作流调试与节点间数据传递 |
| 工作流失败处理 | 配置告警推送与日志记录动作 | 匹配该品类出错后果的应急响应要求，保障异常可追溯 |

## 容易做错的三处
- 工作流中配置的表单输入字段在对话界面无显示，现象为用户提交的巡检信息未出现在工作流上下文，原因是未将表单节点的输出绑定至`variables`节点，导致全局变量未同步输入内容。
- AI对话模块的文件链接配置项未生效，现象为评审环节无法调取机房温湿度记录，原因是未填写正确的知识库关联ID，或未将文档上传至工作流绑定的知识库。
- 工作流执行超时，现象为节点状态长时间停留在运行中，原因是触发节点间隔设置过短，导致高频拉取动环监控数据超出服务资源上限。

## 怎么确认配好了
- 启动工作流测试，提交模拟巡检表单，检查`variables`节点是否正确提取表单字段并显示在上下文。
- 配置AI对话模块的文件链接，上传一条测试巡检记录，发起评审请求，检查是否能调取该记录内容。
- 手动触发实时告警节点，检查分支判断节点是否按告警等级正确跳转至对应处理分支。
- 查看工作流运行日志，确认所有节点的`nodeId`标识正常，无未绑定的变量或缺失的配置项。
