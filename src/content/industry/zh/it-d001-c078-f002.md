# 机柜上架与布线的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的核心使用主体为IDC运维工程师、网络工程师与设备实施人员，日常处理的文档包括上架申请、机柜布线图、端口标签表与施工记录。数据主要来自DCIM系统、资产管理系统、网络拓扑工具与客户工单，更新频率按单或每日更新。文档结构包含结构化字段（如机柜U位编号、端口号、线缆长度）与非结构化内容（如布线示意图、现场拍摄照片），字段无统一标准化格式，部分文档需跨系统关联核对。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据特征直接约束上下文与token的配置逻辑：结构化字段多且字段名不统一，会导致上下文召回时的token消耗波动；非结构化的布线图与照片需先转换为文本token，不同分辨率的图片转换后的token量差异较大；按单更新的数据要求上下文需实时关联最新工单与设备信息，旧数据的token需及时清理；跨系统关联的文档需限制单份数据源的token占比，避免整体上下文溢出。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 10000–14000 token | 依据为单份完整评审包（上架申请、端口标签表、布线图）的平均token消耗，避免上下文溢出 |
| `quoteMaxToken` | 2500–3500 token | 依据为单份机柜布线图或网络拓扑的token转换上限，防止单条引用占用过多上下文 |
| 分块长度 | 800–1200 字符 | 依据为端口标签表、施工记录的单条字段长度，平衡召回精度与token消耗 |
| 上下文刷新间隔 | 每单完成后刷新 | 依据为该品类数据按单更新的频率，确保评审时使用最新的机位与布线数据 |
| 召回匹配条数 | 前5–7条 | 依据为日常评审需核对的机位、端口、线缆三类核心数据，过多会增加token负担 |

## 容易做错的三处
- 上传高清机柜布线图时部分图片触发「token超限」报错，部分低分辨率图片可正常上传。原因是未设置图片转文本的token上限，高清图片的token消耗超过配置阈值，系统拦截了超出部分的内容。
- 配置`maxContext`为15000 token，但特定变更评审问题的响应token自动变为200，回复内容被截断。原因是上下文召回的核心文档总token超过了实际配置的上限，系统自动截断了非关键上下文，导致响应token被压缩。
- 关联DCIM云空间数据源时，无法加载对应token数据，评审流程报错。原因是未正确配置云空间的token关联逻辑，导致上下文无法读取对应数据源的token内容。

## 怎么确认配好了
- 上传一份完整的机柜上架申请与布线图，查看FastGPT上下文预览面板中显示的总token数，确认未超过配置的`maxContext`阈值。
- 发起一次变更评审请求，查看响应内容的token长度，确认未被意外截断至200 token以内。
- 测试上传不同分辨率的布线图，确认所有图片均可正常加载并转换为文本token，无报错。
- 检查数据源关联配置，确认DCIM、资产系统的更新频率与配置的上下文刷新间隔匹配。
