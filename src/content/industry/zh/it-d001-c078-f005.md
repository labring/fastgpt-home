# 机柜上架与布线的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据通常来自DCIM系统、企业资产系统、网络拓扑图与客户施工工单。日常处理的文档包括上架申请单、机柜布线图、端口标签表与施工记录。数据更新频率为每单或每日一次，字段包含机柜机位编号、线缆长度、端口标识、施工日期等，对应单位为U、米、端口序号、年月日。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据按单或每日更新，且包含结构化物理参数与图纸类非结构化内容，这要求多轮对话需绑定单次施工工单的上下文，避免跨单数据混淆。由于涉及机柜布线图、端口标签表等格式差异较大的文档，提示词需明确指定结构化提取规则，适配不同文档的字段格式。物理参数的单位（如U、米）具有行业特定含义，提示词需加入单位校验逻辑，防止参数混用。同时，上架验收环节的多轮确认需按施工流程分步引导，避免遗漏关键步骤。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前工单唯一标识 | 确保多轮对话的上下文与指定工单完全绑定，避免会话混淆 |
| 最大上下文长度 | 8000–12000 字符 | 适配机柜布线图、端口标签表等文档的文本长度，避免截断关键物理参数 |
| 单次`messages`条数 | 前 10 条 | 匹配单工单的施工流程步骤，避免冗余历史干扰当前评审判断 |
| `variables` | 绑定当前工单ID与关联资产数据 | 确保多轮对话仅使用该工单关联的DCIM、资产系统数据，防止跨单数据混淆 |
| 知识库召回上限 | 前 5 条 | 聚焦与当前机位、线缆相关的历史施工记录，减少无关信息干扰 |
| 文件上传大小限制 | 1000 MB | 适配机柜布线图、施工记录等文档的常见大小，避免上传失败 |

## 容易做错的三处
- 对话输出耗时较长。原因是未限制单次`messages`的保留条数，导致每次调用都加载过多历史上下文与无关文档数据。
- 调用API时无法正确传递端口标签表文件。原因是未在`variables`中配置文件上传的字段映射规则，导致系统无法识别传入的文档类型与关联参数。
- 使用提示词调用MCP时出现图片显示不全。原因是提示词未明确指定机柜布线图的分辨率与格式要求，导致MCP返回的图片被截断或压缩。

## 怎么确认配好了
- 发起一次模拟工单评审对话，检查对话上下文是否仅包含当前工单的关联数据，无跨单信息。
- 调用API传入测试端口标签表文件，确认系统能正确识别并提取机位编号、线缆长度等字段。
- 触发提示词调用MCP，检查返回的机柜布线图是否完整显示所有端口与机位标识。
- 查看系统并发配置参数，确认并发量设置匹配当前机房施工的日常请求峰值。
