# 机柜上架与布线的代码与变更评审辅助：引用来源与溯源

在FastGPT v4.17.0版本中，可通过`quoteMaxToken`控制引用内容的最大token长度，通过`responseData`配置返回数据的格式，通过`detail`控制是否召回详细的关联文档信息。

## 这个品类的数据长什么样
该品类的数据来源包括DCIM系统、资产管理系统、网络拓扑图与客户工单。日常产出的文档包含上架申请单、机柜布线图、端口标签表与施工记录。数据更新频率为每单或每日，单条数据对应单次上架或布线任务。字段包含机柜编号、物理端口号、逻辑端口映射关系、设备型号、操作时间与验收状态，部分文档需关联设备物理位置与网络配置信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据分散于多套系统与文档，引用溯源需同时匹配结构化的DCIM资产字段与非结构化的布线图、施工记录内容。数据更新频率较高，单次任务的变更需实时关联最新的工单与资产数据，避免引用过期信息。不同文档的字段结构差异明显，上架申请单含审批状态字段，端口标签表需映射物理与逻辑端口，溯源配置需适配这些差异。同时，物理接入错误的后果直接影响业务，溯源需精准绑定机位与端口信息，确保引用内容与实际施工环节完全对应。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次搜索上限 | 前 5 条 | 覆盖单台机柜的常用设备接入数量 |
| 引用最大token数 | 1000–1500 token | 容纳多份文档的引用内容，避免截断关键信息 |
| 响应数据格式 | 包含完整引用标识 | 确保输出中携带正确的来源与溯源信息 |
| 详情召回开关 | 开启 | 补充DCIM系统与端口标签表的关联数据 |
| 上下文长度 | 800 字符 | 适配上架申请单与施工记录的单块内容长度 |

## 容易做错的三处
- 对话输出中出现引用号乱码，最终显示为非标准引号的符号。原因是未正确配置响应数据格式的引用标识规则，导致输出内容的编码解析异常。
- 工具调用模块关联知识库后无法返回引用内容。原因是未开启详情召回开关，或单次搜索上限设置过低，无法召回上架申请单、机柜布线图等品类专属文档。
- 对话请求接口未返回cite引用id。原因是未配置响应数据格式为携带完整引用标识，或引用最大token数设置过小，截断了引用字段的返回内容。

## 怎么确认配好了
- 发起包含机柜编号、端口信息的测试查询，检查输出内容是否携带对应文档的引用标识。
- 调用对话请求接口，查看返回数据中是否包含cite引用id字段。
- 提交与机柜上架无关的测试问题，确认输出未返回品类专属文档的引用。
- 观察输出内容的引用符号是否为标准格式，无乱码现象。
