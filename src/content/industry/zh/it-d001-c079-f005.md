# 架构设计与技术方案的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来源为历史流量数据、服务拓扑、监控指标、业务增长计划，更新频率为月度或重大需求发布时。日常产出的文档包含技术方案文档、架构拓扑图、容量评估报告、技术评审纪要，字段覆盖跨服务边界定义、资源配额、演进路线节点、约束条件等，单位涉及CPU核数、存储容量、请求吞吐量等，无固定统一的单文档体量，需根据需求规模调整。本文适配FastGPT v4.17.0版本。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据更新频率较低，多轮对话需限定上下文范围，避免引入与当前评审无关的历史数据。文档结构多样的特征要求提示词明确区分不同类型文档的提取规则，适配文字、图表、表格的混合内容。字段涉及跨服务边界等核心架构信息，需按会话主题拆分对话，防止上下文混杂不同需求的评审内容。同时，架构方案出错会导致长期扩展受限，提示词需强化约束条件的校验逻辑，确保评审覆盖所有必要的技术边界与资源配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 按评审会话分组生成唯一值 | 区分不同技术方案的评审上下文，避免会话数据混杂 |
| `messages` | 保留当前评审会话的前20条交互记录 | 匹配架构方案评审短周期、主题集中的对话特征 |
| `variables` | 注入当前技术方案的关联文档元数据 | 为提示词提供固定的上下文锚点 |
| 最大上下文长度 | 8000–12000 token | 适配架构方案文档的内容体量，避免截断关键约束条件 |
| 提示词优化 | 按实测标定 | 适配架构评审的专业术语场景，减少无效输出 |
| 单次关联数据上限 | 前3条历史评审纪要 | 聚焦关联的评审意见，避免引入无关历史数据 |

## 容易做错的三处
- 现象：配置多对话工作流后，某节点输出内容仍展示在前端界面。原因：未正确设置`variables`中的隐藏输出标记参数，或工作流配置中未勾选对应节点的输出屏蔽选项。
- 现象：免登录场景下对话图标未按预期更改，刷新后仍显示默认图标。原因：未在自定义配置项中正确绑定免登录场景的图标资源路径，或路径格式不符合系统要求。
- 现象：调用千问模型时提示connection error，开启代理后仍无法恢复。原因：未在`variables`中配置代理的环境变量参数，或模型接口的超时阈值设置过低，例如小于30秒，导致网络请求未完成即被中断。

## 怎么确认配好了
- 发起一次技术方案评审的模拟对话，检查仅核心节点的输出内容展示在界面，非核心节点的输出被隐藏。
- 进入免登录配置页面，上传自定义图标并保存，刷新页面后确认图标已更新为预设样式。
- 调用千问模型发起测试请求，查看系统日志无connection error报错，且请求响应时长符合预期。
- 检查`chatId`参数是否随不同评审会话生成唯一标识，避免不同会话的上下文出现混杂情况。
