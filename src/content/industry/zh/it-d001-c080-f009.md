# 桌面终端支持的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
该品类的数据通常来自终端管理平台、企业资产系统、用户报障入口与内部软件仓库。日常产出的文档包含终端故障单、装机清单、软件安装记录、远程协助记录，单条数据包含终端序列号、故障类型、关联软件版本、报障时间、处理进度等字段。数据更新频率为每日批量同步或随单次处理请求实时更新，无固定批量统计周期，仅随终端运维动作触发更新。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且格式不统一，导致工具调用前需适配多源数据的解析格式，插件需支持从终端管理平台拉取资产信息、从软件仓库查询版本兼容性。单次请求的数据量较小但实时性要求高，工具调用的超时阈值需适配低延迟场景，避免因等待过久引发员工停工。终端运维的文档多为非结构化文本，插件需支持自然语言解析故障单内容，生成对应的排查指令。数据更新无固定周期，工具调用需支持动态拉取最新的软件仓库与资产信息，避免使用过期数据引发排查错误。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配桌面终端场景下的多工具动态调用需求，无需手动指定工具类型 |
| `functionCall` | `{"name":"fetch_terminal_asset","parameters":{"sn":"{{terminal_serial}}"}}` | 针对终端运维场景，指定拉取对应终端的资产信息 |
| 工具调用超时阈值 | `10–15 秒` | 适配桌面运维的低延迟需求，避免长时间等待导致员工停工 |
| 插件数据拉取范围 | `近 7 天` | 平衡数据时效性与调用效率，避免拉取过多过期的软件或资产数据 |
| 上下文窗口长度 | `8000–12000 token` | 适配终端故障单、装机清单等多文档的上下文承载需求 |
| 插件触发条件 | 按终端报障请求触发 | 适配桌面运维的实时处理需求，避免非必要的工具调用 |

## 容易做错的三处
- 现象：工具调用重复触发，同一终端的软件查询请求多次发起。原因：未正确配置`toolChoice`的自动终止逻辑，导致上下文残留的工具调用指令被重复解析。
- 现象：调用视觉类模型时返回400错误，提示图片格式不对，图片为PNG格式。原因：插件的图片预处理参数未适配模型要求的图像尺寸或编码格式，部分PNG图像的透明通道未被正确处理。
- 现象：使用中转服务调用模型时，工具调用失败。原因：未在模型配置中正确配置中转地址的回调端口，导致插件无法接收返回的工具调用结果。

## 怎么确认配好了
- 提交一条模拟的终端故障单，触发工具调用，查看系统日志中是否有对应插件的调用请求与返回结果。
- 检查插件的参数绑定配置，确认终端序列号变量已关联到故障单的对应字段，无空值或错误绑定。
- 模拟超时场景，验证工具调用是否在设定的阈值内返回结果，无异常阻塞或超时报错。
- 重复提交同一故障单，确认工具调用仅触发一次，无重复执行的日志记录。
