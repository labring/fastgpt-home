# 渗透测试服务的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
渗透测试服务的数据通常来自目标系统、公开漏洞库、自动化扫描器结果与手工验证记录。日常产出的文档包含测试授权书、渗透测试报告、漏洞复现记录与整改建议，字段覆盖授权范围、漏洞编号、复现步骤、风险等级等。数据更新节奏以单个项目或重大版本变更为周期，单项目内的文档会随测试推进逐步新增与完善。

## 这些特征在「上下文与 token」这一环带来什么约束
渗透测试服务的文档包含长文本的复现步骤、结构化的漏洞数据与敏感的授权信息，单项目内的内容总量较高。不同类型的文档需要严格的上下文隔离，避免授权信息混入非授权场景。长文本的漏洞复现步骤若被拆分，会导致逻辑断裂，需要适配的token分配与分块规则。按项目更新的数据要求上下文需随项目节点刷新，避免旧数据干扰当前评审。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配渗透测试报告、漏洞复现记录的长文本内容 |
| `quoteMaxToken` | 3000–5000 token | 确保漏洞验证步骤、扫描器结果片段完整纳入上下文 |
| 上下文刷新时机 | 按项目节点触发 | 匹配渗透测试服务按项目更新数据的节奏 |
| 分块重叠长度 | 200–300 字符 | 避免漏洞复现步骤拆分后逻辑断裂 |
| 单次召回上限 | 前6条 | 适配单项目内的文档数量，控制token占用 |

## 容易做错的三处
- 每次调用MCP工具后上下文丢失：现象为工具调用后历史项目相关内容无法检索，原因是未配置按项目绑定上下文的规则，导致工具调用重置了全局上下文。
- 输出内容被截断：现象为生成的评审结果未包含完整的漏洞复现步骤，原因是未根据文档长度调整`maxContext`参数，超出token上限后内容被截断。
- 上传文件路径解析失败：现象为通过HTTP请求读取上传的测试文档时返回404错误，原因是未正确处理FastGPT上传文件附带的token参数，导致路径解析异常。

## 怎么确认配好了
- 查看当前项目的上下文配置，确认`maxContext`参数取值匹配当前项目文档的总token预估量。
- 测试调用MCP工具后，检索历史项目相关内容，确认上下文未被重置。
- 上传单份长文档（如完整的漏洞复现记录），生成评审内容，确认未出现关键步骤被截断的情况。
- 测试通过HTTP请求读取上传的测试授权书，确认请求路径未携带额外的token参数导致解析失败。
