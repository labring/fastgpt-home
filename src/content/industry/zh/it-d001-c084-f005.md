# 游戏客户端性能优化的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据通常来自引擎Profiler、崩溃平台、真机测试工具与帧率采集系统。日常关联文档包括性能测试报告、机型适配清单、优化记录与崩溃分析报告，文档字段包含机型型号、帧率数值、资源占用占比、崩溃日志ID等，单位涵盖帧率（fps）、内存占用（MB）、包体大小（MB）等。数据更新频率为每日或每版本发布周期，核心环节涉及低端机复现、资源占用分析与优化效果回归验证。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散且格式各异，多轮对话需要整合不同工具的输出，因此需要明确上下文窗口的边界。数据更新频率较高，每版本发布周期内会产生大量新数据，对话历史需支持按版本维度截断，避免冗余信息干扰。核心环节涉及低端机复现，对话中需要调用特定机型的测试数据，提示词需明确指定数据范围。出错后果直接关联商店评价，对话输出需严格限定在性能优化相关内容，避免无关信息。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 前 20 条对话历史 | 匹配游戏客户端性能优化数据的日更新频率，避免过多历史占用资源 |
| 对话ID绑定 | `chatId` 按版本维度生成 | 区分不同版本的优化评审数据，确保上下文关联对应版本的测试报告 |
| 上下文截断 | 保留最近 7 天的对话与文档关联数据 | 适配每版本发布的更新周期，过滤过期的性能测试数据 |
| 变量绑定 | `variables` 绑定机型型号、帧率阈值 | 精准调用对应机型的性能数据，辅助评审变更的影响 |
| 单次回复token上限 | 8000 token | 覆盖性能测试报告、崩溃日志等长文本的完整分析需求 |
| 提示词模板 | 固定为「基于当前版本的性能数据评审代码变更」 | 聚焦游戏客户端性能优化的细分场景，避免无关输出 |

## 容易做错的三处
- 现象：对话结果仅在侧边栏弹窗展示，主对话框无内容。原因：未正确配置`messages`的上下文渲染规则，导致输出未绑定到当前对话会话。
- 现象：每次发起评审都需要新建对话，无法延续历史上下文。原因：未固定`chatId`的生成规则，每次请求生成新的对话ID，导致上下文无法复用。
- 现象：AI回复自动使用Markdown格式，无法切换为纯文本。原因：提示词模板未明确指定输出格式，默认启用了Markdown语法渲染。

## 怎么确认配好了
- 发起一次性能评审请求，检查主对话框是否直接展示分析结果，验证`messages`的渲染配置是否生效。
- 连续发起两次针对同一版本的评审请求，检查是否复用同一对话上下文，验证`chatId`的绑定规则是否正确。
- 修改提示词模板，要求输出纯文本，发起请求后检查回复是否未使用Markdown格式，验证格式配置是否生效。
- 查看变量绑定区域，确认已关联机型型号、帧率阈值等性能数据字段，验证`variables`的配置是否完整。
