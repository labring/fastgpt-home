# 游戏客户端性能优化的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
这个品类的核心数据来自引擎Profiler、崩溃平台、真机测试与帧率采集工具，更新节奏为每日或每版本发布一次。日常产出的文档包含性能测试报告、机型适配清单、优化记录与崩溃分析报告，数据字段包含帧率（fps）、包体大小（MB）、资源加载时长（毫秒）等专属性能指标，不同机型的测试结果会单独归档，整体数据结构偏向按测试批次与机型维度拆分。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据的实时性要求高，因此引用溯源需要同步最新的版本级测试数据，避免引用过时的优化记录。数据按机型与测试批次拆分，溯源时需要精准匹配代码变更对应的测试场景，不能泛泛关联无关数据。字段包含专属性能指标，引用时需要保留完整的参数信息，否则无法支撑性能优化的评审依据。同时，错误引用会直接影响评审结论，导致后续出现卡顿、闪退等问题，因此溯源的准确性要求较高。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | 适配游戏客户端性能文档的单条长度，避免截断帧率、机型等关键参数 |
| `responseData` | 仅返回关联知识库条目 | 确保溯源仅展示性能测试报告、优化记录等官方文档，排除无关内容 |
| `detail` | 开启 | 完整展示引用文档的专属字段，如测试机型、优化前后的帧率对比 |
| 引用匹配阈值 | 0.75–0.85 | 精准匹配代码变更与性能测试数据，避免误关联无关文档 |
| 知识库同步频率 | 每日 / 每版本更新 | 匹配业务数据的更新节奏，保证引用内容的时效性 |
| 召回条数上限 | 前 3 条 | 避免过多引用导致上下文溢出，聚焦核心性能优化相关数据 |

## 容易做错的三处
- 现象：非工具调用模式下，生成的回答未展示性能测试报告的引用来源。原因：未开启`responseData`配置项，导致系统未返回关联知识库的溯源信息。
- 现象：引用的文档仅显示标题，未包含帧率、机型等关键性能数据。原因：未开启`detail`配置项，或`quoteMaxToken`取值过低截断了文档内容。
- 现象：关联多个知识库后，系统提示上下文溢出或生成内容不完整。原因：未限制召回条数上限，且未调整`quoteMaxToken`适配单条文档长度，导致总token超出模型承载范围。

## 怎么确认配好了
- 发起包含“性能优化”“帧率”“机型适配”等关键词的代码评审对话，查看回答底部的引用列表是否包含预设的性能测试报告、优化记录等文档。
- 点击引用条目展开详情，确认展示的内容包含测试机型、帧率数据、包体大小等专属性能字段，验证`detail`配置生效。
- 调整`quoteMaxToken`的取值后，重新发起对话，验证单条引用文档的内容未被截断，确认token限制配置正确。
- 尝试关联超出常规数量的知识库，查看系统是否触发上下文溢出提示，确认召回条数上限配置生效。
