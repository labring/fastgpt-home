# 游戏服务器研发运维的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来源于游戏运行日志、在线人数监控系统、业务数据库与玩家工单。日常维护文档包含服务器架构说明、开服方案、合服方案与故障报告，字段涵盖在线峰值、数据同步延迟、合服校验通过率、玩家投诉关键词等。数据更新频率为日常运维按日更新，大型开服、合服活动前会提前完成全量校验更新。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据关联游戏核心业务逻辑，工具调用需精准匹配服务器运维场景的专属参数，避免泛用工具导致评审结果偏离业务需求。数据更新存在日常与活动两种节奏，插件需支持按日或活动周期动态拉取最新的服务器架构、开服合服文档与校验数据。文档结构包含多环节流程说明，工具调用需支持按文档类型筛选关联片段，同时因出错会引发登录失败、数据回档等严重后果，工具调用的参数校验与失败重试机制需适配高可靠性要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | 指定为`auto` | 适配FastGPT v4.17.0版本的工具调用逻辑，自动选择匹配服务器运维场景的工具 |
| 工具调用超时时间 | `300 秒` | 服务器运维数据拉取通常耗时较短，过长超时会阻塞评审流程 |
| 插件触发条件 | 按代码变更提交触发 | 评审工作围绕提交的变更内容展开，贴合研发运维日常流程 |
| `functionCall` | 开启强制参数校验 | 服务器运维数据字段格式严格，错误参数会导致评审结果失效 |
| 单次工具调用重试次数 | `2 次` | 避免频繁重试占用服务器资源，适配运维场景的低延迟要求 |
| 插件拉取数据范围 | 前 7 天的游戏日志与合服记录 | 日常运维评审仅需近7天的历史数据支撑，避免冗余数据占用资源 |

## 容易做错的三处
- 现象为导出工作流并导入其他环境后，插件调用报错提示未找到关联插件，原因是导出时仅保存了工作流流程配置，未携带插件与当前环境绑定的专属配置信息。
- 现象为工具调用后返回参数格式错误或缺失关键字段，原因是未开启`functionCall`的强制参数校验，导致不符合服务器运维数据格式的参数被传入。
- 现象为工具调用超时并返回状态码504，原因是配置的超时时间过短，无法完成游戏日志或合服校验数据的拉取与分析。

## 怎么确认配好了
- 提交一条模拟的服务器代码变更，触发工具调用，检查是否自动匹配到适配运维场景的工具，确认`toolChoice`配置生效。
- 查看工具调用的日志详情，确认拉取的数据范围符合预设的时间区间，验证插件数据拉取配置正确。
- 模拟传入不符合格式的参数，检查是否触发参数校验拦截，确认`functionCall`的强制校验配置生效。
- 等待工具调用完成，检查输出结果的格式是否符合预设要求，验证结果输出配置正确。
