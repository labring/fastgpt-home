# 游戏版号与出版申报的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自国家新闻出版署办事服务平台、著作权登记档案、游戏包体文件、运营机构提交的资质材料。日常处理的文档包含申报请示文件、游戏出版申请表、著作权权属证明、内容审读报告。数据更新节奏随单款游戏申报流程不定期推进，不同申报阶段会生成对应阶段的材料副本。材料包含权属编号、包体校验值、审读意见标识等结构化字段，以及配套的非结构化文档内容。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散，工具调用需支持对接多类外部数据源接口，避免手动跨平台复制材料。数据更新随单款申报流程不定期推进，工具触发需支持按需调用，不宜设置固定周期同步。日常处理的文档格式多样，插件需适配不同类型文档的解析规则。材料一致性核对需跨数据源比对字段，工具调用需传入明确的数据源标识与权限参数。审批流程对材料准确性要求高，工具调用失败后需触发重试与异常日志记录，避免影响申报进度。

以下配置适用于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` 或 `required` | 根据申报流程是否必须调用工具确定，自动模式适配灵活调用场景，强制模式确保关键步骤调用工具 |
| 知识库绑定范围 | 仅绑定对应申报批次的专属知识库 | 避免无关数据干扰材料一致性核对，符合单款申报的专属数据要求 |
| 数据源权限配置 | 按申报主体配置只读权限，有效期绑定当前申报周期 | 符合著作权与申报材料的保密要求，避免越权访问 |
| 重试次数 | 2–3 次 | 平衡工具调用成功率与流程耗时，避免过度重试占用资源 |
| 超时阈值 | 300–600 秒 | 适配跨多数据源调取材料的平均响应时长，避免因网络波动中断流程 |
| `functionCall` | 开启参数校验模式 | 确保传入工具的参数符合申报材料的格式要求，减少格式错误导致的审批不通过 |

## 容易做错的三处
- 现象：调用工具时提示知识库未找到或无法引用，传入全局变量配置后仍报错。原因：未将当前申报批次的知识库ID显式传入工具调用参数，仅配置全局变量未绑定到具体工具实例。
- 现象：配置MySQL数据库链接后，执行SQL提取结果为空或返回错误。原因：未为数据库链接配置对应申报数据源的只读权限，或SQL语句未匹配申报材料的字段格式。
- 现象：连续发送多个申报相关请求时，工具调用响应延迟或被阻塞。原因：未设置工具调用的并发限制，导致多请求同时占用数据源接口配额。

## 怎么确认配好了
- 触发一次工具调用，检查返回结果中是否包含对应申报批次的专属知识库数据。
- 模拟工具调用失败场景，确认系统会触发预设次数的重试并生成异常日志。
- 查看工具配置界面，确认知识库绑定范围与数据源权限已按设定完成。
- 测试连续发送两个申报相关请求，确认工具调用不会出现阻塞或超时。
