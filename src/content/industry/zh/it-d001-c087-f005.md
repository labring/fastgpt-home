# 游戏策划与数值设计的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
该品类的日常工作文档包含玩法策划案、数值表、版本需求单与平衡性测试记录。数据来源涵盖玩家行为数据、竞品公开资料、战斗日志与版本反馈。更新节奏通常为每周或每版本一次。文档字段多为量化指标，包含规则参数、数值阈值、资源消耗比例等，单位涉及伤害值、留存率、道具产出量等具体量化维度。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据分散且来源多样，多轮对话需逐步对齐玩家行为数据、战斗日志等不同来源的数值信息，避免规则拆解偏差。固定的周/版本更新节奏要求对话上下文需适配版本迭代的节点，关联历史版本的数值记录。文档字段多为量化指标，提示词需明确单位与阈值边界，确保评审时的数值模拟符合业务规则。变更评审需回溯历史版本的数值表与需求单，多轮对话需保留上下文以对比变更前后的规则差异。

## 配置怎么定
本文档基于FastGPT v4.17.0版本配置说明编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 1500–2000 token | 适配玩法策划案、数值表的长文档内容，避免上下文溢出干扰当前评审 |
| `messages` 上下文截断阈值 | 按实测标定 | 过滤冗余历史对话，聚焦当前版本的变更评审需求 |
| 对话记录保存时长 | 30天 | 匹配周/每版本的更新节奏，便于回溯历史版本的评审记录 |
| `variables` 预设变量配置 | 绑定伤害值、留存率等常用单位 | 减少量化字段的重复提示词输入 |
| `chatId` 会话分组规则 | 按版本号分类 | 统一归档同一版本的变更评审对话，便于后续版本复盘 |
| 知识库权限控制 | 按团队角色分组 | 确保数值表等敏感数据仅授权策划与评审人员访问 |

## 容易做错的三处
- 对话记录超出配置时长后仍可被检索到，原因是未正确配置对话保存时长的对应参数，或配置未在系统中生效。
- 知识库中敏感数值表被非授权角色访问，原因是未按团队角色配置知识库权限，直接开放了全量知识库访问权限。
- 多轮对话中数值模拟结果偏差较大，原因是提示词未明确指定文档字段的单位与规则边界，导致上下文召回的内容混淆了不同版本的数值参数。

## 怎么确认配好了
- 手动创建一条测试对话，设置保存时长为30天，等待超过该时长后确认是否仍可在会话列表中检索到该记录。
- 切换至非授权角色账号，尝试访问配置了角色权限的数值表知识库，确认无法正常检索对应内容。
- 输入包含多段历史对话的测试场景，查看系统是否按配置的`messages`阈值截断冗余上下文，仅保留与当前评审相关的内容。
- 新建会话并按版本号命名会话标识，确认会话列表中会按版本自动分组展示所有关联对话。
