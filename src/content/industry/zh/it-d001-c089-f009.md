# 漏洞扫描服务的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
漏洞扫描服务的数据来源于漏洞扫描器、资产清单、CVE库与补丁公告。日常维护的文档包含扫描计划、漏洞清单、整改工单与复扫报告，字段涵盖漏洞编号、CVSS评分、关联资产、整改状态等。数据更新频率为周度或月度，随扫描任务执行、CVE库同步及补丁公告更新同步刷新。

## 这些特征在「工具调用与插件」这一环带来什么约束
漏洞扫描服务的数据来源分散且更新节奏固定，工具调用需适配多源数据的同步逻辑，需定时拉取CVE库、扫描结果与补丁公告，避免使用过期漏洞信息。日常文档结构固定，插件需匹配扫描计划、漏洞清单等文档的字段格式，准确提取漏洞编号、关联资产等核心信息。更新频率为周或月度，工具触发时机需对应扫描任务执行周期，避免过度调用消耗资源。同时，工具需支持自动拉取资产清单、过滤误报结果，适配最耗时的资产确认与误报排除环节。

## 配置怎么定
本文档的配置说明适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 支持自动识别代码评审中的漏洞场景，适配不同检测需求 |
| `functionCall` | 允许任意工具调用 | 满足自由识别工具处理问题的需求，适配跨文档的漏洞数据整合 |
| 工具调用触发时机 | 扫描计划执行完成后10分钟 | 匹配漏洞扫描服务的周/月更新频率，确保调用数据为最新结果 |
| 单次调用数据量 | 前20条漏洞清单条目 | 避免单次调用超出上下文限制，适配代码评审的批量处理场景 |
| 结果过滤阈值 | CVSS评分≥7.0 | 聚焦高危漏洞，减少低风险数据对评审的干扰 |
| 调用超时设置 | 300秒 | 适配多源数据拉取的耗时，避免任务无响应 |

## 容易做错的三处
- 现象：工具调用返回的内容包含非目标的低风险漏洞数据，无法限制输出范围。原因：未配置结果过滤阈值，未聚焦高危漏洞字段，导致无关数据被纳入上下文。
- 现象：工具调用获取的漏洞数据未正确传递至下游AI模型，下游模型无法吸收相关知识。原因：未配置工具调用的结果输出格式，未指定将数据传递至指定模型的逻辑，导致数据流转中断。
- 现象：定时触发的工具调用频繁超时，或触发时机与扫描计划不匹配。原因：未设置合理的调用超时时长，未对齐扫描计划的周/月执行周期，导致调用时机错误或任务失败。

## 怎么确认配好了
- 执行一次手动触发的工具调用，检查返回的漏洞数据是否包含配置的过滤阈值内的条目，确认字段提取正确。
- 查看工具调用的日志，确认触发时机与扫描计划的执行周期对齐，无异常超时记录。
- 配置下游模型接收工具调用结果的逻辑，测试数据是否能正常流转至目标模型，无字段缺失或格式错误。
- 调整`toolChoice`参数为`auto`，验证是否能自动识别代码评审中的漏洞场景并调用对应工具。
