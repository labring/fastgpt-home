# 玩家客服与舆情处理的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据主要来自客服系统、社区论坛、应用商店评论与游戏日志，日常处理的文档包含玩家工单、补偿申请、舆情日报与标准化处理话术。数据更新节奏多为实时或每日，核心字段包含玩家账号标识、反馈内容、处理进度与规则依据，无统一固定单位，需按单次反馈或批量日报维度整合。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且更新节奏差异大，需在溯源时匹配不同系统的时间戳与唯一标识，避免跨源数据混淆。玩家工单与舆情内容的字段差异明显，需针对不同文档类型配置对应召回规则，确保引用内容与原反馈场景匹配。实时更新的游戏日志数据需优先召回，避免引用过期规则，补偿规则判断涉及代码变更的溯源，需匹配代码提交的时间戳与变更记录，同时需控制溯源范围，防止引入非客服场景的冗余数据导致回答偏离业务目标。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | 1000–1500 token | 匹配玩家工单与舆情内容的平均长度，避免截断关键引用内容 |
| `responseData` | 仅返回答复字段 | 确保输出知识库中问答对的原文答复，符合业务标准化要求 |
| 最大引用条数 | 前3条 | 控制单轮回答的信息密度，避免玩家阅读负担 |
| `detail` | 开启 | 展示引用来源的文档ID与更新时间，便于快速核验 |
| 分块长度 | 800–1200 字符 | 适配客服文档的段落长度，提升召回精准度 |
| 超时阈值 | 300 秒 | 避免因数据加载过慢导致的引用失败 |

## 容易做错的三处
- 现象：未开启引用配置项仍返回引用内容。原因：FastGPT v4.17.0 版本中，部分全局配置与知识库单独配置存在优先级冲突，未正确覆盖默认设置。
- 现象：知识库变量引用格式无效，无法正常调用指定数据集。原因：未使用平台指定的变量格式，错误拼接了非标准的对象结构。
- 现象：引用源数据后无法输出完整内容。原因：`quoteMaxToken` 配置值过小，导致引用内容被截断后无法正常拼接，或未正确开启 `responseData` 配置项。

## 怎么确认配好了
- 提交测试问题，检查返回内容是否仅包含知识库中问答对的原文答复，无AI生成的额外内容。
- 查看回答底部的引用标识，确认是否展示了源数据的文档标识与更新时间。
- 调整`quoteMaxToken`的取值，验证引用内容的截断逻辑是否符合预期。
- 测试不同类型的玩家反馈问题，确认仅召回客服专属知识库中的内容，无冗余数据混入。
