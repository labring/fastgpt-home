# 现场部署实施的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自客户机房环境、设备清单、软件包、网络拓扑等现场一手资源，更新节奏为每单或每阶段一次。日常产出的文档包含部署手册、安装记录、配置清单、现场签到表，核心字段涵盖设备型号、软件版本、配置参数、现场签到信息，无统一标准化格式，需随现场实施进度同步更新。

## 这些特征在「工具调用与插件」这一环带来什么约束
现场部署实施的数据来源分散且随单变化，要求工具调用需适配不同客户的设备与软件版本，因此插件需支持动态读取现场配置清单中的参数。数据更新频率为每单或每阶段一次，工具调用流程需支持实时拉取最新的安装记录与配置信息，避免使用过期的现场数据。日常产出的文档多为非结构化文本，插件需具备解析部署手册、提取配置参数的能力，同时需适配现场签到表的格式差异。此外，现场环境的网络限制可能影响工具调用的稳定性，需预留容错空间以应对突发的网络波动。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | auto | 适配不同现场环境的工具调用需求，无需手动指定具体工具，覆盖多样化的部署场景 |
| `functionCall` | enabled | 支持插件调用代码运行节点，满足变更评审中的代码校验与配置校验需求 |
| 插件超时时间 | 300–600 秒 | 现场部署的环境检查、软件安装等环节耗时较长，需适配长周期工具调用的场景 |
| 插件参数读取范围 | 前 3 条安装记录 | 现场安装记录仅需最新的3条即可覆盖当前部署的核心配置信息，避免冗余数据干扰 |
| 文档解析阈值 | 800–1200 字符 | 部署手册的核心配置段落通常为该长度，可精准提取有效配置参数，过滤无关内容 |

## 容易做错的三处
- 现象：添加Doc2X类系统插件后界面报错。原因：未在FastGPT v4.17.0版本的插件管理中配置正确的API密钥与调用地址，导致插件无法正常拉取文档解析服务。
- 现象：在工作流中引用插件后接代码运行节点，点击输入框报错。原因：未正确设置`functionCall`参数为enabled，导致工作流无法触发插件后的代码执行逻辑。
- 现象：工具调用返回结果为空或条数不符。原因：未根据现场部署的配置清单调整插件参数读取范围，导致未提取到有效配置数据。

## 怎么确认配好了
- 进入插件管理页面，检查已配置的工具插件状态为正常运行。
- 新建测试工作流，添加插件节点与代码运行节点，触发测试调用，查看返回结果是否包含有效配置信息。
- 查看工作流日志，确认`toolChoice`参数触发的工具调用符合预期，无超时或报错信息。
- 导入一份模拟的部署手册，验证插件是否能正确提取其中的核心配置参数。
