# 用户增长与留存运营的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
用户增长与留存运营的业务数据主要来源于用户行为日志、推送系统、实验平台与CRM系统。日常产出的文档包括增长实验方案、用户分层表、触达文案与留存分析报告，文档结构以结构化字段为主，包含用户标识、行为时间、触达状态、实验分组等字段，更新频率分为日度与周度两类，核心指标随业务节奏实时或定期更新。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散且涉及多系统交互，要求工具调用需支持跨平台数据拉取与整合；文档以结构化业务规则为主，工具调用需精准匹配文档中的特定字段，避免无效参数传入；更新频率的差异要求工具调用周期与数据更新节奏对齐，防止调用过时数据；核心耗时环节集中在用户分群、触达节奏设计与实验归因，工具调用需辅助压缩该环节的评审周期，同时需严格控制失败场景的影响，避免因工具异常导致用户反感或留存下降。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配增长运营需要调用多类工具的场景，自动选择适配用户分群、触达分析的插件 |
| `functionCall` | `enabled` | 支持将增长实验的参数作为函数入参，自动生成触达文案的结构化调用 |
| 插件调用超时阈值 | `600 秒` | 增长运营的数据拉取涉及多系统交互，600秒可覆盖跨平台数据同步的常规耗时，避免因超时中断导致评审失败 |
| 插件返回结果条数上限 | `前 10 条` | 用户分层表、留存报告的数据量通常集中在核心指标前10项，过多结果会增加评审耗时 |
| 变更评审触发规则 | 按触达文案、用户分群规则的代码变更触发 | 增长运营的核心变更集中在触达逻辑与用户分层规则，精准触发可减少无效评审 |

## 容易做错的三处
- 插件调用无响应且积分扣除：提交代码变更后未触发工具调用，但平台积分记录显示消耗，原因是未配置`toolChoice`为有效模式，导致调用逻辑未启动，但积分校验环节未做前置校验。
- 自定义插件无法被触发：自行开发的插件未在平台完成准入配置，代码中的调用指令无法被平台解析，导致插件始终不执行，原因是未遵循平台的插件接入规范。
- 变更评审遗漏核心字段校验：工具调用时未映射用户分层表的关键标签字段，导致评审结果无法覆盖核心业务规则，原因是未配置插件调用的字段映射参数。

## 怎么确认配好了
- 提交包含用户分层表字段的代码变更，查看FastGPT v4.17.0的工具调用日志是否触发对应插件。
- 模拟触达文案的代码提交，检查插件返回的结果是否包含用户分群的核心指标字段。
- 断开实验平台的网络连接，查看是否触发预设的失败处理逻辑，避免无效积分扣除。
- 查看平台的积分消耗记录，确认仅在有效工具调用完成后才会产生积分消耗。
