# 用户增长与留存运营的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据主要来自用户行为日志、推送系统、实验平台与CRM系统，更新频率多为日度或周度。日常产出的文档包含增长实验方案、用户分层表、触达文案、留存分析报告，数据字段通常包含用户标识、触达渠道、实验分组、留存时长、转化指标等，无统一强制格式，需根据具体业务场景调整字段与结构。该品类主要运营站内用户生命周期，不同于在线广告投放优化类场景，数据均聚焦站内用户行为与业务运营结果。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据特征对引用来源与溯源环节带来多重约束。分散且格式不统一的多系统数据源，要求溯源环节支持跨源字段映射，避免不同系统的用户标识、指标数据混淆。日度或周度的更新频率，要求环节支持定时拉取或增量同步，确保引用内容为最新业务数据。多样的文档类型与非强制格式，需允许自定义引用模板适配增长实验方案、用户分层表等不同文档结构。此外，该品类最耗时的用户分群、实验结果归因等环节，要求引用溯源环节能快速定位关联数据，减少人工核对时间。同时，溯源失误会直接影响业务效果，要求环节能精准绑定引用内容与原始数据来源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.75–0.85 | 适配用户分层表、触达文案的语义匹配精度，平衡召回与精准度 |
| 单次搜索上限 | 前8条 | 匹配日度更新的业务数据规模，避免检索资源过载 |
| 重排 | 开启 | 提升高相关内容的召回优先级，适配分散多源的业务数据 |
| `quoteMaxToken` | 1200–1800 token | 控制单条引用的内容长度，避免上下文溢出影响生成效果 |
| `detail` | 开启 | 保留原始引用的完整字段信息，便于溯源时核对业务数据来源 |
| `responseData` | 开启 | 保留原始检索的完整数据结构，支持跨源溯源的字段映射 |

## 容易做错的三处
- 开启重排功能后出现引用为空或无搜索片段的情况。原因：未同步调整相似度阈值，高相关内容被误过滤出检索范围。
- 无法访问自定义引用模板或高级配置界面。原因：使用的FastGPT版本低于v4.17.0，需升级至对应版本后使用。
- 引用溯源时出现字段不匹配的报错。原因：未开启`detail`参数，未保留原始引用的完整字段信息，无法完成跨源数据核对。

## 怎么确认配好了
- 提交测试检索请求，核对返回结果的引用来源是否匹配业务文档的字段与更新时间。
- 查看配置界面的重排、相似度阈值等参数，确认与业务数据规模匹配的取值已设置。
- 生成引用溯源报告，核对每条引用内容是否绑定了原始数据的来源路径与更新时间。
- 测试长文本文档的引用，确认`quoteMaxToken`参数的取值未超出上下文限制。
