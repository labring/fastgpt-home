# 监控告警配置的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本品类数据来自Prometheus、Zabbix、云监控、应用日志、CMDB系统，更新频率为每日或每次告警规则变更后。日常产出的文档包含监控指标清单、告警规则文件、值班手册、告警变更记录，单条告警规则数据包含阈值参数、触发条件、关联指标、通知链路配置等字段，无统一固定长度，随监控规模增长而增加。

## 这些特征在「上下文与 token」这一环带来什么约束
在FastGPT v4.17.0版本中，数据来源分散导致单次调用需要整合多系统指标信息，更新频率不稳定可能导致上下文数据滞后。告警规则文档结构差异大，无法通过固定分块适配所有场景，容易出现关键配置被拆分丢失的问题。单条数据长度随监控规模增长，若未限制上下文token总量，会超出大模型输入上限，导致响应为空或截断。同时，告警变更记录的时序性要求上下文需保留最近的变更操作，避免评审时引用过时配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配主流大模型输入上限，覆盖告警配置类文档的平均总长度 |
| `quoteMaxToken` | 1500–2000 token | 限制单条引用内容的token占用，避免拆分时丢失关键配置 |
| 上下文刷新时机 | 按变更触发 + 每日全量同步 | 匹配告警配置的日/变更级更新频率，保证上下文时效性 |
| 单次召回引用数 | 前3–5条 | 聚焦核心告警规则与最近变更记录，减少噪声信息 |
| 上下文内容优先级 | 保留最近变更记录与核心阈值配置 | 优先保留告警评审时最关键的配置信息，避免冗余内容占用token |

## 容易做错的三处
- 出现`LLM model response empty`报错，原因是未限制`maxContext`参数，导致上下文总token超出大模型输入上限，模型无法生成有效响应。
- 单次召回内容超过预设token上限，导致回答截断或返回字段为空，原因是未配置`quoteMaxToken`参数，单条引用内容拆分后仍超出token限制。
- 上下文无法保留连续对话的历史配置信息，原因是未开启上下文同步机制，每次调用仅加载当前知识库内容，未关联历史交互的告警配置上下文。

## 怎么确认配好了
- 提交一次告警规则变更的评审请求，检查返回内容是否包含最近3条变更记录与核心指标配置，无冗余无关信息。
- 查看平台运行日志，确认无`LLM model response empty`报错，且响应内容未出现截断。
- 手动修改告警配置后，发起新的评审请求，检查返回内容是否包含最新的变更信息。
- 调整`maxContext`参数后，测试不同规模的监控配置文档，确认模型可正常生成响应且无关键配置丢失。
