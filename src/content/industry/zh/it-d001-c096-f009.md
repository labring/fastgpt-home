# 社区举报处理的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自社区举报系统、待审核内容详情页、举报用户历史行为记录与官方审核规则库。日常产出的文档包含举报工单、举报处理记录、用户申诉单与标准化用户通知模板。数据更新节奏为实时或按日更新，核心字段包含举报唯一标识、关联内容ID、举报类型、处理状态、处置结果与关联用户信息，无额外统计类量化字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类按单处理用户提交的具体举报内容，数据来源分散且更新节奏灵活，要求工具调用需适配多数据源的权限与拉取逻辑。固定的文档结构要求工具入参需严格匹配举报工单、处理记录的字段格式，避免参数错位导致数据拉取失败。实时或按日更新的数据要求工具调用的超时阈值需适配数据拉取的实际耗时，同时单次调用仅处理单个举报工单，防止跨工单数据混淆。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写，以下为工具调用与插件的配置参考：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `"auto"` 或指定为 `["preLogin", "getReportTicket"]` | 自动选择调用预登录接口与举报工单拉取工具，适配社区举报处理的前置校验与数据拉取需求 |
| `functionCall` | 允许函数调用 | 需调用preLogin接口完成前置校验，再调用举报详情拉取工具获取处理所需数据 |
| 工具调用超时时间 | `600 秒` | 社区举报数据可能包含多源拉取，需预留足够的接口响应时间，避免因超时中断处理流程 |
| 单次工具调用上限 | `1 次` | 该品类按单处理举报工单，单次调用仅需拉取对应单条举报的相关数据，防止多工单数据混淆 |
| 函数调用参数校验 | 开启强制校验 | 需确保传入的举报ID、用户标识等参数格式正确，避免因参数错误导致工具调用失败 |

## 容易做错的三处
- 调用工具返回400 status code (no body)，现象为接口响应无内容且状态码为400，原因通常为未先调用preLogin接口完成前置校验，或传入的举报ID参数格式错误。
- 工具调用未触发preLogin接口，现象为无法拉取举报工单的详情数据，原因是未配置`toolChoice`为自动调用前置校验接口，或未将preLogin加入允许调用的函数列表。
- 函数调用效果差，现象为模型生成的工具调用参数与实际需求不匹配，原因是未针对举报工单的字段结构优化函数调用的提示词，或未限定`functionCall`的调用范围仅为社区举报相关工具。

## 怎么确认配好了
- 模拟提交一条测试举报工单，调用工具链，检查是否自动触发preLogin接口并返回有效校验结果。
- 查看工具调用日志，确认每次调用仅拉取单条举报的相关数据，无跨工单数据混入。
- 验证参数校验功能，传入格式错误的举报ID，检查是否触发参数错误提示并拦截工具调用。
- 调整`toolChoice`配置为手动指定，确认工具仅调用预设的举报处理相关函数，无无关调用。
