# 移动端开发的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
该品类的数据来源主要为代码仓库、应用商店后台、崩溃监控平台与机型覆盖数据。日常产出的文档包含端版本发布单、机型适配清单、崩溃分析报告、应用商店审核资料等。数据更新频率为每日或每版本发布周期，文档字段多包含机型版本号、权限配置项、崩溃日志堆栈、应用商店提交状态等具体内容，无统一固定格式要求。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源分散且类型多样，要求工作流编排支持对接多类外部数据源。日常文档结构差异显著，需通过`variables`配置适配不同字段的映射规则。数据更新节奏不固定，工作流需支持定时触发与代码提交事件触发两种模式。同时，需在工作流中嵌入机型适配校验、应用商店资料合规检查等环节，避免后续流程出现不符合要求的输出。本配置说明适用于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 触发节点类型 | 代码提交事件 + 定时触发 | 适配代码仓库更新与版本发布的双场景需求 |
| `variables` 配置 | 包含机型版本号、权限列表、崩溃日志路径3个变量 | 匹配日常文档的核心字段需求 |
| 数据源拉取超时时间 | 600秒 | 适配代码仓库与应用商店后台的接口响应延迟 |
| 节点执行顺序 | 按机型适配→权限校验→审核资料生成的顺序 | 符合移动端开发的常规评审流程 |
| 错误重试次数 | 3次 | 应对临时接口波动导致的执行失败 |
| 输出文档字符长度 | 800-1200字符 | 适配应用商店审核资料的格式要求 |

## 容易做错的三处
- 创建工作流模板后进入编辑界面报错，原因是未正确配置`variables`的初始值，导致系统无法识别后续引用的变量字段。
- 在其他工作流引用已创建的插件后，连接代码运行节点时输入框报错，原因是插件输出的字段未与当前工作流的`variables`做映射绑定。
- 本地部署后打开工作流页面出现Cannot read properties of undefined (reading 'incl')报错，原因是工作流配置中遗漏了`nodeId`的必填项，导致系统无法定位对应执行节点。

## 怎么确认配好了
- 触发对应事件（如提交代码到指定开发分支），检查工作流是否自动启动执行。
- 查看工作流执行日志，确认`variables`中的机型版本号、权限列表等字段均能正确拉取对应数据源的内容。
- 模拟权限适配、机型校验环节，检查输出的评审文档是否符合日常使用的端版本发布单格式要求。
- 测试错误触发场景（如断开应用商店后台的数据源连接），确认工作流会按配置的重试规则执行重试。
