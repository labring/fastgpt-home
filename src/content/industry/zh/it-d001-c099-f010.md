# 移动端开发的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
移动端开发的业务数据主要来自代码仓库、应用商店后台、崩溃监控平台、机型覆盖数据。日常生成的文档包括端版本发布单、机型适配清单、崩溃分析报告、应用商店审核资料。数据更新频率为每日或随版本发布周期，文档结构多包含版本号、适配机型范围、权限配置项、审核状态等字段。

## 这些特征在「引用来源与溯源」这一环带来什么约束
移动端开发的数据来源分散且覆盖多类业务系统，需要精准关联对应数据源的知识库才能召回有效内容。文档结构带有明确的层级与字段标识，引用时需匹配对应字段避免召回无关信息。高更新频率要求知识库同步机制适配版本发布节奏，确保评审时使用最新的适配与审核资料。同时，移动端开发的评审结果直接关联应用商店审核与用户升级体验，溯源信息的准确性直接影响评审有效性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的设置逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配移动端单篇文档的典型分块长度，避免截断关键的机型适配信息 |
| `responseData` | 开启 | 确保代码评审时可追溯变更对应的具体文档来源，便于排查适配问题 |
| `detail` | 2级 | 对应移动端文档的章节结构，展示到机型适配清单或权限配置的具体条目 |
| 单次召回条数 | 前6条 | 覆盖常见的多机型适配场景，避免遗漏关键配置内容 |
| 知识库动态传值 | 绑定对应数据源变量 | 关联代码仓库、应用商店后台等独立数据源，实现精准召回 |
| 引用内容展示开关 | 按需配置 | 适配不同场景的展示需求，例如iframe嵌入时可按需关闭 |

## 容易做错的三处
- 仅配置文本数据集却未关联代码仓库数据源，导致非文本类的机型适配清单未被引用。原因是未将不同业务数据源绑定到对应知识库，仅启用了单一的文本知识库。
- iframe嵌入场景下未调整引用展示设置，导致页面出现冗余的引用内容模块。原因是未关闭对应引用展示的配置项，未匹配嵌入场景的展示需求。
- 动态传值未匹配对应知识库变量，导致AI无法召回指定的版本发布单内容。原因是未将传入的版本号参数与对应知识库的检索条件绑定，无法精准定位目标文档。

## 怎么确认配好了
- 查看知识库关联列表，确认代码仓库、应用商店后台等业务数据源已绑定到对应知识库。
- 发起一次代码变更评审测试，检查返回结果中是否包含对应文档的来源标识，例如文档名称、更新时间。
- 测试动态传值功能，输入指定的版本号参数，确认召回的内容匹配对应版本的发布单或适配清单。
- 检查iframe嵌入场景下的页面展示，确认引用内容的展示状态符合预设需求。
