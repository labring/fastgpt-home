# 等级保护测评咨询的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本品类数据主要来自测评工具导出的系统清单、安全设备日志、项目访谈记录，更新频率为每项目或每年一次。核心文档包含定级报告、差距分析报告、整改方案与测评报告，字段涵盖等保控制项编号、对应整改措施、证据文件路径、测评结果等，单项目文档总量随被测评系统的规模波动，无统一固定的单文档大小上限。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类的数据特征对上下文与token环节带来多重约束。首先，单项目文档总量随系统规模波动，且包含结构化控制项、非结构化日志与整改证据，最耗时的定级材料梳理与控制项核对环节需要召回大量关联文档，需精准控制上下文召回的token总量，避免超出模型承载上限。其次，数据更新周期为每项目或每年一次，上下文配置需适配单次项目全量文档的召回需求，无需频繁调整。另外，合规性要求上下文必须覆盖完整的控制项关联证据，不能截断关键判定内容，对token的精准分配提出更高要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单项目全量文档的召回需求，覆盖等保测评所需的控制项与证据内容 |
| `quoteMaxToken` | 1500–2000 token | 匹配知识库切块与单次引用的合规性要求，避免截断关键整改证据 |
| 上下文召回条数 | 前3–5条 | 平衡文档覆盖度与token占用，避免超出模型上下文上限 |
| 上下文重置规则 | 切换项目时自动执行 | 适配本品类按项目开展的业务模式，防止跨项目数据污染 |
| token统计节点 | 项目完成后统计 | 匹配数据按项目更新的节奏，无需实时统计token消耗 |

## 容易做错的三处
- 现象：配置了较大的响应token上限，但部分问题回复的token仅为200。原因：上下文token占用超出`maxContext`配置，模型自动截断上下文导致响应长度受限。
- 现象：知识库切块设置为5000 token，但引用时仅召回1500 token的内容。原因：误将`quoteMaxToken`设置为1500，覆盖了知识库切块的召回上限。
- 现象：云空间部署时无法配置AIPROXY_API_ENDPOINT与AIPROXY_API_TOKEN这两个服务端环境变量，导致上下文功能无法启动。原因：未遵循服务端环境变量配置要求，未正确设置必填的AIPROXY_API_ENDPOINT与AIPROXY_API_TOKEN，导致启动校验失败。

## 怎么确认配好了
- 检查FastGPT v4.17.0及以上版本服务端的环境变量配置，确认已正确设置AIPROXY_API_ENDPOINT（AI Proxy服务的根地址，不得附加/v1或/chat/completions，非VLLM/Ollama/Xinference等单模型地址）与AIPROXY_API_TOKEN（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空，非应用API Key、模型供应商密钥、按应用签发的token或按请求估算的token数），无空值或错误地址。
- 发起一次针对测评报告的测试调用，查看返回的上下文token数是否符合`maxContext`的配置范围。
- 查看模型调用日志，确认`quoteMaxToken`的取值被正确应用到引用内容的截断逻辑中。
- 切换不同测评项目的文档，确认上下文内容会自动重置，无跨项目数据残留。
