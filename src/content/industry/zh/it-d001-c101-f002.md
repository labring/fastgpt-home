# 续费健康度管理的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
通常，续费健康度管理的相关数据来自CRM系统、产品使用数据、工单统计台账与合同管理系统，更新频率以周或月为周期。日常产出的文档包含客户健康度报告、续费预测表、风险客户清单与跨部门沟通纪要，数据包含客户标识、合同周期、使用频次、工单数量、沟通记录片段等字段，格式不统一，既有结构化的表格数据，也有非结构化的文本内容。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据结构混合了结构化与非结构化内容，会导致上下文的token消耗出现较大波动，需平衡召回范围与token上限。周/月级的更新频率意味着单次任务需要覆盖数周或数月的历史数据，若未限制上下文规模，容易触发超长任务超时。核心文档如沟通纪要与风险清单内容密度较高，若分块不当会产生大量无效片段，进一步推高token消耗。同时，该品类的任务结果直接关联客户留存，若上下文截断关键风险线索，会导致分析偏差，引发客户流失风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 12000–15000 token | 适配通用大模型的输出上限，避免任务执行中出现回复截断 |
| `quoteMaxToken` | 8000–10000 token | 覆盖完整的客户沟通纪要与合同片段，确保续费风险相关的关键线索不被遗漏 |
| 相似度阈值 | 0.5–0.7 | 适配该品类数据的字段密度特征，平衡召回内容的精准度与覆盖范围 |
| 单次召回上限 | 前5条 | 控制上下文的总token规模，防止超长任务执行超时 |
| 分块长度 | 1200–1500 字符 | 适配续费预测表与健康度报告的段落结构，减少分块后的碎片化内容 |

## 容易做错的三处
- 配置`maxContext`超过16384 token时，大模型在输出至12288 token时触发截断，显示超出回复限制。原因是未结合大模型自身的输出上限调整配置，未匹配该品类数据的实际token消耗需求。
- 设置相似度阈值为0.4时，召回大量无关的非续费相关工单与沟通记录，无法引用到需要的客户风险内容。原因是阈值过低，未适配该品类数据的结构化特征，导致召回噪声过多。
- 未设置单次召回上限，将全量周期内的客户健康度报告纳入上下文，导致任务执行超时。原因是未结合该品类数据的更新频率与文档规模，未控制上下文的总token消耗。

## 怎么确认配好了
- 导入单份典型的客户健康度报告，运行代码评审辅助任务，查看上下文召回的片段是否包含合同到期日、工单数量等核心续费相关字段。
- 测试超长任务的执行时长，确认未出现超时报错，且输出内容未被提前截断。
- 调整相似度阈值至0.5，检查召回的文档片段是否与续费风险直接相关，无过多无关内容。
- 查看FastGPT v4.17.0的任务日志，确认`quoteMaxToken`的配置未导致单条引用片段超出预设范围。
