# 续费健康度管理的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
续费健康度管理的业务数据通常来自CRM系统、产品使用数据后台、客服工单统计、合同台账四类来源，更新频率为周度或月度。日常处理的文档包含客户健康度报告、续费预测表、风险客户清单、客户沟通纪要，文档结构包含客户标识、合同周期、使用指标、风险标记、续费意向等字段，无统一固定的单一体量格式，部分文档可能包含嵌套的子项数据。本内容适配FastGPT v4.17.0及以上版本。

## 这些特征在「工作流编排」这一环带来什么约束
多来源的数据需要配置多个独立的数据源节点分别拉取，避免数据混淆或拉取失败。周/月级别的更新节奏要求工作流触发周期与数据更新周期匹配，不宜设置过于频繁的执行间隔。多样的文档结构需要配置灵活的字段映射规则，适配不同文档的字段差异。大体积的合同台账或风险客户清单需要配置循环处理逻辑，避免单次执行超出系统负载阈值。跨系统的数据拉取还需要考虑网络延迟带来的超时风险，需合理设置节点执行的超时参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发周期 | 每周一次或每月一次 | 匹配续费健康度管理的周/月更新节奏 |
| 数据源节点配置 | 分别对接CRM、产品使用数据、工单统计的服务地址 | 适配多来源数据拉取需求 |
| 字段映射规则 | 按业务文档字段匹配数据源返回字段 | 确保提取数据与业务文档结构一致 |
| 节点执行超时 | 600秒 | 应对跨系统数据拉取的延迟情况 |
| 循环体参数 | 按单批次数据量设定单次循环处理条目 | 处理大体积的合同台账或风险客户清单数据 |

## 容易做错的三处
- 现象：工作流执行时出现数据库连接超时错误，界面显示ETIMEDOUT。原因：未正确配置跨系统数据源的网络访问规则，或超时阈值设置过低。
- 现象：工作流启动校验失败，提示缺少必填环境变量。排查项：检查App/Admin服务端是否已配置AIPROXY_API_ENDPOINT（AI Proxy服务的根地址）和AIPROXY_API_TOKEN（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空）且变量值非空。
- 现象：循环体执行异常，无法处理多层嵌套的业务数据结构。原因：未正确配置循环体的嵌套层级规则，或未匹配业务文档的嵌套字段结构。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量配置，确认AIPROXY_API_ENDPOINT（AI Proxy服务的根地址）和AIPROXY_API_TOKEN（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空）已正确添加且非空。
- 手动触发工作流一次，查看执行日志，确认所有数据源节点均成功拉取到对应数据。
- 查看工作流的字段映射结果，确认提取的数据字段与业务文档的字段完全匹配。
- 测试循环体处理大体积数据，确认执行过程中未出现超时或异常中断。
