# 续费健康度管理的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
续费健康度管理类别的数据主要来源于CRM系统、产品使用数据、工单统计台账与合同台账，更新频率多为周度或月度。日常产出的文档包含客户健康度报告、续费预测表、风险客户清单与客户沟通纪要，各文档的字段包含客户唯一标识、合同到期节点、产品使用频次、工单响应时效等，跨文档无统一字段标准，需通过客户标识完成关联溯源。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据特征对引用来源与溯源环节带来多重约束。首先，数据来源分散且跨系统，要求溯源环节需支持多数据源的关联匹配，避免单一来源无法覆盖风险判断依据。其次，更新频率为周度或月度，要求引用的数据源需限定在当前合同周期内的最新版本，避免使用超期历史数据导致判断失真。再者，日常文档类型多样且字段不统一，要求溯源环节需按文档类型配置分类搜索规则，确保不同文档的来源标识可被准确识别。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前 5 条 | 匹配风险客户清单的常规条目数量，避免检索过载 |
| `quoteMaxToken` | 1200–1800 token | 适配续费预测表的单页内容长度，确保完整引用核心数据 |
| `responseData` | 开启返回 | 用于关联工单统计的溯源标识，补充来源细节信息 |
| 最大上下文 | 6000 字符 | 容纳多份客户健康度报告的整合内容，满足跨文档引用 |
| `detail` | 开启详细溯源 | 展示数据来源的具体文档路径，符合溯源核查要求 |
| 字段映射规则 | 按实测标定 | 适配CRM与产品使用数据的字段差异，确保关联准确 |

## 容易做错的三处
- 现象为调大`quoteMaxToken`的取值后，生成结果未携带任何引用来源标识。原因是未同步开启`detail`参数，系统仅完成数据召回但未绑定来源溯源信息。
- 现象为通过外部API调用返回的结果中，引用字段为空且无来源说明。原因是未开启`responseData`参数返回溯源数据，接口未暴露来源关联信息。
- 现象为多文档关联搜索后，溯源结果出现跨周期的历史数据。原因是未按文档更新频率配置搜索时间范围，导致超期数据被误召回。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库关联配置页，查看`quoteMaxToken`、`responseData`与`detail`参数的取值是否与预设配置一致。
- 发起针对风险客户清单的测试提问，查看返回结果的引用模块是否包含对应文档的来源标识。
- 通过外部API调用测试接口，验证返回数据中是否包含`responseData`字段的溯源内容。
- 调整单次搜索上限后，检查召回结果的数量是否与预设的前5条取值匹配。
