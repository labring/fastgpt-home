# 落地页转化优化的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
落地页转化优化的核心数据来自落地页访问日志、热力图、表单数据、广告来源参数。日常关联文档包括落地页方案、埋点需求、AB测试报告、表单字段清单。数据更新频率为周度或按单次活动周期调整，字段包含页面路径、停留时长、表单提交状态、广告渠道ID等，单位多为秒、条、字符。

## 这些特征在「上下文与 token」这一环带来什么约束
落地页转化优化的数据来源分散且关联逻辑复杂，需整合广告来源参数与页面行为数据，因此上下文需要跨多类型文档绑定关联信息。数据更新频率随活动调整，上下文需支持动态刷新以匹配最新的埋点或测试报告。单份活动文档的长度差异较大，从简短的表单字段清单到完整的AB测试分析均有覆盖，token使用量波动明显，需严格控制上下文总长度与单条引用的token占比，避免超出模型限制。该品类的最耗时环节包括页面路径分析、表单阻塞排查、实验结果判断，出错后果直接影响广告投放效果，上下文缺失或token超限会导致分析偏差，引发线索流失与成本上升。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口（`maxContext`） | 8000–12000 token | 匹配落地页相关文档的总长度，覆盖单活动的全部关联数据，同时不超出多数开源模型的上下文限制 |
| 引用最大token（`quoteMaxToken`） | 1500–2000 字符 | 对应单条埋点数据、表单字段清单的典型长度，确保关键业务信息完整提取，避免截断核心内容 |
| 单次召回条数 | 前6条 | 匹配周度活动的文档数量，避免上下文过载导致模型推理延迟 |
| 上下文更新周期 | 按活动周期 | 匹配落地页活动的更新节奏，确保每次活动启动时加载最新的方案与测试报告 |
| 单文档分块长度 | 800 字符 | 适配落地页方案的段落结构，保留内容间的逻辑关联，避免分块破坏业务上下文 |

## 容易做错的三处
- 现象：搜索结果无法关联当前落地页的上下文，返回的分析与活动无关。原因：未将落地页访问日志、广告来源参数绑定到搜索请求的上下文，仅使用独立的查询关键词。
- 现象：代码评审时提示token超限，变更评审流程中断。原因：未限制`maxContext`的取值，将全量历史活动文档加载到当前上下文，超出模型支持的token上限。
- 现象：私有化部署的应用无法通过指定路径访问，页面返回404错误。原因：未在FastGPT配置中正确设置应用访问上下文路径，导致路由匹配失败。

## 怎么确认配好了
- 登录FastGPT v4.17.0的后台，进入应用配置的上下文设置面板，确认`maxContext`和`quoteMaxToken`的取值与预设配置一致。
- 导入一份完整的落地页活动文档，触发检索功能，检查返回的上下文是否包含广告来源参数、表单字段清单等关联信息。
- 触发一次代码评审流程，查看上下文加载的文档数量与token占用情况，确认符合预设的配置范围。
- 访问私有化部署的应用，验证通过/fastgpt路径可以正常加载应用界面，路由配置生效。
