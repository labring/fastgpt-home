# 落地页转化优化的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来源为落地页访问日志、热力图数据、表单提交数据、广告来源参数。数据更新频率为周度或单次活动周期内。日常关联文档包括落地页方案、埋点需求清单、AB测试报告、表单字段配置表。数据字段包含页面路径、停留时长、表单提交率、来源渠道标识，对应单位为秒、百分比、条、渠道编码。日常分析需整合多源数据，且需严格匹配文档中的字段格式，避免跨活动的数据混淆。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据与文档的强绑定特性，要求多轮对话必须严格限定上下文范围，仅保留当前活动周期内的对话内容，避免引入过往活动的冗余数据。数据更新频率为周度或单次活动周期，意味着对话上下文不宜保留超过12轮的历史内容，否则会因数据过期导致分析偏差。日常文档的结构化特征，要求提示词必须明确对齐预设的字段格式，引导模型输出符合表单或埋点要求的内容。多源数据整合的需求，要求多轮对话需逐步拆解分析任务，分步骤引导用户提供对应来源的数据，避免一次性要求过多信息导致输出混乱。同时，需确保每个活动的对话会话独立，避免不同活动的会话数据互相干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定落地页活动的唯一标识 | 实现每个活动独立对话，避免会话数据混淆 |
| `messages` | 保留最近8-12轮对话内容 | 适配周度更新的分析节奏，控制上下文开销 |
| `variables` | 预传入当前活动的表单字段、埋点参数清单 | 对齐日常文档的结构，减少输出格式偏差 |
| 会话超时时间 | 600秒 | 适配周度分析的任务周期，避免中途中断 |
| 提示词模板 | 限定输出格式为文档预设字段 | 约束模型输出符合业务要求的内容 |

## 容易做错的三处
- 会话数据跨活动共享：现象为不同落地页活动的对话内容互相干扰，原因是未正确绑定`chatId`到活动唯一标识。
- 对话无流式输出：现象为模型响应无分段加载效果，内容一次性返回，原因是未配置正确的上下文刷新规则，或未启用流式传输参数。
- 提示词导致格式错误：现象为模型输出的表单字段多空格、字母大写，或对链接内容进行不必要的修改，原因是未在提示词中明确对齐预设的文档字段格式，未传入`variables`约束输出规则。

## 怎么确认配好了
- 发起对应落地页活动的对话，检查`chatId`是否与活动标识一致，可通过FastGPT v4.17.0的会话日志查看绑定关系。
- 输入多轮分析问题，观察上下文是否仅保留最近8-12轮的历史内容，无冗余过往活动的数据干扰。
- 传入预设的表单字段清单，验证模型输出是否严格匹配字段格式，无额外空格或大小写修改。
- 发起测试请求，确认模型响应启用流式输出，内容分段加载展示。
