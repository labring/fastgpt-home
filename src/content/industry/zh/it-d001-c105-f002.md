# 许可证合规与版权声明的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的数据围绕开源项目的版权与许可合规需求生成，数据来源包括代码仓库根目录的LICENSE文件、第三方依赖清单、官方发布的许可证标准文本，以及项目的贡献者记录。日常产出的文档包含项目根目录的LICENSE文件、标注版权归属的NOTICE文件、随依赖更新的许可证清单，以及对应版本的版权声明文档。数据更新随项目版本迭代或第三方依赖变更触发，无固定周期，仅在版本发布或依赖调整时更新。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据来源分散，需整合代码仓库、依赖清单、贡献记录等多源信息，导致上下文的token消耗存在较大波动。数据更新无固定周期，每次变更评审需拉取最新的LICENSE文件、NOTICE文档与依赖许可证清单，上下文长度需适配不同项目的依赖数量与文档规模。日常文档的结构差异明显，LICENSE文件可能包含数千字符的法律条款，依赖清单可能包含数十条第三方包的许可证信息，需精准截取有效内容以避免无效token占用。此外，合规评审需关联贡献记录的版权归属，需将分散的贡献者信息纳入上下文，进一步增加token管理的复杂度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 适配多数开源项目的合规文档总长度，符合FastGPT v4.17.0的默认参数调整范围 |
| `maxContext` | 8000–12000 token | 对应中文界面的最大上下文设置，覆盖整合LICENSE文件、依赖清单后的总token消耗 |
| 引用最大token | 1500–2000 token | 针对单份许可证文本的有效截取，保留核心合规条款与版权声明内容 |
| `quoteMaxToken` | 1500–2000 token | 限定单条引用的token消耗，防止长许可证文本占用过多上下文空间 |
| 分块重叠长度 | 100–200 字符 | 适配许可证文本的长段落结构，避免跨块截断合规条款 |
| 单次召回上限 | 前10条 | 限制召回的依赖许可证数量，控制总token消耗在合理区间 |

## 容易做错的三处
- 界面提示“上下文长度超出模型限制”，原因是未根据开源项目的合规文档总长度调整`maxContext`参数，导致整合的LICENSE文件、依赖许可证清单总token数超过配置上限。
- 合规评审结果遗漏部分第三方依赖的许可证信息，原因是单次召回上限设置过低，未召回全部依赖对应的许可证文本，导致上下文缺少必要合规数据。
- 系统提示“AIPROXY_API_ENDPOINT or AIPROXY_API_TOKEN is not set”，排查项：检查FastGPT的App/Admin服务端是否已配置AIPROXY_API_ENDPOINT（AI Proxy服务根地址，格式如http://aiproxy:3000）和非空的AIPROXY_API_TOKEN（AI Proxy管理员Token）环境变量。

## 怎么确认配好了
- 上传一份包含3个以上第三方依赖的项目依赖清单，检查系统召回的许可证文本数量与实际依赖数量一致。
- 导入一份完整的MIT许可证文本，查看系统截取的有效条款长度符合`quoteMaxToken`的配置范围。
- 运行一次变更评审任务，查看日志中显示的上下文总token数未超出`maxContext`的配置值。
- 检查FastGPT的App/Admin服务端环境变量配置，确认AIPROXY_API_ENDPOINT和AIPROXY_API_TOKEN已正确设置且非空。
