# 许可证合规与版权声明的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源于代码仓库、依赖清单、许可证文本与贡献记录，更新频率为每版本发布或每次依赖变更时触发。日常产出的合规文档包含LICENSE文件、NOTICE文件、依赖许可证清单与版权声明，数据字段涵盖许可证类型、版权归属主体、依赖项名称与版本标识，无专属自定义单位，所有数据均随代码与依赖的迭代同步更新。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据分散且更新频繁，多轮对话需依次拉取代码仓库、依赖清单等不同数据源的内容，需保留完整上下文以衔接各环节的核对逻辑。固定格式的合规文档要求提示词精准匹配LICENSE、NOTICE等文件的结构，避免生成不符合规范的内容。高准确性要求下，多轮对话需分步确认版权归属、许可证兼容性等关键信息，无法通过单次对话完成全量校验，同时需避免使用过期的依赖与许可证数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–10000 token | 本品类需保留多轮对话的核对结果与数据源信息，足够的上下文可衔接各校验环节 |
| 超时时间 | 600 秒 | 拉取依赖清单、许可证文本等数据可能涉及多个仓库节点，充足的超时可避免校验中断 |
| 单次召回结果数 | 前 5 条 | 本品类的关键合规信息集中，少量精准结果可提升校验效率 |
| 变量传递 | 传入依赖清单路径、LICENSE文件地址 | 本品类的数据来源于代码仓库与依赖清单，通过变量可调用最新的实时数据 |
| 提示词模板 | 分版权确认、许可证兼容性、NOTICE更新三阶段编写 | 本品类的合规流程固定，分阶段提示词可精准匹配各环节的校验需求 |

## 容易做错的三处
- 对话返回结果未按指定格式封装，原因是未在提示词中明确输出格式要求，导致合规内容的结构化提取失败。
- 升级FastGPT v4.17.0后，上传附件文件时提示`fail to create post presigned url`，原因是S3存储配置的预签名URL过期参数设置不合理，无法完成附件加载。
- 对话窗口出现连接超时报错，原因是超时时间设置低于600秒，无法完成多仓库的合规数据拉取与校验流程。

## 怎么确认配好了
- 发起包含依赖清单查询的测试对话，核对返回结果是否匹配预设的数据源内容。
- 触发多轮校验流程，确认对话历史被完整保留，可回溯各环节的核对记录。
- 上传测试用的LICENSE与NOTICE文件，确认文件可正常加载并被提示词识别。
- 发起批量依赖校验请求，确认无连接超时报错，调整超时时间至符合业务需求的区间。
