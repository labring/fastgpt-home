# 许可证合规与版权声明的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
本品类的数据围绕开源项目的权利声明与合规文档生成，数据来源包括代码仓库根目录文件、第三方依赖清单、官方许可证文本、代码贡献记录。日常产出的标准文档包含LICENSE文件、NOTICE文件、依赖许可证清单、版权声明四类，每一次版本发布或依赖包变更时数据都会更新。文档字段包含许可证类型全称、版权持有者信息、依赖包名称与版本号、贡献者署名列表，无额外自定义统计字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据来源分散，涉及代码仓库、依赖清单、许可证文本等多个渠道，工具调用与插件需要同时对接多类数据源拉取信息。数据更新频率随版本或依赖变更动态调整，插件需绑定代码提交、依赖包更新事件触发执行。标准文档结构固定，插件需严格匹配预设字段生成合规文件，避免格式偏差。同时合规校验出错会导致商业使用受阻，插件需增加前置校验环节，对异常数据及时告警。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配FastGPT v4.17.0的插件调用逻辑，自动匹配合规校验工具 |
| `functionCall` | 启用 | 触发许可证合规与版权声明的自动校验流程 |
| 数据拉取超时阈值 | 30 秒 | 防止因外部数据源加载缓慢导致任务超时中断 |
| 单次依赖拉取上限 | 前 15 个依赖 | 平衡校验效率与覆盖范围，避免单次调用占用过多系统资源 |
| 触发事件绑定 | 代码提交、依赖变更 | 匹配数据更新节奏，仅在数据发生变更时执行校验 |

## 容易做错的三处
- 现象：插件执行返回状态码400，返回字段`error`显示「参数格式无效」，原因是未按照FastGPT v4.17.0的要求格式化`toolChoice`参数值，导致插件无法正确触发合规校验。
- 现象：插件未读取到LICENSE文件，生成的合规文档缺失许可证声明，原因是未将插件配置指向代码仓库根目录的标准文件路径，仅读取了自定义子目录的文件。
- 现象：依赖变更后未触发合规校验，生成的许可证清单未包含新增依赖的合规信息，原因是未绑定依赖变更事件作为插件触发条件，仅配置了定时拉取任务。

## 怎么确认配好了
- 提交一次包含新增依赖的代码变更，查看FastGPT工作流的插件执行日志，确认`functionCall`被正常触发。
- 进入插件配置页面，核对`toolChoice`参数值为`auto`，确保调用逻辑正确。
- 手动拉取项目的LICENSE文件与NOTICE文件，对比插件生成的输出内容，确认字段匹配一致。
- 模拟一次依赖包变更操作，检查生成的依赖许可证清单是否包含新增依赖的合规信息。
