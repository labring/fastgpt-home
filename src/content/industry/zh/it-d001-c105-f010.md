# 许可证合规与版权声明的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据核心来自开源代码仓库、依赖包清单、官方许可证文本与项目贡献记录。日常产出的文档包含LICENSE文件、NOTICE文件、依赖许可证清单与版权声明文件，其中LICENSE文件包含许可证条款与版权声明段，依赖许可证清单包含依赖包名、许可证类型与版本号，贡献记录包含提交者、提交时间与变更内容。数据更新随项目版本发布或依赖包变更触发，无固定周期但与代码变更强绑定。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源与代码变更、依赖包更新强绑定，溯源环节需要精准匹配每次变更对应的具体文档条目，避免泛化引用知识库内容。由于文档多为合规性文本，需准确定位到文件路径、行号或依赖包版本，避免引入无关内容。由于更新频率随代码变更触发，溯源需支持实时关联最新的LICENSE、NOTICE文件版本，确保引用的合规信息与当前项目状态一致。同时，合规类内容出错会导致商业使用受阻，因此溯源的准确性要求远高于普通问答场景，需过滤冗余的非合规相关文档。

## 配置怎么定
在FastGPT v4.17.0版本中，以下配置项均可在知识库编辑页面的检索与引用模块中完成设置：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 引用最大token | 1000–1500 token | 适配LICENSE、NOTICE等合规文档的常规长度，避免截断关键合规条款 |
| 返回完整元数据 | 开启 | 确保返回知识库id、文件路径、提交哈希等溯源所需的核心信息 |
| 详细溯源开关 | 开启 | 启用包含依赖包版本、许可证文本片段的精准溯源字段 |
| 单次召回上限 | 前3条 | 匹配每个变更对应的核心合规文档，避免引入冗余的非相关内容 |
| 最大上下文长度 | 按实测标定 | 适配批量变更评审的场景，平衡上下文加载量与响应速度 |

## 容易做错的三处
- 对话接口返回结果未携带知识库id或文件路径。原因：未开启返回完整元数据的配置，仅返回了摘要性的合规说明，未挂载溯源所需的元数据。
- 引用的合规文档与当前变更不匹配。原因：单次召回上限设置过高，引入了非当前版本的依赖包合规信息，导致引用偏差。
- 批量变更评审时出现响应超时。原因：最大上下文长度设置过大，加载了过多历史合规文档，超出系统处理阈值。

## 怎么确认配好了
- 发起包含依赖包更新或LICENSE文件修改的测试提问，检查返回结果中是否包含知识库id、文件路径等元数据字段。
- 查看返回的详细响应内容，确认是否包含依赖包版本、许可证文本片段等精准溯源信息。
- 调整引用最大token的取值，验证不同长度的合规文档是否能完整返回且不被截断。
- 发起包含3个以上变更的批量测试请求，确认系统响应正常且返回的引用文档与测试变更匹配。
