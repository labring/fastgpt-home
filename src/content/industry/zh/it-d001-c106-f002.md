# 语音标注与转写的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
这个品类的数据主要来自音频文件、标注平台、专有词表、抽检样本。日常产出的文档包含转写规范、音频清单、质检报告、说话人标注表。数据按日或每批任务更新，核心字段包含音频片段内容、说话人标识、标注结果、质检评分等。处理过程中最耗时的环节为噪声片段判断、说话人区分、专有词校对，一旦出现标注错误，可能引发识别训练偏差、转写返工或交付延期。

## 这些特征在「上下文与 token」这一环带来什么约束
语音标注与转写的任务数据多为按批次产生的结构化文本，且需参考历史标注样本、转写规范等多类文档，因此上下文范围需要覆盖单批次任务的全部关联内容。数据更新频率较高，上下文配置需适配批量任务的快速迭代，避免因上下文范围不足导致评审遗漏专有词校对、说话人区分等关键环节。同时，标注错误可能引发连锁问题，上下文与token配置需平衡参考内容的完整性与响应效率，防止因token占用过高导致任务超时或结果截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 语音标注任务包含转写文本、说话人标注表、质检报告等多类关联数据，需覆盖单批次任务的完整参考范围 |
| `quoteMaxToken` | `2000–3000 token` | 需容纳转写规范、专有词表等核心参考文档内容，确保评审时可调用完整规则 |
| 最大响应tokens | `1500–2500 token` | 需输出覆盖噪声片段判断、说话人区分、专有词校对等完整评审意见 |
| 上下文召回条数 | 前3–5条 | 语音标注数据按批次更新，召回少量高匹配的历史标注样本即可满足评审参考需求 |
| 上下文更新触发规则 | 按任务批次触发 | 适配语音标注数据按日或每批更新的节奏，避免调用过期的标注数据 |

## 容易做错的三处
- 现象：调用应用API时返回的评审结果缺少历史标注上下文。原因：未正确配置`maxContext`参数，未将历史标注数据纳入上下文范围。
- 现象：知识库中引用的转写规范内容被截断。原因：`quoteMaxToken`参数设置过小，未覆盖完整的参考文档内容。
- 现象：生成的评审意见未包含专有词校对相关建议。原因：最大响应tokens设置过低，无法容纳完整的评审要点。

## 怎么确认配好了
- 查看FastGPT v4.17.0的配置页面，确认`maxContext`、`quoteMaxToken`的取值与当前标注任务的批次规模匹配。
- 发起一次测试评审请求，检查返回结果是否包含历史标注样本、转写规范等预期的参考内容。
- 核对生成的评审意见长度，确认是否覆盖了噪声判断、说话人区分等全部核心评审环节。
- 查看应用API的返回日志，确认上下文字段包含当前批次的标注数据内容。
