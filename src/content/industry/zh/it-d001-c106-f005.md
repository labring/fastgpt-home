# 语音标注与转写的代码与变更评审辅助：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来源于原始音频文件、标注平台导出的中间结果、行业专有词表以及抽检样本。日常产出的文档包含转写规范、音频批次清单、质检报告与说话人标注表。数据更新节奏以单日或单批次为单位，随新音频导入、标注进度或质检结果迭代。数据字段包含音频时长、说话人标识、转写文本片段、置信度标签等，无统一固定单位，随标注任务类型调整。核心耗时环节涉及噪声片段判断、说话人区分与专有词校对，产生的数据会随校验环节不断修正。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散且更新频繁，要求多轮对话能够逐步整合不同来源的标注规范、音频清单与质检结果。日常文档格式不统一，需要通过`variables`传递不同批次的专属配置，避免提示词冗余。单次任务涉及的音频与标注数据量较大，多轮对话需限制上下文长度，防止超出处理上限。同时，噪声判断、说话人区分等耗时环节，需要通过多轮拆解提示词，逐步引导模型聚焦核心校验点，避免遗漏专有词校对要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 按任务批次拆分上下文，保留最近10–15轮有效交互 | 语音标注单批次文本量较大，过多上下文会干扰当前评审任务的聚焦性 |
| `variables` | 绑定当前批次的转写规范、专有词表链接 | 需动态传递批次专属校验规则，避免提示词硬编码导致的适配性问题 |
| 最大上下文长度 | 8000–12000 字符 | 覆盖单批次完整的音频清单与质检要求，适配语音标注数据的常规体量 |
| 对话轮次上限 | 前6轮核心交互，后续仅传递关键校验结果 | 过多轮次会导致模型混淆任务目标，聚焦核心评审环节即可提升效率 |
| `chatId` | 绑定当前标注批次的唯一标识 | 确保多轮对话的上下文一致性，关联批次数据避免混淆不同任务 |

## 容易做错的三处
- 现象：上传的音频清单附件无法被识别，界面无报错提示。原因：未通过`variables`绑定附件的有效链接，导致对话节点无法读取文件内容。
- 现象：本地开发环境可正常总结上传的转写文档，镜像部署后无法识别。原因：镜像部署时未配置附件存储路径的环境变量，导致对话节点无法访问本地上传的文件资源。
- 现象：判断器节点后的AI对话无法获取初始用户问题。原因：未通过`messages`传递初始用户输入的完整上下文，导致后续对话丢失原始任务指令。

## 怎么确认配好了
- 上传单批次的音频清单与转写规范附件，检查对话节点能否正确读取附件内的专有词表内容。
- 模拟多轮评审交互，验证`variables`绑定的批次配置是否随对话轮次同步更新。
- 触发判断器节点后，查看AI对话的上下文日志，确认初始用户问题已被完整传递。
- 测试FastGPT v4.17.0版本的兼容性，确认配置项在当前版本下可正常生效。
