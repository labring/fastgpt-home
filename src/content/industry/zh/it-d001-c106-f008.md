# 语音标注与转写的代码与变更评审辅助：工作流编排
本页面配置基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据主要来源于待处理音频文件、标注平台产出的中间结果、行业专有词表以及抽检质检样本。日常关联文档包括转写规范、音频批次清单、质检报告与说话人标注表。数据更新节奏按日或单批次音频任务推进，核心数据为结构化转写文本，需先完成音频到文本的转换，再开展说话人区分、专有词校对等环节，整体流程依赖多类型文档与数据源的协同。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据特征对工作流编排带来多重约束。音频类数据源需工作流支持格式校验与音频转写前置节点，避免无效音频输入进入后续流程。按日或单批次的更新节奏，要求工作流支持按任务批次触发，适配单次或批量任务需求。多类型关联文档需工作流配置多变量引用与校验逻辑，确保转写规范、词表等资源同步更新。核心耗时环节需拆分子任务节点，实现噪声片段判断、说话人区分等步骤的编排，保障整体流程效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 关联音频清单、转写规范、词表三类变量 | 适配多类型数据源的批量调用需求，匹配按日/批次的更新节奏 |
| 节点触发条件 | 音频格式校验通过后触发转写节点 | 避免无效音频输入进入后续流程，减少冗余计算 |
| 批次任务阈值 | 单次处理100–200条音频 | 平衡服务器负载与任务处理效率，按实测标定 |
| `nodeId` | 为噪声片段判断、说话人区分节点分配独立标识 | 便于在变更评审中定位异常节点，快速排查转写错误 |
| 变量引用范围 | 支持多变量组合引用 | 适配转写规范、词表等多文档的校验需求，解决单变量引用限制问题 |
| 单节点超时设置 | 600秒 | 适配长音频转写与复杂校验的耗时需求，按实测标定 |

## 容易做错的三处
- 现象：调用API时全局变量参数赋值错误，导致转写节点无法读取音频清单。原因：未按批次任务的变量规则配置参数映射，混淆了单任务与批量任务的变量格式。
- 现象：工作流运行后返回的知识库引用结果不符合转写规范，且无法定位异常引用来源。原因：未为知识库校验节点分配独立`nodeId`，变更评审时无法快速追溯引用逻辑。
- 现象：仅能在下拉菜单中选择单个变量，无法同时引用转写规范与词表。原因：未开启多变量组合引用的配置项，未适配多文档校验的业务需求。

## 怎么确认配好了
- 调用测试API，传入单条音频与关联变量，检查转写节点是否正常触发并返回结构化文本。
- 查看工作流节点列表，确认噪声片段判断、说话人区分等核心节点均配置了独立`nodeId`。
- 打开变量引用配置界面，验证是否支持同时选择转写规范、词表等多个变量。
- 提交批量测试任务，根据实际运行情况调整批次任务阈值与单节点超时设置。
