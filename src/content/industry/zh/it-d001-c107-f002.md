# 账号封禁与申诉复核的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
该品类的核心数据来源于风控系统、审核记录、用户行为日志与举报证据，日常处理的文档包括封禁记录、申诉材料、复核意见及用户通知。数据更新节奏分为日更与实时更新两类，单份文档通常包含账号标识、违规行为描述、关联证据链接、申诉内容、历史处置记录等字段，无统一固定格式，需根据平台业务规则灵活调整字段与内容结构。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据特征对上下文与token处理带来多重约束。多源实时数据的同步拉取，会增加单轮上下文的总token消耗，易触发模型上下文长度限制报错。日常文档结构不统一，无法通过标准化分块适配所有类型的业务文档，提升上下文拼接的复杂度。长文本类的申诉材料、举报证据常突破单段token上限，需额外处理内容截断或拆分逻辑。账号级关联数据的调取需求，要求同时整合历史违规记录、近期行为日志等多维度信息，进一步推高上下文总长度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的功能逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token（按实测标定） | 适配主流大模型的基础上下文上限，覆盖账号关联的多维度业务数据总长度 |
| 文档分块长度 | 1000–1500 字符 | 匹配单份申诉材料、封禁记录的常见分段规模，避免单块内容超出模型单段处理限制 |
| 分块重叠长度 | 200–300 字符 | 保留分块间的上下文关联，防止违规证据、申诉理由等关键信息在分块边界丢失 |
| `maxContext` | 按业务场景动态调整 | 限定单轮请求的总上下文token消耗，规避模型返回400错误 |
| `quoteMaxToken` | 6000–10000 token | 限定引用的历史违规记录、用户行为日志等数据总长度，优先加载核心复核信息 |
| 预处理触发阈值 | 单文件超过15000 字符 | 自动触发内容截取或压缩逻辑，处理超出上下文上限的长文本申诉材料 |

## 容易做错的三处
- 上传长文本申诉材料时返回400错误。原因是未配置内容预处理逻辑，直接上传的文件内容超出模型上下文长度限制。
- 账号复核结果出现关键证据遗漏。原因是分块长度设置过大或重叠长度不足，导致分块边界截断了违规记录、申诉理由等核心字段。
- 单轮请求超时或返回空结果。原因是未限制`maxContext`参数取值，总上下文token消耗超出服务器或模型接口的承载上限。

## 怎么确认配好了
- 上传单份最长的申诉材料或封禁记录，检查是否触发400错误，根据报错情况调整分块长度与`maxContext`参数。
- 调取包含多维度关联数据的账号复核场景，核对返回的上下文内容是否包含历史违规记录、用户行为日志等核心信息。
- 模拟实时数据拉取场景，检查单轮请求的总token消耗是否符合预设的上下文限制，避免超出模型或接口的承载能力。
- 验证分块重叠长度的设置效果，确认关键信息不会在分块拼接时丢失。
