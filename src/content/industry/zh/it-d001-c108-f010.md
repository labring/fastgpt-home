# 质保期缺陷响应的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据围绕项目交付后的质保服务产生，日常文档包括质保工单、缺陷确认单、修复记录、客户确认单。数据来源涵盖客户提交的服务工单、系统运行日志、项目合同质保条款、代码版本提交记录。数据更新随服务工单推进，通常按单更新，单份文档包含缺陷描述、关联代码片段、版本号、客户确认状态等字段，无固定统一格式，需按工单维度关联多源数据。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的多源分散数据特征，要求引用溯源必须关联工单、日志、版本记录等不同来源的信息，避免单一数据源的偏差。按单更新的数据节奏，要求溯源逻辑需绑定当前服务工单的上下文，不能跨周期引用无关数据。文档无固定格式的特点，要求溯源配置需支持灵活匹配字段，适配不同工单的结构差异。同时，出错会引发质保争议，因此溯源必须精准关联责任边界与修复动作，确保每一处引用都可追溯到原始服务记录。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | 匹配单份质保工单及关联修复记录的总数据长度，避免截断有效关联内容 |
| `responseData` | 开启 | 输出关联的缺陷确认单、修复记录的唯一标识，实现基础溯源 |
| `detail` | 开启 | 展示引用来源的具体字段，如工单编号、代码版本号、缺陷描述片段 |
| 单次搜索上限 | 前3条 | 限制返回的关联数据条数，避免引入无关的历史缺陷记录 |
| 相似度阈值 | 0.6–0.7 | 匹配缺陷描述与历史修复记录的关联度，过滤低相关性内容 |
| 最大上下文 | 按实测标定 | 适配单质保工单的全量关联数据范围 |

## 容易做错的三处
- 现象：AI回答未显示引用来源，或返回的来源字段为空。原因：未开启`responseData`配置项，未启用溯源展示功能。
- 现象：知识库搜索返回结果条数不足，无法匹配到对应缺陷修复记录。原因：未根据质保工单的单批次数据调整`quoteMaxToken`取值，导致截断了有效关联数据。
- 现象：搜索结果关联了非当前质保期的缺陷记录。原因：未通过代码版本记录字段过滤数据，导致跨周期引用无效内容。

## 怎么确认配好了
- 上传一份测试用的质保工单与对应修复记录，发起AI代码评审请求，检查返回结果中是否包含关联的来源标识。
- 调整`quoteMaxToken`的取值，验证返回的引用数据长度是否符合预期设置。
- 查看配置界面的`detail`开关状态，确认是否开启了详细来源展示功能。
- 模拟提交跨质保周期的查询，验证返回结果是否仅包含当前服务周期内的关联数据。
