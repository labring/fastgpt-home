# 配置管理与CMDB维护的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本品类数据来源于CMDB、云资源清单、自动发现工具与采购台账，更新频率为日度或周度。日常产出的文档包含配置项清单、服务组件关系拓扑、变更记录与资产盘点表，单份配置项清单包含配置项ID、所属资产、依赖关系、状态字段，关系拓扑以节点链路形式展示组件间关联，变更记录标注操作人、时间与变更内容。数据字段以资产标识、依赖关系为核心，无额外冗余统计项。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类的数据特征对上下文与token环节带来多重约束。多来源的异构数据格式，要求上下文拼接时需兼容不同字段结构，额外的格式解析内容会占用额外token。日度或周度的更新周期，要求上下文需定期同步最新配置项与变更记录，若未及时更新则会导致评审依据失效。配置项与依赖关系的关联字段较多，单份完整数据的token占用量较高，需严格控制上下文的有效长度，避免超出模型配额。动态追加的变更记录会进一步增加上下文的token消耗，需明确上下文的更新触发条件，避免无意义的token浪费。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 本品类配置项与依赖关系的token占用较高，该区间可覆盖单批次核心评审数据且避免超出模型配额 |
| `quoteMaxToken` | `1500–2000 token` | 单条CMDB变更记录或配置项详情的token占用约为该区间下限，可保证核心引用内容完整 |
| 上下文同步间隔 | 按数据更新节奏匹配（日度数据设为24小时，周度数据设为7天） | 匹配本品类数据的更新频率，避免上下文过期或频繁同步消耗token |
| 上下文过滤规则 | 仅保留近30天的变更记录与活跃配置项 | 减少无效历史数据占用的token，聚焦当前评审相关的最新内容 |
| 上下文格式校验 | 自动过滤非配置项字段的冗余内容 | 兼容本品类多来源的异构数据格式，降低格式解析的额外token消耗 |

## 容易做错的三处
- 现象：界面展示的上下文token数与模型API计费的token数存在偏差。原因：未配置上下文格式校验规则，多来源数据的格式解析冗余内容被计入上下文但未在界面统计，导致两者计算口径不一致。
- 现象：变更评审节点返回空的上下文与AI回复内容。原因：设置的`maxContext`参数值过低，核心CMDB配置项与变更记录的token占用超出限制，导致有效上下文被完全截断。
- 现象：上下文同步后包含大量过期的非活跃配置项数据。原因：未配置上下文过滤规则，同步了超过更新周期的历史数据，额外消耗token配额且干扰评审判断。

## 怎么确认配好了
- 查看上下文预览模块，确认展示的内容为当前评审所需的配置项、关系拓扑与近30天变更记录。
- 调用测试接口，对比界面展示的token消耗与API返回的token消耗，确认两者统计口径一致。
- 模拟变更评审流程，检查AI回复内容是否基于最新的CMDB数据生成。
- 查看同步日志，确认上下文仅同步了符合更新周期的有效数据，无冗余过期内容。
