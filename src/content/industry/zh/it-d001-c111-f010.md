# 配置管理与CMDB维护的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来自CMDB、云资源清单、自动发现工具与采购台账，日常产出配置项清单、服务组件关系拓扑、变更记录、资产盘点表四类文档。数据字段包含配置项唯一标识、跨组件依赖关系、变更执行时间、资产当前状态等，更新频率为每日或每周，数据结构围绕服务间依赖关系构建，区别于通用IT资产盘点的单节点记录。

## 这些特征在「引用来源与溯源」这一环带来什么约束
依赖多源异构数据的特征，要求引用溯源需关联各数据源的唯一标识，避免单源数据偏差导致的溯源错误。固定的更新节奏要求溯源结果需匹配数据最新生效版本，防止引用过时配置项引发评审失误。围绕服务依赖关系的文档结构，要求溯源需明确标注配置项间的关联链路。仅记录单条资产信息无法满足评审所需的关联信息。同时，面向运维与SRE的使用场景，溯源结果需兼容ITSM平台的字段格式，确保可直接接入变更评审流程。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | 800–1200 字符 | 匹配CMDB配置项清单的单条记录长度，避免截断关键依赖关联信息 |
| `responseData` | 仅返回配置项ID、依赖关系、来源标识字段 | 过滤冗余的资产状态描述，聚焦变更评审所需的核心信息 |
| `detail` | 开启 | 展示溯源数据的原始采集路径、工具与版本号 |
| 单次搜索上限 | 前 3 条 | 适配CMDB数据的更新频率，减少冗余结果干扰评审流程 |
| 超时阈值 | 60 秒 | 匹配多源数据拉取的平均响应时长，防止评审流程阻塞 |

## 容易做错的三处
- 现象：检索CMDB中不存在的配置项时，仍返回无关的历史变更记录引用。原因：未限定搜索范围为当前生效的配置项数据，导致召回过时或无关的溯源结果。
- 现象：调用对话接口后，`responseData` 字段未返回引用ID。原因：未开启溯源配置的关联ID返回开关，导致未生成可追溯的唯一标识。
- 现象：配置项溯源结果超出页面显示范围，导致评审界面加载卡顿。原因：`quoteMaxToken` 设置值过大，未限制单条溯源内容的字符上限。

## 怎么确认配好了
- 发起一条针对已知CMDB配置项的变更评审查询，检查返回结果中是否包含配置项的原始来源标识。
- 故意输入不存在的配置项关键词，确认未返回无关的历史数据引用。
- 查看接口返回的`detail`字段，确认是否展示了数据采集时间与来源工具信息。
- 调整`quoteMaxToken`的取值，验证返回内容的字符长度是否符合预期设置。
