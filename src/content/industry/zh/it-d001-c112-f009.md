# 问题管理与根因分析的代码与变更评审辅助：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源为故障时间线、运行日志、监控指标、代码提交记录，更新频率为每次重大故障或每月一次。日常产出文档包括RCA报告、问题单、复盘纪要、整改跟踪表，其中RCA报告包含故障标识、发生时段、影响范围、根因条目、整改措施等字段，代码提交记录包含变更ID、提交人、评审意见、关联问题单号等字段。数据结构以故障关联的多源信息为核心，字段均与故障排查、根因分析的流程强绑定。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据更新频率较低，工具调用需绑定故障单或月度分析周期触发，避免无效调用。多源数据来源要求插件需适配日志、代码变更记录等不同格式的拉取逻辑，确保数据完整性。固定的文档结构要求工具调用的输出需匹配RCA报告等文档的必填字段，方便直接填入现有模板。根因分析的核心依赖准确的关联数据，工具调用需精准关联故障单与对应代码变更、日志信息，避免无关数据干扰分析流程。最耗时的证据收集环节可通过工具调用自动化完成，因此工具调用的触发时机需与故障复盘的流程节点对齐。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 适配多源数据的自动调用逻辑，无需手动指定工具类型 |
| `functionCall` | `["fetch_fault_logs", "fetch_code_changes", "generate_rca_section"]` | 覆盖根因分析所需的日志拉取、代码变更查询、RCA内容生成三类工具 |
| 工具调用超时时间 | `600 秒` | 根因分析需拉取多源数据，耗时较长，600秒可覆盖大部分数据拉取场景 |
| 工具调用缓存时长 | `7 天` | 数据更新频率为每月或重大故障时，缓存一周足够覆盖单次分析周期 |
| 工具调用失败重试次数 | `3 次` | 应对网络波动或接口限流，避免重复调用导致资源消耗 |
| 关联字段匹配规则 | 故障ID、变更ID | 确保拉取的数据与当前故障单强绑定，符合RCA报告的字段要求 |

## 容易做错的三处
- 现象：工具调用返回429 Request rate increased too quickly状态码，原因：未设置合理的调用间隔与重试次数，短时间内触发接口限流。
- 现象：不同工具实例的API密钥配置被互相覆盖，原因：未为每个工具单独绑定专属密钥，复用了全局配置项。
- 现象：工具调用结果无法匹配RCA报告的必填字段，原因：未配置关联字段匹配规则，拉取的数据未与当前故障单绑定。

## 怎么确认配好了
- 提交测试故障单，触发工具调用，检查是否自动拉取关联的日志与代码变更数据。
- 查看工具调用日志，确认限流报错次数符合配置的重试规则，无重复无效调用。
- 检查工具调用结果的字段是否包含故障ID、变更ID等关联字段，可直接填入RCA报告模板。
- 验证多工具实例的API密钥配置，确认不同实例的密钥不会互相覆盖。
