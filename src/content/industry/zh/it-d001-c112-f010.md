# 问题管理与根因分析的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据围绕故障后根因分析与整改落地生成，由SRE、技术负责人、质量团队日常维护，日常文档包括RCA报告、问题单、复盘纪要、整改跟踪表。数据来源为故障时间线、运行日志、监控指标、代码提交记录，更新频率为每次重大故障或每月一次。文档字段包含故障发生时间、根因描述、关联代码提交ID、整改措施、验证结果等，无统一固定的计量单位，部分字段关联具体业务系统标识。

## 这些特征在「引用来源与溯源」这一环带来什么约束
故障相关数据分散在多类系统中，引用溯源需关联跨源数据，需明确匹配代码提交ID与故障事件的关联关系。更新频率低但单批次数据量较大，需限制单次引用的上下文长度，避免超出处理上限。文档结构非标准化，不同团队的RCA报告字段存在差异，需支持灵活匹配文档片段的来源标识。整改跟踪表的关联字段需与原故障记录绑定，溯源时需验证关联关系的一致性，防止出现错误关联。跨源数据的匹配需兼顾不同系统的格式差异，确保溯源结果的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配单份RCA报告或复盘纪要的典型文本长度，避免上下文溢出 |
| `responseData` | 包含source、title、content字段 | 适配本品类文档的标准化溯源字段需求，确保来源信息完整返回 |
| `detail` | 开启 | 用于返回根因分析关联的代码提交记录的详细溯源信息 |
| 单次搜索上限 | 前3条 | 匹配每月单批次故障相关文档的数量，避免冗余引用 |
| 来源匹配阈值 | 0.75–0.85 | 用于匹配故障时间线与代码提交记录的关联度，确保根因溯源的准确性 |
| 最大上下文 | 4000 token | 适配多源数据拼接后的总长度限制，符合FastGPT的处理能力 |
本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：调用知识库时返回的引用上限不足，无法加载全部关联的RCA报告与问题单。原因：`quoteMaxToken`参数取值过低，未适配本品类单份文档的文本长度。
- 现象：通过API获取问答结果时，引用来源的下载链接为空或无法访问。原因：未正确配置`responseData`参数，仅返回了简化的摘要信息，未返回完整来源字段。
- 现象：根因分析关联的代码提交记录未被正确溯源。原因：未开启`detail`配置项，未启用详细的代码提交信息匹配逻辑。

## 怎么确认配好了
- 发起包含故障根因关键词的测试提问，检查返回结果中是否包含关联的代码提交ID与RCA报告标题。
- 调用API获取问答响应，确认`responseData`字段中包含source、title、content三个必填溯源字段。
- 查看配置面板，确认`detail`开关处于开启状态，确保详细来源信息被返回。
- 调整`quoteMaxToken`参数后，验证返回的引用来源条数是否符合预期的文档数量。
