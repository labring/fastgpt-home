# 集成测试与接口测试的代码与变更评审辅助：上下文与 token

## 这个品类的数据长什么样
本品类的数据主要来自接口管理平台、测试环境日志、数据库与消息队列，更新节奏为每日或每版本发布周期。日常关联文档包含接口测试用例、联调问题单、环境说明文档与测试报告，数据字段包含接口路径、请求参数、响应结果、调用链路标识、环境标识与问题排查记录，无统一固定单位，随接口定义与测试场景动态调整。数据使用者多为测试工程师、测试开发团队与接口平台维护人员，用于跨模块交互验证的评审与辅助。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类的数据来源分散且随版本高频更新，要求上下文覆盖多源异构的接口定义、历史测试日志与联调记录，token 限额需适配多批次的接口参数与链路数据。每日或每版本的更新节奏，要求上下文同步机制匹配版本发布周期，避免陈旧数据干扰评审。接口测试用例与联调问题单的字段动态性，要求上下文召回支持灵活的字段匹配，同时需严格控制 token 消耗，防止超出模型预设限额影响评审流程。本品类最耗时的依赖服务准备与链路问题定位环节，也依赖上下文快速召回相关测试数据，进一步提升了对上下文精准性与token利用率的要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 2000–5000 token | 适配接口测试用例、联调日志的多源数据汇总，避免超出FastGPT v4.17.0版本的模型上下文限额 |
| `quoteMaxToken` | 800–1200 字符 | 限制单条引用数据的长度，防止单条引用占用过多上下文token |
| 上下文同步周期 | 每日 / 每版本触发 | 匹配本品类数据的更新节奏，保证上下文数据时效性 |
| 召回数据条数 | 前 5–8 条 | 覆盖典型联调问题与接口调用链路，避免过多冗余数据消耗token |
| 数据过滤阈值 | 按实测标定 | 过滤无效的测试日志与冗余参数，减少上下文加载量 |

## 容易做错的三处
- 现象：变更评审返回接口参数不匹配，且报错提示上下文溢出。原因：未限制`quoteMaxToken`取值，单条引用数据过长导致上下文总token超出`maxContext`限额。
- 现象：跨团队联调评审时，旧版本测试数据被优先召回。原因：上下文同步周期未匹配数据更新频率，未按版本触发同步机制。
- 现象：接口调用链路的日志数据未被正确召回。原因：未配置灵活的字段匹配规则，仅固定匹配接口路径字段，忽略了动态的调用链路标识。

## 怎么确认配好了
- 查看上下文配置页面的`maxContext`与`quoteMaxToken`参数，确认取值与当前测试场景的规模匹配。
- 触发一次代码变更评审，检查召回的测试数据是否包含最新的接口测试用例与联调问题单。
- 模拟提交单条长引用数据的评审请求，确认未触发上下文溢出报错。
- 核对系统数据同步日志，确认同步周期与当前数据的更新节奏一致。
