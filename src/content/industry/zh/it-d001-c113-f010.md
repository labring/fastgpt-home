# 集成测试与接口测试的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来自接口管理平台、测试环境日志、数据库与消息队列，更新频率为每日或每版本发布周期。日常关联文档包含接口测试用例、联调问题单、环境说明与测试报告，数据字段包含接口路径、请求参数、预期响应、调用链路ID、响应状态码与依赖服务标识，各字段按原生系统存储格式留存，无额外自定义单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据的分散存储要求溯源流程需跨接口管理平台、测试日志系统等完成关联匹配，避免单一数据源的信息缺失。按日或版本级的更新节奏，需要配置增量同步与全量重建的切换逻辑，适配不同更新频率的数据源。不同类型文档的字段优先级差异，要求溯源时优先匹配调用链路ID、响应状态码这类高辨识度字段，通用接口参数的匹配优先级较低。依赖服务的标识需严格对齐，防止跨服务的引用混淆，避免出现服务间调用失败、联调延期的出错后果。同时，最耗时的链路问题定位环节也需要依托溯源的精准关联来缩短处理周期。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1500 token | 适配接口测试用例与日志的单条内容长度，保证引用信息完整 |
| `responseData` | 开启 | 展示接口响应的原始内容与状态码，支撑溯源验证 |
| `detail` | 开启 | 输出关联数据的来源系统与更新时间，完善溯源链路 |
| 单次召回上限 | 前 6–10 条 | 适配接口测试与集成测试场景下的平均关联数据源数量，避免冗余信息干扰评审判断 |
| 上下文缓存时长 | 3600 秒 | 适配每日更新的测试数据同步节奏，保证评审时的上下文一致性 |
| 来源过滤规则 | 仅保留接口管理平台、测试日志系统数据 | 过滤非品类关联的无关数据源，提升溯源准确性 |

## 容易做错的三处
- 现象：返回的引用未匹配标注为综合排名第一的测试用例文档。原因：未配置按关联匹配度优先排序的规则，错误使用了文档上传时间作为排序依据。
- 现象：通过API调用时，返回结果中未包含引用的接口测试用例文件名或日志路径。原因：未开启`detail`配置项，未启用元数据返回开关。
- 现象：引用内容截断了关键的响应状态码或调用链路ID信息。原因：`quoteMaxToken`取值过小，未适配接口测试数据的常规内容长度。

## 怎么确认配好了
- 提交一条包含明确调用链路ID的测试评审请求，核对返回的引用内容是否包含对应链路的日志与用例信息。
- 查看配置项的生效状态，确认`quoteMaxToken`、`responseData`、`detail`的取值与预设配置一致，本核对适用于FastGPT v4.17.0版本。
- 发起多源数据的关联检索，验证是否能同时匹配接口管理平台与测试日志系统的关联内容。
- 调用API接口，检查返回结果中是否包含来源系统标识与文件路径信息。
