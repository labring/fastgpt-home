# 需求分析与PRD管理的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
互联网产品团队、业务分析师与产品经理是该品类的典型使用主体，日常产出需求调研纪要、PRD、用户故事清单与需求变更单等文档。数据来源涵盖客户访谈记录、工单系统、竞品公开页面与埋点看板，更新频率为周度或每版本周期。文档包含业务目标、验收口径、变更细节等多类字段，最耗时环节集中在访谈信息归类、边界条件确认与需求变更同步，处理不当可能引发开发返工、排期延误或验收争议。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的多类型文档与非固定更新节奏，要求工作流支持多源数据的动态接入与定期同步，避免因数据过期导致评审偏差。文档字段的多样性与复杂性，需要通过工作流的参数配置精准提取对应内容，减少人工筛选的工作量。需求变更同步的高频性，要求工作流内置循环或触发机制，及时响应变更内容。出错后果的严重性，要求工作流配置失败处理与状态追踪节点，保障评审流程的稳定性。本配置基于FastGPT v4.17.0版本的工作流能力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定需求调研纪要、PRD的结构化字段 | 品类数据包含多类文档，需提取对应字段作为工作流输入 |
| 循环体结束条件 | 检测到需求变更完成标识字段 | 需求变更同步是核心耗时环节，需提前终止无效循环 |
| 单次执行超时 | 600 秒 | 需求文档处理需覆盖多轮信息归类，避免长时间阻塞 |
| `nodeId` | 按工作流节点顺序依次赋值 | 需精准定位每个评审环节的执行节点，避免流程混乱 |
| 工具调用参数 | 传入当前节点的PRD核心内容片段 | 需精准传递需求分析所需的具体内容，提升评审准确性 |
| 单次召回条数 | 前 5 条 | 适配PRD文档中核心评审内容的常规占比 |
| 最大上下文长度 | 800–1200 字符 | 按实测标定，适配PRD文档的常规长度 |
| 单次执行重试次数 | 3 次 | 适配需求评审过程中的临时调整需求 |
| 免登录访问配置 | 按需开启 | 适配部分团队公开预览工作流效果的需求 |

## 容易做错的三处
- 工作流运行预览正常但发布免登录窗口后无响应，原因是未正确配置免登录访问的权限参数，导致匿名访问被拦截。
- 循环体无法按指定条件终止，原因是未将循环结束条件绑定到品类数据中的需求变更标识字段，无法触发终止逻辑。
- 工具调用返回结果与输入内容不匹配，原因是未通过`variables`关联对应文档字段，导致传入的参数未覆盖核心需求内容。

## 怎么确认配好了
- 触发工作流执行，查看各节点的`variables`绑定结果，确认是否正确提取了PRD与需求调研纪要的对应字段。
- 模拟触发循环体的结束条件，验证循环是否在满足指定标识后正常终止，避免无效执行。
- 配置免登录访问后，使用匿名链接访问工作流，测试是否能正常返回评审结果。
- 查看工作流的节点日志，确认`nodeId`的定位是否与预设的评审环节一一对应，无错位情况。
