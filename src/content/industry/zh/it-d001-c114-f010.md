# 需求分析与PRD管理的代码与变更评审辅助：引用来源与溯源

## 这个品类的数据长什么样
本品类的核心数据来自互联网产品团队、业务分析师与产品经理的日常产出，包含需求调研纪要、PRD文档、用户故事清单及需求变更单。数据来源覆盖客户访谈记录、内部工单系统、行业公开页面与埋点看板，更新节奏为每周或每版本迭代一次。文档结构通常包含业务目标定义、验收边界条件、变更触发节点等字段，无统一强制格式，需适配团队日常协作习惯。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的文档无统一强制格式，导致引用溯源环节需适配多类文本结构，无法依赖固定字段完成自动匹配，需额外配置文本特征识别规则。周/每版本的更新节奏，要求溯源系统支持按版本关联历史文档，避免跨版本引用时出现依据混淆。多渠道的数据来源，需整合客户访谈记录、工单系统等分散数据源的引用标记，确保溯源时覆盖全部原始依据。验收口径的严谨性要求，让溯源环节需精准关联原始业务定义，降低后续开发返工与验收争议的概率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 适配PRD文档的单块内容长度，避免截断关键引用依据 |
| `responseData` | 开启引用来源展示 | 满足产品团队对溯源的核心需求，确保正式输出中包含引用文档信息 |
| `detail` | 完整溯源模式 | 覆盖需求调研纪要、变更单等多类文档的详细引用标记，支持展示完整的原始引用信息 |
| 单次搜索上限 | 前5条 | 控制溯源结果的信息量，避免过多冗余内容干扰评审 |
| 上下文缓存时长 | 7 天 | 匹配本品类的周/每版本更新节奏，保留对应周期内的引用关联数据 |

## 容易做错的三处
- 现象：调试页面可展示引用文档的页面链接，但正式发布的聊天页面无该内容。原因：未开启`responseData`对应的正式环境溯源展示开关，仅在调试模式启用了元数据输出。
- 现象：文本内容提取组件无法提取知识库中的引用关联内容。原因：未将`detail`配置为完整溯源模式，组件仅抓取了纯文本片段，未关联原始引用的元数据信息。
- 现象：发布的知识库页面未展示引用文档的出处。原因：未配置`quoteMaxToken`的合理取值，导致引用标记被截断或未生成完整的溯源链接。

## 怎么确认配好了
- 进入FastGPT v4.17.0的正式发布聊天页面，检查是否包含引用文档的出处信息，确认`responseData`配置生效。
- 调用文本内容提取组件，验证是否能提取知识库关联的引用元数据，确认`detail`配置符合需求。
- 提交需求变更评审请求，检查溯源结果是否覆盖对应周期内的全部相关文档，确认上下文缓存时长配置匹配更新节奏。
- 查看系统运行日志，确认`quoteMaxToken`的取值未截断关键的引用依据内容。
