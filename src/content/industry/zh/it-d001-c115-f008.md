# 项目实施计划管理的代码与变更评审辅助：工作流编排

## 这个品类的数据长什么样
通常数据来自项目合同、工作分解结构（WBS）、客户确认的日程、现有项目管理系统。日常维护的文档包括项目计划、里程碑清单、周报、风险问题清单。字段一般包含任务标识、责任人、交付物要求、进度占比、风险等级，更新节奏为每周或每个项目里程碑节点完成一次同步。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需要配置多源数据接入节点，适配合同、WBS等不同数据源的导入。更新节奏灵活要求工作流支持定时触发与手动触发两种模式，适配周度同步与里程碑节点校验的场景。多类型文档的处理需求，要求工作流节点支持不同格式文档的上传与解析环节。任务与评审结果的关联逻辑，要求工作流中配置`variables`绑定任务ID与变更评审条目，确保评审结果能精准关联到对应项目任务。不同于现场部署实施品类，本品类关注进度、范围与责任人的关联，因此工作流需要绑定责任人字段与评审结果，确保责任清晰。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流触发方式 | 按里程碑节点定时触发或手动触发 | 适配项目周度同步与里程碑校验的更新节奏 |
| 表单输入节点默认值 | 取全局`variables`中的项目ID字段 | 确保表单自动关联当前项目上下文 |
| 工具调用分流规则 | 知识库调用优先，MCP调用仅用于变更影响评估 | 匹配代码评审与变更辅助的核心需求 |
| 文档上传格式支持 | 支持docx、xlsx、pdf格式 | 覆盖项目计划、周报等常用文档类型 |
| 失败重试配置 | 重试3次，间隔600秒 | 应对多源数据接入时的临时网络波动 |
| 变量绑定节点 | 绑定`nodeId`为任务评审节点 | 确保评审结果精准关联对应任务 |

## 容易做错的三处
- 工作流导出后无法正常导入，提示格式错误。原因是未选择FastGPT官方导出格式，直接复制界面文本导致结构损坏。
- 工具调用分流不生效，知识库调用始终触发。原因是分流规则未配置`variables`中的请求类型字段作为判断条件，无法识别MCP调用场景。
- 表单输入节点无法获取全局变量值，字段为空。原因是未将全局变量映射到表单的默认值绑定项，未正确关联`variables`中的全局参数。

## 怎么确认配好了
- 手动触发一次工作流，检查是否能正确导入项目管理系统的WBS数据。
- 提交一个变更评审请求，确认工具调用会根据请求类型分流到知识库或MCP节点。
- 打开表单输入节点，检查默认值是否自动填充了当前项目的全局`variables`参数。
- 上传docx格式的项目周报，确认解析后能提取其中的进度更新内容。
