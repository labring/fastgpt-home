# IT资产盘点的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
IT资产盘点场景的核心数据来自资产管理系统、采购系统、财务固定资产模块、终端管理平台。日常产出的文档包括资产台账、月度盘点表、领用归还单、报废申请单。数据字段包含资产编号、设备名称、规格型号、使用人、部署位置、状态等，不同系统导出的文档结构存在差异。数据更新频率以月、季或年为周期，单次汇总的文档规模随盘点范围扩大而增加。

## 这些特征在「上下文与 token」这一环带来什么约束
多来源的文档格式差异要求上下文处理需兼容不同的字段排版，避免切分丢失资产编号、使用人等关键关联信息。低更新频率但单次汇总的大文档量，会导致上下文token消耗显著增加，需严格控制召回与截断阈值。不同文档类型的字段优先级不同，资产台账的核心字段需优先纳入上下文，而报废申请单的审批流程信息仅在特定场景下需要召回。账实核对的业务场景要求上下文保留历史盘点记录的关联关系，避免跨文档的字段断裂，同时需与配置管理CMDB维护场景区分，更聚焦资产权属、位置和使用人的实时关联。

## 配置怎么定
本页面配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 12000–15000 token | 适配IT资产盘点汇总场景的总文档token规模，避免模型截断关键资产信息 |
| `quoteMaxToken` | 4000–6000 token | 限定单条召回文档的token占用，平衡信息完整性与上下文冗余 |
| 分块重叠长度 | 100–150 字符 | 保留资产编号、使用人、位置等跨块关联字段的上下文连续性 |
| 单次召回条数 | 前8条 | 匹配月度盘点表、台账等单批次数据的条目数量，避免过多无关信息干扰 |
| 分块长度 | 800–1000 字符 | 适配资产台账单条记录的字段长度，避免单块包含过多不相关资产信息 |

## 容易做错的三处
- 现象：上下文引用区域显示的文档格式为纯文本，未保留原文档的Markdown排版。原因：未开启文档格式保留配置，或切分时丢失了原文档的格式标记。
- 现象：页面展示的上下文引用条数与发送到模型的实际条数不符。原因：召回时未正确过滤重复资产编号的关联文档，或上下文截断阈值设置与页面展示逻辑不一致。
- 现象：模型返回的token消耗统计与手动计算的文档token数存在偏差。原因：未按照FastGPT的token计算规则处理资产字段的单位与特殊字符，或未排除非核心字段的token消耗。

## 怎么确认配好了
- 上传一份标准的资产台账文档，查看上下文引用区域的格式是否与原文档一致。
- 对比页面展示的上下文条数与模型调用日志中的实际召回条数，调整召回配置使两者对齐。
- 手动统计单份盘点表的token数，与FastGPT的token计算结果对比，验证计算规则适配性。
- 调用API传入自定义上下文参数，确认模型能够正确接收并使用传入的上下文内容。
