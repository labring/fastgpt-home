# Pull Request评审的发布说明与运营报告汇总：定时任务与自动化

## 这个品类的数据长什么样
本品类的数据主要来自代码仓库、CI流水线、关联Issue链接及贡献者提交记录。日常产出的文档包含PR说明、代码评审意见、CI执行结果、合并操作记录。数据更新节奏以日或周为周期，单条数据包含PR编号、提交人信息、变更涉及的文件数量、评审意见条目、CI运行状态及合并标记等字段，无额外预设统计数值。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于本品类数据来自代码仓库的实时变更及CI流水线结果，定时任务需匹配代码提交的常规低峰时段执行，避免与CI资源占用冲突。数据更新以日或周为周期，任务执行周期不宜过短，防止重复处理未发生变更的PR条目。单条数据包含非结构化的评审意见与CI日志，自动化处理需适配多格式的文本解析规则。同时关联Issue链接需实时校验有效性，任务需包含状态检查环节，避免处理失效的关联数据，保障汇总结果的准确性。本品类最耗时的变更意图确认、测试结果检查环节，需通过自动化任务优先处理高优先级PR，提升整体处理效率。

## 配置怎么定
本文档适用于FastGPT v4.17.0版本，以下配置均基于该版本的界面与参数逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发周期 | 每日凌晨2:00-4:00 或 每周一凌晨 | 匹配代码提交的低峰时段，避免占用CI运行资源 |
| 单次处理PR数量上限 | 前20条未处理PR | 适配单次任务的资源消耗，防止任务运行超时 |
| 评审意见解析阈值 | 按实测标定 | 适配不同团队的评审意见格式差异，保障解析准确性 |
| CI结果校验超时时间 | 300秒 | 匹配常规CI运行的平均时长，避免误判临时超时 |
| 失效关联Issue过滤开关 | 开启 | 自动排除已关闭或删除的Issue链接，保障汇总数据有效性 |
| 任务失败重试次数 | 2次 | 应对临时的代码仓库接口波动，提升任务执行成功率 |

## 容易做错的三处
- 现象：定时生成的PR评审汇总数据出现重复条目。原因：未配置PR状态过滤规则，重复处理已合并或关闭的PR。
- 现象：配置的定时任务在次日自动重置为初始值。原因：未将任务配置持久化存储，依赖的临时配置缓存被系统自动清理。
- 现象：任务执行后生成的汇总数据缺少CI结果字段。原因：未开启CI日志抓取配置，未关联CI流水线的执行结果。

## 怎么确认配好了
- 查看任务调度日志，确认任务在预设的触发时段自动启动。
- 手动触发一次任务，检查生成的汇总数据包含正确的PR编号、评审意见及CI运行状态。
- 验证失效Issue过滤功能，输入一个已关闭的Issue链接，确认任务自动排除该条目。
- 检查任务失败重试配置，模拟一次代码仓库接口超时，确认任务自动触发重试。
