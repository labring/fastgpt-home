# 事件响应与故障处理的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
该品类的数据来源包括监控告警、日志平台、APM工具与用户反馈，更新频率为实时或每次事件触发时。日常产出的文档包含故障工单、事件时间线、应急预案与故障通报，字段涵盖故障唯一标识、发生时间、受影响服务范围、止损操作记录、通报对象与执行状态，部分字段需匹配标准化的运维数据格式，无固定统计类百分比字段。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的拉取需求要求工作流需配置多个跨平台的数据接入节点，实时更新的特性要求触发节点需绑定实时事件，适配数据即时更新的节奏。多类型文档的结构化处理需求要求工作流需通过变量存储不同文档的专属字段，避免数据混淆。故障处理的优先级要求恢复服务的节点需置于影响面判断与止损操作之前，同时需预留异常分支的处理链路，应对不同类型的故障场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 包含故障ID、发生时间、影响服务、通报对象4个字段 | 匹配故障工单与事件时间线的结构化字段需求，保障数据调用的准确性 |
| `nodeId` | 按告警触发节点、数据拉取节点、止损执行节点、通报节点依次分配 | 明确工作流各环节的执行顺序与依赖关系，避免链路混乱 |
| 触发时机 | 实时触发（监控告警推送后10秒内） | 匹配数据实时更新的频率，保障故障响应的时效性 |
| 重试次数 | 3次 | 应对监控拉取、日志查询的临时网络波动，减少无效中断 |
| 超时阈值 | 600秒 | 覆盖单次数据拉取与止损操作的最长执行时长，避免工作流无限等待 |
| 节点连接线 | 按执行链路依次连接，关键节点添加分支判断 | 匹配故障处理的串行执行与异常分支处理需求，适配不同故障等级的响应逻辑 |

## 容易做错的三处
- 现象：工作流中的节点无法复制粘贴到其他工作流，拖拽移动时无位移反馈。原因：未在当前工作流编辑页完成组件选中与复制操作，或切换工作流时未保留复制缓存。
- 现象：使用工具调用节点时返回Invalid JSON: Bad control chara报错。原因：节点输入的参数包含未转义的换行符、制表符等控制字符，未通过`variables`变量做格式化处理。
- 现象：拖拽节点时无法生成连接线，界面无连接小圆圈提示。原因：工作流中存在不支持跨链路连接的节点类型，或未开启FastGPT v4.17.0的工作流连接增强功能。

## 怎么确认配好了
- 触发`variables`变量的预览功能，确认包含故障ID、发生时间、影响服务、通报对象的字段。
- 手动触发工作流，查看各节点的执行日志，确认超时阈值与重试次数的配置生效。
- 检查节点连接线的链路顺序，确认与故障处理的执行逻辑一致。
- 打开工具调用节点的设置面板，确认可在模型选择下拉列表中查看当前可用的模型标识。
