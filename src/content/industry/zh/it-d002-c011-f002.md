# 云主机交付与资源开通的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的日常文档包含资源开通单、实例配置表、账号权限单、交付确认单，核心字段涵盖实例ID、计算规格、网络配置、权限范围、计费项等。数据来源为云管理平台、订单系统、IAM系统与计费系统，更新节奏为每单实时同步。单份交付相关文档的内容围绕单台云主机的创建与交付流程展开，关联单据数量随订单复杂度变化。

## 这些特征在「上下文与 token」这一环带来什么约束
多源数据来源要求上下文需整合订单、权限、计费等不同系统的关联信息，若未限定关联范围，会导致上下文冗余且token消耗过高。实时更新的特性要求上下文需同步最新的配置与权限变更，否则会出现配置不符的问题。单份文档的字段集中于云主机核心配置，若引入无关数据，会增加token占用并降低检索效率。同时，该品类出错后果直接影响客户部署，上下文的准确性与token的合理性需严格匹配业务流程，避免因token超限或上下文冗余导致交付异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 覆盖单订单关联的3-4份核心文档的总token消耗，避免超出平台常规限制 |
| `quoteMaxToken` | `5000–8000 token` | 限定单份关联文档的token上限，防止单份文档内容过多导致整体token超限 |
| 上下文关联范围 | 关联当前订单的3份核心单据 | 匹配数据来源的多系统特性，仅引入与当前交付流程直接相关的订单、权限、计费信息 |
| 检索引用上限 | 前3–5条 | 云主机交付的核心配置项集中，过多引用会增加token消耗且不提升信息准确性 |
| 上下文同步频率 | 实时同步 | 适配数据每单实时更新的节奏，保证上下文携带最新的配置与权限信息 |

## 容易做错的三处
- 调用FastGPT应用API后上下文未生效，表现为返回结果未携带历史交付单据信息，原因是未配置`maxContext`参数或取值为0，未开启上下文关联功能。
- 知识库查询时token消耗过大，表现为单次请求token数远超常规范围，原因是未限定`quoteMaxToken`的取值，直接设置为5万token，导致冗余数据被带入上下文。
- 无法将工作流全局变量token传递给MCP工具，表现为MCP工具调用时入参token字段为空，原因是未将上下文变量正确绑定至MCP工具的入参配置项。

## 怎么确认配好了
- 查看FastGPT v4.17.0应用的配置页面，确认`maxContext`与`quoteMaxToken`的取值符合预设范围。
- 发起测试请求，查看返回的上下文内容是否包含当前订单的资源开通单、实例配置表等关联单据信息。
- 监控请求日志，确认单次请求的token数未超出平台限制且符合配置要求。
- 测试MCP工具调用流程，确认全局变量token可正常传递至工具的入参位置。
