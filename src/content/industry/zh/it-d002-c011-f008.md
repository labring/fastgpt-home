# 云主机交付与资源开通的发布说明与运营报告汇总：工作流编排

本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
这个品类的数据主要来自云管理平台、订单系统、IAM权限系统与计费系统，更新节奏为每单实时同步。日常关联文档包括资源开通单、实例配置表、账号权限单与交付确认单，数据字段包含实例ID、计算规格、权限范围、交付状态、计费周期等，单位对应CPU核数、内存GB、时长等，仅聚焦计算资源相关的交付与开通数据，不涉及其他云服务品类的配置内容。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散且更新实时，工作流编排需要跨系统拉取数据并配置触发式执行节点，避免手动同步的延迟。日常文档的多字段结构要求工作流绑定对应单据的变量映射，确保数据准确流转。出错后果直接影响客户资源部署与计费准确性，因此需要配置失败重试与告警机制。同时，该品类仅聚焦计算资源交付，工作流无需涉及网络负载均衡等其他云服务品类的配置环节，需明确节点执行范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `variables` | 绑定资源开通单、实例配置表的字段，格式为`{"instanceId": "", "spec": "2核4GB", "expireTime": "2024-12-31"}` | 匹配日常文档的字段结构，实现跨系统数据自动同步 |
| 节点触发时机 | 按订单状态变更触发 | 匹配数据实时更新的节奏，避免重复拉取无效数据 |
| 失败重试次数与间隔 | 重试3次，间隔60秒 | 应对云API临时抖动，平衡重试成本与交付效率 |
| `nodeId` | 绑定云主机创建节点的唯一标识 | 精准定位工作流中的核心计算资源创建环节，便于异常排查 |
| 结果过滤配置 | 仅保留交付确认单的最终状态字段 | 过滤中间环节的冗余数据，避免输出无关内容 |
| 告警触发阈值 | 超时1200秒触发告警 | 匹配云主机交付的常规耗时区间，及时通知运维人员 |

## 容易做错的三处
- 现象：工作流中插入AI对话节点后，最终输出包含中间对话内容。原因：未配置结果过滤规则，未指定仅保留指定节点的输出字段。
- 现象：工作流执行时出现权限校验失败报错。原因：未绑定IAM系统的权限变量，未在工作流中配置权限拉取环节。
- 现象：资源开通单的字段未自动填充到工作流节点。原因：未正确绑定`variables`参数，未关联对应文档的字段映射。

## 怎么确认配好了
- 触发一条测试资源开通订单，检查工作流是否自动拉取对应订单的配置字段到`variables`中。
- 模拟云API调用失败，检查工作流是否按配置的重试次数执行重试，并在重试失败后触发告警。
- 查看工作流输出日志，确认仅包含交付确认单的最终状态字段，无中间AI对话的冗余内容。
- 核对`nodeId`对应的节点是否为云主机创建环节，确认工作流节点的执行顺序符合资源交付流程。
