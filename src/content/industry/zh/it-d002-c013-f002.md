# 云账单与成本核算的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的数据通常来自云计费系统、标签数据、订单系统与资源监控工具，日常产出账单明细、成本分摊表、资源利用率报表、优化建议单四类文档。数据更新频率多为日度或月度，单份文档包含资源ID、计费项、金额、标签归属、利用率等字段，单位涵盖元、小时、GB等，核心关联标签与资源消耗的对应关系。

## 这些特征在「上下文与 token」这一环带来什么约束
账单明细与成本分摊表的字段关联紧密，上下文召回需匹配标签、计费项等精准字段，对召回精度要求更高；日度更新的账单数据时效性强，需控制上下文刷新频率避免引用过时信息；优化建议单与资源利用率报表的内容长度差异较大，需适配不同长度的上下文片段；异常费用排查场景下需召回多份关联文档，容易超出token限制，需严格控制上下文总长度与单片段占用；部分场景下需通过API直接传入自定义上下文，需确保配置的`maxContext`适配传入的自定义内容长度。

## 配置怎么定
本文档适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多份账单明细、分摊表的总长度，避免超出通用大模型的上下文限制 |
| 单次召回文档数 | 前6–8条 | 匹配云账单场景下单批次关联文档的平均数量，平衡召回精度与token占用 |
| `quoteMaxToken` | 1500–2000 token per quote | 限制单份文档片段的token占用，防止单条引用超出上下文分配额度 |
| 上下文刷新间隔 | 每日1次 | 匹配云账单日度更新的频率，确保上下文引用最新的账单与分摊数据 |
| 上下文召回阈值 | 按实测标定 | 需适配标签、计费项等精准字段的匹配要求，避免召回无关的资源数据 |

## 容易做错的三处
- 现象为页面展示的上下文引用条数与实际传入模型的条数不符，例如页面显示30条但实际传入310条。原因是配置的召回上限与前端展示的截断逻辑未对齐，导致前端展示与实际调用参数不一致。
- 现象为上下文引用的文档片段未正确渲染Markdown格式，仅显示原始的分隔符与标记文本。原因是未启用文档片段的格式解析配置，导致Markdown标记被保留为纯文本。
- 现象为长文本的账单明细片段被过度截断，丢失关键的计费项与标签信息。原因是未针对长文档设置合理的`quoteMaxToken`限制，或未启用自动截断逻辑。

## 怎么确认配好了
- 查看模型调用日志，核对传入的上下文文档条数与配置的单次召回文档数是否一致。
- 测试调用接口，检查返回的上下文片段是否正确渲染表格、列表等Markdown格式。
- 统计单份账单明细文档的token消耗，确认未超出`quoteMaxToken`的预设值。
- 查看系统设置中的上下文刷新间隔，确认与云账单的更新频率匹配。
