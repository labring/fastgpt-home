# 云资源合规审计的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
本品类的数据主要来自云审计日志、IAM权限系统、CMDB资源清单、安全基线扫描结果。日常产出的文档包括合规检查表、权限审计报告、资源盘点清单、整改跟踪表。数据更新频率为月度或季度，单份文档包含资源ID、权限配置项、合规状态、整改进度等字段，仅按实际采集的云资源与合规状态生成对应条目，无额外统计数值。

## 这些特征在「上下文与 token」这一环带来什么约束
云资源合规审计的文档多为结构化表格类内容，且更新周期较长，单次调用需覆盖的历史数据范围相对固定。由于数据来源分散且字段标准化程度高，上下文拼接时需精准匹配资源ID、权限项等关键字段，避免无关数据混入。月度/季度的更新节奏意味着上下文窗口无需频繁刷新，但需保留足够的历史合规记录用于跨周期对比。同时，单份合规报告的token占用量较高，需控制上下文总token数，防止超出模型承载上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 保留近2-3份历史合规审计报告 | 依据合规审计的月度/季度更新周期，该范围可覆盖完整的季度合规跟踪周期，避免冗余数据占用token |
| `quoteMaxToken` | 7500-8500 token | 依据单份合规审计报告的平均token占用量，该区间可覆盖1-2份完整的结构化合规文档，避免超出模型承载上限 |
| 最大上下文总token | 按模型支持上限的70%-90%取值 | 依据云资源合规审计文档的token占用特征，预留足够空间用于拼接临时问题与回答 |
| 上下文字段匹配规则 | 仅匹配资源ID、权限配置项 | 依据结构化文档的字段标准化程度，精准匹配关键字段可避免无关数据混入上下文 |
| 上下文刷新周期 | 月度 | 依据数据更新频率，与合规报告的更新周期保持一致，避免加载过时的合规数据 |

本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：调用API时返回上下文为空，连续追问合规相关问题后答非所问。原因：未正确配置`maxContext`参数，未保留历史合规审计报告的上下文数据，导致模型无法关联跨轮次的资源权限信息。
- 现象：合规文档上传后被截断，无法完整加载全部内容。原因：`quoteMaxToken`取值过低，超出单份文档的token占用量，导致文档被强制切片后丢失关键合规字段。
- 现象：审计报告拼接后出现无关的非合规数据条目。原因：未配置精准的字段匹配规则，将非资源相关的日志数据混入上下文窗口，干扰合规审计结果的生成。

## 怎么确认配好了
- 上传一份完整的合规审计报告，查看系统展示的上下文预览内容，确认包含报告中的关键资源ID与权限配置项。
- 发起连续两轮合规审计相关的提问，查看第二轮回答是否关联第一轮提及的资源信息，确认上下文生效。
- 调用API获取上下文数据，检查返回的上下文条目数量与配置的`maxContext`参数取值一致。
- 调整`quoteMaxToken`参数后上传测试文档，确认文档未被截断且完整加载全部合规字段。
