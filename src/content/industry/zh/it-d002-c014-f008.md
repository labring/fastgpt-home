# 云资源合规审计的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
本品类的数据主要来自云审计日志、IAM权限系统、CMDB资源清单库及安全基线扫描结果。日常产出的文档包括合规检查表、权限审计报告、资源盘点清单、整改跟踪表四类，每类文档包含资源标识、权限配置项、合规状态、整改状态等字段。数据更新频率为月度或季度，核心数据需覆盖全量云资源的权限与配置状态，未经过清洗的原始日志需先完成格式标准化处理。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需集成多系统接口，需按云资源类型、权限维度拆分节点避免请求过载。月度/季度的更新频率要求工作流支持定时触发，且需预留数据校验环节处理原始日志的格式异常。合规文档的强关联性要求工作流中需保留字段映射规则，确保资源清单与审计报告的字段匹配。整改证据核对的高耗时特性要求工作流可配置批量拉取证据的节点，同时需设置异常重试机制避免单次请求超时。审计不通过的风险要求工作流输出的报告需包含完整的合规判定依据，不可省略关键字段。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发周期 | 月/季触发，单次执行时长不超过 3600 秒 | 匹配本品类月度/季度的更新频率，避免频繁调用云接口产生超额费用 |
| 批量请求上限 | 单次拉取前 20 条资源数据 | 适配CMDB与云审计日志的接口限流规则，防止请求被拦截 |
| `variables`配置 | 绑定云资源ID、合规阈值、整改状态标识三类变量 | 确保不同文档间的字段一致性，支持下游节点复用变量值 |
| 重试次数与间隔 | 失败后重试 2 次，间隔 60 秒 | 应对云接口临时波动，避免单次请求失败导致整个工作流中断 |
| `nodeId`关联 | 绑定数据校验节点与报告生成节点的ID | 确保工作流节点执行顺序符合合规文档的生成逻辑 |
| 证据拉取范围 | 按合规检查表的条目筛选待拉取证据 | 减少无效数据拉取，降低整改证据核对的耗时 |

## 容易做错的三处
- 工作流中`variables`配置仅传入模型名称，未绑定MaxToken、温度等参数。现象为节点执行时返回状态码400，提示缺少模型配置参数，原因是未在变量配置中补充模型的额外配置项。
- 未配置`nodeId`关联规则导致全局变量更新不生效。现象为嵌入系统的分享链接携带的custId参数未同步更新，原因是节点间的变量传递未绑定正确的节点ID，导致上游变量未传递到下游配置环节。
- http请求节点未配置jsonPath提取规则。现象为响应结果无法被下游节点读取，字段为空，原因是未在节点设置中配置jsonPath提取规则，导致返回的JSON内容未被解析为可用变量。

## 怎么确认配好了
- 手动触发一次工作流，检查输出的合规检查表是否包含所有配置的资源字段，确认变量映射规则生效。
- 查看工作流的执行日志，确认定时触发周期符合预设的月度/季度节奏，重试次数与间隔符合配置要求。
- 调用http请求节点的测试接口，输入模拟的云审计日志响应，确认jsonPath提取规则能正确提取目标字段。
- 检查`variables`配置项是否包含所有必要的合规相关变量，确保下游节点可直接复用这些变量生成报告。
