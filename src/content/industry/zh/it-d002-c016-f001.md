# 代码安全审计的发布说明与运营报告汇总：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据主要来自源代码仓库、依赖清单、静态代码扫描工具与公开漏洞库，更新节奏为对应代码版本发布或项目审计周期内完成。日常产出的文档包含代码审计报告、漏洞证明材料、修复建议文档与复测记录，字段通常包含漏洞标识、风险等级、影响代码范围、修复状态、复测验证结果等，无统一强制格式，随审计项目调整。FastGPT v4.17.0及以上版本支持对接该类数据的接口拉取。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于该品类数据来源分散且格式无统一标准，HTTP接口需支持多类型输入解析与自定义字段映射，适配不同审计项目的报告结构。数据按代码版本或审计项目更新，接口需支持按项目标识、版本号筛选拉取，避免冗余全量请求。因数据包含高危漏洞信息，接口鉴权需独立于基础应用权限，同时需限制单请求返回数据量，防止敏感信息批量泄露。另外，复测记录的增量更新需求，要求接口支持基于时间戳或更新状态的增量拉取逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带AI Proxy管理员Token的Bearer格式字符串 | 用于接口身份校验，符合FastGPT服务端鉴权要求 |
| `variables` | 包含项目ID、版本号的自定义参数集合 | 用于筛选对应代码版本的审计报告数据 |
| `responseData` | 映射为漏洞标识、风险等级、修复状态的自定义结构 | 适配不同来源的代码审计报告格式 |
| 单次请求数据上限 | 前100条记录 | 防止批量返回敏感漏洞信息，适配接口传输限制 |
| 请求超时时间 | 600秒 | 覆盖复杂审计报告的解析与拉取耗时 |

## 容易做错的三处
- 现象：调用接口后返回的运营报告中多包含重复的历史审计记录。原因：未配置增量拉取逻辑，每次请求全量拉取数据导致重复条目。
- 现象：接口返回状态码401，且无法拉取代码审计报告。原因：误用应用API Key代替AI Proxy管理员Token作为鉴权参数，未遵循服务端环境变量配置要求。
- 现象：开启stream模式调用接口时，无法正确获取最终的发布说明汇总结果。原因：未正确处理流式响应的分段数据，未完成完整内容拼接。

## 怎么确认配好了
- 检查App/Admin服务端的AI Proxy相关环境变量是否已正确配置，且未在应用层或工作流中重复填写鉴权参数。
- 发起测试请求，验证接口返回的字段与预设的`responseData`映射规则一致，无缺失关键审计信息。
- 模拟增量拉取请求，确认仅返回指定时间范围内的更新数据，无重复条目。
- 查看接口响应状态码，确认非401、500等异常状态，符合鉴权与处理逻辑。
