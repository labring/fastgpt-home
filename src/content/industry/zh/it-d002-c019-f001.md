# 众包标注人员管理的发布说明与运营报告汇总：HTTP 接口与外部系统

## 这个品类的数据长什么样
通常，该品类的数据包含人员准入规则、培训材料、绩效表、结算清单四类核心文档。数据来源包括众包平台的人员考勤与接单记录、标注质量校验数据、培训考试结果，以及财务系统的结算流水。数据更新节奏以日度和月度为主，日度数据覆盖当日人员出勤与标注进度，月度数据汇总绩效排名与结算明细。数据字段包含人员ID、接单量、标注准确率、考核得分、结算金额等，无统一强制格式，需匹配外部系统的字段映射规则。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多来源的数据需要接口支持多端点对接，分别对接众包平台、质量校验系统与财务系统，需配置不同的鉴权规则。日度、月度的更新节奏要求接口支持定时触发与手动触发两种调用模式，平衡数据时效性与系统负载。字段无统一格式的特点，要求接口返回的内容支持自定义字段映射，适配不同企业的人员管理文档结构。同时，结算核对与质量排名的高耗时需求，要求接口单次返回的数据量需适配批量处理场景，避免请求超时引发结算错误或项目延期。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 按对接系统类型配置 Bearer 或 Basic 鉴权，有效期设为 7 天 | 适配众包平台、财务系统等不同外部系统的鉴权规则，避免频繁刷新密钥 |
| 接口调用频率 | 日度任务每 2 小时触发一次，月度任务每月 1 日触发 | 匹配数据日度、月度的更新节奏，平衡数据时效性与系统负载 |
| `responseData` | 开启自定义字段映射，保留人员ID、准确率、结算金额等核心字段 | 适配品类内多格式的文档数据，无需强制统一外部系统的字段结构 |
| 单次请求数据量 | 限制为 1000 条/次 | 避免单次请求超时，适配批量人员数据的同步需求 |
| `variables` | 配置项目ID、结算周期等全局变量 | 简化多项目下的接口调用配置，减少重复参数输入 |

## 容易做错的三处
- 调用接口后返回字段为空，现象为接口响应的`responseData`中无人员绩效数据。原因是未开启自定义字段映射，仅保留了默认字段，未匹配品类内的核心数据字段。
- 接口调用频繁触发超时，现象为返回状态码 504 或请求超时提示。原因是单次请求的数据量超过系统承载上限，未按要求限制为 1000 条/次。
- 鉴权失败导致接口无法调用，现象为返回状态码 401。原因是未按对接系统类型配置`Authorization`参数，使用了错误的鉴权方式或过期的密钥。

## 怎么确认配好了
- 调用测试接口，检查返回的`responseData`是否包含品类内的核心字段，如人员ID、标注准确率、结算金额。
- 配置定时触发任务，查看调度日志确认接口按设定的频率触发，匹配数据的更新节奏。
- 模拟鉴权失败的请求，确认接口返回正确的 401 状态码，验证鉴权配置生效。
- 调整单次请求数据量，测试批量数据的同步情况，确认无超时或截断问题。
