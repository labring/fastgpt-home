# 众包标注人员管理的发布说明与运营报告汇总：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自众包平台后台、标注质量抽检记录、标注人员培训考试结果、财务结算系统。日常产出的文档包含人员准入规则、岗前培训材料、月度绩效表、季度结算清单。数据更新节奏以日度和月度为主，核心字段包含标注人员ID、准入审核状态、培训考核得分、单量完成率、质量合格率、结算金额等。不同于文本标注项目的单条数据处理，该品类聚焦于标注人员的人力组织与绩效结算相关数据，无统一的固定字段格式。

## 这些特征在「定时任务与自动化」这一环带来什么约束
该品类的数据来源分散且更新节奏不同，会要求定时任务匹配各数据源的更新周期，避免拉取未完成的临时数据。不同类型文档的字段结构差异较大，自动化汇总流程需要针对人员准入规则、绩效表、结算清单分别配置解析逻辑，防止字段匹配错误。日度数据的汇总任务适合在非业务高峰时段触发，月度结算类任务则需在财务系统结账后执行，否则会拉取到未确认的临时数据。同时，涉及结算的任务失败会直接影响人员薪酬发放，需要配置明确的重试机制与异常告警规则，避免因单次异常导致整体结算流程延误。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 任务触发时段 | 日度任务设为`02:00-04:00`，月度任务设为每月1日`01:00` | 避开业务高峰，避免影响标注人员接单与平台日常运营 |
| 数据源拉取间隔 | 日度质量数据拉取间隔设为`1800 秒`，月度结算数据拉取间隔设为`86400 秒` | 匹配各数据的更新频率，避免重复拉取浪费系统资源 |
| 文档解析模板 | 为人员准入规则、绩效表、结算清单分别配置专属解析模板 | 适配不同文档的字段结构差异，提升汇总结果的准确性 |
| 失败重试次数 | 设为`3 次`，重试间隔设为`300 秒` | 应对临时网络波动或系统短暂卡顿，减少任务失败概率 |
| 异常告警触发阈值 | 任务失败率超过`10%`时触发告警 | 及时发现系统性异常，避免汇总结果出现批量错误 |

## 容易做错的三处
- 现象：定时生成的标注人员绩效索引在数小时后自动消失。原因：未配置索引持久化存储路径，或任务执行时覆盖了原有索引的存储目录。
- 现象：月度结算清单的自动汇总结果中，人员结算金额字段为空。原因：未匹配财务系统的结算字段别名，导致解析流程无法正确提取目标数据。
- 现象：平台root用户密码在次日自动重置为初始值。原因：定时任务脚本中误包含了系统初始化配置的执行逻辑，未限定仅处理标注人员数据相关配置。

## 怎么确认配好了
- 手动触发一次日度汇总任务，查看任务日志中是否包含所有配置的数据源拉取记录。
- 抽取一份生成的运营报告，核对核心字段是否与原始数据源的内容一致。
- 模拟一次任务失败场景，验证是否触发预设的异常告警通知。
- 检查索引存储目录，确认生成的标注人员绩效索引未被自动覆盖或删除。
