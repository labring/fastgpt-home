# 供应商与设备到货管理的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的典型业务主体为项目采购、集成商商务、仓储管理员，日常处理的文档包含采购订单、到货验收单、序列号清单、发票资料。数据来源一般为ERP系统、供应商发货单、物流跟踪信息、设备厂商后台管理系统。数据更新节奏按单或按周更新，单条数据包含采购单号、设备型号、序列号、到货日期、验收状态等字段，部分文档附带物流单号、金额等信息。

## 这些特征在「上下文与 token」这一环带来什么约束
按单/周的更新节奏要求上下文需绑定单批次到货项目的关联数据，避免跨项目的冗余召回。多源数据的字段差异，需要上下文匹配时优先关联同一采购单号的所有文档，防止跨来源的信息错位。单条数据包含型号、序列号等短字段，同时存在10000+行的批量Excel数据，若分块过大则会引入无关字段消耗token，分块过小则会割裂设备型号与序列号的关联关系。同时，物流信息与到货验收单的强绑定关系，要求上下文召回时需保留关联文档的完整关联逻辑，避免召回片段丢失关键业务关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | 8000–12000 token | 符合FastGPT v4.17.0版本的上下文承载上限，该品类单批次到货数据包含多份关联文档，总token量通常在该区间内，避免超出模型限制。 |
| `quoteMaxToken` | 300–500 字符 | 单条业务数据（如设备型号+序列号组合）通常不超过500字符，该取值可保留完整业务关联，同时控制单片段token消耗。 |
| 分块长度 | 200–300 字符 | 适配10000+行的批量Excel数据，平衡召回精度与token消耗，避免拆分关键业务关联字段。 |
| 单次搜索上限 | 前6条 | 单批次到货数据通常关联6份以内的核心文档，召回过多会增加无效token消耗，该取值可覆盖全量关联数据。 |

## 容易做错的三处
- 现象：控制台提示Reached the max retries per request limit，或单轮对话token消耗超出接口额度限制。原因：未调整`quoteMaxToken`的取值，默认参数下单条召回片段过长，单批次数据的token总量超出模型与接口限制，触发重试上限。
- 现象：召回结果中出现跨采购单的设备数据，字段匹配混乱。原因：未绑定采购单号作为上下文关联键，导致召回逻辑未过滤非本单的到货数据，增加无效token消耗。
- 现象：Excel数据分块后出现序列号与型号分离的情况，无法直接关联核对。原因：分块长度设置过大，将同一设备的型号、序列号拆分到不同片段，导致上下文召回时丢失关联关系。

## 怎么确认配好了
- 上传单批次的到货数据文档，查看上下文召回预览，确认召回片段均属于同一采购单号。
- 运行批量测试，统计单轮对话的token消耗，调整`maxContext`或`quoteMaxToken`的取值至符合业务数据量的区间。
- 触发重试逻辑，检查是否出现max retries报错，确认参数设置未超出模型与接口限制。
- 查看分块后的文档片段，确认型号与序列号在同一块内，未被拆分。
