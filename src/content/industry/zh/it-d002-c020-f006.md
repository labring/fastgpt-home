# 供应商与设备到货管理的发布说明与运营报告汇总：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自ERP系统、供应商发货单、物流追踪信息及设备厂商后台。日常涉及的文档包括采购订单、到货验收单、序列号清单与发票资料。数据更新以单订单为基础单元，部分批量采购场景按周同步更新。数据字段包含采购单号、供应商主体信息、设备型号与序列号、到货时间、验收状态、发票关联编号等，无统一固定单位，随设备品类与采购要求变化。

## 这些特征在「定时任务与自动化」这一环带来什么约束
多源数据分散的特征要求定时任务需适配不同系统的接口调用频率，避免触发限流限制。按单或周更新的节奏，使得任务触发周期需匹配采购与到货的实际流转节奏，避免无效重复执行或数据滞后。不同文档的字段结构差异，要求自动化汇总流程需配置针对性的字段映射规则，适配采购订单、验收单等不同文档的校验逻辑。数据关联的强业务属性，使得任务执行失败后需触发明确的告警与重试机制，防止因数据错配导致项目延期或账实不符。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 任务触发周期 | 按单采购设为`15 分钟`，批量采购设为`1 天` | 适配单订单实时性与批量采购的周更新节奏，避免频繁调用外部接口 |
| 数据源拉取范围 | 仅拉取待验收/待汇总的订单数据 | 减少无效数据处理，匹配该品类按单更新的特征 |
| 字段校验规则 | 按文档类型配置对应校验项 | 适配采购订单、序列号清单等不同文档的字段差异 |
| 失败重试次数 | `3 次`，重试间隔`60 秒` | 应对临时接口波动，避免单次失败导致任务中断 |
| 汇总报告输出格式 | 支持PDF与结构化表格 | 适配商务、仓储等不同角色的查看需求 |
| 告警触发阈值 | 任务连续失败`2 次`触发告警 | 及时通知相关人员处理异常，防止业务延误 |

## 容易做错的三处
- 现象：定时任务执行后出现「字段为空」的报错日志，汇总报告缺失设备序列号信息。原因：未配置序列号清单的字段映射规则，未校验该文档的必填字段完整性。
- 现象：批量采购场景下任务执行超时，返回状态码504。原因：任务触发周期设置过短，同时拉取了全量历史订单数据，超出接口调用限制。
- 现象：工作流中配置自动触发汇总任务时，未绑定对应订单的数据源，导致任务无数据可处理。原因：未将工作流触发节点与数据源拉取节点正确关联，未配置订单ID的传递规则。

## 怎么确认配好了
- 手动触发一次测试任务，核对输出的汇总报告是否包含当前测试订单的所有必填字段，包括采购单号、设备型号与序列号。
- 查看任务日志，确认触发周期符合配置要求，无频繁重复执行或长时间未执行的异常。
- 模拟一次数据源接口异常，确认任务触发失败告警的逻辑正常生效，告警信息包含异常订单编号与错误类型。
- 检查不同文档类型的字段映射配置，确认采购订单与到货验收单的关联字段已正确绑定。
