# 供应链安全与开源依赖治理的发布说明与运营报告汇总：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据主要来自包管理器、代码仓库、漏洞库与许可证数据库。日常产出的文档包含SBOM清单、依赖风险报告、许可证清单与修复工单，单份文档包含组件名称、版本号、漏洞编号、许可证类型、修复优先级等字段。数据更新节奏为每日同步或每版本发布后更新，覆盖项目中所有第三方依赖的全生命周期信息。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的数据来源分散且更新节奏差异明显，要求HTTP接口支持多数据源的鉴权与数据拉取适配。不同文档的字段结构差异较大，接口需支持按文档类型返回标准化的响应字段，避免字段缺失或格式混乱。高频更新的依赖数据要求接口配置合理的超时与重试机制，防止因数据拉取延迟导致治理流程阻塞。同时，接口需兼容批量拉取与单条查询两种模式，适配不同规模的依赖资产识别需求。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的接口规范制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | 携带Bearer格式的令牌，取值为平台分配的API密钥 | 符合开源治理工具的通用鉴权规范，保障数据拉取安全 |
| `variables` | 配置依赖组件名称、漏洞库ID、项目标识等固定参数 | 减少重复请求内容，提升接口调用效率 |
| `responseData` | 按SBOM、风险报告、许可证清单三种类型返回结构化字段 | 统一不同文档类型的输出格式，便于下游系统解析 |
| 拉取间隔 | 300–600 秒 | 适配每日更新的依赖数据同步节奏，避免过度请求数据源 |
| 批量拉取上限 | 前 200 条 | 匹配SBOM清单的单页数据规模，防止接口过载 |
| 重试次数 | 3 次 | 应对临时网络波动，减少因单次请求失败导致的治理流程中断 |

## 容易做错的三处
- 现象：调用接口后返回字段为空，无法获取SBOM清单数据。原因：未在`variables`参数中配置正确的依赖组件过滤条件，导致接口未匹配到目标项目的依赖数据。
- 现象：接口返回401状态码，鉴权失败。原因：`Authorization`头未携带正确的Bearer格式令牌，或使用了过期的API密钥。
- 现象：批量拉取依赖数据时返回结果条数不足。原因：批量拉取上限设置过低，未覆盖当前项目的全部依赖资产数量。

## 怎么确认配好了
- 调用接口并携带正确的`Authorization`头，检查返回的响应状态码为200。
- 查看`responseData`返回的字段是否包含组件名称、版本号等预期的依赖信息。
- 手动修改`variables`中的过滤条件，验证接口返回的结果是否随条件变化。
- 模拟临时网络中断，检查接口是否按配置的重试次数自动重试并恢复正常。
