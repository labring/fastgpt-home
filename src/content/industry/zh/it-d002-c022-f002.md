# 信创替代适配的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自企业现有IT系统清单、国产软硬件官方目录、项目测试环境与厂商公开资料。日常产出的文档包括软硬件适配清单、兼容性测试报告、系统迁移方案、问题处理台账。数据更新节奏以单个信创替代项目为周期，或按季度同步最新国产软硬件适配信息。数据字段包含软硬件型号、适配版本、测试结果、迁移步骤等，无统一固定单位，随文档类型调整。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据来源分散且结构多样，上下文召回时需同时关联存量系统信息与新国产软硬件适配数据，易出现来源混杂的问题。数据更新周期不固定，单次项目周期或季度级更新，需在上下文管理中区分新旧适配条目，避免调用过时信息。不同文档的内容长度差异较大，从适配清单的短条目到迁移方案的长文本，token拆分与拼接需适配不同内容体量，防止上下文溢出或关键信息截断。同时，适配失误会导致业务系统不可用，因此上下文与token的配置需兼顾召回完整性与稳定性。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | 不超过12000 token | 适配类文档多为结构化与半结构化混合，需覆盖主要适配条目且避免上下文溢出 |
| `quoteMaxToken` | 单条召回内容不超过2000 token | 适配清单、测试报告等单条内容长度多在1000-1800 token区间，预留冗余空间 |
| 上下文召回条数上限 | 前8条 | 信创替代适配的核心数据条目集中，过多召回会增加token消耗 |
| 关键词拆分开关 | 保留完整字段不拆分 | 适配清单中的硬件型号、版本号为不可拆分的关键信息，拆分后会影响检索匹配 |
| 上下文更新优先级 | 按更新时间倒序排列 | 数据更新周期为项目级或季度级，优先调用最新的适配信息 |

## 容易做错的三处
- 现象为连续对话中无法关联前序的适配问题，原因是未开启上下文会话存储，或`maxContext`参数设置过低导致前序对话内容被自动清理。
- 现象为系统自动拆分适配清单中的硬件型号关键词，导致检索时无法匹配完整型号，原因是未关闭自动关键词拆分功能，或未指定保留完整字段的配置。
- 现象为配置后出现上下文截断，部分适配条目未被召回，原因是误将`quoteMaxToken`作为全局上下文上限，未正确调整`maxContext`参数。

## 怎么确认配好了
- 上传一份适配清单文档，查看系统拆分的token数量，确认单条内容未超过`quoteMaxToken`的设置值。
- 发起连续对话，输入前序适配问题后追加新问题，确认系统能关联前序内容完成上下文调用。
- 检索国产软硬件目录中的特定型号，确认召回的条目数量符合上下文召回条数上限的设置。
- 查看文档上传记录，确认未被自动拆分的关键字段内容完整保留。
