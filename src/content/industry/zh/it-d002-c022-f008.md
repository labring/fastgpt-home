# 信创替代适配的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来源于企业现有IT系统清单、国产软硬件官方目录、信创迁移测试环境及厂商公开资料。日常产出的文档包括软硬件适配清单、兼容性测试报告、迁移实施方案、问题整改台账。数据更新节奏为每个信创迁移项目周期或每季度一次，核心字段包含软硬件型号、版本号、适配状态、测试结论、迁移风险等级，无统一固定单位，随文档类型调整。不同于办公系统流程配置，该品类聚焦软硬件栈替换与兼容验证相关的汇总工作，无需配置通用审批流转节点。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据特征对工作流编排带来多重约束。不同于办公系统流程配置，本工作流聚焦软硬件栈替换与兼容验证相关的汇总流程，无需配置通用审批流转节点。多源异构的数据来源要求工作流配置跨系统拉取节点，适配不同接口格式的数据源。多样的文档类型需要工作流支持适配清单、测试报告、台账等不同格式的内容解析与汇总。非固定的更新节奏需支持按需触发与定时调度两种模式。无统一字段单位的特性，要求工作流添加标准化处理环节，统一数据格式与字段含义。同时需配置校验节点，拦截不符合信创适配要求的异常数据，避免后续流程出错。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按需触发 + 每12周定时触发 | 匹配该品类每项目或每季度的数据更新节奏，兼顾临时汇总与定期归档需求 |
| `variables` | `{"dataSources": ["systemInventory", "chinaSoftCatalog"], "docCategories": ["adaptList", "compatibilityReport"]}` | 适配多源数据拉取与多类型文档汇总的业务需求，FastGPT v4.17.0版本支持该参数配置 |
| `nodeId` | 24位十六进制字符ID，按实际工作流节点配置 | 精准调用指定的数据解析、格式转换节点，避免调用错误 |
| 单次拉取数据量 | 1000 条 | 适配信创适配数据的单次拉取规模，避免接口过载 |
| 数据校验规则 | 校验软硬件版本号非空、适配状态字段为「已适配/待整改/不兼容」枚举值 | 拦截不符合信创适配要求的异常数据，保障汇总结果准确性 |
| 输出格式 | 适配清单用Markdown表格、测试报告用结构化JSON | 匹配不同文档的后续使用场景，提升汇总内容可读性 |

## 容易做错的三处
- 调用工作流时返回axioserror，现象为控制台显示`ECONNABORTED`或`400 Bad Request`报错，原因是未正确配置`variables`参数或`nodeId`格式不符合要求。
- 工作流调用失败提示参数非法，现象为返回`invalid nodeId`字样，原因是传入的`nodeId`未使用24位十六进制字符格式。
- 汇总结果包含无效适配状态数据，现象为出现未定义的适配状态字段值，原因是未配置数据校验规则，导致异常数据流入汇总流程。

## 怎么确认配好了
- 核对`nodeId`是否为24位十六进制字符，可通过FastGPT v4.17.0的工作流编辑界面节点详情页获取对应ID。
- 触发一次按需运行，查看工作流日志是否成功拉取指定数据源的内容，无报错提示。
- 验证输出格式是否匹配对应文档类型的要求，例如适配清单是否生成标准Markdown表格结构。
- 模拟传入缺失版本号的测试数据，确认数据校验规则是否拦截该异常条目。
