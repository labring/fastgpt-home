# 信息流广告创意测试的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自广告投放平台、素材库、用户互动数据与转化数据，更新频率多为日度或周度。日常涉及的文档包括创意脚本、素材测试表、投放数据报告与迭代清单，核心处理对象为不同版本的创意组合测试数据、投放表现记录及优化方向。数据字段通常包含创意素材类型、投放时段、点击量、转化成本等，无固定统一的标准化字段格式，需随单次测试需求调整。

## 这些特征在「上下文与 token」这一环带来什么约束
多源分散的数据来源要求上下文整合广告平台、素材库、用户互动等多类信息，容易超出`maxContext`的承载上限。日度或周度的更新频率会让历史测试数据随时间累积，单轮汇总的上下文长度持续增长，需严格限制token占用以避免处理超时。日常文档结构灵活，长文本创意脚本、多行素材测试表会带来额外的token消耗，需针对性筛选有效信息，避免冗余内容占用过多token。同时，上下文的精准度直接影响测试结论归纳的准确性，需平衡信息完整性与token使用效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 信息流广告创意测试的汇总数据通常包含多组测试记录与历史迭代内容，该区间可覆盖常规汇总需求且避免token超标 |
| `quoteMaxToken` | `2000–3000 token` | 需优先保留核心的投放数据与创意脚本内容，限制引用token以避免上下文过载 |
| 相似度阈值 | `0.5–0.7` | 过滤低相关的历史测试记录，减少无效token占用，同时保留足够的参考信息 |
| 单次搜索上限 | 前10条 | 信息流测试的历史记录通常按投放效果排序，保留前10条可覆盖主要优化方向，避免过多条目消耗token |
| 上下文拼接规则 | 按投放时段从新到旧排序 | 最新的测试数据对当前优化更具参考价值，优先纳入可减少冗余信息的token消耗 |

## 容易做错的三处
- 现象：运行时弹出上下文token数超标的报错提示，任务终止。原因：未设置合理的`maxContext`取值，将全量历史创意脚本与投放数据纳入上下文，导致token占用超出平台限制。
- 现象：任务执行超时，无汇总结果返回。原因：`quoteMaxToken`设置过大，同时未按投放效果筛选有效数据，上下文拼接过长超出处理时限。
- 现象：引用的历史测试数据与当前创意测试无关，无法得出有效优化结论。原因：相似度阈值设置过低，引入大量低相关的冗余数据，既占用额外token又干扰核心信息判断。

## 怎么确认配好了
- 上传1-2组典型的创意测试数据与历史汇总文档，手动查看上下文拼接后的token长度，确认不超过预设的`maxContext`取值。
- 运行一次小型测试任务，检查任务执行时长是否符合预期，确认未出现超时情况。
- 随机抽取1条历史测试数据，验证系统引用的内容是否与当前测试需求相关，确认相似度阈值设置合理。
- 查看FastGPT v4.17.0的token消耗统计面板，确认每次汇总任务的token占用量在预设范围内。
