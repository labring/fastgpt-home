# 值班排班与交接的发布说明与运营报告汇总：数据库与运维

## 这个品类的数据长什么样
本品类核心数据包含值班表、交接记录、升级联系人清单、值班日报四类日常文档。数据来源为排班系统、故障工单、监控告警与组织通讯录，更新频率为日或周。值班表字段包含值班时段、责任人、联系方式；交接记录包含未结事项、待跟进告警、升级路径；升级联系人清单包含岗位、姓名、备用联系方式；值班日报包含当日告警量与处理情况。字段类型以文本、时间、联系人标识为主，无复杂数值单位。

## 这些特征在「数据库与运维」这一环带来什么约束
四类核心文档的多来源属性要求数据库支持非结构化与结构化混合存储，需建立值班责任人与组织通讯录的关联关系。日/周更新频率要求配置差异化的定时同步任务，平衡数据时效性与系统负载。未结事项、升级路径等强关联字段，需设置事务一致性保障，防止交接遗漏导致的响应延误。故障工单与监控告警的实时性需求，要求数据库连接池配置足够的并发连接，避免查询超时。值班表的时段字段需创建专用索引，加速排班冲突排查效率。联系人信息的变更需同步更新所有关联文档，避免联系方式失效引发的无人响应问题。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host]:27017/fastgpt_sre?retryWrites=true` | 存储非结构化的交接记录、值班日报，支持灵活的字段扩展与关联查询 |
| `PG_URL` | `postgresql://[username]:[password]@[host]:5432/sre_ops` | 存储结构化的值班表、升级联系人清单，保障事务一致性与关联查询效率 |
| `DB_MAX_LINK` | `15–25` | 适配批量同步任务与实时告警查询的并发需求，避免连接池耗尽 |
| `REDIS_URL` | `redis://:[password]@[host]:6379/1` | 缓存高频访问的升级联系人、值班时段数据，降低数据库查询压力 |
| 定时同步触发周期 | 10–15分钟（实时告警场景）、24小时（周度排班场景） | 匹配数据日/周的更新频率，平衡实时性与系统资源占用 |

## 容易做错的三处
- 现象：部署后无法连接本地数据库，日志返回`connection timed out`或`authentication failed`。原因：未正确配置`MONGODB_URI`或`PG_URL`的主机地址、端口或认证参数，未开放本地数据库的网络访问权限。
- 现象：批量同步排班数据时出现超时错误，查询返回结果条数不足预期。原因：未设置合理的`DB_MAX_LINK`参数，并发连接数不足导致部分查询排队超时。
- 现象：值班交接记录的未结事项字段为空，无法关联到对应故障工单。原因：未配置多表关联的外键约束，或定时同步任务周期过长导致数据未及时同步。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`、`PG_URL`、`REDIS_URL`的连通性，确认无认证或网络错误。
- 手动触发一次定时同步任务，检查值班表、交接记录的数据是否完整同步，字段无缺失。
- 查看数据库索引状态，确认值班时段、责任人字段的联合索引已创建并生效。
- 模拟排班冲突查询，验证查询响应时间符合业务需求阈值，该阈值需根据实际并发量标定。
