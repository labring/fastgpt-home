# 关卡内容制作的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
关卡内容制作的核心数据来自关卡编辑器、美术资源库、玩家测试数据与缺陷系统。日常产出的文档包含关卡设计稿、资源需求表、测试反馈单与版本提交记录。数据更新频率为周度或每版本一次，文档字段包含关卡区域编号、资源挂载路径、缺陷等级、提交时间等，部分字段对应文件大小（MB）、时间戳等单位，无统一的标准化字段格式。

## 这些特征在「工作流编排」这一环带来什么约束
品类数据来源分散且字段格式不统一，要求工作流需支持对接多类数据源节点，并通过字段映射统一数据结构。数据更新周期为周度或版本级，要求工作流触发方式需匹配该节奏，避免过度频繁拉取数据。多类型文档的混合处理，要求工作流需兼容不同格式的输入节点。出错后可能导致卡关或上线延期，要求工作流需配置失败重试与告警环节，保障流程稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 触发方式 | 按版本提交触发，每周同步一次 | 品类数据更新频率为周/每版本 |
| 变量映射配置 | 使用`variables`配置字段别名 | 不同来源文档的字段命名不一致 |
| 节点超时设置 | 600秒 | 多数据源拉取的平均耗时 |
| 失败重试策略 | 最多重试3次，间隔30秒 | 应对网络波动或数据源临时不可用 |
| 数据源关联 | 关联关卡编辑器、美术资源库、玩家测试系统 | 品类核心数据来源 |
| 节点标识配置 | 为每个环节节点配置`nodeId` | 便于工作流调试与日志追踪 |

## 容易做错的三处
- 现象：工作流导出失败，提示“字段不匹配”。原因：未使用`variables`配置跨文档字段映射，导致不同数据源的字段无法统一匹配。
- 现象：工作流运行后搜索结果未结合上下文。原因：未在工作流中配置上下文关联节点，仅单独调用搜索功能，未传入前置环节的关卡测试数据作为上下文。
- 现象：使用特定大模型时，关闭思考输出开关后仍出现包裹的思考内容。原因：未在模型节点中额外配置内容过滤规则，部分模型的原生思考输出未受全局开关控制。

## 怎么确认配好了
- 手动触发一次工作流，检查各数据源节点是否成功拉取对应文档与数据。
- 查看工作流日志，确认`variables`配置的字段映射已生效，字段名称统一。
- 验证模型输出是否过滤了思考内容，且搜索结果关联了前置环节的上下文。
- 升级至FastGPT v4.17.0后，测试多节点场景下的画布操作流畅度。
