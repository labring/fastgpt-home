# 内部网络与WiFi运维的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
该品类的数据来源包括交换机控制台、无线控制器、办公区监控系统及用户报障工单。日常产出文档包含网络拓扑图、网络变更单、设备故障记录、无线覆盖巡检表。数据字段涵盖交换机端口状态、AP信号强度、巡检执行时间、变更单号、故障定位时间等，更新节奏为每日汇总或每次网络变更后同步。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流支持对接不同协议的设备控制台与工单系统，适配结构化日志与半结构化文本的格式差异。非固定的更新节奏，需要工作流同时支持定时触发与网络变更事件触发。多样的文档类型，需要工作流内置图片转写、表格提取组件处理拓扑图与巡检表。耗时环节的自动化需求，要求工作流内置端口VLAN核对、故障点匹配的标准化节点，减少人工核对的工作量。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 定时+事件双触发 | 适配数据每日汇总与变更后同步的非固定更新节奏 |
| 循环调用阈值 | 3次，每次间隔60秒 | 匹配WiFi运维设备接口的调用频率限制，避免触发限流 |
| `variables`配置 | 按数据源类型分组存储 | 区分交换机、无线控制器、工单系统的不同数据字段 |
| `nodeId`绑定 | 与对应设备控制台节点绑定 | 精准调用指定的无线控制器或交换机数据源 |
| 文本提取组件规则 | 按字段匹配提取 | 适配巡检表、变更单的固定字段结构，提升提取准确率 |
| 超时设置 | 300秒 | 匹配设备接口的平均响应时长，避免无效等待 |

## 容易做错的三处
- 工作流循环调用HTTP接口时未配置重试次数与间隔，导致频繁触发设备接口限流，表现为接口返回429状态码。原因是未结合WiFi运维设备接口的调用限制调整参数。
- 文本内容提取组件首次配置后返回空值，删除重建相同配置后可正常提取内容。原因是首次配置时未正确绑定文档的字段映射关系，重建时自动补全了默认映射规则。
- 未明确`variables`中存储的用户问题变量名，导致对话模型无法调用报障工单的用户描述内容，部分大模型提取异常时未排查变量绑定问题。

## 怎么确认配好了
- 手动触发一次工作流，查看日志中`variables`参数是否正确加载了对应数据源的字段数据。
- 检查循环调用HTTP节点的`nodeId`是否绑定了正确的无线控制器控制台节点，确认调用地址与权限配置无误。
- 运行文本提取组件，对比提取结果与巡检表的原始字段，确认信号强度、巡检时间等字段提取完整。
- 模拟一次网络变更事件，确认工作流是否自动触发并生成汇总报告。
