# 办公系统流程配置的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的核心数据来自企业OA系统、组织架构库、内部制度文件及用户反馈，日常产出流程配置单、审批节点表、表单字段说明与变更记录四类文档。数据随流程变更实时更新，或每月集中同步一次。文档结构以流程节点、权限规则、表单字段为核心字段，包含节点审批人范围、触发条件、字段校验规则等内容，无统一固定标准格式，随企业办公系统适配调整。

## 这些特征在「上下文与 token」这一环带来什么约束
数据来源分散且格式差异较大，拼接上下文时易出现格式混乱，需针对性处理不同来源的文档结构。更新频率波动较大，临时变更的流程数据若未及时同步，会导致上下文包含过期配置规则。单份文档聚焦单一流程节点，整合多节点完整逻辑需占用较多token，需平衡上下文完整性与token占用限额。同时配置内容的准确性要求高，上下文截断或token溢出会导致审批规则丢失，引发流程异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 办公流程配置的单节点文档内容多为数百字符，整合5至8个节点的完整上下文需匹配该token限额，按FastGPT v4.17.0版本实测标定 |
| `quoteMaxToken` | 1500–2000 token | 提取审批规则、权限配置等核心引用内容时，需保证关键信息完整且不超出单段token限制 |
| 分块重叠长度 | 100–150 字符 | 流程节点间存在关联逻辑，重叠分块可避免节点关联信息被截断 |
| 单次召回上限 | 前6条 | 办公流程配置的关联文档多为同系统内的节点表、变更记录，召回过多会导致token占用过高 |
| 上下文截断策略 | 保留最新变更内容 | 流程数据更新频率高，优先保留近期生效的配置规则，避免过期信息干扰配置逻辑 |

## 容易做错的三处
- 未正确设置App/Admin服务端环境变量`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，可能出现连接超时或401未授权报错。排查项包括确认变量值未混入多余空格、不为空且与AI Proxy服务端配置一致，`AIPROXY_API_ENDPOINT`为AI Proxy服务根地址（格式如http://aiproxy:3000，不得附加/v1等路径），`AIPROXY_API_TOKEN`为AI Proxy管理员Token。
- 新增流程配置相关用户时出现E11000重复键错误，提示wisegpt集合冲突。原因是重复提交了相同的用户标识字段，未在配置中设置唯一键校验规则。
- RAG知识库分块时颗粒度过大，导致上下文token占用过高，出现结果截断或匹配失效。原因是未调整分块参数，直接使用默认值处理Excel格式的流程配置数据。

## 怎么确认配好了
- 提交一次流程变更测试，查看审批节点配置是否完整加载，无缺失或错误的权限规则。
- 检查App/Admin服务启动日志，确认服务端环境变量`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`加载正常，无启动校验失败提示。
- 随机抽取10份流程配置文档，验证分块后的上下文内容无明显截断，核心审批规则完整保留。
- 模拟用户反馈提交，确认系统可正确召回相关的变更记录与制度文件，无无关内容混入。
