# 单元测试与组件测试的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
本品类的数据来自代码仓库、测试框架报告、需求说明与接口定义，更新频率为每日或每提交一次。日常产出的文档包含测试用例、覆盖率报告、Mock说明与缺陷单，数据字段覆盖测试用例编号、执行结果、覆盖率数值、缺陷等级与关联代码路径，单位包含用例条数、代码行数、缺陷等级标识等，数据结构随团队使用的测试框架与规范略有差异。

## 这些特征在「上下文与 token」这一环带来什么约束
由于测试数据随提交或每日高频更新，上下文需支持动态拉取最新的测试文档片段，避免引用过期的测试用例或覆盖率报告。测试数据的字段关联紧密，单条缺陷单可能关联多个测试用例与代码路径，上下文需要精准匹配关联信息，防止token配额被冗余数据占用。单条测试文档体量较小但总量随提交次数累积，需限制上下文的总token配额，避免加载过多数据导致调用超时。同时，测试数据的字段类型多样，上下文需支持按特定字段筛选，确保召回的内容与当前测试任务相关。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单元测试与组件测试每日更新的测试报告、用例数据总量，避免token溢出，基于FastGPT v4.17.0版本的上下文处理逻辑 |
| `quoteMaxToken` | 1500–2000 token | 限制单条引用的测试文档片段长度，防止单条缺陷单或覆盖率报告占用过多token配额 |
| 上下文刷新间隔 | 每提交或1天 | 匹配测试数据的更新频率，确保调用时加载最新的测试用例与覆盖率报告 |
| 召回匹配阈值 | 0.75–0.85 | 精准筛选关联的代码路径、测试用例与缺陷信息，减少冗余数据加载 |

## 容易做错的三处
- 调用工作流API时返回的上下文字段为空，现象是接口响应中context字段无测试用例或覆盖率报告内容，原因是未在工作流中绑定测试数据的数据源，导致未拉取关联的测试文档。
- 查询积分消耗时返回403状态码，现象是接口返回权限不足提示，原因是使用的token未配置访问积分文档的权限范围，无法获取消耗明细。
- 测试报告召回结果条数异常，现象是返回的测试用例数量远少于实际提交的数量，原因是未正确设置召回匹配阈值，过滤掉了符合条件的测试数据。

## 怎么确认配好了
- 发起一次测试数据的上下文调用，核对返回的context字段是否包含测试用例、覆盖率报告等目标文档内容。
- 进入FastGPT的配置界面，确认`maxContext`与`quoteMaxToken`的取值与预设配置一致。
- 提交一次新的测试代码，检查上下文是否自动更新为最新的测试文档数据。
- 调用关联接口，检查返回的状态码与提示符合预期，无异常报错。
