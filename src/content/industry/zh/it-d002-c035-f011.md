# 单元测试与组件测试的发布说明与运营报告汇总：数据库与运维

## 这个品类的数据长什么样
这个品类的数据主要来自代码仓库的单元测试与组件测试代码、测试框架生成的覆盖率报告、需求文档中的接口定义，以及配套的测试用例、Mock说明与缺陷单。数据更新节奏为每日或每次代码提交后，由测试工程师或自动化脚本生成。数据字段包含测试用例ID、覆盖范围、Mock配置项、缺陷状态与修复记录，无统一固定单位，随具体测试场景调整，整体数据体量随项目规模与提交频率波动。

## 这些特征在「数据库与运维」这一环带来什么约束
该品类的数据更新频率高且随代码提交波动，要求数据库连接池需适配突发读写请求，避免连接耗尽导致测试构建阻塞。多来源的数据需要区分读写权限，隔离测试数据与生产业务数据，防止测试配置或缺陷数据污染生产环境。测试用例与缺陷单的关联数据需建立索引，提升失败用例定位的查询效率，同时需定期清理过期的测试报告数据，避免存储资源冗余占用。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://fastgpt-test:test-pass@mongodb-test-host:27017/fastgpt-test-db?authSource=admin` | 用于存储单元测试报告、Mock配置与缺陷单数据，需指定专属测试数据库与认证用户，隔离生产环境 |
| `PG_URL` | `postgresql://test-user:test-pass@pg-test-host:5432/fastgpt-test-meta` | 存储结构化的测试用例元数据与覆盖率统计数据，使用PostgreSQL保障关联查询性能 |
| `DB_MAX_LINK` | `100–150` | 适配每日数百次代码提交带来的并发读写请求，避免连接耗尽导致测试构建阻塞 |
| `REDIS_URL` | `redis://redis-test-host:6379/1` | 缓存高频查询的测试用例ID与覆盖率统计结果，降低数据库读写压力 |

## 容易做错的三处
- 部署本地开发环境时出现MongoDB连接超时，pnpm dev命令显示连接超时。原因是未正确配置`MONGODB_URI`的主机地址与端口，或测试数据库未启动。
- 调用MySQL数据库工具时返回400状态码且无响应体。原因是未正确配置对应数据库连接参数，或数据库用户未授予测试场景的读写权限。
- 无法在MongoDB中添加专属测试用户并正常登录。原因是未使用正确的MongoDB创建用户命令，或未指定正确的认证数据库。

## 怎么确认配好了
- 执行本地测试命令，查看控制台输出是否显示数据库连接成功的日志。
- 提交一次测试代码，查看测试框架是否能正常生成覆盖率报告并写入对应数据库。
- 使用指定的数据库用户登录MongoDB或PostgreSQL，验证是否能读取测试用例与缺陷单数据。
- 查看Redis缓存的监控指标，确认高频查询的测试数据被正确缓存。
