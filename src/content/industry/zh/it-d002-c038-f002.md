# 变更管理与发布窗口的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的数据来源为变更管理系统、CI流水线、监控数据与业务日历，日常文档包含变更申请、风险评估、上线窗口计划、回退方案。数据更新频率为周度或单次变更完成后，文档字段包含变更ID、上线窗口时段、风险评级、审批状态、回退触发条件等，其中时段字段以小时为单位，风险评级为标准化枚举值，变更ID为字符串格式。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的文档多为结构化运维记录，批量汇总时会产生较大的token消耗。数据更新频率不固定，需确保上下文始终包含最新的上线窗口与变更状态。字段包含多个关键运维指标，需筛选有效内容避免无效token占用。离线部署场景下，token计算依赖无法通过联网拉取，需提前配置本地依赖。同时，变更记录的批量提交会导致上下文额度快速耗尽，需限制单批次引用的token总量，避免超出模型支持范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 变更管理与发布窗口的单条变更记录约1000-2000token，批量5条左右的变更数据总长度符合该区间，适配运维场景的批量变更汇总需求 |
| `quoteMaxToken` | `2000 token per quote` | 单条风险评估或回退方案文档的核心内容不超过2000token，避免单条引用占用过多上下文额度 |
| 上下文刷新触发规则 | 按变更触发或每7天 | 该品类数据更新频率为周度或单次变更后，按变更触发可确保上下文始终包含最新的上线窗口计划 |
| 上下文筛选匹配度 | `≥0.7` | 变更数据中存在大量重复的审批流程描述，需筛选高匹配度的有效变更记录，减少无效token占用 |
| 离线token依赖配置 | 本地部署tiktoken依赖包 | 离线服务器部署场景下无法联网拉取token计算依赖，提前配置可避免相关报错 |
| 工作流token传递配置 | 绑定变更ID作为传递参数 | 变更管理场景下，变更ID可作为唯一标识传递给外部接口，用于关联对应变更的运营数据 |

## 容易做错的三处
- 界面显示最大上下文token设置后仍出现上下文溢出报错，原因是未考虑批量变更记录的总token消耗，仅单条设置了`maxContext`但未限制批量引用的总额度。
- 离线部署时出现get tiktoken dial tcp报错，原因是未提前配置本地tiktoken依赖包，尝试联网拉取依赖失败。
- 配置的上下文额度低于实际需求，导致生成报告时最高上下文仅能达到6656，原因是未根据批量变更记录的总token消耗调整`maxContext`参数。

## 怎么确认配好了
- 查看FastGPT v4.17.0系统日志中token消耗记录，确认单批次变更汇总的token消耗未超过配置的`maxContext`额度。
- 在离线部署环境中手动触发变更汇总任务，检查是否出现tiktoken相关报错。
- 生成发布说明与运营报告，核对报告中包含的变更记录为最近7天或本次变更范围内的有效数据。
- 调整`quoteMaxToken`参数后，查看单条引用文档的token占用是否符合预期配置。
