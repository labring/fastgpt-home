# 变更管理与发布窗口的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
本文档基于FastGPT v4.17.0版本编写，本品类的数据来源于变更管理系统、CI流水线、监控数据、业务日历四类数据源，更新频率为周度或单次变更触发。日常生成的文档包含变更申请、风险评估、上线窗口计划、回退方案四类核心文件，字段包含变更唯一标识、申请时间、风险评级、发布窗口时段、回退触发条件等，无统一固定的统计单位，仅按业务场景记录文本、时间、数值类信息。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据来源分散且更新节奏不固定，要求工作流需支持对接多系统数据源的节点配置，同时需适配按需触发或定时触发的灵活执行规则。核心文档的固定字段结构，要求工作流节点需映射预设字段到全局变量，避免数据格式混乱。最耗时的风险评级、审批协调环节，要求工作流嵌入自动校验与审批节点，减少人工干预成本。与相邻品类的差异在于，本品类更强调生产环境风险控制，因此工作流需额外配置生产环境发布窗口的校验节点，防止非授权变更进入生产环境。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量隔离配置 | 按使用者ID隔离`variables`作用域 | 支持多使用者的变更流程数据独立存储，避免数据串扰 |
| 自定义引导语绑定 | 关联指定`nodeId`的前置文案 | 绕过系统预设的引导语，实现定制化输出 |
| 工作流超时阈值 | 600秒 | 适配变更流程的常规执行周期，防止节点挂起 |
| web窗口并发阈值 | 8核32G机器设为6个 | 匹配当前硬件的资源承载上限，避免加载阻塞 |
| 工作流触发规则 | 按变更申请提交触发 | 匹配变更管理系统的更新频率，确保数据时效性 |

## 容易做错的三处
- 现象：自定义引导语未按预期展示，仅显示系统预设的猜你想问。原因：未将定制化引导语绑定到对应`nodeId`的工作流节点，仅在全局配置了引导语内容。
- 现象：不同使用者的变更流程数据出现串扰，同名全局变量值被覆盖。原因：未开启`variables`的使用者ID隔离配置，导致全局变量作用域覆盖所有使用者。
- 现象：web窗口超过设定数量后持续处于加载状态，无法正常执行。原因：未根据服务器硬件配置调整web窗口并发阈值，超出了当前机器的资源承载上限。

## 怎么确认配好了
- 提交一次测试变更申请，查看工作流节点前是否展示定制化引导语，确认绑定`nodeId`的配置生效。
- 使用不同使用者ID登录系统，发起相同配置的变更流程，检查全局变量数据是否独立存储，未出现串扰。
- 同时打开7个及以上的工作流执行窗口，查看是否出现加载阻塞，确认并发阈值配置符合硬件要求。
- 等待变更流程执行至超时节点，查看是否在600秒内完成执行，确认超时阈值配置合理。
