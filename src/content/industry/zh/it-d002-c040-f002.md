# 售前技术方案的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
售前技术方案的数据来源包括客户访谈记录、招标文件、厂商产品资料与历史项目方案。日常产出的文档包含技术方案书、客户需求调研表、报价清单与演示脚本，文档结构通常覆盖需求匹配、技术路线、实施边界、报价明细等模块。数据更新频率按单项目进度调整，一般为每单或每周更新一次，单份文档的内容长度与模块数量随项目复杂度波动，无固定格式标准。

## 这些特征在「上下文与 token」这一环带来什么约束
数据源分散且格式不统一，导致分块时需要适配不同类型的文档内容，容易出现token消耗波动的情况。按单或每周的更新频率，要求上下文窗口能够及时容纳最新的方案内容与调整后的参数。文档模块的token占比差异较大，技术路线部分通常占用更多token，需要合理分配上下文配额以覆盖核心内容。单份文档长度波动明显，无法使用固定的上下文配置适配所有项目，需支持灵活调整参数。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 适配售前技术方案的常规总内容长度，覆盖完整的技术路线与报价明细模块 |
| `quoteMaxToken` | `1500–2000 token per quote` | 限制单条引用片段的长度，避免单个引用超出模型单段token限制 |
| 单次搜索上限 | 前6条 | 匹配售前方案参考资料的常规数量，覆盖主要历史项目与厂商资料内容 |
| 上下文重叠长度 | `200–300 字符` | 避免分块内容断裂，保证技术方案逻辑的连贯性 |
| 问题优化开关 | 开启 | 优化售前方案中模糊的需求描述，提升检索匹配的精准度 |

## 容易做错的三处
- 现象：配置分块长度时误将字符数设为token数，导致分块片段超出模型限制。原因：未明确区分FastGPT分块长度的单位，未参考官方文档的参数说明。
- 现象：上传图片时部分报错，提示token超限。原因：图片的OCR文本会被转换为token计入上下文，未限制图片OCR的最大token配额。
- 现象：设置了较大的`maxContext`仍出现上下文溢出。原因：未同步调整引用片段的`quoteMaxToken`，多个长引用片段累加超出总上下文限制。

## 怎么确认配好了
- 导入一份典型的售前技术方案文档，运行分块测试，查看分块后的片段长度是否符合预设的单位和取值区间。
- 发起一次基于历史方案的检索，核对返回的引用片段数量和长度是否符合配置的单次搜索上限与`quoteMaxToken`。
- 上传不同格式的源文件（招标文件、厂商资料、客户访谈记录），测试分块与嵌入流程是否正常，无异常报错。
- 调整`maxContext`参数，验证上下文窗口是否能容纳完整的售前方案内容，无自动截断提示。
