# 备份恢复与灾备演练的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
本品类的数据来源于备份系统、数据库日志、对象存储及灾备平台。日常产出的文档包括备份策略、恢复演练报告、灾备切换预案、数据校验记录。数据更新频率分为日、月、季三类，不同文档对应不同更新节奏。单份文档包含备份时间戳、恢复点标识、演练执行状态、数据校验结果等字段，字段以时间戳、状态码、数值型参数为主要单位，无额外自定义统计字段。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类的多源数据与分层更新节奏，对上下文与token处理带来多重约束。多源异构的文档格式需要统一预处理，避免无效token占用额度。不同更新频率的文档需要设置差异化的加载优先级，日更的备份日志需优先纳入上下文，季更的预案可作为补充项。单份文档的字段数量较多，直接全量导入会超出大模型token上限，需要精准筛选与灾备演练、发布说明相关的字段。此外，不同场景下的token消耗差异较大，恢复点确认环节的上下文需预留更多token空间，以承载完整的校验数据。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配本品类核心文档的平均token消耗，避免超出大模型上下文上限 |
| `quoteMaxToken` | 2000–3000 token | 限制单份引用文档的token占用，防止单条数据过度挤占上下文空间 |
| 单次搜索上限 | 前6条 | 匹配本品类日常文档的平均召回数量，避免冗余数据干扰 |
| 重排开关 | 开启 | 优先筛选与灾备演练、发布说明强相关的上下文内容 |
| 最大上下文时长 | 7天 | 聚焦近期的备份日志与演练报告，过滤过期的历史数据 |

## 容易做错的三处
- 现象：配置`quoteMaxToken`为3000 token以上时，知识库上下文预览显示为空，大模型接收不到上下文内容。原因：超出配置的单条引用token上限，系统自动过滤了超量的上下文数据。
- 现象：离线部署token服务后，调用相关接口时出现cl100k.tiktoken请求失败的报错。原因：未配置本地token模型文件，系统默认尝试请求外网资源，导致离线环境下调用失败。
- 现象：查询灾备演练的发布说明时，召回的文档包含超出更新频率范围的历史记录。原因：未设置按更新时间筛选上下文的规则，召回了过期的历史文档。

## 怎么确认配好了
- 查看知识库的上下文预览界面，确认召回的文档类型与灾备演练、发布说明相关，可根据业务场景调整筛选规则。
- 发起模拟查询，查看大模型返回结果是否包含备份策略、演练报告的核心字段，可根据返回内容调整token配置参数。
- 检查系统运行日志，确认未出现token请求失败、上下文截断的报错信息，可根据报错提示优化配置。
- 模拟不同业务场景的查询，确认召回的上下文匹配当前场景需求，可根据场景调整上下文加载规则。
