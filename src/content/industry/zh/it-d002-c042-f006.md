# 备份恢复与灾备演练的发布说明与运营报告汇总：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据来源于备份系统、数据库日志、对象存储、灾备平台四类核心数据源。日常生成的文档包括备份策略、恢复演练报告、灾备切换预案、数据校验记录四类，每类文档包含固定字段：备份任务ID、恢复点目标（RTO）、恢复点目标（RPO）、校验结果、执行时间戳，字段单位分别为字符串、秒、秒、布尔值、时间戳。数据更新频率分为日、月、季三类，对应日常巡检、月度演练、季度合规校验三类业务场景。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据来自多系统异构数据源，定时任务需要支持跨平台数据拉取与格式统一，否则会出现字段缺失或格式混乱，无法生成符合业务要求的汇总报告。不同更新频率要求任务调度支持灵活的周期配置，无法仅用单一周期覆盖日常巡检、月度演练、季度合规校验三类业务场景。四类文档的固定字段要求汇总逻辑需按文档类型分类，否则运营报告无法满足运维团队、数据库管理员、业务连续性负责人的查看需求。最耗时的恢复点确认、演练脚本执行、数据一致性核验环节，要求定时任务设置合理的超时与重试机制，避免任务无限阻塞占用系统资源。严重的出错后果要求任务失败后触发实时告警，保障业务连续性负责人及时介入处理，避免数据丢失、恢复超时等问题扩大。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务调度周期 | 日任务设`23:00`，月任务设每月1日`02:00`，季任务设每季度首月1日`01:00` | 匹配备份巡检、月度演练、季度合规校验的业务更新频率 |
| 数据源拉取超时时间 | `300 秒` | 覆盖跨备份系统、数据库、对象存储三类数据源的平均拉取耗时 |
| 失败重试次数 | `2 次` | 过滤偶发网络异常，避免重复执行影响业务正常运行 |
| 运营报告生成时机 | 灾备演练完成后`10 分钟`内 | 保障演练结果及时汇总，满足运维团队的即时查看需求 |
| 告警触发阈值 | 连续`2 次`执行失败 | 避免因单次偶发异常触发无效告警 |
| 校验结果同步间隔 | `60 秒` | 平衡数据实时性与系统资源占用 |

## 容易做错的三处
- 现象是灾备演练报告生成后无法自动复制或下载，提示“无法使用浏览器自动复制，请手动复制下面内容”，原因是未在FastGPT v4.17.0中配置跨域资源共享规则，导致前端无法直接拉取后端生成的报告文件。
- 现象是定时任务执行后恢复演练报告字段为空，原因是未配置对应数据源的访问权限，导致无法拉取数据库日志与备份系统的核心数据。
- 现象是灾备演练汇总任务超时，报错`ETIMEDOUT`，原因是数据源拉取超时时间设置过短，未覆盖跨系统拉取的最大耗时。

## 怎么确认配好了
- 手动触发一次日级定时任务，核对拉取的备份系统数据与数据库日志是否与本地存储的原始数据一致。
- 查看任务调度日志，确认任务按预设的周期与时间点执行，无延迟或跳过情况。
- 模拟一次任务失败场景，确认告警通知是否按配置的阈值触发并推送给相关负责人。
- 检查生成的运营报告，确认文档分类与字段符合备份策略、恢复演练报告等四类业务文档的规范。
