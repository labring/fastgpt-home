# 安全培训与钓鱼演练的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的核心数据来自员工通讯录、邮件网关、内部培训平台与点击统计系统，日常产出的文档包含标准化培训课件、季度/年度演练方案、钓鱼邮件模板及演练结果报告。数据更新以季度或年度为周期，单份文档包含演练人群范围、邮件触达记录、员工点击反馈、整改建议等字段，无统一固定单位，随文档类型调整。该品类聚焦人员安全意识与行为的培训演练，与侧重系统配置检查的安全基线检查品类存在明显差异。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的文档多为非结构化的培训内容与半结构化的演练报告，数据来源分散导致上下文拼接时易混入无关字段。季/年度的更新频率意味着单次需加载的历史数据量较大，容易超出token限制。演练结果报告中的点击统计、人群标签等字段若未筛选，会占用过多上下文空间，导致核心的演练复盘内容被截断。同时钓鱼邮件模板的格式要求会影响上下文的规整性，增加token消耗的不可控性。本文基于FastGPT v4.17.0版本编写。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配季/年度汇总的多文档拼接需求，避免核心复盘内容被截断 |
| `quoteMaxToken` | 1500–2000 字符 | 匹配钓鱼邮件模板与演练报告的单段内容长度，精准召回相关片段 |
| 单次召回条数 | 前6条 | 控制上下文总token消耗，避免因召回过多非核心数据超出限制 |
| 上下文筛选规则 | 按演练周期与人群标签过滤 | 减少无关数据占用的token空间，聚焦当前培训与演练的核心内容 |
| 内容截断阈值 | 按实测标定 | 适配不同规模的演练报告数据，避免关键信息丢失 |

## 容易做错的三处
- 界面展示内容被截断，仅显示`...[hide 38432 char]`。原因是未设置合理的`maxContext`参数，导致汇总的多份演练报告与培训课件超出上下文token上限，系统自动截断尾部内容。
- 启动时报错`failed to get gpt-3.5-turbo token encoder`。原因是未正确配置上下文的token编码规则，或引用的外部token服务未完成授权校验。
- 问答响应耗时过长且token消耗过高。原因是未对召回的上下文数据按演练人群、周期进行过滤，导致大量无关的历史培训数据被纳入上下文，额外占用token资源。

## 怎么确认配好了
- 导入一份完整的年度演练结果报告，检查上下文预览是否包含所有核心字段，无提前截断现象。
- 触发一次钓鱼邮件模板的内容汇总，核对召回的片段是否与当前演练场景强相关，无无关数据混入。
- 查看token消耗统计，确认单轮汇总的token值处于预设的合理区间，无异常飙升。
- 模拟异常场景，如导入超出常规规模的培训课件，检查系统是否按配置触发合理的截断或过滤逻辑。
