# 安全基线检查的发布说明与运营报告汇总：HTTP 接口与外部系统

## 这个品类的数据长什么样
安全基线检查的数据来源于服务器配置、中间件配置、安全设备策略及专用基线工具，更新频率为月或季。日常产出的文档包含基线检查表、配置核查记录、整改建议与例外审批单，核心字段包括配置项ID、合规状态、整改时限、例外原因等，单份报告的配置条目数量为数十至数百条，无固定统一的单份数据总量上限。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
由于数据来源分散，需对接多类外部系统的HTTP接口拉取配置与核查结果，因此接口需要支持多源认证与数据聚合。更新频率较低但需保障数据同步的稳定性，接口需具备重试与错误上报能力。文档结构固定，接口返回格式需匹配基线检查的标准字段定义，避免冗余或缺失字段影响后续汇总。此外，基线检查数据的合规性要求较高，接口需严格校验调用权限，防止未授权访问导致敏感配置信息泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `Authorization` | 格式为`Bearer {token}`，有效期不超过7天 | 用于接口身份校验，符合安全基线检查数据的访问权限要求 |
| `variables` | 将基线检查实例与报告类型作为业务输入，字段名称和枚举按外部接口文档配置 | 用于限定查询范围；这些是业务输入，不是 FastGPT 内置参数 |
| `responseData` | 读取外部接口实际返回的检查条目、合规状态和异常原因 | 按接口文档确认响应层级，再把所需业务字段映射至后续节点 |
| 请求超时时间 | 30-60秒 | 适配基线数据同步的平均耗时，避免因数据量波动导致超时 |
| 重试次数 | 2-3次 | 应对临时的网络波动或外部系统接口抖动，保障数据拉取成功率 |

## 容易做错的三处
- 调用后收到 HTML 页面，后续节点无法按 JSON 解析。先核对 HTTP 状态码、最终 URL 和响应内容类型，再检查是否进入登录或错误页面；不能仅据响应格式断言证书或鉴权配置原因。
- 现象：拉取的基线数据字段缺失或顺序混乱。原因：未通过`responseData`参数指定需要返回的字段，或`variables`参数的取值不符合业务定义的枚举范围。
- 现象：接口调用频繁触发超时。原因：未合理设置请求超时时间，或同时拉取了过多历史基线检查数据超出接口承载能力。

## 怎么确认配好了
- 使用curl命令发起接口请求，检查返回的`Content-Type`头为`application/json`，且无HTML标签。
- 对照外部接口文档与本地基线检查表，逐项核对检查条目字段的实际名称、层级和数量，再确认下游映射。
- 模拟外部系统接口异常，验证接口会触发预设的重试机制并在重试失败后记录错误日志。
- 查看FastGPT v4.17.0的系统日志，确认无未授权访问或参数校验失败的报错记录。
