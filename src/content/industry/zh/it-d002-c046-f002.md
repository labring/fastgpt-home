# 安全基线检查的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
本品类数据来自服务器配置、中间件配置、安全设备策略及基线工具输出。日常产出基线检查表、配置核查记录、整改建议、例外审批单四类文档，文档字段包含配置项编号、当前配置值、合规状态、整改建议、审批状态等。数据更新周期为月或季度，核心处理环节需核对大量配置项、确认例外原因及复核整改结果，关联的上下文多为结构化配置记录与非结构化审批文档。

## 这些特征在「上下文与 token」这一环带来什么约束
结构化的配置记录与非结构化审批文档混合的数据源，要求上下文召回需兼顾字段匹配与语义关联；月/季级的更新频率意味着上下文缓存无需高频刷新，但需支持跨周期的历史配置对比；大量配置项的核对需求会导致单轮对话的token消耗较高，需限制上下文召回的长度与数量；例外审批单的非结构化内容易导致上下文冗余，需精准筛选有效关联信息，避免token超标影响对话效率。

## 配置怎么定
本配置说明适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文条数 | 前10–15条 | 匹配安全基线检查的月度/季度更新周期，避免召回过多历史配置记录导致token超标 |
| `maxContext` | 8000–12000 token | 适配单轮对话中多份配置核查记录与整改建议的拼接需求，覆盖典型场景的token消耗 |
| 上下文召回token上限 | 3000–5000 字符 | 限制单轮召回的非结构化文档长度，避免例外审批单的冗余内容占用过多token |
| `quoteMaxToken` | 2000 token | 精准限定单条引用文档的token占比，确保整体上下文不超出大模型支持范围 |
| 上下文召回数量上限 | 前8–12条历史会话 | 匹配安全基线检查的单次核查规模，避免过多历史记录干扰当前配置核对 |

## 容易做错的三处
- 对话明细中仅显示少量上下文，无法关联回复内容。原因是`maxContext`参数设置过低，或上下文召回阈值过高，未正确召回历史配置核查记录。
- 大模型提示上下文token数超标。原因是未限制`quoteMaxToken`或上下文召回总长度，拼接的配置文档与审批单总token超出大模型承载上限。
- 超长任务执行超时。原因是未拆分多份基线文档的上下文召回，单轮处理的token与上下文总量过大，超出接口响应时限。

## 怎么确认配好了
- 查看应用的上下文配置面板，确认`maxContext`与`quoteMaxToken`的取值符合预设范围。
- 发起包含多份历史基线核查记录的测试对话，检查对话明细中展示的上下文条数与配置一致。
- 输入包含多段基线配置内容的测试任务，观察是否出现token超标提示或超时报错，调整配置至无异常。
- 统计单轮对话中引用的基线文档token占比，确保未超出预设的上下文token上限。
