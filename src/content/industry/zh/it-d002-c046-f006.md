# 安全基线检查的发布说明与运营报告汇总：定时任务与自动化

## 这个品类的数据长什么样
本品类的数据主要来自服务器基础配置、中间件运行参数、安全设备访问策略及专用基线检查工具。日常产出的文档包括标准化基线检查表、单次核查的配置记录、整改建议单与例外审批单。数据更新周期为月度或季度，核心字段包含基线项唯一标识、当前配置值、核查结果、整改状态、审批人及审批时间，无额外统计类百分比字段。本品类与漏洞扫描服务存在差异，核心关注配置是否符合组织安全基准，聚焦配置合规性检查。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据来源覆盖多类异构系统，定时任务需支持跨源拉取配置数据，避免手动导入的误差。月度/季度的更新周期决定了任务执行频率不宜过高，否则会占用过多运维资源。标准化的文档字段要求自动化汇总工具需严格匹配字段映射规则，确保输出的运营报告格式统一。而配置核对、例外原因确认、整改结果复核等耗时环节，需通过自动化脚本自动拉取例外审批单关联数据，减少人工介入步骤，同时需支持对未关联数据的告警提醒，避免遗漏例外项导致的风险累积。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务执行周期 | 每月1次，或每季度1次 | 匹配数据月度/季度更新的频率，避免不必要的资源占用 |
| 数据源拉取超时阈值 | 300-600秒 | 适配多源异构数据的拉取时长，防止单次任务因网络波动阻塞 |
| 例外数据自动匹配规则 | 按实测标定 | 适配不同组织的例外审批单字段差异，避免误匹配或遗漏 |
| 报告生成格式 | 标准化PDF或结构化Excel | 匹配日常运维文档的通用格式，便于存档与复核 |
| 失败重试次数 | 2次 | 应对临时网络波动或数据源临时不可用的情况，减少任务中断 |
| 任务告警触发条件 | 连续2次执行失败 | 及时通知运维人员处理异常，避免问题累积 |

## 容易做错的三处
- 现象：定时任务执行后生成的运营报告中配置项字段为空。原因：未正确配置数据源与报告字段的映射规则，导致拉取的数据无法匹配文档预设字段。
- 现象：任务执行超时后直接终止，未触发重试机制。原因：未设置失败重试次数或阈值设置过低，无法应对临时的网络波动或数据源临时故障。
- 现象：月度任务执行后出现大量未关联的例外审批单数据，最终导致弱配置长期未被整改。原因：未启用例外数据自动匹配规则，导致人工确认的例外项未被自动纳入汇总报告，引发审计不通过风险。

## 怎么确认配好了
- 确认当前使用的FastGPT版本为v4.17.0，确保定时任务模块的功能与文档一致。
- 手动触发一次测试任务，核对拉取的配置数据与实际服务器、中间件或安全设备的配置是否一致。
- 查看任务执行日志，确认数据源拉取、字段映射、报告生成各环节均无报错信息。
- 生成一份测试报告，检查报告中的字段是否与预设的基线检查表、整改建议单格式完全匹配。
- 模拟一次数据源临时不可用的场景，确认任务会触发重试机制并在数据源恢复后正常执行。
