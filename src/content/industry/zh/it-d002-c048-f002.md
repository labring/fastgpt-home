# 安全监控与SOC值守的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
本品类的数据主要来自SIEM、EDR、NDR及第三方威胁情报源，更新节奏分为实时与日更两类。日常产出的文档包含告警处置单、值班记录、威胁情报通报、日报周报，单份文档包含告警标识、触发时间、关联IP、处置状态、上报主体等字段，部分周报类文档会汇总当周告警总量、处置率等统计项。

## 这些特征在「上下文与 token」这一环带来什么约束
实时更新的告警数据要求上下文窗口可快速加载最新条目，避免遗漏刚触发的威胁信息；日更的周报类文档篇幅较长，需限制单轮上下文的token消耗，防止超出模型上限。多源异构数据的字段差异会导致上下文拼接时出现格式混乱，需提前对齐字段结构。告警处置单等短文档的高频调用，要求token分配兼顾单条文档的完整加载与多文档的批量召回，避免因token不足截断关键处置信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口 | 8000–12000 token | 适配SOC场景下多份实时告警、当日值班记录及周报的批量拼接需求，避免超出模型token上限 |
| `maxContext` | 8000–12000 token | 对应FastGPT v4.17.0版本的最大上下文窗口配置，匹配多源数据的总长度范围 |
| 引用最大token | 1500–2000 字符 | 限制单条告警或情报文档的引用长度，确保核心字段不被截断 |
| `quoteMaxToken` | 1500–2000 字符 | 对应FastGPT v4.17.0版本的引用最大token配置，适配单份文档的核心内容长度 |
| 单次召回上限 | 前10条 | 控制上下文召回的总数量，避免冗余数据占用过多token |
| 上下文排序规则 | 按告警触发时间倒序 | 确保最新触发的高优先级告警优先纳入上下文，符合SOC值守的研判逻辑 |

## 容易做错的三处
- 现象：配置自定义token后，知识库搜索与报告生成环节仍触发额外扣费。原因：未将自定义token绑定至上下文与token的配置项，导致系统调用默认授权凭证。
- 现象：内网部署后，后台服务频繁重启。原因：`maxContext`取值过大，导致单轮请求的token消耗超出内网部署的资源限制。
- 现象：告警研判时出现关键处置信息缺失。原因：`quoteMaxToken`取值过小，导致单份告警处置单被截断，丢失处置流程字段。

## 怎么确认配好了
- 查看FastGPT后台的上下文监控面板，确认单轮请求的token消耗符合配置的最大上下文窗口取值。
- 导入单份典型告警处置单，检查检索后返回的上下文是否完整加载了所有核心字段，未出现截断。
- 发起多轮连续的报告生成请求，确认服务未出现异常重启或超时报错。
- 验证自定义token的绑定配置，确认调用接口时使用的token与预设配置一致。
