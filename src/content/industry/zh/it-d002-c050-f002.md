# 客户开通与租户初始化的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
这个品类的数据主要来自CRM系统、合同订单库、身份管理系统及产品后台。日常产出的文档包含开通申请单、租户配置表、管理员账号清单与交付确认单，数据更新以每单或每日为节奏。数据字段包含租户唯一标识、开通时间节点、基础权限配置范围、初始token分配额度等，仅围绕单租户开通全流程产生，无跨租户聚合统计字段。本说明适配FastGPT v4.17.0版本。

## 这些特征在「上下文与 token」这一环带来什么约束
由于数据围绕单租户开通流程产生，且更新节奏绑定单订单或每日，上下文与token配置需适配单租户的初始权限与资源额度。数据来源分散于多系统，需确保配置参数能跨系统同步租户的token分配规则。日常文档仅包含基础配置信息，无历史上下文聚合数据，因此配置需以单租户初始token配额为基准，避免跨租户上下文混淆。同时，开通流程的高耗时环节要求配置需简化验证逻辑，减少额外token消耗的校验步骤，防止因配置复杂导致开通延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 10000–15000 token | 匹配单租户初始开通流程的基础上下文承载需求，按实测标定 |
| `quoteMaxToken` | 2000–3000 token | 限制单租户初始化阶段的知识库引用token消耗，避免超出初始配额 |
| 最大上下文刷新间隔 | 24 小时 | 匹配数据每日更新的节奏，确保租户配置同步最新规则 |
| 初始token分配上限 | 按合同约定额度 | 基于合同订单中的资源约定，贴合业务数据来源 |
| 上下文校验超时阈值 | 60 秒 | 适配单租户开通流程的耗时上限，防止校验环节阻塞开通 |

## 容易做错的三处
- 现象：租户初始化后控制台返回token校验失败，无法正常登录。原因：未按合同约定配置`maxContext`参数，导致初始token分配超出系统校验阈值。
- 现象：调用/api/core/dataset/collection/create接口时返回参数非法。原因：未同步租户配置表中的权限字段，导致接口无法识别合法租户标识。
- 现象：租户开通后聊天上下文未体现历史配置信息。原因：未设置正确的上下文刷新间隔，导致初始配置未加载到上下文缓存中。

## 怎么确认配好了
- 登录产品后台，查看租户初始token分配额度，确认与合同约定的额度一致。
- 触发单租户初始化流程，检查上下文校验环节的耗时是否符合预设的超时阈值。
- 调用对应开通接口，验证提交参数是否匹配租户配置表中的字段要求。
- 查看系统运行日志，确认无token校验失败或上下文加载异常的报错记录。
