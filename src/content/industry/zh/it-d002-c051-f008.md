# 客户数据导入迁移的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
这个品类的数据主要来自客户历史业务系统、CSV/Excel模板、数据库导出结果，更新频率为每单或不定期。日常配套文档包含数据模板、迁移方案、字段映射表、迁移验证报告，数据字段需匹配目标系统业务规则，包含客户标识、业务流水号、业务内容等核心字段，无统一固定单位，随具体业务场景变化。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且格式不统一，要求工作流需支持多格式数据接入节点，适配不同导出格式的解析规则。更新频率不固定，需支持按需触发的工作流调度，避免固定周期带来的资源浪费。配套文档依赖字段映射关系，工作流需嵌入字段校验节点，确保映射规则匹配目标系统。核心字段缺失或格式错误会导致迁移失败，工作流需配置脏数据清洗与异常拦截环节，降低出错风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 字段映射校验规则 | 按客户提供的字段映射表配置校验逻辑，匹配目标系统必填字段 | 确保导入数据符合目标系统字段要求，避免字段错位 |
| 脏数据清洗阈值 | 空值占比超过30%时触发拦截 | 过滤无效数据，减少导入失败概率 |
| 工作流触发时机 | 按`variables`中导入任务标识触发 | 匹配单任务独立执行的业务场景，支持多任务并行 |
| 导入超时设置 | 600秒 | 适配批量数据导入的处理时长，避免任务中断 |
| 异常告警节点 | 触发后推送导入日志至指定接收渠道 | 便于及时排查迁移失败原因 |
| 抽样核对节点 | 导入后抽取前100条数据进行字段校验 | 验证整体迁移准确性 |

## 容易做错的三处
- 工作流中文本提取节点未匹配到目标内容后，未配置等待用户输入的分支，直接触发结束节点。现象为工作流运行日志显示文本提取节点无匹配结果后直接结束，无兜底回复。原因是未针对提取失败场景配置兜底回复与等待逻辑，导致任务提前终止。
- 多模态数据与纯文本数据未按处理需求分流，统一调用工具调用节点。现象为工作流统一调用工具调用节点处理多模态数据，返回结果不符合预期。原因是未在工作流中配置数据类型判断分支，未区分不同数据的适配模型。
- 知识库搜索配置引用上限设置为3000，与简体应用端的配置规则不一致。现象为工作流中知识库搜索节点返回结果条数与预期不符。原因是未区分工作流与应用端的配置差异，错误复用其他场景的参数。

## 怎么确认配好了
- 上传测试用的CSV模板，触发工作流执行，查看各节点运行日志是否匹配配置的校验规则。
- 构造空值占比超过30%的测试数据，验证脏数据拦截节点是否正常触发告警。
- 配置`variables`中的导入任务标识，触发工作流，确认触发时机符合预期。
- 导入后抽取部分数据，核对字段映射是否与预设规则一致。
