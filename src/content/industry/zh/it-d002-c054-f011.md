# 容器平台运维的发布说明与运营报告汇总：数据库与运维

## 这个品类的数据长什么样
该品类的数据主要来自Kubernetes API、镜像仓库、监控系统与CI流水线。日常文档包含集群变更单、命名空间配额表、部署记录与故障报告。集群变更单记录变更时间、影响范围与执行结果；命名空间配额表标注CPU、内存配额与已使用量；部署记录包含镜像版本、Pod启动状态与更新时间；故障报告收录错误码、排查日志与恢复时长。数据更新频率为每日或每次集群变更触发。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据接入的需求要求数据库支持异构数据源的写入与查询，适配K8s API、监控指标等不同格式的数据结构。数据更新的突发性（随集群变更触发）要求数据库连接池能够应对瞬时峰值，避免资源抢占。不同文档的字段差异要求数据库支持灵活的schema适配，无需提前定义固定表结构。同时，数据关联业务集群运行状态，一旦数据库运维出错可能引发业务中断，因此需要高可用的数据库部署方案，且需兼容国产替代组件以满足合规要求。此外，日常运维操作依赖快速查询部署记录与故障报告，数据库的查询性能需要匹配集群的响应时效要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 国产兼容的集群内连接字符串，例如 `mongodb://<user>:<pass>@<fastgpt-mongo-svc>:27017/fastgpt?authSource=admin` | 适配K8s集群内的服务发现地址，支持国产MongoDB替代组件，满足合规要求 |
| `PG_URL` | 兼容国产PG的连接字符串，例如 `postgresql://<user>:<pass>@<fastgpt-pg-svc>:5432/fastgpt?sslmode=disable` | 适配命名空间配额表、故障报告的结构化数据存储，兼容国产数据库替代方案 |
| `DB_MAX_LINK` | `100–200` | 匹配K8s集群的并发变更与查询请求，避免连接数过高引发资源抢占，适配每日/变更触发的更新频率 |
| `REDIS_URL` | 集群内缓存地址，例如 `redis://<fastgpt-redis-svc>:6379/0`，连接池按实测标定 | 缓存会话上下文与高频查询的部署记录，加速连续问答与运维查询的响应速度 |

## 容易做错的三处
- 现象：工作流发起数据库查询无返回结果，报错显示连接超时。原因：未正确配置`MONGODB_URI`或`PG_URL`指向集群内的数据库实例，无法从K8s API拉取部署记录等运维数据。
- 现象：集群升级后发布失败，CI流水线日志显示数据库连接被拒绝。原因：`DB_MAX_LINK`设置过低，无法承载瞬时的部署记录写入请求，导致变更同步中断。
- 现象：连续追问时无法关联上下文，第二个问题开始答非所问。原因：未配置`REDIS_URL`，导致会话缓存失效，无法保留前序问答的上下文信息。

## 怎么确认配好了
- 登录FastGPT v4.17.0的后台管理页面，进入数据库配置模块，执行`MONGODB_URI`与`PG_URL`的连接测试，确认测试结果为通过。
- 触发一次模拟的集群变更操作，检查CI流水线的部署记录是否能正常同步至配置的数据库中。
- 发起连续问答测试，确认后续问题能够关联前序对话的上下文，无答非所问的情况。
- 查看集群监控面板，确认数据库的活跃连接数未超过`DB_MAX_LINK`的设置值，无连接溢出告警。
