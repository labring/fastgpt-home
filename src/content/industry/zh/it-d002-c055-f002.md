# 容量规划与资源扩缩容的发布说明与运营报告汇总：上下文与 token

本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据通常来自云账单、监控系统、业务预测、压测报告，更新节奏多为周度或月度。日常产出的文档包括容量规划报告、扩容申请单、资源利用率报表、预算测算表，文档结构通常包含资源占用统计、峰值预测数据、资源配额申请、预算测算项等，字段涵盖资源标识、占用指标、时间周期、申请额度等，单位涉及计算核心数、存储容量单位、时间周期单位等。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据来源分散且包含多维度的资源与预算信息，整合多源上下文时会占用较多token额度。周度或月度的更新节奏意味着无需频繁刷新上下文，但需要稳定调用历史周期内的完整数据，避免因上下文截断丢失关键峰值预测或配额申请信息。文档字段多且涉及资源标识、占用指标等细分项，需精准匹配相关内容，若上下文配置不合理，可能导致关键字段被截断，影响后续容量规划与扩缩容决策。此外，工具调用过程中若超出模型上下文限制，会丢失部分历史资源数据，引发规划偏差或资源配置错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 匹配该品类周度/月度汇总数据的总token消耗，避免截断关键峰值预测与预算测算内容 |
| `quoteMaxToken` | 1500 token/条 | 适配单份容量规划报告或资源利用率报表的核心内容长度，防止单条数据溢出上下文 |
| 多轮上下文召回条数 | 前 3 条历史周期数据 | 贴合该品类周度/月度的更新频率，减少冗余历史数据的token占用 |
| 上下文数据来源过滤 | 仅包含云账单、监控系统数据 | 匹配该品类的核心数据来源，排除非业务相关内容 |
| 上下文刷新周期 | 7 天 | 对应周度更新节奏，平衡数据时效性与token消耗 |

## 容易做错的三处
- 工具调用返回结果为空或关键字段（如峰值预测值、配额申请数）缺失，原因是配置的`maxContext`过小，导致历史峰值预测数据被截断，无法提取核心资源指标。
- 调用时触发token超限报错，状态码返回400或系统提示“上下文溢出”，原因是未设置`quoteMaxToken`限制，单份资源报表的token消耗超出模型上限。
- 多轮对话中重复加载旧版非当前周期的资源数据，原因是未配置按时间周期过滤上下文的规则，导致冗余历史数据占用过多token额度。

## 怎么确认配好了
- 上传一份典型的容量规划报告，查看上下文加载的内容范围，确认仅包含当前周期的核心数据。
- 发起多轮模拟对话，核对返回结果中是否包含所需的资源利用率、峰值预测等关键字段。
- 监控单次调用的token消耗数据，确认额度处于预设的合理区间内。
- 触发一次工具调用，检查是否会因上下文溢出触发报错，验证配置的合理性。
