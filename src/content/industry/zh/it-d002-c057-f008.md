# 工单受理与问题分级的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
本品类的数据来源为工单系统、聊天记录、产品日志、客户合同SLA。日常文档包括客户工单、问题分级表、处理记录、服务报告。数据更新频率为日或实时，随新工单提交实时同步，或每日凌晨批量更新。数据字段包含工单编号、提交时间、客户反馈内容、问题分级标签、分派团队、处理状态、SLA履约情况等，单位涵盖秒、条、字符等，无固定统计百分比或预设数值。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据多源且更新节奏灵活，要求工作流需支持多源数据的整合入口，同时匹配实时或批量的触发逻辑。数据字段包含多个业务相关维度，要求工作流需绑定精准的字段映射规则，避免信息错位。最耗时的问题复现与影响范围判断环节，要求工作流可自动关联产品日志、聊天记录等辅助数据，减少人工操作。出错后果涉及SLA履约，要求工作流需加入超时校验与告警节点，及时规避响应超时风险。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，具体参数与建议如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 触发条件 | 按新工单生成事件触发，或每日凌晨批量处理 | 匹配数据更新的实时/日节奏，贴合工单提交的业务流程 |
| `variables` | 绑定工单ID、客户反馈内容、问题分级标签 | 关联工单系统的核心字段，为后续节点调用提供标准化输入 |
| `nodeId` | 为问题分级节点、SLA校验节点、结果记录节点分配唯一标识 | 确保工作流中节点执行顺序可追踪，避免调用混乱 |
| 超时设置 | 单节点超时设为300秒，整体工作流超时设为3600秒 | 匹配客服响应的常规时限，规避SLA违约风险 |
| 执行顺序 | 按工单受理→问题分级→团队分派→结果记录的顺序编排 | 贴合工单处理的标准业务流程，符合行业通用操作逻辑 |
| 冗余内容屏蔽 | 配置回复节点的屏蔽规则，移除固定标识文案 | 避免生成的回复附带非业务相关的平台提示内容 |

## 容易做错的三处
- 现象：工作流中多个工具未按预设顺序执行，部分节点未触发。原因：未通过`nodeId`明确指定节点依赖关系，或触发条件未绑定正确的执行顺序，导致工作流执行逻辑混乱。
- 现象：AI生成的回复末尾附带固定提示语，未在配置中移除。原因：未在系统提示词或回复节点中配置屏蔽规则，默认调用了平台自带的标识文案。
- 现象：问题分类节点处理速度过慢，导致工单堆积。原因：未对输入的工单内容做前置截断，或未优化`variables`绑定的字段数量，导致大模型处理负载过高。

## 怎么确认配好了
- 提交一条测试工单，查看工作流是否按预设的执行顺序触发所有节点，无遗漏或跳步。
- 检查`variables`绑定的字段是否与工单系统的输出字段完全匹配，无缺失或错位情况。
- 模拟单节点超时场景，确认工作流是否触发预设的告警或中断流程。
- 查看节点日志，确认`nodeId`对应的节点执行记录完整，无异常报错或状态码异常。
