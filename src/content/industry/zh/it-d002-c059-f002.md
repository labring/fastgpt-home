# 广告素材审核的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
本品类的数据来源包括广告平台素材库、落地页截图、商品资质文件及广告法合规条款。数据更新频率为日更或实时，覆盖单条广告素材的文本内容、落地页URL、历史审核意见、修改操作记录等字段。单条数据包含素材唯一标识、违规点标注、审核状态、操作时间等核心字段，文档格式多为结构化文本、图片OCR识别文本及合规条款原文。

## 这些特征在「上下文与 token」这一环带来什么约束
多源数据来源要求上下文需整合不同格式的素材、审核意见与合规条款，导致token消耗波动较大；实时/日更的更新节奏要求上下文需定期刷新，避免加载过期的审核记录；多样的文档结构要求对长文本素材、截图OCR内容进行合理分块，防止单块token超出模型限制。最耗时的文案检查与落地页核对环节，需优先将高相关内容纳入上下文，减少非必要token占用，同时严格控制上下文总长度，避免因溢出导致审核遗漏或违规点标注不全。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配多源广告素材、落地页文本及审核意见的总长度，避免上下文溢出 |
| `quoteMaxToken` | `2000 token` | 限制单条审核意见或修改记录的引用token数，防止单条内容占用过多上下文配额 |
| 上下文分块长度 | `800–1200 字符` | 适配广告素材文案、落地页OCR文本的单块处理长度，平衡token消耗与检索精度 |
| 上下文召回条数 | 前3条 | 优先加载最相关的广告素材、最新审核意见，减少非必要token消耗 |
| 上下文刷新频率 | 实时 / 每6小时 | 匹配广告素材审核数据的日/实时更新节奏，确保上下文包含最新合规与审核信息 |

## 容易做错的三处
- 现象：模型调用时token统计超出配置的`maxContext`配额，报错显示上下文长度超限。原因：未配置`quoteMaxToken`，导致冗余的历史审核意见被重复纳入上下文。
- 现象：新上下文字段返回为空，无法加载最新的审核修改记录。原因：未设置上下文刷新频率，导致系统未触发最新数据的拉取与加载。
- 现象：离线模型运行时间仅显示首token耗时，与在线模型的总运行时间统计规则不一致。原因：未针对广告素材审核的高耗时落地页核对环节，调整模型调用的时间统计配置。

## 怎么确认配好了
- 查看FastGPT v4.17.0的上下文加载日志，确认仅加载广告素材、审核意见等指定品类的文档，核对加载条数与配置的召回条数一致。
- 模拟单条广告素材审核的模型调用，查看token消耗统计面板，确认总token数未超出`maxContext`配置的配额。
- 检查模型调用的详细日志，确认单条引用内容的token数未超过`quoteMaxToken`的限制。
- 对比实时更新的审核数据，确认上下文刷新频率符合配置要求，最新的审核意见已被纳入上下文。
