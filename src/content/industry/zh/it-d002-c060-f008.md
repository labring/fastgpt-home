# 广告账户开户审核的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自广告平台后台、国家企业信用信息公示系统、客户提交的开户申请材料与行业准入规则。数据更新节奏随单次开户申请触发，无固定周期。日常处理的文档包含开户申请单、主体营业执照、对应行业的专项资质文件以及开户审核记录。核心字段涵盖主体统一社会信用代码、申请投放行业、材料完整性标识、审核状态与补正意见，无统一固定的单位体系，各文档字段独立适配业务场景。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的获取需求要求工作流配置多个跨数据源调用节点，规避单一接口的调用限制。无固定更新节奏的特性要求工作流支持按需触发，适配单次申请的实时处理逻辑。多样的文档结构需要工作流配置不同节点分别处理不同类型的资质材料，适配各字段的校验规则。最耗时的资质核验与行业准入判断环节，要求工作流设置并行处理节点或超时预警机制，避免整体流程阻塞。严重的出错后果要求工作流配置失败回滚与人工介入节点，降低违规开户的风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 包含主体统一社会信用代码、申请行业、材料上传链接 | 覆盖开户审核所需的核心核验字段，支持动态参数调用 |
| 节点触发条件 | 按开户申请提交事件触发 | 适配单次申请的实时处理节奏，避免无效的周期执行 |
| RAG知识库召回设置 | 关联行业准入规则库，单次召回前3条 | 匹配审核所需的合规依据，控制召回内容的精准度 |
| `nodeId` | 绑定资质核验节点与补正通知节点 | 实现跨节点的状态流转，确保审核流程的连贯性 |
| 单节点超时设置 | 600秒 | 覆盖资质核验的最长处理时长，避免流程无限阻塞 |
| 失败处理配置 | 触发人工审核节点 | 降低审核失误导致的开户风险，保障流程合规性 |

## 容易做错的三处
- 现象：模型对话节点的提示词无法自动加载当前日期，原因：未正确绑定`variables`中的平台时间变量，导致提示词参数缺失
- 现象：工作流运行速度慢于单独调试的任务对话，原因：未配置节点间的并行执行逻辑，导致多数据源调用串行执行
- 现象：工作流中RAG工具调用无结果返回，原因：未关联匹配当前申请行业的知识库，导致召回内容为空

## 怎么确认配好了
- 提交一条测试开户申请，查看工作流节点是否按预设顺序执行，无节点跳过或异常报错
- 检查`variables`变量是否包含所有必填的审核字段，确保动态参数可正常调用
- 验证RAG知识库召回的内容是否匹配当前测试申请的行业类目，确认召回逻辑生效
- 模拟单节点超时场景，确认是否触发预设的人工审核节点，验证失败处理逻辑正常
- 确认当前使用的FastGPT版本为v4.17.0，确保所有配置项均在兼容范围内
