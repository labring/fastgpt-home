# 性能测试与容量评估的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的核心数据来自压测平台、APM监控、数据库慢日志及生产流量基线，日常产出四类文档：压测方案、容量评估报告、压测数据记录、优化建议单。数据更新频率为每月或每重大版本发布时，核心字段包含吞吐率、延迟值、资源占用率、瓶颈节点标识，单位多为每秒请求数、毫秒、百分比、服务器节点名。

## 这些特征在「上下文与 token」这一环带来什么约束
数据来源分散且多为时序型指标，需整合多源日志与报告内容，会拉长上下文拼接长度，对token分配提出精准要求。更新频率固定且内容体量随版本迭代增长，需限制上下文窗口避免冗余数据占用过多token。核心字段多为数值型指标，需精准匹配关联上下文，不宜过度扩展无关内容。压测场景下的上下文需关联历史压测方案与当前评估结果，token分配需优先保障关键瓶颈指标的留存。

## 配置怎么定
本配置方案适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配压测报告与关联日志的平均内容总长度，避免超出通用大模型的token上限，适配该品类月度更新的文档体量 |
| `quoteMaxToken` | 2000–3000 字符 | 限定单条引用的压测数据或报告片段长度，防止单条慢日志或冗余方案内容占用过多上下文token，贴合该品类的核心字段占比特征 |
| 上下文过滤阈值 | 前3条 | 聚焦最相关的历史压测方案与瓶颈分析结果，减少非核心数据的token消耗，符合该品类最耗时的瓶颈指标定位环节的需求 |
| 上下文排序规则 | 按时间倒序 | 优先保留最新的压测数据与容量评估结论，贴合该品类每月或每重大版本的更新频率 |
| 冗余内容过滤 | 仅保留核心指标字段 | 过滤非关键的操作日志片段，压缩上下文总token占用量，聚焦该品类的吞吐率、延迟等核心指标 |

## 容易做错的三处
- 出现token相关报错，现象为返回包含`token`关键词的错误字段或请求超时状态码，原因是未针对压测场景调整`maxContext`参数，导致上下文拼接超出模型token上限。
- 汇总结果未关联历史压测上下文，现象为返回的优化建议未匹配过往瓶颈指标，原因是未配置上下文过滤规则，导致无关数据混入上下文窗口。
- token消耗超出预期，现象为单轮汇总的token占用超过预设值，原因是未设置`quoteMaxToken`限制单条引用长度，导致冗余的慢日志片段被纳入上下文。

## 怎么确认配好了
- 上传单份典型压测报告，查看上下文拼接后的token占用量，确认不超过`maxContext`的预设取值。
- 输入包含历史瓶颈指标的查询，查看返回结果是否关联对应历史记录，确认上下文过滤规则生效。
- 模拟多轮压测数据汇总，检查token溢出时的截断逻辑是否保留最新的评估结论。
- 核对配置项的取值是否与压测报告的平均内容体量匹配，确认参数设置贴合业务数据特征。
