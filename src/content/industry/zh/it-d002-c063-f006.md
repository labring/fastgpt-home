# 投放计划搭建的发布说明与运营报告汇总：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自广告平台接口、用户画像数据集、内部预算排期表、归因工具接口。日常产出的文档包含投放计划文档、定向设置配置表、预算排期表、转化追踪配置项。数据更新频率为每日或对应广告活动启动周期内。单条数据包含定向人群标签、预算额度、转化事件标识等字段，字段单位涵盖元、人次、天等，无统一固定格式，需匹配各广告平台的字段规范。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据来源涉及多类外部工具与内部文档，定时任务需适配不同广告平台的接口格式，避免跨平台数据解析失败。数据更新频率不固定，任务触发逻辑需支持按日周期或广告活动节点触发。日常文档结构多样，自动化流程需兼容不同格式的投放计划、定向设置等文档，无法依赖单一解析模板。字段无统一规范，需配置灵活的字段映射规则，避免定向人群、预算额度等核心数据错位。同时需覆盖人群定向配置、预算分配、转化事件校验等最耗时环节，减少人工操作成本。

## 配置怎么定
本说明适配 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发时机 | 按日凌晨2点 / 广告活动启动前1天 | 匹配广告平台的日更数据节奏与上线前置准备需求 |
| 数据拉取范围 | 前7天内的投放计划文档与关联数据 | 覆盖完整的活动筹备周期，避免遗漏前置配置 |
| 字段映射规则 | 按目标广告平台预设字段匹配 | 适配不同平台的字段格式，减少数据解析错误 |
| 失败重试次数 | 3次 | 平衡接口调用成本与数据拉取成功率 |
| 异常告警触发条件 | 任务连续执行失败2次 | 及时通知异常情况，避免影响投放准备 |
| 文档解析模式 | 按文档类型自动适配 | 兼容投放计划、定向设置等多种格式的文档 |

## 容易做错的三处
- 现象：嵌套在其他工作流中的投放计划搭建任务执行时，弹窗未隐藏。原因：未关闭任务节点的弹窗触发配置，嵌套调用时默认保留原弹窗设置。
- 现象：定时任务拉取外部数据源的投放计划文档时，返回字段为空。原因：未配置对应数据源的自动同步权限，任务无法获取最新的文档内容。
- 现象：任务执行时频繁出现接口调用失败报错。原因：未设置合理的失败重试次数，单次接口调用超时未触发重试机制。

## 怎么确认配好了
- 手动触发一次定时任务，查看任务执行日志，确认数据拉取、文档解析、字段映射环节均正常完成。
- 模拟一次任务失败场景，确认异常告警通知正常触发。
- 对比自动生成的运营报告与手动整理的投放计划数据，确认核心字段匹配无误。
- 测试嵌套调用场景，确认任务执行时无额外弹窗显示。
