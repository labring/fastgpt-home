# 投放计划搭建的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
投放计划搭建场景的数据主要来自广告平台、用户画像库、预算排期表、归因工具。日常产出的文档包含投放计划、定向设置、预算排期、转化追踪配置四类，字段覆盖定向人群标签、预算额度、转化事件ID、投放时段等，单位涉及元、人次、天等。数据更新频率通常为每日或单次活动启动时，无固定批量同步周期，单条数据体量随投放规模波动。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「工作流编排」这一环带来什么约束
投放计划搭建的数据多源异构且更新节奏灵活，要求工作流需支持多节点间的参数流转，确保定向设置、预算分配、转化校验等环节的数据一致性。文档结构的细分字段较多，需精准映射各节点的输入输出变量，避免参数错位。数据更新无固定批量周期，工作流需支持事件触发或短间隔定时触发，适配投放计划的临时调整。同时，投放配置出错会直接导致预算浪费或投放失败，工作流需内置异常捕获与重试机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按投放计划更新事件触发，间隔不超过600秒 | 匹配投放计划日/活动级的更新节奏 |
| 变量绑定 | 关联`variables`中的定向人群、预算额度字段 | 对应投放计划文档的标准字段结构 |
| 执行顺序配置 | 按`nodeId`升序排列所有工具节点 | 确保工具调用依次执行，规避依赖冲突 |
| 失败重试策略 | 最多3次重试，单次间隔120秒 | 应对广告平台接口的临时波动 |
| 上下文保留 | 缓存最近2次工作流执行的日志与参数 | 便于排查投放计划配置异常 |
| 变量引用范围 | 限定为当前工作流节点的`variables` | 避免跨工作流的参数污染 |

## 容易做错的三处
- 工作流中多个工具未按预期顺序执行，部分节点无调用日志。原因是未按`nodeId`配置执行顺序，或节点间未正确绑定依赖参数。
- 部署后工作流与知识库配置空白，接口可正常调用。原因是本地存储卷挂载未持久化，配置文件未随容器重启保留。
- 知识库选择时变量引用无效，无法加载指定知识库内容。原因是未在`variables`中声明引用的知识库ID变量，或变量作用域未覆盖当前节点。

## 怎么确认配好了
- 触发一次测试投放计划更新，检查工作流日志中各节点的执行状态是否为成功。
- 手动修改投放计划文档的字段值，验证工作流是否自动拉取更新后的参数执行。
- 断开广告平台接口模拟异常，检查工作流是否触发预设的失败重试逻辑。
- 查看`variables`配置面板，确认所有引用的投放计划字段均已正确映射。
