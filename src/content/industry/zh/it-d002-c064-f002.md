# 投标文件编制的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
这个品类的数据来源为招标公告、招标文件、企业资质库、供应商报价，更新频率为每单。日常处理的文档包括投标文件、资格证明、商务偏离表、技术偏离表，核心字段包含招标条款响应要求、资质证明文件编号、报价明细、格式校验规则。数据结构以单次招标的特定要求为核心，随每一次投标项目动态生成，无固定通用模板，需严格匹配对应招标的格式与条款细节。

## 这些特征在「上下文与 token」这一环带来什么约束
每单数据随招标项目动态生成，单次项目的输入文本量波动较大，需严格控制上下文窗口的token占用。招标条款与资质文件的强绑定关系，要求召回的上下文需精准匹配对应条款，避免无关内容挤占token配额。商务偏离表、技术偏离表的逐条款响应需求，会产生大量逐段比对的上下文调用，若未限制召回范围，会快速耗尽token额度。同时，格式校验规则的短文本高频调用，也会增加上下文拼接的token消耗。

## 配置怎么定
本配置说明基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 匹配单次投标项目的总文本量，避免超出模型原生上下文窗口 |
| `quoteMaxToken` | 800–1200 字符 | 控制单条召回内容的token消耗，适配偏离表、资质文件的单段长度 |
| 单次召回条数 | 前5条 | 减少冗余召回内容，避免无关招标条款挤占上下文空间 |
| 上下文重排 | 开启 | 优先召回与当前响应条款强相关的内容，降低无效token占用 |
| 响应token上限 | 4000–6000 token | 适配投标文件的逐条款响应长度，避免输出截断导致格式错误 |

## 容易做错的三处
- 界面提示上下文溢出，后台日志显示累计token超出模型支持范围。原因是未限制`maxContext`的取值，将全量招标文档片段直接拼接进上下文窗口。
- 生成的投标响应被截断，仅输出部分条款内容。原因是未设置合理的响应token上限，超出模型原生输出限制。
- 召回的无关资质材料过多，导致核心招标条款未被优先匹配。原因是未开启上下文重排，且单次召回条数设置过高，引入了大量非必要内容。

## 怎么确认配好了
- 上传单份完整的招标文件与资质文件，查看上下文预览面板的token消耗数值，确认未超出预设的`maxContext`范围。
- 发起一次条款响应测试，查看返回内容的完整度，确认未出现输出截断情况，对应调整响应token上限。
- 测试不同招标条款的召回结果，确认优先召回与当前条款直接相关的内容，验证上下文重排配置生效。
- 查看后台的token消耗统计，确认单轮对话的token消耗符合预设的`quoteMaxToken`限制，无冗余内容占用。
