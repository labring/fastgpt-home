# 数据库运维的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自数据库监控系统、审计日志、SQL执行计划与内部工单系统。日常产出的文档包含数据库变更单、慢SQL性能报告、全量备份记录、权限申请审批单。单份变更单包含变更时间、实例ID、变更语句、审批人字段；慢SQL报告按执行耗时排序，包含SQL指纹、扫描行数（单位为行）、执行耗时（单位为秒）。数据更新频率随变更触发或按日生成，单次变更产生的文档仅在变更完成后更新，日度报告则固定在每日凌晨生成。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散，需编排多个节点拉取不同系统的数据源，因此需配置`variables`统一管理实例ID、工单ID等全局参数，避免重复配置。数据更新无固定统一节奏，部分数据随工单触发，部分按日生成，工作流需支持按定时触发或手动触发两种模式，且需校验数据源返回的字段完整性。文档包含敏感的权限信息与执行语句，工作流需配置节点权限校验，同时慢SQL报告的字段单位需在编排时统一映射，避免后续汇总时出现单位不匹配的问题。出错后果影响较大，工作流需配置失败重试与告警节点，且需保留执行日志用于后续审计。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 全局变量`variables` | 包含实例ID、工单ID、报告日期三个固定字段，取值从工单系统回调参数中提取 | 统一管理跨节点的公共参数，避免重复配置，适配不同数据库实例的拉取需求 |
| 触发方式 | 支持定时触发（每日凌晨0点）与手动触发（变更完成后） | 适配日度报告与单次变更报告的不同更新节奏 |
| HTTP请求节点超时设置 | 600秒 | 数据库监控接口返回数据量较大，避免因超时中断拉取流程 |
| 输出变量映射 | 将返回的SQL指纹、扫描行数字段映射为`nodeId`对应的输出变量 | 统一节点输出格式，便于后续汇总与图表展示 |
| 失败重试配置 | 重试2次，间隔30秒 | 应对数据库接口临时波动，减少工作流中断概率 |
| 基础图表配置 | 按SQL指纹分组，展示执行耗时分布 | 适配慢SQL报告的分析需求，便于后续定位慢查询 |

## 容易做错的三处
- HTTP请求节点的output未在对话结果中显示，现象为节点执行状态显示成功但对话中无对应数据，原因是未将HTTP节点的输出变量映射到全局`variables`中，导致后续节点无法读取该数据源的返回内容。
- 导入旧版本工作流后出现配置丢失，现象为部分节点的参数显示为空，原因是未在FastGPT v4.17.0中导出兼容格式的工作流包，直接导入旧版本文件导致字段结构不匹配。
- 自定义工具变量与基础图表轴配置错误，现象为工具调用时提示缺少必要参数或图表展示数据混乱，原因是未将工具或图表的变量与全局`variables`或`nodeId`对应的输出字段正确绑定。

## 怎么确认配好了
- 触发一次手动工作流，查看各节点的执行日志，确认所有数据源拉取的字段与配置的`variables`参数一致。
- 检查基础图表的轴配置，确认x轴绑定了SQL指纹字段，y轴绑定了执行耗时字段，与节点输出的变量名称匹配。
- 模拟一次变更工单触发工作流，确认工作流按预期触发并生成对应的汇总报告，无超时或字段缺失报错。
- 查看工作流的失败告警配置，确认当节点返回错误状态码时，会触发预设的告警通知。
