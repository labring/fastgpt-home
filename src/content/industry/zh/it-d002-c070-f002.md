# 数据清洗与质检的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的数据来源包括原始数据集、ETL日志、标注平台输出及抽样结果，更新频率为每日或每批交付周期。日常产出的文档包含清洗规则、质检抽样表、异常数据清单与交付报告，文档字段涵盖数据标识、质量评分、异常类型、处理状态等，单位多为数据条数、时间戳等，整体数据体量随业务批次波动。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据来源多样且字段结构存在差异，要求上下文加载逻辑兼容多格式数据标识、质量评分等字段；高更新频率要求上下文支持增量加载，避免重复处理历史批次数据；日常文档涵盖清洗规则、抽样标准等参考内容，上下文窗口需覆盖此类规范以保证处理逻辑一致性；异常数据清单条目随业务波动，token消耗随数据量增长明显，需限制上下文token上限防止溢出。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单批次清洗规则、抽样表及异常数据清单的总内容量，避免token溢出 |
| `quoteMaxToken` | 1500–2000 token | 限定单条异常数据或抽样记录的引用token上限，防止单条内容占用过多窗口 |
| 上下文增量加载 | 开启 | 匹配数据日/每批的更新频率，仅加载最新批次的数据集与日志 |
| 字段兼容模式 | 宽松匹配 | 兼容原始数据集、ETL日志的不同字段结构，减少上下文格式校验的token消耗 |
| 历史数据过滤阈值 | 按实测标定 | 过滤超过更新周期的历史数据，控制上下文总token规模 |

## 容易做错的三处
- 现象：多模型编排的工作流中，总token消耗超出预期，触发服务报错。原因：未单独限制每个环节的引用token上限，导致各模型上下文token叠加后超出全局配置。
- 现象：上下文加载失败，界面显示token超限报错。原因：未限制`maxContext`配置，加载了多批次的历史数据与文档，超出系统token上限。
- 现象：单条异常数据的引用内容不完整，仅显示部分字段。原因：`quoteMaxToken`配置取值过小，截断了异常数据的完整记录。

## 怎么确认配好了
- 查看上下文加载日志，确认仅加载了当前批次的数据集与文档，无历史冗余数据。
- 测试加载单条完整的异常数据清单条目，确认内容未被截断，符合`quoteMaxToken`的配置预期。
- 模拟多模型编排场景，统计各环节的token消耗，确认总消耗未超出`maxContext`的配置范围。
- 调整历史数据过滤阈值，验证上下文加载范围是否随更新周期动态变化。
