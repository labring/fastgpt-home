# 数据清洗与质检的发布说明与运营报告汇总：定时任务与自动化

## 这个品类的数据长什么样
本品类处理的数据来源包括原始数据集、ETL运行日志、标注平台产出结果、抽样质检结果。数据更新节奏为每日或按单批任务触发，日常产出的文档包含清洗规则配置、质检抽样表、异常数据清单与交付报告。数据字段涵盖原始数据标识、异常类型标记、质检评分、处理状态等，无统一固定单位，随具体业务数据集调整。服务主体为数据工程师、质检员与项目经理，日常操作围绕数据质量校验与交付文档生成展开。

## 这些特征在「定时任务与自动化」这一环带来什么约束
数据来源分散且更新节奏不固定，导致定时任务需适配多源数据接入的校验逻辑，避免重复处理未更新的数据集。日常文档的结构化程度不一，自动化流程需兼容清洗规则、抽样表等不同格式的配置导入，无法依赖统一的解析逻辑。异常数据清单与交付报告的生成需绑定特定任务批次，定时触发的时间窗口需与单批任务的处理周期匹配，避免跨批次数据混淆。ETL日志的实时性要求较高，任务重试机制需适配日志采集的延迟特性，减少因短暂网络波动导致的任务失败。质检抽样结果的更新频率决定了定时任务的调度间隔，需避免重复触发未完成的任务批次。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务调度周期 | 按业务更新频率设置为`每日 02:00`或`每批任务完成后触发` | 匹配原始数据集、抽样结果的更新节奏，避免重复处理未更新的数据 |
| 日志采集超时时间 | `600 秒` | 适配ETL日志的常规采集延迟，避免任务因短暂延迟失败 |
| 任务重试次数 | `3 次` | 平衡任务成功率与资源消耗，避免无效重试占用计算资源 |
| 异常数据阈值 | 按实测标定 | 适配不同业务的异常容忍度，避免误判正常数据 |
| 报告生成范围 | 前 1000 条异常数据 | 控制交付报告的输出体量，适配日常查阅需求 |
| 触发条件校验 | 仅当原始数据集更新时执行 | 避免无意义的任务运行，节省平台资源 |

## 容易做错的三处
- 现象：定时生成的交付报告中异常数据字段为空。原因：未配置异常数据清单与交付报告的字段映射规则，导致自动化流程无法提取对应数据。
- 现象：任务触发后长时间处于运行中状态，最终触发超时报错。原因：未设置合理的日志采集超时时间，ETL日志采集延迟超出预设阈值。
- 现象：单批任务重复执行多次，导致异常数据清单出现重复条目。原因：未配置任务触发的去重逻辑，未校验当前任务批次是否已完成处理。

## 怎么确认配好了
- 查看FastGPT v4.17.0的任务调度日志，确认定时任务按预设周期触发。
- 手动触发一次测试任务，检查异常数据清单与交付报告的字段是否完整。
- 模拟一次原始数据集更新，确认任务仅在数据更新时触发，无无意义运行。
- 查看任务重试记录，确认异常任务按预设次数重试后完成或终止。
