# 数据脱敏处理的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
本品类的数据来自数据库、数据字典、脱敏工具及访问审批系统，按每批或每个项目更新。日常产出的文档包含脱敏方案、字段映射表、脱敏验证报告与审批记录，核心字段包括敏感字段标识、脱敏规则参数、验证结果与审批状态，无统一固定单位，随项目场景调整。

## 这些特征在「上下文与 token」这一环带来什么约束
每批项目的脱敏数据结构差异较大，导致上下文关联时需适配不同字段的语义边界，避免跨项目的上下文污染。不同项目的更新频率导致上下文缓存需按项目维度隔离，防止不同批次的脱敏数据混淆。脱敏验证报告与审批记录包含敏感元数据，若上下文未做token级的敏感内容过滤，会引发敏感信息泄露风险。敏感字段识别环节的耗时特征要求上下文token分配需优先匹配高优先级的敏感字段，避免无效token占用导致核心内容截断。

## 配置怎么定
本文适配FastGPT v4.17.0版本，以下配置项基于该版本设计：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8-25 条，按项目敏感等级调整 | 匹配本品类按项目更新的数据特征，避免跨项目上下文污染 |
| `quoteMaxToken` | 800-1200 token | 适配脱敏验证报告、字段映射表的文档长度，防止核心脱敏规则被截断 |
| 上下文隔离规则 | 按项目ID绑定 | 区分不同批次的脱敏数据，防止不同项目的上下文混淆 |
| 敏感字段过滤阈值 | 按实测标定 | 优先保留敏感字段的上下文内容，降低信息泄露风险 |
| 上下文刷新时机 | 按项目审批完成触发 | 匹配本品类的审批记录更新节奏，确保上下文与最新脱敏规则同步 |

## 容易做错的三处
- 对话明细中上下文条数与设置不符，仅显示少量关联内容。原因是未按项目维度配置上下文隔离规则，导致不同批次的脱敏数据上下文被合并覆盖。
- AI回复出现不符合格式的JSON内容。原因是上下文未过滤字段映射表中的敏感元数据，导致token占用超出阈值，触发格式解析异常。
- 上传脱敏相关文件的相对路径附带token导致处理失败。原因是未在上下文环节剥离文件路径中的token参数，导致后端服务无法正确识别文件访问路径。

## 怎么确认配好了
- 查看FastGPT平台的上下文管理界面，确认当前项目的上下文条数与设置的`maxContext`数值匹配。
- 测试导入一份脱敏验证报告，检查上下文token占用量未超出`quoteMaxToken`的设置范围。
- 发起跨项目的对话测试，确认不同项目的上下文不会互相干扰，无上下文污染情况。
- 上传脱敏相关文件，确认后端服务可正常识别文件路径，无token参数干扰。
