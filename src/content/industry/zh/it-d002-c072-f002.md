# 数据采集任务设计的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的核心数据由数据服务项目经理、采集团队、客户算法团队产出，日常文档包含采集方案、样本规格、授权说明、任务排期四类。数据来源涵盖客户需求、公开数据源、采集工具、样本库，更新频率为每项目或每周。单份文档包含样本范围、字段规格、合规说明等明确字段，内容随项目需求动态调整，无统一固定单位。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据来源多样且格式不统一，需在上下文管理中适配多源数据的字段差异，避免token分配失衡。更新频率为每项目或每周，要求上下文缓存需匹配项目周期，避免加载过期的采集参数。日常文档包含合规类内容，需将授权说明等关键文档纳入上下文，因此需通过`maxContext`和`quoteMaxToken`参数调整上下文总token上限，覆盖单项目全量文档的总长度。样本范围定义与字段规格确认环节耗时较长，需将该环节的参数纳入token统计，防止因关键配置未加载导致任务出错。FastGPT v4.17.0的上下文管理模块需适配该品类的动态数据特征，确保token使用符合业务需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 12000 token | 适配单项目采集任务的全量文档总长度，符合FastGPT v4.17.0的参数规范 |
| `quoteMaxToken` | 1800 字符 | 对应单条采集样本的字段规格内容，确保单条引用不溢出token限制 |
| 上下文刷新间隔 | 按项目周期设置 | 匹配数据更新频率为每项目或每周的节奏，确保上下文始终使用最新任务参数 |
| token预警阈值 | 90% 总上下文token | 预留冗余空间应对临时补充的采集排期文档 |
| 单次加载上下文文档数 | 前3条最新文档 | 聚焦当前项目的核心采集文档，减少无效token消耗 |

## 容易做错的三处
- 现象：采集任务执行时token消耗远超预设值，界面弹出上下文溢出提示。原因：未根据单条样本的字段规格调整`quoteMaxToken`取值，默认设置过大导致冗余token消耗，对应Excel数据块过大、颗粒度不足的常见问题。
- 现象：调用采集任务接口时提示重试次数超限。原因：未按项目周期刷新上下文缓存，旧的采集参数重复请求导致接口调用超限，与登录重试限制的报错逻辑一致。
- 现象：采集任务的样本范围定义字段为空，无法生成有效采集任务。原因：未预留足够的上下文空间容纳授权说明等合规文档，导致关键配置未被加载，引发字段缺失报错。

## 怎么确认配好了
- 查看采集任务的上下文加载日志，确认加载的文档与当前项目的采集方案、样本规格、授权说明一致。
- 模拟提交一条样本数据，检查token消耗提示是否在预设的`maxContext`取值范围内，调整阈值以匹配实际业务需求。
- 核对单条样本的引用长度，确认未超过预设的`quoteMaxToken`取值，避免单条数据溢出。
- 等待一个项目周期后，检查上下文是否自动刷新为最新的任务排期与采集参数，确保缓存更新符合设定的刷新间隔。
