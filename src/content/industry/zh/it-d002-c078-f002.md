# 机柜上架与布线的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
IDC运维工程师、网络工程师、设备实施人员是该场景的典型主体，日常处理的文档包括上架申请、机柜布线图、端口标签表、施工记录。数据来源涵盖DCIM系统、资产系统、网络拓扑图及客户工单，更新频率为每单一次或每日一次。核心工作环节涉及机位规划、线缆标签核对与上架验收，出错会导致端口接错、散热受影响或客户开通延期，与机房巡检品类的区别在于该场景聚焦新增或变更设备的物理接入流程。本文基于FastGPT v4.17.0版本的配置逻辑编写。

## 这些特征在「上下文与 token」这一环带来什么约束
多源异构的数据来源导致不同文档的字段格式与单位存在差异，拼接上下文时需统一格式，否则会额外占用token；单工单关联的文档数量与内容规模波动较大，需灵活控制上下文的总token占用量；施工记录、端口标签表等文档的文本密度差异显著，分块处理时需匹配内容特征，避免token分配失衡；同时，需严格限定上下文召回的范围，防止跨工单的无关数据占用有限的token资源，影响核心内容的处理效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 该品类单工单关联文档的总token量通常在此区间，可覆盖上架申请、布线图说明、端口标签表等核心内容，避免超出模型上下文上限 |
| `quoteMaxToken` | 2000–3000 token | 单份端口标签表或施工记录的核心文本token量通常在此区间，可避免单条引用占用过多上下文空间 |
| 分块长度 | 1000–1500 字符 | 匹配机柜布线图的文本注释、端口标签表的单行字段长度，平衡token消耗与召回精度 |
| 单次搜索上限 | 前6条 | 单工单关联的文档数量通常不超过6个，避免召回无关数据占用token |
| 重排 | 开启 | 该品类文档关联性强，重排可提升相关内容的token分配效率，优化上下文召回效果 |

## 容易做错的三处
- 上传部分机柜布线图时提示token超限，部分图片可正常上传。原因：未针对图片关联的元数据设置合理的token折算规则，导致小分辨率图片的元数据token消耗超出预期。
- 执行运营报告汇总时，系统提示token不足，即便已将模型token限制设置为较大值。原因：未配置`quoteMaxToken`，单份端口标签表的完整文本被召回，占用过多上下文token，导致整体超出模型限制。
- 上下文召回结果包含其他工单的设备上架文档。原因：未限定单次搜索的关联范围，召回了跨工单的历史数据，导致额外token被无关内容占用。

## 怎么确认配好了
- 上传单份机柜上架申请单，查看系统返回的上下文拼接日志，核对召回的文档数量是否符合单次搜索上限的设置。
- 提交包含多张布线图的工单，检查系统生成的token消耗统计，确认总消耗未超出`maxContext`的设置范围。
- 触发上架验收的运营报告汇总任务，查看返回结果是否仅包含当前工单关联的文档内容，无跨工单数据。
- 调整分块长度参数，对比不同设置下的token消耗情况，确认取值匹配文档的文本密度特征。
