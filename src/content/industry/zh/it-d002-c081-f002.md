# 渗透测试服务的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的核心文档包含测试授权书、渗透测试报告、漏洞复现记录、整改建议四类，数据来源覆盖目标系统日志、公开漏洞库、自动化扫描器结果与红队手工验证记录。数据更新以单个项目或重大版本为周期，每份文档的结构随测试范围灵活调整，核心字段包括授权编号、漏洞等级、攻击路径、修复方案等，单份文档的token数差异显著，无固定统一长度限制。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的文档类型多样且token数差异显著，授权书等涉密文件需完整保留全部内容，截断会引发法律授权争议；数据来源分散，需整合目标系统日志、漏洞库、扫描结果与手工记录到上下文窗口，需合理分配不同来源内容的token占比；更新周期随项目灵活调整，每次上下文加载的内容均不固定，无法依赖固定配置；且出错后果严重，上下文截断可能导致漏洞遗漏或业务中断。不同于漏洞扫描服务，该品类需整合手工验证的非结构化内容，对上下文的连贯性要求更高，因此上下文与token的配置需兼顾完整性与资源合理性。

以下配置说明基于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000-15000 token | 适配单项目多文档的总token量，预留冗余避免截断授权书等核心涉密文件 |
| `quoteMaxToken` | 1200-1800 token | 匹配单份漏洞复现记录的长度，完整保留攻击路径与利用链细节 |
| 分块长度 | 800-1000 字符 | 适配渗透测试报告的段落结构，平衡上下文连贯性与token占用 |
| 重叠长度 | 100-150 字符 | 适配漏洞验证记录的跨段落关联，避免丢失关键验证步骤 |
| 上下文召回上限 | 前6条 | 控制整合内容的总token数，避免超出模型窗口限制 |

## 容易做错的三处
- 现象：上传完整渗透测试报告时返回400错误，提示上下文长度超限。原因：未对长文档进行预处理，直接加载完整内容超出`maxContext`的设置值。
- 现象：漏洞复现记录的攻击路径描述被截断，风险评级结果缺失关键依据。原因：`quoteMaxToken`设置值低于单条复现记录的token数，导致核心内容被截取。
- 现象：整合扫描器结果与手工验证记录时，部分扫描日志内容丢失。原因：分块长度设置过大，导致短日志条目未被正确加载进上下文窗口。

## 怎么确认配好了
- 上传单份完整的测试授权书，检查返回结果是否包含全部授权编号与授权范围内容。
- 查看上下文加载日志，确认实际加载的token数未超过`maxContext`的设置值。
- 触发漏洞复现记录的上下文调用，检查是否能完整获取攻击步骤的全部描述。
- 调整分块长度后，对比不同配置下的上下文召回结果，确认保留了跨段落的关联信息。
