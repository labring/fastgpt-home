# 渠道归因与线索分发的发布说明与运营报告汇总：数据库与运维
本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据主要来源于广告投放平台、客户关系管理系统、归因采集SDK、在线表单系统，更新节奏为每日或每周批量同步。日常产出的文档包含归因规则配置表、线索分发分配单、渠道效果报表、异常数据核对单据，字段通常包含渠道标识、线索触达时间、归属主体标识、转化关联ID等，单位随来源系统统一，如时间采用UTC时间戳、金额采用对应币种单位。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构的数据格式需要数据库支持灵活的字段映射与清洗逻辑，避免数据入库失败。每日或每周的批量同步任务会产生较高的并发连接需求，需合理配置连接池参数防止连接耗尽。由于涉及销售归属与渠道ROI计算，数据的一致性与完整性要求较高，需保留原始数据与清洗后数据用于异常核对。同时，数据量随投放规模增长，需监控存储容量与查询性能，保障报表生成效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据库连接池最大连接数 | 20–30 | 适配每日批量同步的并发请求，避免连接耗尽 |
| MongoDB连接地址 | `mongodb://user:pass@host:port/fastgpt_attribution` | 对应`MONGODB_URI`参数，存储归因数据与线索历史，支持索引优化 |
| PostgreSQL连接地址 | `postgresql://user:pass@host:port/fastgpt_report` | 对应`PG_URL`参数，存储结构化的归因规则与报表元数据 |
| Redis连接地址 | `redis://:auth@host:port/0` | 对应`REDIS_URL`参数，缓存渠道参数校验结果与去重后的线索ID |
| 数据备份周期 | 每日凌晨2点 | 保留7天原始数据与清洗后数据，满足异常核对需求 |
| 同步任务超时时间 | 600 秒 | 适配`DB_MAX_LINK`关联的任务执行上限，适配周度全量同步的大数据量处理 |

## 容易做错的三处
- 数据库连接配置错误，表现为渠道报表显示字段为空、同步任务报错连接超时，原因是未正确填写`MONGODB_URI`的认证参数或主机地址，或未开启MongoDB服务的远程访问权限。
- 未配置持久化存储，表现为重启服务后线索数据丢失、Sealos部署时无法找到挂载的存储卷，原因是未为数据库容器配置持久化存储卷，或存储卷挂载路径与配置不匹配。
- 线索去重逻辑失效，表现为同一线索被分配给多个销售、ROI报表出现重复数据，原因是未启用Redis缓存去重标识，或`REDIS_URL`配置错误导致缓存无法正常工作。

## 怎么确认配好了
- 执行数据库连通性测试脚本，验证`MONGODB_URI`、`PG_URL`、`REDIS_URL`的连接状态，确认无认证或网络异常。
- 触发一次手动同步任务，检查渠道数据是否成功写入数据库，且核心字段完整无缺失。
- 查看异常核对单生成日志，确认数据清洗与去重流程正常执行，无报错信息。
- 查看数据库连接池监控面板，确认当前活跃连接数未超过配置的连接池阈值，无连接耗尽情况。
