# 游戏内容合规自查的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
这个品类的典型主体为游戏发行合规团队、内容审核人员与游戏制作人，数据主要来自游戏研发与发行阶段的游戏文本、剧情脚本、美术资源，以及日常使用的内容自查表、敏感内容修改记录、用户协议、合规评审纪要，同时包含公开的监管合规要求。数据更新随游戏版本迭代或活动上线节奏，每版本或每活动更新一次。文档结构以结构化字段为主，包含内容类型、合规项、修改状态、评审意见等，部分文档关联美术资源的路径与版本标识。

## 这些特征在「上下文与 token」这一环带来什么约束
游戏内容合规自查的文档多为长文本，剧情脚本、合规评审纪要等单条文本长度差异较大，且随版本或活动高频更新，要求上下文召回需覆盖最新的敏感内容修改记录与评审意见。不同于游戏版号与出版申报，该场景的合规自查发生在申报前和版本更新中，上下文需覆盖高频更新的版本内容。数据来源包含美术资源路径等非文本字段，需在上下文拼接时区分有效合规内容与冗余信息，避免无效token占用。监管公开要求需随时调取参考，上下文召回需优先匹配核心合规项字段，同时需限制总token数，防止因内容过长超出模型承载上限。

## 配置怎么定
本配置说明基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配游戏剧情脚本、合规评审纪要的长文本长度，避免截断核心合规内容 |
| `quoteMaxToken` | 1500–2000 token | 限定单条引用文档的token上限，防止单条内容占用过多上下文空间 |
| 单次召回上限 | 前6条 | 匹配日常文档的数量规模，避免召回过多冗余的历史修改记录 |
| 上下文排序规则 | 按更新时间倒序 | 优先加载最新的敏感内容修改记录与合规评审意见，确保内容时效性 |
| 总输入token限制 | 按实测标定 | 适配所使用的量化模型承载能力，避免token验证失败 |

## 容易做错的三处
- 聊天界面出现token validation failed报错，且长文本合规查询出现回答截断。原因是未正确配置`maxContext`或`quoteMaxToken`的取值，导致输入内容超出模型承载范围。
- 收到400 <400> InternalError.Algo.InvalidParameter: Range of max_tokens sho报错。原因是未设置`maxContext`或`quoteMaxToken`的合理区间，系统默认参数与游戏长文本内容不匹配。
- 无法找到配置最大token的入口，导致无法调整上下文空间。原因是未在应用设置的上下文与token模块中找到对应配置项，误将其他功能参数当作token设置入口。

## 怎么确认配好了
- 导入一份完整的游戏剧情脚本与最新的合规评审纪要，测试上下文召回结果是否包含最新的敏感内容修改记录。
- 发起包含长文本合规查询的对话，检查是否出现token验证失败或内容截断的情况。
- 查看应用配置页面的上下文与token模块，确认`maxContext`、`quoteMaxToken`已填入合理的取值区间。
- 模拟多轮合规评审对话，验证上下文是否能持续加载最新的评审意见，无明显的内容丢失或溢出。
