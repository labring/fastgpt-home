# 游戏客户端性能优化的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的日常文档通常包含性能测试报告、机型适配清单、优化记录、崩溃分析报告四类，数据来源于引擎Profiler、崩溃平台、真机测试结果、帧率采集数据，更新节奏为每日或每版本发布周期。文档无统一强制格式，字段通常涵盖机型标识、帧率数值、资源占用占比、崩溃日志片段等，单份文档的token占用随内容长度存在明显差异。

## 这些特征在「上下文与 token」这一环带来什么约束
FastGPT v4.17.0适配该品类的上下文与token配置需匹配其数据特性。数据分散且格式灵活的特点，会导致单轮问答的有效内容筛选难度提升，需精准控制上下文token配额。高频更新的特性要求上下文缓存需按版本或每日周期刷新，避免引用过时的性能数据。多字段的文档结构需要筛选有效内容，防止无关字段占用过多token。同时，游戏客户端性能数据多关联机型与版本维度，上下文需按对应维度聚合，避免跨维度数据混入导致的token浪费。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1800 token | 匹配游戏客户端性能报告单块有效内容的平均token占用，避免单块内容过长截断关键性能数据 |
| `maxContext` | 8000–12000 token | 适配多份性能文档的聚合需求，覆盖单轮问答所需的机型适配、优化记录等关联内容 |
| 分块重叠长度 | 100–200 字符 | 保留性能数据的时序连续性，防止跨块的帧率变化分析被截断 |
| 单次检索召回上限 | 前6条 | 匹配每日更新的性能文档数量，避免过多历史数据占用上下文token |
| 知识库刷新周期 | 每日或每版本 | 匹配该品类的更新频率，确保上下文引用的性能数据为最新版本 |

## 容易做错的三处
- 配置`quoteMaxToken`为1500 token后，仍出现超出额度的引用结果。原因是知识库分块大小设置为5000 token，单块完整内容被直接召回，未按`quoteMaxToken`进行截断。
- 工作流运行后上下文历史未被清空，累积token超出`maxContext`限制。原因是未在判断条件后绑定正确的上下文清空操作，历史对话记录持续占用token配额。
- 无法查看每次问答的token使用情况。原因是未在系统设置中启用token统计功能，或未开启对应日志记录选项。

## 怎么确认配好了
- 上传一份典型的性能测试报告，发起包含性能数据查询的问答，查看返回内容的token占用是否符合`quoteMaxToken`的设定。
- 发起多轮连续问答，验证达到`maxContext`阈值后，后续问答是否自动截断早期上下文内容。
- 检查知识库的刷新周期设置，确认每日或每版本自动同步最新的性能文档数据。
- 查看问答详情页或系统日志，确认每次问答的token使用数据已正常生成并记录。
