# 游戏版号与出版申报的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的数据由游戏研发发行相关主体日常产出，核心文档包括申报请示文件、游戏申请表、著作权证明、审读报告等。数据来源涵盖国家新闻出版署办事服务平台、著作权登记系统、游戏包体及运营机构资料，更新节奏随单款游戏申报流程不定期推进。单份文档包含申报编号、著作权登记号、审读修改意见、运营数据摘要等字段，部分材料需结合扫描件与结构化信息提交，无统一固定格式。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的文档格式不统一，包含结构化表格与扫描件类文本，会导致上下文拼接需适配多类内容结构，限制通用参数的取值范围。数据随单款游戏申报流程不定期更新，需在会话中动态加载最新材料，对上下文的实时更新机制提出要求。单份申报材料涉及多类审批字段，跨来源核对会增加上下文token占用量，需严格控制总长度避免溢出。同时，部分材料涉及敏感审批信息，上下文调用需限定访问范围，防止token泄露风险。

## 配置怎么定
本配置基于FastGPT v4.17.0版本制定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单款游戏申报材料的总内容长度，避免上下文token溢出 |
| `quoteMaxToken` | 1500–2000 token | 限定单份引用文档的token占用，保证多材料拼接后的上下文合理性 |
| 上下文刷新触发条件 | 随申报节点更新 | 匹配数据随单款流程不定期更新的节奏，保证会话使用最新材料 |
| 敏感信息过滤 | 启用权限绑定 | 限定上下文的访问范围，适配审批材料的敏感属性 |
| 单次召回条数 | 前3–5条 | 控制上下文总token占用，避免过多材料导致参数超限 |

## 容易做错的三处
- 现象：本地部署时调用失败，返回`401 Unauthorized`错误，或服务端无法加载`AIPROXY_API_TOKEN`环境变量。排查项：未配置服务端环境变量`AIPROXY_API_TOKEN`（需为与AI Proxy服务端配置一致的非空管理员Token），或`AIPROXY_API_ENDPOINT`未配置为AI Proxy服务的根地址（例如`http://aiproxy:3000`，不得附加`/v1`或模型服务路径）。
- 现象：上下文拼接后超出`maxContext`限制，导致会话中断。原因：未根据单款申报材料的实际内容调整`maxContext`取值，直接使用通用默认值。
- 现象：召回的材料与当前申报任务不匹配，结果条数异常。原因：未限定上下文的召回范围，导致加载了无关的历史申报材料，占用过多token。

## 怎么确认配好了
- 检查服务端部署的环境变量配置，确认`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址）与`AIPROXY_API_TOKEN`（与AI Proxy服务端配置一致的管理员Token）的取值与部署环境一致。
- 上传单份典型申报材料，测试上下文拼接后的总token数，确认未超出`maxContext`的设置值。
- 触发一次申报流程的模拟调用，查看返回结果中是否包含最新的审读报告或申请表内容，确认上下文刷新生效。
- 检查敏感信息过滤规则，确认核心审批字段已被纳入权限控制范围，避免泄露。
