# 漏洞扫描服务的发布说明与运营报告汇总：定时任务与自动化

## 这个品类的数据长什么样
漏洞扫描服务的数据来源于漏洞扫描器、资产清单、CVE库与补丁公告，日常产出扫描计划、漏洞清单、整改工单与复扫报告四类核心文档。数据字段包含资产IP地址、漏洞CVE编号、漏洞等级、整改状态、扫描时间、补丁版本等，更新频率为周度或月度，不同运营主体的资产范围与扫描需求差异导致数据体量与字段细节存在区别。

## 这些特征在「定时任务与自动化」这一环带来什么约束
数据来源分散且需定期同步，要求定时任务覆盖资产范围拉取、漏洞数据更新、扫描执行与报告生成全流程。数据更新频率为周/月，任务周期不宜过短，需平衡数据时效性与系统资源占用。日常文档字段多且关联紧密，自动化流程需匹配字段映射规则，避免同步时出现字段缺失。最耗时的资产范围确认、误报排除与复扫结果核对环节，可通过定时任务自动化完成，但需配置校验规则规避错误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，具体参数如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发周期 | `每周一 00:00` | 匹配多数企业的周度数据更新节奏，避免占用业务高峰资源 |
| 资产范围自动同步频率 | `每3天` | 平衡资产变动的时效性与系统资源消耗，适配多数企业的资产更新周期 |
| 误报过滤阈值 | `前10%误报率` | 基于CVE库的漏洞评级规则，过滤低风险误报，减少人工排查工作量 |
| 扫描任务重试次数 | `3次` | 应对临时网络波动或扫描器临时故障，避免单次任务失败导致漏洞遗漏 |
| 告警通知延迟 | `10分钟` | 避免频繁告警干扰运营，同时保证高危漏洞能及时触发通知 |
| 日志留存时长 | `7天` | 满足审计需求的同时，控制日志存储的资源占用 |

## 容易做错的三处
- 现象为定时任务未触发，界面显示「任务状态异常」，原因是未开启FastGPT v4.17.0的容器自启配置，依赖手动启动容器与任务。
- 现象为漏洞清单出现条目丢失，结果条数与预期不符，原因是未正确配置资产范围同步参数，导致部分资产未纳入扫描范围。
- 现象为整改工单同步失败，提示字段不匹配，原因是未将扫描结果字段与工单系统字段做映射，导致自动化同步中断。

## 怎么确认配好了
- 手动触发一次定时任务，查看FastGPT后台的扫描日志，确认任务正常启动并生成扫描结果。
- 检查资产同步记录，确认所有配置的资产IP均被纳入本次扫描范围，无遗漏。
- 查看告警通知是否在任务完成后按配置的延迟时间发送，无延迟或遗漏。
- 核对复扫报告的字段完整性，确认漏洞等级、整改状态等关键字段无缺失。
