# 现场部署实施的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来源于客户机房环境、设备清单、软件包、网络拓扑等现场一手资源，日常生成部署手册、安装记录、配置清单、现场签到表四类文档。数据更新节奏为每单或每阶段，由现场实施工程师、系统工程师、客户IT人员同步维护，字段包含设备型号、软件版本、配置参数、签到时间等，无统一固定单位，随现场实际环境调整。

## 这些特征在「上下文与 token」这一环带来什么约束
现场部署实施的数据源分散且每单不同，要求上下文需动态适配部署手册、安装记录等差异化文档结构，无法采用固定模板加载。数据更新频率为每单或每阶段，上下文缓存时长需匹配更新节奏，避免加载过期的配置或签到数据。文档字段多样，不同文档的token占用差异较大，需合理分配token配额以覆盖各类现场文档，同时防止token溢出引发系统不可用。另外，现场数据的准确性直接影响部署结果，上下文过滤逻辑需严格匹配字段规则，避免无效信息占用token资源，保障部署配置的正确性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 匹配现场部署类文档的总token占用区间，预留合理冗余避免上下文溢出 |
| `quoteMaxToken` | 1500–2000 token | 适配部署手册、安装记录等单段内容的常规长度，防止单段引用占用过多上下文配额 |
| 上下文刷新时机 | 按部署阶段完成节点触发 | 匹配该品类每阶段更新数据的节奏，确保加载的配置、签到记录为最新版本 |
| 上下文内容过滤阈值 | 按实测标定 | 过滤无意义的现场环境备注，减少无效token占用 |

## 容易做错的三处
- 现象：部署后LLM返回「上下文token溢出」报错，或输出内容被截断。原因：未根据现场部署文档的实际总长度调整`maxContext`参数，默认参数无法覆盖单份部署手册的token占用。
- 现象：调用时返回的引用内容为空或不完整。原因：未设置合理的`quoteMaxToken`参数，单段引用长度超过限制导致内容被截断。
- 现象：现场部署的最新配置未被加载到上下文。原因：上下文刷新时机设置错误，未匹配每阶段更新数据的节奏，仍使用旧版配置记录。

## 怎么确认配好了
- 查看`maxContext`参数的配置值，确认其匹配当前部署文档的总token占用区间。
- 测试加载单段安装记录，检查`quoteMaxToken`参数是否允许完整加载该段内容。
- 模拟一次部署阶段更新，确认上下文会自动刷新为最新的配置清单内容。
- 触发一次LLM调用，检查返回结果中引用的现场文档内容完整且无截断。
