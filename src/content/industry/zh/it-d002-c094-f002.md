# 用户验收测试支持的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
本品类的数据来自需求规格文档、测试环境配置、客户业务样例数据与缺陷管理系统。日常产出的文档包含UAT用例、验收问题单、验收报告与签字确认单，数据更新以项目阶段或软件版本为节奏，由实施顾问、测试经理与客户业务代表共同维护。数据字段包含业务场景、测试步骤、问题描述、复现条件、验收结论与关联版本号，无固定统一单位，随项目实际场景调整。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类的数据来源分散，跨需求规格、测试环境、缺陷系统等多类系统，整合时需处理异构格式内容，对上下文拼接的token分配提出适配要求。数据更新以项目阶段或软件版本为节奏，上下文需动态匹配当前版本的验收范围，避免跨版本无效内容混入。日常文档包含结构化用例与非结构化问题单，上下文切分需兼容不同内容密度。UAT数据随项目推进逐步积累，token消耗随阶段递增，需限制上下文总规模以避免资源过载。同时验收相关文档含客户确认类内容，上下文过滤需精准区分有效业务数据与冗余信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 8000–12000 token | 适配FastGPT v4.17.0的模型承载上限，兼容UAT多类型文档的整合需求，避免单次加载超出资源阈值 |
| 引用最大token | 2000–3000 字符 | 针对验收问题单的长文本复现内容，预留足够token保留关键细节，避免核心信息被截断 |
| 分块长度 | 1000–1500 字符 | 兼容UAT用例的结构化段落与问题单的非结构化描述，平衡切分效率与上下文连贯性 |
| 单次搜索上限 | 前6条 | 匹配UAT阶段的核心验收文档数量，避免冗余内容占用过多token资源 |
| 上下文过滤规则 | 按版本范围筛选 | 适配数据按阶段/版本更新的节奏，仅加载当前验收阶段的有效文档，减少无效token消耗 |

## 容易做错的三处
-  现象：模型输出的Markdown表格无法正常渲染，或展示内容被截断。原因：未针对UAT验收报告中的结构化表格内容调整`maxContext`与`quoteMaxToken`配置，导致表格内容超出分配token上限被截断。
-  现象：问答响应速度变慢，且token消耗持续升高。原因：未按项目阶段限制上下文加载范围，将历史全阶段的UAT用例、问题单全部纳入上下文，导致token占用随项目推进无节制增长。
-  现象：检索返回的内容与当前验收阶段无关，或出现冗余的历史问题记录。原因：未配置按版本范围筛选上下文的规则，导致跨阶段的无效文档被加载，额外消耗token资源。

## 怎么确认配好了
-  上传一份当前阶段的UAT验收报告与问题单，测试上下文加载是否仅包含当前版本的有效内容，无跨阶段冗余文档。
-  发起包含结构化表格的验收问题查询，确认模型输出的表格可正常渲染，无内容截断。
-  统计连续3次问答的token消耗值，确认消耗值稳定在配置的最大上下文范围内，无异常升高。
-  测试上下文过滤规则，验证跨版本的历史文档不会被纳入当前问答的上下文范围。
