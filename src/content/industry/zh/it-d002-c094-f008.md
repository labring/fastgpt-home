# 用户验收测试支持的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
本品类的数据来源包括需求规格文档、测试环境配置、客户业务样例、缺陷管理系统四类。日常产出的文档包含UAT用例、验收问题单、验收报告、签字确认单，由实施顾问、测试经理、客户业务代表共同维护。数据更新节奏为每阶段或每版本一次，文档均有固定的字段结构，包含业务场景、缺陷等级、验收结论等核心内容。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据来源要求工作流需配置跨数据源拉取的节点，确保能同时获取需求规格、测试环境等不同类型的信息。固定的文档结构要求工作流节点需按UAT用例、验收问题单的标准字段进行映射，避免字段不匹配的问题。每阶段/每版本的更新频率要求工作流需绑定版本触发规则，确保数据同步及时。最耗时的用例准备、问题复现归类、验收结论确认环节，要求工作流需自动化流转逻辑，减少手动操作的耗时，规避验收延期风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定UAT用例ID、验收问题单编号、客户业务样例版本 | 匹配品类数据的核心标识字段，实现跨文档的关联流转 |
| `nodeId` | 按用例评审、问题复现、验收确认三个节点分配固定ID | 明确工作流流转的节点边界，适配品类的固定业务环节 |
| 触发时机 | 每版本发布后72小时内 | 匹配品类每阶段/每版本的更新频率，确保数据同步及时 |
| 文本提取范围 | 提取UAT用例的前置条件、验收问题单的缺陷等级 | 贴合品类文档的标准字段结构，减少手动录入成本 |
| 异常告警阈值 | 问题复现超时600秒时触发告警 | 覆盖品类最耗时的问题复现环节，避免验收延期 |
| 单次数据拉取上限 | 前10条验收问题单记录 | 适配品类单阶段的文档数量规模，避免系统资源过载 |

## 容易做错的三处
- 工作流运行后提取的知识库信息为空：未绑定用户验收测试支持专属的客户业务样例数据源，仅调用了通用数据集，无法匹配品类的业务字段结构。
- 调试时出现节点流转报错：未按照`nodeId`的命名规则分配节点标识，导致FastGPT v4.17.0版本的工作流引擎无法识别节点路径。
- 工作流的处理性能未达预期：未限制`variables`的绑定范围，导致节点重复拉取多阶段的历史数据，占用过多系统资源。

## 怎么确认配好了
- 检查工作流的`variables`是否绑定了品类专属的UAT用例、验收问题单等文档字段。
- 核对每个节点的`nodeId`是否与用例评审、问题复现、验收确认的业务环节一一对应，无重复或遗漏。
- 触发一次版本更新后的工作流，确认数据能从需求规格、测试环境等指定来源正常拉取。
- 模拟问题复现环节的超时场景，确认异常告警规则能够正常触发。
