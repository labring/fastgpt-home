# 等级保护测评咨询的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
这个品类的日常文档包含定级报告、差距分析报告、整改方案、测评报告四类结构化文件，数据来源于测评工具导出的结果、现场访谈记录、系统清单及安全设备日志。数据按单个项目归档更新，更新频率为每项目/年，每个项目的文档包含项目编号、测评对象、控制项清单、整改记录等字段，无统一固定单位，仅按项目维度关联所有业务数据。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据来源分散且按项目归档，需整合多源文档作为上下文，因此上下文窗口需适配单项目多文档的总规模，避免token溢出。单项目数据更新频率低但单次加载量大，需平衡上下文召回的完整性与token消耗效率。日常文档的结构化特征要求上下文需精准匹配测评环节关键词，过滤无关内容。同时，测评流程的多环节关联性要求上下文可跨环节保留历史数据，若配置不当会导致测评材料召回不全，引发整改延期或监管检查风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 适配单项目下四类文档的总token规模，避免模型上下文溢出 |
| 引用最大token | 2000–3000 字符 | 匹配单份核心测评文档的关键段落长度，确保召回的业务信息完整 |
| 单次召回上下文条数 | 前5条 | 覆盖定级、差距分析、整改三个核心环节的文档，避免冗余内容占用token |
| 上下文触发规则 | 按当前测评环节标签 | 精准召回与当前环节相关的历史数据，降低无效上下文占比 |
| 全局上下文存储 | 开启项目级存储 | 保留跨环节的历史会话数据，适配多轮测评流程的上下文需求 |

## 容易做错的三处
- 出现Invalid JSON报错，返回结果包含未转义的控制字符。原因是未对测评报告中的换行、制表符等特殊符号做预处理，导致拼接上下文时生成非法JSON格式。
- 多轮会话中上下文无法跨环节保持。原因是未开启全局上下文存储，仅保留单轮会话的临时上下文，无法关联定级、差距分析、整改等不同环节的历史数据。
- 上下文召回条数超出预设上限后仍返回冗余内容。原因是未配置上下文自动截断规则，导致过多非核心文档占用token，引发模型响应超时。

## 怎么确认配好了
- 导入单项目的全部测评文档，触发上下文召回，检查返回的上下文条数与预设的单次召回条数一致。
- 构造包含换行、制表符等特殊符号的测试文本，提交后检查返回的JSON格式是否合法，无未转义控制字符。
- 连续发起多轮关联不同测评环节的查询，检查上下文是否保留历史环节的关键信息。
- 查看系统token消耗统计，确认单项目会话的token消耗未超出预设的最大上下文阈值。
