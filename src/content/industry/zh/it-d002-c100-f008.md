# 等级保护测评咨询的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
本品类的数据围绕等级保护测评全流程产生，核心文档包括定级报告、差距分析报告、整改方案与测评报告。数据主要来自测评工具导出的扫描结果、现场访谈记录、资产系统清单及安全设备运行日志。每份项目数据的更新周期以项目周期或年度为单位，文档字段包含控制项合规状态、整改完成进度、证据材料关联标识等，未设置统一固定的单位化字段，需随项目实际情况匹配对应内容。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据分散来自多类工具与记录，且随项目周期更新，要求工作流需支持多源数据并行拉取节点。不同项目的文档结构存在差异，工作流需配置动态字段映射规则以适配定级报告、整改方案等不同文档的提取需求。项目级数据的更新逻辑独立，工作流需绑定项目专属`variables`，避免全局变量冲突。耗时环节集中在材料梳理与核对，工作流需设置合理的节点超时与失败重试策略，保障流程推进效率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工作流功能制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按项目维度创建，包含项目标识、测评等级、控制项列表 | 本品类数据以项目为单位更新，需绑定项目专属变量避免数据混淆 |
| `nodeId` | 为每个数据拉取节点分配唯一标识 | 需精准追踪不同来源数据的处理状态与执行结果 |
| 并行节点配置 | 同时启动3-5个数据拉取节点 | 本品类数据来源分散，并行处理可压缩耗时环节的时长 |
| 节点超时时间 | 600秒 | 测评工具导出数据、日志拉取等操作通常需较长等待周期 |
| 失败重试次数 | 2次 | 网络波动或临时数据加载失败可通过重试恢复，避免流程中断 |
| 字段映射规则 | 按文档类型预设映射模板 | 本品类文档结构多样，需动态匹配不同报告的字段提取需求 |

## 容易做错的三处
- 现象：工作流中`variables`未绑定项目专属标识，导致多项目数据交叉混淆。排查项：检查工作流变量是否使用全局变量配置，未按项目维度创建专属变量。
- 现象：多个AI对话节点无法并行执行，流程执行时长超出预期。排查项：检查并行节点配置是否正确，确认节点执行顺序是否为串行。
- 现象：工作流查询合并模块输出结果条数与预期不符，无法匹配控制项核对需求。排查项：检查字段映射规则是否按文档类型预设，确认合并逻辑是否匹配提取需求。

## 怎么确认配好了
- 检查服务端环境变量是否已配置AIPROXY_API_ENDPOINT（AI Proxy服务的根地址）与AIPROXY_API_TOKEN（AI Proxy管理员Token），且未在工作流内重复填写相关参数。
- 启动测试工作流，查看节点日志是否显示正确的项目专属`variables`参数。
- 触发并行节点执行，确认多个数据拉取节点同时启动且无执行顺序冲突。
- 运行字段映射测试，确认不同类型文档的字段提取结果符合预设规则。
