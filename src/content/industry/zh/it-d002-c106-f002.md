# 语音标注与转写的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来源于上传的音频文件、内部标注平台、专有词表与抽检样本。日常产出的文档包含转写规范、音频交付清单、质检报告、说话人标注表等，更新频率按日或单批次任务周期调整。数据处理的核心环节集中在噪声片段判断、说话人区分与专有词校对，涉及的字段包括音频时长、转写文本、说话人标签、置信度评分与质检结果，单位多为秒、字符、条。

## 这些特征在「上下文与 token」这一环带来什么约束
音频转写的原始数据时长跨度大，单批次任务可能包含数十到数百条音频，对应转写文本量差异显著，导致上下文窗口的负载波动明显。日常文档中的转写规范与专有词表需实时纳入上下文以保证标注一致性，但频繁更新的词表会增加token占用。说话人区分与专有词校对环节需要参考历史标注结果，若上下文未关联对应批次的标注数据，易出现识别偏差。此外，抽检样本的质检结果需作为参考依据，若未合理限定上下文范围，会导致token消耗超出预期，同时影响标注结果的准确性。本文基于FastGPT v4.17.0版本编写。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文token | 8000–12000 token | 匹配单批次语音转写文本的平均长度，避免超出模型承载上限 |
| 召回内容token上限 | 4000–6000 token | 限制召回的历史标注与参考文本总量，平衡上下文信息与token消耗 |
| 单次召回条数 | 前3–5条 | 匹配单批次任务的历史标注样本量，避免冗余信息占用token |
| 上下文更新触发规则 | 按任务批次触发 | 匹配该品类按日或单批次的更新节奏，减少无效上下文加载 |
| 专有词表纳入阈值 | 按实测标定 | 结合专有词的使用频次调整，避免无关词表占用过多token |

## 容易做错的三处
- 现象：单次任务token消耗超出预设上限，导致任务中断。原因：未按单批次任务的音频总时长调整上下文token限制，误将全量历史数据纳入上下文。
- 现象：专有词识别错误，转写结果不符合规范。原因：未将最新的专有词表纳入上下文窗口，导致模型无法识别专属术语，引发转写返工。
- 现象：召回的历史标注结果冗余，输出文本过长。原因：未限制单次召回的条数与token上限，引入了无关批次的标注数据，可能导致交付延期。

## 怎么确认配好了
- 查看FastGPT v4.17.0的上下文配置面板，确认最大上下文token与召回内容token上限的取值符合任务需求。
- 导入单批次音频样本，运行测试任务，查看token消耗统计，验证是否与预设配置匹配。
- 提交质检报告与说话人标注表，检查上下文是否正确关联了对应批次的参考数据。
- 更新专有词表后，提交测试转写任务，确认术语识别结果符合最新规范。
