# 账号封禁与申诉复核的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的日常运营文档包含封禁记录、申诉材料、复核意见、用户通知四类。数据来源为风控系统、审核记录、用户行为日志与举报证据，更新节奏分为实时与每日两种。封禁记录包含账号ID、违规时间、处置措施、关联举报ID等字段；申诉材料包含用户提交的佐证内容与沟通痕迹；复核意见包含审核结论与调整依据。数据字段多为枚举值或结构化文本，单条记录的文本长度差异较大。

## 这些特征在「上下文与 token」这一环带来什么约束
多源数据的整合需求要求上下文召回覆盖风控、审核、行为日志等多类来源，单轮召回的token消耗随关联证据数量波动。实时更新的封禁与申诉数据要求上下文同步时效性，需通过`maxContext`与`quoteMaxToken`平衡数据新鲜度与token占用。结构化字段与差异较大的单条文本长度，要求上下文匹配的颗粒度需适配不同长度的记录，避免因块过大导致token超额，或因块过小丢失关联逻辑。同时，账号级的复核需求要求上下文围绕目标账号聚合，避免无关数据占用token配额。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多源封禁与申诉数据的聚合长度，避免单轮对话token超额 |
| `quoteMaxToken` | 2000–3000 字符 | 限制单条召回内容的长度，匹配申诉材料与审核记录的典型文本规模 |
| 单次搜索上限 | 前 8 条 | 控制召回的关联证据数量，减少无关数据的token占用 |
| 分块长度 | 800–1200 字符 | 适配结构化记录的文本粒度，平衡召回精度与token消耗 |
| 重排开关 | 开启 | 优先召回与目标账号关联度高的证据，降低无效上下文的token消耗 |

## 容易做错的三处
- 现象：单轮对话触发token超额报错，返回“token quota exceeded”类提示。原因：未调整`maxContext`与`quoteMaxToken`参数，直接使用默认配置，导致多源上下文聚合后超出配额。
- 现象：召回的关联证据数量超出预设上限，单次请求耗时过长。原因：未限制单次搜索上限，将所有关联记录全部召回，额外占用token与计算资源。
- 现象：申诉复核的上下文匹配精度不足，出现误判违规类型的情况。原因：分块长度设置过大，导致相邻记录的无关内容被合并，丢失关键关联字段的匹配逻辑。

## 怎么确认配好了
- 查看FastGPT v4.17.0的上下文配置面板，确认`maxContext`与`quoteMaxToken`的取值符合预设区间。
- 导入单条封禁记录与关联申诉材料，测试召回结果的条数与单条长度，验证是否符合配置要求。
- 发起模拟复核对话，查看token消耗日志，确认未出现超额报错。
- 对比不同账号的召回结果，确认仅关联该账号的证据被纳入上下文。
