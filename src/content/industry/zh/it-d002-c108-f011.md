# 质保期缺陷响应的发布说明与运营报告汇总：数据库与运维

## 这个品类的数据长什么样
该品类的数据主要来自客户提交的质保工单、系统运行日志、项目合同质保条款及软件版本记录。日常产出的文档包括质保工单、缺陷确认单、修复记录与客户确认单。数据更新以单条工单触发为主，部分汇总类数据按日更新。单条数据包含工单唯一标识、缺陷具体描述、责任方判定、修复版本、修复耗时、客户确认状态等字段，无统一固定单位，随具体业务项调整。

## 这些特征在「数据库与运维」这一环带来什么约束
该品类的数据来源分散，涵盖客户工单、运行日志、合同条款与版本记录，且更新频率不均，既有单条工单触发的实时写入，也有按日更新的汇总数据。日常文档类型多样，需兼容不同结构的表单数据存储。数据需关联项目合同与版本记录，因此要求数据库支持跨表关联查询的准确性。单条数据包含责任边界判定等敏感字段，需配置独立的权限管控机制。无固定更新周期的特性，需避免数据库连接耗尽或写入阻塞影响业务流程，同时需保证数据写入与查询的低延迟以支撑实时售后响应。

## 配置怎么定
以下配置适用于 FastGPT v4.17.0。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://fastgpt:securepass@db-host:27017/qc_defect?authSource=admin` | 存储质保工单、缺陷确认单等半结构化数据 |
| `PG_URL` | `postgresql://qc_user:pass@pg-host:5432/qc_contract` | 存储合同质保条款、客户确认单等关联结构化数据 |
| `DB_MAX_LINK` | `20–30 个` | 适配单工单实时写入与日更批量汇总任务的并发连接需求 |
| `REDIS_URL` | `redis://:redis-pass@cache-host:6379/1` | 缓存临时工单状态、权限校验信息，降低数据库高频查询压力 |

## 容易做错的三处
- 现象：启动后出现`connection refused`报错，日志显示数据库连接失败。原因：未正确配置`MONGODB_URI`或`PG_URL`的连接参数，包含错误的主机地址或认证信息。
- 现象：批量汇总任务执行超时，返回结果为空。原因：未限制`DB_MAX_LINK`的连接数，导致并发连接耗尽，写入阻塞无法完成日更汇总。
- 现象：通过第三方工具直接操作向量库后，系统无法检索到最新的缺陷修复记录。原因：未通过FastGPT内置接口操作向量库，直接修改数据导致元数据与实际存储不一致。

## 怎么确认配好了
- 执行单条质保工单的创建接口，检查数据库中是否生成对应记录，核对字段完整性。
- 触发日更汇总任务，检查关联的合同条款与版本记录是否正确关联到工单数据。
- 查看数据库连接数监控，确认当前连接数未超过`DB_MAX_LINK`的配置值。
- 测试通过FastGPT内置工具访问向量库，确认可正常检索缺陷修复相关的文档内容。
