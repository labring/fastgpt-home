# 运维外包驻场服务的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
这个品类的数据通常来自客户ITSM系统、现场监控平台、资产清单及值班记录。日常产出的文档包含驻场日报、服务台工单、巡检报告与SLA月报，其中驻场日报按日更新，记录当日驻场处理的工单信息与巡检完成情况；SLA月报按月汇总，包含履约周期内的服务交付指标。数据字段涵盖驻场人员标识、工单状态、巡检项完成度、SLA统计指标等，无额外自定义统计项。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且覆盖多系统，工作流需支持跨源数据拉取的顺序编排，确保工单、巡检记录等数据按现场处理逻辑依次拉取。更新频率分日/月两类，需配置匹配不同周期的定时触发节点，分别适配驻场日报的每日汇总与SLA月报的月度统计。日常文档字段零散且结构固定，需设置变量提取节点拆分核心字段，减少冗余数据的干扰。最耗时的汇总环节需自动化替代手动整理，同时需配置优先级判断节点，确保紧急工单的汇总流程优先执行，避免影响合同履约。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 定时触发规则 | 日触发时间设为18:00，月触发时间设为每月1日00:00 | 匹配驻场日报的当日收尾更新与SLA月报的月度周期要求 |
| `variables` | 预设驻场人员ID、工单状态码、SLA达标阈值3个变量 | 适配驻场场景下的人员分配、工单筛选及合规统计需求 |
| 跨源数据拉取节点 | 按`nodeId`依次拉取ITSM工单、监控平台巡检记录 | 确保数据拉取顺序符合现场工单处理的先后逻辑 |
| 字段提取规则 | 提取工单编号、处理时长、巡检完成率3个核心字段 | 聚焦汇总需求，减少冗余数据对流程的干扰 |
| 异常校验节点 | 设置120秒超时阈值，过滤空字段数据 | 避免无效数据进入汇总流程，降低统计出错风险 |
| FastGPT版本 | 选用FastGPT v4.17.0 | 适配当前工作流节点的稳定运行环境 |

## 容易做错的三处
- 现象：工作流调用返回图片流的HTTP接口后，输出字段为空，无法生成文生图相关结果。原因：未配置二进制数据解析节点，仅默认处理文本格式的HTTP响应内容。
- 现象：工作流运行时无法触发用户选择是否跳过知识库检索的交互，直接执行检索流程。原因：未正确绑定`variables`参数，未设置可由用户自定义的触发条件。
- 现象：驻场日报的汇总数据出现重复工单条目，导致后续统计偏差。原因：未配置`nodeId`去重规则，未按工单唯一标识过滤重复拉取的数据。

## 怎么确认配好了
- 手动触发日触发节点，检查是否生成当日驻场日报的临时汇总文件，核对字段是否包含预设的核心内容。
- 触发月触发节点，确认是否按设定周期拉取全月的工单与巡检数据，验证变量绑定是否生效。
- 调用测试用的图片流HTTP接口，检查节点是否正确解析二进制数据并输出可识别的内容。
- 模拟拉取空数据的异常场景，确认异常校验节点是否按规则拦截无效输入。
