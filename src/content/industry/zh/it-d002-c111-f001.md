# 配置管理与CMDB维护的发布说明与运营报告汇总：HTTP 接口与外部系统

## 这个品类的数据长什么样
这个品类的数据来源于CMDB、云资源清单、自动发现工具与采购台账，更新频率为日或周。日常产出的文档包含配置项清单、服务组件关系拓扑图、变更记录台账与资产盘点表，数据字段包含配置项唯一标识、资产类别、关联依赖关系、最后更新时间等，结构以结构化表格与拓扑可视化内容为主，核心聚焦服务组件间的依赖关联，区别于单纯的资产数量统计类文档。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据来源的多样性要求HTTP接口支持多源数据拉取，需兼容不同数据源的字段映射规则。更新频率为日或周，要求接口调用间隔需匹配业务更新节奏，避免过度请求或数据滞后。日常文档包含依赖拓扑与台账，要求接口返回数据需包含配置项标识、关联关系、变更时间等明确字段。由于出错会导致影响分析错误、资产账实不符，接口需支持失败重试机制与详细错误反馈，保障数据拉取的稳定性与准确性。同时，针对配置项采集、关系核对等耗时环节，接口需支持增量拉取功能，减少全量数据传输的资源消耗。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `Authorization` | `Bearer {API密钥} 或 自定义签名头` | 符合外部系统鉴权规范，保障接口调用安全 |
| `variables` | 配置项ID、关联依赖类型、更新时间范围 共3-5个变量 | 匹配CMDB数据的查询条件，缩小返回数据范围 |
| `responseData` | 仅返回配置项清单、依赖关系、变更记录 3类核心字段 | 减少无效数据传输，适配日常文档的结构需求 |
| 接口超时时间 | `30-60 秒` | 匹配CMDB数据拉取的平均响应时长，避免因数据量大导致超时 |
| 轮询间隔 | `86400 秒（1天） 或 604800 秒（1周）` | 匹配数据的日/周更新频率，避免资源浪费 |
| 重试次数 | `2-3 次` | 应对临时网络波动，保障数据拉取成功率 |

## 容易做错的三处
- 现象：调用外部接口时返回协议不支持错误，状态码426。原因：未将FastGPT应用发布API根地址从HTTP升级为HTTPS，导致外部系统拦截非加密请求。
- 现象：HTTP编排节点的output字段未在对话结果中展示。原因：未在`responseData`中配置需要返回的自定义字段映射规则，导致接口返回数据未被正确解析。
- 现象：定时拉取webhook消息时出现数据遗漏或重复。原因：轮询间隔设置与数据更新频率不匹配，或未配置合理的重试机制。

## 怎么确认配好了
本页面内容适配FastGPT v4.17.0版本。
- 调用配置完成的HTTP接口，检查返回数据是否包含配置项清单、依赖关系、变更记录三类核心字段。
- 查看接口调用日志，确认`Authorization`头被正确携带且鉴权通过。
- 模拟一次临时网络波动，检查接口的重试机制是否正常触发。
- 对比接口返回数据与本地CMDB台账，确认字段映射符合业务需求。
