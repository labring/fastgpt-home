# 配置管理与CMDB维护的发布说明与运营报告汇总：定时任务与自动化
本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的数据来源于CMDB、云资源清单、自动发现工具与采购台账，日常产出配置项清单、关系拓扑、变更记录、资产盘点表四类文档。数据字段包含配置项唯一标识、资产类型、跨组件依赖关系、变更时间、采购批次等，无统一固定单位，部分字段需匹配对应数据源的格式要求。数据更新频率分为日更与周更两类，单次数据体量随企业资产规模波动。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据来源包含多类异构工具与台账，定时任务需支持多数据源并行拉取与格式转换；数据更新频率分日/周两类，任务调度需支持灵活调整周期以匹配不同资产的更新节奏；因核心关注组件间依赖关系，任务执行需按拓扑顺序完成采集、校验与更新，避免出现依赖关系错位；单次数据体量波动较大，需限制单任务的单次处理规模，防止执行超时影响整体流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发周期 | 日任务取`24 小时`，周任务取`7 天` | 匹配该品类数据日/周的更新频率 |
| 数据源拉取批次 | 单次拉取`前 1000 条`配置项 | 避免单次拉取过载，适配多数环境的资源上限 |
| 失败重试次数 | `2–3 次`，间隔`60 秒` | 应对临时网络波动或数据源临时不可用的场景 |
| 依赖关系校验阈值 | 匹配率≥`90%`时判定有效 | 保障配置项依赖关系的核对精度 |
| 任务告警阈值 | 连续`2 次`执行失败时触发告警 | 及时发现持续性异常，避免影响资产数据一致性 |
| 日志留存时长 | 保留`30 天`的任务执行日志 | 满足后续排查与审计的基础需求 |

## 容易做错的三处
- 现象：配置项的敏感字段（如系统密码）在定时同步后被重置为初始值。原因：未关闭CMDB自动同步的默认覆盖配置，导致定时任务覆盖了手动修改的敏感字段值。
- 现象：定时任务执行后，配置项的依赖关系拓扑未更新。原因：任务调度顺序错误，未先拉取最新资产数据再执行依赖关系校验。
- 现象：任务执行超时导致部分配置项未完成采集。原因：单次拉取批次设置过大，超出单任务允许的执行时长限制。

## 怎么确认配好了
- 查看任务调度日志，确认任务触发时间与设置的周期一致，无异常跳过情况。
- 随机抽取10条配置项，核对其最新数据与CMDB、云资源清单的实际值匹配。
- 模拟一次任务失败场景，确认告警通知正常触达预设接收渠道。
- 检查任务日志留存目录，确认对应时长内的日志可正常检索与查看。
