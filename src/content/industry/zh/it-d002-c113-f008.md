# 集成测试与接口测试的发布说明与运营报告汇总：工作流编排

## 这个品类的数据长什么样
该品类的数据由测试工程师、测试开发团队、接口平台维护人员的日常工作产出与环境数据组成，日常文档包含接口测试用例、联调问题单、环境说明、测试报告。数据来源覆盖接口管理平台、测试环境日志、数据库、消息队列，包含接口请求路径、请求方法、响应码、执行耗时、联调问题单号等字段。数据更新频率为每日或随版本发布周期同步，整体按测试版本、接口模块进行分类存储，无固定聚合格式，需按测试场景灵活提取，当前适配FastGPT v4.17.0版本的工作流编排逻辑。

## 这些特征在「工作流编排」这一环带来什么约束
因为数据来源分散且无固定聚合格式，工作流编排需配置多源数据拉取节点，分别对接接口管理平台、测试日志、数据库与消息队列，避免遗漏跨模块交互的关键数据。由于数据更新频率为日/每版本，工作流需支持按定时周期或版本发布事件触发运行，确保汇总内容与当前测试进度同步。日常文档包含明确的测试用例ID、联调问题单号等标识字段，工作流需绑定对应字段作为流转变量，便于后续关联问题单与测试结果。依赖服务准备与接口参数核对为最耗时环节，工作流需前置配置依赖服务状态校验、接口参数自动核对节点，减少人工干预耗时，避免出错导致服务间调用失败、联调延期或验收阻塞。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源节点配置 | 关联接口管理平台、测试环境日志、消息队列三个数据源 | 覆盖接口请求、链路日志、异步通知三类核心数据 |
| 触发规则配置 | 按版本发布周期触发，或每12-24小时拉取一次 | 匹配数据日/每版本的更新频率 |
| `variables`配置 | 绑定接口路径、响应码、测试用例ID三个变量 | 匹配日常文档的核心标识与业务字段 |
| 失败处理配置 | 触发告警并重试1-3次后终止流程 | 避免出错导致联调延期、验收阻塞 |
| `nodeId`配置 | 按接口模块分组设置节点ID | 便于后续按模块拆分汇总的运营报告 |

## 容易做错的三处
- 工作流运行时出现`Failed to create post presigned url`报错，原因是未正确配置文件存储节点的权限参数，导致无法生成预签名URL。
- 知识库搜索模块的变量引用未正确绑定`variables`参数，导致测试用例ID、接口路径等字段为空，无法生成对应发布说明与运营报告。
- 未按接口模块分组配置`nodeId`，导致汇总的运营报告无法按模块拆分，排查链路问题时需要手动筛选大量数据。

## 怎么确认配好了
- 手动触发一次工作流，检查是否能拉取到指定数据源的接口请求日志与测试用例数据。
- 验证`variables`参数绑定的字段是否能在工作流节点中正常调用，生成对应字段的汇总内容。
- 模拟依赖服务异常的场景，检查失败处理节点是否能触发告警并执行重试逻辑。
- 查看生成的运营报告，确认是否按接口模块分类展示了对应测试数据。
