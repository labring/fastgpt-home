# 项目文档移交归档的发布说明与运营报告汇总：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自项目文档库、配置清单、会议纪要、测试报告。日常产出的文档包括竣工文档、配置手册、培训记录、验收证书。数据更新节奏为项目各阶段交付后或单项目结束时同步更新。文档通常包含项目编号、版本标识、文档类型、签章状态、移交对象等字段，无统一固定格式，需按项目定制化整理。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的文档更新频率不均，单项目移交时可能一次性导入大量历史文档，需严格控制上下文承载量以避免token超标。不同项目的文档字段差异较大，上下文召回时需精准匹配项目相关内容，避免无关文档混入。竣工文档、验收证书等核心移交材料的token占比偏高，需优先分配token配额，同时防止非核心文档挤占上下文空间。会议纪要等碎片化文档较多，需合理设置上下文召回条数，避免冗余内容干扰核心信息提取。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文条数 | 前20条 | 匹配项目文档按阶段更新的节奏，避免过多历史文档污染上下文 |
| `maxContext` | 15–25条 | 适配单项目移交的文档数量，平衡召回精度与token占用，符合FastGPT v4.17.0的参数逻辑 |
| 单次召回token上限 | 8000 token | 避免单批次召回内容超出通用大模型的上下文限额 |
| `quoteMaxToken` | 6000–10000 token | 匹配竣工文档、验收证书等核心材料的平均token长度，保障核心信息完整 |
| 上下文召回相似度阈值 | 0.75–0.85 | 区分项目专属文档与通用模板，减少无关内容混入 |
| 单次召回文档数量 | 前8条 | 适配碎片化的会议纪要、培训记录等文档类型，控制整体token消耗 |

## 容易做错的三处
- 配置`maxContext`为30条但对话明细仅显示2条：原因是未同步设置`quoteMaxToken`的取值，超出token上限后系统自动截断了早期上下文内容。
- 大模型提示上下文token数超标：原因是未针对竣工文档、验收证书等长文档调整`quoteMaxToken`，导致核心移交材料占用过多token空间。
- 回复出现非预期Json格式内容：原因是召回的配置手册、测试报告中包含结构化代码块，未通过上下文过滤规则排除非业务相关的格式内容。

## 怎么确认配好了
- 导入单项目的典型文档组，查看上下文召回列表，确认仅包含该项目的竣工文档、验收证书等核心材料。
- 模拟多轮业务对话，检查大模型回复是否能关联对应阶段的会议纪要、培训记录内容，无无关项目的文档信息。
- 查看系统运行日志，确认未出现token超限报错，且上下文条数与配置的`maxContext`取值一致。
- 测试长文档导入场景，确认`quoteMaxToken`生效，未出现核心内容被过度截断的情况。
