# 项目文档移交归档的发布说明与运营报告汇总：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自项目文档库、配置清单、会议纪要、测试报告，对应文档包括竣工文档、配置手册、培训记录、验收证书。数据更新节奏为项目阶段结束或整体项目收尾时产生，单份文档通常包含项目配置参数、验收节点记录、运维指引等结构化字段与非结构化文本内容，无固定单次提交的固定体量，需随项目进度逐步归集。

## 这些特征在「定时任务与自动化」这一环带来什么约束
该品类的数据归集节奏随项目阶段灵活变化，无固定周期，因此定时任务无法仅依赖固定间隔触发，需绑定项目节点事件触发执行。文档类型包含结构化配置清单、非结构化会议纪要等多样格式，自动化流程需适配不同文档的校验规则，分别完成完整性检查与版本核对。单次归集的文档体量波动较大，任务执行的资源分配需支持弹性调整，避免因资源不足导致执行中断。归档后需留存完整版本链，自动化流程需自动记录版本变更日志，防止版本不一致引发验收问题。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的定时任务模块。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 任务触发时机 | 绑定项目节点事件，或按项目周期设置为每15-30天执行一次 | 数据更新随项目阶段变化，固定间隔无法适配灵活的归集节奏 |
| 文档校验规则组 | 按文档类型预设（竣工文档检查签章完整性、配置手册核对参数一致性） | 不同文档的校验逻辑差异较大，需分类配置 |
| 单次执行最大文档数 | 前20条 | 避免单次归集量过大导致执行超时 |
| 任务超时阈值 | 1800秒 | 单份文档校验与归档的平均耗时需预留足够缓冲 |
| 版本日志留存路径 | 绑定项目专属归档目录 | 需与项目文档统一存储，便于后续追溯 |
| 异常告警触发条件 | 任务失败或校验不通过时触发 | 需及时通知相关人员处理执行错误 |

## 容易做错的三处
- 现象：任务执行后出现「字段为空」报错，原因：未配置对应文档类型的必填字段校验规则，导致未归集的配置清单参数缺失。
- 现象：执行跨项目文档校验时出现「检索源不匹配」报错，原因：未配置按项目标识自动切换检索知识库的规则，导致调用了错误的知识库配置。
- 现象：归档后的文档出现版本不一致问题，原因：未设置版本自动比对规则，导致归集的文档与历史版本存在参数差异未被拦截。

## 怎么确认配好了
- 手动触发一次测试任务，核对执行日志中是否包含当前项目的所有待归集文档列表，无遗漏的归集项。
- 查看任务配置页面的触发规则，确认绑定的项目节点事件与当前项目的进度匹配，无无效触发条件。
- 模拟一次校验失败的场景，确认异常告警通知能正常推送至预设的接收渠道。
- 查看项目专属归档目录，确认测试任务生成的版本日志与归档文档已按预设路径留存。
