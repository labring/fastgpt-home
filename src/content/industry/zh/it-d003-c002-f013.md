# IT服务台工单处理的安全与合规材料审查：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据包含服务请求单、事件工单、处理记录、用户满意度表四类核心文档，数据来源覆盖ITSM系统、电话或在线聊天记录、资产系统与内部知识库。数据更新节奏为日级或实时，核心字段包括工单唯一标识、请求人身份标识、受理人信息、问题分类标签、处理状态、满意度评分等，单条数据体量与业务场景强相关，无固定统一的标准化字段单位要求。

## 这些特征在「权限与数据隔离」这一环带来什么约束
该品类的数据特征对权限与数据隔离带来多重约束。多来源混合的数据需覆盖ITSM、聊天记录、资产系统等不同数据源的访问范围，避免非授权人员查看资产系统关联的敏感硬件信息。实时更新的工单数据要求权限校验逻辑同步生效，无法仅通过批量离线校验覆盖全量实时工单场景。工单绑定请求人、受理人等身份字段，要求权限隔离需匹配多角色访问边界，仅允许对应角色查看自身关联的工单。用户满意度表包含未公开的员工评价信息，需单独设置隔离规则，避免非管理角色越权查看。同时，不同团队的工单需按`teamId`维度隔离，确保跨团队数据不泄露。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 团队权限隔离规则 | 按`teamId`绑定角色权限 | 匹配IT服务台按团队划分的工单归属，实现跨团队数据隔离 |
| 角色访问范围 | 限定为自身关联的工单数据 | 基于工单的请求人、受理人字段实现精准权限控制 |
| 敏感数据访问开关 | 关闭非授权角色的资产系统数据访问 | 避免资产系统中的敏感硬件信息泄露 |
| 实时数据校验周期 | 10–30 秒 | 适配工单数据的日级或实时更新节奏 |
| 全局变量隔离规则 | 按`tmbId`区分作用域 | 实现不同使用者ID隔离同名全局变量的需求 |
| 单次工单数据展示上限 | 前 20 条 | 适配IT服务台工单列表的常规展示需求 |
| 单点登录（SSO）配置 | 仅对商业版授权用户开放 | 符合企业内部身份认证的合规要求 |

## 容易做错的三处
- 现象：非商业版用户配置SSO功能时，界面提示功能未开放，无法完成保存。原因：SSO功能仅对商业版授权用户开放，未授权版本无法启用该配置。
- 现象：不同使用者调用同名全局变量时，返回了不属于自身的取值，出现数据串扰。原因：未按`tmbId`配置全局变量的作用域隔离规则，导致不同使用者共享变量存储空间。
- 现象：切换团队后，调用tokenLogin接口获取的团队数据未更新，界面仍展示旧团队的工单列表。原因：未配置团队数据的实时存储更新逻辑，缓存中的团队权限信息未同步刷新。

## 怎么确认配好了
- 发起测试工单，使用非授权角色账号登录，尝试查看不属于自身关联的工单数据，确认访问被拒绝。
- 配置全局变量隔离规则后，使用两个不同使用者ID的账号分别调用同名全局变量，确认返回的取值互不影响。
- 切换团队后，调用tokenLogin接口，确认返回的团队数据与当前登录的团队信息匹配。
- 尝试在非商业版环境中配置SSO功能，确认界面提示功能未开放，无法保存配置。
