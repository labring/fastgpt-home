# IT采购与供应商管理的安全与合规材料审查：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据主要来自企业内部采购系统、供应商报价文档、预算表、合同系统。日常产出的文档包括采购申请单、比价记录、正式合同、验收单据。数据更新以单次采购流程为周期，每完成一单更新一次，月度汇总类数据则按月更新。单份文档包含采购单号、供应商资质编号、预算额度、合同条款摘要、验收节点等字段，涉及金额、天数等单位。

## 这些特征在「权限与数据隔离」这一环带来什么约束
该品类的数据分散于多套内部系统，且包含预算额度、合同条款等敏感信息，要求权限需匹配不同岗位的职责边界。单份数据以采购单为独立单元，不同采购项目的文档需严格隔离，避免跨项目权限泄露。数据更新随采购流程推进，权限配置需适配流程节点变化，确保仅参与当前项目的人员可访问对应文档。部分文档仅允许法务、财务等核心岗位查看，普通实习生无法访问敏感内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 团队权限组 | 按采购部门、项目组划分 | 匹配该品类按采购团队、项目管理的业务结构，确保同组人员共享对应采购文档权限。 |
| `teamId` 绑定 | 与采购项目的`teamId`绑定 | 该品类数据以采购单为独立单元，通过`teamId`可精准关联单份采购流程的所有文档，实现项目级隔离。 |
| 敏感数据访问限制 | 仅允许法务、财务岗位账号访问 | 该品类的合同、预算文档属于高敏感内容，需限制非核心岗位人员访问。 |
| 实习生账号权限 | 仅开放公开文档查看权限 | 实习生无需接触完整采购流程的敏感数据，仅可查看采购申请模板等公开内容。 |
| 权限过期配置 | 按采购项目周期设置`7–30 天`有效期 | 该品类数据更新以采购单为周期，权限随项目结束自动失效，避免长期权限残留。 |
| 引用文档展示范围 | 仅展示当前权限内的文档条目 | 避免返回无权限访问的文档引用，符合安全与合规审查要求。 |

## 容易做错的三处
- 现象：非授权成员可访问敏感采购文档，如合同条款或预算额度。原因：未将文档与`teamId`正确绑定，仅配置了全局权限组，未实现项目级隔离。
- 现象：实习生账号可查看完整的合同与预算文档。原因：未针对实习生账号单独配置权限范围，误将公开权限与核心岗位权限混淆。
- 现象：已分配写权限的成员无法创建对应采购项目的知识库。原因：未使用`teamId`关联对应采购项目的团队，权限配置未匹配项目所属的业务单元。

## 怎么确认配好了
- 选取一个非授权账号，尝试访问对应采购项目的合同文档，确认无法打开或查看受限内容。
- 检查知识库的权限绑定关系，确认所有关联的采购文档均已绑定对应`teamId`。
- 提交一次采购流程的文档查询，确认返回的引用条目仅包含当前账号有权限访问的文档。
- 在 FastGPT v4.17.0 版本中，验证权限过期配置，在模拟项目结束后，确认原授权账号无法再访问对应文档。
