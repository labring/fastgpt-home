# IT采购与供应商管理的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
这个品类的日常文档包含采购申请、比价记录、合同、验收单，数据主要来自采购系统、供应商报价文件、预算表、合同系统。数据更新以单次采购流程为单位，单采购单完成即更新，月度汇总类数据按自然周期更新。文档结构包含采购主体、金额范围、供应商资质、条款细则等字段，无统一强制单位，部分字段需结合企业内部采购规则适配。

## 这些特征在「模型接入与配置」这一环带来什么约束
多来源的数据格式差异要求模型接入时适配不同文件的解析规则，避免因格式不兼容丢失关键合规信息。单采购单的更新节奏决定了模型上下文无需过长，可通过限制`maxContext`范围提升调用效率。文档中的合规条款、金额核对等核心字段，要求模型输出具备较高一致性，需严格控制参数避免过度随机性。同时，采购流程的出错后果直接关联企业合规风险，模型配置需优先保障输出的准确性与合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配采购与合同文档的平均长度，避免截断关键合规条款 |
| `maxTokens` | 2000–3000 token | 适配采购审批、合规审查的输出长度需求，避免输出不完整 |
| `temperature` | 0.2–0.4 | 降低输出随机性，保证合规条款核对与金额计算的一致性 |
| `toolChoice` | auto | 按需调用合规校验工具，适配多文档交叉核对的采购场景 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions路径，不得配置为VLLM/Ollama/Xinference等单模型服务地址 | 确保模型调用链路正常，避免连接失败 |
| `AIPROXY_API_TOKEN` | AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空 | 保障模型调用权限与数据传输安全 |

## 容易做错的三处
- 进入工作台编辑页面报错“未配置语言模型”：原因是未在App/Admin服务端配置必填的`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`环境变量，导致服务启动校验失败。
- 在线对话与API调用返回结果差异大：原因是未统一配置`temperature`参数，且API调用时未显式指定`maxContext`与`maxTokens`，导致不同调用链路的上下文处理逻辑不一致。
- doubao 1.6模型输出完思考内容后不输出正文：原因是`maxTokens`取值过低，正文内容被截断，或`toolChoice`配置为强制调用工具导致输出流程异常。

## 怎么确认配好了
- 检查App/Admin服务端是否已配置`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`环境变量，且配置值符合官方要求。
- 配置`temperature`、`maxContext`、`maxTokens`参数后，导入单份采购申请文档进行测试，核对输出是否覆盖所有关键合规字段。
- 分别发起在线对话与API调用，对比两者的输出格式与内容完整性，确认参数配置统一。
- 查看系统日志，确认无模型调用失败或参数解析异常的记录。
