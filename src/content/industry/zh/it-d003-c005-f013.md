# Issue分拣与响应的安全与合规材料审查：权限与数据隔离

## 这个品类的数据长什么样
该品类的典型使用主体为开源维护者、社区运营与核心贡献者。日常处理的文档包括Issue模板、标签规则、回复记录与问题复现说明。数据来源主要为GitHub或Gitee Issue、版本日志、用户环境信息与代码仓库。数据更新频率多为日级或周级，核心字段包含Issue状态、关联标签、创建时间、复现步骤与责任模块标记。不同应用关联的Issue数据相互独立，且需匹配对应仓库的访问权限范围。

## 这些特征在「权限与数据隔离」这一环带来什么约束
数据来源绑定外部仓库权限，要求权限配置需与仓库的访问权限对齐，避免无权限用户获取跨仓库的Issue数据。数据包含用户环境信息与问题复现细节，涉及隐私与合规要求，需隔离不同用户或团队的数据访问范围。数据更新频率为日或周级，权限变更需同步更新配置，确保数据访问权限与仓库权限保持一致。不同应用的Issue数据需按应用划分存储，避免跨应用的数据交叉泄露，保障合规审查的可追溯性。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 团队标识绑定 | 绑定对应仓库的 `teamId` | 匹配数据来源的仓库权限关联，实现跨仓库数据隔离 |
| 成员权限组配置 | 按 `tmbId` 分配1–5级权限 | 区分维护者、运营者与访客的操作范围，符合团队分工需求 |
| 免登录链接限额 | 10–100 个 / 应用 | 匹配订阅套餐的默认限制，支持按需调整 |
| 权限校验超时 | 300 秒 | 保障实时权限校验的响应速度，避免长时间等待 |
| 数据存储隔离 | 按应用划分独立存储目录 | 避免跨应用Issue数据交叉泄露 |
| 操作日志审计 | 开启全操作日志记录 | 留存合规审查所需的访问与操作痕迹 |

## 容易做错的三处
- 现象：创建免登录链接时返回403报错，提示超出限额。原因：未按订阅套餐调整免登录链接数量限制，默认配置仅支持10个链接。
- 现象：非授权成员可查看其他团队的Issue数据。原因：未绑定`teamId`与仓库权限，导致权限隔离失效，数据跨团队泄露。
- 现象：导出的对话内容包含无关应用的Issue数据。原因：未按应用划分数据存储目录，导致不同应用的数据交叉存储。

## 怎么确认配好了
- 尝试使用非授权成员的账号访问指定应用的Issue数据，确认无法查看对应内容。
- 创建免登录链接，验证当前限额与订阅套餐配置的数量一致。
- 查看操作日志，确认所有权限变更与数据访问操作均有完整记录。
- 导出指定应用的对话内容，确认仅包含该应用关联的Issue数据。
