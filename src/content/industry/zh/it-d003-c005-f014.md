# Issue分拣与响应的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据主要来自GitHub或Gitee Issue、代码仓库版本日志、用户提交的环境信息与问题复现说明。日常维护的文档包括Issue模板、标签规则、历史回复记录。数据更新频率以日或周为单位，每条数据包含问题描述、复现步骤、关联代码片段、用户环境参数等字段，无统一固定格式，需适配不同仓库的Issue提交规范。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源分散且格式不统一，模型接入时需适配多来源的非结构化文本与少量图片内容（如用户上传的报错截图）。数据更新频率较高，需配置支持动态增量索引的流程，避免全量重建带来的资源消耗。每条数据包含的字段差异较大，模型需具备灵活的意图识别能力，同时需限制单次处理的上下文长度，防止因输入过长导致调用失败。此外，安全与合规审查要求对Issue中的敏感信息、违规内容进行过滤，需在模型配置中加入对应校验环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配Issue中包含的多段问题描述、复现步骤与代码片段的总长度，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 控制单轮响应的输出长度，确保分拣结果清晰简洁，符合社区Issue回复的常规格式 |
| `vision` | 开启 | 支持识别用户上传的报错截图、日志截图等图片内容，匹配数据中包含的非文本合规材料 |
| `temperature` | 0.3–0.5 | 降低随机性，确保分类、合规校验的结果稳定一致，符合安全审查的确定性要求 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如http://aiproxy:3000 | 为App/Admin服务端必需配置的环境变量，不得附加/v1或/chat/completions等路径，不是单模型服务地址 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具，适配不同场景下的合规校验与分类需求 |

## 容易做错的三处
- 向量索引构建任务长期无进度，界面未显示索引完成或更新状态。原因是未适配Issue数据的非结构化特征，未配置对应的数据处理规则，导致索引流程无法正常触发。
- 中文输入时模型调用报错，英文输入返回异常格式。原因是未将模型的输入语言适配为中文，或配置的`temperature`参数区间不合理，导致模型输出不符合预期格式。
- 本地部署的VLM模型在FastGPT中的识别结果与直接调用接口的结果不一致。原因是未在FastGPT中正确配置`vision`参数的调用链路，或未将模型的输入格式与FastGPT的要求对齐。

## 怎么确认配好了
可通过以下动作核对配置效果，本核对流程适用于FastGPT v4.17.0版本：
- 提交一条包含文本与图片的测试Issue，查看模型是否能正确识别图片内容并完成分类。
- 查看模型调用日志，确认`maxContext`与`maxTokens`参数未触发溢出报错，响应长度符合预期。
- 测试不同语言的输入，确认模型在中文场景下的分类结果稳定，无格式异常。
- 检查App/Admin服务端是否已正确配置非空的`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`环境变量，确保服务启动校验通过。
