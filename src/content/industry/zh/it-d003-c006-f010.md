# Pull Request评审的安全与合规材料审查：引用来源与溯源
本页配置适用于FastGPT v4.17.0。

## 这个品类的数据长什么样
这个品类的典型数据来自代码仓库、CI流水线、Issue链接与贡献者提交，更新频率通常为日或周。日常文档包含PR说明、代码评审意见、CI结果与合并记录，字段涵盖PR编号、变更文件列表、评审人标识、CI通过率、关联Issue地址等，无统一固定的单位要求，数据结构随项目的评审规则动态调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源的分散性要求溯源环节需关联多平台的业务数据，避免仅检索单一仓库的内容；更新频率的周期性意味着溯源需支持增量拉取，无需重复处理全量历史数据。文档结构的灵活性要求溯源配置需适配不同项目的字段规则，不能硬编码固定字段。同时，该品类的出错后果直接影响主干分支稳定性，要求溯源结果需准确关联当前PR的变更内容，避免引入无关数据干扰评审。

## 配置怎么定
以下配置项对应FastGPT的核心参数：引用最大token数对应`quoteMaxToken`，返回数据范围对应`responseData`，溯源详情开关对应`detail`。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 引用最大token数 | 8000–12000 token | 覆盖PR说明、CI结果等典型合规材料的完整内容 |
| 返回数据范围 | 包含关联PR编号、CI日志链接、Issue地址 | 匹配PR评审的核心业务溯源需求 |
| 溯源详情开关 | 开启 | 展示引用来源的具体片段，便于评审核对合规性 |
| 单次召回上限 | 前3–5条 | 避免冗余数据干扰评审，符合PR评审的轻量化审查习惯 |
| 检索超时阈值 | 600 秒 | 适配开源项目的大规模数据检索需求，避免提前终止有效溯源 |

## 容易做错的三处
- 现象：对话中强制展示引用来源无法隐藏，原因：误将溯源详情开关设为开启，且未正确配置隐藏引用的参数。
- 现象：返回的引用来源未关联当前PR的变更内容，原因：未限定检索范围仅覆盖代码仓库、CI流水线、Issue链接的关联数据，导致检索到无关的业务文档。
- 现象：溯源检索出现超时错误，原因：设置了超出合理范围的引用最大token数取值，导致单次处理数据量过大。

## 怎么确认配好了
- 发起一条包含变更文件、CI结果的测试PR，触发合规审查流程，查看返回结果是否包含关联的PR编号、CI日志链接。
- 调整单次召回上限的取值，触发一次检索，确认返回的引用内容数量符合设定的范围。
- 查看FastGPT的运行日志，确认未出现与溯源检索相关的超时或字段缺失报错。
- 模拟合规审查的触发逻辑，确认仅检索与当前PR相关的业务数据，未引入无关的知识库内容。
