# Pull Request评审的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自代码仓库、CI流水线、Issue链接与贡献者提交内容。日常处理的文档包括PR说明、代码评审意见、CI结果与合并记录。数据更新节奏以日或周为周期，单条数据包含变更范围描述、CI校验结果、评审意见条目、贡献者信息与合并状态字段，无固定格式的标准化统计字段，仅随PR提交与处理流程动态生成，内容格式混杂文本、代码片段与结构化校验结果。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且格式多样，包含代码片段、文本说明与结构化校验结果，要求模型接入环节支持混合格式输入与上下文关联。数据更新节奏随PR提交周期动态变化，单次处理的上下文长度存在波动上限，需限制总token消耗避免调用超时。单条PR包含的评审意见与变更条目较多，模型调用时需控制单次处理的条目数量，防止超出模型上下文窗口。同时，数据关联代码仓库与CI结果，需确保模型调用时能正确绑定对应PR的上下文，避免混淆不同评审任务的处理数据。

## 配置怎么定
本文档基于FastGPT v4.17.0版本的配置逻辑编写，具体配置项与建议如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配PR的变更说明、评审意见与CI结果的总长度，避免超出通用大模型的上下文窗口限制 |
| `maxTokens` | 2000–3000 token | 控制单次模型输出的合规审查结果长度，适配评审场景的短结论输出需求 |
| `quoteMaxToken` | 1000–1500 token | 限制引用PR内原始文本的长度，确保审查内容聚焦核心变更与合规风险点 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保合规审查结果的一致性与准确性，避免出现主观偏差 |
| `AIPROXY_API_ENDPOINT` | 为AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径，非单模型服务地址 | 为App/Admin服务端必需配置的环境变量 |
| `AIPROXY_API_TOKEN` | 为与AI Proxy服务端配置一致的非空管理员Token | 为App/Admin服务端必需配置的环境变量，用于AI Proxy服务身份校验 |

## 容易做错的三处
- 现象：调用重排模型后GPU显存占用快速增长至6-7G，且每张GPU均出现占用。原因：未配置重排模型的并发调用限制，导致单次PR评审触发多个模型实例加载，超出单卡显存阈值。
- 现象：离线接入重排模型时提示`rerank error`，日志返回`{ message: { detail: '`。原因：未正确配置模型的本地存储路径，或依赖的库版本与FastGPT v4.17.0要求不匹配。
- 现象：接入国内自研模型时提示无效令牌，通过独立代理接口测试正常。排查项：检查App/Admin服务端`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`是否正确配置且与AI Proxy服务端配置一致；检查AI Proxy服务运行状态。

## 怎么确认配好了
- 检查App/Admin服务端配置的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`值与AI Proxy服务端配置一致，无拼写错误或多余空格。
- 提交一条测试PR，触发安全合规审查流程，查看平台日志是否返回正常的审查结果，无`rerank error`或无效令牌相关报错。
- 查看GPU资源监控面板，确认重排模型的显存占用稳定在合理区间，未出现异常飙升或多卡重复占用的情况。
- 测试包含代码片段与文本说明的混合格式PR，确认模型能正确识别并处理不同类型的输入内容，输出符合预期的审查结论。
