# SLA与服务报告的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源于监控系统、工单系统、服务合同及客户沟通记录，更新频率为月度或季度。日常产出文档包含SLA条款文本、月度服务报告、可用性统计报表、客户复盘纪要，核心字段包括服务周期时长、SLA达标项数值、异常事件发生时间、客户合同标识，字段单位涵盖小时、次、天等。合规审查需基于这些数据校验服务表现与合同条款的一致性，确保内容符合既定业务规则。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据多源分散的特征要求模型接入时支持多格式数据的统一解析，避免因输入格式不兼容导致提取错误。固定的月/季更新节奏，需要配置定时触发的模型调用任务，适配周期内数据量的波动。文档结构差异明显，从结构化的SLA条款到非结构化的复盘纪要，需配置适配不同文本体量的上下文参数。同时，合规审查要求模型准确校验数据与合同的一致性，需保障语义对齐精度，避免出现口径偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions，不得为单模型地址 | 为App/Admin服务端配置的必填环境变量，用于指定AI Proxy服务访问地址 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token，不能为空 | 为App/Admin服务端配置的必填环境变量，用于AI Proxy服务鉴权，不得使用应用API Key、模型供应商密钥等其他密钥 |
| `maxContext` | 8000–12000 token | 月度服务报告包含多源汇总文档，需容纳足够上下文以完成口径对齐与指标校验 |
| `temperature` | 0.1–0.3 | 合规审查需严格匹配既定业务规则，避免生成偏离标准的审查结果 |
| `maxTokens` | 2000–3000 token | SLA指标计算与异常归因的输出需承载足够细节，保障审查内容完整 |
| `toolChoice` | `auto` | 适配多源数据的解析需求，让模型自主选择是否调用数据提取工具 |

## 容易做错的三处
- 服务启动校验失败，或运行工作流时出现模型调用失败报错，排查项：未配置或配置错误`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或Token与AI Proxy服务端配置不一致
- 多渠道配置同一模型后，未按预期触发优先级调用。原因是未在模型接入配置中明确渠道优先级规则，或配置未生效。
- 审查结果显示找不到相关SLA条款信息，但知识库语义检索匹配度达标。原因是`maxContext`配置值过小，导致检索到的文本未被完整纳入模型上下文，无法完成匹配校验。

## 怎么确认配好了
- 核对App/Admin服务端的环境变量配置，确认`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，`AIPROXY_API_TOKEN`为与AI Proxy服务端配置一致的管理员Token
- 触发一次测试任务，查看工作流日志中的模型调用返回结果，确认能正常解析SLA报告与合同文本。
- 调整`maxContext`与`maxTokens`的配置值，根据测试任务的上下文溢出提示调整至合适范围。
- 模拟多渠道配置场景，验证模型调用时是否按预设规则选择对应渠道。
