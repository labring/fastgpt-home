# 专题活动运营的安全与合规材料审查：对话日志与审计

## 这个品类的数据长什么样
该品类的数据通常来自内容库、活动后台、流量数据及用户反馈，更新节奏为周度或节假日周期。日常文档包含活动方案、资源位排期、活动页面文案、复盘报告四类，字段涵盖活动唯一标识、文案内容、流量指标、用户反馈标签等，无固定统一的单位标准，随活动类型与运营需求调整。

## 这些特征在「对话日志与审计」这一环带来什么约束
该品类的数据多源且更新频繁，要求对话日志与审计环节需覆盖活动后台、内容库等多系统的日志采集，支持按活动周期划定审计范围。日常文档类型多样，审计规则需适配活动方案、页面文案等不同文档的合规校验逻辑。活动有明确周期，审计需关联活动时间线，避免跨周期的无效日志被纳入审查，同时需及时拦截违规内容，防止活动低参与或资源浪费。

## 配置怎么定
本配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chatId` | 限定为当前活动关联的`chatId`集合 | 专题活动运营的对话均绑定专属活动ID，可精准过滤无关会话日志 |
| `responseChatItemId` | 仅记录包含活动文案、用户反馈的`responseChatItemId`条目 | 聚焦与活动直接相关的对话内容，降低无效审计数据占比 |
| `detail` | 开启`detail`字段的全量采集 | 完整获取对话上下文细节，用于合规校验与问题回溯 |
| 审计日志保留周期 | 按活动周期匹配，最长保留 30 天 | 适配专题活动的时间周期，满足活动复盘与合规留存需求 |
| 异常告警触发阈值 | 检测到违规内容后 600 秒内触发告警 | 及时拦截违规内容，避免活动运营环节出现合规风险 |

## 容易做错的三处
- 调用模型后返回响应为空，日志显示`message`相关字段异常，原因是未正确配置`detail`字段采集，导致日志中缺失关键请求参数，无法定位模型调用异常。
- 循环体运行下标加1后输出结果为null，原因是未在对话日志中绑定活动专属`chatId`，导致循环逻辑关联的会话上下文丢失。
- 历史记录中包含指定回复插件的冗余内容，干扰合规审计，原因是未过滤`responseChatItemId`中标记为插件执行的条目，导致审计范围混入非活动核心对话。

## 怎么确认配好了
- 查看会话日志列表，确认仅显示当前活动关联的会话，无跨活动的无关日志。
- 导出单条对话的审计详情，确认`detail`字段已完整包含对话上下文与请求参数。
- 模拟触发违规内容，验证告警是否在设定时间内触发。
- 检查历史记忆调用的日志，确认已过滤指定回复插件的冗余条目。
