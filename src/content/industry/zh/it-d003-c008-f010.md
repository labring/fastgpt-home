# 专题活动运营的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据主要来自内部内容库、活动后台管理系统、流量统计工具及用户反馈渠道。日常产出的核心文档包含活动执行方案、资源位排期表、活动页面宣传文案、活动复盘报告四类，字段涵盖活动周期、资源位编码、文案合规性校验结果、流量转化数据等。数据更新以周为常规周期，节假日前后会根据活动筹备节奏临时调整更新频次。

## 这些特征在「引用来源与溯源」这一环带来什么约束
明确的活动周期要求引用溯源需绑定对应活动的时间范围，避免跨活动引用无关材料，确保合规审查仅覆盖当前执行的活动内容。多类型文档并存的结构，要求溯源系统支持按文档类型筛选关联来源，避免将活动文案与复盘报告混淆。数据来源分散的特点，需要溯源功能打通内容库、活动后台等多个数据源的权限与索引，确保所有关联材料均可被检索到。活动周期内的临时更新，要求溯源支持实时同步最新版本的活动材料，确保引用内容与当前执行版本一致。资源位相关数据的溯源，需要关联资源位编码字段，避免出现资源位与宣传文案不匹配的合规问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配活动方案、宣传文案的单页内容长度，避免截断合规校验的关键条款 |
| `responseData` | 开启 | 专题活动运营需明确展示合规审查的材料来源，符合安全合规审查的要求 |
| `detail` | 按活动周期筛选 | 适配专题活动有明确时间范围的特征，避免返回无关历史活动的引用数据 |
| 单次引用条数上限 | 前3条 | 控制页面展示的引用数量，避免信息过载影响活动运营人员快速查阅 |
| 引用来源同步频率 | 1次/周+临时触发 | 匹配数据更新的常规节奏，节假日筹备的临时活动可手动触发同步更新 |

## 容易做错的三处
- 现象：配置关闭`responseData`开关后，问答结果仍展示文档引用内容。原因：FastGPT v4.17.0 中该开关的缓存未及时清理，需重启服务或重新部署配置生效。
- 现象：引用来源无法匹配到活动资源位排期表。原因：未配置按资源位编码字段的索引规则，导致系统无法关联活动宣传文案与对应的资源位数据。
- 现象：引用内容截断了活动方案中的合规校验说明。原因：`quoteMaxToken` 设置值过小，未覆盖合规条款的完整长度。

## 怎么确认配好了
- 上传一份测试用的活动方案文档，发起关联问答，检查返回结果中是否展示了该文档的文件名及对应内容片段。
- 调整`quoteMaxToken`的取值，上传包含长合规条款的测试文档，验证完整内容是否被完整展示，未出现截断情况。
- 关闭`responseData`开关，发起相同的问答，确认结果中不再附带任何文档引用信息。
- 筛选指定活动周期的测试文档，发起问答，检查仅返回该周期内的材料引用，无跨周期的无关历史活动内容。
