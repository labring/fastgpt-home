# 专题活动运营的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
通常，专题活动运营的数据来自内容库、活动后台、流量数据与用户反馈。日常处理的文档包括活动方案、资源位排期、活动页面文案、复盘报告，文档多包含活动ID、资源位编号、流量指标、审核状态等结构化字段，更新频率以周或节假日节点为周期，单份文档的篇幅跨度较大，从简短的活动通知到数十页的复盘报告均有覆盖。

## 这些特征在「文档解析与分块」这一环带来什么约束
活动文档的层级化结构与结构化字段，要求解析分块需保留标题与段落的对应关系，避免拆分后丢失活动阶段、资源位分配等核心关联信息。高更新频率的活动材料，需要适配增量解析与批量上传的需求，同时大型复盘报告可能占用较长解析时长。活动材料的合规审查需精准定位敏感内容，分块不宜过碎导致上下文断裂，也不宜过大导致审查遗漏，同时需保留表格、图片等非纯文本内容的解析结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 活动方案、复盘报告多为长文本，该区间可保留活动周期、资源位等核心信息不被截断 |
| `chunkSplitter` | 按段落+标题拆分 | 活动文档多含层级化标题（如活动主题、执行步骤），保留结构便于合规审查定位 |
| `customPdfParse` | 开启 | 活动文档常以PDF格式提交，开启后可提取内嵌图片文本与排版信息 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 活动相关素材包可能包含多页PDF、排期表格合集，适配批量上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型活动复盘报告解析耗时较长，避免因超时导致解析失败 |
| `chunkSettingMode` | 手动配置 | 活动文档结构差异大，手动调整可适配不同类型的活动材料 |

## 容易做错的三处
- 上传活动相关PDF后解析超时，界面显示请求失败。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认时长不足以解析大型复盘报告。
- 上传表格格式的资源位排期后，部分数据丢失。原因是未开启`customPdfParse`或未配置对应分块规则，导致结构化表格字段被截断。
- 导出导入知识库后，活动文案的图片解析结果丢失。原因是未打包关联的图片文件，或未在新服务器开启`customPdfParse`配置。

## 怎么确认配好了
- 上传一份典型的活动方案PDF，检查解析后的分块是否保留了活动主题、执行步骤等层级化内容。
- 上传超过500 MB的活动素材包，确认上传进度正常，未触发文件大小超限提示。
- 等待解析完成后，查看日志确认未出现超时报错，分块数量与文档页数匹配。
- 导出当前知识库的活动材料，导入至FastGPT v4.17.0的测试环境后，确认所有结构化数据与原文档一致。
