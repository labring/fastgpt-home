# 专题活动运营的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
专题活动运营的核心数据来源于内容库、活动后台、流量数据及用户反馈。日常产出的文档包含活动方案、资源位排期、活动页面文案、复盘报告四类，各文档字段包含活动周期、资源位编号、文案字数、流量转化指标等。数据更新节奏以周为单位，节假日前后会额外同步活动筹备及收尾数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源分散且包含多类结构化、非结构化文档，模型接入环节需要适配多数据源的格式与同步频率。活动周期明确且存在节假日临时更新的需求，需配置符合更新节奏的触发规则。不同文档的内容长度差异较大，从短文案到长复盘报告均有覆盖，需调整模型处理的上下文与输出长度参数。合规审查的准确性直接影响活动落地效果，需稳定的模型输出逻辑以避免审核遗漏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxTokens` | `4000–8000 token` | 适配活动页面文案、复盘报告的常规内容长度 |
| `maxContext` | `8000–12000 token` | 覆盖活动全周期的上下文关联数据，支持跨文档审查 |
| `temperature` | `0.2–0.4` | 降低输出随机性，保障合规审查结果的稳定性 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 http://aiproxy:3000 | 为 AI Proxy 服务的根地址，不可附加 /v1 或 /chat/completions，非单模型服务地址 |
| `quoteMaxToken` | `1000–1500 token` | 预留足够空间引用活动方案、资源位排期等参考文档 |

## 容易做错的三处
- 现象：模型渠道配置页面提示无法连接API端点，报错状态码500或404。原因：未正确配置App/Admin服务端的AIPROXY_API_ENDPOINT环境变量，地址格式或端口配置错误。
- 现象：合规审查结果被截断，仅返回部分内容。原因：`maxTokens`参数设置过低，未匹配活动文案或复盘报告的实际内容长度。
- 现象：工作流全局变量未正确获取发布渠道的API访问链接。原因：未将发布渠道生成的API链接绑定到工作流的全局变量配置项中，变量赋值逻辑缺失。

## 怎么确认配好了
- 确认App/Admin服务端已正确配置AIPROXY_API_ENDPOINT环境变量，值为AI Proxy服务的根地址。
- 上传单篇活动页面文案，触发合规审查任务，查看返回结果是否完整无截断。
- 启动绑定了全局变量的工作流，查看变量日志确认发布渠道的API链接已正确赋值。
- 调整`temperature`参数至0.3，提交多篇不同类型的活动文档，验证输出结果的稳定性符合合规审查需求。
