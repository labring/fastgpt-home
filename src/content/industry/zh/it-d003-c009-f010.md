# 个人信息保护合规的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据主要来自业务系统、App权限清单、隐私政策、用户请求记录，更新频率为季度或每次产品版本变更时。日常处理的文档包括个人信息清单、数据处理规则、个人信息保护影响评估报告、用户授权文本等，文档结构多包含信息字段、处理目的、合法性基础、存储周期等核心字段，无统一强制单位，部分文档需关联自然人信息标识字段。数据分散于多类业务与用户端文档，需精准匹配来源与版本才能满足合规审查要求。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且关联业务系统与用户端文档，要求溯源时需精准匹配文档来源标识，避免混淆不同业务场景的合规材料。更新频率随产品变更波动，需确保引用的材料为最新版本，否则会导致审查依据失效。文档类型多样，不同文档的字段权重不同，需针对性调整检索逻辑以聚焦核心合规内容。涉及自然人信息的字段需严格隔离溯源链路，避免敏感信息在引用环节泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配本品类单份合规文档的平均长度，避免截断核心合规依据 |
| `responseData` | 仅返回合规文档字段 | 过滤非必要内容，聚焦个人信息清单、评估报告等核心合规材料 |
| `detail` | 开启完整溯源 | 展示文档来源、更新时间与关联字段，满足合规审查的溯源要求 |
| 单次检索上限 | 前6条 | 控制审查材料的数量，避免冗余信息干扰合法性基础确认 |
| 源数据同步周期 | 按产品变更触发 | 匹配本品类的更新频率，确保引用的材料为最新版本 |

## 容易做错的三处
- 对话界面显示未配置的非合规文档引用。未配置`responseData`参数为仅返回合规类文档，导致检索范围覆盖了非目标数据源。
- 本地未导入合规知识库却生成引用条目。未关闭全局默认知识库的自动关联，或源数据同步链路未隔离非合规业务数据。
- 混合检索场景下出现低相关度的引用内容。未针对不同合规文档类型设置差异化的检索匹配规则，导致非核心字段的内容被召回。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，导入单份合规文档，发起对应审查问题，检查返回的引用是否仅来自目标合规数据源。
- 关闭所有非合规知识库，发起测试请求，确认未出现未配置数据源的引用条目。
- 调整`quoteMaxToken`参数，验证输出的引用内容是否未被截断核心合规字段。
- 发起混合检索测试，检查是否可通过配置过滤非目标类型的合规文档引用。
