# 个人信息保护合规的安全与合规材料审查：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据主要来自业务系统、App权限清单、隐私政策、用户请求记录，更新频率为季度或每次产品版本变更。日常处理的文档包含个人信息清单、处理规则、影响评估报告、用户授权文本，单份文档包含信息字段、处理目的、合法依据、存储周期、授权范围等内容，由隐私合规团队、安全咨询或法务部门定期维护整理，单份文档的体量随项目规模有所差异。

## 这些特征在「权限与数据隔离」这一环带来什么约束
数据来源分散且关联业务系统，要求隔离不同业务线的合规材料，避免跨部门越权访问。更新频率随产品变更调整，需支持临时权限调整以适配快速迭代。文档包含自然人相关敏感信息，需严格限制访问范围，仅授权对应业务或合规人员。单份文档内容复杂且关联多环节，需确保权限配置与文档所属项目、团队绑定，避免权限混淆。同时需隔离不同租户的合规材料，防止数据泄露或跨租户访问，匹配合规要求对应的追溯与审计需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `teamId`权限关联 | 绑定对应合规项目的团队ID | 匹配合规材料按业务团队分组的存储逻辑 |
| `tmbId`租户隔离 | 为每个合规租户分配独立`tmbId` | 防止跨租户合规材料泄露 |
| 访问权限时效 | 临时权限设为7天，永久权限走审批流程 | 适配季度更新与临时项目需求 |
| 文档存储配额 | 单项目不超过5000 MB | 适配单份合规文档的平均大小与批量存储需求 |
| 超范围访问触发 | 开启跨团队访问审批 | 避免越权访问合规敏感材料 |
| 访问日志留存 | 保留180天访问记录 | 满足合规审计的追溯要求 |

## 容易做错的三处
- 现象：跨团队合规材料被无权限成员正常访问，接口返回成功状态但未拦截。原因：未将`teamId`与合规项目绑定，权限配置未生效。
- 现象：训练后的知识库内容无法导出，提示目标数据字段为空。原因：未按`tmbId`划分租户数据空间，导出接口无法匹配对应租户的存储数据。
- 现象：合规文档的访问日志未被正确记录。原因：未开启访问日志留存配置，或留存时长设置不符合审计要求。

## 怎么确认配好了
- 登录FastGPT v4.17.0的后台管理界面，查看`teamId`绑定的团队列表，确认合规项目的对应团队已被添加到权限配置中。
- 使用非授权成员账号尝试访问指定合规文档，确认系统触发权限拦截或跨团队访问审批流程。
- 调用指定租户的导出接口，确认返回的数据包含对应`tmbId`下的合规文档内容。
- 查看访问日志列表，确认每条记录包含访问时间、操作人账号、访问文档ID等必要信息。
