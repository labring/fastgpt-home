# 个人信息保护合规的安全与合规材料审查：模型接入与配置
本文适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的数据主要来自业务系统导出的结构化文档、App权限清单、公开的隐私政策文本以及用户请求记录。日常处理的文档包括个人信息清单、数据处理规则、个人信息保护影响评估报告、用户授权文本等，所有数据均围绕可识别自然人的信息处理环节生成。数据更新频率随产品版本变更或季度周期调整，由隐私合规团队、安全咨询机构及法务部门负责维护与更新。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征对模型接入与配置带来多重约束。首先，多来源的合规文档格式差异较大，需要模型适配不同结构的文本解析；其次，数据更新频率较高，要求模型接入链路支持动态数据源的快速接入与处理；再次，合规审查的严谨性要求模型输出需严格匹配原始文档内容，避免生成无依据的判断；最后，数据涉及自然人信息，需严格限制数据流转范围，避免配置不当导致信息泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 需要容纳多份合规文档的完整上下文，避免截断个人信息清单、影响评估报告中的关键合规内容 |
| `maxTokens` | `2000–3000 token` | 用于单份合规文档的分析输出，平衡内容完整性与响应速度，适配日常审查的批量处理需求 |
| `quoteMaxToken` | `1500 token` | 精准引用隐私政策、用户授权文本中的合规条款，限制引用长度以保证上下文连贯，避免冗余内容干扰判断 |
| `temperature` | `0.1–0.3` | 合规审查需要严谨一致的输出，较低的温度参数可减少生成不确定的合规判断内容 |
| `toolChoice` | `auto` | 自动调用合规文档解析工具，适配多类型合规材料的处理流程，减少人工配置成本 |
| `AIPROXY_API_ENDPOINT` | 为AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions，不得填写VLLM/Ollama/Xinference等单模型地址 | 作为App/Admin服务端必需的环境变量，确保模型请求通过合规的AI Proxy链路转发 |

## 容易做错的三处
- 排查项：调用模型时返回错误码400，可验证App/Admin服务端是否存在启动校验失败问题，即未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`这两个必需的服务端环境变量。
- 现象：模型输出的合规判断与原始文档内容偏差较大，原因：`maxContext`取值过小，导致关键合规条款被截断，模型无法获取完整的上下文信息。
- 现象：处理图片类合规附件时出现数据泄露风险，原因：未关闭前端直传链路，导致图片实体直接发送至外部服务，违反个人信息保护的合规要求。

## 怎么确认配好了
- 上传单份个人信息清单文档，发起模型审查请求，检查输出的可识别自然人信息字段是否完整覆盖原始文档内容。
- 检查App/Admin服务端的启动日志，确认未出现缺少`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`的启动校验失败提示，确认这两个必需的服务端环境变量已正确配置。
- 调整`temperature`参数至0.1，多次发起相同的合规审查请求，检查输出的判断内容是否一致，确认参数生效。
- 导入多份更新后的合规文档，检查模型处理速度是否符合业务更新的节奏要求，确认动态数据源适配正常。
