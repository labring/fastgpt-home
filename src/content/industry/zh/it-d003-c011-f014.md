# 云主机交付与资源开通的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自云管理平台、订单系统、IAM权限系统与计费系统，更新节奏为每单实时同步。日常处理的文档包括资源开通单、实例配置表、账号权限申请单与交付确认单，数据字段包含实例规格、权限范围、计费项、交付状态等，各系统原生数据格式存在差异，需通过接口对接获取标准化后的业务数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
多数据源的接入需求要求模型配置支持多接口对接，需分别适配各系统的鉴权规则。实时更新的特性要求模型调用需匹配业务流程的触发时机，避免延迟处理导致的合规风险。固定的业务文档结构要求模型提示词需匹配各单据的字段定义，确保审查结果覆盖必要的合规项。同时，出错后果直接影响客户部署与计费，配置需保证校验逻辑的稳定性与准确性，减少资源错开或计费争议的概率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions路径 | 为AI Proxy依赖的服务端环境变量，指定AI Proxy服务访问地址 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的非空管理员Token | 为AI Proxy依赖的服务端环境变量，用于AI Proxy服务的身份鉴权 |
| `maxContext` | 8000–12000 token | 适配单订单包含的多份业务文档的总上下文长度 |
| `maxTokens` | 2000–3000 token | 保证合规审查结果的完整输出，避免截断关键校验信息 |
| `temperature` | 0.1–0.3 | 降低模型输出的随机误差，保证合规校验结果的一致性 |
| `toolChoice` | "auto" | 自动调用合规校验工具与系统API，适配多数据源的接入场景 |

## 容易做错的三处
- 现象：调用后返回`chat:LLM_model_response_empty`错误，排查项：检查`AIPROXY_API_TOKEN`是否为与AI Proxy服务端配置一致的非空管理员Token，检查`AIPROXY_API_ENDPOINT`是否为AI Proxy服务根地址且未附加额外路径
- 现象：同一合规校验请求返回不一致结果，原因：未固定rag模式的上下文召回规则，误配置了非必要的模型微调参数，导致每次调用的匹配逻辑存在差异。
- 现象：合规审查结果遗漏部分字段，原因：`maxContext`取值过小，未加载完整的资源开通单与实例配置表内容，导致模型无法覆盖全部合规校验项。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`是否为符合要求的服务端环境变量，确认服务启动校验通过
- 提交一份标准的资源开通单测试数据，查看模型返回的合规审查结果是否覆盖了实例规格、权限范围、计费项等核心字段。
- 模拟多次相同的合规校验请求，确认返回结果的一致性，验证`temperature`参数的配置效果。
- 查看系统日志，确认无`chat:LLM_model_response_empty`类的错误日志，说明接口调用流程正常。
