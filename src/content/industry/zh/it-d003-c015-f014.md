# 产品使用数据分析的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自埋点系统、数据仓库、CRM与工单系统，更新频率多为日度或周度。日常关联的文档包含使用分析报告、埋点方案、指标口径表与看板需求单，数据字段涵盖客户标识、功能访问频次、操作时长、工单响应时效等，单位多为次、分钟、条等，整体围绕跨客户的产品功能使用行为展开。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求配置兼容不同格式的数据源映射规则，确保埋点、CRM等系统的字段能匹配统一的指标口径；日/周度的批量更新需求，要求模型调用支持批量任务调度与断点续传，避免单次超时长调用导致任务失败。跨客户的行为数据涉及隐私合规，需配置上下文截断规则防止敏感信息泄露；指标口径的不统一特性，要求模型在分析前需关联口径文档完成字段校准，因此配置中需增加关联文档的路径参数。异常数据排查的高频需求，要求模型支持异常字段标记与溯源，需配置对应的工具调用参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址） | 填写私有化部署的AI Proxy服务根地址，如 `http://aiproxy:3000` | 作为AI Proxy服务的访问入口，适配跨源数据调用的跨域访问需求，规避直接调用外部模型的合规风险 |
| `AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空） | 输入与AI Proxy服务端配置一致的管理员Token | 保障AI Proxy服务调用的身份合法性，防止未授权访问敏感的产品使用数据 |
| `maxContext` | 8000–12000 token | 适配跨客户多维度数据的上下文长度，避免因上下文溢出导致分析中断 |
| `temperature` | 0.2–0.4 | 降低分析结果的随机性，保障基于统一指标口径的分析结果一致性 |
| `toolChoice` | auto | 允许模型自动调用关联的指标口径表、埋点方案等文档，完成数据字段校准 |
| `maxTokens` | 2000–3000 token | 限制单次分析输出的长度，适配产品使用分析报告的结构化输出需求 |

## 容易做错的三处
- 排查项：调用通过AI Proxy转发的模型时返回长串错误代码，接口调用状态异常。检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置是否正确匹配，且与AI Proxy服务端配置一致。
- 排查项：生成产品使用分析结果时出现`chat:llm-model-response-empty`报错，尤其在调用流程类分析任务时。检查`maxContext`参数取值是否适配当前上下文长度需求，确保可加载完整的埋点数据与指标口径文档。
- 排查项：配置私有化重排模型后未生效，分析结果未调用重排能力。检查模型渠道的上游供应商地址与凭证配置是否正确，且已正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`服务端环境变量。

## 怎么确认配好了
- 调用测试接口，传入包含客户标识、功能访问数据的样例数据集，检查接口是否正常返回结构化分析结果。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置已被系统正确加载。
- 触发批量数据的分析任务，检查任务执行过程中未出现上下文溢出或超时报错。
- 验证模型输出是否关联了指标口径表的内容，确认工具调用配置已生效。
