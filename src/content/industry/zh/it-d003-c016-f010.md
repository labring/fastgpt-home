# 代码安全审计的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
代码安全审计的数据来源包含项目源代码仓库、第三方依赖清单、静态代码扫描（SAST）工具输出、公开漏洞库。数据更新随项目版本迭代或单次审计任务完成，通常按每个项目或每个版本生成专属文档。日常产出的文档包含代码审计报告、漏洞证明、修复建议、复测记录四类，结构化字段包含漏洞编号、影响代码路径、依赖包版本、修复状态、溯源链路等，无统一固定单位，字段内容随文档类型和审计范围调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据的混合接入要求溯源配置需精准绑定每个来源的唯一标识，避免混淆不同工具的扫描结果或不同项目的审计文档。高更新频率要求配置支持实时关联最新的审计版本，确保溯源信息匹配当前项目的最新状态。复杂的文档结构要求配置按文档类型拆分溯源字段，分别匹配审计报告、漏洞证明等不同文档的内容格式。此外，安全审计场景对溯源精度要求高，需将溯源信息精准到具体代码行或依赖包版本，无法依赖泛化的来源描述。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大引用token数 | 8000–12000 token | 代码审计报告通常包含长文本的漏洞分析与攻击路径描述，需保留完整的溯源信息 |
| 返回数据格式 | 结构化JSON | 需提取漏洞编号、代码路径、依赖版本等字段用于精准溯源，便于后续校验与审计 |
| 详情开关 | 开启 | 需展示原始文档的具体内容，匹配安全审计对溯源信息的详细要求 |
| 单次召回上限 | 前10条 | 覆盖单次审计的主要漏洞项，避免遗漏关键的溯源关联信息 |
| 结果重排 | 开启 | 按漏洞风险等级排序，优先展示高危漏洞的溯源内容，符合安全审计的优先级要求 |
| 最大上下文长度 | 6000 字符 | 适配代码片段的长文本展示，保留完整的攻击路径与修复建议内容 |

本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：引用结果仅返回单条文档，无法关联多个审计报告的溯源信息。原因：未开启结果重排配置，导致高风险漏洞的溯源信息被低优先级内容覆盖。
- 现象：调用后返回空的溯源字段，无法查看原始文档的具体内容。原因：未正确配置返回数据格式为结构化模式，导致原始文档的专属字段未被提取。
- 现象：连续发起审计相关提问后，溯源信息丢失，后续问题答非所问。原因：未绑定单次审计任务的唯一ID，未保留上下文关联标识，导致每次提问的溯源上下文被重置。

## 怎么确认配好了
- 上传一份代码审计报告，触发检索后查看返回结果的来源字段，确认包含仓库地址、扫描工具名称、漏洞编号等标识。
- 调整最大引用token数的配置，上传长文本的漏洞证明文档，验证返回内容未被截断，完整展示漏洞分析细节。
- 开启详情开关后，检索高危漏洞关键词，确认返回结果包含原始文档的具体代码片段或依赖版本信息。
- 发起两次连续的审计相关提问，验证第二次提问仍能关联第一次提问的溯源上下文，未出现上下文丢失的情况。
