# 代码安全审计的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
典型主体为安全研发团队、安全服务商与项目研发团队，日常处理的文档包括代码审计报告、漏洞证明材料、修复建议文档与复测记录。数据来源涵盖项目源代码仓库、第三方依赖清单、静态应用安全测试（SAST）工具输出结果与公开漏洞库。文档更新频率随项目版本或审计周期变动，每份文档通常包含风险条目编号、关联代码片段、风险等级、修复步骤与复测结果等结构化与非结构化内容。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于数据来源包含代码片段与结构化风险条目，文档解析需保留代码格式与风险条目边界，避免分块割裂关键安全信息。不同项目的审计文档格式差异较大，部分文档包含表格化的依赖清单与嵌套的风险描述，需适配灵活的解析规则。同时，文档更新频率较高，解析流程需支持快速适配新的文档结构，且解析结果需确保不遗漏高危风险的完整上下文，否则可能导致后续安全复核环节出现疏漏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `customPdfParse` | 开启，绑定pdf-marker解析规则 | 代码审计报告常包含代码片段与结构化表格，自定义PDF解析可保留格式与代码块结构，避免解析后内容错乱 |
| `chunkSize` | 800–1200 字符 | 代码审计文档包含长代码片段与完整风险描述，该区间可保留单条风险的全部上下文，避免割裂修复建议与风险关联关系 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 大型项目的审计报告可能包含多份附件与源代码片段，超时设置需覆盖完整解析流程，避免中途中断 |
| `chunkSplitter` | 按代码块、标题拆分 | 文档结构以风险条目为核心单元，按标题与代码块拆分可确保每个分块对应独立的安全事项，便于后续安全定位与复核 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 大型项目的审计报告可能包含多份依赖清单与源代码附件，需适配大文件上传需求 |
| `chunkSettingMode` | 自定义模式 | 不同项目的审计文档格式差异显著，自定义模式可灵活调整分块规则，适配各类安全文档结构 |

## 容易做错的三处
- 现象：调用解析接口后返回空的references字段，原因：未开启`customPdfParse`配置，无法识别文档内的关联引用字段。
- 现象：上传PDF后未显示自定义解析的配置选项，原因：未在FastGPT v4.17.0的系统设置中启用pdf-marker集成，本地部署的pdf-marker未与平台完成端口打通。
- 现象：分块结果出现跨风险的内容拼接，原因：`chunkSize`设置过小，将单条风险的修复建议与其他风险的描述合并到同一分块，导致安全信息混淆。

## 怎么确认配好了
- 上传一份包含代码片段与风险条目的测试审计报告，检查解析后的分块是否每个都对应独立的安全事项。
- 进入系统设置的解析配置页，确认`customPdfParse`开关处于开启状态，且绑定了正确的pdf-marker服务地址。
- 查看解析日志，确认未触发`PARSE_FILE_TIMEOUT_SECONDS`对应的超时报错。
- 调用解析接口，检查返回结果中是否包含references字段的关联内容。
