# 代码安全审计的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据主要来自源代码仓库、依赖清单、静态代码扫描（SAST）工具与公开漏洞库。日常产出的文档包括代码审计报告、漏洞证明、修复建议与复测记录，数据按项目版本或单次审计任务更新。单条数据通常包含代码片段、漏洞定位信息、风险等级标注与对应的修复指引，需关联对应项目的代码版本与依赖组件信息。本文基于FastGPT v4.17.0版本的功能逻辑编写。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且关联代码版本与依赖组件，要求模型接入时需支持多源数据的上下文关联，避免割裂不同工具的输出结果。按版本或任务更新的数据量波动较大，需配置合理的上下文长度限制，防止超出模型处理上限。日常文档包含代码片段与修复指引，要求模型支持长文本输入与结构化内容解析，同时需适配不同格式的审计报告字段。此外，数据需关联项目元信息，配置环节需支持绑定对应项目的标识，确保模型输出的审计结果可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如 `http://aiproxy:3000` | 为FastGPT App/Admin服务端配置的AI Proxy服务访问根地址，确保可正常连通AI Proxy服务 |
| `AIPROXY_API_TOKEN` | AI Proxy管理员Token，与AI Proxy服务端配置一致且非空 | 用于验证FastGPT与AI Proxy服务的调用权限，防止未授权访问AI Proxy服务 |
| `maxContext` | 8000–12000 token | 适配代码审计报告的长文本输入需求，避免因上下文过长触发模型截断 |
| `maxTokens` | 2000–3000 token | 匹配代码审计结果的输出长度需求，确保修复建议与漏洞分析可完整返回 |
| `temperature` | 0.2–0.4 | 降低输出随机性，保证漏洞定位与修复建议的准确性与一致性 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具处理代码安全相关的逻辑分析任务 |

## 容易做错的三处
- 现象：调用模型服务返回500错误或无有效结果。排查项：检查`AIPROXY_API_ENDPOINT`是否为AI Proxy服务的根地址，未附加`/v1`等路径，且可正常连通AI Proxy服务
- 现象：每次调用MCP工具后，后续对话的上下文被清空或丢失部分审计数据。原因：未配置`maxContext`适配多轮审计任务的上下文留存，或工具调用后未正确绑定项目元数据导致上下文重置。
- 现象：模型生成漏洞分析或修复建议的耗时过长。原因：`maxTokens`设置过高，超出模型的并发处理上限，或未合理限制`toolChoice`的触发范围导致模型反复调用不必要的工具。

## 怎么确认配好了
- 导入一段小型代码片段或简短的审计报告片段，发起模型调用，检查是否能正常返回漏洞定位结果，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置有效性与连通性。
- 导入一份完整的代码审计报告，核对模型输出的内容未出现截断情况，验证`maxContext`与`maxTokens`的配置合理性。
- 触发MCP工具调用后继续发起多轮审计相关的对话，检查上下文是否正常留存，验证`toolChoice`与上下文绑定配置的有效性。
- 调整`temperature`参数后发起两次相同的审计测试，对比输出结果的差异，确认输出的随机性符合预期。
