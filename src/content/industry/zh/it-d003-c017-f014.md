# 代码评审与合并管理的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来源于Git仓库、CI流水线、静态扫描报告与缺陷库。日常处理的核心文档包括合并请求、代码评审意见、提交记录与分支策略说明。数据更新频率为每日或每提交一次，每条数据包含代码变更内容、评审状态、关联缺陷编号与分支归属信息，字段随代码变更规模动态调整，无固定统一长度。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源分散且更新频率较高，模型接入需适配多源数据的格式差异，需配置足够的上下文容量以覆盖完整的合并请求上下文。代码变更内容的长度波动较大，需限制单轮调用的输出令牌数量，避免任务超时。同时，该品类需结合人工评审的业务语义，模型配置需兼顾输出一致性与灵活性，不能过度依赖随机化判断。此外，数据关联缺陷库的特性要求模型调用链路需符合安全合规要求，需对访问令牌进行单独配置管理。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 合并请求的代码变更通常包含多段提交记录与评审意见，总上下文长度需覆盖完整变更上下文 |
| `maxTokens` | 2000–3000 token | 代码评审的安全合规审查需输出完整检测结论，需预留足够输出空间 |
| `temperature` | 0.2–0.4 | 安全合规审查需保持输出一致性，避免随机化判断影响评审标准 |
| `toolChoice` | auto | 需根据审查内容自动调用代码解析工具，适配不同类型的合并请求 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 http://aiproxy:3000 | 该变量为 App/Admin 服务端必需环境变量，用于指定 AI Proxy 服务地址，不得附加 /v1 或 /chat/completions 路径，非单模型厂商地址 |
| `AIPROXY_API_TOKEN` | AI Proxy 管理员 Token，与 AI Proxy 服务端配置一致且非空 | 该变量为 App/Admin 服务端必需环境变量，不得使用应用 API Key、模型供应商密钥或按应用签发的 Token 替代 |

## 容易做错的三处
- 现象：配置多个同名不同key的模型时，调用时触发令牌不匹配报错。原因：未在模型配置中为每个实例设置唯一标识，导致系统无法区分不同密钥的模型实例。
- 现象：工作流节点输出结果仅包含部分上下文，未覆盖当前合并请求的完整评审记录。原因：未关闭全局上下文复用开关，导致节点调用了非当前任务的上下文数据。
- 现象：尝试接入funasr语音识别模型时，界面提示不支持该模型类型。原因：当前FastGPT代码评审模块仅支持文本类大模型接入，未集成语音识别模型适配逻辑。

## 怎么确认配好了
- 提交一条测试合并请求，触发安全合规审查任务，查看模型调用日志中的令牌标识与配置的密钥是否一致。
- 检查模型厂商图标加载状态，确认网络连接正常且配置的厂商信息与FastGPT v4.17.0内置图标库匹配。
- 触发一次审查任务，查看输出结果是否仅包含当前合并请求的关联数据，未混入其他任务的上下文。
- 调整`temperature`参数至0.1，多次触发同一审查任务，确认输出结果保持一致，验证参数配置生效。
