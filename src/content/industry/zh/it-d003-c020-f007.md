# 供应商与设备到货管理的安全与合规材料审查：对话日志与审计

## 这个品类的数据长什么样
该品类的数据主要来自ERP系统、供应商发货单、物流跟踪信息与设备厂商后台。日常处理的文档包含采购订单、到货验收单、序列号清单、发票资料，包含订单编号、设备型号、序列号、验收状态、供应商信息等字段。数据更新以单批次采购订单为周期，每完成一单或每周同步一次，单批次数据量随项目规模浮动。

## 这些特征在「对话日志与审计」这一环带来什么约束
多源数据带来的关联需求，要求对话日志需绑定对应采购订单编号、设备序列号等唯一标识，确保审计时可追溯到具体项目环节。按单/周更新的节奏，要求审计归档按项目批次拆分，避免跨项目数据混淆。文档包含敏感业务信息，日志存储需遵循最小权限访问规则。设备错配、资产账实不符等出错后果，要求审计链路完整保留型号核对、到货验收环节的完整交互内容，不可截断关键对话步骤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chatId` | 与单采购订单绑定，会话生命周期内保持固定 | 该品类按单管理业务数据，需将对话与具体项目绑定，便于按订单维度审计 |
| `responseChatItemId` | 记录每轮设备型号核对、验收确认的交互项 | 需完整追溯型号配置核对、序列号登记的具体对话细节 |
| `detail` | 开启全量记录，单条日志最大 10000 字符 | 覆盖到货验收全流程的交互内容，满足审计的完整追溯需求 |
| 日志存储周期 | 留存至项目验收完成后 180 天 | 该品类项目周期覆盖采购到验收全流程，审计需求覆盖项目全周期 |
| 访问权限控制 | 按仓储管理员、采购、集成商角色划分访问范围 | 业务数据包含敏感的供应商与设备信息，遵循最小权限访问原则 |
| 单次检索上限 | 返回前 20 条结果 | 匹配该品类日常审计的检索需求，避免返回过多无关数据 |
| 会话超时时间 | 600 秒 | 匹配该品类单批次采购的处理周期，避免会话中断导致日志丢失 |

## 容易做错的三处
- 现象：Docker部署后访问界面报错连接失败，或日志提示slow operation，原因：未将对话日志与订单数据的关联配置正确绑定，导致数据库查询关联字段时响应超时。
- 现象：聊天记录未保存到数据库，或会话无法追溯到对应采购订单，原因：未配置`chatId`与采购订单号的绑定规则，导致日志无唯一关联标识，无法完成审计追溯。
- 现象：多用户共享公开访问链接后，聊天记录出现跨项目混淆，原因：未按角色划分日志访问权限，导致不同岗位人员可查看非负责项目的对话内容。

## 怎么确认配好了
- 进入FastGPT v4.17.0后台的日志管理页面，输入某采购订单编号，验证可检索到对应会话的完整对话内容。
- 发起一次设备型号核对的对话，查看日志详情`detail`字段，确认包含用户输入、AI回复及中间校验步骤。
- 切换不同角色账号，验证仅可查看对应负责项目的对话日志。
- 检查数据库中`chatId`字段与采购订单号的关联关系，确认单会话绑定唯一订单标识。
