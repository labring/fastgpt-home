# 信创替代适配的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
这个品类的日常文档包括适配清单、兼容性测试报告、迁移方案、问题台账，数据来源为现有系统清单、国产软硬件目录、测试环境及厂商资料。数据更新频率为每项目或每季度，单次项目文档规模从数页到数百页不等。适配清单包含软硬件型号、版本号、适配状态字段，兼容性测试报告包含测试项、测试环境、结果判定字段，整体结构以结构化条目和分段报告为主。

## 这些特征在「文档解析与分块」这一环带来什么约束
信创替代适配的文档多为结构化条目或标准化报告，分块需避免拆分同一条适配项或测试结果的关联信息，确保关键字段不被截断。数据更新以项目为单位，无需高频增量解析，可采用全量解析模式。文档来源多为厂商提供的官方资料与测试输出，需保留原始字段的完整性，避免解析过程中丢失适配状态、版本号等合规性关键信息。同时，解析失败或超时会直接影响迁移进度，需严格控制解析时长与准确性。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配信创文档的段落与条目长度，避免拆分同一条适配项的关联信息 |
| `chunkSplitter` | 按文档类型切换 | 适配清单采用按标题拆分，兼容性报告采用按段落拆分，匹配不同文档的结构特征 |
| `customPdfParse` | 开启 | 国产化文档可能存在非标准排版，自定义解析可保留适配状态、版本号等关键合规字段 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 匹配大型兼容性测试报告的解析耗时，避免因超时导致解析失败 |
| `chunkSettingMode` | 手动配置 | 信创适配文档的结构统一但项目差异较大，手动配置可精准控制分块逻辑 |

## 容易做错的三处
- 现象：简易模式下上传国产化适配清单后，大模型未触发文件解析，返回空上下文。原因：未配置`chunkSettingMode`为适配信创文档的规则，默认分块逻辑未识别专用字段，导致解析结果未被关联。
- 现象：使用`customPdfParse`解析大型PDF兼容性测试报告时，FastGPT报超时，但解析服务返回成功。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值小于实际解析耗时，未预留足够的处理时间。
- 现象：工作流中上传Excel格式的迁移方案后，无法读取表格内的软硬件版本信息。原因：未配置`chunkSplitter`为按表格行/列拆分，默认分块未提取表格结构化数据。

## 怎么确认配好了
- 上传单份适配清单文档，查看解析后的文本是否包含所有软硬件型号、版本号、适配状态等关键字段。
- 上传100页以上的兼容性测试报告，等待解析完成后检查是否触发超时类报错。
- 在工作流中添加文件读取节点，上传Excel格式迁移方案，确认可提取表格内的结构化内容。
- 切换不同大模型，验证均能调用解析后的文档内容进行问答。
