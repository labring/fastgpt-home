# 信息化预算与项目组合管理的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的典型使用主体为CIO办公室、PMO及财务BP，日常处理的文档包括年度预算表、项目立项书、项目组合看板与投资复盘报告。数据来源覆盖财务系统、项目管理系统、合同台账及业务部门需求提报，更新频率多为月、季或年。文档结构包含结构化字段如预算金额、项目编号，以及非结构化的复盘文本，不同来源的数据格式存在差异，部分字段需跨系统关联校验。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据来源分散且更新周期不一，要求溯源环节需精准绑定每个引用片段对应的系统与更新时间，避免跨版本数据混淆。文档包含结构化预算字段与长文本复盘内容，需完整保留原始字段信息，不能截断关键的项目编号、预算金额等内容。不同更新频率的数据需对应不同的版本标识，确保引用的是当前生效的预算或项目信息。跨系统关联的字段需匹配唯一标识，避免出现预算错配或项目重复引用的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 该品类文档包含结构化预算字段与长文本复盘报告，需完整保留引用片段的关键信息，避免截断项目编号、预算金额等核心内容 |
| `responseData` | 仅返回关联源数据 | 需严格对齐原始预算表、立项书的字段，避免生成非授权的篡改内容，确保溯源信息与原始数据完全一致 |
| `detail` | 开启完整溯源 | 需展示数据来源的系统标识与更新时间戳，匹配财务、项目管理系统的台账规范，满足合规审查的溯源要求 |
| 单次召回上限 | 前5条 | 该品类的项目组合看板通常单页展示核心项目数量有限，避免召回过多冗余数据干扰溯源与决策 |
| 数据源绑定规则 | 按系统分类关联 | 需将财务系统、项目管理系统的数据分别绑定对应知识库，确保引用的源数据来自正确的业务模块 |

## 容易做错的三处
- 现象：开启引用开关后，未配置对应参数仍强制返回溯源内容。原因：FastGPT v4.17.0版本中，未正确绑定数据源与项目预算文档的关联关系，系统默认触发全量溯源，导致未配置的引用也被展示。
- 现象：配置知识库变量引用格式无效，无法匹配预算文档字段。原因：未使用品类专属的数据源标识参数，仅传入通用数据集ID未关联财务、项目管理系统的台账映射，导致无法召回对应项目的预算数据。
- 现象：召回的源数据字段为空，无法在回答中展示溯源信息。原因：未开启`detail`参数，系统未加载源数据的完整字段内容，仅返回了问答文本，未包含原始文档的关键标识。

## 怎么确认配好了
- 上传单份年度预算表至对应知识库，触发包含预算金额、项目编号的问答请求，检查返回内容中是否包含源数据的文件标识与更新时间戳。
- 配置`quoteMaxToken`为800 token，输入包含长文本的投资复盘问题，检查引用片段的字符长度未超出设定值，验证参数生效。
- 关闭引用开关，触发问答请求，检查回答中未展示任何溯源信息，验证引用开关的配置正确。
- 输入未关联的项目编号，检查系统未召回无关的预算数据，验证数据源绑定规则的配置正确。
