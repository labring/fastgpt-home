# 值班排班与交接的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来自排班系统、故障工单、监控告警与组织通讯录，更新频率为日或周。日常产出的文档包含值班表、交接记录、升级联系人清单、值班日报。值班表包含日期、值班人员、值守时段字段；交接记录标注未结事项、待跟进故障；升级联系人清单按岗位划分联络方式；值班日报汇总当日告警与处理情况。数据结构随运维团队的排班规则略有差异，但核心字段围绕值守权责、事项流转展开。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新周期灵活，要求模型接入时需支持多数据源的批量同步与增量更新，避免全量拉取占用过多资源。日常文档字段无统一标准，需配置适配多格式文本的解析规则，确保值班表的时段字段、交接记录的未结事项标签能被准确识别。更新频率的差异要求配置可自定义同步周期，适配日更的值班日报与周更的升级联系人清单。数据关联运维响应时效，模型调用需保证低延迟，避免影响排班冲突协调与交接流程。

本文基于FastGPT v4.17.0版本编写。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，含端口，例如http://aiproxy:3000，不得附加/v1或/chat/completions等子路径，不得在工作流全局变量、应用API请求头或普通模型管理页面填写 | 为App/Admin服务端需配置的环境变量，确保模型调用请求能正确路由到AI Proxy服务 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不能为空，不得在工作流全局变量、应用API请求头或普通模型管理页面填写，不得作为应用API调用凭证 | 为App/Admin服务端需配置的环境变量，保障AI Proxy服务访问安全，防止未授权调用 |
| `maxContext` | 8000–12000 token | 覆盖值班表、交接记录等多份文档的上下文内容，避免截断关键信息 |
| `maxTokens` | 2000–3000 token | 适配值班日报、升级联系人清单的文本长度，保证输出的审查结果完整 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保合规审查的结果符合固定规则，减少误判 |
| `toolChoice` | auto | 允许模型自动选择是否调用工具处理排班冲突协调、交接事项核对等任务 |

## 容易做错的三处
- 现象为本地部署App/Admin服务时启动校验失败，可排查`AIPROXY_API_ENDPOINT`是否配置正确，确认是否能连接AI Proxy服务。
- 现象为模型调用时无法关联指定的值班表文件，原因是未配置`maxContext`的合理取值，导致上下文被截断，无法读取指定文件的完整内容。
- 现象为生成的合规审查结果出现大量无关内容，原因是将`temperature`设置为过高区间，导致模型输出随机性过强，偏离合规审查的固定规则。

## 怎么确认配好了
1. 访问服务端配置的`AIPROXY_API_ENDPOINT`，验证返回的接口状态码为200，确认连接正常。
2. 上传一份标准值班表文档，触发模型审查任务，检查返回结果中包含值班人员、值守时段的核心字段，确认上下文读取正常。
3. 调整`temperature`参数至0.1区间，发起多次测试调用，观察输出结果的一致性，确认随机性符合预期。
4. 配置增量同步任务，设置同步周期为1天或7天，等待一个周期后检查数据同步日志，确认新生成的值班日报已被正确加载。
