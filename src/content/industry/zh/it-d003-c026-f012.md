# 关卡内容制作的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
这个品类的数据通常来自关卡编辑器、美术资源库、玩家测试数据与缺陷系统，更新节奏为周度或每版本提交周期。日常产出的文档包含关卡设计稿、资源需求表、测试反馈单与版本提交记录，文档字段多包含关卡ID、资源路径、测试用例编号、提交版本号等，部分文档附带坐标、资源数量等具体数值单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
关卡内容制作的文档类型多样，包含结构化表格、长文本描述与结构化记录，部分文档包含坐标、资源数量等带单位的数值字段。高频更新的特性要求分块逻辑适配快速迭代的文档内容，避免因分块过粗导致上下文断裂，或过细增加检索冗余。同时合规审查要求保留字段完整性，分块不能截断关键合规相关的关卡ID、版本提交记录等字段，且需适配多来源的不同格式文件，保证解析一致性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的文档解析与分块逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配关卡设计稿的长文本段落与资源需求表的结构化行组，避免截断包含资源路径的关键字段 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配关卡文档的章节结构，保留关卡路径、资源摆放等上下文关联，适配Excel格式的资源需求表行组 |
| `customPdfParse` | 启用 | 适配导出的关卡设计稿PDF，保留原文档的表格与标题层级，支持合规审查所需的字段完整性 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 容纳单版本提交的批量资源需求表与测试反馈单合集，适配多附件上传的场景 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 避免大型关卡设计稿或批量Excel文件解析超时，适配多格式文件的完整解析时长 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型调整分块规则，适配结构化与非结构化文档的混合场景 |

## 容易做错的三处
- 解析后分块中资源路径字段为空。原因是`chunkSize`设置过小，截断了包含资源路径的完整行组，导致后续合规审查无法匹配对应关卡内容。
- 解析大型Excel格式的资源需求表时返回超时报错。原因是`PARSE_FILE_TIMEOUT_SECONDS`设置低于实际解析所需时长，未适配批量数据的处理节奏。
- 合规审查环节发现分块包含未脱敏的玩家测试数据。原因是未启用`customPdfParse`的敏感字段过滤配置，导致敏感数据随分块进入知识库。

## 怎么确认配好了
- 上传单份典型关卡设计稿，查看解析后的分块列表，确认每个分块包含完整的章节与关键字段。
- 上传批量的资源需求表Excel文件，检查解析任务的完成状态，确认未出现超时报错。
- 针对包含敏感字段的测试反馈单，验证解析后的分块未包含未脱敏的测试数据。
- 调整`chunkSize`参数后上传同一份文档，对比分块结果，确认分块逻辑符合预期配置。
