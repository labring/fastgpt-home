# 内容推荐运营的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
该品类的日常处理文档包含推荐策略记录、内容池清单、实验报告、运营复盘四类，数据来源于内容标签、用户行为日志、实验平台及推荐后台，更新频率多为日更或周更。文档多包含结构化字段如内容ID、标签权重、实验指标数值、流量数据等，部分内容池清单会附带多维度筛选条件，实验报告则会记录多组对照数据，整体结构兼具结构化表格与非结构化文本。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于文档兼具结构化字段与非结构化文本，分块时需兼顾结构化内容的完整性与文本逻辑连贯性，避免拆分破坏实验指标、筛选条件的关联关系。高频更新的日/周级文档要求解析流程具备低延迟特性，避免因解析超时影响运营调度节奏。内容池清单的多维度筛选条件若被错误拆分，会导致后续合规审查遗漏关键合规内容；实验报告的对照数据组若被分散到不同分块，会影响后续指标解读的准确性，进而引发运营决策偏差。同时，合规审查的核心要求需解析结果保留文档溯源信息，确保后续可定位原始内容的来源与修改记录。

## 配置怎么定
以下配置均基于FastGPT v4.17.0版本的参数逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配推荐策略记录、实验报告的常规文本长度，避免拆分破坏实验指标、筛选条件的逻辑关联 |
| `chunkSplitter` | 按段落+标题拆分 | 保留文档的结构层级，便于后续合规审查时快速定位内容所属模块，同时适配多组对照数据的分组需求 |
| `customPdfParse` | 开启结构化解析 | 适配内容池清单的表格化内容，准确提取多维度筛选条件字段，避免表格内容被错误打散 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对周更的大型实验报告、批量内容池清单，避免因文档体积较大导致解析超时，影响运营调度 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容批量上传的历史内容池数据与周更的大型运营复盘文档，满足日常批量处理需求 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型调整分块参数，兼顾实验报告的对照数据分组与内容池清单的结构化字段保留 |

## 容易做错的三处
- 解析后无法返回文档溯源信息。原因是未开启分块时的元数据绑定配置，导致向量库中未存储原始文档的文件名、路径等标识，无法在问答时关联原始内容来源。
- 上传XLSX多行表格时出现字段缺失。原因是未启用自定义文档解析的表格结构化模式，导致多行合并的单元格、多维度筛选条件被错误拆分或遗漏。
- 上传PPT或PDF文档时出现“the argument ‘windows-1252’ is invalid encoding”报错。原因是文档使用了非标准编码格式，未配置自动编码检测参数导致解析失败。

## 怎么确认配好了
- 上传一份典型的实验报告文档，查看解析后的分块结果，确认每个分块保留了完整的实验指标段落与标题层级，无内容被错误拆分。
- 发起一次基于该知识库的问答测试，验证回答内容是否附带原始文档的文件名、段落位置等溯源信息。
- 上传一份体积约500 MB的内容池清单，确认解析任务在600秒内完成，无超时报错。
- 上传XLSX格式的表格文档，查看解析后的字段是否完整保留了多维度筛选条件，无字段丢失或格式错乱情况。
