# 单元测试与组件测试的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自代码仓库、测试框架报告、需求说明与接口定义。日常关联文档包括测试用例、覆盖率报告、Mock说明与缺陷单。数据更新节奏为每日或每次代码提交后更新。数据字段包含代码单元逻辑描述、测试执行结果、覆盖率指标、缺陷关联信息等，无统一固定格式，随测试框架与项目规范调整。数据体量随项目代码量与测试用例数量变化，单次处理数据多为单代码单元或单组件的测试相关文档与执行记录。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据随代码提交高频更新，要求模型接入环节支持实时或近实时的数据拉取与处理，避免因数据滞后导致测试逻辑偏差。测试用例、缺陷单等文档结构不统一，需配置适配多格式文本的模型解析参数，确保不同类型测试数据的合规审查准确性。数据来源包含代码逻辑与执行结果，要求模型接入时需关联代码仓库与测试报告的权限配置，保障审查过程符合安全合规要求。高频更新的数据也要求模型调用的响应速度匹配提交节奏，避免阻塞持续集成流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 4000–8000 token | 适配单元测试代码与测试报告的文本长度，避免上下文溢出导致审查中断 |
| `maxTokens` | 1000–1500 token | 匹配单测试用例或缺陷单的审查输出长度，确保合规性描述完整 |
| `temperature` | 0.2–0.4 | 降低输出随机性，保障安全合规审查结果的一致性与可追溯性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境标定 | AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions路径，确保模型调用链路正常 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致 | AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空，符合安全合规的服务鉴权要求 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具补充测试数据，适配多类型测试文档的审查需求 |

## 容易做错的三处
- 语义检索匹配分数持续偏高，模型审查结果与实际测试逻辑偏差较大。原因是未根据单元测试数据的高频更新特性调整上下文长度配置，导致旧数据残留影响检索准确性。
- 模型调用返回tls验证失败报错，提示证书校验异常。原因是未正确配置代理端点的证书信任规则，或使用的代理服务未适配合规数据的传输要求。
- 单组测试数据关联多组向量时无法完成配置。原因是未明确匹配测试数据与向量存储的映射规则，导致模型接入环节无法识别多向量关联的测试文档结构。

## 怎么确认配好了
- 提交一次测试代码提交触发审查流程，检查模型调用日志是否正常返回合规审查结果，无上下文溢出或超时报错。
- 查看服务端启动日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置通过启动校验，未出现连接异常。
- 调整`temperature`参数区间，对比两次审查结果的一致性，确认输出符合预期的严谨性要求。
- 导入多格式的测试文档（如覆盖率报告、缺陷单），检查模型是否能正确解析不同类型的测试数据。
