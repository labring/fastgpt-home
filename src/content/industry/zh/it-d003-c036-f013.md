# 原型与交互设计的安全与合规材料审查：权限与数据隔离

## 这个品类的数据长什么样
通常，原型与交互设计品类的数据来源于Figma、Axure等设计工具，核心文档包括交互原型文件、页面流程图、组件说明文档、设计评审记录。数据更新节奏多为每周迭代或随产品版本发布同步更新，单份文档包含页面节点属性、操作路径逻辑、组件参数、评审意见等字段，无统一固定单位，以页面、步骤、组件为基础描述单元。

## 这些特征在「权限与数据隔离」这一环带来什么约束
该品类的数据多为团队内部设计协作内容，涉及未公开的产品操作路径与内部评审意见，因此权限隔离需匹配数据的团队归属与角色权限。频繁的版本更新要求权限配置可快速同步变更，避免旧权限绑定新数据导致的泄露风险。同时，不同文档类型（如原型文件与评审记录）需区分权限粒度，确保仅授权角色可访问对应内容，防止未授权人员获取未公开的设计方案。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 团队归属绑定 | 按`teamId`关联原型文件 | 匹配原型文件的所属团队标识，确保跨团队数据不可见 |
| 角色权限配置 | 按角色分配`tmbId`权限区间（100-999） | 区分设计师、评审员、管理员的操作权限范围 |
| 数据访问超时 | 300 秒 | 适配原型文件加载与权限校验的平均耗时 |
| 服务依赖配置 | 配置App/Admin服务端环境变量`AIPROXY_API_ENDPOINT`为`http://aiproxy:3000`，`AIPROXY_API_TOKEN`为与AI Proxy服务端配置一致的非空管理员Token | 满足FastGPT v4.17.0版本的启动校验要求，仅可在App/Admin服务端环境变量配置，不可在应用界面、工作流全局变量或应用API请求头中设置，保障权限服务正常运行 |
| 跨团队访问限制 | 禁用跨团队文件共享 | 防止非授权团队获取未公开的原型与评审数据 |
| 敏感数据脱敏 | 开启评审记录脱敏 | 避免内部用户反馈等敏感信息被未授权角色查看 |

## 容易做错的三处
- 现象：删除团队成员后仍能访问原有原型文件。原因：未同步更新`teamId`绑定关系，残留旧权限配置导致权限未完全回收。
- 现象：普通用户无法查看指定原型文件。原因：误将`tmbId`权限值设置为管理员专属区间，未匹配对应角色的权限要求。
- 现象：团队管理功能无法正常启用。原因：未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`环境变量，导致服务启动校验失败。

## 怎么确认配好了
- 登录不同角色的测试账号，验证是否仅能访问所属团队的原型文件、评审记录等内容。
- 手动修改某份原型文件的`teamId`绑定配置，验证非授权团队成员无法访问该文件。
- 查看服务启动日志，确认无`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`缺失的报错信息。
- 触发团队成员权限变更操作，验证权限更新后对应角色的访问权限同步生效。
