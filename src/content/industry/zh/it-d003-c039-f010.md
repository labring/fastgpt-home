# 后端服务开发的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自代码仓库提交记录、API网关访问日志、数据库操作日志、配置中心变更记录。日常产出的文档包含接口设计文档、数据库变更单、代码评审记录、版本发布说明。数据更新频率为每日同步或随版本发布更新。数据字段包含接口路径、请求参数、执行结果、变更时间、操作人信息，单位多为字符、毫秒、条等，无统一聚合统计字段。

## 这些特征在「引用来源与溯源」这一环带来什么约束
代码仓库的提交记录按版本归档，溯源时需关联版本号匹配对应文档，避免跨版本混淆。API网关日志按请求时序存储，需按请求ID追溯调用链路，避免跨日志块的关联错误。接口设计文档的字段包含接口契约、事务边界，溯源时需校验字段完整性以确保合规性。数据库变更单的更新频率随版本发布，需确保溯源数据与当前版本配置对齐。每日更新的日志数据需设置合理的检索时效，避免超时无法召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大引用token数 | `quoteMaxToken` 设为 800–1200 token | 匹配后端服务文档的单块平均长度，避免截断关键溯源信息 |
| 响应数据溯源开关 | `responseData` 设为 开启 | 可直接关联API网关日志、数据库操作的原始数据字段 |
| 溯源详情展示级别 | `detail` 设为 完整 | 展示代码仓库提交ID、变更单编号等全量关联信息 |
| 引用召回上限 | 前5条 | 匹配后端服务单次请求的常规关联日志数量，避免检索过载 |
| 检索超时阈值 | 60 秒 | 适配后端服务接口的常规响应时长，避免检索任务超时 |
| 引用内容格式 | 按文档类型自定义 | 适配接口设计文档、数据库变更单的不同字段展示规则 |

## 容易做错的三处
- 现象为知识库回答段落末尾未显示引用来源，原因是未开启`responseData`配置项，或引用模板未配置末尾引用占位符。
- 现象为检索关联数据时出现超时报错，状态码为504，原因是检索超时阈值设置低于后端服务日志的检索耗时，或数据来源的更新频率过高导致检索负载过大。
- 现象为溯源数据仅显示部分字段，原因是`detail`配置项设为精简模式，未启用全量字段展示。

## 怎么确认配好了
- 发起包含接口路径、变更单号的测试请求，在FastGPT v4.17.0版本的知识库中检查回答末尾是否显示对应溯源信息。
- 查看配置面板的`quoteMaxToken`、`responseData`参数值，确认与预设配置一致。
- 模拟高频率检索请求，检查是否出现超时报错，验证超时阈值设置合理。
- 切换不同文档类型的检索场景，确认引用格式随文档类型自动适配。
