# 售前技术方案的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自客户访谈、招标文件、厂商产品资料及历史项目方案，更新频率为每单或每周。日常产出的文档包含技术方案书、客户需求调研表、报价清单、演示脚本，字段通常包含技术路线、实施边界、合规要求、报价项等，无统一固定的单位，随单份文档的内容调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
售前技术方案的数据来源分散且多为非结构化文本，要求模型接入时需支持多格式文档解析。更新频率随单项目推进，要求配置的上下文长度可灵活调整以适配不同规模的方案文档。文档包含合规要求相关内容，要求模型配置需优先保障合规审查的准确性。与投标文件编制品类不同，需先明确技术路线与实施边界，因此模型需优先提取方案核心边界信息，保障输出内容贴合售前业务需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 售前技术方案通常包含多份关联文档，需覆盖完整上下文以确保合规审查的完整性 |
| `maxTokens` | `4000–6000 token` | 单份方案的合规审查输出需包含技术路线、边界说明等完整内容，适配标准输出长度 |
| `temperature` | `0.1–0.3` | 合规审查需输出严谨、无发散的内容，避免因参数过高导致无关表述 |
| `AIPROXY_API_ENDPOINT` | 按私有部署环境填写，例如`http://aiproxy:3000`，不得附加/v1或/chat/completions等路径 | 为App/Admin服务端必填环境变量，适配企业内部AI Proxy服务的根访问地址，保障数据传输安全性 |
| `toolChoice` | `auto` | 自动调用内置的合规校验工具，无需手动触发，适配售前顾问的日常操作习惯 |
| `quoteMaxToken` | `2000 token` | 保留足够的原文引用片段，用于合规溯源与客户验证 |

## 容易做错的三处
- 升级FastGPT v4.17.0后运行部署脚本，简易应用出现未捕获异常，现象为界面弹出未捕获异常提示框，后台日志显示上下文长度超限报错。排查项：检查`maxContext`参数是否适配当前任务的上下文长度需求。
- 模型设置禁用思考输出但回答仍包含`<think>`标签，现象为输出内容中出现带格式的思考块。排查项：检查是否未正确配置对应模型的格式校验参数，或未匹配模型原生的思考标签输出规则。
- 工作流问题分类节点无法选中AI模型，现象为下拉列表无可用模型选项。排查项：检查是否未在App/Admin服务端配置必填的`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`环境变量，或未正确配置上游模型渠道的访问权限。

## 怎么确认配好了
- 上传单份售前技术方案文档，运行合规审查任务，查看输出是否包含完整的合规条款提取，无冗余思考内容。
- 运行本地测试脚本，检查控制台日志无未捕获异常，无上下文超限报错。
- 进入工作流配置页面，确认AI模型选项可正常选中并关联预设的售前文档数据源。
- 提交测试用的招标文件片段，查看输出的合规审查结果是否包含对应的原文引用片段。
