# 备份恢复与灾备演练的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来自备份系统、数据库日志、对象存储、灾备平台，日常产出备份策略、恢复演练报告、灾备切换预案、数据校验记录四类文档。数据更新节奏分为日、月、季三类，备份策略与数据校验记录更新频率较高，灾备切换预案通常按季度更新。单份文档包含明确的操作路径、时间戳、校验值、恢复成功率等字段，侧重跨系统的恢复链路信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据的混合接入要求溯源环节明确标记每条引用的来源类型，避免跨系统数据混淆。按日/月/季的更新节奏，需对应调整索引刷新周期，确保引用内容与当前生效的备份策略、最新演练报告一致。固定的文档字段结构，可简化溯源时的字段匹配逻辑，但需严格对应文档中的时间戳与校验值，防止引用过期或篡改后的无效数据。跨系统的可恢复能力定位，要求溯源结果需关联到具体的灾备节点，仅指向通用知识库条目无法覆盖业务需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 字符 | 匹配单份灾备文档的平均长度，避免截断关键校验值与时间戳，符合FastGPT v4.17.0版本的参数配置规范 |
| `responseData` | 开启 | 满足合规审查的溯源要求，明确关联备份系统、灾备平台等来源 |
| 单次搜索上限 | 前 5 条 | 控制溯源结果的展示密度，避免冗余信息干扰恢复点确认环节 |
| 索引刷新周期 | 按数据更新节奏匹配（日/月/季） | 对应备份策略、演练报告的更新频率，确保引用内容实时生效 |
| `detail` | 开启 | 展示文档的具体字段，便于核验数据一致性与恢复成功率 |
| 超时阈值 | 600 秒 | 匹配灾备演练的平均执行时长，避免提前终止校验流程 |

## 容易做错的三处
- 现象：工作流中配置知识库搜索节点，选择变量引用知识库时，返回的引用列表为空。原因：未在API调用时正确传递知识库标识变量，导致节点无法匹配对应灾备相关的文档源。
- 现象：调用chat接口时，返回的引用列表条数超出预设范围。原因：未设置`quoteMaxToken`参数的合理取值，导致系统返回过多非灾备场景的冗余文档。
- 现象：灾备场景下的查询未返回对应备份策略内容，引用列表标记的来源正确但回答未关联。原因：未开启`detail`参数，系统未加载文档的结构化字段，无法匹配恢复点确认的查询意图。

## 怎么确认配好了
- 发起API调用传递知识库变量，检查返回的引用列表是否包含对应灾备文档的字段。
- 调用chat接口，查看返回的引用数据是否标记了备份系统、对象存储等指定来源。
- 触发一次恢复演练相关的查询，确认返回的内容包含校验值、恢复成功率等专属字段。
- 查看配置面板，确认`quoteMaxToken`、`responseData`、`detail`参数的取值符合当前灾备场景的需求。
