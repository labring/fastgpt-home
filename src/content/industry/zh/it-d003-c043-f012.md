# 安全事件应急响应的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
这个品类的数据来自SIEM、EDR、防火墙日志与主机镜像，更新节奏为实时或按单次安全事件触发。日常处理的文档包含应急响应报告、取证记录、处置方案与通报材料，文档结构多包含事件标识、时间戳、操作日志片段、处置步骤与合规校验条目，单份文档内容跨度从数页到数十页不等，无统一固定格式模板。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于数据来源为结构化日志与非结构化报告混合，且格式无统一模板，文档解析环节需兼容多类型文件格式，避免丢失日志片段与元数据。实时或按事件触发的更新节奏要求解析流程需控制耗时，避免延迟影响应急响应的处置时效。单份文档内容跨度差异大，分块策略需兼顾长日志片段与完整处置步骤的完整性，同时避免分块过大导致检索精度下降，或分块过小破坏证据链的上下文关联。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数逻辑，适配安全事件应急响应场景的文档处理需求：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 应急响应文档包含长日志片段与处置步骤，该区间可保留上下文完整性，避免分块破坏证据链的关联逻辑 |
| `chunkSplitter` | 按段落+语义拆分 | 应急响应文档的段落多对应独立处置环节或日志分类，语义拆分可提升检索环节的相关性 |
| `customPdfParse` | 启用 | 原始PDF解析可能丢失嵌入的日志截图与合规校验表格，启用自定义解析可保留完整可视化内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 单份应急响应文档可能包含数十页日志与报告，该时长可覆盖完整解析流程，避免超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 大型主机镜像关联的取证文档可能占用较大存储空间，该上限可覆盖常规事件文档规模 |
| `chunkSettingMode` | 手动配置 | 应急响应文档格式差异较大，手动配置可灵活调整分块规则适配不同文档类型 |

## 容易做错的三处
- 现象：上传PDF后无法提取内嵌的日志截图，解析结果中图片字段为空。原因：未启用`customPdfParse`配置，使用了默认的基础PDF解析逻辑，无法保留非文本可视化内容。
- 现象：检索结果仅返回孤立的日志片段，无法关联对应处置步骤。原因：`chunkSize`取值过小，将完整的处置步骤拆分为多个独立分块，破坏了上下文关联。
- 现象：上传大型取证文档后触发解析超时错误。原因：`PARSE_FILE_TIMEOUT_SECONDS`取值低于文档解析所需时长，未适配应急响应文档的内容规模。

## 怎么确认配好了
- 上传一份典型的应急响应PDF文档，查看解析结果中的图片与表格是否完整，确认自定义PDF解析配置生效。
- 提取单份文档的解析分块，核对分块长度是否符合预设区间，确认分块尺寸配置生效。
- 上传一份接近预设上限的测试文档，验证解析流程是否在预设时长内完成，确认超时配置生效。
- 检索测试文档中的特定日志片段，确认检索结果可关联对应处置步骤，验证分块规则是否适配文档结构。
