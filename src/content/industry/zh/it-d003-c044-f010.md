# 安全产品规则运营的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自WAF、IDS、防火墙及威胁情报平台，更新节奏为每日或随防护事件触发。日常产出的文档包含规则变更单、拦截日志、误报分析报告、策略回滚记录，数据字段包含规则标识、拦截时间、源IP地址、误报触发条件、策略版本号等，单位多为条（用于统计日志条目）、次（用于统计拦截事件），版本号与规则标识无单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据随防护事件实时更新或每日刷新，引用时需确保溯源信息匹配最新的策略版本与事件时间，避免出现版本错位导致的溯源信息失效。拦截日志与误报分析的单条数据量较小但条目密集，需限制单次引用的条目数避免上下文溢出，影响AI回答的准确性。规则变更单与回滚记录需关联具体的规则ID与时间戳，确保溯源时可精准定位到对应策略调整环节。同时，不同数据源的字段格式存在差异，需统一映射后才能作为可信任的引用来源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 10000–30000 token | 该品类的单条日志数据量较小，该区间可覆盖100–500条日志的总token量，平衡上下文长度与溯源覆盖范围 |
| `responseData` | 仅返回规则ID、拦截时间、误报率字段 | 匹配日常文档的核心字段，避免无关信息干扰合规审查的溯源准确性 |
| `detail` | 完整原始日志 | 满足合规审查时的全量溯源需求，确保可追溯到事件的完整细节 |
| 数据同步周期 | 每24小时同步一次 | 匹配数据源的日更节奏，确保引用内容与最新策略版本一致 |
| 来源校验规则 | 绑定策略版本号 | 确保溯源时可关联到具体的规则变更记录，符合安全合规的溯源要求 |

本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 配置引用上限时仅能选择100或900的固定档位，无法设置300左右的自定义数值。原因是平台当前的引用上限配置未开放中间区间的自定义设置，仅提供预设的可选档位。
- 尝试引用HTTP返回内容时出现报错提示。原因是未正确配置数据源的访问权限或响应格式校验，导致无法正常拉取并解析内容。
- 设置最低相关度为1后，仍输出大量与安全规则无关的引用内容。原因是未配置品类专属的字段匹配规则，导致检索时未过滤非防护相关的文档片段。

## 怎么确认配好了
- 查看AI回答的引用来源列表，确认引用条数符合配置的`quoteMaxToken`对应区间。
- 检查每条引用内容的字段是否包含规则ID、拦截时间等核心标识，确保溯源信息精准。
- 验证引用数据的更新时间是否与配置的同步周期一致，确保内容为最新版本。
- 模拟规则变更场景，确认引用的策略回滚记录可关联到对应的规则ID与时间戳。
