# 安全培训与钓鱼演练的安全与合规材料审查：对话日志与审计

## 这个品类的数据长什么样
该品类的核心数据来源于员工通讯录、邮件网关、内部培训平台与用户点击统计系统。日常产出的文档包含标准化培训课件、季度演练方案、钓鱼邮件模板库与演练结果复盘报告。数据更新周期通常为季度或年度，单条记录包含演练批次、参与人员ID、邮件发送记录、点击反馈与整改记录等字段，无固定统一单位，随文档类型与批次维度变化。

## 这些特征在「对话日志与审计」这一环带来什么约束
该品类的数据来源分散且类型多样，要求对话日志审计需支持跨系统关联员工通讯录、邮件网关等多源数据，确保演练全流程可追溯。由于数据更新周期通常为季度或年度，审计日志需支持按批次归档，避免单批次数据丢失。不同文档类型的审计需求存在差异，钓鱼邮件模板的交互日志需记录点击行为关联字段，培训课件的对话日志需保留prompt调用顺序与参数。同时，由于出错后果直接关联员工泄密与审计合规，审计环节需完整捕获每一次对话的关键标识与细节，避免关键字段缺失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` 日志追踪 | 绑定演练批次ID | 实现对话日志与具体演练批次的关联，便于按批次开展审计工作 |
| `responseChatItemId` 存储 | 开启全链路记录 | 捕获每一次模型响应的唯一标识，确保交互流程可完整回溯 |
| `detail` 字段采集 | 包含用户输入、prompt内容与点击统计 | 覆盖该品类的核心审计需求，关联员工交互与行为数据 |
| 日志保留周期 | 365 天 | 匹配该品类年度审计的常规要求，确保历史演练数据可追溯 |
| 归档触发条件 | 按演练批次完成后24小时触发 | 匹配该品类按批次组织培训与演练的业务节奏，避免零散日志堆积 |
| 异常日志告警 | 触发频率每小时校验 | 及时发现钓鱼邮件模板测试、对话调用的异常情况 |

## 容易做错的三处
- 现象：工作流对话显示失败，但模型后台存在响应日志。原因：未开启`detail`字段的异常捕获配置，导致工作流交互日志未同步记录模型响应细节。
- 现象：指定时间范围的对话日志为空。原因：未绑定`chatId`与演练批次ID，检索时未按批次筛选，导致日志无法匹配查询条件。
- 现象：应用对话的异常报错未生成审计日志。原因：未配置异常日志的自动归档触发，报错信息未写入审计日志库。

## 怎么确认配好了
- 发起一次模拟钓鱼邮件对话测试，检查日志中是否包含`chatId`、`responseChatItemId`与`detail`字段的完整信息。
- 按演练批次筛选日志，确认可检索到对应批次的所有对话交互记录。
- 触发一次异常对话调用，检查是否生成对应的异常日志条目。
- 确认FastGPT v4.17.0版本的审计日志权限配置仅授权团队可访问。
