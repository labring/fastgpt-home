# 安全基线检查的安全与合规材料审查：对话日志与审计

## 这个品类的数据长什么样
本品类的数据来源为服务器配置、中间件配置、安全设备策略及基线工具输出，更新节奏为月度或季度。日常产出的合规文档包含基线检查表、配置核查记录、整改建议与例外审批单，字段覆盖配置项ID、核查结果、整改状态、例外原因等。数据关联多类运维与审计流程，需与具体业务操作绑定，确保合规审查的全链路可追溯。

## 这些特征在「对话日志与审计」这一环带来什么约束
因数据来源分散且关联多类配置项，对话日志需建立与具体配置项的关联，实现全链路溯源。因更新频率较低，审计留存周期需匹配月度或季度的更新节奏，无需高频滚动清理。因日常文档为结构化的核查与审批材料，日志字段需覆盖配置核查结果、整改状态、例外原因等，便于后续审计对账。因出错后果直接关联安全风险，日志需支持不可篡改的归档，且可导出为合规文档格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 与安全基线配置项ID绑定 | 建立对话与对应配置项的关联，实现全链路审计溯源 |
| `responseChatItemId` | 绑定每一次核查的交互节点 | 精准记录配置核查的每一步交互结果 |
| `detail` | 存储完整配置项比对原始数据 | 留存不可篡改的核查细节，满足合规要求 |
| 日志留存周期 | 6个月 | 匹配月度/季度的基线数据更新与审计节奏 |
| 单次日志存储上限 | 1000 MB | 适配基线检查表、整改建议等文档的存储需求 |
| 归档触发条件 | 完成一次完整配置核查流程 | 自动触发日志归档，避免冗余存储 |

## 容易做错的三处
- 现象：对话日志中未显示配置项关联信息，无法溯源到对应基线文档。原因：未将`chatId`与配置项ID绑定，导致日志与业务数据脱节。
- 现象：Docker部署后无法查看运行日志，审计流程无法获取系统操作记录。原因：未配置日志挂载目录，导致运行日志未持久化留存。
- 现象：对话日志中仅显示结果未记录例外审批流程，审计时无法确认例外合理性。原因：未将`detail`字段扩展为包含例外审批单关联信息的内容，遗漏关键审计节点。

## 怎么确认配好了
- 查看对话日志列表，确认每条日志均关联有对应的安全基线配置项ID，验证`chatId`绑定配置项的配置生效。
- 进入FastGPT v4.17.0的部署环境，检查日志存储目录是否存在对应日期的运行日志，验证日志持久化配置正确。
- 导出一条完整的对话日志，确认`detail`字段包含配置项比对结果、整改建议及例外审批单关联信息，验证字段配置完整。
- 触发一次完整的安全基线核查流程，确认日志在流程结束后自动归档，验证归档触发条件配置正确。
