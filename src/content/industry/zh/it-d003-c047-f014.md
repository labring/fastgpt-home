# 安全漏洞披露处理的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据围绕单个漏洞事件生成与流转，日常文档包含安全公告、漏洞报告、修复补丁、CVE申请材料。数据来自私密漏洞报告、项目代码仓库、官方CVE编号机构及公开发布渠道，更新频率以单次漏洞事件为周期。每份文档包含漏洞编号、影响范围、修复状态、披露时间等字段，无固定批量更新节奏，仅在新漏洞被发现、修复或披露时触发更新。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据为单次漏洞事件的私密或半私密文档，需保障调用链路的安全性，因此需配置专属的API端点与令牌。单事件文档量波动较大，需适配可变的上下文长度，避免截断关键漏洞编号、影响范围等核心字段。数据更新无固定周期，仅在新事件触发时加载，因此模型配置无需频繁调整，但需支持按需加载事件相关文档。同时，因漏洞披露涉及合规要求，需确保模型输出不泄露未公开的私密漏洞细节，需限制模型的创作性参数。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 对应部署的AI Proxy服务根地址，例如`http://aiproxy:3000`，不要附加`/v1`或其他路径 | 将模型调用路由至合规的AI Proxy链路，保障私密漏洞数据的传输安全 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token，且不能为空 | 用于AI Proxy服务鉴权，避免未授权访问代理服务 |
| `maxContext` | 8000–12000 token | 适配单漏洞事件的文档总长度，避免截断漏洞编号、影响范围等核心信息 |
| `maxTokens` | 2000–3000 token | 限制单轮模型输出长度，确保漏洞评估、披露方案等内容完整且符合格式要求 |
| `temperature` | 0.1–0.3 | 降低模型创作性，确保输出内容贴合漏洞相关的标准化字段与合规要求，避免生成不准确的评估结果 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具处理漏洞相关的代码或CVE数据，提升处理准确性 |

## 容易做错的三处
- 现象：调用外部模型返回空结果，日志显示鉴权失败。原因：未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或变量值与AI Proxy服务端配置不一致。
- 现象：模型输出截断了漏洞影响范围的关键内容。原因：`maxContext`或`maxTokens`取值过小，未适配单事件文档的总长度。
- 现象：模型生成不符合合规要求的披露方案。原因：`temperature`取值过高，导致模型过度创作，偏离漏洞相关的标准化内容。

## 怎么确认配好了
- 检查FastGPT App/Admin服务端的环境变量配置，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`与部署的AI Proxy服务根地址、管理员Token配置一致。
- 上传单份漏洞报告文档，触发模型调用，检查返回结果是否包含完整的漏洞信息，无截断或缺失字段。
- 提交CVE申请材料相关的测试数据，查看模型输出是否贴合标准化字段，无过度创作的内容。
- 启用测试环境的日志追踪，确认模型调用链路无鉴权错误或超时问题。
