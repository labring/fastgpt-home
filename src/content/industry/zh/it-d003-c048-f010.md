# 安全监控与SOC值守的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自SIEM、EDR、NDR及各类威胁情报源，更新节奏分为实时与日更两类。日常处理的文档包含告警处置单、值班记录、威胁情报通报、日报周报，单份文档包含告警标识、处置流程、威胁等级、关联设备信息等字段，部分周报类文档会按周汇总告警数量与处置结果，数据字段多为结构化的操作记录与安全指标，无复杂非结构化文本嵌套。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散导致需同时对接多类知识库或数据源，实时更新的告警数据要求溯源链路支持低延迟调用。结构化字段多的特性要求溯源时需精准匹配告警ID等唯一标识，避免误关联。日更的周报类文档需按时间维度筛选溯源范围，防止引入过期数据。SOC值守的持续运行特性要求溯源环节具备容错能力，避免单数据源异常中断整体流程。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 1000–1500 token | 适配告警处置单、威胁情报通报等文档的字段长度，避免超出上下文限制 |
| `responseData` | 完整结构化字段 | 满足对告警ID、处置时间等唯一标识的精准溯源需求 |
| `detail` | 开启 | 支持提取威胁情报源的完整链接与原始内容，完成合规溯源 |
| 单次召回上限 | 前6–10条 | 匹配SOC值守日常处理的告警量级，避免冗余数据干扰研判 |
| 上下文超时阈值 | 200–400 秒 | 适配实时告警的低延迟响应要求，防止超时影响值守流程 |

## 容易做错的三处
- 调用知识库时默认列表为空，无法直接选定目标知识库。原因是未配置默认关联的数据源路径，导致系统无法自动加载对应SIEM、EDR类知识库。
- 引用内容超出上限导致告警研判环节中断。原因是未调整`quoteMaxToken`参数至适配文档长度的取值，超出系统上下文限制。
- 引用的原始来源无法下载或显示异常。原因是未开启`detail`开关，未提取到威胁情报源的完整链接信息。

## 怎么确认配好了
- 提交一条测试告警处置单，查看引用溯源模块是否自动加载关联的SIEM数据源内容。
- 调整配置项后，检查`responseData`返回格式是否包含告警ID、处置时间等所需字段。
- 触发实时告警查询，确认溯源链路的响应时间符合预设的超时阈值要求。
- 测试多数据源同时调用，检查是否能正确整合SIEM与威胁情报源的内容。
