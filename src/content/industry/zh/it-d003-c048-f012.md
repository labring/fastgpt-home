# 安全监控与SOC值守的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
该品类的数据来源为SIEM、EDR、NDR及威胁情报源，更新节奏为实时或每日。日常处理的文档包括告警处置单、值班记录、威胁情报通报、安全日报周报。告警处置单包含告警ID、触发时间、关联资产、处置步骤等字段；值班记录包含值守时段、异常记录、交接事项；威胁情报通报包含威胁类型、影响范围、处置建议；日报周报包含当日/当周告警统计、处置汇总。文档结构多为结构化表格或分段叙述，无复杂嵌套格式。

## 这些特征在「文档解析与分块」这一环带来什么约束
实时或每日更新的数据要求文档解析流程具备快速批量处理能力，避免延迟影响告警研判与升级响应。多类型业务文档需适配差异化结构，避免结构化字段被错误拆分。告警处置单内的时序化处置步骤需保留上下文关联，分块时不能割裂操作逻辑。威胁情报通报中的影响范围、处置建议等关键字段需精准提取，防止分块导致信息丢失。日报周报内的汇总统计数据需完整保留，避免拆分后无法还原整体结论。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配告警处置单、值班记录的字段长度，保留单块内的完整操作逻辑 |
| `chunkSplitter` | 按语义分段 | 适配威胁情报通报、日报周报的叙述结构，避免割裂段落语义 |
| `customPdfParse` | 启用结构化解析模式 | 适配SIEM导出的PDF告警单，精准提取表格与字段信息 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持批量导入每日的威胁情报通报与值班记录文件 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大体积日报周报的解析时长，避免超时中断 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型调整分块参数，适配多类业务文档的解析需求 |

## 容易做错的三处
- 现象：部分PDF文件无法识别，解析后核心字段为空。原因：未启用`customPdfParse`的结构化解析模式，无法提取SIEM导出的PDF告警单内的表格字段。
- 现象：上传大体积日报周报后，解析任务超时失败。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值低于实际解析所需时长，导致任务被强制终止。
- 现象：告警处置单被拆分为过短的分块，处置步骤的上下文丢失。原因：`chunkSize`设置值过小，割裂了时序化的处置操作逻辑。

## 怎么确认配好了
- 上传单份告警处置单PDF，检查解析后分块是否包含完整的处置步骤与关联资产信息。
- 上传大体积日报周报，查看解析任务的运行时长是否低于`PARSE_FILE_TIMEOUT_SECONDS`设置值。
- 批量导入多类业务文档，确认不同文档类型的解析结果均保留了核心字段与语义完整性。
- 检查文件上传上限，确认导入的文件大小未超过`UPLOAD_FILE_MAX_SIZE`设置值。
