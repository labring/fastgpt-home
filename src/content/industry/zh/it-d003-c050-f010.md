# 客户开通与租户初始化的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自CRM系统、合同订单库、身份管理平台及产品后台。日常关联文档包括客户开通申请单、租户配置表、管理员账号清单与交付确认单，单条数据包含客户唯一标识、租户编码、初始化权限配置项、管理员账号信息等字段。数据更新节奏为每完成一单客户开通流程更新一次，日常运维核对时每日同步一次身份管理系统的账号状态。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据分散来源要求引用溯源时需关联多系统元数据，需明确每条溯源信息对应CRM合同编号、身份管理系统账号创建时间等关联字段。更新节奏的差异要求溯源链路支持按开通申请提交、租户初始化完成等触发节点绑定对应版本的文档快照，避免配置变更后溯源失效。日常文档的字段差异要求溯源系统需兼容不同格式申请单、配置表的字段映射，无需强制统一字段名。初始化环节的出错后果要求溯源信息可快速定位到具体配置节点，缩短排查时长。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 字符 | 匹配日常开通文档的单条内容长度，避免截断关键溯源信息，适配FastGPT v4.17.0的节点参数规则 |
| `responseData` | 仅返回关联字段 | 减少非必要数据传输，符合该品类数据字段少且关联明确的特征 |
| `detail` | 开启 | 展示溯源信息的来源节点，适配运维人员排查需求 |
| 单次溯源关联上限 | 前3条 | 匹配每单开通流程的核心文档数量，避免冗余信息 |
| 溯源快照保存时长 | 30 天 | 覆盖从开通申请到交付确认的常规周期，满足合规审查的溯源需求 |
| 接口超时阈值 | 600 秒 | 按实测标定，适配多系统数据同步的延迟情况 |

## 容易做错的三处
- 现象：工作流节点调用溯源接口时返回空结果。原因：未正确映射开通申请单的客户ID字段与溯源系统的关联键，导致无法匹配对应业务数据。
- 现象：溯源展示的文档来源仅显示文件名，无具体配置节点信息。原因：未开启`detail`配置项，未启用详情展示功能。
- 现象：单次溯源返回的文档条数超出预设范围。原因：单次溯源关联上限配置值过高，加载了非核心的辅助文档，增加排查难度。

## 怎么确认配好了
- 手动触发一次测试客户开通流程，检查溯源信息是否关联了预设的核心业务字段。
- 查看工作流节点的运行日志，确认返回的溯源数据符合配置的返回范围要求。
- 验证溯源详情展示功能，确认可查看每条溯源信息的具体来源节点。
- 模拟配置变更操作，检查历史开通流程的溯源信息未受变更影响，仍可正常调取。
