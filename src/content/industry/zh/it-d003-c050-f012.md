# 客户开通与租户初始化的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
通常该品类的核心数据来自CRM系统、合同订单、身份管理系统及产品后台，日常处理的文档包括客户开通申请单、租户配置表、管理员账号清单、交付确认单。数据更新节奏以每单或每日为单位，单条数据包含客户身份信息、租户权限配置、交付节点状态等字段，无统一固定单位，随客户订单维度变化。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的数据来源分散且格式多样，要求文档解析环节兼容多种原生办公文档格式。数据更新节奏以单次交付或每日为单位，解析任务需具备快速响应能力，避免延迟影响客户开通流程。日常处理的文档多为结构化短文本，分块时需避免破坏客户身份、权限配置等关键字段的完整性，同时需确保敏感信息不会被无关分块携带。此外，数据随客户订单维度变化，解析规则需支持灵活适配不同客户的配置字段差异。

## 配置怎么定
本页面配置基于FastGPT v4.17.0版本，具体配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配该品类结构化短文本的字段长度，避免拆分关键权限配置信息 |
| `chunkSplitter` | 按段落拆分 | 匹配日常文档的段落结构，保留客户信息、权限项的完整语义 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 覆盖单份交付确认单、租户配置表的最大可能体积，适配批量开通场景 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 匹配数据更新的日更或单批节奏，避免因解析超时导致开通流程中断 |
| `customPdfParse` | 开启 | 保留PDF格式的开通申请单中的表格与字段布局，确保权限配置项准确识别 |

## 容易做错的三处
- 现象：前端将打包后的项目部署至服务器后，上传合规文档触发解析时返回404错误。原因：本地环境上传时文件路径为本地相对路径，部署至服务器后未同步更新文件存储目录配置，导致解析节点无法定位目标文件。
- 现象：解析任务执行后返回空结果，且日志显示未读取到文件内容。原因：未正确配置文件存储目录权限，导致解析节点无法访问上传的文档文件。
- 现象：批量推送外部系统的合规文档后，分块结果未包含敏感字段。原因：未开启`customPdfParse`配置，导致PDF格式的管理员账号清单中的表格字段被自动跳过。

## 怎么确认配好了
- 上传一份标准的客户开通申请单，查看解析结果的分块数量，确认分块长度符合预设的`chunkSize`范围。
- 部署测试环境并上传文档，验证解析节点是否能正常读取文件内容，排查路径类错误。
- 查看系统日志，确认解析任务的执行时长未超过`PARSE_FILE_TIMEOUT_SECONDS`设定值。
- 检查文件存储目录的权限配置，确保解析节点具备读取上传文件的权限。
