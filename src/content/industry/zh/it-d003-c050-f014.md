# 客户开通与租户初始化的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据通常来自CRM系统、合同订单库、身份管理系统与产品后台，更新节奏为每单或每日。日常关联文档包括开通申请单、租户配置表、管理员账号清单与交付确认单，数据字段多包含客户主体信息、权限配置项、管理员账号列表与验收节点。数据格式以结构化表格与标准化表单为主，单租户数据量通常较小但字段要求严格，需匹配合规审查的固定校验规则。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入时需支持跨系统数据的格式对齐与校验，避免因数据格式不匹配导致审查失败。单租户小体量但高严格性的字段要求，意味着模型配置需适配固定字段的校验逻辑，不可随意调整校验维度。每单/日的更新节奏要求配置的上下文长度与处理效率需匹配单次单租户的业务量，避免资源浪费或处理超时。严格的出错后果要求配置中需加入前置校验环节，确保模型输出的合规性结论可直接用于交付验收。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的参数逻辑，具体项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 适配单租户所有关联文档的总长度，避免上下文溢出导致审查中断 |
| `maxTokens` | `2000–3000 token` | 覆盖合规审查报告的完整输出需求，确保所有校验结论均可完整呈现 |
| `toolChoice` | `auto` | 支持模型自主判断是否调用知识库校验客户资质材料，适配不同租户的材料差异 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如`http://aiproxy:3000`，不得附加`/v1`或`/chat/completions`路径，不得使用单模型服务地址 | 确保模型请求路由正确，避免跨区域访问延迟或请求失败 |
| `temperature` | `0.1–0.3` | 降低模型输出的随机性，保证合规审查结论的严谨性与一致性 |
| `quoteMaxToken` | `1500 token` | 限制引用的合规材料长度，确保审查内容聚焦核心条款，避免冗余信息干扰 |

## 容易做错的三处
- 现象：触发租户审查后模型未自动调用知识库校验材料，仅生成通用回复。原因：`toolChoice`参数被误设为`none`，未开启自动工具调用能力，导致模型无法获取合规材料的关联数据。
- 现象：界面弹出“字段校验不通过”报错，无法完成租户初始化。排查项：检查`maxContext`是否适配多文档总长度，检查`AIPROXY_API_ENDPOINT`、`AIPROXY_API_TOKEN`服务端环境变量是否已配置且符合要求。
- 现象：合规审查报告的结论模糊，无法直接用于交付确认。原因：`temperature`参数设置过高，模型输出随机性强，不符合合规审查的严谨要求。

## 怎么确认配好了
- 提交测试租户的开通申请单，检查模型是否自动调用知识库校验身份管理系统的身份数据与申请单信息的一致性。
- 查看模型生成的审查报告，确认所有关联文档的字段均被覆盖，无遗漏校验项。
- 模拟输入格式错误的测试数据，检查模型是否触发对应的合规校验提示，无法直接通过审查。
- 验证`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）和`AIPROXY_API_TOKEN`（AI Proxy管理员Token）服务端环境变量配置后，发起测试请求无连接超时或权限错误。
