# 客户数据导入迁移的安全与合规材料审查：对话日志与审计

## 这个品类的数据长什么样
该品类的数据主要来自客户历史业务系统、CSV或Excel模板、数据库导出文件，以及FastGPT生成的产品导入日志。数据更新以单次迁移任务为周期，不定期触发。日常关联文档包含数据模板、迁移方案、字段映射表与迁移验证报告，核心字段包括客户业务字段映射关系、导入状态、错误编码与校验结果，无统一固定单位，随客户业务字段调整。

## 这些特征在「对话日志与审计」这一环带来什么约束
数据来源分散且格式不统一，要求对话日志需完整记录每一次导入任务的数据源路径、字段映射配置、执行时间与错误详情，便于回溯验证。更新周期不固定且单次任务数据量差异大，审计环节需支持按任务ID或时间范围检索日志，避免日志过载。关联文档与导入数据强绑定，审计需关联展示对应迁移方案、字段映射表的版本信息，确保可追溯性。核心字段的校验结果需完整留存，便于后续合规审查与问题定位。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定迁移任务唯一ID | 确保每一次导入操作的日志与对应任务精准关联，便于按任务维度检索审计 |
| `responseChatItemId` | 绑定导入操作的会话节点 | 关联每一次导入触发的对话上下文，追溯操作发起的前置配置与请求 |
| `detail` | 开启全量日志记录 | 留存字段映射规则、数据源校验结果、错误编码与详情等完整信息 |
| 日志保留时长 | 180 天 | 匹配通用合规留存周期，覆盖常规审计与问题回溯的合理范围 |
| 日志存储容量上限 | 1000 MB | 避免单任务日志占用过多存储资源，保障系统运行稳定 |
| 单次日志返回上限 | 前 500 条 | 避免单次检索返回过多日志，影响页面加载与审计效率 |

## 容易做错的三处
- 现象：同一迁移任务的审计日志加载缓慢，新创建的任务日志加载正常。原因：未按`chatId`分组存储日志，导致单会话日志条目过多，检索时触发超时。
- 现象：审计日志中缺失字段映射的配置详情。原因：未开启`detail`全量日志记录，仅存储了基础导入状态信息。
- 现象：不同迁移任务的审计日志出现字段错位。原因：未绑定`chatId`与迁移任务ID，导致日志与任务的关联关系混乱。

## 怎么确认配好了
- 进入FastGPT的审计日志页面，选择任意已完成的导入迁移任务，核对日志中是否包含`chatId`对应的任务标识。
- 查看单条导入任务的日志详情，确认是否包含字段映射规则、数据源路径等`detail`开启后的全量信息。
- 检查日志存储的容量与保留时长设置，确认符合预设的180天与1000 MB上限要求。
- 模拟发起一次小型导入迁移任务，检索对应`chatId`的日志，确认检索结果与任务执行情况完全匹配。
