# 客户数据导入迁移的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自客户历史业务系统、CSV或Excel标准数据模板、数据库导出文件，以及FastGPT产品内的导入操作日志。日常配套文档包含数据导入模板、迁移执行方案、字段映射对照表、迁移效果验证报告。数据更新节奏随客户单项目进度不定期调整，无固定周期。数据字段包含业务实体标识、原始字段名、映射后字段名、数据值、导入状态等，无统一固定单位，随客户业务场景变化。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多数据源的接入要求引用溯源必须关联原始数据的具体来源路径，避免跨数据源混淆。配套文档的版本差异会影响字段映射的准确性，溯源环节需绑定对应版本的迁移方案与字段映射表。不定期更新的数据需要记录每次导入的时间戳与操作人，确保合规审计可追溯。无固定单位的业务字段，溯源需保留原始数据的字段名与映射关系，避免后续核对时出现错位。同时，导入日志的完整留存是合规审查的必要依据，需确保溯源信息可关联到单条导入数据的全链路。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本编写，可根据实际业务场景调整。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 引用来源开关 | 开启 | 绑定导入数据的原始来源路径，满足合规溯源要求 |
| `quoteMaxToken` | 1000–1500 token | 匹配客户导入数据的单批次文本长度，避免截断溯源信息 |
| `responseData` | 保留原始字段与原文 | 保留导入数据的原始字段名与值，确保检索时可直接引用原文 |
| `detail` | 开启全量操作日志 | 记录每次导入的操作人、时间戳与状态，完善审计链路 |
| 单次召回条数 | 前3条 | 匹配导入数据的单批次数量，避免冗余信息干扰 |
| 导入超时时间 | 600秒 | 匹配批量导入的最长等待时间，避免任务异常中断 |
| 字段映射校验 | 开启强制匹配 | 校验导入数据与预设映射表的一致性，避免字段错位 |
| 日志留存周期 | 保留90天 | 满足合规审计的基础留存要求 |

## 容易做错的三处
- 现象：导入的问答对数据在检索后，返回的答复未匹配知识库原文，而是生成了新内容。原因：未正确配置`responseData`参数，未启用原文引用模式，导致系统未绑定原始导入的问答对原文。
- 现象：导入任务执行后，溯源日志中未显示原始数据来源路径。原因：未开启引用来源开关，且未配置`detail`参数开启全量日志，导致原始来源信息未被记录。
- 现象：多批次导入的同字段数据出现错位，无法按批次溯源。原因：未按导入批次绑定对应的字段映射表，导致溯源时无法区分不同批次的字段映射关系。

## 怎么确认配好了
- 执行一次测试数据导入，查看导入日志中是否包含原始数据来源、操作时间与字段映射信息。
- 检索导入的问答对数据，确认返回的答复直接引用原文片段，未生成额外内容。
- 检查`quoteMaxToken`参数的配置值，匹配测试数据的单条文本长度。
- 查看系统留存的导入日志，确认留存周期符合预设要求。
