# 客户数据导入迁移的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据主要来自客户历史业务系统、CSV/Excel模板、数据库导出文件以及产品导入日志。日常配套文档包含数据模板、迁移方案、字段映射表与迁移验证报告。数据更新频率为每单或不定期，字段覆盖客户ID、交易记录、联系人信息等业务维度，无固定统一的单位格式，部分数据存在缺失或格式混乱的情况。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源与格式的多样性要求模型接入配置需适配结构化表格、非结构化日志等多种输入类型；不定期的更新节奏意味着模型调用的上下文需支持动态调整，避免缓存旧数据影响校验结果；字段的不规范性要求模型需具备一定的格式转换与校验能力，因此需要合理配置模型的推理参数；客户数据的敏感性也要求多API密钥的隔离配置，避免单密钥泄露影响全量导入任务。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配客户导入数据的字段映射校验、脏数据清洗等任务的上下文长度需求 |
| `maxTokens` | 2000–3000 token | 满足单批次迁移数据的字段说明、映射规则的生成与校验输出 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保字段映射、数据合规校验的结果准确一致 |
| `toolChoice` | auto | 允许模型自动选择是否调用工具处理数据清洗、格式转换等任务 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的非空管理员Token | 为App/Admin服务端必需的环境变量，用于鉴权访问AI Proxy服务，不可与应用API Key、模型供应商密钥混淆 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000 | 为App/Admin服务端必需的环境变量，不可附加/v1或模型服务子路径，不可配置为单模型服务地址 |

## 容易做错的三处
- 配置多API密钥时在docker-compose.yml中出现格式错误，现象为模型调用返回密钥无效或401状态码，原因是未正确配置环境变量的数组格式或未转义特殊字符。
- 部署模型网关时未调整超时参数，现象为导入任务中途超时中断，日志显示请求超时，原因是默认超时阈值无法适配批量客户数据的校验耗时。
- 误将AI Proxy相关环境变量配置在工作流全局变量、应用API请求头或模型管理页面，现象为服务启动校验失败、模型调用返回鉴权错误或404错误，排查项：确认AI Proxy必需的环境变量已配置为App/Admin服务端的系统环境变量。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量配置，确认`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，`AIPROXY_API_TOKEN`为与AI Proxy服务端一致的非空管理员Token。
- 上传单条测试数据样本，发起字段映射校验任务，查看返回结果是否匹配预设的字段映射规则。
- 查看导入日志，确认模型调用的响应状态码为200，无密钥无效或超时类报错。
- 模拟多批次数据导入，验证不同API密钥是否按分组正常轮换调用，避免单密钥超限。
