# 客户权限与组织架构配置的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自客户HR系统、身份目录、产品后台与审计日志，日常维护权限矩阵、组织架构表、角色配置记录、权限变更单四类文档。数据更新节奏为每单或不定期，随客户权限调整、组织架构变动触发更新。数据字段包含角色ID、部门层级、权限节点、变更时间等，无统一固定的单份文档大小，需适配不同规模的客户组织数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源多系统，要求模型接入需支持对接多源身份数据，需配置适配多数据源的同步规则；更新不定期，需支持增量拉取的配置，避免重复处理旧数据；文档结构固定但规模差异大，需配置可调整的上下文长度参数以适配不同体量的权限文档；出错后果涉及越权访问与审计不通过，需配置稳定的输出参数以保证权限映射的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配权限矩阵、组织架构表的总字段长度 |
| `maxTokens` | `4000–6000 token` | 覆盖单份角色配置记录或权限变更单的内容量 |
| `temperature` | `0.1–0.3` | 保证权限映射、层级核对的输出稳定性 |
| `AIPROXY_API_ENDPOINT` | `http://{部署IP}:{代理端口}` | AI Proxy 服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions 路径，不得指向 VLLM/Ollama/Xinference 等单模型地址 |
| `AIPROXY_API_TOKEN` | `与 AI Proxy 服务端配置一致的非空管理员 Token` | 完成 AI Proxy 服务的安全身份校验，不得使用应用 API Key、模型供应商密钥或按应用签发的 Token |

## 容易做错的三处
- 调用模型时返回异常结果或连接失败。排查项：检查`AIPROXY_API_ENDPOINT`是否为 AI Proxy 服务的根地址，未指向 Ollama 等单模型地址；检查 AI Proxy 服务与上游模型服务的连通性。
- 重启服务器后模型测试失败。原因是未将ollama服务设置为开机自启，或docker镜像启动顺序错误导致代理无法连接本地模型，出现连接超时报错。
- 配置图像模型后无法启用图像输入选项。原因是未将`vision`参数设置为`true`，或未在模型接入界面勾选图像支持的对应开关，导致模型无法识别图像输入。

## 怎么确认配好了
- 检查 App/Admin 服务端的环境变量配置，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`已正确设置且非空。
- 上传一份权限矩阵文档发起模型测试，检查返回结果是否包含角色权限映射的结构化条目。
- 查看产品后台的审计日志，确认模型调用的请求与响应均被正常记录，无异常报错字段。
- 调整`maxContext`参数的取值区间，验证配置是否能适配不同规模的组织架构数据。
