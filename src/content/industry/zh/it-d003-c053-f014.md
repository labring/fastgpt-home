# 客户需求池管理的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
客户需求池管理的安全合规审查数据，来源涵盖工单系统、客户访谈记录、CRM系统与产品路线图文档，更新频率为每周或每产品版本迭代时更新。日常文档包括需求池清单、需求评估表、客户反馈记录、版本规划说明，字段通常包含需求描述、客户标识、合规相关标签、优先级、提交时间、关联的合规材料链接等，数据格式兼具结构化工单字段与非结构化客户访谈文本。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源分散的数据来源要求模型接入环节支持跨系统拉取数据，避免手动导入的误差；更新频率的周期性要求模型配置中设置定时同步任务，确保审查使用的需求池数据为最新版本；文档与字段的多样性要求模型支持解析结构化与非结构化数据，同时需要对合规相关字段进行校验，确保审查时不会遗漏必填项；安全合规审查的场景要求模型调用的配置具备可审计性，便于后续追溯审查过程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000-12000 token | 客户需求池包含多份文档与多条反馈，足够的上下文可覆盖完整的审查范围 |
| `maxTokens` | 2000 token | 合规审查结果需涵盖归并建议、合规风险点，该长度可满足详细输出需求 |
| `quoteMaxToken` | 500 token | 确保引用的合规材料内容不会超出模型处理范围 |
| `temperature` | 0.2-0.4 | 合规审查需稳定一致的判断，较低的温度值可减少随机偏差 |
| `toolChoice` | auto | 自动调用合规校验工具处理需求中的合规条款，无需手动指定 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不能为空 | 用于App/Admin服务端连接AI Proxy服务的身份鉴权 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址（例如http://aiproxy:3000，请勿附加/v1或模型服务地址） | 用于App/Admin服务端指定AI Proxy服务的访问地址 |

## 容易做错的三处
- 现象：模型调用返回`401 Unauthorized`状态码，无法完成合规审查任务。排查项：检查App/Admin服务端的`AIPROXY_API_TOKEN`是否与AI Proxy服务端配置一致且非空，`AIPROXY_API_ENDPOINT`是否为AI Proxy服务的根地址且格式正确。
- 现象：需求归并结果出现随机偏差，合规风险点判断不一致。原因：`temperature`取值超过0.5，模型输出随机性过强，不符合合规审查的稳定性要求。
- 现象：每次接入新的合规审查模型都需要重复修改配置参数，操作繁琐。原因：未使用标准化的配置文件管理模型参数，未实现一键复用配置。

## 怎么确认配好了
- 执行单次需求池数据的合规审查任务，检查返回结果是否覆盖了需求池中的所有合规相关字段。
- 检查App/Admin服务端的环境变量配置，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`已按要求配置。
- 调整`temperature`参数的取值，对比两次相同需求池的审查结果，确认输出的一致性符合预期。
- 测试批量处理需求池数据，确认模型未出现上下文溢出或请求超时的情况。
