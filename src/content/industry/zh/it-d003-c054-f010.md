# 容器平台运维的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的核心数据来自Kubernetes API、镜像仓库、监控系统与CI流水线，日常产出集群变更单、命名空间配额表、部署记录、故障报告四类运维文档。数据更新节奏为每日或随集群变更触发，文档字段包含集群标识、镜像标签、变更时间、资源配额阈值、Pod运行状态等，无统一固定格式，随具体运维流程调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散且随集群变更实时更新，引用溯源环节需精准匹配数据源与变更时间戳，避免引用过期的配额或部署记录。集群变更单、部署记录等文档结构不统一，需在召回时关联对应运维流程的唯一标识，确保溯源信息可对应到具体的Pod调度或资源调整操作。同时，容器平台运维的核心数据多与集群资源强绑定，引用时需同时携带集群命名空间与资源ID，保证溯源的唯一性，避免混淆不同集群的配置信息。

## 配置怎么定
本文适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1800 token | 容器平台运维的单条合规文档多为500–1000 token，结合检索到的切块大小与业务文档长度，避免截断关键配额或变更信息 |
| `responseData` | 携带源文档元数据 | 需返回集群ID、变更时间、镜像仓库地址等元数据，满足溯源时关联具体运维记录的需求 |
| `detail` | 开启完整源信息展示 | 便于运维人员核对引用内容与实际集群配置的一致性，匹配故障排查或合规审查的场景 |
| 单次搜索上限 | 前3–5条 | 容器平台运维的合规文档关联度较高，过多结果会增加溯源复杂度，同时符合集群变更记录的常规召回量 |
| 分块重叠长度 | 100–200 token | 适配集群变更单等长文本的分块衔接，避免关键变更步骤被分割在不同切块中，确保变更流程的完整引用 |

## 容易做错的三处
- 现象：检索到匹配的知识库切块，但返回结果未包含引用源地址。原因：未开启`responseData`配置项的元数据返回开关，未携带源文档的存储路径或API地址。
- 现象：返回的引用内容超过设置的`quoteMaxToken`上限。原因：知识库切块大小设置为5000 token，超过`quoteMaxToken`的取值，导致单条切块直接超出限制。
- 现象：不同分类的工作流调用知识库后，溯源信息无法统一关联。原因：未在配置中统一源文档元数据的标识字段，导致不同知识库的溯源格式不一致。

## 怎么确认配好了
- 发起一次集群变更单相关的查询，检查返回结果是否包含集群命名空间、变更时间等元数据。
- 查看返回内容的Token长度，确认未超过设置的`quoteMaxToken`取值。
- 测试不同分类的工作流调用，确认所有知识库返回的溯源格式一致。
- 模拟检索过期的部署记录，确认返回的源数据时间戳与实际变更时间匹配。
