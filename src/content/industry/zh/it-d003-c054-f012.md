# 容器平台运维的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
该品类的日常文档包含集群变更单、命名空间配额表、部署记录与故障报告，数据来自Kubernetes API、镜像仓库、监控系统与CI流水线，更新频率为每日或每次集群变更后。文档结构多为结构化字段与文本描述结合，包含变更时间、影响范围、资源配额数值、异常节点ID等字段，资源类字段多带核、GiB等单位，故障报告则包含报错日志片段与排查步骤。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的结构化字段占比高且带明确单位，解析时需避免将数值与关联单位拆分，否则会导致合规审查时资源配额判定错误。短文本日志片段占比大，分块时需避免截断完整报错信息或排查步骤。高频更新的文档要求解析流程具备低延迟特性，否则无法匹配集群变更的实时审查需求。多来源的文档格式差异较大，需统一解析规则适配不同结构的内容，避免遗漏关键审批字段。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数规则制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配该品类文档中结构化字段与短日志的混合长度，避免截断关键信息 |
| `chunkSplitter` | 按段落+语义边界 | 适配集群变更单、故障报告的段落结构，保留上下文关联 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–120 秒 | 匹配高频更新文档的解析速度需求，避免因超时导致解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量导入集群变更记录、故障报告归档的文件大小上限 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（配额表/变更单）调整分块参数，满足合规审查的精准性要求 |
| `customPdfParse` | 关闭 | 该品类多数文档为结构化文本或日志格式，无需自定义PDF解析规则，减少解析开销 |

## 容易做错的三处
- 现象：解析自Kubernetes API的boolean类型字段经后续处理后为空。原因：未配置结构化字段的类型映射规则，导致解析时未保留字段原始类型，引发类型转换异常。
- 现象：解析监控日志时抛出Cannot redefine property: toString错误。原因：自定义解析规则中错误修改了内置对象的原型属性，触发系统安全校验拦截。
- 现象：导入批量集群变更记录后，仅部分文档被成功索引。原因：单文档分块数量超出系统默认上限，未开启自动拆分分块的配置项。

## 怎么确认配好了
- 上传一份典型的命名空间配额表，核对解析后的字段是否覆盖了业务要求的核心内容。
- 触发一份故障报告的解析流程，确认解析耗时未超出预设的超时阈值，具体阈值按业务场景标定。
- 导入单份符合品类特征的文档，检查分块后的内容未截断关键上下文关联信息，分块规则按文档类型调整。
- 查看系统运行日志，确认无自定义解析引发的异常报错。
