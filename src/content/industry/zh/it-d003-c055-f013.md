# 容量规划与资源扩缩容的安全与合规材料审查：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据主要来自云账单、监控系统、业务预测报告与压测结果。日常产出的文档包含容量规划报告、扩容申请单、资源利用率报表及预算测算表。数据更新节奏通常为周度或月度，部分高频调整场景下可按季度更新。文档字段包含资源类型、峰值负载阈值、实例规格、预算额度等，对应单位为计算核心数、内存容量单位、金额单位等。

## 这些特征在「权限与数据隔离」这一环带来什么约束
数据来源分散且涉及多类敏感业务资源信息，不同团队的资源数据存在明确归属边界，需严格隔离以避免越权访问。更新频率的差异要求权限配置适配不同数据的流转周期，月度更新的预算数据需更严格的审批权限。文档中包含敏感的预算与资源配置信息，不同角色仅可访问对应职责范围内的文档。跨团队的资源扩缩容申请需通过权限校验，确保仅授权人员可发起或审批操作。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 团队ID `teamId` | 绑定对应业务团队的唯一`teamId` | 明确隔离不同团队的资源规划数据，避免跨团队越权访问 |
| 场景模板ID `tmbId` | 为容量规划与资源扩缩容场景配置专属`tmbId` | 将权限校验绑定至特定业务场景，防止无关模板的权限滥用 |
| 成员权限范围 | 按角色划分，团队负责人可配置全量规则，SRE仅可查看与调整本团队资源数据 | 匹配该品类的角色职责边界，避免误操作引发高峰故障或预算超支 |
| 数据隔离范围 | 限定`teamId`下的资源数据仅对授权成员可见 | 该品类数据包含敏感的预算与资源配置信息，需严格控制访问范围 |
| 审批权限配置 | 设置扩容申请需经团队负责人审批 | 匹配该品类的出错后果管控要求，强化变更流程的合规性 |

## 容易做错的三处
- 界面提示“没有权限操作此对话记录”，原因是当前用户未绑定对应`teamId`，无法访问该团队的容量规划与资源扩缩容数据。
- 团队版订阅的免登录窗口链接数量无法调整至100个，原因是未在对应`teamId`下配置自定义限额，默认限额为10个。
- 配置本地部署模型后测试提示权限错误，原因是未将模型访问权限绑定至当前`teamId`，导致跨团队权限校验失败。

## 怎么确认配好了
- 登录FastGPT v4.17.0的对应`teamId`，检查容量规划报告的可见范围是否仅包含授权成员。
- 发起扩容申请，验证审批流程是否仅对团队负责人开放操作权限。
- 尝试修改免登录窗口链接数量，确认可调整至自定义数值。
- 调用本地部署模型进行测试，验证仅授权用户可访问绑定的模型资源。
