# 工单受理与问题分级的安全与合规材料审查：对话日志与审计

## 这个品类的数据长什么样
本品类数据来自工单系统、客服聊天记录、产品运行日志与客户合同SLA文件。日常留存的文档包括客户工单、问题分级表、处理操作记录、服务合规报告。数据更新节奏为实时或每日批次更新，核心字段包含会话标识`chatId`、响应条目`responseChatItemId`、处理详情`detail`、工单编号、问题分级标签与响应时效记录，无额外虚构统计数值。本页适配FastGPT v4.17.0版本。

## 这些特征在「对话日志与审计」这一环带来什么约束
本品类的数据来源分散，包含工单系统、聊天记录、产品日志与SLA文件，不同来源的日志格式存在差异，需完成标准化处理后才能纳入审计链路。实时或每日批次的更新节奏，要求审计环节支持低延迟数据写入与批量校验。核心字段`chatId`、`responseChatItemId`、`detail`需作为会话与工单绑定的唯一标识，任意字段缺失将导致工单溯源失败。SLA相关记录需与会话日志强绑定，避免出现响应超时与SLA违约的审计盲区，同时需明确工单与会话的关联关系，支撑问题复现与责任分派的审计验证。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 会话日志存储周期 | 365–730 天 | 匹配合规审计的通用留存要求 |
| 审计上下文召回上限 | 前 8 条会话记录 | 适配工单受理的常规上下文长度 |
| `chatId` 绑定规则 | 与工单ID一一映射 | 确保每一条会话日志可追溯至对应工单 |
| `responseChatItemId` 关联规则 | 绑定至具体处理响应 | 精准定位单次会话的处理结果 |
| `detail` 字段校验 | 强制开启 | 确保审计日志包含完整处理信息 |
| 异常告警延迟阈值 | 60 秒 | 及时响应处理中断类问题 |

## 容易做错的三处
- 现象：对话窗口中提问越多响应越慢，知识库检索耗时过长。原因：未配置上下文历史清空触发条件，导致会话日志持续累积，超出系统处理上限。
- 现象：OpenAI网络不通或关联接口启动报错，导致工单处理中断。原因：未设置异常日志告警阈值，或告警延迟设置过长，无法及时触发异常通知。
- 现象：工单审计时无法追溯对应会话记录。原因：未开启`chatId`与工单ID的绑定规则，导致会话与工单的关联关系缺失。

## 怎么确认配好了
- 生成一条测试工单，发起会话并完成分级处理，核对`chatId`是否与工单ID完成绑定。
- 查看审计日志列表，确认`responseChatItemId`与`detail`字段均已完整记录。
- 模拟异常触发场景，确认系统会在设定延迟内发出告警通知。
- 调整上下文召回上限，验证会话日志的召回数量符合配置要求。
