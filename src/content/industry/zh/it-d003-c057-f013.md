# 工单受理与问题分级的安全与合规材料审查：权限与数据隔离
本页面基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的数据主要来自工单系统、聊天记录、产品日志与客户合同SLA，更新频率为日级或实时。日常文档包含客户工单、问题分级表、处理记录与服务报告，核心字段包括工单唯一标识、客户关联标识、问题分级标签、响应时限、SLA履约状态等，数据围绕客户反馈的问题流转，覆盖从受理到闭环的全流程。

## 这些特征在「权限与数据隔离」这一环带来什么约束
该品类的数据包含客户敏感的合同SLA、工单详情，且随客户反馈实时更新，不同客服团队负责的客户群体存在明确边界。权限与数据隔离需匹配团队权责划分，避免跨团队访问非负责客户的工单与处理记录，同时需保证隔离规则不干扰工单实时流转与分级操作，防止因权限校验延迟导致响应超时，还要确保历史工单数据的隔离一致性，避免跨团队的历史数据泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| :--- | :--- | :--- |
| `teamId` | 绑定对应客服团队的唯一标识，取值为团队创建时生成的`teamId` | 匹配客服团队的权责划分，确保仅同团队成员可访问对应客户的工单数据 |
| `tmbId` | 关联对应客户工单的`tmbId`字段 | 实现单工单级别的数据隔离，避免跨客户的工单数据泄露 |
| 权限校验触发时机 | 工单加载、问题分级、数据导出时触发 | 覆盖核心操作环节，防止未授权访问敏感工单数据 |
| 导出数据范围 | 仅允许筛选同团队工单，单次导出上限为`前 500 条` | 限制敏感数据的导出规模，降低泄露风险 |
| 权限校验超时阈值 | 600 秒 | 确保权限校验不干扰工单实时处理，避免响应超时 |

## 容易做错的三处
- 工作流中配置权限隔离相关插件后，插件输入输出参数无显示且无报错日志。原因是未正确绑定`teamId`或`tmbId`参数到插件配置，导致系统无法识别权限校验的关联数据。
- 多账号登录同一团队时，无法查看对应团队的工单数据。原因是未正确配置`teamId`的权限映射，导致账号与团队的关联关系未生效。
- 历史工单数据导出时出现字段缺失。原因是旧版工单数据未填充`tmbId`字段，导致权限校验无法匹配对应团队，出现数据隔离异常。

## 怎么确认配好了
- 以非团队成员账号登录，尝试访问目标团队的工单列表，确认无法查看或提示无权限。
- 配置权限校验规则后，发起工单分级操作，确认操作日志中包含`teamId`或`tmbId`的校验记录。
- 导出同团队工单数据，确认导出结果仅包含当前配置的`teamId`关联的工单，无跨团队数据。
- 模拟权限校验超时场景，确认系统触发超时提示且不影响工单的基础受理流程。
