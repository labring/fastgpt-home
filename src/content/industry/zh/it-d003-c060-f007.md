# 广告账户开户审核的安全与合规材料审查：对话日志与审计

## 这个品类的数据长什么样
该品类的数据来自广告平台后台、国家企业信用信息公示系统、客户提交材料与行业准入规则。日常处理的文档包含开户申请、营业执照、行业资质、开户审核记录。数据更新频率为每日或随每笔开户申请同步。数据字段包含主体统一社会信用代码、行业资质编号、申请提交时间、审核状态等，仅保留申请与审核的全流程原始记录，无额外自定义统计字段。

## 这些特征在「对话日志与审计」这一环带来什么约束
数据来源分散，需在审计环节关联多平台的日志条目，因此对话日志需支持跨数据源的关联查询。更新随申请同步，审计需支持按申请单维度回溯全流程，不能仅按时间筛选。文档结构固定，日志需保留原始材料字段的完整映射，不能随意截断或修改字段名。出错后果明确，审计需留存完整的审核操作日志，以便快速定位资质核验、准入判断环节的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 会话日志存储时长 | 180 天 | 匹配合规审计的常规存档周期要求 |
| 日志关联标识 | 绑定`chatId`与开户申请单号 | 确保每笔开户申请的全流程对话可按申请单唯一检索 |
| 详情展示字段 | 完整加载`detail`字段内容 | 保留原始审核交互的所有细节，匹配业务文档的字段映射规则 |
| 跨源日志关联 | 按`responseChatItemId`关联多数据源日志 | 统一展示广告平台、企业信用系统的审核过程数据 |
| 异常日志触发阈值 | 300-600 秒超时 | 覆盖常规审核操作耗时，避免误触发异常告警 |

## 容易做错的三处
- 查看会话日志时显示空白或返回“invalid chatId”报错。未将开户申请单号与`chatId`正确绑定，导致日志无法关联到对应申请单，无法按申请维度检索。
- 上传的营业执照、行业资质等材料未参与大语言模型的审核统计。未配置日志与上传数据的关联规则，上传的材料数据未被加载到对话上下文的`detail`字段中。
- 调用多模态API审核图片类资质时返回400 invalid image状态码。未在日志审计环节校验图片格式与尺寸参数，导致不符合接口要求的材料被直接提交至审核流程。
