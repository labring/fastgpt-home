# 广告账户开户审核的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
这个品类的核心数据围绕广告账户开户全流程的合规材料生成，日常处理的文档包括开户申请单、营业执照扫描件、对应行业经营资质文件、历史开户审核记录。数据主要来自广告平台后台系统、国家企业信用信息公示系统、客户线下提交的纸质与电子材料，以及公开的行业准入规则。数据更新节奏随开户申请触发，单条申请的材料集更新频率为单次申请周期内，整体日更新量随业务量波动。需要核验的字段包含主体统一社会信用代码、行业许可编号、材料有效期等，无固定统一的字段排序规则。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的材料分散来源与单次触发的更新节奏，要求模型调用需按需触发，避免无效预加载。多类型混合的材料结构，包含结构化文本与非结构化扫描件，要求配置支持多模态识别的模型能力。单条申请的材料体量有限但字段校验逻辑严格，需要限制模型输出的上下文长度，避免冗余信息干扰资质核验。同时，审核失误会直接导致开户失败或违规投放，要求模型输出需附带可溯源的引用依据，配置中需保留结果校验的接口空间。此外，不同行业的准入规则存在差异，模型需具备灵活适配不同行业校验逻辑的能力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 该品类需处理营业执照、行业资质等非结构化扫描件，多模态能力可准确识别图片中的文字与字段信息 |
| `maxContext` | 8000–12000 token | 单条开户申请的材料合集通常包含3-5份文档，该区间可完整承载所有材料的上下文信息，避免截断关键的资质核验内容 |
| `temperature` | 0.1–0.3 | 资质核验需严格遵循规则，较低的温度值可降低模型幻觉概率，保证不同审核任务的结果一致性 |
| `quoteMaxToken` | 1500 token | 需为模型输出的引用依据预留足够长度，确保可完整展示材料来源与核验逻辑，便于后续追溯 |
| `toolChoice` | 固定为`none` | 该场景无需调用外部工具，仅需基于输入材料完成资质核验，避免工具调用带来的额外误差 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions 路径 | 该变量为App/Admin服务端必需环境变量，指向AI Proxy服务根地址，不得填写单模型服务地址 |

## 容易做错的三处
- 现象：模型调用返回“上下文过长”报错，状态码413。原因：未根据单条开户申请的材料体量调整`maxContext`参数，导致超过模型支持的最大上下文阈值。
- 现象：GPU资源使用率长期低于30%，CPU单核占用率持续100%。原因：未配置多模态模型的GPU加速调度，导致推理任务仅由CPU核心处理，无法充分利用GPU算力，该问题常见于未指定模型运行硬件的部署场景。
- 现象：模型输出的资质核验结果出现矛盾判断。原因：`temperature`参数设置过高，导致模型每次输出的逻辑不一致，无法保证审核标准的统一。

## 怎么确认配好了
- 上传单份典型的开户申请材料集，包含营业执照扫描件与行业资质文件，触发模型调用，检查是否能正确识别图片中的关键字段信息。
- 查看App/Admin服务端启动日志，确认`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致且非空）的环境变量已正确配置，服务启动校验无失败，调用链路无超时报错。
- 调整`temperature`参数至0.1与0.3两个区间，对比两次输出的核验结果，确认结果一致性符合业务要求。
- 测试多份不同行业的资质材料，检查模型是否能适配不同行业的准入规则判断逻辑，无明显逻辑偏差。
