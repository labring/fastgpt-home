# 性能测试与容量评估的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来源包括压测平台采集的运行数据、APM监控的链路延迟、数据库慢日志记录的查询瓶颈、生产流量基线的峰值阈值。日常产出的文档包含压测方案、容量评估报告、压测数据记录与优化建议单，数据更新频率为每月或每重大版本发布时。数据字段包含吞吐率（单位：次/秒）、平均延迟（单位：毫秒）、CPU/内存占用率、资源余量（单位：GB），以及压测模型配置、瓶颈定位结论等核心内容。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的数据来源分散且多为技术监控类数据，引用溯源时需关联压测平台、APM监控等多个数据源的对应记录，避免单一数据源的局限性。数据更新频率较低但随重大版本迭代会发生显著变化，需在引用时绑定对应版本的数据集以保证溯源一致性。日常文档包含多类专业技术文件，字段多为性能相关的量化指标，需精准匹配字段名称与单位，避免出现指标混淆。同时由于本品类聚焦吞吐、延迟与资源余量，引用时需明确标注对应指标的采集场景，若溯源失效可能导致性能评估结论失真，引发高峰期超时、资源采购不足或扩容浪费等问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的功能逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 字符 | 适配容量评估报告、压测数据记录等长文档的内容长度，避免截断核心性能指标 |
| `responseData` | 仅返回关联文档 | 限定仅返回与性能测试指标直接相关的引用来源，过滤无关的非业务内容 |
| `detail` | 完整展示引用元数据 | 包含引用文档的文件名、采集时间、对应指标字段，满足合规审查的溯源要求 |
| 引用数据源范围 | 压测平台、APM监控、数据库慢日志 | 覆盖本品类核心数据来源，保证引用的完整性与准确性 |
| 版本锁定开关 | 开启 | 绑定数据更新的版本节点，避免因数据迭代导致溯源失效 |

## 容易做错的三处
- 出现`quote type error`报错：界面弹出参数格式不合法的提示，原因是引用的性能指标字段未匹配预设的量化字段规则，或输入的变量格式不符合系统要求。
- 下拉菜单仅显示单个可引用变量：无法选择多个压测指标或文档作为引用源，原因是未开启多变量引用配置，系统默认仅支持单变量关联。
- 引用内容未展示文件地址：回复中未包含引用文档的存储路径或采集来源，原因是未开启`detail`配置的元数据展示开关，仅返回了指标内容未附带溯源信息。

## 怎么确认配好了
- 提交包含性能指标查询的测试请求，检查返回结果中是否包含至少2个不同数据源的引用记录。
- 触发格式异常的引用测试，验证调整配置后`quote type error`报错是否消失。
- 查看引用配置面板，确认`quoteMaxToken`的取值与本品类文档的平均长度匹配。
- 生成模拟的容量评估报告查询，检查返回结果中是否附带文档文件名与采集时间等元数据。
