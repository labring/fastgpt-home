# 性能测试与容量评估的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
这个品类的数据主要来自压测平台、APM监控、数据库慢日志与生产流量基线。日常产出的文档包括压测方案、容量评估报告、压测数据记录与优化建议单，更新频率为每月或每重大版本发布时。文档通常包含多级目录结构，字段涵盖吞吐率（QPS）、延迟（毫秒）、CPU与内存使用率、瓶颈指标等，单份文档的正文长度跨度较大。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于文档来源多样且格式不统一，解析环节需要适配压测方案的Word、容量评估报告的PDF、压测数据的CSV等多种格式。文档的多级目录结构要求解析时保留层级关联，避免丢失章节与对应数据的绑定关系。单份文档正文跨度较大，拆分时需保证每个分块包含完整的指标上下文，避免割裂吞吐率、延迟等核心性能数据。同时需控制解析时长，防止因超时导致后续流程受阻，月度更新的文档也无需高频增量解析，全量解析即可覆盖更新内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 性能测试文档包含大量指标与上下文，该长度可保留单组压测数据的完整关联 |
| `chunkSplitter` | 按段落+语义拆分 | 性能数据与分析结论绑定紧密，按语义拆分可避免拆分后无法关联指标与分析内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 大型压测报告或多批次数据记录的解析耗时较长，该区间可覆盖多数场景的解析需求 |
| `customPdfParse` | 启用外部解析器配置 | 内置解析器对压测报告的表格格式适配性不足，外部解析可更好保留原始排版与数据结构 |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | 大型压测数据集的归档文件通常体积较大，该阈值可覆盖多数业务场景的上传需求 |

## 容易做错的三处
- 配置`customPdfParse`后未正确设置外部解析器密钥，导致PDF格式的压测报告解析失败，界面显示文件解析超时或结果为空。
- 未针对飞书文档的多级目录调整解析配置，导致仅解析首章节内容，多级目录下的压测数据无法被完整检索。
- Docker部署时未正确挂载文件解析模块，或调用API解析时未正确传递文件参数，导致接口返回调用成功但无解析结果。

## 怎么确认配好了
- 上传一份典型的压测报告PDF，检查解析后的文本是否保留了原始的多级目录结构与表格数据。
- 调用API上传小型压测文档，确认接口返回的解析结果包含完整的文本内容，无空字段或截断情况。
- 查看FastGPT v4.17.0的解析模块日志，确认`PARSE_FILE_TIMEOUT_SECONDS`的配置值未触发超时报错。
- 测试上传超过1000 MB的压测数据归档文件，确认未触发`UPLOAD_FILE_MAX_SIZE`的限制报错。
