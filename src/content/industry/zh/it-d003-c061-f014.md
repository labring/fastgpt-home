# 性能测试与容量评估的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自压测平台、APM监控系统、数据库慢日志以及生产流量基线。日常产出的文档包括压测方案、容量评估报告、压测数据记录和优化建议单，数据更新频率为每月或每重大版本发布时。数据字段包含吞吐率、延迟时间、资源占用率、峰值并发数等，单位分别为请求/秒、毫秒、百分比、并发数。核心处理环节围绕压测模型设计、瓶颈指标定位与容量结论复核展开，结果直接关联业务高峰期的服务稳定性与资源投入合理性。本内容基于FastGPT v4.17.0版本编写。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且更新节奏固定，要求模型接入时需支持多源数据拉取的定时任务配置，避免频繁拉取占用压测与监控资源。日常文档结构标准化，字段明确，要求模型需能识别固定格式的压测指标，无需额外适配不同来源的文档格式。核心指标如吞吐率、延迟的实时性要求较高，需配置合理的上下文长度与响应参数，确保分析结果匹配业务迭代节奏。容量评估结论需严谨可追溯，需开启结果引用相关配置，保障安全与合规审查的可溯源性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions 路径 | 作为App/Admin服务端环境变量，指定AI Proxy服务访问地址，保障服务间通信合法性 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，且不能为空 | 作为App/Admin服务端环境变量，用于AI Proxy服务身份鉴权，符合合规审查要求 |
| `maxContext` | 8000–12000 token | 适配压测报告、容量评估报告等文档的平均长度，避免上下文截断丢失关键指标 |
| `maxTokens` | 2000–3000 token | 控制模型输出的容量结论长度，确保结果简洁且覆盖核心优化建议 |
| `quoteMaxToken` | 1000 token | 限制引用的压测数据片段长度，保障合规审查时可快速定位指标依据 |
| `temperature` | 0.3–0.5 | 降低输出随机性，确保容量评估结论的严谨性与一致性 |

## 容易做错的三处
- 选择简易模型后工作流无法正常加载，原因是未在模型接入配置中关联对应模型的权限与调用路径，导致系统无法识别可用模型。
- 模型调用超时或响应过慢，原因是未合理配置`maxContext`与响应超时参数，导致模型需要处理过长的压测数据上下文，超出系统资源承载上限。
- 模型测试在第三方平台通过但在FastGPT中报错，排查项为检查App/Admin服务端配置的`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`是否与AI Proxy服务端配置一致，未配置必填项会导致启动校验失败。

## 怎么确认配好了
- 核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容，确保与AI Proxy服务端配置一致。
- 运行单次压测数据的模型分析任务，检查输出结果是否包含完整的吞吐率、延迟等核心指标，无明显上下文截断情况。
- 查看模型输出的引用片段，确认`quoteMaxToken`的配置是否符合合规审查时的片段长度要求。
- 调整`temperature`参数后对比两次输出结果，确认输出一致性符合容量评估的严谨性要求。
