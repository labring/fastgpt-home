# 投标文件编制的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的核心数据围绕单份投标项目生成，日常文档包括投标文件、资格证明、商务偏离表、技术偏离表。数据来源为招标公告、招标文件、企业资质库、供应商报价，更新频率为每单一次，每份投标项目对应一套独立数据。文档结构严格匹配单份招标文件的格式要求，包含招标条款响应、资质证明附件、报价明细等固定字段，无通用统一格式，需适配不同招标方的个性化规则。

## 这些特征在「引用来源与溯源」这一环带来什么约束
单项目独立更新的特性要求每次投标前需重新拉取最新的招标公告、资质库与报价数据，避免引用过期内容。文档结构无通用格式的特点，要求引用溯源需严格匹配单份招标文件的特定字段，无法依赖通用模板。多源数据混合使用的场景，要求系统能区分招标要求、企业资质、供应商报价等不同数据源的引用来源，避免混淆。废标级别的出错后果，要求引用溯源的准确性必须达标，确保每一处引用都能对应到原始数据源的具体片段。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配投标文件单条条款响应的常规内容长度，避免截断关键合规信息 |
| `responseData` | 仅返回关联文件名与引用片段 | 符合投标文件合规审查需明确溯源来源的要求，便于快速核对引用内容 |
| `detail` | 完整 | 确保资质材料核对时引用内容完整可验证，避免片段缺失导致的资格不符风险 |
| 单次搜索上限 | 前6条 | 覆盖单份招标公告的核心要求条款，兼顾检索准确性与处理效率 |
| 最大上下文 | 4000–6000 字符 | 适配多页招标文件的上下文关联，确保条款响应的逻辑连贯 |
本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 界面显示`quote type error`报错，原因是输入的引用变量未匹配系统预设的数据源字段格式，未正确绑定招标公告、资质库的固定元数据。
- 仅能选择单个变量作为引用源，无法关联多个数据源，原因是未配置多变量合并的引用池，未开启多源数据关联开关。
- API调用未返回引用的文件名，原因是未开启`responseData`参数的元数据返回配置，或配置中未指定返回文档名称字段。

## 怎么确认配好了
- 上传一份测试用的招标文件与资质库样本，发起条款响应测试，检查生成内容是否附带关联的文件名与具体引用片段。
- 尝试选择多个数据源变量作为引用源，确认配置生效后支持多变量关联引用。
- 输入不符合格式的自定义变量，检查是否触发`quote type error`报错，验证校验规则正常生效。
- 查看生成的投标文件响应内容，确认引用片段与原始数据源的匹配度符合预期，无上下文缺失或错位问题。
