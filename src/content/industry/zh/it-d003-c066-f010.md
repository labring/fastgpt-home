# 搜索广告关键词管理的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的日常文档包含关键词清单、否词表、出价记录与搜索词报告，数据来源为搜索广告后台、搜索词报告、竞价排名数据及落地页数据。数据更新节奏通常为日度或周度，字段包含关键词匹配类型、出价金额、搜索量、否词匹配模式、点击转化数据等，单位涵盖元、次、字符等，无固定统一的标准化字段格式，需按对应广告平台的导出规则整理。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据来源分散，涉及广告后台、搜索词报告等多个平台，引用溯源时需准确关联不同数据源的关键词唯一标识，避免混淆不同投放周期的内容。数据更新节奏为日度或周度，需确保引用的材料与当前投放周期的关键词、否词表一致，否则会导致合规审查偏差。文档字段无统一格式，需针对不同导出文件配置字段映射规则，确保溯源时能精准匹配关键词与对应审查材料。同时，错误的溯源会引发无效点击、品牌词被抢等问题，需严格绑定数据源与关键词的对应关系。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 适配搜索广告关键词清单、否词表等文档的平均内容长度，避免截断合规审查所需的关键信息 |
| `responseData` | 仅返回匹配的关键词与来源字段 | 过滤无关数据，确保溯源结果聚焦于广告投放的核心合规材料 |
| `detail` | 开启完整来源展示 | 展示原始数据的导出文件名、广告平台标识，便于快速核对来源 |
| 单次搜索上限 | 前10条 | 覆盖日常关键词扩展、否词筛选的核心数据范围，避免过多冗余信息干扰审查 |
| 最大上下文长度 | 5000–7000 字符 | 适配多份广告文档的批量审查需求，确保所有引用来源都能被完整关联 |

## 容易做错的三处
-  知识库变量引用下拉框空白，无法选择变量。原因是未在工作流中提前定义与广告数据源绑定的全局变量，或变量未配置为可被知识库搜索节点引用的类型。
-  日志中无法区分不同关键词的来源数据。原因是未配置`detail`参数开启完整来源展示，或未在字段映射中绑定关键词的唯一标识字段。
-  大模型返回伪造的引用ID。原因是未开启`responseData`参数限制返回字段，导致模型无法准确匹配原始数据源的标识信息，或上下文长度不足导致关键来源被截断。

## 怎么确认配好了
-  进入FastGPT v4.17.0的工作流配置页面，打开知识库搜索节点的变量引用设置，检查是否有已定义的广告数据源变量出现在下拉列表中。
-  运行一次关键词审查任务，查看返回结果的溯源信息，确认是否包含原始数据的文件名或平台标识。
-  检查任务日志，确认每条引用的关键词都绑定了对应的数据源字段，无空值或混淆情况。
-  调整`quoteMaxToken`参数后，测试不同长度的关键词清单，确认无关键信息被截断。
