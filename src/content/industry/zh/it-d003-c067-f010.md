# 数据安全分类分级的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
本品类数据主要来自数据资产盘点、数据库元数据、业务系统说明与公开法规文件，日常文档包含数据目录、分类分级规则、重要数据识别表、评审纪要。数据更新以季度为周期，或在对应业务系统发生变更时同步调整。文档结构多包含数据资产标识、敏感字段标注、分级阈值、评审结论等字段，无统一标准化格式，需结合具体业务场景适配。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类数据的分散来源、非标准化结构与非固定更新节奏，会对引用溯源环节带来多重约束。首先，多源异构的元数据与文档需适配不同的索引规则，无法依赖单一的字段匹配逻辑完成溯源。其次，非固定更新周期要求溯源时需校验文档的最新版本，避免引用过期的分类分级规则导致合规风险。另外，无统一文档结构会增加精准匹配数据资产与分级结果的难度，需额外关联资产标识与文档内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 本品类文档多为结构化元数据与评审纪要，单条引用需覆盖完整分级规则与资产关联信息，避免截断关键内容 |
| 最大上下文 | 前3–5条匹配结果 | 数据目录与分级规则的关联条目较多，过多结果会超出上下文上限，过少则无法覆盖全量关联资产 |
| `detail` | 开启 | 需返回引用文档的评审纪要、变更记录等溯源细节，满足合规审查的追溯要求 |
| 单次检索超时阈值 | `600 秒` | 数据资产盘点的元数据查询可能涉及多表关联，需预留足够的检索时间 |
| 检索排序规则 | 按匹配精度+更新时间排序 | 需优先返回与当前任务相关且最新的源文档，确保溯源结果的准确性与时效性 |

## 容易做错的三处
- 现象：检索后仅返回引用标识，未展示对应分类分级规则内容。原因：未开启`responseData`参数，仅返回了文档索引信息，未加载实际文档内容。
- 现象：在工作流中引用数据安全分类分级插件后执行代码时出现报错。原因：配置的`quoteMaxToken`取值超出FastGPT v4.17.0的上下文阈值，导致上下文溢出报错。
- 现象：溯源时发现引用的评审纪要不准确，与当前数据资产不匹配。原因：未设置按更新时间过滤的检索规则，引用了过期的分级规则文档。

## 怎么确认配好了
- 发起一次数据资产分类的检索任务，检查返回结果中是否包含源文档的完整分级规则内容。
- 查看检索日志，确认引用的文档版本与当前业务系统的最新变更记录一致。
- 测试不同数量的匹配结果输入，确认未出现上下文溢出的提示。
- 验证溯源信息中是否包含数据资产标识、评审主体与变更时间等关键字段。
