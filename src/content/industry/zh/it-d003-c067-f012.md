# 数据安全分类分级的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
本品类的数据来自数据资产盘点结果、数据库元数据、业务系统说明文档及公开法规文件，日常处理的文档包括数据目录、分类分级规则表、重要数据识别清单、评审纪要等。数据更新频率为季度级或随业务系统变更时触发，文档多为结构化表格、带格式的规则说明或评审记录，字段包含资产编号、数据类别、敏感等级、管控要求等，无统一固定单位，字段单位随文档类型调整。

## 这些特征在「文档解析与分块」这一环带来什么约束
本品类的数据包含结构化表格类的目录、规则表，以及长段落类的评审纪要，若分块逻辑未适配表格结构，会导致字段拆分断裂，丢失数据关联关系；长评审纪要按固定字符分块可能割裂完整评审意见的逻辑，影响后续分类分级规则的匹配准确性。季度批量更新的文档需支持批量解析，单文档超时会拖慢整体流程；内网部署场景下的Confluence文档，需适配私有数据源的解析规则，避免出现解析失败。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配本品类的结构化表格与长评审纪要，避免拆分关键字段或割裂评审逻辑 |
| `chunkSplitter` | 按表格+段落混合拆分 | 适配数据目录、规则表的结构化表格与评审纪要的长段落，保留数据关联关系 |
| `customPdfParse` | 开启 | 适配批量PDF格式的年报与规则文档，保留表格与文本的原始格式 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 适配1000+页的PDF年报与大型Excel数据清单，避免解析超时 |
| `chunkSettingMode` | 手动模式 | 针对10000+行的Excel数据，可自定义分块规则，避免单块数据过大 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配大型批量文档的上传需求，满足季度级数据资产盘点的批量处理 |

## 容易做错的三处
-  内网Confluence页面无法解析出内容：未配置`customPdfParse`或私有数据源解析规则，导致私有格式的文档无法被识别。
-  大体积Excel文件解析后返回不完整提示：`UPLOAD_FILE_MAX_SIZE`设置过小，或`PARSE_FILE_TIMEOUT_SECONDS`配置不足，导致大型表格未完成解析即终止。
-  10000+行Excel数据块颗粒度过大：未切换`chunkSettingMode`为手动模式，使用默认分块规则拆分大型表格，导致单块数据包含过多行数据，无法精准匹配分类分级规则。

## 怎么确认配好了
-  上传单份1000页的PDF年报，检查解析状态是否在`PARSE_FILE_TIMEOUT_SECONDS`配置的时间内完成，无超时报错。
-  导入一份结构化数据目录Excel，查看解析后的分块是否保留了资产编号、数据类别等字段的关联关系，无拆分断裂。
-  上传内网Confluence格式的评审纪要，确认解析结果包含完整的评审意见内容，无字段缺失。
-  调整`chunkSettingMode`为手动模式后，拆分10000+行的Excel数据，检查分块后的单块数据量是否符合分类分级规则的匹配需求。
