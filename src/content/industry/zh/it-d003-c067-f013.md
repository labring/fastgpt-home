# 数据安全分类分级的安全与合规材料审查：权限与数据隔离

## 这个品类的数据长什么样
本品类的数据主要来自数据资产盘点结果、数据库元数据、业务系统说明文件及公开法规文本。日常产出的文档包含数据目录、分类分级规则、重要数据识别表、评审纪要四类。数据更新周期为季度或单次业务系统变更后触发。文档字段包含资产ID、数据分类标签、分级等级、责任人信息及合规评审状态，部分字段需关联外部系统元数据填充，无统一固定单位。

## 这些特征在「权限与数据隔离」这一环带来什么约束
数据来源分散且关联外部系统元数据，要求权限隔离需支持跨系统元数据的细粒度访问控制。多类文档更新频率不均，需配置基于变更触发的权限同步机制，避免旧权限关联未更新的分类规则。文档包含敏感的合规评审状态与责任人信息，权限配置需区分评审、查看、编辑三类操作权限，防止未授权人员修改分级规则或篡改评审结果。跨团队协作场景下，需限制不同数据治理团队仅访问对应业务域的分类分级数据，避免跨域数据泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 团队权限绑定 | 绑定`teamId`与业务域数据目录 | 依据数据来源分散需跨域隔离的特征，精准限制团队访问范围 |
| 敏感文档权限分配 | 按角色划分查看、编辑权限 | 依据文档包含合规评审状态的特征，区分操作权限等级 |
| 元数据同步周期 | 每 8–12 小时同步一次 | 依据数据更新为季度或系统变更后触发的节奏，平衡时效性与资源消耗 |
| 权限生效延迟 | 不超过 600 秒 | 适配实时协作场景，避免权限变更后无法立即生效的问题 |
| 跨域隔离开关 | 开启`tmbId`级细粒度隔离 | 依据多团队协作需求，防止跨业务域数据泄露 |
| 文档存储配额 | 单业务域不超过 1000 MB | 依据数据目录的存储容量特征，避免单域数据过载 |

## 容易做错的三处
- 现象：配置团队写入权限后，成员仍无法创建分类分级规则文档。原因：未将成员账号关联至对应`teamId`，导致权限范围未覆盖目标业务域数据。
- 现象：手动触发元数据同步后，分类分级规则未更新。原因：未配置`tmbId`关联的自动同步触发条件，仅依赖固定周期同步未关联系统变更事件。
- 现象：非授权成员可修改评审纪要内容。原因：未区分编辑与查看权限，将所有团队成员权限设置为编辑模式。

## 怎么确认配好了
- 登录FastGPT v4.17.0的权限管理页面，验证目标成员是否绑定至对应`teamId`。
- 尝试以非授权成员账号访问敏感文档，确认无法查看或编辑评审纪要与分类分级规则。
- 触发一次业务系统变更，验证元数据是否按设定周期完成同步。
- 查看权限变更日志，确认权限生效时间符合预设延迟要求。
