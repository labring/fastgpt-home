# 数据安全分类分级的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的服务对象为数据治理团队、安全咨询顾问与法务合规人员，日常处理的数据包括数据目录、分类分级规则、重要数据识别表与评审纪要。数据来源涵盖数据资产盘点结果、数据库元数据、业务系统说明及法规文件，更新频率为季度或业务系统变更时。数据结构以结构化表格与半结构化文档为主，包含资产编号、敏感级别、归属系统等字段，无统一的单文档长度上限。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源的多样性要求模型接入需适配多格式的输入内容，避免因格式不兼容导致的信息丢失。更新频率的周期性与突发性，要求配置中需包含定期同步知识库的机制，确保分类分级规则与最新数据资产保持一致。文档的结构化特征与字段多样性，要求模型调用的上下文参数需覆盖足够长度，避免截断核心规则与资产信息。敏感字段识别与规则评审的高耗时特性，要求优化模型调用的参数设置，减少无效重复调用，提升审查效率。合规审查的严格要求，还需确保模型输出格式符合标准化要求，避免因格式错误导致合规整改失败。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 数据目录、分类分级规则等文档的总长度通常在该区间，可避免截断核心审查依据内容 |
| `maxTokens` | 2000–3000 token | 单条敏感字段识别或评审纪要的分析输出需完整返回分级结论，该取值可覆盖常规输出长度 |
| `quoteMaxToken` | 1500 token | 需完整引用数据资产盘点的元数据片段作为审查佐证，该取值可保留完整的引用片段 |
| `toolChoice` | `auto` | 需模型自主判断是否调用检索工具匹配分类分级规则，自动模式可适配多场景的审查需求 |
| `temperature` | 0.1–0.3 | 合规审查需输出稳定、符合预设规则的结论，该取值范围可降低输出的随机偏差 |
| `AIPROXY_API_TOKEN` | AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空 | 该变量为App/Admin服务端环境变量，不得与应用API Key、模型供应商密钥等混淆 |

## 容易做错的三处
- 现象：调用模型返回`404 body not found`，原因：未正确配置App/Admin服务端环境变量`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或二者不匹配。其中`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，不得附加`/v1`或模型相关路径。
- 现象：知识库返回的内容无法识别为标准JSON格式，原因：未设置合理的`maxTokens`取值，导致模型输出被截断，破坏JSON结构的完整性。
- 现象：混合使用不同索引模型与文本模型时，分类分级规则的匹配精度下降，原因：未统一配置`temperature`参数，导致不同模型的输出严谨度与格式存在差异。

## 怎么确认配好了
- 上传单条数据目录文档执行测试，检查模型返回的分类分级结果是否符合预设的分类分级规则。
- 查看FastGPT v4.17.0的服务启动校验日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`已正确配置且服务启动校验通过；查看模型调用日志确认模型调用请求正常返回。
- 批量导入季更的业务系统说明文档，验证模型处理后的敏感字段识别结果无明显格式错误。
- 调整`temperature`参数的取值区间，对比不同配置下的评审纪要分析结果，确认输出符合合规审查的稳定性要求。
