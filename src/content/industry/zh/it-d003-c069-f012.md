# 数据库运维的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
数据库运维场景的核心文档包含数据库变更单、慢SQL报告、备份记录、权限申请单四类，数据来源为数据库监控系统、审计日志、SQL执行计划文件与内部工单系统。文档更新频率按单次数据库变更或每日批量任务执行，单份文档混合结构化字段与长文本内容，例如变更单包含审批流程、变更内容字段，慢SQL报告包含执行耗时、锁等待时长与对应SQL语句。文档中存在敏感权限字段与长文本SQL片段，无统一固定排版，部分文档以PDF或结构化文本格式存储。

## 这些特征在「文档解析与分块」这一环带来什么约束
数据库运维文档的多来源、混合结构特征，对解析分块环节带来多重约束。首先，文档包含敏感权限字段与长SQL片段，分块时需保留字段间的关联关系，避免截断关键审批链或SQL语句。其次，部分文档为批量生成的长文本，解析时需适配不同长度的内容，避免因分块参数过小导致内容碎片化。此外，部分文档以PDF格式存储，需支持复杂排版的字段提取，确保备份记录、慢SQL报告中的指标与对应文本不丢失。最后，文档更新频率较高，解析环节需支持快速处理批量提交的文档，避免因超时导致任务失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配慢SQL报告、SQL执行计划的长文本长度，避免截断关键SQL语句与指标 |
| `chunkSplitter` | 按段落分块 | 匹配数据库变更单、权限申请单的审批流程结构，保留审批节点与对应申请内容的上下文 |
| `customPdfParse` | 启用 | 适配备份记录、慢SQL报告的PDF格式文档，保留原始排版中的字段信息与排版逻辑 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对长SQL执行计划、批量审计日志的解析耗时，避免长文档解析超时失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量备份记录、审计日志的大文件上传需求，支持单次提交多份文档 |
| `chunkSettingMode` | 手动配置 | 针对数据库运维文档的特定字段调整分块规则，适配敏感权限字段与长SQL片段的保留需求 |

## 容易做错的三处
- 界面显示PDF解析失败，返回状态码504。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，长审计日志PDF的解析耗时超出默认阈值。
- 分块后SQL语句与慢查询耗时指标被拆分到不同片段。原因是选择按字符分块，未配置`chunkSplitter`为按段落分块，导致关键关联内容被截断。
- 无法启用PDF增强解析功能。原因是未开启`customPdfParse`配置项，或未完成对应解析插件的部署与配置。

## 怎么确认配好了
- 上传一份数据库变更单PDF，查看解析后的文本是否完整保留了变更时间、申请人、审批意见等字段的上下文关联。
- 查看解析任务的后台日志，确认未出现超时报错，且`PARSE_FILE_TIMEOUT_SECONDS`的配置值匹配实际解析耗时。
- 检查分块后的文档片段，确认SQL执行计划与对应慢查询的耗时指标未被拆分到不同分块。
- 调用FastGPT v4.17.0的API接口上传文档，确认返回的解析结果包含完整的文档字段，无缺失或截断情况。
