# 数据库运维的安全与合规材料审查：权限与数据隔离

## 这个品类的数据长什么样
该品类的核心数据来自数据库监控、审计日志、SQL执行计划与工单系统，关联日常文档包括数据库变更单、慢SQL报告、备份记录与权限申请单。数据更新节奏通常为每日更新或随单次数据库变更同步，文档包含实例标识、操作时间、权限申请条目、执行结果等字段，无固定统一格式，需按运维工单流程归档。日常处理的最耗时环节包括慢查询定位、结构变更审核与备份恢复验证，操作失误可能引发数据损坏、查询超时或权限越界问题。

## 这些特征在「权限与数据隔离」这一环带来什么约束
数据来源分散导致权限校验需覆盖多系统入口，需统一隔离规则以避免跨系统权限越界；更新频率随变更触发，需动态适配权限变更的实时性要求，防止权限配置滞后于数据库结构调整；文档字段无统一格式，权限审查环节需兼容多类文档的字段解析逻辑，确保权限申请的审核准确性；最耗时的慢查询与变更审核环节，需严格限制访问范围，避免权限越界导致的查询超时或数据损坏；权限申请单的流转需绑定运维人员的实例访问权限，防止非授权人员操作生产数据库。

## 配置怎么定
FastGPT v4.17.0 版本下的配置项可参考以下设置：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 权限隔离范围 | 按数据库实例分组划分，`teamId`绑定实例归属团队 | 匹配工单系统与数据库监控的实例归属数据，确保权限与团队绑定一致 |
| 实例访问白名单 | 仅允许运维成员`teamId`与指定DBA账号访问 | 防止非授权人员接触生产数据库实例，降低越权操作风险 |
| 审计日志留存周期 | 180天 | 满足安全合规的日志留存要求，适配日常审计排查的时间跨度 |
| 敏感数据脱敏规则 | 对权限申请单中的敏感字段按`前30%字符`脱敏 | 避免权限审查过程中泄露敏感业务数据 |
| 权限变更同步频率 | 每变更同步一次 | 匹配数据库变更的更新节奏，确保权限规则与实际变更实时同步 |
| 容器权限持久化配置 | 开启本地卷挂载存储权限配置 | 防止重启容器后权限配置丢失，适配ubuntu系统的部署场景 |

## 容易做错的三处
- 现象为重启docker容器后执行SQL出现权限不足报错，原因是容器重启后`teamId`绑定的权限配置未持久化，导致运维账号的访问权限被重置。
- 现象为权限申请单审核后未同步更新数据库实例的访问规则，原因是权限变更同步频率配置为每日同步，未随工单实时触发更新。
- 现象为慢SQL查询时返回跨实例的敏感数据，原因是权限隔离范围未覆盖SQL执行计划的数据源，导致跨实例权限校验失效。

## 怎么确认配好了
- 执行`teamId`绑定的运维账号登录测试，验证是否只能访问指定范围内的数据库实例。
- 提交一份测试权限申请单，查看敏感字段是否按配置的脱敏规则进行处理。
- 重启数据库运维容器后，验证权限配置未发生丢失，运维账号仍可正常访问授权实例。
- 查看审计日志归档记录，确认操作记录已按配置的留存周期进行存储。
