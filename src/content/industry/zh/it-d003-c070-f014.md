# 数据清洗与质检的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
本品类处理的数据来自原始数据集、ETL运行日志、标注平台产出结果、抽样质检结果。数据更新节奏为每日或按每批任务周期更新。日常关联文档包含清洗规则配置文件、质检抽样表、异常数据清单、最终交付报告。无额外自定义单位，核心字段为原始数据内容、数据质量标签、异常类型标识与抽样校验结果。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新周期短，要求模型接入需适配多源数据格式的解析，配置需支持按任务批次动态调整参数。日常文档多为结构化规则与清单，模型需支持读取结构化字段进行合规校验，配置需包含字段映射的适配配置。异常数据清单与交付报告需模型输出结构化结果，配置需限制输出格式以匹配下游文档生成要求。同时，数据不可用或指标失真的出错后果要求模型接入需具备容错配置，避免因模型调用失败影响整体质检流程。

## 配置怎么定
本配置指南适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配清洗规则与质检抽样表的多字段上下文读取，避免截断关键合规校验逻辑 |
| `maxTokens` | 2000–3000 token | 匹配异常数据清单与交付报告的结构化输出长度，确保完整返回校验结果 |
| `temperature` | 0.1–0.3 | 降低输出随机性，保证合规审查结果的一致性，避免因波动导致质检标准不统一 |
| `quoteMaxToken` | 500–800 token | 限制引用数据的长度，确保合规审查时仅加载必要的异常数据内容 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions 路径 | 作为FastGPT App/Admin服务端的环境变量，指定AI Proxy服务的访问地址，不是单模型或第三方模型供应商地址 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，且不能为空 | 作为FastGPT App/Admin服务端的环境变量，用于AI Proxy服务的身份验证，不是模型供应商密钥或应用API Key |

## 容易做错的三处
- 现象为在OneAPI中测试通过的模型提供商，在FastGPT新增后测试返回404错误。原因是未正确匹配模型ID与OneAPI中配置的模型标识，或接口地址填写存在拼写偏差。
- 现象为调用接入的DeepSeek R1模型时，输出未包含思考过程内容。原因是未开启模型的思考过程输出配置，或`temperature`参数设置过高导致输出格式被简化。
- 现象为私有化部署场景下，模型推理速度与云平台测试存在明显差距。原因是`maxContext`参数设置超出服务器显存承载范围，或未根据实际任务调整上下文窗口的取值。

## 怎么确认配好了
- 执行模型测试调用，核对返回结果的字段是否包含异常数据标识、合规校验结论等核心内容，确保与品类的异常数据清单字段匹配。
- 查看FastGPT服务端启动校验日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`已正确配置且非空，无拼写或格式错误。
- 调整测试用的上下文长度，验证`maxContext`参数是否能完整加载清洗规则与质检抽样表的内容，无截断情况。
- 多次调用同一测试数据集，核对输出结果的一致性，确认`temperature`参数的取值符合预期。
