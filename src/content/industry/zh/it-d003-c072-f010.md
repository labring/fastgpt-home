# 数据采集任务设计的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自客户需求、公开数据源、采集工具及自有样本库，更新频率以单项目或周为单位。日常产出的文档包含采集方案、样本规格、授权说明、任务排期四类，核心字段涵盖样本范围、采集字段、合规授权条款、任务排期节点，无统一固定单位，需匹配客户需求及采集工具的格式要求。核心工作围绕样本范围定义、字段规格确认与采集合法性核对展开，一旦出现合规疏漏会导致样本不可用或侵权风险。本页面基于FastGPT v4.17.0版本编写。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据来源分散且更新节奏随单项目或周度波动，要求引用溯源系统需支持多数据源的关联标记与动态绑定。日常产出的授权说明等合规文档，要求溯源环节需将采集样本与对应的合规授权条款精准绑定。核心字段需匹配客户定制化需求，溯源需保留原始采集字段的来源标识与配置细节。由于该品类直接决定原始数据的获取方式，溯源疏漏会直接引发样本不可用或侵权风险，因此需严格关联任务配置与最终采集数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 匹配采集任务相关文档的平均长度，确保完整覆盖授权说明、样本来源等核心合规信息 |
| `responseData` | 开启溯源绑定 | 需将采集任务配置与最终产出的样本数据建立关联，满足合规审查的溯源要求 |
| `detail` | 完整模式 | 保留原始采集字段、授权文件路径、任务排期节点等细节，支撑合法性核对 |
| 单次溯源查询上限 | `前3–7条` | 匹配单采集任务的常规样本批次规模，避免冗余信息干扰合规审查 |
| 溯源缓存有效期 | `7天` | 匹配该品类的周度或项目级更新节奏，避免过期溯源信息干扰审查 |
| 合规信息最小匹配长度 | `100字符` | 确保提取的授权条款、来源说明等信息具备合规审查的有效性 |

## 容易做错的三处
- 出现采集数据溯源字段为空的现象，原因是未开启`responseData`的溯源绑定配置，未建立采集任务与样本数据的关联关系，类似部分用户反馈的配置未生效的问题。
- 出现溯源结果条数超出预期的现象，原因是单次溯源查询上限设置过高，未匹配单采集任务的常规样本批次规模，引入冗余信息。
- 出现合规审查无法匹配授权文件的现象，原因是`detail`配置未启用完整模式，未保留授权说明文档的路径与版本信息。

## 怎么确认配好了
- 查看采集任务的配置页面，确认`quoteMaxToken`、`responseData`、`detail`的配置已按需求设置。
- 生成一条测试采集样本，检查溯源字段是否包含任务配置、授权文件路径等核心信息。
- 触发合规审查流程，确认可关联到对应的采集方案与授权说明文档。
- 调整单次溯源查询上限，验证返回结果的条数符合单任务的样本批次规模。
