# 数据采集任务设计的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
本品类的数据主体来自数据服务项目经理、采集团队与客户算法团队的日常工作产出，包含采集方案、样本规格、授权说明、任务排期四类核心文档。数据来源覆盖客户需求文档、公开数据源、采集工具导出文件与内部样本库，更新频率以单项目为周期，或按周同步最新任务排期与样本范围。文档结构包含结构化表格、固定条款文本与动态任务条目，字段涵盖样本采集范围、字段规格要求、采集合法性核对项与任务时间节点，无统一固定的单位体系，随具体项目需求调整。

## 这些特征在「文档解析与分块」这一环带来什么约束
日常文档的结构化与半结构化混合特征，要求解析环节保留表格排版与条款边界，避免破坏关键合规信息的完整性；多来源的数据格式差异，要求解析工具兼容多种输入格式，适配采集工具导出的PDF、Excel与文本文件。高频更新的任务排期与样本范围，要求分块配置支持快速调整，适配动态变化的文档内容。同时，采集合法性核对的核心需求，要求分块不能拆分授权说明等合规类文档的关键条款，避免出现侵权风险或样本不可用的后果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配采集方案、授权说明的单块信息密度，避免拆分关键合规条款 |
| `chunkSplitter` | 自定义分隔符 + 换行符 | 匹配用户预设的段落边界，保留已手动分段的文档结构 |
| `customPdfParse` | 开启 | 兼容采集工具导出的PDF格式样本规格文档，保留原有排版与表格结构 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配多文档批量处理的耗时需求，避免长排期文档解析超时 |
| `chunkSettingMode` | 手动模式 | 允许针对授权说明、采集方案等不同文档类型调整分块参数，符合项目定制化需求 |

## 容易做错的三处
- 现象：设置自定义分隔符后，分块结果要么合并多个预设段落，要么拆分单个合规条款。原因：未将`chunkSplitter`与自定义分隔符绑定，或`chunkSize`取值与预设段落长度不匹配。
- 现象：docker部署后处理PDF报错，返回包含错误信息的JSON响应。原因：未正确配置`customPdfParse`相关环境变量，或解析超时未调整`PARSE_FILE_TIMEOUT_SECONDS`参数。
- 现象：知识库分块后无法关联来源文档。原因：未开启文档溯源的基础配置，或分块时未保留文档元数据字段。

## 怎么确认配好了
- 上传单份授权说明文档，检查分块结果是否保留完整的授权条款段落，未出现拆分或合并。
- 批量上传采集方案与排期文档，验证解析耗时未超过`PARSE_FILE_TIMEOUT_SECONDS`设定值，无超时报错。
- 查看分块后的文档元数据，确认每条块都关联了原始文档的文件名与路径。
- 在FastGPT v4.17.0版本中，测试调用知识库时，验证回答可关联到对应分块的原始文档信息。
