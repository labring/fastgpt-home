# 数据采集任务设计的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
本品类的数据围绕数据采集任务全流程生成，来源包括客户需求文档、公开合规数据源、采集工具日志及内部样本库。日常产出的文档包含采集方案、样本规格清单、授权说明文件与任务排期表，更新频率按单项目或每周迭代。数据字段多包含样本范围、字段格式、合规校验项、排期节点等，无统一固定单位，需结合具体采集场景匹配对应格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散且更新节奏随项目波动，需模型接入时适配多源数据的格式校验。日常文档结构差异较大，需配置环节支持非标准化文本的解析适配。采集合法性核对依赖合规字段的精准识别，需模型能关联授权说明与采集范围的匹配校验。单项目数据量波动明显，需配置项支持灵活调整以适配不同规模的任务设计审查。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配采集方案、授权说明等多文档拼接的上下文长度需求，避免截断合规校验关键信息 |
| `maxTokens` | 2000–3000 token | 匹配单条合规审查结果的输出长度，确保覆盖样本合法性、授权状态的完整说明 |
| `temperature` | 0.1–0.3 | 降低输出随机性，保障合规校验结果的一致性，避免对授权状态的误判 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致且非空的管理员Token | 为App/Admin服务端的环境变量，用于AI Proxy服务鉴权，不属于应用调用凭证或模型供应商密钥 |
| `toolChoice` | auto | 自动触发合规校验相关工具调用，适配多源数据的格式校验与字段提取需求 |

## 容易做错的三处
- 现象：模型直接返回知识库无匹配内容的拒绝回复，无法触发自定义合规推理。原因：未正确配置`maxContext`或上下文拼接逻辑，导致合规相关的历史授权文档未被纳入检索范围。
- 现象：调用外部模型渠道时返回身份校验失败的报错。排查项：检查上游模型渠道的供应商凭证和渠道地址配置是否正确，检查服务端是否已正确配置`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`环境变量。
- 现象：合规校验结果出现随机偏差，不同提交的相同样本得到不一致结论。原因：`temperature`取值过高，导致模型对授权状态、样本范围的判断出现波动。

## 怎么确认配好了
在FastGPT v4.17.0版本中，可通过以下动作核对配置是否生效：
- 上传单份采集方案与授权说明文档，核对模型返回的合规校验结果是否覆盖文档中的关键字段。
- 调整`maxContext`的取值，验证长文档拼接后是否仍能完整识别合规校验项，无关键信息截断。
- 提交包含异常合规字段的测试样本，确认模型返回的结果与预设校验逻辑一致。
- 验证服务端已正确配置`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`环境变量，服务启动校验通过后发起调用，验证是否能正常获取模型响应，无身份校验类报错。
