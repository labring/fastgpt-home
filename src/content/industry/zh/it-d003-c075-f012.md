# 文档站维护的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
本品类的数据来自代码仓库、文档站构建日志、用户反馈与版本发布记录，更新节奏为每周或随版本发布。日常维护的文档包含安装文档、API文档、迁移指南与FAQ，文档结构多为层级式标题搭配代码块、步骤说明，字段包含版本号、更新时间、适用环境等，内容随技术迭代持续调整，无统一固定单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
层级式标题与代码块混合的结构要求解析时保留语义层级，避免拆分破坏逻辑关联；按周或版本更新的节奏意味着解析需适配高频变更的内容，需支持增量解析适配。不同文档类型的长度差异大，API文档可能仅数页，迁移指南可达数十页，需适配不同体量的文件。用户反馈与构建日志可定位解析失败场景，需将异常数据同步至维护流程，同时合规审查要求敏感内容识别覆盖代码示例与步骤说明中的潜在风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配安装文档、API文档的单段语义长度，避免拆分破坏代码块或步骤逻辑 |
| `chunkSplitter` | 按标题层级拆分 | 匹配文档的层级式结构，保留章节语义完整性，适配不同文档类型的排版 |
| `customPdfParse` | 启用 | 支持解析代码仓库导出的PDF文档，保留代码块与公式格式，适配技术文档的解析需求 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配迁移指南等大体积文档的上传需求，避免因文件过大导致解析中断 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 覆盖大体积文档的解析耗时，避免因超时导致任务失败，适配版本发布时的批量文档解析 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型调整分块参数，满足安装文档、API文档的差异化解析需求 |

## 容易做错的三处
- 联网搜索解析json报错，现象为返回`parse json failed`状态码或解析结果字段为空，原因是未正确配置`chunkSplitter`的格式适配，导致解析后的内容无法转换为标准JSON结构。
- 集成自定义解析工具后持续等待结果超时，现象为任务状态一直处于解析中，最终触发超时报错，原因是未设置合理的`PARSE_FILE_TIMEOUT_SECONDS`参数，未适配大体积文档的解析耗时。
- 本地部署版本无法启用文件解析功能，现象为上传文件后无解析日志生成，任务状态停留在待解析，原因是未开启`customPdfParse`配置项，且未配置对应解析依赖的环境变量。

## 怎么确认配好了
- 上传一份小型安装文档，检查解析后的分块是否保留章节标题与代码块的层级关系，验证`chunkSize`与`chunkSplitter`的配置效果。
- 上传体积超过500 MB的迁移指南，检查任务是否在600秒内完成解析，验证`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`的配置合理性。
- 触发一次批量文档解析任务，检查是否生成完整的解析日志，验证`customPdfParse`配置是否生效。
- 基于FastGPT v4.17.0的版本特性，调整`chunkSettingMode`为自动模式，对比手动配置的分块结果，确认参数适配当前维护的文档类型。
