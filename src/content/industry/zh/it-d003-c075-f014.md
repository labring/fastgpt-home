# 文档站维护的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自代码仓库、文档站构建日志、用户反馈与版本发布记录。日常维护的文档包含安装文档、API文档、迁移指南与FAQ，结构多按功能模块划分，包含操作步骤、参数说明与示例代码。数据更新节奏为每周同步或随版本发布更新，内容字段涵盖版本号、更新日期、文档路径与访问标记，无统一固定统计单位，随文档类型灵活调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征对模型接入配置带来多重约束。首先，数据来源分散且更新频率较高，需配置支持增量索引同步，适配高频的文档更新场景。其次，文档结构覆盖安装、API、迁移等多种类型，平均长度差异较大，上下文长度配置需兼顾不同文档的处理需求。另外，数据包含构建日志与用户反馈的异常文本，需配置支持合规校验逻辑，同时需适配低资源部署场景，避免单进程资源占用过高影响服务稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多数文档站文档的平均长度，覆盖安装、API等单篇文档的核心内容 |
| `maxTokens` | 2000–3000 token | 限制单轮生成的合规审查结果长度，避免输出冗余信息 |
| `quoteMaxToken` | 1500 字符 | 限定引用原文的最大长度，确保合规审查时仅提取必要的文档内容 |
| `temperature` | 0.1–0.3 | 降低生成结果的随机性，保证合规审查结论的一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写AI Proxy服务的根地址，例如 http://aiproxy:3000 | 适配本地或云端的AI Proxy服务部署路径，确保请求能正确路由到AI Proxy服务，请勿附加 /v1 或 /chat/completions 等路径 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的非空管理员Token | 用于AI Proxy服务的身份校验，与AI Proxy服务端配置的Token保持一致且不能为空 |

## 容易做错的三处
- 配置`AIPROXY_API_ENDPOINT`时填写错误的地址，导致服务启动校验失败或请求异常。原因是误将单模型服务地址（如VLLM/Ollama/Xinference等）或附加了 /v1 等路径的地址填入，未使用AI Proxy服务的根地址。
- 启用`maxContext`时设置过大的token值，导致模型加载时GPU内存占用不足，同时CPU单核占用飙升至100%。原因是未根据部署服务器的硬件规格调整上下文长度，超出了单进程的资源承载上限。
- 未设置`temperature`的合理区间，导致合规审查结果出现随机偏差，无法保证审查结论的一致性。原因是未针对文档站的合规审查场景调整生成随机性参数，默认值不符合业务需求。

## 怎么确认配好了
- 发起一次针对测试文档的合规审查请求，检查接口返回的状态码为200，确认模型调用成功。
- 查看模型服务的资源占用情况，确认GPU使用率稳定在合理区间，无CPU单核持续100%占用的现象。
- 对比两次针对同一文档的审查结果，确认输出内容的一致性，验证`temperature`参数配置有效。
- 查看服务启动日志，确认无`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`相关的启动校验失败提示。
