# 日志平台与可观测性的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自日志系统、Trace平台、Metrics系统以及应用SDK。日常维护的官方文档包括日志采集规范、链路追踪说明、指标字典与看板配置记录。数据更新频率为每日或每版本发布时更新，单条数据包含时间戳、源地址、请求路径、响应状态、链路ID、耗时等字段，部分指标类数据带有百分比、毫秒、字节等标准单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入需兼容不同格式的日志、链路与指标数据，避免出现格式解析错误。高频更新的数据特性要求配置支持动态调整，无需重启服务即可更新模型参数。审计溯源的核心需求要求配置需保留原始数据的引用片段，确保审查结果可追溯。同时，该品类需为故障定位提供上下文证据，因此模型的上下文长度需匹配单批次数据的总容量，避免截断关键信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 匹配日志与可观测性数据的单批次上下文总长度，避免截断关键链路追踪信息 |
| `maxTokens` | 2000 token | 控制合规审查结果的输出长度，适配企业审计文档的标准输出格式 |
| `quoteMaxToken` | 1500 token | 保留原始日志、Trace数据的引用片段长度，满足审计溯源的信息完整性要求 |
| `temperature` | 0.1–0.3 | 降低模型输出的随机性，确保合规审查结果的一致性与可追溯性 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径 | 为App/Admin服务端环境变量，适配企业内部网络隔离的部署要求，确保API请求可正常转发 |
| `toolChoice` | auto | 自动选择合规审查所需的工具调用逻辑，适配多源数据的处理场景 |

## 容易做错的三处
- 界面中视觉模型处理按钮持续置灰，后端日志显示图片上传请求状态码200但无后续返回。未正确开启`vision`参数的模型调用开关，导致任务队列阻塞。
- 向量模型检索结果的相似度分值异常偏高，远超出日常测试的合理区间。`temperature`参数设置不符合该品类数据的语义匹配要求，导致模型生成的相似度判断出现偏差。
- curl调用重排模型接口时返回404错误，而OneAPI测试可正常连通。请求路径或AI Proxy服务根地址配置错误，导致请求无法被正确路由。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量配置，确认`AIPROXY_API_TOKEN`已设置为与AI Proxy服务端一致的非空管理员Token。
- 发起一次合规审查测试请求，检查返回结果中是否包含`quoteMaxToken`参数指定长度的原始数据引用片段。
- 调整`temperature`参数至0.2，发起两次相同的合规审查请求，确认两次输出结果的一致性。
- 测试视觉模型调用流程，上传测试图片后确认界面按钮可正常激活并返回处理结果。
