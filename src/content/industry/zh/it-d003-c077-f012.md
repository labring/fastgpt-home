# 机房巡检与环境监控的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
该品类的数据主要来自动环监控系统、门禁系统、UPS监控设备与视频巡检工具。日常生成的文档包括巡检表、温湿度记录、告警记录与值班日志，字段多包含时间戳、设备唯一标识、数值类参数（如温度℃、湿度%RH）、告警等级与故障代码。数据更新节奏多为日级或实时，单份文档条目多且按时间顺序排列，部分巡检表会包含多设备的批量记录。

## 这些特征在「文档解析与分块」这一环带来什么约束
实时或日级更新的数据要求文档解析环节具备稳定的批量处理能力，避免因解析超时导致数据积压。多设备批量记录的巡检表与按时间排序的告警日志，需要按设备分组或时间切片进行分块，确保检索时能精准匹配对应设备的状态信息。数值类参数附带单位的特征，要求解析环节保留原始单位标识，避免后续检索时出现语义混淆。部分带数字签名的巡检文档，可能因格式加密导致基础文本提取失败，需额外适配非标准PDF解析逻辑。

## 配置怎么定
本文适配FastGPT v4.17.0版本，以下配置项需按要求完成设置：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 该品类文档多包含批量设备记录与数值参数，800–1200字符的分块长度可平衡单块信息密度与检索召回精度 |
| `chunkSplitter` | 按段落+设备标识拆分 | 巡检表与告警日志按设备标识分段，可确保同设备的状态记录被整合在同一分块内 |
| `customPdfParse` | 启用 | 适配带数字签名或复杂表格的巡检PDF文档，解决基础解析无法提取完整内容的问题 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 批量巡检文档体积较大，600秒的超时设置可避免因解析耗时过长导致任务中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单份批量巡检日志或长期告警记录的完整上传，适配日级归档文档的处理需求 |
| `chunkSettingMode` | 手动配置 | 针对不同类型的文档（如温湿度记录与告警日志）调整分块规则，满足细分场景的解析需求 |

## 容易做错的三处
- 上传带数字签名的巡检PDF后无解析内容，原因是基础PDF解析模块无法识别加密的签名字段，未启用自定义解析配置。
- 本地部署文档解析工具功能正常，但FastGPT知识库上传PDF时触发读取失败报错，原因是未正确配置App/Admin服务端必需的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量，导致服务启动校验失败或依赖调用异常。
- 批量巡检表上传后分块结果混乱，同设备的记录被拆分到多个分块中，原因是分块规则未绑定设备标识字段，仅按固定字符长度拆分。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量，确认已配置`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，不得附加`/v1`等路径，非单模型服务地址）与非空`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致，非应用API Key或模型供应商密钥），且未在工作流全局变量、应用API请求头或模型管理页面重复配置。
- 上传一份带复杂表格的巡检PDF，查看解析后的文本是否完整保留表格字段与单位，验证`customPdfParse`配置生效。
- 上传单份1000 MB以内的长期告警日志，确认解析任务在600秒内完成，无超时报错。
- 调整`chunkSize`为不同区间，上传同一份巡检表，验证分块结果随配置变化，确认`chunkSettingMode`为手动配置时生效。
