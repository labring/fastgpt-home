# 机柜上架与布线的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自数据中心基础设施管理（DCIM）系统、企业资产系统、网络拓扑图与客户施工工单。日常处理的文档包括上架申请单、机柜布线图、端口标签表、施工验收记录，字段包含机位编号、线缆规格、端口标识、设备型号等。数据更新节奏为每单或每日，单次工单关联的文档量随机柜设备数量变化，核心字段均为物理位置与设备连接相关的结构化内容，无实时流数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散在多套系统中，且单次工单关联的文档为临时施工类材料，要求模型接入配置支持多源临时文档的上下文整合。物理部署类文档的结构化字段较多，需模型准确匹配机位、端口等物理标识，因此配置需兼顾上下文长度与输出准确性。同时，施工数据更新节奏为每单或每日，模型调用需适配单次任务的临时数据加载，不宜依赖长期缓存机制，避免出现数据过期或不匹配的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配机柜布线图、端口标签表等多文档拼接后的上下文长度，避免内容截断导致合规项遗漏 |
| `maxTokens` | 2000–3000 token | 匹配单次合规审查的输出长度需求，确保覆盖所有上架申请、施工记录中的合规校验点 |
| `quoteMaxToken` | 500–800 token | 限制引用文档片段的长度，聚焦机位编号、线缆规格等核心合规字段，避免冗余信息干扰 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保物理标识、合规条款的匹配准确性，适配部署类任务的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000，不要附加/v1或/chat/completions，不是VLLM/Ollama/Xinference等单模型地址 | 为App/Admin服务端必需的环境变量，用于对接AI Proxy服务，不是界面配置项 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token，不能为空 | 为App/Admin服务端必需的环境变量，与模型供应商密钥、应用API Key无关，不是界面配置项 |

## 容易做错的三处
- 现象：调用重排模型时GPU显存快速增长至6-7G且多卡均占用。原因：未针对机柜布线图这类结构化文档调整模型的批处理参数，导致单次调用加载过多上下文片段。
- 现象：配置国内模型时提示无效令牌，且第三方代理测试正常。原因：未正确配置App/Admin服务端必需的AIPROXY_API_ENDPOINT、AIPROXY_API_TOKEN环境变量，或未正确配置模型渠道的接口地址与供应商凭证。
- 现象：离线接入重排模型失败，返回`rerank error fastgpt | { message: { detail: ' 报错。原因：未将模型文件放置在FastGPT指定的模型加载目录，或模型文件格式与FastGPT支持的重排模型格式不匹配。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中执行单次工单的合规审查测试，核对模型输出的合规项是否覆盖上架申请、布线图中的所有核心字段。
- 查看GPU显存占用情况，确认重排模型的显存占用稳定在合理区间，无持续异常增长。
- 测试模型渠道配置的接口地址与供应商凭证是否正常，检查App/Admin服务端的AIPROXY_API_ENDPOINT、AIPROXY_API_TOKEN环境变量是否配置正确，无无效令牌报错。
- 检查配置的上下文长度参数，确认在加载最大工单文档时未出现内容截断提示。
