# 架构设计与技术方案的安全与合规材料审查：模型接入与配置
本页面基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
这个品类的数据通常来自历史流量数据、服务拓扑、监控指标与业务增长计划。日常产出的文档包含技术方案、架构图、容量评估报告与技术评审纪要，文档中会标注跨服务边界配置、长期演进约束、资源分配阈值等结构化字段，更新频率多为月度或重大需求触发时。数据无固定统计数值或百分比，仅以结构化方式记录架构决策与关联业务参数。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于该品类数据更新频率较低且依赖历史服务拓扑与业务增长计划，模型接入时需适配非高频但长周期的文档解析需求。文档包含架构图、评审纪要等多类型内容，要求配置支持多模态输入与结构化信息提取。同时，架构决策关联长期系统演进，模型输出需保持一致性，避免因参数波动导致跨服务边界配置出现偏差。此外，数据来源多为内部运维与业务规划文档，需确保模型调用的权限与合规性适配内部管控流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `4096–8192 token` | 适配架构文档的多段拼接需求，避免因上下文截断丢失关键约束条件 |
| `maxTokens` | `2000–3000 token` | 控制单轮输出长度，适配技术方案评审纪要的结构化提取需求 |
| `vision` | `开启` | 支持解析架构图、容量评估图表等可视化文档内容 |
| `temperature` | `0.2–0.4` | 降低输出随机性，确保架构决策相关的合规审查结果保持一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境标定 | AI Proxy 服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions 等路径后缀，不得配置为单模型服务地址 |
| `AIPROXY_API_TOKEN` | 按部署环境标定 | AI Proxy 管理员 Token，与 AI Proxy 服务端配置一致且不能为空，不得使用应用 API Key、模型供应商密钥或其他业务鉴权 Token |

## 容易做错的三处
- 界面可选模型与官方介绍不符，且无法切换到GPT4或Claude 3.5：排查项：检查服务端环境变量 `AIPROXY_API_ENDPOINT` 和 `AIPROXY_API_TOKEN` 是否正确配置，检查上游模型渠道配置是否启用对应模型。
- 大模型无法稳定输出Markdown格式的审查结果：原因是`temperature`参数设置过高，导致输出格式随机波动，未匹配结构化文档的解析需求。
- 配置oneAPI的kimi密钥后提示调用失败：排查项：检查上游模型渠道配置中的oneAPI密钥是否正确，检查服务端环境变量 `AIPROXY_API_ENDPOINT` 和 `AIPROXY_API_TOKEN` 是否符合要求。

## 怎么确认配好了
- 调用模型接口测试，验证是否能正常解析上传的架构图文档，确认`vision`配置生效。
- 提交技术评审纪要进行审查，核对输出结果的格式稳定性，确认`temperature`参数取值符合预期。
- 查看代理日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置与部署环境匹配，无网络报错。
- 切换可选模型列表，确认新增的GPT4、Claude 3.5等模型已在配置中启用，可正常选择。
