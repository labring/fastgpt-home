# 桌面终端支持的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据来自终端管理平台、资产系统、用户报障渠道、软件仓库。日常处理的文档包含终端故障单、装机清单、软件安装记录、远程协助记录。终端故障单包含终端ID、故障类型、报障时间、处理进度字段；装机清单包含硬件型号、软件版本、安装时间字段；远程协助记录包含会话时长、操作日志字段。数据更新频率为每日批量同步或随用户请求实时更新。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源分散的数据来源要求配置多渠道数据接入规则，确保终端管理平台、资产系统等不同数据源的字段可被模型正确映射。数据更新频率兼具批量与实时特性，要求配置支持按需拉取与定时同步的模型调用逻辑，避免处理过时的终端资产信息。文档字段多样且包含敏感终端信息，要求配置严格的权限校验规则，防止未授权访问终端数据，同时明确模型输入的字段范围，避免无关信息干扰合规审查。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 桌面终端相关文档单批次上下文总量较大，该取值可覆盖多数场景的文档内容，避免上下文超限 |
| `maxTokens` | `2000–3000 token` | 合规审查需输出详细的校验结论与整改建议，该取值可预留足够的输出空间 |
| `quoteMaxToken` | `1000–1500 token` | 审查过程需引用终端资产数据作为依据，该取值可控制引用文本的长度，避免冗余信息干扰模型判断 |
| `toolChoice` | `auto` | 需自动调用合规校验工具处理终端安全规则，自动模式可适配不同类型的审查任务 |
| `temperature` | `0.1–0.3` | 合规审查需保持输出严谨性，较低的温度值可减少输出的随机性，确保结论一致 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions路径，不得配置为单模型服务地址 | 该变量为App/Admin服务端必需环境变量，桌面终端数据多存储在内网环境，需通过AI Proxy安全转发模型请求，保障数据传输安全 |

## 容易做错的三处
- 现象为接口调用返回`400 Bad Request`，提示上下文长度超限，排查项为未正确配置`maxContext`参数，超出模型支持的上下文阈值。
- 现象为合规审查结果未包含思维链内容，排查项为未开启模型的思维链输出开关，或未配置对应参数，匹配社区常见的API响应思维链内容的咨询场景。
- 现象为POST请求返回连接超时或空响应，排查项为未正确配置`AIPROXY_API_ENDPOINT`（未指向AI Proxy服务根地址、附加多余路径）、未配置非空的`AIPROXY_API_TOKEN`，或AI Proxy服务未正常运行，匹配社区的接口调用测试场景。

## 怎么确认配好了
- 提交一条终端故障单的合规审查请求，检查接口返回结果包含预期的合规校验字段。
- 检查服务端环境变量配置无启动校验错误，AI Proxy服务正常运行。
- 测试调用不同类型的终端文档，如装机清单、远程协助记录，确认审查结果覆盖对应文档的字段。
- 验证`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`配置正确，AI Proxy服务正常运行。
