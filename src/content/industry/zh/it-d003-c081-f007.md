# 渗透测试服务的安全与合规材料审查：对话日志与审计

## 这个品类的数据长什么样
典型主体为安全服务公司、红队工程师与企业安全团队。日常关联文档包含测试授权书、渗透测试报告、漏洞复现记录与整改建议。数据来源覆盖目标系统、公开漏洞库、自动化扫描器结果与手工验证记录。数据更新频率为每项目或每重大版本，单份数据包含授权范围、攻击路径、漏洞评级等专属字段，与通用数据的结构差异明显。

## 这些特征在「对话日志与审计」这一环带来什么约束
多源混合的数据要求日志同时记录人工操作与工具调用结果，避免审计遗漏手工验证环节。按项目更新的特性要求审计需按项目维度隔离日志，防止跨项目数据混淆。丰富的关联文档要求日志需绑定对应项目的唯一标识，便于溯源到测试授权书、漏洞报告等合规材料。最耗时的测试授权确认、漏洞验证、报告评级环节，需通过日志完整追踪操作链路，防止篡改或遗漏关键步骤。严重的出错后果要求日志不可篡改，留存周期需覆盖项目全生命周期。

## 配置怎么定
本配置方案基于FastGPT v4.17.0版本，具体配置项如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前渗透测试项目的唯一标识 | 确保同项目的对话日志与测试授权书、漏洞报告关联，便于按项目开展合规审计 |
| `responseChatItemId` | 记录每一轮对话的节点ID | 精准追溯漏洞复现、报告评级等关键环节的操作链路，满足审计溯源要求 |
| `detail` | 开启全量日志记录 | 包含扫描器原始输出、手工验证步骤细节、模型调用参数等内容，覆盖合规审查的完整证据需求 |
| 最大上下文长度 | 前200条对话记录 | 适配渗透测试项目多轮验证的对话场景，覆盖完整测试流程的上下文信息 |
| 日志留存周期 | 180天 | 符合安全合规的通用留存要求，覆盖单个渗透测试项目的全生命周期 |
| 对话超时阈值 | 15秒 | 适配渗透测试中模型调用、扫描器响应的平均耗时，避免偶发超时导致流程中断 |

## 容易做错的三处
- 现象：工作流中代码运行节点输入包含历史记录时，校验失败无法执行。原因：未正确绑定`chatId`参数，导致历史记录的上下文范围超出当前渗透测试项目的审计边界。
- 现象：配置聊天记录展示条数后，实际仍仅显示50条，无法调大。原因：未将对话日志配置与渗透测试项目的上下文需求绑定，仅使用平台默认参数。
- 现象：调用公司自研模型时偶发响应为空，卡住10秒后报错，通过oneapi调用无对应日志。原因：未开启`detail`全量日志配置，无法追溯模型调用的超时或参数异常环节。

## 怎么确认配好了
- 核对`chatId`参数是否与当前渗透测试项目的唯一标识绑定，可通过系统项目管理页面确认标识一致性。
- 验证`responseChatItemId`是否记录了每一轮对话的节点ID，可通过查看历史对话列表确认每条记录的关联标识。
- 检查`detail`配置是否开启，确认日志中包含扫描器原始输出、手工验证步骤等完整细节，可通过单条日志详情页验证。
- 验证日志留存周期是否按项目合规要求设置，可通过系统日志管理页面查看留存规则。
