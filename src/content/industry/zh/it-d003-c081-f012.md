# 渗透测试服务的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
该品类的数据主要来自目标系统、公开漏洞库、自动化扫描器结果与手工验证记录。日常处理的文档包含测试授权书、渗透测试报告、漏洞复现记录、整改建议四类，每类文档有专属字段，比如授权书含授权编号与授权范围，报告含漏洞详情与风险评级。数据更新节奏为每项目交付或每重大版本迭代时更新，无固定周期。

## 这些特征在「文档解析与分块」这一环带来什么约束
测试授权书作为合规核心文档，需完整保留授权范围、授权主体等关键字段，避免分块破坏字段完整性；漏洞复现记录包含连贯的步骤描述，分块时需保留操作上下文，防止拆分后无法复现验证流程；不同来源的文档格式差异明显，包含Word格式的授权书、PDF格式的测试报告、CSV格式的扫描结果，需要适配多格式解析逻辑；数据更新无固定周期，分块配置需兼容单项目文档从数页到数十页的长度差异。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | `800–1200 字符` | 渗透测试报告与漏洞复现记录的单段内容通常在该区间内，可保留完整的漏洞描述或复现步骤 |
| `chunkSplitter` | 按自定义分隔符+段落换行 | 该品类文档多按授权项、漏洞条目分段，自定义分隔符可匹配文档固有结构，避免强制拆分 |
| `customPdfParse` | 开启 | 渗透测试报告多为带格式的PDF，开启后可保留文本层级与字段关联，避免内容错乱 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 大型渗透测试报告包含多份附件，需支持较大文件上传，避免因文件超限报错 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型扫描结果文件解析耗时较长，该时长可覆盖多数项目文档的解析需求 |
| `chunkSettingMode` | 手动配置 | 该品类文档结构差异大，手动配置可灵活调整分块规则，适配不同类型的业务文档 |

## 容易做错的三处
- 上传3MB的PDF文件后出现解析报错，原因是未调整`UPLOAD_FILE_MAX_SIZE`参数，默认阈值不足以容纳大型渗透测试报告文件。
- 自定义分隔符配置后，分块结果仍出现段落合并或拆分错误，原因是未匹配文档固有分隔符，如未将漏洞条目间的空行设为分隔规则，导致分块逻辑与文档结构不符。
- 解析后出现部分字段为空的情况，原因是未开启`customPdfParse`，导致带格式的PDF文档中的结构化字段无法被正确提取。

## 怎么确认配好了
- 上传一份标准的渗透测试报告PDF，查看解析后的文本是否保留了漏洞ID、风险等级等关键字段。
- 调整`chunkSize`参数后，上传一份漏洞复现记录，检查分块结果是否未拆分完整的复现步骤。
- 上传一个超过默认上传阈值的测试文件，确认上传与解析流程是否正常触发。
- 查看解析日志，确认`customPdfParse`参数已生效，无格式错乱的解析结果。
