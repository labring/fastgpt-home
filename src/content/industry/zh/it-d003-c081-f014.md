# 渗透测试服务的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
渗透测试服务的日常文档包含测试授权书、渗透测试报告、漏洞复现记录、整改建议，数据来源涵盖目标系统、公开漏洞库、自动化扫描器结果与人工攻击验证记录。数据更新以单个项目或模型版本迭代为周期，不同文档的字段差异明显：测试授权书包含审批流程与权限范围字段，渗透测试报告包含漏洞等级与影响范围字段，漏洞复现记录则包含攻击路径与利用代码片段。该品类与通用漏洞扫描服务的核心差异在于包含人工验证的攻击链路分析内容，数据结构相对复杂且存在非标准化的手工记录部分。

## 这些特征在「模型接入与配置」这一环带来什么约束
渗透测试服务的数据特征对模型接入配置提出了多重约束：首先，多来源、非标准化的文档结构要求模型支持适配不同格式的输入，需针对性配置上下文长度参数；其次，按项目更新的数据节奏意味着模型调用需绑定项目上下文，不宜使用全局固定的调用规则；再者，人工验证的攻击链路内容需要较高的输出严谨性，需限制模型的随机生成参数；最后，合规材料的敏感性要求调用权限需严格绑定项目授权，需通过独立的密钥与端点配置保障访问安全。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ------------ |
| `maxContext` | 8000–12000 token | 渗透测试报告通常篇幅较长，需完整加载项目全量上下文以保障审查准确性 |
| `maxTokens` | 2000–3000 token | 漏洞复现记录与整改建议的摘要生成需足够长度，覆盖核心技术细节 |
| `temperature` | 0.2–0.4 | 合规审查需严谨输出，避免随机生成的偏差内容，保障漏洞评级与整改建议的一致性 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 http://aiproxy:3000 | 为 App/Admin 服务端配置的 AI Proxy 服务访问端点，不得附加 `/v1` 等路由路径，不得配置为单模型地址 |
| `AIPROXY_API_TOKEN` | 与 AI Proxy 服务端配置一致且非空的管理员 Token | 为 App/Admin 服务端配置的 AI Proxy 服务访问凭证，保障服务间通信权限 |
| `toolChoice` | `auto` | 自动适配不同类型的审查材料，无需手动切换工具即可处理授权书、报告等多种文档 |

## 容易做错的三处
- 未正确配置 App/Admin 服务端环境变量 `AIPROXY_API_TOKEN`（需与 AI Proxy 服务端配置一致且非空），导致服务启动校验或模型调用时报权限错误，原因是凭证不匹配 AI Proxy 服务端校验规则。
- 误在FastGPT模型配置界面填写 `AIPROXY_API_ENDPOINT`，或未正确配置 App/Admin 服务端环境变量 `AIPROXY_API_ENDPOINT`（需为 AI Proxy 服务根地址，不得附加 `/v1` 等路由路径，不得配置为单模型地址），导致模型调用返回异常，原因为端点配置不符合要求。
- 工作流中使用代码运行模块调用模型时，未正确配置流式输出的响应解析逻辑，导致结果无法分段返回，原因是未适配模型的流式响应格式。

## 怎么确认配好了
- 在FastGPT的模型测试界面输入一段测试授权书的审批内容，检查模型是否能正确识别权限范围字段并生成合规性判断。
- 调用模型生成单条漏洞复现记录的摘要，核对输出长度与`maxTokens`的配置范围匹配。
- 检查 FastGPT 服务端环境变量配置，确认 `AIPROXY_API_ENDPOINT` 与 `AIPROXY_API_TOKEN` 已正确设置且符合要求。
- 触发绑定项目上下文的工作流调用模型，检查是否能按预期生成渗透测试合规审查报告。
