# 渠道归因与线索分发的安全与合规材料审查：模型接入与配置
本指南基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的核心数据来自广告平台、CRM系统、归因SDK与表单系统，更新频率多为日度或周度。日常处理的文档包含归因规则配置表、线索分发表、渠道流量报表、异常核对单，字段多包含渠道标识、转化时间、线索ID、销售归属人、预算分配额度等，无统一强制格式，需匹配各系统导出的原始字段结构。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散导致字段格式不统一，模型接入时需适配多源异构数据的字段映射，避免参数错位引发销售归属争议。日/周级的批量数据更新要求配置支持定时批量调用，需设置合理的上下文与token限制以处理多源数据拼接，防止批量任务超时导致预算错配。线索归属核验的高复杂度要求模型具备多字段关联校验能力，需调整参数平衡准确性与逻辑严谨性，避免渠道参数核验失误引发渠道ROI失真。异常核对单的非结构化内容需支持视觉解析，以处理图片类异常凭证。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配多源数据拼接后的上下文长度，避免截断核心归因规则与线索字段 |
| `maxTokens` | 4000 token | 限制单轮输出长度，适配渠道报表与异常核对单的解析需求，避免冗余输出 |
| `vision` | 开启 | 支持解析异常核对单中的图片类凭证，适配非结构化数据处理场景 |
| `temperature` | 0.2–0.4 | 降低随机性，提升渠道参数核验、线索去重的逻辑严谨性 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，格式示例为http://aiproxy:3000，不得附加/v1或/chat/completions等路径，不得填写单模型服务地址 | 为FastGPT App/Admin服务端必需环境变量，用于路由模型请求 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致且非空的管理员Token | 为FastGPT App/Admin服务端必需环境变量，不得为应用API Key、模型供应商密钥 |

## 容易做错的三处
- 渠道链接调用时返回"undefined is not valid json"报错。排查项为检查FastGPT App/Admin服务端是否已正确配置`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址，格式如http://aiproxy:3000，不得附加额外路径）和非空`AIPROXY_API_TOKEN`，未配置会导致服务启动校验失败或无法正常路由模型请求，引发响应解析异常。
- 本地部署版本新建知识库时无法看到图片理解模型选项。原因是未开启`vision`配置项，或部署环境未加载对应的视觉模型依赖包。
- 批量调用日度数据时出现超时错误。原因是未合理设置`maxContext`与`maxTokens`，导致单轮请求处理的数据量过大，超出接口响应时限。

## 怎么确认配好了
- 执行单条线索归属核验测试，核对模型输出的归属结果与人工校验结果是否一致。
- 上传包含图片的异常核对单，确认模型可以正常提取图片中的关键信息并生成解析结果。
- 配置定时批量任务，验证日度数据更新时模型可以正常调用并处理多源数据拼接后的上下文。
- 检查FastGPT App/Admin服务端环境变量配置，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`已正确设置；检查API调用日志，确认应用API请求使用合法应用API Key鉴权，请求路径匹配已配置的`AIPROXY_API_ENDPOINT`根地址。
