# 游戏内容合规自查的安全与合规材料审查：对话日志与审计

## 这个品类的数据长什么样
该品类的数据主要来自游戏研发与迭代阶段的剧情脚本、线上游戏文本、美术资源，以及监管公开的合规要求。日常关联文档包括内容自查表、敏感内容修改记录、用户协议、合规评审纪要。数据更新随游戏版本迭代或活动上线节奏调整，每版本或每活动更新一次。文档结构多以结构化字段为主，包含内容类型、审核状态、修改痕迹、评审意见等，部分美术资源附带元数据标签。

## 这些特征在「对话日志与审计」这一环带来什么约束
游戏内容合规自查的对话日志与审计需适配多类型数据源的更新节奏，每版本/每活动的高频更新要求日志留存需覆盖全周期审核对话。结构化文档与元数据字段要求审计日志需精准关联对应内容的唯一标识，避免跨版本混淆。监管要求的可追溯性需要日志包含完整的对话链路，包括审核请求、修改反馈、评审意见等环节。美术资源与文本的混合审核场景，要求审计模块可区分不同类型内容的日志条目，便于后续合规回溯。同时，审核过程中的修改痕迹与评审意见需完整留存，以应对后续的合规检查。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定游戏内容的唯一版本标识 | 确保每一条审核对话关联对应版本的游戏内容，避免跨版本混淆 |
| `responseChatItemId` | 关联审核节点的唯一ID | 精准定位单条审核对话的响应内容，便于回溯修改过程 |
| `detail` | 采集完整对话上下文 | 包含审核请求、修改意见、反馈结果等全字段，满足合规审查的细节要求 |
| 日志留存时长 | 365 天 | 满足合规审计的长期追溯要求 |
| 日志采集开关 | 开启全链路采集 | 覆盖从内容提交到评审闭环的全流程，确保无遗漏 |
| 日志存储上限 | 1000 MB / 应用 | 适配单游戏版本的审核数据规模，避免存储溢出 |

## 容易做错的三处
- 现象为部署FastGPT v4.17.0后，marker日志显示`ocr error`。原因是未针对游戏美术资源的文本提取配置适配的OCR采集参数，导致敏感美术文本无法正常识别。
- 现象为点击合规自查的审核提交按钮后报错，报错行指向聊天记录的正则表达式匹配环节。原因是未正确配置对话日志的提取规则，或传入的聊天记录字段未按要求格式填写。
- 现象为实际发起了合规审核调用，但FastGPT的调用日志无对应记录。原因是未开启对应应用的全链路日志采集开关，或采集范围未覆盖审核对话的全流程。

## 怎么确认配好了
- 发起一次合规审核流程，核对FastGPT的调用日志是否完整记录从内容提交到评审反馈的全链路对话。
- 查看日志字段是否包含`chatId`、`responseChatItemId`和`detail`，且字段值与当前审核的游戏内容版本、节点对应。
- 测试关闭日志采集开关后，确认无新日志生成，开启后恢复记录，验证采集开关生效。
- 模拟不符合格式的输入，查看是否生成对应错误日志，确认异常日志捕获机制正常运行。
