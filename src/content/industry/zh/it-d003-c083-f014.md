# 游戏内容合规自查的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源为游戏文本、美术资源、剧情脚本与监管公开要求。日常处理的文档包括内容自查表、敏感内容修改记录、用户协议及合规评审纪要。数据更新随游戏版本迭代或活动上线触发，单次更新覆盖单版本全量剧情、活动文案及配套美术素材。数据包含结构化自查条目、非结构化文本片段与视觉资源，无固定统一字段，需适配多类型输入格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据包含多类型混合内容，且随版本迭代高频更新，要求模型接入需同时支持文本与视觉输入，因此需配置适配多模态的模型参数。数据无固定统一字段结构，需模型具备灵活的内容理解能力，不宜设置过强的格式约束。单次更新覆盖范围较广，需限制单轮处理的最大上下文长度，避免超出模型承载上限。合规审查需严格匹配监管要求，需确保模型调用链路稳定，避免因配置错误导致审查结果偏差。本环节发生在游戏版本更新与活动上线前，不同于版号申报环节的批量集中处理，需适配高频小范围的更新需求。本页面内容适配FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启 | 本品类包含美术资源审查需求，需支持角色立绘、场景图等视觉素材的合规解析 |
| `maxContext` | 8000–12000 token | 适配单版本剧情文本与活动文案的总长度，避免上下文溢出导致关键信息丢失 |
| `maxTokens` | 2000–3000 token | 限制单轮审查的输出长度，确保合规意见清晰且不冗余，符合评审纪要的记录规范 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保不同批次的合规审查结果保持一致性与严谨性 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions 路径 | 作为App/Admin服务端的环境变量，配置AI Proxy服务的访问地址，确保服务可正常连接AI Proxy |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不得为空 | 作为App/Admin服务端的环境变量，用于AI Proxy服务的身份验证，确保服务调用权限合法有效 |

## 容易做错的三处
- 现象：调用ollama部署的模型时，预设的合规审查引导词未生效。可验证排查项：检查`toolChoice`参数配置是否正确，或模型是否开启工具调用适配模式。
- 现象：生成的合规审查结果未结合当前版本的剧情上下文。可验证排查项：检查`maxContext`参数取值是否过小，导致历史与当前版本的关键文本被截断。
- 现象：调用第三方代理接口时返回收费相关提示。可验证排查项：检查上游模型渠道的地址与供应商凭证配置是否正确，或模型渠道配置是否存在权限限制。

## 怎么确认配好了
- 登录FastGPT平台的模型管理页面，查看`vision`参数的开启状态是否与配置一致。
- 提交单段游戏剧情文本与配套美术素材，触发审查流程，检查输出结果是否同时包含文本与视觉的合规分析内容。
- 调用测试接口，传入预设的合规审查引导词，确认返回结果是否匹配引导词定义的审查逻辑。
- 查看模型调用日志，确认`AIPROXY_API_TOKEN`的验证请求返回正常状态码。
