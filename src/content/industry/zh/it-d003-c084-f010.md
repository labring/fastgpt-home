# 游戏客户端性能优化的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
通常数据来自引擎Profiler导出的性能日志、真机测试的帧率与资源占用记录、崩溃平台的异常上报、版本迭代的优化记录；日常产出的文档包括性能测试报告、机型适配清单、优化迭代记录、崩溃分析台账；数据更新频率为每日或每版本迭代周期；文档字段通常包含机型型号、帧率数值、内存占用占比、资源加载时长、崩溃堆栈片段等，无固定强制格式但需匹配对应测试场景。

## 这些特征在「引用来源与溯源」这一环带来什么约束
分散的多源数据要求支持多格式数据源接入与增量同步，适配每日或每版本的更新节奏；不固定的文档结构需允许自定义引用字段的提取规则，适配不同测试报告的格式差异；单轮分析需处理多份机型测试数据，需限制单条引用的内容长度，避免超出上下文阈值；性能数据的准确性直接影响优化方向，需严格溯源到具体测试批次与机型，确保合规审查的可追溯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 字符 | 适配游戏客户端性能优化单条测试报告的典型长度，避免超出上下文处理上限 |
| `responseData` | 仅返回性能核心字段 | 过滤非必要的文档元数据，聚焦机型、帧率、资源占用等与优化直接相关的内容 |
| `detail` | 开启完整溯源 | 保留引用来源的文档ID、测试批次、机型型号等关键信息，满足合规审查要求 |
| 最大上下文 | 4000–6000 token | 容纳多份性能测试报告的引用内容，适配多机型对比分析的场景 |
| 知识库最大引用 | 前6条 | 匹配日常性能分析的典型参考样本量，避免冗余信息干扰模型输出 |
| 最大响应tokens | 1500–2000 token | 保证优化建议的输出长度足够覆盖具体调整方向与对应来源 |
*本页配置基于FastGPT v4.17.0版本*

## 容易做错的三处
- 现象：返回结果中携带冗余的引用标记与来源链接，干扰客户端性能优化建议的展示。原因：未正确设置`responseData`参数，默认保留了全量溯源字段，未过滤非必要的文档元数据。
- 现象：引用的性能测试报告内容中，预设的换行转义符被原样输出，未实现文本换行排版。原因：未开启`detail`参数的文本格式化配置，导致原始日志中的转义字符未被正确解析。
- 现象：单轮性能分析仅返回少量引用数据，无法覆盖多机型的测试结果。原因：`quoteMaxToken`取值区间设置过小，或知识库最大引用的条数限制过低，截断了有效性能数据。

## 怎么确认配好了
- 发起一次包含多机型性能数据的查询，核对返回结果中引用的来源字段是否包含测试批次、机型型号等关键信息。
- 查看引用内容的排版，确认预设的换行转义符已被正确解析为文本换行格式。
- 调整配置项后，验证返回的引用内容长度是否匹配预设的取值区间。
- 检查返回结果中是否仅包含与性能优化直接相关的核心字段，无冗余的非必要元数据。
