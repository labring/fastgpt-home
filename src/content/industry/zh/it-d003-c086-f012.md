# 游戏版号与出版申报的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
该品类的日常文档包含申报请示文件、游戏申请表、著作权证明、审读报告等，数据来源包括国家新闻出版署办事服务端口、著作权登记系统、游戏包体及运营机构提交的资料。数据更新节奏为每款游戏对应不定期更新，文档结构多为固定申报模板填充内容，部分审读报告为长文本格式，无统一标准化字段，需适配不同申报阶段的文档格式差异。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的多来源、格式不统一的文档，要求解析环节适配docx、pdf等多种格式，避免非标准申报模板的核心字段丢失。长文本审读报告可达千页，会带来解析超时风险，需调整解析与分块的超时阈值。不定期更新的单款游戏申报材料，需支持批量并行上传多份文件，避免串行处理拖慢流程。不同申报阶段的文档字段差异较大，分块时需保留上下文关联，避免拆分后丢失申报逻辑关联，影响后续合规审查的一致性核对。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配单款游戏申报材料的单段申报逻辑长度，避免拆分后丢失上下文关联 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配申报文档的固定模板结构，保留申报字段与对应内容的关联 |
| `customPdfParse` | 启用标准解析模式 | 适配游戏包体导出的pdf审读报告，保留原文档的排版与核心字段位置 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 秒 | 应对千页级长pdf审读报告的解析耗时，避免超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持批量上传多份申报文件，覆盖单款游戏全量申报材料的总大小 |
| `chunkSettingMode` | 手动配置 | 适配不同申报阶段的文档格式差异，灵活调整分块规则 |

## 容易做错的三处
- 现象：批量上传多份申报文件时出现部分文件解析失败，返回超时状态码。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，千页级pdf审读报告的解析耗时超出默认阈值。
- 现象：知识库中新建文本数据集时，内网confluence页面无法解析出内容，外网链接可正常解析。原因：未配置对应内网环境的解析权限，文档解析环节无法访问内网资源。
- 现象：启用父子分块功能后，申报文档的层级结构未被保留。原因：未正确配置`chunkSplitter`的层级识别规则，或当前配置未匹配游戏申报文档的固定标题层级。

## 怎么确认配好了
- 上传一份典型的千页级pdf审读报告，查看解析进度条是否正常完成，无超时报错。
- 批量上传多份docx格式的申报文件，确认并行处理时无文件被跳过或解析失败。
- 查看分块后的文本块，确认单块长度符合预期，无单段申报逻辑被拆分的情况。
- 测试内网confluence页面的解析配置，确认解析环节可正常访问内网资源。
