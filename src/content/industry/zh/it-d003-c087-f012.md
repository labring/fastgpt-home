# 游戏策划与数值设计的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
该品类的日常文档包含玩法策划案、数值表、版本需求单、平衡性测试记录。数据来源包括玩家行为数据、竞品公开资料、战斗日志与版本反馈。更新节奏为周度或每版本更新一次。文档结构多为结构化数值表格、带规则条目与版本编号的文本，数值表包含角色ID、属性值等字段，单位涉及攻击力数值、百分比、战斗时长等，玩法策划案则按模块划分玩法规则与数值逻辑。

## 这些特征在「文档解析与分块」这一环带来什么约束
结构化数值表的字段与对应数值关联性强，分块时需保留字段与数值的绑定关系，避免割裂后无法还原数值逻辑。玩法策划案的规则条目按模块划分，固定字符数分块易打断完整规则表述。周度或每版本的高频更新需求，要求分块适配小体量文档的快速处理。非结构化的战斗日志与玩家行为数据，需额外适配原始格式解析，防止字段信息丢失。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配玩法策划案的模块长度与数值表的字段组长度，避免拆分规则或数值关联 |
| `chunkSplitter` | 按文档结构拆分 | 适配结构化数值表与玩法策划案的模块划分，比固定字符分块更能保留内容关联性 |
| `customPdfParse` | 开启 | 游戏策划文档多包含表格与内嵌数值图表，开启后可保留原有排版与字段结构 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配单版本需求单或平衡性测试记录的解析时长，避免大文档超时失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配单批次版本更新的文档集合上限，支持批量上传需求 |
| `trainingType` | 通用文本训练 | 覆盖游戏策划文档中的规则文本与结构化数值两类内容，保障解析完整性 |

## 容易做错的三处
- 调用chunk模式调用pushdata api上传后持续显示索引中：原因是未根据周度更新的小体量文档调整`chunkSize`参数，分块过小导致索引队列堆积。
- 上传PDF格式的玩法策划案或数值表后图片被忽略：原因是未开启`customPdfParse`配置，默认解析仅提取纯文本，未保留内嵌的图表与数值截图。
- 上传javadoc生成的HTML格式版本需求说明后无解析结果：原因是未配置对应文档类型的解析规则，直接上传原始HTML文件未提取有效结构化内容。

## 怎么确认配好了
- 上传一份典型的数值表文档，检查解析后是否保留字段与数值的对应关系，验证分块未割裂关联内容。
- 上传包含内嵌图片的PDF文档，检查解析结果是否包含图片关联信息，确认`customPdfParse`配置生效。
- 调用pushdata api上传小体量版本需求单，检查索引状态是否在合理时长内完成，验证`PARSE_FILE_TIMEOUT_SECONDS`配置适配。
- 上传批量HTML格式的接口文档，检查解析结果是否提取有效文本内容，确认文档类型解析规则配置正确。
