# 游戏策划与数值设计的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类日常产出玩法策划案、数值表、版本需求单、平衡性测试记录等文档，数据来源包括玩家行为数据、竞品公开资料、战斗日志、版本反馈。数据更新以周或每版本为周期，数值表包含等级、伤害系数、资源消耗等字段，单位涉及金币、钻石、秒等，玩法策划案则包含规则描述、触发条件等非结构化内容，整体兼具结构化字段与自由文本形式。

## 这些特征在「模型接入与配置」这一环带来什么约束
品类文档兼具结构化数值表与非结构化玩法描述，要求模型接入配置需兼顾字段提取与文本理解能力；数据更新以周或每版本为周期，知识库同步需匹配该节奏，避免过期数据干扰审查结果；数据来源包含实时性较强的战斗日志与版本反馈，检索时需控制上下文长度以保证响应速度；合规审查结果直接影响玩法平衡与版本上线，需保证召回覆盖所有核心文档内容，避免遗漏关键校验项。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 该品类核心文档（玩法策划案、数值表）单份长度多在5000-8000 token，需保留完整上下文以覆盖所有合规校验相关内容 |
| `maxTokens` | 4000–6000 token | 安全与合规审查需生成包含规则校验、数值偏差分析的详细报告，需足够输出空间承载完整结论 |
| `quoteMaxToken` | 2000–3000 token | 需召回足够的战斗日志、版本反馈片段作为合规佐证，控制引用片段总长度避免上下文溢出 |
| `temperature` | 0.1–0.3 | 合规审查需输出稳定、一致的校验结论，避免随机性导致的判断偏差 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 http://aiproxy:3000（请勿附加 /v1 或 /chat/completions，不得使用 VLLM/Ollama/Xinference 等单模型地址） | 为 App/Admin 服务指定 AI Proxy 服务的访问地址 |
| `AIPROXY_API_TOKEN` | 与 AI Proxy 服务端配置一致的管理员 Token，且不能为空 | 用于 App/Admin 服务与 AI Proxy 服务之间的鉴权，不得使用应用 API Key、模型供应商密钥或其他类型令牌 |

## 容易做错的三处
- 现象：知识库检索响应缓慢，页面等待超过10秒未返回结果。原因：未针对品类的结构化数值表优化索引分片规则，导致检索时需加载过多分片文件。
- 现象：上传玩法策划案或数值表后，解析结果缺失伤害系数、资源消耗等核心字段。原因：未适配结构化文档的解析逻辑，导致数值表的字段关联信息未被正确提取。
- 现象：工作流运行时出现`gpt-4o-mini调用失败`的日志，未主动配置该模型调用。原因：工作流节点中残留了未清理的模型引用配置，系统尝试触发无效调用。

## 怎么确认配好了
- 上传一份典型的数值表文档，检查解析结果是否完整包含等级、伤害系数、资源消耗等核心字段。
- 发起一次合规审查请求，查看响应时间是否符合业务预期，无明显超时情况。
- 验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置，发起测试调用确认 App/Admin 服务可正常连接 AI Proxy 服务。
- 运行包含合规审查节点的工作流，检查日志中无无效模型调用的报错信息。
