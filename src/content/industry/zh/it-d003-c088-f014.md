# 游戏运营活动配置的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自游戏运营后台、玩家分群系统、付费数据平台与活动日志系统。日常产出的文档包括活动方案、奖励配置表、上线检查单与活动复盘材料，通常包含活动标识、奖励类型、配置数值、生效时段、触发规则、合规检查项等字段。数据更新频率多为周度或节假日活动周期内的临时调整，单次更新涉及单条或多条活动配置条目。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且格式各异，要求模型接入环节支持对接多类数据源的标准化输出，避免格式解析错误。活动配置更新频率较高，模型配置需支持快速调整上下文与调用参数，适配临时变更的活动规则。不同文档的字段结构存在差异，模型的上下文窗口与调用参数需适配多样的文档长度与字段类型。合规审查需准确核对奖励数值与生效时段，因此模型的参数需兼顾精度与响应速度，避免因配置不当导致审查结果偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 作为App/Admin服务端环境变量填写AI Proxy服务根地址，如`http://aiproxy:3000`，不得在工作流全局变量、应用API请求头或普通模型管理页面填写，不可附加路径后缀且不是VLLM/Ollama/Xinference等单模型地址 | 符合FastGPT v4.17.0及以上版本的环境变量要求，不可附加路径后缀 |
| `AIPROXY_API_TOKEN` | 作为App/Admin服务端环境变量填写与AI Proxy服务端配置一致且非空的管理员Token，不得在工作流全局变量、应用API请求头或普通模型管理页面填写 | 满足服务启动校验的必填要求，不可使用应用API密钥、模型供应商密钥、按应用签发的token或按请求估算的token数替代 |
| `maxContext` | 8000–12000 token | 适配活动文档与检查单的总长度，避免上下文溢出导致审查中断 |
| `maxTokens` | 1000–1500 token | 平衡合规审查的详细程度与响应耗时，避免输出过长或信息缺失 |
| `temperature` | 0.1–0.3 | 降低随机输出概率，确保奖励数值、生效时段等合规项的审查结果准确 |
| `quoteMaxToken` | 2000–3000 token | 限制单条引用文档的长度，确保审查时聚焦核心配置项 |

## 容易做错的三处
- 现象：启动App/Admin服务时触发启动校验失败，或提示缺少必填环境变量，或模型调用返回401未授权状态码。原因：未作为App/Admin服务端环境变量配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或填写的Token与AI Proxy服务端配置不一致。
- 现象：合规审查结果出现奖励数值计算错误，或生效时段判断偏差。原因：`temperature`参数取值过高，导致模型输出随机性过大，偏离精确审查的配置要求。
- 现象：模型调用超时，或返回上下文溢出提示。原因：`maxContext`参数取值过小，无法容纳活动文档与检查单的总内容，导致模型无法完成完整审查。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量配置，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`已正确填写且非空。
- 发起一次测试性的合规审查任务，观察模型是否能正常返回审查结果，无上下文溢出或超时报错。
- 调整`maxContext`、`maxTokens`等参数后，验证不同长度的活动文档是否都能被正常处理。
- 核对模型返回的审查结果与原始活动配置的一致性，确保核心项的判断符合预期。
