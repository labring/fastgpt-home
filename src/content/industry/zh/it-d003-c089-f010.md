# 漏洞扫描服务的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来源为漏洞扫描器、资产清单、CVE库与补丁公告，更新频率为周度或月度。日常产出文档包含扫描计划、漏洞清单、整改工单与复扫报告，各文档字段包含漏洞编号、关联资产IP、风险等级、整改状态、复扫结果等。单份漏洞清单可包含数十至数百条漏洞条目，复扫报告按单次扫描任务生成，关联对应扫描周期的资产与漏洞数据，用于安全合规审查的核心数据源为漏洞清单与复扫报告。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据特性要求引用溯源需区分漏洞扫描器原生数据、CVE库标准信息与补丁公告更新内容，避免混淆不同来源的可信度等级。周/月级的更新节奏决定了引用时需标注数据的采集周期，确保合规审查的时效性与准确性。不同文档的字段差异要求溯源需关联对应文档的唯一标识，如扫描计划ID或漏洞条目编号。误报排除与复扫核对环节则要求溯源可回溯至原始扫描结果，便于快速定位异常数据，避免高危漏洞暴露或审计扣分风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配单份漏洞清单或复扫报告的平均内容长度，避免截断关键溯源字段 |
| `responseData` | 开启 | 确保返回原始文档的完整元数据，用于关联漏洞编号、资产信息等核心溯源内容 |
| `detail` | 开启 | 展示原始文档的详细字段，便于定位具体漏洞条目与扫描周期 |
| 单次召回上限 | 前 3–5 条 | 匹配安全运营团队单次审查的高危漏洞数量，避免冗余信息干扰审查流程 |
| 相似度阈值 | 0.6–0.7 | 过滤低相关的扫描结果，减少误报对溯源精准度的影响 |

## 容易做错的三处
- 现象：调用API返回的溯源信息中，引用来源字段为空。原因：未开启`responseData`配置项，未启用原始数据返回开关，无法提取文档元数据。
- 现象：配置`quoteMaxToken`为 2000 token 后，仍无法召回需要的漏洞条目。原因：设置的token上限超出了当前知识库的内容总量，或相似度阈值设置过低，导致有效内容被过滤。
- 现象：复扫报告的溯源信息未关联对应扫描周期。原因：未在配置中启用`detail`展示，未加载文档的扫描周期字段，导致溯源信息缺失时间维度。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，发起一次漏洞扫描相关的测试查询，查看返回结果中是否包含漏洞编号、关联资产IP等溯源字段。
- 检查返回结果的上下文长度，确认未出现关键内容被截断的情况，匹配`quoteMaxToken`的设置值。
- 核对召回的溯源条目数量，确认与单次召回上限的设置一致。
- 查看返回的源数据标识，确认可关联到原始的扫描计划或复扫报告文档。
