# 漏洞扫描服务的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
本品类的数据主要来自漏洞扫描器产出的扫描计划、漏洞清单，企业资产清单、公开CVE库及补丁公告。日常处理的文档包含标准化扫描配置、按资产分组的漏洞条目、整改工单的进度记录、复扫后的结果对比报告。数据更新频率以周或月为周期，单份文档包含资产IP/域名、漏洞CVE编号、危害等级、修复状态等字段，无复杂嵌套格式，但单份文档的条目数量随企业资产规模波动。

## 这些特征在「文档解析与分块」这一环带来什么约束
首先，数据来源包含原生文本文档与图片扫描格式的报告，需要适配非原生文本的PDF解析需求。其次，周/月级的更新频率要求分块后的数据便于同步更新，过长的分块会增加后续同步更新时的冗余处理成本。单份文档包含大量标准化漏洞条目，分块需按条目或段落拆分，避免跨漏洞的上下文混淆。同时，资产范围确认环节依赖精准的字段关联，分块时需保留资产与对应漏洞的绑定关系，防止拆分后丢失关键对应信息。此外，高危漏洞暴露的出错后果要求解析与分块的完整性，避免关键条目遗漏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配漏洞清单的单条漏洞描述与关联字段长度，避免拆分后丢失上下文 |
| `chunkSplitter` | 按段落+固定字符截断 | 匹配漏洞文档的结构化段落格式，同时防止超长条目无法完整解析 |
| `customPdfParse` | 开启图片OCR模式 | 适配扫描件格式的复扫报告，提取图片内嵌的文本内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 700 秒 | 覆盖大型资产清单的批量解析耗时，避免触发超时报错 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量导入的扫描计划与资产清单文档 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（如漏洞清单、整改工单）调整分块参数，适配字段关联需求 |

本文适配FastGPT v4.17.0版本。

## 容易做错的三处
- 上传扫描件格式的漏洞复扫报告后，解析结果为空或仅提取少量文本。原因是未开启`customPdfParse`的图片OCR模式，仅识别文档中的原生文本内容。
- 上传大型资产清单文档时，平台返回超时报错。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`至匹配文档规模的时长，默认超时限制无法覆盖批量资产的解析流程。
- 检索指定条件的漏洞数据时，返回的条目数量少于源Excel文件的实际条目数。原因是分块时未保留资产字段与漏洞条目的关联关系，拆分后部分条目因上下文截断无法被完整索引。

## 怎么确认配好了
- 上传一份扫描件格式的复扫报告，查看解析后的文本是否包含图片中的漏洞条目与资产信息。
- 上传一份超过500MB的资产清单文档，验证解析过程未触发超时报错。
- 检索指定危害等级的漏洞条目，核对返回结果数量与源文档的条目数量是否匹配。
- 调整`chunkSize`至不同区间，测试分块后的文本是否保留了单条漏洞的完整关联信息。
