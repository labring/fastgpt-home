# 漏洞扫描服务的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
漏洞扫描服务的日常文档包含扫描计划、漏洞清单、整改工单、复扫报告，数据来源为漏洞扫描器、资产清单、CVE库与补丁公告，更新频率为周或月。单条数据包含漏洞CVE编号、关联资产IP或域名、漏洞等级、整改状态、复扫结果等字段，整体为结构化与半结构化结合的安全运营数据，用于支撑漏洞发现、整改与合规审计。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据以结构化安全运营记录为主，更新频率固定，意味着模型接入无需极高实时吞吐，但需要稳定适配长文档与结构化字段处理。漏洞数据的准确性直接关联合规审计结果，因此模型调用的鉴权与稳定性要求更高。同时，资产范围确认、误报排除等耗时环节需要模型关联多份文档内容，要求配置的上下文窗口能够覆盖关联数据，避免关键信息截断。此外，数据更新周期固定，无需频繁调整模型适配逻辑，可采用稳定的参数配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `AIPROXY_API_ENDPOINT` | `http://aiproxy:3000`（示例根地址，不附加`/v1`路径） | FastGPT v4.17.0起要求的App/Admin服务端AI Proxy服务根地址，非VLLM/Ollama/Xinference等单模型或下游模型供应商API地址 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token，非空 | 官方要求的App/Admin服务端必填环境变量，不可用应用API Key或模型供应商密钥替代 |
| `maxContext` | `8000–12000 token` | 适配复扫报告、漏洞清单等长文档的上下文需求，避免截断关联的资产与整改信息 |
| `maxTokens` | `2000–3000 token` | 平衡漏洞分析的输出长度与调用成本，适配单轮漏洞排查的内容输出需求 |
| `temperature` | `0.1–0.3` | 保障漏洞分类、整改建议输出的稳定性，避免随机性过高导致误判 |
| `toolChoice` | `auto` | 支持模型自主选择是否调用工具辅助漏洞验证或整改建议生成，适配安全审查的多步骤需求 |

## 容易做错的三处
- 现象：App服务启动时返回缺少必填环境变量的校验报错。排查项：检查App/Admin服务端是否已配置`AIPROXY_API_ENDPOINT`和非空的`AIPROXY_API_TOKEN`，属于启动校验问题。
- 现象：模型调用返回404路径错误或连接失败。排查项：检查`AIPROXY_API_ENDPOINT`是否为AI Proxy服务的根地址，未附加`/v1`或下游模型API路径，且不是VLLM/Ollama/Xinference等单模型地址。
- 现象：外部调用应用API鉴权失败。排查项：检查是否将`AIPROXY_API_TOKEN`误用为应用API Key或模型供应商密钥，两类鉴权凭证用途不同。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量配置，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`已正确设置且非空。
- 访问AI Proxy服务的根地址，验证服务正常运行，无连接超时或拒绝访问的情况。
- 在FastGPT的模型渠道配置页面，测试调用已配置的上游模型，确认可正常获取模型响应。
- 触发一次漏洞扫描任务的模型辅助审查流程，查看是否能正常生成漏洞分类结果或整改建议。
