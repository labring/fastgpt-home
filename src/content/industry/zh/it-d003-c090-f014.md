# 版本发布与Release Notes的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据为单版本发布对应的一组结构化变更记录，日常载体为Release Notes、变更日志、版本标签、发布检查单。数据来源为Git标签、合并提交记录、CI构建制品、Issue里程碑条目，更新频率为每版本发布一次。每条数据包含变更类型、关联提交哈希、关联Issue编号、制品校验值等字段，覆盖从代码变更到发布制品的全流程信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
品类数据的长文本特性要求模型接入时需配置足够的上下文容纳量，避免截断关键变更信息。按版本触发的更新节奏，要求配置支持手动或定时触发的审查流程，适配发布相关人员的日常操作习惯。数据来源依赖代码仓库与CI制品，要求模型接入需兼容结构化代码文本与校验信息的解析，确保审查范围仅覆盖已合并的发布内容。同时，审查结果需直接映射到Release Notes的合规要求，需配置模型输出格式与发布文档的字段对齐。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本，针对本场景定制。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://aiproxy:3000`（示例根地址，替换为实际AI Proxy服务根地址） | AI Proxy服务的根地址，不得附加`/v1`或具体模型路径，为App/Admin服务端必需配置的环境变量 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token | 完成AI Proxy服务的身份验证，确保调用权限合法，不得使用模型供应商密钥或应用API Key，为App/Admin服务端必需配置的环境变量 |
| `maxContext` | `8000–12000 token` | 容纳单版本全部变更记录的长文本内容，避免输入截断 |
| `temperature` | `0.1–0.3` | 生成稳定的合规审查与变更分类结果，避免无关输出干扰Release Notes编写 |
| `maxTokens` | `1500–2000 token` | 控制单条审查结果的输出长度，适配发布文档的格式规范 |
| `toolChoice` | `none` | 专注于文本审查任务，无需调用外部工具 |

## 容易做错的三处
- 调用模型时返回`422 "Messages token length must`报错。原因：未针对品类的长文本变更数据调整`maxContext`参数，导致输入上下文超出模型支持的token上限。
- 配置重排模型后，审查结果返回false。原因：未将重排模型绑定到对应审查任务的触发流程，或配置的重排模型输入格式与品类的变更日志字段不匹配。
- 本地部署的自定义模型无法正常接入。原因：未正确配置AI Proxy对接的上游模型渠道，或未正确配置AI Proxy管理员Token的权限范围。

## 怎么确认配好了
- 检查App/Admin服务启动日志，确认无`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`相关的启动校验失败提示。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置未出现格式错误，且网络连接正常。
- 触发一次版本发布的自动审查流程，检查是否能正常拉取Git标签、CI制品等品类数据，无数据遗漏或截断。
- 调整`temperature`参数的取值区间，对比不同配置下的审查结果一致性，确认符合预期的稳定度。
