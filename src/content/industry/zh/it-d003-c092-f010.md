# 现场部署实施的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
现场部署实施品类的数据来自客户机房环境、设备清单、软件包、网络拓扑等现场一手资源，日常产出部署手册、安装记录、配置清单、现场签到表四类文档。数据更新节奏为每单或每阶段，字段包含部署节点标识、软件版本号、配置参数值、现场签到时间、网络连通状态等，无统一标准化格式，随客户现场环境差异调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
现场部署实施的数据源多为客户现场一手资源，且随每单或每阶段更新，要求引用溯源必须精准绑定具体部署任务的文档条目。日常文档格式不统一，需支持多类型文档的来源标记。数据关联的是现场安装配置的实际结果，因此溯源需区分部署实施的实际执行数据与前期规划类文档。同时，现场数据的唯一性较强，需避免不同部署单的引用内容混淆，确保溯源链路可追溯到具体现场环节。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本设定：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前2–4条 | 匹配现场部署单的核心文档数量，避免引入无关的冗余内容 |
| `quoteMaxToken` | 1200–1800 token | 适配现场部署文档通常的5000 token切块设置，控制单条引用的长度 |
| `responseData` | 包含来源路径、文档类型字段 | 提取部署手册、安装记录等现场文档的标识，支撑精准溯源 |
| 最大上下文 | 不超过5000 token | 匹配知识库切块大小，容纳单阶段部署的完整配置信息 |
| `detail` | 开启 | 展示文档的具体条目，如安装记录的节点信息，细化溯源维度 |

## 容易做错的三处
- 现象：检索到匹配的现场部署文档切块，但最终引用内容超出设置的`quoteMaxToken`上限。原因：未将知识库切块大小与`quoteMaxToken`配置联动，切块内的内容长度超过设置的token限制。
- 现象：引用来源仅显示知识库名称，未标记部署手册、安装记录等具体文档类型。原因：未开启`responseData`的字段提取配置，未配置来源路径与文档类型的映射规则。
- 现象：多部署单的引用内容出现混淆，无法区分不同客户的现场数据。原因：未绑定部署任务ID作为检索过滤条件，导致跨单的文档内容被错误召回。

## 怎么确认配好了
- 发起针对现场部署文档的检索，检查返回结果的来源字段是否包含部署手册、安装记录等对应类型。
- 调整`quoteMaxToken`为1000 token，检索单条5000 token的切块，确认引用内容未超出设置的token长度。
- 针对两个不同的部署单发起检索，确认返回的来源信息仅关联当前任务的文档，无跨单混淆。
- 查看返回结果的`detail`字段，确认包含具体的节点标识、配置参数等现场部署的细节信息。
