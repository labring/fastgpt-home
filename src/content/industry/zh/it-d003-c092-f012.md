# 现场部署实施的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
典型数据来自客户机房环境、设备清单、软件包、网络拓扑文档，更新频率为每单或每项目阶段。日常处理的文档包括部署手册、安装记录、配置清单、现场签到表，文档结构多为多列表格、分段说明、参数列表，字段包含设备型号、IP地址、软件版本、配置参数、签到时间等，单位涉及台、个、秒、MB等。

## 这些特征在「文档解析与分块」这一环带来什么约束
多列表格类文档（如配置清单、网络拓扑）要求解析工具保留列关联关系，避免默认规则仅识别前两列内容；非标准排版的现场文档（如带有手写标注的部署手册）无法通过通用解析规则准确提取字段；单份文档体积差异较大，从几KB的现场签到表到数十MB的设备清单，对解析超时设置提出灵活要求；每单数据独立且无通用模板，需支持自定义分块规则适配不同客户的文档格式。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置逻辑编写
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配部署手册、配置清单的单段内容长度，避免分块过碎导致检索分散，或过长导致上下文溢出 |
| `chunkSplitter` | 按段落+表头分隔 | 适配多列表格文档，保留列与内容的关联关系，避免仅识别前两列数据 |
| `customPdfParse` | 开启 | 适配非标准排版的现场PDF文档，提取原始排版中的设备型号、版本号等关键字段 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对大型设备清单、复杂拓扑文件的解析耗时，避免因超时导致解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配现场部署场景下的大型设备清单、拓扑文件上传需求 |
| `chunkSettingMode` | 手动模式 | 适配不同类型的现场文档，灵活调整分块规则以匹配文档结构 |

## 容易做错的三处
- 现象：上传多列配置清单excel后，检索时仅能匹配前两列内容。原因：未调整分块规则，使用默认配置仅识别前两列数据。
- 现象：部署手册PDF解析后缺失设备型号字段。原因：未开启`customPdfParse`参数，默认解析无法适配非标准排版的现场文档。
- 现象：解析后的布尔类型配置参数经条件判断后为空。原因：解析时未保留原始数据类型，转换为字符串后未做适配处理。

## 怎么确认配好了
- 上传单份典型配置清单excel，检查解析后的数据列数是否与原文档一致。
- 上传非标准排版的部署手册PDF，确认解析结果中包含设备型号、版本号等关键字段。
- 触发大型设备清单的解析任务，查看任务日志无超时报错，确认耗时符合预设范围。
- 导入布尔类型参数的测试数据，验证条件判断组件可正常识别参数类型。
