# 用户增长与留存运营的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
该品类的典型处理主体为增长运营、用户运营与数据分析师，日常处理的文档包含增长实验方案、用户分层表、触达文案、留存分析报告四类。数据来源涵盖用户行为日志、推送系统、实验平台与CRM系统，更新频率多为日度或周度。文档结构兼具结构化与非结构化特征，其中用户分层表包含分层标签、触达阈值等字段，触达文案包含渠道、触发时机等参数，增长实验方案与留存分析报告则以段落化的分析内容为主。本文基于FastGPT v4.17.0版本撰写。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于数据来源多样，文档格式涵盖word、excel、txt及pdf等多种类型，要求解析环节需适配多格式文件。日度/周度的更新频率带来批量处理需求，需控制解析与分块的整体耗时，避免影响运营流程。结构化文档的表格字段与非结构化文本需分别适配解析逻辑，确保关键合规字段不被拆分或遗漏。同时，安全与合规审查要求解析环节需过滤敏感内容，分块时需保留与合规相关的完整上下文，避免拆分关键审核节点。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 品类内日常文档多为短段落与结构化表格，该长度可保留完整上下文，同时避免分块过长导致检索效率下降 |
| `chunkSplitter` | 按段落+自定义规则 | 兼顾非结构化文本的段落拆分与结构化表格的字段提取，适配多类型文档的解析需求 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量上传日度/周度的批量报告与日志文件，避免因文件过大导致上传失败 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 满足大型用户分层表、留存分析报告的解析耗时需求，避免因超时中断解析任务 |
| `customPdfParse` | 开启 | 适配合规类pdf文档的解析，可自定义提取敏感字段与文本内容，满足安全审查需求 |

## 容易做错的三处
- 现象：调用知识库API返回文件阅读链接，点击链接访问时提示"Only support .txt, .m"错误；原因：上传的文件格式未被系统支持，未开启对应格式的解析配置。
- 现象：上传word或excel文件后，解析结果正常，但大模型生成回答时未包含文档内的图片内容；原因：未开启`customPdfParse`或未配置图片解析提取规则，分块时未关联图片的文本描述信息。
- 现象：设置自定义分块长度时，无法明确参数值的实际含义，导致分块过长或过短；原因：未结合品类文档的平均长度配置参数，混淆了字符数与token数的换算逻辑。

## 怎么确认配好了
- 上传品类内典型文档，如用户分层表、触达文案，检查解析结果是否完整提取了表格字段与文本内容。
- 调用知识库API获取分块结果，核对分块长度是否符合预设的`chunkSize`范围。
- 上传格式合规的文件，验证访问返回的链接是否可正常打开，无格式报错提示。
- 批量上传多个日更文档，检查解析任务是否在`PARSE_FILE_TIMEOUT_SECONDS`内完成，无超时中断情况。
