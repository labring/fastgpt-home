# 用户验收测试支持的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于需求规格、测试环境、客户业务样例、缺陷系统，由实施顾问、测试经理、客户业务代表维护。日常产出的文档包括UAT用例、验收问题单、验收报告、签字确认单，文档结构以业务场景为核心，包含操作步骤、预期结果、问题描述、整改意见等字段。数据更新频率为每阶段或每版本，随验收进度同步调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源依赖测试环境与客户业务样例，要求模型接入需适配测试环境的部署配置，避免跨环境调用引发合规风险。文档以业务场景为核心的结构，要求模型输入需对齐UAT用例的字段格式，无法直接使用纯技术化的参数输入。每阶段的更新频率，要求配置支持快速调整与版本回滚，适配验收进度的迭代节奏。出错后果直接关联验收延期与尾款延迟，要求模型调用的稳定性与合规性需纳入配置校验范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配UAT用例、验收问题单的批量文本长度，覆盖单阶段验收的全量业务上下文 |
| `maxTokens` | 4096 token | 匹配验收报告的单页输出长度，避免截断关键验收结论 |
| `quoteMaxToken` | 1000 token | 限定引用的客户业务样例文本长度，确保合规审查的聚焦性 |
| `temperature` | 0.2–0.4 | 保持合规审查的严谨性，避免生成不符合验收标准的内容 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions，不得使用VLLM/Ollama/Xinference等单模型地址 | 为App/Admin服务端必需的环境变量，对接测试环境的AI Proxy服务，匹配数据来源的测试环境要求 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，且不能为空，不得使用应用API Key、模型供应商密钥等其他密钥 | 为App/Admin服务端必需的环境变量，保障模型调用的权限合规，符合安全与合规审查的管控要求 |

## 容易做错的三处
- 调用模型时返回`401 Unauthorized`错误，排查项：检查App/Admin服务端的`AIPROXY_API_TOKEN`环境变量是否与AI Proxy服务端配置的管理员Token一致且非空。
- 模型重排功能未按预期返回匹配UAT用例的结果，原因是未正确配置`toolChoice`参数，导致模型未启用对应工具能力。
- 整点自动触发模型调用，原因是测试环境中残留的定时任务配置未关闭，引发非预期的模型访问，违反合规审查的可控性要求。

## 怎么确认配好了
- 验证App/Admin服务端已正确配置`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`环境变量，服务启动校验通过。
- 导入单份UAT用例文本，调用模型生成合规审查结果，检查输出未触发`maxContext`或`maxTokens`的截断报错。
- 关闭所有非必要的定时任务，观察24小时内无额外模型调用记录，确认配置的可控性。
- 提交多份验收问题单，验证模型输出的引用文本长度未超过`quoteMaxToken`的预设范围。
