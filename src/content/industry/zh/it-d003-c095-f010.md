# 监控告警配置的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来自Prometheus、Zabbix、云监控、应用日志、CMDB等系统，更新频率为每日或每配置变更时。日常维护的文档包含监控指标清单、告警规则、值班手册、告警变更记录，字段包含告警触发阈值、关联指标名称、变更时间、值班责任人等，单位涵盖秒、条、百分比等，单条告警配置文档的标准长度多在800–1200字符区间。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据源分散要求溯源环节需绑定各系统的唯一标识，避免混淆不同监控工具的告警数据；更新频率灵活决定了引用内容需支持按变更时间筛选，确保溯源的时效性；文档结构聚焦告警规则与指标，要求溯源仅关联告警相关的文档，排除无关内容；字段多且细粒度高，需要精准匹配字段名称才能完成准确溯源，否则会出现关联错误。同时，合规审查要求溯源结果可直接追溯到原始告警配置，无法出现无来源的告警解释。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | `800–1200 字符` | 匹配单条告警配置文档的标准长度 |
| `responseData` | 仅返回关联告警条目 | 聚焦合规审查所需的告警相关内容 |
| `detail` | 显示关联指标与变更记录 | 满足溯源所需的完整上下文 |
| 最大溯源条目数 | 前3条 | 避免过多冗余信息干扰审查 |
| 溯源超时阈值 | `30 秒` | 匹配告警响应的SLA要求 |
| 适用版本 | FastGPT v4.17.0 | 适配当前版本的配置逻辑 |

## 容易做错的三处
- 现象为查看告警回答的知识库引用时出现“关联数据源未匹配”报错，原因是未将告警规则的CMDB标识配置为溯源关联字段。
- 现象为回答中显示非告警类的知识库搜索input和response内容，原因是未开启仅关联告警配置的引用过滤开关，导致加载了无关的知识库内容。
- 现象为溯源结果加载超时，原因是未设置合理的`quoteMaxToken`取值，导致加载过多冗余文档内容。

## 怎么确认配好了
- 触发一条测试告警，查看回答的引用部分，确认仅显示关联的告警规则、指标清单与变更记录内容。
- 检查`quoteMaxToken`的配置取值，确认符合告警文档的单条长度范围。
- 查看系统日志，确认溯源请求仅关联指定的Prometheus、Zabbix、CMDB数据源。
- 模拟一次告警配置变更，验证引用内容随变更记录同步更新。
