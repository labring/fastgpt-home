# 社区举报处理的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自举报系统、内容详情页、用户历史操作记录及审核规则库。日常处理涉及的文档包括举报工单、举报处理记录、用户申诉单、违规处置通知模板。数据更新节奏通常为实时或每日同步，单条数据包含举报主体、被举报内容、关联用户ID、审核依据字段，单位以条、字符、分钟为核心计量维度，整体数据结构围绕单条举报事件的全流程处理展开。

## 这些特征在「引用来源与溯源」这一环带来什么约束
举报工单的单条被举报内容长度差异显著，引用来源与溯源环节需限制单次引用的token总量，避免上下文溢出导致输出异常。数据实时或每日更新的节奏，要求溯源逻辑能快速关联最新的审核规则与用户历史操作记录。不同文档类型的字段结构存在差异，需精准匹配举报工单、申诉单等数据源的字段提取规则。环节出错可能引发用户投诉或违规内容留存，需确保溯源结果可追溯且可复现。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配举报工单的平均内容长度，避免上下文溢出 |
| `responseData` | 仅关联来源文档字段 | 聚焦举报处理所需的审核依据，减少冗余信息 |
| `detail` | 开启 | 展示被引用内容的原始片段，满足合规审查的溯源需求 |
| 单次关联知识库上限 | 前8条 | 匹配单条举报工单的审核数据量级，避免资源占用过高 |
| 知识库总字数限制 | 按实测标定 | 适配社区运营团队的日常文档存储规模 |
| 响应超时阈值 | 600 秒 | 适配FastGPT v4.17.0的实时审核响应要求 |

## 容易做错的三处
- 输出内容未附带引用来源的原始片段。原因是未开启`detail`配置项，未启用原始内容展示开关。
- 单条对话关联知识库数量超过上限导致内容截断。原因是未设置合理的单次关联知识库上限，超出预设的关联条数限制。
- 知识库上传的文档原文无法被溯源查询。原因是未配置`responseData`为包含原始文档存储路径的返回格式，导致系统未记录原文位置。

## 怎么确认配好了
- 发起一条模拟举报工单的测试对话，查看输出结果是否附带被引用内容的原始片段。
- 上传多份测试文档，核对单次关联知识库的条数是否符合预设上限。
- 查看系统日志，确认响应超时未超过预设阈值。
- 检查溯源信息字段，确认已记录上传文档的原始存储路径。
