# 社区举报处理的安全与合规材料审查：模型接入与配置
本文适配 FastGPT v4.17.0 版本，针对社区举报处理场景的安全合规材料审查环节的模型接入与配置提供具体指引。

## 这个品类的数据长什么样
社区举报处理场景的数据来自社区举报系统的工单详情、关联内容快照、用户历史行为记录与平台审核规则库。日常产出的文档包含结构化举报工单、处置记录、申诉复核单与标准化用户通知。数据更新节奏为实时同步新提交的举报工单，每日批量同步历史归档的审核数据。字段包含举报唯一标识、涉诉内容片段、用户标识、举报类型与审核状态，无额外统计类量化字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
举报工单的涉诉内容长度跨度较大，从短文本评论举报到长文内容投诉，要求模型上下文配置可适配不同长度的输入。实时同步的工单要求模型接入接口具备低延迟响应能力，避免阻塞审核队列。多源数据的关联审核需求，要求模型支持整合工单、内容快照与历史记录的关联信息。结构化的工单字段要求模型输出格式可直接映射至预设字段，便于快速写入处理系统。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 800–1500 字符 | 适配举报工单与涉诉内容的混合输入长度，覆盖多数单条举报的上下文需求 |
| `maxTokens` | 200–400 token | 控制举报有效性判断的输出长度，确保结果可直接填入工单字段 |
| `quoteMaxToken` | 100–200 token | 限定违规证据截取的引用长度，避免输出过长无法嵌入处理记录 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保审核判断的一致性，符合合规审查的标准化要求 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 http://aiproxy:3000 | 为 AI Proxy 服务的访问根地址，需与 AI Proxy 服务端配置一致，不得附加 /v1 或 /chat/completions 路径，确保服务可达 |
| `toolChoice` | none | 无需调用额外工具，仅需基于输入文本完成审核判断，符合单条举报处理的轻量化需求 |

## 容易做错的三处
- 现象：调用通过 AI Proxy 接入的模型时返回空结果，排查项：检查服务端环境变量 AIPROXY_API_ENDPOINT（AI Proxy 服务根地址）、AIPROXY_API_TOKEN（AI Proxy 管理员 Token）是否正确配置，确认 AI Proxy 服务可达且凭证与服务端配置一致
- 现象：vllm部署的模型处理举报工单时出现延迟过高，排查项：检查 AI Proxy 服务响应延迟、上游模型渠道配置是否正确，确认 maxContext 参数设置符合业务输入长度需求
- 现象：模型输出结果无法适配工单字段要求，排查项：检查 toolChoice 参数是否设置为 none，确认模型未尝试调用未配置的工具

## 怎么确认配好了
- 调用配置的接口，使用测试用的举报工单文本发起请求，检查返回状态码正常且结果有效。
- 输入长短差异的举报内容，确认模型均可正常解析并生成符合要求的审核判断。
- 批量提交测试工单，检查接口响应符合业务场景的延迟要求。
- 验证模型输出结果可适配预设的举报工单字段映射规则，无格式错误。
