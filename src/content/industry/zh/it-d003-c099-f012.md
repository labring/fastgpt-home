# 移动端开发的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
这个品类的数据主要来自代码仓库、应用商店后台、崩溃监控平台、机型覆盖数据。日常处理的文档包括端版本发布单、机型适配清单、崩溃分析报告、应用商店上架资料。数据更新节奏以每日或每版本发布周期为准，文档结构多包含固定字段，如版本号、适配机型范围、权限调用配置、审核状态标识等，部分文档会嵌入截图、多列表格、跨页排版的合规附件。

## 这些特征在「文档解析与分块」这一环带来什么约束
端版本发布单和适配清单的多机型字段、应用商店资料的分段合规要求，要求解析时保留字段关联关系，避免跨字段分块导致信息断裂。多列表格、跨页排版的文档会让通用分块逻辑出现内容割裂，需要针对性调整分块边界。崩溃分析报告的时序性数据，要求分块保留上下文关联，不能拆分关键时序节点。嵌入的图片附件和多格式内容，需要在解析时同步关联对应文本内容，避免出现文本与素材分离的情况。同时每日更新的版本数据和周期性发布的文档，要求解析流程具备稳定的超时处理能力，适配高频更新的业务节奏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配移动端文档的字段长度与合规材料的分段要求，避免拆分关键权限配置或版本信息 |
| `chunkSplitter` | 按段落+标题拆分 | 适配版本发布单、适配清单的结构化文档结构，保留字段关联关系 |
| `customPdfParse` | 开启 | 适配FastGPT v4.17.0版本的PDF解析引擎，支持多列表格、内嵌图片的复杂排版提取 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配单份版本发布单或上架资料的附件体积上限，满足大型适配清单的上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配多机型适配清单、崩溃分析报告的解析耗时，避免高频更新场景下的解析中断 |
| `chunkSettingMode` | 手动配置 | 针对移动端文档的特殊排版，自定义分块边界与关联规则，适配不同类型的合规材料 |

## 容易做错的三处
- 上传包含内嵌图片的PDF文档后，解析结果仅返回文本内容，无图片关联信息。原因是未开启`customPdfParse`配置，默认解析逻辑未同步提取并关联内嵌图片内容。
- 多列排版的适配清单或应用商店资料导入后，表格内容出现列错位或字段合并。原因是未使用按段落+标题拆分的`chunkSplitter`，通用分块逻辑无法识别多列文档的结构边界。
- 解析大型版本发布单时出现超时报错，返回状态码504。原因是未将`PARSE_FILE_TIMEOUT_SECONDS`调整至适配大型文档的取值区间，默认超时时长不足以完成完整解析。

## 怎么确认配好了
- 上传一份包含多列表格与内嵌图片的测试文档，核对解析结果是否完整保留表格结构与图片关联文本。
- 上传单份体积符合`UPLOAD_FILE_MAX_SIZE`取值的文档，确认上传与解析流程无中断报错。
- 针对时序性的崩溃分析报告，检查分块结果是否保留相邻节点的上下文关联，未出现关键时序信息拆分。
- 调整`chunkSize`取值后，验证分块后的文本单元是否完整覆盖单条合规字段或版本信息。
