# 等级保护测评咨询的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
本品类的核心数据来自测评工具输出、现场访谈记录、资产系统清单、安全设备运行日志，日常产出定级报告、差距分析报告、整改方案、测评报告四类核心文档。数据更新以单个测评项目为周期，单项目周期内按需同步更新，无固定年度外的批量更新节奏。文档结构以等保标准控制项为核心框架，包含控制项编号、现状描述、整改要求、佐证材料清单等固定字段。

## 这些特征在「引用来源与溯源」这一环带来什么约束
核心文档以等保控制项为框架，每个控制项对应多份佐证材料，引用时需精准匹配控制项与佐证来源，避免跨项混淆。数据按项目更新，引用溯源需绑定项目标识，防止跨项目数据混用。单项目文档量随系统规模扩大而增加，需限制单次召回的文档数量，避免上下文过载。不同来源数据格式差异较大，需统一溯源展示的字段格式，确保合规材料的可追溯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配单份合规文档的平均长度，避免上下文溢出，适配FastGPT v4.17.0的参数逻辑 |
| 单次召回上限 | 前5–15条 | 适配单项目的文档规模，防止召回过多材料导致token超限 |
| `detail` | 开启完整佐证字段 | 展示整改证据的原始内容，支撑测评环节的核对工作 |
| `responseData` | 包含来源文档路径与控制项编号 | 满足合规审查的溯源展示要求，便于监管核查 |
| 上下文窗口 | 4000–6000 token | 适配不同规模项目的文档总量，平衡召回精度与效率 |

## 容易做错的三处
- 现象：生成的回答未展示任何引用文档的出处，对应字段为空。原因：未开启`responseData`配置的来源字段绑定，或未正确关联文档与控制项标识。
- 现象：单轮回答token数远超设置上限，出现截断或报错提示。原因：将`quoteMaxToken`设置为过高数值，未匹配单项目文档的实际长度，导致上下文过载。
- 现象：召回的引用文档数量远超预期，无法控制展示条数。原因：未设置单次召回上限，或上限值未适配单项目的文档规模，导致冗余材料被召回。

## 怎么确认配好了
- 生成一段针对等保控制项的查询，检查回答末尾是否展示了对应的文档来源与控制项编号。
- 调整`quoteMaxToken`参数，观察回答的token消耗是否符合预期，无明显溢出或截断。
- 测试不同规模的项目文档，验证单次召回的文档数量是否符合预设的上限要求。
- 核对展示的引用内容是否与原始文档的控制项字段一致，确保溯源信息准确。
