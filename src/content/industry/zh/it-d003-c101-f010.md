# 续费健康度管理的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据覆盖客户全周期续费相关信息，日常文档包含客户健康度报告、续费预测表、风险客户清单、沟通纪要四类核心文件。数据来源包括CRM系统、产品使用数据、工单统计、合同台账，更新频率按周或月执行。数据字段涵盖客户关联标识、合同周期节点、使用行为记录、服务交互记录等，不同类型文档的字段结构存在差异，无统一固定的单字段格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来自多个异构数据源，需确保每条引用片段都能精准关联到原始数据源的具体条目，避免溯源混淆。因数据按周或月更新，引用的时间范围需匹配更新周期，防止引用过期数据影响健康度判断。不同类型文档的字段差异较大，需配置对应文档类型的唯一标识映射规则，比如合同台账需展示合同编号、工单需展示工单号，确保溯源链路清晰。同时，数据解读环节耗时较长，明确的溯源链路可缩短排查时间，这要求引用配置需包含明确的来源标识与层级。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | `8000–12000 token` | 匹配续费健康度管理类文档的平均长度，避免超出大模型上下文限制 |
| `responseData` | 开启 | 满足直接输出知识库原文且无额外修饰的需求 |
| `detail` | 显示数据源类型与唯一标识 | 快速定位原始数据条目，缩短排查时间 |
| 多知识库关联配置 | 关联CRM、产品使用数据、工单统计、合同台账四类数据源 | 覆盖该品类全量数据来源，支持跨源查询 |
| 引用分类展示 | 显示文档所属类型 | 帮助快速识别数据类别，辅助健康度分析 |

## 容易做错的三处
- 现象：引用结果仅显示通用来源名称，未展示具体的唯一标识（如合同编号、工单号）。原因：未配置对应文档类型的唯一标识映射规则，导致溯源链路模糊。
- 现象：每次查询响应超时，或返回结果被截断。原因：未根据续费健康度管理的数据规模调整`quoteMaxToken`参数，取值超出大模型可处理的上限。
- 现象：仅能引用单一数据源的内容，无法同时获取多个知识库的续费相关数据。原因：未开启多知识库关联配置，仅绑定了单一数据源，无法覆盖该品类全量数据需求。

## 怎么确认配好了
- 发起一次包含续费健康度相关数据的查询，检查返回结果中每条引用片段是否附带数据源类型与唯一标识。
- 查看引用片段的Token占用情况，确认未超出预设的`quoteMaxToken`限制。
- 开启`responseData`开关后，检查是否能直接输出对应文档的原文内容，无额外修饰。
- 测试同时关联多个数据源的知识库，确认查询结果能覆盖不同类型的续费相关文档。
