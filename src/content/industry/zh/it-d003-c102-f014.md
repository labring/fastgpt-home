# 缺陷管理与回归测试的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于缺陷管理系统、测试报告、代码提交记录与用户反馈，更新频率为每日或每版本发布周期。核心文档包含缺陷单、回归测试清单、修复验证记录及缺陷统计报表，其中缺陷单包含缺陷标识、严重等级、复现步骤、关联代码提交与验证状态字段，回归清单则关联测试用例标识、对应版本号与执行结果字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据高频更新的特性要求模型接入配置需适配实时或准实时的文档同步，避免因上下文窗口不足丢失最新缺陷信息。多源异构的数据格式，包含结构化清单、非结构化描述与统计数据，要求配置需支持混合输入的解析逻辑。缺陷复现与验证环节的高耗时特性，要求模型输出需精准匹配缺陷单与回归清单的字段格式，减少人工校验成本。高优缺陷遗漏的出错后果，要求配置需强化对严重等级字段的识别权重。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配每日更新的缺陷单与回归清单的累计文本长度，避免截断关键复现步骤与验证记录 |
| `maxTokens` | `2000–3000 token` | 满足缺陷单详细描述、回归清单批量条目与统计报表的输出解析需求 |
| `quoteMaxToken` | `500 token` | 限制引用的缺陷单与测试报告片段长度，确保上下文聚焦核心缺陷信息 |
| `toolChoice` | `auto` | 自动适配缺陷分类、优先级判定等多步骤处理需求，无需手动指定工具 |
| `temperature` | `0.2–0.4` | 降低随机输出概率，提升缺陷字段识别与回归结果判定的一致性 |
| `AIPROXY_API_TOKEN` | 服务端环境变量，为 AI Proxy 管理员 Token，与 AI Proxy 服务端配置一致且非空 | 作为 AI Proxy 依赖的必填环境变量，符合安全与合规要求 |

## 容易做错的三处
- 现象：调用模型后返回“API Key 权限不足”报错。原因：误用 AI Proxy 管理员 Token 作为应用 API Key 进行鉴权，AI Proxy 管理员 Token 不可替代应用 API Key 用于外部应用调用鉴权。
- 现象：批量处理回归清单时输出结果不完整，仅返回前3条测试用例。原因：未调整`maxContext`参数适配批量条目长度，导致上下文窗口截断了后续的回归测试数据。
- 现象：识别缺陷严重等级时出现偏差，将一般缺陷判定为高优缺陷。原因：`temperature`参数取值过高，导致模型输出随机化，偏离缺陷单预设的严重等级字段规则。

## 怎么确认配好了
- 检查服务端是否已配置非空的`AIPROXY_API_TOKEN`环境变量，该变量为 AI Proxy 管理员 Token，与 AI Proxy 服务端配置一致。
- 检查服务端是否已配置`AIPROXY_API_ENDPOINT`环境变量，其值为 AI Proxy 服务的根地址（例如 http://aiproxy:3000），未附加 /v1 或 /chat/completions 路径。
- 上传一份完整的缺陷单与回归清单，核对模型输出的字段是否覆盖了所有预设的缺陷标识、严重等级与验证状态。
- 触发批量回归测试数据的解析任务，确认输出结果的条目数与输入清单的条目数一致。
