# 许可证合规与版权声明的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来源于代码仓库、依赖清单、许可证文本与贡献记录，日常维护的核心文档包含LICENSE文件、NOTICE文件、依赖许可证清单与版权声明。数据更新节奏为每版本发布或每依赖变更时同步更新，不同文档的字段各有明确侧重：LICENSE文件包含许可证类型与授权范围，NOTICE文件记录版权持有者与第三方授权声明，依赖许可证清单汇总项目所有第三方依赖的合规信息，版权声明标注项目核心版权归属。数据关联的主体为开源办公室、项目维护者与法务人员，用于日常合规核对与分发授权管理。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且覆盖代码仓库与依赖清单两类渠道，要求溯源环节需支持多数据源关联校验，避免仅依赖单一清单出现合规信息遗漏。数据更新频率较高，溯源需支持按版本匹配对应合规文档，确保引用内容与当前项目或依赖的实际版本一致。不同文档的字段差异明显，溯源需精准定位对应字段的内容，比如从LICENSE文件提取许可证类型，从NOTICE文件获取版权声明信息。最耗时的合规核对环节依赖溯源的精准性，要求溯源结果可直接关联到原始文档的具体位置，满足后续合规审计的可追溯要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | 800–1200 token | 匹配许可证与版权声明文档的平均字符长度，避免截断关键合规信息 |
| `responseData` | 仅包含许可证编号、版权持有者 | 聚焦核心合规字段，减少冗余内容占用上下文空间 |
| `detail` | 开启 | 需展示溯源的具体文件路径与版本信息，满足合规审查的可追溯要求 |
| 数据源优先级 | 代码仓库优先于依赖清单 | 代码仓库的官方许可证文件可信度更高，优先作为溯源基准 |
| 版本匹配开关 | 开启 | 本品类数据按版本更新，需匹配对应版本的合规文档，避免版本错位 |

## 容易做错的三处
- 现象为聊天回复中出现知识库引用报错，状态码返回400，原因是未配置`quoteMaxToken`参数，导致引用内容超出上下文长度限制。
- 现象为回复中展示了冗余的知识库搜索input和response内容，原因是未关闭非核心合规信息的展示开关，误将工具调用的中间步骤纳入溯源展示。
- 现象为溯源结果未匹配到对应版本的许可证文件，原因是未开启版本匹配规则，使用了最新版本的文档匹配旧版本依赖的合规数据。

## 怎么确认配好了
- 生成包含依赖许可证信息的测试提问，核对引用内容的长度符合预设的token范围。
- 查看回复内容，确认仅展示核心合规字段，无冗余的工具调用中间步骤。
- 切换不同版本的依赖数据，核对溯源结果匹配对应版本的合规文档。
- 检查FastGPT v4.17.0的系统日志，确认无引用相关的报错记录。
