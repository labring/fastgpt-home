# 许可证合规与版权声明的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自代码仓库、依赖清单、许可证文本与贡献记录。日常产出的文档包含LICENSE文件、NOTICE文件、依赖许可证清单与版权声明。数据更新节奏为每版本发布或每一次依赖变更时触发。单份数据包含许可证类型、版权持有者、依赖包名称与版本号等字段，无额外自定义单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散、更新节奏随版本与依赖变更高频触发，且文档结构固定但字段明确，适配FastGPT v4.17.0版本的模型接入配置逻辑。这要求模型接入环节支持多源数据的定向拉取，配置需适配高频调用的稳定性需求；同时固定的文档字段结构，要求模型能精准识别并校验许可证类型、版权持有者等核心字段，避免因字段匹配偏差导致合规校验出错。多源数据的关联校验需要足够的上下文承载能力，防止因上下文截断遗漏关键关联信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions，不得填写为 VLLM/Ollama/Xinference 等单模型地址 | 作为AI Proxy服务的根地址，确保App/Admin服务能正确连接AI Proxy，避免请求无法送达 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token，且不能为空，不得为应用API Key、模型供应商密钥或按应用签发的token | 完成AI Proxy服务的身份校验，防止未授权访问 |
| `maxContext` | 8000–12000 token | 适配多源合规文档的上下文长度，避免关键校验信息被截断 |
| `maxTokens` | 2000–3000 token | 控制单轮合规校验的输出长度，确保结果清晰完整 |
| `temperature` | 0.1–0.3 | 降低输出随机性，保证许可证兼容性核对的结果准确一致 |
| `toolChoice` | auto | 允许模型自主选择合适的校验逻辑，适配不同类型的合规文档 |

## 容易做错的三处
- 工作台编辑页面报错“未配置语言模型”，可排查：未正确配置服务端环境变量`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或`AIPROXY_API_TOKEN`与AI Proxy服务端配置不一致。
- 模型流响应为空，原因是`maxContext`设置过小导致上下文被截断，或`maxTokens`取值过低无法承载完整输出内容，部分场景下也可能因`temperature`取值过高导致输出格式不符合预期。
- doubao 1.6模型输出思考内容后无正文，原因是`maxTokens`设置未覆盖正文输出所需的token额度，或模型接入的上下文参数配置存在偏差。

## 怎么确认配好了
- 检查App/Admin服务的服务端环境变量配置，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的取值与官方指引一致。
- 触发一次小型合规校验任务，查看模型调用日志中的响应状态，确认返回正常的成功状态码。
- 检查工作流的模型选项列表，确认目标合规校验模型已出现在可选列表中。
- 手动输入一份测试用的依赖许可证清单，运行校验流程，确认模型输出包含许可证兼容性核对与版权归属确认的核心内容。
