# 语音标注与转写的安全与合规材料审查：对话日志与审计

## 这个品类的数据长什么样
本品类的数据主要来自音频文件、标注平台、专用词表、抽检样本。日常关联文档包括转写规范、音频清单、质检报告、说话人标注表。数据更新节奏为每日或按标注批次执行，单条数据包含音频时长、说话人标识、转写文本、标注状态、质检结果等字段，字段单位随具体标注项调整，无统一固定格式。

## 这些特征在「对话日志与审计」这一环带来什么约束
音频文件体积较大，对话日志需支持关联大体积源数据的索引，避免存储冗余或关联失败。按批次更新的数据要求日志按批次归档，避免跨批次混淆导致的溯源错误。多字段的结构化数据需要日志完整记录标注链路，包括原始音频、标注操作、质检结果，便于后续排查转写返工或识别训练偏差问题。无固定单位的字段要求日志保留原始字段映射关系，确保审计时可还原完整标注过程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话日志保留时长 | 7–30 天 | 匹配标注批次的常规归档周期，适配日常审计与溯源需求 |
| 日志存储上限 | 1200 GB | 按单批次标注数据量与日更新量估算，预留合理缓冲空间 |
| `chatId` 任务绑定 | 开启 | 用于绑定单条标注任务的完整对话与操作链路，避免源数据关联丢失 |
| `responseChatItemId` 索引 | 启用 | 快速定位单条标注操作的上下文信息，提升审计效率 |
| `detail` 全量日志 | 开启 | 记录标注过程中的所有参数与中间结果，覆盖完整标注链路 |
| docker日志挂载 | 开启 | 便于将日志持久化存储，避免容器重启或更新后日志丢失 |

本配置方案适配FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：对话日志中仅留存转写结果，无原始音频关联记录。原因：未开启`chatId`任务绑定配置，导致源数据与日志的映射关系丢失，无法追溯标注的原始依据，易引发转写返工或交付延期问题。
- 现象：日志存储占用超过设定阈值后自动清理早期数据，导致历史标注日志丢失。原因：未设置合理的日志保留时长与存储上限，或未配置自动归档规则，超出阈值后触发强制清理，无法满足长期审计需求。
- 现象：审计时无法快速定位单条标注操作的上下文。原因：未启用`responseChatItemId`索引配置，日志未按操作项建立索引，检索效率低下，难以快速排查异常标注项。

## 怎么确认配好了
- 进入系统日志管理页面，查看`chatId`与标注任务的绑定关系是否完整。
- 检索单条标注操作的日志，确认`responseChatItemId`索引可正常返回上下文信息。
- 检查日志存储面板，确认保留时长与存储上限的配置与当前业务需求匹配。
- 模拟触发一次标注操作，查看`detail`字段是否完整记录了操作参数与中间结果。
- 查看docker容器配置，确认日志挂载路径已正确配置，无存储丢失风险。
