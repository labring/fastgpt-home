# 语音标注与转写的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
该品类的日常文档包含转写规范、音频清单、质检报告、说话人标注表四类。数据来源为音频文件、标注平台、专有词表与抽检样本。更新频率为每日或按标注批次更新。转写规范为带专有术语列表的结构化文本，音频清单为含音频路径、时长的表格文件，质检报告包含片段标注与修正意见，说话人标注表记录说话人ID与对应角色。文档结构差异较大，部分文件含表格、批注与元数据字段。

## 这些特征在「文档解析与分块」这一环带来什么约束
四类文档的结构差异要求解析环节需适配文本、表格与带批注的混合格式，避免遗漏专有术语与说话人关联信息。按日或批次更新的数据需要稳定的批量解析能力，防止因单次处理超时导致任务中断。专有词校对与说话人区分的核心环节，要求分块时保留上下文关联，避免拆分同一说话人的转写片段或专有术语，否则会引发后续训练偏差与返工。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本，具体如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 该品类文档包含专有词表与长文本转写片段，该区间可保留上下文，避免拆分专有术语与说话人关联内容 |
| `chunkSplitter` | 按段落加语义边界 | 适配转写规范、质检报告等混合格式文档，保留说话人标注与专有词的上下文关联 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 批量处理音频清单、质检报告等复杂文档时，预留足够解析时间，避免中途超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持该品类批量抽检样本与长音频元数据文件的上传需求 |
| `customPdfParse` | 开启 | 准确提取带批注、表格的质检报告与转写规范中的结构化内容 |
| `chunkSettingMode` | 手动模式 | 适配四类文档的格式差异，灵活调整分块规则以匹配业务需求 |

## 容易做错的三处
- 现象：批量上传多份转写规范文档时，中途出现解析中断，重启Docker后无法恢复解析进度。原因：未配置合理的`PARSE_FILE_TIMEOUT_SECONDS`，超时后未自动恢复任务队列。
- 现象：对话框上传音频清单文件后，界面显示未解析，后台无报错日志。原因：未开启`customPdfParse`，默认解析无法正确识别表格格式的音频清单内容。
- 现象：分块结果丢失说话人标注信息，导致后续质检环节无法关联对应片段。原因：`chunkSplitter`配置为仅按固定字符拆分，未保留说话人上下文边界。

## 怎么确认配好了
- 上传单份转写规范文档，查看解析后的分块是否完整保留专有词表的上下文内容。
- 上传批量音频清单文件，检查解析进度是否符合预设的超时阈值，无中途中断提示。
- 上传带批注的质检报告，确认解析结果中提取了批注的修正意见与表格字段。
- 查看系统运行日志，确认无文件解析超时或格式解析失败的报错记录。
