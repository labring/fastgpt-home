# 账号封禁与申诉复核的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的核心数据围绕账号级惩罚与复核流程产生，日常文档包括账号封禁记录、用户申诉材料、复核判定意见、违规处置通知。数据主要来自风控系统的违规触发日志、人工审核的操作记录、用户行为留存日志以及举报留存的证据材料，更新节奏为实时或每日批次更新。数据字段包含账号唯一标识、违规类型标签、处置等级、申诉提交时间、复核结果等，无统一固定单位，随具体文档类型变化。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散在多个独立系统，引用溯源需先完成跨源字段映射，确保不同系统的账号标识、违规内容等字段可统一关联。实时或每日更新的数据特性要求溯源逻辑支持增量拉取或全量校验，避免遗漏最新提交的申诉或复核记录。账号级的业务属性要求溯源结果必须绑定唯一账号标识，防止跨账号的违规证据混淆。同时，处置结果关联合规校验要求，溯源需保留完整的证据链路，确保每一条引用内容均可直接追溯至原始记录，为复核或申诉提供可验证的依据，规避误封、违规账号回流等风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `1000–1500 token` | 该品类的申诉与封禁文档单篇长度多在千字符左右，该区间可完整保留核心引用内容且控制上下文开销 |
| `detail` | `true` | 需获取申诉材料的完整元数据与原始内容，`detail`为`true`时可返回未截断的文档信息与账号绑定字段 |
| `responseData` | 返回原始文档标识与账号绑定字段 | 该品类需将引用结果与对应账号绑定，确保溯源不混淆不同账号的违规证据 |
| 单次引用返回上限 | 前5条 | 该品类的核心违规证据通常集中在3-5条，过多引用会增加审核团队的核对负担 |
| 溯源数据源范围 | 风控系统、审核记录、举报证据库 | 该品类的核心数据来源为上述三类系统，限定范围可避免无关数据干扰溯源结果 |
| 增量更新开关 | 开启 | 数据更新以实时或每日批次为主，增量拉取可提升溯源效率，减少重复校验开销 |

## 容易做错的三处
- 现象：返回的引用内容未包含指定账号的申诉材料，或关联了错误的违规记录。原因：未在`responseData`配置中绑定账号唯一标识，导致溯源结果混淆了不同账号的原始数据。
- 现象：知识库输出的引用文件指向错误的封禁记录或申诉材料。原因：未正确配置`detail`参数，仅返回了压缩后的元数据，无法匹配原始文档的唯一标识。
- 现象：FastGPT v4.17.0 中关闭引用开关后仍返回引用内容。原因：版本兼容问题导致全局配置与单次调用参数的校验逻辑未正确生效，未拦截非预期的引用返回。

## 怎么确认配好了
- 发起一次携带测试账号标识的调用，检查返回结果中是否包含绑定该账号的申诉材料、封禁记录的引用信息，确认溯源关联的准确性。
- 调整`quoteMaxToken`的取值范围，验证返回的引用内容无截断或溢出情况，确认上下文配置符合业务需求。
- 关闭引用开关后发起调用，确认无额外引用内容返回，验证配置的生效性。
- 查看系统运行日志，确认溯源请求正确拉取了指定的风控系统、审核记录等数据源的内容，验证数据源范围配置的正确性。
