# 质保期缺陷响应的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
典型主体为售后服务工程师、项目经理、研发支持；日常使用的文档包括质保工单、缺陷确认单、修复记录、客户确认单。数据来源为客户提交的工单、系统运行日志、合同质保条款、软件或硬件版本记录，更新频率为每日或随每单任务同步。文档通常包含缺陷编号、责任边界标识、修复执行步骤、客户确认标识等字段，无统一强制格式，但需关联原始项目交付的相关信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据来源分散且覆盖项目交付全流程，要求引用溯源环节需支持多类型数据源的关联检索，避免割裂的信息片段。文档随单或每日更新，要求检索链路适配高频小批量的数据更新，无需全量重新索引。文档字段包含责任边界、客户确认标识等关键合规信息，要求溯源结果需精准匹配到具体的缺陷工单、修复记录或合同条款条目。同时，质保争议场景下需留存引用的原始元数据，确保每一处引用都可追溯到原始业务节点。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1500 token | 适配质保工单、修复记录等单文档的平均长度，避免截断关键合规字段 |
| `responseData` | 保留原始来源标识 | 记录引用内容对应的文档存储路径、更新时间等元数据 |
| `detail` | 开启完整字段溯源 | 展示引用内容关联的缺陷编号、责任方等业务字段 |
| 单次搜索召回条数 | 前6–8条 | 覆盖单缺陷对应的多类关联文档，避免遗漏合同条款或版本记录 |
| 相似度阈值 | 0.75–0.85 | 匹配质保相关关键词，过滤无关的运维类文档 |
| 重排开关 | 开启 | 优先排序包含客户确认标识的文档，提升合规审查效率 |

## 容易做错的三处
- 现象为开启重排功能后，检索结果返回空或引用片段为空；原因为重排的相似度阈值设置过高，过滤掉了符合要求的低相关度但属于质保相关的文档片段。
- 现象为导入导出的工作流中引用的数据源或插件无法识别；原因为未保留原环境中关联的数据源路径配置，或插件的版本与目标环境不匹配。
- 现象为引用内容未显示关联的业务字段；原因为未开启`detail`参数的完整溯源配置，仅返回了文本片段未携带元数据。

## 怎么确认配好了
- 提交一条典型的质保缺陷查询，检查返回结果是否包含关联的质保工单、合同条款等文档片段。
- 在FastGPT v4.17.0版本中，查看引用内容的详情面板，确认是否包含来源文档的更新时间、缺陷编号等业务字段。
- 测试调整相似度阈值，对比不同阈值下的检索结果条数，验证阈值配置的合理性。
- 导出引用溯源的相关数据，检查是否包含`responseData`字段的完整标识信息。
