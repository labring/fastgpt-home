# 质保期缺陷响应的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自客户提交的质保工单、缺陷确认单、修复执行记录、客户验收确认单，数据来源涵盖客户反馈工单、系统运行日志、项目合同质保条款、软件版本更新记录。数据更新频率为每日或随每笔业务单生成，单份文档包含缺陷描述、责任边界标注、修复方案、关联版本号、客户确认签字等固定字段，字段与单位随不同项目的质保条款略有调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据多源分散且随单更新，要求模型接入环节支持对接工单、日志、合同等多类型数据源，避免数据割裂。单份文档内容长度随缺陷复杂度波动，需适配不同场景的上下文容量限制，防止内容截断丢失关键责任边界信息。文档字段无强制统一标准，需模型可灵活识别非固定字段的核心信息，同时需保留数据引用溯源能力，确保审查结果可追溯至原始工单或合同条款，降低质保争议风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 单份质保工单结合关联日志、合同的总内容量通常在该区间内，可避免截断关键责任边界信息，在FastGPT v4.17.0版本的配置界面中可直接设置该参数 |
| `quoteMaxToken` | `2000–3000 token` | 保留足够的原始引用片段用于合规审查溯源，确保责任边界判断的依据可追溯至原始文档 |
| `temperature` | `0.1–0.3` | 该场景需稳定的责任判断结果，该参数区间可降低输出随机性，避免引发质保争议 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 `http://aiproxy:3000`（不得附加 `/v1` 或 `/chat/completions` 路径） | 作为 App/Admin 服务端必需环境变量，配置正确可确保 AI Proxy 调用链路合规稳定，避免因地址错误导致启动校验或调用失败 |
| `toolChoice` | `auto` | 根据审查任务自动选择是否调用检索工具获取合同条款等参考数据，适配多源数据的审查需求 |

## 容易做错的三处
- 现象：调用模型时返回“该令牌无权使用模型”的报错，或提示无可用渠道。排查项：未正确配置`AIPROXY_API_TOKEN`，或`AIPROXY_API_TOKEN`与 AI Proxy 服务端配置不一致、为空。
- 现象：模型输出的审查结果未关联原始文档片段，或引用内容缺失。原因：未配置`quoteMaxToken`参数，或取值过小导致引用片段被截断，无法保留完整的原始依据。
- 现象：模型生成的责任边界判断结果存在随机偏差。原因：将`temperature`参数设置为过高区间，导致每次输出结果不一致，引发质保争议风险。

## 怎么确认配好了
- 调用单份测试质保工单的审查任务，查看返回结果是否包含原始文档的引用片段，核对引用片段的长度是否符合预设配置要求。
- 更换不同类型的质保工单与合同条款进行测试，确认模型可正确识别不同字段的核心信息，无明显内容截断或信息误判。
- 检查 App/Admin 服务端部署的环境变量配置，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`未出现格式错误或内容遗漏，且`AIPROXY_API_TOKEN`非空。
- 多次运行同一审查任务，确认输出结果的一致性，验证`temperature`参数的取值符合预期的稳定性要求。
