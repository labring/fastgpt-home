# 身份账号与权限管理的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来自企业IAM平台、HR系统、业务系统操作日志与审批系统。日常产出的文档包括账号申请单、权限矩阵表、离职账号回收单、月度权限审计报告。数据更新节奏为每日同步或随人事入离转调实时更新。单条数据字段包含账号唯一标识、绑定的业务权限范围、审批流程状态、生效与失效时间，数据结构以结构化表格为主，部分审批流单据为半结构化文档。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源多为企业内部系统的结构化与半结构化文档，且更新随人事变动触发，引用溯源需匹配实时同步的权限状态。账号ID、权限范围等字段的唯一性要求溯源时需精准匹配字段值，避免跨账号混淆。半结构化的审批单据需支持提取审批节点与操作时间，确保溯源链路可追溯到具体审批环节。同时，审计报告的批量数据需支持按时间范围筛选引用，适配合规审查的周期要求。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配IAM相关文档的字段长度，避免截断关键权限信息与审批状态 |
| `responseData` | 包含账号ID、权限范围、审批状态 | 匹配本品类数据的核心字段，确保溯源信息覆盖合规审查所需内容 |
| `detail` | 开启 | 支持提取半结构化审批单据的附加信息，如审批人、生效时间 |
| 单次召回上限 | 前3条 | 适配IAM数据单场景的条目数，避免冗余信息干扰合规审查 |
| 上下文引用范围 | 按实测标定 | 适配多轮对话中入离转调的全流程权限变更场景 |

## 容易做错的三处
- 代码运行节点的变量选择面板中无知识库引用选项，仅显示空引用字段。原因是未通过`responseData`配置指定提取IAM专属字段，系统未将IAM数据纳入可引用变量范围。
- 回复为空但附带引用链接。原因是`quoteMaxToken`设置低于600 token，截断了权限申请单的审批状态字段，导致无法生成有效回复内容。
- 无法配置多轮对话上下文引用，仅召回单条历史数据。原因是未将上下文引用范围调整为覆盖多轮审批流程节点，未适配本品类数据随人事变动的更新节奏。

## 怎么确认配好了
- 上传一份账号申请单测试文档，触发引用溯源，检查返回的引用数据是否包含账号ID、审批状态字段。
- 调整`quoteMaxToken`至1000 token，生成权限审计报告相关的回复，检查回复内容与引用数据是否匹配。
- 开启`detail`配置，发起包含离职回收流程的查询，检查是否返回审批人、生效时间等附加信息。
- 发起多轮权限申请对话，检查系统是否自动关联历史对话中的账号信息作为引用依据。
