# 身份账号与权限管理的安全与合规材料审查：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自企业IAM系统、HR系统、业务系统日志与审批系统。日常处理的文档包含账号申请单、权限矩阵、离职回收单、合规审计报告。数据更新节奏为每日同步或随人事入离转调实时更新，字段包含账号标识、权限绑定范围、审批节点状态、变更时间等，无额外非必要的自定义统计字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据来源要求模型接入需兼容不同接口的响应格式，需配置统一的字段映射规则。数据更新无固定周期，需支持模型调用随数据变动触发，适配临时的人事变更场景。固定结构的日常文档需模型预设字段提取模板，避免提取偏差。合规审计的严格性要求模型输出需保留完整推理依据，确保审核结果可追溯。同时，需适配不同文档的字段顺序灵活性，避免因权限文档的格式差异导致的提取错误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的模型接入界面，其中`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`为App/Admin服务端环境变量，不得在界面配置。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 本品类的合规文档（权限矩阵、审计报告等）单批次上下文量较大，需承载多源数据的完整内容 |
| `maxTokens` | `2000–3000 token` | 身份权限审核的输出需覆盖权限校验、异常标注等内容，避免截断关键合规结论 |
| `quoteMaxToken` | `500–800 token/条` | 需为每条权限相关文档片段分配足够上下文，确保模型能准确匹配权限规则与文档内容 |
| `toolChoice` | `auto` | 需模型自主选择是否调用权限校验工具，适配不同场景的合规审查需求 |
| `temperature` | `0.1–0.3` | 合规审查需严格对齐预设规则，降低推理随机性，确保审核结果一致性 |
| `AIPROXY_API_ENDPOINT` | 为AI Proxy服务的根地址，例如`http://aiproxy:3000`，不得附加`/v1`或`/chat/completions`路径，不可填写VLLM/Ollama/Xinference等单模型服务地址 | 该变量为App/Admin服务端环境变量，用于指定AI Proxy服务访问地址 |
| `AIPROXY_API_TOKEN` | 为与AI Proxy服务端配置一致的管理员Token，且不能为空 | 该变量为App/Admin服务端环境变量，用于AI Proxy服务的身份验证，不得用作应用API调用鉴权 |

## 容易做错的三处
- 现象：模型输出的权限异常列表中包含已离职员工的账号信息，日志显示数据未同步最新的离职回收单。原因：未配置数据更新触发机制，模型调用仍使用旧版权限矩阵数据，未同步HR系统的最新变动信息。
- 现象：配置`maxTokens`为`10000 token`后，模型响应超时，界面显示上下文溢出提示。原因：未结合本品类文档的实际长度调整参数，超出模型支持的最大输出限制。
- 现象：模型提取的账号ID存在大量缺失，无法生成完整的权限审计报告。原因：未开启工具调用能力，模型无法调用预设的字段匹配模板，导致核心字段提取不完整。

## 怎么确认配好了
- 导入一份已归档的账号申请单与权限矩阵，执行审核任务，核对模型提取的核心字段是否与原始文档匹配。
- 触发一次模拟的人事变动操作，调用模型审核相关权限变更，检查是否能同步获取最新的业务系统日志与审批数据。
- 查看模型输出的合规校验结果，确认是否保留了对应文档片段的引用内容，确保审核依据可追溯。
- 调整参数区间后，多次运行同一审核任务，验证输出结果的稳定性与一致性。
