# 运维外包驻场服务的安全与合规材料审查：引用来源与溯源

## 这个品类的数据长什么样
这个品类的典型数据主体为外包驻场工程师、服务经理与客户IT部门。日常产出与流转的文档包括驻场日报、服务台工单、巡检报告、SLA月报。数据主要来源于客户ITSM系统、监控平台、资产清单与值班记录，更新频率多为日度或月度。文档字段包含工单编号、巡检项、服务响应时长、SLA达标情况等，无统一强制格式，需按客户交付要求整理，部分文档为现场半结构化录入的非标准化文本。

## 这些特征在「引用来源与溯源」这一环带来什么约束
驻场类文档多为非标准化格式且来源分散，要求溯源功能需兼容多类数据源的元数据提取。日度更新的工单与值班记录时效性强，需确保溯源结果的时间戳与原始数据完全一致，避免合规审查时出现时间不符的问题。SLA月报涉及合同合规要求，溯源需保留完整的文档版本与提交人信息，以明确责任边界。驻场人员的巡检报告多为现场手写或半结构化录入，需支持对非结构化文本的精准溯源定位。同时，客户IT部门的合规审查要求溯源链路可追溯至原始数据源，不能仅依赖中间处理结果。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配驻场日报、巡检报告等单文档的核心内容长度，避免截断关键合规审查所需的信息 |
| `responseData` | 开启 | 支持返回原始文档的关联元数据，满足合规审查时需同步展示来源的要求 |
| `detail` | 完整模式 | 可展示原始文档的存储路径、更新时间与提交人信息，覆盖客户IT部门的核查需求 |
| 单次召回上限 | 前5条 | 匹配日常工单与巡检报告的关联数据量，避免冗余信息干扰审查流程 |
| 知识库关联总容量 | 1000–2000 MB | 覆盖客户ITSM、监控平台等所有相关数据源的文档总量，确保溯源无遗漏 |

## 容易做错的三处
- 界面显示红色数字报错，且无法展示任何溯源信息。原因是未开启`responseData`配置项，导致系统仅返回模型生成的内容，无法关联原始文档数据。
- 溯源结果中未显示原始文档的具体存储位置与提交人信息。原因是未将`detail`配置为完整模式，仅返回了内容片段而未关联完整元数据。
- 关联多个数据源后出现召回不全或内容截断。原因是未按客户资产清单范围配置知识库关联总容量，超出预设阈值导致部分数据源未被加载。

## 怎么确认配好了
- 发起包含驻场日报、巡检报告或SLA月报相关关键词的对话，检查回复下方是否展示了溯源数据的入口。
- 点击溯源入口，确认可查看原始文档的存储路径、更新时间与提交人信息。
- 测试关联2-3个不同类型的数据源文档，检查是否能正常召回并展示对应溯源信息。
- 调整`quoteMaxToken`的取值，验证回复内容的截断情况是否符合预期。
