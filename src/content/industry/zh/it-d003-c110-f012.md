# 运维外包驻场服务的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
运维外包驻场服务的日常文档主要包括驻场日报、服务台工单、巡检报告、SLA月报，数据来源为客户ITSM系统、监控平台、资产清单、值班记录。更新频率分为日更（驻场日报、工单）与月更（SLA月报），文档结构包含自然段落、多行业务表格与统计字段，常见字段包括工单编号、巡检点位、SLA达成率、值班时段，单位涉及小时、台数、百分比等。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于文档来源覆盖多套客户系统，格式包含XLSX、PDF、PPT与纯文本，解析环节需适配多种文件类型；日更与月更的批量文档需求，要求配置支持批量定时解析与合理的超时阈值；驻场类文档的表格多为多行业务记录，分块需保留表格上下文避免拆分错位；合规审查要求解析过程不丢失敏感字段，需准确还原文档结构；部分老旧客户文档存在非UTF-8编码，可能引发解析报错。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 驻场日报、巡检报告的单段有效信息长度，避免分块过碎或跨关键业务信息 |
| `chunkSplitter` | 按段落+表格拆分 | 工单、巡检报告包含多行表格与自然段落，混合拆分可保留完整业务上下文 |
| `customPdfParse` | 开启 | 驻场巡检报告多为带格式或扫描版PDF，自定义解析可还原表格与排版结构 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 批量上传的月度SLA月报、汇总工单包的常见最大体积 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大体积PDF或多表格PPT的常规解析耗时，避免超时中断任务 |
| `chunkSettingMode` | 手动模式 | 驻场类文档格式差异较大，手动配置可适配不同文档类型的分块需求 |

## 容易做错的三处
- 现象：上传PPT或文档时出现“the argument ‘windows-1252’ is invalid encoding”报错，原因：未适配文档的非UTF-8编码，默认解析编码无法识别字符集
- 现象：XLSX格式的多行工单表格被拆分为零散小块，原因：未配置按表格拆分的分块规则，仅按字符长度分块丢失表格上下文关联
- 现象：批量上传月度SLA月报时解析超时失败，原因：`PARSE_FILE_TIMEOUT_SECONDS`配置值过低，未适配大体积多表格文档的解析耗时

## 怎么确认配好了
- 上传一份驻场日报文档，查看解析后的分块内容是否保留了工单编号、处理结果等关键字段，无明显内容截断
- 上传XLSX格式的巡检报告，检查表格内容是否完整导入，未出现单元格内容拆分错位的情况
- 上传1000 MB以内的月度SLA月报，确认解析任务在600秒内完成，无超时报错
- 查看FastGPT v4.17.0的后台配置日志，确认`customPdfParse`、`chunkSettingMode`等配置项已按预设生效
