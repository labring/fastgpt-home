# 配置管理与CMDB维护的安全与合规材料审查：权限与数据隔离

## 这个品类的数据长什么样
本品类的数据覆盖运维资产全生命周期相关内容，日常产出配置项清单、服务组件关系拓扑、变更记录、资产盘点表四类核心文档。数据来源包括自建CMDB、云资源清单、自动发现工具及采购台账，更新频率为每日或每周。数据字段包含资产唯一标识、跨组件依赖关系、变更时间、操作责任人等，未设置额外统计百分比或虚构数值，核心围绕配置项的采集、核对与更新流程。

## 这些特征在「权限与数据隔离」这一环带来什么约束
数据来源分散且涉及多系统资产，权限隔离需覆盖不同数据入口的访问控制，避免跨系统越权访问。更新频率的差异要求权限策略适配实时与周期性更新场景，防止权限过期或未同步导致的访问异常。配置项清单与关系拓扑包含服务依赖链路，权限不足会直接影响故障定位效率。资产盘点表与变更记录涉及敏感操作权限，需严格区分配置项采集、审核、变更的角色权限。同时，本品类与IT资产盘点品类的差异要求隔离规则聚焦依赖关系，不聚焦单一资产，避免跨品类权限混淆。

## 配置怎么定
本文档适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `teamId` | 按业务团队划分，取值为`["ops-team", "sec-team", "audit-team"]` | 数据涉及多业务线资产，需按团队隔离访问权限，匹配日常运维角色分工 |
| `tmbId` | 按CMDB实例环境划分，取值为`["cmdb-prod", "cmdb-test"]` | 配置项分生产与测试环境，需按实例ID隔离跨环境访问，避免测试数据泄露 |
| 数据更新权限 | 仅允许变更管理员执行，触发频率匹配`每日/每周更新任务` | 数据更新频率为日/周，需严格控制更新操作权限，防止误修改核心配置 |
| 敏感字段脱敏 | 对资产责任人、采购台账信息脱敏，保留后4位字符 | 资产盘点表与采购台账包含敏感信息，需合规隔离非授权访问 |
| 访问日志留存 | 留存90天 | 合规审查需追溯权限操作记录，满足安全审计要求 |

## 容易做错的三处
- 现象：配置权限隔离规则后，工作流任务中自定义插件无输入输出参数展示，无报错日志。原因：未通过`teamId`绑定对应业务团队的插件权限范围，导致权限校验拦截参数加载流程。
- 现象：本地部署完成后，无法创建多账号，资产表格添加数据无响应。原因：未配置`tmbId`对应的CMDB实例分组权限，导致数据写入被隔离策略拦截。
- 现象：配置数据隔离后，无法对接SSO认证系统。原因：未将SSO认证域与团队权限范围绑定，导致认证通过后无对应数据访问权限。

## 怎么确认配好了
- 登录不同业务团队的账号，验证仅能查看对应`teamId`范围内的配置项清单。
- 触发数据更新任务，验证仅授权角色可执行配置项采集与变更操作。
- 提交SSO认证请求，验证认证后账号自动匹配对应`tmbId`的权限范围。
- 查看访问日志，验证所有权限操作均被记录且可追溯。
