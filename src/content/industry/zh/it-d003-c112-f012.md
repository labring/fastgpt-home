# 问题管理与根因分析的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
本品类的数据来自故障时间线、运行日志、监控指标、代码提交记录，更新节奏为每次重大故障或每月一次。日常处理的文档包括RCA报告、问题单、复盘纪要、整改跟踪表，文档结构通常包含故障发生时间、根因分析结论、整改跟踪项、关联监控数据片段等字段，无统一固定格式，部分文档会嵌入日志截图或代码片段，数据体量随故障发生频次波动。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于数据来源分散且文档格式不统一，解析环节需兼容多类型附件与非结构化文本；更新频率低但单份文档内容关联度高，分块需保留上下文关联以支撑根因关联分析；整改跟踪表等文档包含明确的责任字段与时间节点，分块时需避免拆分关键关联信息；批量处理的故障复盘文档数量随故障频次波动，需适配突发的大文件解析需求，同时避免因解析超时导致任务中断，影响合规审查进度。

## 配置怎么定
FastGPT v4.17.0版本中，可通过系统设置的文档解析模块完成以下配置：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配RCA报告中根因描述、整改项等关联文本的长度，避免拆分关键逻辑 |
| `chunkSplitter` | 按段落优先 | 匹配复盘纪要、问题单的自然分段逻辑，保留上下文关联 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配批量大体积日志文档、嵌入截图的复盘报告的解析耗时 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单次上传包含多份日志附件的故障复盘包 |
| `customPdfParse` | 开启 | 兼容嵌入图表、截图的合规审查PDF文档解析 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（如整改跟踪表、RCA报告）调整分块参数 |

## 容易做错的三处
- 上传大批量文档后解析中断，重启容器后无法继续解析。原因是未配置`PARSE_FILE_TIMEOUT_SECONDS`的合理时长，导致大体积文档解析超时后进程异常退出，未保留解析断点。
- 对话框上传文件始终无解析进度，后台无报错。原因是未开启`customPdfParse`，导致嵌入复杂格式的合规文档无法被正确识别解析。
- 配置`chunkSize`过小导致根因分析的上下文被拆分。原因是未结合RCA报告的文本长度调整分块参数，破坏了根因描述的完整逻辑。

## 怎么确认配好了
- 上传单份100MB的RCA报告PDF，查看解析进度是否在600秒内完成，无中断报错。
- 上传包含多段日志的复盘纪要，检查分块结果是否保留了完整的故障时间线段落。
- 调用知识库添加接口，验证分块内容是否符合预设的`chunkSize`范围。
- 查看`UPLOAD_FILE_MAX_SIZE`配置是否匹配当前上传的最大文档体积，避免上传超限被拦截。
