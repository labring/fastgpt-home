# 项目实施计划管理的安全与合规材料审查：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据通常来自合同、工作分解结构（WBS）、客户日程及项目管理系统，核心文档包含项目计划、里程碑清单、周报、风险问题清单。数据更新节奏以周为单位，或随项目里程碑节点触发更新，字段包含项目编号、责任人、任务周期、风险等级等，无统一固定单位，随文档类型灵活适配，由项目经理、实施经理及PMO负责维护。

## 这些特征在「权限与数据隔离」这一环带来什么约束
该品类的数据涉及跨协作方的项目进度、风险信息，需按角色划分访问边界，避免非授权人员接触敏感内容；高频更新的特性要求权限配置可快速同步变更，适配项目进度的动态调整；不同文档的权限粒度差异显著，比如项目计划仅允许PMO修改，周报允许项目经理查看，风险问题清单仅允许核心成员提交；内网部署场景下需适配自定义认证逻辑，同时支持多账号绑定同一团队，避免权限混乱；权限配置错误可能导致进度延期、客户验收受阻等后果，需严格管控访问范围。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配项目实施计划管理的权限与数据隔离需求：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `teamId` | 绑定至具体项目团队，取值为项目备案的唯一标识 | 确保项目专属文档仅对授权团队成员可见，避免跨项目数据泄露 |
| `tmbId` | 为每个文档版本自动生成唯一标识，缺失时自动填充预设默认值 | 解决历史版本同步时字段缺失导致的异常问题，适配应用历史版本云端同步功能 |
| 多账号团队绑定 | 允许最多5个账号绑定同一`teamId` | 适配项目经理多终端协作的实际使用场景，满足跨设备访问需求 |
| SSO对接配置 | 开启企业认证自动同步，配置超时时间为600秒 | 适配内网环境的统一身份认证需求，减少手动配置的工作量 |
| 单团队存储上限 | 设置为1000 MB | 控制单项目数据占用资源规模，避免单团队数据过度膨胀 |
| 权限校验触发 | 每次文档访问时校验`teamId`匹配性 | 拦截跨团队非法访问请求，强化数据隔离能力 |

## 容易做错的三处
- 现象为应用历史版本同步至云端时，MongoDB中较早的历史版本文档无`tmbId`字段，导致数据同步失败。原因是未在版本创建时自动生成`tmbId`，未对存量数据做兼容处理。
- 现象为本地部署后无法创建多账号绑定同一团队，无法实现跨终端协作。原因是未正确配置`teamId`的共享绑定规则，未开启团队账号权限。
- 现象为内网部署后对接依赖服务时，出现数据库连接拒绝报错，日志显示数据库服务正常启动但无法建立连接。原因是未配置正确的内网网络策略，未开放服务间的访问端口。

## 怎么确认配好了
- 创建2个不同账号，绑定同一`teamId`，尝试访问同一份项目计划文档，验证双方均可正常查看与编辑。
- 上传一个无`tmbId`字段的旧版本历史文档，检查数据库中是否自动补全该字段，无异常报错提示。
- 配置SSO对接后，使用企业认证账号登录，验证是否自动匹配到所属项目团队的权限范围。
- 上传单份项目文档，查看系统存储占用提示，确认未超出预设的单团队存储上限。
