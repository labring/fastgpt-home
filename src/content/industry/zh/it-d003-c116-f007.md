# 项目文档移交归档的安全与合规材料审查：对话日志与审计

## 这个品类的数据长什么样
该品类的数据主要来自项目文档库、配置清单、会议纪要、测试报告，更新节奏为项目各阶段交付后或整体项目结束时。日常涉及的文档包括竣工文档、配置手册、培训记录、验收证书，核心字段包含项目唯一标识、文档版本号、签章核验状态、移交归档时间，部分文档附带关联的项目执行过程记录，数据体量随项目规模浮动。

## 这些特征在「对话日志与审计」这一环带来什么约束
该品类的数据分散于多类项目产出物，且更新节奏随项目阶段变化，要求对话日志与审计环节需关联不同来源的文档操作记录。文档包含版本号与签章状态字段，审计需留存版本一致性核对、签章核验的完整对话交互过程。由于数据更新无固定高频节奏，审计触发需匹配项目移交节点，同时需覆盖文档完整性检查环节的全流程日志，确保验收环节可追溯操作依据。

## 配置怎么定
以下配置适用于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 日志留存时长 | 180–365 天 | 匹配项目质保期与合规追溯要求 |
| 单条日志最大存储 | 2000–5000 字符 | 适配项目文档的文本长度范围 |
| 审计触发绑定 | 按`chatId`关联项目编号 | 确保日志与特定项目精准绑定 |
| 异常告警阈值 | 连续3次校验失败 | 及时拦截不合规的移交操作 |
| 日志导出格式 | 结构化 CSV | 适配合规审查的归档与检索需求 |
| 审计查询限定 | 仅检索当前项目的`responseChatItemId` | 缩小范围提升检索效率 |
| 审计详情开关 | 开启`detail`模式 | 留存完整的对话交互细节 |

## 容易做错的三处
- 现象：审计日志仅显示操作结果，未留存完整对话交互过程。原因：未开启`detail`模式，仅记录了极简操作日志，无法回溯校验细节。
- 现象：项目移交时触发`chatId`绑定报错，日志提示无关联项目标识。原因：未在配置中绑定日志与项目编号的关联规则，导致审计无法匹配对应项目。
- 现象：问答对提取任务卡在训练中，调用日志无记录。原因：未配置审计触发的节点联动，任务执行日志未同步至审计模块，导致无法通过日志排查停滞原因。

## 怎么确认配好了
- 手动触发一次文档完整性检查对话，查看日志是否包含完整的交互细节，确认`detail`模式已生效。
- 输入测试项目编号，检索对应`chatId`的审计日志，确认日志与项目精准绑定。
- 触发一次异常校验操作，验证是否会触发预设的异常告警，确认阈值配置正确。
- 尝试导出审计日志，确认导出格式为结构化 CSV，可正常读取。
