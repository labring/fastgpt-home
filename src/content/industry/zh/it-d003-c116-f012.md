# 项目文档移交归档的安全与合规材料审查：文档解析与分块

## 这个品类的数据长什么样
该品类的数据主要来自项目文档库、配置清单、会议纪要、测试报告，更新节奏为每项目阶段结束或整体项目收尾。日常处理的文档包括竣工文档、配置手册、培训记录、验收证书，文档结构包含结构化字段（如项目编号、验收节点）与非结构化业务说明，部分文档会附带标准化签章页。数据由项目经理、实施顾问、客户档案管理员日常维护，单份文档体量随项目规模波动，核心围绕项目交付证据与后续运维支撑展开。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档特征对解析与分块带来多项约束。批量离线处理的任务属性，要求解析工具支持批量上传与批量分块配置。文档类型涵盖结构化清单、非结构化纪要与带签章的验收证书，需针对性配置分块规则，避免拆分破坏结构化字段的关联关系或签章页的完整性。历史归档文档可能存在版本不一致的情况，分块时需保留版本标识的上下文，避免检索时混淆不同版本的内容。单份文档体量随项目规模波动，需适配不同长度的文档解析，避免单块内容过载或过碎影响检索效果。

## 配置怎么定
FastGPT v4.17.0版本下，以下配置项可针对性适配该品类的文档解析需求：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配该品类文档的业务段落长度，避免单块内容过载或过碎 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配该品类文档的结构化章节结构，保留上下文关联 |
| `customPdfParse` | 开启 | 适配带签章的验收证书等复杂PDF文档，提升解析完整性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对大型竣工文档或批量文档的解析耗时需求 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配项目归档文档的单份体量上限 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型调整分块规则，满足合规审查的精准性要求 |

## 容易做错的三处
- 现象：解析大型PDF文档时触发超时报错，日志显示请求耗时超过60000ms。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以处理大型竣工文档的解析任务。
- 现象：检索Excel数据时返回条数少于源文件，例如筛选国外使用地的结果不完整。原因：分块时未保留结构化表格的完整行关联，或未配置针对表格数据的解析规则，导致部分字段被截断或遗漏。
- 现象：批量上传文档后，部分验收证书的签章页解析为空或格式错乱。原因：未开启`customPdfParse`配置，默认PDF解析无法适配带嵌入式签章的归档文档格式。

## 怎么确认配好了
- 上传单份典型文档（如验收证书），查看解析后的分块内容，确认结构化字段与签章页未被错误拆分。
- 调整`chunkSize`参数后，对比不同取值下的分块结果，选择符合业务段落长度的配置。
- 上传大型竣工文档，监控解析耗时，确认`PARSE_FILE_TIMEOUT_SECONDS`参数设置满足实际耗时需求。
- 上传包含表格的配置手册，验证检索时能否返回完整的表格数据字段。
