# CDN与边缘加速配置的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来自CDN控制台、DNS解析记录、用户访问日志与节点监控告警。日常产出的标准化文档包括域名接入单、缓存规则配置单、刷新预热操作记录、故障排查分析报告。数据字段包含域名、缓存规则参数、节点IP、访问峰值、告警触发条件等，更新频率为每日或随配置变更实时同步。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据分散自多类控制台与日志，不同于云网络与负载均衡配置，其面向公网内容分发与缓存，混合检索需整合域名配置、访问日志、告警信息等多源内容。数据更新频率随配置变更实时同步，要求检索链路具备时效性，重排模型需优先匹配最新的缓存规则与接入单内容。日常文档结构包含标准化的参数字段，重排与混合检索需适配不同文档的字段匹配逻辑，优先定位域名备案核对、缓存规则调试这类高耗时环节的相关内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 混合检索召回上限 | 前10-15条 | 适配CDN多源数据的分散特性，避免过多冗余结果干扰重排环节 |
| 重排模型召回阈值 | 0.75-0.85 | 匹配CDN配置文档的专业术语相似度，过滤低相关的日志或告警内容 |
| 检索上下文长度 | 800-1200字符 | 适配缓存规则、接入单这类标准化文档的字段长度，保证检索内容完整 |
| 重排模型调用超时 | 600秒 | 适配离线部署或跨节点调用的延迟情况，避免因超时中断检索流程 |
| 多源数据合并规则 | 按文档类型分组 | 区分接入单、缓存规则、日志类数据，便于重排时按业务优先级排序 |

## 容易做错的三处
- 现象：应用端开启重排模型后无检索结果，但知识库测试环节结果正常。原因：未配置多源数据的跨文档关联映射，导致应用检索时无法整合CDN控制台数据与知识库内容。
- 现象：升级FastGPT版本后离线部署的重排模型配置失败，模型测试提示请求错误。原因：离线部署的模型文件未同步更新至对应版本的依赖目录，或端口映射配置未适配新版本的API路径。
- 现象：重排模型调用超时或返回空结果。原因：未调整重排模型调用超时阈值，未适配CDN多源数据的检索量导致模型负载过高。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型测试页面，选择配置的重排模型，输入CDN缓存规则相关的测试文本，验证模型返回结果的排序优先级符合预期。
- 上传一份域名接入单文档至知识库，检索“域名备案核对步骤”，确认检索结果优先返回对应文档的核心内容。
- 模拟应用端的检索请求，调用配置好的混合检索与重排链路，检查返回结果的条数与排序逻辑符合预设配置。
- 查看FastGPT的系统日志，确认重排模型的调用请求无报错，响应时长符合预设阈值。
