# IT服务台工单处理的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源于企业ITSM系统、电话或在线聊天记录、资产系统及内部知识库。数据更新频率为日级或实时，随工单提交、处理进度更新即时同步。日常生成的文档包含服务请求单、事件工单、处理记录与用户满意度表，字段涵盖工单编号、问题描述、分类标签、处理状态、响应时长与满意度评分，未使用非标准自定义单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据来源分散且更新节奏多样，要求多轮对话环节需精准关联工单编号、处理状态等字段，避免上下文混淆。实时更新的工单数据要求对话上下文需限制历史消息长度，防止冗余信息干扰当前处理流程。服务请求单、事件工单等标准化文档结构，要求提示词需预设固定的分类、派单规则，辅助对话自动完成问题归类。同时，由于数据包含用户聊天记录，多轮对话需保留原始诉求上下文，减少重复提问，适配问题分类、远程排障等耗时环节的处理需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` 参数 | 绑定当前工单的唯一标识 | 确保对话上下文与指定工单强关联，避免跨工单混淆 |
| `messages` 参数 | 仅保留近3轮对话内容 | 过滤历史冗余数据，聚焦当前工单的最新诉求 |
| `variables` 变量配置 | 预设工单编号、用户ID字段 | 辅助对话自动关联对应工单的处理记录 |
| 最大上下文长度 | 前1000–1500 字符 | 适配本品类工单文档的单条标准长度 |
| 知识库关联配置 | 绑定ITSM系统、聊天记录知识库 | 匹配本品类多源数据来源的业务特征 |
| 问题分类触发阈值 | 按实测标定 | 适配本品类的问题分类复杂度，平衡准确率与处理效率 |

## 容易做错的三处
- 调用关联知识库的接口后无匹配结果，日志显示未正确绑定数据源。原因是未在配置中指定对应ITSM系统或聊天记录的知识库关联规则，导致对话无法调取品类专属数据。
- 尝试通过API创建工作流时返回未定义接口错误。原因是当前版本仅开放对话、知识库相关API，未提供工作流创建的直接接口，需通过现有配置项组合实现。
- 部署后调用模型报错，第三方日志显示令牌字段值为“fastgpt”。原因是令牌配置环节未正确替换为目标模型的有效令牌，导致系统使用默认占位符发起请求。

## 怎么确认配好了
- 发起测试对话，输入模拟工单问题，核对对话上下文是否自动关联预设的`variables`字段内容。
- 调用知识库关联接口，验证是否能调取ITSM系统或聊天记录中的对应工单数据。
- 查看系统日志，确认`messages`参数仅保留指定轮次的历史对话内容，无冗余信息。
- 提交模拟工单处理请求，核对提示词是否自动触发预设的分类规则，生成符合业务文档格式的处理建议。
