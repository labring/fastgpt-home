# IT采购与供应商管理的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自采购系统、供应商报价文件、预算表与合同系统。日常处理的文档包含采购申请单、比价记录、正式合同与验收单据，字段通常包含采购编号、供应商全称、预算额度、条款明细与交付周期。数据更新以每笔采购订单为单位，单笔订单从需求发起至验收完成期间会逐步生成对应文档，月度会汇总当期所有采购的归档数据。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散的特点要求多轮对话需明确关联对应采购订单的专属标识，避免跨订单的采购申请、合同等信息混淆。更新以单笔订单为单位的规则，要求对话上下文绑定对应订单的唯一标识，确保每轮交互仅调用该订单的关联数据。文档包含合同条款等严谨内容，提示词需限定输出格式，同时需控制上下文长度，防止超出处理上限导致关键信息截断。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前采购订单的唯一标识 | 确保多轮对话仅关联对应订单的采购申请、合同等数据，避免跨订单信息混淆 |
| 最大上下文 | 800–1200 字符 | 该品类文档多包含长条款文本，该区间可覆盖单订单核心文档的关键内容，防止上下文溢出 |
| 问题优化 | 开启，按实测标定 | 售前答疑常涉及模糊的采购需求，优化后可更精准匹配供应商报价与预算数据 |
| 单次召回上限 | 前 6 条 | 单笔采购的关联文档数量有限，召回过多会增加处理负担，过少则可能遗漏关键比价记录 |
| `variables` | 注入当前订单的采购编号、预算额度 | 让提示词可直接调用订单专属字段，无需重复询问用户已知信息 |
| 对话历史保留时长 | 30 天 | 匹配该品类月度归档的更新节奏，避免存储过多过期数据 |
| `messages` | 按对话轮次追加最新交互内容 | 保留售前答疑的历史沟通上下文，确保多轮对话的逻辑连贯性 |

## 容易做错的三处
- 现象：调用工作流后，对话日志中的运行数据为空。原因：未通过`chatId`绑定对应采购订单的专属数据，导致系统无法匹配到关联的采购申请、合同等文档，无法生成运行数据。
- 现象：在文本内容提取模块的提示词中使用`any`参数提取代码块，完整响应显示代码块为`undefined`。原因：未通过`variables`注入对应采购合同的代码块字段，提示词无法定位到目标提取内容，导致返回空值。
- 现象：用户删除单轮对话后，整条对话日志同步消失。原因：未配置对话上下文的独立存储规则，系统默认绑定`chatId`的关联数据被同步删除，导致订单专属对话记录丢失。

## 怎么确认配好了
- 发起一笔模拟采购订单的售前答疑，检查对话上下文是否仅显示该订单的关联文档内容。
- 查看对话日志，确认运行数据包含当前订单的采购编号、预算额度等专属字段。
- 测试删除单轮对话，验证剩余对话内容仍保留该订单的关联信息，未出现整体丢失。
- 输入模糊的采购需求，确认系统自动优化后的问题可精准匹配供应商报价数据。
