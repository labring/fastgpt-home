# Issue分拣与响应的客户技术支持与售前答疑：知识库检索与召回

本文适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据主要来源于GitHub或Gitee Issue、版本日志、用户环境信息与代码仓库。日常维护的文档包括Issue模板、标签规则、回复记录与问题复现说明。数据更新频率为日或周，由社区运营或核心贡献者定期同步最新的Issue与回复内容。数据字段包含问题标题、报错信息、复现步骤、责任模块与优先级标签，无统一固定格式，部分内容包含代码块与多语言混杂文本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据来源分散且格式多样，检索环节需适配多类型文本与代码块，避免因格式差异导致召回失效。数据更新频率为日或周，要求知识库支持增量同步与定时更新，确保召回内容匹配最新的Issue模板与标签规则。数据字段无统一格式，需通过语义与关键词双重匹配提升分类准确性，减少人工补全复现信息的耗时。若召回结果偏差，会直接导致问题分类错误，延长问题处理周期，引发用户流失与缺陷定位延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75-0.85 | 适配Issue的问题描述特征，平衡召回准确率与覆盖范围，可按实测标定调整 |
| `limit` | 前8-12条 | 控制检索结果的上下文长度，避免过多无关内容干扰问题分类，同时覆盖常见Issue场景 |
| `searchMode` | `keyword+vector`混合模式 | 适配Issue中同时包含关键词（如报错码、模块名）与语义化描述的特征 |
| `usingReRank` | 开启 | 过滤低相关的召回结果，提升Issue分类的准确性，减少人工筛选成本 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充用户环境、版本信息等上下文，匹配更精准的Issue复现与回复文档 |
| `collectionIds` | 绑定Issue模板、标签规则对应的知识库集合 | 限定召回范围，避免无关文档干扰Issue分拣与响应流程 |

## 容易做错的三处
- 现象：检索响应耗时超过10秒，结果条数不足预期。原因：`limit`取值超过15条且未开启`usingReRank`，导致检索资源占用过高，返回结果被截断。
- 现象：知识库中上传的中文文件名显示为乱码。原因：未在API请求头中指定正确的字符编码参数，导致文件元信息解析错误。
- 现象：召回结果包含大量非Issue相关的通用文档。原因：未配置`collectionIds`绑定品类专属知识库集合，导致检索范围覆盖了无关内容。

## 怎么确认配好了
- 检查`collectionIds`是否绑定了Issue模板、标签规则对应的知识库集合，确保召回范围仅限品类专属文档。
- 输入常见Issue关键词发起测试检索，验证`similarity`取值下的召回结果是否覆盖核心问题分类场景。
- 开启`usingReRank`后，核对检索结果的排序是否符合问题相关性的优先级逻辑。
- 模拟高频检索请求，确认响应耗时符合业务处理的预期节奏。
