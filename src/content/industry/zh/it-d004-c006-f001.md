# Pull Request评审的客户技术支持与售前答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
Pull Request评审的数据通常来自代码仓库、CI流水线、关联Issue链接与贡献者提交内容。日常产出的文档包含PR说明、代码评审意见、CI执行结果与合并记录。数据更新节奏以日或周为周期，由代码提交、CI触发或合并操作驱动。数据字段包含变更代码块、评审意见、测试状态、关联任务标识等，无统一固定格式，随仓库配置调整。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于PR评审数据分散于代码仓库、CI流水线等多源系统，HTTP接口需支持跨系统数据拉取与权限校验，适配不同平台的认证规则。数据更新周期与代码提交、合并动作绑定，接口调用频率需匹配业务节奏，避免过度请求触发限流。数据包含代码块、评审意见等非结构化内容，接口需支持大体积请求体或分块传输。同时，PR评审的合并冲突、CI结果等状态需通过接口同步，接口需返回标准化的状态字段以支撑后续处理。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 文件上传开关 | 开启，单文件上限设为1000 MB | 支持PR关联的测试报告、日志文件上传 |
| 历史记录优化 | 开启，保留前3轮对话 | 解决指代消除问题，适配上下文关联的代码变更意图 |
| 单次请求超时时间 | 60–120 秒 | 匹配代码仓库数据拉取、CI结果同步的常规耗时 |
| 最大上下文长度 | 8000–12000 字符 | 承载PR说明、代码评审意见等长文本内容 |
| `responseData`字段过滤 | 保留代码变更、评审状态字段 | 精准提取PR评审所需的核心数据 |
| `variables`全局配置 | 绑定仓库访问密钥 | 统一管理跨接口的认证信息 |

## 容易做错的三处
- 调用对话接口时无法上传PR关联的文件，仅前端界面支持上传。原因：未在HTTP接口配置中开启文件上传开关，或未设置正确的文件大小上限。
- 搜索结果未关联历史对话，无法解决指代消除问题。原因：未开启历史记录优化配置，或历史记录窗口设置过小。
- 接口请求返回配置错误提示，提示重复配置模型相关参数。原因：在`config.json`与外部系统认证配置中重复添加了模型相关参数，导致参数冲突。

## 怎么确认配好了
- 发起包含测试文件的POST请求，检查接口返回的`responseData`中是否包含文件上传成功的标识。
- 输入包含指代内容的问题，例如“查看上次的变更”，检查返回结果是否关联了历史对话中的PR信息。
- 查看接口日志，确认`Authorization`认证头已正确携带，无401或403权限错误。
- 等待60秒后发起请求，确认接口未触发超时错误，返回正常的PR评审数据。
