# Pull Request评审的客户技术支持与售前答疑：分享与嵌入

## 这个品类的数据长什么样
Pull Request评审的核心数据来源于代码仓库、CI流水线、Issue链接与贡献者提交记录。日常关联文档包括PR说明文档、代码评审意见、CI执行结果与合并状态记录。数据更新频率通常为日或周，随代码变更与评审进度同步更新。数据字段包含PR编号、变更文件列表、评审状态、CI通过率、关联Issue编号与合并时间等，无统一固定的单位要求，仅随具体评审内容匹配对应格式。

## 这些特征在「分享与嵌入」这一环带来什么约束
由于PR评审数据关联未合并的代码变更与敏感评审信息，分享与嵌入环节需严格控制访问权限，避免泄露未公开的代码内容。数据更新频率测试示例为日或周，分享链接的缓存与有效期需适配常见代码评审周期，避免过期导致的信息滞后。PR评审的文档结构包含代码片段与CI日志，嵌入界面需适配技术文档的排版格式，保证内容完整展示。同时，数据来源分散于代码仓库与CI流水线，需通过FastGPT商业版身份验证对接外部项目权限系统，确保访问权限与项目权限一致，避免越权访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分享入口 `shareId` | 复制系统生成的完整分享链接，不自行替换标识 | 标识分享入口；Pull Request评审业务记录与数据权限仍需由外部系统处理 |
| 分享链接有效期 | 测试起点：7 天；按Pull Request评审协作周期和撤销要求实测调整 | 验证有效期内可用及到期后的访问行为，该值不是官方默认或行业统计 |
| QPM | 测试起点：每用户每分钟 20 次；按实际负载调整 | 限制单个用户的访问频率，需要结合请求日志与实际负载验证 |
| 身份验证 | 有身份权限要求时，先核对商业版能力及第三方身份服务返回的 uid | 持有分享链接不等于具备业务数据权限；第三方身份与数据范围需分别核验 |
| 引用内容展示 | 按Pull Request评审资料敏感程度选择引用片段、全文及原文的展示配置 | 在已授权数据范围内检查展示内容，不能用隐藏界面替代数据权限控制 |
| 对话记录验证 | 测试示例：准备 10 条Pull Request评审问答样本，分别在同一浏览器和另一设备检查 | 匿名记录依赖浏览器本地身份，跨设备或清理缓存后不能保证保留 |

## 容易做错的三处
- Pull Request评审相关分享入口打开失败。先核对系统生成的完整链接及其有效期，再对照浏览器请求状态；不得自行替换 `shareId`。
- Pull Request评审数据的可见范围与预期不符。分别核对第三方身份验证结果、工作流请求参数和外部系统的数据权限；分享入口标识本身不提供业务授权。
- 同一Pull Request评审问答在另一设备上看不到原对话。匿名场景先核对设备、浏览器及本地身份状态；跨设备或清除缓存后不能保证保留记录，不能单凭该现象判断服务异常。

## 怎么确认配好了
- 复制FastGPT免登录窗口生成的分享链接或嵌入代码，部署至测试页面，打开后检查界面语言为简体中文。
- 尝试使用未通过FastGPT商业版身份验证的账号访问嵌入页面，验证无法查看外部PR评审相关的文档与数据。
- 调整嵌入容器的高度参数，确认所有外部PR说明、评审意见与CI结果均可完整显示，无内容溢出或滚动异常。
- 验证分享链接在配置的有效期内可正常访问，过期后无法访问，或根据实际评审周期调整有效期参数。
