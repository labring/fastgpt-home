# SLA与服务报告的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源为监控系统、工单系统、合同文本与客户沟通记录，更新节奏为月度或季度。日常产出文档包含SLA条款、月度服务报告、可用性统计报表与客户复盘纪要，数据字段涵盖服务周期范围、SLA达标率指标、异常事件分类、客户反馈记录等，数据体量随服务客户数量与统计维度调整，无固定统一的单条数据长度。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征对知识库检索与召回带来多重约束。首先，月度或季度的更新节奏，无需配置高频实时索引同步，可按更新周期批量刷新向量库，降低运维成本。其次，多源异构的数据来源，需支持兼容合同文本、工单记录、监控日志等不同格式的文档导入，检索时需适配多字段的语义匹配逻辑。另外，数据包含SLA条款、服务指标等专业术语，召回时需优先匹配与服务报告、SLA合规相关的语义，避免无关内容干扰结果。最后，数据体量随服务客户数量变化，需合理配置检索参数以平衡召回精度与响应速度。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配SLA相关的专业术语，过滤低相关性的非服务类内容 |
| `limit` | 前3–5条 | 控制召回结果数量，适配月度服务报告的汇总统计需求，避免过多冗余数据 |
| `searchMode` | semantic | 优先匹配语义关联的SLA条款与服务记录，适配专业术语检索场景 |
| `usingReRank` | 开启 | 对初始召回结果进行二次排序，提升SLA相关内容的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于原始查询生成扩展语义，覆盖SLA相关的同义表述，提升召回覆盖度 |
| `collectionIds` | 按目标知识库集合指定 | 限定检索范围仅为SLA与服务报告相关的知识库集合，避免无关数据干扰 |

## 容易做错的三处
- 现象：检索返回结果与知识库引用完全无关，答案未命中知识库内的SLA或服务报告相关内容。原因：未配置`similarity`阈值或阈值设置过低，导致低相关性内容被优先召回。
- 现象：知识库检索耗时超过30秒，无法按时完成服务报告生成。原因：未限制`limit`参数，召回过多冗余数据导致向量匹配与排序耗时增加。
- 现象：导出的知识库数据集缺失content字段或索引与内容关联错误。原因：未正确配置知识库集合的索引映射规则，导致数据导出时字段未正确关联。

## 怎么确认配好了
- 执行一次测试检索，输入SLA条款或服务报告相关的查询，核对返回结果是否包含知识库中对应的内容。
- 查看检索耗时，根据实际服务报告生成的时间要求，调整参数取值以符合需求。
- 检查召回结果的引用来源，确认所有结果均来自配置的目标知识库集合。
- 导出测试用的知识库数据集，核对index与content字段是否正确关联。
