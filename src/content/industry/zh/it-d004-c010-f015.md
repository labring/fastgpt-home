# 事件响应与故障处理的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据主要来自监控告警、日志平台、APM工具及用户反馈，日常文档包含故障工单、事件时间线、应急预案、故障通报。数据更新节奏为实时或每次事件发生后同步，文档结构以结构化字段为主，包含事件标识、影响范围、发生时间、止损操作记录等，仅保留事件全流程的原始记录与处置内容，无额外自定义统计字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据来源包含实时监控与用户反馈，检索需支持动态更新的数据集接入，避免召回过时的处置方案。文档结构包含事件标识、影响范围等特定字段，检索需匹配对应字段以精准定位相关故障工单与应急预案。实时更新的特性要求召回结果需与当前事件状态同步，无法依赖静态缓存数据。同时，该品类核心耗时环节依赖精准的处置参考，检索需优先返回与当前故障影响范围、止损操作强相关的内容，避免冗余结果干扰决策。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配事件响应与故障处理场景的知识库检索需求。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 匹配该品类故障处置文档的语义相关性要求，避免召回无关的历史事件记录，保障处置参考的精准性 |
| `limit` | 前3–5条 | 该品类需快速获取核心处置参考，过多结果会增加决策负担 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配故障工单中既有明确标识又有语义关联的内容 |
| `usingReRank` | 开启 | 对初步召回结果二次排序，优先返回与当前故障影响范围匹配度更高的预案 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户提问自动扩展相关故障处置关键词，覆盖运维人员可能的模糊提问 |
| `collectionIds` | 对应故障知识库的专属集合ID | 隔离业务数据，避免检索到非运维场景的文档 |

## 容易做错的三处
- 现象：配置了指定嵌入模型与知识库参数后，检索返回“无可匹配结果”报错。原因：未将目标故障知识库的`collectionIds`填入对应配置项，或嵌入模型配置未关联至故障知识库专属数据集，导致检索范围未覆盖业务专属数据。
- 现象：知识库引用的第一条内容正确，但未在回答正文中展示。原因：未开启`datasetSearchUsingExtensionQuery`，无法将引用内容与提问语义关联，导致生成回答时未整合引用内容。
- 现象：通过API发起对话后，生成的回复未包含知识库文档内容。原因：未在请求参数中指定关联的`collectionIds`，或未将`searchMode`设置为hybrid，无法召回相关知识库内容。

## 怎么确认配好了
- 登录FastGPT管理后台，核对知识库配置项中的`collectionIds`是否与目标故障知识库的集合标识一致。
- 提交一条与当前运维场景相关的测试提问，查看检索返回的结果数量是否匹配`limit`配置的设定。
- 开启检索调试日志，确认`similarity`阈值、`usingReRank`开关等参数被正确加载。
- 调用官方API接口发起对话，验证返回结果中是否包含配置范围内的知识库文档内容。
