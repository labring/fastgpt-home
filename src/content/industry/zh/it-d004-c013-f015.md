# 云账单与成本核算的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自云计费系统、标签数据、订单系统与资源监控工具。日常产出的文档包含账单明细、成本分摊表、资源利用率报表、优化建议单，字段涵盖资源标识、计费周期、实际费用、标签键值、分摊比例等，单位多为元、GB、小时等。数据更新频率通常为日度或月度，部分高频资源监控场景下会按小时同步最新数据。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据多系统来源导致字段维度分散，检索时需精准匹配资源标识、标签键值等关联字段，避免无关资源的费用数据混入结果。不同文档的更新频率存在差异，要求召回逻辑区分日度资源监控数据与月度账单数据的展示优先级，优先返回最新的有效数据。明细类文档的长文本结构，需要合理控制分块与召回范围，以保留费用分摊、异常标注等关键关联信息。同时，异常费用排查与成本解释的业务需求，要求召回结果具备高置信度，避免遗漏可能引发客户争议的费用条目。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 云账单数据的字段关联性强，阈值过低会引入无关资源的费用数据，过高则可能遗漏匹配的异常账单条目 |
| `limit` | 前20条 | 单条云账单明细包含多维度字段，过多召回结果会超出上下文窗口，过少则无法覆盖全部分摊逻辑 |
| `usingReRank` | 开启 | 云账单的标签与费用关联逻辑复杂，重排模型可过滤低相关性的分摊表条目，提升售前答疑的准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 客户咨询常包含模糊表述，如“某服务器的上月费用”，通过扩展查询可关联标签与资源ID，匹配对应账单文档 |
| `searchMode` | 向量检索+关键词混合 | 同时覆盖精确的资源ID匹配与模糊的费用描述检索，适配技术支持与售前的不同提问场景 |
| `collectionIds` | 按业务线分组配置 | 云账单数据按业务线隔离，指定集合ID可避免跨业务线的无关数据被召回 |

## 容易做错的三处
- 现象：界面开启`usingReRank`与知识库索引重排开关后，在线召回测试结果未体现重排排序变化。原因：未在大模型调用环节同步开启重排调用，仅配置索引阶段的重排无法生效。
- 现象：配置`limit`取值为3000后，在线测试时大模型未接收到上下文内容。原因：系统对单次召回的上下文总token数存在隐含限制，3000条明细数据的总token数超出窗口上限，导致上下文被自动清空。
- 现象：设置分块重复率参数后，知识库检索结果仍出现重复的账单明细条目。原因：未针对云账单的长文本分块配置合理的重叠长度，导致相邻分块的重复率计算逻辑未匹配明细类文档的结构。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库在线测试界面，输入包含具体资源ID的咨询语句，核对返回结果是否包含对应账单明细文档。
- 开启`usingReRank`开关后，对比开启前后的检索结果排序，确认高相关性的成本分摊表条目优先展示。
- 调整`similarity`阈值，观察检索结果的匹配精度，确认阈值符合当前业务场景的需求。
- 查看检索日志，确认`datasetSearchUsingExtensionQuery`已生效，扩展后的查询词已关联到标签与资源ID字段。
