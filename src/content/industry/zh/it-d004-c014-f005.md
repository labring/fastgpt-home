# 云资源合规审计的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据主要来自云审计日志、IAM权限系统、CMDB资源清单、安全基线扫描结果。更新节奏为月度或季度，日常产出的文档包含合规检查表、权限审计报告、资源清单、整改跟踪表。文档字段包含资源标识、权限配置项、合规校验结果、整改进度等，无统一固定单位，随具体资源类型与合规项变化。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新节奏较慢的特征，要求多轮对话中需明确提示词区分不同数据源的字段与使用场景，避免混淆云审计日志、IAM权限数据与CMDB资源信息。日常文档类型多样，提示词需指定不同文档的调用优先级，例如优先调用权限审计报告中的异常项，同时参考单次安全基线扫描结果。同时，由于合规审计出错后果明确，多轮对话需保留`variables`中的历史审计范围与合规项配置，确保上下文一致性，避免重复校验或遗漏关键项。另外，需限制对话中对非当前更新周期内的数据进行引用，防止使用过期信息。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 上下文窗口大小 | 前8000–12000 token | 合规审计相关文档包含多份报告与资源清单，较长上下文可完整保留历史校验范围与异常项 |
| 历史变量加载配置 | 开启并绑定`variables` | 需在新对话中复用之前保存的审计范围、合规检查表版本等全局变量，确保校验一致性 |
| 多轮上下文拼接规则 | 按`messages`顺序拼接 | 需按对话时序保留用户的合规审计需求与AI的校验结果，避免上下文错乱 |
| 提示词模板配置 | 固定包含数据源说明 | 明确提示调用云审计日志、IAM数据等来源的字段，避免混淆不同类型的合规数据 |
| 对话超时阈值 | 600秒 | 合规审计数据整合需遍历多份文档，较长超时可避免因数据加载中断导致对话失败 |

## 容易做错的三处
- 现象：在新对话中调用历史全局变量时，变量为空或未加载。原因：未在工作流节点中配置变量绑定规则，或未指定历史会话的`chatId`参数，导致无法关联之前保存的审计范围配置。
- 现象：添加数据库工具调用时返回400 status code (no body)。原因：提示词中未明确指定数据库查询的合规数据范围，或未限制查询字段为合规审计所需的权限、资源配置项，导致无效请求被拦截。
- 现象：多轮对话中出现合规校验结果不一致。原因：未按对话时序拼接`messages`上下文，导致AI混淆不同轮次的审计需求与校验规则，出现重复校验或遗漏异常项。

## 怎么确认配好了
- 发起一次新的合规审计对话，输入历史会话中使用过的审计范围关键词，检查是否能正确加载之前保存的全局变量。
- 配置数据库工具调用后，执行一次测试查询，确认返回结果包含合规审计所需的资源与权限字段，无400状态码报错。
- 连续发起多轮对话，逐步添加不同的合规校验需求，检查AI是否能按对话时序保留上下文，不重复或遗漏校验项。
- 查看对话日志，确认`messages`与`variables`参数均被正确传递，无缺失或格式错误。
