# 云资源合规审计的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自云审计日志、IAM权限系统、CMDB资源清单、安全基线扫描结果。日常产出的文档包括合规检查表、权限审计报告、资源盘点清单、整改跟踪表，数据更新周期为月或季度。文档字段包含资源ID、权限配置项、合规状态、整改责任人、扫描时间等，无统一单位，部分字段需关联多系统数据生成，整体为结构化与半结构化混合格式，核心围绕合规校验相关属性展开。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类数据分散来自多系统，检索需关联跨源字段，对召回的字段匹配精度要求更高。月或季度的更新频率意味着知识库无需高频增量同步，但单次导入的全量资源清单等文档条目较多，需适配长文档的分段规则。合规类文档的属性关联性强，检索需精准匹配权限配置、合规状态等核心字段，避免无关结果干扰。整改跟踪表需关联最新扫描数据，需限定召回数据的时间范围，确保结果与当前合规状态一致。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配合规类文档的精准匹配需求，过滤低相关性的权限或配置项结果 |
| `limit` | 前8–12条 | 资源清单类文档条目较多，控制召回数量避免上下文溢出，同时覆盖足够的合规校验维度 |
| `searchMode` | vector + keyword | 结合向量语义匹配与关键词匹配，兼顾权限配置项等结构化字段的精准召回与合规描述的语义匹配 |
| `usingReRank` | 开启 | 对召回结果进行重排，优先返回与合规问题关联度更高的整改跟踪表或权限审计报告 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展用户的合规相关问题，覆盖更多同类型合规文档 |
| `collectionIds` | 按合规文档集合指定 | 仅检索云资源合规审计相关的知识库集合，避免混入其他品类的文档干扰结果 |

## 容易做错的三处
- 调用知识库检索接口返回未授权错误，已配置API key仍提示无权限。原因是未将云资源合规审计专属的知识库集合绑定到对应API key，或`collectionIds`配置错误导致检索范围无效。
- 检索结果混入大量非合规类文档，核心字段如合规状态为空。原因是未指定`collectionIds`，检索了无关的知识库集合，导致结果偏离合规审计场景。
- 针对word格式的合规检查表检索时，无法匹配目录对应的检查项。原因是未按word文档的目录结构进行分段，导致目录层级与具体合规项无法关联，语义匹配失效。

## 怎么确认配好了
- 在FastGPT v4.17.0的知识库配置页面，查看`collectionIds`仅包含云资源合规审计相关的文档集合。
- 发起一条测试查询，如「检查当前IAM权限配置是否合规」，核对返回结果的字段是否包含资源ID、权限配置项、合规状态等合规相关属性。
- 查看检索配置的`similarity`阈值，确认取值在0.75–0.85区间内，可通过调整后对比检索结果的相关性。
- 开启`usingReRank`后，核对重排后的结果是否优先返回整改跟踪表或权限审计报告等核心合规文档。
