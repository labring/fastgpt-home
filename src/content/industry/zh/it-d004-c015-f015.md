# 产品使用数据分析的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据主要来源于埋点系统、数据仓库、CRM、工单系统，更新频率为日或周。日常产出的文档包含使用分析报告、埋点方案、指标口径表、看板需求单，文档以结构化字段组合为主，包含指标名称、事件编码、统计口径、业务释义等字段，单位多为次、人次、百分比等业务通用单位。数据关联的核心主体为产品运营、数据分析师与客户成功运营，内容围绕产品功能使用与客户行为展开，核心解决指标口径统一、异常数据排查等业务问题。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据来源分散且关联多类业务系统，要求知识库检索需限定在产品运营专属的数据集范围内，避免混入客户工单、销售数据等无关内容。文档以结构化指标与口径说明为主，要求检索需精准匹配指标名称、业务释义等核心字段，不能仅依赖字面关键词匹配。数据更新频率为日或周，要求召回结果需关联最新的口径表与埋点方案，避免使用过期的指标定义。此外，该品类的用户问题常涉及指标别名与自定义口径，要求检索需支持扩展查询以覆盖更多相关的口径说明文档，提升检索的覆盖范围与准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 产品使用数据的指标口径文档需要较高匹配度，避免无关的埋点描述或业务释义混入结果 |
| `limit` | 前8–12条 | 该品类的文档多为结构化指标说明，单条内容较短，过多结果会增加上下文处理负担 |
| `usingReRank` | 开启 | 产品使用数据的关联关系复杂，重排模型可过滤掉仅字面匹配但逻辑无关的结果，比如混淆不同业务线的埋点指标 |
| `datasetSearchUsingExtensionQuery` | 开启 | 该品类的用户问题常包含指标别名或自定义口径，扩展查询可覆盖更多相关的口径说明文档 |
| `searchMode` | hybrid | 结合语义匹配与关键词匹配，精准召回包含指标名称与业务释义的文档，适配该品类结构化文档的检索需求 |
| `collectionIds` | 传入产品使用分析专属知识库的集合ID | 限定检索范围，避免混入其他类别的业务文档 |

## 容易做错的三处
- 现象：调用API时，`usingReRank`参数已配置为开启，但返回结果中重排结果字段为false。原因：未绑定重排模型的部署权限到对应知识库集合，或重排模型的部署地址未在FastGPT平台完成配置。
- 现象：在线聊天与API调用的检索结果差异显著，在线聊天正确率更高。原因：在线聊天默认开启了`datasetSearchUsingExtensionQuery`与`usingReRank`，而API调用未显式配置对应参数，导致检索范围与匹配逻辑不一致。
- 现象：检索结果包含大量无关的客户工单内容，未匹配到目标指标口径文档。原因：`collectionIds`参数未限定为产品使用分析专属的知识库集合，混入了其他业务类别的文档，扩大了检索范围。

## 怎么确认配好了
- 查看FastGPT v4.17.0的知识库配置页面，确认`collectionIds`参数仅包含产品使用分析相关的数据集。
- 发起包含指标别名的测试查询，确认开启`datasetSearchUsingExtensionQuery`后，能召回对应的指标口径说明文档。
- 调用API并传入`usingReRank`为true，检查返回结果中是否包含重排后的排序字段，且排序符合业务逻辑，比如将最相关的指标口径文档排在前列。
- 对比在线聊天与API调用的检索结果，在配置一致的前提下，两者的结果差异应处于合理范围，无显著偏差。
