# 代码安全审计的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
代码安全审计的数据通常来自源代码仓库、依赖清单、静态代码扫描工具与公开漏洞库，随项目每版本或每迭代周期更新。日常产出的文档包含代码审计报告、漏洞证明材料、修复建议文档与复测记录，数据字段通常包含漏洞定位信息、风险等级标注、关联代码片段、修复方案与验证结果，无统一强制格式，随服务商或团队需求调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于代码安全审计数据随项目版本迭代更新，多轮对话需支持动态加载对应项目的审计文档，避免上下文混杂不同版本的漏洞信息。数据来源包含人工审查的业务逻辑与攻击路径，提示词需明确区分静态扫描结果与人工复核结论，防止混淆风险等级判定。日常文档结构不统一，提示词需兼容多种格式的审计报告、修复建议等内容，需配置通用的文档解析适配规则。同时，对话需关联复测记录，确保每轮答疑可追溯漏洞修复的验证状态，避免重复解答同一问题。

## 配置怎么定
本配置适用于FastGPT v4.17.0。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定项目唯一标识 | 区分不同项目的审计对话上下文，避免跨项目数据混淆 |
| `messages` | 按项目版本过滤历史消息 | 确保多轮对话仅加载当前版本的审计文档与答疑记录 |
| `variables` | 传入当前项目的审计文档路径 | 动态加载对应项目的代码审计报告、复测记录等数据 |
| 上下文窗口大小 | 8000–12000 token | 适配代码审计文档的长文本内容，避免截断关键漏洞信息 |
| 历史对话召回上限 | 前10条 | 控制上下文冗余，聚焦最近的答疑与审计数据 |
| 代码片段匹配阈值 | 0.7–0.9 | 适配代码安全审计场景下的漏洞代码片段识别精度 |

## 容易做错的三处
- 现象：调用接口后对话日志中的运行数据字段为空。原因：未在`variables`中传入当前项目的代码审计数据源路径，系统无法加载对应项目的审计文档与运行记录。
- 现象：向文本内容提取模块传入any参数提取代码块时，完整响应提示代码块为undefined。原因：提示词未明确限定代码块的提取规则，未适配代码安全审计场景下的漏洞代码片段格式。
- 现象：手动删除单条对话记录后，关联的日志数据同步消失。原因：对话与日志的绑定逻辑未按`chatId`做项目级隔离，误删操作波及同一项目下的全部关联数据。

## 怎么确认配好了
- 发起一次测试对话，输入当前项目的审计文档关键词，核对对话上下文是否仅加载当前版本的审计数据。
- 查看`messages`参数的过滤逻辑，确认历史消息仅保留当前项目的答疑与审计记录，无跨项目数据混入。
- 触发代码块提取操作，核对响应中是否能正确识别审计文档内的漏洞代码片段，无undefined提示。
- 手动删除一条测试对话，确认仅目标对话记录被删除，其余项目的对话与日志未受影响。
