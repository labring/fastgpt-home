# 众包标注人员管理的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据通常来自众包平台、标注质量数据、培训考试记录与财务系统。日常维护的文档包含人员准入规则、标注培训材料、绩效统计表格与结算清单。数据更新节奏多为每日或月度，覆盖人员资质、标注质量、考核结果与结算明细等字段。不同于文本标注项目，该品类关注人力组织与绩效结算，无统一固定单位，随文档类型变化，如绩效表含工号、结算额等字段，培训材料含操作步骤文本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
人员准入规则、培训材料多为长文本，需适配长片段检索以完整覆盖关键内容；结算清单与绩效表含结构化字段，检索需兼顾文本语义与数值关联，避免混淆不同人员的信息；数据按日或月度更新，需定期同步知识库增量内容，防止召回过时的结算或绩效数据；不同文档的字段差异较大，需避免跨文档的无效召回，确保检索结果聚焦目标文档类型；标注质量数据关联人员绩效，检索结果需精准匹配人员ID与质量指标，防止出现张冠李戴的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.72–0.80` | 适配众包标注文档的长文本特征，过滤低相关召回结果，避免混入非目标人员的规则内容 |
| `limit` | `前 8 条` | 平衡检索效率与召回覆盖，满足绩效表、结算清单的多条目检索需求 |
| `searchMode` | `vector` | 针对长文本培训材料与规则文档，优先使用向量检索保证语义匹配精度 |
| `usingReRank` | `开启` | 对结算清单的结构化字段进行重排，提升精准匹配结算额、工号的结果排序 |
| `datasetSearchUsingExtensionQuery` | `关闭` | 避免对人员准入规则这类固定文档生成扩展查询，防止引入无关的标注项目内容 |
| `collectionIds` | `指定目标文档集合的ID数组` | 限定检索范围仅为人员准入规则、绩效表等品类专属文档，避免混入无关数据 |

## 容易做错的三处
- 现象：配置`datasetSearchUsingExtensionQuery`时出现Invalid array length报错。原因：未正确指定`collectionIds`的数组格式，传入空数组或非数组类型参数。
- 现象：调试预览可正常检索知识库，部署到自有页面后无法触发搜索。原因：未在自有页面正确传递用户问题参数，或未配置跨域访问权限。
- 现象：无法导入Markdown格式的培训材料或结算清单。原因：Markdown文件包含未闭合的代码块或特殊符号，未通过FastGPT的格式校验。

## 怎么确认配好了
- 上传一份测试用的绩效表与人员准入规则，执行检索，检查返回结果是否包含目标人员的绩效数据与准入条款。
- 调整`similarity`参数的取值，观察召回结果的相关度变化，确认参数生效。
- 开启`usingReRank`后，验证结构化字段的排序是否符合预期，如结算额从高到低排列。
- 查看FastGPT v4.17.0的系统日志，确认检索请求的参数无缺失，无报错信息。
