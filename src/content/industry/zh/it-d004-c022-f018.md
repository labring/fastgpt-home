# 信创替代适配的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
这个品类的核心数据围绕信创软硬件替换场景生成，通常来自现有系统清单、国产软硬件官方目录、测试环境输出结果与厂商公开资料。日常产出的文档包括适配清单、兼容性测试报告、迁移方案与问题台账，数据字段一般包含软硬件型号、版本号、兼容状态、测试环境参数等。数据更新节奏随项目推进或季度周期调整，单次更新覆盖单项目或单批次国产化替换的全量相关信息。

## 这些特征在「重排与混合检索」这一环带来什么约束
信创替代适配的数据更新随项目或季度调整，单次更新的文档量与字段复杂度较高，要求混合检索优先召回与当前咨询匹配的软硬件兼容信息。适配清单、测试报告等文档的字段差异较大，部分字段仅在特定场景下生效，重排环节需基于咨询的具体场景（如服务器替换、办公软件迁移）对召回结果做针对性排序。存量系统盘点类数据的时效性要求较高，混合检索需优先召回最新版本的兼容信息，避免使用过期测试结果。同时问题台账中的故障排查步骤需与当前咨询的软硬件型号精准匹配，重排环节需关联型号字段与咨询关键词，提升排查效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 适配信创场景下软硬件型号、版本号的精准匹配需求，过滤低相关性的兼容信息 |
| `limit` | 前10条 | 适配单项目适配清单的常规条目量，避免召回过多冗余数据影响检索效率 |
| `searchMode` | hybrid | 结合向量召回与关键词召回，覆盖型号关键词、兼容状态描述等多类型数据 |
| `usingReRank` | 开启 | 针对信创文档的字段差异，对召回结果按咨询场景做二次排序，提升精准度 |
| 重排候选上限 | 前20条 | 为二次排序预留足够的候选数据，避免遗漏关键兼容信息 |
| 检索超时阈值 | 300–600 秒 | 适配信创文档的单条长度较长的特点，避免因检索超时导致任务失败 |

## 容易做错的三处
- 检索结果重排无响应，界面检索结果面板中重排标记字段为空或显示false。原因是未正确配置reranker服务的调用渠道，或自定义渠道的接口地址未指向可用的reranker实例。
- 混合检索召回结果与咨询关键词不匹配，且未触发重排流程。原因是`usingReRank`开关未开启，或重排候选上限设置过低导致有效数据被过滤。
- 自定义reranker服务调用失败，返回400或404状态码。原因是在中转渠道配置时，未正确填写服务密钥或接口路径，导致请求无法正常转发。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库配置页面，查看`usingReRank`开关是否处于开启状态。
- 发起一条针对特定软硬件型号的咨询，检查检索结果是否包含对应型号的兼容信息，且重排后的结果排序符合预期。
- 调用reranker服务的测试接口，确认返回结果的状态码为200且包含有效排序分数。
- 查看检索日志面板，确认`searchMode`为hybrid，且`similarity`阈值处于预设的0.72–0.85区间内。
