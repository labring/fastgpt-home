# 值班排班与交接的客户技术支持与售前答疑：知识库检索与召回

本文基于FastGPT v4.17.0版本编写，以下内容适配该版本及兼容版本。

## 这个品类的数据长什么样
这个品类的数据主要来自排班系统、故障工单、监控告警与组织通讯录，更新频率为日度或周度。日常文档包含值班表、交接记录、升级联系人清单、值班日报，字段涵盖值班时段、待交接未结事项、升级联系人姓名与联系方式、故障响应路径等。数据结构随团队规模调整，小型团队可将各类文档合并为单份值班交接表，大型团队则拆分出独立的升级联系人清单与值班日报。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据按日或周更新，知识库检索需支持按更新时间过滤，确保召回最新的值班安排与交接记录。不同类型的业务文档对应独立的知识库集合，检索时需定向匹配对应集合，避免混淆不同时段的值班表与升级联系人信息。字段中的值班时段、未结事项等结构化内容，要求检索支持按字段精准匹配，结合语义召回补充非结构化内容的匹配。未结事项关联实时故障工单，检索需联动最新工单数据，确保返回的交接内容包含当前待处理事项。团队规模差异带来的文档结构差异，要求检索配置支持灵活调整集合范围，适配不同团队的文档组织方式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 平衡语义匹配精度与召回覆盖，避免误召回非对应时段的值班信息 |
| `limit` | `前 8–12 条` | 单次检索返回的内容需覆盖单轮值班交接的核心事项，同时控制上下文长度 |
| `searchMode` | `向量召回+关键词混合` | 兼顾结构化字段（如值班时段）与非结构化内容（如未结事项描述）的匹配需求 |
| `usingReRank` | `开启` | 对召回结果按相关性排序，确保最相关的值班安排与升级联系人信息优先返回 |
| `collectionIds` | `指定值班表、交接记录、升级联系人清单对应集合ID` | 定向检索目标业务文档，避免混入无关的故障工单或监控告警数据 |
| `datasetSearchUsingExtensionQuery` | `开启` | 自动扩展检索关键词，补充匹配值班时段、联系人姓名等结构化字段的同义表述，提升召回精准度 |

## 容易做错的三处
- 现象：检索结果仅返回少量目标数据，无法匹配指定条件的值班人员或交接事项。原因：未通过`collectionIds`指定对应业务集合，导致检索范围覆盖了无关的历史数据，且未配置字段匹配规则过滤非目标内容。
- 现象：检索结果包含过期的值班安排，无法获取当前时段的值班人员信息。原因：未设置按更新时间过滤的检索条件，知识库未同步最新的日度排班数据，导致召回旧版文档。
- 现象：检索返回的交接记录未包含完整的未结事项内容。原因：未开启`datasetSearchUsingExtensionQuery`，无法匹配未结事项的同义表述，且`limit`取值过低，截断了核心交接内容。

## 怎么确认配好了
- 手动输入指定值班时段的关键词，核对检索结果是否仅包含对应集合的文档内容，验证`collectionIds`配置生效。
- 上传一份测试用的过期值班表，发起检索后确认结果未包含该过期文档，验证更新时间过滤配置生效。
- 输入包含未结事项描述的检索词，核对返回结果是否包含完整的待交接内容，验证重排与扩展查询配置生效。
- 调整`similarity`取值区间，观察检索结果的匹配精度变化，确认配置参数符合业务需求。
