# 内容审核规则运营的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自内容审核后台、用户举报渠道、公开法规政策文件与内部样本库，更新节奏为每日同步或随政策变更即时更新。日常产出与使用的文档包含审核规则条目、违规处置指南、用户申诉记录、质检复盘报告，文档字段多包含规则编号、触发阈值、样本标签、处置说明等，无统一固定单位，随具体规则类型与业务场景调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新节奏不固定，要求多轮对话上下文需支持快速关联最新审核规则与申诉记录；日常文档多为条目化结构，提示词需适配分块读取的规则内容，避免混淆不同编号的审核条款；样本库与质检报告的字段差异较大，需在对话中支持动态切换上下文维度；合规场景下需留存完整交互日志，便于后续监管复核与内部质检。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 上下文窗口大小 | 8000–12000 token | 适配FastGPT v4.17.0版本下审核规则、申诉记录与交互日志的总长度，避免截断关键合规信息 |
| `messages` | 保留最近15–20轮交互记录 | 内容审核场景的交互多为规则查询与样本复核，过多历史会干扰当前判定 |
| `variables` | 注入当前审核规则编号、业务场景标签 | 精准匹配对应规则条目，缩小上下文检索范围 |
| 附件上传限制 | 单文件最大100 MB，支持PDF、TXT格式 | 匹配审核规则文档与质检报告的常见文件规格 |
| `chatId` | 绑定会话至对应审核项目ID | 实现会话与特定业务场景的绑定，便于后续日志溯源与合规复核 |
| 会话超时设置 | 3600秒 | 覆盖单次复杂申诉复核的完整交互时长，避免中途中断 |

## 容易做错的三处
- 现象：调用`api/v1/chat/completions`接口时，无法返回指定知识库标签关联的审核规则内容，原因：未在`variables`参数中配置对应业务场景与规则标签，导致上下文未匹配到正确数据来源。
- 现象：对话界面无法上传审核规则文档或申诉记录附件，原因：配置的单文件上传上限低于待上传文档的实际大小，或未开启对应文件格式支持。
- 现象：导出的会话交互记录缺失部分历史交互环节，原因：未开启完整会话日志留存配置，仅保留了当前轮次的交互数据，未同步存储历史`messages`参数内容。

## 怎么确认配好了
- 发起包含审核规则编号的查询，核对`messages`参数是否包含该查询的历史交互记录，确认上下文窗口未截断关键信息。
- 上传一份符合业务场景的文档，核对界面是否正常接收并加载附件内容，确认上传配置与文档规格匹配。
- 调用`api/v1/chat/completions`接口，传入预设的`variables`参数，核对返回结果是否关联了对应知识库标签的审核规则。
- 发起一轮完整的申诉复核对话，核对会话是否绑定了对应`chatId`，确认后续可通过该ID检索完整交互日志。
