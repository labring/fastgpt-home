# 内容推荐运营的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
内容推荐运营的核心数据来自内容标签库、用户行为日志、实验平台及推荐后台。日常产出的文档包括标准化的推荐策略记录、内容池清单、实验报告与运营复盘。数据更新频率通常为日度或周度，单份文档包含内容ID、标签权重、用户点击率、实验分组等字段，无统一固定单位，随文档类型调整。最耗时的内容池筛选、实验指标解读等环节，依赖多源数据的交叉验证。

## 这些特征在「知识库检索与召回」这一环带来什么约束
内容标签、用户行为等多源数据的更新节奏存在日度与周度差异，要求知识库检索需支持增量召回，避免全量重扫导致的资源浪费。内容池清单、实验报告等文档结构差异较大，部分包含嵌套章节与外部链接，要求检索配置需适配多格式内容的分组绑定。实验指标类数据的字段无统一单位，需在召回时保留原始元数据用于后续业务验证。高耗时的内容池筛选环节依赖精准匹配，若检索召回结果偏差，会直接放大低质内容或导致核心推荐指标异常，因此需严格控制召回的相关性与结果条数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配内容推荐场景下的标签与用户行为的相关性要求，避免召回无关的实验报告或内容池条目 |
| `limit` | 前10条 | 适配内容池清单、实验报告等单文档的内容量，同时控制检索返回的结果条数，避免上下文溢出 |
| `searchMode` | 语义检索 | 适配多源异构的推荐运营数据，支持标签、行为日志等非结构化内容的精准匹配 |
| `usingReRank` | 开启 | 对召回的结果按用户行为权重重新排序，修正初始检索的相关性偏差，贴合推荐运营的业务逻辑 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动基于用户的售前或支持问题生成扩展查询，匹配内容策略记录中的细节参数 |
| `collectionIds` | 按运营分组指定 | 绑定对应内容池、实验报告的知识库集合，避免检索跨品类的无关数据 |

## 容易做错的三处
- 现象：上传包含章节标题、链接、简介的文档组时，检索结果拆分出单章节条目，无法匹配完整的一组信息。原因：未配置集合间的关联召回参数，导致系统按单文本块独立召回。
- 现象：通过知识库接口创建纯文本集合时，无法找到`trainingType`的有效枚举选项，或配置后接口返回格式异常。原因：误用了非官方指定的参数值，未匹配FastGPT支持的枚举范围。
- 现象：FastGPT v4.17.0版本中，知识库回答的段落末尾未显示引用标注，或企业版高并发场景下出现检索超时。原因：未开启引用展示的全局配置，或未调整`limit`参数适配并发负载。

## 怎么确认配好了
- 上传单份内容池清单文档，检索包含“核心内容标签”的测试问题，核对返回结果是否包含完整的条目信息，无拆分片段。
- 调用知识库检索接口，传入测试问题，检查返回结果中是否包含`collectionIds`指定的集合内的文档，无跨集合的无关内容。
- 开启`usingReRank`后，对比初始召回与重排后的结果顺序，确认结果排序贴合推荐运营的业务权重逻辑。
- 模拟多并发请求，观察接口返回状态码，确认无异常报错，调整参数至符合业务并发要求。
