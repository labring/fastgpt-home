# 创作者入驻与认证的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
创作者入驻与认证场景的数据来源主要包括创作者后台、企业信用信息平台、账号历史系统与合同管理系统。日常处理的文档包含入驻申请表单、身份资质扫描件、认证审核记录、合作协议文本等。数据更新节奏以单次申请触发为主，部分公共资质数据按日同步。数据字段涵盖申请人账号标识、资质文件标识、审核状态、合作期限等，既有结构化的审核编号、信用代码，也有非结构化的申请描述、资质说明文本。

## 这些特征在「重排与混合检索」这一环带来什么约束
多源异构的数据结构要求混合检索同时支持结构化字段匹配与非结构化文本召回，避免仅依赖单一检索方式导致的资质材料漏检。数据更新的实时性要求检索链路支持动态加载最新的审核记录与资质文件，无法使用静态缓存的数据集。单次申请的关联数据量有限，需控制召回结果的总条数以避免审核人员信息过载。同时，虚假认证的出错后果要求重排环节优先召回高风险的审核状态、异常资质等关键数据，确保核心审核依据的优先级最高。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 用于匹配资质材料与审核记录的核心关联字段，过滤低相关的历史账号数据 |
| `limit` | 前10条 | 控制单次检索的总召回结果数，适配单次入驻申请的关联数据量级 |
| `searchMode` | hybrid | 开启混合检索模式，同时匹配结构化字段（如企业信用代码）与非结构化文本（如申请描述） |
| `usingReRank` | 开启 | 对多源召回的结果进行重排序，优先召回高优先级的审核状态、异常资质等核心数据 |

## 容易做错的三处
- 现象：界面显示结果重排状态为false，检索结果未按审核优先级排序。排查项：未正确配置`usingReRank`参数，或服务启动校验未通过（未配置App/Admin服务端必填的AIPROXY_API_ENDPOINT和AIPROXY_API_TOKEN环境变量）。
- 现象：多源召回结果无法匹配到对应创作者的资质材料。排查项：未在混合检索配置中绑定创作者账号ID作为关联字段，导致跨数据源匹配失效。
- 现象：arm架构部署后重排功能无法启动。排查项：使用了amd架构的重排模型镜像，未选择适配arm架构的部署包。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）和`AIPROXY_API_TOKEN`（AI Proxy管理员Token）是否已正确配置，无空值，且符合FastGPT v4.17.0及以上版本的要求。
- 发起一次测试入驻申请的检索请求，查看召回结果的排序是否符合审核优先级，如审核记录优先于普通申请文本。
- 验证多数据源的匹配逻辑，确认结构化字段（如企业信用代码）和非结构化文本均可被正确召回。
- 查看服务启动日志，确认无重排模块的启动报错或参数校验失败提示。
