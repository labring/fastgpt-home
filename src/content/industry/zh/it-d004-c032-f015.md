# 创作者激励结算的客户技术支持与售前答疑：知识库检索与召回

本文基于FastGPT v4.17.0版本编写

## 这个品类的数据长什么样
该品类数据通常来自内容数据、广告分成系统、财务系统与账号后台。日常文档包含激励规则、结算明细、申诉记录与付款清单，字段涵盖创作者账号标识、结算周期区间、分成核算口径、申诉提交时间、付款凭证编号与金额数值。数据更新频率多为月度或随专属运营活动触发，不同文档的字段格式与更新节奏存在差异，结算明细与付款清单的结构化程度较高，激励规则与申诉记录则以非结构化文本为主。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散导致检索范围需严格限定，避免跨系统无关数据干扰。更新频率非实时，需按月度或活动周期触发索引刷新，避免检索到过期数据。文档结构与字段差异要求检索模式兼顾结构化明细与非结构化规则，单一检索模式无法覆盖全部查询场景。结算相关结果的准确性直接关联争议与错付风险，需严格过滤低关联结果，保障召回内容的相关性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.85–0.92 | 该品类数据涉及结算金额与规则，需过滤低关联结果，避免引发结算争议 |
| `limit` | 前8–12条 | 兼顾结算明细与规则类查询的结果数量，避免过多内容增加客服阅读成本 |
| `searchMode` | 语义+全文混合检索 | 覆盖规则类文本与结构化明细的不同查询场景，适配创作者与运营人员的多样化提问 |
| `usingReRank` | 开启 | 过滤语义相似但无关的条目，提升结算明细类数据的检索准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 适配口语化提问，匹配标准规则文本，解决创作者非标准化表述的查询需求 |
| `collectionIds` | 指定激励规则、结算明细、申诉记录三个核心集合的专属ID | 限定检索范围，排除跨品类无关数据，提升检索效率 |

## 容易做错的三处
- 现象：检索结果的`similarity`分值低于0.8，且全文检索匹配度不足。原因：未根据品类数据特征调整`similarity`阈值，未开启混合检索模式，导致低关联结果被召回。
- 现象：前端界面持续显示「正在检索」状态，无结果返回。原因：未配置`limit`参数的合理取值，或知识库索引未按月度/活动更新频率完成刷新，导致检索超时无响应。
- 现象：检索配置界面仅显示GPT3.5相关选项，无法选择其他模型。原因：未在系统部署中开启多模型适配，或未将品类知识库绑定至支持多模型的环境。

## 怎么确认配好了
- 进入FastGPT知识库管理界面，查看`similarity`阈值配置，验证取值是否符合品类要求。
- 发起一条结算明细查询，检查返回结果的条数是否在`limit`参数设定的范围内。
- 提交一条口语化提问，如「我的结算金额为什么不对」，验证`datasetSearchUsingExtensionQuery`是否生效，返回标准规则内容。
- 查看检索日志，确认仅从指定的三个核心集合中召回数据，无跨品类无关结果。
