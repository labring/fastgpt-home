# 前端应用开发的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的日常文档通常包含接口文档、组件说明、联调记录、发布清单四类。数据来源为代码仓库、接口管理平台、设计稿文件与浏览器兼容性数据库。更新节奏通常为每日同步或每版本发布时更新。接口文档包含接口路径、请求参数、返回字段结构；组件说明标注props参数、触发事件与终端兼容范围；联调记录记录调试步骤与报错日志；发布清单记录版本号与变更内容。字段多包含字符型参数、版本号、兼容终端类型等，无统一金额或时长类固定单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据来源分散且更新频繁，通常要求检索系统支持多数据源增量同步，避免全量重建索引占用过多资源。不同类型文档结构差异显著，接口文档需按单个接口维度拆分，组件说明需按props参数分组，需灵活配置分块规则适配不同文档格式。技术类字段多包含专业术语与版本号，检索需优先匹配精准关键词，避免泛化召回无关内容。同时前端场景的技术支持需快速定位兼容性问题，召回结果需覆盖浏览器兼容性数据，需确保检索范围包含对应数据源。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配前端技术文档的精准术语，过滤低相关性的通用技术内容 |
| `limit` | 前 8–12 条 | 控制检索结果的总token数，适配前端场景下的上下文长度要求 |
| `usingReRank` | 开启 | 提升结构化文档如组件说明、接口文档的召回排序准确性 |
| `searchMode` | hybrid | 结合关键词匹配与语义检索，覆盖专业术语查询与模糊问题场景 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展售前咨询中的模糊问题，将「弹窗组件」等简化表述匹配到对应文档 |
| `collectionIds` | 按当前项目关联的前端知识库数据集ID填写 | 限定检索范围，避免召回非当前项目的前端相关文档 |

## 容易做错的三处
- 现象为开启`usingReRank`并完成知识库索引后，在线召回测试结果未体现重排后的排序变化。原因是未在大模型调用环节配置启用重排结果的传入，或重排模型的API密钥未正确绑定到当前知识库。
- 现象为设置`limit`为3000条时，大模型接收不到上下文内容。原因是检索结果总token数超出大模型上下文窗口上限，导致系统自动截断或丢弃上下文数据。
- 现象为检索结果出现大量重复内容，或召回文件数不符合预期配置。原因是未正确配置分块重复率阈值，或未按文档类型调整分块规则导致重复片段过多。

## 怎么确认配好了
- 进入FastGPT的知识库检索测试页面，输入前端相关问题，查看返回结果的排序是否符合预期，验证`usingReRank`是否生效。
- 调整`limit`参数为不同数值，核对检索返回的结果条数是否与配置一致。
- 输入包含专业术语的问题，查看检索结果是否优先匹配接口文档、组件说明等目标文档，验证`similarity`参数的配置效果。
- 检查数据集关联配置，确认仅当前项目的前端知识库被纳入检索范围，验证`collectionIds`的配置正确性。
