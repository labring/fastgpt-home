# 办公系统流程配置的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
该品类的核心数据来自企业OA系统、组织架构库、内部制度文件与用户反馈工单。日常维护的文档包括流程配置单、审批节点表、表单字段说明与变更记录，更新频率随业务变更每月调整。数据字段包含审批节点权限、表单校验规则、流转路径参数等，核心围绕业务审批的路径配置与权限绑定展开，与身份账号管理类数据的差异在于聚焦流程流转逻辑，不涉及账号权限本身的分配与管理。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散，包含OA系统流程数据、组织架构信息与用户反馈工单，多轮对话需按数据类型拆分上下文，防止不同来源的配置信息相互混淆。文档结构包含多层级审批节点与表单字段，多轮对话需跟踪用户提及的具体节点ID或表单参数，避免上下文丢失或错位。更新频率随业务变更动态调整，提示词模板需支持实时调用最新的变更记录，防止使用过期配置内容。审批规则与权限配置的错误会直接导致业务流转停滞，提示词需明确校验配置项的逻辑合理性，同时在多轮交互中保留历史配置的上下文，便于回溯排查配置异常。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `messages` | 保留前 20–30 轮对话，按实测标定 | 该品类的多轮对话需跟踪审批节点与表单字段的历史询问，保留足够轮次避免关键配置信息丢失 |
| `chatId` | 绑定对应流程配置的唯一会话ID | 确保不同流程配置的多轮对话上下文隔离，防止跨配置的信息混淆 |
| `variables` | 传入当前流程的节点ID、表单字段列表 | 为提示词提供当前配置的具体上下文，便于精准答疑 |
| 最大上下文token数 | 8000–12000 token | 适配该品类的流程配置文档与历史对话的总长度，避免上下文溢出 |
| 对话超时时间 | 60 秒 | 匹配企业内部流程配置的排查响应节奏，防止长时间等待导致会话中断 |
| 提示词模板加载频率 | 随配置变更实时更新 | 适配该品类数据随业务变更动态调整的特性，确保提示词始终使用最新的流程规则 |

## 容易做错的三处
- 工作流对话显示失败但模型测试正常，后台有响应日志。原因是未正确绑定`chatId`参数，导致会话上下文无法关联到对应流程配置，工作流节点无法读取历史配置数据。
- 调用工具时无法传入历史对话内容。原因是未在请求参数中正确携带`messages`参数，或未将历史对话按顺序拼接至工具调用的上下文参数中。
- 应用对话出现异常报错但无日志记录。原因是未开启会话日志的完整采集配置，或日志存储路径权限不足，导致报错信息未被正常写入。

## 怎么确认配好了
- 发起一轮针对具体审批节点的询问，核对对话界面返回的内容是否包含当前流程的节点权限与流转规则。
- 发起多轮连续询问，检查`chatId`是否保持一致，确保上下文未被重置。
- 触发一次配置校验类的请求，查看后台日志是否正常记录`variables`参数传入的流程配置数据。
- 模拟一次配置变更，检查提示词是否能自动加载最新的变更记录，无需手动更新模板。
