# 办公系统流程配置的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
通常，办公系统流程配置的相关数据主体为企业信息化管理员、OA管理员及业务流程管理员。日常产生的文档包括流程配置单、审批节点表、表单字段说明与变更记录。数据主要来源于企业OA系统、组织架构库、内部制度文件及用户反馈，更新频率随业务变更而定，一般为每变更一次更新一次。日常最耗时的环节为审批规则梳理、节点权限配置与测试验证，配置出错可能导致审批卡住、权限错误或制度执行偏差。与身份账号权限管理品类不同，该品类聚焦业务审批路径与表单配置。

## 这些特征在「重排与混合检索」这一环带来什么约束
办公系统流程配置的数据特征对重排与混合检索环节带来明确约束。首先，数据包含结构化的审批节点表、表单字段说明与非结构化的制度文件，混合检索需同时适配语义匹配与结构化字段匹配，避免返回无关的权限配置内容。其次，数据更新频率随业务变更，检索需优先匹配最新的变更记录，防止管理员使用过时的流程配置。最后，日常耗时环节集中在规则梳理，检索结果需快速定位到具体的审批节点或配置条目，减少管理员的手动排查时间。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `usingReRank` | 开启 | 办公系统流程配置数据包含多类条目，重排可过滤低相关的历史配置与无关的权限规则 |
| `similarity` | 0.75–0.85 | 流程配置的匹配精度要求较高，避免引入与当前查询无关的旧变更记录 |
| `limit` | 前10条 | 单次检索返回的配置条目数量适配管理员快速定位的需求，避免信息过载 |
| `searchMode` | 混合检索模式 | 结合语义匹配与结构化字段匹配，适配流程配置的多类型数据结构 |
| 重排模型接入 | 按业务数据实际文本长度标定 | 需匹配流程配置文档的平均长度，避免模型输入溢出或精度下降 |

## 容易做错的三处
- 配置重排模型后测试提示错误，但引用后可运行，启用重排却显示异常。原因：未正确配置重排模型的ACCESS Token，或模型部署的端口未开放至FastGPT服务网络。
- 知识库启用结果重排后状态显示为叉号。原因：未完成重排模型的连通性校验，或检索返回的结果条数未达到重排模型的最小输入要求。
- 检索结果中旧的流程配置条目优先级高于最新变更记录。原因：未设置合理的相似度阈值过滤旧数据，或未优先匹配最新的流程变更记录。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库检索配置页面，确认`usingReRank`开关处于开启状态，且重排模型的配置信息完整。
- 发起一条与当前流程配置相关的查询，核对返回结果的条数与`limit`配置项的取值一致。
- 对比开启重排前后的检索结果，确认高相关的审批节点配置条目排序更靠前。
- 运行检索测试，确认无报错提示，且结果中包含最新的流程变更记录。
