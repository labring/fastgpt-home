# 单元测试与组件测试的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
本品类的数据主要来自代码仓库、测试框架报告、需求说明与接口定义，更新节奏为每日或每次代码提交后。日常关联文档包含测试用例、覆盖率报告、Mock接口说明与缺陷单，数据字段包含测试用例编号、覆盖代码范围、边界条件说明、缺陷复现步骤与严重等级等，无统一固定单位，随文档类型变化。数据体量随项目规模波动，核心围绕代码单元与组件的验证逻辑展开，部分数据包含代码片段与测试步骤的混合内容。

## 这些特征在「重排与混合检索」这一环带来什么约束
数据更新频率高，要求检索链路适配快速增量同步，避免因数据滞后导致检索结果偏差。测试用例、缺陷单等文档结构碎片化，混合检索需同时匹配语义与关键词特征，避免遗漏边界条件相关内容。数据来源包含代码与测试报告，需区分代码逻辑与测试结果两类数据的权重，重排环节需针对不同文档类型调整排序依据。单次检索涉及的测试数据条目较多，需限制返回范围以控制耗时，同时保障核心边界条件用例被优先召回。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本，针对单元测试与组件测试的客户技术支持与售前答疑场景定制：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.72–0.85 | 匹配测试用例与用户问题的语义相似度，覆盖边界条件用例的召回需求 |
| 单次搜索上限 | 前 10–15 条 | 限制单次检索返回的基础结果数量，适配测试数据碎片化的特征 |
| 检索模式 | hybrid | 开启混合检索模式，同时匹配关键词与语义特征，适配测试文档多类型结构 |
| 重排开关 | 开启 | 对召回结果重排，优先排序缺陷复现步骤、边界条件等核心测试相关内容 |
| 重排召回条数 | 前 5–8 条 | 缩小重排范围，控制检索耗时，适配测试数据更新频率高的场景 |
| 检索超时时间 | 8–12 秒 | 适配测试数据体量波动，避免因检索超时导致的构建阻塞风险 |

## 容易做错的三处
- 现象：调用重排环节报错，返回`rerank error fastgpt | { message: { detail: '`格式的错误提示。原因：未正确配置重排模型的调用参数，或模型与当前FastGPT版本不兼容。
- 现象：混合检索链路耗时超过10秒，超出业务可接受范围。原因：未限制单次检索上限与重排召回条数，同时召回并重排了过多测试用例与缺陷单数据。
- 现象：部署重排模型后，单GPU或多GPU节点下显存占用随调用快速增长至较高水平。原因：未配置重排模型的并发调用限制，导致多个请求同时占用GPU资源。

## 怎么确认配好了
- 执行单次检索测试，核对返回结果的数量与配置的单次搜索上限一致。
- 触发重排环节，检查系统日志中是否包含重排结果的排序依据字段，确认重排逻辑生效。
- 模拟高频率数据更新场景，核对检索链路的同步延迟是否符合业务预期。
- 分别调用纯语义检索与混合检索模式，对比两类检索的结果差异，确认混合模式正常工作。
