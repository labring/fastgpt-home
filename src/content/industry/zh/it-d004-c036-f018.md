# 原型与交互设计的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
该品类的典型主体为产品设计师、交互设计师与前端产品小组。日常产出的文档包括交互原型、页面流程图、组件说明与评审记录。数据主要来源于Figma或Axure文件、团队内部设计系统、用户反馈与可用性测试记录。数据更新频率通常为每周或每版本迭代时更新，文档结构围绕页面操作路径、组件属性与评审意见展开，核心字段包含页面节点ID、跳转逻辑、组件说明文本与评审修改记录。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据以层级化的页面节点、操作路径与评审修改记录为核心，首先要求混合检索能够识别文档内的层级关联，避免召回不相关的孤立组件说明。其次，数据更新频率为每周或每版本迭代，检索流程需要适配增量更新逻辑，确保召回内容始终匹配当前最新的设计版本。此外，文档中包含大量操作路径描述与评审意见，重排环节需要优先匹配与用户查询的技术支持或售前答疑场景强相关的内容，同时需过滤已被评审驳回的过时设计内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `usingReRank` | 开启 | 该品类数据包含层级化的页面节点与操作路径，开启重排可过滤低相关性的孤立内容，提升技术支持场景的检索准确性 |
| `limit` | 前8–12条 | 交互设计文档的核心内容集中在少量关键页面节点，限制返回条数可避免冗余信息干扰答疑场景 |
| `similarity` | 0.72–0.85 | 该品类文档的操作路径描述存在固定句式，该相似度区间可精准匹配用户查询的跳转逻辑或组件说明 |
| `searchMode` | 混合检索 | 适配该品类的层级化文档结构，结合全文检索与节点关联检索，覆盖页面流程与组件说明两类数据 |

## 容易做错的三处
- 现象：部署在Docker中的重排模型返回请求不兼容的报错。原因：未按照模型要求的格式配置自定义请求地址，未正确匹配模型的输入输出字段。
- 现象：检索结果未优先展示最新的设计版本内容。原因：未配置适配周度或版本级更新的增量逻辑，召回了过时的评审记录或旧版原型内容。
- 现象：重排模型返回空结果或无有效排序。原因：未正确配置重排模型的API密钥或请求地址，导致无法正常调用模型服务。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库配置页面，查看`usingReRank`开关是否处于开启状态。
- 提交一条包含具体操作路径的测试查询，核对返回结果的条数是否符合`limit`参数的设置。
- 对比开启重排前后的检索结果顺序，确认重排模型已对结果进行重新排序。
- 检查自定义重排模型的请求地址与密钥是否正确，验证模型返回的结果是否匹配预期的设计文档内容。
