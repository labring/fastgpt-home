# 发布管理与版本验收的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自CI流水线、变更系统、测试报告与监控看板，更新频率为周度或每版本周期。日常产出的文档包含发布计划、上线清单、验收报告、回滚预案，数据字段包含语义化版本号、发布时间窗口、变更内容清单、回滚触发条件与验证步骤，每条数据关联具体的研发迭代批次，单条数据的长度随发布规模动态调整，无统一固定标准。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据的周/每版本更新节奏要求知识库支持增量同步机制，避免旧版本无效数据混入当前检索范围。多类关联文档的结构需要检索时按版本号、发布时间过滤，确保召回结果匹配当前迭代批次。多源自动化系统产出的字段格式存在批次间的细微差异，检索时需匹配关联字段以避免跨版本混淆。应急类的回滚预案文档需要优先召回，因此需要设置内容权重区分，避免被普通变更文档覆盖。单批次发布的文档数量有限，单次召回的上限需适配该规模，防止上下文窗口过载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 该品类文档多为结构化技术内容，阈值过低会引入无关版本数据，过高则可能遗漏匹配的变更项。 |
| `limit` | `前6–10条` | 单批次发布的关联文档数量通常在5-8份，召回过多会超出FastGPT v4.17.0模型支持的上下文窗口限制。 |
| `searchMode` | `vector+keyword` | 该品类数据包含结构化版本号与自由文本变更描述，混合检索可兼顾精确匹配与语义关联。 |
| `usingReRank` | `开启` | 回滚预案等应急文档需要优先排序，重排可基于内容相关性调整结果顺序，提升应急场景的检索效率。 |
| `datasetSearchUsingExtensionQuery` | `开启` | 用户售前答疑常提及版本兼容性问题，扩展查询可补充关联的测试报告与变更记录，完善回答内容。 |
| `collectionIds` | `绑定发布管理专属数据集` | 避免召回其他品类的无关文档，确保检索范围精准匹配当前发布管理场景。 |

## 容易做错的三处
- 现象：API调用检索时返回401未授权错误，原因：启用了自动Bearer令牌补充功能，导致请求头携带不符合目标知识库系统要求的令牌格式。
- 现象：检索结果未优先展示回滚预案等应急文档，原因：未开启`usingReRank`功能，无法按内容相关性调整结果排序，导致普通变更文档覆盖应急内容。
- 现象：测试查询召回了跨版本的无效文档，原因：未按版本号配置过滤规则，或`collectionIds`绑定了包含历史版本数据的非专属数据集。

## 怎么确认配好了
- 进入FastGPT知识库管理页面，检查`collectionIds`是否仅绑定发布管理专属数据集。
- 发起测试查询，输入包含具体版本号的问题，验证召回结果仅包含对应版本的发布计划、上线清单等文档。
- 查看检索日志，确认`searchMode`为vector+keyword混合模式，召回数量符合`limit`设置的范围。
- 测试API调用，关闭自动Bearer令牌补充功能后，验证请求可正常返回匹配的检索结果。
