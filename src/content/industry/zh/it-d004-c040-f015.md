# 售前技术方案的客户技术支持与售前答疑：知识库检索与召回

本页配置基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
这个品类的日常文档包含技术方案书、客户需求调研表、报价清单、演示脚本，数据来源为客户访谈、招标文件、厂商产品资料与历史项目方案。更新节奏为每单或每周，单项目文档随需求调整实时更新，批量文档按周同步。文档结构包含专业技术术语、项目边界说明、报价明细与演示流程，字段覆盖客户需求点、技术路线、实施范围与成本配置，无统一固定格式，需结合当前项目需求定制内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
文档类型多样且无统一格式，既有长文本的技术方案书，也有短文本的报价清单，要求检索适配不同长度与结构的内容。数据按项目绑定专属数据源，需精准过滤跨项目的无关内容，避免售前答疑时混入不匹配的方案信息。更新频率灵活，需支持增量同步与全量更新两种模式，确保召回内容与当前项目状态一致。专业术语占比高，要求检索匹配精度符合业务要求，避免因低相关结果导致方案边界澄清出错。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 售前方案包含大量专业技术术语，该阈值可过滤低匹配度的无关结果，同时保留相关度符合要求的内容 |
| `limit` | 前8条 | 售前答疑需覆盖方案边界、报价、演示等多场景，过多结果会超出上下文长度，该数量可平衡信息完整性与检索效率 |
| `searchMode` | `vector` | 数据以专业技术内容为主，向量检索比关键词匹配更适配术语匹配需求，可提升召回精准度 |
| `usingReRank` | 开启 | 售前方案的内容关联性较强，重排可优化高相关结果的排序位置，提升用户获取关键信息的效率 |
| `datasetSearchUsingExtensionQuery` | 开启 | 客户提问可能隐含技术需求，扩展查询可匹配未直接提及的专业内容，完善答疑覆盖范围 |
| `collectionIds` | 按项目绑定对应厂商产品、历史方案集合 | 售前方案按项目定制，绑定专属集合可避免检索跨项目的无关数据，确保召回内容精准匹配当前项目 |

## 容易做错的三处
- 现象：调用API同步知识库集合时提示身份验证不通过。原因：未正确配置数据集的访问密钥，或调用的API账号未被授予对应知识库集合的访问权限。
- 现象：检索返回的结果条数与配置的`limit`不符。原因：未正确指定`collectionIds`，导致检索范围覆盖了无关的知识库集合，结果被系统自动过滤。
- 现象：知识库检索响应耗时过长。原因：同时开启了`usingReRank`和`datasetSearchUsingExtensionQuery`，且`limit`设置过高，增加了检索、扩展查询与重排的计算负载。

## 怎么确认配好了
- 核对`collectionIds`配置，确认仅绑定当前售前项目对应的厂商产品资料、历史项目方案等专属数据源。
- 发起模拟客户提问的检索测试，检查返回结果的数量与预设的`limit`一致。
- 查看检索日志，确认`usingReRank`与`datasetSearchUsingExtensionQuery`的触发状态符合配置要求。
- 测试不同类型的提问场景，如技术路线询问、报价核对、演示脚本调整，确认检索结果的相关性符合业务预期。
