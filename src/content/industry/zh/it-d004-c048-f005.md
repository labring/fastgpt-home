# 安全监控与SOC值守的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据主要来自SIEM、EDR、NDR及威胁情报源，更新频率为实时或每日。日常关联文档包含告警处置单、值班记录、威胁情报通报、日报周报，单份告警处置单包含告警ID、关联资产、触发时间、处置状态等字段，值班记录按值班班次记录告警研判结果，威胁情报通报包含最新威胁特征与处置建议。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据来源分散且更新节奏差异大，要求多轮对话上下文需实时同步最新告警与情报数据，避免依赖过期缓存。日常文档类型多样，提示词需明确区分告警处置单、值班记录等不同文档的使用场景，确保对话调用的数据源匹配当前任务。告警处置单等文档包含固定字段，提示词需指定字段提取规则，避免混淆不同文档的字段信息。实时更新的威胁情报数据要求对话中的变量需实时拉取，无法使用静态缓存内容。

## 配置怎么定
本配置适用于FastGPT v4.17.0。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定告警ID作为唯一标识 | 确保同一场告警的多轮对话上下文关联正确，避免跨告警混淆 |
| `messages` | 保留最近20条对话上下文 | 覆盖告警研判的完整流程，同时控制上下文长度不超过8000 token |
| `variables` | 实时拉取当前告警的关联资产数据 | 基于SIEM实时数据源，确保对话中使用的资产信息为最新状态 |
| 最大上下文长度 | 8000 token | 适配告警处置单、值班记录等文档的总长度，避免超出模型处理上限 |
| 温度参数 | 0.6–0.8 | 平衡告警研判的准确性与灵活性，符合安全场景的严谨性要求 |
| 单次对话文档召回上限 | 前3条告警处置单 | 聚焦当前告警相关的历史处置记录，减少无关信息干扰 |

## 容易做错的三处
- 现象：获取对话记录列表接口返回的数据中，AI回复与用户提问的关联关系不清晰，出现字段错位。原因：未使用`chatId`绑定唯一的告警会话标识，导致不同告警的对话数据混杂。
- 现象：在同一对话中修改全局变量后，后续轮次无法读取更新后的值。原因：未将`variables`配置为实时更新模式，仅加载了初始静态变量值。
- 现象：无法获取同一场对话中三次提问的独立内容，仅能获取合并后的文本。原因：未正确配置`messages`参数保留单轮对话的独立上下文，错误将多轮内容拼接为单一条目。

## 怎么确认配好了
- 发起一场模拟告警的多轮对话，检查`chatId`是否与告警ID一致，确保对话上下文仅关联当前告警。
- 调用对话记录列表接口，核对返回的`messages`数组中，每一条用户提问与AI回复的顺序与内容匹配正确。
- 修改测试用的全局变量值，发起后续对话，确认模型使用了更新后的变量内容。
- 查看对话上下文长度，确保未超过配置的最大上下文阈值，避免出现内容截断。
