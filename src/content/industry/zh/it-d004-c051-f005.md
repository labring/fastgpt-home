# 客户数据导入迁移的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自客户历史业务系统、标准化CSV/Excel模板、数据库导出文件，以及FastGPT平台的导入运行日志。日常配套文档包含数据导入模板、迁移执行方案、字段映射对照表、迁移效果验证报告。数据更新节奏随项目进度不定期调整，通常每完成一次迁移动作或收到客户反馈后更新一次。数据核心字段包含业务实体标识、属性值、关联关系三类，部分场景需携带数据创建时间、校验标记等辅助字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据特征对多轮对话与提示词环节带来多重约束。首先，数据来源包含多类异构格式文件，不同客户的字段命名、单位标准存在差异，需要通过多轮对话逐步确认字段映射规则，避免直接套用通用模板。其次，配套文档数量多且更新频繁，提示词需引导用户按项目阶段上传对应文档，确保对话上下文关联的是当前迁移任务的最新文件。此外，数据更新节奏不定期，需通过`chatId`绑定单任务对话链，避免不同项目的上下文混淆，同时限制对话上下文长度，防止因历史数据过多导致对话卡顿。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的界面与API逻辑，具体配置项及依据如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文token数 | 8000–12000 token | 覆盖字段映射确认、脏数据清洗规则协商等核心多轮对话的内容长度，避免关键信息被截断 |
| `chatId`绑定规则 | 与迁移任务ID一一对应 | 确保单任务的对话上下文不与其他项目混淆，符合该品类按项目隔离数据的业务要求 |
| `variables`预设值 | 导入模板字段、客户系统字段对照表 | 减少用户重复输入基础配置信息，适配该品类高频的字段映射咨询需求 |
| 多轮反问触发条件 | 检测到用户输入包含“字段”“映射”“清洗”“验证”关键词 | 针对该品类常见的咨询场景，自动启动多轮确认流程 |
| 单次对话响应超时 | 600秒 | 覆盖数据模板解析、字段映射校验等耗时操作的等待时长，防止中途断开连接 |
| 历史对话存储上限 | 按当前项目的总对话条数 | 匹配数据更新的不定期节奏，避免无效历史数据占用系统资源 |

## 容易做错的三处
- 现象：调用对话API时无法上传数据模板或字段映射表文件，返回“不支持文件类型”的报错文案。原因：未在提示词中明确要求用户通过指定的迁移文档提交入口提交内容，错误套用通用对话的文件上传逻辑。
- 现象：不同客户的历史对话记录未隔离，可跨项目查看他人迁移数据。原因：未为每个迁移任务绑定唯一的`chatId`，导致上下文共享，违反该品类按项目隔离数据的业务要求。
- 现象：工作流节点仅能发起单次提问，无法根据用户反馈调整字段映射规则。原因：未配置多轮对话触发逻辑，仅调用了单次问答接口，未启用多轮上下文管理功能。

## 怎么确认配好了
- 发起包含字段映射、脏数据清洗关键词的测试提问，观察系统是否自动启动多轮确认流程，核对对话上下文是否仅关联当前测试任务的内容。
- 生成两个不同的迁移任务测试对话，确认各自的对话记录无法互相访问，验证数据隔离配置生效。
- 上传测试用的CSV模板与字段映射表，核对系统是否能正确识别并关联到当前对话任务，无报错返回。
- 等待超过预设的响应超时时长，观察系统是否能正常处理后续提问，验证超时配置合理。
