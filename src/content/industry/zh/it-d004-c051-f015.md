# 客户数据导入迁移的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据主要来自客户历史系统、CSV或Excel模板、数据库导出及产品导入日志，日常关联文档包含数据模板、迁移方案、字段映射表、迁移验证报告。数据更新节奏随单或不定期，核心内容围绕业务数据标识、字段映射关系、数据校验规则、导入结果状态展开，无统一固定单位，需结合客户具体业务场景匹配对应字段与单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据来源分散且格式多样，既包含结构化的字段映射表、CSV模板，也包含非结构化的迁移方案与验证报告，要求检索环节兼容多格式数据的召回。数据更新随单且无固定周期，需支持按需同步最新的迁移配置与日志文档。核心业务文档围绕字段映射、数据校验展开，要求检索能精准匹配字段名称、映射规则等专业术语，避免召回无关内容。同时导入日志的报错信息需快速关联到对应解决方案文档，需优化召回的精准度以匹配技术支持场景的时效性需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配字段映射、迁移规则这类专业术语，兼顾召回覆盖与精准度 |
| `limit` | 前 6 条 | 覆盖常见的迁移问题场景，避免返回过多冗余内容 |
| `searchMode` | 语义检索 | 适配半结构化的迁移方案与结构化的字段映射表的混合检索需求 |
| `usingReRank` | 开启，重排前 3 条 | 提升核心报错、字段映射类内容的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充关联的迁移日志、验证报告等延伸内容，覆盖售前答疑的扩展问题 |
| `collectionIds` | 绑定迁移类文档专属集合 | 隔离其他品类的知识库内容，避免召回无关文档 |

## 容易做错的三处
- 出现“Request failed with status code 400”报错，原因是未配置`collectionIds`绑定专属迁移文档集合，检索时触发了跨源数据的格式校验异常。
- 知识库检索无法匹配标题相关的迁移问题，原因是未开启`datasetSearchUsingExtensionQuery`，未将文档标题纳入检索范围。
- 调用API知识库时出现自动补充Bearer的异常，原因是未在检索配置中调整授权参数逻辑，导致请求头格式不符合目标系统要求。

## 怎么确认配好了
- 手动输入字段映射相关的关键词，核对返回结果是否包含该品类的专属文档。
- 模拟导入场景触发报错关键词，检索是否能召回对应的迁移验证或故障排查文档。
- 确认`collectionIds`配置仅绑定迁移类知识库集合，排除其他品类的文档干扰。
- 验证`usingReRank`开启后，核心报错相关内容的排序是否优先于冗余内容。
