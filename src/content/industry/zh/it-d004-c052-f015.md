# 客户权限与组织架构配置的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的核心数据由实施顾问、客户管理员、技术支持日常维护，包含权限矩阵、组织架构表、角色配置记录、权限变更单四类文档。数据来源涵盖客户HR系统、身份目录、产品后台与审计日志，更新频率为每单或不定期。数据字段包含部门ID、角色ID、权限项、变更时间等，无统一固定的单位，需结合具体业务场景匹配对应规则。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源数据的混合接入要求检索时需区分不同数据源的权限范围，避免跨源越权召回。不定期的更新频率要求检索链路支持增量同步或实时拉取最新的权限配置文档。文档字段的非标准化特征要求检索时需匹配角色、部门等语义关联字段，不能依赖固定格式的关键词。组织层级与权限映射的复杂性，要求召回结果需包含关联的上级权限与子部门权限条目，避免遗漏关键配置内容。

## 配置怎么定
FastGPT v4.17.0版本下，针对该品类的知识库检索与召回可参考以下配置项：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 权限配置的匹配需要较高精度，避免无关权限项被误召回，保障检索的精准性 |
| `limit` | 前10条 | 权限相关文档的条目相对集中，过多召回结果会增加上下文干扰，降低排查效率 |
| `searchMode` | `vector` | 权限配置的语义关联较强，如部门层级、角色映射等，向量检索可有效匹配此类模糊关联 |
| `usingReRank` | 开启 | 权限配置的关联逻辑复杂，重排可提升高相关结果的排序优先级，减少人工排查成本 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 权限配置的查询需求明确，无需额外扩展查询词，避免匹配到无关的非权限类文档 |
| `collectionIds` | 指定仅包含权限矩阵、组织架构表的知识库集合ID | 缩小检索范围，排除其他无关知识库的干扰，提升检索效率与精准度 |

## 容易做错的三处
- 现象：配置知识库问答拆分时触发Invalid array length报错，必现。原因：权限相关的Markdown文档中存在格式异常的数组字段，拆分流程无法识别有效数据结构。
- 现象：调试预览阶段知识库搜索正常，但部署到自有页面后无法触发检索。原因：未正确同步`collectionIds`参数，生产环境的知识库集合ID与调试环境不一致。
- 现象：无法导入权限配置相关的Markdown文件。原因：未将Markdown文件的标题与权限字段（如角色ID、部门名称）进行规范映射，导致导入校验失败。

## 怎么确认配好了
- 检查`collectionIds`参数是否仅包含权限矩阵、组织架构表所属的知识库集合ID，排除无关知识库的干扰。
- 验证`similarity`参数的取值是否符合预设区间，通过测试查询「管理员权限」「部门层级配置」等关键词，确认召回结果的相关性。
- 开启`usingReRank`后，核对重排后的前3条结果是否包含目标权限文档，确认排序优先级符合预期。
- 模拟自有页面的检索请求，对比返回结果与调试预览阶段的内容，确认一致性。
