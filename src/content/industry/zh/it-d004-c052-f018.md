# 客户权限与组织架构配置的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
该品类的核心数据来自客户HR系统、身份目录、产品后台与审计日志，更新节奏为每单或不定期。日常产出的文档包括权限矩阵、组织架构表、角色配置记录、权限变更单，数据字段包含角色ID、部门层级、权限节点、变更时间与操作人信息，单条数据兼具结构化字段与非标准化的文本描述，整体结构偏向半结构化。

## 这些特征在「重排与混合检索」这一环带来什么约束
多源分散的数据来源要求混合检索需同时对接结构化权限矩阵与非结构化配置记录，避免遗漏跨系统的权限关联信息。不定期的更新节奏要求检索链路支持增量同步，确保返回的权限配置为最新状态。结构化的字段特征要求重排环节需优先匹配部门层级、角色权限这类核心字段，仅依赖基础语义相似度会降低匹配精准度。同时，权限配置的高相关性要求需严格过滤低匹配度的无关结果，避免技术支持人员被冗余信息干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `usingReRank` | 开启 | 该品类数据需精准匹配权限层级与角色关联关系，重排可过滤低相关的跨部门、跨角色结果，提升技术支持场景的检索精准度 |
| `searchMode` | 混合检索模式 | 需同时检索结构化权限矩阵、组织架构表与非结构化的角色配置记录、权限变更单，混合模式可覆盖多源异构的品类数据 |
| `similarity` | 0.75–0.85 | 权限配置文本的语义差异通常较小，阈值过高会遗漏相近的权限配置条目，过低会引入无关的非权限类结果，按实测标定 |
| `limit` | 前10条 | 权限配置的单知识库条目数量通常有限，限制返回条数可避免冗余展示，适配技术支持人员快速查阅核心配置的需求 |
| 重排模型调用超时阈值 | 300秒 | 权限配置数据的检索链路需稳定对接，超时阈值设置可避免因数据量波动导致的检索失败，符合客户技术支持的实时响应要求 |

## 容易做错的三处
- 现象：开启`usingReRank`后返回结果为空或无权限相关内容。原因：未配置重排模型的调用密钥或未绑定对应模型的API权限。
- 现象：混合检索结果未按部门层级优先级排序。原因：未在重排环节加入部门层级字段的权重配置，仅依赖基础语义相似度计算。
- 现象：设置`similarity`阈值高于0.85后，无法检索到权限变更单。原因：权限变更单的文本描述通常存在细微的格式差异，过高的阈值会过滤掉符合业务需求的匹配结果。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库配置页，查看`usingReRank`开关是否处于开启状态。
- 提交一条包含部门层级或角色名称的查询，验证返回结果是否优先展示匹配部门/角色的权限配置条目。
- 调整`similarity`阈值，观察返回结果的条数变化，确认阈值调整对检索结果的影响符合预期。
- 查看检索日志，确认混合检索同时调用了权限矩阵、组织架构表等品类专属数据源。
