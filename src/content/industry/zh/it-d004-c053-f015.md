# 客户需求池管理的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
客户需求池管理的核心数据来自工单系统、客户访谈记录、CRM客户档案、产品路线图文档。日常维护的文档包括需求池清单、需求评估表、客户反馈记录、版本规划说明，数据更新频率为每周或每版本发布周期。数据字段包含需求来源、客户层级、优先级标签、关联版本号、评估成本与价值维度，单条文档内容多围绕具体客户的功能诉求、改进建议展开，无统一的短文本格式。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据来源分散且更新频率较高，检索环节需限定范围仅覆盖客户需求池相关文档，避免混入其他品类的业务数据。数据包含结构化标签与自然语言描述，需兼顾语义匹配与精准字段过滤。单条文档内容较长，需控制单次召回的内容长度，避免超出上下文窗口。售前与技术支持场景下的问题多围绕需求优先级、排期规划展开，检索结果需按业务优先级排序。跨系统的需求数据需定期同步至知识库，确保检索内容与最新版本规划一致，否则会出现匹配内容过时的问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的知识库检索与召回逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配客户需求描述的语义相似度阈值，平衡召回精度与覆盖度，适配需求池文档的长文本特征 |
| `limit` | 前8条 | 单次召回的文档数量，适配需求池单条内容较长的场景，避免上下文过载 |
| `searchMode` | 向量检索+关键词混合 | 结合需求池的结构化字段与自然语言描述，提升跨来源数据的匹配准确性 |
| `usingReRank` | 开启 | 对召回结果按需求优先级、关联客户层级重排序，匹配售前与技术支持的业务评估逻辑 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展用户的售前/支持问题为需求池相关的检索词，提升短问题的匹配覆盖度 |
| `collectionIds` | 指定需求池知识库集合ID | 限定检索范围仅覆盖客户需求池相关文档，避免无关业务内容干扰检索结果 |

## 容易做错的三处
- 现象：调用知识库检索API返回code:514错误。原因：未正确指定`collectionIds`参数，或未配置对应知识库集合的访问权限。
- 现象：检索结果条数与配置的`limit`不符。原因：未关闭无关知识库的自动检索开关，或`similarity`阈值设置过高导致有效结果被过滤。
- 现象：检索结果未关联对应版本规划内容。原因：未开启`datasetSearchUsingExtensionQuery`，未将用户的售前问题扩展为匹配需求池版本字段的检索词。

## 怎么确认配好了
- 执行curl测试调用指定的知识库检索接口，检查返回结果的相似度分值是否落在0.75–0.85的配置区间内。
- 查看检索结果的来源字段，确认仅包含需求池相关的知识库集合，无其他无关业务文档。
- 提交包含需求优先级描述的测试问题，检查返回结果的排序是否按优先级从高到低排列。
- 验证`datasetSearchUsingExtensionQuery`开启后，短测试问题是否能扩展为匹配需求池字段的检索词，提升召回覆盖度。
