# 容器平台运维的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
通常，容器平台运维的日常文档包含集群变更单、命名空间配额表、部署记录与故障报告。数据主要来源于Kubernetes API、镜像仓库、监控系统与CI流水线，更新频率为每日或每一次集群变更。数据字段包含集群节点标识、Pod运行状态、镜像版本号、资源配额阈值等，单位多为个、秒、MB与命名空间名称标识，无固定统计聚合格式，需按单次对话请求实时拉取。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来源分散且更新频率不固定，多轮对话的上下文不能无限制保留，否则会引入过期的集群配置信息。日常文档的结构化字段要求提示词必须明确指定查询的字段范围，避免泛化提问导致返回无关数据。同时，运维场景的出错后果直接关联业务稳定性，对话的异常处理需严格匹配集群数据的校验规则，且附件解析仅能限定当前上传内容，避免加载冗余历史文档干扰排查。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 最大上下文对话轮次 | 前10条 | 匹配容器平台运维的单次对话数据量，避免上下文过载影响响应速度 |
| 上下文自动清空触发规则 | 用户发送“清空”“重置”关键词，或每24小时自动触发 | 适配数据每日或按需更新的频率，避免旧配置干扰当前对话 |
| `variables` 配置 | 包含集群标识、命名空间名称的固定变量 | 精准匹配集群运维的专属数据字段，避免跨集群查询混淆，匹配FastGPT v4.17.0版本的变量配置规范 |
| 知识库引用开关 | 默认关闭，仅在用户明确请求时开启 | 运维场景多依赖原生集群API数据，无需额外知识库引用 |
| 对话链接鉴权配置 | 开启团队级鉴权 | 保护集群运维数据的内部敏感性，避免外部访客访问敏感配置 |
| 附件解析范围控制 | 仅解析当前上传的附件 | 避免历史文档加载导致的解析冗余，符合运维场景的单次排查需求 |

## 容易做错的三处
- 对话中知识库引用无法关闭，表现为每次回复都附带知识库引用内容。原因是未关闭默认的知识库引用开关，或未配置仅在用户请求时开启的规则。
- 对话上下文未按条件清空，表现为`messages`字段包含冗余的历史对话记录。原因是未配置上下文自动清空的触发规则，或触发条件未与集群变更事件绑定。
- 附件解析加载历史文档，表现为文档解析结果包含非当前上传的文件。原因是未配置附件解析范围控制，默认加载了全量历史文档，与用户仅解析当前附件的需求不符。

## 怎么确认配好了
- 发送包含“清空上下文”的指令，检查`messages`字段是否仅保留当前对话内容。
- 生成对话分享链接，使用非授权账号尝试访问，确认无法查看对话内容，验证`chatId`绑定的集群权限生效。
- 上传单个附件并发起解析请求，检查解析结果仅包含当前上传的附件，无历史文档混入。
- 发起指定命名空间的配额查询请求，检查返回结果仅匹配该命名空间的配额数据，验证`variables`配置的集群标识生效。
