# 对象存储与备份服务的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自对象存储控制台、备份系统、访问日志与客户策略表，更新节奏为每日同步或随存储桶、备份策略变更实时更新。日常文档包含存储桶配置参数、备份执行策略、恢复操作记录、生命周期规则条目，字段涵盖权限策略条目、备份任务状态、恢复耗时、访问请求IP等，无统一固定单位，具体单位随配置项类型变化。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散导致检索需覆盖多类数据源，需配置跨源关联召回逻辑；更新节奏差异要求区分全量与增量召回触发时机，避免重复加载过期数据；文档结构多样，包含参数条目、策略文本、日志记录，需适配不同长度的分块规则；权限策略字段的存在，要求检索结果需同步校验访问权限，过滤无权限的内容，避免泄露敏感配置信息。

## 配置怎么定
以下为FastGPT v4.17.0 版本下的适配配置：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配对象存储配置、备份策略这类专业文档的语义相似度阈值，平衡召回精度与覆盖范围 |
| `limit` | 前5–10条 | 适配单轮技术支持场景的上下文长度，避免过多内容超出对话窗口限制 |
| `searchMode` | 语义检索 | 适配存储配置、策略文本这类结构化与半结构化混合的文档类型 |
| `usingReRank` | 开启 | 对召回结果进行二次排序，修正单一语义匹配的偏差，提升高相关内容的展示优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题生成扩展查询词，覆盖备份任务监控、恢复抽检这类高频咨询场景的潜在关键词 |

## 容易做错的三处
- 现象：使用Docker部署的FastGPT上传对象存储相关知识库文件时提示上传失败。原因：未正确挂载存储桶配置、备份日志这类本地文件目录，导致FastGPT无法读取目标文档。
- 现象：通过接口创建知识库向量并执行检索后，服务器磁盘或内存占用持续走高，每日定时触发资源耗尽。原因：未配置增量召回或分块大小不合理，导致每日全量扫描备份系统、访问日志的海量数据，未做分片处理。
- 现象：检索结果中出现未授权的存储桶权限策略内容。原因：未开启知识库权限校验配置，未关联客户IT部门的策略表字段进行过滤。

## 怎么确认配好了
- 上传一份存储桶配置文档，执行包含配置关键词的查询，确认返回结果包含文档内的配置参数。
- 查看检索日志，确认召回的数据源覆盖对象存储控制台、备份系统等指定来源，无遗漏。
- 测试带权限关键词的查询，确认结果仅返回符合预设权限规则的内容，无越权条目。
- 调整`similarity`参数区间，验证召回结果的相关性变化符合预期调整方向。
