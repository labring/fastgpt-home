# 工单受理与问题分级的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来源于工单系统、聊天记录、产品日志与客户合同SLA，更新频率为日级或实时。日常维护的文档包含客户工单、问题分级表、处理记录与服务报告，数据字段包含工单唯一标识、客户关联信息、问题描述文本、分级标签、响应时限要求与分派团队信息，所有字段围绕客户反馈与问题处置流程生成，无额外自定义单位字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
工单数据以文本描述为主且更新实时，要求多轮对话需保留会话上下文与关联工单信息，避免重复询问客户已提供的内容。问题分级依赖标准化的分级表，提示词需固定引用分级标签的固定格式，确保输出结果可直接匹配分级规则。工单数据包含SLA时限要求，多轮对话需在响应环节嵌入时限校验逻辑，防止超时触发违约。同时数据来源分散，需在对话初始化时自动拉取关联的历史处理记录，减少人工录入成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前工单的唯一标识 | 关联历史会话与对应工单数据，确保上下文与业务主体一致 |
| `messages` | 保留前15轮对话与关联工单的历史记录 | 覆盖完整的问题溯源链路，避免重复询问客户已提供的信息 |
| `variables` | 传入工单ID、SLA响应时限两个预设变量 | 自动填充业务参数，减少人工录入的操作成本 |
| 最大上下文 | 8000–12000 token | 覆盖完整工单与多轮对话的信息总量，按实测标定 |
| 问题优化 | 开启 | 将客户模糊描述转化为标准化分级查询语句，匹配预设的问题分级规则 |

## 容易做错的三处
- 调用API发起工单相关对话，生成的回复未引用配置的知识库文档。未在请求参数中通过`variables`传入关联工单的知识库关联标识，导致对话未触发知识库召回流程。
- 使用FastGPT v4.17.0版本时，对话页面或知识库页面出现崩溃。会话缓存未设置合理的过期时间，导致大量`chatId`绑定数据占用内存资源。
- 配置Ollama部署的模型后，预设的引导词未生效。未将引导词写入`messages`的系统消息列表，导致模型未加载预设的问题分级规则。

## 怎么确认配好了
- 发起模拟客户工单的测试对话，输入预设的问题描述，检查返回结果是否自动关联了对应工单的历史处理记录。
- 查看对话请求日志，确认`chatId`、`messages`、`variables`参数均已正确传入请求体。
- 调整测试用的客户问题描述，验证模型输出的分级标签是否符合预设的分级表规则。
- 切换不同的模型类型，确认配置的引导词均能正常被模型识别并执行，无异常报错信息。
