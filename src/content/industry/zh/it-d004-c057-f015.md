# 工单受理与问题分级的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源于工单系统、客服聊天记录、产品运行日志、客户合同SLA文档。日常产出的文档包括客户工单、问题分级表、问题处理记录、客户服务报告。数据更新节奏为日更或实时同步。文档字段包含工单唯一标识、客户关联信息、问题描述文本、预分级标签、影响范围、责任团队标识、处理时限要求等，字段多为文本、枚举类型，无复杂嵌套结构。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据以非结构化的客户问题描述、历史处理记录为主，且更新频率包含实时同步，要求知识库检索需支持快速增量更新与语义匹配。数据包含预分级标签与责任团队标识，检索时需支持按分级标签、责任团队维度过滤召回结果，避免跨团队的无效匹配。工单与聊天记录的文本长度差异较大，部分短问题仅包含核心诉求，需适配短文本的语义召回精度。历史处理记录包含已解决的问题方案，召回时需关联对应分级的有效解决方案，避免返回过时或不匹配的内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.85–0.92` | 本品类问题多为短文本诉求，过滤低语义匹配的结果，避免无效召回 |
| `limit` | `前8–12条` | 工单受理需快速匹配核心方案，过多结果会增加客服筛选成本 |
| `searchMode` | `语义优先` | 本品类数据以客户自然语言描述为主，语义匹配优于关键词匹配 |
| `usingReRank` | `开启` | 进一步过滤召回结果的相关性，适配多来源的历史工单数据 |
| `datasetSearchUsingExtensionQuery` | `开启` | 基于用户问题自动扩展相关同义词，覆盖不同表述的同类工单问题 |
| `collectionIds` | `绑定对应工单分类的知识库集合` | 精准限定检索范围，避免跨品类的无效数据召回 |

## 容易做错的三处
- 检索结果中出现语义相似度低于预设阈值的低匹配内容。原因是未正确配置`similarity`参数的阈值区间，或阈值设置过低。
- 知识库未同步对应工单分类的数据。原因是未绑定正确的`collectionIds`，或部署后的数据库连接配置未完成更新。
- 检索过程持续显示加载状态。原因是`limit`参数设置的召回条数过多，或未开启`usingReRank`导致检索计算耗时超出业务允许范围。

## 怎么确认配好了
- 提交一条典型的客户工单问题，查看检索返回结果的语义相似度是否符合预设的`similarity`阈值区间。
- 检查知识库集合的绑定关系，确认`collectionIds`参数已关联本品类的工单与处理记录数据集。
- 模拟单次检索请求，确认返回结果的条数不超出`limit`参数设定的范围。
- 查看FastGPT v4.17.0的检索日志，确认`usingReRank`与`datasetSearchUsingExtensionQuery`参数已生效。
