# 广告账户开户审核的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据围绕广告账户开户全流程生成，日常文档包含开户申请表单、营业执照扫描件、对应行业经营资质文件、开户审核记录台账。数据来源包括广告平台后台的账户申请记录、国家企业信用信息公示系统的主体核验数据、客户提交的纸质或电子材料、公开的行业准入规则。数据更新频率随单次开户申请推进，每完成一个申请节点更新一次，主体资质核验、行业准入判断环节会产生多轮校验数据。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
上述数据特征对多轮对话与提示词配置带来明确约束。首先，数据来源分散且包含非结构化材料，要求多轮对话需支持跨数据源的信息拉取与校验；其次，更新频率随申请节点变动，提示词需适配单次会话的上下文绑定，避免跨申请的信息混淆；第三，主体资质核验环节耗时占比高，多轮对话需支持分段核验的流程引导，同时需留存每一轮的审核记录；第四，行业准入规则的动态性要求提示词能实时调用最新规则库，且需区分不同行业的准入差异；最后，材料补正沟通的高频性要求多轮对话能自动识别缺失材料字段，触发定向补正提醒。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，具体如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chatId` | 绑定单次开户申请的唯一标识 | 避免不同开户申请的对话上下文混淆，确保会话日志与申请记录一一对应 |
| `messages` | 限制上下文窗口为前15轮对话内容 | 开户审核的多轮沟通通常集中在资质补正、规则说明环节，15轮足够覆盖完整申请流程，避免上下文过载 |
| `variables` | 绑定客户提交的资质字段变量 | 可在对话中自动调用营业执照注册号、行业资质编号等已提交数据，减少重复录入 |
| 最大上下文 | `8000–12000 字符` | 单份开户申请的材料与沟通内容总和通常在此区间，避免超出模型处理上限 |
| 问题优化 | 开启，按实测标定 | 可将客户的口语化补正请求转换为标准化的资质字段校验项，提升审核效率 |

## 容易做错的三处
- 现象：调用API时传入`chatId`参数后，对话日志未显示该参数值。原因：未在会话初始化逻辑中关联`chatId`与开户申请的唯一标识，导致参数未被正确写入日志字段。
- 现象：免登录链接用户删除对话内容后，后台审核日志同步被清空。原因：未配置对话内容与审核记录的独立存储逻辑，误将会话存储作为审核日志的唯一数据源。
- 现象：对话中调用行业准入规则时返回不匹配的审核结果。原因：提示词未限定仅使用当前会话绑定的行业准入规则库，导致调用了过期或不相关的规则数据。

## 怎么确认配好了
- 发起一次模拟开户申请对话，传入预设的`chatId`参数，检查后台日志是否显示该参数值。
- 生成免登录链接并发起对话，手动删除对话内容后，检查后台审核记录是否仍保留完整的沟通日志。
- 在工作流中配置历史变量加载节点，发起新对话后验证是否能调取之前会话中保存的资质字段变量。
- 发起超过15轮的模拟对话，检查上下文是否自动截断至最近的15轮内容，避免冗余信息干扰。
