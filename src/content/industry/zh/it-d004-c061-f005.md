# 性能测试与容量评估的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据主要来自压测平台、APM监控工具、数据库慢日志以及生产流量基线。日常产出的文档包含压测方案、容量评估报告、压测数据记录与优化建议单。数据更新频率为每月或每重大版本发布时。数据字段通常包含吞吐指标、延迟指标、资源消耗值与资源余量，对应单位分别为请求每秒、毫秒、计算单位与存储单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据特征对多轮对话与提示词环节带来明确约束。首先，数据来源分散，多轮对话需支持跨压测平台、APM监控等数据源的字段关联，提示词需明确指定需调用的数据源类型。其次，数据更新频率较低，对话上下文的缓存有效期需匹配月度或重大版本周期，避免使用过期数据。日常文档结构固定，提示词需预设压测方案、容量评估报告的固定字段顺序与格式要求。此外，数据包含专业性能指标，提示词需补充指标的定义与对应单位说明，降低理解偏差。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `messages` 上下文长度限制 | 8000–12000 token | 适配性能测试数据的字段总量，避免截断关键指标 |
| `variables` 参数绑定开关 | 开启 | 用于关联压测方案中的固定参数字段 |
| 单次召回条目数 | 前3条 | 匹配压测数据记录的典型条目规模 |
| `chatId` 会话缓存时长 | 720 小时 | 匹配月度数据更新周期，保障对话数据一致性 |
| 文档分块长度 | 1000–1500 字符 | 适配容量评估报告的单段内容长度 |
| 问题语义优化 | 开启 | 简化专业性能指标的表述，提升对话理解效率 |

## 容易做错的三处
- 现象：调用API时返回令牌无效报错，日志显示令牌字段为“fastgpt”。原因：未正确将外部模型令牌填入对应配置项，误将平台内部标识作为令牌使用。
- 现象：多轮对话中无法关联压测知识库内容。原因：未开启参数绑定配置，或未明确知识库与对话会话的关联规则。
- 现象：对话返回的性能指标单位混乱。原因：提示词未明确指定指标的单位要求，导致提取的字段单位不一致。

## 怎么确认配好了
- 发起包含性能指标的测试对话，检查返回内容是否包含预设的压测数据字段。
- 查看会话缓存日志，确认`chatId`对应的上下文有效期符合设定时长。
- 调用API传入`variables`参数，检查是否成功绑定预设的文档字段。
- 调整上下文长度参数，验证是否会截断关键性能指标内容。
