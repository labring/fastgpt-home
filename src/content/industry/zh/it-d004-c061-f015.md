# 性能测试与容量评估的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的日常文档包含压测方案、容量评估报告、压测数据记录与优化建议单，数据主要来自压测平台、APM监控、数据库慢日志及生产流量基线。数据更新频率为每月一次或每重大版本发布时，文档字段通常包含吞吐率、延迟值、资源占用率、容量阈值等，单位多为每秒请求数、毫秒、百分比、GB等。数据关联的核心场景为压测模型设计、瓶颈指标定位与容量结论复核，异常后果涉及高峰期服务超时、资源采购失衡或扩容浪费。

## 这些特征在「知识库检索与召回」这一环带来什么约束
压测相关文档的数据源分散在多个监控与平台系统，检索时需覆盖多来源的结构化与非结构化数据，因此需要支持跨数据集召回。数据更新频率为月级或重大版本时，知识库的增量同步周期需匹配更新节奏，避免检索到过期的压测参数。文档字段包含吞吐率、延迟等专业指标，检索时需支持按指标维度过滤，同时召回的内容需包含明确的单位与场景关联信息，才能支撑技术支持与售前答疑的精准性。此外，压测场景的异常后果影响业务资源与服务稳定性，检索召回的结果需具备较高的置信度，避免误导决策。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数逻辑：
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 匹配压测场景下专业术语与指标的语义相似度，避免召回无关的通用测试文档 |
| `limit` | 前8条 | 控制单次召回的结果数量，适配压测文档单条内容较长的特点，减少上下文拼接耗时 |
| `searchMode` | hybrid | 结合关键词匹配与语义检索，覆盖压测方案中的具体步骤与容量评估的指标描述 |
| `usingReRank` | 开启 | 对召回结果按与问题的相关性重排，优先返回瓶颈定位、容量结论类的核心内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展查询词，补充压测相关的同义词，比如将“延迟”扩展为“响应延迟”“请求耗时” |
| `collectionIds` | 指定压测域、APM监控域的知识库集合ID | 限定检索范围为性能测试与容量评估相关的文档，避免召回非目标域的冗余内容 |

## 容易做错的三处
- 现象：完成知识库检索后，最终AI对话输出耗时较长，界面显示等待超过30秒。原因：未通过`collectionIds`限定检索范围，召回了超出性能测试域的冗余文档，导致上下文拼接与推理耗时增加。
- 现象：使用onapi集成本地部署的m3e-large模型作为嵌入工具后，检索召回结果为空或匹配度偏差较大。原因：未指定`collectionIds`关联对应嵌入模型的知识库集合，或向量维度未与嵌入模型对齐。
- 现象：知识库召回的容量相关数据与当前生产基线不符。原因：未按照月级或重大版本的更新频率配置增量同步，检索到过期的压测数据。

## 怎么确认配好了
- 执行一次针对压测瓶颈定位的查询，核对召回结果是否仅包含压测方案、容量评估报告类文档，确认`collectionIds`配置生效。
- 查看FastGPT v4.17.0版本的检索日志，核对单次召回的结果数量是否符合`limit`的设置，确认检索范围与数量控制正常。
- 对比开启与关闭`usingReRank`后的召回结果排序，确认重排逻辑正常生效。
- 模拟一次压测数据更新，检查知识库是否在设定的周期内完成增量同步，确认更新频率匹配业务要求。
