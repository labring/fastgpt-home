# 投放效果优化的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
本品类的典型使用主体为广告优化师、增长分析师与代理商运营人员。日常产出与使用的文档包含广告投放日报周报、实时调价记录、素材A/B测试数据表、投放效果优化复盘文档。数据来源涵盖广告平台后台数据、归因系统转化数据、CRM客户线索数据、落地页访问数据，更新节奏多为每日同步或实时推送。文档字段包含曝光量、点击量、转化数、获客成本等投放相关指标，单位多为次、元、百分比。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征对知识库检索与召回环节带来多重约束。数据多为实时或每日更新，要求知识库支持增量同步机制，确保检索结果匹配最新投放数据。日常文档包含结构化数据表与非结构化复盘文本，需要检索系统兼顾字段精准匹配与语义关联召回，覆盖不同格式的业务文档。多来源数据存在字段口径差异，要求检索环节支持基础的字段对齐处理，避免跨系统数据混淆。同时，投放效果优化的核心场景为异常指标定位与预算调配，需检索系统快速返回高相关结果，支撑实时决策。另外，错误的检索结果可能直接导致获客成本升高或预算提前耗尽，对召回的准确率提出更高要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配投放业务对检索结果相关性的基础要求，过滤低价值的历史数据 |
| `limit` | 前8–12条 | 平衡检索响应速度与结果信息量，适配异常指标定位的快速查看场景 |
| `searchMode` | hybrid | 兼顾语义检索与关键词检索，覆盖结构化数据表与非结构化复盘文档 |
| `usingReRank` | 开启 | 对初始召回结果进行二次排序，提升高相关文档的展示优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户原始问题生成扩展查询词，适配投放场景下的模糊提问需求 |
| `collectionIds` | 按投放业务域分组配置 | 限定检索范围仅覆盖投放效果优化相关的知识库集合，避免无关文档干扰 |

## 容易做错的三处
- 现象：在工作流中调用知识库节点时无法获取有效知识库ID。原因：未在FastGPT后台正确创建知识库并复制其唯一标识，或未将知识库授权给对应工作流使用。
- 现象：传入`collectionIds`参数后未返回任何搜索结果。原因：配置的知识库集合未同步投放业务的最新文档，或参数中填写的知识库ID与实际部署的集合ID不匹配。
- 现象：调用知识库检索接口时返回Query read timeout错误。原因：未针对投放业务的高频检索场景调整超时配置，导致大量并发检索请求超出系统响应阈值。

## 怎么确认配好了
- 提交一条包含投放业务关键词的测试查询，查看返回结果的相关性，调整相似度阈值至匹配业务需求的区间。
- 传入指定的`collectionIds`参数发起检索，验证返回结果仅包含对应业务域的文档，无无关内容混入。
- 开启`usingReRank`配置后，对比初始召回结果与重排后的结果顺序，确认高相关文档被优先展示。
- 模拟单次检索请求，检查接口响应是否符合业务实时性要求，调整检索上限参数平衡速度与结果信息量。
