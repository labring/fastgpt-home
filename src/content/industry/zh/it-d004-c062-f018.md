# 投放效果优化的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
这个品类的数据通常来自广告平台后台、归因系统、CRM线索库与落地页统计工具。更新节奏多为日级或实时，适配投放效果的即时调整需求。日常处理的文档包含广告投放日报周报、关键词调价记录、素材AB测试表与优化复盘报告，字段涵盖曝光量、点击量、转化数、获客成本、预算消耗等业务指标，无统一固定单位，需按具体数据类型匹配。

## 这些特征在「重排与混合检索」这一环带来什么约束
多源数据的整合需求要求混合检索需覆盖广告平台、归因、CRM等不同数据源，避免单一数据源的信息偏差。实时/日级的更新节奏要求检索配置支持增量拉取与快速响应，避免延迟影响优化决策。业务字段的多样性决定重排需以转化、成本等业务指标为核心，仅依赖语义相似度无法满足业务需求。耗时的异常定位与预算调配环节，要求检索结果需精准过滤无关内容，减少人工筛选的工作量。出错后果直接影响获客成本与预算效率，因此重排与混合检索的准确性需适配业务决策的严谨性要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `usingReRank` | 开启 | 投放效果优化需按转化数、获客成本等业务指标排序，基础语义相似度无法匹配业务需求 |
| `similarity` | `0.65–0.75` | 过滤低相关的历史广告数据与线索记录，保留有效业务关联内容 |
| `limit` | `前10–15条` | 适配日报、调价记录等单文档的长度，避免上下文溢出影响模型推理 |
| `searchMode` | 混合检索 | 整合广告平台数据、归因系统记录与CRM线索，覆盖完整的投放业务链路 |
| 重排模型选择 | `bge-rerank-base` | 适配广告业务的语义与业务关联排序需求，符合社区通用部署方案 |
| 检索数据源范围 | 近7天的广告数据、归因记录、CRM线索 | 投放效果优化的常规决策周期为7天，覆盖当前投放调整的有效周期 |
| FastGPT版本 | FastGPT v4.17.0 | 确保配置项与界面功能的兼容性 |

## 容易做错的三处
- 现象：部署`bge-rerank-base`镜像后测试返回401 unauthorized错误，其他平台配置正常。原因：未在FastGPT v4.17.0的模型配置页面填写正确的镜像访问密钥，或未开放对应容器的网络权限。
- 现象：开启重排功能后，检索结果条数少于预设的`limit`值。原因：重排模型会过滤掉相似度低于阈值的结果，导致最终返回的有效条目数低于初始召回的上限。
- 现象：未开启重排功能时，无法理解检索结果与投放业务的关联度。原因：基础语义相似度仅能匹配关键词，无法区分不同素材的转化效果、预算消耗等核心业务指标，导致相关度判断不符合业务需求。

## 怎么确认配好了
- 登录FastGPT v4.17.0的知识库管理后台，进入对应投放效果优化知识库的检索配置页面，确认`usingReRank`开关处于开启状态。
- 输入一条与广告优化相关的查询词，如“如何降低获客成本”，查看检索结果是否按照转化数、获客成本等业务指标排序。
- 测试配置的重排模型，输入一段包含广告数据的测试文本，确认返回结果无401错误且符合预期的排序规则。
- 查看检索日志，确认检索范围覆盖了近7天的广告数据、归因记录与CRM线索，符合预设的数据源配置。
