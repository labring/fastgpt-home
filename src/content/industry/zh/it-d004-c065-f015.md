# 接口联调与数据对接的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据围绕系统间接口交互场景产生，来源包括客户侧系统接口定义、对外API文档、联调测试数据与运行日志。日常产出的文档包含接口清单、联调记录、字段映射表与问题跟踪表，数据更新频率为每日或按项目阶段同步。数据结构以结构化字段为主，包含接口地址、请求参数、返回码、字段类型等明确的技术标识，同时伴随非结构化的联调问题描述与排查记录。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据特征对检索召回环节形成多重约束。首先，数据来源依赖客户侧接口与API文档，要求检索需精准匹配接口字段、异常码等结构化标识，避免泛化检索。其次，更新频率为日或阶段同步，要求知识库需支持定期增量更新，确保联调最新配置与异常说明被及时收录。再者，日常文档以接口清单、字段映射表为主，要求检索需兼顾结构化字段匹配与自然语言问题的语义关联。最后，核心耗时环节为字段口径与异常码对齐，要求召回结果需优先关联高优先级的接口内容，减少排查成本。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的知识库检索模块：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.72–0.88` | 适配接口字段、异常码的精准匹配需求，过滤低相关的非目标内容 |
| `limit` | `前6–12条` | 匹配接口联调问题的单场景关联内容量，避免过多冗余信息干扰排查 |
| `searchMode` | `语义+关键词混合` | 兼顾接口文档的结构化字段和自然语言描述的联调问题 |
| `usingReRank` | `开启` | 对召回结果按相关性重新排序，优先展示核心接口或高频异常的关联内容 |
| `datasetSearchUsingExtensionQuery` | `开启` | 自动扩展问题为接口相关的同义词，覆盖不同工程师的表述习惯 |
| `collectionIds` | `指定联调专属数据集ID` | 限定检索范围，排除无关的通用知识库内容 |

## 容易做错的三处
- 点击知识库触发检索后返回指定报错文案，控制台显示参数校验失败。原因是未正确配置`collectionIds`，限定检索范围的参数未传入或错误。
- 知识库响应延迟明显，超过业务允许的耗时阈值。原因是未限制`limit`参数且未开启`usingReRank`，召回了过量冗余的历史联调日志数据，增加了检索与排序开销。
- 召回结果包含大量不相关的通用技术文档，未命中目标接口的字段或异常码。原因是`similarity`阈值设置过低，混入了低匹配度的非目标内容。

## 怎么确认配好了
- 执行单接口联调问题的测试检索，核对召回结果是否包含对应接口的字段映射、异常码说明内容。
- 查看检索耗时，根据联调场景的实时响应要求调整`limit`和`usingReRank`配置。
- 检查检索结果的相关性排序，确认高匹配度的接口文档优先展示。
- 模拟异常场景发起检索，验证是否能快速返回对应异常码的排查指南。
