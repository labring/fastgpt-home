# 接口联调与数据对接的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
接口联调与数据对接的专属数据包含多类结构化与非结构化内容。数据来源主要为客户系统接口、API文档、测试数据与联调日志，更新频率分为日常日更与项目阶段更新两类。日常文档包括接口清单、联调记录、字段映射表与问题跟踪表，其中接口清单包含接口地址、请求方法、参数名与返回码等结构化字段，联调日志则记录调用链路、异常码与排查过程等非结构化内容。字段口径与单位需严格匹配客户系统定义，常见单位包括毫秒、字符、字节等。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据结构与更新节奏对重排与混合检索环节带来多重约束。首先，结构化的接口清单与非结构化的联调日志并存，混合检索需同时适配两类数据的召回逻辑，避免仅召回单一类型内容。其次，数据更新频率不一致，日更的测试数据与阶段更新的联调记录需按时间权重调整检索优先级，确保最新的联调排查结果优先展示。此外，字段口径需严格匹配客户系统定义，检索时需优先召回与接口参数、异常码直接相关的内容，避免误匹配与当前联调项目无关的通用技术内容。最后，该环节的检索结果直接影响联调排查效率，需控制结果数量与排序逻辑，减少工程师的信息筛选成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.70–0.85 | 匹配接口字段口径与报错信息的核心阈值，过滤无关的通用技术内容 |
| 单次召回上限 | 前8–12条 | 控制单次基础召回的结果数量，适配单轮联调排查的信息展示密度 |
| 检索模式 | 混合检索 | 同时召回结构化接口清单与非结构化联调日志，覆盖全量关联数据 |
| 启用重排 | 是 | 对召回结果按报错关联度与字段匹配度排序，优先展示最相关的排查内容 |
| 重排后展示条数 | 前5–7条 | 聚焦核心排查线索，减少工程师的信息浏览负担 |

## 容易做错的三处
- 现象：配置重排模型时，同名模型的配置被覆盖，界面仅显示最后一次添加的模型。原因：系统默认以模型名称作为唯一标识，未提供多实例管理或重命名功能。
- 现象：调用第三方重排模型时返回空内容，接口返回状态码200但无有效检索结果。原因：模型接口权限未开通，或请求参数格式不符合模型要求的字段结构。
- 现象：本地部署的开源模型无法接入检索流程，无法返回预期的联调相关内容。原因：未正确配置模型的API访问地址与端口，或未开放对应端口的外部访问权限。

## 怎么确认配好了
- 上传包含接口清单、联调日志与测试数据的混合测试集，执行检索后查看召回结果的覆盖范围是否符合预期。
- 检查重排功能的开关状态，确认检索结果的前N条与预设的字段匹配度、报错关联度一致。
- 调用测试接口，查看检索返回的结果数量是否与配置的单次召回上限、重排后展示条数匹配。
- 验证不同来源的数据（如API文档、联调日志）是否都被正确召回，无遗漏的关联内容。
