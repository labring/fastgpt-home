# 搜索广告关键词管理的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的日常处理数据主要来自搜索广告后台、搜索词报告、竞价排名数据与落地页数据，更新频率通常为日度或周度。日常涉及的文档包含结构化的关键词清单、否词表、出价记录，以及非结构化的搜索词报告。数据字段涵盖关键词文本、匹配模式、单次出价金额、历史搜索量、转化关联数据等，单位包含元、次、字符等。围绕用户主动搜索词的处理逻辑，区别于信息流广告的创意测试场景。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据的结构化与非结构化混合特征，要求多轮对话中需区分关键词文本、出价数值等结构化字段与搜索词文本等非结构化字段，提示词需明确字段格式约束。日度或周度更新的数据要求对话上下文需限制在近7天的报告范围内，避免引入过时数据。关键词清单的条目量通常较大，多轮对话的上下文窗口需限制有效字段数量，防止超出模型处理上限。搜索词报告的非结构化文本需先完成字段提取，多轮对话中需保留提取的中间结果供后续调用。围绕用户主动搜索词的处理逻辑，要求提示词需聚焦于搜索场景的关键词关联分析，避免引入无关的创意测试逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 会话ID绑定 | 绑定`chatId`参数 | 确保多轮对话的会话唯一性，避免跨会话混淆 |
| 最大上下文窗口 | 前6轮对话 + 近7天数据摘要 | 匹配日度更新的数据频率，避免过时信息，同时限制上下文长度防止模型过载 |
| 上下文记忆开关 | 开启 | 需保留`messages`中的历史对话内容，确保多轮问答的连贯性 |
| 变量绑定 | 绑定关键词清单、否词表的最新文件 | 确保`variables`调用的是最新的业务数据，匹配日度更新节奏 |
| 提示词格式约束 | 要求输出符合JSON Schema的结构化结果 | 适配关键词数据的结构化字段，便于后续自动处理 |
| 单次对话token上限 | 8000 token | 适配搜索词报告与关键词清单的文本长度，避免截断关键信息 |

## 容易做错的三处
- 现象：设置了6轮上下文记忆，模型仍无法关联上一轮提问的关键词出价信息。原因：未正确绑定`messages`参数的历史对话内容，或上下文窗口配置未覆盖完整的历史交互。
- 现象：提取的关键词信息显示为乱码。原因：未在提示词中明确指定编码格式，或未对非结构化搜索词报告的特殊字符做转义处理。
- 现象：生成的关键词扩展结果与当前业务数据不符。原因：未在对话流程中调用`variables`绑定的最新关键词清单或否词表数据，导致使用了过时的业务配置。

## 怎么确认配好了
- 发起一轮包含历史关键词出价信息的提问，核对模型是否能关联上一轮的出价数值。
- 上传最新的搜索词报告，发起提取关键词的请求，核对输出结果的格式是否符合预设要求。
- 测试无交互的iframe嵌入场景，观察系统性能指标是否符合预期。
- 检查配置页面中`variables`绑定的文件是否为最新的日度更新版本。
