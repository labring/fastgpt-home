# 搜索广告关键词管理的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的核心数据来源于搜索广告后台、搜索词报告、竞价排名数据及落地页数据，更新频率多为日度或周度。日常使用的文档包括结构化的关键词清单、否词表、出价记录与搜索词报告，字段包含关键词文本、匹配模式、出价数值、搜索量、转化关联数据等，数据格式多为表格化结构化内容，常见导出格式为CSV或Excel。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的广告数据来源要求检索支持跨格式、跨字段的融合召回，避免因数据格式差异遗漏相关条目。日/周级的更新频率要求知识库配置定时增量同步任务，保障数据时效性。结构化的关键词、否词等文档，要求检索同时支持精确匹配与语义扩展，兼顾精准的规则查询与灵活的问题适配。最耗时的关键词扩展、否词筛选环节，要求召回结果需控制合理数量，避免超出模型上下文处理能力，同时需优先返回与用户技术支持问题强相关的条目，防止无效结果干扰决策。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75-0.85 | 平衡搜索广告关键词的语义相关性与召回覆盖范围，避免过高阈值过滤有效扩展关键词，过低阈值引入无关结果 |
| `limit` | 前10-15条 | 适配否词筛选、关键词扩展的业务场景，控制返回结果数量，避免超出模型上下文窗口 |
| `searchMode` | 语义+精确混合 | 同时支持精确匹配核心关键词、否词表条目，以及语义扩展相关的搜索词报告数据，覆盖售前与技术支持的不同查询需求 |
| `usingReRank` | 开启 | 对多源召回的结果进行重排序，优先返回与用户问题匹配度更高的条目，例如客户询问否词规则时优先展示对应否词表内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 对用户的口语化技术支持问题进行查询扩展，覆盖更多隐含的关键词相关文档，适配非结构化的用户提问 |
| `collectionIds` | 绑定专属搜索广告关键词管理知识库集合ID | 限定检索范围，避免跨品类文档干扰，提升检索精准度 |

## 容易做错的三处
- 现象：调用知识库检索接口时返回异常计费提示，原因是未使用自定义openapi token，使用平台默认token导致计费规则不匹配。
- 现象：检索结果仅返回少量结构化关键词条目，未覆盖扩展的搜索词相关内容，原因是`similarity`阈值设置过高，过滤了语义相关的扩展结果。
- 现象：发起QA搜索测试时弹出“当前分组default下对于模型gpt-4o-mini无可用渠道”的报错，原因是未在对应分组下配置gpt-4o-mini的可用渠道，或分组绑定错误。

## 怎么确认配好了
- 上传测试用的关键词清单、否词表与搜索词报告至对应知识库集合，发起包含“如何筛选否词”“扩展关键词有哪些”的测试查询，验证返回结果包含匹配的文档条目。
- 查看FastGPT v4.17.0版本的接口调用日志，确认检索请求使用的是自定义openapi token，无异常计费相关的日志记录。
- 检查配置中的`collectionIds`参数，确认绑定的是专属搜索广告关键词管理的知识库集合，避免检索到无关品类的文档。
- 调整`similarity`阈值至0.7和0.8，验证召回结果的数量变化符合预期，确认阈值配置生效。
