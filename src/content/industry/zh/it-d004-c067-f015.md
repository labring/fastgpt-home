# 数据安全分类分级的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自数据资产盘点结果、数据库元数据、业务系统说明文档及公开法规文件，日常维护的核心文档包括数据目录、分类分级规则表、重要数据识别清单与评审纪要。数据更新频率为季度级或对应业务系统变更时触发，文档结构多包含资产编号、敏感等级、归属系统、合规要求等字段，无统一固定单位，需随具体数据资产的属性调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且更新频率不均，会导致知识库内容新旧混杂，需定期同步最新的分类分级规则与数据资产清单以保证合规性。文档结构包含多维度精准字段，检索时需匹配资产编号、敏感等级等属性，避免泛化召回无关内容。单次召回的文档量需合理控制，避免合规相关的敏感内容过载影响AI判断，同时需确保评审纪要等时效性强的文档优先被检索到。另外，该品类覆盖个人信息以外的数据资产，检索时需区分不同业务系统的资产范围，防止跨系统数据混淆引发合规风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配数据安全分类分级场景的知识库检索与召回需求：

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | `0.75–0.85` | 该品类文档多为结构化规则与清单，需过滤低匹配度的无关数据，确保召回内容与合规要求强相关 |
| `limit` | `前8–12条` | 数据资产清单条目较多，过多召回会超出上下文窗口，同时保证覆盖主要的分级规则与资产信息 |
| `searchMode` | `vector+keyword` | 需同时匹配结构化字段（如资产编号）与文本规则（如分级标准），兼顾精准度与召回率 |
| `usingReRank` | `开启` | 需对召回结果按合规相关性排序，避免非核心规则或旧版评审纪要混入最终参考内容 |
| `datasetSearchUsingExtensionQuery` | `开启` | 可将用户的技术支持问题转化为扩展查询，覆盖分类分级规则的不同表述方式，提升检索覆盖率 |
| `collectionIds` | `绑定专属数据集ID` | 隔离该品类的知识库内容，避免与其他业务知识库混淆，防止跨品类检索干扰 |

## 容易做错的三处
- 现象为创建该品类专属知识库时进程卡住，ollama日志提示需降低批次大小。原因是未针对该品类的大文档（如完整数据资产盘点表）调整批次参数，单次加载的文档量超出模型支持上限。
- 现象为检索结果传入HTTP工作流后，AI无法正确引用知识库内容。原因是未返回包含文档元数据（如敏感等级、归属系统）的结构化格式，仅返回纯文本片段，导致AI无法识别引用依据。
- 现象为知识库召回结果条数与配置不符，出现大量无关的旧版评审纪要。原因是未设置`similarity`阈值，或阈值设置过低，导致低匹配度的非当前业务数据被召回。

## 怎么确认配好了
- 上传该品类的典型文档（如分类分级规则表），执行检索测试，确认匹配结果包含对应字段的内容。
- 查看知识库同步日志，确认最新的季度更新数据已完成同步，无报错信息。
- 调整`usingReRank`开关，对比前后召回结果的排序，确认重排功能生效。
- 测试跨业务系统的检索，确认仅召回绑定数据集内的内容，未混入其他品类的知识库数据。
