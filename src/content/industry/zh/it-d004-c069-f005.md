# 数据库运维的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来源于数据库监控系统、操作审计日志、SQL执行计划文件与内部工单系统。日常关联文档包含数据库变更单、慢查询性能报告、备份恢复记录与权限申请审批单。数据更新节奏随单次数据库变更触发或按日更新，单条数据包含数据库实例标识、操作执行时间、操作内容、关联工单编号等字段，无统一固定单位，随数据类型区分。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据库运维场景的多轮对话需关联数据库实例标识、工单编号等精准字段，因此对话上下文需保留`chatId`与`messages`中的历史交互标识，避免混淆不同实例的咨询。数据按变更触发或按日更新，提示词需适配动态更新的备份记录与慢SQL报告，需在对话启动时自动拉取最新关联数据。日常文档结构固定但字段多样，提示词需明确指定提取变更单编号、慢SQL指纹等字段，防止遗漏关键信息。运维场景错误后果直接关联数据安全，多轮对话需限制单次交互的上下文长度，避免加载冗余数据。

## 配置怎么定
本配置说明基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 适配数据库运维文档的单批次内容长度，避免截断关键SQL与变更信息 |
| `chatId` | 绑定数据库实例ID | 确保多轮对话关联对应实例的历史数据，避免跨实例混淆 |
| `messages` | 保留近20条交互记录 | 覆盖运维咨询的完整问题链路，如慢查询定位的多轮排查步骤 |
| `variables` | 注入当前工单编号与实例标识 | 自动关联用户咨询对应的内部工单与数据库实例，减少手动输入 |
| 交互超时时间 | 600 秒 | 适配慢查询分析、备份恢复验证等耗时较长的运维场景 |
| 附件上传上限 | 1000 MB | 支持上传大型SQL执行计划与备份日志文件 |

## 容易做错的三处
- 现象：添加的提示词未生效，模型返回无关内容。原因：未将提示词注入`variables`参数或未在对话初始化时触发加载，导致提示词未被纳入上下文。
- 现象：对话记录无法导出或无法定位到对应存储库。原因：未配置`chatId`关联的对话归档规则，导致系统未按实例分类存储交互日志。
- 现象：无法在对话中上传附件继续交互。原因：未调整附件上传上限配置，或未开启对话场景的附件权限，导致无法识别运维类大文件。

## 怎么确认配好了
- 发起包含数据库实例ID的咨询，检查对话上下文是否自动关联对应实例的历史数据。
- 上传符合配置上限的SQL执行计划文件，确认对话中可正常解析并关联当前咨询。
- 发送预设的测试提示词，检查模型输出是否严格遵循提示词要求的内容格式。
- 发起多轮交互，检查近20条的历史记录是否被完整保留并用于后续问答。
