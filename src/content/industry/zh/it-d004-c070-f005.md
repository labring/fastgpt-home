# 数据清洗与质检的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源包括原始数据集、ETL日志、标注平台输出与抽样结果，更新节奏为每日或按每批任务触发。日常产出的文档包含清洗规则、质检抽样表、异常数据清单与交付报告，各文档字段包含数据条目数、异常类型、处理状态、抽样批次等，无统一固定单位，随具体任务的数据集规格调整。本文内容基于 FastGPT v4.17.0 版本编写。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散导致对话需关联多类数据源的上下文，更新频率不稳定要求对话上下文需支持动态加载最新的清洗与质检数据。日常文档结构多样，提示词需适配不同文档的字段格式，避免固定模板的适配偏差。多轮对话需区分业务人员的不同角色，数据工程师关注清洗规则调整，质检员关注抽样结果验证，项目经理关注交付报告进度，需通过上下文记忆精准匹配角色需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按用户会话生成唯一标识，保留 24 小时有效期 | 区分不同业务用户的聊天记录，避免上下文跨会话混淆 |
| `messages` | 保留最近 8–12 轮对话上下文，过滤指定回复插件的冗余内容 | 适配数据清洗与质检场景的短平快对话需求，减少无效信息干扰 |
| `variables` | 传入当前任务的数据集 ID、抽样批次号 | 绑定具体业务数据，让提示词精准关联当前处理的清洗或质检任务 |
| 最大上下文长度 | 8000–12000 字符 | 适配清洗规则、异常数据清单等文档的常规长度 |
| 历史记忆开关 | 按实测标定 | 不同批次数据的上下文复杂度差异较大，需灵活调整 |

## 容易做错的三处
- 现象：对话历史中包含指定回复插件生成的冗余内容，导致AI生成的清洗建议偏离业务需求。原因：未在`messages`参数配置中过滤插件产生的非业务对话片段。
- 现象：部署后无法发起对话，界面返回密钥无效的报错。原因：未在系统配置页面正确填写AI密钥，或密钥未开通对应服务权限。
- 现象：不同业务用户的聊天记录互相可见，导致数据任务信息泄露。原因：未通过`chatId`为每个用户生成唯一会话标识，未隔离会话上下文。

## 怎么确认配好了
- 发起一条测试对话，输入当前任务的清洗规则摘要，核对AI回复是否关联了传入的`variables`参数中的业务标识信息。
- 开启多会话测试，使用不同`chatId`发起对话，确认各会话的历史记录互不干扰。
- 发送包含指定回复插件的测试内容，检查对话历史中是否保留了业务相关的对话片段，过滤了插件生成的冗余内容。
- 查看系统运行日志，确认每次对话的上下文未出现异常截断，符合配置的长度要求。
