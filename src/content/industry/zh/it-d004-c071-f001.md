# 数据脱敏处理的客户技术支持与售前答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据来源于企业数据库、数据字典、脱敏工具及访问审批系统，更新节奏按每批任务或单个项目推进。日常关联文档包含脱敏方案、字段映射表、脱敏验证报告与审批记录，核心字段涵盖敏感数据标识、脱敏规则编码、验证结果状态等，无固定通用单位，需结合具体项目的敏感数据类型匹配。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据按项目批次更新的特性要求接口需支持按项目标识拉取对应脱敏数据集，避免跨项目数据混淆。多来源的数据格式差异要求接口需兼容字段映射表的自定义字段结构，无法依赖固定数据模板。敏感数据的合规要求使得接口传输过程需强制启用加密校验，且需记录访问日志用于后续审计。同时，脱敏验证报告的同步需求要求接口需支持返回结构化的验证结果字段，便于外部系统对接合规流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ------------ |
| `Authorization` | 携带 Bearer 前缀的 2048 位随机密钥 | 用于接口身份校验，保障敏感数据访问权限 |
| `variables` | 绑定项目ID、敏感字段列表为固定变量 | 适配按项目批次更新的数据特征，简化调用参数 |
| `responseData` | 仅返回脱敏后字段、验证结果字段 | 匹配脱敏验证报告的文档结构，精简传输内容 |
| 接口超时设置 | 600 秒 | 适配单批次脱敏数据的处理时长，避免超时中断 |
| 单次请求数据量上限 | 1000 MB | 适配单批次脱敏数据的体积范围，避免传输过载 |
| 访问日志开关 | 开启全链路记录 | 满足合规审计需求，匹配审批记录的文档要求 |

## 容易做错的三处
- 现象为接口返回重复的脱敏数据片段，原因是未在`variables`中绑定唯一项目ID，导致多次调用拉取到同一批次的重复数据。
- 现象为接口返回401未授权状态码，原因是`Authorization`参数未携带正确的Bearer前缀，身份校验失败。
- 现象为脱敏验证报告字段为空，原因是未在`responseData`中配置验证结果字段的返回规则，导致接口未返回对应数据。

## 怎么确认配好了
以下核对动作适用于 FastGPT v4.17.0 版本：
- 调用接口携带正确的`Authorization`参数，检查返回状态码为200。
- 传入测试项目ID，核对返回数据的字段与项目的字段映射表一致。
- 查看接口日志，确认访问记录已被正确存储。
- 触发脱敏验证流程，核对返回的`responseData`包含验证状态字段。
