# 文本标注项目的客户技术支持与售前答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
文本标注项目的数据主要来自客户提供的语料、内部标注平台、专属词表以及质检抽样结果。日常关联文档包含标注规范、样本包、质检报告和问题反馈表。数据更新节奏通常为每日或按标注批次更新，核心字段涵盖标注文本、实体标签、语义边界说明、质检结果等。业务流程中最耗时的环节集中在标签边界解释、疑难样本仲裁与一致性抽检，数据异常会直接引发模型训练偏差、返工或交付延期，与图像标注项目相比，更侧重语义边界、实体识别与意图分类相关的内容。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
文本标注项目的数据特征会对HTTP接口与外部系统配置带来多维度约束。数据来源多样且批次性强，接口需要支持按批次拉取样本包、同步质检报告，需兼容多来源数据的格式校验。更新频率灵活，接口需支持动态调整拉取周期，适配每日或按批更新的节奏。核心耗时环节涉及标签边界解释，接口需要返回标准化的标签释义字段，辅助标注人员理解规则。数据异常的后果严重，接口需提供详细的错误反馈字段，便于快速定位标注偏差问题。同时，语义类标注的字段复杂度更高，接口需支持携带实体、意图等多维度标注参数，区别于图像类标注的像素级参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {API_KEY}，固定前缀加64位随机密钥` | 符合FastGPT v4.17.0版本的接口鉴权规范，保障数据调用安全 |
| `variables` | 传入样本批次ID、质检阈值两个自定义变量 | 适配文本标注项目按批次处理样本、绑定质检规则的业务需求 |
| `responseData` | 返回标注文本、实体标签、语义边界说明、质检结果四个核心字段 | 匹配文本标注项目的核心数据结构，减少后续数据清洗成本 |
| 请求超时时间 | 300–600 秒 | 文本标注的样本处理通常包含多轮校验，需预留足够的接口响应时长 |
| 拉取样本上限 | 前 200 条 | 单次拉取过多样本会增加网络传输负担，适配标注团队的日常处理规模 |

## 容易做错的三处
- 现象：调用工作流接口时无法获取MCP工具的执行过程日志，返回结果仅包含最终标注结果。原因：未在请求参数中开启日志追踪配置，未通过`responseData`指定返回工具调用链路字段。
- 现象：配置本地大模型接口时，相同参数调用后结果与线上API存在明显差异。原因：未针对文本标注的语义校验场景调整参数，直接沿用了通用对话场景的默认配置。
- 现象：调用API上传标注样本时出现超时错误。原因：单次上传的样本包大小超过接口限制，未按拉取样本上限的配置调整单次传输规模。

## 怎么确认配好了
- 发起单次样本拉取请求，核对返回字段是否包含预设的标注文本、实体标签等核心内容。
- 调用鉴权接口，确认返回状态码为200且无权限相关报错。
- 触发一次标注质检同步请求，核对接口是否能正确接收并返回质检结果。
- 查看接口日志，确认请求参数中的`variables`和`responseData`配置已正确生效。
