# 文本标注项目的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
文本标注项目的核心数据来自客户语料、标注平台产出内容、专用词表以及质检抽样结果。日常维护的文档包括标注规范、样本包、质检报告与问题反馈表。数据更新节奏通常为每日或按每批标注任务同步，不同文档有明确字段：标注规范含标签定义与边界说明，样本包包含待标注文本与对应标签字段，质检报告记录抽检偏差与整改项，问题反馈表记录标注异常与客户诉求。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且更新频繁，要求检索环节支持多源文档的实时同步召回，避免因数据滞后导致标注规范与实际标注要求不符。文档类型多样且字段明确，检索需精准匹配标签定义、样本边界等语义类内容。按批或每日更新的数据，需要检索链路支持增量更新的知识库同步，同时质检报告与问题反馈表的内容需快速召回，用于疑难样本仲裁与一致性抽检的实时参考，避免检索结果覆盖不全影响标注质量与交付进度。

## 配置怎么定
以下配置说明基于FastGPT v4.17.0版本。
| 界面设置项名 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.75–0.85 | 匹配标注规范中的标签定义与语义边界，避免过低引入无关结果，过高遗漏精准匹配的专业内容 |
| 单次搜索上限 | 6–10 条 | 覆盖单批标注任务的常见疑问类型，同时控制上下文长度适配模型输入限制 |
| 检索模式 | 语义检索 | 适配文本标注的语义类查询需求，如标签边界解释、样本意图识别等场景 |
| 重排开关 | 开启 | 对召回结果进行二次排序，提升疑难样本相关文档的展示优先级 |
| 问题优化开关 | 关闭 | 避免对标注样本的原始文本进行额外改写，保留标注数据的原始格式 |
| 检索范围 | 仅当前项目专属知识库 | 限定检索范围仅在当前项目的标注规范、样本包等文档内，避免跨项目文档干扰检索结果 |
| 文档上传限制 | 仅支持文本类文档 | 符合文本标注项目的数据源要求，避免非文本内容干扰检索流程 |

## 容易做错的三处
-  界面提示`invalid configuration parameter name "hnsw.iterative_scan"`，原因是误使用了FastGPT官方参数清单以外的检索配置项，未采用指定的合规参数。
-  知识库搜索结果条数与设置的单次搜索上限不符，原因是未正确限定检索范围，导致检索覆盖了非当前项目的知识库文档，额外返回无关结果。
-  模型输出时出现多余空格与字母大写修改，原因是开启了问题优化开关，导致对标注样本的原始文本进行了不必要的改写，违背了标注数据的原始格式要求。

## 怎么确认配好了
-  上传当前项目的标注规范、样本包、质检报告与问题反馈表，创建专属知识库，确认检索范围已绑定该知识库。
-  发起一条标签边界解释的查询，检查返回结果的匹配度是否落在预设区间内。
-  查看检索结果条数，确认与设置的单次搜索上限一致，无额外无关文档返回。
-  测试输入包含样本疑问的查询，检查模型输出是否保留原始文本格式，未出现多余空格或字母大写修改。
-  在Ubuntu系统下检查知识库文件的上传路径，确认文档已成功同步至平台。
