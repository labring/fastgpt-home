# 文档站维护的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
本品类的日常文档包含安装文档、API文档、迁移指南与FAQ三类，数据来源为代码仓库、文档站构建日志、用户反馈及版本发布记录。更新节奏多为每周一次或随软件版本发布同步。文档结构按功能模块拆分，包含操作步骤、参数说明、版本差异说明等内容，部分文档附带版本号、更新时间、关联接口路径等元数据字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
文档数据随版本高频更新，要求多轮对话上下文需及时关联最新版本元数据，避免引用过期内容。多类文档结构差异大，提示词需适配不同文档类型的查询逻辑，例如API文档需优先匹配接口路径字段，FAQ需直接匹配问题条目。用户反馈数据会持续补充新的常见问题，对话历史需定期同步新增的问题库内容。代码仓库与构建日志的结构化数据，要求对话系统可识别版本号字段，快速定位对应版本的文档内容。单次咨询的轮次通常有限，上下文加载需控制范围以提升响应速度。

## 配置怎么定
本页面配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 800–1200 字符 | 适配单篇文档的核心内容长度，避免上下文溢出 |
| 上下文关联轮次 | 前 3 轮对话 | 匹配文档站用户单次咨询的典型轮次，减少无效数据加载 |
| 超时时间 | 300 秒 | 适配文档站查询的平均响应时长，避免长文档查询中断 |
| 变量绑定规则 | 绑定文档版本号、接口路径 | 关联品类数据中的元数据字段，确保对话匹配最新内容 |
| `messages` 格式 | 按`user`/`system`角色拆分 | 符合多轮对话的标准交互逻辑，便于上下文解析 |
| `chatId` 配置 | 绑定用户会话唯一标识 | 实现对话记录的独立存储与查询 |
| `variables` 配置 | 传入当前文档的版本号 | 用于过滤对应版本的文档内容 |

## 容易做错的三处
- 现象：调用对话接口返回`400 Bad Request`，提示上下文格式错误。原因：未按`messages`要求的角色拆分消息，混入未定义的消息类型。
- 现象：调用对话记录查询接口后返回空数据。原因：未正确绑定`chatId`参数，无法定位目标会话。
- 现象：对话返回的文档内容与查询的文档类型或版本不符。原因：未针对不同文档类型调整提示词逻辑，或未在`variables`中传入最新的文档版本号，导致匹配错误。

## 怎么确认配好了
- 发起一轮包含版本号查询的对话，核对返回内容是否匹配当前最新版本的安装文档。
- 发起连续3轮的咨询，查看会话存储的上下文是否包含完整的`messages`序列。
- 调用对话记录查询接口，传入已知的`chatId`，确认返回的会话数据不为空。
- 传入自定义`variables`参数，核对对话系统是否能基于该参数过滤对应版本的文档内容。
