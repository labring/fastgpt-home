# 文档站维护的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
这个品类的数据主要来自代码仓库、文档站构建日志、用户反馈与版本发布记录。日常产出的文档包含安装文档、API文档、迁移指南与FAQ，通常按功能模块分章节，附带版本标记与代码示例块。数据更新节奏为每周迭代或随版本发布同步，字段包含文档版本号、最后更新时间、关联代码分支等，无统一固定单位，随文档类型调整。

## 这些特征在「重排与混合检索」这一环带来什么约束
文档站维护的文档多为技术说明类，包含代码片段、版本差异说明与结构化FAQ，混合检索需区分不同类型内容的权重，避免代码示例与文字说明混淆召回。数据更新频率较高，需确保检索索引能快速同步最新版本内容，防止召回过期文档。文档按功能模块分章节，重排环节需优先匹配用户问题对应的功能模块，聚焦具体的技术说明内容。同时用户反馈补充的高频疑问需整合进检索池，提升精准匹配度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.62–0.78 | 过滤匹配度过低的非相关文档，适配技术文档的精准检索要求，避免召回过期或不相关的版本说明 |
| `limit` | 前6–10条 | 控制初始召回的结果数量，避免上下文超出模型处理上限，适配文档站的长文本特性 |
| `searchMode` | hybrid | 开启混合检索模式，整合语义匹配与关键词匹配，覆盖不同提问方式的用户，比如直接搜索API名称或功能场景 |
| `usingReRank` | 开启 | 对初始召回结果进行二次排序，优先返回与用户问题最贴合的技术内容，提升售前答疑与客户支持的响应质量 |
| 重排模型超时阈值 | 25–35 秒 | 适配文档站维护的批量索引与实时答疑场景，防止请求阻塞导致索引中断或响应延迟 |

## 容易做错的三处
- 现象：开启`usingReRank`后，在线召回测试未返回重排后的结果。原因：未在知识库索引环节同步开启重排配置，或未绑定有效的重排模型接口。
- 现象：重排模型调用时返回报错信息。原因：未配置正确的重排模型地址与密钥，或模型版本与FastGPT v4.17.0兼容要求不匹配。
- 现象：调用重排模型时显示`Invalid URL (POST /v1/rerank)`。原因：重排模型的接口路径配置错误，或代理服务未正确转发重排请求。

## 怎么确认配好了
- 进入FastGPT v4.17.0版本的知识库检索测试页面，输入对应文档的关键词，查看初始召回结果与重排后的结果是否存在差异。
- 查看知识库索引日志，确认重排模型的调用状态为成功，无超时或报错记录。
- 调整`similarity`参数的取值范围，验证检索结果的匹配度是否随配置变化而调整。
- 手动触发一次全量索引，确认重排配置随索引任务同步生效。
