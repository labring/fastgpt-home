# 日志平台与可观测性的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自日志系统、Trace平台、Metrics系统与应用SDK，日常维护的文档包括日志采集规范、链路追踪说明、指标字典、看板配置记录。数据更新频率为每日或每版本发布时更新，文档结构多包含字段定义、采集规则、排查流程与配置示例，字段多涉及日志级别、Trace ID、指标名称与阈值范围，无统一强制单位，需结合具体采集场景匹配。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据特征对检索召回带来多重约束。多源数据来源要求检索需支持跨日志、链路追踪、指标系统的文档整合召回；高频更新节奏要求配置适配日更或版本级别的数据同步，避免召回过时的采集规范或排查流程；文档包含技术字段与配置示例，要求检索精准匹配日志级别、Trace ID等专业关键词；高频耗时的链路排查场景，要求召回结果需包含完整的上下文证据，保障故障定位的效率。

## 配置怎么定
本文配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.72–0.85` | 匹配日志与链路排查的专业术语精度，避免过严导致召回不足或过松引入无关内容 |
| `limit` | `前8–12条` | 覆盖单次排查所需的上下文片段，同时控制上下文窗口长度 |
| `searchMode` | `vector + fulltext` | 兼顾专业术语的语义匹配与关键词的精确召回，适配日志字段与链路ID的检索需求 |
| `usingReRank` | `开启` | 对召回的多源文档进行二次排序，提升链路排查场景的结果相关性 |
| `datasetSearchUsingExtensionQuery` | `开启` | 自动扩展检索词，覆盖采集规范中定义的字段别名与常用排查句式 |
| `collectionIds` | `按业务域绑定指定集合ID` | 隔离不同业务线的日志与可观测性文档，避免跨域召回干扰 |

## 容易做错的三处
- 知识库上传后状态长时间停留在索引中。原因：未配置适配日志与可观测性文档的分块参数，大体积的看板配置记录或链路追踪文档导致索引耗时过长。
- 调用知识库时无法正确显示内嵌图片。原因：未开启图片关联检索配置，或检索时未携带图片资源的路径参数，导致回复中仅返回文本内容。
- 变量引用格式配置错误导致检索失败。原因：误用非标准的变量包裹格式，未匹配FastGPT要求的变量引用规则，导致系统无法解析采集规范中的字段变量。

## 怎么确认配好了
- 上传单份日志采集规范文档，检查索引完成状态是否在合理时间内更新，确认分块参数适配文档体积。
- 发起包含Trace ID关键词的检索，检查召回结果是否包含链路追踪说明与对应看板配置记录，验证多源文档整合功能。
- 配置测试变量引用，发起包含自定义字段的检索，确认系统能正确解析并匹配文档中的字段定义。
- 开启重排功能后发起检索，对比开启前后的结果排序，验证重排配置生效。
