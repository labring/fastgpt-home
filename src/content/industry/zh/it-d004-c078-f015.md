# 机柜上架与布线的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
典型主体为IDC运维工程师、网络工程师、设备实施人员，日常文档包含上架申请、机柜布线图、端口标签表、施工记录。数据来自DCIM系统、资产系统、网络拓扑图、客户工单，更新频率为每单或每日。上架申请包含申请单号、设备型号、机位需求字段；机柜布线图标注U位、线缆类型；端口标签表记录端口编号与对应设备接口；施工记录留存验收时间与接线细节。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源要求知识库支持对接不同系统的结构化与非结构化文档；按单/日的更新节奏需要配置增量同步逻辑，避免全量检索的冗余开销。文档结构差异大，既有表格化的端口标签表，也有图文结合的布线图文本，需要适配不同格式的召回规则。新增或变更设备物理接入的业务属性，要求知识库区分存量设备与新增设备的文档，避免巡检类文档的干扰。机位规划、线缆核对的高耗时环节，需要精准召回匹配用户查询的具体机位、端口信息，降低人工核对成本。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配机柜布线、端口标签这类结构化文本，过滤低相关的冗余结果 |
| `limit` | 前6条 | 单条售前或支持查询涉及的机位、端口数量有限，过多结果会干扰决策 |
| `searchMode` | 精准匹配 | 适配上架申请、端口标签表这类强结构化文档，提升召回精准度 |
| `usingReRank` | 开启 | 对初步召回的结果按语义重排，修正关键词匹配的偏差，控制检索耗时在3秒内 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题生成扩展查询，覆盖不同表述的机位、线缆需求 |
| `collectionIds` | 按机柜区域分组 | 缩小检索范围，减少无关文档的召回，提升查询速度 |

## 容易做错的三处
- 现象：检索返回知识库外的线缆选型建议，且未提示无法回答。原因：未配置`similarity`阈值，低相关文档被召回，且未开启知识库外内容的拒答逻辑。
- 现象：模型输出语言与预设的英文要求不符，即使知识库与prompt均为英文。原因：未针对英文场景开启`datasetSearchUsingExtensionQuery`，且语种绑定配置未匹配英文知识库。
- 现象：检索耗时过长，无法支撑实时售前答疑。原因：未限制`limit`参数的召回数量，或未开启轻量化的`usingReRank`模式。

## 怎么确认配好了
- 上传一份机柜布线图与端口标签表，发起包含「U12机位的网线端口对应哪个交换机」的查询，核对召回结果是否包含对应文档片段。
- 调整`similarity`参数至0.8，发起模糊查询如「某机房的上架要求」，确认低相关结果被过滤。
- 查看知识库更新日志，确认每单提交的施工记录、上架申请按日增量同步至知识库。
- 测试英文查询如「Which port corresponds to server in U8」，确认召回英文文档且模型输出英文内容。
