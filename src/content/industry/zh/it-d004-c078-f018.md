# 机柜上架与布线的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
通常，该品类的数据来自DCIM系统、资产管理系统、网络拓扑图与客户提交的工单。日常文档包含上架申请单、机柜布线图、端口标签表、施工记录单，字段包含机位编号、线缆规格、端口映射关系、施工时间等。数据更新频率为每单每日，每份文档对应单次设备上架或变更的全流程信息，无统一聚合的批量数据。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据按单更新且关联特定机位与设备，要求检索需精准匹配工单关联的机柜范围，避免跨单冗余结果。文档包含物理位置、线缆参数等强关联字段，混合检索需同时匹配文本语义与结构化字段属性。单份文档长度差异较大，从简短的申请单到复杂的布线图解析文本，需适配不同长度的召回与重排逻辑。数据来源分散，需整合多系统的结构化与非结构化内容，对检索的跨源匹配能力提出要求。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写，以下为针对该场景的配置建议：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.72–0.80 | 精准匹配机柜编号、端口标签等结构化字段，过滤低相关结果 |
| 单次搜索上限 | 前10条 | 适配单工单关联的有限文档量，避免冗余信息干扰售前与技术支持对话 |
| 检索模式 | 混合检索 | 同时覆盖语义文本与结构化机位数据，匹配上架申请与布线图的关联信息 |
| 启用重排 | 是 | 对初始召回结果进行二次排序，修正跨机柜文档的误匹配问题 |
| 重排模型显存限制 | 1000 MB | 适配机柜布线图等大尺寸文档的解析，防止显存占用过高 |
| 上下文长度 | 800–1200 字符 | 匹配单份施工记录或端口标签表的典型长度，优化检索召回精度 |

## 容易做错的三处
- 现象：重排模型运行后显存持续占用无法释放，最终触发内存不足报错。原因：未配置自动显存回收策略，未限制重排模型的最大显存占用阈值。
- 现象：检索结果仅返回单类文档，无法同时匹配上架申请与布线图信息。原因：未将检索模式设置为混合检索，仅启用了纯语义检索。
- 现象：配置重排模型后点击测试提示错误，强行运行后结果异常。原因：未在知识库配置中绑定对应品类的文档解析规则，导致布线图等格式文档无法被正确识别。

## 怎么确认配好了
- 提交包含机柜编号或端口标签的关键词检索，检查返回结果是否包含对应机位的布线图与端口标签表。
- 查看系统检索日志，确认重排模型被正常调用，且返回结果的排序符合语义相关性逻辑。
- 调整相似度阈值区间，观察检索结果的数量变化，验证阈值配置是否生效。
- 测试上传大尺寸机柜布线图文档的检索，确认未触发内存不足报错，验证显存限制配置是否生效。
