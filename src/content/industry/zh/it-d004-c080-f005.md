# 桌面终端支持的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
桌面终端支持的业务数据主要来自终端管理平台、资产系统、用户报障渠道、软件仓库四类来源。日常产生的文档包含终端故障单、装机清单、软件安装记录、远程协助记录，单份文档包含终端序列号、硬件型号、软件版本、报障时间、处理进度等字段。数据更新频率为每日批量同步或按用户请求实时更新，单条记录的核心关联维度为终端设备的唯一标识，不同文档间通过该标识形成关联关系。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源分散的数据来源要求多轮对话需通过唯一标识关联不同类型文档，避免跨终端的信息混淆。文档结构零散且字段明确的特点，要求提示词需限定检索范围为终端相关的故障、装机、安装记录，减少无关信息干扰。按日或实时更新的数据节奏，要求对话上下文需匹配数据更新周期，避免使用过期的软件安装或故障处理记录。单会话故障排查的典型流程，要求多轮对话保留历史交互的`messages`，减少工程师重复输入终端信息的操作，同时避免上下文过载影响推理效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文窗口 | 前 8 轮对话或 4000 字符 | 匹配桌面终端支持单会话故障排查的典型交互轮次，避免过长上下文导致模型推理延迟 |
| `messages`历史保留时长 | 7 天 | 对应业务中历史故障单的平均查询周期，支持跨多天的连续故障排查 |
| `variables`会话变量绑定 | 绑定终端序列号、报障部门 | 快速关联对应资产系统的专属记录，缩小检索范围，提升排查精准度 |
| 单次召回文档上限 | 前 6 条 | 匹配故障排查时常用的参考文档数量，避免信息冗余干扰排查思路 |
| 上下文更新触发方式 | 按请求触发 | 匹配业务数据的日/实时更新节奏，实时获取最新的软件安装或远程协助记录 |
| 问题优化开关 | 开启 | 针对零散的终端故障描述，优化用户提问的召回精度，提升匹配效率 |

## 容易做错的三处
- 刷新页面报“检测到没有可用的索引模型”，原因是未绑定桌面终端支持专属的资产系统数据源，或`variables`未正确关联索引配置。
- 对话接口无法返回查看来源原文，原因是未开启源文档召回开关，或`messages`中未携带源文档标识参数。
- 历史对话无法继续交互，原因是未保留`chatId`会话标识，或上下文窗口设置过短导致历史`messages`被截断。

## 怎么确认配好了
- 在FastGPT v4.17.0平台中发起一条包含终端序列号的故障提问，检查返回结果是否关联了对应终端的装机清单或历史故障单。
- 切换不同的终端会话后，检查`chatId`是否自动更新，确保不同终端的对话上下文完全隔离。
- 发起多轮连续提问，检查历史`messages`是否被正确保留，无需重复输入终端序列号或故障细节。
- 查看配置面板，确认单次召回文档上限、问题优化开关等参数已按实测标定值完成设置。
