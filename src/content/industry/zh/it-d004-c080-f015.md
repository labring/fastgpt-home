# 桌面终端支持的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的日常文档包含终端故障单、装机清单、软件安装记录、远程协助记录，字段覆盖设备MAC地址、操作系统版本、报错代码、用户工位号、修复动作、操作时长等。数据来源为终端管理平台、资产系统、用户报障渠道、软件仓库。更新频率为每日增量更新或随单次服务请求实时更新。文档类型涵盖结构化的设备信息与非结构化的故障排查步骤，格式以纯文本、Markdown为主，部分记录包含操作日志片段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据特征为检索召回环节带来多重约束。数据分散于多套系统且类型多样，涵盖结构化设备信息与非结构化排查步骤，要求检索需兼顾关键词匹配与语义理解，避免单一模式遗漏关键内容。更新频率灵活，支持每日增量或随请求实时更新，要求知识库支持近实时同步，避免滞后数据影响排查参考价值。文档聚焦终端场景，限定检索范围可减少无关干扰，同时故障记录的准确性直接关联服务效率，要求召回结果需具备较高的匹配精准度。另外，用户报障多为口语化描述，需对查询进行优化以匹配专业术语，提升检索匹配效果。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 桌面终端故障的描述通常包含明确的报错代码与设备特征，阈值过低会引入无关的非终端类故障文档，过高则可能漏召回同类型但细节有差异的记录 |
| `limit` | `前6–10条` | 桌面终端支持的常见故障排查步骤通常集中在有限的场景，过多召回会超出大模型上下文窗口，影响对问题的理解与回复生成 |
| `searchMode` | `semantic+keyword` | 该品类数据包含结构化的设备型号、报错代码（适合关键词匹配）与非结构化的排查步骤（适合语义匹配），混合模式可兼顾精准度与召回率 |
| `usingReRank` | 开启 | 桌面终端故障存在较多相似表述，例如不同硬件场景下均可能出现“蓝屏”现象，重排可优先召回匹配度更高的修复步骤 |
| `datasetSearchUsingExtensionQuery` | 开启 | 用户报障多为口语化描述，例如“电脑卡”，优化后的查询可补充“系统卡顿”“CPU占用高”等专业术语，提升检索匹配度 |
| `collectionIds` | 填入当前项目下终端运维专属知识库的集合ID列表 | 该品类数据仅包含终端相关文档，限定集合可排除无关的IT服务台工单数据，减少检索干扰 |

## 容易做错的三处
- 现象为工作流日志显示未发起配置的HTTP请求，仅返回大模型生成的独立内容，原因是未在知识库检索节点后正确绑定HTTP请求节点，或未将检索结果作为请求的上下文参数传入。
- 现象为导入Markdown格式的文档后，原一级二级标题未被保留，仅显示正文内容，原因是导入知识库时未开启Markdown格式解析开关，或分块配置未保留标题层级信息。
- 现象为大模型生成的回复中夹杂“引用标记：［1］”字样，原因是未配置检索结果的引用格式过滤，或大模型提示词未明确要求隐藏引用标记的前缀文字。

## 怎么确认配好了
- 查看知识库集合的文档列表，确认仅包含终端故障单、装机清单等该品类的专属文档，无无关的跨品类数据。
- 发起一条包含明确报错代码的测试查询，检查检索召回的结果中是否包含匹配的故障排查记录，且结果数量符合配置的`limit`取值。
- 查看工作流运行日志，确认知识库检索节点完成后触发了配置的HTTP请求，且传入了正确的检索结果上下文参数。
- 生成一条测试回复，检查回复中未出现格式错误的引用标记，且内容与检索到的文档匹配度符合预期。
