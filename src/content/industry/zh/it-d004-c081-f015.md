# 渗透测试服务的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自目标系统、公开漏洞库、自动化扫描器结果与手工攻击验证记录。日常产出的文档包含测试授权书、渗透测试报告、漏洞复现记录、整改建议等，单份文档通常包含项目编号、漏洞等级、复现步骤、授权范围等字段。数据更新以单项目为单位，每个项目完成或重大漏洞版本更新时同步更新知识库内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据特征对检索召回环节带来多重约束。首先，数据包含结构化扫描结果与非结构化手工验证记录，需适配多格式内容的精准召回。其次，数据以单项目为单位更新，需支持按项目维度增量同步知识库，避免冗余数据干扰检索。另外，文档包含测试授权范围与漏洞等级字段，检索时需关联过滤非授权项目的内容，防止出现法律授权争议。同时，漏洞复现步骤的细节密度较高，需限制召回片段的长度，避免上下文过载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 渗透测试文档包含大量专业安全术语，该区间可过滤低相似度的无关内容，避免召回非相关的漏洞报告 |
| `limit` | 前8–12条 | 渗透测试报告的内容细分维度较多，适量召回可覆盖不同漏洞类型的参考信息，同时控制上下文总长度 |
| `usingReRank` | 开启 | 渗透测试场景的检索结果易受术语同义词干扰，重排可提升高相关内容的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 客户售前问题常包含模糊的漏洞描述，扩展查询可补充相关安全术语，提升召回覆盖度 |
| `collectionIds` | 按项目分组配置对应集合ID | 渗透测试数据按项目隔离存储，按集合ID检索可避免跨项目的敏感授权数据泄露 |
| 分块长度 | 800–1200 字符 | 渗透测试文档的漏洞复现步骤细节较多，该区间可保留完整的步骤信息，避免截断关键内容 |
| 检索超时时间 | 60–120 秒 | 渗透测试文档的内容较长，该区间可保证完整的检索过程完成 |

## 容易做错的三处
- 上传包含图片的DOCX文档时提示文件格式不正确。原因是未正确配置文档解析插件的图片处理逻辑，或上传文件超出知识库支持的100 MB单文件大小限制。
- 配置问答拆分模式后无法实现图片内容的问答召回。原因是未开启图片OCR文本提取配置，或检索环节未关联图片解析后的文本内容。
- 调用外部程序上传HTML标题与内容的接口时，无法将内容正确关联到指定知识库。原因是未按接口要求传递`title`和`content`字段，或字段格式不符合接口规范。

## 怎么确认配好了
- 检查FastGPT v4.17.0版本下App/Admin服务端的AI Proxy环境变量`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，不得附加`/v1`等路径后缀）和`AIPROXY_API_TOKEN`（AI Proxy管理员Token，需与AI Proxy服务端配置一致且非空）是否已正确配置。
- 上传一份包含图片的渗透测试报告DOCX文档，验证解析是否成功，无格式报错提示。
- 发起一条包含模糊漏洞描述的售前咨询，核对检索结果的条数与配置的`limit`参数范围一致，且排序符合预期。
- 调用外部上传接口传递HTML标题与内容，验证内容是否成功同步到指定知识库集合。
