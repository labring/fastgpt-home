# 游戏内容合规自查的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
本品类的数据主要来自游戏研发与发行环节的日常产出与合规相关文档，包括游戏文本、剧情脚本、美术资源说明，以及内容自查表、敏感内容修改记录、用户协议、合规评审纪要等内部文档。数据更新随游戏版本迭代或活动上线节奏进行，每版本或每活动更新一次。文档多为结构化与半结构化混合，包含文本段落、字段标注、评审意见等内容，无统一固定格式，部分文档附带关联的资源路径与版本号。

## 这些特征在「重排与混合检索」这一环带来什么约束
游戏内容合规自查的文档多为随版本迭代更新的非标准化内容，且需关联对应版本的监管要求，因此重排与混合检索需适配高频更新的数据集。不同文档的字段差异大，检索时需优先匹配与当前合规场景强相关的内容，避免无关文档干扰。美术资源与文本的关联检索需求，要求检索链路同时支持文本与元数据的混合匹配。版本更新带来的数据增量，需确保检索与重排流程的响应速度适配快速迭代的业务节奏，避免因数据量增长导致检索延迟。合规场景对检索结果的相关性要求更高，需避免遗漏敏感内容或引入无关信息，对检索与重排的参数精度提出了更严格的要求。

## 配置怎么定
| 配置项               | 建议取法               | 这样取的依据 |
| ----------------------|------------------------|------------------------------------------------------------------------------ |
| `usingReRank`        | 开启                   | 游戏合规自查需精准匹配敏感内容与监管要求，重排可过滤低相关检索结果，提升合规判断效率 |
| `similarity`         | 0.70–0.85              | 合规场景需严格控制检索相关性阈值，避免遗漏敏感文档或引入无关内容，按实测标定 |
| `limit`              | 前8–12条               | 平衡合规文档的覆盖范围与检索响应速度，单次返回上限适配版本更新后的数据集规模 |
| `searchMode`         | hybrid                 | 适配游戏合规数据包含文本、元数据与资源关联信息的特征，混合检索可同时匹配语义与属性标签 |
| 重排模型调用超时     | 30–60秒                | 合规文档多为长文本，需预留足够的重排模型处理时间，避免因超时中断检索流程 |

## 容易做错的三处
- 离线部署FastGPT v4.17.0后配置重排模型，点击模型测试提示请求错误。原因是离线环境未正确加载重排模型的本地依赖包，或配置路径未指向本地模型文件。
- 知识库问答开启重排后检索速度过慢。原因是单次检索返回的`limit`条数设置过高，且合规文档多为长文本，重排模型处理长文本的耗时随结果条数增加显著提升。
- 配置重排模型后检索结果为空或相关性不足。原因是`similarity`阈值设置过高，导致符合要求的检索结果被过滤，或`searchMode`未适配合规文档的混合数据结构。

## 怎么确认配好了
- 进入知识库的检索配置页面，确认`usingReRank`开关处于开启状态。
- 输入一条合规相关的测试问题，查看检索结果的排序逻辑，确认高相关文档优先展示。
- 模拟版本更新后的数据集增量，执行批量检索测试，确认检索响应时间符合业务节奏要求。
- 调用模型测试接口，验证重排模型可正常返回结果，无超时或报错提示。
