# 游戏策划与数值设计的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的日常文档包含玩法策划案、数值表、版本需求单、平衡性测试记录，数据来源包括玩家行为数据、竞品公开资料、战斗日志与版本反馈。更新频率多为周度或每版本周期。文档多包含结构化数值字段、规则描述文本，部分数值表带有明确单位如伤害倍率、升级所需经验值，数据需随版本迭代快速更新。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化数值表与规则文本混合的文档结构，要求检索需同时支持语义匹配与精准字段匹配；高频更新的版本数据要求检索链路支持快速刷新知识库；多来源的玩家与战斗日志数据，需区分公开资料与内部测试数据的检索权限；数值类内容的检索结果需保证精度，避免模糊匹配导致的规则偏差；版本反馈的时效性要求召回结果优先匹配最新版本的文档内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.88 | 适配数值规则与结构化文档的精度要求，避免低匹配度的无关内容干扰检索 |
| `limit` | 前8–12条 | 控制单次召回的内容总量，适配策划文档中长数值表与规则文本的上下文承载 |
| `searchMode` | 混合语义与精准匹配 | 同时覆盖玩法逻辑的语义查询与数值字段的精准检索需求 |
| `usingReRank` | 开启 | 对初始召回结果重新排序，优先返回与当前版本规则、数值设计相关的内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动优化专业术语的检索关键词，适配游戏策划的专属表达习惯 |
| `collectionIds` | 指定对应游戏项目的知识库集合ID | 隔离不同游戏版本的文档数据，避免跨项目的无效检索 |

## 容易做错的三处
- 现象：上传的数值表文档无法正确分块，出现长文本截断或字段拆分混乱。原因：未针对结构化表格文档调整分块规则，默认分块逻辑无法识别表格的行列结构。
- 现象：新建知识库时无法配置图片理解模型，导致包含战斗图表的策划文档无法被正确解析。原因：未在部署环节启用对应模型插件，或当前版本未集成图片理解能力。
- 现象：检索结果中混入非当前版本的旧版玩法文档，无法匹配最新版本需求。原因：未指定`collectionIds`参数，检索范围覆盖了全量知识库集合。

## 怎么确认配好了
- 上传一份典型的数值表文档，执行分块测试，确认表格的行列结构被正确识别，未出现截断或拆分混乱。
- 输入一条包含专业策划术语的查询，查看检索结果的相关性，确认`usingReRank`与`datasetSearchUsingExtensionQuery`的配置生效。
- 切换不同版本的知识库集合，验证`collectionIds`参数是否正确限定了检索范围，仅返回对应版本的文档内容。
- 使用FastGPT v4.17.0版本的平台进行测试，调整`similarity`参数的取值区间，测试不同阈值下的检索结果数量，确认匹配精度符合当前业务需求。
