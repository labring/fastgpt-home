# 游戏策划与数值设计的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
游戏策划与数值设计的日常文档包含玩法策划案、数值表、版本需求单、平衡性测试记录。数据来源主要为玩家行为数据、竞品公开资料、战斗日志与版本反馈。文档更新频率为周度或每版本周期，字段通常包含规则触发条件、伤害系数、留存目标值等，涉及的单位包括倍率、时间区间、百分比区间等。不同文档的结构差异明显，数值表为结构化表格形式，策划案为非结构化文本形式，版本需求单则混合了文本描述与量化指标。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的文档结构差异大、更新频率高，要求重排与混合检索需适配多类型数据的混合匹配。结构化数值表的字段精度要求高，混合检索需兼顾语义匹配与字段精准匹配，避免召回无关的版本反馈或策划片段。周度/版本级的更新节奏要求检索逻辑可快速适配新上传的文档块，同时需控制检索结果的上下文长度，避免超出模型处理上限。售前答疑场景需快速召回关联的规则与历史版本数据，对检索的召回范围与排序权重有明确要求，需优先返回与当前提问相关的数值规则或玩法说明。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 重排开关 | 开启 | 该品类需过滤低匹配度的数值表与策划案片段，重排可提升结果相关性 |
| 相似度阈值 | 0.72–0.85（按实测标定） | 数值字段匹配精度要求高，需高于通用场景阈值避免无关召回 |
| 单次召回上限 | 前10条 | 兼顾上下文长度与关键信息覆盖，适配周更/版本更的文档规模 |
| 检索模式 | 混合检索 | 兼顾语义匹配与结构化字段匹配，适配策划案文本与数值表数据 |
| 重排模型 | 本地部署的轻量模型 | 该品类数据需内网处理，本地部署可保障数据安全且响应稳定 |
| 上下文长度 | 8000–12000 token | 容纳多份策划案与数值表片段，满足售前答疑的规则整合需求 |

## 容易做错的三处
- 现象：对话详情中未显示重排模型的调用记录，检索结果排序与初始召回结果一致。原因：未在FastGPT v4.17.0的配置文件中正确启用重排开关，或未绑定混合检索模式。
- 现象：配置重排后，检索结果仅返回单条最高相似度内容。原因：误将重排后的返回条数设为1，或未正确配置重排模型的召回数量参数。
- 现象：内网可ping通重排模型，但对话中未触发重排逻辑。原因：配置文件中的重排模型路径填写错误，或未将知识库关联至重排配置项。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库配置页面，查看重排开关是否处于开启状态。
- 发起包含数值规则或玩法描述的测试提问，查看检索结果的排序是否与初始召回结果不同。
- 导出对话详情日志，检查是否包含重排模型的调用记录与返回结果。
- 调整相似度阈值，验证检索结果的召回数量是否随阈值变化而调整。
