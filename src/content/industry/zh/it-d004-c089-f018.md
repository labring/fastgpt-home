# 漏洞扫描服务的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
漏洞扫描服务的数据来源包括漏洞扫描器、资产清单、CVE库、补丁公告，更新频率为周或月。日常产出的文档包含扫描计划、漏洞清单、整改工单、复扫报告四类，其中扫描计划包含资产范围、扫描周期字段，漏洞清单包含CVE编号、危害等级、修复状态字段，整改工单关联对应漏洞与修复责任人，复扫报告包含复扫结果与整改完成率。各类文档的字段与单位差异明显，例如扫描时长以小时为单位，漏洞数量以条为单位。

## 这些特征在「重排与混合检索」这一环带来什么约束
由于数据来源多样且更新周期为周或月，混合检索需要整合嵌入检索与关键词检索两种模式，以覆盖不同类型文档的检索需求。文档结构包含四类业务场景，重排环节需要区分不同文档的权重，优先召回高危漏洞相关内容。更新频率的不确定性要求定期刷新索引，避免检索到过期的补丁公告或复扫结果。同时，该品类的出错后果直接关联高危漏洞暴露风险，因此重排与混合检索需要保证结果的精准度，过滤低相关性的误报内容。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `usingReRank` | 开启 | 针对漏洞清单、复扫报告这类结构化数据，开启重排可过滤低相关性的误报结果 |
| `similarity` | 0.72–0.85 | 匹配资产范围、CVE编号这类精准字段，该区间可平衡召回率与精准度，按实测标定 |
| `limit` | 前10条 | 限制返回结果数量，适配整改工单、复扫报告的单页展示长度 |
| `searchMode` | hybrid | 整合嵌入检索与关键词检索，适配异构的漏洞扫描相关文档类型 |

## 容易做错的三处
- 现象为调用重排模型返回空内容，原因是未正确配置模型的API访问密钥与请求域名，或使用了与文档格式不兼容的重排模型版本。
- 现象为本地部署的ollama重排模型无法正常调用，原因是未在FastGPT中正确填写自定义请求地址，或未开放模型服务的端口权限。
- 现象为检索结果中误报漏洞条目过多，原因是未设置合理的`similarity`阈值，或未开启重排环节对结果进行二次过滤。

## 怎么确认配好了
- 上传一份近期的漏洞清单文档，输入测试问题如「当前高危漏洞列表」，查看检索结果是否包含对应CVE编号与危害等级信息。
- 开启重排功能后，对比关闭重排时的检索结果，确认结果的相关性排序是否更符合业务需求。
- 检查配置项的取值是否与当前数据的更新频率、文档结构匹配，例如`limit`的取值是否适配单页展示的最大条目数。
- 查看FastGPT的运行日志，确认重排模型的调用请求与返回结果无报错，状态码为200。
