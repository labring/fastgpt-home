# 玩家客服与舆情处理的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来自客服系统、社区论坛、应用商店评论与游戏日志。日常处理的文档包括玩家工单、补偿申请、舆情日报与标准化处理话术，字段通常包含玩家标识、反馈内容、关联游戏场景、处理进度与反馈渠道标识。数据更新节奏多为日级或实时，单条文档长度跨度较大，短则几十字符的玩家即时反馈，长则数千字符的舆情汇总报告。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据特征对重排与混合检索带来多重约束。多源分散的数据需要混合检索适配客服系统、社区论坛等不同格式的输入，确保跨渠道召回的一致性。文档长度跨度大的特点，要求重排模型可适配短至数十字符的玩家即时反馈，与长至数千字符的舆情汇总报告，避免短内容被截断或长内容超出模型上限。实时更新的反馈要求检索链路延迟可控，重排环节不能显著拖长整体响应时间。同时，工单与处理话术的强关联属性，要求混合检索优先召回同游戏场景的历史记录，重排环节需过滤无关噪音内容，保障核心信息的优先级。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 重排开关 | 开启 | 该品类需精准排序多源反馈与历史话术，开启后可提升结果相关性 |
| 相似度阈值 | 0.72–0.85 | 适配玩家反馈的短文本特征，按实测标定阈值区分有效与无效召回结果 |
| 单次搜索上限 | 前10条 | 平衡检索效率与召回覆盖，避免过多冗余结果加重重排模型负载 |
| 检索模式 | 混合检索模式 | 适配多源数据来源，整合客服工单、社区评论等不同渠道的检索结果 |
| 重排输入长度限制 | 1024–2048 token | 适配舆情日报等长文档，避免内容截断影响排序准确性 |
*本配置基于FastGPT v4.17.0版本*

## 容易做错的三处
- 现象：检索结果的重排标记为false，或未显示重排后的排序结果。原因：重排开关未正确开启，或检索链路未绑定重排模型。
- 现象：长文档（如舆情日报）检索后，重排模型未被触发调用。原因：重排模型输入长度限制设置过低，超出长文档的字符数，系统自动跳过重排环节。
- 现象：单独知识库检索测试时重排正常，但绑定大模型的对话链路中重排功能失效。原因：对话链路的检索配置未同步重排设置，或大模型上下文截断影响了重排参数传递。

## 怎么确认配好了
- 进入FastGPT知识库配置页面，确认重排开关已开启，检索模式设置为混合检索模式。
- 提交不同长度的测试文本，包括短玩家反馈与长舆情报告，核对重排模型是否被正常调用。
- 查看检索结果的返回字段，确认重排后的排序优先级符合业务需求，无明显冗余结果。
- 模拟实时玩家反馈的检索请求，核对链路延迟符合业务要求。
