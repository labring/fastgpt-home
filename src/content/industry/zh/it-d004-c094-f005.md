# 用户验收测试支持的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源于需求规格文档、测试环境配置、客户业务样例素材与缺陷管理系统，更新频率为每交付阶段或每版本迭代。日常关联文档包含UAT用例、验收问题单、验收报告与签字确认单，数据字段包含用例步骤、问题复现路径、验收结论、关联业务场景，单位多为步骤序号、时间戳、业务场景名称。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
UAT用例按阶段更新的特性，要求多轮对话上下文需适配阶段性业务场景切换，避免跨阶段冗余信息干扰。验收问题单的结构化字段，要求提示词需精准匹配用例步骤与缺陷字段，减少非关联信息提取。客户业务样例的非标准化特性，要求对话组件需支持动态加载`variables`适配不同客户场景。同时，验收结论的签字确认环节，要求对话过程需保留完整`messages`链路，便于回溯验收依据。此外，数据更新频率较高的特性，要求对话配置需支持快速切换当前阶段的业务数据，避免旧数据残留。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 保留最近20轮对话上下文，每阶段交付后清空 | 适配UAT用例按阶段更新的特性，避免跨阶段冗余信息干扰 |
| `variables` | 绑定当前阶段的UAT用例ID、验收问题单编号 | 匹配结构化文档字段，精准关联业务场景数据 |
| `chatId` | 按交付阶段生成唯一标识 | 区分不同客户的验收会话，避免数据混淆 |
| 最大上下文长度 | 8000–12000 字符 | 覆盖单阶段UAT用例与验收问题单的完整内容 |
| 会话归档周期 | 按交付项目归档，保留30天 | 匹配验收报告的归档要求，便于后续回溯 |

## 容易做错的三处
- 发起验收相关对话时，无法检索到已上传的UAT用例文件。原因是未将文件存储标识绑定至`variables`会话变量，导致对话上下文无法关联对应存储资源。
- 私有部署环境中调用AI对话组件触发未捕获的异常。原因是未正确配置`chatId`的会话缓存路径，导致会话数据读取失败。
- 通过代码调用API发起对话，返回结果未关联知识库匹配内容。原因是未在`messages`中加入知识库关联的客户业务样例上下文，导致提示词未触发检索逻辑。

## 怎么确认配好了
- 发起一次验收问题复现的对话，检查返回结果是否关联当前阶段的UAT用例字段。
- 查看`chatId`对应的会话日志，确认`messages`上下文仅保留当前阶段的对话内容。
- 触发私有部署环境的会话缓存，检查是否能正常读取配置的`variables`绑定数据。
- 上传测试用的UAT用例文件，确认对话过程中可检索到该文件内容。
