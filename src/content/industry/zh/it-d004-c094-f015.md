# 用户验收测试支持的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来源于需求规格文档、测试环境运行记录、客户业务样例数据与缺陷系统台账。日常产出的文档包含UAT用例、验收问题单、验收报告与签字确认单，单份文档通常包含业务场景描述、测试步骤、问题复现步骤、验收结论等字段，无统一强制单位要求。数据更新以项目阶段或版本迭代为节奏，每完成一个验收阶段或系统版本更新后，相关文档与数据会同步更新，确保检索内容与当前项目状态匹配。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散导致检索时需跨多个数据源关联匹配，需配置支持多数据集联合召回的规则；文档结构不统一，要求检索模型适配非标准化文本的语义匹配，避免因格式差异导致召回失败；按阶段/版本更新的特性，需定期同步知识库的数据集版本，避免检索到过期的验收用例或问题单；面向业务场景的检索需求，需优先召回与当前UAT阶段匹配的文档内容，减少无关结果对验收判断的干扰。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配UAT用例与验收问题单的语义匹配精度，过滤低相关的非业务类结果 |
| `limit` | 前8条 | 匹配UAT阶段的单场景测试文档量，避免上下文过长影响验收结论判断 |
| `searchMode` | semantic | 优先基于语义召回与当前UAT业务场景相关的文档，适配非标准化的验收问题描述 |
| `usingReRank` | 开启 | 对初始召回结果二次排序，提升高相关的验收问题单与复现步骤的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户输入的验收问题自动生成扩展查询词，覆盖客户业务样例中的隐性场景描述 |
| `collectionIds` | 按当前项目的UAT用例、验收问题单数据集绑定 | 限定检索范围仅包含当前项目的验收相关数据，避免召回无关系统的缺陷记录 |

## 容易做错的三处
- 现象：将验收知识库迁移至新部署环境后，执行检索返回空结果。原因：未同步迁移绑定的`collectionIds`数据集配置，或未重建对应数据集的索引，导致新环境无法识别原有数据集。
- 现象：执行知识库检索后返回`text index required for $text query`报错。原因：升级版本后未重建对应数据集的全文索引，无法支持语义检索。
- 现象：工作流中通过API传递知识库变量时，无法匹配到当前UAT用例。原因：未开启`datasetSearchUsingExtensionQuery`，未生成适配业务场景的扩展查询词，导致检索范围过窄。

## 怎么确认配好了
- 手动输入一条长度为500字符的当前项目验收问题，等待10秒后核对检索结果中是否包含对应UAT用例或验收问题单。
- 检查配置面板中`collectionIds`是否仅绑定当前项目的验收相关数据集，无无关数据集的ID。
- 查看检索日志，确认是否触发了`usingReRank`与`datasetSearchUsingExtensionQuery`的相关逻辑。
- 模拟版本升级后的检索场景，验证是否不会出现`text index required for $text query`报错。
