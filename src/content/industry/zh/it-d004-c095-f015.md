# 监控告警配置的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
本品类数据主要来自Prometheus、Zabbix等监控工具、云监控平台、应用日志及CMDB系统。日常文档包含监控指标清单、告警规则、值班手册、告警变更记录，字段涵盖指标名称、阈值区间、告警级别、通知对象、触发条件等，部分字段带有百分比、毫秒、触发次数等单位。数据更新频率为每日或随告警规则变更实时更新，单份文档长度跨度较大，既有简短的单行告警规则条目，也有完整的数十页值班手册合集。

## 这些特征在「知识库检索与召回」这一环带来什么约束
监控告警配置的数据来源分散且格式差异较大，要求检索环节需兼容多数据源的字段格式，避免因字段不匹配导致召回结果偏差。文档长度跨度大，既有单行告警规则，也有完整的值班手册，需适配不同长度文本的分块与召回逻辑。数据更新频率较高，检索环节需支持实时或定时同步最新的告警变更记录，确保返回内容与当前生效配置一致。部分字段带有明确单位，检索时需匹配单位相关的查询意图，否则会出现语义不匹配的情况。告警配置的关联链路复杂，召回结果需包含完整的通知对象、阈值参数等关联信息，避免返回碎片化内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 匹配告警配置的精准度需求，阈值过低会引入无关告警规则，过高则遗漏有效配置内容，按实测标定调整 |
| `limit` | 前8–12条 | 监控告警配置的条目数量通常较多，单次召回过多会超出上下文窗口，过少则无法覆盖完整的告警链路配置 |
| `searchMode` | semantic | 针对告警规则的语义匹配需求，语义检索可识别阈值、指标名等关键词的关联意图，优于纯关键词匹配 |
| `usingReRank` | 开启 | 告警配置的字段关联性强，重排可过滤语义相似但无关的条目，提升结果相关性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可扩展用户的售前或技术支持查询，比如将「怎么设置CPU告警阈值」扩展为匹配对应指标、阈值配置的检索词 |
| `collectionIds` | 绑定对应监控知识库的集合ID | 确保检索范围仅限监控告警配置相关的知识库，避免混入其他品类的文档 |

## 容易做错的三处
- 检索结果与知识库内容不符，表现为返回的告警阈值配置与实际录入内容不一致。原因是`similarity`阈值设置不合理，过低引入无关文档，或未开启`usingReRank`导致语义相似的无关条目被优先召回。
- 应用关联知识库查询无相关内容，表现为返回空结果或提示无匹配内容。原因是未配置`collectionIds`限定检索范围，导致检索范围覆盖了非监控告警的知识库，或`limit`设置过低未召回有效条目。
- 长文档切割不符合需求，表现为告警规则被错误拆分导致语义断裂。原因是未针对监控告警配置的文档结构调整分块逻辑，未匹配告警条目与上下文的关联。

## 怎么确认配好了
- 手动输入一条已知的监控告警配置关键词，核对检索结果是否包含对应文档的核心内容，比如指标名、阈值参数。
- 检查知识库同步日志，确认监控告警相关的文档已完成最新的增量或全量同步，确保数据时效性。
- 查看检索接口的返回参数，确认`similarity`、`limit`等配置项的取值与预设一致。
- 模拟售前或技术支持场景的查询，验证返回结果是否包含告警阈值、通知链路等核心配置信息。
