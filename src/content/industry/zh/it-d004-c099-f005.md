# 移动端开发的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
通常的数据来源包括代码仓库、应用商店后台、崩溃监控平台、机型覆盖数据；更新节奏为每日或每版本发布周期；日常产出的文档包含端版本发布单、机型适配清单、崩溃分析报告、应用商店审核资料；文档字段通常包含机型版本号、崩溃堆栈信息、应用包体大小、审核状态标识等，无统一固定单位，随文档类型变化。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且类型多样，多轮对话需通过`messages`参数按交互时序拼接不同模块的上下文，避免遗漏关键业务信息；更新频率较高，需限制上下文窗口长度，避免过期的旧版本文档干扰当前问题解答；移动端开发的专属业务参数（如机型版本、应用包ID）需通过`variables`传递，无需重复向用户采集；不同文档场景（如崩溃排查、审核咨询）的提示词需分别预设，适配不同的字段提取与回答逻辑；机型覆盖数据的多维度特性，要求多轮对话中保留历史交互的机型信息，确保后续解答的针对性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 最大上下文长度 | 8000–12000 字符 | 移动端开发的核心文档多为单份数千字符的发布单或崩溃报告，过长上下文会分散模型注意力 |
| 变量传递参数（`variables`） | 传递机型版本、应用包ID、审核状态字段 | 需在多轮对话中保留专属业务参数，避免重复采集用户信息 |
| 对话历史保留规则（`chatId`有效期） | 最长7天 | 移动端版本更新周期多为7-14天，过期上下文无实际业务价值 |
| 提示词模板配置 | 分场景预设（崩溃排查/审核咨询/适配咨询） | 移动端开发的业务场景差异大，统一提示词无法覆盖不同类型的文档内容 |
| 单次召回内容上限 | 前3条 | 移动端开发的核心问题多集中在1-2个核心文档片段，过多召回会增加上下文负担 |

## 容易做错的三处
- 现象：调用已配置的API key后，界面提示无授权，返回401状态码。原因：未将API key绑定至当前移动端开发场景的专属知识库，或API key的权限范围未覆盖FastGPT v4.17.0版本的应用调用权限。
- 现象：对话仅在交互结束后返回完整内容，无流式输出效果。原因：未开启流式输出的对应配置项，或调用时未正确启用相关参数。
- 现象：调大单次召回上限后，大模型未引用任何召回的知识库内容，且召回详情显示内容已正常获取。原因：召回内容的格式不符合提示词的字段要求，或上下文窗口超出限制导致召回内容被截断，无法被模型识别。

## 怎么确认配好了
- 发起一次包含机型版本、崩溃日志片段的多轮对话，检查`variables`参数是否携带了专属业务字段，且`messages`参数中保留了之前的交互内容。
- 调用API并观察返回结果，确认是否有流式输出的分段返回内容，或界面是否启用了流式展示模式。
- 调整单次召回上限为前2条，检查大模型是否能准确引用召回的适配清单或崩溃分析报告内容，无无关字段混入回答。
- 检查召回内容是否自动过滤了段落ID或人才编号等非业务字段，确认大模型回答中未出现无关标识。
- 输入错误的API key，确认界面会返回授权错误提示，验证权限配置的有效性。
