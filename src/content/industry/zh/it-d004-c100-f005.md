# 等级保护测评咨询的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
等级保护测评咨询的业务数据来自测评工具、访谈记录、系统清单、安全设备日志，更新频率为每项目/年。日常产出的文档包含定级报告、差距分析报告、整改方案、测评报告，文档围绕等保测评的定级、差距核对、整改全流程生成，字段包含控制项编号、整改要求、证据材料清单等，无统一固定单位，随项目具体需求调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据按项目独立更新，多轮对话需绑定项目专属的知识库范围，避免跨项目文档混淆。文档类型覆盖长文本的定级与测评报告，对话上下文需承载足够长度的历史信息，确保专业术语与流程的连贯性。业务流程中的定级材料梳理、控制项差距核对环节耗时较长，多轮对话需支持逐步追问缺失的文档片段，辅助完成信息补全。同时，测评不通过、整改延期的风险较高，提示词需严格匹配等保测评的专业规范，避免遗漏关键控制项。

## 配置怎么定
以下配置均基于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 字符 | 适配定级报告、测评报告等长文档的多轮对话上下文承载 |
| 单次召回文档数 | 前 6 条 | 覆盖控制项差距核对、整改证据收集所需的多类业务文档 |
| 单次对话最大token数 | 4000–6000 token | 避免上下文过长导致处理超时 |
| `variables` 变量注入时机 | 对话发起前 | 确保项目专属的系统清单、访谈记录等数据提前绑定到对话上下文 |
| `chatId` 会话关联规则 | 按项目 ID 绑定 | 区分不同客户项目的对话历史，避免跨项目数据混淆 |
| `messages` 历史传递范围 | 仅当前项目会话 | 确保多轮对话的上下文仅包含当前项目的交互内容 |

## 容易做错的三处
- 对话返回的知识库引用字段为空，原因是未将项目专属的系统清单、安全设备日志等数据绑定到`variables`变量中，导致检索时无法匹配对应项目的文档。
- 流式输出中断且返回超时状态，原因是未限制单次对话的上下文长度，导致处理时长超出系统阈值。
- 多轮对话的上下文被跨项目复用，原因是未按`chatId`绑定项目ID，导致不同项目的对话历史被错误关联。

## 怎么确认配好了
- 发起新对话，输入与当前项目相关的定级问题，检查返回结果是否包含当前项目的文档片段。
- 查看`variables`变量绑定面板，确认系统清单、访谈记录等项目专属数据已正确注入对话上下文。
- 切换不同项目的`chatId`，检查对话历史不会在不同项目间显示。
- 发起两轮连续提问，确认第二轮提问会基于第一轮的交互上下文生成响应。
