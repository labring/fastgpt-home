# 缺陷管理与回归测试的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
本品类的数据主要来自缺陷管理系统、测试报告、代码提交记录与用户反馈。日常产出的文档包括缺陷单、回归测试清单、修复验证记录与缺陷统计报表。数据字段包含缺陷唯一标识、优先级等级、复现步骤、关联版本号、验证状态等。数据更新频率为每日或每版本发布周期，随缺陷修复、测试执行与版本迭代动态变化。

## 这些特征在「重排与混合检索」这一环带来什么约束
本品类的数据按版本、缺陷优先级与修复状态分层，且随版本迭代高频更新。混合检索需同时匹配语义关联与元数据特征，避免仅依赖语义相似度导致高优缺陷被低优先级结果掩盖。不同文档类型的长度差异较大，从单条缺陷复现步骤的数百字符到汇总报表的数千字符不等，重排模型需适配跨度较大的输入长度。数据更新频率决定检索需支持动态刷新关联的缺陷与测试数据，确保检索结果与当前版本状态一致。

## 配置怎么定
以下配置适用于FastGPT v4.17.0及以上版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `usingReRank` | 开启 | 本品类数据需区分缺陷优先级与关联度，重排可优化检索结果的相关性排序 |
| `similarity` | 0.75–0.85 | 过滤低语义关联的缺陷与测试数据，避免无关结果干扰检索 |
| `limit` | 前10条 | 控制单次检索返回的基础结果数量，适配缺陷管理数据的单批次处理规模 |
| `searchMode` | hybrid | 结合语义相似度与元数据特征，匹配本品类混合的缺陷与测试文档类型 |
| 重排模型超时阈值 | 30 秒 | 避免因重排模型响应延迟导致检索流程阻塞，适配缺陷排查的实时性需求 |

## 容易做错的三处
- 现象：创建应用时无法勾选结果重排选项。原因：未在服务端配置`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，不得附加/v1等路径）与`AIPROXY_API_TOKEN`（与AI Proxy服务端配置一致的管理员Token，不得为空），导致服务启动校验失败，无法连接AI Proxy，无法加载依赖AI Proxy的重排模型功能，进而无法勾选结果重排选项。
- 现象：配置重排模型后检索结果顺序未发生变化。原因：未将`usingReRank`参数设置为开启，或`similarity`阈值设置过高，过滤了所有基础检索结果。
- 现象：重排模型调用返回超时错误。原因：重排模型超时阈值设置过短，或重排模型部署资源不足，无法在规定时间内完成排序计算。

## 怎么确认配好了
- 检查服务端环境变量是否已配置`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1等路径）与`AIPROXY_API_TOKEN`（与AI Proxy服务端配置一致的管理员Token，不得为空），且参数值与AI Proxy服务端配置一致。
- 进入应用的检索配置页面，确认`usingReRank`开关处于开启状态，且`similarity`与`limit`参数符合当前业务需求。
- 提交包含缺陷ID、版本号的测试查询，查看检索结果的排序是否与缺陷优先级、关联度匹配。
- 验证重排模型的调用日志，确认无超时或鉴权失败的报错信息。
