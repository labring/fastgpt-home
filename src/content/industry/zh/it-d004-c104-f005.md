# 落地页转化优化的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
该品类的典型使用主体为增长产品、前端运营与广告优化师。数据主要来自落地页访问日志、热力图、表单提交数据及广告来源参数。日常关联文档包含落地页方案、埋点需求文档、AB测试报告与表单字段清单。数据更新频率为周度或随单次营销活动调整。日常最耗时的工作环节为页面路径分析、表单阻塞排查与实验结果判断。数据异常或处理失误可能导致线索流失、数据无法归因及广告投放成本上升。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
落地页转化优化的数据来源分散且关联多类文档，要求多轮对话需绑定单次访问的`chatId`以保留上下文关联。数据更新随活动调整，提示词需动态适配当期的表单字段清单与埋点需求。日常耗时环节集中在路径分析与结果判断，多轮对话需预设可快速调取历史分析结果的流程。同时需将落地页方案、AB测试报告等文档作为知识库素材传入，通过`variables`传递当前活动的专属参数，避免重复调用无关数据。此外，需通过`messages`结构规范每轮对话的输入输出格式，确保与落地页业务逻辑对齐。

## 配置怎么定
以下配置说明适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定落地页访问会话的唯一标识 | 确保多轮对话保留单次用户从点击广告到提交表单的完整上下文 |
| `messages` | 初始系统提示包含当期表单字段清单与归因规则，每轮追加用户提问与AI响应 | 适配落地页转化优化的专属业务场景，避免上下文丢失 |
| `variables` | 传入当前活动的广告来源参数、表单字段清单 | 动态加载当期业务数据，无需每次修改提示词 |
| 最大上下文token数 | 800–1200 token | 匹配落地页相关文档的平均长度，避免超出处理上限 |
| 单次搜索上限 | 前 3 条知识库结果 | 聚焦与当前落地页方案最相关的内容，减少无效信息干扰 |
| 对话超时时间 | 600 秒 | 匹配落地页用户的平均等待时长，避免会话提前中断 |

## 容易做错的三处
- 对话日志标注功能未生效，仅显示原始对话内容。原因是未开启会话日志的自动标注开关，未关联落地页访问的`chatId`进行分类标记。
- AI输出直接在页面显示，未经过文本拼接组件处理。原因是未配置对话节点的输出延迟逻辑，直接将AI响应挂载到页面DOM，未按业务需求通过指定组件统一输出。
- 知识库检索结果无法正确传入AI对话节点。原因是未按要求传递`variables`格式的知识库引用数据，导致AI无法识别检索到的落地页文档内容。

## 怎么确认配好了
- 发起一次模拟落地页用户提问，检查对话上下文是否保留前一轮的表单字段信息，确认`chatId`绑定生效。
- 触发AI对话节点，验证输出是否先进入文本拼接组件，待所有数据处理完成后再统一展示，确认输出逻辑符合配置要求。
- 传入模拟的知识库检索结果，检查AI是否能正确引用落地页方案中的内容，确认`variables`传递的格式正确。
- 查看会话日志，确认每条对话都带有落地页访问的专属标识，标注功能正常生效。
