# 许可证合规与版权声明的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源为代码仓库、依赖清单、许可证文本、贡献记录，更新频率为每版本发布或每依赖变更时更新。日常运维文档包含LICENSE文件、NOTICE文件、依赖许可证清单、版权声明文件，字段涵盖许可证类型、版权归属方、依赖项名称、版本号等。处理主体为开源项目办公室、项目维护者与法务人员，核心环节包含许可证兼容性核对、版权归属确认、NOTICE文件更新，出错后果包含许可证违规、商业使用受阻、项目下架整改。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
品类数据的更新频率与文档结构，对多轮对话配置形成明确约束。首先，多份许可证与依赖文档需精准区分，因此对话需支持指定检索特定文档的配置；其次，数据更新频繁，上下文缓存时长需匹配版本迭代周期，避免调用过时的许可证信息；再者，咨询内容多为专业合规问题，需过滤无关闲聊，限定`messages`字段仅保留有效咨询内容；最后，用户可能反复询问存档、清理规则，对话存档上限需适配项目日常咨询规模。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文轮次 | 前8–12轮对话 | 依据许可证合规咨询多为短序列问题，过长上下文会混入无关依赖项信息 |
| 上下文缓存时长 | 72小时 | 依据依赖清单每版本更新频率，缓存时长匹配单次项目迭代周期 |
| 单次召回条数 | 前3–5条 | 依据许可证文档内容较短，单次召回可覆盖核心合规信息 |
| 知识库召回限定 | 按知识库标签筛选 | 依据品类数据包含多份许可证文档，按标签筛选可精准召回目标文件 |
| `messages` 字段处理 | 仅保留有效咨询消息 | 依据品类数据多为专业合规问题，过滤无效闲聊可提升回答准确性 |
| `variables` 变量配置 | 绑定当前项目的LICENSE文件ID | 依据品类数据来源为代码仓库托管文件，绑定ID可精准调用本地文档 |
| 对话存档上限 | 500条 | 依据开源项目日常咨询规模，500条可覆盖月度合规咨询需求 |

## 容易做错的三处
- 现象：多轮对话中后续问题无法关联上下文，回答与当前咨询无关。原因：未配置上下文保留规则，或上下文轮次设置过低，导致`chatId`关联的历史对话未完整加载`messages`字段内容。
- 现象：无法指定召回特定许可证文档，召回结果混杂多个文件内容。原因：未配置知识库标签筛选规则，未通过配置项限定检索范围。
- 现象：对话存档空间不足或自动清理不生效。原因：未设置对话存档上限与缓存时长，或缓存时长设置过长超出项目存储配额。

## 怎么确认配好了
- 发起两轮连续的许可证合规相关咨询，确认第二轮回答关联第一轮的上下文信息。
- 配置知识库标签后，发起指定特定文档的检索请求，确认召回结果仅包含目标文档内容。
- 查看FastGPT v4.17.0的对话管理界面，确认存档条数不超过设定上限，且旧对话自动清理。
- 检查`variables`变量绑定配置与`chatId`关联规则，确认已关联当前项目的LICENSE文件路径或ID。
