# 账号封禁与申诉复核的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自风控系统、审核记录、用户行为日志与举报证据。日常生成的文档包含封禁记录、申诉材料、复核意见与用户通知，字段通常包含账号标识、违规类型、封禁时效、申诉提交时间、复核结论等。数据更新频率多为日级或实时，单条数据体量适中，无复杂嵌套结构，核心字段多为枚举或文本类，便于结构化存储与检索。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且更新频繁，要求检索链路支持高频增量同步，确保召回的封禁记录、申诉材料等为最新版本。核心字段包含账号标识、违规类型等枚举与文本内容，需同时支持结构化字段精准匹配与全文语义检索，覆盖不同检索需求。单条数据关联多类文档，需在召回后按账号维度聚合结果，避免重复推送同账号的多条冗余记录。非结构化申诉材料的语义差异较大，需调整召回的语义匹配逻辑，确保与申诉理由、复核意见的关联度达标。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | 匹配账号封禁相关的申诉理由与复核意见，该区间可过滤低关联度的历史记录，避免误召回无关违规内容，适配FastGPT v4.17.0的语义匹配逻辑 |
| `limit` | 前8条 | 单次召回最多8条关联数据，覆盖账号封禁的全流程记录，同时控制上下文长度不超出模型输入限制 |
| `searchMode` | hybrid | 结合结构化字段匹配与全文语义检索，适配该品类多类型数据的检索需求，兼顾精准性与覆盖率 |
| `usingReRank` | 开启 | 对召回结果进行重排，优先返回与当前申诉理由、复核结论关联度更高的记录，提升回答的相关性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户申诉内容自动扩展检索词，覆盖同义词、违规类型的同义表述，提升召回覆盖率 |
| `collectionIds` | 指定封禁申诉专属知识库的集合ID | 限定检索范围仅为该品类专属的封禁记录、申诉材料等数据集，避免混入其他品类的无关数据 |

## 容易做错的三处
- 现象：知识库搜索调试正常，但AI对话阶段未召回相关封禁记录。原因：未配置`datasetSearchUsingExtensionQuery`，无法覆盖用户申诉内容的同义检索词，导致模型无法关联到对应文档。
- 现象：检索结果包含大量与当前账号无关的违规记录。原因：未正确设置`collectionIds`，检索范围覆盖了全平台知识库，混入了其他账号的无关数据。
- 现象：检索返回的结果关联度过低，包含大量未涉及账号封禁的无关记录。原因：`similarity`阈值设置过低，未过滤低关联度的非目标文档。

## 怎么确认配好了
- 提交测试用的账号申诉内容，核对检索返回的结果是否包含该账号的封禁记录、申诉材料与复核意见。
- 调整`similarity`参数，观察返回结果的关联度变化，确认阈值可过滤无关内容。
- 检查检索结果的条数，确认符合`limit`的设置要求，且未出现冗余的跨账号记录。
- 验证`usingReRank`开启后，结果的排序是否优先匹配当前申诉的核心诉求。
