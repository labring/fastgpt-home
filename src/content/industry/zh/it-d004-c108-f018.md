# 质保期缺陷响应的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
本品类的数据主要来自客户提交的质保工单、系统运行日志、项目合同质保条款、软件/硬件版本记录。日常归档文档包括质保工单、缺陷确认单、修复执行记录、客户确认回执单。数据更新频率为每日或随单触发，每条数据包含工单编号、缺陷描述、关联项目信息、责任判定痕迹、客户反馈字段，无额外统计类量化指标。

## 这些特征在「重排与混合检索」这一环带来什么约束
本品类的数据来源分散且格式差异大，既有零散的日志片段，也有长文本的质保合同条款，同时数据随单或每日更新，要求检索链路具备实时响应能力。不同文档的核心诉求不同，质保工单侧重缺陷详情，合同条款侧重责任边界，这要求混合检索需兼顾短文本召回与长文本匹配。责任边界判断是核心耗时环节，重排环节需优先召回与责任判定、修复方案相关的内容，避免无关信息干扰核心决策，同时需适配单条数据量波动较大的特征。

## 配置怎么定
本页面的配置说明基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.72–0.80 | 过滤与质保缺陷无关的低匹配内容，聚焦核心业务数据 |
| 单次召回上限 | 前10条 | 适配本品类单工单关联数据量有限的特征，避免冗余信息进入上下文 |
| 检索模式 | 混合检索 | 适配多格式数据的召回需求，兼顾短文本工单与长文本合同条款 |
| 重排开关 | 开启 | 优先排序与责任边界判断、修复方案相关的内容，提升核心决策效率 |
| 检索超时时间 | 8–10秒 | 匹配本品类业务响应的合理耗时，避免过长等待影响客户支持效率 |

## 容易做错的三处
- 现象：混合检索任务耗时超过10秒，界面显示检索超时提示。原因：未针对本品类数据量调整召回上限与重排阈值，同时未配置合理的超时参数。
- 现象：调用重排模型后，GPU显存占用快速增长至6-7G且多卡均出现占用。原因：未限制重排模型的并发调用数量，或未为单卡分配合理的模型加载批次。
- 现象：离线接入重排模型时界面返回rerank error，提示信息包含空字段或未找到模型。原因：未正确配置重排模型的API地址或本地模型路径，导致模型无法正常加载调用。

## 怎么确认配好了
- 查看FastGPT系统的检索链路日志，确认混合检索与重排模块均正常启动，无报错信息。
- 提交一条测试质保工单，核对召回结果中优先展示责任判定、修复方案相关的文档内容。
- 测试不同格式的输入文本，确认短文本工单与长文本合同条款均能被正确召回。
- 查看GPU显存占用情况，确认重排模型的显存占用符合预期范围。
