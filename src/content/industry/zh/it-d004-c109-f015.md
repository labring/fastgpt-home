# 身份账号与权限管理的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据主要来自IAM系统、HR系统、业务系统日志与审批系统。日常维护的文档包含账号申请单、权限矩阵、离职账号回收单、合规审计报告，文档字段包含账号ID、权限范围、审批状态、变更时间等。数据更新频率为每日同步或随人事变动实时更新，单份文档体量从数页到数十页不等，核心字段多为结构化与半结构化结合，部分权限矩阵存在多维度关联字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据随人事变动实时更新，要求知识库召回的内容需保持同步，避免使用过时的权限规则或离职账号信息。结构化与半结构化的文档字段，要求检索时需精准匹配账号ID、权限范围等字段，避免模糊召回无关内容。多维度关联的权限矩阵数据，需要召回时关联上下文，确保返回的权限说明完整。单次检索需覆盖多系统来源的文档，需限定检索范围避免混入其他品类的无关数据。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 本品类的权限相关文档需精准匹配，避免低相似度的无关权限规则 |
| `limit` | `前 8–12 条` | 权限矩阵等文档内容关联度高，少量条目即可覆盖完整信息 |
| `searchMode` | `vector + fulltext` | 本品类既有结构化字段也有半结构化文档，混合检索可兼顾精准度与召回率 |
| `usingReRank` | `开启` | 多维度权限数据易出现语义相近但场景不同的条目，重排可提升相关性排序准确性 |
| `datasetSearchUsingExtensionQuery` | `开启` | 人事变动类文档需关联账号申请、审批流程的上下文，扩展查询可补充关联信息 |
| `collectionIds` | `指定IAM、HR、审批系统对应的知识库集合` | 限定检索范围，避免混入其他品类的无关数据 |

## 容易做错的三处
- 现象：检索结果中出现已离职账号的权限信息。原因：未配置实时同步更新规则，知识库未同步HR系统的离职回收单数据。
- 现象：搜索卡片中选择知识库时无法引用账号ID变量。原因：未配置变量绑定规则，未将检索参数与账号ID字段关联。
- 现象：创建知识库时无法选择表格数据集。原因：未开启表格数据集上传权限，或上传的表格未包含账号ID、权限范围等必填字段。

## 怎么确认配好了
- 手动上传一份最新的离职回收单，触发知识库同步，检索离职账号相关内容，确认结果包含最新状态。
- 输入包含具体账号ID的查询词，检查检索结果是否精准匹配对应权限矩阵条目。
- 尝试上传表格数据集，确认可选列表中包含表格类型，验证数据集选择功能正常。
- 开启重排与扩展查询后，对比开启前后的检索结果排序，确认重排功能生效。
