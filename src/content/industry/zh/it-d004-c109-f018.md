# 身份账号与权限管理的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
本品类数据主要来自企业IAM系统、HR系统、业务系统日志与审批系统，更新节奏为每日同步或随人事入离转调实时更新。日常产出的文档包含账号申请单、权限矩阵、离职账号回收单与权限审计报告，字段涵盖账号ID、权限组、审批状态、审计周期等，无统一固定计量单位，数据体量随企业员工规模与业务系统数量变化。

## 这些特征在「重排与混合检索」这一环带来什么约束
跨系统的数据来源要求混合检索需同时关联IAM、HR与审批系统的数据集，避免单一数据源的信息缺失。更新节奏非固定要求检索索引需支持按需刷新，适配人事变动的实时同步需求。文档结构差异显著，既有结构化权限矩阵表格，也有非结构化工单文本，重排模型需适配不同字段的权重分配。同时，权限数据出错会引发越权风险，检索结果的相关性排序需严格匹配业务场景的优先级。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.75–0.85 | 适配结构化权限数据，过滤低相关性的跨系统检索结果 |
| 单次搜索上限 | 前10条 | 控制基础检索返回的结果数量，适配IAM系统的单批次数据体量 |
| 搜索模式 | 混合检索 | 关联多源系统数据，覆盖账号、权限、审批全链路信息 |
| 重排开关 | 开启 | 修正结构化与非结构化文档的排序偏差 |
| 重排召回上限 | 前20条 | 为重排模型提供充足的候选结果，保障排序准确性 |
| 上下文窗口 | 8000–12000 token | 适配权限审计报告等长文本的检索需求 |

## 容易做错的三处
- 现象：重排模型启动失败，日志返回“硬件架构不兼容”报错。原因：仅加载了amd架构的重排模型镜像，未适配arm架构的部署环境。
- 现象：配置完成后重排功能未生效，返回结果与基础检索完全一致。原因：未开启重排开关配置项，或未将重排模型绑定至混合检索流程。
- 现象：混合检索返回的权限相关结果相关性偏差过大，出现无关的业务日志条目。原因：相似度阈值设置过低，未过滤低匹配度的跨系统数据。

## 怎么确认配好了
- 进入FastGPT v4.17.0的检索配置页面，确认搜索模式已设置为混合检索。
- 检查重排相关配置项的开关状态，确认重排开关已开启。
- 提交一条权限相关的测试查询，对比基础检索与重排后的结果排序差异。
- 查看检索日志，确认已关联IAM、HR与审批系统的多源数据集。
