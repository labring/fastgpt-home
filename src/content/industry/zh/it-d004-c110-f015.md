# 运维外包驻场服务的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自客户ITSM系统、监控平台、资产清单与值班记录，日常生成驻场日报、服务台工单、巡检报告、SLA月报四类文档。数据更新以日度为主，部分SLA月报为月度更新。文档包含驻场人员信息、工单编号、巡检项、SLA达标率等字段，无统一固定单位，部分字段需匹配客户现有系统格式。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且格式不统一，导致知识库导入时需适配多类源系统结构，增加预处理复杂度。更新频率的差异要求检索时优先匹配最新的日度工单与值班记录，避免调用过时的月度SLA数据。文档字段多样，需针对驻场人员、工单、巡检等不同场景配置定向检索规则，防止无关字段干扰召回结果。同时，驻场服务的合同化交付属性要求检索结果需符合服务约定的响应边界，避免召回内容超出服务范围。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 适配驻场工单与巡检报告的文本相似度匹配，平衡召回精度与覆盖范围 |
| `limit` | 前8条 | 控制单次召回结果数量，适配驻场工程师现场处理的信息承载量 |
| `searchMode` | 语义搜索 | 适配多来源的非结构化文档，更适配工单描述的口语化内容 |
| `usingReRank` | 开启 | 对召回结果二次排序，过滤低相关的驻场日报冗余内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题扩展检索词，覆盖巡检报告中专业术语的同义表述 |
| `collectionIds` | 按服务合同绑定的数据集ID | 限定检索范围，确保仅调用对应客户的驻场服务文档 |

## 容易做错的三处
- 现象：知识库召回覆盖不全，用户提出的驻场工单相关问题未被匹配。原因：未开启`datasetSearchUsingExtensionQuery`，或未针对工单场景配置扩展检索词，导致同义表述无法被识别。
- 现象：调用`api/v1/chat/completions`接口时指定知识库标签无匹配结果。原因：未正确绑定`collectionIds`参数，或标签与数据集配置不匹配。
- 现象：创建通用知识库时无法启用图片理解功能。原因：本地部署版本未配置对应模型依赖，需补充部署图片理解模型包。

## 怎么确认配好了
- 传入驻场工单的典型问题调用检索接口，核对返回结果的相似度分值是否符合预设区间。
- 检查单次召回的结果数量是否与`limit`参数配置一致。
- 验证指定`collectionIds`后，仅返回对应服务合同绑定的数据集内容。
- 开启`usingReRank`后，确认召回结果的排序优先级符合业务场景需求。
