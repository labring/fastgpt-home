# 运维外包驻场服务的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来自客户ITSM系统、运维监控平台、资产清单数据库与驻场值班记录。日常产出的文档包括驻场日报、服务台工单、巡检报告与SLA月报，各文档字段包含工单编号、巡检项、SLA达标情况、值班时段等。数据更新节奏以日度为主，驻场日报、工单记录每日更新，SLA月报则按月汇总更新。数据结构围绕驻场服务交付全流程，关联客户侧的IT资产与服务请求信息，各数据源的字段格式存在一定差异。

## 这些特征在「重排与混合检索」这一环带来什么约束
数据来源分散且关联多系统，混合检索需跨源整合不同格式的工单、巡检报告等内容，需明确各数据源的字段映射规则，避免出现字段不匹配的问题。更新频率的差异要求检索时区分实时数据与历史月报，优先使用当日的工单与巡检记录，避免混合不同时效的信息影响准确性。驻场服务文档多为流程性记录，字段关联性强，重排环节需优先匹配工单优先级、SLA时效等核心业务字段，同时需兼顾业务合规性，约束了检索结果的筛选维度与展示顺序。

## 配置怎么定
| 配置项         | 建议取法               | 这样取的依据 |
| ----------------|------------------------|------------------------------------------------------------------------------ |
| 搜索模式       | 混合检索模式           | 适配多源异构的驻场服务文档，兼顾语义匹配与关键词召回，覆盖工单、巡检报告等不同类型数据 |
| 相似度阈值     | 0.72–0.80              | 过滤低相关的值班记录与非核心巡检项，保留与客户技术问题强关联的内容，按实测标定 |
| 单次搜索上限   | 前12条                 | 控制初始召回的文档数量，适配驻场服务数据的日均更新量，避免上下文过载 |
| 重排开关       | 开启                   | 针对多源数据的字段关联性，通过重排优化工单优先级、SLA时效等核心字段的排序，提升检索结果匹配度 |
| 重排召回上限   | 前6条                  | 缩小重排后的结果范围，聚焦最相关的工单与巡检记录，符合售前与技术支持的信息密度要求 |

## 容易做错的三处
- 现象：混合检索返回的结果包含大量非目标文档，如无关的值班记录。原因：未针对驻场服务文档的字段设置过滤规则，未限定检索范围为工单与巡检报告类数据。
- 现象：界面显示重排开关为开启状态但检索结果未发生变化。原因：未确认检索模式是否支持重排功能，或重排的触发条件未与检索请求绑定。
- 现象：工作流中Http请求后的多变量无法绑定指定知识库。原因：未在重排配置中为不同变量设置对应的数据源过滤规则，未匹配驻场服务文档的分类字段。

## 怎么确认配好了
- 查看检索日志，确认返回的文档类型包含驻场日报、服务台工单等目标品类的文档，核对文档来源与配置的数据源一致。
- 测试开启与关闭重排功能，对比检索结果的排序逻辑，确认重排后的结果优先展示高优先级工单与合规性强的巡检记录。
- 调整相似度阈值与单次搜索上限，观察检索结果的数量与相关性变化，确认配置参数对检索结果的影响符合预期。
- 输入非目标品类的关键词，验证过滤规则是否生效，确认检索结果未返回无关的资产清单或值班记录。
