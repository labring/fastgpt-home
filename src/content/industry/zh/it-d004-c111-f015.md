# 配置管理与CMDB维护的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
这个品类的典型使用主体为运维资产管理员、SRE、ITSM平台管理员，日常产出与维护的文档包括配置项清单、服务组件关系拓扑、变更记录、资产盘点表。数据主要来源于CMDB系统、云资源清单、自动发现工具与采购台账，更新频率为每日或每周。核心工作围绕配置项采集、关系核对与变更后更新展开，数据需准确反映服务组件间的依赖关系，区别于仅统计资产数量的IT资产盘点工作。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据来源包含CMDB、云资源清单等多类系统，检索时需完成不同数据源的字段映射与格式对齐，避免出现字段不匹配的结果。因数据更新频率为日或周，需配置定期同步机制，确保召回的配置项数据与最新台账一致。因核心关注服务组件的依赖关系，检索时需关联配置项与拓扑文档，满足依赖分析的业务需求。日常文档包含结构化清单与非结构化变更记录，需针对不同文档类型调整检索权重，提升不同场景下的召回准确性。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本，针对配置管理与CMDB维护的业务场景定制：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.7–0.85` | 配置管理类数据字段标准化程度较高，需过滤低相关的检索结果 |
| `limit` | `前10–15条` | 配置项关联的依赖关系较多，需覆盖足够的核心配置项与关联文档 |
| `searchMode` | `关联召回模式` | 需同时检索配置项本身与对应的服务组件拓扑关系，满足依赖分析需求 |
| `usingReRank` | `开启` | 变更记录等非结构化文本需二次排序，提升与用户问题的匹配度 |
| `datasetSearchUsingExtensionQuery` | `开启` | 需扩展用户问题，匹配配置项的别名与常用简称，提升召回覆盖范围 |
| `collectionIds` | `指定CMDB相关集合ID` | 隔离非配置管理类的知识库数据，确保检索结果仅覆盖目标业务场景 |

## 容易做错的三处
- 现象为检索结果中配置项文档内的图片无法正常显示，原因是知识库同步时未保留图片的相对路径或CDN缓存未及时更新。
- 现象为检索返回的配置项关联id为空，原因是未开启`datasetSearchUsingExtensionQuery`，导致无法匹配到配置项与关联字段的映射关系。
- 现象为单次检索返回的结果条数超出预期，原因是未设置`limit`参数或取值过大，拉取了过多非核心的配置项与关联数据。

## 怎么确认配好了
- 手动输入一个已知的核心配置项名称，检查检索结果是否包含对应的配置项清单、服务组件拓扑文档与近期变更记录。
- 查看检索日志，确认返回结果的`similarity`值落在预设的`0.7–0.85`区间内，过滤掉低相关的结果。
- 测试变更记录类文档的检索，确认开启`usingReRank`后，结果排序符合业务场景的相关性要求。
- 检查知识库集合的筛选配置，确认仅`collectionIds`指定的CMDB相关集合被纳入检索范围，无无关数据混入。
