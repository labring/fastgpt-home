# 配置管理与CMDB维护的客户技术支持与售前答疑：重排与混合检索

## 这个品类的数据长什么样
本品类的数据来自CMDB、云资源清单、自动发现工具与采购台账，更新频率为日或周。日常维护的文档包含配置项清单、服务组件关系拓扑、变更记录与资产盘点表，单份文档包含配置项ID、所属集群、依赖关系、最近变更时间、采购批次等字段，部分拓扑文档还会包含节点IP、端口号等网络属性，数据结构以结构化字段为主，同时存在关联关系型的非结构化描述内容。

## 这些特征在「重排与混合检索」这一环带来什么约束
由于数据来源分散且更新频率存在差异，混合检索需要同时匹配结构化配置字段与非结构化拓扑描述，因此需要支持多维度字段的召回逻辑。配置项与依赖关系的关联逻辑复杂，重排环节需要优先召回关联度高的配置项组合，仅以关键词匹配作为辅助匹配逻辑。同时，数据更新频率较高，检索环节需要适配实时或近实时的数据源同步，避免召回过期的配置信息。此外，单份文档的字段数量较多，混合检索的召回范围需要限定在与客户技术支持相关的配置项维度，避免无关数据干扰检索结果。

## 配置怎么定
本配置指南适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.72–0.85 | 适配CMDB配置项的结构化字段匹配精度，避免召回无关的低关联度资产数据 |
| 单次召回上限 | 前10–15条 | 匹配CMDB单批次配置项的数量上限，平衡检索速度与结果覆盖度 |
| 检索模式 | 混合检索 | 同时启用向量检索与关键词检索，适配结构化与非结构化混合的CMDB数据 |
| 开启重排 | 是 | 针对配置项依赖关系的复杂关联逻辑，对初始召回结果进行二次排序，提升关联配置项的召回优先级 |
| 重排模型显存阈值 | 500 MB | 适配本地部署的轻量重排模型，避免检索后持续占用过多系统资源 |
| 问题优化开关 | 开启 | 针对客户技术支持的口语化提问，优化检索关键词，提升匹配准确性 |

## 容易做错的三处
- 现象：查看系统进程或显存监控面板，发现重排模型在检索任务完成后仍占用500 MB以上显存未释放。原因：未配置重排模型自动卸载逻辑，模型在检索任务结束后未被从显存中释放。
- 现象：开启问题优化与结果重排后，消息返回耗时超过30秒。原因：单次召回上限设置过高，或重排模型选用了参数规模过大的版本，超出了当前部署的硬件承载能力。
- 现象：配置了重排模型且开启了索引重排，但在线召回测试时未返回重排结果。原因：未在检索环节同步开启重排开关，仅在知识库索引阶段配置了重排功能。

## 怎么确认配好了
- 执行在线召回测试，输入包含配置项ID、服务依赖关系或变更记录关键词的提问，核对返回结果是否包含关联的配置项清单、拓扑信息或变更记录。
- 查看系统资源监控面板，确认重排模型在检索任务完成后显存占用被自动释放，无持续占用情况。
- 检查检索日志，确认混合检索模式与重排开关的配置参数与预设值一致，无参数缺失或错误。
- 调整相似度阈值，对比不同阈值下的召回结果，确认结果的关联度符合预期。
