# 问题管理与根因分析的客户技术支持与售前答疑：多轮对话与提示词

## 这个品类的数据长什么样
数据来源为故障时间线、运行日志、监控指标、代码提交记录；更新节奏为每次重大故障或每月一次；典型文档包括RCA报告、问题单、复盘纪要、整改跟踪表；字段包含故障发生时间、根因定位描述、关联整改项、验证结果等，无统一强制单位，部分字段以时间戳、文本段落形式存在。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据更新频率较低且单次规模较大，要求多轮对话限制上下文窗口与超时时长，避免因加载过多历史数据或长推理过程导致溢出或中断；文档结构多样且字段分散，需要提示词明确区分不同文档类型的处理逻辑，引导整合多源信息；根因分析需严谨推理，要求多轮对话保留历史上下文用于假设验证，避免重复提问相同信息；业务数据具有专属标识，需要动态注入变量以提升回答针对性，同时需明确输出格式适配技术支持场景。

## 配置怎么定
本文适配FastGPT v4.17.0版本，以下配置基于该版本的界面与参数逻辑：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 对话上下文绑定 | 绑定`chatId`参数 | 维持同一场景的多轮对话连贯性，避免每次对话重置 |
| 历史消息长度限制 | 8000 字符 | 适配根因分析相关文档的单次加载规模，防止上下文溢出 |
| 变量注入配置 | 开启`variables`参数 | 动态传入问题单编号、故障时间等专属业务数据 |
| 输出格式控制 | 禁用Markdown语法 | 适配技术支持场景的纯文本输出需求 |
| 关联文档召回上限 | 前 3 条匹配结果 | 聚焦核心根因证据，减少冗余信息干扰 |
| 对话超时设置 | 600 秒 | 适配根因分析的长推理场景，避免中途中断 |

## 容易做错的三处
- 现象：对话结果仅在侧边栏的历史记录中展示，主对话窗口无实时输出内容。原因：未正确配置`messages`参数的上下文挂载逻辑，导致输出未关联至当前对话会话。
- 现象：每次发起新的技术咨询，系统都会自动新建独立对话会话，无法延续之前的对话内容。原因：未绑定`chatId`参数，系统无法识别当前对话的延续性，默认生成新会话。
- 现象：AI生成的回答始终包含Markdown格式标记，无法调整为纯文本输出。原因：未在提示词配置中明确禁用Markdown格式的输出要求，未通过`variables`参数注入格式控制指令。

## 怎么确认配好了
- 发起连续三次同场景的技术咨询，检查是否始终在同一对话会话内延续，无新建会话的提示或弹窗。
- 输入包含业务专属字段的测试问题，检查AI回答是否自动带入对应字段的内容。
- 查看返回的回答内容，确认无Markdown格式标记，仅为纯文本段落。
- 核对会话的绑定标识，确认每次同场景咨询均使用同一`chatId`进行绑定。
- 等待超过600秒后再次发起咨询，检查系统是否正常完成推理并返回结果，无超时报错。
