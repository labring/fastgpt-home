# 问题管理与根因分析的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
本品类的典型数据由SRE、技术负责人及质量团队维护，来源包括故障时间线、系统日志、监控指标与代码提交记录。日常产出的文档包含RCA报告、问题单、复盘纪要与整改跟踪表，字段涵盖故障发生时间、根因描述、关联日志片段、验证步骤与整改措施。数据更新频率为每次重大故障后或每月一次，单次文档内容长度跨度较大，部分报告包含多段结构化与非结构化内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据更新频率较低，无需实时索引，但单次文档内容跨度较大，要求检索系统适配长文本片段的召回。数据来源包含多类结构化与非结构化内容，需限定检索范围以排除无关的监控指标或代码提交记录。文档中存在根因描述与整改措施的强关联关系，召回时需优先匹配根因相关内容，同时需处理不同文档间可能存在的根因描述冲突问题。动态传入知识库检索参数时，需确保关联的知识库集合正确，避免出现未命中目标文档的情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75-0.85 | 根因分析需高相关文档，过滤低干扰的非关联内容 |
| `limit` | 前5-8条 | 控制召回内容总长度，避免超出大模型上下文窗口 |
| `usingReRank` | 开启 | 对召回结果进行二次相关性排序，解决文档内容冲突问题 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展检索关键词，覆盖根因分析相关的隐含表述 |
| `collectionIds` | 指定目标问题管理类知识库的集合ID | 限定检索范围，排除非品类相关的文档数据 |

## 容易做错的三处
- 排查项：检索结果未命中目标RCA报告，可验证是否未指定`collectionIds`导致检索范围覆盖非问题管理类的知识库数据。
- 排查项：返回结果中存在内容冲突的文档片段，可验证是否未启用`usingReRank`，未对召回结果进行二次相关性排序。
- 排查项：创建知识库时文本理解模型列表为空，可验证是否未在App/Admin服务端配置`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，不可附加/v1等路径、非单模型地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与服务端配置一致且不能为空，非应用/模型供应商密钥）环境变量，导致服务启动校验失败。

## 怎么确认配好了
- 检查App/Admin服务端是否已按FastGPT v4.17.0要求配置`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，不可附加/v1等路径、非单模型地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与服务端配置一致且不能为空，非应用/模型供应商密钥）环境变量，确认无空值或格式错误。
- 验证`collectionIds`是否指向已创建的问题管理类知识库集合，可通过知识库管理页面查看集合ID。
- 发起模拟检索请求，传入预设的根因相关问题，确认返回结果的`similarity`得分处于预设区间内。
- 查看检索日志，确认召回结果未包含无关的监控指标或代码提交记录，且无内容冲突片段。
