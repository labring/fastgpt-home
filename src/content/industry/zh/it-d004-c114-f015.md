# 需求分析与PRD管理的客户技术支持与售前答疑：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自客户访谈记录、内部工单系统、竞品公开页面与埋点看板，由互联网产品团队、业务分析师及产品经理维护。日常产出的文档包含需求调研纪要、PRD文档、用户故事清单与需求变更单，数据更新频率为每周或每产品版本迭代一次。文档多围绕业务目标、验收口径、需求边界展开，包含访谈摘要、变更记录、用户反馈字段，无统一强制格式，随团队使用习惯调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源导致文本格式差异较大，需要适配结构化PRD与零散访谈记录的混合召回。周/版本级的更新频率要求配置增量同步任务，避免全量同步占用过多资源。文档聚焦需求边界与验收口径，检索时需要优先匹配业务术语，避免泛语义内容混入。需求变更单的时效性较强，召回结果需优先返回最新版本，防止使用旧版需求内容引发偏差。零散的用户反馈与工单内容需要拆分成长度合适的文本块，保留上下文关联以确保检索准确性。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置说明。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配需求文档中严谨的业务术语与验收口径，避免低相关结果混入 |
| `limit` | 前6条 | 需求类文档单块内容较长，限制召回条数避免上下文过载 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配访谈记录中零散的口语化反馈与PRD的结构化内容 |
| `usingReRank` | 开启 | 对召回结果重排，优先匹配需求边界确认类的关键问题 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题扩展同义业务术语，覆盖不同团队对同一需求的不同表述 |
| `collectionIds` | 按FastGPT v4.17.0后台生成的专属ID配置 | 仅检索需求分析与PRD管理类文档，避免混入其他品类数据 |

## 容易做错的三处
- 现象：配置专属知识库后调用返回418状态码。原因：未正确配置`collectionIds`参数，或知识库的访问权限未开放给当前应用。
- 现象：无法触发联网搜索结果。原因：未在应用配置中开启联网检索选项，或未配置联网检索的关联参数。
- 现象：知识库预览显示匹配的上下文，但聊天时召回结果不包含对应内容。原因：`limit`参数设置过低，或重排逻辑过滤了部分匹配内容。

## 怎么确认配好了
- 进入FastGPT应用的调试面板，输入典型需求类问题，查看召回结果的来源是否为配置的专属知识库。
- 调整`similarity`参数至0.8，测试输入模糊的需求术语，确认召回结果包含相关的PRD或调研纪要内容。
- 上传一份标注了旧版本的需求变更单，测试检索是否会优先返回最新版本的文档，验证更新时间过滤逻辑生效。
- 查看知识库的存储与文件数量统计，确认未超出1000 MB存储空间上限与默认文件数量阈值。
