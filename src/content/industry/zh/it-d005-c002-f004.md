# IT服务台工单处理的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来自企业ITSM系统、电话或聊天记录、资产系统及内部知识库。日常生成的文档包括服务请求单、事件工单、处理记录与用户满意度表，数据字段包含工单编号、提交人信息、问题描述、处理状态、派单记录等。数据更新节奏为日级或实时，单条数据多围绕具体技术问题展开，包含明确的问题场景与操作痕迹。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来明确约束。多源异构的数据来源，要求索引兼容结构化工单字段与非结构化聊天记录、文档内容的嵌入适配。日级或实时的更新节奏，需索引支持增量同步机制，避免全量重建占用过多资源。短文本为主的工单内容，要求分块逻辑保留问题上下文，避免截断关键排障信息。关联的资产、处理记录等附属数据，要求索引支持跨字段关联召回，确保问答时匹配完整的问题处理链路。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 工单内容多为短技术描述，该长度可保留单条问题的完整上下文，避免截断关键排障信息 |
| 重叠长度 | 100–200 字符 | 弥补短文本分块的上下文断裂问题，确保跨分块的技术逻辑连贯 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的无关工单与文档，确保召回结果贴合具体技术问题 |
| 单次搜索上限 | 前 5 条 | 控制返回结果数量，适配IT服务台快速排障的场景，避免信息过载 |
| `maxToken` | 4096 token | 适配大模型上下文窗口限制，确保召回的向量数据可完整传入模型 |
| `defaultToken` | 2048 token | 适配快速响应的小上下文场景，避免Token超限报错 |
| 增量索引开关 | 开启 | 匹配工单数据的实时更新节奏，减少索引重建的资源消耗 |

## 容易做错的三处
- 现象：页面提示“检测到没有可用的索引模型”，但单独测试Agent与模型配置均正常。原因：未将向量模型绑定至对应工单知识库的索引环节，或增量索引任务未完成导致关联关系未生效。
- 现象：接入多模态Embedding模型时返回Invalid格式报错，接入通用文本Embedding模型可正常运行。原因：未适配多模态模型的输入格式要求，传入的非图像类数据触发了模型的格式校验拦截。
- 现象：升级系统后，原有工单数据的召回结果出现偏差或无法匹配。原因：新版本的分块逻辑与旧版存在差异，未对老数据执行重新分块与索引重建，导致向量嵌入结果与当前系统不匹配。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的系统中，进入知识库管理页面，查看索引状态是否显示为“已完成”，确认增量同步任务的执行日志无报错。
- 发起一条模拟工单问题的查询，核对召回的结果是否包含对应工单的处理记录与相关文档，调整相似度阈值至符合业务需求的区间。
- 调用API接口测试索引创建与召回流程，确认返回的结果字段与配置的召回规则一致。
- 查看向量模型的绑定状态，确认当前使用的模型与知识库的索引模型匹配。
