# IT服务台工单处理的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来自企业ITSM系统、电话或在线聊天记录、资产系统与内部知识库。数据更新节奏为日级或实时，核心文档包含服务请求单、事件工单、处理记录与用户满意度表。单条数据包含工单编号、提交人信息、问题描述、处理状态、关联资产信息、处理步骤等字段，无统一固定单位，随工单类型与企业配置调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散的特征要求溯源环节需关联ITSM、聊天记录、资产系统等多系统的原始数据，不可仅依赖单一知识库来源。实时或日级的更新节奏要求溯源支持增量同步与实时校验，确保引用内容与当前工单的最新状态匹配。工单包含多维度字段的特征，要求溯源时需匹配对应工单上下文，将引用内容绑定至对应问题描述、处理步骤或关联资产条目。统一受理入口的特征要求溯源结果需统一归集至工单详情页，避免多渠道展示混乱。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 适配IT服务台工单引用内容的常见长度，避免超出上下文窗口限制 |
| `responseData` | 开启 | 满足多系统数据的溯源要求，将工单关联的ITSM、聊天记录等来源统一展示 |
| `detail` | 按工单复杂度开启 | 针对复杂排障工单展示完整引用详情，简化常规工单的展示 |
| 单次搜索上限 | 前5条 | 匹配IT服务台工单的典型关联知识库条目数量，避免信息过载 |
| 引用来源展示位置 | 工单详情页底部 | 贴合IT服务台工程师的操作习惯，便于核对处理依据 |
| 引用来源校验开关 | 实时校验 | 适配数据实时更新的特征，确保引用内容与当前工单状态一致 |

## 容易做错的三处
- 出现`quote type error`报错。原因是引用的变量格式不符合配置要求，未匹配工单字段与知识库条目的绑定规则。
- 引用内容超出设置的`quoteMaxToken`限制仍被召回。原因是未正确关联工单上下文与检索逻辑，导致超出配置token上限的切块被纳入检索范围。
- 引用来源未在工单详情页展示。原因是未开启`responseData`配置项，或展示位置设置错误。

## 怎么确认配好了
- 提交一条测试工单，查看回复内容中是否包含预设的引用来源信息。
- 调整`quoteMaxToken`的配置，验证超出设置长度的引用内容是否被截断或过滤。
- 检查工单详情页的引用展示位置，确认来源信息与工单处理步骤正确绑定。
- 模拟实时数据更新，验证引用来源校验开关是否触发实时核对逻辑。
