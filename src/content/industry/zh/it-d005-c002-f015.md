# IT服务台工单处理的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主体为企业IT服务台的日常运维记录，来源包括ITSM系统、电话/在线聊天交互记录、企业资产系统及内部技术知识库。数据更新频率为日级或实时，新工单提交、处理进度更新、满意度反馈会即时或每日同步至数据源。文档结构包含工单ID、问题描述、处理步骤、关联资产编号、用户满意度评分等字段，单条数据以工单为单位，字段多为技术术语或运维相关文本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据来源分散且包含多系统的运维文本，检索环节需要支持跨知识库的关联召回，避免遗漏跨系统的关联信息。数据更新频率较高，要求检索环节能够适配增量更新的知识库内容，避免返回过时的运维方案。工单问题描述多为具体技术故障，存在专业术语集中、表述相对固定的特点，需要兼顾语义匹配与关键词匹配的双重召回能力。同时，工单处理需符合服务时效要求，检索环节需保证响应速度，避免因召回耗时过长导致超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | IT服务工单的技术问题描述专业性强，该阈值可过滤无关结果，保留与故障描述高度匹配的知识库内容 |
| `limit` | `前10–15条` | 兼顾召回覆盖度与模型上下文长度限制，避免过多冗余结果超出模型处理上限 |
| `searchMode` | `vector + fulltext` | 适配工单既有语义关联又有明确技术关键词的特点，混合召回模式可提升结果准确性 |
| `usingReRank` | `开启` | 多知识库召回结果可能存在冗余，重排可优化Top结果的相关性，适配工单快速排障的需求 |
| `datasetSearchUsingExtensionQuery` | `开启` | 工单问题可能存在表述模糊的情况，扩展查询可补充同义词、技术术语变体，提升召回覆盖度 |
| `collectionIds` | `绑定IT服务台专属知识库集合` | 隔离业务数据，避免无关知识库结果干扰工单处理流程 |

## 容易做错的三处
- 现象：挂载多个知识库后，返回结果未按预期优先级展示。排查项：确认已通过`collectionIds`指定优先检索的知识库集合，避免所有挂载知识库的结果混合返回。
- 现象：通过mongorestore导入知识库后，无法查询到导入的文档内容。排查项：确认已执行文档索引重建操作，确保导入的原始数据已生成向量或全文索引，可被检索环节识别。
- 现象：批量重新训练知识库文档后，检索结果仍未更新。排查项：确认知识库的向量索引已完成重建，且已触发实时召回逻辑，未使用旧的缓存索引结果。

## 怎么确认配好了
- 检查FastGPT v4.17.0服务端环境变量，确认`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions，非VLLM/Ollama/Xinference等单模型地址）和`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空，非应用API Key、模型供应商密钥、按应用签发的token）已正确配置且无空值，未配置将导致服务启动校验失败，符合官方部署要求。
- 发起模拟工单查询，验证返回结果包含指定专属知识库的内容，且结果条数符合`limit`参数的设置范围。
- 调整`similarity`参数值后发起重复查询，观察返回结果的相关性变化，确认参数配置已生效。
- 查看AI Proxy服务日志，确认检索请求未出现连接超时或鉴权失败的报错，确保检索链路正常。
