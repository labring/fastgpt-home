# IT资产盘点的技术文档与接口问答：向量模型与索引
本文适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的数据主要来自资产管理系统、采购系统、财务固定资产模块、终端管理平台。日常处理的文档包括资产台账、盘点表、领用归还单、报废申请。数据更新节奏为月、季或年周期，单次更新涉及单条或批量资产信息。文档结构多包含资产编号、设备名称、部署位置、使用责任人、采购时间、资产状态等字段，无统一固定格式，部分系统导出的文档会带有批量表头。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散导致字段格式不统一，需在索引前完成字段标准化适配，避免向量提取偏差。更新频率低但单次批量数据量可能较大，索引构建需支持增量更新，减少全量重建的耗时。文档类型多样，需针对台账、申请单等不同文档设置差异化分块规则，适配不同长度的文本内容。不同于配置管理与CMDB维护，本品类的索引需优先聚焦资产权属、位置和使用人相关字段，这会影响向量编码的优先级设置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配资产台账、申请单的单块文本长度，避免分块过碎或过长 |
| 重叠长度 | 50–100 字符 | 保留相邻块的上下文关联，确保资产位置、使用人等跨块信息不丢失 |
| `defaultToken` | 1024 | 匹配通用向量模型的输入token上限，适配多数资产类文本的编码需求 |
| `maxToken` | 4096 | 限制单条索引的最大token数，防止超长文本导致的索引失败 |
| 单次搜索上限 | 前 10 条 | 平衡召回效率与精准度，覆盖核心资产查询的结果需求 |
| 最大上下文 | 按实测标定 | 适配不同规模的资产数据集，避免上下文溢出 |

## 容易做错的三处
- 切换知识库索引时出现60秒超时，界面返回请求超时提示。原因是未针对低更新频率的资产数据启用增量索引，执行全量重建时耗时超出系统限制。
- 知识库仅包含少量资产数据，但长期处于训练中或重建状态超过一天。原因是分块长度设置过小，导致大量冗余分块被生成，延长了索引处理流程。
- 批量为资产集合添加索引时，请求返回参数错误无法完成入库。原因是未按照资产文档的字段结构配置索引映射，导致系统无法识别核心资产信息字段。

## 怎么确认配好了
- 提交单条资产文档的索引测试，查看向量编码结果是否包含资产编号、使用人等核心字段。
- 模拟批量索引提交，检查系统任务队列的处理速度是否符合预期，无长期堆积的重建任务。
- 发起资产位置查询的测试，确认召回结果的条数与配置的单次搜索上限匹配。
- 查看索引集合的映射规则，确认所有资产文档的分块统一映射到同一索引集合，未配置单文档单独索引。
- 查看索引构建日志，确认`defaultToken`与`maxToken`的取值未触发编码超限报错。
