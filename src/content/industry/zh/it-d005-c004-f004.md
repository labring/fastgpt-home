# IT采购与供应商管理的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据通常来自采购系统、供应商报价文件、预算表、合同系统。日常生成的文档包括采购申请单、比价记录、正式合同、验收单，单条数据对应单次采购流程节点，更新频率为单次采购单生成即更新，月度会有批量的预算调整或供应商准入文档同步。文档字段包含申请单号、预算金额、采购品类、验收合格率等，部分文档附带结构化报价明细与条款文本，无统一固定格式，随采购品类差异存在字段变化。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。多源异构的数据来源要求索引支持多格式解析，保留字段与文档的关联关系。按单更新的频率决定需优先配置增量索引逻辑，避免全量重建带来的资源占用。文档字段随采购品类差异变化，分块处理时需保留字段元信息作为上下文，防止向量匹配时混淆不同品类的采购参数。文本包含IT设备参数、合同条款等专业内容，向量模型需适配专业术语的语义编码，降低匹配偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配采购申请、合同等文本的平均段落长度，避免块内语义割裂 |
| 重叠长度 | 100–200 字符 | 保留跨块的上下文关联，防止分块切断关键条款或参数 |
| `defaultToken` | 2000 token | 匹配单次查询的上下文窗口需求，容纳多条采购文档的核心信息 |
| `maxToken` | 6000 token | 支持批量召回文档的完整嵌入，适配多文档问答的上下文长度 |
| 相似度阈值 | 0.72–0.85 | 过滤低相关性的比价记录或合同条款，避免无效召回 |
| 单次搜索上限 | 前 8 条 | 适配单采购流程的关联文档数量，控制返回结果的冗余度 |

## 容易做错的三处
- 现象：从FastGPT v4.9.0升级到v4.9.3后，原可查询的采购文档无法召回，搜索结果为空。原因：升级后默认增量索引逻辑变更，未触发历史文档的重新向量化，导致旧版本索引格式不兼容。
- 现象：上传Excel格式的供应商报价表后，向量化完成但搜索结果字段混乱。原因：未配置Excel表格的列映射规则，分块时未保留采购品类、报价金额等关键字段的关联关系。
- 现象：尝试接入m3e向量模型时，使用aiproxy代理无法正常生成向量。原因：未正确配置向量模型的代理路径与请求头，aiproxy的转发规则未适配m3e的接口格式。

## 怎么确认配好了
- 手动上传单份采购申请单，执行定向搜索，确认可召回对应文档的核心条款。
- 触发增量索引任务，查看FastGPT v4.17.0的索引日志，确认仅新增的采购单被处理，无全量重建的异常耗时。
- 调整相似度阈值，测试不同阈值下的召回结果数量，确认符合预期的过滤效果。
- 验证多源数据导入，分别上传PDF合同与Excel报价单，确认两类文档均可正常生成向量索引。
