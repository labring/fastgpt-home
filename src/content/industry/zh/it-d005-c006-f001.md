# Pull Request评审的技术文档与接口问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
Pull Request评审的核心数据来自关联代码仓库的提交记录、CI流水线执行结果、关联Issue链接及贡献者提交内容。日常流转的文档包含PR说明文档、代码评审意见、CI测试报告、合并状态记录。数据更新频率通常为日或周，单条PR数据包含变更范围、冲突标记、测试通过率、提交者信息等字段，无固定统计数值，仅按实际提交节奏更新。该品类处理的是可合并的代码变更，与Issue分拣等品类的处理对象存在明确差异。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
Pull Request评审的数据来源分散且关联多个外部系统，需通过HTTP接口拉取代码仓库的PR详情、CI结果等内容，因此接口鉴权需匹配各外部系统的权限规则。数据更新节奏不稳定，接口调用需适配批量拉取与增量同步的逻辑，避免重复请求或遗漏更新。单条PR数据字段存在非标准化结构，接口返回的`responseData`需做字段映射，适配评审工具的解析逻辑。同时，变更意图确认环节依赖上下文关联，接口调用需携带关联上下文参数，确保返回内容匹配PR的具体变更范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {外部系统鉴权令牌}` | 符合HTTP接口标准鉴权规范，适配代码仓库、CI工具的接口权限校验 |
| `variables` | 包含PR编号、仓库地址、CI任务ID的键值对 | 用于动态传入PR评审的上下文参数，替换提示词中的占位变量 |
| `responseData` | 按`{prId: string, ciStatus: string, hasConflict: boolean}`结构映射 | 标准化接口返回格式，适配评审工具的字段解析逻辑 |
| 接口超时阈值 | 30-60秒 | 适配CI结果拉取的平均耗时，避免因外部系统响应延迟导致调用失败 |
| 单次拉取数量 | 前10-20条待评审PR | 匹配日常评审的处理节奏，避免单次请求数据量过大 |

## 容易做错的三处
- 现象：调用接口后返回内容未替换提示词中的占位变量，结果与PR场景无关。原因：未通过`variables`参数正确传入上下文参数，或占位变量命名与传入键名不匹配。
- 现象：启动FastGPT v4.17.0及以上版本的服务时校验失败，提示AI Proxy配置缺失。排查项：检查是否在App/Admin服务端配置了`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）和`AIPROXY_API_TOKEN`（AI Proxy管理员Token）环境变量，或是否误将其填入工作流全局变量、应用API请求头或普通模型管理页面等非服务端部署配置位置。
- 现象：调用外部接口后返回数据解析失败，出现字段为空或格式错误。原因：未通过`responseData`配置标准化字段映射，直接使用原始接口返回的非结构化数据。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量，确认`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）和`AIPROXY_API_TOKEN`（AI Proxy管理员Token）已正确配置，且`AIPROXY_API_ENDPOINT`未附加`/v1`等路径后缀。
- 发起测试接口调用，传入测试用的`variables`参数，验证占位变量是否被正确替换，返回内容匹配PR评审场景。
- 查看接口调用日志，确认`Authorization`头已正确携带，且返回的`responseData`字段符合预设的映射结构。
- 启动FastGPT服务，验证服务启动无校验报错，且外部系统接口调用返回正常状态码。
