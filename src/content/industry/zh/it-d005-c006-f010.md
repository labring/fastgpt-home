# Pull Request评审的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
数据来自代码仓库的PR元数据、CI流水线执行日志、关联的Issue链接、贡献者提交的变更文件；更新节奏通常为日度或周度；日常文档包含PR说明文本、代码评审意见条目、CI结果报告、合并状态记录；字段涵盖变更内容摘要、关联Issue编号、CI通过率、提交者标识等，无统一固定的多字段统计格式，随对应仓库的配置灵活调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据分散于代码仓库、CI流水线等多个独立系统，需配置跨源关联规则以完整追溯PR评审的全部依据；更新节奏不固定，需匹配索引更新频率以保证引用数据的时效性；日常文档包含结构化评审意见与非结构化变更说明，需适配不同格式的内容拆分与检索；PR关联的Issue、CI结果随评审推进动态更新，溯源环节需绑定最新的变更快照，避免引用过时的评审依据。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配PR评审文档的平均长度，避免截断关键评审意见与CI结果内容 |
| 重排 | 开启 | 适配PR数据中混杂的结构化评审条目与非结构化变更说明，提升检索相关性 |
| 单次搜索上限 | 前6条 | 匹配单PR关联的典型关联数据数量，避免引入冗余的非评审相关内容 |
| `detail` | 开启 | 保留引用来源的完整元数据，便于溯源关联的CI结果与Issue链接 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关的非PR关联数据，聚焦评审相关的核心内容 |
| `responseData` | 仅返回关联PR与CI数据 | 限定溯源范围，避免引入无关的知识库内容 |

## 容易做错的三处
- 现象：开启重排后出现引用为空的结果。原因：PR关联的CI结果或Issue链接的文本长度较短，重排阈值过滤了符合基础相似度的有效片段。
- 现象：检索请求超时未返回结果。原因：未调整`quoteMaxToken`适配长PR文档，导致检索时加载过多内容触发超时。
- 现象：引用来源未关联到对应PR的变更记录。原因：未开启`detail`配置，未保留元数据关联字段，无法绑定PR的合并状态与提交信息。

## 怎么确认配好了
- 发起一条模拟PR评审的技术问答，检查返回结果中是否包含关联的CI结果与Issue链接。
- 调整`quoteMaxToken`参数，验证返回引用的token长度是否符合预设范围。
- 关闭重排功能后重新检索，对比结果条数变化，确认重排配置已生效。
- 查看引用溯源的元数据字段，确认是否包含提交者标识与合并状态信息。
