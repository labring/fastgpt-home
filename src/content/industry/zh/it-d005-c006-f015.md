# Pull Request评审的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来自项目代码仓库、CI流水线、关联Issue链接及贡献者提交记录，更新频率通常为日或周。日常文档包含PR说明、代码评审意见、CI结果与合并记录，其中PR说明标注变更范围与依赖项，CI结果包含失败步骤与耗时，合并记录记录审批人与时间戳。数据结构混杂代码片段、结构化日志与自然语言文本，字段包含变更文件列表、代码行数、评审意见ID等，通常无统一的标准化格式。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源混杂的格式要求检索系统需适配代码、日志与自然语言的混合匹配，需针对不同数据源配置差异化的召回权重。日/周级的更新频率要求知识库增量更新调度需匹配项目的迭代节奏，避免数据滞后或冗余更新。PR评审的上下文长度有限，过多的召回结果会超出模型输入限制，需严格控制召回条数。同时，PR关联数据存在强依赖关系，需确保检索结果同时覆盖变更意图、依赖信息与历史评审记录，避免遗漏关键关联内容。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.72–0.80` | 匹配PR相关的代码与文档语义，平衡召回完整性与结果相关性 |
| `limit` | `前6条` | 适配PR评审的上下文长度限制，避免超出模型输入阈值 |
| `searchMode` | `代码语义+文档关联` | 覆盖PR数据中的代码变更与关联文档、CI日志两类核心信息 |
| `usingReRank` | `开启` | 对召回的多组相似结果进行重排序，提升高相关内容的展示优先级 |
| `datasetSearchUsingExtensionQuery` | `开启` | 通过扩展PR的变更关键词，关联召回关联的Issue、CI日志等辅助信息 |
| `collectionIds` | `绑定PR关联的代码仓库、CI日志、Issue数据集ID` | 限定检索范围，排除无关知识库内容的干扰 |

## 容易做错的三处
- 现象：调试时检索结果为空或无匹配内容。原因：未绑定对应代码仓库、CI日志的数据集ID，或`similarity`阈值设置过高过滤了有效结果。
- 现象：问答环节显示冗余的知识库搜索标记。原因：未关闭问答结果中的搜索展示开关，或未配置仅在需要时触发检索的规则。
- 现象：线上部署后导入的PR相关文档出现乱码。原因：线上部署的编码格式与本地不一致，或导入的CI日志包含未转义的特殊字符未被预处理。

## 怎么确认配好了
- 上传一条模拟PR说明，检查检索结果是否包含关联的代码变更、CI结果与历史评审意见。
- 调整`similarity`参数至0.70与0.85，观察检索结果的召回条数变化，确认阈值生效。
- 关闭`usingReRank`后对比检索结果的排序，确认重排功能正常工作。
- 查看知识库绑定的`collectionIds`，确认仅包含PR评审相关的数据集，无冗余绑定。
