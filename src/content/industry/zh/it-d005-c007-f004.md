# SLA与服务报告的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
本品类的数据主体来自客户成功经理、服务经理与技术支持主管的日常工作产出，包含SLA条款文档、月度服务报告、可用性统计表格、客户复盘纪要等。数据来源涵盖监控系统的运行数据、工单系统的服务记录、正式合同文本与客户沟通记录。数据更新频率以月或季度为周期，无高频实时更新需求。文档结构包含固定字段如服务周期、指标类型、事件详情，部分非结构化文档为口语化的复盘内容，整体数据体量随服务周期累积增长。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于数据以月或季度为周期更新，无需频繁执行增量索引，可采用批量离线构建索引的方式降低资源消耗。数据包含结构化统计表格与非结构化纪要两类格式，向量模型与索引需同时适配文本段落与表格字段的向量化处理，避免丢失结构化数据中的关键指标关联。固定的服务周期与指标类型字段要求索引需支持按时间维度与关键词进行精准召回，确保检索结果可直接用于SLA指标计算与异常事件归因。低频更新的特性也要求索引结构优先保障检索效率与召回准确率，避免因索引错误引发赔付争议或客户投诉。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配月度服务报告、SLA条款的段落长度，避免跨关键信息分割 |
| 重叠长度 | 100–150 字符 | 保留跨分块的SLA指标上下文，确保检索时不丢失关键关联 |
| maxToken | 4000 token | 匹配商用API的输入限制，适配长文档的向量处理 |
| 相似度阈值 | 0.75–0.85 | 过滤低关联的历史服务记录，避免错误归因 |
| 单次搜索上限 | 前10条 | 平衡检索效率与召回完整性，适配月度汇总的报告数据量 |
| 重排 | 开启 | 优化SLA条款与服务事件的匹配相关性，提升口径对齐效率 |

## 容易做错的三处
- 现象：向量检索首次响应耗时超过8秒，混合检索耗时更长。原因：未针对月度/季度更新的低频数据调整索引策略，仍使用高频增量索引导致资源占用过高。
- 现象：建索引任务停留在最后一组，无明确报错提示。原因：未设置合理的`defaultToken`上限，导致大体积的SLA条款文档在向量化时触发API调用超时。
- 现象：部分文件无法成功向量化，知识库构建失败。原因：未提前确认支持的文件类型，误上传非标准格式的合同扫描件或未结构化的音频转写文件。

## 怎么确认配好了
- 执行单次向量检索测试，核对返回结果是否包含目标SLA条款或历史服务报告的关键内容。
- 查看FastGPT v4.17.0的索引构建日志，确认无超时或格式错误提示，任务可在合理时间内完成。
- 调整相似度阈值，验证返回结果的关联度是否符合业务场景的需求。
- 批量导入测试用的SLA文档与服务报告，确认所有文件均可正常完成向量化与索引。
