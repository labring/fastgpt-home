# SLA与服务报告的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来源包含监控系统、工单系统、合同文件与客户沟通记录，更新周期为月或季度。日常产出的文档包括SLA条款文本、月度服务报告、可用性统计报表与客户复盘纪要，核心字段包含SLA指标项、事件发生时间、统计周期、服务响应次数与异常事件详情，无百分比类统计单位，单份文档的文本长度跨度较大，从数百字符的指标条目到数千字符的复盘纪要均有覆盖。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散且涉及多系统的原始记录，溯源环节需要同时关联多个数据源的标识，确保SLA指标与对应原始数据的匹配准确性。更新周期为月或季度，无需实时拉取数据，但需按周期对齐统计口径，避免跨周期数据混淆。文档结构多样且字段差异明显，需要针对不同文档类型配置不同的匹配规则，确保引用内容与原始来源的对应关系清晰。此外，出错后易引发赔付争议，因此溯源环节必须保证引用内容的完整性与准确性，不能出现缺失或错位。

## 配置怎么定
本页面配置逻辑基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配月度服务报告、SLA条款的单段文本长度，完整保留引用内容 |
| `responseData` | 开启 | 用于关联原始数据的溯源标识，匹配多来源的SLA统计数据 |
| `detail` | 完整 | 展示原始文档的完整内容，满足异常事件归因的需求 |
| 单次溯源上限 | 前5条 | 控制返回的溯源条目数量，避免内容过载影响阅读 |
| 溯源匹配阈值 | 按实测标定 | 适配不同来源文档的字段匹配精度，确保关联准确 |

## 容易做错的三处
- 现象：返回的溯源结果中无原始文档的链接或唯一标识，原因是未开启`responseData`配置，未关联数据源的关键标识。
- 现象：引用的SLA条款或服务报告文本被截断，无法完整展示核心内容，原因是`quoteMaxToken`取值过小，未覆盖目标文本的长度。
- 现象：工作流调用接口时，无法通过本地变量关联内部存储的SLA文档，仅支持传入外部资源链接，原因是未配置溯源参数的变量绑定规则，仅识别直接传入的外部地址。

## 怎么确认配好了
- 发起针对SLA指标计算的接口问答，检查返回结果中是否包含溯源的原始数据标识，如文档ID或来源链接。
- 测试引用长文本的SLA条款，确认返回的引用内容未被截断，完整覆盖目标文本。
- 调用工作流接口，验证是否可以通过变量绑定关联内部存储的SLA文档数据。
- 检查返回的溯源条目数量，确认符合配置的单次溯源上限要求。
