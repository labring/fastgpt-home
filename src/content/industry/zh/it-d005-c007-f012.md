# SLA与服务报告的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
本品类的数据主要来自监控系统、工单系统、合同文本与客户沟通记录。日常处理的文档包括SLA条款、月度服务报告、可用性统计报表、客户复盘纪要，更新周期多为月度或季度。文档结构多包含服务周期、指标阈值、实际达成值、异常事件记录、赔付条款等字段，字段多为文本型数值与状态标识，无统一固定格式，部分文档存在跨页重复内容与零散备注。

## 这些特征在「文档解析与分块」这一环带来什么约束
数据来源分散导致文档格式不统一，需适配合同文本的条款式结构、工单系统的结构化日志与客户纪要的自由文本。月度或季度的更新频率意味着解析任务需批量处理，无法接受过长等待时间。文档中包含SLA指标阈值、实际达成值等核心字段，解析时需保留字段关联性，避免分块破坏指标上下文。异常事件记录与赔付条款的强关联要求分块不能割裂相关内容，否则会影响后续SLA指标计算与归因。同时，部分文档存在跨页的重复表头与零散备注，需在解析时过滤无效冗余内容。

## 配置怎么定
本文档适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 本品类文档多包含连贯的条款与指标，该长度可保留SLA条款、指标组的完整上下文，避免割裂关联内容 |
| `chunkSplitter` | 按段落+标题分割 | 适配SLA文档的层级结构，确保每个分块对应独立的服务条款或指标项，便于后续口径对齐 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 月度服务报告通常包含多页统计数据，该超时区间可覆盖批量解析的等待需求，避免因超时中断任务 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 本品类季度汇总报告可能包含多份历史文档的整合，该上限可满足批量上传需求 |
| `customPdfParse` | 开启 | 本品类文档多为标准化PDF格式，开启自定义解析可保留原始排版与字段结构，提升解析准确性 |

## 容易做错的三处
- 现象：调用文件解析接口后返回超时错误，状态码为504。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以处理月度汇总类的大体积文档，对应第三方解析工具集成后的排队超时场景。
- 现象：本地部署版本开启文件解析后功能失效，无报错日志。原因：未开启`customPdfParse`配置，且未安装对应解析依赖，导致无法处理标准PDF格式的SLA文档。
- 现象：解析后的分块出现SLA指标与对应赔付条款被拆分到不同块的情况。原因：`chunkSize`设置过小，且`chunkSplitter`未配置为按标题分割，破坏了条款间的上下文关联。

## 怎么确认配好了
- 上传一份标准SLA条款PDF，查看解析后的分块是否保留了独立条款的完整性。
- 调整`PARSE_FILE_TIMEOUT_SECONDS`参数后，上传一份100页以上的月度服务报告，确认解析任务可正常完成无超时。
- 检查`UPLOAD_FILE_MAX_SIZE`的配置，确保可上传符合业务需求的最大体积文档。
- 查看解析后的分块元数据，确认核心字段如服务周期、指标阈值已被正确提取并保留在分块内。
