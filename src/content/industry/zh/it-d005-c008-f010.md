# 专题活动运营的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的核心数据围绕专题活动全流程产生，日常文档包括活动方案、资源位排期、活动页面文案、复盘报告四类。数据来源覆盖内部内容库、活动后台管理系统、流量统计工具及用户反馈渠道。内容更新节奏以周为单位，遇节假日专属活动会临时调整更新频率。数据字段包含活动周期、资源位编号、文案版本、流量指标等，需结合具体文档类型匹配对应标识，无统一固定单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
专题活动运营的内容有明确周期与资源位限定，因此引用溯源需精准匹配当前活动的时间范围与资源位，避免召回跨周期或无关内容。多来源的数据需要清晰区分标识，例如将活动后台的资源位排期与内容库的文案分别标注来源，便于运营人员复盘时快速核对。活动文档的更新节奏以周为单位，知识库同步需匹配该节奏，防止引用过期内容。活动文案与复盘报告的长度差异较大，溯源信息的展示需适配不同文档的排版需求，避免出现格式冲突。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配专题活动运营的业务特征：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 适配活动文案、复盘报告的单段内容长度，避免截断关键溯源信息 |
| `responseData` | 包含来源文件名+资源位ID | 匹配活动运营的多来源数据特征，明确标注内容来自活动后台还是内部内容库 |
| 知识库同步周期 | 7天，节假日活动可临时调整 | 匹配专题活动运营的周度更新节奏，避免引用过期内容 |
| `detail` | 开启 | 保留完整的溯源细节，适配复盘报告的严谨性要求 |
| 单次召回上限 | 前3条 | 聚焦当前活动的核心内容，避免过多召回干扰上下文，符合专题活动的窄范围内容属性 |
| 引用来源展示开关 | 开启 | 满足活动复盘时的溯源需求，便于运营人员核对活动方案与页面文案的一致性 |

## 容易做错的三处
- 现象：工作流中调用知识库模块后，输出未关联对应活动文档的引用来源。原因：未将`responseData`配置为包含活动专属的来源标识，导致溯源信息缺失。
- 现象：AI输出的引用标记出现乱码，最终显示为错误的引号格式。原因：未开启`detail`配置项的格式校验，导致溯源标记的编码未适配活动文案的排版规则。
- 现象：当用户提问超出当前活动知识库范围时，仍返回已过期的活动内容引用。原因：未根据活动的周度更新节奏调整知识库同步周期，导致召回了非当前周期的内容。

## 怎么确认配好了
- 发起针对活动方案或资源位排期的针对性提问，核对输出的引用标记是否包含对应文档的名称与资源位编号。
- 测试超出当前活动知识库范围的提问，确认是否未返回无关的活动内容引用。
- 查看输出内容的末尾引用格式，确认无乱码或错误的引号标记。
- 调整`quoteMaxToken`的取值，验证输出是否完整保留了溯源所需的文档片段，未出现截断。
