# 个人信息保护合规的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自业务系统、App权限清单、隐私政策、用户请求记录，由隐私合规团队、安全咨询或法务部门维护。日常处理的文档包括个人信息清单、处理规则、影响评估报告、用户授权文本，文档结构多为结构化字段与非结构化文本结合，包含自然人识别信息关联字段、处理场景描述、合规判定项等，更新频率为季度或每次产品功能变更时。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且包含自然人识别信息，需在索引阶段严格过滤敏感字段，避免合规风险。更新频率随产品变更调整，索引需支持增量更新，降低全量重建的维护成本。文档类型多样，既有结构化清单也有长文本报告，向量模型需适配混合格式的文本切分，避免长文本截断导致合规信息丢失。同时，数据关联自然人信息，需确保索引过程不泄露原始个人信息，仅存储加密后的向量特征。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配个人信息清单、处理规则等文档的平均长度，避免单块包含过多敏感信息或截断关键合规条款 |
| 重叠长度 | 100–200 字符 | 保留跨块的合规关联信息，避免分块破坏处理规则的上下文完整性 |
| 相似度阈值 | 0.75–0.85 | 区分相似的个人信息处理场景，避免重复索引或误关联不同的授权文本 |
| 单次搜索上限 | 前 8 条 | 平衡合规查询的召回范围与响应速度，避免返回过多关联信息导致合规判定冗余 |
| `maxToken` | 4096 token | 适配长文本的影响评估报告，确保完整加载合规判定所需的上下文，FastGPT v4.17.0版本默认适配该参数范围 |
| `defaultToken` | 2048 token | 满足常规技术文档与接口问答的上下文需求，平衡资源占用与查询效果 |

## 容易做错的三处
- 现象：调用向量模型接口返回401未授权错误，curl测试可正常获取向量结果。原因：FastGPT配置的向量模型访问密钥未正确绑定对应模型权限，或密钥未随业务系统更新同步。
- 现象：自定义文档切分后生成的索引顺序与原始文档块不一致，自定义切分的索引顺序丢失。原因：知识库全局去重开关处于开启状态，系统自动删除重复块时打乱了原始切分的排列顺序。
- 现象：知识库索引合并组件运行后，部分相似的个人信息处理规则未被正确识别，或关键合规条款被误合并。原因：相似度阈值设置不符合合规文档的匹配需求，未针对个人信息清单类文档调整匹配精度。

## 怎么确认配好了
- 上传一份测试用的个人信息清单文档，查看切分后的块数与预期一致，无明显敏感字段遗漏。
- 发起一次技术文档与接口问答查询，核对返回结果的上下文完整性，确认未出现关键合规条款截断。
- 检查向量模型的调用日志，确认未出现401、超时等异常状态码，接口调用符合预期。
- 关闭全局去重开关后上传自定义切分的文档，验证索引块的顺序与原始切分结果一致。
