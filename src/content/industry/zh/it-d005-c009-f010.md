# 个人信息保护合规的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来源于业务系统、App权限清单、隐私政策、用户请求记录，更新节奏为每季度或每次产品功能变更时触发。日常产出的文档包含个人信息清单、处理规则、影响评估报告、用户授权文本，核心字段包括信息类型、处理目的、合法性基础、存储期限等，不同文档类型的格式存在差异，需按类型匹配对应字段完成引用。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据源分散导致需关联多系统、多类型文档完成溯源，对引用范围的精准性要求较高。更新节奏不固定，需定期同步最新版本的合规文档，避免引用过时内容引发合规风险。文档结构无统一格式，需针对不同文档类型匹配对应字段，增加了引用片段的精准匹配难度。同时，该品类出错后果为投诉、行政处罚，要求溯源结果必须准确可追溯，无法接受模糊或错误的引用来源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `1200–1800 token` | 匹配合规文档核心片段的平均长度，避免截断关键合规字段 |
| `responseData` | 仅包含合规文档核心字段 | 过滤非合规相关数据，简化溯源流程 |
| `detail` | 包含来源文件名+字段名+原文片段 | 满足合规审计的完整溯源要求 |
| 数据源同步频率 | 按产品变更触发+每季度全量同步 | 匹配该品类的更新节奏，确保引用内容为最新版本 |
| 引用来源标识配置 | 自动附加文档ID与更新时间 | 快速定位数据源版本，便于合规回溯 |

## 容易做错的三处
- 引用结果中混入非合规文档内容，原因是未限制`responseData`的引用范围，引入了无关数据源。
- 合规字段被截断无法完整展示，原因是`quoteMaxToken`取值过低，未匹配合规文档核心片段的长度。
- 工作流调用时仅支持外部链接上传合规文档，无法关联本地变量绑定的文档，原因是未正确配置引用来源与工作流参数的绑定规则。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的控制台中查看引用日志，确认每条引用结果均附带文档ID与更新时间标识。
- 触发一次模拟的产品功能变更，检查合规文档的引用内容是否同步更新为最新版本。
- 调整`quoteMaxToken`的取值，验证引用片段的长度是否随配置变化。
- 运行合规场景的模拟调用，确认仅返回合规文档的核心字段，无无关数据混入。
