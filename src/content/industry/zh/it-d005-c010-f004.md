# 事件响应与故障处理的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
本品类的典型数据来自监控告警、日志平台、APM工具与用户反馈，更新节奏为实时或每次事件触发时生成。日常文档包含故障工单、事件时间线、应急预案与故障通报，字段包含告警发生时间、影响服务范围、止损操作步骤、通报对象等，无统一固定格式，多为半结构化或非结构化文本，单条数据长度差异较大，从短告警信息到完整事件复盘报告均有覆盖。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时或事件触发的更新节奏要求索引支持增量更新与快速刷新，避免因全量索引重建导致的延迟。半结构化的文档结构要求分块策略需匹配事件节点与业务逻辑，保障上下文完整性。数据的时效性要求向量检索需控制延迟，确保运维人员可快速获取关联信息。同时，故障场景下的信息优先级差异，要求索引可按事件时间、影响范围等字段进行过滤，避免无关数据干扰检索结果。同一个文档块的多个索引需按业务关联维度绑定，检索时需按优先级返回匹配结果，避免重复或无关信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配故障工单、应急预案的单段信息密度，避免单块信息过载或过碎 |
| 重叠长度 | 100–200 字符 | 保障事件时间线的上下文连续性，防止跨块的操作步骤或时间节点断裂 |
| `maxToken` | 8192 token | 适配主流向量模型的输入上限，兼容长文本格式的故障通报与完整事件复盘 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关的历史告警信息，聚焦当前事件的关联数据 |
| 单次搜索上限 | 前 10 条 | 控制检索结果数量，适配运维值班的快速响应需求，避免信息过载 |
| `defaultToken` | 4096 token | 平衡上下文长度与检索速度，满足实时故障处理的时效性要求 |

## 容易做错的三处
- 向量化请求仅发送单文本切片。现象为向量化接口返回耗时超出预期，服务器资源占用偏高。原因是未启用批量发送配置，FastGPT默认按单条文本调用向量化服务，未匹配向量化服务的批处理接收逻辑。
- 无法获取分块索引内容。现象为调用API返回的分块信息字段为空。原因是未开启分块索引持久化存储开关，导致分块元数据未被正确记录。
- 自定义阿里multimodal-embedding-v1向量模型失败。现象为模型加载报错或检索结果无匹配内容。原因是未正确配置模型的API端点、请求头鉴权参数，未适配多模态模型的输入格式要求。

## 怎么确认配好了
- 查看向量化服务的调用日志，验证单请求发送的文本切片数量符合批处理要求。
- 调用分块索引查询API，传入测试文档ID后检查返回的分块内容字段是否存在有效数据。
- 在FastGPT v4.17.0版本中，通过向量模型管理页面上传测试文本，验证模型返回的向量数据格式正确。
- 上传一份测试故障工单，执行检索查询，验证返回结果的数量与相似度符合配置阈值。
