# 云主机交付与资源开通的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自云管理平台、订单系统、IAM权限系统与计费系统。日常处理的文档包括资源开通单、实例配置表、账号权限单、交付确认单，包含实例规格、网络安全组配置、账号权限范围、计费关联项等字段，单位涉及vCPU核数、内存GB、带宽Mbps等。数据更新节奏为每单实时同步，每完成一次资源开通或配置变更，对应文档与系统数据即完成更新。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源数据来源要求索引支持跨系统数据关联，避免割裂的业务信息；实时/按单更新的节奏要求索引支持增量同步，无需全量重建即可覆盖新开通的资源数据；多样的文档结构要求分块逻辑适配不同单据的字段组合，避免拆分破坏业务语义；明确的字段与单位要求向量建模时保留业务标识，确保召回结果与实际资源配置匹配。同时，高耗时的规格核对环节，需要索引优先召回高匹配度的资源规格与配置项，降低后续人工校验成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配资源开通单、实例配置表的字段长度，避免拆分破坏业务语义 |
| 重叠长度 | 100–200 字符 | 覆盖跨分块的配置关联信息，比如安全组规则跨分块的描述 |
| 相似度阈值 | 0.75–0.85 | 匹配资源配置的精准匹配需求，避免召回不匹配的规格或权限项 |
| 单次搜索上限 | 前10条 | 控制召回结果数量，适配运维人员快速核对的场景 |
| maxToken | 4096 token | 适配云主机配置文档的上下文长度，确保完整传递业务信息 |
| defaultToken | 按实测标定 | 适配不同私有化部署的资源数据规模，平衡召回效率与准确性 |

## 容易做错的三处
- 现象：向量召回结果出现非匹配的云主机规格，无法正确关联账号权限信息。原因：未针对资源开通单、实例配置表的专属业务字段配置分块逻辑，导致分块拆分破坏了规格与权限的关联语义。
- 现象：本地部署FastGPT v4.17.0后，无法加载外部配置的索引模型，界面弹出模型加载失败提示。原因：未正确配置模型访问的网络权限与地址，未适配云主机数据的字段格式完成模型输入适配。
- 现象：向量存储迁移后出现数据召回异常，无法检索到新开通的云主机资源。原因：未配置增量同步索引的更新规则，仍使用全量重建逻辑，导致新数据未被正确索引。

## 怎么确认配好了
- 上传一份真实的资源开通单文档，发起关键词检索，核对召回结果是否包含对应实例规格与配置项。
- 模拟一次新的资源开通操作，等待索引同步完成后发起检索，确认新资源信息可被正常召回。
- 调整相似度阈值或单次搜索上限，验证召回结果的数量与匹配度是否符合业务核对需求。
- 查看索引监控面板，确认增量同步任务的执行状态与数据更新频率符合实时/按单的节奏。
