# 云资源合规审计的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据主要来自云审计日志、IAM、CMDB及安全基线扫描工具，日常处理的文档包括合规检查表、权限审计报告、资源清单与整改跟踪表。数据更新节奏为月度或季度周期，文档结构多为结构化表格与合规条目组合，字段包含资源ID、权限配置项、合规状态、整改记录等，仅按业务场景记录原始配置与审计结果，无额外自定义统计数值。

## 这些特征在「向量模型与索引」这一环带来什么约束
这些特征在向量模型与索引环节带来明确约束。数据来源分散且多为结构化格式，需适配不同字段的向量提取逻辑，避免非结构化文本干扰合规匹配。月度或季度的更新频率决定索引无需高频增量同步，可采用定期全量更新策略，降低索引构建的资源消耗。结构化文档的固定字段要求向量模型需支持多列数据的联合嵌入，确保权限、资源ID等关键字段的语义关联被正确捕捉。同时，合规审计的严谨性要求索引召回结果需严格匹配字段定义，不可引入无关配置项的语义偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配合规检查表、资源清单的结构化字段长度，避免单块截断关键权限配置 |
| 重叠长度 | 100–200 字符 | 保留跨块的权限关联信息，防止合规条目被分割后语义断裂 |
| 相似度阈值 | 0.75–0.85 | 匹配合规审计的严谨性要求，过滤低相关性的资源配置项 |
| 单次搜索上限 | 前 10 条 | 覆盖月度资源清单的常规条目数量，避免召回冗余数据 |
| `maxToken` | 4096 token | 适配嵌入模型的输入长度限制，确保完整嵌入合规报告的核心段落 |

## 容易做错的三处
- 界面显示“检测到没有可用的索引模型”，且已配置模型并通过对话测试。原因是未在知识库设置中绑定对应向量模型到当前合规审计知识库，仅在全局配置中完成了模型设置。
- 点击启用Doubao-embedding-large索引模型，填写自定义请求地址和APIKey后测试报错。原因是未校验自定义地址的连通性，或APIKey权限未开放向量嵌入接口访问。
- 为表格数据开启多向量支持后无法召回结构化字段。原因是未正确配置表格列的嵌入映射，仅启用了整体表格的多向量开关，未指定需嵌入的权限、资源ID等关键字段。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库设置页面，打开向量模型配置模块，确认已选择适配合规审计场景的嵌入模型，且测试连接返回成功状态。
- 上传一份合规检查表样本触发索引构建，查看索引进度日志中无字段截断或嵌入失败的提示信息。
- 发起针对权限异常的查询，核对召回结果中包含的资源ID、合规状态字段与原始文档内容一致。
- 调整相似度阈值后，验证召回结果的数量变化符合预期，无大量无关配置项被召回。
