# 云资源合规审计的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
云资源合规审计场景的核心数据来自云审计日志、IAM权限配置、CMDB资源清单、安全基线扫描结果，日常产出的文档包括合规检查表、权限审计报告、资源盘点清单、整改跟踪表。文档分为结构化与半结构化两类：结构化文档如CSV格式的资源清单包含实例ID、区域、权限配置等字段，半结构化文档如PDF格式的合规检查表包含检查项、合规状态、整改建议等段落。数据更新频率为月或季度，以批量导出的形式提交至系统。

## 这些特征在「文档解析与分块」这一环带来什么约束
该场景的文档来源与更新节奏决定了解析分块需兼顾批量处理与结构化关联。首先，批量导出的云审计日志与资源清单体积较大，需适配大文件上传与解析的参数限制；其次，结构化文档包含多列关联字段，分块时需避免拆分跨字段的关联内容，否则会影响后续权限异常识别与整改证据核对；另外，半结构化的合规检查表与整改跟踪表需保留自然段落的上下文关联，同时场景内存在CSV、PDF、飞书文档等多种格式，需针对不同格式配置对应的解析规则。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配合规检查表、资源清单的单块字段覆盖范围，避免拆分跨关联字段的内容 |
| `chunkSplitter` | 按段落+语义分块 | 匹配整改跟踪表、权限审计报告的自然段落结构，保留上下文关联 |
| `customPdfParse` | 启用外部解析器 | 适配加密PDF或非标格式的合规文档，匹配实际使用的外部pdf-maker解析器的配置需求 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 容纳季度批量导出的云审计日志压缩包，避免上传错误 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大型资源清单的解析耗时，避免中途超时中断 |
| `chunkSettingMode` | 手动配置 | 针对CSV、PDF、飞书文档等不同文档类型调整分块规则，满足结构化与非结构化文档的解析需求 |

## 容易做错的三处
- 上传CSV格式的资源清单后仅提取前两列数据，原因是未配置CSV解析的列范围参数，默认逻辑仅加载前两列字段。
- Docker模式部署下上传合规审计文档时提示413错误，原因是未调整`UPLOAD_FILE_MAX_SIZE`参数，默认值不足以容纳批量导出的大型文件。
- 启用外部pdf-maker解析器后无法正常解析PDF文档，原因是未正确配置解析器对应的密钥参数；同时飞书多级目录文档解析后仅获取顶层内容，内嵌doc文档与图片无法正常检索，原因是未开启飞书文档的全目录递归解析开关，且未启用对应格式的解析适配规则。

## 怎么确认配好了
- 上传单份合规检查表PDF，检查解析后的分块是否覆盖完整检查项与整改建议，无内容截断或错位情况。
- 上传测试用CSV资源清单，确认所有配置的字段均被提取，无强制截断前两列的情况。
- 调整`PARSE_FILE_TIMEOUT_SECONDS`后上传大型云审计日志压缩包，确认解析过程无超时中断提示。
- 上传飞书多级目录文档，确认子目录内容与内嵌doc、图片均被正常解析并纳入检索范围。
