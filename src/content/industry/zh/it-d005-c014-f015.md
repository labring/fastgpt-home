# 云资源合规审计的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来源于云审计日志、IAM权限系统、CMDB资源清单、安全基线扫描结果。日常产出的文档包括合规检查表、权限审计报告、资源清单、整改跟踪表，数据更新频率为月或季度。文档字段包含资源唯一标识、权限配置项、合规校验状态、整改跟踪进度等，无统一固定单位，部分字段依赖对应云厂商的原生标识体系。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且格式异构，要求检索环节支持多源格式的适配与统一解析；更新频率低但单次数据体量较大，需平衡召回效率与全量覆盖范围；文档聚焦权限、配置、证据留存三类核心主题，检索需精准匹配合规相关关键词；整改跟踪表的时效性要求检索结果能关联最新的合规状态，避免调用过时数据；资源清单盘点环节的耗时特性，要求召回环节减少冗余计算，避免延长整体处理时长。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配云资源合规类文档的关键词密度与字段相关性，过滤无关的非合规类数据 |
| `limit` | 前 8–12 条 | 覆盖合规审计所需的权限、配置、整改三类核心文档，同时控制单次检索的上下文长度 |
| `searchMode` | `vector` | 优先匹配语义关联的合规检查表、权限审计报告，适配多源异构的合规文档结构 |
| `usingReRank` | 开启 | 对召回结果按合规相关性重排，优化权限异常识别类查询的结果排序 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户查询自动扩展合规相关的关键词，提升资源清单盘点类查询的召回精度 |
| `collectionIds` | 绑定专属合规文档集合 | 隔离合规审计数据与其他品类数据，避免检索结果混入非合规类文档 |

## 容易做错的三处
- 现象：上传合规文档至知识库时返回`upstream connect error or disconnect/reset before head`。原因：未绑定专属合规文档集合，导致检索请求触发跨集合的上游连接超时。
- 现象：通过OpenAPI知识库接口创建的QA拆分集合，检索速度慢且效果不佳。原因：未开启`datasetSearchUsingExtensionQuery`配置，手动处理查询扩展增加了额外开销。
- 现象：检索结果仅返回少量权限配置文档，无法覆盖整改跟踪表数据。原因：`limit`参数取值过低，未覆盖全量合规文档类型。

## 怎么确认配好了
- 执行一次资源清单盘点相关的查询，核对返回结果是否包含合规检查表、权限审计报告、整改跟踪表三类文档。
- 查看检索日志，确认`similarity`、`limit`等配置项的取值与预设配置一致。
- 上传一份新的合规文档，验证上传无`upstream connect error`类报错。
- 对比开启与关闭`usingReRank`后的检索结果排序，确认重排逻辑生效。
