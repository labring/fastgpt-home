# 产品使用数据分析的技术文档与接口问答：引用来源与溯源

本文适用于FastGPT v4.17.0及以上版本。

## 这个品类的数据长什么样
产品使用分析的数据通常来自埋点系统、数据仓库、CRM系统与工单系统，更新频率多为日度或周度。日常产出的文档包含使用分析报告、埋点方案、指标口径表与看板需求单，数据字段包含功能标识、操作时间、操作类型、关联客户ID与指标数值，单位涵盖次、分钟、条等基础统计单位，无统一的复杂格式要求。

## 这些特征在「引用来源与溯源」这一环带来什么约束
产品使用分析的数据来源分散且格式多样，引用溯源时需精准匹配对应数据源的字段与更新周期，避免引用滞后或不匹配的内容。不同文档的指标口径存在差异，溯源时需关联对应的口径说明文档，确保分析结果的一致性。数据更新频率固定为日度或周度，需在引用时标注对应周期，便于后续排查异常数据。多字段的组合引用需求，要求溯源配置支持多来源变量的同时加载，避免遗漏关键的功能操作或客户关联信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 引用最大token数 | 800–1200 token | 适配产品使用分析数据的长文本溯源需求，避免截断关键的指标口径说明 |
| 返回原始数据开关 | 开启 | 用于关联具体的埋点记录或数据仓库表名，满足溯源的精准性要求 |
| 溯源详情等级 | 完整 | 包含数据来源的系统、更新周期与字段信息，匹配分析报告的合规性展示需求 |
| 多来源引用上限 | 前5条 | 平衡溯源信息密度与回复可读性，适配多数据源的组合分析场景 |
| 引用格式配置 | 按「来源系统+更新周期+指标口径」格式 | 统一溯源展示样式，便于跨文档的指标核对与异常排查 |
| 溯源展示开关 | 开启 | 确保回复中包含必要的来源信息，满足客户成功运营的追溯需求 |

## 容易做错的三处
- 界面下拉菜单仅显示单个引用变量，无法配置多来源引用。原因是未调整多来源引用上限的配置项，默认限制了单次引用的数据源数量。
- 调用接口时返回`quote type error`报错。原因是引用的变量格式不符合产品使用分析数据的字段规则，未匹配埋点系统、数据仓库等数据源的标准字段命名。
- 回复中无法隐藏引用来源的完整内容。原因是未将溯源详情等级调整为极简模式，或未关闭溯源展示开关。

## 怎么确认配好了
- 发起测试请求，检查返回结果中是否包含配置的溯源字段，如来源系统、更新周期等信息。
- 查看下拉菜单的可选变量列表，确认是否包含产品使用分析数据的所有目标字段。
- 模拟不符合格式的变量输入，验证是否触发`quote type error`报错，确认格式校验规则生效。
- 关闭溯源展示开关后发起请求，确认回复中不再显示引用来源的详细内容。
