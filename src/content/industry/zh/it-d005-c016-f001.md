# 代码安全审计的技术文档与接口问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
本页面基于FastGPT v4.17.0版本编写。本品类的数据主要来源于源代码仓库、依赖清单、静态应用安全测试（SAST）工具与公开漏洞库。数据更新节奏为每项目版本迭代或单次审计任务完成后更新。日常产出的文档包含代码审计报告、漏洞证明材料、修复建议文档与复测记录。数据字段包含漏洞定位路径、危险函数引用标记、修复方案细则、复测结果标识等，按单个审计项目的版本维度拆分存储。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据按项目版本拆分存储，且更新频率随项目迭代变动，因此HTTP接口调用时需绑定项目与版本标识，避免跨项目数据混淆。日常产出的文档包含结构化的漏洞定位信息与非结构化的修复建议，接口需同时支持结构化字段查询与全文检索能力。数据来源包含本地SAST工具结果与外部漏洞库内容，接口需兼容跨源数据的聚合请求，同时需验证请求合法性以保护敏感审计数据。增量更新的需求也要求接口支持按时间戳或版本号拉取新增数据，减少无效传输开销。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `Authorization` | `Bearer {专属审计API密钥}` | 验证外部系统调用接口的身份，符合代码安全审计场景的敏感数据访问权限要求 |
| variables | `{"project_id": "目标项目ID", "audit_version": "当前版本号"}` | 绑定审计项目与版本参数，匹配数据按版本拆分的存储特征 |
| 单次请求超时时间 | `30–60 秒` | 代码审计数据包含较多文本与路径信息，预留足够的处理与传输时间，按实测标定合理区间 |
| `responseData` | `仅返回漏洞定位、修复建议、复测结果字段` | 过滤非必要的审计数据，降低HTTP接口传输负载，提升外部系统调用效率 |
| 重试次数 | `2 次` | 应对临时网络波动或SAST工具返回延迟的场景，避免单次请求失败中断审计流程 |

## 容易做错的三处
- 现象：HTTP请求组件接收的插件传入数值为空，返回`Request failed`报错。原因：未在variables配置中显式声明待传递的数值参数，导致参数未被正确绑定到请求体中。
- 现象：调用知识库接口创建文件集合时，传入`metadata`参数无对应说明，无法确认参数作用。原因：未查阅代码安全审计专属的接口文档，误将通用知识库参数套用到审计场景的接口中，未区分品类专属的参数规则。
- 现象：尝试通过接口下载审计报告附件时，仅能通过页面“查看原始内容”获取下载地址。原因：未配置接口的文件下载权限映射，未将审计文档的存储路径映射为可公开访问的接口地址。

## 怎么确认配好了
- 发起携带`Authorization`的测试请求，检查接口返回的身份验证状态，确认权限配置生效。
- 传入绑定了项目与版本的variables参数，验证返回结果仅包含指定审计项目的数据，确认参数绑定正确。
- 发起包含`responseData`过滤规则的请求，检查返回字段是否符合预设的过滤要求，确认数据裁剪配置生效。
- 模拟临时网络中断后重试请求，确认接口按配置的重试次数自动重试，确认重试机制正常运行。
