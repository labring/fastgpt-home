# 代码安全审计的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来源于源代码仓库、依赖清单、SAST工具输出与公开漏洞库，日常生成的业务文档包括代码审计报告、漏洞证明、修复建议与复测记录。数据更新节奏随项目版本迭代或单次审计任务完成触发，每个项目或版本对应一套独立的数据集。单条数据包含代码片段、漏洞描述、风险等级、修复方案等字段，无统一固定单位，随文档类型与审计内容灵活调整。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。首先，数据包含代码片段、漏洞描述、修复方案等混合格式内容，要求索引适配多类型文本的向量生成逻辑，避免单一模型无法覆盖不同字段的语义特征。其次，数据更新随项目版本或单次审计任务触发，需支持增量索引配置，无需每次全量重建数据集，降低计算资源占用。再者，单条数据的字段结构随审计内容灵活调整，需允许自定义向量生成的目标字段，避免无关内容参与向量计算。最后，安全审计的业务时效性要求，需保证索引查询的响应速度匹配任务推进节奏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `defaultToken` | 2048 token | 适配FastGPT v4.17.0版本的向量生成逻辑，覆盖代码片段与文本描述的混合输入长度 |
| 分块长度 | 800–1200 字符 | 匹配代码审计报告中单段漏洞描述与代码片段的长度，避免分块过碎或过长丢失语义 |
| 重叠长度 | 100–200 字符 | 保证跨分块的代码逻辑与漏洞上下文不被割裂，支持数据流追踪的语义关联 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的漏洞信息，避免误报或无关结果干扰安全审计判断 |
| 单次搜索上限 | 前 8 条 | 平衡查询效率与结果完整性，覆盖常见的漏洞关联与修复方案匹配需求 |
| 最大上下文 | 6000 字符 | 适配安全审计中多段关联数据的整合需求，支持完整攻击路径的语义分析 |

## 容易做错的三处
- 现象：导入源代码仓库数据时，未过滤的注释与空行内容被纳入向量索引。原因：未配置分块前的文本清洗规则，将非核心审计内容纳入了向量生成环节。
- 现象：增量更新索引时出现超时报错。原因：未启用增量索引模式，每次触发更新都执行全量索引重建，超出硬件性能上限。
- 现象：检索漏洞修复方案时返回大量低匹配度条目。原因：相似度阈值设置过低，未过滤语义关联较弱的无关数据。

## 怎么确认配好了
- 上传单份核心审计文档，查看向量生成环节的日志，确认仅预设的目标字段参与了向量计算。
- 触发一次增量索引更新，核对更新耗时与硬件性能匹配，确认未执行全量数据集重建。
- 输入包含漏洞描述的测试查询，查看返回结果的数量与相关性，调整相关配置至符合业务判断标准。
- 验证向量数据库的连接与读写状态，确认索引数据可正常被检索调用。
