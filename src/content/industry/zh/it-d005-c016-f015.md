# 代码安全审计的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自源代码仓库、依赖清单、静态应用安全测试（SAST）工具输出及公开漏洞库。日常产出的文档包含代码审计报告、漏洞证明材料、修复建议文档与复测记录。数据更新随项目版本迭代或项目推进节奏调整，通常每版本或每项目更新一次。单条数据包含漏洞编号、危险函数定位信息、数据流追踪路径、修复代码片段与复测结果等字段，无统一固定单位，随具体审计内容变化。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据来源分散且格式多样，包含原生代码片段、结构化审计报告与非结构化复测记录，要求检索环节兼顾代码语义匹配与文本语义理解能力。数据更新随项目版本迭代，需确保召回的知识库内容与当前审计项目的版本同步，避免使用过期的漏洞或修复数据。单条数据包含精准的定位信息与路径细节，要求召回结果需覆盖危险函数、数据流追踪等核心字段，支撑安全研发的快速定位与复核工作。同时，审计数据的准确性直接影响业务风险，检索环节需优先保障高置信度结果的召回优先级。

## 配置怎么定
以下配置适用于FastGPT v4.17.0及以上版本：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配代码安全相关的语义相似度，避免过低召回无关漏洞或过高遗漏有效审计记录 |
| `limit` | 前10条 | 覆盖单次审计任务的核心参考数据量，平衡检索效率与结果完整性 |
| `searchMode` | 混合检索 | 兼顾关键词匹配与语义检索，适配代码片段与审计报告的混合数据格式 |
| `usingReRank` | 开启 | 对初始召回结果进行重排序，优先返回与危险函数、漏洞定位相关的高相关条目 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索关键词，补充漏洞编号、危险函数名等专业术语，提升召回精准度 |
| `collectionIds` | 对应审计项目的专属知识库ID | 隔离不同项目的审计数据，避免跨项目检索干扰 |

## 容易做错的三处
- 现象：检索结果包含过期的漏洞修复记录或旧版本审计内容。原因：未按项目版本更新知识库同步频率，使用了未关联当前审计项目版本的数据集。
- 现象：通过localFile接口创建的知识库图片无法长期保存，到期后无法访问。原因：未配置知识库的永久存储策略，默认使用临时过期机制存储上传文件。
- 排查项：若调用接口返回鉴权失败（状态码401），可排查是否误将AI Proxy管理员Token作为应用API Key传入外部请求头，未使用正确的应用鉴权密钥。

## 怎么确认配好了
- 核对App/Admin服务端的环境变量，确认已配置`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或单模型服务地址）与非空`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致），且不得在工作流全局变量、应用API请求头或普通模型管理页面填写以替代服务部署配置。
- 发起测试检索请求，验证返回结果的条数与`limit`配置值匹配，且相似度得分处于`similarity`的设定区间内。
- 查看知识库同步日志，确认已按项目版本周期完成数据更新，无过期审计数据残留。
- 检查模型渠道配置页面，确认上游模型的渠道地址与供应商凭证已正确配置（上游模型的渠道地址与供应商凭证由模型渠道配置处理，不得与AI Proxy服务环境变量混为一谈），未与AI Proxy环境变量混淆。
