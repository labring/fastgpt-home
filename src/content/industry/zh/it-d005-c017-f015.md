# 代码评审与合并管理的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自Git仓库、CI流水线、静态扫描报告与缺陷库，更新频率为每日或每代码提交时。日常产出的文档包含合并请求、代码评审意见、提交记录与分支策略说明，字段包括变更文件列表、评审人标识、冲突标记、关联缺陷编号等。其中变更文件路径、评审状态为核心检索字段，数据结构以结构化文本为主，部分文档包含代码片段与图片格式的评审批注。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且更新频繁，要求知识库支持增量同步与私有数据源接入，避免召回滞后于最新代码变更。文档包含代码片段与结构化字段，要求检索需兼顾语义匹配与字段精准关联，例如通过变更文件路径匹配关联评审历史。合并请求的评审上下文通常较短，要求检索结果需控制在合理范围内，避免超出大模型的上下文处理窗口。分支策略说明等文档的结构相对固定，需保留完整的上下文块以确保检索语义连贯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 匹配代码变更与评审意见的语义相似度，过滤低相关结果，适配代码评审场景的语义匹配精度 |
| `limit` | 前10条 | 适配单次评审的上下文长度，避免超出大模型的上下文窗口限制 |
| `searchMode` | 语义检索 | 匹配代码变更的业务语义，覆盖跨文件的变更关联场景 |
| `usingReRank` | 开启 | 对初始召回结果重排，优先关联当前合并请求的变更文件，提升评审相关结果的优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索词，覆盖分支策略、CI配置等关联文档，解决单一检索词覆盖不全的问题 |
| `collectionIds` | 绑定Git仓库关联的知识库集合 | 限定检索范围，排除无关业务文档，确保召回结果仅与当前研发项目相关 |

## 容易做错的三处
- 现象：检索结果中混入大量与当前合并请求无关的通用业务文档。原因：未绑定`collectionIds`限定检索范围，导致检索覆盖了非当前项目的知识库数据。
- 现象：无法检索到PDF格式的代码评审报告中的图片文本内容。原因：未启用文档图片文本识别配置，仅支持纯文本格式的文档解析，对应代码评审场景下的图片批注无法被召回。
- 现象：多次重复检索相同的合并请求问题。原因：未开启`datasetSearchUsingExtensionQuery`，未对历史评审问题进行语义扩展，导致无法覆盖用户的潜在检索意图，重复触发相似检索。

## 怎么确认配好了
- 查看FastGPT v4.17.0版本的知识库同步日志，确认最新的代码提交记录与合并请求已被增量同步至目标知识库集合。
- 输入当前合并请求的变更文件路径作为检索词，验证是否能召回关联的历史评审意见与冲突解决记录。
- 测试开启`usingReRank`后，检索结果的排序是否优先展示与当前变更直接相关的内容。
- 检查`collectionIds`配置，确认仅绑定了当前Git仓库对应的知识库集合，无跨项目数据混入。
