# 众包标注人员管理的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自众包平台、标注质量数据、培训考试记录与财务系统。日常文档包含人员准入规则、培训材料、绩效表与结算清单。数据更新频率通常为日度或月度，字段包含人员唯一标识、准入审核状态、培训考核得分、质量评级、结算金额等，无统一强制格式，随项目需求调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据特征对引用溯源带来多重约束。首先，数据来源分散，需关联众包平台的人员信息、标注质量的质检结果、培训考核记录与财务结算数据，溯源时需匹配多系统的唯一标识字段；其次，更新频率不均，日度更新的绩效数据需实时关联，月度更新的结算数据需定期同步，未配置跨源同步规则易出现引用数据滞后；另外，文档结构不统一，不同项目的人员信息字段存在差异，需配置字段映射规则才能准确关联引用来源；最后，结算类数据涉及敏感字段，溯源时需确保权限校验与数据一致性，避免引用错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 适配该品类人员文档、绩效表的常规长度，保留足够上下文用于溯源 |
| `responseData` | `开启` | 需返回引用来源的具体字段与数据位置，满足质检与结算核对需求 |
| `detail` | `完整` | 需展示引用数据的完整内容，便于核对人员绩效等级或结算金额 |
| 跨源字段映射 | 按项目实际字段匹配 | 适配该品类多系统数据的字段差异，确保多源数据关联准确 |
| 数据更新同步周期 | 按数据来源调整，日度数据设为1小时同步，月度数据设为24小时 | 匹配该品类数据的更新频率，避免引用数据滞后，适配FastGPT v4.17.0版本的数据源管理逻辑 |
| 召回条数上限 | 前5条 | 控制溯源返回的数据源数量，避免信息过载影响核对效率 |

## 容易做错的三处
- 界面显示引用标记，但返回内容与人员管理知识库的文档完全无关，原因是未配置正确的数据源关联规则，导致召回了无关的通用数据。
- 仅文本类的人员文档被成功引用，绩效、结算类数据未出现在溯源结果中，原因是未为非文本数据源配置对应的嵌入与召回规则。
- 调用API触发工作流时，无法引用指定的人员管理知识库，返回结果未包含预期的溯源数据，原因是未将知识库ID正确传入工作流的上下文参数中。

## 怎么确认配好了
- 触发一次人员绩效相关的问答，检查返回结果中是否包含配置的引用来源字段，确认关联规则生效。
- 查看引用溯源面板，确认所有配置的数据源类型均被正确召回，无遗漏。
- 对比返回的引用数据与原始知识库文档，确认内容匹配度符合预期。
- 调用API接口，检查返回的`responseData`字段是否包含完整的引用来源信息。
