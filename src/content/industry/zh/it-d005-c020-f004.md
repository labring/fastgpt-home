# 供应商与设备到货管理的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自ERP系统、供应商发货单、物流追踪信息及设备厂商后台。日常流转的文档包含采购订单、到货验收单、序列号清单与发票资料，字段覆盖采购单号、设备型号、序列号、到货日期、验收结论等。数据更新以单批次采购为最小周期，单项目下的到货数据每周同步更新一次，单文件体量通常符合业务常规范围。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据多源且字段差异明显，结构化字段（如采购单号、序列号）与非结构化文本（如验收说明）混合，要求索引配置适配混合数据格式。数据更新以单批次采购为最小周期，增量索引的触发逻辑需匹配到货节点，避免全量重索引占用过多系统资源。单批次文件数量较多但单文件体量可控，需限制单次索引的文件上限，防止处理超时。同时，检索需聚焦设备型号、序列号等核心业务字段，避免无关内容干扰匹配结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配采购订单、到货验收单的常规文本长度，避免单块内容过于分散 |
| 重叠长度 | 100–200 字符 | 保留相邻块的关键信息，防止序列号、设备型号等核心字段被拆分 |
| 相似度阈值 | 0.75–0.85 | 匹配设备型号、序列号的精准匹配需求，适配bge-large-zh-1.5等主流中文嵌入模型的向量相似度分布，降低错配概率 |
| `maxToken` | 8192 token | 适配长文档的上下文整合，满足发票资料、物流说明的文本长度 |
| 单次搜索上限 | 前 8 条 | 控制返回结果的数量，避免检索结果过多影响验收核对效率 |
| `defaultToken` | 256 token | 配置单段短文本的默认嵌入长度，适配序列号清单的短字段内容 |

## 容易做错的三处
- 现象：索引任务持续处于“正在索引”状态，无进度更新且无报错提示。原因：未针对单批次索引的文件数量设置合理上限，多源混合数据的分块处理耗时过长导致阻塞。
- 现象：检索结果同时返回两个知识库的内容，未按预设的知识库优先级优先匹配指定知识库。原因：未在检索配置中开启知识库优先级绑定，或未将优先级规则关联到设备型号、采购单号等核心业务字段。
- 现象：执行知识库索引切换时返回超时报错，提示处理时长超出阈值。原因：单次索引的文件总长度超出配置上限，或`maxToken`取值过大导致嵌入处理耗时过长，触发FastGPT的超时限制。

## 怎么确认配好了
- 上传单份采购订单文档，在FastGPT v4.17.0的索引管理页面查看分块结果，确认分块长度与重叠长度符合预设配置。
- 发起包含设备型号关键词的检索请求，核对返回结果的相似度分值是否落在预设的合理区间内。
- 配置两个测试知识库，上传对应业务文档后发起检索，验证检索结果是否优先匹配指定的高优先级知识库。
- 批量上传3-5份不同类型的业务文档，执行索引操作，确认处理流程未出现无进度阻塞的情况。
