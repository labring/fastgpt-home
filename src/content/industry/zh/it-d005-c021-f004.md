# 供应链安全与开源依赖治理的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自包管理器、代码仓库、漏洞库与许可证数据库，日常产出SBOM清单、依赖风险报告、许可证清单、修复工单四类文档。文档多为半结构化格式，包含组件名称、版本号、许可证类型、CVE编号、风险等级等固定字段，更新频率为每日或每软件版本一次，数据结构相对规整但字段关联性强，需保留组件与对应风险、许可证的绑定关系。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据字段关联性强，需保留组件与对应风险、许可证的绑定关系，因此分块时不能过度拆分单个组件的关联信息；高更新频率要求索引支持增量更新，避免全量重建带来的性能损耗；文档多为短文本组合，向量模型需适配组件名、CVE编号等短字段的编码精度；同时数据关联高危漏洞与合规风险，索引召回的准确率需严格匹配业务需求，避免误召回低风险依赖或遗漏高危项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配SBOM、风险报告的字段密度，避免拆分单个组件的关联信息 |
| 重叠长度 | 50–100 字符 | 保留跨分块的组件版本与风险关联信息 |
| `maxToken` | 8192 | 适配开源组件名称、CVE编号等短文本的向量编码上限 |
| 相似度阈值 | 0.75–0.85 | 区分高危漏洞与低风险依赖的匹配精度 |
| 单次召回上限 | 前20条 | 平衡漏洞匹配的召回率与查询耗时 |
| `defaultToken` | 按实测标定 | 适配本地或私有部署的向量模型上下文需求 |

## 容易做错的三处
- 现象：使用PG数据库、docker部署时索引无法建立，宿主机为8c16G无GPU虚拟机，文件体积不大。原因：未调整分块长度与召回上限，导致向量计算占用内存超出分配阈值。
- 现象：接入oneapi embedding模型时持续报错。原因：未单独配置索引模型，直接复用了oneapi的通用接口，未指定专用向量模型端点。
- 现象：导入飞书文件夹下的excel文件与多维文档后，未生成有效索引结果。原因：未开启对应文件格式的解析适配，且未配置字段映射规则，无法提取供应链相关的组件信息。

## 怎么确认配好了
- 上传一份测试用SBOM清单，在FastGPT v4.17.0的管理后台查看向量索引生成状态，确认无字段丢失提示
- 发起组件漏洞匹配查询，核对召回结果的相似度值是否落在配置的阈值区间内
- 检查索引更新日志，确认按日或按版本的增量更新任务正常执行
- 验证私有向量模型接入，查看向量编码返回结果无格式报错
