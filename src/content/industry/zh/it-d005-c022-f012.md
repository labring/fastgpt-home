# 信创替代适配的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
该品类的数据主要来自企业现有系统清单、国产软硬件目录、测试环境产出的文档及厂商公开资料，日常产出的文档包括适配清单、兼容性测试报告、迁移方案、问题台账。数据更新节奏以单项目或季度为周期，单项目内的文档会随适配进度动态调整。文档结构包含结构化表格（如适配清单的软硬件型号、兼容性等级列）、长文本段落（如迁移步骤说明）、枚举字段（如兼容性状态），无统一固定的单位格式，部分字段为纯字符串类型。

## 这些特征在「文档解析与分块」这一环带来什么约束
信创替代适配的文档类型多样且结构不统一，要求解析分块环节不能破坏原有结构化字段的完整性，避免拆分适配清单中的软硬件型号、版本号等关键信息。数据来源分散导致导入格式存在差异，需兼容PDF、Word、Excel等多种文档格式。单项目数据量较大，解析环节需支持大文件处理，避免因文件过大导致解析中断。此外，国产软硬件的命名规则存在特定格式，分块时需保留这些命名的完整性，防止拆分导致兼容性验证失效。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本的规则制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配信创文档中长文本字段的完整保留，避免拆分迁移方案中的关键步骤 |
| `chunkSplitter` | 按段落+标题锚点 | 适配适配清单、兼容性测试报告的结构化格式，防止拆分表格行或标题内容 |
| `customPdfParse` | 开启 | 适配国产软硬件PDF文档的特殊排版，解决原生解析报错问题 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容单项目批量导入的大型兼容性测试报告 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大型文档的解析耗时，避免超时中断任务 |
| `chunkSettingMode` | 手动配置 | 针对不同信创项目的文档结构调整分块规则，适配特定场景的文档格式 |

## 容易做错的三处
- 现象：调用创建文件集合的API时未指定`customPdfParse`参数，PDF解析失败。原因：未按信创场景开启自定义PDF解析适配国产文档的特殊排版。
- 现象：FastGPT节点输出的变量存入飞书多维表格时HTTP调用失败，返回状态码400。原因：未正确拼接飞书API的请求头与参数格式，未匹配信创场景下的变量字段命名规则。
- 现象：上传多个信创文档后，解析结果无法区分来源文件。原因：未开启分块时保留文档元数据的配置，导致解析后丢失文件标识字段。

## 怎么确认配好了
- 上传单份信创适配PDF文档，查看解析后的分块是否保留了软硬件型号、版本号等关键字段的完整性
- 调用创建文件集合的API，携带`customPdfParse`参数，验证返回状态码为200且无解析报错日志
- 上传多份不同格式的信创文档，检查解析结果中是否包含对应的文件元数据字段用于区分来源
- 等待解析任务完成，确认耗时未超过`PARSE_FILE_TIMEOUT_SECONDS`设定的时长，无超时中断提示
