# 信息化预算与项目组合管理的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自财务系统、项目管理系统、合同台账及业务部门需求。日常产出的文档包括年度预算表、项目立项书、项目组合看板与投资复盘报告，文档包含预算金额、项目优先级、立项周期、投资回报率等字段，单位涉及万元、自然月、百分比等。数据更新节奏多为月度、季度或年度，部分临时项目需求文档的更新频率更高。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量建模与索引环节带来多重约束。首先，数据来源分散于多个异构系统，不同系统导出的文档格式差异较大，需适配表格、段落、看板等多种结构进行分块。其次，更新频率不固定，部分临时项目文档需高频同步索引，否则会导致查询结果滞后。此外，文档混合结构化数值与非结构化文本，需针对性设置字段权重以优化向量匹配精度。单份文档体量差异显著，年度预算表可能包含多页表格，而项目立项书多为短段落文本，索引分块规则需兼顾不同文档的长度特征。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的向量模型与索引功能规则。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 分块长度 | 800–1200 字符 | 适配该品类混合的表格与文本类文档，避免分块过碎或过长 |
| 重叠长度 | 100–200 字符 | 减少分块断裂导致的语义丢失，适配预算表与复盘报告的长文本结构 |
| `defaultToken` | 4096 token | 适配主流大模型的基础上下文窗口，覆盖多数单份项目文档的核心内容 |
| `maxToken` | 8192 token | 覆盖体量较大的年度预算表与完整投资复盘报告的内容边界 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关的非项目类数据，精准匹配预算与项目优先级查询需求 |
| 单次搜索上限 | 前 10 条 | 控制返回结果的信息量，避免过多冗余数据干扰预算决策分析 |

## 容易做错的三处
- 现象：调用One API接入大模型时，索引创建失败并返回`invalid api key`报错。原因：未将One API的自定义接口地址配置到向量模型调用路径中，仅填写了默认OpenAI官方地址。
- 现象：搜索项目优先级相关问题时，返回大量无关的供应商报价文档，结果条数偏差较大。原因：未针对该品类的预算与项目数据调整相似度阈值，直接使用了通用知识库的默认配置。
- 现象：上传PDF格式的项目立项书后，表格内的预算金额字段未被正确提取，向量索引缺失结构化数值信息。原因：未开启针对结构化文档的分块优化，仅使用通用文本分块规则处理混合格式文档。

## 怎么确认配好了
- 上传一份标准的年度预算表，查看分块后的文本片段是否完整保留预算金额与项目名称字段。
- 发起预算优先级相关的接口查询，检查返回结果的条数是否匹配单次搜索上限的配置。
- 查看向量索引的更新日志，确认月度更新的财务系统数据是否按设定周期完成同步。
- 测试Word、PDF格式的项目文档上传，确认索引创建状态均显示成功。
