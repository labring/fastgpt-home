# 信息化预算与项目组合管理的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据主要来自财务系统、项目管理系统、合同台账及业务部门需求。日常产出的文档包括年度预算表、项目立项书、项目组合看板、投资复盘报告。数据更新频率多为月、季或年度，文档字段通常包含项目编号、预算分配额度、立项审批节点、组合优先级、复盘周期等，对应单位涵盖人民币元、季度、年度等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且更新周期跨度大，需溯源的文档格式差异明显，要求引用溯源需适配多系统导出的结构化与非结构化数据。预算与项目数据的准确性直接影响决策，溯源环节需明确标注每条引用内容的原始系统、更新时间及文档版本，防止出现预算错配或决策失真。项目组合看板与复盘报告的关联数据较多，需支持跨文档关联溯源，避免单一文档引用导致的信息片面。同时，月度/季度更新的数据需在溯源中体现最新版本，防止引用过期信息引发决策偏差。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 9000–11000 token | 适配本品类长文档的字段密度，保留完整的预算金额、项目编号等关键信息 |
| `responseData` | 启用结构化溯源模式 | 提取原始文档的结构化字段，便于快速核对数据来源与更新时间 |
| `detail` | 开启全片段溯源 | 展示引用内容的原始文档位置、版本信息，支持回溯原始合同或预算表 |
| 单次召回上限 | 前8条 | 覆盖多系统导入的项目与预算数据，避免遗漏跨部门的关联信息 |
| 版本锁定开关 | 按更新周期开启 | 匹配本品类月/季/年的更新频率，确保引用的是最新版本的预算与项目数据 |

## 容易做错的三处
- 现象：调用知识库时仅返回1条引用结果，无法召回多文档内容。原因：单次召回上限配置过低，未覆盖多系统导入的预算与项目数据。
- 现象：知识库选择框为空，需手动选择后才能使用。原因：未配置默认知识库绑定，未将财务系统、项目管理系统的文档批量关联至目标应用。
- 现象：引用内容无法下载溯源文件。原因：未开启`responseData`的完整路径配置，导致溯源链接无法指向原始文档存储位置。

## 怎么确认配好了
- 发起包含预算字段或项目编号的测试提问，检查返回结果的引用条数是否符合配置的单次召回上限。
- 查看每条引用的溯源详情，确认标注了原始系统、更新时间及文档版本信息。
- 尝试点击溯源链接或下载溯源文件，确认可正常访问对应原始文档。
- 测试调用过期的历史预算数据，确认版本锁定开关生效后仅召回当前周期的最新数据。
