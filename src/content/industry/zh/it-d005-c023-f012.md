# 信息化预算与项目组合管理的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
该品类的典型数据来自CIO办公室、PMO及财务BP的日常工作产出，包含年度预算表、项目立项书、项目组合看板、投资复盘报告等文档。数据来源多为财务系统、项目管理系统、合同台账及业务部门需求，更新频率多为月、季或年。文档结构包含结构化表格、层级化项目说明及数值型字段，常见字段包括预算金额、项目编号、优先级标识，单位涉及万元、项目周期天数等。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的数据特征对文档解析与分块带来多重约束。多来源的文档格式差异较大，既有结构化表格类的预算报表，也有纯文本类的项目复盘报告，需适配不同格式的解析规则。单次处理的文档可能包含大量关联数据，分块时需避免拆分跨字段的关联内容，如预算数值与对应项目名称，否则会影响后续检索的准确性。更新频率较低的特性意味着无需高频解析，但需支持大型文档的单次处理。同时，文档中的优先级、预算金额等核心字段需被完整保留在分块中，以保障后续问答的业务相关性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 该品类文档包含结构化表格与大段项目说明，800–1200字符可保留单张预算表或完整项目段落的关联性 |
| `chunkSplitter` | 按段落+标题 | 该品类文档有明确的项目章节与预算分类标题，按标题拆分可保留文档的逻辑结构 |
| `customPdfParse` | 开启 | 该品类的PDF文档多为财务系统导出的带表格报表，开启后可保留表格单元格的关联关系 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 年度预算表等大型文档解析耗时较长，600秒可覆盖大部分文件的解析时长 |
| `chunkSettingMode` | 自定义模式 | 该品类文档格式差异较大，自定义模式可灵活调整分块规则适配不同类型的预算与项目文档 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 该品类的年度复盘报告等文档可能包含多年数据，较大的文件尺寸可满足单次上传需求 |

## 容易做错的三处
- 现象：知识库搜索测试无法命中目标预算数据，返回结果为空或不相关。原因：分块时拆分了关联的预算数值与对应项目名称，导致检索时无法匹配完整的业务逻辑。
- 现象：上传多个项目文档后，解析结果无法区分不同文件的内容。原因：未在分块配置中绑定文件元数据，导致分块结果未标记所属文档的标识信息。
- 现象：解析后的分块内容包含大量无效的格式标记，无法被正确检索。原因：未开启`customPdfParse`配置，导致PDF解析时保留了冗余的表格边框与排版标记。

## 怎么确认配好了
- 上传单份年度预算表文档，在FastGPT v4.17.0的知识库解析预览中，确认每个分块包含完整的项目段落或单张预算表格。
- 上传多份不同类型的文档，查看解析结果列表，确认每个分块都标记了所属文件的名称或ID。
- 检索包含特定预算数值的关键词，确认搜索结果命中了对应的分块内容。
- 测试大型文档的上传与解析，确认解析过程未出现超时错误。
