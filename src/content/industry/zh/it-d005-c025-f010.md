# 值班排班与交接的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据核心来自排班系统、故障工单、监控告警与组织通讯录。日常文档包含标准化值班表、跨班次交接记录、升级联系人清单与值班日报，字段涵盖值班时段、未结事项、应急联系人、告警响应路径等。数据更新频率以日或周为单位，随班次轮换、故障变更或人员调整，实现实时或定期的信息刷新。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的数据多源且更新节奏灵活，要求引用溯源时需明确标注数据源类型，避免将故障工单的告警信息与排班表的值班安排混淆。固定的文档结构要求检索时匹配对应文档类型，确保引用的值班时段、交接事项等字段准确对应。高频或定期更新的数据需要同步刷新知识库的数据源版本，防止引用过期的排班或联系人信息，否则可能引发无人响应、交接遗漏等业务问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | 本品类核心文档（值班表、交接记录）单份长度适中，该区间可覆盖完整班次的排班与交接内容，避免截断关键信息 |
| `responseData` | 返回数据源类型、文档ID、更新时间 | 本品类数据多源且需溯源，明确返回这些字段可快速定位引用内容的来源与时效性 |
| `detail` | 开启完整字段展示 | 本品类文档包含值班时段、未结事项等关键字段，完整展示可确保交接与排班信息的准确性 |
| 相似度阈值 | `0.6–0.7` | 本品类检索内容多为结构化排班数据，该区间可过滤低相关的非排班类文档，提升匹配精准度 |
| 单次搜索上限 | `前3条` | 本品类核心信息集中在单份值班表或交接记录中，过多结果会增加模型筛选成本，且易引入无关内容 |
| 最大上下文 | `1500–2000 token` | 需同时加载排班表、交接记录与升级联系人信息，该区间可覆盖完整的关联信息，确保模型回答的完整性 |

## 容易做错的三处
- 现象：检索时无法匹配到目标值班表，返回无关的故障工单内容。原因：未配置文档类型过滤，未设置合理的相似度阈值，导致非排班类数据被优先召回。
- 现象：引用的值班信息显示过期，无法匹配当前班次的排班安排。原因：未定期刷新知识库的数据源版本，引用了周前更新的旧排班表。
- 现象：配置`quoteMaxToken`后，返回的引用内容被截断，丢失未结交接事项。原因：设置的token区间过小，未覆盖单份交接记录的完整长度。

## 怎么确认配好了
- 发起针对当前班次排班的检索，核对返回结果的数据源类型是否为值班表或交接记录。
- 查看引用内容的更新时间，确认与当前系统的排班更新时间一致。
- 调整配置项的取值，验证返回的引用内容是否完整覆盖所需的值班时段、交接事项等字段。
- 测试多源数据检索，确认不同类型的文档（如排班表、告警记录）被正确区分，不会混同引用。
