# 值班排班与交接的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来自排班系统、故障工单、监控告警与组织通讯录，更新频率为日度或周度。日常文档包含值班表、交接记录、升级联系人清单、值班日报，字段包含值班时段、责任人姓名与联系方式、未结故障事项、升级链路联系人等，每份文档关联具体值班周期与对应运维组信息，无额外冗余统计字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类数据来源分散且更新频率较高，要求知识库检索需支持多源数据的字段对齐匹配，避免召回跨周期或跨组的无效信息。不同类型文档（值班表、交接记录）的结构差异，要求召回时需按文档类型筛选结果，确保返回的值班时段、联系人信息与当前查询场景匹配。未结事项与升级链路的时效性强，需限制召回数据的更新时间范围，防止使用过期的交接内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配值班时段、联系人等精准字段，避免召回无关的历史排班记录 |
| `limit` | 前6条 | 覆盖单轮值班交接的核心信息，避免结果过多干扰判断 |
| `searchMode` | hybrid | 结合关键词与语义匹配，适配排班系统导出的结构化数据与自由格式的交接记录 |
| `usingReRank` | 开启 | 对召回结果按与查询的相关性重排序，确保未结事项、升级链路等关键信息排在前列 |
| `datasetSearchUsingExtensionQuery` | 开启 | 优化值班相关的口语化查询，比如将「今晚谁值班」转化为结构化检索词 |
| `collectionIds` | 按运维组绑定专属集合 | 隔离不同运维组的排班数据，避免跨组信息泄露或误召回 |

## 容易做错的三处
- 升级FastGPT v4.17.0后，调用知识库问答返回404错误。原因：未更新数据集绑定的`collectionIds`参数，旧版本的集合ID在升级后失效。
- 检索值班信息时返回空结果。原因：未开启`datasetSearchUsingExtensionQuery`，无法将口语化查询如「明天值班人员」转化为结构化检索词。
- 召回结果包含过期的历史值班记录。原因：未配置数据更新时间过滤规则，导致召回超过7天的旧排班数据。

## 怎么确认配好了
- 提交包含具体值班时段、责任人姓名的查询，核对返回结果是否包含对应文档的核心字段。
- 查看检索日志，确认`searchMode`、`usingReRank`等参数按配置生效。
- 测试提交过期时段的查询，确认超过更新周期的文档未被召回。
- 跨运维组提交相同查询，确认仅返回本运维组的排班数据。
