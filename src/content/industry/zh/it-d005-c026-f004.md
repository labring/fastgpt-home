# 关卡内容制作的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
通常，关卡内容制作的数据来源于关卡编辑器、美术资源库、玩家测试数据与缺陷系统。日常产出的文档包括关卡设计稿、资源需求表、测试反馈单与版本提交记录，字段一般包含关卡ID、资源路径、测试时间、缺陷等级与提交人信息。数据更新频率多为每周或每版本迭代一次，单次更新的内容体量随关卡规模变化，部分大型关卡的单份设计稿可超过万字。

## 这些特征在「向量模型与索引」这一环带来什么约束
关卡内容制作的数据来源分散且更新节奏固定，要求索引系统支持增量更新以适配每周/版本级别的迭代。不同类型文档的结构差异较大，分块策略需要适配从短文本测试反馈单到长文本关卡设计稿的跨度。数据字段包含大量游戏专属的路径、ID与测试标签，向量模型需要能准确识别这些领域术语的语义关联。同时，关卡内容的错误会直接影响玩家体验，因此索引召回的准确率需要优先保障，避免出现低相关结果干扰策划调试。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配关卡设计稿的单页内容长度，避免单块内容过长丢失语义连贯性 |
| 重叠长度 | 100–200 字符 | 覆盖关卡路径、资源摆放等跨块的连续内容，防止语义断裂影响检索效果 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 过滤测试反馈单、缺陷记录中的低相关内容，精准匹配关卡相关的核心信息 |
| `maxToken` | 4096 token | 适配通用embedding模型的输入上限，避免长文本关卡设计稿被截断丢失关键规则 |
| 单次搜索上限 | 前10条 | 控制返回的关卡相关资源数量，避免上下文过载影响调试效率 |
| `defaultToken` | 1024 token | 设定默认的单段索引文本长度，统一基础配置标准，减少新手用户的配置复杂度 |

## 容易做错的三处
- 现象：替换embedding模型后，检索相似度数值异常偏高。原因：未调整相似度阈值的匹配逻辑，沿用原模型的分数计算基准，导致新模型的得分区间与原配置不匹配。
- 现象：知识库上传关卡数据后无索引进度显示，或最终显示索引失败。原因：未正确配置向量数据库的连接参数，或关卡数据中的资源路径字段包含非法字符导致解析失败。
- 现象：源码部署后无法生成有效索引。原因：未同时启动MongoDB、向量数据库与sandbox服务，导致索引存储与执行环境无法正常联动。

## 怎么确认配好了
- 上传一份典型的关卡设计稿，检查FastGPT v4.17.0的索引进度是否在1分钟内完成，无报错日志输出。
- 输入与关卡资源相关的查询词，查看返回结果是否包含匹配的资源路径、测试反馈单等关联内容。
- 调整相似度阈值，验证低相关的测试记录是否被正确过滤，高相关的关卡设计内容是否保留。
- 登录向量数据库管理界面，确认存在对应关卡数据的向量条目，且条目数量与上传的文档数量一致。
