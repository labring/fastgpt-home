# 内容推荐运营的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
内容推荐运营的日常数据主要来自内容标签、用户行为日志、实验平台及推荐后台。日常产出的文档包括推荐策略记录、内容池清单、实验报告与运营复盘，字段包含策略编号、内容标签、曝光量、实验指标等。数据更新频率通常为日度或周度，内容池清单随新内容上线实时更新，实验报告则在单次实验结束后生成。与专题活动运营的一次性活动文档不同，本品类的文档均围绕常态化分发的内容池与策略配置展开。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且包含实时行为日志与静态策略文档，要求检索系统支持多源数据的混合召回。文档类型覆盖策略、清单、报告三类，不同文档的字段差异要求检索配置需针对不同文档类型设置专属的字段匹配规则。日度/周度的更新频率要求系统支持增量召回，避免全量检索带来的性能损耗。内容池筛选与实验指标解读为最耗时环节，要求检索结果需优先返回高匹配度的内容池条目与实验数据，减少人工筛选成本。出错后会导致低质内容放大或核心指标下滑，要求检索结果需具备可追溯的匹配依据。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配内容推荐运营的策略与实验报告的文本长度，过滤低相关结果 |
| `limit` | 前10条 | 覆盖内容池筛选与指标解读的常规查看需求，避免结果过多增加人工筛选成本 |
| `usingReRank` | 开启 | 针对多源数据的混合召回结果进行重排序，优先返回与内容池、策略相关的高匹配条目 |
| `datasetSearchUsingExtensionQuery` | 开启 | 对指代性问题进行扩展，解决“该策略”“该内容池”这类模糊查询的匹配问题 |
| `searchMode` | 混合检索 | 同时匹配内容标签与文本语义，适配内容池清单与策略记录的不同检索需求 |
| `collectionIds` | 绑定推荐运营专属数据集ID | 限定检索范围仅覆盖运营相关的内容池、策略文档，避免无关数据干扰 |

## 容易做错的三处
- 检索结果中Excel导入的内容被合并为单一条目：现象是上传Excel格式的内容池清单后，同单元格内的多行内容未被正确拆分，全部出现在一个检索结果中。原因是未配置自定义分隔符，系统默认按换行符拆分单元格内容，未适配Excel的多行文本格式。
- 调用知识库关联接口时返回空结果：现象是通过API请求关联知识库时，接口返回无匹配数据。原因是未正确传入`collectionIds`参数，或传入的ID未指向推荐运营专属的数据集。
- 检索结果未覆盖实验报告的指标字段：现象是搜索实验指标相关问题时，返回的结果未包含曝光量、转化率等核心指标字段。原因是未针对实验报告文档配置专属的字段提取规则，仅匹配了文本语义未提取指定字段。

## 怎么确认配好了
- 上传测试用Excel文件，配置自定义分隔符为单元格换行符，检查拆分结果是否为单条内容对应一个检索条目。
- 调用知识库关联接口，传入正确的`collectionIds`参数，检查返回结果是否包含绑定数据集内的文档。
- 输入指代性问题如“上周的推荐策略”，检查检索结果是否自动扩展为具体的策略编号与内容。
- 开启`usingReRank`后，搜索“高曝光内容池”，检查高匹配度的内容池条目是否排在结果前列。
