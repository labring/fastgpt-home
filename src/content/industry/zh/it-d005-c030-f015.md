# 内部网络与WiFi运维的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
内部网络与WiFi运维的日常数据主要来自交换机控制台、无线控制器、监控系统及用户报障渠道，更新频率为每日或每次网络变更后。常见文档包含网络拓扑图、配置变更单、故障记录、无线覆盖巡检表，数据字段包含端口号、VLAN ID、SSID名称、巡检时间、故障点位等，部分文档为结构化表格格式，部分为半结构化的故障描述文本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据来源分散且更新频率较高，要求知识库检索需兼顾结构化字段匹配与半文本内容的语义召回，避免遗漏关键的变更记录与故障点位信息。运维场景的问题多为实时故障排查，需优先召回近7天内的最新文档，同时需严格限定结果范围，防止无关的其他业务配置内容干扰排查。此外，数据包含端口、VLAN等专业运维字段，检索需支持精准字段匹配，避免泛化召回导致的无效信息过多。

## 配置怎么定
本配置适用于FastGPT v4.17.0及以上版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 内部网络运维的故障排查需精准匹配核心字段，避免无关的历史配置条目干扰检索结果 |
| `limit` | `前8–12条` | 运维人员需快速浏览核心的故障记录与变更单，过多条目会增加筛选成本 |
| `searchMode` | 向量+关键词混合检索 | 数据包含结构化的端口/VLAN字段和半结构化的故障描述，混合检索兼顾精准度与召回完整性 |
| `usingReRank` | 开启 | 需对召回结果按更新时间与故障紧急度排序，优先展示近7天内的最新变更单与当前故障相关记录 |
| `datasetSearchUsingExtensionQuery` | 开启 | 运维人员提问常省略专业术语，扩展查询可覆盖更多相关文档，例如用“wifi断了”匹配“SSID覆盖异常” |
| `collectionIds` | 绑定运维专属知识库集合 | 隔离网络运维数据与其他业务数据，防止召回无关内容影响排查效率 |

## 容易做错的三处
- 现象：上传WPS保存的CSV格式巡检表后，检索结果出现乱码字段。原因：未将CSV文件编码转为UTF-8格式，导致知识库解析时出现字符识别错误。
- 现象：检索时返回的结果条数与设置的`limit`不符，例如设置前10条却返回20条。原因：未正确配置混合检索的权重规则，导致向量检索与关键词检索的结果出现重复叠加。
- 现象：发起检索后返回504超时报错。排查项：检查App/Admin服务端是否已配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，检查AI Proxy服务连通性，检查上游模型渠道配置。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量，确认`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，格式为类似`http://aiproxy:3000`（未附加`/v1`或`/chat/completions`路径），`AIPROXY_API_TOKEN`为与AI Proxy服务端配置一致且非空的管理员令牌，不得在工作流全局变量、应用API请求头或普通模型管理页面填写该变量。
- 发起测试检索，输入运维常见问题如“VLAN配置变更记录”，核对返回结果的条数、字段完整性与预期一致。
- 确认`collectionIds`已绑定网络运维专属的知识库集合，避免召回无关业务数据。
- 查看检索日志，确认请求未出现鉴权失败或超时相关的报错。
