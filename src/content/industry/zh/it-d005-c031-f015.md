# 创作者入驻与认证的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
通常该品类的数据主要来自创作者后台、企业信用信息系统、账号历史库与合同管理系统。日常处理的文档包含入驻申请表单、身份资质扫描件、认证审核记录、合作协议文本等。数据更新节奏随申请流程触发，单次申请全链路更新频次为日级或每申请一次。核心字段包含账号唯一标识、资质核验状态、审核节点记录、合作条款摘要等，无统一固定的单位化统计字段，仅随业务流程流转。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据分散于多个独立系统，且随单次申请触发更新，要求知识库检索需支持跨集合的定向召回，避免跨数据源冗余匹配。文档包含结构化表单与非结构化资质材料两类内容，需同时适配语义检索与关键词匹配的混合逻辑。单次申请的流程数据时效性要求高，检索环节需优先召回最新更新的审核记录与资质文件，避免调用过期数据。同时，检索结果直接关联账号准入与身份核验，需严格控制召回结果的相关性阈值，防止无关内容干扰核验判断。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配资质材料与审核记录的语义相关性，平衡召回完整性与结果精准度 |
| `limit` | 前6条 | 适配单次申请的多文档关联审核场景，避免过多冗余内容超出上下文窗口 |
| `searchMode` | hybrid | 同时覆盖结构化表单字段与非结构化资质文本的检索需求 |
| `usingReRank` | 开启 | 对召回的多结果进行重排序，修正语义检索的局部偏差，提升资质核验的匹配精度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户查询扩展相关关键词，覆盖入驻申请中常见的同义表述，如“认证”与“资质审核” |
| `collectionIds` | 按业务集合分组配置 | 定向召回创作者后台、企业信用库、合同系统对应的知识库集合，避免跨业务数据干扰 |

## 容易做错的三处
- 现象：语义检索召回多条匹配结果，但模型返回“未找到相关答案”。原因：召回结果的`similarity`阈值设置偏低，或未开启`usingReRank`导致高相关结果被低相关结果覆盖，超出模型上下文窗口的有效范围。
- 现象：知识库检索时单次传入的token量超出预设上限，导致查询超时。原因：未限制`limit`参数的召回条数，或未对扩展后的查询内容做长度裁剪，导致token消耗过量。
- 现象：知识库内的markdown格式图片链接无法被正常检索匹配，或AI返回结果与知识库原始文档内容不一致。原因：未配置针对markdown资源的检索索引规则，仅检索文本内容忽略图片关联的元数据；或未开启`searchMode`的混合模式，仅使用语义检索导致对结构化表单字段的匹配失效。

## 怎么确认配好了
- 查看FastGPT知识库后台的检索配置页面，确认`collectionIds`已绑定对应业务数据源的知识库集合，无无关业务的数据集被纳入检索范围。
- 提交模拟入驻申请的查询文本，验证检索结果是否覆盖资质材料、审核记录等核心业务文档，调整`similarity`阈值至符合业务核验需求。
- 触发一次模拟申请流程，检查检索环节返回的结果条数是否符合`limit`的配置，无过多冗余结果干扰后续处理。
- 查看检索日志，确认`usingReRank`和`datasetSearchUsingExtensionQuery`已按配置生效，无异常参数报错信息。
