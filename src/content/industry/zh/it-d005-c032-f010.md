# 创作者激励结算的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
创作者激励结算场景的日常文档包含激励规则、结算明细、申诉记录、付款清单四类核心内容，数据来源涵盖内容数据、广告分成系统、财务系统与账号后台。数据字段通常包含创作者标识、收益核算口径、结算周期、付款状态等，更新节奏随月度结算周期或专属活动变动，文档结构多为结构化明细条目与规则说明结合的形式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多系统来源的字段差异要求溯源环节需统一创作者标识与结算周期的匹配规则，避免跨系统数据错位。月度或活动级的更新节奏要求知识库需同步匹配更新频率，防止引用过期的激励规则或过时的结算明细。文档分为规则与明细两类，需区分基础规则的通用溯源与单创作者结算数据的精准溯源，同时结算争议的出错后果要求溯源信息需完整关联到具体批次与个体，确保可追溯性。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.6–0.7 | 精准匹配创作者结算明细的专属字段，过滤通用激励规则的干扰 |
| 单次召回条数 | 前3–5条 | 对应单创作者关联的结算相关文档数量，避免冗余引用 |
| `quoteMaxToken` | 800–1200 token | 覆盖单条结算明细的完整字段内容，确保溯源信息无缺失 |
| `responseData` | 开启结构化返回 | 保留原始数据的标识字段，便于关联创作者与结算批次 |
| `detail` | 开启详细溯源 | 展示申诉记录与付款清单的关联信息，支持异常作弊排查 |
| 知识库更新频率 | 按结算周期同步 | 匹配数据更新节奏，避免引用过期的规则或明细 |

## 容易做错的三处
- 现象：配置的单次召回条数未生效，返回的溯源条目超出设定值。原因：仅在前端界面修改设置，未在API调用参数中同步配置对应参数，导致前端修改未实际生效。
- 现象：仅通过API调用获取语料时，无法展示答案出处。原因：未开启`responseData`参数的结构化返回，未携带原始数据的来源标识，无法关联到具体的结算文档。
- 现象：相似度阈值设置过低，无法召回需要的结算明细。原因：阈值低于0.5时，会匹配到大量不相关的通用激励规则，无法精准定位目标创作者的专属结算数据。

## 怎么确认配好了
- 发起一次针对创作者结算场景的测试调用，查看返回结果中是否包含创作者ID、结算周期等专属字段的溯源信息。
- 检查返回结果的溯源条目数量，确认与设定的单次召回条数一致。
- 验证`quoteMaxToken`参数的生效情况，查看溯源内容的token长度未超出设定范围。
- 手动调整相似度阈值，观察召回的文档列表是否随阈值调整发生对应变化。
