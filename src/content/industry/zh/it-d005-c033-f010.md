# 前端应用开发的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据主要来自代码仓库、接口管理平台、设计稿系统与浏览器兼容性数据库。日常产出的文档包含接口文档、组件说明、联调记录与发布清单，数据字段涵盖接口请求路径、参数规则、组件属性定义、兼容终端版本等。数据更新频率多为每日同步或随版本发布更新，单条数据体量较小但更新频次较高，且多为结构化的技术内容。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散的特征要求溯源环节需绑定各来源系统的唯一标识，确保引用内容可追溯至原始代码仓库或接口管理平台。高更新频率要求配置中启用定期增量同步，避免引用过时的接口参数或组件说明。单条数据体量小但总量多的特点，要求溯源时需过滤无关条目，仅保留与当前调试场景匹配的内容。前端场景侧重终端兼容数据，溯源需优先关联对应终端版本的来源信息，确保引用内容适配目标运行环境。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配前端单条接口文档或组件说明的平均长度，避免截断关键参数与注释 |
| `responseData` | 开启来源字段 | 确保返回结果中包含原始数据的来源路径与更新时间，适配前端调试时的溯源需求 |
| `detail` | 显示完整来源信息 | 包含代码仓库分支、接口管理平台的接口ID等细节，满足前端联调时的精准溯源 |
| 引用条目上限 | 前3–5条 | 前端调试场景下无需过多引用，避免界面信息过载，依据前端单页调试的信息密度设定 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 过滤低相关的兼容数据或过时文档，匹配前端场景下的内容匹配精度要求 |
| 是否显示引用条目 | 按需开启或关闭 | 匹配前端调试时是否需要展示溯源信息的场景需求 |

## 容易做错的三处
- 现象：返回的引用条目排序不符合预期，并非按内容相似度排列。原因：未针对前端场景的终端兼容数据调整排序权重，误将通用文档优先级置于兼容数据之上。
- 现象：对话中显示了未关联本地知识库的引用内容。原因：未开启仅召回已上传知识库内容的开关，导致调用了全局公共数据源，包含本地未上传的接口文档。
- 现象：引用内容被截断无法查看完整参数。原因：`quoteMaxToken` 设置值过小，截断了接口文档中的关键请求参数与注释。

## 怎么确认配好了
- 发起一条包含接口参数查询的提问，检查返回结果中是否包含原始来源的路径与更新时间。
- 上传一份测试用的接口文档，发起相关提问，确认仅该上传文档被列为引用来源。
- 调整`quoteMaxToken`的取值，验证返回的引用内容是否完整显示所有关键字段。
- 查看对话界面的引用区域，确认显示的条目数量符合预设的上限要求。
- 切换是否显示引用条目的开关，验证对话界面的引用区域是否按需求显示或隐藏。
