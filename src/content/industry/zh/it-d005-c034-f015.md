# 办公系统流程配置的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据主要来自企业OA系统、组织架构库、内部制度文件与用户反馈。日常产出的文档包括流程配置单、审批节点表、表单字段说明、变更记录，包含审批节点ID、权限范围、表单字段名、生效时间等字段。数据更新频率随流程变更触发，通常每月有1到数次更新，更新内容多为节点调整、权限变更或表单字段优化。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据分散在多个系统与文档中，检索时需覆盖OA流程配置、组织权限规则等多类数据源，对跨源召回的准确性提出要求。流程配置单、审批节点表等文档结构固定但字段关联紧密，检索时需精准匹配节点ID与权限范围，避免无关结果干扰。数据更新频率随流程变更波动，召回环节需支持增量同步更新后的文档，确保检索结果与当前生效规则一致。此外，变更记录需作为辅助检索依据，帮助定位近期调整的流程节点。

## 配置怎么定
本文适配FastGPT v4.17.0版本的官方规则，在配置前需确保App/Admin服务端已正确配置AIPROXY_API_ENDPOINT与非空AIPROXY_API_TOKEN，且未将其与模型渠道配置混淆。以下为具体配置项与建议：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配流程配置的精准度要求，避免过低出现无关审批节点，过高遗漏有效配置 |
| `limit` | `前 8–12 条` | 办公流程配置的节点数量通常有限，少量结果即可覆盖完整配置逻辑 |
| `searchMode` | `vector + keyword` | 兼顾语义匹配流程描述与关键词匹配节点ID、字段名等结构化信息 |
| `usingReRank` | `开启` | 对检索出的多段配置内容进行排序，优先返回与当前查询最相关的审批规则 |
| `datasetSearchUsingExtensionQuery` | `开启` | 自动扩展查询词，覆盖流程配置中常见的同义词，如「审批节点」与「审核环节」 |
| `collectionIds` | `指定对应流程配置知识库的集合ID` | 限定检索范围，避免混入其他品类的知识库数据，提升检索精准度 |

## 容易做错的三处
- 现象：单份流程配置文档上传后显示分8段，后续查看变为13段，出现重复分段内容。原因：未配置合理的分块关联参数，或知识库同步时未清理旧版本数据，导致重复索引。
- 现象：检索结果混入非流程配置类的文档内容，如员工账号权限说明。原因：未指定`collectionIds`参数，检索范围覆盖全量知识库，无关数据被召回。
- 现象：发起审批节点查询时，返回结果包含大量不相关的表单字段说明。原因：`similarity`参数取值不合理，过低返回冗余结果，过高遗漏匹配的配置内容。

## 怎么确认配好了
- 查看知识库索引日志，确认仅目标流程配置类文档被索引，无其他品类数据混入。
- 发起测试查询，输入具体的审批节点名称，核对返回结果的分段数量与原文档一致，无重复内容。
- 调整`similarity`参数区间，验证检索结果的精准度是否符合流程配置的查询需求。
- 触发一次流程配置的更新，确认知识库同步更新后，新的配置内容可被正常检索到。
