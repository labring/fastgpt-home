# 单元测试与组件测试的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的核心数据来自代码仓库、测试框架报告、需求说明与接口定义，更新频率为每日或每次代码提交后。日常产出的文档包含测试用例、覆盖率报告、Mock说明与缺陷单，其中测试用例包含用例ID、前置条件、执行步骤与预期结果字段，覆盖率报告包含文件路径、覆盖率数值与关联测试用例字段，Mock说明包含接口地址、请求参数与返回示例字段。数据以结构化字段为主，部分文档附带二进制格式的测试日志附件。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散在代码仓库与测试框架，溯源需要关联具体的提交哈希或构建记录，避免跨数据源混淆。更新频率较高，要求溯源系统支持近实时的数据源同步，确保引用的测试数据与当前代码状态一致。日常文档的结构化字段较多，引用时需精准匹配用例ID、文件路径等唯一标识，避免泛化匹配导致的溯源错误。测试数据构造环节耗时较长，溯源需减少重复查找的步骤，同时出错后果可能导致局部逻辑漏测，因此溯源的准确性直接影响测试质量。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 前 8000 token | 匹配测试用例、覆盖率报告等文档的平均长度，避免截断关键测试步骤与接口定义内容 |
| 单次搜索上限 | 前 10 条 | 控制召回的测试数据总量，平衡溯源准确性与接口响应速度 |
| 重排 | 开启 | 优先召回与当前测试任务关联度更高的文档，优化溯源结果的相关性 |
| 问题优化 | 开启 | 对测试相关查询进行语义优化，提升对测试用例ID、接口路径等标识的识别精度 |
| `quoteMaxToken` | 500–800 token | 限制引用的文档块长度，确保溯源信息简洁且不超出上下文窗口限制 |
| `responseData` | 仅返回关联字段 | 仅返回测试用例ID、文件路径等必要溯源字段，减少冗余信息对查询的干扰 |
| `detail` | 完整 | 保留测试用例的完整执行步骤与预期结果，确保溯源信息可完整追溯 |

## 容易做错的三处
- 现象：返回的溯源信息中未关联对应的测试用例变量，原因：未正确配置变量引用的数据源绑定，导致无法拉取测试用例的结构化字段。
- 现象：引用的文档块超出预期长度，原因：未正确设置`quoteMaxToken`参数，导致召回的测试数据过长，超出上下文窗口。
- 现象：接口问答请求超时，原因：未限制单次搜索上限，召回了过多不相关的测试框架报告与缺陷单，导致上下文加载超时。

## 怎么确认配好了
- 运行包含测试用例ID的接口问答请求，检查返回结果中是否包含对应的溯源文档链接或唯一标识。
- 查看FastGPT v4.17.0的溯源日志，确认引用的文档来源指向正确的代码仓库路径或测试框架报告。
- 调整`quoteMaxToken`参数为不同区间，验证返回的引用文档块长度是否符合设定值。
- 关闭重排配置后，对比两次召回结果的相关性，确认重排配置已生效。
