# 原型与交互设计的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
典型主体为产品设计师、交互设计师、前端产品小组，日常处理的文档包括交互原型、页面流程图、组件说明、评审记录。数据来源主要为Figma或Axure文件、设计系统、用户反馈、可用性测试记录，更新频率通常为每周或每版本迭代时更新。文档结构多包含页面层级、操作路径、组件属性、修改意见等内容，字段涵盖页面ID、操作节点、组件名称、修改时间等，部分文件为嵌套结构，无统一的标准化字段格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
交互原型与评审记录的嵌套结构要求分块时保留上下文关联，避免拆分破坏操作路径的完整性；高频的版本更新要求索引配置支持增量同步，减少全量重建的资源消耗；数据中包含大量操作路径描述与异常场景说明，向量模型需要适配长文本的上下文关联，同时索引需要覆盖高频修改的内容；数据量随版本迭代逐步累积，需要控制单批次索引的处理规模，避免资源占用过高。此外，`maxToken`参数的配置需要匹配大模型的输入上限，防止向量化过程中截断关键操作描述。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配交互原型与评审记录的单页内容长度，避免拆分破坏操作路径上下文 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的操作路径关联，降低上下文断裂概率 |
| `maxToken` | 4096 token | 适配大模型的输入上限，避免向量生成时截断关键操作描述 |
| `defaultToken` | 按实测标定 | 匹配本地向量模型的最大输入长度，确保原型文件的完整内容被正确向量化 |
| 单次召回上限 | 前 8 条 | 匹配前端小组的日常评审与修改的核心关注范围，减少冗余检索结果 |
| 最大上下文 | 3000–4000 字符 | 适配交互设计文档的单轮问答长度，确保检索结果覆盖完整操作路径 |

## 容易做错的三处
- 现象：向量化任务触发速率限制报错，日志显示请求频率超限。原因：未调整并行处理参数，线程数设置过高，导致向量化请求超出接口限额。
- 现象：知识库检索响应耗时较长，相同模型配置下表现不佳。原因：分块长度设置过大，单批次向量检索计算量过高，未优化检索召回的过滤规则。
- 现象：问答对提取方式长期处于索引中状态，无法切换至就绪状态。原因：增量更新的触发逻辑配置错误，或源文件的同步权限异常，导致索引同步任务无法完成。

## 怎么确认配好了
- 上传一份小型交互原型文件，查看向量化任务的日志，确认分块长度与重叠长度的匹配度符合配置要求。
- 发起一次针对操作路径的检索，核对返回结果的数量与配置的单次召回上限一致。
- 提交一次增量更新任务，查看索引同步的进度，确认任务能在合理时间内完成并切换至就绪状态。
- 检查数据集中的重复条目，确认增量更新的去重规则已生效，无额外的重复索引生成。
