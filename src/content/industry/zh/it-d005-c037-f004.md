# 发布管理与版本验收的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自CI流水线、变更系统、测试报告、监控看板，更新节奏为每周或每个版本周期。日常产出的文档包含发布计划、上线清单、验收报告、回滚预案，文档字段包含版本标识、变更内容、测试结论、回滚触发条件等，无统一固定的单条数据长度上限，随单次版本发布的规模动态变化，部分文档包含多段落的结构化条目与半结构化说明，如上线清单会按模块罗列具体变更项。

## 这些特征在「向量模型与索引」这一环带来什么约束
首先，数据多来自自动化系统的批量产出，需适配批量增量更新的索引流程，避免单次全量索引占用过多集群资源。其次，更新周期为周或单版本周期，无需高频实时索引，可配置定期同步任务完成全量或增量更新。再者，文档包含版本标识、变更内容等关联字段，分块处理时需保留字段关联关系，避免拆分后丢失跨分块的上下文关联，影响检索时的关联准确性。最后，单条数据长度随版本规模波动，需灵活调整分块参数适配不同长度的文档内容，避免出现分块过长超出模型处理上限或过短导致上下文断裂。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 分块长度 | 800–1200 字符 | 适配发布计划、上线清单等文档的半结构化内容长度，避免拆分破坏字段关联 |
| 重叠长度 | 50–100 字符 | 保留相邻分块的上下文关联，确保版本号等跨分块字段的连贯性 |
| `maxToken` | 4096 token | 适配向量模型的输入长度限制，避免单条数据超出模型处理上限 |
| 相似度阈值 | 0.72–0.85 | 过滤低关联的检索结果，匹配发布项核对、回滚条件确认等场景的精准度需求 |
| 单次搜索上限 | 前10条 | 控制检索返回结果的数量，适配上线窗口协调、发布项核对的有限信息需求 |
| `defaultToken` | 2048 token | 配置默认的向量生成输入长度，适配多数日常文档的分块规模 |

## 容易做错的三处
- 现象：向量模型接入后显示未就绪，日志提示渠道配置缺失。原因：未按照界面指引填写向量模型的专属接入密钥与接口地址，混淆了大语言模型与向量模型的配置参数。
- 现象：检索结果返回条数与配置的单次搜索上限不符。原因：分块长度设置过大，导致有效分块数量不足，无法达到预设的检索条数。
- 现象：索引更新后旧版本数据未被覆盖。原因：未配置增量索引的版本匹配规则，导致新数据与旧数据的版本标识未关联，重复生成索引条目。

## 怎么确认配好了
- 手动上传一份典型的上线清单文档，触发向量生成与索引流程，查看FastGPT v4.17.0界面上的索引状态是否显示为已完成。
- 输入一条与回滚预案相关的查询语句，核对检索返回结果的相似度是否落在预设的阈值区间内。
- 提交一次版本更新后的文档，查看索引列表中是否新增对应版本的条目，且旧版本条目未被遗漏。
- 进入向量模型配置页面，确认已选择的模型与配置参数与预设值一致，无缺失的必填项。
