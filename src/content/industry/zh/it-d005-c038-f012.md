# 变更管理与发布窗口的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
本品类的数据主要来自变更管理系统、CI流水线、监控数据与业务日历，更新频率为周度或每变更周期一次。日常使用的文档包含变更申请、风险评估、上线窗口计划、回退方案四类，文档结构固定，包含章节标题、执行时段、风险等级、审批状态等明确字段，部分文档附带历史操作记录与附件内容，整体数据以结构化或半结构化为主。

## 这些特征在「文档解析与分块」这一环带来什么约束
变更类文档的固定层级结构要求解析与分块环节需保留章节关联信息，避免拆分后丢失上下文导致检索不准确；高更新频率意味着解析环节需具备合理的响应速度，避免影响变更流程的推进；多来源的数据格式包含PDF、DOCX等常见办公格式，需要适配不同文档的解析规则；部分文档包含历史记录与附件，对文件上传与解析的容量限制提出了要求。这些特征共同决定了分块规则需兼顾内容完整性与检索精准度，同时需适配多格式文档的解析需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 变更类文档的单章节正文长度适中，该区间可保留完整的业务上下文，避免分块过碎或冗余 |
| `chunkSplitter` | 按章节标题+段落拆分 | 变更文档具备明确的章节层级，按此规则拆分可保留章节关联信息，提升RAG检索时的上下文准确性 |
| `customPdfParse` | 启用 | 变更文档多为正式的PDF格式文件，启用后可精准提取文本与排版结构，避免丢失关键字段 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 部分变更文档包含历史记录与附件，该容量可覆盖绝大多数业务场景下的文件上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 大型变更文档的解析耗时较长，该区间可避免因超时中断解析流程，保障变更文档的完整处理 |
| `chunkSettingMode` | 手动配置 | 变更文档的结构固定，手动配置可精准匹配业务的检索与分块需求，适配不同场景的使用习惯 |

## 容易做错的三处
- 现象：前端本地环境上传变更文档可正常解析，服务器环境上传后文档解析节点返回404错误，无法读取文件内容。原因：服务器环境下文件上传路径配置与本地不一致，解析节点无法定位到上传的文件存储目录。
- 现象：使用Vllm 0.10部署Qwen3-14B时，无法从PDF格式的变更文档解析结果中提取响应字段，使用Qwen2.5-14B则可正常提取。原因：不同大模型对解析后的文本格式适配性存在差异，部分模型无法兼容变更文档中特定的排版与字段结构。
- 现象：上传DOCX格式的变更申请文档后，RAG检索结果仅包含正文内容，未附带对应的章节标题信息。原因：未配置按章节标题拆分的分块规则，解析时未保留文档的层级结构。

## 怎么确认配好了
- 登录FastGPT v4.17.0的控制台，上传一份标准变更申请文档，查看解析后的分块结果，确认每个分块包含对应的章节标题与正文内容。
- 上传超过500 MB的变更文档，确认解析过程未触发超时错误，完成解析后可正常发起RAG检索。
- 测试PDF、DOCX两种格式的变更文档，确认解析结果的文本完整性与结构准确性，无明显内容丢失。
- 查看服务器的文件存储目录，确认上传的文档已正确保存，解析节点可正常访问该目录下的文件，无权限或路径错误。
