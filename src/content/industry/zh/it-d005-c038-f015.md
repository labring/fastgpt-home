# 变更管理与发布窗口的技术文档与接口问答：知识库检索与召回
本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类数据来源为变更管理系统、CI流水线、监控数据与业务日历，日常文档包含变更申请单、风险评估报告、上线窗口计划、回退方案等。数据字段包含变更唯一标识、窗口起止时间、风险评级、审批状态、回退触发条件等，更新频率为每周或每次变更后更新，单份文档内容围绕单次生产环境变更的全流程信息展开。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类数据来源分散且格式存在差异，要求检索环节支持多源数据的统一映射与字段对齐。更新频率随变更节奏波动，需支持增量更新以避免全量索引重建的性能损耗。文档内容聚焦变更全流程，检索时需优先召回与风险评级、上线窗口、回退方案相关的片段，且需关联变更的时间属性以匹配当前生产环境的窗口限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配变更相关文档的核心语义，避免召回无关的通用运维文档 |
| `limit` | 前8条 | 覆盖单次变更所需的全部关联文档，避免过多冗余内容干扰审批决策 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配变更文档中既有结构化字段又有非结构化描述的场景 |
| `usingReRank` | 开启 | 对召回结果重新排序，优先展示风险评级、窗口时间等关键字段的匹配结果 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题生成扩展查询，覆盖变更申请、回退方案等不同类型的文档片段 |
| `collectionIds` | 变更管理专属集合ID | 限定检索范围仅在本品类的知识库集合，避免混入其他业务的文档 |

## 容易做错的三处
- 现象：检索结果中混入大量非变更管理类的通用运维文档，无法精准匹配目标内容。原因：未配置`collectionIds`限定检索范围为变更管理专属知识库集合，导致跨集合召回无关数据。
- 现象：导入中文变更文档后界面显示乱码，英文文档无异常。原因：导入流程未指定UTF-8编码格式，导致中文字符解析错误。
- 现象：检索返回的结果条数与配置的`limit`参数不符，出现结果过多或过少的情况。原因：未正确配置重排后的结果过滤逻辑，或重排参数超出了召回上限。

## 怎么确认配好了
- 查看知识库管理界面的集合列表，确认`collectionIds`已填入变更管理专属的集合标识。
- 发起一条包含“变更窗口”“风险评估”的测试查询，核对返回结果的相似度是否在0.75–0.85区间内。
- 导入一份中文变更申请单，确认界面显示无乱码，且向量召回流程正常触发。
- 查看检索日志，确认`usingReRank`已生效，结果排序优先展示风险评级、窗口时间等关键字段。
