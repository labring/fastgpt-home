# 安全事件应急响应的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自SIEM、EDR、防火墙日志与主机镜像，更新节奏为实时或每事件一次。核心处理文档包括应急响应报告、取证记录、处置方案、通报材料，单条数据包含事件时间戳、关联IP、告警等级、处置步骤、证据链编号等字段，无统一固定长度，单次事件数据量随攻击复杂度波动。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时或每事件的更新节奏，要求向量索引支持增量写入，避免全量重建带来的处理延迟。多源异构的日志与文档结构，要求向量模型适配非结构化文本与结构化字段的混合编码，确保不同来源数据的向量一致性。证据链整理的核心需求，要求索引保留原始数据的关联标识，防止向量检索时丢失关键溯源信息。单次事件数据量的波动特性，要求索引的分片策略支持动态扩容，避免单分片过载影响响应速度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配应急响应日志与文档的平均长度，避免单块内容过于分散或冗余 |
| 重叠长度 | 100–200 字符 | 保留跨块的上下文关联，确保攻击路径还原时的逻辑连贯性 |
| `defaultToken` | 按实测标定 | 适配多源日志的token消耗差异，避免单请求token超限 |
| `maxToken` | 4096 token | 符合通用开源向量模型的上下文窗口限制，平衡检索精度与响应速度 |
| 单次搜索上限 | 前10条 | 兼顾证据链整理的全面性与检索响应速度，避免冗余数据干扰 |
| 相似度阈值 | 0.75–0.85 | 过滤低关联的日志条目，聚焦高风险的攻击关联信息 |

## 容易做错的三处
- 现象：导出的知识库dataset.csv仅包含index字段，无content字段。原因：分块配置时未正确关联原始日志的content字段，仅索引了元数据信息。
- 现象：向量检索返回大量低关联的日志条目，无法快速定位核心攻击证据。原因：相似度阈值设置过高，未过滤无关的正常日志数据。
- 现象：Docker部署环境中索引模型无法正常加载。原因：未在docker-compose配置中挂载模型存储目录，或向量模型的调用参数未与部署环境对齐。

## 怎么确认配好了
- 上传单条应急响应日志样本，执行向量检索，检查返回结果是否包含关联的攻击路径与处置方案信息。
- 导出知识库的dataset.csv，确认文件同时包含index与content字段，字段内容与原始日志的文本信息一致。
- 在FastGPT v4.17.0版本的系统监控中查看向量模型加载日志，确认无报错信息。
- 模拟实时事件写入，检查索引更新的延迟时间是否符合业务时效要求。
