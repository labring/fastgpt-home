# 安全事件应急响应的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自SIEM、EDR、防火墙日志与主机镜像，更新频率为实时或每事件级。日常文档包含应急响应报告、取证记录、处置方案、通报材料，字段多包含攻击源IP、处置时间、证据链哈希值、影响范围等，单份文档长度跨度较大，从数百字符的告警摘要到数万字符的完整取证报告不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据实时更新要求检索链路支持低延迟召回，避免因日志滞后影响应急处置。多源异构数据格式要求检索模型适配结构化日志与非结构化文档的混合召回。单份文档长度跨度大，需调整分块策略避免关键信息被截断。攻击路径还原、证据链整理等核心环节依赖精准匹配，对召回的相关性有严格要求，误召回将导致处置方向偏差，扩大安全风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配安全事件应急响应场景的检索需求：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配安全事件的高相关性要求，避免误召回无关告警或处置方案 |
| `limit` | 前10条 | 平衡检索效率与信息完整性，满足攻击路径还原的多线索需求 |
| `searchMode` | hybrid | 支持结构化日志与非结构化文档的混合检索，适配多源数据特征 |
| `usingReRank` | 开启 | 提升长文档或多源数据下的召回排序准确性，优化证据链相关内容的匹配度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展应急相关专业术语，覆盖攻击手段、处置工具等场景词汇 |
| `collectionIds` | 按数据源分组配置 | 区分SIEM日志库、处置方案库等，精准召回对应场景的知识库内容 |

## 容易做错的三处
- 执行curl调用检索接口返回code514错误，现象是返回指定报错格式的响应内容，原因是未正确传入有效的kb_id参数或未配置知识库的API访问权限。
- 对比Milvus与PGVector版知识库的检索效果时未匹配场景，现象是高并发日志检索中PGVector版出现延迟，原因是未根据实时更新的日志数据量选择适配的向量数据库存储方案。
- 无法通过API完成知识库与对话流程的关联，现象是在官方文档中未找到对应接口路径，原因是混淆了知识库独立管理接口与对话绑定配置接口，需通过指定的配置模块完成关联。

## 怎么确认配好了
- 执行预设的攻击告警关键词检索，核对返回结果是否包含对应处置方案文档，确认`similarity`参数的取值符合场景要求。
- 查看检索日志，确认多源数据（如SIEM日志与处置报告）均被正确召回，验证`searchMode`为hybrid的配置生效。
- 模拟实时日志导入场景，测试检索延迟是否符合应急响应的时间要求，确认配置未引入额外性能开销。
- 检查API返回的结果字段，确认`collectionIds`参数过滤后的数据源仅包含目标应急知识库内容。
