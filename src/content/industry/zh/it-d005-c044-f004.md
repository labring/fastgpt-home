# 安全产品规则运营的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据主要来自WAF、IDS、防火墙及威胁情报平台。日常生成的文档包含规则变更单、拦截日志、误报分析报告、策略回滚记录，单条数据多包含规则ID、触发条件、拦截阈值、关联事件ID等字段。数据更新频率多为每日或随安全事件触发，单条记录的字段数量和格式随防护设备类型略有差异，整体以结构化文本和半结构化日志为主。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且格式差异较大，要求索引环节适配多源异构数据的解析逻辑。更新频率随安全事件波动，需支持增量索引以避免全量重建的资源消耗。误报分析和规则复核依赖精准的上下文召回，对向量模型的语义匹配精度有较高要求。单条记录包含规则ID、触发条件等强关联字段，需在索引时保留字段级元数据以支撑精准检索，同时需控制索引体积避免影响实时查询性能。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配拦截日志、规则变更单的单段文本长度，避免块内语义断裂 |
| 重叠长度 | 100–200 字符 | 保留跨块的规则上下文，防止检索时遗漏关联的触发条件描述 |
| 相似度阈值 | 0.75–0.85 | 平衡误报拦截和漏报风险，匹配安全规则的语义匹配精度要求 |
| 单次搜索上限 | 前 10 条 | 控制检索返回量，避免过载同时覆盖常见的误报分析场景 |
| `defaultToken` | 4096 | 适配长文本的规则变更单和威胁情报报告，保证完整上下文输入 |
| 重排开关 | 开启 | 优化检索结果的排序逻辑，提升误报样本的关联召回效率 |

## 容易做错的三处
- 现象：本地部署FastGPT v4.17.0时，新建知识库上传文档后无图片索引模型选项。原因：该图片索引功能默认仅在商业版部署包中预置，开源本地部署需手动导入对应模型插件。
- 现象：配置`defaultToken`为2048时，长规则变更单无法完整加载至上下文。原因：未匹配文档实际长度，导致关键规则描述被截断，影响关联检索精度。
- 现象：配置Embedding模型连接OneAPI时出现报错，无法生成向量。原因是未正确配置OneAPI的接口地址和密钥，或未在FastGPT中启用对应Embedding模型的适配设置。

## 怎么确认配好了
- 上传一条完整的规则变更单，检查分块后的文本块是否保留完整的规则ID和触发条件描述。
- 输入误报分析相关的查询词，核对检索返回的结果条数是否符合单次搜索上限的配置。
- 测试连接Embedding模型，确认无连接报错，且生成的向量可正常存入索引。
- 上传一条最新的拦截日志，验证增量索引是否能在配置周期内完成更新并被检索到。
