# 安全培训与钓鱼演练的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的典型数据主体为安全运营团队、企业内训部门及外部安全服务商。日常产生的文档包含培训课件、钓鱼演练方案、钓鱼邮件模板与演练结果报告四类，数据来源涵盖员工通讯录、企业邮件网关、内部培训平台与员工点击统计数据。数据更新频率多为季度或年度，核心耗时环节涉及演练人群筛选、邮件模板设计与演练结果复盘，数据关联场景涉及人员安全意识提升与合规审计要求。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源多样，包含结构化的员工通讯录、半结构化的点击统计数据与非结构化的长文本课件、短文本邮件模板，要求向量模型需兼容多类型文本的向量化处理。数据更新频率较低，无需构建实时索引，可采用批量离线构建的方式降低计算成本。文档长度差异显著，长课件需合理拆分以保留语义完整性，短模板需避免过度拆分导致语义断裂。同时，演练结果报告与人员、场景的关联字段需在索引中保留，以便后续复盘时溯源具体信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配培训课件、演练方案这类长文本的拆分，避免语义断裂，适配FastGPT v4.17.0的默认分块逻辑 |
| 重叠长度 | 100–150 字符 | 保留分块间的语义关联，适配钓鱼邮件模板这类短文本的上下文衔接需求 |
| `maxToken` | 8192 token | 适配主流embedding模型的输入长度限制，兼容长文档拆分后的单块内容，符合FastGPT v4.17.0的参数要求 |
| `defaultToken` | 按实测标定 | 适配不同embedding模型的默认token计数规则，避免模型调用时的格式报错 |
| 相似度阈值 | 0.72–0.85 | 平衡检索召回率与精准度，适配演练结果报告的关键信息检索需求 |
| 单次搜索上限 | 前 10 条 | 控制检索结果的返回量，避免冗余信息干扰演练复盘环节 |

## 容易做错的三处
- 现象：更换embedding模型后，原有知识库检索结果偏差明显或返回“模型不匹配”提示。原因：未执行索引重建操作，原有向量数据仍基于旧模型生成，与新模型的向量空间不一致。
- 现象：调用embedding接口时返回“undefined model must match "^(text”报错。原因：未正确配置所选embedding模型的名称格式，或未开通对应模型的API调用权限。
- 现象：知识库搜索结果排序与语义相似度预期不符，低相关内容靠前展示。原因：未配置重排环节，仅依赖基础向量召回的原始排序逻辑，未结合演练场景的权重调整结果。

## 怎么确认配好了
- 调用embedding测试接口，生成单份钓鱼邮件模板的向量值，核对与所选模型的输出格式一致，验证模型配置正确。
- 执行批量索引重建操作，确认无报错且索引进度正常完成，验证索引配置与数据处理逻辑匹配。
- 导入单份演练结果报告，检索“演练人群”“违规点击”等关键词，核对返回结果的排序与语义相关性符合预期。
- 查看索引分块统计面板，确认分块长度、重叠长度的配置与预设值一致，验证分块规则生效。
