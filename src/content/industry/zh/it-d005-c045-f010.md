# 安全培训与钓鱼演练的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的核心数据包括安全培训课件、钓鱼演练方案、钓鱼邮件模板及演练结果报告，数据来源通常为员工通讯录、邮件网关、内部培训平台与用户点击统计系统。数据更新频率多为季度或年度，文档结构包含演练人群规则、模板参数、结果统计字段，无统一强制单位，字段随单次演练场景按需调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据特征对引用溯源环节带来多项约束。多源分散的数据来源要求溯源需关联员工通讯录、邮件网关等多系统的原始记录，确保演练人群、点击数据可交叉验证。低更新频率要求引用的源数据需锁定对应周期的版本，避免因后续数据更新导致溯源失效。多样的文档类型需要匹配不同的溯源字段，培训课件需关联培训计划编号，邮件模板需绑定版本标识。严重的出错后果要求溯源信息完整可查，不得缺失关键证据节点。

## 配置怎么定
本文基于 FastGPT v4.17.0 版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次检索条数上限 | 前3-5条 | 该品类核心文档数量有限，过多条目会分散溯源注意力 |
| `quoteMaxToken` | 1200-1500 token | 匹配该品类常见文档切块长度，避免截断关键溯源字段 |
| 引用源地址展示 | 开启 | 需完整展示源文档路径，满足审计溯源的合规要求 |
| `detail` | 完整 | 保留源文档的全部溯源信息，包括演练编号、版本标识 |
| 最大上下文长度 | 2000-2500 token | 整合多源数据的溯源内容，支持跨系统交叉验证 |
| `responseData` | 包含源文档元数据 | 确保溯源信息包含文档的创建时间、更新周期等元数据，匹配低更新频率的溯源要求 |

## 容易做错的三处
- 现象：回复中未展示源文件的完整地址。原因：未开启引用源地址展示的配置项，导致溯源信息缺失。
- 现象：检索到符合条件的文档切块，但实际返回的引用条数超出设置上限。原因：未正确配置`quoteMaxToken`与单次检索条数上限的匹配关系，导致切块长度超出限制后仍被纳入结果。
- 现象：引用的溯源字段不完整，缺少演练编号或版本标识。原因：未将`detail`配置为完整模式，仅返回了部分文档内容，无法满足审计要求。

## 怎么确认配好了
- 发起一次针对钓鱼演练方案或培训课件的接口问答，检查回复中是否包含源文档的完整路径。
- 查看回复中的引用条数，确认其符合配置的单次检索上限。
- 核对引用内容的字段，确认包含演练编号、版本标识等溯源信息。
- 调整`quoteMaxToken`参数后，验证回复中引用内容的长度是否符合设置。
