# 安全基线检查的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据围绕安全基线合规场景生成，日常文档包括基线检查表、配置核查记录、整改建议与例外审批单。数据来源为服务器配置、中间件配置、安全设备策略及基线工具输出结果，更新频率为月或季度。数据字段包含配置项ID、合规状态、核查时间、关联设备信息，单位多为标准配置项编号、布尔值、日期格式，无额外自定义单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据来源分散于服务器、中间件、安全设备及基线工具，引用溯源时需关联设备标识、工具版本等元数据，避免引用无关联的配置项。数据更新频率为月或季度，溯源时需验证引用内容的更新时间是否匹配当前核查周期，确保合规性时效性。日常文档包含多维度合规字段，溯源时需精准匹配配置项ID与核查记录的对应关系，避免混淆不同批次的基线检查结果。例外审批单的引用需关联具体审批流程，确保溯源时可追溯整改豁免的合法依据。

## 配置怎么定
本配置基于 FastGPT v4.17.0 版本制定，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 8000–12000 token | 匹配安全基线检查文档的平均长度，避免截断关键合规字段 |
| 单次搜索上限 | 前 8 条 | 覆盖单批次基线检查的核心配置项数量，避免冗余引用 |
| 引用内容细节 | 开启 | 保留配置项ID、核查时间、关联设备信息，满足溯源要求 |
| 引用去重阈值 | 0.80–0.90 | 过滤重复的配置项核查记录，避免重复引用 |
| 溯源时间校验 | 开启 | 验证引用数据的更新时间是否在当前核查周期内 |
| 温度设置 | 0.3–0.5 | 平衡回答的严谨性与可读性，适配合规场景的严肃需求 |

## 容易做错的三处
- 现象：上传批量基线检查文档后，部分内容显示训练异常，引用时无法溯源到原始配置数据。原因：未开启数据溯源开关，未绑定文档与原始基线工具的输出关联关系。
- 现象：变量引用模式下无法找到温度设置按钮，无法调整回答严谨性。原因：未在对话组件配置中开启自定义参数入口，导致合规场景无法适配不同核查需求。
- 现象：引用内容出现重复的配置项核查记录，溯源时无法区分不同批次的检查结果。原因：未设置引用去重阈值，或阈值设置不符合当前数据规模，导致重复内容未被过滤。

## 怎么确认配好了
- 上传一批测试用的基线检查表，查看训练状态日志，确认无异常报错。
- 发起一次基线合规问答，查看引用来源面板，确认显示配置项ID、核查时间等元数据。
- 调整引用相关配置后，发起多轮问答，验证引用内容的去重与时间校验逻辑生效。
- 检查对话组件的参数设置面板，确认自定义参数入口已开启，可调整温度等参数。
