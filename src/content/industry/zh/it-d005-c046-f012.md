# 安全基线检查的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
本品类服务于安全运维、安全咨询顾问、内控审计人员，日常处理的文档包括基线检查表、配置核查记录、整改建议、例外审批单。数据来源于服务器配置、中间件配置、安全设备策略的导出快照，以及基线工具生成的检查报告，更新频率为月度或季度。文档多为结构化格式，包含配置项ID、检查项描述、当前配置值、合规状态等固定字段，部分文档附带配置截图或合规说明附件。

## 这些特征在「文档解析与分块」这一环带来什么约束
结构化的基线文档要求分块需保留配置项的关联关系，避免拆分同组检查项与合规说明。多来源的配置快照可能包含word、excel、导出文本等多种格式，要求解析环节支持多格式兼容并保留表格、字段结构。月度/季度的更新频率意味着分块无需过细，但需保留足够的上下文以支撑配置核对。最耗时的配置项核对环节，要求分块将同类别配置项聚合，提升检索匹配效率。严重的出错后果要求解析与分块环节不能遗漏关键配置项，确保检索结果完整覆盖合规检查内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数逻辑制定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 匹配单组基线检查项+合规说明的典型长度，避免拆分同组配置关联内容 |
| `chunkSplitter` | 按标题+段落拆分 | 适配基线文档按检查项分类的结构，保留每个检查项的完整语义 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配批量导出的大型基线核查记录的解析耗时，避免大型文件解析中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持批量导入多份季度基线报告的文件体积需求 |
| `customPdfParse` | 启用 | 保留基线检查表PDF中的表格结构与字段标识，避免解析后格式错乱 |

## 容易做错的三处
- 现象：导入基线检查表的图片后，对话中图片无法加载，图片链接仅保留相对路径。原因：未启用自定义文档解析的图片路径补全配置，仅在word转存时处理了域名，markdown格式导入时未补全完整域名。
- 现象：解析大型基线配置文件时出现超时报错，日志显示请求超时。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值低于实际解析所需耗时，导致未完成解析即中断。
- 现象：检索特定配置项时返回的分块内容不完整，缺少合规状态字段。原因：`chunkSize`设置值过小，将单条配置项拆分至多个分块，导致检索时无法获取完整内容。

## 怎么确认配好了
- 上传一份典型的基线检查表文档，查看解析后的分块预览，确认同组检查项与合规说明未被拆分至不同分块。
- 查看上传文件的解析日志，确认解析耗时未超过`PARSE_FILE_TIMEOUT_SECONDS`设置的阈值。
- 测试检索特定配置项的合规状态，确认返回的分块内容包含完整的检查项描述与当前配置值。
- 上传包含图片的基线文档，检查对话中展示的图片链接是否补全了完整的域名前缀。
