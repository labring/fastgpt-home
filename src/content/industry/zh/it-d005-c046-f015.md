# 安全基线检查的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据以安全运维、内控审计人员日常产出的基线检查表、配置核查记录、整改建议、例外审批单为核心载体，数据来源覆盖服务器配置、中间件配置、安全设备策略及专用基线工具。数据更新周期为月或季度，单条数据多包含配置项名称、合规状态、核查时间、例外说明等字段，无统一固定单位，需结合具体安全基准要求匹配内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且兼具结构化配置项与非结构化审批文本，需同时支持精准匹配配置字段与模糊匹配整改建议内容。更新周期较长，知识库无需高频增量同步，但需支持按周期全量刷新。数据字段随安全基准动态调整，检索需适配变化的配置项规则。例外审批单的非结构化内容占比高，需平衡精准召回与模糊匹配的权重，避免遗漏例外场景的相关核查记录。同时需区分配置项核对与整改结果复核的不同检索需求，避免检索结果混淆两类场景。FastGPT v4.17.0 版本的检索框架可适配该类混合数据的检索约束。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 适配安全基线配置项的精准匹配需求，避免过低导致无关配置混入，过高遗漏合规配置 |
| `limit` | 前10条 | 平衡检索效率与覆盖范围，安全基线核查的配置项数量通常集中在数十条，10条可覆盖核心核查项 |
| `searchMode` | `vector` | 针对结构化配置字段与非结构化整改文本的混合检索，向量模式可适配语义匹配需求 |
| `usingReRank` | 开启 | 对检索结果进行二次排序，优化例外审批单这类非结构化内容的召回排序，提升整改建议匹配精度 |
| `collectionIds` | 传入目标基线知识库集合ID | 限定检索范围，避免跨基准的冗余数据被召回，确保检索结果仅针对当前执行的安全基线检查 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 安全基线数据的规则相对固定，无需额外扩展查询词，避免引入无关检索结果 |

## 容易做错的三处
- 现象：检索结果中出现大量与当前基线基准无关的配置项。原因：未设置合理的`similarity`阈值，或未指定`collectionIds`限定目标知识库集合，导致跨基准的冗余数据被召回。
- 现象：调用接口后无法生成结构化索引，或检索结果未包含整改建议内容。原因：混淆了「集合添加数据」与「创建训练订单」的功能边界，集合添加数据仅完成文本上传，创建训练订单触发针对基线数据的结构化索引构建流程，需按场景选择对应接口。
- 现象：检索返回的配置项顺序与核查优先级不符，高优先级整改项未前置。原因：未开启`usingReRank`重排功能，仅依赖初始向量召回的排序结果，无法适配整改建议的语义优先级。

## 怎么确认配好了
- 上传一份测试基线检查表，执行检索查询，核对返回结果是否包含匹配的配置项名称与合规状态。
- 调用指定接口传入`collectionIds`参数，确认检索结果仅来自目标安全基线知识库集合。
- 开启`usingReRank`后，对比重排前后的整改建议排序结果，确认高优先级整改项前置。
- 调整`similarity`阈值，验证检索结果的冗余条数变化是否符合预期。
