# 安全漏洞披露处理的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
本品类为安全漏洞披露处理场景下的技术文档与接口问答数据，来自项目安全响应小组、维护者及安全研究员的日常产出与外部渠道，包含安全公告、漏洞报告、修复补丁、CVE申请材料等文档。数据来源涵盖私密漏洞报告、代码仓库、官方CVE编号发布机构与项目公开渠道，更新节奏以单次漏洞事件为单位，单条数据包含漏洞编号、影响范围、修复版本、披露时间、补丁链接等结构化字段与非结构化文本内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据按单次漏洞事件更新，无固定批量周期，且包含私密漏洞报告与公开文档两类权限层级。数据同时包含结构化字段（如CVE编号、修复版本）与非结构化文本（如漏洞描述、补丁说明），且单条数据的文本长度差异较大。这类特征要求向量模型与索引需支持分层权限控制，适配非结构化与半结构化混合数据的编码，同时可灵活响应突发的单事件数据更新，避免固定批量索引的延迟问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配漏洞描述、补丁说明类文本的自然分段 |
| 重叠长度 | 100–200 字符 | 保留跨分块的上下文关联，避免漏洞细节被拆分丢失 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关的历史漏洞报告，聚焦当前事件的关联信息 |
| 单次搜索上限 | 前 10 条 | 控制检索结果的信息量，避免超出模型上下文窗口 |
| `maxToken` | 8000 token | 适配CVE申请材料、完整安全公告的长文本编码 |
| `defaultToken` | 2000 token | 作为单条向量编码的默认上下文长度，平衡精度与性能 |

## 容易做错的三处
- 升级到FastGPT v4.17.0后调用索引接口返回400状态码且无响应体：原因是未适配新版本的索引权限校验规则，未为私密漏洞报告数据配置对应的访问权限。
- 本地部署后向量读写导致服务器资源撑满：原因是未限制单批次索引的文件数量与大小，未设置`defaultToken`的合理上限，导致大量长文本同时编码占用过多资源。
- 知识库文件上传偶尔卡在1组或2组索引中：原因是分块长度设置与漏洞报告的文本长度不匹配，导致部分分块无法完成向量编码，未开启失败重试机制。

## 怎么确认配好了
- 上传一条测试用的漏洞报告文档，查看向量生成日志，确认分块长度与重叠长度的配置生效。
- 发起一次漏洞影响评估的检索请求，查看返回结果的数量与相似度分值，确认阈值与单次搜索上限的配置生效。
- 导出当前知识库的配置信息，核对`maxToken`与`defaultToken`的取值与预设配置一致。
- 模拟私密漏洞报告的上传与检索，确认权限控制的配置生效，未出现越权访问提示。
