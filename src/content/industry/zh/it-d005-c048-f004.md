# 安全监控与SOC值守的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来源为SIEM、EDR、NDR及外部威胁情报源，日常文档包含告警处置单、值班记录、威胁情报通报、日报周报。数据更新节奏分为实时与日更两类，文档结构多包含告警ID、处置步骤、威胁等级、响应时限等字段，单位多为条、次、小时、等级标识。服务主体为SOC分析师、安全运营外包团队及企业安全中心，数据围绕持续告警研判与升级处置流转。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时更新的告警数据要求索引支持增量写入，避免全量重建带来的性能损耗；多源异构数据需适配不同文档结构的字段解析，确保向量嵌入的一致性；日更的周报通报类数据需定期触发索引更新，保障情报时效性；告警ID、威胁等级等结构化字段需与非结构化文本内容结合向量化，提升检索精准度；单次处理的告警数据量较大，需限制索引分片的单节点负载，防止检索超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配告警处置单、值班记录的文本长度，避免单块内容过于分散或冗余 |
| 重叠长度 | 100–200 字符 | 保留跨块的上下文关联，确保告警处置步骤的完整检索 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关的告警数据，减少误报堆积带来的检索干扰 |
| 单次搜索上限 | 前 10 条 | 控制单次检索返回的结果量，适配SOC分析师的快速研判需求 |
| maxToken | 4096 | 适配主流API模型的上下文窗口，避免截断关键的威胁情报内容 |
| defaultToken | 1024 | 为基础查询上下文预留足够的告警相关文本空间 |

## 容易做错的三处
- 现象：混合检索响应时长稳定在10秒以上，首次向量检索耗时约8秒。原因：未根据SOC场景的实时告警数据量调整单次搜索上限与分块参数，导致向量计算与结果聚合的负载超出阈值。
- 现象：建索引流程停留在最后一组数据，进度无更新。原因：未开启增量索引更新，全量重建时因实时涌入的告警数据占用资源，或导入的文件格式未适配系统支持的类型。
- 现象：知识库创建后部分告警处置单的向量结果为空。原因：未配置多源数据的字段映射规则，导致SIEM导出的结构化告警字段未被正确嵌入向量。

## 怎么确认配好了
1. 导入单份告警处置单，执行模拟检索，核对返回结果的相关性是否符合研判需求，调整相似度阈值至匹配预期。
2. 提交实时告警数据的增量更新任务，查看索引进度条是否正常推进，确认无卡顿现象。
3. 调用接口测试向量生成结果，检查告警ID、威胁等级等关键字段是否被正确嵌入，无空值返回。
4. 对比开启与关闭问题优化后的检索结果，确认查询优化功能对告警相关问题的匹配精度有正向影响。
5. 确认当前运行环境为FastGPT v4.17.0，确保配置参数与版本适配。
