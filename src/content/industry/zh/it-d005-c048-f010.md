# 安全监控与SOC值守的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
本品类服务主体为SOC分析师、安全运营外包团队、企业安全中心，日常处理的文档包含告警处置单、值班记录、威胁情报通报、日报周报。核心数据来源为SIEM、EDR、NDR及各类威胁情报源，数据更新节奏分为实时（告警流转）与日更（周报、情报汇总）两类。文档结构包含告警ID、时间戳、处置状态、关联源地址等标准化字段，无额外自定义非标准字段。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据的混合调用要求溯源链路必须覆盖SIEM、EDR等不同数据源的唯一标识，避免溯源混淆。实时更新的告警数据要求引用溯源的响应速度匹配研判时效，不能出现过长延迟。标准化的文档字段要求溯源配置必须绑定固定字段，确保引用的准确性。告警研判的高耗时环节要求溯源配置能够快速定位关联文档，减少无效信息干扰。真实攻击漏报、误报堆积的出错后果要求溯源链路必须完整覆盖全流程处置记录，不可遗漏关键节点。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配告警处置单、威胁情报通报的单篇文档平均长度，避免截断关键溯源标识 |
| `responseData` | 仅返回关联数据源字段 | 对应SIEM、EDR等源的告警ID、时间戳字段，确保溯源精准匹配具体告警事件 |
| `detail` | 开启完整溯源链路 | 关联值班记录、日报周报的关联ID，覆盖从告警发现到派单的全流程研判依据 |
| 单次搜索上限 | 前 5 条匹配结果 | 匹配实时告警的快速研判需求，避免冗余信息干扰分析师判断 |
| 上下文引用触发规则 | 按告警级别触发 | 高优先级告警强制展示溯源信息，低优先级告警可简化配置，按实测标定 |

本文档适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 配置`quoteMaxToken`取值小于600 token，导出的告警处置单文档被截断，引用溯源时缺失关键告警ID，导致无法定位原始告警。
- 导出工作流JSON后未同步绑定数据源映射配置，导入其他环境时，关联的SIEM/EDR插件无法匹配对应数据源，出现插件找不到报错。
- 开启引用显示开关后未配置对话权限，回答末尾显示“没有权限操作此对话记录”，无法正常隐藏或展示引用信息。

## 怎么确认配好了
- 发起一条模拟高优先级告警查询，核对回答末尾是否关联了对应SIEM告警ID与威胁情报源链接。
- 导出当前环境的工作流配置JSON，导入测试环境后，检查关联的数据源插件是否正常加载。
- 调整`quoteMaxToken`至测试区间，验证长文档的引用内容未被截断。
- 关闭引用显示开关，发起对话，确认回答末尾未出现权限报错或无效引用提示。
