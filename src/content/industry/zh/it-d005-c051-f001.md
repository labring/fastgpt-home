# 客户数据导入迁移的技术文档与接口问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据主要来自客户历史业务系统、CSV或Excel模板、数据库导出结果，以及FastGPT产品的导入日志。数据更新节奏为每单或不定期，随客户迁移需求触发。日常配套文档包含数据模板、迁移方案、字段映射表与迁移验证报告。数据字段多为业务相关标识，如客户ID、业务流水号、数据创建时间等，单位涵盖元、件、人次等常规业务单位，需严格匹配新旧系统的字段定义。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据来源多样且格式不统一，要求HTTP接口支持灵活的字段映射配置，适配不同客户的旧系统导出规则。数据更新无固定周期，接口需支持按需触发的批量导入请求，适配单次或阶段性的迁移需求。字段映射的准确性直接影响数据导入效果，接口需传递映射参数以完成新旧字段的对应转换。同时，脏数据清洗与导入后核对环节耗时较长，接口需预留足够的处理时长，避免因超时导致导入中断。数据出错会引发严重业务影响，接口需返回标准化的结果信息，便于外部系统对接后的异常排查。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `Authorization` | `Bearer ${apiKey}` | 符合HTTP接口鉴权通用标准，保障接口访问的安全性 |
| `variables` | `{"field_mapping": [{"old": "旧字段名", "new": "新字段名"}], "clean_dirty": true}` | 匹配字段映射表的配置需求，支持脏数据自动标记与清洗 |
| 单次请求数据量 | `100–500 条` | 避免单次请求超时，适配多数外部系统的单次导出数据上限 |
| 请求超时时间 | `600 秒` | 兼容批量数据导入的清洗、校验与传输时长，覆盖全流程处理 |
| `responseData` | `{"code": 200, "message": "操作状态描述", "import_count": 导入成功条数}` | 统一返回格式，便于外部系统对接后快速解析导入结果 |

## 容易做错的三处
- 调用接口返回405 Method Not Allowed报错。原因是未使用POST请求方式发起数据导入，或接口路径配置与FastGPT系统要求不符。
- 导入后客户数据的业务字段与预期配置错位。原因是未正确配置`variables`中的字段映射参数，或映射关系与线下字段映射表不一致。
- 批量导入时部分数据失败且日志显示格式错误。原因是未开启脏数据校验配置，或未在`variables`中指定对应的脏数据处理规则。

## 怎么确认配好了
- 调用鉴权接口验证`Authorization`参数配置正确，返回有效响应结果。
- 上传小批量测试数据，查看`responseData`返回的导入成功计数与实际提交数据量一致。
- 导出导入后的部分数据，核对字段映射关系与线下配置的字段映射表完全匹配。
- 模拟包含脏数据的提交请求，查看系统是否按配置执行清洗或拦截操作。
