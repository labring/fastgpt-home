# 客户数据导入迁移的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的典型使用主体为实施顾问、数据实施工程师与客户IT接口人，数据通常来自客户历史系统、CSV或Excel模板、数据库导出以及产品导入日志。日常配套文档包含数据模板、迁移方案、字段映射表与迁移验证报告。数据更新频率为每单或不定期，单批次数据量随客户业务规模浮动。字段涵盖客户业务核心字段、导入状态与错误码等，部分字段带有明确单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源多样，包含结构化数据库导出、半结构化表格与非结构化业务文档，要求向量模型需适配不同格式的文本向量化。数据更新无固定周期且单批次处理，索引需支持增量更新以避免全量重建的资源消耗。字段映射关系随客户定制化需求变化，索引需保留原始字段的关联元数据，便于后续导入验证与问题溯源。此外，单批次数据量差异较大，索引分片需具备灵活调整能力以适配不同规模的导入任务。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配客户导入的业务文本长度，避免单块token超出模型输入上限 |
| 重叠长度 | 100–200 字符 | 保留块之间的上下文关联，减少语义断裂对检索精度的影响 |
| 相似度阈值 | 0.65–0.85 | 过滤低匹配度的检索结果，适配导入数据的字段匹配与抽样核对需求 |
| `defaultToken` | 4096 | 适配多数开源向量模型的标准输入token限制，保证基础文本完整向量化 |
| `maxToken` | 8192 | 兼容长文本的导入文档，如完整的迁移方案或字段映射表，避免关键内容被截断 |
| 单次搜索上限 | 前10条 | 控制检索返回量，适配导入数据的抽样核对与问题排查需求 |

本文基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 搜索测试返回报错，如接口返回500状态码或“向量维度不匹配”提示，原因是新接入的embedding模型与索引配置的向量维度未保持一致，未同步更新索引的维度参数。
- 仅能在数据库中查询到向量字段，无法找到向量化对应的原始文档内容，原因是未开启索引的原始文本关联存储配置，仅写入了向量数据。
- 使用bge-m3模型时语义检索得分普遍偏高，如得分均超过0.9，原因是未对导入的脏数据做基础清洗，或分块长度设置过小导致语义碎片过多，放大了相似度计算结果。

## 怎么确认配好了
- 导入1条测试业务数据，执行向量生成任务，查看任务日志确认token使用量未超出`maxToken`配置。
- 执行检索测试，检查返回结果中是否同时包含向量数据与原始导入文本的关联信息。
- 调整相似度阈值，观察检索结果条数的变化是否符合预期匹配逻辑。
- 导入多批次不同格式的测试数据，确认索引可正常完成增量更新，无重复或遗漏数据。
