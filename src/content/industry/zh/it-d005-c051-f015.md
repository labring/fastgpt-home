# 客户数据导入迁移的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的核心数据来源于客户历史业务系统、CSV/Excel模板、数据库导出文件以及产品导入日志。日常产出的文档包括数据迁移模板、字段映射表、迁移执行方案与迁移验证报告。数据更新频率随单定制，无固定周期。数据结构包含结构化业务字段、非标准化的迁移说明文档，以及带有操作痕迹的导入日志，字段需匹配客户原有系统的业务定义，无统一固定单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源多样且结构不统一，要求检索需同时覆盖结构化字段与非结构化文档，避免遗漏迁移方案或字段映射表的关键内容。数据更新无固定周期，要求召回机制可灵活适配单次导入的专属数据集，无法依赖全局定期更新的缓存。字段需匹配客户原有系统定义，要求检索需关联字段映射表的上下文，避免误召回无关字段的内容。导入日志包含操作痕迹，要求检索可过滤无效的脏数据条目，提升结果精度。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 匹配客户导入数据的字段关联精度，避免误召回无关迁移日志或非目标客户的数据 |
| `limit` | `前 8–12 条` | 单批次导入数据量较大，控制检索结果的上下文长度，避免超出模型输入限制 |
| `searchMode` | `vector + fulltext` | 覆盖结构化业务字段与非结构化迁移文档的检索需求，适配多类型数据特征 |
| `usingReRank` | `开启` | 过滤脏数据与低匹配度的导入日志条目，提升检索结果的相关性 |
| `datasetSearchUsingExtensionQuery` | `开启` | 结合字段映射表的上下文优化检索词，确保匹配到正确的业务字段定义 |
| `collectionIds` | `绑定对应客户导入数据集的专属ID` | 隔离不同客户的导入迁移数据，避免跨单召回无关内容 |

## 容易做错的三处
- 现象为工作流中调用知识库工具模块时，返回结果为空或无法关联目标客户的导入数据。原因是未绑定对应客户导入数据集的`collectionIds`，导致检索范围覆盖了无关知识库内容。
- 现象为上传的CSV/Excel迁移模板数据在知识库中丢失部分字段。原因是未开启`datasetSearchUsingExtensionQuery`，未关联字段映射表的上下文，导致系统误过滤非标准格式的字段数据。
- 现象为配置知识库检索后，工具调用模块无法正常触发。原因是未合理设置`limit`参数，检索结果占用全部模型上下文，未预留工具调用的参数空间。

## 怎么确认配好了
- 导入单批次测试数据，执行检索动作，核对返回结果包含对应字段映射表和迁移方案的核心内容。
- 调整`similarity`阈值，验证匹配结果的字段关联精度符合预期，避免过高或过低的阈值导致误召回或漏召回。
- 查看知识库数据集的操作日志，确认上传的表格数据未被过滤或丢失字段。
- 测试工作流中同时调用知识库和工具模块，确认两者的上下文参数配置兼容，无冲突占用。
