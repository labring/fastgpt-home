# 客户权限与组织架构配置的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
通常，该品类的数据来源于客户HR系统、身份目录、产品后台与审计日志，更新节奏为每单或不定期。日常产出的文档包含权限矩阵、组织架构表、角色配置记录、权限变更单，字段多包含部门标识、角色编码、权限范围、生效节点等，无统一的固定格式，部分文档会随客户组织调整频繁更新。

## 这些特征在「文档解析与分块」这一环带来什么约束
在FastGPT v4.17.0版本中，由于数据来源分散且格式不统一，解析环节需兼容多种文档结构，避免误拆分权限关联的字段组合。不定期的更新节奏要求分块逻辑适配增量与全量两种场景，防止重复解析已处理的权限配置。同时，权限类文档的出错会引发越权访问等问题，分块时需保留权限与对应角色、部门的绑定关系，不能破坏数据的业务完整性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 权限类文档字段密集，该区间可保留权限与角色的绑定关系，避免拆分关键关联单元 |
| `chunkSplitter` | 按语义分组分块 | 适配组织架构表的层级结构，确保每个分块包含完整的部门或角色权限配置 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 覆盖大型权限变更单的解析时长，防止因超时中断处理流程 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配大型组织架构导出文件的上传需求，避免因文件过大被拦截 |
| `trainingType` | 增量训练 | 匹配该品类不定期的更新节奏，减少重复解析已处理的权限配置 |
| `customPdfParse` | 开启 | 适配权限矩阵PDF的固定表头格式，准确提取表格内的权限配置字段 |

## 容易做错的三处
- 上传权限相关文档后数据处理为空。原因是未开启`customPdfParse`，导致PDF的表头被误判为内容分隔符，无法提取有效权限配置字段。
- 知识库上传文档后向量化耗时过长。原因是`chunkSize`设置过小，生成的分块数量超出正常范围，增加了向量化计算量。
- 普通提问文本被触发文档解析流程。原因是`trainingType`配置为全量训练，覆盖了所有输入类型，未区分问答请求与文档解析请求。

## 怎么确认配好了
- 上传测试用的权限矩阵PDF，查看数据处理后的字段列表，确认包含部门、角色、权限范围等核心字段。
- 提交超过常规大小的组织架构表文件，确认未触发上传大小限制的报错提示。
- 等待解析完成后查看分块日志，确认每个分块未拆分权限与对应角色的绑定内容，且字符数处于800–1200字符区间内。
- 发起普通文本提问，确认对话流程未触发文档解析的相关日志。
