# 客户权限与组织架构配置的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自客户HR系统、身份目录、产品后台及审计日志。日常生成的文档包括权限矩阵、组织架构表、角色配置记录、权限变更单。数据更新频率为每单或不定期，无固定周期。文档多为结构化格式，包含部门ID、角色名称、权限范围、生效时间等字段，无额外非结构化注释内容，整体数据关联性强，需严格匹配权限边界。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据来源分散且更新无固定周期，检索时需优先保证数据时效性，避免召回已失效的权限配置。结构化的文档格式要求检索模式需适配关键词与语义双重匹配，否则易出现权限条目匹配偏差。多字段的权限数据会增加单次检索的处理复杂度，需限制召回结果数量以控制核对耗时。同时，权限数据的敏感性要求召回结果严格匹配目标角色与部门，避免越权访问风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配权限数据的结构化特征，过滤低相关性的权限条目 |
| `limit` | 前10条 | 控制单次召回的文档数量，减少组织层级核对的耗时 |
| `searchMode` | vector + hybrid | 结合语义与关键词匹配，覆盖权限矩阵、变更单等多类型文档 |
| `usingReRank` | 开启 | 对召回结果按相关性排序，修正结构化数据的检索偏差 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 权限数据多为结构化配置，无需额外扩展查询以减少模型调用 |
| `collectionIds` | 绑定专属权限知识库集合 | 隔离权限配置数据与其他业务文档，避免检索干扰 |
*FastGPT v4.17.0*

## 容易做错的三处
- 现象：知识库检索耗时过长，返回结果延迟明显。原因：未限制`limit`参数取值，召回过多权限相关文档导致组织层级核对环节耗时增加。
- 现象：工作流运行时出现未触发的大模型调用报错日志。原因：误开启`datasetSearchUsingExtensionQuery`，生成额外查询请求触发未配置的模型调用。
- 现象：知识库文档的目录结构被自动删除。原因：未正确绑定专属`collectionIds`，导致系统误将权限配置文档与其他类型文档合并处理。

## 怎么确认配好了
- 查看检索日志，确认单次召回结果条数符合配置的`limit`取值。
- 模拟权限变更场景，验证召回结果仅包含目标部门、角色的相关配置文档。
- 运行工作流，检查是否出现未预期的大模型调用报错日志。
- 上传测试权限配置文档，确认目录结构未被自动修改。
