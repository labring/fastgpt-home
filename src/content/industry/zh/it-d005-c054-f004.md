# 容器平台运维的技术文档与接口问答：向量模型与索引
本页面的配置说明适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据主要来自Kubernetes API、镜像仓库、监控系统与CI流水线，日常覆盖集群变更单、命名空间配额表、部署记录、故障报告四类核心文档。数据更新节奏多为每日同步或随集群变更实时更新，文档结构多包含集群标识、资源配额、异常代码、操作步骤等字段，无统一固定单位，部分字段随集群配置动态变化。

## 这些特征在「向量模型与索引」这一环带来什么约束
多来源的数据格式差异较大，需适配不同数据源的抽取逻辑，例如从Kubernetes API提取的结构化配额数据与从监控系统导出的非结构化日志文本，需采用差异化的分块策略。实时更新的集群变更记录要求支持增量索引，避免全量重索引带来的过长耗时。文档中的技术标识与数值参数较多，向量编码需保留字段间的语义关联，同时需适配不同规模的集群数据量，防止索引资源过载。此外，运维文档的内容多指向具体操作步骤与异常排查，分块时需避免破坏逻辑完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 分块长度 | 800–1200 字符 | 容器运维文档多为技术说明与日志片段，该长度可完整覆盖单条操作步骤或异常描述 |
| 重叠长度 | 100–200 字符 | 避免跨块的技术逻辑被拆分，保障向量检索的上下文完整性 |
| 相似度阈值 | 0.72–0.85 | 适配集群配置的字段匹配精度，过滤低相关的非集群类文档 |
| 单次搜索上限 | 前 10 条 | 容器运维场景的问题多指向特定集群资源，少量高相关结果即可满足排查需求 |
| `maxToken` | 4096 token | 适配主流向量模型的输入长度限制，保障集群文档的完整语义输入 |
| `defaultToken` | 512 token | 作为默认的上下文截断阈值，适配运维问题的短查询场景 |

## 容易做错的三处
- 现象：索引任务持续超过 600 秒仍未完成，界面显示索引中状态无更新。原因：未配置增量索引规则，全量扫描了全量集群变更单与部署记录，导致索引耗时过长。
- 现象：调用multimodal-embedding-v1模型时返回模型未找到报错。原因：未在向量模型配置中添加对应模型的API端点与权限密钥，或模型名称拼写错误。
- 现象：同一文档块配置多个索引维度后，检索结果未按预期优先级返回。原因：未设置不同索引维度的权重规则，导致多个向量索引的匹配结果排序混乱。

## 怎么确认配好了
- 上传一份命名空间配额表的测试文档，查看索引完成耗时是否符合预期。
- 输入集群异常排查相关的问题，核对检索结果的相似度分值是否在预设阈值区间内。
- 在向量模型配置页面添加multimodal-embedding-v1模型，验证模型加载状态显示为已连接。
- 查看开源版本的索引模型配置，确认emb3对应开源的多模态向量模型。
