# 容量规划与资源扩缩容的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自云账单、监控系统、业务预测报告与压测结果，日常产出的文档包括容量规划报告、扩容申请单、资源利用率报表及预算测算表。数据更新节奏多为周度或月度，字段包含资源规格（如CPU核数、存储容量）、利用率数值、预算额度与时间节点等，单位多为核、GB、元与小时。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据更新频率较低，无需高频增量索引，可采用全量索引周期更新的方式。数据来源分散，需兼容多格式文档的向量化处理，且需保留字段间的关联关系。单份文档体量较大，如压测报告、预算测算表，分块时需适配长文本结构。资源类数值字段的语义关联需精准匹配，避免因向量偏差导致的容量判断失误。同时，月度或周度更新的特性允许索引构建时间窗口放宽，无需追求毫秒级响应。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配容量规划报告、压测报告等长文本结构，避免单块内容语义断裂 |
| 重叠长度 | 100–200 字符 | 保留跨分块的上下文关联，避免资源利用率、预算额度等字段的语义割裂 |
| 相似度阈值 | 0.75–0.85 | 精准匹配资源规格、瓶颈描述等核心语义，过滤低相关的历史报表数据 |
| 单次索引上限 | 前 20 条 | 适配周/月度更新的低频特性，平衡索引构建效率与数据完整性 |
| `maxToken` | 4096 token | 适配长文档的向量编码需求，避免长文本截断导致的信息丢失 |
| `defaultToken` | 按实测标定 | 适配不同来源的文档格式，兼容云账单、监控数据的字段结构 |

## 容易做错的三处
- 现象：索引构建过程停留在最后一组文件未完成，界面无进度更新。原因：未适配长文档的分块参数，导致单块内容超出编码上限，触发隐性超时。
- 现象：新建知识库后卡在索引步骤，无法完成向量化流程。原因：未配置对应数据来源的文档格式支持，无法识别云账单、压测报告的特定格式字段。
- 现象：更换embedding模型后可完成索引，但搜索测试返回报错。原因：未同步更新相似度阈值与新模型的语义匹配区间，导致向量相似度计算偏差超出阈值范围。

## 怎么确认配好了
- 查看FastGPT v4.17.0版本的索引构建日志，确认分块后的文本长度符合配置的分块长度区间。
- 测试单份容量规划报告的向量化流程，验证无隐性超时或文本截断报错。
- 更换embedding模型后，重新标定相似度阈值的适配区间。
- 核对索引完成后的文档数量，与待索引的文档清单保持一致。
