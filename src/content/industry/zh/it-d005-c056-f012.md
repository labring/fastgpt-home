# 对象存储与备份服务的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
通常该品类的数据主要来源于对象存储控制台、备份系统、访问日志及客户策略表，日常维护的文档包括存储桶配置、备份策略、恢复记录与生命周期规则。数据更新节奏随策略变更触发，日常更新频率为每日或随策略调整即时生效。数据字段包含存储桶权限、备份时效阈值、恢复成功率、生命周期规则触发条件等，部分字段需结合存储容量、时间周期等维度标注，无统一固定单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的结构化配置文档与非结构化日志混合的特征，要求文档解析需兼顾字段完整性，避免拆分关键策略单元。数据更新节奏随策略变更触发，解析任务需支持增量处理以适配实时更新的备份记录。权限相关字段需在分块时保留上下文，防止权限策略解析断裂。数据量随存储规模扩大而增长，需通过分块控制避免索引过载，同时适配混合格式的访问日志解析需求。

## 配置怎么定
以下配置项适用于FastGPT v4.17.0版本，可根据实际业务场景调整：
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配该品类结构化配置文本的字段长度，避免拆分关键策略单元 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 秒 | 覆盖备份策略、恢复记录等长文档的解析耗时，避免超时报错 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 匹配对象存储单文件上传的常规上限，适配备份日志包的大小 |
| `customPdfParse` | 开启 | 适配存储桶配置导出的PDF格式文档，保留原始排版与字段结构 |
| `chunkSettingMode` | 手动配置 | 针对结构化数据调整分块规则，适配不同类型的策略文档 |
| `chunkSplitter` | 按段落+语义边界 | 避免拆分连续的权限策略或生命周期规则文本 |

## 容易做错的三处
-  解析任务触发超时报错，界面显示“解析超时”相关提示。原因是未针对备份策略、恢复记录等长文档调整`PARSE_FILE_TIMEOUT_SECONDS`设置，沿用默认短超时阈值。
-  检索返回的Excel数据少于源文件预期条数，无法匹配全部筛选条件。原因是分块时拆分了跨字段的关联数据，未保留检索所需的完整上下文关联。
-  上传的PDF文档解析后字段缺失或排版错乱。原因是未开启`customPdfParse`配置，使用默认解析逻辑无法适配存储桶配置导出的PDF格式。

## 怎么确认配好了
-  上传单份存储桶配置PDF文档，检查解析后的文本是否保留完整的权限策略段落，无强制拆分。
-  提交批量备份策略文件解析任务，查看任务耗时是否在预设的`PARSE_FILE_TIMEOUT_SECONDS`范围内，无超时报错。
-  检索配置文档中的权限字段，确认返回结果包含源文件中的全部匹配条目，无遗漏。
-  查看知识库上传记录，确认上传文件大小未超过`UPLOAD_FILE_MAX_SIZE`的限制。
