# 工单受理与问题分级的技术文档与接口问答：HTTP 接口与外部系统
本页内容适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的核心数据来自工单系统、聊天记录、产品日志及客户合同SLA，更新频率为日级或实时。日常维护的文档包括客户工单、问题分级表、处理记录与服务报告，数据字段包含工单ID、客户标识、问题类型、分级等级、SLA响应阈值、处理状态等。数据主体由客服团队、技术支持团队及客户成功团队日常维护，每条数据对应单次客户反馈的全流程处理信息。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于数据来源为多个外部系统，需通过HTTP接口完成数据拉取与同步，因此接口需支持多源对接的身份校验机制。因数据更新频率为日级或实时，接口需适配轮询或webhook两种同步方式，避免数据延迟。数据字段包含工单ID、分级等级等核心标识，接口参数需严格匹配这些字段格式，避免因字段不匹配导致数据拉取失败。同时，因出错后果涉及SLA违约与客户投诉，接口需配置超时控制与重试机制，保障调用稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `Authorization` | `Bearer {FastGPT平台生成的API密钥}` | 对接外部工单系统、产品日志系统时，通过该参数完成身份校验，保障接口访问安全 |
| `variables` | `{"work_order_id": "", "sla_threshold": "24小时"}` | 匹配工单数据的核心字段，将工单ID、SLA要求作为动态变量传入接口，适配不同工单的处理规则 |
| `responseData` | `仅返回分级结果、处理建议、关联工单ID` | 过滤冗余数据，仅保留工单受理与问题分级所需的核心信息，降低数据传输成本 |
| 超时设置 | 600秒 | 匹配SLA的基本响应要求，避免因接口超时触发SLA违约 |
| 重试机制 | 3次重试，间隔10秒 | 应对临时网络波动，减少接口调用失败率，保障工单处理流程不中断 |
| 变量可选配置 | 按业务需求标记 | 适配部分工单的非必填参数，避免因缺失可选参数导致调用失败 |

## 容易做错的三处
- 现象：调用外部数据库接口时返回SQL查询失败的报错，无法获取工单关联数据。原因：未在`variables`参数中正确传递工单ID或筛选条件，导致SQL语句无法匹配到有效数据。
- 现象：使用花生壳等内网穿透地址发起HTTP请求时返回getaddrinfo错误。原因：未在FastGPT所在服务器配置正确的DNS解析，或穿透地址的端口未开放访问权限。
- 现象：自定义工具的变量设置后无法正常调用，平台提示参数缺失。原因：未在`variables`参数中声明变量的可选状态，导致调用时强制要求填写非必要参数。

## 怎么确认配好了
- 发起单次测试调用，查看接口返回的`responseData`是否包含工单分级结果、处理建议等核心字段。
- 模拟触发一次真实工单的接口同步，检查外部系统的日志中是否有成功的调用记录。
- 调整接口的超时时间阈值，验证当接口响应超过设定时长时，系统是否触发预设的重试机制。
- 检查`Authorization`参数的格式是否符合Bearer令牌规范，确认未出现密钥泄露或格式错误的情况。
