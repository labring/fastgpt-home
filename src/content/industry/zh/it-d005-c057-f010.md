# 工单受理与问题分级的技术文档与接口问答：引用来源与溯源

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的核心数据来自工单系统、聊天记录、产品日志与客户合同SLA，更新节奏为日更或实时同步。日常产出的文档包括客户工单、问题分级表、处理记录与服务报告，字段包含工单唯一标识、问题类型、分级等级、处理人、关联SLA条款等，无额外自定义统计单位，数据以单次客户反馈或服务事件为最小存储单元。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据的混合接入要求溯源环节需绑定唯一标识区分不同来源的内容，实时更新的特性要求配置同步机制保障引用数据的时效性。以工单为核心的文档结构要求溯源需关联到具体工单ID与处理记录，避免泛化引用。问题复现与影响范围判断的高耗时需求，要求溯源环节可快速定位原始数据，减少人工核查成本。SLA违约的出错后果要求引用内容必须与原始记录完全匹配，禁止伪造关联信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配工单与处理记录的常规引用内容长度，避免截断关键溯源信息 |
| `responseData` | 仅返回关联工单ID、处理记录与SLA条款 | 聚焦该品类核心数据，减少冗余内容干扰溯源判断 |
| `detail` | 完整 | 保留原始数据的完整字段，支持精准溯源到具体处理环节 |
| 单次召回条目上限 | 前5条 | 匹配工单问题分级的信息密度，避免过多无关内容占用上下文 |
| 知识库动态绑定 | 按工单所属客户匹配 | 适配工单数据按客户隔离的存储规则，实现精准调用对应知识库 |
| 引用标记过滤 | 开启 | 移除冗余的标记格式，符合输出规范 |

## 容易做错的三处
- 动态指定知识库时引用变量空白：界面中未在知识库搜索节点配置变量绑定触发规则，导致可选变量列表未加载。
- 日志中无法区分不同来源的引用内容：未开启`responseData`配置的来源标识返回，无法通过日志字段定位原始数据来源。
- 大模型伪造引用ID：未开启`detail`模式下的原始数据关联校验，导致生成的引用ID未匹配实际检索到的工单记录。

## 怎么确认配好了
- 发起一条测试工单，查看大模型返回结果是否关联对应工单ID与处理记录，验证溯源信息准确。
- 查看系统日志，确认每条引用内容都带有唯一来源标识，可快速定位到原始工单或处理记录。
- 在知识库搜索节点中配置变量绑定，验证动态指定知识库的可选变量列表正常加载。
- 生成测试回复，确认输出内容未包含冗余的引用标记格式，仅保留核心引用内容。
