# 工单受理与问题分级的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据来自工单系统、聊天记录、产品日志、客户合同SLA，更新频率为日级或实时。日常文档包含客户工单、问题分级表、处理记录、服务报告，其中工单包含唯一标识、问题描述、关联产品模块、客户反馈时间、分级标签等字段，问题分级表包含优先级、响应时限、责任团队映射等字段，处理记录包含响应时长、解决结果等字段，服务报告包含周期内工单总量、分级分布等统计项。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且更新频率灵活，要求检索系统支持多源数据的跨域召回，同时需适配实时增量更新的索引逻辑，避免因全量索引占用过多资源。工单与分级表的字段结构差异显著，需针对不同文档类型配置差异化的召回规则，防止无关内容干扰问题匹配。SLA相关数据的时效性要求高，检索需优先匹配近实时更新的SLA规则，确保问题分级符合合规要求。客户聊天记录多为非结构化的口语化内容，需优化语义匹配精度，减少模糊匹配带来的误判。工单量随业务波动，检索需支持动态调整召回上限，避免资源过载影响服务响应。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 适配工单问题描述的语义匹配精度，避免召回无关的工单或分级规则 |
| `limit` | 前10条 | 控制单次召回的结果数量，适配客服团队快速浏览的场景 |
| `searchMode` | semantic | 针对非结构化的工单与聊天记录，提升语义匹配的精准度 |
| `usingReRank` | 开启 | 优化召回结果的排序逻辑，优先展示与问题关联度更高的内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于原问题生成扩展查询，覆盖同义词与行业术语，提升召回覆盖度 |

## 容易做错的三处
- 现象：索引任务停滞，界面显示索引进度未更新，未完成的工单数据无法被检索。原因：未配置索引断点续传功能，全量索引过程中断后无法恢复，导致部分数据未完成索引。
- 现象：检索结果中出现重复的工单或分级规则条目。原因：未开启知识库的文件去重校验，相同内容的文档被多次索引，导致重复召回。
- 现象：检索接口返回包含`$schema`字段的格式错误提示。原因：在配置数据集关联时误引入了非标准的元数据字段，违反了FastGPT的接口格式要求。

## 怎么确认配好了
- 上传一份测试工单文档与问题分级表，执行检索测试，核对召回结果是否包含目标内容。
- 查看索引日志，确认增量索引按日或实时频率自动更新，未出现停滞情况。
- 检查检索结果的排序，确认开启重排开关后高相关内容优先展示。
- 对比开启与关闭问题优化开关的检索结果，确认扩展查询提升了召回覆盖度。
