# 性能测试与容量评估的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
本品类的数据主要来自压测平台、APM监控系统、数据库慢日志及生产流量基线。日常产出的文档包括压测方案、容量评估报告、压测数据记录与优化建议单，更新频率为每月或每重大版本迭代时。文档字段包含吞吐率、响应延迟、资源占用率等核心指标，单位多为tps、毫秒、百分比或GB，部分报告附带结构化的瓶颈分析表格与资源配置清单。

## 这些特征在「文档解析与分块」这一环带来什么约束
本品类的数据来源包含结构化表格、时序监控数据与分析文本，不同来源的内容格式差异较大。文档更新频率较低但版本迭代时会批量更新，解析时需保留指标与单位的绑定关系，避免拆分后无法关联核心性能指标。由于文档聚焦瓶颈定位与容量结论，分块需兼顾长文本分析段落与结构化表格的上下文完整性，避免将跨页的瓶颈分析与对应数据拆分至不同块中，影响后续问答的关联准确性。

## 配置怎么定
本文档适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 本品类文档包含长文本分析段落与结构化表格，该区间可兼顾单块信息完整性与检索粒度 |
| `chunkSplitter` | 按段落+标题拆分 | 适配压测方案、评估报告的章节结构，保留分析逻辑的上下文关联 |
| `customPdfParse` | 开启 | 用于解析支持外部资源的PDF格式压测报告，避免默认解析丢失图像链接与表格格式 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 大型压测数据记录文件内容较多，需预留足够解析时间 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量压测数据的上传需求，避免因文件过大被拦截 |
| `chunkSettingMode` | 手动配置 | 允许针对不同类型的文档（如方案类、数据类）调整分块参数，适配本品类多格式文档 |

## 容易做错的三处
- 现象：上传包含外部图像链接的压测报告PDF后，解析结果无图像相关内容或提示文件解析失败。原因：未开启`customPdfParse`配置，默认解析引擎无法处理外部图像链接的嵌入内容。
- 现象：本地部署MinerU后，勾选增强PDF解析仍无法调用服务。原因：未将FastGPT的解析端口与MinerU的本地Docker端口对齐，或未在防火墙开放对应端口。
- 现象：开启表格多向量支持后，检索结果未包含完整表格字段信息。原因：未将分块配置适配结构化表格，将表格拆分至多个独立块中，破坏了表格的上下文完整性。

## 怎么确认配好了
- 上传一份标准压测方案PDF，检查解析后的文本是否保留了指标单位与章节标题的关联关系。
- 查看知识库设置中的解析状态日志，确认`customPdfParse`选项已勾选，且解析任务未出现超时报错。
- 上传一份超过500MB的压测数据记录文件，确认上传与解析流程未被中断。
- 测试检索压测报告中的特定瓶颈指标，确认检索结果可关联到对应分块的完整上下文内容。
