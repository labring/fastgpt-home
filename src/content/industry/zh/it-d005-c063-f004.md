# 投放计划搭建的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自广告平台、用户画像库、预算排期表、归因工具，日常文档包含投放计划、定向设置规则、预算分配方案、转化追踪配置项。数据更新节奏多为每日同步或单次活动启动时更新，文档结构以结构化字段组合为主，包含定向人群标签、预算金额、转化事件ID、投放时段等明确字段，非结构化内容占比极低。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的结构化数据特征要求向量索引需保留字段语义关联，不可随意拆分定向标签、预算数值等关联字段。高频更新需求要求索引支持增量同步，避免全量重建带来的性能损耗。明确的字段单位与业务含义，要求向量生成时需保留字段上下文，防止不同单位的数值被混淆匹配，同时需适配`maxToken`参数控制输入长度，避免长文本的预算排期方案被截断。单条数据长度差异较大，短则数十字符的定向规则，长则数千字符的预算排期方案，需适配多长度文本的向量处理逻辑。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本的向量模型与索引模块编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 投放计划类文档多为结构化字段组合，该长度可保留单条业务规则的完整语义，避免拆分破坏关联逻辑 |
| 重叠长度 | 100–200 字符 | 补充跨分块的上下文信息，确保定向设置、预算排期等跨块内容的语义连贯性 |
| maxToken | 8192 | 适配多数开源嵌入模型的最大输入限制，避免文本截断丢失核心业务信息 |
| defaultToken | 按实测标定 | 针对单条数据的剩余token补充填充，确保不同长度的输入文本都能生成完整向量 |
| 相似度阈值 | 0.75–0.85 | 投放计划的匹配需精准对应定向规则、预算参数，该区间可过滤低相关性的历史配置方案 |
| 单次召回上限 | 前 10 条 | 广告投放计划的配置参考通常无需过多历史数据，控制召回量可提升查询效率 |

## 容易做错的三处
- 现象：配置同名向量模型后，原有配置被覆盖，无法同时调用多个同类型嵌入模型。原因：未开启多模型分组配置，系统默认以模型名称作为唯一标识，重复提交同名配置会直接覆盖原有条目。
- 现象：结构化数据分块后，定向标签与预算数值被拆分到不同块中，匹配时出现关联逻辑丢失。原因：分块长度设置过小，未考虑结构化字段的语义绑定关系，强行拆分导致业务上下文断裂。
- 现象：长文本的预算排期方案生成向量时出现截断，无法完整匹配完整配置信息。原因：未调整`maxToken`参数至适配当前模型的最大输入长度，超出限制的文本被直接截断，丢失核心配置信息。

## 怎么确认配好了
- 上传单条投放计划文档，查看分块预览界面，确认结构化字段未被拆分到不同块中。
- 调用向量生成接口，检查返回的向量维度与所选嵌入模型的输出维度一致。
- 执行测试查询，核对召回结果的条数与单次召回上限的设置匹配。
- 提交同名模型配置，查看系统是否提示重复配置风险或支持分组标识。
