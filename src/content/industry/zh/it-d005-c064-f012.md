# 投标文件编制的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
本品类的数据来源为招标公告、招标文件、企业资质库与供应商报价，更新节奏为每单对应一次。日常处理的文档包含投标文件、资格证明、商务偏离表、技术偏离表，整体结构严格遵循招标方指定格式，包含资格响应条款、商务报价项、技术参数项等固定字段，无统一固定单位，具体单位随招标需求动态调整。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于投标文件严格遵循招标方指定格式，文档解析与分块需匹配章节结构，避免跨章节切割导致后续条款响应核对出现断裂。数据更新节奏为每单一次且单量分散，需支持快速批量解析不同格式的招标文件与资质文件。资格证明、商务偏离表等文档包含大量结构化表格与固定字段，解析需保留原格式关联关系，否则会影响资质材料核对的准确性。单份投标项目可能包含多类文档，需自动识别不同文档类型并适配对应的分块规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 投标文件中单条款响应内容通常为数百字符，该区间可完整保留单条响应逻辑，避免切割关键条款 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配投标文件按章节标题划分的结构，保留条款上下文关联 |
| `customPdfParse` | 启用 | 针对投标文件中大量表格与格式化内容，保留原始排版信息，便于后续核对 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配多页招标文件与批量资质文件的上传需求，避免大文件被拦截 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 单份大型投标文件解析需足够时长，避免因超时导致解析失败 |
| `chunkSettingMode` | 手动配置 | 可针对不同类型的投标文档（如资格证明、偏离表）调整分块规则，适配结构化内容 |

## 容易做错的三处
- 解析json格式的资格证明文件时报错，返回格式错误提示。原因是未针对结构化文档开启自定义解析规则，默认分块逻辑无法正确识别json内的嵌套字段。
- 本地部署的FastGPT v4.17.0无法启用文件解析功能。原因是未正确配置解析依赖服务的环境变量，或本地资源不足以支撑解析进程。
- 调用doc2x解析数百页的投标文件时失败，小页数文件可正常解析。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，大文件解析耗时超出默认阈值，触发超时中断。

## 怎么确认配好了
- 上传一份包含章节标题与响应条款的典型投标文件，查看解析后的分块结果，确认每个分块包含完整的单条响应逻辑，无跨章节切割情况。
- 上传符合`UPLOAD_FILE_MAX_SIZE`设置的最大测试文件，确认上传与解析流程可正常完成，无拦截或超时提示。
- 启用`customPdfParse`后，上传包含表格的资格证明文件，确认解析结果保留表格的行列关联关系，无关键内容丢失。
- 调整`chunkSize`参数后，对比不同取值下的分块数量，确认分块长度适配当前处理的文档内容完整性要求。
