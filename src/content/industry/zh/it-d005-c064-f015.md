# 投标文件编制的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源为招标公告、招标文件、企业资质库与供应商报价。数据更新节奏为每单项目更新一次，随投标任务启动同步录入。日常处理的文档包含投标文件、资格证明、商务偏离表、技术偏离表，核心字段涵盖招标方资质要求、响应条款、报价明细、格式规范等，无统一固定单位，随招标要求动态调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征为检索环节带来多重约束。首先，数据随单项目动态更新，要求检索环节支持按需关联最新的招标文件、企业资质与供应商报价，避免调用过期内容。其次，核心文档包含商务偏离表、技术偏离表等结构化响应文件，需精准匹配招标方的条款要求与格式规范，对召回内容的相关性与格式适配性要求更高。另外，数据来源分散，需支持跨多数据源的联合检索，同时需限制召回结果的范围，确保仅返回符合投标资格与响应要求的内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 匹配投标条款的精准度要求，避免召回无关的非响应内容 |
| `limit` | 前10条 | 控制单次召回的结果数量，适配投标文件的单页响应篇幅 |
| `searchMode` | 全文检索 | 覆盖偏离表、资质项等多类文本的匹配需求 |
| `usingReRank` | 开启 | 提升高相关内容的排序优先级，确保核心响应条款优先返回 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展检索范围，覆盖招标公告中的隐含格式与条款要求 |
| `collectionIds` | 按单项目绑定对应数据集 | 确保仅调用当前投标任务的专属数据，避免跨项目内容干扰 |

## 容易做错的三处
- 现象：工作流场景下的知识库检索结果总字符数不足3000，或召回条数远低于预期。原因：混淆了独立知识库搜索与工作流内知识库搜索的配置上限参数，未按当前投标任务调整对应设置。
- 现象：检索结果中出现与当前招标项目无关的历史资质或报价数据。原因：未绑定当前投标任务专属的数据集ID，调用了全量公共数据集，导致跨项目内容混入。
- 现象：检索返回的内容未匹配招标方的条款响应要求，包含大量非针对性的通用文档片段。原因：未开启重排功能，或相似度阈值设置过低，导致低相关内容被优先召回。

## 怎么确认配好了
- 进入对应工作流或知识库配置页面，查看`limit`参数的设置值，确认与单项目投标任务的响应篇幅匹配。
- 输入一条招标条款的关键词，执行检索，核对返回结果的条数与相似度符合预设配置。
- 检查绑定的`collectionIds`，确认仅包含当前投标任务的招标文件、资质库等专属数据集。
- 开启`usingReRank`功能后，再次检索，确认高相关的响应条款内容排在结果前列。
