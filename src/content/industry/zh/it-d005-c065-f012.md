# 接口联调与数据对接的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
该品类的数据主要来自客户系统接口、API文档、测试数据与联调日志，更新频率多为每日或每项目阶段。日常处理的文档包含接口清单、联调记录、字段映射表、问题跟踪表，多为结构化或半结构化格式，包含接口地址、请求方法、参数名、返回码、业务含义等字段，部分文档带有时序性的调用记录与异常信息，数据结构随项目阶段动态调整。

## 这些特征在「文档解析与分块」这一环带来什么约束
品类数据的结构化特性要求分块需保留字段间的关联关系，避免拆分跨关联的字段映射内容；时序性的联调日志则需要保留调用链路的上下文，确保检索时能还原完整的调用流程。高频更新的数据需要分块支持快速增量解析，避免全量重解析带来的耗时问题；同时多类型文档混合处理时，需适配不同文档的结构特征，比如表格类文档需保留行列关联，日志类文档需保留时序顺序。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 接口清单与字段映射表的单条记录长度适中，避免拆分跨关联字段，同时保证检索时的上下文完整性 |
| `chunkSplitter` | 按结构化数据拆分 | 品类数据多为表格、JSON格式的结构化内容，保留字段与行的关联关系，避免割裂业务逻辑 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 联调日志可能包含多阶段的时序数据，解析时需足够的处理时间，避免中途超时中断 |
| `chunkSettingMode` | 手动模式 | 需针对接口清单、联调日志、字段映射表等不同文档类型，单独调整分块规则，适配各文档的业务特征 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 部分联调日志与测试数据的文件体积较大，需允许上传符合业务规模的文档 |

## 容易做错的三处
- 现象：导入Excel格式的字段映射表后，检索时无法匹配到完整的字段对应关系。原因：分块时拆分了跨单元格的关联字段，导致映射关系被割裂，无法在检索时关联完整的业务逻辑。
- 现象：知识库中显示的表格内容，在问答输出时缺失部分行或列。原因：分块时未保留表格的整体结构上下文，仅拆分单个单元格内容，丢失了表格的行列关联信息。
- 现象：使用本地向量模型完成分块后上传到服务器，检索结果为空或与预期不符。原因：不同向量模型的分块逻辑与嵌入规则存在差异，导致分块后的文本无法被服务器端的索引系统正确识别。

## 怎么确认配好了
- 上传单份接口清单文档，检查分块结果是否保留了单条接口的完整请求参数、返回码与业务含义，未出现拆分跨字段的情况。
- 导入Excel格式的字段映射表，发起包含字段对应关系的检索请求，验证返回结果包含完整的关联信息。
- 上传一份包含多阶段调用的联调日志，确认分块结果保留了时序调用的上下文，检索时能还原完整的调用链路。
- 在FastGPT v4.17.0版本中，调整`chunkSize`参数后重新解析文档，检查分块长度符合预设的800–1200字符范围。
