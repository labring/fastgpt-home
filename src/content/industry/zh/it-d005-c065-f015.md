# 接口联调与数据对接的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自客户系统接口、公开API文档、联调测试数据与问题跟踪日志。日常产出的文档包括接口清单、联调记录、字段映射表、问题跟踪表，数据更新频率为每日或按项目阶段更新。字段包含接口地址、请求参数、返回字段、错误码定义、字段映射规则等，部分数据包含单位信息，如接口响应超时阈值、数据传输字节数。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据来源包含实时接口数据与静态文档，检索需同时适配结构化接口参数与非结构化文档内容，避免召回结果割裂。字段映射与口径确认的高频需求，要求检索召回需支持字段级精准匹配，减少模糊匹配带来的歧义。每日或按阶段的更新频率，要求知识库召回能够快速同步最新的联调记录与接口变更，避免使用过时数据。单次联调涉及的接口数量较多，单次召回的结果条数需控制在合理范围，避免上下文过载影响排查效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配接口字段与联调记录的精准度，区间覆盖常见的口径匹配需求，按实测标定 |
| `limit` | `前 8–12 条` | 接口联调涉及的接口数量较多，控制召回条数避免上下文过载，适配联调排查的信息密度 |
| `searchMode` | `vector + fulltext` | 兼顾结构化接口参数的向量匹配与非结构化文档的全文检索，覆盖接口清单、联调日志等多类型数据 |
| `usingReRank` | `开启` | 接口相关问题需精准匹配错误码、字段名，重排可提升高相关结果的排序优先级 |
| `datasetSearchUsingExtensionQuery` | `开启` | 自动扩展用户的联调问题，补充接口名、错误码等关键词，提升召回覆盖度 |
| `collectionIds` | `按项目绑定专属集合` | 隔离不同客户的联调数据，避免跨项目的无关结果干扰 |

## 容易做错的三处
- 现象：调用配置的LLM后返回结果与知识库内容无关。原因：未开启`datasetSearchUsingExtensionQuery`，或`searchMode`配置错误，导致未正确关联联调相关的知识库数据。
- 现象：随着知识库内容增加，问答响应耗时变长且token消耗增加。原因：未限制`limit`的取值范围，召回过多冗余的接口文档与联调日志，导致上下文长度超标。
- 现象：测试模型配置提示错误，但引用知识库后可运行。原因：`similarity`的取值区间不合理，导致模型校验不通过，但实际检索逻辑未受影响。

## 怎么确认配好了
- 上传一份测试用的接口清单文档，发起包含接口名的查询，核对召回结果包含该文档的相关片段。
- 调整`limit`的取值，观察单次召回的结果条数是否符合配置的区间范围。
- 切换不同的项目集合，确认召回结果仅包含当前绑定集合内的联调数据。
- 核对FastGPT v4.17.0的版本信息，确认配置项与当前版本兼容。
- 上传单份体积为120MB的测试文档，确认系统支持正常导入或给出合理提示。
