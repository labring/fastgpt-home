# 搜索广告关键词管理的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
通常该品类的核心数据来自搜索广告后台、搜索词报告、竞价排名数据与落地页数据，更新频率为日或周。日常使用的文档以结构化表格为主，包括关键词清单、否词表、出价记录、搜索词报告，字段包含关键词文本、匹配类型、单次出价、点击量、转化数等，单位涵盖元/次、次、个等基础单位，部分文档存在合并单元格、空行等格式细节。

## 这些特征在「文档解析与分块」这一环带来什么约束
结构化表格为主的文档结构要求解析环节需保留行列关联，避免拆分关键词与对应出价、匹配规则等关联字段；日/周级别的更新频率带来批量上传需求，需适配多文档同时解析的耗时要求；字段包含文本与数值混合类型，分块时需保证同组数据的完整性，防止跨块丢失关联关系；部分原始文档存在格式不统一的情况，需兼容合并单元格、空行等非标准格式的解析。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 该品类文档多为关联紧密的结构化表格，单块需包含完整的关键词组与对应出价、匹配类型等字段，避免拆分关联数据 |
| `chunkSplitter` | 按表格行组拆分 | 结构化表格数据需保留每行关键词与对应字段的绑定关系，避免跨行拆分导致数据关联断裂 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300–600 秒` | 批量上传日/周级别的搜索词报告等文档时，需预留足够的解析时间以避免任务中断 |
| `chunkSettingMode` | 手动配置 | 该品类文档字段固定且关联逻辑明确，自定义分块规则可更好适配业务数据特征 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 适配批量上传多份周度搜索词报告等大体积表格文档的需求，满足批量处理的容量要求 |

## 容易做错的三处
- 上传飞书在线表格生成的知识库后，导出的dataset.csv仅包含模板格式，无实际关键词数据。原因是解析时未正确识别在线表格的嵌套单元格结构，导致字段映射失败。
- 分块后出现大量仅包含单个关键词的小块，无对应出价或匹配类型信息。原因是未设置按表格行组拆分的分块规则，误将通用文本拆分逻辑应用于结构化表格数据。
- 批量上传多份周度搜索词报告时，解析任务频繁超时。原因是未调高`PARSE_FILE_TIMEOUT_SECONDS`参数，未适配批量大体积文档的解析耗时。

## 怎么确认配好了
- 上传单份包含100行关键词的表格文档，检查解析后的分块结果，确认每个分块包含至少1组完整的关键词与对应出价、匹配类型字段。
- 查看解析任务日志，确认未出现超时报错，且任务耗时符合`PARSE_FILE_TIMEOUT_SECONDS`参数设置的区间。
- 导出知识库的分块数据集，确认所有字段均已完整填充，无空字段或模板占位内容。
- 上传多份周度批量文档，检查批量解析的成功率，确认未出现批量任务中断的情况。
