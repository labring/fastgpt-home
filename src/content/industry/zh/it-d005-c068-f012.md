# 数据库云服务运维的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
该品类的数据主要来自云数据库控制台、慢日志、监控指标与工单系统。日常处理的文档包括实例变更单、备份恢复记录、性能诊断报告与参数调整记录。数据更新频率为每日或每完成一次变更操作。文档包含结构化字段与非结构化文本，结构化字段如实例ID、变更时间、备份路径，非结构化内容如慢SQL语句、性能分析描述，部分字段带有特定单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档结构差异显著，既有结构化的参数调整记录，也有非结构化的慢日志文本，要求分块规则需兼顾字段关联与上下文完整性。数据更新频率较高，解析环节需支持批量快速处理，避免影响运维响应速度。文档来源包含多租户的控制台与工单数据，分块时需避免跨租户信息的拼接，保障数据隔离性。大尺寸归档日志与PDF格式的诊断报告占比高，解析环节需适配大文件与复杂排版的内容提取，同时保留字段与文本的对应关系。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 该品类文档包含长短不一的慢SQL语句与参数调整内容，该区间可平衡上下文完整性与分块检索效率 |
| `chunkSplitter` | 按段落+标题 | 该品类文档带有明确的标题层级，如实例变更单的变更项、备份步骤，按段落+标题拆分可保留业务上下文关联 |
| `customPdfParse` | 开启 | 该品类的备份恢复记录、性能诊断报告多为PDF格式，开启自定义解析可提取表单字段与代码块内容 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 该品类单次上传的慢日志归档文件尺寸跨度较大，该上限可覆盖常规归档文件的存储与解析需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大尺寸PDF或结构化日志解析需要较长处理时间，该时长可避免常规文件解析出现超时中断 |
| `chunkSettingMode` | 手动配置 | 该品类文档结构差异明显，手动配置可适配不同文档类型的分块规则 |

## 容易做错的三处
- 现象：上传大尺寸PDF或日志归档文件时，上传进度到90%左右出现“偏移量超出范围”报错。原因：未调整`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`配置，文件解析超时或超出上传上限。
- 现象：通过API上传与平台直接上传的文件分块结果不一致。原因：未统一`chunkSettingMode`与`chunkSplitter`配置，两种上传路径的默认分块规则存在差异。
- 现象：直接分块识别PDF中的慢SQL语句或参数调整记录失败。原因：未开启`customPdfParse`，默认PDF解析未提取结构化表单与代码块内容。

## 怎么确认配好了
- 查看知识库上传配置页面，确认`chunkSize`、`chunkSplitter`等参数的取值与预设配置一致。
- 上传单份1000 MB以内的归档日志文件，确认上传进度无中断且无偏移量报错。
- 上传一份包含实例变更单与慢SQL的混合文档，检查分块结果是否保留了标题与对应内容的上下文关联。
- 调用创建文件集合API上传测试文件，对比平台直接上传的分块结果，确认两者分块规则一致。
