# 数据库运维的技术文档与接口问答：文档解析与分块

本文基于FastGPT v4.17.0版本的配置逻辑编写。

## 这个品类的数据长什么样
通常服务于DBA、数据平台运维、后端团队，日常处理的文档包含数据库变更单、慢SQL报告、备份记录、权限申请单。数据来源多为数据库监控、审计日志、SQL执行计划、工单系统，更新频率为每日或单次变更触发。文档结构混杂结构化表格与自由文本，包含实例标识、操作时间、执行耗时、权限范围等字段，单位涵盖毫秒、条、GB等，部分文档涉及敏感权限相关内容。

## 这些特征在「文档解析与分块」这一环带来什么约束
因文档包含结构化表格与自由文本混合的格式，解析与分块需同时适配表格内容提取与上下文保留逻辑，避免拆分后丢失单条慢SQL、单次变更的完整关联信息，影响慢查询定位与变更审核效率。因更新频率为日或单次变更触发，分块流程需支持按文件更新时间增量处理，减少重复解析开销。因文档关联数据库实例、操作类型等精准字段，分块需保留相邻文档块的上下文关联，确保检索时可完整匹配对应运维场景的上下文，避免出现权限申请单与对应实例的关联断裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配数据库变更单、慢SQL报告的文本长度，保留单条操作或慢查询的完整上下文 |
| `chunkSplitter` | 按段落+表格行拆分 | 匹配日常运维文档的结构化与自由文本混合格式，避免拆分后丢失表格关联 |
| `customPdfParse` | 启用 | 针对上传的PDF格式变更单、备份记录，启用自定义解析规则提取结构化字段 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量导入的备份记录、审计日志文件大小，满足日常运维文档的批量上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 匹配大体积备份记录的解析耗时，避免因超时导致解析失败 |
| `chunkSettingMode` | 手动配置 | 针对不同类型的运维文档（如慢SQL报告、权限申请单）调整分块参数，适配细分场景需求 |

## 容易做错的三处
- 现象：上传的音视频文件解析失败，返回不支持的文件类型提示。原因：未配置对应媒体解析插件，当前默认解析规则仅支持文本类文档。
- 现象：上传的PDF文档解析后仅提取到纯文本，丢失表格数据。原因：未启用`customPdfParse`配置，默认解析逻辑未适配运维文档中的结构化表格格式。
- 现象：主动推送的文件未出现在知识库检索结果中。原因：未完成分块切片流程，或`chunkSize`设置过大导致检索召回阈值不匹配。

## 怎么确认配好了
- 上传一份数据库变更单PDF，检查解析后的文本是否包含变更时间、实例ID等核心字段，验证`customPdfParse`配置生效。
- 上传一份100MB左右的备份记录文件，等待解析完成后查看任务状态，确认`PARSE_FILE_TIMEOUT_SECONDS`设置足够覆盖解析耗时。
- 发起针对慢SQL报告的检索，查看返回的文档块是否包含完整的执行时长、扫描行数等上下文信息，验证`chunkSize`与`chunkSplitter`配置合理。
- 测试通过外部系统推送一份权限申请单，确认推送后可在知识库中检索到对应内容，验证主动推送流程的分块配置生效。
