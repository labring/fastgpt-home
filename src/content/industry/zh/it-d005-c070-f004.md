# 数据清洗与质检的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
本品类处理的数据来自原始数据集、ETL日志、标注平台及抽样结果，更新频率为每日或每批任务批次。日常产出的文档包含清洗规则、质检抽样表、异常数据清单与交付报告，数据字段涵盖数据条目标识、异常类型、处理状态、抽样比例、交付时间等，单位包含数据条数、时间戳、百分比等，单条数据内容跨度从短文本规则到长文本的异常记录清单。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散导致单批次数据量波动较大，需适配不同规模的向量索引加载与更新。较高的更新频率要求索引支持增量更新，避免全量重建带来的额外耗时。文档类型多样，从短文本的清洗规则到长文本的异常清单，需兼容不同长度的文本分块配置。异常数据占比不定，向量召回需支持灵活的阈值调整，以覆盖不同质量层级的数据。同时，数据交付需严格匹配质检结果，索引关联的元数据需完整保留异常标识、处理状态等字段，避免关联信息丢失影响后续质检流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配清洗规则、异常清单等不同长度的文本，平衡向量表征精度与索引存储效率 |
| 重叠长度 | 50–100 字符 | 避免分块截断关键的异常标识、规则逻辑等内容，提升召回完整性 |
| `defaultToken` | 按实测标定 | 适配本品类数据的token消耗特征，支撑应用维度的token用量统计需求 |
| `maxToken` | 16000 token | 覆盖单批次质检报告、完整异常清单的上下文长度，满足接口问答时的内容调用需求 |
| 单次搜索上限 | 前 20 条 | 覆盖不同占比的异常数据，确保召回结果可支撑抽样质检的核对需求 |
| 重排开关 | 开启 | 针对多类型文档的召回结果排序优化，提升异常数据、清洗规则的匹配精度 |

本配置基于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：应用维度token统计结果为空或偏差较大。原因：未基于本品类的分块配置正确统计token用量，未关联原始数据集、ETL日志等数据源的元数据。
- 现象：向量索引部署失败，提示存储资源不足。原因：未根据单批次数据量调整分块长度与索引分片配置，导致单索引大小超出预设阈值。
- 现象：向量库部署时出现数据库依赖相关报错无法启动。原因：未使用适配本品类数据规模的官方配置文件，错误引用了包含额外依赖的模板。

## 怎么确认配好了
- 执行单批次数据的向量生成任务，核对生成的向量数量与原始数据条目数一致。
- 调用接口查询清洗规则或异常数据相关内容，确认返回结果包含匹配的文本与关联的元数据字段。
- 查看索引监控面板，确认索引更新频率与数据更新节奏匹配，无频繁全量重建的情况。
- 测试异常数据的召回结果，确认可按异常类型、处理状态等维度进行过滤查询。
