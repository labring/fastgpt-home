# 数据清洗与质检的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来源包括原始数据集、ETL运行日志、标注平台产出结果、抽样质检结果。数据更新节奏为每日或每批任务完成后更新。日常产出的文档包含清洗规则配置文件、质检抽样统计表、异常数据清单、最终交付质量报告。数据字段涵盖数据标识、异常类型、处理状态、抽样比例、质检结论等，无统一固定单位，随具体数据类型调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
原始数据集和ETL日志的批量更新特性，要求溯源环节支持按批次关联多来源数据，避免溯源信息碎片化。清洗规则文档的版本化属性，要求溯源需绑定对应规则版本的引用标识，确保溯源可追溯到具体的清洗配置。异常数据清单和交付报告的结构化输出要求，要求溯源返回的来源需匹配字段层级，便于后续质检复盘。每日或每批的更新节奏，要求溯源的时间戳与数据更新周期对齐，避免引用过期的清洗或质检结果。标注平台的多源标注结果，要求溯源能区分不同标注环节的来源标识，确保质检溯源的准确性。

## 配置怎么定
本配置说明适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 数据清洗与质检的来源文档多为结构化字段，该区间可覆盖完整引用内容且不超出上下文限制 |
| 引用来源上限 | 前10条 | 数据清洗与质检的单批数据来源多为有限批次，该上限可覆盖主要处理环节的来源 |
| `detail` | 开启完整溯源 | 异常数据清单、交付报告需展示具体处理节点，完整溯源可返回对应环节的日志与结果 |
| `responseData` | 包含来源ID、更新时间、处理环节 | 该品类需关联数据来源、质检环节等信息，确保溯源可追溯完整处理链路 |
| 时间戳对齐规则 | 匹配日/每批更新周期 | 按数据实际更新节奏对齐，避免引用过期的清洗或质检结果 |

## 容易做错的三处
- 现象：调用接口返回的引用来源条数不足设定上限。原因：未正确配置引用来源上限的取值，或`quoteMaxToken`参数的取值未适配单条来源的内容长度。
- 现象：接口返回的溯源信息中无下载链接或下载失败。原因：未开启`detail`配置项，或来源数据的存储路径未正确关联到FastGPT的知识库索引。
- 现象：导出的溯源数据粒度无法匹配单条清洗规则或抽样批次。原因：误将知识库维度作为唯一导出粒度，未按数据更新周期配置溯源的关联维度。

## 怎么确认配好了
- 调用FastGPT的问答接口，检查返回结果中是否包含溯源相关的字段信息。
- 调整引用来源上限的配置值，验证接口返回的引用条数是否匹配设定值。
- 导出溯源数据，核对导出粒度是否可按清洗规则、抽样批次等维度拆分。
- 测试过期数据的引用，确认返回的溯源信息中包含正确的更新时间戳。
