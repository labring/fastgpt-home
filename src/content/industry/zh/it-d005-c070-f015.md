# 数据清洗与质检的技术文档与接口问答：知识库检索与召回

以下配置项适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的数据来源包括原始数据集、ETL日志、标注平台输出及抽样结果，更新频率为每日或每批任务完成后。日常产出的文档包含清洗规则、质检抽样表、异常数据清单与交付报告，文档字段多包含数据标识、异常类型、处理规则、抽样比例与交付状态等，无统一强制单位，部分字段需匹配原始数据集的字段定义。

## 这些特征在「知识库检索与召回」这一环带来什么约束
原始数据集的规模与ETL日志的时序性，要求检索需支持按数据批次或时间范围过滤召回结果；清洗规则、异常清单等文档的更新频率较高，需保证检索索引的定时刷新或实时同步机制；质检抽样表与交付报告的字段多关联原始数据标识，检索时需兼顾精确字段匹配与语义关联；重复数据识别与异常值处理的高耗时环节，要求检索召回的结果需精准覆盖高频查询的规则与异常类型，避免无效召回拖慢整体流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配清洗规则、异常数据这类专业术语的语义相似度，避免召回无关的抽样表内容 |
| `limit` | 前8–12条 | 覆盖重复数据识别、异常值处理的高频查询场景，同时控制单轮检索的上下文长度 |
| `searchMode` | 语义检索+全文检索混合模式 | 兼顾专业术语的语义匹配与字段标识的精确匹配，适配文档内的多类型查询需求 |
| `usingReRank` | 开启 | 对召回结果按相关性排序，优先返回最匹配的清洗规则与异常处理方案 |
| `datasetSearchUsingExtensionQuery` | 开启 | 优化查询词的语义扩展，适配数据工程师常用的专业术语缩写或行业黑话 |
| `collectionIds` | 按业务场景指定对应知识库集合 | 隔离不同批次的数据集与质检文档，避免跨业务的无效召回 |

## 容易做错的三处
- 工作台指定查询已存在的文档却返回无结果，原因是未将目标文档加入当前配置的`collectionIds`集合，或`similarity`阈值设置过高过滤了匹配结果。
- 语义检索工具返回“Connection error”，原因是FastGPT与向量数据库的连接配置有误，或向量数据库服务未正常启动。
- 知识库查询超出预设上限，原因是未按业务批次拆分知识库集合，导致单集合存储的数据量超出系统默认限制。

## 怎么确认配好了
- 上传一份测试用的清洗规则文档，在工作台输入该文档的核心规则关键词，确认检索结果包含该文档。
- 查看向量数据库的连接日志，确认无频繁的连接超时或错误日志。
- 调整`similarity`阈值，验证召回结果的相关性随阈值变化符合预期。
- 检查知识库集合的配置，确认当前查询的文档已被正确关联到`collectionIds`指定的集合中。
