# 文档站维护的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据通常来自代码仓库、文档站构建日志、用户反馈与版本发布记录，更新节奏为每周或每版本发布一次。日常维护的文档包含安装指南、API接口文档、迁移手册与常见问题，数据字段包含版本标识、接口参数、操作步骤与错误排查说明。数据由技术写作者、维护者或开发者关系团队整理，内容偏向长期可查的使用说明，无固定强制格式但需匹配当前软件版本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据按周或每版本更新，要求知识库支持增量同步与过期内容自动过滤，避免返回过时的安装或接口说明。多源数据包含代码仓库的注释、构建日志与用户反馈，需支持对非结构化文本的清洗，过滤无效日志与冗余反馈。文档类型涵盖结构化API文档、问答对与步骤类指南，检索需适配不同文本结构，对接口路径做精准匹配，对步骤类内容做语义召回。长期可查的属性要求召回结果需关联当前软件版本，避免跨版本内容混淆。

## 配置怎么定
本文配置基于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配技术文档的精准检索需求，过滤低相关的冗余内容 |
| `limit` | 前 8–12 条 | 控制单次召回的结果数量，避免上下文过长影响后续生成 |
| `searchMode` | semantic | 针对技术文档的语义结构，优先匹配语义关联的专业内容 |
| `usingReRank` | 开启 | 对召回结果做二次排序，提升API文档与迁移指南的排序准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题生成扩展查询，覆盖技术文档中的同义词与参数别名 |
| `collectionIds` | 按文档站关联的知识库集合填写 | 限定检索范围，避免混入其他品类的文档数据 |

## 容易做错的三处
- 现象：检索时返回`invalid configuration parameter name "hnsw.max_scan_tuple"`报错。原因：错误使用了非平台指定的配置项名称，未遵循FastGPT的官方配置规范。
- 现象：单次知识库检索耗时超过3–5秒，页面加载出现卡顿。原因：未设置合理的`limit`取值，召回了过多冗余的文档片段，导致后续重排与拼接步骤耗时增加。
- 现象：检索扫描版PDF转换后的文档时，召回结果语义不匹配，无法提取图片中的技术内容。原因：未对扫描版文本做OCR后的清洗处理，保留了大量排版冗余字符，导致语义嵌入效果不佳。

## 怎么确认配好了
- 提交一条已知存在的技术文档关键词，检查返回结果的匹配度是否符合业务预期。
- 查看检索日志，确认仅召回了文档站关联的知识库集合内的内容，未混入其他来源的数据。
- 提交多个连续的技术问题，检查是否能生成对应的扩展查询并返回匹配的文档片段。
- 模拟检索请求，确认单次检索耗时符合业务侧的性能要求。
