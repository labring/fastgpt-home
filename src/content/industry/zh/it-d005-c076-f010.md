# 日志平台与可观测性的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自日志系统、Trace平台、Metrics系统与应用SDK。日常维护的文档包括日志采集规范、链路追踪说明、指标字典与看板配置记录。数据更新频率通常为每日或随版本迭代。字段包含时间戳、日志级别、链路ID、指标数值与对应单位，例如延迟以毫秒为单位，日志存储容量以GB为标识。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散导致需整合多系统的上下文信息，溯源时需关联不同平台的链路ID以保证上下文完整。较高的更新频率意味着需定期刷新索引，确保引用内容与当前系统状态一致。文档结构分层且内容专业，需精准匹配对应文档的章节范围，避免跨类引用导致信息混乱。字段包含特定标识如链路ID，需在溯源时提取该字段作为关联依据，否则无法准确定位原始日志或指标记录。日志与指标的单位差异可能导致引用混淆，需在溯源时统一单位标注，避免数据解读偏差。

## 配置怎么定
本配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.7–0.9 | 过滤低相关的日志与指标数据，避免冗余引用 |
| 单次召回条数 | 前3–5条 | 控制上下文总长度，符合`quoteMaxToken`的限制 |
| 最大上下文长度 | 800–1200 字符 | 适配单条日志与指标数据的常规长度，避免超出模型输入上限 |
| 响应数据包含范围 | 原始日志片段+链路ID | 保证溯源时可直接关联Trace平台的完整链路信息 |
| 详情召回开关 | 开启 | 补充指标字典与看板配置的细节内容，提升溯源准确性 |
| `detail`参数开关 | 开启 | 启用详细的溯源信息展示，包含数据来源与采集时间 |

## 容易做错的三处
- 现象：将知识库最低相关度设置为0.1后，回答中仍返回大量无关的日志片段与指标记录。原因：未正确配置相似度阈值，或单次召回条数设置过高，未过滤低匹配度内容。
- 现象：调用接口时返回`responseData`为空的报错。原因：未开启响应数据包含范围的对应配置，或参数取值超出系统支持范围。
- 现象：溯源时无法关联到原始链路ID对应的完整日志。原因：未在配置中开启链路ID的提取与关联逻辑，或日志采集时未正确标注链路ID字段。

## 怎么确认配好了
- 输入一条已知的日志关键词，查看回答中引用的内容是否包含该关键词的原始片段。
- 检查回答末尾的溯源信息，确认是否标注了数据来源为日志系统、Trace平台或Metrics系统。
- 调整相似度阈值，观察回答中引用的条目数量是否随之变化，验证阈值配置生效。
- 测试调用接口，确认`detail`参数返回了预期的溯源详情，包括数据采集时间与来源标识。
