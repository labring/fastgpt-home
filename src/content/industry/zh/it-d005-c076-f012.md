# 日志平台与可观测性的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
数据来源包括日志系统、链路追踪（Trace）平台、Metrics指标系统与应用SDK。日常处理的文档包含日志采集规范、链路追踪说明、指标字典、看板配置记录等，更新频率为每日或每版本。数据结构涵盖结构化字段（如日志级别、TraceID、指标名称、时间戳、单位）与非结构化说明文本，部分文档为表格化的看板配置或JSON格式的采集规则。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「文档解析与分块」这一环带来什么约束
日志平台与可观测性的文档包含长文本说明、结构化表格与JSON格式的配置规则，大文件（如10万中文字的word文档、15000行的excel配置表）较为常见。频繁的版本更新要求解析分块能快速响应文档变更，而结构化字段与非文本内容的混合，要求分块不能破坏链路追踪的上下文关联，同时需适配向量模型的长度限制。此外，不同文档类型（采集规范、指标字典）的结构差异较大，通用分块逻辑可能丢失关键的字段关联信息，需要针对性的配置调整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配多数主流向量模型的上下文窗口限制，同时保留日志链路追踪的完整上下文关联 |
| `chunkSplitter` | 按段落+语义分割 | 适配日志文档中结构化说明与流程文本混合的特征，避免拆分破坏字段关联 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配10万中文字word文档、15000行excel配置表等大文件的上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 为大文件的格式转换与分块处理提供充足的执行时间，避免解析超时中断 |
| `chunkSettingMode` | 手动模式 | 适配不同类型的日志文档（采集规范、指标字典、看板配置）的结构差异，灵活调整分块规则 |

## 容易做错的三处
- 上传10M以上的日志配置文件时，出现部分chunk向量化异常，反复点击重试后恢复。原因：未匹配`UPLOAD_FILE_MAX_SIZE`与`chunkSize`的配置，大文件分块时触发临时内存占用过高或超时。
- 从数据库查询的JSON格式日志结果无法直接用于问答，需额外编写代码解析。原因：未开启`customPdfParse`适配结构化JSON格式，默认解析逻辑仅处理非结构化文本内容。
- 知识库分块长度超过向量模型支持上限，生成向量失败。原因：未根据`chunkSize`的配置限制调整分块参数，忽略了长文本指标字典的长度约束。

## 怎么确认配好了
- 上传单份10万中文字的word格式日志采集规范文档，查看解析后的分块数量与单块长度，确认符合`chunkSize`的配置范围。
- 上传15000行的excel格式看板配置记录，验证解析后无字段丢失或格式错乱。
- 提交包含TraceID、日志级别的测试文本，确认分块后保留了完整的上下文关联信息。
- 调整`PARSE_FILE_TIMEOUT_SECONDS`为600秒，上传大文件后确认解析任务无超时报错。
