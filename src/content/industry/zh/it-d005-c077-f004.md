# 机房巡检与环境监控的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来源包括动环监控系统、门禁系统、UPS监控设备与视频巡检设备，日常文档涵盖巡检表、温湿度记录、告警记录与值班日志。数据更新节奏分为实时与日更两类，实时数据来自告警触发与现场巡检提交，日更数据为批量归档的巡检台账。单条数据包含结构化字段与自然语言内容，结构化字段如设备ID、带单位的温湿度数值、告警等级，自然语言内容如巡检描述与值班交接内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据的混合结构要求索引同时适配结构化字段与自然语言文本，需保留单位等关键细节以避免语义匹配偏差。实时更新的告警数据要求支持增量索引，避免全量重建带来的性能损耗。单条数据长度跨度较大，短则告警记录仅数十字符，长则巡检表可达千余字符，需灵活调整分块规则适配不同文本长度。同时，异常告警的快速召回需求要求索引的搜索延迟控制在合理范围，保障值班人员的响应效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 分块长度 | 800–1200 字符 | 适配巡检表、值班日志的常规文本长度，避免语义断裂 |
| 重叠长度 | 100–200 字符 | 保留跨分块的上下文关联，适配时序类的温湿度、告警记录 |
| 相似度阈值 | 0.75–0.85 | 区分正常环境数据与异常告警的语义相似度，降低误召回概率 |
| 单次搜索上限 | 前10条 | 平衡召回覆盖范围与搜索速度，适配实时告警的快速确认需求 |
| `maxToken` | 4096 | 适配主流嵌入模型的输入长度限制，避免截断关键设备信息 |
| `defaultToken` | 按实测标定 | 适配本地部署的PGSQL向量库内存占用，避免索引崩溃 |

## 容易做错的三处
- 向量库搜索时弹出“无可匹配结果”报错，且已在配置文件中添加`text-embedding-ada-002`模型信息。原因是未在FastGPT的向量库关联配置中正确绑定该嵌入模型，或本地部署时未开放模型调用的端口权限。
- 分块长度设置过大，导致全量索引耗时过长，无法适配实时更新的告警记录。原因是未结合机房巡检数据的更新频率调整索引策略。
- 相似度阈值设置过高，导致大量正常温湿度波动数据被误判为异常告警，增加值班人员的确认负担。原因是未结合机房环境的常规波动范围调整阈值参数。

## 怎么确认配好了
- 查看FastGPT v4.17.0版本的向量库索引日志，确认数十万条巡检、告警数据已完成索引且无异常报错。
- 发起模拟搜索，输入包含温湿度单位的关键词，核对返回结果的字段与单位信息是否完整匹配。
- 手动新增一条测试告警记录，确认索引任务自动触发且新数据可被正常召回。
- 检查配置文件，确认`maxToken`与`defaultToken`参数已按本地部署环境完成设置。
