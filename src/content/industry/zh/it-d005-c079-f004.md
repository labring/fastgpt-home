# 架构设计与技术方案的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自历史流量数据、服务拓扑图、容量评估报告、技术评审纪要与业务增长计划。日常产出的文档包含结构化技术方案、可视化架构图、量化容量指标、评审意见记录。数据更新频率为每月一次或重大需求变更时触发，文档通常包含架构版本、依赖服务清单、资源阈值等字段，部分架构图为矢量格式的非结构化内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的文档存在结构复杂、单次内容体量较大、更新频率不均的特征。长文本技术方案与架构图需要适配合理的分块规则，避免单块内容超出向量模型输入限制。非结构化的架构图文本化后需单独调整索引权重，确保核心依赖关系被优先召回。低频更新但单次更新体量较大的特性，要求索引流程支持增量更新与全量重建的灵活切换，避免重复索引冗余内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配FastGPT v4.17.0版本的向量模型输入限制，匹配该品类长文本技术方案的平均段落长度 |
| 重叠长度 | 100–150 字符 | 保障跨分块的上下文连贯性，覆盖技术方案中跨段落的依赖关系 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的非结构化架构图文本，保留核心技术关联内容 |
| 单次搜索上限 | 前 8 条 | 该品类文档的核心关联内容通常集中在少量条目内，避免冗余召回 |
| maxToken | 4000–6000 token | 适配向量模型输入长度限制，容纳分块后的完整上下文 |
| defaultToken | 2000 token | 处理短片段的评审纪要类文档，平衡召回精度与响应速度 |

## 容易做错的三处
- 现象：单个技术方案文件持续处于索引中，无进度更新。排查项：检查分块参数配置是否适配当前文档长度，验证单块内容未超出向量模型输入限制。
- 现象：切换知识库索引时出现60秒超时报错。排查项：验证AIPROXY_API_ENDPOINT是否为AI Proxy服务的根地址，未附加/v1或/chat/completions等路径；验证AIPROXY_API_TOKEN是否与AI Proxy服务端配置一致且非空；检查FastGPT服务端与AI Proxy服务的网络连通性。
- 现象：知识库A存在匹配内容，但问答结果仍优先调用知识库B的内容。排查项：检查知识库优先级配置是否正确；验证索引流程是否按配置加载指定知识库的优先权重。

## 怎么确认配好了
- 检查FastGPT服务端的AI Proxy环境变量配置，确认`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，例如http://aiproxy:3000，不要附加/v1或/chat/completions）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空）已正确设置且非空。
- 手动触发一次小体量的技术方案文档索引，查看索引进度日志，确认分块参数生效，生成的片段数量符合预期。
- 发起针对核心架构依赖的问答请求，验证召回结果的相似度与优先级符合配置要求。
- 查看知识库索引状态面板，确认重建或切换索引的操作可在合理时间内完成，无持续阻塞现象。
