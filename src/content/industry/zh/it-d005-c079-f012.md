# 架构设计与技术方案的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
这个品类的典型使用主体为架构师、技术负责人与平台研发组，日常产出的文档包括技术方案、架构拓扑图、容量评估报告、技术评审纪要。数据来源多为历史业务流量、服务部署拓扑、集群监控指标与中长期业务增长计划。文档更新频率多为每月一次或伴随重大业务需求变更。文档结构通常包含约束条件、方案论证、依赖关系、评审意见等模块，字段多涉及资源用量、响应时长、服务边界等，单位包含CPU核数、存储容量、时间周期等。

## 这些特征在「文档解析与分块」这一环带来什么约束
日常文档的结构化特征要求分块不能破坏章节逻辑与依赖关系，否则会导致后续检索无法匹配完整的方案论证内容。文档来源包含监控指标与拓扑数据，其中包含大量技术缩写与专有术语，分块需保留上下文关联以确保检索准确性。更新频率的不确定性要求解析流程支持增量更新与全量重解析两种模式，避免重复解析全量文档。文档体积差异较大，从数页的评审纪要到数十页的容量评估报告均有覆盖，分块配置需适配不同体积的文档解析需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 架构设计文档多包含结构化段落与技术参数，该长度可保留单条约束条件或方案论证的完整语义 |
| `chunkSplitter` | 按Markdown标题/段落拆分 | 日常文档多为Markdown格式或导出的结构化文档，按标题拆分可保留章节完整性与层级关系 |
| `customPdfParse` | 启用 | 架构图、评审纪要常以PDF格式上传，启用后可保留文本层级与嵌入的图表说明文本 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 包含多份架构图与监控数据的大型文档解析耗时较长，该时长可避免解析任务中途超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 归档类架构文档可能包含多份附件与拓扑图，该上限可覆盖绝大多数业务场景的文档体积需求 |

## 容易做错的三处
- 现象：上传Word或Excel文档后，知识库搜索无匹配结果，界面显示解析错误。原因：未启用`customPdfParse`配置，或未针对Office文档配置正确的分块规则，导致文本被错误截断或丢失关键信息。
- 现象：知识库搜索测试返回结果条数与预期不符，仅返回部分零散内容。原因：`chunkSize`取值过小，导致完整的约束条件或方案论证被拆分到多个分块中，检索时无法匹配完整语义。
- 现象：更新版本后无法找到原miner-u相关的解析功能入口。原因：未切换`chunkSettingMode`为自定义模式，或未开启对应解析插件，原miner-u功能已整合至核心配置项中。

## 怎么确认配好了
- 上传一份典型的架构方案文档，查看解析后的分块预览，确认每个分块包含完整的章节或论证段落。
- 执行知识库搜索测试，输入包含约束条件或服务依赖的关键词，确认返回结果包含对应文档的完整片段。
- 上传体积不超过1000 MB的归档文档，确认解析任务在600秒内完成且无超时报错。
- 检查`customPdfParse`配置项的开关状态，确认PDF格式的架构图文档解析后保留了文本层级与嵌入的图表说明。
