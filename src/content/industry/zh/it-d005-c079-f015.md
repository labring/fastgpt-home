# 架构设计与技术方案的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的核心数据由架构师、技术负责人与平台研发组产出，日常文档包含技术方案、架构图、容量评估报告、技术评审纪要。数据来源主要为历史流量数据、服务拓扑、监控指标与业务增长计划，更新频率通常为每月一次，或伴随重大业务需求调整时同步更新。文档结构多包含约束条件、技术选型依据、跨服务边界定义等字段，部分文档附带量化指标如峰值QPS、扩容阈值等，整体内容偏向专业技术领域，术语密度较高。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据多包含结构化约束、量化指标与跨服务关联定义，长文本占比高且部分内容带有专业技术术语。数据更新频率相对稳定但存在突发性调整场景，要求检索召回环节能适配长文本分段与专业术语匹配。同时，文档中的服务拓扑、容量阈值等字段需精准匹配检索意图，避免召回无关的非架构类内容。此外，重大需求触发的高频更新要求召回结果能快速同步最新的业务增长计划与约束条件，保障检索内容的时效性与准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配架构文档中专业术语的匹配精度，避免召回无关的低相关性内容，平衡精准度与召回范围 |
| `limit` | 前10条 | 架构类文档单次检索需覆盖多服务关联内容，10条可平衡召回完整性与上下文长度，避免输出过载 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配架构图、服务拓扑这类兼具结构化与语义特征的文档，提升跨服务关联内容的召回效果 |
| `usingReRank` | 开启 | 对召回结果二次排序，修正专业术语匹配的偏差，提升评审纪要、容量评估类文档的召回准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动优化架构相关的检索意图，补充如“服务边界”“扩容阈值”等行业关键词，提升召回精准度 |
| `collectionIds` | 按业务域划分的知识库集合 | 隔离不同业务线的架构文档，避免跨域无关内容被召回，适配架构设计的多业务场景 |

## 容易做错的三处
- 未选择ada 002作为embedding模型时，调用知识库检索出现undefined model报错，原因是默认检索阈值适配ada 002的向量输出格式，更换模型后未同步调整匹配参数。
- 对多列Excel格式的架构评审纪要进行自动分段时，分段结果杂乱无章，无法按行划分业务单元，原因是默认自动分段逻辑未适配结构化表格数据，未识别行级业务单元。
- 对话输出中附带冗余的知识库引用信息，无法按需求关闭，原因是未在检索配置中关闭引用展示开关，默认保留了来源附加输出。

## 怎么确认配好了
- 检索架构方案相关关键词，查看返回结果的匹配分数，确认处于预设的`similarity`区间内。
- 核对单次检索返回的结果数量，确认不超过配置的`limit`取值。
- 上传结构化表格格式的评审纪要，验证自动分段是否按业务单元划分。
- 发起对话测试，确认知识库引用的附加输出可按需求调整。
