# 桌面终端支持的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据主要来自终端管理平台、资产系统、用户报障渠道、软件仓库四类来源。日常产出的文档包括终端故障单、装机清单、软件安装记录、远程协助记录，字段包含设备SN码、故障编号、软件版本号、操作时间等，单位多为条、字符、天。数据更新频率通常为日更新或随请求实时更新，单条文档的长度集中在500-1000字符区间，整体数据结构零散且关联维度较多。本页面基于FastGPT v4.17.0版本的配置逻辑编写。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且关联维度多，要求溯源环节必须精准匹配设备SN、故障编号等唯一标识，避免跨设备、跨工单的错误关联。文档结构零散且单条长度集中，要求引用的token区间需适配业务数据规模，避免截断核心信息或冗余加载。更新频率灵活，要求溯源的刷新策略需匹配数据更新节奏，防止使用过期的终端配置或故障记录。出错会直接导致员工停工或工单积压，要求溯源信息必须准确可追溯，不可出现模糊或错误的来源指向。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 桌面终端运维文档单条内容长度集中在500-1000字符，该token区间可完整承载单条业务数据 |
| `responseData` | 包含设备SN、故障单号、软件版本号 | 过滤非必要字段，聚焦终端支持的核心关联信息，避免回复冗余 |
| `detail` | 开启 | 强制在回复中附带来源系统名称与记录唯一ID，满足IT工程师快速溯源的需求 |
| 最大上下文引用条数 | 前3条 | 桌面终端支持的问题通常关联单台设备的1-2条历史记录，过多引用会干扰核心回答 |
| 引用来源刷新间隔 | 每12小时 | 匹配终端数据的日更新频率，保证溯源信息的时效性 |

## 容易做错的三处
- 现象：回复中附带了不必要的知识库引用内容，无法按需隐藏。原因：未正确配置`detail`参数，未关闭非必要的溯源展示项。
- 现象：引用的故障单记录时间与当前问题不匹配，出现过期数据。原因：引用来源刷新间隔设置过长，未匹配终端数据的日更新节奏。
- 现象：表单输入节点无法获取默认变量值，导致引用的终端配置参数为空。原因：未在接口问答配置中绑定对应资产系统的变量映射规则。

## 怎么确认配好了
- 提交一条模拟终端故障报障，检查回复中附带的溯源信息是否包含设备SN、故障单号等核心字段。
- 调整`quoteMaxToken`的取值区间，验证单条引用内容的长度是否适配业务文档的实际规模。
- 修改引用来源刷新间隔为1小时，模拟过期数据场景，检查回复是否同步更新溯源信息的时间戳。
- 测试表单输入节点的变量绑定，确认引用的终端配置参数可正常加载并展示。
