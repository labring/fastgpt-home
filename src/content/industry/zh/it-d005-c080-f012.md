# 桌面终端支持的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
该品类的数据主要来自终端管理平台、资产系统、用户报障渠道与软件仓库。日常处理的文档包含终端故障单、装机清单、软件安装记录、远程协助记录，数据更新频率为每日或随单次请求触发。文档多为结构化或半结构化格式，包含设备序列号、故障编号、软件版本号、操作时间等字段，部分文档附带图片格式的操作步骤或故障截图。

## 这些特征在「文档解析与分块」这一环带来什么约束
多源异构的数据格式要求解析模块兼容多种结构化、半结构化及图片型文档；高频更新的特性要求解析分块流程轻量化，避免因处理延迟影响工单流转。文档中包含固定字段与自由文本混合的内容，分块时需保留字段间的逻辑关联，避免破坏故障描述、装机步骤等完整信息。部分文档存在图片内嵌的情况，需额外适配OCR解析流程，确保非文本类文档可被正常处理。

## 配置怎么定
FastGPT v4.17.0 版本下的配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 匹配桌面终端文档中单段故障描述或操作记录的常规长度，避免分块过碎丢失上下文关联 |
| `chunkSplitter` | 按段落+固定分隔符 | 适配工单类文档的段落结构，保留故障单、装机清单的逻辑块完整性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–120 秒 | 适配终端类文档单文件的常规解析耗时，避免因超时触发平台报错 |
| `customPdfParse` | 启用 | 处理扫描版装机手册、故障记录PDF等图片型文档，适配实际业务中的非纯文本文件场景 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 匹配终端管理平台、资产系统导出文档的最大尺寸限制 |
| `chunkSettingMode` | 手动配置 | 适配桌面终端文档的差异化结构，灵活调整分块规则以匹配不同类型的业务文档 |

## 容易做错的三处
- 上传扫描版PDF文档后解析结果为空，界面显示解析成功但无有效文本内容，原因是未启用`customPdfParse`对应的OCR适配配置。
- 接入自定义PDF解析服务时触发超时报错，日志显示超时时间超出阈值，原因是未将`PARSE_FILE_TIMEOUT_SECONDS`调整至匹配自定义服务的实际处理耗时。
- 检索结果出现重复或不相关内容，现象是同一条故障记录被拆分为多个无逻辑关联的分块，原因是`chunkSplitter`配置为纯字符分割，未保留段落与步骤的完整性。

## 怎么确认配好了
- 上传单份终端故障单文档，检查解析后的文本块是否完整保留故障描述、设备信息的逻辑关联。
- 上传扫描版装机清单PDF，验证解析结果包含图片中的文字内容与步骤说明。
- 调整`PARSE_FILE_TIMEOUT_SECONDS`后，上传最大尺寸的终端资产清单，确认无超时报错。
- 检索测试文档中的典型故障关键词，检查返回的分块内容与关键词的匹配度符合业务预期。
