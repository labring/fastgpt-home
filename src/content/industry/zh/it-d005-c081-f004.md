# 渗透测试服务的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自目标系统、公开漏洞库、自动化扫描器结果与红队手工验证记录。日常产出的文档包括测试授权书、渗透测试报告、漏洞复现记录及整改建议，各文档字段包含授权范围、漏洞编号、复现步骤、风险等级等。数据更新以单个渗透测试项目为周期，或在目标系统版本重大更新、漏洞库新增关键条目时同步更新。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束：多来源数据包含结构化扫描结果、非结构化手工记录与表格类整改文档，要求向量模型支持跨格式的语义编码；项目级更新节奏要求索引支持增量同步，避免全量重建占用过多资源；漏洞复现记录与测试报告存在长段落内容，需合理设置分块规则避免语义断裂；部分文档包含敏感授权信息，需确保索引过程不泄露非授权内容；人工验证的非标准格式内容，需开启自动段落识别功能适配。

## 配置怎么定
本配置适用于FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxToken` | 8192 | 适配多数公开Embedding模型的上下文长度限制，避免截断关键漏洞信息 |
| `defaultToken` | 4096 | 平衡索引计算资源消耗与语义覆盖范围 |
| 分块长度 | 800–1200 字符 | 适配渗透测试报告、漏洞复现记录的常规段落长度，避免语义割裂 |
| 重叠长度 | 100–200 字符 | 保持相邻分块的语义连贯性，防止关键授权或漏洞信息断裂 |
| 最大段落深度 | 3 | 适配渗透测试文档的层级结构，提升自动段落识别的准确性 |
| 多向量支持 | 开启 | 适配整改建议中的表格数据，提升结构化内容的检索精度 |

## 容易做错的三处
- 现象：在知识库设置中为表格数据开启多向量支持后，检索结果无法匹配表格内的结构化内容。原因：未在向量模型配置中启用多向量支持开关，或未针对表格数据单独触发索引生成。
- 现象：已完成模型配置与Agent对话测试，刷新页面后弹出“检测到没有可用的索引模型”报错。原因：未将选中的Embedding模型同步至系统索引服务，或索引模型的部署状态未正常激活。
- 现象：接入多模态Embedding模型时返回包含Invalid的报错信息。原因：未按照模型要求的输入格式传递文档内容，或API密钥的权限配置存在限制。

## 怎么确认配好了
- 进入知识库设置页面，查看向量模型配置项，确认选中的模型与当前使用的Embedding模型一致。
- 上传一份包含表格的整改建议文档，触发手动索引，检查索引任务的状态是否显示为完成。
- 发起包含表格内容的测试查询，确认检索结果中包含匹配的表格片段。
- 查看系统日志，确认无索引模型缺失或格式错误的报错信息。
