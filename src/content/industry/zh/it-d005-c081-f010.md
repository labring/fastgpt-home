# 渗透测试服务的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据围绕渗透测试全流程生成，日常文档包含测试授权书、渗透测试报告、漏洞复现记录与整改建议。数据来源覆盖目标系统资产、公开漏洞库、自动化扫描器结果与手工验证记录，更新节奏以单个测试项目为周期，或随系统版本、漏洞库重大更新同步调整。数据字段包含测试范围、漏洞编号、复现步骤、风险评级、整改时限等，无统一固定单位，随单个测试项目的具体需求灵活调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据特征对引用溯源环节带来多重约束。由于数据来源分散，覆盖目标系统、漏洞库、扫描器结果与手工验证记录，需为不同来源的内容配置独立的溯源标识，避免混淆不同类型的测试数据。以项目为单位的更新节奏，要求溯源信息绑定当前测试项目的唯一标识，确保引用内容属于对应任务。文档包含测试授权书等合规文件，溯源需关联合规依据，避免法律授权争议。漏洞复现记录与最终报告强关联，溯源需保留完整的验证链路，防止漏洞遗漏或风险评级偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 1500–2000 token | 适配渗透测试报告中长段落的漏洞复现步骤引用需求，避免截断关键信息 |
| `responseData` | 开启关联文档全字段 | 覆盖测试授权书、漏洞复现记录等多类型文档的溯源信息，完整保留来源细节 |
| `detail` | 开启完整溯源 | 保留手工验证记录与扫描器结果的原始来源标识，区分不同验证方式的内容 |
| 最大上下文窗口 | 前6轮对话 | 匹配渗透测试中多轮验证、复现的连续提问场景，保留前序测试步骤的上下文 |
| 引用展示位置 | 段落末尾 | 对应渗透测试报告中漏洞项的溯源标注习惯，便于查阅者快速定位依据 |
| 溯源绑定标识 | 项目ID前缀 | 区分不同测试项目的引用内容，避免跨项目的溯源信息混淆 |

*本文适配FastGPT v4.17.0版本的配置逻辑*

## 容易做错的三处
- 免登录分享链接访问应用时，引用原文按钮显示但点击无响应。原因：未在应用配置中开启分享场景下的溯源权限，导致共享链接无法加载关联文档数据。
- 知识库回答末尾未显示引用标注。原因：未开启`detail`配置项，或配置的`quoteMaxToken`取值过低，导致引用内容被截断或未生成。
- 连续提问时无法关联上下文，后续回答出现答非所问的情况。原因：未配置最大上下文窗口的轮次限制，或窗口取值过小，无法保留前序测试步骤的提问信息。

## 怎么确认配好了
- 发起单条漏洞复现的提问，检查回答末尾是否显示溯源来源的文档类型与标识。
- 切换到免登录分享链接，尝试点击回答中的引用按钮，确认可跳转至对应文档内容。
- 连续发起3条以上关联测试步骤的提问，确认后续回答可关联前序提问的上下文信息。
- 导出测试问答记录，检查每条引用内容是否绑定了当前项目的唯一标识。
