# 渗透测试服务的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类数据主要来自目标系统、公开漏洞库、自动化扫描器结果与手工验证记录。日常产出的文档包含测试授权书、渗透测试报告、漏洞复现记录、整改建议四类，单份文档长度跨度较大。数据更新以单个项目或重大版本迭代为周期，无固定全局更新节奏，单条数据的字段包含授权范围、漏洞编号、复现步骤、风险等级等，无统一强制的字段格式要求。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据特征对检索召回环节带来多重约束。多源异构且格式不统一的数据来源，要求检索系统支持灵活的解析适配逻辑，兼容扫描器输出、手工记录等不同格式的内容。单份文档长度跨度大，长报告可能超出基础检索的上下文承载上限，需要针对性的分块与截断策略。无固定全局更新周期，检索系统需支持增量更新，避免重复处理历史项目数据。测试授权书涉及合规边界，召回结果需严格匹配授权范围，防止超出权限的信息被返回。漏洞复现记录包含攻击路径细节，排序逻辑需优先匹配当前测试场景的验证需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.72–0.85 | 匹配渗透测试场景下漏洞描述、复现步骤的语义相似度需求，避免过低导致无关结果过多，过高遗漏相关漏洞记录 |
| `limit` | 前8–12条 | 单轮检索返回的结果数量适配红队工程师的人工审核效率，避免过多结果增加审核负担 |
| `searchMode` | `vector` | 针对漏洞复现记录、扫描结果这类半结构化数据，优先使用向量检索匹配语义关联 |
| `usingReRank` | 开启，重排前5条 | 针对长文档分块后的召回结果，通过重排模型过滤无关分块，提升核心漏洞信息的召回精度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展测试相关的同义词，适配渗透测试场景的专业术语习惯 |

## 容易做错的三处
- 现象：部署重排模型后界面显示测试通过，但调用检索接口返回结果的`usingReRank`字段始终为false。原因：未在检索接口请求参数中显式传入`usingReRank=true`，或未配置知识库与重排模型的绑定关系。
- 现象：上传渗透测试报告后分块存储，实际块大小与预设值偏差较大。原因：未针对长段落的漏洞复现步骤设置合理的分块边界，导致系统自动拆分时偏离预设参数。
- 现象：当召回的分块总长度超过系统默认阈值时，重排模型未被触发调用。原因：未配置长上下文截断后的重排触发逻辑，系统默认仅在召回结果条数低于阈值时触发重排，未适配长文档分块的场景。

## 怎么确认配好了
- 调用检索接口，传入渗透测试相关关键词，查看返回结果的相似度参数是否符合预设配置。
- 显式传入`usingReRank=true`参数发起检索，确认返回结果的排序与原始向量召回结果存在差异。
- 上传单份长文档后发起检索，确认系统触发重排模型并返回经过排序的结果。
- 通过接口创建知识库并传入关联参数，调用对话接口验证可正常调用该知识库的检索内容。
