# 渠道归因与线索分发的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自广告平台、CRM系统、归因SDK与表单系统，日常处理的文档包括归因规则、线索分发表、渠道报表与异常核对单。数据更新节奏以日度或周度为主，单份文档包含渠道标识、转化节点、归属规则、线索ID等字段，单位涵盖曝光量、点击量、转化数、金额等，需完成渠道参数核验、重复线索去重与销售归属确认等核心处理环节。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散导致字段格式不统一，需适配多源异构数据的向量转换逻辑。日度/周度的批量更新要求索引支持增量同步，避免全量重建耗时过长。单份文档包含多类业务字段，需针对渠道标识、转化数据等核心字段优化向量提取权重。重复线索去重与销售归属确认的业务逻辑，要求索引召回结果需严格匹配业务规则，避免无关数据干扰检索精度。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配归因规则、渠道报表等文档的字段密度，避免单块包含过多无关业务信息 |
| 重叠长度 | 100–200 字符 | 保留跨分块的渠道参数、转化节点等关键上下文，防止关键信息被截断 |
| `defaultToken` | 4000 token | 匹配单批次线索分发表的平均长度，平衡向量转换精度与计算成本 |
| `maxToken` | 8000 token | 覆盖完整的异常核对单与渠道报表内容，确保召回信息完整 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非目标渠道数据，避免干扰销售归属确认流程 |
| 单次搜索上限 | 前 10 条 | 控制检索返回量，适配渠道归因的快速核验需求 |

## 容易做错的三处
- 现象：在开源版本中配置索引模型时，误将阿里-emb3与通用嵌入模型混用。原因：未结合渠道数据的多源异构特征，未匹配对应嵌入模型的适配场景。
- 现象：检索召回了相关的渠道报表或线索分发表，但大模型输出提示未找到相关内容。原因：未针对渠道标识、转化节点等核心业务字段优化向量提取权重，导致召回的文档向量与查询意图匹配度不足。
- 现象：批量更新索引后，重复线索的检索结果未完成去重。原因：未按照日度/周度的更新节奏配置增量同步规则，导致新旧重复数据未被正确关联过滤。

## 怎么确认配好了
- 查看向量转换日志，确认单份业务文档的分块数量符合预期，无过度截断或冗余分块。
- 发起针对特定渠道参数的检索测试，核对召回结果的字段与查询意图匹配度符合业务需求。
- 执行增量同步测试，确认更新后的线索数据能正确关联到已有索引，无重复数据残留。
- 监控检索请求的响应时长，确认符合业务处理的实时性要求，调整相关配置项适配节奏。
