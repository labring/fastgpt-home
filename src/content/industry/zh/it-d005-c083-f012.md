# 游戏内容合规自查的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
本品类的典型数据主体为游戏发行合规团队、内容审核人员与游戏制作人。日常处理的文档包含内容自查表、敏感内容修改记录、用户协议、合规评审纪要四类，数据来源涵盖游戏剧情脚本、游戏内文本、美术资源配套说明与监管公开合规要求。文档结构多为混合格式，包含结构化表格、纯文本段落与PDF内嵌批注，字段包含内容标题、审核状态、修改说明、监管条款对应项，更新频率为每版本或每活动周期更新一次。

## 这些特征在「文档解析与分块」这一环带来什么约束
合规文档的混合格式特征要求解析环节支持结构化表格与PDF批注的提取，避免遗漏关键审核信息；按版本或活动的高频更新节奏，要求分块逻辑可适配局部内容修改后的增量解析，避免全量重解析浪费资源；游戏文本与剧情脚本的长文本属性，要求分块阈值需匹配监管条款与对应游戏内容的关联长度，防止拆分后关联信息断裂；文档更新的时效性要求，需控制单文件解析时长以适配版本上线的节奏，避免因解析超时影响整体进度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配合规文档中监管条款与对应游戏内容的关联长度，避免拆分后关联信息断裂 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配合规文档按评审节点、监管条款分类的结构，保留上下文关联 |
| `customPdfParse` | 开启 | 支持解析合规评审纪要中的PDF内嵌批注与表格内容，适配美术资源配套的合规文档格式 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配单版本更新的全量合规文档包，避免因文件过大无法上传 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 满足多格式混合文档的解析时长需求，避免版本上线前解析超时 |
| `chunkSettingMode` | 手动配置 | 针对合规文档的特殊结构调整分块规则，适配不同类型的自查文档 |

## 容易做错的三处
- 上传合规文档包后，界面显示分块数异常且部分chunk状态为向量化失败，反复重试仍偶发异常。原因：未调整`chunkSize`参数，过小的分块阈值导致大量碎片化chunk，增加向量化节点的负载压力。
- 使用DB节点查询合规数据库后，返回的JSON或JSON数组无法直接用于接口问答，需额外编写代码转换。原因：未配置适配结构化数据的解析规则，默认解析逻辑无法自动识别数据库返回的非文本格式数据。
- 解析合规评审纪要时，PDF内嵌的表格批注内容丢失。原因：未开启`customPdfParse`配置，默认解析逻辑未提取PDF内嵌的补充内容。

## 怎么确认配好了
- 上传单份典型合规文档，查看解析后的分块结果，确认内容关联未被拆分断裂。
- 测试数据库查询节点与问答接口的联动，确认返回的结构化数据可直接被问答逻辑处理。
- 上传包含表格与批注的合规文档，检查解析后chunk是否保留原有格式与补充内容。
- 调整分块相关配置后，重新上传大文件，确认解析流程无超时或异常报错。
