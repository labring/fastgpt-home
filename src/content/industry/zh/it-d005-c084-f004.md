# 游戏客户端性能优化的技术文档与接口问答：向量模型与索引

本页面适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据主要来自引擎Profiler导出文件、崩溃平台上报日志、真机测试采集的帧率与资源数据、版本迭代的优化记录。日常产出的文档包括性能测试报告、机型适配清单、优化跟踪记录、崩溃分析复盘文档。数据更新节奏通常为每日增量更新或每版本全量更新，文档字段包含帧率数值、CPU占用率、内存占用量、崩溃堆栈标识等，单位多为fps、百分比、MB。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源带来索引格式兼容约束，需同时支持结构化性能指标数据与非结构化日志、文档文本。高频更新节奏要求索引支持增量同步，避免每次全量重建占用过多服务器资源。专业技术术语密集的文档内容，要求向量模型适配工业级技术文本的语义编码，避免关键性能术语的语义丢失。特定字段的单位与标识信息，需要在索引阶段关联元数据，确保检索时可按指标类型、机型维度快速过滤结果。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配性能测试报告、崩溃分析文档的单段内容长度，避免割裂帧率、CPU占用等关键性能指标的语义关联 |
| 重叠长度 | 100–200 字符 | 保留跨分块的上下文关联，适配长文档中优化步骤的连贯性描述 |
| `defaultToken` | 4096 token | 匹配多数技术文档的单段token上限，避免截断Draw Call、帧率抖动等专业术语的完整描述 |
| `maxToken` | 8192 token | 支持整合多段分块后的上下文，覆盖完整的版本优化复盘内容 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关的非性能类文档，确保检索结果聚焦客户端卡顿、闪退等问题 |
| 单次搜索上限 | 前 10 条 | 控制返回结果数量，适配客户端工程师快速定位性能问题的检索习惯 |

## 容易做错的三处
- 调用知识库接口创建的QA拆分集合检索速度过慢。原因是未配置增量索引同步，每次检索触发全量向量计算，无法适配性能数据高频更新的节奏。
- 更换embedding模型后，已导入的知识库无法返回匹配的历史性能数据。原因是未重新生成原有文档的向量索引，仍使用旧模型的编码结果进行检索。
- 检索结果混入大量无关的机型适配清单内容。原因是相似度阈值设置过低，未过滤匹配度不达标的非目标文档。

## 怎么确认配好了
- 查看FastGPT后台的索引任务日志，确认增量同步任务按日或每版本的更新节奏触发，无全量重建的异常报错。
- 手动输入客户端性能相关的查询词，核对返回结果的匹配度，调整相似度阈值至符合业务需求的区间。
- 调用知识库检索接口，指定机型或性能指标维度，确认返回结果的条数符合单次搜索上限的配置。
- 检查已更换embedding模型的知识库，确认向量索引已完成重新生成，无旧模型编码的残留提示。
