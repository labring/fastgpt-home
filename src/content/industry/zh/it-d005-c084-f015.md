# 游戏客户端性能优化的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的核心数据来自引擎Profiler、崩溃平台、真机测试与帧率采集工具，更新频率为每日或每版本迭代。日常产出的文档包括性能测试报告、机型适配清单、优化记录与崩溃分析报告，文档字段通常包含测试机型型号、帧率数值（fps）、内存占用量（MB）、优化前后对比数据等，格式随测试场景动态调整，无统一固定结构。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且格式不统一，要求检索环节需适配多类文档结构，避免因格式差异导致召回遗漏。高频更新的特性要求检索链路限制单次检索的上下文加载量，防止历史对话堆积增加耗时。多场景的文档类型覆盖，要求检索规则需优先匹配性能优化核心条目，同时兼顾机型适配、崩溃分析等细分场景。低端机复现与资源分析的高耗时环节，也要求检索结果需精准指向可复用的优化方案，减少无效信息干扰。

## 配置怎么定
本页面基于FastGPT v4.17.0版本的配置逻辑编写，以下为针对游戏客户端性能优化场景的推荐配置：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配游戏性能优化相关文档的语义精度要求，过滤低相关的通用技术内容 |
| `limit` | `前10条` | 游戏客户端优化的相关文档总量适中，过多条目会增加上下文处理负担 |
| `searchMode` | `语义检索模式` | 针对专业技术文档的语义匹配效果更稳定，符合该场景的实际需求 |
| `usingReRank` | `开启` | 过滤低相关性的性能测试报告条目，提升最终召回结果的精准度 |
| `datasetSearchUsingExtensionQuery` | `开启` | 扩展问题语义，覆盖工程师常用的性能优化术语变体，提升召回覆盖范围 |
| `collectionIds` | `绑定专属性能优化知识库集合` | 隔离不同品类的文档资源，避免无关内容干扰检索结果 |

## 容易做错的三处
- 现象：同一对话窗口内多轮提问后，知识库检索耗时超过60秒，切换新窗口则恢复正常。原因：未限制对话上下文长度，每次检索都加载过多历史对话内容，增加了检索链路的负载。
- 现象：语义检索返回结果分数较高，但与当前优化场景不匹配，例如针对低端机卡顿问题召回了包体优化的文档。原因：未配置`similarity`阈值，或阈值设置过低，召回了大量分数达标但无关的条目。
- 现象：直接引用知识库ID可正常返回结果，但通过应用变量传递知识库ID时出现报错。原因：未正确绑定`collectionIds`配置，或变量传递时未匹配知识库集合的权限规则。

## 怎么确认配好了
- 发起连续5轮以上的性能优化相关提问，检查单次检索的耗时是否稳定在合理区间，无明显递增趋势。
- 切换不同搜索模式，对比返回结果的相关性，验证`searchMode`配置的实际效果是否符合预期。
- 尝试通过应用变量传递知识库集合ID，检查是否能正确召回对应集合内的文档，无报错信息返回。
- 调整`similarity`参数的取值区间，验证返回结果的数量和相关性是否符合当前场景的需求。
