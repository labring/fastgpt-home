# 游戏服务器研发运维的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
游戏服务器研发运维的核心数据包含服务器架构说明、开服方案、合服方案、故障报告等文档，数据来源包括游戏运行日志、在线人数监控数据、业务数据库、玩家工单。文档结构多包含技术参数、操作步骤、校验规则，字段涉及服务器IP、并发上限、日志时间戳等，单位多为并发数/秒、存储容量GB、时间戳毫秒级。数据更新频率多为每日或随游戏活动同步更新，部分核心配置文档更新频率更高。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据更新频率较高，知识库检索需支持增量同步以保证召回内容的时效性；文档包含大量精准技术参数，要求检索需具备字段级匹配能力，避免召回无关内容；单条文档内容较长且数据量较大，需严格控制召回条数以适配对话上下文窗口；故障报告、合服方案等文档的操作步骤关联性强，需优先召回最新或最相关的条目，因此需要针对性调整召回与重排规则。

## 配置怎么定
以下为FastGPT v4.17.0版本下的可配置项：
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 游戏服务器运维文档包含大量精准技术参数，该区间可平衡召回精度与覆盖范围，避免无关文档被纳入结果 |
| `limit` | 前8–12条 | 服务器运维核心信息集中在少量文档中，过多召回会超出对话上下文窗口，导致关键信息被截断 |
| `searchMode` | `local` | 游戏服务器运维数据多为内部私有知识库，无需调用外部搜索资源，可减少无效检索开销 |
| `usingReRank` | 开启 | 故障报告、合服方案等文档结构复杂，重排可将关键操作步骤、校验规则的召回优先级提升，优化检索结果相关性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 运维问题常包含行业缩写或自定义术语（如合服、开服），扩展查询可覆盖更多相关文档，提升召回完整性 |
| `collectionIds` | 绑定专属游戏服务器运维知识库集合 | 精准限定检索范围，避免混入其他品类的文档，确保召回结果与业务场景匹配 |

## 容易做错的三处
- 现象：调用知识库聊天时，系统提示词内的<Reference>标签未显示召回的文档内容。原因：未开启将知识库召回结果注入系统上下文的配置开关，导致检索到的文档未被纳入对话上下文。
- 现象：无法导出知识库里上传文件的完整文件名清单。原因：未通过官方提供的数据集管理界面或接口导出清单，直接尝试遍历容器存储目录会因权限限制或路径映射问题失败。
- 现象：检索返回的结果条数与配置的`limit`参数不符。原因：开启重排功能后，系统会对初始召回结果进行二次筛选，未同步调整`limit`的取值范围以适配重排后的结果数量。

## 怎么确认配好了
- 上传一份测试用的服务器架构文档，发起包含该文档关键参数（如指定端口、并发上限）的查询，核对返回结果中是否包含该文档的相关片段。
- 查看对话的系统提示词区域，确认<Reference>标签内已显示召回的文档内容，验证上下文注入配置生效。
- 调整`similarity`参数至0.7，发起包含模糊运维术语的查询，核对召回结果的相关性是否符合预期。
- 进入数据集管理界面，尝试导出文件清单，确认可获取所有上传文件的完整名称，验证文件管理配置正常。
