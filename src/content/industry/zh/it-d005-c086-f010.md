# 游戏版号与出版申报的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的核心数据围绕单款游戏的出版申报流程生成，日常文档包含申报请示文件、游戏申请表、著作权证明、审读报告等，字段涵盖版本号、著作权登记编号、审读意见编号、运营机构备案信息等。数据来源包括国家新闻出版署办事服务平台、著作权登记系统、游戏包体文件及运营机构提交的备案资料，更新频率为每款游戏单独触发，无固定周期，单款申报的材料集合体量从数十KB到数MB不等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
单款申报数据的专属属性要求溯源信息必须绑定对应游戏的唯一标识，避免跨款材料混淆。非固定更新频率意味着知识库需支持增量同步，仅在单款申报材料更新时触发索引，避免全量冗余检索。多类型结构化文档的混合使用，要求引用溯源需精准匹配字段维度，同时覆盖不同文档类型的元数据。单款材料的体量范围，决定了引用参数的取值需适配单份申报的核心信息长度，防止过度截断或冗余加载。

## 配置怎么定
本配置基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配单款申报材料的核心元数据总长度，避免截断著作权编号、审读意见等关键字段 |
| `responseData` | 包含来源元数据 | 保留数据来源的官方渠道、提交时间、关联游戏标识等信息，满足溯源核对需求 |
| `detail` | 开启完整字段展示 | 提取审读报告编号、运营机构备案号等品类专属字段，便于材料一致性核对 |
| 最大上下文 | 4000–6000 token | 覆盖单款申报的全套文档上下文，支持跨材料的关联查询 |
| 知识库最大引用 | 前3条 | 聚焦最相关的官方办事指南和已通过申报案例，减少冗余信息干扰 |
| 单次搜索上限 | 5条 | 匹配省级初审沟通的参考材料数量，适配业务沟通的信息密度 |

## 容易做错的三处
- 现象：接口返回的引用内容截断了审读报告编号字段。原因：`quoteMaxToken`取值设置过低，未覆盖单份申报材料的核心元数据长度。
- 现象：检索结果混入了其他游戏的申报材料。原因：未通过`responseData`绑定单款游戏的专属数据来源标识，未过滤跨品类文档。
- 现象：调用接口后未返回任何引用溯源信息。原因：未开启`detail`参数，未启用品类专属元数据的提取逻辑。

## 怎么确认配好了
- 上传单款游戏的申报请示文件，发起技术文档问答，检查返回结果中是否包含著作权登记号、审读报告编号等专属字段。
- 调用接口并指定`quoteMaxToken`为1000 token，验证返回的引用内容未截断核心元数据。
- 查看知识库检索日志，确认仅返回游戏版号申报类文档，无跨品类或其他游戏的材料。
- 调整`detail`参数为关闭状态，验证接口返回结果不再附带引用来源信息。
