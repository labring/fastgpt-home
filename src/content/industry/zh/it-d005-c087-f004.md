# 游戏策划与数值设计的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
通常，游戏策划与数值设计的日常文档包含玩法策划案、结构化数值表、版本需求单、平衡性测试记录。数据来源一般为内部玩家行为数据、公开竞品资料、战斗日志与版本反馈。文档更新频率多为每周或每版本迭代，其中数值表包含角色属性、技能系数、关卡阈值等带单位的字段，玩法策划案则以规则描述类文本为主，整体数据兼具结构化数值与非规则文本两类形态。

## 这些特征在「向量模型与索引」这一环带来什么约束
品类数据的更新节奏决定了索引需适配增量触发逻辑，避免全量重复执行占用过多计算资源。结构化数值表与非结构化规则文本并存的特征，要求向量模型需同时适配专业术语嵌入与数值关联逻辑的语义捕捉，否则可能丢失关键系数关联。高风险的出错后果则要求索引召回的准确率需匹配业务需求，避免因召回偏差导致玩法失衡或版本返工。同时，文档的单次长度差异较大，需合理配置分块规则以平衡语义完整性与索引效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配玩法策划案、数值表的单条规则长度，避免语义割裂 |
| 重叠长度 | 100–200 字符 | 保留跨块的数值关联逻辑，避免拆分后丢失系数关联 |
| `maxToken` | 4096 token | 适配长文本的嵌入上限，覆盖完整的版本需求单内容 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配的非相关数值规则，降低玩法失衡风险 |
| 单次搜索上限 | 前 5 条 | 控制上下文长度，避免超出模型输入限制 |
| `defaultToken` | 按实测标定 | 适配品类内专业术语的嵌入精度，匹配游戏数值场景的语义需求 |

## 容易做错的三处
- 现象：知识库索引进度停滞，未完成的文件长期处于处理中状态。原因：未配置增量索引触发规则，使用全量索引适配周/每版本的更新频率导致资源占用过高。
- 现象：调用上传文件API后无法获取索引完成状态。原因：未启用FastGPT v4.17.0的索引状态回调接口，未配置状态轮询的触发条件。
- 现象：向量嵌入结果与数值规则匹配度偏低。原因：使用通用文本向量模型，未适配游戏数值、专业规则类文本的语义特征。

## 怎么确认配好了
- 上传一份典型的数值表文档，查看分块后的文本片段是否保留了完整的系数、阈值等关键信息。
- 发起一条关于“角色破甲系数”的查询，核对返回的上下文是否包含对应数值规则的相关文档片段。
- 查看索引任务日志，确认增量索引仅在每周或版本更新后触发，未重复执行全量索引。
- 切换向量模型后，重新嵌入测试文档，对比嵌入结果的语义相似度变化是否符合预期。
