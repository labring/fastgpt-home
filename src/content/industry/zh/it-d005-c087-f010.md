# 游戏策划与数值设计的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
游戏策划与数值设计的日常文档包含玩法策划案、数值表、版本需求单、平衡性测试记录。数据来源包括玩家行为数据、竞品公开资料、战斗日志、版本反馈。更新频率通常为周度或每版本迭代一次。文档结构多包含规则描述、参数表格、迭代记录，字段多带有明确单位，如伤害系数、成长等级、冷却时间等，数值表还会区分不同角色或玩法的专属参数。

## 这些特征在「引用来源与溯源」这一环带来什么约束
游戏策划与数值设计的文档更新频率较高，要求引用溯源能够快速定位最新版本的内容，避免使用过时的数值或规则。文档中的参数带有明确单位与细分字段，溯源需精准匹配到具体段落或单元格，不使用泛泛的文档标题。数据来源多样，不同来源的可信度存在差异，溯源需标注来源类型以便校验。数值失衡或规则错误会直接影响玩法体验与留存，溯源环节需确保引用内容与答案完全对应，避免无关信息干扰决策。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 适配单段策划文档或数值表的内容长度，避免截断关键成长曲线参数 |
| `detail` | 开启 | 展示引用原文的具体字段与单位，匹配数值设计的参数精度要求 |
| `responseData` | 携带来源文档路径与更新时间 | 关联版本需求单的迭代记录，便于回溯修订依据 |
| 单次搜索上限 | 前3条 | 避免过多引用导致数值模拟逻辑混乱 |
| 最大上下文 | 4000–6000 token | 适配长段玩法策划案的上下文需求 |
| 问题优化模型 | 与知识库嵌入模型对齐 | 匹配游戏数值规则的语义匹配精度 |

## 容易做错的三处
- 现象：返回答案与引用来源无关联，引用条目为空或随机匹配。原因：未对齐问题优化模型与知识库嵌入模型，导致语义匹配偏差。
- 现象：配置`detail`后未展示具体字段，仅显示文档标题。原因：未开启原文字段提取配置，无法定位数值表中的伤害系数等关键参数。
- 现象：引用条数超出预期上限且包含无关来源。原因：未限制单次召回的知识库条目范围，导致冗余信息干扰匹配逻辑。

## 怎么确认配好了
- 提交包含数值参数的查询，核对返回结果中引用的文档是否为对应版本的数值表或策划案。
- 查看系统日志，确认引用来源携带了文档路径与更新时间的标识。
- 配置引用可见度后，切换不同协作角色，验证可见度配置是否生效。
- 调整`quoteMaxToken`参数，测试长段策划文档的引用是否被完整保留或合理截断。
