# 游戏策划与数值设计的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
游戏策划与数值设计的日常文档包含玩法策划案、数值表、版本需求单、平衡性测试记录，数据来源包括玩家行为数据、竞品公开资料、战斗日志与版本反馈。文档更新频率为周度或每版本迭代，结构多包含结构化数值表格、规则描述文本与版本变更记录，字段与单位涉及伤害系数、升级经验、单位阈值等游戏专属参数，单份文档长度跨度较大，从单页数值表到数十页版本需求单均有覆盖。

## 这些特征在「文档解析与分块」这一环带来什么约束
品类文档的结构化表格与长规则文本并存，且更新频率较高，这对文档解析与分块环节带来多重约束。首先，分块不能破坏表格单元格完整性与规则段落的上下文关联，否则会影响后续规则拆解与数值模拟工作。其次，单份文档长度跨度大，从单页数值表到数十页版本需求单均有覆盖，分块配置需支持灵活调整以匹配不同规模的文档。此外，文档中的数值参数直接关联游戏玩法平衡，分块准确性不足可能引发玩法失衡或版本返工。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配游戏策划与数值设计的文档特征：

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配品类内常见的规则段落与数值表单块长度，避免拆分关键数值或完整规则 |
| `chunkSplitter` | 按段落+表格边界 | 保留结构化数值表格的单元格完整性，避免拆分跨单元格的关联参数 |
| `customPdfParse` | 开启 | 适配品类文档中常见的带内嵌表格、公式与图片的策划案PDF，保留文档格式与内容结构 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 秒 | 匹配大型版本需求单或多页数值表的解析耗时，避免因超时导致解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持上传多份文档合集或大型版本包，满足品类批量文档处理需求 |
| `chunkSettingMode` | 手动配置 | 适配品类文档结构差异大的特征，可针对不同类型文档单独调整分块规则 |

## 容易做错的三处
- 现象：上传带内嵌图片或表格的策划案PDF后，解析结果缺失图片内的数值文本或表格格式。原因：未开启`customPdfParse`配置，默认解析逻辑未适配内嵌非文本元素的提取。
- 现象：上传excel格式的数值表后，提问时无法关联同一表格内的伤害系数与升级经验参数。原因：未配置`chunkSplitter`按表格边界分割，默认按字符拆分破坏了表格的单元格关联。
- 现象：上传大型版本需求单后，解析任务触发后短时间内返回超时错误。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置过低，未匹配大型文档的解析耗时。

## 怎么确认配好了
- 上传一份典型的数值表PDF，检查解析结果是否保留了完整的单元格内容与格式。
- 上传一段长规则文本，调整`chunkSize`配置后，确认分块未拆分完整的规则段落或关键数值。
- 上传一份大型版本需求文档，验证解析任务未触发超时异常。
- 上传excel格式的数值表，提问后确认可准确提取指定单元格的数值与关联参数。
