# 游戏运营活动配置的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自游戏运营后台、玩家分群系统、付费数据报表与活动运行日志。日常产出的文档包括活动执行方案、奖励配置表、上线前检查单与活动复盘报告。数据更新节奏多为周度或节假日活动前临时调整，文档字段多包含活动唯一标识、奖励类型与数值、生效时间范围、触发条件等，部分配置项带有明确单位，如奖励发放额度、玩家触发阈值。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据的结构化与半结构化混合特征，要求向量索引需同时适配表格类结构化奖励配置表与长文本类活动方案。高频更新的特性要求索引支持增量同步，避免全量重建耗时过长影响活动上线效率。活动配置的字段带有明确单位与数值约束，向量模型需保留字段语义关联，避免数值类信息丢失导致的检索偏差。活动执行的容错空间极小，检索结果的准确性直接影响配置核对效率，因此索引的召回精度需适配业务校验的严谨需求。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的界面逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配活动方案的段落长度与奖励配置表的单表行数，避免跨块拆分关键配置项 |
| 重叠长度 | 100–200 字符 | 保留跨块的活动时间、奖励规则等关键上下文，防止分块破坏语义完整性 |
| 相似度阈值 | 0.75–0.85 | 匹配活动配置的严谨校验需求，过滤低相关的历史活动方案，减少人工核对成本 |
| `maxToken` | 4000 | 适配活动复盘报告的长文本检索，确保完整召回关联的配置细节 |
| 单次搜索上限 | 前 5 条 | 匹配运营人员的常规核对范围，避免过多结果增加筛选负担 |
| `defaultToken` | 按实测标定 | 适配不同向量模型的token限制，避免因token超限导致的检索失败 |

## 容易做错的三处
- 切换知识库向量模型后界面显示无同步进度，且无法回退到原模型。原因是未清理旧模型的索引缓存，系统仍绑定原模型的索引路径。
- 配置豆包embedding模型时测试返回"404 page not found"。原因是未正确填写模型的专属API端点，或未在渠道配置中开启对应模型权限。
- 未开启向量归一化配置，使用未归一化的向量模型时，检索结果的相似度排序出现偏差。原因是向量模型的输出未做归一化处理，导致相似度计算基准不一致。

## 怎么确认配好了
- 上传一份测试用的活动配置表与历史活动方案，执行检索后检查返回结果的相似度排序是否符合预期。
- 在模型渠道配置页面测试向量生成接口，确认返回的向量数据无异常报错，且匹配`defaultToken`与`maxToken`的设置限制。
- 手动触发一次增量索引同步，等待任务完成后检查索引更新日志，确认新上传的活动文档已被正确收录。
- 调整相似度阈值至区间边界，验证检索结果的召回数量是否随阈值变化合理调整。
