# 游戏运营活动配置的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
游戏运营活动配置的数据通常来自运营后台、玩家分群系统、付费数据平台与活动日志系统。日常产出的文档包括活动方案、奖励配置表、上线检查单与活动复盘报告。数据更新节奏多为周度或节假日活动前临时调整。文档结构多包含结构化配置字段与非结构化说明文本，奖励配置表含道具ID、发放数量、生效时间等字段，活动周期以天为单位标注。

## 这些特征在「文档解析与分块」这一环带来什么约束
结构化配置字段多为固定格式，需避免分块打断字段关联，确保奖励数值与对应说明绑定。周度或临时更新的文档需支持快速解析，需控制单文件解析时长与资源占用。奖励配置表的数值字段需精准提取，避免分块拆分数值与对应配置项。活动复盘文档包含时序数据，分块需保留时间线连贯性。同时文档中可能嵌入图片、表格，需适配多格式解析需求。

## 配置怎么定
本文基于 FastGPT v4.17.0 版本配置规则。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配活动方案与配置表的文本长度，避免拆分关联配置项 |
| `chunkSplitter` | markdown 分块器 | 保留文档中表格、标题的结构，适配活动配置表的结构化内容 |
| `customPdfParse` | 开启 | 适配活动方案中的内嵌图片与表格，提升结构化提取准确率 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 容纳多页活动复盘报告与批量奖励配置表 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大型活动文档的解析时长，避免超时中断 |
| `chunkSettingMode` | 手动模式 | 针对运营活动配置的特殊文档结构，自定义分块规则 |

## 容易做错的三处
- 上传含图片的docx文件后返回无效图片标识：原因是未开启`customPdfParse`配置，导致图片资源无法被正确提取与关联。
- 单文件解析触发超时报错：原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`至适配大型活动文档的取值，或`chunkSize`设置过小导致分块数量过多。
- 上传excel奖励配置表后解析字段缺失：原因是未使用适配结构化表格的`chunkSplitter`，导致表格被错误拆分为独立文本块。

## 怎么确认配好了
- 上传单份奖励配置表docx文件，检查解析结果中是否完整提取道具ID、发放数量等结构化字段。
- 上传含内嵌图片的活动方案pdf文件，确认解析结果中包含图片的关联说明文本。
- 上传100MB左右的活动复盘报告，检查解析过程未触发超时报错。
- 调整`chunkSize`至800字符，验证分块结果未拆分同一奖励配置的关联行。
