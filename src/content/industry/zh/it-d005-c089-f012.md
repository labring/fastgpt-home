# 漏洞扫描服务的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
漏洞扫描服务的核心数据来自内部漏洞扫描器、企业资产清单、公开CVE库与补丁公告。日常产出的文档包含扫描计划、漏洞清单、整改工单、复扫报告四类。扫描计划包含任务标识、扫描范围、执行配置字段；漏洞清单包含CVE编号、风险等级、影响资产字段；整改工单包含关联漏洞、整改要求字段；复扫报告包含复扫时间、修复验证结果字段。数据更新频率为周度或月度，随扫描任务执行与漏洞库同步更新。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档来源多样，包含结构化表格、纯文本、PDF报告等格式，解析时需适配不同文档的结构特征，避免拆分破坏CVE编号、风险等级等关键关联字段。批量处理周度或月度更新的扫描任务文档时，需控制单文档解析时长与分块数量，防止超时中断。不同来源的数据格式差异较大，公开CVE库条目与内部扫描报告的字段排布不同，需配置适配的分块规则，确保关键漏洞信息完整保留。同时，高危漏洞数据的解析准确性直接影响后续安全运营，分块时需优先保留高风险等级的漏洞条目，避免因分块拆分导致关键信息丢失。

## 配置怎么定
以下配置项可在FastGPT v4.17.0的技术文档解析模块中调整：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | `800–1200 字符` | 该品类的漏洞描述与整改要求多为长文本，800–1200字符的分块长度可保留单条漏洞信息的完整性，避免拆分关键关联字段 |
| `chunkSplitter` | 按段落与标题拆分 | 扫描计划、漏洞清单等文档存在明确的标题与段落层级，按此规则拆分可保留文档的逻辑结构，便于后续检索关联漏洞信息 |
| `customPdfParse` | 启用 | 该品类的复扫报告多为PDF格式，启用自定义PDF解析可正确提取表格中的CVE编号、风险等级等结构化字段，避免纯文本解析导致的字段丢失 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 批量扫描任务的复扫报告可能包含大量资产扫描数据，1000 MB的上传上限可满足批量文档的上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型复扫报告的解析耗时较长，600秒的超时设置可避免因解析超时导致的任务中断 |
| `chunkSettingMode` | 手动配置 | 该品类的文档结构差异较大，手动配置可针对不同文档类型调整分块规则，适配扫描计划、漏洞清单等不同文档的解析需求 |

## 容易做错的三处
- 现象：配置飞书知识库同步后，上传PPT或PDF文档至知识库时，分块预览界面返回「无法读取该文件内容」。原因：未启用`customPdfParse`配置，默认解析规则无法适配飞书同步文档的加密格式与表格嵌套结构。
- 现象：本地部署FastGPT v4.8.12版本时，上传包含复杂数学公式的漏洞报告，解析后返回的分块内容无法正确显示公式结构，线上v4.9.0版本可正常返回公式解析结果。原因：不同版本的内置文档解析模块存在功能差异，低版本未适配复杂公式的排版识别与OCR逻辑。
- 现象：执行docker run --gpus all -itd -p 7231:7231 marker_images:v0.1命令启动解析服务时出现报错。原因：启动命令参数格式错误，或本地GPU驱动版本与镜像要求不匹配，导致容器无法正常拉起解析进程。

## 怎么确认配好了
- 上传单份扫描计划文档，检查解析后的分块内容是否保留了任务标识、扫描范围等关键字段，无明显内容丢失。
- 调整`chunkSize`配置后，上传包含长文本漏洞描述的文档，核对分块长度是否符合预设的取值区间。
- 启用`customPdfParse`配置后，上传复扫报告PDF，检查表格中的CVE编号、风险等级等结构化字段是否被正确提取。
- 上传批量文档，确认解析任务未在预设的`PARSE_FILE_TIMEOUT_SECONDS`时长内出现超时中断。
