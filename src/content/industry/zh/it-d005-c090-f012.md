# 版本发布与Release Notes的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
该品类的核心数据为版本发布与Release Notes相关文档，日常使用的文档包括变更日志、版本标签说明、发布检查单等。数据来源主要为Git仓库标签、合并提交记录、CI/CD流程生成的制品文件、Issue里程碑跟踪记录。数据更新频率为每版本发布一次，每条数据包含版本号、变更类型、关联提交、影响范围等字段。文档结构通常以版本号作为起始标识，后跟多条按类型分类的变更条目，部分文件会附带发布前的检查项与制品下载链接。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的数据以版本为单位更新，要求解析分块需严格匹配版本边界，避免跨版本内容混淆。数据来源包含结构化的提交记录与非结构化的文本日志，需同时适配两种格式的解析规则。变更归类是该品类最耗时的环节，分块需保证每条变更条目完整落在单个块内，避免拆分导致归类困难。出错后可能引发用户升级失败或社区误解，因此分块需准确识别破坏性变更、关键修复等核心内容，不可遗漏或错误合并。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的功能逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | `800–1200 字符` | 该品类的单条变更条目长度集中在数百字符区间，此设置可保证单块包含完整变更信息，避免跨条目拆分 |
| `chunkSplitter` | `按版本标签+换行符拆分` | Release Notes通常以版本号作为文档起始标识，按此规则可保证每个分块对应一个完整版本的变更集合 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 该品类相关的CI制品与日志文件通常不会超过该大小，此设置可避免无效的大文件上传请求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 批量处理多版本的Release Notes文件时，需预留足够时间完成解析与分块，避免中途解析中断 |
| `customPdfParse` | `启用版本标签匹配规则` | PDF格式的Release Notes中，版本号通常以标题或加粗形式呈现，启用自定义解析规则可准确识别分块起始点 |
| `chunkSettingMode` | `手动配置` | 该品类的文档结构固定，手动配置分块规则可适配版本标签与变更条目的特定格式，无需依赖通用分块逻辑 |

## 容易做错的三处
- 解析后分块包含多个版本的变更条目，现象为不同版本的变更内容被合并到同一分块中。原因是未配置`chunkSplitter`为按版本标签拆分，使用通用换行分块规则导致跨版本内容合并。
- 解析过程超时并返回504状态码，现象为文件解析进度停滞超过预设时间。原因是`PARSE_FILE_TIMEOUT_SECONDS`设置值小于实际批量解析所需时间，或未针对多版本文件调整超时参数。
- Excel格式的变更日志导入后，多条单行内容被合并为一个分块。现象为单个分块包含Excel表中多行变更条目。原因是未启用按行分隔的分块规则，或未配置自定义分隔符匹配Excel行结束标记，对应社区常见的导入拆分异常问题。

## 怎么确认配好了
- 上传单条版本的Release Notes文件，查看解析后的分块列表，确认每个块对应一个版本或一组相关变更条目。
- 批量上传3个以上版本的Release Notes文件，检查解析耗时是否在`PARSE_FILE_TIMEOUT_SECONDS`设置范围内。
- 导入Excel格式的变更日志，检查每个分块是否对应Excel表中的单行内容。
- 针对分块中的变更条目发起测试问答，确认相关变更信息可被准确召回。
