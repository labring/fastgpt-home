# 现场部署实施的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自客户现场机房环境、设备清单、软件安装包、网络拓扑图等一手资源，日常产出部署手册、安装记录、配置清单、现场签到表四类文档。数据更新节奏为每执行单阶段任务或完成单订单更新一次，文档字段包含部署节点标识、软件版本号、配置参数值、现场签到时间等，无统一固定的通用字段格式，需匹配客户现场的实际部署要求。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来自客户现场的实时资源且按单阶段更新，引用溯源需确保匹配当前部署的软件版本与现场节点，避免调用过期的历史配置数据。非标准化的现场文档结构要求溯源支持自定义字段的匹配逻辑，不依赖固定格式的通用字段。单订单独立更新的特性，要求溯源上下文按单任务隔离，防止跨订单的配置数据混淆。同时现场部署的资源多为离线或本地文件，溯源需支持本地文件的直接关联与权限校验。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的后台逻辑，具体如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配现场部署文档的平均单段长度，确保引用内容完整覆盖部署步骤与配置参数 |
| `responseData` | 开启本地文件关联模式 | 适配现场部署的离线文档来源，直接关联本地存储的部署手册与配置清单 |
| `detail` | 开启详细溯源模式 | 展示现场文档的具体字段，如设备型号、安装时间等，满足实施工程师的排查需求 |
| 最大上下文轮次 | 前3轮对话上下文 | 限制单订单内的上下文范围，避免跨单数据干扰，符合现场部署按单执行的特性 |
| 引用匹配阈值 | 0.75–0.85 | 适配现场文档的非标准化格式，平衡召回精度与覆盖范围，按实测标定 |

## 容易做错的三处
- 现象为免登录分享链接访问应用时，即使关闭引用查看功能，界面仍显示引用来源弹窗。原因是未在应用配置中同步关闭分享场景下的溯源权限开关，导致配置未覆盖全访问渠道。
- 现象为FastGPT回复仅返回引用列表，无任何正文内容。原因是`quoteMaxToken`取值过小，无法容纳正文内容，仅加载了引用元数据。
- 现象为多轮对话中无法关联前一轮的现场部署配置信息。原因是未配置按单任务隔离的上下文范围，导致跨轮次的上下文被清空或混淆。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的应用后台上传一份现场部署的配置清单，发起相关问答，核对返回结果中是否包含配置字段的引用溯源链接。
- 调整`quoteMaxToken`的取值，测试不同长度的引用内容是否能完整加载，确认无截断或丢失。
- 切换免登录分享模式，验证引用查看功能是否随配置同步生效或关闭。
- 发起跨轮次的部署排查问答，确认上下文是否保留前一轮的现场节点信息。
