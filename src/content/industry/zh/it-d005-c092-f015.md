# 现场部署实施的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自客户机房环境、设备清单、软件包、网络拓扑等现场一手资源，日常产出部署手册、安装记录、配置清单、现场签到表等文档。数据更新节奏为每单或每实施阶段一次，单份数据包含设备型号、IP地址、软件版本、配置参数、现场签到信息等字段，无统一固定单位，随现场实际环境调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据多为单次项目的临时资源，更新频率为每单或每实施阶段一次，要求知识库检索能快速适配新增的单份项目数据。文档包含部署步骤、配置参数、现场记录等多种类型，字段无统一固定格式，要求召回环节能兼容不同结构的文本内容。数据来自客户现场环境，存在敏感信息，要求检索范围限定在当前项目关联的数据集内，避免跨项目数据泄露。单份数据体量随项目复杂度波动，需适配不同数据量的检索响应要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，针对现场部署实施的场景优化：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配现场部署的配置参数类文本，避免过低引入无关结果，过高遗漏有效配置项 |
| `limit` | 前3–5条 | 现场部署的文档多为单项目专用，少量结果即可覆盖现场排查需求，避免过多信息干扰 |
| `usingReRank` | 开启 | 现场部署的步骤类文本存在相似表述，重排可提升关键步骤的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充客户现场的环境描述作为扩展查询，提升对现场特定设备的召回精度 |
| `collectionIds` | 绑定当前项目的专属数据集ID | 限定检索范围为当前项目的部署文档，避免跨项目数据泄露 |

## 容易做错的三处
- 调用知识库接口创建文件集合后索引速度缓慢。原因是未限定当前项目的`collectionIds`范围，检索时扫描了全量数据集，增加了检索开销。
- 上传文件时出现`upstream connect error or disconnect/reset before head`报错。原因是未配置当前项目数据集的本地部署网络策略，导致接口调用时无法连接到本地向量库服务。
- Excel导入后自动拆分结果为多行合并为一条。原因是未正确设置自定义分隔符，未将每行作为独立的问答条目拆分，未匹配现场部署文档的单行记录格式。

## 怎么确认配好了
- 调用知识库接口传入当前项目的`collectionIds`参数，检查返回结果仅包含当前项目的部署文档、安装记录等专属数据。
- 输入现场设备的IP地址或软件版本作为查询词，检查召回结果包含对应的配置清单内容。
- 上传Excel文件并设置自定义分隔符，检查导入后每条记录对应Excel的一行内容。
- 触发检索后查看重排后的结果顺序，确认关键部署步骤排在前列。
