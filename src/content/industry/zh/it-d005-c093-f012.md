# 用户增长与留存运营的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
这个品类的典型使用主体为增长运营、用户运营、数据分析师。日常处理的文档包含增长实验方案、用户分层表、触达文案、留存分析报告。数据来源包括用户行为日志、推送系统、实验平台、CRM系统，更新频率多为日度或周度。文档结构包含结构化表格、自然段落文本两类，字段包含用户标识、行为时间、触达记录、实验分组等，无固定统一的单位格式。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档包含多列结构化表格与零散自然文本，要求分块需精准匹配业务单元，避免拆分跨列的用户分层数据。日度或周度的批量数据更新，要求解析流程具备批量处理能力且避免超时中断。多来源的文档格式差异，要求解析模块适配多种文件类型，同时支持自定义分块规则。若分块错误将导致用户分群、实验归因环节出错，进而引发用户反感或预算浪费，因此分块需严格对应业务字段的边界。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配增长实验方案、留存分析报告的常规段落长度，避免拆分核心业务单元 |
| `chunkSplitter` | 按行分割（Excel）、按段落分割（文本） | 匹配不同文档的结构特征，例如用户分层表需按行拆分以保留单条用户数据完整性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配批量解析周度用户行为日志的耗时需求，避免大型文件解析中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持上传较大体量的日度用户行为数据集，满足批量解析需求 |
| `chunkSettingMode` | 手动配置 | 针对结构化文档自定义分块规则，规避自动分块的混乱结果 |

## 容易做错的三处
- 多列Excel文档自动分块结果混乱，每行内容被拆分到不同分段中。原因是未针对结构化表格配置按行分割的分块规则，使用了默认的段落分割逻辑。
- 单次解析时批量加载历史上传的文档，仅处理当前上传附件的配置未生效。原因是未开启单文件独立解析模式，系统默认关联了历史知识库的解析批次。
- 上传图片格式的测试文档后，模型无法识别图片内容。原因是未启用FastGPT v4.17.0的图片解析配置，或未配置对应的解析参数。

## 怎么确认配好了
- 上传一份包含多列的测试Excel文档，查看分块结果，确认每行内容对应一个独立分段。
- 上传单份测试文档后，查看解析日志，确认仅当前上传的文件被加载，无历史文档关联。
- 调用API上传图片格式的测试文档，发起对应问答请求，验证模型可返回图片相关的有效内容。
- 上传单份PDF文档，配置单文档检索参数，发起问答请求，验证仅该文档的内容被用于回答。
