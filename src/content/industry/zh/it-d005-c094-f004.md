# 用户验收测试支持的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来源为需求规格文档、测试环境配置、客户业务样例数据与缺陷系统记录。日常使用与维护的文档包括UAT用例、验收问题单、验收报告及签字确认单，维护主体为实施顾问、测试经理与客户业务代表。数据更新节奏为每项目阶段或每版本迭代一次，文档字段包含用例步骤、预期结果、问题描述、复现环境等，无统一固定单位，随文档类型与业务场景调整。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且覆盖多类业务文档，要求索引支持跨源异构数据的关联召回；更新按阶段或版本批量触发，无需实时增量索引，适合全量构建的索引策略；日常文档结构差异较大，分块策略需适配不同文档的语义单元长度；验收场景对匹配精准度要求较高，需保障向量召回与业务场景的强关联，避免低置信度的无效匹配。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写，适配本品类的业务数据特征：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配UAT用例、验收问题单的单段语义完整性，避免语义拆分过度 |
| 重叠长度 | 100–150 字符 | 保留相邻块的上下文关联，适配验收文档的步骤连贯性 |
| 相似度阈值 | 0.75–0.85 | 保障业务场景匹配的精准度，降低验收问题的误召回率 |
| 单次搜索上限 | 前 6–10 条 | 覆盖单项目阶段的典型验收问题数量，平衡召回效率与召回范围 |
| maxToken | 3500–4500 token | 适配验收相关文档的上下文长度，满足完整用例或问题单的语义召回 |
| defaultToken | 120–180 token | 控制单条向量的存储成本，适配按阶段批量构建的索引规模 |

## 容易做错的三处
- 导出的知识库dataset.csv仅包含index字段无content字段。原因是未正确配置分块后的内容提取规则，仅同步了索引元数据未关联原始文本内容。
- 内网Docker部署后无法加载自定义索引模型。原因是未将模型文件挂载至容器内的指定路径，或未在配置文件中正确声明模型调用地址。
- 导入文本时使用默认分块参数截断了完整业务内容。原因是未根据验收文档的语义长度调整分块设置，导致向量匹配无法关联完整的用例步骤或问题描述。

## 怎么确认配好了
- 执行一次单份UAT用例文档的索引构建，查看任务日志中是否存在分块失败或向量生成失败的报错。
- 发起一条验收相关的检索请求，验证返回结果是否包含匹配的业务文档，且排序符合预期的置信度规则。
- 查看知识库的索引统计页面，确认已生成的向量数量与导入的文档数量匹配。
- 调整相似度阈值后，验证检索结果的数量变化是否符合配置调整的预期。
