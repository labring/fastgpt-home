# 用户验收测试支持的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来源为需求规格文档、测试环境配置、客户业务样例数据与缺陷管理系统记录。日常产出的文档包含UAT用例、验收问题单、验收报告与签字确认单，由实施顾问、测试经理与客户业务代表维护更新，更新节奏为每测试阶段或每软件版本迭代一次。数据字段包含用例步骤、预期结果、问题复现路径、验收结论等，无统一固定单位，随业务场景调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且关联特定测试阶段，要求溯源时需绑定对应版本的测试环境与需求文档，避免跨阶段数据混淆。更新频率随版本迭代，需确保引用的文档与当前验收阶段匹配，无法直接复用通用业务文档的溯源逻辑。日常产出的签字确认单等文档需明确关联对应验收环节，溯源时需保留可追溯的关联标识。UAT用例的步骤与预期结果字段需精准匹配，确保引用内容与验收场景一致，保障验收结论的可信度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 14000–16000 token | 适配多份UAT用例与验收文档的总长度，避免截断溯源信息 |
| 单次搜索上限 | 前3–5条 | 控制检索返回的文档数量，平衡溯源准确性与查询效率 |
| `quoteMaxToken` | 7000–11000 token | 限制单份引用文档的token长度，适配大模型的输入限制 |
| 引用来源过滤 | 绑定测试阶段ID | 确保溯源信息与当前验收环节匹配，避免跨阶段数据混淆 |
| `responseData` | 包含文档类型与创建时间 | 保留溯源所需的关键元数据，便于验收报告的归档核对 |
| `detail` | 仅保留关联字段 | 精简引用内容，聚焦UAT用例步骤与缺陷复现路径 |

## 容易做错的三处
- 现象：工作流中调用知识库工具后，返回结果未显示引用来源。原因：未配置`responseData`参数开启来源返回，或未绑定对应验收阶段的知识库权限。
- 现象：知识库查询耗时过长，单次检索消耗超出预期的token量。原因：`quoteMaxToken`设置为过高区间，导致每次检索加载全量文档内容，超出业务实际需求。
- 现象：引用的文档与当前验收阶段不匹配，出现跨版本用例。原因：未配置引用来源过滤规则，未绑定测试阶段ID，导致检索到历史阶段的文档。

## 怎么确认配好了
- 发起一次UAT用例相关的问答，检查返回结果中是否包含文档来源路径与创建时间。
- 调整`quoteMaxToken`的取值，验证检索返回的文档长度是否符合当前验收阶段的文档规模。
- 测试多知识库关联场景，确认仅当前阶段的文档被正确引用。
- 查看FastGPT v4.17.0版本的工具调用日志，确认返回的`detail`字段包含UAT用例的关键步骤信息。
