# 用户验收测试支持的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
本品类的核心数据来自需求规格文档、测试环境输出、客户业务样例及缺陷管理系统，更新频率为每阶段或每版本。日常处理的文档包含UAT用例、验收问题单、验收报告与签字确认单，其中UAT用例包含测试步骤、预期结果、实际结果等结构化字段，验收问题单包含缺陷ID、复现步骤、严重等级等字段，签字确认单则包含非结构化的签字日期与业务确认信息。

## 这些特征在「文档解析与分块」这一环带来什么约束
多来源的文档格式差异要求解析环节适配PDF、图片、文本等多种格式；按阶段/版本更新的特性要求分块规则可灵活调整，适配不同版本的文档结构；结构化的UAT用例与验收问题单要求分块保留字段关联性，避免拆分破坏业务逻辑；非结构化的签字确认单则要求解析环节支持扫描件文本提取。此外，验收环节的时效性要求解析与分块流程不能出现超时或错误，否则将直接影响验收进度，甚至引发范围争议。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，具体如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配UAT用例单条测试步骤与预期结果的整体长度，避免拆分破坏业务逻辑关联性 |
| `chunkSplitter` | 按段落拆分 | 匹配验收问题单的缺陷复现步骤分段规则，便于精准召回对应缺陷的上下文 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 覆盖大型验收报告的完整解析耗时，避免因超时导致文档解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量上传的多份验收报告组合包，满足阶段验收的文档提交需求 |
| `customPdfParse` | 开启 | 适配扫描版签字确认单的非结构化PDF格式，提升文本提取准确率 |
| `chunkSettingMode` | 手动配置 | 针对不同类型的UAT文档灵活调整分块参数，兼顾结构化与非结构化文档的解析效果 |

## 容易做错的三处
- 现象：调用文件解析接口时返回`413 Request Entity Too Large`错误。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，超过默认限制导致大型验收报告上传失败。
- 现象：解析后的UAT用例分块丢失测试步骤序号。原因：使用了按字符拆分的`chunkSplitter`，未按段落拆分导致序号与对应步骤分离，无法完整还原用例逻辑。
- 现象：工作流调用图片解析接口后返回空结果。原因：未在接口配置中启用VLM解析能力，导致上传的测试环境截图无法被正确解析。

## 怎么确认配好了
- 上传单份标准UAT用例PDF，检查解析后的分块是否保留完整的测试步骤与预期结果，无字段拆分断裂情况。
- 调用文件上传接口，上传超过默认大小的验收报告组合包，确认接口返回正常无超时或大小限制错误。
- 开启`customPdfParse`后上传扫描版签字确认单，确认解析后的文本可正常检索到签字日期与确认人信息。
- 调整`chunkSize`为800–1200字符区间，对比解析后的分块结果，确认符合当前处理文档的结构拆分需求。
