# 监控告警配置的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
本品类的核心数据来自运维工程师、SRE团队及平台工程团队的日常运维文档与监控系统，包括监控指标清单、告警规则、值班手册、告警变更记录。数据来源涵盖Prometheus、Zabbix、云监控、应用日志及CMDB系统，更新频率为每日或每次配置变更时。文档结构按运维场景分层，监控指标清单包含指标名称、采集周期、阈值范围，告警规则包含触发条件、通知对象与链路，字段多带明确单位，如采集周期以秒为单位，阈值以百分比或数值为单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多数据源的混合来源要求引用溯源环节支持跨系统的来源标注，避免混淆不同监控平台的告警配置。日级或变更级的更新频率要求配置合理的引用刷新周期，确保问答使用的是最新的告警规则与指标数据。文档分层结构与带单位的字段要求溯源时保留原始文档的层级与单位信息，防止丢失告警配置的关键细节。长文本的告警变更记录与指标清单则要求控制引用的总长度，避免超出模型的上下文限制。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.75–0.85 | 匹配告警规则与指标清单的精准匹配需求 |
| 单次搜索上限 | 前10条 | 覆盖常用的告警规则、指标清单数据量 |
| 最大上下文 | 800–1200 字符 | 适配告警配置文档的单块内容长度 |
| `quoteMaxToken` | 1500 token | 容纳告警变更记录的多段引用内容 |
| `responseData` | 开启字段溯源 | 保留告警配置的原始字段与单位信息 |
| `detail` | 开启完整引用 | 包含告警规则的触发条件与通知链路信息 |

## 容易做错的三处
- 连续追问告警配置相关问题时，后续回答脱离前序上下文，无法关联到之前提及的监控指标。原因是最大上下文的取值未覆盖连续提问的上下文长度，或未开启上下文关联配置。
- 问答结果中出现过期的告警阈值或已删除的告警规则。原因是未设置引用来源的刷新周期，或刷新周期长于告警配置的日级或变更级更新频率。
- 接口调用返回的引用数据为空或仅包含部分字段。原因是`quoteMaxToken`取值过小，无法容纳告警配置的完整文本内容，导致引用被强制截断。

## 怎么确认配好了
- 发起包含告警阈值查询的连续提问，验证后续问题的回答是否关联前序提问的监控指标名称。
- 查看问答结果的引用溯源模块，确认显示的文档来源与实际使用的监控系统一致。
- 调整`quoteMaxToken`取值后，验证长文本的告警变更记录是否完整显示在引用内容中。
- 触发告警配置的更新操作，等待刷新周期结束后，验证问答结果是否同步更新为最新的告警规则。
