# 移动端开发的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自iOS、Android及跨端开发团队的日常产出与业务系统。日常文档包含端版本发布单、机型适配清单、崩溃分析报告、应用商店审核资料等。数据来源覆盖代码仓库、应用商店后台、崩溃监控平台、机型覆盖数据库。更新频率多为每日或每版本发布周期。数据字段包含机型版本号、权限配置项、崩溃日志堆栈、应用商店提交状态等，无统一固定单位，随文档类型动态变化。

## 这些特征在「向量模型与索引」这一环带来什么约束
移动端开发的文档类型多样且更新节奏随版本波动，导致分块策略需适配不同文档结构。崩溃分析报告包含长堆栈信息，需调整分块边界避免截断关键日志；应用商店资料多为短文本，需匹配更紧凑的分块逻辑。数据来源分散导致向量索引需兼容多格式数据源，且需按版本更新频率调整索引刷新周期，避免索引与实时数据脱节。机型覆盖数据的字段维度多，向量计算时需优先匹配高权重字段，防止低价值数据稀释检索精度。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配崩溃分析报告的长文本与应用商店资料的短文本混合场景，避免单块内容过长或过短 |
| 重叠长度 | 50–100 字符 | 保留跨分块的上下文关联，防止版本发布单中的跨页流程被截断 |
| `maxToken` | 4096 token | 匹配多数开源嵌入模型的输入上限，适配跨端开发文档的长文本块 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配度的机型适配结果，避免检索到不相关的旧版本配置 |
| 单次搜索上限 | 前 8 条 | 适配移动端开发的高频检索场景，控制返回结果的冗余度 |
| `defaultToken` | 1024 token | 统一短文本文档的向量计算输入长度，平衡精度与计算开销 |

## 容易做错的三处
- 导入数据后长期显示创建索引中：未适配移动端文档的多格式混合场景，索引构建任务未按更新频率拆分，导致大体积的崩溃分析报告块占用过长计算资源。
- 向量计算得分异常且结果一致：未调整分块长度适配短文本的应用商店资料，导致所有短文本块的向量特征被嵌入模型统一映射，丢失区分度。
- 向量化流程耗时过长：未针对机型覆盖数据的高维度字段做前置过滤，将低价值数据纳入向量计算，导致整体计算开销超出服务器承载能力。

## 怎么确认配好了
- 查看索引构建日志，确认单块文本的分块长度符合预设区间，无异常截断的日志片段。
- 检索指定机型的适配文档，核对返回结果的相似度得分分布符合预期区间，无全量一致的异常结果。
- 模拟每日版本更新的数据导入流程，确认索引刷新耗时符合预设阈值，无长期挂起的任务。
- 核对向量模型的`maxToken`参数匹配当前使用的嵌入模型输入上限，避免触发截断报错。
