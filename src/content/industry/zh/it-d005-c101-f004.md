# 续费健康度管理的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自CRM系统、产品使用数据、工单统计与合同台账，更新频率多为周度或月度。日常处理的文档包含客户健康度报告、续费预测表、风险客户清单与沟通纪要，数据字段涵盖客户标识、合同金额、到期日期、活跃天数、工单响应时长等，对应单位包含元、天、次等。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于数据来源包含结构化表格与半结构化文本，索引需要同时适配字段拼接与自然语言语义的检索需求；周/月级的更新频率无需实时索引刷新，可采用增量更新模式降低资源消耗；不同文档类型的长度差异较大，比如续费预测表多为短字段组合，沟通纪要则为长文本，分块与索引配置需兼顾不同文档的语义完整性；多字段的单位关联要求分块时保留上下文关联，避免语义断裂影响检索精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配续费预测表、沟通纪要等长短文本的语义完整性 |
| 重叠长度 | 100–200 字符 | 避免分块切断合同到期日、客户风险等级等关键关联上下文 |
| 相似度阈值 | 0.72–0.80 按实测标定 | 平衡风险客户识别的召回率与精准度 |
| 单次搜索上限 | 前 10 条 | 适配批量风险客户清单的快速检索需求 |
| `defaultToken` | 4096 | 承载客户健康度报告的多字段拼接上下文 |
| `maxToken` | 8192 | 覆盖续费预测表的全量字段与关联沟通纪要内容 |

## 容易做错的三处
- 界面显示「索引未就绪」时直接发起检索，返回空结果或状态码400。原因是索引构建未完成，或分块长度超出模型支持的最大输入限制。
- 直接将整表的某几列作为知识库索引，未按文档类型拆分分块。原因是忽略了不同字段的语义关联，导致检索结果无法匹配客户风险的完整上下文。
- 在部署deepseek模型时未正确配置对应的向量模型关联参数，导致向量模型调用报错。原因是未绑定与deepseek适配的向量模型，或参数配置格式错误。

## 怎么确认配好了
- 进入FastGPT v4.17.0的索引管理页面，查看目标索引的状态标识，确认显示就绪。
- 上传单份测试用的风险客户清单片段，执行检索测试，确认返回结果的条数匹配单次搜索上限的设置。
- 查看向量模型的绑定配置，确认已选择适配的模型类型，比如Doubao-embedding。
- 调用测试接口传入续费相关的查询词，检查返回上下文的token数未超出`maxToken`的限制。
