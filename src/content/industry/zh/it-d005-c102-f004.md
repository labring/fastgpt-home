# 缺陷管理与回归测试的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
这个品类的典型数据来自缺陷管理系统、测试报告、代码提交与用户反馈，日常文档包含缺陷单、回归清单、修复验证记录与缺陷统计报表。缺陷单包含缺陷ID、复现步骤、优先级、关联版本号等字段，回归清单按测试用例ID、关联缺陷、验证状态组织内容。数据更新频率为每日或每版本发布周期，单条数据文本长度跨度较大，既有短文本的优先级标签，也有数百字符的复现步骤描述。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源的多样性要求索引支持结构化与半结构化文本的混合嵌入，高频更新频率需要索引具备增量更新能力，避免全量重建的耗时问题。缺陷单与回归清单的文本长度差异，要求分块策略适配不同长度的内容单元，防止过短导致语义断裂或过长导致嵌入精度下降。高优缺陷遗漏的出错后果，要求召回环节的阈值设置需兼顾准确率与召回率，避免关键缺陷被过滤。按版本更新的数据特征，需要索引支持按版本维度的分组检索，提升回归测试的查询效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配缺陷单复现步骤、回归清单用例的文本长度，平衡语义完整性与嵌入效率 |
| 重叠长度 | 100–200 字符 | 保留跨块的上下文关联，确保缺陷复现步骤的完整语义传递 |
| `maxToken` | 8192 token | 匹配主流嵌入模型的输入上限，适配批量缺陷统计报表的文本处理需求 |
| `defaultToken` | 1024 token | 适配单条缺陷单的问答场景，控制单轮上下文的token消耗 |
| 单次搜索上限 | 前 10 条 | 覆盖当前版本的回归测试用例与关联缺陷的召回范围，避免冗余结果 |
| 相似度阈值 | 0.75–0.85 | 区分高优缺陷与普通缺陷的语义匹配度，减少误召回与漏召回 |

## 容易做错的三处
- 上传缺陷相关文件后无法确认索引完成状态，表现为接口返回成功但向量索引未生成或数据未同步，原因是未配置索引生成的回调通知或轮询校验逻辑。
- 选用未适配短文本的嵌入模型，表现为高优缺陷的语义匹配度低于普通缺陷，原因是未针对缺陷单的短标签与长步骤混合文本调整模型选择。
- 未限制`maxToken`导致上下文溢出，表现为接口返回token超限报错，原因是未按缺陷数据的平均文本长度调整`maxToken`的取值。

## 怎么确认配好了
- 上传单条标准缺陷单文件，在FastGPT v4.17.0的日志系统中查看分块记录，确认分块数量与预设的分块长度匹配。
- 发起针对特定缺陷的问答查询，核对返回结果的相似度分值处于预设的阈值区间内。
- 调用token统计接口，验证单轮查询的token消耗与`defaultToken`、`maxToken`的配置参数一致。
- 模拟版本更新后的增量上传操作，确认索引更新的耗时符合每日或每版本的更新节奏要求。
