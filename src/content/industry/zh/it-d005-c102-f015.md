# 缺陷管理与回归测试的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据主要来自缺陷管理系统、测试报告、代码提交记录与用户反馈。日常产出的文档包括缺陷单、回归测试清单、修复验证记录、缺陷统计报表。数据更新频率为每日或每版本发布周期，单条数据包含缺陷ID、优先级、复现步骤、关联版本、修复状态等字段，结构围绕缺陷从发现到闭环的全生命周期展开，不同文档类型的字段格式存在差异，结构化文档字段明确，非结构化文档多为测试步骤与验证描述。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类数据围绕缺陷生命周期展开，字段关联紧密且包含版本、优先级等关键属性，检索时需精准匹配关联维度以提升召回相关性。数据更新频率较高，需保障同步链路稳定，避免召回过时的缺陷状态信息。文档类型涵盖结构化缺陷单与非结构化测试报告，需适配多格式的解析与召回逻辑。单条数据关联条目较多，需合理控制召回结果数量，避免上下文溢出影响回答准确性。同时，缺陷相关信息的时效性要求高，召回结果需优先匹配当前版本的缺陷与回归任务。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的知识库功能，具体配置项与取法如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配缺陷复现步骤与优先级的精准度需求，避免召回无关缺陷条目 |
| `limit` | `前 8 条` | 平衡上下文长度与召回覆盖范围，适配缺陷关联信息较多的场景 |
| `searchMode` | `vector` | 针对结构化缺陷字段与非结构化测试步骤的混合检索需求，兼顾精准度与召回范围 |
| `usingReRank` | `开启` | 提升高优先级缺陷与核心回归测试内容的召回排序准确性，优先展示关键信息 |
| `datasetSearchUsingExtensionQuery` | `开启` | 基于缺陷ID、版本号等字段扩展检索范围，覆盖关联的修复记录与验证报告 |
| `collectionIds` | `指定当前项目的缺陷管理与回归测试数据集ID` | 隔离无关业务数据集，保障召回范围精准聚焦于当前研发测试场景 |

## 容易做错的三处
-  回复内容包含知识库外的技术信息，原因是未开启严格的知识库内容限定配置，导致模型调用外部信息生成回答。
-  检索docx格式文档的结果未包含章节标题信息，原因是未开启文档扩展检索配置，仅召回纯正文内容未关联章节结构。
-  调用创建文件集合接口时传入`metadata`字段无预期效果，原因是未查阅官方接口文档，误将非标准参数传入接口。
-  回复中自动附加知识库内容的引用链接，原因是未关闭检索结果的引用标记配置，导致链接被自动携带到回答中。

## 怎么确认配好了
-  上传一份标准缺陷单文档，执行检索测试，检查召回结果是否包含关联的版本与优先级字段信息。
-  调用知识库检索接口传入`similarity`参数，验证返回结果的相似度是否符合预设区间。
-  模拟更新缺陷数据后触发同步，检查知识库是否能在预设周期内完成数据更新。
-  发起不包含缺陷管理相关内容的问题提问，确认回答无法生成知识库外的相关信息。
