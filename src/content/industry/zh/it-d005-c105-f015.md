# 许可证合规与版权声明的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据核心来自开源代码仓库、第三方依赖清单、官方许可证文本与项目贡献记录。日常维护的文档包括项目根目录的LICENSE文件、NOTICE声明文件、批量生成的依赖许可证清单，以及精准到每个贡献者的版权归属记录。数据更新随项目版本迭代或第三方依赖变更触发，无固定周期。单条数据包含许可证类型、版权持有者、版本号、依赖包标识等字段，部分贡献记录还包含提交哈希与授权范围。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据分散于代码仓库、依赖清单与贡献记录等多源，要求检索环节需覆盖跨数据源的召回逻辑，避免遗漏分散的许可证与版权信息。数据更新随版本或依赖变更触发，无固定周期，要求知识库同步机制需适配动态更新节奏，确保检索结果与最新合规文档一致。单条数据包含多维度字段，检索时需匹配许可证类型、版权持有者等关联信息，仅依靠单一关键词无法覆盖全部检索需求。同时合规场景对召回准确率要求严格，漏召回关键许可证将直接导致合规风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 匹配许可证文本与版权声明的专业术语精准度要求，避免低相关的通用文本混入检索结果 |
| `limit` | 前10条 | 覆盖常见许可证类型与依赖项的召回量，平衡检索效率与合规内容的完整性 |
| `usingReRank` | 开启 | 优化多字段匹配后的结果排序，提升合规相关内容的优先级，强化关键信息的展示 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索词，覆盖许可证别名、依赖包常用名称等变体，避免漏检相似合规内容 |
| `collectionIds` | 按合规文档专属集合指定 | 限定检索范围至LICENSE、NOTICE等合规类文档，排除无关的项目代码或测试内容 |
| `searchMode` | 混合检索 | 结合关键词匹配与语义匹配，适配许可证文本的专业术语与依赖包名称的检索需求 |

## 容易做错的三处
- 配置`usingReRank`开启后，检索任务返回500状态码或返回空的重排结果。原因：未正确配置重排模型的部署路径与访问权限，导致模型加载失败。
- 检索结果条数不足，无法覆盖所有相关许可证与版权声明。原因：`limit`取值过低，或未开启`datasetSearchUsingExtensionQuery`导致漏检许可证别名、依赖包变体名称等关键词。
- 检索结果混入非合规类文档内容。原因：未指定`collectionIds`限定检索范围，导致检索覆盖了无关的项目代码或测试文档。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的后台配置界面中，手动输入一条许可证文本关键词，检查检索结果是否包含对应LICENSE或NOTICE文件内容。
- 查看检索日志，确认`usingReRank`参数已生效，重排后的结果排序符合合规内容优先级。
- 核对`collectionIds`参数，确认检索范围仅包含合规类文档集合，无无关内容混入。
- 触发一次依赖清单更新的同步任务，检查知识库是否自动拉取了新的依赖许可证信息。
