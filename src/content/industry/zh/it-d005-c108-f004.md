# 质保期缺陷响应的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自客户提交的质保工单、系统运行日志、项目合同质保条款、软件版本更新记录。日常产出的文档包括质保工单、缺陷确认单、修复执行记录、客户确认单。数据更新节奏为每日批量同步或随单生成，单条数据包含工单编号、缺陷描述、责任边界判定、修复方案、客户反馈等字段，部分内容为非结构化文本，无统一固定格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源分散的数据来源要求向量模型支持跨格式文本的统一向量化处理；灵活的更新节奏需要索引系统适配日级批量更新与单条实时增量更新，避免延迟影响响应速度。非结构化且字段多样的文档内容，要求向量模型具备较强的语义提取能力，同时索引结构需支持按工单编号、责任方等字段的精准过滤。数据间存在强关联（如同一缺陷的多份记录），索引需支持关联召回，避免重复匹配无效内容，提升检索效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配质保工单、缺陷确认单等文档的单段语义完整性，避免块内语义断裂 |
| 重叠长度 | 100–200 字符 | 保留相邻块的语义关联，防止跨块缺陷描述被拆分丢失关键信息 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配度的非相关工单，同时保留责任边界判断所需的弱关联历史记录 |
| 单次搜索上限 | 前 8 条 | 平衡召回精度与响应速度，适配质保期缺陷响应的单轮问答场景 |
| 索引模型选择 | 按实测标定 | 适配多源非结构化数据的语义提取，兼容工单、日志等不同格式的文本 |
| `maxToken` | 4096 | 容纳完整的缺陷上下文与关联文档，支持责任边界判定的全量信息输入 |

## 容易做错的三处
- 界面无法选择目标索引模型，原因是未在系统配置中添加对应模型的部署信息，或模型版本与FastGPT v4.17.0不兼容。
- 索引召回结果条数不符合业务预期，原因是相似度阈值设置偏离该品类数据的语义分布区间，导致过多无效内容或过少有效内容被召回。
- 调用接口时出现超时错误，原因是单次搜索上限设置过高，且未限制`defaultToken`的取值，导致向量检索与上下文拼接耗时超出阈值。

## 怎么确认配好了
- 上传单条质保工单文档，查看索引生成日志，确认无报错且块划分符合预设长度。
- 输入典型缺陷描述，验证召回结果包含关联的修复记录与客户确认单，匹配度符合业务判断标准。
- 通过接口调用测试，输入预设问题，确认返回结果包含正确的责任边界判定相关文档片段。
- 触发批量索引更新任务，查看系统后台日志，确认日级同步任务正常执行无延迟。
