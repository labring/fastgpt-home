# 质保期缺陷响应的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
该品类的数据主要来自客户提交的质保工单、系统运行日志、合同质保条款及项目版本记录。日常处理的文档包含标准化的缺陷确认单、修复执行记录、客户确认回执单等，包含工单编号、缺陷描述、责任边界标注、修复时限、客户签字状态等字段。数据更新节奏为每日批量同步或随单触发，每份文档对应单次质保缺陷的全流程信息。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档多为半结构化的质保流程单据，夹杂非结构化的缺陷描述与合同条款，且部分单据包含内嵌图片、表格或手写确认标记。数据随单或按日更新，单份文档体量通常较小但关联信息需完整保留。若分块截断责任边界或合同质保条款，会导致后续问答无法准确判断责任归属；若未正确提取内嵌图像与表格内容，则可能丢失客户确认的关键凭证，影响后续闭环判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | `800–1200 字符` | 该品类的文档包含半结构化单据与非结构化描述，该区间可平衡上下文完整性与分块粒度，避免关键条款被截断 |
| `chunkSplitter` | 按段落+标题拆分 | 质保类文档多按流程节点划分段落，按标题拆分可保留责任边界、条款项的上下文关联，适配标准化单据的结构 |
| `customPdfParse` | `开启` | 该品类的pdf文档常包含内嵌图片与表格，开启后可完整提取文本与图像关联信息，避免丢失客户确认凭证 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 秒` | 单份质保文档体量通常较小，该时长可覆盖常规解析耗时，避免因超时导致解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | 该品类的单份文档多为工单、记录类文件，该上限可覆盖多数场景且避免资源浪费 |
| `chunkSettingMode` | 手动配置 | 该品类的文档结构相对固定，手动配置可精准匹配分块规则，适配不同类型的质保单据 |

## 容易做错的三处
- 解析结果中仅提取纯文本，表格与内嵌图片的关联描述缺失。原因是未开启`customPdfParse`配置，导致解析工具忽略非文本类介质信息。
- 分块结果截断了合同质保条款的关键内容，导致后续问答无法识别完整责任边界。原因是`chunkSize`取值过小，将完整的责任边界条款拆分为多个独立分块，丢失上下文关联。
- 解析任务触发后长时间无返回结果，界面显示超时状态码。原因是`PARSE_FILE_TIMEOUT_SECONDS`取值过低，超出单份文档的常规解析耗时，触发超时失败。

## 怎么确认配好了
基于FastGPT v4.17.0版本的解析逻辑，可通过以下动作核对配置是否生效：
- 上传一份包含内嵌图片的质保确认单pdf，检查解析结果是否包含图片的关联描述或标注信息，确认`customPdfParse`配置生效。
- 导入一份完整的合同质保条款文档，查看分块结果是否保留了条款的完整段落，确认`chunkSize`与`chunkSplitter`配置匹配文档结构。
- 上传单份最大体量的测试文档，检查解析任务是否在预设时长内完成，确认`PARSE_FILE_TIMEOUT_SECONDS`取值合理。
- 导出分块后的文本片段，核对是否包含工单编号、责任方等核心字段，确认分块未截断关键信息。
