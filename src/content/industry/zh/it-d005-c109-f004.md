# 身份账号与权限管理的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自企业IAM系统、HR系统、业务系统日志与审批系统。日常产出的文档包括账号申请单、权限矩阵、离职回收单与审计报告。账号申请单包含申请人工号、申请时间、申请权限范围；权限矩阵标注角色ID、关联业务系统与权限项；离职回收单记录员工工号、回收执行时间与回收权限列表；审计报告汇总审计周期内的异常权限条目。数据更新频率为每日或随人事变动触发。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且更新无固定批量周期，会导致索引增量更新时需适配多源数据格式差异。人事变动触发的高频小批量更新，要求索引支持低延迟增量同步，避免全量重建带来的资源消耗。文档字段多为结构化标识类内容，对向量模型的细粒度字段匹配能力有要求。审计报告包含的异常条目多为离散文本，需确保索引能准确召回高相关的权限配置片段。权限矩阵的关联系统字段需与业务系统日志字段对齐，否则会导致召回结果与实际权限不匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配账号申请单、权限矩阵等文档的单块结构化信息长度，避免块内信息割裂 |
| 重叠长度 | 100–200 字符 | 保留跨块的权限关联信息，防止权限矩阵的跨系统权限配置被分块截断 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关的权限条目，避免召回与当前查询无关的历史账号申请记录 |
| 单次搜索上限 | 前 10 条 | 控制返回结果的数量，适配IAM管理员日常查询的权限条目量级 |
| `maxToken` | 4096 个 | 适配审计报告等长文档的向量召回后上下文拼接需求 |
| `defaultToken` | 按实测标定 | 适配不同规模企业的权限数据量，避免 token 溢出或召回不足 |

## 容易做错的三处
- 现象为本地部署FastGPT v4.17.0后，上传权限矩阵等文档时无图片索引模型选项。原因是该功能需在部署时开启商业版插件开关，开源版本默认未加载对应索引模块。
- 现象为增量索引更新后，离职员工的权限残留条目仍被召回。原因是未配置按人事变动触发的增量同步规则，仍使用全量更新模式。
- 现象为查询账号申请单时，返回的结果包含无关的审计报告片段。原因是未设置字段过滤规则，未限定查询范围为账号申请单的文档类型。

## 怎么确认配好了
- 上传一份权限矩阵文档，查看索引生成日志中是否包含角色ID、关联系统等字段的向量嵌入记录。
- 发起一条包含“离职员工权限回收”的查询，核对返回结果中是否包含离职回收单的相关内容。
- 检查增量同步任务的执行记录，确认每日或人事变动时是否自动触发索引更新。
- 调整相似度阈值后，验证低相关结果的过滤效果是否符合预期。
