# 身份账号与权限管理的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据主要来自IAM系统、HR系统、业务系统日志与审批系统。日常产出的文档包含账号申请单、权限矩阵、离职回收单、审计报告。数据更新节奏为每日同步或随人事变动实时更新。文档结构多包含账号标识、权限范围、生效失效时间、审批节点与复核结果等字段，无通用的外部标准化格式，部分文档为离线表单或结构化表格。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据格式导致检索时需要兼容不同字段的语义映射，无法直接使用通用的标准化字段匹配逻辑。数据随人事变动实时更新，要求知识库的召回结果需与最新的权限状态同步，避免召回已失效的离职账号权限信息。内部文档如权限矩阵、审计报告包含敏感权限细节，检索时需严格匹配访问权限，仅向授权用户返回对应结果。日常文档多为结构化表格或离线表单，检索时需针对表格内的权限范围、账号ID等字段做精准匹配，适配结构化文档的检索逻辑。

## 配置怎么定
本页面的配置说明基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 匹配IAM相关的权限描述、账号ID等精准字段，避免低相关的权限文档混入结果 |
| `limit` | 前10条 | 内部IAM文档数量可控，返回足够的权限矩阵、申请单等参考内容，同时控制上下文长度 |
| `searchMode` | vector + keyword | 兼顾语义匹配与账号ID、权限编码等关键词的精准召回，适配多格式内部文档 |
| `usingReRank` | 开启 | 对初步召回的权限相关文档做二次排序，修正语义匹配的偏差，比如区分不同账号类型的权限配置 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户的权限检索query生成扩展术语，比如将「离职账号回收」匹配到「离职回收单」等内部文档关键词 |
| `collectionIds` | 绑定IAM专属知识库集合 | 仅检索身份账号与权限管理相关的文档，避免混入其他业务系统的无关内容 |

## 容易做错的三处
- 现象：导出的知识库文件体积仅几百KB，且内容不全面。原因：未绑定全部身份账号与权限管理专属的知识库集合，仅导出了部分零散的权限配置片段。
- 现象：检索权限相关问题时返回大量不相关的业务日志内容。原因：未通过`collectionIds`限定检索范围，或`similarity`阈值设置过低，导致低匹配度的非IAM文档被召回。
- 现象：导入包含本地图片链接的markdown账号申请单后，检索时无法获取图片关联的权限说明。原因：未配置知识库的本地资源关联逻辑，仅导入了文本内容，图片链接未被纳入检索上下文。

## 怎么确认配好了
- 发起包含「离职账号回收」的检索，核对返回结果是否覆盖权限矩阵、离职回收单等对应文档，无无关业务内容。
- 导出当前绑定的知识库集合，确认导出文件体积与实际IAM文档总量匹配，无内容缺失。
- 模拟一次人事变动，触发知识库增量更新，验证后续检索可召回最新的权限配置信息。
- 检查检索配置面板，确认`similarity`、`limit`等参数的启用状态与取值符合当前IAM文档的检索需求，可通过多次测试调整至符合需求的匹配效果。
