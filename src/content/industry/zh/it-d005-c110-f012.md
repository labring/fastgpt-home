# 运维外包驻场服务的技术文档与接口问答：文档解析与分块

以下配置基于FastGPT v4.17.0版本的功能逻辑。

## 这个品类的数据长什么样
这个品类的典型数据来自客户ITSM系统、监控平台、资产清单及值班记录，日常生成的文档包含驻场日报、服务台工单、巡检报告、SLA月报四类。文档结构随类型差异明显：驻场日报包含值班时段、问题描述、处理结果等字段；工单包含编号、优先级、响应时限等业务标识；巡检报告包含设备编号、状态、巡检时间等运维字段；SLA月报包含服务达成项统计内容。数据更新频率分为日更（驻场日报、服务台工单）与月更（SLA月报）。

## 这些特征在「文档解析与分块」这一环带来什么约束
数据来源分散且包含结构化与非混合内容，要求解析引擎同时适配文本段落与表格字段，分块时需保留业务字段的关联性，避免拆分关键标识。不同文档的更新频率差异，要求分块策略适配时效性需求：日更文档需适配高频查询的信息粒度，月更文档需保留统计逻辑的完整性。驻场服务文档多包含设备编号、响应时长等专业运维字段，分块时需避免拆分跨段落的业务单元，防止解析后信息断裂导致后续问答无法关联完整业务场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配驻场日报、工单等单条业务内容的信息密度，避免拆分关键业务字段 |
| `chunkSplitter` | 按段落+标题分割 | 适配巡检报告、SLA月报的层级结构，保留文档逻辑连贯性 |
| `customPdfParse` | 启用 | 适配驻场服务中多为格式标准化的PDF文档，提升结构化内容的解析准确率 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 秒 | 适配大型SLA月报、批量工单文档的解析耗时，避免超时失败 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 适配批量上传巡检报告、月度汇总文档的需求，满足驻场服务的批量归档场景 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型调整分块参数，适配驻场服务多类业务文档的特征 |

## 容易做错的三处
- 现象：部署在Docker Desktop中的`customPdfParse`调用出现连接失败报错，尝试本地地址仍无法连通。原因：Docker容器内的解析服务未正确暴露端口，或容器网络模式限制了本地访问。
- 现象：上传驻场日报、工单等文档后，解析结果为空或无法识别表格字段。原因：未启用`customPdfParse`配置，默认解析引擎对结构化表格的适配性不足。
- 现象：解析SLA月报时出现超时错误。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值低于文档解析实际耗时，未适配大型月度汇总文档的处理节奏。

## 怎么确认配好了
- 登录FastGPT后台，进入文档解析配置页面，核对`PARSE_FILE_TIMEOUT_SECONDS`、`UPLOAD_FILE_MAX_SIZE`等配置项的设置值与预设参数一致。
- 上传一份典型的驻场日报文档，查看解析结果中的字段完整性，确认未拆分关键业务标识。
- 尝试上传单份500 MB以内的月度汇总文档，验证上传与解析流程无超时报错。
- 针对不同类型的业务文档，切换`chunkSettingMode`为手动配置，调整`chunkSize`后预览分块效果，确认符合业务信息粒度需求。
