# 配置管理与CMDB维护的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
本品类的核心数据来自CMDB、云资源清单、自动发现工具与采购台账，涵盖配置项清单、服务组件关系拓扑、变更记录、资产盘点表四类文档。数据更新频率为每日或每周，字段包含配置项唯一标识、依赖关系、归属业务线、最新变更时间等，仅记录资产与配置的实际状态，无额外统计类数值。

## 这些特征在「向量模型与索引」这一环带来什么约束
配置管理与CMDB维护的数据包含强依赖关系字段与高频更新的变更记录，向量建模时需保留配置项间的关联语义，因此需避免单配置项文本单独向量化。每日/周级别的更新频率要求索引更新策略适配增量同步，避免全量重建带来的性能损耗。资产账实不符的出错后果要求向量检索结果需精准匹配配置项的实际状态，因此索引需绑定配置项的唯一标识字段，防止检索结果与实际资产脱节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配配置项清单、关系拓扑的文本长度，避免单块语义断裂 |
| 重叠长度 | 50–100 字符 | 保留配置项间依赖关系的上下文衔接，防止跨块丢失关联语义 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非关联配置项，避免检索结果混杂无关资产 |
| 单次搜索上限 | 前 10 条 | 匹配运维排查时的常用检索量，平衡召回精度与查询效率 |
| `defaultToken` | 4096 | 适配CMDB文档的总文本长度，确保完整加载配置项与关联关系 |
| `maxToken` | 8192 | 覆盖批量检索时的上下文总长度，支持多配置项的关联语义整合 |

## 容易做错的三处
- 现象：向量服务调用日志显示每次仅传入单文本切片，无法触发批处理。原因：未在FastGPT v4.17.0版本中开启批量向量化配置，默认按单条文本调用服务，未适配向量化服务的批量输入要求。
- 现象：检索结果无法关联到原始配置项，分块索引内容为空。原因：未在向量索引配置中绑定配置项的唯一标识字段，导致分块文本与实际资产的映射关系丢失。
- 现象：添加阿里multimodal-embedding-v1向量模型后，检索结果无有效内容。原因：未在FastGPT的模型配置中正确适配多模态模型的输入格式，仅传入文本字段未匹配多模态数据要求。

## 怎么确认配好了
- 查看向量服务的调用日志，确认每次请求的切片数量符合批量配置要求。
- 检索测试配置项的依赖关系，核对返回结果的配置项标识与原始CMDB数据一致。
- 测试模型更新触发逻辑，确认新增的变更记录能在指定更新周期内同步到向量索引。
- 验证多索引检索的去重效果，确认同一配置项的多个分块仅返回一次有效结果。
