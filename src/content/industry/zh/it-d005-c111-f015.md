# 配置管理与CMDB维护的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来自CMDB、云资源清单、自动发现工具与采购台账，日常文档包含配置项清单、服务组件关系拓扑、变更记录与资产盘点表。数据更新频率为日度或周度，文档结构涵盖结构化表格类的配置项清单、带关联关系的拓扑图、时序化变更日志。字段包含配置项唯一标识、所属资产型号、关联依赖项、更新时间、采购批次号等，单位涉及设备编号、IPV4地址、GB、天等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据分散且来源多样，要求检索支持跨CMDB、云资源清单等多数据集的关联召回，避免遗漏核心依赖关系。数据更新频率为日/周，需定期同步增量数据，确保检索结果与最新配置状态一致。文档包含结构化与非结构化两种格式，需适配不同类型内容的召回与解析。配置项间的依赖关系是核心检索目标，需优先召回关联度高的内容，忽略孤立配置项。资产账实不符的出错后果要求检索结果需匹配CMDB官方数据的置信度，避免出现偏差。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配CMDB配置项的精准度要求，避免召回无关的非关联资产数据 |
| `limit` | 前20条 | 适配CMDB单次检索的配置项数量上限，避免返回过多冗余数据导致上下文溢出 |
| `searchMode` | hybrid | 结合关键词与语义检索，兼顾配置项名称匹配与依赖关系的语义关联 |
| `usingReRank` | 开启 | 对召回的配置项按相关性重排，优先返回核心依赖项与变更记录 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展检索范围至关联的云资源清单与采购台账，覆盖全品类数据源 |
| `collectionIds` | 按CMDB专属数据集配置 | 限定检索范围至对应CMDB数据集，避免混入其他品类的资产数据 |

## 容易做错的三处
- 现象：检索返回的配置项数量始终固定为10条，无法通过界面或API调整。原因：未正确配置`limit`参数，或绑定的数据集默认限制了返回条数。
- 现象：知识库测试检索中`usingReRank`功能正常，但接入大模型调用时重排未生效。原因：大模型调用时未开启知识库检索的重排开关，仅在单独知识库测试中启用了该配置。
- 现象：知识库中存在重复的配置项条目，无法自动去重。原因：未开启知识库的文件去重配置，或未对CMDB导出的重复配置项进行预处理。

## 怎么确认配好了
- 发起针对核心配置项的检索，核对返回结果的数量与`limit`参数设置的上限是否匹配。
- 对比知识库测试检索与大模型调用的结果，确认重排后的结果排序一致。
- 查看检索结果的元数据字段，确认每条结果关联了对应的数据源（如CMDB、云资源清单）。
- 模拟变更后的数据更新，验证检索结果是否能在更新周期内同步最新的配置项信息。
