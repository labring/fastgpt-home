# 问题管理与根因分析的技术文档与接口问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源为故障时间线、日志、监控指标、代码提交记录，更新频率为每次重大故障或每月一次。日常产出的文档包括RCA报告、问题单、复盘纪要、整改跟踪表，文档结构通常包含故障发生时间、根因分析结论、验证步骤、整改项及跟踪状态等字段，字段随具体故障场景灵活调整，无统一强制单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据来源分散且格式多样，包含结构化的监控指标、半结构化的日志与代码提交记录，以及非结构化的复盘文档，要求检索环节支持跨格式内容的匹配。由于更新频率为单次重大故障或每月一次，无需配置高频增量同步，可采用定期全量更新的方式。同时文档包含根因、整改项等专属字段，检索时需优先匹配与故障分析强相关的内容，避免无关信息干扰根因定位。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 本品类需优先匹配与根因分析强相关的内容，该区间可过滤低相关性的历史故障文档 |
| `limit` | 前10条 | 适配SRE团队快速浏览核心案例的需求，避免过多结果增加信息筛选成本 |
| `usingReRank` | 开启 | 多源数据格式多样，重排可提升根因相关内容的排序优先级，优化检索结果质量 |
| `searchMode` | 语义搜索 | 本品类的问题多为模糊的故障现象，语义搜索可匹配隐含的根因关联 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可基于用户的故障描述自动扩展检索关键词，覆盖更多相关历史文档 |
| `collectionIds` | 当前项目关联的故障分析知识库集合ID | 限定检索范围，避免检索无关的业务知识库内容 |

## 容易做错的三处
- 现象：上传RCA报告或故障日志时，界面返回embedding error报错。原因：未适配本品类多源数据的格式，长文本日志未按合理长度拆分，超出嵌入模型的处理上限。
- 现象：使用docker-compose部署的FastGPT v4.17.0版本新建故障分析知识库时，出现初始化报错。原因：部署配置中未正确挂载知识库存储目录，导致数据写入失败。
- 现象：配置知识库搜索插件时，无法通过变量选择指定的故障分析知识库。原因：未正确配置`collectionIds`参数，未限定目标知识库的ID范围。

## 怎么确认配好了
- 上传一条测试用的故障复盘文档，确认无嵌入报错提示。
- 输入模拟故障现象的查询词，核对检索结果是否优先展示与根因分析相关的历史文档。
- 检查配置参数的取值是否适配本品类的多源数据格式与更新节奏。
- 验证知识库搜索插件的配置是否能准确关联到目标故障分析知识库集合。
