# 集成测试与接口测试的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来源于接口管理平台、测试环境日志、数据库、消息队列，更新频率为每日或每版本迭代。日常产出的文档包含接口测试用例、联调问题单、环境说明、测试报告，数据字段包含接口地址、请求参数、响应状态码、测试用例标识、文档版本号等，数据结构围绕跨模块交互的验证需求组织，聚焦服务间调用的链路细节。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且更新频繁，要求溯源环节需关联对应版本的文档与实时日志，避免跨版本匹配错误。接口测试用例与联调问题单的字段关联性强，溯源时需精准匹配接口标识与测试环节，无法仅通过文本关键词泛化匹配。更新频率高意味着需定期同步数据源的版本信息，否则溯源结果会指向过期的接口配置或日志，影响问题定位的准确性。

## 配置怎么定
本配置规则适用于FastGPT v4.17.0及以上版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配接口测试文档与日志的单块文本长度，避免截断关键溯源字段 |
| `responseData` | 开启 | 捕获接口响应的原始内容，用于匹配测试用例中的预期结果与实际返回值 |
| `detail` | 开启 | 展示溯源数据的完整元信息，包括接口标识、测试环节与文档版本 |
| 单次搜索上限 | 前5条 | 匹配集成测试场景下的核心依赖服务数量，避免冗余结果干扰问题定位 |
| 数据源同步周期 | 每日 | 贴合该品类数据日更或每版本更新的节奏，保证溯源数据的时效性 |

## 容易做错的三处
- 现象：接口问答返回的溯源结果中未包含测试用例ID、接口标识等元字段，原因：未开启`detail`配置项，未启用完整元信息展示。
- 现象：工作流中配置知识库搜索节点时，通过API传入的知识库变量无法触发正确溯源，原因：未将变量绑定至数据源匹配规则，导致无法关联到接口测试的专属数据源。
- 现象：调用chat接口时返回的引用列表包含未解析的{{}}模板变量，原因：未使用/模式取变量，沿用{{}}格式导致变量解析冲突，影响溯源结果的格式正确性。

## 怎么确认配好了
- 发起一次接口测试场景的问答请求，检查返回的溯源信息中是否包含接口标识、测试用例ID等元字段，确认`detail`配置项已生效。
- 模拟通过API传入知识库变量，触发工作流中的知识库搜索节点，检查是否能匹配到对应接口测试的数据源，确认变量绑定规则正确。
- 查看chat接口的返回结果，确认引用列表的格式符合预期，无未解析的模板变量，确认变量解析规则已调整。
- 检查溯源结果的文本覆盖范围，确认`quoteMaxToken`参数的取值适配当前场景的文本长度需求。
