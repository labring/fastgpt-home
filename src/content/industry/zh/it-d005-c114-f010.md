# 需求分析与PRD管理的技术文档与接口问答：引用来源与溯源

## 这个品类的数据长什么样
该品类的典型使用主体通常为互联网产品团队、业务分析师与产品经理，日常产出的文档包含需求调研纪要、PRD文档、用户故事清单、需求变更单。数据来源主要包括客户访谈记录、内部工单系统、竞品公开页面与业务埋点看板，更新频率多为每周一次或随产品版本迭代。文档字段通常包含业务目标定义、验收口径说明、需求边界条件、变更记录等，无统一强制单位，部分字段需关联原始访谈或工单内容作为支撑依据。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据来源分散且包含内部与公开两类内容，要求引用溯源环节支持跨数据源的精准关联，避免混淆不同来源的需求信息。文档更新频率随版本迭代或每周调整，需配置定期刷新知识库的机制，确保引用内容与当前版本的需求文档同步。业务目标、验收口径等核心字段需绑定原始支撑材料，要求溯源环节保留完整的引用链路，便于验证需求依据的真实性。需求变更单的时效性较强，需支持按版本号关联溯源，避免引用过时的变更记录引发开发偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | `800–1200 token` | 该品类的单条需求支撑材料多为业务描述与验收条件，该token范围可覆盖核心内容且避免冗余 |
| 单次召回条数 | 前3–5条 | 需求分析的支撑材料通常集中在少量核心访谈或工单，过多召回会引入无关内容 |
| `responseData` | 仅返回关联源文档 | 该品类的溯源需明确指向原始支撑材料，避免返回冗余的检索中间数据 |
| 知识库刷新间隔 | 7天 | 匹配该品类文档每周或随版本的更新频率，保证溯源内容的时效性，符合FastGPT v4.17.0版本的配置规范 |
| `detail` | 完整路径 | 该品类的文档需关联具体的来源类型与更新时间，完整路径可明确溯源链路 |
| 溯源展示开关 | 开启 | 需求文档的验收口径需绑定原始依据，开启后可在输出中直接展示引用来源 |

## 容易做错的三处
- 现象：配置知识库检索时，使用全局变量指定知识库标识后出现红色报错提示。原因：未在检索节点的数据源配置中开启变量引用权限，或变量作用域未覆盖当前工作流节点。
- 现象：基于问题分类的工作流中，仅第一轮提问可触发知识库引用，后续提问无检索结果。原因：未配置上下文传递逻辑，导致后续提问无法关联已加载的知识库检索配置。
- 现象：在工作流知识库检索节点中，设置了全局变量datasetid但无法正常调用。原因：未将全局变量绑定至检索节点的数据源配置项，或变量命名与节点配置项的参数名不匹配。

## 怎么确认配好了
- 发起一条针对需求验收口径的提问，检查输出结果中是否展示了明确的引用来源标识或文档路径。
- 调整知识库刷新间隔后，验证检索结果是否匹配最新的需求变更单或访谈记录。
- 测试多轮提问场景，确认每一轮提问都能正确关联已配置的知识库数据源。
- 检查变量引用配置，确认全局变量已正确绑定至检索节点的对应配置项。
