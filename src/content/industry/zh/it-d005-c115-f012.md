# 项目实施计划管理的技术文档与接口问答：文档解析与分块

## 这个品类的数据长什么样
这个品类的数据主要来自项目合同、工作分解结构（WBS）、客户日程及项目管理系统。日常处理的文档包括项目计划、里程碑清单、周报、风险问题清单，包含任务编号、责任人、工期、里程碑节点、风险等级等字段，更新频率为每周或每完成一个项目里程碑。文档结构多包含结构化表格与按时间/任务层级排列的条目，部分文档会以PDF、Excel或Word格式存储。

## 这些特征在「文档解析与分块」这一环带来什么约束
项目实施计划管理的文档多包含结构化任务条目与关键业务字段，分块时不能拆分单个任务单元或关键字段，否则会影响跨方排期协调与风险跟踪。文档更新频率较高，解析流程需适配快速迭代的文档内容，避免因解析延迟影响进度跟进。不同来源的文档格式差异较大，需支持Excel、PDF、Word等多种格式的解析，且需保留表格内的结构化数据。大型项目的WBS文档体积较大，解析过程耗时较长，需合理设置超时与上传上限参数。

## 配置怎么定
本页面适配FastGPT v4.17.0版本，以下配置基于该版本的参数规则：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配项目文档的任务条目长度，避免拆分单个任务或关键业务字段 |
| `chunkSplitter` | 换行符 + 分号 | 匹配项目文档中任务段落、表格行的分隔格式，保证分块逻辑与文档结构一致 |
| `UPLOAD_FILE_MAX_SIZE` | 5000 MB | 适配大型项目计划文档的上传需求，避免因文件体积超限报错 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对包含大量结构化表格的WBS文档的解析耗时，防止中途超时中断 |
| `customPdfParse` | 开启 | 保留PDF文档中的表格结构与字段信息，避免丢失任务编号、工期等关键内容 |
| `chunkSettingMode` | 手动 | 适配项目文档的结构化特征，灵活调整分块规则以匹配业务需求 |

## 容易做错的三处
- 上传3MB的项目PDF文档后出现解析报错 | 未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认时长不足以处理包含大量WBS表格的复杂文档
- 自定义分隔符设置完成后，分块仍合并多个段落或拆分单个任务条目 | 未同步调整`chunkSize`参数，分块长度与自定义分隔符的匹配度不足，导致分块逻辑失效
- 配置Marker后处理PDF文档报错 | 未正确配置`customPdfParse`关联的系统环境变量，或未预留足够的系统资源用于文档解析

## 怎么确认配好了
- 上传一份测试用的项目计划PDF文档，检查解析后的文本是否保留了任务ID、工期、责任人等关键字段
- 上传一份Excel格式的WBS文档，确认解析后的内容未丢失结构化表格的行列信息
- 调整`chunkSize`为不同区间，上传分段后的测试文档，验证分块未拆分单个任务条目
- 查看系统运行日志，确认文件上传和解析流程未出现超时或格式错误提示
