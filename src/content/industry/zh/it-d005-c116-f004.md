# 项目文档移交归档的技术文档与接口问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自项目文档库、配置清单、会议纪要、测试报告，日常流转竣工文档、配置手册、培训记录、验收证书等文件。数据更新节奏为项目每阶段结束或单项目完成时触发，文档通常包含项目关联编号、版本号、生成时间、签章标识等字段，单份文档体量从数百字符到数十兆字节不等，无固定统一格式，部分文件包含结构化表格与非结构化文本混合内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且格式混合，包含结构化表格与非结构化文本，要求索引环节支持多类型文件解析适配。数据更新节奏非实时，仅在项目阶段或完成时触发，可采用增量索引以节省计算资源。文档包含项目关联编号、版本号等元数据，需在索引时保留对应字段以支持按项目维度精准检索。单份文件体量差异较大，需限制单文件分块上限避免内存溢出。签章等非文本标识字段需单独处理，避免干扰向量匹配精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类单份文档混合格式的文本长度，避免分块过碎或过长影响向量精度 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的上下文关联，避免跨块的项目关联信息断裂 |
| `maxToken` | 4096 token 仅作支持该长度的模型配置示例，实际值按所选向量模型文档与接口实测确定 | 这是向量模型的最大输入 token 数，不能把示例值当作所有模型的输入上限 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的无关文档，符合项目文档移交归档的精准检索需求 |
| 单次搜索上限 | 前 10 条 | 控制返回结果数量，避免冗余信息干扰移交归档的验证环节 |
| defaultToken | 按实测标定 | 适配不同部署环境的Token计算规则，避免索引时出现Token溢出错误 |

## 容易做错的三处
- 数据集导入文件后长期处于索引中状态。原因：未针对该品类的大体积混合文档调整分块长度，导致单文件分块过多，索引任务堆积。
- 向量计算得分异常偏高且多条结果得分一致。原因：未设置合理的相似度阈值，或未对文档元数据进行单独过滤，导致匹配逻辑混乱。
- 十万条数据的 CSV 文件入库后数量与预期不符。先核对解析成功、失败及待重试记录，再检查空值过滤、去重与输入长度；`defaultToken` 是默认分段 token 数，`maxToken` 是所用向量模型的最大输入 token 数，不能仅凭数量变化确定根因。

## 怎么确认配好了
- 上传单份典型竣工文档，查看分块预览结果，确认分块长度符合预设范围，相邻分块存在重叠内容。
- 检索预设的项目关联关键词，查看返回结果的相似度分布，调整相似度阈值至符合业务验证需求的区间。
- 导入十万条级别的 CSV 测试文件，按源记录标识核对解析与入库状态，并记录每条源数据的分段数量；向量分段数不能直接视为 CSV 行数。
- 查看FastGPT v4.17.0的索引日志，确认无Token溢出或超时报错，匹配任务执行时长符合预期。
