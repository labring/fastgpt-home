# CDN与边缘加速配置的测试用例与缺陷分析：工作流编排

本页面适配FastGPT v4.17.0版本的工作流编排功能。

## 这个品类的数据长什么样
本品类的数据主要来自CDN控制台、DNS解析记录、公网访问日志与边缘节点监控告警。日常关联文档包括域名接入单、缓存规则配置表、刷新预热操作记录、故障分析报告。数据更新频率为每日同步或随配置变更实时更新，字段包含域名标识、缓存策略参数、节点IP、访问响应码、预热任务状态等，无额外强制统计单位，仅按操作生成对应记录。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需要对接多类数据源，需配置跨源数据拉取节点以整合控制台配置、DNS解析结果与访问日志。更新频率的差异要求工作流设置动态触发规则，避免使用固定周期拉取过期数据。日常文档的结构化程度不同，需在工作流中适配不同格式的输入输出，比如解析域名接入单的文本字段与缓存规则的JSON配置。边缘节点的分布式特性要求工作流支持多节点状态校验，同时需兼容不同地域的访问日志格式差异，确保流程执行的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量定义 | 绑定`variables`为域名、缓存规则ID、节点IP | 匹配CDN场景下的核心业务字段，便于流程内参数传递与复用 |
| 触发规则 | 按配置变更事件触发 | 对应数据更新频率，避免无效循环执行 |
| 超时阈值 | 600 秒 | 覆盖CDN控制台接口调用、日志拉取的常规耗时 |
| 节点校验 | 接入`nodeId`对应的边缘节点状态检查 | 验证边缘节点的接入有效性，匹配CDN分布式部署特性 |
| 结果输出 | 保存至故障分析报告模板 | 适配日常文档的归档与复盘要求 |

## 容易做错的三处
- 工作流执行时提示“undefined” is not valid json，现象是渠道链接调用失败。原因是未在`variables`中绑定CDN接口返回的JSON字段，导致参数传递为空。
- 工作流节点执行超时，现象是触发后长时间无执行结果返回。原因是未设置合理的超时阈值，或未过滤无效的边缘节点请求。
- 无法在工作流中展示图片URL对应的内容，现象是配置了图片拉取节点但无预览输出。原因是未在流程中添加图片资源校验环节，未适配CDN图片访问的防盗链配置。

## 怎么确认配好了
- 手动触发工作流，检查`variables`参数是否正确加载了测试域名的缓存规则配置。
- 查看工作流日志，确认`nodeId`对应的边缘节点状态校验环节返回正常结果。
- 生成测试用例，调用渠道链接，验证输出格式符合预设的故障分析报告模板要求。
- 模拟域名配置变更事件，确认工作流自动触发并更新对应缓存规则的校验记录。
