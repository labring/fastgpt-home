# IT采购与供应商管理的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
这个品类的数据通常来自企业内部采购系统、供应商报价文档、预算表及合同系统。日常产生的核心文档包括采购申请单、比价记录、正式合同与验收单。数据更新以单次采购流程为单位，单笔采购从申请到验收完成会完成全量数据更新，常规月度批量采购则按月同步全量供应商与预算数据。文档字段包含申请单号、采购品类、预算额度、候选供应商清单、合同条款编号、违约约定等，无统一固定的单位字段，随采购品类匹配对应计价单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散且格式差异较大，工具调用环节需要适配多系统数据源的接入需求，需配置对应插件实现采购系统、合同系统等不同数据源的拉取与解析。数据更新以单笔采购流程为核心触发节点，工具调用需绑定采购流程的具体环节，避免无效触发。不同文档的字段结构差异明显，工具调用的参数提取规则需针对采购申请、合同等不同文档类型单独配置，确保字段匹配准确。同时，该环节出错会直接导致采购延期或预算超支，工具调用的失败处理需配置重试机制与异常告警逻辑，保障流程稳定性。

## 配置怎么定
以下配置说明基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 该品类的工具调用场景覆盖多数据源拉取与字段提取，自动模式可适配不同文档的动态需求 |
| `functionCall` | `enabled` | 该品类需调用多系统插件完成数据拉取与解析，启用函数调用可实现精准的参数传递与结果解析 |
| 单次工具调用超时时间 | `300 秒` | 采购系统与合同系统的接口响应通常在3分钟内，超时可避免流程阻塞 |
| 工具调用结果缓存时长 | `7 天` | 月度批量采购的历史数据需保留至少一个结算周期，缓存可提升重复调用效率 |
| 异常重试次数 | `2 次` | 系统临时波动导致的调用失败可通过重试恢复，过多重试会延长流程周期 |
| iframe跨域白名单配置 | 包含采购系统、合同系统的域名 | 该品类的工具调用常需嵌入多系统的文档资源，配置白名单可确保资源正常加载 |

## 容易做错的三处
- 现象为iframe嵌入的供应商报价或合同文档无法显示图像与用户头像，多数浏览器加载失败仅夸克可正常展示。原因是未配置iframe跨域白名单，部分浏览器的跨域策略限制了非信任域名的资源加载。
- 现象为两层工具调用的Workflow中，第一层工具调用的AI返回内容被打印至流程日志，且无法隐藏。原因是未开启Workflow的中间步骤隐藏设置，默认会输出所有节点的执行内容。
- 现象为工具调用模块同时输出AI回复内容并触发下一级分支执行，无法仅执行其一。原因是未正确设置分支触发的依赖条件，导致并行执行了多个流程节点。

## 怎么确认配好了
- 发起一笔模拟采购申请流程，触发工具调用环节，核对是否成功拉取采购系统的历史预算数据与供应商报价信息。
- 查看Workflow的执行日志，确认仅输出必要的工具调用结果，无冗余的AI回复内容或中间步骤日志。
- 模拟系统临时超时的场景，确认工具调用会触发预设的重试机制与异常告警。
- 切换不同浏览器测试iframe嵌入的合同文档加载情况，确认跨域资源可正常展示。
