# IT采购与供应商管理的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自企业内部采购系统、供应商报价文件、预算表及合同系统。日常处理的文档包含采购申请单、比价记录表、正式合同、验收单据，字段通常包含采购单号、供应商主体名称、报价金额、合同条款条目、验收节点等。数据更新以每笔采购订单为周期，月度汇总更新整体供应商与采购台账。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散在多个内部系统，需要模型适配不同格式的数据源接入，配置时需考虑多源数据的统一解析逻辑。数据更新以单订单为周期，模型上下文窗口需适配单订单关联的多份文档总长度，避免超出处理上限。日常文档包含合同条款这类长文本，需调整模型的上下文处理参数以覆盖完整内容。同时采购数据涉及金额、条款等敏感信息，配置时需兼顾数据安全与调用效率，避免敏感信息泄露。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的逻辑制定：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单采购订单关联的采购申请、比价记录、合同等多份文档的总长度，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 满足合同条款核对、供应商比价分析的输出长度需求，平衡生成质量与调用耗时 |
| `quoteMaxToken` | 1000 token | 针对单份供应商报价文档的分段处理，适配该品类单份报价的典型长度 |
| `toolChoice` | auto | 自动选择调用工具处理结构化的采购数据比对，适配多源数据的分析需求 |
| `temperature` | 0.3–0.5 | 降低随机生成概率，确保采购条款核对、比价分析的结果严谨准确 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的非空管理员Token | 作为FastGPT App/Admin服务端的AI Proxy身份验证凭证，与模型服务商密钥无关 |

## 容易做错的三处
- 现象：调用时出现`Cannot read properties of null (reading 'q')`报错。排查项：检查FastGPT App/Admin服务端是否已配置非空的`AIPROXY_API_TOKEN`和正确的`AIPROXY_API_ENDPOINT`根地址，未配置会导致启动校验失败。
- 现象：批量处理多份供应商报价时生成结果超时。排查项：检查`maxContext`参数取值是否适配单采购订单关联的多份文档总长度，避免超出模型上下文处理上限。
- 现象：模型生成的合同条款核对结果与实际单据存在偏差。排查项：检查`temperature`参数取值是否符合场景需求，当前取值过高可能导致生成结果随机波动。

## 怎么确认配好了
- 上传单份采购申请单与对应供应商报价，触发模型分析，检查是否能正常返回比价结果。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置值与AI Proxy服务端配置的对应值一致。
- 调整`temperature`参数至0.3，多次调用同一份合同文本，检查生成的条款核对结果是否一致。
- 上传包含多份关联文档的采购订单包，确认模型能完整读取所有文档并完成分析。
