# Pull Request评审的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自代码仓库、CI流水线、Issue链接与贡献者提交的变更内容。日常关联文档包括PR说明、代码评审意见、CI执行结果与合并记录。数据字段包含PR编号、变更文件列表、CI通过率、评审意见条数、合并状态等，无统一的标准化格式。更新频率通常为日或周，随PR提交与合并节奏动态更新。

## 这些特征在「模型接入与配置」这一环带来什么约束
PR评审的数据来源分散且格式不统一，要求模型接入配置需支持多源数据的格式适配，因此需配置`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址）作为App/Admin服务端必需环境变量以对接模型服务。数据更新节奏随PR提交动态变化，模型上下文长度需匹配PR关联文档的总规模，避免因`maxContext`设置过小导致关键评审信息丢失。PR评审的核心环节为变更意图确认与缺陷分析，对模型输出的精准度要求较高，因此`temperature`参数需设置在合理区间。此外，部分PR包含代码截图类变更，需开启`vision`参数以支持视觉分析。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `10000–15000 token` | 适配PR关联的代码变更、评审意见与CI结果的总长度 |
| `temperature` | `0.2–0.4` | 保障缺陷分析与评审意见的输出精准度，避免随机化偏差 |
| `maxTokens` | `8000 token` | 匹配主流代码分析模型的单次输出上限，防止结果截断 |
| `toolChoice` | `auto` | 允许模型自主选择是否调用代码分析或视觉分析工具 |
| `AIPROXY_API_ENDPOINT` | `AI Proxy 服务的根地址，例如 http://aiproxy:3000` | 作为App/Admin服务端必需环境变量，配置AI Proxy服务的访问根地址 |
| `AIPROXY_API_TOKEN` | `与AI Proxy服务端配置一致的管理员Token，不能为空` | 作为App/Admin服务端必需环境变量，完成与AI Proxy服务的身份校验 |

## 容易做错的三处
- 现象：配置`vision`参数后，代码截图类PR的视觉分析未触发，模型输出未包含代码截图的分析结果。原因：未将`toolChoice`参数设为`auto`，模型无法自主调用视觉分析工具。
- 现象：模型调用时的实际token数与页面配置的`maxContext`不符，出现上下文截断或超限报错。原因：未同步调整`maxTokens`参数与`maxContext`的取值范围，导致配置冲突。
- 现象：模型调用提示身份验证失败。排查项：检查`AIPROXY_API_ENDPOINT`是否为AI Proxy服务的正确根地址，`AIPROXY_API_TOKEN`是否与AI Proxy服务端配置一致且非空，且变量已作为App/Admin服务端环境变量配置。

## 怎么确认配好了
- 检查App/Admin服务启动校验是否通过，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`已作为服务端环境变量正确配置。
- 触发一次PR评审的模型调用，查看请求参数中`maxContext`与`maxTokens`的取值是否与配置一致。
- 测试设置不同`temperature`参数的PR评审任务，确认输出结果的随机性符合预期。
- 上传包含代码截图的PR，确认开启`vision`参数后模型可以输出视觉分析相关的评审意见。
