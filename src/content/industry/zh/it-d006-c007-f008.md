# SLA与服务报告的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
本品类的数据来源为监控系统、工单系统、合同文件与客户沟通记录。数据更新节奏为月度或季度批量同步。日常产出的文档包含SLA条款文本、月度服务报告、可用性统计表格、客户复盘纪要。数据字段包含合同约定的服务阈值、跨系统采集的事件时间戳、异常事件标识、客户反馈内容，无固定量化统计数值，仅按采集到的原始记录归档与汇总。本文档基于FastGPT v4.17.0版本编写。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源跨监控、工单、合同等多个系统，工作流编排需支持多数据源的联动拉取与格式转换。由于数据按月度或季度批量更新，工作流需配置定时触发机制，避免实时执行带来的资源消耗。由于日常文档包含文本类SLA条款与表格类统计内容，工作流需兼容不同格式的数据源接入与解析。由于数据字段需匹配不同客户的个性化阈值，工作流需支持自定义变量的灵活配置，适配SLA指标计算、异常事件归因、报告口径对齐等耗时环节的个性化需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发周期 | `每月1日 00:00`、`每季度首月1日 00:00` | 匹配数据月度/季度更新的节奏，避免重复执行 |
| `variables` | `["SLA阈值", "客户ID", "统计周期"]` | 适配不同客户的个性化SLA配置，灵活调用字段数据 |
| 数据源接入格式 | 自动识别CSV、TXT、JSON格式 | 兼容月度服务报告、可用性统计等多格式文档的接入 |
| `nodeId` | 按数据处理顺序依次绑定`节点1`至`节点5` | 明确工作流节点的执行逻辑，避免节点关联混乱 |
| 异常告警阈值 | `连续3个统计周期` | 过滤单次偶发异常，聚焦长期服务表现异常的场景 |
| 上下文调用范围 | 仅当前工作流节点 | 避免全局上下文干扰SLA指标计算的准确性 |

## 容易做错的三处
- 现象：工作流执行文件上传节点时返回`Failed to create post presigned url`报错。原因：未配置对应存储节点的权限参数，或存储服务连接状态异常。
- 现象：调用工作流API传递图片参数时返回字段为空或格式错误。原因：未按文档要求配置图片参数的传入格式，未确认参数名与接口定义一致。
- 现象：工作流节点使用全局上下文，导致SLA指标计算出现偏差。原因：未正确设置上下文调用范围，绑定了全局上下文至当前工作流节点。

## 怎么确认配好了
- 查看工作流的定时触发配置，确认触发周期与数据更新节奏一致。
- 测试调用工作流API，传入模拟的客户数据与参数，验证`variables`是否能正确加载。
- 检查节点关联关系，确认`nodeId`的绑定顺序与数据处理逻辑匹配。
- 模拟异常场景，验证异常告警规则是否能按预设逻辑触发。
