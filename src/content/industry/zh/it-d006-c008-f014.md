# 专题活动运营的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档包含活动方案、资源位排期、活动页面文案、复盘报告，数据来源为内部内容库、活动后台、流量数据、用户反馈。数据更新节奏以周为单位，节假日前后会额外调整排期与文案内容。数据字段涵盖活动周期、资源位编号、文案内容、转化指标等，格式随活动类型灵活调整，无统一固定结构。

## 这些特征在「模型接入与配置」这一环带来什么约束
明确的活动周期要求模型上下文需匹配单场活动的时间范围，避免跨周期数据混淆；多来源的非结构化数据需适配不同格式的召回规则，需严格控制上下文token数量防止溢出；资源位与文案的强关联特性要求模型调用时需绑定对应活动标识，防止跨活动调用错误；高频更新的排期与文案需设置合理的上下文刷新间隔，确保数据时效性；活动低参与、资源浪费的出错后果要求模型输出需经过校验，需验证失败重试与告警机制是否正常触发。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `3000–5000 token` | 匹配单场活动的全量文案、排期与复盘数据总量，避免跨活动数据混入 |
| `maxTokens` | `1000–1500 token` | 控制单轮模型输出长度，适配活动文案审核、缺陷标注的常规输出需求 |
| `temperature` | `0.2–0.4` | 降低输出随机性，确保测试用例与缺陷分析的结论一致性 |
| `quoteMaxToken` | `800–1200 token` | 召回活动相关的历史文案与用户反馈数据，避免无关内容干扰分析 |
| `toolChoice` | `auto` | 允许模型根据任务需求自动选择工具，适配活动数据复盘的多步骤分析 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 `http://aiproxy:3000` | 为 App/Admin 服务端必填环境变量，需与 AI Proxy 服务端配置一致 |
| `AIPROXY_API_TOKEN` | AI Proxy 管理员 Token | 为 App/Admin 服务端必填环境变量，需与 AI Proxy 服务端配置一致且非空 |

## 容易做错的三处
- 排查项：页面展示的上下文条数与实际发送至模型的条数不一致（例如界面显示30条但实际调用携带310条），需验证`maxContext`参数配置是否符合活动数据量阈值要求，是否正确截断冗余内容。
- 排查项：部署的服务出现无限重启、无法正常启动，需验证`AIPROXY_API_ENDPOINT`、`AIPROXY_API_TOKEN`是否为已配置的服务端必填环境变量，且配置值符合要求。
- 排查项：知识库模型配置页面仅显示部分模型选项（例如仅显示GPT3.5相关选项），无法选择其他可用模型，需验证上游模型渠道配置是否正确。

## 怎么确认配好了
- 登录FastGPT v4.17.0后台的服务部署配置页面，核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`是否为已配置的服务端环境变量，且配置值符合要求。
- 发起一次测试用例生成任务，查看系统日志中携带的上下文token数量是否与`maxContext`设置的范围匹配。
- 调整`temperature`参数后，重复生成多次相同场景的测试用例，确认输出结果的一致性符合活动场景的需求。
- 触发一次模型调用失败的测试场景，确认服务是否按配置触发失败重试与告警机制。
