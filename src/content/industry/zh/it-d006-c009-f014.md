# 个人信息保护合规的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自业务系统、App权限清单、隐私政策、用户请求记录。日常处理的文档包括个人信息清单、处理规则、影响评估报告、用户授权文本，字段涵盖信息类型、处理目的、合法性基础、存储期限等。数据更新频率为季度或每次产品版本变更时，需同步最新的权限配置与用户授权信息。本文档适用于FastGPT v4.17.0版本。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源多样且格式不统一，要求模型接入时需支持多源文档解析，适配不同格式的合规文档。更新频率较高，需配置自动同步机制以确保模型使用最新的权限与授权数据。文档字段固定且需严格匹配合规要求，模型输入输出需对齐特定字段，避免泛化分析。出错后果严重，需在配置中加入严格的校验环节，确保生成的测试用例与缺陷分析符合合规标准。与其他品类的差异要求模型聚焦可识别自然人的信息处理，避免无关数据的干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | 8000–12000 token | 合规类文档通常篇幅较长，需保留足够上下文以完整覆盖隐私政策、个人信息清单的全部内容 |
| `maxTokens` | 2000–3000 token | 适配合规测试用例、缺陷分析报告的常规生成长度，避免输出截断 |
| `vision` | 开启 | 支持解析权限清单、用户授权文本中的图片内容，覆盖多模态合规审查场景 |
| `temperature` | 0.1–0.3 | 生成稳定、符合合规要求的分析结果，减少主观偏差 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径，不得填写VLLM/Ollama/Xinference等单模型地址 | 为App/Admin服务端配置的AI Proxy服务访问根地址，是AI Proxy必需依赖的环境变量 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，且不能为空 | 为App/Admin服务端配置的AI Proxy管理员身份凭证，是AI Proxy必需依赖的环境变量，不得使用应用API Key、模型供应商密钥等其他凭证 |

## 容易做错的三处
- 调用本地VLLM部署的模型时返回无法提供图片内容，原因是未正确开启`vision`配置项，或未在对话节点中关联视觉模型参数。
- 配置Qwen3-Embedding-8B模型时出现连接报错，可排查项：检查App/Admin服务端配置的`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`是否正确且非空，检查模型渠道配置中上游模型的地址与凭证是否正确。
- 生成的合规测试用例未覆盖全部文档字段，原因是`maxContext`设置过小，未能完整加载原始文档的全部内容。

## 怎么确认配好了
- 检查App/Admin服务端配置的`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，且与AI Proxy服务端配置一致，发起测试调用验证与AI Proxy服务的连通性。
- 开启`vision`配置项后，上传隐私政策相关图片，验证模型能否识别图片中的权限条款内容。
- 导入一份完整的个人信息清单文档，验证模型生成的测试用例覆盖了文档中的信息类型、处理目的等核心字段。
- 调整`temperature`至0.2，多次调用生成缺陷分析结果，确认输出稳定且符合合规审查的基本要求。
