# 事件响应与故障处理的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来源于监控告警、日志平台、APM工具及用户反馈，更新节奏为实时或单次事件触发后即时同步。日常产出的文档包含故障工单、事件时间线、应急预案、故障通报，数据字段包含事件唯一标识、告警触发时间、受影响服务范围、止损操作记录、对外通报对象等，字段随具体事件场景动态调整，无统一固定单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散且实时更新，引用溯源需覆盖多系统的关联数据，需通过事件唯一标识完成跨源关联。单次事件的文档体量随故障复杂度提升，需限定溯源数据的范围避免上下文过载。故障场景的时效性要求高，溯源环节需支持按事件时间线快速定位关联文档，且需确保溯源结果与当前响应的故障事件强绑定，避免引用无关历史事件数据。同时，故障工单、通报等文档的字段差异，要求溯源配置支持自定义字段匹配规则，确保引用内容与当前处理的故障场景直接相关，减少无效溯源结果。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配故障工单、事件时间线的单条内容长度，避免上下文过载 |
| `responseData` | 仅返回关联源数据 | 确保溯源结果仅包含与当前故障事件相关的文档内容，过滤无关数据 |
| `detail` | 开启完整字段展示 | 便于匹配事件唯一标识、告警时间等核心字段，完成跨源关联 |
| 单次搜索上限 | 前3条 | 限制溯源返回结果数量，避免冗余信息干扰故障判断 |
| 溯源匹配阈值 | 0.75–0.85 | 按实测标定，平衡召回准确性与覆盖范围 |
| 上下文窗口大小 | 600 秒 | 匹配故障事件的处理周期，确保溯源数据覆盖事件发生至当前的全部周期 |

## 容易做错的三处
- 现象：返回的故障处置建议与关联的溯源数据无关联，引用的文档未匹配当前处理的事件ID。原因：未配置基于事件唯一标识的字段匹配规则，导致召回了无关历史事件的文档。
- 现象：溯源环节超时，界面返回请求失败状态码。原因：未设置合理的上下文窗口大小，导致系统尝试加载过多历史数据超出响应时限。
- 现象：开启`detail`配置后，返回的溯源数据包含大量非核心字段，干扰故障判断。原因：未开启仅返回关联源数据的`responseData`配置，导致召回了冗余的非事件相关字段。

## 怎么确认配好了
- 导入一条模拟故障工单，触发溯源流程，核对返回的引用数据是否包含该工单的唯一标识。
- 调整`quoteMaxToken`的取值，验证返回的溯源内容长度是否符合设定范围。
- 配置可见度规则后，验证故障通报场景下的引用展示是否符合预设要求。
- 模拟超时场景，核对溯源环节是否在设定的上下文窗口内完成数据召回。
