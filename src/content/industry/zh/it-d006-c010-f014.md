# 事件响应与故障处理的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主体为SRE、运维值班与研发值班负责人的日常运维文档，包含故障工单、事件时间线、应急预案与故障通报。故障工单包含事件ID、发生时间、影响服务范围、当前处置状态等字段；事件时间线按时间戳排序，记录告警触发、操作执行与状态变化的完整序列；应急预案按影响级别划分处置流程；数据来源为实时推送的监控告警、聚合日志平台、APM链路数据与用户反馈工单，每次事件触发时更新数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时更新的事件数据要求模型调用延迟匹配业务允许的服务中断窗口，避免延长故障恢复时间。多源异构的数据格式要求模型接入支持多类型数据的prompt拼接，参数需适配不同来源数据的长度差异。故障工单与通报的结构化字段要求模型输出符合固定格式，需约束输出长度与格式。严重的出错后果要求配置失败重试与降级策略，避免因模型调用失败延误处置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配故障事件的多源数据拼接长度，避免截断关键告警与日志内容 |
| `maxTokens` | 1500–2000 token | 限制模型输出的处置建议长度，适配运维人员快速阅读的需求 |
| `quoteMaxToken` | 3000–4000 token | 约束引用的原始告警、日志数据长度，避免上下文过载导致调用失败 |
| `toolChoice` | auto | 允许模型自主选择是否调用内置故障处置工具，适配不同场景的处置需求 |
| `temperature` | 0.2–0.4 | 降低输出随机性，确保处置建议的一致性与可执行性 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加`/v1`或模型路径后缀 | 为AI Proxy服务的根地址，确保请求路由正确，适配多租户与跨区域的模型调用需求 |

## 容易做错的三处
- 现象：升级FastGPT v4.17.0后，将`AIPROXY_API_ENDPOINT`设置为m3e模型地址时返回调用失败，提示参数格式错误。原因：`AIPROXY_API_ENDPOINT`需为AI Proxy服务的根地址，不是单模型地址，错误配置了带模型路径的地址。
- 现象：配置本地重排模型时，界面显示请求错误，返回500状态码。原因：未在本地模型部署端口开放跨域访问，或上游模型渠道配置错误。`AIPROXY_API_ENDPOINT`为AI Proxy服务根地址，不要指向本地模型监听地址。
- 现象：并发请求上升时，模型回答延迟显著增加，伴随MongoDB写入超时。原因：`maxContext`设置过大，每次调用都需要加载过多历史事件数据，导致MongoDB查询与上下文拼接耗时过长。

## 怎么确认配好了
- 检查FastGPT服务端部署的环境变量，确认已配置非空的`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token），且配置与部署环境一致。
- 触发一条模拟故障事件，查看模型输出的处置建议是否符合预设的格式与长度要求。
- 调整并发请求数，观察系统监控中的模型调用延迟是否在可接受范围内。
- 检查日志平台中是否存在模型调用的成功日志，无报错信息。
