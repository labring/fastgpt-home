# 云主机交付与资源开通的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自云管理平台、订单系统、IAM权限系统与计费系统，更新节奏为每单实时同步。日常产出的文档包含资源开通单、实例配置表、账号权限单与交付确认单，核心字段包括实例规格、部署地域、权限绑定范围、计费关联订单号，单位多为核心（CPU/内存）、GB（存储）、token（上下文长度）等，无统一标准化格式，随云服务商配置略有差异。该品类聚焦计算资源创建，与云网络、负载均衡配置类品类的核心数据维度不同。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散于多系统，要求模型接入时配置多源API对接权限，确保可拉取订单、权限、计费等全链路数据。实时更新的特性要求模型上下文同步频率匹配订单流转节奏，避免使用过期的资源配置信息。文档格式不统一的特点，要求模型适配多字段解析规则，需调整参数适配长文本解析需求。核心字段的单位差异需要模型自动识别转换，需控制生成逻辑的严谨程度，确保测试用例与缺陷分析的结论准确。同时，该品类聚焦计算资源创建的特性，要求模型调用时优先校验实例规格、权限配置等核心字段，忽略非计算类配置的校验逻辑。

以下配置项适配FastGPT v4.17.0版本
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 该品类的核心文档（资源开通单、实例配置表等）单份长度多在数千token区间，需覆盖全量订单关联数据 |
| `maxTokens` | `2000 token` | 测试用例与缺陷分析的输出需包含明确的校验结果，过长输出会增加人工复核成本 |
| `quoteMaxToken` | `1500 token` | 需保留来自云管理平台的原始配置片段作为缺陷分析的佐证依据 |
| `toolChoice` | `auto` | 该场景需自动调用订单、IAM、计费系统的工具接口，无需手动指定调用工具 |
| `temperature` | `0.3–0.5` | 测试用例与缺陷分析需保持严谨性，避免生成无依据的校验结论 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不能为空 | 该变量为App/Admin服务端的环境变量，用于AI Proxy服务身份验证，非模型供应商密钥或应用API Key |

## 容易做错的三处
- 现象为服务启动校验失败、AI Proxy连接异常或代理鉴权失败，排查项为未正确配置`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，无需附加/v1等路径）与`AIPROXY_API_TOKEN`（与AI Proxy服务端配置一致的管理员Token），或上游模型接口出站权限未开放。
- 现象为多模型配置后调用时混淆密钥，导致权限校验失败，原因是未按实例维度绑定模型密钥，未区分不同模型的配置参数。
- 现象为工作流节点执行时返回冗余的历史上下文数据，干扰当前云主机交付的校验逻辑，原因是未在节点配置中限定仅使用当前会话的上下文，错误启用了全局上下文同步。

## 怎么确认配好了
- 执行单条资源开通的模拟测试，核对模型返回的测试用例是否覆盖实例规格、权限配置、计费项三个核心字段，确认字段匹配逻辑正确。
- 查看模型调用日志，确认`maxContext`参数限制下的上下文长度符合配置要求，无截断导致的关键信息丢失。
- 配置多模型场景，切换不同模型渠道配置的供应商凭证发起调用，确认对应模型可正常发起请求，无凭证混淆问题。
- 触发工作流节点的测试，确认节点仅使用当前会话的上下文数据，未引入全局冗余信息。
