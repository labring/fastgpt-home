# 云资源合规审计的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自云审计日志、IAM权限配置、CMDB资源清单与安全基线扫描结果，更新频率为月或季。日常处理的文档包含合规检查表、权限审计报告、资源清单与整改跟踪表，整体为结构化格式，核心字段包含资源唯一标识、权限配置项、合规基线匹配状态、整改完成标记等。数据以批量导出的文件或时序日志形式存在，单份文档的内容长度差异较大，从数百字符到数千字符不等，无统一固定长度。

## 这些特征在「模型接入与配置」这一环带来什么约束
月/季的更新频率决定了无需配置过长的上下文窗口，避免冗余历史数据占用模型资源。多来源的结构化数据要求配置时明确字段映射规则，确保模型能准确提取权限、合规状态等核心信息。批量文档的处理需求，要求模型接入支持多文档上下文拼接功能。同时，审计出错可能导致合规不通过、越权访问等后果，因此需要配置稳定的错误重试与状态校验机制，保障调用的可靠性。此外，本品类聚焦权限与配置合规，模型需具备识别IAM策略、基线规则的能力，对工具调用的支持有明确要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配月/季更新的批量合规文档上下文，避免冗余数据溢出 |
| `maxTokens` | 2000–3000 token | 满足合规规则解析、权限异常识别的输出长度需求 |
| `quoteMaxToken` | 500–800 token | 限定单份合规文档的引用长度，防止上下文过载 |
| `toolChoice` | auto | 支持自动调用合规规则匹配、字段提取工具，适配多类型审计文档 |
| `temperature` | 0.1–0.3 | 降低输出随机性，保障合规判定的一致性 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如http://aiproxy:3000 | 为FastGPT App/Admin服务端配置AI Proxy服务接入地址，不可附加/v1或/chat/completions路径 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不能为空 | 为FastGPT App/Admin服务端配置AI Proxy服务鉴权凭证，不可使用应用API Key、模型供应商密钥或其他业务token |

## 容易做错的三处
- 调用模型时返回一串红色数字报错。排查项：检查FastGPT App/Admin服务端是否已正确配置`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`环境变量，未配置必填变量会导致启动校验失败，或服务无法连接AI Proxy服务。该问题常因未正确配置这两个环境变量引发，不可使用第三方API中转服务的密钥作为该凭证。
- 调用多模态模型时无法识别图片中的资源配置信息。原因：未开启`vision`参数，或未配置适配的视觉模型调用路径，无法完成图像内容解析。
- 模型返回的合规判定结果与实际审计文档字段不匹配。原因：未设置合理的`maxContext`参数，导致上下文溢出丢失关键字段信息，或字段映射规则配置错误。

## 怎么确认配好了
- 输入单份标准合规检查表文档，执行模型调用，核对输出是否包含权限状态、合规匹配结果等核心字段。
- 检查FastGPT App/Admin服务端的环境变量配置，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的取值未出现拼写错误，与部署环境匹配。
- 触发模拟异常调用，验证错误处理流程是否正常启动，如重试机制、报错提示是否清晰。
- 调整上下文长度参数，核对输入文档的关键信息是否被完整加载，无截断或丢失情况。
