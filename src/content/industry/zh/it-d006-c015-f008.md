# 产品使用数据分析的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
本品类数据主要来自埋点系统、数据仓库、CRM及工单系统，更新节奏为日或周批量同步。核心字段包含客户标识、功能访问路径、操作时长、异常触发次数、工单关联ID，单位为次、秒、条。配套文档包括使用分析报告、埋点方案、指标口径表、看板需求单，需统一字段定义与指标计算规则，保障跨团队数据对齐。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散且需对齐多套文档规则，工作流编排需先配置多数据源的字段映射校验，避免跨系统数据错位。日/周的更新节奏要求工作流调度周期匹配数据刷新窗口，避免读取未完成同步的脏数据。指标口径的统一性要求工作流内嵌口径校验节点，对计算逻辑做前置验证，同时需预留异常数据排查的分支，适配不同来源的异常字段格式。测试用例需覆盖数据源切换、口径变更后的流程稳定性，缺陷分析则需追踪异常数据在工作流中的流转节点。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 包含客户ID、指标口径版本、数据源标识的固定变量集合 | 匹配配套文档中的指标口径与字段定义，避免运行时动态取值出错 |
| `nodeId` | 按数据源校验、口径验证、异常排查的顺序分配连续节点ID | 便于测试用例编写与缺陷追踪时快速定位流程节点 |
| 数据源校验开关 | 开启全量字段校验模式 | 覆盖埋点、CRM、工单系统的字段格式，提前拦截脏数据进入流程 |
| 调度周期 | 按数据更新节奏设置为`86400 秒`（1天）或`604800 秒`（7天） | 匹配日/周的数据同步频率，避免读取未完成的数据集 |
| 异常分支阈值 | 异常数据占比超过`5%`时触发人工排查分支 | 适配日常异常数据排查的耗时需求，减少无效流程运行 |

## 容易做错的三处
- 现象：FastGPT v4.17.0版本中，`variables`配置项仅显示两个可选变量，无法调用历史版本的自定义变量。原因：新版本对全局变量的注册规则做了调整，需通过代码仓库的变量配置文件重新导入存量变量，直接沿用旧版配置会导致变量缺失。
- 现象：运行工作流时提示「Key is error. You need to use the app key rather than the account key」，流程直接终止。原因：未区分应用密钥与账号密钥，配置数据源时误用了账号级别的访问密钥，导致权限校验失败。
- 现象：工作流中使用指定回复节点输出HTML代码，流程执行后未显示内容且直接进入下一分支。原因：指定回复节点默认会对输出内容做转义处理，HTML标签被转换为纯文本，未开启原生HTML输出配置。

## 怎么确认配好了
- 手动触发一次工作流，查看`variables`变量是否全部加载成功，核对字段名称与指标口径表一致。
- 模拟异常数据输入，确认`nodeId`对应的校验节点能正确识别异常并触发对应分支。
- 查看调度日志，确认工作流按预设周期自动启动，未出现超时或数据读取失败的记录。
- 测试免登录调用场景，确认工作流消耗的API配额与应用配置的密钥绑定一致。
