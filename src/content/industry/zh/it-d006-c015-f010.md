# 产品使用数据分析的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据主要来自埋点系统、数据仓库、CRM与工单系统，更新节奏通常为日更或周更。日常产出的文档包含使用分析报告、埋点方案、指标口径表与看板需求单，数据字段包含用户标识、功能模块、操作触发时间、行为类型与关联客户信息，字段单位多为次、分钟、事件标识等通用格式，无统一强制的固定单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散要求溯源逻辑需对接多系统的校验规则，确保跨源数据的一致性；更新频率的差异要求溯源信息需匹配对应数据的刷新周期，避免使用过期数据生成分析结果；文档类型多样意味着需适配不同格式的来源标注规则，防止指标口径冲突；字段的非标准化特性要求溯源时需绑定原始数据的字段定义，防止出现指标误判。在测试用例与缺陷分析场景中，还需快速定位溯源数据的原始节点，保障分析结果的可追溯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配产品使用数据分析单条分析内容的长度，避免上下文溢出 |
| `responseData` | 仅返回关联源字段 | 适配埋点、CRM与工单系统的轻量化溯源校验，降低数据传输开销 |
| `detail` | 开启完整溯源模式 | 用于测试用例的全链路缺陷排查，匹配看板需求单的详细标注要求 |
| 单次搜索上限 | 前5条 | 控制多系统引用的返回条数，避免分析结果冗余 |
| 最大上下文 | 6000 token 按实测标定 | 适配跨源数据整合的溯源需求，适配日更数据的批量校验 |

## 容易做错的三处
- 现象：正式聊天页面不显示引用文档来源，调试页面可正常展示。原因：未在配置中开启`detail`模式，仅返回精简的响应数据，未携带溯源字段。
- 现象：引用返回条数超出预期，无法限制为指定数量。原因：未配置单次搜索上限参数，默认返回全量跨源数据，不符合测试用例的条数校验要求。
- 现象：长文本分析的溯源标记错位，无法匹配原始数据的位置。原因：未设置`quoteMaxToken`适配长文本的拆分规则，导致溯源标记与原始数据片段不对应。

## 怎么确认配好了
- 执行单条埋点数据的溯源测试，检查返回结果中是否包含原始数据的来源标识与字段定义。
- 触发批量跨系统数据的引用请求，核对返回条数是否符合预设的单次搜索上限配置。
- 导入长文本分析用例，验证溯源标记是否与原始数据片段的位置匹配。
- 在FastGPT v4.17.0版本中，切换调试与正式环境，确认两处场景下的溯源信息展示一致性。
