# 代码安全审计的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
本品类的数据主要来源于源代码仓库、依赖清单、静态代码扫描（SAST）工具及公开漏洞库，更新节奏随项目版本迭代或单次审计任务推进。日常产出的文档包含代码审计报告、漏洞证明材料、修复建议文档与复测记录，字段覆盖漏洞等级、关联代码行、攻击路径、修复方案等，无统一固定单位，随审计项目的代码规模与风险等级调整。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据的拉取需求要求插件支持对接多类工具与仓库，按需触发的特性要求调用逻辑适配不同项目的迭代节奏，结构化的文档字段要求插件能精准提取并关联对应数据，人工审查的环节要求插件支持混合AI分析与人工复核的流程。

## 配置怎么定
本文档适配FastGPT v4.17.0版本的工具调用与插件配置，具体配置项如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `functionCall` | 开启并指定为代码安全审计专用函数 | 适配代码安全审计的结构化输出需求，便于精准提取漏洞等级、关联代码等核心字段 |
| `toolChoice` | 设为`auto` | 允许AI自主选择调用代码仓库、SAST工具等对应插件，适配多源数据拉取的灵活需求 |
| 单次调用超时阈值 | 600秒 | 覆盖代码仓库拉取、SAST结果解析等耗时较长的操作，避免中途中断任务 |
| 插件数据源白名单 | 仅添加项目关联的源代码仓库、SAST工具地址 | 防止调用非授权数据源，降低供应链风险 |
| 召回关联文档上限 | 前20条 | 限制单次调用返回的文档数量，避免上下文过载影响分析效率 |
| 单次返回文档字符上限 | 8000字符 | 适配代码审计报告的常规文本长度，确保分析内容完整且不超出上下文限制 |

## 容易做错的三处
1. 现象：调用`functionCall`时返回空结果或报错“不支持函数调用”，原因：未正确配置AI模型的函数调用权限，或使用的本地部署模型未开启函数调用支持。
2. 现象：插件调用超时且返回504状态码，原因：超时阈值设置过低，未覆盖代码仓库拉取或SAST结果解析的实际耗时。
3. 现象：插件返回的漏洞数据与实际代码不匹配，原因：未配置项目专属的数据源白名单，调用了非关联的漏洞库或代码仓库。

## 怎么确认配好了
1. 手动触发一次工具调用，检查是否能拉取到指定源代码仓库的代码片段或SAST工具的扫描结果。
2. 查看AI输出的结构化数据，确认是否包含漏洞等级、关联代码行等预设字段，验证`functionCall`的配置生效。
3. 调整超时阈值为120秒，模拟耗时较小的调用操作，确认调用未因超时中断。
4. 检查插件数据源配置，确认仅包含项目关联的地址，无额外非授权来源。
