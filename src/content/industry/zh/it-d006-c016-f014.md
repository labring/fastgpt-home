# 代码安全审计的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来源于源代码仓库、依赖清单、静态代码扫描工具及公开漏洞库。数据更新节奏随项目版本迭代或安全审计周期推进，通常每版本或每项目更新一次。核心文档包含代码审计报告、漏洞证明文件、修复建议文档与复测记录，字段包含漏洞等级、受影响函数路径、依赖组件版本、修复状态等，无统一固定单位，随文档类型变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据输入要求模型接入需兼容不同格式的代码片段、漏洞描述与依赖信息。高频更新的审计数据要求配置需支持动态调整上下文长度，避免因数据溢出导致分析中断。危险函数定位与数据流追踪环节的高算力消耗，要求模型参数需适配长文本处理能力。同时，高危漏洞上线的出错后果，要求配置需具备稳定的调用容错机制，避免因配置错误导致审计流程失效。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配代码安全审计的长文本输入需求，覆盖完整的函数上下文与数据流追踪内容 |
| `maxTokens` | 4000 token | 限制单轮模型输出长度，避免超长结果导致解析失败，适配审计报告与修复建议的生成需求 |
| `quoteMaxToken` | 1500 token | 限定引用的代码片段长度，确保模型可精准定位受影响的危险函数与代码路径 |
| `temperature` | 0.2–0.4 | 降低随机生成概率，提升漏洞分析与修复建议的准确性与一致性 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如`http://aiproxy:3000`，不得附加`/v1`或`/chat/completions`路径，不得填写单模型服务地址 | 作为App/Admin服务端必需环境变量，配置后可建立与AI Proxy服务的网络通路，适配私有部署的安全审计场景 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不得为空 | 作为App/Admin服务端必需环境变量，完成与AI Proxy服务的身份验证，保障接口调用的安全性 |

## 容易做错的三处
- 未正确配置`AIPROXY_API_ENDPOINT`服务端环境变量，填写错误的AI Proxy服务根地址（如附加额外路径或填写单模型服务地址），模型调用时返回`502 Bad Gateway`报错，或服务启动校验失败。排查项：核对AI Proxy服务的实际根地址，确认未附加`/v1`或`/chat/completions`等额外路径。
- 未正确配置`AIPROXY_API_TOKEN`服务端环境变量，填写的Token与AI Proxy服务端配置不一致或为空，模型调用时返回`401 Unauthorized`报错，无法生成漏洞分析结果。排查项：核对AI Proxy服务端配置的管理员Token，确认Token非空且与服务端配置一致。
- 将`maxContext`设置为超过15000 token的数值，模型调用超时，审计任务停滞。原因是未适配代码安全审计的长文本处理上限，超出模型支持的上下文长度阈值。

## 怎么确认配好了
- 核对App/Admin服务端的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量配置，确认`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，`AIPROXY_API_TOKEN`为与服务端配置一致的非空管理员Token。
- 发起一次小型代码片段的测试调用，查看模型返回的漏洞分析结果是否包含危险函数定位内容，验证配置是否生效。
- 调整`temperature`参数后，对比两次相同输入的模型输出，确认结果的一致性符合预期。
- 查看系统运行日志，确认无`401`或`50x`类的模型调用报错，验证配置的稳定性。
