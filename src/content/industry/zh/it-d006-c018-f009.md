# 企业软件许可证管理的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
本品类数据来自软件资产管理系统、采购系统、终端扫描结果及厂商授权文件，更新周期为月或季度。日常关联文档包含许可证台账、软件使用清单、采购合同与合规审计报告，数据字段包含软件名称、授权类型、授权数量、安装终端数、到期日期，单位多为台、份、天，无额外虚构统计数值。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类数据来源分散，需调用多源工具拉取不同系统的台账、扫描结果及授权文件，需适配不同接口格式完成数据整合。更新周期为月或季度，字段固定且无高频变动，工具调用需锁定对应字段映射，避免跨周期数据混淆。授权数量、安装终端数为核心校验字段，工具参数需精准匹配字段名，否则会导致超装识别错误。合规审计需关联采购合同与授权文件，插件需支持多文档上下文联动，单次调用需覆盖全量关联数据，避免上下文断裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配授权数量核对、超装识别、续费提醒等不同工具调用场景，自动选择匹配的工具 |
| `functionCall` | `enabled` | 此配置需在FastGPT v4.17.0及以上版本中支持，强制触发结构化工具调用，确保参数与许可证台账、终端扫描数据的字段精准匹配 |
| 工具调用超时时间 | 300–600 秒 | 数据需拉取多源系统内容，超时时间覆盖全量拉取与校验的合理时长 |
| 关联文档召回上限 | 前 3 条 | 合规审计需关联采购合同、授权文件与软件使用清单，避免冗余数据干扰校验逻辑 |
| 上下文保留长度 | 1200–1500 字符 | 需覆盖多文档关联的上下文，避免工具调用打断后丢失核心字段信息 |

## 容易做错的三处
- 现象：每次调用工具后，模型生成的回答无法延续之前的许可证台账上下文，出现上下文断裂。原因：未将`functionCall`配置为强制模式，工具调用后未保留关联的采购合同、授权文件上下文。
- 现象：工具调用完成后，模型响应时长超出预设阈值，出现超时报错。原因：工具调用超时时间配置过短，未覆盖多源数据拉取与校验的完整流程。
- 现象：调用许可证校验工具时，返回字段为空的报错，无法完成超装识别。原因：未在工作流中配置参数补充环节，未引导用户输入授权数量、安装终端数等必填字段的数值。

## 怎么确认配好了
- 触发一次工具调用，检查返回的字段是否与许可证台账、终端扫描数据的字段完全匹配，匹配逻辑需按实际业务场景标定。
- 模拟多源数据拉取场景，验证工具调用是否能在预设时长内完成，超时阈值需按实际拉取耗时标定。
- 测试工具调用后，模型是否能延续之前的上下文生成合规校验结论，上下文保留长度需按关联文档的总字符数标定。
- 触发超装识别校验，检查是否能正确关联采购合同中的授权数量与终端扫描的安装数量，关联规则需按业务要求标定。
