# 企业软件许可证管理的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源为软件资产管理系统、采购系统、终端扫描工具及厂商授权文件。更新频率为月度或季度。日常产出的文档包括许可证台账、软件使用清单、采购合同与合规审计报告。数据字段包含授权编号、授权许可数量、实际安装终端数、授权到期日期、厂商名称等，无额外自定义单位，字段均为标准化的文本、整数或日期格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散且格式标准化程度不一，要求模型接入时需适配多源数据的统一解析逻辑。月度或季度的更新频率，决定了模型调用无需高频触发，可配合批量任务调度。多样的文档类型需要模型支持多格式输入解析，而标准化的字段结构则简化了模型抽取规则的配置。同时，核心业务环节的授权核对、超装识别等任务，要求模型输出的结构化结果需严格匹配预设字段格式，避免出现字段缺失或格式错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配许可证台账、合规审计报告等长文档的上下文承载需求，避免截断核心授权信息 |
| `maxTokens` | 2000–3000 token | 满足授权数量核对、超装识别等任务的结构化输出长度，避免结果不完整 |
| `toolChoice` | auto | 允许模型自主判断是否调用工具完成批量授权数据的比对 |
| `temperature` | 0.1–0.3 | 保持授权核对结果的一致性，减少非必要的格式偏差 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径，不得填写单模型服务地址 | 为App/Admin服务端必需环境变量，确保AI Proxy请求路由正确 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不能为空 | 为App/Admin服务端必需环境变量，保障AI Proxy请求的身份合法性，避免未授权访问 |

## 容易做错的三处
- 现象：App/Admin服务启动校验失败或模型请求无法正常建立。原因：未在服务端配置必填环境变量`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，导致请求无法正常建立。
- 现象：多模态视觉模型调用图片分析任务时返回错误，提示无法下载图片。原因：未配置模型的图片访问权限或网络代理，导致模型无法获取终端扫描生成的软件安装截图。
- 现象：配置`toolChoice`为auto后，模型未触发工具调用完成授权数量核对。原因：未在系统提示词中明确要求模型调用工具处理批量授权数据，导致自主决策逻辑未生效。

## 怎么确认配好了
- 发起单次授权台账解析测试，检查模型输出的结构化字段是否与源数据字段匹配，调整对应参数直至格式符合业务要求。
- 触发批量超装识别任务，查看工具调用日志，确认模型自主触发了工具调用，完成授权数量的批量核对。
- 验证模型请求的网络连通性，检查服务端配置的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的有效性，确保无连接报错。
- 上传一张软件授权凭证图片至多模态模型，确认模型可正常解析图片中的关键授权信息。
