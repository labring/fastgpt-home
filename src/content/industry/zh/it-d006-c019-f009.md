# 众包标注人员管理的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自众包平台的人员注册与资质信息、标注任务的质量抽检结果、标注人员的培训考试答卷，以及财务系统的结算记录。日常维护的核心文档包括人员准入规则、标注培训材料、月度绩效表与结算清单。数据更新节奏分为日度（标注质量、实时绩效数据）与月度（结算清单、人员准入规则更新），核心字段包含人员唯一标识、准入资质等级、标注准确率、结算金额等，无统一固定的单位标准，随不同标注项目的类型调整。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散，覆盖平台、质检、培训、财务等多个独立系统，工具调用需适配多源异构数据的格式转换规则。不同数据的更新节奏存在差异，要求工具支持日度批量处理与实时单条调用两种触发模式。核心文档包含准入规则、绩效表、结算清单等不同类型，工具需绑定对应场景的处理逻辑，避免将结算数据与质量考核数据混淆。人员信息与结算数据强关联，工具调用时需校验字段匹配关系，防止出现错配引发的结算风险。

## 配置怎么定
本页面适配FastGPT v4.17.0版本，以下配置项基于该版本的工具调用与插件逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用模式 | 按场景切换`toolChoice`与`functionCall` | 适配批量质检与单条校验的不同需求，匹配标注任务的处理规模 |
| 多模型调度规则 | 按输入数据类型分配模型，多模态数据调用多模态模型，纯文本数据调用Qwen2系列模型 | 匹配不同标注任务的模型适配性，解决多模型分流的配置需求 |
| 定时任务触发频率 | 日度批量任务设为`86400 秒`，实时任务按需触发 | 匹配数据的日度/实时更新节奏，避免重复调用或遗漏更新 |
| 数据源校验规则 | 校验人员ID与结算金额的关联一致性 | 防止数据错配引发的结算风险，适配品类的强关联数据特征 |
| 结果存储路径 | 按项目维度划分目录，如`/annotator/[project_id]/` | 便于后续质检与结算核对，匹配品类的文档分类管理需求 |
| 最大重试次数 | `3 次` | 应对网络波动或接口临时故障，降低单次调用失败导致的流程中断概率 |

## 容易做错的三处
- 现象：单工作流中未按任务类型分配模型，导致多模态数据被传入纯文本模型处理。原因：未配置按输入数据类型触发对应模型的规则，未区分不同标注任务的模型适配需求。
- 现象：必应搜索插件调用无结果，国内环境下无法正常返回内容。原因：未替换为适配国内网络环境的搜索工具，或未正确配置插件的网络参数。
- 现象：工具调用后出现结算字段与人员信息不匹配，引发错付风险。原因：未开启数据源校验配置，未校验不同系统数据的关联一致性，忽略品类数据的强关联特征。

## 怎么确认配好了
- 触发单条标注质量校验任务，验证工具是否调用指定的模型与数据源，核对返回结果与预期处理逻辑一致。
- 触发定时批量任务，验证是否按配置的频率调用对应数据源，无重复调用或遗漏更新的情况。
- 模拟数据错配场景，验证工具是否触发校验告警，拦截异常的人员与结算数据关联关系。
- 切换不同类型的标注任务，验证工具是否自动分配对应模型，符合配置的调度规则。
