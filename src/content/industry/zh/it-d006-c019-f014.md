# 众包标注人员管理的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自众包平台、标注质量采集系统、标注人员培训考核记录、财务结算系统。日常关联文档包含人员准入规则、标注培训材料、绩效排名表、结算明细清单。数据更新频率通常为每日或每月，核心字段涵盖人员资质信息、标注任务完成量、质量合格率、结算金额等，不同项目的标注规则与结算标准存在差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且格式多样，要求模型接入环节需支持对接多源异构数据，适配人员准入规则、绩效表、结算清单等不同文档的格式。数据更新频率的差异，要求配置支持按日或按月的同步策略灵活切换。核心字段存在较强的项目自定义性，需模型能灵活映射不同项目的专属字段。结算相关数据的严谨性要求模型配置需匹配财务系统的字段规则，避免因字段不匹配引发错付漏付的风险。同时，测试用例需覆盖多源数据接入的兼容性，缺陷分析需重点关注字段映射错误、数据截断等问题。

## 配置怎么定
以下服务端环境变量与模型参数基于FastGPT v4.17.0版本的配置逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://172.17.0.1:8000`（内网Docker部署场景，为AI Proxy服务根地址，勿附加/v1或/chat/completions等路径） | 适配内网部署的众包标注管理平台的AI Proxy服务调用需求，规避公网访问限制 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的非空管理员Token | 保障AI Proxy服务调用的身份合法性，防止未授权访问 |
| `maxContext` | 8000–12000 token | 适配人员准入规则、绩效表、结算清单等多文档拼接的上下文长度需求，避免内容截断 |
| `temperature` | 0.2–0.4 | 保障字段映射与数据同步的结果一致性，降低随机偏差 |
| `toolChoice` | `none` | 该场景无需调用外部工具，仅需完成数据格式转换与字段映射 |
| `maxTokens` | 2000–3000 token | 适配单条结算明细或绩效记录的处理长度，避免单次请求超出模型上限 |

## 容易做错的三处
- 现象：Docker内网部署场景下，服务调用返回连接超时错误，状态码500。原因：未正确配置App/Admin服务端的`AIPROXY_API_ENDPOINT`环境变量（应为AI Proxy服务根地址，勿附加/v1等路径），导致服务无法连通AI Proxy服务。
- 现象：在Config.json中配置模型参数后，模型仍以流式返回结果，无法切换为非流式模式。原因：未正确配置非流式控制的相关参数，导致配置项未被系统识别生效。
- 现象：接入whisper语音模型后，语音输入的标注任务无法生成有效转写结果，返回空内容。原因：未正确配置多模态模型的相关参数，导致语音数据无法被模型正确解析处理。

## 怎么确认配好了
- 在内网环境下，使用curl命令调用配置的`AIPROXY_API_ENDPOINT`地址，验证AI Proxy服务是否正常响应。
- 导入一份包含自定义字段的人员绩效表，检查模型输出的字段映射结果是否覆盖了所有自定义字段，无缺失。
- 调整模型参数至不同区间，对比多次同步结算数据的结果一致性，确认参数取值符合业务需求。
- 查看模型调用日志，确认长文档处理时未触发内容截断警告，相关参数配置已生效。
