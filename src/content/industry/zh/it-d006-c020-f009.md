# 供应商与设备到货管理的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
通常该品类的数据来自ERP系统、供应商发货单、物流跟踪信息及设备厂商后台。日常处理的文档包含采购订单、到货验收单、序列号清单与发票资料，每份订单对应独立的数据集。数据更新节奏以单订单为单位，部分批量到货场景按周更新。数据字段包含采购型号、序列号、到货数量、验收状态、供应商信息等，无统一强制单位，部分字段需匹配设备厂商的专属编码规则。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据分散于多套系统与文档中，工具调用需适配不同数据源的格式差异，因此需配置多源数据拉取的插件规则。数据更新节奏以单订单或周为单位，工具触发时机需匹配业务流程节点，避免无效调用占用资源。字段包含专属设备编码与序列号，工具调用的参数需明确字段映射规则，防止数据错配。出错后果直接影响项目交付，因此工具调用需配置失败重试与数据校验逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `functionCall` | 强制开启 | 适配多源数据拉取的标准化调用流程，匹配采购订单的单数据处理逻辑 |
| `toolChoice` | 设为auto | 让大模型自动选择合适的工具调用，适配多源数据拉取场景 |
| 调用超时 | 600秒 | 应对物流信息、设备厂商后台的接口响应延迟 |
| 字段映射规则 | 采购型号→设备型号、序列号→资产编码 | 匹配品类数据的专属字段命名，避免数据错配 |
| 重试次数 | 2–3次 | 应对临时接口波动，降低单次调用失败概率 |
| 最大调用条数 | 10条以内 | 匹配单订单的常规数据量，避免接口过载 |

## 容易做错的三处
- 现象：调用飞书多维表格HTTP接口时返回403权限错误或字段为空。原因：未配置品类专属的字段映射规则，将通用字段直接传入接口，不符合多维表格的列名要求。
- 现象：调用设备厂商后台接口后无返回结果或超时未响应。原因：未设置合理的调用超时时长，未配置重试机制，无法应对接口延迟或临时波动。
- 现象：通过Function CALL调用MYSQL数据库后，大模型回答未引用数据库原文片段。原因：未将工具调用返回的数据库原文片段纳入大模型上下文，导致大模型无法引用对应内容。

## 怎么确认配好了
- 手动触发一次工具调用，查看返回结果是否包含采购订单、序列号等品类专属字段，字段格式与业务文档一致。
- 模拟单次到货场景的调用流程，检查工具是否在触发后自动拉取对应物流信息与设备厂商数据。
- 配置失败重试逻辑后，模拟接口超时场景，确认工具是否按预设规则触发重试。
