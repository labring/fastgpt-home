# 供应商与设备到货管理的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
该品类的日常文档通常包含采购订单、到货验收单、序列号清单、发票资料，数据一般来自ERP系统、供应商发货单、物流信息及设备厂商后台，更新频率为每单或每周。文档字段多包含采购方信息、供应商信息、设备型号、序列号、到货时间、验收结果等，单位多为台、套、件等实物单位，数据关联具体集成项目的交付节点，随采购与到货流程动态更新。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据多源分散、按单或按周更新，且核心字段聚焦设备型号、序列号等精准标识，在引用来源与溯源环节带来多重约束。需关联采购订单号、序列号等唯一标识完成跨文档溯源，避免跨批次数据混淆；需绑定单次采购或到货节点，防止引用过期或不匹配的文档；需精准匹配设备型号、序列号字段，避免泛关键词检索引发的错配；同时需关联具体项目信息，确保溯源结果与交付节点对应，规避项目延期风险。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 900–1100 token | 适配单份到货验收单或序列号清单的内容长度，完整保留设备型号、序列号等关键溯源信息 |
| `responseData` | 包含源文件名与存储路径 | 满足业务对溯源到具体单据的需求，便于相关人员核对采购与到货信息 |
| `detail` | 开启字段级匹配 | 精准匹配采购订单号、设备序列号等唯一标识，避免泛关键词检索引发的错配 |
| 单次搜索召回上限 | 前5条 | 覆盖单采购批次关联的核心文档数量，避免冗余数据干扰分析 |
| 检索过滤条件 | 绑定采购订单号 | 限定检索范围为本次采购批次的文档，防止跨周期数据混入 |
| 上下文窗口大小 | 2000–2500 字符 | 容纳多份关联文档的内容，支持跨单据的溯源分析 |

## 容易做错的三处
- 现象：返回的引用文档包含非本次采购批次的发票资料，原因：未绑定采购订单号作为检索过滤条件，召回了跨周期的冗余数据，易引发资产账实不符的缺陷。
- 现象：引用内容中设备序列号字段被截断无法显示，原因：`quoteMaxToken`设置过低，截断了包含序列号的关键溯源信息。
- 现象：测试用例执行后提示无有效引用来源，原因：未开启字段级匹配，无法识别设备型号与序列号的精准关联，导致检索不到匹配文档。

## 怎么确认配好了
- 提交单份采购订单关联的测试用例，检查返回的引用列表是否仅包含本次采购批次的单据，调整检索过滤条件直至匹配。
- 查看引用返回的内容，确认设备型号、序列号等字段完整显示，调整`quoteMaxToken`取值直至无截断情况。
- 触发缺陷分析场景，输入包含设备错配描述的问题，检查返回的引用是否精准指向对应型号的采购订单或发货单。
- 调用API接口，确认返回的响应数据包含源文件名与存储路径，符合溯源需求。
