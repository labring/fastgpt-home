# 供应链安全与开源依赖治理的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
这个品类的数据通常来自包管理器、代码仓库、公开漏洞库与许可证数据库，更新节奏为每日或每软件版本发布时。日常产出的文档包含SBOM清单、依赖风险报告、许可证合规清单与漏洞修复工单，字段覆盖组件名称、版本号、漏洞CVE编号、许可证类型、风险等级等，无额外自定义统计单位，核心围绕第三方开源组件的资产与风险信息展开。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散且更新频率较高，工具调用需支持多源并行拉取，同时需适配不同数据源的接口格式与鉴权规则。日常文档的字段标准化程度有限，插件传参需精准匹配组件名称、版本号等核心标识，避免跨组件匹配错误。依赖资产识别与漏洞匹配环节耗时较长，工具调用需设置合理并发阈值，防止单次调用过载。同时需对调用结果做格式校验，避免无效数据流入后续风险评估流程。

## 配置怎么定
本配置说明适配FastGPT v4.17.0版本的插件系统。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 允许系统自动匹配适配供应链安全场景的插件，减少手动配置复杂度 |
| `functionCall` | `{"name":"pull_dependency_risk","parameters":{"scope":"all"}}` | 精准触发依赖风险拉取的标准化调用，适配品类的核心数据获取需求 |
| 并发调用上限 | `10–15 次/秒` | 避免超过公开漏洞库、包管理器的调用限流阈值，适配日常业务并发场景 |
| 调用超时时间 | `300–600 秒` | 覆盖依赖资产识别、漏洞版本匹配的最长耗时环节，防止中途中断 |
| 单次调用数据上限 | `500 MB` | 适配单批次依赖资产的最大拉取量，防止单次调用数据过载 |
| 失败重试次数 | `2 次` | 应对临时网络波动或接口限流导致的调用失败，减少手动干预 |

## 容易做错的三处
- 现象：并发调用量达到1秒2-3次时，工具调用返回空结果。原因：未设置合理的并发调用上限，触发了第三方数据源的限流机制，导致部分调用被丢弃。
- 现象：插件传参时多张图片无法正确传递。原因：未配置适配多模态数据的传参格式，未将图片转换为符合插件要求的base64或URL格式。
- 现象：部署后插件调用频繁失效，且提示存储服务需要公网访问。原因：未正确配置内网环境下的插件存储路径，误将公网访问作为强制要求，未适配内网部署的存储链路。

## 怎么确认配好了
- 查看工具调用日志，确认每次调用的参数与配置项一致，无缺失或错误的字段。
- 模拟日常业务并发量，验证工具调用的返回结果不为空，且符合品类文档的格式要求。
- 检查插件的存储配置，确认内网环境下可正常读写依赖数据，无需公网访问链路。
- 触发一次完整的依赖风险拉取流程，核对生成的SBOM清单与实际依赖资产一致。
