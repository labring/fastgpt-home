# 供应链安全与开源依赖治理的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自包管理器、代码仓库、漏洞库与许可证数据库，更新频率为每日或每版本发布时。日常产出的文档包含SBOM清单、依赖风险报告、许可证清单与修复工单，字段通常包含依赖包名、版本号、漏洞CVE编号、许可证类型、风险等级等，由安全团队、研发效能团队与开源治理办公室日常维护。本说明适配FastGPT v4.17.0版本。

## 这些特征在「模型接入与配置」这一环带来什么约束
依赖资产识别、漏洞版本匹配、升级影响评估是该品类最耗时的环节，对应的数据量随项目规模波动较大。SBOM清单与漏洞报告的字段格式不统一，模型需要适配多源异构数据。高频更新的数据要求模型调用响应速度匹配日更节奏，同时需处理大量依赖包与漏洞条目，上下文长度与输出token限制需适配批量分析场景，避免因单次处理量不足导致任务中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–16000 token | 适配SBOM清单与漏洞报告的批量数据长度，避免上下文溢出 |
| `maxTokens` | 4000–8000 token | 满足单批次依赖风险分析的输出需求，覆盖漏洞说明与修复建议 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保漏洞匹配与风险评级的一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写AI Proxy服务根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径 | 为App/Admin服务端必填环境变量，指定AI Proxy服务访问地址 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不能为空 | 为App/Admin服务端必填环境变量，用于AI Proxy服务身份验证 |

## 容易做错的三处
- 部署后在docker compose配置中未找到`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`相关环境变量。在FastGPT v4.17.0版本的部署模板中，部分部署场景未默认包含该类环境变量，需手动添加对应参数到compose文件。
- 模型输出文本长度受限，无法完整输出批量依赖的分析结果。原因是未调整`maxTokens`参数至适配批量分析的取值区间，默认上限无法覆盖多条目分析的输出需求。
- App/Admin服务启动校验失败。排查项：确认docker compose配置中已配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量，参数值与AI Proxy服务端配置一致，AI Proxy服务正常启动。

## 怎么确认配好了
- 检查App/Admin服务的docker compose配置文件中是否包含`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`相关环境变量，参数值与AI Proxy服务端配置一致。
- 发起单次小型依赖分析任务，查看模型输出的漏洞评级与修复建议是否符合预期，无上下文溢出或截断情况。
- 查看模型调用日志，确认无身份验证失败、超时或参数格式错误的报错记录。
- 调整`maxContext`与`maxTokens`参数后，验证批量分析任务能否正常完成，无中途中断情况。
