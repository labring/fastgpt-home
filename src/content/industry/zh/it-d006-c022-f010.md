# 信创替代适配的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据主要来自现有系统清单、国产软硬件目录、测试环境记录与厂商公开资料，日常产出适配清单、兼容性测试报告、迁移方案、问题台账四类文档。适配清单包含软硬件型号、版本号与兼容验证状态，测试报告关联测试用例ID与缺陷等级。数据更新以单个信创替代项目为周期，或按季度同步国产软硬件目录更新，无固定高频更新节奏。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的数据特征直接约束引用溯源环节的执行逻辑。由于数据来源分散，涵盖内部系统清单、外部国产软硬件目录与测试环境记录，需精准溯源每个引用片段的原始出处，避免混淆不同项目的适配数据。文档结构差异显著，适配清单、问题台账的字段规则各不相同，需在溯源时匹配对应文档的字段格式。数据更新以项目或季度为周期，引用时需标注数据的更新节点，确保适配验证的时效性。同时缺陷数据关联业务系统可用性，溯源需保留完整的测试环境与复现路径，保障引用的可信度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | `8000–12000 token` | 信创适配相关文档通常包含软硬件型号、测试步骤等长文本，需保留足够上下文避免截断关键验证信息 |
| `responseData` | 返回完整引用元数据 | 需包含适配文档的文件ID、测试用例ID等溯源字段，满足缺陷排查与合规追溯需求 |
| `detail` | 开启全量详情 | 信创缺陷分析需复现测试环境参数，全量详情可提供测试时间、环境配置等关键信息 |
| 单次搜索上限 | 前10条 | 信创适配知识库通常按项目划分，过多引用会导致上下文过载，10条可覆盖主要适配场景 |
| 引用数据唯一ID | 按查询到的单条数据ID | 匹配信创适配文档的字段规则，精准定位到具体测试用例或缺陷记录 |

## 容易做错的三处
- 现象：设置`quoteMaxToken`过大时，返回结果包含冗余的非适配相关文本，导致大模型生成内容偏离测试分析主题。原因：未结合信创适配文档的实际长度调整token上限，盲目放大参数导致上下文过载。
- 现象：批量上传5kb大小的适配文档后，部分文档显示训练异常，重新上传时未触发自动去重，导致知识库中存在重复的适配记录。原因：未开启知识库的自动去重配置，或上传时未匹配文档哈希标识，导致重复数据未被清理。
- 现象：在AI对话组件中引用测试用例数据时，无法获取正确的引用ID，导致溯源失败。原因：误将知识库文件集合ID作为引用ID，未使用查询到的单条数据ID作为溯源标识。

## 怎么确认配好了
- 发起一次信创适配缺陷分析的查询，检查返回结果中是否包含完整的引用元数据，包括文件ID、测试用例ID等字段。
- 查看知识库的引用日志，确认每次引用的片段都标注了正确的更新时间与来源文档。
- 上传重复的适配文档，检查知识库是否自动清理重复条目，验证去重配置生效。
- 调整`quoteMaxToken`参数后，验证返回的上下文长度符合预期，无关键信息截断情况。
