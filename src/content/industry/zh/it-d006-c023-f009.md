# 信息化预算与项目组合管理的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自财务系统、项目管理系统、合同台账与业务部门需求。日常产出的文档包含年度预算表、项目立项书、项目组合看板与投资复盘报告，字段包含预算额度（单位万元）、项目周期（单位月）、优先级等级、收益预估等。数据更新频率多为月、季或年度，单次批量数据体量较大，且不同系统导出的文档格式存在差异，部分为结构化表格，部分为纯文本汇报。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散要求工具调用需支持对接多系统接口，避免手动聚合数据带来的误差。批量大体积数据的处理需求，要求插件配置需适配增量拉取与分段解析，防止超时或上下文溢出。不同格式的文档要求工具调用的参数需兼容多类数据结构，确保字段解析的一致性。固定的更新频率要求工具触发逻辑需匹配数据更新周期，避免重复拉取过时数据或遗漏最新的预算与项目信息，影响测试用例与缺陷分析的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | 设为「auto」或指定为「budget_query, project_analysis」 | 适配多类工具的自动选择或定向调用品类相关数据的需求 |
| `functionCall` | 开启参数校验，限定传入字段为预算额度、项目周期等 | 确保传入的业务字段符合品类数据的格式与单位要求 |
| 工具调用超时时间 | 300–600 秒 | 适配批量拉取财务与项目数据的耗时，避免因数据体量过大导致超时 |
| 流式返回解析开关 | 开启 | 支持增量处理大体积的预算与项目文档，提升解析效率 |
| 知识库召回上限 | 前 3–5 条 | 避免过多数据超出上下文窗口，适配品类数据的整体体量 |
| FastGPT 版本 | v4.17.0 | 确保工具调用与插件功能的兼容性，适配当前版本的参数规则 |

## 容易做错的三处
- 调用对话接口时无法指定目标知识库，返回结果未关联预设的预算与项目数据。原因：未在请求参数中正确配置知识库关联规则，导致工具无法定向调用品类相关的数据集，影响测试用例的准确性。
- 流式返回的detail字段解析后出现字段为空或格式混乱。原因：未开启流式返回的结构化解析配置，直接按原始文本拆分数据，无法适配品类数据的多字段结构与单位要求。
- 工具调用触发逻辑异常，部分项目数据未触发工具调用。原因：未根据品类数据的更新频率调整工具触发的调度间隔，导致数据未及时拉取或重复触发无效调用，引发缺陷分析偏差。

## 怎么确认配好了
- 发起模拟测试调用，传入包含预算额度、项目周期的测试数据，确认工具自动调用对应系统接口拉取相关数据。
- 查看流式返回结果，确认detail字段被正确解析为结构化的预算与项目字段，无缺失或格式错误。
- 检查工具调用日志，确认`functionCall`参数被正确识别并执行预设的参数校验规则。
- 调整知识库召回上限参数，验证返回结果的条数符合预设的取值范围，确保上下文窗口适配合理。
