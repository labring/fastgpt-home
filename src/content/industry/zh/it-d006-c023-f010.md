# 信息化预算与项目组合管理的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自财务系统、项目管理系统、合同台账与业务部门需求，测试用例文档与缺陷报告也作为辅助数据纳入体系，用于验证预算分配与项目需求的匹配性。日常产出的文档包括年度预算表、项目立项书、项目组合看板、投资复盘报告，字段包含预算额度、项目编号、优先级标识、预期收益等。数据更新节奏通常为月度、季度或年度，单次更新涉及的文档体量随周期跨度变化，核心字段多为结构化数值与项目标识类文本。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散且涉及多套业务系统，引用溯源需建立跨系统的元数据关联规则，确保每条引用内容可追溯至原始台账、测试用例或缺陷报告。因数据更新节奏为月/季/年，引用的来源时效性需匹配业务周期，避免调用未完成更新的临时数据。不同文档的结构差异较大，既有结构化的预算表格，也有可视化的项目看板、长文本复盘报告与测试用例条目，溯源环节需适配多种文档格式的元数据提取逻辑，确保字段匹配的准确性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的界面逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | 800–1200 token | 该品类核心文档包含结构化预算数据、长文本复盘内容与测试用例条目，800-1200token可覆盖单条关键引用的完整上下文 |
| `responseData` | 返回原始来源元数据 | 该品类的溯源需关联财务系统、项目管理系统的结构化字段，返回原始元数据可直接匹配业务台账与测试用例记录 |
| `detail` | 开启 | 该品类的文档需明确标注来源的更新周期与项目ID，详细溯源可提取这些关键信息用于缺陷与预算匹配校验 |
| 单次搜索上限 | 前 5 条 | 该品类的项目组合与预算数据关联紧密，前5条高匹配度结果可覆盖主要业务关联项，避免冗余信息干扰测试用例校验 |
| 上下文超时时间 | 60 秒 | 该品类的数据更新周期较长，60秒的超时时间可覆盖多系统关联查询的响应延迟 |
| 重排 | 按实测标定 | 该品类的业务术语多为项目编号、预算编码等专属字段，需针对专属术语调整重排逻辑以提升匹配精度 |

## 容易做错的三处
- 现象：返回结果末尾自动附加未配置的引用链接列表，原因：未关闭默认的引用源展示开关，导致将财务系统、项目管理系统的后台日志作为冗余引用输出。
- 现象：溯源结果无法匹配到项目ID或预算额度字段，原因：未针对该品类的结构化文档配置专属字段匹配规则，仅使用通用全文检索逻辑。
- 现象：引用内容超出上下文长度被截断，原因：设置的`quoteMaxToken`参数值小于该品类单条核心引用的token量，导致关键预算或测试用例信息丢失。

## 怎么确认配好了
- 发起包含项目编号或预算额度的查询，检查返回结果是否附带对应文档的更新时间与来源路径。
- 查看引用结果的排序，确认高匹配度的项目关联内容优先展示。
- 调整`quoteMaxToken`参数值，验证返回的引用内容是否覆盖完整的业务字段与测试用例标识。
- 关闭引用展示开关，确认结果末尾不再附加冗余的引用链接列表。
