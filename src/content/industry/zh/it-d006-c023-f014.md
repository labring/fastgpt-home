# 信息化预算与项目组合管理的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自财务系统、项目管理系统、合同台账与业务部门需求，更新频率多为月、季或年度。日常处理的文档包含年度预算表、项目立项书、项目组合看板与投资复盘报告，文档字段多包含预算额度、项目编号、优先级评分、收益预估等，部分文档带有结构化表格与多段分析文本，无固定统一的格式模板。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入需兼容不同格式的数据源导入与解析；月度/季度/年度的更新节奏要求知识库同步频率需匹配业务更新周期，避免使用过时数据；长文本与结构化文档混合的特征，要求模型上下文容纳能力与片段截取规则适配不同长度的输入内容；同时，测试用例与缺陷分析的严谨性需求，要求模型输出需与原始数据的字段精度对齐，避免出现预算错配、项目重复建设类的偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 该品类文档多为长文本的预算表、复盘报告，需容纳多份项目与预算相关的数据源内容，避免上下文截断 |
| `maxTokens` | 2000–3000 token | 测试用例与缺陷分析的结果输出长度需求适中，兼顾输出完整性与调用成本 |
| `quoteMaxToken` | 4000 token | 需保留足够的原始文档片段用于溯源，匹配预算表、复盘报告的单页内容长度 |
| `toolChoice` | auto | 允许模型自主判断是否调用工具补充最新项目预算或项目组合数据 |
| `temperature` | 0.3–0.5 | 测试场景需结果严谨，避免过度发散导致的预算优先级判断偏差 |
| `AIPROXY_API_ENDPOINT` | 为AI Proxy服务的根地址，例如http://aiproxy:3000，勿附加/v1等路径 | 是App/Admin服务端的必填环境变量，需与AI Proxy服务端配置一致 |

## 容易做错的三处
- 排查项：检查App/Admin服务端是否已配置`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致且非空）与`AIPROXY_API_ENDPOINT`；未配置或配置错误会导致服务启动校验失败或模型调用异常。
- 现象为配置了支持联网的模型，但生成的测试用例未包含最新的项目预算数据；原因是未将`toolChoice`设为允许调用搜索工具，且知识库更新频率未匹配数据源的月更节奏。
- 现象为检索项目立项书时返回的关联片段与测试需求不匹配；原因是未根据文档的字段长度调整`quoteMaxToken`的取值，导致片段截取过长或过短。

## 怎么确认配好了
- 检查App/Admin服务端部署的环境变量，确认`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，`AIPROXY_API_TOKEN`为与AI Proxy服务端配置一致的非空管理员Token。
- 发起一次针对年度预算表的测试用例生成请求，检查返回结果中是否包含准确的预算额度与项目编号字段信息。
- 验证知识库更新任务的触发频率是否与数据源的更新节奏匹配，确保最新的项目组合数据已同步至知识库。
- 查看模型调用日志，确认`maxContext`与`maxTokens`的参数未触发超限报错，调用链路正常。
