# 信息流广告创意测试的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
不同于搜索广告的关键词管理，该品类核心测试对象为图片、视频与文案的组合效果。数据主要来自广告投放平台、内部素材库、用户互动数据与后端转化数据，更新频率多为日度或周度。日常关联文档包含创意脚本、素材测试表、投放数据报告与迭代清单，数据字段包含素材格式、文案内容、投放定向、点击率、转化成本等，无统一固定的字段长度要求，需匹配当前投放的广告账户配置。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散且更新频率不一，工作流需支持对接多源数据接口，同时需适配不同广告账户的字段差异。日常文档的结构化程度较低，工作流需包含文本解析节点，将脚本、测试表中的内容转换为可处理的测试用例。素材疲劳判断与测试结论归纳环节依赖实时互动数据，工作流需配置定时触发与批量处理能力，避免因单节点超时影响整体流程。另外，出错后果直接影响投放效果，工作流需添加失败重试与告警节点，确保异常可及时响应。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 全局变量初始化 | 按测试用例清单配置`variables`，包含素材ID、文案模板、投放定向 | 匹配日常文档中的创意脚本与测试表字段 |
| 多源数据拉取节点 | 拉取时间范围设为近7天，单次拉取条数上限为前200条 | 适配日/周更新的数据频率，避免接口过载 |
| 节点触发规则 | 按`variables`中标记的测试用例ID触发 | 精准匹配每个创意的独立测试流程 |
| 失败重试配置 | 重试次数设为3次，重试间隔为60秒 | 应对广告平台接口临时波动与短时异常 |
| 全局变量获取时机 | 按钮触发时读取已赋值的`variables` | 避免获取未初始化的变量值 |
| 工作流导出 | 按节点执行顺序导出配置文件 | 便于版本管理与跨团队同步 |

## 容易做错的三处
- 尝试为现有组件添加自定义参数后无法生效。原因是未在工作流的`variables`中提前注册该参数的键名与类型，系统未加载自定义配置项。
- 点击数据面板按钮时获取到未赋值的全局变量。原因是变量赋值节点的执行顺序晚于按钮触发节点，变量未完成初始化。
- 工作流调试时触发危险行为报错。原因是节点配置了无终止条件的循环逻辑，触发系统内置的安全拦截机制。

## 怎么确认配好了
- 执行一条测试用例，检查全局变量列表中是否包含所有预设的`variables`参数值。
- 触发数据面板按钮，核对返回的变量值是否与当前流程中的实时数据一致。
- 模拟一次广告平台接口异常，检查工作流是否触发预设的重试与告警逻辑。
- 导出工作流配置文件，核对节点顺序与参数配置是否与编辑界面一致。
