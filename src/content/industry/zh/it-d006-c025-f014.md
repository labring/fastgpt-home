# 值班排班与交接的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的典型数据来自SRE团队的排班系统、故障工单、监控告警与组织通讯录，更新频率为日或周。日常产出的文档包含固定格式的值班表、交接记录、升级联系人清单与值班日报，字段涵盖值班时段、交接事项、联系人信息、告警级别与响应时效要求，无额外统计类百分比数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源分散且包含多类结构化与非结构化文档，需支持多源数据的向量入库与上下文拼接；日/周级别的更新频率要求模型配置适配批量数据同步的节奏；值班表、交接记录等文档的固定字段结构，要求模型调用时需精准匹配对应字段进行分析；同时，排班冲突协调、交接遗漏等出错后果会影响业务连续性，因此模型调用的稳定性与结果严谨性需得到保障。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 值班相关文档包含多日交接记录、升级路径与完整排班信息，需容纳完整上下文以支持连贯分析 |
| `maxTokens` | `2000–3000 token` | 单条排班冲突分析或交接事项梳理的输出长度需求，避免截断关键信息 |
| `quoteMaxToken` | `1500–2000 token` | 需引用完整的值班表片段、升级联系人清单或历史交接记录，确保引用内容完整 |
| `toolChoice` | `auto` | 需自动判断是否调用工具完成排班协调、未结事项核对等任务，适配多场景需求 |
| `temperature` | `0.1–0.3` | 排班与交接场景需严谨结果，避免随机偏差导致的排班冲突或交接遗漏 |
| `AIPROXY_API_ENDPOINT` | 按部署的AI Proxy服务根地址填写，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions 路径，不得作为单模型服务地址 | 作为App/Admin服务端环境变量，配置AI Proxy服务的访问根地址 |
| `AIPROXY_API_TOKEN` | 配置与AI Proxy服务端一致的非空管理员Token | 作为App/Admin服务端环境变量，完成AI Proxy服务的身份验证，确保调用权限合法，不得使用应用API Key、模型供应商密钥或其他类型Token |

## 容易做错的三处
- 现象：检索值班表或交接记录时返回空结果或匹配内容偏差较大。原因：本地与服务器使用不同向量模型，嵌入维度不匹配，导致向量转换结果无法对齐。
- 现象：调用模型时返回状态码400或提示模型不支持当前任务。原因：未正确配置模型重定向规则，实际调用的模型无法处理排班冲突分析、交接事项梳理这类场景任务。
- 现象：修改FastGPT服务密码后无法正常启动核心进程。原因：未按服务分组重启对应模块，导致配置未生效或端口冲突。

## 怎么确认配好了
- 上传一份标准值班表文档，执行向量入库操作，查看FastGPT v4.17.0的入库日志中是否显示嵌入成功且维度匹配。
- 发起排班冲突检测的测试请求，查看返回结果是否包含对应值班人员的信息及协调建议。
- 检查App/Admin服务端的环境变量配置，确认`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token）已正确配置且非空。
- 触发交接记录的自动梳理任务，查看输出结果是否包含完整的未结事项与升级路径信息。
