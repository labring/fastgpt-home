# 关卡内容制作的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自关卡编辑器导出的关卡设计稿、美术资源库的资源清单、玩家测试反馈单与版本提交记录，以及缺陷系统的报错日志。日常维护的文档包含关卡路径节点坐标、资源摆放位置、任务触发规则等细粒度字段，更新频率为每周或每版本迭代。数据围绕具体地图与任务节点展开，不涉及抽象数值规则，仅记录落地后的内容状态与反馈。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据围绕具体地图节点与资源摆放展开，工具调用需精准匹配关卡坐标、资源ID等细粒度字段，无法仅依赖模糊文本检索。数据更新频率较高，插件需支持实时拉取最新版本提交记录与测试反馈，避免调用过时的关卡数据。由于出错后果直接影响上线节奏，工具调用的返回结果需附带明确的缺陷定位字段，便于快速关联对应关卡节点。同时，需适配关卡编辑器导出的标准化文档格式，确保插件能解析非结构化的设计稿内容。

## 配置怎么定
本页面基于 FastGPT v4.17.0 版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` 或 指定为 `["defect_analysis", "level_check"]` | 适配关卡内容制作的细分场景，自动选择对应工具或指定缺陷分析、关卡校验工具 |
| `functionCall` | `enabled` | 强制启用结构化函数调用，确保返回结果包含关卡节点ID、缺陷位置等可解析字段 |
| 知识库绑定规则 | 按当前关卡版本绑定专属知识库 | 避免检索到无关版本的关卡数据，缩小检索范围 |
| 单次工具调用超时时间 | `30–60 秒` | 适配关卡数据加载与测试反馈分析的耗时需求 |
| 工具调用结果返回条数 | `前 3–5 条` | 聚焦高优先级的关卡缺陷与路径问题 |

## 容易做错的三处
- 现象：工具调用节点返回空结果或状态码 500。原因：未绑定当前关卡版本对应的专属知识库，导致检索范围覆盖无关数据。
- 现象：工具返回的结果未包含关卡节点ID或资源ID字段。原因：未启用`functionCall`参数，导致返回结果为非结构化文本，无法解析具体缺陷位置。
- 现象：工具调用超时。原因：未配置合理的超时时间，导致无法完成大型关卡数据的加载与分析。

## 怎么确认配好了
- 发起一次针对当前关卡设计稿的工具调用，检查返回结果是否包含关卡节点ID与缺陷定位字段。
- 查看工具调用日志，确认是否拉取了当前版本的测试反馈单与资源清单。
- 切换至其他关卡版本，验证工具调用是否仅检索对应绑定的知识库内容。
- 调整`toolChoice`参数为`auto`，确认工具自动选择了缺陷分析与关卡校验的对应功能。
