# 关卡内容制作的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自关卡编辑器、美术资源库、玩家测试数据与缺陷系统。日常产出的文档包含关卡设计稿、资源需求表、测试反馈单、版本提交记录，字段涵盖关卡ID、资源路径、测试用例编号、缺陷严重等级、提交时间等。数据更新以周或每版本为周期，随关卡迭代、测试反馈与版本提交实时或批量更新，不同来源的数据格式存在一定差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散在多类系统与文档中，不同来源的格式差异会增加模型接入时的格式适配难度。周度或版本级的更新节奏要求配置的上下文窗口可灵活调整，适配不同周期的测试数据量。文档与数据中的多字段关联逻辑，需要在模型配置中开启对应关联检索能力，确保测试用例生成与缺陷分析能匹配关卡ID、资源路径等关键信息。同时，测试反馈单与缺陷系统的实时性要求，需配置合理的请求频率避免超出接口限制，保障数据处理的及时性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 配置为AI Proxy服务的根地址，包含完整协议与端口，不得附加`/v1`或模型接口路径 | 作为App/Admin服务端必需的环境变量，确保模型请求能正常转发至AI Proxy服务 |
| `AIPROXY_API_TOKEN` | 配置为与AI Proxy服务端一致的管理员Token，不能为空 | 作为App/Admin服务端必需的环境变量，保障AI Proxy服务的访问鉴权安全 |
| `maxContext` | 8000–12000 token | 适配周度或版本级的测试反馈单、关卡设计稿等多文档的上下文长度，避免截断关键测试信息 |
| `maxTokens` | 2000–3000 token | 控制单轮测试用例生成或缺陷分析的输出长度，适配关卡内容的详细描述需求 |
| `temperature` | 0.3–0.6 | 平衡测试用例的规范性与灵活性，避免生成过于发散或过于刻板的关卡测试内容 |
| `toolChoice` | auto | 自动选择是否调用检索工具，适配多源数据的关联分析需求 |

## 容易做错的三处
- 现象：模型输出未包含思考过程，仅返回最终测试用例。原因：未开启模型的思考过程展示配置，或输出格式未包含中间步骤的要求。
- 现象：部署后无法连接到AI Proxy服务，日志显示地址解析失败或鉴权失败。原因：未正确配置服务端环境变量`AIPROXY_API_ENDPOINT`，或`AIPROXY_API_TOKEN`配置有误。
- 现象：重排模型调用失败，返回模型不兼容提示。原因：未在配置中指定适配的重排模型，或使用了未支持的模型类型如gte-rerank-v2未正确配置调用路径。

## 怎么确认配好了
- 发起测试请求，输入一份关卡设计稿片段，检查是否能生成对应的测试用例，且输出风格符合配置的temperature参数对应的表现。
- 查看服务端启动日志与模型调用日志，确认AI Proxy连接正常，无鉴权或地址错误的提示。
- 提交包含多字段关联信息的测试数据，检查模型是否能正确关联关卡ID与对应缺陷、资源信息，生成针对性的分析结果。
- 测试较长上下文的输入，确认`maxContext`配置未触发内容截断，输出完整且覆盖关键测试信息。
