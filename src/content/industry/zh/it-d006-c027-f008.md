# 内容审核规则运营的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
本品类的数据来源包含内容审核后台的规则配置、用户举报的违规样本、公开法规政策文本、标注过的合规与违规样本库。日常维护的文档包括审核规则细则、违规内容处置指南、用户申诉记录、月度质检报告。不同文档的字段结构各有侧重，审核规则包含触发条件与处置动作，申诉记录包含申诉理由与复核结果。数据更新频率随政策调整或每日同步，无固定的批量统计阈值。本页面基于FastGPT v4.17.0版本编写。

## 这些特征在「工作流编排」这一环带来什么约束
多来源的数据输入要求工作流支持多数据源的绑定与切换，避免手动整理数据的重复操作。不同文档的字段结构差异需要在工作流中配置统一的映射规则，确保各环节的数据格式一致。数据更新频率随政策或每日同步，要求工作流支持定时触发与手动触发两种模式，适配不同的运营节奏。疑难样本判定的耗时环节需要在工作流中插入人工审核节点，处理无法自动完成的判定任务，同时配置失败告警机制，避免异常流转带来的违规风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 每日定时触发或政策变更后手动触发 | 数据更新频率为日/随政策调整 |
| 数据源绑定 | 绑定`variables`中预设的审核后台、样本库变量 | 多来源数据需要统一管理输入路径 |
| 字段映射规则 | 按文档类型匹配对应字段 | 审核规则、申诉记录等文档字段结构不同 |
| 人工审核触发阈值 | 按业务需求设定的置信度阈值 | 适配疑难样本判定的耗时环节 |
| 失败告警节点 | 关联`nodeId`为alarm_001的告警节点 | 异常时及时通知运营团队 |
| 重试次数 | 3次，间隔60秒 | 处理临时的数据源连接波动 |

## 容易做错的三处
- 现象：工作流中配置AI对话组件时出现未捕获的异常。原因：私有部署环境下的配置文件未正确关联审核规则的数据源路径。
- 现象：工作流无法选择简易模型作为问题分类节点的数据源。原因：未在`variables`中绑定模型调用的权限变量，导致可选模型列表未加载。
- 现象：控制台抛出bootstrap-legacy-autofill-overlay.js相关的类型错误。原因：工作流节点的`nodeId`配置重复，导致前端渲染冲突。

## 怎么确认配好了
- 手动触发一次工作流，检查输入的审核规则样本是否按配置的字段映射完成格式转换。
- 查看告警节点的触发日志，确认异常场景下是否能正确推送通知。
- 检查`variables`中绑定的数据源变量是否包含审核后台、样本库的正确路径。
- 验证按业务需求设定的低置信度样本是否自动流转至人工审核节点。
