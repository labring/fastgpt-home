# 内容审核规则运营的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
本品类数据主要来自内容审核后台、用户举报渠道、公开法规政策、合规样本库。日常产出的文档包含审核规则、处置指南、申诉记录、质检报告，文档字段包含规则标识、触发条件、处理流程、申诉状态等。数据更新频率为每日同步或随政策变更即时更新，单条数据体量随审核场景复杂度变化，无固定统计标准。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的数据特征对引用来源与溯源环节带来多重约束。首先，数据来源分散，包含审核后台、用户举报、政策文件等多个渠道，需在引用时关联对应来源的唯一标识，确保溯源时可快速定位原始数据节点。其次，更新频率不固定，随政策变更即时更新或每日同步，需在溯源信息中同步标注数据生效时间，避免使用过期审核规则。再者，日常文档类型多样，包含审核规则、处置指南、申诉记录等，需区分不同文档的引用格式，确保溯源信息可被快速识别。最后，单条数据体量随场景复杂度波动，需限制单条引用的字符长度，避免超出大模型上下文承载上限。

## 配置怎么定
本配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配本品类单条审核规则、申诉记录的典型字符长度，避免超出大模型上下文阈值 |
| `responseData` | 包含来源标识、生效时间字段 | 满足溯源时需关联原始数据节点与生效时间的约束 |
| `detail` | 开启完整字段返回 | 确保引用时可获取审核规则的触发条件、申诉记录的处理结果等完整信息 |
| 单次搜索上限 | 前10条 | 覆盖日常审核场景的典型样本数量，避免冗余数据干扰 |

## 容易做错的三处
- 现象：配置`quoteMaxToken`为3000时，大模型无法获取上下文内容。原因：本品类单条数据体量波动较大，3000 token超出多数大模型的上下文承载上限，导致系统截断引用内容。
- 现象：返回的引用内容中未携带来源标识与生效时间。原因：未开启`responseData`配置，未指定需返回的来源相关字段，导致引用时未携带原始数据的元信息。
- 现象：将HTTP响应数据作为知识库引用后无效果。原因：未将响应数据转换为符合平台要求的结构化格式，未关联对应来源标识，导致系统无法识别有效引用内容。

## 怎么确认配好了
- 发起一条包含审核规则相关的查询，查看返回结果中是否携带来源标识与生效时间字段。
- 调整`quoteMaxToken`的取值，验证大模型是否能正常接收并使用引用内容。
- 上传一条测试用的审核规则文档，确认引用时可完整获取文档内的触发条件与适用场景信息。
- 调用指定接口，验证返回的`responseData`字段包含预设的来源与元数据信息。
