# 内容审核规则运营的测试用例与缺陷分析：模型接入与配置
本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的数据主要来自内容审核后台、用户举报渠道、公开法规政策文件与内部审核样本库。日常维护的文档包含审核规则条目、违规内容处置指南、用户申诉记录与季度质检报告。数据更新频率为每日同步，或随监管政策调整即时更新。文档结构以规则编号、触发条件、处置阈值为核心字段，样本库包含标注过的合规/违规内容片段，按内容类型与审核场景分类存储。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新频率不固定，要求模型接入时支持多数据源的批量调用与增量同步。审核规则与样本库的字段无统一格式，要求配置环节支持自定义提示词适配不同文档结构。最耗时的规则解释与疑难样本判定环节，需要模型处理长文本与复杂场景，因此需限制上下文与token消耗。出错后果直接关联监管与用户权益，要求模型调用的稳定性与结果可追溯，需配置明确的失败重试与日志记录机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配审核规则与申诉记录的长文本长度，避免截断关键规则描述 |
| `maxTokens` | 4000 token | 控制单轮审核结果的输出长度，防止超出内容平台的接口限制 |
| `temperature` | 0.1–0.3 | 降低随机输出概率，保证审核规则判定的一致性 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径，非单模型服务地址 | 为AI Proxy依赖的App/Admin服务端环境变量，确保服务可连接AI Proxy |
| `AIPROXY_API_TOKEN` | AI Proxy管理员Token，需与AI Proxy服务端配置一致且非空，非应用API Key、模型供应商密钥等 | 为AI Proxy依赖的App/Admin服务端环境变量，用于身份验证 |
| `vision` | 开启 | 支持接入视觉模型处理图片类审核样本 |

## 容易做错的三处
- 现象：批量执行节点在线调试正常，但API调用时无法完成全部循环。原因：未配置`maxContext`适配批量请求的上下文累积，导致长循环触发上下文溢出。
- 现象：接入视觉模型后无法处理审核图片样本。原因：未开启`vision`配置项，或未在提示词中明确指定视觉输入的处理逻辑。
- 现象：模型调用返回的审核结果与预设规则偏差较大。原因：`temperature`取值过高，导致判定结果出现随机波动，未匹配审核规则的严格一致性要求。

## 怎么确认配好了
- 执行单条审核规则的测试用例，检查接口返回的结果是否包含完整的规则判定逻辑。
- 检查App/Admin服务端是否正确配置了`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量，未出现格式错误，且`AIPROXY_API_TOKEN`非空。
- 调整`temperature`参数后，对比同一样本的多次调用结果，确认判定结果的一致性符合预期。
- 提交批量样本测试，检查循环执行的完整性与结果的可追溯性。
