# 内容推荐运营的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
内容推荐运营的日常数据来自内容标签、用户行为日志、实验平台与推荐后台，更新频率多为日或周。日常产出的文档包含推荐策略记录、内容池清单、实验报告与运营复盘，其中内容池清单包含内容标识、分类标签、上线时间等字段，实验报告包含曝光量、点击率等统计项，用户行为日志包含交互时长、跳转路径等原始数据。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新周期不一，要求工作流支持多数据源的定时拉取与字段映射。文档结构异构且字段多样，需要通过统一的变量配置实现跨文档数据调用，避免手动整理的冗余操作。异常排查与指标解读环节耗时占比高，工作流需自动化筛选异常内容与解读实验数据，同时需配置失败触发分支，防止低质内容放大或核心指标下滑。内容池的常规规模较大，工作流需限定单次处理的内容数量，避免资源过载。

## 配置怎么定
FastGPT v4.17.0 版本下，以下配置项可直接在工作流编辑器中完成设置：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按文档字段映射配置 | 内容池清单、实验报告存在多异构字段，需通过`variables`统一调用，适配跨文档数据获取 |
| `nodeId` | 按环节拆分配置唯一标识 | 工作流需串联内容筛选、缺陷检查、结果输出多个独立环节，通过`nodeId`实现节点定位与调试 |
| 单次搜索上限 | 前20条 | 覆盖内容池常规候选范围，避免冗余数据影响大模型处理效率 |
| 最大上下文 | 800–1200 字符 | 适配推荐策略文档的常规长度，匹配大模型的上下文处理能力 |
| 调试超时时间 | 600 秒 | 覆盖常规内容检查与数据拉取的耗时，避免调试过程意外中断 |
| 失败触发阈值 | 按实测标定 | 不同运营场景的异常容忍度存在差异，需结合实际业务调整 |

## 容易做错的三处
- 现象：工作流中仅能调用单变量，下拉菜单仅展示单文档字段。原因：未通过`variables`配置多字段映射规则，仅默认调用单文档的固定字段。
- 现象：调试节点无法停止，工作流持续执行无响应。原因：未配置调试超时终止规则，且未在编辑器中设置强制停止入口。
- 现象：知识库引用检查结果为空，未输出异常内容。原因：未设置异常触发分支，当引用内容不符合规则时未触发结果输出环节。

## 怎么确认配好了
- 导入一份测试用的内容池清单与实验报告，验证工作流能否自动拉取多字段数据并完成关联。
- 触发调试模式，手动终止节点运行，确认调试状态可正常退出，无持续执行的残留进程。
- 构造一条不符合规则的知识库引用内容，验证工作流是否输出异常提示与对应内容详情。
- 查看工作流运行日志，确认各节点的`nodeId`与配置参数匹配无误。
