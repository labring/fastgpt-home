# 内部网络与WiFi运维的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自交换机控制台、无线控制器、办公网络监控系统及一线用户报障记录。日常产出的文档包含网络拓扑图、变更单、故障排查记录、无线覆盖巡检表，字段包含端口编号、VLAN标识、信号强度参数、巡检周期、故障定位时间等。数据更新节奏为每日更新或随网络变更即时同步。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散于多类硬件控制台与系统，工具调用需适配不同协议的接口格式，需提前配置各数据源的访问权限。日常文档包含混合结构的网络拓扑图、巡检表与故障记录，插件需支持解析不同格式的附件内容。数据更新随网络变更即时触发或每日同步，工具调用需支持动态拉取最新配置与巡检数据，避免使用过期信息。故障定位依赖多维度数据关联，插件需支持跨数据源的字段匹配逻辑，简化人工核对流程。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `functionCall` | 强制启用 | 确保模型仅调用预设的运维工具，避免生成不符合流程的非结构化分析内容 |
| 多源数据拉取间隔 | 600–1800 秒 | 平衡网络数据的时效性与系统资源占用，适配该品类日/变更级的更新节奏 |
| `toolChoice` | 限定为端口检测、巡检查询、故障定位工具 | 仅开放与内部网络运维相关的工具权限，缩小调用范围 |
| 插件附件解析范围 | 拓扑图、故障日志、无线巡检表 | 匹配该品类日常使用的文档类型，避免解析无关附件 |
| 接口超时阈值 | 30–60 秒 | 适配交换机、无线控制器等硬件接口的常规响应时长，减少无效等待 |
| 结果缓存时长 | 86400 秒 | 契合该品类数据日更特性，避免缓存过期或过长占用存储资源 |

## 容易做错的三处
- 现象：调用本地ollama模型时返回空内容。原因：未在插件配置中正确指定ollama的本地接口地址与模型名称，导致工具调用无法正常拉取模型响应。
- 现象：调用openapi接口时提示缺少应用ID参数，且无法通过现有接口创建应用。原因：未提前配置应用创建的前置权限，或未在工具调用中绑定对应应用的标识参数，导致接口鉴权失败。
- 现象：工作流中处理HTTP文件流（如文生图返回的图片）时无解析结果。原因：未配置插件的文件流接收与转换逻辑，仅支持结构化文本接口的调用，无法处理二进制文件内容。

## 怎么确认配好了
- 执行端口检测工具调用测试，核对返回结果与交换机控制台的实际端口状态是否一致。
- 模拟一次网络变更操作，查看插件是否自动拉取最新的巡检表与故障记录，确认数据更新符合预设节奏。
- 调用指定的模型工具，检查返回内容是否严格遵循预设的工具调用格式，无自由生成的无关内容。
- 测试二进制文件流的接口调用，确认插件可正确接收并转换文件内容，生成符合预期的输出。
