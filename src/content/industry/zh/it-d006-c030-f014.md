# 内部网络与WiFi运维的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
这个品类的日常数据主要来自交换机控制台、无线控制器、监控系统及用户报障渠道，更新频率为每日或每次网络变更后。典型文档包含网络拓扑图、变更单、故障记录、无线覆盖巡检表，字段涵盖设备端口号、VLAN配置、信号强度、故障发生时间与影响范围，无统一标准化统计单位，需结合具体运维场景适配。数据主体为网络管理员、桌面支持及外包驻场人员，核心围绕办公现场的网络接入与故障排查展开。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源分散且包含图像类文档，模型接入需支持多类型数据源的解析与对接。每日更新的故障记录与临时变更单要求上下文窗口需适配非固定长度的文档输入，避免截断关键信息。同时，运维场景对结果严谨性要求较高，需限制模型的发散性输出，且需支持调用内部运维工具完成端口核对、覆盖盲区排查等耗时环节。此外，内部网络的安全要求需对模型访问密钥与接口地址进行严格绑定，防止未授权访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配日常故障记录、巡检表等文档的总长度，避免上下文截断 |
| `maxTokens` | 2000–3000 token | 匹配测试用例与缺陷分析的合理输出长度，避免结果过长或过短 |
| `toolChoice` | auto | 支持模型自主选择调用端口核对、覆盖排查等内部运维工具，提升分析效率 |
| `vision` | 开启 | 用于解析网络拓扑图、无线覆盖巡检表等带图像的文档，提取关键配置信息 |
| `temperature` | 0.3–0.5 | 控制模型输出的严谨性，减少无关发散，适配运维场景的精准分析需求 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的非空管理员Token | 作为App/Admin服务端环境变量，用于鉴权访问AI Proxy服务 |

## 容易做错的三处
- 配置`AIPROXY_API_TOKEN`后调用失败，返回密钥无效。排查项：确认该变量为与AI Proxy服务端配置一致的非空管理员Token，未使用应用API Key、模型供应商密钥或其他非管理员Token。
- 本地部署的模型添加后无法调用，返回连接超时。排查项：确认`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址（如http://aiproxy:3000，勿附加/v1或模型接口路径），且该地址可从App/Admin服务端网络访问；确认使用FastGPT v4.17.0+版本的部署方式。
- 模型输出提示请求不完整，无法生成完整测试用例。原因是`maxContext`设置过小，无法容纳完整的故障记录与巡检表数据，导致上下文截断。

## 怎么确认配好了
- 检查App/Admin服务端启动日志，确认无环境变量缺失或校验失败提示；验证AI Proxy服务可正常响应请求。
- 上传一张标准格式的网络拓扑图，确认`vision`参数生效，模型能准确识别图中的设备端口与VLAN配置信息。
- 查看接口返回的token消耗数据，确认`maxTokens`与`maxContext`的取值符合预期，未出现频繁的上下文截断或输出长度超限。
- 触发工具调用测试，输入需要端口核对的查询，确认`toolChoice`参数自动触发了对应的内部运维工具调用。
