# 创作者入驻与认证的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
该品类的数据围绕创作者准入与身份验证生成，日常文档包含入驻申请、身份资质材料、认证审核记录、合作协议。数据来源覆盖创作者后台、企业信用信息平台、账号历史库与合同系统，更新频率为每日或随单份申请提交触发。字段包含申请标识、资质类型、审核状态、合作绑定信息等，无统一固定单位，随对应文档的字段规则调整。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据多源分散且随单申请更新，要求工具调用需支持对接创作者后台、企业信用信息等多类数据源，适配按需触发的执行节奏。核心环节资质核验与账号风险判断依赖多字段组合校验，工具调用需整合多维度数据输入，避免单源数据偏差导致的核验失效。数据关联合作协议与权益分配，工具调用的输出需严格匹配文档字段格式，防止出现权益错配类错误。同时，因出错后果涉及虚假认证与合作纠纷，工具调用需增加前置校验与失败兜底机制。

## 配置怎么定
以下配置适用于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配不同类型入驻申请，自动选择资质核验、账号风险判断等对应工具 |
| `functionCall` | 启用并限制工具范围 | 仅允许调用资质验证、信用查询类工具，规避越权调用风险 |
| 单次工具调用超时时间 | 300-600 秒 | 资质核验需对接多数据源，耗时存在波动，该区间可覆盖多数正常场景 |
| 工具调用结果缓存时长 | 1 天 | 匹配数据每日或随申请更新的频率，避免缓存数据与最新资质信息不符 |
| 工具调用失败重试次数 | 2-3 次 | 规避临时网络波动或数据源临时不可用导致的调用失败 |
| 输入字段映射规则 | 按入驻申请文档字段一一对应 | 严格匹配入驻申请、资质材料的字段格式，确保工具调用输入数据准确 |

## 容易做错的三处
- 现象：循环调用AI会话处理资质材料数组时，工具调用输入字段为空或格式异常。原因：未将入驻申请中的资质材料数组正确映射到循环输入参数，导致循环体无法读取对应数据。
- 现象：集成的插件无法与对话应用正常联动，工具调用无响应。原因：未配置对话应用与工具调用的参数映射规则，导致申请数据无法正确传递到插件。
- 现象：工具调用返回“Failed to get the VQD”类报错。原因：未对查询参数做前置校验，直接使用未处理的创作者账号名作为查询词，触发工具接口异常。

## 怎么确认配好了
- 提交一份测试入驻申请，查看工具调用是否自动触发对应流程，无异常中断。
- 查看工具调用日志，确认仅调用已配置的授权工具，无未授权工具的调用记录。
- 模拟数据源临时不可用的场景，验证工具调用是否触发重试机制并在恢复后正常执行。
- 核对工具输出的字段与入驻申请文档的字段是否完全匹配，无缺失或格式偏差。
