# 前端应用开发的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
通常，前端应用开发的测试用例与缺陷分析数据来自代码仓库、接口管理平台、设计稿及浏览器兼容性数据，更新频率为每日或每版本发布时。日常配套文档包含接口文档、组件说明、联调记录与发布清单，测试用例多围绕页面渲染、交互逻辑、兼容问题展开。数据字段一般包括测试用例ID、缺陷等级、复现步骤、浏览器兼容版本、接口请求参数等，不同来源的数据结构差异明显，代码仓库的缺陷数据多关联代码提交记录，接口管理平台数据则聚焦请求响应异常。

## 这些特征在「工作流编排」这一环带来什么约束
由于前端测试数据来源分散且更新频率较高，工作流需要支持多数据源并行拉取，避免单节点拉取导致的超时问题。日常文档类型多样，工作流需通过`variables`传递不同文档的上下文参数，确保每个节点调用对应类型的文档内容。前端应用更关注UI状态与终端兼容，工作流需单独设置兼容性数据校验节点，且触发时机需匹配版本发布或日常迭代节奏，避免冗余执行。同时，数据结构差异要求工作流节点支持自定义字段映射，适配不同来源的数据格式，确保数据调用的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发时机 | 版本发布后10分钟 / 每日凌晨2点 | 匹配前端应用的版本更新与日常迭代节奏，符合数据更新频率 |
| `variables`配置 | 绑定接口文档、联调记录的上下文变量 | 适配多类型前端测试文档的调用需求，传递对应场景的专属参数 |
| 节点超时设置 | 600秒 | 覆盖前端多数据源拉取的耗时需求，避免因代码仓库数据量大导致的执行中断 |
| 问题分类模型 | 通用文本分类模型，配置前端缺陷专属提示词 | 适配前端缺陷的场景特征，提升UI异常、兼容报错等分类的准确率 |
| MCP接入配置 | 绑定外部代码仓库接口的权限密钥 | 适配FastGPT v4.17.0的外部插件接入规范，支持拉取前端专属数据源 |
| `nodeId`配置 | 对应数据源节点的唯一标识 | 确保工作流节点调用的数据源准确，避免不同数据源节点的混淆 |

## 容易做错的三处
- 工作流调用后返回结果中出现「知识库检索：xxx」的冗余内容，原因是未在工作流节点中关闭默认的知识库检索开关，导致冗余检索内容被带入输出。
- 工作流中问题分类的识别准确率偏低，原因是未配置适配前端缺陷场景的专属提示词，使用通用分类模型无法精准识别前端UI布局异常、兼容报错等特定缺陷类型。
- 外部MCP插件调用失败，原因是未正确配置插件的权限参数与数据源绑定关系，导致无法正常拉取前端代码仓库或接口管理平台的测试数据。

## 怎么确认配好了
- 手动触发一次测试工作流，检查最终输出结果是否仅包含缺陷分析与测试用例结论，无「知识库检索」相关的冗余内容。
- 查看工作流的`variables`配置项，确认已绑定对应前端测试场景的接口文档、联调记录等数据源，无遗漏的关键测试数据来源。
- 测试MCP插件的调用功能，验证外部服务能否正常拉取代码仓库中的缺陷数据与联调记录，确认插件接入生效。
- 调整问题分类模型的提示词，触发测试后检查分类结果是否匹配前端常见的缺陷类型，如UI渲染异常、浏览器兼容报错等，确认分类逻辑生效。
