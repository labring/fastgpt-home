# 前端应用开发的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据主要来自代码仓库、接口管理平台、设计稿文件与浏览器兼容性数据集。日常产出的文档包含接口文档、组件说明、联调记录与版本发布清单。数据更新节奏多为每日同步或随版本发布更新，字段涵盖接口请求参数、组件兼容性标记、页面渲染异常日志、缺陷复现步骤等，无统一固定单位，随具体数据类型变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
前端应用开发的测试数据多为每日或版本级更新，模型接入需适配高频调用场景，需配置合理的上下文长度避免内容溢出。数据来源分散，涵盖接口文档、联调日志等多格式内容，模型调用需支持兼容多源数据的解析，需明确接口端点与鉴权配置适配内网或公网部署环境。前端测试数据包含大量终端兼容性细节与页面状态异常信息，模型配置需支持调整temperature参数，适配不同复杂度的缺陷分析与测试用例生成需求，同时需兼容仅支持stream模式的大模型调用。

## 配置怎么定
本文档适用于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配前端测试用例与缺陷日志的平均长度，避免上下文溢出导致调用失败 |
| `maxTokens` | 2000–3000 token | 控制单轮模型输出长度，适配缺陷分析报告或测试用例生成的常规篇幅 |
| `temperature` | 0.3–0.7 | 平衡缺陷分析的准确性与多样性，适配前端场景下的标准化与个性化需求 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000 | 为AI Proxy服务的根地址，不得附加/v1或/chat/completions路径，不得填写VLLM/Ollama/Xinference等单模型地址，适配部署环境的网络访问 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token | 完成AI Proxy服务的身份验证，确保接口访问权限合法，且不能为空 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具，适配前端测试中多源数据的整合需求 |

## 容易做错的三处
- 调用仅支持stream模式的大模型时出现调用失败。可排查项：检查模型配置是否启用stream模式适配，是否兼容目标API的流式返回规则。
- 本地前端项目切换模型渠道后返回304状态码。可排查项：检查是否存在浏览器缓存导致接口请求未重新发起，或模型渠道的接口地址配置是否同步更新。
- 配置模型渠道后出现调用日志报错「获取数据异常」。可排查项：检查模型渠道的鉴权密钥配置是否正确，接口端点地址是否与实际部署环境匹配。

## 怎么确认配好了
- 检查App/Admin服务端环境变量配置，确认已正确设置非空的AIPROXY_API_ENDPOINT和AIPROXY_API_TOKEN。
- 提交一份前端缺陷日志或接口联调记录作为输入，验证模型生成的分析结果符合预期格式。
- 查看系统调用日志，确认无鉴权异常、接口超时或数据解析失败的条目。
- 在内网部署场景下，确认服务器可访问配置的API端点，无网络阻断记录。
