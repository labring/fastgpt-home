# 单元测试与组件测试的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
本品类的数据主要来自代码仓库、测试框架报告、需求说明与接口定义，更新频率为每日或每代码提交一次。日常关联文档包含测试用例、覆盖率报告、Mock说明与缺陷单。测试用例字段包含用例标识、前置条件、预期行为与执行结果；覆盖率报告包含代码行覆盖率、分支覆盖率等量化指标；Mock说明包含模拟对象的入参规则与返回值定义；缺陷单包含缺陷等级、复现步骤与关联用例ID。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据高频更新且关联文档格式各异，为工作流编排带来多重约束。首先，数据随代码提交或每日更新，工作流需配置为触发式拉取最新的代码仓库、测试报告数据，避免使用静态缓存导致的信息滞后。其次，测试用例、覆盖率报告、缺陷单等文档字段格式差异明显，工作流需配置字段映射规则，实现不同文档间的自动关联。此外，测试数据构造与失败用例定位环节耗时较长，工作流可集成预设节点，自动生成Mock数据或回溯失败用例的关联代码提交记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按代码提交事件触发，或每日凌晨2点定时触发 | 适配本品类数据日/每提交的更新频率，保证工作流使用最新的测试与代码数据 |
| 变量配置 `variables` | 绑定测试用例ID、缺陷单关联字段 | 实现测试用例与缺陷单的自动关联，匹配本品类文档的关联需求 |
| 节点ID `nodeId` | 为每个功能节点分配唯一标识 | 便于工作流调试与节点间的数据传递，避免节点识别冲突 |
| 失败处理策略 | 触发告警并暂停后续节点，或跳过失败节点继续执行 | 适配本品类出错后果，可根据业务场景选择对应处理逻辑 |
| 数据拉取范围 | 拉取近1次提交的测试报告，或近7天的缺陷单数据 | 按实测标定，避免拉取过量数据导致工作流超时 |
| 字段映射规则 | 将测试用例的用例ID映射为缺陷单的关联用例字段 | 匹配本品类文档的字段结构，实现自动化关联 |

本页面配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：本地部署后打开工作流页面，控制台报错Cannot read properties of undefined (reading 'incl')。原因：未正确配置`variables`参数的关联字段，导致工作流尝试读取未初始化的变量属性。
- 现象：创建插件后在其他工作流引用并接入代码运行节点，输入配置时弹出报错提示。原因：未为插件节点分配唯一`nodeId`，导致工作流无法识别插件的输入输出映射关系。
- 现象：创建工作流模板后进入编辑页面，页面加载缓慢或功能按钮无响应。原因：未适配本品类高频更新的数据拉取规则，导致工作流尝试拉取过量的测试报告数据触发超时。

## 怎么确认配好了
- 触发工作流一次，检查是否能自动拉取最新的代码提交与测试报告数据。
- 查看工作流的字段映射配置，确认测试用例与缺陷单的关联关系符合预期。
- 模拟测试用例执行失败的场景，检查失败处理策略是否按配置触发对应动作。
- 检查工作流的`variables`与`nodeId`参数是否已正确配置，无空值或重复标识。
