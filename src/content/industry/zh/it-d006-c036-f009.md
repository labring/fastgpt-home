# 原型与交互设计的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
这个品类的典型使用主体为产品设计师、交互设计师与前端产品小组。日常产出的文档通常包含交互原型、页面流程图、组件说明与评审记录。数据主要来源于Figma或Axure文件、团队内部设计系统、用户反馈及可用性测试记录，更新频率通常为每周或每版本迭代一次。日常处理的核心内容为页面结构与操作路径，需梳理状态流转、补齐异常场景并完成设计评审修改，若处理不当可能引发研发理解偏差、上线后操作路径不通或返工问题。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源多为结构化或半结构化的设计文件，需插件支持解析Figma/Axure的导出格式，因此插件配置需适配特定文件类型的解析规则。数据更新频率为周或每版本，工具调用的触发时机需匹配该节奏，避免过度触发导致资源浪费。日常文档的字段多与页面节点、交互逻辑相关，工具入参需精准映射原型中的具体元素，避免泛化提取内容。同时，出错后果直接影响研发与上线流程，需配置失败重试与校验机制，降低异常场景下的处理风险。

## 配置怎么定
在FastGPT v4.17.0版本中，针对原型与交互设计场景的工具调用与插件配置可参考以下规则：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配原型与交互设计分析的灵活需求，可自动判断是否需要调用插件完成测试用例生成 |
| `functionCall` | 强制指定交互路径分析 | 精准提取原型中的操作逻辑，避免生成泛化的测试用例，匹配该品类对页面结构的核心处理需求 |
| 插件触发时机 | 原型文件上传完成后 | 匹配该品类周/每版本的更新频率，无需实时触发，降低系统资源消耗 |
| 参数映射规则 | 将原型页面ID映射为工具入参`q` | 适配日常文档中的页面流程图与组件说明，确保工具调用时能精准匹配目标分析对象 |
| 失败重试次数 | `2 次` | 应对原型文件可能存在的格式异常，降低单次解析失败的概率 |
| 结果输出格式 | JSON格式，包含操作路径、异常场景 | 标准化输出结果，便于后续生成测试用例与缺陷分析文档 |

## 容易做错的三处
- 现象：插件配置后无法在工具列表中找到，界面提示“未找到匹配的插件配置”。原因：未将插件文件放置到FastGPT指定的插件存储目录，或配置路径时未匹配系统默认的插件加载路径。
- 现象：工具调用返回结果为空或核心字段缺失。原因：未正确配置参数映射规则，未将原型文件中的页面ID、交互节点等字段准确映射到工具入参。
- 现象：插件调用超时，返回状态码504。原因：未设置合理的超时阈值，原型文件较大时解析耗时超出系统默认限制，且未配置重试机制。

## 怎么确认配好了
- 上传一份经过简化的Axure原型测试文件，触发插件调用，检查工具列表中是否显示已配置的目标插件。
- 查看FastGPT的插件调用日志，确认入参是否正确提取了原型文件中的页面ID、交互节点等核心信息。
- 验证插件返回的结果格式是否符合预设的测试用例与缺陷分析模板，字段是否完整。
- 模拟异常场景，上传格式损坏的原型文件，检查是否触发了预设的失败处理逻辑并返回友好提示。
