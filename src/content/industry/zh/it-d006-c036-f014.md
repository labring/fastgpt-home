# 原型与交互设计的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来源于Figma、Axure等设计工具导出的交互原型、页面流程图、组件说明文档，以及可用性测试记录、设计评审记录。数据更新频率通常为每周或每版本迭代一次，文档结构以页面层级、操作路径、组件属性、评审意见为核心字段，包含结构化的页面跳转逻辑与非结构化的评审反馈内容，整体数据围绕用户操作流程与界面交互展开。

## 这些特征在「模型接入与配置」这一环带来什么约束
原型与交互设计的数据以嵌套式页面跳转路径为核心，长上下文内容占比高，要求模型接入配置需适配长文本解析需求；数据更新频率较高，需确保向量索引与模型调用的同步节奏匹配版本迭代周期；数据同时包含结构化的组件参数与非结构化的评审意见，要求配置需兼顾逻辑严谨性与灵活适配性；部分设计文件导出格式存在差异，要求模型接入支持解析多种原生设计文件格式，避免格式转换导致的信息损耗。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配原型文件的嵌套页面与跳转路径的长上下文需求，避免截断核心交互逻辑 |
| `temperature` | 0.3–0.6 | 平衡测试用例生成的严谨性与异常场景覆盖的灵活性，符合设计评审的标准要求 |
| `quoteMaxToken` | 1500–2000 字符 | 确保召回的原型片段足够覆盖对应交互逻辑，避免引用内容不足导致测试用例缺失 |
| `maxTokens` | 2000–3000 token | 限制单条测试用例的输出长度，确保符合设计评审文档的常规阅读习惯 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径，不得填写VLLM/Ollama/Xinference等单模型地址，为App/Admin服务端需配置的环境变量 | 适配AI Proxy服务的访问路径，避免因根地址或端口配置错误导致服务启动校验失败或模型调用异常 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具梳理原型状态流转，适配复杂交互设计的测试用例生成 |

## 容易做错的三处
- 配置`AIPROXY_API_ENDPOINT`时填写错误根地址或端口，会导致App/Admin服务启动校验失败或模型调用异常。部分代理服务可能允许非标准地址的请求通过，但实际无法正常转发模型请求。
- 语义检索分数持续偏高，更换向量模型后无改善，需排查是否针对原型文件的结构化特征调整了召回相关配置。
- 尝试配置多组向量模型时仅能选择单模型，需按照官方文档要求的配置方式完成多组模型设置。

## 怎么确认配好了
- 上传单份Axure原型文件，触发测试用例生成，检查生成的用例是否覆盖核心页面的跳转逻辑与异常操作场景。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`的请求地址与配置一致，无端口或域名错误。
- 调整`temperature`参数区间，观察生成的测试用例的异常场景覆盖数量变化，确认参数生效。
- 检查向量库同步记录，确认原型文件的更新内容已被正确索引，检索结果匹配配置的`quoteMaxToken`长度要求。
