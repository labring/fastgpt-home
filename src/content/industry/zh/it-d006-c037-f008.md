# 发布管理与版本验收的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
发布管理与版本验收的测试用例与缺陷分析数据，来源包含CI流水线、变更系统、测试报告、监控看板四类业务系统。数据更新频率为每周或每版本发布周期一次，随正式版本的迭代节奏同步更新。日常关联的业务文档包括发布计划、上线清单、验收报告、回滚预案四类核心文件，核心字段包含版本标识、测试用例关联ID、缺陷分级、变更内容、回滚触发条件等，字段类型多为枚举值、字符串或时间戳，无统一的单一场景固定单位，需根据业务场景做字段映射处理。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散在多个独立系统，工作流需配置多节点分别拉取不同系统的业务数据，避免单节点处理过多跨系统请求导致的延迟。数据更新频率较低，工作流无需高频触发，可按版本周期调度执行，无需设置分钟级别的触发间隔。关联文档类型多样且存在关联校验需求，工作流需支持多文档的批量校验与流转。核心字段覆盖版本、测试、缺陷、应急全链路，工作流需通过变量存储各环节的临时数据，确保字段映射准确且无冲突。出错后果直接影响线上服务的稳定性，工作流需配置明确的失败处理分支，触发预设的应急流程以降低影响范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 初始化数组为`["versionId", "testCaseList", "defectList", "rollbackThreshold"]` | 匹配发布管理的核心业务字段，统一存储流程内流转的业务数据 |
| `nodeId` | 为CI拉取节点、缺陷同步节点、验收校验节点、回滚触发节点分配唯一标识 | 精准控制各业务环节的执行顺序与数据流向，避免节点冲突 |
| 全局变量赋值规则 | 按`{"key": "value"}`格式提取外部API返回字段 | 适配外部系统的数据结构，避免字段叠加错误 |
| 工作流触发时机 | 按版本发布前72小时触发 | 匹配周/每版本的更新频率，预留校验与调整时间 |
| 失败处理分支 | 绑定回滚预案执行节点 | 对应上线失败的出错后果，自动触发应急流程 |
| 外部调用鉴权 | 使用应用API Key作为鉴权凭证 | 符合外部API鉴权要求，避免权限泄露 |

## 容易做错的三处
- 排查项：若全局变量字符串数组赋值后，后续节点调用时出现字段叠加，例如变量B的结果包含变量A的内容，可验证是否未正确使用`variables`参数隔离每个节点的作用域，导致变量缓存未重置。
- 排查项：若工作流导出失败，系统提示配置不完整，可验证是否未为每个节点配置唯一`nodeId`，或`variables`数组包含未定义的字段。
- 排查项：若调用外部API访问链接赋值全局变量失败，返回401状态码，可验证是否使用了AI Proxy管理员Token作为外部调用鉴权凭证，未使用应用API Key。

## 怎么确认配好了
- 检查FastGPT v4.17.0及以上版本的服务端环境变量是否已配置`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址）和`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空），且未在工作流配置中重复填写相关内容。
- 运行工作流的测试节点，查看`variables`数组的取值是否与外部系统返回的字段一致，无叠加或缺失情况。
- 导出工作流配置文件，确认所有节点的`nodeId`唯一且`variables`参数格式符合`{"key": "value"}`的规范。
- 模拟上线失败场景，验证失败处理分支是否自动触发回滚预案节点，执行预设的应急流程。
