# 发布管理与版本验收的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据通常来自CI流水线、变更系统、测试报告与监控看板，更新节奏为每周或每版本发布周期。日常关联文档包含发布计划、上线清单、验收报告、回滚预案，核心字段涵盖发布版本标识、变更项明细、测试通过率统计、回滚触发条件等。数据由版本经理、研发运维团队与产品负责人共同维护，围绕版本从构建到生产发布的全流程流转，不同文档的字段结构存在差异，部分文档包含结构化清单与非结构化文本内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散于多套系统，且随版本发布周期更新，要求模型接入环节支持跨源数据拉取与轻量化上下文加载，避免占用过多资源影响紧凑的上线窗口。日常文档格式差异较大，需模型适配清单、报告、预案等不同结构的文本，确保分析结果符合业务场景的标准化要求。同时，发布环节出错后果直接影响线上服务，要求模型调用具备明确的状态反馈与失败重试机制，确保配置后的模型能稳定支撑版本验收与缺陷分析流程，避免因模型异常导致发布延误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径，不得填写单模型服务地址 | 用于指定AI Proxy服务的根访问地址，适配本地部署或云端部署的不同场景 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不能为空，不得使用应用API Key、模型供应商密钥等其他类型密钥 | 该变量为AI Proxy服务的管理员鉴权凭证，用于App/Admin服务端调用AI Proxy的身份验证，不得作为应用API调用的鉴权密钥 |
| `maxContext` | 8000–12000 token | 适配发布管理场景下多源文档的总长度，确保完整加载发布计划、测试报告等核心数据 |
| `maxTokens` | 2000–3000 token | 控制模型输出的缺陷分析与测试用例总结长度，符合上线清单的快速审阅需求 |
| `temperature` | 0.3–0.5 | 降低输出随机性，保证测试用例与缺陷分析的结果符合标准化的验收流程要求 |
| `toolChoice` | auto | 让模型自主选择是否调用工具，适配多源数据拉取与格式整理的实际需求 |

## 容易做错的三处
- 现象：模型调用返回权限不足的报错。排查项：检查是否使用了非AI Proxy管理员Token的密钥，或未配置有效的AIPROXY_API_TOKEN。
- 现象：本地部署实例中无法调用视觉模型处理测试报告中的截图。原因：未在配置中启用`vision`参数，且未部署对应视觉模型插件。
- 现象：模型输出的缺陷分析结果冗余且格式混乱。原因：将`temperature`参数设置为过高的值，导致输出偏离标准化的验收报告格式。

## 怎么确认配好了
- 执行一次针对当前版本发布数据的测试用例与缺陷分析调用，查看返回结果是否包含完整的版本标识、变更项明细等核心字段。
- 检查App/Admin服务启动日志与运行日志，确认未因缺少AIPROXY_API_ENDPOINT或AIPROXY_API_TOKEN触发启动校验失败，且服务调用AI Proxy的身份验证请求返回成功状态码。
- 核对配置的`maxContext`与`maxTokens`参数，确保其取值范围适配当前版本关联文档的总长度与输出需求。
- 验证模型输出的内容是否符合发布验收的标准化格式，无明显冗余或不符合业务要求的字段。
