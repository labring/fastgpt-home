# 变更管理与发布窗口的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于变更管理系统、CI流水线、监控数据与业务日历。日常关联文档包含变更申请、风险评估表、上线窗口计划与回退方案。数据更新频率为周度或随单次变更触发。数据字段包含变更唯一标识、计划上线时段、风险评级等级、审批状态、回退触发条件等，无额外自定义统计单位，所有字段均与变更流程强绑定。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且关联多系统，要求模型接入时支持多格式数据源的拉取与解析，需配置适配结构化变更文档与非结构化监控数据的统一输入规则。更新频率随单次变更触发，要求模型调用需支持按需触发，避免固定周期调用产生的无效计算。关联字段多且依赖紧密，需配置模型能识别字段间的关联逻辑，比如上线窗口时段与风险评级的匹配关系。同时，变更流程的审批与回退环节需模型输出可追溯的结构化结果，需固定结果输出的格式与字段。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 本品类关联的变更文档、监控数据等内容量较大，需保留足够上下文以识别字段间的关联关系 |
| `maxTokens` | 2000–3000 token | 需输出风险评级、窗口适配建议等结构化结果，避免超出返回长度限制 |
| `temperature` | 0.3–0.5 | 需生成严谨的风险评估与变更建议，避免过度发散的非预期结果 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径，不得使用VLLM/Ollama/Xinference等单模型地址 | 作为App/Admin服务调用AI Proxy服务的入口，确保调用链路稳定，为App/Admin服务端的环境变量，不得在工作流全局变量、应用API请求头或普通模型管理页面配置 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token，且不能为空，不得为应用API Key、模型供应商密钥或按应用签发的token | 作为App/Admin服务与AI Proxy服务通信的身份验证凭证 |

## 容易做错的三处
- 现象：调用API触发批量执行节点时，仅完成部分循环任务，在线调试环境可完整执行全部流程。原因：FastGPT v4.17.0版本中，API调用的默认超时时长未适配本品类多变更数据的批量处理需求，未调整参数覆盖全量循环的执行周期。
- 现象：接入视觉模型时无法正常解析上传的监控截图或变更文档配图。原因：未开启`vision`参数配置，未适配视觉模型的输入格式要求。
- 现象：模型调用返回的token消耗统计无法按应用维度拆分。原因：未配置模型调用的应用标识绑定，未开启token消耗的上下文关联记录。

## 怎么确认配好了
- 发起单次变更的测试调用，检查模型返回的结果包含风险评级、上线窗口适配建议等预期字段。
- 查看服务端启动校验结果与模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`已正确配置为服务端环境变量，无身份验证相关报错。
- 调整`temperature`参数后发起两次调用，对比结果的严谨程度，确认参数生效。
- 触发批量执行节点的API调用，检查全部循环任务是否完成，无中途中断的情况。
