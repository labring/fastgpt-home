# 后端服务开发的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
这个品类的数据主要来自代码仓库、API网关日志、数据库、配置中心，更新频率为每日或每版本发布周期。日常关联文档包含接口设计文档、数据库变更单、代码评审记录、服务发布说明。数据字段通常包含接口请求参数、异常日志堆栈信息、数据库变更SQL语句、服务启动配置项、接口响应状态码等，部分字段以字符、毫秒、行数为单位，无统一固定的计量标准。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需配置多节点分别拉取代码仓库、网关日志等不同数据源，需适配不同接口的鉴权与数据解析规则。更新频率较高要求工作流支持定时触发或版本变更触发的调度模式。日常文档结构多样，需通过`variables`配置节点间传递的字段映射规则，适配接口设计文档、变更单等不同格式的输入。异常排查耗时环节多，需在工作流中设置异常分支，针对超时、数据格式错误等场景配置自动重试或告警触发，避免服务回滚等严重后果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流触发方式 | 按代码提交事件 / 按版本发布周期 | 匹配后端服务开发的数据更新频率，适配每日或每版本的更新节奏 |
| 变量映射规则 | 通过`variables`配置字段映射 | 适配后端服务开发的接口文档、日志字段结构，统一节点间数据传递格式 |
| 节点超时设置 | 300–600 秒 | 覆盖接口契约确认、异常日志排查等耗时环节的执行时长 |
| 异常分支配置 | 触发告警 + 重试 2 次 | 应对接口超时、数据格式错误等常见异常，降低服务风险 |
| 工具调用终止节点 | 流程末尾强制添加 | 避免工具调用无终止导致的循环执行 |
| HTTP请求鉴权 | 使用应用API Key | 符合FastGPT v4.17.0官方环境变量配置要求，保障鉴权安全 |

## 容易做错的三处
- 工作流执行至工具调用节点后无终止，持续循环触发工具调用，日志中出现重复的工具调用记录。原因是未在流程末尾添加工具调用终止节点，导致工作流未识别执行完成状态。
- HTTP请求节点无法正确接收自定义输入变量，接口返回参数缺失或格式错误。原因是未通过`variables`配置节点间的变量传递规则，未匹配接口定义的参数接收格式。
- 无关问题触发知识库回答分支，输出与提问不相关的知识库内容。原因是未配置问题相关性校验节点，未对提问内容与知识库的匹配度进行前置判断，导致分支逻辑错误。

## 怎么确认配好了
- 验证工作流触发配置是否与数据更新频率匹配，手动触发定时任务或模拟代码提交事件，确认工作流正常启动。
- 运行测试工作流，检查`variables`配置的变量能否在节点间正确传递，无字段缺失或格式异常。
- 模拟接口超时、数据格式错误等异常场景，验证异常分支是否触发预设的告警或重试动作。
- 查看工作流执行日志，确认工具调用节点后无循环执行的记录，流程正常终止。
