# 图像标注项目的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
图像标注项目的数据主要来自标注平台产出的图片样本、标注规范文档、类别字典、抽检结果与返工清单。日常产出的文档包含框选样例、质检报告、返工清单，字段多包含目标边界框坐标、类别标签、置信度、抽检标记等。数据更新按日或单批次标注任务完成后触发，不同任务的样本量、标注规则无统一固定格式，需随标注需求动态调整。

## 这些特征在「工作流编排」这一环带来什么约束
图像标注项目的数据特征对工作流编排带来多重约束。首先，数据以视觉样本为核心，工作流需支持接入图片URL、本地图片路径的输入节点，适配视觉数据的校验与处理逻辑。其次，数据按日或单批次更新，工作流需支持定时触发或按批次任务触发的配置，适配不同更新节奏的校验需求。此外，标注规范、框选样例等文档需作为动态变量传入工作流，用于实时校验标注结果的合规性，同时需针对边界框坐标、类别匹配等视觉专属字段设置校验规则，避免无效数据流入后续环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 触发方式 | 按单批次任务完成 / 定时触发（`86400 秒`间隔） | 匹配数据按日或单批次更新的节奏，适配标注任务的执行周期 |
| `variables` | 传入标注规范、框选样例、类别字典的文件路径 | 动态加载校验规则与参考数据，适配不同标注项目的专属要求 |
| 节点校验逻辑 | 开启边界框坐标校验、类别匹配校验 | 验证视觉标注结果的合规性，避免无效数据流入后续环节 |
| 失败重试次数 | `2–3 次` | 标注数据校验失败多为临时格式问题，有限重试可减少人工介入 |
| 超时阈值 | `300–600 秒` | 图片解析与校验需一定处理时长，避免短超时中断流程，FastGPT v4.17.0 版本优化了视觉节点的超时处理逻辑 |
| `nodeId` | 绑定质检节点与校验节点的ID | 确保工作流节点的执行顺序与依赖关系正确，避免环节遗漏 |

## 容易做错的三处
- 现象：本地测试工作流无报错，但通过外部渠道调用时提示“undefined”is not valid json。原因：未在`variables`中配置渠道调用所需的必填参数，导致传入数据格式缺失。
- 现象：工作流中传入图片URL后，无法正常显示预览。原因：未配置图片解析节点的URL校验规则，或未开启节点的图片渲染权限。
- 现象：工作流执行后无校验结果输出。原因：未绑定`nodeId`指定校验节点的执行顺序，导致校验环节未触发。

## 怎么确认配好了
- 执行本地测试调用，传入标注样本数据与校验规则，查看工作流节点的执行日志，确认所有校验环节均正常触发。
- 配置外部渠道调用，传入符合格式的测试数据，核对返回结果是否包含校验后的标注结果与异常标记。
- 调整数据更新频率，验证工作流是否按预设的定时或批次规则自动触发执行。
- 检查`variables`与`nodeId`的配置项，确认所有必填参数均已正确传入并绑定对应节点。
