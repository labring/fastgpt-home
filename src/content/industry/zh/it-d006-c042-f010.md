# 备份恢复与灾备演练的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据来自备份系统、数据库日志、对象存储、灾备平台。日常产出的文档包括备份策略、恢复演练报告、灾备切换预案、数据校验记录。数据更新频率分为日、月、季三类，核心字段包含备份时间戳、恢复点目标时长、数据校验哈希值、演练执行状态，单位涉及秒、GB、执行次数等，无统一固定的多维度聚合统计格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据的混合接入要求溯源环节需明确绑定各数据源的唯一标识，避免不同备份系统的重复数据干扰。不同更新频率的文档需匹配对应的召回时效规则，日更的演练报告需支持实时检索，季更的备份策略可降低检索优先级。分散的文档结构要求配置字段映射规则，将备份时间戳、恢复点目标时长等核心字段与测试用例的校验项绑定。数据一致性核验的结果需直接关联原始日志的哈希值，确保溯源的不可篡改，支撑缺陷分析的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | 匹配灾备演练报告、数据校验记录的单文档长度，避免截断核心校验字段 |
| `responseData` | 仅返回备份系统、灾备平台的数据源 | 过滤无关日志数据，聚焦本品类的核心溯源来源 |
| `detail` | 开启完整字段展示 | 展示备份时间戳、恢复点目标时长等核心字段，支撑测试用例的缺陷分析 |
| 最大上下文 | 4000–6000 token | 适配多源数据的拼接长度，满足跨文档的关联溯源需求 |
| 单次搜索上限 | 前6条 | 覆盖日更演练报告、季更备份策略的召回量，避免冗余数据干扰 |
| 数据源超时阈值 | 300 秒 | 适配灾备平台的接口响应时长，避免检索中断 |

## 容易做错的三处
- 现象：生成的溯源提示中包含未解析的\n转义字符，未实现自然换行展示。原因：未开启`detail`配置下的文本格式解析开关，直接返回原始备份日志的原生转义内容。
- 现象：检索返回的溯源数据条数不足，无法覆盖完整的单份恢复演练报告内容。原因：单次搜索上限设置过低，未匹配本品类日更文档的平均召回需求。
- 现象：溯源结果未关联数据校验的哈希值字段，无法验证恢复数据的一致性。原因：未配置多源数据的字段映射规则，未绑定灾备平台的校验记录核心字段。

## 怎么确认配好了
- 登录FastGPT v4.17.0的配置页面，检查`quoteMaxToken`、`responseData`、`detail`的设置是否与预设值一致。
- 发起一次针对灾备演练场景的测试用例查询，检查溯源提示中的换行是否正常生效，无未解析的转义字符。
- 查看检索结果的总条数，确认是否符合单次搜索上限的设置值，无明显缺失的核心文档。
- 核对溯源结果中是否包含备份时间戳、数据校验哈希值等核心字段，验证字段映射规则是否生效。
