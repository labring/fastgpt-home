# 备份恢复与灾备演练的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源涵盖备份系统、数据库日志、对象存储、灾备平台四类核心系统。日常产出的文档包括备份策略、恢复演练报告、灾备切换预案、数据校验记录，文档结构包含操作步骤、时间戳、校验结果、资源占用等字段。数据更新频率分为日级（备份日志、校验记录）、月级（恢复演练报告）、季级（灾备切换预案）三类。核心业务环节涉及恢复点确认、演练脚本执行、数据一致性核验，出错后会引发数据丢失、恢复超时、业务连续性中断等后果，与数据库运维品类的核心差异在于关注跨系统的整体可恢复能力。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据多源分散且更新节奏差异明显，要求模型接入配置支持多数据源的统一调用权限管理。不同更新频率的文档需要适配不同的模型调用频次，高频更新的备份日志需要更短的模型响应延迟。核心业务环节的校验逻辑依赖大模型对跨系统数据的整合分析，因此配置需要预留足够的上下文空间。同时，出错后果严重，要求配置包含失败重试机制与调用链路的可观测性设置，避免单一环节故障引发全链路业务中断。FastGPT v4.17.0版本的配置模板可适配此类多源数据的接入需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配备份策略、恢复演练报告等单文档的平均token规模，避免上下文截断导致校验逻辑缺失 |
| `maxTokens` | 2000 token | 匹配灾备演练场景下的单轮回答长度需求，确保返回的校验步骤完整 |
| `quoteMaxToken` | 1500 token | 限制引用的备份日志、对象存储元数据的长度，避免冗余信息干扰模型判断 |
| `toolChoice` | auto | 允许模型自主选择是否调用内置的灾备校验工具，适配不同演练场景的复杂需求 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000 | 为App/Admin服务端的环境变量，不得附加/v1或单模型服务地址 |
| `temperature` | 0.2 | 降低随机输出概率，确保灾备校验步骤的准确性与规范性 |

## 容易做错的三处
- 配置`AIPROXY_API_ENDPOINT`时仅配置单模型专属端点（如VLLM/Ollama/Xinference地址）或附加了/v1等路径，未使用AI Proxy服务的根地址，导致模型调用卡滞无响应，重启服务也无法恢复。
- 将未补充上下文前缀的原始备份结果字符串直接传入大模型，未做格式校验，导致大模型无法识别有效问题，返回`Question is empty`报错，即便原始结果存在有效内容。
- 配置`toolChoice`时强制指定为`none`，禁用了模型的工具调用能力，导致无法触发灾备演练的脚本执行校验逻辑，无法识别演练环节的异常。

## 怎么确认配好了
- 检查App/Admin服务启动校验日志，确认无`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`缺失报错。
- 查看模型调用日志，确认`maxContext`参数的取值匹配当前导入的灾备文档总token规模，未出现上下文截断提示。
- 模拟触发一次小规模灾备演练，检查模型调用的返回结果是否包含针对演练脚本执行的校验建议。
- 验证App/Admin服务端配置的`AIPROXY_API_TOKEN`与AI Proxy服务端配置一致且非空。
