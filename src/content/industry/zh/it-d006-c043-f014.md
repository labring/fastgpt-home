# 安全事件应急响应的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据以单次安全事件为单位聚合，数据来源包括SIEM、EDR、防火墙日志与主机镜像。数据更新随事件触发，支持实时或按事件粒度更新。日常关联文档包含应急响应报告、取证记录、处置方案与通报材料，单份文档围绕特定事件展开，包含事件时间、攻击路径、处置动作等核心字段，整体数据结构随事件复杂度动态调整，无统一固定长度限制。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据特征对模型接入配置带来三点核心约束：第一，数据来源多样且为实时或按事件粒度更新，需配置高可用的模型调用端点，保障安全处置环节的响应速度；第二，单份数据围绕特定安全事件，输入长度波动范围大，需设置适配可变上下文的参数，避免截断关键攻击路径或证据链信息；第三，核心任务聚焦攻击路径还原与证据链整理，需配置对应工具调用规则，优先调用适配日志解析的工具，提升处置效率。

## 配置怎么定
本文档适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 该品类单事件数据输入长度波动大，覆盖日志片段与处置文档，该区间可适配多数事件的上下文需求 |
| `maxTokens` | `2000–3000 token` | 应急响应报告与处置方案的输出需覆盖完整步骤，该区间可保障输出信息量充足 |
| `quoteMaxToken` | `1500 token` | 需优先保留原始日志与取证记录的关键内容，避免引用截断核心证据 |
| `toolChoice` | `auto` | 核心任务包含日志解析与攻击路径还原，自动调用工具可适配多类型数据源 |
| `temperature` | `0.2–0.4` | 处置建议需保持一致性，避免输出波动影响应急决策 |
| `AIPROXY_API_TOKEN` | 配置为与AI Proxy服务端一致的管理员Token，不能为空 | 该变量为App/Admin服务端环境变量，非应用API Key、模型供应商密钥或按请求签发的token |
| `AIPROXY_API_ENDPOINT` | 配置为AI Proxy服务的根地址，例如http://aiproxy:3000，按区域就近配置高可用节点，请勿附加/v1或/chat/completions等路径 | 数据实时更新，低延迟的AI Proxy服务端点可保障安全处置环节的响应速度，该地址非VLLM/Ollama/Xinference等单模型地址 |

## 容易做错的三处
- 现象：配置重排模型后，单次安全事件分析的响应延迟超过60秒，或出现调用超时报错。原因：未针对该品类的多日志数据源场景，限制重排模型的输入片段数量，导致处理负载过高。
- 现象：在FastGPT平台、工作流全局变量、应用API请求头或普通模型管理页面配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或在本地config.json中重复配置AI Proxy相关环境变量，出现调用权限冲突或请求重复发送。排查项：确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`为App/Admin服务端环境变量，未在非服务端部署配置的位置填写。
- 现象：基于知识库生成的应急响应建议仅包含摘要内容，未引用具体的处置条款或日志细节。原因：未调整`quoteMaxToken`参数，导致原始文档的引用内容被过度截断，无法输出完整的细节信息。

## 怎么确认配好了
- 提交单条安全事件的模拟数据集，核对模型输出的响应延迟，调整相关参数匹配业务场景的延迟要求。
- 查看模型调用日志，确认`toolChoice`自动调用了适配日志解析的工具，无异常报错或工具调用失败的情况。
- 验证生成的应急响应报告是否包含原始日志与取证记录的核心片段，确认引用内容未被过度截断。
- 检查服务端部署的`AIPROXY_API_ENDPOINT`环境变量，确认其为AI Proxy服务的根地址，例如http://aiproxy:3000，未附加/v1或/chat/completions等路径，且为就近高可用节点，无跨区域调用导致的延迟问题。
