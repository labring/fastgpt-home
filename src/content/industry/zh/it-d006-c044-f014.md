# 安全产品规则运营的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自WAF、IDS、防火墙及威胁情报平台，更新节奏为每日或随防护事件触发。日常产出的文档包含规则变更单、拦截日志、误报分析报告、策略回滚记录，字段多包含规则ID、触发时间、匹配特征、业务影响范围，无统一强制格式，随企业防护策略调整灵活更新。

## 这些特征在模型接入与配置这一环带来什么约束
数据来源分散且更新无固定批次，要求模型接入时支持多源日志的批量解析；误报分析与策略回滚需关联历史事件，需保留足够的上下文窗口；规则变更单的审核与效果复核需要模型快速匹配历史规则库，因此需限制单次调用的token消耗；拦截日志的实时性要求决定了模型调用需设置合理阈值，避免影响防护策略生效速度。误报样本的多维度分析需要模型同时关联多源数据，因此需配置合适的上下文长度，避免截断关键关联信息；策略灰度发布的效果验证需要模型快速对比不同规则版本的拦截表现，需调整参数平衡分析的稳定性与灵活性。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本的界面与参数逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 需关联多源防护日志与历史误报记录，足够的上下文可保留规则关联的完整特征链 |
| `maxTokens` | 2000–3000 token | 单次规则分析或误报复盘的输出需覆盖策略调整建议，避免截断关键结论 |
| `temperature` | 0.2–0.4 | 规则运营需稳定的分析结果，较低温度可减少无关结论，保证策略调整的一致性 |
| `toolChoice` | auto | 自动选择是否调用工具处理日志解析或规则匹配，适配多源数据的动态处理需求 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如`http://aiproxy:3000`，不要附加`/v1`或`/chat/completions`，不是VLLM/Ollama/Xinference等单模型地址 | 作为App/Admin服务端的环境变量，配置后可确保服务正常连接AI Proxy，避免因地址错误导致请求失败 |
| `AIPROXY_API_TOKEN` | AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空，不是应用API Key、模型供应商密钥等 | 作为App/Admin服务端的环境变量，完成与AI Proxy服务的身份验证，保障调用权限合法有效 |

## 容易做错的三处
- 模型响应中出现「链接断开」提示，可验证排查项：检查`AIPROXY_API_ENDPOINT`环境变量配置是否正确、网络策略是否限制了AI Proxy服务调用端口，或是否未配置该必填环境变量导致服务无法连接AI Proxy。
- 相同提示词下回复效果与原生模型存在差异，原因是`temperature`参数设置不当，或`maxContext`截断了关键的规则历史上下文信息。
- 模型提供商页面未显示调用日志，原因是未启用调用日志的持久化配置，或日志存储周期设置过短导致数据被自动清除。

## 怎么确认配好了
- 确认App/Admin服务端已正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量，服务启动校验通过，发起测试调用无身份验证或地址错误提示。
- 调整`maxContext`与`maxTokens`参数，上传一份规则变更单与拦截日志，确认完整内容被正确解析且无截断提示。
- 设置`temperature`为0.3，多次调用相同提示词，确认输出结果的一致性符合预期。
- 进入模型提供商页面，查看是否生成了近1小时内的调用日志记录，确认日志存储配置生效。
