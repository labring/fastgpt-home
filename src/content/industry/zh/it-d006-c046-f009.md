# 安全基线检查的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源于服务器、中间件的配置文件，安全设备策略日志及专用基线核查工具。数据更新频率为月或季度，核心文档包括基线检查表、配置核查记录、整改建议与例外审批单。基线检查表包含配置项名称、当前配置值与合规基准值；配置核查记录记录核查时点、异常项清单与执行人信息；例外审批单则关联异常项的申请理由与审批状态。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散于服务器、中间件配置文件、安全设备策略及专用基线核查工具，工具调用需支持多格式配置文件的解析接入。月或季度的更新频率决定无需高频轮询，可配置固定周期触发任务。多关联文档的结构要求插件支持跨文档字段关联，例如将例外审批单的审批状态同步至基线检查表的对应异常项。批量配置项核对的高耗时需求，要求工具调用支持批量拉取异常项，同时需包含合规状态校验逻辑，避免弱配置长期留存。跨团队的知识库关联场景，要求插件支持跨团队权限校验，确保合规基准数据的安全访问。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多类基线核查工具的自动调用，无需手动指定工具 |
| `functionCall` | 按实测标定 | 适配自定义基线检查脚本的参数传递 |
| 全局变量传递 | 开启并绑定工作流token变量 | 满足跨工具的身份凭证传递需求 |
| 本机MCP调用 | 开启本地服务监听端口 | 支持直接调用本地部署的基线核查工具 |
| 知识库关联查询 | 绑定合规基准知识库 | 实现异常项的自动匹配与整改建议生成 |
| 单次异常项拉取 | 前5条 | 适配基线检查的批量核对节奏，减少单次调用负载 |
| 调用超时时间 | 600秒 | 适配多源数据拉取的合理耗时 |

## 容易做错的三处
- 工作流中调用MCP工具时无法获取全局变量，表现为工具接收的token字段为空。原因是未开启全局变量绑定配置，未将工作流token映射至工具调用参数。
- 调用本机MCP工具失败，表现为连接超时报错。原因是未开启本地服务监听端口，或防火墙拦截了工具通信端口。
- 处理带修订标记的Word文档时格式错乱，表现为修订内容丢失或排版混乱。原因是未调用专用文档解析插件，使用通用文本解析工具处理带格式的Word文件。

## 怎么确认配好了
- 触发一次工作流调用，查看工具调用日志，确认全局变量token已正确传递至MCP工具参数中。
- 检查本机MCP工具的服务状态，确认监听端口已开启，且能通过本地地址发起调用请求。
- 上传带修订标记的Word文档，调用文档处理插件，确认解析后保留原有格式与修订内容。
- 测试关联非同一团队的知识库，提交基线相关查询，确认返回结果包含合规基准数据。
