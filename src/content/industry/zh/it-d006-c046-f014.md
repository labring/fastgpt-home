# 安全基线检查的测试用例与缺陷分析：模型接入与配置
FastGPT v4.17.0

## 这个品类的数据长什么样
本品类的数据来源于服务器、中间件、安全设备的配置参数，以及基线工具的扫描结果，更新频率为月或季度。日常产出的文档包含基线检查表、配置核查记录、整改建议与例外审批单，数据字段包含基线项唯一标识、配置项实际值、合规性判定结果、例外审批状态与整改完成标记，无额外自定义统计字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于本品类数据来源为静态配置类参数，更新频率较低，模型接入时无需高频同步知识库内容，可降低同步频率以节省资源。基线检查表等文档结构固定、字段明确，模型调用时需限定检索范围仅匹配预设基线项相关字段，避免无关内容干扰。例外审批单存在非结构化文本，需配置参数处理长文本输入。同时数据量相对稳定，可限制单次调用的token消耗，避免超出模型限额。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配基线检查表、整改建议等文档的平均长度，避免截断关键配置项内容 |
| `maxTokens` | `2000 token` | 限制单次模型输出长度，适配整改建议的生成需求，避免冗余内容 |
| `quoteMaxToken` | `1500 字符` | 限定检索引用的知识库内容长度，匹配基线核查记录的单条记录长度 |
| `toolChoice` | `auto` | 允许模型自主选择是否调用工具完成配置项核对与例外原因提取 |
| `temperature` | `0.2` | 降低生成随机性，确保整改建议与基线要求的一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions 等路径 | 作为App/Admin服务端必需的环境变量，用于连接AI Proxy服务 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不能为空 | 作为App/Admin服务端必需的环境变量，用于AI Proxy服务的身份验证 |

## 容易做错的三处
- 现象：调用模型时返回的整改建议未引用基线检查表内容，或检索结果为空。原因：未正确配置`quoteMaxToken`参数，导致检索的知识库内容被截断或超出匹配范围。
- 现象：App/Admin服务启动校验失败，或无法正常调用AI Proxy服务。原因：`AIPROXY_API_ENDPOINT`配置错误，例如误填为单模型服务地址、附加了 /v1 等不允许的路径，或端口配置错误。
- 现象：每次调用MCP工具后模型上下文被重置，无法关联历史基线核查结果。原因：未正确设置`toolChoice`参数，导致工具调用后未保留上下文关联，或配置的`maxContext`长度不足。

## 怎么确认配好了
- 提交一条基线核查记录的测试数据，查看模型返回的整改建议是否包含对应基线项的合规性判定内容。
- 访问填写的`AIPROXY_API_ENDPOINT`地址，使用`AIPROXY_API_TOKEN`发起测试请求，确认返回状态码为200。
- 发起包含例外审批单内容的测试调用，查看模型是否能正确提取例外原因并生成对应整改建议。
- 连续发起3次不同基线项的测试调用，确认模型上下文未被意外重置，每次调用结果均基于历史上下文生成。
