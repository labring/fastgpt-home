# 安全漏洞披露处理的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据均围绕单个漏洞事件产生，来源包括私密漏洞报告、项目代码仓库、CVE编号机构公开信息及官方发布渠道。数据更新节奏为每事件一次，单次数据包含漏洞编号、影响范围、披露时间、修复补丁链接、报告人信息等字段。日常文档包括安全公告、漏洞报告、修复补丁包、CVE申请材料，格式多为结构化文本或Markdown格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据包含私密的漏洞细节与跨团队协调记录，因此模型接入需优先保障数据传输安全，不得使用公开的第三方代理接口。单次事件的数据长度差异较大，从数百字符到数千字符不等，需限制模型的上下文与输出长度，避免超出接口限额。数据字段相对固定但需精准提取，因此需配置模型的输出格式约束，确保分析结果符合漏洞处理流程的要求。此外，漏洞处理的时效性要求较高，需配置合理的超时与重试机制，避免影响披露协调进度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | 8000–12000 token | 适配单次漏洞事件的完整上下文长度，包含漏洞报告、补丁信息和历史协调记录 |
| `maxTokens` | 2000–3000 token | 限制模型输出的漏洞分析结果长度，避免超出接口限额并简化后续人工审核 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 http://aiproxy:3000 | 为 FastGPT 服务端配置的 AI Proxy 服务访问地址，不得附加 /v1 或 /chat/completions 等路径 |
| `AIPROXY_API_TOKEN` | 与 AI Proxy 服务端配置一致的非空管理员 Token | 作为 FastGPT 服务端访问 AI Proxy 的鉴权凭证 |
| `temperature` | 0.3–0.5 | 平衡漏洞分析的准确性和灵活性，避免生成无关或不准确的评估内容 |
| `toolChoice` | auto | 允许模型自动选择是否调用工具辅助漏洞影响范围评估 |

## 容易做错的三处
- 调用模型时返回401 unauthorized报错，排查项为未正确配置`AIPROXY_API_TOKEN`，或该 Token 与 AI Proxy 服务端配置的管理员 Token 不匹配。
- 工作流的AI模型下拉列表为空，排查项为未正确配置`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`必填环境变量，或 FastGPT 服务启动校验未通过，或 AI Proxy 服务未正常启动。
- 漏洞影响评估结果超出预期长度，原因是未限制`maxTokens`参数，导致模型输出冗余内容，增加人工审核负担。

## 怎么确认配好了
- 检查FastGPT部署时设置的`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`环境变量，其值与 AI Proxy 服务端的对应配置一致。
- 进入FastGPT工作流编辑器，打开AI节点的模型选择下拉列表，确认目标模型已显示在列表中。
- 提交一份模拟的漏洞报告数据，触发模型调用，确认返回结果无权限报错或超时提示。
- 调整`maxTokens`参数为1000 token，提交测试输入，确认模型输出长度符合设置的限制。
