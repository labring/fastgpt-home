# 安全监控与SOC值守的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
本品类的数据来自SIEM、EDR、NDR及威胁情报源，更新节奏为实时或每日。日常产出与处理的文档包括告警处置单、值班记录、威胁情报通报、日报周报，核心字段包含告警标识、关联资产IP、威胁等级、处置状态与响应时长。数据使用者为SOC分析师、安全运营外包团队及企业安全中心，需基于实时告警与周期性报表开展研判与值守工作。

## 这些特征在「工作流编排」这一环带来什么约束
实时告警与多源数据接入要求工作流支持低延迟触发，避免告警信息积压导致响应超时。不同数据源的格式差异，需要工作流配置统一的数据解析节点，对齐告警标识、威胁等级等核心字段。日更的威胁情报通报与日报周报，要求工作流支持定时触发与批量生成节点。告警研判、误报排除的多步骤流程，需要拆分独立节点，预留人工审核环节，适配SOC团队的值守排班节奏。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发间隔 | `600 秒` 至 `3600 秒` | 适配实时告警研判的轮询节奏，避免延迟过高 |
| 问题优化 | 按实测标定 | 优化告警原始文本的表述，提升模型对安全场景的理解精度 |
| `variables` | 预设告警ID、关联资产、威胁等级变量 | 传递核心业务字段到后续工作流节点，实现数据联动 |
| 工具调用后处理 | 开启自定义代码节点 | 处理工具调用返回的不稳定结果，抽取特定字段或格式化输出 |
| `nodeId` | 为每个工作流节点分配唯一标识 | 便于追踪工作流执行状态，定位异常环节 |
| 单次工具调用上限 | 前5条 | 限制单次调用返回的告警数量，避免超出模型上下文限制 |

## 容易做错的三处
- 开启知识库插件的问题优化后，在工作流节点内关闭该配置仍生效，工作流无法正常调用。原因：问题优化配置的全局设置与工作流节点配置未做隔离，导致节点内的设置被全局参数覆盖。
- 嵌入业务系统后，无法关联业务用户身份。原因：发起工作流HTTP请求时未携带用户标识参数，未配置身份校验的前置节点。
- 工具调用节点返回结果条数不稳定。原因：未配置工具调用的重试机制与结果校验节点，依赖单一工具调用的返回结果。

## 怎么确认配好了
- 手动触发工作流，检查核心变量是否正确传递到后续节点，确认`variables`配置的字段正常显示。
- 测试工具调用节点，查看返回结果是否经过自定义代码处理，验证后处理逻辑生效。
- 模拟异常触发场景，检查工作流是否按`nodeId`标识追踪执行日志，定位异常环节。
- 嵌入业务系统发起请求，确认用户身份参数被正确携带，工作流可正常启动。
