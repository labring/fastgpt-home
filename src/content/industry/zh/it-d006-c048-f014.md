# 安全监控与SOC值守的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自SIEM、EDR、NDR及各类威胁情报源，更新节奏涵盖实时与日更两类。日常处理的文档包含告警处置单、值班记录、威胁情报通报、日报周报，单条告警数据包含告警等级、源IP、目标资产、触发时间、处置状态等结构化字段，值班记录包含值守时段、处置动作、流转记录等内容，威胁情报通报则包含IOC特征、关联事件等非结构化文本，日报周报则整合多日告警统计与处置结果。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时更新的告警数据要求模型接入支持低延迟调用，避免延误研判窗口；多源异构数据（结构化告警字段、非结构化情报文本）要求配置适配混合格式的输入解析，确保不同类型数据都能被正确处理；日报周报等批量文档的日更需求，要求模型支持批量任务调度与上下文复用，提升批量分析效率；SOC分析师的日常处置流程需要模型输出符合现有文档字段的结构化结果，避免额外格式转换成本；误报排除与升级派单的高频操作，要求配置的响应速度匹配实时研判的时间要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配告警、情报通报等多源文本的上下文长度，避免截断关键告警等级与IOC特征 |
| `maxTokens` | 2000–3000 token | 匹配告警研判、误报排除的单轮输出需求，确保结构化处置建议完整 |
| `quoteMaxToken` | 1000 字符 | 限制引用源数据的长度，避免输出冗余的原始告警内容，聚焦处置逻辑 |
| `temperature` | 0.3–0.5 | 降低输出随机性，确保告警研判结果的一致性，符合SOC值守的标准化处置要求 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径 | 确保FastGPT能正确路由请求到AI Proxy服务，避免连接失败 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，且不能为空 | 完成FastGPT与AI Proxy服务的身份校验，确保请求被AI Proxy服务正常受理 |

## 容易做错的三处
- 调用模型返回400错误，提示参数格式异常。排查项：检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`是否按要求正确配置，或是否存在未完成FastGPT服务启动校验的情况。
- 修改config.json后模型列表未更新。原因是未重启FastGPT容器加载新配置，或配置文件路径填写错误，未指向/app/data/config目录。
- 模型流响应为空，无有效输出。原因是`maxContext`设置过小，导致关键告警上下文被截断，模型无法生成有效研判结果，或`temperature`设置过高导致输出不符合格式要求。

## 怎么确认配好了
- 调用测试接口传入单条告警数据，检查返回结果是否包含符合告警处置单字段的结构化内容。
- 查看FastGPT后台模型列表，确认目标模型已正常加载并显示。
- 开启流响应调试模式，观察是否有分段的研判结果输出，无空包或中断情况。
- 传入批量的日报周报样本，检查模型输出是否符合日更文档的统计与分析格式要求。
