# 客户开通与租户初始化的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来源于CRM系统、合同订单库、身份管理系统与产品后台，日常维护文档包含开通申请单、租户配置表、管理员账号清单与交付确认单。数据更新节奏按单执行，单次开通流程完成后即完成全量数据同步，日常运维中每日会同步更新租户权限与账号状态。数据字段包含客户身份标识、权限范围、资源配额等信息，无统一的标准化格式，需根据不同客户的合同条款调整字段映射规则。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入配置需适配不同格式的文档结构，支持自定义字段映射规则。按单更新的节奏意味着配置需要支持快速迭代调整，无需全局重启即可生效。敏感字段的存在要求模型接入时需配置权限校验逻辑，避免未授权的配置读取与修改。同时，该环节出错会直接导致客户无法登录、交付延期或合同验收受阻，因此配置需包含前置校验步骤，确保参数合法性与权限范围匹配。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxTokens` | 8000–16000 token | 适配租户初始化流程中批量账号创建、权限配置的长文本处理需求 |
| `temperature` | 0.1–0.3 | 保证权限分配、账号生成等配置结果的一致性，避免出现偏差 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions路径 | 为AI Proxy服务的合法根地址，确保App/Admin服务可连接AI Proxy服务 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置的管理员Token一致且不能为空 | 确保App/Admin服务与AI Proxy服务的身份校验合法 |
| `toolChoice` | auto | 自动选择工具处理开通申请单中的字段提取与映射 |
| `quoteMaxToken` | 2000 token | 限制引用的配置文档长度，避免上下文溢出影响处理效率 |

## 容易做错的三处
- 现象：docker私有部署后无法连接本地ollama，接口返回404错误。原因：未正确配置`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，或未配置与AI Proxy服务端一致的`AIPROXY_API_TOKEN`进行身份校验。
- 现象：iframe嵌入租户初始化页面后，配置项无法正常加载。原因：未在FastGPT后台开放对应域名的跨域访问权限，或未正确配置iframe的沙箱参数。
- 现象：批量发送开通请求后，后续请求被阻塞无法中断。原因：未配置合理的`maxContext`限制单请求上下文长度，或未启用流式响应的中断机制，导致请求堆积无法取消。

## 怎么确认配好了
- 执行连通性验证，确认`AIPROXY_API_ENDPOINT`对应的AI Proxy服务可正常响应请求。
- 提交一条测试开通申请单，查看模型是否能正确提取文档中的客户信息与权限配置字段，生成符合要求的租户配置项。
- 触发批量开通流程，验证可以正常中断或取消正在执行的请求，避免资源堆积。
- 检查管理员账号清单与交付确认单，确认生成的账号信息与配置项的映射规则一致。
