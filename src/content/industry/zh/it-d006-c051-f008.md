# 客户数据导入迁移的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自客户历史系统、CSV或Excel模板、数据库导出文件以及产品导入日志。数据更新频率为每单或不定期，伴随迁移项目的推进动态调整。日常关联文档包括数据模板、迁移方案、字段映射表与迁移验证报告，核心字段包含客户标识、业务数据字段、校验规则字段，无统一固定单位，需按客户业务场景匹配。典型处理主体为实施顾问、数据实施工程师与客户IT接口人，核心流程涉及字段映射确认、脏数据清洗与导入后抽样核对，出错后可能引发历史数据丢失、字段错位或客户拒收。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散要求工作流配置多格式适配节点，兼容CSV、Excel与数据库导出格式。更新频率不定期要求工作流支持按需触发，无需绑定固定调度周期。多关联文档需在工作流中嵌入字段映射表调用环节，确保迁移规则实时同步。核心耗时环节要求工作流拆分并行处理节点，降低单节点运行时长。严重出错后果要求工作流配置失败回滚与告警节点，覆盖数据错位、丢失等异常场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `variables` | 定义Number类型全局计数器，初始值设为0，每次执行完成后调用变量更新节点将值加1 | 匹配客户数据导入迁移的执行次数统计需求，符合FastGPT v4.17.0的变量规则 |
| 工作流触发方式 | 按需手动触发或按导入文件上传事件触发 | 适配该品类不定期、按需执行的更新频率特征 |
| 格式校验节点 | 配置CSV/Excel格式校验、数据库连接校验，校验超时设为600秒 | 覆盖多来源数据的格式合法性检查，避免无效数据进入流程 |
| 字段映射调用 | 关联预设字段映射表节点，调用时加载最新映射规则 | 匹配该品类核心的字段映射确认环节需求，确保数据字段对应正确 |
| 失败回滚配置 | 设置导入前数据备份节点，备份存储容量设为1000 MB，失败时自动回滚至备份状态 | 降低该品类出错后的历史数据丢失风险 |
| 告警触发节点 | 配置失败状态码≥400或字段异常时触发告警，告警推送间隔设为300秒 | 及时通知相关人员处理异常，避免客户拒收 |

## 容易做错的三处
- 现象：全局Number类型计数器无法在执行完成后自动加1，变量更新插件无法触发自身值变更。原因：未在工作流中配置变量更新节点的触发逻辑，仅绑定了基础变量定义，未关联执行完成后的回调步骤。
- 现象：FastGPT v4.17.0版本的工作流编排调试面板中，代码运行节点不显示执行详情。原因：调试面板的节点显示过滤规则未开启全节点展示，或当前工作流未启用调试日志开关。
- 现象：调用外部工作流的配置后，中间结果与预期不符，仅最终输出符合预期。原因：导入的外部工作流配置未同步关联字段映射表，或节点执行顺序被意外调整，导致中间校验环节缺失。

## 怎么确认配好了
- 手动触发一次测试导入流程，检查全局计数器是否正确累加，验证变量配置生效。
- 上传格式不符合要求的测试文件，确认格式校验节点触发拦截并返回对应提示，验证校验配置生效。
- 模拟字段错位的测试数据，确认失败回滚节点触发备份恢复，验证异常处理配置生效。
- 触发预设异常场景，检查告警消息是否正常推送，验证告警配置生效。
