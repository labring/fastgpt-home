# 客户数据导入迁移的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据主要来自客户历史系统、CSV或Excel模板、数据库导出以及产品导入日志。日常关联文档包含标准化数据模板、迁移执行方案、字段映射对照表与迁移验证报告。数据更新节奏随项目进度而定，通常每单或不定期更新。字段覆盖客户标识、业务流水、联系人信息、交易金额等，单位随具体业务场景变化，无统一固定格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源的多样性要求模型接入配置支持多格式输入解析，需针对CSV、数据库导出等不同数据源预设适配规则。更新节奏的不确定性意味着配置需支持动态调整，无需重启服务即可生效。字段无统一格式的特点，要求模型具备语义化字段映射能力，相关参数需匹配业务场景的语义匹配精度。导入日志的存在要求配置可关联异常排查，需保留参数溯源记录。脏数据占比不定，需配置合理的过滤阈值以确保导入数据的有效性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，针对客户数据导入迁移场景调整：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配客户导入数据的总长度，覆盖字段映射与验证的上下文需求 |
| `temperature` | 0.2–0.4 | 降低随机输出，确保字段映射与规则匹配的一致性 |
| `toolChoice` | auto | 允许模型自主判断是否调用工具处理导入数据的格式校验与清洗 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写AI Proxy服务的根地址，例如http://aiproxy:3000，不要附加/v1或/chat/completions，不是单模型地址 | 确保模型请求的路由正确，避免连接错误 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token，且不能为空 | 保障接口调用的身份合法性，防止未授权访问；该变量为App/Admin服务端环境变量，不得在工作流全局变量、应用API请求头或普通模型管理页面填写 |

## 容易做错的三处
- 接入模型时返回404 status code (no body)，原因是`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址）或`AIPROXY_API_TOKEN`（AI Proxy管理员Token）配置错误，导致请求无法到达AI Proxy服务；或未配置必填变量导致启动校验失败。
- 非工具调用模式下大模型未引用网络搜索内容，原因是未将`toolChoice`配置为auto或required，模型无法触发工具调用流程。
- 简易模式下上传文件后模型未自动解析文件内容，原因是`maxContext`配置值过小，无法容纳文件解析后的上下文内容，导致模型跳过解析步骤。

## 怎么确认配好了
- 访问`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址），验证AI Proxy服务连通性，确认返回正常响应。
- 上传一份测试用的CSV模板，触发字段映射解析，查看模型输出的映射结果是否符合预设的字段对照表。
- 触发一次模拟导入操作，查看产品导入日志中是否记录了模型调用的完整参数与返回结果。
- 调整`temperature`参数至不同区间，对比字段映射的一致性，确认配置生效。
