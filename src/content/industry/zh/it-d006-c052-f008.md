# 客户权限与组织架构配置的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
该品类的核心数据包括权限矩阵、组织架构表、角色配置记录、权限变更单，数据来源为客户HR系统、身份目录、产品后台与审计日志。数据更新无固定周期，随客户权限变更单触发。文档字段包含部门层级、角色权限范围、关联用户ID、变更时间戳，无统一量化单位，部分字段采用层级编号、权限项名称等文本格式。日常由实施顾问、客户管理员维护，需定期核对组织层级与权限映射关系。本页内容适配FastGPT v4.17.0版本。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需对接多系统接口，需适配HR系统同步、身份目录拉取等不同数据格式。更新无固定周期要求工作流支持按需触发，仅在有效变更提交后启动，避免无效执行。文档字段多为非量化内容，工作流的条件判断需基于文本匹配与层级校验，难以直接依赖单一数值阈值完成校验。组织层级核对与角色权限映射为耗时环节，需在工作流中插入人工审核节点，降低自动化校验的误判风险。审计日志需作为流程溯源节点嵌入，确保每一步权限变更可追溯，满足合规核查要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按权限变更单提交状态触发 | 匹配品类数据更新无固定周期的特征，仅在有效变更提交后启动工作流 |
| 变量绑定规则 | `variables` 绑定权限矩阵、组织架构表字段 | 确保工作流调用的权限数据与客户当前配置一致，避免引用过期数据 |
| 校验节点定位 | `nodeId` 指定为层级核对节点ID | 精准定位组织层级校验环节，便于后续日志溯源与异常排查 |
| 单次校验数据上限 | 前100条 | 避免因一次性拉取过多权限数据导致工作流卡顿，适配系统性能限制 |
| 人工审核触发条件 | 当角色权限映射字段不匹配时触发 | 覆盖跨部门、多角色的复杂权限组合校验场景，降低自动化校验的误判率 |
| 超时阈值 | 600 秒 | 避免因数据拉取延迟导致工作流阻塞，保障流程执行效率 |
| 审计日志留存时长 | 按实测标定 | 适配客户审计要求的留存周期，满足合规核查需求 |

## 容易做错的三处
- 现象：工作流执行后返回403 Forbidden报错，提示无权限访问目标资源。原因：未在`variables`中绑定当前用户的部门层级字段，导致权限校验节点调用了错误的权限数据。
- 现象：工作流执行超过600秒后中断，界面显示流程执行超时提示。原因：未配置合理的超时阈值，且未设置重试节点，当数据拉取延迟时直接中断流程。
- 现象：权限变更提交后，FastGPT后台的变更单状态未更新，工作流执行日志显示节点未触发。原因：未将`nodeId`与产品后台的审计日志节点正确绑定，流程执行完成后未触发状态同步，导致变更记录未留存。

## 怎么确认配好了
- 手动提交一条测试权限变更单，检查工作流是否在变更单提交后自动启动。
- 在工作流的`variables`绑定节点中，随机抽取一条权限矩阵中的角色权限数据，验证工作流调用后的数据与源文档完全一致。
- 查看工作流执行日志，确认`nodeId`对应的层级核对节点已完成校验，且FastGPT后台的审计日志节点已留存本次操作的记录。
- 模拟角色权限映射不匹配的场景，提交一条跨层级的权限变更申请，验证人工审核节点是否触发，确认流程拦截逻辑生效。
