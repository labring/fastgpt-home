# 客户权限与组织架构配置的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来源于客户HR系统、身份目录、产品后台与审计日志，更新节奏为每单或不定期。日常产出的文档包括权限矩阵、组织架构表、角色配置记录、权限变更单，核心字段包含部门层级关系、角色权限项、变更生效时间与操作人信息。数据需匹配客户现有组织架构与权限规则，无固定统计阈值，仅随客户业务调整或权限变更触发更新。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散、更新节奏不固定且文档格式多样，会对模型接入与配置带来多重约束。需支持对接多源身份目录与审计日志，确保权限数据的实时同步；需适配权限矩阵、组织架构表等多种文档格式，完成角色权限映射与组织层级核对；需支持动态拉取更新后的权限数据，适配不定期的更新节奏；同时需严格校验权限映射逻辑，避免因配置错误引发越权访问或审计不通过的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配权限矩阵、组织架构表等多份文档的上下文存储，避免因上下文溢出导致权限映射逻辑中断，符合FastGPT v4.17.0版本的配置规范 |
| `maxTokens` | `2000–3000 token` | 控制单轮模型输出的权限分析结果长度，确保结果可完整匹配组织架构字段，避免信息截断 |
| `quoteMaxToken` | `1000–1500 token` | 限制引用的权限文档片段长度，聚焦核心权限规则与组织层级信息，提升分析准确性 |
| `toolChoice` | `auto` | 自动选择合适的工具完成权限数据提取与映射，适配多源文档的解析需求 |
| `temperature` | `0.1–0.3` | 降低输出随机性，确保权限配置的分析结果与实际规则一致，规避越权风险 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如 http://aiproxy:3000 | 是App/Admin服务端必需的环境变量，为AI Proxy服务的访问根地址，不得附加 /v1 或 /chat/completions 等路径 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的非空管理员Token | 是App/Admin服务端必需的环境变量，用于AI Proxy服务的身份校验，不得作为应用API Key或模型供应商密钥使用 |

## 容易做错的三处
- 配置仅支持stream模式的大模型时，调用后返回空结果且日志报错获取数据异常。原因：未在模型配置中启用stream模式支持，导致无法解析模型的流式响应格式。
- 在内网环境部署FastGPT并调用模型时，服务启动校验失败或无法正常调用模型。原因：未正确配置`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，或未配置与服务端一致的`AIPROXY_API_TOKEN`，导致无法正常访问AI Proxy服务。
- 导入权限变更单时模型未正确识别角色权限映射关系，生成错误的权限配置建议。原因：`maxContext`取值过小，未完整加载权限变更单的全部内容，导致上下文信息缺失。

## 怎么确认配好了
- 检查FastGPT服务启动校验是否通过，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`作为服务端环境变量已正确配置。
- 导入一份权限矩阵文档，查看模型输出的权限映射结果是否与文档中的角色权限项一致，确认`temperature`与`maxContext`取值适配需求。
- 测试仅支持stream模式的大模型调用，查看是否能正常接收流式响应，确认stream模式配置已启用。
- 查看系统审计日志，确认模型生成的权限配置建议未出现越权相关的异常提示，验证配置的有效性。
