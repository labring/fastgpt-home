# 客户需求池管理的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
这个品类的数据通常来自工单系统、客户访谈记录、CRM系统与产品路线图，更新频率为每周或每版本发布周期。日常产出的文档包含需求池清单、需求评估表、客户反馈记录与版本规划说明，数据字段一般包含需求来源标识、关联客户信息、优先级标签、预计研发周期与影响范围，未设置统一强制统计单位，字段单位由各业务场景自行定义。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于该品类的数据分散在多个异构系统中，工具调用环节需要适配多源数据拉取插件，确保能同步工单、CRM与访谈记录中的需求信息。数据更新周期与版本发布绑定，意味着插件触发逻辑需匹配版本排期节点，避免调用过时的需求池数据。同时，重复需求归并与价值评估环节依赖模型推理，插件需支持批量调用模型处理单批次需求条目，适配重复需求归并的批量处理需求，且需限制单次调用的数据量以避免超时。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 适配场景中需要自主选择需求匹配、缺陷关联的工具调用逻辑 |
| `functionCall` | `仅调用需求分析与缺陷匹配类工具` | 聚焦客户需求池管理的测试用例与缺陷分析场景，限定工具调用范围 |
| 工具调用重试次数 | `2–3 次` | 应对单次调用的网络波动或模型响应异常，避免流程中断 |
| 最大上下文长度 | `8000–12000 字符` | 适配单版本周期内需求池文档的总数据量，避免上下文溢出 |
| 工具调用超时时间 | `60 秒` | 平衡多源数据拉取与模型推理的耗时，避免长时间等待 |
| 输出思考内容 | 开启 | 便于排查工具调用失败的推理过程，匹配场景的调试需求 |

## 容易做错的三处
- 现象：界面显示工具调用失败，返回`400`状态码或空响应。原因：未正确配置`toolChoice`参数，或未授权对应工具的调用权限。
- 现象：工具调用后未输出思考内容，仅返回最终结果。原因：未开启输出思考内容的配置开关，或模型未适配思考输出格式。
- 现象：多轮会话访问时，第一个AI模型的聊天记录未按预期保留。原因：未针对需求池管理的场景配置对应上下文保留规则，导致会话上下文被错误截断。

## 怎么确认配好了
- 手动触发一次工具调用，查看是否能拉取到需求池清单中的关联数据，验证多源数据同步配置生效。
- 查看工具调用日志，确认`toolChoice`参数已按配置生效，且调用的工具属于需求分析与缺陷匹配类。
- 提交测试用例，触发缺陷匹配工具调用，查看是否输出完整的思考内容与匹配结果。
- 模拟多次会话访问，验证上下文保留规则符合配置要求，无异常截断。
