# 客户需求池管理的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自工单系统、客户访谈记录、CRM客户管理系统及产品路线图，更新节奏为周度或每版本迭代前。日常产出的文档包含需求池清单、需求评估表、客户反馈记录与版本规划说明，字段通常包含客户标识、反馈场景、需求描述、优先级标签、关联工单编号与版本适配范围，多为文本类非结构化或半结构化数据，无强制统一的标准化格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的输入来源要求模型接入模块支持混合格式的数据源导入，避免额外的格式转换成本。周度/版本级的更新节奏要求配置的上下文窗口适配周期性批量数据处理，避免单次处理数据量过大导致超时。重复需求归并的高耗时环节要求模型绑定语义聚类的prompt逻辑，降低人工归并的工作量。需求承诺失真的出错后果要求配置保留原始需求的引用字段，避免信息丢失。作为客户需求池管理，区别于需求分析与PRD管理，需要优先处理跨客户的共性需求，因此模型接入需优先对齐跨客户需求的筛选逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的模型接入模块。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 适配周度批量导入的需求池总文本长度，避免截断核心需求描述 |
| `maxTokens` | `2000 token` | 控制单条需求转化为测试用例的输出长度，确保格式统一 |
| `quoteMaxToken` | `1500 token` | 保留原始客户反馈的完整引用，避免在需求归并和缺陷分析中丢失客户侧原始信息 |
| `toolChoice` | `auto` | 自动触发语义聚类、需求优先级排序的工具调用，适配重复需求归并的高耗时环节 |
| `temperature` | `0.3–0.5` | 降低输出随机性，确保需求筛选和测试用例生成的逻辑一致性，避免优先级判断偏差 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务根地址，例如 http://aiproxy:3000 | 为 App/Admin 服务端的必填环境变量，需与 AI Proxy 服务端配置的根地址一致，不得附加 /v1 或模型服务地址路径 |

## 容易做错的三处
- 现象：本地模型接入后输出的时间与服务器当前时间不一致。排查项：检查系统时间同步配置及本地模型的时间获取逻辑。
- 现象：触发需求转测试用例的流程后无法切换到人工审核环节。原因：未正确配置`toolChoice`为允许调用人工介入工具，导致模型始终自动生成结果。
- 现象：批量导入需求池数据后，模型输出的重复需求归并结果出现逻辑混乱。原因：`temperature`取值过高，导致语义聚类的判断逻辑出现随机偏差。

## 怎么确认配好了
- 上传单条客户反馈记录，检查模型输出的需求归并结果是否保留原始描述内容。
- 批量导入周度需求池数据，验证模型输出的测试用例字段与需求池清单的字段匹配情况。
- 查看代理日志，确认`AIPROXY_API_ENDPOINT`的请求状态码为200，无超时或报错信息。
- 调整`temperature`参数后，对比两次输出的需求优先级排序结果，确认逻辑一致性。
