# 容器平台运维的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
容器平台运维的核心数据来源于Kubernetes API、镜像仓库、监控系统与CI流水线，更新频率为每日或每一次集群变更。日常产出的文档包括集群变更单、命名空间配额表、部署记录与故障报告，数据字段包含集群节点状态、Pod运行状态、镜像标签、CI构建结果、资源配额阈值等，无统一固定的单条数据长度，单批次数据量随集群规模波动。

## 这些特征在「模型接入与配置」这一环带来什么约束
容器平台运维的数据结构以结构化字段为主，同时包含非结构化的日志与故障描述，要求模型接入配置需同时支持结构化字段解析与非上下文内容引用。数据更新频率较高，模型调用需适配实时性需求，避免因上下文长度限制丢失关键集群状态信息。工具调用场景集中在Pod异常排查、资源配额调整等操作，需配置自动工具选择以适配不同运维场景，同时需保障调用链路的内网安全性，匹配容器平台的RBAC权限体系。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 容器平台运维的上下文包含完整集群状态快照、多份故障报告与变更记录，需覆盖足够长度的历史数据以支撑全面排查 |
| `maxTokens` | `2000–3000 token` | 测试用例与缺陷分析的回答需包含具体排查步骤、配额调整建议，该取值可平衡输出完整性与模型性能 |
| `quoteMaxToken` | `1500 token` | 需优先引用集群变更单、故障报告中的原文内容，保障排查依据可追溯，避免生成虚构的运维建议 |
| `toolChoice` | `auto` | 容器平台运维需频繁调用Kubernetes API查询Pod状态、配额信息，自动工具选择可适配不同排查场景的调用需求 |
| `temperature` | `0.2–0.4` | 缺陷分析与测试用例生成需严谨准确，较低的温度值可减少虚构内容的生成概率 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如 http://aiproxy:3000 | 该变量为App/Admin服务端必需环境变量，需配置为AI Proxy服务的内网可访问根地址，不得附加 /v1 或 /chat/completions 路径；使用内网端点可保障数据传输安全，避免外部网络攻击风险 |

## 容易做错的三处
- 现象：调用模型时返回「不支持非流式调用」错误，状态码为400。原因：未适配目标模型的调用模式，FastGPT agent的流式请求设置与Qwen3等仅支持流式调用的模型不兼容，导致调用失败。
- 现象：模型回答中未引用关联的知识库内容，显示「未提供具体知识库内容」。原因：`maxContext`取值过小，知识库片段被截断后无法被模型读取，或未正确关联集群变更单、故障报告对应的知识库源。
- 现象：模型召回的集群日志中包含大量无关内容，未按预期过滤。原因：未明确rerank模型的接入层级，导致其未在召回后执行过滤逻辑，影响排查效率。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的测试工作台中，传入「查询指定命名空间Pod异常状态」的模拟请求，检查返回结果中是否包含工具调用记录，确认`toolChoice`配置生效。
- 查看模型回答的引用标记，确认是否包含知识库中集群变更单的原文片段，验证`quoteMaxToken`配置合理。
- 模拟非流式调用请求，检查是否返回「不支持非流式调用」错误，确认模型接入的流式设置与目标模型兼容。
- 检查App/Admin服务端部署的环境变量中是否已配置非空的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，确认服务启动校验通过；验证AI Proxy服务的网络连通性
