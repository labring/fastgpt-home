# 容量规划与资源扩缩容的测试用例与缺陷分析：工具调用与插件

本页内容基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
这个品类的数据主要来自云账单、监控系统、业务预测、压测报告，更新频率多为周或月。日常产出的文档包含容量规划报告、扩容申请、资源利用率报表、预算测算表，字段覆盖资源使用时段、节点规格、调用量峰值、预算额度等，无固定统一的单位标准，需根据数据源类型匹配对应计量方式，数据结构随业务场景调整，无强制统一格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散且更新周期多为周或月，工具调用需支持对接多类数据源插件，避免手动聚合数据的重复操作。文档结构无固定强制格式，插件需支持字段映射配置，适配不同业务的文档模板要求。峰值预测与资源瓶颈定位环节耗时较长，工具调用需支持批量拉取历史数据、并行计算的能力，减少人工干预的时间成本。同时，预算与采购协调环节需精准的资源数据，工具调用的输出需符合运维与财务文档的字段规范，避免数据错位导致的流程阻塞。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 允许系统自动选择匹配容量规划场景的工具，无需手动指定 |
| 数据源插件调度间隔 | `7 天` | 匹配周更的资源利用率报表更新频率，避免重复拉取冗余数据 |
| `functionCall` | 开启 | 允许调用预设的容量计算、峰值预测专用函数，提升流程自动化程度 |
| 函数调用超时阈值 | `300 秒` | 应对跨云监控数据拉取的延迟，避免因超时中断流程 |
| 结果输出格式 | `JSON 格式` | 适配各类容量规划文档的字段解析需求，简化后续格式转换 |
| 插件依赖校验开关 | 开启 | 提前校验数据源插件、认证参数的可用性，减少运行时错误 |

## 容易做错的三处
- 嵌套工作流调用容量规划工具后无法生成完整文档，原因是未映射数据源字段与文档模板的必填项，导致关键字段缺失。
- 调用第三方云账单接口时返回`Error: write EPROT`报错，原因是未配置插件的网络代理规则，导致跨区域访问被拦截。
- 调用Qwen模型做峰值预测时无法正常执行，原因是未开启`functionCall`配置，导致模型无法调用预设的预测函数。

## 怎么确认配好了
- 触发工具调用流程，检查拉取的数据源数据是否包含预设的资源使用时段、节点规格字段，字段匹配度按业务文档要求确认。
- 查看插件运行日志，确认无`write EPROT`类网络报错，网络连通性按目标数据源的访问规则确认。
- 触发模型调用环节，检查是否生成符合容量规划报告格式的中间结果，输出格式按预设模板要求确认。
- 测试嵌套工作流调用，确认子工作流可完整执行预设的资源计算逻辑，流程完整性按工作流节点配置确认。
