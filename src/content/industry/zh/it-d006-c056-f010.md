# 对象存储与备份服务的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
对象存储与备份服务的核心数据来源于对象存储控制台、备份系统、访问日志与客户策略表。日常维护的文档包括存储桶配置文件、备份策略文档、恢复记录台账与生命周期规则表。数据更新频率通常为每日同步或随策略变更实时更新，字段包含存储桶名称、备份任务ID、恢复时长、权限策略内容、文件访问路径等，无统一固定统计单位，随具体文档类型变化。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散在多个独立系统，引用溯源需关联控制台配置、备份日志与客户策略的对应条目，避免跨系统数据错位。数据更新随策略变更触发，要求溯源环节需实时匹配最新的存储桶或备份规则，无法依赖静态缓存。日常文档类型多样，引用需精准对应到具体的文件路径或任务ID，不能泛泛关联大类数据。同时出错后果直接关联数据泄露或恢复失败，溯源的准确性需严格匹配业务数据的字段格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | 匹配存储桶配置、备份策略这类文档的平均长度，避免截断关键权限策略或恢复路径内容 |
| `responseData` | 仅返回关联源数据 | 过滤无关信息，聚焦对象存储控制台、备份系统的核心溯源字段 |
| `detail` | 显示源文件路径与修改时间 | 对应恢复记录与访问日志的标准字段，方便快速定位引用来源 |
| 单次引用源数量上限 | 前3条 | 匹配单备份任务的常规关联访问日志条目数，避免结果过载 |
| 引用源时间校验范围 | 近30天 | 匹配生命周期规则与备份策略的常规更新周期，确保引用数据时效性 |
| 引用匹配阈值 | 0.75–0.85 | 区分存储桶配置的不同版本，避免误关联相似但不匹配的策略内容 |

## 容易做错的三处
- 现象：调用接口时返回`quote type error`报错文案，原因是输入的变量格式不符合要求，例如将数字类型的备份任务ID误传为非字符串格式，未匹配存储桶名称、策略ID的字段规范。
- 现象：生成的回复中未显示引用的文件名或存储路径，原因是未开启`responseData`配置项，未关联对象存储控制台的文件路径字段，导致溯源信息缺失。
- 现象：无法同时引用多个变量，例如同时调用存储桶名称和备份任务ID时结果异常，原因是未配置支持多变量关联的参数，仅默认启用单变量匹配逻辑，未覆盖该品类多源数据的关联需求。

- 输入包含变量的测试问题，触发`quote type error`报错，确认报错提示与变量格式要求匹配，验证配置的格式校验逻辑。
- 调整`quoteMaxToken`的取值，提交包含长文档的测试查询，验证引用内容未被截断，确认配置的token限制生效。
- 模拟存储桶策略变更，提交关联新策略的测试查询，确认返回的引用源自动更新为最新的配置内容，验证时间校验范围的设置合理性。
