# 工单受理与问题分级的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的核心数据来源于工单系统、聊天记录、产品日志与客户合同SLA，更新频率为日级或实时。日常维护的文档包括客户工单、问题分级表、处理记录与服务报告，其中工单文档包含工单ID、客户标识、问题描述、提交时间、关联产品字段；问题分级表包含分级标签、响应时限、责任团队映射；处理记录包含流转节点、处理人、耗时数据。所有数据以非结构化文本与结构化字段混合的形式存在，无统一的固定格式模板。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征对模型接入配置带来多项约束：首先，实时更新的工单与聊天记录要求模型接口具备低延迟响应能力，需限制上下文与输出token的总占用；其次，多源混合的数据结构要求模型能兼容非结构化问题描述与结构化字段的混合输入，需合理配置上下文长度参数；第三，问题分级与SLA履约判断依赖精准的分类结果，需调整模型的随机性参数以保证输出一致性；最后，客户合同SLA的字段匹配要求模型能识别结构化字段的取值规则，需固定工具调用的触发逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配工单与聊天记录的平均上下文长度，避免溢出 |
| `maxTokens` | 2000–3000 token | 覆盖问题分级、责任分派的完整输出需求 |
| `temperature` | 0.2–0.4 | 保证问题分级与SLA判断的输出稳定性，减少随机波动 |
| `AIPROXY_API_ENDPOINT` | `http://localhost:8000`（本地部署场景） | AI Proxy 服务的根地址，不得附加 `/v1` 等路径后缀 |
| `AIPROXY_API_TOKEN` | 与 AI Proxy 服务端配置一致的非空管理员 Token | 保障 AI Proxy 服务调用的安全性 |
| `toolChoice` | auto | 自动判断是否需要调用工具处理工单流转或SLA校验 |

## 容易做错的三处
- 接口返回上下文溢出错误，状态码413。原因是未结合工单和聊天记录的平均上下文长度调整`maxContext`取值，导致输入token超出模型限制。
- 模型选择下拉框频繁跳动，新增渠道时模型列表刷新异常。排查项：未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`服务端环境变量，可能导致服务启动校验失败或无法连接 AI Proxy 服务，触发界面状态异常。
- 无法通过自定义协议接入本地模型，新增渠道时协议类型无自定义选项。排查项：未在模型渠道配置中正确配置上游模型的协议与地址，`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`为 App/Admin 服务端环境变量，无需在渠道配置中填写。

## 怎么确认配好了
- 提交一条测试工单，包含预设的问题描述与结构化字段，查看模型输出的问题分级结果是否与预设分级表一致。
- 查看FastGPT的接口调用日志，确认`maxContext`与`maxTokens`的实际调用值与配置值匹配。
- 验证 App/Admin 服务端已正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量，服务可通过 AI Proxy 正常获取模型响应。
- 模拟包含SLA时限的工单场景，确认模型能正确识别并关联对应的责任团队与处理要求。
