# 广告合规留痕的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
本品类的数据主要来自广告平台后台、客户资质文件、合同系统及监管公开规则。日常处理的核心文档包含广告审查表、资质附件、投放记录、整改通知四类。数据更新节奏以单次广告活动或自然月为周期。广告审查表包含投放时段、合规审查标识字段；资质附件标注有效期与发证机关；投放记录留存投放渠道与触发节点；整改通知关联对应违规事项与整改要求。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据来源分散且更新周期不固定，工具调用需适配多源异构数据的对接逻辑，避免频繁触发全量数据拉取导致资源占用过高。四类核心文档有固定格式，插件需预设对应字段的提取规则，确保广告审查表的合规标识、资质附件的有效期等关键信息被精准识别。跨文档关联需求突出，需通过插件实现投放记录与整改通知的绑定，避免数据割裂。监管规则的非固定更新节奏，要求插件支持动态加载最新校验逻辑，无需每次重新配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` 或指定合规校验插件 | 适配广告合规留痕的固定校验场景，自动选择对应工具完成校验 |
| `functionCall` | `enabled` | 强制模型调用合规校验插件，确保关键业务字段被精准提取 |
| 插件数据源配置 | 关联广告平台后台、客户资质库、合同系统三个数据源 | 匹配本品类数据来源的实际路径，覆盖全部核心数据入口 |
| 字段提取规则 | 按四类文档分别配置对应提取字段 | 覆盖本品类核心文档的固定字段结构，避免遗漏关键信息 |
| 单次调用数据上限 | `500 MB` | 适配本品类单活动周期内的文档总大小，避免内存溢出 |
| 调用超时设置 | `300 秒` | 适配多源数据拉取的平均耗时，避免因数据量波动导致调用失败 |

## 容易做错的三处
- 现象：调用合规校验插件后返回结果始终为`false`，但插件本身可正常拉起。原因：未在`toolChoice`配置中指定合规校验插件的专属标识，导致工具调用匹配错误。
- 现象：FastGPT v4.17.0版本中，插件编辑页面保存后，页面顶部仍持续显示“未保存”提示。原因：插件配置的本地缓存与后端存储未同步，未触发保存确认的状态更新。
- 现象：调用接口生成合规校验的索引模型时，返回的模型与预设不一致。原因：未在插件配置中固定索引模型参数，导致调用默认更新后的模型。

## 怎么确认配好了
- 手动触发一次插件调用，核对返回结果中是否包含广告审查表的合规标识字段。
- 检查插件数据源配置页面，确认已关联广告平台后台、客户资质库、合同系统三个数据源。
- 查看FastGPT v4.17.0版本的插件调用日志，确认未触发频繁的超时报错。
- 模拟一次广告活动结束后的触发流程，核对插件是否按预设周期自动执行校验。
