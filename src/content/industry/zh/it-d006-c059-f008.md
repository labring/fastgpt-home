# 广告素材审核的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
本品类的数据主要来自广告投放平台、落地页托管服务、商品资质备案系统及广告法合规条款库，更新节奏为日级或实时。日常处理的文档包含广告素材文件、落地页截图、审核人员出具的整改意见、素材修改历史记录。数据字段包含素材唯一标识、投放渠道类型、违规点分类、整改完成状态、审核时间戳等，无额外自定义统计单位。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新节奏差异大，要求工作流编排时需配置多数据源拉取节点，分别对接广告平台素材库、落地页校验接口及合规条款库。多类型文档输入需适配不同格式解析逻辑，避免节点兼容性问题。实时更新的数据要求工作流支持按需触发运行，避免固定周期执行带来的无效资源消耗。高风险的出错后果要求编排时加入前置校验、失败重试及异常告警节点，确保每个环节的执行结果可追溯，便于后续合规审计。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源触发时机 | 按素材更新事件触发，无事件时每600秒轮询一次 | 匹配本品类实时/日级的数据更新节奏，减少无效拉取次数 |
| 单次拉取数据量 | 100–200条素材记录 | 平衡节点负载与批量处理效率，适配广告素材审核的常规单批次处理规模 |
| 节点超时阈值 | 300–600秒 | 覆盖落地页加载、合规条款查询等耗时较长的审核环节 |
| 失败重试次数 | 2次 | 应对临时网络波动或接口抖动，避免误判为永久审核失败 |
| `variables` 作用范围 | 工作流全局 | 确保跨节点传递素材ID、违规类型等核心审核参数不丢失 |
| 节点执行顺序 | 先拉取数据→再校验格式→最后执行合规检查 | 符合广告素材审核的常规业务逻辑，避免无效计算 |

## 容易做错的三处
- 现象：工作流画布拖动节点时卡顿，状态显示延迟数秒。原因：未使用FastGPT v4.17.0版本，旧版本如4.6.5的画布渲染逻辑未优化，节点数量较多时会出现性能瓶颈。
- 现象：工作流在预览页面正常运行，聊天页面无返回结果。原因：未配置`variables`的全局传递范围，导致聊天场景下的上下文参数未正确带入审核节点。
- 现象：HTTP请求节点配置form-data参数时，无法正确上传落地页截图文件。原因：未在文件参数项中指定正确的文件来源字段，或未匹配广告素材审核的文件格式校验规则。

## 怎么确认配好了
- 触发一条测试素材的审核工作流，查看各节点的执行日志，确认数据源拉取的记录数量符合预期。
- 模拟临时断开数据源接口的异常场景，验证失败重试节点是否按配置触发重试及告警动作。
- 检查`variables`的配置面板，确认核心审核参数已设置为全局可传递，避免跨节点参数丢失。
- 对比工作流节点执行顺序与常规广告素材审核流程，确认各环节的执行逻辑匹配业务需求。
