# 广告账户开户审核的测试用例与缺陷分析：工作流编排
本文基于FastGPT v4.17.0版本编写

## 这个品类的数据长什么样
这个品类的数据主要来自广告平台后台、国家企业信用信息公示系统、客户提交的开户申请材料、行业准入规则。数据更新节奏为每日同步或随每一笔开户申请触发更新。日常关联文档包含开户申请单、营业执照扫描件、对应行业经营资质文件、历史开户审核记录。数据字段包含主体统一社会信用代码、行业资质有效期、申请提交时间、审核节点状态等，无统一固定单位，部分字段需匹配对应资质文件的格式要求。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需对接多类外部接口，需配置多节点并行或串行调用不同数据源。更新频率随申请触发要求工作流支持按需启动，无法使用固定周期触发的方式。多类型文档混合处理要求工作流内置格式校验节点，适配不同资质文件的解析规则。字段无统一单位要求需在编排中增加字段标准化处理环节，避免因格式差异导致审核逻辑出错。历史审核记录作为参考数据，需配置上下文关联节点，确保审核判断基于过往合规案例。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 数据源节点数量 | 不超过4个 | 该品类数据源分散，过多节点会增加整体调用延迟 |
| 触发方式 | 按开户申请提交事件触发 | 数据更新随每笔申请触发，固定周期触发无法匹配实时需求 |
| 节点超时时间 | 600秒 | 对接的外部数据源接口响应通常在10分钟内，600秒可覆盖多数异常延迟场景 |
| 格式校验规则 | 按资质类型分设校验项 | 不同行业资质有不同格式要求，分设规则可提升校验准确率 |
| `variables` | 配置主体统一社会信用代码、资质有效期为全局变量 | 多节点需复用这些核心字段，全局变量可减少重复配置 |
| `nodeId` | 为每个数据源节点分配唯一标识 | 便于工作流编排时追踪节点执行状态，排查异常时快速定位 |

## 容易做错的三处
- 现象：工作流中配置的表单输入字段在对话环节无法显示，交互内容为空。原因：未将表单字段绑定至全局`variables`，导致节点无法读取用户提交的开户申请信息。
- 现象：高级编排工具调用时无法自动选择后续执行节点。原因：未配置`nodeId`关联的触发逻辑，导致工作流无法识别节点执行状态以跳转后续步骤。
- 现象：AI对话模块中配置的文件链接与用户问题项未生效，无法调取历史审核记录。原因：未将对应数据源的文件路径与历史审核查询条件绑定至配置项，导致模块无法读取目标数据。

## 怎么确认配好了
- 触发测试：提交一笔模拟开户申请，确认工作流按提交事件启动并执行所有配置节点。
- 变量校验：查看工作流运行日志，确认`variables`中配置的核心字段已正确加载用户提交的信息。
- 节点追踪：核对每个数据源节点的标识，确认执行状态可在编排界面正常显示。
- 交互验证：发起模拟对话，确认表单输入字段与AI对话模块的配置项可正常展示与调用。
