# 性能测试与容量评估的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
性能测试与容量评估的数据来源包括压测平台、APM监控、数据库慢日志、生产流量基线。数据更新频率为每月或每重大版本发布时。日常产出的文档包含压测方案、容量评估报告、压测数据记录、优化建议单。数据字段包含吞吐率（单位：次/秒）、请求延迟（单位：毫秒）、资源消耗（单位：核心数/GB）、峰值并发数（单位：个），无固定统一的格式模板，需匹配对应业务的压测规范。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散的特征要求插件支持对接多类外部工具，需配置不同数据源的拉取权限与格式适配规则。更新频率偏低但变更影响较大的特点，要求插件优先采用增量同步模式，避免全量拉取重复数据占用资源。文档结构不统一的情况，需要插件内置字段映射逻辑，将外部工具返回的原始数据转换为统一的分析输入格式。最耗时的压测模型设计与瓶颈定位环节，要求工具调用支持批量处理压测数据，减少人工整理的工作量，提升分析效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 设为`auto` | 适配多工具调用场景，自动选择压测数据拉取、APM分析等工具 |
| 多源数据拉取触发时机 | 按压测任务完成后触发 | 匹配压测数据的生成节奏，避免拉取未完成的任务数据 |
| 增量同步间隔 | 每6小时 | 适配月度更新频率，平衡数据时效性与资源消耗 |
| 字段映射规则 | 按压测数据字段名直接映射 | 匹配现有压测文档的字段结构，减少转换成本 |
| `functionCall` | 开启参数校验模式 | 确保传入分析工具的字段符合要求，避免无效分析 |
| 数据校验阈值 | 按实测标定 | 适配不同业务的压测数据标准，避免误判异常数据 |

## 容易做错的三处
- 现象：插件调用返回的分析结果与原始压测数据不符。原因：插件暴露的配置参数有限，无法自定义字段映射规则，导致大模型使用错误的字段进行分析。
- 现象：插件触发后出现超时错误，耗时超过300秒。原因：未启用增量同步模式，全量拉取月度压测数据导致请求负载过大。
- 现象：大模型调用提示欠费，但API余额充足。原因：插件绑定的外部工具API密钥配置错误，被第三方服务误判为欠费场景。

## 怎么确认配好了
- 手动触发一次插件调用，检查返回结果是否包含吞吐率、请求延迟等核心性能指标字段。
- 查看FastGPT v4.17.0的插件日志，确认仅在压测任务完成后触发数据拉取，无重复请求记录。
- 提交一份模拟压测数据，验证字段映射是否正确，无字段缺失或错位情况。
- 检查插件绑定的API密钥配置，确保外部工具可以正常拉取压测平台与APM监控的数据。
