# 性能测试与容量评估的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自压测平台采集的并发请求数据、APM监控的接口延迟与资源占用指标、数据库慢日志的慢查询记录，以及生产环境的流量基线数据。日常产出的文档包括压测方案、容量评估报告、压测数据记录与优化建议单，字段通常包含吞吐率、平均延迟、峰值并发数、CPU/内存使用率等，更新频率为每月一次或每重大软件版本发布后。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且格式各异，需要模型兼容结构化指标、半结构化日志等多种数据类型，因此模型接入时需适配多源数据的解析逻辑。数据更新节奏随版本迭代调整，要求配置支持动态调整上下文窗口以适配不同周期的压测数据。同时，性能测试的结果直接关联生产稳定性，模型调用的延迟与准确率需匹配压测分析的时效性要求，避免因模型响应过慢导致分析滞后。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配压测报告与多源日志的拼接长度，避免截断关键指标数据 |
| `maxTokens` | 4000 token | 控制单轮分析的输出长度，确保缺陷定位结论完整且不超出接口限制 |
| `quoteMaxToken` | 1000 token | 限制引用的压测日志片段长度，避免冗余数据干扰分析 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具分析瓶颈指标，适配不同压测场景的分析需求 |
| `temperature` | 0.2–0.4 | 降低输出随机性，保证缺陷分析结论的一致性与准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写AI Proxy服务根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions，不得填写单模型服务地址 | 为App/Admin服务端必需的环境变量，确保请求可正常路由至AI Proxy服务 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的非空管理员Token，不得为应用API Key、模型供应商密钥等 | 为App/Admin服务端必需的环境变量，完成AI Proxy服务的身份校验，避免未授权访问 |

## 容易做错的三处
- 调用时返回`400 Bad Request`，提示上下文长度超限。原因是未根据压测数据的实际拼接长度调整`maxContext`参数，导致请求超出模型支持的最大上下文阈值。
- 无法调用本地部署的大模型，工具调用功能失效。原因是未正确配置`toolChoice`参数为`auto`，或未在代理服务中开启function call支持，导致模型无法触发瓶颈定位的工具调用。
- 分析结果与实际压测数据偏差较大。原因是将`temperature`参数设置过高，导致模型输出的缺陷结论随机性过强，无法匹配真实的性能瓶颈。

## 怎么确认配好了
- 发起一次小型压测数据的分析请求，检查接口返回的响应码是否为200，确认服务端已正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量。
- 查看模型调用的日志，确认`maxContext`与`maxTokens`参数被正确带入请求参数，无截断或超限提示。
- 提交两组不同参数的`temperature`配置，对比分析结果的一致性，确认参数取值符合预期。
- 触发一次包含多源数据的分析任务，检查模型是否能自动调用工具完成瓶颈指标定位，确认`toolChoice`配置生效。
