# 投放计划搭建的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据主要来自广告平台API、用户画像数据集、线下预算排期表、归因工具日志。日常关联文档包含投放计划文档、定向设置配置表、预算排期表、转化追踪配置文件。数据更新频率为每日或单次活动周期内。数据字段包含定向人群包标识、预算额度、转化事件类型、投放时段参数等，单位涉及元、人次、小时等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源包含广告平台API、离线预算表等多类异构数据源，引用溯源需为不同来源的内容添加专属标识，避免混淆。数据更新频率为每日或单次活动周期，溯源信息需同步标注对应数据的更新时间，确保引用内容的时效性。日常关联文档多为结构化表格类文件，引用需精准定位到具体配置项行。字段多为唯一标识类参数，溯源需关联原始数据的唯一ID，便于后续校验。不同于投放效果优化类场景，投放计划搭建为上线前的账户结构配置，溯源需覆盖全量配置项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 900–1100 token | 适配投放计划结构化文档的平均内容长度，保留完整配置参数 |
| 引用内容展示长度 | 800–1200 字符 | 避免过长内容干扰阅读，同时覆盖核心配置信息 |
| `responseData` | 开启来源元数据返回 | 确保结果中携带数据源类型、更新时间等溯源必要信息 |
| 单次引用条数上限 | 前5条 | 匹配广告优化师日常关注的核心配置项数量，避免冗余 |
| `detail` | 启用完整溯源模式 | 展示引用内容的原始文档行号、唯一标识，适配结构化配置表的精准定位 |
| 溯源时间戳开关 | 随内容同步展示 | 适配数据日更或活动级更新的时效性校验需求 |

本配置基于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：配置单次引用上限超过2000 token后，大模型无法接收到上下文内容。原因：系统对引用token总和存在阈值限制，超过后会截断所有引用内容，导致上下文为空。
- 现象：返回结果中未显示引用来源的具体内容。原因：未开启`responseData`对应的元数据返回配置，仅返回了大模型生成的摘要内容。
- 现象：引用内容出现格式错乱。原因：未针对结构化表格类文档启用精准行号定位，导致跨格式的内容拼接出现异常。

## 怎么确认配好了
- 生成一条针对投放计划配置的测试查询，检查返回结果中是否包含预设的数据源标识。
- 查看返回内容的token长度，确认未超过配置的`quoteMaxToken`取值范围。
- 核对引用内容的行号或唯一标识，确认与原始配置文档的定位一致。
- 调整单次引用条数上限，验证返回结果的引用条数符合预期设置。
