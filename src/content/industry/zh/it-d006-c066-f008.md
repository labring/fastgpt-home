# 搜索广告关键词管理的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
该品类的日常文档包含关键词清单、否词表、出价记录、搜索词报告，其中关键词清单包含匹配类型、投放出价、地域限制字段，否词表包含匹配模式、生效时段信息。数据主要来自搜索广告后台、搜索词报告、竞价排名数据及落地页统计工具，更新频率为每日或每周拉取。数据字段多且关联紧密，需按广告账户维度拆分处理，避免跨账户数据混杂。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且需按账户拆分，要求工作流支持多数据源节点对接与权限隔离；日/周级别的更新节奏，要求工作流配置定时触发机制，避免重复拉取无效数据；关键词扩展、否词筛选为最耗时环节，要求工作流支持批量节点与并发执行；数据出错会引发无效点击、品牌词被抢等后果，要求工作流配置失败重试与异常告警环节。同时，文档字段多且格式固定，需通过参数传递不同文档的字段值，适配不同广告账户的配置差异。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发周期 | 每日 0 点 / 每周一 2 点 | 匹配搜索广告数据日/周更新节奏，避免重复拉取旧数据 |
| 批量节点并发数 | 5–10 并发 | 适配广告平台接口调用限制，避免触发接口限流 |
| 上下文调用范围 | 绑定当前节点的 `variables` | 隔离不同广告账户的关键词数据，防止上下文污染 |
| 节点失败重试次数 | 2 次，间隔 60 秒 | 应对广告平台临时接口波动，降低单次任务失败概率 |
| 节点超时阈值 | 300 秒 | 适配批量关键词处理的耗时需求，避免任务提前终止 |
| 账户节点过滤 | 绑定目标账户的 `nodeId` | 精准定位对应广告账户的工作流任务，避免跨账户干扰 |

## 容易做错的三处
- 现象：大模型节点运行返回 500 Gateway forwarding error 状态码，提示服务断开。原因：未配置上下文隔离规则，跨广告账户的关键词数据混杂导致服务异常。
- 现象：批量运行节点耗时远超预期，任务触发超时告警。原因：未开启批量节点的并发执行配置，采用串行方式处理大量关键词任务。
- 现象：工作流节点图标不显示，上传关键词清单时弹出网络错误提示。原因：未在 FastGPT v4.17.0 版本中完成本地存储权限配置，或网络代理设置异常。

## 怎么确认配好了
- 查看工作流触发配置面板，确认定时触发的时间点与广告数据更新频率匹配。
- 运行批量节点后查看执行日志，确认节点以并发模式执行任务。
- 检查节点上下文配置，确认仅绑定当前工作流节点的 `variables` 参数。
- 上传测试用的关键词清单，确认文件上传无网络错误提示，节点图标正常显示。
