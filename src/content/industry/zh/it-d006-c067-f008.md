# 数据安全分类分级的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
这个品类的数据来自数据资产盘点、数据库元数据、业务系统说明与法规文件，更新频率为季度或系统变更时触发。日常产出的文档包括数据目录、分类分级规则、重要数据识别表与评审纪要。数据目录包含资产ID、资产名称、存储位置字段；分类分级规则包含敏感数据类型、定级阈值字段；评审纪要包含评审节点、评审意见字段。该品类覆盖个人信息以外的数据资产。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新无固定周期，要求工作流支持多源数据接入与增量同步配置。文档结构差异较大，需支持自定义字段映射，避免硬编码适配不同团队的文档格式。评审纪要的节点化内容，要求工作流支持按评审状态分支流转。重要数据识别表的字段校验，需嵌入前置检查环节，防止漏填定级信息。合规类文档的变更需触发工作流重新校验，确保数据安全分类分级结果与最新法规对齐。

## 配置怎么定
本配置说明基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 知识库搜索触发条件 | 按`variables`中的「待分类数据ID」触发 | 匹配数据目录的资产ID字段，确保仅针对已盘点的数据执行搜索 |
| 单次搜索召回条数 | 前10条 | 匹配重要数据识别表的字段数量，避免冗余信息干扰 |
| 批量执行节点 | 单次处理100–200条数据 | 适配数据目录的批量更新节奏，避免系统过载 |
| 变量优先级配置 | 优先取`variables`传入值，未获取到则使用插件默认值 | 支持灵活传入临时参数，同时保留默认兜底 |
| 工作流超时阈值 | 600秒 | 匹配分类分级规则评审的平均耗时，防止长时间阻塞 |
| 节点跳转规则 | 按`nodeId`匹配评审状态分支 | 对应评审纪要的节点流转逻辑，实现通过/驳回分支处理 |

## 容易做错的三处
- 工作流调用知识库搜索时返回无匹配结果，界面提示「未找到相关数据」。原因是未使用`variables`中的资产ID作为搜索关键词，直接调用全量搜索，无法匹配仅针对已盘点数据的分类分级规则，可能导致重要数据漏管。
- 插件参数未按预期使用默认值，直接返回空结果。原因是未配置变量优先级逻辑，未指定未获取到`variables`参数时的兜底规则。
- 批量执行节点触发后仅处理少量数据，未达到预期批量规模。原因是未设置合理的单次处理条数，超出系统并发限制导致部分任务被截断。

## 怎么确认配好了
- 触发工作流时，检查知识库搜索的入参是否包含`variables`中的资产ID字段，确认触发逻辑匹配数据目录的资产范围。
- 模拟未传入指定变量的场景，验证插件是否自动使用预设的默认参数，确认优先级配置生效。
- 提交批量执行任务，查看任务日志中的处理条数，确认单次处理规模符合系统承载能力。
- 触发评审分支跳转，验证工作流是否按`nodeId`匹配评审状态，正确流转至通过或驳回节点。
