# 数据安全分类分级的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的核心数据由数据治理团队、安全咨询顾问、法务合规团队日常产出与维护，包含数据目录、分类分级规则、重要数据识别表、评审纪要四类文档。数据来源覆盖数据资产盘点结果、数据库元数据、业务系统说明文件及公开法规文件。数据更新频率为季度周期或每次业务系统变更时触发，文档结构包含结构化字段与非结构化评审内容，无统一固定单位，字段随业务系统与合规要求动态调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入需支持解析不同格式的输入内容，包括结构化表格与非结构化文本。季度或变更触发的更新节奏要求配置可灵活调整，适配规则的动态变化。文档中包含的评审纪要等长文本内容，要求模型上下文配置需满足长文本处理需求，避免关键信息截断。同时，数据资产梳理与敏感字段识别的高耗时环节，要求模型调用的参数配置需平衡响应速度与识别精度，减少无效计算。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配多源文档的长上下文拼接，避免截断核心分类分级规则与评审纪要内容 |
| `maxTokens` | 4000 token | 平衡单轮输出长度与响应速度，适配结构化数据目录与识别表的解析需求 |
| `toolChoice` | auto | 允许模型自主选择工具调用路径，适配敏感字段识别的灵活场景 |
| `temperature` | 0.2–0.4 | 降低随机性，保证分类分级规则匹配的一致性，避免结果偏差 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致且非空的管理员Token | 作为App/Admin服务端环境变量，用于AI Proxy服务身份验证，防止未授权访问 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如 http://aiproxy:3000（不得附加 /v1 或 /chat/completions 路径） | 作为App/Admin服务端环境变量，用于指定AI Proxy服务访问地址 |

## 容易做错的三处
- 现象：调用Gemini模型时提示工具调用失败，返回状态码400。原因：未将`toolChoice`配置为auto或指定对应function call模式，导致模型无法触发工具调用。
- 现象：模型解析数据目录时返回空字段结果。原因：`maxTokens`配置过低，截断了结构化字段的解析内容，无法完整提取数据分类标签。
- 现象：Windows系统部署后重启，配置的模型与应用信息全部丢失。原因：未将模型配置文件挂载至持久化存储目录，系统重启后临时配置被清空。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量配置，确认`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的取值与部署环境一致。
- 上传一份测试用的分类分级规则文档，触发模型调用，检查返回的工具调用结果是否包含预期的字段识别内容。
- 调整`temperature`参数至0.3，多次调用同一测试文档，确认返回的分类结果无明显偏差。
- 重启部署服务，验证模型配置与应用配置未发生丢失。
