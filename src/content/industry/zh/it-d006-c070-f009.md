# 数据清洗与质检的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源包括原始数据集、ETL日志、标注平台输出、抽样结果。数据更新频率为日度或按每批任务触发。日常产出的文档包含清洗规则、质检抽样表、异常数据清单与交付报告。数据字段涵盖数据唯一标识、字段原始值、处理批次号、异常类型编码、抽样比例、交付校验状态等，无统一强制单位，部分字段需匹配上游数据源的单位定义。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源且批次化的数据输入，要求工具调用需支持按任务批次触发，避免跨批次数据混淆；日度或批级的更新节奏，要求工具调用的超时阈值适配单批次任务的执行时长；多样的文档格式与字段结构，要求插件需兼容解析清洗规则、异常清单等非标准化文档；无统一单位的字段要求，需工具调用时保留原始字段的单位关联逻辑，防止数据单位失真。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `functionCall` | 强制启用 | 适配数据清洗与质检的结构化规则调用需求，符合FastGPT v4.17.0的工具调用参数规范 |
| `toolChoice` | 指定为auto | 允许模型自主选择是否调用工具，适配灵活的质检场景 |
| 最大上下文token数 | 8000–12000 token | 适配清洗规则、异常清单等多文档的上下文承载需求 |
| 单次工具调用上限 | 前3条异常数据 | 匹配日常质检抽样的常规异常量，防止单次调用过载 |
| 超时阈值 | 600秒 | 适配单批次数据清洗与质检任务的常规执行时长 |
| 触发方式 | 按任务批次触发 | 匹配本品类按批更新的数据节奏，避免跨批次数据混淆 |

## 容易做错的三处
- 现象：MCP服务调用失败，返回连接超时或权限拒绝报错。原因：未正确配置MCP代理端点，未匹配数据清洗任务的数据源访问规则，导致工具无法调用对应服务。
- 现象：模型输出的清洗规则解析结果出现单位失真。原因：未保留原始字段的单位关联逻辑，工具调用时直接转换字段单位，导致数据指标失真。
- 现象：工具调用过程中触发上下文溢出报错。原因：最大上下文token数设置过小，未适配清洗规则、异常清单等多文档的上下文承载需求，超出模型支持的上下文长度。

## 怎么确认配好了
- 提交单批次测试数据，查看工具调用日志，确认触发规则与配置的触发方式一致。
- 检查模型输出的工具调用参数，确认调用模式符合配置要求，无格式错误。
- 验证异常数据处理结果，确认单位关联逻辑保留，无单位失真问题。
- 模拟长上下文的测试场景，确认未触发上下文溢出报错，可根据实际任务调整上下文阈值。
