# 数据清洗与质检的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来源于原始数据集、ETL日志、标注平台与抽样结果，更新频率为日或每批。日常产出的文档包含清洗规则、质检抽样表、异常数据清单与交付报告，其中原始数据集包含数据ID、字段值与来源标识，ETL日志记录执行时间与处理行数，质检抽样表标注抽样批次号与异常条目，异常数据清单记录异常类型与处理结果。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源的数据来源要求溯源系统需关联原始数据集、ETL日志、标注平台与抽样结果四类标识，避免溯源信息割裂。按日或每批的更新节奏，要求溯源需绑定批次号或时间戳作为关联依据，确保同批次数据的溯源一致性。日常文档的结构化特征，要求溯源需匹配文档版本与处理环节，覆盖清洗规则、异常处理等关键环节的记录，确保缺陷分析可追溯到具体的处理动作。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `quoteMaxToken` | `800–1200 token` | 清洗规则、异常数据清单等文档的常规长度在此区间，可完整覆盖溯源所需的上下文内容 |
| `responseData` | 包含原始数据集ID、ETL执行时间戳 | 业务数据来源包含原始数据集与ETL日志，需关联两类标识完成完整溯源 |
| `detail` | 开启完整溯源 | 需覆盖标注平台、抽样结果的细节信息，确保缺陷分析的溯源链路完整 |
| 单次溯源上限 | 前6条 | 按日/每批的更新频率，单批次关联的溯源文档数量通常在此范围内，避免过载 |
| 关联匹配规则 | 按批次号匹配 | 数据按批次更新，批次号是最明确的关联标识，可减少匹配误差 |
| 溯源超时阈值 | `600 秒` | 单批次数据处理的常规耗时在此区间，避免因等待过久导致任务失败 |

## 容易做错的三处
- 现象：触发溯源时出现「参数未绑定」报错。原因：误将本地变量作为溯源引用的上传源，未使用公开可访问的链接。
- 现象：溯源结果返回为空。原因：未正确配置批次号与ETL日志的关联匹配规则，导致无法匹配到对应数据源。
- 现象：溯源返回的关键内容被截断。原因：`quoteMaxToken`的取值设置过小，截断了清洗规则或异常数据清单的核心信息。

## 怎么确认配好了
- 上传一份清洗规则文档，触发溯源测试，检查返回结果中是否包含文档的原始来源标识与批次信息。
- 查看配置项`quoteMaxToken`的取值，确认符合预设的区间范围。
- 导入一份异常数据清单，验证溯源是否能关联到对应的ETL处理日志与抽样结果。
- 在FastGPT v4.17.0版本中，测试使用批次号作为搜索条件，确认能匹配到同批次的所有关联数据。
