# 数据清洗与质检的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类处理的数据来源于原始数据集、ETL运行日志、标注平台产出结果及抽样质检结果。数据更新频率为每日或按批执行。日常关联文档包含清洗规则配置文件、质检抽样记录表、异常数据清单与交付报告。数据字段包含原始数据内容、ETL处理标记、标注标签、抽样校验结果等，无统一固定单位，随原始业务数据格式调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
原始数据集规模波动大，需配置适配不同数据量的模型上下文参数；按批或日更新的数据要求模型接入支持定时触发或批量任务绑定，需确认服务端环境变量`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token，需与AI Proxy服务端配置一致且非空）的有效性以适配批量请求。异常数据清单包含非结构化文本、数值异常项，需配置`temperature`适配不同类型的异常识别需求。ETL日志包含时序性运行记录，需模型支持上下文关联分析，限制`maxTokens`避免日志过长导致请求超时。同时，质检抽样表的结构化字段需模型准确匹配字段映射，需提前定义模型输入输出的字段格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配ETL日志、原始数据集的批量上下文关联分析需求，避免截断关键业务关联信息 |
| `maxTokens` | 4000 token | 限制单批次异常数据识别的输出长度，适配每日/每批的批量任务处理节奏 |
| `temperature` | 0.2–0.6 | 平衡异常值识别的准确性与灵活性，适配清洗规则与抽样结果的校验场景 |
| `quoteMaxToken` | 2000 token | 限制引用的清洗规则文档长度，避免超出模型输入上下文限制 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务根地址，例如`http://aiproxy:3000`，不得附加`/v1`或模型相关路径后缀 | 作为App/Admin服务端必需环境变量，确保模型请求路由正确，避免连接失败 |
| `toolChoice` | auto | 允许模型自动选择合适的工具处理重复数据识别、异常值分类等任务 |

## 容易做错的三处
- 现象：工作流中无法找到已配置启用的模型，接口返回404或500状态码。原因：服务端未配置必填环境变量`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）或`AIPROXY_API_TOKEN`（AI Proxy管理员Token，需与AI Proxy服务端配置一致且非空），导致启动校验失败，或渠道配置未绑定对应模型的映射关系。
- 现象：批量处理数据时出现请求超时错误。原因：`maxContext`或`maxTokens`设置过大，超出模型接口的单次请求限制。
- 现象：异常数据识别结果与实际抽样校验结果偏差过大。原因：`temperature`设置过高，导致模型生成的校验逻辑偏离预设的清洗规则。

## 怎么确认配好了
- 检查服务端环境变量`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token，需与AI Proxy服务端配置一致且非空）的配置与部署环境一致。
- 发起单次小批量测试请求，查看接口返回状态码是否为200，无异常报错。
- 在测试用例中绑定已配置的模型，运行单条异常数据校验任务，确认输出结果符合预期的清洗规则逻辑。
- 查看FastGPT v4.17.0的系统日志，确认模型接入请求无身份验证或路由错误。
