# 数据脱敏处理的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
本品类的数据主要来源于业务数据库、系统数据字典、自研脱敏工具及访问审批系统，更新频率随项目批次或单次任务调整。日常产出的核心文档包括脱敏方案、敏感字段映射表、脱敏验证报告与访问审批记录，字段覆盖敏感类型标识、脱敏规则编码、验证阈值及审批状态，无固定通用单位，需结合项目场景匹配对应字段定义。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且随项目动态更新，要求工具调用需支持多源数据拉取适配，避免硬编码固定数据源。文档结构随项目变化，需插件支持动态解析字段映射表与验证报告，无法依赖固定模板。敏感字段识别与验证环节耗时，工具调用需内置批量处理能力以压缩验证周期。访问审批记录需随脱敏流程同步校验，工具调用需对接审批系统状态接口，防止未授权脱敏数据流入测试环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配多类型脱敏工具调用场景，自动匹配对应函数 |
| `functionCall` | `[{"name":"batch_desensitize","parameters":{"count":"200 条"}}]` | 匹配批量脱敏任务的处理节奏，避免单条调用的性能损耗 |
| 工具调用超时阈值 | 600 秒 | 覆盖复杂项目的多源数据拉取与脱敏验证耗时 |
| 敏感字段匹配阈值 | 0.75–0.85 | 基于业务字段的语义相似度，平衡识别准确率与误报率 |
| 审批状态校验开关 | 开启 | 对接访问审批系统，确保仅通过审批的脱敏任务执行 |

## 容易做错的三处
- 调用脱敏工具时返回的内容未按要求隐藏敏感审批记录字段，原因是未在`functionCall`参数中配置输出过滤规则，导致敏感审批信息被返回。
- 工具调用超时并返回504状态码，原因是未调整工具调用超时阈值，复杂项目的多源数据拉取耗时超过默认限制。
- 脱敏验证结果未按预期输出，原因是未自定义敏感字段匹配阈值，使用默认配置导致误识别或漏识别高风险敏感字段。

## 怎么确认配好了
- 发起单次小批量脱敏测试，检查工具调用返回的`functionCall`结果是否包含正确的脱敏后字段。
- 对接访问审批系统接口，验证工具调用时是否自动校验审批状态，未通过审批的任务无法触发执行。
- 调整敏感字段匹配阈值，对比不同阈值下的识别结果，确认符合业务场景的识别准确率。
- 模拟超时场景，验证工具调用超时阈值配置是否生效，超时后是否触发对应处理逻辑。
