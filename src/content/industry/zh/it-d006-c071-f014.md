# 数据脱敏处理的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自数据库、数据字典、脱敏工具及访问审批系统，按每批项目或单次任务更新。日常产出的文档包含脱敏方案、字段映射表、脱敏验证报告与审批记录，核心字段包括敏感类型标识、脱敏规则编码、验证通过率及审批状态，无统一固定单位，具体字段单位随项目配置调整。数据处理流程围绕敏感字段识别、规则配置与可用性验证展开，核心目标为降低敏感信息暴露风险。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散且按项目更新，要求模型接入环节支持按项目动态关联不同数据源与文档集合。日常文档包含多维度字段，要求配置环节支持敏感字段、脱敏规则与模型参数的绑定映射。高更新频率要求配置流程支持快速迭代调整，无需重复全量初始化。针对测试用例与缺陷分析的场景，配置需要支持模拟不同脱敏规则的测试流程，便于验证合规性。同时，敏感信息处理的高合规风险，要求模型接入配置包含结果校验与异常拦截的参数，避免敏感数据未脱敏直接进入模型上下文。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配脱敏后文档的平均长度，避免超出模型上下文限制 |
| `maxTokens` | 2000–3000 token | 满足脱敏验证报告的生成长度需求，平衡输出效率与内容完整性 |
| `quoteMaxToken` | 1000 token | 限制引用的脱敏文档片段长度，防止上下文过载 |
| `temperature` | 0.2–0.4 | 降低输出随机性，确保脱敏规则执行的一致性与合规性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 为AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径，不是单模型地址 |
| `AIPROXY_API_TOKEN` | 按部署配置填写 | 为AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空，不是应用API Key或模型供应商密钥 |

## 容易做错的三处
- 现象：模型接入后配置的脱敏字段映射为空，无法触发预设脱敏规则。原因：未将字段映射表与模型上下文参数绑定，导致模型无法识别需处理的敏感字段范围。
- 现象：模型生成的脱敏验证报告中出现未脱敏的原始敏感信息。原因：`temperature`参数设置超出合理区间，导致模型生成结果偏离预设脱敏规则，出现执行偏差。
- 现象：重复添加同项目的模型配置后，原有配置被覆盖。原因：未使用项目唯一标识区分配置项，使用相同名称的配置参数导致资源被覆盖，属于常见的同名配置冲突问题。

## 怎么确认配好了
- 检查App/Admin服务端部署的AIPROXY_API_ENDPOINT和AIPROXY_API_TOKEN环境变量，确认AIPROXY_API_ENDPOINT为AI Proxy服务根地址，AIPROXY_API_TOKEN与AI Proxy服务端配置一致且非空。
- 上传单条包含敏感信息的测试数据，触发脱敏流程，核对输出结果中敏感字段是否已按预设规则处理。
- 验证多项目配置的隔离性，确认不同项目的模型配置不会互相覆盖。
- 触发脱敏验证任务，查看系统生成的验证报告是否包含完整的脱敏校验记录。
