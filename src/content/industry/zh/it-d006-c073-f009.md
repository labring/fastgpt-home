# 数据集交付与版本管理的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
这个品类的数据主要来自对象存储、数据仓库、标注平台与客户验收反馈。数据更新节奏通常为每批交付或每版本迭代一次，配套的日常文档包含数据集说明、版本记录、交付清单与验收报告。数据字段一般包含版本号、样本总条数、单样本大小、数据来源标识、交付时间、验收状态等，单位涵盖条、MB、天等，不同批次的字段需保持统一以保证可追溯性。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据集需按版本追溯且需匹配客户验收要求，工具调用时需固定关联对应版本的数据集路径，避免跨版本调用导致数据混用。多批次数据的字段差异需在插件配置中提前校验，防止因字段缺失或格式错误引发交付异常。版本记录需随工具调用同步更新，确保调用日志与版本记录一一对应，便于后续缺陷回溯。同时，交付清单需通过插件自动拉取核对，减少人工核对的耗时与失误，提升交付准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 插件触发时机 | 数据集版本更新后自动触发 | 确保每次版本迭代都同步执行工具调用，避免版本与调用结果不匹配 |
| 字段校验规则 | 校验版本号、样本条数、验收状态必填字段 | 提前拦截字段缺失导致的交付异常 |
| `toolChoice` | 固定为`auto` | 让模型自主选择适配的工具完成数据集交付校验 |
| `functionCall` | 开启强制校验模式 | 确保工具调用严格遵循预设的数据集交付流程 |
| 失败重试次数 | 3次，间隔60秒 | 应对临时网络波动导致的调用失败 |
| 交付清单生成 | 调用工具自动拉取数据集元数据生成 | 替代人工核对，提升交付完整性核对效率 |

## 容易做错的三处
- 插件编辑页面始终显示“未保存”状态，即便点击保存按钮后仍未消失。原因是插件配置与数据集版本绑定的同步逻辑未正确加载，导致页面状态与后台配置不一致。
- 调用数据集交付工具时返回连接拒绝错误，日志显示`connect ECONNREFUSED 172.23.0.2:3001`。原因是目标插件服务未正常启动，或网络策略限制了内部端口访问。
- 工具调用生成的交付清单缺少样本差异说明字段。原因是配置中未开启字段校验规则，未提前校验该字段的必填性，导致遗漏关键交付信息。

## 怎么确认配好了
- 手动触发一次插件调用，核对生成的交付清单是否包含所有预设的必填字段。
- 在FastGPT v4.17.0版本中，查看插件调用日志，确认每次调用都同步更新了对应版本的版本记录。
- 模拟插件调用失败场景，确认系统会按照配置的重试次数与间隔执行重试操作。
- 检查插件配置页面的状态标识，确认保存后状态变为已保存。
