# 文本标注项目的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
文本标注项目的数据主要来自客户提供的原始语料、标注平台产出的标注结果、配套词表以及质检抽样得到的验证结果。日常产出的核心文档包括标注规范细则、待标注样本包、质检报告与问题反馈表。数据更新节奏通常为每日更新或按标注批次同步，核心字段涵盖标注文本内容、实体标签、意图分类结果、质检标记与溯源ID等，与图像标注项目不同，其数据聚焦语义层面的实体与意图关联。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且多批次更新，需要溯源时关联原始语料、标注操作记录与质检结果，因此需明确各来源数据的唯一标识规则。日常文档格式不统一，标注规范、质检报告的字段差异会导致溯源时的匹配难度提升。更新频率的不确定性要求溯源机制支持按批次或时间窗口快速定位数据版本，避免因数据版本混淆引发测试用例失效或缺陷分析偏差。语义类数据的特性要求溯源信息需保留实体与意图的关联细节，仅存储文本本身无法满足完整溯源的需求。

## 配置怎么定
本文适配FastGPT v4.17.0版本，以下配置均基于该版本的界面与参数规则。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配文本标注项目单条样本的平均长度，避免截断核心语义信息 |
| 引用匹配阈值 | 0.75–0.85 | 适配文本语义相似度的常规区间，减少误匹配或漏匹配 |
| 单次召回上限 | 前6条 | 对应质检抽样的常规抽检数量，避免引入过多无关标注数据 |
| 返回溯源字段 | `responseData` 包含标注ID、质检标记 | 覆盖溯源所需的核心标识与验证信息 |
| 详情展示开关 | 开启 | 便于查看标注来源的完整上下文，辅助缺陷分析 |
| `detail` | 开启 | 补充返回标注操作的时间戳与操作人员信息，强化溯源准确性 |

## 容易做错的三处
1. 配置`quoteMaxToken`取值过小，导致引用的标注文本被截断，出现字段为空的现象。原因是未匹配文本标注项目单条样本的平均长度，截断了核心语义信息。
2. 未配置`responseData`返回标注ID字段，在测试用例执行时无法关联原始样本与标注结果，出现溯源失败的报错。原因是未覆盖溯源所需的核心标识信息。
3. 未绑定标注项目专属数据源，在配置变量引用时出现无可选值的现象。原因是未将标注平台的数据源配置为引用来源，导致系统无法识别对应变量。

## 怎么确认配好了
1. 执行单条标注样本的测试用例，检查返回的引用内容是否包含完整的标注文本与关联的质检标记。
2. 触发缺陷分析任务，验证是否能通过溯源ID关联到原始客户语料、标注操作记录与质检报告。
3. 调整`quoteMaxToken`的取值，观察引用内容的截断情况，确认取值匹配当前标注样本的长度范围。
4. 查看配置详情页，确认`responseData`与`detail`的返回字段已勾选所需的溯源信息项。
