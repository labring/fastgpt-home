# 文本标注项目的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
文本标注项目的数据主要来自客户提供的语料、自有标注平台产出的标注结果、行业通用词表以及质检抽样的结果。日常关联文档包括标注规范、样本包、质检报告和问题反馈表。数据更新节奏按日或按标注批次执行，单批次数据包含待标注文本、对应标签体系、标注结果字段及质检标记，核心字段围绕语义实体、意图分类和标签匹配度展开，无额外复杂单位要求。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新频繁，要求模型接入时需支持多源数据的批量适配，配置项需预留数据格式校验规则。日常文档多为非结构化文本，模型配置需针对语义边界、实体识别和意图分类场景优化参数。质检抽样结果作为反馈依据，需在模型测试环节支持按抽样批次导入测试用例，配置需关联质检报告的字段映射逻辑。单批次数据量随标注进度波动，需配置动态适配的上下文长度参数，避免因数据量变化导致调用失败或资源浪费。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配文本标注项目的测试用例与缺陷分析场景：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配文本标注项目的批量样本包长度，避免因上下文溢出导致调用中断 |
| `maxTokens` | 2000–3000 token | 匹配单条标注文本的语义分析需求，覆盖标签解释、实体识别的输出长度 |
| `temperature` | 0.2–0.4 | 降低随机生成概率，保证标签匹配和语义判断的一致性，符合标注规范的统一要求 |
| `quoteMaxToken` | 1500 token | 限制引用质检报告内容的长度，避免冗余信息干扰测试用例分析 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions路径，非单模型地址 | 该变量为App/Admin服务端必需环境变量，需与AI Proxy服务端配置一致且不能为空 |
| `toolChoice` | auto | 支持自动调用工具处理质检抽样结果的字段映射，提升测试用例生成效率 |

## 容易做错的三处
- 新增模型测试时报404错误，日志显示Api response error: /api/core/ai/model/test?model=xxx，可排查项：检查模型ID是否与第三方平台中配置的标识一致，是否匹配对应提供商的模型命名规则。
- 模型调用后返回结果为空或不完整，可排查项：检查`maxTokens`取值是否过小，是否无法覆盖标签解释、实体识别的完整输出长度，是否存在结果被强制截断丢弃的情况。
- 聊天对话框无法切换已配置的AI模型，可排查项：检查是否在模型配置中开启多模型可用权限，是否将目标模型添加至可用模型列表中。

## 怎么确认配好了
- 进入FastGPT模型提供商页面，选择已配置的目标模型，执行测试调用，确认返回状态码为200且无报错信息。
- 导入一批标注样本包作为测试用例，调用模型生成标签匹配结果，核对输出字段与标注规范的要求一致。
- 切换已配置的多个可用模型，确认聊天对话框可正常加载并切换不同模型的调用结果。
- 查看模型调用日志，确认`maxContext`、`maxTokens`等配置参数的实际取值与预设值一致，无异常溢出或篡改。
