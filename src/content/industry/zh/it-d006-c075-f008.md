# 文档站维护的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
本品类的数据主要来自代码仓库提交记录、文档站构建日志、用户反馈工单与版本发布记录。日常产出的文档包含安装指南、API参考、版本迁移说明与常见问题解答，结构固定包含版本标识、操作步骤、示例代码块与接口参数说明。数据更新节奏以周度或每版本发布为周期，核心字段包括文档版本号、最后更新时间、关联的代码分支与用户反馈的异常关键词。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源关联代码仓库与版本发布记录，工作流需绑定对应代码分支与版本标识作为触发条件，避免跨版本的文档校验失效。文档结构固定且包含示例代码块，工作流需配置节点校验示例代码的可执行性，防止无效示例流入。数据更新节奏无固定每日频次，工作流需支持手动触发与版本更新触发两种模式，适配周度或按版本的更新需求。用户反馈的异常关键词需作为校验依据，工作流需关联反馈工单的分类标签，定位文档缺陷的具体位置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按代码提交或版本发布事件触发，或手动触发 | 匹配文档站维护的周度/按版本更新节奏，适配数据来源的更新周期 |
| `variables` | 绑定版本号、代码分支、文档路径变量 | 关联数据来源的代码仓库与版本记录，确保校验环节指向对应版本的文档 |
| `nodeId` | 限定为当前版本文档的关联节点ID | 避免工作流调用非目标文档的节点数据，缩小校验范围 |
| 节点超时时间 | 300–600 秒 | 适配文档示例验证的耗时需求，避免因长示例校验触发超时 |
| 示例代码校验长度 | 500–800 字符 | 匹配文档示例的常规长度范围，过滤过长的无效代码块 |
| 上下文调用上限 | 前 3 条关联反馈工单 | 聚焦当前版本的用户反馈，减少无效数据的干扰 |

## 容易做错的三处
- 工作流导出功能无法正常触发，提示参数缺失。原因是未绑定`variables`中的文档路径变量，导致导出逻辑无法匹配对应文档的存储位置。
- 自动分支节点无法正常执行，流程中断。原因是使用了不支持function call的模型，未在工作流中配置替代的手动触发节点或通用搜索节点。
- 问答环节输出包含未预期的`<think>`标签内容。原因是未在工作流中配置模型输出过滤节点，未关闭模型的原生思考输出开关，且FastGPT v4.17.0之前的版本模型输出处理逻辑存在兼容问题。

## 怎么确认配好了
- 手动触发工作流，确认导出功能可生成对应文档的有效链接或文件。
- 使用不支持function call的模型运行工作流，确认流程能自动跳转至通用搜索节点。
- 拖动工作流画布中的节点，确认FastGPT v4.17.0及以上版本中操作响应无明显延迟。
- 运行模型节点后，检查最终输出内容是否不含未预期的`<think>`标签。
