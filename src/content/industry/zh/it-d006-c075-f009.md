# 文档站维护的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
本品类的数据主要来自代码仓库提交记录、文档站构建日志、终端用户反馈与版本发布记录。日常维护的文档包含安装指南、API接口文档、版本迁移手册与常见问题解答。数据更新节奏以周度或单次版本发布为周期，单篇文档包含依赖版本、接口路径、示例代码、过期标记等字段，无统一固定的单位约束，仅随文档类型对应不同的内容结构。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据特征会对工具调用与插件配置带来多维度约束。数据来源包含代码仓库与构建日志，需要工具调用拉取代码变更、解析构建报错信息，因此需配置对应代码仓库的访问权限与日志解析规则。文档类型多样，不同文档的解析逻辑存在差异，工具调用需支持按文档类型切换处理流程，需通过指定参数触发对应处理逻辑。数据更新节奏固定，工具触发需匹配周度或版本发布的周期，避免过度调用消耗资源。非结构化的用户反馈数据，需要插件完成缺陷分类与定位，需配置对应的模型调用参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配不同文档类型的工具调用需求，让模型自主选择匹配当前任务的插件 |
| `functionCall` | 按文档类型指定函数标识 | 针对API文档、安装文档等不同场景，强制调用对应解析插件 |
| 工具调用超时时间 | 600 秒 | 匹配文档站构建日志的解析周期，避免因日志加载过久导致任务中断 |
| 插件触发阈值 | 前 3 条匹配结果 | 过滤低相关性的文档数据，聚焦核心维护内容 |
| 上下文窗口大小 | 8000 token | 适配单篇文档的平均长度，确保解析时能完整获取文档内容 |
| FastGPT 版本 | FastGPT v4.17.0 | 该版本修复了工具调用的跨域与参数传递问题，适配当前配置需求 |

## 容易做错的三处
- 现象：工具调用时返回模型不支持指定参数的报错，状态码为400。原因：未结合文档站维护的场景选择适配的模型，错误使用了仅支持基础对话的模型。
- 现象：第三方调用工具API时返回跨域拦截提示，无法正常拉取文档数据。原因：未在FastGPT配置中添加对应第三方调用的跨域白名单，未匹配文档站维护的外部调用需求。
- 现象：工作流调用文档解析插件后返回空结果，未获取到代码仓库的变更记录。原因：未配置代码仓库的访问权限，导致插件无法拉取对应数据，未匹配本品类的数据来源特征。

## 怎么确认配好了
- 触发一次工具调用，查看返回结果是否包含对应文档的解析内容，核对是否与实际文档结构一致。
- 调用跨域测试接口，确认第三方请求可以正常访问工具API，无拦截提示。
- 查看工具调用的日志，确认`toolChoice`或`functionCall`参数被正确传递，模型调用了匹配的插件。
- 模拟版本发布后的触发流程，确认工具会按预设的周度或版本周期自动执行，无异常中断。
