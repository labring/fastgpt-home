# 文档站维护的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自代码仓库、文档站构建日志、用户反馈与版本发布记录，日常维护的文档包含安装文档、API文档、迁移指南与FAQ。数据更新频率为周度或随版本发布同步，文档结构按类型区分：API文档包含接口路径、请求参数与返回字段，FAQ包含标准化问题与对应解答，安装文档包含分步操作步骤。数据字段随文档类型变化，无统一固定单位，需按文档内容提取对应信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源包含代码与构建日志，需模型适配技术类文本的结构化解析；周度或版本级的更新频率，要求配置支持批量向量更新，避免单文件上传的低效操作。不同类型的文档结构差异，要求模型接入时需适配不同的字段提取规则，例如从API文档中提取接口参数用于测试用例生成，从FAQ中整理常见问题用于缺陷分析。此外，用户反馈与版本发布记录的非结构化特征，需模型具备语义理解能力，将其转化为可用于缺陷排查的测试用例，同时需保障配置的可复用性，适配不同文档站的内容规模。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000-12000 token | 文档站的单篇文档长度普遍较长，需覆盖完整的上下文信息以支撑测试用例生成与缺陷溯源 |
| `maxTokens` | 2000-4000 token | 满足测试用例、缺陷分析结果的生成长度需求，避免截断关键技术表述 |
| `temperature` | 0.2-0.4 | 保障生成内容的准确性与一致性，适配技术文档的严谨性要求 |
| `quoteMaxToken` | 1500-2000 token | 保留足够的原文引用片段，用于缺陷分析时溯源文档原文内容 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions，不得指向 VLLM/Ollama/Xinference 等单模型地址 | 为 App/Admin 服务端必需配置的环境变量，实现模型请求的正确转发，适配本地或云端的 AI Proxy 部署环境 |
| `AIPROXY_API_TOKEN` | 与 AI Proxy 服务端配置一致的管理员 Token，不能为空 | 为 App/Admin 服务端必需配置的环境变量，保障 AI Proxy 接口的访问安全，避免未授权调用 |

## 容易做错的三处
- 批量触发向量模型重新训练时仅更新单份文件，未覆盖全量文档站数据，原因是未配置批量训练的触发规则，仅启用了单文件上传的更新逻辑。
- 接入模型后返回404状态码，无响应体内容，排查项：检查`AIPROXY_API_ENDPOINT`是否为 AI Proxy 服务的根地址，未附加 /v1 或 /chat/completions，未指向 VLLM/Ollama/Xinference 等单模型地址。
- 本地部署模型无法基于文档内容生成回答，仅返回通用回复，原因是`maxContext`配置值过小，无法加载完整的文档解析数据，导致模型无法获取上下文参考信息。

## 怎么确认配好了
- 上传一份测试用的API文档，触发向量更新流程，检查FastGPT v4.17.0的构建日志中是否存在批量向量训练的成功记录。
- 发起模型调用请求，核对返回结果中是否包含文档站原文的引用片段，确认引用长度符合`quoteMaxToken`的配置范围。
- 调整`temperature`参数至0.1，生成的测试用例是否保持技术表述的一致性，无冗余或错误的生成内容。
- 检查 App/Admin 服务端的`AIPROXY_API_TOKEN`环境变量配置正确，与 AI Proxy 服务端配置一致且非空。
