# 日志平台与可观测性的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据包含结构化日志条目、分布式链路追踪Span信息、时序监控指标样本。数据来源为应用埋点SDK、集中式日志系统、分布式追踪平台与时序指标系统，更新频率为每日或随应用版本迭代。配套日常文档包括日志采集规范、链路追踪说明、指标维度字典、看板配置记录，字段包含时间戳、服务标识、日志级别、调用链ID、指标值与对应单位，指标单位随类型变化，如请求量为“次”、延迟为“毫秒”。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入时需适配不同格式的日志、链路与指标数据，配置环节需明确数据关联的核心字段（如调用链ID）以实现上下文聚合。数据随版本迭代更新，需确保模型调用的上下文规则与最新的采集规范、指标字典保持一致。单条日志与链路数据的token占用量较高，需限制单次输入的上下文总长度，避免超出模型支持范围。测试用例与缺陷分析依赖完整的上下文证据，配置中需保留足够的关联信息，同时避免冗余数据干扰模型推理。

以下配置项适配FastGPT v4.17.0版本的日志平台与可观测性场景。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions 路径 | 为 AI Proxy 服务端配置的合法根地址，确保模型调用路由正确 |
| `AIPROXY_API_TOKEN` | 与 AI Proxy 服务端配置一致的管理员 Token，不能为空 | 用于 AI Proxy 服务端的身份验证，与模型渠道配置的供应商凭证无关 |
| `maxContext` | 8000–12000 token | 平衡日志与链路数据的上下文完整性与模型推理效率，适配单批次缺陷分析的场景 |
| `maxTokens` | 2000–3000 字符 | 限制模型输出长度，避免缺陷分析结果过长超出展示或存储阈值 |
| `quoteMaxToken` | 1500 token | 保留足够的原始日志与链路片段作为引用依据，支撑测试用例的追溯需求 |
| `temperature` | 0.3–0.5 | 降低输出随机性，确保缺陷分析与测试用例生成的结果符合运维场景的严谨性要求 |

## 容易做错的三处
- 配置`AIPROXY_API_ENDPOINT`时误填单模型服务地址（如 VLLM/Ollama/Xinference 地址）或附加了 /v1 等路径，导致 AI Proxy 服务启动校验失败或模型调用异常 |
- 升级版本后未重新校验上下文相关参数，导致上下文长度超出新版模型的支持阈值，表现为知识库查询能返回数据但模型无输出，符合常见的场景问题表现。
- 未设置`quoteMaxToken`的合理取值，导致引用的日志片段被截断，无法完整支撑缺陷定位，表现为测试用例中缺少关键的链路关联信息。

## 怎么确认配好了
- 检查 App/Admin 服务端启动校验日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`已正确配置且非空 |
- 导入单条测试用例的日志与链路数据，触发模型推理，检查输出结果是否包含关联的调用链ID与日志级别信息。
- 调整`temperature`参数的取值，观察模型输出的一致性，确认结果符合运维场景的严谨性要求。
- 查看模型调用的日志记录，确认`maxContext`与`quoteMaxToken`的取值未触发模型的token限制报错。
