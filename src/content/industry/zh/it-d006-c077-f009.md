# 机房巡检与环境监控的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自机房动环监控系统、门禁管控平台、UPS电源监控设备与视频巡检终端。日常产出巡检记录表、温湿度统计台账、告警事件日志、值班交接日志等文档。数据更新节奏多为实时或按日归档，字段包含设备编号、监测数值（如温湿度℃、电压V）、告警等级、触发时间等，核心围绕机房物理环境与设施运行状态展开。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据接入要求工具调用需支持对接不同类型的第三方监控插件，需提前配置对应数据源的鉴权参数。实时更新的监测数据要求工具调用的超时阈值适配短延迟场景，避免因等待超时丢失最新告警信息。结构化的环境与设施字段需明确映射规则，确保AI调用工具时能准确提取对应数值。巡检类文档的非结构化内容需搭配文档解析插件，才能完成字段提取与异常判断。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配机房巡检场景下的动态工具调用需求，自动选择匹配当前告警或巡检任务的插件 |
| 工具调用超时 | `30 秒` | 机房实时监测数据的延迟容忍度较低，超时过长会导致告警响应滞后 |
| `functionCall` | `enabled` | 强制启用结构化工具调用，避免AI直接生成非结构化回答导致的巡检信息遗漏 |
| 工具调用重试次数 | `1–2 次` | 机房巡检场景下的临时网络波动较为常见，少量重试可提升调用成功率，过多重试会延误告警处理 |
| 插件鉴权超时 | `60 秒` | 部分老旧监控设备的鉴权流程耗时较长，合理延长鉴权超时可避免正常调用被误判为失败 |
| 最大上下文 | `4000 token` | 适配机房巡检相关的多源数据拼接需求，避免因上下文溢出导致工具调用失败 |

## 容易做错的三处
- 现象：AI未触发工具调用，直接生成无实时数据支撑的巡检报告或告警分析内容。原因：未启用`functionCall`参数或工具调用开关，导致AI无法识别需要调用插件拉取机房实时数据的场景。
- 现象：工具调用失败，界面返回「调用超时」提示或返回空的监测数据结果。原因：未根据机房监测设备的类型调整超时阈值，设置的超时时间过短，无法完成多源数据的拉取与解析。
- 现象：调用插件后返回的字段与巡检表不匹配，出现数值单位错误或关键字段缺失。原因：未配置插件与机房监测数据的字段映射规则，直接使用默认参数调用插件，导致数据格式与巡检文档不兼容。

## 怎么确认配好了
- 手动触发模拟机房告警场景，查看AI是否自动调用对应监控插件拉取实时数据。
- 进入FastGPT的插件配置页面，确认所有机房数据源的鉴权参数均已正确填写且无格式错误。
- 查看工具调用日志，确认每次触发的工具调用均能返回符合机房监测字段规范的结果。
- 模拟临时网络波动场景，验证工具调用的重试机制是否正常触发并完成调用。
