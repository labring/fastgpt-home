# 机房巡检与环境监控的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据主要来自动环监控系统、门禁控制器、UPS监控设备与视频巡检终端，更新节奏多为实时或每日归档。日常产出的文档包含巡检记录表、温湿度统计台账、告警事件日志、值班交接日志，数据字段通常包含设备编号、采集时间、温湿度数值（单位为℃与%RH）、告警等级、通行记录ID等，单条数据体量较小但批量数据总量随机房规模扩大而增加。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据来源分散且更新节奏灵活，要求引用溯源环节支持跨多系统数据的关联匹配。日常文档以结构化表格与时序日志为主，需支持按设备编号、采集时间等字段精准检索，不依赖全文模糊匹配。高时效性的实时数据要求溯源时可限定时间范围，避免引用过期的历史记录。单条数据体量小但批量总量大，需限制单次召回的结果条数，防止返回冗余信息干扰分析。同时，巡检与告警数据的关联性强，溯源时需同时关联设备状态与事件时间线，确保引用的完整性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 机房巡检与告警数据单条记录体量较小，批量召回后需控制总token占用，避免超出模型上下文限制 |
| `responseData` | 开启 | 巡检日志、温湿度记录等源数据需完整展示，支撑缺陷分析的溯源验证 |
| `detail` | 开启 | 需召回结构化字段的详情，如设备编号、采集时间，确保引用的信息可被精准核对 |
| 单次搜索上限 | 前6条 | 机房单起异常事件的关联记录通常不超过6条，过多结果会干扰分析逻辑 |
| 时间范围限定 | 最近7天 | 符合日常巡检与告警的复盘周期，避免引用过期的历史数据 |
| 分块分隔符 | 按标题层级分割 | 适配巡检表、告警日志的文档结构，提升检索的精准度 |

## 容易做错的三处
- 现象：页面嵌入后未展示引用内容，或API调用返回的结果中无引用字段。原因：未开启`responseData`配置项，或配置参数未正确同步到嵌入或API调用链路。
- 现象：动态传入知识库搜索参数后，未召回对应巡检或告警数据。原因：未按巡检数据的结构化字段配置检索匹配规则，导致搜索范围与目标数据不匹配。
- 现象：召回的引用内容包含大量无关的温湿度记录。原因：未设置合理的时间范围限定或单次搜索上限，导致召回了过期或冗余的数据。

## 怎么确认配好了
- 发起一次针对已知机房告警事件的查询，检查返回结果中是否包含对应的告警日志与巡检记录。
- 查看嵌入页面或API返回的内容，确认是否展示了引用来源的详细信息。
- 调整检索的时间范围，验证召回结果是否随参数变化而正确更新。
- 测试动态传入知识库参数的场景，确认是否能精准召回对应机房设备的相关数据。
