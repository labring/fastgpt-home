# 机柜上架与布线的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自DCIM系统、资产管理系统、网络拓扑图与客户施工工单。日常产出的文档包含上架申请单、机柜布线图、端口标签表与施工记录，字段涵盖机位编号、线缆规格、端口标识、施工时间等。数据更新频率为每单或每日，随施工流程推进同步更新，未完成的上架与布线任务数据会保持待更新状态，已完成的任务数据归档留存。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据来源要求工具调用需兼容不同系统的API响应格式，比如DCIM返回的机位数据与资产系统的设备清单格式存在差异，插件需支持自定义字段映射。按单更新的节奏要求插件触发需绑定施工任务节点，避免无效拉取。混合结构化与可视化文档的场景，工具需支持文本解析与图像信息提取的组合调用，适配布线图的机位校验需求。端口标签表的固定字段要求，工具入参需严格匹配机位编号、端口标识等字段，否则会导致调用失败。本内容适配FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | 自动 | 适配多源异构数据的工具调用场景，无需手动指定工具类型 |
| `functionCall` | 开启 | 支持将结构化数据转换为可分析的文本格式，处理上架申请单、端口标签表的字段提取 |
| 单次工具调用超时 | 600–900 秒 | 匹配机柜上架与布线施工的常规耗时区间，避免中途中断调用 |
| 工具返回结果上限 | 前 8 条 | 适配单施工任务关联的DCIM、资产系统数据量，过滤冗余信息 |
| 入参格式校验 | 启用 | 匹配端口标签表的固定字段规则，防止因字段缺失或格式错误导致调用失败 |
| 上下文窗口 | 4000–8000 token | 容纳机柜布线图、网络拓扑图的解析文本与施工记录内容 |

## 容易做错的三处
- 现象：工具调用返回空结果，或连续多次未执行预设的缺陷分析逻辑。原因：未将插件触发绑定至施工任务的提交节点，导致插件拉取的数据与当前任务不匹配。
- 现象：工具返回的搜索结果为array<object>格式，无法直接用于缺陷分析。原因：未启用`functionCall`配置，未对结构化数据进行格式转换，导致原始数据无法被解析为可读文本。
- 现象：调用工具插件时，端口标签表的入参变量无法添加，或返回的布线图信息显示不全。原因：未开启入参格式校验开关，或未指定匹配端口标识、机位编号的固定字段，导致入参格式不兼容。

## 怎么确认配好了
- 提交一条测试施工任务，触发插件调用，检查工具是否返回与任务关联的DCIM、资产系统数据。
- 输入一条包含array<object>格式的测试数据，检查工具是否返回可直接用于分析的文本内容。
- 尝试添加端口编号、机位编号作为入参变量，检查是否能正常保存并调用。
- 查看插件调用日志，确认未出现超时或格式不匹配的报错信息。
