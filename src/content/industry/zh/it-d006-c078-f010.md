# 机柜上架与布线的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
典型主体为IDC运维工程师、网络工程师、设备实施人员，日常产出的文档包括上架申请单、机柜布线图、端口标签表、施工记录。数据来源覆盖DCIM系统、资产管理系统、网络拓扑图、客户服务工单。数据更新频率为每单/日，核心字段包含机位编号、线缆类型、端口对应关系、施工日期，部分字段为文本标签类内容，无统一标准化单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
机柜上架与布线的业务数据来源分散，涉及DCIM、资产系统等多套异构系统，因此引用溯源需关联唯一工单编号或设备序列号，确保不同来源的引用可交叉验证。日常文档包含结构化表格与非结构化图纸，溯源环节需同时支持结构化字段匹配与图纸片段的位置锚定。数据更新随施工单实时变动，过长的历史上下文可能包含过期数据，因此需限制引用的时间范围与token总量，避免引入过时的机位规划或布线信息。此外，核心字段无统一单位，溯源时需保留原始字段的文本标签，不可强行标准化转换。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.7–0.85 | 匹配机柜布线图的结构化端口字段与测试用例的缺陷描述，避免低关联的历史工单干扰 |
| `quoteMaxToken` | 800–1200 token | 限制单轮引用的上下文总量，适配机柜布线文档的单页图纸或表格长度，FastGPT v4.17.0版本默认值为1000 token，可按实测标定 |
| 单次搜索上限 | 前6条 | 匹配机柜上架的核心设备数量，避免引入无关的其他机柜数据 |
| `responseData` | 保留机位号、端口编号、施工日期字段 | 映射端口标签表的核心字段，确保溯源信息可直接关联原始施工记录 |
| `detail` | 开启 | 展示引用片段的具体位置，如机柜布线图的第3页第2段，帮助定位缺陷来源 |

## 容易做错的三处
- 现象：设置最低相关度阈值为1后，检索结果仍包含大量低关联的非目标机柜数据。原因：未结合机柜编号、端口编号等结构化字段做二次过滤，仅依赖全局语义相似度匹配，无法区分不同机柜的布线信息。
- 现象：引用来源显示为空白或无有效链接。原因：未配置`responseData`参数映射端口标签表的核心字段，导致溯源时无法提取有效关联信息。
- 现象：检索响应超时或返回内容截断。原因：未限制`quoteMaxToken`的取值，导致上下文长度超过系统上限，触发超时或截断逻辑。

## 怎么确认配好了
- 生成模拟的端口接错缺陷测试用例，查看响应是否关联对应机柜的布线图与端口标签表的引用片段。
- 检查响应中的溯源信息是否包含机位编号、施工日期等核心字段，且可直接关联原始施工记录。
- 调整相似度阈值至0.7，验证低关联的非目标机柜数据是否被过滤。
- 查看单轮响应的token消耗，确认未超过`quoteMaxToken`的配置值，无超时或截断情况。
