# 桌面终端支持的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自终端管理平台、资产系统、用户报障渠道、软件仓库。日常产出的文档包含终端故障单、装机清单、软件安装记录、远程协助记录，数据字段包含终端唯一标识、故障类型、处理节点、软件版本、外设型号等。数据更新节奏为每日同步或随用户请求实时更新，无固定批量更新周期。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需对接多类系统接口，需在编排时配置多数据源的变量绑定规则。日常文档结构不统一，不同终端的故障单、装机清单字段存在差异，需在工作流中设置字段映射节点适配格式。数据更新节奏灵活，工作流需支持按需触发或定时同步，避免因数据滞后导致排查偏差。故障复现与排查环节耗时较长，工作流需拆分步骤并设置分支判断，适配不同排查结果的流转逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 多数据源变量绑定 | 按终端ID、故障类型映射字段 | 适配分散的终端管理、资产系统数据来源 |
| 字段映射规则 | 按故障单标准模板补全缺失字段 | 解决日常文档结构不统一的问题 |
| 工作流超时阈值 | 600–1200 秒 | 适配故障排查的耗时特性 |
| 输出过滤配置 | 仅保留工具返回结果，隐藏input和response字段 | 适配终端故障排查的简洁输出需求 |
| 最大上下文长度 | 800–1500 字符 | 适配终端故障单的内容长度 |
| `variables`绑定 | 绑定终端日志、软件版本等核心字段 | FastGPT v4.17.0 版本原生支持该配置，适配多数据源流转 |
| `nodeId`绑定 | 指定排查节点的唯一标识 | 用于精准控制工作流分支跳转逻辑 |

## 容易做错的三处
- 现象：工作流中配置的HTML输出节点未在界面展示，直接执行后续分支。原因：未通过`variables`绑定HTML内容的输出参数，节点未触发渲染逻辑。
- 现象：工作流整体运行耗时超出预期。原因：未按需关闭非必要的跨系统接口调用，或超时阈值设置过短导致重复重试。
- 现象：工具调用完成后，回答中仍显示知识库搜索的input和response字段。原因：未配置输出过滤规则，或规则未限定仅保留工具返回的故障排查结果。

## 怎么确认配好了
- 手动触发一条模拟终端故障工单的工作流，检查HTML输出节点是否正常渲染内容。
- 查看工作流运行日志，确认多数据源变量绑定的字段映射无缺失。
- 调用工具节点后，检查最终输出是否仅包含排查结果，无冗余的input和response字段。
- 模拟高频率的终端故障请求，验证工作流的超时阈值是否适配运行节奏。
