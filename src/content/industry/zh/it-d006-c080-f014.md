# 桌面终端支持的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自终端管理平台、资产系统、用户报障渠道与软件仓库。日常处理的文档包含终端故障单、装机清单、软件安装记录、远程协助记录，每条记录包含设备编号、故障现象、操作步骤、处理结果等字段。数据更新频率为每日批量同步或随每一次终端运维请求实时更新，无固定统计周期，仅随实际运维操作产生新数据，数据格式以非结构化文本为主，部分字段为标准化设备编号与操作标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且格式多样，导致模型接入时需要配置统一的字段映射规则，才能将不同系统的终端数据整合为模型可识别的输入。更新频率灵活且实时性要求高，需要适配动态上下文长度，避免因单次请求数据量过大超出模型的处理上限。日常文档多为非结构化文本，需配置合适的上下文截断参数，确保故障现象、排查步骤等关键信息不被丢失。同时，桌面终端支持的处理流程依赖快速响应，模型调用的配置需匹配运维工作的时效要求，防止因等待过久导致工单积压。

## 配置怎么定
在FastGPT v4.17.0版本中，以下配置项可直接在模型接入页面完成设置；`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`需作为App/Admin服务端环境变量配置，不得在模型接入页面填写：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配桌面终端故障单、远程协助记录的常规文本长度，避免上下文溢出导致分析中断 |
| `maxTokens` | 2000 token | 控制单轮回复长度，匹配运维工程师快速获取排查结论的信息需求 |
| `quoteMaxToken` | 1000 token | 限制引用的终端日志、装机清单等文档的最大长度，防止冗余信息干扰核心分析 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具，适配故障排查中可能需要的终端操作验证场景 |
| `temperature` | 0.3–0.5 | 降低回复随机性，确保故障分析结论的准确性与一致性 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的非空管理员Token | 作为App/Admin服务端环境变量，完成AI Proxy服务的身份验证，防止未授权访问导致的请求失败 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions路径 | 作为App/Admin服务端环境变量，完成AI Proxy服务的基础接入配置，确保请求路由正确 |

## 容易做错的三处
- 排查项：模型调用返回结果为空或未包含预期的思维链中间步骤时，检查`maxContext`参数配置是否适配当前处理的文本长度
- 排查项：代理请求返回401未授权错误时，检查`AIPROXY_API_TOKEN`是否为与AI Proxy服务端配置一致的非空管理员Token，且已作为App/Admin服务端环境变量配置
- 排查项：代理请求无法正常转发时，检查`AIPROXY_API_ENDPOINT`是否为AI Proxy服务的根地址，未附加/v1或/chat/completions等路径，且已作为App/Admin服务端环境变量配置

## 怎么确认配好了
- 执行测试请求，检查返回结果的字段完整性，确认关键故障信息未被上下文参数截断。
- 验证代理连接状态，使用指定的API调用工具发起请求，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`作为App/Admin服务端环境变量的配置可正常完成
- 调整`temperature`参数并发起多轮测试，确认回复的随机性符合预设的分析严谨性要求。
- 切换不同的模型渠道，检查配置是否生效，确认工具调用的设置符合故障排查场景。
