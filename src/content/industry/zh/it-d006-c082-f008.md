# 渠道归因与线索分发的测试用例与缺陷分析：工作流编排

本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
这个品类的典型数据来自广告平台、CRM系统、归因SDK与表单系统，日常维护的文档包括归因规则、线索分发表、渠道报表与异常核对单。数据更新频率通常为日度或周度，核心字段包含渠道标识、线索ID、归属销售账号、转化时间与参数校验标记等，不同来源的数据字段格式存在差异，需在处理前做统一适配。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的接入要求工作流需配置多个异构数据源对接节点，避免单一节点的兼容性问题。数据更新的低频特性要求工作流支持定时触发与事件触发两种模式，适配不同的业务节奏。核心文档的复用需求要求工作流将归因规则、线索分发表等配置绑定为全局变量，减少重复配置。最耗时的渠道参数核验、重复线索去重与销售归属确认环节，需通过工作流自动化完成，同时需设置异常检测节点，避免出错导致渠道ROI失真、销售争议或预算错配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发时机 | 按日定时触发 / 按新线索事件触发 | 数据更新频率为日/周，且线索实时产生 |
| `variables` 绑定 | 绑定归因规则、线索分发表为全局变量 | 日常工作文档包含归因规则、线索分发表，需在工作流中复用配置 |
| `nodeId` 分配 | 为重复线索去重节点分配唯一`nodeId` | 需精准定位该环节的执行日志与报错信息 |
| 单次校验条目数 | 设为`1000 条` | 避免单节点处理数据量过大导致超时 |
| 超时阈值 | 设为`300 秒` | 最耗时环节为渠道参数核验、重复线索去重，需避免工作流阻塞 |
| 输出格式 | 输出包含渠道ID、线索归属的标准化JSON | 日常需生成渠道报表、异常核对单，需统一字段结构 |

## 容易做错的三处
- 工作流中AI模型选项为空，无法选择初始化模型。原因是未在全局配置中绑定对应AI服务，导致节点可调用的模型列表未加载。
- 工作流文本内容提取节点返回空JSON结果。原因是未正确配置`variables`绑定待提取的原始线索数据字段，导致节点无有效输入内容。
- 新建问题分类节点使用初始化AI模型时保存报错，切换模型后恢复正常。原因是初始化模型的权限配置未同步至工作流节点，切换模型后覆盖了权限配置。

## 怎么确认配好了
- 运行工作流后，检查`variables`绑定的归因规则是否被正确读取，可在节点日志中查看加载的配置内容。
- 触发测试用例，模拟多渠道线索提交，验证重复线索去重节点的`nodeId`是否被正确记录，可通过节点执行详情查看。
- 模拟渠道参数异常的测试数据，验证超时阈值是否生效，可通过调整测试数据的处理时长确认触发逻辑。
- 导出工作流运行结果，核对输出字段是否与渠道报表、异常核对单的要求一致。
