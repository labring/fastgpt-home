# 渠道归因与线索分发的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自广告平台、CRM系统、归因SDK与表单系统。日常维护的文档包括归因规则配置表、线索分发表、渠道效果报表与异常核对单。数据更新节奏以日度或周度为主，单份数据集包含渠道标识、线索唯一ID、转化时间戳、归属销售账号、预算分配节点等字段，字段单位随对应业务系统的原生配置调整，无统一固定标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征会对模型接入与配置环节带来多重约束。首先，数据来源分散且字段无统一标准，要求配置环节支持多数据源的字段映射规则，避免因字段格式差异导致模型解析失败。其次，数据更新以日度或周度为主，模型批量调用需适配非实时调度场景，不宜设置过短的超时阈值。日常维护的文档多为结构化表格，模型输入需优先适配结构化数据解析，需配置合理的上下文长度参数以容纳完整的归因规则与线索列表。临时异常核对单的动态数据需支持快速加载，模型调用需允许临时调整参数以适配临时校验需求。此外，该品类的核心耗时环节为渠道参数核验、重复线索去重与销售归属确认，模型接入需支持快速校验与批量修正，避免因处理耗时过长影响业务节奏。出错后果包括渠道ROI失真、销售归属争议与预算错配，模型调用需确保结果的准确性与一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多份结构化归因文档与线索列表的批量输入需求，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 满足渠道归因规则解析、线索去重逻辑的输出长度要求，避免截断关键判断依据 |
| `temperature` | 0.1–0.3 | 降低归因判断的随机性，确保渠道归属与销售分配的结果一致性 |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000（请勿附加/v1或/chat/completions等路径） | 为App/Admin服务端配置的AI Proxy服务根地址，确保模型请求可正常路由至AI Proxy服务 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token，且不能为空 | 作为AI Proxy服务的鉴权凭证，与服务端配置一致以完成校验，避免未授权访问 |

## 容易做错的三处
- 现象：在渠道归因模块的模型选择下拉框中仅显示部分大模型，无法找到已通过One API接入的GLM系列模型。原因：未在FastGPT的模型接入配置中开启对应渠道的适配开关，或未将归因模块的模型调用范围限定为已接入的全量模型。
- 现象：批量处理周度线索数据时出现模型调用超时错误，返回状态码504。原因：设置的`maxContext`参数过小，导致批量数据无法完整加载，或超时阈值设置过短，无法适配周度数据集的解析耗时。
- 现象：无法在渠道归因模块中选择未通过One API接入的Embedding模型用于线索字段向量化。原因：未单独配置Embedding模型的接入信息，仅配置了对话模型的调用参数，导致Embedding模型无法被模块识别。

## 怎么确认配好了
以下核对动作适用于FastGPT v4.17.0版本。
- 手动导入一份小型归因规则文档与10条测试线索，触发模型调用，检查返回的渠道归属结果与预设规则是否匹配。
- 查看模型调用日志，确认服务端配置的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`未出现拼写错误，无401或403报错。
- 调整`maxContext`参数为不同区间，导入批量数据，检查是否出现上下文溢出或截断问题，确认取值适配当前业务数据量。
- 开启批量任务调度测试，验证模型调用可按日度或周度节奏自动触发，无重复执行或遗漏任务的情况。
