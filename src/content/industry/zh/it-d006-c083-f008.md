# 游戏内容合规自查的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
本品类数据主要来源于游戏文本、美术资源、剧情脚本及监管公开要求，更新节奏为每版本或每活动周期。日常产出的文档包括内容自查表、敏感内容修改记录、用户协议、合规评审纪要，字段包含内容片段、合规校验标签、修改状态、评审意见等，无固定统一格式，随项目调整。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据输入要求工作流支持文本、文件等多类型节点接入，适配游戏文本与美术资源的混合校验场景；高频更新节奏要求工作流可绑定版本更新、活动上线等触发条件，无需重复配置；非标准化文档结构要求工作流适配动态`variables`解析，兼容不同格式的自查表与评审纪要；长链路的校验-修改-评审流程，要求工作流支持节点间的状态传递与失败分支跳转，覆盖争议内容的二次校验环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按版本节点触发，或绑定`variables`中的版本号参数 | 匹配本品类按版本/活动更新的节奏，避免手动触发遗漏 |
| 输入节点类型 | 文本节点+文件上传节点 | 覆盖游戏文本、美术资源等多源数据输入需求 |
| 全局变量存储方式 | 按会话存储`variables` | 适配单次合规自查流程的状态传递，保留当前版本的校验记录 |
| 失败分支配置 | 跳转至人工审核节点，超时时间设为600秒 | 覆盖争议内容无法自动校验的场景，匹配合规流程的人工评审环节 |
| 节点参数绑定 | 关联`nodeId`对应的上下文变量 | 确保每个校验节点的结果可准确传递至后续修改或评审环节 |
| 调试模式配置 | 开启节点输入输出日志 | 便于排查参数传递异常问题，适配FastGPT v4.17.0的调试功能 |

## 容易做错的三处
- 现象：工作流作为工具调用时，上传的文件无法正确传递文件链接至下游节点。原因：未在输入节点中配置文件链接提取逻辑，直接使用原始上传参数导致链路断裂。
- 现象：设置全局变量后，下游节点调试时报输入为空。原因：未将`variables`中的变量正确绑定至下游节点的输入参数，或变量更新未同步至全局上下文。
- 现象：工作流未按预期在版本更新时触发。原因：触发方式配置为手动触发，未绑定版本更新的事件节点，导致流程无法自动启动。

## 怎么确认配好了
- 上传一份游戏剧情脚本文件，触发工作流运行，检查输入节点是否正确读取文件内容。
- 在工作流中配置全局变量，在下游节点中调用`variables`参数，验证变量值是否正确传递。
- 模拟校验失败场景，检查工作流是否跳转至人工审核节点。
- 检查工作流的触发配置，确认绑定了版本更新或活动上线的触发条件。
