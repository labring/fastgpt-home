# 游戏内容合规自查的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
本品类数据来自游戏研发阶段的文本、美术资源、剧情脚本，以及监管公开的合规要求。日常维护的文档包括内容自查表、敏感内容修改记录、用户协议、合规评审纪要，更新节奏为每版本或每活动上线前。数据字段包含内容类型、自查项编号、修改痕迹、评审结论等，无统一固定单位，随具体自查项的要求调整。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源多模态的数据来源要求插件需兼容文本、美术元数据的解析格式，否则无法覆盖全量自查内容；高频更新的节奏要求工具调用的配置需支持快速调整，避免因配置冗余导致版本更新延迟；多样的日常文档结构要求插件支持自定义字段映射，适配不同团队的自查表格式；缺陷分析需关联修改记录与评审意见，要求工具调用支持上下文关联检索，否则无法快速定位合规问题的根源。

## 配置怎么定
本页面的配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `"function"` | 明确指定调用合规校验工具，避免模型自主选择无关工具 |
| `functionCall` | 仅调用合规校验相关的预定义函数 | 确保工具调用聚焦于合规检查，不执行无关操作 |
| 单次工具调用超时时间 | `600 秒` | 合规校验需处理多份游戏文本与美术元数据，耗时较长 |
| 单次工具调用处理字符数 | `800–1200 字符` | 适配游戏脚本单段自查内容的常规长度，避免截断关键信息 |
| 失败重试间隔 | `60 秒` | 给临时资源恢复留出足够时间，降低重试失败概率 |
| 失败重试次数 | `3 次` | 合规校验失败可能源于临时网络或资源问题，重试可降低误判率 |

## 容易做错的三处
- 现象为插件处理上传的游戏文本语料后返回空结果，原因是未配置适配游戏脚本格式的解析规则，导致语料无法被正确识别。
- 现象为调用API后无法获取知识库关联的合规文档列表，原因是未开启工具调用的上下文返回配置，未将文档关联信息纳入返回字段。
- 现象为替换文档解析工具后无法正常读取美术资源元数据，原因是未修改对应插件的格式适配配置项，导致新工具与现有校验逻辑不兼容。

## 怎么确认配好了
- 上传一份测试用的游戏剧情脚本，触发工具调用，检查是否返回合规校验结果，确认工具被正常调用。
- 调用对应API，检查返回结果中是否包含文档关联信息，确认上下文返回配置生效。
- 替换文档解析工具后，上传美术资源元数据文件，检查是否能正常解析并纳入合规校验，确认格式适配配置生效。
- 模拟工具调用失败场景，检查是否触发预设的告警与重试机制，确认失败处理配置生效。
