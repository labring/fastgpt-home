# 游戏内容合规自查的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自游戏研发阶段的剧情脚本、角色台词、弹窗文案等游戏文本，以及角色立绘、场景美术等美术资源，同时结合监管公开的合规要求生成内容自查表、敏感内容修改记录、用户协议、合规评审纪要等文档。数据更新随游戏版本迭代或活动上线节奏进行，每版本或每活动更新一次，包含合规校验标签、修改版本号、评审意见等结构化字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据随版本或活动高频更新，需适配可变长度的上下文输入，避免因上下文溢出导致校验中断。数据包含文本与美术两类资源，需同时支持文本与视觉模型接入。日常文档多为结构化自查表与评审纪要，需保留关键校验字段的上下文关联。合规校验对结果准确性要求高，需平衡模型生成的灵活性与校验结果的严谨性，同时需配置稳定的API接入参数以避免校验流程中断影响版本上线节奏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | 8000–12000 token | 适配游戏剧情文本与合规评审纪要的上下文长度，避免校验时丢失关键历史校验记录 |
| `maxTokens` | 2000–3000 token | 覆盖单轮合规校验的输出需求，确保完整返回修改建议与缺陷标记 |
| `vision` | 开启 | 支持对角色立绘、场景美术等资源的合规校验，覆盖文本外的美术数据类型 |
| `temperature` | 0.2–0.4 | 降低生成结果的随机性，提升合规校验结果的一致性与准确性 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions路径，不得使用VLLM/Ollama/Xinference等单模型服务地址 | 为AI Proxy服务的根地址，保障App/Admin服务能正常连接AI Proxy服务 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不得为空 | 作为AI Proxy服务的身份验证凭证，保障App/Admin与AI Proxy服务间的通信安全 |

## 容易做错的三处
- 现象：返回结果中包含模型内部思考过程的冗余文本，影响合规报告可读性。原因：未关闭模型系统提示词中强制输出思考过程的配置项。
- 现象：返回结果出现乱码或格式错乱，无法正常识别游戏文本中的特殊字符。原因：未在API调用中指定正确的字符集，或未适配游戏美术资源的非标准编码格式。
- 现象：上传图片或DOC格式的剧情脚本后，无合规校验结果返回。原因：未开启`vision`参数以支持视觉资源解析，或未配置文件上传的关联解析插件。

## 怎么确认配好了
- 执行单条剧情台词的合规校验，检查返回结果是否包含完整的缺陷标记与修改建议，无冗余思考过程文本。
- 上传一张测试用的角色立绘图片，确认模型能返回对应的合规校验结论，无乱码或无结果情况。
- 查看App/Admin服务启动日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的环境变量已正确配置，无启动校验失败报错。
- 调整`temperature`参数至0.3，执行多轮同一段文本的校验，确认结果无明显偏差，符合合规校验的基本要求。
