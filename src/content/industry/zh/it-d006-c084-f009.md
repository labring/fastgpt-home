# 游戏客户端性能优化的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自引擎Profiler工具、崩溃上报平台、真机性能测试集群与帧率采集设备，更新节奏为每日汇总或每版本发布前同步。日常产出的文档包含性能测试报告、机型适配清单、优化记录与崩溃分析报告，数据字段包含帧率（fps）、内存占用（MB）、资源包体大小（MB）、场景加载时长（秒）等，单位统一为行业通用的性能测试标准单位，无自定义特殊字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散且格式各异，工具调用环节需要适配多源接口的鉴权规则与数据格式转换逻辑。不同于移动端开发场景，该品类更关注帧率、包体与资源加载相关的数据，因此插件需优先适配这类字段的映射。高频率的更新节奏要求调用频次需匹配数据同步周期，避免触发接口限流。固定结构的业务文档需要插件预设字段映射规则，将原始性能数据匹配到测试报告的标准字段中。同时依赖真机测试数据的场景，需要插件支持远程真机接口调用，适配不同机型的参数差异。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 适配多工具调用场景，自动选择匹配性能测试数据的工具 |
| `functionCall` | `enabled` | 支持结构化输出性能测试结果，便于后续分析与报告生成 |
| 单次工具调用超时时间 | `300 秒` | 真机测试与跨平台数据拉取通常需要一定时长，避免因超时中断流程 |
| 工具调用重试次数 | `2 次` | 应对网络波动或接口临时不可用的情况，减少无效调用 |
| 每次调用返回数据上限 | `前 20 条` | 性能测试数据通常包含多组样本，限制返回条数避免上下文溢出 |
| 插件数据映射规则 | 按实测标定 | 不同项目的性能测试报告字段存在差异，需匹配实际业务文档结构 |

## 容易做错的三处
- 现象：工具调用后返回结果为空，页面显示无匹配数据。原因：未将`toolChoice`配置为适配性能测试工具的模式，导致无法触发对应插件的调用逻辑。
- 现象：调用日志未在指定页面展示，无法排查接口问题。原因：未开启插件的日志上报配置，导致调用过程未生成可追溯的日志记录。
- 现象：工具调用超时报错，状态码显示504。原因：单次工具调用超时时间设置过短，未匹配真机测试或数据拉取的实际耗时。

## 怎么确认配好了
- 进入FastGPT v4.17.0的插件管理页面，查看已配置的性能优化工具插件的启用状态是否正常。
- 发起一次测试用例的工具调用，查看返回结果是否包含结构化的性能数据字段，匹配预设的映射规则。
- 检查插件的调用日志页面，确认是否生成了完整的调用链路记录，包含接口请求与返回参数。
- 模拟低端机测试场景，验证插件是否能正确调用远程真机接口获取帧率与内存占用数据。
