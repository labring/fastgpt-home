# 游戏策划与数值设计的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
该品类的日常文档包含玩法策划案、结构化数值表、版本需求单与平衡性测试记录，数据来源涵盖玩家行为数据、竞品公开资料、战斗日志与版本反馈。数据更新以周或单版本为周期，文档字段包含规则参数、数值区间、测试阈值与反馈条目，单位涉及伤害系数、留存率、资源消耗比例等，无统一固定格式，需随玩法调整动态更新。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的混合格式文档与高频更新节奏，要求工具调用需支持多源数据的格式解析与增量拉取；数值表的强字段关联特性，要求插件调用时需保留字段映射规则，避免数值计算时的单位或参数错位；玩法失衡的高风险后果，要求缺陷分析环节需增加前置校验逻辑，对输入的规则参数进行合法性验证；版本反馈的碎片化特征，需配置工具自动聚合同类问题的功能，提升分析效率。

## 配置怎么定
本文基于FastGPT v4.17.0版本进行配置说明。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用触发时机 | 按版本节点触发 + 实时反馈拉取 | 适配周/每版本的更新节奏与实时缺陷反馈需求 |
| 上下文窗口长度 | 8000–12000 token | 容纳完整数值表与玩法规则的文本内容 |
| `toolChoice` | 自动 | 允许模型自主选择匹配的工具完成数值校验或缺陷定位 |
| 缺陷分析阈值 | 按实测标定 | 适配不同玩法的失衡判定标准 |
| 插件调用重试次数 | 3次 | 应对网络波动或模型调用失败的场景 |
| 结果聚合规则 | 按问题类型分类 | 便于策划快速定位同类缺陷 |

## 容易做错的三处
- 现象：调用大模型生成测试用例时偶现报错，返回内容为空或状态码异常。原因：未配置插件调用的重试机制，网络波动或模型服务临时不可用时未触发重试。
- 现象：使用关联文档功能提取数值表内容时，关键字段被截断无法完整识别。原因：未设置适配数值表长度的上下文窗口，导致部分核心参数未被纳入模型输入范围。
- 现象：调用缺陷分析工具时，生成的平衡性校验结果无法匹配实际数值表单位。原因：未在插件配置中保留字段映射规则，导致模型无法识别数值表的单位与参数对应关系。

## 怎么确认配好了
- 触发一次按版本节点的工具调用，检查是否能拉取到最新的版本需求单与战斗日志数据，确认数据更新逻辑生效。
- 提交一份包含完整数值表的测试用例生成请求，检查返回内容是否包含所有关键字段，未出现截断情况。
- 模拟一次网络波动场景，检查插件是否触发重试机制并在重试后返回有效结果。
- 提交一份包含多类缺陷的分析请求，检查结果是否按问题类型完成分类聚合。
