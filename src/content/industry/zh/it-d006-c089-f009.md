# 漏洞扫描服务的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
漏洞扫描服务的数据来源于漏洞扫描器、资产清单、CVE库与补丁公告。日常产出的文档包含扫描计划、漏洞清单、整改工单与复扫报告，其中扫描计划包含执行周期字段，漏洞清单包含CVE编号、资产IP、漏洞等级、发现时间等字段，整改工单关联对应漏洞与整改责任人，复扫报告包含复扫时间、整改完成率等信息。数据更新频率为周或月，单次扫描覆盖的资产范围由资产清单的IP段、标签等字段限定。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散且更新周期固定，工具调用需支持批量拉取多源数据，避免重复请求不同接口。资产范围与漏洞等级的字段限定，要求工具调用需配置针对性的过滤规则，仅处理符合业务需求的字段与数据。日常文档的多类型结构，要求插件需支持按文档类型映射不同的参数逻辑，例如扫描计划的周期参数需匹配数据更新节奏，复扫报告的字段需与整改工单联动。此外，数据更新频率较低，工具调用的触发周期需与周/月更新节奏对齐，避免无效调用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 适配FastGPT v4.17.0的工具自动选择逻辑，支持按需调用漏洞扫描相关插件 |
| `functionCall` | `{"name": "vulnerability_scan", "parameters": {"scan_type": "full"}}` | 绑定预设的漏洞扫描工具，指定全量扫描类型匹配资产清单的覆盖范围 |
| 定时触发周期 | 每周 / 每月 | 匹配漏洞扫描服务的周/月数据更新频率，避免频繁触发无效扫描 |
| 资产范围过滤 | 按资产IP前缀匹配 | 基于资产清单的IP段字段，过滤非目标范围的扫描数据 |
| 误报过滤阈值 | 中危及以上 | 基于漏洞清单的等级字段，排除低危误报数据，聚焦核心风险 |
| 单次工具调用超时 | 600秒 | 匹配漏洞扫描的常规执行时长，避免因扫描耗时过长导致调用失败 |

## 容易做错的三处
- 调用`/api/v1/chat/completions`接口时提示词未生效，原因是未正确配置`functionCall`的上下文参数，导致模型未加载预设的漏洞扫描业务提示词。
- 工具调用返回的漏洞列表条数与预期不符，原因是未配置资产范围过滤规则，导致扫描范围超出预设的资产清单。
- 插件执行后未生成复扫报告，原因是未设置结果同步的触发条件，导致扫描数据未写入对应文档模板。

## 怎么确认配好了
- 发起测试调用`/api/v1/chat/completions`，检查返回结果中是否包含漏洞扫描相关的工具调用输出。
- 查看FastGPT的插件日志，确认定时触发周期与预设的每周或每月规则一致。
- 手动修改一个高危漏洞的整改状态，检查是否能在复扫报告中同步更新对应字段。
- 验证token调用方式，确认请求头携带的`Authorization`参数格式符合平台要求。
