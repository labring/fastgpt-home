# 漏洞扫描服务的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
漏洞扫描服务的核心数据来自漏洞扫描器、资产清单、CVE库与补丁公告。日常产出的文档包含扫描计划、漏洞清单、整改工单与复扫报告，字段涵盖资产IP或域名、CVE编号、漏洞等级、修复状态、复扫时间等。数据更新频率为周度或月度，单次扫描结果集包含多类结构化条目，部分关联漏洞详情的非结构化文本片段，整体数据以标准化字段为核心支撑。

## 这些特征在「模型接入与配置」这一环带来什么约束
漏洞扫描服务的数据特征直接约束模型接入配置的设计。多源数据来源要求配置支持结构化字段与非结构化文本的混合解析，需适配扫描计划、漏洞清单等不同文档的格式。周度或月度的更新频率，要求模型调用的缓存策略匹配数据更新周期，避免无效重复拉取。单任务多条目的数据结构，要求`maxContext`等上下文相关参数需预留足够长度，完整容纳单批次扫描的全量信息。误报排除的高耗时环节，要求配置需平衡分析准确性与生成效率，避免过度调整随机性参数导致结果偏差。FastGPT v4.17.0版本的配置界面已针对该类场景优化了多源适配的默认参数。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–16000 token` | 适配单批次扫描任务的全量漏洞详情与上下文需求 |
| `maxTokens` | `2000–4000 token` | 满足缺陷分析结论、整改建议的生成长度需求 |
| `quoteMaxToken` | `500–1000 token` | 限制引用漏洞详情片段的长度，避免上下文溢出 |
| `temperature` | `0.2–0.4` | 降低生成随机性，提升缺陷分类与误报排除的准确性 |
| `AIPROXY_API_ENDPOINT` | `填写AI Proxy服务的根地址，例如http://aiproxy:3000` | 为AI Proxy服务的访问根地址，不得附加/v1或/chat/completions等路径后缀，不得指向单模型服务地址 |
| `AIPROXY_API_TOKEN` | `填写与AI Proxy服务端配置一致的非空管理员Token` | 为AI Proxy服务的身份验证凭证，不得为应用API Key、模型供应商密钥或其他业务密钥 |

## 容易做错的三处
- 测试模型接入时返回status code 404错误，排查项包括：未正确配置`AIPROXY_API_ENDPOINT`为AI Proxy服务根地址，或`AIPROXY_API_TOKEN`未正确配置或为空。
- 批量扫描任务完成后模型持续占用显存，原因是未配置模型自动卸载逻辑，或`maxContext`设置过大导致显存占用超出服务器阈值。
- 多API KEY无法按业务分组管理，排查项包括：未通过模型渠道配置完成身份凭证的分组绑定，或未正确配置对应模型渠道的访问参数。

## 怎么确认配好了
- 执行单条漏洞清单的模型分析任务，查看返回的缺陷分析结果是否包含对应CVE的等级与整改建议。
- 检查AI Proxy服务的访问日志，确认请求的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`与配置内容一致。
- 模拟批量扫描计划的模型调用，观察服务器显存占用情况，确认未出现持续占用的异常。
- 配置两组不同的模型渠道身份凭证，验证不同凭证的分组调用是否正常生效，确认分组逻辑符合预期。
