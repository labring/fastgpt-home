# 版本发布与Release Notes的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自Git仓库标签、合并提交记录、CI构建制品与Issue里程碑。日常产出的文档包括版本发布说明、变更日志、版本标签清单与发布检查单。数据更新节奏为每正式版本发布一次，核心字段包含变更归类标签、破坏性变更说明、制品校验值与关联Issue编号，无额外统计类量化指标。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散于多系统且单次处理体量对应单版本全量变更，要求模型接入需适配多源异构输入格式。固定的版本级更新节奏，要求配置需支持单次处理全量变更数据，避免分段截断导致信息丢失。核心字段的精准识别需求，限制了生成类参数的波动范围，同时发布环节的出错后果要求配置需包含失败重试与校验逻辑，保障生成内容的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配单版本全量变更记录、CI制品说明的总上下文长度 |
| `maxTokens` | `2000–3000 token` | 保障Release Notes与测试用例分析的输出长度足够覆盖所有变更说明 |
| `temperature` | `0.2–0.4` | 降低生成波动，保障变更归类、破坏性变更说明的表述准确性 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 `http://aiproxy:3000`，不得附加 `/v1` 或 `/chat/completions` 等路径 | 确保 AI Proxy 服务调用链路正常，避免地址配置错误导致的请求失败 |
| `AIPROXY_API_TOKEN` | 与 AI Proxy 服务端配置一致的管理员 Token，不能为空 | 完成 AI Proxy 服务调用的身份验证，保障请求合法性 |
| `toolChoice` | `auto` | 按需调用内置工具完成变更信息的提取与校验，适配多源数据处理需求 |

## 容易做错的三处
- 界面显示一串红色数字报错，同时在第三方API渠道测试验证通过。排查项：检查是否正确配置了App/Admin服务端的`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`环境变量，未配置或配置值错误会导致启动校验失败或请求异常。
- 调用模型时返回404状态码。排查项：检查`AIPROXY_API_ENDPOINT`是否为AI Proxy服务的根地址，未附加额外路径；同时检查上游模型渠道配置的地址是否符合要求。
- 配置关闭思考过程输出后仍生成额外思考内容。原因是未在模型专属配置中关闭系统提示词内的思考流程要求，或temperature参数过高导致生成内容偏离预设规则。

## 怎么确认配好了
- 在FastGPT v4.17.0及以上版本中，执行单版本变更数据的模型调用测试，检查返回内容是否包含完整的变更归类与破坏性变更说明。
- 查看模型调用日志，确认API请求的端点与密钥均匹配配置项，无格式错误。
- 触发一次模拟发布流程，验证生成的测试用例与缺陷分析内容是否符合预设的输出格式要求。
- 调整`temperature`参数后对比生成结果，确认参数变更对输出内容的影响符合预期。
