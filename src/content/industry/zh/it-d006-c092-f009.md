# 现场部署实施的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
这个品类的数据主要来自客户机房环境、设备清单、软件包与网络拓扑，日常依托部署手册、安装记录、配置清单、现场签到表形成结构化文档。数据更新节奏为每单或每阶段，随现场部署环节推进同步更新，核心字段包含设备标识、软件版本、配置参数、网络连通状态，无统一的标准化字段模板，需结合客户现场环境调整。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散且依赖客户现场实时环境，工具调用需支持多源异构数据的拉取与解析，无法依赖固定的全局数据源模板。数据更新随单调整的特性，要求插件配置需支持单实例定制，避免全局规则覆盖不同客户的部署需求。日常文档的非标准化结构，要求工具需兼容不同格式的部署手册、配置清单内容提取。现场问题排查的高耗时属性，要求插件需集成环境校验、日志解析的自动化调用能力，减少人工排查成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配现场部署中动态变化的工具调用需求，无需手动指定工具类型，匹配FastGPT v4.17.0的默认调用逻辑 |
| `functionCall` | `enabled` | 支持测试用例与缺陷分析场景下的结构化参数传递，匹配部署文档的字段格式 |
| 插件鉴权配置 | 基于客户机房IP白名单，有效期绑定单部署阶段 | 匹配现场部署的临时访问需求，避免全局鉴权带来的安全风险 |
| MCP格式适配 | 按部署手册的字段结构映射，超时阈值设为300秒 | 适配客户现场设备清单的结构化格式，超时阈值覆盖常规网络延迟区间 |
| 代码执行触发 | 仅在配置清单校验通过后触发，单次执行时长不超过600秒 | 避免未完成环境配置时执行代码，限制执行时长防止资源占用过高 |
| 插件调用频率限制 | 每10分钟不超过20次 | 匹配现场部署的单阶段操作节奏，避免触发平台调用限制 |

## 容易做错的三处
- 现象：调用MCP格式接口返回403状态码，原因：未将客户机房IP加入FastGPT插件的白名单配置，鉴权规则与现场部署的临时访问需求不匹配。
- 现象：工具调用返回空结果，原因：未按部署手册的字段结构映射MCP格式参数，导致插件无法识别配置清单中的有效字段。
- 现象：自动执行的代码未生成预期结果，原因：未在配置清单校验通过后触发代码执行，提前执行导致依赖的环境配置未完成。

## 怎么确认配好了
- 执行插件鉴权测试，使用客户机房的测试IP发起调用，确认返回200状态码。
- 导入一份本地部署手册的结构化片段，调用MCP格式适配插件，确认能正确提取设备版本、网络拓扑字段。
- 触发代码执行测试，确认仅在配置清单校验通过后启动执行，且执行时长未超过预设阈值。
- 查看FastGPT v4.17.0的插件日志，确认工具调用的参数与配置项完全匹配。
