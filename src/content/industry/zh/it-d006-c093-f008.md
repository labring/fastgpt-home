# 用户增长与留存运营的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自用户行为日志、推送系统、实验平台与CRM系统，更新频率多为日度或周度。日常产出的文档包含增长实验方案、用户分层表、触达文案与留存分析报告，数据字段通常包含用户分层标签、触达时间区间、实验分组标识、留存周期指标等，无统一固定的单条数据长度，需适配多格式的输入输出要求。

## 这些特征在「工作流编排」这一环带来什么约束
多来源的数据需要通过统一的变量传递机制整合，因此工作流需支持`variables`配置跨系统数据的传入。不同更新频率的业务需求要求工作流可配置定时触发或手动触发两种模式。多样的文档格式则要求工作流节点适配不同结构的输入内容，避免解析失败。长耗时的用户分群环节易引发执行超时，需拆分节点或调整执行阈值，同时出错后需快速触发告警与重试，防止影响用户留存与渠道预算投放。

本配置适用于 FastGPT v4.17.0。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次执行时长限制 | 600–1200 秒 | 覆盖用户分群、触达节奏设计等典型长耗时环节的平均执行区间 |
| 变量传入规则 | 绑定`variables`传递跨系统数据 | 适配多来源的业务数据接入需求，统一输入格式 |
| 表单前置校验 | 校验前3个必填字段 | 确保触发工作流时已完成核心运营信息填写 |
| 文件上传绑定 | 限制单文件不超过1000 MB | 匹配平台文件存储的通用上限，避免资源占用过高 |
| 工作流重试策略 | 失败后重试2次，间隔60 秒 | 应对临时的系统调用波动，降低执行失败概率 |
| 节点ID关联 | 指定`nodeId`绑定核心处理节点 | 精准控制工作流的执行链路，避免节点顺序错误 |

## 容易做错的三处
- 现象：工作流执行超过1200秒后被系统中断，界面显示执行超时提示。原因：未针对用户分群等长耗时环节设置合理的执行时长限制，未拆分长任务为多个子节点。
- 现象：调用文件上传相关工作流API时返回参数缺失报错。原因：未通过`variables`配置将上传的文件绑定为工作流的输入变量，导致API无法读取文件内容。
- 现象：未完成表单必填字段填写即可启动工作流执行。原因：未配置表单前置校验规则，未限制仅在所有必填字段填充后触发工作流。

## 怎么确认配好了
- 模拟单条用户分层数据运行工作流，核对执行时长是否在预设的600–1200秒区间内。
- 上传测试文件后调用工作流API，核对日志中是否正确读取到文件相关的`variables`参数。
- 尝试不填写表单必填字段启动工作流，核对是否被拦截无法触发执行。
- 查看工作流节点链路，核对`nodeId`指定的核心处理节点是否处于正确的执行顺序中。
