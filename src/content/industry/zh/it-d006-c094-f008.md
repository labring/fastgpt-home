# 用户验收测试支持的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
本品类的数据来源为需求规格、测试环境、客户业务样例、缺陷系统，更新频率为每阶段或每版本。日常产出的文档包含UAT用例、验收问题单、验收报告、签字确认单，其中UAT用例包含场景、前置条件、操作步骤、预期结果字段，验收问题单包含问题编号、复现步骤、严重程度、所属模块字段，所有数据需贴合客户实际业务场景。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来自客户业务样例与测试环境，工作流需支持接入多源异构的测试文档与缺陷数据；因更新频率为阶段或版本级，工作流需支持动态绑定全局变量，无需每次重新配置节点。日常文档有固定字段结构，工作流节点需适配字段提取规则，同时需覆盖用例准备、问题复现归类、验收结论确认三个最耗时环节，设置失败分支以应对验收延期、尾款延迟等风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定UAT用例场景、缺陷复现步骤为全局变量 | 数据来源包含客户业务样例与需求规格，需动态适配不同阶段的测试数据 |
| `nodeId` | 为文档解析节点、缺陷同步节点分配固定`nodeId` | 需稳定调用测试环境与缺陷系统的数据源，避免节点ID变动导致工作流失效 |
| 全局变量赋值 | 按阶段更新变量取值区间为`200–500 字符`的用例描述 | UAT用例文档的场景描述通常为该长度，适配FastGPT v4.17.0中文档解析节点的输入要求 |
| 失败分支触发 | 设置为`600 秒`超时触发失败分支 | 验收问题单的复现步骤提取通常需该时长，超时则触发人工复核流程 |
| 知识库选择 | 按测试模块筛选前 5 条匹配知识库 | 需聚焦当前UAT阶段的业务场景，避免无关知识库内容干扰分析 |

## 容易做错的三处
- 现象：文档解析节点在服务器环境返回404错误，无法读取上传文件内容。原因：未将文件存储路径绑定至`variables`参数，本地环境路径与服务器路径不匹配，导致节点无法定位文件资源。
- 现象：工作流执行后未返回对应缺陷分析结果，知识库匹配条数为0。原因：未按测试模块筛选知识库，直接调用全量知识库，导致匹配规则未命中相关业务内容。
- 现象：全局变量未按预期更新，验收问题单的严重程度字段为空。原因：未在节点配置中设置变量赋值触发条件，仅在流程启动时初始化变量，未同步实时更新的缺陷数据。

## 怎么确认配好了
- 上传服务器环境的测试文件，运行工作流，检查文档解析节点是否返回正常的文件内容解析结果。
- 模拟超时场景，运行工作流，验证是否自动跳转至失败分支并触发人工复核流程。
- 修改全局变量的取值，运行工作流后检查节点输入是否同步更新为新的变量内容。
- 选择特定测试模块的知识库，运行用例分析节点，检查返回的匹配结果是否仅包含该模块的相关内容。
