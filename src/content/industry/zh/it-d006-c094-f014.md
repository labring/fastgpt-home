# 用户验收测试支持的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于需求规格文档、测试环境配置、客户业务样例素材及缺陷管理系统。日常产出的核心文档包括UAT用例、验收问题单、验收报告与签字确认单，文档字段包含场景标识、预期结果、实际操作步骤、缺陷等级、验收结论等。数据更新节奏为每项目阶段或每软件版本同步，由实施顾问、测试经理及客户业务代表共同维护。

## 这些特征在「模型接入与配置」这一环带来什么约束
品类数据的多来源特性要求模型接入时支持自定义业务术语映射，适配不同客户的专属业务表述；按阶段/版本的更新节奏，要求配置支持快速迭代调整，无需重新部署即可适配新的UAT阶段数据；核心文档包含签字确认单等需溯源的内容，要求模型输出关联的上下文参数保留完整链路信息；对接缺陷系统与客户业务样例的需求，要求配置项需明确指定API访问端点与验证令牌。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions路径，不得使用VLLM/Ollama/Xinference等单模型服务地址 | 符合AI Proxy依赖的官方配置要求，保障服务启动校验通过 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token，不能为空 | 符合AI Proxy服务的鉴权要求，保障服务启动校验通过，不得使用应用API Key、模型供应商密钥或按应用签发的Token |
| `maxContext` | 8000–12000 token | 覆盖单阶段UAT用例与验收问题单的完整上下文，避免截断关键信息 |
| `maxTokens` | 2000–3000 token | 控制单轮缺陷分析或用例生成的输出长度，适配验收文档的排版规范 |
| `quoteMaxToken` | 1500 token | 限定引用的UAT用例或缺陷单内容长度，确保输出聚焦核心结论 |
| `temperature` | 0.3–0.5 | 降低输出随机性，保障验收结论与缺陷归类的一致性 |

## 容易做错的三处
- 现象为模型输出的缺陷归类结果与实际验收问题单的业务场景不匹配，原因是未配置自定义术语映射，未适配客户专属业务表述。
- 现象为接口请求返回401未授权错误，排查项为`AIPROXY_API_ENDPOINT`配置是否符合官方要求，或`AIPROXY_API_TOKEN`是否为与AI Proxy服务端配置一致的有效非空管理员Token。
- 现象为模型输出的用例生成结果截断关键步骤，原因是`maxContext`配置值过低，未覆盖完整的UAT阶段上下文信息。

## 怎么确认配好了
以下核对动作需基于FastGPT v4.17.0版本执行。
- 发起一次测试用例生成请求，核对返回结果包含当前阶段的UAT用例字段，确认`maxContext`配置适配当前数据长度。
- 提交一条验收问题单，查看模型输出的缺陷归类结果是否匹配业务场景，确认自定义术语映射配置生效。
- 检查接口请求日志，确认`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，且`AIPROXY_API_TOKEN`为与AI Proxy服务端配置一致的有效非空管理员Token。
- 验证多轮对话上下文是否完整保留，确认`maxContext`配置满足链路溯源需求。
