# 社区举报处理的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自社区举报系统、涉事内容详情页、举报用户历史行为记录及平台审核规则库。日常处理的核心文档包括举报工单、举报处理记录、用户申诉单、违规处置通知模板。数据更新节奏为日更或实时同步，单条数据包含举报标识、涉事内容链接、举报事由、审核状态等字段，无统一固定统计单位，仅按单条举报工单的流转流程进行管理。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据分散来自多源异构渠道，且更新节奏为日更或实时，要求工具调用需支持对接多数据源接口，适配不同格式的工单、申诉单输入。核心文档无固定标准化字段，插件需支持自定义字段提取规则，匹配不同社区的工单结构。单条举报的处置时效要求严格，工具调用需限制单次处理的上下文长度，避免超时。同时，出错会引发用户投诉或社区冲突，需配置异常捕获与回退机制，将异常工单转入人工审核流程。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` 或指定为`["file_parse", "knowledge_retrieval"]` | 社区举报处理需同时调用内容解析与知识库检索工具，auto模式可自动匹配所需工具，指定模式可减少无效调用 |
| 插件调用超时时间 | `30–60 秒` | 举报工单的处置时效要求严格，超时则需转入人工审核，避免延误 |
| `functionCall` | `strict: true` | 需严格匹配举报工单的字段提取规则，避免返回无关内容 |
| 文档解析工具配置 | 按实测标定 | 不同社区的涉事内容格式差异较大，需根据实际上传语料调整解析参数 |
| 异常重试次数 | `前 3 次重试` | 少量重试可覆盖临时网络波动，过多重试会占用系统资源 |
| 返回字段过滤 | 仅返回举报ID、处置建议、关联文件列表 | 精简返回内容，避免上下文溢出影响工具调用效率 |

## 容易做错的三处
- 现象：配置替换文档解析工具后，上传涉事举报内容无解析结果。原因：仅修改了全局文档解析配置，未针对社区举报处理场景单独调整插件绑定的解析工具参数。
- 现象：通过API调用工具后，返回结果中未包含知识库关联的举报文件列表。原因：未开启工具调用的字段返回配置，或未正确建立举报工单与知识库文件的关联映射规则。
- 现象：工具调用频繁触发超时，大量举报工单被转入人工审核。原因：配置的超时时间过短，或未限制单次工具调用的上下文长度，导致处理复杂举报内容时耗时超出设定阈值。

## 怎么确认配好了
- 提交一条测试举报工单，调用绑定的插件工具，检查是否能正确解析涉事内容文本。
- 调用API触发工具调用，查看返回结果是否包含预设的举报关联字段，确认字段映射正确。
- 模拟单次工具调用的超时场景，检查异常工单是否按配置转入人工审核队列。
- 修改文档解析工具配置后，上传不同格式的涉事内容，确认解析结果符合预期。
