# 社区活动与开发者关系的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档通常包含活动方案、讲稿、报名名单、活动复盘四类，其中活动方案含议题时长、讲者对接人字段，报名名单含到场状态、签到时间字段，活动复盘含用户反馈评分、到场人数字段。数据来源覆盖社区论坛、报名系统、社交媒体、项目路线图，分别承载用户提问、参与数据、互动数据、规划节点信息。数据更新频率为每月或单次活动结束后，单份文档的文本长度差异较大，从数百字符的活动通知到数千字符的复盘总结不等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多来源的异构数据要求模型接入配置需适配不同格式的输入文本，避免出现解析错误。数据更新频率与活动周期绑定，模型调用需匹配活动节奏，避免高频无效调用消耗资源。日常文档的长度差异大，长文本处理需要合理配置上下文与输出长度参数，确保模型能完整理解活动相关信息。结构化输出需求（如报名名单分析、复盘总结）要求模型生成内容保持较高准确性，需平衡温度参数的取值。出错后可能导致活动冷场或口碑受损，因此需配置完善的错误重试与日志记录机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | 社区活动相关文档（活动方案、复盘、用户反馈）通常长度较大，需保留足够上下文确保模型理解完整活动脉络 |
| `maxTokens` | `2000–3000 token` | 活动反馈整理、议题生成的输出长度适中，避免过长导致调用超时 |
| `temperature` | `0.3–0.5` | 活动相关的结构化输出需要较高准确性，不宜过高导致生成内容偏离活动主题 |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 http://aiproxy:3000；不要附加 /v1 或 /chat/completions；不是 VLLM/Ollama/Xinference 等单模型地址 | 该变量为 App/Admin 服务端必需配置的环境变量，用于指定 AI Proxy 服务的访问根地址 |
| `AIPROXY_API_TOKEN` | 与 AI Proxy 服务端配置一致的管理员 Token，且不能为空；不是应用 API Key、模型供应商密钥、按应用签发的 token 或按请求估算的 token 数 | 该变量为 App/Admin 服务端必需配置的环境变量，用于验证与 AI Proxy 服务的调用权限 |
| `toolChoice` | `auto` | 社区活动场景可能需要调用工具（如报名数据查询、活动日程整理），自动选择工具可提升处理效率 |

## 容易做错的三处
- 现象为模型测试阶段返回`connector error`，可排查AIPROXY_API_ENDPOINT和AIPROXY_API_TOKEN的配置是否正确，或AI Proxy服务是否正常运行。
- 现象为模型测试成功但对话时无流式响应，可排查是否未开启模型的流式输出开关，或`maxContext`参数配置是否合理。
- 现象为调用模型后响应为空且日志显示消息截断，原因是`maxTokens`参数设置过小，无法容纳模型生成的完整响应内容。

## 怎么确认配好了
- 检查服务端环境变量AIPROXY_API_ENDPOINT和AIPROXY_API_TOKEN的配置是否符合要求，验证AI Proxy服务可正常访问。
- 上传一份活动方案文档，触发模型生成总结，检查生成内容是否覆盖文档核心信息，调整`maxContext`和`maxTokens`参数至符合需求。
- 发起一次模拟用户提问，观察是否有流式响应输出，确认流式开关是否正确配置。
- 查看系统报错日志，确认无`connector error`或消息截断类的报错，验证错误处理机制是否生效。
