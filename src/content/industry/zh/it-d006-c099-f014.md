# 移动端开发的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自代码仓库、应用商店后台、崩溃监控平台及机型覆盖数据，更新节奏为每日或每版本发布周期。日常关联文档包括端版本发布单、机型适配清单、崩溃分析报告、应用商店审核资料，数据字段包含机型版本、权限调用记录、崩溃日志编号、应用商店提交状态等，无统一固定的量化统计单位，随单条数据的业务属性变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且格式差异较大，不同数据源的字段命名、结构均有区别，要求模型接入环节需支持多源数据的格式适配。数据更新频率较高，单次批量处理的内容量波动明显，需限制上下文与token的使用上限避免超时。同时业务内容聚焦机型适配、权限排查与审核相关缺陷，需配置匹配移动端开发场景的模型参数，确保对专业术语的识别准确性。此外，部分数据需同步至应用商店后台，模型输出的内容需符合平台审核的格式要求，避免因格式问题影响后续流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 适配移动端测试文档的单批次内容长度，避免超出模型上下文限制 |
| `maxTokens` | `4000–6000 token` | 匹配移动端缺陷分析的输出需求，平衡内容完整性与响应速度 |
| `quoteMaxToken` | `1500–2000 token` | 限制引用测试用例或崩溃日志的长度，确保上下文不溢出 |
| `toolChoice` | `auto` | 自动选择适合缺陷分析的工具，适配多源数据的处理逻辑 |
| `temperature` | `0.3–0.5` | 降低随机输出，保证测试用例与缺陷分析的准确性与一致性 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如`http://aiproxy:3000`，不得附加`/v1`或`/chat/completions`路径 | 为App/Admin服务端必需的环境变量，指定AI Proxy服务的访问根地址，适配FastGPT v4.17.0的代理接入规范，确保请求路由正确 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，不得为空 | 为App/Admin服务端必需的环境变量，用于AI Proxy服务的身份验证，保证接入权限的安全性，避免未授权访问 |

## 容易做错的三处
-  配置`AIPROXY_API_ENDPOINT`时填写错误的根地址，出现请求超时或404状态码。排查项为检查变量值是否为AI Proxy服务的根地址，未附加`/v1`等额外路径，且未混淆为单模型服务地址。
-  设置`maxTokens`超出模型支持的上限，出现输出截断或模型拒绝响应。原因是未结合移动端测试文档的实际内容长度调整参数，盲目使用通用配置。
-  误将索引模型配置为非embedding类模型，导致测试用例的召回结果为空。原因是混淆了对话模型与索引模型的配置要求，未按场景选择对应模型类型。

## 怎么确认配好了
-  发起一次移动端崩溃日志的分析请求，检查返回结果是否包含机型、权限调用等核心字段，确认上下文参数生效。
-  查看系统日志，确认代理请求的状态码为200，无超时或权限报错，验证接入地址与密钥配置正确。
-  提交一批测试用例数据，检查召回结果的条数与配置的`maxContext`参数匹配，确认上下文限制生效。
-  调整`temperature`参数后再次发起请求，对比两次输出的差异，确认参数配置生效。
