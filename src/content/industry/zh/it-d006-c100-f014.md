# 等级保护测评咨询的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
等级保护测评咨询的核心数据围绕定级报告、差距分析报告、测评报告等标准化文档生成，数据来自测评工具导出的控制项清单、现场访谈记录、安全设备日志及系统资产台账。数据更新以单个测评项目为周期，单项目完成后归档，年度复核时更新全量数据。文档字段包含控制项编号、合规要求、差距项描述、整改证据链接等，无统一单位，按控制项维度逐一记录。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据以单个测评项目为更新周期，模型调用需绑定项目专属的知识库分片，避免跨项目数据混淆。文档包含结构化控制项与非结构化整改证据的混合内容，模型需支持多模态输入处理。测评报告需严格匹配等保标准条款，模型输出需保留原始字段映射，不能随意改写字段名。单次项目数据量较大，模型上下文长度需适配多文档拼接后的总token数，避免截断关键合规条款。同时，测评结果需可追溯，模型调用日志需绑定对应项目ID，便于后续合规核查。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单项目多文档拼接后的总token数，避免截断关键合规条款 |
| `maxTokens` | 2000–3000 token | 匹配测评报告输出的标准篇幅，确保完整覆盖控制项整改建议 |
| `quoteMaxToken` | 1500 token | 限制引用文档的token占比，保留足够空间生成合规分析内容 |
| `temperature` | 0.1–0.3 | 保障输出内容严格匹配等保标准，降低主观偏差 |
| `vision` | 开启 | 支持解析整改证据中的截图、日志图片等非文本数据 |
| `AIPROXY_API_TOKEN` | AI Proxy服务端配置的非空管理员Token，与服务端配置一致 | 为App/Admin服务调用AI Proxy的鉴权凭证，不得作为项目专属密钥或应用API Key |

## 容易做错的三处
-  界面显示上下文条数为30，但实际发送给模型的token数对应310条，出现条数不一致。原因是未正确配置`maxContext`参数的token换算规则，将条目数直接绑定为上下文长度限制，未匹配实际文档token占比。
-  自定义添加的向量模型被错误调用为大语言模型。原因是未明确区分大语言模型与向量模型的接入配置，混淆了两类模型的调用链路参数。
-  无法处理整改证据中的图片内容，模型输出未提及图片中的关键信息。原因是未开启`vision`参数，未启用多模态模型支持。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量配置，确认`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址（例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径），且`AIPROXY_API_TOKEN`为对应AI Proxy服务端配置的非空管理员Token。
- 上传单份定级报告文档，触发模型调用，检查输出内容是否保留原始控制项编号字段。
- 上传一张整改证据截图，验证模型是否能提取图片中的文字内容并生成合规分析结果。
- 查看模型调用日志，确认传入的`maxContext`参数值与配置项的设定值一致。
