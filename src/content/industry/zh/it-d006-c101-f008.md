# 续费健康度管理的测试用例与缺陷分析：工作流编排

## 这个品类的数据长什么样
续费健康度管理的数据通常来自CRM系统、产品使用数据看板、工单统计后台与合同台账。数据更新节奏以周度或月度为主，对应业务的常规复盘周期。核心文档包含客户健康度报告、续费预测表、风险客户清单与沟通纪要，字段涵盖客户唯一标识、合同到期日、近周期功能调用频次、工单办结时长、合同剩余周期天数等，无额外自定义统计单位，仅按业务原生字段格式存储。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源覆盖多套业务系统，工作流需要配置多节点对接不同数据源，避免单节点拉取超时。数据更新节奏固定，工作流触发周期需匹配该节奏，不宜过于频繁导致资源浪费。核心文档字段结构多样，工作流需支持灵活的变量映射，适配不同文档的字段格式。业务流程中数据解读与风险归类环节耗时较长，工作流需自动归集数据并生成中间结果，减少人工操作。同时，流程异常可能直接导致客户流失，需配置异常告警节点及时干预。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发时机 | 按周/月定时触发 | 匹配数据周/月的更新节奏，适配业务复盘周期 |
| 数据源关联 | 绑定四类数据源，单次拉取不超过500条数据 | 覆盖品类所需的全量数据来源，避免单节点负载过高 |
| `variables`映射 | 映射客户ID、合同到期日、功能调用频次、工单办结时长字段 | 适配品类核心文档的字段结构，实现数据自动归集 |
| 异常告警配置 | 当风险客户占比达标时触发告警 | 提前识别流失风险，对应业务出错后果 |
| 工作流超时设置 | 300-600秒，按实测标定 | 适配多数据源拉取的耗时需求，避免节点阻塞 |
| 节点执行顺序 | 先拉取数据再做风险归类，最后生成报告 | 匹配业务流程的先后逻辑，保证数据处理合理性 |

## 容易做错的三处
- 创建工作流模板后进入编辑界面弹出报错弹窗，原因是未正确绑定`variables`参数对应的数据源字段，导致节点初始化时无法读取必要数据。
- 在工作流中引用自定义插件后，接入代码运行节点时输入框报错，原因是未配置`nodeId`对应的插件关联标识，导致节点无法识别调用目标。
- 本地部署后进入工作流页面提示Cannot read properties of undefined (reading 'incl')，原因是工作流配置中遗漏了必填的节点关联配置，导致运行时无法读取对应字段。

## 怎么确认配好了
- 查看工作流触发日志，确认按设定的周/月周期正常拉取对应数据源的数据。
- 手动触发一次工作流，检查是否正确映射了所有配置的字段，生成的中间结果符合预期格式。
- 模拟符合风险阈值的客户数据，验证异常告警节点是否正常触发告警通知。
- 调整工作流执行时长，确认节点执行未超过设定的超时阈值，无阻塞情况。
