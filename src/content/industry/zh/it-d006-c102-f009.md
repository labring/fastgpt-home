# 缺陷管理与回归测试的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来自缺陷管理系统、测试报告、代码提交记录与用户反馈，更新频率为每日或每版本发布周期。日常产出的文档包括缺陷单、回归测试清单、修复验证记录与缺陷统计报表。数据字段包含缺陷唯一标识、优先级等级、复现步骤、关联测试用例ID、受影响版本号、修复状态等，以结构化字段为主，部分复现步骤与验证记录为非结构化文本。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散且包含结构化与非结构化内容，工具调用需适配多数据源的接口格式，同时支持结构化字段提取与非结构化复现步骤的语义解析。更新频率为每日或每版本，要求工具调用的触发逻辑需绑定版本迭代节点或定时任务，避免拉取过期的缺陷与测试数据。缺陷数据与测试用例、版本强关联的特征，要求插件需保留关联字段的传递链路，确保回归验证时的上下文完整。针对缺陷复现与优先级判定的高耗时环节，工具调用需优先处理关联的历史缺陷与测试用例数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | auto | 允许模型自主判断是否调用工具处理缺陷分析与回归测试相关任务 |
| `functionCall` | 限定为缺陷优先级判定、回归验证两个场景 | 聚焦核心业务环节，避免无关工具调用消耗资源 |
| 工具调用触发时机 | 每日定时或每版本发布前1小时 | 匹配数据每日或每版本的更新频率，确保调用数据为最新状态 |
| 单次召回上限 | 前10条 | 控制工具返回的数据源条目数量，避免上下文超出处理阈值 |
| 相似度阈值 | 0.75–0.85 | 筛选与当前缺陷描述、测试用例匹配的关联数据 |
| 知识库匹配触发条件 | 匹配到3条以上相关条目时调用 | 减少无效工具调用，提升分析效率 |

## 容易做错的三处
- 现象为调用重排模型后GPU显存占用快速增长且每个GPU均占用较高资源，原因是未限制工具调用的并发数量与触发频率，导致模型被频繁调用且未及时释放显存资源。
- 现象为工具调用返回结果为空或与当前缺陷无关，原因是未设置合理的相似度阈值与召回上限，导致召回了过多低相关性的历史缺陷数据。
- 现象为工具调用触发时机与数据更新不同步，导致分析使用了过期的缺陷单或回归清单，原因是未将触发时机绑定版本发布节点或每日定时任务。

## 怎么确认配好了
- 查看工具调用日志，确认触发时机与数据更新节奏匹配，验证返回数据的版本与当前业务版本一致。
- 模拟不同缺陷场景的调用请求，确认工具仅在预设的业务环节内被触发，未出现非预期调用。
- 调整配置项的取值，核对工具返回的条目数量与相关性符合配置要求。
- 监控资源使用情况，确认工具调用的资源占用符合预设的分配规则。
