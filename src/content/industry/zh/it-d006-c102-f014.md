# 缺陷管理与回归测试的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于缺陷管理系统、测试报告、代码提交记录与用户反馈。日常产出的文档包括缺陷单、回归测试清单、修复验证记录与缺陷统计报表，更新频率为每日或每版本发布周期。缺陷单包含缺陷ID、优先级、复现步骤、关联测试用例ID、修复版本等字段；回归清单则记录测试用例ID、执行状态、通过率等信息，数据结构围绕功能缺陷的生命周期流转。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散且随版本迭代更新，要求模型接入配置需支持对接多源异构的测试与缺陷数据。日常文档的字段结构固定但覆盖范围明确，配置需适配缺陷单、回归清单等不同文档的字段识别逻辑。由于更新频率为日或每版本，上下文长度与处理时长需做合理限制，避免因数据量过大导致任务超时。同时，缺陷优先级判定与回归验证环节对模型准确性要求较高，配置需优先保障关键字段的提取与分类精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配缺陷单、回归清单等单批次文档的平均长度，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 满足缺陷复现步骤、优先级判定等核心任务的输出长度需求 |
| `toolChoice` | auto | 支持自动调用工具处理长文本切割、多段发送等场景，适配缺陷数据的批量处理 |
| `temperature` | 0.2–0.4 | 降低随机性，保障缺陷优先级判定、用例关联匹配等任务的结果一致性 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的AI Proxy服务根地址填写，例如http://aiproxy:3000，不得附加/v1或/chat/completions路径 | 为App/Admin服务端必需环境变量，用于指定AI Proxy服务地址，适配代理服务对接需求 |
| `AIPROXY_API_TOKEN` | 按与AI Proxy服务端配置一致的非空管理员Token填写 | 为App/Admin服务端必需环境变量，用于AI Proxy服务身份验证，避免未授权访问 |

## 容易做错的三处
- HTTP API返回长文本后触发请求超时或内容截断，现象为接口返回413状态码或提取结果不完整。原因是未启用`toolChoice`自动处理分段，未按批次拆分长文本后逐段发送数据。
- 内容提取节点无法调用自建模型接口，现象为节点配置中无自建模型选项或调用时报错“接口未授权”。可排查项：未正确配置App/Admin服务端的`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`环境变量，或AI Proxy服务未正常运行。
- 创建知识库时无法选择本地部署的模型，现象为模型列表中无对应模型条目。可排查项：未正确配置模型渠道的上游模型地址与供应商凭证，或未正确配置App/Admin服务端的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量。

## 怎么确认配好了
- 提交一份包含缺陷单与回归清单的测试数据，核对模型输出的缺陷优先级判定结果是否符合业务预期，调整参数直至结果匹配需求。
- 上传一段超过`maxContext`限制的长文本缺陷复现记录，核对模型是否自动触发分段处理，确认`toolChoice`配置生效。
- 确认App/Admin服务端已正确配置`AIPROXY_API_ENDPOINT`与非空`AIPROXY_API_TOKEN`环境变量，服务启动无校验报错。
- 查看FastGPT v4.17.0的系统日志，确认无模型接入相关的报错信息，验证配置参数已正确加载。
