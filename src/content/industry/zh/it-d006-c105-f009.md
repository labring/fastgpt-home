# 许可证合规与版权声明的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
本品类的数据核心围绕代码使用与分发权利相关文档，来源包括项目代码仓库、第三方依赖清单、官方许可证文本及贡献者提交记录。日常产出的标准化文档包含根目录LICENSE文件、NOTICE声明文件、依赖项许可证清单及项目版权声明。数据更新随项目版本迭代或第三方依赖变更触发，无固定周期，需随代码与依赖变动同步更新，覆盖开源项目全生命周期的合规文档管理需求。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散且需匹配多类许可证文本格式，工具调用需支持多源数据拉取与格式校验，避免字段不匹配错误。依赖清单更新频率不固定，插件需支持按需触发数据同步，以适配非定期的依赖变更。版权归属数据来自贡献记录，需支持关联提交哈希与贡献者信息，确保溯源准确。不同许可证的字段差异较大，工具调用需适配多类文档结构，避免因格式不兼容导致的校验失败。FastGPT v4.17.0 版本的插件框架支持上述灵活配置需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `toolChoice` | `auto` | 适配多类合规文档的自动识别需求，无需手动指定工具类型，符合FastGPT v4.17.0版本的工具调用逻辑 |
| `functionCall` | `enabled` | 支持结构化调用许可证校验、依赖清单生成等工具，确保输出格式符合合规文档的标准化要求 |
| 单次工具调用超时时间 | `120–180 秒` | 需拉取多源数据（代码仓库、依赖清单），超时区间覆盖常规数据拉取时长，按实测标定 |
| 工具调用结果缓存时长 | `24 小时` | 依赖清单更新频率不固定，缓存24小时可平衡数据时效性与调用开销 |
| 插件输入参数校验规则 | 匹配LICENSE、NOTICE文件格式 | 确保输入数据与本品类文档结构对齐，避免无效调用 |

## 容易做错的三处
- 现象：数据链接工具调用返回`SQL语法不兼容`报错。原因：未按照依赖清单的字段格式编写SQL查询语句，无法正确拉取合规数据。
- 现象：插件执行后依赖许可证清单为空。原因：未配置按需触发数据同步，仍使用固定轮询缓存，未及时拉取最新的第三方依赖变更数据。
- 现象：JSON输入框无法选择预设变量。原因：未将变量绑定为插件输入的可选参数，仅将输入框配置为静态JSON格式，未开启变量映射功能。

## 怎么确认配好了
- 触发一次工具调用，检查返回结果是否包含完整的依赖许可证清单、版权归属信息，无缺失字段。
- 模拟第三方依赖变更，触发插件执行，确认缓存数据自动更新，无需手动刷新。
- 查看插件配置日志，确认`toolChoice`和`functionCall`参数已按预设值生效，无异常报错。
- 输入非合规文档格式的测试数据，确认插件触发参数校验报错，拦截无效调用。
