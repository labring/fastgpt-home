# 语音标注与转写的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自待标注音频文件、标注平台产出的中间结果、行业词表以及抽检样本。日常关联文档包含转写规范、音频批次清单、质检报告与说话人标注表。数据更新以单批次或每日为节奏，每条数据包含音频文件路径、对应转写文本初稿、说话人标签、噪声片段标记等字段。数据处理需覆盖噪声识别、说话人区分与专有词校对环节，最终输出结构化转写结果。

## 这些特征在「模型接入与配置」这一环带来什么约束
音频数据依赖本地或远程文件读取，要求模型接入配置适配大文件分片加载规则；多说话人标注与专有词校对需要模型上下文匹配标注规范，需限制上下文长度避免混淆；数据更新频率较高，需配置适配批量任务调度的超时参数；结构化转写结果需与标注表字段对齐，要求模型输出格式符合预设字段要求；噪声片段判断需要模型具备音频特征识别能力，需匹配对应模型的处理配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxTokens` | 4096 token | 适配语音转写的长文本输出需求，避免截断专有词或长句 |
| `temperature` | 0.2–0.4 | 降低输出随机性，保证专有词与说话人标签的一致性 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如 http://aiproxy:3000 | 为AI Proxy服务的根地址，不得附加 /v1 或 /chat/completions 路径，不得配置为单模型服务地址 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token | 为AI Proxy管理员Token，不能为空，用于服务与AI Proxy的鉴权 |
| `maxContext` | 8000 token | 容纳转写规范、历史质检记录等上下文信息，确保模型输出符合标注要求 |

## 容易做错的三处
- 调用时提示connection error，开启代理后仍无法恢复。排查项为未正确配置服务端环境变量`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或AI Proxy服务未正常运行，或该变量未配置导致启动校验失败。
- 新增模型渠道时报错“getModifierState不是一个函数”。原因是未完成FastGPT v4.17.0的前端资源加载，或浏览器缓存了旧版本的界面脚本。
- 批量转写任务突然全部失败，提示欠费。原因是未监控API调用的累计消耗，未及时补充账户额度，导致调用权限被暂停。

## 怎么确认配好了
- 调用测试接口输入一段包含专有词与多说话人的音频转写请求，核对输出结果是否包含正确的专有词与说话人标签。
- 查看服务端部署配置，确认`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）与`AIPROXY_API_TOKEN`（与AI Proxy服务端配置一致的管理员Token）的配置值正确，无格式错误。
- 提交单批次小样本任务，检查任务执行状态是否为成功，输出结果是否符合转写规范的字段要求。
- 调整`temperature`参数至0.1与0.5，对比两次输出的专有词一致性，确认参数生效。
