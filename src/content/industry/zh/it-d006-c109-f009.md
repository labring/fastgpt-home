# 身份账号与权限管理的测试用例与缺陷分析：工具调用与插件

## 这个品类的数据长什么样
本品类数据主要来自企业IAM系统、HR系统、业务系统运行日志与审批系统。数据更新节奏随人事变动实时触发，日常批量同步频率为每日一次。核心文档包含账号申请单、权限矩阵表、离职账号回收单与合规审计报告，字段涵盖账号唯一标识、员工归属部门、权限组配置、生效与失效时间、审批节点状态等，无额外自定义统计字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据分散来源要求工具调用插件需支持对接IAM、HR、业务日志与审批系统的多源鉴权，避免跨系统权限泄露。实时更新与每日批量同步的节奏，要求插件同时支持事件触发与定时拉取两种调用模式，适配人事变动的即时同步与日常批量校验。固定的文档结构要求插件输入输出字段需匹配账号申请单、权限矩阵的标准格式，无法灵活适配非标准化字段，同时需内置越权访问、账号残留的前置校验逻辑，降低出错后果影响。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配多系统并行调用的动态选择需求 |
| `functionCall` | 启用 | 支持标准化字段的结构化返回，匹配权限文档的固定格式 |
| 插件调用超时时间 | 300 秒 | 适配IAM系统接口的常规响应时长 |
| 批量同步触发周期 | 每日 0 点 | 匹配日常权限复核的批量处理节奏 |
| 异常权限数据缓存 | 1000 MB | 满足单日权限日志与申请单的临时存储需求 |
| 多源鉴权重试次数 | 3 次 | 平衡调用成功率与系统资源消耗 |

## 容易做错的三处
- 安装数据库连接插件时提示服务器内部错误。原因是未配置IAM系统的跨系统鉴权密钥，导致插件无法拉取权限矩阵数据。
- 调用API获取权限数据时无法拿到dataId。原因是未在插件配置中启用`functionCall`，导致数据未按标准结构化字段输出。
- 插件返回的权限数据字段为空。原因是未匹配账号申请单的标准字段格式，导致数据解析失败。

## 怎么确认配好了
- 手动触发一次账号申请单的同步调用，检查返回数据包含账号ID、权限组等必填字段，确认可获取对应dataId。
- 查看minio存储桶，确认权限日志、离职回收单数据已按配置路径完成存储，验证minio正常使用。
- 模拟一次员工离职事件，验证插件是否触发实时同步并更新离职账号回收状态。
- 检查FastGPT v4.17.0的插件调用日志，确认未出现服务器内部错误或字段解析异常。
