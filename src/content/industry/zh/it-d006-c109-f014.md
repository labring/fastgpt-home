# 身份账号与权限管理的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于企业IAM系统、HR系统、业务系统日志与审批系统。日常维护的文档包括账号申请单、权限矩阵、离职回收单与审计报告，核心字段包含账号ID、权限范围、审批状态、生效时间与失效时间。数据更新频率随人事变动触发，入离转调操作发生时同步更新，日常按日批量同步全量账号与权限数据，无固定统计百分比或量化指标。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源覆盖多套企业内部系统，模型需兼容不同格式的结构化与半结构化数据输入，需配置适配多源数据的上下文加载规则。数据更新频率随人事变动实时触发，要求模型接入环节支持近实时同步配置，避免使用固定离线数据源导致权限数据滞后。核心文档包含权限矩阵等强关联规则数据，模型需准确识别字段间的关联关系，因此上下文长度配置需覆盖完整的权限链路信息，同时需严格控制生成结果的严谨性，避免出现越权相关的错误判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 身份账号与权限管理的核心文档包含权限矩阵、审计报告等长文本，需覆盖完整的权限关联链路数据 |
| `maxTokens` | `2000–3000 token` | 测试用例与缺陷分析需生成覆盖多场景的校验步骤，输出内容需包含权限校验逻辑与异常排查方向 |
| `quoteMaxToken` | `1500 字符` | 需完整引用账号申请单、离职回收单中的表单字段，避免截断账号ID、权限范围等关键信息 |
| `temperature` | `0.1–0.3` | 权限校验需保持严谨的规则判断，避免生成模糊或错误的权限判定结果 |
| 注：`AIPROXY_API_ENDPOINT`、`AIPROXY_API_TOKEN`为FastGPT App/Admin服务端必填环境变量，不属于本环节模型配置项 | - | - |
| 重排 | 开启 | 权限数据关联关系复杂，重排可提升高权限关联字段的召回优先级，优化测试用例的覆盖范围 |

## 容易做错的三处
- 现象：模型生成的测试用例未覆盖跨系统权限关联场景，仅生成单系统权限校验规则。原因：未配置足够的`maxContext`参数，截断了权限矩阵中的跨系统关联字段，导致模型无法识别完整权限链路。
- 现象：解析离职回收单时无法提取账号失效时间字段，生成的缺陷分析包含无效权限残留的错误判断。原因：未设置合理的`quoteMaxToken`参数，截断了文档中的生效与失效时间字段，导致模型无法识别账号的有效周期。
- 现象：重排配置开启后，生成的缺陷分析仅包含单条权限异常，未覆盖批量权限异常场景。原因：未调整`maxContext`参数以覆盖全量权限数据，或重排召回的关联数据未被纳入上下文，导致模型仅基于单条数据生成结果。

## 怎么确认配好了
- 上传一份真实的账号申请单与权限矩阵文档，核对模型生成的测试用例是否包含账号ID、申请权限、审批状态等核心字段。
- 模拟入离转调场景，输入对应员工账号信息，核对模型生成的缺陷分析是否包含权限遗漏、越权访问等异常场景。
- 检查FastGPT App/Admin服务端的环境变量配置，确认`AIPROXY_API_ENDPOINT`、`AIPROXY_API_TOKEN`已正确配置，服务启动校验通过。
- 调整`temperature`参数区间，核对生成的校验规则是否保持一致的严谨性，无随机偏差。
