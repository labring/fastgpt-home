# 运维外包驻场服务的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
该品类的典型主体为外包驻场工程师、服务经理与客户IT部门，数据通常来自客户ITSM系统、监控平台、资产清单与值班记录，更新节奏分为日度与月度。日常产出文档包括驻场日报、服务台工单、巡检报告与SLA月报，涉及字段涵盖工单编号、巡检项、SLA达标率、驻场人员值班时段等，数据关联驻场服务的全流程交付环节，无统一强制格式要求。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散的特征要求溯源环节需关联多系统的唯一标识，避免跨数据源的引用冲突。更新节奏的差异要求配置区分日度巡检数据与月度SLA报表的溯源逻辑，适配不同的更新频率。文档结构的多样性则要求溯源工具可适配驻场日报、工单等不同格式的字段提取。同时，该品类的出错后果直接影响服务合同，因此溯源的准确性需满足交付合规要求，不可出现引用缺失或标识错误。

本文基于FastGPT v4.17.0版本编写。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配驻场日报、巡检报告等文档的平均长度，确保引用内容完整 |
| `responseData` | 仅返回关联字段 | 减少冗余数据，聚焦工单编号、巡检项等核心溯源字段 |
| `detail` | 开启全字段溯源 | 满足SLA月报等需要多维度关联的溯源需求 |
| 单次搜索上限 | 前 8 条 | 覆盖驻场服务日常产生的工单与巡检记录的平均覆盖量 |
| 数据源关联规则 | 按客户ITSM标识格式配置 | 适配不同客户的系统字段命名差异 |
| 溯源更新频率 | 日度/月度分档 | 匹配该品类数据的日/月更新节奏 |

## 容易做错的三处
- 对话请求接口未返回cite引用id。原因是未开启`detail`配置项的全字段溯源，导致引用标识字段未被纳入返回数据。
- 知识库搜索卡片选择知识库后变量引用失效。原因是未配置数据源关联规则，无法匹配驻场工单与巡检报告的唯一标识。
- 查看聊天回答的知识库引用时出现字段为空报错。原因是`quoteMaxToken`设置过小，导致引用内容被截断无法匹配源数据。

## 怎么确认配好了
- 发起测试请求，检查返回结果中是否包含cite引用id，核对配置的`quoteMaxToken`是否适配当前测试文档长度。
- 选择对应知识库发起搜索，验证变量引用可正常关联驻场工单或巡检报告的源数据。
- 查看聊天回答的引用模块，确认无字段格式错误或缺失的问题，调整校验规则匹配目标客户的系统格式。
- 切换日度与月度数据源，验证溯源逻辑可按配置的更新频率自动适配。
