# 运维外包驻场服务的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
运维外包驻场服务的测试用例与缺陷分析相关数据，主要来源于客户ITSM系统、监控平台、资产清单及值班记录。日常产出的文档包括驻场日报、服务台工单、巡检报告与SLA月报，数据更新频率分为日度与月度两类。驻场日报包含值班时段、工单处理条目、巡检完成情况等字段，SLA月报则记录服务达标情况与相关记录，各文档的字段结构与更新节奏均贴合驻场服务的合同化交付要求。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且覆盖多类系统，要求模型接入需支持多源数据的统一拉取与解析；文档结构多样且更新节奏不同，需配置适配不同字段的prompt模板与上下文窗口。驻场服务的合同化属性要求模型调用需隔离客户数据，同时需留存完整的调用日志以满足审计需求。此外，缺陷分析的严谨性要求模型参数需适配驻场场景的业务逻辑，避免生成不符合运维规范的结论。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `AIPROXY_API_ENDPOINT` | AI Proxy 服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions，不得为 VLLM/Ollama/Xinference 等单模型地址 | 该变量为 App/Admin 服务端必需环境变量，需与 AI Proxy 服务端部署地址一致 |
| `AIPROXY_API_TOKEN` | AI Proxy 管理员 Token，需与 AI Proxy 服务端配置一致且不能为空 | 该变量为 App/Admin 服务端必需环境变量，不得为应用 API Key、模型供应商密钥或按应用签发的 token |
| `maxContext` | `8000–12000 token` | 覆盖1-3天的驻场工单、巡检报告等多份文档的内容，避免上下文截断 |
| `maxTokens` | `2000–3000 token` | 确保测试用例与缺陷分析的输出包含完整的排查建议与整改方案，满足驻场服务的交付要求 |
| `toolChoice` | `auto` | 自动调用文档解析、日志查询工具，适配多源数据的处理需求 |
| `temperature` | `0.3–0.5` | 保持缺陷分析结论的严谨性，避免生成过于发散的排查方向 |

## 容易做错的三处
- 在模型配置文件中添加`avatar`字段并使用网络链接，导致模型启动失败。原因是运维外包驻场服务的专属模型不支持自定义头像配置，无需添加该字段。
- 尝试使用未授权的语音识别模型，调用时提示权限不足。原因是驻场服务的模型接入需使用合同约定的合规模型，未授权模型无法通过权限校验。
- 查看OneAPI调用日志时无法找到对应记录。原因是未开启模型调用的日志留存配置，驻场服务的审计需求需开启完整日志记录。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，发起一次测试用例生成请求，检查返回结果是否包含驻场工单的关联信息。
- 检查 App/Admin 服务端启动日志，确认无 AIPROXY_API_ENDPOINT 或 AIPROXY_API_TOKEN 缺失导致的启动校验失败。
- 调整`temperature`参数后，检查分析结果的严谨性是否符合预期。
- 验证多源数据拉取功能，确认从ITSM、监控平台等来源的文档均可被模型正常解析。
