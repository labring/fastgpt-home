# 配置管理与CMDB维护的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
本品类的核心数据由运维资产管理员、SRE、ITSM平台管理员日常维护，包含配置项清单、服务组件关系拓扑、变更记录、资产盘点表四类结构化文档。数据来源包括CMDB系统、云资源清单、自动发现工具与采购台账，更新频率为每日或每周。最耗时的环节为配置项采集、依赖关系核对与变更后数据更新，数据直接关联服务故障定位与资产账实一致性。与IT资产盘点品类不同，本品类聚焦服务组件间的依赖关系，所有数据均为可直接溯源的结构化记录。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散且更新节奏不同，溯源环节需明确标记每条引用内容的原始数据源与更新时间，避免混淆不同周期的配置数据。配置项与关系拓扑的结构化特征要求溯源需关联具体的组件ID与依赖链路，无法仅通过文本关键词匹配。变更记录的实时性要求溯源结果需同步最新的配置修改信息，否则会导致分析偏差。同时，资产账实不符的出错后果要求溯源环节必须锁定唯一的原始数据来源，不可混用多套非统一的配置数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `8000–12000 token` | 匹配CMDB配置项清单与关系拓扑的平均内容长度 |
| `responseData` | 仅返回关联配置项ID、变更时间与数据源标签 | 聚焦溯源核心信息，减少冗余内容 |
| `detail` | 开启 | 展示配置项的完整依赖链路与变更历史 |
| 最大上下文长度 | `15000–20000 字符` | 覆盖单批次的配置项清单与拓扑数据 |
| 单次搜索上限 | 前 6 条 | 匹配日常运维的配置项检索数量 |
| 数据源过滤 | 仅选择CMDB、云资源清单 | 排除非配置类的采购台账数据 |

本配置规则适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：测试用例分析结果中未显示配置项的引用来源，引用字段为空。原因：未正确配置`responseData`参数，未开启溯源关联开关。
- 现象：API调用返回超时错误，响应时长超过`60 秒`。原因：`quoteMaxToken`设置超出系统处理阈值，导致内容解析耗时过长。
- 现象：溯源结果包含无关的采购台账条目。原因：未配置数据源过滤规则，混用了非配置类的文档数据。

## 怎么确认配好了
- 查看测试用例的溯源弹窗，确认关联的配置项ID、变更记录与CMDB数据源标签均正确显示。
- 调用FastGPT API接口，检查`responseData`字段返回的内容符合预设的筛选规则，无冗余数据。
- 调整`quoteMaxToken`取值，验证返回的溯源内容长度匹配设置的参数范围。
- 模拟配置项变更操作，确认溯源结果自动更新为最新的变更记录。
