# 配置管理与CMDB维护的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源包括CMDB、云资源清单、自动发现工具、采购台账。日常维护的文档包含配置项清单、服务组件关系拓扑、变更记录、资产盘点表。数据更新节奏为日度或周度，字段包含配置项唯一标识、依赖关系标识、变更时间戳、资产状态等，涉及的单位包括资产数量、关联关系条数、变更记录条数等，整体数据结构以结构化的资产信息与关联关系为主。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源分散且多为内部系统，模型接入需支持多组API端点与访问令牌的配置，适配CMDB、云资源清单等不同数据源的接入要求。由于更新节奏为日度或周度，需配置合理的缓存刷新与上下文管理参数，避免缓存过期或冗余拉取。由于文档包含复杂的服务组件关系拓扑这类长文本内容，需调整上下文长度相关参数以完整承载数据。由于配置错误会影响业务影响分析与故障定位，需配置失败后的重试与校验机制。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，如 http://aiproxy:3000 | 配置AI Proxy服务的访问入口，为App/Admin服务端必填环境变量 |
| `AIPROXY_API_TOKEN` | 填写与AI Proxy服务端配置一致的管理员Token，且不能为空 | 为App/Admin服务端必填环境变量，用于AI Proxy服务鉴权 |
| `maxTokens` | 8000–12000 token | 适配配置项清单、关系拓扑这类长文本数据的处理需求 |
| `maxContext` | 3–5 条历史同步记录 | 匹配日/周度的更新节奏，避免缓存过期或冗余 |
| `temperature` | 0.2–0.4 | 降低生成结果的随机性，保障配置项分析的准确性 |
| `quoteMaxToken` | 1000–1500 字符 | 适配资产盘点表、变更记录的文本长度要求 |

## 容易做错的三处
- 现象：App/Admin服务启动失败或无法调用AI Proxy服务，返回401认证失败状态码。原因：填写的`AIPROXY_API_TOKEN`与AI Proxy服务端配置不一致，或使用了第三方模型密钥、应用API Key等非AI Proxy管理员Token的内容。
- 现象：配置项分析结果出现大量冗余的重复条目。原因：未匹配数据源的日/周更新节奏，设置了过短的缓存刷新间隔，导致重复拉取同一批次的配置数据。
- 现象：关系拓扑的分析结果被截断，无法完整展示组件依赖。原因：`maxTokens`设置值过小，无法承载完整的拓扑结构文本内容。

## 怎么确认配好了
- 执行一次手动同步任务，检查配置项清单的拉取结果是否包含预期的资产条目。
- 查看FastGPT v4.17.0的服务启动日志或AI Proxy服务端日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置校验通过，调用返回状态码为200。
- 生成一份配置项依赖分析报告，检查报告的长度是否符合预期，未出现截断情况。
- 等待一个更新周期后，检查变更记录的同步结果是否包含最新的资产变更数据。
