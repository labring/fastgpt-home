# 集成测试与接口测试的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
数据来源为接口管理平台、测试环境日志、数据库、消息队列；更新节奏为每日或每版本迭代时更新；日常产出文档包含接口测试用例、联调问题单、环境说明、测试报告；数据字段包含接口端点、请求参数、响应状态码、缺陷关联标识、测试环境标识，无额外统计类字段，所有数据均围绕跨模块交互的验证过程产生。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求接入时配置统一的解析适配规则，避免不同来源的日志、用例格式导致模型识别偏差；高更新频率要求配置合适的上下文长度参数，适配每日或版本级别的数据增量；固定的文档字段结构要求模型调用时明确指定提取规则，确保缺陷分析时能准确关联接口端点、响应状态码等关键信息；同时，测试数据的链路属性要求配置工具调用相关参数，支持跨模块的问题定位。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | 8000–12000 token | 适配每日更新的接口测试用例与联调日志，避免上下文溢出导致关键测试数据丢失 |
| `maxTokens` | 2000–3000 token | 满足接口响应内容、缺陷描述的完整输出需求，避免截断关键错误信息 |
| `temperature` | 0.2–0.4 | 降低随机生成概率，确保缺陷分析时输出的接口参数、状态码等信息准确一致 |
| `toolChoice` | auto | 支持自动调用工具定位接口链路问题，适配集成测试的跨模块验证需求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径 | 确保App/Admin服务端能正确路由AI Proxy服务 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置一致的管理员Token，且不能为空 | 用于App/Admin服务端调用AI Proxy服务的身份验证，避免未授权访问 |

## 容易做错的三处
- 现象为调用模型相关接口时返回404 page not found或连接失败，排查项：检查`AIPROXY_API_ENDPOINT`是否配置为AI Proxy服务的正确根地址，未附加多余路径。
- 现象为模型识别问题分类的结果偏差较大，原因是未配置`temperature`参数或取值过高，导致生成的分类规则不稳定。
- 现象为接口测试用例解析后关键字段为空，原因是未设置`maxContext`参数，导致上下文过长被截断，丢失了接口地址、请求参数等核心信息。

## 怎么确认配好了
- 提交一条已知的接口测试用例，检查模型返回的缺陷分析结果是否包含接口端点、响应状态码等预期字段。
- 查看AI Proxy服务端日志，确认App/Admin服务端的调用请求验证通过，无未授权访问相关报错。
- 触发一次联调问题单的模型分类任务，检查结果的字段完整性与准确性。
- 调整`maxContext`参数后提交大体积测试数据，确认无上下文溢出相关报错。
