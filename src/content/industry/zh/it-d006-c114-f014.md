# 需求分析与PRD管理的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自需求调研纪要、PRD文档、用户故事清单及需求变更单，更新频率为周度或每版本发布周期。数据字段包含业务目标、验收口径、关联测试点、变更记录等，整体结构以需求节点为核心，附带多轮访谈记录与版本迭代痕迹。数据来源覆盖客户访谈记录、工单系统、竞品公开页面及团队埋点看板，无强制标准化格式，存在中英文对照的文档场景。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据特征直接约束模型接入配置：首先，数据无强制标准化格式且存在中英文对照场景，要求模型接入时需配置适配多语言的上下文处理逻辑，避免因字段识别偏差导致测试用例与PRD口径不匹配；其次，更新频率为周度或每版本，要求上下文窗口需保留完整的版本迭代信息，避免因上下文截断丢失旧的需求变更记录；最后，最耗时的访谈信息归类与边界条件确认环节，要求模型调用需兼顾严谨性与灵活性，平衡需求分析的准确性与测试用例生成的效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配周/每版本的需求文档更新量，保留完整的PRD、用户故事清单及变更记录上下文，避免关键信息截断 |
| `temperature` | 0.3–0.5 | 平衡需求分析的严谨性与测试用例生成的灵活性，适配验收口径的准确匹配，减少边界条件确认的偏差 |
| `quoteMaxToken` | 1500–2000 token | 保留PRD中核心的业务目标与验收口径字段，确保模型在生成测试用例时可引用关键信息，符合需求文档的核心逻辑 |
| `toolChoice` | auto | 自动触发需求变更校验、测试用例关联的工具调用，适配需求变更单的同步需求，确保测试用例与最新需求保持一致 |
| `AIPROXY_API_ENDPOINT` | 为AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions等路径，不得配置为单模型服务地址 | 为App/Admin服务端必需的环境变量，用于指定AI Proxy服务地址，确保模型调用路由正确，避免跨区域或跨环境的调用失败 |
| `AIPROXY_API_TOKEN` | 与AI Proxy服务端配置的管理员Token一致且非空 | 为App/Admin服务端必需的环境变量，与AI Proxy服务端配置的管理员Token保持一致，保障AI Proxy服务的访问安全，防止未授权访问 |

## 容易做错的三处
- 现象：模型回答时提示未获取到知识库内容，或生成的测试用例未关联PRD中的验收口径。原因：`maxContext`取值过小，导致完整的PRD和需求变更记录无法被模型读取，上下文截断丢失核心信息。
- 现象：rerank模型未按预期对测试用例相关的PRD内容进行排序。原因：未正确配置`quoteMaxToken`，导致模型无法识别需要优先匹配的PRD字段，rerank模型的输入上下文不完整，无法精准关联测试用例与需求文档。
- 现象：Qwen3模型调用时出现流式行为异常，导致节点模型执行中断。原因：未根据模型特性调整`maxTokens`取值，超出模型支持的非流式调用上下文上限，触发调用失败。

## 怎么确认配好了
- 检查App/Admin服务端的`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`环境变量配置，确认服务启动校验通过，模型调用路由正确，无启动失败提示。
- 触发一次需求变更同步的模型调用，确认`toolChoice`自动触发了关联的测试用例校验节点，无报错返回，测试用例同步了最新的需求变更内容。
- 导入包含中英文对照的PRD文档，生成一组测试用例，确认模型同时匹配了中文需求和对应的英文翻译内容，无内容遗漏或匹配偏差。
- 调整`temperature`至0.4，生成3组测试用例，对比结果的一致性，确认取值符合预期，无过度发散或过于僵化的生成结果。
