# 项目文档移交归档的测试用例与缺陷分析：引用来源与溯源

## 这个品类的数据长什么样
本品类的数据主要来自项目文档库、配置清单、会议纪要、测试报告。日常产出的文档包括竣工文档、配置手册、培训记录、验收证书。数据更新节奏为项目各阶段结束或整体项目收尾时同步。文档通常包含文档版本号、关联项目标识、签章状态、测试用例编号、缺陷记录编号等字段，无固定统一的单位字段，以文本描述类内容为主。

## 这些特征在「引用来源与溯源」这一环带来什么约束
项目文档移交归档的数据多为阶段式更新，引用时需匹配对应项目周期的版本，避免跨阶段引用过期文档。文档字段包含测试用例与缺陷相关标识，溯源时需精准关联对应测试环节的记录。由于数据更新频率不固定，需在引用时校验文档的最新版本状态，防止引用未完成签章或未归档的草稿文件。同时，文档多为文本描述类内容，需确保引用时能准确匹配到原始文档的具体章节与条目，便于后续的验收核对与运维追溯。

## 配置怎么定
本配置适用于FastGPT v4.17.0及以上版本，具体参数设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配项目文档单段文本长度，避免截断测试用例与缺陷的关键描述 |
| `responseData` | 包含引用源元数据 | 确保返回结果携带文档版本号、关联项目ID等溯源字段 |
| `detail` | 开启完整溯源模式 | 展示原始文档的具体章节位置，便于核对测试用例与缺陷的关联关系 |
| 单次搜索上限 | 前3条匹配结果 | 聚焦最相关的项目文档，避免冗余信息干扰测试用例分析 |
| 版本校验开关 | 开启 | 确保仅引用当前项目阶段的最新版本文档 |

## 容易做错的三处
- 接口调用成功但无有效内容返回，仅返回空字段。原因是未正确配置`responseData`参数，未开启引用源元数据的返回开关，导致系统未关联到项目文档库的有效数据。
- 引用的文档版本与当前测试阶段不匹配，出现过期的测试用例内容。原因是未开启版本校验开关，允许引用历史阶段的未归档草稿文档。
- 引用内容出现格式混乱或截断异常。原因是未设置合理的`quoteMaxToken`参数，导致长文本被截断后拼接异常，或未开启`detail`模式导致原始文档的章节信息丢失。

## 怎么确认配好了
- 发起包含测试用例关键词的测试请求，查看返回结果中是否包含文档版本号、关联项目ID等元数据字段，确认`responseData`配置生效。
- 提交包含历史版本标识的测试用例查询，验证系统是否仅返回当前项目阶段的最新文档，确认版本校验开关生效。
- 查看返回的引用源详情，确认是否展示了原始文档的具体章节位置，确认`detail`模式开启。
- 调整`quoteMaxToken`参数为不同区间，提交包含长文本描述的缺陷查询，验证返回内容未被过度截断或拼接异常。
