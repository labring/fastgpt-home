# 项目文档移交归档的测试用例与缺陷分析：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据通常来自项目各阶段产出的项目文档库、配置清单、会议纪要、测试报告，日常处理的文档包括竣工文档、配置手册、培训记录、验收证书。数据更新节奏随项目阶段或项目结束触发，无固定周期。文档结构包含结构化字段与非结构化内容，部分验收证书、培训记录存在扫描件或签章图片，字段多包含项目编号、版本号、交付日期、签章状态等，无统一强制单位要求，需随单份项目文档的格式灵活适配。

## 这些特征在「模型接入与配置」这一环带来什么约束
项目文档移交归档的多源分散数据特征，要求模型接入需支持多格式数据处理，覆盖文本与图片类文档。长文本类竣工文档、配置手册的存在，要求配置需覆盖足够的上下文长度，避免关键信息被截断。按阶段更新的数据特性，要求模型配置可灵活适配不同阶段的文档格式与字段规则。同时，该品类的分析结果直接关联项目验收与尾款结算，要求模型输出需具备严谨性，避免生成无关或偏差内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 项目文档多为长文本，需覆盖完整交付文档的上下文内容，避免关键信息截断 |
| `vision` | 开启 | 日常处理的验收证书、培训记录多包含扫描件或签章图片，需支持多模态识别能力 |
| `temperature` | 0.2–0.4 | 测试用例与缺陷分析需保持输出严谨性，避免生成无关或偏差内容 |
| `AIPROXY_API_ENDPOINT` | 填写AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions 路径，不得填写VLLM/Ollama/Xinference等单模型服务地址 | 该变量为App/Admin服务端必需配置的环境变量，需与AI Proxy服务端配置的监听地址一致 |
| `toolChoice` | auto | 需根据任务自动调用工具完成文档完整性、版本一致性的核对工作 |
| `quoteMaxToken` | 1000–1500 token | 需保留足够的原文片段用于缺陷溯源与交付证据核对 |

## 容易做错的三处
- 现象为模型返回的分析结果丢失文档关键片段，排查项为未配置`maxContext`参数或取值过小，导致长文档上下文被截断。
- 现象为扫描版验收证书无法被正确解析，排查项为未开启`vision`配置项，未启用多模态图片识别能力。
- 现象为模型调用返回连接失败或不兼容报错，排查项为未配置App/Admin服务端必需的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量，其中`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，`AIPROXY_API_TOKEN`为AI Proxy管理员Token且需与AI Proxy服务端配置一致且不能为空，或`AIPROXY_API_ENDPOINT`地址与部署的AI Proxy服务环境不匹配，未配置会导致App/Admin服务启动校验失败。

## 怎么确认配好了
- 上传单份完整的竣工文档，检查模型能否正确提取项目编号、版本号等核心字段。
- 上传含签章的扫描版验收证书，检查模型能否识别图片中的签章信息并完成有效性校验。
- 配置`toolChoice`为auto后，提交缺陷分析任务，检查模型能否自动调用工具完成文档版本一致性核对。
- 查看FastGPT v4.17.0的模型调用日志，确认无上下文截断或参数配置错误的提示。
