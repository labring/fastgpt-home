# CDN与边缘加速配置的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自CDN控制台、DNS解析记录、公网访问日志与边缘节点监控告警。日常关联文档包括域名接入单、缓存规则配置表、刷新预热操作记录、故障分析报告。数据更新节奏为每日同步或随配置变更实时更新，字段包含节点IP、缓存命中率、请求响应码、刷新任务状态等，无额外强制统计单位，仅按业务场景记录原始操作与运行数据。本页面基于FastGPT v4.17.0的定时任务模块编写。

## 这些特征在「定时任务与自动化」这一环带来什么约束
数据来源分散导致定时任务需要跨多系统拉取数据，需适配不同接口的鉴权与返回格式。更新频率的差异要求任务调度区分实时变更触发与每日批量校验场景。文档结构的标准化程度决定了自动化脚本的解析逻辑，需适配域名接入单的字段顺序、缓存规则的正则匹配规则。异常节点排查的高耗时属性，要求定时任务优先覆盖高频故障节点的巡检，避免全量扫描占用过多资源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 巡检任务触发周期 | 每 15–30 分钟 | 匹配数据每日更新节奏，及时响应边缘节点异常 |
| 跨系统数据拉取超时时间 | 30–60 秒 | 预留冗余时间适配多接口响应差异，避免任务阻塞 |
| 异常告警阈值匹配规则 | 缓存命中率低于 80%、响应码4xx/5xx占比超 5% 触发 | 符合行业通用异常判定标准，过滤无效告警 |
| 故障复盘报告生成频率 | 每日 0 点 | 汇总当日全量数据，满足次日分析需求 |
| 批量刷新预热任务并发数 | 10–20 个 | 适配CDN控制台接口调用限制，避免触发限流 |

## 容易做错的三处
- 现象：定时推送的企业微信外部群消息为空或触发报错。原因：未配置CDN故障数据与消息模板的字段映射，导致待发送内容缺失。
- 现象：定时巡检任务频繁触发重复告警。原因：未设置告警去重周期，同一异常节点的告警在短时间内多次推送。
- 现象：批量刷新预热任务执行超时被拦截。原因：未限制并发数，超出CDN控制台的接口调用上限导致请求被拒绝。

## 怎么确认配好了
- 手动触发一次定时巡检任务，检查是否能从CDN控制台、DNS解析系统拉取到对应数据。
- 查看任务执行日志，确认跨系统数据拉取的超时时间未触发报错。
- 生成一次临时故障复盘报告，检查报告是否包含缓存规则、刷新记录等核心字段。
- 模拟异常节点场景，确认告警是否能按配置规则触发推送。
