# IT采购与供应商管理的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
本品类的数据主要来自企业内部采购系统、供应商报价文档、预算表及合同系统。日常产出的核心文档包括采购申请单、比价记录表、正式合同与验收单据，字段通常包含采购单号、供应商主体信息、预算额度、合同条款明细与验收状态。数据更新节奏以单采购流程为单位，单次采购从申请到验收完成会产生多份关联文档，常规月度批量更新的场景也较为常见。

## 这些特征在「定时任务与自动化」这一环带来什么约束
本品类的数据来源分散且格式多样，要求定时任务需适配多系统接口调用权限与不同文档的解析逻辑。数据更新以单采购流程或月度批量为节奏，定时周期需匹配业务实际推进节奏，避免过度调用内部采购系统占用资源，或因周期过长无法及时响应紧急采购的故障排查需求。同时，关联文档的字段差异较大，自动化流程需支持动态匹配不同单据的关键信息，否则易出现参数校验失败的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发周期 | 300–1800 秒（按业务场景标定） | 匹配采购流程的更新节奏，避免频繁调用采购系统接口 |
| 任务重试次数 | 2–3 次 | 应对采购系统临时接口波动，减少人工介入 |
| 单次数据拉取上限 | 前 10 条采购单据 | 控制单次任务的资源占用，避免任务超时阻塞 |
| 告警触发阈值 | 连续 2 次任务失败 | 及时通知运维人员处理异常场景 |
| 文档解析分段阈值 | 800–1200 字符/单段 | 适配采购合同与验收单的文本长度，提升解析准确率 |
| 接口超时设置 | 60 秒 | 匹配内部采购系统的常规响应时长，避免任务挂起 |

## 容易做错的三处
- 现象：定时任务触发间隔设置为3000毫秒，导致频繁调用采购系统接口引发限流。原因：未匹配采购系统的接口调用频率限制，误将毫秒级间隔用于企业内部系统调用。
- 现象：工作流中添加自定义采购单据解析插件后，输入输出参数未显示，且无报错日志。原因：插件配置未关联对应采购单据的字段映射规则，或插件包未正确上传至工作流目录。
- 现象：执行升级脚本时返回POST /api/admin/initv4818 404错误。原因：升级脚本调用的接口路径与当前FastGPT版本不匹配，未更新脚本中的接口地址参数。

## 怎么确认配好了
- 手动触发一次定时任务，查看FastGPT v4.17.0版本的任务日志，确认拉取的采购单据数量与配置的单次拉取上限一致。
- 模拟一次采购系统接口异常，验证任务是否按照配置的重试次数执行重试，并在达到阈值后触发预设告警。
- 上传一份标准采购合同文档，验证自动化流程是否能正确提取关键字段并生成结构化结果。
- 检查工作流的插件配置页面，确认自定义插件的输入输出参数已正确加载并显示。
