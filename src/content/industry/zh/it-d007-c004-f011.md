# IT采购与供应商管理的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
这个品类的数据主要来源于采购系统、供应商报价、预算表、合同系统，日常关联的文档包括采购申请、比价记录、合同、验收单。数据字段通常包含采购单号、供应商名称、预算金额、合同期限、验收状态等，单位涉及元、天等。数据更新节奏为每单或每月，单次更新的数据量随采购流程节点变化，从单条申请到批量月度对账数据不等，整体并发访问量较低，以批量写入和定时查询为主。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据接入的需求要求数据库支持结构化与非结构化数据混合存储，需分别适配PostgreSQL和MongoDB的存储场景。按单或月度的更新节奏，决定了数据库无需高并发实时写入配置，可采用批量提交或定时同步的策略。数据关联采购全流程文档，要求数据库表结构需匹配采购申请、合同等文档的字段规范，避免字段缺失或格式不统一。出错后果涉及采购延期、预算超支等风险，要求数据库需具备可靠的备份与恢复机制，保障数据在故障场景下可快速恢复，同时需限制不必要的外部访问，保障内部采购数据的安全性。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `MONGODB_URI` | `mongodb://admin:password@192.168.1.100:27017/fastgpt_purchase?authSource=admin` | 对接采购合同系统的MongoDB存储库，适配非结构化的合同文本与验收单数据 |
| `PG_URL` | `postgresql://purchase_user:pass123@192.168.1.101:5432/purchase_db` | 对接供应商报价、预算表的PostgreSQL数据库，适配结构化的比价与预算数据查询 |
| `DB_MAX_LINK` | `20–30 条` | 采购数据更新频率为每单/月，并发连接无需过高，避免服务器资源过度占用 |
| `REDIS_URL` | `redis://:redis_pass@192.168.1.102:6379/0` | 缓存采购申请的审批状态，缩短高频查询的响应耗时 |

## 容易做错的三处
- 现象：执行版本升级后，页面返回502错误，无法登录系统。原因：修改了`MONGODB_URI`或`PG_URL`的配置文件后，未正确重启服务，或配置参数格式错误导致数据库连接失败。
- 现象：离线环境下执行版本升级时，提示依赖包缺失或数据库连接失败。原因：未提前下载对应版本的离线安装包，未将数据库镜像和数据完整备份至本地存储介质，导致升级过程中无法读取必要的配置与数据。
- 现象：查询供应商比价记录时返回结果为空或格式异常。原因：错误替换了数据库连接参数，或未正确配置数据库的访问权限，导致无法读取结构化的比价数据，或读取的数据字段与预期不匹配。

## 怎么确认配好了
- 执行FastGPT内置的数据库连接测试工具，验证`MONGODB_URI`、`PG_URL`、`REDIS_URL`等配置项可正常建立连接，无超时或权限报错。
- 提交一条模拟采购申请，查看数据是否正确写入对应数据库表，字段匹配采购申请文档的结构要求。
- 检查Redis缓存的采购审批状态是否能正常更新和读取，无缓存过期或写入失败的系统日志。
- 查看系统监控面板，确认数据库连接数未超过`DB_MAX_LINK`的设定值，无连接耗尽的告警信息。
