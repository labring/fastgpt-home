# SLA与服务报告的线上故障排查与复盘：定时任务与自动化
本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的数据来源为监控系统、工单系统、合同文本与客户沟通记录。更新节奏以月度或季度为周期，核心产出文档包含SLA条款、月度服务报告、可用性统计报表与客户复盘纪要。数据字段包含服务周期标识、SLA约定指标、异常事件关联信息、客户反馈记录，字段需匹配合同约定的服务条款，无固定统一的单位格式，需结合具体业务场景调整。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据更新以月度或季度为周期，定时任务的触发频率需匹配该节奏，避免过度执行浪费资源。多数据源的整合需求要求任务支持从监控、工单、合同等不同系统拉取数据，需预设数据格式校验规则，确保拉取的字段匹配SLA约定的口径。异常事件归因环节需关联多源数据，任务需内置关联逻辑，同时需配置失败重试与告警机制，避免因数据缺失或格式错误引发赔付争议。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发周期 | 月度 / 季度 | 匹配本品类数据更新的月/季频率，避免无效执行 |
| 数据源拉取超时阈值 | 300–600 秒 | 适配多系统拉取的网络延迟，防止单次任务超时中断 |
| 数据格式校验开关 | 开启 | 确保拉取的字段符合SLA条款约定的格式要求 |
| 异常事件关联规则 | 按工单编号与监控事件ID匹配 | 实现异常事件的精准归因，符合复盘需求 |
| 任务失败重试次数 | 2–3 次 | 应对临时网络波动或数据源临时不可用的情况 |
| 告警触发阈值 | 任务失败连续2次 | 及时通知相关人员处理异常，避免影响报告产出 |

## 容易做错的三处
- 现象：SLA分类调用次数统计字段为空，未随定时任务执行更新。原因：未配置变量更新的触发规则，仅在手动触发时更新统计变量。
- 现象：月度服务报告中出现多份文档冲突的异常事件描述，未提示异常。原因：未开启多源数据的冲突校验配置，未设置不同来源数据的口径对齐规则。
- 现象：定时任务执行完成后未向企业微信外部群发送通知。原因：未配置外部群的消息推送触发条件，仅开启了内部群的推送权限。

## 怎么确认配好了
- 查看定时任务列表，确认触发周期设置为月度或季度，与业务约定的报告周期一致。
- 手动触发一次测试任务，检查拉取的数据源字段是否匹配预设的SLA条款要求。
- 模拟一次数据源拉取失败，确认是否触发预设的告警规则。
- 检查变量更新配置，确认统计分类调用次数的变量已绑定定时触发更新逻辑。
