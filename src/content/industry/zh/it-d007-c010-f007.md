# 事件响应与故障处理的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
这个品类的数据来源于监控告警、日志平台、APM工具与用户反馈，更新节奏为实时或每次故障事件触发。日常关联文档包含故障工单、事件时间线、应急预案与故障通报，数据字段包含`chatId`、`responseChatItemId`、操作人账号、告警触发源、响应步骤、中断时长与结果状态，每条数据对应单次故障事件的完整对话与操作链路，无额外统计类百分比数据。

## 这些特征在「对话日志与审计」这一环带来什么约束
多源数据来源要求对话日志需支持跨平台数据的`chatId`关联聚合，确保单次故障事件的完整操作链路可溯源。实时更新节奏要求审计日志需支持实时落库，避免因客户端中断或请求超时导致数据丢失。文档与字段的结构化特征要求对话日志需绑定事件工单ID，方便按故障事件快速筛选查询。同时，由于出错后果涉及服务中断与监管压力，对话日志需具备不可篡改的存储机制，且需按运维团队职责划分隔离维度，防止敏感信息泄露。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId`绑定规则 | 绑定事件工单ID | 匹配品类数据的事件溯源需求，关联对话记录与故障工单 |
| `responseChatItemId`关联规则 | 绑定单条回复节点ID | 匹配单步操作的溯源需求，细化故障排查的链路追踪 |
| 对话日志存储周期 | `7 天` | 满足常规审计与复盘的周期需求，避免存储资源冗余 |
| `detail`字段采集范围 | 采集告警源、响应步骤、中断时长 | 覆盖品类核心业务环节的溯源需求，匹配故障排查的关键字段 |
| 用户会话隔离规则 | 按业务团队划分隔离维度 | 匹配运维团队的职责边界，防止跨团队日志泄露 |
| SSE中断后暂存机制 | 启用本地缓存暂存未完成内容 | 避免客户端关闭SSE导致对话记录丢失，适配实时更新的约束 |
| 历史对话查询上限 | `前 20 条` | 控制单事件查询的负载，适配多源数据的处理需求 |

## 容易做错的三处
- 现象：启动Docker容器后，Mongo连接失败且手动登录Mongo也失败，无法访问FastGPT 3000端口界面。原因：未将Mongo的账号密码与FastGPT配置项正确绑定，导致对话日志无法正常落库。
- 现象：客户端关闭SSE连接后，未完成的对话记录未存入数据库。原因：未启用本地缓存暂存机制，仅依赖实时请求落库，导致中断后数据丢失。
- 现象：按应用维度查询对话历史时返回过多冗余数据，无法快速定位目标事件。原因：未配置按`chatId`绑定事件工单的筛选规则，未限制查询范围。

## 怎么确认配好了
- 发起一次模拟故障排查对话，检查对话记录是否绑定了指定的事件工单ID。
- 模拟客户端关闭SSE的场景，查看本地缓存是否暂存未完成的对话内容，并在连接恢复后自动落库。
- 按业务团队维度查询对话记录，确认非授权团队无法查看其他团队的对话日志。
- 查看Mongo数据库的日志，确认对话记录已按配置的存储周期正常落库。
