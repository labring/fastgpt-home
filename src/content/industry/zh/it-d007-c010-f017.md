# 事件响应与故障处理的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
本品类的数据来自监控告警、日志平台、APM工具与用户反馈，更新节奏为实时或每次事件发生后即时同步。日常产出的文档包含故障工单、事件时间线、应急预案与故障通报，字段覆盖事件唯一标识、受影响服务范围、发生与恢复时间、根因分析结果、影响用户数等，无固定统计单位，仅按事件维度记录与更新。

## 这些特征在「部署与升级」这一环带来什么约束
本品类的数据多源且实时更新，且需持久化留存用于后续复盘，因此部署环节需保障数据库连接的稳定性，避免因连接中断导致事件数据丢失。同时，单次事件的文档包含多字段结构化记录，需配置足够的存储容量与合理的连接参数。此外，故障响应的时效性要求部署后的服务可用性达标，升级环节需支持无停机或滚动更新，避免影响正在处理的事件工单。若采用容器化部署，需配置持久化存储卷，防止断电等异常情况导致数据库数据损坏。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `DB_MAX_LINK` | 10-20 个 | 适配多源数据实时写入的并发需求，避免连接耗尽导致的数据写入失败 |
| `MONGODB_URI` | mongodb://user:pass@host:port/dbname?authSource=admin | 存储事件时间线与故障通报的非结构化数据，需配置认证信息保障数据安全 |
| `PG_URL` | postgresql://user:pass@host:port/dbname?sslmode=require | 存储故障工单、应急预案等结构化业务数据，SSL模式保障传输安全 |
| `REDIS_URL` | redis://:pass@host:port/0 | 缓存实时告警与用户反馈数据，降低数据库查询压力 |
| `ROOT_KEY` | 随机生成的32位字符串 | 配置系统管理员权限密钥，保障后台操作的安全性 |
| `STORAGE_S3_ENDPOINT` | 按实际存储服务地址填写 | 存储故障相关的日志、截图等附件数据，适配多环境存储需求 |

## 容易做错的三处
- 现象：容器化部署后断电重启，PG或MongoDB服务无法启动，日志显示连接拒绝或数据文件损坏。原因：未配置持久化存储卷，容器内数据随容器销毁丢失，重启后无法读取原有业务数据。
- 现象：通过docker compose部署后无法注册新用户，后台无明显报错提示。原因：未配置公开注册开关，或未正确配置用户权限相关参数，导致新用户注册流程被拦截。
- 现象：配置第三方模型密钥后无法正常调用，对话界面返回空结果或403状态码。原因：未正确配置模型密钥的环境变量，或密钥权限不足，无法完成模型接口调用验证。

## 怎么确认配好了
- 执行容器启动命令，查看服务日志中数据库连接相关的报错信息，确认无连接失败或认证失败提示。
- 尝试创建一条测试故障工单，填写完整字段后提交，确认数据成功写入数据库且可在后台查询到。
- 配置第三方模型密钥后发起测试对话，确认接口返回正常响应内容，无权限或连接超时报错。
- 模拟断电重启场景，验证容器重启后数据库服务可正常启动，原有故障工单数据未丢失。
