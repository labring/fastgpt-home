# 云主机交付与资源开通的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
该品类的数据主要来自云管理平台、订单系统、IAM权限系统与计费系统，更新节奏为每单实时同步。日常关联的业务文档包括资源开通单、实例配置表、账号权限单与交付确认单，数据字段通常包含实例唯一标识、开通时间、计算规格、权限范围、计费项等，其中实例标识为字符串格式，计算规格以vCPU核数、内存GB为单位，订单号为数字串格式。

## 这些特征在「对话日志与审计」这一环带来什么约束
多源数据来源要求对话日志需整合云管理平台、订单系统、IAM与计费系统的业务标识，避免出现关联断层。实时/每单的更新节奏要求审计日志需同步留存每笔订单的交互过程，无法批量延后存储。多样的业务文档结构要求日志需关联对应单据的字段，便于直接定位规格核对、权限配置等环节的问题。出错后果的严重性要求日志需保留完整的交互链路，支撑故障发生后的全流程溯源。不同于云网络与负载均衡配置品类，该品类仅聚焦计算资源的交付，日志无需关联过多网络配置字段，进一步简化了审计范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chatId` | 绑定云主机实例ID | 每笔云主机交付订单对应唯一实例标识，可通过`chatId`关联交互日志与业务单据，实现精准溯源，适配FastGPT v4.17.0的工作流配置规则 |
| `responseChatItemId` | 绑定每轮LLM回复的唯一标识 | 便于定位偶发的空响应或超时问题，匹配该品类的多轮交互链路特征 |
| `detail` | 存储全量交互内容与关联单据ID | 覆盖该品类的核心业务文档字段，满足审计与故障复盘的完整记录需求 |
| 聊天记录最大条数 | 前20-30条 | 该品类的交互围绕资源开通、配置核对展开，20-30条可覆盖完整流程，适配业务实际长度 |
| 日志留存时长 | 180天 | 匹配故障复盘与合规审计的常规需求，符合该品类的业务更新频率 |

## 容易做错的三处
- 现象为工作流中“代码运行”节点输入包含历史记录时校验失败，无法执行。原因是未正确配置`chatId`与工作流变量的绑定规则，导致历史记录参数未被系统正确识别。
- 现象为LLM响应为空，偶发卡住10秒后报错，通过第三方调用工具无对应日志。原因是未开启`detail`字段的全量日志存储，无法定位偶发的接口调用超时或参数缺失问题。
- 现象为聊天记录默认仅保留50条，超出后前置的规格核对记录被截断。原因是未根据该品类的业务交互长度调整配置，导致关键的业务前置信息丢失。

## 怎么确认配好了
- 查看交互日志列表，确认每条日志均关联了云主机实例ID与对应订单号，验证`chatId`的绑定配置已生效。
- 触发一次模拟的资源开通流程，检查每轮LLM回复是否带有唯一标识，确认`responseChatItemId`的关联配置可正常工作。
- 查看日志存储详情，确认`detail`字段已存储完整的交互内容与关联的业务单据信息，验证全量记录配置正确。
- 调整聊天记录条数配置，根据该品类的实际交互长度验证修改后的留存规则可正常生效。
