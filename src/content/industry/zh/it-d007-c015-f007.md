# 产品使用数据分析的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
这个品类的数据主要来自埋点系统、数据仓库、CRM与工单系统，更新节奏多为日级或周级。日常关联文档包含使用分析报告、埋点方案、指标口径表与看板需求单，数据字段通常包含会话标识、响应项标识、详细操作记录、关联客户ID、功能模块、操作时间等，单位多为条、次、符合预设格式的时间戳，需严格匹配预设的指标口径定义。

## 这些特征在「对话日志与审计」这一环带来什么约束
数据来源的多样性要求对话日志与审计环节需支持跨系统数据的关联校验，确保日志完整覆盖埋点、业务操作与客户交互全链路。更新节奏的日/周级属性，决定了审计任务需匹配对应调度周期，避免过度占用计算资源。关联文档的复杂性要求审计过程需留存字段与指标口径的溯源记录，便于后续核对。跨客户的功能行为洞察属性，要求审计配置需支持细粒度的权限隔离，防止敏感数据泄露。异常排查的高耗时特性，要求审计工具需提供快速定位异常会话的筛选能力。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` 关联规则 | 按会话唯一标识关联全链路日志 | 确保单会话的操作与响应可完整追溯 |
| `responseChatItemId` 保留上限 | 保留前20条响应记录 | 覆盖主要功能交互的审计需求，避免存储冗余 |
| `detail` 日志采集开关 | 开启全字段采集 | 满足指标口径与异常排查的溯源要求 |
| 审计调度周期 | 按数据更新频率设为每日或每周 | 匹配数据产出节奏，降低资源消耗 |
| 权限隔离范围 | 按客户分组配置访问权限 | 符合跨客户洞察的数据安全要求 |
| 日志存储阈值 | 按磁盘容量设为1000 GB | 避免存储空间被审计日志耗尽 |

## 容易做错的三处
- 模型渠道调用返回 `error` 且调用日志显示数据获取异常。原因是未按`chatId`关联埋点与业务日志，导致无法定位数据来源的口径偏差。
- 网页分享应用后无法取回历史对话记录。原因是未开启`detail`字段的持久化存储，导致会话关联数据被临时清理。
- Docker部署场景下误删核心审计日志文件。原因是未区分`detail`字段的审计日志与临时缓存文件，错误清理了审计所需的全量记录。

## 怎么确认配好了
- 随机选取1条会话记录，核对`chatId`是否同时出现在埋点日志与业务工单系统中，确认跨源关联生效。
- 查看审计任务的调度日志，确认执行周期与数据更新周期匹配，无重复或遗漏执行的情况。
- 验证不同客户分组的账号，确认仅能访问对应分组的会话日志，权限隔离配置生效。
- 导出单条会话的`detail`字段日志，确认包含完整的操作步骤与响应内容，满足溯源需求。
