# 众包标注人员管理的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
该品类的数据主要来自众包平台后台、标注质量统计系统、人员培训考试记录与财务结算系统。日常关联文档包含人员准入规则、岗位培训材料、月度绩效表与结算清单。数据更新节奏以日度和月度为主，覆盖人员资质、标注质量、考核结果与结算明细等字段，字段包含人员ID、标注任务量、合格率、结算金额等，无额外自定义单位。

## 这些特征在「对话日志与审计」这一环带来什么约束
由于数据来源分散且覆盖人员资质、标注质量、财务结算多类信息，对话日志需支持按人员ID、任务批次、结算周期等多维度关联检索。数据更新节奏分日度和月度，日志需支持按精确时间区间筛选，避免跨周期数据混淆。日常关联文档与日志需绑定对应人员与任务，审计时需验证日志内容与准入规则、绩效表的一致性，因此需保留完整的对话链路与操作痕迹，不可截断或篡改。同时，出错后果涉及标注质量波动与结算错漏，日志需留存足够细节以定位问题根源，需避免日志字段缺失或不完整。

## 配置怎么定
本文适配FastGPT v4.17.0版本的配置逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定任务批次与人员ID的组合ID | 用于关联同批次标注人员的所有对话日志，实现按任务或人员维度检索 |
| `responseChatItemId` | 保留完整会话节点ID | 用于追溯单条标注对话的完整交互链路，匹配标注质量数据中的单任务结果 |
| `detail` | 开启全量日志存储 | 留存对话中的人员资质查询、结算核对等细节，满足审计溯源要求 |
| 单次日志存储上限 | 1000 MB | 适配月度结算数据与批量标注日志的存储需求，避免磁盘溢出 |
| 日志检索时间范围 | 近30天 / 近180天 | 匹配日度和月度的数据更新节奏，便于跨周期排查问题 |
| 审计日志导出格式 | CSV格式 | 便于与财务系统的结算清单进行批量核对与校验 |

## 容易做错的三处
- 现象：检索日志时出现跨任务批次的无关数据，原因：未使用`chatId`绑定任务批次与人员ID，仅按通用会话ID检索，导致数据范围混乱。
- 现象：审计日志中无法追溯结算核对的完整对话，原因：未开启`detail`全量日志存储，仅保留了基础交互内容，无法覆盖结算相关的操作细节。
- 现象：调用日志返回数据库连接失败，且数据库服务状态正常，原因：未正确配置日志存储的数据库连接参数，或容器网络策略限制了日志组件与数据库的通信。

## 怎么确认配好了
- 检索指定任务批次的日志，验证返回结果仅包含对应批次的人员对话数据，确认`chatId`配置生效。
- 查看单条会话的日志详情，确认包含完整的交互链路与`responseChatItemId`字段，验证节点追溯功能正常。
- 导出审计日志，检查是否包含人员ID、任务批次、结算金额等关键字段，确认`detail`存储配置正确。
- 模拟内网环境下的日志写入操作，验证日志可正常存储且无字段缺失，确认存储参数配置无误。
