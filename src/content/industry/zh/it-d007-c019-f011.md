# 众包标注人员管理的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
众包标注人员管理的业务数据主要来自众包平台、标注质量数据、培训考试系统与财务系统。日常维护的文档包含人员准入规则、培训材料、绩效表与结算清单。数据更新频率多为日度或月度，核心耗时环节包括人员筛选、质量排名与结算核对。数据结构包含人员基础信息、标注质量得分、培训考核结果与财务结算明细，该品类聚焦人力组织与绩效结算相关的全流程数据，与文本标注类项目的品类特征存在明显差异。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据接入要求数据库支持跨表关联查询，以完成人员筛选、质量排名与结算核对的跨系统数据整合。日度或月度的批量数据更新，要求数据库具备稳定的批量写入与事务支持能力，避免结算核对环节出现数据不一致。核心耗时环节的高并发查询需求，需要数据库配置合理的连接池与索引优化，防止因查询压力过大导致系统响应延迟。此外，数据直接关联人员绩效与财务结算，一旦出现错误会引发错付漏付或项目延期，要求运维环节优先保障数据准确性与可恢复性，配置完善的备份与回滚机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 单节点部署：`mongodb://[用户名]:[密码]@[主机]:27017/fastgpt`；生产副本集部署：`mongodb://[用户名]:[密码]@[主机1]:27017,[主机2]:27017,[主机3]:27017/fastgpt?replicaSet=rs0` | 存储标注对话历史、人员操作日志等非结构化数据，单节点适配本地测试，副本集保障生产环境的高可用性 |
| `PG_URL` | `postgresql://[用户名]:[密码]@[主机]:5432/fastgpt` | 存储人员绩效表、结算清单、准入规则等结构化数据，PostgreSQL支持复杂多表关联查询，适配人员筛选与质量排名的业务需求 |
| `DB_MAX_LINK` | `200–300 个并发连接` | 支撑批量结算核对、人员质量排名的高并发查询需求，避免连接耗尽导致的服务中断 |
| `REDIS_URL` | `redis://[密码]@[主机]:6379/0` | 缓存高频访问的人员名单、绩效排名数据，降低数据库的重复查询压力，提升核心环节的响应速度 |

## 容易做错的三处
- 启动时报错“副本集未配置”，原因是本地单节点部署时误保留了副本集配置参数，未根据实际部署场景调整`MONGODB_URI`的内容。
- 无法在MongoDB中查看标注对话历史记录，原因是`MONGODB_URI`未正确指定数据库命名空间，导致数据写入错误库或未关联到对应标注项目的对话数据。
- 本地Windows 10部署时无法连接MongoDB，原因是`MONGODB_URI`中的主机地址、端口或认证信息配置错误，未匹配本地MongoDB的实际运行参数。

## 怎么确认配好了
- 执行FastGPT v4.17.0内置的数据库连通性检测工具，验证`MONGODB_URI`、`PG_URL`的连接状态是否正常。
- 提交一条测试人员准入记录，检查MongoDB与PostgreSQL中是否生成对应的数据条目，验证数据库写入功能正常。
- 发起批量绩效查询操作，观察系统响应时间，确认`DB_MAX_LINK`配置可支撑并发查询需求，无连接耗尽报错。
- 查看Redis监控指标，确认缓存命中率处于合理区间，验证`REDIS_URL`配置的缓存功能正常生效。
