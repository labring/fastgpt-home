# 供应链安全与开源依赖治理的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自包管理器、代码仓库、公开漏洞库与许可证数据库，更新节奏为每日同步或随代码版本发布更新。日常产出的文档包含SBOM清单、依赖风险报告、许可证清单与修复工单，核心字段包括依赖包名称、版本号、漏洞CVE编号、许可证类型、风险影响等级，无固定统计单位，字段数量与类型随资产扫描范围动态调整。

## 这些特征在「定时任务与自动化」这一环带来什么约束
该品类的数据来源分散且覆盖范围广，单次全量扫描耗时较长，因此定时任务需合理划分执行窗口，避免占用核心业务资源。更新节奏兼具每日同步与版本触发两种模式，自动化任务需同时适配两种触发逻辑。文档字段关联紧密，自动化流程需校验依赖包名、漏洞信息、许可证类型等字段的完整性，防止遗漏关键风险项。任务执行失败可能引发高危依赖上线或许可证违规，需配置失败后的自动重试与人工告警链路。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务执行窗口 | `22:00–06:00` | 避开业务高峰时段，减少对线上服务的资源占用，适配FastGPT v4.17.0的调度规则 |
| 触发时机 | 每日固定时间 + 代码版本推送触发 | 适配每日同步与版本更新两种数据更新节奏，覆盖全量与增量扫描场景 |
| 扫描并发数 | `2–4 线程` | 平衡扫描效率与服务器资源消耗，按实测标定 |
| 失败重试次数 | `2 次` | 避免单次临时网络波动导致任务失败，减少无效重试对资源的占用 |
| 字段校验范围 | 依赖包名、版本号、漏洞等级 | 覆盖核心风险识别的必要字段，降低误报率 |
| 告警触发阈值 | 高危漏洞数量 ≥1 条 | 优先响应最紧急的供应链安全风险，符合线上故障排查优先级 |

## 容易做错的三处
- 现象：定时任务执行后返回`404: not found`报错，日志显示依赖包索引请求失败。原因：未配置包管理器镜像源的自动切换逻辑，在跨区域扫描时无法访问默认源地址。
- 现象：自动化生成的SBOM清单中图片链接缺失域名前缀，仅保留相对路径。原因：未在扫描配置中开启静态资源域名自动补全功能，仅在手动导入流程中生效。
- 现象：静态页面更新后未同步到知识库依赖风险报告。原因：未配置版本推送触发的增量扫描任务，仅依赖每日全量扫描，无法及时响应页面内容变化。

## 怎么确认配好了
- 手动触发一次定时任务，查看任务执行日志，确认配置的校验字段已被纳入扫描范围。
- 模拟一次代码版本推送，验证任务是否按配置的触发逻辑执行。
- 构造一个包含高风险项的依赖组合，验证任务失败后是否触发预设的告警流程。
- 查看自动化生成的文档，确认静态资源链接已按配置补全相关信息。
