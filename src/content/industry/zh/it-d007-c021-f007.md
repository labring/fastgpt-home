# 供应链安全与开源依赖治理的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
本品类的数据主要来源于包管理器、代码仓库、漏洞库与许可证数据库，更新频率为每日或每版本发布时。日常产出的文档包括SBOM清单、依赖风险报告、许可证清单与修复工单，数据字段通常包含依赖包名、版本号、漏洞CVE ID、许可证类型、关联应用标识与更新时间等，用于支撑安全团队、研发效能团队的依赖治理工作。

## 这些特征在「对话日志与审计」这一环带来什么约束
本品类的数据多源且更新频率为每日或每版本，要求对话日志必须绑定对应应用的依赖资产上下文，否则无法精准追溯依赖变更或风险事件。日常产出的文档字段结构复杂，审计日志需完整保留依赖相关的核心字段，以匹配业务排查与合规校验的需求。由于出错后果涉及高危依赖上线与许可证违规，对话日志的留存与查询需满足安全追溯的基本要求，同时需避免因多源数据关联导致的查询性能损耗。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定对应应用的SBOM清单唯一标识 | 关联多源依赖数据，确保日志匹配具体应用的依赖上下文 |
| `responseChatItemId` | 每轮依赖分析对话生成唯一ID，保留 7 天 | 追溯单轮漏洞匹配或许可证校验的完整链路 |
| `detail` | 包含依赖包名、版本号、CVE ID、许可证类型，单条日志不超过 2000 字符 | 匹配业务文档的字段结构，保留完整依赖审计信息 |
| 对话日志留存时长 | 30–90 天 | 匹配依赖更新的日/每版本频率，满足安全团队的追溯需求 |
| 审计查询结果上限 | 前 1000 条 | 避免单次查询返回过多数据导致性能损耗 |

## 容易做错的三处
- 现象：查询某用户的历史依赖审计记录时无匹配结果。原因：未通过`chatId`绑定用户与对应应用的依赖资产关联关系，导致日志未关联到具体用户或应用上下文。
- 现象：删除对话会话后，关联的依赖审计日志同步消失。原因：审计日志与对话会话绑定了强关联删除逻辑，未保留依赖审计的独立归档数据。
- 现象：按应用统计模型tokens消耗时无法拆分结果。原因：未配置`detail`字段关联应用与token消耗的绑定关系，导致无法按应用维度聚合统计数据。

## 怎么确认配好了
- 发起基于`chatId`的查询测试，验证可返回绑定对应应用的依赖审计日志。
- 执行单条对话会话删除操作，验证关联的审计日志未被自动清除。
- 发起按应用维度的tokens消耗统计查询，验证结果可按应用维度聚合展示。
- 查看FastGPT v4.17.0的审计日志存储配置，确认其存储路径与对话会话的存储路径相互独立。
