# 供应链安全与开源依赖治理的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
该品类的数据主要来自包管理器、代码仓库、漏洞库与许可证数据库。日常产出的文档包含SBOM清单、依赖风险报告、许可证清单与修复工单，核心字段包括第三方组件名称、版本号、关联漏洞编号、许可证类型、风险等级与影响范围。数据更新频率为每日或每版本发布时同步，覆盖当前部署的所有开源依赖资产，适用于FastGPT v4.17.0版本的本地化部署场景。

## 这些特征在「数据库与运维」这一环带来什么约束
多来源的数据接入要求数据库兼容多种结构化格式的批量写入，高频的每日/版本级更新会带来持续的写入压力，需预留足够的连接与存储资源。多字段的文档结构需要针对性建立索引，避免全表扫描拖慢查询速度。不同类型的风险报告与工单数据需按业务场景分表存储，降低单表数据量。同时，数据异常会直接影响依赖治理结果，需保障数据库的高可用与故障快速恢复能力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | 内网可访问的MongoDB连接地址，如`mongodb://user:pass@host:27017/fastgpt` | 适配离线部署场景，避免外网依赖 |
| `PG_URL` | 内网可访问的PostgreSQL连接地址 | 用于存储许可证清单与修复工单数据 |
| `DB_MAX_LINK` | 64–128 个连接 | 匹配64核以上服务器的并发处理能力，避免连接耗尽 |
| `REDIS_URL` | 内网可访问的Redis连接地址 | 用于缓存高频查询的依赖风险数据 |
| 数据库备份周期 | 每日 0 点 | 匹配数据日更节奏，保障故障后可恢复至最近的完整数据 |
| 批量写入阈值 | 50–100 条/次 | 平衡写入效率与服务器IO负载，适配高频的SBOM数据导入 |

## 容易做错的三处
- 重启后出现`getaddrinfo EAI_AGAIN mongo`报错：现象为服务启动时无法解析MongoDB地址，无法建立数据库连接。原因是`MONGODB_URI`配置的域名未正确写入本地hosts文件，或本地DNS缓存未及时更新。
- 写入依赖数据时进程卡住、硬盘使用率持续达100%，或 SBOM 清单导入超时，需要区分磁盘容量、I/O 等待、数据库锁、任务队列与上游响应。先核对监控和任务日志，不能据此认定缺少自动清理规则；存储需求按数据规模、索引与保留周期测算，不设置未经验证的统一容量下限。
- 依赖风险报告查询延迟过高：现象为查询结果返回时间超过30秒，或部分字段为空。原因是未按组件名称、版本号建立联合索引，导致数据库执行全表扫描，拖慢查询速度。

## 怎么确认配好了
- 执行数据库连接测试命令，验证`MONGODB_URI`与`REDIS_URL`配置的地址可正常建立连接，无超时或解析错误。
- 查看磁盘容量与 I/O 监控；20%剩余容量仅作运维预警示例，按实际增长速度标定。若部署自行设置清理任务，应先在隔离环境核对备份、清理范围与恢复流程。
- 发起一次依赖数据导入测试，使用50–100条的批量写入阈值，确认写入延迟符合预期，无IO阻塞情况。
- 发起一次风险报告查询，确认返回结果完整，延迟在可接受范围内。
