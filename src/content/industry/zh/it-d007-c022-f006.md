# 信创替代适配的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
这个品类的数据主要来自现有系统清单、国产软硬件目录、测试环境及厂商公开资料。日常产出的文档包括适配清单、兼容性测试报告、迁移方案与问题台账，其中适配清单需记录软硬件名称、版本号、兼容验证结果，兼容性测试报告需标注测试场景与异常项。数据更新以单个信创迁移项目为周期，或按季度同步国产软硬件目录的最新版本，未完成的迁移项目数据会随阶段推进更新。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据来源分散且需跨系统拉取，定时任务需匹配国产软硬件目录的更新节奏，避免过度拉取占用资源。不同文档的字段要求存在差异，自动化流程需校验适配清单、测试报告等文档的必填字段完整性，防止无效数据流入后续环节。数据更新以项目或季度为周期，定时任务的执行频率不宜过高，同时需针对迁移风险评估环节的延迟数据，设置合理的超时等待阈值，保障流程稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 定时任务触发周期 | 按项目阶段调整，迁移准备期设为7天，迁移实施期设为1天 | 匹配国产软硬件目录的季度更新节奏与项目推进周期，适配FastGPT v4.17.0的调度逻辑 |
| 自动化校验阈值 | 前3条异常项触发告警 | 适配清单的异常项需及时同步至问题台账，避免遗漏迁移风险 |
| 异步任务超时时间 | 1800秒 | 兼容兼容性测试的全量扫描时长，避免中途中断任务 |
| 失败重试次数 | 2次 | 平衡拉取失败的重试成本与流程执行效率 |
| 任务日志留存时长 | 90天 | 匹配季度数据更新的审计周期要求，便于后续问题复盘 |

## 容易做错的三处
- 定时任务未按项目节奏触发，界面显示任务状态为「未执行」。原因是触发周期设置与国产软硬件目录更新节奏不匹配，未根据项目阶段调整参数。
- 异步兼容性测试任务超时终止，日志显示「参数缺失」。原因是未校验适配清单的必填字段，导致任务执行时缺少软硬件版本信息。
- 自动化迁移后的问题台账未同步更新，显示字段为空。原因是未配置stream回复完毕后的回调触发逻辑，导致数据同步延迟。

## 怎么确认配好了
- 查看定时任务调度日志，确认近一个周期内的任务执行记录与设置的触发周期一致。
- 模拟触发一次异步校验任务，检查日志中是否包含适配清单、测试报告的字段校验结果。
- 手动触发一次失败重试流程，确认异常任务在重试后是否能正常完成。
- 查看任务日志留存目录，确认近90天的执行日志已正常归档。
