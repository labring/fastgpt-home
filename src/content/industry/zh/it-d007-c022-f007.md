# 信创替代适配的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
这个品类的数据主要来自现有系统清单、国产软硬件目录、测试环境与厂商公开资料。日常关联文档包括适配清单、兼容性测试报告、迁移方案与问题台账。数据更新节奏以单项目周期或季度为单位，字段覆盖软硬件型号、兼容性验证结果、迁移步骤与故障记录，无统一强制格式，需贴合项目实际场景整理。

## 这些特征在「对话日志与审计」这一环带来什么约束
由于数据来源覆盖现有系统清单、国产软硬件目录等多类分散资源，对话日志需支持关联不同来源的适配验证记录与问题台账。更新以单项目或季度为周期，无需高频实时归档，但需留存完整链路的审计轨迹，便于跨周期复盘。字段无统一强制格式，日志采集需兼容自定义字段，同时需补充软硬件型号、迁移步骤等上下文信息。涉及国产化适配的合规审计，日志需留存完整的调用链路与参数变更记录，避免出现字段缺失或内容截断。

以下内容基于FastGPT v4.17.0版本编写。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定项目适配唯一标识 | 将对话日志与单项目的适配清单、迁移方案关联，实现按项目维度审计 |
| `responseChatItemId` | 关联单条软硬件验证请求 | 精准追踪单条兼容性测试的交互过程，定位故障触发节点 |
| `detail` | 存储800–1200字符的上下文信息 | 适配字段无统一格式的场景，补充软硬件型号、测试环境参数等内容 |
| 日志保留时长 | 90天 | 匹配单项目周期与季度更新频率，满足跨周期复盘需求 |
| 全量日志采集开关 | 开启 | 故障排查需完整交互链路，避免遗漏适配过程中的异常调用 |
| 审计关键词配置 | 按适配故障关键词库匹配 | 快速筛选出包含兼容性报错、参数不匹配的日志条目 |

## 容易做错的三处
- 现象：前端界面输出内容不完整，日志中无报错信息，刷新页面后可显示完整内容。原因：未开启`detail`字段的完整上下文存储，导致日志截断，前端渲染时无法加载完整交互数据。
- 现象：无法按项目维度筛选适配过程中的对话日志。原因：未绑定`chatId`到项目适配标识，导致日志与项目文档无法关联，审计维度缺失。
- 现象：无法统计适配过程中的高频问题或token使用量。原因：未配置`responseChatItemId`关联单条请求，且未开启全量日志采集，无法获取完整的交互数据用于统计。

## 怎么确认配好了
- 查看`chatId`字段是否与项目适配标识一致，确认日志与项目文档的关联关系。
- 随机抽取一条适配对话日志，检查`detail`字段是否包含所需的上下文信息，验证存储长度符合配置要求。
- 触发一次兼容性测试请求，确认`responseChatItemId`字段已正确关联该请求，可精准定位交互节点。
- 查看日志保留时长配置，确认符合项目周期与审计需求，无提前清理的情况。
