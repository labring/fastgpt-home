# 值班排班与交接的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
本品类的数据来源包括排班系统、故障工单、监控告警与组织通讯录，更新频率为日或周。日常产出的文档包含值班表、交接记录、升级联系人清单、值班日报，字段涵盖值班时段、未结交接事项、关联故障单号、升级联系人信息与联系方式，未包含额外统计类数值。

## 这些特征在「对话日志与审计」这一环带来什么约束
本品类的数据来源分散且关联多业务系统，要求对话日志需绑定对应排班系统ID、故障工单编号与告警标识，确保审计时可快速定位关联业务节点。更新频率为日或周，审计周期需匹配该节奏，避免日志留存周期过短或过长。日常文档包含多类结构化内容，对话日志需覆盖排班协调、未结事项交接、升级路径确认等核心环节的完整对话，同时需留存升级联系人的沟通记录，确保交接环节无遗漏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 对话日志存储周期 | 7 天 | 匹配本品类周度更新的值班文档节奏，覆盖完整值班周期的审计需求 |
| `chatId`绑定规则 | 绑定对应排班系统的值班组ID | 确保日志可关联到具体值班团队，便于按组追溯交接与排查记录 |
| `detail`字段采集范围 | 包含未结事项、升级路径、排班冲突协调内容 | 覆盖本品类最耗时的三个核心环节，满足审计的完整追溯需求 |
| `responseChatItemId`关联规则 | 绑定故障工单的唯一编号 | 实现对话与具体故障的精准关联，便于复盘时快速定位问题处理链路 |
| 单次审计查询上限 | 前 20 条 | 匹配值班团队的日常排查规模，避免查询资源过度占用 |
| 单条日志最大大小 | 100 KB | 避免存储资源过度占用，适配日常对话的内容长度 |
| 审计日志触发间隔 | 60 秒 | 匹配监控告警的实时推送节奏，确保故障对话及时留存 |
| 日志导出格式 | Markdown 格式 | 可直接导入值班日报文档，贴合本品类日常文档的使用习惯，适配FastGPT v4.17.0的导出接口 |

## 容易做错的三处
- 现象：对话日志中仅显示系统指令内容，无用户原始提问记录，`detail`字段为空。原因：未开启`detail`字段的全量采集配置，仅采集了系统预设指令而遗漏用户的原始提问内容。
- 现象：排班冲突协调的对话未被审计日志捕获，审计结果条数为0。原因：未将排班系统ID绑定到`chatId`，导致日志无法关联到具体值班场景，触发过滤规则被排除。
- 现象：提交故障排查对话后操作按钮持续无法响应，查看系统日志显示上传成功但无后续日志生成。原因：未配置`responseChatItemId`与故障工单的绑定规则，导致系统无法完成审计日志的提交校验，阻塞操作流程。

## 怎么确认配好了
- 随机选取当日的值班交接对话，检查`detail`字段是否包含未结事项、升级路径等核心内容，确认采集范围符合配置要求。
- 导入一个测试排班系统ID，验证`chatId`是否正确绑定到对应值班组，确保日志可按组筛选。
- 提交一个模拟故障工单的对话，检查`responseChatItemId`是否关联到工单编号，验证审计日志的触发逻辑。
- 查看日志存储目录，确认已生成对应周期的审计日志文件，匹配配置的存储周期要求。
