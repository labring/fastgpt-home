# 值班排班与交接的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
该品类的数据来源包括排班系统、故障工单、监控告警、组织通讯录，更新频率为日或周。核心文档包含值班表、交接记录、升级联系人清单、值班日报，其中值班表包含日期、值班人员、联系方式字段，交接记录包含未完成任务、待跟进故障、升级路径字段，升级联系人清单包含岗位、姓名、紧急联系方式字段，值班日报包含当日故障处理情况、交接事项汇总字段。

## 这些特征在「数据库与运维」这一环带来什么约束
由于数据来源多样且包含文档型、结构化两种类型，数据库配置需要兼容不同存储引擎的连接需求。数据更新频率为日或周，要求数据库连接支持增量同步或定时全量同步，避免重复加载全量数据。核心文档包含多个关联字段，需要为关键字段配置约束以避免冲突。同时，高频查询的值班人员联系方式、当日升级路径需要缓存以降低数据库压力，连接池配置需要匹配日均读写请求量，避免连接耗尽导致的服务中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:port/database?authSource=admin` | 适配非结构化的交接记录、临时值班调整笔记的存储需求 |
| `PG_URL` | `postgresql://user:pass@host:5432/fastgpt?schema=public` | 存储结构化的值班表、升级联系人清单、值班日报等带明确字段的文档 |
| `DB_MAX_LINK` | `15–25 个` | 匹配日均值班排班数据的读写并发量，避免连接池耗尽导致的请求排队 |
| `REDIS_URL` | `redis://default:password@host:6379/1` | 缓存高频查询的当日值班排班、升级联系人信息，降低数据库查询延迟 |

## 容易做错的三处
- 现象：工作流中数据库连接显示“connect ETIMEDOUT”，本地可访问对应数据源但FastGPT中失败。原因：未将排班系统、监控告警的数据源IP加入FastGPT所在环境的安全白名单，或配置的`PG_URL`、`REDIS_URL`中指定的端口未开放。
- 现象：同一工作流使用FastGPT v4.17.0时，数据库连接耗时远高于旧版。原因：`DB_MAX_LINK`配置过低，连接池耗尽导致请求排队等待，或未配置增量同步导致每次查询加载全量值班排班数据。
- 现象：出现重复值班记录，未触发排班冲突提示。原因：未在`PG_URL`对应的数据库中为值班日期与值班人员组合字段添加唯一约束，或未开启定时冲突校验任务。

## 怎么确认配好了
- 登录FastGPT的数据库配置页面，测试`MONGODB_URI`、`PG_URL`、`REDIS_URL`的连通性，查看返回的连接成功提示。
- 调用测试接口查询值班表数据，确认返回字段与值班表、交接记录的预设结构一致，无缺失或异常字段。
- 模拟多并发的排班查询请求，观察连接池使用情况，确认连接数未超出`DB_MAX_LINK`的配置阈值。
- 检查FastGPT与关联数据库的运行日志，确认无频繁的连接超时、连接耗尽或数据同步失败报错。
