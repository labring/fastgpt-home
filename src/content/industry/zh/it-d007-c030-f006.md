# 内部网络与WiFi运维的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据来源包括交换机控制台、无线控制器、企业监控系统与用户报障工单。数据更新节奏为每日或每次网络变更后。日常运维文档包含网络拓扑图、变更审批单、故障归档记录、无线覆盖巡检表。数据字段包含端口编号、VLAN标识、无线信号强度值、巡检时间戳与故障点位坐标，单位包括dBm、端口号与标准时间戳格式。

## 这些特征在「定时任务与自动化」这一环带来什么约束
该品类的数据来源分散且涉及硬件设备接口，定时任务需兼容多源数据拉取的权限与协议适配，避免频繁调用超出设备接口限制。数据更新以日度或单次变更后为准，定时周期需匹配更新节奏，避免重复拉取冗余历史数据。日常文档格式差异较大，自动化流程需适配拓扑图、巡检表等多类型文档的结构化解析，需预留字段校验逻辑，适配端口号、信号强度dBm等专用单位的参数匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发周期 | 300–1800 秒 | 匹配数据日度或变更后的更新节奏，避免频繁调用占用设备接口 |
| 拉取数据范围 | 最近1次变更/当日数据 | 适配数据更新频率，减少冗余数据处理量 |
| 异常告警阈值 | 信号强度低于-85dBm | 匹配无线运维的信号质量标准，快速定位覆盖盲区 |
| 任务失败重试次数 | 2–3 次 | 平衡接口波动影响与系统资源消耗 |
| 结构化解析规则 | 按巡检表字段映射 | 适配日常文档的固定字段结构，提升解析准确率 |
| 日志留存时长 | 30 天 | 匹配故障复盘的归档要求，便于后续排查溯源 |

## 容易做错的三处
- 现象：设置定时触发间隔为3000毫秒，触发频率过高导致交换机接口请求被拦截。原因：未匹配品类数据更新节奏，过度频繁调用硬件接口。
- 现象：添加自定义网络运维插件后，工作流中无输入输出参数显示，无报错日志。原因：未按照品类文档的字段映射规则配置插件参数，未绑定端口号、VLAN ID等专用字段。
- 现象：执行升级脚本时返回POST /api/admin/initv4818 404错误。原因：未在对应版本的部署目录下执行升级命令，或升级脚本路径配置错误。

## 怎么确认配好了
- 查看FastGPT v4.17.0的定时任务执行日志，确认拉取的数据来源与范围符合配置要求，核对拉取时间间隔与设定值一致。
- 手动触发一次自动化任务，检查是否能正确解析巡检表、拓扑图等文档，生成符合字段要求的结构化数据。
- 模拟异常场景，比如无线信号低于设定阈值，确认告警触发与重试逻辑正常执行。
- 检查升级脚本执行路径，确认对应版本的初始化接口可正常调用，无404类报错。
