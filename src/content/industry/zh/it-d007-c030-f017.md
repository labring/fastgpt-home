# 内部网络与WiFi运维的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
该品类的数据来源为交换机控制台、无线控制器、办公区监控系统与终端用户报障信息，更新频率为每日或每次网络变更后。日常维护文档包含网络拓扑图、变更单、故障记录与无线覆盖巡检表，数据字段包含故障发生时间、接入AP编号、所属VLAN、终端MAC地址、报障人联络信息等，无额外统计类量化指标。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据来源分散且依赖硬件设备与人工报障，部署阶段需预留多类数据源对接的配置项，确保可接入交换机、无线控制器的日志接口。日常维护文档的结构固定，部署时需支持导入标准化格式的网络拓扑与巡检表文件。数据更新频率随运维动作动态变化，升级环节需保证数据同步服务不中断，避免故障排查时出现数据缺失。同时，故障记录的字段需与运维流程匹配，部署配置需支持自定义字段映射规则，适配不同企业的运维文档格式。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:password@internal-db:27017/fastgpt?authSource=admin` | 存储故障记录、拓扑图等结构化与非结构化运维数据，默认端口27017需与内部网络其他服务无端口冲突 |
| `PG_URL` | `postgresql://admin:password@internal-db:5432/fastgpt` | 存储运维变更单、巡检表的结构化元数据，默认端口5432适配企业内部数据库部署习惯 |
| `REDIS_URL` | `redis://:cachepass@internal-cache:6379/0` | 缓存实时故障告警与用户报障信息，数据库索引0避免与其他业务缓存冲突 |
| `DB_MAX_LINK` | `20–30 个连接` | 适配每日批量导入的巡检表与故障日志数据量，避免数据库连接耗尽影响运维响应 |
| `FE_DOMAIN` | `https://fastgpt.internal-net.com` | 提供故障排查工具的内部访问入口，需与企业内部DNS配置匹配 |
| `FILE_TOKEN_KEY` | 随机生成的64位字符串 | 加密存储上传的网络拓扑、巡检表等文件，避免运维文档被未授权访问 |
| `ROOT_KEY` | 随机生成的32位字符串 | 配置系统管理员权限密钥，用于初始化运维管理界面 |

## 容易做错的三处
- 现象：Docker部署后断电重启，PG或MongoDB服务无法启动，日志显示连接拒绝或数据库文件损坏。原因：未配置容器数据卷持久化存储，断电导致内存中的数据库文件丢失。
- 现象：配置`MONGODB_URI`后无法导入无线控制器日志，界面提示连接超时。原因：未开放MongoDB端口到内部网络，无线控制器所在网段无法访问数据库服务。
- 现象：本地Docker Compose部署后无法创建新用户，管理员界面无用户管理入口。原因：未正确配置`ROOT_KEY`或未执行系统管理员初始化流程，导致无法获取后台管理权限。

## 怎么确认配好了
- 执行内置的数据库连通性测试工具，验证`MONGODB_URI`与`PG_URL`配置的连通性，确认可读取存储的运维数据。
- 上传一份标准格式的无线覆盖巡检表，验证文件上传与解析功能正常，确认`FILE_TOKEN_KEY`配置有效。
- 模拟终端用户提交报障信息，检查系统是否生成对应故障记录并推送到运维界面，确认`REDIS_URL`的缓存功能正常。
- 访问`FE_DOMAIN`对应的内部域名，确认可正常加载运维工具界面，验证域名配置正确。
