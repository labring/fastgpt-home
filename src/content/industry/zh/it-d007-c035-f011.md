# 单元测试与组件测试的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
本品类的数据主要来自代码仓库、测试框架报告、需求说明与接口定义，更新频率为每日或每提交一次。日常产出的文档包含测试用例、覆盖率报告、Mock说明与缺陷单，其中测试用例包含测试场景、预期与实际结果字段；覆盖率报告包含行覆盖率、分支覆盖率数值；Mock说明包含模拟依赖的接口地址与返回规则。数据结构围绕代码单元与组件的逻辑验证展开，无额外业务聚合字段。

## 这些特征在「数据库与运维」这一环带来什么约束
由于本品类数据更新频率高且随代码提交同步变更，数据库与运维环节需适配快速迭代的测试环境部署。测试用例、覆盖率报告等数据与代码强绑定，需保证测试数据库与开发代码库的版本一致性，避免因版本不匹配导致的验证失效。高频次的单元与组件执行会产生大量临时测试数据，需配置自动清理机制防止存储溢出。同时，Mock依赖的配置需与测试数据库的访问权限绑定，确保测试环境与生产环境的隔离性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 包含测试库认证信息，格式为 `mongodb://username:password@host:port/test_db` | 隔离单元测试的MongoDB数据，避免与生产环境混淆 |
| `PG_URL` | 配置为测试环境PostgreSQL连接串，添加`application_name=fastgpt-unit-test` | 便于运维识别测试场景的数据库连接，优化排查效率 |
| `DB_MAX_LINK` | `8–12 个` | 适配单元测试高频短连接的执行特征，防止连接池资源耗尽 |
| `REDIS_URL` | 指向独立测试Redis实例，格式为 `redis://username:password@host:port/1` | 缓存测试用例的Mock依赖数据，避免重复初始化 |
| 测试数据自动清理周期 | `每 24 小时` | 匹配本品类数据日更的更新频率，防止测试数据库存储溢出 |

## 容易做错的三处
- 现象：数据库连接报错返回`Access denied`，原因：未配置测试环境数据库的专属用户权限，混用生产数据库账号导致权限不足。
- 现象：批量执行测试用例时无输出结果，原因：`DB_MAX_LINK`配置值过低，连接池耗尽导致后续测试请求无法建立连接。
- 现象：AI生成的数据库查询语句执行失败或返回异常结果，原因：未适配测试库的表结构，或未使用测试专用数据库实例。

## 怎么确认配好了
- 执行单条单元测试用例，检查数据库连接是否能正常建立，无权限或连接超时报错。
- 运行批量测试任务，确认测试用例执行完成率达到预期，无连接耗尽导致的失败。
- 查看测试数据库的连接日志，确认连接数未超过`DB_MAX_LINK`的配置值。
- 在FastGPT v4.17.0的测试环境中，执行AI生成的数据库查询语句，确认能正确返回测试数据，无语法或权限错误。
