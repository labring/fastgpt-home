# 原型与交互设计的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
该品类的数据通常来自Figma或Axure原型文件、团队内部设计系统、用户反馈记录与可用性测试结果。日常产出的文档包括交互原型稿、页面流程图、组件属性说明与设计评审记录。数据更新频率多为每周一次或随产品版本迭代同步更新，核心字段包含页面跳转路径、交互触发逻辑、组件样式规范与评审意见，无统一强制单位，随具体设计项目调整。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据依赖设计工具导出的结构化文件与团队内部评审记录，部署升级时需确保配置与当前版本的原型逻辑、设计系统规范对齐。由于数据更新频率随版本迭代，升级过程中需保留历史原型版本的关联配置，避免上线后研发与设计文档脱节。同时，设计相关的静态资源与交互逻辑参数需与数据库存储的配置项匹配，若数据来源变更或格式调整，需同步更新部署环节的读取规则，防止出现路径解析错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt_design?authSource=admin` | 存储原型文件元数据、评审记录与设计系统配置，需指定对应业务数据库 |
| `PG_URL` | `postgresql://user:pass@pg-host:5432/design_db?sslmode=require` | 存储交互路径配置、组件属性等结构化设计数据，需开启SSL保障数据传输安全 |
| `DB_MAX_LINK` | `20–30 个` | 适配设计文档批量读取的并发需求，避免数据库连接耗尽 |
| `REDIS_URL` | `redis://:redis-pass@redis-host:6379/0` | 缓存高频访问的原型预览链接与设计评审状态，降低数据库查询压力 |
| `FE_DOMAIN` | `https://design.your-domain.com` | 配置前端服务的访问域名，用于生成原型预览的可访问链接 |
| `FILE_TOKEN_KEY` | `随机32位字符串` | 用于加密原型文件的访问令牌，防止未授权访问设计文档 |

## 容易做错的三处
- 现象：Docker容器重启后，原型预览配置与设计系统关联参数全部丢失。原因：未将数据库挂载到本地持久化存储，容器内的`PG_URL`、`MONGODB_URI`配置仅存储于容器临时目录，重启后数据被清空。
- 现象：上传Axure原型文件后无法正常解析页面路径。原因：未正确配置`FILE_TOKEN_KEY`导致文件访问权限校验失败，无法读取原型文件内的结构化数据。
- 现象：升级后设计评审记录无法正常加载。原因：未同步更新`DB_MAX_LINK`的取值，导致数据库连接数不足，无法批量拉取评审记录数据。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`与`PG_URL`配置的连通性，确认可读取存储的设计数据。
- 访问`FE_DOMAIN`配置的域名，验证原型预览链接可正常打开，确认`FILE_TOKEN_KEY`配置的加密逻辑生效。
- 重启Docker容器后检查数据库内的设计配置数据是否保留，确认持久化存储配置正确。
- 针对FastGPT v4.17.0版本，批量上传多份原型文件，验证`DB_MAX_LINK`的配置可支撑并发读取请求，无连接超时报错。
