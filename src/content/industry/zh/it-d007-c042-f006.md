# 备份恢复与灾备演练的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
本品类的数据主要来自备份系统、数据库日志、对象存储及灾备平台，服务对象为运维团队、数据库管理员、业务连续性负责人。日常产出的文档包括备份策略文档、恢复演练报告、灾备切换预案、数据校验记录。数据更新频率分为日、月、季三类：备份校验记录按日更新，演练报告按月归档，灾备预案按季评审更新。核心字段包含备份时间戳、恢复点目标值、演练执行时长、数据一致性校验结果，无额外自定义统计字段。

## 这些特征在「定时任务与自动化」这一环带来什么约束
本品类的数据来源分散且服务对象涉及多岗位，要求定时任务需适配多系统的权限校验与调用频率限制，避免因跨系统调用冲突导致任务中断。数据更新频率分层，需将任务调度匹配对应节奏：日级数据校验任务需每日触发，月级演练报告归档任务需按月执行，季级灾备预案评审任务需按季度触发。核心字段格式存在差异，自动化流程需统一字段解析规则，避免因字段格式不匹配导致任务失败。同时，最耗时的恢复点确认、演练脚本执行、数据一致性核验环节，需通过自动化拆分任务节点，避免单任务超时触发业务连续性风险。本品类关注跨系统的可恢复能力，不同于单一数据库运维场景，需确保多系统间的任务协同，因此定时任务需支持跨系统节点的串行/并行调度配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发周期 | 按数据更新节奏匹配：日级校验为`每日 02:00`，月级归档为`每月1日 03:00`，季级评审为`每季度首月1日 04:00` | 匹配本品类数据的日/月/季更新频率，适配FastGPT v4.17.0的调度规则 |
| 任务超时阈值 | `3600 秒` | 覆盖恢复点确认、演练脚本执行的最长耗时区间，避免单任务超时中断 |
| 自动重试次数 | `2 次` | 应对跨系统调用的临时网络波动，减少因偶发故障导致的任务失败 |
| 多系统对接并发数 | `前 2 条` | 适配备份系统、灾备平台的默认调用限制，避免触发对方的限流规则 |
| 数据校验节点拆分 | 按备份集拆分任务 | 拆分最耗时的数据一致性核验环节，降低单任务负载 |
| 告警触发条件 | 任务失败后`10 分钟`内触发 | 及时通知运维团队处理故障，避免影响业务连续性 |

## 容易做错的三处
- 任务执行后界面显示长时间无响应，但任务管理器显示进程在运行：原因是未拆分最耗时的演练脚本执行节点，单任务占用资源过多导致界面渲染阻塞。
- 定时执行工具无法找到：原因是未在备份恢复与灾备演练专属模块中开启自动化调度开关，仅在通用任务面板配置未绑定品类专属流程。
- 仅能选择单一模型进行日志解析：原因是未在该模块的模型配置中添加第三方模型，仅使用了平台默认内置模型，未完成模型接入配置。

## 怎么确认配好了
- 登录FastGPT v4.17.0的运维后台，查看备份恢复与灾备演练模块的任务调度列表，确认对应定时任务已按预设周期显示在列表中。
- 手动触发一次测试任务，核对任务日志中是否包含备份系统、灾备平台的调用记录与数据校验结果。
- 检查对象存储的归档目录，确认测试任务生成的演练报告或校验记录已按规则写入对应存储路径。
- 查看告警配置面板，确认任务失败触发的告警渠道已绑定对应运维联系人组。
