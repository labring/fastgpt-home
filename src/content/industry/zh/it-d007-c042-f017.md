# 备份恢复与灾备演练的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
本品类的数据来自备份系统、数据库日志、对象存储、灾备平台，更新频率分为日、月、季。日常产出的文档包含备份策略、恢复演练报告、灾备切换预案、数据校验记录，文档字段包含恢复执行时长、校验通过率、灾备切换耗时等，单位涵盖秒、百分比、条等，由运维团队、数据库管理员、业务连续性负责人按职责维护。

## 这些特征在「部署与升级」这一环带来什么约束
本品类的数据来源分散，覆盖备份系统、数据库日志、对象存储与灾备平台，部署时需为每类数据源预留独立的配置对接入口，避免跨系统调用冲突。日常文档的固定结构要求升级时保留预设的字段映射规则，确保备份策略、恢复演练报告等文档可正常解析与存储。更新频率的日/月/季差异，需在部署阶段配置灵活的定时同步任务，适配不同业务的维护节奏。不同维护主体的权限划分，要求升级时同步更新权限配置项，保障数据访问的合规性。同时，灾备演练的出错后果包含数据丢失、恢复超时、业务连续性失败，部署时需配置容错机制，避免单点故障导致演练中断。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–200 个并发连接` | 适配多并发的备份数据拉取与校验请求，避免数据库连接耗尽 |
| `MONGODB_URI` | 带读写分离标识的集群连接串 | 灾备演练需同时读取备份数据与写入校验记录，集群连接保障高可用性 |
| `REDIS_URL` | `600 秒超时的缓存连接配置` | 缓存恢复点目标的临时数据，超时设置匹配日常演练的平均执行周期 |
| `STORAGE_S3_ENDPOINT` | 对应对象存储的区域接入端点 | 备份数据与演练日志需存储至指定对象存储，确保数据持久化与可访问 |
| `ROOT_KEY` | 按部署环境生成的随机密钥串 | 保障灾备配置管理接口的访问权限，防止未授权的配置修改 |

## 容易做错的三处
- 现象：部署后备份数据拉取失败，返回`503 Service Unavailable`状态码。原因：`DB_MAX_LINK`配置值过低，无法支撑批量备份数据的并发拉取请求。
- 现象：灾备演练报告无法正常写入存储，指定字段为空。原因：未正确配置`STORAGE_S3_ENDPOINT`，导致对象存储接入失败，无法写入校验记录。
- 现象：本地部署后调用模型时出现密钥验证失败，无法加载对应模型。原因：未按部署环境正确配置`REDIS_URL`缓存密钥，导致API密钥的临时存储失效，验证环节超时失败。

## 怎么确认配好了
- 执行数据库连接池状态查询脚本，查看活跃连接数是否处于`DB_MAX_LINK`配置的区间内，确认连接配置生效。
- 提交一条模拟的恢复演练记录，检查是否能正常写入指定的对象存储路径，验证`STORAGE_S3_ENDPOINT`配置有效性。
- 访问灾备配置管理接口，使用`ROOT_KEY`进行权限校验，确认接口可正常响应且无未授权访问风险。
- 启动一次小型恢复演练，查看缓存的恢复点数据是否在`REDIS_URL`配置的超时时间内正常更新，确认缓存配置生效。
