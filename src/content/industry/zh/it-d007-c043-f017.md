# 安全事件应急响应的线上故障排查与复盘：部署与升级

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类的数据来源于SIEM、EDR、防火墙日志与主机镜像，更新节奏为实时或按单事件触发。日常产出的文档包含应急响应报告、取证记录、处置方案与通报材料，数据字段包含攻击路径节点、隔离操作记录、证据链哈希值、监管通报编号等，单位涵盖时间戳、字节数、事件ID等，无额外强制统计要求。

## 这些特征在「部署与升级」这一环带来什么约束
本品类的数据来源多样且更新节奏灵活，部署与升级环节需适配多源日志接入的持久化存储需求，避免实时数据丢失。单事件数据量波动较大，需预留弹性存储容量以支撑攻击路径还原、证据链整理等耗时环节。文档包含结构化字段与非结构化取证内容，需支持混合格式的存储与检索。同时，需配置加密存储与访问权限控制，防止数据篡改或泄露，避免引发数据泄露扩大、业务停摆等后果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | `200–300 个连接` | 适配多源日志的并发接入需求，避免数据库连接池耗尽 |
| `MONGODB_URI` | 副本集或分片集群连接地址 | 存储非结构化取证内容与时序日志，集群部署保障高可用 |
| `REDIS_URL` | `600 秒超时的集群缓存地址` | 缓存实时告警与临时取证数据，降低关系型数据库的查询压力 |
| `STORAGE_S3_ENDPOINT` | 国内合规对象存储端点 | 存储不可篡改的日志副本与证据材料，保障数据完整性 |
| `FILE_TOKEN_KEY` | `32 位随机字符串` | 加密取证文件的访问令牌，防止未授权访问取证内容 |
| `ROOT_KEY` | `长度不小于 16 位的强密码` | 配置平台超级管理员权限，保障后台操作的安全性 |

## 容易做错的三处
- 执行`docker-compose up`后出现`connection refused`报错，原因是未正确配置`MONGODB_URI`或`REDIS_URL`，导致依赖服务无法正常连接。
- 平台内未显示接入的模型，原因是仅修改了模型接入地址配置项未同步更新关联的模型密钥配置，或未重启服务使新配置生效。
- 上传取证文件时提示存储权限不足，原因是未配置`STORAGE_S3_ENDPOINT`对应的存储桶访问密钥与读写权限，导致存储访问被拒绝。

## 怎么确认配好了
- 执行`docker ps`命令，确认所有FastGPT依赖服务与主容器均处于运行状态。
- 访问配置的`FE_DOMAIN`地址，登录平台后台查看存储、数据库等配置项是否与预设值一致。
- 上传一份小型测试取证文件，确认文件可正常存储并在平台内检索查看。
- 发起一次模拟应急事件查询，确认多源日志数据可正常加载并展示攻击路径相关内容。
