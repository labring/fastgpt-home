# 安全产品规则运营的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
数据来源为WAF、IDS、防火墙、威胁情报平台，更新节奏为每日或随防护事件触发。日常产出的文档包括规则变更单、拦截日志、误报分析报告、策略回滚记录。数据字段通常包含规则标识、会话时间戳、源IP、请求路径、响应状态码、误报判定标记、会话上下文长度等，单位多为毫秒级时间戳、IP字符串、字符数。

## 这些特征在「对话日志与审计」这一环带来什么约束
多源异构的数据来源要求对话日志需按会话维度完整存储，避免单条防护事件的关键信息丢失。随防护事件触发的更新节奏，要求审计链路可关联会话与对应规则版本，支持策略回滚时的回溯验证。误报分析的高频需求，要求保留完整的对话上下文与工具调用返回结果，支撑根因定位。同时，防护操作的可追溯性要求审计日志包含完整的操作链路，包括规则配置变更、会话触发条件、响应结果等关键节点。本文适配FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话日志保留时长 | 7–30 天 | 误报分析通常需要回溯7天以上的会话，同时满足常规审计需求 |
| `chatId`关联规则版本 | 绑定当前会话的规则版本号 | 策略回滚时需验证对应版本的会话触发逻辑，快速定位规则变更影响 |
| `responseChatItemId`记录工具返回结果 | 开启完整返回内容存储 | 工具调用异常时需回溯返回内容，定位参数或逻辑错误 |
| `detail`字段开启完整日志 | 开启所有会话的detail字段存储 | 长文本任务调试需完整上下文，排查offset超出范围类的格式错误 |
| 单次审计会话条数上限 | 前 100 条 | 聚焦高频防护事件，避免审计资源浪费 |
| 会话审计范围 | 仅筛选防护相关会话 | 减少非必要日志存储，聚焦安全运营核心场景 |

## 容易做错的三处
- 现象：执行长文本防护规则调试任务时，页面显示任务正常完成，但控制台抛出The value of "offset" is out of range报错。原因：未开启`detail`字段的完整日志存储，长文本会话上下文被提前截断，超出偏移量阈值。
- 现象：通过MCP工具集测试企查查专利查询可正常返回结果，但通过工具调用组件调用时返回企业无专利信息记录。原因：未通过`chatId`绑定当前会话的业务上下文，导致工具调用时未携带正确的查询参数。
- 现象：超过预设时长的对话日志无法检索到。原因：对话日志保留时长设置过短，未覆盖误报分析所需的回溯周期。

## 怎么确认配好了
- 检索任意防护事件的会话记录，验证`detail`字段包含完整的请求与返回内容。
- 查看会话关联的规则版本号，确认`chatId`已绑定当前生效的规则配置。
- 触发一次测试性防护事件，检查`responseChatItemId`是否记录了完整的工具返回结果。
- 调整日志保留时长后，验证超过预设周期的会话记录仍可正常检索。
