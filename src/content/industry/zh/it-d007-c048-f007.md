# 安全监控与SOC值守的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
本品类的数据来源为SIEM、EDR、NDR及威胁情报源，更新频率为实时或每日。日常关联的文档包括告警处置单、值班记录、威胁情报通报、日报周报。数据字段包含告警标识、处置主体、时间戳、威胁关联信息等，对话日志需绑定对应告警或处置流程的唯一标识，用于后续的故障排查与审计工作。

## 这些特征在「对话日志与审计」这一环带来什么约束
多源数据来源要求对话日志需关联不同系统的告警标识，实现跨系统溯源；实时更新的特性要求日志采集需支持实时同步，避免数据遗漏；日常文档的多样性要求审计日志需匹配告警处置单等文档的字段结构，便于跨文档关联；最耗时的告警研判环节要求日志需支持快速检索与定位，提升复盘效率；出错后果的严重性要求日志需具备不可篡改的留存机制，确保审计结果的可信度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定告警ID生成唯一标识，格式为`alert-{alertId}_chat_{timestamp}` | 关联SIEM、EDR告警数据，实现对话与告警的一键溯源 |
| `responseChatItemId` | 按处置步骤顺序编号，每轮交互生成独立ID | 便于复盘时定位单条告警研判的具体对话环节 |
| `detail` | 开启全量日志采集，包含告警上下文与处置动作 | 匹配告警处置单的字段结构，简化审计归档 |
| 日志留存周期 | 30 天 | 匹配SOC值守的值班周期与常规审计要求 |
| 单条日志存储上限 | 1000 MB | 适配多源数据同步的存储需求，避免单条日志溢出 |
| 检索回溯范围 | 前 7 天的对话日志 | 匹配日常告警研判的复盘时效需求 |

## 容易做错的三处
- 现象：刷新对话页面后前台无历史记录，但后台日志列表可查看到完整记录。原因：未正确配置`chatId`与前台会话的绑定逻辑，导致前台会话标识与后台存储的`chatId`不匹配。
- 现象：导出的审计日志缺少`detail`字段内容。原因：未开启全量日志采集配置，仅同步了基础对话元数据。
- 现象：对话日志检索结果条数与实际不符。原因：未设置合理的检索回溯范围，超出预设的日志留存周期或检索上限。

## 怎么确认配好了
本核对流程适用于FastGPT v4.17.0版本。
- 手动创建一条测试告警对话，检查前台页面是否显示与告警ID绑定的`chatId`标识。
- 导出一段周期内的审计日志，核对是否包含`detail`字段及告警关联信息。
- 模拟页面刷新操作，验证前台会话是否能正确加载后台存储的历史对话记录。
- 检查日志存储占用，确认单条日志未超出预设的存储上限。
