# 客户开通与租户初始化的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
该品类的数据主要来自CRM系统、合同订单库、身份管理系统与产品后台。日常产出的文档包括开通申请单、租户配置表、管理员账号清单、交付确认单。数据更新节奏为每单或每日，核心字段包含租户唯一标识、客户关联信息、基础权限配置、账号状态、开通时间戳，无额外统计类量化指标。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据接入要求数据库支持跨系统同步配置，避免数据不一致。按单或每日的更新节奏，需要合理设置数据库连接池参数，防止连接耗尽。核心字段的唯一性校验要求数据库建立租户ID、客户标识的唯一索引，避免重复初始化。同时，该环节直接关联客户登录与交付进度，数据库需配置高可用冗余，保障元数据读写稳定。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 包含认证信息与专属数据库名的完整连接串 | 存储租户账号与权限配置等核心元数据，适配FastGPT v4.17.0版本的存储规范 |
| `PG_URL` | 附带只读权限子账号的结构化数据连接地址 | 存储开通申请单、交付确认单等表单类数据，分离读写权限保障安全 |
| `DB_MAX_LINK` | 50-100 个 | 匹配每单或每日的更新节奏，避免高并发场景下数据库连接耗尽 |
| `REDIS_URL` | 包含访问密码的专用缓存连接地址，连接超时设为 30 秒 | 缓存租户会话与临时配置，缩短高频查询的响应延迟 |
| 数据库唯一索引 | 为租户ID、客户标识字段创建索引 | 保障数据唯一性校验效率，避免重复初始化记录 |
| 数据库空闲超时 | 300 秒 | 减少无效连接占用，优化数据库资源利用率 |
| 会话缓存过期时间 | 1800 秒 | 匹配租户会话的生命周期，避免无效缓存占用资源 |

## 容易做错的三处
- 现象：控制台返回`text index required for $text query`报错，知识库初始化失败。原因：未在PostgreSQL对应表中创建全文索引，导致配置检索无法正常执行。
- 现象：MongoDB连接失败，界面提示认证错误或连接超时。原因：`MONGODB_URI`配置未包含正确的数据库认证信息或目标库名称，或`DB_MAX_LINK`设置过小导致连接耗尽。
- 现象：升级系统版本后，原有租户数据无法正常读取。原因：未在升级前备份数据库元数据，或配置指向了错误的数据库实例。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的系统后台，进入租户配置模块，执行数据库连接测试，验证`MONGODB_URI`、`PG_URL`配置可正常建立连接。
- 登录目标数据库，查看索引列表，确认租户ID、客户标识字段已创建唯一索引。
- 提交一条测试开通申请单，验证数据可正常写入对应数据库表并完成跨系统同步。
- 进入Redis缓存管理页面，确认`REDIS_URL`配置可正常读写缓存数据，会话缓存过期时间符合预设要求。
