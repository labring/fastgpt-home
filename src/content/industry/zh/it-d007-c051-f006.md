# 客户数据导入迁移的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自客户历史业务系统、CSV/Excel模板、数据库导出文件，更新节奏为每单或不定期。日常配套文档包含数据模板、迁移方案、字段映射表与迁移验证报告，数据字段涵盖业务标识、业务属性、关联关系等，单位随客户原有系统或导入模板定义，无统一固定格式。实施过程中需完成字段映射确认、脏数据清洗与导入后抽样核对，出错后可能引发历史数据丢失、字段错位或客户拒收。

## 这些特征在「定时任务与自动化」这一环带来什么约束
数据来源与格式的多样性要求定时任务适配多类数据源与字段规则，避免因格式不兼容导致导入失败。更新不定期的特征意味着任务触发时机不宜固定周期，需支持按需或事件触发。字段映射与脏数据清洗环节耗时且易出错，自动化任务需嵌入前置校验与清洗逻辑，提前拦截异常数据。导入后抽样核对需自动化校验规则，确保数据合规后完成迁移，同时任务失败后需留存完整日志便于复盘。

## 配置怎么定
本配置适配 FastGPT v4.17.0
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发时机 | 按迁移计划触发 / 事件触发 | 适配数据更新不定期的特征，避免固定周期浪费资源 |
| 单次导入数据量 | 5000–10000 条 | 平衡系统负载与导入效率，适配批量数据处理需求 |
| 脏数据处理阈值 | 按实测标定 | 适配不同客户数据质量差异，避免误拦截有效数据 |
| 任务超时时间 | 1800 秒 | 覆盖批量数据清洗与导入的耗时需求，避免任务异常中断 |
| 校验规则触发节点 | 导入前 / 导入后抽样 | 对应字段映射与抽样核对环节，提前发现数据错位问题 |
| 失败重试次数 | 2 次 | 应对临时网络波动或系统抖动，减少人工介入成本 |

## 容易做错的三处
- 现象：导入任务状态长时间无变化，但系统监控显示进程仍在运行。原因：未配置脏数据处理超时分支，大量脏数据清洗导致任务假死。
- 现象：无法自定义触发规则，仅支持固定周期执行。原因：未开启事件触发配置项，未关联字段映射变更或数据上传事件。
- 现象：定时任务执行后无校验结果反馈。原因：未配置导入后抽样核对的自动化日志输出，导致故障无法快速定位。

## 怎么确认配好了
- 手动上传一份测试CSV模板，触发定时任务，查看导入日志是否包含字段映射校验记录。
- 配置事件触发规则，上传符合格式的测试数据，确认任务自动启动并生成迁移验证报告。
- 模拟脏数据场景，确认任务触发预设的处理逻辑并生成异常日志。
- 查看任务管理界面，确认超时时间与重试次数的配置值与预设方案一致。
