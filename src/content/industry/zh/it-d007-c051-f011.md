# 客户数据导入迁移的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
通常，客户数据导入迁移的数据源包含客户历史系统导出文件、CSV或Excel模板、第三方数据库导出结果，以及FastGPT产品自带的导入日志。日常配套文档包括标准化数据模板、迁移执行方案、字段映射对照表与迁移验证报告。数据更新节奏为每单或不定期，单批次导入数据量随客户业务规模变化。核心处理环节涉及字段映射确认、脏数据清洗与导入后抽样核对，数据处理失误可能导致历史数据丢失、字段错位，引发客户拒收。

## 这些特征在「数据库与运维」这一环带来什么约束
数据源的多样性要求数据库运维环节适配多种连接协议与格式，需兼容结构化与非结构化数据的导入校验。数据更新的不定期性要求导入配置支持灵活的批次调整，避免固定阈值导致的资源浪费或导入失败。字段映射与脏数据清洗的高耗时特性，要求数据库连接配置兼顾稳定性与处理效率，防止单批次任务超时。数据失误的严重后果则要求运维环节保留完整导入日志，支持故障复盘与快速回滚操作。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 包含认证信息、端口号与目标库路径的完整连接串 | 适配客户历史系统的MongoDB数据库部署，确保跨环境连接权限 |
| `PG_URL` | 格式为postgresql://user:pass@host:port/dbname的连接串 | 兼容客户导出的结构化数据存储需求，支持字段映射校验 |
| `DB_MAX_LINK` | 10–20 并发连接 | 匹配单批次导入的数据量上限，避免数据库连接耗尽 |
| 单次导入分块大小 | 5000–10000 条数据 | 适配字段映射校验的处理节奏，降低单事务超时风险 |
| 导入日志保留时长 | 30 天 | 满足故障复盘的日志溯源需求，符合运维归档规范 |

## 容易做错的三处
- 现象为数据库连接节点无法输入端口号，原因是FastGPT v4.17.0及以上版本将端口号整合至`MONGODB_URI`或`PG_URL`连接串中，未单独开放输入框。
- 现象为mongorestore导入知识库后无法查询结果，原因是未执行数据索引重建，或导入过程中向量嵌入任务未完成。
- 现象为启动后同级目录无mongo/data文件夹，原因是FastGPT v4.17.0调整了MongoDB数据卷挂载路径，默认未在启动目录生成本地文件夹。

## 怎么确认配好了
- 执行小批量样本导入，查看导入日志是否存在连接超时或权限报错。
- 核对数据库连接串配置，确认`MONGODB_URI`或`PG_URL`包含正确的认证与路径信息。
- 检查导入日志保留时长配置，确认符合复盘需求的周期。
- 抽样验证导入后的数据字段与映射表一致，无错位或缺失。
