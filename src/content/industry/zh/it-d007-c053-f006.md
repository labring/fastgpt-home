# 客户需求池管理的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自工单系统、客户访谈记录、CRM系统与产品路线图。日常维护的文档包括需求池清单、需求评估表、客户反馈记录与版本规划说明。数据更新频率通常为每周一次或随产品版本迭代同步更新。数据字段一般包含需求来源标识、客户关联信息、优先级分级、处理状态与版本绑定字段，无统一强制的计量单位要求，部分字段需关联客户ID与研发排期相关项。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据来源分散于多个系统，定时任务需支持跨系统接口调用，需配置多数据源的权限校验与数据拉取规则。因数据更新频率随版本迭代或周度周期变动，任务触发需支持按固定周期或版本发布节点触发，避免无效执行。日常文档格式多样，自动化流程需兼容多种格式的需求清单导入，需配置格式校验规则过滤无效内容。字段无统一标准，需支持自定义字段映射，避免需求信息错位导致后续评估偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源拉取间隔 | 3600 秒 | 适配工单系统与CRM的周度数据更新节奏，避免频繁调用超出接口限额 |
| 任务触发方式 | 按周定时 + 版本发布事件触发 | 匹配该品类的周/每版本更新频率，兼顾固定周期与版本联动的需求 |
| 字段映射规则 | 按需关联需求来源、优先级、客户ID | 适配该品类无统一字段标准的特征，确保需求信息准确对应 |
| 无效内容过滤阈值 | 800–1200 字符 | 过滤过短的无效反馈记录，保留有效需求信息 |
| 失败重试次数 | 3 次 | 平衡接口临时波动与任务执行效率，避免重复执行占用资源 |
| 告警触发条件 | 连续 2 次执行失败 | 及时通知运维人员排查异常，符合FastGPT v4.17.0的告警配置逻辑 |

## 容易做错的三处
- 现象：定时任务执行日志显示`执行超时`或`无数据返回`，界面上需求池数据未按计划更新。原因：未配置多数据源的权限校验，导致跨系统拉取工单与CRM数据时被拦截，或拉取间隔设置过短超出接口限额。
- 现象：导入Excel格式的需求清单后，多条客户反馈被合并为单条记录，字段排列错乱。原因：未开启自定义分隔符配置，使用默认的全局分隔符未适配Excel的行级数据结构，导致解析逻辑错误。
- 现象：任务执行后生成的需求评估表出现空字段，无法用于后续版本排期。原因：未配置字段映射规则，未将CRM中的客户优先级字段映射到需求池清单的对应位置，导致关键信息缺失。

## 怎么确认配好了
- 手动触发一次定时任务，查看拉取的数据源数据是否与工单系统、CRM的最新记录一致，核对字段映射是否正确。
- 等待预设的触发周期或模拟版本发布事件，确认任务是否自动执行，检查执行日志是否无报错。
- 导入一批测试用的需求清单，验证格式校验规则是否过滤了无效内容，自定义分隔符是否按行拆分数据。
- 模拟一次任务执行失败的场景，确认是否触发预设的告警通知，检查告警渠道是否配置正确。
