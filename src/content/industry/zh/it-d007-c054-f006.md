# 容器平台运维的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
容器平台运维的日常数据来源于Kubernetes API、镜像仓库、监控系统与CI流水线，更新节奏为每日同步或每次集群变更后触发。常见文档包含集群变更单、命名空间配额表、部署记录与故障报告，字段涵盖集群节点ID、Pod状态码、镜像版本、资源配额阈值等，单位包含台、GB、次等，单份文档的条目数随集群规模动态变化。

## 这些特征在「定时任务与自动化」这一环带来什么约束
数据来源分散且依赖外部接口，要求定时任务需适配不同系统的调用限流规则，避免频繁请求导致接口被阻断；更新节奏非实时，意味着定时任务无需设置过短的触发周期，可按变更或日级节奏执行以减少资源消耗；文档格式与字段存在差异，自动化流程需兼容结构化表格与非结构化日志的解析；最耗时的资源配额调整、Pod异常排查环节，要求定时任务优先处理高优先级故障工单，出错后果直接关联业务中断，因此需配置完善的失败重试与告警机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时任务触发周期 | 每300秒 / 每日凌晨2点 | 匹配Kubernetes API的日志更新频率与集群低峰时段，避免频繁调用超出接口限流 |
| 单次排查Pod数量上限 | 前20条 | 控制单轮任务的资源占用，适配集群节点的并发处理能力 |
| 故障告警阈值 | 连续3次Pod重启 | 过滤临时网络抖动或调度波动引发的异常，减少误报次数 |
| 自动化修复重试次数 | 2次 | 避免重复执行可能引发资源冲突的操作，平衡修复成功率与资源消耗 |
| 日志拉取超时时间 | 60秒 | 适配监控系统的日志返回延迟，防止任务长时间阻塞 |
| 全局变量更新触发条件 | 集群变更完成后 | 匹配业务文档的更新节奏，确保变量与实际集群配置保持一致 |

## 容易做错的三处
- 现象：API请求返回404 - 未找到资源。原因：定时任务调用的Kubernetes API路径未随集群版本更新，或配置的命名空间名称拼写错误。
- 现象：设置的全局变量值未自动更新。原因：定时任务触发条件未绑定集群变更事件，仅按固定周期执行，未同步最新的命名空间配额表数据。
- 现象：知识库图片无法自动索引。原因：定时任务未配置镜像仓库的图片元数据拉取环节，或未指定图片存储路径的扫描规则。

## 怎么确认配好了
- 手动触发一次定时任务，查看FastGPT v4.17.0的任务执行日志，确认能拉取到指定命名空间的Pod状态数据。
- 修改一条集群变更单的配置，等待任务执行后验证全局变量是否同步更新为最新值。
- 模拟一次Pod异常重启，查看是否触发预设的自动化排查流程并生成对应的故障报告。
- 手动阻断一次API请求，确认连续失败达到阈值后会触发预设的告警通知。
