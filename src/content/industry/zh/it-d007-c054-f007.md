# 容器平台运维的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
该品类的数据主要来自Kubernetes API、镜像仓库、监控系统与CI流水线，更新节奏为每日或每次集群变更后。日常关联文档包含集群变更单、命名空间配额表、部署记录与故障报告，数据字段包含集群节点ID、Pod状态、镜像版本、CI构建结果、资源配额阈值等，无统一固定的单位要求，部分字段随集群配置动态调整。

## 这些特征在「对话日志与审计」这一环带来什么约束
多源异构的数据来源要求对话日志需支持关联Kubernetes节点、镜像、监控指标等多维度标识，避免排查时割裂信息。动态更新的节奏要求审计功能支持按变更时间、集群事件时间灵活筛选日志范围，适配每日或即时的变更场景。关联的集群变更单、配额表等文档，要求日志字段需预留对应关联ID的存储位，方便后续回溯操作链路。同时，故障排查的高风险属性要求审计日志完整留存对话上下文与操作参数，确保回溯时可复现排查过程。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` 过滤规则 | 按集群命名空间分组配置 | 适配容器平台多租户隔离的运维场景，避免跨命名空间的日志泄露 |
| `responseChatItemId` 关联开关 | 开启并绑定Kubernetes资源ID | 实现对话日志与具体Pod、节点的关联，简化故障排查链路 |
| `detail` 日志存储粒度 | 保留完整请求与响应体 | 覆盖所有操作参数与返回结果，满足审计回溯的完整要求 |
| 并发线程数限制 | 10–30 线程 | 适配容器平台的资源配额，避免触发系统限流 |
| 日志留存周期 | 30–180 天 | 适配容器平台运维的常规审计周期，可按实测调整 |
| 单次导出日志上限 | 前 1000 条 | 避免导出操作占用过多集群资源，影响正常运维 |

## 容易做错的三处
- 现象：不同用户登录后仅能查看自身发起的对话，无法查看团队内其他成员的运维对话。原因：未开启`chatId`的命名空间分组过滤配置，导致权限隔离失效。
- 现象：通过API创建的对话，在日志预览界面中Human字段为空。原因：未在请求参数中正确传递`detail`字段的用户标识信息，导致日志无法采集用户身份。
- 现象：向量化任务报错提示速率超限，无法正常生成知识库向量。原因：未限制并发线程数，导致embedding请求超出集群资源配额，引发系统限流。

## 怎么确认配好了
- 登录不同权限的测试账号，验证仅可查看对应命名空间下的对话日志。
- 发起API调用并携带完整`detail`参数，检查日志预览界面中Human字段是否正常显示用户标识。
- 导出审计日志，确认格式为JSON且包含完整的请求与响应内容。
- 查看日志留存周期与单次导出上限配置，验证导出操作符合资源占用要求。
