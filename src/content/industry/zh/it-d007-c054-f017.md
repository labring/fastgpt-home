# 容器平台运维的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
容器平台运维的核心数据来源于Kubernetes API、镜像仓库、CI流水线与集群监控系统。日常维护文档包含集群变更单、命名空间配额表、部署记录与故障报告，字段覆盖集群节点标识、Pod运行状态、镜像版本号、变更时间与资源使用配额。数据更新频率为每日或每次集群变更后，不同文档的字段需保持一致，确保变更与运维动作可完整追溯。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据依赖Kubernetes API与集群监控，部署时需确保服务账号拥有足够的API访问权限，避免因权限不足导致资源状态采集失败。数据更新频率较高，升级前需通过CI流水线验证镜像兼容性，同时对照命名空间配额表调整Pod的资源请求与限制，防止资源抢占引发的业务中断。故障报告的字段需与排查日志匹配，因此部署时需关联日志采集工具，确保异常信息可被完整捕获与回溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `DB_MAX_LINK` | `100–200 个连接` | 匹配容器集群的并发连接上限，适配Pod的资源配额配置 |
| `MONGODB_URI` | `mongodb://<db-user>:<db-pass>@<mongo-svc>:27017/fastgpt?authSource=admin` | 符合官方要求的数据库连接格式，适配容器内服务发现的地址规则 |
| `REDIS_URL` | `redis://:<redis-pass>@<redis-svc>:6379/1` | 指向容器化部署的Redis服务，使用1号数据库隔离业务数据，匹配集群网络策略 |
| `FE_DOMAIN` | `https://your-fastgpt-domain.com` | 对应容器平台对外暴露的Ingress域名，确保前端访问路径正确 |
| `FILE_TOKEN_KEY` | 按实测标定的32位随机字符串 | 满足文件上传鉴权的安全要求，避免未授权的文件访问 |

## 容易做错的三处
- 现象：docker compose私有化部署后，访问知识库出现接口报错。原因：未在App/Admin服务端正确配置`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token）环境变量，触发FastGPT v4.17.0起的启动校验失败。
- 现象：升级至FastGPT v4.17.0后，简易应用出现未捕获异常。原因：未对照命名空间配额表调整Pod的资源请求与限制，导致容器集群资源不足。
- 现象：问答流程结束后无前端输出，需查看详情才能查看消息。原因：混淆了`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址）、`AIPROXY_API_TOKEN`（AI Proxy管理员Token）与模型供应商凭证，未通过官方模型渠道配置页面设置上游模型参数。

## 怎么确认配好了
- 查看App/Admin服务的容器日志，确认启动时无环境变量缺失的校验报错。
- 访问配置好的前端域名，验证知识库功能可正常加载并发起查询请求。
- 登录FastGPT的模型渠道配置页面，确认上游模型的渠道地址与供应商凭证已正确配置。
- 执行集群资源检查命令，确认所有服务Pod处于运行中状态，资源使用符合配置要求。
