# 容量规划与资源扩缩容的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自云账单、监控系统、业务预测模型输出、压测报告。数据更新节奏通常为周度或月度。配套文档包含容量规划报告、扩容申请单、资源利用率报表、预算测算表，文档字段包含资源使用量、峰值阈值、采购申请额度、资源利用率相关标识，单位涵盖CPU核数、内存容量单位、存储容量单位等。

## 这些特征在「定时任务与自动化」这一环带来什么约束
数据来源分散的特征要求定时任务需配置多源数据拉取的权限校验与格式适配逻辑，避免因数据源格式不统一导致任务失败。周度或月度的更新节奏限定了定时任务的执行周期不宜过短，否则会产生不必要的资源消耗。配套文档的字段差异则要求自动化流程需预设字段映射规则，适配不同类型文档的字段格式。同时，由于出错会引发高峰故障或资源浪费，定时任务需配置失败回调与告警触发机制，确保异常及时被感知。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的定时任务与自动化模块逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时任务执行周期 | 7天 / 30天 | 匹配该品类周度/月度的更新节奏，避免过度执行消耗资源 |
| 多源数据拉取超时时间 | 300秒 | 适配云账单、监控系统等数据源的常规响应时长，避免单次拉取任务无意义阻塞 |
| 字段映射规则预设 | 按业务文档字段清单标定 | 适配容量规划报告、扩容申请单等不同文档的字段差异，提升自动化处理准确性 |
| 失败重试次数 | 2次 | 平衡任务稳定性与资源消耗，避免因临时网络波动导致任务失败 |
| 异常告警触发阈值 | 任务连续失败1次 | 及时感知定时任务异常，避免因任务未执行引发后续容量规划偏差 |
| 资源扩缩容触发阈值 | 按压测报告峰值标定 | 匹配业务峰值预测数据，避免误触发或延迟触发扩缩容操作 |

## 容易做错的三处
- 定时任务执行后资源利用率报表字段为空：未配置多源数据拉取的字段映射规则，导致从监控系统拉取的数据无法匹配目标文档的字段格式，无法完成数据写入。
- 任务执行超时被强制终止：未设置合理的超时时间，或未配置失败重试机制，当云账单拉取延迟时直接导致任务失败。
- 自动化流程无法识别文档中的附件资源数据：未配置附件解析的适配规则，无法提取扩容申请单中的资源参数，导致自动化流程无法完成后续的容量测算。

## 怎么确认配好了
- 查看定时任务的执行日志，确认多源数据拉取的格式适配逻辑正常运行。
- 手动触发一次定时任务，核对生成的容量规划报告字段是否与预设的映射规则一致。
- 检查异常告警配置，确认任务失败时会触发指定的通知渠道。
- 验证扩缩容触发阈值的配置，确认阈值参数与压测报告的峰值数据匹配。
