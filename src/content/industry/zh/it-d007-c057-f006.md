# 工单受理与问题分级的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
本品类的数据来源于工单系统、聊天记录、产品日志与客户合同SLA，更新节奏为日级或实时。日常处理的文档包含客户工单、问题分级表、处理记录与服务报告，核心字段包括工单唯一标识、故障类型标签、问题分级等级、响应时限要求、处理状态与关联日志ID，仅按业务流程流转存储，无额外自定义统计数值。

## 这些特征在「定时任务与自动化」这一环带来什么约束
工单数据的实时性要求决定了定时任务需兼顾延迟与资源占用，高频更新的产品日志与工单需避免重复触发自动化流程。问题分级表的字段固定性要求自动化规则需匹配预设的分级标签，不可随意调整字段映射逻辑。SLA时限要求需严格绑定定时任务的触发节点，避免超时未触发分级与分派动作。同时，多源数据的聚合需在定时任务中做去重校验，防止重复生成处理记录。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时任务触发周期 | 600–1800 秒 | 匹配工单实时更新节奏，平衡任务执行频率与系统资源占用 |
| 故障类型匹配阈值 | 70%–90% | 适配预设的问题分级标签体系，降低自动化分级的误判率 |
| 单次任务处理工单上限 | 前 200 条 | 控制单轮任务的内存与网络消耗，防止任务超时中断 |
| 失败重试次数 | 3 次 | 应对临时的系统波动或接口调用异常，减少任务失败概率 |
| SLA时限告警触发提前量 | 3600 秒 | 匹配客户合同约定的响应时限，提前触发分派与处理动作 |
| 多源数据去重开关 | 开启 | 避免重复生成处理记录与服务报告，保证数据一致性 |

## 容易做错的三处
- 现象：定时任务生成的服务报告无法自动复制到指定存储位置，界面提示「无法使用自动复制，请手动操作」，原因：未配置目标存储路径的访问权限，或导出格式与目标系统的兼容规则不匹配，导致自动复制动作触发失败。
- 现象：定时任务执行后部分工单未被分级，结果条数少于预期，原因：故障类型匹配阈值设置过高，导致部分故障描述未达到匹配标准，自动化规则未触发分级动作。
- 现象：定时任务触发后出现重复的处理记录，原因：未开启多源数据去重开关，同一工单被多次匹配并触发处理流程，导致数据冗余。

## 怎么确认配好了
- 手动提交一条测试工单，等待对应定时任务触发后，检查工单是否被正确分级，匹配预设的故障类型标签。
- 查看定时任务的执行日志，确认触发周期符合设置的600–1800秒范围，单次处理工单数量未超出上限。
- 检查目标存储路径，确认服务报告已自动生成并复制到位，无报错提示。
- 模拟一次系统波动，观察定时任务是否按设置的重试次数执行失败恢复动作，未出现任务永久中断的情况。
