# 广告合规留痕的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类数据主要来自广告平台后台、客户资质库、合同系统及监管公开规则，日常文档包含广告审查表、资质附件、投放记录、整改通知四类核心文件。数据更新以单次投放活动或自然月为周期，单条记录包含投放主体、资质编号、合规审查状态、整改节点等字段，无统一固定单位，需按文档类型匹配对应字段规则。

## 这些特征在「定时任务与自动化」这一环带来什么约束
该品类的数据特征对定时任务与自动化环节带来多重约束。因更新以单次投放活动或自然月为周期，定时触发时机需支持灵活配置，适配不同更新节奏；数据来源分散跨系统，自动化流程需适配多源数据拉取与校验逻辑；单条记录字段规则随文档类型动态变化，需配置动态字段映射规则，避免归档错误；核心耗时的资质归档、整改证据整理环节需批量自动化处理，否则会延误合规时效；且出错后果直接关联监管与客户追责、账户处罚，失败链路需完整留存便于后续复盘。

本文档适配 FastGPT v4.17.0 版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发时机 | 按投放活动节点触发，无活动时按自然月每日凌晨2点触发 | 匹配数据以活动或月为周期的更新节奏 |
| 多源数据拉取并发数 | 2-4 并发 | 避免超出广告平台后台的接口限流阈值 |
| 字段映射校验阈值 | 90% 匹配度 | 兼顾不同文档类型的字段差异与归档准确性 |
| 批量处理单次上限 | 500 条/次 | 适配合规数据的单次归档规模，避免任务超时 |
| 失败告警触发条件 | 任务执行失败后10 分钟内触发 | 及时响应合规风险，避免延误整改 |
| 日志留存周期 | 180 天 | 满足监管与客户复盘的证据留存要求 |

## 容易做错的三处
- 现象：跨APP切换后仍触发原APP的必填全局变量校验报错。原因：未在任务配置中清除旧的全局变量绑定，导致上下文残留旧配置。
- 现象：定时任务执行后，投放记录字段为空。原因：未配置多源数据拉取的重试机制，接口调用失败后未补拉对应数据。
- 现象：批量处理时触发接口限流报错。原因：未限制多源数据拉取的并发数，超出广告平台后台的接口调用上限。

## 怎么确认配好了
- 手动触发一次定时任务，核对拉取的文档数量与广告平台后台的对应周期内的投放记录数量一致。
- 检查任务配置中的触发时机，确认覆盖投放活动节点与自然月周期两种场景。
- 查看失败告警配置，确认任务失败后会推送至指定的通知渠道。
- 核对日志留存配置，确认留存周期符合合规要求的时长标准。
