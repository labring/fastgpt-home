# 广告合规留痕的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
广告合规留痕的数据来源包括广告平台后台、客户资质文件、合同系统以及监管公开规则。日常处理的文档包含广告审查表、资质附件、投放记录、整改通知，覆盖结构化字段与非结构化文件两类。数据更新以单次广告活动或月度为周期，按需触发写入，无固定批量更新节奏。数据字段包含广告主标识、投放时段、合规资质编号、整改状态等，需支持多来源数据的关联存储。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据更新以单次活动或月度为周期，部署时需支持按需写入的存储配置，避免固定批量带来的资源浪费。多来源的数据需要对接不同存储介质，因此需同时配置结构化与非结构化数据的存储参数。合规场景的数据出错会导致监管处罚，因此部署时需确保存储的可靠性与权限隔离。大体积的资质附件与投放记录文件，需要适配内网环境的分布式存储配置，避免单节点存储瓶颈。按活动触发的更新节奏，还要求缓存配置能灵活适配临时高并发的写入请求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配，适配广告合规留痕场景的部署与升级需求。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `MONGODB_URI` | `mongodb://[用户名]:[密码]@[内网IP]:27017/fastgpt_compliance?authSource=admin` | 广告合规留痕的投放记录、整改通知等非结构化数据适合用MongoDB存储，适配多文档结构的存储需求 |
| `PG_URL` | `postgresql://[用户名]:[密码]@[内网IP]:5432/fastgpt_compliance` | 广告审查表、合同系统的结构化字段适合用PostgreSQL存储，支持复杂的关联查询 |
| `REDIS_URL` | `redis://:[密码]@[内网IP]:6379/0` | 缓存合规资质的校验结果与会话信息，适配按活动触发的更新节奏，减少重复数据库查询 |
| `STORAGE_S3_ENDPOINT` | `http://[内网存储IP]:9000` | 适配资质附件、投放记录的大文件存储需求，支持内网环境下的分布式文件访问 |
| `DB_MAX_LINK` | `20–30 条` | 兼顾多数据源的并发连接需求，避免单个数据库连接耗尽影响业务 |
| `FE_DOMAIN` | `https://compliance-fastgpt.内部域名` | 配置前端访问地址，适配合规场景的内部权限控制与访问路径 |

## 容易做错的三处
- 现象：使用docker-compose部署后，合规留痕模块未在前端界面显示。原因：未正确配置`FE_DOMAIN`或`ROOT_KEY`，导致前端与后端的权限校验失败，模块未正常加载。
- 现象：内网部署时，合规留痕的存储服务持续重启。原因：未正确配置`STORAGE_S3_ENDPOINT`或`REDIS_URL`，导致存储或缓存服务无法建立连接，引发重启。
- 现象：配置了合规校验模型的新版本后，调用时仍使用旧版本逻辑。原因：未同步更新`REDIS_URL`对应的缓存配置，旧版本的校验结果缓存未被清除，导致复用历史配置。

## 怎么确认配好了
- 执行`docker-compose logs -f fastgpt fastgpt-api`命令，查看数据库连接相关日志，无`connection refused`或`auth failed`报错，表示基础连接配置正常。
- 上传一份测试用的资质附件，通过合规留痕模块的上传入口提交，确认文件能正常存储并关联到对应广告活动记录。
- 模拟生成一条广告审查记录，查看对应数据库中是否生成对应条目，验证数据持久化功能正常。
- 访问`FE_DOMAIN`对应的前端地址，登录后进入合规留痕模块，确认所有配置项均已正确加载，无配置缺失的提示。
