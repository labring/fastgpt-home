# 广告账户开户审核的线上故障排查与复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据主要来自广告平台后台、国家企业信用信息公示系统、客户提交的开户申请材料与行业资质文件，以及公开的行业准入规则。日常关联文档包含开户申请单、营业执照扫描件、行业经营许可证、开户审核流转记录。不同于广告素材审核类场景，该品类核心围绕投放主体资质与行业准入开展，数据字段更侧重主体身份与经营合规性相关内容。数据更新节奏随单次开户申请触发，或按日同步广告平台的审核状态变更。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多来源异构数据需要通过HTTP接口拉取，不同数据源的鉴权方式、返回格式存在差异，需要适配不同的鉴权配置。按申请触发的更新节奏要求接口调用需绑定单次开户流程，避免无意义的批量请求占用系统资源。包含资质文件等大体积字段的接口调用，需要合理设置请求体大小限制，同时处理跨系统的格式转换。审核状态的实时同步需求要求接口超时时间需匹配行业审核的常规耗时区间，确保数据拉取不中断审核流转流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 按数据源类型配置Bearer Token或基础认证 | 适配广告平台、公示系统等不同数据源的鉴权要求 |
| 接口超时时间 | 60-120秒 | 匹配资质核验、准入判断等最耗时环节的常规耗时 |
| `variables` | 绑定开户申请ID、主体统一社会信用代码作为入参 | 确保每次接口调用对应单次审核流程，避免数据混淆 |
| 请求体大小限制 | 10-20 MB | 适配营业执照、行业资质等扫描件的上传或拉取需求 |
| `responseData` | 提取审核状态、补正提示字段作为返回值 | 简化后续流程的状态判断与流转逻辑 |

## 容易做错的三处
- 调用外部系统接口时出现`tls: failed to verify certificate`报错，原因是未配置可信证书链或使用了自签名证书，未在接口配置中添加信任白名单。
- 工作流HTTP模块接收自定义变量失败，原因是未将入参字段与`variables`中绑定的申请参数正确映射，导致接口无法识别传入的开户申请标识。
- 批量拉取审核数据时出现超时，原因是未设置合理的超时时间，且未对单批次请求的数量做限制，导致超出接口调用的负载阈值。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的工作流HTTP模块中，发起单次资质核验的测试调用，检查`responseData`中是否返回了正确的审核状态字段，无空值或异常格式。
- 查看接口调用日志，确认`Authorization`认证头被正确携带，鉴权返回状态码为200。
- 传入自定义变量触发调用，确认接口能正确解析`variables`中绑定的开户申请ID，返回对应主体的核验结果。
- 模拟证书校验异常场景，确认配置的信任白名单能正常拦截非法证书请求，避免无效调用。
