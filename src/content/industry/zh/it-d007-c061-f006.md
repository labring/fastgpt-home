# 性能测试与容量评估的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
这个品类的数据通常来自压测平台、APM监控、数据库慢日志、生产流量基线。日常产出的文档包括压测方案、容量评估报告、压测数据记录、优化建议单，数据更新频率为月度或每重大版本发布后。数据字段包含吞吐率（单位为次/秒）、请求延迟（单位为毫秒）、服务器资源使用率（百分比）、容量阈值等，不同来源的数据格式存在差异，需统一校验后用于线上故障排查与复盘。

## 这些特征在「定时任务与自动化」这一环带来什么约束
多源数据的拉取需求带来了适配不同接口格式的约束，需在定时任务中配置兼容逻辑。数据更新频率为月度或重大版本后，触发周期需匹配该节奏，避免过度执行或遗漏关键数据。固定格式的业务文档要求自动化流程严格遵循预设字段顺序，否则复盘报告无法用于后续决策。资源使用率、吞吐率等带单位的字段需统一校验，否则容量评估结论会出现偏差。故障排查的时效性要求定时任务需在流量高峰前完成数据校验与报告生成，避免影响业务运行。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 定时任务触发周期 | 每月1次 或 重大版本发布后24小时内 | 匹配数据更新频率为月度或每重大版本的业务节奏 |
| 多源数据拉取并发数 | 3–5 个并发 | 适配压测平台、APM等数据源的常规接口限流阈值 |
| 压测数据校验阈值 | 延迟超出基线120%、CPU使用率超过85% | 以生产流量基线为正常运行参考标准，超出即判定为性能瓶颈 |
| 文档生成模板绑定 | 固定压测报告模板 | 匹配日常文档的固定结构，保障复盘报告格式统一 |
| 异常告警触发条件 | 连续3次拉取失败 | 避免单次网络波动触发误告警，保障复盘流程稳定性 |
| 模型显存自动释放配置 | 任务完成后120秒内释放 | 适配rerank模型运行后显存占用较高的特性，避免资源持续挤占 |

本页面配置说明基于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象为rerank模型运行后显存未释放，持续挤占内存，最终触发显存溢出报错。原因是未配置任务完成后的显存自动释放逻辑，仅依赖系统默认回收机制。
- 现象为批量导入md文档时触发maxLength报错，单次导入条数超出平台限制。原因是未设置批量导入的单次上限，未匹配平台上传规则。
- 现象为自动生成的复盘报告字段顺序与预设模板不符。原因是未绑定固定文档模板，自动化生成时未按预设字段顺序填充数据。

## 怎么确认配好了
- 手动触发一次定时任务，核对多源数据是否完整拉取并匹配预设字段。
- 运行rerank模型后查看系统资源占用，确认显存是否在任务完成后按配置释放。
- 批量导入少量测试文档，核对生成的报告是否与预设模板结构一致。
- 模拟一次数据拉取失败，确认异常告警是否按配置触发。
