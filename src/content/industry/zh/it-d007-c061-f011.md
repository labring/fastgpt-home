# 性能测试与容量评估的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
该品类的数据通常来自压测平台、APM监控系统、数据库慢日志与生产流量基线。更新节奏为每月一次或伴随重大版本发布。日常产出文档包含压测方案、容量评估报告、压测数据记录与优化建议单，数据字段通常包含吞吐率、平均延迟、资源峰值使用率、并发连接数，单位分别为次/秒、毫秒、百分比、个。

## 这些特征在「数据库与运维」这一环带来什么约束
数据来源分散且多源，需统一对接`PG_URL`、`MONGODB_URI`等数据库配置项，确保不同来源的压测数据能正常拉取与存储。更新频率固定，需定期校验数据库连接有效性，避免因配置过期导致压测数据丢失。文档字段标准明确，运维环节需按字段规范存储压测结果，便于后续复盘时快速定位数据库瓶颈。压测模型设计耗时且资源消耗大，需预留足够的数据库连接池资源，避免压测过程中连接耗尽影响业务。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `PG_URL` | 本地PostgreSQL实例的标准连接串 | 对接业务核心数据库，用于存储压测数据与复盘日志 |
| `MONGODB_URI` | 副本集连接串，包含至少2个节点地址 | 保障压测数据存储的高可用性，避免单点故障 |
| `DB_MAX_LINK` | 800–1200 个连接 | 匹配压测并发峰值的连接需求，避免连接池耗尽 |
| `REDIS_URL` | 带密码认证的集群连接地址 | 缓存压测中间结果与流量基线数据，提升复盘效率 |
| 数据库慢日志采集开关 | 开启并保留7天日志 | 便于线上故障复盘时定位数据库执行瓶颈 |

## 容易做错的三处
- 现象：压测时出现`connection refused`报错，状态码503。原因：未按要求配置`DB_MAX_LINK`，连接池大小不足以支撑压测并发量，导致数据库连接耗尽。
- 现象：容量评估报告中数据库相关字段为空。原因：未正确配置`PG_URL`或`MONGODB_URI`，无法拉取压测平台的原始数据，导致复盘数据缺失。
- 现象：离线升级FastGPT v4.17.0后，压测数据无法加载。原因：未提前备份数据库镜像与数据目录，升级过程中配置文件被覆盖，导致数据库连接配置丢失。

## 怎么确认配好了
- 执行基础压测脚本，检查各数据库配置项的连接日志，确认无连接失败提示。
- 查看压测数据记录文档，核对字段是否与预设的压测方案一致，确保数据正常写入。
- 模拟线上峰值流量，检查APM监控与数据库慢日志是否能正常采集到对应数据。
- 触发容量评估报告生成，确认报告中所有数据库相关字段均有有效数据。
