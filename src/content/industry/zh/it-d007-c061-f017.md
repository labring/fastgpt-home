# 性能测试与容量评估的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
该品类的数据来源包含压测平台、APM监控工具、数据库慢日志与生产流量基线，更新频率为每月或每重大版本发布时。日常产出的文档包括压测方案、容量评估报告、压测数据记录与优化建议单，常规字段包含吞吐、延迟、资源使用率、资源余量等，对应各自的度量单位，需匹配企业内部的性能评估规范，无强制统一的格式要求。

## 这些特征在「部署与升级」这一环带来什么约束
数据来源分散要求部署时需配置多个外部数据源的连接参数，保障各类性能数据的采集与存储。更新周期不固定，升级时需兼容旧版压测报告与容量评估数据的解析格式，避免历史数据丢失。文档类型多样且需长期留存，部署时需配置足够的存储资源与访问权限，确保压测记录与优化建议单可正常归档。此外，该品类的出错会直接影响业务高峰期的服务稳定性，因此部署升级时需配置健康检查参数，提前验证各配置项的连通性。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本的性能测试与容量评估模块：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–200 个连接` | 适配压测场景下的并发数据库连接需求，避免连接池耗尽影响压测执行 |
| `REDIS_URL` | `redis://:自定义密码@访问地址:6379/0` | 存储压测过程中的临时会话数据与缓存压测指标，保障数据读写效率 |
| `PG_URL` | `postgresql://数据库用户:自定义密码@访问地址:5432/业务库名?sslmode=require` | 持久化存储压测方案、容量评估报告等核心业务数据 |
| `STORAGE_S3_ENDPOINT` | `企业内部对象存储访问地址` | 留存压测数据记录与优化建议单，符合月度更新的数据留存要求 |
| `FILE_TOKEN_KEY` | `按实测标定的32位随机字符串` | 保障压测过程中上传的压测日志文件的访问安全 |

## 容易做错的三处
- 现象：启动容器后执行初始化脚本报错，原因：升级时未正确配置`PG_URL`或`REDIS_URL`的访问权限，导致初始化脚本无法连接核心存储组件。
- 现象：本地部署卡在数据库连接步骤，原因：未正确设置`DB_MAX_LINK`的取值范围，超出数据库实例的最大连接限制，导致连接请求被拒绝。
- 现象：压测数据无法正常留存，原因：未配置`STORAGE_S3_ENDPOINT`或配置的对象存储地址无法访问，导致压测记录无法持久化归档。

## 怎么确认配好了
- 核对`PG_URL`配置的数据库连接参数，使用对应数据库客户端工具执行连通性测试，确认参数匹配实例的访问规则。
- 检查`REDIS_URL`的认证信息与端口配置，通过缓存客户端工具执行ping与读写测试，验证可正常访问缓存实例。
- 上传一份小型测试用的压测数据文件，通过配置的`STORAGE_S3_ENDPOINT`存储路径，确认文件可正常上传与读取。
- 结合预期的压测并发规模，调整`DB_MAX_LINK`的配置值，通过数据库监控工具确认当前连接数未超出配置范围。
