# 投放效果优化的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
投放效果优化的核心数据来自广告平台API、归因系统、CRM线索与落地页埋点数据。日常产出的文档包含日报周报、调价记录、素材测试表与优化复盘文档，字段包含曝光量、点击量、转化成本、预算余额等，单位涵盖元、次等。数据更新节奏分为实时与日级两类，实时数据随广告投放动作同步更新，日级数据每日固定时段汇总完成。该环节发生在广告投放运行后，不同于投放计划搭建的前置配置环节。

## 这些特征在「定时任务与自动化」这一环带来什么约束
数据来源分散且格式存在差异，要求定时任务需适配多数据源的拉取逻辑与字段映射规则。更新节奏的差异要求任务触发时机需匹配对应数据源的更新周期，避免拉取未完成的半成数据。日常文档的结构化特征要求自动化流程需支持表格字段的自动填充与格式校验。最耗时的异常指标定位环节，需要定时任务自动拉取全量指标并对比阈值，减少人工排查的时间成本。异常指标未及时定位会导致获客成本升高、预算提前耗尽，因此定时任务需匹配业务的监控需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发频率 | 按数据源更新节奏匹配，实时数据源设为`300 秒`，日级数据源设为`86400 秒` | 匹配广告平台、归因系统的实际更新周期，避免拉取未完成数据 |
| 单次拉取数据上限 | 前1000条 | 适配单任务的内存占用上限，避免数据过载 |
| 任务重试次数 | 3 次 | 应对临时网络波动或广告API的临时限流 |
| 日志留存时长 | 30 天 | 满足线上故障排查的日志溯源需求 |
| 任务超时时间 | 600 秒 | 适配多数据源拉取的平均耗时 |
| 异常指标阈值 | 按实测标定，如转化成本波动超过±15% | 匹配投放效果优化的核心监控标准 |

## 容易做错的三处
- 现象：定时任务执行后，配置的广告账户root权限被自动重置为初始值。原因：未在FastGPT v4.17.0中关闭定时任务的默认权限重置开关。
- 现象：MCP辅助任务的模型思考耗时超过120秒。原因：未限制单次任务的上下文token使用上限，导致模型加载过多冗余数据。
- 现象：工作流调试的任务响应速度比线上运行更快。原因：调试模式跳过了部分日志写入与权限校验步骤，线上任务需完整执行全部流程。

## 怎么确认配好了
- 查看任务调度日志，确认触发频率与配置的取值一致。
- 模拟符合阈值的异常指标，检查任务是否正常触发并生成对应告警。
- 验证任务执行后的数据是否正确同步到预设的复盘文档或数据看板。
- 检查权限配置项，确认未出现自动重置的情况。
