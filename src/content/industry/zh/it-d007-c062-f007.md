# 投放效果优化的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
投放效果优化场景的数据来源包括广告平台数据、归因系统、CRM线索、落地页数据，更新节奏为实时或日更。日常产出的文档包含日报周报、调价记录、素材测试表、优化复盘文档，数据结构按广告应用、时间、素材维度分类，核心字段包含广告计划ID、素材ID、转化线索标识、token消耗、会话标识等，仅按业务维度归档，无固定统一统计口径。

## 这些特征在「对话日志与审计」这一环带来什么约束
投放效果优化场景的数据多源异构、更新节奏灵活且关联具体业务操作，这为对话日志与审计环节带来三点约束。第一，需按广告应用维度隔离会话日志，避免不同投放项目的操作记录混淆。第二，日志采集需匹配业务的实时或日更节奏，确保异常发生时可快速回溯对应时段的操作。第三，需采集广告计划ID、token消耗等核心业务字段，以便后续按应用维度统计资源消耗、定位异常指标。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chatId` 隔离规则 | 按广告应用ID划分 | 匹配投放效果优化的应用维度统计与权限隔离需求 |
| 日志留存时长 | 30–90 天 | 覆盖常规投放复盘的周期，同时控制存储成本 |
| `responseChatItemId` 采集粒度 | 全量返回对话内容 | 完整记录调价、素材测试等操作的完整对话链路 |
| `detail` 字段采集范围 | 包含token消耗、广告计划ID | 满足按应用维度统计token消耗的业务需求 |
| 异常日志告警阈值 | 单会话token消耗超 5000 token 触发 | 匹配常规投放会话的操作量级，过滤正常波动 |

## 容易做错的三处
- 现象：仅部分Agent可查看对话记录，其余Agent无权限访问 | 原因：未按`chatId`绑定广告应用ID，导致会话隔离配置未生效
- 现象：调用日志页面无内容，无法查看模型调用记录 | 原因：未开启`detail`字段的核心业务标识采集，导致日志未关联有效业务信息
- 现象：对话日志丢失，无法回溯异常操作 | 原因：未配置合理的日志留存时长，或docker配置文件未正确挂载日志存储路径

## 怎么确认配好了
- 登录FastGPT v4.17.0的管理后台，进入目标广告应用的会话日志页面，验证仅该应用绑定的Agent可查看对应对话记录
- 执行一次调价或素材测试的对话操作，查看日志详情中的`detail`字段，确认包含token消耗、广告计划ID等业务标识
- 进入token统计页面，按应用维度筛选数据，验证统计结果与实际对话操作的token消耗匹配
- 检查docker配置文件的日志存储路径，确认日志文件未被自动清理，且留存时长符合配置要求
