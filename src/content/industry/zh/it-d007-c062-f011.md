# 投放效果优化的线上故障排查与复盘：数据库与运维

本文基于FastGPT v4.17.0版本编写

## 这个品类的数据长什么样
这个品类的数据主要来自广告平台API、归因系统、CRM线索库与落地页埋点数据，更新节奏多为实时或每日批次更新。日常关联文档包含广告投放日报周报、关键词或素材调价记录、AB测试素材效果表、优化复盘台账。数据字段包含曝光量、点击量、转化数、预算额度、素材标识、投放时段等，单位多为次、元、小时等。

## 这些特征在「数据库与运维」这一环带来什么约束
通常情况下，该品类数据来源分散且更新节奏实时或每日批次触发，要求数据库与运维环节支持多数据源同步写入，避免连接耗尽。日常文档多为结构化的报表与调价记录，需配置事务性存储以保障数据一致性。高频率的数据更新会带来并发写入压力，需要合理设置连接池参数。同时，数据字段包含预算、转化量等核心指标，需规划合理的存储容量与索引结构，加速异常指标的定位查询。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ----------- |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/fastgpt_ad?retryWrites=true&w=majority` | 适配多数据源同步写入的事务性需求，支持失败重试保障数据一致性 |
| `PG_URL` | `postgresql://user:pass@host:5432/ad_optimize?sslmode=require` | 存储结构化的调价记录、测试报表等文档，SSL加密保障敏感数据安全 |
| `DB_MAX_LINK` | `200–300 个连接` | 适配实时/高并发的数据更新场景，避免连接耗尽导致写入失败 |
| `REDIS_URL` | `redis://:pass@host:6379/0` | 缓存高频查询的投放指标数据，缩短异常定位的响应时间 |

## 容易做错的三处
- 现象：知识库同步失败，界面显示「数据源连接超时」或字段为空。原因：未正确配置`MONGODB_URI`指向docker部署的数据库实例，导致FastGPT无法读取同步后的知识库数据。
- 现象：数据库备份文件过大，无法直接转移至本地。原因：未针对投放效果优化的高数据量场景配置分批次备份策略，导致单备份文件超出本地存储上限。
- 现象：实时投放指标查询超时，返回结果条数不足。原因：未设置合理的`DB_MAX_LINK`参数，连接池耗尽导致新的查询无法建立连接。

## 怎么确认配好了
- 运行内置的数据库连通性测试工具，验证`MONGODB_URI`、`PG_URL`与`REDIS_URL`的连接状态，确认无认证或地址配置错误。
- 提交一条模拟的投放调价记录，查看系统日志与数据库表数据，确认数据成功写入。
- 发起多并发的指标查询请求，确认数据库连接池未出现耗尽情况，连接数符合业务并发需求。
- 查看缓存监控面板，确认高频投放数据被正常缓存，查询流程符合预期。
