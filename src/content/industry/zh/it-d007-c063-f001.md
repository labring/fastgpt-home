# 投放计划搭建的线上故障排查与复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据主要来自广告平台接口、用户画像数据集、内部预算排期表与归因工具。日常产出的文档包含投放计划、定向设置规则、预算排期表、转化追踪配置项。数据更新频率为每日或单次活动启动时更新，字段包含定向人群标签、预算额度、转化事件ID、投放时段等，单位涉及元、人次、小时等，无固定统一的格式规范，需匹配对接的外部广告系统的字段要求。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的数据来源分散且格式不统一，要求HTTP接口需支持多源数据的字段映射与格式转换，避免因字段不匹配导致配置失败。数据更新频率为每日或单次活动启动时，接口调用频率需匹配数据更新节奏，避免高频调用触发外部系统限流。日常产出的配置文档包含多类独立模块，接口需支持分模块提交或完整计划同步，减少单次请求的复杂度。同时，配置错误会直接导致预算浪费或投放无法启动，接口需内置基础校验逻辑，提前拦截无效参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `Authorization` | `Bearer {API_KEY}` 格式的令牌 | 符合FastGPT v4.17.0官方接口的身份校验规范，确保接口调用权限合法 |
| `variables` | 按投放计划模块分组传递，例如`{"targeting": [], "budget": {}}` | 匹配日常投放计划的文档结构，降低字段映射的复杂度，便于排查错误 |
| `responseData` | 包含`code`、`message`、`data`三级结构 | 统一外部系统的返回格式，便于快速识别调用结果与错误原因 |
| 单次请求数据量 | 10–20 条投放配置项 | 匹配广告平台接口的单次提交上限，避免因请求过大触发限流 |
| 超时时间 | 30–60 秒 | 覆盖预算校验、人群标签拉取等常规操作的耗时，避免因超时导致的半成功配置 |

## 容易做错的三处
- 调用接口返回`{"code":514,"statusText":"invalid api key"}`，原因：未正确配置`Authorization`参数，令牌格式或权限不匹配对接系统要求。
- 接口返回的结果无文本格式内容，仅包含结构化数据，原因：未在请求中指定`responseData`的文本解析规则，未匹配投放计划搭建所需的可读输出格式。
- 提交批量投放配置后部分定向设置未生效，原因：单次请求数据量超过外部广告系统的单次提交上限，导致部分配置项被截断未处理。

## 怎么确认配好了
- 调用接口前，核对`Authorization`参数与对接系统提供的令牌一致，确保身份校验通过。
- 提交测试配置后，检查`responseData`返回的结构是否符合预设的投放计划字段要求，确认数据格式匹配。
- 发起单次小批量配置请求，观察外部广告系统的返回日志，确认配置项已正确同步。
- 模拟投放计划的更新场景，验证接口的重试机制是否在超时后正确触发，避免半成功配置。
