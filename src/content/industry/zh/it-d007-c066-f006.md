# 搜索广告关键词管理的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
搜索广告关键词管理的核心数据来自搜索广告后台、搜索词报告、竞价排名数据、落地页数据。日常处理的文档包含关键词清单、否词表、出价记录、搜索词报告，字段覆盖关键词文本、匹配类型、单次出价金额、点击量、转化成本、落地页跳转链接等。数据更新频率通常为每日或每周，不同广告账户的同步节奏存在差异。不同于信息流广告创意测试，该品类围绕用户主动搜索词展开管理。本文基于FastGPT v4.17.0版本进行配置说明。

## 这些特征在「定时任务与自动化」这一环带来什么约束
数据来源分散且更新节奏不固定，要求定时任务需匹配广告数据的实际更新周期，避免在数据未同步时触发处理任务。多类型文档混合处理时，需区分不同文档的字段规则，自动化流程需兼容不同格式的输入文件。数据字段多且关联紧密，任务执行时需校验字段完整性，避免因缺失字段导致后续处理异常。针对关键词扩展、否词筛选、出价匹配调整等最耗时环节，自动化流程需优先处理高优先级任务。故障发生后会直接影响广告投放效果，要求自动化流程具备及时的失败告警与重试机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发时机 | 按广告数据更新周期（每日凌晨2点/每周一凌晨3点） | 匹配广告平台的数据同步节奏，避免处理未完成更新的数据源 |
| 批量处理批次大小 | 50-100条/次 | 平衡任务执行效率与系统资源占用，避免单任务加载过多数据超时 |
| 任务超时阈值 | 600秒 | 适配常规广告数据处理的耗时范围，防止任务长期占用执行资源 |
| 失败重试次数 | 2次 | 抵消临时网络波动或接口抖动的影响，减少不必要的任务失败 |
| 告警触发条件 | 任务失败/耗时超过阈值2倍 | 及时通知运维人员处理异常，避免故障扩大影响广告投放 |
| 日志留存周期 | 30天 | 满足线上故障排查的日志查询需求，平衡存储资源消耗 |

## 容易做错的三处
- 现象：批量处理关键词清单时，前十几条正常执行，后续任务无响应或返回空结果。原因：未拆分批量任务为小批次，单任务加载的关键词数量超出系统单次处理上限。
- 现象：定时任务仅能以1小时为最小间隔执行，无法调整为更短的周期。原因：沿用了平台预设的默认调度间隔，未修改任务触发周期的配置参数。
- 现象：飞书知识库关联的关键词数据未自动更新，需手动触发同步操作。原因：未开启知识库自动同步配置，未绑定数据更新的触发规则。

## 怎么确认配好了
- 手动触发一次配置好的定时任务，查看任务执行日志中是否有对应数据的处理记录。
- 检查任务调度列表，确认触发间隔符合预期设置，与预设的广告数据更新周期匹配。
- 模拟一次异常场景，如断开临时数据源连接，验证告警通知是否正常触发。
- 对比手动处理单条数据的结果与自动化批量处理的结果，确认字段匹配与数据一致性。
