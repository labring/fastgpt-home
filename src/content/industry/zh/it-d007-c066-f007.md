# 搜索广告关键词管理的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
该品类的数据通常来自搜索广告后台、搜索词报告、竞价排名数据与落地页数据，更新频率为日级或周级。日常产出的文档包含关键词清单、否词表、出价记录与搜索词报告，数据结构以结构化字段为主，包含关键词文本、匹配类型、出价金额、点击量、转化量、否词规则条目等，单位涉及元、次、千次展示成本等，文档格式多为表格或可编辑清单，便于批量管理与检索。

## 这些特征在「对话日志与审计」这一环带来什么约束
该品类的数据来源分散且格式存在差异，要求对话日志需统一采集不同系统的关键词操作、出价调整、否词变更记录，并关联业务文档的唯一标识。数据更新频率存在日级与周级的差异，要求审计周期需匹配对应数据的更新节奏，避免跨周期日志遗漏。日常文档字段较多且涉及广告投放核心操作，要求日志需完整保留操作人、时间、修改内容等字段，不得随意截断，同时需支持按`detail`字段检索具体的操作细节，以快速定位故障关联的对话链路。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chatId` | 绑定对应搜索广告账户的唯一标识 | 确保对话日志与特定广告账户的关键词操作绑定，避免跨账户日志混淆 |
| `responseChatItemId` | 保留最近8条对话上下文 | 覆盖单次故障排查的完整交互链路，避免关键调整步骤的上下文丢失 |
| `detail` | 记录关键词文本、出价变更前后值、否词规则调整内容 | 完整保留审计所需的操作细节，满足合规追溯的核心字段要求 |
| 日志存储周期 | 180 天 | 匹配广告行业常规的合规审计周期，覆盖月度、季度复盘的时间跨度 |
| 检索触发阈值 | 按实测标定 | 适配该品类数据量规模，避免检索时返回过多无效日志 |

## 容易做错的三处
- 现象：工作流中配置文本内容提取节点后，多轮对话上下文无法被正确读取。原因：未正确绑定`chatId`参数，导致对话上下文与当前操作的广告账户关键词任务不匹配。
- 现象：工作流的代码运行节点输入包含历史记录字段时，校验失败无法启动。原因：未按配置要求限定历史记录的关联范围，导致字段校验逻辑触发异常。
- 现象：调用模型时偶发响应为空，且流程卡住10秒后报错。原因：对话日志未配置`detail`字段的完整记录，导致无法定位模型调用时的输入参数异常。

## 怎么确认配好了
- 进入FastGPT v4.17.0的日志管理页面，输入目标广告账户的`chatId`，验证是否能检索到对应关键词调整的对话记录。
- 查看单条日志详情，确认`detail`字段包含关键词文本、出价变更前后值等核心操作信息。
- 触发一次关键词出价调整的工作流，检查日志是否完整保留操作人、时间、修改内容等审计所需字段。
- 在工作流配置页面，验证历史记录绑定参数，确认配置后校验环节无报错。
