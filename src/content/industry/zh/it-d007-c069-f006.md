# 数据库运维的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
数据库运维场景的数据主要来源于数据库监控系统、操作审计日志、SQL执行计划文件与工单系统。日常产出的文档包括数据库变更单、慢SQL性能报告、备份恢复记录与权限申请审批单。数据更新节奏分为两类：随单次数据库变更实时生成，或按日生成批量统计报表。数据字段包含执行时长（毫秒）、备份文件大小（GB）、权限申请的审批状态等，不同来源的数据格式与结构存在差异。

## 这些特征在「定时任务与自动化」这一环带来什么约束
数据来源分散且格式各异，要求定时任务需适配多数据源的拉取逻辑与格式解析规则，避免因格式不兼容导致数据丢失。更新节奏的差异要求任务周期需匹配对应数据的生成频率，例如针对变更单需按触发式执行，针对慢SQL报告需按日执行。数据关联的业务风险较高，任务失败或执行异常可能引发数据权限越界或查询超时，因此需配置完善的失败重试与告警机制，确保异常可被及时感知与处理。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 定时任务触发周期 | `1 天` 或 `每变更触发` | 匹配慢SQL报告、数据库变更单的常规更新节奏，避免重复处理或遗漏关键数据 |
| 任务执行超时阈值 | `300 秒` | 适配单实例慢SQL分析、日志拉取的常规耗时，防止任务长时间阻塞占用资源 |
| 失败重试次数 | `2 次` | 应对临时的监控接口波动或网络抖动，降低单次异常导致的任务失败概率 |
| 知识库绑定范围 | 绑定对应业务数据库的专属知识库 | 限定检索范围，避免跨库数据干扰故障排查结果 |
| 异常告警触发条件 | 任务失败或检索结果为空时 | 及时通知运维人员处理异常，符合故障排查的时效性要求 |

## 容易做错的三处
- 现象：定时任务执行后返回空的慢SQL分析结果。原因：未正确配置任务拉取的数据库监控数据源地址，导致无法获取有效日志数据。
- 现象：配置自动切换知识库时出现报错。原因：未将知识库与对应数据库实例的标识绑定，任务无法识别目标检索范围。
- 现象：任务启动校验失败，提示缺少必填配置。排查项：验证是否未在App/Admin服务端配置必填环境变量AIPROXY_API_ENDPOINT（AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加路径后缀，不是VLLM/Ollama/Xinference等单模型地址）和AIPROXY_API_TOKEN（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空，不是应用API Key、模型供应商密钥等），或错误将变量填写至应用API请求头、工作流全局变量等处，违反FastGPT v4.17.0的部署要求。

## 怎么确认配好了
- 检查App/Admin服务端的环境变量，确认AIPROXY_API_ENDPOINT（AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加路径后缀，不是VLLM/Ollama/Xinference等单模型地址）和AIPROXY_API_TOKEN（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空，不是应用API Key、模型供应商密钥等）已正确配置且非空。
- 手动触发一次定时任务，查看任务执行日志，确认数据源拉取、知识库检索环节无异常报错。
- 模拟一次数据库变更工单，验证自动化审核流程是否正常触发并生成对应结果。
- 配置失败告警，模拟任务异常场景，确认告警通知正常触达。
