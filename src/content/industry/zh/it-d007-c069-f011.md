# 数据库运维的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
通常，数据库运维的线上故障排查与复盘数据来源于数据库监控系统、操作审计日志、SQL执行计划文件以及内部工单系统。日常产出的文档包括数据库变更单、慢SQL分析报告、全量/增量备份记录、权限申请审批单。数据更新频率通常为每日同步或随数据库变更实时更新，文档结构以结构化字段为主，包含实例ID、执行时间、影响行数、权限等级等基础字段，无额外自定义统计单位。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据来源要求运维环节需关联不同系统的日志与文档，才能完整定位故障根因。日级或变更级的更新节奏，要求故障排查流程需及时拉取最新的监控数据与变更记录，避免依赖过期信息。多样的日常文档类型，意味着运维配置需支持按文档类型快速检索，同时需统一归档路径便于后续复盘。最耗时的慢查询定位环节，要求配置需支持按执行时间、影响行数快速过滤SQL执行计划，缩短排查周期。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[username:password]@host:port/database?authSource=admin` | 符合MongoDB官方连接格式，适配FastGPT v4.17.0的数据库接入要求 |
| `PG_URL` | `postgresql://username:password@host:port/database` | 遵循PostgreSQL标准连接字符串规范，兼容主流云数据库实例 |
| `DB_MAX_LINK` | `100–200 个` | 平衡数据库并发处理能力与资源占用，避免连接耗尽导致服务中断 |
| `REDIS_URL` | `redis://[password@]host:port` | 满足FastGPT的会话缓存、向量索引缓存需求，保障服务状态持久化 |
| 慢查询超时阈值 | `600 秒` | 覆盖绝大多数业务查询的正常执行时长，便于定位异常慢查询 |
| 备份保留周期 | `7–30 天` | 符合日常数据库归档的通用要求，便于故障发生后回溯历史数据 |

## 容易做错的三处
- 现象：无法通过`MONGODB_URI`连接外部MongoDB实例，返回连接超时或认证失败报错。原因：未在连接字符串中添加正确的认证源参数，或网络安全策略限制了数据库端口的访问权限。
- 现象：本地调试环境请求外部数据库接口失败，返回403或连接拒绝状态码。原因：未配置正确的网络白名单或代理规则，导致本地请求无法穿透到外部数据库服务。
- 现象：数据库连接池耗尽，出现Too many connections报错。原因：配置的`DB_MAX_LINK`参数超过数据库实例的最大连接数上限，未结合实例资源情况调整取值。

## 怎么确认配好了
- 运行FastGPT内置的数据库连接测试工具，验证`MONGODB_URI`、`PG_URL`等配置项能否正常建立连接，测试阈值按数据库实例的连接要求设定。
- 执行慢查询检测脚本，确认慢查询超时阈值配置生效，触发条件按业务查询的平均耗时标定。
- 查看缓存服务监控面板，确认`REDIS_URL`配置正常，会话状态能够正常持久化。
- 检查备份任务的执行日志，确认备份保留周期配置符合预设的归档要求。
