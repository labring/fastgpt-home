# 数据清洗与质检的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
这个品类的数据来源包括原始数据集、ETL日志、标注平台输出与抽样结果。日常关联文档包含清洗规则、质检抽样表、异常数据清单与交付报告。数据更新节奏为每日或按每批任务触发。数据字段涵盖原始数据标识、清洗标记、异常类型、质检评分与交付状态，无额外约定单位。处理环节聚焦重复数据识别、异常值处理与抽样质检，结果直接影响业务指标的准确性与交付合规性。

## 这些特征在「定时任务与自动化」这一环带来什么约束
数据来源分散且更新节奏不固定，要求定时任务需支持按批量触发或固定周期拉取不同数据源。日常文档多为结构化规则与清单，自动化配置需适配规则导入与校验逻辑。数据字段的标准化程度影响异常识别的精准度，定时任务需预留字段映射调整空间。每批任务的数据量波动较大，自动化流程需配置合理的资源阈值。异常数据清单的实时更新要求任务失败后能触发重试机制，避免数据不可用风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发周期 | 按数据更新节奏设置为每日1次或每批任务完成后 | 匹配数据日更或按批交付的更新频率 |
| 单次任务数据处理上限 | 10000条 | 适配常规批量数据的处理规模，避免资源过载 |
| 失败重试次数 | 3次 | 应对临时网络或数据源波动导致的任务中断 |
| 异常数据告警阈值 | 异常占比超过5% | 触发人工复核，避免指标失真 |
| 任务超时时间 | 3600秒 | 适配复杂清洗与质检流程的耗时需求 |

## 容易做错的三处
- 现象为API请求返回404 - 未找到资源，原因是定时任务配置中未正确关联数据源的存储路径或索引配置。
- 现象为知识库检索无自动索引的图片内容，原因是定时任务未配置图片元数据的同步环节，仅同步了文本数据。
- 现象为定时任务执行后异常数据清单字段为空，原因是任务配置中未映射异常数据的对应字段，导致清洗结果无法正确写入目标文档。

## 怎么确认配好了
- 手动触发一次定时任务，查看FastGPT v4.17.0版本的任务日志模块，确认包含数据源拉取、清洗规则执行与质检结果生成的完整记录。
- 检查异常数据清单的字段完整性，确认异常类型、原始数据标识等字段均已正确填充。
- 模拟数据源更新，验证定时任务是否按预设周期自动触发并完成全流程。
- 查看告警配置是否在异常占比超出阈值时触发通知，确认告警链路正常。
