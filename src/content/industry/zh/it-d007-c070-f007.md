# 数据清洗与质检的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
本品类处理的数据来源于原始数据集、ETL运行日志、标注平台产出结果及抽样质检结果。数据更新按日或单批任务节奏推进，日常产出清洗规则文档、质检抽样表、异常数据清单与交付报告。单条数据包含原始内容字段、清洗标记字段、质检状态字段、异常类型字段，无额外强制单位，字段值多为文本、布尔型或枚举类型。

## 这些特征在「对话日志与审计」这一环带来什么约束
本品类的数据来源覆盖多系统产出，对话日志与审计环节需支持按原始数据集、ETL日志、标注结果等来源维度筛选，确保跨系统操作可追溯。数据按日或单批更新的节奏，要求审计日志需按更新周期归档，避免存储资源冗余。异常数据清单与交付报告需与审计日志绑定，日志需记录异常数据关联ID、质检状态标记，确保问题回溯可匹配对应质检环节。多角色参与的清洗与质检流程，日志字段需包含操作人角色、操作类型与操作时间，区分不同岗位的操作权限与操作痕迹。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 日志存储周期 | 30–90 天 | 适配FastGPT v4.17.0版本的日志归档规则，匹配本品类日/批更新的任务节奏，确保完整追溯周期 |
| 关联`chatId`字段 | 开启 | 绑定单批清洗/质检任务的对话上下文，确保日志与任务一一对应，便于按任务维度检索 |
| 开启`detail`日志 | 开启 | 记录完整操作内容，包括清洗规则调整、质检抽样参数变更等细节，覆盖本品类核心操作场景 |
| 日志筛选维度 | 按数据来源、任务批次、操作角色 | 匹配本品类多来源、分批次更新、多角色参与的业务特征 |
| 审计权限范围 | 限定为数据工程师、质检员角色 | 区分岗位操作权限，避免非授权人员查看敏感清洗与质检数据 |
| 日志导出格式 | CSV 格式 | 适配本品类日常交付的质检抽样表、异常数据清单等文档格式，便于后续分析 |

## 容易做错的三处
- 现象：调用对话删除接口后，对应审计日志仍保留在列表中。原因：未配置`responseChatItemId`关联的日志清理规则，导致审计日志与实际对话记录解绑。
- 现象：执行清洗任务时无响应，服务器日志未返回明确报错信息。原因：未开启`detail`日志记录，无法捕获任务执行中的异常环节。
- 现象：下载异常数据清单时触发代理报错。原因：未配置审计日志的文件访问权限，导致日志关联的异常数据文件无法正常访问。

## 怎么确认配好了
- 执行单批清洗任务，查看审计日志列表是否包含对应`chatId`的上下文记录，确认任务关联关系正常。
- 切换不同角色账号，验证是否仅能查看对应权限范围内的审计日志，确认角色权限配置生效。
- 触发异常数据标记操作，查看`detail`字段是否记录完整操作内容，确认详细日志开启正常。
- 下载审计日志文件，验证导出格式与日常交付文档格式匹配，确认导出配置生效。
