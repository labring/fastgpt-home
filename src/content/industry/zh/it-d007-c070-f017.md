# 数据清洗与质检的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
本品类处理的数据来源包括原始数据集、ETL运行日志、标注平台产出结果及抽样质检结果，更新频率为每日或每批次任务周期。日常关联文档包含清洗规则配置文件、质检抽样统计表、异常数据清单与交付报告，字段涵盖数据ID、异常类型、处理状态、抽样覆盖率等，无统一强制单位，随业务数据集字段适配。

## 这些特征在「部署与升级」这一环带来什么约束
数据来源分散且更新节奏不稳定，要求部署环节需支持多数据源对接配置，升级时需兼容旧版数据源映射规则，避免数据拉取失败。日常文档多为结构化配置与清单类文件，部署时需预设文档存储路径与权限规则，防止清洗规则、质检抽样表等核心文件丢失。单次任务数据量波动大，升级后需预留足够的内存与计算资源缓冲，防止异常值处理环节过载。同时需保障部署环境与标注平台、ETL工具的网络连通性，否则会导致数据拉取与处理中断。

## 配置怎么定
以下配置适用于 FastGPT v4.17.0 版本

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `50–80 连接` | 适配每日/每批批量数据处理的并发需求，避免连接池耗尽 |
| `MONGODB_URI` | `mongodb://用户名:密码@部署地址:27017/clean_data` | 存储异常数据清单、质检抽样表等结构化文档 |
| `REDIS_URL` | `redis://:自定义密码@部署地址:6379/0` | 缓存清洗规则与临时抽样结果，降低重复计算开销 |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.aliyuncs.com` | 存储原始数据集备份与交付报告文件 |
| `ROOT_KEY` | `长度≥32位的强随机字符串` | 保障部署环境的管理员权限安全，防止未授权配置修改 |
| `FE_DOMAIN` | `https://your-fastgpt-domain.com` | 配置前端页面的跨域访问规则，确保文档预览功能正常 |

## 容易做错的三处
- 现象：部署后清洗规则无法加载，关联的原始数据集无数据返回。原因：未正确配置`MONGODB_URI`或`REDIS_URL`，导致配置文件与临时缓存无法读取。
- 现象：工作流中添加数据清洗与质检插件后，无输入输出参数显示。原因：部署时未正确设置`FE_DOMAIN`，前端无法拉取插件元数据接口，导致参数渲染失败。
- 现象：批量数据清洗任务超时失败，日志显示连接池耗尽。原因：`DB_MAX_LINK`配置值过低，无法支撑批量任务的并发数据库请求。

## 怎么确认配好了
- 登录部署服务器，执行数据库连接测试命令，验证`DB_MAX_LINK`配置的连接数可正常建立并复用。
- 访问前端域名，打开清洗规则管理页面，确认可正常加载已配置的清洗规则与异常数据清单。
- 提交一批测试数据，运行清洗任务，查看任务日志无数据库连接或存储相关报错。
- 进入工作流编辑器，添加数据清洗与质检插件，确认输入输出参数列表正常加载。
