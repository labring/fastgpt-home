# 数据脱敏处理的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
该品类的数据主要来自业务数据库、数据字典、脱敏执行工具与访问审批系统，更新节奏按单批次或单项目推进。日常产出的文档包含脱敏方案、字段映射表、脱敏验证报告与访问审批记录，数据字段涵盖敏感字段标识、脱敏规则编码、执行批次号、审批状态与验证结果，无统一固定单位，随单条数据的属性灵活匹配。

## 这些特征在「对话日志与审计」这一环带来什么约束
数据按批次更新且关联项目，要求对话日志审计需按项目维度隔离数据，避免跨项目敏感信息泄露。文档依赖字段映射表，审计时需关联对应字段的脱敏规则，验证日志中的信息是否完成合规脱敏。数据来源覆盖多系统集成，需确保审计日志能同步各系统的操作记录，覆盖脱敏工具执行、审批流程触发等全环节。敏感字段的审计需精准匹配标识，无法依赖通用日志解析规则，需结合字段映射表完成校验。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chatId` 会话隔离规则 | 按项目+用户维度生成 | 匹配该品类按项目更新的数据特征，实现跨项目会话日志隔离 |
| `detail` 日志采集粒度 | 800 字符截断 | 平衡日志可读性与存储成本，覆盖核心审计信息 |
| `responseChatItemId` 响应关联标识 | 强制绑定至脱敏批次号 | 便于将审计日志与脱敏执行记录关联，实现全链路溯源 |
| 日志批量提交间隔 | 30 秒 | 平衡审计实时性与系统负载，适配多批次数据的同步需求 |
| 日志存储周期 | 90 天 | 匹配合规审计的常规留存要求，与该品类审批记录的留存周期一致 |
| 敏感字段审计触发阈值 | 按实测标定 | 不同项目的敏感字段定义不同，需结合字段映射表调整参数 |

## 容易做错的三处
- 现象：对话日志中部分敏感字段未完成脱敏，原因：未关联字段映射表配置审计校验规则，导致未触发对应字段的脱敏验证。
- 现象：客户端关闭SSE连接后，对话日志未写入数据库，原因：未等待`responseChatItemId`绑定完成就终止请求，导致日志落盘失败。
- 现象：跨项目的会话日志可被非授权用户查看，原因：未按`chatId`的项目维度配置隔离规则，导致会话标识未绑定项目信息。

## 怎么确认配好了
- 生成一条测试会话，查看审计日志中是否包含`detail`字段的完整上下文，验证采集粒度符合配置要求。
- 检查`chatId`参数是否按项目+用户维度生成，尝试用非授权账号访问对应会话，确认无法查看日志内容。
- 手动触发SSE连接后快速关闭，查看数据库中是否存在对应`responseChatItemId`的日志条目，验证绑定逻辑生效。
- 查看FastGPT v4.17.0的系统日志存储目录，确认日志留存周期符合配置的90天要求。
