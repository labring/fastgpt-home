# 文本标注项目的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
这个品类的日常文档包含标注规范、样本包、质检报告、问题反馈表，数据主要来自客户语料、标注平台、词表及质检抽样结果，更新节奏以每日或每批标注任务为周期。数据字段多包含文本内容、标注标签、质检评分、问题标注等，单位以字符、标签类别、抽样批次为主，整体围绕语义边界、实体识别与意图分类的标注需求展开，区别于图像标注项目对视觉特征的关注。

## 这些特征在「定时任务与自动化」这一环带来什么约束
数据来源分散且更新周期不固定，需定时同步多渠道的语料与标注结果，易出现数据重复或遗漏。样本包与质检报告的批量处理需求大，单次处理量受系统限制，需拆分任务避免超时。标注规范的版本更新频繁，需定时校验当前使用的规范与最新版本是否一致，防止标注偏差。问题反馈表的实时性要求高，需自动化流转至对应处理环节，避免人工跟进延迟。同时，文本数据的语义校验需依赖词表与标注规则，定时更新词表可提升标注一致性。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置逻辑编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 定时触发周期 | 15–60 分钟，或按标注批次完成后触发 | 适配日/每批的更新节奏，避免频繁触发占用系统资源 |
| 单次处理样本量 | 100–500 条 | 匹配系统单次数据处理的限制，防止触发内容长度超限报错 |
| 规范与词表校验间隔 | 24 小时 | 适配标注规范、词表的每日更新频率，确保使用最新规则 |
| 任务超时阈值 | 600 秒 | 为批量文本处理预留充足时间，避免中途中断任务 |
| 失败重试次数 | 2–3 次 | 应对临时的网络波动或数据读取异常，减少任务失败率 |

## 容易做错的三处
- 现象：批量导入大量文档时触发maxLength报错，单次处理结果条数不足。原因：未设置合理的单次处理任务量，超出系统单次数据读取的内容长度限制。
- 现象：知识库检索完成后，重排模型持续占用显存，无法自动释放。原因：未配置任务完成后自动卸载闲置模型的规则，导致资源持续被占用。
- 现象：工作流中对话框自动提问功能无响应，未触发预设动作。原因：未正确绑定触发条件与提问动作，未关联对应标注任务的上下文数据。

## 怎么确认配好了
- 查看定时任务的触发日志，确认任务按预设周期或批次节点正常启动。
- 执行单次批量处理测试，核对处理的样本量与配置的单次处理任务量一致。
- 模拟标注规范或词表更新，校验系统是否按配置的间隔触发校验动作。
- 触发一次失败的测试任务，确认系统按配置的重试次数执行重试操作。
