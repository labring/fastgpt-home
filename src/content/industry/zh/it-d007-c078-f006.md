# 机柜上架与布线的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据来源为DCIM系统、资产管理系统、网络拓扑图与客户服务工单。日常产出的文档包括机柜上架申请单、布线拓扑图、端口标签对照表、现场施工记录。数据更新节奏为每完成一单或每日同步一次。字段包含机位编号、线缆端口号、设备型号、施工时间等，单位多为物理位置单位（如U位）、端口编号、长度单位等。处理的是新增或变更设备的物理接入环节，区别于机房巡检类的日常巡查工作。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据来源分散，覆盖DCIM、资产系统等多个平台，定时任务需配置跨系统数据拉取逻辑，需根据系统响应速度调整拉取间隔，避免占用过多资源。文档类型多样，包含表格类的端口标签表、拓扑类的布线图，自动化流程需适配不同文档的解析规则。数据更新随工单完成实时变动，定时任务需支持按工单触发的灵活调度。物理字段的精确性直接决定排查结果，自动化校验环节需严格匹配机位编号、端口号等无歧义字段，无法容忍近似匹配。

## 配置怎么定
本配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 跨系统数据拉取间隔 | 300–600 秒 | 匹配数据每日更新与工单即时性的平衡，避免频繁拉取占用系统资源 |
| 任务执行超时时间 | 120 秒 | 避免单任务执行过长占用队列资源，确保任务按时完成 |
| 文档解析触发时机 | 按上架工单提交后触发 | 对应数据更新节奏，确保解析数据与工单状态同步 |
| 端口标签校验规则 | 精确匹配端口编号 | 物理接入环节对字段精度要求高，无法接受模糊匹配 |
| 任务失败重试次数 | 2–3 次 | 应对临时网络波动导致的拉取失败，避免重复执行过度占用资源 |
| 异常告警触发阈值 | 连续2次校验失败 | 及时通知运维人员处理异常，避免影响上架进度 |

## 容易做错的三处
- 现象：定时校验任务执行后，端口标签匹配结果为空，无报错日志。原因：未配置跨系统拉取DCIM数据的权限，导致任务无法获取最新的端口编号数据。
- 现象：定时任务重复执行多次后，机柜布线图的解析结果出现重复条目。原因：未设置任务去重逻辑，同一工单的文档被多次拉取解析。
- 现象：上架验收环节的自动化校验触发后，工单状态未同步更新，导致后续流程阻塞。原因：未配置任务执行完成后联动资产系统更新工单状态的回调逻辑。

## 怎么确认配好了
- 手动触发一次定时任务，检查拉取的数据是否包含当前测试工单的全部关联文档与系统数据。
- 提交一份测试上架工单，触发对应定时任务，确认校验规则是否按预设的精确匹配逻辑执行。
- 模拟一次数据拉取失败的场景，确认是否触发预设的告警通知，且重试逻辑按配置执行。
- 查看任务执行日志，确认所有关联系统的调用均按配置的间隔与权限正常完成。
