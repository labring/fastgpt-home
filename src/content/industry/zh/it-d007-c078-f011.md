# 机柜上架与布线的线上故障排查与复盘：数据库与运维
本文基于FastGPT v4.17.0版本编写

## 这个品类的数据长什么样
该品类的数据主要来自DCIM系统、资产管理系统、网络拓扑图及客户服务工单。日常产出的文档包括机柜上架申请单、布线拓扑图、端口标签台账、现场施工记录。数据更新频率为每单或每日更新，随每一次上架、布线调整同步变更。数据字段包含机位编号、线缆型号、端口对应关系、施工日期、验收状态等，单位多为物理位置单位（如U位）、线缆长度单位（如米）、端口标识（如RJ45-1）。

## 这些特征在「数据库与运维」这一环带来什么约束
数据来源分散且关联物理实体设备，要求数据库需支持多源数据同步与跨系统关联查询，需兼容不同系统的字段格式差异。更新频率随工单触发，峰值时段的并发请求量较高，数据库连接池需支持按需扩容，避免连接耗尽导致数据同步失败。物理设备的唯一性要求，需在数据库中对机位编号、端口标识建立唯一索引，防止重复上架或接错端口。施工记录的归档需求要求数据库支持历史版本查询，便于故障复盘时回溯操作轨迹。同时，数据关联物理实体，运维环节需严格控制数据写入权限，避免误修改导致的物理接入错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://dcim-ops:securepass@dcim-cluster:27017/rack_data?authSource=admin` | 适配DCIM系统的分布式文档存储，用于保存机柜布线图、端口标签表等非结构化数据 |
| `PG_URL` | `postgresql://asset-ops:assetpass@asset-db:5432/rack_ops?sslmode=prefer` | 存储结构化的上架申请单、施工记录，支持按机位、施工日期进行多条件查询 |
| `DB_MAX_LINK` | `15–25` | 匹配每日工单的并发处理量，避免因连接池耗尽导致数据同步中断 |
| `REDIS_URL` | `redis://redis-auth:redispass@cache-host:6379/1` | 缓存临时机位规划结果与端口校验状态，减少数据库的高频重复查询开销 |

## 容易做错的三处
- 控制台返回`connection timed out`或`authentication failed`报错，无法查询机柜端口数据。原因：`MONGODB_URI`配置中未正确指定DCIM集群的副本集地址或认证信息，未匹配DCIM系统的数据库权限。
- 端口标签表查询结果为空，无法核对线缆对应关系。原因：`PG_URL`配置的数据库用户无端口标签表的查询权限，或未关联资产系统的对应数据表。
- 施工记录更新后未同步到运维面板，导致上架验收状态异常。原因：`DB_MAX_LINK`取值过低，连接池耗尽后新的写入请求被拒绝。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`与`PG_URL`的连通性，测试用例需覆盖DCIM与资产系统的核心数据表。
- 提交一条测试上架工单，观察施工记录是否能正常写入数据库，验证`DB_MAX_LINK`的连接池配置是否满足写入需求。
- 查看REDIS缓存的机位规划数据，确认临时校验结果能正常生成与过期，验证`REDIS_URL`的配置有效性。
- 检查数据库的慢查询日志，确认端口标签、布线图的查询耗时符合业务预期，调整连接池参数时以此为依据。
