# 渗透测试服务的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
本品类的数据主要来自目标系统、公开漏洞库、自动化扫描器结果与红队工程师手工验证记录，随单个渗透测试项目或目标系统重大版本更新。日常产出的文档包含测试授权书、渗透测试报告、漏洞复现记录与整改建议，字段覆盖授权范围、漏洞编号、复现步骤、风险评级等。数据关联的核心环节为测试授权确认、漏洞验证与报告评级，数据缺失或错误可能引发业务中断、漏洞遗漏或法律授权争议。

## 这些特征在「定时任务与自动化」这一环带来什么约束
本品类的数据随单个项目或目标系统版本更新，要求定时任务绑定项目启动、版本迭代等事件触发。多源数据包含自动化扫描结果与手工验证记录，自动化环节需配置数据校验规则，区分两类结果的优先级。测试授权书作为合规依据，定时任务需前置校验授权范围，避免越权操作。漏洞验证环节耗时占比高，自动化任务需预留人工复核触发节点，同时配置严格的失败告警与数据回滚机制，防止因任务异常引发漏洞遗漏或合规风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 任务触发方式 | 绑定项目启动/目标系统版本更新事件 | 本品类数据随项目或版本更新，固定周期触发易产生无效任务 |
| 任务执行超时阈值 | 1800秒 | 漏洞验证与报告生成环节耗时较长，需预留足够执行时间 |
| 扫描结果召回上限 | 前5条 | 避免过多扫描数据占用任务资源，同时覆盖主要漏洞类型 |
| 授权范围校验规则 | 校验当前项目授权书与目标系统的匹配性 | 避免越权操作，符合合规要求 |
| 结果合并逻辑 | 优先使用手工验证记录，补充前3条未验证扫描结果 | 本品类包含人工验证环节，需保证结果准确性 |
| 失败告警触发条件 | 任务执行失败或结果校验不通过时触发 | 本品类出错后果严重，需及时响应 |
| 任务重试次数 | 2次 | 平衡任务成功率与资源消耗，符合FastGPT v4.17.0版本的任务重试机制设计 |

## 容易做错的三处
- 现象：定时任务执行时提示“未获取有效授权范围”，但当前项目已上传测试授权书。原因：未配置任务前置校验授权文档的逻辑，直接调用扫描工具导致权限校验失败。
- 现象：跨渗透测试项目切换后，旧项目的必填全局变量仍被校验，引发配置报错。原因：未清理上下文关联的旧项目参数，定时任务复用了历史配置的全局变量。
- 现象：自动化扫描任务生成的报告未包含手工验证的漏洞记录。原因：未配置结果合并时优先使用手工验证数据的规则，仅调用了扫描器结果。

## 怎么确认配好了
- 触发一次测试项目的定时任务，检查任务日志中是否包含授权范围校验通过的记录。
- 切换不同的渗透测试项目，确认任务仅校验当前项目的授权文档与目标系统信息。
- 模拟任务执行失败的场景，检查是否触发预设的告警通知。
- 查看任务执行结果，确认手工验证记录优先于扫描结果被纳入最终报告。
