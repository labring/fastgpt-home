# 渗透测试服务的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
渗透测试服务的核心数据来源于目标系统、公开漏洞库、自动化扫描器结果与红队工程师手工验证记录。日常关联文档包括测试授权书、渗透测试报告、漏洞复现记录与整改建议，数据字段通常包含测试授权编号、漏洞CVE标识、复现步骤、操作时间戳、执行主体ID与风险评级。数据更新节奏以单个测试项目或重大版本迭代为周期，无固定高频更新频率。

## 这些特征在「对话日志与审计」这一环带来什么约束
这些特征对对话日志与审计环节带来明确约束。首先，数据关联测试授权书与合规文档，日志必须绑定唯一授权编号，防止跨项目日志混淆，规避法律授权争议。其次，数据按单个项目或版本更新，对话日志需按项目维度隔离存储，不同测试项目的日志不可交叉访问。再者，手工验证记录依赖完整交互细节，日志需留存对话上下文与操作步骤，便于漏洞复现与风险评级。最后，数据出错会引发业务中断或合规风险，日志需具备不可篡改属性，留存周期覆盖项目全周期与后续整改环节。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId`绑定规则 | 按测试授权编号生成唯一`chatId`，绑定对应会话 | 确保不同测试项目的会话日志隔离，符合数据按项目划分的特征 |
| 详细日志开关 | 开启`detail`参数，采集前1000 字符的上下文 | 完整记录用户输入与红队操作细节，满足漏洞复现需求 |
| 日志保留时长 | 90–180 天 | 覆盖项目全周期与后续整改、审计环节 |
| 日志超时阈值 | 600 秒 | 匹配红队工程师手工验证的平均操作时长，避免会话长时间占用资源 |
| 会话权限控制 | 按执行主体ID隔离会话 | 确保不同工程师或团队仅能查看自身负责项目的日志 |
| `responseChatItemId`关联规则 | 将工作流模块日志绑定到对话节点ID | 关联代码运行输出与对话上下文，便于排查模块执行问题 |

## 容易做错的三处
- 现象：通过API创建的对话无法在页面查看历史记录，原因是未配置`chatId`绑定规则，API会话未关联页面会话标识，导致会话数据分离。
- 现象：响应记录预览中Human字段为null，原因是未开启`detail`参数的用户输入日志采集，未完整记录对话交互内容，仅存储了部分上下文。
- 现象：工作流代码运行模块的console.log无法在检查控制台查看，原因是未将模块日志与`responseChatItemId`绑定，未将运行输出关联到对应对话节点，导致日志无法溯源。

## 怎么确认配好了
- 发起携带`chatId`参数的API对话，验证返回结果中包含对应会话的日志内容，且日志关联了测试授权编号。
- 查看对话详情页，确认Human字段存在用户输入内容，`detail`参数对应的详细日志已完整采集。
- 运行工作流代码模块，检查控制台是否有日志关联到当前对话的`responseChatItemId`，可通过日志搜索验证关联关系。
- 切换不同执行主体的会话，验证仅能查看自身绑定`chatId`的日志，无法访问其他项目的会话数据。
