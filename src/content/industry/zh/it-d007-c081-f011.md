# 渗透测试服务的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
该品类的数据主要来自目标系统日志、公开漏洞库、自动化扫描器结果与红队工程师手工验证记录。日常关联文档包括项目测试授权书、正式渗透测试报告、漏洞复现流程记录、整改优先级建议。数据更新以单个项目或系统重大版本迭代为节奏，无固定周期。单份项目数据包含授权范围、漏洞编号、利用路径、修复状态等字段，无统一量化统计单位，仅按项目维度归档存储。

## 这些特征在「数据库与运维」这一环带来什么约束
该品类的数据特征对数据库与运维环节带来多重约束。多源混合的数据来源，包含结构化的漏洞评级数据与非结构化的手工验证文本，要求数据库支持多格式存储与灵活的混合查询能力。数据更新无固定周期，需支持按需写入，避免定时批量同步导致的闲置资源占用。关联的测试授权书属于敏感法律文档，需配置细粒度权限控制，防止数据越权访问。项目数据量随漏洞数量增长，需限制单库并发连接数，避免运维层面的性能瓶颈，保障工具调用的响应速度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://pentest_user:secure_pass@db-host:5432/pentest_db?sslmode=require` | 存储结构化的测试授权书、漏洞评级数据，适配FastGPT v4.17.0的结构化数据存储规范，需SSL加密保障敏感信息安全 |
| `MONGODB_URI` | `mongodb://pentest_user:secure_pass@mongo-host:27017/pentest_data?authSource=admin` | 存储非结构化的漏洞复现记录、手工验证文本，支持灵活的文档型查询，适配多源数据的混合检索需求 |
| `DB_MAX_LINK` | `20–30` | 匹配单项目数据量与并发验证请求，避免数据库连接池耗尽导致的服务中断，适配红队工程师的日常操作节奏 |
| `REDIS_URL` | `redis://:cache_pass@redis-host:6379/0` | 缓存高频查询的漏洞库数据与授权状态，降低数据库重复访问压力，提升工具调用的响应速度 |

## 容易做错的三处
- 现象：开启问题优化与结果重排后，工具调用返回超时，耗时超过30秒。原因：未配置`DB_MAX_LINK`的合理取值，导致数据库连接池耗尽，无法及时响应多源数据查询请求。
- 现象：工具选择环节出现并发调用，同一漏洞验证请求触发多次扫描器调用。原因：未通过Redis缓存工具调用结果的临时锁，导致重复触发任务，增加数据库与扫描器的负载。
- 现象：本地部署后无法创建项目数据库。原因：未正确配置`PG_URL`的数据库权限，当前用户缺少CREATE SCHEMA或CREATE TABLE的必要权限，无法完成数据库初始化。

## 怎么确认配好了
- 执行FastGPT v4.17.0内置的数据库连接测试脚本，验证`PG_URL`与`MONGODB_URI`的连通性，确认权限配置符合文档存储的安全要求。
- 提交单份测试授权书数据，检查数据库写入与关联查询的响应速度，匹配业务场景的耗时要求。
- 查看Redis连接日志，确认缓存键的过期时间配置符合漏洞库数据的更新节奏，避免缓存数据过期导致的重复查询。
- 模拟多用户并发提交漏洞验证请求，检查数据库连接池的使用情况，确认`DB_MAX_LINK`的取值适配并发负载。
