# 渠道归因与线索分发的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
渠道归因与线索分发的数据来自广告平台、CRM系统、归因SDK与表单系统，更新节奏多为日度或周度汇总。日常维护的核心文档包括归因规则配置表、线索分发表、渠道效果报表与异常核对单，数据字段包含渠道标识、线索来源时间、转化节点、归属销售ID、转化金额等，无统一固定格式，需根据对接的数据源调整校验维度。

## 这些特征在「定时任务与自动化」这一环带来什么约束
多源异构的数据来源要求定时任务需支持跨系统的数据拉取与格式适配，避免因字段缺失导致任务中断。日度或周度的更新节奏要求任务触发时间需匹配各数据源的同步窗口，防止拉取到未完成结算的不完整数据。核心文档的校验依赖要求自动化流程需内置字段核验逻辑，减少人工核对的耗时。同时，渠道ROI失真、销售归属争议等出错后果，要求任务需配置失败重试与告警机制，保障流程稳定性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的官方规范。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发时间 | 每日凌晨2:00-4:00（按数据源日结窗口标定） | 匹配多数广告平台与CRM系统的日结周期，避免拉取未完成的数据 |
| 数据拉取范围 | 前1个自然日的全量渠道与线索数据 | 覆盖当日所有转化线索，保障归因与分发的完整性 |
| 字段校验规则 | 渠道ID、线索来源时间、归属销售ID为必填项 | 过滤无效数据，避免因字段缺失导致任务异常 |
| 失败重试次数 | 3次，每次间隔60秒 | 应对临时网络波动或数据源短暂不可用的场景 |
| 任务超时时间 | 1800秒 | 避免长任务占用集群资源，适配多数日度任务的执行时长 |
| 异常告警阈值 | 任务失败率超过5%时触发告警 | 及时发现批量异常，避免错误数据流入后续流程 |

## 容易做错的三处
- 定时任务执行后返回404状态码，排查项为未正确配置服务端的AIPROXY_API_ENDPOINT（AI Proxy服务根地址，不可附加/v1、/chat/completions等路径后缀）或AIPROXY_API_TOKEN（AI Proxy管理员Token，需与服务端配置一致且非空，不是应用API Key、模型供应商密钥等其他token）环境变量，导致依赖服务无法正常访问。
- 线索去重结果为空或数量异常，原因是未配置对应重复字段的校验规则，导致重复线索无法被自动识别。
- 定时任务触发后无数据输出，原因是任务触发时间晚于数据源的日结窗口，导致未拉取到当日的有效数据。

## 怎么确认配好了
- 检查服务端部署配置中的AIPROXY_API_ENDPOINT（AI Proxy服务根地址，不可附加/v1、/chat/completions等路径后缀）和AIPROXY_API_TOKEN（AI Proxy管理员Token，需与服务端配置一致且非空，不是应用API Key、模型供应商密钥等其他token）是否正确。
- 手动触发一次定时任务，查看任务日志中是否有对应数据源的拉取与处理记录。
- 核对任务输出的线索分发表字段是否与对接的源数据字段一致，无缺失或异常。
- 模拟输入一条不符合校验规则的测试数据，查看任务是否触发对应异常提示。
