# 游戏内容合规自查的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
本品类的数据主要来源于游戏研发与运营阶段的文本内容、美术资源、剧情脚本，以及监管公开的合规要求。日常维护的核心文档包括内容自查表、敏感内容修改记录、用户协议、合规评审纪要。数据更新节奏为每版本或每运营活动触发，核心字段包含内容类型、合规校验状态、关联版本号、评审修改记录，数据体量随游戏内容的更新规模动态变化。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据更新随版本与活动触发，定时任务需匹配游戏研发的版本打包、活动预热周期，避免在核心开发时段占用计算资源。多类型数据源要求任务支持分模块校验，需配置不同的校验规则适配文本、美术、脚本等不同内容格式。数据关联的合规文档需绑定版本号，任务执行时需校验当前关联的自查表、评审纪要等文档的版本有效性。出错后果涉及上线延期与舆情风险，任务需配置明确的失败告警与重试阈值，避免因单次校验异常导致整体流程阻塞。

## 配置怎么定
本文配置基于FastGPT v4.17.0版本，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发时机 | 版本打包前24小时、活动上线前48小时 | 匹配游戏版本与活动的筹备周期，预留校验与修改时间 |
| 校验数据源范围 | 本次版本新增的文本、美术、剧情脚本 | 避免重复校验历史合规内容，提升任务执行效率 |
| 失败重试次数 | 2次 | 平衡校验准确性与资源占用，避免因临时网络异常导致任务失败 |
| 告警触发阈值 | 连续2次校验失败 | 及时通知合规团队处理异常，避免延误上线节奏 |
| 任务执行超时时间 | 3600秒 | 适配多类型内容的校验时长，避免因内容体量过大导致任务中断 |
| 结果留存周期 | 180天 | 匹配合规文档的留存要求，便于后续评审与溯源 |

## 容易做错的三处
- 现象：切换合规文档数据源后，任务仍调用旧版本的自查表字段进行校验，触发「字段缺失」报错。原因：未在任务配置中更新关联的文档版本号，导致任务沿用历史配置的变量参数。
- 现象：定时任务执行后仅返回文本校验结果，未包含美术资源的合规状态。原因：未在数据源范围配置中勾选美术资源校验项，导致任务遗漏对应内容的校验逻辑。
- 现象：任务执行超时后直接终止，未触发预设的告警通知。原因：未配置告警触发阈值，仅依赖任务默认的失败处理逻辑，导致异常未被及时感知。

## 怎么确认配好了
- 手动触发一次测试任务，检查任务日志中关联的文档版本号与当前使用的自查表版本一致。
- 查看任务配置的数据源范围，确认本次版本新增的所有内容类型均被勾选。
- 模拟一次校验失败的场景，检查是否触发预设的告警通知。
- 查看任务执行后的结果报告，确认所有配置的校验模块均生成了对应的合规状态记录。
