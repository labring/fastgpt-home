# 游戏内容合规自查的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
本品类的数据由游戏发行合规岗、内容审核员、游戏制作人日常生成，来源包括游戏文本、美术资源、剧情脚本及监管公开要求。数据更新频率为每版本或每运营活动，日常配套文档包含内容自查表、敏感内容修改记录、用户协议、合规评审纪要。数据围绕单次合规检查任务生成，包含审核内容片段、审核动作、评审意见及关联的版本或活动标识，结构贴合合规自查的全流程节点。

## 这些特征在「对话日志与审计」这一环带来什么约束
不同于游戏版号与出版申报，本品类的合规自查发生在申报前和版本更新中，因此日志无需覆盖全出版流程，仅需聚焦单次版本或活动的检查节点。数据按版本或活动更新的特征，要求对话日志需支持按版本、活动维度批量检索与归档，便于按批次回溯合规检查问题。日常配套文档的结构化特征，要求日志字段需关联具体审核节点、任务ID，确保可与自查表、修改记录一一对应。数据包含多类型内容资源的审核记录，要求日志需区分内容类型并记录对应校验参数，适配不同资源的合规检查逻辑。监管相关的数据属性，要求日志留存需满足合规追溯要求，且不可随意篡改或删除。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 对话日志留存周期 | 90–120 天 | 匹配游戏版本更新的平均周期，满足合规追溯与复盘需求 |
| `chatId` 参数启用 | 开启 | 关联单条对话与具体审核任务，解决调用日志无法定位对应审核任务的问题 |
| `detail` 日志开关 | 开启 | 记录完整的审核内容片段与评审意见，满足合规自查的审计要求 |
| `responseChatItemId` 字段采集 | 开启 | 记录单条对话的唯一标识，便于跨系统关联审核任务与日志 |
| 日志检索超时阈值 | 600 秒 | 避免长时间检索导致系统负载过高，适配批量合规检查的场景 |
| 日志自动清理规则 | 按版本归档后清理过期日志 | 降低冗余存储占用，适配高频次的版本更新节奏 |

## 容易做错的三处
- 现象：调用合规检查接口后，对话日志中未显示`chatId`字段。原因：未开启`chatId`参数的日志采集配置，导致任务关联信息缺失。
- 现象：无法查看OneAPI调用大模型的失败日志详情。原因：未开启`detail`日志开关，仅采集了基础调用状态，未记录详细报错内容。
- 现象：合规自查日志因存储占用过高被自动清理。原因：未按版本周期配置留存周期，留存时长超过系统预设的存储阈值。

## 怎么确认配好了
- 发起一次合规检查调用，传入指定`chatId`，在对话日志列表中确认该字段已正常显示。
- 触发一次大模型调用失败的场景，查看日志详情，确认包含`detail`字段记录的报错信息。
- 尝试按版本ID检索日志，确认可快速定位对应批次的合规检查记录。
- 查看系统存储监控，确认已配置的自动清理规则可定期清理过期日志，避免存储溢出。
