# 游戏客户端性能优化的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
该品类的数据主要来自引擎Profiler导出的帧率、CPU占用日志，崩溃平台的闪退上报数据，真机测试的资源加载耗时记录，以及版本迭代配套的性能测试报告、机型适配清单、优化记录与崩溃分析报告。数据更新频率为每日或每版本迭代时更新，文档通常包含机型标识、帧率数值、资源加载路径、崩溃堆栈信息等字段，单位涵盖帧率（fps）、耗时毫秒（ms）、资源占用兆字节（MB）等。

## 这些特征在「数据库与运维」这一环带来什么约束
该品类的数据来源分散且更新频率不定，需要数据库支持多格式的批量数据写入，因此数据库连接池配置需要适配高并发批量写入场景。多维度的字段结构要求数据库建立针对性索引，以优化按机型、版本号等条件的查询效率。数据出错会直接导致游戏卡顿、闪退甚至商店差评，因此需要保证数据写入的可靠性与查询的低延迟。此外，该品类更关注帧率与资源加载相关数据，对时间序列查询的性能有较高要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://perf_user:xxxx@db-host:27017/game_perf?authSource=admin` | 存储非结构化的崩溃堆栈、优化记录等文档型数据，支持灵活的字段扩展 |
| `PG_URL` | `postgresql://perf_user:xxxx@db-host:5432/perf_metrics?sslmode=prefer` | 存储结构化的帧率、资源加载耗时等时间序列数据，支持高效的范围与条件查询 |
| `DB_MAX_LINK` | `20–30 个连接` | 匹配每日版本迭代时的批量数据写入并发，避免数据库连接耗尽 |
| `REDIS_URL` | `redis://:xxxx@redis-host:6379/1` | 缓存高频访问的机型适配清单、近期性能测试报告摘要，降低数据库读负载 |
| Redis缓存过期时间 | `3600 秒` | 缓存变化频率较低的机型适配数据，减少重复数据库查询开销 |

## 容易做错的三处
- 现象：MongoDB连接状态显示失败，控制台返回连接超时或认证失败报错。原因：未正确配置`MONGODB_URI`中的用户名、密码或认证源参数，或数据库网络策略限制了访问。
- 现象：并发请求达到一定数量后出现无应答，本地模型服务器资源未耗尽。原因：未调整`DB_MAX_LINK`的连接数上限，数据库连接池被耗尽，无法接收新的请求。
- 现象：性能数据查询结果为空或缺失近期记录。原因：批量写入数据时未设置合理的数据库写入超时，导致部分日志数据未成功入库。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`、`PG_URL`和`REDIS_URL`的连通性，确认无认证或网络错误。
- 模拟每日版本迭代的批量数据写入场景，检查数据库连接池的使用情况，确认连接数未超过`DB_MAX_LINK`的配置值。
- 查询缓存中的机型适配清单数据，确认数据更新频率符合业务要求，验证Redis缓存的有效性。
- 发起多并发的性能数据查询请求，观察数据库的负载情况，确认查询延迟符合排查需求。
