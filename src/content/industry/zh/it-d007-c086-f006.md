# 游戏版号与出版申报的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自国家新闻出版署办事服务平台、著作权登记系统、游戏包体文件及运营机构提交的资质材料。日常处理的文档包含申报请示文件、游戏申请表、著作权证明、审读报告等，单款游戏的申报数据更新无固定周期，随审批流程推进不定期调整。数据字段包含申报批次编号、著作权登记号、包体校验值、审读修改意见等，不同申报阶段的文档结构存在差异，部分材料需随包体版本同步更新。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据来源分散且更新无固定周期，定时任务无法仅依赖固定时间间隔触发，需绑定申报流程中的节点事件。不同申报阶段的文档结构差异明显，自动化处理流程需适配多套文档格式，无法使用统一的拆分与校验规则。数据字段存在跨来源的格式差异，需在自动化环节中加入字段映射与格式校验步骤，避免因字段不匹配导致的流程中断。同时，申报材料的一致性要求较高，对应业务中最耗时的材料核对环节，定时任务的失败处理需触发人工复核流程，防止错误数据进入审批环节。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按申报节点事件触发，固定间隔设为7天作为备用 | 适配数据更新不定期的特征，避免无效执行 |
| 文档拆分规则 | 按行拆分Excel文件，单块长度设为800–1200字符 | 匹配申报文档的单行单条数据格式，避免内容合并 |
| 字段校验阈值 | 字段匹配度设为90%以上，超时时间设为300秒 | 保障申报材料的一致性，适配审批流程的时效要求 |
| 失败重试配置 | 重试2次，重试间隔设为60秒 | 应对临时的接口调用失败，减少人工介入 |
| 知识库导入分隔符 | 自定义为换行符，Excel导入启用单行单条模式 | 解决Excel导入时多行内容合并的问题，符合业务数据格式 |
| 告警触发条件 | 任务失败或结果异常时触发 | 及时通知项目负责人处理异常，避免影响审批进度 |

## 容易做错的三处
- 现象：Excel导入申报材料时，自动拆分结果为多行内容合并在单条数据中，字段出现错位。原因：未启用自定义分隔符的单行单条模式，默认拆分规则未适配Excel的行分隔逻辑。
- 现象：定时任务执行图片处理环节后，未按预期替换文档中的图片链接，任务状态显示为失败。原因：未配置图片上传的目标文件服务器地址，自动化流程无法完成链接替换。
- 现象：工作流调用知识库助手生成审读报告时，API返回空值，任务执行超时。原因：使用v4.8.10以上版本的FastGPT时，未在工作流中正确配置知识库调用参数，导致上下文加载失败。

## 怎么确认配好了
- 手动触发一次定时任务，检查申报材料的拆分结果是否为单行单条，确认分隔符配置生效。
- 模拟一次字段不匹配的场景，查看告警是否正常触发，确认告警配置的有效性。
- 调用API测试工作流，检查返回结果是否包含预期的审批材料校验信息，确认知识库与工作流的联动正常。
- 查看任务日志，确认重试机制在临时失败时是否正常触发，确认失败处理配置的正确性。
