# 游戏策划与数值设计的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自玩家行为日志、公开竞品资料、游戏内战斗记录与版本反馈。日常产出的文档包含玩法策划案、数值配置表、版本需求单及平衡性测试记录。数据更新以周或单版本为周期，数值表字段包含伤害系数、技能冷却时长、掉落概率等，单位涉及秒、道具数量等，文档结构多为结构化表格与规则说明文本。

## 这些特征在「定时任务与自动化」这一环带来什么约束
该品类的数据更新以周或单版本为周期，因此定时任务触发频率需匹配更新节奏，避免重复处理未更新的历史数据。日常产出的结构化数值表与规则文档，要求自动化流程适配表格解析、字段匹配逻辑，减少格式错误导致的异常。战斗日志与玩家反馈数据量随版本迭代增长，定时任务的批量处理上限需适配数据规模，防止处理超时。数值类配置的错误会直接引发玩法失衡，自动化环节需增加前置校验步骤，确保配置合规后再执行。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时任务触发周期 | `7天`或单版本上线前1天 | 匹配数据周/单版本的更新节奏，避免重复处理历史数据 |
| 批量处理数据上限 | 前2000条或按实测标定 | 适配战斗日志与版本反馈的数据规模，同时符合FastGPT v4.17.0的任务调度能力 |
| 自动化校验开关 | 开启 | 数值配置错误会直接引发玩法失衡，前置校验可提前拦截异常配置 |
| 失败重试次数 | 3次，间隔`60秒` | 应对服务器临时波动导致的任务中断，合理重试降低失败率 |
| 异常告警阈值 | 连续2次任务失败 | 过滤单次临时异常，连续失败时及时通知相关人员 |

## 容易做错的三处
- 现象：定时任务执行后，关联的知识库索引状态长时间显示未就绪，无自动重试触发。原因：未配置任务失败后的自动重调度逻辑，或触发周期设置过长导致未及时补执行。
- 现象：自动化校验环节误拦截合规的数值配置，导致任务终止。原因：校验规则未适配该品类的数值字段范围，例如未允许小数精度的概率配置。
- 现象：服务器重启后，已配置的定时任务未自动恢复执行，需手动触发。原因：未配置任务持久化存储，重启后调度信息丢失。

## 怎么确认配好了
- 查看任务调度日志，确认触发周期与业务更新节奏匹配，可通过对应配置项调整周期。
- 模拟单次临时异常场景，确认任务触发自动重试逻辑，验证重试次数与间隔符合预设规则。
- 提交一份合规的数值配置样例，确认自动化校验环节正常通过，无误拦截情况。
- 手动触发服务器重启模拟，确认定时任务自动恢复执行，无需手动干预。
