# 游戏策划与数值设计的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
该品类的数据主要来源于玩家行为数据、战斗日志、版本反馈及竞品公开资料，更新频率为周度或每版本周期。日常产出的文档包含玩法策划案、数值表、版本需求单与平衡性测试记录，其中数值表包含伤害系数、成长曲线参数等字段，单位多为相对比例、固定数值或时间区间，玩法策划案则包含规则描述与流程节点。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据来源分散且更新频繁，要求部署环节需稳定支持多源数据的接入与存储，避免因连接中断导致数值计算中断。高频率的版本更新要求升级流程需兼容旧版数值表与玩法文档的格式，减少版本返工成本。多样的文档结构与字段单位，需要部署配置适配不同类型的解析规则，确保数值模拟与平衡性测试的数据读取准确，同时需兼顾不同环境下的存储与网络适配需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 个连接` | 该品类需频繁读取数值表与战斗日志数据，合理的连接数可避免数据库连接耗尽，支撑并发的数值计算任务 |
| `MONGODB_URI` | 指向专属副本集地址 | 用于存储版本反馈与玩家行为数据，专属地址可隔离业务流量与其他服务，提升数据安全性 |
| `PG_URL` | 配置为带只读副本的数据库地址 | 用于存储数值计算的中间结果，只读副本可分担读压力，避免主库过载 |
| `REDIS_URL` | `600 秒过期时间` | 用于缓存临时的平衡性测试数据，过期时间适配周度更新的节奏，避免缓存占用过多资源 |
| `FILE_TOKEN_KEY` | `32 位随机字符串` | 用于生成文件上传的鉴权令牌，保障策划文档上传的安全性 |
| `STORAGE_S3_ENDPOINT` | 按本地存储或云服务商地址填写 | 用于存储玩法策划案与版本需求单的归档文件，适配不同部署环境的存储需求 |

## 容易做错的三处
- 现象：执行`docker build`命令时返回`ERROR: failed to solve: archive/tar: unknown file mod`错误。原因：部署时未正确处理数值表与策划文档的文件权限，导致打包过程中出现无法识别的文件模式。
- 现象：升级到FastGPT v4.17.0后，数值模拟接口返回`API请求失败: 404 - 未找到资源`报错。原因：升级时未更新`FE_DOMAIN`配置项，导致前端与后端的路由匹配失败。
- 现象：API请求频繁超时，无法读取战斗日志数据。原因：`DB_MAX_LINK`配置过低，导致数据库连接池耗尽，无法处理并发的数值计算请求。

## 怎么确认配好了
- 执行`docker ps`命令，确认所有FastGPT相关容器处于运行状态，检查容器日志中无数据库连接失败的报错。
- 访问配置的`FE_DOMAIN`地址，验证前端页面可正常加载数值配置模块，无资源加载失败提示。
- 提交一份测试用的数值表，触发平衡性模拟任务，确认任务可正常执行并返回结果，无超时或格式错误。
- 检查`REDIS_URL`对应的缓存服务，确认临时测试数据可正常写入与读取，过期时间符合更新节奏要求。
