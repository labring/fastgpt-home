# 漏洞扫描服务的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
漏洞扫描服务的核心数据来源于漏洞扫描器、企业资产清单、公开CVE库及官方补丁公告。日常产出的文档包含标准化扫描计划、漏洞详情清单、整改流转工单、复扫验证报告，各文档包含资产IP/域名、CVE编号、风险等级、修复状态、扫描时间戳等字段。数据更新频率以周或月为周期，随资产变动、CVE库更新同步调整。

## 这些特征在「部署与升级」这一环带来什么约束
漏洞扫描服务的数据来源涉及多系统对接，部署阶段需配置多数据源连接参数，确保扫描器、资产库、CVE库的连通性。日常文档结构标准化，部署需预设字段映射规则，避免扫描结果与工单字段不匹配。数据更新频率灵活，升级时需兼容新旧版本的扫描计划格式，防止历史配置失效。资产范围确认环节依赖精准的资产导入，部署时需校验资产清单的格式合法性，避免扫描范围偏差。误报排除与复扫核对需保留历史扫描数据，升级时需确保数据迁移的完整性，防止历史漏洞记录丢失。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本的漏洞扫描服务部署。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–200 个 | 适配多扫描任务并发的数据库连接需求，避免连接池耗尽 |
| `MONGODB_URI` | 包含认证信息的分片集群连接地址 | 存储海量扫描历史数据与漏洞清单，支持高并发读写 |
| `PG_URL` | 带独立账号密码的关系型数据库连接串 | 存储扫描计划、整改工单等结构化业务数据 |
| `REDIS_URL` | 带访问密码的缓存实例地址 | 缓存扫描任务状态、临时资产数据，降低数据库查询压力 |
| `STORAGE_S3_ENDPOINT` | 企业合规存储服务的官方端点 | 存储扫描报告、日志附件等大体积文件，满足数据留存要求 |
| `ROOT_KEY` | 随机生成的32位字符串 | 作为系统管理员最高权限验证密钥，保障部署后访问安全 |

## 容易做错的三处
- 现象：扫描任务启动后返回`500 Internal Server Error`，日志显示数据库连接超时。原因：未正确配置`DB_MAX_LINK`参数，连接池上限过低导致并发任务耗尽连接。
- 现象：工作流中调用漏洞扫描工具无输出，数据库查询结果为空。原因：`PG_URL`或`MONGODB_URI`配置错误，未包含正确的数据库认证信息或网络访问权限受限。
- 现象：复扫报告无法生成，上传失败。原因：`STORAGE_S3_ENDPOINT`配置的存储服务权限不足，无法写入扫描生成的报告文件。

## 怎么确认配好了
- 执行内置的数据库连通性测试工具，验证`DB_MAX_LINK`、`MONGODB_URI`、`PG_URL`、`REDIS_URL`的配置有效性，确认连接池无耗尽风险。
- 提交一个包含少量资产的测试扫描任务，等待任务完成后检查漏洞清单是否生成，字段是否与预设的文档结构匹配。
- 访问`FE_DOMAIN`配置的前端访问地址，使用`ROOT_KEY`完成管理员权限验证，确认系统访问控制正常。
- 手动上传一份测试用的扫描日志文件，确认`STORAGE_S3_ENDPOINT`配置的存储服务可正常写入和读取文件。
