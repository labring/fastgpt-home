# 现场部署实施的线上故障排查与复盘：定时任务与自动化
本页面基于FastGPT v4.17.0版本编写，面向现场部署实施场景的线上故障排查与复盘定时任务配置。

## 这个品类的数据长什么样
本品类的数据来源于客户机房环境、设备清单、软件包、网络拓扑等现场一手资料，更新节奏为每单或每部署阶段一次。日常产出的文档包括部署手册、安装记录、配置清单、现场签到表，字段覆盖设备型号、软件版本、部署时间、排查节点、现场签到标识等，无统一全局格式，需随单适配客户现场的环境要求，数据仅在对应部署单闭环前有效。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据随单更新且无全局统一格式，定时任务无法使用固定全局周期触发，需绑定对应部署单的完成节点启动。由于数据来源依赖客户现场环境，任务执行需适配不同的网络拓扑与权限规则，超时阈值需预留足够缓冲空间。由于日常文档为非标准化的现场记录，任务需支持动态读取单份文档的指定字段，无法依赖预设的通用数据结构。此外，该品类最耗时环节为环境检查与软件安装配置，故障排查的结果需关联现场部署的具体环节，失败处理需兼顾客户现场的服务时效要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发时机 | 按对应部署单完成后10分钟触发 | 匹配现场部署的收尾流程，确保排查时机贴合实际部署状态 |
| 任务执行超时阈值 | 300-600秒 | 适配客户机房常见的网络波动范围，避免误判正常执行延迟 |
| 日志留存时长 | 7天 | 满足故障复盘所需的日志调取周期，同时控制存储资源占用 |
| 失败重试次数 | 2次 | 避免重复占用客户现场的资源，同时覆盖单次临时网络波动的情况 |
| 异常告警触发条件 | 连续2次执行失败 | 及时通知现场实施工程师，避免故障排查延误 |
| 数据源绑定规则 | 仅关联当前部署单的专属文档 | 避免读取无关数据，确保排查结果的准确性 |

## 容易做错的三处
- 现象：定时任务调用`MCP工具`时返回连接超时报错，状态码504。原因：未针对客户机房的网络拓扑配置访问白名单，导致工具调用节点无法与客户环境建立有效连接。
- 现象：部署单的配置清单字段为空，定时任务无法获取软件包版本参数。原因：未在部署流程中强制同步配置清单数据到定时任务关联的数据源，导致任务读取不到有效信息。
- 现象：定时任务执行后未生成复盘日志，任务状态显示成功但无排查结果。原因：未配置日志输出的触发条件，仅在任务失败时生成日志，导致成功执行的任务无记录留存。

## 怎么确认配好了
- 手动触发一次对应部署单的定时任务，查看任务执行日志是否包含完整的环境检查、软件配置校验步骤。
- 模拟一次客户机房的网络波动，验证任务在超时阈值内是否能完成重试并恢复执行。
- 检查异常告警是否在任务连续失败2次后触发，确认告警渠道配置正确。
- 核对任务执行后生成的复盘数据是否与部署手册、安装记录的字段完全匹配。
