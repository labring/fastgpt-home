# 用户增长与留存运营的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自用户行为日志、推送系统、实验平台与CRM系统，更新频率多为每日或每周一次。日常产出的文档包含增长实验方案、用户分层表、触达文案与留存分析报告，文档结构以标签化字段为主，包含用户标识、触达参数、实验变量与留存指标等内容，无统一二进制格式，多为结构化表格或富文本格式。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据来源分散且更新节奏固定，定时任务需匹配数据同步周期，避免重复处理未更新的历史数据；文档类型多样且需保持版本一致性，自动化任务需关联对应文档的最新版本，防止使用过期的用户分层规则或触达文案；同时该类任务出错会直接影响用户体验与留存指标，需配置失败重试与异常告警机制，降低故障扩散风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发周期 | 按数据更新频率设置为每日1次或每周1次 | 匹配用户分层表、留存报告的更新节奏，避免重复处理旧数据 |
| 任务失败重试次数 | 3次 | 应对推送系统临时波动导致的任务失败，减少人工介入 |
| 单次任务处理数据量 | 不超过10万条用户记录 | 避免超出系统内存上限，防止任务超时 |
| 任务超时时间 | 1800秒 | 适配多系统数据拉取的平均耗时，避免任务被强制终止 |
| 告警触发阈值 | 任务失败率超过5%时触发 | 及时发现触达或归因环节的异常 |
| 文档版本校验开关 | 开启 | 确保使用最新的触达文案、用户分层表执行任务，避免使用过期配置 |

## 容易做错的三处
- 现象：定时同步静态页面到知识库后，查询返回旧版本内容。原因：未将静态页面变更触发与定时任务绑定，仅按固定周期拉取未更新的页面快照。
- 现象：定时器持续调用API但无任务执行记录，日志显示接口参数缺失。原因：未在API请求中配置任务关联的运营文档ID，导致系统无法识别执行目标。
- 现象：工具调用输出包含Human <Instruction>格式的冗余提示。原因：未关闭任务的默认系统提示开关，导致冗余指令混入工具调用上下文，干扰执行结果。

## 怎么确认配好了
- 查看FastGPT v4.17.0的定时任务执行日志，确认每次触发后都能拉取到最新的用户分层数据与触达文案。
- 模拟单次任务失败场景，验证告警通知是否能按配置的失败率阈值触发。
- 调用关联API，检查请求参数中包含正确的运营文档版本标识，无缺失字段。
- 执行一次工具调用任务，确认输出结果中无冗余的系统提示内容。
