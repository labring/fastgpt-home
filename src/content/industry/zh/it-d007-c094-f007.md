# 用户验收测试支持的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
这个品类的数据来自需求规格文档、测试环境运行日志、客户提供的业务样例数据以及缺陷管理系统。更新节奏为每个测试阶段或版本迭代时更新。日常涉及的文档包含UAT用例、验收问题单、验收报告与签字确认单，数据结构涵盖测试场景编号、用户交互内容、故障状态、处理时长等字段。字段均采用业务标准的文本与数值类型，无自定义单位，所有数据围绕验收测试的全流程生成。

## 这些特征在「对话日志与审计」这一环带来什么约束
数据来源涉及客户业务样例，需严格隔离不同客户的对话日志，避免跨用户数据混淆。更新频率为阶段或版本级，日志需按测试阶段归档，便于回溯对应版本的验收过程。文档结构包含UAT用例与验收问题单，审计需关联对应测试场景的日志条目，确保故障排查与用例匹配。字段含用户交互标识，需按`chatId`区分不同参与方的对话记录，避免交互内容交叉干扰。缺陷系统的故障日志需与对话日志绑定，便于复盘时关联故障提交与全流程交互。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 与UAT用例编号绑定，单测试场景生成唯一`chatId` | 便于关联对应测试用例的对话日志，匹配数据来源与文档结构的关联要求 |
| `detail` | 存储完整对话上下文，包含用户提问、助手回复、故障复现描述 | 覆盖验收问题单的核心信息，满足故障排查与审计的细节需求 |
| `responseChatItemId` | 与缺陷系统的故障工单ID一一绑定 | 实现对话日志与缺陷提交的关联，便于复盘时追溯故障处理全流程 |
| 上下文保留条数 | 前12–18条 | 适配UAT测试的对话轮次特征，保留足够交互细节同时避免冗余数据 |
| 日志归档周期 | 按验收阶段结束后7天归档 | 匹配数据每阶段/每版本的更新节奏，便于按阶段开展审计与回溯 |
| 日志存储配额 | 500–1500 MB 按实测标定 | 适配单阶段验收的对话数据量范围，预留空间应对多客户并行测试场景 |

## 容易做错的三处
- 现象：使用FastGPT API对接业务系统时，无法区分不同业务用户的聊天记录，日志中出现交互内容混淆的情况。原因：未按`chatId`绑定对应客户或业务用户的标识，导致不同用户的对话日志未实现有效隔离。
- 现象：点击日志提取配置按钮时触发报错，后台提示正则表达式匹配失败。原因：未针对UAT用例的标准化格式配置正则规则，误将非对话类的文档内容纳入提取范围。
- 现象：部署FastGPT v4.17.0后，尝试通过url创建知识库时提示cannot fetch internal url。原因：未将测试环境的内部接口纳入允许访问的白名单，导致对话日志关联的内部资源无法正常拉取。

## 怎么确认配好了
- 随机选取一条验收对话记录，核对`chatId`是否与绑定的UAT用例编号一致。
- 查看`detail`字段，确认是否包含完整的对话上下文与故障复现描述。
- 关联缺陷系统工单ID，核对`responseChatItemId`是否与工单ID一一对应。
- 检查日志归档规则，确认是否按验收阶段完成时间触发归档动作。
