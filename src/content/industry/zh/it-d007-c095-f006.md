# 监控告警配置的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
本品类的数据来源包括Prometheus、Zabbix、云监控、应用日志与CMDB，更新频率为每日或每次告警规则变更后。日常维护的文档包含监控指标清单、告警规则、值班手册与告警变更记录，数据字段包含指标名称、阈值区间、告警触发条件、通知对象、变更时间与关联资源ID，单位涵盖秒、条、字符等，不同来源的字段格式存在细微差异。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据来源多样且格式存在差异，定时任务需要统一适配多源数据的解析规则，避免出现字段不匹配的问题。数据更新频率为每日或每次变更后，定时任务的执行周期需匹配该节奏，既不能过于频繁浪费计算资源，也不能过于滞后导致告警信息失效。此外，告警规则变更后需触发配置校验，确保变更后的规则能正常生效，同时噪声清理与通知链路验证需通过定时任务定期执行，保障告警体系的稳定性。

## 配置怎么定
本文适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时任务执行周期 | 300秒-3600秒 | 匹配告警数据的更新频率，平衡数据及时性与资源消耗 |
| 告警数据拉取范围 | 前1个变更周期的记录 | 覆盖最新的告警规则变更与指标数据，减少无效历史数据加载 |
| 告警噪声过滤阈值 | 连续3次触发 | 过滤临时波动的误报，避免干扰值班人员 |
| 通知链路验证频率 | 每日1次 | 保障告警通知的可达性，及时发现链路故障 |
| 配置校验触发时机 | 每次告警规则变更后 | 及时验证变更后的配置是否符合要求，避免故障隐患 |

## 容易做错的三处
- 多源告警数据的冲突项未被自动标记，现象是不同来源的告警规则对比后出现字段不一致但未高亮显示，原因是未开启定时的文档冲突分析任务。
- 企业微信外部群主动发送消息失败，现象是调用发送接口返回权限错误，原因是未配置外部群的消息发送白名单校验。
- 告警噪声清理配置不生效，现象是冗余告警仍持续推送，原因是定时任务的执行周期设置过长，未及时清理新增的噪声告警。

## 怎么确认配好了
- 查看定时任务的执行日志，确认最近一次拉取的告警数据条数符合预期范围。
- 手动修改一条告警规则，等待校验任务触发后检查是否生成对应的变更校验记录。
- 模拟触发一次符合阈值的告警指标，验证告警通知是否能正常发送到指定链路。
- 检查冲突分析任务的输出结果，确认多源告警数据的冲突项被正确标记。
