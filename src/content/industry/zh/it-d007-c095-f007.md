# 监控告警配置的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
监控告警配置的数据来源包括Prometheus、Zabbix、云监控、应用日志、CMDB，更新频率为每日或每次配置变更时。日常关联文档包含监控指标清单、告警规则、值班手册、告警变更记录。数据字段包含告警ID、触发阈值、配置生效时间、变更人、关联监控指标，阈值单位多为百分比、毫秒或流量单位，变更记录包含操作时间与操作主体标识。

## 这些特征在「对话日志与审计」这一环带来什么约束
由于数据来源分散，对话日志需关联不同监控系统的唯一标识，确保跨源审计的一致性。更新频率的不确定性要求审计日志需实时记录每次配置变更，避免遗漏关键操作。多字段的结构化数据要求日志需完整保留告警ID、阈值、变更人等核心字段，支撑故障排查时的配置回溯。同时，告警配置变更直接影响故障发现能力，审计日志需具备可追溯性，无法随意修改或删除。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 对话日志导出上限 | 5万条/次 | 匹配FastGPT v4.17.0开源版本的单次导出实测上限，避免导出中断 |
| 对话日志保存时长 | 7–30天 | 覆盖告警配置的常规变更周期与值班复盘的时间跨度 |
| 日志字段配置 | 包含告警ID、触发阈值、变更人、关联指标、`detail` | 覆盖监控告警配置的核心审计维度，`detail`字段记录详细操作细节 |
| 对话ID绑定规则 | 绑定告警配置变更会话的`chatId` | 确保审计链路的唯一性，便于关联对话上下文 |
| 对话回复ID绑定 | 绑定`responseChatItemId` | 关联对话中的具体回复内容，完善审计链路 |
| 审计触发时机 | 配置变更时触发 | 匹配告警配置的更新频率，减少无效日志的生成 |
| 日志存储阈值 | 1000 MB | 按单条日志1–2 KB的平均大小，匹配月度审计数据的存储需求 |

## 容易做错的三处
- 导出对话日志时仅获取5万条记录，无法全量导出。原因是未调整导出上限配置，受限于平台单次导出的默认上限。
- 无法查看接口报错的系统运行日志。原因是未开启详细操作记录的存储配置，未启用`detail`字段的日志采集。
- 对话日志提前被自动清理。原因是未将保存时长设置为匹配告警配置变更周期的时长，默认保存时长过短。

## 怎么确认配好了
- 发起一次告警配置变更，检查审计日志中是否生成对应记录，包含`chatId`、`detail`字段。
- 手动触发一次日志导出操作，确认导出条数符合配置的上限要求。
- 查看日志保存时长配置，确认与告警配置的变更周期匹配。
- 触发一个接口报错，检查是否生成包含错误详情的日志记录。
