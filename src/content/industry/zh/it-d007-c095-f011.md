# 监控告警配置的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
该品类的数据来源包括Prometheus、Zabbix、云监控、应用日志与CMDB系统，更新频率为每日或每次告警规则变更后。日常维护的文档包含监控指标清单、告警规则、值班手册与告警变更记录，字段涵盖指标名称、阈值区间、触发条件、通知链路与关联数据源，单位多为秒、请求次数、连接数等运维常用单位。

## 这些特征在「数据库与运维」这一环带来什么约束
多数据源的采集需求要求数据库连接配置需兼容不同类型的实例，需通过`PG_URL`、`MONGODB_URI`等参数完成对接。高频更新的告警规则与变更记录需要稳定的数据库存储，避免数据丢失或同步延迟。指标阈值的设定需匹配数据库的实际承载能力，例如连接池大小需与`DB_MAX_LINK`参数联动，防止因阈值不合理导致告警噪声或故障漏报。通知链路的验证需依赖`REDIS_URL`配置的缓存服务，确保告警消息能正常转发。

## 配置怎么定
本文档适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据库连接串 | 填写对应数据库实例的完整连接信息，包含用户名、密码与端口 | 适配Prometheus或Zabbix的数据源对接需求 |
| 最大连接池限制 | 800–1200 条 | 匹配数据库的并发承载能力，避免连接耗尽 |
| 告警通知缓存地址 | 填写Redis实例的连接参数 | 用于临时存储告警通知队列，降低主数据库压力 |
| 多行查询执行开关 | 开启 | 支持同时运行多条数据库语句，适配复杂监控指标的批量查询 |
| 告警变更记录同步频率 | 每24小时同步一次 | 匹配告警变更记录的更新频率，确保数据一致性 |
| 测试告警触发阈值 | 当数据库连接失败次数超过10次/分钟时触发 | 对应日常监控指标清单的阈值设定，避免误报 |

## 容易做错的三处
- 执行多行数据库查询时返回语法错误，报错文案包含“you have an error in your SQL syntax”。未开启多行查询执行开关，导致数据库连接插件仅允许单条语句执行。
- 备份恢复后知识库与智能体未显示原有内容。告警配置的备份数据同步链路未关联数据库的备份节点存储路径，导致恢复时未加载正确的数据集。
- 告警通知未按预期发送至值班团队。告警通知缓存地址配置错误，导致告警通知队列无法正常缓存与转发。

## 怎么确认配好了
- 登录FastGPT后台的数据库配置页面，验证数据库连接串的连接状态，查看是否显示连接正常。
- 手动触发一条测试告警，检查是否能通过配置的通知渠道发送至指定对象。
- 查看告警变更记录页面，确认配置的变更已同步至数据库存储。
- 执行一次模拟的多行数据库查询，确认返回结果符合预期。
