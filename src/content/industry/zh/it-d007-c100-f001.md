# 等级保护测评咨询的线上故障排查与复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
等级保护测评咨询的核心数据来自测评工具、访谈记录、系统清单与安全设备日志，更新频率为每项目一次。日常产出的文档包含定级报告、差距分析报告、整改方案与测评报告，数据字段围绕等保控制项、整改证据、系统资产展开，无统一全局字段，需按单个项目单独梳理。该品类的核心工作环节为定级材料梳理、控制项差距核对与整改证据收集，数据关联风险较高，任何数据偏差均可能导致测评不通过或监管检查风险。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于数据按单个项目独立更新且关联监管风险，接口需支持按项目维度隔离数据，避免跨项目数据泄露。多源数据来源要求接口适配不同格式的日志与系统清单，需提供灵活的字段过滤与解析规则。核心文档依赖结构化的控制项与整改数据，接口返回需仅包含业务必要字段，减少冗余数据传输。高风险属性要求接口具备稳定的失败处理机制，降低手动干预成本，同时需适配内部测评工具的自定义配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {测评项目专属令牌}` | 等保测评数据涉及敏感监管信息，使用项目专属鉴权令牌可实现数据隔离，避免跨项目权限泄露 |
| 请求超时时间 | `300-600 秒` | 单次请求可能拉取大量系统清单或日志条目，预留足够响应时间适配大体积数据传输 |
| `responseData` | 仅返回包含控制项ID、整改状态、资产编号的字段 | 匹配日常文档的核心字段需求，过滤冗余内容以降低传输成本，提升数据整理效率 |
| `variables` | 绑定项目编号、测评周期两个全局变量 | 自动适配不同项目的接口请求路径与返回解析规则，无需为每个项目单独配置接口参数 |
| 重试策略 | 失败后重试2次，间隔60 秒 | 应对测评工具临时采集延迟导致的请求失败，减少手动排查与干预的工作量 |

## 容易做错的三处
- 接口请求返回`self-signed certificate`报错，原因是未在FastGPT中导入内部测评工具的自定义SSL证书，等保场景下多数内部工具使用自建证书，未添加信任会阻断数据拉取。
- 接口请求返回`404 page not found`，原因是未绑定`variables`中的项目编号变量，使用固定全局路径发起请求，无法匹配不同项目的专属接口地址。
- 接口返回数据包含冗余字段，原因是未按`responseData`配置过滤规则，返回了未被日常文档使用的日志详情字段，导致后续整理定级报告时需额外清理数据。

## 怎么确认配好了
- 发起单次接口请求，验证`Authorization`鉴权生效，返回数据仅包含配置指定的核心字段。
- 导入自定义SSL证书后，重新发起请求，确认`self-signed certificate`报错消失。
- 切换`variables`绑定的项目编号变量，验证接口请求路径自动更新，返回数据适配新的项目规则。
- 模拟请求失败场景，验证系统在间隔60 秒后自动重试，重试2次后请求成功。
- 确认当前使用FastGPT v4.17.0版本，确保配置项的解析逻辑与当前版本兼容。
