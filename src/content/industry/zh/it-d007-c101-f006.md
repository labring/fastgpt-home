# 续费健康度管理的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自CRM系统、产品使用日志、工单统计台账与合同管理系统。数据更新节奏通常为周度或月度，核心文档包含客户健康度报告、续费预测表、风险客户清单及跨部门沟通纪要。数据字段包含客户唯一标识、合同周期节点、产品使用频次、工单响应时效、续费意向标签等，无统一强制格式，需适配企业内部业务台账的字段结构。

## 这些特征在「定时任务与自动化」这一环带来什么约束
由于数据来源分散且需对接多套业务系统，定时任务需配置跨数据源拉取逻辑，避免单次拉取过载影响目标业务系统的正常运行。数据更新节奏为周度或月度，导致任务执行周期不宜过短，否则会产生重复无效的拉取与计算，浪费系统资源。文档结构无统一标准，自动化流程需兼容多格式业务台账，需预留字段映射调整空间以适配不同企业的台账格式。同时，该环节出错会直接影响续费风险判断，因此需配置失败重试与告警触发机制，避免数据偏差导致客户流失或收入预测失真。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务执行周期 | 每周1次 / 每月2次 | 匹配业务数据的周度/月度更新节奏，避免冗余拉取 |
| 数据源拉取并发数 | 2-4个并发请求 | 平衡数据拉取效率与目标系统的负载承受能力 |
| 失败重试次数 | 3次，重试间隔1200秒 | 应对临时接口波动，避免频繁触发告警通知 |
| 字段映射规则 | 按企业业务台账自定义匹配 | 兼容多格式、非标准化的业务文档结构 |
| 告警触发阈值 | 连续2次任务失败触发 | 及时感知任务异常，避免风险判断滞后 |
| 日志留存时长 | 30天 | 满足后续故障排查的日志追溯需求 |

本页面适配 FastGPT v4.17.0。

## 容易做错的三处
- 现象：定时任务无法设置短于1小时的执行周期，任务触发时间与预期调度存在偏差。原因：默认调度配置限制了最小执行间隔，未调整任务调度的周期参数适配业务需求。
- 现象：批量拉取客户健康数据时，部分字段出现空值或格式错误。原因：未配置自定义字段映射规则，直接使用通用模板匹配企业内部非标准化的业务台账字段。
- 现象：任务执行失败后未收到告警通知，异常状态未被及时感知。原因：告警触发阈值设置不合理，未匹配业务风险的最低触发标准。

## 怎么确认配好了
- 查看任务调度日志，确认任务按预设周期触发，无重复或遗漏执行的记录。
- 手动触发一次任务，核对拉取的数据字段与业务台账的字段匹配一致，无空值或格式错误。
- 模拟一次任务执行失败的场景，确认告警通知能按配置触发并推送至指定渠道。
- 检查日志留存目录，确认任务执行日志按预设时长正常留存，可用于后续故障排查。
