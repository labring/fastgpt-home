# 缺陷管理与回归测试的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
本品类的数据来源于缺陷管理系统、测试报告、代码提交记录与线上用户反馈，更新频率为每日或每个版本发布周期。核心文档包含缺陷单、回归清单、修复验证记录与缺陷统计报表。缺陷单包含唯一标识、优先级等级、复现步骤、修复版本号与验证结果；回归清单包含测试用例ID、关联缺陷与执行状态；修复验证记录包含提交人、操作时间与验证结论；缺陷统计报表按周期汇总缺陷分布与修复进度。数据兼具半结构化与强schema特征，覆盖缺陷全生命周期的追踪与复盘需求。

## 这些特征在「数据库与运维」这一环带来什么约束
多来源的数据同步需要兼容不同格式的写入请求，高频的日更或版本级更新要求数据库支持高并发读写。强schema与半结构化数据混合存储，需要数据库同时支持灵活查询与事务一致性保障。缺陷复现、优先级判定与回归验证的高耗时环节，要求数据库支持复杂关联查询与快速数据加载。严重的出错后果需要数据库具备高可用能力，避免数据丢失或查询中断影响故障排查与复盘流程。本品类聚焦功能缺陷生命周期，与性能测试类品类的数据模型差异显著，需避免混用存储逻辑。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@mongo-host:27017/fastgpt-defect?authSource=admin` | 适配缺陷单、修复验证记录等半结构化数据存储，支持灵活的缺陷生命周期查询 |
| `PG_URL` | `postgresql://username:password@pg-host:5432/fastgpt-regression` | 存储回归清单、缺陷统计报表等强schema结构化数据，保障数据写入与查询的一致性 |
| `DB_MAX_LINK` | `20–30` | 匹配每日或版本级的高频读写需求，避免数据库连接池耗尽导致查询超时 |
| `REDIS_URL` | `redis://:redis-password@redis-host:6379/0` | 缓存热门回归测试用例、缺陷优先级判定规则，降低主数据库的查询压力 |
| 数据保留周期 | `按版本保留12个月` | 满足故障复盘的历史数据查询需求，同时控制长期存储成本 |

## 容易做错的三处
- 现象：本地docker部署的数据库无法写入缺陷数据，报错显示认证失败或连接超时。原因：`MONGODB_URI`或`REDIS_URL`未正确配置docker内部网络地址与认证信息，未匹配容器内的服务端口与账号密码。
- 现象：回归测试用例的执行状态更新后，统计报表未同步更新。原因：混用`MONGODB_URI`存储强schema的统计数据，未使用`PG_URL`绑定专用结构化数据库，导致写入冲突与数据不一致。
- 现象：缺陷优先级判定查询延迟过高，影响故障复盘效率。原因：未配置`REDIS_URL`缓存热门判定规则，每次查询都直接访问主数据库，导致高并发下的延迟。

## 怎么确认配好了
- 执行批量创建缺陷单与查询操作，查看数据库连接日志无连接超时或认证失败报错。
- 检查`PG_URL`绑定的数据库，确认回归清单、统计报表的强schema字段无缺失或异常。
- 查看缓存监控面板，确认热门回归测试用例的请求被正确缓存，无频繁主数据库查询记录。
- 验证数据更新后，统计报表能按业务预设的周期完成同步，无数据滞后情况。
