# 许可证合规与版权声明的线上故障排查与复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据主要来自开源项目的代码仓库、第三方依赖清单、官方许可证文本与贡献者记录。日常产出的文档包含项目根目录的LICENSE文件、标注第三方依赖版权的NOTICE文件、自动生成的依赖许可证清单，以及明确项目版权归属的声明文件。数据更新节奏随项目版本发布或第三方依赖变更触发，核心字段涵盖许可证类型、版权持有者名称、依赖包标识与版本号，无统一的标准化格式，需随依赖调整实时更新。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据分散且格式不统一，要求HTTP接口支持从代码仓库、依赖管理工具、外部合规服务等多源拉取不同结构的许可证与版权文件。高频更新的特性要求接口支持事件触发或定时拉取，避免因数据滞后导致合规校验失效。同时，核心的许可证兼容性核对与版权归属确认环节需依赖外部合规工具的HTTP调用，接口需兼容不同供应商的校验参数格式，且需保证请求的鉴权与权限隔离，防止敏感的许可证配置信息泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 对应接口的合法鉴权凭证（如应用API Key） | 符合对应HTTP接口的鉴权规范，确保接口调用权限合法 |
| `variables` | `{"license_sources": ["github", "npm"], "check_interval": "3600 秒"}` | 适配多源数据拉取与定时更新的业务需求，匹配本品类高频变更的特性 |
| `responseData` | `{"license_type": string, "copyright_holder": string, "compliance_result": boolean}` | 统一合规校验后的返回格式，便于后续故障排查与复盘 |
| 超时时间 | `300 秒` | 覆盖多源数据拉取与合规校验的完整流程，避免因网络延迟导致请求中断 |
| 触发规则 | 依赖变更事件触发 + 每日全量校验 | 平衡数据实时性与系统资源占用，适配本品类的更新频率 |

## 容易做错的三处
- 现象：调用HTTP接口时返回`401 Unauthorized`，且日志显示鉴权失败。排查项：核对接口鉴权使用的Token是否为对应接口的合法鉴权凭证（如应用API Key），检查是否误将AI Proxy管理员Token填入接口请求头的Authorization字段。
- 现象：拉取依赖许可证清单时返回空数据，且未触发错误日志。原因：未正确配置`variables`中的数据源路径，导致接口无法定位到依赖清单文件。
- 现象：向外部合规服务发送校验请求后返回`504 Gateway Timeout`。原因：未设置合理的超时时间，合规校验流程耗时超过接口默认限制，导致请求中断。

## 怎么确认配好了
- 检查服务端环境变量`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token）是否已正确配置，且未在工作流全局变量、应用API请求头或模型管理页面配置。
- 发起一次测试HTTP请求，验证`Authorization`头的鉴权有效性，确认返回的`responseData`包含预期的合规校验字段。
- 触发一次手动拉取任务，核对返回的许可证数据与本地仓库的LICENSE、NOTICE文件内容一致。
- 模拟一次依赖变更事件，确认接口自动触发合规校验流程，无异常报错。
