# 许可证合规与版权声明的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
本品类的数据核心围绕开源项目的使用授权与版权归属展开。数据来源包括项目代码仓库、第三方依赖清单、官方许可证文本、代码贡献记录。日常产出的标准化文档包含LICENSE文件、NOTICE文件、依赖许可证清单、版权声明文件。数据更新节奏为每版本发布或依赖包变更时触发，单条数据包含依赖包名称、版本号、许可证类型、版权持有者、许可证文本片段、贡献者标识等字段，无额外聚合统计类数值字段。

## 这些特征在「对话日志与审计」这一环带来什么约束
本品类的数据分散在代码仓库、依赖清单等多个独立源，且更新频率随版本或依赖变更触发，无统一的集中存储入口，需通过不同工具分别拉取。在对话日志与审计环节，需同时关联对话上下文与对应依赖项的合规信息，因此需要跨源拉取数据的能力。标准化文档的字段与对话日志中的调用记录需严格匹配，例如对话中提及的依赖包名称需与依赖清单中的字段完全一致，否则会导致合规核对失效。此外，数据无额外聚合统计类数值字段，仅能基于结构化元数据完成合规校验，无法通过聚合类指标快速定位异常。同时，由于数据更新无固定周期，审计环节需支持按版本或依赖维度筛选日志，确保覆盖最新的合规配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` 关联维度 | 按会话ID绑定，单会话关联不超过50条依赖记录 | 本品类数据按依赖与会话关联，单会话涉及的依赖项通常不超过50个，避免日志过载 |
| `responseChatItemId` 日志绑定节点 | 绑定至回复节点，仅记录合规校验相关的回复内容 | 合规校验的核心信息存在于对话的回复环节，绑定该节点可精准定位合规相关的日志片段 |
| `detail` 日志展开字段 | 开启全量展开，包含依赖包名称、许可证类型字段 | 本品类数据依赖结构化元数据，展开该字段可完整获取合规校验所需的关键信息 |
| 日志存储周期 | 90 天 | 本品类数据随版本更新，90天的存储周期可覆盖至少3个版本的合规校验需求，同时避免存储资源过度占用 |
| 跨源依赖拉取上限 | 前 10 条 | 单会话涉及的依赖项通常不超过10个，拉取前10条可覆盖绝大多数合规排查场景，减少拉取耗时 |
| 版本自动同步配置 | 按项目版本号自动更新关联清单 | 本品类数据更新随版本或依赖变更触发，自动同步可确保审计日志始终匹配当前版本的合规配置 |

## 容易做错的三处
- 现象：审计日志中未显示依赖包的许可证类型字段，原因：未开启`detail`全量展开配置，仅拉取了基础会话信息，未包含合规所需的元数据字段。
- 现象：对话界面显示令牌校验失败，日志中显示令牌为“fastgpt”，原因：未正确绑定`chatId`与项目的合规配置，导致会话关联的依赖清单未匹配当前令牌的授权范围，引发合规校验异常。
- 现象：无法获取全量对话记录，原因：未设置合理的跨源拉取上限，或未按`responseChatItemId`绑定节点，导致部分合规相关的对话片段未被纳入审计范围。

## 怎么确认配好了
- 进入FastGPT v4.17.0的审计日志页面，选择对应会话的`chatId`，检查日志中是否包含依赖包名称、许可证类型字段，确认`detail`配置已生效。
- 模拟一次合规相关的对话，触发依赖校验流程，检查日志是否绑定至`responseChatItemId`对应的回复节点，确保合规信息被正确记录。
- 查看日志存储周期配置，确认已设置为90天，可覆盖至少3个项目版本的审计需求。
- 测试拉取跨源依赖数据，确认拉取数量不超过设定的上限，且自动同步了当前项目版本的依赖清单。
