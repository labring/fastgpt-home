# 语音标注与转写的线上故障排查与复盘：定时任务与自动化

## 这个品类的数据长什么样
该品类的数据主要来自上传的音频文件、标注平台交互记录、行业专有词表、人工抽检样本。日常产出的文档包含转写规范、音频批次清单、质检结果报告、说话人标注对照表。数据更新节奏以单日或单批次为周期，每次处理的音频文件会对应生成结构化转写文本、标注日志与质检结果。不同于文本标注项目，语音标注与转写需先完成音频到结构化文本的转换，再开展后续标注与质检工作。

## 这些特征在「定时任务与自动化」这一环带来什么约束
该品类的数据来源分散且需关联音频与标注记录，要求定时任务需支持多源数据拉取与关联校验。数据更新以单日或单批次为周期，定时任务的触发周期需匹配该节奏，避免重复处理已归档的音频数据。核心耗时环节（如噪声片段判断、说话人区分、专有词校对）对计算资源要求较高，自动化任务需配置断点续传机制，防止单次任务超时中断导致全量返工。同时，转写结果需与原音频、标注表一一对应，任务需保留完整的关联字段，保障后续质检与复盘的可追溯性。出错后果包括识别训练偏差、转写返工、交付延期，因此任务需配置失败重试与告警机制，降低异常导致的业务影响。

## 配置怎么定
本配置项适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 任务触发周期 | 按单批次完成时间+1小时 或 每日凌晨2点 | 匹配数据日/每批的更新节奏，避免重复处理已归档的音频数据 |
| 单任务最大处理时长 | 1200秒 | 覆盖核心耗时环节的平均处理时长，防止任务被强制终止 |
| 失败重试次数 | 3次 | 应对临时的资源调用失败，减少人工介入概率 |
| 失败告警触发阈值 | 连续2次任务失败 | 及时通知运维人员排查异常 |
| 断点续传开关 | 开启 | 适配长耗时的语音转写与标注环节，避免单次中断后全量重跑 |
| 多工具并行触发开关 | 按需开启 | 支持同时调用转写、标注、质检工具，提升任务执行效率 |

## 容易做错的三处
- 现象：任务状态长时间显示「待处理」，但系统任务管理器显示进程处于运行中。原因：核心耗时环节占用大量计算资源，导致任务进度未及时同步至状态记录接口。
- 现象：定时触发的转写任务无法同时调用多个工具完成转写与标注。原因：任务配置中未开启多工具并行触发开关，仅支持单工具依次调用。
- 现象：转写任务无法选择指定的文本理解模型，仅显示默认选项。原因：未在系统配置中完成模型的批量导入与关联，导致任务可选模型列表未更新。

## 怎么确认配好了
- 手动触发一次测试任务，核对任务触发后是否拉取到指定的音频批次与词表文件
- 查看任务日志，确认失败重试机制在模拟的临时错误下正常触发
- 检查告警配置，模拟连续2次任务失败，确认告警通知正常推送
- 中断正在运行的测试任务，确认断点续传功能可恢复任务进度
