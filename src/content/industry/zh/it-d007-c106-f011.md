# 语音标注与转写的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
语音标注与转写的核心数据包含音频源文件、标注平台产出的转写文本、专有词表、抽检质检报告以及说话人标注表。数据更新通常按日或按标注批次进行，单批数据量随项目规模波动。日常维护的文档包含转写执行规范、音频交付清单、质检结果汇总表等，数据字段固定包含说话人标识、时间戳、转写内容、置信度评分与质检标记。

## 这些特征在「数据库与运维」这一环带来什么约束
语音标注与转写的数据兼具非结构化音频元数据、结构化转写结果与质检报告，要求数据库同时支持文档型存储与向量检索。按日或按批次的高频更新需求，需要数据库支持批量写入与增量同步机制。固定字段的结构化数据需要兼容复杂条件查询，而专有词表、说话人映射等高频访问数据需要缓存降低数据库负载。数据错误可能导致训练偏差或交付延期，因此需要完善的备份与回滚机制，同时需适配低算力环境的部署约束。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://fastgpt:yourpass@db-host:27017/voice_label?authSource=admin` | 语音标注数据分散存储在多个集合中，需指定认证源与目标数据库，保障多集合访问的安全性与准确性 |
| `DB_MAX_LINK` | `100–150` | 单批标注数据量较大，批量写入转写结果与质检报告时，足够的数据库连接可避免写入阻塞 |
| `REDIS_URL` | `redis://:redispass@redis-host:6379/0` | 用于缓存高频访问的专有词表、说话人映射表，降低主数据库的查询压力 |
| `PG_URL` | `postgresql://fastgpt:pgpass@pg-host:5432/voice_label` | 存储结构化的音频清单、质检报告汇总表，支持按项目、时间范围的复杂条件查询 |

## 容易做错的三处
- 仅启动mongodb与向量数据库容器，未启动sandbox容器，导致标注任务无法正常调度，界面显示任务状态始终处于pending。原因是sandbox容器负责执行标注任务的调度与资源分配，缺失后无法完成数据流转。
- 未适配CPU不支持AVX的环境，直接使用MongoDB 5.x镜像启动，更换为mongo:4.4.29后未调整数据库兼容参数，出现版本不兼容的启动报错。原因是旧版MongoDB镜像的默认配置与低算力环境存在冲突。
- 未配置`DB_MAX_LINK`的合理取值，直接使用默认的连接数限制，在批量提交转写数据时出现连接耗尽，界面显示“数据库连接超时”报错。原因是批量写入的并发请求超过了数据库连接上限。

## 怎么确认配好了
- 执行`docker ps`命令，查看FastGPT依赖的mongodb、milvus、redis、sandbox容器均处于running状态。
- 连接`MONGODB_URI`对应的数据库，验证转写结果集合、音频元数据集合可正常执行写入与查询操作。
- 提交一批测试标注数据，通过数据库监控工具查看当前连接数未超过`DB_MAX_LINK`的设定值，无超时报错产生。
- 使用redis-cli工具连接`REDIS_URL`，验证专有词表、说话人映射表的缓存键值可正常读取与更新。
