# 运维外包驻场服务的线上故障排查与复盘：对话日志与审计

## 这个品类的数据长什么样
这个品类的数据主要来自客户ITSM系统、监控平台、资产清单与值班记录。日常关联文档包含驻场日报、服务台工单、巡检报告、SLA月报。数据更新节奏以日度为主，部分SLA统计类数据按月更新。数据字段通常包含工单编号、驻场工程师标识、事件发生时间、处理步骤、结果反馈，单位多为条、小时，SLA相关字段使用百分比作为单位，无额外非标准统计字段。

## 这些特征在「对话日志与审计」这一环带来什么约束
该品类的数据来源分散于客户现有ITSM、监控平台等系统，对话日志与审计环节需兼容多源异构格式的日志导入，需支持绑定工单编号、驻场工程师标识等关联字段。日度更新的巡检记录与服务台工单，要求日志同步频率不低于事件发生后1小时。驻场日报与SLA月报的关联统计需求，要求审计日志需保留字段映射规则，支持按客户IT部门的自定义维度筛选。多角色访问的场景下，需区分驻场工程师、服务经理、客户IT人员的日志查看权限，避免敏感运维数据泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话日志存储时长 | 180天 | 匹配驻场日报、SLA月报的月度统计周期，满足常规审计需求 |
| 日志自动清理触发阈值 | 磁盘占用80% | 避免日志存储耗尽服务器资源，适配运维场景的磁盘容量 |
| 日志字段映射规则 | 绑定工单编号、工程师标识 | 匹配该品类日常文档的关联需求，便于后续统计汇总 |
| 多角色权限隔离 | 按用户角色分组 | 区分驻场工程师、服务经理、客户IT人员的查看权限 |
| 日志同步频率 | 1小时内 | 匹配日度更新的巡检与工单数据的同步要求 |
| 审计日志导出格式 | CSV、JSON | 兼容客户现有ITSM系统的导入格式，便于数据整合 |

## 容易做错的三处
- 现象：对话日志返回结果包含非当前授权用户的历史记录，`chatId`字段未关联对应工程师标识。原因：未配置`chatId`与驻场工程师ID的绑定规则，导致日志未按用户维度隔离。
- 现象：启动后审计日志模块报错，提示数据库连接异常。原因：未将对话日志存储指向客户现有ITSM兼容的数据库实例，导致数据无法正常写入。
- 现象：对话日志存档条数超出预期上限，无法按周期自动清理。原因：未设置日志自动清理的触发条件，仅保留手动清理方式。

## 怎么确认配好了
- 登录FastGPT后台，进入对话日志管理页面，筛选指定驻场工程师ID，确认仅返回该工程师的对话记录。
- 导入一条模拟服务台工单数据，检查审计日志是否自动关联工单编号字段，字段映射关系符合预设规则。
- 手动触发一次日志清理操作，确认过期日志被正常删除，磁盘占用量符合预设阈值。
