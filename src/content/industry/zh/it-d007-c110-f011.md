# 运维外包驻场服务的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
这个品类的数据主要来源于客户ITSM系统、运维监控平台、硬件资产清单与驻场值班记录。日常产出的文档包括驻场日报、服务台工单、巡检报告与SLA月报，数据字段覆盖故障编号、处理时长、巡检项状态、人员值班信息等。数据更新频率分为日度与月度，日度数据包括当日工单与巡检记录，月度数据为SLA统计与资产盘点报表。数据结构包含结构化的工单字段与非结构化的巡检日志，需支持多源数据的统一存储与关联查询，适配驻场服务的日常复盘需求。

## 这些特征在「数据库与运维」这一环带来什么约束
数据来源分散且类型多样，要求数据库需支持多源数据的接入与映射，适配结构化工单与非结构化巡检日志的混合存储。更新频率的差异要求配置数据的增量同步与定期归档策略，避免数据库冗余占用过多存储资源。日常文档的字段关联驻场人员与客户服务要求，需在数据库层面配置外键约束与权限控制，保证数据关联的正确性与访问安全性。此外，出错后果直接影响服务合同履约，要求数据库具备可靠的备份与恢复机制，降低数据丢失风险，避免客户扣罚或合同终止。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host]:27017/fastgpt?authSource=admin` | 用于存储驻场工单、巡检日志的非结构化数据，需指定认证源与目标库名，适配FastGPT v4.17.0版本的存储要求。 |
| `PG_URL` | `postgresql://[username]:[password]@[host]:5432/fastgpt_sla?sslmode=require` | 用于存储SLA月报、资产清单的结构化数据，开启SSL保证内网传输安全，避免敏感数据泄露。 |
| `DB_MAX_LINK` | `20–30 个` | 匹配驻场服务的日常并发处理量，避免数据库连接池耗尽导致工单无法写入或查询失败。 |
| `REDIS_URL` | `redis://[host]:6379/0` | 用于缓存值班记录、实时监控告警数据，降低主数据库的查询压力，提升工单处理效率。 |

## 容易做错的三处
- 现象：MongoDB启动失败，日志显示挂载目录权限异常。原因：驻场工程师在数据库迁移或重装时未重置挂载目录的属主与权限，导致FastGPT进程无法访问数据文件。
- 现象：数据库连接报错，返回`Failed to connect to [host]:port`。原因：未在客户内网防火墙开放数据库端口，或`MONGODB_URI`/`PG_URL`中的地址配置错误，未匹配客户内网的数据库节点。
- 现象：单节点并发处理能力不足，50个并发请求导致服务卡顿。原因：`DB_MAX_LINK`配置值超出数据库承载上限，或未根据驻场服务的日常工单量调整连接池参数，导致连接耗尽。

## 怎么确认配好了
- 登录FastGPT的数据库监控面板，查看连接池的活跃连接数，确认数值在配置的`DB_MAX_LINK`范围内。
- 执行一次驻场工单的创建与查询操作，确认数据能正常写入与读取，无报错返回。
- 检查数据库的备份任务状态，确认每日/每月的归档任务按计划执行。
- 验证`REDIS_URL`的缓存功能，查看实时告警数据的更新延迟是否符合驻场服务的监控要求。
