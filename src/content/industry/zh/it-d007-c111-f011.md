# 配置管理与CMDB维护的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
本品类的数据来源包括CMDB系统、云资源清单、自动发现工具与采购台账，更新频率为日或周。日常产出的文档包含配置项清单、服务组件关系拓扑、变更记录与资产盘点表，字段涵盖配置项唯一标识、资产类型、依赖关系条目、变更时间、采购批次等，核心特征为关注服务组件间的依赖关系，区别于仅统计资产数量的IT资产盘点，无额外统计类量化数值。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据的同步需求要求数据库支持多格式数据导入与增量更新，避免单次全量同步导致的性能波动。作为核心特征的依赖关系管理，需要数据库设计支持多表关联查询，准确映射服务组件间的链路。日/周级别的更新频率要求写入操作具备批量处理能力，同时需保留全量变更日志用于故障回溯。配置与实际资产的一致性校验需要数据库内置或外接校验逻辑，防止账实不符导致的故障定位延迟。

## 配置怎么定
本文档适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | 填写包含认证信息的MongoDB连接地址，指向独立的CMDB专用库 | 存储CMDB配置项、变更记录等非结构化或半结构化数据，与业务数据库隔离 |
| `PG_URL` | 填写PostgreSQL连接串，配置ssl模式为`require` | 存储服务组件关系拓扑、资产盘点表等需要强关联查询的结构化数据，保障数据传输安全 |
| `DB_MAX_LINK` | 配置为 `80–150` 个 | 限制数据库连接池最大连接数，避免并发配置同步请求导致数据库负载过高 |
| `REDIS_URL` | 填写Redis缓存地址，设置键过期时间为 `1800–3600 秒` | 缓存高频访问的配置项与依赖关系数据，降低后端数据库的查询频次 |

## 容易做错的三处
- 现象：启动FastGPT时出现`init root user mongo start connect init root user error`报错，原因：未正确配置`MONGODB_URI`的认证信息，或MongoDB实例未开放对应访问端口。
- 现象：CMDB配置项与实际云资产的关联关系为空或不一致，原因：未按日/周更新频率配置自动同步任务，导致数据更新滞后于实际资产变化。
- 现象：并发配置查询时出现数据库连接耗尽报错，原因：未限制`DB_MAX_LINK`的连接数，导致连接池资源被耗尽。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`与`PG_URL`的连接有效性，确认无认证或地址错误。
- 登录Redis管理界面，查看缓存键的存活时间与访问频次，确认`REDIS_URL`配置的缓存服务正常运行。
- 触发一次手动配置同步任务，检查数据库中是否生成对应的变更记录与更新后的配置项数据。
- 查看数据库连接池监控面板，确认当前活跃连接数未超过`DB_MAX_LINK`的设置值。
