# 项目实施计划管理的线上故障排查与复盘：数据库与运维

## 这个品类的数据长什么样
该品类的数据主要来自合同、工作分解结构（WBS）、客户日程及企业项目管理系统，日常产出项目计划、里程碑清单、周报、风险问题清单四类文档。数据更新以周为周期，或按单个项目里程碑节点触发。数据字段包含任务唯一标识、责任人姓名、计划完成时间、实际完成时间、风险等级与跟踪状态，无统一强制标准格式，需适配各项目管理系统导出结构。

## 这些特征在「数据库与运维」这一环带来什么约束
数据来源分散导致需对接多套外部系统，数据库配置需支持多源数据拉取与格式适配。更新频率偏低且按节点触发，无需高频实时写入，连接池参数可按低并发场景标定。文档结构无统一标准，需预留灵活字段扩展空间，避免硬编码字段映射。风险问题清单数据更新频次略高，可单独分配存储分片以避免阻塞核心任务数据读写。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本，针对项目实施计划管理的数据库与运维场景设计。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://user:password@db-host:27017/project_db?authSource=admin` | 适配非结构化的风险问题清单、周报存储需求，支持灵活的文档字段扩展 |
| `PG_URL` | `postgresql://pmo_user:secure_pass@pg-host:5432/project_plan?sslmode=require` | 存储结构化的项目计划、里程碑数据，sslmode=require保障合同与客户日程数据的传输安全 |
| `DB_MAX_LINK` | `10–15` | 数据更新以周或里程碑为周期，低并发场景下足够支撑多系统对接，避免连接资源浪费 |
| `REDIS_URL` | `redis://redis-host:6379/0?password=redis_pass` | 缓存高频访问的项目里程碑清单与风险问题跟踪状态，降低数据库查询压力 |
| 单次数据同步批次 | 前 200 条 | 适配项目数据单次导出的规模上限，避免单次同步超时 |

## 容易做错的三处
- 现象：数据库查询节点返回原始JSON或JSON数组，未生成可直接使用的结构化字段。原因：未配置数据映射规则，直接读取数据库存储的非结构化文档字段。
- 现象：并发调用量达到每秒2-3次时，工作流内的数据库调用返回空结果。原因：`DB_MAX_LINK`取值过低，无法支撑短时间内的多任务数据读写请求。
- 现象：本地运行环境无法连接外部Mongo数据库，查询结果为空。原因：未正确配置`MONGODB_URI`，未开放本地网络访问外部数据库端口。

## 怎么确认配好了
- 执行单次测试同步任务，查看目标数据库中是否写入对应项目计划、里程碑数据，验证`MONGODB_URI`与`PG_URL`配置有效。
- 发起连续多轮风险问题清单查询请求，查看连接池占用情况，确认`DB_MAX_LINK`取值满足当前并发需求。
- 检查Redis缓存中是否存在最近更新的项目里程碑数据，验证`REDIS_URL`配置生效。
- 模拟高并发调用场景，查看工作流日志中无数据库连接超时报错，确认参数配置合理。
