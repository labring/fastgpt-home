# 项目实施计划管理的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
该品类的数据通常来自项目合同、工作分解结构（WBS）、客户共享日程及企业项目管理系统。日常产出的文档包含项目计划、里程碑清单、周报与风险问题清单，核心字段涵盖任务标识、责任人、截止时限、进度状态与风险等级，更新节奏为每周一次或按单个项目里程碑节点推进。

## 这些特征在「部署与升级」这一环带来什么约束
由于项目实施计划管理的数据来源分散且更新节奏为周度或按里程碑推进，部署时需配置多源数据的同步适配规则，避免跨系统数据格式冲突。不同项目的文档结构存在差异，升级时需保留自定义字段映射的兼容能力，防止现有项目数据无法正常读取。周度或里程碑级别的数据同步会产生批量请求，部署时需调整数据库连接池参数以适配并发负载，避免连接耗尽导致任务同步失败。同时，项目数据的字段变更会影响存储结构，升级前需验证数据迁移脚本的兼容性，防止进度数据丢失或格式错乱。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:securepass@db-host:27017/fastgpt_project?authSource=admin` | 适配项目实施计划管理的风险问题清单、里程碑数据的持久化存储需求 |
| `REDIS_URL` | `redis://:redispass@redis-host:6379/1` | 用于缓存项目任务的进度状态、周报摘要，降低数据库查询压力 |
| `DB_MAX_LINK` | `20–30 个连接` | 匹配周度或里程碑级别的数据同步并发量，避免连接耗尽导致任务同步失败 |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.aliyuncs.com` | 用于存储项目文档的上传版本、风险问题的附件材料 |
| `ROOT_KEY` | `32 位以上随机字符串` | 用于管理项目数据的后台访问权限，防止未授权的配置修改 |

## 容易做错的三处
- 现象：Docker桌面部署时容器状态持续处于启动转圈状态。原因：未正确配置`MONGODB_URI`的认证参数，导致数据库连接失败，容器反复重试启动。
- 现象：通过docker-compose安装后，无法为项目数据集合添加索引。原因：未在部署配置中开启自动索引初始化逻辑，或未正确指定数据库连接的读写权限范围。
- 现象：执行npm list命令无法查找到mongoose版本，但项目可正常运行。原因：mongoose依赖被封装在FastGPT v4.17.0的基础镜像中，未在本地项目的package.json中显式声明，需通过容器内命令查看版本。

## 怎么确认配好了
- 执行docker ps命令，确认所有FastGPT v4.17.0相关容器处于运行状态，无异常退出日志。
- 访问`FE_DOMAIN`配置的前端地址，登录后台后可正常查看项目计划的列表数据，无加载超时提示。
- 在后台数据库管理页面，验证`MONGODB_URI`对应的数据库中已创建项目数据的核心索引。
- 提交一条测试项目任务数据，验证数据可正常写入指定存储路径，无连接报错或格式异常提示。
