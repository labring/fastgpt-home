# 项目文档移交归档的线上故障排查与复盘：部署与升级

## 这个品类的数据长什么样
该品类的数据来源为项目文档库、配置清单、会议纪要、测试报告，更新节奏为每阶段交付或单项目结束后。日常处理的文档包含竣工文档、配置手册、培训记录、验收证书，核心字段包含项目编号、文档版本、签署人、归档时间、关联系统标识，无固定统一的单文档格式，需兼容Word、PDF、Excel等多种业务文档类型。数据更新无固定周期，仅随项目推进或交付节点触发，单次更新的文档体量随项目规模波动。

## 这些特征在「部署与升级」这一环带来什么约束
数据来源分散且格式多样，要求部署环节支持多源文档的批量导入与格式适配，避免因文档类型差异导致导入失败。更新节奏非固定，仅随项目节点触发，升级环节需兼容历史归档数据的版本映射逻辑，防止增量同步时出现字段不匹配。核心流程依赖文档完整性与版本一致性校验，部署时需内置可自定义的校验规则，确保移交归档的合规性。此外，数据涉及客户业务信息，部署与升级时需保障数据传输与存储的权限隔离，避免未授权访问。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `DB_MAX_LINK` | `100–200 个连接` | 适配项目文档库的并发读写需求，避免数据库连接耗尽 |
| `MONGODB_URI` | 国内镜像加速的集群内网地址 | 规避Linux环境下拉取镜像或依赖包的超时问题 |
| `REDIS_URL` | 带访问密码的内网缓存地址，缓存过期时间设为`600 秒` | 保障文档校验缓存的读写效率与安全性 |
| `STORAGE_S3_ENDPOINT` | 国内合规对象存储节点地址，单项目存储配额设为`500 GB` | 适配归档文档的大容量存储需求，降低跨区域访问延迟 |
| `FILE_TOKEN_KEY` | `32 位随机字符串` | 保障归档文件的临时访问权限校验，防止未授权下载 |
| `ROOT_KEY` | 按项目权限分级配置 | 区分不同交付项目的文档访问范围，符合移交归档的权限要求 |

## 容易做错的三处
- 现象：部署后归档文档无法正常访问，返回`403 Forbidden`报错。原因：未正确配置`FILE_TOKEN_KEY`，导致临时访问令牌校验失败。
- 现象：Linux环境下拉取FastGPT镜像超时，即使已配置国内镜像源。原因：未将`MONGODB_URI`等依赖服务地址指向国内镜像节点，跨区域拉取链路未优化。
- 现象：Docker在线升级后部分历史归档文档的版本信息丢失。原因：升级时未保留原有的版本校验规则，导致增量同步时字段映射逻辑冲突。

## 怎么确认配好了
- 执行FastGPT容器的日志查看命令，确认无数据库连接超时、缓存连接失败类报错。
- 上传一份测试用竣工文档，触发内置的完整性校验流程，确认校验结果正常输出。
- 生成归档文档的临时访问链接，验证链接可正常打开且无权限拦截。
- 创建测试项目账号，验证仅授权用户可访问对应归档文档，确认权限配置生效。
