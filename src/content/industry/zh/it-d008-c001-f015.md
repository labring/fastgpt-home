# CDN与边缘加速配置的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
通常该品类的核心数据来自CDN控制台、DNS解析记录、用户访问日志与集群监控告警。日常产出的文档包含域名接入单、缓存规则配置表、刷新预热操作记录、故障根因分析报告。数据字段一般包含域名、缓存规则ID、边缘节点IP、访问流量单位、告警触发阈值等，更新频率为每日同步或随配置变更实时更新。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据特征会对知识库检索与召回带来多重约束。分散的数据来源包含静态配置文档与实时访问日志，要求检索需同时适配结构化字段与非结构化文本；灵活的更新频率要求知识库支持增量同步，避免全量重建占用运维资源；多字段的技术文档需精准匹配域名、节点IP等特定参数，降低误召回概率；高频的备案核对、缓存规则调试场景，需控制单次检索的token消耗与响应时长，保障运维值班的实时响应效率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配CDN与边缘加速配置的运维场景：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配CDN配置的技术参数精度，兼顾召回覆盖率与准确性 |
| `limit` | 前6条 | 单次召回结果条数，适配运维工单的短平快查询需求 |
| `searchMode` | semantic | 语义检索模式，覆盖缓存规则、故障报告等非结构化文档 |
| `usingReRank` | 开启 | 对召回结果重排，修正语义匹配的偏差，提升根因分析的准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 优化查询词，补充CDN相关技术术语，提升检索匹配精度 |
| `collectionIds` | 绑定指定的CDN配置、日志、告警数据集 | 限定检索范围，避免无关数据干扰，提升检索效率 |

## 容易做错的三处
- 现象：语义检索召回多条匹配结果，但模型回复未找到相关答案。原因：未开启`usingReRank`重排，或`similarity`阈值设置过高，导致有效匹配结果被过滤，剩余低相关性内容无法支撑模型生成有效回复。
- 现象：知识库查询响应超时，或单次检索消耗过多token。原因：未限制`limit`参数的召回条数，或未优化查询词长度，导致检索时传入的上下文token超出平台阈值。
- 现象：知识库中嵌入的markdown图片无法被正常检索匹配。原因：未将图片外链配置为可公开访问，或知识库未支持图片内容的向量化解析，导致图片关联信息未被纳入检索索引。

## 怎么确认配好了
- 发起针对特定域名缓存规则的查询，核对召回结果是否包含匹配的技术参数，调整`similarity`与`limit`参数至符合业务需求的水平。
- 查看检索过程的token消耗记录，确认单次检索的token占用符合运维响应的实时要求，验证`datasetSearchUsingExtensionQuery`是否优化了查询词长度。
- 上传包含markdown格式的故障分析报告，确认检索结果可匹配报告中的缓存异常描述，验证图片与文本的检索适配配置是否正常。
- 提交一条未在现有知识库中出现的临时缓存规则查询，确认新同步的数据可被正常召回，验证增量更新配置是否生效。
