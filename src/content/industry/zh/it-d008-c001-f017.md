# CDN与边缘加速配置的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
通常，该品类的数据来源于CDN控制台、DNS解析记录、访问日志与监控告警。日常配套文档包含域名接入单、缓存规则配置表、刷新预热记录台账与故障分析报告，字段覆盖域名、缓存时效、节点IP、访问带宽等。数据更新频率为每日或随配置变更实时同步，最耗时的操作环节包含域名备案核对、缓存规则调试与异常节点排查，出错后可能引发公网访问变慢、缓存错乱或域名无法接入的问题。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据来源于多类云服务控制台与日志，部署时需提前配置对应数据源的访问权限，避免对接失败。数据更新频率较高，升级过程中需采用灰度发布策略，分批验证配置同步的时效性。日常文档的字段结构决定了检索配置需匹配域名、缓存规则等专属字段，不可直接复用通用检索的字段映射。最耗时的人工环节需在部署阶段通过自动化脚本简化核对流程，降低运维成本。出错后果影响公网服务，升级前需完成全量配置的备份与回滚测试。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 填写CDN节点监控数据的集群连接串 | 对接CDN控制台的监控数据源，存储告警与访问日志 |
| `REDIS_URL` | 配置为本地缓存CDN缓存规则的实例地址 | 加速缓存规则的检索，适配日更的配置更新节奏 |
| 单次检索上限 | 前6条 | 匹配实际业务中常见的检索需求，避免超出CDN日志的单批次返回量 |
| `STORAGE_S3_ENDPOINT` | 填写CDN刷新预热记录的存储端点 | 存储历史刷新操作的归档数据，用于工单溯源 |
| `DB_MAX_LINK` | 150-200 | 适配CDN访问日志的高并发查询场景，避免连接耗尽 |
| 浏览器版本要求 | Chrome 90+、Firefox 88+ | 适配FastGPT v4.17.0的前端渲染逻辑，兼容公网访问的浏览器环境 |

## 容易做错的三处
- docker部署的reranker调用返回false，实际接口连通但返回结果为空。原因是未配置CDN访问日志的数据源权限，导致检索结果无法正确关联到缓存规则。
- 私有化部署后自定义检索数量无法调整到6条以上。原因是未修改`DB_MAX_LINK`的取值，默认限制了单批次查询的条目数，无法匹配CDN日志的批量返回。
- 升级到指定版本后插件编辑页提示未保存。原因是未同步更新`FE_DOMAIN`的配置，前端与后端的域名校验不匹配，导致保存状态无法同步。

## 怎么确认配好了
- 执行reranker接口调用，检查返回结果是否包含CDN缓存规则的匹配内容，确认数据源对接正常。
- 尝试将检索数量调整为7条，查看是否可以保存生效，确认`DB_MAX_LINK`的配置生效。
- 修改插件配置并点击保存，检查页面右上角的提示是否消失，确认`FE_DOMAIN`的配置正确。
- 查看CDN控制台的监控告警，确认FastGPT是否可以正常拉取访问日志数据，确认数据源权限配置正确。
