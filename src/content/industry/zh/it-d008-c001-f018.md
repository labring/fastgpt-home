# CDN与边缘加速配置的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来自CDN控制台、DNS解析记录、边缘节点访问日志与监控告警系统。日常运维与工单关联的文档包括域名接入单、缓存规则配置文档、刷新预热操作记录、故障根因分析报告。数据字段包含域名、缓存规则标识、边缘节点IP、访问延迟值、告警等级、故障触发时间等，更新频率为每日同步或随配置变更实时更新。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类多源分散的数据特征，要求混合检索同时覆盖结构化配置数据、半结构化日志与非结构化故障报告。数据更新节奏差异大，实时变更的缓存规则与每日汇总的访问日志需在检索时区分时效性权重，避免陈旧数据干扰结果。不同类型数据的字段差异明显，需针对域名、告警等级、节点IP等专属字段设置匹配规则，确保检索结果与运维场景强关联。同时需适配不同格式的数据结构，确保检索逻辑兼容结构化与非结构化内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `usingReRank` | 开启 | CDN运维场景需优先匹配高关联度的故障与配置数据，重排可过滤低相关性召回结果 |
| `limit` | 前8–12条 | 运维工单的有效信息通常集中在少量高关联条目，该区间可平衡检索覆盖度与效率 |
| `searchMode` | hybrid | 需同时匹配结构化配置字段与非结构化故障描述，混合检索可兼顾精确匹配与语义匹配 |
| `similarity` | 0.72–0.88 | 针对CDN域名、节点IP等强标识字段，该区间可过滤无关的跨域名检索结果 |
| 模型渠道配置 | 绑定对应重排模型的供应商凭证 | 确保重排服务可正常调用，符合FastGPT v4.17.0的模型渠道配置要求 |

## 容易做错的三处
- 现象：检索结果中重排标记字段为false，无重排后结果。原因：未在App/Admin服务端正确配置`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址，格式如http://aiproxy:3000，不得附加路径）与`AIPROXY_API_TOKEN`（与AI Proxy服务端配置一致的管理员Token）环境变量，导致App/Admin服务启动校验失败，重排服务无法正常调用。
- 现象：商用重排模型返回空内容。原因：重排模型的供应商凭证未在模型渠道配置页面正确填写，或模型名称与控制台配置不匹配。
- 现象：同一模型名称同时用于嵌入与重排配置后覆盖原有设置。原因：FastGPT v4.17.0中模型配置仅允许唯一名称，无论用途类型，重复添加同名模型会自动替换原有配置。

## 怎么确认配好了
- 检查App/Admin服务端是否正确设置了`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址，格式如http://aiproxy:3000，不得附加路径）与非空的`AIPROXY_API_TOKEN`（与AI Proxy服务端配置一致的管理员Token）环境变量。
- 检查模型渠道配置中重排模型的供应商凭证与模型名称配置正确。
- 输入一条CDN运维相关的测试关键词，查看检索结果列表是否带有重排后的排序标识。
- 尝试添加与已有配置同名的重排模型，确认系统拦截重复配置，验证唯一性规则生效。
