# IT服务台工单处理的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
本品类的数据来自企业ITSM系统、电话或内部聊天记录、资产台账系统及内部知识库。日常生成的文档包含服务请求单、事件工单、处理过程记录、用户满意度反馈表。数据更新频率为日级或实时，每条数据包含工单编号、提交人信息、问题描述、分类标签、处理状态、派单记录与满意度评分等字段，需适配多源异构的数据导入与存储。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的数据来源要求部署时需配置多个存储与对接参数，适配不同系统的数据读写需求。日/实时的更新频率要求部署时配置合理的缓存策略，保障工单处理的低延迟响应。工单数据包含员工与设备的敏感信息，部署时需配置加密与权限验证参数，保障内部数据安全。统一受理派单的业务模式要求部署时配置统一的访问入口，适配企业内部局域网的访问场景。升级过程中需兼容历史工单数据的格式，避免处理记录与满意度数据丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 填写企业ITSM系统对接的MongoDB集群连接地址 | 适配工单数据的持久化存储，满足日/实时更新的读写需求 |
| `PG_URL` | 填写内部资产系统关联的PostgreSQL数据库连接地址 | 存储设备台账与工单关联数据，保障数据关联准确性 |
| `REDIS_URL` | 配置为局域网内Redis服务的连接地址，缓存有效期设为300-600秒 | 加速工单分类与派单的缓存查询，降低实时处理延迟 |
| `FE_DOMAIN` | 填写企业内部访问的域名或局域网IP地址，如http://192.168.0.111:3000 | 保障内部员工通过统一入口访问服务台，适配局域网访问需求 |
| `FILE_TOKEN_KEY` | 使用随机生成的32位字符串作为密钥 | 加密工单附件与敏感数据的传输，保障内部数据安全 |
| `ROOT_KEY` | 配置为仅内部运维人员知晓的密钥，用于系统后台管理权限验证 | 限制敏感配置的修改权限，避免误操作影响业务 |

## 容易做错的三处
- 现象为部署完成后，127.0.0.1可访问但局域网IP无法访问，原因是未正确配置`FE_DOMAIN`为局域网IP或域名，或未开放对应端口的防火墙权限。
- 现象为工单分类结果偏差较大，无法匹配预设的服务类型，原因是未对接ITSM系统的历史工单数据进行模型训练，或缓存参数配置不合理导致数据更新不及时。
- 现象为系统底部显示官方二维码无法移除，原因是未修改前端静态配置文件中的二维码展示参数，或未在FastGPT v4.17.0版本的部署包中关闭默认推广组件。

## 怎么确认配好了
- 执行ping命令测试配置的`FE_DOMAIN`地址，确认局域网内设备可连通对应地址与端口。
- 登录`PG_URL`对应的数据库，查询是否有测试工单的关联数据写入，验证数据对接流程正常。
- 提交一条测试服务请求单，查看系统是否自动生成工单分类与派单记录，验证核心业务流程可用。
- 检查系统前端页面底部，确认官方二维码已移除，验证前端配置修改生效。
