# IT采购与供应商管理的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的日常文档主要包含采购申请、比价记录、合同、验收单，数据来源多为采购系统、供应商报价文件、预算表及合同系统。数据更新节奏以单订单或月度为周期，单条文档通常包含采购主体、品类规格、报价明细、合同条款、验收节点等字段，无统一固定单位，随采购品类与内部规则调整。内部工单多关联具体采购项目，需匹配对应订单的历史文档内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
采购类文档单条内容跨度大，从申请到验收覆盖多业务环节，分块后片段关联性强，需避免跨环节无关片段被召回；数据更新以单订单为单位，增量更新频率不均，需适配动态增量召回逻辑，避免全量检索的冗余开销；不同文档字段差异明显，采购申请侧重规格与预算，合同侧重条款与权责，检索时需匹配对应字段的语义权重，避免不同类型文档的检索偏差；内部工单多指向具体采购单，需精准召回对应订单的历史文档，避免无关供应商或其他项目的内容干扰问答结果。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，针对IT采购与供应商管理的业务特征制定具体配置方案：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 采购类文档语义差异显著，需过滤低相关片段，避免合同条款与采购申请的检索混淆 |
| `limit` | 前8条 | 单采购订单关联的历史文档数量适中，保留足够上下文同时控制召回冗余 |
| `searchMode` | 语义检索 | 适配采购需求、合同条款等非结构化文本的语义关联，覆盖多类型业务文档 |
| `usingReRank` | 开启 | 二次过滤语义检索结果，精准召回与工单关联的具体采购环节内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充工单中隐含的采购项目细节，扩大有效召回范围且不降低相关性 |
| `collectionIds` | 指定内部IT采购知识库的集合ID | 限定检索范围仅覆盖采购类文档，避免其他品类数据干扰检索结果 |

## 容易做错的三处
- 开启`usingReRank`后检索结果为空。现象为界面显示“无匹配片段”，后台日志无有效召回条目。原因是`similarity`阈值设置过高，结合重排过滤后，初始语义检索的结果被全部剔除。
- 本地部署的知识库无法上传新文档。现象为上传采购合同或验收单时弹出“知识库数目超限”提示。原因是未调整本地实例的知识库默认数目限制参数，未适配该品类单批次上传的文档数量。
- 检索结果混杂非采购类文档。现象为工单问答中出现无关业务内容。原因是未通过`collectionIds`限定检索范围，误将其他品类的知识库内容纳入召回池。

## 怎么确认配好了
- 上传单份采购申请文档，发起包含该采购品类关键词的测试工单，核对检索返回的片段是否仅包含该文档的相关内容。
- 开启`usingReRank`后，对比开启前后的检索结果条数，确认重排后过滤了低相关的冗余片段。
- 调整`similarity`阈值至0.75，发起多轮测试，确认返回结果的相关性符合业务预期。
- 检查`collectionIds`配置，确认检索范围仅覆盖内部IT采购知识库，无跨品类数据混入。
