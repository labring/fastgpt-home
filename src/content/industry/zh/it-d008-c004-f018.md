# IT采购与供应商管理的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的典型数据来自企业IT采购系统、供应商报价文档、预算表与合同系统，日常文档包含采购申请单、比价记录、正式合同与验收单。采购申请单通常包含需求规格、申请额度与使用部门信息，比价记录包含多供应商的报价与资质文件，合同包含条款细则与履约期限，验收单包含到货与履约情况。数据更新频率通常按采购单执行，单次采购相关文档更新周期多为每单或每月，部分长期供应商的资质文档更新周期为季度。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据兼具结构化字段与非长文本内容，采购申请单的结构化字段需优先匹配，而合同与比价记录的长文本内容需精准匹配关键词。多源数据的更新频率不均，部分历史合同与资质文档更新较慢，需在检索时区分优先级。内部工单问答的问题多围绕采购需求、供应商资质、合同条款展开，需同时召回结构化采购数据与非结构化文档，因此重排环节需兼顾不同格式数据的相关性排序，避免低相关结果干扰工单响应。此外，采购相关的检索结果直接影响采购流程进度，需确保重排后的结果精准匹配用户问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本进行说明。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 重排开关 | 开启 | 采购类文档多包含长文本条款与结构化字段，重排可有效过滤低相关召回结果 |
| 相似度阈值 | 0.72–0.85 | 匹配采购需求的核心字段，避免召回无关的历史合同或供应商报价 |
| 单次召回上限 | 前8–12条 | 兼顾内部工单问答的响应速度与召回覆盖，避免过多冗余数据拖慢上下文长度 |
| 检索模式 | hybrid | 结合向量检索与关键词检索，适配采购系统结构化数据与非结构化文档的混合检索 |
| 重排模型调用超时 | 60 秒 | 适配采购文档的长文本处理，避免因模型响应慢导致工单问答超时 |
| 重排模型选择 | 按实测标定 | 适配企业采购文档的文本特征，优先选择支持长文本处理的重排模型 |

## 容易做错的三处
- 现象：创建应用时无法勾选重排模型，界面显示空白或报错。原因：未在config.js中正确配置重排模型的API地址与密钥，或配置格式不符合FastGPT要求。
- 现象：检索结果中出现大量无关的供应商报价或历史合同，结果条数不符合预期。原因：未设置合理的相似度阈值，或未开启重排过滤低相关结果，导致召回结果冗余。
- 现象：调用重排模型时返回`rerank error fastgpt | { message: { detail: ' 错误信息。原因：离线重排模型未正确部署，或API调用超时、密钥无效，未按文档要求完成重排模型的接入配置。

## 怎么确认配好了
- 进入FastGPT应用的配置页面，确认重排开关已开启，且相似度阈值、单次召回上限等参数已设置为对应取值。
- 提交一条测试工单，输入与采购相关的问题，查看检索结果的条数与相关性是否符合预期。
- 查看应用的运行日志，确认重排模型调用成功，无报错信息。
- 调整相似度阈值，验证检索结果的相关性是否随阈值变化而合理调整。
