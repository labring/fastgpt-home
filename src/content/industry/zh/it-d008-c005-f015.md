# Issue分拣与响应的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
典型主体为开源维护者、社区运营及核心贡献者，数据主要来源于GitHub或Gitee Issue、版本日志、用户环境信息与代码仓库，更新频率为日或周。日常维护的文档包括Issue模板、标签规则、回复记录与问题复现说明，数据字段包含问题描述、分类标签、复现步骤与责任模块等，整体内容以结构化规则与半结构化问题记录为主。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据以Issue相关的自然语言问题与规则文档为主，要求检索召回需匹配问题描述、标签规则等核心信息，因此需选用适配自然语言的检索模式。数据更新频率为日或周，需配置定期同步机制以保证知识库内容与最新的标签规则、回复模板一致。日常文档多为分类规则类内容，需保证召回片段准确对应问题分类、响应标准，避免无关内容干扰分拣流程。数据量随社区活跃度波动，需限制单次召回条数以控制上下文长度，确保运维值班场景下的响应效率。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，具体配置项及建议如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 匹配Issue类问题的语义相似度阈值，覆盖常见运维工单与问题分类场景，按实测标定 |
| `limit` | 前6条 | 限制单次召回结果条数，适配运维值班场景下的短上下文处理需求，避免信息过载 |
| `searchMode` | 语义检索 | 匹配Issue问题的自然语言描述，适配运维人员提交的非标准化工单内容 |
| `usingReRank` | 开启 | 对召回结果进行二次排序，修正语义检索的偏差，提升Issue分类的准确性 |
| `collectionIds` | 绑定Issue相关知识库集合 | 限定检索范围，仅调用预设的运维工单、Issue规则与回复模板知识库 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展问题关键词，补充Issue相关的高频标签、模块名，提升对运维工单中具体问题的召回匹配度 |

## 容易做错的三处
- 检索返回的结果中，`similarity`分数全部高于0.9，且包含大量与当前工单无关的历史Issue内容。原因是未设置合理的`similarity`阈值，或未开启`usingReRank`对结果二次排序，导致低相关性内容被误召回。
- 在工作流中配置`collectionIds`参数时，引用全局变量后触发配置报错，或检索结果未匹配指定知识库。原因是未按FastGPT v4.17.0的变量绑定规则配置`collectionIds`的引用格式，或变量作用域未覆盖当前工作流。
- 导入Excel格式的Issue模板数据后，检索结果未匹配表格中的标签规则。原因是未将Excel表格的列名与知识库的检索字段正确映射，或未启用表格数据集的字段匹配模式。

## 怎么确认配好了
- 手动提交一条典型运维工单问题，查看检索结果的`similarity`分数是否落在预设区间内，调整阈值至符合业务需求。
- 检查工作流中`collectionIds`参数的配置，验证指定的知识库集合是否包含当前检索所需的Issue规则、回复模板数据。
- 触发一次完整的Issue分拣流程，查看召回结果的条数是否符合`limit`参数的设定，无额外无关内容混入。
- 导入测试用的Excel数据集，验证检索结果是否能匹配表格中的标签、复现步骤等字段，确认映射关系生效。
