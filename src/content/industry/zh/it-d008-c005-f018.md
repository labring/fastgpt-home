# Issue分拣与响应的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来自GitHub或Gitee Issue、代码仓库版本日志、用户提交的环境信息与问题复现说明。日常维护的文档包括Issue模板、标签规则、历史回复记录。数据更新频率为日或周级，随新提交的问题、版本迭代同步更新。数据字段包含问题标题、描述、标签、提交时间、关联代码片段、用户环境信息等，无统一固定单位，随具体Issue内容动态变化。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据分散于代码片段、环境说明、纯文本问题等多种格式，混合检索环节需兼容多类型文本的召回逻辑，避免单一语义检索遗漏关键代码关联信息。数据更新频率为日或周级，需配置定期同步机制，确保召回的标签规则、历史回复记录为最新版本。Issue字段无固定结构，重排环节需支持动态调整不同字段的权重，适配不同类型问题的分拣需求。同时问题数量随项目活跃度波动，需限制单次召回的条目上限，避免上下文过载影响响应速度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.65–0.75 | 匹配Issue语义相关性的合理区间，平衡召回数量与精准度，避免误召回无关问题 |
| 单次召回上限 | 前10条 | 适配运维值班的快速响应需求，避免过多信息干扰分拣效率 |
| 搜索模式 | 混合检索 | 需同时匹配语义、标签与关联代码，覆盖多维度召回需求，提升分拣准确性 |
| 重排开关 | 开启 | 对召回的Issue结果按相关性重新排序，优先展示高优先级问题 |
| 重排模型适配 | 按实测标定 | 适配ARM或AMD架构的部署环境，FastGPT v4.17.0版本已提供对应架构的镜像选项 |

## 容易做错的三处
- 现象：语义检索模式返回的结果比混合检索更准确。原因：未配置混合检索的标签、代码片段召回规则，仅依赖纯语义匹配，未覆盖Issue的标签关联信息。
- 现象：工作流Http请求输出多变量时，无法将单个变量绑定到指定知识库。原因：未在重排与检索环节配置变量与知识库的映射逻辑，导致无法精准匹配对应数据源。
- 现象：ARM架构部署时无法加载重排模型镜像。原因：使用了AMD架构的重排模型镜像，未选择适配ARM架构的镜像版本。

## 怎么确认配好了
- 查看检索配置页面，确认搜索模式设置为混合检索，重排开关处于开启状态。
- 提交一条包含代码片段与标签的测试Issue，核对检索结果是否优先返回匹配标签与代码的历史回复。
- 检查部署环境的镜像版本，确认重排模型镜像适配当前系统架构。
- 查看工作流日志，确认检索环节返回的结果条数符合单次召回上限的设置。
