# SLA与服务报告的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来源为监控系统、工单系统、合同文件与客户沟通记录，更新节奏为月度或季度。日常文档包含SLA条款、月度服务报告、可用性统计表格、客户复盘纪要，字段包含服务时效指标、客户合同标识、事件发生时间、合规校验项等，无固定统一的单文档长度，按业务归档周期进行分组存储。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类数据分散于多系统，包含结构化的合同条款、工单记录与非结构化的复盘纪要，需适配多格式的召回逻辑。更新节奏为月度或季度，无需高频增量同步，但需按归档周期更新索引以保证数据时效性。文档包含合规校验相关字段，检索时需过滤非授权内容以避免合规风险。SLA相关指标为核心检索目标，召回排序需结合字段关联度与关键词匹配度，避免无关内容干扰SLA指标计算与报告口径对齐。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 适配SLA条款与工单记录的关键词匹配精度，平衡召回完整性与相关性 |
| `limit` | 前10条 | 控制单次召回的文档数量，避免过多内容拖慢响应，符合SLA报告的小批量精准检索需求 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配结构化与非结构化混合的SLA品类数据 |
| `usingReRank` | 开启 | 对召回结果重排，优先匹配SLA核心指标相关的文段，提升报告口径对齐效率 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动优化用户输入的SLA相关问题，补充合同编号、时效阈值等隐含检索词 |
| `collectionIds` | 按业务归档分组配置 | 仅检索对应月度/季度归档的SLA文档集合，缩小检索范围，提升响应速度 |

## 容易做错的三处
- 调用API返回内容未包含知识库匹配结果，原因是未在API请求中绑定正确的`collectionIds`参数，或未开启知识库检索权限。
- 检索响应时长超过30秒，原因是同时开启了`usingReRank`与`datasetSearchUsingExtensionQuery`，且召回`limit`设置过高，超出单请求处理阈值。
- 召回结果未关联指定文件名，原因是未配置`searchMode`为适配多源文档的模式，或未在检索参数中开启文件名关联索引。

## 怎么确认配好了
- 检查API请求参数是否包含配置的`collectionIds`，且与目标SLA文档集合一致。
- 查看检索日志，确认`usingReRank`与`datasetSearchUsingExtensionQuery`的开关状态与配置一致。
- 发起测试检索，输入包含SLA时效关键词的问题，核对返回结果的相关性与数量是否符合配置的`limit`与`similarity`要求。
- 验证响应时长，确认在配置的参数组合下，时长处于可接受的业务范围内。
