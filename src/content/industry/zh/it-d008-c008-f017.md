# 专题活动运营的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
通常的主体为内容运营、活动运营、设计和研发支持。日常文档包含活动方案、资源位排期、活动页面文案、复盘报告。数据来源为内容库、活动后台、流量数据、用户反馈。更新频率为周度或节假日周期。文档包含活动周期、资源位ID、流量指标、审核状态等字段，无固定统一单位，随文档类型变化。

## 这些特征在「部署与升级」这一环带来什么约束
活动方案与资源位排期有明确的时间窗口约束，部署与升级需避开活动进行时段，避免影响业务流转。FastGPT v4.17.0版本的部署流程中，需特别注意活动周期内的升级窗口设置。文档包含多类结构化与非结构化内容，数据库与缓存的配置需适配批量文档上传、实时流量查询的并发需求。用户反馈数据需及时同步至工单系统，部署时需配置稳定的外部服务连接。升级过程中需保留活动周期内的历史数据，避免因配置变更导致数据丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt?authSource=admin` | 存储活动方案、复盘报告等结构化文档，适配多类型活动数据的存储需求 |
| `REDIS_URL` | `redis://:password@host:6379/0` | 缓存活动实时流量数据、工单会话信息，支撑快速的内部问答查询 |
| `DB_MAX_LINK` | `20–30 个连接` | 支撑周度活动方案批量上传的并发连接，避免数据库连接耗尽 |
| `ROOT_KEY` | `32位随机字符串` | 管理内部工单系统的根权限，保障配置修改的安全性 |
| `FILE_TOKEN_KEY` | `按实测标定` | 保护活动页面文案的下载权限，避免未授权访问 |

## 容易做错的三处
- 现象：docker-compose.yml移除`networks - fastgpt`后，组件间无法通信，界面返回500状态码，提示连接超时。原因：FastGPT默认通过指定网络隔离组件通信，移除后无法解析内部服务地址。
- 现象：升级到FastGPT v4.9.8后修改root用户密码，次日自动重置为初始值。原因：未在环境变量中持久化`ROOT_KEY`配置，或部署时未挂载持久化存储卷保存配置。
- 现象：FastGPT v4.9.11版本接入qwen3-embedding-8b后，文件状态持续显示“索引中”，无进度更新。原因：FastGPT对该版本嵌入模型的接口兼容性未适配，或请求超时参数配置不足。

## 怎么确认配好了
- 执行docker-compose ps命令，确认所有组件状态为Up，无连续重启记录。
- 登录FastGPT后台，进入内部工单模块，创建测试工单并提交，确认工单能正常流转至对应负责人。
- 上传一份活动方案文档，触发索引流程，确认索引状态在合理时间内完成更新。
- 查看`REDIS_URL`对应的缓存服务，确认有活动流量数据的缓存记录。
