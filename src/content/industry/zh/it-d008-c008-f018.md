# 专题活动运营的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来自内部内容库、活动后台、流量统计工具及用户反馈渠道。日常维护的文档包含活动执行方案、资源位排期表、活动页面文案、复盘总结报告。数据更新节奏以周为单位，节假日前后会临时追加更新。文档字段包含活动周期、资源位编号、流量指标、用户反馈标签等，无统一固定的单位标准，随单份文档的业务属性调整。

## 这些特征在「重排与混合检索」这一环带来什么约束
专题活动运营的文档多为短期周期的活动相关内容，数据更新频率高且存在节假日前后的临时变更，因此重排与混合检索需要适配快速更新的数据源。不同于内容推荐运营的长期个性化推荐，该品类的检索需匹配明确的活动周期与资源位要求。活动方案、资源位排期等文档的字段差异大，混合检索时需优先匹配活动周期、资源位编号等精准字段，避免无关的通用运营内容被召回。同时活动相关内容的召回结果直接关联活动落地效果，需要严格控制召回与重排的精度，防止低相关内容进入上下文，避免活动审核遗漏或资源位错配。另外，数据来源分散，混合检索需整合内容库、活动后台、流量数据等多平台的内容，对检索链路的稳定性有更高要求。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.65–0.75 | 匹配活动方案、资源位排期等精准业务字段，过滤低相关的通用运营文档 |
| `limit` | 前8–12条 | 控制单次检索返回的结果规模，适配活动类文档的单次检索需求 |
| `usingReRank` | 开启 | 针对多源异构的活动文档，通过重排优化结果排序精度 |
| `searchMode` | 混合检索 | 整合内容库、活动后台、流量数据的多源内容，覆盖全流程活动文档 |
| 重排最低相关度阈值 | 0.55–0.60 | 按实测标定，避免出现召回结果为空或引入无关内容的情况 |

## 容易做错的三处
- 现象：开启重排后检索结果为空，返回片段无有效内容。原因：`similarity`阈值设置过高，过滤掉了所有符合活动业务场景的召回结果。
- 现象：重排后的结果排序混乱，无法匹配活动优先级需求。原因：未结合活动文档的资源位、周期等字段特征调整重排参数，仅使用默认权重。
- 现象：本地部署的BGE Reranker v2 m3模组调用报错，无法完成重排环节。原因：未在FastGPT中正确配置本地模型的部署路径与端口，或模组版本与当前FastGPT版本不兼容。

## 怎么确认配好了
- 导入10份典型活动文档，执行检索测试，核对返回结果是否包含活动方案、资源位排期等核心业务文档。
- 查看FastGPT的检索链路日志，确认重排模型正常调用，无超时或报错信息。
- 调整`similarity`阈值与重排最低相关度阈值，对比不同配置下的结果相关性，标定符合业务需求的取值。
- 模拟节假日临时更新的活动数据，测试检索结果是否能及时覆盖新的活动内容。
