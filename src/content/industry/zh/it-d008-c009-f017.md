# 个人信息保护合规的运维值班与内部工单问答：部署与升级

本配置适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
这个细分品类的数据围绕可识别自然人的个人信息处理全流程生成，典型来源包括业务系统操作日志、App权限清单、官方隐私政策文本、用户请求记录。日常产出的文档包含个人信息清单、处理规则、影响评估报告、用户授权文本，数据更新频率为季度或每次产品功能变更时。数据字段包含信息类型、处理目的、合法性基础、存储周期等，无统一固定格式，需根据业务场景灵活调整。出错后可能引发投诉、行政处罚或下架整改，与其他数据安全品类的核心差异在于聚焦自然人信息的全链路合规校验。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据来源分散且格式灵活，部署阶段需支持多源数据的自定义导入与字段映射配置，避免硬编码适配不同业务的合规文档结构。数据更新频率随产品变更调整，升级阶段需兼容旧版合规工单与文档的迁移，防止历史数据失效。由于合规场景的出错后果严重，部署时需额外配置校验环节，拦截不符合格式的敏感数据导入。同时，合规相关的工单与文档需隔离存储，部署时需明确划分存储资源与其他业务数据的边界。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[合规数据库用户名]:[合规数据库密码]@[数据库主机]:[端口]/fastgpt_compliance?authSource=admin` | 存储合规工单、个人信息清单等敏感数据，需指定专属数据库与认证源，隔离普通业务数据 |
| `REDIS_URL` | `redis://:[缓存密码]@[缓存主机]:[端口]/1` | 缓存合规校验的中间结果、工单会话信息，使用独立数据库编号避免与业务缓存混淆 |
| `DB_MAX_LINK` | `80–120` | 合规场景下工单与文档查询并发较高，适配连接池上限以避免连接耗尽 |
| `STORAGE_S3_ENDPOINT` | 按合规存储服务商提供的端点地址填写 | 存储用户授权文本、影响评估报告等敏感文档，需使用符合合规要求的对象存储服务 |
| `FILE_TOKEN_KEY` | 自定义随机字符串，长度不低于32字符 | 生成文件访问令牌，用于安全传递用户上传的合规相关文件参数，防止未授权访问 |

## 容易做错的三处
- 工作流中添加自定义合规插件后，输入输出参数未在节点中显示，且无报错日志。原因是插件未在`ROOT_KEY`对应的权限配置中开放合规场景的调用权限，导致前端无法加载插件配置。
- 使用HTTP模块发送用户上传的合规相关文件至外部处理端时，无法获取完整文件参数。原因是未正确配置`FILE_TOKEN_KEY`，导致文件访问令牌过期或无效，无法读取文件内容。
- 部署后合规工单页面频繁崩溃，刷新后无法加载数据。原因是`DB_MAX_LINK`取值过低，并发查询合规文档时数据库连接池耗尽，触发服务异常。

## 怎么确认配好了
- 登录前端控制台，进入系统配置页面，检查`MONGODB_URI`与`REDIS_URL`的连接状态，查看是否显示正常连接提示。
- 上传一份个人信息清单文档，触发合规校验流程，通过缓存监控确认中间结果已正常写入Redis。
- 调用自定义合规插件，查看工作流节点的输入输出参数是否正常加载，确认插件权限配置生效。
- 模拟多并发的工单查询请求，通过系统监控确认数据库连接数未超过`DB_MAX_LINK`的配置值，服务未出现崩溃或超时。
