# 云网络与负载均衡配置的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据主要来自云平台控制台导出的VPC规划文档、安全组规则清单、负载均衡配置文件，以及网络拓扑图、流量监控报表、客户提交的架构设计图。日常产出的文档包括单次变更的配置单、网段规划表、健康检查策略说明，数据更新频率随每一次配置变更或工单交付同步更新。单条数据的核心字段包含网段范围、端口映射规则、健康检查阈值、关联云资源ID，无统一的单位前缀，部分字段需结合云厂商控制台的原始格式解析。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据来源分散于云平台控制台、网络拓扑图、流量监控报表等多类格式，部分内容为非结构化的配置片段或截图，要求检索环节适配多源异构数据的解析逻辑。数据更新随每一次配置变更或工单交付同步触发，需保证知识库索引的增量更新频率匹配业务变更节奏，避免召回过时的网段规则或健康检查配置。核心字段无统一标准单位，检索时需额外关联云资源的上下文信息才能完成准确匹配。内容聚焦网络连通与流量分配规则，与其他云服务品类的资源开通类数据差异显著，需针对性调整召回的匹配优先级。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配云网络配置的精准度要求，避免召回无关的安全组规则或网段规划 |
| `limit` | 前8条 | 单工单涉及的配置项通常不超过7个，保留冗余量以覆盖多规则核对场景 |
| `searchMode` | semantic | 适配非结构化的网络拓扑与配置文档，优先匹配语义关联的网段与端口规则 |
| `usingReRank` | 开启 | 对召回的配置项按工单问题的相关性重排序，优化健康检查配置的检索结果顺序 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展工单中的网络术语，将「负载均衡」关联到「端口转发」「会话保持」等相关配置 |
| `collectionIds` | 绑定专属云网络配置知识库 | 隔离与其他品类的知识库数据，避免召回云主机相关的配置内容 |

## 容易做错的三处
-  检索结果混入非目标品类的内容，现象：召回结果中出现云主机资源开通的配置条目，原因：未绑定专属的`collectionIds`，导致跨知识库检索到无关品类的数据。
-  私有部署环境下无法添加图片数据集，现象：知识库上传界面无图片数据集的配置入口，原因：FastGPT v4.17.0的私有部署版本中，图片数据集模块未默认集成到基础知识库配置流程，需手动开启扩展配置。
-  无法查看单篇资料的历史调用日志，现象：界面仅显示全局知识库调用记录，无法筛选单篇文档的调用情况，原因：当前版本的日志查询模块未开放单篇文档的维度筛选功能，仅支持全局维度的统计。

## 怎么确认配好了
-  上传一条测试用的负载均衡配置文档，发起包含「端口转发规则」的测试工单，核对检索结果是否仅包含云网络相关的配置内容。
-  查看知识库的索引更新日志，确认索引更新频率匹配业务变更的时间要求。
-  发起包含模糊术语的测试查询，比如「检查负载均衡的健康策略」，核对检索结果是否按相关性完成重排序。
-  进入知识库的配置页面，确认`collectionIds`已绑定专属的云网络配置知识库，无其他品类的知识库关联。
