# 产品使用数据分析的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来源于埋点系统、数据仓库、CRM及工单系统，更新频率多为日度或周度。日常关联文档包括产品使用分析报告、埋点方案、指标口径表、看板需求单。数据字段通常包含用户ID、功能模块、操作时长、触发时间、客户ID、工单优先级等，单位涵盖次、分钟、天等，不同来源的数据字段格式存在一定差异。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据来源分散且格式各异，要求混合检索需同时覆盖语义相似的分析文档与精准匹配的字段数据，避免单一检索模式的局限性。数据更新频率为日度或周度，意味着检索数据集需定期同步，重排阈值需适配更新后的数据集分布。此外，指标口径统一是核心耗时环节，要求重排结果需优先匹配指标口径的语义关联，约束了检索与重排的权重设置，确保分析结果的口径一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配产品使用数据的语义关联强度，过滤低相关性的埋点记录与文档 |
| `limit` | 前 15–20 条 | 平衡检索效率与分析所需的样本覆盖范围 |
| `searchMode` | hybrid | 同时召回语义相似的分析报告、精准匹配的指标口径字段，适配多源数据检索需求 |
| `usingReRank` | 开启 | 对混合检索的结果进行二次排序，修正基础检索的语义偏差 |
| 重排模型镜像 | arm架构兼容镜像 | 适配arm架构的部署环境，避免运行时兼容性报错 |

## 容易做错的三处
- 现象：混合检索结果条数与配置的`limit`不符，部分知识库数据未召回。原因：未在工作流中为每个知识库绑定对应的检索变量，导致跨源数据无法正确关联。
- 现象：`usingReRank`设置为开启但结果未按预期重排。排查项：未正确配置FastGPT v4.17.0及以上版本的App/Admin服务端必需环境变量`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions）和非空`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致），未配置会导致启动校验失败或功能异常。
- 现象：部署后重排功能报错，日志提示架构不兼容。原因：使用了amd架构的重排镜像，未适配arm架构的部署环境。

## 怎么确认配好了
- 检查FastGPT v4.17.0及以上版本的App/Admin服务端环境变量，确认`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions）和非空`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致）已正确配置且非空。
- 发起测试检索，查看返回结果的排序逻辑，确认重排功能已生效。
- 验证混合检索的召回范围，确认同时覆盖了埋点日志、指标口径表等多源数据。
- 查看部署环境的架构兼容性，确认重排模型镜像与运行环境匹配。
