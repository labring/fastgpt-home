# 代码安全审计的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据主要来源于源代码仓库、依赖清单、静态应用安全测试（SAST）工具与公开漏洞库，按项目版本或单次审计任务更新。日常产出的文档包含代码审计报告、漏洞证明材料、修复建议文档与复测记录，单份报告通常包含项目标识、漏洞定位信息、风险等级标注与整改指引，数据字段涵盖项目ID、代码片段、漏洞编号、修复状态等核心项。

## 这些特征在「权限与数据隔离」这一环带来什么约束
源代码仓库与漏洞库的访问权限需绑定项目维度，不同审计团队无法越权访问其他项目的代码与漏洞数据。按版本更新的审计报告需匹配当前`teamId`，避免跨团队数据混淆。内部工单问答场景中，运维值班人员的操作范围需限定在负责的项目组内，无法查看非关联项目的审计数据。同时，复测记录与修复建议的流转需匹配当前团队的权限范围，防止敏感安全信息泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `teamId` | 绑定当前审计项目的团队标识 | 审计数据按项目维度存储，需匹配团队权限范围 |
| `tmbId` | 绑定当前登录用户的身份标识 | 区分不同运维值班人员的操作权限，防止越权访问 |
| 数据隔离范围 | 按项目组划分权限域，仅允许访问负责项目的1000 MB以内的审计数据 | 日常审计数据按项目版本更新，跨项目访问会导致数据混淆 |
| 会话权限校验 | 每次对话请求校验`teamId`与`tmbId`的匹配性 | 内部工单问答场景需确保操作人与权限域一致 |
| 操作日志留存 | 留存180天的权限操作日志 | 符合安全审计的追溯要求，便于排查越权操作 |

## 容易做错的三处
- 现象：不同运维值班人员访问同一工作流的全局变量时，获取到的审计数据出现跨项目混淆。原因：未通过`teamId`绑定团队权限，全局变量作用域未按项目划分，导致不同团队的数据互相干扰。
- 现象：切换团队后，tokenLogin接口返回的团队数据未同步更新，导致后续权限校验失败。原因：未将返回的团队数据与当前用户的`tmbId`绑定存储，未实时更新会话的权限域配置。
- 现象：内部工单问答时，无权限用户查看对话记录后，界面显示“没有权限操作此对话记录”，且无法取消该提示。原因：权限校验逻辑仅拦截了操作，未配置无权限时的静默处理，直接抛出了默认报错文案。

## 怎么确认配好了
- 登录不同`teamId`的账号，尝试访问非负责项目的审计数据，确认无法查看对应内容。
- 切换团队后，调用tokenLogin接口，验证返回的团队数据与当前账号的`tmbId`匹配。
- 发起内部工单问答，查看无权限用户的对话界面，确认是否按照配置显示对应提示或静默处理。
- 检查权限操作日志，确认留存周期符合配置要求，且所有权限变更都有记录。
