# 代码安全审计的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的典型使用主体为安全研发、安全服务商与研发团队。日常维护的文档包含代码审计报告、漏洞证明、修复建议、复测记录四类，文档结构通常包含漏洞编号、风险等级、关联代码片段、修复方案、复测结果等字段。数据来源涵盖源代码仓库、依赖清单、静态应用安全测试（SAST）工具输出、公开漏洞库，更新节奏随项目版本迭代，每完成一个版本的审计或复测即更新对应文档，无固定周期。

## 这些特征在「知识库检索与召回」这一环带来什么约束
代码安全审计的文档包含大量代码片段与技术细节，要求检索环节需兼顾语义匹配与语法一致性，避免召回与当前场景无关的通用漏洞文档。数据来源分散且随项目迭代更新，要求检索范围需严格限定在当前项目的专属知识库集合内，防止跨项目文档干扰。文档字段包含风险等级与关联代码，要求检索需优先召回高风险等级的文档，同时支持按代码片段语义精准匹配。运维值班与工单场景下需快速获取结果，要求检索流程需控制响应时长，避免过长等待影响值班效率。

## 配置怎么定
以下配置基于FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 代码片段的语义匹配需要较高阈值，避免低相关结果混入，同时覆盖同漏洞不同代码实现的场景 |
| `limit` | 前8条 | 运维值班场景下需快速浏览结果，过多条目会增加人工复核负担，同时保证覆盖核心关联文档 |
| `searchMode` | `vector` | 代码安全审计的文档包含大量代码和技术细节，向量检索比关键词检索更适配语义匹配需求 |
| `usingReRank` | 开启 | 代码片段的相似性容易被表面差异干扰，重排可以过滤掉语义不匹配的结果，提升召回精准度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 运维工单常包含模糊的漏洞描述，扩展查询可以关联到具体的代码审计报告与修复建议 |
| `collectionIds` | 绑定当前项目的代码审计知识库集合 | 确保检索范围限定在当前项目的合规文档内，避免跨项目文档干扰检索结果 |

## 容易做错的三处
- 现象：控制台抛出“invalid configuration parameter name "hnsw.iterative_scan"”报错。原因：使用了FastGPT允许参数清单外的检索配置项，错误引入了非指定参数。
- 现象：检索结果仅返回2条，无法覆盖当前工单关联的所有漏洞文档。原因：`limit`配置过低，且未开启`datasetSearchUsingExtensionQuery`，无法召回通过扩展查询关联的间接文档。
- 现象：召回的代码审计报告片段出现格式错乱，包含多余空格或大小写修改。原因：未在知识库配置中关闭自动文本格式化，或错误配置了检索流程导致文档预处理异常。

## 怎么确认配好了
- 登录FastGPT后台，进入对应知识库集合页面，检查`collectionIds`是否绑定了当前项目的代码审计报告、漏洞证明等专属文档集合。
- 提交一条包含模糊漏洞描述的测试工单，验证`datasetSearchUsingExtensionQuery`是否能召回关联的代码审计文档与修复建议。
- 查看FastGPT检索日志，确认返回结果的`similarity`值处于0.75–0.85区间内，且结果条数符合`limit`配置要求。
- 上传一段测试代码片段，验证`searchMode`为`vector`时能正确召回语义匹配的代码审计报告。
