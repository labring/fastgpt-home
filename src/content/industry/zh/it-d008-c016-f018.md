# 代码安全审计的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来自源代码仓库、依赖清单、静态应用安全测试（SAST）工具与公开漏洞库。日常产出的文档包含代码审计报告、漏洞证明材料、修复建议文档与复测记录。数据更新节奏为每项目版本迭代或单次审计完成后更新，单条数据通常包含漏洞等级、关联函数路径、修复代码片段、项目标识等字段，无统一固定长度，随审计复杂度变化。

## 这些特征在「重排与混合检索」这一环带来什么约束
代码安全审计的数据多为结构化与半结构化混合，且单条数据长度差异较大，会导致混合检索时召回结果的相关性波动明显。按项目版本更新的数据需保证检索时关联当前项目的上下文，避免跨项目无效召回。人工审查的业务逻辑与攻击路径数据，需要重排模型精准匹配用户的运维值班查询，仅依赖基础相似度匹配难以覆盖业务细节。同时，复测记录与修复建议的关联关系，要求重排环节保留数据间的上下文关联，避免拆分后丢失关键逻辑。

## 配置怎么定
本配置适用于FastGPT v4.17.0及以上版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 重排开关 | 开启 | 适配代码安全审计数据的复杂语义匹配需求，过滤低相关性召回结果 |
| 相似度阈值 | 0.72–0.85 | 匹配代码类数据的语义相似度区间，避免遗漏高危漏洞相关的召回结果 |
| 单次召回上限 | 前8–12条 | 平衡检索效率与召回覆盖，适配单次运维值班查询的上下文长度限制 |
| 检索模式 | 混合检索 | 结合向量检索与关键词检索，适配代码审计报告中结构化与半结构化混合的特征 |
| 重排召回上限 | 前4–6条 | 聚焦高相关性结果，适配运维值班的快速查询需求 |
| 重排模型适配 | 按实测标定 | 适配Qwen3-Reranker-8B、bge-reranker系列等主流重排模型，匹配算力资源配置 |

## 容易做错的三处
- 现象：重排模型部署后通过本地测试，但线上检索时返回的重排结果标记为false。原因：未在FastGPT配置中绑定对应重排模型的API地址或密钥，或配置的模型版本与部署版本不匹配。
- 现象：知识库中单条文档长度超过8000字符时，重排环节未触发。原因：系统默认设置了重排触发的单条文档长度上限，未针对代码审计报告的长文本内容调整阈值。
- 现象：检索结果的相关性排序与实际业务需求不符，高危漏洞信息排在低危内容之后。原因：未根据代码安全审计的业务优先级调整重排模型的打分权重，或相似度阈值设置过低导致无关内容被召回。

## 怎么确认配好了
- 进入FastGPT的知识库配置页面，查看重排开关是否处于开启状态，确认绑定的重排模型与部署的模型一致。
- 提交一条包含高危漏洞关键词的测试查询，查看检索结果的重排标记是否为true，且结果排序符合业务优先级。
- 上传一条长度超过5000字符的代码审计报告，触发检索后确认重排环节被正常调用，无跳过提示。
- 查看系统日志，确认重排模型的调用请求已正常发送，无超时或报错记录。
