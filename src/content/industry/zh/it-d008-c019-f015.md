# 众包标注人员管理的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自众包平台后台、标注质量统计报表、标注员培训考核档案、财务结算明细。日常维护的文档包含人员准入规则、培训材料、绩效核算表、结算对账清单等。数据更新节奏为人员资质变动日更，绩效与结算数据月更。文档字段包含标注员工号、准入资质等级、单次标注准确率、月度结算金额等，不同来源的数据结构存在差异，部分为结构化表格，部分为非结构化文本说明。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多来源的数据结构差异要求检索系统需适配结构化与非结构化混合检索，避免因字段不匹配导致召回失败。日更的人员资质数据需要配置增量更新机制，确保检索结果实时反映最新人员状态。月更的绩效与结算数据则无需高频更新，可设置定时全量同步。文档类型覆盖规则、档案、报表等多种形式，需要针对性调整检索模式，确保不同类型文档的召回准确性。同时，字段包含人员资质、绩效、结算等敏感内容，检索时需严格控制召回范围，避免泄露无关数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 该品类文档包含资质、绩效等结构化字段，阈值过低会引入无关标注员数据，过高会遗漏匹配的人员档案内容 |
| `limit` | 前10条 | 众包标注人员管理的知识库条目多为人员档案、规则文档，单次召回过多会超出上下文窗口，影响LLM响应效率 |
| `searchMode` | 语义检索 | 该品类需要匹配人员资质描述、绩效规则等非结构化文本，语义检索可适配自然语言查询的语义匹配需求 |
| `usingReRank` | 开启 | 多来源数据存在冗余，重排可过滤低相关性结果，提升检索结果的准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可对用户查询进行语义优化，适配标注员管理场景下的模糊查询需求，比如“符合中级资质的标注员”这类非精确查询 |
| `collectionIds` | 按业务模块划分，如标注员资质库、绩效规则库、结算流程库 | 该品类数据来自多个独立系统，分库配置可精准召回对应业务模块的内容，避免跨库召回无关数据 |

## 容易做错的三处
- 现象：检索结果同时返回标注员资质和结算流程的无关内容，原因：未正确配置`collectionIds`参数，未按业务模块划分知识库集合，导致跨库召回无关业务的文档。
- 现象：使用Docker Compose部署FastGPT v4.17.0后，点击新建知识库弹出“无法创建目录”报错，原因：未挂载正确的知识库存储卷，或配置文件中数据集路径未匹配实际挂载目录，导致系统无法读写知识库文件。
- 现象：LLM返回的回答包含知识库中未提及的标注员结算规则，原因：`similarity`阈值设置过低，或未开启`usingReRank`，导致召回结果未覆盖用户问题的核心需求，或未配置严格的上下文过滤规则。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理页面，查看已配置的`collectionIds`是否对应标注员资质、绩效规则、结算流程等业务模块的专属知识库ID。
- 发起测试查询，输入“符合中级资质的标注员”，核对检索结果是否仅包含标注员资质库的相关片段，且返回结果条数不超过10条。
- 查看系统检索日志，确认返回结果的`similarity`得分处于0.75–0.85区间内，无跨业务模块的异常召回记录。
- 检查Docker Compose部署的存储卷挂载状态，确认无新建知识库报错的日志记录，且知识库文件可正常读写。
