# 供应商与设备到货管理的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
这个品类的数据通常来自ERP系统、供应商发货单、物流跟踪信息及设备厂商后台，日常关联的文档包含采购订单、到货验收单、序列号清单与发票资料。数据更新以单条项目订单为单位，或按周批量同步，核心字段包含设备型号、序列号、到货时间、供应商信息与验收状态，仅围绕单个集成项目的交付节点流转，无统一的全局统计口径。

## 这些特征在「部署与升级」这一环带来什么约束
品类的数据来源分散且绑定具体项目节点，部署时需配置多数据源的对接参数，适配不同系统的接口格式。数据更新频率为单条或周度批量，因此知识库的增量更新策略需支持小批量、低延迟的同步，避免全量重导带来的资源消耗。核心字段的唯一性要求（如序列号）需在部署时配置文档去重规则，防止重复录入导致资产账实不符。同时，由于服务于具体集成项目，部署需支持项目级的权限隔离，确保不同项目的到货数据互不干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://fastgpt:yourpassword@db-host:27017/fastgpt?authSource=admin` | 品类的采购订单、序列号清单均为多字段文档型数据，适配MongoDB的存储结构，满足项目级数据的灵活查询 |
| `REDIS_URL` | `redis://:redispass@redis-host:6379/0` | 缓存内部工单的会话信息与到货文档的分片索引，适配高频的运维值班查询需求 |
| `DB_MAX_LINK` | `300 秒` | 品类数据更新频率为单条或周度批量，长连接可减少重连开销，避免高频查询时的连接超时 |
| `FE_DOMAIN` | `https://fastgpt.your-company-intranet.com` | 配置内部访问域名，用于运维值班的工单推送与应用管理的回调请求，适配集成项目的内部协作场景 |
| `STORAGE_S3_ENDPOINT` | 按实测标定 | 存储发票资料、到货验收单等文档附件，适配不同云环境或本地存储的接入需求 |

## 容易做错的三处
- 现象：删除自建应用时提示network错误，原因：未正确配置`FE_DOMAIN`与后端API的跨域白名单，导致前端请求无法正常发起。
- 现象：调用文档解析模块报错Cannot read properties of undefined，原因：升级至FastGPT v4.17.0后未同步更新`FILE_TOKEN_KEY`的配置值，导致文档鉴权失败。
- 现象：序列号查询结果条数不符，原因：未调整`DB_MAX_LINK`的超时时间，导致高频查询时连接被断开，返回不完整的查询结果。

## 怎么确认配好了
- 访问配置的`FE_DOMAIN`，确认可以正常登录并进入应用管理页面。
- 上传一份采购订单文档，确认可以正常解析并提取设备型号、序列号等核心字段。
- 发起一条内部运维工单，确认可以正常提交并推送给预设的值班人员。
- 登录Redis实例，确认存在到货文档的缓存索引记录。
