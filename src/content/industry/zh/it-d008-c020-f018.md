# 供应商与设备到货管理的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据通常来自ERP系统、供应商发货单、物流跟踪信息及设备厂商后台。日常处理的文档包含采购订单、到货验收单、序列号清单与发票资料，数据更新以每单或每周为节奏。数据字段包含采购型号、序列号、供应商信息、到货时间、验收状态等，单位多为台、套、件等实物计量单位，且需绑定具体集成项目的交付要求。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据分散来自多源系统，更新节奏随采购单变动，会导致混合检索需兼容异构文档格式与字段结构。文档核心字段为采购型号、序列号等实物属性，重排环节需优先匹配强关联业务字段，避免泛语义匹配导致的结果偏差。同时数据绑定具体集成项目，检索结果需按项目维度过滤，且需适配运维值班的快速响应需求，限制单次返回的有效结果条数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.72–0.85 | 匹配采购型号、序列号等强业务字段，过滤低关联的泛语义结果 |
| 单次搜索上限 | 前8–12条 | 适配运维值班的快速响应需求，减少人工筛选的工作量 |
| 搜索模式 | 混合检索 | 兼容ERP、供应商发货单、物流信息等多源异构数据 |
| 启用重排 | 是 | 优先重排型号、序列号等核心业务字段，提升检索结果的业务匹配精度 |
| 重排结果上限 | 前3–5条 | 按实测标定，聚焦最匹配的到货验收相关结果 |

本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：重排模型调用返回“模型不兼容”报错，或返回空结果。原因：未按FastGPT要求的请求格式配置重排模型，或使用了未适配的重排模型架构。
- 现象：自定义重排模型的请求地址填写后无法连通，日志显示连接超时。原因：未正确填写docker容器内的模型服务地址，或未开放模型服务的端口权限。
- 现象：无法使用Qwen3-Reranker-8B作为重排模型，调用时出现异常。原因：当前FastGPT版本未针对该型号的重排模型做适配，请求参数不匹配。

## 怎么确认配好了
- 上传该品类的典型文档，执行检索测试，查看结果是否优先匹配型号、序列号等核心业务字段。
- 检查重排功能的启用状态，确认检索结果在展示前经过了重排处理。
- 验证多源数据的混合检索效果，确认ERP、物流信息、供应商发货单等不同来源的文档均可被检索到。
- 调整配置项参数，观察检索结果的数量与相关性变化，确认配置生效。
