# 信息化预算与项目组合管理的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据来源为财务系统、项目管理系统、合同台账与业务部门需求。日常文档包含年度预算表、项目立项书、项目组合看板与投资复盘报告，多为结构化表格搭配少量非结构化说明，字段涵盖预算金额、项目周期、立项优先级、投资回报率等，部分字段带有明确单位。数据更新频率为月、季或年，不同来源的文档格式存在细微差异。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据特征对重排与混合检索环节带来多重约束。首先，数据来源分散且格式存在差异，混合检索需同时匹配结构化字段与非结构化文本语义，避免因字段格式不统一导致的检索偏差。其次，更新频率较低，向量库同步周期不宜过短，需平衡数据新鲜度与系统资源占用。此外，运维工单与内部问答多聚焦预算调整、项目优先级等核心需求，检索结果需优先返回匹配关键字段的文档，重排模型需针对结构化字段调整权重分配，提升核心信息的召回优先级。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ------------ |
| `usingReRank` | 开启 | 该品类文档兼具结构化与非结构化内容，重排可过滤低相关性结果，提升检索精准度 |
| `limit` | 前10条 | 运维值班与工单问题通常聚焦少数核心项目或预算项，过多结果会增加筛选成本 |
| `similarity` | 0.72–0.85 | 该品类文档字段明确，该阈值可匹配结构化字段的匹配精度，避免误匹配低相关数据 |
| `searchMode` | 混合检索 | 该品类数据同时包含结构化字段与非结构化文本说明，混合检索可兼顾语义与字段匹配 |

## 容易做错的三处
- 现象：调用gte-rerank-v2或Qwen3-Reranker-8B模型时返回模型不兼容报错，或重排结果为false。原因：未在FastGPT中配置对应重排模型的API密钥与正确请求端点，或模型输入格式与品类文档的结构化字段不匹配。
- 现象：docker部署的reranker服务无法被FastGPT调用，返回请求失败提示。原因：未将docker容器的内部端口与宿主机端口正确映射，或FastGPT填写的自定义请求地址未携带正确的API路径。
- 现象：检索结果中低相关性的非核心文档占比过高，或关键预算项目文档未被召回。原因：未正确设置`similarity`阈值或`limit`参数，导致阈值过低或召回条数过多。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库配置页面，确认`usingReRank`已开启，`searchMode`设置为混合检索。
- 提交一条测试工单，例如“2024年IT项目预算优先级调整”，查看检索结果是否优先返回对应年度预算表的关键字段内容。
- 检查重排模型的调用日志，确认返回的排序结果符合预期，无明显低相关性结果混入。
- 验证自定义reranker的请求地址是否可正常访问，无超时或404类报错。
