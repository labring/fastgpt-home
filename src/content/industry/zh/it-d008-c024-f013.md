# 信息流广告创意测试的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
信息流广告创意测试的核心数据来源于广告投放平台、内部素材库、用户互动数据与转化数据，更新频率多为日度或周度。日常关联文档包括创意脚本、素材测试表、投放数据报告与迭代清单，数据字段包含素材ID、创意类型、测试周期、点击率、转化成本、素材合规状态等，无统一固定单位，部分字段需结合对应广告平台的接口规范定义。

## 这些特征在「权限与数据隔离」这一环带来什么约束
信息流广告创意测试的多来源跨系统数据，需要匹配优化师、创意团队、增长团队的不同业务角色访问边界，避免跨组越权查看敏感投放数据。日度或周度更新的测试数据与迭代清单存在时效性，权限配置需随项目变更实时生效，防止旧权限残留导致的数据泄露。创意测试的出错后果直接关联投放效果，权限隔离需防止非授权人员修改正式投放的创意配置或测试结论，同时避免不同测试项目的素材数据交叉混淆。内部工单的流转需绑定对应测试项目的权限，确保工单仅在授权范围内审批与处理。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的权限与数据隔离模块实现。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 团队权限绑定 | 绑定`teamId`与广告账户归属 | 匹配广告平台的账户归属逻辑，确保仅同团队成员可访问对应创意测试数据 |
| 素材权限绑定 | 绑定`tmbId`与素材库分组 | 限定素材访问范围仅为当前测试项目的素材资源，避免跨项目素材泄露 |
| 全局变量隔离 | 开启`teamId`维度变量隔离 | 解决不同团队的同名全局变量互相覆盖的问题，匹配业务角色的变量使用场景 |
| 工单权限范围 | 限定为当前`teamId`下的测试工单 | 缩小工单审批的权限边界，确保审批仅能处理对应团队的内部工单 |
| 访问时效控制 | 限定为最近7天且单份最大1000 MB的测试数据 | 减少权限覆盖范围，降低历史数据泄露风险，匹配日常测试数据的体量 |
| 日志审计配置 | 仅记录当前`teamId`的操作日志 | 简化问题排查范围，同时满足内部合规审计的需求 |

## 容易做错的三处
- 现象：不同团队的优化师查看测试报告时，出现跨组素材数据交叉显示。原因：未绑定`teamId`与广告账户归属，权限未按团队隔离，导致跨组数据权限混乱。
- 现象：配置同名全局变量后，不同使用者的变量值互相覆盖。原因：未开启`teamId`维度的变量隔离，未按团队或使用者ID隔离变量作用域，引发配置冲突。
- 现象：运维值班人员无法查看对应测试项目的工单详情。原因：工单审批角色未绑定对应`tmbId`或`teamId`，权限范围未覆盖目标测试项目的关联数据。

## 怎么确认配好了
- 切换不同团队的测试账号，验证仅能访问对应`teamId`绑定的创意测试数据与工单。
- 配置同名全局变量，使用不同团队账号发起测试，确认变量值互不干扰。
- 提交内部工单，验证审批角色仅能查看对应`teamId`下的工单与关联测试数据。
- 查看操作日志，确认仅记录当前账号所属团队的操作行为，无跨组操作记录。
