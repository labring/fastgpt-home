# 值班排班与交接的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来自排班系统、故障工单、监控告警与组织通讯录，日常文档包含值班表、交接记录、升级联系人清单及值班日报。数据更新频率为日度或周度，核心字段包含值班时段、交接事项、升级联系人信息、未结故障状态等，不同团队的排班规则、交接模板存在差异，数据结构随团队运维流程调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据来源分散且结构异构，需限定检索范围至专属业务集合，避免无关数据干扰检索结果。日常文档包含强时序的值班时段、未结事项等字段，检索时需优先匹配当前值班周期的内容，过滤过期的历史排班信息。数据更新频率为日度或周度，需定期同步知识库增量，确保检索结果包含最新的值班安排与交接记录。同时，核心场景依赖升级联系人、故障状态等关联信息，检索召回需覆盖多字段的关联匹配。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `collectionIds` | 按业务场景指定，例如`["值班排班集合","交接记录集合","升级联系人集合"]` | 限定检索范围至该品类专属数据，排除其他业务知识库的无关内容 |
| `limit` | 前8-12条 | 该品类核心数据条目较少，过多结果会增加值班人员筛选成本 |
| `similarity` | 0.75-0.85 | 平衡检索精准度与召回完整性，避免遗漏近期更新的排班或交接信息 |
| `usingReRank` | 开启 | 该品类数据包含强时序与关联字段，重排可优先返回匹配值班时段、未结事项的结果 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索词，覆盖排班规则、交接流程的同义表述，提升召回覆盖度 |
| `searchMode` | 语义检索 | 该品类数据包含非结构化的交接记录与排班说明，语义检索比关键词匹配更适配业务场景 |

## 容易做错的三处
- 现象：检索结果包含非值班排班类的业务文档，与当前场景无关。原因：未通过`collectionIds`参数限定检索范围，或配置的集合ID与实际业务集合不匹配。
- 现象：检索返回的值班文档仅显示标题与摘要，无法获取完整交接记录内容。原因：未启用文档扩展检索配置，未配置针对值班文档的内容抓取规则。
- 现象：md格式的值班表文档上传后，内嵌图片无法正常加载。原因：上传文件时未将图片资源同步至知识库存储目录，或原md文件中的图片路径未替换为知识库可访问的绝对地址。

## 怎么确认配好了
- 手动输入一条近期的值班时段关键词，检查检索结果是否仅包含该品类的值班表、交接记录等文档。
- 调整`similarity`参数的取值区间，验证检索结果的精准度是否符合业务需求，确认阈值设置合理。
- 上传一份测试用的md格式值班文档，检查内嵌图片是否正常加载，确认文档资源配置正确。
- 查看检索日志，确认仅调用了指定的业务集合，未检索到无关知识库内容。
