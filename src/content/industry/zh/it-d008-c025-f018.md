# 值班排班与交接的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据来自排班系统、故障工单、监控告警与组织通讯录，更新频率为日或周。日常文档包含值班表、交接记录、升级联系人清单与值班日报，其中值班表含值班日期、值班人员、联系方式字段，交接记录记录未结工单、待跟进事项与升级路径，升级联系人清单标注各运维组的二线对接人。

## 这些特征在「重排与混合检索」这一环带来什么约束
数据来源分散且更新节奏不同，排班系统数据每日更新，组织通讯录每周更新，混合检索需适配不同数据源的时效性权重。日常文档结构差异明显，值班表为结构化字段数据，交接记录多为非结构化文本，重排环节需针对不同文档类型调整匹配优先级。该品类核心场景聚焦排班冲突协调、未结事项交接与升级路径确认，检索需优先召回对应高价值字段，避免无关结果干扰核心决策。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | `0.72–0.85` | 适配值班表结构化字段的匹配精度，避免召回无关排班记录 |
| 单次召回上限 | `前 8 条` | 覆盖单次值班周期内的核心交接与排班数据，避免结果过多干扰检索 |
| 搜索模式 | 混合检索 | 结合关键词匹配与语义检索，适配结构化与非结构化文档的混合检索需求 |
| 重排开关 | 开启 | 针对交接记录的非结构化文本，通过重排提升未结事项与升级路径的召回排序精度 |
| 检索超时阈值 | `60 秒` | 适配多数据源检索的响应时长，避免因排班系统接口延迟导致检索失败 |

## 容易做错的三处
- 界面未显示本地部署的重排模型。原因：未在FastGPT的配置文件中正确配置重排模型的访问地址与安全凭证，导致平台无法识别本地部署的服务。
- 检索结果排序不符合业务优先级，未结事项未排在前列。原因：未开启重排开关，或相似度阈值设置偏差，导致非结构化的交接记录未被正确排序。
- 检索结果条数不足预期。原因：单次召回上限设置过低，或多数据源检索时部分接口超时，导致完整数据未被召回。

## 怎么确认配好了
- 进入FastGPT v4.17.0及以上版本的知识库配置页面，确认重排开关处于开启状态。
- 发起包含值班日期、未结工单关键词的测试检索，核对返回结果的排序是否符合业务优先级。
- 查看检索日志，确认多数据源的召回数据均被正常加载，无超时或连接报错。
- 调整相似度阈值后，验证召回结果的数量与相关性是否符合业务需求。
