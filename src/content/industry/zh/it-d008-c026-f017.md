# 关卡内容制作的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
通常关卡内容制作团队的数据来自关卡编辑器、美术资源库、玩家测试数据与缺陷系统。日常产出的文档包含关卡设计稿、资源需求表、测试反馈单与版本提交记录，文档字段多包含关卡ID、资源路径、测试节点、提交版本号等，更新频率为周度或每版本迭代。数据围绕具体地图与任务规则生成，区别于侧重数值与规则框架的其他游戏研发品类。

## 这些特征在「部署与升级」这一环带来什么约束
关卡内容制作的高频版本更新与多类型文档数据，要求部署环节支持轻量化的版本回滚机制，避免版本升级导致的关卡数据异常。数据来源分散于编辑器与资源库，部署时需配置跨源数据访问权限，确保内部工单问答能拉取全链路文档。单次更新涉及大量关卡资源与测试反馈，部署后的校验环节需覆盖资源路径匹配、版本号同步等场景，防止因配置遗漏导致上线延期或卡关问题。同时，团队内部的多账号协作需求，要求部署时配置合理的权限隔离与团队管理参数，保障不同策划的关卡数据隔离。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本，建议服务器配置为至少2核CPU、4000 MB内存。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150 个连接` | 适配多团队同时提交关卡数据与测试反馈的并发访问需求，避免数据库连接耗尽 |
| `MONGODB_URI` | 指向存储关卡设计稿、版本提交记录的专属MongoDB实例 | 隔离游戏业务数据与通用运维数据，防止权限交叉导致的文档泄露 |
| `PG_URL` | 指向本地PostgreSQL实例，存储团队权限与工单数据 | 保障内部运维与工单系统的数据存储独立，避免与业务数据混淆 |
| `REDIS_URL` | 配置为本地私有Redis服务，内存配额`2000 MB` | 缓存高频访问的关卡资源路径与测试反馈数据，降低数据库查询压力 |
| `FE_DOMAIN` | 填写团队专属的运维值班页面域名，如 https://fastgpt-game-dev.com | 确保内部工单问答的跳转链接指向正确的团队部署地址 |
| `ROOT_KEY` | 生成随机32位字符串 | 作为后台最高权限验证密钥，限制内部运维人员的操作范围 |
| `FILE_TOKEN_KEY` | 生成随机64位字符串 | 用于生成关卡资源访问的临时令牌，保障美术资源库的访问安全 |
| `STORAGE_S3_ENDPOINT` | 指向团队自建的美术资源库存储端点 | 直接拉取关卡制作所需的美术资源数据，减少跨存储服务的延迟 |

## 容易做错的三处
- 部署新版本后访问`FE_DOMAIN`返回404状态码，未正确配置`FE_DOMAIN`参数导致前端静态资源未绑定到正确的域名路径。
- 无法创建多账号且表格添加数据后无响应，未正确配置`PG_URL`或`REDIS_URL`导致用户权限与团队数据存储链路异常。
- 工单问答加载关卡数据超时，未按`DB_MAX_LINK`的建议配置数据库连接数，或`REDIS_URL`的内存配额不足导致缓存失效。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本的部署流程：
- 访问配置的`FE_DOMAIN`，确认运维值班页面正常加载，无404或502错误。
- 登录后台使用`ROOT_KEY`验证权限，确认最高权限操作可正常执行。
- 提交一条测试工单，尝试拉取本地关卡设计稿的关联数据，确认存储服务与数据库链路正常。
- 模拟多账号登录，确认不同账号的团队权限隔离生效，无法访问其他团队的关卡数据。
