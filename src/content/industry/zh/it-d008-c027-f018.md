# 内容审核规则运营的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
本品类的核心数据来自内容审核后台、用户举报入口、公开法规政策库与内部审核样本库。日常维护的文档包含审核规则条目、违规处置指南、用户申诉记录与质检复盘报告，字段涵盖规则编号、触发阈值、违规类型、申诉状态、质检得分等。数据更新频率为每日同步或随政策法规变更即时更新，单份文档长度跨度较大，从数十字符的规则条目到数千字符的完整申诉案卷不等。

## 这些特征在「重排与混合检索」这一环带来什么约束
本品类的数据分散于多系统与文档库，混合检索需整合审核后台规则、申诉案卷、政策文件等异构数据源，需确保不同来源的字段可统一匹配。文档长度跨度大，短至数十字符的规则条目，长至数千字的完整申诉案卷，重排模型需适配不同长度的文本特征。数据更新频率随政策变动即时调整，检索链路需支持快速拉取最新规则与样本数据，避免返回过时内容。同时，疑难样本判定与申诉复核环节对检索精准度要求高，需过滤无关结果，聚焦核心规则与关联样本。

## 配置怎么定
以下配置适用于FastGPT v4.17.0。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `usingReRank` | 开启 | 本品类需精准匹配审核规则与申诉样本，重排可过滤低相关结果，提升复核效率 |
| `similarity` | 0.72–0.85 | 审核规则与样本文本的语义匹配需兼顾精准与召回，该区间适配短规则与长案卷的混合检索 |
| `limit` | 前10条 | 运维值班与工单问答场景下，单次检索返回结果需控制在合理范围，避免信息过载 |
| `searchMode` | hybrid | 需整合向量检索与关键词检索，覆盖规则关键词匹配与语义关联的样本检索 |
| 重排模型匹配阈值 | 0.68–0.75 | 针对审核规则的短文本特征，该阈值可有效过滤无关样本，聚焦核心关联内容 |

## 容易做错的三处
- 部署bge-rerank-base镜像后调用重排模型返回401 unauthorized错误，原因是未正确配置模型访问密钥或镜像的权限校验参数，导致FastGPT无法正常调用重排模型。
- 未开启重排功能时，检索结果仅按向量相似度排序，无法过滤语义不相关的规则条目，导致运维人员需手动筛选大量无效内容。
- 混合检索配置为纯向量模式时，无法匹配审核规则中的关键词字段，导致高频触发的通用违规规则无法被精准召回，影响工单响应效率。

## 怎么确认配好了
- 进入FastGPT的检索配置页面，确认`usingReRank`开关处于开启状态。
- 提交一条包含违规类型关键词的测试工单，核对返回结果中是否包含最新的审核规则条目与关联申诉样本。
- 查看检索返回结果的条数，确认与`limit`配置的取值一致。
- 对比开启与关闭重排功能后的检索结果，确认开启后低相关结果占比下降。
