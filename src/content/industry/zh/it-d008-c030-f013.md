# 内部网络与WiFi运维的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据主要来自交换机控制台、无线控制器、办公区监控系统及员工用户报障渠道。日常维护产生的文档包含网络拓扑图、网络变更单、故障排查记录、无线覆盖巡检表。数据更新频率为每日同步或随网络变更即时更新。数据字段包含设备端口号、VLAN配置、无线信号强度、故障发生时间、处理进度等，部分文档需关联具体办公区域与设备编号。

## 这些特征在「权限与数据隔离」这一环带来什么约束
网络拓扑图、变更单等文档包含企业办公网络的核心配置信息，需限制仅授权运维人员访问。不同办公区域的无线覆盖巡检数据需按区域隔离，避免跨部门运维人员获取无关区域的网络配置。设备端口与VLAN的核对数据涉及网络安全边界，需确保仅对应区域的运维人员可操作。用户报障数据关联具体工位，需绑定提交者所属部门，避免非授权人员查看其他部门的报障信息。每日更新的监控数据需按团队权限划分存储，防止敏感网络配置泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `teamId` | 按运维团队划分的唯一标识，取值范围为`10001–10005` | 匹配企业内部运维团队的岗位归属，实现按团队隔离数据访问权限 |
| `tmbId` | 绑定办公区域的设备分组ID，取值为`50–200`按区域分段 | 匹配该品类按办公区域划分的运维职责，避免跨区域访问无关网络数据 |
| 全局变量隔离规则 | 按`tmbId`限定作用域，不同`tmbId`下的同名变量互不共享 | 解决不同运维团队使用同名全局变量时的数据冲突问题 |
| SSO权限开关 | 商业版开启，仅绑定`teamId`通过验证的用户可访问 | 匹配商业版SSO功能的权限需求，实现身份与权限的绑定验证 |
| 故障记录访问权限 | 仅允许对应`teamId`的用户查看本团队处理的故障记录 | 匹配该品类的故障排查职责范围，避免非授权人员查看敏感故障数据 |
| tokenLogin数据存储 | 按`teamId`分类存储接口返回的团队数据 | 符合团队数据存储的需求，确保不同团队的配置数据互不干扰 |

## 容易做错的三处
- 现象：不同运维团队使用同名全局变量时，出现跨团队数据混淆，查看的变量值与预期不符。原因：未按`tmbId`配置全局变量的作用域隔离规则，导致变量作用域未绑定团队标识。
- 现象：非商业版用户尝试开启SSO功能时，界面提示权限不足或功能未开放。原因：未区分基础版与商业版的SSO权限配置，错误在基础版开启该功能。
- 现象：跨区域运维人员查看了非负责区域的无线覆盖巡检数据，导致敏感配置泄露。原因：未按`tmbId`绑定设备分组ID，错误开放了跨区域的数据访问权限。

## 怎么确认配好了
- 登录FastGPT v4.17.0，切换至不同`teamId`的账号，验证仅能查看对应团队负责的网络设备数据。
- 提交测试工单，使用不同`tmbId`的账号，确认同名全局变量的取值互不干扰。
- 调用tokenLogin接口，验证返回的团队数据仅包含当前`teamId`对应的配置信息。
- 尝试在基础版环境中开启SSO功能，确认界面提示功能未开放，符合权限隔离要求。
