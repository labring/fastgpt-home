# 内部网络与WiFi运维的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
通常，内部网络与WiFi运维的相关数据由网络管理员、桌面支持及外包驻场人员产生与维护。日常文档包含网络拓扑图、变更单、故障记录、无线覆盖巡检表等，数据来源涵盖交换机控制台、无线控制器、办公区网络监控系统及终端用户报障渠道。数据更新频率为每日同步或随配置变更即时更新，核心字段包含端口编号、VLAN配置、故障发生时间、无线信号强度等，无统一固定单位，需结合具体文档场景匹配。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据特征对检索召回环节带来多重约束。首先，数据来源混合了结构化的设备配置与非结构化的故障记录，要求检索同时支持精确匹配与语义理解；其次，更新频率较高且随变更即时生效，要求召回机制支持增量更新与实时同步；再者，故障定位与排查是核心耗时环节，要求检索结果优先返回与当前问题强相关的拓扑、记录类文档；最后，办公中断、会议受影响等出错后果严重，要求检索结果具备较高精准度，避免无关信息干扰决策。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配内部网络故障相关的专业术语，避免低相关结果干扰运维判断，适配设备配置、故障记录的文本特征 |
| `limit` | 前10条 | 平衡运维值班时的信息获取效率与完整度，避免过多内容占用对话上下文，符合快速排查故障的场景需求 |
| `searchMode` | 混合检索 | 同时匹配结构化的端口/VLAN配置与非结构化的故障记录文本，覆盖该品类全类型文档 |
| `usingReRank` | 开启 | 对初步召回的结果按运维场景优先级重排，优先展示故障定位、网络优化相关的文档，缩短排查耗时 |
| `collectionIds` | 指定内部网络运维集合 | 限定检索范围，排除无关知识库内容，提升精准度，避免跨业务线文档干扰 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动补充运维场景相关的扩展查询词，比如“端口占用”“无线漫游”“VLAN隔离”等，覆盖更多相关文档 |

以下配置基于FastGPT v4.17.0版本。

## 容易做错的三处
-  检索结果超出指定的内部网络运维范围，返回其他业务线的文档。原因是未配置`collectionIds`参数，未限定检索的知识库集合，导致检索覆盖了全量知识库内容。
-  上传到知识库的网络拓扑图、巡检表图片无法在对话中正常输出。原因是未开启知识库图片检索的关联配置，或未为图片生成对应的结构化索引信息，导致检索无法关联图片内容。
-  单次检索返回结果条数远超预期，导致上下文溢出。原因是未设置合理的`limit`参数，或`similarity`阈值设置过低，召回了过多低相关的文档。

## 怎么确认配好了
-  创建仅包含内部网络运维文档的独立知识库集合，调用检索接口传入`collectionIds`参数，验证返回结果仅包含该集合内的文档。
-  输入典型运维问题，比如“某楼层无线覆盖弱怎么办”，查看检索结果是否优先展示无线覆盖巡检表、故障记录类内容，确认重排功能生效。
-  上传测试图片到知识库，输入包含图片描述的问题，比如“查看这个交换机端口配置图”，验证对话中可正常展示对应图片。
-  上传两份内容完全一致的运维变更单，执行检索，查看结果是否仅展示单条记录，确认重复文件过滤逻辑生效。
