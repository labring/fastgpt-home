# 创作者入驻与认证的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
通常，创作者入驻与认证的业务数据来源包括创作者后台、企业信用信息查询接口、账号历史记录系统、合作合同管理系统。日常处理的文档包含入驻申请表单、身份资质扫描件、认证审核流转记录、合作框架协议。数据更新节奏按单次申请触发或每日批量同步，字段涵盖账号唯一标识、资质编号、审核状态、合作期限等，部分为结构化字段，部分为自由文本内容，无统一固定格式。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据来源分散且字段格式多样，知识库检索需支持多数据源关联匹配，避免遗漏跨系统的关联信息。按申请触发的更新节奏要求知识库支持增量同步，确保最新的资质审核记录能及时被检索到。多样的文档结构需要检索策略兼顾结构化字段与自由文本的匹配精度，同时最耗时的资质核验环节要求召回结果具备较高的精准度，避免无关内容干扰审核判断，否则可能引发虚假认证或账号权益错配等问题。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置规范，具体配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配入驻申请、资质材料这类专业文本时，该区间可过滤低相关结果，同时覆盖真实匹配的内容 |
| `limit` | 前8条 | 平衡内部工单处理的上下文长度与召回全面性，避免过多结果导致处理过载 |
| `usingReRank` | 开启 | 入驻相关文本存在大量格式差异，重排可提升精准匹配度，优化资质核验的召回效果 |
| `datasetSearchUsingExtensionQuery` | 开启 | 针对账号ID、资质编号这类结构化字段，通过问题优化扩展检索范围，提升结构化数据的召回率 |
| `collectionIds` | 绑定创作者入驻认证专属知识库集合 | 隔离业务数据，避免与其他品类的知识库内容产生干扰 |

## 容易做错的三处
- 出现`quote type error`报错：现象为配置变量引用时返回格式错误提示，原因是未按知识库字段的格式要求传入变量，例如资质编号字段未使用正确的包裹符号或格式不匹配。
- 完全匹配的chunk无法召回：现象为特定知识库下，与问题完全一致的文本块未被召回，新建相同内容的知识库却可正常召回，原因是旧知识库的分块参数与当前检索配置不匹配，或`searchMode`配置未统一。
- 检索结果无来源标注：现象为返回的检索结果未展示知识库引用信息，原因是未开启引用展示开关，或重排操作后未保留原始chunk的来源关联信息。

## 怎么确认配好了
- 提交包含资质编号、账号ID的测试问题，检查返回结果的相似度是否处于0.75–0.85区间内，验证`similarity`配置生效。
- 查看检索结果的返回条数，确认不超过8条，验证`limit`配置的取值符合设定。
- 传入格式正确的资质编号变量，确认无`quote type error`报错，验证变量引用配置正确。
- 对比新旧知识库的检索结果，确认`searchMode`配置统一后，相同内容的召回逻辑一致，验证集合绑定配置生效。
