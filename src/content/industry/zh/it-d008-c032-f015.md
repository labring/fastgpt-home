# 创作者激励结算的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的核心参与方为创作者运营、财务运营与数据运营岗位，日常维护的文档包括激励规则、结算明细、申诉记录与付款清单四类。数据来源涵盖内容数据系统、广告分成系统、财务系统与创作者账号后台，更新频率为月度结算周期或单次活动周期。文档字段通常包含创作者唯一标识、结算周期编号、收益计算口径、申诉状态、付款金额等，无统一固定格式，随不同结算活动调整字段细节。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源数据接入需求要求检索覆盖多个独立数据集，需配置跨数据集检索能力。非固定更新频率要求检索优先召回最新同步的结算数据，避免使用过期缓存。文档字段的非标准化特征，要求检索配置支持自定义字段匹配，避免通用检索无法精准定位结算相关内容。单笔结算明细数据量较大，需控制单次召回的文档块长度，防止超出上下文窗口限制。创作者结算问题常包含简称或口语化表述，需支持查询扩展以覆盖更多相关文档。

## 配置怎么定
本配置建议基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.72–0.80` | 结算相关问题需较高匹配精度，避免低匹配度的非结算内容干扰，防止引发结算核对错误 |
| `limit` | `前 8–12 条` | 结算明细与申诉记录通常条目较多，限制召回条数可压缩上下文长度，同时覆盖核心结算信息 |
| `searchMode` | `全文检索` | 覆盖规则类文档的关键词匹配与明细类数据的字段精准匹配需求 |
| `usingReRank` | `开启` | 结算问题需精准排序相关结果，重排可提升高匹配内容的展示优先级 |
| `datasetSearchUsingExtensionQuery` | `开启` | 创作者结算问题常包含简称或口语化表述，扩展查询可覆盖更多相关文档 |
| `collectionIds` | `按结算相关数据集ID配置` | 限定检索范围仅覆盖激励规则、结算明细等目标数据集，排除无关内部文档 |

## 容易做错的三处
- 检索响应超时，表现为运维工单的回复延迟超过预设阈值。原因是未通过`collectionIds`限定检索数据集范围，同时召回了大量非结算相关的历史文档，导致检索负载过高。
- 关联知识库后问答响应变慢，表现为触发问答后等待时间显著长于未关联知识库的场景。原因是未配置数据集过滤规则，召回了全量内部数据集，且未限制`limit`参数的召回条数，增加了检索与重排的计算量。
- API调用报错，表现为返回401未授权状态码。原因是系统自动补充了Bearer令牌，与用户配置的认证信息冲突，导致认证失败。

## 怎么确认配好了
- 手动输入一条结算相关的测试问题，检查返回结果的匹配度是否符合`similarity`参数的阈值要求。
- 查看检索日志，确认仅召回了配置的`collectionIds`对应的数据集文档，无无关内部内容。
- 测试API调用，确认请求头未被自动补充额外的Bearer令牌，符合预期配置。
- 调整`limit`参数的取值，检查返回结果的条数是否符合设定的区间。
