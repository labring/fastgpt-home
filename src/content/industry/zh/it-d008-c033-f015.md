# 前端应用开发的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据通常来自代码仓库、接口管理平台、设计稿系统与浏览器兼容性数据库。日常产出的文档包含接口文档、组件使用说明、联调记录与发布清单。数据更新频率为每日或每版本迭代时。接口文档包含请求路径、响应状态码、参数说明；组件说明包含props定义、版本适配范围；联调记录标注调试时间、问题现象与修复方案；发布清单记录版本号、变更内容与上线时间。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据分散在多类平台的特性，要求检索环节需支持跨数据集召回，避免遗漏代码仓库、接口管理平台等来源的有效内容。高频更新的特性，要求召回逻辑支持增量同步配置，确保检索结果始终匹配最新的接口定义与组件版本。文档结构的多样性，要求分块策略适配不同格式的内容，既保留接口参数的结构化信息，也完整保留联调记录的上下文。浏览器兼容性数据的精准匹配需求，进一步约束了检索的相似度阈值与召回条数。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的知识库检索逻辑，适配前端应用开发的业务场景：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 适配前端文档的短文本与结构化字段匹配需求，避免召回无关的兼容性数据或旧版本内容 |
| `limit` | 前8条 | 平衡检索结果的丰富度与上下文窗口占用，适配前端联调记录与接口文档的批量检索需求 |
| `searchMode` | hybrid | 结合关键词匹配与语义检索，覆盖接口路径的关键词检索与组件说明的语义匹配场景 |
| `usingReRank` | 开启 | 对前端多来源的召回结果进行重排序，优先展示最新版本的组件文档与联调记录 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索query，补充接口参数的同义词与组件版本的关联关键词，提升召回覆盖度 |
| `collectionIds` | 按项目绑定的数据集ID | 精准限定检索范围，避免召回无关项目的前端文档数据 |

## 容易做错的三处
- 检索结果条数远低于预期，仅返回1-2条内容。原因是错误设置了`similarity`阈值过高，过滤掉了大量相关的联调记录与组件说明内容。
- 检索结果混杂了旧版本的组件文档与过时的接口定义。原因是未配置数据集的增量更新规则，且未开启`usingReRank`排序逻辑，导致旧数据权重高于新数据。
- 无法召回浏览器兼容性相关的精准内容。原因是未开启`datasetSearchUsingExtensionQuery`，未能自动补充机型与版本的关联检索词，导致匹配度不足。

## 怎么确认配好了
- 选取1个典型的前端开发问题，比如「如何调用用户信息接口」，执行检索后核对返回结果是否包含对应接口的路径与参数说明。
- 手动调整`similarity`阈值，观察检索结果的数量变化，确认阈值设置符合当前场景的匹配需求。
- 查看检索日志，确认是否触发了`datasetSearchUsingExtensionQuery`的扩展逻辑，是否补充了相关的同义词检索词。
- 验证跨数据集检索的配置，确认仅绑定了当前项目的`collectionIds`，未召回无关项目的文档内容。
