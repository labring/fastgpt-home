# 前端应用开发的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
这个品类的数据主要来自代码仓库、接口管理平台、设计稿系统与浏览器兼容性数据库。日常产出的文档包含接口文档、组件说明、联调记录与发布清单，数据字段涵盖接口请求路径、组件参数定义、兼容性适配版本、联调问题记录等。数据更新频率为每日或每版本发布周期，单条数据长度差异较大，接口文档片段多为数百字符，兼容性记录多为短条目。

## 这些特征在「重排与混合检索」这一环带来什么约束
前端开发的数据源分散且更新频繁，混合检索需同时召回代码片段、接口文档与兼容性数据，需适配多格式数据的向量对齐。短条目与长片段混合的结构，要求重排模型能区分不同数据类型的相关性权重。每日更新的特性要求检索链路支持增量召回，避免全量重扫导致的延迟。运维与工单场景下的检索需优先匹配联调问题、发布异常相关的内容，需通过重排调整召回结果的优先级，避免无关的通用组件文档干扰排查。

## 配置怎么定
本配置建议适用于FastGPT v4.17.0版本，具体如下表：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 重排开关 | 开启 | 前端多源异构数据需过滤低相关片段，重排可提升运维排查的精准度 |
| 相似度阈值 | 0.70–0.85 | 适配接口文档、代码片段的向量分布区间，避免遗漏联调相关的短条目数据 |
| 单次召回上限 | 前12条 | 适配运维值班场景的上下文长度，避免超出通用大模型的输入限制 |
| 搜索模式 | 混合检索 | 同时覆盖关键词匹配与向量相似度，可匹配接口路径、组件名等结构化字段 |
| 重排召回条数 | 前6条 | 优先展示最相关的联调记录与发布清单，缩短排查耗时 |

## 容易做错的三处
- 开启重排开关后检索结果顺序无变化：原因是未正确配置重排模型的API密钥或接入地址，或重排模型与FastGPT版本不兼容。
- 配置重排模型时无法勾选模型选项：原因是未在系统配置中提前录入重排模型的接入信息，或配置文件中未正确声明可用重排模型列表。
- 重排结果未按预期排序：原因是相似度阈值设置过高，过滤了部分潜在相关的短条目数据，导致重排输入样本不足。

## 怎么确认配好了
- 进入应用配置页面，确认重排开关处于开启状态，且已选择对应重排模型。
- 发起一条包含联调关键词的测试查询，查看检索结果的排序是否与预期一致。
- 查看系统日志，确认重排模型的调用请求已正常发送，无报错返回。
- 调整相似度阈值，观察检索结果的召回数量变化，验证配置生效。
