# 单元测试与组件测试的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
单元测试与组件测试的业务数据主要来自代码仓库、测试框架报告、需求说明与接口定义。日常产出的文档包含测试用例、覆盖率报告、Mock说明与缺陷单。数据更新频率为每日或每提交一次，测试数据构造、边界条件补齐与失败用例定位是该品类最耗时的环节。出错后可能导致局部逻辑缺陷漏测、回归成本上升或构建阻塞，其验证的是较小代码单元的独立逻辑，与集成测试存在核心差异。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据来源包含代码仓库与实时测试报告，部署环节需要对接代码仓库的权限配置，保障测试数据的拉取与同步。高频更新的特性要求升级流程支持增量部署与快速回滚，避免影响日常测试工作。测试用例、覆盖率报告等文档的存储需求，要求部署配置支持挂载专用存储服务。同时，该品类出错后果较为严重，部署与升级环节需要配置完善的权限校验与状态监控，保障测试流程的稳定性。

本文档适用于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–200 个连接` | 单元测试与组件测试的测试报告生成频繁，需要足够数据库连接支撑高频读写操作 |
| `REDIS_URL` | `本地 6379 端口` 或 `托管式 Redis 实例地址` | 用于缓存测试用例执行状态、临时测试数据，降低高频读取的数据库压力 |
| `STORAGE_S3_ENDPOINT` | `按存储服务商提供的标准端点配置` | 用于存储测试用例、覆盖率报告等业务文档，支持批量上传与下载操作 |
| `FILE_TOKEN_KEY` | `32 位随机字符串` | 保障测试文件上传下载的权限安全，避免未授权访问敏感测试文档 |
| `FE_DOMAIN` | `部署服务的公网或内网域名` | 用于生成可访问的测试报告链接，供运维值班人员与测试团队查看 |
| `ROOT_KEY` | `仅在初始化时配置的随机密钥` | 保障部署实例的初始管理权限安全，避免默认密钥导致的权限泄露 |

## 容易做错的三处
- Docker部署后容器启动失败，日志提示数据库连接超时。原因是未正确配置`MONGODB_URI`或`PG_URL`参数，未匹配测试环境的数据库地址与端口。
- 本地部署后无法解析上传的测试用例文件，日志提示文件权限错误。原因是未正确配置`FILE_TOKEN_KEY`参数，或挂载的存储目录权限不足，无法读取上传的测试文档。
- 云版本登录时仅支持微信扫码，无法使用账号密码登录。原因是未在部署配置中开启账号密码登录模式，或初始管理员账号未正确配置密码凭证。

## 怎么确认配好了
- 执行`docker ps`命令，确认所有部署的容器处于运行状态，无异常退出记录。
- 访问`FE_DOMAIN`配置的域名，登录系统后上传一份测试用例文件，确认文件可正常解析并生成预览链接。
- 执行单元测试脚本生成覆盖率报告，确认报告可正常上传至配置的存储服务，且`STORAGE_S3_ENDPOINT`参数生效。
- 查看数据库连接日志，确认`DB_MAX_LINK`参数配置的连接数未被耗尽，数据库连接正常且无超时报错。
