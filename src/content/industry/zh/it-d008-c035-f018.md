# 单元测试与组件测试的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
本品类的数据来自代码仓库、测试框架报告、需求说明与接口定义，更新频率为每日或每代码提交。日常使用的文档包括结构化测试用例、覆盖率统计报告、Mock接口说明、缺陷跟踪单，其中测试用例包含用例ID、前置条件、执行步骤、预期结果字段，覆盖率报告包含文件路径、覆盖情况、未覆盖分支信息，Mock说明包含接口地址、请求参数、返回格式字段，数据以纯文本或结构化JSON格式存储。

## 这些特征在「重排与混合检索」这一环带来什么约束
本品类的数据特征对重排与混合检索环节带来三点约束。第一，数据更新频率为每日或每提交，要求检索链路支持增量同步，避免检索到过期的测试用例或覆盖率报告。第二，数据包含结构化字段与非结构化文本，混合检索需同时匹配关键词与字段属性，例如匹配测试用例的执行步骤与缺陷单的复现步骤描述。第三，测试用例与缺陷单存在强关联关系，重排环节需优先关联度高的测试数据与工单内容，同时需适配不同文档的长度差异，避免长文档截断导致关键信息丢失。

## 配置怎么定
以下配置适用于FastGPT v4.17.0及以上版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | `0.72–0.85` | 匹配测试用例与缺陷单的语义相似度，避免过低引入无关结果，过高遗漏相关测试文档 |
| 单次返回上限 | 前10条 | 运维值班场景需快速定位问题，限制返回结果数量以减少阅读负担，同时覆盖主要相关数据 |
| 检索模式 | 混合检索 | 本品类数据包含结构化字段与非结构化文本，混合检索模式可同时匹配关键词与语义特征，适配多类型测试文档 |
| 启用重排 | 是 | 测试数据与工单的关联关系复杂，重排环节可基于语义关联度对检索结果进行二次排序，提升关键信息的展示优先级 |
| 重排召回数 | 前5条 | 重排环节需聚焦高关联度结果，限制重排处理的文档数量以降低链路耗时，适配运维值班的实时性要求 |
| 检索超时阈值 | 600秒 | 避免因测试文档过长或数据量过大导致检索超时，保障运维值班场景的响应速度 |

## 容易做错的三处
- 现象：重排功能开关设置为启用后，检索结果未进行二次排序，返回结果与初始检索结果一致。原因：未正确配置AI Proxy的环境变量，或AI Proxy服务未正常启动，导致重排模型无法调用。
- 现象：混合检索仅匹配关键词，未覆盖语义特征，检索结果包含大量无关的测试用例。原因：未将检索模式配置为混合检索，仅使用了关键词检索模式。
- 现象：在arm架构环境中部署后，重排功能无法正常运行，日志提示架构不兼容。原因：使用了仅支持amd架构的重排模型镜像，未选择适配arm架构的模型镜像或重新编译重排模型。

## 怎么确认配好了
- 查看FastGPT服务启动日志，确认未提示AI Proxy环境变量缺失或校验失败。
- 发起针对测试用例或缺陷单的检索请求，查看返回结果的排序逻辑，确认重排环节已生效。
- 检查检索结果的数量，确认符合配置的单次返回上限。
- 查看检索结果的匹配特征，确认混合检索模式同时匹配了关键词与语义信息。
