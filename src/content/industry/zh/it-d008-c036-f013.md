# 原型与交互设计的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据通常来自Figma或Axure文件、内部设计系统、用户反馈及可用性测试记录，日常产出交互原型、页面流程图、组件说明与评审记录。数据更新节奏为每周或每产品版本迭代一次，核心围绕页面结构、操作路径与交互细节展开，字段多包含原型版本号、组件属性、评审意见编号与测试场景标识，与需求分析类品类的差异在于不聚焦业务规则梳理，仅负责前端交互落地的文档沉淀。

## 这些特征在「权限与数据隔离」这一环带来什么约束
交互原型与评审记录通常包含未公开的页面路径、内部组件命名规则及未定稿的调整意见，按周或产品版本更新的特性要求隔离粒度需匹配迭代节奏，避免跨团队的未授权访问。不同前端小组的设计资产存在明确业务域差异，需按团队维度隔离数据，防止跨产品线的交互文档混淆。同时，评审记录包含内部反馈细节，需限制仅项目参与人员可见，避免未关联人员获取未公开的设计调整内容。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 团队隔离标识 | `teamId` 绑定前端小组ID | 匹配业务域归属，避免跨组设计文档混淆 |
| 租户隔离标识 | `tmbId` 绑定部署实例 | 确保本地部署的团队数据独立存储，不与其他租户共享 |
| 知识库访问范围 | 仅项目参与人员可见 | 匹配评审与设计的参与范围，防止未授权访问 |
| 模型调用密钥 | 每个团队绑定专属密钥 | 便于单独核算各团队的模型调用费用，符合商业版需求 |
| 知识库存储配额 | 1000 MB per team | 匹配小组的设计文档产出规模，避免存储溢出 |
| 会话上下文长度 | 4000 token | 匹配设计文档的平均字符长度，控制上下文成本 |
| 会话保留周期 | 7–14天 | 匹配产品版本迭代周期，避免过期数据占用存储 |

## 容易做错的三处
- 现象：本地部署后所有用户均可访问全部设计文档，无法按小组划分权限。原因：未正确绑定`teamId`与前端小组的组织架构，未开启租户级隔离配置。
- 现象：导出的训练文本包含其他产品线的交互原型内容。原因：未按`teamId`划分数据存储表，导致不同团队的设计文档被混合导入知识库。
- 现象：非项目参与人员可查看内部评审记录与未上线页面路径。原因：未配置知识库的项目组可见权限，将私有设计文档设置为全平台公开。

## 怎么确认配好了
- 登录不同团队的账号，验证仅能访问对应小组的设计文档知识库，无法查看其他团队的内容。
- 导出训练文本时，选择指定`teamId`的存储表，确认仅包含当前小组的交互原型与评审记录。
- 测试模型调用时，使用团队专属密钥发起请求，验证仅该团队的账号可使用绑定的模型。
- 查看会话列表，确认仅项目参与人员可查看对应交互设计相关的会话内容。
