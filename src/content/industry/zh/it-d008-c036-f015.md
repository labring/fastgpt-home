# 原型与交互设计的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
原型与交互设计的日常文档主要包含交互原型、页面流程图、组件说明与评审记录，数据来源多为Figma或Axure文件、内部设计系统、用户反馈与可用性测试记录。文档通常以章节为单位组织，每组包含章节标题、对应页面链接与功能简介，更新频率多为每周或每版本迭代时同步。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于文档以带关联关系的分组形式存在，检索时需保证同组的章节标题、链接与简介不被拆分召回，否则会导致运维人员无法获取完整的操作路径信息。原型文档更新频率较高，需适配增量更新的召回逻辑，避免重复或过期内容被匹配。同时，运维值班的问题多为口语化的操作路径询问，需优化查询以匹配原型的结构化字段，提升召回准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数逻辑：
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 相似度阈值 | `0.75–0.85` | 原型文档的语义关联度较高，过滤低匹配结果，避免无关评审记录被召回 |
| 单次召回上限 | `前 8 条` | 运维值班的问题通常对应1-2个核心原型页面，过多结果会干扰上下文理解 |
| 重排开关 | 开启 | 原型文档的片段关联性强，重排可优化结果排序，让更贴合查询的内容靠前展示 |
| 查询优化开关 | 开启 | 运维工单的问题多为口语化表述，优化查询后可更好匹配原型的章节标题与组件说明 |
| 集合ID过滤 | 指定对应设计知识库的集合ID | 隔离不同项目的原型文档，避免非当前项目的内容被误召回 |
| 文档结构匹配 | 开启 | 匹配原型的层级结构，保证同组的章节、链接与简介同时被关联召回 |

## 容易做错的三处
- 上传分组原型文档后，召回结果拆分了章节标题与对应页面链接。原因是未开启文档结构匹配配置，导致系统将分组内容作为独立片段分别召回，无法提供完整的操作路径信息。
- 检索结果中出现非当前项目的原型文档。原因是未配置集合ID过滤，系统召回了所有知识库内的文档，导致无关内容干扰查询。
- 发起运维工单查询后，返回大量低匹配的评审记录。原因是相似度阈值设置过低，未过滤与问题无关的文档片段。

## 怎么确认配好了
- 上传一组包含章节标题、页面链接与功能简介的原型文档，发起模拟运维查询，确认返回结果中同时包含该组的全部关联信息，未出现拆分情况。
- 查看检索日志，确认仅召回指定集合ID对应的文档，未出现其他项目的原型内容。
- 调整相似度阈值至低于0.75，验证低匹配的无关内容被过滤，再调回原阈值确认结果恢复正常。
- 关闭查询优化开关，发起口语化查询，对比开启开关后的结果，确认优化后匹配准确性提升。
