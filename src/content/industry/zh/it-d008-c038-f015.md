# 变更管理与发布窗口的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源于变更管理系统、CI流水线、监控数据与业务日历，更新频率为周度或每一次变更事件触发。日常产出的文档包含变更申请单、风险评估报告、上线窗口计划、回退方案，以及网段记录表等多列业务表格。文档字段包含变更编号、执行时段、风险等级、回退步骤、所属网段、维护人等，部分表格存在多列关联字段，单篇文档长度跨度较大，从数百字符的简短申请到数千字符的详细回退方案均有覆盖。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源数据的格式差异要求检索系统同时适配结构化表格与非结构化文本。周度或事件驱动的更新节奏，要求知识库同步机制具备准实时的更新能力。多列字段的业务文档，需要检索系统支持精准匹配特定字段内容，避免无关条目返回。长文本与短文本混合的文档结构，要求检索与召回环节兼顾短文本的快速匹配与长文本的有效召回，同时需处理长内容的排序优化问题，避免出现结果混乱的情况。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数规则制定：

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75-0.85 | 变更管理场景需精准匹配业务字段，过滤低匹配度的无关内容，保障检索结果的业务相关性 |
| `limit` | 前8-12条 | 运维值班场景需快速获取核心信息，过多条目会增加上下文处理负担，过少则无法覆盖全部相关文档 |
| `usingReRank` | 开启 | 变更文档存在长文本片段，重排模型可优化长内容的排序逻辑，解决长文本后未触发重排的问题 |
| `datasetSearchUsingExtensionQuery` | 开启 | 运维工单常包含模糊表述，扩展查询可匹配变更编号、网段等结构化字段，提升检索精准度 |
| `searchMode` | 混合检索 | 同时支持语义匹配与关键词匹配，适配多列表格与长文本文档的混合检索需求 |
| `collectionIds` | 指定对应变更管理知识库的数据集ID | 隔离其他业务场景的知识库内容，避免检索结果混入无关文档 |

## 容易做错的三处
- 现象：检索长文本回退方案时，未触发重排模型排序，结果排序混乱。原因：未开启`usingReRank`配置，或长文本超出重排模型的输入上限。
- 现象：上传网段记录表等多列Excel文档时，仅识别前两列内容。原因：未针对多列表格配置分块规则，默认分块逻辑仅识别基础列结构。
- 现象：提示词与引用模板的配置混淆，导致知识库引用内容格式错误。原因：未明确区分提示词的指令逻辑与引用模板的内容拼接逻辑。

## 怎么确认配好了
- 上传测试用的变更申请单与网段记录表，执行检索操作，检查返回结果是否包含所有列的字段内容，验证多列文档的分块与检索配置是否生效。
- 提交包含长文本回退方案的测试查询，查看检索结果是否触发重排模型，排序结果是否符合业务优先级逻辑。
- 对比提示词与引用模板的配置，确认引用模板仅处理知识库返回的内容片段，提示词负责指定检索规则与提取要求。
- 调整`similarity`阈值，提交测试查询，验证检索结果的匹配度是否符合运维场景的精准要求。
