# 售前技术方案的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
通常，该品类的数据来源于客户访谈、招标文件、厂商产品资料与历史项目方案。日常使用的文档包含技术方案书、客户需求调研表、报价清单与演示脚本，文档结构覆盖需求条目、技术路线、报价明细与演示步骤，部分字段带有项目编号、需求优先级、报价单位等标识。数据更新频率为每单或每周，单份文档的长度跨度较大，从数百字符的需求条目到数万字符的完整方案书不等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散导致文本表述风格差异明显，客户访谈的口语化内容与招标文件的官方表述容易出现语义偏差，需要检索模型适配多风格文本的匹配。更新频率较高且按单更新，要求检索系统支持增量式的知识库同步，避免全量重导带来的额外耗时。文档长度跨度大，短文本的需求条目与长文本的方案书需要适配不同的分块与召回策略。同时，售前方案的核心需求是匹配当前项目的边界与技术路线，需要避免召回无关的历史项目文档，严格限定检索范围。

## 配置怎么定
FastGPT v4.17.0版本下的配置项说明如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 适配售前方案的专业术语与多风格文本，过滤低相关的召回结果 |
| `limit` | 前8–12条 | 平衡召回覆盖范围与上下文窗口占用，避免过多长文本超出处理上限 |
| `usingReRank` | 开启 | 对初始召回结果进行二次排序，过滤语义相似但与当前项目无关的历史方案 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展检索词的语义范围，适配客户需求调研表中表述不直接匹配的检索场景 |
| `collectionIds` | 绑定售前方案专属知识库集合 | 限定检索范围，避免检索到其他品类的文档，提升精准度 |

## 容易做错的三处
- 检索时召回了非目标文档，比如提问某客户的需求条目，却返回了其他项目的方案。原因是未配置`collectionIds`限定检索范围，导致检索覆盖了全量知识库。
- 线上部署的售前方案知识库导入后出现乱码，本地部署则正常。原因是线上环境的字符编码未设置为UTF-8，导致厂商产品资料中的特殊字符无法正常解析。
- 界面展示了知识库搜索结果模块，无法隐藏。原因是未关闭前端的知识库搜索展示开关，或未在系统配置中隐藏检索入口。

## 怎么确认配好了
- 检查知识库集合的绑定ID，确认仅包含售前方案相关的技术方案书、需求调研表、报价清单与演示脚本。
- 发起测试提问，输入某客户需求调研表中的具体条目，验证召回结果仅包含与该条目直接相关的文档。
- 查看初始召回结果的相似度得分，确认得分处于`similarity`预设的阈值区间内。
- 上传一份新的报价清单，验证知识库能在10分钟内完成增量更新并支持检索。
