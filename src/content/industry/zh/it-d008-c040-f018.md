# 售前技术方案的运维值班与内部工单问答：重排与混合检索

本页适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
这个品类的数据主要来自客户访谈、招标文件、厂商产品资料与历史项目方案，更新节奏为每单或每周。日常产出的文档包含技术方案书、客户需求调研表、报价清单与演示脚本，其中技术方案书会按技术路线、实施边界、报价配置等模块划分结构，报价清单包含单项服务金额与总报价字段，需求调研表记录客户的功能与预算要求。

## 这些特征在「重排与混合检索」这一环带来什么约束
由于数据来源包含招投标相关文档，内容需严格匹配客户需求边界，混合检索时需优先召回与当前售前需求匹配的历史方案与厂商资料。更新频率为单次项目周期内高频调整，检索结果需覆盖最新的厂商产品参数与客户最新需求。日常文档结构差异较大，技术方案书的长文本与报价清单的结构化数据需分别适配检索逻辑，避免非相关内容干扰核心匹配结果，同时需保证检索结果能直接支撑方案边界设计与报价核对环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `usingReRank` | 开启 | 售前方案需严格匹配需求边界，重排可过滤低相关的历史方案与厂商资料 |
| `similarity` | 0.72–0.85 | 适配招投标文档的严谨匹配要求，避免召回无关的非售前类内容 |
| `limit` | 前10条 | 平衡检索覆盖范围与结果处理效率，适配单售前项目的文档体量 |
| `searchMode` | hybrid | 结合关键词检索与语义检索，适配结构化与非结构化混合的售前文档类型 |
| 重排模型调用超时阈值 | 15 秒 | 避免因模型响应延迟影响售前方案的快速生成与核对 |

## 容易做错的三处
- 重排模型测试返回401未授权错误。未正确配置重排模型的API密钥，或密钥权限未覆盖重排模型调用范围。
- 未开启重排功能时检索结果的相关度指标无明确参考价值。基础语义检索仅基于文本语义匹配，未结合查询意图做针对性排序，无法过滤与当前售前需求无关的冗余内容。
- 混合检索返回的结果条数超出预期范围。未正确设置`limit`参数的取值，导致过多低相关文档被召回，增加售前方案边界设计的核对成本。

## 怎么确认配好了
- 进入FastGPT的检索配置页面，确认`usingReRank`开关处于开启状态。
- 提交一条售前需求相关的测试查询，查看返回结果的排序是否优先匹配当前售前方案的核心需求。
- 检查重排模型的调用日志，确认无401未授权错误或超时报错。
- 调整`similarity`参数的取值，验证检索结果的召回范围是否随参数变化合理调整。
