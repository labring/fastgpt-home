# 安全事件应急响应的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来源为SIEM、EDR、防火墙日志与主机镜像，更新节奏为实时或每事件触发。日常产出的文档包含应急响应报告、取证记录、处置方案与通报材料，单份文档包含攻击链路细节、处置步骤、证据哈希值、事件等级字段，无统一固定长度，随事件复杂度变化。数据以结构化日志片段与非结构化文档混合形式存在，字段多包含时间戳、事件ID、关联资产信息，部分字段需按事件维度关联聚合。数据上传后生成的索引用于快速定位向量与结构化字段，向量数据库存储的向量特征用于语义匹配，检索时结合索引与向量特征完成召回。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据混合结构化与非结构化形式，且随事件实时更新，要求检索需同时支持结构化字段匹配与向量召回。事件数据关联资产、时间戳等强关联字段，需限定检索范围为当前事件关联的数据集，避免无关结果干扰。单份文档长度差异大，需适配不同长度的内容拆分与召回逻辑。实时更新的特性要求检索索引同步频率匹配事件处理节奏，避免索引滞后导致无法召回最新处置方案。运维值班场景下需快速返回结果，约束检索耗时需控制在合理区间，避免影响应急响应进度。内部工单问答需关联具体事件的上下文，要求检索结果需携带事件ID与关联资产信息，便于工程师快速定位工单对应事件。

## 配置怎么定
本文基于FastGPT v4.17.0版本配置说明。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配安全事件处置方案的语义匹配精度，避免过低导致无关结果，过高遗漏有效处置步骤 |
| `limit` | 前10条 | 平衡检索效率与信息完整性，满足运维值班时快速获取核心处置信息的需求 |
| `searchMode` | hybrid | 同时支持向量召回与结构化字段匹配，适配混合格式的安全事件数据 |
| `usingReRank` | 开启 | 对召回结果重排，优先返回攻击路径还原相关的高相关性内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题扩展检索词，覆盖安全领域专业术语的同义匹配 |
| `collectionIds` | 按事件关联资产指定 | 限定检索范围为当前工单关联的安全数据集，避免跨事件数据干扰 |

## 容易做错的三处
- 现象：检索结果为空，且工具调用返回空响应；原因：未正确配置`datasetSearchUsingExtensionQuery`参数，同时未限定检索范围为本地安全数据集，导致无法召回本地应急处置数据。
- 现象：检索结果包含非本地知识库的外网内容；原因：未关闭全局联网检索开关，导致扩展查询触发外部数据源，引发数据泄露风险。
- 现象：检索结果匹配度过高但未命中有效处置步骤；原因：`similarity`阈值设置过高，过滤了语义相近但细节有差异的取证记录，影响攻击路径还原的完整性。

## 怎么确认配好了
- 上传一份历史应急响应报告，输入对应事件的问题，核对返回结果是否包含该报告的处置步骤与取证记录。
- 查看检索日志，确认仅调用本地安全数据集，无外部联网请求，验证数据未泄露至外网。
- 调整`similarity`参数，观察召回结果的相关性变化，验证参数配置生效。
- 触发实时更新的事件数据，确认检索结果可同步包含最新的处置方案与通报材料。
