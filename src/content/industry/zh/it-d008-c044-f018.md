# 安全产品规则运营的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
这个品类的数据主要来自WAF、IDS、防火墙及威胁情报平台，日常文档包含规则变更单、拦截日志、误报分析报告、策略回滚记录。数据更新节奏为每日或随安全事件触发，字段包含规则ID、拦截阈值、误报率、业务关联域、变更时间等，不同来源的文档结构存在差异，无统一固定格式。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据来源分散且更新频繁，要求重排与混合检索需同时覆盖多源日志、报告及工单数据，避免遗漏关键安全事件信息。不同文档的结构差异较大，需适配不同字段的语义权重，确保误报分析、规则变更等核心内容的检索相关性。运维值班场景下需快速响应，重排环节不能增加过多耗时，同时出错后果严重，需保证重排结果的准确性，避免正常业务被误拦或攻击被漏过。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 重排开关 | 开启 | 安全产品规则数据误报率较高，重排可过滤低相关的拦截日志或规则记录，提升检索精准度 |
| 相似度阈值 | 0.75–0.85 | 匹配规则变更单、拦截日志的语义关联，避免遗漏关键策略变更或误报分析内容 |
| 召回结果上限 | 前10条 | 运维值班场景下需快速浏览核心结果，过多条目会增加分析负担，影响值班响应效率 |
| 检索模式 | 混合检索 | 需同时覆盖WAF/IDS日志、威胁情报、历史工单数据，单一检索模式无法满足全数据源检索需求 |
| 重排后显存释放 | 检索完成后自动卸载 | 避免检索后重排模型持续占用显存，影响其他安全工具的运行资源 |

## 容易做错的三处
- 现象：知识库启用结果重排后界面显示红色异常叉号，无法正常启用。原因：未正确配置Reranker模型的访问凭证，或凭证权限不足无法调用模型。
- 现象：重排模型调用成功但检索结果未发生预期排序变化。原因：未正确开启重排开关，或相似度阈值设置超出合理区间，导致重排逻辑未触发或过滤规则过严/过松。
- 现象：检索流程完成后重排模型持续占用显存未释放。原因：未配置检索完成后自动卸载重排模型的参数，导致显存资源被长时间占用。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库设置页面，查看重排开关状态为开启，无红色异常标记。
- 提交一条包含规则变更关键词的测试查询，对比初始检索结果与重排后的结果，确认排序逻辑符合业务相关性要求。
- 执行一次完整的检索重排流程，通过系统监控查看重排模型的显存占用在检索完成后是否自动释放。
- 核对配置的相似度阈值与业务场景匹配度，可通过多次测试调整后确认结果合理性。
