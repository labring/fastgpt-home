# 安全培训与钓鱼演练的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
该品类的核心数据包含培训课件、演练方案、钓鱼邮件模板、演练结果报告四类，数据来源通常为员工通讯录、企业邮件网关、内部培训平台与用户点击统计系统。数据更新节奏多为季度或年度，单份文档结构包含场景分类、操作步骤、风险等级、统计结果等字段，无统一固定单位，部分文档附带用户行为数据标签。

## 这些特征在「权限与数据隔离」这一环带来什么约束
员工通讯录数据包含隐私信息，需限制仅安全运营团队可访问完整数据集。钓鱼邮件模板属于高风险内容，需按岗位层级划分访问权限，避免非授权人员获取敏感演练素材。演练结果报告涉及内部审计依据，需保留不同角色的访问日志。数据更新频率较低，权限规则无需高频调整，但需确保历史版本的权限配置同步生效。不同文档类型的敏感程度差异较大，需针对课件、模板、报告分别设置差异化权限粒度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，具体参数可根据实际业务调整：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `teamId` | 绑定对应业务团队的ID，取值区间1-5000 | 实现跨团队的知识库与会话数据物理隔离 |
| 角色权限组 | 按岗位划分，如安全运营岗、内训岗、实习生岗 | 匹配该品类的岗位权限差异需求 |
| 文档访问粒度 | 按文档类型设置，如钓鱼模板仅安全组可访问 | 适配不同文档的敏感等级 |
| 会话有效期 | 1800 秒 | 控制未授权会话的访问时长 |
| 数据存储路径 | 按分类划分，如/training、/phishing-template、/report | 实现按文档类型的存储隔离 |

## 容易做错的三处
- 现象：测试调用本地部署模型时返回权限错误，界面提示“无访问权限”。原因：未通过`teamId`绑定模型部署的团队ID，导致跨团队调用模型资源失败。
- 现象：实习生账号可查看钓鱼邮件模板文档。原因：未按文档敏感程度设置差异化访问粒度，将高风险文档的权限设置为全员可见。
- 现象：团队内部分成员无法查看专属的演练结果报告。原因：未配置基于用户所属部门的权限过滤规则，导致数据访问范围错误。

## 怎么确认配好了
- 登录不同角色的账号，验证是否仅可访问对应权限范围内的文档。
- 查看会话日志，确认仅授权用户可发起与安全培训相关的会话请求。
- 检查`teamId`配置项是否与当前业务团队的ID一致，确保数据隔离生效。
- 验证高敏感文档（如钓鱼邮件模板）是否仅可被指定角色访问。
