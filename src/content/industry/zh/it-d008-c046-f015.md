# 安全基线检查的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源于服务器配置、中间件配置、安全设备策略及基线工具输出结果。日常关联文档包含基线检查表、配置核查记录、整改建议与例外审批单，字段涵盖配置项标识、合规校验结果、整改要求及例外审批状态。数据更新频率为月度或季度，单份文档包含大量独立配置项，且不同业务环境的配置项存在差异。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据多源异构，且单份文档包含大量独立配置项，会导致检索时的上下文冗余。数据更新周期为月度或季度，要求知识库检索环节支持周期性增量同步，避免全量重扫带来的资源消耗。例外审批单等非标准化文档的存在，要求检索需兼顾精确匹配配置项与模糊匹配例外原因。同时，不同环境的配置项存在差异，需确保检索范围可按业务场景划分，避免跨环境的无效匹配。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本调整：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 适配安全基线配置项的精确匹配需求，过滤低相关性的配置校验结果 |
| `limit` | 前8–12条 | 控制单次召回的配置项数量，避免上下文过载，符合运维人员快速定位问题的习惯 |
| `searchMode` | 向量搜索+关键词混合 | 兼顾配置项的精确关键词匹配与语义关联的向量召回，适配多源异构的基线数据 |
| `usingReRank` | 开启 | 对召回结果重新排序，提升高匹配度配置项的展示优先级，减少人工筛选成本 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户提问自动生成扩展查询词，覆盖配置项的别名、行业通用表述，适配运维人员的口语化提问 |
| `collectionIds` | 按业务环境分组配置 | 隔离不同服务器、中间件环境的基线知识库，避免跨环境的无效召回 |

## 容易做错的三处
- 输出结果中包含「引用标记：［1］」字样。原因是未关闭知识库检索结果的引用标注开关，导致检索匹配的文档标识被直接拼接进生成内容。
- 检索结果的颗粒度不符合业务需求。原因是未针对基线检查表的单条配置项设置合理的分块规则，导致大段冗余内容被召回，或有效配置项被拆分过度。
- 检索结果与当前运维环境不匹配。原因是未按业务环境配置`collectionIds`参数，导致跨环境的基线数据被错误召回。

## 怎么确认配好了
- 发起一条包含具体配置项名称的提问，核对召回结果的匹配度是否符合预期。
- 查看检索结果的排序，确认重排功能是否生效，高匹配度的配置项是否优先展示。
- 切换不同的业务环境分组，确认仅当前环境的基线知识库数据被召回。
- 检查生成内容，确认未出现引用标记类的冗余字样。
