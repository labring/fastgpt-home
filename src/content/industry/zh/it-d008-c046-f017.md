# 安全基线检查的运维值班与内部工单问答：部署与升级

本页面适配FastGPT v4.17.0版本

## 这个品类的数据长什么样
安全基线检查的数据来源于服务器配置、中间件配置、安全设备策略及基线工具的输出内容，日常产出基线检查表、配置核查记录、整改建议、例外审批单四类核心文档。文档字段包含配置项名称、合规状态、整改建议、例外审批意见等结构化内容，更新周期为月度或季度。该品类聚焦配置是否符合组织安全基准，区别于漏洞扫描服务的漏洞检测逻辑，核心数据围绕配置合规性展开。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据来源分散且需对接多类配置源，部署阶段需配置兼容多种配置导出格式的导入模块，支持从服务器、中间件、安全设备同步配置数据。由于更新周期为月度或季度，升级时需保证历史核查记录与新基线模板的字段兼容性，避免存量数据失效。由于核心文档包含固定字段，部署时需预设匹配基线检查表格式的结构化存储字段。由于合规核查需关联例外审批流程，升级时需集成内部工单系统的审批状态同步接口，确保数据链路完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `DB_MAX_LINK` | `100–200` | 适配多台服务器的配置数据并发读取需求，避免连接池耗尽 |
| `MONGODB_URI` | `mongodb://[username]:[password]@host:port/database?authSource=admin` | 存储基线核查记录、例外审批单等结构化文档，支持灵活的字段查询 |
| `REDIS_URL` | `redis://:[password]@host:port` | 缓存高频访问的基线模板与配置比对结果，降低数据库查询压力 |
| `FE_DOMAIN` | `https://your-baseline-check-domain.com` | 配置前端访问域名，用于生成工单跳转链接与合规报告的访问入口 |
| `FILE_TOKEN_KEY` | `随机生成的32位字符串` | 加密存储上传的基线检查表附件，防止未授权访问 |
| `STORAGE_S3_ENDPOINT` | 按实测标定 | 适配企业自建对象存储或云存储服务，用于存储基线检查表的附件与整改凭证 |

## 容易做错的三处
- 现象：Linux环境部署后无法加载基线配置数据，界面返回`502 Bad Gateway`，原因：未正确配置`DB_MAX_LINK`的连接数上限，导致数据库连接池耗尽，无法处理并发的配置读取请求。
- 现象：使用zilliz版本部署时出现网络访问报错，无法同步安全设备策略数据，原因：未在`MONGODB_URI`或`STORAGE_S3_ENDPOINT`的配置中添加代理参数，导致跨网段访问失败。
- 现象：在阿里云DSW环境中部署时，Docker容器启动失败，无法加载基线检查服务，原因：未开放Docker所需的端口权限，或未配置正确的镜像拉取地址，导致依赖组件无法下载。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`与`PG_URL`的配置是否能正常读取基线核查记录。
- 上传一份测试基线检查表，验证`FILE_TOKEN_KEY`的加密逻辑是否正常，附件能否正常下载。
- 发起一条内部工单，验证工单状态能否同步至基线检查系统，例外审批流程是否正常触发。
- 访问`FE_DOMAIN`对应的前端地址，验证界面能否正常加载基线模板与合规报告。
