# 安全漏洞披露处理的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
本品类的数据来自私密漏洞报告、代码仓库、CVE编号机构及官方发布渠道。日常文档包含安全公告、漏洞报告、修复补丁、CVE申请材料。数据更新以单次漏洞事件为节奏，无固定周期。核心字段包括漏洞编号、影响范围、修复状态、披露时间、补丁链接，无统一固定单位，随文档类型变化。

## 这些特征在「部署与升级」这一环带来什么约束
私密漏洞报告的非公开属性要求部署时需对敏感数据进行隔离存储，避免未授权访问；多源数据接入需适配不同接口格式，升级时需兼容旧有数据同步逻辑，避免历史漏洞数据丢失；单次事件驱动的更新节奏无需固定定时任务，但需支持手动触发与事件监听，适配漏洞披露的突发特性；字段随文档变化的特性要求配置项需支持自定义字段映射，避免硬编码字段名导致的兼容性问题；漏洞处理的高风险属性要求部署时需开启全链路审计日志，便于追溯操作与问题排查。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt_vuln` | 存储漏洞报告、补丁记录等结构化数据，需指定专属数据库实例 |
| `REDIS_URL` | `redis://:password@host:6379/1` | 缓存临时漏洞评估结果与工单会话，端口默认6379，选第1库隔离业务数据 |
| `DB_MAX_LINK` | `20–30` | 适配多源数据同步的并发连接数，避免数据库连接耗尽 |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` | 存储补丁包、漏洞报告附件，需匹配部署环境的对象存储服务地址 |
| `ROOT_KEY` | `随机32位字符串` | 配置平台超级管理员权限，避免默认密钥泄露风险 |
| `FE_DOMAIN` | `https://vuln-handle.your-domain.com` | 指定前端访问域名，用于生成漏洞披露通知的跳转链接 |

## 容易做错的三处
- 启动后OneAPI连接报错，提示连接超时或认证失败。原因是未正确配置`REDIS_URL`或`MONGODB_URI`的认证参数，导致依赖服务无法连通。
- 漏洞附件无法正常上传，前端显示文件解析失败。原因是未正确配置`STORAGE_S3_ENDPOINT`或存储服务的权限未开放，导致文件存储链路中断。
- 工单会话无法正常保存，刷新后数据丢失。原因是`DB_MAX_LINK`取值过低，数据库连接池耗尽，无法写入会话数据。

## 怎么确认配好了
- 访问配置的前端域名，验证页面能否正常加载，检查浏览器控制台是否有配置项相关的报错信息。
- 执行本地数据同步脚本，导入测试用的漏洞报告数据，验证能否成功写入指定的数据库实例。
- 上传测试用的补丁附件，验证是否能正常存储并生成可访问的链接。
- 调用超级管理员接口，使用配置的`ROOT_KEY`验证权限，确认能否正常获取管理员操作权限。
