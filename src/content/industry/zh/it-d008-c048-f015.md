# 安全监控与SOC值守的运维值班与内部工单问答：知识库检索与召回

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类数据主要来自SIEM、EDR、NDR及威胁情报源，日常文档包含告警处置单、值班记录、威胁情报通报、日报周报。数据更新节奏分为实时与日更两类，其中实时告警数据由安全设备同步生成，日报周报等周期性文档按自然日更新。告警处置单包含告警触发时间、源IP、处置流程、误报标记字段；值班记录包含值守时段、告警处理进度字段；威胁情报通报包含IOC值、威胁类型字段，无额外自定义单位字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据异构性强，包含结构化设备日志、半结构化工单文档与非结构化情报通报，要求检索环节适配多格式内容的匹配逻辑。实时更新的告警数据要求召回链路支持近实时同步，避免因数据滞后导致告警研判偏差。文档字段聚焦告警ID、威胁等级、处置步骤等运维相关内容，检索需优先匹配与当前告警强相关的处置规则，同时需控制召回延迟，防止影响值班响应效率。另外，误报排除与升级派单依赖精准召回结果，召回结果的相关性不足会直接加剧误报堆积或真实攻击漏报。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 过滤低相关性的告警记录，避免误报干扰研判流程 |
| `limit` | 前8–12条 | 适配SOC分析师的单次研判窗口，减少无效信息阅读量 |
| `searchMode` | 混合检索 | 兼顾结构化设备日志的关键词匹配与非结构化情报的语义关联 |
| `usingReRank` | 开启 | 提升高相关性处置文档的排序优先级，优化研判效率 |
| `datasetSearchUsingExtensionQuery` | 开启 | 覆盖行业专属术语与自定义缩写，提升告警描述的检索匹配度 |
| `collectionIds` | 按SIEM、EDR、威胁情报源分组配置 | 限定检索范围，排除无关数据源的文档干扰 |

## 容易做错的三处
- 现象为检索时返回「数据库连接超时」报错，原因是未针对实时告警数据调整`limit`参数，召回过多文档导致检索链路超时。
- 现象为检索结果混杂大量非告警类文档，原因是未配置`collectionIds`限定检索集合，导致跨业务数据源的文档被召回。
- 现象为检索返回的处置步骤与当前告警类型不匹配，原因是未开启`datasetSearchUsingExtensionQuery`，无法覆盖告警描述中的行业术语与自定义缩写。

## 怎么确认配好了
- 导入单条标准告警测试数据，执行检索后核对返回结果的相关性，调整`similarity`参数直至符合研判需求。
- 查看检索日志，确认召回的文档均来自预设的SIEM、EDR等数据源，验证`collectionIds`配置生效。
- 模拟高频检索请求，检查检索延迟是否符合值班响应的时间要求，调整`limit`参数控制返回条数。
- 输入包含行业缩写的告警描述，核对检索结果是否覆盖对应术语的相关文档，验证`datasetSearchUsingExtensionQuery`的配置效果。
