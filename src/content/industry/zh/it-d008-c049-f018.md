# 客户培训与使用手册的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来自产品帮助中心、客户组织架构、培训录屏、工单系统四类来源，更新频率为每单或每版本。文档形态包含培训课件、用户手册、培训签到表、问题答疑清单，其中用户手册多为结构化操作步骤，培训录屏转写后为非结构化长文本，工单系统数据多为短文本的具体问题与回复。数据字段包含角色权限说明、操作流程节点、问题分类标签等，无统一固定的单位格式。

## 这些特征在「重排与混合检索」这一环带来什么约束
品类数据的多源混合特性要求检索环节同时覆盖结构化手册内容与非结构化录屏、工单数据，因此需要混合检索模式适配不同形态的文本。高频更新的工单数据要求检索结果具备实时性，避免返回过时的培训内容。角色权限字段的存在要求检索结果需匹配对应角色的可见范围，同时长文本的培训课件与短文本的工单回复语义差异较大，需要重排环节调整相关性权重，避免短文本工单内容挤占核心手册的展示位置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `usingReRank` | 开启 | 品类数据包含长文本课件与短文本工单，重排环节可修正初始检索的语义偏差，提升核心手册内容的排序优先级 |
| `limit` | 前10条 | 适配运维值班的快速响应需求，避免过多结果导致检索耗时过长 |
| `searchMode` | 混合检索模式 | 适配多源数据的形态差异，同时召回帮助中心、工单系统等不同来源的内容 |
| `similarity` | 0.75-0.85 | 平衡检索的召回率与准确率，适配多源数据的语义差异，避免漏检核心内容或返回无关结果 |
| 重排模型显存阈值 | 总显存的60%（按实测标定） | 避免重排模型占用过多显存导致系统卡顿，适配FastGPT v4.17.0的资源调度规则 |

## 容易做错的三处
- 现象：rerank模型调用后显存持续占用不释放，系统提示内存不足。原因：未配置FastGPT v4.17.0的自动显存回收策略，重排模型加载的临时参数未被正确释放。
- 现象：混合检索结果中工单数据占比过高，核心用户手册内容未排在前列。原因：未调整多源数据的检索权重，默认配置偏向短文本的工单数据，未适配品类的业务优先级。
- 现象：配置`similarity`参数后测试检索提示错误。原因：误将参数设置为超出0-1区间的数值，不符合FastGPT的参数校验规则。

## 怎么确认配好了
- 进入FastGPT知识库的检索配置页面，确认`usingReRank`开关处于开启状态，`searchMode`设置为混合检索模式。
- 提交一条运维值班常见的角色权限问题，查看检索结果的排序，确认核心用户手册内容排在前3条。
- 查看检索返回的结果条数，确认与`limit`参数设置的数值一致，无额外或缺失的结果。
- 运行10分钟后查看系统显存占用，确认重排模型的临时显存已正常释放，无持续占用情况。
