# 客户数据导入迁移的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据主要来自客户历史系统、CSV或Excel模板、数据库导出以及产品导入日志，由实施顾问、数据实施工程师、客户IT接口人日常维护。日常产出的文档包括数据模板、迁移方案、字段映射表、迁移验证报告，数据更新节奏为每单或不定期，单份数据包含字段映射规则、批量导入参数、脏数据清洗标准等内容，无固定统一单位，随客户业务场景调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且格式多样，要求知识库检索需兼容多格式数据源的字段匹配逻辑，避免跨系统字段错位。单份数据更新无固定周期，需支持增量召回与全量刷新的灵活切换。日常文档结构固定但字段逻辑复杂，需精准召回对应字段映射表、迁移方案等关联文档，防止检索结果与当前工单场景不匹配。批量导入的日志数据量随工单规模波动，需适配不同并发下的检索响应约束。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的知识库功能制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.72–0.85` | 匹配字段映射表、迁移方案这类专业文档，避免过低召回无关内容或过高遗漏有效信息，按实测标定区间 |
| `limit` | `前 6 条` | 单工单关联的文档数量通常有限，控制返回条数避免上下文过载 |
| `searchMode` | `embedding` | 适配字段映射表等结构化文档的语义匹配需求，优先召回语义关联的迁移类文档 |
| `usingReRank` | `开启` | 对批量导入日志、字段映射表这类长文本文档，重排可优化高相关结果的排序优先级 |
| `datasetSearchUsingExtensionQuery` | `开启` | 补充匹配用户工单中提到的客户系统名称、字段名等扩展关键词，提升检索精准度 |
| `collectionIds` | `指定客户数据导入迁移专属集合` | 隔离业务场景，避免召回其他品类的文档干扰检索结果 |

## 容易做错的三处
- 现象：检索结果返回非客户数据导入迁移类的文档，原因：未指定`collectionIds`参数，导致检索范围覆盖全平台知识库。
- 现象：上传的字段映射表、迁移方案等关联文档被拆分为多个独立条目，无法作为整体匹配用户工单，原因：未正确配置关联分组参数，或分块逻辑未保留文档的结构关联。
- 现象：调用知识库接口创建训练订单后，检索召回结果未包含预期的导入日志数据，原因：`trainingType`取值未匹配纯文本业务文档的类型要求，或`similarity`阈值设置过高导致有效文档未被召回。

## 怎么确认配好了
- 手动输入一条字段映射相关的测试问题，核对返回结果是否仅包含客户数据导入迁移类文档。
- 上传一组带章节标题、链接的测试文档，验证是否作为整体被召回，未被拆分。
- 模拟多工单并发提交检索请求，确认检索响应无明显延迟，并发承载符合业务预期。
- 调用知识库接口创建训练订单，检查返回的订单状态是否正常，且关联文档的参数配置符合要求。
