# 客户数据导入迁移的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来自客户历史系统、CSV或Excel模板、数据库导出文件以及产品导入日志，更新节奏为每单或不定期。日常关联文档包含数据导入模板、迁移执行方案、字段映射对照表、迁移验证报告等，服务主体为实施顾问、数据实施工程师与客户IT接口人。数据包含业务字段、映射规则、导入校验结果等内容，无统一固定单位，需结合客户原有系统字段与导入模板要求确定。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据来源多样且格式不统一，混合检索时需适配CSV、数据库导出等不同格式的数据源字段结构，避免检索结果出现字段错位。数据更新无固定周期，需支持动态匹配最新的迁移方案、导入日志与验证报告，确保检索结果覆盖最新配置。日常文档分散在模板、映射表、报告中，重排环节需整合关联内容，优先展示与当前工单相关的字段映射规则与异常记录，适配运维值班时快速定位问题的需求。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 过滤与当前工单无关的迁移日志与映射内容，适配导入数据的字段匹配精度要求 |
| 单次检索上限 | 前10条 | 限制单次检索返回结果数量，避免运维值班时过载，符合工单问答的快速定位需求 |
| 搜索模式 | 混合检索 | 整合向量检索与关键词检索，适配多样的数据源格式 |
| 重排开关 | 开启 | 对初始检索结果按字段匹配度、异常等级重排，优先展示高风险的字段错位、数据丢失记录 |
| 检索数据源范围 | 迁移日志、字段映射表、导入模板 | 限定检索范围为该品类专属文档，避免无关内容干扰检索结果 |

## 容易做错的三处
- 现象为结果重排开关显示为false，检索结果未按优先级排序。原因是未正确关联重排模型与检索任务，或重排配置未绑定至当前导入迁移的工单场景。
- 现象为Http请求后的多变量无法对应指定知识库，检索结果混杂不同客户的迁移数据。原因是未为每个变量配置独立的检索数据源范围，导致跨客户数据混淆。
- 现象为arm架构系统中重排功能无法正常加载，检索结果无重排逻辑。原因是使用了仅支持amd架构的重排模型镜像，未适配系统架构。

## 怎么确认配好了
- 查看检索配置界面，确认相似度阈值、单次检索上限、搜索模式与重排开关的设置与预期一致。
- 提交一条测试工单，检索关联的迁移日志与映射表，核对结果是否按优先级排序。
- 检查检索数据源范围是否限定为该品类专属的模板、映射表与日志文档，排除无关内容干扰。
- 查看系统日志，确认重排模型已正常加载，无架构不兼容或配置错误提示。
