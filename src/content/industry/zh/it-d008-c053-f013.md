# 客户需求池管理的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据主要来自工单系统、客户访谈记录、CRM系统及产品路线图文档，更新频率为每周或每产品版本发布时。日常维护的文档包含需求池清单、需求评估表、客户反馈记录与版本规划说明，数据字段通常包含需求编号、关联客户标识、需求内容、优先级评分、排期状态等，无统一的行业标准字段，仅随业务团队的筛选排序规则调整。

## 这些特征在「权限与数据隔离」这一环带来什么约束
由于该品类数据来源分散且包含客户敏感信息，不同角色的访问范围需严格区分。运维值班人员仅可查看与内部工单关联的需求池数据，客户成功团队需仅访问对应负责客户的反馈记录，产品经理则可查看全量需求评估与规划文档。数据按周或版本更新的特性，要求权限变更需同步更新数据访问范围，避免过期权限导致的信息泄露或需求排期混乱。多类型文档的混合存储，也要求针对不同文档模板设置差异化的隔离规则，防止非授权角色接触高敏感的客户反馈或版本规划内容。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 团队数据隔离配置 | 按`teamId`划分独立数据空间 | 匹配需求池数据按客户或业务团队分组的存储逻辑 |
| 角色权限绑定 | 为`teamId`与`tmbId`绑定对应角色的访问权限 | 区分运维值班、客户成功、产品经理的不同职责范围 |
| 敏感文档隔离 | 将客户反馈记录设置为仅对应团队可访问 | 防止非授权角色接触客户敏感信息 |
| 权限同步时效 | 数据更新后12小时内同步权限规则 | 匹配每周/每版本的需求池更新频率 |
| 访问日志留存 | 留存90天的权限操作与数据访问日志 | 便于排查需求承诺失真或排期混乱的问题 |

## 容易做错的三处
- 现象：团队邀请成员后，受邀成员未收到权限开通提示，无法访问指定需求池数据。原因：未同步完成`teamId`与成员角色的绑定配置，导致权限未生效。
- 现象：运维值班人员可查看全量客户反馈记录，超出职责范围。原因：未针对运维场景设置独立的`teamId`隔离空间，误将全量数据权限开放给运维角色。
- 现象：调用绑定需求池的自定义插件时返回空结果。原因：未在插件配置中指定正确的`teamId`参数，无法匹配对应的数据空间。

## 怎么确认配好了
- 登录不同角色的测试账号，验证是否仅能访问对应职责范围内的需求池文档与数据。
- 发起团队成员邀请，确认受邀成员可收到权限配置相关的系统提示。
- 调用绑定需求池的自定义插件，传入指定`teamId`参数，验证是否能返回对应的数据结果。
- 查看权限操作日志，确认最近的权限变更已按配置的时效同步生效。
