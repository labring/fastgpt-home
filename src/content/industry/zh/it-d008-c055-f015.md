# 容量规划与资源扩缩容的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据主要来自云账单、监控系统、业务预测报告与压测结果。日常产出的文档包含容量规划报告、扩容申请单、资源利用率报表与预算测算表。数据更新周期多为周或月，单份文档包含服务器型号、资源配置参数、预估峰值负载、采购预算等字段，字段单位涵盖CPU核数、存储容量、金额、请求阈值等，无统一固定格式，需匹配具体业务场景调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据更新周期以周或月为主，知识库增量同步需匹配该节奏，避免高频更新占用集群资源。文档格式与字段不统一，检索环节需支持自定义字段映射与多格式文本解析，确保不同来源的容量规划文档均可被有效召回。数值类字段占比高，检索需支持参数范围匹配逻辑，适配资源利用率、峰值负载等数值查询需求。运维值班场景下检索响应需保持稳定，避免因召回延迟影响内部工单的处理效率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的检索逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配容量规划文档中高相关性的数值参数与业务描述，避免召回无关的低匹配度内容 |
| `limit` | 前8–12条 | 覆盖单份容量规划报告的核心参数，同时控制上下文长度，避免超出模型处理上限 |
| `searchMode` | 综合排序 | 结合关键词匹配与语义相似度，优先召回包含峰值负载、资源配置的核心文档 |
| `usingReRank` | 开启 | 对初始召回结果二次排序，修正初始检索的排序偏差，匹配业务场景的优先级逻辑 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动优化用户的工单问题，将运维术语转换为匹配知识库字段的检索词，提升召回精度 |

## 容易做错的三处
- 检索结果排序不符合预期，综合排序结果未优先展示高匹配的容量规划文档。原因是未开启`usingReRank`配置，初始召回仅依赖基础语义相似度，未结合业务场景的优先级逻辑调整排序。
- 知识库导入或检索时出现`getaddrinfo EAI_AGAIN mongo`报错，重启服务后仍无法恢复。原因是知识库关联的数据库连接配置异常，或集群网络策略限制了数据库访问，导致检索环节无法正常连接数据源。
- 无法从PDF格式的容量规划报告中召回图片内嵌的资源利用率数据。原因是未启用文档图片解析功能，仅提取了PDF的纯文本内容，未覆盖图片中的结构化数据。

## 怎么确认配好了
- 提交一条包含峰值负载关键词的测试检索，核对召回结果的排序是否符合业务预期，调整相关配置直至匹配。
- 查看知识库的同步日志，确认数据更新频率匹配周/月的业务节奏，无高频无效同步记录。
- 触发一次包含数值参数的检索，验证是否能召回包含对应字段的容量规划文档，确认自定义字段映射配置生效。
- 模拟日常检索请求，检查响应延迟是否符合运维值班场景的实时性要求，调整返回结果数量控制配置。
