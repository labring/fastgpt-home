# 工单受理与问题分级的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来源于工单系统、内部聊天记录、产品运行日志、客户合同SLA文档，更新频率为日级或实时。日常生成的文档包含客户工单、问题分级表、处理记录、服务报告，字段包含工单唯一标识、问题描述文本、分级标签、关联处理人、SLA约束项等，每条数据关联具体的服务场景与责任主体。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且更新频率灵活，要求知识库检索环节支持跨源召回工单系统、聊天记录、产品日志等多类数据源，避免遗漏实时产生的工单与异常信息。结构化的问题分级表、处理记录等文档，要求检索需匹配对应分级标签与责任主体字段，确保召回结果与当前工单的分级维度对齐。值班场景的即时性需求，要求检索链路需支持低延迟响应，否则无法快速完成问题复现与影响范围判断。不同格式的文档需统一预处理，避免因文本结构差异导致召回精度下降。

## 配置怎么定
FastGPT v4.17.0 版本下的配置项如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配工单问题描述与历史处理记录的语义相似度，过滤低相关召回结果 |
| `limit` | 前10条 | 控制召回结果的总token数，适配模型上下文窗口限制 |
| `searchMode` | 向量搜索+关键词混合 | 兼顾语义匹配与关键词精准匹配，适配工单的标准化与口语化问题表述 |
| `usingReRank` | 开启 | 对初始召回结果进行二次排序，提升高相关历史工单与分级表的优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 将用户输入的问题扩展为同义表述，覆盖更多潜在相关的内部文档 |
| `collectionIds` | 绑定运维工单专属知识库集合 | 限定检索范围，避免混入非运维类业务文档 |

## 容易做错的三处
- 现象：调用API检索知识库返回的阅读链接点击后提示`Only support .txt, .m`错误。原因：未正确配置知识库的文档上传校验规则，仅允许上传指定格式的文件，非合规格式的文档无法生成可访问的阅读链接。
- 现象：检索结果条数与配置的`limit`参数不符，出现召回结果超出或不足设定数量的情况。原因：未正确绑定`collectionIds`参数，检索范围覆盖了多个不相关的知识库集合，导致召回结果数量异常。
- 现象：导入的知识库无法生成精准的匹配结果，回答内容偏离工单问题的核心诉求。原因：未开启`usingReRank`参数，未对初始召回结果进行二次排序，导致低相关文档排在高优先级位置。

## 怎么确认配好了
- 提交测试工单，查看检索返回的结果数量，确认与配置的`limit`参数匹配。
- 输入包含分级标签的测试问题，检查召回结果是否包含对应分级表的内容，确认`similarity`阈值的配置符合业务需求。
- 点击检索返回的文档链接，确认可以正常访问，检查文档格式校验规则的配置是否正确。
- 对比开启与关闭`usingReRank`参数后的检索结果，确认高相关文档的排序优先级符合预期。
