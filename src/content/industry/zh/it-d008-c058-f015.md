# 广告合规留痕的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自广告平台后台、客户资质、合同系统及监管公开规则，日常文档包含广告审查表、资质附件、投放记录、整改通知。数据更新随单次广告活动或自然月完成，单份文档多包含活动ID、客户名称、合规校验结果、附件哈希值等字段，部分资质附件为多页扫描件格式，无统一固定字段长度，文档体量随广告活动规模波动。

## 这些特征在「知识库检索与召回」这一环带来什么约束
广告合规留痕数据随单次广告活动更新，单次活动关联的文档集合相对独立，需按活动维度限定检索范围，避免跨活动无关结果干扰值班判断。单份文档结构差异大，既有结构化审查表格，也有非结构化投放记录与扫描件，需适配多格式召回逻辑。数据更新频率固定但单次活动数据量波动明显，需预留足够索引容量应对峰值。合规场景对结果置信度要求高，召回结果需关联原始数据来源，避免无关匹配影响合规判断。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配合规场景对结果相关性的严格要求，过滤低相关性的干扰内容 |
| `limit` | 前10条 | 兼顾运维值班的信息密度与检索效率，避免过多结果占用工单响应时间 |
| `searchMode` | hybrid | 适配结构化审查表与非结构化投放记录的混合格式，提升多类型文档召回率 |
| `usingReRank` | 开启 | 对初始召回结果二次排序，过滤语义偏差的匹配项，符合合规场景的高置信度要求 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索关键词，覆盖合规场景中同义词、行业术语的匹配需求，如将“资质”扩展为“授权文件” |
| `collectionIds` | 按活动ID绑定 | 限定检索范围为当前活动关联的知识库集合，避免跨活动无关数据干扰 |

## 容易做错的三处
- 现象：多知识库关联后返回结果未按预期分配权重，仅优先显示单个知识库内容。原因：未正确配置多集合检索的权重逻辑，或仅绑定了单个`collectionIds`集合。
- 现象：知识库通过mongorestore导入后无法检索到内容。原因：导入后未触发索引重建流程，向量索引未完成生成，需执行全量索引重建操作。
- 现象：检索结果条数与预期不符，仅返回少量匹配项。原因：`limit`参数设置过低，或`similarity`阈值设置过高，过滤了部分有效合规相关结果。

## 怎么确认配好了
- 进入知识库管理页面，查看`collectionIds`参数是否包含当前活动关联的所有合规文档集合。
- 执行单条测试检索，输入包含活动ID的关键词，验证返回结果是否仅关联当前活动的文档。
- 触发一次全量索引重建，等待任务完成后，执行导入后的检索测试，确认可正常返回结果。
- 开启检索日志，查看返回结果的元数据是否包含文档来源、上传时间等合规溯源所需字段。
