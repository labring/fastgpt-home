# 广告账户开户审核的运维值班与内部工单问答：重排与混合检索

本文基于FastGPT v4.17.0版本的配置说明，以下内容针对广告账户开户审核场景下的运维值班与内部工单问答，讲解重排与混合检索的具体配置、约束与问题处理。

## 这个品类的数据长什么样
该品类的数据主要来自广告平台后台、国家企业信用信息公示系统、客户提交的开户申请材料、行业准入规则。日常处理的文档包含开户申请单、营业执照扫描件、对应行业资质文件、历史开户审核记录。数据更新节奏为每日批量同步或随单提交实时更新，单条数据包含主体名称、统一社会信用代码、申请行业类目、审核状态等核心字段，不同来源的文档格式存在一定差异。

## 这些特征在「重排与混合检索」这一环带来什么约束
跨数据源的内容需要混合检索覆盖，因此需配置多源召回通道。不同文档类型的字段差异要求重排模型适配结构化资质字段与非结构化申请文本的混合匹配。随单或每日的更新节奏要求检索索引需定期同步，避免调用过期的审核规则或资质数据。单条数据的核心字段集中在主体资质与行业类目，重排时需优先关联这些高权重字段，提升审核相关检索的精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 启用重排 | 开启 | 该品类需精准匹配资质与审核规则，重排可过滤低相关性的召回结果 |
| 分块相似度阈值 | 0.72–0.85 | 适配结构化资质字段与非结构化申请文本的混合匹配精度 |
| 单次召回上限 | 前6–10条 | 平衡检索效率与上下文长度，适配运维值班的快速查询场景 |
| 检索模式 | 混合检索 | 覆盖广告平台后台、客户提交材料等多源内容，实现跨源混合检索 |
| 重排召回数 | 前4–6条 | 聚焦高相关结果，适配内部工单问答的快速定位需求 |

## 容易做错的三处
- 现象：在线召回测试时未显示重排结果，检索结果仍按初始召回顺序排列。原因：未在检索配置中开启重排功能，或知识库索引环节未同步关联重排模型。
- 现象：调用重排模型时返回Invalid URL (POST /v1/rerank)报错。原因：重排模型的API接口地址配置错误，或部署的重排服务未开放对应POST请求路径。
- 现象：检索结果中低相关性的非资质类文档占比过高。原因：相似度阈值设置不合理，未过滤无关内容，或未配置混合检索模式覆盖核心数据源。

## 怎么确认配好了
- 进入FastGPT的检索测试页面，输入一条开户申请相关的查询，查看返回结果是否经过重排调整顺序。
- 检查当前检索的配置项，确认启用重排功能的开关已打开，且绑定了适配的重排模型。
- 切换检索模式为混合检索，验证是否能召回来自广告平台后台、客户提交材料的多源文档。
- 查看检索日志，确认重排模型的调用请求已成功发送并返回有效结果。
