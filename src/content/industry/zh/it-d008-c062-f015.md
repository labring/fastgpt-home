# 投放效果优化的运维值班与内部工单问答：知识库检索与召回

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的核心数据来自广告平台后台、归因系统、CRM线索库与落地页数据，更新节奏多为日级或实时。日常产出的文档包含投放日报周报、单次调价记录、素材AB测试表与优化复盘笔记，字段多包含广告计划ID、消耗金额、转化量、素材点击率等，单位涉及元、次、百分比等。数据体量随投放规模动态变化，核心用于异常指标定位、预算调配与素材效果复盘。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据多源且更新频率灵活，要求知识库检索需支持跨数据源的关联召回，避免割裂的信息片段。日常文档结构差异大，从结构化的调价记录到非结构化的复盘笔记，需要检索环节适配不同格式的内容拆分与匹配。实时更新的投放数据要求检索链路延迟控制在10秒以内，否则无法支撑运维值班的即时问题响应。同时，投放效果调整的出错后果直接影响业务成本，要求召回结果的相关性与准确性需匹配业务决策的精度需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配投放业务的信息相关性要求，过滤低关联的冗余结果 |
| `limit` | 前6条 | 控制单轮检索返回的结果量，适配运维值班的快速阅读需求 |
| `usingReRank` | 开启 | 优化结构化与非结构化混合文档的排序效果，提升复盘类内容的召回准确性 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配调价记录等结构化数据与复盘笔记等非结构化数据的混合检索 |
| `collectionIds` | 指定广告投放、归因分析相关的集合ID | 聚焦品类专属数据，过滤非投放类的冗余知识库内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索词，覆盖广告优化师常用的行业术语变体 |

## 容易做错的三处
- 现象：检索结果传入AI对话后出现上下文截断报错。原因：未正确计算知识库内容与用户问题的总token数，超出模型支持的上下文窗口。
- 现象：检索返回结果条数与设置的`limit`不符。原因：未同步配置重排环节的结果数量限制，导致重排后结果数量被调整。
- 现象：配置问题优化后检索召回结果无明显变化。原因：混淆了知识库节点的问题优化与独立的问题优化节点，前者用于优化知识库内的问题映射，后者用于优化用户输入的查询词。

## 怎么确认配好了
- 手动输入一条典型业务问题，比如“昨日广告消耗超标如何调整预算”，核对检索返回的结果是否包含调价记录与预算调配相关内容。
- 查看检索日志，确认返回结果的`similarity`分值处于预设的0.75–0.85区间内。
- 测试实时更新的投放数据，确认检索结果能在10秒内返回。
- 检查知识库集合的关联关系，确认`collectionIds`仅包含品类专属的知识库内容。
