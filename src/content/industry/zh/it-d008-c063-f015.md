# 投放计划搭建的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的日常文档包含投放计划、定向设置、预算排期、转化追踪配置等，数据来源涵盖广告平台后台、用户画像库、预算管理表、归因分析工具。单份文档通常包含计划唯一标识、定向人群包参数、单日预算额度、转化事件配置项等字段，单位涉及元、千次曝光、转化事件名等。数据更新频率多为每日同步或随投放活动触发更新。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散的特性要求检索环节支持跨多数据集的关联召回，避免仅从单一广告平台拉取信息。文档字段多且带有专属单位的特征，要求检索时需匹配字段精度，避免召回不相关的配置项。高频更新的特性要求定期刷新数据集索引，确保召回内容与最新投放配置同步。投放数据的准确性直接影响业务结果，因此召回结果的相关性校验需要适配业务场景的严格标准。同时单份文档的结构化特征，要求分块时保留字段完整性，避免拆分关键配置信息。

## 配置怎么定
FastGPT v4.17.0 版本下，以下配置项可适配投放计划搭建场景的知识库检索需求：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配投放配置的字段精度要求，避免召回无关的低相关性内容 |
| `limit` | 前8条 | 适配单份投放文档的字段数量，避免上下文过载影响后续处理 |
| `searchMode` | vector_search | 针对结构化投放数据的向量召回需求，优先匹配语义与字段特征 |
| `usingReRank` | 开启 | 对召回结果二次排序，优化投放配置相关结果的展示优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展检索范围，覆盖跨广告平台、预算表的关联配置数据 |
| `collectionIds` | 绑定对应投放计划、定向设置等数据集的ID | 精准限定检索范围，避免无关数据集的干扰 |

## 容易做错的三处
-  执行知识库创建时出现日志报错`try reducing the size of the batc`，原因是未针对结构化投放文档调整分块参数，批量处理的文档总长度超出系统默认阈值。
-  检索结果传入HTTP工作流后，AI对话无法正确关联知识库内容，原因是返回的检索结果未携带结构化的字段标识与来源信息，仅保留纯文本片段。
-  检索召回的内容总token超出上下文限制，导致后续AI处理失败，原因是未控制`limit`参数的召回条数，未结合投放文档的平均长度调整分块与召回数量。

## 怎么确认配好了
-  手动触发一次检索，核对返回结果的字段是否与目标投放配置文档的字段一致。
-  查看检索日志，确认召回结果的数量符合`limit`参数的设定范围。
-  检查工作流中传递的检索结果格式，确认包含元数据与原始内容字段。
-  模拟投放配置变更后，触发数据集刷新，验证检索结果是否同步更新为最新内容。
