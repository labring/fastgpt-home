# 数据库云服务运维的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自云数据库控制台、慢日志、监控指标与内部工单系统，更新节奏为每日同步或随实例变更实时更新。日常运维文档包含实例变更单、备份恢复记录、性能诊断报告与参数调整记录，每条数据包含实例ID、变更时间、操作内容、监控指标数值、工单编号等字段，无统一固定单位，指标类数据随对应监控项匹配单位，文档类数据以纯文本格式存储。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散导致知识库需对接多类数据源，需分别配置不同数据的导入规则与格式适配。更新频率差异要求结合增量同步与全量同步，避免数据滞后或冗余导入。文档结构多样，既有结构化的监控指标数值，也有非结构化的运维说明文本，需适配不同格式的文本拆分逻辑。工单与变更记录的强关联性要求检索时需关联实例ID等字段，避免跨实例的无效召回。慢日志与性能报告的时效性要求召回结果优先匹配最新的变更与诊断记录，保障内容的参考价值。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配云数据库运维场景下的专业术语精度，避免召回无关的历史记录 |
| `limit` | 前8条 | 覆盖慢SQL定位、参数调整等常见运维场景的知识点数量，避免上下文过长 |
| `searchMode` | 精准匹配 | 优先召回与运维工单、变更记录高度相关的内容，贴合原封不动返回知识库答复的需求 |
| `usingReRank` | 开启 | 对初步召回的结果按相关性重排，提升备份恢复、性能诊断类内容的排序准确性 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 避免生成额外查询导致偏离知识库原文内容，保障答复完全来自导入的问答对与文档 |

## 容易做错的三处
- 现象：检索结果出现非知识库原文的生成内容，原因：未关闭`datasetSearchUsingExtensionQuery`配置，导致系统生成额外查询扩展了召回范围。
- 现象：部分用户提问无法召回对应知识点，原因：未针对云数据库运维的细分场景配置合理的检索策略，导致专业术语的匹配精度不足。
- 现象：无法按实例ID或工单编号过滤召回结果，原因：未配置知识库的过滤字段，未将业务关联字段纳入检索匹配范围。

## 怎么确认配好了
- 输入一条知识库中已有的运维问答对原文，检查返回结果是否完全匹配知识库内的答复内容。
- 查看检索日志，确认召回的结果均来自已导入的云数据库运维相关文档，无额外生成的非知识库内容。
- 尝试按实例ID、工单编号等业务字段检索，验证过滤功能是否可按指定字段筛选结果。
- 调整`similarity`阈值，观察召回结果的相关性变化，确认符合当前场景的精度需求。
