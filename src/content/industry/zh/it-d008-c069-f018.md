# 数据库运维的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来自数据库监控、审计日志、SQL执行计划与内部工单系统。日常处理的文档包含数据库变更单、慢SQL报告、备份记录、权限申请单，各文档包含实例标识、执行时间、权限等级、变更内容等字段。数据更新频率随数据库变更触发或按日更新，单条数据体量跨度较大，部分慢SQL报告包含结构化的执行耗时、锁等待等细节信息。

## 这些特征在「重排与混合检索」这一环带来什么约束
该品类的数据多源异构，混合检索需同时整合结构化的监控指标、半结构化的SQL执行计划与非结构化的工单文本，需配置适配多格式数据的检索逻辑。数据更新随数据库变更触发，检索结果需优先匹配最新的变更记录与权限申请单，避免返回过时的配置信息。文档包含实例标识、权限等级等精准匹配字段，重排环节需优先关联查询中的实例信息，避免无关结果混入。单条数据体量差异较大，需限制检索结果的单条长度，适配系统的上下文窗口限制。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | 匹配数据库运维场景下的精准查询需求，避免低相关的慢SQL或工单混入结果 |
| `limit` | 前10条 | 适配运维值班场景下的快速浏览需求，避免结果过多占用上下文窗口 |
| `searchMode` | hybrid | 对应混合检索模式，整合向量检索与关键词检索，覆盖结构化与非结构化数据 |
| `usingReRank` | 开启 | 针对多源异构数据优化排序优先级，优先匹配实例标识与权限相关的结果 |
| 单次搜索上限 | 2000 字符 | 适配慢SQL报告与变更单的文本长度，避免截断关键执行信息 |
| 重排模型调用阈值 | 前8条召回结果 | 平衡检索效率与排序精度，符合数据库运维场景的查询响应要求 |

## 容易做错的三处
- 现象：检索结果未按业务优先级排序，无关的历史备份记录出现在慢SQL查询结果的前列。原因：未开启`usingReRank`配置，仅依赖基础向量相似度排序，未关联实例标识等精准匹配字段。
- 现象：混合检索返回结果条数远低于预期，且无明确报错。原因：`limit`参数取值过小，同时未调整`similarity`参数的阈值范围，导致部分符合要求的低相似度结果被提前过滤。
- 现象：重排环节触发失败，界面显示模型调用失败提示。原因：未在FastGPT平台中配置重排模型的调用密钥与地址，或召回结果的总字符数超过模型的输入上限。

## 怎么确认配好了
- 提交包含数据库实例ID的查询，核对检索结果是否优先返回对应实例的变更单与慢SQL报告。
- 查看检索日志，确认`searchMode`为hybrid模式，且`usingReRank`配置已启用。
- 调整查询关键词，验证结果条数随`similarity`参数的调整发生合理变化。
- 触发一次数据库变更工单的查询，确认更新后的内容在合理时间内出现在检索结果中。
