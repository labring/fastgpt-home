# 数据清洗与质检的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
数据清洗与质检场景的核心数据包含清洗规则、质检抽样表、异常数据清单、交付报告四类文档，数据来源为原始数据集、ETL运行日志、标注平台输出及抽样质检结果。数据更新频率为每日或按每批任务触发，单批任务数据量随业务规模变化。文档字段包含任务标识、数据范围、处理规则、抽样比例、异常标记、交付状态等，部分关联字段需绑定对应业务主体的权限标识。

## 这些特征在「权限与数据隔离」这一环带来什么约束
该场景的数据多源且包含业务敏感内容，权限隔离需匹配数据来源的层级差异，对原始数据集、ETL日志等资源设置不同的访问权限。数据按日或每批更新，需支持按任务周期动态调整权限生效范围，避免权限过期或未及时生效。文档包含清洗规则、异常数据清单等核心业务内容，需限制仅对应项目的工程师、质检员及项目经理可见。字段绑定的业务主体标识需作为权限校验的核心依据，避免跨项目数据越权访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `teamId` | 绑定对应业务项目的唯一标识 | 数据清洗与质检任务按项目划分，`teamId`可直接关联项目权限范围，过滤跨项目数据 |
| `tmbId` | 绑定单个业务成员的唯一员工标识 | 内部工单及值班场景需按成员权限过滤数据，避免非授权人员查看敏感业务文档 |
| SSO认证对接 | 配置为对接企业自有SSO服务，超时阈值设为30–60秒 | 运维值班场景多在内网部署，统一身份认证可简化登录流程，适配内网网络环境 |
| 历史版本数据隔离 | 开启`tmbId`字段校验，缺失字段的历史版本默认仅项目管理员可见 | 适配历史文档无`tmbId`字段的场景，避免越权访问旧版本数据 |
| 角色权限划分 | 按岗位分配权限：数据工程师可编辑清洗规则，质检员可查看抽样结果，项目经理可查看全量交付报告 | 匹配数据清洗与质检场景的岗位分工，限制不同角色的操作与查看范围 |

## 容易做错的三处
- 内网部署后对接SSO时出现连接超时或认证失败，现象为界面弹出认证失败提示，日志显示无法访问SSO服务地址。原因是未配置内网环境下的SSO服务白名单，或超时阈值设置过短。
- 查看历史版本数据时出现权限校验失败，现象为部分旧版文档无`tmbId`字段，无法匹配当前权限规则。原因是未开启`tmbId`字段的兼容校验逻辑，未对无该字段的历史数据设置默认权限。
- 内网部署时出现数据库连接拒绝报错，现象为日志显示MySQL连接被拒绝，虽MySQL服务正常启动。原因是未配置数据库访问的内网白名单，或数据库绑定地址未开放对应端口。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的系统进行测试，登录对应项目的账号，尝试访问非所属项目的清洗规则文档，确认无法查看或提示无权限。
- 查看MongoAppVersion表的历史文档，确认缺失`tmbId`字段的版本仅项目管理员可访问。
- 在内网环境下测试SSO认证流程，确认可通过企业账号直接登录系统，无需重复输入账号密码。
- 尝试添加团队成员，输入对应员工标识后确认可正常显示用户名并分配权限。
