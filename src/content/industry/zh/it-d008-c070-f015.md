# 数据清洗与质检的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来源包括原始数据集、ETL运行日志、标注平台产出结果、抽样质检结果。日常维护的文档包含清洗规则、质检抽样表、异常数据清单、交付报告。数据更新频率为每日或每批任务完成后更新，文档字段包含数据标识、异常类型、处理状态、抽样比例等，无额外自定义单位，核心字段围绕已获取的业务数据开展质量校验与处理流程。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源多样且更新频繁，要求检索召回需覆盖多源异构数据，避免遗漏ETL日志中的异常记录与最新抽样结果，适配运维值班场景下的实时响应需求；日常文档结构固定且专业术语集中，需精准匹配清洗规则、异常清单等专属术语，避免泛化召回无关内容，提升工单问答的专业性；更新频率为日/每批，意味着知识库需支持增量同步，否则检索结果会滞后于最新的业务数据，无法支撑最新的质检与清洗任务；核心业务环节依赖异常数据识别与抽样质检，召回结果需优先关联历史处理方案，缩短运维人员的排查时间。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 匹配数据清洗与质检的专业术语精度，避免召回无关的通用文档 |
| `limit` | 前3–5条 | 控制单次召回结果数量，适配运维值班场景下快速浏览的需求 |
| `searchMode` | 语义检索 | 优先匹配专业文档的语义关联，适配清洗规则、异常清单等结构化文档 |
| `usingReRank` | 开启 | 对召回结果二次排序，优先展示与异常数据识别、抽样质检相关的高相关内容 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 避免生成额外扩展查询导致召回非目标文档，适配固定业务场景的工单问答 |
| `collectionIds` | 对应数据清洗与质检知识库的ID列表 | 限定检索范围，仅调用该品类专属的知识库文件 |

## 容易做错的三处
- 现象：回答末尾自动附加知识库检索的input与response引用块，原因是未在FastGPT v4.17.0的工作流配置中关闭检索结果的展示开关，或未启用回答内容的引用过滤设置。
- 现象：检索召回的结果包含与数据清洗、质检无关的通用文档，原因是未通过`collectionIds`限定检索范围，导致调用了全平台的知识库文件。
- 现象：检索结果未覆盖最新的异常数据清单或ETL日志，原因是未配置知识库的增量同步机制，仅按固定周期执行全量更新，无法匹配日/每批的更新频率。

## 怎么确认配好了
- 发起一条包含“异常数据识别”“清洗规则”等关键词的测试工单，查看回答是否仅展示处理方案，无额外引用内容。
- 进入FastGPT v4.17.0的检索日志页面，确认仅调用了数据清洗与质检专属的知识库集合，未出现跨品类的检索结果。
- 提交一份新的清洗规则文档，触发知识库更新后，发起对应关键词的检索，确认新文档被正确召回。
- 检查配置项的参数值，确认`similarity`、`limit`等参数符合预设的建议取值。
