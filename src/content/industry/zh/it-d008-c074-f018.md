# 文本标注项目的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
文本标注项目的日常文档以标注规范、样本包、质检报告、问题反馈表为主，数据来源包括客户提供的语料、内部标注平台、专用词表以及质检抽样结果，更新节奏按日或每批标注任务推进。数据字段多包含文本片段、标注标签、质检评分、反馈问题描述等，核心围绕语义边界、实体识别与意图分类展开，区别于图像标注项目的视觉特征处理逻辑。

## 这些特征在「重排与混合检索」这一环带来什么约束
文本标注项目的高频动态更新数据，要求混合检索适配快速刷新的样本与质检结果；多类型文档的语义差异显著，需重排模型区分不同文档的相关性权重；标签边界解释、疑难样本仲裁等核心场景的检索需求集中，需优先召回高匹配度的标注规范与质检记录；单次检索需覆盖标注全流程的信息调用，因此检索上限需适配多环节的内容需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 匹配文本标注项目的语义匹配精度需求，过滤低相关的非标注类内容 |
| `limit` | 1200–1500 条 | 覆盖标注全流程的文档调用量，避免因结果过少无法支撑标签解释与仲裁 |
| `searchMode` | hybrid | 适配多类型文档的混合检索逻辑，结合语义与关键词匹配召回标注规范、样本包等不同类型的内容 |
| `usingReRank` | 开启 | 针对标注项目语义差异大的文档，重排模型可优化结果相关性排序，优先召回质检报告与规范内容 |
| 检索刷新间隔 | 1天 / 每批标注任务 | 匹配文本标注项目的日常数据更新节奏 |

## 容易做错的三处
- 重排序模型测试报错，排查发现未在FastGPT v4.17.0中配置私有化模型的接入路径，导致模型调用失败。
- 未开启重排功能时，检索结果仅按基础相似度排序，无法区分标注规范与无关样本的语义差异，导致工单处理时出现无关内容干扰。
- 混合检索配置`limit`为1500条但实际返回结果不足，原因是未同步更新标注项目的检索库数据，导致召回池无法覆盖全量标注文档。

## 怎么确认配好了
- 登录FastGPT v4.17.0的项目后台，查看检索配置面板，确认`usingReRank`处于开启状态。
- 输入测试问题（如“标签边界如何界定”），核对返回结果的排序是否优先展示标注规范文档。
- 调整`similarity`阈值，验证低匹配度的非标注类内容是否被过滤。
- 检查检索结果的条数是否符合`limit`配置的1200–1500条区间。
