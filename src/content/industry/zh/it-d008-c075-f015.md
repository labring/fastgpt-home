# 文档站维护的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据主要来自代码仓库、文档站构建日志、用户反馈与版本发布记录。日常产出的文档包含安装指南、API参考、迁移教程与常见问题解答，内容按版本、模块划分字段，包含更新时间、文档路径、版本标识与正文内容。数据更新节奏多为每周同步或随版本发布触发，单次更新覆盖单版本或单模块的文档内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
文档站数据按版本与模块划分，检索时需关联版本标识避免跨版本内容混淆，需定向匹配对应模块的文档内容。高频更新节奏要求检索环节支持增量同步配置，避免全量刷新占用过多资源。技术文档包含专业术语与版本差异内容，召回需优先匹配精确关键词，同时需过滤过期内容。此外，文档内容多为结构化技术说明，检索结果需按文档章节或模块排序，便于运维人员快速定位。

## 配置怎么定
以下配置项适用于FastGPT v4.17.0及以上版本，需在FastGPT后台与服务端环境中完成对应设置。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配技术文档的精确性需求，过滤低相关的非目标内容 |
| `limit` | `前 8–12 条` | 平衡召回覆盖率与上下文长度，适配运维人员快速浏览的场景 |
| `searchMode` | `embedding` | 针对结构化技术文档，向量检索比关键词检索更适配专业术语匹配 |
| `usingReRank` | `开启` | 优化召回结果的排序，优先返回与问题最相关的文档章节 |
| `datasetSearchUsingExtensionQuery` | `开启` | 自动优化用户问题，适配技术文档的专业术语表达，提升召回准确性 |
| `collectionIds` | `对应文档站专属数据集的集合ID` | 定向召回文档站维护的专属数据集内容，避免混入其他业务知识库数据 |

## 容易做错的三处
- 现象：检索结果返回条数远低于配置的`limit`值，且未召回预期的文档内容。原因：未正确配置`collectionIds`，导致检索范围覆盖了非文档站的数据集，或配置了错误的集合ID。
- 现象：检索响应耗时过长，超出预期交互阈值。原因：未合理设置`similarity`阈值，召回了过多低相关内容，导致后续上下文拼接与模型调用耗时增加，或未开启`usingReRank`导致冗余结果过多。
- 现象：外部接入场景下未按预期返回流式分段内容，直接输出完整结果。原因：未正确启用应用端的流式返回配置，或未正确对接AI Proxy的流式响应链路，导致交互体验不符合需求。

## 怎么确认配好了
- 确认App/Admin服务端已正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量，且未在FastGPT后台界面、工作流全局变量或应用API配置入口重复设置此类参数。
- 发起针对文档站内容的测试检索，输入如“安装步骤”“API接口说明”等问题，核对召回结果的来源是否为目标文档站数据集，且返回条数符合配置的`limit`范围。
- 对比开启与关闭`usingReRank`后的检索响应耗时，确认配置对结果排序与响应速度的影响符合预期。
- 测试外部接入场景的流式回复功能，确认检索结果能按分段形式逐步返回，无卡顿或一次性输出完整内容的情况。
