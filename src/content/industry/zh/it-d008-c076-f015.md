# 日志平台与可观测性的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自日志系统、Trace平台、Metrics系统与应用SDK，更新频率为每日或每版本迭代一次。日常运维文档包含日志采集规范、链路追踪说明、指标字典与看板配置记录，数据字段包含时间戳、服务名、TraceID、SpanID、调用耗时、指标维度与数值等结构化内容，同时伴随非结构化的日志文本片段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源要求检索环节需支持跨系统文档的关联召回，避免割裂的信息片段。高频更新的特性要求知识库需配置增量同步机制，确保检索结果始终匹配最新的采集规范与看板配置。结构化字段与专业术语的存在，要求检索需兼顾关键词匹配与语义理解，避免因字段格式不匹配导致召回失败。故障定位的核心需求要求召回结果需包含足够的上下文证据，确保运维人员可快速定位问题根源。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 日志与可观测性文档包含大量专业术语与特定格式字段，该阈值可过滤低匹配度的无关内容，保留核心关联信息 |
| `limit` | 前5–15条 | 运维值班场景需同时参考多段日志、链路追踪片段，该范围可平衡召回数量与上下文窗口占用 |
| `searchMode` | 混合检索 | 兼顾关键词匹配与语义理解，适配日志ID、服务名等结构化字段与通用说明文本的混合检索需求 |
| `usingReRank` | 开启 | 日志与指标数据的语义相似度区分度较低，重排环节可进一步筛选出与问题高度相关的召回结果 |
| `datasetSearchUsingExtensionQuery` | 开启 | 运维问题常包含行业缩写或自定义术语，扩展查询可补充匹配相关的规范文档内容 |
| `collectionIds` | 绑定专属运维知识库集合 | 避免召回非运维类文档，确保检索结果聚焦于日志平台与可观测性相关内容 |

## 容易做错的三处
-  使用URL创建知识库时提示`cannot fetch internal url`：未配置FastGPT访问内部日志系统的网络权限，或目标URL对应的接口未开放必要的访问权限。
-  知识库内的PDF文件点击分块预览时提示无法读取该文件内容：PDF文件包含加密内容、嵌入非标准字体或存在损坏的文件结构，导致解析环节失败。
-  上传知识库时无法多文件上传，或单个文件转译耗时过长后出现网络失败：未配置批量上传的并发阈值，或单文件大小超出知识库允许的上传上限，导致服务端处理超时。

## 怎么确认配好了
-  检索日志平台相关问题时，查看召回结果是否包含日志采集规范、链路追踪说明等专属文档内容。
-  检查检索结果的匹配度是否符合设定的`similarity`阈值，无明显低匹配度的无关内容。
-  验证批量上传文件时，是否可同时上传多个日志相关文档，且单个文件转译无超时报错。
-  开启重排功能后，查看排序靠前的结果是否与运维问题的关联度更高。
