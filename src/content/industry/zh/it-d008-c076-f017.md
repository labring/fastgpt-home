# 日志平台与可观测性的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
这个品类的数据主要来自日志系统、Trace平台、Metrics系统与应用SDK，通常由SRE、平台工程师及研发效能团队维护。日常配套文档包括日志采集规范、链路追踪说明、指标字典与看板配置记录，数据更新频率为每日或每版本迭代。数据字段包含日志时间戳、服务标识、错误码、链路ID、调用耗时、QPS、内存占用等，部分字段需遵循内部标准化规则，单位涵盖毫秒、条、GB等不同类型。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据来源分散且更新频繁，部署时需同时配置多类数据源的连接参数，避免出现跨系统连接失败。日常维护的配套文档较多，部署前需同步梳理日志字段与知识库的映射规则，确保内部工单问答能匹配正确的上下文信息。数据更新频率为每日或每版本迭代，升级时需提前校验配置与新版本的兼容性，避免因字段规则变更导致查询异常。此外，采集字段标准化的要求，使得部署环节需额外配置字段映射逻辑，保障后续运维值班的查询准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `DB_MAX_LINK` | 30-50 个连接 | 适配日志平台的并发查询负载，避免数据库连接池溢出 |
| `MONGODB_URI` | 填写日志聚合存储的副本集连接地址 | 适配每日新增的海量日志数据，保障查询稳定性 |
| `REDIS_URL` | 配置为带认证的内部缓存服务地址，缓存有效期设为1800秒 | 缓存链路追踪的临时查询结果，降低日志系统的重复请求压力 |
| `PG_URL` | 指向存储指标字典与看板配置的关系型数据库，启用SSL加密 | 保障敏感运维配置的传输安全 |
| `FE_DOMAIN` | 设置为内部运维门户的域名 | 确保内部工单问答的跳转路径指向合规的运维工作台 |
| `STORAGE_S3_ENDPOINT` | 填写内部对象存储服务的端点地址，如`http://s3.internal.corp:9000` | 存储日志查询导出文件与看板快照 |

## 容易做错的三处
- 升级后点击知识库出现连接失败报错，原因是未同步更新`MONGODB_URI`与日志存储集群的连接配置，导致无法读取日志数据源。
- 调用内置工具时返回模型流响应为空，原因是未正确配置`REDIS_URL`的缓存有效期，导致链路追踪数据无法正常缓存传递。
- 重启Docker容器后出现SQL权限报错，原因是未保留`PG_URL`的数据库连接认证参数，容器重启后认证凭证丢失。

## 怎么确认配好了
- 执行FastGPT v4.17.0的内置健康检查脚本，验证`MONGODB_URI`、`PG_URL`、`REDIS_URL`的连接状态是否正常。
- 上传一条测试日志数据，通过内部工单问答触发日志查询，确认返回结果包含预期的服务名、错误码字段。
- 访问`FE_DOMAIN`绑定的运维门户，点击知识库跳转链接，确认页面跳转无报错。
- 生成一条看板配置记录，通过`STORAGE_S3_ENDPOINT`验证文件存储是否正常写入。
