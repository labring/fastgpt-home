# 机房巡检与环境监控的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据主要来自动环监控系统、门禁系统、UPS监控设备与视频巡检终端。数据更新节奏为日更或实时推送。日常运维文档包含巡检表、温湿度记录、告警记录、值班日志，字段多包含设备编号、温湿度数值（单位为℃与%RH）、告警等级、巡检时间、通行权限标识等，部分文档为结构化日志格式，部分为半结构化的纸质转换电子巡检记录。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据实时性与字段多样性带来明确约束。实时更新的动环告警数据要求检索召回的数据源需支持近实时同步，避免召回过时信息。多来源的结构化与半结构化文档存在大量语义相似的条目，例如不同设备的温湿度超限告警描述，需调整检索逻辑以区分精准匹配与相似场景的召回优先级。不同设备的专属字段如UPS输出电压、门禁通行ID，需通过指定数据集范围过滤无关内容，减少无效召回。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | 适配本品类语义相似的告警与巡检描述，平衡精准召回与覆盖范围 |
| `limit` | 前 8–12 条 | 匹配机房巡检单页文档的常规条目数量，避免上下文过载 |
| `searchMode` | vector_only | 针对结构化的运维日志与巡检记录，优先使用向量检索，不使用关键词混合模式 |
| `usingReRank` | 开启 | 对相似的温湿度告警、设备状态描述进行重排，提升精准度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 优化运维场景下的模糊提问，例如将“UPS异常”自动扩展为匹配UPS监控相关文档 |
| `collectionIds` | 按目标机房数据集填写 | 限定检索范围仅包含当前机房的动环、巡检数据，排除其他无关知识库内容 |

## 容易做错的三处
-  检索结果返回为空。原因是未指定`collectionIds`参数，检索范围覆盖了无关数据集，无法匹配机房专属的巡检与告警文档。
-  相似语义的条目无法精准区分，例如“温湿度超标”与“温度超限”的召回结果混淆。原因是未开启`usingReRank`，或`similarity`阈值设置过低，导致大量无关相似条目被召回。
-  半结构化巡检表的字段无法被正确提取。原因是未针对结构化文档调整检索逻辑，或未启用`datasetSearchUsingExtensionQuery`优化字段匹配。

## 怎么确认配好了
-  上传单条机房温湿度告警记录到测试数据集，发起包含该告警描述的提问，验证是否能召回对应文档。
-  调整`similarity`阈值至0.78，发起包含相似告警描述的提问，查看重排后的结果排序是否符合预期。
-  检查`collectionIds`配置是否仅包含当前机房的动环监控、巡检日志数据集，避免跨数据集召回无关内容。
-  发起包含模糊运维提问的测试，例如“UPS电源异常”，验证是否能自动匹配到UPS监控相关文档。
