# 机柜上架与布线的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据主要来自DCIM系统、内部资产台账、网络拓扑图及客户提交的工单。日常处理的文档包括机柜上架申请单、物理布线图、端口对应标签表、单次上架施工记录。数据更新随单触发或每日更新，字段包含机位编号、线缆规格、端口标识、施工时间、客户接入需求等，单条数据的字段数量和格式随工单类型略有差异。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征会对知识库检索与召回带来多重约束。首先，数据来自多套异构系统，字段格式存在差异，检索时需精准匹配机位编号、端口标识等特定字段，避免泛化召回无关内容。其次，数据更新随单或每日触发，知识库需保持实时同步，确保召回内容与最新施工记录、资产台账一致。此外，日常文档包含表格类布线图、文本类工单申请，不同格式的内容需要适配的分块与召回逻辑，同时工单问题多聚焦具体机位的布线规划与核对，要求召回结果的针对性更强。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.78 | 匹配机柜布线的精准字段需求，避免召回无关机位的布线数据 |
| `limit` | 前6条 | 平衡召回范围与上下文长度，适配工单问题的窄范围聚焦需求 |
| `searchMode` | 精确匹配字段 | 针对机位编号、端口标识等结构化字段，提升召回精准度 |
| `usingReRank` | 开启 | 对召回结果按相关性重新排序，修正初始检索的字段匹配偏差 |
| `datasetSearchUsingExtensionQuery` | 开启 | 对运维工单的口语化提问进行标准化处理，适配结构化字段的检索逻辑 |
| `collectionIds` | 绑定上架工单、布线图专属集合 | 隔离本品类的专属知识库数据，避免与其他机房场景的内容混淆 |

## 容易做错的三处
- 现象：设置自定义分隔符与手动换行后，分块结果要么合并多个布线段落，要么拆分单个端口标签条目。原因：未结合本品类文档的结构化格式调整分块参数，仅依赖固定分隔符无法适配表格类布线图、固定格式标签表的分块需求。
- 现象：中文提问无法召回知识库内的机柜相关文档。原因：未开启`datasetSearchUsingExtensionQuery`，未对口语化的运维提问进行标准化转换，导致无法匹配结构化的机位编号、端口标识字段。
- 现象：检索返回的结果包含非目标机位的布线信息。原因：未设置`similarity`阈值或阈值设置过低，导致召回了相似度不达标的内容。

## 怎么确认配好了
- 上传一份机柜上架申请单与布线图，执行模拟检索，核对返回结果是否包含对应文档的关键片段。
- 检查知识库同步日志，确认DCIM系统、工单系统的最新数据已同步至绑定的`collectionIds`集合内。
- 调整`similarity`阈值，验证不同阈值下的召回结果是否符合机位匹配的精准需求。
- 提交一条包含具体机位编号的测试工单提问，确认返回结果是否聚焦该机位的布线信息。
