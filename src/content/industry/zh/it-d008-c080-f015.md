# 桌面终端支持的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自终端管理平台、企业资产系统、用户报障工单、软件仓库。日常处理的文档包含终端故障单、装机清单、软件安装记录、远程协助操作记录。数据更新频率为每日同步或随单更新，单条文档通常包含设备序列号、故障现象、排查步骤、软件版本号等字段，字段随文档类型灵活调整，无统一固定的单位要求。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散导致文档格式不统一，检索时需适配不同来源的字段结构，避免召回无关的资产台账内容。更新频率灵活要求检索模块支持实时或按需刷新知识库索引，防止召回过时的装机记录。单条文档字段灵活的特点，要求检索时需通过关键词精准匹配故障类型、设备标识等核心字段，避免泛化召回无关内容。同时，桌面终端支持的工单响应时效要求，需控制检索耗时，避免影响值班工程师的处理效率。

## 配置怎么定
以下配置项适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配终端故障单的精准度要求，过滤低相关的通用运维内容 |
| `limit` | 前 5–8 条 | 适配值班工程师快速查阅的需求，避免过多结果分散注意力 |
| `searchMode` | 关键词匹配优先 | 适配终端故障单中设备序列号、故障现象等明确字段的检索 |
| `usingReRank` | 开启 | 对召回结果按相关性重排，提升核心排查文档的展示优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 生成扩展查询词，覆盖终端故障的常见表述变体 |
| `collectionIds` | 绑定桌面终端支持专属知识库集合 | 限定检索范围，避免召回其他品类的运维文档 |

## 容易做错的三处
- 现象：检索结果包含非桌面终端相关的装机清单，字段为空。原因：未正确配置`collectionIds`，未绑定专属知识库集合，导致检索范围覆盖全平台知识库。
- 现象：worker terminated due to reaching memory limit报错，FastGPT v4.13.2版本常见。原因：未限制`limit`参数取值，召回过多文档导致内存占用超出阈值。
- 现象：变量引用后检索结果无匹配内容。原因：未正确将用户报障的设备序列号作为检索变量传入，或未在检索配置中启用变量匹配逻辑。

## 怎么确认配好了
- 手动输入一条已知的终端故障单关键词，检查检索结果是否仅包含桌面终端支持相关的文档。
- 查看知识库检索模块的日志，确认未出现内存超限报错，且检索耗时符合预期。
- 传入设备序列号作为检索变量，验证是否能召回对应设备的装机清单、软件安装记录。
- 开启`usingReRank`后，检查召回结果的排序是否与故障排查的核心需求匹配。
