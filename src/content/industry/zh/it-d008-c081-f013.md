# 渗透测试服务的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据主要来自目标业务系统、公开漏洞库、自动化扫描器输出结果，以及红队工程师的手工验证记录。日常关联文档包括项目测试授权书、正式渗透测试报告、漏洞复现步骤记录、整改优先级建议文档。数据更新以单个项目为周期，或在重大版本迭代时批量同步，单份数据包含授权范围、漏洞详情、利用链分析、修复方案等字段，无固定统一的单位化字段，随项目场景灵活调整。

## 这些特征在「权限与数据隔离」这一环带来什么约束
该品类的数据特征会带来三类权限约束。第一，数据包含法律生效的测试授权书，越权访问或泄露可能引发法律争议，需严格绑定项目授权范围配置权限。第二，数据以单个项目为更新周期，不同项目的渗透测试数据、报告需严格隔离，避免跨项目权限泄露。第三，数据包含手工验证的漏洞利用链细节与敏感操作记录，需区分角色的查看、编辑权限，禁止非授权人员修改验证结果或获取未授权的项目数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `teamId` 绑定 | 关联单个渗透测试项目的专属`teamId` | 确保仅该项目授权的团队成员可访问对应数据，避免跨项目权限泄露 |
| `tmbId` 绑定 | 为每个内部工单创建专属`tmbId` | 精准隔离单条工单的对话与关联数据，防止非授权人员查看其他工单内容 |
| 免登录链接数量限制 | `10–100 个`，按实测标定 | 匹配渗透测试项目的临时协作需求，既避免无限制链接导致的数据泄露，又满足多成员临时访问的需要 |
| 对话记录权限校验 | 开启基于`teamId`与`tmbId`的双字段校验 | 拦截未授权的对话记录访问，避免越权操作 |
| 角色权限划分 | 按红队工程师、运维、安全经理划分权限层级 | 匹配渗透测试服务的日常协作流程，确保不同角色仅可访问对应职责范围内的数据 |
| 项目数据存储隔离 | 将不同项目的数据存储至独立目录，按`teamId`划分 | 避免跨项目数据混淆，简化权限审计与隔离管理 |

## 容易做错的三处
- 现象：界面弹出「没有权限操作此对话记录」的提示，无法访问目标工单或测试数据。原因：未正确绑定对话的`teamId`与`tmbId`，导致权限校验逻辑不匹配。
- 现象：免登录窗口仅可创建10个链接，无法调整至更高数量。原因：未在团队配置中修改免登录链接上限的取值范围，仍使用团队版默认的基础限制。
- 现象：外部团队成员可访问未授权的渗透测试项目数据。原因：未按项目配置专属`teamId`，误将全局团队ID绑定至多个项目，导致权限隔离失效。

## 怎么确认配好了
- 登录FastGPT v4.17.0的团队管理后台，查看`teamId`与`tmbId`的绑定配置，确认每个项目的专属ID已正确关联至对应数据与工单。
- 尝试使用非授权成员的账号访问目标对话，验证是否弹出「没有权限操作此对话记录」的提示，确认权限校验生效。
- 进入免登录窗口配置页，调整链接数量上限至`50 个`，确认保存后可创建对应数量的临时链接，验证上限配置生效。
- 切换至红队工程师角色的账号，尝试编辑漏洞复现记录，再切换至运维角色的账号，验证仅可查看记录无法修改，确认角色权限划分正确。
