# 游戏内容合规自查的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
本品类的数据主要来源于游戏文本、美术资源、剧情脚本及监管公开要求，更新节奏为每版本或每活动周期。日常维护的文档包含内容自查表、敏感内容修改记录、用户协议、合规评审纪要，单份文档包含内容分类标签、修改时间、审核人标识、关联版本号等字段，美术资源数据还附带分辨率、文件格式与关联剧情节点信息。

## 这些特征在「权限与数据隔离」这一环带来什么约束
由于数据按版本与活动周期更新且关联特定业务主体，不同项目组的合规自查数据需严格隔离，避免跨版本或跨项目的信息泄露。文档包含审核人、关联版本等敏感字段，需限制仅对应项目的运维与审核人员可访问。美术资源数据体积差异较大，需匹配不同存储权限配额，同时因更新频率较高，需同步更新权限配置的关联规则，防止旧版本数据遗留权限漏洞。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `teamId` | 与项目版本绑定的唯一标识 | 匹配本品类按版本/活动更新的数据隔离需求，确保不同项目的自查数据仅对授权成员可见 |
| `tmbId` | 按合规评审角色划分的权限组 | 本品类文档包含审核人、评审纪要等敏感内容，需按角色限制访问范围 |
| 数据存储配额 | 1000 MB 按实测标定 | 美术资源数据体积差异较大，需预留足够空间且避免资源浪费 |
| 邀请通知触发规则 | 绑定`teamId`的站内推送 | 确保受邀成员可在对应团队下获取通知，解决邀请后无通知的问题 |
| 账号隔离配置 | 按服务器部署节点划分 | 满足本地部署场景下的账号隔离需求，避免跨服务器的数据泄露 |
| 通知延迟阈值 | 60 秒 | 确保受邀成员可及时获取权限通知，避免延迟过长影响工作流程 |

## 容易做错的三处
- 现象：受邀成员登录FastGPT平台后，未在通知中心看到团队邀请消息，无法获取对应合规自查项目的访问权限。原因：未绑定`teamId`配置邀请通知的触发范围，导致通知仅在默认团队下发。
- 现象：尝试添加第二个合规自查团队时，系统提示配置冲突，无法完成创建。原因：未为每个团队分配独立的`tmbId`，导致系统无法识别不同团队的权限边界。
- 现象：本地部署FastGPT后，跨账号访问了其他项目的内容自查表或美术资源数据。原因：未按服务器部署节点配置账号隔离规则，导致默认权限覆盖了跨节点的访问范围。

## 怎么确认配好了
- 邀请指定测试成员加入目标合规自查团队，查看FastGPT通知中心是否显示对应邀请消息，确认邀请配置生效。
- 登录不同角色的测试账号，验证仅对应角色可访问内容自查表、合规评审纪要等文档。
- 上传美术资源文件，检查存储配额是否按配置生效，无超额报错提示。
- 切换本地部署的不同账号，验证无法访问其他账号的版本自查数据。
