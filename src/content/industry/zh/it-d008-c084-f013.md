# 游戏客户端性能优化的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据主要来自引擎Profiler、崩溃平台、真机测试工具与帧率采集系统，更新节奏为每日或每版本发布周期。日常产出的文档包含性能测试报告、机型适配清单、优化记录与崩溃分析报告，数据字段包含帧率（单位fps）、包体大小（单位MB）、资源加载时长（单位秒）、机型型号、崩溃日志ID等，不同测试场景下的字段会存在差异，无统一标准化格式。

## 这些特征在「权限与数据隔离」这一环带来什么约束
该品类的核心数据包含未公开的性能优化方案、真机测试的敏感机型数据，且更新频率较高，不同岗位的工程师仅能访问对应职责范围内的文档与数据。运维值班与工单场景中，不同团队成员的权限边界需严格匹配其工作范围，避免跨团队访问未授权的性能测试报告或崩溃分析数据。同时，数据来源分散导致权限管控需覆盖多类数据源，需确保隔离规则与数据归属的对应关系，防止权限越权导致核心优化信息泄露。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 团队权限分组 | 按客户端、引擎、性能测试三类岗位划分 | 匹配该品类的典型岗位分工 |
| `teamId`绑定规则 | 绑定至对应项目的性能优化数据集 | 确保仅同项目成员可访问对应性能数据 |
| `tmbId`校验开关 | 开启 | 拦截未授权的跨团队数据访问请求 |
| 工单数据归属 | 关联至提交者所属`teamId` | 避免工单内容被非关联团队查看 |
| 日志保留时长 | 30 天 | 匹配该品类的版本迭代与复盘周期 |
| 跨源数据访问 | 仅允许同`teamId`下的成员调用 | 覆盖多数据源的权限隔离需求 |

## 容易做错的三处
- 输入团队成员用户名后显示用户名无效：未正确配置`teamId`与成员账号的绑定关系，系统无法识别对应团队的合法成员。
- 跨团队访问性能测试报告时返回权限不足报错：未开启`tmbId`校验开关，或权限分组未匹配该品类的岗位分工规则。
- 工单关联的性能数据无法正常加载：数据归属未绑定至提交工单的成员所属`teamId`，系统无法匹配对应的权限范围。

## 怎么确认配好了
- 尝试使用非本团队成员的账号访问本团队的性能测试报告，确认系统返回权限不足提示。
- 提交一条内部工单，确认工单仅本团队成员可查看，非本团队成员无法搜索到该工单。
- 检查`teamId`绑定的数据集，确认仅对应项目的性能数据被关联至该分组。
- 查看权限审核日志，确认跨团队数据访问请求被正确拦截。
