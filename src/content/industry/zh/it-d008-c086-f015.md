# 游戏版号与出版申报的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来自国家新闻出版署办事服务平台、著作权登记系统、游戏包体及运营机构资料，更新节奏为每款游戏申报周期内不定期更新。日常文档包含申报请示文件、游戏申请表、著作权证明、审读报告，单份文档多包含申报编号、著作权登记号、审读结论等固定字段，部分文档存在多版本迭代情况，不同来源的文档格式差异明显。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散导致不同文档的格式差异较大，检索时需适配多源文档的字段特征，避免因格式不兼容导致召回失败。更新不定期意味着知识库需要支持增量更新，防止过期审批材料被误召回。单份文档存在多版本的情况，需精准匹配最新版本的申报材料，避免返回过时内容。内部工单常涉及专业合规问题，检索结果需严格关联官方来源数据，确保内容的合规性与可信度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 游戏版号申报材料包含大量专业术语，该区间可过滤低相关结果，同时保留合规性相关的弱关联内容 |
| `limit` | 前6条 | 内部工单回复需兼顾全面性与可读性，过多结果会超出上下文窗口限制 |
| `searchMode` | 语义检索 | 申报材料包含结构化字段与专业表述，语义检索可更好匹配工单中的模糊提问 |
| `usingReRank` | 开启 | 多源文档的相关性排序易受格式干扰，重排可优化结果的相关性优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 内部工单常包含省略的上下文，扩展查询可补充隐含的申报编号等字段 |
| `collectionIds` | 绑定专属游戏版号申报知识库集合 | 需隔离其他品类的文档，避免召回无关的业务材料 |

## 容易做错的三处
- 现象：AI回复未显示知识库引用标记，检索结果无关联文档来源。原因：未正确配置`collectionIds`参数，导致检索范围覆盖非目标知识库集合。
- 现象：创建知识库时文本理解模型列表为空，无法选择对应模型。原因：未配置对应模型的API密钥，或FastGPT版本未适配当前模型版本。
- 现象：企微会话无法触发知识库检索，提示连接失败。原因：未更新企微集成配置，或未在FastGPT v4.17.0中完成对应权限配置。

## 怎么确认配好了
- 发起包含目标申报编号的测试工单，检查回复中是否出现预期的知识库引用标记。
- 查看知识库配置页面，确认`collectionIds`参数已绑定专属的游戏版号申报知识库集合。
- 测试开启`usingReRank`后的检索结果排序，验证重排后的结果相关性是否符合业务需求。
- 检查模型配置页面，确认文本理解模型的API密钥已正确配置，模型列表可正常加载。
