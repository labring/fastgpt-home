# 游戏运营活动配置的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
通常服务于游戏运营、活动策划、数据运营三类主体，核心日常文档包括活动方案、奖励配置表、上线检查单、活动复盘四类。数据来源覆盖运营后台、玩家分群数据、付费数据与活动日志，更新节奏以周或节假日周期为主。文档包含奖励数值、活动生效时段、玩家分群规则、补偿触发条件等字段，单位涉及游戏内虚拟货币、时间戳、用户群体标签等，无统一标准化格式，多为运营人员直接从运营后台导出的业务表格。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的业务文档格式不统一，且包含数值、时间、分群规则等非文本字段，对检索的字段匹配精度提出较高要求。高频更新的业务数据需要匹配实时索引策略，避免召回过期的活动配置内容。运维值班与内部工单场景下，问题多围绕异常补偿、配置错误排查，需快速定位到对应活动的检查单与复盘文档，因此召回结果的相关性权重需高于通用检索。同时，内部工单涉及的配置参数多来自运营后台导出的表格，需支持结构化数据的召回匹配。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数规则制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配活动配置的数值与规则字段，避免召回无关的历史活动文档 |
| `limit` | 前6条 | 覆盖单次工单可能涉及的多份活动文档，同时控制上下文长度 |
| `searchMode` | `vector+keyword` | 兼顾文本语义匹配与结构化字段（如活动时间、奖励数值）的精确匹配 |
| `usingReRank` | 开启 | 对召回结果按相关性重新排序，适配运维场景下快速定位核心问题的需求 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题自动扩展检索词，覆盖活动配置中的专业术语（如“付费拉新活动”“补偿发放”） |
| `collectionIds` | 绑定游戏运营活动专属数据集 | 避免检索到其他品类的文档，缩小召回范围 |

## 容易做错的三处
- 上传知识库文件后状态持续显示“索引中”，未完成同步。原因是绑定的活动文档包含大量结构化表格，索引解析耗时较长，且未调整检索引擎的批量处理参数。
- 知识库变量引用时使用[{datasetId: xxx}]格式无法生效。原因是未使用平台支持的标准变量语法，错误套用了非适配的数据集ID引用格式。
- 回复中无法直接展示知识库内的活动配置截图。原因是未开启图片内容的检索关联配置，或截图未被正确嵌入可被召回的文档节点中。

## 怎么确认配好了
- 提交测试问题（如“上周春节活动的奖励配置是否正确”），检查召回结果是否包含对应活动的配置表与检查单。
- 查看检索日志，确认召回结果的相似度分值处于预设的`similarity`区间内。
- 测试变量引用功能，验证是否能正确加载活动文档中的结构化字段内容。
- 上传一份测试用的活动文档，确认索引完成后能被正确检索到。
