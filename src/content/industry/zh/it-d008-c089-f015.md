# 漏洞扫描服务的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
漏洞扫描服务的核心数据来自漏洞扫描器导出的扫描结果、企业内部资产清单、公开CVE漏洞库与官方补丁公告。日常维护的文档包含扫描计划、漏洞清单、整改工单与复扫报告，其中扫描计划包含资产范围、扫描周期字段，漏洞清单标注CVE编号、风险等级与影响资产，整改工单关联工单编号与处理状态，复扫报告记录复扫时间与修复结果。数据更新频率为周度或月度，覆盖常规扫描与补丁同步需求。

## 这些特征在「知识库检索与召回」这一环带来什么约束
漏洞扫描服务的数据来源包含工具导出的结构化文档与公开知识库内容，要求检索需精准匹配字段属性，避免无关文档混入。固定的更新周期要求知识库向量库需按周或月度刷新，确保召回结果包含最新的CVE信息与补丁公告。最耗时的资产范围确认、误报排除与复扫核对环节，需要检索结果快速定位对应文档，减少人工筛选成本。高危漏洞暴露的出错后果，要求召回结果需具备足够的语义匹配精度，避免遗漏关键漏洞信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 匹配运维问题与漏洞文档的语义相似度，过滤低相关性的召回结果，适配误报排除环节的精准需求 |
| `limit` | 前10条 | 限制单次召回的文档数量，适配运维值班场景下的快速查阅需求，避免信息过载 |
| `searchMode` | `local` | 限定检索范围为绑定的专属知识库，避免跨库召回无关的渗透测试或其他品类文档 |
| `usingReRank` | 开启 | 对初始召回结果按相关性重新排序，优化复扫结果核对环节的信息展示顺序 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索词，覆盖CVE编号、资产名称等字段的精确匹配，提升资产范围确认环节的检索效率 |
| `collectionIds` | 按实际部署的漏洞扫描服务知识库集合ID填写 | 精准绑定专属知识库，确保检索仅覆盖漏洞扫描相关的文档数据 |

## 容易做错的三处
- 调用`/api/v1/chat/completions`接口后未返回文档溯源信息，原因是未开启知识库的内容溯源配置，或未在检索参数中指定正确的关联参数。
- 召回结果包含大量非漏洞扫描类的无关文档，原因是未通过`collectionIds`绑定专属知识库集合，或错误将`searchMode`设置为跨库检索模式。
- 检索结果未命中最新的补丁公告或复扫报告，原因是未按周或月度更新频率刷新知识库向量数据，或`similarity`阈值设置过高导致新文档未被正常召回。

## 怎么确认配好了
- 调用`/api/v1/chat/completions`接口，传入配置好的`collectionIds`与检索参数，检查返回结果是否仅包含漏洞扫描服务相关的文档。
- 触发一次模拟运维值班的查询，检查返回结果是否附带对应的文档溯源信息，确认`usingReRank`与`datasetSearchUsingExtensionQuery`功能生效。
- 上传一份新的漏洞清单文档，确认FastGPT v4.17.0的文件处理模型已正确解析文档内容，等待向量刷新流程完成后发起检索，确认新文档能被正常召回。
- 查看FastGPT v4.17.0的知识库管理界面，确认关联的集合ID与配置项一致，且`similarity`值处于预设的0.72–0.80区间内。
