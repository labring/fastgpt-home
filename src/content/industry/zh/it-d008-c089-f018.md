# 漏洞扫描服务的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
本品类的数据主要来自漏洞扫描器、企业资产清单、公开CVE漏洞库与官方补丁公告。日常产出的文档包含扫描计划、漏洞清单、整改工单、复扫报告四类。数据字段包含漏洞CVE编号、关联资产IP/域名、漏洞严重等级、整改状态、扫描执行时间等。数据更新频率以周或月为周期，随扫描计划执行或补丁公告发布同步更新。

## 这些特征在「重排与混合检索」这一环带来什么约束
本品类的数据结构包含多类文档与多维度字段，且更新周期固定，对重排与混合检索带来三点约束：第一，需支持跨文档类型的混合匹配，例如同时检索漏洞清单的技术细节与整改工单的关联资产信息，避免仅匹配单一文档类型导致的信息缺失；第二，需针对漏洞严重等级、整改状态设置差异化相关性权重，优先匹配高危未整改漏洞相关内容，适配运维值班场景下的优先级需求；第三，需适配固定更新周期的数据集，无需频繁调整检索阈值，可基于周/月的扫描周期校准检索参数，减少不必要的参数维护成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | `0.65–0.75` | 漏洞扫描数据包含大量相似的漏洞描述与资产信息，该区间可过滤低相关的误报扫描结果，保留核心漏洞与工单内容 |
| `limit` | `前10–15条` | 运维值班场景下需快速浏览核心结果，过多条目会增加排查负担，该范围可覆盖单轮扫描的典型高危漏洞数量 |
| `searchMode` | 混合检索 | 需同时匹配漏洞清单的技术细节与整改工单的流程信息，混合检索可兼顾语义与关键词匹配效果 |
| `usingReRank` | 开启 | 漏洞数据存在大量语义相似的描述（如不同扫描器对同一CVE的描述差异），重排可进一步过滤语义冗余结果，提升高危漏洞的排序优先级 |

本配置适用于FastGPT v4.17.0及以上版本。

## 容易做错的三处
- 现象：重排结果无变化或排序混乱，原因：未正确配置`usingReRank`为开启状态，或未完成重排模型的渠道关联配置
- 现象：检索结果条数远低于预期，原因：`similarity`阈值设置过高，过滤了大量符合业务需求的低相似度但相关的漏洞信息
- 现象：混合检索无法匹配整改工单与漏洞清单，原因：`searchMode`未设置为混合检索模式，仅使用了单一检索类型

## 怎么确认配好了
- 检查FastGPT服务端的`AIPROXY_API_ENDPOINT`（AI Proxy服务根地址，格式例如http://aiproxy:3000，无需附加路径）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token，需与AI Proxy服务端配置一致且非空）环境变量是否正确配置
- 发起测试检索，输入“高危未整改漏洞”，核对返回结果的排序是否优先展示高危漏洞条目
- 调整`similarity`阈值，观察检索结果条数的变化，确认阈值符合业务需求
- 查看检索日志，确认`searchMode`与`usingReRank`参数被正确应用
