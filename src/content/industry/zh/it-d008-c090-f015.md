# 版本发布与Release Notes的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的核心数据为版本发布相关文档，包括Release Notes、变更日志、版本标签、发布检查单，数据来源主要为Git标签、合并提交记录、CI构建制品、Issue里程碑。数据更新节奏为每版本一次，单次更新包含该版本下所有已合并变更的归类说明、破坏性变更提示、制品校验信息等内容。数据结构以结构化字段为主，包含版本号、变更类型、影响范围、制品哈希等标识项，同时附带半结构化的变更详情文本，用于支撑运维值班的核对与问题排查。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源绑定代码仓库与CI流程，要求检索需精准关联版本标识与制品信息，避免召回非当前版本的变更内容。更新频率为每版本一次，要求知识库支持增量同步，避免全量重建带来的资源消耗与延迟。变更归类环节耗时较长，要求检索召回结果需覆盖全量关键变更项，支撑运维值班的快速核对。同时，发布制品核对需要关联外部CI返回的校验结果，要求检索支持接入非原生的外部数据源，无需手动整理数据即可完成核对。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配Release Notes中变更描述与运维问题的语义相关性，避免召回无关变更或遗漏关键内容 |
| `limit` | `前8–12条` | 覆盖该版本下的核心变更项，支撑运维值班的全量核对需求，同时控制上下文长度 |
| `searchMode` | `语义搜索+关键词匹配` | 兼顾版本号、制品哈希等结构化字段与变更描述的半结构化文本，适配该品类数据的混合结构特征 |
| `usingReRank` | `开启，重排前5条` | 过滤低相关性的召回结果，聚焦破坏性变更、关键修复等运维关注的内容 |
| `datasetSearchUsingExtensionQuery` | `开启` | 支持接入CI返回的制品校验结果作为扩展数据源，满足发布制品核对的需求 |
| `collectionIds` | `对应Release Notes专属集合的ID` | 限定检索范围仅覆盖当前版本的发布文档，避免召回其他版本或非发布类内容 |

## 容易做错的三处
- 现象：检索结果包含非目标版本的变更文档或无关的PR评审内容，原因：未配置`collectionIds`限定知识库集合，导致召回了其他版本或非发布类的文档数据。
- 现象：检索返回的结果条数不足，无法覆盖当前版本的全部关键变更，原因：`limit`取值过低，未预留足够的召回数量以支撑全量变更核对。
- 现象：无法将CI工具返回的制品校验结果纳入检索数据源，原因：未开启`datasetSearchUsingExtensionQuery`，未配置外部数据源同步规则，无法接入非原生的发布制品数据。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理页面，确认目标Release Notes集合的ID已正确填入`collectionIds`配置项。
- 发起测试检索，输入“版本v2.3.0的破坏性变更说明”，检查返回结果是否仅包含该版本的破坏性变更内容，无无关文档混入。
- 查看检索日志，确认`similarity`阈值、`usingReRank`等参数已生效，召回结果的相关性符合预期。
- 调用FastGPT对话接口，传入指定的`collectionIds`参数，确认接口返回的结果仅来自目标Release Notes知识库集合。
