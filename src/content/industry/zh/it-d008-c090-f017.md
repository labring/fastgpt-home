# 版本发布与Release Notes的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
版本发布与Release Notes的数据通常来自Git标签、合并提交记录、CI构建制品、Issue关联里程碑，更新节奏为每正式版本发布一次。日常产出的文档包含Release Notes、变更日志、版本标签、发布检查单，文档字段通常包含版本标识、变更归类项、破坏性变更说明、制品校验值等，所有内容围绕已合并的变更集合展开，不包含未提交的草稿内容。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据来源依赖代码仓库与CI制品的权限，部署环节需要配置对应的存储与访问权限，确保能拉取最新的版本元数据。由于更新频率为每版本一次，升级流程需要适配版本标签的校验逻辑，避免拉取未标记的临时变更。由于文档包含变更归类与破坏性变更说明，部署前需要配置自动校验环节，拦截未完成合规标注的版本。同时，出错会导致升级失败、版本回滚或社区误解，因此需要配置回滚预案与版本校验机制，保障发布流程的稳定性。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt?authSource=admin` | 适配版本发布元数据的存储需求，关联Git与CI的制品索引，保障版本标签与变更日志的持久化 |
| `REDIS_URL` | `redis://:password@host:6379/0` | 缓存版本标签与变更日志的查询结果，降低重复拉取Git与CI数据的开销 |
| `DB_MAX_LINK` | `10–30 个` | 适配版本发布数据的并发连接需求，避免连接池耗尽导致的元数据拉取失败 |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.aliyuncs.com`（按实际存储区域调整） | 存储Release Notes的附件与CI制品的校验文件，保障版本发布文档的完整存储 |
| `FE_DOMAIN` | `https://your-fastgpt-domain.com` | 配置版本发布页面的访问域名，确保内部工单与值班人员的访问路径正确 |
| `FILE_TOKEN_KEY` | `按环境生成的随机字符串，长度不小于32 字符` | 校验模型API密钥的合法性，保障本地部署的模型调用权限 |

## 容易做错的三处
- 现象为内部工单生成的Release Notes仅显示固定的底部引用提示，无自定义关联的知识库条目，原因是未配置`DB_MAX_LINK`限制元数据的拉取数量，导致关联的知识库文档索引无法正常加载。
- 现象为部署后版本标签无法同步，报错提示「未找到关联的Git仓库权限」，原因是未正确配置`STORAGE_S3_ENDPOINT`关联CI制品的存储路径，导致无法拉取版本元数据。
- 现象为本地部署的模型调用失败，报错提示「API密钥无效」，原因是未配置`FILE_TOKEN_KEY`用于模型API的签名校验，导致本地部署的模型密钥无法被系统识别。

## 怎么确认配好了
- 执行`mongo --uri $MONGODB_URI`命令，验证数据库连接正常，能查询到包含版本标识与变更字段的集合数据。
- 访问`$FE_DOMAIN/api/release-notes`接口，确认返回的JSON数据包含版本号、变更归类项等预期字段。
- 上传一份测试的Release Notes附件，验证`STORAGE_S3_ENDPOINT`能正常完成文件存储与读取。
- 查看Redis缓存的键列表，确认存在以`fastgpt:release:*`为前缀的缓存条目，说明版本数据已正常缓存。
