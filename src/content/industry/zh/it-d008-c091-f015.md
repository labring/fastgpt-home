# 玩家客服与舆情处理的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自游戏客服系统、社区论坛、应用商店评论与游戏日志。日常处理的文档包括玩家工单、补偿申请、舆情日报与标准化处理话术，字段包含玩家标识、问题类型、反馈渠道、情绪倾向等。数据更新节奏多为日更或实时，单条数据体量较小但单日产出量较高，且需关联玩家账号、历史反馈等上下文信息。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源混合的数据输入要求检索环节优先匹配与玩家身份、问题类型强相关的知识库条目，避免无关舆情或旧工单干扰判断。实时更新的文档需配置高频同步机制，确保最新的补偿规则、处理话术可被及时召回。单条数据的轻量化特征与高产出量，要求检索链路轻量化以降低延迟，适配运维值班的实时响应需求。同时，账号核验、补偿规则判断等核心耗时环节，需关联对应细分文档集，避免跨品类无关内容被召回。

## 配置怎么定
本配置适用于FastGPT v4.17.0及以上版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | 0.75–0.85 | 匹配玩家工单与知识库话术的语义精度，过滤低相关内容 |
| `limit` | 前5–8条 | 控制单轮召回的上下文长度，适配运维值班的实时响应需求 |
| `usingReRank` | 开启 | 优化多源召回结果的排序，优先返回与玩家问题最匹配的处理话术与工单案例 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展问题语义，覆盖玩家模糊表述的工单场景，提升召回覆盖率 |
| `collectionIds` | 指定玩家客服、舆情日报专属数据集ID | 隔离跨品类知识库内容，确保仅召回与当前业务相关的文档 |

## 容易做错的三处
- 检索结果中附带知识库文档的引用链接，导致回复冗余。原因是未调整检索配置关闭引用输出，默认保留了文档来源链接。
- 创建doc/docx格式的文件集合时，未正确传递metadata参数，导致检索结果无法关联章节标题信息。原因是未了解该参数用于标注文档结构层级，需按接口要求传递章节相关字段。
- AI回答超出知识库范围，出现非文档内的内容。原因是未限定检索范围为指定数据集，或未配置仅调用知识库内容的响应规则。

## 怎么确认配好了
- 查看App/Admin服务的启动日志，确认服务端环境变量`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或/chat/completions，不是VLLM/Ollama/Xinference等单模型地址）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空，不是应用API Key、模型供应商密钥、按应用签发的token或按请求估算的token数）已正确配置，无启动校验报错。两类变量不得在工作流全局变量、应用API请求头或普通模型管理页面填写以替代服务部署配置。
- 提交一条玩家工单相关的测试问题，核对检索返回的结果是否仅包含指定客服与舆情数据集的文档。
- 上传doc/docx格式的测试文档，检索后确认结果包含正文所在的章节标题信息，验证metadata参数生效。
- 提交知识库外的无关问题，确认AI无法生成对应回答，仅返回知识库相关内容。
