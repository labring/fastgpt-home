# 现场部署实施的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
本品类的数据来源为客户机房环境、设备清单、软件包与网络拓扑，日常关联文档包括部署手册、安装记录、配置清单及现场签到表。数据更新节奏为每单或每阶段，由实施工程师、系统工程师及客户IT人员共同维护。数据字段包含设备型号、软件版本、配置参数、现场操作记录等，无统一强制格式，需匹配客户现场环境的实际记录要求。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据依赖客户现场的专属环境与设备清单，部署前需逐一核对客户机房的网络连通性、资源配额，无法直接复用标准化通用配置。数据按单更新的节奏要求每次部署与升级都需重新匹配客户当前的配置清单，避免遗留历史参数导致冲突。日常文档的非强制格式要求需同步更新部署手册、安装记录等文件，确保现场操作可追溯。同时，现场部署依赖本地软件包与客户网络，需提前准备可用的镜像资源，避免因网络限制导致拉取失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–200 个连接 | 适配现场部署的单客户机房并发请求量，避免数据库连接耗尽，适配FastGPT v4.17.0版本的数据库连接池配置要求 |
| `MONGODB_URI` | 客户机房内网可访问的 MongoDB 服务地址 | 保障工单数据与知识库内容的本地存储安全，符合客户网络隔离要求 |
| `REDIS_URL` | 客户现场部署的 Redis 实例地址，连接超时设为 30 秒 | 支撑运维值班的实时会话缓存，避免跨公网延迟影响响应速度 |
| `STORAGE_S3_ENDPOINT` | 国内可用的对象存储内网端点 | 适配现场部署的网络环境，降低文件传输耗时 |
| `ROOT_KEY` | 按现场安全策略生成的随机字符串 | 保障后台管理权限的安全性，避免默认密钥泄露 |
| `FE_DOMAIN` | 客户现场分配的访问域名或 IP 地址 | 匹配客户的网络访问规则，确保内部工单系统可正常访问 |

## 容易做错的三处
- 配置`MONGODB_URI`时使用公网地址，出现数据库连接超时报错。原因是未遵循现场部署的网络隔离要求，未使用客户内网可访问的服务地址。
- 升级版本后出现知识库检索时间明显增加的情况，且日志中无明显报错。原因是未同步更新`DB_MAX_LINK`配置，导致数据库连接池耗尽，检索请求排队等待。
- 部署时提示插件拉取失败，返回404状态码且无响应体。原因是未配置国内可用的镜像资源，直接使用官方地址导致网络访问受限。

## 怎么确认配好了
- 执行数据库连接测试命令，验证`DB_MAX_LINK`、`MONGODB_URI`、`REDIS_URL`等配置的连通性，确认连接数符合现场环境的承载要求。
- 访问`FE_DOMAIN`配置的地址，验证内部工单与运维值班界面可正常加载，无访问权限报错。
- 上传测试文件至`STORAGE_S3_ENDPOINT`配置的存储服务，确认文件传输无延迟或失败情况。
- 生成随机`ROOT_KEY`并测试后台管理接口的权限验证，确认配置生效且无默认密钥泄露风险。
