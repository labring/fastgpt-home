# 现场部署实施的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
现场部署实施的日常文档包含部署手册、安装记录、配置清单、现场签到表，数据来源为客户机房环境、设备清单、软件包、网络拓扑。数据更新随每单或每阶段项目推进调整，关联主体为实施工程师、系统工程师、客户IT人员，核心字段包含设备型号、软件版本、配置参数、现场签到时间等，整体为分散的异构现场文档，无统一标准化格式。

## 这些特征在「重排与混合检索」这一环带来什么约束
由于数据来源分散且为客户现场的异构文档，混合检索需兼容不同结构的部署手册、安装记录等数据源，无法依赖单一检索逻辑。单份数据体量不大但更新随单变化，要求检索链路轻量化以适配现场快速排查的需求。现场工单关联的设备、软件信息分散在多份文档中，重排环节需优先匹配当前客户的专属配置字段，避免召回通用文档，同时需控制计算资源消耗以适配现场部署的有限硬件环境。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `usingReRank` | 开启 | 现场部署工单需精准匹配当前客户的设备与文档，重排可过滤无关的通用召回结果 |
| `similarity` | 0.72–0.80 | 现场部署的文档多为客户专属配置，该阈值可过滤相似度较低的非当前客户文档 |
| `limit` | 前6–10条 | 单工单关联的现场文档数量有限，过多召回会增加GPU显存占用与计算耗时 |
| `searchMode` | 混合检索 | 需同时检索部署手册、安装记录、配置清单等异构数据源，整合多类现场信息 |

## 容易做错的三处
- 现象：调用重排模型后GPU显存占用快速增长至6-7G，且多GPU均被占用。原因：未限制单次召回的文档条数，并发调用时模型显存占用叠加超出单卡阈值。
- 现象：离线接入reranker模型时返回rerank error fastgpt | { message: { detail: ' （截断报错）。原因：未正确配置模型加载路径，或文档分块长度超出模型支持的最大输入长度。
- 现象：混合检索结果中出现大量非当前客户现场的通用文档。原因：相似度阈值设置过低，未过滤与当前工单无关的通用部署文档。

## 怎么确认配好了
- 查看重排模型的GPU显存占用情况，确认单卡占用不超过现场服务器的预设阈值。
- 发起一条现场部署工单的检索请求，检查返回结果是否优先匹配当前客户的设备与配置信息。
- 切换检索模式为混合检索，确认同时返回部署手册、安装记录等多类文档。
- 调整相似度阈值，验证召回结果的数量随阈值变化符合预期。
