# 用户增长与留存运营的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据主要来自用户行为日志、推送系统、实验平台与CRM系统，更新频率多为日度或周度。日常产出的文档包含增长实验方案、用户分层表、触达文案、留存分析报告，数据字段多包含用户标识、行为类型、触达渠道、实验分组、转化指标等，无统一固定单位，部分字段需结合具体业务场景匹配格式。

## 这些特征在「权限与数据隔离」这一环带来什么约束
该品类的数据涉及用户行为、实验分组等敏感信息，且来源分散覆盖多系统，因此权限隔离需确保不同运营小组的实验数据、用户分层表无法被未授权人员访问。日常文档更新频率较高，权限配置需适配快速迭代的业务需求，避免因权限校验过严阻碍数据查询与工单处理。不同文档的敏感程度差异明显，触达文案与用户分层表需更高等级的隔离规则，同时需避免权限配置影响内部运维值班的响应效率，防止出现因权限问题导致的工单流转延迟或数据泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `teamId` 绑定 | 按业务线分配专属 ID | 隔离不同增长运营团队的知识库与内部工单数据 |
| `tmbId` 权限校验 | 开启细粒度校验 | 针对单运营人员的临时值班工单请求做权限限制 |
| 敏感数据加密 | 开启 | 保护用户分层表、触达文案中的敏感业务信息 |
| 日志留存周期 | 7–30 天 | 适配运维值班的审计与问题排查常规需求 |
| 外部调用鉴权 | 绑定应用专属 API Key | 避免误用 AI Proxy 管理员 Token 引发权限泄露 |

## 容易做错的三处
-  误将 AI Proxy 管理员 Token 用于外部应用 API 鉴权，导致非授权人员可访问全量运营数据。原因是混淆了服务端环境变量与应用 API 鉴权密钥的使用场景。
-  未配置 `teamId` 隔离规则，导致不同业务线的增长实验数据互相可见，引发实验结果泄露或预算分配混乱。原因是忽略了品类数据按业务线分组的业务特征。
-  未明确知识库存储与租户权限的对应关系，无法快速导出指定团队的留存分析报告。原因是混淆了通用存储逻辑与品类专属数据的隔离需求。

## 怎么确认配好了
-  启动 FastGPT v4.17.0 版本的服务端，检查启动日志是否提示 AI Proxy 相关环境变量配置正确，无启动校验失败报错。
-  切换不同 `teamId` 对应的运营账号，验证仅能访问本团队的知识库文档与内部工单。
-  发起外部应用 API 请求，使用应用专属 API Key 鉴权，确认无法使用 AI Proxy 管理员 Token 完成调用。
-  查看敏感字段的展示状态，确认用户标识、实验分组等字段在查询结果中已做脱敏处理。
