# 用户验收测试支持的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
该品类的数据来源于需求规格文档、测试环境配置、客户业务样例与缺陷系统。日常产出UAT用例、验收问题单、验收报告、签字确认单四类核心文档，字段包含测试场景、问题复现步骤、验收结论、客户签字项等。数据更新频率为每项目阶段或每版本迭代一次，核心围绕客户业务场景的验收需求调整，未纳入通用业务数据池。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据依赖客户侧非标准化的业务样例与验收文档，部署时需预留字段扩展空间以适配不同客户的验收用例结构。每阶段或每版本的更新要求部署流程支持增量同步，避免全量覆盖导致的验收数据丢失。由于核心数据关联客户验收结论，升级过程需保障数据一致性，防止因配置变更引发的验收问题单字段异常。同时，实施顾问与测试经理的使用场景要求部署后的界面需适配验收文档的上传与检索逻辑，需预留对接缺陷系统的接口配置项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30 个` | 适配UAT用例、验收问题单等多文档的并发读取需求，避免数据库连接耗尽 |
| `MONGODB_URI` | `按客户验收数据的专属存储集群地址配置` | 存储验收问题单、缺陷系统同步数据，匹配客户侧的数据库权限与网络策略 |
| `PG_URL` | `按测试环境的PostgreSQL实例地址配置` | 存储需求规格文档与验收报告的结构化字段，保障数据查询效率 |
| `REDIS_URL` | `127.0.0.1:6379` 或专属缓存集群地址 | 缓存UAT用例的检索结果与验收状态，降低重复查询的资源消耗 |
| `FILE_TOKEN_KEY` | `有效期 1800 秒` | 生成客户业务样例附件的访问令牌，保障临时下载链接的安全性 |
| `FE_DOMAIN` | `客户验收平台的访问域名` | 配置前端访问地址，保障签字确认单的在线预览与提交链路正常 |
| `STORAGE_S3_ENDPOINT` | `按客户云存储服务商的官方端点配置` | 存储客户业务样例的附件与验收报告，适配客户已有的云存储环境 |

## 容易做错的三处
- 现象：执行升级脚本时返回`POST /api/admin/initv4818 404`报错，耗时76ms。原因：未使用FastGPT v4.17.0及以上版本的升级脚本，或部署环境的接口访问权限未开放至对应路径。
- 现象：部署完成后无法查询到客户上传的UAT用例文档。原因：未正确配置`STORAGE_S3_ENDPOINT`或关联的存储密钥，导致文档无法正常同步至系统存储路径。
- 现象：登录系统后无法查看验收报告的完整字段。原因：未根据验收文档的结构调整数据库字段映射配置，导致结构化数据读取异常。

## 怎么确认配好了
- 执行`DB_MAX_LINK`的连接测试脚本，验证数据库连接数在并发读取UAT用例时未超过配置上限。
- 上传一份测试用的UAT用例文档，确认可通过前端界面正常预览并存储至指定路径，验证`STORAGE_S3_ENDPOINT`配置生效。
- 触发一次验收问题单的同步任务，确认数据可从缺陷系统正常拉取并存储至对应数据库实例，验证`MONGODB_URI`与`PG_URL`配置正确。
- 使用管理员密钥登录系统，确认可访问所有验收相关的配置模块，验证`FILE_TOKEN_KEY`与角色权限配置生效。
