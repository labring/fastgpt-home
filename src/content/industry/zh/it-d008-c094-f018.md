# 用户验收测试支持的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
本品类的数据来自需求规格文档、测试环境配置、客户业务样例素材与缺陷系统记录。日常产出的文档包含UAT用例、验收问题单、验收报告与签字确认单，各文档按测试阶段或版本迭代更新。数据字段包含用例步骤、预期结果、问题复现路径、缺陷等级、验收结论等，无统一强制单位，字段内容随客户业务场景调整。

## 这些特征在「重排与混合检索」这一环带来什么约束
UAT用例与验收问题单随项目阶段更新，需检索结果匹配当前验收阶段的最新文档，因此混合检索需优先召回近期更新的数据源。客户业务样例的个性化特征强，混合检索需结合语义与业务场景匹配，避免召回无关的通用测试文档。缺陷系统记录的问题复现路径细节多，重排环节需优先排序复现步骤完整、匹配当前工单关键词的结果，同时需控制结果条数适配测试人员的快速查阅需求。签字确认单为最终归档文档，需排除非当前版本的历史记录，因此检索需按版本维度过滤无关内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | `0.65–0.75` | UAT用例的业务语义匹配度需兼顾召回率与精准度，该区间可过滤低相关的通用测试文档，适配验收场景的检索需求。 |
| `limit` | `前 8–12 条` | 测试人员需快速浏览结果，过多条目会增加筛选成本，该范围适配单轮检索的有效信息承载量，符合日常查阅习惯。 |
| `searchMode` | `混合检索模式` | 需结合关键词匹配与语义召回，覆盖UAT用例的步骤描述与验收问题单的关键词标签，适配多类型文档的检索需求。 |
| `usingReRank` | 开启 | 需对初始召回结果按业务相关性重排，优先展示复现路径完整的缺陷记录与匹配的用例，提升问题复现与归类的效率。 |
| 重排模型调用阈值 | 按实测标定 | 不同项目的UAT文档特征差异大，需通过实际检索结果调整阈值以匹配具体业务场景的需求。 |
| 版本过滤开关 | 开启 | 仅召回当前验收阶段的文档，避免历史版本的UAT用例干扰检索结果，符合项目验收的时效性要求。 |

## 容易做错的三处
- 现象：配置`usingReRank`后检索结果无明显变化，原因：未关联重排模型的有效API密钥，或重排模型的输入文本长度超出接口限制，导致重排环节未正常触发。
- 现象：混合检索返回大量非当前阶段的UAT用例，原因：未配置按项目版本或阶段的过滤规则，导致召回了历史验收环节的文档，干扰当前工单的处理。
- 现象：`similarity`设置后检索结果条数不符合预期，原因：混淆了`similarity`与`limit`的作用逻辑，误将相似度阈值作为结果条数的限制条件，导致检索结果超出或不足预期数量。

## 怎么确认配好了
- 手动输入一条验收问题单的关键词，查看初始召回结果是否包含相关的UAT用例与缺陷系统记录。
- 开启`usingReRank`后对比重排前后的结果顺序，确认匹配度高的复现路径文档排在前列。
- 调整`similarity`的取值，观察检索结果的数量变化，确认配置生效。
- 检查检索结果是否仅包含当前项目阶段的文档，确认版本过滤开关配置正确。

该核对流程适配FastGPT v4.17.0版本。
