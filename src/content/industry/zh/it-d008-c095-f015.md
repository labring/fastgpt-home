# 监控告警配置的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自Prometheus、Zabbix、云监控、应用日志、CMDB等运维工具，更新节奏为每日同步或每次告警规则变更后即时更新。日常文档包含监控指标清单、告警规则配置、值班值守手册、告警变更记录，数据字段包含指标名称、阈值参数、告警触发条件、通知对象、变更时间等，部分指标带有明确单位，如CPU使用率百分比、响应时间毫秒级。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据特征对检索召回带来多重约束。分散的多源数据格式差异较大，包含结构化指标参数、半结构化配置文本，会增加语义匹配的难度，导致无关内容被召回。按日或变更触发的更新节奏，要求知识库同步机制匹配变更节点，否则召回内容会与当前生效的告警配置不符。专业的技术配置文本包含大量专有参数和单位，普通检索逻辑容易匹配到语义相近但不相关的条目。数据长度跨度大，从几行的阈值配置到完整的值班手册，需要适配不同长度的分块与召回策略，避免上下文过载或信息遗漏。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的知识库检索功能。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配告警配置的专业术语密度，过低会引入无关内容，过高会遗漏相关告警规则 |
| `limit` | 前8条 | 告警配置相关文档通常条目清晰，8条可覆盖核心告警规则与值班要点，避免上下文过载 |
| `searchMode` | semantic | 针对专业配置文本，语义检索比关键词检索更能匹配隐含的阈值逻辑 |
| `usingReRank` | 开启 | 对召回的结果进行重排，过滤掉语义关联较弱的告警配置条目 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于原问题生成扩展查询，覆盖告警配置中常见的同义词，如“阈值”与“触发条件” |
| `collectionIds` | 绑定告警配置专属知识库 | 避免检索到其他品类的文档，确保召回内容仅来自监控告警相关数据集 |

## 容易做错的三处
- 检索结果包含与当前告警配置无关的内容，例如提问“如何调整CPU告警阈值”却返回了值班排班表。原因是`similarity`阈值设置过低，导致低关联度的文档被错误召回。
- 告警配置中的数学公式无法正常渲染显示。原因是知识库分块时未保留公式的完整结构，或未启用对应格式的解析适配。
- 同一告警相关问题多次检索的结果不一致。原因是未固定`limit`参数，或本地部署的模型未统一embedding生成逻辑，导致召回的条目存在差异。

## 怎么确认配好了
- 提交一条针对告警阈值配置的测试问题，核对召回结果的关联度是否符合预设要求。
- 查看知识库同步记录，确认告警配置变更后是否及时完成数据集更新。
- 多次提交相同的告警相关问题，核对召回结果的一致性。
- 测试包含数学公式的告警规则查询，确认公式可正常渲染输出。
