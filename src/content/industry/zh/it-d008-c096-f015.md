# 社区举报处理的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类按单条用户提交的举报内容开展处理，核心数据来自社区举报系统、待审核内容详情页、用户历史举报记录与官方审核规则文档。日常处理的文档包括单条举报工单、处置进度记录、用户申诉单与标准化通知模板。数据更新节奏多为实时或按日同步，每条记录包含举报唯一标识、关联内容ID、举报类型标签、提交用户信息与处置状态字段，无额外统计类聚合字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
单条举报工单的数据体量较小，但关联内容可能包含多格式素材，实时更新的审核规则需同步更新知识库向量，避免召回过时的判定依据。不同举报类型的检索需求差异明显，需按工单字段精准匹配对应知识库集合，避免召回无关的违规判定标准。同时，违规证据截取与有效性判断为场景最耗时环节，检索时需优先匹配核心字段，减少无效召回结果，提升整体处理效率。

## 配置怎么定
本配置适用于FastGPT v4.17.0及以上版本，以下为针对社区举报处理场景的检索召回配置项：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配举报类型与审核规则的精准度，避免过低召回无关规则或过高遗漏有效判定依据 |
| `limit` | `前 8 条` | 单条举报工单的关联信息有限，过多召回结果会超出模型上下文窗口限制 |
| `searchMode` | `关键词+向量混合检索` | 兼顾举报内容的文本关键词匹配与审核规则的语义匹配需求 |
| `usingReRank` | `开启` | 对召回结果按相关性重排序，提升违规判定的准确性 |
| `datasetSearchUsingExtensionQuery` | `开启` | 基于原举报问题生成扩展查询词，覆盖同义词与场景化表述 |
| `collectionIds` | `按举报类型绑定对应知识库集合` | 仅召回当前举报类型关联的审核规则与处置模板，减少无效检索 |

## 容易做错的三处
- 检索结果中数字与文字间出现多余空格：现象为知识库召回的审核规则或工单文本中，数字与相邻文字之间存在录入时未显示的空格。排查项：检查知识库分块后的文本是否清理了隐性格式空格。
- 无法召回指定知识库的内容：现象为提交举报工单后未返回预期的审核规则或处置模板。排查项：确认`collectionIds`参数绑定了正确的知识库集合ID。
- 检索结果条数超出预期：现象为返回的召回结果条数超过配置的`limit`取值。排查项：确认检索节点中已锁定`limit`参数为配置值。

## 怎么确认配好了
- 检查服务端环境变量配置，确认已正确设置`AIPROXY_API_ENDPOINT`（AI Proxy 服务的根地址，例如 http://aiproxy:3000，不得附加 /v1 或 /chat/completions 等路径）与`AIPROXY_API_TOKEN`（AI Proxy 管理员 Token，与 AI Proxy 服务端配置一致且不能为空），无空值或错误格式。
- 提交一条测试举报工单，检索后核对返回结果的相关性与条数是否符合配置的`similarity`与`limit`要求。
- 查看知识库的向量更新日志，确认举报类型关联的知识库集合已完成实时同步。
- 测试扩展查询功能，确认检索结果覆盖了原举报问题的同义词与场景化表述。
