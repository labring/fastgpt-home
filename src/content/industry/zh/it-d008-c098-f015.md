# 社区贡献者治理的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据围绕社区贡献者治理的人员与规则体系展开，日常文档包含贡献指南、行为准则、维护者名单、治理会议纪要。数据来源为代码仓库提交记录、社区论坛讨论、贡献统计数据、线下或线上治理会议记录，更新频率为月度或季度。数据字段包含角色权限说明、晋升规则、贡献者资质记录、会议决议内容，以文本描述类内容为主，无统一数值单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
首先，数据以非结构化文本为主且更新频率较低，无需高频增量召回，可降低实时同步的配置开销。其次，数据包含角色权限、晋升规则等敏感内容，检索时需严格限定访问范围，避免非授权内容被召回。另外，数据来源分散在代码仓库、论坛等不同平台，召回时需指定对应数据集的集合ID，确保检索范围覆盖全部治理相关文档。同时，单条文档长度差异较大，会议纪要可能较长，需合理控制召回结果的总长度，避免超出模型上下文窗口，适配FastGPT v4.17.0的检索逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配社区治理文档的文本特征，避免召回无关的业务工单内容 |
| `limit` | 前 8 条 | 覆盖月度更新的治理文档总量，避免过多结果超出上下文限制 |
| `searchMode` | hybrid | 结合关键词与语义检索，适配贡献指南、会议纪要等不同类型的治理文档，适配FastGPT v4.17.0的混合检索逻辑 |
| `usingReRank` | 开启 | 对召回结果进行二次排序，提升晋升规则、权限说明等高优先级内容的排序位置 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 治理文档更新频率低，无需额外扩展查询词，避免引入无关内容 |
| `collectionIds` | 按社区治理专属集合填写 | 限定检索范围仅覆盖贡献指南、维护者名单等治理相关数据集，避免召回其他业务数据 |

## 容易做错的三处
- 检索时返回`invalid configuration parameter name "hnsw.max_scan_tuples"`报错：错误使用了官方指定清单外的非标准配置参数，未遵循FastGPT的配置规范。
- 召回结果包含非治理类的业务工单内容：未配置`collectionIds`限定检索范围，导致检索覆盖了无关的业务数据集。
- 升级后对话时提示知识库为空：未同步迁移治理文档的集合ID配置，或未重新触发检索范围的校验流程。

## 怎么确认配好了
- 查看检索配置页面，确认所有使用的配置项均来自官方指定清单，无额外自定义参数。
- 发起一次测试检索，输入贡献者晋升相关的问题，核对召回结果仅包含治理类文档。
- 触发一次知识库同步任务，确认更新后的治理文档在检索结果中正常出现。
- 检查上下文窗口设置，确保单次召回的总内容长度符合模型的限制要求。
