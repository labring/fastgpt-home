# 社区贡献者治理的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
本品类的数据来源为代码仓库提交记录、社区论坛讨论帖、贡献统计报表、治理会议纪要与官方文档。日常维护的文档包括贡献指南、行为准则、维护者名单、季度治理会议纪要。数据更新频率为月度或季度，核心字段包含贡献者ID、角色权限、贡献次数、治理规则版本、会议决议内容。处理的核心对象为社区贡献者的身份、权限与治理相关的规则与决策记录，区别于静态文档类数据。

## 这些特征在「重排与混合检索」这一环带来什么约束
本品类数据分散于多源渠道，既有结构化的维护者名单、贡献统计，也有非结构化的论坛讨论、会议纪要，因此混合检索需覆盖不同格式的数据源。数据更新频率较低但变更后需及时同步，重排环节需适配低频更新的知识库索引节奏，避免因索引延迟导致检索结果过时。核心内容涉及权限、角色等敏感信息，检索结果的排序需优先匹配治理规则的准确性，仅以语义相似度作为辅助参考。同时，检索需覆盖角色权限确认、治理规则解释、贡献者晋升评估三类高频场景，因此重排权重需针对不同业务场景调整，过滤无关的社区闲聊内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 重排开关 | 开启 | 本品类检索内容涉及敏感权限与治理规则，需通过重排过滤低相关的冗余内容 |
| 相似度阈值 | 0.75–0.85 | 平衡检索召回率与语义匹配精度，适配敏感类内容的检索要求 |
| 单次召回上限 | 前10条 | 控制返回结果规模，避免角色权限确认等核心场景的信息过载 |
| 检索模式 | 混合检索 | 覆盖代码仓库提交记录、社区论坛、贡献统计等多源异构数据 |
| 重排模型调用超时 | 30秒 | 适配月度/季度的低频数据更新节奏，避免长文本检索超时 |
| 重排模型类型 | 本地开源模型 | 适配社区治理数据的本地化部署需求，降低外部调用风险 |

## 容易做错的三处
- 现象：开启重排开关后，在线召回测试无重排结果返回。原因：未在知识库索引环节同步开启重排配置，或重排模型的调用路径未正确绑定至当前检索流程。
- 现象：本地重排模型部署后，界面显示请求错误。原因：重排模型的监听端口未开放，或FastGPT配置的模型地址与实际部署地址不匹配。
- 现象：使用ollama重排模型通过oneAPI接入时，界面返回Invalid URL (POST /v1/rerank)。原因：oneAPI未正确配置重排模型的接口路径，或ollama的重排模型未启动对应服务端口。

## 怎么确认配好了
- 进入知识库的检索测试页面，输入包含角色权限或治理规则的测试问题，查看返回结果是否包含重排环节的排序标记。
- 检查检索模式是否设置为混合检索，确认已绑定的数据源包含贡献统计、会议纪要等本品类核心数据。
- 查看重排模型的运行日志，确认无连接超时或参数错误的报错信息。
- 调整相似度阈值的测试区间，验证检索结果的相关性是否符合业务预期。
