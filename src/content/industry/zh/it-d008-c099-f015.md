# 移动端开发的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
移动端开发的运维与工单数据主要来自代码仓库、应用商店后台、崩溃监控平台、机型覆盖数据，更新频率为每日或每版本发布周期。日常使用的文档包括端版本发布单、适配清单、崩溃分析报告、应用商店审核资料，其中端版本发布单包含版本号、适配机型范围等字段，适配清单标注系统版本与权限配置项，崩溃分析报告记录机型与系统版本的异常数据，应用商店资料包含审核要求与版本描述字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散导致需要跨系统关联检索，需优先匹配机型、系统版本等核心字段；更新频率较高要求检索需支持实时或近实时的文档更新同步；文档结构多样，既有结构化的清单类文档，也有非结构化的分析报告，需适配不同格式的内容召回；工单问题多聚焦权限排查、机型适配、审核规则等细分场景，需避免无关品类的文档干扰检索结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 移动端开发文档多为技术细节，该区间可平衡召回精准度与覆盖范围，适配FastGPT v4.17.0版本的语义匹配逻辑 |
| `limit` | 前8条 | 移动端开发工单通常聚焦单一场景，过多结果会干扰工程师快速定位问题 |
| `searchMode` | 语义检索 | 开发问题多为模糊技术排查，语义匹配比关键词匹配更能匹配隐含的技术场景 |
| `usingReRank` | 开启 | 多机型适配类文档相似度接近，重排可提升关键内容的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 开发问题常伴随缩写或行业术语，扩展查询可覆盖更多相关文档 |
| `collectionIds` | 绑定移动端开发专属知识库集合 | 隔离其他品类数据，避免无关内容干扰检索结果 |

## 容易做错的三处
- 现象：对话时而触发知识库检索，时而不触发。原因：未固定开启全局检索配置，或未启用`datasetSearchUsingExtensionQuery`导致部分输入未触发扩展检索逻辑。
- 现象：同窗口多轮对话后检索耗时显著增加，新窗口则恢复正常。原因：未限制上下文窗口长度，累积的历史对话挤占检索资源，导致`limit`参数的实际生效范围被压缩。
- 现象：混合检索结果比语义检索效果更差。原因：未针对移动端开发的技术文档调整`searchMode`，混合检索的关键词权重会干扰语义匹配的精准度。

## 怎么确认配好了
- 发起包含机型适配关键词的查询，检查返回结果是否包含适配清单文档的核心字段。
- 连续发起3轮同类查询，观察检索耗时波动是否符合预期。
- 切换`searchMode`为混合检索，对比返回结果的精准度，确认语义检索更适配当前场景。
- 检查`collectionIds`配置，确认未包含非移动端开发的知识库集合。
