# 等级保护测评咨询的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的核心数据来自测评工具导出的原始数据、项目访谈记录、资产系统清单与安全设备日志。日常产出的标准化文档包括定级报告、差距分析报告、整改方案与测评报告，每份文档包含控制项编号、合规要求、差距描述、整改措施等固定字段。数据更新以单个项目为周期，单个项目周期内仅随整改进度、测评结果更新，无高频迭代需求。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据以单个项目为单位更新且文档结构固定，知识库无需频繁全量同步，仅需在项目完成后增量更新即可。文档中存在大量标准化控制项内容，检索时需精准匹配控制项编号与合规要求字段，避免无关结果干扰。单份文档内容较长，需合理控制召回片段长度，确保检索结果覆盖核心整改与测评环节，同时避免冗余信息占用上下文空间。此外，内部工单与运维值班场景下，检索需求多围绕当前项目的具体问题，需优先召回对应项目的专属文档内容。

以下配置基于FastGPT v4.17.0版本，适配等保测评咨询场景的知识库检索需求：

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配等保文档中标准化控制项的精确性要求，平衡召回精度与覆盖范围 |
| `limit` | 前8条 | 覆盖单个项目下的主要控制项与文档片段，兼顾检索效率与结果完整性 |
| `usingReRank` | 开启 | 对长文档拆分后的片段进行二次排序，提升控制项相关内容的召回优先级 |
| `searchMode` | vector + hybrid | 结合语义向量与关键词匹配，同时覆盖控制项编号等结构化字段与整改描述等非结构化内容 |
| `collectionIds` | 按当前项目绑定 | 限定检索范围为当前运维工单对应的项目知识库，避免跨项目文档干扰 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充项目相关的上下文描述，提升针对特定工单问题的召回准确性 |

## 容易做错的三处
- 检索得分出现4000+的异常数值，原因是未正确配置`similarity`参数的归一化逻辑，或使用了非标准的相似度计算方式。
- 无法召回指定知识库文档，原因是未通过`collectionIds`绑定对应项目的知识库集合，或文档未正确导入到指定集合中。
- 复杂表格无法被正确检索，原因是文档拆分时未保留表格结构的语义关联，导致片段匹配失效。

## 怎么确认配好了
- 手动输入某份定级报告中的控制项编号，验证检索结果包含对应片段。
- 查看检索结果的`similarity`得分，确认数值处于0-1区间内。
- 传入指定项目的`collectionIds`，验证检索结果仅包含该项目的文档。
- 提交包含复杂表格的查询，确认召回结果包含表格的核心内容。
