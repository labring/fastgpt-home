# 续费健康度管理的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
这个细分品类的数据通常来自CRM系统、产品使用数据、内部工单统计与合同台账。日常产出的文档包含客户健康度报告、续费预测表、风险客户清单与沟通纪要。数据更新频率多为周度或月度，字段涵盖客户基础信息、合同周期、产品使用频次、工单响应情况与风险等级标识，数据格式不统一，部分为结构化表格，部分为非结构化文本记录。

## 这些特征在「重排与混合检索」这一环带来什么约束
多源异构的数据来源要求混合检索需同时支持结构化字段召回与非结构化文本检索，需配置适配多类型数据的召回规则。周/月级别的更新频率意味着无需高频触发重排任务，可按固定周期执行重排以降低计算开销。文档包含风险客户清单等优先级明确的内容，重排环节需基于业务字段设置权重，优先召回距离合同到期日较近、工单数量较多的高风险客户数据，避免运维值班时被低优先级信息干扰。内部工单问答的场景要求检索结果简洁精准，需控制返回结果的数量与排序逻辑，匹配一线运维与客户成功人员的使用习惯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `usingReRank` | 开启 | 该场景需优化高风险客户数据的排序优先级，重排可提升关键信息的展示顺位 |
| `searchMode` | hybrid | 需同时召回结构化客户台账字段与非结构化沟通纪要内容，混合检索模式适配多源数据类型 |
| `similarity` | 0.75–0.85 | 平衡精准召回与覆盖范围，适配续费健康度管理的风险客户检索需求 |
| `limit` | 前10条 | 控制返回结果数量，避免运维值班时信息过载，符合内部工单问答的简洁性要求 |
| 重排模型调用方式 | 优先使用开源本地模型，按需调用API | 开源模型可保障内部数据隐私，API模型可适配更高算力需求，符合企业内部安全规范 |
| 重排触发时机 | 按周触发 | 匹配业务数据周/月的更新频率，避免不必要的重排计算开销 |

## 容易做错的三处
- 现象：创建应用时无法勾选重排模型选项，配置项显示灰色。原因：未在`usingReRank`配置项中开启重排功能，或未在系统配置中加载重排模型文件。
- 现象：添加重排模型后，知识库检索结果顺序未发生变化。原因：未将`searchMode`设置为hybrid模式，或重排模型的调用阈值设置过高，导致未触发重排逻辑。
- 现象：调用重排模型时出现超时报错。原因：未配置合理的`limit`参数，返回结果过多导致重排计算超时，或开源重排模型的部署算力不足。

## 怎么确认配好了
- 进入FastGPT v4.17.0应用的检索配置页面，确认`usingReRank`开关处于开启状态。
- 发起一条针对高风险客户的检索请求，查看返回结果的排序是否优先展示距离合同到期日较近的客户数据。
- 检查系统后台日志，确认重排模型已成功调用，无报错信息。
- 对比开启重排前后的检索结果顺序，验证重排逻辑已生效。
