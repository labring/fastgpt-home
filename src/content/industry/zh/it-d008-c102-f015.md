# 缺陷管理与回归测试的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源为缺陷管理系统、测试报告、代码提交记录与用户反馈，更新频率为每日或每版本发布周期。日常处理的文档包含标准化缺陷单、版本回归清单、修复验证记录、缺陷统计报表，字段包含缺陷ID、优先级、复现步骤、修复版本、验证结果等，部分文档为半结构化的表格或文本记录，数据结构围绕缺陷全生命周期展开。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且更新频率为每日或每版本，要求检索环节需支持快速同步最新的缺陷与验证记录，避免使用过期数据。文档结构围绕缺陷生命周期设计，包含明确的优先级、复现步骤等字段，要求检索需精准匹配关键字段，避免召回低相关内容。高优缺陷遗漏会引发版本延期或客户投诉，要求召回结果需具备足够置信度，同时单篇文档长度与召回条数需适配上下文窗口，防止token超限影响回答效率。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配缺陷单的精准字段，过滤低相关的历史记录，避免干扰优先级判定 |
| `limit` | 前10条 | 控制召回条数，适配缺陷管理文档的单篇长度，防止总token超出上下文窗口 |
| `searchMode` | semantic | 针对复现步骤、修复记录的语义匹配，快速定位同类缺陷的解决方案 |
| `usingReRank` | 开启 | 对召回结果重排，优先展示高优先级缺陷的验证记录，提升决策效率 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 缺陷管理文档结构固定，无需扩展查询词，避免引入无关检索结果 |
| `collectionIds` | 绑定指定缺陷管理知识库ID | 限定检索范围，排除其他品类的文档，确保召回结果仅关联缺陷管理数据 |

## 容易做错的三处
- 现象为单次回答token超过3000，即使输入问题简短。原因是将`limit`设置为2000，召回的文档总长度超出上下文窗口。
- 现象为知识库搜索结果直接展示在界面，后续AI回答重复输出相同内容。原因是未关闭搜索结果的直接输出开关，导致工作流中两次输出检索结果。
- 现象为召回结果无法精准匹配目标缺陷的复现步骤。原因是未按缺陷单的标准化结构组织文档，导致嵌入模型无法识别关键字段信息。

## 怎么确认配好了
- 发起包含高优缺陷关键词的测试查询，核对召回结果的匹配得分是否符合预设区间。
- 查看工作流输出日志，确认仅在指定环节输出检索结果，无重复的检索内容展示。
- 导入一份标准缺陷单文档，发起匹配查询，确认召回结果包含该文档的核心字段信息。
- 调整`limit`参数，验证召回条数符合预期，且总token未超出上下文窗口限制。
