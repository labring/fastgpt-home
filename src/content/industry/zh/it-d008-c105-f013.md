# 许可证合规与版权声明的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
本品类的数据主要来自代码仓库、依赖清单、许可证文本与贡献记录，日常文档包含LICENSE文件、NOTICE文件、依赖许可证清单与版权声明。数据按项目版本或依赖变更频率更新，字段包含许可证类型、版权持有者、依赖包名、版本号与更新时间。不同项目的合规数据相互独立，无跨项目的默认关联关系。

## 这些特征在「权限与数据隔离」这一环带来什么约束
数据来源分散且更新频繁，要求权限配置需匹配数据的归属维度，避免跨项目数据泄露。不同项目的合规文档无默认关联，需通过团队维度绑定数据，防止非授权人员访问其他项目的许可证与版权信息。更新频率高的特性要求权限配置支持实时或定时同步，确保合规数据的权限规则及时生效。出错后果涉及许可证违规与商业使用受阻，需严格限制敏感合规数据的编辑与查看范围。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `teamId` | 绑定项目所属团队的唯一标识 | 匹配合规数据的归属团队，适配FastGPT v4.17.0的团队权限逻辑 |
| `tmbId` | 关联成员的团队归属标识 | 校验成员是否具备对应项目的合规数据操作权限 |
| 数据同步间隔 | 每 12 小时 | 匹配依赖变更与版本发布的更新频率 |
| 单次同步依赖数量上限 | 前 500 条 | 控制接口请求负载，避免同步超时 |
| 单项目合规数据存储上限 | 1000 MB | 限制单项目合规文档的存储规模，避免资源占用过高 |
| 敏感数据可见范围 | 仅团队维护者可查看 | 防止非授权人员访问版权声明与许可证兼容性信息 |

## 容易做错的三处
- 现象：调用关联许可证数据的接口返回无相关内容。原因：未通过`teamId`绑定数据归属团队，跨团队请求时未过滤非本项目的依赖清单与版权声明。
- 现象：团队维护账号无法编辑NOTICE文件。原因：未配置敏感数据可见范围为仅维护者可操作，误开放了全团队编辑权限。
- 现象：非授权成员看到其他项目的许可证文本。原因：未设置单次同步依赖数量上限，跨项目数据未按团队维度过滤展示。

## 怎么确认配好了
- 登录非团队维护账号，尝试访问合规文档页面，确认无权限访问对应项目的LICENSE与NOTICE文件。
- 提交跨团队的合规数据查询请求，确认返回结果仅包含本项目的依赖许可证清单与版权声明。
- 修改项目的许可证数据后，触发手动同步，确认数据在配置的同步周期内完成更新。
- 进入团队管理页面，确认仅维护账号可配置权限规则与查看成员使用记录。
