# 许可证合规与版权声明的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的服务对象为开源办公室、项目维护者与法务人员，数据主要来自代码仓库、依赖清单、许可证文本与贡献记录。日常维护的文档包含LICENSE文件、NOTICE文件、依赖许可证清单与版权声明。LICENSE文件包含许可条款与版权归属声明，NOTICE文件汇总第三方依赖的版权信息，依赖许可证清单以结构化格式记录依赖名称、版本、许可证类型与版权持有者，贡献记录则标注代码提交者与对应版权归属。数据更新频率为每版本发布或每次依赖变更时触发。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征决定了检索召回需适配多类结构化与非结构化文档。依赖许可证清单的结构化属性要求检索支持按依赖名称、版本字段过滤，避免匹配无关依赖的合规信息。数据更新频率较高，检索环节需支持增量同步机制，确保每次版本或依赖变更后，知识库能快速获取最新内容。不同文档的语义差异较大，比如LICENSE文件的专业条款与NOTICE文件的汇总信息，需要检索模型能精准区分不同场景下的合规需求，同时避免召回无关的代码提交记录。此外，合规内容的准确性直接影响业务风险，检索召回的结果需具备高置信度，不能遗漏关键的许可证条款或版权声明。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配许可证文本与依赖声明的语义相似度，平衡精准度与召回范围，适配合规内容的专业语义特征 |
| `limit` | 前10条 | 覆盖常见的许可证类型与依赖项，避免过多结果超出FastGPT v4.17.0的上下文窗口限制 |
| `searchMode` | vector_search | 针对许可证文本的专业语义匹配需求，优先使用向量检索，提升合规内容的召回准确性 |
| `usingReRank` | 开启 | 对召回结果进行重排，优先返回最相关的许可证合规内容，减少无关结果的干扰 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展查询词，比如将“GPL协议”扩展为对应许可证文本的关键词，提升跨文档的召回覆盖度 |
| `collectionIds` | 按实际部署的许可证合规知识库集合ID填写 | 限定检索范围仅包含LICENSE、NOTICE等合规文档，避免混入其他无关的项目数据 |

## 容易做错的三处
- 现象：工作流中仅第一个问题触发知识库引用，后续问题无知识库结果。原因：未配置会话级的数据集ID持久化，或检索节点未绑定全局变量的正确引用路径。
- 现象：导入中英文对照的知识库后，大模型未读取对应中文内容。原因：检索配置未适配中文语义的向量生成，或`datasetSearchUsingExtensionQuery`未针对中文关键词做扩展。
- 现象：关联知识库后，模型提示未提供具体知识库内容。原因：`collectionIds`配置为空或填写错误，检索范围未覆盖目标许可证合规文档集合。

## 怎么确认配好了
- 手动触发知识库检索节点，输入“MIT许可证条款”，核对返回结果是否包含对应LICENSE文件的核心内容。
- 查看检索节点的运行日志，确认召回结果的条数与`limit`配置的取值一致。
- 测试多轮对话，依次输入“Apache 2.0协议”“当前项目的依赖许可证清单”，验证后续问题能否正确召回相关合规内容。
- 检查数据集的同步状态，确认最新的依赖许可证清单与NOTICE文件已完成增量导入。
