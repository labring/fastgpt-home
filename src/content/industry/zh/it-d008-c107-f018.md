# 账号封禁与申诉复核的运维值班与内部工单问答：重排与混合检索

## 这个品类的数据长什么样
该品类的数据主要来自风控系统、审核记录、用户行为日志与举报证据。日常处理的文档包含账号封禁记录、用户申诉材料、复核意见与用户通知。数据更新节奏分为实时与每日两种。单条数据通常包含账号唯一标识、违规行为类型、申诉提交时间、审核状态、关联证据路径等字段，字段随平台治理规则调整，无统一固定的字段单位。

## 这些特征在「重排与混合检索」这一环带来什么约束
多源异构的数据来源要求混合检索兼容风控日志、审核文档、申诉材料等不同格式与字段的内容，实时与每日更新的节奏则要求检索链路具备低延迟的增量索引刷新能力。单条数据包含账号标识、违规类型等差异化字段，重排环节需要针对账号级关联证据、申诉理由的语义匹配度进行加权排序。同时，该品类的出错后果直接关联用户权益，重排需要优先匹配申诉材料与违规证据的核心关联点，避免无关内容干扰关键判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 重排开关 | 开启 | 该品类需过滤低相关的召回结果，重排可提升申诉材料与违规证据的匹配优先级 |
| 相似度阈值 | 0.70–0.88 | 适配账号封禁场景的文本匹配精度，该区间可平衡误封风险与申诉通过率，按FastGPT v4.17.0版本实测标定 |
| 单次搜索上限 | 前8–12条 | 控制单轮检索返回结果数量，适配运维值班人员的快速浏览需求，符合内部工单的处理节奏 |
| 搜索模式 | 混合检索 | 需混合召回风控系统日志、审核记录、申诉材料等多源数据，混合模式可兼顾精确匹配与语义召回 |
| 重排返回条数 | 前5–7条 | 聚焦核心关联内容，避免冗余信息干扰运维值班人员的复核判断，按FastGPT v4.17.0版本实测标定 |

## 容易做错的三处
- 配置离线重排模型后启动报错，界面提示`rerank error fastgpt | { message: { detail: `。原因：未正确配置模型路径或依赖包缺失，导致FastGPT无法加载离线重排模型文件。
- 创建应用时无法勾选结果重排的模型选项。原因：未在全局配置文件中正确注册重排模型，或注册的模型格式不符合FastGPT要求。
- 混合检索返回结果与申诉材料关联度极低。原因：未设置合理的相似度阈值与重排权重，导致低相关的风控日志干扰核心匹配结果。

## 怎么确认配好了
- 进入FastGPT应用配置页面，确认重排开关已开启，搜索模式设置为混合检索。
- 上传一条测试申诉材料与关联违规证据，执行检索后查看返回结果的排序逻辑，确认高相关内容优先展示。
- 检查全局配置文件，确认已正确注册所需的重排模型，且无模型加载相关的报错日志。
- 模拟实时更新的数据接入，确认检索链路可在合理时间内返回结果。
