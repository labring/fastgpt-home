# 身份账号与权限管理的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自企业IAM系统、HR系统、业务系统日志与审批系统，更新节奏为每日同步或随人事变动触发。日常运维文档包含标准化的账号申请单、权限矩阵表、离职账号回收单与合规审计报告，文档字段包含账号ID、权限范围、生效时间、审批状态、关联业务系统等，单份文档长度跨度较大，从数十行的审批单到数百行的权限矩阵均有覆盖。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散导致不同文档的格式差异明显，检索时需适配结构化表格与非结构化文本的混合输入。更新频率灵活且触发无固定周期，需支持增量召回与全量重建的切换。文档包含敏感权限字段，检索结果需严格控制可见范围，避免越权访问风险。单份文档长度差异大，需适配不同长度的分块规则，避免长文本截断丢失关键权限信息。同时运维值班场景要求检索响应速度快，需平衡召回数量与查询耗时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 适配权限类文档的语义匹配精度，避免低相关结果混入，同时保留足够的召回候选 |
| `limit` | 前 10 条 | 平衡运维值班场景下的信息密度与检索速度，避免过多结果导致值班人员无法快速定位 |
| `searchMode` | 语义召回 | 适配权限矩阵、审计报告这类半结构化与非结构化文档的检索需求，匹配关键词与语义关联 |
| `usingReRank` | 开启 | 对召回结果进行二次排序，优先展示包含最新权限变更的文档，符合运维场景的时效性需求 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于原始问题生成扩展查询词，覆盖账号ID、权限范围这类专业术语的检索，提升召回率 |
| `collectionIds` | 绑定IAM、审批系统专属知识库集合 | 限定检索范围，避免无关文档干扰，确保仅返回身份账号与权限管理相关的内容 |

## 容易做错的三处
- 执行全量重建索引后检索结果无更新，原因是未正确指定`collectionIds`参数绑定目标知识库集合，导致重建操作未作用于权限管理专属数据集。
- 检索结果中同质化的权限矩阵文档排序混乱，原因是未开启`usingReRank`，未按文档更新时间或关联的人事变动时间进行权重调整。
- 检索返回的结果包含未授权的敏感权限字段，原因是未配置检索结果的权限过滤规则，直接返回了原始文档的全部内容。

## 怎么确认配好了
- 执行一次测试检索，输入“离职账号回收流程”，核对返回结果是否仅包含身份账号与权限管理相关文档，无其他业务系统的无关内容。
- 上传一份新的权限矩阵文档，等待1小时后执行检索，确认新文档可被正常召回。
- 查看FastGPT v4.17.0的检索日志，确认`usingReRank`和`datasetSearchUsingExtensionQuery`参数已生效，无报错记录。
- 调整`similarity`参数至0.8，检索“账号越权排查”，核对返回结果的相关度是否符合预期。
