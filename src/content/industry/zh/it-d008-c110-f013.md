# 运维外包驻场服务的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
该品类的数据通常来自客户ITSM系统、监控平台、资产清单及内部值班记录。日常产出驻场日报、服务台工单、巡检报告、SLA月报四类文档，其中驻场日报按日更新，包含当日现场处理事项与巡检情况；SLA月报按月汇总，涵盖服务达标率、工单响应时长等字段。各类数据均绑定对应客户的驻场服务合同，字段随客户IT资产配置、服务范围调整而变化。

## 这些特征在「权限与数据隔离」这一环带来什么约束
不同客户的驻场服务数据存在严格的合同边界，需避免跨客户数据泄露。按日更新的驻场日报、工单数据时效性强，权限配置需支持实时校验访问主体的服务范围。按月生成的SLA月报涉及客户服务考核指标，需锁定对应租户的编辑与查看权限。驻场工程师仅能访问负责区域的客户IT资产数据，无法越权查看其他客户的运维信息。同时，数据来源涉及客户自有系统，需隔离外包团队与客户内部IT部门的访问权限，防止敏感资产信息泄露。

## 配置怎么定
本章节配置适用于FastGPT v4.17.0版本：

| 配置项               | 建议取法                                       | 这样取的依据 |
| ----------------------|----------------------------------------------|---------------------------------------------- |
| 租户隔离配置         | 为每个驻场服务项目创建独立租户                     | 匹配不同客户的服务合同边界，避免跨客户数据混淆 |
| 团队权限绑定         | 按驻场工程师的负责区域分配专属权限组                 | 限制工程师仅能访问对应客户的运维数据 |
| 数据存储分区         | 按租户划分独立存储目录，单租户存储上限设为1000 MB       | 确保工单、驻场日报等数据物理隔离，防止资源抢占 |
| 访问时效校验         | 为日更数据配置1小时内的访问有效期                   | 适配驻场日报的实时性要求，防止过期敏感数据泄露 |
| 权限审计日志         | 开启全量访问日志记录，日志保留时长设为30天             | 便于追溯跨权限访问行为，符合服务合同的合规要求 |
| 模型密钥隔离         | 为每个租户绑定专属模型调用密钥                     | 按租户隔离模型费用统计，匹配商业版权限需求 |

## 容易做错的三处
- 现象：跨客户的驻场工单数据被非授权驻场工程师查看。原因：未按驻场服务项目配置独立租户权限，导致不同客户的运维数据未做有效隔离。
- 现象：本地部署环境中无法启用团队级权限管理功能。原因：未完成租户管理模块的初始化配置，导致权限隔离逻辑未加载。
- 现象：不同客户的SLA月报数据被错误合并展示。原因：未按租户划分数据存储分区，导致检索时返回跨租户的历史数据。

## 怎么确认配好了
- 登录不同租户的后台，尝试访问其他租户的工单数据，确认无权限访问。
- 查看权限审计日志，确认所有访问操作均记录了对应租户与访问主体的信息。
- 导出指定租户的驻场日报数据，确认仅包含该服务项目的相关内容。
- 验证模型调用密钥的绑定关系，确认不同租户的密钥无法跨租户使用。
