# 运维外包驻场服务的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据通常来自客户ITSM系统、监控平台、资产清单及值班记录。日常生成的文档包含驻场日报、服务台工单、巡检报告、SLA月报，数据更新频率分为日更与月更两类。文档结构多以结构化字段为主，例如驻场日报包含巡检时段、处理事项、反馈结果，SLA月报包含服务达标率统计项，字段无统一强制标准格式，需按外包服务的交付要求整理。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多来源的异构数据带来检索范围的适配需求，需兼容不同系统导出的非标准化格式内容。日更的工单与值班记录要求检索响应速度匹配现场处理的时效性，月更的SLA月报则允许稍长的召回延迟。驻场场景下的检索需覆盖驻场工程师的现场操作参考、服务经理的合同交付依据，且需避免召回无关的客户内部敏感数据。同时，出错后果直接关联服务合同履约，需严格控制检索结果的准确性与相关性。

## 配置怎么定
本文适配FastGPT v4.17.0版本的知识库检索配置逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 匹配驻场工单的场景需求，平衡召回相关性与覆盖范围，避免遗漏关键处理步骤 |
| `limit` | 前8条 | 适配现场值班时的快速查阅需求，单次返回条目足够覆盖常见运维场景，同时控制检索耗时 |
| `searchMode` | semantic | 针对驻场日报、巡检报告的非结构化内容，通过语义匹配召回相关处理经验 |
| `usingReRank` | 开启 | 优化召回结果的排序，优先返回与当前工单最匹配的处理方案，降低现场决策成本 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 驻场服务的知识库为固定交付文档，避免模型生成额外内容偏离服务要求 |
| `collectionIds` | 指定驻场服务专属集合ID | 隔离客户内部其他非外包相关数据，确保检索范围仅覆盖合规的服务文档 |

## 容易做错的三处
- 检索返回条目不足，仅返回1条结果。原因是`limit`配置取值过低，未覆盖驻场场景下多步骤处理的参考需求。
- 检索结果混入非专属集合的文档。原因是未指定`collectionIds`为驻场服务专属集合，导致召回无关的客户内部敏感数据。
- 知识库内的专有运维术语被错误拆分。原因是未配置对应字段的禁止拆分规则，导致术语被拆分后影响检索准确性。

## 怎么确认配好了
- 导入一份驻场日报样本，执行检索测试，核对返回结果是否包含该文档的相关内容。
- 查看FastGPT的检索日志，确认`limit`与`similarity`参数生效，返回结果符合配置取值范围。
- 尝试检索非专属集合的文档，确认未被召回，验证数据隔离配置生效。
- 模拟现场工单提问，核对召回结果仅包含知识库内的原文片段，未出现模型生成的额外内容。
