# 配置管理与CMDB维护的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
该品类数据主要来自企业CMDB系统、云资源清单、自动发现工具与采购台账，包含配置项清单、服务组件依赖拓扑、变更记录、资产盘点表四类核心文档。数据字段包含配置项唯一标识、组件依赖关系、变更时间、资产归属部门等，更新频率为每日或每周，单条资产数据包含物理或虚拟资源的基础属性与关联关系信息。

## 这些特征在「权限与数据隔离」这一环带来什么约束
该品类数据覆盖多业务部门的资产与依赖关系，不同角色仅能访问对应职责范围内的配置项。依赖拓扑数据包含跨组件关联信息，未授权访问可能泄露未公开的服务链路。数据按日或周更新，权限规则需随资产变更同步调整。多来源的数据需统一权限校验入口，避免出现跨系统权限不一致的情况，同时需限制敏感字段（如采购台账）仅对授权管理员可见。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 团队权限绑定 | 按`teamId`绑定对应CMDB数据分组 | 匹配不同运维团队负责的资产范围，避免跨团队访问未授权配置项 |
| 角色权限配置 | 按`tmbId`分配前3级操作权限 | 区分管理员、值班工程师、实习生等角色的访问与编辑权限 |
| 数据隔离范围 | 按资产归属部门划分 | 限制不同部门仅能查看本部门的配置项清单与拓扑 |
| 敏感字段掩码 | 隐藏采购台账的采购金额字段 | 避免敏感财务信息泄露，符合运维数据权限要求 |
| 权限同步周期 | 每日凌晨2点（1天周期） | 匹配数据日更频率，确保权限规则与资产变更同步 |
| 权限校验超时 | 600秒 | 避免长耗时校验导致的页面卡顿，适配CMDB数据的查询延迟 |

## 容易做错的三处
- 现象：测试调用本地部署模型时提示权限错误，界面返回“无访问权限”报错。原因：未将当前团队的`teamId`配置到模型调用的权限白名单中，导致跨团队调用被拦截。
- 现象：实习生账号无法访问部分知识库文档，却能查看全量配置项拓扑。原因：未按`tmbId`配置角色权限范围，仅限制了文档访问未限制拓扑数据的查看。
- 现象：资产更新后权限规则未同步生效。原因：权限同步周期设置为每周一次，未匹配数据日更的更新频率，导致权限滞后。

## 怎么确认配好了
- 登录FastGPT v4.17.0后台，进入团队管理页面，验证`teamId`与CMDB数据分组的绑定关系是否正确。
- 切换不同角色账号，尝试访问对应职责范围内的配置项清单与拓扑，确认无权限访问的内容被拦截。
- 手动触发一次资产更新，检查权限规则是否在设定的同步周期内完成更新。
- 查看敏感字段掩码配置，确认采购台账等敏感数据已被正确隐藏。
