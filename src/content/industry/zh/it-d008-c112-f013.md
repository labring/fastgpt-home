# 问题管理与根因分析的运维值班与内部工单问答：权限与数据隔离

## 这个品类的数据长什么样
问题管理与根因分析的运维数据，来源为故障时间线、系统日志、监控指标、代码提交记录，更新频率为每次重大故障或每月一次。日常产出的文档包括RCA报告、问题单、复盘纪要、整改跟踪表，其中RCA报告包含故障时间、根因分析结论、整改项；问题单包含故障编号、责任团队、处理进度；整改跟踪表包含整改项编号、完成状态、验收时间。数据字段多涉及生产环境敏感信息，无统一固定的单位，随具体故障场景变化。

## 这些特征在「权限与数据隔离」这一环带来什么约束
数据来源包含生产监控与代码提交记录，涉及生产环境权限，因此需要严格按业务团队划分数据访问范围，避免跨团队泄露敏感运维信息。日常文档多为团队内部敏感复盘材料，需确保仅责任团队成员可查看与编辑。数据更新频率较低但单次数据量较大，权限校验需支持按团队维度批量绑定数据，避免单次校验开销过大。整改跟踪表关联具体业务域，需确保不同业务域的整改数据互不交叉，防止跨域整改信息泄露。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `teamId` | 绑定故障所属业务团队的唯一标识 | 匹配RCA报告、问题单的归属团队属性，确保数据仅对对应团队可见 |
| `teamId` | 按整改跟踪表的责任团队划分 | 对应业务事实中的整改跟踪表归属，避免跨团队访问整改数据 |
| `tmbId` | 绑定监控指标的所属集群ID | 匹配故障时间线、监控指标的集群范围，隔离不同集群的运维数据 |
| 团队数据隔离范围 | 仅开放当前团队近30天的RCA报告与问题单 | 符合数据更新频率为每月或每次重大故障的特征，避免数据过期泄露 |
| 插件调用权限配置 | 限制为团队内部成员可调用，单次返回前5条问题单 | 匹配运维值班与内部工单的使用场景，防止外部人员调用根因分析工具 |
| 团队邀请有效期 | 7天 | 确保受邀成员在合理时间内完成团队加入流程，避免邀请过期失效 |

## 容易做错的三处
- 现象：跨团队成员仍能访问当前团队的RCA报告与问题单。原因：未将`teamId`正确绑定到对应故障的归属团队，导致权限校验未生效。
- 现象：团队自定义插件无法作为工具调用，且无相关配置入口。原因：未开启团队插件的工具调用权限配置，或未将插件关联到对应`teamId`。
- 现象：发送团队邀请后，受邀成员未收到任何通知且无法查看团队数据。原因：未配置团队邀请的通知触发规则，或`tmbId`未正确关联邀请的目标团队。

## 怎么确认配好了
- 切换到非归属团队的账号，尝试访问对应团队的RCA报告，确认无法查看该团队的敏感运维数据。
- 调用根因分析工具，检查返回结果仅包含当前`teamId`绑定的故障日志、监控指标与问题单。
- 发送团队邀请，确认受邀成员在7天有效期内收到通知，并能成功加入对应团队查看数据。
- 配置多团队后，确认每个团队的根因分析数据仅对本团队成员可见，无跨团队数据泄露。
