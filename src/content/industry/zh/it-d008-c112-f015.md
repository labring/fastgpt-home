# 问题管理与根因分析的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源于故障时间线、运行日志、监控指标、代码提交记录。更新节奏为每次重大故障后更新，月度累计归档。核心文档包含RCA报告、问题单、复盘纪要、整改跟踪表，字段包含故障唯一标识、根因定位描述、关联监控指标、整改闭环状态，无额外统计类量化字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据以长文本的故障复盘文档为主，且依赖时序类、指标类关联数据，要求检索召回需支持跨文档的关联匹配。由于更新频率较低，无需频繁触发知识库增量同步，但需保证历史故障数据的召回精准度。文档结构固定包含根因描述、整改项等核心字段，检索逻辑需优先匹配根因相关关键词，避免无关内容干扰。同时数据来源包含日志与监控指标，需支持多维度的检索匹配规则。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.75–0.85 | 匹配根因描述的核心语义，避免召回无关故障文档 |
| 单次搜索上限 | 前8–12条 | 适配RCA报告的单篇长度，控制上下文总占用 |
| 搜索模式 | 关键词+语义混合 | 同时匹配根因关键词与语义关联，覆盖日志与复盘文档的检索需求 |
| 重排 | 开启 | 对召回结果二次排序，提升根因相关文档的展示优先级 |
| 问题优化 | 开启 | 自动扩展根因相关的同义词，覆盖不同运维人员的表述差异 |
| 指定检索集合 | 绑定故障复盘与工单集合ID | 限定检索范围，排除非本品类的无关知识库内容 |
| 最大上下文 | 12000–15000 token | 适配长文本RCA报告的上下文需求，避免截断核心根因内容 |

## 容易做错的三处
- 测试工作流时，回复末尾固定携带固定预设提示语。原因是未在对话配置中关闭默认的系统提示词输出。
- 知识库检索召回结果条数与配置的单次搜索上限不符。原因是未正确绑定指定的检索集合，导致检索范围超出预设。
- 采用docker-compose部署后，过段时间知识库与工作流配置变为空白但接口可用。原因是挂载的配置卷未持久化存储，容器重启后配置文件丢失。

## 怎么确认配好了
- 手动输入一条已知根因的故障关键词，核对召回结果的前3条是否包含同类型的RCA报告。
- 查看检索配置面板，确认相似度阈值、重排、问题优化的开关状态与预设配置一致。
- 导出当前知识库的集合ID列表，核对指定检索集合的配置是否仅包含本品类的故障复盘与工单集合。
- 触发一次工作流测试，检查回复末尾是否无默认系统提示语输出。
