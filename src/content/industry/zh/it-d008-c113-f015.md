# 集成测试与接口测试的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来自接口管理平台、测试环境日志、数据库与消息队列，更新频率为每日或每版本发布时。日常文档包含结构化的接口测试用例（含接口地址、请求参数、预期返回字段）、联调问题单、环境说明文档与测试报告。文档多包含接口标识、请求头、响应状态码、链路节点等字段，部分日志类数据为非结构化文本，需经过解析后纳入知识库。

## 这些特征在「知识库检索与召回」这一环带来什么约束
接口测试相关数据的结构化程度差异较大，非结构化的日志与问题单需要更精准的分块策略，避免检索时混入无关链路信息。数据更新频率较高，需配置适配高频更新的同步机制，防止知识库内容滞后于当前测试环境状态。接口文档的字段多为技术类精准术语，检索时需优先匹配专业词汇，同时需控制召回结果的上下文长度，避免超出模型处理上限。不同来源的数据格式差异明显，需针对接口用例、日志分别配置不同的解析规则，确保检索时的字段匹配准确性。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 接口测试相关内容多为专业技术术语，该相似度区间可平衡召回精度与覆盖范围，过滤低关联的无关结果 |
| `limit` | `前8–12 条` | 接口测试的上下文通常包含多链路节点，适量召回可覆盖完整问题场景，避免遗漏关键配置与报错信息 |
| `searchMode` | `vector` | 本品类数据多包含精准技术字段，向量检索可匹配语义相似的接口参数、链路问题与报错日志 |
| `usingReRank` | `开启` | 接口日志与问题单的语义相似度较高，重排可进一步过滤冗余结果，提升检索精准度 |
| `datasetSearchUsingExtensionQuery` | `开启` | 测试问题常包含缩写或变体术语，问题优化可扩展检索词覆盖范围，匹配更多相关文档 |
| `collectionIds` | `指定接口测试、联调相关的知识库集合ID` | 隔离非相关品类的知识库数据，避免召回无关的业务文档或其他测试类内容 |

## 容易做错的三处
- 现象：检索结果中混入大量非接口测试相关的文档。原因：未配置`collectionIds`限定目标知识库集合，导致召回了其他品类的数据集内容。
- 现象：配置`usingReRank`后检索结果排序无明显变化。原因：未在平台界面开启重排功能的关联开关，或未配置重排模型的调用配额。
- 现象：知识库解析长接口测试用例时出现段落截断。原因：对知识库解析最大段落深度的理解偏差，未根据用例的嵌套结构调整参数，导致长段落未被正确拆分。

## 怎么确认配好了
- 在测试环境发起检索，输入典型的接口测试问题，核对召回结果是否包含指定知识库集合内的文档。
- 调整`similarity`参数的取值，观察检索结果的条数变化，确认阈值生效。
- 开启`usingReRank`后，对比开启前后的检索结果排序，确认重排功能正常运行。
- 触发知识库同步任务，核对更新后的文档是否在预设的更新周期内出现在检索结果中。
