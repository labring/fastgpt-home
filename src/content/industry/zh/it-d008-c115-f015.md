# 项目实施计划管理的运维值班与内部工单问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自合同、工作分解结构（WBS）、客户日程及项目管理系统，日常文档包含项目计划、里程碑清单、周报与风险问题清单。数据更新节奏为每周或每完成一个里程碑时更新，文档结构多包含任务节点、责任人、时间节点、风险等级等字段，无统一固定单位，部分字段需结合具体项目场景匹配对应数值。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散在多个系统，需跨源召回关联不同系统的文档片段；更新以周或里程碑为周期，无需实时增量同步，但需支持周期性批量更新的召回逻辑；日常文档字段多样，需支持多维度语义与关键词匹配，覆盖任务、时间、风险等不同业务维度；运维值班与工单场景下需快速定位对应项目的排期、风险处理方案，对召回结果的时效性与精准度有明确要求，需避免无关项目内容混入检索结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `similarity` | `0.75–0.85` | 项目文档多包含结构化字段与明确业务关键词，该区间可平衡召回精准度与覆盖范围 |
| `limit` | `前8–12条` | 运维值班与工单场景需快速获取关键信息，过多结果会增加一线人员的筛选成本 |
| `searchMode` | `vector+keyword` | 项目文档兼具语义化描述与结构化字段，混合搜索可兼顾语义匹配与关键词精准召回 |
| `usingReRank` | `开启` | 多源召回的结果存在冗余，重排可提升Top结果的相关性，适配快速定位的业务需求 |
| `datasetSearchUsingExtensionQuery` | `开启` | 项目场景下用户提问常省略项目编号、客户名称等上下文，扩展查询可补充隐含信息 |
| `collectionIds` | `绑定对应项目的专属集合ID` | 需隔离不同项目的文档，避免跨项目内容干扰检索结果 |

## 容易做错的三处
- 调用知识库内容添加接口时返回参数缺失报错，原因是未传入项目计划、风险清单等该品类文档的必填字段，仅传入了通用文本内容。
- 表格格式的项目文档检索结果未匹配到结构化字段，原因是未在知识库设置中为表格数据开启多向量支持，仅生成了单文本向量。
- 检索结果包含跨项目的无关文档，原因是未指定`collectionIds`参数，召回了当前租户下所有知识库集合的内容。

## 怎么确认配好了
- 登录FastGPT v4.17.0的知识库管理页面，查看目标表格文档的设置项，确认多向量支持开关已开启。
- 调用检索接口时传入指定的`collectionIds`参数，验证返回结果仅包含对应项目的文档内容。
- 提交包含项目节点、风险等级等关键词的测试提问，查看检索结果是否包含该品类的专属文档。
- 开启`usingReRank`功能后，对比重排前后的Top结果，确认Top3结果的相关性符合业务预期。
