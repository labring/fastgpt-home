# 项目文档移交归档的运维值班与内部工单问答：部署与升级

## 这个品类的数据长什么样
该品类的数据主要来自项目文档库、配置清单、会议纪要、测试报告，更新节奏为每项目阶段结束或整体项目完成时。日常涉及的文档包含竣工文档、配置手册、培训记录、验收证书，数据字段通常包含项目标识、文档版本号、归档时间、签章状态等，数据以单个项目为归集单元，单份文档容量从数十KB到数MB不等，单项目归档包容量可达1000 MB上下。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据分散且格式多样，部署时需支持多源文档批量导入，适配竣工文档、验收证书等不同格式的文件上传与解析。由于数据更新节奏随项目阶段波动，升级环节需兼容历史归档数据的无损迁移，避免版本升级导致的文档记录丢失。同时，数据需关联项目标识与签章状态，部署时需配置对应的权限校验与存储路径，确保归档数据的可追溯性，支撑后续运维值班与内部工单问答的信息准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `DB_MAX_LINK` | `100–200 个连接` | 该品类单项目归档包容量可达1000 MB，多文档并发读取与内部工单的文档查询需足够连接数支撑 |
| `STORAGE_S3_ENDPOINT` | 按私有化部署的对象存储服务商地址填写 | 该品类的竣工文档、验收证书等需存储在私有化环境中，确保归档数据不被未授权访问 |
| `FILE_TOKEN_KEY` | `32 位随机字符串` | 需保障归档文档与对话记录的访问权限，避免敏感运维文档泄露 |
| `REDIS_URL` | `本地 Redis 服务地址` | 该品类的运维值班与工单问答需缓存会话记录与文档索引，本地部署可降低访问延迟 |
| `FE_DOMAIN` | 部署服务器的公网域名或内网 IP | 需确保运维值班人员可通过指定地址访问对话页面，查看历史工单与归档文档 |
| `ROOT_KEY` | 按实测标定的管理员密钥 | 需限制仅授权人员可配置归档规则与系统参数，保障数据安全 |

## 容易做错的三处
- 升级FastGPT v4.17.0后刷新对话页面，对话记录显示为空，仅展示新对话。原因是升级时未正确迁移`REDIS_URL`对应的会话缓存配置，导致历史会话数据未被加载。
- 批量导入竣工文档时出现部分文件上传失败，提示存储路径错误。原因是未正确配置`STORAGE_S3_ENDPOINT`的访问权限，导致无法写入归档存储目录。
- 配置TTS模型后无法正常生成归档文档的语音播报。原因是未同步`FILE_TOKEN_KEY`到TTS服务的配置项中，导致文档音频无法正常调用。

## 怎么确认配好了
- 登录系统后台，查看`DB_MAX_LINK`的配置值是否与预设的连接数一致，测试多文档并发导入时无连接超时报错。
- 上传一份竣工文档，检查是否能正常存储到指定的`STORAGE_S3_ENDPOINT`对应目录，且可通过配置的`FE_DOMAIN`地址访问。
- 发起一条内部运维工单，查看会话记录是否正常保存，刷新页面后历史对话未丢失。
- 测试TTS模型调用，确认可生成对应归档文档的语音播报内容。
