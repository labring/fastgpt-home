# CDN与边缘加速配置的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
CDN与边缘加速配置的核心数据来自CDN控制台、DNS解析记录、用户访问日志与监控告警系统。日常产出的文档包括域名接入单、缓存规则配置表、刷新预热操作记录、故障分析报告。数据更新频率为每日或随配置变更实时更新，字段包含域名、缓存策略类型、刷新预热量、边缘节点状态、告警阈值等，单条文档长度差异较大。

## 这些特征在「上下文与 token」这一环带来什么约束
CDN数据的高频更新特性要求上下文不能包含过期的配置或故障记录，否则会误导需求与设计文档的起草决策。单条文档长度差异大的特点，会导致token消耗波动明显，若未限制引用上限，可能出现单次请求携带过量token的情况。同时，文档字段聚焦于域名、缓存规则等细分内容，需要精准召回相关条目，避免无关数据占用token配额，影响起草效率与准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 1–3 天的业务数据量 | 匹配CDN配置的日/变更级更新频率，确保上下文包含最新的域名接入与缓存规则数据 |
| `quoteMaxToken` | 8000–12000 token | 适配CDN单条文档的平均长度，避免截断关键配置参数，同时控制单次请求的token消耗 |
| 单次召回条数 | 前 3–5 条 | 聚焦核心的域名接入、缓存规则、故障记录，减少无效token消耗 |
| 上下文刷新间隔 | 每 24 小时 | 对齐CDN监控告警的日更新频率，确保上下文始终包含最新的节点状态数据 |

## 容易做错的三处
- 配置`quoteMaxToken`为5万token，导致每次请求携带过量token，引发大语言模型响应延迟或超时。原因是未结合CDN单条文档的实际长度设置合理阈值，盲目放大引用上限。
- 无法在工作流中传递全局变量token给MCP工具。原因是未在上下文配置中开启全局变量透传功能，或未将token参数正确绑定到对应调用节点。
- 知识库召回的上下文混入过期的缓存规则或无效域名数据。原因是未根据CDN配置的变更频率调整上下文刷新周期，导致上下文包含旧数据。

## 怎么确认配好了
- 查看FastGPT v4.17.0的大语言模型调用日志，确认单次请求携带的token数未超过`quoteMaxToken`的预设阈值。
- 手动修改一条CDN缓存规则，检索知识库后验证是否能召回最新的规则内容，确认上下文刷新逻辑生效。
- 检查工作流中的MCP工具参数绑定，确认全局变量token已正确传递到工具调用节点，无参数缺失情况。
- 核对召回的知识库条目，确认仅包含当前目标域名或节点的相关配置数据，无无关条目混入。
