# CDN与边缘加速配置的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
CDN与边缘加速配置的日常文档包含域名接入单、缓存规则、刷新预热记录、故障分析报告。数据来源为CDN控制台、DNS解析记录、用户访问日志、节点监控告警，更新频率为每日或每次配置变更时更新。文档字段包含备案编号、源站IP地址、缓存TTL值、任务执行状态等，部分字段需匹配备案相关规范，无统一固定单位，不同文档类型的字段差异明显。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
CDN与边缘加速配置的文档类型分散、字段差异明显，多轮对话需先明确当前处理的文档类别，避免混淆备案编号、缓存TTL等核心字段的校验逻辑。数据来源分散且更新频率灵活，提示词需引导用户提供最新的配置变更信息，确保生成的文档与当前系统状态一致。备案核对、缓存规则调试为最耗时环节，多轮对话需优先收集核心字段，减少无效交互。公网访问相关的出错后果要求提示词包含字段校验逻辑，确保文档参数合规。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文窗口 | 前 20 轮对话或 8000 字符 | 匹配CDN文档的多环节字段，避免上下文溢出导致信息丢失 |
| 变量映射规则 | 绑定`variables`中的备案号、源站地址字段 | 对应域名接入单的必填字段，确保生成的文档字段完整 |
| 会话重置阈值 | 按`chatId`分组，每 600 秒重置一次上下文 | 避免跨工单的上下文混淆，符合CDN工单的独立处理逻辑 |
| 提示词更新频率 | 每日同步一次最新缓存规则库 | 匹配数据的日更新频率，确保提示词覆盖最新配置项 |
| 对话角色区分 | 按`messages`的角色区分用户输入与系统提示 | 区分需求收集与文档校验环节，避免交互逻辑混乱 |

## 容易做错的三处
- 并发调用工作流时返回空结果，查看工作流日志后发现触发了运行次数限制。原因是未针对CDN工单的高频提交场景调整运行阈值，导致高频调用触发限流。
- AI回复的变量结果出现内容叠加，上一轮的变量A结果被带入当前变量B的输出中。原因是未正确配置`variables`的上下文隔离规则，未按`chatId`重置会话变量。
- 开启输入引导与词库后，对话界面未显示预期引导问题。原因是未将缓存规则、备案校验等CDN专属术语同步到输入引导配置中，导致匹配失败。

## 怎么确认配好了
- 测试调用包含`variables`的备案号、源站地址字段的提示词，检查返回的文档片段是否包含对应字段。
- 模拟高频调用场景，查看工作流日志是否出现限流相关的状态码，确认阈值配置符合实际使用需求。
- 开启输入引导功能，手动输入CDN专属术语，检查是否触发对应词库的匹配逻辑。
- 查看`chatId`分组的会话日志，确认不同工单的上下文未发生混淆。
