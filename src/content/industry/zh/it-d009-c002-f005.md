# IT服务台工单处理的需求与设计文档起草：多轮对话与提示词
本页内容基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类的典型数据来自ITSM系统、电话或聊天记录、资产系统及内部知识库。日常处理的文档包括服务请求单、事件工单、处理记录与用户满意度表，每个工单包含唯一标识、用户信息、问题描述、处理状态、派单记录及满意度反馈等字段。数据更新频率为日级或实时，覆盖从工单提交到闭环的全流程信息。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来源覆盖多套异构系统，多轮对话需要支持跨数据源的上下文联动，确保工单信息、资产数据与历史处理记录的完整调用。通过`chatId`关联当前工单的对话上下文，保障多轮对话的连贯性。由于更新频率为日或实时，提示词需配置定期同步知识库的逻辑，避免使用过期的处理流程或资产信息。由于工单包含多个结构化字段，多轮对话的提示词需明确指定需提取的字段，避免生成不完整的需求文档。同时，工单处理出错会导致员工无法办公或SLA超时，因此多轮对话需配置超时处理与异常反馈机制，确保流程可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口长度 | 前 8000–10000 字符 | 适配工单文档的平均长度，避免截断`messages`中的关键历史对话与工单信息 |
| 问题优化开关 | 开启 | 用于提炼工单中的核心问题，简化后续提示词的输入逻辑 |
| 知识库关联范围 | 关联IT服务台专用知识库 | 匹配该品类的专属业务文档，避免无关内容干扰 |
| 多轮对话超时时间 | 60 秒 | 适配IT服务台的实时响应需求，避免影响员工办公 |
| 变量绑定 | 绑定工单ID、用户部门字段 | 确保生成的需求文档精准匹配对应工单的上下文，可通过`variables`传入绑定参数 |
| 最大召回条数 | 前 3 条 | 控制返回的知识库内容体量，避免超出上下文窗口限制 |

## 容易做错的三处
- 调用对话接口时返回关联知识库内容为空，无法获取IT服务台的标准处理流程。原因：未在`variables`中正确传入知识库绑定参数，或未配置对话与专属知识库的关联关系。
- 解析10M以上的Word文档时，处理时长超过120秒。原因：未针对大文件配置分段解析的优化逻辑，直接加载完整文档导致内存占用过高。
- 生成需求文档时触发超时报错，无法完成输出。原因：未设置合理的多轮对话超时时间，或上下文窗口设置过大导致模型推理耗时过长。

## 怎么确认配好了
- 发起模拟工单对话，输入测试工单的基础信息，检查生成的需求文档是否包含指定的结构化字段。
- 上传测试用的大文件Word文档，查看解析进度与返回结果的完整性。
- 调用对话接口，检查返回结果中是否包含关联知识库的相关业务内容。
- 发起连续多轮对话，检查上下文是否能正确保留历史工单的关键信息。
