# IT服务台工单处理的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
本品类的数据来自企业ITSM系统、电话或聊天记录、资产系统及内部知识库。日常生成的文档包含服务请求单、事件工单、处理记录与用户满意度表，各文档字段覆盖工单唯一标识、提交主体、问题类型、优先级、处理进度、满意度评分等。数据更新频率为日级或实时，随工单提交、处理流转、满意度反馈同步更新。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需支持多数据源接入，需配置对应节点拉取不同系统的工单数据。实时更新的工单要求工作流节点触发逻辑支持实时事件监听，避免延迟导致SLA超时。多类型文档结构差异要求工作流需预设字段映射规则，统一不同单据的标准化字段格式。工单处理流程的多环节流转要求工作流支持分支判断，根据问题分类、优先级分配不同处理节点，同时需适配跨系统的权限校验规则，确保敏感数据仅在授权节点流转。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 数据源接入配置 | 分别对接ITSM系统、聊天记录归档库 | 匹配本品类多来源的数据特征 |
| 字段映射规则 | 映射为工单ID、问题描述、处理状态等标准字段 | 统一不同文档的结构化格式 |
| 触发节点设置 | 按工单提交事件触发 | 适配实时或日级的数据更新节奏 |
| 超时阈值 | 600秒 | 符合企业IT服务台的常规响应时限要求 |
| `variables` 调用 | 按需提取工单字段变量 | 支持工作流中动态读取工单数据 |
| `nodeId` 配置 | 按节点功能命名唯一标识 | 便于工作流调试与节点间调用 |

本配置方案基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 现象：工作流中配置数据库连接节点后，日志显示`connect ETIMEDOUT`报错，但本地可正常访问数据库。原因：未配置工作流运行环境的出站网络规则，导致部署节点无法访问外部数据库服务。
- 现象：工作流中尝试配置多层循环体，运行时出现节点执行异常。原因：循环体嵌套层级超出平台的预设上限，导致执行栈溢出。
- 现象：工作流中配置多组AI问答节点后，返回了全部中间回答内容。原因：未配置节点的结果过滤规则，默认保留了所有中间输出。

## 怎么确认配好了
- 手动提交一条测试工单，查看工作流是否按预设的触发规则启动执行。
- 查看工作流的字段映射日志，确认不同来源的工单数据已被正确转换为标准字段格式。
- 触发数据库连接节点，验证是否能正常拉取ITSM系统的工单数据且无超时报错。
- 运行包含多组AI问答的测试流程，确认仅返回最后一次回答内容。
