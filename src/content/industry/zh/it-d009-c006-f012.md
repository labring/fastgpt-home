# Pull Request评审的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
Pull Request评审的相关数据主要来自代码仓库、CI流水线、Issue链接与贡献者提交，更新频率为日或周。日常处理的文档包含PR说明、代码评审意见、CI结果与合并记录，结构通常包含变更范围、依赖项、测试步骤、评审意见等字段，单位涉及字符数、提交次数、CI运行时长等元数据。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的数据来源包含多格式文件（如docx格式的PR模板、pdf格式的CI日志），高频更新要求解析流程具备高效性。PR文档的结构化字段（如变更范围、评审意见）要求分块时保留逻辑关联，避免拆分跨字段的完整评审逻辑。CI结果与合并记录的长文本片段，需要合理控制分块长度以兼顾检索精度与上下文完整性。部分文档包含内嵌表格与代码块，分块策略需适配此类特殊格式，防止丢失数据关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | PR评审文档包含变更说明、测试步骤等长段落，该区间可保留单条评审逻辑的完整上下文 |
| `chunkSplitter` | 按标题+段落分块 | PR文档有明确的变更范围、评审意见等标题层级，按标题拆分可保留逻辑关联 |
| `customPdfParse` | 启用MinerU适配模式 | 适配开源PDF转Markdown服务，解决部分复杂表格解析问题 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 部分大型PR附带的CI日志文档较长，需足够超时时间完成解析 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持大型合并记录与CI日志文件上传，适配团队级PR评审数据量 |
| `chunkSettingMode` | 手动配置 | 针对PR文档的特定结构，手动调整分块参数比自动模式更贴合业务需求 |

## 容易做错的三处
-  部分docx文档无法解析，界面显示解析失败提示。原因是未启用`customPdfParse`适配复杂内嵌格式的PR文档模板，导致部分自定义字段无法被识别。
-  部分表格无法正确分块，分块结果丢失表格列关联信息。原因是`chunkSplitter`配置为仅按换行分块，未适配PR文档中表格标题与内容绑定的结构。
-  容器部署后报显存溢出，无法识别GPU。原因是未正确挂载CUDA环境变量，且`PARSE_FILE_TIMEOUT_SECONDS`设置过短导致解析进程反复重试消耗显存。

## 怎么确认配好了
-  上传一份包含表格与长段落的PR评审示例文档，查看解析后的Markdown是否保留表格结构与段落逻辑。
-  上传100 MB左右的CI日志文件，确认解析任务在600秒内完成且无超时报错。
-  调整`chunkSize`参数后，验证分块后的文本片段是否完整包含单条评审意见或变更说明。
-  查看FastGPT v4.17.0的系统GPU监控面板，确认解析进程调用了已配置的CUDA环境，无显存占用异常。
