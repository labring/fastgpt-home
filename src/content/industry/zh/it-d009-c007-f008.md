# SLA与服务报告的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
该品类的数据来自监控系统、工单系统、合同文件与客户沟通记录，更新周期为月度或季度。日常产出的文档包含SLA条款文本、月度服务报告、可用性统计报表、客户复盘纪要。数据字段包含合同绑定的服务指标、事件发生时间、统计周期范围、服务达标情况标识，仅按行业通用格式记录服务相关的量化与文本信息，无额外自定义单位。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散且更新周期固定，工作流需支持按月度或季度定时触发，自动从多系统拉取对应周期的数据。由于文档字段有明确规范，工作流需配置字段校验环节，确保拉取的合同编号、服务指标等字段符合格式要求。由于核心耗时环节为SLA指标计算与口径对齐，工作流需内置标准化的计算逻辑，减少手动调整步骤，同时需配置口径统一的节点，避免不同周期的报告出现统计口径差异。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 定时触发设置 | 月度/季度 | 匹配该品类数据的更新频率，确保工作流按合同周期执行 |
| `variables`配置 | 绑定合同编号、统计周期 | 复用业务核心标识，避免重复录入，符合`variables`的全局变量使用场景 |
| 节点输出过滤 | 隐藏中间AI对话节点内容 | 避免非必要的中间步骤结果混入最终服务报告 |
| 问题指代消除 | 开启历史上下文关联 | 解决知识库搜索时的指代消除问题，优化搜索结果准确性 |
| 单次搜索结果上限 | 前5条 | 控制返回结果数量，避免服务报告内容冗余 |
| 工作流版本管理 | 按实测标定 | 适配不同周期的报告调整需求，保留历史配置版本 |

## 容易做错的三处
- 现象：工作流运行后，中间AI对话节点的内容被包含在最终服务报告中。原因：未配置节点输出过滤规则，未隐藏非必要的中间步骤输出。
- 现象：全局变量未在工作流全环节生效，部分节点无法调用预设的合同编号或统计周期。原因：未正确绑定`variables`参数，或未在对应节点中启用全局变量调用。
- 现象：知识库搜索结果无法正确处理指代类问题，例如将“该服务”识别为未知内容。原因：未开启历史上下文关联的配置，未关联用户历史对话记录优化搜索问题。

## 怎么确认配好了
- 手动触发一次工作流，检查最终输出的文档是否仅包含服务报告所需的内容，无中间AI对话的冗余信息。
- 查看全局变量配置页面，确认`variables`中绑定的合同编号、统计周期等标识已正确关联到工作流的各个节点。
- 测试知识库搜索节点，输入包含指代的问题，检查返回结果是否与历史上下文关联，解决指代消除问题。
- 验证定时触发功能，设置临时测试周期，确认工作流会按预设的月度或季度周期自动启动。
