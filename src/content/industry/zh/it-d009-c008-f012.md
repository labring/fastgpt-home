# 专题活动运营的需求与设计文档起草：文档解析与分块

本页面配置基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
这个品类的日常文档包含活动方案、资源位排期表、活动页面文案、活动复盘报告四类，数据来源为内部内容库、活动后台管理系统、流量统计工具及用户反馈表单。文档更新节奏以周为单位，节假日前后会临时追加更新。单份文档包含活动周期、资源位编号、投放渠道、转化数据等结构化字段，部分复盘报告附带非结构化的用户评论片段。

## 这些特征在「文档解析与分块」这一环带来什么约束
活动方案的周期字段与资源位编号需保留上下文关联，分块时不能割裂；资源位排期表的多行表格结构易被常规分块逻辑打散，需适配表格解析规则；复盘报告附带的用户评论片段存在非规范表述，需调整分块粒度避免语义断裂。活动文档的临时更新会导致批量解析时的时效性要求提升，超时风险增加。部分文档包含跨页的活动流程描述，分块需保留段落间的逻辑衔接，避免拆分后语义不完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配活动方案、复盘报告的段落长度，保留资源位编号与活动周期的上下文关联 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配活动文档的标题层级与段落结构，避免打散表格类排期文档的逻辑 |
| `customPdfParse` | 开启表格识别模式 | 适配资源位排期表的多行表格结构，保留单元格内的字段关联 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容批量上传的大型活动复盘报告与多页活动方案文档 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对节假日临时追加的批量文档解析，避免因文件过大或内容复杂导致超时 |
| `chunkSettingMode` | 手动配置模式 | 针对活动文档的非标准化格式，灵活调整分块规则与解析参数 |

## 容易做错的三处
- 上传PPT文档解析时报错“the argument ‘windows-1252’ is invalid encoding”，原因是未配置自定义编码适配活动文档中使用的非标准字符集。
- 多行XLSX格式的资源位排期表被拆分为零散文本块，原因是未开启表格识别模式，默认分块逻辑无法保留单元格间的字段关联。
- 知识库召回结果未附带文档溯源信息，原因是未开启文档解析与分块环节的元数据采集配置，导致分块时未记录来源文档标识。

## 怎么确认配好了
- 上传一份测试用的活动方案文档，检查解析后的分块是否保留了活动周期与资源位编号的上下文关联。
- 上传XLSX格式的资源位排期表，验证解析结果是否保留了表格的单元格结构与字段对应关系。
- 触发一次批量文档解析任务，检查是否在设定的超时时间内完成，无异常报错。
- 查看知识库分块后的元数据，确认每条文本块附带了来源文档的标识信息。
