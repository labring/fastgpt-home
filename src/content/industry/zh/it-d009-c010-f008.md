# 事件响应与故障处理的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
本品类的核心数据来自监控告警系统、日志平台、APM工具与用户反馈渠道，更新节奏为实时或每次事件触发时更新。日常产出的文档包含故障工单、事件时间线、应急预案、故障通报，包含事件唯一标识、影响业务范围、发生与恢复时间、处置步骤、通报对象等字段，字段均为文本或标准时间格式，适配运维处置的核心流程需求。本页面基于FastGPT v4.17.0版本开发。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源覆盖多类系统，工作流编排需支持多源数据的接入与聚合，需配置对应节点拉取实时更新的告警、日志等数据。因更新节奏为实时，工作流触发节点需匹配实时触发逻辑，避免延迟处理导致的处置滞后。因故障处置的核心环节耗时较长，工作流需配置影响面判断、止损操作、通报同步等节点的顺序与分支逻辑，且需配置失败处理机制，避免出错导致的服务中断或通报延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 布尔类型状态开关，匹配故障恢复状态 | 适配全局变量为Boolean类型的状态判断需求，用于分支执行逻辑 |
| 节点触发时机 | 实时触发，按数据源更新事件触发 | 匹配本品类数据实时更新的节奏，确保工作流及时响应故障事件 |
| 多源数据接入 | 接入监控告警、日志平台、APM工具与用户反馈渠道 | 覆盖本品类全量数据来源，确保工作流获取完整的故障相关信息 |
| 失败处理策略 | 重试2次，间隔60秒后触发告警 | 应对故障处置出错后果严重，需保障处置流程的可靠性 |
| 工具调用输出控制 | 隐藏工具调用结果 | 避免冗余信息干扰故障处置 |
| `nodeId` | 绑定对应故障事件的唯一标识 | 确保工作流节点与对应故障工单关联 |

## 容易做错的三处
- 现象：MongoDB Change Streams节点出现断连报错，无法自动重连。原因：未配置主节点漂移后的重连逻辑，未绑定副本集节点切换的触发检查。
- 现象：`variables`为Boolean类型的全局变量判断器未触发分支切换。原因：判断条件未准确匹配`true`/`false`的状态值，或未绑定`nodeId`关联的事件上下文。
- 现象：多模态AI对话节点开启图片识别后，返回无法提供图片内容的提示。原因：未正确配置多模态模型的图片识别参数，或未开启节点的图片输入权限。
- 现象：工具调用完成后结果仍展示在工作流输出中。原因：未正确配置工具调用输出控制节点，或工具调用结束节点未绑定到对应执行链路。

## 怎么确认配好了
- 触发一次模拟故障事件，检查工作流是否自动拉取对应数据源的告警数据，确认`variables`的故障状态是否正确更新。
- 查看工作流的节点日志，确认MongoDB Change Streams节点在模拟主节点切换后自动重连。
- 上传测试图片到多模态AI对话节点，确认节点返回图片识别结果。
- 执行工具调用，确认工具调用结果未出现在工作流输出中。
