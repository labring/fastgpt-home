# 云主机交付与资源开通的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
该品类的数据通常来自云管理平台、订单系统、IAM、计费系统，更新频率为每单或实时。日常产出的文档包括资源开通单、实例配置表、账号权限单、交付确认单，结构多为结构化字段组合，包含实例规格（单位为vCPU核数、GB内存）、地域、镜像ID、权限组ID、计费周期等核心字段，单份文档的内容量通常在几百到几千字符区间。

## 这些特征在「上下文与 token」这一环带来什么约束
多源数据的整合要求上下文召回需覆盖云管理平台、订单系统等不同来源的关联字段，避免核心配置信息缺失；实时更新的特性要求上下文配置需适配动态变化的资源状态，防止召回过时的订单或权限数据；结构化的文档结构要求分块与召回逻辑需匹配字段边界，避免拆分破坏实例规格、地域等核心配置项的完整性；单份文档的内容量区间要求上下文与token配置需平衡召回范围与资源占用，防止token溢出或关键信息被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 该品类单份交付文档的核心内容通常不超过10000字符，对应token数符合FastGPT v4.17.0的上下文承载范围 |
| `quoteMaxToken` | `2000–3000 token` | 单份资源开通单的核心字段内容约1500-2500字符，匹配该品类的文档内容规模 |
| 分块重叠长度 | `100–200 字符` | 该品类文档为结构化字段组合，少量重叠可保证上下文连贯，避免字段拆分断裂 |
| 召回匹配阈值 | `0.75–0.85` | 需精准匹配实例规格、地域等核心字段，避免无关历史数据混入上下文 |
| 单次召回条数 | 前3–5条 | 该品类单份交付文档关联的数据量有限，过多召回会占用过多token资源 |

## 容易做错的三处
- 未合理设置`maxContext`取值，取值过小可能导致上下文截断后缺失实例规格、地域等核心字段，引发资源配置错误。
- 未正确配置`quoteMaxToken`，可能导致引用的Excel源数据块过大，消耗过多token，出现上下文溢出或结果截断报错。
- 未匹配IAM系统的权限字段结构配置召回逻辑，可能导致新增账号时触发E11000重复键错误，引发数据库冲突。

## 怎么确认配好了
- 上传单份资源开通单文档，查看FastGPT上下文预览面板，确认实例规格、地域、权限组等核心字段均被完整召回。
- 发起一次资源配置校验请求，查看token消耗统计，确认`maxContext`与`quoteMaxToken`的取值未被超出。
- 检查服务端环境变量`AIPROXY_API_ENDPOINT`（AI Proxy服务的根地址，例如http://aiproxy:3000，不得附加/v1或单模型服务地址路径）与`AIPROXY_API_TOKEN`（AI Proxy管理员Token，与AI Proxy服务端配置一致且不能为空，不得作为应用API Key、模型供应商密钥等使用，不得在工作流全局变量、应用API请求头或普通模型管理页面填写此类变量替代服务部署配置）的配置值，与实际AI Proxy服务信息一致。
- 模拟新增账号权限操作，查看系统日志，确认未出现E11000重复键错误相关异常提示。
