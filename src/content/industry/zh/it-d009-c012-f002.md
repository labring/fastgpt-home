# 云网络与负载均衡配置的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
这个品类的数据主要来自云平台控制台导出的配置、网络拓扑图、流量监控报表、客户架构设计图。日常产出的文档通常包括VPC规划方案、安全组规则清单、负载均衡配置单、变更执行单。数据更新频率随每一次配置变更或新单交付推进，文档字段通常包含网段CIDR、端口范围、健康检查阈值、后端服务器组信息，单位涵盖IP段格式、端口号、流量速率等。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的文档多为结构化配置类内容，字段密集且依赖精确参数匹配，单次输入的token通常集中在网段、端口等关键配置项。由于配置变更通常需追溯历史规则，上下文召回需覆盖近几次的变更单与拓扑数据，避免遗漏关联配置。同时，文档更新频率随变更单推进，上下文窗口需适配新增的配置字段，若token配额不足会截断关键网段或健康检查参数，导致起草的文档无法完整匹配实际配置要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配负载均衡配置单的字段密度，避免截断关键网段与端口配置 |
| `quoteMaxToken` | 1500–2000 token | 匹配单份安全组规则文档的平均长度，确保完整引用历史配置 |
| 上下文召回条数 | 前3–5条 | 覆盖最近的变更单与拓扑数据，满足网段规划与规则核对的需求 |
| 单次匹配召回上限 | 前6条 | 避免召回无关的历史配置，缩小有效上下文范围 |
| 按实测标定 | 按实际变更单的平均长度调整 | 适配不同规模的云网络配置场景 |

## 容易做错的三处
- 找不到`maxContext`参数的配置入口。原因是未在FastGPT的知识库配置页的上下文与token模块中查找，该参数默认隐藏在进阶设置中。
- 设置了较大的token限制，但仍出现配置内容截断。原因是混淆了字符数与token数的换算关系，未按实际token配额调整输入内容长度。
- 上传变更单文档时出现报错，提示上下文溢出。原因是未根据文档的字段密度调整`maxContext`参数，导致token配额不足。

## 怎么确认配好了
- 导入一份典型的负载均衡配置单，检查文档内容是否完整显示，无截断情况。
- 查看上下文召回的历史配置，确认包含最近3次以内的变更单与拓扑数据。
- 核对`quoteMaxToken`参数的取值，确保单份引用文档的长度不超过该配额。
- 在FastGPT v4.17.0版本中，提交测试用的变更单，检查是否出现内容截断或召回异常。
