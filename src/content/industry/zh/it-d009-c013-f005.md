# 云账单与成本核算的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
通常，该品类的数据来源于云计费系统、标签数据、订单系统与资源监控工具。日常产出的文档包括账单明细、成本分摊表、资源利用率报表与优化建议单。账单明细包含资源标识、计费项、结算金额与使用时长等字段，单位多为元与小时；成本分摊表标注分摊比例与归属部门；数据更新频率分为日度与月度两类，不同文档适配不同更新节奏。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源的多样性要求多轮对话中需明确指定当前调用的数据源类型，避免混淆不同系统的字段定义。文档结构的差异需要提示词先确认当前处理的文档类型，再匹配对应的字段提取规则。更新频率的差异则要求对话中需明确指定数据的时间范围，例如日度账单或月度分摊表。标签归属核对的高耗时特性，需要多轮对话逐步引导确认资源标签的归属主体，避免一次性输入过多信息导致混淆。异常费用排查需基于资源监控数据，提示词需引导用户提供异常账单的具体特征与时间区间。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口 | 8000–12000 token | 覆盖账单明细、成本分摊表等文档的常规长度，完整加载历史对话与文档内容 |
| 多轮历史保留条数 | 前20条 | 适配标签核对、异常排查等多轮交互的历史需求，避免上下文溢出 |
| `variables`参数配置 | 绑定云账单字段变量 | 支持动态调用预设的计费项、资源标识等字段，简化提示词编写 |
| 单次回复token上限 | 2000 token | 限制单轮回复长度，避免响应超时或内容冗余 |
| 问题优化开关 | 按实测标定 | 针对云账单专业术语优化提问拆解，提升响应速度与准确性 |
| `messages`参数配置 | 保留系统提示词与用户历史交互 | 确保多轮对话中上下文的一致性，延续之前的文档处理逻辑 |
| `chatId`参数配置 | 绑定专属对话标识 | 区分不同云账单项目的对话上下文，避免不同项目的配置混淆 |

## 容易做错的三处
- 现象为对话中针对成本分摊的解释请求响应速度过慢，原因是未开启问题优化开关，或未限制单次处理的文档片段数量。
- 现象为多轮对话中上下文丢失，导致无法延续之前的异常费用排查流程，原因是未正确配置多轮历史保留条数，或未启用`messages`参数的上下文关联逻辑。
- 现象为对话开场白快捷按键未触发预设的成本核算文档模板，原因是未将预设模板与快捷按键绑定，或未在提示词中加载对应模板的变量。

## 怎么确认配好了
- 发起包含账单明细字段的测试请求，确认回复中正确提取了资源标识、结算金额等预设字段。
- 发起连续多轮交互，核对历史对话内容被正确保留并用于后续的标签归属核对或异常排查请求。
- 触发预设的对话开场白快捷按键，确认加载了对应云账单文档的模板与变量。
- 查看配置面板，确认`variables`参数、最大上下文窗口等配置项与当前业务需求匹配。
