# 云资源合规审计的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自云审计日志、IAM系统、CMDB数据库及安全基线扫描结果，更新频率为月度或季度。日常产出的文档包含合规检查表、权限审计报告、资源清单、整改跟踪表，各文档字段涵盖资源ID、权限配置项、合规状态、整改责任人等，无统一固定单位，需匹配对应云服务商的资源标识与合规项定义。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且需跨系统拉取，多轮对话需支持分批次调用不同数据源接口，避免单次请求过载。更新频率固定为月度或季度，提示词需适配批量数据处理逻辑，不宜要求实时刷新结果。文档字段无统一标准，多轮对话需支持动态识别字段映射，避免硬编码字段名。资源清单盘点、权限异常识别等环节耗时较长，对话需支持上下文留存与断点续传，确保跨轮次的任务连贯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | `8000–12000 字符` | 云资源合规审计的单批次数据量较大，需容纳多轮对话的资源清单、权限数据等内容，避免上下文溢出 |
| 单次对话轮次上限 | `8–12 轮` | 跨数据源拉取需多轮确认字段与数据范围，过多轮次易导致上下文混乱，影响合规文档生成准确性 |
| `variables` 配置 | 绑定云资源ID、合规状态字段 | 日常文档需关联具体资源与合规项，需动态传入对应字段变量，确保生成文档的字段匹配业务需求 |
| `messages` 上下文拼接规则 | 按会话轮次依次拼接历史对话 | 确保多轮对话的上下文逻辑连贯，符合云资源合规审计的分步拉取需求 |
| 上下文召回条数 | `前6–10 条历史对话` | 需保留跨轮次的数据源拉取指令与结果反馈，避免关键上下文丢失 |
| 提示词模板更新频率 | 按季度更新 | 匹配本品类数据月度或季度的更新频率，确保模板适配批量数据处理逻辑 |

## 容易做错的三处
- 现象为对话返回`401 No auth credentials found`错误，原因是未在`variables`中配置云服务商的访问密钥变量，导致无法拉取云审计日志等数据源。
- 现象为生成的合规文档字段缺失或错位，原因是未绑定对应云资源的字段变量，提示词未明确要求映射文档字段与数据源结果。
- 现象为多轮对话上下文丢失，原因是未指定`chatId`持久化会话标识，导致每次对话重置上下文，无法延续跨轮次的数据源拉取任务。

## 怎么确认配好了
- 发起一次测试对话，请求拉取指定云账号的资源清单，核对返回结果是否包含CMDB、IAM的数据源字段。
- 发起多轮对话，连续调用3-5次数据源接口，核对`chatId`是否保持一致，上下文是否延续上一轮的指令与结果。
- 检查`variables`中是否已配置云服务商访问相关的必要变量，确保无空值或错误配置。
- 使用FastGPT v4.17.0版本的配置界面，触发一次合规文档生成任务，核对生成内容是否匹配预设的合规检查表、权限审计报告等文档结构。
