# 产品使用数据分析的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
该品类的数据通常来自埋点系统、数据仓库、CRM、工单系统，更新频率多为日度或周度。日常产出的文档包含使用分析报告、埋点方案、指标口径表、看板需求单，数据字段包含用户ID、功能模块、操作时长、客户层级、工单状态等，单位涵盖操作次数、分钟、客户数等，不同来源的数据格式存在差异，需在工作流中完成统一对齐。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的接入要求工作流配置多个数据拉取节点，需按数据优先级依次关联埋点、仓库等来源，避免数据遗漏。日/周更新的节奏要求工作流设置匹配的定时触发周期，避免处理未完成的原始数据。指标口径的统一需求要求工作流前置字段校验环节，确保不同系统的字段映射符合指标口径表的定义。跨客户的行为洞察产出要求工作流支持按客户层级分组处理数据，同时异常数据排查需要配置分支判断逻辑，及时拦截异常数据进入后续环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 定时触发周期 | 按数据更新节奏设为每日凌晨2点或每周一凌晨 | 匹配数据日/周更新频率，避免处理未完成的原始数据 |
| 数据来源节点 | 依次关联埋点系统、数据仓库、CRM节点 | 覆盖全量业务数据来源，确保分析维度完整 |
| 字段映射规则 | 按指标口径表匹配字段名与单位 | 确保指标口径统一，消除跨系统字段差异 |
| `variables`配置 | 绑定全局客户层级、功能模块变量 | 复用文档中的固定参数，减少重复配置 |
| 异常分支处理 | 指定`nodeId`为告警节点，触发告警并暂停后续节点 | 确保异常分支精准触发，避免误操作 |
| 超时设置 | 600秒 | 适配多数据源拉取的平均耗时，避免任务中断 |

## 容易做错的三处
- 运行工作流时弹出`quote type error`报错，原因是未按规范使用`variables`包裹变量格式，直接输入未加约束的变量名。
- 工具调用节点同时输出AI回复与触发下一级分支，原因是未正确配置分支触发条件，未限制单节点的执行逻辑。
- 循环嵌套中的HTTP请求执行失败，原因是未调整超时设置，且未配置循环节点的重试规则，导致请求超时未处理。

## 怎么确认配好了
- 运行测试工作流，检查`variables`绑定的全局变量是否正确传递到各数据节点。
- 查看定时任务日志，确认工作流按FastGPT v4.17.0版本的设定周期触发执行。
- 模拟异常数据输入，验证异常分支是否触发告警并暂停后续节点。
- 核对字段映射结果，确认与指标口径表的字段名与单位匹配一致。
