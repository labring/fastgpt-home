# 产品使用数据分析的需求与设计文档起草：表单与交互

## 这个品类的数据长什么样
这个品类的数据来源包括埋点系统、数据仓库、CRM、工单系统，更新频率为日或周。日常产出的文档包含使用分析报告、埋点方案、指标口径表、看板需求单，核心字段涵盖功能点击量、客户行为标签、工单响应时长等，无统一强制单位，需随指标类型调整。数据关联跨客户的功能使用行为，需基于统一口径进行整合，用于输出跨主体的产品使用洞察，支撑运营与客户成功动作。

## 这些特征在「表单与交互」这一环带来什么约束
多数据源的接入需求要求多渠道字段的绑定与校验由外部业务系统或后续节点实现，避免跨源数据的口径冲突。日/周级别的更新频率要求数据刷新节奏由外部业务系统或后续节点控制，确保展示数据与最新数据源同步。跨客户的洞察产出要求交互组件可提供客户分群标签选择项，筛选逻辑由外部业务系统或后续节点实现，且需关联指标口径表进行一致性校验，减少异常数据排查的耗时。同时，出错后果直接影响运营与续费判断，要求异常数据标记与提示能力由外部业务系统或后续节点实现，避免因指标误判导致的运营动作错误。

## 配置怎么定
本文基于FastGPT v4.17.0版本的表单与交互配置逻辑撰写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 表单输入节点 `formInput` | 测试示例：从产品使用数据分析字段中选 3 个作为必填输入，实际字段按任务确定 | 该节点收集用户输入；缺必填项时需排查交互状态，避免后续节点无法获得完整输入 |
| 用户选择节点 `userSelect` | 测试示例：设置 2 个业务选项，逐项检查对应分支 | 该节点处理用户选择；产品使用数据分析相关记录的查询、筛选需由后续接口或外部系统实现 |
| 提交后字段传递 | 测试示例：准备 10 条产品使用数据分析输入样本，覆盖完整填写、缺必填项和取消操作 | 对照输入与节点输出，核对后续节点是否收到对应字段；结果阈值按实际任务确定 |
| 外部实施项：定时更新节奏 | 需由外部系统另行实现；由外部业务系统或后续节点控制，建议取每日 0 点 / 每周一 0 点（待实测） | 匹配品类数据日/周的更新频率，确保数据时效性 |
| 外部实施项：指标口径校验逻辑 | 需由外部系统另行实现；由外部业务系统或后续节点实现 | 统一指标定义，减少异常数据排查的耗时 |
| 外部实施项：异常数据标记与提示 | 需由外部系统另行实现；由外部业务系统或后续节点实现，用于标记埋点异常、数据缺失的字段 | 快速定位异常数据，避免指标误判 |

## 容易做错的三处
- 现象：前端测试时输入的客户ID在工作流中无法匹配到对应数据，原因：未在外部业务系统中配置客户ID的数据源关联规则，导致变量未正确映射到实际数据来源。
- 现象：同一个埋点指标在工作流调试和前端实际运行中数值不一致，原因：调试阶段使用临时测试数据，未切换到正式的日/周更新数据源，导致数据口径不统一。
- 现象：HTTP请求返回的JSON数据传入下一个交互节点时出现多余转义符，可观察症状：节点接收数据格式异常；核对动作：检查外部接口返回数据格式、确认后续节点的数据处理逻辑，`formInput`仅负责收集输入数据，格式修正由外部接口或后续节点实现。

## 怎么确认配好了
- 检查`formInput`收集的字段与埋点方案中的指标定义一致，数据源关联由外部业务系统处理，确保数据来源正确。
- 测试`userSelect`节点的用户交互流程，确认外部业务系统或后续节点可基于用户选择项过滤对应的数据范围。
- 确认外部业务系统按设定周期同步数据，与数据源的更新节奏匹配。
- 模拟异常数据输入，确认外部校验逻辑正常触发提示，标记异常字段。
