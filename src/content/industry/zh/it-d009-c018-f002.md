# 企业软件许可证管理的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
本品类的数据主要来自软件资产管理系统、采购系统、终端扫描工具及厂商授权文件。日常产出的文档包含许可证台账、软件使用清单、采购合同与合规审计报告。数据更新频率为月度或季度，核心字段涵盖授权许可数量、厂商授权有效期、终端安装数量、合规校验状态，单位涉及台、份、自然日等。数据结构以结构化台账为主，伴随非结构化的厂商授权扫描件与合同文本。

## 这些特征在「上下文与 token」这一环带来什么约束
月度或季度更新的低频数据，要求上下文窗口适配批量历史台账与单次审计报告的总长度。多来源的混合数据，包含结构化字段与非结构化文本，需要在token分配上区分权重，避免非结构化的扫描件占用过多上下文资源。合规审计报告的长文本特性，要求限制单段token上限，防止超出模型上下文阈值。授权数量、安装终端数等数值型字段的token占比需控制，确保与上下文的语义关联匹配。跨系统的异构数据需要统一token编码规则，避免字段混淆导致的上下文偏差。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配月度合规审计报告的批量文本长度，覆盖多份许可证台账与合同的总token量 |
| `quoteMaxToken` | `2000–3000 token` | 限制单条引用的非结构化授权文件或扫描件的token占比，避免上下文溢出 |
| 分块长度 | 1500–2000 字符 | 匹配许可证台账的单条记录长度，平衡分块后的语义完整性与token利用率 |
| 重叠长度 | 100–200 字符 | 保留跨分块的授权有效期、终端数量等关键字段的上下文关联 |
| 单次召回上限 | 前 8 条 | 适配月度更新的许可证数据量，避免召回过多历史记录占用上下文 |

## 容易做错的三处
- 上传厂商授权扫描件时触发token超限报错，部分小尺寸文件却可正常上传。原因是未对非结构化的图片文本提取结果分配合理的token配额，导致大尺寸扫描件的提取文本超出单段token限制。
- 设置最大上下文窗口后，合规审计报告的召回结果缺失关键授权数量字段。原因是分块长度过小，拆分后的分块丢失了跨块的字段关联信息。
- 配置引用最大token数后，许可证台账的数值字段未被正确关联到查询上下文。原因是未区分结构化字段与非结构化文本的token分配，导致数值字段的token占比被过度限制。

## 怎么确认配好了
- 导入单份月度许可证台账，查看上下文窗口的实际占用token数，确认未超出设定的`maxContext`值。
- 上传不同尺寸的厂商授权文件，检查是否触发token超限报错，验证`quoteMaxToken`的配置生效。
- 拆分长文本的合规审计报告，核对分块后的重叠内容是否保留了授权有效期、安装终端数等关键字段。
- 触发一次合规审计查询，查看召回的历史记录条数是否符合单次召回上限的设定。
