# 企业软件许可证管理的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
本品类的数据主要来自软件资产管理系统、采购系统、终端扫描结果及厂商授权文件。日常产出的核心文档包含许可证台账、软件使用清单、采购合同与合规审计报告。数据更新频率为月度或季度，字段包含软件名称、授权类型、授权数量、安装终端数、到期日期、厂商信息等，字段需匹配对应厂商的计量标准，无统一强制单位。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需配置跨系统对接节点，确保可拉取多源存量数据；更新频率偏低要求工作流触发机制适配定时批量同步，适合非实时的批量处理场景；文档字段需严格匹配厂商授权的计量规则，避免字段映射错误；合规审计类文档需保留完整链路追溯节点，确保后续审计可查。授权数量核对环节耗时占比高，工作流需内置自动校验节点，减少人工干预步骤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 全局变量绑定 | 关联许可证台账、软件使用清单数据源 | 适配FastGPT v4.17.0的全局变量调用规则，基于本品类核心数据来源直接调用存量数据 |
| 定时触发配置 | 按每30天定时执行 | 匹配本品类数据月度更新频率，减少无效运行次数 |
| 知识库关联节点 | 绑定合规审计报告专属知识库 | 适配合规校验环节的文档调用需求 |
| `variables`参数配置 | 传入动态知识库ID | 支持工作流调用指定合规知识库，适配多审计场景 |
| `nodeId`配置 | 设为授权校验节点的唯一标识 | 确保工作流节点调用无冲突，避免链路中断 |
| 文件上传大小限制 | 不超过100 MB | 匹配厂商授权文件的常规大小范围，避免存储过载 |
| 授权校验阈值 | 单次校验上限为前100条记录 | 匹配本品类数据更新规模，避免单次处理过载 |

## 容易做错的三处
-  工作流调用知识库时返回无匹配文档，界面显示知识库ID字段为空。原因是未通过`variables`参数传递动态知识库ID，仅绑定了全局变量但未在工作流节点中引用该参数。
-  配置文档上传触发节点后，无法触发后续分析流程。原因是未限定上传文件的格式范围，非厂商授权文件或合规审计报告的上传文件未触发节点启动。
-  工作流执行后出现授权数量核对错误，结果与实际台账不符。原因是未匹配厂商授权的计量字段，直接使用软件资产管理系统的默认字段进行校验，导致单位或计数规则不匹配。

## 怎么确认配好了
-  手动触发一次工作流，查看运行日志中是否正确加载了许可证台账的数据源字段。
-  传入预设的测试知识库ID，验证工作流是否能调用对应知识库的文档内容。
-  上传一份模拟的厂商授权文件，确认工作流是否触发后续校验节点。
-  检查定时触发配置，确认系统将按设定的月度周期自动启动工作流。
