# 供应商与设备到货管理的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
供应商与设备到货管理的日常文档包括采购订单、到货验收单、序列号清单、发票资料。数据来源涵盖ERP系统、供应商发货单、物流信息平台及设备厂商后台。单项目执行周期内，数据以每单为基础更新频次，也会按周同步最新物流、验收信息。文档字段包含采购单号、设备型号、序列号、供应商名称、到货日期、验收结果等，单位多为台、套、件等实物计量单元。

## 这些特征在「上下文与 token」这一环带来什么约束
多源异构的数据来源要求上下文整合不同系统的格式与字段，需精准匹配设备型号、序列号等核心标识，避免跨系统数据错位。单周或单单的更新节奏，要求上下文处理的时效性匹配业务流转周期，避免使用过期的物流或验收数据。文档字段多且与实物强绑定，上下文召回需优先保留核心业务字段，否则会引发设备错配、项目延期等问题。同时，单份文档的token总量需适配模型的上下文窗口，防止因token溢出导致推理失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 适配单项目下多份文档（采购订单、验收单等）的总token长度，符合FastGPT v4.17.0的默认窗口范围 |
| `maxContext` | 8000–12000 token | 限制全局上下文的总token上限，防止模型因输入过长导致推理超时 |
| `quoteMaxToken` | 2000–3000 token | 限定单条引用文档的token上限，优先保留设备型号、序列号等核心业务字段 |
| 单次召回上限 | 前6条 | 匹配单项目涉及的供应商与设备数量，避免冗余数据占用上下文空间 |
| 上下文召回阈值 | 按实测标定 | 适配ERP、物流信息等多源数据的字段匹配精度，确保召回数据的相关性 |
| 问题优化开关 | 开启 | 针对采购、验收类专业文档优化上下文提取逻辑，提升核心字段的召回准确率 |

## 容易做错的三处
- 界面显示选择了v2模型版本，但调用日志显示仍消耗旧版本token额度，原因是仅在全局config中配置模型版本，未在对应知识库的上下文配置中绑定指定模型。
- 开启知识库搜索和问题优化功能后产生平台扣费，即使已设置自定义openapi token，原因是未将这两个功能的调用链路绑定自定义token，仍使用平台默认计费token。
- 处理包含多份序列号清单的上下文时出现token溢出报错，原因是未设置`quoteMaxToken`参数限制单条引用文档的token上限，导致核心业务字段被截断。

## 怎么确认配好了
- 登录FastGPT v4.17.0后台，进入对应知识库的上下文配置页面，确认`maxContext`和`quoteMaxToken`的取值与预设配置一致。
- 调用openapi接口测试知识库搜索功能，检查请求头中的token是否与自定义配置的token匹配，查看返回结果的token消耗统计。
- 上传单份采购订单和到货验收单，验证上下文召回的字段是否包含设备型号、序列号等核心业务信息。
- 在内网部署环境中，查看系统日志确认oneapi进程无重启，且上下文处理的耗时符合预期。
