# 供应链安全与开源依赖治理的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据通常来自包管理器、代码仓库、公开漏洞库与许可证数据库，更新频率为每日或每版本发布时。日常产出的文档包含SBOM清单、依赖风险报告、许可证清单与修复工单，核心字段包含依赖包名、版本号、漏洞CVE编号、许可证类型与影响范围。数据由安全团队、研发效能团队或开源治理办公室维护，用于支撑供应链风险识别与治理工作。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散且更新频繁，多轮对话需限定上下文范围，避免加载无关的跨项目依赖数据。核心文档字段较多，提示词需明确指定提取依赖包名、CVE编号等必填项，防止生成冗余或缺失关键信息的内容。数据更新频率高，对话需支持实时拉取最新的依赖风险数据，避免依赖静态缓存。复杂的依赖评估任务需通过多轮对话拆分，逐步引导用户提供依赖清单、风险报告等素材，避免单次请求过载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 对话上下文长度 | 8000–12000 token | 匹配SBOM、依赖风险报告等文档的平均长度，避免超出模型上下文上限 |
| `messages` | 保留最近20条历史 | 供应链治理文档通常较长，过多历史会挤占有效上下文，按实测标定 |
| `variables` | 注入当前项目的SBOM链接、漏洞库地址 | 确保多轮对话基于当前项目的专属数据生成内容 |
| 会话ID绑定 | `chatId`绑定项目标识 | 避免不同项目的依赖数据混淆，确保对话上下文与对应项目匹配 |
| 单次最大召回数 | 前5条 | 限制返回的依赖风险条目数量，避免内容过载 |
| 提示词校验开关 | 开启 | 自动检查生成文档的必填字段，防止遗漏高危依赖信息 |

## 容易做错的三处
- 现象：对话完成后点赞或点踩操作未生效。原因：未绑定对话会话与用户反馈的关联逻辑，或配置未开启反馈同步功能。
- 现象：对话返回内容不符合JSON格式要求。原因：提示词未严格指定JSON结构，或上下文数据包含未转义的特殊字符。
- 现象：上传附件生成预签名URL失败，如提示“fail to create post presigned url”。原因：升级版本后S3存储配置未同步更新，或存储桶权限未适配FastGPT v4.17.0的API参数。

## 怎么确认配好了
- 发起测试对话，输入“生成当前项目的SBOM清单”，检查返回内容包含依赖包名、版本号等核心字段，字段完整性符合业务要求。
- 测试多轮对话流程，先上传依赖风险报告，再询问高危依赖的修复方案，检查对话上下文保留了上传的文档信息，回答基于上传内容生成。
- 检查`variables`是否注入了当前项目的专属数据，如SBOM的本地路径或远程链接，确保对话使用项目专属数据。
- 触发附件上传操作，验证预签名URL生成成功，无报错提示，确认存储配置适配当前版本。
- 测试点赞或点踩操作，检查反馈数据是否同步至后台，确认关联逻辑配置正确。
