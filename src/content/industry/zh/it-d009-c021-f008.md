# 供应链安全与开源依赖治理的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自包管理器、代码仓库、公开漏洞库与许可证数据库。日常产出的文档包含SBOM清单、依赖风险报告、许可证清单与修复工单，各文档包含组件名称、版本号、漏洞等级、许可证类型、修复状态等字段。数据更新频率为每日或每版本发布时更新，覆盖当前项目的第三方依赖全量资产信息。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流需配置多节点对接不同数据源，需为每个数据源配置独立的鉴权规则。数据更新频率的灵活性要求工作流支持两种调度触发模式，适配每日批量更新与版本触发的场景。文档字段的非标准化特征要求工作流需配置字段映射节点，统一对齐不同来源的组件信息字段。出错后果的严重性要求工作流需配置校验拦截节点，对高危漏洞组件、不合规许可证直接阻断流程，避免风险流入后续环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 调度触发方式 | 按版本更新触发 / 每日0点定时触发 | 匹配数据日/每版本的更新频率，避免重复拉取无效数据，适配FastGPT v4.17.0的调度逻辑 |
| 多源数据源鉴权 | 为包管理器、漏洞库分别配置API密钥 | 对接不同来源的依赖数据，保障数据拉取的权限合规 |
| `variables` | 预设平台时间变量、SBOM版本号变量 | 用于文档落款、工单编号等动态字段场景，满足需求文档的格式要求 |
| 字段映射规则 | 将组件名称、版本号统一映射为标准字段 | 对齐不同来源的字段差异，保障后续风险分析的准确性 |
| 异常拦截阈值 | 高危漏洞组件直接阻断流程 | 匹配出错后果的风险等级，避免高危依赖进入后续环节 |
| 日志存储时长 | 保留90天的工作流执行日志 | 满足合规审计与问题排查的需求 |

## 容易做错的三处
- 现象：工作流执行后提示词中未显示正确的落款时间。原因：未在`variables`配置中绑定平台时间变量，或未在提示词中正确引用该变量。
- 现象：工作流节点状态显示异常，无法查看MCP服务的详细日志。原因：未开启节点日志采集配置，或日志保留时长设置过短导致旧日志被自动清理。
- 现象：相同任务在工作流中执行耗时比单独调试更长。原因：工作流中配置了多源数据同步节点，且调度触发方式设置为实时触发，导致重复拉取冗余数据。

## 怎么确认配好了
- 手动触发一次工作流，检查生成的文档中落款时间与当前系统时间一致。
- 进入工作流节点详情页，查看对应节点的日志信息，确认MCP服务的调用记录完整且未被清理。
- 对比单独调试与工作流执行的耗时，确认调度触发方式未设置为高频重复触发。
- 查看节点配置列表，确认`variables`参数已正确绑定平台时间变量与其他必要字段。
