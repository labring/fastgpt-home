# 信创替代适配的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
这个品类的数据主要来自企业现有IT系统清单、国产软硬件官方目录、项目测试环境记录与厂商公开资料。日常产出的文档包含适配清单、兼容性测试报告、迁移方案与问题台账四类，文档字段多包含软硬件型号、版本号、兼容状态、测试结论与风险等级，单位多为硬件型号标识、版本号字符串、测试日期等。数据更新以单个项目为周期，或按季度同步最新国产软硬件目录信息。

## 这些特征在「上下文与 token」这一环带来什么约束
适配类文档多包含大量软硬件型号、版本细节与结构化测试数据，单篇文档的token占用量较高，会限制上下文窗口可承载的有效内容占比。数据来源分散在系统清单、厂商资料等多个渠道，需要跨源召回关联信息，要求上下文召回的范围与token配额精准匹配。数据更新的周期差异也带来了时效性要求，项目级数据需优先匹配当前项目的最新适配信息，避免调用过时的厂商资料。问题台账的条目多为具体故障场景，需要精准召回相关上下文，token配额不足会导致关键故障细节丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配类文档单篇token量较高，需覆盖完整的软硬件适配信息与测试结论，符合FastGPT v4.17.0的上下文窗口配置逻辑 |
| `quoteMaxToken` | `1500–2000 token/条` | 单条适配或测试报告的核心内容长度集中在该区间，避免单条引用占用过多上下文配额 |
| 分块长度 | `800–1000 字符` | 适配类文档多包含结构化型号与文本描述，该长度可平衡分块粒度与召回精度 |
| 单次召回上限 | 前6条 | 项目级适配数据的关联条目数量集中在5-7条，过多会超出上下文窗口的承载范围 |
| 分块重叠长度 | `100–150 字符` | 避免跨分块的适配信息被截断，保障上下文的连贯性 |

## 容易做错的三处
- 现象：界面提示上下文token超限，无法生成需求与设计文档。原因：未根据适配文档的实际token量调整`maxContext`参数，默认配额不足以承载完整的适配清单与测试报告内容。
- 现象：无法找到`maxContext`或`quoteMaxToken`的配置入口，或误将分块长度设置为token单位。原因：未在FastGPT v4.17.0的知识库配置页中找到对应设置项，混淆了分块长度的单位规则。
- 现象：上传部分包含嵌入式表格的适配文档时触发资源超限报错。原因：嵌入式表格转换为文本token的占比超出单次处理配额，未调整分块长度参数。

## 怎么确认配好了
- 上传单篇典型适配清单文档，查看上下文预览窗口中显示的召回内容是否覆盖核心软硬件型号与测试结论。
- 查看配置项的实际取值，确认`maxContext`与`quoteMaxToken`的设置符合当前项目的文档长度要求。
- 发起一次需求文档生成测试，检查生成的文档是否包含完整的迁移方案与风险评估内容。
- 测试多文档召回场景，确认召回的条目数量符合单次召回上限的设置。
