# 信创替代适配的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
信创替代适配的需求与设计文档相关数据，服务于企业IT架构师、国产化项目组与系统集成商，通常来源于现有系统清单、国产软硬件目录、测试环境配置与厂商公开资料。日常产出的文档包括适配清单、兼容性测试报告、迁移方案与问题台账，文档字段包含存量系统名称、替换国产软硬件型号、兼容性验证结果、迁移风险等级等，单位以系统数量、测试项个数、版本号为主。数据更新频率以单个适配项目为周期，或按季度同步最新国产软硬件目录信息。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且字段多样，要求多轮对话需逐步引导提取完整的存量系统与适配信息，避免遗漏核心字段。数据更新周期灵活，要求上下文管理需按项目隔离，避免不同项目的适配数据混淆。文档篇幅随项目复杂度增长，要求提示词需明确限定输出格式，防止生成冗余内容。出错后果影响业务可用性，要求多轮对话中需加入校验逻辑，确保生成的文档符合信创适配的合规要求。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` 绑定规则 | 绑定单个信创适配项目ID | 隔离不同项目的对话上下文，避免数据交叉污染 |
| `messages` 格式校验 | 强制按「用户-助理」轮次结构 | 确保多轮对话的上下文符合需求文档起草逻辑 |
| `variables` 注入配置 | 开启 | 用于加载当前项目的存量系统清单、国产软硬件目录等专属数据 |
| 历史对话召回条数 | 前3–5条 | 匹配项目级数据更新节奏，减少冗余上下文干扰 |
| 最大上下文长度 | 8000–12000 token | 适配信创文档的平均篇幅，避免截断核心适配信息 |
| 会话超时时间 | 30分钟 | 适配项目文档起草的平均耗时，防止会话意外中断 |

## 容易做错的三处
- 工作流对话显示失败但模型测试正常：现象为界面返回异常状态码，后台无对应对话日志，原因是未正确绑定`chatId`导致上下文无法被工作流读取。
- 调用节点无法传入历史对话：现象为节点返回的上下文为空，原因是未配置历史对话召回条数，或未按`messages`轮次格式保存对话内容。
- 对话日志为空：现象为工作流节点的日志面板无内容，原因是未开启会话日志存储，或`chatId`绑定错误导致上下文未被记录。

## 怎么确认配好了
- 发起一轮测试对话，传入预设的存量系统清单，检查返回的文档是否包含对应字段，验证`variables`注入生效。
- 发起两轮连续对话，查看上下文是否自动保存上一轮的提问与回复，验证历史对话召回配置正确。
- 触发一次异常调用，检查是否生成对应日志记录，验证日志存储配置生效。
- 切换不同的项目ID发起对话，验证上下文不会跨项目共享，确认`chatId`绑定规则生效。
