# 信息化预算与项目组合管理的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据通常来自财务系统、项目管理系统、合同台账及业务部门提报的需求。日常产出的文档包括年度预算表、项目立项书、项目组合看板与投资复盘报告，数据更新节奏多为月、季或年度。文档字段通常包含项目编号、预算额度、优先级标识、收益预估等，单位涉及万元、项目周期（月）等，无统一标准化格式，需结合多系统数据整合后生成正式文档。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散导致单次输入的上下文跨度大，需限定有效上下文范围以避免冗余信息干扰。更新频率固定的批量数据，需在对话中明确指定对应周期的数据集，避免跨周期数据混淆。文档字段多样且无统一格式，提示词需明确要求对齐业务部门常用的字段定义，确保生成文档符合业务习惯。多主体协同的需求收口环节，需通过多轮对话逐步澄清模糊的需求描述，减少信息偏差。项目组合管理涉及的优先级排序逻辑复杂，提示词需包含预设的优先级判定规则，降低人工调整成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–10000 字符 | 适配多轮需求澄清的对话长度，符合FastGPT v4.17.0的上下文管理上限 |
| `messages` 格式 | 按「用户提问-助理回复」的结构化格式存储 | 适配多轮对话的上下文回溯，保证对话逻辑连贯 |
| `variables` 作用域 | 限定在当前项目组的会话内 | 避免跨项目的预算数据混淆，符合品类的项目隔离需求 |
| `chatId` | 绑定当前项目组的唯一标识 | 确保多轮对话的上下文绑定到对应项目，避免跨项目混淆 |
| 数据源绑定 | 绑定财务系统、项目管理系统的预设变量 | 对齐品类数据来源，确保生成内容引用真实业务数据 |
| 会话超时时间 | 600 秒 | 适配需求收口环节的多轮沟通节奏，避免会话提前终止 |

## 容易做错的三处
- 现象：工作流中配置多个AI对话节点后，最终聊天界面展示所有节点的回复内容。原因：未对非核心对话节点的输出配置隐藏规则，导致上下文冗余。
- 现象：单次提问后无法触发多轮反问，仅能获取单次回复。原因：未开启多轮对话的上下文保留配置，导致每次提问重置会话上下文。
- 现象：生成的预算文档字段缺失或格式不符。原因：提示词未明确绑定品类专属的文档字段规则，未对齐业务部门的常用格式。

## 怎么确认配好了
- 发起一轮需求澄清的多轮对话，检查上下文是否保留前序提问与回复内容。
- 调用绑定的数据源变量，验证生成内容是否引用了对应系统的真实数据字段。
- 配置多个AI对话节点，测试非核心节点的输出是否不会展示在最终聊天界面。
- 生成一份测试文档，检查是否包含预设的项目编号、预算额度等必填字段。
