# 信息化预算与项目组合管理的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
该品类的日常文档包含年度预算表、项目立项书、项目组合看板、投资复盘报告，数据来源为财务系统、项目管理系统、合同台账与业务部门需求。文档更新频率多为月、季或年，部分核心看板按周同步。文档结构差异明显：预算表为多行列数字表格，附带项目编码与优先级标签；立项书包含结构化的预算申请、周期说明与收益预估；投资复盘报告则混合段落总结与图表数据。字段包含预算金额、项目周期、优先级等级等，单位多为万元、人天、季度。

## 这些特征在「文档解析与分块」这一环带来什么约束
品类文档的结构差异与字段特性，对解析分块环节带来多重约束。首先，多格式混合的数据源要求解析工具适配Excel、Word、PDF等多种导出格式，避免因格式解析失败丢失预算金额、项目编码等核心字段。其次，密集的数字表格内容若分块过碎，会拆分跨行列的预算明细，导致数据关联性断裂；若分块过大，则会混入无关章节内容，影响后续预算优先级排序的准确性。此外，低频更新的大型文档（如年度预算表）需要更长的解析时长，默认配置易出现超时中断，需针对性调整超时参数。

以下配置基于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配品类文档的密集字段密度，避免拆分跨行列的预算明细与项目编码 |
| `chunkSplitter` | 按标题+段落拆分 | 匹配立项书、复盘报告的章节结构，将同一优先级的项目内容整合为一个分块 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 支持大型年度预算表的完整解析，避免因耗时过长触发超时报错 |
| `customPdfParse` | 开启 | 保留从项目管理系统导出的PDF看板的表格对齐格式，防止数字字段错位 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配季度汇总的大型项目组合看板文件，满足日常导入需求 |
| `chunkSettingMode` | 手动模式 | 针对不同文档类型切换分块规则，预算表用固定字符分块，立项书用标题分块 |

## 容易做错的三处
- 现象：上传文件后解析节点无工作日志，或日志报slow operation xxxxms。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，大型预算表的解析耗时超出默认阈值，导致解析中断。
- 现象：从数据库表格导入的项目数据仅抓取部分内容。原因：`chunkSize`设置过小，将跨多行的预算明细行拆分，导致部分项目编码与对应金额未完整提取。
- 现象：Markdown格式的预算表格输出被截断。原因：未开启`customPdfParse`，解析时丢失表格的行列结构，导致内容被错误拆分。

## 怎么确认配好了
- 上传一份100MB左右的年度预算表，查看解析进度是否在10分钟内完成，无超时相关报错。
- 提取解析后的分块内容，核对是否包含完整的项目优先级字段与对应预算金额，无字段拆分断裂的情况。
- 上传带表格格式的PDF立项书，确认解析后保留原表格的行列对齐格式，无乱码或内容错位。
- 检查知识库上传限制，确认`UPLOAD_FILE_MAX_SIZE`设置不低于日常导入的最大文档体积。
