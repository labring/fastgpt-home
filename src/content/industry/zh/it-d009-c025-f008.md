# 值班排班与交接的需求与设计文档起草：工作流编排
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
值班排班与交接的核心数据包括值班表、交接记录、升级联系人清单、值班日报。数据来源为排班系统、故障工单、监控告警与组织通讯录，更新频率为日或周。文档字段包含值班时段、值班人员姓名、联系方式、未结事项、升级路径等，无额外统计类字段。

## 这些特征在「工作流编排」这一环带来什么约束
多数据源的接入要求工作流节点需分别对接排班系统、故障工单等不同平台，完成字段映射。日/周的更新频率要求工作流触发时机需匹配数据刷新节奏，避免使用过于频繁的触发逻辑。排班冲突协调、未结事项交接等耗时环节，要求工作流内置校验规则与分支处理逻辑。数据异常或校验不通过时，需触发告警通知相关人员，防止出现无人响应、交接遗漏等后果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 用户选择组件 | 绑定组织通讯录的值班人员字段 | 依据：需提供已授权的值班人员选项 |
| 表单输入组件 | 支持传入`variables`变量 | 依据：可自动填充排班系统已有的未结事项内容 |
| `nodeId` | 绑定冲突校验节点的ID | 依据：快速跳转至排班冲突的处理分支 |
| 触发时机 | 每日8点 / 每周一0点 | 依据：对应数据更新频率为日/周 |
| 数据校验规则 | 校验值班时段不重叠、升级路径完整 | 依据：避免排班冲突与交接遗漏 |
| API访问配置 | 开启用户交互提示 | 依据：确保发布渠道调用时弹出表单输入提示 |

## 容易做错的三处
- 现象：将v4.6.7版本的工作流导入v4.8.10版本后，`variables`参数绑定失效。原因：新旧版本的变量存储结构存在差异，未完成兼容映射。
- 现象：通过API调用发布的工作流，未弹出用户选择或表单输入的交互提示。原因：未在API访问配置中开启用户交互提示开关。
- 现象：配置升级路径校验时，未关联故障工单数据导致字段为空。原因：未将数据来源与工作流节点正确绑定，遗漏了故障工单的字段映射。

## 怎么确认配好了
- 打开工作流的预览界面，选择任意值班人员与时段，验证表单输入组件是否自动填充`variables`中的未结事项内容。
- 触发定时任务，检查工作流是否按设定的每日/每周时间点启动，且校验规则拦截了重叠的排班时段。
- 通过API调用工作流，确认界面弹出用户选择与表单输入的交互提示。
- 导出工作流的配置日志，检查`nodeId`与冲突校验节点的绑定关系是否正确。
