# 值班排班与交接的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
本品类的数据来自运维排班系统、故障工单库、监控告警平台及组织通讯录。日常处理的文档包括标准化值班表、跨班次交接记录、升级联系人清单、每日值班日报。文档结构包含明确的时间字段、责任主体字段、未结事项条目与联系方式，更新频率为每日或每周。数据以结构化文本为主，部分交接记录包含非结构化的手写备注或截图附件。

## 这些特征在「文档解析与分块」这一环带来什么约束
数据来源多样且更新频率不一，要求解析模块支持批量处理多格式文档。值班表的时间字段需精准匹配班次时段，分块时需保留时间与责任主体的关联关系，避免语义断裂。交接记录包含未结事项与联系方式，分块长度需覆盖完整的事项条目，确保检索时可获取完整信息。部分文档含附件截图，需支持图文混合解析，同时需控制解析超时时间，避免批量处理时出现阻塞。升级联系人清单的字段格式统一，可针对性优化分块规则以提升检索匹配精度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的文档解析模块说明，针对值班排班与交接场景的文档解析与分块环节制定如下建议：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 值班表与交接记录的单条事项长度多在500-1000字符，该区间可保留完整的班次时段、未结事项等核心信息，避免拆分导致语义断裂 |
| `chunkSplitter` | 按段落+标题拆分 | 日常文档包含值班时段标题、交接事项段落等结构化内容，按段落+标题拆分可保留语义完整性，提升检索匹配精度 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 180 秒 | 批量解析多份周度值班表或含多张截图的交接记录时，需预留足够处理时间，避免因超时导致解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 支持包含多张截图的交接记录文档，满足运维场景下的附件上传需求 |
| `customPdfParse` | 开启 | 值班表与交接记录多以PDF格式存档，开启该配置可精准提取文本与内嵌图片的关联信息 |
| `chunkSettingMode` | 手动配置 | 针对排班类文档的特殊字段（如班次时段、责任人员），手动配置可优化分块规则，提升检索匹配的针对性 |

## 容易做错的三处
1.  现象：Docker部署环境下解析排班文档时日志报slow operation xxxxms。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，批量解析多份周度值班表时超时未完成。
2.  现象：上传含图片的交接记录文档后，返回结果显示无效图片字段。原因：未开启`customPdfParse`配置，默认解析逻辑无法提取内嵌图片的关联文本信息。
3.  现象：批量解析升级联系人清单时返回结果条数不足。原因：`chunkSize`设置过小，将完整的联系人条目拆分为多个分块，导致检索时无法匹配完整清单信息。

## 怎么确认配好了
1.  上传一份标准值班表PDF文档，查看解析后的分块结果，确认每个分块包含完整的班次时段与责任人员信息。
2.  上传含内嵌图片的交接记录文档，检查解析结果是否包含图片的关联文本描述，无报错提示。
3.  批量上传5份周度值班文档，查看日志无超时报错，确认`PARSE_FILE_TIMEOUT_SECONDS`配置生效。
4.  查看系统参数配置页面，确认`chunkSettingMode`为手动配置状态，`chunkSize`取值符合预设区间。
