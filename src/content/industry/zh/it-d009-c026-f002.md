# 关卡内容制作的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
关卡内容制作的通常核心数据来自关卡编辑器、美术资源库、玩家测试数据与缺陷系统。日常通常产出的文档包含关卡设计稿、资源需求表、测试反馈单与版本提交记录，结构覆盖关卡编号、路径节点、资源点位、任务触发条件、测试结果等字段。数据更新频率为周度或每版本迭代，单次文档的内容长度随关卡规模增长，核心字段多且关联紧密。

## 这些特征在「上下文与 token」这一环带来什么约束
关卡内容制作的数据更新频繁且关联紧密，要求上下文窗口需及时同步最新的关卡编辑与测试反馈内容，避免使用过期的资源需求或测试结果。文档结构复杂且字段多，需优先保留关卡路径、资源点位等核心信息，因此token分配需平衡内容完整性与模型调用效率。周度或版本级的更新节奏，要求上下文召回需匹配数据更新周期，防止冗余旧数据混入。同时，关卡内容出错会导致卡关或上线延期，需严格控制上下文的token总量，避免超出模型承载上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配关卡设计稿、资源需求表的总内容长度 |
| `quoteMaxToken` | 1500–2000 token | 匹配单份测试反馈单或资源需求条目的内容规模 |
| 上下文召回上限 | 前6条 | 平衡召回内容的数量与token消耗，避免超出模型阈值 |
| 上下文重叠长度 | 200–300 字符 | 防止关卡路径、资源点位等核心信息被分块截断 |
| 模型最大输出token | 4000 token | 适配关卡玩法规则的详细描述需求 |

## 容易做错的三处
-  配置上下文召回上限为3000后，大模型接收不到完整上下文。可验证排查项：检查单条引用与总上下文的token限制配置是否匹配，确认阈值设置合理
-  离线部署环境中出现cl100k.tiktoken外网请求报错。可验证排查项：检查离线部署环境是否可访问外网获取tokenizer依赖文件，或确认本地tokenizer文件已正确部署
-  高并发调用时出现模型响应超时。原因是未根据硬件配置调整上下文处理的并发阈值，超出系统承载能力。

## 怎么确认配好了
-  检查FastGPT v4.17.0部署环境的服务端环境变量，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`已正确配置，无额外路径后缀。
-  发起针对关卡设计文档的测试请求，查看上下文预览模块是否包含最新的关卡路径、资源点位等核心信息。
-  调整上下文相关配置后，验证模型输出是否覆盖完整的关卡玩法规则与资源需求说明。
-  查看系统日志，确认无token统计相关的外网请求报错，无上下文截断提示。
