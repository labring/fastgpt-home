# 关卡内容制作的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
关卡内容制作的核心数据来自关卡编辑器、美术资源库、玩家测试数据与缺陷系统。日常产出的文档包含关卡设计稿、资源需求表、测试反馈单与版本提交记录，字段涵盖关卡坐标、资源ID、测试反馈条目、版本号等，无统一固定单位，随单份文档的具体内容调整。数据更新频率为周度或每版本提交周期，通常随关卡迭代进度同步更新。

## 这些特征在「工作流编排」这一环带来什么约束
关卡内容制作的工作流需适配多源数据的关联需求，例如需将关卡编辑器导出的坐标数据与美术资源库的资源ID绑定，因此需要支持跨数据源的字段映射。周度或版本级的更新节奏要求工作流需按固定周期触发，避免频繁执行导致资源浪费。同时，文档字段无统一单位，工作流需支持灵活的字段校验规则，适配不同关卡的个性化配置。此外，出错后果可能导致卡关或上线延期，工作流需加入前置校验环节，减少人工疏漏的概率。不同于其他游戏研发品类，关卡内容制作的工作流需聚焦具体地图与任务的规则落地，聚焦个性化的关卡配置需求。

## 配置怎么定
本配置适用于FastGPT v4.17.0及以上版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables`绑定配置 | 绑定关卡ID、资源版本号、测试批次号为全局变量 | 匹配关卡内容制作的多源数据关联需求，确保不同环节的工作流可共享核心标识 |
| `nodeId`分配规则 | 为表单节点、知识库调用节点分配固定`nodeId` | 支持跨分支复用节点，解决链路跳转无法识别目标节点的问题 |
| 上下文长度设置 | 800–1200 字符 | 适配关卡设计文档的单段平均长度，避免上下文信息过载 |
| 触发时机配置 | 按版本提交周期触发，间隔7天 | 匹配周度或每版本的更新节奏，减少无效执行 |
| 字段校验规则 | 自动校验资源需求表的必填字段完整性 | 减少人工梳理文档的疏漏，匹配日常文档的核心字段要求 |
| 超时阈值设置 | 600 秒 | 适配关卡数据的加载与处理时长，避免因数据量过大导致工作流中断 |

## 容易做错的三处
- 现象：跨分支调用表单节点时，链路无法跳转，节点未触发。原因：未为目标节点配置固定`nodeId`，导致工作流无法识别复用节点的唯一标识。
- 现象：调用工作流API返回空值，嵌套知识库助手的场景下无结果输出。原因：未在`variables`中正确绑定知识库关联的关卡资源ID参数，导致上下文匹配失效。
- 现象：变量引用时抛出`quote type error`报错。原因：未按要求将变量格式化为对应数据类型，例如将字符串类型的关卡版本号直接传入数值型字段。

## 怎么确认配好了
- 手动触发一次工作流，选择跨分支调用表单节点，检查节点是否正常唤起并执行，确认`nodeId`配置生效。
- 调用工作流API，验证返回结果包含预期的关卡设计文档片段，确认`variables`绑定的全局变量正确生效。
- 提交一份包含完整必填字段的资源需求表，检查工作流是否自动同步对应字段到生成的文档中，确认校验规则配置正确。
- 输入格式错误的变量，检查工作流是否抛出对应报错，确认超时阈值与校验规则配置有效。
