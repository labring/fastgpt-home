# 内容审核规则运营的需求与设计文档起草：工作流编排

本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的数据来源为内容审核后台、用户举报渠道、公开法规政策、标注样本库。日常维护的文档包括审核规则、处置指南、申诉记录、质检报告，文档字段包含规则条款、样本标签、处置阈值、申诉状态、处置结果等。数据更新频率为每日同步或随政策变更触发更新，更新节奏随业务优先级调整，无固定统计周期外的额外要求。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散要求工作流支持多源数据拉取，需配置跨数据源的变量拉取规则；更新频率不固定要求工作流支持按需触发或定时触发，避免依赖固定周期的同步逻辑；文档字段复杂要求工作流需支持自定义字段映射，适配不同类型审核文档的结构；规则解释与申诉复核环节耗时较长，要求工作流可拆分节点并支持人工干预，同时需保留完整流程日志用于溯源；出错后果严重要求工作流配置失败重试与告警机制，避免违规内容扩散或误伤创作者。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定审核规则、申诉记录、质检报告的核心字段 | 适配本品类多来源的文档数据结构 |
| 触发方式 | 按需触发或按政策变更触发（按实测标定） | 适配数据更新频率不固定的业务特征 |
| `nodeId` | 为规则解释、申诉复核节点分配唯一标识 | 便于流程日志的溯源与节点状态追踪 |
| 失败重试 | 重试2次，间隔60秒 | 应对多源数据拉取的不稳定风险 |
| 日志保留 | 保留全流程日志180天 | 满足合规溯源与问题排查需求 |
| 人工节点配置 | 允许在规则解释、申诉复核环节插入人工审批 | 适配本品类耗时且需人工判定的业务环节 |

## 容易做错的三处
- 现象：特定工作流在执行至知识库搜索或AI对话节点后终止，流程状态显示失败或无返回结果，同配置下仅特定问题触发该情况。原因：未通过`variables`绑定第三方API返回的审核样本字段或历史会话数据，节点依赖的参数为空，触发流程中断。
- 现象：尝试将历史申诉记录作为变量传入代码节点时无对应选项，无法完成参数传递。原因：未在`variables`配置中开启历史记录绑定开关，导致全局变量池未收录该类数据。
- 现象：工作流启动后未自动调用第三方API获取审核规则数据，无法完成后续节点的参数准备。原因：未在触发节点配置中添加第三方API调用步骤，或未通过`variables`绑定API返回的字段。

## 怎么确认配好了
- 触发工作流，核对各节点加载的字段是否与配置的`variables`绑定项一致。
- 模拟多源数据拉取场景，检查节点是否能正确获取审核后台、用户举报的对应数据。
- 触发流程中断测试，确认失败重试与日志记录功能正常启用。
- 连接跨节点的数据链路，验证输出数据是否能在不同节点间正常传递。
