# 内容推荐运营的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
内容推荐运营的日常数据来源包含内容标签、用户行为日志、实验平台、推荐后台。日常产出的文档包括推荐策略记录、内容池清单、实验报告、运营复盘，其中内容池清单包含内容唯一标识、分类标签、上线时间，实验报告包含实验分组、交互次数、停留时长。数据更新节奏通常为日或周，核心耗时环节集中在内容池筛选、实验指标解读、异常流量排查，异常处理不当可能引发业务风险。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散要求工作流需整合多个异构数据源节点，避免手动拼接数据的误差。文档结构固定且字段明确，需要通过`variables`定义字段映射规则，确保不同节点间的数据格式统一。更新频率的周期性要求工作流支持定时触发机制，适配日/周级别的数据更新节奏。耗时环节较多则需要拆分工作流为并行子任务，同时需配置失败处理节点，应对异常流量排查等临时波动，避免引发业务风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 定时触发周期 | `1 天` 或 `7 天` | 匹配数据日/周更新的常规节奏 |
| `variables`字段映射 | 按文档字段名一对一绑定 | 适配推荐策略记录、内容池清单的固定结构 |
| 失败重试次数 | `2-3 次`，间隔`60 秒` | 应对异常流量排查的临时波动 |
| 日志记录开关 | 开启 | 留存实验数据用于后续运营复盘 |
| `nodeId`绑定规则 | 使用已上线应用的唯一节点ID | 确保调用的是指定应用实例，避免调用错误节点 |
| 分享参数传递 | 开启URL参数绑定 | 支持多场景调用全局变量 |

## 容易做错的三处
- 调用外部应用或插件节点后，对话日志字段为空。原因是未开启跨节点日志同步开关，导致调用记录未被捕获。
- 旧版本工作流运行时提示“文本加工节点不存在”。原因是FastGPT v4.17.0版本升级后功能节点重构，原文本加工节点被整合为通用处理节点，需重新配置对应环节。
- 通过分享链接带入全局变量时，参数未被加载。原因是未开启分享链接的参数绑定权限，导致URL参数无法传递至工作流的`variables`中。

## 怎么确认配好了
- 触发定时工作流，检查对应数据源节点是否拉取到最新的内容池或实验数据。
- 运行跨节点调用任务，确认日志面板中记录了完整的交互与数据流转信息。
- 生成分享链接并携带测试参数后访问，检查工作流的`variables`参数是否加载了对应值。
- 模拟异常场景，如模拟数据源拉取失败，确认工作流触发失败重试机制并生成对应告警。
