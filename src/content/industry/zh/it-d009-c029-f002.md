# 内容版权与授权管理的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
本品类数据主要来自合同系统、版权登记信息库、内部内容库及投诉邮箱，日常处理的文档包括授权合同、版权台账、下架通知与侵权投诉材料。数据更新以单业务订单或月度为周期，单份文档包含授权主体、授权范围、授权期限、侵权细节等字段，每份材料关联具体内容ID与权利归属信息，需按业务节点完成新增、更新或归档操作。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类数据的跨文档关联属性要求上下文召回需覆盖授权合同、版权台账等多类材料，避免关键权利归属、授权范围等信息遗漏；单份文档字段多且关联具体内容ID，需限制单轮上下文的token总量，防止超出大语言模型的处理上限；月度或单订单的更新节奏要求上下文配置可灵活调整召回范围，同时需适配投诉邮箱等非结构化数据的提取，避免无效token消耗；授权范围、期限等核心字段的核对需求，要求上下文召回的内容必须完整，不能出现截断或关键信息缺失。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配本品类多文档关联的内容规模，避免授权范围、权利归属等关键信息被截断 |
| `quoteMaxToken` | 1500–2000 字符 | 匹配单份授权合同条款、侵权投诉材料的文本长度，确保核心内容完整提取 |
| 单次召回上限 | 前6条关联文档 | 覆盖单业务周期内的版权台账、下架通知等材料，控制上下文token总消耗 |
| 上下文召回跨度 | 按业务周期标定 | 适配月度或单订单的更新节奏，避免召回过期或无关的授权数据 |
| 非结构化数据处理token限制 | 按实测标定 | 适配投诉邮箱的非结构化文本，确保侵权细节完整提取 |

## 容易做错的三处
- 现象：知识库查询返回的内容中，授权合同的图片地址被截断，无法正常访问。原因：未调整`quoteMaxToken`配置，取值低于单份授权合同附带文本的长度。
- 现象：调用应用API时未返回历史授权台账的关联信息。原因：未正确配置`maxContext`，未召回跨周期的历史关联数据。
- 现象：单次查询消耗的token远超预期，接近设置的5万token上限。原因：单次召回上限设置过高，同时未限制`maxContext`的总token规模，导致冗余内容被纳入上下文。

## 怎么确认配好了
- 发起一次包含授权范围核对的测试查询，检查返回内容是否包含完整的授权条款与关联文档信息。
- 查看API调用日志，确认上下文召回的token总量未超出预设的`maxContext`上限。
- 核对单次召回的文档条数，确认与配置的单次召回上限一致。
- 测试调用历史侵权投诉相关的查询，确认返回内容包含跨周期的关联材料。
