# 内部网络与WiFi运维的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自交换机控制台、无线控制器、办公区监控系统及一线用户报障渠道。日常产出的文档包含网络拓扑图、网络变更单、设备故障记录、无线覆盖巡检表，字段涵盖设备端口号、VLAN配置、信号强度数值、巡检时间戳等，单位涉及dBm、端口号、VLAN ID等。数据更新频率随运维动作调整，日常巡检数据按日更新，网络变更或故障处置后即时更新相关文档。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据来源分散，包含交换机控制台日志、无线控制器配置、巡检表数值及用户报障内容，不同来源的上下文格式差异显著，需统一清洗后才能纳入token处理流程。日常文档更新频率随运维动作波动，网络变更或故障处置时会批量新增数据，若上下文token配额不足，易丢失关键端口、VLAN配置等核心信息。巡检表中的信号强度、端口号等字段单位与格式不统一，未做前置处理会占用额外token且降低上下文匹配精度。运维场景需覆盖近期7天内的变更与巡检数据，对token的有效分配与窗口设置提出明确约束。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `maxContext` | 8000–12000 token | 该品类需覆盖7天内的网络拓扑、变更单、巡检表等核心数据，此区间可容纳完整运维信息且避免全局token溢出 |
| `quoteMaxToken` | 1000–1500 字符 | 单条运维文档的核心内容通常不超过此范围，可保证引用信息完整且不占用过多上下文配额 |
| 上下文召回上限 | 前6–8 条 | 该品类的有效运维数据量适中，过多召回会占用额外token，过少则遗漏关键故障记录或变更信息 |
| 上下文更新触发规则 | 每日定时 + 运维变更触发 | 日常巡检数据按日更新，网络变更或故障处置后即时触发更新，可保证上下文数据的时效性 |
| 上下文清洗阈值 | 按实测标定 | 该品类的数据格式包含端口号、VLAN ID、信号强度等多类型字段，需根据实际接入的数据源调整清洗规则，避免无效信息占用token |

## 容易做错的三处
- 现象：启动后返回`AIPROXY_API_ENDPOINT`未配置或`AIPROXY_API_TOKEN`无效的报错，或请求模型时返回401状态码。原因：未配置App/Admin服务端的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量，或填写的`AIPROXY_API_ENDPOINT`格式错误（如遗漏http/https前缀）。`AIPROXY_API_ENDPOINT`为AI Proxy服务根地址，`AIPROXY_API_TOKEN`为AI Proxy管理员Token，与模型接口地址及模型授权令牌无关。
- 现象：生成的需求与设计文档中缺少近期的网络变更单内容，或故障记录匹配不全。原因：`maxContext`配置值过小，无法容纳7天内的全部核心运维数据，导致关键上下文被截断。
- 现象：单条引用的运维文档内容不完整，仅显示开头部分。原因：`quoteMaxToken`配置值小于目标文档的核心内容长度，导致引用内容被提前截断。

## 怎么确认配好了
- 查看上下文窗口的实时占用情况，确认当前配置的`maxContext`值适配已接入的运维数据总量，调整时需结合近期数据更新频率与新增量。
- 手动导入一条完整的变更单或故障记录，检查引用内容的完整度，确认`quoteMaxToken`配置值匹配该文档的核心内容长度。
- 触发一次运维文档的召回测试，核对返回的召回条数是否符合配置的上下文召回上限，确认召回规则生效。
- 检查App/Admin服务端的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量配置值，确认格式正确且与AI Proxy服务端配置一致。
