# 创作者激励结算的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
创作者激励结算的核心数据来自内容数据、广告分成系统、财务系统与账号后台。日常产出的文档包含激励规则、结算明细、申诉记录与付款清单，核心字段包括创作者唯一标识、收益金额、结算周期、申诉状态与付款进度，单位涵盖元、条、天等。数据更新频率为月度或单次活动结束后，无实时高频更新需求，单批次数据量随活动规模波动。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的整合要求工作流支持跨系统接口调用，需预先配置各数据源的权限与字段映射规则。月度/活动级的更新节奏决定工作流需适配定时触发或事件触发模式，避免无效重复执行。文档字段的多样性要求工作流变量需精准绑定业务字段，防止数据错位。最耗时的收益核对、异常排查环节，要求工作流内置校验与分支跳转节点，同时出错后果需通过异常处理流程降低结算争议与错付风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `variables` | 映射创作者ID、收益金额、结算周期、申诉状态 | 匹配业务文档的核心字段，确保工作流处理的数据与实际业务一致 |
| `nodeId` | 为收益核对节点、异常处理节点分配唯一标识 | 快速定位工作流中的关键环节，便于运行日志排查与流程调整 |
| 触发方式 | 每月1日 00:00 定时触发，或按活动完成事件触发 | 匹配月度/活动级的更新频率，避免重复执行无效任务 |
| 超时阈值 | 设置为600秒 | 匹配单批次结算数据的处理时长，避免工作流无故中断 |
| 单次拉取数据上限 | 限定为1000条 | 控制单批次调用的负载，避免工作流运行超时 |
| 异常分支配置 | 为收益核对失败、付款资料校验不通过设置独立跳转路径 | 覆盖最耗时的异常排查环节，降低错付漏付与创作者流失风险 |
| 输出节点 | 生成结算明细、付款清单的结构化文档 | 匹配日常运营归档的文档类型，满足业务留存需求 |

## 容易做错的三处
- 现象：工作流中途输出HTML代码未在界面显示，直接进入下一分支。原因：未在输出节点配置HTML渲染权限，或节点执行顺序错误导致HTML未被前置处理。
- 现象：工作流运行超时，日志显示执行时长超出600秒阈值。原因：未限定单次调用的数据范围，同时拉取全量历史结算数据导致负载过高。
- 现象：工具调用后回答中出现知识库搜索的input和response内容。原因：未在回答生成节点关闭知识库关联配置，或未限定仅使用工具调用结果作为回答来源。

## 怎么确认配好了
- 触发一次测试工作流，检查输出的结算明细文档字段是否与业务系统数据一致。
- 模拟收益核对失败的异常场景，确认工作流是否跳转至预设的异常处理分支。
- 查看FastGPT v4.17.0版本下的工作流运行日志，确认仅调用了财务系统、广告分成系统等指定的数据源接口。
- 测试工具调用后的回答输出，确认未出现知识库搜索相关的input和response内容。
