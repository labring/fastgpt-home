# 前端应用开发的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
该品类的核心数据来自代码仓库、接口管理平台、设计稿文件与浏览器兼容性数据集。日常产出的文档包含接口文档、组件说明、联调记录、版本发布清单，数据字段多包含接口路径、参数定义、组件属性、兼容机型版本等。数据更新频率多为每日或每版本迭代，随代码提交、接口调整、兼容测试更新同步变化。

## 这些特征在「上下文与 token」这一环带来什么约束
前端文档随版本高频更新，要求上下文关联的历史数据需匹配最新版本，避免过时信息干扰。多源数据格式差异大，需在上下文整合时统一字段映射逻辑，防止token溢出。浏览器兼容性数据条目多且颗粒度细，若上下文召回过多会占用过多token配额，导致核心文档信息被截断。联调记录包含时序性操作，上下文需要保留关联的时间与场景信息，进一步增加了token管理的复杂度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 800–1200 字符 | 适配前端需求文档、接口文档的平均篇幅，避免token配额溢出 |
| `quoteMaxToken` | 500–700 token | 匹配前端组件说明、联调记录的单段内容长度，保留完整参考信息 |
| 上下文召回条数 | 前 3 条 | 前端核心参考文档关联性集中，少量召回即可覆盖业务场景 |
| 分块重叠长度 | 100–150 字符 | 保留接口参数、组件属性等跨块关联内容，避免信息断裂 |
| 上下文更新触发规则 | 按版本提交触发 | 匹配前端数据日更或每版本更新的节奏，确保召回最新内容 |

## 容易做错的三处
- 配置`maxContext`时设置为过长数值，导致token超限报错，界面返回结果为空或截断。原因是未匹配前端文档的平均篇幅，过多召回非核心数据占用配额。
- 未设置合理的分块重叠长度，导致接口文档的参数定义跨块断裂，联调时无法获取完整参数信息。原因是忽略了前端文档中接口参数与路径的强关联属性。
- 部署FastGPT的App/Admin服务时未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`环境变量，可能导致上下文召回请求失败，返回连接超时或权限错误。`AIPROXY_API_ENDPOINT`为AI Proxy服务的根地址，例如`http://aiproxy:3000`，不得附加`/v1`或单模型服务地址；`AIPROXY_API_TOKEN`为与AI Proxy服务端配置一致的非空管理员Token。二者均为服务端环境变量，不得通过工作流全局变量、应用API请求头或界面配置替代。

## 怎么确认配好了
- 上传一份典型的前端接口文档，测试上下文召回结果是否包含所需的接口路径与参数定义，调整召回规则直至覆盖核心内容。
- 提交版本更新后，验证上下文召回的文档是否为最新版本，确认更新触发规则生效。
- 模拟联调场景输入查询，检查返回的上下文内容是否未出现跨块断裂的信息，验证分块重叠长度设置合理。
- 查看token使用统计面板，确认单轮请求的token消耗未超过预设配额，调整相关参数至符合业务需求。
