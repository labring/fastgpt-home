# 前端应用开发的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
前端应用开发场景的日常文档包含接口文档、组件说明、联调记录、发布清单四类，数据来源为代码仓库、接口管理平台、设计稿、浏览器兼容性数据。接口文档包含接口路径、请求方法、参数类型、返回字段等结构化内容；组件说明包含props、事件、插槽等配置项；联调记录为零散的步骤与问题记录；浏览器兼容性数据按终端类型与版本划分支持情况。数据更新频率为每日或每版本发布周期。

## 这些特征在「文档解析与分块」这一环带来什么约束
文档类型多样且混合结构化内容与代码片段，要求解析与分块逻辑需适配不同文档结构，避免拆分单个接口参数、组件配置等完整单元。文档来源包含代码仓库与接口管理平台，部分导出的PDF文档存在表格排版丢失问题，需针对性处理。高频更新的文档要求解析流程适配快速处理节奏，避免因超时或分块效率影响研发流程。浏览器兼容性数据按终端版本绑定，分块需保留对应终端信息，确保上下文关联完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配前端文档中接口参数、组件props等结构化内容的长度，避免拆分单个参数定义或代码块 |
| `chunkSplitter` | 按段落+代码块分隔 | 适配前端文档混合文本与代码片段的结构，保留代码块完整性与上下文关联 |
| `customPdfParse` | 开启 | 处理从接口管理平台导出的PDF格式接口文档，正确提取表格与结构化参数排版，采用本地化解析逻辑保障内容安全 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配前端团队常上传的大型组件库文档、兼容性数据集 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 匹配前端文档解析时的代码片段提取、表格解析耗时 |
| `chunkSettingMode` | 手动配置 | 针对不同类型的前端文档（如接口文档、联调记录）调整分块规则 |

## 容易做错的三处
- 现象：上传接口文档PDF后解析内容为空。原因：未开启`customPdfParse`配置，无法正确提取PDF中的表格与结构化参数。
- 现象：解析联调记录时出现上下文断裂。原因：使用默认的按字符分块逻辑，未设置`chunkSplitter`为按段落+代码块分隔，拆分了联调步骤的上下文关联。
- 现象：上传大型组件库文档时触发请求错误。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，超出默认文件大小限制。

## 怎么确认配好了
- 上传一份测试用的接口文档PDF，检查解析结果中是否保留了接口路径、请求参数的完整排版与字段对应关系。
- 上传一份包含代码片段的组件说明文档，检查解析后的分块是否未拆分单个代码块。
- 上传一份超过默认大小的测试文档，确认上传与解析流程未触发大小限制报错。
- 查看FastGPT v4.17.0的解析日志，确认`PARSE_FILE_TIMEOUT_SECONDS`配置生效，未出现超时中断。
