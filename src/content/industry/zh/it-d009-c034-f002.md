# 办公系统流程配置的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
本品类的数据主要来自企业OA系统、组织架构库、内部制度文件及一线用户反馈。日常产出的文档包含流程配置单、审批节点表、表单字段说明与变更记录。数据更新随流程变更触发，每月至少完成一次全量同步。字段涵盖审批节点权限、表单校验规则、流转路径参数等，无统一固定单位，随配置项类型变化。

## 这些特征在「上下文与 token」这一环带来什么约束
流程配置类文档的字段多为权限、路径类的结构化内容，且需关联组织架构的层级信息，上下文需要覆盖完整的审批节点链路与关联权限规则，避免出现权限遗漏。数据更新频率随变更触发，上下文窗口需支持动态适配新增的配置项，防止因旧数据覆盖导致配置偏差。单份配置文档的token量随流程复杂度提升，若token超限会导致生成的需求文档缺失关键流转规则，同时知识库检索需精准匹配节点权限与表单字段，避免召回无关的历史变更记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口 | 8000–12000 token | 适配流程配置文档的结构化内容量，覆盖完整审批链路与关联权限数据，适配FastGPT v4.17.0版本的上下文处理逻辑 |
| `quoteMaxToken` | 2000–3000 token | 限定单条召回文档的token上限，避免单条数据过长挤占上下文空间，防止大模型响应超时 |
| 单次召回数量 | 前6条 | 匹配流程配置的节点数量范围，确保召回的审批规则与表单字段完整 |
| 上下文重叠长度 | 200–300 字符 | 保留跨分块的审批节点关联信息，防止分块切割导致规则断裂 |
| `maxContext` | 按实测标定 | 适配企业自有流程的复杂度，避免因上下文超限导致生成失败 |

## 容易做错的三处
- 现象：大模型响应超时或返回内容不完整，日志显示token超限报错。原因：将引用最大token设置为50000 token，单次召回的文档总token超出大模型支持上限，挤占上下文空间。
- 现象：生成的需求文档缺失部分审批节点规则。原因：上下文重叠长度设置过小，跨分块的节点关联信息被截断，无法完整还原审批链路。
- 现象：调用API时无法保留上下文会话信息。原因：未正确配置上下文窗口的持久化参数，导致每次请求重置会话上下文。

## 怎么确认配好了
- 查看配置页面的最大上下文窗口与引用最大token取值，确认符合流程文档的平均token量，可通过单份流程配置文档的token统计工具验证。
- 发起一次模拟的流程配置需求起草请求，检查返回的文档是否包含完整的审批节点、权限规则与表单字段。
- 查看检索日志，确认单次召回的文档数量与token量符合预设配置，无过量召回的情况。
- 测试多次连续调用API，确认上下文会话信息被正确保留，无会话重置的情况。
