# 办公系统流程配置的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自企业OA系统、组织架构库、内部制度文件与用户反馈。日常产出的文档包含流程配置单、审批节点表、表单字段说明与变更记录，通常数据更新随流程变更触发，频率为每月至少一次。文档字段包含审批节点权限、表单关联规则、生效时间范围与操作人信息，无统一强制单位，部分字段需匹配企业内部组织架构编码。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
在FastGPT v4.17.0版本中，数据来源分散且需匹配企业内部组织架构，导致多轮对话需关联`variables`中的组织变量，避免跨部门权限冲突。文档结构固定但更新频繁，需通过`chatId`绑定当前流程配置会话，确保对话历史关联正确的审批节点配置。单次会话需处理审批规则、表单字段等多类信息，提示词需限定上下文范围，防止冗余数据干扰。变更记录需同步至对话历史，确保后续会话可追溯配置调整轨迹。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chatId` | 与当前流程配置单的唯一ID绑定 | 确保多轮对话关联正确的流程上下文，避免会话混淆 |
| 上下文窗口长度 | 800–1200 字符 | 匹配流程配置文档的单页平均长度，防止信息溢出 |
| `variables` | 仅加载当前流程关联的组织、表单变量 | 减少冗余数据，提升提示词准确性 |
| 历史记录保留时长 | 30 天 | 匹配流程变更的月度更新频率，便于追溯配置调整 |
| 单次对话最大轮次 | 前 5 轮 | 限制审批规则梳理的对话复杂度，避免逻辑混乱 |

## 容易做错的三处
- 现象：指定回复内容未保存至对话历史，再次打开会话时自动回复为空。原因：未绑定`chatId`与会话上下文，导致历史记录未正确关联至当前流程配置。
- 现象：多轮对话工作流执行效率低于单步调试。原因：未限定`messages`的上下文范围，加载了冗余的历史配置数据。
- 现象：语音输入对话时出现格式报错。原因：容器环境未正确配置依赖工具，且未获取足够权限安装组件。

## 怎么确认配好了
- 发起一次流程配置的多轮对话，检查`chatId`是否与当前流程配置单的唯一ID一致。
- 保存对话后关闭会话，重新打开，验证自动回复内容是否与历史记录匹配。
- 调整`variables`加载范围，确认仅加载当前流程关联的变量数据。
- 测试语音输入功能，确认容器环境依赖工具正常加载。
