# 单元测试与组件测试的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来自代码仓库、测试框架报告、需求说明与接口定义，更新节奏为每日或每次代码提交后更新。日常产出的文档包含结构化测试用例、覆盖率统计报告、Mock接口说明、缺陷跟踪单，文档字段包含测试场景编号、预期结果、代码覆盖率阈值、Mock响应参数等，无统一强制格式，随团队研发流程调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且随提交更新，要求多轮对话需关联`chatId`绑定当前研发会话上下文，避免重复拉取过期的测试框架报告。文档结构不统一，提示词需适配多种字段格式，需通过`messages`传递历史对话中的测试用例模板与缺陷单字段规则。更新频率高，需限制单次对话调用的上下文长度，避免加载过多旧数据导致卡顿。同时需通过`variables`传递当前项目的测试覆盖率阈值、Mock接口列表等动态参数，确保生成内容符合团队研发标准。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 适配单元测试与组件测试文档的平均长度，避免加载过期数据导致卡顿 |
| `chatId`绑定规则 | 绑定当前研发会话的`chatId` | 关联历史测试用例、缺陷单与覆盖率报告的上下文，避免会话混乱 |
| `messages`历史传递上限 | 前10条对话消息 | 过滤冗余的测试讨论内容，聚焦当前需求与设计文档的起草需求 |
| `variables`参数注入 | 注入当前项目的测试覆盖率阈值、Mock接口列表 | 确保生成的测试文档符合团队研发标准 |
| 单次对话超时时间 | 600秒 | 避免因加载大量测试框架报告导致对话中断 |
| 问题优化触发 | 按实测标定 | 适配不同团队的测试文档起草习惯，优化多轮对话的提问逻辑 |

## 容易做错的三处
- 现象为多轮对话时界面卡顿，日志显示上下文加载超时，原因是未限制最大上下文长度，加载了过多过期的测试框架报告与覆盖率数据。
- 现象为上传的测试用例或Mock文档未被对话调用，生成内容未包含上传数据的字段信息，原因是未通过`variables`或`messages`将上传数据绑定到当前会话上下文。
- 现象为调用多模态接口生成测试用例时返回400 invalid image错误，原因是未正确格式化上传的接口定义截图，未匹配平台要求的输入格式。

## 怎么确认配好了
- 发起测试用例起草的对话，查看上下文是否包含最近提交的测试框架报告数据，确认`chatId`绑定生效。
- 上传一份Mock接口说明文档，发起统计总结请求，确认生成内容包含上传文档的字段信息，验证`variables`参数注入生效。
- 发起多轮对话，检查对话过程中无明显卡顿，确认最大上下文长度与超时时间配置合理。
- 调用API接口传入测试用例截图，检查返回结果无格式错误，验证多模态输入配置正确。
