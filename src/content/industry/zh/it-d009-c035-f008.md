# 单元测试与组件测试的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
本品类的数据主要来自代码仓库、测试框架报告、需求说明与接口定义，更新频率为每日或每代码提交。日常产出的文档包含测试用例、覆盖率报告、Mock说明与缺陷单。测试用例包含用例标识、执行步骤、验证逻辑与关联代码模块；Mock说明包含依赖服务地址、返回参数模板；缺陷单包含关联用例、复现步骤与修复状态。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散且随代码提交高频更新，工作流编排需绑定代码提交触发节点或定时执行节点，确保文档与代码同步更新。由于文档类型多样，需配置多数据源适配节点，分别读取不同格式的测试用例、Mock说明等内容。由于测试数据构造与边界条件补齐为最耗时环节，工作流需内置自动化数据生成节点，减少人工操作。同时，需配置失败重试与告警节点，避免局部缺陷漏测导致的构建阻塞，保障研发流程顺畅。

## 配置怎么定
本配置适用于 FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发时机 | 按代码提交事件 / 每日 0 点 | 匹配本品类数据的更新频率，确保文档与代码同步 |
| 数据源路径 | 代码仓库`main`分支、测试报告输出目录 | 覆盖本品类数据的两类核心来源 |
| 变量范围 | 关联代码模块、测试用例ID | 匹配测试用例与缺陷单的核心标识字段 |
| 失败重试次数 | 2–3 次 | 应对临时的测试报告读取或数据生成失败 |
| 超时阈值 | 300 秒 | 适配单次测试数据构造的合理耗时上限 |
| 分支触发规则 | 按代码变更模块匹配 | 对应测试用例的关联代码模块字段，精准触发对应测试流程 |

## 容易做错的三处
- 工作流中代码运行节点报错，原因是未正确绑定`variables`参数，导致测试用例的输入参数未传入节点，即使代码本身无问题也无法正常运行。
- 工作流分支触发逻辑不符合预期，原因是未按代码变更模块配置分支规则，导致未匹配到对应测试用例的执行分支，无法完成针对性的文档起草。
- 调试工作流时出现两次思考过程，原因是未关闭节点的中间日志输出配置，导致工具调用环节重复生成日志内容，出现重复的思考记录。

## 怎么确认配好了
- 触发一次测试代码提交，查看工作流是否自动启动执行。
- 进入工作流的数据源节点日志页面，确认能正常读取测试用例、覆盖率报告等文件。
- 手动修改测试用例的关联代码模块，验证工作流是否按规则触发对应分支。
- 模拟超时场景，查看工作流是否按配置的重试次数执行重试操作。
