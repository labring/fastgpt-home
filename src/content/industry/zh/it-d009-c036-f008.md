# 原型与交互设计的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
这个品类的数据主要来自Figma或Axure文件、团队内部设计系统、用户反馈及可用性测试记录。日常产出的文档包含交互原型、页面流程图、组件说明与评审记录，数据字段涵盖页面节点层级、跳转逻辑、组件交互规则、评审修改意见等。数据更新频率通常为每周或每版本发布周期，不同项目的文档结构会根据业务复杂度略有调整。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源分散，包含设计工具文件、用户反馈等多类非结构化或半结构化内容，要求工作流支持多源数据拉取与整合。数据更新频率较高，工作流需适配版本迭代节奏，避免因旧数据导致的设计偏差。文档字段无统一强制规范，工作流需配置字段校验规则，确保传递的交互逻辑、组件信息准确。同时，日常需处理大量评审修改的异常场景，工作流需支持分支流转与状态同步。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定设计文档字段与工作流输入输出 | 适配原型与交互设计的字段传递需求，确保评审意见、交互逻辑可跨模块流转 |
| `nodeId` | 绑定至Figma/Axure的页面节点ID | 精准定位对应交互原型的配置信息，避免跨页面混淆 |
| 关键词提取规则 | 按实体类型拆分提取（日期、城市、动作） | 从用户反馈或评审记录中提取交互场景关键词，适配需求起草需求 |
| 工作流超时阈值 | 300–600 秒 | 适配设计文件拉取与解析的耗时，避免因大文件解析导致流程中断 |
| 上下文窗口配置 | 前 1000–1500 字符 | 保留核心交互逻辑与评审意见，避免冗余信息干扰工作流处理 |
| MCP工具参数绑定 | 关联全局`variables`传递参数 | 适配最新版本工具集的参数传递需求，符合FastGPT v4.17.0的功能规范 |

## 容易做错的三处
- 现象：工作流引用多个知识库后，交互原型的节点信息出现重复拼接。原因：未配置多源数据的去重逻辑，导致来自不同设计工具的相同节点被重复拉取。
- 现象：工作流无法从用户反馈或评审记录中提取出发日期、城市等关键词变量，提取结果为空。原因：未正确配置`variables`的实体识别规则，未指定需要提取的字段类型。
- 现象：工作流中设置的全局变量无法在后续节点中调用，执行时提示变量未定义。原因：未将`nodeId`绑定至全局变量的作用域配置，导致变量仅在当前节点生效。

## 怎么确认配好了
- 上传一份测试用的Figma或Axure文件，触发工作流，检查拉取的节点信息是否包含正确的页面层级与交互逻辑。
- 输入包含日期、城市的测试文本，运行关键词提取模块，检查是否能正确提取目标字段。
- 配置全局变量并绑定至MCP工具入参，运行工作流，检查工具调用是否能正常获取变量值。
- 查看工作流日志，确认超时阈值未触发，且所有节点的流转状态符合预期。
