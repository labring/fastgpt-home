# 后端服务开发的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
后端服务开发的核心数据来自代码仓库、API网关日志、数据库与配置中心，更新频率为每日或每版本发布周期。日常产出的文档包含接口设计文档、数据库变更单、代码评审记录与发布说明，数据结构多包含接口路径、请求参数、事务边界、异常码与配置项等字段，部分日志类数据附带时间戳与调用链路信息。

## 这些特征在「上下文与 token」这一环带来什么约束
后端服务开发的文档多涉及技术契约与数据规则，上下文需关联多份跨类型文档，因此token消耗与文档长度强相关。频繁的更新节奏要求上下文需支持实时同步最新的变更内容，避免使用过期的接口定义或配置信息。同时，接口契约与事务边界的描述对完整性要求高，token截断可能导致关键逻辑丢失，引发后续开发或部署错误。多轮会话的上下文还需关联同一服务的多版本变更记录，避免跨版本的上下文混淆，影响需求与设计文档的准确性。

以下配置基于FastGPT v4.17.0版本的功能逻辑
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 6000–10000 token | 覆盖后端服务单轮需求文档起草的上下文范围，包含接口设计、变更记录等关联内容 |
| 引用最大token | 1500–2500 token | 适配单份接口设计文档或代码评审记录的引用长度，保留完整的请求参数与异常处理逻辑 |
| 上下文更新频率 | 每日 | 匹配后端服务文档的日更与版本发布节奏，确保多轮会话使用最新的接口契约与发布说明 |
| 单次召回条数 | 前6条 | 聚焦核心的接口设计、数据库变更、代码评审三类文档，避免冗余信息占用过多token |
| 上下文持久化 | 开启 | 支持多轮会话间的上下文保持，避免重复输入相同的服务背景信息 |

## 容易做错的三处
- 多轮会话中上下文丢失，表现为后续请求无法关联之前提及的接口契约描述，原因是未开启上下文持久化配置，导致会话中断后上下文被清空。
- 工具调用节点出现Invalid JSON报错，表现为返回内容包含格式错误的日志片段，原因是引用的配置中心日志包含不可见控制字符，超出引用最大token限制后被截断导致格式断裂。
- 上下文召回冗余，表现为接口响应超时或token消耗超限，原因是未限制单次召回的文档条数，加载了过多非核心的历史评审记录。

## 怎么确认配好了
- 发起包含接口设计文档关键词的多轮会话，验证后续请求能自动关联之前提及的接口参数与事务边界描述。
- 调用工具节点引用配置中心日志，检查返回内容无截断且格式合法，无Invalid JSON报错。
- 查看系统token消耗监控，确认单轮会话的token使用量在配置的最大上下文范围内。
- 模拟版本更新后的文档同步，验证上下文能自动加载最新的发布说明与变更内容。
