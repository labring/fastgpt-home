# 后端服务开发的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
后端服务开发的日常文档包含接口设计文档、数据库变更单、代码评审记录、发布说明。数据来源通常为代码仓库、API网关日志、数据库、配置中心，更新频率为每日或每版本发布周期。文档字段多包含接口请求参数、响应码、事务边界、异常处理逻辑等，单位涉及请求超时时间（秒）、数据存储容量（MB）、接口调用频次（次/分钟）等，结构以结构化字段为主，辅以自然语言描述的业务规则。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
后端服务开发的文档结构化程度高且关联专属业务数据，要求多轮对话需精准匹配接口契约、事务边界等核心字段，因此需要限定上下文范围，避免引入冗余的历史日志或变更单内容。同时文档更新频率较高，需控制对话历史的保留长度，防止上下文溢出导致模型输出偏差。此外，数据来源涉及多系统的配置与日志，提示词需注入专属业务参数，确保生成的需求与设计文档符合当前项目的技术规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 前 8000–12000 字符 | 匹配后端服务单份接口设计文档的常规长度，适配FastGPT v4.17.0的模型上下文上限 |
| 单次对话历史保留条数 | 前 5 条 | 过滤冗余的代码评审记录与历史日志，聚焦当前需求起草的核心内容 |
| `chatId` 绑定规则 | 绑定单次需求起草会话 | 隔离不同接口设计的上下文，避免跨会话的无关信息干扰生成结果 |
| `messages` 角色限定 | 仅保留用户、助理角色 | 过滤系统预设的无关角色提示，聚焦需求与设计文档的生成逻辑 |
| `variables` 注入开关 | 开启 | 传入当前项目的配置中心字段、代码仓库地址等专属数据，增强提示词的针对性 |
| 会话日志存储 | 开启 | 留存完整的多轮对话记录，便于后续排查生成偏差 |

## 容易做错的三处
- 模型仅输出中文，即便提示词明确要求英文输出。原因：未在`variables`中注入语言限定参数，或未在`messages`的系统提示中明确指定输出语言，导致模型默认使用训练数据中的高频语言。
- 上传数据库变更单等长文档时出现解析报错。原因：未配置匹配后端服务文档格式的分块规则，导致长文本被错误截断，丢失事务边界的关键字段。
- 应用调用后无法查看内部对话详情。原因：未开启会话日志存储配置，或`chatId`未正确绑定到应用调用链路，导致日志未被正确归集。

## 怎么确认配好了
- 上传一份接口设计文档，检查模型输出是否包含请求参数、响应码、事务边界等后端服务专属字段。
- 查看会话详情页面，确认`messages`列表中仅保留用户与助理的交互内容，无无关角色的冗余信息。
- 触发一次应用调用，检查`chatId`是否在会话详情中正确显示，且日志被完整记录。
- 注入英文语言限定的`variables`参数，验证模型输出是否符合预设的语言要求。
