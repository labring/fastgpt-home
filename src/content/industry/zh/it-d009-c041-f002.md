# 图像标注项目的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
这个品类的日常文档包含标注规范、框选样例、质检报告、返工清单，数据来源为图片样本、标注平台、类别字典、抽检结果，更新频率为日或每批。典型使用主体为标注团队、计算机视觉算法团队与质检员，核心处理视觉目标的位置与类别信息，区别于文本标注项目。最耗时环节集中在目标边界框定、遮挡样本判定与质检返工沟通，处理失误会引发识别误差、返工率升高或客户拒收。

## 这些特征在「上下文与 token」这一环带来什么约束
图像标注项目的批量数据导入与多文档参考需求，要求上下文需承载多批次的标注规范、历史框选样例等内容，因此需限制上下文总token总量避免溢出。日常文档的类别字典、质检报告按日或每批更新，上下文需支持动态加载最新版本的参考内容，同时需控制单条引用内容的token长度，防止干扰核心标注逻辑。返工清单与历史标注结果的token占用远高于文本数据，需拆分上下文块并设置合理的引用上限，避免上下文过载导致LLM响应异常。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文总token数 | 8000–12000 token | 适配图像标注项目多批次文档、视觉类数据的token占用总量，避免上下文溢出 |
| 单次引用最大token数 | 1500–2000 token | 匹配框选样例、质检报告等单文档的长度，防止单条引用内容过载 |
| 上下文刷新时机 | 按项目批次触发 | 匹配数据日/每批的更新频率，确保引用的标注规范、类别字典为最新版本 |
| 上下文引用条数上限 | 前5条 | 限制历史返工清单、抽检结果的加载数量，降低上下文总token消耗 |
| 上下文块重叠长度 | 200–300 token | 保证视觉类参考内容的连贯性，避免拆分后丢失关键标注规则 |

## 容易做错的三处
- 现象：LLM响应返回空内容，界面提示`LLM model response empty`。原因：上下文总token超过设置的最大限制，导致LLM无法加载足够的标注参考内容，无法生成有效响应。
- 现象：上下文引用的标注规范与当前批次不符。原因：未按项目批次触发上下文刷新，仍加载了旧版本的类别字典或标注规则。
- 现象：单条框选样例的引用内容被截断。原因：单次引用的token数超过设置的上限，导致视觉参考内容被提前截断，丢失关键边界框标注信息。

## 怎么确认配好了
- 导入一批测试用的图片样本与对应标注规范，查看上下文加载的文档列表是否包含最新版本的类别字典。
- 触发LLM生成标注建议，检查响应内容是否引用了框选样例、历史质检结果等相关参考内容。
- 切换不同批次的测试数据，确认上下文内容随批次更新。
- 查看系统日志，确认未出现上下文token溢出的报错提示。
