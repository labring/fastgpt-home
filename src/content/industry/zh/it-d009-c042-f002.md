# 备份恢复与灾备演练的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
本品类的数据来自备份系统、数据库日志、对象存储、灾备平台，日常产出备份策略、恢复演练报告、灾备切换预案、数据校验记录四类文档。数据更新频率覆盖日、月、季，核心字段包含恢复点目标、恢复时间目标、演练执行时间、数据校验结果等。不同文档的字段维度存在差异，备份策略多以周期、存储路径为核心，恢复演练报告侧重执行步骤与校验结果，灾备切换预案包含跨系统切换的流程说明。

## 这些特征在「上下文与 token」这一环带来什么约束
品类数据来源分散且文档结构差异大，导致上下文召回的关联范围需限定在灾备相关文档内，避免混入无关运维数据。不同文档的更新频率差异，要求上下文调用时需优先匹配近期更新的演练报告与校验记录。核心字段的关联性强，需在上下文拼接时保留字段关联关系，避免token溢出。跨系统的可恢复属性要求上下文需覆盖多来源的关联数据，增加了token配额的使用压力，需严格控制上下文的有效范围。FastGPT v4.17.0版本的上下文配置需适配这类特征，避免出现召回无效数据或token超限的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `10000–15000 token` | 品类文档的字段关联密集，需保留足够的关联信息且避免token溢出 |
| `quoteMaxToken` | `3000–5000 token` | 灾备文档的单条内容较长，需限制单条引用的token占用 |
| 上下文召回范围 | 仅包含灾备相关文档 | 数据来源分散，需排除无关运维数据干扰 |
| 更新时间过滤阈值 | 最近90天 | 品类数据更新频率覆盖日/月/季，优先使用近期的演练报告与校验记录 |
| 单次召回条数 | 前3条 | 核心环节的关联数据集中，过多召回会增加token消耗且降低准确性 |

## 容易做错的三处
- 现象：文档分类结果始终匹配兜底类别，无关联灾备文档的分类结果。原因：未限定上下文召回范围为灾备相关文档，导致召回了无关运维数据，干扰分类逻辑。
- 现象：系统提示token溢出报错，或生成的文档内容被截断。原因：未合理设置`maxContext`与`quoteMaxToken`的取值，导致上下文拼接时超出token配额。
- 现象：恢复演练报告的历史数据未被纳入上下文，生成的预案内容缺失历史校验结果。原因：更新时间过滤阈值设置过短，未覆盖需要参考的历史演练数据。

## 怎么确认配好了
- 查看上下文召回日志，确认仅召回灾备相关的文档，无其他类别数据。
- 测试拼接上下文的token占用，调整`maxContext`与`quoteMaxToken`的取值，确保不触发token溢出报错。
- 导入不同更新时间的灾备文档，验证召回结果是否符合设置的更新时间过滤阈值。
- 起草测试文档，核对生成内容是否包含预期的历史演练报告与校验记录。
