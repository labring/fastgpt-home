# 安全产品规则运营的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自WAF、IDS、防火墙及威胁情报平台，更新节奏为每日或随防护事件触发。日常产出的文档包含规则变更单、拦截日志、误报分析报告、策略回滚记录，各文档字段包含规则ID、生效时间、拦截特征、误报样本哈希值、回滚版本号等，无统一固定单位，随具体防护场景调整。执行主体为安全运营工程师、WAF/IDS产品管理员及SOC团队，核心工作围绕防护策略与规则集的维护展开。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据特征对多轮对话与提示词配置带来多重约束。分散且随事件更新的数据源，要求多轮对话流程需支持实时拉取最新拦截日志与威胁情报，避免使用过期规则数据。文档字段无统一格式，提示词需适配不同防护场景的字段结构，降低解析错误概率。误报分析与灰度发布的高耗时特性，要求多轮对话可按规则ID、生效时间回溯历史上下文，辅助规则复核。防护策略变更的严重出错后果，要求提示词需包含风险校验环节，确保规则配置的严谨性。同时需稳定传递对话上下文，避免历史对话信息丢失。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 包含用户输入、历史回复与规则数据集的数组 | 适配多轮对话的上下文传递需求，确保历史交互与当前规则数据被完整带入 |
| `chatId` | 绑定至当前规则运营任务的唯一标识 | 用于关联对话上下文与具体的规则变更、误报分析任务，避免上下文混淆 |
| 最大上下文长度 | 8000–12000 字符 | 适配规则变更单、拦截日志等文档的常规长度，避免截断关键防护规则信息 |
| 历史对话保留条数 | 前 10 条 | 平衡上下文完整性与推理效率，符合该品类单次任务的信息体量 |
| `variables` | 注入当前规则ID、拦截特征值、回滚版本号等专属字段 | 用于动态替换提示词中的占位符，适配不同防护场景的规则配置 |
| 风险校验触发开关 | 开启 | 需在规则变更类对话中加入风险校验环节，匹配防护策略变更的出错后果约束 |

## 容易做错的三处
- 现象：调用规则分析节点时，历史对话未被正确带入，提示词未读取到过往的误报分析记录。原因：未正确绑定`chatId`参数，导致对话上下文与任务未关联，历史对话数据丢失。
- 现象：对话过程中出现上下文截断报错，或返回的规则建议缺失关键字段。原因：最大上下文长度设置过小，截断了规则变更单、拦截日志等长文档内容。
- 现象：对话返回的规则配置建议未触发风险校验，直接生成变更指令。原因：未开启风险校验触发开关，未在提示词中加入风险校验环节，无法规避误操作风险。

## 怎么确认配好了
- 手动触发一次规则变更类对话，查看对话上下文面板，确认历史的误报分析记录、拦截日志数据被完整带入。
- 输入包含规则ID、拦截特征的查询，查看返回结果中是否动态替换了专属字段，匹配当前任务的规则信息。
- 触发包含风险校验的对话流程，确认返回结果中包含风险校验相关的提示或步骤。
- 查看对话日志，确认`messages`参数中包含了当前与历史的所有交互内容，无缺失。
