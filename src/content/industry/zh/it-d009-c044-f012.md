# 安全产品规则运营的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
该品类的核心数据来源于WAF、IDS、防火墙及威胁情报平台，日常产出规则变更单、拦截日志、误报分析报告、策略回滚记录四类文档。数据更新节奏为每日或随单次事件触发，文档通常包含唯一标识、生效时间、规则内容、关联业务范围、误报/拦截占比等字段，无统一强制格式，多为结构化表格或半结构化文本。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于数据来源分散且格式不统一，解析环节需兼容多类非标准化文本结构。单次事件触发的更新带来高频上传需求，需控制单文件解析超时与大小限制。文档中包含的误报占比、规则生效时间等字段对分块精度要求较高，需保留上下文关联信息，避免拆分后丢失规则与对应业务范围的绑定关系。拦截日志的时间戳、规则ID等元数据需与正文一同提取，保障后续检索时可快速定位对应策略。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的文档解析模块编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 安全产品文档多包含规则文本与关联元数据，该区间可保留单条规则完整上下文，避免拆分后规则与业务范围脱节 |
| `chunkSplitter` | 按标题+段落拆分 | 适配文档中常见的章节标题、规则条目结构，保障分块后内容逻辑连贯 |
| `customPdfParse` | 启用 | 多数安全产品文档导出为PDF格式，启用后可精准提取文本与元数据，避免格式错乱 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量上传拦截日志、误报分析报告的需求，避免大文件上传失败 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 处理包含大量日志条目的文档时，预留足够解析时间，防止超时中断 |
| `chunkSettingMode` | 手动配置 | 针对安全文档的特殊结构，可灵活调整分块参数，适配不同类型的运营文档 |

## 容易做错的三处
- 现象：服务器环境上传doc或docx格式文件后，文档解析节点返回404错误，无法读取文件内容。原因：本地环境可访问本地文件路径，但服务器环境未正确配置文件存储路径映射，导致解析节点无法获取上传文件的实际地址。
- 现象：RAG检索结果仅包含正文内容，未携带章节标题信息。原因：分块配置未开启标题关联提取，或`chunkSplitter`未设置为按标题拆分，导致章节标题与正文分离。
- 现象：批量上传多份拦截日志后，部分文档解析超时失败。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以处理大容量日志文档。

## 怎么确认配好了
- 上传一份典型的规则变更单文档，查看解析后的文本是否完整保留规则内容与关联业务范围。
- 检查解析节点的运行日志，确认无404或超时报错，验证`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`配置是否适配当前上传需求。
- 触发RAG检索，确认返回结果包含正文与对应章节标题，验证`chunkSplitter`与分块上下文配置是否生效。
- 上传不同格式的安全文档（如PDF、docx），确认`customPdfParse`配置可正常解析各类格式文件。
