# 安全培训与钓鱼演练的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
该品类的日常文档包含培训课件、演练方案、钓鱼邮件模板、演练结果报告，数据来源通常为员工通讯录、邮件网关、内部培训平台与演练行为点击统计。数据更新频率多为季度或年度，核心文档包含演练人群标签、邮件触发规则、复盘统计字段等。日常处理的核心环节涉及人群筛选、模板设计与结果复盘，数据关联人员信息、邮件发送记录与培训完成情况。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的文档包含非结构化的培训材料与结构化的演练报告，数据关联多维度的人员与行为标签，会占用较多上下文空间。季度或年度的更新频率意味着上下文无需频繁刷新，但单次调用需覆盖完整的演练周期数据。演练人群筛选与模板设计环节需要精准匹配人员标签，若上下文token超限，会导致核心的人群规则、模板变量无法完整加载。同时，复盘报告的多字段统计需要稳定的token配额，避免因token不足导致复盘数据截断，影响审计依据的完整性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 覆盖单轮演练所需的全部方案、课件与复盘报告核心内容，适配该品类文档的平均长度 |
| `quoteMaxToken` | 1500–2000 token | 匹配钓鱼邮件模板、演练结果报告的单份核心片段长度，避免冗余数据占用过多配额 |
| 单次检索上限 | 前3条 | 该品类核心数据多按演练周期聚合，少量检索即可覆盖关键的人群与行为标签 |
| 上下文刷新规则 | 按季度触发 | 匹配数据更新频率，减少无效的token消耗 |
| 上下文清理阈值 | 当上下文超过10000 token时自动清理最早的非核心记录 | 避免token超限导致核心规则加载失败 |

## 容易做错的三处
- 现象：配置引用最大token为1500 token，但检索到的切块仍超出该额度。原因：未将知识库切块与上下文token配额联动，切块大小设置为5000 token时，单条检索结果已超过引用上限，导致token消耗超出预期。
- 现象：无法查看单次问答的token使用情况。原因：未在系统设置中开启token统计日志功能，或未配置日志导出路径。
- 现象：上下文历史记录无法按规则清空。原因：未绑定触发条件到上下文清理节点，或触发条件未匹配演练周期结束的时间节点。

## 怎么确认配好了
- 进入系统设置的上下文与token配置页面，核对`maxContext`、`quoteMaxToken`的取值是否匹配当前演练周期的文档长度。
- 发起一次模拟钓鱼演练的问答请求，查看返回内容是否包含完整的演练方案与人群标签，无截断情况。
- 检查日志系统，确认每次问答的token使用量未超过配置的最大上下文额度。
- 触发演练周期结束的事件，验证上下文历史记录是否按规则被清空。
