# 安全培训与钓鱼演练的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
安全培训与钓鱼演练品类的典型主体为安全运营团队、企业内训部门或外部安全服务商。日常产出的文档包含培训课件、钓鱼演练方案、钓鱼邮件模板、演练结果报告四类。数据主要来自员工通讯录、企业邮件网关、内部培训平台及用户点击统计系统，更新频率多为季度或年度。最耗时的环节集中在演练人群筛选、邮件模板设计与演练结果复盘，生成内容出错可能引发员工泄密、审计缺项或整改无证据等风险。与安全基线检查品类不同，该品类聚焦人员安全意识与行为的训练。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来源包含员工通讯录、邮件网关等结构化字段，多轮对话需要精准调用对应字段实现人群筛选与模板定制，因此需在对话中预设数据源关联逻辑。日常文档类型多样，不同文档的格式要求差异较大，多轮对话需按文档类型拆分上下文块，避免格式冲突。更新频率偏低意味着提示词配置无需高频调整，但需适配季度更新的人群数据。最耗时的环节需要多轮对话自动拆解为分步任务，因此需将人群筛选、模板生成等步骤拆分为连续交互。出错后果的严重性要求提示词对生成内容做合规校验，避免生成风险内容。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前钓鱼演练项目的唯一标识 | 区分不同项目的对话上下文，避免跨项目数据混淆 |
| `messages` | 按演练文档类型拆分上下文块，每块不超过800字符 | 适配培训课件、邮件模板等日常文档的长度，防止上下文溢出 |
| `variables` | 注入员工部门、历史演练记录等字段 | 调用员工通讯录、培训平台的数据源，实现精准的演练人群筛选 |
| 单次调用文档数 | 前3–5份 | 避免加载过多文档导致对话响应变慢 |
| 最大上下文窗口 | 2000–3000 token | 兼顾多轮对话的历史记录和导入的文档数据，避免内容截断 |
| 问题优化开关 | 开启 | 适配不同起草场景的需求，优化多轮对话的提问逻辑 |

## 容易做错的三处
- 现象：对话响应耗时较长，原因：未拆分`messages`上下文块，导致每次调用都加载全部演练文档数据，超出系统处理上限。
- 现象：控制台出现`Unexpected end of JSON input`报错，原因：未对`variables`注入的数据源字段做格式校验，导致传入非法字符触发模型解析失败，尤其在使用chatglm2类模型时更易出现。
- 现象：多轮对话生成的内容未直接在主对话框输出，需手动在侧边栏查看，原因：未配置`messages`的上下文绑定逻辑，导致对话历史未关联到当前项目的文档起草任务。

## 怎么确认配好了
- 发起一次模拟的钓鱼邮件模板起草对话，检查`chatId`是否绑定了正确的演练项目标识，确保上下文不与其他项目混淆。
- 导入一份演练方案文档，验证`variables`是否正确注入了员工部门等字段，确认生成的人群筛选条件符合预期。
- 连续发起3轮以上的对话，检查所有生成的内容是否直接显示在主对话框中，确认`messages`的上下文传递逻辑正常。
- 测试使用chatglm2类模型发起对话，检查控制台是否出现`Unexpected end of JSON input`报错，确认格式校验配置生效。
