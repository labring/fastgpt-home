# 安全基线检查的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
本品类数据来源于服务器配置、中间件配置、安全设备策略及基线工具输出结果，更新频率为月或季。日常产出的文档包含基线检查表、配置核查记录、整改建议与例外审批单，其中基线检查表包含配置项名称、基准值、实际检测值字段，配置核查记录包含检测时间、检测节点、异常项清单字段，整改建议包含异常项描述、整改措施字段，例外审批单包含例外原因、审批状态字段。数据主体为安全运维、安全咨询顾问及内控审计人员，核心关注配置项是否符合组织安全基准，区别于漏洞扫描服务。本页面基于FastGPT v4.17.0版本编写。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且依赖多类系统配置，要求工作流需支持跨节点拉取不同数据源的配置数据；更新频率偏低但需定期同步，要求工作流需配置定时触发节点，避免使用实时触发导致资源浪费；日常文档字段固定且需标准化输出，要求工作流需预设对应字段的变量映射规则，确保生成的文档格式统一；最耗时环节为配置核对、例外确认与整改复核，要求工作流需支持批量异常项标记、自动关联例外审批单模板，减少人工重复操作；出错后果影响安全合规，要求工作流需添加异常结果校验节点，拦截不符合基准的配置项流转。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `nodeId` | 为每个数据源节点配置唯一的`nodeId` | 跨节点拉取数据时，需通过`nodeId`精准定位对应数据源的输出内容 |
| `variables` | 预设配置项名称、基准值、实际检测值、异常标记4个变量，匹配1000–1200字符的文档模板 | 确保生成的文档字段标准化，符合业务场景的排版要求 |
| 触发方式 | 按周定时触发，或按安全设备策略更新触发 | 数据更新频率为月或季，定时触发可平衡资源消耗与数据时效性 |
| 数据源绑定 | 绑定服务器配置节点、中间件配置节点、安全设备策略节点各1个 | 本品类数据来源于三类系统，需分别拉取对应配置信息 |
| 异常校验阈值 | 按实测标定，匹配组织安全基准的偏差范围 | 基于实际安全基准判断配置异常，避免误判或漏判 |
| 重试策略 | 失败后重试2次，间隔600秒 | 降低跨节点拉取时网络波动导致的流程中断概率 |

## 容易做错的三处
- 现象：工作流生成的配置核查记录字段为空，原因：未在`variables`中配置对应字段的映射规则，导致节点输出数据未关联到文档模板的必填字段。
- 现象：工作流触发后长时间无响应，状态码显示超时，原因：未配置重试策略，单次拉取多类数据源时因网络波动导致请求超时，且未设置超时拦截节点。
- 现象：生成的整改建议与实际异常项不匹配，原因：未通过`nodeId`绑定对应数据源的异常项清单节点，错误使用通用模板生成内容，未关联实际检测到的配置偏差数据。

## 怎么确认配好了
- 手动触发一次工作流，检查生成的基线检查表是否包含配置项名称、基准值、实际检测值字段，字段内容是否与拉取的数据源一致。
- 模拟配置项异常的场景，触发工作流，检查异常校验节点是否标记对应异常项，是否生成对应的整改建议内容。
- 查看工作流日志，确认定时触发节点是否按预设周期运行，跨数据源拉取是否成功，无报错信息。
- 导出一次工作流生成的例外审批单，检查是否自动关联了对应异常项的例外原因模板，格式是否符合业务要求。
