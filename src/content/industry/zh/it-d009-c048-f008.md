# 安全监控与SOC值守的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
该品类的数据来源为SIEM、EDR、NDR及外部威胁情报源，更新节奏分为实时告警流与日度汇总文档两类。日常产出的文档包含告警处置单、值班记录、威胁情报通报、日报周报，字段覆盖告警ID、处置状态、研判结论、派单对象、响应时长等，仅按业务流程记录标准化的安全运营数据，无额外自定义统计数字。

## 这些特征在「工作流编排」这一环带来什么约束
实时更新的告警数据要求工作流支持低延迟触发，无法使用过长的固定轮询间隔；多类型文档的差异化字段结构，要求工作流具备灵活的数据源映射能力，适配不同业务文档的格式；告警研判、误报排除的高耗时环节，要求工作流内置标准化的处置节点以减少重复操作；升级派单的跨团队流转需求，要求工作流支持角色权限绑定与操作痕迹记录；严重的出错后果，要求工作流内置失败重试与异常通知机制，避免真实攻击漏报或响应超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发时机 | 按实时告警流触发，间隔不超过60秒 | 匹配SIEM、NDR的实时告警更新节奏，避免漏报延迟 |
| 数据源适配 | 按`variables`定义的字段映射规则 | 适配告警处置单、值班记录等多文档的字段差异，统一数据输入格式 |
| 单节点超时设置 | 120秒 | 覆盖告警研判、情报查询的常规耗时，避免中途中断流程 |
| 失败重试策略 | 前2次重试间隔300秒，第3次触发人工介入 | 应对临时网络波动或情报源临时不可用，降低误判概率 |
| 流转权限绑定 | 按`nodeId`绑定对应团队角色 | 区分SOC分析师、值班主管的节点操作权限，符合安全值守的流程规范 |
| 上下文缓存保留时长 | 7天 | 匹配日度周报的统计周期，便于跨日研判溯源 |

## 容易做错的三处
- 现象：节点数量超过20个时，画布拖动延迟超过5秒。原因：未启用工作流的轻量化渲染配置，未按节点功能分组排布。该卡顿问题在FastGPT v4.17.0版本中已优化节点渲染逻辑。
- 现象：工作流在运行预览页面可正常输出结果，聊天页面无返回内容。原因：未配置工作流的输出节点绑定到对话上下文，或未开启对话触发的工作流开关。
- 现象：http请求节点选择form-data类型时，无法正确上传文件参数。原因：未在`variables`中定义文件类型的变量绑定，或未正确配置文件上传的请求头。

## 怎么确认配好了
- 触发一条模拟告警数据，检查工作流是否自动启动并按预设节点流转。
- 查看工作流的日志面板，确认每个节点的执行耗时符合预设的超时设置。
- 模拟节点执行失败的场景，检查是否触发预设的重试机制和人工介入通知。
- 切换不同角色的账号，验证节点操作权限是否符合配置的角色绑定规则。
