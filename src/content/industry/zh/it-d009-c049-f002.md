# 客户培训与使用手册的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
本品类的核心文档包括培训课件、用户手册、培训签到表、问题答疑清单，数据主要取自产品帮助中心、客户组织架构、培训录屏与工单系统。文档更新频率为每单或每版本更新，通常围绕产品版本迭代、客户新需求调整内容。文档结构多包含角色权限说明、操作步骤拆解、常见问题解答三类字段，部分签到表会包含参训人员信息与培训时长字段，整体数据以文本类结构化与半结构化内容为主。

## 这些特征在「上下文与 token」这一环带来什么约束
品类数据的多来源特性导致内容格式差异较大，培训录屏转写的文本可能存在冗余口语化内容，工单系统的问题答疑则偏向碎片化短句。每单/每版本的更新频率要求上下文关联的内容需及时同步最新版本信息，避免引用过时的操作步骤。文档包含角色权限、操作步骤等细分字段，不同字段的重要性差异要求上下文召回需区分优先级，且单次召回的token总量需适配单份文档的平均长度，防止超出模型上下文窗口。另外，碎片化的答疑内容可能导致上下文拼接时出现逻辑断层，需限制召回内容的冗余度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口 | 8000–12000 token | 适配本品类单份文档的平均长度，避免超出模型原生上下文限制，适配FastGPT v4.17.0版本的配置逻辑 |
| `quoteMaxToken` | 1500–2000 字符 | 限制单条召回内容的token占用，防止碎片化答疑内容过度占用上下文资源 |
| 单次召回内容条数 | 前6条 | 匹配本品类碎片化的答疑清单与操作步骤文档的内容密度 |
| 内容重叠长度 | 100–150 字符 | 适配培训课件与用户手册的长段落结构，避免上下文拼接出现逻辑断层 |
| 相似度阈值 | 0.75–0.85 | 区分核心操作步骤与冗余说明，确保召回内容与用户查询的匹配度 |

## 容易做错的三处
- 现象为调整上下文窗口配置后，聊天过程中未体现召回的历史培训内容与用户手册片段，原因是未同步更新关联的知识库召回规则，导致上下文仅加载空字段或无效内容。
- 现象为配置`maxContext`参数后出现模型响应截断或接口报错，原因是取值超出当前部署模型的原生上下文窗口上限，同时未对召回内容做token预计算。
- 现象为召回的培训录屏转写内容出现大量冗余口语化片段，原因是未设置内容过滤规则，且未限制`quoteMaxToken`的取值区间，导致无效内容占用过多token资源。

## 怎么确认配好了
- 上传一份最新版本的用户手册与培训答疑清单，执行一次关联查询，核对召回内容的条数与字段匹配度，调整配置项直到召回内容覆盖核心操作步骤。
- 查看上下文拼接日志，确认召回内容的总token量未超出最大上下文窗口的设定值，且单条内容未超过`quoteMaxToken`的限制。
- 模拟客户首次使用的查询场景，验证模型响应中是否包含对应版本的权限说明与操作步骤，无过时内容。
- 该核对流程适配FastGPT v4.17.0版本的配置界面，可通过平台内置的调试工具验证上下文召回效果。
