# 客户数据导入迁移的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自客户历史系统、CSV或Excel模板、数据库导出及产品导入日志，更新频率为每单或不定期。日常产出的文档包含数据模板、迁移方案、字段映射表、迁移验证报告，核心字段包括源系统字段名、目标系统映射规则、数据校验规则、导入批次号等，数据体量随客户业务规模浮动，无固定单位标准。

## 这些特征在「上下文与 token」这一环带来什么约束
数据来源多样导致格式不统一，需在上下文处理中兼容多源数据的字段映射逻辑，避免token溢出。更新频率不定期意味着导入批次的上下文需单独管理，无法复用固定上下文模板。核心字段的映射规则需嵌入上下文，确保token统计覆盖映射逻辑与校验规则，避免因字段错位导致的导入失败。数据体量浮动要求上下文与token配置需适配不同批次的导入规模，防止单次处理超出系统阈值。

## 配置怎么定
FastGPT v4.17.0版本的配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–15000 token | 适配多源导入数据的字段映射与校验逻辑，避免上下文溢出 |
| `quoteMaxToken` | 1000–2000 token | 覆盖单批次导入的字段映射规则与校验说明，确保上下文完整 |
| 最大上下文缓存时长 | 3600秒 | 匹配不定期导入的批次周期，避免上下文过期导致的映射错误 |
| 导入字段映射上下文开关 | 开启 | 确保token统计覆盖字段映射逻辑，防止遗漏规则导致的字段错位 |
| 单次导入token上限 | 按实测标定 | 适配不同客户的业务数据体量，避免系统过载 |

## 容易做错的三处
- 现象：导入任务触发「token超限」报错，但导入日志未显示具体超限的上下文内容。原因：未开启上下文token的明细统计配置，无法定位超限的字段映射或校验规则。
- 现象：云空间部署的导入任务无法找到token相关设置入口。原因：云空间版本的FastGPT默认隐藏高级配置项，需通过权限申请或切换至标准版获取配置权限。
- 现象：导入批次完成后，历史上下文未被清理，导致后续批次出现字段映射错位。原因：未配置导入任务完成后自动清空上下文的规则，上下文缓存未随批次更新。

## 怎么确认配好了
- 查看导入任务的上下文日志，确认字段映射规则已被纳入token统计范围。
- 测试小体量的导入批次，核对token消耗与配置的`maxContext`、`quoteMaxToken`是否匹配。
- 检查云空间版本的配置入口，确认token相关设置项已显示并可修改。
- 完成单批次导入后，验证上下文缓存是否被自动清理，避免影响后续批次。
