# 客户权限与组织架构配置的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
本品类的数据主要来自客户HR系统、身份目录、产品后台与审计日志。日常产出的文档包括权限矩阵、组织架构表、角色配置记录、权限变更单。数据更新频率为每单或不定期，核心字段包含部门层级标识、角色权限范围、变更操作时间与操作人信息。数据关联客户的实际组织架构与权限规则，无统一标准化格式，需适配不同客户的组织管理逻辑。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类的数据来源分散且格式不统一，会导致上下文加载时需兼容多套字段结构，增加token消耗。数据更新频率无固定周期，若上下文未及时同步最新的组织架构与权限变更记录，会出现权限校验失效的问题。权限数据的颗粒度较细，包含部门、角色、操作权限的多层映射，若未限制上下文的token上限，会导致单轮请求的token溢出。同时跨客户的权限数据隔离要求，需在上下文加载时精准过滤非目标客户的相关数据，进一步约束token的分配逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `4000–8000 token` | 适配本品类多层权限映射的字段数量，避免单轮请求token溢出，保证权限规则完整加载 |
| `quoteMaxToken` | `1000–2000 token` | 限制权限文档片段的token消耗，适配本品类权限文档的切块大小 |
| 上下文刷新周期 | 按实测标定 | 适配本品类数据不定期更新的特点，平衡数据时效性与token消耗 |
| 权限数据过滤条数 | `前 50–100 条` | 过滤非目标客户的权限数据，减少无效token占用，保证上下文仅包含当前客户的规则 |
| 权限上下文绑定开关 | 开启 | 确保上下文清空操作可同步清理权限相关的token缓存，避免历史数据残留 |

## 容易做错的三处
- 现象：配置`quoteMaxToken`为`1500 token`后，仍出现权限文档切块超出限制的报错。原因：未结合本品类权限文档的实际切块大小调整配置，权限矩阵的单条记录通常包含多层映射，切块后token消耗超出预设上限。
- 现象：检索权限数据时返回非目标客户的组织架构信息。原因：未配置权限数据过滤规则，上下文加载时未隔离跨客户的权限数据，导致无效token占用过多空间。
- 现象：工作流中执行上下文清空操作后，权限相关的上下文仍保留历史记录。原因：未将权限上下文与对话上下文绑定，清空操作仅作用于对话历史，未同步清理权限缓存的token数据。

## 怎么确认配好了
- 登录FastGPT v4.17.0的产品后台，查看上下文token消耗日志，确认单轮请求的token值未超过`maxContext`的配置上限。
- 检索权限文档片段，验证返回结果仅包含当前目标客户的组织架构、角色配置等数据，无跨客户内容。
- 提交权限变更单后，等待配置的刷新周期，验证上下文加载的是最新的权限规则数据。
- 触发上下文清空操作，确认权限相关的token缓存已被清理，后续请求加载最新配置。
