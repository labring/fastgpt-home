# 客户需求池管理的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
这个品类的典型使用主体为产品运营、客户成功与产品经理，日常处理的文档包括需求池清单、需求评估表、客户反馈记录与版本规划说明。数据来源涵盖工单系统、客户访谈记录、CRM系统与产品路线图，更新频率多为每周或每版本发布周期。文档结构包含需求优先级、提交时间、关联客户ID等专属字段，无统一固定格式，部分文档嵌入图片或表格内容。

## 这些特征在「文档解析与分块」这一环带来什么约束
多源异构的文档来源导致格式差异明显，需适配pdf、excel、文本等多种格式，且部分文档包含内嵌图片，对解析工具的图文混合处理能力提出要求。高频更新的文档需要批量解析能力，需控制单文件与批量解析的时长阈值。专属字段的存在要求分块过程保留上下文关联，避免拆分后丢失需求优先级、客户关联信息等关键内容，否则将影响后续重复需求归并与价值评估环节的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配需求池文档的字段密度，避免拆分过碎导致重复需求无法关联，或拆分过粗影响后续归并效率 |
| `customPdfParse` | 启用图文混合解析 | 适配需求文档中常嵌入的客户反馈截图、评估表图表，避免仅提取文本内容丢失关键视觉信息 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 匹配周更批量文档的解析时长要求，避免因单文件解析超时导致批量任务中断 |
| `chunkSplitter` | 按语义块拆分 | 保留需求优先级、版本号、关联客户ID等专属字段的上下文关联，确保分块内容具备独立评估价值 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量导入的版本规划说明等大型文档，满足全周期需求文档的批量处理需求 |

## 容易做错的三处
- 解析后图片字段为空，现象为上传含内嵌图片的pdf需求评估表后，解析结果未包含图片相关内容，仅保留纯文本。原因是未启用`customPdfParse`的图文混合解析模式，仅提取基础文本内容。
- 批量解析触发超时报错，现象为上传多份周更需求文档时，部分任务返回超时状态码。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`至适配批量解析的取值，单文件解析时长超出预设阈值。
- 分块后重复需求无法归并，现象为同一客户的多次反馈被拆分为多个独立块，无法通过语义聚类完成归并。原因是`chunkSize`设置过小，将同一段需求文本拆分为多个无关联的小分块。

## 怎么确认配好了
- 上传一份含内嵌图片的pdf需求评估表，检查解析结果是否包含图片标注或对应的文本描述。
- 上传单份100MB左右的版本规划说明文档，确认解析进度未触发超时报错，任务正常完成。
- 选取一段包含需求优先级与客户ID的文本，验证分块结果保留了该段内容的完整上下文。
- 导入excel格式的客户反馈记录，检查解析后的文本块是否完整保留了表格列字段信息。
