# 容器平台运维的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
容器平台运维的核心数据来自Kubernetes API、镜像仓库、监控系统与CI流水线，更新频率为每日或每一次集群变更。日常产出的文档包含集群变更单、命名空间配额表、部署记录与故障报告，其中集群变更单包含变更时间、资源配额、Pod副本数等字段，命名空间配额表以namespace名称、CPU核数配额、内存GiB配额为核心字段，所有文档均为结构化或半结构化格式。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源依赖外部集群API与流水线，要求工作流支持集成第三方数据源节点，定时或事件触发拉取数据；更新频率的灵活性要求工作流可配置定时触发或变更事件触发，匹配集群运维的变更节奏；结构化文档的特征要求工作流内置表格解析与字段提取能力，快速提取配额、副本数等核心运维参数；最耗时的资源配额调整、Pod排查环节，需要将其拆分为独立编排节点，减少重复操作；出错后果直接影响业务稳定性，要求工作流配置失败重试与告警节点，避免集群中断风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发时机 | 按集群变更事件触发或每日0点定时 | 匹配数据更新频率为每变更或日更的业务节奏，确保工作流获取最新的集群数据 |
| `variables` 配置 | 绑定集群ID、命名空间配额阈值等运维专属变量 | 用于在工作流中传递集群级配置参数，适配不同命名空间的差异化运维需求 |
| 循环体嵌套 | 支持多层嵌套 | 满足多轮对话、多命名空间遍历等复杂数据处理场景 |
| 结果过滤规则 | 仅保留最后一次AI问答结果 | 匹配业务中仅需最终输出的场景，避免冗余中间结果 |
| 失败重试次数 | 3次，间隔60秒 | 应对临时网络波动或API调用抖动，降低单次失败导致的工作流中断风险 |
| 上下文窗口 | 按实测标定 | 适配10万中文字档或15000行Excel数据的多轮处理需求 |

## 容易做错的三处
- 现象为工作流执行数据库连接节点时返回“connect ETIMEDOUT”报错，本地环境可正常访问数据库。原因是工作流未关联容器集群的网络策略配置，或`variables`中配置的数据库地址未使用集群内部服务域名。
- 现象为多层嵌套的循环体仅执行最外层逻辑，内层循环未触发。原因是未在FastGPT v4.17.0的工作流设置中开启多层循环支持，或内层循环的触发条件未正确绑定外层循环的输出参数。
- 现象为工作流返回多组AI问答的所有中间结果，未仅保留最后一次回答。原因是未配置结果过滤节点，或过滤规则未正确绑定到最后一个问答节点的`nodeId`。

## 怎么确认配好了
- 触发一次模拟集群变更事件，检查工作流是否自动启动并拉取对应集群的配额数据。
- 上传10万中文字档或15000行Excel数据，验证工作流是否完成多轮处理并输出预期结果。
- 配置数据库连接节点，执行测试连接，确认无“connect ETIMEDOUT”报错。
- 运行多组AI问答的工作流，检查输出是否仅保留最后一次问答节点的结果。
