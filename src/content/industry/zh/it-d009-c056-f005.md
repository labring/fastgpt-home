# 对象存储与备份服务的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自对象存储控制台、备份系统、访问日志与客户策略表。日常产出的文档包含存储桶配置、备份策略、恢复记录、生命周期规则等。数据更新节奏为每日更新或随策略变更触发更新。字段通常包含存储权限、备份保留周期、恢复校验状态、访问日志时间戳等，无额外强制统计单位，仅按行业通用文档规范记录对应配置项与执行结果。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散且更新节奏不固定，多轮对话需支持动态拉取不同系统的最新配置数据，避免使用过期的存储桶或备份策略信息。日常文档字段覆盖存储权限、备份周期、恢复校验、访问日志等多维度，多轮对话需按文档结构逐步引导确认配置项，防止遗漏关键参数。同时，因配置出错会引发数据泄露或恢复失败，对话环节需嵌入合规性校验逻辑，确保生成的文档符合预设的策略规范。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定目标存储桶 ID | 确保对话上下文与指定存储桶的配置强关联，避免跨桶配置混淆 |
| `messages` | 按文档结构分轮传递 | 拆分存储桶配置、备份策略等模块，逐步引导对话完成起草 |
| `variables` | 传入备份策略 ID、生命周期规则参数 | 精准加载对应资源的历史数据，减少无效检索 |
| 最大上下文长度 | 8000–10000 字符 | 匹配该品类单份核心文档的平均长度，避免截断关键信息 |
| 单次对话返回上限 | 前 3 条 | 适配单轮需确认的核心配置项数量，避免信息过载 |
| 会话超时时间 | 1800 秒 | 匹配运维人员处理单份配置文档的平均耗时 |

## 容易做错的三处
- 对话中尝试上传存储桶日志附件后无响应，原因是未在`variables`中配置附件解析的存储路径参数，导致系统无法定位对应日志文件。
- 调用`chat/completions`接口返回400状态码，原因是提示词模板未适配该品类的备份策略字段，存在未定义的配置项占位符。
- 对话无法按指定标签检索备份记录，原因是未在`messages`中明确标注需检索的标签范围，导致系统默认检索全量数据。

## 怎么确认配好了
- 发起测试对话，输入指定存储桶ID，核对返回的上下文是否包含对应存储桶的配置信息。
- 调用`chat/completions`接口，传入预设的备份策略参数，检查返回结果是否包含该策略的核心字段。
- 模拟多轮对话拆分起草备份策略文档，确认每轮传递的`messages`模块未超出预设的上下文长度限制。
- 上传测试用的存储桶访问日志附件，核对对话是否能正确解析并关联对应日志数据。
