# 对象存储与备份服务的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
通常，该品类的核心数据来自对象存储控制台、备份系统、访问日志与客户策略表。日常产出的文档包含存储桶配置、备份策略、恢复记录与生命周期规则，单份文档包含存储桶名称、权限策略、备份周期、数据保留天数等字段，单位涵盖GB、天、次等。数据更新频率为每日或随策略变更实时更新，部分多存储桶汇总文档体量较大。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档以结构化配置内容为主，包含层级化的标题与字段说明，解析时需避免切分破坏权限策略、备份周期等关键配置单元。多体量文档与高频更新的特性，要求解析流程具备适配大文件的能力，同时需控制单任务耗时以匹配日常运维的响应节奏。不同来源的文档格式存在差异，部分备份日志为纯文本，部分策略文档为PDF格式，解析工具需兼容多种输入格式，确保字段提取的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 该品类文档包含字段说明与配置项，此区间可避免切分破坏单个配置单元的完整性 |
| `chunkSplitter` | 按段落+标题拆分 | 存储桶配置、备份策略具备明确的层级标题与独立段落，保留结构可提升后续检索准确性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 单份多存储桶汇总文档可能包含数十条生命周期规则，解析耗时较长，此取值可覆盖多数场景 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配大型备份日志或多策略汇总文档的上传需求，避免因文件过大被拦截 |
| `customPdfParse` | 开启 | 部分备份策略文档为PDF格式，自定义解析可保留表格与字段对齐效果，提升分块准确性 |

## 容易做错的三处
- 现象：使用FastGPT v4.17.0的文件增强解析功能无响应，更换为旧版本或启用v1 marker后恢复正常。原因：新版解析插件与对象存储备份文档的复杂表格解析逻辑存在兼容性问题。
- 现象：调用指定模型时无法调起文件解析工具，对话中无解析结果返回。原因：未在配置中关联对应解析服务与文档解析环节，或权限配置未开放文档解析接口。
- 现象：运行`marker_images:v0.1`的Docker容器时出现报错。原因：未正确挂载GPU驱动目录或端口映射参数配置错误，导致容器无法正常启动解析服务。

## 怎么确认配好了
- 上传一份典型的存储桶配置PDF文档，查看解析后分块结果是否保留了权限策略、生命周期规则等核心字段。
- 检查`PARSE_FILE_TIMEOUT_SECONDS`参数是否设置为符合文档解析耗时的取值，通过控制台日志确认解析任务未出现超时报错。
- 测试上传超过500 MB的备份日志文档，确认上传与解析流程正常完成，无文件大小限制报错。
- 切换至不同配置组合，验证解析结果的一致性，确认`customPdfParse`等参数的配置生效。
