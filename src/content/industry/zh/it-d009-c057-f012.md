# 工单受理与问题分级的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
本品类的数据由客服、技术支持及客户成功团队日常产出，核心文档包括客户工单、问题分级表、处理记录与服务报告。数据来源覆盖工单系统、客服聊天记录、产品运行日志及客户合同SLA文件，更新频率为日级或实时。工单类文档包含工单ID、客户标识、问题描述、提交时间等字段，问题分级表则包含优先级、影响范围、责任团队等字段，数据以单条工单、单份表格为基础存储单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
多源数据的混合解析需求要求解析引擎支持PDF、Excel、纯文本等多种格式，避免丢失不同类型文档的字段结构。实时或日级更新的数据要求解析流程具备高效性，避免因解析耗时过长导致数据同步延迟。工单与分级表的强字段关联性要求分块操作需保留关键标识，不能割裂同一工单的问题描述与处理记录，否则会影响后续问题分级与分派的准确性。同时，批量工单包与SLA合同的体积差异，要求解析配置可适配不同大小的文件上传与解析。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 工单内容包含连续的问题描述与处理记录，该长度可保留上下文关联，避免割裂关键信息，FastGPT v4.17.0版本默认值为1000字符，可按实际工单长度微调 |
| `chunkSplitter` | 按段落+标题分割 | 工单与分级表存在明确的标题与段落结构，按此分割可保留字段关联性，避免跨工单或跨字段分块 |
| `customPdfParse` | 启用 | 工单常以PDF格式提交，启用后可完整提取文本排版与表格字段，避免出现内容缺失或格式混乱 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–90 秒 | 包含多页聊天记录或附件的工单PDF解析耗时较长，该取值可覆盖多数场景的解析需求，避免触发超时错误 |
| `UPLOAD_FILE_MAX_SIZE` | 50–100 MB | 批量工单包与客户合同SLA文件体积差异较大，该取值可适配多数上传场景，按实际业务需求标定 |

## 容易做错的三处
- 上传PDF工单后显示解析失败，日志返回请求超时。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认取值不足以解析包含多页聊天记录的工单PDF。
- 导入的问题分级表表格内容在检索结果中为空。原因：未启用`customPdfParse`，默认解析引擎无法完整提取表格中的优先级与影响范围字段。
- 分块后的内容割裂了同一工单的问题描述与后续处理记录。原因：设置`chunkSplitter`为按固定字符分割，未按段落与标题分割，导致跨字段的内容被拆分到不同分块中。

## 怎么确认配好了
- 上传单页PDF格式的客户工单，检查解析后的文本是否包含完整的工单ID、问题描述与提交时间字段。
- 上传包含表格的问题分级表，确认解析结果中保留表格的优先级、影响范围列内容。
- 上传10 MB的批量工单包，检查解析过程未触发超时错误提示。
- 调整`chunkSize`为700字符，确认分块后的内容未割裂连续的处理记录段落。
