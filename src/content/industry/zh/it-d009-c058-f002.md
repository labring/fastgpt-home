# 广告合规留痕的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
本品类数据来自广告平台后台、客户资质库、合同系统及监管公开规则，日常文档包含广告审查表、资质附件、投放记录、整改通知四类核心文件。数据更新随单次广告活动完成或月度周期触发，单条投放记录包含投放时段、素材版本、审查编号等字段，资质附件多为结构化证照或扫描件格式。

## 这些特征在「上下文与 token」这一环带来什么约束
本品类数据来源分散，需整合多系统的结构化与非结构化内容，上下文拼接时需区分审查类文本与投放执行类文本的优先级。数据更新随单次活动或月度周期触发，单次批量导入的文档数量较多，需严格控制`maxContext`的取值，避免超出模型承载上限。投放记录与资质附件的字段差异显著，需通过`quoteMaxToken`限制单条引用的token消耗，防止无关数据占用过多上下文空间。需优先纳入归档、整理环节对应的核心证据类文档，确保合规审查的关键信息优先被召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配广告合规类文档的平均token总量，避免超出FastGPT v4.17.0的模型承载上限 |
| `quoteMaxToken` | 1000–1500 token | 适配投放记录、资质附件的单文档长度，防止单条引用占用过多上下文空间 |
| 上下文匹配优先级 | 按审查文档优先 | 符合合规留痕的核心业务需求，优先纳入广告审查表、监管规则类文本 |
| 批量导入单次上限 | 50 条/次 | 适配月度更新的文档规模，降低token拼接时的内存压力 |
| 重排模型触发阈值 | 按实测标定 | 针对合规文档的文本特征调整，提升上下文召回的精准度 |

## 容易做错的三处
- 现象：离线接入重排模型后触发`rerank error fastgpt`报错。原因：未按合规文档的文本特征调整重排模型的触发阈值，导致长文本无法正常完成重排流程。
- 现象：LLM返回内容为空，提示`LLM model response empty`。原因：`maxContext`取值过大，上下文拼接后超出模型token上限，LLM无法生成有效响应内容。
- 现象：设置引用上限后，短问答仍触发token超限报错。原因：未结合`quoteMaxToken`限制单条引用的token长度，多份投放记录的总token消耗超出单轮上下文配额。

## 怎么确认配好了
- 导入单份核心合规文档，查看上下文拼接后的总token数，确认匹配`maxContext`的取值范围。
- 触发一次合规文档的检索流程，检查返回的引用单条长度，符合`quoteMaxToken`的限制要求。
- 批量导入月度更新的文档，确认系统无拼接异常或内存溢出的提示。
- 发起连续对话，验证历史合规审查记录可被正常调用并纳入上下文。
