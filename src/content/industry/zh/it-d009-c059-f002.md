# 广告素材审核的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
广告素材审核的核心数据包含四类来源：广告平台投放的素材文案、落地页截图、商品资质文件，以及通用广告法合规条款。日常处理的文档包括单条素材的文本内容、落地页转写文本、审核人员出具的违规整改意见、历史修改操作记录。数据更新频率为日级或实时，其中商品资质与最新法规条款会随监管要求实时同步，素材与审核记录则随投放进度更新。文档无统一固定字段，素材包含投放渠道、尺寸要求，审核意见包含违规类型、整改要求，修改记录包含操作人与操作时间。

## 这些特征在「上下文与 token」这一环带来什么约束
广告素材审核的数据特征对上下文与token配置带来多重约束。首先，多源异构的数据结构要求上下文需覆盖文本、转写文本等不同格式的内容，token分配需兼顾不同类型文档的长度差异。其次，实时更新的资质与法规要求上下文需支持动态加载最新合规依据，避免使用过期数据。再者，单条审核涉及的关联文档数量较多，上下文召回的范围需覆盖足够的历史审核记录与合规条款，同时需控制总token占用量，防止超出模型上限。最后，出错后果直接关联广告投放合规性，上下文需优先保留高优先级的合规依据，不能因token截断导致关键信息丢失。

## 配置怎么定
本章节配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 10000–15000 token | 广告素材审核需召回多份历史审核意见、最新商品资质及广告法条款，该区间可覆盖批量审核的完整上下文需求 |
| 单条引用最大token数 | 1800–2200 token | 单条广告素材的文案、落地页提取文本及对应审核意见的长度集中在该区间，避免截断关键违规判定内容 |
| 上下文召回条数 | 前6–8条 | 匹配广告素材审核的核心关联数据，过多会占用过多token，过少会遗漏关键整改依据 |
| 上下文更新策略 | 实时同步 | 匹配广告资质与法规的实时更新节奏，确保审核依据的时效性 |
| token溢出处理规则 | 优先保留合规依据 | 优先保留广告法条款、历史合规修改记录，截断次要的落地页截图冗余文本 |

## 容易做错的三处
- 现象：调用知识库创建或集合创建接口后，聊天上下文未按预期加载。原因：未配置上下文召回的关联匹配字段，导致系统无法关联广告素材与历史审核意见的对应关系。
- 现象：聊天记录调大后未体现上下文记忆，或搜索知识干扰上下文召回结果。原因：上下文召回条数设置过低或单条引用最大token数取值过小，导致关键历史审核记录被强制截断。
- 现象：知识库容量计算结果与实际文档占用量不符。原因：未按广告素材、审核意见等不同文档类型的实际token占用量计算，误将落地页截图转写的冗余文本计入有效容量。

## 怎么确认配好了
- 上传单条广告素材及对应历史审核意见，查看上下文召回的内容是否包含至少3条相关审核记录。
- 调整单条引用最大token数的取值，验证单条引用的文本未出现强制截断的广告法条款或整改要求。
- 模拟上传实时更新的商品资质文件，确认上下文可自动加载最新的合规依据。
- 查看系统运行日志，确认无上下文token溢出的报错记录。
