# 投放效果优化的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
投放效果优化相关数据主要来自广告平台后台、归因系统、CRM线索库与落地页数据。日常产出的文档包含每日/每周投放日报、预算调价记录、素材AB测试表与优化复盘报告，数据更新节奏为日级或实时。数据字段包含广告消耗、转化量、获客成本、素材点击率、线索来源等，无统一固定格式，随业务调整灵活变动。

## 这些特征在「上下文与 token」这一环带来什么约束
广告投放相关文档与实时数据的混合输入，会导致上下文长度波动较大。实时数据的高频更新要求上下文需包含最新的调价记录与当日转化数据，而长周期的复盘报告又会占用大量token配额。不同文档的字段差异要求上下文召回需精准匹配业务场景，避免无关数据混入导致token无效消耗。同时，投放效果优化的核心决策依赖实时指标，上下文召回的延迟会直接影响决策效率，因此上下文与token的配置需兼顾数据时效性与配额合理性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 按业务文档总长度上浮10%–20% | 预留异常指标定位时的额外数据需求 |
| `quoteMaxToken` | 3000–5000 token | 适配单份素材测试表或调价记录的内容长度 |
| 单次上下文召回条数 | 前5条 | 匹配日常投放文档的单批次内容量 |
| 上下文召回更新间隔 | 10–15分钟 | 适配实时数据的日/实时更新节奏 |
| 全局上下文token上限 | 8000–12000 token | 覆盖多份日报、复盘报告与实时数据的混合输入 |
| 上下文数据过滤阈值 | 按实测标定 | 排除无关的历史数据，减少token无效消耗 |

## 容易做错的三处
- 单次对话token消耗远超日常用量，后台日志显示召回了多份无关的历史复盘报告。原因是未配置合理的上下文过滤规则与召回条数，导致非当日的历史数据被错误混入上下文，浪费token配额。同时未正确设置`maxContext`的预留空间，进一步加剧了无效消耗。
- 模型输出文本被无故截断，或界面提示上下文token超限。原因是未根据投放文档的实际总长度调整`maxContext`与全局上下文token上限配置，默认配额不足以承载多份日报、测试表的混合输入。
- 无法调整模型输出的token限制，默认上限仅为4000 token。原因是未正确修改`quoteMaxToken`或全局上下文配置项，未适配投放效果优化的长文档与数据召回需求。

## 怎么确认配好了
- 查看上下文召回日志，核对召回的数据是否为当前业务场景所需的投放相关文档，无无关历史数据混入。
- 输入一份完整的投放日报、调价记录与素材测试表，确认未触发token超限类报错。
- 对比调整配置前后的单次对话token消耗数据，确认消耗处于合理区间。
- 验证模型输出的完整度，确认未出现无故截断的情况。
