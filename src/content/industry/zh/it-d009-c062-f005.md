# 投放效果优化的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自广告平台后台、归因系统、CRM线索库与落地页统计工具。日常关联文档包含每日投放日报、周度优化周报、实时调价记录、素材AB测试台账与效果复盘报告。数据更新节奏多为日更或实时同步，字段包含曝光量、点击量、单次转化成本、剩余预算等，单位涉及元、次、千次曝光（CPM）等，单份文档的字段数量随投放量级浮动。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且实时性要求高，导致多轮对话需要持续同步最新的投放数据快照，因此`messages`上下文需要限定有效数据窗口，避免旧数据干扰当前分析。日常文档格式不统一，调价记录与测试台账的字段差异，要求提示词需要提前指定字段映射规则，减少对话中格式纠错的开销。实时更新的特性让`variables`需要绑定实时数据接口，避免调用过时的离线数据。同时投放场景的异常指标定位需要快速回溯历史查询，因此`chatId`需要绑定单次投放优化的完整会话链路，方便后续效果复盘。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 上下文窗口长度 | 前 8 轮对话 + 最近 24 小时的投放数据快照 | 匹配投放效果优化的实时分析需求，避免过长上下文导致的响应延迟 |
| `variables` 绑定数据源 | 广告平台API、归因系统实时接口 | 确保对话中调用的数据与当前投放状态同步 |
| 提示词字段映射规则 | 曝光量→曝光次数、转化成本→CPA | 统一日常文档的字段表述，减少格式歧义 |
| `chatId` 会话绑定规则 | 绑定单次投放账户的唯一标识 | 方便回溯同一场景下的多轮调整记录 |
| 单次对话最大响应token数 | 1500–2000 token | 覆盖单份投放日报的核心分析内容，避免截断关键结论 |
| 知识库召回上限 | 前 6 条历史优化记录 | 匹配日常复盘的参考范围，减少冗余信息干扰 |

## 容易做错的三处
- 对话中上传本地投放文档无法读取，但知识库上传文件正常。原因是对话场景的文件解析权限未绑定对应存储路径，仅开放了知识库专属的文件上传目录。
- 知识库检索在对话中返回空结果，但知识库后台测试可正常召回。原因是`variables`绑定的实时数据接口未同步更新检索的数据源范围，导致对话上下文过滤了匹配内容。
- 对话请求返回404 Invalid URL (POST /api/chat/completions)。原因是FastGPT v4.17.0版本中，未正确配置`chatId`的会话路由规则，导致请求未指向正确的聊天接口路径。

## 怎么确认配好了
- 发起包含历史投放数据查询的对话，核对`messages`上下文是否仅包含当前会话的有效轮次与最新数据快照。
- 调用`variables`绑定的实时接口，验证对话中返回的投放数据与广告平台后台的实时数值一致。
- 上传一份本地调价记录文档至对话窗口，确认可正常解析并提取其中的字段信息。
- 检查`chatId`是否绑定了当前投放账户的唯一标识，确保同一场景的多轮对话可被统一关联。
