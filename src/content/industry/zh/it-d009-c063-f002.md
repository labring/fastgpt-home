# 投放计划搭建的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
该品类的核心数据来自广告平台接口、用户画像标签库、预算排期表、归因工具日志。日常产出的文档包含投放计划框架、人群定向规则、预算分配细则、转化事件配置清单，字段涵盖定向维度、金额数值、活动时间节点。数据更新频率为每日或单次活动启动前，核心内容需反复校验定向匹配度与预算合理性。

## 这些特征在「上下文与 token」这一环带来什么约束
投放计划搭建的文档包含多维度定向规则、预算数值、转化事件等结构化内容，且需关联广告平台、用户画像等多来源的外部数据，上下文窗口需容纳多段长文本与跨源数据片段。数据更新频率较高，需确保上下文能实时同步最新的预算调整、定向变更内容。同时，文档字段多为强关联的业务参数，上下文召回时需保留字段间的逻辑关联，避免拆分后丢失业务语义。若token限制不足，会导致关键配置片段被截断，引发投放启动失败或预算配置错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 投放计划文档通常包含多段定向规则与预算明细，需容纳至少3份完整的历史投放计划片段与当前配置内容 |
| `quoteMaxToken` | 1500–2000 token | 单条投放计划的核心配置片段（如定向组合、预算分配）需完整保留，避免关键业务参数被截断 |
| 上下文召回数量 | 前6条 | 匹配投放计划相关的文档片段，避免召回过多无关内容占用token |
| 上下文召回重叠度 | 200–300 字符 | 保留相邻配置片段的逻辑关联，防止拆分后丢失定向规则与预算的对应关系 |
| 实时上下文同步 | 开启 | 适配投放计划高频更新的特性，确保调用时携带最新的预算与定向配置 |

以上配置基于FastGPT v4.17.0版本的界面逻辑。

## 容易做错的三处
- 现象：界面显示配置了`maxContext`为12000 token，但生成投放计划文档时，人群定向规则被截断，无法生成完整配置。原因：未将广告平台导出的定向数据片段纳入上下文窗口，导致有效业务内容超出实际可用token额度。
- 现象：设置最大响应token为3500，但部分转化事件校验的回复仅返回200 token长度的内容。原因：上下文召回时未保留转化事件与归因工具的关联字段，模型无法调用完整业务参数生成完整回复。
- 现象：云空间部署的FastGPT接入微信公众号后，无法加载已上传的投放计划文档。原因：云空间未配置上下文同步的token相关参数，导致无法获取文档的完整内容片段。

## 怎么确认配好了
- 手动导入一份完整的投放计划文档，检查上下文窗口是否包含所有定向规则、预算明细与转化事件配置。
- 触发一次转化事件校验请求，查看回复长度是否符合预设的最大响应token设置，无明显截断情况。
- 在云空间部署场景下，确认已配置上下文同步的相关参数，确保公众号能正常拉取文档内容。
- 调整上下文召回数量，验证召回的文档片段是否与当前投放计划的业务场景强相关，无无关内容混入。
