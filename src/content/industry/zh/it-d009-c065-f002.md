# 接口联调与数据对接的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
这个品类的数据主要来自客户系统接口、API文档、测试数据与联调日志。日常产出的文档包含接口清单、联调记录、字段映射表、问题跟踪表，数据字段涵盖接口地址、请求参数、返回码、字段映射规则、异常码定义等。数据更新频率为每日或按项目阶段调整，不同阶段的接口变更、字段调整会同步更新对应文档与数据记录。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的数据多源且更新频繁，接口变更、字段映射调整会快速同步到文档与数据中，要求上下文必须覆盖最新的接口规则与联调记录，避免使用过时信息引发联调错误。字段映射与异常码对齐环节涉及大量细节字段，会增加单条检索内容的token消耗，需要限制上下文总token量防止超出模型上限。同时联调日志包含大量重复的异常排查记录，无差别纳入上下文会冗余占用token配额，降低检索精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 12000–15000 token | 匹配接口联调相关文档的平均总长度，避免超出模型上下文承载上限 |
| `quoteMaxToken` | 1500 token | 适配单条接口文档、字段映射表的典型内容长度，确保核心字段完整保留 |
| 单次检索召回数 | 前6–10条 | 覆盖接口清单的常规条目范围，避免冗余内容占用token |
| 上下文刷新周期 | 按项目阶段 | 匹配数据的日更新或阶段更新节奏，确保上下文包含最新接口规则 |

## 容易做错的三处
- 配置`quoteMaxToken`为1500，但检索到的切块长度超过该值时，返回内容被截断导致字段映射规则不完整。原因是未匹配单条文档的实际token长度，直接套用通用设置。
- 在工作流中未正确配置上下文清空触发条件，导致历史联调记录持续占用上下文token，引发模型响应超出限制。原因是未结合联调阶段的节点切换逻辑设置触发时机。
- 无法查看单轮联调问答的token使用情况，无法排查上下文超限问题。原因是未开启对应日志采集开关，或未在系统设置中启用token统计功能。

## 怎么确认配好了
- 导入一份完整的接口清单与字段映射表，在FastGPT v4.17.0中测试检索流程，查看返回的上下文内容总token值未超出配置的`maxContext`范围。
- 触发一次联调日志的检索流程，核对返回的单条引用内容长度不超过配置的`quoteMaxToken`值。
- 调整单次检索召回数，验证返回的关联文档数量符合配置的取值范围。
- 模拟一次接口变更后的文档更新，确认上下文刷新后能加载最新的接口规则内容。
