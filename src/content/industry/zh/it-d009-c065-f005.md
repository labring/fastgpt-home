# 接口联调与数据对接的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
接口联调与数据对接的日常文档包含接口清单、联调记录、字段映射表、问题跟踪表。数据主要来自客户系统接口、API文档、测试数据与联调日志，更新频率为每日或每联调阶段。核心字段包括接口地址、请求方法、参数名、返回码、业务口径等，部分字段需匹配客户系统的单位规范，如请求超时时间以毫秒为单位，数据传输量以MB为单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来源分散且更新节奏灵活，多轮对话需隔离不同联调任务的上下文，避免跨任务的信息干扰。字段口径与异常码的对齐需要历史联调记录作为参考，因此对话需保留足够的历史上下文。接口文档与字段映射表的更新频率较高，提示词需同步匹配最新的业务规则，避免生成过时的文档内容。同时，单条联调任务的文档篇幅有限，需控制上下文窗口大小以确保关键信息不被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` 绑定规则 | 绑定单条联调任务ID | 依据FastGPT v4.17.0的会话隔离能力，区分不同联调任务的上下文，避免信息混淆 |
| `messages` 历史条数 | 保留前6条 | 覆盖核心联调记录与字段映射信息，避免上下文过载，适配联调场景的常规上下文长度 |
| `variables` 注入范围 | 注入当前接口清单、异常码表 | 利用`variables`参数的变量替换能力，自动填充业务数据，减少手动输入重复内容 |
| 上下文窗口大小 | 800–1200 字符 | 适配接口文档与字段映射表的常规篇幅，确保关键参数与业务规则完整呈现 |
| 提示词模板更新频率 | 按联调阶段调整 | 匹配接口文档的更新节奏，确保提示词与最新业务规则一致 |

## 容易做错的三处
- 插件节点文本提取配置聊天记录保留6条后，工作流执行时出现格式报错。原因是未将联调字段映射表作为`variables`注入到对话上下文，导致提取逻辑与接口参数规则不匹配。
- 线上联调对话长时间无响应，持续触发知识库搜索。原因是未限制`messages`的历史条数，导致上下文窗口过载，超出平台处理阈值。
- 接口联调文档起草时，模型生成的字段定义与实际接口不符。原因是未绑定`chatId`隔离不同联调任务的上下文，导致历史任务的错误规则被复用。

## 怎么确认配好了
- 触发一次联调测试，查看对话上下文是否包含当前任务的接口清单、字段映射表等核心信息
- 检查`messages`的历史条数是否与配置一致，确认无冗余历史干扰当前任务
- 验证`variables`注入的变量是否能在对话中自动替换为当前联调的业务数据
- 提交测试请求，确认模型生成的文档格式符合接口联调的标准模板
