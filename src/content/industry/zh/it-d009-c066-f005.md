# 搜索广告关键词管理的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自搜索广告后台、搜索词报告、竞价排名数据与落地页数据。日常产出的文档包含关键词清单、否词表、出价记录、搜索词报告，字段覆盖关键词文本、匹配模式、单次出价金额、点击量、转化数等，单位包含元、次、条。数据更新频率通常为日度或周度，单份文档的条目数随广告账户的规模变化。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来源包含多类广告后台与业务报表，多轮对话需明确区分不同数据源的字段归属，避免混淆竞价排名数据与落地页转化数据。文档结构固定且字段明确，提示词需预先指定关键词、匹配模式、出价金额等必填字段，确保生成的文档符合业务规范。数据更新频率较高，对话上下文需限制在近期的日度或周度数据范围内，避免引用过期信息。同时，需在多轮流程中加入数据校验环节，防止因字段错误导致后续竞价调整失误。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 开启并绑定广告业务专属变量 | 用于注入实时出价阈值、否词规则、账户ID等品类专属参数 |
| `chatId` | 绑定专属会话标识 | 区分不同广告账户的对话上下文，避免数据跨账户混淆 |
| `messages` | 按会话顺序拼接上下文 | 确保多轮对话的历史信息完整传递，避免关键需求丢失 |
| 最大上下文长度 | 800–1200 字符 | 匹配单份关键词清单的常规条目总长度，避免截断核心数据 |
| 单次对话返回上限 | 前 10 条 | 适配单轮文档起草的输出规模，防止内容过载影响阅读 |
| 单次请求超时时间 | 300 秒 | 匹配广告数据的加载节奏，避免因数据拉取过久导致对话中断 |
| 多轮对话历史保留时长 | 600 秒 | 匹配广告优化师的常规工作节奏，避免历史上下文过期 |

## 容易做错的三处
- 对话输出仅包含中文，未遵循英文prompt的语言要求。原因是未在`variables`中绑定语言强制参数，或提示词未明确指定输出语言规则。
- 上传关键词清单或搜索词报告后解析失败。原因是未预先配置对应文档的字段映射规则，导致模型无法识别关键词、出价金额等核心字段。
- 应用调用后无法查看详细对话记录。原因是未开启对话日志存储配置，或未绑定`chatId`以关联会话与日志条目。

## 怎么确认配好了
- 上传一份测试用的关键词清单，检查生成的文档是否包含预设的字段与格式。
- 在`variables`中配置英文语言参数，发起英文prompt的对话，验证输出语言是否符合要求。
- 发起多轮对话并生成会话链接，检查`chatId`是否正确关联当前会话的上下文数据。
- 调用应用接口后，查看对话详情页是否显示完整的交互日志与参数调用记录。
