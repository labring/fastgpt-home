# 搜索广告关键词管理的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
搜索广告关键词管理的日常核心文档包含关键词清单、否词表、出价记录、搜索词报告四类。数据主要来自搜索广告后台、搜索词报告、竞价排名数据及落地页数据，更新频率为日或周。文件字段包含关键词文本、匹配模式、出价金额、否词类型、转化数据等，其中出价金额以元为单位，关键词文本长度多为1至20字符，部分扩展关键词可达50字符。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源多为后台导出的结构化文件，且更新频率固定，工作流需支持定时触发或接收外部文件触发的模式。不同文档的字段存在差异，需在工作流中配置字段映射环节，避免数据读取错误。同时，关键词扩展、否词筛选、出价匹配调整为最耗时环节，工作流需拆分节点执行，避免单次请求超时。此外，数据偶发存在格式异常，需配置校验环节过滤无效记录，防止后续环节出错。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发时机 | 按日定时触发，或接收后台导出文件后触发 | 匹配搜索广告数据日/周的更新频率 |
| 单次处理条数 | 200-500条/次 | 适配搜索广告数据的单批次处理规模，避免节点过载 |
| `variables`绑定范围 | 绑定关键词清单、否词表的字段映射 | 关联不同文档的字段，确保节点读取目标数据 |
| 单次执行超时 | 600秒 | 覆盖批量处理大量关键词数据的耗时需求 |
| 失败重试次数 | 2次 | 应对后台导出数据的偶发网络波动或格式异常 |
| 前置校验开关 | 开启 | 过滤无效关键词记录，避免后续环节出错 |

## 容易做错的三处
- 现象：工作流中`variables`绑定的关键词字段为空，节点输出无有效数据。原因：未正确映射搜索词报告与关键词清单的字段对应关系，导致变量无法读取目标列。
- 现象：循环体无法获取外部变量，工作流执行中断后提示未找到变量。原因：未将外部变量配置为全局可访问，导致循环节点无法读取上下文参数。
- 现象：工作流执行超时，返回状态码504。原因：单次处理的关键词记录数量超出系统上限，未拆分批次执行。

## 怎么确认配好了
- 执行一次测试工作流，检查各节点输出的字段是否与关键词清单、否词表的列名一致。
- 查看FastGPT v4.17.0版本的工作流日志，确认`variables`绑定的参数未出现空值或格式错误。
- 模拟批量数据导入，验证节点执行时长未超过预设的超时阈值。
- 触发定时任务，确认工作流按日/周的更新频率自动启动。
