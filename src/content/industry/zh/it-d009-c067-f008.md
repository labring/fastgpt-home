# 数据安全分类分级的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
本品类的数据由数据治理团队、安全咨询顾问、法务合规日常产出与维护。核心日常文档包含数据目录、分类分级规则、重要数据识别表、评审纪要。数据来源包括数据资产盘点结果、数据库元数据、业务系统说明文件、公开法规文件。数据更新频率为季度周期或每次业务系统变更时触发。文档字段包含数据资产编号、敏感字段标识、分级等级、评审意见等，无统一固定单位，随业务场景调整。

## 这些特征在「工作流编排」这一环带来什么约束
多来源的数据接入要求工作流需支持多节点并行拉取不同类型的数据源，避免单节点过载。季度或按需更新的特性要求工作流配置可灵活触发，支持定时运行或手动触发两种模式。多类型文档的处理需要工作流内置变量存储节点，分别承载不同文档的内容与字段。评审环节的多轮校验需要工作流设置串行审批节点，确保分级规则与识别结果经过合规确认后才能进入下一环节。同时，出错后果涉及合规风险，要求工作流配置错误告警与回滚机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 问题优化 | 前置在敏感字段识别节点后启用 | 用于清洗原始资产盘点数据，优化敏感字段匹配规则 |
| 最大上下文 | 8000–12000 字符 | 需承载分类分级规则、数据目录等多文档内容，按实测标定 |
| `variables` 绑定 | 按上传文件的元数据字段映射 | 需将数据资产盘点表、业务系统说明等多类型数据源传入工作流 |
| 超时阈值 | 600 秒 | 覆盖分级规则评审、敏感字段识别的多轮校验流程，避免中途中断 |
| `nodeId` 关联 | 绑定分类分级主节点的唯一ID | 确保工作流按资产梳理→敏感识别→规则评审的顺序执行 |

## 容易做错的三处
- 现象：工作流运行后敏感字段识别结果为空，界面显示`variables`未加载完成。原因：未将数据资产盘点表的元数据字段绑定到工作流变量，导致数据源未正确传入。
- 现象：配置问题优化组件后，分级规则评审环节出现超时报错。原因：将问题优化组件放在了评审节点之后，提前消耗了上下文额度导致后续流程无法完成。
- 现象：简易应用中调用该工作流作为工具时，上传的文件无法传入参数。原因：未在工作流的`variables`配置中开启文件链接映射开关，导致简易应用的上传参数无法传递到工作流中。

## 怎么确认配好了
- 进入FastGPT v4.17.0的工作流编辑页面，检查`variables`配置是否包含数据目录、分类分级规则等数据源的字段映射。
- 触发工作流的测试运行，查看敏感字段识别节点的输出结果是否包含上传的资产盘点表中的敏感字段信息。
- 调用绑定该工作流的工具，上传测试文件，确认文件链接是否能正确传递到工作流的参数中。
- 查看工作流的运行日志，确认超时阈值设置后，评审环节未出现超时报错。
