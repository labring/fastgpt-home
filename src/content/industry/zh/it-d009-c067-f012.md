# 数据安全分类分级的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
本品类的数据主要来自数据资产盘点结果、数据库元数据、业务系统说明文件及公开法规文件，日常产出数据目录、分类分级规则表、重要数据识别表、评审纪要四类文档。更新频率为季度级或对应业务系统变更时触发。文档多为结构化表格搭配说明段落，字段包含资产编号、敏感等级、合规依据、负责人等，无统一固定单位，随具体资产类型调整。

## 这些特征在「文档解析与分块」这一环带来什么约束
多来源的文档格式混杂，既有结构化表格又有纯文本段落，要求解析引擎适配多种格式以保留核心合规信息。季度级更新且随业务系统变更的特性，要求解析配置具备稳定性，避免频繁调整。结构化表格中的合规字段多为固定项，分块时需保留表格完整性，防止拆分跨页的规则条目。评审纪要多为短段落拼接，需避免将关联评审意见拆分为独立块，影响后续合规评审的上下文关联。同时，覆盖非个人信息的全量数据资产，解析时需准确识别敏感等级字段，防止遗漏关键合规内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配本品类文档中规则条目与评审纪要的段落长度，避免拆分核心合规字段 |
| `chunkSplitter` | 按段落+标题分隔 | 保留分类分级规则的层级结构，避免破坏评审纪要的上下文关联 |
| `customPdfParse` | 启用 | 适配FastGPT v4.17.0版本的结构化表格与混合格式的合规文档，提升表格解析完整性 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容批量导入的季度级数据资产盘点文件 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对大型元数据导出文件的解析耗时 |
| `chunkSettingMode` | 手动配置 | 针对本品类固定字段的文档，自定义分块规则以匹配合规文档结构 |

## 容易做错的三处
- 现象：上传分类分级规则PDF后，界面显示无法读取该文件内容。原因：未启用`customPdfParse`配置，默认解析引擎无法适配结构化合规表格。
- 现象：配置飞书知识库同步后，未获取到PPT、PDF格式的文档。原因：未在知识库同步配置中开启对应文件类型的解析权限，或`UPLOAD_FILE_MAX_SIZE`设置过小导致大文件被拦截。
- 现象：部署最新版marker后，日志显示ocr error。原因：未配置`chunkSettingMode`适配扫描版合规文档的OCR识别，或未调整`PARSE_FILE_TIMEOUT_SECONDS`以匹配解析耗时。

## 怎么确认配好了
- 上传一份典型的分类分级规则PDF，查看解析后的分块预览，确认表格结构完整未被拆分。
- 核对`UPLOAD_FILE_MAX_SIZE`配置，确保其取值匹配当前需导入文件的最大体积。
- 调整`chunkSize`后，验证评审纪要段落是否被完整保留在单个分块内。
- 测试上传季度级数据资产盘点文件，确认解析过程未触发超时限制。
