# 数据库云服务运维的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
数据库云服务运维的日常数据来自云数据库控制台、慢日志、监控指标、工单系统，更新频率为日更或每次实例变更后生成。常见文档包括实例变更单、备份恢复记录、性能诊断报告、参数调整记录，各文档字段结构差异明显：实例变更单包含操作时间、变更前后参数值；慢日志包含SQL语句、执行耗时、发起IP；备份记录包含存储路径、恢复成功率。字段单位涉及毫秒、GB等，不同来源的数据格式存在一定差异。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据库云运维的数据来源分散、更新节奏频繁且文档结构多样，对多轮对话与提示词配置带来明确约束。首先，不同来源的数据需通过关键标识隔离，因此需通过`variables`传递租户ID与实例ID等参数，防止跨租户数据混淆。其次，高频更新的运维数据易导致对话上下文过载，需限制`messages`的保留长度，避免超出模型窗口。最后，不同文档的字段差异要求提示词需适配特定文档的解析规则，确保提取的信息精准匹配运维需求。在FastGPT v4.17.0中，这些约束需通过标准化配置落地，避免模型出现无效检索或信息混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 会话标识绑定 | 绑定`chatId`到实例ID | 匹配多租户服务边界的业务特征，确保会话与指定云数据库实例一一对应 |
| 对话历史保留上限 | 前 20 条对话 | 适配数据库云运维文档的日更/变更触发节奏，避免`messages`上下文过载 |
| 变量传递规则 | 仅传递`variables`内的租户ID与实例ID | 严格隔离不同客户的运维数据，防止跨租户查询 |
| 问题优化开关 | 开启 | 针对慢SQL定位、参数风险评估等耗时环节，自动优化提问精准度 |
| 上下文截断阈值 | 8000 字符 | 匹配单份运维文档的平均长度，适配通用大语言模型的上下文窗口 |
| 单次搜索上限 | 前 5 条结果 | 符合慢日志、监控指标等数据的单轮查询量级，减少冗余信息干扰 |

## 容易做错的三处
- 现象：升级到FastGPT v4.17.0后，上传云运维数据集文件时出现接口报错，状态码返回400，且模版导入功能正常。原因：未正确配置`variables`内的S3存储桶权限变量，导致跨存储迁移时鉴权失败。
- 现象：多轮对话中多次返回无关云数据库实例的慢SQL日志，无法定位目标实例的问题。原因：未在`messages`中正确传递实例ID参数，导致检索范围未限定到指定实例。
- 现象：对话窗口返回「上下文长度超出限制」报错，且无法完成后续提问。原因：未设置对话历史保留上限，导致`messages`累积过多历史内容超出模型窗口。

## 怎么确认配好了
- 上传一份测试用的云数据库实例变更单，检查对话历史中是否正确提取了实例ID与变更时间字段。
- 触发慢SQL定位的提问，检查返回结果是否限定在当前租户的云数据库实例范围内。
- 查看FastGPT v4.17.0的配置面板，确认对话历史保留上限、变量传递规则已按设定生效。
- 测试S3存储迁移后的文件上传，确认无鉴权或超时报错。
