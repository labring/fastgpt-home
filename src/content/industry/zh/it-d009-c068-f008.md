# 数据库云服务运维的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
这个品类的数据主要来自云数据库控制台、慢日志、监控指标与工单系统。日常产出的文档包含实例变更单、备份恢复记录、性能诊断报告、参数调整记录，各文档包含实例唯一标识、变更时间、操作类型、关联资源ID等字段。数据更新频率为每日或每完成一次变更操作时更新，不同文档的字段覆盖云产品控制台权限、租户边界信息与运维操作细节。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散且包含云控制台、慢日志等多类异构数据源，工作流编排需支持多节点按顺序对接不同数据源，通过`variables`传递跨节点的实例标识参数。数据更新无固定定时周期，需配置为事件触发式启动工作流。文档包含租户边界与权限字段，需在编排中校验`nodeId`对应的租户权限，避免跨租户操作。慢SQL定位、备份恢复等耗时环节需串行执行工具，防止并行调用导致监控指标采集冲突或数据不一致。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 事件触发（实例变更/慢日志告警） | 匹配数据更新无固定周期的特征，避免无效轮询 |
| 节点执行顺序 | 按配置的节点序列依次执行 | 确保慢SQL定位、备份校验等环节串行运行，避免资源冲突 |
| `variables`参数配置 | 传递实例ID、租户标识 | 统一跨节点的核心标识参数，保障数据关联准确性 |
| `nodeId`权限校验 | 绑定当前租户的云控制台权限 | 匹配云服务运维的多租户边界要求，防止越权操作 |
| 超时阈值 | 600秒 | 覆盖备份恢复、性能诊断等最长耗时场景 |
| 重试次数 | 2次 | 应对临时的云API调用失败，避免单次失败终止工作流 |
| 单次重试间隔 | 30秒 | 避免短时间内频繁重试占用云服务资源 |
| 批量处理上限 | 前10条 | 匹配单批次运维操作的常规数量 |

## 容易做错的三处
- 工作流内工具未按顺序执行，部分工具无调用记录。原因是未配置节点执行顺序，或未正确绑定`variables`传递的执行依赖参数，导致并行触发工具调用。
- 部署后工作流与知识库配置空白，但接口可正常调用。原因是本地存储的配置文件未正确挂载，或容器重启后未加载持久化的工作流编排数据。
- 知识库选择时变量引用无效，返回空结果。原因是未在工作流节点中配置`variables`的上下文传递，导致变量未被正确替换为实际实例信息。

## 怎么确认配好了
- 手动触发一次实例变更事件，检查工作流日志是否按配置顺序调用所有工具节点。
- 查看`nodeId`对应的权限校验日志，确认仅当前租户的实例可被关联到工作流中。
- 提交慢SQL定位任务，检查`variables`传递的实例ID是否与实际查询的实例一致。
- 模拟云API调用失败场景，确认工作流触发重试机制，未直接终止执行。
