# 数据库云服务运维的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
数据库云服务运维的日常文档包含实例变更单、备份恢复记录、性能诊断报告、参数调整记录。数据来源为云数据库控制台、慢日志、监控指标与工单系统，更新频率为每日或每次变更后。文档多含标准化表头、数值指标与实例标识字段，字段包括实例ID、变更时间、慢SQL语句、备份路径等，单位涵盖秒、MB、百分比等。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类文档含长SQL语句、多表格监控数据与标准化实例标识，分块时需避免拆分破坏语义关联。文档更新频率高且单次体量可能较大，需控制解析时长与文件上传上限。部分文档含多租户权限字段，分块时需保留上下文边界避免跨租户信息混淆。此外，运维文档的表格结构固定，通用解析逻辑易出现错位，需针对性调整解析规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 该品类文档多含长SQL语句与监控指标行，此区间可避免拆分破坏语义完整性 |
| `customPdfParse` | 开启 | 该品类文档多含标准化表格与实例编号，本地化解析可保留表格格式与字段关联 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 单份备份恢复记录可能包含多日监控数据，需足够时间完成完整解析 |
| `chunkSplitter` | 按段落+表头分隔 | 该品类文档含性能报告表头与慢SQL块，按表头分隔可保留分组语义 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 运维文档可能包含归档的慢日志批量文件，需放宽上传上限 |
| `chunkSettingMode` | 手动模式 | 需针对实例变更单、性能报告等不同文档类型调整分块规则 |

## 容易做错的三处
- 现象：上传PDF文件后解析内容失败，控制台返回413状态码。原因：未调整`UPLOAD_FILE_MAX_SIZE`参数，文件大小超过默认限制。
- 现象：上传的表格文档解析后出现错位，分块结果混乱。原因：未开启`customPdfParse`，使用通用分块逻辑无法识别运维文档的标准化表格结构。
- 现象：API对接后对话时上传文件解析超时。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置过短，无法处理包含多日监控数据的文档。

## 怎么确认配好了
- 上传单份1000 MB以内的归档慢日志文件，检查解析进度是否在300–600秒内完成。
- 上传含多表格的性能诊断报告，检查解析后的分块是否保留表头与对应数据行的关联。
- 测试上传实例变更单，检查分块是否保留工单编号与变更内容的完整上下文。
- 查看FastGPT v4.17.0的本地解析日志，确认无外部网络传输记录，验证解析为本地化处理。
