# 数据清洗与质检的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
本品类处理的数据来自原始数据集、ETL日志、标注平台及抽样结果，更新节奏为每日或每批次。日常涉及的文档包括清洗规则、质检抽样表、异常数据清单与交付报告，文档结构多为结构化表格、带格式的规则条目或明细清单，字段包含数据标识、异常类型、抽样比例、校验规则等，无统一强制单位，部分字段需匹配对应数据集的业务单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
本品类的数据特征对文档解析与分块环节带来多重约束。多来源数据导致解析格式混合，需适配结构化表格、自由文本规则、明细清单等多种文档结构；高频更新要求解析分块支持批量快速处理，避免拖慢数据流转节奏；清洗规则、异常清单等文档需保留完整逻辑单元，不能拆分跨关联的规则条目或异常关联记录；交付报告需完整保留结论与支撑数据，分块不能破坏报告的逻辑完整性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配清洗规则、异常清单等文档的逻辑单元长度，避免拆分完整校验规则或异常关联记录 |
| `chunkSplitter` | 按语义分段 | 适配本品类混合格式的文档，保留规则与异常记录的语义完整性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 匹配批量文档的解析时长，避免高频更新场景下的超时中断 |
| `customPdfParse` | 开启 | 适配标注平台导出的PDF格式质检报告，保留表格与文本的对应关系，支持提取图片内容 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量交付报告与原始数据集文档的上传需求 |
| `chunkSettingMode` | 手动配置 | 适配本品类多样的文档结构，灵活调整分块规则以匹配不同文档的逻辑单元 |

## 容易做错的三处
- 上传将Java接口文件后缀修改为txt的文档后，解析结果无有效数据，原因是未配置自定义解析规则，无法适配代码类文本的格式逻辑。
- 使用chunk模式调用pushdata api上传文档后，界面持续显示索引中状态，原因是解析超时配置不足，批量文档未完成解析即进入索引流程。
- 上传PDF格式的质检抽样表后，文档内的图片未被解析提取，原因是未开启图片提取相关配置，仅解析PDF中的纯文本内容。

## 怎么确认配好了
- 上传单份清洗规则文档，核对解析后的分块是否保留完整的校验规则条目，未出现跨逻辑单元的拆分。
- 批量上传同批次的异常数据清单，确认解析耗时未超过配置的超时阈值，无超时报错日志。
- 上传修改后缀的代码类文档，检查解析结果是否包含代码片段或接口定义等有效内容。
- 上传包含图片的PDF交付报告，确认解析结果是否包含图片对应的文本描述或提取内容。
