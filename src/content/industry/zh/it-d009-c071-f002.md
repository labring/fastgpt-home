# 数据脱敏处理的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
这个品类的数据主要来自业务数据库、数据字典、自研脱敏工具及访问审批系统，日常产出脱敏方案、字段映射表、脱敏验证报告与审批记录四类核心文档。数据更新以单项目或单批次为单位，无固定周期。文档字段包含敏感字段标识、脱敏规则类型、执行范围、验证结果与审批节点，无统一固定单位，随项目场景调整。数据处理过程中需关联多系统的元数据与审批流信息，整体数据体量随项目复杂度波动。

## 这些特征在「上下文与 token」这一环带来什么约束
该品类的文档多为结构化合规类内容，单批次数据量波动大，且需关联多系统元数据，导致上下文窗口的有效内容占比难以统一。敏感字段识别与脱敏规则配置环节需反复调用历史项目的字段映射表与验证记录，若上下文窗口过小，无法召回关联的历史配置信息，导致规则配置效率下降。数据更新以项目为单位，每次启动新任务时需重新加载当前项目的脱敏规则与审批节点，若token配额不足，无法完整加载当前项目的完整配置文档，引发脱敏任务中断。合规审计要求留存完整的上下文关联记录，若token超限导致部分历史验证报告丢失，将无法通过合规审计。

## 配置怎么定
FastGPT v4.17.0 版本的上下文与token配置项支持以下调整：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 前 3–8 条历史项目记录 | 该品类数据以项目为单位更新，单项目关联的历史记录数量有限，无需加载过多无关批次数据 |
| `maxContext` | 单项目专属上下文池 | 区分不同项目的上下文数据，避免跨项目的敏感信息泄露 |
| `quoteMaxToken` | 800–1200 token | 脱敏方案与字段映射表的单份核心文档长度多在该区间内，可完整加载单份关键内容 |
| 上下文召回上限 | 按实测标定 | 需结合单项目的文档总数量调整，避免召回过多非关联的历史审批记录 |
| 关联匹配阈值 | 0.75（按项目场景调整） | 用于筛选与当前脱敏任务强关联的历史字段映射记录，过滤冗余数据 |

## 容易做错的三处
- AI节点配置的`maxContext`为30条，但对话明细中仅显示2条上下文，无法关联历史脱敏配置。原因是未正确配置关联匹配阈值，系统过滤了大部分非关联的历史脱敏文档，导致有效上下文被截断。
- 任务执行时提示上下文token数超标，无法加载完整的脱敏方案文档。原因是设置的`quoteMaxToken`过小，未覆盖单份核心脱敏方案的文档长度，导致加载失败。
- 超长脱敏任务执行超时，任务状态显示为失败。原因是未调整任务超时阈值，默认阈值无法覆盖多批次数据的关联上下文加载与验证流程。

## 怎么确认配好了
- 查看当前项目的脱敏方案文档，确认加载的内容完整度符合预期，无关键字段缺失。
- 测试调用历史项目的字段映射表，确认系统可召回与当前任务强关联的记录。
- 提交小批量测试任务，观察任务执行时长是否符合预设的超时阈值，无中断情况。
- 检查上下文关联日志，确认仅加载了与当前项目相关的历史记录，无冗余数据混入。
