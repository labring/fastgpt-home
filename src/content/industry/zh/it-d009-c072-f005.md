# 数据采集任务设计的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自客户需求文档、公开数据源、采集工具日志与自有样本库。日常产出的文档包含采集方案、样本规格表、授权说明与任务排期表。数据更新节奏以单项目为周期，跨项目复用时可按周同步更新。文档字段包含样本范围、采集字段、合规校验项、排期节点，单位多为样本量、时间周期、权限标识，无统一标准化单位体系。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散且文档结构不统一，最耗时的样本范围定义、字段规格确认环节，需通过多轮对话逐步澄清客户模糊需求。提示词需预设合规校验的基础规则，避免遗漏授权说明的核心条款。由于数据更新以单项目为周期，对话上下文需保留项目专属的采集要求，需限制历史消息的留存长度以保障交互效率。同时，不同项目的文档字段无统一标准，提示词需明确引导提取标准化的采集参数，避免生成不符合项目要求的任务设计内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `messages`历史消息保留上限 | 前3–5轮对话内容 | 适配单项目采集任务的上下文长度，避免冗余信息干扰提示词逻辑 |
| `variables`预设采集字段模板 | 包含样本范围、合规校验项的结构化变量 | 统一不同项目的文档字段提取规则，对齐日常采集方案的标准结构 |
| 单次对话超时阈值 | 600 秒 | 适配复杂合规校验与多轮澄清的交互时长，避免因任务细节多导致超时 |
| `chatId`绑定项目专属上下文 | 绑定当前项目的唯一标识 | 确保多轮对话仅保留当前项目的采集需求，避免跨项目数据混淆 |
| 问题优化开关 | 开启 | 自动优化用户的模糊需求表述，辅助明确样本范围与字段规格 |
| 最大上下文token数 | 8000 token | 适配采集方案、授权说明等长文档的提示词输入，保障信息完整 |

## 容易做错的三处
在FastGPT v4.17.0版本中，常见的配置错误包含以下三类：
- 对话窗口弹出“上下文解析失败”报错，原因是未限制`messages`的历史轮次，多轮对话积累的冗余内容超出配置的最大上下文token数，导致系统无法完整加载上下文。
- 上传文件与文本数据集失败，但模版导入功能可正常使用，原因是未在`variables`中配置数据源的校验规则，系统未正确识别非模版类的上传请求格式。
- 对话开场白仅能显示单个预设问题，无法生成多个可选问题，原因是未在提示词中明确要求生成多选项开场白，且未将预设问题列表写入`variables`的初始对话变量。

## 怎么确认配好了
- 发起一轮模拟对话，输入模糊的采集需求，检查系统是否能逐步澄清样本范围与字段规格，确认`messages`的历史轮次限制生效。
- 上传非模版类的采集方案文档，检查上传功能是否正常，确认`variables`的数据源校验规则配置正确。
- 查看对话初始界面，确认是否显示预设的多个可选问题，检查`variables`的初始变量是否包含预设问题列表。
- 发起包含合规校验项的对话，检查系统是否能自动关联授权说明的相关条款，确认提示词的预设规则生效。
