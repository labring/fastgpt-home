# 文本标注项目的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
文本标注项目的数据主要来自客户提供的原始语料、内部标注平台产出的标注结果、专用词表以及质检抽样后的结果。日常维护的文档包括标注规范手册、批量样本包、质检报告和问题反馈表，更新频率按日或每批标注任务执行。数据字段包含原始文本、标注标签、标注人信息、质检结果等，单位以字符、标签类别、批次编号为主。该品类聚焦语义边界、实体识别与意图分类，区别于图像标注项目的视觉特征处理逻辑。

## 这些特征在「上下文与 token」这一环带来什么约束
文本标注项目的多源数据与高频更新特性，会直接影响上下文与token的使用逻辑。原始语料长度差异大，批量样本包的总字符量远超单模型上下文上限，容易触发token溢出或结果截断。标注规范与质检报告的语义细节需要完整保留，以确保标注逻辑对齐，若上下文截取不当会导致标签边界解释偏差。同时，每日或每批的更新节奏要求上下文配置适配动态变化的语料规模，避免因固定参数导致的token消耗异常或响应延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配批量文本标注的语料规模，避免单轮上下文溢出，适配FastGPT v4.17.0的上下文处理逻辑 |
| `quoteMaxToken` | 2000–3000 字符 | 保留标注规范、质检报告等关键参考文本的完整语义，确保标注逻辑对齐 |
| 最大上下文刷新间隔 | 每6小时 | 适配每日或每批的更新频率，及时加载最新的标注规范与样本数据 |
| 单批样本上下文上限 | 前100条样本 | 控制单轮token消耗，避免批量处理时的响应延迟 |
| 语义对齐阈值 | 按实测标定 | 匹配标注任务的语义边界精度要求，避免过度截取关键标签解释内容 |

## 容易做错的三处
- 现象：配置`maxContext`后仍出现文本截断，日志显示`[hide X char]`。原因：未同步调整`quoteMaxToken`参数，导致引用的标注规范文本被提前截取，无法完整传递语义边界要求。
- 现象：批量标注任务执行时响应超时，接口返回状态码504。原因：未限制单批样本的上下文加载数量，导致token消耗超出模型承载上限，触发超时。
- 现象：启动关联模型服务时报错`failed to get gpt-3.5-turbo token encoder`。原因：未针对文本标注项目的语料特征调整上下文参数，导致模型编码器无法适配批量文本的token统计逻辑。

## 怎么确认配好了
- 执行单批100条样本的测试任务，检查上下文是否完整加载标注规范与历史质检报告，无截断或隐藏字符。
- 查看token消耗统计，确认单轮任务的token使用量在配置的`maxContext`范围内，无异常飙升。
- 关联最新的标注规范更新，验证上下文配置是否能自动加载最新版本的文档内容。
- 测试批量任务的响应速度，确认符合标注团队的日常处理节奏。
