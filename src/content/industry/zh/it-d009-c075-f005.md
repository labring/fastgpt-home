# 文档站维护的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据主要来自代码仓库、文档站构建日志、用户反馈与版本发布记录。日常维护的文档包含安装文档、API文档、迁移指南与FAQ，通常按文档类型与版本号分类存储。更新节奏多为周度或随版本发布触发，单篇文档的核心字段包含版本标识、更新时间、关联代码分支与用户反馈标签。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据特征会从三个维度约束多轮对话与提示词配置。第一，数据来源包含版本发布记录与代码仓库，多轮对话需关联当前文档版本的上下文，避免跨版本的错误指引。第二，更新节奏为周度或随版本发布触发，对话上下文需要定期刷新，防止加载过期的文档内容。第三，文档类型多样，提示词需根据安装文档、API文档等不同类型调整输出格式，确保匹配用户的查询场景。此外，用户反馈与构建日志会影响对话的纠错逻辑，需保留历史交互信息以精准调整后续回复。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `messages` | 保留最近 15–25 轮对话上下文 | 文档更新频率为周/每版本，避免过期上下文干扰当前查询，符合FastGPT v4.17.0的上下文管理规范 |
| `variables` | 注入当前文档版本、文档类型变量 | 数据来源包含版本发布记录与文档类型，需关联对应场景的提示词 |
| `chatId` | 绑定文档站专属会话ID | 需区分不同文档站的对话上下文，避免会话数据混淆 |
| 上下文刷新间隔 | 每 7 天 自动刷新上下文缓存 | 匹配周度更新节奏，确保加载的文档内容为最新版本 |
| 单次对话最大token数 | 8000–12000 token | 匹配日常文档的平均长度，避免超出模型上下文限制 |
| 提示词模板匹配规则 | 按查询关键词匹配文档类型 | 日常文档包含多种类型，需精准匹配对应输出模板 |

## 容易做错的三处
- 现象：选择Ollama对应模型后，预设引导词未生效，原因：未在`variables`中注入引导词配置参数，导致提示词未被正确加载。
- 现象：无法将建好的对话应用与集成插件对接，原因：未通过`chatId`绑定对应插件的会话标识，导致上下文与插件不匹配。
- 现象：使用知识库对话应用的API key仍提示未授权，原因：未在`messages`中正确传递授权校验字段，导致会话权限校验失败。

## 怎么确认配好了
- 发起安装文档相关查询，检查回复是否包含当前版本的准确安装指引内容，验证上下文刷新与版本关联配置生效。
- 切换不同类型的AI模型后发起API文档相关查询，确认回复基于新模型的输出，验证模型切换配置生效。
- 提交授权错误场景的测试，确认授权校验逻辑正常触发，验证API key配置的正确性。
- 查看会话日志，确认`chatId`、`messages`、`variables`参数均被正确传递，验证基础配置无误。
