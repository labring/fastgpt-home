# 日志平台与可观测性的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自日志系统、Trace平台、Metrics系统及应用SDK，日常产出的文档包括日志采集规范、链路追踪说明、指标字典与看板配置记录。数据更新频率多为每日或随版本迭代，文档结构多包含字段定义、采集规则、关联逻辑与维护说明，字段涵盖日志级别、Trace ID、指标名称与阈值参数，单位多为毫秒、字节、条等可观测性专用单位。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散的特点要求工作流需配置跨源数据拉取节点，对接多系统获取日志、链路追踪与指标数据。文档更新频繁的属性要求工作流设置版本校验环节，避免使用过期的采集规范或指标字典。字段多且单位特殊的特征要求工作流包含标准化处理步骤，统一不同来源数据的格式与单位。此外，该品类最耗时的采集字段标准化、链路关联排查等环节，要求工作流简化重复操作，自动同步最新文档配置，提升起草效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按文档更新频率绑定`24 小时`刷新周期 | 匹配该品类文档的常规更新频率，避免使用过期的全局配置 |
| `nodeId` | 为每个工作流节点分配`001-999`区间的唯一ID | 避免节点冲突，便于后续工作流链路排查 |
| 全局变量配置 | 将Redis连接信息、日志索引前缀设为全局变量，取值按`500 MB`到`2000 MB`区间标定 | 统一管理跨节点共享的配置参数，便于批量调整 |
| 版本校验阈值 | 设置为`1 天`的文档更新间隔 | 拦截过期的采集规范、指标字典等文档数据 |
| 字段标准化规则 | 将日志级别统一映射为`INFO/WARN/ERROR`标准格式 | 统一该品类分散的日志字段格式，简化后续链路关联 |
| 子流程变量继承 | 开启子流程继承父流程`variables`的开关 | 满足外层流程与嵌套子流程共享全局变量的需求 |

## 容易做错的三处
- 工作流执行后返回`400 Bad Request`报错，原因是未正确配置`variables`参数的必填字段，导致全局变量无法被系统识别。
- 嵌套子流程无法获取外层流程的共享变量，原因是未开启子流程继承父流程`variables`的配置，导致变量作用域被隔离。
- 工作流拉取的日志字段格式混乱，导致后续链路排查耗时增加，原因是未配置字段标准化规则，直接使用原始采集的非标准格式数据。

## 怎么确认配好了
本页面的配置规则适用于FastGPT v4.17.0版本。
- 调用工作流创建API，检查返回的工作流ID与预设`nodeId`是否匹配，确认基础配置已生效。
- 手动触发工作流，查看全局变量加载日志，确认Redis连接信息等参数已被正确读取。
- 提交包含过期文档标识的测试数据，确认工作流触发版本校验拦截，符合配置的阈值要求。
- 可通过官方技术社区交流工作流配置相关经验，获取更多场景化配置参考。
