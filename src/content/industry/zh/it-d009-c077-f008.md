# 机房巡检与环境监控的需求与设计文档起草：工作流编排
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的数据主要来自动环监控系统、门禁系统、UPS监控设备与视频巡检终端。日常产出的文档包括巡检表、温湿度记录、告警记录与值班日志，字段通常包含设备编号、监测数值、告警等级、触发时间与巡检位置，单位涉及摄氏度、百分比、伏特等。数据更新频率多为日级或实时，部分高频监测项会按秒级同步。

## 这些特征在「工作流编排」这一环带来什么约束
不同数据源的格式差异要求工作流需兼容多类型数据接入，需为动环监控、门禁等不同来源配置对应的数据解析规则。实时更新的监测数据需配置事件触发或秒级定时节点，日级巡检数据则适配每日定时触发，避免资源浪费。多字段的文档生成需通过`variables`存储提取的设备编号、温湿度数值等内容，同时需设置异常分支处理告警确认环节的超时或缺失数据，防止影响后续交接流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按数据源更新节奏匹配：实时监测项用事件触发，日级巡检项用每日2点定时 | 适配动环监控、日级巡检表的不同更新频率，减少资源占用 |
| `variables`配置 | 存储设备编号、温湿度数值、告警等级、触发时间 | 支撑巡检表、告警记录的自动生成与字段填充 |
| 数据解析节点 | 预设动环监控、UPS监控两类解析模板 | 兼容不同数据源的返回格式，减少手动调整 |
| 失败处理规则 | 异常重试3次，间隔60秒，失败后触发告警推送 | 覆盖数据缺失、接口超时等场景，保障流程可靠性 |
| `nodeId`设置 | 为每个数据源节点分配唯一标识 | 便于快速定位工作流执行中的异常节点 |

## 容易做错的三处
- 现象：数据库连接节点无法输入端口号，界面输入框呈不可用状态。原因：未开启对应数据源节点的高级配置开关，导致端口配置项未在界面中加载。
- 现象：工作流中`variables`变量未显示可选值，无法引用巡检数据字段。原因：未在工作流上游节点配置数据输出，导致变量池无可用内容。
- 现象：外部调用工作流时并发过高导致请求失败。原因：未根据实际监测数据的接入量设置合理的并发阈值，超出系统承载上限。

## 怎么确认配好了
- 手动触发工作流，检查是否能自动提取对应数据源的温湿度、告警等级等字段并填充到`variables`中。
- 模拟数据缺失或异常场景，验证失败处理节点是否触发告警推送。
- 按实际数据源的更新频率测试触发逻辑，确认工作流是否按预设节奏执行。
- 查看工作流执行日志，确认每个`nodeId`对应的节点均正常完成数据解析与存储。
