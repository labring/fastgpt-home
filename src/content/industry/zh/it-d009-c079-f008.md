# 架构设计与技术方案的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自历史流量数据、服务拓扑、监控指标与业务增长计划，日常产出的文档包括技术方案、架构图、容量评估报告及技术评审纪要。不同于后端服务开发的代码与接口文档，该品类的文档核心聚焦跨服务边界定义与长期演进规划。数据更新频率通常为每月一次或伴随重大需求变更同步更新，文档通常包含约束条件、方案选型依据等核心内容，无统一强制格式但需覆盖项目全周期的架构规划需求。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据分散来自多类系统与业务文档，单份输入可能达到十万字或万行级体量，且更新节奏随业务需求波动。可通过`variables`配置节点间的数据流转，整合多源业务数据。工作流编排需适配多源数据的整合逻辑，支持大体积文档的分段处理与多轮交互，同时需关联评审节点完成意见闭环。此外，架构设计文档需明确跨服务边界与长期扩展规划，工作流节点需预留扩展字段以匹配不同项目的约束条件收集需求，确保方案的可落地性与可扩展性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 全局变量绑定 | 绑定`variables`为历史流量数据节点输出 | 自动拉取最新业务数据用于方案推导 |
| 节点ID关联 | 指定`nodeId`为评审纪要节点 | 自动关联评审意见闭环流程 |
| 分块长度 | 800–1200 字符 | 适配十万字Word文档的分段处理，避免单节点过载 |
| 单次处理行数上限 | 1000–1500 行 | 匹配万行Excel数据的处理边界，防止超时 |
| 上下文窗口大小 | 4000–8000 token | 支撑多轮对话的上下文留存需求 |
| 文件引用开关 | 关闭自动引用标识 | 移除生成技术方案中的冗余引用内容 |

## 容易做错的三处
- 现象：工作流处理十万字Word文档时出现超时中断。原因：未配置合理的分块长度，单节点输入数据超出处理阈值。
- 现象：工作流返回多轮问答的全部历史结果。原因：未设置结果输出规则为仅返回最后一次节点输出，默认保留了全量上下文。
- 现象：运行代码节点后无法查看打印日志。原因：未开启节点日志查看权限，或未配置日志输出到指定面板。

## 怎么确认配好了
- 上传测试用的大体积文档，验证工作流是否能正常完成分段处理与多轮对话。
- 触发工作流后，检查输出结果是否仅包含最后一次问答的内容。
- 查看生成的技术方案文档，确认无多余引用标记。
- 运行代码节点，通过对应面板查看打印日志，验证调试逻辑是否正常。
