# 桌面终端支持的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
桌面终端支持的日常数据来自终端管理平台、资产系统、用户报障入口、软件仓库。日常生成的文档包含终端故障单、装机清单、软件安装记录、远程协助记录，字段涵盖设备型号、软件版本、报障时间、故障等级、操作记录等，单位涉及台、次、天等。数据更新频率为每日或每一次服务请求，单条记录的token消耗随文档复杂度波动。

## 这些特征在「上下文与 token」这一环带来什么约束
桌面终端支持的数据源分散且更新频繁，单次会话的上下文可能包含多台设备的历史记录，需限制上下文总token量避免超出模型上限。日常文档字段多样，拼接后token消耗较快，需控制引用的知识库片段token数。故障排查场景对召回结果的准确性要求较高，上下文不足会导致排查逻辑缺失，上下文过量则会增加token成本与响应延迟。此外，高频更新的终端数据可能存在时效性差异，需定期清理过期上下文以保证准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 桌面终端支持的上下文多为单设备的故障、装机、远程记录，单会话token消耗适中，该区间可覆盖典型场景 |
| `quoteMaxToken` | `1200–1800 token` | 知识库切块通常为5000token，引用片段需控制在合理范围，适配桌面终端支持的故障排查场景 |
| 上下文历史保留条数 | 前8–12条对话 | 桌面终端支持的会话通常围绕单台设备的单类问题，过多历史会额外增加token消耗 |
| 上下文自动清理触发阈值 | 达到`maxContext`的75%时触发 | 避免token消耗超出预设上限，适配高频更新的终端数据 |
| 单次检索召回上限 | 前3–5条匹配结果 | 桌面终端支持的故障多有典型特征，过多召回会增加上下文token消耗 |

## 容易做错的三处
- 现象：配置`quoteMaxToken`为1500token后，仍出现检索到超出该阈值的知识库片段。原因：仅设置了最终引用的token上限，未对原始检索返回的切块内容进行提前截断，导致未处理的原始片段仍占用token。
- 现象：无法查看单次问答的token使用统计数据。原因：未启用全局token统计配置，或未在对应会话页面开启日志展示功能，部分版本需手动开启对应调试开关。
- 现象：会话上下文无法按设备或故障类型自动清空。原因：未配置上下文清理的关联字段，未将会话上下文与当前处理的设备标识绑定，导致无法识别清理触发条件。

## 怎么确认配好了
- 发起一次模拟桌面终端故障排查的问答，查看返回结果中引用的知识库片段长度是否符合`quoteMaxToken`的配置要求。
- 查看FastGPT v4.17.0的全局统计页面，确认每次问答的token消耗数据正常展示，无缺失或异常值。
- 手动构建超出`maxContext`阈值的会话上下文，检查是否自动触发清理逻辑，保留有效历史记录。
- 配置基于设备标识的上下文清理规则，发起跨设备的问答会话，验证符合条件的上下文是否被清空。
