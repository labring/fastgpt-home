# 桌面终端支持的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自终端管理平台、资产系统、用户报障渠道、软件仓库。日常产出的文档包含终端故障单、装机清单、软件安装记录、远程协助记录，字段包含终端序列号、故障现象描述、装机时间、软件版本号、远程协助时长等。数据更新频率为每日或随每一次请求触发更新。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散，覆盖终端管理、资产、报障等多个独立系统，因此多轮对话的`messages`需要按请求来源分类拼接，避免跨系统信息混乱。日常文档字段多且结构不统一，提示词需明确指定故障类型、终端序列号等核心字段的提取优先级。数据更新频率随请求触发，对话上下文需支持动态加载最新的终端资产与报障数据。非结构化的故障描述内容较多，提示词需引导模型按固定文档格式整理输出。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的功能逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定终端唯一序列号 | 确保每台终端的对话上下文独立，避免跨设备信息混淆 |
| `messages` | 保留最近10条对话+当前终端的最新3条资产数据 | 平衡上下文完整性与响应速度，适配终端场景的短对话需求 |
| 最大上下文长度 | 8000–12000 字符 | 覆盖终端故障排查、装机记录整理的常规内容长度，按实测标定 |
| `variables` | 注入当前终端的资产ID、报障时间戳 | 让模型实时获取最新的终端数据，适配按请求更新的数据源 |
| 提示词模板 | 固定包含「优先提取终端序列号」「故障步骤按时间排序」的指令 | 适配该品类的文档结构与核心业务需求 |
| 对话超时时间 | 60 秒 | 匹配桌面终端支持的日常响应时效，避免长时间等待影响工程师工作 |

## 容易做错的三处
-  流式输出未按预期分段，前端页面出现乱序内容。原因是未正确绑定`chatId`导致上下文串台，对话流未按终端唯一标识对齐。
-  工作流中AI对话输出直接展示在页面，无法通过后续组件处理。原因是未关闭自动输出开关，未配置`variables`指定输出回调节点。
-  对话日志标注功能无法关联对应终端文档。原因是未将标注字段与终端序列号绑定，导致标注信息与具体设备脱节。

## 怎么确认配好了
-  发起一条终端故障排查的测试请求，检查返回结果中是否包含当前终端的序列号与最新资产信息。
-  查看对话日志，确认每条对话的`chatId`与对应终端的唯一标识一致。
-  触发工作流中的AI对话节点，确认输出内容需经过指定组件处理后才展示在页面。
-  测试超时场景，确认请求在60秒内返回或触发超时提示。
