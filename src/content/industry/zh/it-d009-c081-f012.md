# 渗透测试服务的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
渗透测试服务的核心数据来自目标系统、公开漏洞库、自动化扫描器结果与手工验证记录，日常产出测试授权书、渗透测试报告、漏洞复现记录、整改建议四类文档。文档结构随项目差异较大，测试授权书包含授权范围、主体信息等字段，渗透测试报告含漏洞详情与评级，漏洞复现记录多为多步骤操作流程，整改建议则包含修复方案与优先级。数据更新频率以单个项目或重大版本迭代为周期。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于文档包含多列结构化表格（如网段记录表、漏洞详情表）与长段落操作步骤，分块需保留字段完整性，避免截断跨列或跨步骤的关联信息。不同项目的文档结构差异显著，无法仅依赖通用解析规则适配所有场景。单份文档可能包含多页扫描结果与手工验证细节，解析耗时存在波动，需合理设置超时阈值。若分块遗漏授权条款或漏洞评级字段，可能引发法律授权争议或漏洞验证遗漏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 渗透测试文档包含长段落复现步骤与多列表格，该区间可保留字段完整性同时避免检索冗余 |
| `chunkSplitter` | 按段落+标题拆分 | 渗透测试报告有明确的章节结构，按标题拆分可保留上下文关联 |
| `customPdfParse` | 启用 | 渗透测试文档多含格式复杂的表格与扫描器导出的结构化数据，启用后可提升解析准确率 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 单份渗透测试报告可能包含多页扫描结果，需足够超时时间避免解析中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 单份渗透测试报告的扫描结果可能占用较大存储空间，该阈值可覆盖常见项目文档大小 |
| `chunkSettingMode` | 手动配置 | 不同项目的文档结构差异较大，手动配置可适配具体场景 |

## 容易做错的三处
- 上传多列结构化文档（如网段记录表）时检索结果不全，现象为仅能匹配到前两列的内容，原因是默认Excel解析规则仅识别前两列数据，未开启自定义表格解析配置。
- 启用PDF增强解析时出现解析失败报错，现象为任务状态显示超时或参数错误，原因是未正确配置第三方解析API的调用密钥与地址。
- 解析后的布尔类型字段经组件处理后为空，现象为授权状态字段在条件判断环节丢失有效值，原因是分块时截断了包含该字段的完整上下文段落。

## 怎么确认配好了
- 上传单份典型渗透测试报告，查看解析后的分块列表，确认每个分块包含完整的漏洞复现步骤或授权条款。
- 上传包含多列的excel测试授权书，检查解析后的文本是否覆盖所有列的内容。
- 查看解析任务的运行日志，确认未触发`PARSE_FILE_TIMEOUT_SECONDS`对应的超时报错。
- 在FastGPT v4.17.0环境下，输入漏洞CVE编号进行检索，确认能匹配到包含该编号的完整分块内容。
