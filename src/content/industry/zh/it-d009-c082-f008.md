# 渠道归因与线索分发的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
该品类的核心数据来自广告平台、CRM系统、归因SDK与表单系统，更新频率多为日度或周度。日常产出的文档包括归因规则、线索分发表、渠道报表与异常核对单，文档字段通常包含渠道标识、转化事件ID、线索归属ID、转化金额、核验状态等，无统一固定格式，需匹配各业务系统的字段定义。数据体量随业务投放规模波动，核心围绕线索的来源追踪与归属分配展开。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散导致工作流需对接多类API，需配置多节点的数据源拉取逻辑；日/周度的更新频率要求工作流支持定时触发，避免频繁调用超出接口限额；文档字段无统一格式，需在工作流中添加字段映射节点，适配不同系统的字段命名差异；核心耗时环节的核验逻辑需嵌入工作流节点，自动完成渠道参数校验、重复线索去重与归属确认，减少人工介入。同时，需配置告警机制，避免渠道ROI失真、销售争议等问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源对接 | 按业务系统类型配置多节点，每个节点对应广告平台/CRM/归因SDK | 数据来源分散，需分别拉取各系统的专属数据 |
| 定时触发周期 | 日度（24:00）或周度（每周一00:00） | 匹配数据日/周度的更新节奏，适配业务报表生成周期 |
| 字段映射规则 | 预设3-5组通用映射模板，支持自定义修改 | 各系统字段命名无统一标准，需快速适配不同业务文档的格式 |
| `variables` 配置 | 存储渠道白名单、知识库ID等固定配置，单组`variables`大小不超过100 MB | 避免重复配置固定参数，降低工作流的冗余度 |
| 异常告警阈值 | 按业务场景标定 | 及时拦截渠道参数异常、重复线索占比过高等问题 |
| `nodeId` 配置 | 为每个业务节点分配唯一标识 | 便于后续工作流调试与异常定位 |

## 容易做错的三处
- 现象：调用工作流上传文件后，传入知识库返回参数错误提示。原因：未在`variables`中配置目标知识库的关联参数，或未正确映射文件上传的输出字段。
- 现象：工作流执行后重复线索占比超出预期。原因：未嵌入重复线索去重的校验节点，或字段映射时未关联线索的唯一标识字段。
- 现象：工作流定时触发后未拉取到广告平台数据。原因：未配置数据源节点的权限校验，或定时周期与广告平台的数据更新节奏不匹配。

## 怎么确认配好了
- 执行单节点测试，验证数据源节点能否正常拉取指定系统的测试数据。
- 手动触发工作流，检查字段映射节点是否将各系统的字段转换为统一格式。
- 配置测试告警规则，模拟异常场景，确认告警节点能否正常触发通知。
- 查看工作流的`nodeId`配置，确认每个节点的标识唯一，便于后续调试。
