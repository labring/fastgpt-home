# 游戏内容合规自查的需求与设计文档起草：工作流编排

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类的数据主要来自游戏研发阶段的剧情脚本、上线前及版本更新中的游戏文本、美术资源，同时参考监管公开的合规要求。日常产出的文档包括内容自查表、敏感内容修改记录、用户协议、合规评审纪要。数据更新随游戏版本或运营活动节奏推进，无固定周期，需随版本迭代、内容调整实时同步，覆盖文本、美术多类型合规检查所需的全部原始素材与输出记录。

## 这些特征在「工作流编排」这一环带来什么约束
游戏内容合规自查的文档多随版本更新迭代，工作流需支持按版本节点触发，避免跨版本数据混淆。数据来源包含文本、美术多模态内容，工作流需兼容多类型输入节点，分别处理文本合规校验与美术合规识别。合规文档需留存评审纪要与修改记录，工作流需配置自动归档环节，关联对应版本的自查数据。监管要求随监管动态调整，工作流需预留参数更新入口，适配不同阶段的合规标准变更，同时需支持多角色权限配置，保护合规文档的保密性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发条件 | 按版本号/活动ID触发 | 适配本品类按版本/活动更新数据的节奏，确保仅针对当前版本执行合规检查 |
| 节点流转规则 | 文本校验节点→美术校验节点→评审归档节点，绑定`nodeId`指定节点顺序 | 匹配本品类先文本后美术的合规检查顺序，明确各环节的执行链路 |
| `variables` | 绑定版本号、自查表ID、审核人ID | 关联对应版本的合规数据，避免跨版本混淆，同时记录审核相关信息 |
| 失败重试策略 | 重试2次，间隔60秒 | 应对临时接口波动或数据加载延迟，保障检查流程不中断 |
| 归档路径 | 按版本号分类存储 | 便于后续合规评审与数据追溯，快速定位对应版本的自查文档 |
| 权限控制 | 仅合规团队成员可编辑节点配置 | 保护合规文档的保密性，防止非授权人员修改检查规则 |

## 容易做错的三处
- 工作流中复用填写表单节点时，跨分支无法跳转至该节点。原因是未配置节点间的流转条件，仅允许固定链路调用节点。
- 调用工作流API返回空值。原因是未在`variables`中绑定必填的合规检查参数，导致流程无法触发执行。
- 配置变量引用时出现`quote type error`报错。原因是未将变量格式转换为符合节点要求的字符串类型，直接传入了非文本格式的参数。

## 怎么确认配好了
- 触发测试版本的工作流，检查各节点是否按预设的文本校验→美术校验→评审归档顺序执行。
- 调用工作流API，验证返回结果包含合规检查的核心字段，无空值情况。
- 尝试跨分支调用填写表单节点，确认链路可正常跳转至目标节点。
- 查看归档路径下的文件，确认已按版本号分类存储合规自查文档。
