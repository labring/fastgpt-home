# 游戏内容合规自查的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
本品类的数据主要来源于游戏文本、美术资源说明、剧情脚本及监管公开要求。日常使用的文档包括内容自查表、敏感内容修改记录、用户协议、合规评审纪要。文档结构多包含层级标题、表格字段与状态标记，如自查表含合规项、对应文本片段、修改状态字段，修改记录含操作时间、修改内容、审核人字段。数据更新频率为每版本或每活动一次。

## 这些特征在「文档解析与分块」这一环带来什么约束
品类内的文档类型多样，既有纯文本的剧情脚本，也有带表格的自查表与评审纪要，且单份文档长度跨度较大。频繁的版本更新要求解析流程具备高效性与稳定性，避免延误版本上线。文档中包含的关联字段（如合规项与对应文本片段）需要在分块时保留上下文关联，否则会导致合规检查逻辑断裂。部分监管文档格式不统一，需要解析工具适配多种排版样式，确保关键信息不丢失。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配游戏剧情脚本、合规自查表的单段文本长度，避免拆分破坏合规项与对应文本的关联 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配合规评审纪要、自查表的层级结构，保留不同合规项之间的上下文逻辑 |
| `customPdfParse` | 启用 | 适配美术资源说明、合规文档的PDF格式，保留原文档的表格排版与文本层级 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单版本批量提交的剧情脚本包、合规文档合集，满足批量自查需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配长文档解析的耗时需求，避免因超时中断解析流程 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（如表格类自查表、纯文本剧情）灵活调整分块规则 |

## 容易做错的三处
- 上传合规文档合集时返回413错误，原因是未调整`UPLOAD_FILE_MAX_SIZE`参数至适配的阈值。
- 导入csv格式的敏感内容修改记录时仅读取前两列，原因是未配置分块时的表格解析规则，默认仅提取前两列字段。
- 启用外部pdf-maker解析器后无法生效，原因是未在系统配置中正确设置对应解析器的密钥参数。

## 怎么确认配好了
- 上传单份合规自查表csv文件，检查解析后是否包含所有预设字段，无缺失或错位。
- 上传一份100MB以内的剧情脚本PDF，查看解析进度是否在600秒内完成，无超时报错。
- 进入分块配置页面，确认`chunkSize`取值与当前品类的文档长度匹配。
- 启用`customPdfParse`后，上传美术资源说明PDF，检查是否保留了原文档的表格排版与文本层级。
