# 游戏客户端性能优化的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
这个品类的数据主要来自引擎Profiler工具、崩溃上报平台、真机测试设备与帧率采集工具。日常产出的文档包含性能测试报告、机型适配清单、优化记录、崩溃分析报告，字段多包含帧率数值、资源占用占比、机型型号、复现场景、优化前后对比数据。数据更新频率为每日或每版本迭代周期，核心数据围绕游戏客户端的帧率、包体大小、资源加载时长展开，区别于通用移动端开发，更聚焦游戏专属的性能表现维度。

## 这些特征在「上下文与 token」这一环带来什么约束
游戏客户端性能优化的文档数据多为结构化的性能指标与场景化的复现记录，单条数据长度差异较大，从几行的帧率统计到数页的崩溃分析报告不等。每日或每版本的更新频率要求上下文召回需覆盖近期的优化记录与最新机型适配数据，避免引用过时的性能结论。同时，该品类的文档需关联特定机型与帧率阈值，上下文召回时需精准匹配机型、资源类型等字段，若上下文范围过大则会引入无关的历史优化数据，干扰当前需求的文档参考。此外，卡顿、闪退等出错后果关联直接的用户反馈，上下文召回需优先包含高优先级的崩溃分析与复现步骤文档。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `12000–18000 token` | 游戏客户端性能优化文档包含多份性能报告与机型数据，合理的上下文范围可覆盖1-2个版本的核心优化记录与测试数据，避免超出FastGPT v4.17.0的模型处理上限。 |
| `quoteMaxToken` | `2000–3000 字符` | 单份核心文档如崩溃分析报告或帧率测试数据的长度多在千字符级别，限定引用token长度可确保提取的内容精准匹配当前需求，避免冗余信息干扰。 |
| 上下文召回相似度阈值 | `0.75–0.85` | 该品类的文档多以性能指标为核心，需精准匹配机型、优化场景等字段，阈值过低会引入无关的历史优化数据，过高则可能遗漏相关的机型适配记录。 |
| 单次召回上限 | `前8条` | 日常性能优化的需求关联的文档多不超过5份，限定召回条数可减少模型处理的冗余数据，加快文档参考的生成效率。 |
| 上下文分块重叠长度 | `200–300 字符` | 性能测试报告多为分段的指标统计，重叠分块可确保完整提取帧率、资源占用等关键数据，避免分块截断导致的信息缺失。 |
| 召回文档排序规则 | 按更新时间倒序 | 性能优化数据的时效性较强，最新的机型适配清单与优化记录对当前需求的参考价值更高，优先召回近期更新的文档。 |

## 容易做错的三处
- 现象：模型生成的优化建议无法匹配当前机型的帧率要求。原因：上下文召回的相似度阈值设置过高，遗漏了对应机型的性能测试报告数据，导致参考文档不足。
- 现象：docker部署后上下文配置未生效，无法加载性能优化文档。原因：未在配置项中正确指定性能测试报告、崩溃分析报告的数据源目录，导致token关联的文档池为空。
- 现象：生成的需求文档包含过时的包体优化数据。原因：未按更新时间排序召回上下文，或`maxContext`设置过大，引入了多个版本前的优化记录，干扰当前需求的参考逻辑。

## 怎么确认配好了
- 手动导入一份近期的机型适配清单与性能测试报告，验证上下文召回是否能匹配到该文档。
- 触发一次需求起草流程，检查生成的参考文档是否包含当前版本的优化记录与真机测试数据。
- 查看FastGPT v4.17.0的配置日志，确认`maxContext`、`quoteMaxToken`的取值已按标定值加载。
- 模拟低端机的性能测试场景，验证召回的文档是否包含对应机型的适配要求。
