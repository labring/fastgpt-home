# 游戏客户端性能优化的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自引擎Profiler工具、崩溃上报平台、真机测试设备与帧率统计工具。日常产出的文档包含性能测试报告、机型适配清单、优化记录、崩溃分析报告，更新节奏为每日或每版本迭代。数据字段包含帧率数值、包体大小、资源加载耗时、崩溃堆栈信息等，单位多为fps、MB、毫秒，且需绑定对应机型与游戏版本标识。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源分散且格式差异大，要求工作流支持对接多类数据源节点，适配引擎Profiler、崩溃平台等不同工具的输出格式。更新频率为每日或每版本迭代，要求工作流可绑定版本触发或定时触发节点，适配项目迭代节奏。日常产出的文档结构不统一，要求工作流支持自定义解析模板，提取性能测试报告、优化记录中的关键信息。核心关注帧率、包体、资源加载等特定指标，要求工作流预设对应字段与单位的变量。出错后果直接影响商店评价，要求工作流配置异常告警节点，及时通知相关团队。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源接入 | 按引擎Profiler、崩溃平台、真机测试工具分别配置节点 | 该品类数据来源分散，需分别对接不同工具的输出接口 |
| 触发方式 | 版本发布前24小时 或 每日凌晨2点 | 数据更新频率为日/每版本，适配项目迭代节奏 |
| 文档解析模板 | 预设帧率、包体、资源加载耗时常量字段 | 该品类核心关注上述指标，需标准化提取关键信息 |
| 超时重试次数 | 3次 | 低端机复现环节耗时较长，需配置合理重试避免流程中断 |
| 异常告警触发 | 当帧率低于30fps、包体超出1000MB时触发 | 性能异常会直接导致卡顿、闪退，影响商店评价 |
| 变量配置 | 绑定机型、游戏版本标识，启用`variables`参数 | 性能数据需绑定对应环境，确保分析精准 |
| 节点ID配置 | 为每个流程节点分配唯一`nodeId` | 便于排查流程异常，快速定位问题节点 |

## 容易做错的三处
- 现象：工作流执行后输出的性能分析结果未包含帧率数据。原因：未在`variables`中绑定帧率字段的提取规则，导致解析环节遗漏核心指标。
- 现象：知识库搜索环节返回结果正常，但最终输出的研判结果未参考搜索到的性能文档。原因：未在工作流中配置上下文关联节点，导致LLM调用时未加载知识库检索结果。
- 现象：工作流触发后无任何执行日志，节点状态显示未导入配置。原因：未正确关联数据源节点与解析节点，流程链路断裂。

## 怎么确认配好了
- 核对工作流的数据源节点，确认已对接引擎Profiler、崩溃平台等对应工具的输出接口。
- 触发一次测试执行，检查解析后的文档是否提取了帧率、包体等核心指标。
- 模拟帧率低于30fps或包体超出1000MB的场景，确认异常告警节点可正常触发通知。
- 检查`variables`与`nodeId`配置，确认已绑定对应环境标识与唯一节点ID。
