# 游戏运营活动配置的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
游戏运营活动配置的核心数据来自游戏运营后台、玩家分群系统、付费数据平台与活动日志系统。日常产出的文档包含活动方案、奖励配置表、上线检查单与活动复盘报告，文档字段多包含活动ID、生效时段、奖励类型与数值、触发条件等，更新频率多为周度或节假日活动前的临时调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散导致对话需要跨系统拉取信息，需明确限定可调用的数据源范围；文档字段多且格式不统一，提示词需固定字段提取规则避免歧义；更新频率波动要求对话上下文支持临时调整的活动参数；奖励数值与时间配置的高风险属性，需要多轮校验环节确认参数合规性。同时，活动配置的文档需关联具体的活动ID与玩家分群数据，对话上下文需保留完整的讨论链路，防止关键配置信息丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定活动专属ID | 确保同一场活动的对话上下文不与其他活动混淆 |
| `messages` | 保留前10轮对话内容 | 覆盖单次活动配置的完整讨论周期，避免关键参数丢失 |
| `variables` | 限定调用运营后台、玩家分群两类数据源 | 限制对话可访问的数据范围，防止越权获取无关信息 |
| 上下文记忆上限 | 8000字符 | 适配活动配置多轮校验的沟通需求，避免上下文溢出 |
| 提示词模板 | 固定包含活动ID、生效时段、奖励字段的提取要求 | 统一文档生成的格式，减少字段遗漏 |

## 容易做错的三处
- 对话接口调用时返回字段为空，现象为生成的文档缺少奖励配置数值。原因是未正确绑定`variables`对应的数据源参数，导致无法拉取运营后台的奖励数据。
- 对话上下文丢失，现象为多轮配置时后续提问无法关联之前的活动ID。原因是未正确设置`chatId`，导致每次对话生成独立上下文。
- 提示词无法正确生成英文格式的文档，现象为生成的活动复盘报告出现中文字段名。原因是未将提示词适配英文业务场景的字段命名规则。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本的配置逻辑。
- 发起一次测试对话，输入活动ID与奖励配置需求，检查生成的文档是否包含完整的活动字段，验证`variables`参数配置正确。
- 发起两轮以上的连续对话，确认后续提问可以关联之前提及的活动参数，验证上下文记忆功能正常。
- 调用对话接口上传奖励配置表文件与活动截图，检查接口是否能正确解析文件内容并纳入对话上下文，验证文件上传配置生效。
- 切换提示词语言为英文，输入活动配置需求，检查生成的文档字段是否符合英文命名规则，验证中英文提示词配置生效。
