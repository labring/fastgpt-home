# 版本发布与Release Notes的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
该品类的核心数据来自Git标签、合并提交记录、CI制品、Issue里程碑，更新频率为每版本一次。日常产出的文档包括Release Notes、变更日志、版本标签说明、发布检查单，主体使用方为开源维护者、发布经理与文档维护者。文档结构通常包含版本号头部、变更分类条目、破坏性变更标记、制品校验信息等字段，无统一强制格式，但多以Markdown或纯文本形式产出。

## 这些特征在「文档解析与分块」这一环带来什么约束
首先，每版本一次的更新频率要求解析流程具备可重复性与准确性，避免因分块逻辑波动导致版本信息错位。其次，数据来源分散且格式多样，既包含结构化的Git提交日志，也包含非结构化的手动编写的变更说明，要求分块工具适配多种文本结构。另外，变更归类与破坏性变更说明是最耗时的环节，分块需按变更类型、版本节点拆分，便于后续归类整理，同时需避免跨版本的分块错误，防止引发社区误解或版本回滚问题。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 版本发布文档的单条变更条目通常为数百字符，该取值可保证单块包含完整的变更说明与关联信息 |
| `chunkSplitter` | 按Markdown标题拆分 | 版本发布文档多以版本号、变更分类作为标题层级，按标题拆分可保证每块对应独立的变更组 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | CI制品生成的日志文档通常较长，该取值可覆盖多数文档的解析耗时，避免中途超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 版本发布相关的制品包与日志文件通常不超过该阈值，可避免无效大文件占用解析资源 |
| `customPdfParse` | 开启 | 部分CI制品会导出为PDF格式的发布说明，开启自定义解析可准确提取文本与关联的制品信息 |
| `chunkSettingMode` | 手动配置 | 不同版本的发布文档格式存在差异，手动配置可灵活适配特定版本的文档结构 |

## 容易做错的三处
- 现象为点击复制提示“无法使用浏览器自动复制，请手动复制下面内容”，原因是解析后的文档文本未正确绑定同源页面上下文，导致浏览器复制权限校验失败。
- 现象为部分MCP服务无法正常解析，原因是配置的`chunkSplitter`未适配对应服务的日志输出格式，导致分块时丢失关键的服务标识信息。
- 现象为知识库中图片链接无法被问答调用，原因是分块时仅提取了文本内容，未同步保留图片链接与上下文的关联关系，导致嵌入时丢失关联信息。

## 怎么确认配好了
- 上传一份典型的版本发布文档，查看解析后的分块是否按版本号、变更分类进行拆分，确保每块包含完整的变更信息。
- 运行一次大体积的CI制品解析任务，确认解析过程未触发超时报错，验证`PARSE_FILE_TIMEOUT_SECONDS`的取值合理性。
- 触发复制功能，确认可正常将解析后的文本复制到剪贴板，验证同源上下文配置的正确性。
- 上传包含图片链接的发布文档，查看分块后的文本是否保留了图片链接与对应变更条目的关联关系。
