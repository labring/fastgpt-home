# 玩家客服与舆情处理的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
该品类的数据源主要包括客服系统、社区论坛、应用商店评论、游戏日志。数据更新节奏多为日更或实时同步。日常产出的文档包含玩家工单、补偿申请、舆情日报、标准化处理话术。数据字段通常包含唯一标识、玩家账号、反馈内容、关联游戏ID、处理进度等，无统一固定格式，随业务需求灵活调整，覆盖从用户反馈到处理结果的全流程信息。

## 这些特征在「工作流编排」这一环带来什么约束
多源实时数据要求工作流支持实时触发与多数据源接入，避免数据延迟导致处理不及时。多样的文档结构要求工作流通过`variables`绑定不同业务字段，适配工单、舆情等不同类型的输入。账号核验、补偿规则判断等耗时环节，要求配置分支判断节点分流反馈。出错可能导致玩家流失的风险，要求设置失败处理与告警节点。节点数量较多时，需适配FastGPT v4.17.0的性能优化标准，避免界面卡顿。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| :--- | :--- | :--- |
| `variables` | 绑定工单ID、玩家账号、反馈类型字段 | 匹配玩家客服与舆情处理的核心业务字段，便于流程中精准调用关联数据 |
| `nodeId` | 为每个工作流节点分配唯一标识 | 便于工作流调试、异常节点定位与流程回溯 |
| 单次触发节点数 | 不超过15个 | 适配FastGPT v4.17.0的性能优化标准，避免节点过多导致界面卡顿 |
| 上下文窗口 | 前1000–1500字符 | 覆盖单条工单或舆情的完整内容，保证账号核验、补偿判断的依据充分 |
| 超时设置 | 600秒 | 匹配账号核验、补偿规则判断的平均耗时上限，避免流程无响应 |
| 失败重试次数 | 最多2次 | 避免重复触发导致玩家重复收到回复，降低不必要的打扰 |

## 容易做错的三处
- 现象：工作流节点拖动时卡顿，操作延迟数秒才响应。原因：使用FastGPT v4.6.5等旧版本，未升级到v4.17.0的性能优化版本，且工作流节点数量超过15个。
- 现象：工作流无法导出为本地文件。原因：未在工作流设置中开启导出权限开关，或当前使用的版本未支持该功能。
- 现象：搜索舆情结果未结合玩家工单上下文。原因：未通过`variables`绑定工单的上下文字段，或上下文窗口配置的字符数不足，无法覆盖完整反馈内容。

## 怎么确认配好了
- 打开工作流画布，拖动节点测试响应速度，确认无明显卡顿。
- 进入工作流设置页面，检查导出权限是否已开启。
- 触发一条测试工单，查看流程中调用的上下文是否包含完整的玩家反馈内容。
- 检查`nodeId`配置，确认每个节点的标识唯一且可在系统日志中定位。
