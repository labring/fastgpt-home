# 用户增长与留存运营的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自用户行为日志、推送系统、实验平台与CRM系统，更新频率多为日度或周度。日常产出的文档包含增长实验方案、用户分层表、触达文案、留存分析报告，文档字段通常包含用户分群标签、触达渠道、实验变量、留存率指标，单位多为人次、百分比、触达次数等，需结合运营周期匹配数据更新节奏。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新节奏不一，要求多轮对话需支持跨系统数据拉取的上下文衔接；文档类型多样，提示词需适配不同文档的字段格式与业务逻辑；用户分群、触达设计等耗时环节依赖多轮迭代，需配置稳定的上下文记忆机制；实验结果归因需关联多维度数据，提示词需明确字段提取规则，避免混淆不同来源的数据指标。

## 配置怎么定
本文适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` 上下文拼接规则 | 按用户分层标签、触达渠道、实验结果的顺序排列，保留最近7条历史消息 | 适配周度更新的运营文档结构，便于提取核心业务字段 |
| `variables` 绑定范围 | 绑定用户行为日志、CRM系统的用户ID与触达次数字段 | 覆盖该品类的数据来源，实现跨系统数据关联 |
| `chatId` 绑定规则 | 绑定单个增长实验的会话标识 | 隔离不同实验的对话上下文，避免数据混淆 |
| 最大上下文窗口 | 前10轮对话 + 最近3天的历史数据 | 按实测标定，覆盖用户分群、触达设计的多轮迭代需求 |
| 提示词字段限定 | 仅提取用户分群、留存率、触达次数字段 | 匹配日常文档的核心字段，减少无效信息干扰 |

## 容易做错的三处
- 对话界面提示未选择知识库，但调试预览正常。原因是会话未正确绑定`chatId`对应的数据源配置，导致运行时无法匹配预设的知识库关联规则。
- 多轮对话后出现上下文混淆，不同实验的用户数据被混合提取。原因是未按实验维度绑定`chatId`，导致不同会话的上下文未做隔离处理。
- 提示词提取的字段与业务文档不符，出现无关指标。原因是未限定提示词的字段提取范围，导致模型抓取非核心业务数据。

## 怎么确认配好了
- 输入一个已有的用户分层表字段，核对多轮对话返回的内容是否包含该字段。
- 切换不同的`chatId`，确认不同实验的对话上下文不会互相干扰。
- 查看调试预览与正式运行的结果，确认知识库或数据源的匹配状态一致。
- 检查变量绑定的字段是否与业务文档的核心字段一致，避免提取无效数据。
