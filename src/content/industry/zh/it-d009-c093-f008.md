# 用户增长与留存运营的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
该品类的数据通常来自用户行为日志、推送系统、实验平台与CRM系统。日常产出的文档包括增长实验方案、用户分层表、触达文案与留存分析报告。数据更新频率多为日度或周度，用户分层表包含用户ID、触达频次、留存周期等字段，触达文案需适配不同用户群体的标签参数，留存分析报告则按周度汇总核心指标数据。

## 这些特征在「工作流编排」这一环带来什么约束
多源且节奏不一的数据来源，要求工作流需适配不同数据源的同步周期，避免因数据滞后导致分群结果偏差。多样的文档类型与动态字段需求，要求工作流需支持绑定自定义变量以适配不同运营场景。用户分群、触达节奏设计与实验结果归因是最耗时的环节，要求工作流可将这些环节拆分为独立可复用节点。出错后可能引发用户反感与预算浪费，要求工作流需配置前置校验与异常捕获环节。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| 知识库引用范围 | 全量可访问 | 支持用户自由访问现有任意文件，满足精准提取需求 |
| `variables` | 绑定用户分层标签、触达周期变量 | 适配运营文档的动态字段，实现个性化触达 |
| 单次搜索上限 | 前8条 | 平衡召回内容的精度与上下文长度，避免超出处理阈值 |
| 引用内容模板 | 保留原文核心句，去除冗余标注 | 精简可用内容，适配触达文案的篇幅限制 |
| `nodeId` | 绑定实验节点与归因节点ID | 关联工作流环节与实验数据，便于后续归因分析 |
| 最大上下文长度 | 8000字符 | 适配留存分析报告的常规篇幅，避免内容截断 |

## 容易做错的三处
- 现象：工作流调试时的知识库召回结果与前端实际测试结果不一致。原因：调试时未绑定场景专属的变量过滤规则，前端测试带入了实际运行的用户分层参数。
- 现象：免登录链接中自定义变量未显示。原因：工作流中未将变量配置为公开可传递参数，仅在调试环境启用。
- 现象：AI对话节点返回的引用内容与配置的模板不符。原因：混淆了引用内容模板与引用模板提示词的配置逻辑，前者用于格式化召回的原始内容，后者用于引导AI整合内容。

## 怎么确认配好了
- 手动生成免登录链接，检查自定义变量是否在链接参数中正常传递并在前端页面显示。
- 切换不同的用户分层标签，验证知识库召回的内容是否匹配对应标签的文件范围。
- 对比AI对话节点的调试输出与前端实际调用的返回内容，确认引用模板的格式一致。
- 查看工作流节点的状态日志，确认`nodeId`绑定的环节未出现执行超时或数据丢失。
