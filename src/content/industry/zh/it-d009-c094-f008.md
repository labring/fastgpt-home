# 用户验收测试支持的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
这个品类的数据围绕用户验收测试支持的全流程生成，核心文档包括UAT用例、验收问题单、验收报告、签字确认单。数据来源为需求规格文档、测试环境配置、客户业务样例数据及缺陷管理系统。数据更新以项目阶段或版本为周期，每个阶段会同步更新用例覆盖范围、问题记录及验收结论。文档字段包含测试场景、预期结果、缺陷等级、验收状态等，所有数据需经客户业务代表确认后生效。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据特征对工作流编排带来多重约束。首先，数据需经客户业务代表确认，因此工作流需配置人工审批节点，在验收结论生成后触发客户确认环节。其次，数据来源包含测试环境与缺陷系统，工作流需对接多数据源拉取节点，同步测试结果与缺陷记录。再者，数据更新以阶段为周期，工作流需绑定阶段触发规则，避免跨阶段数据混乱。另外，文档字段固定，工作流的输出节点需匹配UAT用例、验收单的标准字段，防止数据格式不兼容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源关联配置 | 绑定需求规格、测试环境、缺陷系统3个数据源 | 覆盖该品类全量数据来源，保证用例与问题数据同步 |
| 阶段触发规则 | 按项目迭代阶段触发 | 匹配数据按阶段更新的节奏，避免跨阶段数据混乱 |
| 人工审批超时 | 72小时 | 保障客户有充足时间确认验收结论，超时自动触发异常告警 |
| `variables` 配置 | 绑定UAT用例标准字段（测试场景、预期结果） | 确保工作流输出文档符合品类固定字段要求 |
| `nodeId` 配置 | 为每个阶段的UAT用例节点分配唯一标识 | 便于跨阶段追溯数据流转与变更记录 |

## 容易做错的三处
- 工作流中添加自定义UAT支持插件后，无输入输出参数显示且无报错日志。原因：未正确配置`variables`绑定UAT文档的标准字段，导致插件无法识别参数结构。
- 工作流触发后弹出未捕获的异常提示。原因：私有部署场景下未正确配置数据源节点的连接参数，导致无法拉取缺陷系统或测试环境数据。
- 工作流循环处理UAT用例数组时，循环体无法正确读取数组元素。原因：未为循环节点配置与`nodeId`匹配的关联规则，导致元素映射关系错误。

## 怎么确认配好了
本页面内容适配FastGPT v4.17.0版本。
- 核对数据源节点是否已关联需求规格、测试环境、缺陷系统三类数据源，确认数据拉取路径正确。
- 检查`variables`配置是否绑定了UAT用例的标准字段，确保输出文档格式符合品类要求。
- 验证人工审批节点的触发逻辑，确认在验收结论生成后会自动推送至客户确认环节。
- 测试循环节点的参数映射，确认数组元素可被循环体正确读取。
