# 监控告警配置的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
该品类的数据来自运维工程师、SRE团队日常产出的监控相关文档，包括监控指标清单、告警规则、值班手册、告警变更记录。数据来源多为Prometheus、Zabbix、云监控、应用日志及CMDB系统，更新频率为每日或每次告警配置变更后。单份文档通常包含指标名称、阈值区间、告警级别、通知对象、触发条件等字段，单位涵盖百分比、毫秒、告警条数等，不同来源的文档格式存在细微差异。

## 这些特征在「上下文与 token」这一环带来什么约束
多源异构的数据来源要求上下文需整合不同格式的监控文档，因此输入token的总长度需适配多源数据的总容量，避免关键信息被截断。高频更新的业务数据要求上下文需定期同步最新的告警配置与变更记录，否则起草的文档会与实际运维配置脱节。单份文档的字段复杂度较高，上下文需保留完整的阈值、级别等核心字段，因此token分配需优先保障核心信息加载。告警配置的准确性直接影响运维故障发现效率，上下文的token截断或缺失会直接导致配置文档的有效性受损。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖单份告警配置文档集的平均内容量，适配多源监控数据的整合需求 |
| `quoteMaxToken` | 1500 token | 限制单条历史告警变更记录的引用长度，避免冗余数据占用过多token |
| 上下文同步周期 | 每日 | 匹配业务数据的日更新频率，保障配置文档的时效性 |
| 全局token注入配置 | 按应用绑定 | 传递专属的监控平台API标识，支持跨应用的上下文隔离 |

## 容易做错的三处
- 接口请求返回401未授权错误，排查项：检查服务端环境变量中的AIPROXY_API_ENDPOINT（AI Proxy服务根地址）与AIPROXY_API_TOKEN（AI Proxy管理员Token）是否正确配置，未配置会导致服务启动校验失败或该错误。
- 生成的告警配置文档出现阈值字段缺失，原因是`maxContext`参数配置过小，导致关键阈值信息被token截断。
- 单轮上下文拉取请求超时，原因是未限制`quoteMaxToken`参数，引入过多历史告警噪声数据，超出模型输入token上限。

## 怎么确认配好了
- 检查服务端部署的环境变量，确认已配置AIPROXY_API_ENDPOINT（AI Proxy服务根地址，格式如http://aiproxy:3000）和非空的AIPROXY_API_TOKEN（AI Proxy管理员Token，与AI Proxy服务端配置一致）。
- 上传一份测试用的告警规则文档，触发上下文拉取操作，检查返回内容包含完整的指标名称、阈值区间与告警级别字段。
- 提交一次模拟的告警配置变更，验证上下文同步周期触发后，新的变更记录已被纳入上下文范围。
- 调整`maxContext`参数至较小值，检查是否出现关键字段截断的提示，确认参数生效逻辑正常。
