# 等级保护测评咨询的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
本品类数据主要来自等保测评机构、安全咨询公司的日常业务产出，核心文档包括定级报告、差距分析报告、整改方案、测评报告四类，数据采集自测评工具、访谈记录、系统清单与安全设备日志。数据更新以单个项目为周期，单个项目周期内完成一次完整更新。文档结构围绕等保标准的控制项展开，包含控制项编号、现状描述、整改要求、证据清单等字段。

## 这些特征在「上下文与 token」这一环带来什么约束
核心文档多为结构化与半结构化混合内容，单份项目文档长度差异较大，会导致上下文窗口占用波动。按项目更新的数据需要在每次测评周期内完成同步，若未合理控制召回范围，会引入无关历史项目数据，增加token消耗。控制项相关字段的精准召回需求，要求上下文仅保留当前项目的有效数据，避免跨项目数据干扰。同时，定级材料梳理、控制项差距核对等高频工作会产生高频的上下文调用需求，需平衡召回精度与token占用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配单份等保项目文档的平均长度，避免单次调用超出模型上下文上限，适配FastGPT v4.17.0的上下文处理逻辑 |
| `quoteMaxToken` | 1500–2000 字符 | 限定单条召回文档的token占用，防止单条数据过度消耗上下文，符合等保文档的单控制项内容长度范围 |
| 单次搜索上限 | 前8条 | 控制单次召回的总数据量，避免引入过多非核心的控制项材料，减少无效token消耗 |
| 上下文过滤阈值 | 0.75–0.85 | 过滤与当前需求关联度较低的历史项目数据，确保上下文仅包含当前测评项目的有效内容，适配控制项差距核对的精准需求 |
| 重排开关 | 开启 | 优先召回与控制项核对、整改证据收集相关的高关联数据，优化上下文的整体质量 |

## 容易做错的三处
- 对话后返回token消耗异常偏高的日志，原因是未设置上下文过滤阈值，召回了多个历史项目的无关文档，导致上下文总token超出预期。
- 模型输出被截断，无法完整生成整改方案内容，原因是`maxContext`设置值低于当前上下文与生成需求的总token占用，未预留足够的生成token空间。
- 召回结果仅包含系统清单字段，缺少控制项现状描述，原因是单次搜索上限设置过低，未召回足够数量的关联文档，无法覆盖完整的测评材料。

## 怎么确认配好了
- 导入单份完整的等保项目文档，触发一次上下文召回，查看召回结果是否仅包含当前项目的相关材料，无跨项目数据。
- 调整`maxContext`配置后，查看单条召回文本的token占用是否符合预期，可通过FastGPT的内置token统计工具验证。
- 模拟一次需求起草的完整流程，查看模型输出的长度是否满足文档生成需求，无无故截断情况。
- 多次触发上下文调用，查看token消耗日志是否符合预设的配置范围，无异常偏高或偏低的情况。
