# 等级保护测评咨询的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主体为等保测评机构、安全咨询公司及企业安全负责人的工作产出与输入。日常文档包含定级报告、差距分析报告、整改方案、测评报告四类结构化文件。数据来源涵盖测评工具导出数据、项目访谈记录、系统清单、安全设备日志。数据更新以单个项目为周期，每年或每个测评项目完成一次全量更新。核心耗时环节涉及定级材料梳理、控制项差距核对、整改证据收集，数据需严格匹配等保标准的控制项要求。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源多样且结构分散，要求多轮对话需整合测评工具、访谈、日志等多类数据源，提示词需明确指定每类数据的提取规则。文档结构固定为四类报告，提示词需锚定对应报告的字段要求，避免生成不符合格式的内容。数据更新以项目为周期，多轮对话的上下文需限定在单个项目内，不能跨项目复用数据。核心耗时环节的梳理、核对工作，要求多轮对话需聚焦控制项匹配、证据收集等具体任务，减少无关信息的召回。

本文基于FastGPT v4.17.0版本进行以下配置说明。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配定级报告、差距分析报告的常规段落长度，确保控制项描述与文档内容完整匹配 |
| 重叠长度 | 100–200 字符 | 避免控制项描述被分块截断，保证多轮对话中可完整召回相关控制项内容 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非等保相关数据，确保召回的测评工具、日志数据符合项目要求 |
| 单次搜索上限 | 前 10 条 | 控制召回数据的体量，避免超出多轮对话的上下文承载上限 |
| 最大上下文 | 4000 token | 适配单项目的多轮对话交互长度，确保可完整存储单个项目的定级材料梳理过程 |
| 问题优化 | 按实测标定 | 针对等保文档的结构化要求，优化提示词以匹配四类报告的输出格式 |

## 容易做错的三处
- 对话详情页无应用内部交互记录。原因：未启用`chatId`关联的会话日志存储配置，导致多轮对话的上下文未被持久化记录。
- 本地部署后知识库训练数据处理为空。原因：分块长度设置超出文档实际段落长度，或未正确绑定`variables`参数关联的系统清单、安全设备日志数据源。
- http请求调用知识库返回内容格式混乱。原因：未配置问题优化环节，提示词未明确要求输出符合等保测评文档的结构化内容，导致召回的信息未匹配报告格式要求。

## 怎么确认配好了
- 发起一轮针对定级报告字段的多轮对话，核对详情页是否完整展示`messages`参数的交互日志。
- 上传一份系统清单文档完成训练，确认数据处理环节生成有效分块内容。
- 发送http请求调用对话接口，验证返回内容匹配等保测评文档的结构要求。
- 调整相关配置项后进行多轮测试，确认召回的数据源符合当前项目的需求。
