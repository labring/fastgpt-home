# 等级保护测评咨询的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
等级保护测评咨询的日常文档包含定级报告、差距分析报告、整改方案、测评报告四类，数据来源涵盖测评工具输出、访谈记录、系统清单、安全设备日志。数据更新以单个项目为周期，单项目周期内完成全部文档的迭代。文档结构围绕等保测评标准的控制项展开，包含控制项编号、合规要求、现状描述、整改措施等固定字段，无统一的单份文档长度上限。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的多源数据、多文档类型与项目级更新频率，要求工作流需支持按项目维度隔离配置，避免不同项目的参数混淆。四类固定结构的文档需对应独立的处理节点，确保控制项字段的精准提取。多源数据的整合需求，要求工作流包含跨数据源的聚合节点，定级材料梳理与控制项差距核对等耗时环节需内置自动化校验步骤，降低人工核对的出错风险。同时，测评不通过的严重后果，要求工作流需添加前置校验节点，提前排查文档缺失或字段错误的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 前12000 token | 等保单份文档最长约3000字符，4类文档总长度适配该取值，避免上下文截断 |
| 单次搜索上限 | 前8条 | 常规等保项目的控制项数量约为6-10项，8条可覆盖全部测评项的匹配需求 |
| `variables` | 绑定项目编号、测评等级字段 | 每项目独立更新，需传递项目专属参数以确保文档处理的针对性 |
| `nodeId` | 按文档类型绑定对应处理节点 | 四类文档需分别触发匹配的字段提取与校验流程，避免节点混淆 |
| 问题优化 | 开启 | 需将通用搜索问题转化为等保标准术语，提升与控制项内容的匹配精度 |
| 响应超时阈值 | 600秒 | 适配多源数据聚合的处理时长，避免因数据量过大导致工作流中断 |

## 容易做错的三处
- 现象：工作流节点拖动时卡顿超过3秒，保存后状态异常。原因：未升级至FastGPT v4.17.0，旧版本节点渲染逻辑未优化，多文档节点加载时占用资源过高。
- 现象：搜索结果未结合项目上下文，仅返回零散的测评项内容。原因：未配置`variables`绑定项目专属的系统清单或访谈记录数据，搜索query未关联项目背景。
- 现象：部分模型执行工作流节点时返回无效内容，无法触发后续步骤。原因：未配置兼容非function call模型的 fallback 节点，直接使用了仅支持function call的节点类型。

## 怎么确认配好了
- 打开工作流画布，拖动任意节点，观察响应时间，确认符合当前版本的性能表现。
- 上传一份定级报告与系统清单作为测试数据，触发搜索节点，检查返回结果是否关联了项目专属的参数内容。
- 尝试导出当前工作流配置，确认弹窗正常弹出且无参数缺失提示。
- 关闭模型的思考输出开关，执行工作流节点，检查返回结果中未出现`<think>`标签包裹的内容。
