# 等级保护测评咨询的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
等级保护测评咨询的核心数据来自单个等保测评项目产出的文档与配套原始材料，日常使用的固定文档包括定级报告、差距分析报告、整改方案、测评报告四类。数据来源涵盖测评工具导出的系统清单、访谈记录、安全设备日志等，更新以单个项目为周期，项目周期内按需补充整改证据与最新测评结果。文档结构包含标准化的控制项条目、风险描述、整改要求等固定字段，不同来源的数据格式差异较大，既有结构化的表格类报告，也有非结构化的访谈记录与日志文本。

## 这些特征在「文档解析与分块」这一环带来什么约束
等保测评咨询的文档类型多样且结构固定，要求解析环节保留控制项、风险描述等核心字段的完整性，避免拆分导致信息断裂。数据来源包含工具导出的结构化表格与非结构化日志，需适配不同格式的解析规则。项目周期型的更新节奏要求解析流程可快速适配单项目下多份文档的批量处理，且需避免因解析错误导致后续测评环节延误。同时，测评结果直接关联监管检查风险，解析环节需确保核心业务字段无遗漏，避免因分块错误导致后续核对环节出现偏差。

## 配置怎么定
基于FastGPT v4.17.0版本的功能逻辑，以下配置项可适配等保测评咨询的文档解析与分块需求：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配等保报告的标准段落长度，避免拆分单个控制项的完整描述内容 |
| `chunkSplitter` | 按段落+标题拆分 | 保留文档的层级结构，便于后续控制项差距核对与整改方案匹配 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大型测评报告的完整解析耗时，避免因单文件过大导致解析超时中断 |
| `customPdfParse` | 开启 | 针对PDF格式的定级报告与测评报告，保留文本排版与字段定位，避免结构化内容丢失 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单项目下多份文档批量上传的最大单文件限制，适配大型整改方案文档 |
| `chunkSettingMode` | 手动配置 | 针对系统清单、安全日志等不同格式的数据源，灵活调整分块规则，适配等保数据的多样性 |

## 容易做错的三处
- 现象为将Java接口文档重命名为TXT格式上传后，解析结果为空或无有效接口安全配置内容；原因是TXT格式默认解析逻辑未识别代码注释与接口定义结构，无法提取等保测评所需的核心字段。
- 现象为使用chunk模式调用pushdata API上传文档后，长期处于索引中状态；原因是`chunkSize`设置过大或`PARSE_FILE_TIMEOUT_SECONDS`取值不足，导致解析流程未在规定时间内完成。
- 现象为上传包含图片的PDF测评报告后，图片与内嵌表格内容未被解析；原因是未开启`customPdfParse`配置，默认PDF解析逻辑仅提取纯文本内容，忽略非文本元素。

## 怎么确认配好了
- 上传单份定级报告，检查解析后的文本是否包含控制项编号与描述字段，核对核心业务字段的完整性。
- 查看解析任务的运行日志，确认无超时报错，验证任务耗时符合预期配置。
- 测试HTML格式的Javadoc接口文档上传，确认解析结果包含接口参数与安全相关说明，无内容丢失。
- 调整`chunkSplitter`配置后，验证分块结果是否保留文档的标题层级，无跨段落拆分的控制项内容。
