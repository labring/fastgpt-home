# 续费健康度管理的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
该品类的数据主要来自CRM系统、产品使用数据、工单统计台账与合同档案。日常产出的文档包含客户健康度报告、续费预测表、风险客户清单及跨部门沟通纪要。数据更新节奏以周度或月度为主，单份文档通常包含多维度客户指标字段，如客户标识、健康度评分、风险等级、合同到期节点等，无固定统一的单文档长度限制。

## 这些特征在「上下文与 token」这一环带来什么约束
多源异构的数据来源带来字段格式差异，需确保上下文召回时能匹配不同类型的客户数据字段。周度或月度的更新节奏降低了实时token刷新的必要性，但需支持历史数据的增量token更新同步。文档包含结构化表格与非结构化纪要两类内容，长文本的续费预测表与短文本的风险标注需适配差异化的token拆分规则，避免关键指标被截断或拆分混乱。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文召回数 | 前6条客户相关记录 | 适配续费健康度管理的单批次数据量，避免上下文过载 |
| `quoteMaxToken` | 1200–1500 token | 匹配续费预测表的平均文本长度，避免关键预测数据被截断 |
| 分块长度 | 800–1000 字符 | 适配沟通纪要与健康度报告的常规段落长度，兼顾拆分精度与召回效率 |
| `maxContext` | 按实测标定 | 适配多源数据的总token占用，避免超出模型上下文窗口 |
| 强制保留字段 | 客户ID、合同到期日 | 确保核心业务字段不被拆分或遗漏，匹配续费管理的核心业务逻辑 |

## 容易做错的三处
- 出现核心业务字段被拆分截断的现象，原因是未针对续费预测表的结构化内容设置强制保留字段规则，导致关键指标被拆分至不同块中。
- 配置`maxContext`时取值过大导致上下文溢出报错，原因是未结合单批次召回的客户记录总token量调整参数，超出模型支持的上下文窗口。
- 统一使用单一分块长度参数处理所有文档类型，导致沟通纪要的关键对话被错误拆分，原因是未区分结构化表格与非结构化文本的分块适配规则。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的平台中，上传一份标准的续费预测表，检查全文本token字段是否完整保留核心预测指标，无截断或拆分混乱。
- 查看`maxContext`参数的配置值，结合单批次召回的客户记录数，确认总token占用未超出模型窗口限制。
- 测试强制保留字段的配置，验证风险客户清单中的客户ID、风险等级字段未被拆分至不同召回块中。
- 针对沟通纪要调整分块长度参数，上传单份纪要文档，确认单段落内容未被强制拆分。
