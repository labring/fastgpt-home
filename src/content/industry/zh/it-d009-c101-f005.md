# 续费健康度管理的需求与设计文档起草：多轮对话与提示词

以下配置基于FastGPT v4.17.0版本说明。

## 这个品类的数据长什么样
续费健康度管理的核心数据来自CRM系统、产品端用户行为数据、工单统计台账与合同备案信息。日常产出的文档包含客户健康度报告、续费预测表、风险客户清单与跨周期沟通纪要，数据更新以周度或月度为周期。文档字段包含客户ID、合同到期节点、近周期活跃时长、风险等级标签、历史沟通记录等，无统一固定单位，随单条数据的业务属性调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
续费健康度管理的多源数据来源、周期性更新节奏与多类文档结构，对多轮对话与提示词配置带来多重约束。多源数据的格式差异要求多轮对话需统一字段映射规则，避免跨系统数据混淆。周/月级的更新节奏限制了提示词需适配周期性数据的刷新节点，不宜要求实时动态响应。多类文档的差异化字段要求对话需明确上下文所属文档类型，防止跨文档数据串用。同时，风险归类与数据解读的高耗时属性，要求多轮对话需支持分步引导拆解任务，且需通过`variables`传递固定的业务参数模板。此外，需确保会话上下文的持久化绑定，避免多轮问答中历史对话丢失，适配实际工作流中的连续咨询需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定客户唯一标识的字符串，如`crm_{customerId}` | 确保同客户的多轮对话上下文不跨会话共享，适配续费健康度管理的客户专属数据需求 |
| `messages` | 保留最近15–20轮对话内容 | 适配周度/月度数据更新的节奏，避免上下文过长导致响应延迟，覆盖连续的风险分析需求 |
| `variables` | 预设客户健康度、风险等级、合同到期日三类业务变量 | 通过标准化参数传递，减少重复输入，提升多轮对话的一致性 |
| 会话上下文最大长度 | 8000–10000 token | 适配多类业务文档的字段总量，避免上下文溢出导致的信息丢失 |
| 多轮问答触发规则 | 按`chatId`绑定会话触发 | 确保同客户的连续咨询使用同一上下文，符合续费健康度管理的场景要求 |
| 提示词模板更新节奏 | 周度同步数据更新周期 | 适配周/月度的数据刷新频率，确保提示词匹配当前业务文档结构 |

## 容易做错的三处
- 现象：多轮对话中历史对话内容丢失，后续提问无法关联之前的客户风险等级信息。原因：未正确绑定`chatId`，导致每次对话生成新的会话上下文，无法复用历史信息。
- 现象：工作流中多个AI对话节点的回复全部展示在最终聊天界面，冗余信息过多。原因：未配置节点输出的上下文过滤规则，导致所有中间节点的内容被纳入`messages`上下文。
- 现象：提示词调用`variables`时出现字段为空的报错。原因：未提前在`variables`中配置对应业务字段的默认值，导致部分客户数据未同步到会话中。

## 怎么确认配好了
- 发起一次模拟客户咨询，连续提问两个关联问题，检查上下文是否保留之前的客户风险等级信息。
- 配置包含多个AI对话节点的测试工作流，发起对话后查看最终聊天界面，确认仅保留必要的输出内容。
- 调用`variables`传递预设的业务参数，检查提示词是否能正确读取并使用该参数生成内容。
- 查看会话日志，确认每次对话的`chatId`与客户唯一标识一致，无跨会话的上下文串用。
