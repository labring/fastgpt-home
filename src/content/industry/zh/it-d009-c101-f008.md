# 续费健康度管理的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
续费健康度管理的核心数据来自CRM系统、产品使用日志、客户工单统计、合同台账四类来源，更新周期通常为周或月。日常产出的文档包含客户健康度报告、续费预测表、风险客户清单、客户沟通纪要四类，文档字段包含客户唯一标识、合同到期日、近周期活跃天数、有效工单量、续费金额阈值等，无统一强制单位，字段随客户合同条款略有调整。

## 这些特征在「工作流编排」这一环带来什么约束
多数据源的特性要求工作流需统一管理不同来源的字段映射，避免数据混淆。周/月级的更新频率要求工作流触发周期需匹配数据更新节奏，不宜设置过短的触发间隔。固定文档结构的特性要求工作流节点需对应文档的固定字段，无法灵活适配非标准化字段。最耗时的解读与归类环节要求工作流需自动化字段筛选与风险标记步骤，减少人工操作。出错后果直接关联客户留存，要求工作流需配置完整的失败处理与重试机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定CRM、产品使用数据、工单统计的专属字段映射 | 品类数据来源多样，需统一管理跨源字段 |
| 触发时机 | 按周/月周期触发 | 匹配数据周/月的更新频率 |
| `nodeId` | 绑定风险客户清单、续费预测表的专属节点ID | 对应品类核心产出文档的处理节点 |
| 失败重试策略 | 重试2次，间隔600秒 | 避免临时网络或数据源波动导致工作流失败 |
| 单次处理数据量 | 前200条高风险客户数据 | 适配文档字段结构，避免节点过载 |

## 容易做错的三处
- 上传关联文档时提示Load file error，原因是未在`variables`中绑定文档解析节点与风险客户清单的字段映射，导致节点无法读取对应数据。
- 工作流代码运行节点无法执行自定义逻辑，原因是未配置`nodeId`关联对应代码节点的权限绑定，导致节点无法访问专属数据源。
- 工作流解析节点无执行记录，原因是触发时机设置为按日触发，与数据周/月的更新频率不匹配，导致无可用数据源加载。

## 怎么确认配好了
- 手动触发工作流，检查`variables`绑定的字段是否正确加载到对应节点。
- 查看FastGPT v4.17.0版本的工作流日志，确认`nodeId`对应的节点执行状态为成功。
- 对比工作流输出的风险客户清单与本地导出的CRM清单字段是否一致。
- 等待一个完整的更新周期，确认工作流自动触发并生成续费预测表。
