# 缺陷管理与回归测试的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
本品类的数据来源为缺陷管理系统、测试报告、代码提交记录与用户反馈，更新频率为每日或每版本发布周期。日常处理的文档包括缺陷单、回归清单、修复验证记录与缺陷统计报表，文档结构包含缺陷ID、优先级、复现步骤、关联版本号、验证结果等字段，字段多为字符串、枚举值与语义化版本号，无统一数值统计单位。数据围绕功能缺陷生命周期产生，覆盖从缺陷发现到修复验证的全流程。

## 这些特征在「文档解析与分块」这一环带来什么约束
本品类的文档围绕功能缺陷生命周期展开，包含复现步骤、优先级判定等强关联内容，分块时需保留上下文完整性，避免拆分关键逻辑导致复现困难。数据按版本更新的特性要求分块结果需关联对应版本标识，防止跨版本内容混淆影响回归验证。多源数据格式差异要求解析环节兼容PDF、PPT、文本等多种导入格式，且需保留表格、公式等复杂排版结构。高频更新的缺陷单与报表需控制解析耗时，避免影响测试流程推进。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 缺陷单、回归清单的核心段落多在数百字符范围，避免拆分复现步骤、优先级说明等关键上下文 |
| `chunkSplitter` | 按段落+标题分块 | 缺陷文档包含明确的优先级、复现步骤等标题层级，保留结构可提升后续检索的关联性 |
| `customPdfParse` | 启用 | 适配缺陷统计报表、修复验证记录的PDF格式，保留表格、公式等复杂排版内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型缺陷统计报表的解析耗时较长，避免因超时中断解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持批量导入的版本回归清单与历史缺陷报表，适配大规模测试文档的上传需求 |
| `chunkSettingMode` | 手动配置 | 针对不同类型的缺陷文档调整分块规则，适配优先级、版本号等专属字段的关联展示 |

## 容易做错的三处
- 现象：Docker部署`marker_images:v0.1`时执行`docker run --gpus all -itd -p 7231:7231`命令报错。原因：本地GPU驱动版本与镜像依赖不匹配，或FastGPT版本与镜像版本存在兼容性差异。
- 现象：FastGPT知识库内的PDF文件点击分块预览，返回无法读取该文件内容。原因：`customPdfParse`配置未启用，或上传文件超出`UPLOAD_FILE_MAX_SIZE`限制，或文档为加密格式。
- 现象：配置飞书知识库后，无法同步PPT和PDF类文档。原因：未开启对应文档格式的解析权限，或`customPdfParse`配置未覆盖飞书同步的文档类型。

## 怎么确认配好了
- 上传一份包含复杂公式的缺陷统计报表PDF，在FastGPT v4.17.0版本中检查解析后分块预览是否保留公式结构与完整文本内容。
- 执行指定的Docker运行命令，查看容器启动日志无报错，且端口7231可正常访问。
- 上传一份超过默认大小的回归清单文档，确认系统提示符合`UPLOAD_FILE_MAX_SIZE`的限制规则。
- 配置飞书知识库并上传PPT格式的回归清单，确认文档可正常同步并解析。
