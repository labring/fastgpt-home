# 落地页转化优化的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
落地页转化优化的日常工作文档包含落地页方案、埋点需求、AB测试报告、表单字段清单，核心数据来源为落地页访问日志、热力图、表单提交数据与广告来源参数。数据更新节奏为周度或单次活动周期，字段涵盖页面路径、停留时长、表单提交状态、广告渠道标识等，需随具体活动调整分析维度，无固定统一的统计口径。

## 这些特征在「上下文与 token」这一环带来什么约束
落地页转化优化的多源数据与动态更新节奏，对上下文与token配置带来多重约束。首先，多来源的碎片化数据需整合为连贯的分析上下文，需严格控制召回内容的token占用，避免超出模型承载上限。其次，周度或单次活动周期的更新节奏要求上下文数据具备时效性，旧数据不应占用过多token资源。此外，多样的文档结构与字段需精准匹配检索条件，若上下文召回范围过宽，会导致无效token消耗，若过窄则无法覆盖完整的分析依据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配落地页方案、AB测试报告等单份文档的平均长度，适配FastGPT v4.17.0的上下文承载上限 |
| `quoteMaxToken` | 1500–2000 字符 | 对应单条落地页访问日志、表单数据的有效信息长度，避免冗余token占用 |
| 上下文召回条数 | 前6条 | 匹配日常文档的字段清单数量，控制单轮上下文的token消耗 |
| 上下文更新频率 | 按活动周期同步 | 匹配该品类周/每活动的更新节奏，确保上下文数据时效性 |
| 上下文检索阈值 | 0.75–0.85 | 过滤低相关性的热力图、访问日志数据，提升有效token的利用率 |

## 容易做错的三处
- 现象：工作流中编排多个AI大模型对话后，总token消耗超出配置上限，返回状态码413。原因：未区分不同模型的上下文隔离，将跨模型的token累计计算，超出`maxContext`的设置范围。
- 现象：配置上下文调用密钥后，检索任务失败，提示密钥无效。原因：误将广告平台的API密钥填入`ACCESS_TOKEN`配置项，未使用FastGPT平台分配的上下文调用密钥。
- 现象：页面路径分析环节多次重试后失败，返回Reached the max retries。原因：未调整上下文检索的超时参数，导致落地页热力图数据加载超时触发重试上限。

## 怎么确认配好了
- 导入单份完整的落地页方案文档，检查上下文窗口的召回内容是否包含完整的页面路径、表单字段清单与埋点需求说明。
- 运行一次模拟的落地页转化分析任务，查看token消耗统计是否在配置的`maxContext`范围内。
- 配置多模型工作流，验证每个模型的上下文调用是否独立，无跨模型的token累积影响。
- 测试跨活动周期的上下文更新，确认旧活动的分析数据不会被误召回至新的分析任务中。
