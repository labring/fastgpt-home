# 落地页转化优化的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自落地页访问日志、热力图、表单提交数据及广告来源参数。日常产出的文档包含落地页方案、埋点需求清单、AB测试报告与表单字段配置表，更新频率为每周或随单次营销活动调整。文档字段多包含页面路径、停留时长、表单字段校验规则、实验分组标识等，单位涵盖秒、条、字符等，核心数据需与广告投放的来源参数做关联对齐。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且需跨系统关联，要求多轮对话需逐步引导补充不同维度的数据源信息，避免一次性输入过多字段导致上下文混乱。文档结构多样且需匹配业务场景，提示词需适配落地页方案、埋点需求等不同文档类型的字段规则。更新频率随活动调整，对话上下文需支持按活动周期归档，避免跨活动数据混淆。页面路径分析等耗时环节需关联历史数据，提示词需具备按时间范围筛选数据的能力，减少人工排查成本。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口长度 | 前 8 轮对话 + 最近 1200 字符 | 适配周度更新的文档长度，避免上下文溢出影响后续提问 |
| 知识库召回上限 | 前 6 条 | 匹配表单字段、埋点需求等文档的常规字段数量上限 |
| 变量绑定规则 | 按活动维度绑定 `variables` | 区分不同营销活动的落地页数据，避免参数混淆 |
| 对话超时阈值 | 600 秒 | 覆盖页面路径分析、实验结果判断等耗时环节的处理时长 |
| 历史消息保留规则 | 保留最近 10 条`messages` | 适配多轮对话的上下文连贯性，避免冗余信息干扰 |
| 问题优化开关 | 开启 | 自动简化复杂的埋点需求、AB测试分析类提问，提升理解效率 |

## 容易做错的三处
- 现象：调用对话接口时提示未选择知识库，但调试预览时正常。原因：未在请求参数中传入`chatId`绑定对应活动的知识库配置，或`variables`中未指定知识库ID。
- 现象：对话日志未按周期自动清理，占用存储空间。原因：未配置按活动周期归档对话记录的规则，默认保留全量历史数据。
- 现象：多轮对话中历史文档片段丢失，导致后续提问无法关联之前的落地页方案内容。原因：上下文窗口长度设置过短，未保留足够的历史交互与文档信息。

## 怎么确认配好了
- 发起包含埋点需求字段的提问，检查回复是否关联了预设的落地页文档内容。
- 调用对话接口时传入`chatId`参数，确认同一会话的上下文可被正确保留。
- 查看对话日志归档规则，确认按活动周期自动清理过期数据的配置已生效。
- 测试输入长文本的AB测试报告内容，确认上下文窗口可正常加载完整信息。
