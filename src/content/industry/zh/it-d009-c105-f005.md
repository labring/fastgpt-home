# 许可证合规与版权声明的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据围绕开源项目的权利声明与合规文件生成，核心文档包含LICENSE文件、NOTICE文件、依赖许可证清单、版权声明文本。数据来源为代码仓库、第三方依赖清单、官方许可证文本、项目贡献记录，更新节奏随项目版本迭代或依赖变更触发。文档字段包含许可证类型、版权归属主体、依赖项名称、合规校验结果，仅需匹配开源协议标准格式，无额外自定义单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据分散且更新频繁，要求多轮对话需实时拉取代码仓库、依赖清单的最新内容，确保合规校验基于最新版本。文档字段需严格匹配开源协议标准，提示词需固定输出格式以生成符合要求的LICENSE、NOTICE文件。多轮对话需覆盖许可证兼容性核对、版权归属确认等耗时环节，需逐步追问补充依赖项信息、贡献记录细节，同时需避免生成不符合合规要求的内容，防止后续违规风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 按每轮对话追加1000–1500字符的上下文 | 本品类需保留最新的依赖清单、版权记录，过长上下文会增加校验耗时，该区间可平衡信息完整性与处理效率 |
| `variables` | 预设3个固定变量，分别为项目名称、依赖清单路径、许可证类型模板 | 标准化变量可减少重复输入，确保生成的LICENSE、NOTICE文件格式统一 |
| `chatId` | 绑定项目专属ID | 可隔离不同开源项目的合规对话上下文，避免跨项目数据混淆 |
| 最大上下文长度 | 8000–12000 token | 需覆盖单版本的依赖清单与贡献记录，该区间可完整承载核心合规校验所需信息 |
| 问题优化 | 开启 | 可将模糊的合规需求转化为明确的校验项，提升对话效率与准确性 |

## 容易做错的三处
- 现象：调用对话API使用流式输出时，生成的许可证链接仅能覆盖当前页面，无法跳转新页面。原因：未配置流式输出的链接跳转触发规则，导致前端渲染逻辑未正确处理外部链接。
- 现象：FastGPT v4.17.0版本中，对话日志详情内容与实际生成的版权声明文本不一致，多次对话后日志仍显示旧内容。原因：未绑定项目专属`chatId`，导致不同对话的上下文被混淆，日志缓存未正确区分会话。
- 现象：生成的NOTICE文件遗漏部分第三方依赖的许可证声明。原因：未在多轮对话中追加最新的依赖清单数据，仅使用了初始加载的旧依赖列表。

## 怎么确认配好了
- 发起一次包含多个第三方依赖的合规校验对话，核对生成的依赖许可证清单是否包含所有输入的依赖项。
- 查看对话日志，确认每条会话的`chatId`与对应项目ID一致，日志内容与实际生成的文档内容匹配。
- 触发流式输出，点击生成的许可证链接，确认可跳转至对应协议的官方页面。
- 调整依赖清单后发起新对话，确认生成的NOTICE文件包含更新后的依赖信息。
