# 语音标注与转写的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
语音标注与转写场景的数据主要来自音频文件、标注平台、专有词表与抽检样本，更新节奏为每日或按项目批次。日常产出的文档包含转写规范、音频清单、质检报告与说话人标注表，数据结构以结构化的音频元数据、转写文本、标注标签为核心。与文本标注项目不同，该品类需先将音频内容转换为结构化文本再开展后续处理，核心耗时环节集中在噪声片段判断、说话人区分与专有词校对。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据特征对工作流编排带来多项约束。首先，数据来源分散且按批次更新，要求工作流支持批量拉取音频与关联标注元数据，并配置定时触发规则匹配更新节奏。其次，核心环节耗时较长，需拆分独立节点实现分段处理，避免单节点超时。再者，标注结果的准确性直接影响后续算法训练，工作流需嵌入质检节点与失败重试机制，同时需匹配日常文档的输出格式要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按批触发，每批不超过50条音频 | 匹配数据的日/每批更新节奏，避免单次处理过载 |
| `variables` | 绑定音频路径、说话人标注表ID | 关联数据来源的音频文件与标注元数据，确保流程能读取对应标注规则 |
| 节点超时时间 | 600秒 | 覆盖噪声判断、说话人区分等核心耗时环节的处理时长 |
| 重试次数 | 2次 | 应对标注平台临时接口波动导致的执行失败 |
| `nodeId` | 按音频导入→转写→质检→导出的顺序编排 | 匹配语音标注的标准业务流程顺序，确保节点执行逻辑连贯 |
| 批量输出格式 | 匹配转写规范与质检报告模板 | 满足日常文档的输出要求，便于团队直接复用结果 |

## 容易做错的三处
- 现象：工作流导入其他环境后，关联的标注平台插件无法调用。原因：未将插件配置随工作流导出，仅导出了流程JSON文件。
- 现象：工作流执行时出现超时报错。原因：未根据核心耗时环节调整节点超时时间，设置的超时时长不足。
- 现象：转写结果的说话人标注与源表不一致。原因：未在工作流中绑定说话人标注表的`variables`参数，导致元数据未正确关联。

## 怎么确认配好了
- 检查工作流的触发节点配置，确认触发规则匹配数据的日/每批更新节奏。
- 验证`variables`参数绑定的数据源，确认能正确拉取音频文件与标注元数据。
- 运行单条测试用例，核对节点执行时长是否在预设的超时范围内。
- 导出工作流配置，确认关联的插件与元数据配置已同步导出。
