# 质保期缺陷响应的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
该品类的数据围绕项目交付后的质保服务产生，来源包括客户提交的质保工单、系统运行日志、合同约定的质保条款、软件版本迭代记录。日常产出的文档包含质保工单、缺陷确认单、修复记录、客户确认单，每份文档包含缺陷描述、责任主体、修复时限、客户反馈等字段，数据更新频率为每日或随单触发。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且随单更新，要求工作流需支持多源数据的自动拉取与拼接，避免手动录入导致的信息偏差。文档字段存在明确的责任边界判断环节，工作流需设置节点对数据进行校验，确保责任主体、修复记录等字段完整。更新频率随单触发的特性，要求工作流支持按需启动，适配不同质保工单的处理节奏。同时，数据关联的合同条款与版本记录，需在工作流中嵌入关联查询环节，确保处理依据符合约定。

以下配置基于FastGPT v4.17.0版本的工作流功能制定，适配质保期缺陷响应的业务需求。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按新工单创建事件触发 | 匹配数据随单更新的特性，无需固定周期启动 |
| 变量绑定 | 绑定`variables`为工单基础信息 | 统一调用工单中的缺陷描述、客户信息等字段 |
| 节点输出存储 | 按节点顺序拼接结果 | 对应修复记录的生成逻辑，确保环节可追溯 |
| 超时阈值 | 600 秒 | 覆盖责任边界判断、方案协调的常规处理时长 |
| 上下文调用上限 | 前 3 条版本记录 | 匹配数据来源中的版本记录关联需求，避免冗余信息干扰 |
| 错误重试次数 | 2 次 | 适配临时接口调用异常的场景，减少工单停滞 |

## 容易做错的三处
-  工作流节点输出变量存入飞书多维表格时调用失败。原因是未正确配置`variables`中的工单ID字段与飞书API的请求参数映射，导致接口无法识别目标存储位置。
-  工作流执行中途停滞且无报错提示。原因是触发条件未绑定正确的数据源更新事件，或节点间的`nodeId`关联配置错误，导致流程无法向下传递。
-  工作流节点报Premature close错误。原因是超时阈值设置过短，未覆盖责任边界判断的复杂处理时长，导致流程中途中断。

## 怎么确认配好了
-  手动触发一条测试质保工单，查看工作流是否自动启动并拉取对应工单的基础信息。
-  检查节点输出的变量是否完整包含缺陷描述、责任主体等必填字段，无空值或缺失项。
-  模拟接口调用异常场景，验证工作流是否按配置的重试次数执行重试操作。
-  查看工作流运行日志，确认各节点的执行顺序与预期的责任边界判断、修复记录生成环节一致。
