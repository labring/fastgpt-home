# 质保期缺陷响应的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
本品类的数据主要来自客户提交的质保工单、现场缺陷确认单、研发团队的修复记录以及最终客户的确认单。数据更新以单条工单为周期，每日或随每单处理进度同步更新。文档结构无统一固定格式，常见格式包含Word、PDF或扫描件，核心字段包括缺陷编号、发生场景、复现步骤、关联版本、责任判定项与闭环状态等。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于文档来源多样且格式不统一，解析环节需兼容多类文件格式，避免因格式解析失败丢失缺陷复现步骤等关键信息。单条工单数据体量不大但更新频繁，分块需适配短文本高频处理的节奏，避免超时。文档中包含的责任判定、客户反馈等敏感字段需在分块时保留上下文关联，防止拆分后丢失责任边界判断所需的完整信息。同时，部分文档附带扫描件或内嵌图片，解析时需同步提取图片关联信息，避免仅提取文本导致关键场景描述缺失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配单条质保工单的核心内容长度，避免拆分后丢失缺陷复现的完整上下文 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配质保文档按缺陷场景、处理步骤划分的自然结构，保留业务逻辑关联性 |
| `customPdfParse` | 启用 | 针对扫描件PDF或内嵌复杂格式的质保文档，提升解析准确率 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配单批次多工单批量解析的耗时需求，避免因超时导致解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容批量打包提交的质保文档包，满足项目组集中处理的场景 |
| `chunkSettingMode` | 手动配置 | 允许针对不同类型的质保文档调整分块规则，适配多样的业务文档结构 |

## 容易做错的三处
- 现象：上传PDF或Word格式的质保文档后，解析结果无图片关联信息，或图片链接未携带预设域名。原因：未启用`customPdfParse`配置，或未配置图片提取规则，导致仅提取纯文本内容。
- 现象：分块后部分工单的责任判定字段与上下文拆分分离，导致后续检索时无法关联完整判定依据。原因：`chunkSplitter`配置为按固定字符拆分，未匹配文档的自然段落结构。
- 现象：批量上传多份质保文档时出现解析超时错误，返回类似net::ERR_INCOMP的状态码。原因：`PARSE_FILE_TIMEOUT_SECONDS`配置值过低，未适配批量文档的解析耗时。

## 怎么确认配好了
本核对流程适用于FastGPT v4.17.0版本。
- 上传一份包含扫描件、内嵌图片的质保PDF文档，核对解析结果是否包含图片链接及对应描述。
- 导入一份包含多段缺陷描述的Word格式工单，检查分块结果是否按段落划分，未出现跨段落拆分的情况。
- 批量上传5份以上质保文档，等待解析完成后检查是否出现超时报错，确认解析耗时符合预期。
- 查看分块后的文本片段，确认责任判定项与关联的缺陷复现步骤处于同一块内容中。
