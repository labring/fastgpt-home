# 身份账号与权限管理的需求与设计文档起草：文档解析与分块

## 这个品类的数据长什么样
本品类的核心使用主体为IAM管理员、信息安全专员与业务系统管理员，日常处理的文档包含账号申请单、权限矩阵、离职回收单与内部审计报告。数据来源为企业IAM系统、HR系统、业务系统日志与审批系统，更新频率随人事变动或每日同步。文档多为结构化表单与表格格式，字段包含账号标识、权限分配范围、生效失效时间、审批节点信息等，单份文档体量多在几KB到几十MB之间。本页面适配FastGPT v4.17.0版本。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于核心文档多为结构化表单与权限矩阵表格，解析时需保留字段关联关系，避免拆分跨权限绑定的内容块。数据更新随人事变动或每日同步，解析环节需支持快速响应上传请求，避免缓存旧数据。文档包含账号标识、权限范围等敏感字段，分块需确保单块内容不割裂关键权限关联逻辑。同时单份文档体量有限但字段密集，分块参数需适配结构化内容的最小合理单元，避免拆分导致语义断裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---|---|--- |
| `chunkSize` | 800–1200 字符 | 适配权限矩阵等结构化文档的字段密度，避免拆分跨权限关联的内容块 |
| `chunkSplitter` | 按段落与表格拆分 | 保留账号申请单、离职回收单的表单结构，避免破坏字段关联 |
| `customPdfParse` | 开启 | 适配扫描件或格式复杂的审计报告，保留原有排版与字段位置 |
| `UPLOAD_FILE_MAX_SIZE` | 50 MB | 匹配IAM审计报告等单文档最大常见体量，避免大文件解析超时 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对多系统数据合并后的批量解析需求，避免中小型文档因等待超时失败 |
| `chunkSettingMode` | 手动配置 | 适配IAM文档的结构化特征，避免自动分块破坏权限关联逻辑 |

## 容易做错的三处
- 配置`UPLOAD_FILE_MAX_SIZE`时设置过小，上传权限矩阵Excel文件时触发上传失败，原因是未匹配IAM文档的常见单文件体量。
- 未开启`customPdfParse`，扫描版离职回收单解析后出现字段缺失、排版错乱，原因是默认解析无法识别扫描件的结构化内容。
- 未调整`PARSE_FILE_TIMEOUT_SECONDS`至合理区间，本地部署大模型版本上传审计报告后显示请求失败，重启服务器无效，原因是默认超时时长不足以完成多日志数据的合并解析。

## 怎么确认配好了
- 上传一份标准权限矩阵Excel文件，检查解析后是否保留完整的表格结构与字段关联。
- 上传一份体量约40MB的审计报告文件，确认上传与解析流程无报错。
- 提交一份离职回收单文档，等待解析完成后检查分块内容未割裂账号与权限的绑定关系。
- 查看系统日志，确认解析耗时未超过`PARSE_FILE_TIMEOUT_SECONDS`的设置值。
