# 集成测试与接口测试的需求与设计文档起草：上下文与 token

## 这个品类的数据长什么样
这个品类的数据主要来自接口管理平台、测试环境日志、数据库与消息队列。日常产出的文档包括接口测试用例、联调问题单、环境说明与测试报告，包含接口地址、请求参数、响应状态码、用例执行结果等字段。数据更新频率为每日或每版本发布周期，随测试推进与联调进度动态调整，不同来源的数据格式存在一定差异。

## 这些特征在「上下文与 token」这一环带来什么约束
接口测试与集成测试的文档多包含动态参数与跨服务交互细节，数据更新频繁导致上下文需及时同步最新接口状态与测试结果。测试用例与联调单的字段复杂度较高，单份内容的token消耗相对固定，需精准控制总上下文token占用避免超出模型上限。不同来源的日志与队列数据格式存在差异，需在上下文整理时统一字段结构，防止无效信息占用有效token空间。测试环节的上下文需关联特定测试环境与版本，不能混入无关测试数据，进一步压缩有效token的可用范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 8000–12000 token | 适配集成测试与接口测试文档的多字段结构，避免单次调用超出模型token限制 |
| 引用最大token | 1500–2000 token | 匹配单份接口测试用例或联调问题单的平均内容长度，确保核心测试信息完整 |
| 单次召回条数 | 前3–5条 | 对应每日更新的测试日志与问题单总量，减少冗余数据的token占用 |
| 上下文同步周期 | 每日更新 | 贴合数据日更或每版本更新的节奏，保证上下文包含最新测试与联调状态 |

## 容易做错的三处
- 现象：无法在指定路径找到token使用统计数据，或统计结果与实际调用不符。原因：未在FastGPT v4.17.0的全局配置或会话详情页查看对应统计项，误将非token统计字段当作目标。
- 现象：设置了1500 token的引用上限后，仍出现超出token限制的报错。原因：未区分知识库切块token与上下文引用token的配置逻辑，切块大小仅影响知识库存储，引用上限仅控制单条召回内容的token消耗，未同步调整最大上下文总长度。
- 现象：工作流中无法触发符合条件的上下文清空操作。原因：未将清空逻辑绑定至指定的判断节点，或未正确配置触发条件的字段匹配规则，导致上下文历史未被重置。

## 怎么确认配好了
- 查看会话详情页的token使用统计项，确认单次调用的token消耗符合配置的最大上下文与引用上限。
- 模拟调用接口测试用例相关的prompt，检查召回的知识库内容长度未超出设置的引用最大token值。
- 触发预设的上下文清空条件，验证会话历史中的旧测试数据已被清除。
- 对比每日更新的测试日志与上下文同步记录，确认数据更新频率符合配置的同步周期。
