# 集成测试与接口测试的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
本品类的数据来源于接口管理平台、测试环境日志、数据库与消息队列，更新频率为每日或每版本发布周期。日常产出的文档包括接口测试用例、联调问题单、环境说明与测试报告，其中接口测试用例包含接口地址、请求方法、请求头、请求参数、预期响应码、依赖服务标识等字段，联调问题单记录链路节点、报错信息与排查节点信息。环境说明文档标注测试集群的服务依赖关系，测试报告汇总接口通过率与链路异常记录。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散的特征要求工作流编排支持多数据源拉取配置，适配接口管理平台、测试日志等不同数据格式。更新频率的要求决定了工作流节点需支持动态刷新参数，适配每日或版本级别的数据更新。日常文档结构多样的特点，要求工作流可灵活配置不同类型文档的处理节点。同时，依赖服务准备与链路问题定位的高耗时场景，要求工作流内置依赖校验与链路追踪节点，减少人工核对成本。此外，出错后果的严重性要求工作流配置异常重试与告警节点，避免联调延期或服务调用失败。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量配置 | 按接口管理平台导出的测试环境变量填充 | 匹配接口测试用例中的依赖服务配置 |
| 请求头参数配置 | 从联调问题单提取的标准请求头格式 | 适配接口测试用例的请求规范 |
| 流程触发节点 | 启动时发起第三方API请求 | 支持提前拉取测试环境的依赖服务状态 |
| 节点超时设置 | 300-600秒 | 覆盖接口调用与日志拉取的常规耗时 |
| 变量存储配置 | 按`variables`参数绑定测试用例字段 | 匹配数据来源的字段映射规则 |
| 链路追踪配置 | 关联`nodeId`标记每个流程节点 | 便于定位联调问题单中的链路节点 |

## 容易做错的三处
- 现象：工作流运行时提示全局变量获取失败，界面显示`variables`字段为空。原因：未将接口管理平台导出的环境变量绑定至工作流的全局配置节点。
- 现象：第三方API请求返回参数无法存入工作流变量，请求头中全局变量引用格式不符合规范。原因：未按照测试用例的参数规范配置变量引用路径。
- 现象：特定测试场景下工作流运行至中间节点后中断，可复现该异常。原因：未配置`nodeId`对应的链路校验节点，未排查对应联调问题单中的链路节点报错。

## 怎么确认配好了
- 运行工作流前，核对全局变量配置是否与接口管理平台导出的环境变量一致。
- 发起第三方API请求后，检查工作流日志中是否正确返回请求结果并绑定至`variables`字段。
- 配置`nodeId`标记每个流程节点后，运行工作流查看链路追踪日志是否完整覆盖所有节点。
- 针对特定测试场景，复现问题后核对对应节点的超时设置是否符合实际接口响应耗时。
