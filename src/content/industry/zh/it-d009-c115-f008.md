# 项目实施计划管理的需求与设计文档起草：工作流编排

本页面配置指南适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的核心数据来自合同、工作分解结构（WBS）、客户日程及项目管理系统，日常产出项目计划、里程碑清单、周报、风险问题清单四类文档。数据更新节奏为每周或每里程碑节点一次，文档字段包含任务工期（天）、责任人、里程碑日期、风险优先级、整改期限（天）等标准化字段，整体结构固定且无额外强制自定义字段。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源分散且更新节奏固定，要求工作流需支持多源数据拉取节点，确保从合同、WBS等系统同步最新数据。日常文档类型多样，需配置不同节点适配项目计划、风险清单等不同文档的字段校验。任务拆解与跨方排期为最耗时环节，工作流需自动流转任务分配、排期确认等节点，减少手动协调成本。数据更新频率决定了工作流触发周期需匹配周或里程碑节点，避免过度触发或遗漏更新。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按里程碑节点更新触发，或按周定时触发 | 匹配品类数据周/每里程碑的更新频率，确保工作流与数据更新节奏一致 |
| `variables`映射 | 将任务ID、工期、责任人字段映射到文档对应列 | 品类文档包含标准化任务相关字段，需确保数据准确流转至后续节点 |
| 节点超时时间 | 1800秒 | 品类数据拉取涉及多系统对接，需预留足够的同步时间，适配跨系统数据交互的耗时 |
| 上下文留存条数 | 前10条 | 匹配周级更新的数据量，避免冗余上下文干扰任务判断与排期协调 |
| 循环分支触发条件 | 按`variables`中的任务完成状态判断 | 品类需循环校验任务拆解结果，确保符合项目计划的要求 |
| `nodeId`绑定 | 绑定排期协调节点的唯一标识 | 确保工作流流转至正确的跨方协调环节，减少手动调整节点的成本 |

## 容易做错的三处
- 现象：工作流循环节点未按预期终止，反复触发重复任务。原因：未将`variables`中的任务完成状态正确绑定到分支判断逻辑，导致循环条件失效。
- 现象：节点调用后仅返回少量上下文内容，无法关联历史项目数据。原因：未按品类数据更新频率配置上下文留存规则，导致旧数据被自动清理。
- 现象：上传的项目文档无法被大模型正确理解，返回无关回复。原因：未将上传的文件直接绑定到`variables`参数，而是使用了默认的文本解析流程，丢失了文档原有格式与字段信息。

## 怎么确认配好了
- 手动触发工作流，查看`variables`中的字段是否正确映射到上传的项目计划文档，确认数据流转无误。
- 模拟里程碑节点更新，确认工作流按预期触发并拉取最新的WBS数据。
- 测试循环分支逻辑，输入不同的任务完成状态，确认工作流按配置的条件流转。
- 查看节点日志，确认上下文留存条数符合配置要求，无异常截断情况。
