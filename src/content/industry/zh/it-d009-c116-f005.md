# 项目文档移交归档的需求与设计文档起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类的核心数据来自项目文档库、配置清单、会议纪要、测试报告。日常产出的文档包括竣工文档、配置手册、培训记录、验收证书，数据更新节奏为项目阶段结束或整体项目收尾时。文档通常按项目编号、阶段节点、交付主体分类存储，包含项目编号、交付日期、签署方、版本号等字段，无固定强制单位，需随项目实际情况匹配。典型使用主体为项目经理、实施顾问与客户档案管理员，核心工作围绕交付证据的完整性与可追溯性展开。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据来源分散且更新节点集中，多轮对话需关联不同阶段的文档内容，因此需要稳定的上下文绑定机制。文档包含版本号、签署方等强校验字段，提示词需明确要求核对字段一致性，避免遗漏验收证书、配置手册等关键交付物。数据更新频率与项目进度强绑定，多轮对话需支持按阶段触发文档梳理，同时需保留历史交互记录用于版本追溯。不同文档的格式差异较大，提示词需引导统一的输出结构，便于后续归档与签章流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 字符 | 匹配单项目文档的总字符量，避免截断关键版本信息 |
| `chatId` 绑定规则 | 按项目编号生成固定标识 | 确保同项目的多轮对话关联同一上下文，避免权限或上下文丢失 |
| `variables` 预设字段 | 包含项目编号、交付阶段、文档类型 | 传递归档所需的元数据，支持工作流触发导出操作 |
| 多轮对话触发阈值 | 3 轮交互后自动校验 | 匹配项目文档移交的多阶段校验需求 |
| `messages` 上下文保留数量 | 最近 20 条交互记录 | 覆盖项目全周期的交互过程，便于回溯版本核对细节 |
| FastGPT 版本 | v4.17.0 | 适配当前版本的上下文绑定与工作流触发逻辑 |

## 容易做错的三处
- 对话页面显示“没有权限操作此对话记录”，原因是未按项目编号生成固定`chatId`，导致上下文关联失败，权限校验不通过。
- 工作流无法在对话底部创建导出word的下载链接，原因是未在`variables`中配置文档元数据参数，未触发导出触发条件。
- 升级FastGPT v4.17.0后刷新页面对话记录丢失，原因是未正确配置`messages`上下文持久化规则，导致历史交互未被正确存储。

## 怎么确认配好了
- 输入项目编号与历史文档关键词，发起多轮对话，检查后续交互是否关联同一项目的上下文内容。
- 触发预设的文档导出工作流，验证是否在对话界面底部生成可下载的word文件链接。
- 刷新当前对话页面，检查历史交互记录是否完整保留，未显示为新对话。
- 上传测试文档至系统提示词指定的文档库，检查AI是否能正确读取文档内容并完成字段校验。
