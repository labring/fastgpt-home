# 项目文档移交归档的需求与设计文档起草：工作流编排

## 这个品类的数据长什么样
本品类的数据主要来自项目文档库、配置清单、会议纪要、测试报告。日常产出的文档包括竣工文档、配置手册、培训记录、验收证书。数据更新节奏为每项目阶段结束或整体项目收尾时同步。单份文档包含项目编号、文档版本号、签署人信息、归档日期、关联项目ID等字段，部分验收类文档还附带甲方签章扫描件与验收结果标识。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新节奏灵活，要求工作流支持多源数据拉取节点，可对接项目文档库、配置清单等不同存储路径的数据源。文档类型覆盖竣工、培训、验收等多个类别，不同文档的校验规则存在差异，需在工作流中配置分类校验分支。单份文档包含多维度字段，版本一致性核对与完整性检查为核心耗时环节，工作流需内置自动化校验节点，对缺失字段、版本不匹配的文档触发异常标记。归档过程需留存操作轨迹，以支撑后续运维溯源。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发节点设置 | 按项目阶段完成标记触发，或手动触发 | 适配本品类按阶段/收尾更新数据的节奏 |
| 多源数据拉取配置 | 关联`variables`中预设的项目ID参数 | 精准拉取对应项目的文档库、配置清单数据 |
| 拉取超时阈值 | 300秒 | 适配多源文档拉取的耗时需求 |
| 文档校验节点 | 匹配竣工文档、验收证书等分类规则 | 区分不同文档的校验逻辑 |
| 异常告警配置 | 触发后5分钟内推送告警信息 | 确保问题及时响应 |
| 归档存储路径 | 按`/project_archive/{nodeId}/v{version}`格式配置 | 按项目ID与版本号分类存储 |

## 容易做错的三处
- 现象：工作流中代码节点的运行结果无法传入AI对话节点，触发`chat:ai_input_is_e`报错。原因：未在`variables`中配置结果存储变量，未将代码节点输出绑定到AI节点的输入参数。
- 现象：使用数据库连接插件对接PostgreSQL时，界面提示“工作流校验失败，请检查是否缺失、缺值，连线是否正常”，无法完成配置校验。原因：未在`variables`中配置数据库连接所需的地址、端口、账号密码参数，或连线未正确关联数据库节点与后续处理节点。
- 现象：在工作流中引用项目文档的字段时，使用`[{datasetId: xxx}]`格式无法正常读取数据。原因：未使用FastGPT标准的`{{variables.xxx}}`变量引用格式，错误套用了知识库变量的语法。

## 怎么确认配好了
- 手动触发一次工作流，查看各节点的运行日志，确认多源数据拉取节点成功获取到对应项目的文档数据。
- 提交一份包含缺失字段的测试文档，确认校验节点能正确标记异常并触发告警。
- 检查归档节点的存储路径，确认生成的归档文件按项目ID与版本号分类存放。
- 查看工作流的变量绑定配置，确认`variables`与`nodeId`参数已正确关联到对应节点。
