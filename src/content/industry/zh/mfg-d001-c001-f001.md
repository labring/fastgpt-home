# PCB制造的供应商与过程质量审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据主要来自客户提供的Gerber文件、钻带、BOM清单，以及工厂内部CAM系统、生产设备参数、槽液化验结果、AOI检测报告、电测报告与实验室切片报告。数据更新节奏覆盖每生产批、每班的连续采集，日常文档包含工程制作指示、钻孔层压参数、药水分析记录等。数据字段涵盖图形参数、孔位信息、检测结果、工艺参数等，单位随检测项与工艺要求调整。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的数据来源分散且更新频率高，要求接口支持多数据源的批量拉取与实时同步。日常文档包含Gerber解析记录、AOI报告等结构化与非结构化内容，接口需兼容文件上传与字段提取能力。数据关联生产批次与工艺参数，接口需支持按生产批标识关联数据，避免数据错位。出错后果严重，接口需配置完善的失败重试与状态校验机制，保障数据传输准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer ${工厂系统API密钥}` | 符合HTTP标准鉴权格式，适配多数工业系统的鉴权规则 |
| `variables` | `{"batch_no": "${当前生产批编号}", "gerber_path": "${上传的Gerber文件路径}"}` | 匹配PCB制造按生产批管理数据的业务逻辑，传递核心业务标识与核心文件参数 |
| `responseData` | `提取字段: [{"defect_type": "检测报告.缺陷类型"}, {"pass_rate": "检测报告.合格率"}]` | 快速从AOI、电测报告的返回结果中提取供应商审核所需的关键指标 |
| 超时时间 | `300–600 秒` | PCB制造的工艺参数与检测报告生成需要一定耗时，避免短超时导致正常请求被中断 |
| 文件传输方式 | `multipart/form-data` | 适配Gerber文件、AOI报告等非结构化文件的上传需求，兼容多数工业设备的接口要求 |

## 容易做错的三处
- 现象：调用接口将stream选择为true时，仅收到分段数据无法获取最终结果。原因：未配置结果聚合逻辑，仅接收了流式返回的分片数据，未合并为完整输出。
- 现象：上传Gerber文件或AOI报告时接口报错，参数传递失败。原因：未正确配置multipart/form-data格式的请求体，或未将文件参数映射到接口要求的字段名。
- 现象：接口调用成功但无法提取所需的审核字段，返回字段为空。原因：未按照接口返回的实际数据结构配置`responseData`提取规则，字段路径匹配错误。

## 怎么确认配好了
- 调用测试接口，查看返回的鉴权状态码，确认`Authorization`配置正确。
- 上传测试用的小型Gerber文件，检查接口返回的文件解析结果，确认`variables`与文件参数配置匹配业务逻辑。
- 配置`responseData`提取规则后，查看返回数据的字段提取结果，确认字段路径与接口返回结构一致。
- 模拟长时间运行的生产批审核请求，确认接口未触发超时，超时阈值按实际工艺耗时标定。
