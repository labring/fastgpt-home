# PCB制造的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自PCB制造工厂的工程、生产、品质与实验室团队，涵盖工程制作指示、Gerber解析记录、钻孔与层压参数、槽液化验结果、AOI报告、电测报告及切片报告。数据来源包含客户提供的Gerber文件、钻带、BOM，以及CAM生成文件、设备运行参数、现场检测数据。更新节奏为每生产批、每班或连续采集，单份文档包含参数数值、检测结果、工序记录等结构化与非结构化字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的多源异构数据结构，要求向量索引支持Gerber文件、结构化参数表格、非结构化检测报告等混合格式解析，避免单一解析规则导致特征丢失。高频更新频率要求索引适配增量同步逻辑，无需每次全量重建即可覆盖新生产批的检测与参数数据。精密参数与定性描述并存的文档结构，需针对性配置向量编码规则，区分数值型工序参数与定性异常描述的特征权重。同时工序流转的关联属性，要求索引保留文档间的上下文关联，便于审核时快速追溯异常的上游工序来源。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配PCB文档中工序参数与检测报告的单块信息密度，避免块内信息断裂 |
| 重叠长度 | 100–200 字符 | 保留相邻分块间的工序上下文，避免跨块的参数关联丢失 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 区分正常工艺参数与异常检测结果的特征匹配度 |
| 单次搜索上限 | 前 10 条 | 覆盖单批次审核所需的关联工序文档数量 |
| `maxToken` | 4096 token | 适配PCB文档的总长度，避免截断关键的Gerber解析记录 |
| `defaultToken` | 150 token | 处理单条短参数记录的向量编码，保证小体量数据的特征完整性 |

## 容易做错的三处
- 现象：知识库索引数十万条PCB数据后，搜索响应超时超过30秒。原因：未配置增量索引规则，每次搜索触发全量向量匹配，导致计算负载过高。
- 现象：搜索结果中出现大量不相关的槽液化验记录，无法定位钻孔参数异常。原因：未针对数值型参数与文本报告配置差异化的向量编码权重，导致特征混淆。
- 现象：导入Gerber文件后，索引结果中缺失钻孔坐标字段。原因：分块长度设置过小，将完整的坐标参数拆分为多个块，导致关键信息被截断。

## 怎么确认配好了
- 导入单份典型PCB工序文档，检查分块后的文本是否保留完整的参数与检测描述，无关键信息断裂。
- 发起针对异常工序关键词的搜索，核对返回结果的数量与关联工序的匹配度，调整相似度阈值至符合审核需求的区间。
- 导入新生成的生产批数据，验证索引是否仅同步新增文档，无需全量重建即可完成更新。
- 查看向量存储的占用空间，确认`maxToken`与分块长度的配置未导致单条向量数据过大，超出存储限制。
