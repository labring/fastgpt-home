# PCB制造的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据来自客户提供的Gerber文件、钻带、BOM清单，以及工厂内部CAM系统、生产设备参数、槽液化验结果、AOI检测报告、电测数据与实验室切片报告。数据更新随生产批次、班组班次连续采集，日常文档包含工程制作指示、Gerber解析记录、钻孔与层压参数、药水分析记录、各类检测报告与切片报告。数据字段包含工艺参数、检测结果、批次信息等，无统一固定单位，随检测项与工艺环节变化。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类数据更新频率高且多源异构，要求多轮对话需绑定生产批次维度，避免跨批次数据混淆。多轮交互中需逐步对齐不同来源的工艺参数与检测结果，提示词需明确引导对话聚焦当前批次的Gerber解析、钻孔层压参数、检测报告等特定文档。同时，数据字段与单位无统一标准，多轮对话需在交互中逐步确认参数的对应单位与含义，防止因格式差异导致审核偏差。此外，单批次数据量较大，需限制对话上下文的历史长度，避免token消耗超出阈值。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定生产批次编号 | 确保对话上下文仅关联当前批次的Gerber、检测报告等数据，避免跨批次信息干扰 |
| `messages` | 保留最近10轮对话内容 | 单批次数据量较大，限制历史对话长度以控制token消耗，避免上下文溢出 |
| `variables` | 预设生产批次、检测类型变量 | 快速过滤对应批次的槽液化验、AOI报告数据，提升检索效率 |
| 最大上下文长度 | 8000–12000 token | 适配单批次多份检测报告与工艺参数的总token量，按实测标定 |
| 问题优化 | 开启 | 适配FastGPT v4.17.0的专业术语优化功能，对齐PCB制造的工艺词汇逻辑 |
| 单次搜索上限 | 前6条结果 | 匹配单批次的核心检测报告与工艺文档，避免冗余信息干扰审核判断 |

## 容易做错的三处
- 现象：对话中上传的批次专属Gerber文件未被纳入当前知识库检索范围。原因：未通过`variables`绑定当前生产批次编号，导致系统无法匹配对应批次的文档。
- 现象：对话界面无法查看当前交互的token消耗情况。原因：未启用全局的token统计配置，或未在对话模块开启统计展示功能。
- 现象：多轮审核对话中，连续发送的两条专业提问仅触发一次回复。原因：未配置`messages`的上下文续接规则，系统默认限制单轮仅处理一条用户输入。

## 怎么确认配好了
- 发起针对当前生产批次的Gerber参数提问，确认系统仅返回对应批次的解析记录与工艺参数。
- 查看对话界面的token消耗统计模块，确认每次交互的token用量被正常记录。
- 连续发送两条独立的审核提问，确认系统依次生成对应的回复内容。
- 发送Markdown格式的检测报告内容，确认在对话界面显示格式符合专业审核需求。
