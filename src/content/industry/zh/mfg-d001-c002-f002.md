# SMT贴片与电子组装的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
本品类典型主体为EMS厂、消费电子及工控汽车电子工厂。日常数据来源包括客户提供的BOM、Gerber坐标文件，工厂MES系统，锡膏与元件批次台账，贴片机、SPI/AOI检测设备及回流焊炉温记录。数据更新节奏为每工单、每次换线实时同步，文档包含BOM与坐标文件、换线表、钢网与炉温记录、首件确认报告、SPI/AOI检测报告、维修记录与追溯标签，核心字段包含料号、位号、元件批次、炉温参数等。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来多重约束。实时按工单、换线更新的特性，要求索引支持增量同步，避免全量重建带来的计算资源占用。文档包含结构化坐标、炉温参数与非结构化检测报告，需适配混合格式的向量编码，保障不同类型字段的语义召回一致性。核心字段料号、位号的精确匹配需求较高，需兼顾语义相似性与字段精准召回。单工单数据量随产线规模波动，索引召回上限需适配不同产线的处理需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本设计。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配BOM、检测报告等文档的平均长度，避免块内语义断裂 |
| 重叠长度 | 100–200 字符 | 保留块间语义关联，防止跨块的料号、位号信息丢失 |
| `maxToken` | 4096 token | 适配主流向量模型的输入上限，避免超长文本截断导致关键信息缺失 |
| `defaultToken` | 2048 token | 作为默认上下文长度，适配常规工单审核的文本量 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 平衡精准匹配料号与召回相关缺陷报告的需求 |
| 单次搜索上限 | 前 10 条 | 适配产线审核的快速响应需求，避免过多冗余结果干扰判断 |

## 容易做错的三处
-  索引召回结果中料号匹配偏差较大，原因是未针对料号、位号这类精准字段调整向量编码权重，导致语义相似性干扰了精准匹配。
-  增量索引更新超时，原因是未配置增量同步的触发规则，每次全量同步海量工单数据，超出系统处理上限。
-  检索结果出现空字段，原因是分块长度设置过大，将包含空值的维修记录完整纳入块中，导致向量编码时关键字段信息被稀释。

## 怎么确认配好了
-  上传单份BOM与SPI报告，检查向量索引生成的块是否覆盖所有核心字段，无明显语义断裂。
-  输入料号查询指令，核对召回结果的匹配精准度，调整相似度阈值至符合业务需求的区间。
-  模拟单次换线后的增量更新任务，检查索引同步耗时是否符合产线响应要求。
-  导入多份不同工单的混合数据，确认单次搜索上限的召回结果无冗余且覆盖相关检测记录。
