# 仓储、批次与厂内物流的供应商与过程质量审核：工具调用与插件

## 这个品类的数据长什么样
这个品类的日常文档包含收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录，核心字段涵盖物料编码、批次号、库位号、效期、检验状态、数量单位。数据来源包括ERP/WMS系统、条码或RFID设备、采购与工单、库位信息、AGV或输送系统、称重数据，更新节奏分为实时、每日、月度盘点三类。

## 这些特征在「工具调用与插件」这一环带来什么约束
多来源的异构数据要求工具调用需支持对接不同协议的系统，批次、效期等多字段的文档结构要求插件需精准提取指定字段，实时与周期性混合的更新节奏要求调用策略区分即时数据与静态数据，账实一致与批次追溯的业务目标要求工具调用需严格校验字段完整性，避免因数据缺失引发错料、停线等风险。

## 配置怎么定
本页面的配置说明适用于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | auto | 允许模型自主匹配仓储、批次相关的工具类型 |
| 工具调用超时时间 | 600–1200 秒 | 适配ERP/WMS系统的批量数据拉取延迟 |
| 插件请求重试次数 | 2–3 次 | 应对条码RFID设备的临时连接波动 |
| `functionCall` | 按单据类型指定 | 针对收货单、盘点表等固定格式文档调用专用工具 |
| 单次返回数据条数 | 前 10 条 | 匹配批次台账的单次查询数据量级 |
| 参数校验开关 | 开启 | 校验物料编码、批次号等必填字段 |

## 容易做错的三处
- 工具调用返回`400 InternalError.Algo.InvalidParameter`报错，原因是未校验批次号、效期等必填字段，导致传入的参数格式不符合系统要求。
- 首次工具调用延迟较高，后续请求恢复正常，原因是未预热内网ERP/WMS系统的连接，首次请求需建立网络通道或拉取全量基础配置数据。
- HTTP插件调用内网系统失败，原因是未配置代理适配内网访问限制，无法绕过外部网络隔离。

## 怎么确认配好了
- 提交包含物料编码、批次号的测试单据，检查工具是否能正确拉取对应ERP/WMS系统的关联数据。
- 模拟首次调用与连续调用，验证首次延迟与后续延迟是否符合业务预期。
- 构造缺失批次号的测试用例，确认是否触发参数校验的报错提示。
- 配置代理后，测试内网WMS系统的插件调用是否能正常完成。
