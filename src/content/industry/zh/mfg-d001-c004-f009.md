# 仓储、批次与厂内物流的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
典型主体包括原材料库、线边库、成品库及物流与物控部门。日常文档涵盖收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录。数据来源包含ERP/WMS系统、条码或RFID设备、采购工单、库位信息、AGV输送系统、称重数据。更新节奏分为实时（如AGV位置、条码扫描数据）、每日（如领退料记录）、月度（如盘点表）三类，核心字段包括物料编码、批次号、库位、效期、检验状态，单位多为件、千克、立方米等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入时需适配不同格式的数据源，需配置对应的代理或接口适配参数。更新节奏的差异要求索引刷新策略需匹配数据更新频率，实时数据需高频同步，月度数据可按需批量更新。核心字段的专业性要求模型的检索与生成需精准匹配物料编码、批次号等专属字段，避免泛化处理。审核类任务的严谨性要求模型参数需偏向低随机性，确保结果的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 该品类的审核任务需覆盖多份批次台账、盘点表与工单数据，足够的上下文可确保信息完整 |
| `maxTokens` | 3000–4000 token | 审核类任务无需过长生成内容，避免冗余输出影响审核效率 |
| `quoteMaxToken` | 1500–2000 token | 需引用收货单、移库单等多份单据的字段信息，限定引用token可聚焦核心数据 |
| `temperature` | 0.2–0.4 | 审核任务需严谨的结果，较低的温度可减少生成偏差 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属地址 | 适配ERP/WMS、条码系统等多源数据的接入需求 |
| `toolChoice` | auto | 需调用工具解析条码、RFID等非结构化数据，自动选择工具可提升处理效率 |

## 容易做错的三处
- 现象：接入第三方embedding服务时持续返回报错。原因：未单独配置索引模型，错误复用对话模型的参数，导致embedding维度与仓储品类的物料字段不匹配。
- 现象：上传批次台账PDF时触发请求错误。原因：未正确启用`vision`参数，导致模型无法解析PDF中的条码、效期等关键字段。
- 现象：核对物料批次时返回的结果与ERP数据不一致。原因：`maxContext`取值过小，未覆盖当前工单关联的所有收货单、移库单数据，导致上下文缺失。

## 怎么确认配好了
- 测试读取单份收货单文档，检查模型能否正确提取物料编码、批次号、供应商信息。
- 发起批量物料核对任务，检查模型返回的结果是否与ERP/WMS的同步数据一致。
- 查看FastGPT v4.17.0版本的模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置未出现格式错误。
- 调整`temperature`参数，检查生成结果的严谨性是否符合审核需求。
