# 仓储、批次与厂内物流的供应商与过程质量审核：知识库检索与召回

## 这个品类的数据长什么样
该品类数据主要来自ERP/WMS系统、条码或RFID采集设备、采购工单、库位管理台账、AGV输送系统与称重设备。日常文档包含收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录。数据更新节奏分为实时（如库位变动、扫码入库）、每日（如工单领用统计）与月度盘点（如库存对账），核心字段包含物料编码、批次号、库位编号、检验状态、效期与收发数量，单位多为件、千克或立方米。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据来源分散且更新节奏差异大，要求知识库检索需支持按数据更新频率划分的数据集分组召回。核心字段聚焦物料编码、批次号与库位编号，检索需优先匹配精准字段，避免使用泛化关键词召回，防止错配物料或批次。日常文档类型多样，需按业务场景关联对应文档集合，确保召回内容贴合收货、盘点或配送等具体审核环节。同时，账实一致与批次追溯的核心需求，要求召回结果需包含完整的检验状态与效期信息，支撑质量审核判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.75–0.85 | 匹配仓储批次类精准字段，避免泛化召回无关物料数据 |
| `limit` | 前8–12条 | 覆盖单次审核需核对的物料批次数量，同时控制上下文长度 |
| `searchMode` | `embedding` | 优先基于物料编码、批次号等字段的向量匹配，确保精准召回 |
| `usingReRank` | 开启 | 对召回结果按业务相关性重排，优先返回检验状态与效期相关内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充批次号、库位号等字段的扩展检索，覆盖多维度查询场景 |
| `collectionIds` | 按业务场景绑定对应集合 | 区分收货、盘点、配送等场景的文档集合，避免跨场景召回干扰 |

## 容易做错的三处
- 现象为界面无法找到知识库集合标签入口，原因是未在FastGPT v4.17.0中开启对应场景的数据集管理权限，或未创建贴合仓储审核的业务集合。
- 现象为聊天返回的知识库关联id无法匹配目标文档，原因是检索配置中未正确填写`collectionIds`参数，导致召回范围超出目标集合。
- 现象为工作流中的http请求步骤未执行，直接触发AI对话，原因是工作流节点未设置正确的触发逻辑，或参数格式不符合FastGPT v4.17.0的要求。

## 怎么确认配好了
- 输入具体的物料编码与批次号，检查召回结果是否包含对应收货单、盘点表等文档。
- 查看检索日志，确认召回结果的`similarity`分值落在0.75–0.85区间内。
- 核对工作流节点的配置，确认`collectionIds`参数绑定了对应场景的数据集集合。
- 触发工作流的http请求步骤，查看日志确认请求已发送且返回了对应业务数据。
