# 光伏电池片制造的供应商与过程质量审核：向量模型与索引

以下配置适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
通常，光伏电池片制造企业的工艺、设备、品质与生产部门会产生多类业务数据。数据来源涵盖硅片来料记录、MES生产管理系统、扩散炉/镀膜设备/印刷机的运行参数、EL缺陷检测图、IV电性能测试数据以及实验室良率报告。数据更新节奏为每批来料、每片产品检测以及每日汇总统计。日常文档包含固定格式的工艺卡、分段式的扩散与镀膜参数表、实时打印的烧结记录、带像素标注的EL检测图、按电性能分档的IV数据，以及阶段性良率统计报表。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于数据包含结构化的参数表、数值型的测试数据与非结构化的图像类文档，向量模型需要同时支持多模态数据的嵌入与结构化元数据的关联。高频次的按批、按片更新要求索引支持增量更新，避免全量重建带来的性能损耗。片级与批次级的追溯需求，要求检索结果需绑定对应的设备ID、生产批次与来料批次信息，防止跨批次的无效数据被召回。同时，工艺参数与缺陷检测的关联分析，需要向量索引的维度与字段匹配业务数据的粒度，保障检索的精准性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块最大长度 | 800–1200 字符 | 匹配光伏电池片工艺卡、烧结记录等单份文档的常规段落长度 |
| 最大段落深度 | 3 | 适配EL检测图分层标注、IV数据分档的文档结构 |
| `maxToken` | 1024 token | 匹配多模态嵌入模型的输入长度限制，适配EL检测图的嵌入需求 |
| 索引维度 | 128 | 匹配业务场景下的向量检索精度与存储成本平衡 |
| `defaultToken` | 512 token | 设置默认分块的token配额，适配结构化参数表的常规长度 |
| 增量更新触发规则 | 按生产批次触发 | 适配光伏电池片每批来料、每批次生产的更新节奏 |

## 容易做错的三处
- 接入多模态Embedding模型时返回Invalid格式的报错：未针对EL检测图、IV分档数据配置多模态嵌入的适配规则，或输入的非结构化数据未通过格式校验。
- 升级新版本后，老向量库数据无法正常检索：未同步更新分块参数与索引维度配置，新旧向量的空间映射不一致，导致检索匹配失效。
- 全量重建索引任务执行失败或超时：未提前清理过期的生产批次数据，导致索引存储超出配额，或分块参数设置超出系统上限。

## 怎么确认配好了
- 在FastGPT v4.17.0版本下，上传单份工艺卡与EL检测图，检查分块结果是否符合预设的最大段落深度与分块长度。
- 调用API发起针对某批次生产数据的检索，验证返回的结果是否关联了正确的生产批次与设备元数据。
- 执行向量库迁移操作，检查迁移后的索引是否能正常召回历史生产批次的相关数据。
- 触发全量重建索引任务，确认任务能正常完成且无报错提示。
