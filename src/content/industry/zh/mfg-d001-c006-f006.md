# 光伏组件封装的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来源于电池片分档、玻璃胶膜背板批次、MES系统、串焊与层压设备、EL/IV测试仪。更新节奏为每块组件、每批材料生成对应记录。日常文档包含排版图、材料批次记录、层压工艺记录、EL图、IV测试报告、绝缘耐压记录、包装清单。字段包含批次编号、供应商代码、层压温度、EL隐裂坐标、峰值功率等，单位涵盖摄氏度、瓦、毫米等专业参数。

## 这些特征在「引用来源与溯源」这一环带来什么约束
每块组件对应独立的溯源数据，要求引用溯源需精准到单组件的批次与测试记录，避免跨组件的错误匹配。高频更新的业务数据要求知识库支持增量同步，确保召回的内容为最新的工艺与测试结果。多类型的文档结构要求召回逻辑需按文档类型分类匹配，优先关联材料批次与测试报告。专业字段如EL隐裂坐标、电流档位需精准匹配，泛化召回会导致审核结果失效，严重时引发客户索赔。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次搜索上限 | 前 8–12 条 | 匹配光伏组件封装多源文档的结构，避免召回过多无关数据 |
| 最大上下文 | 10000–12000 字符 | 容纳材料批次记录、EL图说明等多段溯源内容 |
| 返回来源元数据 | 开启 | 保留供应商代码、批次号、测试参数等关键审核信息 |
| 详情召回开关 | 开启 | 精准匹配单块组件对应的工艺与测试数据 |
| `quoteMaxToken` | 6000–8000 token | 控制溯源信息总长度，避免上下文溢出 |

## 容易做错的三处
- 配置单次搜索上限过低时，召回的来源文档条数不足，界面展示的引用来源为空。未匹配光伏组件封装多份批次文档的召回需求，仅召回少量数据无法覆盖审核所需的完整溯源链。
- 未开启返回来源元数据时，导出的溯源数据仅包含文本内容，无法关联到具体的材料批次或测试报告。忽略了该品类审核需精准关联供应商与批次数据的业务要求。
- 配置知识库关联规则时未指定对应品类的文档目录，导致调用时知识库选项为空。未按照光伏组件封装的文档分类配置导入路径，对应社区中提及的知识库为空问题。

## 怎么确认配好了
- 上传一份光伏组件的材料批次记录与EL图，调用审核功能，查看返回的引用来源是否包含对应文档的元数据。
- 调整`quoteMaxToken`的取值，验证返回的溯源内容是否完整，无截断情况。
- 测试调用时选择指定的知识库，确认界面可直接选定目标知识库，无需手动补充。
- 导出溯源数据，检查是否包含批次号、测试参数等关键字段。
