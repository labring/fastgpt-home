# 光伏组件封装的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
光伏组件封装的业务数据来自电池片分档台账、玻璃胶膜背板批次记录、车间MES系统、串焊与层压设备日志、EL/IV测试仪输出文件。日常产出的文档包含组件排版图、材料批次溯源单、层压工艺参数记录、EL隐裂检测图、IV功率测试报告、绝缘耐压检测记录、成品包装清单。数据更新频率为每块组件生成对应检测记录，每批原材料同步批次档案，字段包含材料规格、工艺参数、检测数值、设备编号与检测时间。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的高频小体量多模态数据特征，要求模型接入时需适配图片格式输入，需开启`vision`配置。多来源的结构化与非结构化数据混合，要求配置项需兼容不同格式的文档解析，同时需限制上下文长度避免冗余信息干扰。每块组件的独立数据更新节奏，要求单次请求的`maxTokens`适配单条检测记录的信息规模，避免超出模型处理上限。业务出错后果严重的特性，要求配置容错机制，处理模型调用失败的场景。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本制定：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启 | 需处理EL图、IV测试报告等图片类检测数据 |
| `temperature` | 0.2–0.4 | 需保证质量判读的一致性，避免随机偏差影响审核结果 |
| `maxTokens` | 800–1200 token | 适配单块组件的检测记录与关联文档的总信息规模 |
| `maxContext` | 4000–6000 token | 限制单次请求的上下文总量，避免冗余数据干扰模型判读 |
| 工作流/API 工具选择配置 | auto | 自动选择是否调用工具处理批次数据匹配与档位查询 |

## 容易做错的三处
- 调用多模态模型时返回格式错误，现象为输出未识别EL图的隐裂描述。原因是未开启`vision`配置，模型无法解析图片类输入数据。
- 模型调用超时或返回空结果，现象为工作流节点状态显示超时错误。原因是`maxContext`或`maxTokens`设置过大，超出模型处理上限。
- 未配置失败重试机制，现象为不稳定模型调用失败后工作流直接终止。原因是未通过工作流的异常分支配置备用模型调用逻辑，未覆盖模型不稳定的场景。

## 怎么确认配好了
- 上传一张EL测试图，触发模型调用，检查输出是否包含图片内容的判读结果，确认`vision`配置生效。
- 导入单块组件的完整检测记录，核对模型输出的上下文长度是否符合预设范围，确认`maxContext`与`maxTokens`配置合理。
- 模拟模型调用失败的场景，验证工作流是否自动切换至备用模型，确认容错机制配置正确。
- 核对API相关配置，发起测试调用，确认接口返回正常的审核结果。
