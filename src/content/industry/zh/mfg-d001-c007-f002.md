# 冲压与板材成形的供应商与过程质量审核：向量模型与索引

以下配置适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类数据主要来自汽车覆盖件、家电钣金、五金件企业的冲压车间，日常文档包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录。数据来源包括钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、MES系统、三坐标或检具检测数据。数据按每卷料、每批生产批次、每次换模操作更新，单份文档包含钢号、材料厚度、模具编号、检测尺寸、压边力参数等字段，单位涉及毫米、千牛、批次号等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据更新频率高且场景分散，包含结构化的设备运行参数、非结构化的质检记录与表单文档。不同来源的数据字段差异较大，需确保向量模型兼容多格式内容，避免索引时出现字段匹配偏差。换模与生产批次带来的增量数据频繁，索引构建需支持增量更新，避免全量重建的耗时问题。同时，数据需绑定模具编号、生产批次等关键标识，向量索引需保留这些关联字段，以支撑供应商与过程质量审核场景下的精准关联检索。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 该品类文档多为短段落的作业指导书与检测记录，过长分块会丢失局部关联信息 |
| 重叠长度 | 100–150 字符 | 换模记录、首末件记录等文档存在连续逻辑，重叠分块可保留上下文关联 |
| `defaultToken` | 2048 | 该品类的单份文档平均token数适配该阈值，避免截断关键参数 |
| `maxToken` | 8192 | 适配主流embedding模型的最大token限制，避免模型调用报错 |
| 相似度阈值 | 按实测标定 | 不同审核场景的匹配精度需求存在差异，需结合实际检索结果调整 |
| 单次搜索上限 | 前 8 条 | 该品类的质量审核需关联多份关联文档，过多结果会增加后续处理耗时 |
| 最大上下文 | 4000–6000 token | 审核场景需关联模具、批次、检测数据等多份文档的内容，足够的上下文可支撑完整推理 |

## 容易做错的三处
- 界面提示“没有可用的渠道”，且配置了第三方embedding模型的API密钥。原因是未在分组管理中为对应模型开通知识库问答权限，或未正确配置模型的调用渠道。
- 检索过程耗时过长，且知识库采用直接分段或自动分段设置。原因是分块长度设置过大或重叠长度过高，导致单批次检索的向量数据量超标，或未启用合理的检索优化策略。
- 界面提示“模型token超出限制”，且配置了第三方embedding模型。原因是`maxToken`的设置值小于模型的最大支持token数，导致模型调用报错。

## 怎么确认配好了
- 进入向量模型配置页面，检查已添加的embedding模型是否显示为可用状态，核对API密钥与渠道配置是否与实际部署一致。
- 执行一次小批量文档的索引构建，查看索引进度日志中是否出现字段解析错误或截断提示，确认分块参数的适配性。
- 发起一条质量审核相关的测试查询，查看检索结果的关联字段是否包含模具编号、生产批次等关键标识，确认索引的关联逻辑正常。
- 查看系统的检索耗时统计，对比调整配置前后的耗时变化，确认参数设置符合场景需求。
