# 化妆品生产的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自护肤、洗护、彩妆及特殊化妆品生产企业的多类业务文档，包括配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验单据、标签审核文件。数据来源涵盖注册备案配方、原料安全资料、生产设备、ERP/MES系统、实验室数据及包材版本记录，更新频率为每批生产或每次换线时触发。文档字段包含原料名称、用量、限用物质含量、批次号、操作时间、检验结果、宣称内容等，部分单据需关联备案编号与包材版本信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多项约束。高频率的批次级更新要求索引支持增量同步，避免每次换线或新批次生产时重复处理全量历史数据。文档中包含受备案约束的合规字段，如限用物质含量、备案编号，需确保分块时不割裂合规关联内容，保证检索时语义完整。多源异构的数据格式，包括结构化设备日志、非结构化检验报告与标签文本，需要统一的分块规则适配不同文档结构，同时保留字段间的关联关系，避免检索时丢失关键上下文。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配配方工艺单、检验记录等文档的语义完整性，避免拆分限用物质含量、备案编号这类关键合规字段 |
| 重叠长度 | 50–100 字符 | 保留跨分块的上下文关联，确保批次号、操作时间这类跨段落的字段不被割裂 |
| maxToken | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.75–0.85 | 匹配合规复核的精准度需求，过滤低相关性的非合规内容 |
| 单次搜索上限 | 前 10 条 | 控制检索结果数量，避免服务器在多批次数据场景下负载过高 |
| defaultToken | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 现象：上传10M以上的配方工艺单或检验记录时，分块后出现部分chunk向量化异常，界面显示报错或字段为空。原因：未针对高频率批次更新的文档调整分块与向量化参数，导致大文件分块过多超出本地模型的处理上限。
- 现象：本地CPU服务器部署ollama后，更新FastGPT版本至4.9至4.10区间，原索引的知识库无法返回检索结果。原因：版本升级后向量模型的嵌入维度或索引格式发生变更，未重新生成对应知识库的向量索引。
- 现象：多批次生产数据同时上传导致服务器崩溃，重启后知识库处于未就绪状态，无法自动完成索引。原因：未配置增量索引触发规则，全量索引任务在服务器异常中断后未自动恢复，需手动触发重建。

## 怎么确认配好了
- 上传单份符合品类特征的文档，检查分块数量与向量化状态，确认无异常提示。
- 检索预设的合规字段内容，验证返回结果的相关性符合业务复核的需求，按需调整对应配置项。
- 触发一次增量索引任务，确认任务完成后知识库状态更新为就绪，无卡顿或报错。
- 验证跨版本的索引兼容性，确认升级后原有知识库可正常检索。
