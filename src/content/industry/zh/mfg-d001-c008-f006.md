# 化妆品生产的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
该品类数据来自护肤、洗护、彩妆及特殊化妆品生产企业的日常业务文档，包括配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品与成品检验报告、标签审核文件。数据来源涵盖注册或备案配方、原料安全资料、生产设备日志、ERP/MES系统、实验室检测结果及包材版本文件，更新频率为每批生产或每次换线，文档包含原料名称、批次号、操作参数、检验结果、备案编号等字段，无额外自定义单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
每批生产或每次换线的高频更新，要求引用来源与溯源系统需快速匹配最新批次数据，避免引用过期的配方或包材信息。多来源的业务数据需统一对齐备案编号、原料批次、生产批号等核心字段，确保不同文档间的引用关联准确。配方、标签等受备案约束的内容需严格关联官方注册备案文件，无法仅依赖内部业务记录。感官与稳定性检验的半结构化数据需明确关联对应生产批次的操作记录，确保溯源链路完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配单批化妆品生产文档的平均长度，完整覆盖配方工艺、检验记录等核心内容 |
| `responseData` | 仅返回备案编号、原料批次、生产批号 | 聚焦溯源所需的核心关联字段，减少非必要数据的匹配干扰 |
| `detail` | 开启 | 允许返回完整文档片段，用于复核配方与备案的一致性 |
| 单次搜索上限 | 前5条 | 匹配每批生产的关联文档数量，避免冗余结果影响检索效率 |
| 检索匹配阈值 | 按实测标定 | 适配化妆品生产中备案编号、批次号等强匹配字段的检索规则 |

本配置基于FastGPT v4.17.0版本

## 容易做错的三处
- 现象：知识库搜索环节选择变量引用时，无备案编号、生产批号等可选字段。原因：未将生产批次、备案编号等核心字段映射为可引用变量，或未配置关联的数据源节点。
- 现象：线上环境抛出Cannot redefine property: toString报错。原因：自定义逻辑中重复定义了toString方法，与系统内置的引用溯源处理逻辑产生冲突。
- 现象：检索结果中召回了非当前生产批次的清场记录或配方文档。原因：未添加按生产批号、备案编号过滤的检索条件，导致关联了过期的历史数据。

## 怎么确认配好了
- 发起一次针对当前生产批次的溯源检索，检查返回结果中是否包含对应批次的配方工艺单、检验记录。
- 查看变量引用下拉列表，确认备案编号、生产批号等核心字段已作为可选变量出现。
- 模拟调用自定义逻辑，检查是否未抛出Cannot redefine property: toString类的报错。
- 对比检索结果与实际生产文档，确认仅召回当前批次或关联备案的有效文档。
