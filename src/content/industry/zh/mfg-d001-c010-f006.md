# 医疗器械装配与洁净生产的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
这个品类的核心数据来自设计历史文件、器件与材料批次台账、MES系统、洁净环境监测设备、灭菌设备、检验校准系统。日常生成的文档包含生产工艺规程、批生产记录、洁净区温湿度与压差记录、灭菌批记录、第三方检验报告、软件版本日志、不良事件与追溯资料。数据更新频率为每批或每台器械一次，洁净环境监测数据按既定监测计划更新。文档字段包含唯一器械标识（UDI）、批次号、灭菌参数、洁净区指标、检验结果等，单位涵盖℃、Pa、分钟、批次编号字符串等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源分散的数据需要关联不同系统的批次台账信息，对跨源召回的准确性提出要求。高频更新的批记录与监测数据，要求溯源流程支持近实时的文档检索与更新。多样的文档结构包含结构化的批次台账与非结构化的工艺规程，需要适配不同格式的内容拆分与匹配。关键字段如UDI、批次号的精准匹配需求，要求检索逻辑优先关联核心标识字段。严重的出错后果，要求溯源结果可完整追溯至原始文档与数据来源，避免错引或漏引。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前6条 | 覆盖单批医疗器械生产涉及的材料、灭菌、检验等核心文档，满足供应商审核的多文档关联需求 |
| 最大上下文 | 12000–15000 字符 | 容纳多份关联的批记录、洁净区监测数据的完整片段，支撑完整的审核逻辑 |
| 重排 | 开启 | 优先匹配UDI、批次号等关键溯源字段的内容，提升精准召回率 |
| `quoteMaxToken` | 8000 token | 确保召回的文档片段足够支撑溯源与审核逻辑，避免内容截断导致的信息缺失 |
| `responseData` | 返回关联批次ID与文档来源路径 | 满足合规性溯源要求，便于审核人员核对原始数据 |
| `detail` | 开启 | 展示文档片段的具体字段与数值，便于审核人员快速定位关键审核点 |

## 容易做错的三处
- 工作台知识库简单应用中发起供应商审核查询时，每次仅返回1条文档，无法关联多份批记录与检验报告。原因是单次搜索上限配置过低，未覆盖单批生产涉及的多文档关联场景。
- 导入预设的JSON格式知识库后，知识库选择下拉框无默认选项，需手动配置关联路径。原因是未为导入的知识库添加元数据标签与默认关联规则。
- 配置`responseData`后测试模型提示错误，强行忽略后可正常运行引用。原因是测试环境的上下文长度未匹配正式运行的配置，或测试接口权限未完全开放。

## 怎么确认配好了
- 导入单批医疗器械生产的所有关联文档，发起“核对该批次供应商材料、灭菌与洁净记录”的查询，检查返回的引用条数是否符合配置的单次搜索上限。
- 查看返回结果的`responseData`字段，确认包含批次ID、文档来源路径等溯源所需的核心信息。
- 调整`quoteMaxToken`的取值，验证返回的文档片段长度是否适配审核人员的查看与核对需求。
- 模拟缺失某份核心文档的场景，检查系统是否提示缺失的溯源来源，确认异常场景的提示逻辑正常。
