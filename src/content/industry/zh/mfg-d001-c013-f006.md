# 印刷与包装加工的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
该品类覆盖彩印、标签、纸箱、软包装及药包材生产全流程，日常文档包含印前文件、拼版单、印刷工艺单、油墨配色记录、首件签样、条码检测及模切与复合记录。数据来源包括客户稿件、色彩管理系统、印刷机运行数据、油墨与基材批次台账、分光仪检测结果、条码检测仪读数。数据更新随每订单、每批生产或每次印版更换触发，单份文档包含版本号、批次号、色彩参数、检测结果等字段，单位随检测项或工艺参数调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的工艺文档与检测数据随生产批次、印版更换频繁更新，需确保溯源引用的是对应批次的准确版本，避免跨批次数据混淆。多源数据（如印刷机运行数据与分光仪色彩检测结果）需明确绑定同一生产环节，否则会导致审核依据冲突。印前文件与版次关联紧密，引用溯源需绑定版次ID防止错版引用。条码、模切等检测数据需精确匹配批次号，否则无法支撑质量审核的合规性校验。单份订单的多环节数据需按生产顺序关联，避免溯源时出现环节错位。

## 配置怎么定
本页配置基于 FastGPT v4.17.0 版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 该品类单份核心工艺文档的有效内容长度多在此区间，可覆盖完整审核依据 |
| `responseData` | 开启 | 需完整返回批次台账、检测报告等溯源数据，支撑供应商与过程质量审核 |
| `detail` | 高 | 印刷包装的色彩参数、版次ID等需精确匹配，避免模糊引用导致审核偏差 |
| 引用变量范围 | 绑定当前生产批次 | 该品类数据按订单、批次更新，需限定变量仅调用对应批次的数据源 |
| 单次引用上限 | 前3–5条 | 单批次审核的核心依据通常不超过5份文档，过多会干扰模型审核逻辑 |

## 容易做错的三处
- 现象为工作流中知识库搜索节点的引用变量下拉框无可选值，无法动态指定对应批次的知识库。原因是未将生产批次变量设置为全局可调用范围，或未绑定当前生产批次的数据源权限。
- 现象为日志中无法区分不同来源的生产数据，字段内容重复或无明确标识。原因是未在数据导入时添加来源标识字段，或未配置日志的来源区分规则。
- 现象为模型生成的回答中出现未匹配实际提交数据的伪造引用ID。原因是未开启`detail`配置项，或`quoteMaxToken`设置过小导致无法获取完整溯源数据，模型无法验证引用合法性。

## 怎么确认配好了
- 触发模拟生产批次的审核流程，检查知识库搜索节点的引用变量下拉框是否显示对应批次的可选数据源，确认变量配置范围正确。
- 查看流程日志，确认每条溯源数据都带有可区分来源的标识，可识别印刷机数据、检测报告等不同类型的数据源。
- 核对模型生成回答中的引用ID与提交的溯源数据ID是否匹配，验证引用的准确性。
- 调整`quoteMaxToken`的取值，查看返回的溯源内容长度是否符合配置要求，确认参数生效。
