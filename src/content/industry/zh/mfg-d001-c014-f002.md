# 印染与后整理的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
典型主体为染整厂、面料企业的染色、定形、实验室与质量部门。日常文档包含染色配方、称化料记录、染缸曲线、打样确认、色差报告、定形工艺单、污水台账。数据来源为客户色样、配方库、染化料批次、染缸控制设备、测色仪、定形机、环保监测设备。更新频率为每缸、每批、每班。数据字段包含色差值、升温速率、加料量、保温时长等，单位涉及ΔE、℃、kg、小时等，单条记录多为与生产批次强关联的时序数据。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的生产数据以批次强关联的时序记录为主，单条记录包含专业数值与工艺文本的混合内容，要求向量索引需支持多特征融合的语义召回。高频次的每缸/每批更新会带来增量索引的频繁写入需求，需适配小批量、高频的索引更新逻辑。色差值、染缸曲线等专业数值型字段的向量匹配，需选择适配数值特征的嵌入模型，避免通用模型对专业语义的偏差。同时，污水台账等合规类数据需单独建立索引隔离，防止跨业务场景的无关召回。多语言的色样描述与工艺说明，也会对分块与向量编码的一致性提出要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配染缸曲线、染色配方等长文本的语义完整性，避免拆分破坏工艺逻辑 |
| 重叠长度 | 100–150 字符 | 保留相邻缸次工艺的关联信息，减少分块间的语义断层 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 8192 token | 支持完整染缸工艺曲线的向量编码，避免截断关键升温、加料参数 |
| 相似度阈值 | 按实测标定 | 适配色差值ΔE等专业数值的匹配精度，满足实验室审核的召回要求 |
| 单次搜索上限 | 前 10 条 | 匹配质量审核时的样本比对量级，兼顾召回效率与结果准确性 |

## 容易做错的三处
- 切换向量模型后知识库无进度且无法切回原模型，原因是未先执行全量知识库重嵌入操作，直接切换模型导致索引映射关系断裂。
- 配置嵌入模型后测试返回404错误，原因是未正确配置模型渠道的API密钥与请求端点，或端点路径与平台要求不匹配。
- 批量重嵌入后多语言召回效果差，原因是分块时未保留原语言的语义边界，且未针对多语言场景调整分块与向量匹配逻辑。

## 怎么确认配好了
- 查看FastGPT v4.17.0的知识库配置页面，确认当前使用的嵌入模型与预设配置一致，检查`defaultToken`与`maxToken`的配置是否与所选模型匹配，同时确认API密钥与端点填写完整。
- 上传单条染色配方文档，执行向量嵌入测试，查看嵌入进度条是否正常推进，无报错提示。
- 发起包含色差值、染缸参数的检索请求，核对返回结果的关联度符合业务审核的匹配逻辑，调整相似度阈值至合适范围。
- 执行增量嵌入测试，上传新的染缸生产记录，确认索引更新无延迟，新增数据可被正常召回。
