# 印染与后整理的供应商与过程质量审核：知识库检索与召回

## 这个品类的数据长什么样
该品类数据来自客户色样、配方库、染化料批次记录、染缸运行数据、测色仪报告、定形机参数、环保监测台账等。日常文档包含染色配方、称化料台账、染缸温度曲线、打样确认单、色差分析报告、定形工艺单、污水排放记录。数据更新以每缸、每批、每班为节奏，单份文档包含工艺参数、批次编号、检测数值、操作人员等字段，涵盖温度、浓度、批次号、排放指标等单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的高频更新、批次强绑定的特征，要求知识库检索需优先召回最新批次的文档，避免使用过期工艺数据。多结构化的工艺参数与检测报告文档，要求检索支持数值区间匹配与文本语义结合的混合查询。设备直连与人工记录并存的数据来源，带来字段格式差异，需配置兼容的召回规则以覆盖不同格式的同类型数据。单缸染色全流程关联多份文档，检索需支持跨文档的关联召回，避免割裂关键工艺信息。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配印染工艺参数的精度要求，避免召回不相关的旧批次数据 |
| `limit` | 前8条 | 覆盖单缸染色关联的多份文档数量，同时控制检索返回的上下文长度 |
| `searchMode` | semantic | 适配染色配方、色差报告的语义匹配需求，支持跨文档的工艺关联 |
| `usingReRank` | 开启 | 对召回结果按工艺相关性重排，修正单纯语义匹配的排序偏差 |
| `datasetSearchUsingExtensionQuery` | 开启 | 针对工艺关键词扩展语义查询，覆盖不同表述的同类型工艺参数 |
| `collectionIds` | 按业务线绑定的知识库集合 | 隔离不同订单、不同车间的工艺数据，避免跨批次的无效召回 |

## 容易做错的三处
- 现象：知识库搜索返回结果相关性整体偏低，部分结果与当前染色批次无关。原因：未设置合理的`similarity`阈值，或未开启`usingReRank`重排，导致低相关性的旧批次数据被优先召回。
- 现象：无法通过关键词精准匹配到特定染缸的温度曲线数据。原因：未开启`datasetSearchUsingExtensionQuery`，未对工艺关键词进行语义扩展，无法覆盖不同表述的同类型参数。
- 现象：上传的称化料记录文档无法被对应车间的检索场景调用。原因：未按业务线绑定`collectionIds`，导致文档被归入错误的知识库集合，无法被对应订单或车间的检索访问。

## 怎么确认配好了
- 执行单缸染色工艺的关键词查询，核对返回结果的批次编号与当前查询的订单批次一致。
- 上传一份新的染缸曲线文档，执行对应参数的检索，确认新文档被正常召回。
- 调整`similarity`阈值，观察返回结果的数量变化，确认阈值配置生效。
- 开启`usingReRank`后，对比重排前后的结果顺序，确认重排功能正常运行。
