# 原料药与医药中间体生产的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
数据来源涵盖注册工艺文件、原料批次台账、DCS生产数据、称量系统记录、LIMS检验数据、色谱数据系统报告及QMS偏差变更文档。更新节奏为每生产批次、每工艺步骤触发一次。日常文档包括批生产记录、物料平衡表、反应与精制记录、清洁验证记录、杂质谱报告、偏差与变更申请文件。核心字段包含原料批次号、反应温度与时间、杂质含量数值、溶剂残留量、收率数据，单位涉及mg/kg、ppm、小时等专业化工参数。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源分散的数据来源要求溯源系统需跨系统关联不同类型的专业文档，避免单一数据源的局限性。高频次的按批更新要求溯源配置需支持实时关联最新生产批次的记录，确保审核依据的时效性。结构化与半结构化的文档格式要求溯源匹配需精准对应批次号、杂质参数等专属字段，避免泛化匹配导致的错误关联。复杂的工艺步骤与变更关联要求溯源范围需覆盖多环节的关联文档，确保审核逻辑的完整性。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 1500–2000 token | 匹配单份杂质谱报告、批生产记录的完整内容长度 |
| `responseData` | 包含来源文档ID、原料批次号、反应参数 | 关联原料药生产审核的核心溯源字段 |
| `detail` | 开启 | 展示完整的检验原始数据与工艺记录细节 |
| 单次搜索上限 | 前8条 | 覆盖多步合成反应的关联文档数量 |
| 最大上下文 | 4000–5000 字符 | 容纳完整的物料平衡与偏差变更文件内容 |

## 容易做错的三处
- 现象：返回的审核答案与引用的知识库内容无关联，引用文档未涉及当前批次的杂质或工艺参数。原因：未针对原料药生产的专属字段（如批次号、杂质谱）配置精准召回规则，导致召回文档与场景不匹配。
- 现象：无法隐藏指定查询的引用来源内容，所有结果均强制显示原文链接。原因：误将全局可见度配置应用到了供应商审核的专用流程，未区分不同场景的可见度权限。
- 现象：部分杂质谱报告、清洁记录未生成问答对，直接以原文形式嵌入知识库。原因：未针对结构化的化工专业文档启用专用拆分规则，导致嵌入匹配失败。

## 怎么确认配好了
- 发起包含“XX批次杂质检测结果”的查询，核对返回结果中引用的文档是否包含对应批次的杂质谱报告。
- 查看引用来源的详情，确认包含原料批次号、反应参数等专属字段。
- 测试隐藏引用内容的配置，确认对应查询的结果界面不显示原文链接按钮。
- 上传一份模拟的中间体转序记录，验证系统可生成对应的问答对并正确关联溯源信息。
