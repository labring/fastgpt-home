# 喷涂与涂装的供应商与过程质量审核：工作流编排
本文档适配FastGPT v4.17.0版本的工作流编排功能。

## 这个品类的数据长什么样
喷涂与涂装品类的数据来源包括涂料供应商TDS/SDS文档、喷房与烘炉运行数据、色差仪、膜厚仪采集数据、MES系统工单与质检记录。更新节奏分为三类：每批涂料批次生成对应单据、每班生产周期更新工艺与环保台账、设备数据连续采集。日常文档包含涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账，字段涉及涂层厚度、色差差值、烘炉温度、涂料黏度、VOCs浓度等，对应不同采集节点的专属单位。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据分散且更新节奏多样，要求工作流支持多数据源接入与混合触发规则。不同来源的数据格式差异较大，需适配结构化数据库查询、非结构化文档解析、实时设备数据采集等多种节点类型。最耗时的工序匹配、调色控制、缺陷分析环节，要求工作流可编排并行节点拆分任务，避免串行阻塞。出错后果直接关联产品外观与合规性，需配置失败重试与异常告警节点，保障流程稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按生产批次触发+实时设备数据补全 | 匹配涂装生产的批次节奏与实时参数校验需求 |
| 并行节点上限 | 3-5个节点并行 | 适配喷涂工序多工位并行处理的业务场景，避免资源过载 |
| 失败重试次数 | 2次，间隔60秒 | 应对设备采集波动或临时网络抖动，减少流程中断概率 |
| 告警触发条件 | 当`variables`中检测到异常参数时触发 | 基于预设的质检阈值变量，快速定位质量或合规风险 |
| 单节点超时设置 | 120秒 | 适配烘炉曲线分析、色差计算等耗时环节的处理需求 |
| 变量缓存时长 | 3600秒 | 缓存批次级工艺参数，避免重复读取数据源提升效率 |

## 容易做错的三处
- 现象：DB节点查询数据库后返回空JSON或字段未映射的非结构化数据，无法直接用于后续质检判断。原因：未通过`variables`映射查询结果的指定字段到工作流变量，导致数据未正确传递。
- 现象：并发调用MCP节点达到1秒2-3次时，返回空结果或无响应内容。原因：未设置节点并发上限与超时参数，高并发下系统资源耗尽导致请求失败。
- 现象：循环节点拼接多批次质检结果后，调用飞书Webhook无消息发送。原因：未校验拼接后的文本长度，或未正确传递`nodeId`对应的上下文数据，导致请求参数异常。

## 怎么确认配好了
- 模拟单次生产批次触发工作流，检查各节点输出与涂装工艺卡、涂料批次单的参数是否匹配。
- 调高并发调用频率至1秒2-3次，验证MCP节点无空返回或异常状态码。
- 构造超出阈值的异常参数（如膜厚超标、VOCs浓度超限），检查告警节点是否正常触发。
- 查看工作流运行日志，确认`variables`中的字段均已正确映射并传递到后续节点。
