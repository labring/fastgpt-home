# 喷涂与涂装的供应商与过程质量审核：模型接入与配置

本文适配FastGPT v4.17.0版本的模型接入配置。

## 这个品类的数据长什么样
该品类的日常文档包含涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账，数据来源覆盖涂料供应商TDS/SDS、喷房和烘炉实时采集数据、色差仪、膜厚仪、环境监测设备及MES系统。数据更新节奏随生产流程调整，每批涂料、每班均生成对应台账，烘炉、色差等检测数据为连续采集。文档字段涉及涂料批次编号、膜厚数值、烘炉温度曲线节点、VOCs浓度等业务内容，格式包含结构化系统数据与非结构化电子或纸质文档。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入环节支持结构化传感器数据、半结构化工艺文档、非结构化检测报告的统一格式转换，避免数据解析错误。高频连续采集的烘炉、色差数据要求模型调用的响应延迟匹配生产节拍，避免因延迟导致审核滞后。不同文档的字段差异需要模型能准确识别并关联对应业务字段，确保审核依据的准确性。批次级的更新要求知识库同步频率匹配涂料批次和班次的更新节奏，避免数据滞后影响跨批次的质量关联分析。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | `8000–12000 token` | 需要关联涂装工艺卡、涂料批次单、多份检测报告的内容，覆盖多文档上下文以支撑完整审核逻辑 |
| `maxTokens` | `2000–3000 token` | 适配涂装质量审核结论的输出长度需求，避免截断关键的缺陷分析或整改建议 |
| `quoteMaxToken` | `1500–2000 token` | 保留足够的引用内容，用于关联膜厚、色差等具体检测数据作为审核依据 |
| `temperature` | `0.2–0.4` | 保障审核结论的稳定性，避免随机波动影响质量判断的一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署的代理地址填写，如`https://xxx/v1` | 适配代理平台的模型调用路径，确保请求能正确路由到目标模型 |
| `AIPROXY_API_TOKEN` | 按代理平台生成的有效密钥填写 | 完成模型调用的身份验证，保障接入链路的安全性 |

## 容易做错的三处
- 现象为知识库搜索报错`invalid configuration parameter name "hnsw.max_scan_tuple"`，原因是误将非FastGPT支持的参数填入配置项，未使用指定的配置参数清单。
- 现象为选择大模型开启输出思考功能后无思考过程，原因是模型预设的输出格式未正确配置，或`temperature`取值过高导致生成逻辑出现随机偏差。
- 现象为代理调用时返回模型列表为空，原因是代理地址错误使用了`/v1/models`路径，未匹配代理要求的`/v1/model/list`路径。

## 怎么确认配好了
- 调用模型测试接口，输入涂装质量审核相关的测试问题，检查返回结果是否包含正确的检测数据或工艺文档引用。
- 查看代理调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的请求无认证失败或路径错误。
- 调整`temperature`参数后，多次测试相同的审核问题，检查结果是否保持相对稳定，符合低随机性的审核需求。
- 上传单批次的涂装文档与检测数据，测试知识库召回的内容是否匹配该批次的对应信息，验证数据关联的准确性。
