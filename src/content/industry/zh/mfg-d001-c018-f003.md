# 基础化工连续生产的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
基础化工连续生产的典型数据来源包括DCS/SIS系统、在线分析仪、LIMS实验室管理系统、设备状态监测、能源计量装置、原料储罐数据。数据更新节奏分为实时、每班、每日三类。日常文档涵盖操作规程、工艺指标卡、DCS趋势图、化验报告、联锁旁路记录、特殊作业票、班报。数据字段包含反应温度（℃）、系统压力（MPa）、物料流量（m³/h）、联锁编号、作业票编号等，单位符合化工生产的通用计量标准。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
实时更新的生产数据要求对话上下文不能包含过旧的冗余信息，需限定检索和对话的时间范围。多类型文档需要提示词明确区分检索场景，例如优先调用工艺指标卡核对参数，或调取联锁旁路记录确认合规性。多数据源的关联需求要求配置绑定对应生产单元的专属标识，避免不同装置的审核数据混淆。固定的字段与单位需要提示词统一校验格式，确保返回的审核结果符合化工生产的计量规范。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本，具体参数如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配单页工艺指标卡、DCS趋势单条记录的内容长度，避免截断关键参数 |
| 重叠长度 | 150–200 字符 | 覆盖工艺参数跨块的连续描述，确保联锁逻辑的完整检索 |
| 单次搜索上限 | 前6条 | 匹配每班生成的班报、化验报告的单批次条目数，避免冗余数据干扰 |
| 最大上下文 | 前3轮对话 + 实时数据快照 | 适配实时数据的时效性，减少旧数据对当前审核的影响 |
| `chatId` 配置 | 绑定装置编号 | 关联对应生产单元的专属数据，隔离不同装置的审核信息 |
| `variables` 配置 | 注入当前班组、原料批次 | 匹配实时更新的生产参数，精准匹配当前审核场景 |

## 容易做错的三处
-  配置`messages`时仅传入历史文本未绑定`chatId`，导致不同生产装置的审核对话上下文互相干扰，出现跨装置的数据混淆。
-  对话组件的AI回复注释配置为仅在stream回复完毕后触发，无法在审核过程中实时调用DCS实时数据，导致返回的注释内容滞后于当前生产状态。
-  迁移知识库后，在知识库页面能看到所有文字内容，但对话时模型提示知识库为空，原因是未配置`variables`绑定当前关联的原料储罐数据，导致检索范围未匹配到已迁移的对应文档。

## 怎么确认配好了
-  发起包含当前班组、原料批次的测试对话，检查返回内容是否包含对应装置的实时工艺参数。
-  导入已迁移的历史化验报告，发起对应审核问题，确认模型能正确检索到文档内容。
-  上传xlsx格式的联锁旁路记录，发起检索请求，检查是否能提取到对应联锁编号的内容。
-  查看`chatId`绑定的装置编号，确认不同装置的对话上下文不会互相混淆。
