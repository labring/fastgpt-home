# 基础化工连续生产的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
基础化工连续生产的典型主体包括氯碱、合成氨、甲醇、纯碱等企业，日常文档涵盖操作规程、工艺指标卡、DCS趋势、化验报告、联锁旁路记录、特殊作业票、班报。数据来源为DCS/SIS、在线分析仪、LIMS、设备状态、能源计量、原料储罐，更新节奏包含实时、每班、每日。数据字段包含工艺参数的压力、温度、流量单位，化验结果的浓度、纯度单位，以及设备运行状态编码。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的多源实时数据与分时段更新文档，要求溯源系统需支持按数据采集时间精准匹配引用，避免跨时段的无效关联。强联锁与危险介质的业务特性，要求引用的联锁旁路记录、特殊作业票等文档必须精准对应审核时段，不能混入无关记录。多类型文档的结构差异，要求溯源展示需适配不同格式的字段，如结构化的DCS趋势需展示时间戳与参数值，半结构化的作业票需展示审批人与作业时间。大宗连续生产的特性要求溯源数据的覆盖范围需匹配全流程的工艺节点，避免遗漏关键环节的引用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 基础化工的工艺文档与实时数据总长度较长，需覆盖完整的反应、分离、循环系统逻辑 |
| `quoteMaxToken` | 1500–2000 token | 单条溯源数据需保留足够的工艺参数细节，避免截断关键指标与联锁信息 |
| 知识库最大引用 | 前6条 | 该品类的核心数据来源集中在DCS、LIMS等6类系统，过多引用会超出上下文限制 |
| 最大响应tokens | 3000–4000 token | 审核报告需包含溯源信息与工艺分析，需预留足够空间展示完整内容 |
| `responseData` | 开启 | 需返回完整的引用来源元数据，包括数据采集时间、所属系统与文档类型 |
| `detail` | 开启 | 需展示溯源数据的具体字段，如化验结果的浓度值、DCS的实时压力值 |

## 容易做错的三处
- 现象：生成的审核报告中出现红色报错标记，无法正常展示引用来源。原因：未正确配置`quoteMaxToken`参数，导致引用数据的token超出限制，触发格式校验失败。
- 现象：返回的引用列表包含非工艺相关的文档，如行政类通知。原因：未通过变量限定知识库搜索的数据源范围，未筛选DCS、LIMS等核心系统的文档。
- 现象：调用接口后响应结果中未携带引用来源信息。原因：未开启`responseData`参数，未启用溯源数据返回功能。

## 怎么确认配好了
- 上传该品类的典型文档，如DCS趋势图、月度化验报告，发起供应商与过程质量审核请求，检查响应中是否包含对应文档的溯源信息。
- 进入FastGPT v4.17.0的配置界面，查看`quoteMaxToken`、`responseData`等参数的取值，确认符合预设规则。
- 发起包含多类数据源的测试请求，检查引用列表仅包含工艺类文档，未混入无关内容。
- 测试包含完整工艺流程的审核请求，确认响应未被截断，且所有引用数据的具体字段完整展示。
