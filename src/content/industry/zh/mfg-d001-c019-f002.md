# 塑料注塑成型的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来源包括树脂批次与物性表、注塑机运行参数、模温机数据、生产MES系统、尺寸与外观检测结果。日常文档涵盖注塑工艺卡、原料干燥记录、模具履历、首件检验表、班组巡检表、换料清机记录。数据更新随生产批次、换模换料操作、每班生产节奏触发，单条数据包含工艺参数数值、设备运行时长、检测结果等字段，部分字段带有℃、MPa、小时等单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据随生产批次、换模换料、每班生产高频更新，要求索引支持增量刷新，避免全量重建占用过多计算资源。日常文档包含多类结构化半结构化内容，字段带有不同单位与业务含义，向量分块时需保留字段关联信息，避免拆分后丢失业务上下文。单条数据参数精度要求高，向量模型需适配数值型字段的编码逻辑，同时索引需支持按生产批次、模具编号等维度过滤召回结果，确保审核时的上下文匹配精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配注塑工艺卡、巡检表等文档的单段业务信息长度，避免拆分后丢失工艺参数关联 |
| 重叠长度 | 50–80 字符 | 保留相邻分块的参数上下文，防止换料清机记录的关键信息被拆分 |
| 相似度阈值 | 0.75–0.85 | 匹配注塑工艺参数、检测结果的相似性需求，过滤低相关性的历史数据 |
| 向量数据库连接 | 对接自有Qdrant实例 | 适配自定义向量数据库需求，无需迁移现有生产环境的存量数据 |
| `maxToken` | 4096 token | 适配腾讯混元等大模型的输入长度限制，确保完整传入工艺卡与检测记录的上下文 |
| `defaultToken` | 1024 token | 配置基础上下文窗口，满足常规审核场景的信息展示需求 |

## 容易做错的三处
- 召回结果中混入不同模具编号的注塑工艺参数。原因：未配置按模具编号、生产批次的索引过滤规则，导致召回范围覆盖无关生产批次的数据。
- 向量搜索请求超时。原因：分块长度设置超过1500字符，且单次搜索上限设置为前15条，超出FastGPT v4.17.0的基础处理阈值。
- 匹配结果包含不同树脂批次的物性数据，引发混料风险误判。原因：未按树脂批次维度配置索引过滤，导致跨批次数据被错误匹配。

## 怎么确认配好了
- 上传单份注塑工艺卡文档，触发向量索引生成，查看分块后的文本片段是否保留完整的工艺参数与单位信息。
- 发起一次针对特定模具编号的审核查询，确认召回结果仅包含该模具的历史生产数据，无跨模具的无关内容。
- 测试`maxToken`配置，输入一段完整的注塑工艺卡与检测记录，确认返回的上下文未被截断。
- 调整相似度阈值后发起重复查询，观察召回结果的数量变化是否符合预期。
