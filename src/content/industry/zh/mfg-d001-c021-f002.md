# 家具与木制品制造的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类主体包含板式家具、实木家具、定制家居及木门企业，日常产生的文档涵盖拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金物料清单、试装及包装记录。数据主要来自订单设计系统、板材与木材批次台账、数控开料钻孔设备、ERP/MES系统及含水率检测设备，更新节奏随单份订单、每日或单批材料批次变动，核心字段包含板件尺寸、物料编号、工艺参数、检测结果等。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且格式不统一，需在索引前完成跨系统文档的格式标准化处理。文档包含结构化清单与非结构化工艺图纸，向量模型需兼顾文本与图像特征的提取，适配多类型文档的索引需求。更新频率随订单与批次变动，索引需支持增量同步以匹配实时数据节奏，避免全量重建的资源消耗。定制化订单导致单份文档的长度与结构差异较大，分块策略需适配不同长度的内容单元，确保向量提取的完整性。

## 配置怎么定
以下配置基于FastGPT v4.17.0适配该品类场景：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类拆单图说明、开料清单等文档的平均长度，避免单块内容过长导致向量提取偏差 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，确保检索时不会丢失跨块的工艺参数信息 |
| 相似度阈值 | 0.75–0.85 | 精准匹配板件尺寸、五金型号等关键审核参数，避免低相似度的无关结果干扰判断 |
| 单次搜索上限 | 前 8 条 | 覆盖该品类单订单的典型板件数量，同时控制检索过程的资源开销 |
| `maxToken` | 4000 token | 适配涂装工艺、试装记录等长文本文档的向量索引上限，避免内容截断丢失关键信息 |
| `defaultToken` | 150 token | 优化五金清单、批次台账等短文本内容的向量提取效率 |

## 容易做错的三处
- 现象：接入通义多模态向量模型时触发调用失败，界面返回“模型不支持当前调用方式”的报错文案。原因：未按照系统要求配置多模态模型的接入规则，导致系统无法完成模型调用链路的校验。
- 现象：检索结果出现大量无关的板件尺寸数据，匹配精度未达到审核要求。原因：未针对该品类的核心审核字段调整向量模型的权重，直接使用通用参数进行检索。
- 现象：自定义RAG检索仅返回单份文档的内容，无法关联板件与安装现场的尺寸匹配关系。原因：未配置向量索引与关系图谱的联动逻辑，仅基于扁平化实体进行检索，未引入跨文档的关联关系。

## 怎么确认配好了
- 上传该品类典型的开料清单与拆单图，确认索引生成状态无报错，文档内容未出现异常截断。
- 输入针对板件尺寸或五金型号的审核查询，核对检索结果的相关性是否符合预设的匹配逻辑，结果数量与配置的单次搜索上限一致。
- 调整向量模型的配置参数后，重新生成索引并执行检索，确认结果的相关性随参数调整发生符合预期的变化。
- 测试多模态模型接入后的图纸检索功能，确认上传拆单图后可返回关联的工艺参数与开料数据。
