# 家具与木制品制造的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
该品类数据主要来自订单设计系统、板材与木材批次台账、数控开料钻孔设备日志、ERP/MES系统及含水率检测设备。日常文档包含个性化拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金物料清单、试装及包装记录。数据更新节奏随订单、每日或每批材料变动，单订单关联的板件数据量较多，字段包含尺寸、材质批次、含水率、孔位参数等，通常这类数据无统一固定的标准化BOM结构。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的个性化订单驱动特征，要求模型接入需适配非标准化的拆单图、开料清单等文档。多来源的批次数据更新节奏，要求配置时需关联数据时间戳，避免调用过期参数。单订单关联大量板件数据的特点，需限定单次请求的token上限，防止模型处理过载。同时，现场设备的高频日志数据，需配置合理的上下文窗口长度，确保调用时仅加载最新的生产参数。在FastGPT v4.17.0版本中，还需注意适配企业内部数据隔离的需求，避免敏感生产参数外流。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 800–1200 字符 | 适配该品类单订单多板件的文档总量，避免上下文溢出 |
| `maxTokens` | 4000–8000 token | 匹配定制家具订单的多文档解析需求，平衡处理速度与内容完整性 |
| `quoteMaxToken` | 1500–2000 token | 限定召回文档的总token量，确保核心开料、五金参数优先被模型读取 |
| `temperature` | 0.2–0.4 | 保持审核结果的一致性，避免工艺参数或尺寸的随机偏差 |
| `AIPROXY_API_ENDPOINT` | 填写本地部署的代理地址 | 适配企业内部数据隔离需求，避免敏感生产数据外流 |
| `AIPROXY_API_TOKEN` | 使用企业专属鉴权密钥 | 保障模型调用的安全性，限制未授权访问 |

## 容易做错的三处
- 现象：本地部署FastGPT v4.17.0后，配置的外部模型未出现在可用模型列表中。原因：未正确填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或代理服务未正常响应鉴权请求。
- 现象：工作流中编排多模型节点时，不同订单的审核结果出现参数混淆。原因：未通过`maxContext`限定单订单的上下文范围，导致跨订单的生产数据被混合加载。
- 现象：模型调用返回超时提示，且日志显示请求耗时超过300秒。原因：`maxTokens`取值超出模型服务的处理上限，或未配置合理的请求超时策略。

## 怎么确认配好了
- 访问FastGPT后台的模型渠道管理页面，确认已填写的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`与企业内部部署的代理服务一致。
- 上传单份定制家具订单的拆单图、开料清单及五金清单，触发模型审核，检查返回结果是否覆盖该订单的所有核心生产参数。
- 在工作流中编排两个独立的模型审核节点，分别关联不同批次的板材数据，确认两个节点的审核结果未出现参数混淆。
- 查看模型调用的详细日志，确认每次请求的上下文长度与token上限符合预设配置，无超出限制的报错信息。
