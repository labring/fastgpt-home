# 家用电器整机制造的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
本品类涵盖空调、冰箱、洗衣机及小家电整机制造，日常文档包含配置BOM、装配作业书、制冷剂充注记录、电气安全测试报告、性能抽检报告与返修记录。数据来源覆盖ERP/MES系统、零部件批次台账、拧紧与充注设备日志、安规测试仪数据、性能实验室检测结果及售后故障记录。数据更新节奏按单台产品、每班生产批次或抽检计划执行，单条数据包含零部件编号、工艺参数、检测结果、批次标识等字段。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多型号混线装配的生产模式要求溯源时精准绑定单台产品的零部件批次、工艺参数与检测结果，避免不同型号数据混淆。高频更新的单台、每班生产数据，要求溯源链路能快速定位对应生产批次的全量记录，防止跨批次数据干扰判断。多源数据来源覆盖设备日志、系统台账与售后记录，需要统一的引用规则确保溯源时可反向关联从生产到售后的全环节数据。安规、性能检测的严格合规要求，让溯源环节需明确引用来源的可信度标识，避免无效或错误数据被纳入审核判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 适配单台家电整机的全量工艺、检测文档长度，确保引用覆盖配置BOM、充注记录等审核必需内容 |
| `responseData` | 包含零部件批次、安规测试结果、返修标识 | 匹配家电制造审核的核心字段，快速提取溯源所需的关键业务数据 |
| `detail` | 开启 | 展示引用来源的文档路径、生成时间与设备编号，便于审核人员追溯原始生产记录 |
| 单次搜索上限 | 前6–10 条 | 覆盖每班生产的典型批次数量，避免冗余数据干扰审核判断 |
| 最大上下文 | 500–700 秒 | 适配多源数据的检索耗时，确保复杂溯源请求完成全链路数据拉取 |
| 问题优化 | 开启 | 针对混线装配的多型号场景，优化溯源关键词的匹配精度，减少错配 |

## 容易做错的三处
- 现象：配置引用溯源时，选择目标知识库后变量引用无可选值。原因：未将零部件批次、设备编号等核心业务字段配置为知识库的可引用元数据，或元数据未正确绑定到上传的BOM、检测报告等文档中。
- 现象：线上运行时出现Cannot redefine property: toString报错。原因：在自定义溯源节点中重复定义了toString方法，或引入的外部依赖与FastGPT v4.17.0的内置工具方法产生冲突。
- 现象：引用的溯源数据包含非目标型号的文档内容。原因：未设置按产品型号、生产批次的过滤规则，导致混线装配场景下的多型号数据被同时检索返回。

## 怎么确认配好了
- 上传单台家电的装配作业书与制冷剂充注记录，触发溯源请求，核对返回的引用来源是否包含文档的元数据字段。
- 输入指定零部件批次的检索关键词，检查返回的引用数据是否仅关联对应批次的生产与检测记录，无跨型号数据混入。
- 查看系统生成的引用日志，确认每条引用内容都带有文档路径、生成时间与设备编号，符合配置要求。
- 运行包含多源数据拉取的溯源流程，确认请求未超时，且返回的引用条数符合预设的单次搜索上限规则。
