# 家用电器整机制造的供应商与过程质量审核：文档解析与分块

## 这个品类的数据长什么样
该品类典型主体为空调、冰箱、洗衣机及小家电生产企业，日常文档包含配置BOM、装配作业书、制冷剂充注记录、电气安全测试报告、性能抽检报告、返修记录。数据来源覆盖ERP/MES系统、零部件批次台账、拧紧与充注设备、安规测试仪、性能实验室及售后故障数据库。更新节奏按单台产品、每班生产或抽检计划执行，文档字段包含物料编码、充注量、耐压测试值、故障代码等，附带对应单位如千克、伏特、小时。

## 这些特征在「文档解析与分块」这一环带来什么约束
多品类混线生产带来的文档版本差异，要求解析环节需精准匹配对应型号的文档结构，避免跨型号字段混淆。高频更新的单台/每班数据，要求分块粒度适配短周期生成的小批量文档，避免冗余分块占用存储。安规、性能类文档包含强制合规字段，需保留字段完整性，不能因分块截断关键参数。来自多设备的异构数据格式，要求解析环节兼容结构化表格与非结构化文本混合的文档类型，同时适配批次号、测试值等带单位的字段提取。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配该品类文档中单段工艺描述、测试数据的长度，避免截断充注量、耐压值等关键参数 |
| `chunkSplitter` | 按段落+语义分块 | 适配装配作业书、返修记录等带有自然流程的文档，保留工艺步骤的完整性 |
| `customPdfParse` | 开启结构化解析模式 | 适配BOM、测试报告等带有表格的文档，准确提取字段与单位信息 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容单批次多份大型测试报告、完整产线BOM包的上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大型安规测试报告的解析耗时，避免因超时导致解析失败 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（如作业书、测试报告）调整分块参数，适配异构文档场景 |

## 容易做错的三处
- 上传PDF后向量化缓慢，搜索测试结果为空。原因是未开启`customPdfParse`的结构化解析，导致非结构化文本分块冗余，且未调整`chunkSize`适配文档长度。
- 本地部署后数据处理为空，上传文件后无解析完成提示。原因是未正确配置`PARSE_FILE_TIMEOUT_SECONDS`，或`UPLOAD_FILE_MAX_SIZE`设置低于实际上传文件的大小，导致解析进程中断。
- 提问文字内容触发文档解析流程。原因是未正确设置关联规则，导致非知识库查询也触发文档解析逻辑，混淆了训练与对话场景。

## 怎么确认配好了
- 上传一份典型的制冷剂充注记录PDF，查看解析后的文本是否保留了充注量、设备编号等带单位的字段，无明显截断。
- 检查系统日志中是否无`PARSE_FILE_TIMEOUT_SECONDS`相关的超时报错，确认大型文档可正常完成解析。
- 上传超过500 MB的安规测试报告包，确认上传进度正常且无文件大小超限提示。
- 发起非知识库相关的对话，确认不会触发文档解析流程，验证配置生效。
