# 工艺变更与工程变更的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类的数据由制造企业研发、工艺、质量、生产、采购共同组成的变更管理团队产生与使用，核心来源包括PLM、ERP、MES系统，以及供应商资料、工艺验证试验记录、客户特殊要求文件。日常产生的文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本文件、工艺验证报告、生产切换计划、库存处置单、客户批准文件等。数据更新无固定周期，每次工艺或工程变更触发时同步生成新内容，单次变更会关联多类跨系统文档。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据关联多系统、跨文档属性，且每次变更会触发批量关联文档更新，对向量模型与索引环节带来多重约束。首先，跨系统文档格式差异大，包含结构化字段与非结构化文本，需支持混合类型内容的向量化处理；其次，不定期的增量更新要求索引支持轻量化同步，避免全量重索引占用过多计算资源；另外，变更关联的连锁影响需要检索时跨文档关联匹配，需索引保留文档间的关联关系；最后，长文本的变更评估与验证报告，需确保向量化时保留完整的逻辑链条，避免分块截断关键决策信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配ECN、变更评估报告等长文本文档，保留完整的变更逻辑与审批节点信息 |
| 重叠长度 | 100–200 字符 | 避免跨分块的变更关联信息被截断，确保检索时能匹配完整的变更链条 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的历史变更文档，聚焦当前变更关联的有效内容 |
| 单次搜索上限 | 前 20 条 | 覆盖主要的变更关联文档，避免过多冗余结果影响后续处理 |
| `maxToken` | 8192 | 适配长文本的工艺验证报告与BOM版本文件，确保向量化时不截断核心内容 |
| `defaultToken` | 256 | 为短文本的变更表单设置基础向量化长度，平衡计算效率与信息完整性 |

## 容易做错的三处
- 向量化任务报错提示embedding速率超限：未配置并发线程限制，批量提交的向量化请求超出接口调用限额，导致速率触发限流。
- 知识库检索速度缓慢：分块长度设置过大，单块文本的向量计算耗时增加，同时未优化检索的召回范围，导致大量无关文档被加载。
- 数据集自动生成多组索引：未配置增量索引的触发规则，系统默认每次同步PLM等数据源时都生成新索引，导致重复索引数据堆积。

## 怎么确认配好了
- 上传一份完整的ECN文档，查看向量化任务的进度状态，确认任务在合理时间内完成，无报错提示。
- 输入变更评估相关的关键词进行检索，检查返回结果的相关性与条数，确认符合单次搜索上限的配置要求。
- 查看数据集的索引记录列表，确认仅在手动触发或配置的变更事件时生成新索引，无自动重复生成的情况。
- 导入一份长文本的工艺验证报告，检查向量化后的文本片段，确认未出现关键逻辑被截断的情况，符合`maxToken`的配置范围。
- 查看当前FastGPT版本信息，确认使用的是FastGPT v4.17.0，确保配置项的兼容性。
