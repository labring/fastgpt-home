# 工艺变更与工程变更的供应商与过程质量审核：工具调用与插件

## 这个品类的数据长什么样
本品类数据由制造企业变更管理团队生成与使用，核心文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本记录、工艺验证报告、生产切换计划、库存处置单及客户批准文件。数据来源覆盖PLM、ERP、MES系统、供应商资质资料、验证试验记录与客户特殊要求，更新随每次工艺或工程变更不定期触发。数据字段包含变更编号、版本号、生效时间、影响范围、审批状态等，无统一固定的批量更新节奏。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类数据分散于多系统且格式多样，工具调用需支持跨PLM、ERP、MES等数据源的关联拉取，确保变更数据的完整性。变更触发无固定周期，插件需支持按需触发，适配临时发起的变更审核场景。文档包含结构化表单与非结构化图纸、验证报告，工具需兼容多格式数据解析，覆盖字段提取与内容校验需求。变更涉及跨部门审批状态，插件调用需携带准确的变更编号与权限参数，避免拉取未完成审批的无效数据。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的插件系统编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用触发时机 | 按变更状态更新触发 | 本品类变更触发无固定周期，按需触发可避免无效调用 |
| 数据源连接超时时间 | 600 秒 | 跨系统拉取PLM、ERP数据需足够等待时间，避免因网络延迟触发失败 |
| 单次数据拉取条数 | 前 10 条 | 变更数据单次批量不宜过大，避免插件处理超时 |
| `toolChoice` | auto | 适配多类型变更文档的解析需求，自动选择合适的工具函数 |
| `functionCall` | 按变更类型绑定 | 不同变更类型需调用不同的解析插件，精准匹配数据提取规则 |
| 插件调用重试次数 | 3 次 | 应对临时网络波动导致的调用失败 |
| 最大上下文长度 | 8000 token | 适配多页图纸与验证报告的文本解析 |

## 容易做错的三处
- 现象：使用数据库连接插件连接PostgreSQL时，报“工作流校验失败，请检查是否缺失、缺值，连线是否正常”。原因：未在插件配置中填写变更数据关联的数据库表名与变更编号字段，或字段配置与PLM、ERP中的实际字段不匹配。
- 现象：工具调用在调试模式下正常运行，在运行模式下报错。原因：运行模式下未配置跨系统访问的权限凭证，或未绑定变更审核的审批状态参数，导致权限校验失败。
- 现象：调用marker-pdf插件时出现请求错误，使用127.0.0.1部署仍连接失败。原因：插件容器与FastGPT容器未在同一docker网络中，或未开放插件服务的对应端口，导致跨容器网络连接失败。

## 怎么确认配好了
- 查看插件调用日志，确认拉取的变更数据包含ECN编号、版本号等核心字段，字段内容与PLM系统中的记录一致。
- 模拟一次临时变更触发，检查插件是否能正常拉取对应数据并完成格式校验。
- 配置权限校验参数，验证未完成审批的变更数据不会被拉取到审核流程中。
- 调整数据源连接超时时间，确认在网络延迟场景下不会触发连接超时错误。
