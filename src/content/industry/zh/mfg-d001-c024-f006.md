# 工艺变更与工程变更的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
该品类数据由制造企业研发、工艺、质量、生产、采购团队共同维护，日常文档包含ECN/ECR、变更评估表、图纸与BOM版本文件、工艺验证报告、生产切换计划、库存处置单、客户批准文件。数据来源覆盖PLM、ERP、MES系统、供应商资料、验证试验记录及客户特殊要求，更新随每次工艺或工程变更不定期触发，单条变更关联文档数量随变更复杂度波动，字段包含变更编号、版本号、生效时间、关联物料/工艺节点、审批状态等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
变更类文档版本关联紧密，引用溯源需精准匹配版本号，避免新旧版本混用。数据来源分散多系统，需支持跨数据源关联调取，确保引用内容来自对应PLM、MES等系统的最新存档版本。单次变更关联文档数量较多，需限制召回范围避免上下文过载。变更生效时间明确，溯源需绑定生效节点，确保审核环节引用的是切换前或切换后的正确版本。客户批准文件为强制合规依据，溯源需保留完整审批链路与客户签署记录，不可遗漏关联项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次召回上限 | 前6–10条 | 单条变更关联文档数量随复杂度波动，避免召回过多导致上下文过载 |
| 最大上下文token数 | 8000–12000 token | 覆盖ECN、BOM、验证报告等多类关联文档的完整内容 |
| 版本匹配规则 | 启用版本号精准匹配 | 避免新旧版本混用，确保引用的是变更生效前后的正确文档版本 |
| 数据源绑定 | 绑定PLM、ERP、MES指定数据源 | 覆盖该品类核心数据来源，确保引用内容来自官方系统存档 |
| `quoteMaxToken` | 1500–2000 token | 限制单篇引用文档的输出长度，避免长文档占用过多上下文空间 |
| `detail` | 开启 | 展示引用文档的完整版本号与数据源信息，便于溯源核查 |

## 容易做错的三处
- 现象：文本内容提取组件无法从知识库引用结果中提取字段，返回结果为空或非目标字段。原因：未配置`responseData`参数开启结构化数据返回，仅获取了非结构化的文本片段。
- 现象：引用结果包含非本次变更关联的文档，条数超出预期。原因：未绑定对应数据源，召回了其他业务模块的文档，未限定变更关联范围。
- 现象：引用的文档版本与当前变更要求不符，出现新旧版本混用。原因：未启用版本匹配规则，仅通过关键词匹配召回，未识别文档的版本号字段。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的控制台发起一次变更相关的查询，检查返回的引用来源是否包含PLM、ERP等指定数据源的文档。
- 查看引用结果的版本号字段，确认与当前变更的生效版本一致。
- 统计单次召回的文档数量，确认不超过预设的单次召回上限。
- 测试文本内容提取组件，确认可以从知识库引用结果中提取变更编号、版本号等目标字段。
