# 工艺变更与工程变更的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据由制造企业研发、工艺、质量、生产、采购共同组成的变更管理团队生成，日常文档包括ECN/ECR、变更评估报告、图纸与BOM版本、工艺验证报告、切换计划、库存处置单、客户批准文件等。数据来源涵盖PLM、ERP、MES、供应商资料、验证试验记录及客户特殊要求，更新随每次变更不定期触发，文档包含变更编号、生效节点、涉及物料与工艺项等字段，无统一固定更新周期。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入时适配不同系统的接口格式与数据结构，需配置统一的解析规则处理跨系统的变更相关数据。不定期的变更触发节奏导致上下文长度波动范围较大，需预留足够的上下文与响应token空间，避免因数据量突增导致处理失败。文档包含结构化字段与非结构化图纸、文本内容，需配置支持混合格式的输入处理逻辑，确保各类变更相关文件均可被正确解析。变更涉及跨部门协同的多类文件，需明确关联文档的召回规则，避免遗漏关键验证或客户批准文件，防止出现不符合质量管控要求的问题。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配制造企业工艺变更与工程变更的审核场景：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 变更相关文档的总token量随复杂度波动，预留足够空间容纳ECN、BOM版本对比及多份验证报告内容 |
| `maxTokens` | `4000–6000 token` | 单轮变更审核的响应长度需覆盖变更影响分析、切换节点确认等核心内容，避免截断关键结论 |
| `quoteMaxToken` | `2000–3000 token` | 需召回足够的供应商资料、验证报告及客户批准文件作为审核依据，确保引用内容完整 |
| `temperature` | `0.2–0.4` | 变更审核需保持严谨性，降低生成结果的随机性，确保结论符合企业质量管控要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应接口地址 | 适配企业内部网络环境的访问需求，确保模型接口可正常调用 |
| 工作流/API 工具选择配置 | `auto` | 自动调用文档解析工具处理混合格式的变更文件，无需手动指定处理逻辑 |

## 容易做错的三处
- 现象：调用接口返回`model not supported`报错，原因是未在`AIPROXY_API_ENDPOINT`对应的代理配置中添加目标模型的访问权限。
- 现象：生成的变更审核结论被截断，原因是`maxTokens`取值过小，未覆盖单轮响应所需的token量，导致关键内容丢失。
- 现象：召回的关联文档缺失客户批准文件，原因是`quoteMaxToken`取值过低，未覆盖所需引用文档的总token长度，导致部分关键文件未被召回。

## 怎么确认配好了
- 提交一份完整的ECN文档与关联BOM版本数据，检查模型是否能正确解析变更内容并生成审核结果。
- 查看接口返回的上下文长度统计，确认`maxContext`的取值大于当前测试数据的总token量。
- 触发一次变更审核任务，检查召回的引用文档是否包含供应商资料、验证报告及客户批准文件。
- 调整`temperature`取值为0.5，对比两次审核结果的差异，确认参数配置生效。
