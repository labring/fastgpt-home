# 工装夹具与检具制造的供应商与过程质量审核：工作流编排

## 这个品类的数据长什么样
本品类的核心数据来自汽车、航空、机械装配企业工装部门及专用工装供应商的业务产出，日常文档包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历。数据来源涵盖产品数模与GD&T、工艺路线、三坐标检测数据、现场试用反馈、计量系统。数据更新按单个项目推进，伴随产品变更触发更新，定期校准的检具与工装需同步更新校准记录。数据字段包含基准参数、尺寸公差、校准有效期、变更版本号等，部分图纸类文档带有非结构化标注内容。

## 这些特征在「工作流编排」这一环带来什么约束
品类数据的多类型文档结构要求工作流需适配结构化文本、图纸标注、计量数据等多种输入格式，需在编排时设置多类型文件的解析节点。按项目与变更触发的更新节奏，要求工作流绑定项目元数据与变更事件，确保流程仅在有效数据更新时启动。GD&T、三坐标数据等专业计量数据的关联性，要求工作流通过节点间参数传递串联各环节，避免数据脱节。定期校准的记录要求流程中加入有效期校验环节，防止过期检具数据进入审核环节。品类最耗时的基准转化与干涉验证环节，要求工作流加入自动校验节点，减少人工重复操作。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 输入文档分类 | 按工装需求书、夹具图、校准记录等品类专属文档类型划分 | 品类日常文档包含多类结构化与非结构化文件，分类后可提升解析精度 |
| `variables` | 绑定项目编号、GD&T基准参数、校准有效期 | 数据按项目更新，变量用于跨节点传递核心业务参数，确保各环节数据一致 |
| `nodeId` | 关联三坐标数据节点、验收报告节点、变更履历节点 | 需串联计量数据与审核结果，节点ID确保流程链路正确，避免环节脱节 |
| 触发时机 | 按项目提交、产品变更后、校准完成后 | 匹配品类数据按项目、变更、定期校准的更新频率 |
| 文本提取字符阈值 | 800–1200 字符 | 夹具图的标注文本长度集中在此区间，适配FastGPT v4.17.0的文本解析组件参数范围 |
| 召回结果上限 | 前10条 | 适配品类文档的关键词分布，避免冗余数据占用上下文 |

## 容易做错的三处
- 工作流中文本提取组件返回空内容，重新添加同配置组件后恢复。原因是首次配置时未绑定品类专属的文档分类标签，导致组件无法识别工装夹具类文档的文本结构。
- 部分大模型无法完成定位基准方案的文本提取。原因是未针对GD&T格式的专业术语开启术语增强配置，通用大模型无法识别专业字段，部分小参数模型的专业语料覆盖不足。
- 工作流中调用`variables`时未传入项目编号参数。原因是未在流程初始化节点绑定品类的项目元数据，导致跨节点参数传递失败，无法关联对应项目的验收与校准数据。

## 怎么确认配好了
- 上传一份典型的夹具图文档，检查文本提取组件是否返回定位基准、夹紧要求等字段。
- 触发一次按项目提交的工作流，查看`variables`中是否包含项目编号、GD&T参数等核心业务变量。
- 验证节点间的`nodeId`关联是否正确，确保三坐标数据能自动同步到验收报告节点。
- 模拟一次产品变更后的流程触发，确认FastGPT v4.17.0的工作流自动启动并加载最新的变更履历数据。
