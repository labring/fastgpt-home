# 工装夹具与检具制造的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来自汽车、航空、机械装配企业工装部门及专用工装供应商的日常产出，包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录与变更履历。数据来源涵盖产品数模与GD&T、工艺路线、三坐标测量数据、现场试用反馈及计量系统，更新按项目节点、产品变更或定期校准执行，单份文档包含定位基准、尺寸公差、校准参数等结构化字段与图纸类非结构化内容。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类数据的多源混合结构要求溯源环节同时覆盖结构化参数与非结构化图纸内容，避免仅检索文本遗漏几何公差等关键信息。按项目与变更的更新节奏，要求溯源关联版本标识，确保引用的夹具图、校准记录与当前生产批次匹配。专业字段如GD&T公差、三坐标测量值需保留原始单位与精度，不能被泛化转换。多类来源的交叉验证需求，也要求溯源链路可追溯至原始计量系统或现场试用记录，仅依赖中间文档不足以完成精准溯源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 本品类文档包含图纸元数据与三坐标测量数据，需足够token容纳完整溯源信息，适配FastGPT v4.17.0版本的token分配规则 |
| `detail` | 开启 | 需返回溯源文档的完整元数据，如校准日期、变更版本号，支持细分参数提取 |
| 单次搜索上限 | 前6条 | 本品类单项目关联文档数量有限，过多结果会干扰精准匹配 |
| 最大上下文 | `4000–6000 字符` | 需容纳多份溯源文档的关联内容，避免截断关键变更履历 |
| `responseData` | 仅返回结构化字段与原始来源标识 | 本品类需精准关联验收报告、校准记录的原始数据，避免冗余非结构化内容 |
| 超时阈值 | `300 秒` | 本品类单份文档的检索耗时较长，适配FastGPT v4.17.0版本的超时处理逻辑 |

## 容易做错的三处
- 搜索结果返回与当前工装项目无关的旧版本夹具图，原因是未关联版本标识进行溯源，仅匹配了关键词，未结合项目批次进行筛选。
- 无法精准引用三坐标数据的x轴、y轴测量值，原因是未开启`detail`配置，未返回结构化字段的细分参数。
- 溯源结果未关联变更履历，导致引用了已失效的定位基准方案，原因是未启用版本过滤逻辑，未筛选最新版本的文档。

## 怎么确认配好了
- 发起针对特定工装项目的提问，检查返回结果是否包含该项目的验收报告、校准记录等指定文档。
- 查看溯源结果的元数据，确认是否包含变更版本号、校准日期等字段。
- 验证`quoteMaxToken`配置是否能完整显示三坐标测量数据的全部内容，无截断。
- 测试触发搜索后，是否仅返回与当前项目相关的文档，无无关内容。
