# 有色金属冶炼与电解的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
该品类的日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账。数据来源涵盖精矿与辅料分析报告、DCS系统数据、电解槽电压电流监测值、化验室检测结果、能源与环保监测数据。数据更新节奏随原料批次、熔炼炉次或电解槽工况变动，部分监测数据为实时同步。文档字段包含原料成分数值、炉温参数、槽电压、金属回收量、污染物排放数值等，单位多为摄氏度、伏特、吨、毫克每立方米等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
实时的槽况、炉温数据与批次化的原料配料单、化验报告需要对话上下文准确关联批次与工况节点，避免跨批次数据混淆。多源异构数据的字段差异要求提示词明确指定数据来源与对应文档类型，否则易出现数据提取偏差。高频实时数据的更新要求多轮对话的上下文窗口需适配短周期数据的时效性，过长的历史上下文可能引入过时数据干扰当前审核。批次化文档的关联查询需要提示词明确绑定原料批次、炉号或槽号等唯一标识，否则无法精准匹配供应商来料与过程质量数据。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 前10条对话历史 | 匹配冶炼行业批次化审核的短周期需求，避免过长历史引入过时数据 |
| 单次搜索上限 | 前8条匹配文档 | 覆盖单批次原料、多炉次熔炼的关联数据量，满足过程审核的信息需求 |
| 变量填充 | 绑定`variables`参数指定炉号/槽号 | 精准关联对应工况的熔炼、电解槽况记录，避免跨批次数据混淆 |
| 对话标识 | 绑定`chatId`参数关联单审核任务 | 确保多轮对话上下文仅属于当前供应商或过程审核，隔离不同任务数据 |
| 提示词优化 | 开启，按实测标定 | 适配有色金属冶炼的专业术语与字段格式，提升数据提取准确率 |

## 容易做错的三处
- 现象：发起多轮对话后未返回目标审核数据，界面显示结果为空或匹配错误。原因：未在提示词中绑定原料批次、炉号或槽号等唯一标识，导致上下文无法精准关联对应文档。
- 现象：配置提示词后无法提取本年或本月的冶炼相关数据。原因：未明确指定数据的时间范围字段与文档类型，未适配有色金属冶炼文档的时间戳格式与字段命名规则。
- 现象：工作流中设置上下文数量为0后，对话无法加载预设的审核引导规则。原因：误解了`messages`参数的作用范围，该参数包含初始提示词与系统引导内容，设置为0将丢失核心审核逻辑。

## 怎么确认配好了
- 手动输入包含已知炉号或批次号的查询语句，核对返回结果是否关联对应炉号的熔炼记录与化验报告。
- 调整上下文数量参数，测试多轮对话中历史上下文是否按设定数量加载，无冗余无关数据。
- 查看工作流运行日志，确认`chatId`与`variables`参数是否正确绑定当前审核任务的唯一标识。
- 输入未指定标识的查询，核对结果是否出现跨批次或跨炉号的错误数据，验证配置的约束效果。
