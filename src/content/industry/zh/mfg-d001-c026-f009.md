# 有色金属冶炼与电解的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自铜、铝、铅锌等冶炼企业的熔炼、电解、化验与调度部门，日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录与环保台账。数据来源覆盖精矿与辅料分析、DCS系统、槽电压电流监测、化验室检测、能源与环保监测设备，更新频率随原料批次、炉次或电解槽运行状态实时变化，部分台账数据按生产周期归档。字段包含精矿品位、杂质含量、槽电压、电流值、金属回收率等冶炼专属参数，无通用行业的统一格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入环节需兼容不同格式的文档与实时数据流，需配置足够的上下文容量以覆盖批量历史生产数据。高频更新的生产数据意味着模型调用需适配实时性要求，不能依赖过旧的上下文缓存。冶炼场景对杂质分析、金属平衡计算的精度要求较高，需限制模型输出的随机偏差。同时，该品类对炉况、电解槽状态的判断依赖具体数值参数，模型需具备处理结构化生产数据的能力，不能仅依赖非结构化文本分析。此外，国内大模型接入需求普遍，需支持通过中转API配置非OpenAI类模型，适配无原生OpenAI密钥的部署场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 覆盖多份历史配料单、电解槽况记录的拼接需求，避免上下文截断丢失关键生产数据 |
| `temperature` | 0.2–0.4 | 减少杂质成分分析、金属平衡计算的随机偏差，符合冶炼场景的精度管控要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应中转端点 | 适配国内大模型接入场景，解决无OpenAI官方密钥的配置需求 |
| `maxTokens` | 2000–3000 token | 平衡单次审核结果的完整性与调用耗时，适配实时炉况判断的时效性要求 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具处理成分核算、槽况分析等结构化计算任务 |

## 容易做错的三处
- 调用模型返回“令牌无效”报错，原因是将平台原生密钥填入`AIPROXY_API_TOKEN`，未使用中转服务生成的有效令牌。
- 无法正常接入Docker部署的FastGPT实例，原因是未将`AIPROXY_API_ENDPOINT`配置为容器内部或映射后的API端口地址。
- 模型输出缺失核心生产参数，原因是`maxContext`设置过小，未加载足够的历史生产数据用于对比分析。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`是否与部署的中转服务或大模型平台匹配，可通过FastGPT内置的模型测试接口验证连通性。
- 上传单份配料单与电解槽况记录，触发供应商与过程质量审核任务，核对输出是否包含精矿品位、槽电压等核心字段。
- 调整`temperature`参数后，多次触发相同审核任务，观察输出结果的一致性是否符合场景的精度管控要求。
- 查看FastGPT v4.17.0的模型调用日志，确认上下文长度未触发`maxContext`或`maxTokens`的限制阈值。
