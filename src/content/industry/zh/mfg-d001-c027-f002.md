# 服装裁剪与缝制的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类的日常数据涵盖工艺单、CAD样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等。数据主要来自订单与尺码表、CAD设计文件、面辅料检验记录、吊挂生产系统、验针机数据及客户封样件。数据更新以每订单、每款、每批为节奏，款式多、季节性强，面料裁片不可逆且人工工序密集，无通用的标准化批量本体数据。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据类型多样，包含结构化表格、CAD绘图文件、文本记录与设备采集数据，要求向量模型需适配非标准化的多源输入。数据更新频率高且单款订单差异大，索引需支持快速增量更新以匹配每批生产节奏。面料裁片不可逆的业务特性，要求向量召回的精度需覆盖工序细节与版型匹配，避免批量偏差。同时人工工序密集的特点，使得工序质量表等文本数据的字段粒度较细，分块时需匹配工序拆分逻辑，避免破坏工艺关联信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配工序质量表、工艺单的单段工序描述长度，避免拆分破坏工序逻辑 |
| 重叠长度 | 100–150 字符 | 覆盖相邻工序的关联描述，防止关键工艺信息被分块截断 |
| `defaultToken` | 8192 | 适配CAD样板与排料图的文本标注长度，满足多段工序数据的上下文容纳需求 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非目标工序数据，避免尺码、色差类批量错误的误召回 |
| 单次搜索上限 | 前 10 条 | 匹配单款订单的工序数量，避免冗余结果干扰现场审核判断 |

## 容易做错的三处
- 现象：索引建立失败，宿主机为8c16G无GPU虚拟机且文件体积较小。原因：未针对多源非结构化数据调整分块参数，导致分块后token超出模型承载上限，触发内存溢出报错。
- 现象：调用embedding模型时报错，无法使用指定渠道。原因：未单独配置索引模型的调用渠道，默认使用全局chat模型配置，导致跨渠道的模型兼容性问题。
- 现象：启动容器后返回503错误，提示default分组下text-embedding-v3无可用渠道。原因：未在docker-compose配置中正确注入索引模型的API密钥与渠道配置，导致模型调用链路中断。

## 怎么确认配好了
- 上传单款服装的工艺单与工序质量表，检查分块后的文本片段是否保留完整的工序描述，无关键信息截断。
- 发起版型匹配检索，核对返回结果的相似度区间是否符合预设的阈值范围，无无关的历史订单数据混入。
- 启动增量索引更新，验证新上传的批次订单数据是否能被快速纳入现有索引，无长时间等待或失败提示。
- 查看FastGPT v4.17.0的容器日志，确认embedding模型调用无渠道报错，API密钥配置与索引模型匹配。
