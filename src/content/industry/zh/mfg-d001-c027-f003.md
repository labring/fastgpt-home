# 服装裁剪与缝制的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
该品类的日常文档包含工艺单、样板、排料图、裁剪单、首件封样、工序质量表、包装配码单。数据来源涵盖订单与尺码表、CAD样板、面辅料检验记录、吊挂系统数据、验针机结果、客户封样件。数据更新频率为每订单、每款、每批，单款服装的工序明细与裁片信息字段包含尺码、色号、裁片编号、工序节点等，单位多为厘米、件、批。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的文档多为工序化明细且更新频繁，单款内容体量较大，因此多轮对话的上下文长度需要严格限制，避免冗余信息干扰审核判断。不同批次的订单数据关联性强，需通过明确的会话标识区分不同审核场景，防止上下文混淆。同时，文档字段多为非标定制化内容，提示词需精准绑定订单、款号等变量，确保审核规则与实际生产数据匹配。裁片不可逆的特性也要求对话历史需完整留存，避免因上下文丢失导致审核偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | `8000–12000 字符` | 单款服装的工艺单、排料图等文件内容体量较大，需覆盖完整的工序明细 |
| 单次上传文件上限 | `10–15 个` | 单批订单的工艺、样板、检验记录等文件数量集中在该区间 |
| `variables` 变量绑定 | 绑定订单号、款号字段 | 需精准关联对应批次的生产数据与审核规则 |
| `messages` 历史上下文截取 | `前 20 轮对话` | 多轮审核中仅需保留近期的质量校验与沟通记录，避免冗余 |
| `chatId` 会话标识配置 | 绑定订单批次号 | 区分不同供应商的不同订单审核场景，防止会话上下文混淆 |
| 会话超时设置 | `600 秒` | 单批订单的审核流程通常耗时在10分钟以内，避免会话提前中断 |

## 容易做错的三处
- 调用对话接口时无法正确传递上传的工艺单文件，原因是未通过`variables` 绑定文件上传的临时路径参数。
- 审核结果出现工艺要求匹配偏差，原因是未在提示词中明确区分预设规则与实际审核请求的边界。
- 前端页面同时展示多个模块的输出内容无法区分，原因是未通过`messages` 字段为每个审核环节添加明确的角色标识。

## 怎么确认配好了
- 在FastGPT v4.17.0环境下，调用对话接口上传单款服装的工艺单与排料图，检查接口返回的`messages` 字段是否包含上传文件的解析文本。
- 发起多轮审核对话，查看`chatId` 是否保持一致，确认会话上下文未被重置。
- 配置`variables` 绑定订单号后，发起审核请求，检查输出结果是否关联了对应订单的尺码要求。
- 测试多模块输出场景，确认不同环节的对话内容通过`messages` 字段被正确区分。
