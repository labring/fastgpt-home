# 服装裁剪与缝制的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
该品类典型主体为服装OEM/ODM、品牌供应链及裁剪缝制车间，日常产生工艺单、样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等文档。数据来源覆盖订单与尺码表、CAD样板、面辅料检验、吊挂系统、验针机及客户封样，更新节奏为每订单、每款、每批。品类特征为款式多、季节性强，面料裁片不可逆且人工工序密集，与纺织面料本体品类存在明显差异。

## 这些特征在「引用来源与溯源」这一环带来什么约束
品类高频更新的订单、款式、批次数据，要求引用溯源环节需支持实时同步最新工艺单、排料图等文档。裁片不可逆且人工工序密集的特征，要求溯源需精准绑定具体批次的面辅料检验、裁剪工序及首件封样记录，避免模糊匹配导致的溯源偏差。多款式季节性的属性，要求溯源环节可按订单、款号快速筛选关联文档，同时需适配工序质量表、包装配码单等多类型字段的匹配逻辑，确保审核时可快速定位对应环节的校验数据。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，适配服装裁剪与缝制品类的审核场景。以下为具体配置项及依据：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 该品类文档多为工序单、排料图等，单条引用内容不宜过长，避免上下文溢出影响审核逻辑 |
| `responseData` | 开启 | 需在审核结果中返回关联文档的元数据，便于核对供应商提交的工序数据与知识库中标准工艺的匹配情况 |
| `detail` | 完整 | 该品类需溯源裁剪、缝制、检验等多环节数据，完整详情可覆盖工序质量表、验针机记录等多类型文档内容 |
| 单次搜索上限 | 前6条 | 该品类单订单关联文档数量适中，过多引用会干扰核心审核逻辑，过少则无法覆盖全部关键工序数据 |
| 最大上下文 | `4000–6000 字符` | 需同时承载订单信息、工艺要求及多环节检验数据，避免上下文截断导致关键信息丢失 |

## 容易做错的三处
- 现象为调试页面展示引用文档列表，正式聊天页面引用文档字段为空。原因是未开启`responseData`配置项，或配置后未关联至对话输出模块。
- 现象为返回的引用文档条数不符合预期，无法固定限制为指定条数。原因是误将分数阈值作为条数限制依据，未正确匹配品类的文档数量特征调整配置。
- 现象为文本内容提取组件无法从知识库引用中提取内容。原因是未将知识库引用模块的输出接入文本提取组件的输入源，或组件未适配多类型工序文档的内容提取逻辑。

## 怎么确认配好了
- 发起针对某款服装裁剪工序的审核请求，检查返回结果中是否包含关联的工艺单、排料图等文档的元数据，确认配置生效。
- 查看返回引用的token数量，调整`quoteMaxToken`取值至符合当前文档长度的区间，确保无内容截断。
- 测试不同订单、款号的查询，确认可按订单、款号快速筛选到对应关联文档，验证上下文配置适配品类的多文档场景。
- 接入文本提取组件，尝试从知识库引用的内容中提取工序编号、尺码要求等字段，确认组件可正常读取引用内容。
