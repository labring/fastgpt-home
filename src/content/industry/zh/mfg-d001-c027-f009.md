# 服装裁剪与缝制的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
该品类典型主体为服装OEM/ODM、品牌供应链及裁剪缝制车间，日常文档包含工艺单、CAD样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等。数据来源覆盖订单与尺码表、CAD设计文件、面辅料检验记录、吊挂系统工序数据、验针机检测结果及客户封样件。数据更新随每订单、每款、每批完成，单批次关联文档包含多类型格式，既有结构化的工序参数表，也有非结构化的照片、图纸文件，字段涉及尺码码数、裁片配套要求、包装配比等服装加工专属内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类数据随订单、款式频繁更新，需频繁切换不同批次的知识库内容，要求模型接入时支持动态配置数据源。多类型文档混合输入的场景，包括CAD图纸、工序表格、质检照片，需适配多模态识别能力。单订单关联文档总长度较长，需合理控制上下文截断逻辑，避免关键工序、尺码要求等核心信息丢失。设备采集的结构化数据与人工填写的质检表单需统一解析，要求模型支持混合格式的输入处理。同时，业务峰值时段的并发请求量需适配单批次文档的处理复杂度，避免超出模型服务能力。本页面基于FastGPT v4.17.0版本编写。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 该品类需审核首件封样照片、裁剪排料图等视觉类文档，需开启多模态识别能力 |
| `maxTokens` | 8000–12000 token | 单订单关联的工艺单、工序表等文档总长度较长，需保证关键工序、尺码要求不被截断 |
| `maxContext` | 按单订单文档总大小的1.2倍标定 | 避免上下文溢出导致400错误，适配该品类单批次文档量 |
| `temperature` | 0.2–0.4 | 质量审核需结果严谨一致，降低随机性以保证审核标准统一 |
| `AIPROXY_API_ENDPOINT` | 填写本地模型服务器地址 | 适配企业自有部署的大模型，满足数据本地化要求 |
| `AIPROXY_API_TOKEN` | 按平台生成的专属令牌填写 | 保证接口调用权限安全，避免未授权访问 |

## 容易做错的三处
- 共享页面并发超过60后无应答，本地模型服务器资源未达瓶颈。原因：未根据品类单批次文档处理复杂度调整并发上限，默认并发配置未适配该品类多文档混合处理的需求。
- 上传超过上下文长度的工艺单或排料图时返回400错误。原因：未设置合理的`maxContext`与`maxTokens`参数，未在工作流中添加文件内容截取预处理逻辑，导致上下文溢出。
- 模型返回结果未包含工序质量表中的结构化数据，<FilesContent>标签内存在对应内容。原因：未正确配置模型的上下文引用规则，或未开启对应文档类型的解析开关，导致结构化内容未被正确纳入模型输入。

## 怎么确认配好了
- 发起单订单全量文档的测试请求，核对模型返回的审核结果是否包含工艺单、尺码表中的关键要求。
- 调整并发请求数量，观察模型响应状态，确认在业务峰值并发下无无应答情况。
- 上传超出常规文档长度的测试文件，核对是否返回400错误，若出现则调整`maxContext`与`maxTokens`参数。
- 上传首件封样照片，核对模型是否能正确识别照片中的缝制瑕疵或尺码偏差。
