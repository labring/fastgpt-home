# 来料检验与供应商质量的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据覆盖制造企业IQC、SQE等部门的全流程质量文档，包含检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告、让步接收审批单等类型。数据来源涵盖采购订单、图纸规格、供应商质保书、检验设备采集数据、历史质量记录、供应商门户系统。更新节奏随业务场景波动，每批来料时产生新的来料报告与检验记录，每月或季度开展供应商评价更新审核报告，不定期开展专项审核生成临时文档。文档包含批次标识、供应商编码、检验参数阈值、整改闭环状态等字段，同时存在结构化表单与非结构化长文本两类格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。多源分散的数据来源要求索引支持跨系统数据的统一聚合与元数据关联；波动的更新频率需要适配增量索引机制，避免全量重建的资源浪费与延迟；混合格式的文档要求分块策略兼顾短字段的完整性与长文本的语义连贯性；严格的业务判定要求检索结果需精准匹配供应商、批次等维度，同时平衡误判与漏判的风险，防止不良物料流入或误拒收导致停线。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配来料报告、8D报告等长文本的语义完整性，同时兼容抽样方案等短文档的分块效率 |
| 重叠长度 | 100–200 字符 | 避免长文本分块后语义断裂，覆盖跨块的批次、供应商关联信息 |
| 相似度阈值 | 0.75–0.85 | 平衡来料检验的严格判定需求，降低误判与漏判概率 |
| 单次搜索上限 | 前10条 | 保证检索结果覆盖足够的历史质量数据，同时控制返回量避免资源浪费 |
| `maxToken` | 4096 token | 适配长上下文的供应商审核报告检索需求 |
| `defaultToken` | 按实测标定 | 匹配本地部署的向量模型服务承载能力，避免并发请求超限 |

本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：知识库容量估算结果与实际存储占用偏差较大。原因：未按混合文档结构设置分块规则，误将所有文档按单文档平均长度计算，导致容量规划不合理。
- 现象：界面显示`503`状态码报错，向量模型请求失败。原因：未针对`defaultToken`调整并发控制参数，高频来料检验的批量检索请求超出服务承载上限。
- 现象：检索结果无法按供应商或批次过滤匹配。原因：未在索引中关联供应商编码、批次标识等元数据字段，导致检索维度缺失。

## 怎么确认配好了
- 上传单份8D报告与抽样方案，检查分块后的文本片段，确认无关键业务信息断裂。
- 发起包含指定供应商编码的检索请求，验证返回结果仅包含对应供应商的历史审核与检验文档。
- 发起批量检索测试，确认未触发`503`状态码报错，服务运行稳定。
- 调整相似度阈值，验证检索结果的召回与过滤符合来料检验的业务判定逻辑。
