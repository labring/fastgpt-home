# 来料检验与供应商质量的供应商与过程质量审核：文档解析与分块

## 这个品类的数据长什么样
本品类的数据主要来自采购订单、图纸与规格文档、供应商质保书、检验设备采集数据、历史质量记录及供应商门户。更新节奏覆盖每批来料、月度或季度供应商评价、不定期专项审核。日常处理的文档包含检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D整改报告及让步接收审批单，字段包含批次号、抽样比例、不合格项、供应商编号等，单位涉及件、百分比、批次编号等业务标准单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
多类型结构化文档要求解析器支持表格、列表等结构化内容提取，避免分块截断关键业务字段。高频更新的批量文档需求要求解析流程支持高效任务调度，避免单次解析耗时过长。元数据包含批次号、供应商ID等业务关联字段，要求分块时绑定对应元数据，便于后续检索时关联业务上下文。部分文档如大型供应商审核报告篇幅较长，需要合理设置分块参数避免上下文断裂，影响后续检索精度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配本品类的业务数据特征：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配来料报告、8D报告等业务文档的单章节长度，避免分块截断关键业务逻辑 |
| `chunkSplitter` | 按文档结构分块 | 适配检验规范、抽样方案等带固定章节的文档，保留章节语义完整性 |
| `customPdfParse` | 开启结构化解析 | 提取PDF中的表格、元数据字段，避免丢失供应商编号、批次号等关键信息 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容大型供应商审核报告、批量来料检验汇总文档的上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对大型文档解析的耗时需求，避免中途超时失败 |
| `chunkSettingMode` | 手动配置 | 针对不同业务文档类型调整分块参数，适配检验规范与来料报告的差异 |

## 容易做错的三处
- 上传3MB以上的PDF文档时触发解析失败报错。原因是未调整`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`的配置，超出默认阈值导致拦截或超时。
- 检索返回的文本块未关联对应批次号、供应商编号等元数据。原因是分块配置未开启元数据绑定，未将文档中的业务字段与文本块关联。
- 无法导入Excel格式的来料报告或供应商审核文档。原因是未配置Excel文件的解析适配规则，系统默认未开启非PDF/文本格式的解析支持。

## 怎么确认配好了
- 上传单份1000MB以内的PDF文档，查看解析状态是否显示完成，无超时或拦截报错。
- 导入一份包含表格的来料检验规范文档，查看解析后的文本块是否保留表格结构与字段信息。
- 检索业务关键词，查看返回结果是否附带对应批次号、供应商ID等元数据字段。
- 批量上传多份来料报告，查看解析任务是否按配置的超时参数完成处理。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
