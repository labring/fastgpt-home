# 来料检验与供应商质量的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来源包括采购订单、图纸和规格、供应商质保书、检验设备采集数据、历史质量记录及供应商门户。日常处理的文档涵盖检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告及让步接收审批单据。数据更新节奏为每批来料同步更新、每月或季度完成供应商整体评价、不定期开展专项质量审核。数据字段包含来料批次号、检验项参数、不合格判定结果、供应商编号及检验日期，部分字段带有物理单位或标准化编号格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源分散的数据来源要求接入配置需适配不同格式的文档与系统数据，避免出现关键字段丢失。高频更新的来料批次数据要求上下文窗口需保留供应商、批次等关联元数据，不能过度截断导致审核逻辑断裂。多样的文档结构需要配置合理的上下文与引用长度，确保审核时可完整调用原始检验依据。同时，质量审核需严谨统一的判定逻辑，对模型输出的稳定性有明确要求，需限制随机参数的取值范围。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 该品类需保留来料批次、供应商信息、历史质量记录等关联元数据，避免截断关键审核依据 |
| `maxTokens` | `2000–3000 token` | 单轮审核回复需包含判定结论、整改建议及引用依据，避免输出内容被截断 |
| `quoteMaxToken` | `1500 token` | 需完整引用检验规范、抽样方案等原始文档片段作为审核支撑，控制引用内容的总长度 |
| `temperature` | `0.2–0.4` | 质量审核需保持判定逻辑的一致性，降低输出结果的随机波动 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的私有代理地址填写 | 适配企业内部的模型调用链路，确保数据不流出私有网络 |
| `AIPROXY_API_TOKEN` | 配置企业专属的校验令牌 | 保障模型调用的身份合法性，防止未授权访问 |

## 容易做错的三处
- 模型调用返回401未授权错误，原因是未正确配置`AIPROXY_API_TOKEN`，或令牌与代理地址不匹配。
- 审核结果缺少来料批次或供应商关联信息，原因是`maxContext`取值过小，截断了关键的元数据内容。
- 服务出现异常重启或无限重试，原因是`maxTokens`设置超出模型接口的响应上限，导致调用链路反复失败。

## 怎么确认配好了
- 输入一条包含来料批次、供应商信息的典型审核查询，查看回复是否完整关联对应字段，确认上下文参数生效。
- 发起测试调用，检查返回结果的token消耗值是否符合配置的`maxTokens`范围，确认输出截断逻辑正确。
- 使用无效令牌发起调用，确认返回未授权错误，验证身份校验配置生效。
- 两次输入相同的审核查询，对比两次回复的逻辑一致性，确认温度参数配置符合预期。
