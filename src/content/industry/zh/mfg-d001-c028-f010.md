# 来料检验与供应商质量的供应商与过程质量审核：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来自采购订单、图纸和规格、供应商质保书、检验设备、历史质量数据及供应商门户。日常生成的文档包含检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告、让步接收审批。数据更新随每批来料、每月或季度供应商评价、不定期审核推进。文档字段包含供应商编号、来料批次、检验项目、合格判定参数、整改时限等，部分文档附带物理单位如件、批次、工时。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征对检索召回带来多重约束。数据来源分散且更新随批次、周期或临时审核推进，需确保检索能实时同步最新的供应商质保书、来料报告与审核结果。文档包含结构化报表与非结构化报告，需适配不同文本结构的召回逻辑，同时需关联供应商编号、来料批次等专属字段，避免跨批次、跨供应商的结果混淆。业务场景要求平衡风险控制与生产保供，检索召回需兼顾精准度与召回范围，防止误召回不合格数据或漏召回关键合规信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.75–0.85 | 适配来料检验的合规判定需求，平衡精准度与召回覆盖，避免误召回非匹配的检验规范 |
| `limit` | 前8条 | 满足单次审核需对照多份抽样方案、历史报告的场景，避免过多结果增加人工核对负担 |
| `searchMode` | hybrid | 兼顾结构化字段匹配与非结构化文本语义召回，适配FastGPT v4.17.0及以上版本的混合检索能力 |
| `usingReRank` | 开启 | 对召回结果重排，优先展示包含最新审核日期、批次匹配的文档，提升关键信息可见性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展问题为包含供应商、批次、检验类型的关联查询，适配本品类按业务维度检索的需求 |
| `collectionIds` | 按业务域划分的供应商质量知识库ID集合 | 限定检索范围在本品类专属文档中，避免混入其他品类的无关数据 |

## 容易做错的三处
- 现象：检索时返回`invalid configuration parameter name "hnsw.max_scan_tuple`报错。原因：错误使用了非指定配置项，误将外部向量库参数写入FastGPT检索配置。
- 现象：单次检索耗时过长，界面加载卡顿。原因：未设置合理的`limit`参数，召回过多无关文档，或未限定`collectionIds`导致检索范围过大，同时未开启`usingReRank`的优化逻辑。
- 现象：扫描版PDF文档的检索召回率极低，无法提取有效业务内容。原因：未配置针对图片型PDF的OCR预处理流程，仅对纯文本PDF进行了分块与嵌入，无法识别扫描内容中的检验数据与审核结论。

## 怎么确认配好了
- 核对配置项列表，确认仅使用指定的检索参数，无额外未授权参数。
- 执行包含供应商编号、来料批次的查询语句，验证召回结果是否限定在对应业务域的知识库中。
- 上传扫描版PDF测试文档，确认检索流程可提取图片中的文本内容。
- 测试多问题批量查询场景，确认检索接口可按批次返回对应结果。
