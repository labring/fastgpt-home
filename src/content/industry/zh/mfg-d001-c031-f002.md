# 水泥熟料与粉磨的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类的数据覆盖水泥企业矿山、生料、烧成、粉磨、质量及能源部门的多类业务文档，包括生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录与能源报表。数据来源涵盖在线成分分析设备、DCS系统、化验室、窑磨设备、原燃料台账及能源计量装置，更新节奏包含实时、每班及每日三个层级，字段多包含物料成分、设备参数、能耗数值与质量指标，单位涉及吨、千瓦时等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。多来源的异构数据包括在线实时数据、每班巡检记录、每日报表台账，需适配不同的增量与批量索引逻辑。文档类型覆盖结构化化验数据与非结构化操作文本，需针对不同内容设计分块规则，避免长文本截断丢失关键热工参数或质量指标。不同更新节奏要求索引策略区分实时增量更新与定时全量构建，同时需适配单批次十万级数据的导入处理，避免资源占用超出合理范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类的单份文档平均长度，避免截断窑操作记录的完整热工参数段 |
| 重叠长度 | 100–150 字符 | 覆盖分块间的关键衔接内容，防止生料配料方案的连续逻辑被拆分 |
| `maxToken` | 4096 token | 匹配主流API模型的输入上限，适配化验报告的多字段组合文本 |
| `defaultToken` | 512 token | 配置单条短文本的默认向量生成长度，适配设备巡检记录的简短内容 |
| 相似度阈值 | 0.75–0.85 | 区分原燃料台账的相似条目，避免误匹配不同批次的物料数据 |
| 单次召回上限 | 前 20 条 | 覆盖每班巡检记录的关键异常项，满足审核时的全量参考需求 |

## 容易做错的三处
- 现象：导入十万条原燃料台账CSV数据后，向量后剩余条目仅九万余条，缺失数千条。原因：未配置分块过滤规则，导致部分含特殊格式的化验报告数据未被正确解析，或重复的巡检记录条目被自动合并。
- 现象：创建文档集合返回成功提示，但页面索引状态始终显示“未就绪”，无法发起检索。原因：未适配该品类的批量数据更新节奏，索引构建任务因资源占用过高被后台暂停，或文档中包含无法被模型解析的非标准文本格式。
- 现象：本地环境下向量检索结果符合预期，但打包为Docker镜像运行后，所有文本的向量得分完全一致。原因：Docker容器内未正确配置模型调用参数，导致调用的模型参数被统一重置，或容器资源限制导致模型推理出现异常。

## 怎么确认配好了
- 随机抽取10份不同类型的文档（如窑操作记录、化验报告），执行向量导入操作，核对导入条目数与源数据条数是否一致。
- 发起检索请求，核对返回结果的排序逻辑与业务场景匹配度，调整相似度阈值至符合审核需求的区间。
- 查看FastGPT v4.17.0的索引构建日志，确认实时数据的增量更新任务是否按预设的每班/每日节奏正常触发。
- 测试Docker容器部署后的向量检索结果，确认不同文本的得分存在合理差异，无完全一致的情况。
