# 水泥熟料与粉磨的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自水泥企业矿山、生料、烧成、粉磨、质量和能源部门的日常业务文档与系统数据。日常文档包含生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录、能源报表。数据来源涵盖在线成分分析系统、DCS控制系统、化验室检测数据、窑磨设备运行数据、原燃料台账、能源计量装置。数据更新节奏分为实时（设备运行参数、在线成分）、每班（巡检记录、班组操作记录）、每日（化验报告、能源结算报表）。数据字段包含原燃料批次标识、设备运行参数数值、检测结果数值，单位涵盖摄氏度、转每分钟、吨每小时、兆帕等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据特征对多轮对话与提示词环节带来明确约束。首先，数据来源分散且包含实时与批量两类，提示词需明确区分在线实时参数与历史报表数据的调用规则。其次，更新频率差异大，多轮对话需支持按实时、每班、每日的时间范围筛选对应数据，避免混入过期信息。第三，日常文档类型多样，提示词需指定不同文档的查询优先级，例如优先调用化验报告验证熟料强度指标。最后，原燃料波动、窑热工制度调整等核心业务环节依赖动态数据，多轮对话需支持实时触发数据拉取，确保返回结果匹配当前生产状态。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables`参数配置 | 绑定原燃料批次、在线成分、设备运行参数 | 支持动态注入实时业务数据，匹配本品类多源数据特征，基于FastGPT v4.17.0版本的动态变量绑定特性 |
| `messages`参数配置 | 按轮次拼接系统提示词与历史对话内容 | 保留完整的质量审核对话链，适配多轮业务沟通场景 |
| 最大上下文长度 | 8000–12000 token | 覆盖单轮质量审核所需的全部生产数据，避免截断关键指标 |
| 多轮对话历史保留时长 | 4小时 | 匹配每班生产调整的周期，确保审核过程可追溯 |
| 批量数据拉取间隔 | 15秒 | 匹配在线成分分析的实时更新节奏，确保数据时效性 |
| 单次召回文档上限 | 前3条 | 优先匹配最新的化验报告与窑操作记录，过滤冗余历史数据 |

## 容易做错的三处
- 对话返回结果末尾出现追溯展示规则的符号。原因：未在提示词配置中关闭规则展示开关，导致大模型自动附加系统提示词的标记内容。
- 并发调用工作流时，部分请求返回空值。原因：未调整工作流最大运行次数与批量执行节点最大输入长度参数，并发请求超出系统默认承载上限。
- 对话无法匹配当前生产批次的原燃料数据。原因：未通过`variables`参数绑定当前批次标识，导致召回错误的历史台账数据。

## 怎么确认配好了
- 发起模拟对话，输入当前生料配料的参数，核对返回结果是否关联对应业务文档。
- 启动多轮对话流程，依次提交质量审核的不同环节需求，核对对话历史是否完整留存。
- 调整并发请求数量，发起多组测试调用，核对返回结果是否无异常标记与空值。
- 进入配置界面，确认绑定的变量、对话历史规则与召回上限参数已按要求设置。
