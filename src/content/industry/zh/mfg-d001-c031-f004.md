# 水泥熟料与粉磨的供应商与过程质量审核：工作流编排

## 这个品类的数据长什么样
本品类数据覆盖水泥企业矿山、生料、烧成、粉磨、质量和能源部门，日常文档包括生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录、能源报表。数据来源为在线成分分析系统、DCS控制系统、化验室、窑磨设备、原燃料台账与能源计量装置，更新节奏涵盖实时、每班、每日三个层级，字段与单位匹配各业务环节的计量与检测标准。本页面基于FastGPT v4.17.0版本展开说明。

## 这些特征在「工作流编排」这一环带来什么约束
本品类数据的多来源、多更新节奏特征，要求工作流支持多节点并行拉取不同周期的数据，避免跨周期数据混淆。实时类数据（如在线成分分析结果）需配置短间隔触发的节点，以匹配原燃料波动的快速响应需求；每班、每日类数据则需绑定定时调度规则，适配日常巡检、能耗统计的业务周期。多样的文档类型需工作流配置适配不同格式的节点，确保生料配料方案、化验报告等文件能被正确解析与调用，同时匹配各环节的字段与单位标准。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发节点调度 | 按实时、每班、每日分节点调度 | 匹配本品类数据的多更新节奏，避免跨周期数据混淆 |
| 数据源绑定 | 关联在线成分分析、DCS、化验室等指定数据源 | 对应本品类数据来源的多渠道特征，确保数据准确性 |
| 变量传递配置 | 启用`variables`节点传递标准化检测参数 | 支持工作流内跨节点流转化验数据、能耗数据等字段，减少重复配置 |
| 超时设置 | 600秒超时阈值 | 适配DCS数据拉取与化验报告解析的平均耗时，避免节点阻塞 |
| 分支触发规则 | 按原燃料波动、窑热工状态、强度指标阈值触发 | 匹配本品类最耗时的业务环节，实现流程自动分流 |
| 数据缓存时长 | 24小时缓存周期 | 减少重复拉取历史数据的资源消耗，适配每日更新的台账类数据 |

## 容易做错的三处
- 工作流执行到工具调用节点后停滞，日志显示数据库连接超时。原因：未按本品类多数据源的更新节奏配置节点调度，导致同时拉取多渠道数据超出连接上限。
- 工作流无法引用原文件在线预览，仅能查看知识库切片内容。原因：未在节点中绑定原文件的存储路径参数，仅调用了知识库切片数据。
- 渠道测试成功但语音节点调用失败，返回状态码500。原因：未适配本品类实时数据的触发逻辑，语音节点调用时未传入标准化的`variables`参数。

## 怎么确认配好了
- 检查各数据源节点的更新频率是否与实际业务周期匹配，调整触发规则。
- 验证跨节点变量传递是否正常，确认`variables`参数能在各环节正确流转。
- 模拟原燃料波动场景，触发分支节点，检查流程是否按预期跳转。
- 调用工具节点后查看运行日志，确认无超时或连接异常报错。
