# 水泥熟料与粉磨的供应商与过程质量审核：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据覆盖水泥生产全流程，来源包括在线成分分析系统、DCS集散控制系统、化验室报表、窑磨设备传感器、原燃料台账与能源计量装置。数据更新节奏分为实时（如窑筒体温度、在线成分数据）、每班（如设备巡检记录）、每日（如质量控制通知单、能源报表）。日常文档多为结构化工业报表与非结构化操作记录，包含熟料游离钙含量、磨机台时产量、窑热工制度参数等字段，附带通用工业单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
实时数据需要支持增量索引，避免全量扫描占用过多服务器资源；每班、每日更新的文档需要配置定期全量同步任务，确保审核所需的最新记录被纳入知识库。工业文档的格式差异较大，既有标准化化验报告也有自由格式的操作记录，需要适配多类型文本的分块与向量化。字段附带特定工业单位，检索时需匹配单位相关关键词，避免将不同参数的同类指标混淆。回转窑热工制度、配料调整等核心审核环节的内容需要优先召回，因此需要调整召回权重与搜索规则。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配工业专业术语的语义精度，避免误召回非相关的窑磨数据 |
| `limit` | 前6条 | 适配每班生成的操作记录总量，控制上下文长度不超出模型限制 |
| `searchMode` | 向量+关键词混合 | 兼顾生料配料方案的精确关键词匹配和DCS数据的语义匹配 |
| `usingReRank` | 开启 | 修正单一向量召回的偏差，优先召回回转窑热工制度相关内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充原燃料波动相关的上下文，提升配料调整场景的召回准确性 |
| `collectionIds` | 对应水泥熟料与粉磨专属数据集 | 隔离其他品类的知识库数据，避免无关内容召回 |

## 容易做错的三处
- 上传3MB的PDF格式化验报告时报错，界面显示文件解析失败。原因是未针对工业PDF的多页表格内容调整分块规则，导致单块文本长度超出系统默认上限。
- docker部署环境下知识库持续显示索引中状态，无进度更新。原因是未配置增量索引触发机制，对实时生成的化验报告执行全量索引，导致服务器资源占用过高。
- 输入中文提问后未召回知识库内的英文设备巡检文档。原因是未开启跨语言检索配置，仅匹配中文关键词，无法识别英文文本内容。

## 怎么确认配好了
- 上传一份生料配料方案PDF，等待索引完成后，检查知识库文件列表是否显示该文件，确认索引流程正常。
- 输入“调整生料配料应对原燃料波动”的提问，检查召回结果是否包含生料配料方案、窑操作记录等相关文档。
- 查看检索结果的相似度得分，确认得分处于预设的`similarity`阈值区间内，验证配置生效。
- 测试输入英文关键词“clinker free calcium”，确认是否能召回知识库内的英文化验报告内容。
- 测试输入提问，确认返回内容严格匹配知识库原文，未进行额外整理。
