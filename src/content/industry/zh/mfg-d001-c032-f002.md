# 汽车整车总装的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自ERP/MES系统、VIN与车辆配置系统、供应商批次管理模块、拧紧工具终端、EOL下线检测线及质量追溯系统。日常文档包含生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录与一致性放行文件。数据更新节奏为每车级实时更新、每班批量同步，核心字段包含唯一VIN码、装配扭矩值、供应商批次号、检测合格状态等，单条数据关联对应整车的全流程装配、检测与返修信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于该品类以VIN为单车主线关联全流程质量数据，向量索引需支持按VIN字段进行精准过滤召回，避免无关整车数据干扰召回结果。高频实时的更新节奏要求索引支持增量写入，无需每次全量重建索引以适配生产节拍。多类型文档的结构差异明显，装配作业指导书为长文本，拧紧数据为短数值型文本，需统一分块逻辑适配不同长度与类型的输入内容。单批次数据量随混线生产规模增长，需限制单批次索引的内存占用，避免服务过载。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面参数设置：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配装配作业指导书的单工位长文本，同时避免单块过长导致向量计算溢出 |
| 重叠长度 | 100–200 字符 | 保留相邻块的上下文关联，确保VIN与装配步骤的信息不被分块截断 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的召回结果，适配汽车总装场景下对质量信息准确性的要求 |
| 单次搜索上限 | 前 20 条 | 控制召回结果的数量，避免过多无关数据占用上下文窗口 |
| `maxToken` | 8000 个 | 适配长文档的上下文拼接，满足整车全流程质量信息的召回需求 |
| `defaultToken` | 1500 个 | 平衡单轮问答的输入长度与模型推理效率，适配审核场景的问题复杂度 |

## 容易做错的三处
- 现象：向量索引任务长时间处于等待状态无进度。原因：未配置按生产节拍触发的增量索引规则，使用全量索引重建适配实时更新的生产数据，导致索引任务堆积。
- 现象：召回结果与提问无关，且未关联目标VIN的质量信息。原因：未开启按VIN字段的过滤配置，召回范围覆盖全量整车数据，导致无关结果混入。
- 现象：索引任务出现超时报错。原因：未调整`defaultToken`与`maxToken`的取值，单块分块过长导致向量计算超时，或单次搜索上限设置过高超出服务承载能力。

## 怎么确认配好了
- 查看索引任务的日志，确认增量写入触发规则已按生产节拍配置，无全量重建的重复任务。
- 输入包含特定VIN的审核问题，核对召回结果仅返回该VIN关联的装配、检测与返修数据。
- 测试不同长度的提问，确认上下文拼接未超出`maxToken`的设置范围，无截断报错。
- 查看知识库的分块统计，确认单块长度符合预设区间，无异常分块。
