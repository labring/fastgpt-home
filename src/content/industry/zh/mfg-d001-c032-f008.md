# 汽车整车总装的供应商与过程质量审核：文档解析与分块

## 这个品类的数据长什么样
该品类数据主要来自ERP/MES系统、VIN与配置系统、供应商批次台账、拧紧工具、EOL检测线及质量追溯系统。更新节奏覆盖每车、实时及每班更新。日常文档包含生产订单、VIN清单、装配作业指导书、拧紧数据、下线检测报告、返修记录与一致性放行文件。数据字段包含VIN码、零件编号、扭矩参数、检测结果等，配套对应物理单位，如扭矩单位为牛米，时间单位为秒。

## 这些特征在「文档解析与分块」这一环带来什么约束
单车辆关联的配置、拧紧、检测等数据需以VIN为核心关联，分块时需避免跨VIN的无关数据混入同一块，否则检索时会返回冗余信息。多列结构化文档（如拧紧数据表格、VIN清单）存在多字段关联，解析时需保留列间关联关系，分块需匹配单条记录或单工位的完整数据。实时与每班更新的文档体量较大，分块尺寸需兼顾检索精度与存储同步效率，避免单块过大导致解析超时或检索召回范围不合理。

以下配置基于FastGPT v4.17.0版本的系统设置。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配多列结构化文档的字段关联，避免单块拆分破坏数据逻辑，同时平衡检索召回与存储开销 |
| `customPdfParse` | 启用mineru API | 适配装配作业指导书、下线检测报告等多格式PDF文档，保留图表与表格的列关联关系 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 应对单批次拧紧数据、VIN清单等体量较大的文档，避免解析超时中断 |
| `chunkSettingMode` | 按文档类型自定义 | 针对VIN清单类结构化文档与作业指导书类非结构化文档分别配置分块规则 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配每班汇总的多工位检测报告合集，避免上传时因文件过大被拦截 |

## 容易做错的三处
- 上传多列Excel文档后检索结果仅匹配前两列数据。原因是未启用适配多列结构化文档的解析模式，默认分块逻辑仅提取前两列字段。
- 启用PDF增强解析时无法调用mineru API。原因是未在系统配置中正确绑定mineru API密钥，或未开启`customPdfParse`参数。
- 条件判断组件处理解析得到的boolean类型数据后参数为空。原因是分块时未保留原始数据类型关联，解析后的字段未正确映射为布尔值格式，导致组件无法识别有效参数。

## 怎么确认配好了
- 上传一份包含多列字段的拧紧数据Excel文档，检查解析后的分块是否包含全部列的关联数据。
- 上传一份带表格的装配作业指导书PDF，确认解析后的文本保留了表格的行列结构，无字段错位。
- 上传一份100 MB左右的批量VIN清单文档，检查解析过程未触发超时错误，且分块数量符合预期。
- 在测试检索中输入单条VIN码，确认返回的分块仅包含该VIN关联的相关数据，无冗余跨VIN内容。
