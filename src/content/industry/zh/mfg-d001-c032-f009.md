# 汽车整车总装的供应商与过程质量审核：模型接入与配置

以下配置基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据来源包括ERP/MES系统、VIN与车辆配置系统、供应商批次台账、拧紧工具终端、EOL下线检测线及质量追溯系统。数据更新节奏为每车对应一次、关键工位实时上传、每班汇总批量记录。日常文档涵盖生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录与一致性放行文件，包含VIN码、零件编号、扭矩阈值、检测结果等字段，部分数据带有Nm、批次号等专属单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据以单车辆VIN为核心关联维度，混线生产下单批次数据量随生产节拍波动，模型接入需适配动态变化的上下文长度。实时拧紧数据与下线检测结果的低延迟要求，限制了推理环节的等待阈值，避免影响产线节拍。多类型文档的混合检索需求，要求配置支持跨文档字段匹配，精准关联VIN与对应装配要求。供应商批次数据的溯源要求，需模型能关联多系统的跨表数据，同时需兼容不同系统的数据格式差异，降低配置适配成本。每车级别的高频更新，也要求配置的上下文处理效率匹配生产节奏，防止延迟引发产线停滞。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单车辆关联的多文档总长度，避免截断关键VIN关联数据 |
| `vision` | 开启 | 支持解析装配作业指导书的图纸、拧紧工具的可视化日志与下线检测照片 |
| `temperature` | 0.1–0.3 | 降低推理随机性，保证扭矩阈值、VIN匹配结果的一致性 |
| 工作流/API 工具选择配置 | auto | 自动选择是否调用工具处理跨系统数据查询，适配多源数据关联需求 |
| AIPROXY_API_ENDPOINT | 产线内网部署节点地址 | 适配产线封闭网络环境，避免公网延迟影响实时推理 |
| `quoteMaxToken` | 1500 token | 限制单条引用的文档长度，聚焦与当前VIN相关的装配要求 |

## 容易做错的三处
-  新建知识库后无法启用图片理解功能，原因是未在系统配置中开启`vision`参数，且未加载支持视觉推理的模型依赖包。
-  知识库检索仅返回严格匹配的内容，无法对未知场景进行泛化推理，原因是`temperature`参数被设置为0，导致模型仅能复刻现有文档内容，无法进行合理推导。
-  模型调用外部工具失败，原因是未正确配置`AIPROXY_API_ENDPOINT`与对应令牌，导致工具调用请求无法触达产线内网的数据源接口。

## 怎么确认配好了
-  上传一份带装配图纸的作业指导书，验证模型能否正确解析图纸中的扭矩要求，确认`vision`配置生效。
-  输入一条包含未收录VIN的测试查询，验证模型能否基于现有关联文档进行合理推导，确认`temperature`参数的取值符合预期。
-  发起一次跨系统数据关联的查询，验证模型能否自动调用工具获取供应商批次信息，确认工具调用配置正常。
-  查看系统上下文长度监控日志，确认单车辆关联数据未触发`maxContext`截断阈值，验证上下文配置适配产线数据规模。
