# 汽车零部件批量制造的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
汽车零部件批量制造的供应商与过程质量审核数据，来源包括客户图纸、特殊特性清单、ERP/MES系统、量检具、设备过程参数及供应商质保书。数据更新按批次、每班持续采集，日常文档涵盖控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料及8D报告。数据字段包含客户特殊特性、工序参数、批次号、质检结果等，单位涉及毫米、牛·米、批次编号等专业工业计量标准。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据按批次高频更新的特征，要求多轮对话需严格关联当前审核批次的专属数据，避免跨批次信息干扰审核逻辑。多类型专业文档的存在，要求提示词需明确指定文档类型与字段格式，防止混淆不同工序的SPC报表与PPAP资料。受整车客户强质量约束的特点，要求对话中需严格遵循客户特殊特性的传递规则，不可随意修改参数阈值或跳过合规流程。同时，批量数据的规模要求上下文管理需裁剪冗余历史，仅保留与当前审核环节相关的内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 上下文窗口大小 | 8000–12000 token | 单批次的控制计划、SPC报表等文档总字符量较高，需保留足够的多轮对话上下文，且符合FastGPT v4.17.0的处理上限 |
| `variables` 绑定范围 | 仅绑定当前批次的工艺参数与质检数据 | 避免跨批次数据干扰审核逻辑，确保对话仅关联当前审核对象 |
| 知识库权限控制 | 按供应商与批次划分访问范围 | 遵循汽车零部件行业的保密要求，限制非授权用户访问敏感质保资料 |
| `messages` 历史截断阈值 | 保留近3轮对话与当前批次上下文 | 多轮审核中仅需关联当前工序的异常与整改记录，冗余历史会干扰判断 |
| `chatId` 绑定规则 | 仅绑定当前会话的批次标识 | 确保多轮对话始终关联同一审核批次，避免会话混淆 |
| 对话记录保存时长 | 365天 | 需留存批次审核记录用于整车厂溯源与合规检查 |

## 容易做错的三处
- 现象：对话返回的质检记录包含多个批次的内容，原因：未通过`variables`绑定当前审核批次的专属数据范围，导致召回了无关批次的SPC报表与首件记录。
- 现象：设置对话记录保存时长后未生效，原因：误修改了非平台自带的配置文件，未通过官方设置模块调整保存时长参数。
- 现象：提示词无法正确识别客户特殊特性字段，原因：未在提示词中明确指定文档来源为控制计划与特殊特性清单，导致模型混淆了工序参数与客户要求。

## 怎么确认配好了
- 发起针对特定批次的审核对话，检查返回的质检记录仅包含该批次的首件与巡检数据。
- 切换至非授权供应商的账号，确认无法访问对应供应商的PPAP资料与质保书。
- 查看平台的对话记录管理模块，确认当前对话的保存时长符合预设要求。
- 测试多轮连续对话，检查每一轮的上下文仅保留近3轮的对话内容与当前批次的相关文档。
