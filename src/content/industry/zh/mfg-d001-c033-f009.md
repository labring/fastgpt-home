# 汽车零部件批量制造的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自制动、转向、底盘等汽车零部件供应商的业务系统与现场资源，包含客户图纸、特殊特性清单、ERP/MES数据、量检具读数、设备过程参数及供应商质保书。日常生成的文档包括控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料与8D报告。数据更新节奏为每批生产、每班作业同步采集，部分关键参数持续实时更新。数据字段包含零件编号、特性参数、检测结果、批次号等，配套明确的单位体系。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据类型要求模型接入时支持多模态与结构化数据解析，需适配不同文档格式的解析逻辑。高频实时更新的数据要求配置的上下文窗口与召回逻辑适配短周期数据刷新，避免陈旧数据干扰审核结果。受整车客户强约束的固定格式文档，要求模型的提示词配置贴合行业标准文档范式，同时需匹配供应商与过程质量审核的特定流程节点。批量数据的规模要求配置的token限制与上下文长度适配批次级数据的批量处理需求，避免单次处理超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配批次级审核文档的总长度，覆盖控制计划、SPC报表等多份关联文档的内容 |
| `maxTokens` | 4000 token | 限制单次审核输出的token数量，避免超长结果超出下游系统处理上限 |
| `quoteMaxToken` | 1500 token | 限定引用的原始文档片段长度，确保审核依据的信息完整且不冗余 |
| `vision` | 开启 | 适配客户图纸、量检具读数照片等视觉类数据的解析需求 |
| `temperature` | 0.2–0.4 | 降低输出随机性，确保审核结论的一致性，符合汽车行业质量审核的严谨要求 |
| `AIPROXY_API_TOKEN` | 按项目申请的专属密钥 | 区分应用与通用权限，适配供应商审核场景的专属数据安全要求 |

## 容易做错的三处
- 现象：创建索引模型后关联的语言模型配置丢失，无法触发审核流程。原因：未正确区分索引模型与语言模型的绑定关系，误将索引模型替换为语言模型配置。
- 现象：本地部署版本中无法启用视觉解析功能，无法处理客户图纸照片。原因：未在FastGPT v4.17.0本地部署配置中加载视觉模型依赖包，或未开启`vision`相关配置项。
- 现象：检索返回的参考文档条数与预期不符，无法覆盖批次级的所有检测记录。原因：未正确配置`quoteMaxToken`或`maxContext`参数，导致召回的文档片段被截断或过滤。

## 怎么确认配好了
- 上传单份PPAP资料与首件巡检记录，验证模型能否正确提取特殊特性参数与检测结果，核对输出内容与原始文档的匹配度。
- 提交包含图纸照片的测试请求，验证视觉解析功能能否正常识别图纸中的尺寸标注与零件编号。
- 调用审核接口，使用应用特定密钥发起请求，确认返回结果无权限相关报错。
- 调整`temperature`参数并重复测试，确认输出结论的一致性符合质量审核的严谨要求。
