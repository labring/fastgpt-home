# 烘焙与方便食品的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类的典型主体为面包糕点、饼干、方便面与速冻面点工厂。日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量系统、生产设备、实验室与食品追溯台账。更新频率按生产批次、班次或每日执行，文档字段多包含批次号、原料名称、量化参数与检测结果，部分文档附带时间戳与单位标识。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。高频按批次、班次更新的文档，要求索引支持增量同步与快速刷新，避免全量重建耗时过长。多字段、带量化参数的文档结构，需要嵌入模型能够准确关联文本描述与数值信息，保障语义捕捉精度。过敏原、异物控制相关的专业文档，需嵌入模型适配食品加工领域的专属术语。频繁的产品换线带来文档结构多变，索引分块规则需兼容不同长度的文本类型。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类配方、生产记录等文档的平均长度，覆盖完整语义单元 |
| 重叠长度 | 50–100 字符 | 避免分块导致的语义断裂，保障跨块信息的连贯性 |
| `defaultToken` | 8192 token | 匹配qwen3-embedding-8b模型的上下文窗口限制，适配FastGPT v4.17.0版本的长文档处理要求 |
| `maxToken` | 1024 token | 控制单条嵌入向量的生成长度，平衡语义精度与索引存储开销 |
| 相似度阈值 | 0.75–0.85 | 保障召回结果的相关性，适配食品质量审核的严格匹配要求 |
| 单次索引上限 | 前 200 条 | 控制单次批量处理的文档数量，避免部署资源过载 |

## 容易做错的三处
- 索引任务长期停留在「索引中」状态，无进度更新。原因：未正确配置嵌入模型的访问地址与权限，或`maxToken`设置超出模型支持范围，导致嵌入生成过程超时中断。
- 新增嵌入模型配置后，原有同名称的配置被自动覆盖。原因：未使用唯一标识区分不同模型实例，仅以模型名称作为配置键，导致系统重复写入覆盖。
- 召回结果中缺失批次号、检测值等关键文档字段。原因：分块长度设置过小，将包含关联字段的完整文本拆分为语义断裂的片段，导致向量无法捕捉字段间的关联关系。

## 怎么确认配好了
- 查看嵌入模型配置页面，确认目标模型已正确添加且无重复的配置条目。
- 上传一份该品类的典型文档，触发手动索引任务，观察任务状态的更新过程。
- 输入与食品质量审核相关的测试查询，核对召回结果的匹配逻辑是否符合业务需求。
- 检查索引存储的磁盘占用与内存使用情况，确认配置后的索引处理未出现资源过载。
