# 烘焙与方便食品的供应商与过程质量审核：工具调用与插件

本文档适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类数据主要来自面包糕点、饼干、方便面及速冻面点工厂的日常生产与合规文档，包括配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量设备、烤炉或油炸线、实验室检测系统及食品追溯台账。数据按生产批次、班组班次或每日频次更新，核心字段包含物料名称、投料量、工艺参数、检测结果、保质期等，部分文档需关联过敏原标识与清洁切换记录。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据按生产批次、班组或每日更新，工具调用需支持按时间范围精准拉取对应批次的生产与检测数据。由于品类需重点管控过敏原标识、清洁切换记录等特殊字段，插件需适配自定义字段的格式校验与关联查询。由于数据来源覆盖设备、ERP、实验室等多系统，工具调用需支持多数据源的并行聚合与格式统一。由于产品换线频繁，工具调用需支持快速切换不同产线的数据集配置，避免跨批次数据混淆。同时，由于质量审核出错可能引发召回，工具调用需附带结果合法性校验环节。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 工作流/API 工具选择配置 | `auto` | 适配多工具调用场景，自动匹配当前审核所需的数据源工具 |
| 工作流/API 函数调用配置 | `enabled` | 支持自定义工具调用，适配品类多字段校验需求 |
| 超时阈值 | `60–120 秒` | 品类数据多来自实时设备与业务系统，需在合理时间内拉取批次数据 |
| 自定义字段映射 | 按过敏原、投料量、工艺曲线字段匹配 | 品类需重点管控过敏原与生产参数，需将工具返回数据映射至对应审核字段 |
| 批量调用上限 | `前 10 条批次数据` | 单次审核仅需覆盖当前待查批次，避免过多数据占用上下文 |
| 数据源校验开关 | 开启 | 品类质量审核需严格匹配合规文档，需校验工具返回数据的来源合法性 |

## 容易做错的三处
- 现象：添加MySQL数据库工具调用后，对话返回400 status code (no body)。原因：未正确配置数据库连接的认证字段，或工具调用的SQL语句未匹配品类的批次数据查询格式。
- 现象：自定义代码调用生产数据接口时，提示AggregateError Code:ETIMEDOUT。原因：未设置合理的超时阈值，或数据源接口响应速度超出工具调用的等待时间。
- 现象：工具返回的过敏原数据为空，审核结果异常。原因：未配置自定义字段映射规则，导致工具无法识别品类特有的过敏原标识字段。

## 怎么确认配好了
- 执行单次批次数据查询，核对工具返回的字段是否包含配方、投料量、金属检测结果等品类核心文档字段。
- 模拟异常数据场景，触发工具调用校验，确认是否触发自定义字段的格式校验逻辑。
- 调整数据源的时间范围，核对工具是否能精准拉取对应批次的生产数据。
- 查看工具调用日志，确认返回的状态码与响应内容符合预期配置。
