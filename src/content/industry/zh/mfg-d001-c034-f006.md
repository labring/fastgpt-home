# 烘焙与方便食品的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
典型主体为面包糕点、饼干、方便面和速冻面点工厂，日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源涵盖原辅料合格证明、ERP/MES系统、称量系统、烤炉或油炸线、实验室检测设备、食品追溯台账。数据更新频率为每批、每班或每日，核心字段包含过敏原标识、烘烤/油炸温度与时长、包装日期、保质期、批次号等，部分文档为结构化表格格式，部分为非结构化文本，字段结构随生产环节差异有所不同。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的多文档格式、高频更新与细分字段特征，对引用溯源环节带来多重约束。首先，混合格式的日常文档要求分块规则需适配结构化表格与非结构化文本，避免拆分配方投料单的配料行或烘烤曲线的时间-温度序列。其次，每批、每班的高频更新要求知识库支持增量同步，避免重复加载旧批次数据导致上下文过载。再者，过敏原、批次号等核心字段的精准提取需求，要求召回结果优先匹配高权重字段，同时需保留原始数据的来源标识，确保溯源时可定位到具体生产环节。产品直接食用的特性也要求溯源信息不可出现误差，需严格匹配批次与检测结果的对应关系。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配该品类单份文档的字段密度，避免拆分配方投料单的配料组或烘烤曲线的完整序列 |
| `quoteMaxToken` | 1500–2000 token | 适配金属检测报告、生产记录等长文本的完整引用，确保审核时可查看全部参数细节 |
| 单次搜索上限 | 前6条 | 覆盖多源数据的召回需求，同时避免上下文过载影响审核效率 |
| `responseData` | 仅返回核心字段 | 仅提取过敏原、批次号、检测结果等关键信息，简化溯源时的信息筛选成本 |
| `detail` | 开启 | 保留引用数据的原始来源标识，便于追溯到具体的生产批次或检测报告 |
| 增量更新开关 | 按实测标定 | 适配每批、每班的高频更新节奏，避免重复加载旧数据 |

## 容易做错的三处
- 批量上传100份5kb文档时，界面显示一半文件训练异常，日志出现「格式不匹配」报错。原因：未针对该品类的混合格式文档设置统一的分块规则，导致部分结构化表格文档被错误拆分。
- 切换为变量引用模式后，温度设置按钮消失，无法调整生成参数。原因：变量引用模式下的参数需通过`responseData`绑定的上下文字段传递，未正确配置关联项。
- 引用内容模板中{{id}}字段返回空值，无法定位具体溯源数据。原因：未开启`detail`配置，系统未保留引用数据的唯一批次标识，导致模板变量无法提取有效信息。

## 怎么确认配好了
- 上传一份完整的面包配方文档，查看引用结果是否包含全部配料、过敏原标识等核心字段，调整分块长度至匹配文档内容。
- 批量上传多份同批次的检测报告，确认知识库训练状态全部正常，且引用时自动去重重复的批次数据。
- 调用引用模板，验证{{id}}字段返回对应文档的唯一批次标识，确认`detail`配置生效。
- 调整`quoteMaxToken`参数，验证长文本的引用不会被截断，确保完整显示烘烤曲线的全部数据。
