# 烘焙与方便食品的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
该品类涵盖面包糕点、饼干、方便面及速冻面点工厂，日常数据包含配方与投料单、生产记录、烘烤/蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量设备、生产产线、实验室检测系统及食品追溯台账，更新频率为每批、每班或每日。单批次数据包含过敏原标识、生产温度、时间阈值等字段，单位涉及摄氏度、秒、千克等，且因产品换线频繁，同批次内的文档类型与字段组合存在差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的高频换线与多源数据特征，要求模型接入配置需适配短周期、多类型的文档处理需求。每批/每班的高频更新要求模型调用的响应速度需匹配生产节奏，避免因配置不当导致数据处理延迟。过敏原核查与生产窗口控制为核心审核环节，要求配置需支持精准的字段提取与规则匹配，避免模糊处理。多源数据对接需求则要求配置需兼容不同系统的API接口，确保数据同步的稳定性。此外，直接食用的产品属性要求审核结果需具备高严谨性，对模型输出的可控性提出了更高要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 单批次的配方、生产记录、检测记录总长度通常处于该区间，可避免截断关键的过敏原信息与生产参数 |
| `maxTokens` | 1500–2000 token | 匹配质量审核报告的标准输出长度，避免过长导致调用超时或资源浪费 |
| `temperature` | 0.1–0.3 | 质量审核需要严谨的结论输出，该温度区间可降低生成内容的随机性，提升结果可信度 |
| `toolChoice` | auto | 可根据输入的文档类型自动选择过敏原核查、生产曲线分析等适配工具，适配多类型审核场景 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的数据源接口填写 | 用于对接ERP/MES、检测设备等多源数据，确保数据同步的正确性 |
| `AIPROXY_API_TOKEN` | 按对应接口的认证要求填写 | 保障多源数据对接的安全性，避免未授权访问 |

## 容易做错的三处
- 现象：创建应用时无法勾选已配置的重排模型，或出现“当前分组 default 下对于模型 gpt-4o 无可用渠道”报错。原因：未在`AIPROXY_API_ENDPOINT`中配置重排模型的专属API端点，或配置的令牌未覆盖重排模型的调用权限。
- 现象：尝试导入本地LLaMA 3模型处理知识库文件时加载失败。原因：未正确配置`AIPROXY_API_ENDPOINT`指向本地部署的LLaMA 3接口，或配置的令牌未授权访问该模型。
- 现象：搜索结果仅返回模糊匹配内容，无法触发AI补充审核结论。原因：未正确设置`toolChoice`为适配审核场景的模式，或`maxContext`配置过小导致无法加载完整的生产记录与配方数据。

## 怎么确认配好了
- 进入FastGPT v4.17.0的应用配置页面，检查已配置的模型列表是否包含目标模型，确认无“无可用渠道”类报错。
- 上传一份单批次的烘焙生产记录文档，发起审核请求，等待10–30秒查看输出结果，检查是否包含过敏原核查、生产窗口核对等核心审核内容。
- 调用测试接口，验证`maxContext`与`maxTokens`的配置是否符合预期，无内容截断或调用超时情况。
- 查看数据源对接日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无连接失败或权限报错。
