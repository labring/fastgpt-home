# 烘焙与方便食品的供应商与过程质量审核：知识库检索与召回

## 这个品类的数据长什么样
典型主体为面包糕点、饼干、方便面和速冻面点工厂。日常文档包括配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验。数据来源涵盖原辅料合格证明、ERP/MES、称量系统、烤炉或油炸线、实验室、食品追溯台账。更新频率为每批、每班、每日。文档结构包含结构化表格、时序曲线与文本记录，字段涉及原料名称、投料量、过敏原标注、烘烤参数、保质期等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
烘焙与方便食品生产换线频繁，配方与过敏原信息需快速精准匹配，因此知识库检索需要支持多维度的字段匹配。多源异构的数据来源要求检索系统能够整合不同格式的文档，避免信息割裂。高更新频率意味着检索召回需要适配实时或近实时的数据同步，确保审核时使用最新的生产记录与检验报告。过敏原管控是核心风险点，检索需优先召回过敏原相关的投料、清洁文档，避免错标或交叉污染。该品类更依赖配方与清洁切换的验证，因此检索的重点需向清洁消毒记录与配方调整文档倾斜。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配过敏原标识、配方参数等关键信息，平衡精准度与召回覆盖范围 |
| `limit` | 前8条 | 覆盖单批次生产的多类文档，避免结果过多干扰审核人员复核 |
| `usingReRank` | 开启 | 对召回的结果按相关性重新排序，优先展示烘烤曲线、过敏原相关文档 |
| `datasetSearchUsingExtensionQuery` | 开启 | 针对换线频繁的场景，优化检索query，匹配不同批次的投料单与生产记录 |
| `searchMode` | hybrid | 兼顾配方的精确字段匹配与生产记录的文本描述，适配多类文档结构 |

## 容易做错的三处
- 配置嵌入模型时未选择`text-embedding-ada-002`（或指定其他未配置的模型），触发`undefined model must match "^(text`报错。原因是未在知识库设置中完成对应模型的配置，或选型不符合FastGPT v4.17.0的支持范围。
- 多列结构化excel（如投料单）导入后自动分段混乱，无法按每行作为独立分段。原因是未针对多列数据调整分段规则，默认自动分段未识别列与行的对应关联。
- 本地知识库未上传对应文档，仍在审核结果中展示知识库引用标识。原因是未关闭全局的知识库引用展示开关，或未将无关数据集从当前审核的检索范围中排除。

## 怎么确认配好了
- 上传一份测试用的多列excel投料单，触发自动分段，确认每行作为独立分段完成拆分。
- 发起包含过敏原关键词的检索，检查返回结果的引用来源是否仅包含配置的目标数据集。
- 调整`similarity`的取值，验证召回结果的数量随阈值变化符合预期。
- 关闭知识库引用展示开关，发起检索，确认结果中无额外的引用链接或标识。
