# 热处理的供应商与过程质量审核：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自材料牌号台账、客户技术要求文件、炉温温控仪表、炉温均匀性检测报告、硬度计与金相设备导出数据、车间MES系统。数据按每炉次、每批更新，核心文档包含热处理工艺卡、装炉布局图、实时炉温曲线、硬度与金相检测报告、设备点检记录表、异常处置单。数据字段包含材料牌号、加热温度、保温时长、冷却速率、炉温偏差值、硬度值、金相组织类型等，部分参数带有明确单位，如温度为摄氏度、时长为分钟，部分非结构化数据如炉温曲线需通过图表解析工具提取。

## 这些特征在「工具调用与插件」这一环带来什么约束
每炉次的高频更新要求工具调用需支持低延迟触发，避免延迟导致的审核流程中断。多类型异构文档（工艺卡、曲线、报告）要求插件需适配不同格式的解析，支持提取结构化字段与非结构化图表数据。数据关联强，需通过工具调用关联材料牌号、客户要求与检测结果，插件需支持跨数据源的字段匹配。单次异常可能导致整炉报废，要求工具调用的结果校验环节需覆盖关键参数，异常时触发预设的异常处置流程。同时，数据的强关联性要求工具调用的上下文需保留当前炉次的所有关联数据，避免跨批次数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配多类型异构文档的工具调用需求，无需手动指定工具，覆盖工艺卡、检测报告等多种审核场景 |
| 工具调用超时时间 | 300 秒 | 匹配炉温曲线、金相报告等数据的提取与校验耗时，避免超时中断审核流程 |
| 工具返回结果校验规则 | 按必填字段（材料牌号、炉温、硬度值）校验 | 确保提取的数据符合热处理审核的核心要求，避免无效结果进入后续流程 |
| 工具调用失败重试次数 | 2 次 | 平衡重试成本与流程效率，应对临时的设备数据读取异常或网络波动 |
| `functionCall` | 开启 | 支持结构化的工具调用参数传递，适配数值型的温度、时长等参数的准确传输 |
| 工具调用结果格式 | 结构化 JSON | 便于后续与MES系统的异常处置单做字段匹配，简化审核流程的自动化处理 |

## 容易做错的三处
- 现象：工具调用返回结果为空，无有效热处理工艺或检测数据。原因：未配置工具返回结果的必填字段校验，导致未匹配到材料牌号、炉温偏差等核心字段的结果被丢弃。
- 现象：MCP服务调用时，自定义参数的type被固定为string类型。原因：插件配置未启用结构化参数声明，导致所有传入参数默认以字符串格式传递，无法适配数值型的温度、时长参数。
- 现象：工具调用的流输出无法主动停止，持续占用会话资源。原因：未关闭工具调用的流输出开关，导致会话无法正常结束审核流程。

## 怎么确认配好了
- 上传一份标准热处理工艺卡，触发工具调用，核对提取的材料牌号、加热温度等字段是否与文档内容一致。
- 模拟炉温数据读取异常，触发工具调用，核对是否按配置的重试次数执行重试操作。
- 查看FastGPT v4.17.0的插件配置页面，确认`toolChoice`参数设置为auto或指定的工具类型，符合当前审核场景需求。
- 关闭工具调用的流输出开关后，触发工具调用，核对会话是否在工具调用完成后正常结束，无持续输出。
