# 热处理的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来自材料牌号、客户技术条件、温控仪表、炉温均匀性测试设备、硬度计与金相设备、生产执行系统（MES）。日常产出热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单。数据按每炉次、每批更新，字段包含炉温区间、保温时长、硬度值、金相组织评级等，附带明确的单位标识，如温度以摄氏度计，时长以分钟或小时计，单条数据体量适中但批次关联性强。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类数据的高时效性、多文档类型与精准字段要求，对引用溯源环节带来多重约束。每炉次的专属数据需绑定唯一炉批号，避免跨批次数据混淆。多类型文档（含图表类的装炉图、炉温曲线）要求溯源系统能识别并关联非纯文本数据集。带明确单位的字段需在检索时匹配单位信息，防止无关数据被误引。同时，过程审核需追溯异常处置单的关联流程，要求溯源链路覆盖从工艺制定到异常处理的全环节，确保审核依据的完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文token数 | 8000–12000 token | 适配单炉次全量数据的总字符量，避免截断关键工艺参数与炉温曲线 |
| `quoteMaxToken` | 1500–2000 token | 限定单条引用的返回长度，适配硬度报告、金相分析结果的单段数据长度 |
| 引用详情展示 | 开启 | 确保返回的引用包含完整字段与单位信息，如炉温1250℃、硬度HRC35 |
| `responseData` | 包含工艺卡、装炉图、异常处置单等所有类型 | 覆盖多类数据源，避免仅引用文本数据集 |
| `detail` | 按实测标定 | 控制引用内容的展开层级，匹配过程审核需核对的具体环节粒度 |
| 单次召回上限 | 前8条 | 匹配单炉次相关文档的常规数量，避免冗余引用干扰审核判断 |

## 容易做错的三处
- 现象：返回的引用仅包含文本类文档，未关联装炉图、炉温曲线等非文本数据。原因：未配置`responseData`覆盖全类型数据源，仅默认启用了文本数据集的召回。
- 现象：引用内容与专业知识库中的实际数据不匹配，或未命中预期的炉次数据。原因：未限定`quoteMaxToken`的合理范围，导致截断了关键参数或引入了无关批次的数据。
- 现象：调用API传入知识库后，无法关联到对应热处理数据。原因：未将知识库ID作为工作流入参传递，导致工作流无法定位到指定数据源。

## 怎么确认配好了
- 上传单炉次的热处理工艺卡、炉温曲线与硬度报告，发起审核类提问，检查返回的引用列表是否包含所有上传的文档类型。
- 查看单条引用的展开内容，确认是否包含完整字段与单位信息，如保温时长、硬度值的具体参数。
- 调用API传入指定知识库ID，检查工作流是否能正确召回对应批次的热处理数据，无空引用或错误关联。
- 查看系统日志，确认`quoteMaxToken`的配置值未导致引用内容被过度截断，符合FastGPT v4.17.0版本的参数规则。
