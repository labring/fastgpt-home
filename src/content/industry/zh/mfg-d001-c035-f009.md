# 热处理的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
数据来源包括材料牌号、客户技术条件、温控仪表、炉温均匀性测试设备、硬度计、金相设备与生产执行系统。更新节奏为每炉次、每批更新一次。日常文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单，其中工艺卡包含加热温度、保温时长、冷却方式等结构化字段，炉温曲线为带时间轴的折线图，硬度报告标注HV等力学性能单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
多类型文档与高频更新要求模型接入适配可视化内容与实时数据同步需求。专业字段与固定单位需要模型具备行业术语识别能力，避免参数解析错误。单炉次文档总长度适中但包含多组关联数据，需控制上下文总量以适配模型输入限制。异常处置单的时效性要求召回的历史数据需精准匹配当前批次参数，避免无关内容干扰审核结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启 | 需识别装炉图、炉温曲线等可视化文档内容，满足审核场景的图像解析需求 |
| `maxTokens` | 8000–16000 token | 热处理相关文档包含多组炉温、硬度、金相数据，需足够的token承载完整上下文 |
| `quoteMaxToken` | 4000 字符 | 单炉次关联文档总长度适中，该取值可平衡上下文召回量与模型输入限制 |
| `temperature` | 0.1–0.3 | 供应商与过程质量审核需精准判断参数合规性，不宜过度发散 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写本地或云端端点 | 适配FastGPT v4.17.0的模型接入规范，支持本地部署与云端调用两种模式 |

## 容易做错的三处
- 现象：在线召回测试时返回结果未按重排顺序展示，原因：未在知识库索引环节同步开启重排配置，且未关联对应重排模型。
- 现象：配置引用上限调整至3000以上后，上下文无法传递给大模型，原因：超出FastGPT平台的上下文承载上限，未按实际文档长度调整相关参数。
- 现象：上传的炉温曲线图片无法被正确识别，原因：未开启`vision`配置，或未接入支持视觉能力的模型。

## 怎么确认配好了
- 上传单份热处理工艺卡与炉温曲线图片，发起测试提问，检查是否能正确识别图片内的文字参数与图表趋势。
- 调整`maxTokens`参数至不同区间，验证输入上下文长度是否符合预期配置。
- 发起多轮质量审核提问，检查返回结果是否包含正确的专业字段与单位。
- 查看FastGPT v4.17.0的应用日志，确认模型接入端点与令牌配置无报错。
