# 焊接结构件制造的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自设计图纸、材料质保书、焊接设备参数、焊材库、无损检测系统及人员资质台账。日常文档包含焊接工艺评定、焊接工艺规程、焊材领用记录、焊工资格记录、焊缝检验报告、返修单。数据更新以每条焊缝或每批、每班为节奏，单条文档多包含工艺参数、资质编号、检测结果等明确结构化字段，部分图纸类文档含结构化尺寸与焊接位置信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据的高频更新节奏要求索引支持增量同步，避免全量重建耗时过长。多类文档的字段差异，如工艺参数的数值型字段、资质的编号型字段、检测报告的文本型字段，要求索引适配混合格式数据。焊缝相关的单条数据体量较小但更新频次高，需控制分块粒度以匹配单焊缝的信息边界。部分来源数据含非结构化图纸片段，需额外配置适配图像或结构化图纸的索引规则，同时需保证资质编号、焊材批号这类关键字段的向量检索精度，支撑快速核验。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配单份焊接工艺文档的典型段落长度，避免切割破坏工艺参数完整性 |
| 重叠长度 | 100–200 字符 | 覆盖焊缝检测报告中跨块的关键结论描述，防止检索时丢失上下文 |
| `defaultToken` | 4096 | 适配多数外接API的默认token上限，满足焊接工艺评定文档的完整内容输入 |
| `maxToken` | 8192 | 覆盖包含多张焊缝图纸描述的长文档，避免内容被截断 |
| 相似度阈值 | 0.75–0.85 | 区分合格与不合格的焊材资质匹配结果，降低误判概率 |
| 单次搜索上限 | 前 10 条 | 匹配班组级审核时需快速调取的多份参考文档数量 |

## 容易做错的三处
- 现象：使用PG数据库docker部署时，知识库索引始终无法建立，宿主机为8核16G无GPU虚拟机。原因：未配置适配结构化焊材领用记录的分块规则，且默认索引分片大小超出虚拟机内存可分配阈值。
- 现象：外接向量与语言API时，arm软路由运行出现卡顿或超时。原因：未关闭本地模型加载，仅依赖外接API的硬件资源，但未配置合理的`defaultToken`上限导致单次请求数据量过大。
- 现象：导入飞书文件夹内的excel与多维文档后，检索结果为空。原因：未开启对应文件格式的解析开关，且未调整分块长度适配excel表格的单元格字段结构。

## 怎么确认配好了
- 上传单份焊材领用记录文档，触发索引建立，查看索引状态显示为完成，且检索该文档的焊材批号可返回匹配结果。
- 配置外接API后，发起一次小型检索请求，确认响应时长符合预期，且无连接超时报错。
- 导入多类文档，包括焊接工艺规程、焊缝检验报告，检索焊工资质编号，确认返回结果包含对应资质的完整记录。
- 查看索引分片占用内存，确认未超过宿主机可分配内存的合理比例，无内存溢出相关报错。
