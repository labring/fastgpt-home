# 生产计划与车间排程的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自企业ERP系统、车间生产终端与供应商协同文档，涵盖销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单等类型。数据更新节奏不固定，包含每日的产能与库存更新、每周的排程调整，以及插单、缺料、设备故障时的临时更新。文档包含结构化字段，如订单号、物料编码、产能工时、班次人数，与非结构化描述，如工单异常说明、交期变更原因，单位涉及件、小时、天等生产场景标准单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且格式混合，结构化数值与非结构化文本并存，要求向量模型同时适配两类内容的编码逻辑。更新频率波动大，存在突发的临时更新，需要索引支持增量更新与快速同步。数据体量随订单量与工序复杂度增长，单批次检索需覆盖多工序、多物料的关联数据，对索引的召回效率与准确率提出要求。此外，文档内包含大量生产专属术语与编号，向量索引需保留语义关联的精准性，避免检索结果偏离供应商质量审核与排程调整的核心需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配该品类工单、排产表的平均内容长度，避免块内语义割裂 |
| 重叠长度 | 100–150 字符 | 衔接相邻分块的语义，避免排程工序、物料关联信息被截断 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的供应商到货记录与排程冗余条目，适配质量审核的检索精度 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| 单次搜索上限 | 前 20 条 | 平衡检索效率与召回覆盖范围，满足多工序排程的关联数据需求 |

## 容易做错的三处
- 现象：调用 VLLM 部署的 Qwen3-Embedding-8B 时出现连接超时或格式错误。检查 vLLM 地址、请求格式、模型日志与输入长度。`defaultToken`控制文本切分，不是嵌入维度。
- 现象：检索供应商质量审核相关内容时返回大量不相关的库存记录，原因是相似度阈值设置过低，未过滤非核心的物料库存数据。
- 现象：查看知识库磁盘占用时发现重复的原文件与嵌入向量条目，原因是未配置按更新频率增量更新索引，导致重复生成相同内容的向量数据。

## 怎么确认配好了
- 在 FastGPT v4.17.2 中，按所选嵌入模型/服务输入上限核对`maxToken`，并用代表性工单抽查`defaultToken`的分块效果。
- 手动上传一份测试工单文档，查看切分结果的块长度与重叠长度符合预设的800–1200字符与100–150字符区间。
- 执行一次供应商质量审核相关的检索，确认返回结果的条数与单次搜索上限的前20条匹配。
- 查看系统磁盘占用统计页面，确认统计范围包含原文件、分割后的文件块与嵌入向量三类数据。
