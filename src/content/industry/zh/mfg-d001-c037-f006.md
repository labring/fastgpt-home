# 生产计划与车间排程的供应商与过程质量审核：引用来源与溯源

本页面适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据来源包括ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。日常处理的文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单。数据更新频率为每日、每周，或在订单生成、异常发生时触发。文档字段包含订单号、物料编码、产能单位、班次时长、在制品数量等，需匹配工序、设备、人员的关联信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源且不定期更新的数据要求溯源系统需精准绑定每个业务文档的来源标识，避免混淆不同批次的排程数据。多样的文档结构要求溯源配置需适配不同字段的提取规则，例如从工单中提取工序信息、从供应商到货单中匹配物料交付状态。跨环节的业务流程要求溯源链路需覆盖订单分解、排程调整、交期变更的全路径，以便快速定位质量审核中的异常源头。审核场景还需平衡溯源信息的完整性与展示简洁性，避免冗余数据干扰判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配主生产计划、物料需求计划等长文档的完整内容保留，避免截断关键溯源字段 |
| `responseData` | 开启数据源关联标记 | 匹配ERP订单、BOM、供应商到货等多类业务源的信息绑定，满足审核溯源需求 |
| `detail` | 开启全链路溯源 | 记录工单分解、排程调整、交期变更的完整流程，覆盖生产计划的全环节 |
| 最大上下文召回数 | 前8条匹配结果 | 覆盖单次排程涉及的多工单、物料需求，按实测标定 |
| 引用展示开关 | 可手动配置开启/关闭 | 适配审核场景的信息展示要求，满足用户调整引用展示的需求 |

## 容易做错的三处
- 现象：知识库回答末尾强制显示引用标记且无法取消，原因：未配置引用展示开关的默认关闭选项，未适配审核场景下的非强制引用需求。
- 现象：输入的换行符`\n`被原文输出未实现格式换行，原因：未开启文本解析的换行渲染配置，导致周日排产表、工单等带换行的文档无法正常展示。
- 现象：溯源结果的引用条数超出预期上限，原因：未根据生产计划的文档数量合理调整`quoteMaxToken`或召回数，导致过多非必要的历史排程数据被纳入溯源范围。

## 怎么确认配好了
- 输入包含具体工单编号的查询，检查回复中是否关联了对应的ERP订单、物料需求计划等数据源标签。
- 测试输入包含换行的周日排产表查询，确认回复中的换行符被正确渲染为段落分隔。
- 调整引用展示开关的配置，验证回复末尾的引用标记是否可以正常开启或关闭。
- 输入涉及多工单的批量查询，检查返回的溯源结果条数是否符合设定的召回数范围。
