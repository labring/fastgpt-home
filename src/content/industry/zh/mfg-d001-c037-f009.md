# 生产计划与车间排程的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来源于企业ERP系统订单与库存、BOM清单、工艺路线、设备产能台账、人员排班表、在制品库存记录及供应商到货回执。数据更新节奏包含每日同步产能与排班、每周更新主生产计划，以及订单变更、缺料、设备故障等异常发生时的实时刷新。日常处理的文档包含销售订单、物料需求计划、周日排产表、生产工单、缺料清单、交期变更单，字段包含订单编号、物料编码、工序工时、设备负载率、在制品数量等，单位涵盖件、小时、台、班次等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入需支持跨系统数据拉取与格式适配，避免因字段不匹配导致的信息丢失。更新频率的不确定性要求配置需支持增量同步与按需触发刷新，保障排程与审核数据的时效性。复杂的文档结构与多维度字段，要求模型上下文配置需适配长文本处理需求，同时需针对不同文档类型设置字段映射规则。此外，生产计划与排程需严谨的结果输出，要求模型配置需兼顾响应速度与输出稳定性，避免因参数设置不当导致排程建议偏差或审核结论失效。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 生产计划与排程数据包含多份关联文档，应完整传入订单、排程表、缺料清单等内容以保障逻辑关联 |
| `maxTokens` | 4000–6000 token | 生成排程调整建议或质量审核结论的文本长度需求，避免输出被截断 |
| `temperature` | 0.2–0.4 | 生产场景需严谨的结果输出，降低随机性以保障排程与审核结论的一致性 |
| `quoteMaxToken` | 1500–2000 token | 限制单条引用文档的长度，避免过长内容干扰模型对核心排程逻辑的判断 |
| `AIPROXY_API_ENDPOINT` | 企业内部私有代理地址 | 保障生产敏感数据不直接暴露至外部网络，符合制造企业数据安全要求 |
| 工作流/API 工具选择配置 | auto | 允许模型自主判断是否调用排程计算、数据校验等工具，适配复杂的审核与排程场景 |

## 容易做错的三处
- 现象：知识库可检索到排程表与工单数据，但传递给大模型后无输出。原因：`maxContext`配置值过小，检索到的长文本超出上下文上限被截断，导致模型无法获取完整输入信息。
- 现象：模型生成的排程建议与实际设备产能、人员班次严重不符。原因：`temperature`取值过高，导致模型输出随机性过强，偏离生产计划的严谨性要求。
- 现象：模型调用返回认证失败或接口异常。原因：`AIPROXY_API_TOKEN`填写错误，或未配置内部代理直接调用外部模型，违反生产数据安全规范。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本执行。
- 上传一份测试工单与周日排产表，触发模型调用，检查上下文展示面板中是否完整显示传入的文档内容。
- 调整`temperature`参数后再次发起测试请求，对比两次生成的审核结论，确认结果稳定性符合生产场景要求。
- 填写错误的`AIPROXY_API_TOKEN`，验证是否触发认证报错，确认代理与密钥配置生效。
- 模拟插单场景发起请求，检查模型是否能关联现有排程数据生成合理的调整建议。
