# 生物制品与无菌生产的供应商与过程质量审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类典型数据来自细胞库与种子批、过程分析、洁净区监测、MES、LIMS、设备完整性测试等系统。日常文档包含细胞库或种子批记录、培养纯化记录、无菌灌装记录、环境监测数据、培养基模拟灌装结果、无菌检验报告、批放行资料。数据更新节奏分为每批生产完成、实时监测触发、按固定监测计划执行三类，核心字段包含批次标识、检测项名称、结果值、时间戳，部分检测项带有专属单位，如菌落形成单位/立方米、摄氏度、小时等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据来源分散，需对接多套外部系统的HTTP接口，因此需支持多端点配置与差异化鉴权规则。数据更新节奏多样，要求接口支持定时拉取与实时触发两种调用模式，适配不同类型数据的获取需求。文档字段与业务强绑定，需要精准指定返回字段以避免无关数据干扰审核流程。数据关联要求高，需通过批次号等参数关联种子批、过程记录与放行资料，因此接口需要支持参数化查询。同时由于出错后果严重，接口需配置严格的鉴权与数据校验规则，防止错误数据进入审核环节。

## 配置怎么定
本页配置基于 FastGPT v4.17.0 版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | Bearer Token 格式，绑定企业专属鉴权密钥 | 严格限制未授权访问，保护敏感生产与质量数据 |
| `variables` | 传入批次号、检测项类型等业务参数 | 精准拉取对应批次的质量审核相关数据，避免冗余请求 |
| `responseData` | 仅返回批次号、检测结果、时间戳等核心业务字段 | 减少无效数据传输，适配生产数据的精简处理需求 |
| 定时拉取间隔 | 15–60 秒（实时监测数据）、每批生产结束后触发（批记录数据） | 匹配数据更新频率，平衡数据时效性与接口调用成本 |
| 失败重试次数 | 3 次，间隔 10 秒 | 应对临时网络波动，同时避免重复提交导致的数据混乱 |
| 返回数据校验规则 | 按业务阈值校验无菌检测结果、环境参数范围 | 确保接入数据符合生产要求，防止错误数据进入审核流程 |

## 容易做错的三处
- 现象：调用接口后返回空结果，无法拉取到LIMS中的批放行资料。原因：未在`variables`参数中传入正确的批次号参数，导致接口无法匹配对应业务数据。
- 现象：接口返回`403 Forbidden`状态码。原因：未按要求配置`Authorization`参数，使用了过期的鉴权密钥，导致访问被拒绝。
- 现象：接口返回的`responseData`包含大量无关的设备运行日志字段。原因：未配置返回字段过滤规则，拉取了非审核必需的数据，增加后续处理负担。

## 怎么确认配好了
- 调用接口并传入测试批次号，检查`responseData`中是否包含预期的核心业务字段，验证返回字段过滤配置生效。
- 使用合法的专属鉴权信息发起请求，确认未返回`401`或`403`状态码，验证`Authorization`配置正确。
- 模拟临时网络中断后重试请求，确认接口按配置的重试次数自动重连，验证失败重试逻辑生效。
- 配置对应更新周期的定时拉取任务，等待周期结束后检查是否成功拉取到新的批次数据，验证定时触发配置生效。
