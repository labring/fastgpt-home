# 生物制品与无菌生产的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源包括细胞库与种子批、过程分析系统、洁净区监测数据、MES、LIMS及设备完整性测试记录。数据更新节奏覆盖每批生产周期、实时监测节点及固定监测计划。日常文档包含细胞库或种子批记录、培养纯化记录、无菌灌装记录、环境监测报告、培养基模拟灌装结果、无菌检验报告及批放行资料。字段包含批编号、培养温度、洁净区沉降菌数、设备运行时长等，单位多为℃、cfu/㎡、小时等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据按批、实时或固定计划更新，多轮对话需保留对应批次的上下文信息，避免跨生产批的审核数据混淆。日常文档包含多维度过程与检验记录，提示词需明确限定检索范围为当前审核批次的关联文档，防止无关数据干扰审核逻辑。字段带有专业单位，多轮对话需自动识别并匹配字段单位，避免单位不匹配导致的检索偏差。无菌生产审核涉及高风险场景，多轮对话需固定上下文窗口大小，防止关键历史审核记录被新对话内容挤出。同时，多轮对话需维护`messages`数组的顺序，确保历史对话的逻辑连贯，避免审核判断出现偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文窗口 | 8000–12000 token | 适配本品类单批审核文档的总字符规模，避免关键历史对话内容被截断 |
| 关联知识库上限 | 前6个 | 匹配本品类审核需关联的核心文档类型数量，避免检索资源过载 |
| 单次输入字符限制 | 2000–3000 字符 | 适配单批次审核问题的常规输入长度，防止输入超限报错 |
| `chatId` 绑定规则 | 按生产批次绑定 | 确保同批次审核的多轮对话共享统一上下文，防止跨批次数据混淆 |
| `variables` 预设参数 | 填入当前批编号、生产车间编号 | 为多轮对话提供固定检索依据，简化后续提问的重复输入 |
| `messages` 数组维护 | 按对话顺序保留历史内容 | 确保多轮对话的逻辑连贯，避免历史对话顺序混乱 |

## 容易做错的三处
- 调试预览界面出现模型自动切换为非目标模型的报错。原因是未正确配置LLM调用的绑定规则，导致系统默认调用了预设的公共模型。
- 关联知识库数量超出上限后无法加载审核文档。原因是未调整关联知识库上限配置，超出预设的检索数量阈值。
- 输入json格式的审核文档片段时触发字符超限报错。原因是未调整单次对话输入限制的取值，未适配长片段的审核数据输入。

## 怎么确认配好了
- 发起同批次的连续多轮提问，核对对话界面保留了之前的批次编号与审核上下文。
- 调整关联知识库数量后，测试加载对应批次的所有核心文档，确认检索结果覆盖全部需要的文档类型。
- 输入长片段的json格式审核数据，核对系统未触发输入超限的报错提示。
- 检查FastGPT v4.17.0的LLM调用日志，确认每次对话均调用了预设的本地模型，未出现自动切换的情况。
