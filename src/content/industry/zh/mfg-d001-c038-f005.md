# 生物制品与无菌生产的供应商与过程质量审核：工具调用与插件

## 这个品类的数据长什么样
这个品类的数据来自细胞库与种子批、过程分析、洁净区监测、MES、LIMS、设备完整性测试。数据更新节奏包含每批、实时、按监测计划。日常文档涵盖细胞库或种子批记录、培养纯化记录、无菌灌装记录、环境监测、培养基模拟灌装、无菌检验、批放行资料。字段包含种子批编号、培养温度、灌装环境沉降菌数、批放行检验结果等，对应单位为℃、cfu/㎡、批次号等。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散且格式多样，要求工具调用需支持对接多类数据源插件，实现跨系统数据拉取。数据更新节奏差异大，工具调用需适配按需触发与批量调度的不同场景。文档结构复杂且字段要求严格，工具调用的参数需精准匹配业务字段，避免泛化调用导致的信息偏差。同时，审核出错后果严重，工具调用需内置校验与失败重试机制，保障数据调用的准确性与稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配生物制品审核的多工具需求，自动选择供应商与过程质量审核的对应插件 |
| `functionCall` | `strict: true` | 强制匹配种子批编号、培养参数等关键审核字段，避免遗漏核心信息 |
| 插件超时设置 | 300 秒 | 适配复杂的批放行数据查询与跨系统调用的耗时需求 |
| 批量触发阈值 | 每批 1 次 | 匹配该品类按批更新的数据节奏，避免重复触发导致的资源浪费 |
| 工具重试次数 | 2 次 | 平衡调用稳定性与资源占用，应对临时的接口波动 |
| 上下文窗口 | 8000–12000 token | 容纳多份审核文档的完整内容，支持跨文档的综合审核分析 |

## 容易做错的三处
- 调用Bedrock工具时返回software.amazon.awssdk.services.bedrockruntime.model开头的报错，原因是未正确配置生物制品审核场景下的工具权限范围，导致无法访问LIMS或洁净区监测的指定数据接口。
- 接口调用返回aiPointsNotEnough，原因是未按每批或实时更新的节奏触发工具调用，导致用于审核的有效数据点不足。
- 多模态插件无法正确解析无菌灌装记录的图像数据，原因是未配置匹配生物制品文档格式的图像预处理参数，无法识别沉降菌计数标签等关键字段。

## 怎么确认配好了
- 发起一次模拟供应商审核请求，检查工具是否自动调用对应数据源的插件拉取所需数据。
- 触发批放行审核流程，确认工具调用的触发时机匹配按批更新的业务节奏。
- 查看FastGPT v4.17.0版本的工具调用日志，确认函数调用的参数严格匹配生物制品审核的必填字段。
- 模拟异常数据输入，检查工具是否触发预设的失败处理与重试机制。
