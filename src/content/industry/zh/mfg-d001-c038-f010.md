# 生物制品与无菌生产的供应商与过程质量审核：知识库检索与召回

## 这个品类的数据长什么样
本品类典型主体为疫苗、抗体、血液制品与无菌注射剂企业，日常文档包含细胞库或种子批记录、培养纯化记录、无菌灌装记录、环境监测数据、培养基模拟灌装结果、无菌检验报告、批放行资料。数据来源涵盖细胞库与种子批系统、过程分析设备、洁净区监测系统、MES、LIMS及设备完整性测试工具。数据更新频率按批执行、实时同步监测结果或遵循既定监测计划。文档字段包含批次编号、操作时间、参数值、检验结果、操作人员标识，部分记录需关联设备序列号与环境温湿度数值，部分参数需匹配行业专用计量标准。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征对检索召回环节形成多重约束。按批更新且强关联批次编号的文档，要求检索需精准绑定批次上下文，避免跨批次数据混淆。多源分散的系统数据，要求检索需覆盖多数据集的关联内容，确保审核所需的全链条数据可被召回。大量专业工艺参数、检验结果与专用计量字段，要求检索策略需保留字段关联性，避免拆解后破坏参数逻辑。实时监测数据的即时更新需求，要求检索链路具备低延迟响应能力，适配过程审核的即时判断要求。无菌生产记录的高合规性要求，需过滤无关冗余内容，保证检索结果仅关联质量审核相关文档。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.85–0.92 | 匹配无菌生产工艺参数与检验结果的精准度要求，避免低关联结果干扰质量审核 |
| `limit` | 前8条 | 平衡检索召回的信息完整性与上下文长度，适配批记录的多字段关联内容，避免超出模型处理上限 |
| `searchMode` | `fullTextRecall` | 覆盖工艺参数、检验结果与批次信息的全维度检索需求，满足供应商与过程审核的全链条数据调用 |
| `usingReRank` | 开启 | 对初始召回的多源数据进行二次排序，强化专业术语与审核场景的匹配度，提升结果准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索关键词，覆盖工艺参数的同义词与行业专用表述，适配生物制品生产的专业术语体系 |
| `collectionIds` | 按业务数据集分组配置 | 区分批次数据、环境监测数据与检验报告等独立数据集，避免跨类数据混淆，保证检索结果的业务关联性 |

## 容易做错的三处
- 建索引阶段卡住，界面显示索引构建进度无更新或超时提示。原因：未按业务数据集分组配置`collectionIds`，一次性导入全量多源数据，导致索引构建资源占用过高无法完成。
- 搜索测试触发报错，返回字段解析失败的提示。原因：未开启`datasetSearchUsingExtensionQuery`，无法适配生物制品生产的专业术语扩展，导致检索关键词无法匹配文档字段。
- 检索结果包含非本品类的内容，未严格匹配无菌生产相关文档。原因：`collectionIds`配置包含了其他品类的数据集，导致召回了不相关的文档内容。

## 怎么确认配好了
- 查看索引构建日志，确认各业务数据集的索引进度正常完成，无超时或报错记录。
- 输入专业工艺参数或批次编号关键词进行检索，核对召回结果是否包含对应业务场景的文档内容。
- 开启`usingReRank`后，对比初始召回与重排后的结果，确认专业术语匹配度更高。
- 检查`collectionIds`配置，确认仅包含本品类的业务数据集ID，无跨品类数据集混入。
