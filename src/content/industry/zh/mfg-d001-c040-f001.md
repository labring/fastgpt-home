# 电池PACK与储能系统集成的供应商与过程质量审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类主体为动力电池包、储能柜及BMS系统制造商，日常文档包含配组规则、BOM清单、焊接与扭矩记录、BMS刷写记录、绝缘耐压报告、EOL测试数据、系统配置清单。数据来源于电芯分容系统、MES系统、焊接设备、扭矩工具、BMS软件版本库、EOL试验台，更新节奏为每台产品产出或每次软件版本变更时触发，字段涵盖电芯参数、装配参数、测试结果、软件版本等核心业务信息。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据来源分散，涵盖电芯分容、MES、测试设备等多类异构系统，HTTP接口需适配不同系统的鉴权规则与数据格式。产品与软件版本更新频繁，接口需支持动态加载最新的配组规则、测试参数等配置，同时处理单次数据量波动较大的请求。多类型文档的字段差异要求接口实现灵活的字段映射逻辑，且因出错可能引发热管理失效、系统停机等严重后果，接口需配置完善的参数校验与异常捕获机制。

## 配置怎么定
本配置基于FastGPT v4.17.0版本制定，具体参数如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {平台分配的API密钥}` | 符合HTTP接口标准鉴权规范，适配多系统对接的统一鉴权要求 |
| `variables` | 按产品类型预设电芯参数、测试阈值等变量，取值为`电芯分容数据、BMS版本号、EOL测试项` | 匹配本品类核心业务数据字段，简化接口调用时的参数传递 |
| `responseData` | 返回核心业务字段，取值为`前10条有效测试数据` | 聚焦供应商审核与过程质量管控的核心指标，减少无效数据传输 |
| 接口超时设置 | `300-600秒` | 适配本品类单次测试数据的传输与处理时长，避免因设备响应延迟导致接口失败 |
| 重试策略 | 失败后重试2-3次，间隔`10-30秒` | 应对MES、测试设备等外部系统的临时波动，保障数据同步可靠性 |

## 容易做错的三处
- 现象：部署的HTTP接口服务始终监听3000端口，无法通过配置文件调整。原因：容器启动时未正确覆盖默认端口参数，或配置文件的端口配置未被服务读取。
- 现象：调用外部系统接口时返回参数错误，部分核心业务字段为空。原因：未通过`variables`配置正确的业务参数映射，未匹配本品类文档的字段格式。
- 现象：批量同步EOL测试数据时频繁触发超时错误。原因：未设置合理的超时阈值，未适配本品类单次数据量波动较大的传输需求。

## 怎么确认配好了
- 调用配置好的测试接口，检查`Authorization`鉴权头是否正确携带，验证返回状态码符合预期。
- 传入预设的电芯参数与测试数据，检查`responseData`返回的字段是否覆盖本品类核心业务指标。
- 模拟外部系统临时断开，验证接口是否触发预设的重试机制，在系统恢复后完成数据同步。
- 调整配置文件中的超时与重试参数，验证接口行为是否符合预设的业务需求。
