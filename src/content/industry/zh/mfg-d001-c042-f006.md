# 石油炼制的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
石油炼制的业务数据来源包括DCS/APC系统、LIMS实验室管理系统、罐区计量系统、原油评价数据库、设备管理系统与能源管理系统。数据更新节奏覆盖实时、每班、每日三个层级。日常文档包含操作规程、生产方案、物料平衡表、馏出口质量报告、联锁台账、交接班记录与变更管理文件。数据字段包含原油性质参数、装置运行参数、产品质量指标与设备状态参数，对应单位包括摄氏度、毫克每千克、立方米等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多来源且更新节奏差异明显的数据，要求溯源时能精准匹配数据生成时间与对应来源系统，避免引用过期或未更新的信息。多套连续装置通过物流与能源网络耦合的业务逻辑，要求溯源时能关联上下游物料流转的完整链路。文档类型多样且字段专业，要求溯源时能区分不同文档的引用权重，优先匹配核心业务文档。数据字段的专业性较强，要求溯源结果能完整保留专业参数，避免截断关键信息。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1500 token | 匹配炼油专业文档如馏出口质量报告的单条内容长度，避免截断关键参数 |
| `responseData` | 包含来源系统、更新时间、文档类型 | 满足溯源时的多维度信息校验需求 |
| `detail` | 开启 | 支持返回完整的引用文档片段与关联元数据 |
| 最大上下文 | 8000–10000 字符 | 容纳多装置耦合的业务关联数据 |
| 单次搜索上限 | 前6条 | 覆盖主要的物料平衡与质量报告数据源 |
| 重排 | 按来源系统优先级排序 | 优先匹配DCS与LIMS的核心业务数据 |

## 容易做错的三处
- 现象：对话输出末尾自动附加引用文件列表，无法隐藏。原因：未调整`responseData`的输出配置，保留了默认的引用展示逻辑。
- 现象：引用片段被截断，馏程、硫含量等关键质量参数丢失。原因：`quoteMaxToken`取值小于专业文档的单条内容长度，导致内容被强制截断。
- 现象：溯源结果未匹配对应原油批次的评价数据。原因：未按数据源优先级排序搜索结果，优先匹配了非核心的文档来源。

## 怎么确认配好了
- 发起包含原油性质、装置负荷的查询，检查返回结果是否附带来源系统、更新时间与文档类型信息。
- 测试长文本查询，确认引用片段未被截断，完整包含专业参数内容。
- 查看`quoteMaxToken`的配置取值，验证是否匹配业务文档的平均长度。
- 发起多装置关联查询，确认溯源结果关联了上下游的物料与能源流转数据。
