# 精细化工间歇合成的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
这个品类的主体为涂料、树脂、助剂、农化中间体和专用化学品企业。日常文档包含批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据来源涵盖配方与工艺库、原料批次信息、反应釜DCS数据、称量系统记录、LIMS系统、仓储系统。数据更新频率为每批生产或每个关键步骤，且存在多品种、多批次切换的特征，配方与工艺数据需严格保密，清洗确认记录为核心审核依据之一。

## 这些特征在「向量模型与索引」这一环带来什么约束
多批次高频更新的数据要求索引支持增量触发，避免全量重索引占用过多资源。多品种多文档类型的特征要求分块规则需适配不同文档的字段结构，例如投料复核单的结构化字段与DCS的时序数据需采用不同分块逻辑。配方保密需求要求向量存储需配置权限隔离，防止敏感数据泄露。反应过程记录与清场记录的强关联特征，要求向量索引需保留上下文关联信息，避免检索时割裂批次流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配该品类单份投料复核单、反应过程记录的平均字符长度 |
| 重叠长度 | 100–150 字符 | 保留批次生产流程的上下文关联信息 |
| `maxToken` | 8000 token | 适配公开API的输入长度限制，满足审核场景的信息输入需求 |
| `defaultToken` | 按实测标定 | 适配不同公开API的默认token分配规则 |
| 相似度阈值 | 0.75–0.85 | 按实测标定，过滤低置信度的匹配结果 |
| 单次搜索上限 | 前 10 条 | 控制检索范围，避免冗余数据干扰审核判断 |
| 重排 | 开启 | 优化检索结果的排序精度，适配多维度的审核依据 |

## 容易做错的三处
- 现象为索引构建过程停留在最后一组批次数据，无法完成全量索引生成。原因是未针对按批次更新的数据源配置增量索引触发规则，导致全量重索引耗时超出预期。
- 现象为混合检索响应时长超过10秒，且单次检索结果条数异常。原因是未关闭非必要的召回源，或未配置单次搜索上限，导致检索范围覆盖过多无关数据。
- 现象为部分专有文档无法完成向量化，例如LIMS导出的加密PDF或带批次编号的结构化Excel表。原因是未配置该品类专属的文档解析规则，导致解析失败。

## 怎么确认配好了
- 查看FastGPT v4.17.0的索引管理页面，确认索引更新触发方式为按批次增量更新。
- 发起一次供应商审核相关的检索，查看响应时长是否符合预期，调整相似度阈值至符合业务置信度要求。
- 上传该品类的典型文档，如投料复核单、反应过程记录，确认向量化任务无报错且生成的向量库可正常检索。
- 测试混合检索与纯向量检索的响应差异，确认非必要的召回源已关闭。
