# 精细化工间歇合成的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类的核心数据来自涂料、树脂、助剂等企业的生产与质量体系，日常文档包含批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据来源涵盖配方与工艺库、原料批次台账、反应釜DCS系统、称量记录系统、LIMS实验室管理系统、仓储库存系统。数据更新以每批生产或每个关键工艺步骤为节点，单份文档包含批次标识、工艺参数数值、物料称量值、设备清洗记录、检验结果等字段，无固定通用模板，随生产产品的品种调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类多品种、按批次切换的生产特性，要求多轮对话需绑定特定批次的工艺与质量数据，避免跨批次数据混淆。按关键步骤更新的生产数据，需在对话中按工艺顺序调用，提示词需明确限定数据的批次范围与环节类型。间歇合成单次工艺周期长、环节多，对话上下文需保留多步骤的投料、反应、清场记录，防止上下文溢出导致关键信息丢失。因配方与工艺信息保密，提示词需屏蔽未授权的跨企业数据调用，且需严格匹配当前生产批次的原料与设备信息，避免出现不符合实际生产的关联建议。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 本品类单批生产的多步骤记录总长度约为6000–10000 token，预留足够空间保留多轮对话的历史信息 |
| 默认回复token上限 | 3000 token | 覆盖单批次投料复核、反应判断的完整说明需求，避免短响应截断关键内容 |
| `variables`绑定规则 | 仅绑定当前批次的原料、设备、工艺变量 | 防止跨批次数据混用，符合本品类按批次管理的业务要求 |
| `chatId`关联规则 | 绑定当前生产批次的唯一标识 | 确保对话上下文仅关联该批次的生产与质量数据 |
| `messages`历史保留上限 | 前20轮对话消息 | 避免上下文溢出，同时覆盖多步骤的操作记录与质量反馈 |
| 多轮对话触发条件 | 按工艺步骤顺序触发 | 匹配本品类间歇合成的分步操作逻辑 |

## 容易做错的三处
- 现象：对话中部分问题的回复token上限自动变为200，输出内容过短。原因：未在提示词中明确限定当前批次的上下文范围，系统触发了短上下文的保护机制。
- 现象：无法将单批生产的清场记录、检验报告成功导入知识库。原因：未按照本品类的批次标识字段对文档进行分类标注，导致知识库检索无法匹配对应批次的数据。
- 现象：高级编排节点无法实现一次对话发送两条消息。原因：未正确配置`messages`的数组结构，未为两条消息分别添加角色与内容字段。

## 怎么确认配好了
- 手动导入单批次的投料复核单与反应过程记录，在对话中询问该批次的投料参数，确认返回内容与导入数据一致。
- 发起多轮对话，依次询问不同工艺步骤的要求，确认系统能按顺序关联对应步骤的文档信息。
- 查看`chatId`的绑定标识，确认对话上下文仅显示当前生产批次的相关数据，无跨批次的无关内容。
- 测试不同复杂度的问题，确认回复token上限稳定在预设值，未出现自动缩减的情况。
