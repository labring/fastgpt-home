# 纸浆造纸的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
纸浆造纸场景通常的数据来源包括木浆废纸批次台账、DCS/QCS系统、纸机在线测量设备、实验室检测报告、能源与水处理系统日志。日常产生的文档包含配浆单、打浆操作记录、纸机运行日志、在线质量曲线、断纸与换品批次记录等。数据更新节奏覆盖实时（如纸机在线测量值）、每班（如班组配浆统计）、每卷（如单卷纸质量检测数据）。单份文档字段包含浆料配比参数、打浆度、纸幅克重、水分含量、断纸时长等，附带批次号、卷号等唯一标识。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
纸浆造纸场景通常的数据分散且更新节奏差异显著，多轮对话需按数据源的更新周期对齐上下文窗口，避免调用过期的实时测量数据。单卷、单批次的专属文档需在对话中绑定对应批次号与卷号，防止跨批次、跨班次的数据混淆。在线质量曲线、打浆记录等半结构化数据，需通过提示词明确指定提取字段与单位，避免输出无标识的模糊结果。多轮对话的上下文需限制在单批次生产周期内，防止无关数据干扰审核逻辑。

## 配置怎么定
本配置基于 FastGPT v4.17.0 版本，具体参数与取法如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前生产批次的唯一标识 | 确保多轮对话关联同一批次的配浆、打浆、质量检测数据，避免跨批次混淆 |
| `messages` | 限制上下文为最近10轮对话或8000字符以内 | 纸浆造纸场景的审核需关联多份近时数据，过长上下文会导致响应延迟，符合实时审核节奏 |
| `variables` | 传入当前卷号、批次号、纸机型号3个固定变量 | 绑定专属生产参数，让提示词能精准匹配对应设备与批次的文档数据 |
| 最大上下文 | 600–1200 秒的会话有效期 | 纸浆造纸单卷生产周期通常覆盖数小时，该区间可覆盖完整单卷审核流程，避免会话过期中断 |
| 问题优化 | 开启自动补全专业术语 | 纸浆造纸行业有打浆度、湿部负荷等专属术语，自动补全可提升提示词精准度 |
| 单次搜索上限 | 前 8 条匹配文档 | 单批次生产涉及的文档数量有限，过多匹配结果会增加上下文负载，影响响应速度 |

## 容易做错的三处
- 现象：调用对话API使用流式输出后，页面仅覆盖当前内容，无法通过链接跳转至新页面。原因：未在流式响应的回调逻辑中配置新页面跳转触发条件，仅绑定了当前容器的内容替换事件。
- 现象：多轮对话中，上一轮的输出未被正确带入下一轮的提示词上下文。原因：未正确绑定`messages`参数的上下文传递逻辑，或会话上下文未关联当前`chatId`，导致对话上下文断裂。
- 现象：提示词未正确提取在线质量曲线的字段，输出结果缺少克重、水分等关键参数。原因：提示词未明确指定需提取的纸浆造纸专属字段与单位，未限定关联当前批次的文档数据。

## 怎么确认配好了
- 发起包含当前批次号的测试对话，核对`chatId`是否绑定了对应批次的配浆单、打浆记录等文档。
- 触发流式输出测试，确认响应内容逐段返回，且可通过界面操作跳转至关联的质量报告页面。
- 提交包含专业术语的测试问题，核对系统是否自动补全术语并精准匹配对应文档。
- 测试多轮对话，确认上一轮的输出内容被正确带入下一轮的提示词上下文，未出现数据混淆。
