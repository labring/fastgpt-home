# 纺纱与织造的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类主体为棉纺、化纤纺、机织和针织企业，日常产生配棉或配料单、工艺上机单、设备运转记录、纱线检验记录、坯布检验记录、疵点记录等文档。数据来源涵盖原纤维检验报告、ERP系统、纺机与织机实时数据、条干仪、验布机采集数据及订单规格文件。数据更新频率随每批原料、每班生产、每匹布产出同步更新，单份文档包含纤维指标、工艺参数、设备运行参数、检验结果等字段，部分字段带有明确单位，如捻度、纱线强力、疵点尺寸等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的高频更新、多源异构数据特征，要求索引支持增量同步以适配每批原料、每班、每匹布的实时更新节奏。多类来源的文档格式差异较大，需统一文本嵌入的预处理逻辑，确保仪器采集的数值型参数、ERP的结构化字段、手工填写的疵点记录均能被正确解析。单份文档包含带单位的工艺与检验字段，分块时需保留字段关联上下文，避免拆分后丢失参数与结果的对应关系。疵点记录与工艺参数强相关，索引需支持跨文档关联检索，便于快速定位异常来源。

## 配置怎么定
本页面基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配单份工艺或检验文档的字段密度，避免拆分后丢失配棉单、工艺参数与检验结果的关联 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工艺上下文，防止捻度、织造组织参数等关键信息被拆分在不同块中 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 1024 token | 作为单块文本的默认嵌入上限，平衡嵌入精度与处理速度 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的无关记录，避免非相关的设备运转数据干扰质量审核判断 |
| 单次搜索上限 | 前 10 条 | 控制检索返回量，适配审核场景下快速定位核心异常的需求 |

## 容易做错的三处
- 现象：检索结果返回大量无关的设备运转记录，无法定位到配棉单的纤维指标内容。原因：分块长度设置过短，拆分后丢失了配棉单与纤维指标的上下文关联。
- 现象：调用嵌入接口返回超时错误，状态码504。原因：未配置合理的`maxToken`，单块文本过长导致嵌入模型处理超时。
- 现象：上传的Word格式工艺上机单解析后字段为空。原因：未开启针对办公文档的文本提取配置，导致结构化的工艺参数字段无法被正确识别。

## 怎么确认配好了
- 上传一份配棉单与对应的纱线检验记录，执行检索“纱线强力不合格的原因”，核对返回结果是否包含配棉单的纤维指标内容。
- 模拟单批原料的增量更新，查看索引同步状态是否正常，确认新增数据未遗漏关键字段。
- 调整相似度阈值，验证返回结果的数量与相关性是否符合质量审核场景的预期。
- 测试上传Word格式的工艺上机单，确认解析后的文本包含组织参数、捻度等核心工艺字段。
