# 纺纱与织造的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
该品类的核心数据来自原纤维检验报告、ERP系统、纺机与织机运行日志、条干仪、验布机及订单规格文件。日常留存的文档包括配棉配料单、工艺上机单、设备运转记录、纱线检验单、坯布检验单与疵点台账。数据更新随每批原料进厂、每班设备运行、每匹布产出完成，单条数据对应具体批次原料、单台设备班次或单匹织物的检验结果。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据分散于离线检验报告、在线设备日志与ERP系统，多格式数据源的关联溯源需适配不同存储形态。数据更新随每批原料、每班设备运行、每匹布产出完成，需确保引用的溯源信息与当前审核批次实时匹配。日常文档结构差异明显，配棉单侧重纤维指标、工艺单侧重工艺参数、检验单侧重疵点记录，需精准匹配审核场景的字段关联。单条数据体量小但覆盖全流程批次，需避免溯源结果冗余且覆盖原料到成品的全链路节点。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ------------ |
| 引用最大token数 | 800–1200 token | 适配纺纱织造品类单份检验单、工艺单的平均字符长度，避免截断关键溯源信息 |
| 返回关联数据开关 | 开启 | 需返回原始数据源的批次、设备、检验时间等字段，支撑供应商审核的溯源校验 |
| 详情展示开关 | 完整展示 | 需呈现疵点记录、工艺参数等细节，匹配过程质量审核的全链路追溯需求 |
| 单次召回上限 | 前6条 | 覆盖单匹布的检验、设备运转、配棉等多环节数据，避免结果冗余 |
| 知识库分块重叠长度 | 50–80 字符 | 保留工艺参数、检验指标等跨块关联信息，防止溯源时丢失关键上下文 |
| 搜索相似度阈值 | 0.75–0.85 | 过滤低匹配度的无关数据，精准匹配纺纱织造的原料、工艺、检验等场景 |

## 容易做错的三处
- 现象：对话中自动附加知识库引用的文件链接。原因：未关闭关联数据返回配置，或未调整引用展示的开关设置。
- 现象：搜索结果中混入非当前批次的原料检验数据。原因：未绑定批次维度的检索过滤条件，导致溯源结果覆盖全量历史数据。
- 现象：溯源结果截断了工艺上机单的关键捻度参数。原因：引用最大token数设置过小，未适配单份文档的字符长度。

## 怎么确认配好了
- 发起针对单匹坯布的质量审核查询，核对返回结果中是否包含对应批次的配棉单、工艺上机单与检验记录。
- 检查对话末尾的引用区域，确认仅展示当前审核所需的数据源，无冗余无关文件链接。
- 验证当查询工艺参数时，是否返回完整的捻度、组织参数等细节内容，无截断情况。
- 调整检索关键词后，确认返回结果的条数符合预设的单次召回上限。
