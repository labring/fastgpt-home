# 肉制品与屠宰加工的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据主要来自屠宰场、熟肉与冷冻调理食品企业的日常生产与合规文档，包括动物检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告等。数据来源涵盖动物检疫信息、供应商批次台账、生产追溯系统、实时温度采集设备、金属检测设备与实验室检验结果。更新频率按生产批次、班次执行，冷链温度记录为连续实时更新，字段包含批次编号、检疫编号、温度值（摄氏度）、检测时间、分区标识等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来三项核心约束。首先，连续实时的冷链温度记录更新频率高，需适配高频增量索引更新策略，避免全量索引重建带来的性能损耗。其次，批次与检疫证明的强关联要求索引需绑定批次编号元数据，防止跨批次的无关记录被匹配。第三，不同文档类型的长度差异较大，从简短的检疫编号到数页的生产记录，需调整分块策略以适配向量模型的输入长度限制，同时保留跨块的关键关联信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配检疫证明、生产记录等文档的平均长度，避免单块包含过多跨批次关联信息 |
| 重叠长度 | 100–150 字符 | 保留批次号、温度值等跨块关键元数据，防止关联信息被分块截断 |
| `maxToken` | 4096 token | 匹配Qwen3-Embedding-8B的输入token上限，适配单批次记录的总长度 |
| 相似度阈值 | 0.75–0.85 | 区分合格与不合格的微生物检验、温度记录的向量匹配精度 |
| 单次搜索上限 | 前10条 | 覆盖单批次审核所需的关联记录数量，避免冗余数据干扰审核逻辑 |
| 最大上下文 | 8000 字符 | 整合多块关联的检疫、生产、冷链数据，满足完整审核逻辑的上下文需求 |

## 容易做错的三处
- 配置`maxToken`时设置超过4096的数值，出现接口报错返回413状态码。原因是未匹配Qwen3-Embedding-8B的输入token限制，导致向量化请求被模型拒绝。
- 未配置元数据索引关联批次编号，向量搜索结果中出现跨批次的冷链温度记录。原因是未将批次号作为索引关联字段，向量匹配仅基于文本内容，无法过滤无关批次的数据。
- 未调整高频温控数据的索引刷新周期，导致知识库中存储的温度记录与实际生产数据偏差超过1小时。原因是使用了与静态文档一致的索引更新间隔，未适配连续实时更新的温控数据。

## 怎么确认配好了
- 上传单批次的检疫证明与对应生产记录，执行向量搜索，确认返回结果仅包含该批次的关联文档。
- 查看FastGPT v4.17.0的系统磁盘占用统计，确认知识库占用包含原文件、分割后文本块、嵌入向量三部分。
- 调用本地部署的VLLM嵌入接口，输入测试文本，确认返回的向量维度与Qwen3-Embedding-8B的标准维度一致。
- 触发批量向量化任务，观察任务日志中无`maxToken`超限报错，且任务完成率为100%。
