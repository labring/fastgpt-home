# 肉制品与屠宰加工的供应商与过程质量审核：工作流编排

## 这个品类的数据长什么样
本品类的核心数据来源包括动物检疫信息、供应商批次、生产追溯、温度采集、金属检测、实验室检验。日常留存的审核相关文档包括检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告。数据更新节奏为每批原料对应一次检疫与批次绑定，每班完成一次生产记录上传，冷链温度则为连续采集更新。数据字段包含批次号、检疫编号、温度值（单位℃）、检测结果、加工时间等，部分字段需与供应商资质绑定关联。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的业务特征对工作流编排带来多重约束：按批、按班的更新节奏要求流程需绑定唯一批次号触发，避免跨批次数据混淆；连续温控的实时性要求需配置实时采集节点，超时需触发告警分支；检疫证明与原料批次的强绑定要求流程中需校验关联字段，确保病害原料无法进入生产环节；生熟分区与杀菌温度的严格管控要求流程设置分支判断节点，对不同加工环节执行差异化审核；高风险出错后果要求流程配置失败重试与人工介入节点，确保异常可追溯。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按`nodeId`绑定批次号触发 | 匹配每批原料独立审核的业务节奏，确保流程与批次一一对应 |
| 全局变量`variables`赋值格式 | 数组格式：`{"批次号":"XXX", "检疫编号":"YYY"}` | 实现批次与检疫证明的绑定校验，满足生产溯源要求 |
| 节点超时设置 | 300-600秒 | 匹配冷链温度采集的连续监测时长，避免流程因等待实时数据卡住 |
| 失败处理分支 | 触发人工审核节点 | 应对微生物超标、交叉污染等高风险出错场景，确保异常可追溯 |
| 上下文拼接开关 | 关闭自动拼接 | 避免AI对话回复的变量结果出现内容叠加，修复常见的变量叠加问题 |
| 导出配置 | 按批次维度导出审核记录 | 匹配生产追溯的文档留存需求，便于后续审计 |

## 容易做错的三处
- 节点连线正常但状态卡在运行中，无下一步日志输出。原因：未配置`variables`中批次号的触发校验，流程无法匹配当前批次的检疫证明数据，触发条件未满足。
- 全局变量字符串数组赋值后字段为空。原因：未使用标准键值对数组格式赋值，导致变量解析失败。
- AI对话回复的变量结果出现历史内容叠加。原因：未关闭上下文自动拼接开关，前一次对话的结果被带入当前变量中。

## 怎么确认配好了
- 手动触发一个测试批次的流程，检查节点是否按预设顺序依次执行，无卡顿现象。
- 输入符合格式的全局变量数组，确认流程可以正常读取批次号、检疫编号等字段内容。
- 模拟一次AI对话回复，检查返回的变量结果仅包含当前会话内容，无历史数据叠加。
- 配置导出节点并触发，确认可以生成对应批次的审核记录文件。
