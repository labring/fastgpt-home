# 肉制品与屠宰加工的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
该品类数据覆盖屠宰场、熟肉与冷冻调理食品生产企业的全流程文档，包含动物检疫证明、屠宰分割记录、配料腌制台账、热加工参数记录、冷链温度日志、微生物检验报告等。数据来源涵盖动物检疫信息、供应商批次编码、生产追溯链路、实时温度采集、金属检测结果与实验室检验数据。更新节奏按生产批次、班次执行，冷链温度需连续采集更新，单批次数据关联检疫、原料、加工与检验全环节信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的溯源数据需绑定批次与检疫信息，单条数据关联多环节字段，要求引用时精准匹配批次编码。连续采集的冷链温度数据更新频率高，需确保溯源时调用最新的时段日志。生熟分区与加工环节的记录需严格隔离，引用时需区分原料与成品数据，避免交叉污染相关记录混淆。同时，数据字段包含生物风险相关的检疫状态，引用时需保留原始字段的合规性标识，确保溯源结果可追溯至源头检疫环节。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本，适配肉制品与屠宰加工品类的溯源需求。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次召回上限 | 前6条 | 该品类单批次关联数据量适中，召回过多会增加上下文冗余，过少则无法覆盖全环节溯源信息 |
| 最大上下文 | 8000–12000 token | 需容纳检疫证明、批次记录、温度日志等多环节数据，按实测标定调整 |
| `quoteMaxToken` | 1500 token | 匹配单条溯源文档的平均长度，避免截断关键批次与检疫信息 |
| 返回原始数据 | 开启 | 需保留原始文档的检疫编号、温度数值等字段，满足合规溯源要求 |
| 详情开关 | 开启 | 展示原始数据的具体字段，便于核对溯源信息的完整性 |

## 容易做错的三处
- 现象：系统长时间无响应，界面显示加载超时。原因：未限制单次召回的文档数量，导致加载过多批次与温度日志数据，超出系统上下文承载上限。
- 现象：回答仅生成通用表述，未引用知识库中的原始检疫或生产记录。原因：未开启返回原始数据配置，系统未调用知识库中的专属文档内容。
- 现象：工作流代码节点中无法选择知识库返回的批次字段。原因：未在知识库配置中开启详情开关，未暴露原始文档的字段信息，导致节点无法识别可用变量。

## 怎么确认配好了
- 上传单批次的检疫证明与温度日志至关联知识库，发起溯源查询，核对返回结果包含原始文档的全部字段。
- 查看查询返回的上下文长度，确认未超过配置的最大上下文值，无文档截断提示。
- 打开工作流节点的变量选择面板，确认可选择知识库返回的批次编码、检疫编号等字段。
- 查看系统运行日志，确认调用了知识库中的对应文档，无上下文溢出报错。
