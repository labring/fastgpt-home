# 计量器具与实验室管理的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据主要来自企业计量室、CNAS体系实验室的计量管理系统、LIMS平台、外部校准机构证书及标准器数据。日常文档包含量具台账、校准计划、校准证书、期间核查记录、试验原始记录、标准物质台账、偏离处置单等，字段包含溯源编号、测量值、测量不确定度、校准周期、环境参数等，单位涵盖长度、质量、温度等计量专用单位。数据更新按校准周期、每次试验或异常情况触发，无固定批量更新节奏。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据具有强溯源性、格式规整性与高合规要求，给多轮对话与提示词配置带来三点约束。第一，需保留完整会话上下文以追踪溯源链变更，避免截断关键的校准证书编号或测量不确定度数据。第二，提示词需明确指定字段提取规则，确保从量具台账、校准证书等多类文档中精准提取计量专用字段，避免泛化处理。第三，需适配动态更新的数据节奏，在对话中实时调用最新的校准计划或期间核查记录，确保审核结果基于当前有效数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 覆盖多轮校准证书、量具台账的完整对话上下文，避免截断关键溯源信息 |
| 单次召回结果上限 | 前 5 条 | 本品类数据条目规整且精度要求高，少量召回即可覆盖全部关联计量记录 |
| `variables` 绑定字段 | 溯源编号、测量不确定度 | 用`variables`参数绑定业务核心字段，确保对话中可直接调用校验 |
| `chatId` 持久化 | 开启 | 用`chatId`参数保留会话上下文，追踪多轮审核的溯源链变更 |
| `messages` 上下文整理 | 按会话顺序拼接，保留溯源编号、测量不确定度等核心字段 | 用`messages`参数规范对话上下文格式，避免冗余信息干扰审核 |
| 提示词强制注入 | 开启 | 确保模型执行预设的计量审核逻辑，避免被自定义内容覆盖 |
| 上下文刷新间隔 | 24 小时 | 适配日常校准计划的更新节奏，确保对话调用最新数据 |

## 容易做错的三处
- 对话回复未关联知识库文档：现象为调用API发起对话后，返回内容未引用知识库中的校准证书或量具台账。原因是未正确绑定`variables`参数指向知识库的计量数据索引，导致检索范围偏离业务场景。
- 页面加载崩溃：现象为使用FastGPT v4.8.20版本时，对话页或知识库页加载失败。原因是旧版本对多轮计量文档的上下文缓存处理存在内存溢出缺陷，建议升级至FastGPT v4.17.0。
- 预设提示词未生效：现象为选择Ollama部署的模型时，预设的审核提示词未被模型执行。原因是未在会话配置中开启提示词强制注入，或模型的系统提示词被自定义内容覆盖。

## 怎么确认配好了
- 发起包含预设在知识库中的溯源编号的测试提问，核对返回结果是否包含知识库中对应校准证书的内容。
- 开启多轮会话，连续提交3条不同的计量数据提问，核对会话是否持续保留上下文关联。
- 配置自定义审核提示词后，触发模型生成审核结果，核对输出是否包含预设的校验逻辑。
- 查看会话日志，确认`variables`参数绑定的业务字段已被正确提取并调用。
