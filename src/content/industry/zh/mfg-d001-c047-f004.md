# 计量器具与实验室管理的供应商与过程质量审核：工作流编排

## 这个品类的数据长什么样
数据来源包括企业计量管理系统、外部校准机构证书、标准器、LIMS、环境监测设备；更新按校准周期、每次试验或异常情况触发。日常文档包含量具台账、校准计划、校准证书、期间核查记录、试验原始记录、标准物质台账、偏离处置单。字段包含器具编号、校准有效期、测量不确定度、溯源链编号、环境温湿度参数，单位多为毫米、牛顿、帕斯卡等计量专用单位。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且依赖外部机构输出，要求工作流支持多源数据拉取与格式校验。更新频率不固定，需配置触发式节点，根据校准计划或异常事件启动流程。日常文档字段多为计量专用参数，需预设字段校验规则，避免无效数据进入流程。溯源链与不确定度审查需要串联多步骤节点，确保流程符合体系要求。出错后果直接关联产品质量判定，需配置异常节点触发告警与流程回滚机制。

## 配置怎么定
本配置规则适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量 | 按计量器具台账字段映射 | 支撑后续节点调用器具溯源、校准状态等核心信息 |
| 节点触发规则 | 按校准到期前7天触发 | 匹配校准计划的更新与提醒节奏 |
| 数据校验阈值 | 测量不确定度误差按实测标定 | 符合计量专业精度要求 |
| `variables` 作用域 | 全局生效 | 确保跨节点的器具状态与参数同步 |
| `nodeId` 绑定规则 | 绑定校准证书上传节点 | 固定流程链路，避免节点错位导致的数据混乱 |

## 容易做错的三处
- 打开工作流提示Cannot read properties of undefined (reading 'incl')，原因是未正确配置`variables`绑定的计量器具字段，导致节点调用时读取空对象。
- 设置全局变量后后续组件无法获取变量值，原因是未将`variables`作用域设置为全局生效，仅配置了节点私有变量。
- 工作流执行时校准证书校验失败，原因是未配置字段校验规则，未过滤不符合计量单位的参数输入。

## 怎么确认配好了
- 核对`variables`绑定的字段是否覆盖计量器具台账的核心参数，包括器具编号、校准有效期等。
- 测试触发节点是否按设定的校准周期节点启动流程。
- 检查数据校验规则是否匹配计量专用单位与精度要求。
- 查看流程链路的`nodeId`是否与实际页面中的节点ID一一对应。
