# 设备点检与预防维修的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自制造企业设备部、维修班组等主体的日常文档与系统数据，包含设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录等类型。数据来源涵盖EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史、备件库存及法定检验信息，更新节奏覆盖每班、日/周/月周期及故障发生时的实时更新，字段包含设备编号、点检位置、实测参数、故障现象、备件型号、检验有效期等。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据类型多样，包含结构化的点检参数、非结构化的故障分析文本及关联法定记录，且更新频率跨度大，因此索引需支持多模态数据的向量映射与增量同步。设备台账与检验记录关联合规性字段，需确保索引字段的语义一致性，避免拆分关键关联信息。维修工单的故障描述多为口语化工业表述，需选择适配工业场景的向量模型以保证语义匹配精度。同时因非计划停机风险较高，索引检索需保证低延迟的召回效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配设备点检表、维修工单的单段语义完整性，避免拆分故障描述或备件型号的关联信息 |
| 重叠长度 | 100–150 字符 | 防止分块边界切断点检项与实测值的对应关系，保证语义连贯性 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.72–0.80 | 过滤低相关性的设备传感数据，保留与当前故障排查强关联的历史记录 |
| 单次搜索上限 | 前10条 | 控制检索结果规模，适配车间维修班组的快速查询场景 |

## 容易做错的三处
- 现象：嵌入模型调用返回503错误，提示指定模型无可用渠道。原因：未为索引环节单独配置嵌入模型，复用了对话接口的密钥与渠道配置，导致嵌入请求无法匹配正确的模型资源。
- 现象：配置CHAT_API_KEY环境变量后，服务未加载新的密钥信息。原因：未重建容器以加载更新后的环境变量配置，导致旧的运行配置仍在生效。
- 现象：检索返回的点检记录与故障描述不匹配，结果相关性偏差较大。原因：分块长度设置不合理，拆分了点检项与实测值的关联语义，导致向量模型无法捕捉完整的业务关联。

## 怎么确认配好了
- 进入FastGPT的索引管理页面，查看当前嵌入模型的配置是否与索引专用模型一致。
- 上传一份设备点检表或维修工单样本，执行检索测试，核对返回结果的相关性符合预设阈值。
- 查看服务运行日志，确认嵌入模型调用无503或密钥错误的报错信息。
- 调整分块长度参数后，重新上传样本数据，验证检索结果的语义完整性未被破坏。
