# 设备点检与预防维修的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
本品类数据覆盖制造企业设备部、车间维修班组、公用工程部门等主体，日常文档包含设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录。数据来源包括EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史档案、备件库存数据、法定检验信息。更新节奏覆盖每班、日/周/月周期及故障发生时的即时更新，文档字段包含设备编号、点检项、参数阈值、维修记录编号、备件型号等，无额外自定义单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
设备点检相关数据来源分散，包含结构化系统数据与非结构化传感、点检记录，要求模型接入时支持多源数据格式适配。多更新频率带来的数据时效性差异，需配置支持动态调整上下文召回的时间范围。文档字段包含设备编号、点检参数阈值等专业字段，需确保模型能准确识别设备专属标识与运维参数。特种设备检验记录涉及法定合规内容，配置时需关联对应审核校验逻辑，避免非合规数据进入上下文。维修工单与备件清单的关联关系，要求模型接入时保留数据间的关联映射，确保检索结果的关联性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的参数逻辑，具体设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配设备点检多文档拼接的上下文长度需求，覆盖多份点检表、维修工单的整合内容 |
| `maxTokens` | 2000 token | 限制单轮回复长度，符合设备运维文档的常规查阅习惯 |
| `quoteMaxToken` | 1500 token | 确保召回的设备台账、点检记录等源数据片段完整展示，满足审核校验的溯源需求 |
| `temperature` | 0.2–0.4 | 降低随机输出，保证故障定位、备件核对等场景的结果一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或私有部署的模型调用地址，确保运维数据不出域 |
| `AIPROXY_API_TOKEN` | 按权限分配生成 | 保障模型接入的访问安全，限制非授权调用 |

## 容易做错的三处
- 配置`maxContext`时设置过大，导致接口返回413状态码。原因是未结合设备点检单批次上下文的实际长度，超出模型支持的最大上下文阈值。
- 未合理配置`quoteMaxToken`导致召回的设备台账片段被截断，无法核对备件型号与点检参数。原因是忽略了设备运维文档需完整溯源的业务需求。
- 错误固定`toolChoice`参数值，导致模型无法主动调用知识库检索维修历史记录。原因是未理解设备点检场景需依赖历史数据辅助故障定位的业务逻辑。

## 怎么确认配好了
- 发起包含设备编号与点检参数的测试请求，核对返回结果中是否包含对应文档的完整片段。
- 查看模型调用日志，确认请求地址与令牌与配置项一致。
- 测试故障定位场景，核对输出结果是否与维修历史记录的关联关系正确。
- 调整`temperature`参数，验证输出结果的一致性是否符合业务要求。
