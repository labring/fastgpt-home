# 通用机械设备装配的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
通常为泵、阀、压缩机、减速机、机床及非标设备制造商所使用，日常文档包含装配工艺卡、BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单。数据来源覆盖PLM/ERP系统、零件检验数据、装配工具采集数据、试验台数据、MES系统、客户技术协议。更新频率以单台设备或每订单为单位，文档结构多包含层级化BOM、带具体数值的装配参数，核心差别为多品种按订单装配，最终性能依赖部件配合与现场调试，区别于以单一尺寸合格为主的零件加工品类。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多品种按订单装配的属性要求溯源信息需绑定订单号与设备序列号，避免不同订单的文档混淆。多层级BOM与多源数据的组合，要求溯源系统需精准关联不同系统的文档，确保引用内容来自正确的装配环节。高频更新的单台设备数据，要求索引机制支持近实时同步，保证引用的是最新的装配与检验记录。带具体参数的文档内容，要求溯源时需保留字段与单位信息，便于核对实物与记录的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配装配工艺卡、BOM等文档的段落结构，避免拆分关键层级信息 |
| 重叠长度 | 150–200 字符 | 保留BOM父子件的关联上下文，防止跨块丢失层级关系 |
| 单次搜索上限 | 前 8 条 | 覆盖单台设备装配涉及的多类文档，避免遗漏关键检验记录 |
| `quoteMaxToken` | 3000 token | 容纳完整的扭矩、间隙等装配参数的引用内容，确保溯源信息无截断 |
| `responseData` | 开启 | 输出引用来源的文档类型、更新时间与关联订单号，满足审核溯源的元数据需求 |
| `detail` | 开启 | 展示引用内容的原始片段，便于直接核对实物与记录的一致性 |

## 容易做错的三处
- 现象：检索结果中未返回对应订单的扭矩记录。原因：未配置关联MES系统的数据源，仅索引了PLM中的静态BOM数据，无法获取实时装配采集信息。
- 现象：页面控制台报错Cannot redefine property: toString。原因：在配置`responseData`时错误修改了系统内置的原型方法，导致初始化冲突。
- 现象：引用的间隙调整记录未显示具体单位。原因：分块长度设置过小，截断了包含单位的参数字段，丢失了关键校验信息。

## 怎么确认配好了
- 发起针对单台设备装配工艺的查询，检查返回结果中是否包含对应文档的来源标识与关联订单号。
- 查看引用片段的原始内容，确认是否包含扭矩、间隙等品类特有的参数字段及对应单位。
- 测试多订单数据的检索，确认不同订单的文档不会被混淆引用。
- 检查FastGPT v4.17.0的系统日志，确认未出现原型方法重定义的报错信息。
