# 金属切削加工的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自机加工厂、精密零部件厂的业务系统与现场采集，包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表、量具校准记录等文档。数据来源覆盖产品图纸与三维模型、CAPP/CAM、机床采集数据、刀具管理系统、MES系统及量检具数据。更新随工单、单件生产、抽检或刀具更换触发，文档字段多包含明确单位的参数，如尺寸偏差、进给率、刀具寿命等。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据的多源分散、高频更新及多类型文档特征，对向量模型与索引环节带来多重约束。多源数据包含结构化参数文档与非结构化工艺文本，需适配混合格式的分块与向量化规则。高频更新触发场景要求索引支持增量同步，避免全量重建耗时过长。文档中包含大量带明确单位的工艺参数，向量模型需保留参数的语义关联，避免单位信息被丢失。现场采集的原始数据可能存在格式差异，需在索引前完成基础格式对齐。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配数控程序、工艺卡等文档的单段语义完整性，避免跨工序信息分散 |
| 重叠长度 | 100–200 字符 | 保留工序间的关联信息，防止分块切断基准、装夹方案等关键内容 |
| 相似度阈值 | 0.75–0.85 | 匹配刀具磨损、尺寸偏差等强关联的工艺参数，降低误匹配概率 |
| 单次搜索上限 | 前 8 条 | 覆盖单工单涉及的工序、刀具、检验记录等核心关联数据 |
| maxToken | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 用代表性工艺文档样本实测校准 | 这是直接文本切分使用的默认 token 数；请抽查样本文档的分块结果。它与嵌入模型输入上限和 LLM 对话上下文相互独立。参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx) |

## 容易做错的三处
- 现象：索引检索结果中未包含新提交的刀具更换巡检记录。原因：未针对刀具清单、巡检表等高频更新的文档配置增量索引，仅执行全量索引导致新数据未被及时纳入。
- 现象：检索返回的数控程序片段出现行号、进给率等参数断裂。原因：分块长度设置过小，切断了数控程序的连续语义单元，导致向量检索无法关联完整工序逻辑。
- 现象：自定义检索流程无法关联工序卡与首件检验记录。原因：未启用实体关联的索引配置，仅使用扁平化实体索引无法匹配跨文档的工序-检验关联逻辑。

## 怎么确认配好了
- 上传单份数控程序与对应工序卡，检查检索返回的关联文档是否包含刀具清单、工序卡等预设关联类型，确认配置的单次搜索上限生效。
- 新增一份刀具更换记录，验证索引是否完成增量同步，无需执行全量索引操作。
- 查看向量化过程的日志，确认文档中的尺寸偏差、进给率等带单位的参数被完整纳入向量表征。
- 测试不同分块长度的检索效果，调整至符合本品类文档语义完整性的取值。
