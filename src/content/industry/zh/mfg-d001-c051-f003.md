# 金属切削加工的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源包括产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES系统及量检具数据。数据更新随每工单、单件工件加工、抽检环节或刀具更换触发。日常文档涵盖工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表及量具校准记录，包含工序号、切削参数、刀具编号、尺寸偏差值等字段，部分文档带专用单位如微米、分钟。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类多源高频更新的数据特征，要求多轮对话需绑定`chatId`跟踪单工单的完整审核流程，避免上下文混淆。不同类型文档的专用字段与单位，要求提示词需明确指定提取目标的文档类型与字段规则，例如仅从工序卡提取切削参数，不关联其他文档的无关字段。高频更新的刀具与质检数据，要求对话上下文需限制有效轮次，防止过时数据干扰审核判断。同时，数控程序的代码格式与量检具的校准记录格式差异，要求提示词需适配不同数据的解析逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前工单的唯一标识 | 确保多轮对话关联同一审核流程，避免上下文串扰 |
| `messages` | 保留最近8轮对话内容 | 适配高频更新的质检与刀具数据，防止过时信息干扰 |
| `variables` | 预设工单编号、刀具型号等审核变量 | 快速匹配对应工件的工艺与质检文档 |
| 单次搜索上限 | 前6条召回结果 | 匹配本品类多类型文档的检索量，避免冗余数据 |
| 最大上下文长度 | 4000–6000 字符 | 适配工序卡、数控程序等单文档的内容长度，按实测标定 |
| 文本提取触发规则 | 按文档类型匹配对应字段 | 适配本品类不同文档的专用字段格式 |

## 容易做错的三处
- 现象：文本提取环节返回空字段，系统触发指定回复后未进入等待用户输入的状态。原因：未配置对话等待触发规则，导致流程直接终止，无法接收用户补充的信息。
- 现象：配置英文prompt后模型仅输出中文内容。原因：未在提示词中明确指定输出语言的强制规则，且未关联英文知识库的语言匹配配置。
- 现象：上传数控程序或工序卡文件后解析报错。原因：未针对本品类的专用文档格式（如G代码、带单位的尺寸参数）配置自定义解析规则，导致通用提取逻辑无法适配。

## 怎么确认配好了
- 发起模拟工单对话，输入不同类型的文档关键词，核对对话上下文是否随`chatId`绑定保留。
- 配置英文提示词并输入英文查询，核对模型输出是否符合指定语言要求。
- 上传本品类的典型文档（如工序卡、数控程序），核对文本提取是否能正确返回预设字段。
- 触发文本提取失败的场景，核对系统是否触发指定回复并等待用户补充信息。
