# 钢材轧制与精整的供应商与过程质量审核：工作流编排

## 这个品类的数据长什么样
该品类数据主要来自板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与MES系统。更新频率为每卷或每支钢卷实时更新。日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书，字段包含批次号、加热温度、轧制压下量、板形偏差值、表面缺陷等级等，单位涵盖摄氏度、毫米、平方米、吨等。

## 这些特征在「工作流编排」这一环带来什么约束
实时更新的批次级数据要求工作流触发节奏匹配每卷或每支钢卷的生产节奏，不宜使用固定周期触发。多源异构的数据来源需要在编排中设计数据对齐节点，确保同一批次的加热、轧制、检测数据关联正确。大体积的板形、厚度记录数据存在上下文溢出风险，需拆分节点处理分段数据。质保书等文档需绑定对应批次的检测结果，工作流需支持跨节点数据关联。同时，该品类出错后果严重，编排中需加入前置校验节点，提前拦截异常参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` 自动更新规则 | 绑定批次节点完成事件 | 该品类数据按每卷或每支实时更新，需在对应批次数据采集完成后同步更新全局变量 |
| 分块长度 | 800–1200 字符 | 单卷板形、厚度记录数据量较大，分块适配上下文长度限制 |
| 单次搜索上限 | 前10条 | 匹配批次级关联数据的合理数量，避免冗余信息干扰分析 |
| 最大上下文 | 16000 token | 适配多源数据合并后的总长度，按实测标定调整 |
| `nodeId` 绑定规则 | 绑定对应轧机批次的节点ID | 确保工作流节点与实际生产设备批次一一对应，避免数据混淆 |
| 超时阈值 | 300 秒 | 覆盖单批次数据采集、校验的合理耗时，避免流程中断 |

## 容易做错的三处
- 现象：全局`variables`值未随批次数据更新，界面显示字段为空。原因：未将变量更新规则绑定到对应批次节点的完成事件，仅设置了固定周期触发。
- 现象：工作流执行时提示上下文长度超限，无法完成分析。原因：未设置合理的分块长度与最大上下文参数，未拆分大体积的板形记录数据。
- 现象：表面检测图片无法触发视觉分析流程，转码后的数据未传入后续节点。原因：未将图片转码节点配置在表面检测节点之后，触发时机与生产流程不匹配。

## 怎么确认配好了
- 查看工作流的`variables`配置项，确认自动更新规则绑定了对应批次节点的完成事件。
- 测试单批次数据输入，检查上下文长度是否适配，调整分块长度与最大上下文参数至符合需求。
- 验证表面检测节点后的图片转码流程，确认图片可正常转码并触发后续视觉分析节点。
- 确认FastGPT v4.17.0版本的所有节点均已正确关联，无缺失或错误绑定的节点ID。
