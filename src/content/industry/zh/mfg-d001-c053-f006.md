# 钢铁冶炼与连铸的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据覆盖钢铁联合企业炼铁、炼钢、连铸、质量与调度部门的全流程产出，属于高温连续流程工业，炉次与浇次耦合强度高，不同于有色熔炼的矿种和电解路线。日常文档包含炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单，字段包含炉次号、铁水成分、终点温度、浇铸速度、板坯缺陷类型等，单位涉及摄氏度、吨、毫米等。数据来源为铁水与废钢数据、L2过程控制系统、化验室检测结果、MES系统、能源介质系统与设备状态监测数据，更新频率按每炉次、实时或每班触发。

## 这些特征在「引用来源与溯源」这一环带来什么约束
高温连续流程且炉次与浇次耦合强度高，不能随意停机的特性要求溯源数据必须完整覆盖异常炉次的全流程记录，避免因中断导致的数据缺失。实时更新的L2过程数据与每班归档的板坯判定单需区分实时检索与批量回溯场景，适配不同的更新节奏。多源数据的字段对齐难度较高，不同系统的成分数据可能存在单位差异，需在溯源环节完成统一映射。单炉次关联的文档数据量集中，单次检索的上下文上限需适配单炉次文档的总长度，避免超出处理阈值。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 单炉次关联的文档总token数通常处于该区间，适配FastGPT v4.17.0的上下文处理上限，避免内容溢出 |
| `responseData` | 返回原始文档元数据+片段 | 需保留炉次号、检测时间、数据来源系统等元数据，满足质量审核的溯源关联需求 |
| `detail` | 开启 | 需展示具体的冶炼记录片段与成分报告内容，支撑供应商与过程质量的细节审核 |
| 单次搜索上限 | 前6条 | 控制检索结果的冗余量，避免多源数据的结果超出业务处理的有效范围 |
| 上下文拼接顺序 | 按炉次时间倒序 | 最新的过程数据与板坯判定结果对质量审核的参考价值更高，符合业务审核逻辑 |

## 容易做错的三处
- 现象为检索返回的引用条数超出预设的前6条上限，原因是未正确配置`quoteMaxToken`的取值，导致系统未对检索结果进行有效截断。
- 现象为引用结果的排序不符合业务预期，未按炉次时间或检测优先级排列，原因是未设置按元数据字段重排，仅依赖默认的检索匹配逻辑。
- 现象为对话中始终显示知识库引用内容，无法通过对话设置关闭，原因是未在工作流的输出节点关闭引用展示配置，保留了强制渲染的全局设置。

## 怎么确认配好了
- 检索单炉次的配料单与转炉冶炼记录，检查返回的引用片段是否包含正确的炉次号与对应检测数据。
- 查看引用结果的排列顺序，确认按炉次时间倒序展示，符合业务审核的优先级逻辑。
- 触发一次质量审核相关的查询，测试是否可通过输出配置切换引用展示的开启与关闭状态。
- 核对引用的元数据是否包含数据来源系统的标识，确认可追溯至L2过程控制、化验室等对应数据源。
