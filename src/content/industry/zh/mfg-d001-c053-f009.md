# 钢铁冶炼与连铸的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源包括铁水与废钢数据、L2过程控制系统、化验室检测数据、MES系统、能源介质系统与设备状态监测系统。日常文档包含炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单。数据更新频率按炉次、实时或每班执行，字段涵盖工艺参数、成分含量、设备状态等，涉及温度、重量、百分比等单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时性与高频更新的特性要求模型调用延迟控制在合理范围，避免影响生产节奏。多源异构的业务数据需要配置精准的字段映射规则，确保模型能正确关联不同系统的工艺与质量数据。单炉次关联多份文档的场景，要求限制上下文总长度以避免模型报错。高温连续流程的特性，要求模型调用不能出现长时间无响应的情况，否则可能引发连铸中断等生产事故。

## 配置怎么定
本文基于FastGPT v4.17.0版本，以下配置项适配钢铁冶炼与连铸的业务场景：

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配单炉次多文档的总上下文体量，避免超出模型的上下文限额 |
| `temperature` | 0.3–0.6 | 平衡工艺推理的严谨性与关联逻辑的灵活性，适配质量审核的专业要求 |
| `maxTokens` | 2000–3000 token | 控制单轮回复的输出长度，适配生产场景的快速响应需求 |
| 工作流/API 工具选择配置 | auto | 自动选择工具处理结构化数据查询，适配多源工艺数据的提取与关联需求 |
| `AIPROXY_API_ENDPOINT` | 企业内部私有部署端点 | 满足生产数据不出厂的合规要求 |
| `AIPROXY_API_TOKEN` | 按企业权限生成的专属令牌 | 保障接口调用的安全性与权限可控性 |

## 容易做错的三处
- 模型测试时返回「上下文长度超限」报错，原因是未根据钢铁冶炼的多文档体量调整`maxContext`参数，使用了通用场景的默认值。
- 审核结果出现乱码，原因是未适配冶炼记录中的特殊工艺符号（如温度单位℃、成分百分比符号），未配置正确的字符编码规则。
- 文件上传后无法分析，原因是未将连铸工艺记录、板坯判定单等专属文档的格式（如结构化CSV、带工艺表格的PDF）提前配置到系统支持的解析规则中。

## 怎么确认配好了
- 发起单炉次业务数据的模型测试，核对返回结果是否包含配料单、转炉记录的关键字段，确认字段映射配置正确。
- 连续发起多次实时数据的调用，检查响应延迟是否符合生产场景的要求，调整相关参数适配延迟。
- 上传连铸工艺记录的示例文件，确认系统能正确提取工艺参数与缺陷信息，验证文档解析配置生效。
- 查看接口调用日志，确认`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置未出现认证或连接错误。
