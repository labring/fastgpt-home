# 钣金下料折弯的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自机柜机箱、通风设备等非标设备制造商的业务链路，日常文档包含展开图、数控下料程序、折弯工艺卡、套料图、首件记录、工序流转卡。数据来源覆盖CAD/CAM工具、订单BOM、板材库存系统、激光切割机、折弯机设备及MES系统。数据更新节奏随订单、每日生产或换型操作触发，核心字段包含折弯补偿量、板材厚度、下料尺寸、折弯角度、套料利用率等，部分文档为结构化参数文本，部分为设备导出的原始程序文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
多品种小批量的生产模式导致数据更新频率高，要求索引支持增量更新以避免全量重复计算。文档类型多样，包含结构化工艺参数、数控程序文本及CAD转写内容，需适配不同格式的分块规则，避免核心字段被割裂。核心字段如折弯补偿量、下料尺寸直接影响生产质量，要求索引优先嵌入此类高价值字段，同时需控制分块长度以保证嵌入精度。频繁的换型与订单变更也要求索引的召回速度适配实时审核的需求，避免延迟过长影响生产节拍。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配折弯工艺卡、套料图等文档的核心信息长度，避免单块内关键参数被拆分 |
| 重叠长度 | 100–150 字符 | 覆盖折弯系数、板材厚度等跨块出现的核心字段，保证信息完整性 |
| 相似度阈值 | 0.75–0.85 | 区分相似工艺参数与错误补偿值，降低供应商审核中的误召回概率 |
| 单次搜索上限 | 前 8 条 | 匹配多品种小批量场景下核心匹配结果的分布区间 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 512 | 适配本地轻量向量模型的输入限制，避免嵌入任务超时 |

## 容易做错的三处
- 现象：知识库新建数据后长时间显示索引中，原因：未适配该品类的高更新频率，未开启增量索引配置，导致全量索引重复执行。
- 现象：自定义索引配置后无有效召回结果，原因：未将折弯补偿量、下料尺寸等核心生产字段纳入嵌入范围，仅对通用文本进行处理。
- 现象：接入本地m3e模型后向量计算超时，原因：未调整`defaultToken`适配本地模型的输入长度限制，导致嵌入任务超出模型处理上限。

## 怎么确认配好了
- 查看索引任务日志，核对每个文档的分块数量与预期的800–1200字符块数匹配。
- 输入一段包含折弯系数、板材厚度的查询，确认召回结果中包含对应核心字段。
- 上传一份新的首件记录，确认索引任务在预设的时间范围内完成。
- 查看向量存储的使用情况，确认未超出预设的容量阈值。
