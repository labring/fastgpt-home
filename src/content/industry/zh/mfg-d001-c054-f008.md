# 钣金下料折弯的供应商与过程质量审核：文档解析与分块

## 这个品类的数据长什么样
该品类服务于机柜机箱、通风设备、电气柜、非标设备制造商，日常产生的文档包含展开图、数控下料程序、折弯工艺卡、套料图、首件记录、工序流转卡。数据主要来自CAD/CAM工具、订单BOM、板材库存系统、激光切割机与折弯机设备、MES系统。更新频率随订单、每日或每次产线换型调整，文档多包含尺寸参数、工艺参数、设备代码等字段，部分文档内嵌CAD绘图对象或结构化表格。

## 这些特征在「文档解析与分块」这一环带来什么约束
多品种小批量的业务模式导致文档格式不统一，需适配内嵌CAD对象、结构化表格等多种文档结构。图纸驱动的业务逻辑要求解析后需准确提取折弯系数、展开尺寸、公差值等关键字段，避免遗漏影响质量审核。高频更新的文档需要解析流程具备较快的响应速度，超时设置需匹配业务节奏，同时分块逻辑需兼顾检索精度与内容完整性，防止因分块不当导致关键工艺参数无法被精准召回，进而引发后续装配误差或板材浪费。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 钣金下料折弯的文档包含紧凑的工艺参数与尺寸信息，该区间可保证单块内容包含完整的工序参数或单张表格片段，兼顾检索精度与上下文完整性 |
| `chunkSplitter` | 按表格与段落拆分 | 套料图、折弯工艺卡多包含结构化表格，按表格与段落拆分可避免破坏表格结构，确保审核时可完整获取套料布局、折弯顺序等关键信息 |
| `customPdfParse` | 开启 | 该品类文档常内嵌CAD绘图对象或复杂矢量图形，开启自定义解析可优化对这类内容的提取效果，解决常规解析无法识别内嵌绘图的问题 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大尺寸展开图或套料图解析需较长时间，600秒可覆盖多数文档的解析周期，避免因超时导致文档解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 部分产线导出的CAD程序文件尺寸较大，该上限可满足常规大文档的上传需求 |

## 容易做错的三处
- 现象：部分docx文档上传后显示解析失败，日志返回解析异常报错。原因：未开启`customPdfParse`配置，钣金下料的展开图常内嵌CAD绘图对象，常规解析逻辑无法识别这类内嵌内容，导致解析失败。
- 现象：知识库中部分套料图或工艺卡的表格无法被正确分块，内容被截断或跨块合并。原因：未将`chunkSplitter`设置为按表格与段落拆分，默认分块逻辑会破坏表格结构，导致关键的套料尺寸、折弯顺序等信息分散在多个分块中。
- 现象：Docker部署后启动解析任务时报显存溢出，且无法识别GPU信息。原因：未正确挂载宿主机的CUDA驱动目录，同时`PARSE_FILE_TIMEOUT_SECONDS`设置过长，导致解析大尺寸CAD导出的PDF时占用过多显存，触发溢出报错。

## 怎么确认配好了
- 上传一张包含内嵌CAD绘图的docx格式展开图，检查解析后的文本是否包含折弯系数、展开尺寸等关键字段，确认解析状态显示成功。
- 上传一张套料图PDF，查看知识库分块列表，确认表格内容未被拆分，单块内容包含完整的表格行与参数。
- 查看系统运行日志，确认上传1000 MB以内的大尺寸文档时，未出现超时报错，且`PARSE_FILE_TIMEOUT_SECONDS`的配置值匹配解析耗时。
- 验证`customPdfParse`开启后，内嵌复杂矢量图形的文档可正常生成解析后的文本内容，无缺失字段。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
