# 钣金下料折弯的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
该品类数据通常来自CAD/CAM软件、订单BOM系统、板材库存台账、激光切割机与折弯机设备日志、车间MES系统。日常生成的文档包含零件展开图、数控下料程序、折弯工艺卡、套料规划图、首件检验记录、工序流转卡。数据更新节奏随订单交付、每日设备运行、每次生产换型同步调整，核心围绕图纸展开的折弯系数补偿、套料余料管理、工序顺序核对等环节生成，整体呈现多品种小批量、图纸驱动的特征。

## 这些特征在「模型接入与配置」这一环带来什么约束
多品种小批量的生产模式要求模型接入配置支持灵活适配不同规格的钣金图纸，避免固化的模板限制场景覆盖。多源异构的数据来源，要求配置中适配多格式文档的解析与向量生成规则，确保CAD展开图、工艺卡等不同类型数据的统一处理逻辑。高频更新的数据节奏，需要配置支持按需触发的向量同步，避免冗余存储或延迟响应。折弯补偿与套料的精度要求，决定了模型推理参数需兼顾专业场景的细节准确性与响应效率，防止因参数设置不当导致审核结果偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配钣金图纸解析、多份工艺卡拼接的长文本上下文需求，避免截断关键的折弯系数与工序信息 |
| `maxTokens` | 4000 token | 限制单轮推理输出长度，确保套料规划、折弯顺序建议的输出完整且不冗余 |
| `quoteMaxToken` | 2000 字符 | 限定召回文档的总长度，优先保留展开图尺寸、首件记录偏差等核心审核相关数据 |
| `temperature` | 0.3–0.5 | 降低随机输出概率，保障折弯补偿计算、工序核对的结果一致性，符合生产审核的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 按模型服务商提供的专属地址填写 | 适配多源模型接入需求，支持对接不同厂商的专业工业大模型 |
| `AIPROXY_API_TOKEN` | 按服务商生成的密钥填写 | 保障模型调用的身份合法性，避免未授权访问导致的审核数据泄露 |

## 容易做错的三处
- 现象为不同FastGPT版本（如4.8.9与FastGPT v4.17.0）下模型调用失败，原因为版本更新后`AIPROXY_API_ENDPOINT`的默认配置项发生变更，未同步更新对应参数。
- 现象为向量模型启用后无法正常配置渠道，原因为未按照`AIPROXY_API_TOKEN`的生成规则绑定对应模型服务商的密钥，导致身份验证失败。
- 现象为模型输出的折弯补偿结果偏差过大，原因为`temperature`参数设置过高，导致推理过程中出现非标准化的计算逻辑，不符合钣金加工的工艺规范。

## 怎么确认配好了
- 调用测试接口，输入一张钣金展开图与对应工艺卡，检查模型是否能正常返回折弯系数计算结果与工序核对建议。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置参数与服务商提供的信息一致，无字段为空或格式错误。
- 对比同一输入的多次模型输出，确认`temperature`参数设置下的结果一致性符合生产审核的严谨要求。
- 测试高频数据更新场景下的向量召回速度，确认`maxContext`与`maxTokens`的配置未导致超时或关键信息截断。
