# 锻造与模锻的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据覆盖锻造全流程，来源包括原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图。日常生成的文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告。数据更新以每件锻件、每批物料或每炉次为单位，包含炉批号、锻造比、纤维方向、缺陷类型等字段，部分数据带有MPa、小时等计量单元。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且更新频率随生产批次波动，要求索引支持按炉批号、锻件批次快速增量更新，避免全量索引重建耗时过长。专业字段如锻造比、纤维方向、缺陷类型等带有工业专属语义，需选用适配机械制造领域的向量模型以保证语义对齐。不同文档类型的文本长度差异显著，从下料卡的短文本到超声检测报告的长文本，需适配`defaultToken`与`maxToken`的配置要求，覆盖不同长度的工业文档。结构化采集数据与非结构化文档混合存储，需明确向量索引的字段映射规则，避免跨来源数据的向量混淆。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配超声检测报告、锻造过程卡等长文本的语义完整性，避免过短导致专业术语拆分断裂 |
| 重叠长度 | 100–150 字符 | 弥补分块边界的语义断层，覆盖锻造比、纤维方向等跨分块的关键专业字段 |
| 相似度阈值 | 按实测标定 | 需匹配锻件缺陷检测、工艺匹配的业务精度需求，避免误召回或漏召回 |
| 单次搜索上限 | 前 10 条 | 平衡召回效率与结果覆盖度，适配批量锻件审核的快速检索需求 |
| `defaultToken` | 8192 | 适配长文档的向量生成上限，覆盖完整工艺规程的文本长度 |
| 最大上下文 | 600 秒 | 适配工业数据批量检索的响应时长要求，避免超时中断 |

## 容易做错的三处
- 现象：点击启用Doubao-embedding-large索引模型，填写自定义请求地址和APIKey后测试直接报错。原因：未匹配该模型的请求头格式或请求路径，未按工业场景的向量生成要求配置专业字段的映射规则。
- 现象：知识库中表格数据（如加热炉记录的压力值表格）未生成有效向量。原因：未开启表格数据的多向量支持配置，未指定表格列的向量生成映射规则。
- 现象：检索结果条数与预期不符，召回了非当前批次的锻件数据。原因：未按炉批号或锻件批次配置索引的过滤规则，导致跨批次数据被误召回。

## 怎么确认配好了
- 执行向量生成测试，上传单份超声检测报告，检查生成的向量维度与所选模型的标准维度一致。
- 触发增量索引更新，上传一份新的加热炉记录，检查索引更新日志中仅显示新增批次的处理记录，无全量重建提示。
- 检索指定炉批号的锻件数据，检查返回结果仅包含该炉批号对应的文档，无跨批次数据混入。
- 测试长文本分块效果，导入完整锻造工艺规程，检查分块后的文本未出现专业术语被强行拆分的情况。
