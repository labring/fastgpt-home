# 锻造与模锻的供应商与过程质量审核：多轮对话与提示词

## 这个品类的数据长什么样
锻造与模锻的生产与审核数据来源于原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图，更新频率为每件、每批或每炉次。日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告，各文档字段包含炉号、加热温度、保温时长、锻件批号、缺陷当量、锻造比等，单位涵盖℃、小时、mm等，单份文档内容长度多集中在数百至数千字符区间。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据按炉次、批次高频更新，对话上下文需限制轮次以避免旧数据干扰批次匹配；多字段的业务文档要求提示词需明确指定需提取的核心审核字段，避免遗漏炉号、锻件批号等关键信息；多源数据来源要求多轮对话需引导用户补充缺失的参数，确保审核的完整性；出错后果严重的特性要求多轮校验环节需强制核对关键匹配项，防止批次混淆或缺陷漏检。

## 配置怎么定
本配置基于FastGPT v4.17.0版本逻辑制定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文轮次限制 | 前3轮对话 | 锻造生产数据按炉次/批次更新，旧对话冗余且易引入批次混淆 |
| 文档分块长度 | 800–1200 字符 | 锻造工艺规程、检测报告单段内容多在该区间内 |
| 会话参数绑定 | 绑定`chatId`、`messages`、`variables` | 追踪会话批次、对话历史与用户输入的审核参数 |
| 单次召回结果数 | 前5条 | 锻件相关文档条目集中，过多结果易干扰审核判断 |
| 提示词变量配置 | 填入锻件批号、炉号、缺陷类型 | 匹配锻造审核需核对的核心业务字段 |
| 检索结果排序 | 按检测时间倒序 | 优先使用最新的加热炉记录与超声检测报告 |

## 容易做错的三处
- 调用对话接口时未携带`messages`参数，导致无法关联已检索的锻造文档，现象为返回结果未参考工艺规程或检测报告。原因是未正确配置会话上下文绑定。
- 未绑定`chatId`参数，导致对话历史未被持久化存储，现象为mongodb中无对应会话的记录条目。原因是忽略了会话追踪的必要配置。
- 提示词未限定核心审核字段，多轮对话中未引导核对材料炉批与锻件批次，现象为审核结果出现批次匹配错误。原因是未结合锻造品类的业务字段设计提示词。

## 怎么确认配好了
- 发起测试对话，输入锻件批号，检查返回结果中是否关联了对应批次的加热炉记录与超声检测报告。
- 查看会话存储介质，确认`chatId`对应的对话历史已被正确写入。
- 触发多轮对话，依次输入不同的审核参数，检查`variables`是否正确传递了用户输入的字段值。
- 调试工作流中的知识库检索环节，确认召回结果数符合配置的单次召回条数。
