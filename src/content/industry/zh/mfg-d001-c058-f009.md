# 预制混凝土构件的供应商与过程质量审核：模型接入与配置

## 这个品类的数据长什么样
预制混凝土构件的业务数据来自BIM深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检验报告及二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣日志、养护周期记录、脱模与出厂检验报告。数据按单件构件、每批原材料、每一养护窑次更新，包含构件编号、钢筋规格、预埋位置、强度检测值、出厂日期等字段，部分为CAD导出的结构化数据，部分为纸质扫描件或非结构化文档。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且格式多样，既有结构化的台账数据，也有工程图纸类非结构化文件，要求模型接入支持多格式文档解析。数据更新频率高，单件、每批原材料及每一养护窑次均产生新数据，需控制模型上下文长度以避免冗余信息干扰。专业字段如预埋位置、混凝土强度检测值需模型具备工程领域语义理解能力，同时因出错后果严重，需平衡生成准确性与响应速度，配置时需兼顾上下文窗口与推理精度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 匹配预制混凝土构件工程文档的平均长度，避免截断关键的深化图参数与检验记录 |
| `temperature` | 0.2–0.4 | 降低随机生成概率，确保钢筋规格、预埋位置等专业内容输出准确 |
| `quoteMaxToken` | 2000–3000 token | 保留足够的原始文档片段用于质量审核的溯源核对 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配代理平台的接入地址，确保模型调用链路正常 |
| `AIPROXY_API_TOKEN` | 与代理平台绑定的密钥 | 完成身份验证，避免未授权调用 |
| 工作流/API 工具选择配置 | auto | 自动选择是否调用检索工具，适配多文档混合的审核场景 |

## 容易做错的三处
- 现象：模型在代理平台测试正常，但在FastGPT中调用报错。原因：未在FastGPT的代理配置中正确填写`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，或代理平台未开放对应模型的调用权限。
- 现象：知识库调用时提示无可检索内容。原因：未正确配置模型调用参数，或上传文档时未完成向量生成，导致无法匹配审核需求的检索片段。
- 现象：生成的审核结果出现钢筋规格、预埋位置错误。原因：`temperature`取值过高，导致专业术语的生成偏离原始文档数据。

## 怎么确认配好了
- 执行模型调用测试，输入预制混凝土构件的单份检验记录片段，验证模型能正确返回结构化的审核结论。
- 上传一份钢筋下料单文档，检查向量生成进度与检索结果是否正常，确认可提取到符合审核需求的原始片段。
- 查看代理调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置无拼写错误，无401或404状态码返回。
- 调整`temperature`参数后，对比两次生成的预埋位置描述，确认参数调整后输出的一致性符合预期。
