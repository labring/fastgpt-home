# 预拌混凝土生产的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
数据来源于工程订单、砂石水泥外加剂检验报告、含水率测定记录、搅拌站控制系统日志、工程项目试验室试块记录。日常文档包含配合比通知单、开盘鉴定表、生产运输单、原材料检验单据、试块强度报告。数据更新频率为每车生产记录、每批原料检验、每日汇总统计。文档字段包含原料批次号、含水率数值、坍落度数值、强度等级、浇筑部位等，单位涵盖千克、立方米、小时、兆帕等。

## 这些特征在「向量模型与索引」这一环带来什么约束
每车高频更新的生产数据要求索引支持增量更新流程，避免全量重索引带来的额外耗时。多类型结构化文档覆盖配合比、检验报告、生产单等，要求向量模型适配混合字段的语义提取，避免仅针对纯文本内容的召回偏差。每日汇总的批量数据规模要求索引的批量嵌入能力适配单次处理上限。原料批次与试块记录的强关联属性要求索引支持跨文档关联召回，不进行孤立匹配单条内容。坍落度、强度等数值型字段需转换为语义化表述，避免纯数值直接嵌入导致的语义匹配失效。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配配合比通知单、试块报告等单文档的平均内容长度，避免块内语义断裂 |
| 重叠长度 | 100–150 字符 | 覆盖跨块的关联信息，如配合比与对应坍落度的关联描述 |
| `defaultToken` | 4096 token | 适配主流嵌入模型的输入上限，匹配单块内容的token规模 |
| 相似度阈值 | 0.75–0.85 | 区分合格与异常的原材料检验、试块强度记录，避免误召回或漏召回 |
| `maxToken` | 8192 token | 适配批量嵌入时的单次总token限制，满足每日汇总数据的处理需求 |
| 单次搜索上限 | 前 8 条 | 覆盖多批次原料、多车生产的关联召回需求，避免召回冗余 |

## 容易做错的三处
- 现象：FastGPT v4.17.0版本接入qwen3-embedding-8b后，文件状态持续显示“索引中”。原因：该嵌入模型的输入格式与平台默认的分块token规则不匹配，导致嵌入流程无法正常完成。
- 现象：手动插入的原材料检验文档，数小时后自动生成的默认索引消失。原因：增量索引的同步触发机制未绑定对应数据的更新事件，导致索引缓存被自动清理。
- 现象：批量执行全量知识库重嵌入时，部分试块记录的嵌入结果缺失。原因：未调整`maxToken`配置以适配批量数据的总token规模，导致部分长文档嵌入失败。

## 怎么确认配好了
- 上传一份典型的配合比通知单，查看分块后的内容是否完整保留了原料配比、坍落度要求等核心信息。
- 触发一次批量嵌入任务，检查任务日志中是否存在嵌入失败的报错，确认`defaultToken`与`maxToken`配置适配当前使用的嵌入模型。
- 搜索“砂石含水率修正”相关的业务问题，查看召回结果是否包含关联的生产单与检验报告，确认跨块关联召回功能生效。
- 等待12小时后查看索引状态，确认自动生成的索引未被意外清理，验证同步机制运行正常。
