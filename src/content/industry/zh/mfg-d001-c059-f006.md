# 预拌混凝土生产的供应商与过程质量审核：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来源包括工程订单、砂石水泥外加剂检验记录、骨料含水率测定数据、搅拌站控制系统日志、工程项目试验室存档文件。数据更新节奏为每车生产记录、每批原料检验、每日汇总统计。日常文档包含配合比通知单、开盘鉴定表、生产运输单、原材料检验报告、试块强度记录。字段包含原料批次号、搅拌参数、运输时长、试块强度值，对应单位为千克、立方米、小时、兆帕。

## 这些特征在「引用来源与溯源」这一环带来什么约束
每车级的高频更新要求溯源系统需支持实时拉取最新生产与检验数据，避免引用过期的原料参数。多来源的分散数据需统一关联到对应工程订单与批次，确保溯源链路完整。文档类型多样且字段差异大，需精准匹配不同文档的字段规则，比如配合比通知单的参数需对应到搅拌站的实际配料数据。试块强度记录的滞后性要求溯源时可关联历史批次的后续验证数据，支撑质量异常的回溯分析。原料检验与搅拌参数的强绑定需求，要求引用来源时需同时匹配原料批次与生产时间，避免跨批次的错误关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 最大上下文 | 8000–12000 字符 | 适配FastGPT v4.17.0的上下文处理规则，匹配单份工程订单关联的多份文档总长度 |
| `quoteMaxToken` | 前 3–5 条匹配结果 | 限制单轮溯源的引用条数，符合预拌混凝土生产中单批次原料或单车生产的数据规模 |
| 知识库最大引用 | 10000 token | 覆盖单批次原料检验与生产记录的总token量，避免关键参数被截断 |
| `responseData` | 包含原料批次号、试块强度字段 | 强制返回审核所需的核心业务字段，简化质量审核的信息提取流程 |
| `detail` | 开启完整溯源链路展示 | 展示数据来源的文档类型与更新时间，满足供应商与过程质量审核的溯源要求 |
| 最大响应tokens | 2000–3000 字符 | 适配审核报告的输出长度，可完整展示多组溯源数据的关联说明 |

## 容易做错的三处
- 现象：返回的溯源数据中残留原始换行标记`\n`，未实现预期的段落换行效果。原因：未配置文本格式化规则，直接将原始文档中的换行符原样返回至审核结果中。
- 现象：单轮审核请求返回的溯源数据条数不符合预期，过多或过少。原因：未合理设置`quoteMaxToken`或知识库最大引用的取值，未匹配预拌混凝土生产中单批次数据的规模。
- 现象：溯源查询返回空结果或超时。原因：最大上下文设置超出平台处理上限，或未正确关联工程订单与原料批次，无法召回有效关联数据。

## 怎么确认配好了
- 发起针对单批次原料检验记录的查询，核对返回结果中是否包含正确的原料批次号与检验时间。
- 查看返回的溯源数据格式，确认换行符已正确渲染为换行效果，无原始`\n`标记残留。
- 调整`quoteMaxToken`的取值，验证返回的匹配结果条数符合业务数据规模。
- 触发包含多份关联文档的查询，确认核心业务参数未被截断。
