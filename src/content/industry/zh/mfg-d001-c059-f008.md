# 预拌混凝土生产的供应商与过程质量审核：文档解析与分块

## 这个品类的数据长什么样
该品类的核心数据来自工程订单、砂石水泥外加剂检验、含水率测定、搅拌站控制系统与工程项目试验室。日常文档包含配合比通知单、开盘鉴定、生产运输单、原材料检验记录、试块台账与强度报告。数据更新节奏为每车生产单、每批原料检验、每日汇总报告。文档字段包含配料用量、坍落度指标、试块强度值、检验批次号与浇筑地点等，单位多为千克每立方米、兆帕、毫米等，无统一固定格式，部分为扫描件与电子表格混合。

## 这些特征在「文档解析与分块」这一环带来什么约束
高频更新的单批次文档要求分块需匹配业务颗粒度，避免跨批次内容混淆。多格式混合文档（电子表格、扫描PDF）要求解析工具需适配不同文件类型，保留原始字段与单位信息。按批次更新的试块强度记录与配合比数据，要求分块时保留上下文关联，确保检索时可获取完整的单批次修正信息。批量上传的月度汇总报告要求解析超时设置需适配大体积文档，同时上传文件大小限制需满足批量文档的存储需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配单批次生产单、试块记录的业务颗粒度，避免跨批次内容混杂，保证检索上下文完整 |
| `chunkSplitter` | 按段落+表格拆分 | 适配配合比通知单、原材料检验报告等混合格式文档，保留表格字段与单位信息 |
| `customPdfParse` | 开启OCR模式 | 处理扫描版开盘鉴定、试块记录，避免扫描文本无法被正确提取 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 秒 | 适配批量上传多车生产单的解析耗时，避免单次解析超时失败 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 适配月度汇总的检验报告包，满足批量文档上传需求 |
| `chunkSettingMode` | 手动配置 | 针对单批次文档与汇总报告分别调整分块参数，适配高频更新的业务数据 |

## 容易做错的三处
- 上传扫描版原材料检验报告后显示字段为空，原因是未开启`customPdfParse`的OCR模式，导致扫描文本无法被正确识别提取。
- 上传多车生产运输单后解析超时，原因是`PARSE_FILE_TIMEOUT_SECONDS`设置值过低，未适配批量文档的解析耗时，重启服务器无法修复底层配置问题。
- 导入导出知识库后数据缺失不全，原因是未按业务批次配置分块规则，导致分块时合并了跨批次的内容，后续检索时丢失单批次的配料修正信息。

## 怎么确认配好了
- 上传单份扫描版原材料检验报告，检查解析后是否包含检验批次号、骨料指标等原始字段，确认`customPdfParse`配置生效。
- 上传5份连续的生产运输单，查看解析耗时是否在`PARSE_FILE_TIMEOUT_SECONDS`设置范围内，无超时报错提示。
- 导出已配置的知识库分块数据，检查单块内容是否包含完整的单批次配合比或试块记录，无跨批次混杂情况。
- 上传最大允许尺寸的月度报告包，确认上传进度正常，无文件超限提示。
