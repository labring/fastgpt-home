# 预拌混凝土生产的供应商与过程质量审核：部署与升级

## 这个品类的数据长什么样
数据来源包含工程订单、砂石水泥外加剂检验记录、骨料含水率测定数据、搅拌站控制系统实时数据、试验室检测报告。日常处理的文档包括配合比通知单、开盘鉴定、生产运输单、原材料检验单、试块记录、强度报告。数据更新频率为每车生成生产记录、每批原料完成检验、每日汇总统计，单条记录包含原料配比、运输时长、坍落度、试块强度等字段。

## 这些特征在「部署与升级」这一环带来什么约束
高频的车级、批级数据更新要求部署时配置足够的数据库连接池，避免写入阻塞。多类型文档的解析与存储需求，要求适配专用文档格式的解析规则与大容量存储配置。实时控制系统数据与离线试验室数据的混合接入，要求支持多源数据同步的配置项。出错后果涉及工程停工与质量责任，要求核心配置的权限管控严格，避免误操作导致数据异常。每日汇总的统计数据需要稳定的存储与查询能力，保障质量审核的及时性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30 个` | 适配每车、每批原料的高频数据写入，避免数据库连接阻塞 |
| `REDIS_URL` | `带访问密码的本地集群地址` | 支撑高频的会话缓存与实时数据同步，适配车级更新频率 |
| `STORAGE_S3_ENDPOINT` | `1000 MB 以上的存储节点地址` | 存储试块记录、强度报告等多类型文档，满足大容量存储需求 |
| `MONGODB_URI` | `分片数量为2–3 的集群连接地址` | 按每日、每批的结构化数据分类存储，降低单库查询压力 |
| `FILE_TOKEN_KEY` | `按实测标定的32位随机字符串` | 保障上传的配合比通知单等文档的访问安全，防止未授权访问 |
| `ROOT_KEY` | `仅部署管理员知晓的复杂密钥` | 限制核心配置的修改权限，避免误操作影响生产流程 |

## 容易做错的三处
- 现象：升级后登录系统提示账号密码不匹配，无法进入管理后台。原因：升级过程中未正确迁移`ROOT_KEY`配置，导致身份验证密钥与原有系统不匹配。
- 现象：上传配合比通知单后，解析结果缺失骨料含水率、坍落度等核心字段。原因：部署时未配置专用文档解析规则，无法识别预拌混凝土生产的专用文档格式。
- 现象：使用ocearbase版本的compose.yml部署时，fastgpt容器持续重启，无有效日志输出。原因：`REDIS_URL`配置错误，导致缓存服务连接失败，容器无法完成初始化。

## 怎么确认配好了
- 登录系统后台的配置页面，核对`DB_MAX_LINK`的配置值与预设的20–30个连接数匹配。
- 上传单份原材料检验单，确认解析结果能提取出砂石、水泥的检验参数，无必填字段缺失。
- 执行docker logs命令查看fastgpt容器日志，无数据库连接超时或身份验证失败的报错信息。
- 使用`ROOT_KEY`生成临时访问令牌，确认能正常访问存储的生产运输单文档。
