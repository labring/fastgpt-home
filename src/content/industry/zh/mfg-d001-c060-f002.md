# 饮料与瓶装水的供应商与过程质量审核：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自碳酸、果汁、茶饮、功能饮料及包装饮用水工厂的多类业务文档，包括配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验与成品检验报告。数据采集自水源与原料检测系统、配方管理系统、在线糖度酸度监测设备、灌装生产线、视觉检测装置及LIMS系统，更新节奏为每批生产、每班巡检及连续实时采集，文档字段包含原料指标参数、生产工序记录、检验结果与产品批号等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类多源异构的数据特征要求索引支持结构化与非结构化数据混合录入，连续实时采集的生产数据带来高频更新需求，需适配增量索引逻辑避免全量重建耗时过长。不同文档的长度差异显著，短至单条在线监测数据、长至完整配方单，需支持灵活分块规则适配不同内容长度。专业生产字段如糖度、酸度、无菌参数等需向量模型适配食品饮料行业的专业术语，确保语义召回匹配度。同时，审核场景需精准召回异常数据，索引的召回精度需满足过程质量复核的严谨要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配多数生产记录与检验报告的内容长度，避免单块包含过多无关信息 |
| 重叠长度 | 100–200 字符 | 保留相邻块的上下文关联，防止长文档的跨块语义断裂 |
| 相似度阈值 | 按实测标定 | 需结合异常数据的召回优先级调整，满足质量审核的精准匹配要求 |
| 单次搜索上限 | 前 10 条 | 平衡召回效率与审核复核的信息完整性，避免过多冗余结果 |
| maxToken | 4096 | 适配主流向量模型的输入长度限制，确保分块内容可完整嵌入 |
| 重排 | 开启 | 提升高相关结果的排序优先级，适配质量审核的关键信息优先展示需求 |

## 容易做错的三处
- 现象：升级FastGPT版本后，原CSV格式的生产记录文件无法正常分块，界面提示分块失败。原因：新版本对CSV文件的字段解析规则调整，未同步适配饮料品类特有的多单位混合字段（如糖度与菌落总数同表）的解析逻辑。
- 现象：知识库索引任务长时间卡在运行状态，未完成的生产数据记录显示为空。原因：连续采集的实时数据未做批量整理，单批次数据量超出系统默认处理上限，导致索引进程阻塞。
- 现象：调用知识库引用时返回的结果与预期的向量模型不匹配。原因：未在系统配置中更新向量模型的绑定参数，仍沿用旧模型的索引向量格式。

## 怎么确认配好了
- 上传单份典型文档（如完整配方单），检查分块结果是否覆盖全部核心内容，无明显语义断裂。
- 提交一条异常数据查询（如灌装液位超限记录），核对召回结果的排序与匹配度是否符合审核需求。
- 查看索引任务日志，确认增量更新仅处理新增的生产批次数据，无全量重建的异常触发。
- 切换向量模型后，验证相同查询的召回结果是否与新模型的语义匹配逻辑一致。
