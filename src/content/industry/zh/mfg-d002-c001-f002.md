# PCB制造的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
PCB制造场景的数据覆盖印制电路板工厂的工程、生产、品质与实验室四类主体的日常文档，包括工程制作指示、Gerber解析记录、钻孔和层压参数、药水分析、AOI报告、电测报告、切片报告。数据来源包含客户Gerber/钻带/BOM文件、CAM设计文件、设备运行参数、槽液化验结果、AOI与电测检测数据、实验室切片分析记录。数据更新频率覆盖每生产批、每班以及连续采集的实时数据，单生产批会产生多格式、多维度的工艺与异常关联文档。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据格式与来源要求索引模块支持二进制、表格、纯文本等多种文档的向量提取与同步；高频更新的生产批级数据要求索引支持增量同步，避免全量重建带来的性能损耗；工艺参数与异常报告的强关联特性要求向量召回需精准匹配字段关联，以确保检索结果的针对性；不同文档的长度差异，从单条钻孔参数到完整切片报告，要求分块策略适配不同文本单元，避免关键关联信息被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 覆盖完整的工艺参数段或异常报告段落，避免关键信息被分块截断 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的重叠内容，确保跨分块的关联信息可被完整匹配 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 按实测标定 | 匹配本地向量存储的单条数据最大长度限制 |
| 相似度阈值 | 0.75–0.85 | 过滤低关联度的非目标文档，确保检索结果与工艺、异常场景强相关 |
| 单次搜索上限 | 前 10 条 | 控制检索结果的总长度，避免超出上下文窗口限制 |

## 容易做错的三处
- 现象：检索异常报告时返回大量无关的槽液化验数据，原因：相似度阈值设置过低，未过滤低关联度的非目标文档，导致错误匹配非工艺关联内容，可能引发工艺调整偏差，进而导致整批板报废。
- 现象：导入Gerber二进制文件后，向量索引生成日志显示格式不支持报错，原因：未开启二进制文件的文本提取配置，无法将Gerber文件转换为可向量化的文本内容。
- 现象：触发增量更新后，新生产批的工艺文件无法被检索到，原因：未配置增量同步触发规则，仅执行了一次性全量索引构建，未覆盖实时更新的生产数据。

## 怎么确认配好了
- 导入一份标准的钻孔参数文档，检查向量索引生成日志中无格式报错。
- 输入AOI报告中的异常关键词，核对检索结果返回关联的层压工艺文档。
- 触发一次增量同步任务，确认新增的生产批数据被正确纳入索引范围。
- 调用测试接口进行检索，核对返回结果的内容符合预设的关联匹配要求。
