# PCB制造的工艺文件与异常报告起草：文档解析与分块

## 这个品类的数据长什么样
该品类的数据来自印制电路板工厂的工程、生产、品质与实验室部门，涵盖工程制作指示、Gerber解析记录、钻孔与层压参数、药水分析报告、AOI报告、电测报告、切片报告等。数据来源包括客户Gerber文件、钻带、BOM清单、CAM文件、设备运行参数、槽液化验结果及各类检测数据，更新频率为每生产批、每班或连续采集，文档多包含精密数值、工艺步骤与检测结果字段。

## 这些特征在「文档解析与分块」这一环带来什么约束
Gerber文件、钻带等工业格式的结构化程度不一，部分需专用解析逻辑，需适配不同文档结构的分块规则；连续采集的高频数据会产生大量单条短文档，需调整分块粒度避免信息割裂；工艺参数与检测结果的数值需保留原始单位与精度，分块时不能丢失关联字段；异常报告包含故障定位与整改建议，需按工艺环节拆分块以保留上下文关联。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的标准设置：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配PCB工艺文档中包含参数、步骤的段落长度，避免拆分关键工艺逻辑 |
| `chunkSplitter` | 按段落+语义边界 | 适配Gerber解析记录、检测报告的结构化内容，保留工艺步骤与检测结果的关联 |
| `customPdfParse` | 启用 | 针对Gerber、CAM导出的PDF文档，启用自定义解析可保留原始矢量图形与数值字段 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配单批次生产的完整工艺包文件大小，避免大文件上传失败 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 处理包含多页检测报告、复杂Gerber文件的解析需求，避免超时中断 |
| `chunkSettingMode` | 手动配置 | 针对PCB文档的特殊字段，手动调整分块规则以保留工艺参数与关联说明 |

## 容易做错的三处
- 现象：上传Gerber格式PDF文件后解析结果中无钻孔参数字段。原因：未启用`customPdfParse`配置，默认PDF解析无法识别工业矢量文档中的结构化参数。
- 现象：调用工具发起HTTP请求后，工具未触发执行但参数日志显示正常。原因：未配置工具的触发条件与知识库绑定关系，或超时设置过短导致请求未完成。
- 现象：导入飞书多维表格后，检索结果无法返回完整表格内容。原因：未开启自定义分块的表格识别模式，默认解析仅提取文本内容丢失表格结构。

## 怎么确认配好了
- 上传单份典型工艺文件，查看解析后的分块结果，确认关键参数如钻孔孔径、层压温度是否完整保留在同一块内容中。
- 发起工具调用测试，查看工具执行日志，确认参数传递与执行触发流程正常。
- 导入飞书表格与多维文档，检索后查看返回内容，确认表格结构与原始数据一致。
- 上传超过预设大小的工艺包文件，确认上传与解析流程未出现超时或中断提示。
