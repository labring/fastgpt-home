# 乳制品加工的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自奶源检测、MES系统、均质与热处理设备、在线温度流量采集、CIP清洗系统及LIMS实验室管理系统。日常文档包含原奶验收记录、标准化配料单、巴氏或UHT热处理记录、CIP清洗记录、灌装操作记录、留样与微生物检测报告。数据更新节奏为每奶罐、每批或实时生成，单份文档包含批次编号、检测数值、设备参数、操作时间等字段，部分数值带有温度、压力、浓度等单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时或高频更新的批次数据要求索引支持增量同步，避免全量重建带来的延迟。多源异构数据格式需要统一向量转换逻辑，确保不同设备采集的温流量、检测数据能被正确编码。单份文档字段多且带有单位，需在分块时保留批次标识与关键参数，避免检索时丢失上下文。批量生成的异常报告与工艺文件需要索引支持按批次、时间范围快速过滤，缩小检索范围。易腐原料的工艺数据时效性强，需限制索引更新的延迟时长，确保检索结果匹配当前生产状态。

## 配置怎么定
本配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配单份工艺文档的典型段落长度，保留完整操作步骤或检测结果上下文 |
| 重叠长度 | 100–200 字符 | 避免分块后丢失批次编号、设备参数等跨块关键信息 |
| `maxToken` | 4000–6000 token | 适配单批次多文档合并后的向量长度，确保检索结果能完整带入大语言模型上下文 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 过滤低匹配度的非生产相关文档，聚焦同批次或同工艺环节的内容 |
| `defaultToken` | 2000 token | 作为默认检索上下文长度，平衡检索精度与系统负载 |
| 单次搜索上限 | 前 10 条 | 控制初始召回的文档数量，避免过多冗余数据占用系统资源 |

## 容易做错的三处
- 现象：检索结果返回非当前生产批次的文档，或缺失检测数值的单位信息。原因：分块时未保留批次编号与单位字段，或索引未按批次标签进行过滤配置。
- 现象：后台日志显示召回了匹配文档，但大语言模型返回未找到相关内容。原因：检索召回的文档未达到`maxToken`要求的上下文长度，导致大语言模型无法读取完整匹配内容。
- 现象：系统返回超时报错，检索请求耗时超出预期。原因：未配置合理的单次搜索上限与`defaultToken`长度，导致系统加载过多冗余数据。

## 怎么确认配好了
- 上传单份原奶验收记录，检索对应批次编号，核对召回结果是否包含该批次的全部相关文档。
- 调整相似度阈值与单次搜索上限，观察检索结果的匹配度与数量，根据实际业务需求标定合适取值。
- 提交包含多源设备参数的检索请求，核对大语言模型返回内容是否包含检索到的文档中的具体数值与操作步骤。
- 查看系统增量同步日志，确认索引更新节奏与生产批次的更新频率一致，无全量重建的延迟报错。
