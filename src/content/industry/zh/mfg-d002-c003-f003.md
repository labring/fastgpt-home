# 乳制品加工的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自奶源检测、MES系统、均质与热处理设备、在线温度流量系统、CIP系统、LIMS。日常文档包含原奶验收记录、标准化配料单、巴氏或UHT灭菌记录、CIP清洗记录、灌装记录、留样与微检报告。数据更新节奏为每奶罐、每批、实时。文档按生产批次关联，字段包含批次编号、检测数值、设备运行参数，单位涵盖mg/kg、万/mL、℃、秒、L等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
因为数据按批次实时更新且关联多系统，多轮对话需固定关联对应批次的上下文，避免跨批次数据混淆。因文档字段与单位存在品类特异性，提示词需明确限定调用当前批次的专属文档字段，防止引入无关数据。因出错后果涉及整罐拒收或大范围召回，对话需快速验证数据一致性，避免生成错误的工艺文件或异常报告。因液态原料易腐且流程连续，需限制对话响应时长，确保异常处理及时。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按生产批次生成唯一ID | 区分不同奶罐、批次的对话上下文，避免数据串扰 |
| `messages` | 保留最近10轮对话 | 覆盖乳制品加工批次的多步骤操作记录，确保上下文完整 |
| `variables` | 绑定批次编号、检测数值、设备编号 | 关联对应批次的多系统文档，精准调用专属字段 |
| 单次对话返回上限 | 前3条批次关联记录 | 避免信息过载，聚焦当前异常相关的文档 |
| 上下文字符限制 | 8000–12000 字符 | 覆盖单批次的完整工艺与检测文档内容 |
| 响应时长限制 | 不超过600秒 | 确保异常处理及时，适配液态原料易腐的特性 |
| 提示词模板 | 按实测标定 | 匹配企业自身的工艺与异常报告格式 |

## 容易做错的三处
- 对话接口传文件时返回“参数缺失”报错，原因是未在`variables`中绑定文件对应的生产批次编号。
- 提示词调用MCP后生成的异常报告中设备图片显示不全，原因是未在多轮对话中限定仅调用当前批次的专属设备截图。
- 升级至FastGPT v4.17.0后，对话返回结果末尾出现规则类符号，原因是未关闭对话设置中的规则追溯展示开关。

## 怎么确认配好了
- 发起针对单批次原奶异常的多轮对话，核对`chatId`是否保持一致且关联了该批次的所有历史文档。
- 上传一份原奶验收记录，检查`variables`是否自动提取了批次编号与检测数值等字段。
- 触发异常报告生成，检查返回结果未包含额外的规则类符号。
- 发起多个批次的并发对话，检查各对话上下文未出现数据串扰。
