# 乳制品加工的工艺文件与异常报告起草：工具调用与插件

## 这个品类的数据长什么样
该品类的日常文档包括原奶验收记录、标准化配料单、巴氏或UHT热处理记录、CIP清洗记录、灌装记录、留样与微生物检测报告。数据来源涵盖奶源检测设备、生产MES系统、均质与热处理在线传感器、实时流量温度采集装置、CIP系统与LIMS实验室管理系统。数据更新频率为每奶罐、每生产批次实时同步，液态生物原料易腐且生产链路连续，无逐批隔离缓冲空间。

## 这些特征在「工具调用与插件」这一环带来什么约束
实时高频的生产数据更新要求工具调用的响应延迟需匹配生产节奏，避免延迟导致的工艺偏差。多源异构的数据格式要求插件需支持对接不同协议的数据源，统一字段格式以生成标准化工艺文件。每奶罐、每批次的独立数据标识要求`toolChoice`需绑定唯一批次编码，确保工具调用仅拉取对应批次的数据，避免跨批次数据混淆。液态原料无逐批隔离缓冲的特性，要求异常报告生成工具需快速触发，避免问题扩大影响范围。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写：
| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ------------ |
| 工作流/API 工具选择配置 | `auto` | 适配多源数据的自动工具调用逻辑，匹配乳制品加工多环节的工艺与异常处理需求 |
| 工作流/API 函数调用配置 | 绑定唯一批次编码 | 确保工具调用仅拉取对应奶罐或生产批次的数据，避免跨批次数据混淆 |
| 数据源请求超时 | 60 秒 | 匹配生产环节的实时数据采集延迟要求，防止因设备数据拉取超时阻塞工艺文件生成 |
| 单次调用返回数据条数 | 前 10 条 | 控制工具调用的返回数据量，避免上下文过载影响异常报告的快速生成 |
| 异常报告触发条件 | 匹配微生物检测异常阈值 | 对齐乳制品加工的检测判定标准，自动触发异常报告的起草流程 |
| 工具调用重试次数 | 2 次 | 平衡数据拉取成功率与生产链路的响应速度，避免重复请求占用系统资源 |

## 容易做错的三处
- 界面弹出`The tool call is not supported`报错。原因是未在应用配置中启用工具调用功能，或未完成对应工具插件的绑定与授权。
- 工具调用返回的工艺文件数据与当前生产批次不匹配。原因是未配置绑定唯一批次编码的触发规则，导致工具拉取了跨批次的历史数据。
- 本地部署模型后工具调用持续超时。原因是配置的数据源请求超时阈值过短，未匹配本地模型的推理延迟或设备数据拉取的实际耗时。

## 怎么确认配好了
- 发起一次模拟生产批次的工具调用，核对返回的数据是否仅包含对应批次的原奶验收、热处理等记录。
- 触发异常报告起草流程，核对工具是否自动拉取对应的微生物检测报告与设备日志数据。
- 查看插件调用日志，确认工具调用的重试次数与超时设置符合预期配置。
- 测试跨批次的工具调用请求，确认系统会自动拦截不符合批次编码的调用请求。
