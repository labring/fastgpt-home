# 乳制品加工的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
乳制品加工的核心文档包括原奶验收记录、标准化配料单、巴氏或UHT热处理记录、CIP清洗记录、灌装操作记录、留样与微生物检测报告。数据来源包括奶源检测设备、生产MES系统、均质与热处理在线温度流量传感器、CIP清洗系统、LIMS实验室管理平台。数据更新节奏为每奶罐、每生产批次实时同步，液态生物原料的连续性生产要求数据无中断流转，且需严格匹配单批次的生产周期。

## 这些特征在「模型接入与配置」这一环带来什么约束
每奶罐、每批次的实时数据要求模型调用需匹配短周期、高并发的请求节奏，避免延迟影响连续生产流程。多源异构的数据格式，包括结构化的设备数值与非结构化的纸质转电子检测报告，要求配置环节需适配混合输入的解析逻辑。原料易腐的特性要求异常报告生成需具备实时性，模型上下文长度需适配单批次全流程数据的快速整合，同时需限制无效请求以降低算力消耗。此外，乳制品加工的合规关联风险要求模型输出需严格匹配预设字段，避免遗漏关键检测项或异常判定。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单批次生产全流程的多份文档上下文整合需求，避免截断关键的原奶检测或热处理参数 |
| `maxTokens` | 2000–3000 token | 匹配单份异常报告或工艺补充文件的生成长度，适配乳制品加工单批次的数据总量 |
| `quoteMaxToken` | 1500–2000 token | 限制引用的源文档片段长度，确保模型可快速定位原奶抗生素检测、灌装温度等核心生产字段 |
| `temperature` | 0.2–0.4 | 降低生成随机性，确保工艺参数、异常判定的一致性，符合生产规范要求 |
| `AIPROXY_API_ENDPOINT` | 按FastGPT v4.17.0部署实例填写实际访问地址 | 适配外部模型或本地部署模型的调用链路，确保请求可正常路由至目标模型服务 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具，适配多源数据的整合与异常判定的复杂需求 |

## 容易做错的三处
- 调用本地ollama模型时返回空结果。原因是ollama服务未随FastGPT容器同步启动，或网络端口映射配置错误导致无法连通本地ollama实例。
- 配置图像模型后无法启用图像上传选项。原因是未正确开启`vision`相关配置项，或部署的模型本身未适配视觉输入能力。
- 启用AIPROXY后本地vllm模型调用正常，但ollama模型调用失败。原因是ollama的API路径未在AIPROXY的转发规则中配置，或本地ollama服务的监听端口未对外开放。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型测试页面，输入单批次原奶验收记录的典型文本，触发模型生成工艺补充说明，检查输出是否包含原奶检测的核心字段。
- 查看模型调用日志，确认请求的`maxContext`、`maxTokens`参数与配置值一致，无异常截断提示。
- 重启FastGPT容器与本地模型服务后，再次发起测试请求，确认结果可正常返回且无空值。
- 配置`AIPROXY_API_TOKEN`后，发起外部模型调用请求，检查返回结果是否符合预设的字段格式要求。
