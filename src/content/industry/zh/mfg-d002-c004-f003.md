# 仓储、批次与厂内物流的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
仓储、批次与厂内物流的业务数据通常来源于ERP/WMS系统、条码或RFID采集设备、采购与工单数据、库位档案、AGV或输送系统、称重设备等。日常产出的文档包括收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录等，核心字段包含物料编码、批次号、库位编号、效期、数量、检验状态等，单位涉及件、千克、立方米等。数据更新频率覆盖实时（如AGV位置、称重数据）、每日（如领退料记录）、月度盘点（如库存对账数据）。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来源分散且更新节奏不同，多轮对话需保留近期的批次、库位等关键信息，避免上下文过期导致的校验错误。文档字段多且关联紧密，提示词需明确指定需提取的业务字段，减少模糊查询带来的结果偏差。批次与效期的校验需要跨数据源核对，多轮对话需支持上下文传递，确保每一轮的查询都基于前序的业务参数。实时数据的调用需控制会话响应时间，避免因等待数据源导致对话中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按业务系统用户ID拼接会话唯一标识，格式为`{user_id}_{session_timestamp}` | 区分不同用户的聊天记录，避免多用户会话数据混淆，适配FastGPT v4.17.0的会话隔离逻辑 |
| `messages` 上下文保留长度 | 前20–30轮对话或8000–12000字符 | 仓储数据更新频繁，需保留近期的批次、库位信息，避免上下文丢失导致的校验错误 |
| `variables` | 预设物料编码、批次号、库位ID、效期阈值等业务变量 | 快速绑定ERP/WMS的实时数据，减少重复输入，适配不同起草场景的参数需求 |
| 提示词动态加载 | 关联知识库的工艺文档模板，按触发场景自动加载 | 适配收货、盘点、异常报告等不同起草场景，无需每次手动修改提示词 |
| 工具调用超时 | 15–30秒 | 预留足够时间等待AGV、称重设备等实时数据源的响应，避免会话因超时中断 |

## 容易做错的三处
- 现象：不同业务用户的聊天记录无法区分，出现会话数据串用。原因：未使用`chatId`绑定用户唯一标识，仅使用临时会话ID导致数据混淆。
- 现象：每次打开新对话均弹出版本更新说明。原因：会话初始化时未关闭默认的版本提示配置，未通过`variables`预设关闭提示的参数。
- 现象：工具调用结果仅在重新进入对话时显示，首次调用无返回内容。原因：未将工具返回结果正确追加到`messages`会话消息列表，导致前端未渲染最新内容。

## 怎么确认配好了
- 发起测试对话，输入不同的用户标识，查看会话数据是否按`chatId`隔离，确认不同用户的聊天记录互不干扰。
- 新建会话，检查界面是否未弹出版本更新说明，确认提示开关配置生效。
- 调用工具查询指定批次的库存数据，查看对话框实时显示工具返回的库位、效期等信息，确认`messages`的消息追加逻辑正常。
- 触发收货单起草场景，查看加载的提示词模板是否与知识库中存储的收货单起草模板一致，确认动态加载配置生效。
