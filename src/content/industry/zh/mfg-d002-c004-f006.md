# 仓储、批次与厂内物流的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
通常该品类的核心数据来自ERP/WMS系统、条码或RFID识别设备、采购与生产工单、库位管理模块、AGV或输送系统以及称重设备。日常生成的文档包括收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录等，字段覆盖物料编码、批次号、库位编码、效期、入库出库数量、称重数据等。数据更新节奏分为实时（如AGV位置、库位占用状态）、每日（如领退料记录）与月度盘点（如库存总量与呆滞物料统计）三类。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源数据与差异化更新节奏要求溯源环节需区分实时物流数据与静态台账文档的检索时效，避免引用过期的月度盘点数据用于当前异常处理。批次号、库位编码等精准业务字段的存在，要求检索必须优先匹配核心标识，不能仅依赖通用关键词匹配。同时，该品类的异常处理与工艺起草出错后会直接关联生产停线与物料浪费，因此溯源环节需确保引用数据的唯一性与关联性，防止跨工单、跨库位的无关数据被纳入最终内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的逻辑制定，针对仓储、批次与厂内物流场景的溯源需求优化：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 该品类文档包含批次号、库位编码等长字段，需保留足够token以完整呈现溯源所需的原始文档元数据 |
| 相似度阈值 | `0.75–0.85` | 需精准匹配批次号、库位编码等核心业务字段，过滤无关的跨品类物料数据 |
| 单次搜索上限 | 前6条 | 该品类物料关联工单、效期、物流轨迹等多维度信息，少量条目即可覆盖批次全链路溯源需求 |
| `responseData` | 返回完整元数据 | 异常报告与工艺文件需引用批次台账、盘点表等文档的具体字段，如效期、库位、称重数据，仅返回摘要无法满足追溯要求 |
| `detail` | 开启详细溯源 | 该品类的异常报告需关联收货单、移库单等原始单据，详细模式可直接关联原始文档链接与字段值 |
| 最大上下文长度 | `1500–2000 字符` | 需保留工单、AGV物流轨迹等关联信息，避免截断关键溯源链路 |

## 容易做错的三处
- 现象：配置知识库ID或引用变量时，初始输出结果一致，但将应用变量接入知识库时触发报错，界面显示「数据源权限不足」或「变量绑定失败」。原因：未正确绑定该品类专属的ERP/WMS数据源权限，导致变量无法匹配仓储模块的专属数据池。
- 现象：混合检索后返回大量无关的采购文档，无法过滤出仓储类单据。原因：未配置针对批次号、库位编码的专属检索过滤规则，仅依赖通用关键词匹配。
- 现象：引用的批次台账数据与当前工单的物料批次不匹配。原因：未设置按物料编码、工单ID的二次过滤，导致跨批次的冗余数据被纳入溯源范围。

## 怎么确认配好了
- 手动输入一个已知的仓储批次号，检索后确认返回的文档包含该批次对应的收货单、盘点表等专属仓储类文档，且字段完整。
- 触发异常报告起草流程，检查引用的溯源数据是否包含库位、效期、AGV轨迹等该品类专属业务字段。
- 调整`quoteMaxToken`参数值，观察返回的溯源文档长度是否随之变化，确认参数生效。
- 测试应用变量接入知识库的场景，确认无权限报错且返回数据与专属数据源一致。
