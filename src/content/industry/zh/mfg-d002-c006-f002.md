# 光伏组件封装的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
光伏组件封装场景的数据来自电池片分档、玻璃胶膜背板批次、MES系统、串焊与层压设备、EL/IV测试仪。日常产生的文档包含排版图、材料批次记录、层压工艺记录、EL图、IV测试报告、绝缘耐压记录、包装清单。数据更新频率为每块组件、每批材料同步生成，字段涵盖电池片电流档位、层压温度压力、EL隐裂位置、IV功率数值等，附带专业工艺单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该场景的数据特征对向量模型与索引环节带来多重约束。首先，数据按每块组件、每批材料高频更新，要求索引支持增量同步与低延迟更新，避免数据滞后影响工艺判断。其次，文档包含图文混合内容，需同时适配文本参数记录与EL图、IV测试报告等多模态数据的向量编码，覆盖不同类型的业务文档。再者，专业字段多且语义严谨，分块处理时需保留字段关联完整性，防止跨块语义断裂导致参数匹配错误。最后，工艺参数与异常报告的匹配精度要求高，需针对电池片电流档位、层压参数等核心字段优化召回逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配工艺文档的段落长度，平衡语义完整性与索引存储效率 |
| 重叠长度 | 100–200 字符 | 避免跨块语义断裂，保留相邻段落的关联信息 |
| 相似度阈值 | 0.75–0.85 | 匹配专业工艺参数的精度要求，过滤低相关的召回结果 |
| 重排功能 | 开启 | 针对异常报告与工艺文档的混合检索，优化结果排序合理性 |
| `defaultToken` | 4096 | 适配单份工艺文档的常规段落长度，满足基础上下文需求 |
| `maxToken` | 8192 | 整合多份关联测试报告的上下文，支持复杂场景的语义推理 |

## 容易做错的三处
- 本地部署FastGPT v4.17.0时，知识库上传EL图等图片类文档后，无图片索引模型选项。原因是该版本本地部署包未内置多模态索引依赖组件，需手动安装对应插件。
- 设置Rerank模型并开启全局索引配置后，在线召回测试无重排结果。原因是未在目标知识库的召回设置中单独开启重排开关，全局配置仅作为默认生效条件。
- 配置Embedding模型通过OneAPI调用时出现连接报错。原因是本地部署的FastGPT未正确配置OneAPI的接口地址与访问密钥，导致模型调用超时或被拒绝。

## 怎么确认配好了
- 上传一份层压工艺记录文档，等待索引进度完成后，检索“电池片电流档位”关键词，确认返回结果包含对应字段的匹配内容。
- 开启重排功能后，检索包含“EL隐裂”描述的异常报告，核对返回结果的排序是否按相关性调整。
- 查看FastGPT后台的模型调用日志，确认Embedding模型与重排模型均有正常的请求记录。
- 增量上传一份新的材料批次记录，确认索引任务自动触发并在短时间内完成。
