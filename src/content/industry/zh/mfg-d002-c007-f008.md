# 冲压与板材成形的工艺文件与异常报告起草：文档解析与分块

## 这个品类的数据长什么样
冲压与板材成形场景的日常文档包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录。数据来源涵盖钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、MES系统、三坐标或检具检测数据。更新节奏随生产批次变动，每卷料、每批工件、每次换模均会生成对应文档。文档包含固定字段，如模具型号、压边力数值、板材厚度、检测尺寸，单位多为毫米、吨位。

## 这些特征在「文档解析与分块」这一环带来什么约束
多源异构的数据来源与高频更新节奏，要求文档解析需适配不同格式的生产文档，避免遗漏跨系统关联的字段信息。固定字段与单位的文档结构，要求分块时需保留单批次生产的完整参数组合，避免拆分关键工艺数据。高频生成的批量文档，要求解析与分块流程需适配快速处理需求，避免因超时或分块不合理导致后续环节出错。不同文档类型的结构差异，要求解析规则可灵活调整，适配作业指导书、检验报告等各类生产文档的格式特点。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配冲压工艺文档中工艺参数、批次记录的字段长度，避免拆分单批次生产的完整参数组合 |
| `chunkSplitter` | 按段落+表格块拆分 | 对应模具点检表、换模记录的结构化内容，保留表格内数据的关联性 |
| `customPdfParse` | 启用结构化解析模式 | 适配钢卷标签、质保书的固定版式PDF，精准提取钢号、板材厚度等固定字段 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 应对批量文档解析时多系统数据整合的耗时，避免解析中途超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 适配单份冲压工艺文档的常见大小，避免因文件过大导致上传失败 |
| `chunkSettingMode` | 手动配置 | 针对作业指导书、检验报告等不同文档类型，灵活调整分块规则 |

## 容易做错的三处
- 上传材料利用率表后，仅抓取到表头无数据行。原因：未启用`customPdfParse`的结构化表格解析模式，默认通用解析无法识别冲压行业表格的固定列结构。
- 上传冲压作业指导书后，解析节点显示超时无响应。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认值不足以处理包含多系统关联数据的文档。
- 分块后相邻换模记录的字段被拆分到不同块中。原因：`chunkSize`设置过小，将单批次换模的完整参数组合拆分。

## 怎么确认配好了
- 上传单份模具点检表，检查解析后分块是否保留完整的点检日期、模具编号、磨损量字段。
- 上传批量换模记录文档，确认解析耗时未超过`PARSE_FILE_TIMEOUT_SECONDS`的设置值。
- 验证结构化解析模式下，钢卷质保书的钢号、厚度字段被准确提取。
- 调整`chunkSize`后，检查同批次工艺参数未被拆分到不同分块中。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
