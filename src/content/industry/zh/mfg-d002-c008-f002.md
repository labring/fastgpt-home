# 化妆品生产的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
数据来源包括注册或备案配方、原料安全资料、生产设备采集的称量与乳化记录、ERP/MES系统数据、实验室检验报告及包材版本档案。数据更新随每批生产或换线操作触发，单次更新覆盖对应批次的全流程文档。单份文档包含配方原料清单、投料参数、生产环节记录、检验结果与标签审核信息，字段包含原料名称、投料重量、乳化温度、均质时长、成品批号与包材版本号，附带生产环节的数值型与文本型记录。

## 这些特征在「向量模型与索引」这一环带来什么约束
化妆品生产数据随每批生产或换线高频更新，索引需支持增量同步以避免全量重建耗时过长，适配生产流程的节奏。单批次文档包含多类型字段，部分为投料重量、乳化温度等数值型参数，需适配混合类型数据的向量化编码。原料与标签内容受备案约束，需确保向量化后能精准匹配备案要求的合规性字段，避免合规风险。异常报告涉及生产偏差的详细记录，文本长度跨度大，需适配长短文本的分块规则，避免关键信息被截断。同时，数据关联批次与生产环节，索引需保留上下文关联的元数据，便于后续溯源与复核。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本的向量索引功能制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配单份工艺文档的核心段落长度，避免截断关键配方与参数信息 |
| 重叠长度 | 100–150 字符 | 保留跨块的生产环节关联信息，防止分块后丢失上下文 |
| 相似度阈值 | 0.75–0.85 | 适配备案合规字段的精准匹配需求，过滤低相关的非合规记录 |
| 单次搜索上限 | 前 6 条 | 覆盖单批次生产的多类文档，避免检索结果过多干扰大语言模型判断 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 用代表性工艺文档样本实测校准 | 这是直接文本切分使用的默认 token 数；请抽查样本文档的分块结果。它不配置混合类型数据处理。参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx) |

## 容易做错的三处
- 现象：检索返回对应批次的配方文档，但 LLM 输出未找到相关内容。先检查查询、检索过滤条件与结果、提示词、对话历史和 LLM 上下文预算。`maxToken`是嵌入模型输入上限，不是检索结果或 LLM 上下文总上限。
- 现象：索引构建报告输入格式不支持或嵌入失败。检查文档解析结果、样本文本分块、所选嵌入模型/服务响应与错误日志。`defaultToken`控制默认文本切分 token 数，不负责开启混合类型数据处理。
- 现象：增量索引更新耗时过长，超出生产流程的响应窗口。原因：未配置增量同步规则，每次更新都触发全量索引重建，未针对批次级数据做优化。

## 怎么确认配好了
- 导入单批次的完整工艺文档，执行检索测试，核对返回结果的分块长度是否符合预设规则，无明显内容截断。
- 输入合规性查询指令，如“某原料的备案相关要求”，核对检索结果是否覆盖对应备案文档的核心字段。
- 模拟单次换线后的增量索引更新，检查更新耗时是否符合生产流程的时间要求。
- 查看索引元数据，确认批次号、生产环节等关联信息已被正确绑定至对应向量条目。
