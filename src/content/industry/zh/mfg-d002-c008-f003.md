# 化妆品生产的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
化妆品生产的数据主要来自注册或备案配方、原料安全资料、称量与乳化设备、ERP/MES系统、实验室检测记录与包材版本库。日常生产相关文档包含配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验报告、标签审核表。数据更新频率为每批生产或每次换线时更新，文档字段包含配方组分、限用物质含量、生产温度、批号、包材版本等，部分字段需符合备案合规要求。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
化妆品生产的批次独立性与合规要求，对多轮对话与提示词配置带来明确约束。首先，数据按批次更新且需严格匹配备案要求，对话上下文不能跨批次共享数据，否则会导致工艺文件与备案不一致，引发合规风险。其次，文档字段包含合规性强的限用物质、标签宣称等内容，提示词需限定仅调用当前批次的合规数据，避免生成不符合备案要求的内容。最后，多系统来源的数据需精准关联，对话需能追溯对应批次的投料、检验记录，确保异常报告的关联性与准确性，避免遗漏生产环节的关键信息。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 10000–15000 字符 | 覆盖单批次全流程文档的字符总量，避免截断限用物质、批号等核心合规字段 |
| `variables` 绑定规则 | 按当前生产批次ID映射专属数据 | 确保每轮对话仅加载对应批次的投料、检验记录，不跨批次读取历史数据 |
| `messages` 字段处理 | 自动过滤非当前批次的历史消息 | 避免上下文污染，符合化妆品生产的批次管控要求 |
| 提示词模板配置 | 嵌入备案配方校验逻辑 | 确保生成的工艺文件与备案数据保持一致 |
| `chatId` 绑定规则 | 绑定生产批次唯一ID作为标识 | 区分不同生产批次的对话上下文，避免数据串扰 |
| 响应预览开关 | 开启Human消息预览 | 便于排查`messages`字段为空的异常情况 |

## 容易做错的三处
- 调用API时响应预览中`messages`字段的Human值为空。未正确将当前批次的用户输入绑定到`messages`数组的对应位置，导致系统无法识别用户问题上下文。
- 生成的工艺文件包含非当前批次的配方数据。未配置`variables`的批次绑定规则，导致对话调用了历史批次的文档数据，违反批次管控要求。
- 对话界面交互卡顿，历史消息加载异常。未正确配置`chatId`的批次绑定，导致不同批次的对话上下文混合显示，超出系统处理上限。

## 怎么确认配好了
- 发起单批次生产相关对话，检查响应预览中`messages`字段的Human值是否包含当前用户输入。
- 生成工艺文件后，核对其中的限用物质含量是否与备案配方数据一致。
- 切换不同批次的`chatId`，确认对话上下文不会跨批次共享数据。
- 触发异常报告生成，检查是否关联了当前批次的检验记录与投料数据。
