# 化学药制剂生产的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自经批准处方工艺、MES电子批记录、LIMS系统、质量管理系统，覆盖生产、质量保证、质量控制、仓储部门。日常文档包含主生产文件、批生产记录、清场记录、偏差/CAPA/变更文件、批放行审核表。数据按每批生产、每个工艺关键步骤、监测计划更新，字段包含物料批次号、工艺参数值、偏差描述、检验结果等，附带标准化单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据按生产批次、工艺步骤高频更新，且需与生产操作同步，要求索引支持增量更新以避免重复索引全量数据。文档包含结构化批记录与非结构化偏差报告，不同文档的字段长度差异大，需适配分块规则以保留完整工艺参数与异常描述。GMP要求数据全链路可追溯，索引需保留原始数据与生产批次的关联关系，同时需确保检索结果匹配GMP文件合规性要求，避免引入非合规数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配批生产记录、偏差报告的单段内容长度，避免拆分关键工艺参数 |
| 重叠长度 | 50–100 字符 | 保留相邻块的上下文关联，确保工艺步骤的连续性检索 |
| 相似度阈值 | 0.75–0.85 | 匹配GMP合规检索的精度要求，过滤低相关性的非合规文档 |
| `defaultToken` | 1000 token | 适配单篇工艺文件的平均长度，保证基础检索的内容完整性 |
| `maxToken` | 4000 token | 容纳完整批放行审核表的内容，满足异常报告起草的全量数据调用 |
| 单次搜索上限 | 前 8 条 | 控制检索结果的数量，避免引入过多非必要的历史批次数据 |

## 容易做错的三处
- 现象：升级FastGPT v4.17.0后，同一份CSV格式的批记录文件无法正常分块。原因：新版本对分块规则的字符编码校验更严格，未适配旧版导出的非UTF-8编码文件。
- 现象：知识库索引卡住，界面显示未索引完成的状态持续超过30分钟。原因：未配置增量索引触发逻辑，全量索引处理高频更新的批记录数据时超出处理时长。
- 现象：检索结果中出现未完成放行审核的批次记录。原因：相似度阈值设置过低，过滤规则未关联批放行状态字段，引入非合规数据。

## 怎么确认配好了
- 上传单篇完整的批生产记录，检查分块后的内容是否保留全部关键工艺参数与批次标识。
- 触发增量索引操作，验证仅新增的批次数据被纳入索引，未重复处理历史数据。
- 输入异常报告起草相关的检索词，检查返回结果的相似度是否落在预设区间内。
- 查看索引运行日志，确认无编码错误、超时报错或数据关联异常。
