# 半导体封装测试的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据来源包括晶圆测试图、MES系统、键合机与塑封设备、ATE测试机、X-ray/SAM检测设备及客户规格文档。日常文档涵盖封装流程卡、键合与塑封参数表、晶圆来料图、测试程序版本文件、良率报告、失效分析报告。数据更新频率为每生产批次、每颗芯片测试及每日一次。文档字段包含工序编号、参数阈值、设备型号、批次号、bin码、失效类型等，部分文档附带可视化的晶圆点位图与测试时序数据。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于数据包含可视化点位图与结构化测试参数，非结构化文本块长度差异大，部分测试程序文件可达数万字符，需适配长文本分割规则。多源数据更新频率差异大，需支持增量索引与全量索引的灵活切换。晶圆点位图的嵌入需匹配图像向量模型，与文本向量需统一索引空间。不同批次的良率报告格式存在细微差异，需配置自适应的文本分块逻辑，避免因格式偏差导致块丢失。同时，异常报告涉及的失效类型词汇专业性强，需确保向量模型对专业术语的编码准确性，避免语义匹配偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配封装流程卡、良率报告的单块信息密度，避免块丢失 |
| 重叠长度 | 100–150 字符 | 保留跨块的专业术语上下文，避免语义断裂 |
| 相似度阈值 | 0.72–0.85 | 区分专业术语与通用词汇的匹配精度，适配半导体行业术语的语义差异 |
| 单次召回条数 | 前 8 条 | 覆盖多源数据的召回范围，避免遗漏关键测试参数 |
| `defaultToken` | 1024 | 匹配专业文档的token长度，确保长文本的嵌入完整性 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 知识库上传后状态长时间停留在索引中。原因是多源数据的更新频率差异大，增量索引的触发逻辑未适配每批次、每日的更新节奏，导致索引队列堆积。
- 向量化时报错提示embedding速率超限。原因是未调整线程数或模型调用配额，同时未配置合理的分块长度，导致单次调用的token量超出限制。
- 分块长度设置为3000字符时出现块丢失。原因是专业文档的段落结构与通用文本差异大，过长的分块会导致模型无法正确识别语义边界，出现内容截断丢失。

## 怎么确认配好了
- 上传一份封装流程卡样本，检查分块后的文本块数量与预期一致，无明显内容丢失。
- 输入一条专业失效分析问题，查看召回的知识库条目包含对应的测试程序版本与良率数据。
- 查看向量模型的调用日志，确认token使用量未超出`maxToken`的设置范围。
- 测试增量索引功能，上传新的批次良率报告，确认索引状态可在合理时间内完成更新。
