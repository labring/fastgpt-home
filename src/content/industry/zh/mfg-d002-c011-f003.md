# 半导体封装测试的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
半导体封装测试的业务数据来源包括晶圆测试图、MES系统、键合机与塑封设备日志、ATE测试机数据、X-ray/SAM检测报告、客户规格书。日常生成的文档包含封装流程卡、键合与塑封参数表、晶圆来料图、测试程序版本文件、良率报告、失效分析报告。数据更新频率按生产批次、单颗芯片测试结果、每日设备日志更新，文档字段包含晶圆批次号、键合温度、塑封压力、测试bin码、良率数值等专业参数。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据按生产批次、单颗测试结果更新，多轮对话需绑定唯一批次标识以避免上下文混淆。文档包含大量专业设备参数与测试指标，提示词需预设专业字段引导准确检索。多源数据来自不同设备与系统，对话需关联不同索引库的数据源，同时需控制上下文长度以适配多份文档的同时展示需求。此外，异常报告起草需关联批次的完整测试链数据，多轮对话需支持逐步回溯前置参数。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前生产批次的唯一标识 | 用于在多轮对话中关联同一批次的工艺数据与测试结果，避免上下文混乱 |
| `messages` | 预设包含晶圆批次号、键合参数查询的开场话术 | 引导用户快速输入业务核心信息，对齐封装测试的专业场景 |
| `variables` | 预设晶圆批次号、bin码统计范围、良率阈值字段 | 自动填充业务变量，减少手动输入的误差 |
| 单次召回文档上限 | 前10条 | 匹配单批封装测试文档的常规数据量，避免上下文过载 |
| 上下文窗口大小 | 8000–12000 token | 适配多轮对话中需关联的设备日志、测试报告等多份文档的总长度 |
| 问题优化开关 | 开启 | 将用户的口语化查询转换为符合封装测试术语的检索指令，提升召回精度 |

## 容易做错的三处
- 对话开场白仅预设单个问题，无法覆盖多维度业务查询。原因是未在`messages`中配置多个预设业务问题，导致用户无法快速触发对应场景的检索。
- 对话返回404 status code（no body）。原因是`variables`中配置的业务字段未在索引库中存在对应映射，或模型调用时未正确传递上下文参数。
- 刷新页面报“检测到没有可用的索引模型”。原因是未将封装流程卡、良率报告等专属文档上传至对话agent绑定的索引库，或索引配置未完成校验。

## 怎么确认配好了
- 新建对话，输入预设的晶圆批次号，检查`chatId`是否自动绑定对应批次的工艺数据。
- 发送测试问题，检查对话是否能返回预设的`variables`字段内容，且无404类报错。
- 点击回答中的来源标识，确认能跳转至对应封装文档的原文页面。
- 刷新对话页面，检查无“检测到没有可用的索引模型”提示。
