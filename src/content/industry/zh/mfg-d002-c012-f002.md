# 半导体晶圆制造的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
半导体晶圆制造的日常文档涵盖工艺流程卡、批次运行记录、设备配方、SPC图、异常处置单、缺陷图谱、良率报告等。数据主要来自MES系统、设备FDC模块、缺陷检测与量测设备、工艺配方库及实验数据。更新频率覆盖每批晶圆、实时及每日三类，涉及晶圆批次号、工艺参数、缺陷坐标等专业字段，数据结构随工序类型与文档类型存在差异。

## 这些特征在「向量模型与索引」这一环带来什么约束
多来源、多类型的数据需要统一的预处理逻辑，避免专业术语与格式差异导致的embedding偏差。混合的更新频率要求索引策略适配实时、批量两种更新场景，保障数据时效性。超长工艺链与纳米级参数的耦合特性，需要分块时保留工序间的上下文关联，同时提高召回精度以匹配细微的工艺漂移差异。异常报告与良率报告的长文本属性，要求向量模型与索引能够处理较大的token容量。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配单道工艺文件的典型内容长度，适配晶圆制造工序文档的信息密度 |
| 重叠长度 | 100–150 字符 | 保留相邻工序的上下文关联，避免工艺链的逻辑断裂 |
| `maxToken` | 4096 token | 适配异常报告、良率报告的长文本内容，覆盖完整的批次分析数据 |
| 相似度阈值 | 0.75–0.85 | 区分工艺参数漂移与正常波动，适配纳米级参数的细微差异 |
| 单次搜索上限 | 前10条 | 满足跨工序归因的召回需求，避免冗余数据干扰 |
| `defaultToken` | 512 | 作为基础分块的默认长度，适配短文本的异常处置单 |

本文基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 现象：批量重嵌入知识库后，包含多语言专业术语的异常报告召回率未达到预期。原因：未针对晶圆制造的专属术语（如工艺参数单位、缺陷类型）微调embedding模型，或未全量重新构建索引。
- 现象：手动插入的异常报告文档对应的索引数小时后消失。原因：未配置增量索引的持久化存储，或索引刷新周期与晶圆批次的更新频率不匹配导致覆盖。
- 现象：FastGPT v4.9.11版本接入qwen3-embedding-8b后，工艺文件状态持续显示「索引中」。原因：未适配该embedding模型的输入格式，或单批次文档的总token超过模型支持上限，导致索引进程阻塞。

## 怎么确认配好了
- 上传一份典型的晶圆批次运行记录，核对分块后的文本片段与原文档的关键工序描述匹配度。
- 更换embedding模型后，检索包含专业参数的异常报告，检查召回结果的排序符合业务归因逻辑。
- 提交批量重嵌入任务，确认任务完成后索引总数与待处理文档总数一致。
- 模拟实时更新的设备FDC数据上传，验证索引能及时响应数据更新。
