# 半导体晶圆制造的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据覆盖晶圆厂工艺整合、设备、良率等部门的日常产出，包含工艺流程卡、批次运行记录、设备配方、SPC控制图、异常处置单、缺陷图谱、良率报告等文档。数据来源包括MES系统、设备FDC模块、缺陷检测与量测设备、晶圆图文件、工艺配方库与实验数据集，更新节奏随每批晶圆生产、实时参数采集与每日汇总同步推进，字段包含工序编号、晶圆批次ID、参数漂移阈值、缺陷坐标等，单位多为纳米级参数、批次号、时间戳格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的多源异构数据与高频更新节奏，要求引用溯源必须绑定唯一的晶圆批次ID与工序编号，避免跨批次数据混淆。超长工艺链与纳米级参数耦合的特性，要求溯源结果需精准匹配对应工序的参数阈值与缺陷坐标，无法依赖模糊匹配。同时，跨部门的文档关联需求，要求溯源模块可同时关联MES记录、设备FDC数据与缺陷图谱，确保异常报告的引用链路完整覆盖生产全流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配单份晶圆工艺文档的平均长度，避免截断核心工序参数 |
| `responseData` | 仅返回关联字段 | 聚焦晶圆批次ID、工序编号等溯源关键字段，减少无效数据加载 |
| `detail` | 开启完整溯源模式 | 保留数据源的原始文件路径与更新时间戳，满足生产追溯的合规要求 |
| 单次搜索上限 | 前6条 | 覆盖单批次生产涉及的核心工序数据，避免过多低关联结果干扰 |
| 上下文窗口 | 1500–2000 token | 适配多源异构数据的拼接需求，确保异常报告的引用链路完整 |
| 重排逻辑 | 按批次优先级排序 | 优先匹配当前生产批次的数据源，提升溯源准确性 |

以上配置基于FastGPT v4.17.0版本的功能逻辑。

## 容易做错的三处
- 现象：返回的引用条数少于配置的单次搜索上限，且未覆盖当前生产批次的核心工序数据。原因：未绑定晶圆批次ID作为过滤条件，导致搜索结果混杂历史批次的无效数据。
- 现象：引用结果的排序不符合业务预期，并非优先匹配当前生产批次的参数。原因：未配置按批次优先级排序的重排逻辑，仅依赖通用相似度排序。
- 现象：生成的工艺文件或异常报告中附带无法关闭的知识库引用链接。原因：未在工作流的输出节点中关闭引用展示开关，导致所有生成内容自动附带溯源标识。

## 怎么确认配好了
- 导入一份模拟的晶圆批次运行记录，发起搜索请求，检查返回的引用结果是否仅关联该批次的文档。
- 生成一份异常报告草稿，查看引用溯源是否包含原始数据的文件路径与更新时间戳。
- 测试不同生产批次的搜索请求，确认结果是否优先匹配当前配置的批次优先级排序。
- 关闭引用展示开关后，再次生成工艺文件，检查生成内容是否未附带任何知识库引用链接。
