# 印刷与包装加工的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
该品类数据来自客户稿件、色彩管理系统、印刷机运行数据、油墨与基材批次记录、分光仪检测结果、条码检测仪读数等。日常生成的文档包含印前文件、拼版单、印刷工艺单、油墨配色记录、首件签样、条码检测报告、模切与复合工序记录。数据更新随每笔订单、每批次生产、每次印版更换触发，单份文档包含客户需求、工艺参数、检测结果等结构化字段与非结构化图像内容。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的文档同时包含结构化工艺参数与非结构化图像内容，且更新随每笔订单、每批次生产、每次印版更换触发，引用溯源需同时覆盖文本与图像类来源。数据来源分散在客户稿件、色彩管理系统、印刷机数据等多套系统与设备中，需整合多源异构数据，确保引用内容的来源标识与具体生产批次、版次一一对应。异常报告起草需追溯油墨批次、印刷机运行参数等细节，因此溯源环节需精准绑定每个生产节点的原始数据，避免泛化引用导致溯源失效。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 匹配印刷工艺单、条码检测记录等结构化内容的精度需求，避免误引无关批次数据 |
| 单次搜索上限 | 前6条 | 覆盖单份工艺文件关联的拼版单、油墨记录等多份文档，同时控制上下文长度 |
| 重排 | 开启 | 优先排序首件签样、条码检测等核心溯源文档，提升引用准确性 |
| `quoteMaxToken` | 1200–1500 token | 容纳单份异常报告所需的多源溯源内容，避免截断关键批次信息 |
| `responseData` | 包含来源路径与生成时间 | 关联生产批次、设备编号等溯源字段，满足合规性要求 |
| `detail` | 完整 | 保留原始文档的图像引用标识与参数细节，便于后续审核追溯 |

本配置适用于FastGPT v4.17.0

## 容易做错的三处
- 现象：开启重排后，异常报告的引用片段为空，搜索结果条数不足。原因：未调整相似度阈值适配重排后的排序逻辑，阈值设置过高导致有效结果被过滤。
- 现象：导出工作流导入新环境后，溯源环节的数据源引用失效。原因：未将关联的知识库源同步至新环境，仅导出工作流配置未携带绑定的数据源信息。
- 现象：`quoteMaxToken`设置过小，引用内容被截断，无法完整显示油墨批次与印刷机参数。原因：未结合单份溯源文档的平均长度调整参数，导致关键溯源信息丢失。

## 怎么确认配好了
- 生成一份模拟异常报告，核对引用内容的来源路径是否与生产批次、版次一一对应。
- 调整重排开关，对比前后的引用片段排序，确认核心文档如首件签样、条码检测报告被优先展示。
- 导入导出工作流后，检查溯源环节的数据源绑定状态，确认无缺失提示。
- 调整`quoteMaxToken`参数，查看引用内容是否完整显示所有必要的工艺参数与批次信息。
