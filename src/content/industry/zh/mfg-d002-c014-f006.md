# 印染与后整理的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
这个品类的典型主体为染整厂、面料企业的染色、定形、实验室与质量部门。日常生成的文档包含染色配方、称化料记录、染缸曲线、打样确认、色差报告、定形工艺单、污水台账。数据来源包括客户色样、配方库、染化料批次、染缸控制系统、测色仪、定形机、环保监测设备。数据更新频率为每缸、每批、每班，文档字段包含具体数值与批次标识，如染缸温度、化料重量、色差值等，随生产环节动态调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据以批次化湿化学加工为核心，每缸生产对应多份关联文档，且更新频率极高。引用溯源需精准绑定每一批次的染化料、测色数据与工艺参数，无法依赖通用的全局匹配逻辑。单份文档如染缸曲线包含大量连续数值，上下文长度容易超出模型限制，因此需要严格控制引用的token总量。同时，溯源需明确指向具体生产环节的设备、批次与操作人员信息，因此需要保留完整的源文档字段与路径，不能简化或截断关键标识。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 1200–1800 token | 单条染缸曲线或色差报告可达数百字符，设置该区间可避免上下文溢出，确保关键参数完整加载 |
| `responseData` | 前6–10条 | 每批染整生产对应多份工艺与检测记录，返回6到10条可覆盖完整业务链路的关联数据 |
| `detail` | 开启 | 需精准溯源到染化料批次、测色仪读数、染缸编号等具体字段，开启后可显示完整源文件路径与字段信息 |
| 引用触发匹配阈值 | 按实测标定 | 匹配印染工艺的特征字段如色差值、升温曲线斜率，避免召回无关的历史数据 |
| 知识库分块规则 | 按生产批次拆分 | 每缸或每批数据作为独立分块，确保引用溯源时可精准定位单批次生产记录 |

## 容易做错的三处
- 现象：发起工艺查询时，回答未包含本地知识库中的染色配方或染缸记录，仅返回通用模型生成的模糊回复。原因：未正确绑定染整厂专属的配方库、染缸记录知识库，或配置的`responseData`返回条数过低，无法覆盖业务所需的关联数据。
- 现象：引用源显示字段为空或缺失染化料批次、染缸编号等关键标识。原因：未开启`detail`配置，或知识库分块时未保留核心溯源字段，导致引用时无法提取完整信息。
- 现象：API调用返回上下文过长错误。原因：`quoteMaxToken`设置超出FastGPT v4.17.0的接口限制，导致模型无法加载完整的引用源数据。

## 怎么确认配好了
- 上传单份染缸曲线文档，发起包含具体参数的查询，检查返回结果是否包含文档中的温度、时长等实测数值。
- 发起溯源查询，检查每条引用是否显示完整的源文件名称、存储路径与批次标识。
- 调用FastGPT API接口，检查返回的`responseData`字段是否包含匹配的知识库条目，且字段完整。
- 模拟批量查询场景，确认接口未出现超时或上下文溢出错误，配置的`quoteMaxToken`符合接口要求。
