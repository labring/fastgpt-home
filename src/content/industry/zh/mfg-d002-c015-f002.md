# 原料药与医药中间体生产的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
原料药与医药中间体生产的核心数据来自注册工艺文档、原料批次台账、DCS系统、称量系统、LIMS、色谱数据系统及QMS。日常产出的文档包括批生产记录、物料平衡表、反应与精制步骤记录、清洁验证记录、杂质谱报告、偏差与变更文件。数据更新以每生产批次、每工艺步骤为节奏，包含批次标识、反应参数、收率数据、杂质含量、溶剂残留量、偏差原因及整改措施等字段，不同来源的数据格式存在异构性。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引支持跨系统数据的统一嵌入与检索；每批每步骤的高频更新，需要索引适配增量更新配置，避免全量重建带来的计算资源浪费。专业文档中的杂质谱、反应步骤等细分字段，要求向量模型能够准确捕捉医药化工领域的专业术语关联。批次级的更新节奏与严格的合规要求，使得索引召回的精准性直接影响后续工艺审核与异常处理的效率，同时需避免无关批次数据的误召回。

## 配置怎么定
本文适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配批生产记录、杂质谱报告的单页内容长度，避免拆分专业反应步骤或杂质关联段落 |
| 重叠长度 | 100–150 字符 | 保留反应步骤、杂质溯源的上下文连续性，防止分块破坏专业逻辑关联 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 过滤低相关的历史批次数据，精准召回与当前异常或工艺需求匹配的文档 |
| 单次搜索上限 | 前 8 条 | 控制上下文窗口占用，适配单批次工艺分析的信息密度需求 |
| `maxToken` | 4096 token | 适配专业文档的长文本嵌入要求，匹配多数医药领域向量模型的输入上限 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 现象：搜索结果包含未关联当前生产批次的辅助物料数据。原因：未配置数据范围过滤规则，将辅助台账等非核心文档纳入了索引范围。
- 现象：同一批生产记录的不同字段（如反应参数与杂质谱）被合并为单向量，召回时无法精准匹配工艺步骤与杂质问题。原因：未启用分字段向量化配置，或未针对专业字段设置独立的分块规则。
- 现象：上传本地模型生成的向量文件后，服务器端搜索返回空结果。原因：未对齐本地模型与服务器端模型的嵌入维度，或向量文件格式未匹配FastGPT的存储要求。

## 怎么确认配好了
- 上传单份完整的批生产记录，查看嵌入任务的日志，确认分块长度与重叠长度符合配置要求。
- 发起针对特定杂质类型的搜索，核对召回结果的字段是否包含目标杂质相关内容，调整相似度阈值以匹配业务精度需求。
- 新增一条偏差记录并上传，检查索引更新状态，确认增量更新流程正常触发。
- 切换不同的向量模型，验证嵌入后的向量维度一致，确认模型兼容性配置生效。
