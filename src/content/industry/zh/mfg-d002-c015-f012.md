# 原料药与医药中间体生产的工艺文件与异常报告起草：部署与升级

## 这个品类的数据长什么样
原料药与医药中间体生产的工艺文件与异常报告数据，来源涵盖注册工艺文档、原料批次台账、DCS生产数据、称量系统记录、LIMS实验室信息管理系统、色谱数据系统输出及QMS质量管理系统。日常生成的文档包括批生产记录、物料平衡表、反应与精制步骤记录、清洁验证记录、杂质谱报告、偏差与变更文件。数据更新随每一批次生产、每一个工艺步骤完成触发，文档包含批次号、反应收率、杂质含量、溶剂残留量、工艺参数等字段，结构随多步合成或发酵流程呈现层级化特征。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据多源异构且更新频率高，每批生产都会产生新的文档与数据，因此部署环节需要配置兼容多系统数据导入的参数。层级化的长文档需要适配的存储与索引配置，避免单次加载过载。同时，杂质谱报告、变更文件等内容涉及注册合规相关数据，部署时需要配置权限控制与加密存储的参数。升级环节需保证数据迁移的完整性，避免因版本更新导致LIMS、色谱数据系统的字段映射失效，影响异常报告起草的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 本地私有部署的副本集连接串，如`mongodb://user:pass@192.168.1.50:27017/fastgpt?authSource=admin` | 存储批生产记录、杂质谱报告等层级化长文档，适配该品类随生产批次递增的数据存储需求 |
| `REDIS_URL` | `192.168.1.51:6379?password=secure_pass_123` | 缓存频繁更新的工艺步骤数据与用户会话，降低多部门并发访问时的数据库压力 |
| `STORAGE_S3_ENDPOINT` | 内网S3兼容存储端点，如`http://192.168.1.52:9000` | 存储色谱数据系统导出的大体积原始数据文件，满足离线存储的合规要求 |
| `FILE_TOKEN_KEY` | 32位随机生成的字符串 | 生成工艺文档与异常报告的临时下载令牌，控制敏感数据的访问权限 |
| `DB_MAX_LINK` | 20–30 | 适配合成、质量、注册等多部门并发的数据库连接请求，避免连接耗尽导致的服务中断 |
| `ROOT_KEY` | 仅内部运维使用的强密码字符串 | 控制平台最高权限的访问，防止非授权人员修改工艺数据相关配置 |

## 容易做错的三处
- 现象：离线部署后无法拉取更新镜像，服务版本滞后。原因：未提前导出FastGPT v4.17.0的离线镜像包，未配置本地镜像仓库用于版本升级。
- 现象：知识库迁移后杂质谱数据字段为空，无法生成异常报告。原因：迁移时未保留LIMS系统导出的原始字段映射配置，导致数据无法正确关联至工艺文件模板。
- 现象：单机部署时频繁出现数据库连接超时，报错状态码503。原因：`DB_MAX_LINK`配置过低，未适配多部门并发的工艺文件查询请求，导致连接池耗尽。

## 怎么确认配好了
- 执行`docker ps`命令，确认MongoDB、Redis、S3存储依赖容器及FastGPT主容器均处于正常运行状态。
- 上传一份测试用的杂质谱报告文件，验证文件可正常存储并生成临时下载链接，确认`FILE_TOKEN_KEY`配置生效。
- 发起符合实际生产并发量的工艺文件查询请求，验证数据库连接数未触发上限，确认`DB_MAX_LINK`配置适配业务需求。
- 使用`ROOT_KEY`登录平台，验证仅可通过该密钥访问最高权限设置页面，确认权限控制配置生效。
