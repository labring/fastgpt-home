# 喷涂与涂装的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据覆盖汽车、家电、工程机械等涂装线的生产与合规记录，日常文档包含涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账。数据来源包括涂料供应商TDS/SDS、喷房与烘炉实时采集数据、色差仪、膜厚仪、环境监测设备及MES系统。更新频率覆盖每批涂料、每班生产及连续时序采集，文档结构包含固定参数段与动态时序数据，字段包含烘炉温度（℃）、膜厚（μm）、VOCs浓度（mg/m³）、色差ΔE值等带专业单位的项。

## 这些特征在「向量模型与索引」这一环带来什么约束
涂装品类的高频更新与多源数据特征，要求索引支持增量更新以适配实时生产数据。长时序文档如烘炉曲线、连续采集的喷房数据会产生超长文本块，需要适配向量模型的输入长度限制。专业术语如“流挂”“橘皮”“VOCs管控阈值”的精准匹配，要求向量编码适配工业场景的语义特征。多设备并行采集的海量数据，需要调整索引召回规则以覆盖足够的关联文档。合规类台账如VOCs记录的精准匹配，要求相似度阈值符合工业场景的精度需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配涂装工艺卡、烘炉曲线等文档的单段有效信息长度，避免截断核心工艺参数 |
| 分块重叠长度 | 100–200 字符 | 防止“流挂缺陷”“膜厚偏差”等专业术语被分块截断，提升向量匹配的完整性 |
| `maxToken` | 1024 token | 符合行业通用向量模型的输入限制，适配长文档分块后的文本长度 |
| 相似度阈值 | 0.75–0.85 | 匹配涂装缺陷描述、工艺参数的专业语义，平衡召回精度与覆盖范围 |
| 单次搜索上限 | 前 8 条 | 覆盖涂装工艺的多参数关联需求，避免遗漏关键工艺窗口信息 |
| `defaultToken` | 512 token | 适配异常报告起草时的上下文填充需求，保证生成内容的连贯性 |

## 容易做错的三处
- 现象：上传10M以上涂装文档时，部分chunk向量化异常，反复点击重试仍无异常提示。原因：未设置合理的分块重叠长度，导致专业术语被截断，触发向量模型的输入格式校验失败。
- 现象：Ubuntu系统下本地部署ollama后重启服务器，未完成的索引任务卡滞无响应，知识库未就绪。原因：未配置自动恢复索引的规则，重启后未自动续接未完成的分块与向量化流程。
- 现象：发起异常报告起草查询时，返回结果条数不符合预期，且出现token超限报错。原因：未按`maxToken`限制调整分块长度，导致分块文本超出模型支持的token上限。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本上传一份标准涂装工艺卡，检查分块后的chunk列表无异常标记，且分块长度符合预设范围。
- 发起“烘炉温度匹配”查询，验证返回结果条数与单次搜索上限的设置一致。
- 上传超长时序文档如烘炉曲线，确认无token超限报错，且分块重叠长度生效。
- 重启服务器后，检查未完成的索引任务是否自动恢复并推进。
