# 喷涂与涂装的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
喷涂与涂装场景的数据覆盖汽车、家电、工程机械、金属家具等涂装线的全流程信息。日常生成的文档包括涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账，字段包含膜厚单位μm、色差ΔE值、烘炉温度℃、涂料黏度秒等。数据来源涵盖涂料供应商TDS/SDS文件、喷房与烘炉实时采集数据、色差仪与膜厚仪检测结果、环境监测记录、MES生产系统。更新频率为每批涂料更新批次单、每班更新工艺执行记录、连续采集设备运行数据。

## 这些特征在「引用来源与溯源」这一环带来什么约束
涂装场景的多源异构数据与高频更新特性，对引用溯源环节带来多重约束。首先，数据来源覆盖设备、供应商、生产系统三类，需精准关联到具体生产批次与时间窗口，避免跨批次数据混淆。其次，文档类型包含结构化报表与非结构化工艺文件，需支持不同格式的内容还原与字段提取。再者，高频采集的实时数据要求上下文召回覆盖近时段的生产记录，避免引用过期信息。最后，涂装缺陷分析需匹配前处理、喷涂、固化全流程数据，需召回多维度关联文档，确保溯源逻辑完整。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 6000–8000 token | 覆盖单批次涂料的全流程生产与检测数据 |
| `responseData` | 保留原始文档格式 | 还原涂料TDS/SDS、烘炉曲线等专业文档的排版 |
| 分块长度 | 800–1200 字符 | 适配涂装工艺卡、缺陷返修单等文档的字段完整性 |
| 单次召回上限 | 前7条 | 匹配涂装工序的多维度关联数据 |
| `detail` | 显示来源文件名与采集时间 | 关联MES系统的生产批次与设备运行记录 |
| 重排开关 | 开启 | 优先召回与喷涂缺陷直接相关的检测数据 |

## 容易做错的三处
- 上下文引用区域仅显示由`|`分隔的原始文本片段，未保留文档原有的表格、标题格式，原因是未正确开启`responseData`的原始格式保留配置。
- 发起关于特定批次涂料缺陷的提问后，无法召回目标涂装工艺卡或膜厚色差报告，原因是分块长度设置过小导致关键信息被截断，或单次召回上限设置过低。
- 生成的异常报告中残留无法移除的引用来源标注，原因是未正确配置`detail`参数的显示开关，误将引用内容直接从响应中删除。

## 怎么确认配好了
- 上传一份完整的涂装工艺卡文档，发起关于工艺参数的提问，检查上下文引用区域是否保留原始文档的表格结构与单位标注。
- 发起关于某批次涂料缺陷的提问，核对召回结果中是否包含对应批次的调漆记录与烘炉曲线数据。
- 查看生成的异常报告，确认引用来源的文件名、采集时间与生产批次信息是否完整显示。
- 调整单次召回上限参数，验证召回结果的条数是否符合预设的取值范围。
