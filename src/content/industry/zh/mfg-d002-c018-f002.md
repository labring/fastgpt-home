# 基础化工连续生产的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来自DCS/SIS控制系统、在线分析仪、LIMS实验室管理系统、设备状态监测模块、能源计量系统及原料储罐台账。日常文档涵盖操作规程、工艺指标卡、DCS趋势数据、化验报告、联锁旁路记录、特殊作业票、班组日报。数据更新节奏包含实时、每班交接、每日汇总。文档字段包含设备运行参数、物料浓度、操作阈值、报警记录等，参数单位多为MPa、℃、m³/h等工业通用单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源与差异化更新节奏，要求索引环节支持灵活的同步策略，适配实时数据流、每班批量数据与每日汇总数据的不同更新频率。多样化的文档类型包含结构化参数卡、半结构化趋势数据与非结构化作业记录，需要针对不同文档结构设计适配的分块规则，避免拆分破坏参数关联或段落完整性。工艺相关的异常报告起草依赖精准的联锁记录、操作阈值匹配，索引召回需优先关联工艺核心字段，同时需保障高召回覆盖率以避免遗漏关键处置依据。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配基础化工工艺文档的段落与参数块长度，避免拆分关键工艺参数组 |
| 重叠长度 | 100–150 字符 | 保障相邻分块的工艺上下文连贯性，避免参数跨块丢失 |
| `maxToken` | 4096 token | 适配长段工艺文档的内容长度，满足向量编码的完整信息需求 |
| `defaultToken` | 1024 token | 平衡异常报告起草的上下文召回与计算资源消耗 |
| 相似度阈值 | 按实测标定 | 不同企业的工艺参数阈值差异较大，需结合实际业务场景调整 |
| 单次搜索上限 | 前 10 条 | 覆盖足够的工艺相关文档，同时避免冗余结果干扰起草 |
| 重排模型 | 私有化部署的重排模型 | 保障工艺相关内容的排序精准性，适配企业自有数据特征 |

## 容易做错的三处
- 现象：配置重排模型时选择通用公开模型，导致异常报告中出现与企业工艺不匹配的冗余内容。原因：未针对基础化工连续生产的专属工艺数据调整重排模型，通用模型无法优先召回联锁记录、工艺阈值等核心内容。
- 现象：单次搜索上限设置为前3条，导致关键的联锁旁路记录或历史异常报告未被召回。原因：未考虑基础化工文档中异常相关内容分散在多个文档中的特征，搜索上限过低遗漏关键依据。
- 现象：`maxToken`设置为2048 token，导致长段的DCS趋势数据被截断，向量编码丢失关键参数信息。原因：未结合基础化工工艺文档的内容长度调整`maxToken`参数，截断了影响异常判断的核心数据。

## 怎么确认配好了
- 导入一份典型的工艺指标卡与异常报告草稿，检查分块后的文档片段是否保留完整的参数阈值与操作步骤。
- 发起一条模拟异常查询，核对召回的文档中是否包含联锁旁路记录、历史异常处置记录等核心内容。
- 查看向量编码后的文档元数据，确认不同更新频率的数据源均已正确同步至索引库。
- 对比启用重排模型前后的召回结果排序，确认工艺相关内容的排序符合业务预期。
