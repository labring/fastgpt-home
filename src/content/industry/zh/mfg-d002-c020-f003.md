# 安全环保与特殊作业管理的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的文档包含风险辨识记录、动火/受限空间/吊装等作业票、在线监测记录、危废台账、排放监测数据、事故与隐患整改报告。数据来源涵盖法规标准库、在线环保监测设备、气体检测仪、人员资质清单、设备隔离清单及监管平台。数据更新随单次作业完成、实时监测节点或定期检查推进，文档字段包含作业时长、气体浓度值、资质编号、隔离点位等，单位匹配对应检测与管理要求。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且包含离线静态资质与在线实时监测数据，要求多轮对话需分阶段动态调用不同数据源。单次作业的全流程记录需通过会话上下文留存，避免信息断裂。作业前的风险辨识、资质核验需多轮校验，确保合规性。异常报告需关联实时监测数据与历史整改记录，提示词需支持跨数据源的信息整合。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` 会话跟踪 | 启用 | 保留单次作业全流程的多轮对话上下文 |
| `variables` 变量绑定 | 绑定人员资质库、设备隔离清单、实时监测接口 | 动态引用分散的数据源，避免硬编码静态数据 |
| 最大上下文长度 | 8000–12000 token | 容纳作业票、监测记录与整改报告的完整内容 |
| 模型调用超时 | 600 秒 | 匹配复杂风险辨识与多源数据整合的耗时需求 |
| 知识库搜索范围 | 绑定指定合规集合 | 确保仅调用与安全环保相关的法规与历史数据 |
| `messages` 历史管理 | 保留最近30轮对话 | 控制上下文负载，避免请求超时 |

## 容易做错的三处
- 对话组件中配置变量引用时无温度设置入口，原因：未在模型配置界面开启高级参数开关，导致无法调整生成相关参数。
- 单轮对话耗时超600秒且调用分组计数仅为1，原因：未限制上下文窗口长度，单次请求加载过多历史作业记录，超出系统处理上限。
- 添加数据库连接插件后配置报错，原因：未将数据库连接信息写入`variables`变量池，直接硬编码导致路径或权限校验失败。

## 怎么确认配好了
- 发起模拟动火作业对话，检查是否自动引用绑定的监护人资质、设备隔离清单数据。
- 查看会话日志，确认`chatId`随每轮对话更新并完整保留作业流程的历史记录。
- 测试触发异常报告生成，检查是否关联实时排放监测数据与历史隐患整改记录。
- 确认FastGPT v4.17.0版本下，变量引用配置可正常加载绑定的数据源内容。
