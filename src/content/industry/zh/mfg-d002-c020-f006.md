# 安全环保与特殊作业管理的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
本品类的典型文档包含风险辨识清单、动火/受限空间作业票、在线环保监测记录、危废台账、事故整改报告等。数据来源涵盖法规标准库、在线环保监测设备、气体检测仪、人员资质档案、设备隔离清单与监管平台。更新节奏分为三类：单次作业完成后即时更新作业票与风险记录，监测数据按实时或日度刷新，合规台账按季度定期更新。文档字段包含作业许可编号、气体浓度值、危废产生量、监管反馈编号等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源异构的数据来源要求溯源系统区分静态资质、实时监测与合规文档的召回优先级；单次作业关联的多份文档需要按作业ID精准关联，避免跨作业的无效引用；不同更新频率的数据需要匹配对应的溯源校验逻辑，确保实时监测数据的时效性；由于出错后果涉及人身安全与合规处罚，溯源必须保证引用内容的完整性与准确性，无法遗漏关键字段。FastGPT v4.17.0的溯源配置需适配这些特征，否则会导致合规核查无法完成。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 16000–20000 token | 覆盖法规标准、多份作业票、监测报告的完整上下文 |
| 知识库最大引用 | 前7条 | 匹配单次安全作业关联的资质、隔离、监测数据总量 |
| 最大响应tokens | 1800–2200 字符 | 满足异常报告起草的完整说明与溯源要求 |
| `quoteMaxToken` | 10000–14000 token | 限定单条引用的最大长度，避免冗余数据干扰 |
| `detail` | 开启 | 保留引用来源的完整字段，包括检测时间、资质编号等 |
| `responseData` | 包含引用文档的更新时间与来源类型 | 便于核查数据的时效性与合规性 |

## 容易做错的三处
- 配置`quoteMaxToken`取值过小，导致引用的监测报告内容被截断，界面显示为截断标记，无法完整查看气体检测的浓度数值与时间。原因是未匹配安全环保文档的单篇长度需求，截断了关键溯源信息。
- 未设置`responseData`保留源文档标识，导致生成的异常报告仅显示内容，无法关联到对应的作业票编号或监管平台反馈记录，无法完成合规核查。原因是关闭了引用溯源的元数据输出配置。
- 未正确处理换行标记，生成的文档中提示的\n被原样输出为文本，无法实现段落分隔。原因是未启用响应内容的格式解析开关，误将换行指令作为普通文本处理。

## 怎么确认配好了
- 提交一份包含作业票、气体检测记录的测试查询，检查返回的引用内容是否包含完整的检测时间、浓度值等字段。
- 查看引用元数据，确认是否包含对应文档的更新时间与来源类型，可通过`responseData`对应的输出字段验证。
- 调整`quoteMaxToken`的取值，测试不同长度的引用内容是否被完整返回，无截断标记。
- 输入包含换行提示的测试指令，确认生成的文档中换行标记被正确解析为段落分隔。
