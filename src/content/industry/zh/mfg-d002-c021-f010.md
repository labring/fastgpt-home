# 家具与木制品制造的工艺文件与异常报告起草：知识库检索与召回

## 这个品类的数据长什么样
这个品类的典型数据来自订单设计系统、板材与木材批次记录、数控开料钻孔设备日志、ERP/MES系统及现场检测记录。日常文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺规范、五金配套清单、试装与包装记录。数据更新随定制订单生成、每日生产同步、每批次材料进场触发，文档多包含板件尺寸、生产批次编号、工艺步骤等字段，无统一固定格式，随订单个性化调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
定制订单驱动的生产模式导致单批次文档数量多且个性化强，要求检索环节支持多文档关联召回以匹配对应板件的工艺要求。多来源的数据更新频率差异大，需支持按订单、按批次的增量更新机制。文档无统一格式，段落长度差异明显，要求检索环节适配不规则文本的分块与识别。板件尺寸、批次编号等字段的精准匹配直接影响生产结果，要求检索的召回结果需严格关联对应生产参数。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.72–0.88` | 适配家具木制品工艺文档的个性化特征，平衡召回数量与结果精准度，避免无关板件参数混入 |
| `limit` | `前 6–10 条` | 定制订单单批次涉及的板件与工艺文档较多，单次召回足够覆盖核心生产与异常处理需求 |
| `usingReRank` | `开启` | 工艺文档段落差异大，重排环节可过滤低相关结果，提升异常报告起草时的内容准确性 |
| `datasetSearchUsingExtensionQuery` | `开启` | 补充订单编号、板件批次等专属字段的检索扩展，匹配多来源的生产数据 |
| `collectionIds` | `按生产文档分类绑定对应集合` | 区分拆单图、工艺规范、五金清单等不同类型文档，避免跨品类无关内容干扰 |

## 容易做错的三处
- 现象：私有化部署升级版本后，点击知识库文件详情显示“Invalid dataset file key ”。原因：升级过程中未同步更新数据集文件关联的密钥缓存，导致系统无法识别原有文件的合法标识。
- 现象：知识库分块后检索结果出现板件尺寸与工艺步骤不匹配的情况。原因：未开启模型识别段落功能，或最大段落深度设置为3、最大分块大小为1000时未适配工艺文档的层级结构，导致分块割裂了工艺与对应板件参数的关联。
- 现象：通过API拉取外部文档库时无法同步飞书多维表的实时数据。原因：未正确配置外部数据源的API调用权限，或未启用数据集扩展检索功能，导致无法关联多维表中的五金清单或开料数据。

## 怎么确认配好了
- 检索测试时输入某定制订单的板件尺寸，核对召回结果是否包含对应开料清单与涂装工艺文档。
- 查看知识库分块日志，确认已按模型识别段落的方式完成分块，且最大段落深度与分块大小符合预设配置。
- 调用检索API，验证返回结果是否包含来自ERP系统的生产批次数据与外部文档库的配套信息。
- 检查系统日志，确认未出现数据集文件密钥相关的异常报错。
