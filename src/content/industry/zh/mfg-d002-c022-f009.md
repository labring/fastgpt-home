# 家用电器整机制造的工艺文件与异常报告起草：模型接入与配置

本文基于FastGPT v4.17.0版本编写

## 这个品类的数据长什么样
该品类数据来源包括ERP/MES系统、零部件批次台账、拧紧与制冷剂充注设备、安规测试仪、性能实验室数据及售后故障记录。日常文档涵盖配置BOM、装配作业书、制冷剂充注记录、电气安全测试报告、性能抽检报告与返修记录。数据更新节奏按单台设备、每班生产批次及抽检计划执行，文档字段包含机型编号、零部件批次号、工艺参数值、测试结果与故障编码等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多型号混线装配的生产场景要求模型精准匹配对应机型的工艺文档，因此需配置足够的上下文窗口以承载多机型的工艺文件与设备数据。高频更新的设备实时参数、按批次生成的抽检与返修记录，要求模型调用适配实时性与批量数据处理的规则。安规、能效相关的异常判断需严格匹配合规要求，因此模型的随机性参数需控制在合理区间。多源数据来源分散的现状，要求配置统一的API接入端点以整合ERP、MES与生产设备的各类文档与数据，避免跨系统调用的格式冲突。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 需承载多机型的BOM、装配作业书及近期设备数据，避免上下文截断导致工艺参数遗漏 |
| `maxTokens` | 4000–6000 token | 限制单次生成的工艺文件或异常报告的长度，避免输出过长超出平台限制 |
| `temperature` | 0.1–0.3 | 安规与工艺判断需低随机性，确保异常报告与工艺文件的表述一致性 |
| `quoteMaxToken` | 2000–3000 字符 | 需引用足够的设备测试记录、返修数据作为工艺起草的依据 |
| `toolChoice` | auto | 需自动调用文档检索工具获取对应机型的装配作业书与安规要求 |
| `AIPROXY_API_ENDPOINT` | 对应模型的官方接入地址 | 适配不同模型的接入场景，确保数据传输符合生产环境要求 |

## 容易做错的三处
- 现象：调用Azure OpenAI模型时返回401未授权错误。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的对应关系，或密钥权限未覆盖工艺文档与设备数据的访问范围。
- 现象：生成的工艺文件中出现跨机型的错误装配参数。原因：`maxContext`配置过小，导致模型无法加载对应机型的专属装配作业书，混淆了不同机型的工艺要求。
- 现象：工作流中落款时间字段为空或显示异常。原因：未正确绑定系统内置的时间变量，未在提示词中明确要求调用平台提供的当前日期变量。

## 怎么确认配好了
- 发起一次单机型的工艺文件起草测试，检查生成内容是否包含对应机型专属的装配参数与安规要求，调整`maxContext`与`quoteMaxToken`直至内容完整。
- 提交异常报告生成任务，核对输出结果的随机性是否符合工艺严谨性要求，调整`temperature`的取值区间。
- 调用API接入测试工具，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置可正常拉取ERP中的BOM数据，无格式转换错误。
- 触发工作流中的落款时间生成步骤，确认字段自动填充当前日期，验证系统时间变量的绑定逻辑正常。
