# 工业仪器仪表制造与校准的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自设计文件、标准器监测数据、校准软件输出、实验室信息系统及客户量程要求。日常生成装配调试单、校准规程、原始校准记录、误差曲线、计量证书、软件版本记录等文档，每台设备每次校准即更新数据。数据字段包含被测参数值、校准日期、溯源编号、环境监测参数，单位覆盖流量、压力、温度等对应计量标准单位，单份校准记录数据量随校准点数增加而变化。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类数据按单台设备每次校准更新，多轮对话需关联对应设备的历史校准记录与当前校准数据，避免混淆不同批次或设备的参数。文档包含专业计量字段与单位，提示词需明确指定字段提取格式，确保误差值、溯源编号等关键信息准确匹配。单份校准记录数据量随校准点数增加，多轮对话的上下文长度需适配多份关联文档的加载，同时需保留历史对话中的设备编号、客户量程要求等信息，保证后续提问的上下文一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口大小 | 8000–12000 token | 适配单台设备多份校准文档（原始记录、误差曲线、证书）的总长度，避免截断溯源编号等关键信息 |
| `variables` 全局变量 | 绑定单台设备的校准记录ID、客户量程要求 | 确保多轮对话中始终关联对应设备的专属数据，避免跨设备参数混淆 |
| `messages` 历史消息保留规则 | 保留最近4轮对话及首次设备标识输入 | 平衡上下文完整性与调用效率，保留设备编号与初始量程要求 |
| 提示词模板结构 | 按「校准数据校验→误差计算→异常报告生成」顺序拆分 | 匹配本品类文档的固定审核与生成流程，确保专业字段提取准确 |
| `chatId` 会话隔离规则 | 按单台设备每次校准创建独立会话 | 确保不同批次或设备的校准数据不会跨会话干扰，符合本品类按台次更新数据的特征 |
| 大模型温度设置 | 0.1–0.3 | 确保计量相关的数值与溯源信息生成准确，避免随意改动专业参数，符合FastGPT v4.17.0的参数配置逻辑 |

## 容易做错的三处
- 现象：全局变量首次传入后，在同对话中修改变量值后，后续组件调用仍显示初始值。原因：未正确绑定`variables`的会话内更新逻辑，导致变量未随对话轮次同步刷新。
- 现象：AI对话组件选择变量引用大模型时，界面未显示温度设置入口，无法调整生成参数。原因：未在高级配置页开启参数展示开关，导致温度设置项隐藏。
- 现象：仅配置对话模型时，调用分组显示为1组，但对话回传耗时超过600秒。原因：未限制`messages`的历史消息保留轮次，导致上下文过长，大模型处理超时。

## 怎么确认配好了
- 发起单台设备的校准流程测试对话，输入首次校准参数，核对全局变量是否正确绑定对应设备的ID与量程要求。
- 连续发起3轮针对不同校准数据的提问，核对每一轮的原始问题均可被正确识别与关联。
- 检查大模型调用日志，确认上下文窗口未出现关键文档内容截断，且会话隔离规则生效。
- 调整大模型温度参数，核对生成的计量报告数值精度是否符合预期，无随意改动的专业字段。
