# 工业仪器仪表制造与校准的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
本品类数据覆盖流量、压力、温度、分析仪器制造商及计量实验室的日常业务，日常文档包含装配调试单、校准规程、原始校准记录、误差曲线、计量证书、软件版本记录。数据来源包括设计文件、标准器监测数据、校准软件输出、实验室信息系统及客户量程要求，更新频率为每台设备每次校准后更新，文档字段包含校准日期、误差值、计量证书编号、软件版本号等，单位多为国际标准计量单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类数据的多来源、单次校准即更新的特征，要求引用溯源环节需精准匹配单台设备的单次校准记录，避免跨设备、跨批次数据混淆。不同来源数据的优先级需明确，标准器监测数据需优先作为溯源依据，校准软件输出需关联原始采集记录。文档类型多样，需针对装配调试单、校准规程、计量证书等不同文档配置对应召回规则，确保引用内容与业务场景匹配。同时校准记录作为核心交付物，引用时需完整保留字段与单位，避免信息失真。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 适配FastGPT v4.17.0的上下文处理能力，容纳多份校准文档、误差曲线的长文本内容 |
| 单次搜索上限 | 前6条 | 覆盖单台设备的校准规程、原始记录、计量证书等核心文档，避免无关数据干扰 |
| 重排 | 开启 | 优先召回与校准溯源、异常原因直接相关的内容，提升引用准确性 |
| `quoteMaxToken` | 1500–2000 字符 | 限制单条引用片段长度，确保工艺文件与异常报告中引用内容清晰不冗余 |
| `responseData` | 保留原始字段与单位 | 确保引用的校准数据、误差值等内容完整匹配业务文档格式 |
| `detail` | 开启 | 要求大模型严格保留原始文档的字段、单位与数值细节，避免信息篡改 |

## 容易做错的三处
- 现象：生成的异常报告中引用字段为空，或未显示校准证书编号。原因：未正确配置`responseData`，未要求大模型提取并保留原始文档的关键字段。
- 现象：召回的引用内容跨设备批次，与当前起草报告的仪器不匹配。原因：未配置按设备序列号、校准日期过滤召回结果，导致召回范围覆盖了无关设备的文档。
- 现象：大模型输出的引用片段与原始文档单位不一致，如将kPa误写为bar。原因：未开启`detail`配置项，未强制要求大模型严格遵循原始文档的单位与数值格式。

## 怎么确认配好了
- 上传单台指定设备的校准文档与计量证书，发起起草工艺文件的测试请求，检查返回结果中是否包含对应设备的校准日期与误差值。
- 查看引用来源的元数据，确认每条引用都标注了文档类型与来源路径，符合溯源要求。
- 调整单次搜索上限的取值，测试召回结果的条数是否符合预期，验证过滤规则是否生效。
- 检查生成的异常报告中引用的单位是否与原始文档一致，确认`detail`配置项生效。
