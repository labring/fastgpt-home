# 工艺变更与工程变更的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据由PLM、ERP、MES、供应商资料、验证试验、客户特殊要求等来源生成，更新随每次变更不定期触发。日常文档包含ECN/ECR、变更评估、图纸与BOM版本、工艺验证报告、切换计划、库存处置单、客户批准文件，字段包含变更编号、生效节点、关联物料/工序、验证状态等，无统一固定周期，每次变更触发对应数据的新增或更新。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散导致需关联多类知识库片段，提示词需明确指定调用对应来源的文档；不定期更新要求对话系统支持按需触发知识库刷新，避免使用固定周期同步导致的文档过期；文档含版本号与关联物料/工序字段，多轮对话需跟踪变更的版本关联，避免引用旧版文件引发混用风险；变更涉及多部门协同，多轮对话需保留`messages`上下文以承接不同角色的变更诉求，确保起草的文件覆盖所有关联影响。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前6条 | 该品类文档数量随变更递增，需限制返回结果避免上下文过载 |
| 引用内容模板 | 「变更编号：{编号}，生效时间：{时间}，关联工序：{工序}」 | 匹配该品类文档的核心字段，便于快速提取变更关键信息 |
| 最大上下文长度 | 8000–12000 token | 适配多轮对话中需保留的多部门变更诉求与关联文档内容 |
| 变量配置 | `variables` 绑定变更编号、生效节点 | 用于快速定位对应知识库中的专属变更文件 |
| 对话ID绑定 | `chatId` 绑定当前变更会话 | 用于区分不同变更的对话上下文，避免会话混淆，FastGPT v4.17.0 及以上版本支持该配置 |
| 问题优化 | 开启 | 帮助模型将模糊的变更诉求转化为精准的知识库检索指令 |
| 重排 | 开启 | 优先返回与当前变更主题最相关的文档片段 |

## 容易做错的三处
-  检索结果包含无关的旧版变更文档，原因是未在提示词中明确指定需关联当前变更的指定文件，导致模型检索到不匹配的历史文件。
-  对话无法调用指定的新建变更知识库，原因是未在配置中绑定对应变更的专属变量，导致系统无法定位到正确的知识库关联项。
-  起草的文件混淆提示词与知识库引用模板的内容，原因是未明确区分提示词的指令逻辑与知识库引用的内容格式，导致模型输出混乱。

## 怎么确认配好了
-  输入一条模拟的变更诉求，检查检索返回的文档是否包含当前变更的编号与关联工序，核对字段匹配度。
-  发起多轮对话，连续提出不同部门的变更补充诉求，检查上下文是否被保留并被模型正确承接。
-  查看配置界面的变量绑定项，确认变更相关的核心字段已被正确关联到对话流程中。
-  触发知识库刷新操作，检查新上传的变更文档是否能被后续检索正常调用。
