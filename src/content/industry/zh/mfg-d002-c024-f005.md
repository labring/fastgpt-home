# 工艺变更与工程变更的工艺文件与异常报告起草：工具调用与插件

## 这个品类的数据长什么样
本品类数据由制造企业变更管理团队产生，覆盖研发、工艺、质量、生产、采购多部门协作内容。数据来源包含PLM、ERP、MES、供应商资料、验证试验及客户特殊要求，更新频率为每次变更不定期触发。核心文档包括ECN/ECR、变更评估报告、图纸与BOM版本、工艺验证报告、切换计划、库存处置单及客户批准文件，包含变更编号、生效日期、影响物料清单等结构化字段，以及图纸、试验报告等非结构化内容。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据分散于多系统且更新无固定周期，要求工具调用需支持按需触发，适配每次变更的临时数据需求。文档包含结构化与非结构化混合内容，需搭配格式解析插件处理不同格式的文件。变更关联多部门协作内容，工具调用需集成权限校验环节，避免越权访问敏感的客户批准文件与工艺图纸。同时，变更数据量随影响范围波动，需动态调整工具调用的资源分配，避免单次调用过载。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的插件系统。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | `auto` | 支持自动匹配变更场景的工具，适配不同类型的变更需求 |
| 工作流/API 函数调用配置 | `enabled` | 强制启用结构化工具调用，确保生成的变更文档与异常报告符合合规格式 |
| 多源数据拉取插件 | 按变更触发调用，单次拉取最多5条数据源数据 | 适配本品类数据不定期更新的特征，避免无效的定时拉取 |
| 超时阈值 | 120 秒 | 预留足够时间完成跨系统的数据拉取与格式解析 |
| 格式解析插件 | 前3条关联文档优先解析，单文档最大处理长度1500字符 | 优先处理变更核心关联的文档，提升处理效率 |
| 权限校验配置 | 按实测标定 | 适配不同企业的权限规则差异，确保数据访问合规 |

## 容易做错的三处
- 现象：调用AntV Chart MCP插件时，仅返回XML或JSON代码块，未渲染可视化图表。原因：未配置图表渲染的关联触发规则，工具调用仅完成数据拉取未执行渲染步骤。
- 现象：API调用生成的变更文档与在线聊天结果差异明显。原因：API请求未携带完整的上下文参数，或未同步在线聊天中启用的知识库关联配置。
- 现象：工具调用拉取PLM数据时返回空字段。原因：未正确配置数据源的权限校验参数，无法访问对应变更关联的图纸与BOM版本数据。

## 怎么确认配好了
- 发起模拟变更请求，检查工具调用日志是否自动匹配到对应数据源的拉取动作。
- 输入变更相关的查询，确认返回结果包含结构化的工具调用输出与合规的文档格式。
- 调用API接口发起相同请求，对比在线聊天与API的返回结果，确认一致性。
- 测试异常场景，比如请求不存在的变更编号，检查工具调用是否返回明确的错误提示。
