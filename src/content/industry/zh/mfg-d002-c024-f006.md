# 工艺变更与工程变更的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来源于PLM、ERP、MES、供应商资料、验证试验结果及客户特殊要求，更新随每次工艺或工程变更不定期触发。日常产出文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本记录、工艺验证报告、生产切换计划、库存处置单及客户批准文件，数据字段包含变更编号、版本号、生效节点、物料编码、验证结论等，无统一固定的批量更新节奏。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且随每次变更独立更新，需精准匹配变更编号与版本号才能避免跨版本引用错误。文档类型多样且字段非标准化，需针对ECN表单、工艺验证报告等不同文档调整检索匹配逻辑。不定期更新要求溯源功能实时关联最新版本数据，无法依赖固定周期的索引刷新。变更关联多部门协同产出的文件，需同时溯源研发、工艺、质量等多来源的验证记录，扩大了检索范围与匹配复杂度，增加了结果过滤的难度。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，具体如下：
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 相似度阈值 | 0.75–0.85 | 匹配变更编号、版本号这类精准字段，需较高相似度保证引用准确性 |
| 单次搜索上限 | 前8条 | 覆盖多来源的变更关联文档，避免遗漏关键验证记录 |
| 重排 | 开启 | 优先排序带变更编号、版本号的高相关片段，提升溯源效率 |
| `quoteMaxToken` | 1200–1500 token | 容纳ECN、工艺验证报告等长文档的完整引用片段 |
| 最大上下文 | 8000–10000 字符 | 承载多来源的变更关联数据，保证溯源逻辑完整 |
| 问题优化 | 开启 | 自动补充变更编号、版本号等关键检索条件，优化检索精度 |

## 容易做错的三处
- 现象：开启重排功能后检索结果为空或引用片段缺失。原因：重排阈值设置过高，过滤掉了带变更编号的低相似度但关键的文档片段。
- 现象：检索超时导致引用失败。原因：单次搜索上限设置过高，同时检索多来源的大量文档超出`quoteMaxToken`限制。
- 现象：引用的文档版本与当前变更不匹配。原因：未在检索条件中加入版本号过滤，导致跨版本的旧文档被错误引用。

## 怎么确认配好了
- 提交包含变更编号的测试问题，检查返回结果中是否附带对应文档的变更编号与版本号。
- 开启重排功能后，验证检索结果的排序是否优先展示带变更标识的片段。
- 调整`quoteMaxToken`参数后，确认长文档的完整引用片段未被截断。
- 查看系统日志，确认无检索超时或结果为空的异常记录。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
