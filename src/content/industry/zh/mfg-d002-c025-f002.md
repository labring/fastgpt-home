# 工装夹具与检具制造的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自产品数模与GD&T、工艺路线、三坐标数据、现场试用反馈及计量系统。日常文档包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录与变更履历。数据更新按项目节点、产品变更触发，定期校准环节也会产生新数据。文档包含GD&T公差参数、三坐标测量值、定位夹紧方案细节等字段，部分文档附带工程图纸关联的二进制附件。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来多重约束。含工程图纸的文档需适配多模态向量编码，匹配多模态向量模型的调用要求。按项目与变更触发的更新节奏，要求索引支持增量更新与版本化管理，避免重复索引历史数据。高精度的GD&T公差、三坐标测量值等字段，需要向量模型保留细节精度，防止编码后丢失关键定位信息。结构化的计量数据与非结构化的操作文档混合，需要统一的分块规则适配不同格式的内容长度。

## 配置怎么定
FastGPT v4.17.0版本下的配置项如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类文档中夹具图说明、验收报告的平均长度，避免单块内容包含跨页图纸注释 |
| 重叠长度 | 100–150 字符 | 覆盖定位基准方案、变更履历的跨块关键信息，防止分块切断连续的公差描述 |
| `defaultToken` | 4096 token | 匹配多数开源向量模型的默认输入长度，适配本品类单份文档的平均token总量 |
| `maxToken` | 8192 token | 支持包含多份校准记录的批量索引场景，满足长文本的编码需求 |
| 相似度阈值 | 0.72–0.80 | 过滤低匹配度的非相关工装文档，保留与当前工艺需求高度匹配的定位方案 |
| 重排 | 开启，取前3条 | 对召回结果重新排序，修正向量编码中可能出现的公差参数匹配偏差 |

## 容易做错的三处
- 现象：Embedding模型连接OneAPI时返回身份验证失败或连接超时报错。原因：未正确配置OneAPI的接入端点与密钥，或向量模型的调用格式与OneAPI要求的参数不匹配。
- 现象：开启Rerank模型配置后，在线召回测试未返回重排后的结果。原因：未在索引环节绑定对应的Rerank模型，或召回前置条数设置少于重排所需的最小数量。
- 现象：尝试接入通义多模态向量模型时无法正常调用。原因：未在系统中添加自定义多模态向量模型的适配逻辑，未正确映射模型的输入输出格式。

## 怎么确认配好了
- 进入向量模型管理页面，验证已配置的Embedding模型、Rerank模型的连通性测试返回成功。
- 执行单份夹具图文档的索引测试，查看分块后的内容与原文档的关键信息匹配度符合预期。
- 发起在线召回测试，输入定位基准相关的查询词，确认返回结果包含重排后的排序变化。
- 查看索引日志，确认增量更新仅处理了新增的校准记录与变更履历，未重复索引历史数据。
