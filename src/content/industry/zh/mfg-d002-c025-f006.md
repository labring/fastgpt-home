# 工装夹具与检具制造的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
该品类的核心文档包括工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历。数据来源涵盖产品数模与GD&T、工艺路线、三坐标测量数据、现场试用反馈、计量系统。更新按单个项目推进，伴随产品变更触发更新，定期执行校准记录更新。文档字段包含定位基准坐标、GD&T公差值、三坐标测量结果、计量设备编号、变更版本号等，部分图纸类文档附带装配尺寸链参数。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的文档与具体项目、产品变更强绑定，溯源需精准匹配项目ID与版本信息，避免跨项目引用混淆。多源数据包含专业公差、坐标等结构化字段，检索需匹配专业术语，无法依赖泛化关键词筛选。高频更新的校准记录与变更履历要求溯源关联最新版本数据，否则会导致工艺文件与实际生产状态不符。单份文档的专业参数密度较高，需保证引用上下文覆盖核心校验字段，避免溯源失效。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 工装夹具与检具的文档包含大量结构化参数，该取值可覆盖核心校验字段的上下文 |
| `responseData` | 返回文件名、变更版本号、计量设备编号 | 该品类溯源需关联变更履历与校准记录，明确的元数据可快速定位有效来源 |
| `detail` | 包含定位基准坐标、GD&T公差字段 | 该品类工艺文件的核心校验依赖专业参数，需确保引用内容覆盖关键字段 |
| 单次搜索上限 | 前6条 | 单项目下的关联文档数量适中，过多条目会干扰核心引用的关联性判断 |
| 上下文窗口 | 按实测标定 | 不同项目的文档长度差异较大，需结合实际文档体量调整窗口大小 |

## 容易做错的三处
- 现象：返回的引用文档数量超出预期，界面显示冗余。原因：未设置单次搜索上限，未按项目ID过滤检索范围，导致跨项目文档被错误引用。
- 现象：返回的引用未匹配当前项目的最新变更履历。原因：未开启版本匹配的检索配置，未关联项目ID进行检索，导致引用旧版文档。
- 现象：调用API返回的引用文件名字段为空。原因：未开启`responseData`的文件名返回开关，或未正确映射文档库的文件名元数据字段。

## 怎么确认配好了
- 发起工装工艺文件起草的测试请求，检查返回的引用列表中是否包含当前项目对应的夹具图、检具操作书与校准记录。
- 调用FastGPT v4.17.0的API接口，查看返回结果中是否包含`responseData`字段下的文件名、变更版本号等元数据。
- 调整`quoteMaxToken`参数至600 token与1400 token，验证返回的引用上下文是否覆盖GD&T公差、三坐标测量结果等核心字段。
- 模拟异常报告起草请求，检查引用是否自动关联了最近的变更履历与校准记录。
