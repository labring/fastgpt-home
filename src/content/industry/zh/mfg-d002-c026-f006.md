# 有色金属冶炼与电解的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
该品类的典型业务主体为铜、铝、铅锌等冶炼企业的熔炼、电解、化验与调度部门，日常生成的文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账。数据来源覆盖精矿与辅料分析、DCS系统、槽电压电流监测、化验室检测、能源与环保监测等渠道，更新频率按每批原料、每炉或每槽、实时不等。文档字段包含原料成分占比、设备运行参数、化验结果数值、批次编号、时间戳等，单位随对应数据类型匹配。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据多源且更新节奏差异大，要求溯源时必须精准匹配批次号、炉槽号、时间戳等核心关联标识，避免跨批次或跨设备的数据混淆。多类文档的字段格式存在差异，需针对不同数据源的文档结构配置对应匹配规则，确保引用的原始数据与当前起草的工艺文件或异常报告对应一致。实时性较强的槽电压电流等数据，要求溯源链路能快速获取最新版本的监测记录，保障异常排查时的数据时效性。同时，该品类工艺与异常关联的业务逻辑复杂，溯源需覆盖从原料到成品的全流程数据节点，为工艺调整或异常追责提供完整依据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 知识库关联数据源 | 绑定精矿分析、DCS运行、化验报告、环保监测四类数据源 | 覆盖该品类核心业务文档与数据来源 |
| `quoteMaxToken` | 800–1200 token | 适配冶炼行业单批次工艺文档的长度，避免截断关键参数 |
| 单次召回条数 | 前6条 | 匹配单批次工艺相关的多类文档数量，兼顾召回全面性与上下文长度 |
| 溯源字段匹配规则 | 按批次号、炉槽号、时间戳关联匹配 | 该品类数据以批次、炉槽、时间为核心关联标识 |
| `responseData` | 返回完整来源元数据 | 满足异常报告起草时需溯源原始数据的要求 |
| `detail` | 开启全链路溯源 | 便于排查工艺异常时追溯从原料到成品的全流程数据 |

## 容易做错的三处
- 现象：查看聊天回答的知识库引用时出现报错。原因：未配置数据源与知识库的字段关联规则，导致溯源时无法匹配到对应数据条目。
- 现象：知识库搜索卡片中选择知识库后变量引用无法生效。原因：未开启`responseData`参数的元数据返回配置，导致无法提取引用源的变量字段。
- 现象：生成的异常报告中引用的工艺数据与实际批次不符。原因：`quoteMaxToken`取值过小，截断了批次号等核心关联字段，导致溯源时匹配错误。

## 怎么确认配好了
- 导入单批次的配料单、熔炼记录等测试文档，发起工艺文件起草请求，检查返回结果中是否包含完整的来源元数据。
- 模拟异常场景输入槽电压异常的问题，核对引用的溯源数据是否关联到对应炉槽的实时运行记录。
- 调整`quoteMaxToken`的取值，验证不同长度的文档是否能被完整引用且无截断。
- 检查配置的数据源是否覆盖了精矿分析、DCS运行、化验报告、环保监测四类核心数据来源。
