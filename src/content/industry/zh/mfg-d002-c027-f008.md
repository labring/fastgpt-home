# 服装裁剪与缝制的工艺文件与异常报告起草：文档解析与分块

## 这个品类的数据长什么样
该品类的日常文档通常包含工艺单、排料图、裁剪单、工序质量表、包装配码单等，数据来自订单尺码表、CAD样板、吊挂系统、验针机及客户封样。文档按订单、款式、批次更新，每份文档包含裁片规格、面料方向、工序要求、异常记录等字段，单位多为厘米、件数、批次号，且裁片数据不可逆，无重复复用空间。

## 这些特征在「文档解析与分块」这一环带来什么约束
款式多、季节性强导致单批次文档量小但总存量大，分块需按订单批次隔离，避免跨批次数据混淆。裁片数据不可逆，解析时需保留原始字段关联，不能随意合并或截断关键信息。高频更新要求分块支持增量解析，仅处理新增或修改的文档。多样的文档格式（CAD图、工序表格、异常报告文本）需适配不同解析规则，确保裁片规格、面料方向等核心字段完整提取。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配服装工艺文档的单工序描述长度，避免拆分破坏工序关联 |
| `chunkSplitter` | 按段落+自定义分隔符 | 支持按工艺步骤、异常记录类型拆分，保留文档逻辑结构 |
| `customPdfParse` | 启用 | 适配CAD导出的PDF工艺单，保留矢量图文本层的字段提取 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 处理大型排料图PDF时预留足够解析时间，避免超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 容纳单批次多份工艺文档的打包上传，适配批量订单场景 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（裁剪单/异常报告）调整分块规则，满足细分需求 |

## 容易做错的三处
- 现象：分块总数超过3000后出现索引异常。原因：未按订单批次拆分文档，导致单知识库内跨批次分块过多，超出系统默认块数限制。
- 现象：升级版本后CSV文件分块报错。原因：未适配新版解析规则对CSV字段分隔符的校验，原有文件的分隔符配置未同步更新。
- 现象：上传的排料图无法解析出裁片数量。原因：未启用`customPdfParse`配置，导致CAD导出的PDF文档无法正确提取矢量文本层的核心字段。

## 怎么确认配好了
- 上传单份工艺单PDF，查看分块预览，确认裁片规格、面料方向等核心字段未被拆分截断。
- 上传批量打包文档，检查上传文件大小未超过`UPLOAD_FILE_MAX_SIZE`设定值，无上传失败提示。
- 触发增量解析任务，确认仅新增或修改的文档被处理，无重复分块记录。
- 测试异常报告CSV文件，确认分块后保留异常类型、工序编号等字段的完整关联。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
