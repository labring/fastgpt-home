# 来料检验与供应商质量的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来源包括采购订单、图纸规格、供应商质保书、检验设备输出、历史质量记录、供应商门户信息。更新节奏随每批来料、月度/季度供应商评价、不定期审核调整。日常文档涵盖检验规范、抽样方案、来料检验报告、供应商审核报告、异常联络单、8D整改报告、让步接收审批单。数据字段包含批次编号、检验项、不合格项描述、供应商资质编号、整改验证记录，沿用业务固有字段标识，无额外自定义单位，字段命名贴合制造业质量管控的通用规范。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类数据来源分散且格式各异，需精准匹配批次与版本信息，避免引用过期的检验规范或非对应批次的来料数据。高更新频率要求知识库实时同步最新供应商质保书、月度评价记录与临时异常整改数据，否则溯源结果无法匹配当前业务场景。文档包含多层级审批与整改验证环节，需准确关联异常报告与对应整改闭环记录，确保溯源时覆盖完整业务流程。同时需区分历史质量数据与当前批次的关联关系，避免混淆不同供应商的资质与检验结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 前1200–1500 字符 | 适配本品类多字段的文档长度，避免截断关键批次与整改信息 |
| `quoteMaxToken` | 800–1000 token | 控制引用内容的输出长度，确保异常报告起草时可完整展示检验依据 |
| `responseData` | 包含引用来源ID与文档标题 | 匹配业务溯源需求，便于关联异常报告与对应检验规范或来料报告 |
| `detail` | 开启 | 展示引用文档的完整字段信息，如供应商编号、批次号等，满足溯源精度要求 |
| 单次搜索上限 | 前6 条 | 覆盖多来源的检验数据，避免遗漏关键供应商资质或历史质量记录 |
| 知识库同步周期 | 按实测标定 | 适配本品类的更新节奏，确保知识库数据与业务系统状态一致 |

## 容易做错的三处
- 现象：对话返回的引用仅展示文档标题，未包含对应批次编号或供应商ID。原因：未开启`detail`参数，未配置引用数据的字段展示规则。
- 现象：调用对话接口后无法获取引用来源的知识库ID。原因：未将`responseData`配置为包含引用来源ID的返回格式，导致接口未返回对应字段。
- 现象：引用内容过长导致输出截断，无法完整展示检验规范的抽样方案。原因：`quoteMaxToken`取值过低，未覆盖对应文档的实际长度。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库配置页面，检查引用字段展示相关开关是否开启。
- 发起一次模拟来料异常的对话，查看返回结果中是否包含引用文档的完整字段信息。
- 调用对话接口，验证返回数据中是否包含`responseData`对应的引用来源ID与文档标题。
- 调整`quoteMaxToken`参数后，测试引用内容的输出长度是否符合业务文档的展示需求。
