# 模具设计制造的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
该品类的典型数据来自注塑、冲压、压铸模具企业及制造企业模具中心的全项目流程，包含模具设计任务书、DFM报告、零件图、加工工艺卡、试模报告、改模通知、模具履历等文档。数据来源涵盖客户产品模型、模流或成形仿真文件、CAD/CAM输出文件、机加工与测量数据、试模样件相关记录。数据按单个项目节奏更新，每次试模或改模后都会生成新文档或更新原有记录。单份文档通常包含零件尺寸、材料牌号、加工公差、试模缺陷描述等字段，单位多为毫米、兆帕、小时等工程常用单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的文档类型多样且包含大量工程专用字段，要求索引环节适配CAD格式文本、仿真结果数据等非通用内容结构。按项目更新的数据体量随项目推进逐步累积，单次索引的文档数量波动较大，需要索引流程适配动态数据量。工程字段的单位与专业表述要求向量模型能准确识别专业术语，避免语义混淆。试模与改模的高频更新要求索引支持增量同步，避免全量重建带来的耗时问题。单份文档的长度差异较大，从简短的改模通知到完整的DFM报告均有覆盖，要求分块与索引规则具备灵活性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配模具图纸、工艺卡的单块文本长度，避免专业术语被拆分 |
| 重叠长度 | 50–100 字符 | 保留跨分块的专业表述关联，避免截断改模通知、试模缺陷的完整描述 |
| 相似度阈值 | 0.75–0.85 | 区分工程场景下的近似表述与精准匹配，避免误召回无关模具项目数据 |
| 单次搜索上限 | 前 10 条 | 匹配单项目的关联文档数量，避免加载过多历史记录影响响应速度 |
| `maxToken` | 8000 | 适配DFM报告、完整试模报告的上下文长度，满足长文本解析需求 |
| `defaultToken` | 1024 | 适配通用工程文本的基础嵌入长度，平衡语义精度与计算开销 |

## 容易做错的三处
- 搜索响应超时，单次搜索返回结果条数远低于预期。原因是未针对模具项目的动态数据量调整单次搜索上限，且未启用增量索引，全量检索数十万条模具相关数据导致耗时过长。
- 向量存储结构无法识别CAD格式的零件图元描述。原因是未配置适配工程专用文本的分块规则，导致专业字段被错误拆分，丢失元数据关联。
- 召回结果包含跨项目的无关模具数据。原因是相似度阈值设置过低，将近似的工程术语匹配判定为有效召回，混淆了不同项目的工艺文件。

## 怎么确认配好了
- 导入单份完整试模报告，检查分块后的文本是否保留了缺陷描述与改模要求的完整关联，无明显术语截断。
- 发起针对特定项目改模通知的检索，确认召回结果仅包含该项目的相关文档，无跨项目数据混入。
- 测试多次检索同一专业问题，记录响应时间，调整相关配置直到符合业务场景的耗时要求。
- 验证增量索引功能，新增一份改模通知后，检索结果可及时包含新文档，无需全量重建索引。
