# 模具设计制造的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的日常文档包含模具设计任务书、DFM报告、零件图、加工工艺卡、试模报告、改模通知、模具履历。数据来源包括客户提供的产品模型、模流或成形仿真结果、CAD/CAM文件、机加工与测量数据、试模样件参数。数据更新按单个项目推进，每次试模或改模后都会同步更新相关文档，文档字段通常包含脱模要求、成形精度指标、改模次数等具体参数。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的文档结构固定且数量多，数据来源多样，更新频率随试模、改模实时变化，且包含大量专业工艺参数。这要求多轮对话需按文档类型拆分提示词，分别适配设计任务书、试模报告等不同场景。同时需绑定`variables`关联对应项目的专属数据源，确保调用的是当前项目的最新数据。此外，对话上下文需限制仅保留当前项目的历史记录，避免混入其他项目的旧数据干扰生成结果，提示词还需嵌入模具行业专有术语，保障生成内容符合行业规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口大小 | 前800–1200 字符 | 匹配模具类文档单页的常规篇幅，避免截断关键脱模、精度参数 |
| 历史对话保留上限 | 前3条项目相关对话 | 聚焦当前试模或改模的最新记录，避免冗余历史干扰生成 |
| `variables` 绑定规则 | 绑定当前项目的专属数据源 | 确保生成内容引用对应项目的DFM报告、试模数据等专属信息，符合FastGPT v4.17.0的配置规范 |
| 提示词模板分组 | 按文档类型拆分 | 分别适配工艺文件、异常报告的不同生成需求 |
| 分块检索长度 | 600 字符 | 适配模具工艺卡、零件图说明的常规段落长度，提升检索匹配度 |

## 容易做错的三处
- 现象：配置提示词时嵌入了模具DFM报告的解读内容，调用生成工艺文件时，系统提示未上传文件。原因：仅在提示词文本中写入了文档引用说明，未将对应文档绑定到`variables`参数，系统无法识别关联的数据源。
- 现象：升级后刷新对话页面，当前模具项目的历史对话记录消失，显示为全新对话。原因：未配置`chatId`的持久化存储，会话数据仅保存在本地临时缓存，页面刷新后缓存被清除。
- 现象：在对话过程中尝试切换不同模具项目的知识库，生成内容未匹配对应项目的试模数据。原因：未通过`messages`传递实时切换的知识库标识，系统仍调用默认绑定的知识库。

## 怎么确认配好了
- 发起多轮对话，输入当前模具项目的试模缺陷描述，核对生成的异常报告是否引用了该项目的试模数据。
- 查看配置项中的`variables`绑定，确认已关联当前项目的模具设计任务书、零件图等文档。
- 刷新对话页面，检查历史改模、试模的对话记录是否完整保留。
- 切换不同的文档类型提示词模板，确认生成的工艺文件或异常报告符合对应文档的格式要求。
