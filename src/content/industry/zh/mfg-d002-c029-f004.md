# 模具设计制造的工艺文件与异常报告起草：工作流编排

## 这个品类的数据长什么样
模具设计制造的日常文档包含模具设计任务书、DFM报告、零件图、加工工艺卡、试模报告、改模通知、模具履历。数据来源为客户产品模型、模流或成形仿真、CAD/CAM、机加工与测量数据、试模样件。更新按单个模具项目、每次试模或改模进行，文档包含模具型腔数、材料牌号、硬度要求、试模缺陷类型等专业字段，无通用标准化格式。

## 这些特征在「工作流编排」这一环带来什么约束
模具设计制造的数据来源分散且随项目迭代频繁更新，要求工作流需支持对接多系统数据源并动态触发。专业文档字段多且无统一格式，需通过工作流配置变量存储不同文档的专属字段。单次项目周期内需反复调用试模、改模数据，要求工作流支持历史会话变量复用。同时，模具延期或缺陷会影响量产节点，需在工作流中添加校验环节，避免无效流程启动。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量隔离规则 | 按使用者ID隔离 | 每个模具项目由不同使用者对接，需保证同名变量不跨项目冲突 |
| 历史上下文加载节点 | 关联`variables`参数 | 调用已保存的试模报告、改模通知等历史会话数据 |
| 自定义引导语节点 | 预设模具专业审查话术 | 匹配工艺文件起草、异常报告撰写的场景需求 |
| 工作流触发条件 | 绑定`nodeId`至项目节点 | 仅在收到新的试模或改模数据时启动流程 |
| 超时阈值 | 300–600 秒 | 适配模具数据调取、AI专业分析的耗时节奏 |

## 容易做错的三处
- 调用工作流API时上下文未生效，现象为接口返回结果未携带历史试模数据，原因是未在请求中绑定对应会话的`variables`参数。
- 全局变量作用域混淆，现象为不同使用者的模具项目变量互相覆盖，原因是未配置按使用者ID隔离的规则。
- 自定义引导语未生效，现象为回复仍使用默认猜你想问话术，原因是未在工作流中添加自定义引导语节点。

## 怎么确认配好了
- 发起测试请求，检查返回结果是否包含历史会话中保存的试模缺陷数据。
- 切换不同使用者ID发起请求，确认同名全局变量的取值互不干扰。
- 触发工作流，检查回复前是否出现预设的专业引导话术。
- 查看工作流日志，确认触发条件与绑定`nodeId`的项目节点匹配。
