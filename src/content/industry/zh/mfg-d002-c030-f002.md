# 橡胶混炼与制品硫化的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自配方系统、原材料批次台账、密炼机、门尼粘度仪、硫化机及实验室检测设备。日常文档包含配方单、称量记录、混炼曲线、胶料快检报告、硫化工艺卡、模具使用记录、成品性能报告。数据更新频率为每车原材料的批次、每批胶料、每模次硫化作业。文档字段包含混炼温度、硫化时长、胶料门尼粘度、成品拉伸强度等，附带℃、分钟、MU、MPa等专业工业单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据更新频率高且覆盖多类型工业文档，要求索引支持高频增量同步，避免生产数据滞后导致异常报告起草出现偏差。文档包含带专业单位的数值型字段与工艺描述文本，向量模型需适配橡胶工业专属术语与单位体系，确保语义编码准确，避免参数匹配偏差。单条数据体量小但总数据量随生产节奏增长，索引分片需适配小批量高频写入的场景，防止写入阻塞。同时异常报告关联多维度生产数据，索引需支持跨文档关联召回，保障工艺异常溯源的准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配本品类单份工艺文档的平均长度，避免分块破坏专业术语与参数的完整性 |
| 重叠长度 | 100–150 字符 | 覆盖跨分块的混炼与硫化衔接逻辑，防止分块后丢失关键生产关联信息 |
| 相似度阈值 | 0.75–0.85 | 匹配工业工艺参数的语义相似度要求，过滤低相关性的异常报告与工艺文件 |
| `maxToken` | 4096 token | 适配本品类批量工艺数据的向量编码长度，避免截断关键参数与描述内容 |
| 单次搜索上限 | 前 8 条 | 平衡召回效率与异常溯源的信息完整性，覆盖多维度生产关联数据 |
| `defaultToken` | 按实测标定 | 适配宿主机8c16G无GPU的硬件配置，保障向量模型加载与编码的稳定运行 |

## 容易做错的三处
- 现象：PG数据库部署的知识库索引始终无法建立，界面显示索引状态为失败。原因：未配置适配小批量高频写入的索引分片策略，且宿主机8c16G无GPU资源，向量模型加载超时。
- 现象：使用外部Embedding模型调用报错，无法生成向量。原因：未单独配置专属索引模型，依赖通用模型无法适配橡胶工业专业术语的语义编码。
- 现象：docker-compose启动后配置环境变量未生效，索引创建无响应。原因：未重建容器加载新的配置文件，直接修改配置未触发容器更新。

## 怎么确认配好了
- 上传一份本品类的典型文档（如硫化工艺卡），检查分块后的内容是否保留完整的专业字段与单位信息。
- 发起基于异常工艺参数的查询，核对召回结果的关联维度是否覆盖混炼、硫化、成品检测的全流程数据。
- 查看部署容器的运行日志，确认向量模型加载与索引写入未出现内存或超时类报错。
- 上传一份新增的生产批次数据，验证索引同步完成的时间是否匹配本品类的更新节奏。
