# 水泥熟料与粉磨的工艺文件与异常报告起草：工具调用与插件

## 这个品类的数据长什么样
日常文档包含生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录、能源报表。数据来自在线成分分析系统、DCS控制系统、化验室数据、窑磨设备传感器、原燃料台账、能源计量仪表。更新节奏分为实时（设备状态、成分数据）、每班（巡检记录、操作记录）、每日（质量控制通知单、能源报表）。文档字段包含物料配比、温度参数、强度指标、能耗数值，单位涉及百分比、摄氏度、兆焦、兆帕等。

## 这些特征在「工具调用与插件」这一环带来什么约束
实时数据的调取需求要求工具调用响应需控制在合理时长内，否则无法支撑异常报告的即时起草；多来源的异构数据需通过插件完成格式统一，避免字段不匹配导致生成的工艺文件与异常报告逻辑混乱；每班、每日的批量文档需配置批量处理插件，减少手动整理的耗时；不同文档类型的专属字段（如生料配料方案的配比项、窑操作记录的温度参数）需在工具调用时明确提取规则，否则生成内容无法匹配业务场景。此外，水泥熟料与粉磨的热工稳定要求，工具调用需优先调取窑磨设备的实时核心数据，确保报告的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多类型文档的自动工具调用需求，覆盖配料、巡检、化验等多场景数据提取 |
| 批量处理上限 | 每班100份文档 | 匹配每班生成的巡检、操作记录文档数量，避免单次调用过载 |
| 字段映射规则 | 按文档类型预设 | 对应生料配料方案的配比项、窑操作记录的温度参数等专属字段 |
| 工具调用超时时间 | 300 秒 | 适配DCS系统数据调取的常规响应时长，避免因实时数据未返回导致生成失败 |
| 异常触发阈值 | 设备温度偏差±50摄氏度 | 匹配回转窑热工稳定的行业常规阈值，自动生成异常报告 |
| FastGPT版本 | v4.17.0 | 适配当前稳定版的插件调用逻辑，确保功能正常运行 |

## 容易做错的三处
- 现象：工具调用时持续返回slow operation日志，mongodb响应延迟。原因：未设置适配实时DCS数据调取的超时时间，导致工具调用等待超时。
- 现象：配置deepseek-r1进行工具调用后生成结果偏差大。原因：未预设水泥熟料与粉磨专属的字段映射规则，导致提取的配比、温度等数据不符合业务逻辑。
- 现象：全局计数器插件无法实现自增。原因：未在插件配置中绑定对应业务场景的触发条件，仅配置了基础变量更新逻辑。

## 怎么确认配好了
- 上传一份生料配料方案文档，触发工具调用，核对提取的配比字段是否与原文档一致。
- 模拟设备温度偏差超出阈值的场景，检查是否自动触发异常报告起草流程。
- 查看工具调用日志，确认超时时间设置符合业务响应需求，无频繁超时报错。
- 测试批量处理功能，上传每班生成的文档，确认插件能正常完成格式转换与数据整合。
