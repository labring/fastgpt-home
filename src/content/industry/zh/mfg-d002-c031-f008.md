# 水泥熟料与粉磨的工艺文件与异常报告起草：文档解析与分块

## 这个品类的数据长什么样
这个品类的数据来自在线成分分析系统、DCS控制系统、化验室检测设备、窑磨运行设备、原燃料台账及能源计量装置。日常文档包括生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录与能源报表。数据更新节奏分为实时、每班及每日，文档结构多包含固定格式的参数项与检测结果，字段涉及原料配比参数、烧成温度、粉磨细度、能耗数值及质量检测结果，单位涵盖摄氏度、千克、立方米、兆焦等。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的数据特征对文档解析与分块带来三点约束：其一，数据更新节奏覆盖实时、每班、每日三类，实时工况文档与周期报表需适配不同的分块粒度阈值；其二，文档包含多维度字段，如生料配料的原料参数、窑操作的热工数据、化验报告的检测结果，需避免跨业务板块的内容被错误拼接；其三，工艺文档与异常报告存在强关联，异常报告需关联对应时段的操作记录，分块需保留文档间的上下文关联，防止关键关联信息被拆分。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配该品类文档中多字段组合的语义长度，避免单块包含跨业务板块内容 |
| `chunkSplitter` | 按段落+固定字段拆分 | 匹配生料配料方案、化验报告等固定格式文档的结构，提升分块语义完整性 |
| `customPdfParse` | 启用 | 适配FastGPT v4.17.0版本的PDF解析引擎，确保水泥熟料相关文档的复杂排版被正确识别 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 覆盖大体积窑操作记录、批量能源报表的解析耗时，防止解析中途超时 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配单班次窑操作记录汇总文件的大小需求 |
| `chunkSettingMode` | 按文档类型自定义 | 区分实时工况文档与周期报表的分块规则，适配不同更新节奏的数据处理 |

## 容易做错的三处
- 现象：PDF解析任务返回报错日志，状态码显示解析引擎异常。原因：未启用`customPdfParse`配置，或未指定适配水泥熟料文档的PDF解析规则，导致复杂排版的化验报告、配料方案无法被正确提取字段，触发解析报错。
- 现象：在节点中调用上传的文件时，大模型返回的内容与原始文档不符，存在大量冗余或缺失字段。原因：未跳过默认的文本解析流程，直接将原始文件传递给大模型，未完成适配品类文档的解析与分块。
- 现象：通过API创建文件集合时，无法触发PDF专属解析流程。原因：未在请求参数中正确配置`customPdfParse`参数，导致系统使用通用解析逻辑处理水泥熟料相关的PDF文档。

## 怎么确认配好了
- 上传一份典型的生料配料方案PDF，查看解析后的文本是否完整提取了原料配比、烧成温度等核心字段，确认解析结果符合预期。
- 在节点中调用解析后的文件，检查分块后的内容是否按业务板块拆分，未出现跨配料、热工、质量环节的内容拼接。
- 提交大体积的窑操作记录文件，查看解析任务的耗时是否在预设的`PARSE_FILE_TIMEOUT_SECONDS`范围内，未出现超时报错。
- 调用知识库文件集合创建API，检查返回结果中是否包含正确的解析配置标识，确认解析规则已正确应用。
