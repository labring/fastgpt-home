# 汽车整车总装的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据以单台车辆VIN为核心主线，来源涵盖ERP/MES系统、VIN与配置系统、拧紧工具、EOL下线检测线及质量追溯系统。日常文档包含生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录与一致性放行文件。数据按每车、实时、每班的频率更新，字段包含VIN码、扭矩值、检测项编号、供应商批次号，单位涉及牛米、百分比、工位编号等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
以VIN为核心的单车主线特征，要求多轮对话必须绑定对应VIN的上下文，避免跨车辆配置混淆。实时更新的拧紧数据与下线检测数据，要求对话环节支持快速拉取最新的单车辆数据，避免使用过期信息。每班更新的班组与工位配置，要求提示词需适配当日的生产排班与工位权限。混线生产的高配置复杂度，要求多轮对话需逐步澄清装配要求，防止错配漏装。异常报告起草需关联对应VIN的返修记录与历史检测数据，确保追溯逻辑完整。

## 配置怎么定
本页配置基于FastGPT v4.17.0。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前VIN的会话ID | 确保多轮对话始终关联对应车辆的专属数据，避免上下文混淆 |
| `messages` | 保留最近20轮对话内容 | 覆盖单台车辆从装配到异常处理的完整流程，避免丢失关键配置信息 |
| `variables` | 注入当前VIN、工位编号、当日生产班次 | 让提示词能直接调用当前生产场景的专属参数，无需重复询问 |
| 最大上下文长度 | 8000–12000 token | 容纳单台车辆的多份装配文档与检测数据，满足复杂场景的对话需求 |
| 对话超时时间 | 600秒 | 处理跨工位的异常数据查询与文档拼接，避免因数据量较大导致超时 |
| 附件上传限制 | 单文件不超过50 MB，支持PDF、CSV格式 | 适配装配作业指导书、拧紧数据报表等常见文档的大小与格式 |

## 容易做错的三处
- 现象：对话记录无法导出，或导出后缺失VIN关联信息。原因：未在`variables`中绑定当前VIN参数，导致对话上下文未关联专属车辆数据，导出时无法匹配对应文档。
- 现象：上传的装配作业指导书无法被对话识别。原因：未设置适配PDF、CSV格式的附件上传限制，或未开启附件解析开关。
- 现象：调用知识库时返回无关车辆的配置数据。原因：未通过`messages`传递当前对话的VIN上下文，导致知识库召回未按车辆维度过滤。

## 怎么确认配好了
- 发起绑定已知VIN的对话，检查对话过程中是否自动带出对应车辆的配置信息，确认参数注入生效。
- 上传一份标准的拧紧数据CSV文件，验证对话能否正常解析并引用其中的扭矩数据，确认附件上传与解析配置正确。
- 发起多轮对话，连续发送20条以上的交互内容，检查对话上下文未出现丢失或混淆，确认上下文保留规则生效。
- 尝试导出对话记录，检查导出文件中包含当前VIN与关联的生产数据，确认会话关联逻辑正确。
