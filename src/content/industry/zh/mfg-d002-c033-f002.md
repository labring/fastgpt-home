# 汽车零部件批量制造的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自汽车制动、转向、底盘、内外饰及动力系统零部件供应商的业务文档，包括控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料及8D报告。数据来源涵盖客户图纸与特殊特性清单、ERP/MES系统、量检具数据、设备过程参数及供应商质保书，更新节奏为每批生产、每班作业及持续实时采集，文档包含固定业务字段与动态参数，部分需匹配客户指定格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源需要向量模型同时适配结构化参数与非结构化文本的语义编码；高频更新节奏要求索引支持增量写入与定时刷新，避免数据滞后；文档需匹配客户特定格式的要求，需要在向量索引中保留字段级关联，防止丢失特殊特性等关键业务标识；异常报告类文档存在长文本片段，需要模型支持足够的输入长度以完整编码根因分析内容。结合FastGPT v4.17.0的本地化部署环境，还需适配硬件资源限制，平衡编码精度与计算开销。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配作业指导书、8D报告等长文档的语义完整性，避免跨块截断关键工艺步骤 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的上下文关联，防止工艺参数、异常原因被分块割裂 |
| `maxToken` | 4096 token | 适配PPAP资料、完整SPC报表的长文本编码，符合FastGPT v4.17.0的本地化模型支持范围 |
| `defaultToken` | 512 token | 用于首件巡检记录、简短异常描述的高效编码，平衡计算资源与语义精度 |
| 单次搜索上限 | 前10条 | 匹配批量制造场景下的高频异常检索需求，避免冗余结果干扰根因分析 |
| 重排 | 开启 | 对检索到的工艺文档进行语义重排序，适配客户特殊特性的精准匹配要求 |

## 容易做错的三处
- 现象：切换向量数据库后检索报错，返回维度不匹配提示。原因：未统一向量维度参数，原有索引与新数据库的嵌入维度不一致，未适配批量文档的统一编码要求。
- 现象：本地化向量模型加载失败，出现显存不足报错。原因：未选择轻量化适配NVIDIA 1080ti硬件的模型，且未合理分配系统显存，结合WSL部署环境，未正确映射GPU资源。
- 现象：检索结果无法匹配客户指定的特殊特性字段。原因：分块时未保留特殊特性的固定字段关联，导致向量索引丢失关键业务标识，无法精准匹配检索请求。

## 怎么确认配好了
- 上传单份完整的8D报告，检查分块后的文本片段是否保留完整的根因分析与遏制措施段落，无关键内容截断。
- 提交包含客户特殊特性的检索请求，核对返回结果的排序是否优先匹配目标特性字段。
- 批量上传10份当日生成的巡检记录，检查索引更新任务是否在预设时间内完成，无超时报错。
- 查看向量嵌入日志，确认`defaultToken`与`maxToken`参数已按配置生效，无参数冲突提示。
