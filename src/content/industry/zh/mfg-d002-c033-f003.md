# 汽车零部件批量制造的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的核心数据来自客户图纸、特殊特性清单、ERP/MES系统、量检具读数、设备过程参数及供应商质保书。日常生成的文档包含控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料及8D报告，各文档有固定字段与单位，如尺寸用毫米、扭矩用牛米、批量数用件。数据更新频率为每批、每班或持续采集，核心特殊特性需随产线实时同步。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新节奏差异大，要求多轮对话需按环节逐步调取对应数据源的内容，避免一次性加载过多冗余数据。文档结构复杂且有强制格式要求，提示词需明确指定提取各文档的必填字段，确保生成的工艺文件与异常报告符合整车客户的质量体系规范。批量制造的一致性要求，需在对话中校验数据的匹配性，如SPC报表的异常点与巡检记录的对应关系。实时采集的设备参数需在对话中即时调用，确保起草的文件与当前产线状态一致。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前产线的专属会话ID | 该品类按产线批量生产，绑定专属会话ID可隔离不同产线的对话数据与生成文档 |
| `variables` | 包含客户特殊特性、当日设备参数、巡检记录的变量组 | 该品类的工艺文件与异常报告需绑定实时生产数据，通过变量调用可确保内容准确 |
| `messages` | 保留前10轮对话上下文，过滤系统提示中的冗余说明 | 批量制造的异常追溯通常不超过10轮对话，过多上下文会干扰专业术语的准确识别 |
| 最大上下文长度 | 8000–12000 字符 | 该品类的文档包含多页控制计划与SPC报表，需足够上下文整合跨文档信息，按实测标定调整 |
| 问题优化开关 | 开启 | 汽车零部件制造的专业术语较多，优化后的提示词可准确识别特殊特性标识，避免生成不符合质量要求的内容 |
| 对话超时时间 | 60 秒 | 产线异常需快速响应，超时会影响车间处理效率，符合该品类的实时性要求 |

## 容易做错的三处
- 现象：调试预览能正常显示LaTeX格式的公差标注，发布后仅显示原始代码格式。原因：未在发布环境配置LaTeX渲染支持，仅本地调试环境默认开启了格式渲染。
- 现象：Workflow中插入的AI对话节点结果被自动包含在最终输出内容中。原因：未关闭该节点的输出传递开关，导致中间步骤的对话内容被带入最终生成的报告。
- 现象：部署后对话一直卡在加载状态，无响应内容。原因：未正确配置数据源的访问权限，导致对话调用ERP/MES或量检具数据时超时无反馈。

## 怎么确认配好了
- 上传一份典型的客户特殊特性清单，发起起草控制计划的对话，核对生成的文档是否包含清单中的关键特性字段与对应单位。
- 模拟一次异常上报的多轮对话，检查生成的8D报告是否包含必填的问题描述、根因分析、遏制措施等内容，符合该品类的文档格式要求。
- 测试LaTeX格式的尺寸标注在发布后的对话框中正常显示，无原始代码残留。
- 验证多轮对话回溯功能，确认能调取前几轮的异常记录与设备参数，生成连贯的分析内容。
