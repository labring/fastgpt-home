# 汽车零部件批量制造的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
本品类主体为汽车制动、转向、底盘、内外饰及动力系统零部件供应商，日常生成的文档包含控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料、8D报告。数据来源覆盖客户图纸与特殊特性清单、ERP/MES系统、量检具数据、设备过程参数及供应商质保书，更新节奏为按生产批次、每班频次持续采集，文档结构多包含工序参数、质量阈值、异常判定标准等字段。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的数据来源分散且更新频繁，引用溯源环节需精准关联生产批次对应的原始单据，避免跨批次数据混淆。受整车客户质量体系约束，溯源结果需明确对应客户特殊特性清单中的要求，无法仅依赖通用字段匹配。同时，异常报告起草需关联设备过程参数、量检具记录等实时采集数据，要求溯源链路覆盖从原始采集到文档生成的全流程，确保异常判定的依据可追溯。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1000–1500 token | 适配汽车零部件单条异常记录或工序参数的文档长度，避免上下文溢出 |
| `responseData` | 开启 | 需返回引用来源的原始数据标记，满足溯源要求 |
| `detail` | 完整 | 展示原始文档的完整字段，包括客户特殊特性、设备参数等核心内容 |
| 原文件关联设置 | 保留导入前原文件副本 | 支持直接查看导入知识库前的原始文档详情 |
| 批次关联匹配 | 按生产批次过滤 | 匹配本品类按批次更新数据的特征，避免跨批次数据混淆 |
| 上下文缓存时长 | 3600–7200 秒 | 适配每班更新的数据缓存需求，确保引用数据的时效性 |

## 容易做错的三处
- 触发文档生成请求后无法查看引用片段对应的原文件详情，界面仅显示片段摘要。原因是未开启原文件关联存储设置，未保留导入知识库前的原始文档副本。
- 调用流程时返回一串红色数字报错。原因是`quoteMaxToken`取值超出系统允许的上限，或批次过滤规则与数据更新节奏不匹配，导致上下文长度异常。
- 无法确认输出内容的知识库来源，响应结果未附带任何文档标识。原因是未开启`detail`配置项，未在响应中嵌入来源文档的关键标识字段。

## 怎么确认配好了
- 触发工艺文件起草或异常报告生成请求，检查响应结果中是否包含引用来源的文档标识字段。
- 点击响应中的引用链接，确认可跳转查看导入知识库前的原始文档内容。
- 调整`quoteMaxToken`的取值，验证上下文长度是否符合配置的区间范围。
- 模拟异常场景生成报告，确认溯源结果关联了对应生产批次的原始数据。
