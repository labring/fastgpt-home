# 汽车零部件批量制造的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来自客户图纸与特殊特性清单、ERP/MES系统、量检具、设备过程参数采集端及供应商质保书。日常生成的文档包含控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料与8D报告。数据更新节奏为每批生产、每班巡检及持续采集设备参数，文档字段包含批次号、特殊特性参数、设备运行读数、缺陷记录等，部分字段带有扭矩、压力、批次数量等专属单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新节奏差异明显，要求模型接入环节支持多源异构数据的统一适配与实时同步。日常文档类型多样且字段固定，需预设对应文档的结构化提取规则，确保生成内容符合质量体系要求。批量生产场景下数据量随批次动态增长，需配置适配批量调用的参数阈值，避免处理超时或内容截断。受整车客户强约束，生成的文件需严格匹配预设字段与格式，不能偏离既定规范。本配置适配FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 该品类单批次生产的多源数据量较大，需容纳完整的过程参数、巡检记录与历史文档 |
| `maxTokens` | `4000–6000 token` | 单份工艺文件或异常报告的生成内容需符合固定格式，避免关键信息被截断 |
| `temperature` | `0.1–0.3` | 需保持生成内容的严谨性，严格匹配质量体系要求的字段与格式 |
| `toolChoice` | `auto` | 自动适配多源数据的调用与格式校验，无需手动配置复杂的工具路由 |
| `AIPROXY_API_ENDPOINT` | 按接入模型的官方接口地址填写 | 确保模型请求的正确路由，避免连接失败 |
| `AIPROXY_API_TOKEN` | 按平台分配的密钥填写 | 完成模型接入的身份验证，保障请求合法性 |

## 容易做错的三处
- 批量执行节点在线调试可完成全流程，但通过API调用时无法完整执行。原因是未配置`maxContext`或`maxTokens`的合理阈值，批量调用时上下文溢出或内容截断，导致节点执行中断。
- ollama视觉模型接入后无法正常解析图像类异常数据。原因是未开启`vision`配置项，或未将`AIPROXY_API_ENDPOINT`指向视觉模型的专属接口地址。
- 生成的工艺文件与异常报告中无tokens消耗统计数据。原因是未启用平台内置的tokens统计模块，或未正确关联模型调用的日志记录。

## 怎么确认配好了
- 调用测试接口发起单批次数据的模型调用，确认返回结果包含预设的所有文档字段与格式。
- 查看模型调用日志，确认`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置与接入模型的要求一致。
- 触发批量调用任务，检查节点执行状态与返回结果的完整性，调整`maxContext`或`maxTokens`的取值至符合当前数据量的范围。
- 验证异常报告生成流程，确认生成内容符合整车客户质量体系的固定格式要求。
