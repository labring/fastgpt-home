# 烘焙与方便食品的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自面包糕点、饼干、方便面与速冻面点工厂的多类业务文档，包括配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量设备、烤炉/油炸线、实验室与食品追溯台账，更新节奏按每批生产、每班作业、每日汇总推进。文档字段包含过敏原标识、投料重量、烘烤温度与时长、清洁批次等，部分文档含标准化数值与非结构化文本内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类多源、高频更新的业务数据，要求向量索引支持按生产批次、产品线进行增量更新，避免全量重建耗时过长。带标准化数值的烘烤/蒸煮曲线、投料单等文档，需要向量模型兼顾结构化数值与非结构化文本的编码一致性，避免同类数据向量偏差过大。频繁的产品换线带来的文档分类切换，要求索引的召回逻辑适配不同产品线的专属字段，同时过敏原、异物控制等高风险字段需配置更高的检索优先级，保障异常报告起草的准确性，向量模型的`maxToken`参数需适配多文档拼接的需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxToken` | 6000 token | 适配FastGPT v4.17.0的接口限制，承载多份生产记录与配方的向量拼接 |
| 分块长度 | 800–1200 字符 | 适配本品类配方、生产记录的文本长度，避免单块包含跨批次的无关内容 |
| 重叠长度 | 100–150 字符 | 保留生产曲线、投料单的上下文关联，防止分块截断关键数值 |
| 相似度阈值 | 0.75–0.85 | 匹配过敏原标识、烘烤参数等高敏感字段的检索精度，兼顾召回率与准确率 |
| 单次搜索上限 | 前 8 条 | 覆盖单批次生产的关联文档数量，避免冗余结果干扰异常报告起草 |
| `defaultToken` | 200 token | 优化单块文本的向量编码效率，适配本品类文档的平均长度 |

## 容易做错的三处
- 现象：混合检索耗时超过10秒，单次检索响应延迟明显。原因：未针对本品类高频更新的多源数据配置增量索引，全量检索时加载了过多过期的历史文档。
- 现象：系统停留在最后一组索引的创建步骤，长时间无进度更新。原因：未按生产批次拆分索引分组，单批次数据量过大导致索引构建阻塞，未启用分片索引功能。
- 现象：部分文档无法正常向量化，知识库中出现空字段或报错提示。原因：未确认支持的文件类型包含配方PDF、生产记录Excel、烘烤曲线CSV等本品类核心文档，直接上传了未转换格式的原始数据。

## 怎么确认配好了
- 发起针对过敏原标识的检索，核对返回结果的排序优先级是否匹配业务风险等级。
- 上传单批次的生产记录与配方文档，查看索引创建进度是否无卡顿，未停留在某一阶段。
- 分别发起纯向量检索与混合检索，确认响应时长符合当前业务的使用需求。
- 核对知识库支持的文件类型列表，确认包含PDF、Excel、CSV等本品类核心文档格式。
