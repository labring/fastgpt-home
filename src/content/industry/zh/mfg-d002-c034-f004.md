# 烘焙与方便食品的工艺文件与异常报告起草：工作流编排

## 这个品类的数据长什么样
该品类的核心文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源包括原辅料合格证明、ERP/MES系统、称量系统、生产设备、实验室检测结果与食品追溯台账。更新频率按生产批次、班次或每日执行，字段涵盖物料名称、投料量、工艺参数、检测结果、批次号等，单位涉及重量、温度、时间、保质期时长等。

## 这些特征在「工作流编排」这一环带来什么约束
品类换线频繁且配方多样，要求工作流能快速切换不同产品的数据源；多源数据更新节奏不一，需配置按批次触发的节点调度；过敏原与异物控制的严格性，要求工作流嵌入多文档交叉校验环节；直接食用的属性放大错误后果，需在异常报告起草环节自动关联历史检测数据。文档字段的单位差异，要求工作流支持单位标准化转换，避免校验失败。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按生产批次映射字段 | 适配该品类多源数据的字段差异，确保参数与实际生产数据对齐 |
| `nodeId` | 绑定初始化触发节点 | 实现会话自动启动的逻辑，无需用户手动触发 |
| 单次搜索上限 | 前 10 条 | 匹配多文档交叉校验的需求，避免冗余数据占用token |
| 最大上下文 | 3000–4000 token | 适配配方、检测报告等多文档合并后的内容体量 |
| 超时设置 | 600 秒 | 避免多源数据调取时的等待超时 |
| 引用上限 | 8 条 | 控制异常报告起草的信息密度，符合阅读与排版要求 |

## 容易做错的三处
- 现象：导出工作流时无法生成JSON格式文件。原因：未开启工作流导出的JSON权限开关，或节点配置存在未保存的无效参数。
- 现象：知识库搜索返回结果超过设定的引用上限，导致token超限。原因：未正确关联搜索过滤规则与产品批次，误将全量知识库内容纳入搜索范围。
- 现象：会话启动后无自动回复，需手动触发。原因：未正确配置`nodeId`绑定的初始化触发逻辑，仅绑定了用户发送消息的触发条件。

## 怎么确认配好了
- 手动触发一次按批次编号的工作流，检查是否自动调取对应产品的配方与检测文档。
- 导出工作流文件，确认生成的格式包含可解析的JSON结构。
- 模拟用户打开会话窗口，验证是否自动启动工作流并返回初步内容。
- 调整引用上限参数，检查搜索返回结果的条数是否符合设定值。
