# 烘焙与方便食品的工艺文件与异常报告起草：工具调用与插件

## 这个品类的数据长什么样
该品类数据覆盖面包糕点、饼干、方便面及速冻面点工厂的生产全流程，日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源于原辅料合格证明、ERP/MES系统、称量设备、烤炉或油炸线、实验室检测系统及食品追溯台账，更新频率为每批、每班或每日。数据字段包含物料名称、过敏原标识、温度曲线参数、检测结果、保质期等，单位涉及摄氏度、千克、分钟等。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的高频换线、过敏原管控要求，要求工具调用需快速匹配最新配方与清洁记录。多源异构数据来源意味着插件需对接不同系统接口，适配不同数据格式。按批、班、日更新的数据要求工具调用时优先拉取最新批次的生产与检测数据，避免使用过期信息。直接食用的属性让异常报告的准确性要求更高，工具生成的报告需严格关联对应批次的检测与生产记录，不能混淆批次数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | `auto` | 适配多类型工具调用需求，覆盖配方查询、异常报告生成、数据拉取等场景 |
| 工具调用超时时间 | 600 秒 | 适配烤炉曲线等实时设备数据的拉取等待时长，避免因设备响应慢导致调用失败 |
| 单次工具调用返回条数 | 前 3 条 | 匹配单批次生产数据量，避免冗余信息干扰异常报告的生成逻辑 |
| 最大上下文长度 | 8000–12000 token | 适配多份生产记录与检测报告的上下文承载需求，确保工具调用能获取足够的参考数据 |
| 插件数据源过滤规则 | 按批次号匹配 | 对应数据按批更新的特征，确保调用的生产与检测数据属于当前处理的生产批次 |

## 容易做错的三处
-  配置`toolChoice`为`none`时，工具调用功能无知识库选择入口。原因是该配置项关闭了工具调用的知识库关联逻辑，仅允许直接调用预设函数。
-  调用AntVchart MCP插件时仅返回代码块不渲染图表。原因是未配置图表渲染的必要参数，或插件对接的数据源未返回可渲染的结构化数据。
-  工具调用返回的异常报告核心字段为空。原因是未按批次号过滤数据源，调用了过期的生产与检测数据，导致无法匹配当前异常对应的批次信息。

## 怎么确认配好了
-  发起一次模拟异常请求，核对工具调用是否触发预设的配方查询或数据拉取动作，确认`toolChoice`配置生效。
-  查看插件调用日志，确认返回的数据来源为当前批次的生产与检测记录，匹配按批次过滤的规则。
-  调用图表插件，验证是否生成可渲染的可视化结果，确认插件的数据源与渲染参数配置正确。
-  提交多批次的测试数据，核对工具调用是否仅拉取对应批次的文档，避免跨批次数据混淆。
