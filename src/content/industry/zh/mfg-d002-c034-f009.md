# 烘焙与方便食品的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
本品类典型主体为面包糕点、饼干、方便面及速冻面点工厂，日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量系统、烤炉或油炸线、实验室设备及食品追溯台账，更新频率为每批、每班或每日。文档字段包含过敏原标识、工艺参数、检验结果、保质期等，不同来源的数据格式存在差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求接入环节支持不同格式的文档解析；高频更新的生产数据要求上下文窗口不能过大，避免单次调用token超限；大量涉及过敏原、工艺参数的文档内容，要求检索与模型输出需精准匹配字段；直接食用的产品属性，要求模型生成的工艺与异常报告具备高可信度，避免参数偏差。同时，换线频繁的特点要求配置可快速适配不同产品线的文档特征。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单批次烘焙或方便食品的全量工艺文档量，避免单次调用token超限 |
| `quoteMaxToken` | 5000–8000 token | 匹配单条生产记录、检测报告的长度，避免检索到的内容总token超出模型承载范围 |
| `temperature` | 0.2–0.4 | 保障工艺与异常报告的严谨性，减少无关或发散的输出内容 |
| `AIPROXY_API_ENDPOINT` | 填写对应模型部署的接入地址 | 完成模型调用的基础路由配置 |
| `AIPROXY_API_TOKEN` | 填写申请的模型访问密钥 | 完成模型调用的身份验证 |
| 工作流/API 工具选择配置 | auto | 允许模型自主触发检索工具，获取最新的生产与检验数据 |

## 容易做错的三处
- 现象为知识库语义检索返回多条结果，但模型返回未找到相关答案，原因是`quoteMaxToken`设置过高，单次传入的检索内容总token超过模型上下文限制，导致模型无法读取有效检索片段。
- 现象为模型调用耗时过长或直接超时，原因是`maxContext`设置超出模型支持的最大token范围，或接入的API响应延迟超出阈值。
- 现象为Basic Auth认证失败，原因是未正确填写`AIPROXY_API_TOKEN`对应的密钥，或`AIPROXY_API_ENDPOINT`地址配置错误。

## 怎么确认配好了
- 查看FastGPT v4.17.0的模型调用日志，确认每次传入的上下文token未超过配置的`maxContext`值。
- 提交一份包含特定过敏原或工艺参数的起草请求，核对返回结果中是否包含检索到的对应文档片段。
- 测试Basic Auth认证的模型接入，确认接口返回200状态码且无认证相关报错。
- 调整`temperature`参数至0.2–0.4区间，观察输出内容的严谨性是否符合工艺文档的要求。
