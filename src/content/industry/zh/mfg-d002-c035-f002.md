# 热处理的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
典型数据来源包括材料牌号档案、客户技术要求、温控仪表日志、炉温均匀性测试报告、硬度计与金相设备检测结果、车间MES系统。日常文档包含热处理工艺卡、装炉布置图、实时炉温曲线、硬度与金相分析报告、设备点检表、异常处置单。数据按每炉次、每批更新，单份文档包含炉温（℃）、保温时长（小时）、硬度值（HV）等带明确单位的专业字段，部分文档附带金相组织图片。

## 这些特征在「向量模型与索引」这一环带来什么约束
按炉次、每批的高频更新要求，需要支持增量索引以避免全量重建的冗余。文档包含结构化表格、非结构化文本与图片，需同时支持文本与多模态向量索引。带明确单位的专业字段要求向量模型对齐单位相关语义，避免参数混淆。异常处置单与工艺卡的专业术语密度高，需合理控制分块长度以保留上下文关联，同时适配高频更新的数据量。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 匹配热处理工艺卡、炉温曲线的单段专业内容长度，避免跨块拆分关键参数 |
| 重叠长度 | 100–150 字符 | 保留跨块的炉温曲线时序关联，防止分块破坏工艺逻辑 |
| 相似度阈值 | 0.75–0.85 | 过滤与查询无关的历史炉次数据，提升检索精准度 |
| 最大上下文 | 4000 token | 覆盖单份完整工艺卡的核心参数，满足模型推理的上下文需求 |
| `defaultToken` | 1024 | 适配bge-m3模型的默认输入长度，平衡索引效率与语义完整性 |
| `maxToken` | 8192 | 匹配ollama qwen2.5的最大上下文支持范围，避免截断关键内容 |

## 容易做错的三处
- 现象：创建知识库时文本理解模型下拉框无已添加的ollama qwen2.5或bge-m3模型，原因是未在模型管理页面配置对应模型的本地调用地址或端口映射，导致平台无法识别可用模型。
- 现象：上传热处理文档后显示分8段，后续状态变为13段且存在重复分片，原因是增量索引未正确清理旧版本分片，或上传时触发了重复校验失效，导致重复生成向量分片。
- 现象：仅支持单文件调整参数后重新上传，无法批量触发向量模型训练，原因是未在系统设置中开启批量索引训练的配置开关，导致平台仅开放单文件训练入口。

## 怎么确认配好了
- 上传单份标准热处理工艺卡，查看分块数量与预期一致，无跨关键参数的拆分。
- 提交包含炉温参数的查询，查看返回结果的相似度符合设定的阈值范围。
- 批量上传3-5份同类型炉次数据，确认索引更新后无重复分片，且分块数量符合预期。
- 进入模型管理页面，确认嵌入模型与语言模型的状态均为正常加载，无报错提示。
