# 热处理的工艺文件与异常报告起草：工具调用与插件

## 这个品类的数据长什么样
热处理场景的数据来自材料牌号档案、客户技术条件文档、温控仪表、炉温均匀性测试报告、硬度计与金相设备导出结果、车间MES系统。数据更新频率为每炉次、每批。日常产出的文档包括热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单。数据字段包含炉温（单位℃）、保温时长（单位分钟或小时）、硬度值（单位HV或HRC）、金相组织评级等，无额外虚构统计数字。

## 这些特征在「工具调用与插件」这一环带来什么约束
热处理场景的数据来源分散，覆盖设备直连数据、系统存档文档与人工填报记录，工具调用需支持多源数据的格式适配。数据更新频率高，每炉次均会生成新的工艺与检测数据，工具调用需支持实时触发与动态参数适配。场景内文档包含结构化表格与非结构化图表，工具调用需兼容不同格式的数据提取与填充。同时异常分析需严格匹配工艺参数与检测结果，工具调用的结果校验逻辑需覆盖字段完整性与合规性要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 工作流/API 工具选择配置 | `auto` | 适配热处理场景中动态切换工艺校验、异常分析等工具调用需求 |
| 工作流/API 函数调用配置 | 按预设工具参数格式触发 | 需严格匹配热处理工艺卡、炉温曲线等工具的字段要求 |
| 工具调用超时时间 | 300–600 秒 | 热处理炉温数据采集、金相分析结果获取需较长等待周期 |
| 数据库连接池大小 | 8–12 个连接 | 适配多炉次并发的数据查询与文档生成需求 |
| 工具结果校验规则 | 匹配热处理文档必填字段 | 确保装炉位置、炉温参数等核心信息无缺失 |
| MCP绑定数据源范围 | 仅开放车间热处理专属数据库 | 避免无关数据干扰工具调用的准确性 |

## 容易做错的三处
- 添加MySQL数据库工具调用后返回400 status code (no body)，原因是未将工具参数与热处理工艺卡的材料牌号、炉温参数等字段做匹配校验。
- 自定义代码调用返回AggregateError Code:ETIMEDOUT，原因是工具调用超时阈值设置短于炉温曲线采集、硬度数据读取的实际耗时。
- 部署MCP时未绑定热处理专属的数据源权限，导致无法读取炉温均匀性测试、MES系统的工艺数据。

## 怎么确认配好了
- 发起模拟单炉次工艺查询，检查工具调用是否能自动拉取对应炉号的炉温曲线数据。
- 提交异常报告起草请求，验证工具是否能自动填充硬度计、金相设备导出的检测结果字段。
- 查看FastGPT v4.17.0的工具调用日志，确认数据库连接无超时、参数格式符合预设规范。
- 测试多炉次并发调用，检查工具调用的并发处理是否符合配置的连接池大小。
