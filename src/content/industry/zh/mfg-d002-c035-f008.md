# 热处理的工艺文件与异常报告起草：文档解析与分块

## 这个品类的数据长什么样
该品类数据来自材料牌号档案、客户技术要求文件、温控仪表采集数据、炉温均匀性测试报告、硬度计与金相设备检测结果、车间MES系统。日常生成热处理工艺卡、装炉布局图、炉温曲线、硬度与金相检测报告、设备点检表、异常处置单等文档，更新频率为每炉次或每生产批次。文档包含材料牌号、加热保温冷却参数、炉温曲线节点、硬度值、金相组织类型等字段，参数单位多为摄氏度、小时、HV或HRC硬度单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的高频次批量更新、多类型混合文档特征，对文档解析与分块带来多重约束。每炉次或每生产批次的文档数量多且更新频繁，需适配批量解析的超时与容量限制。文档包含结构化参数、时序曲线、图像类内容，需区分不同内容类型设置分块规则，避免拆分破坏曲线或图像的上下文关联。混合来源的文档既有设备自动采集的规整数据，也有人工填写的异常说明，需在分块时保留字段关联，确保后续检索时可匹配完整的工艺异常逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–1200 秒 | 单批次包含多张炉温曲线PDF、金相报告等文件，解析时长较长，需避免中途中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 单份装炉图或炉温曲线PDF可能包含多页时序数据，需适配大容量单文件上传 |
| `chunkSplitter` | 按文档类型切换 | 工艺卡使用固定字符分块，炉温曲线使用按时间节点分块，金相报告使用按检测项分块 |
| `chunkSize` | 800–1200 字符 | 适配工艺参数与异常描述的信息密度，避免分块过碎丢失关联或过长影响检索效率 |
| `customPdfParse` | 开启结构化提取模式 | 可自动提取炉温曲线的温度-时间节点、硬度检测的结构化数值，替代纯文本解析的信息丢失 |
| `chunkSettingMode` | 按文档分类配置 | 为热处理工艺卡、异常处置单分别设置差异化分块参数，适配各自的内容结构 |

## 容易做错的三处
- 现象：批量上传热处理相关文档时中途中断，重启Docker容器后无法恢复解析进度。原因：未配置合理的`PARSE_FILE_TIMEOUT_SECONDS`参数，单批次解析时长超出系统限制，导致解析进程强制终止且未保留断点。
- 现象：上传单份大容量炉温曲线PDF后，知识库未生成对应分块内容。原因：未开启`customPdfParse`的结构化提取模式，纯文本解析无法提取曲线的温度-时间节点数据，导致有效分块缺失。
- 现象：对话框上传文件后界面无解析进度反馈，后台无报错日志。原因：未调整`UPLOAD_FILE_MAX_SIZE`参数，上传的金相报告图像文件超出系统默认限制，被系统静默拦截。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的系统，上传单份1000 MB以内的炉温曲线PDF，查看解析进度是否在`PARSE_FILE_TIMEOUT_SECONDS`设置的时长内完成。
- 开启`customPdfParse`后，解析热处理工艺卡文档，检查分块内容是否包含材料牌号、加热参数等结构化字段。
- 批量上传3份以上不同类型的热处理文档，确认所有文档均生成对应分块且无中途中断情况。
- 调用对应API测试分块添加功能，确认传入的文档类型参数可被系统正确识别并生成分块。
