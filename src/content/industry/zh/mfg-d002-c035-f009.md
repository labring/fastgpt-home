# 热处理的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
热处理场景的数据来自材料牌号档案、客户技术条件、车间温控仪表、炉温均匀性测试报告、硬度计与金相设备检测结果，以及生产MES系统。数据更新频率为每炉次、每批更新。日常产出的文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单，字段涵盖材料牌号、加热温度、保温时长、冷却方式、硬度值、金相组织类型等，单位包含摄氏度、小时、HV、批次号等专业参数。

## 这些特征在「模型接入与配置」这一环带来什么约束
单炉次数据更新频繁且结构混合结构化文档与非结构化图表，要求模型上下文容量需匹配单炉次数据总量，避免截断核心工艺参数。多来源的数据需通过统一接口对接，要求配置的API端点需兼容设备与MES系统的输出格式。异常报告与工艺文件的准确性直接影响零件服役性能，要求模型生成的内容需严格匹配行业参数规范，不可随意调整专业字段。同时，单炉次任务的时效性要求接口调用需稳定可靠，避免超时影响生产节奏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 对应车间MES系统的API网关地址，或大模型服务的官方调用路径 | 确保模型可正常对接业务数据源与大模型服务，覆盖热处理全流程数据的获取需求 |
| `AIPROXY_API_TOKEN` | 从MES系统或大模型服务商获取的有效身份凭证 | 完成接口调用的身份验证，避免因权限不足导致数据无法读取或模型调用失败 |
| `maxContext` | `8000–12000 token` | 单炉次的工艺卡、炉温曲线、检测报告等文档总token量通常在此区间，可完整加载核心业务数据 |
| `maxTokens` | `1500–2000 token` | 满足单份工艺文件或异常报告的输出长度需求，兼顾响应速度与内容完整性 |
| `temperature` | `0.2–0.4` | 热处理工艺参数需保持严谨性，较低的温度值可减少生成内容的随机性，确保参数符合行业规范 |
| `toolChoice` | `none` | 该场景仅需基于现有业务文档生成文本，无需调用外部工具获取额外数据 |

## 容易做错的三处
- 现象：平台模型列表为空，仅配置`AIPROXY_API_ENDPOINT`后未显示可用模型。原因：未同步配置`AIPROXY_API_TOKEN`，或端点地址未包含正确的API路径前缀。
- 现象：模型映射配置后仍无法调用指定模型，生成内容不符合预期。原因：未在平台绑定对应模型与业务数据源的权限，导致模型无法访问热处理专属数据。
- 现象：模型测试返回401错误或连接超时，使用阿里云百炼或本地Ollama模型均出现该问题。原因：`AIPROXY_API_TOKEN`已过期，或本地部署的Ollama服务未开放外部访问端口。

## 怎么确认配好了
- 在FastGPT v4.17.0的模型调试页面，输入单炉次的工艺卡核心内容，发起测试调用，验证返回状态码为200且无权限相关报错。
- 上传单炉次的完整业务文档包，触发工艺文件起草任务，检查输出内容未出现加热温度、保温时长等核心参数的截断。
- 多次触发相同输入的起草任务，对比输出结果的差异，确认差异符合`temperature`配置的区间范围，未出现明显的参数偏差。
- 查看任务执行日志，确认未触发额外工具调用，仅生成文本类输出，验证`toolChoice`配置生效。
