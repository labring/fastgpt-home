# 焊接结构件制造的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
该品类的日常文档包含焊接工艺评定报告、焊接工艺规程、焊材领用记录、焊工资格台账、焊缝检验报告及返修单等。数据来源涵盖设计图纸、材料质保书、焊接设备运行参数、焊材库存系统、无损检测结果及人员资质档案。数据更新以每条焊缝或每批工件、每班作业为节奏，单条文档包含明确的工艺参数、检测结果、人员资质信息与操作记录，字段多涉及焊接电流、电压、母材牌号、焊材型号等专业参数。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且更新频繁，要求索引支持增量更新与多源数据接入，适配高频的焊缝、批次级数据写入。单条文档字段专业且关联紧密，需要向量模型适配工业专业术语的语义理解，避免通用模型对焊接工艺术语的误判。更新节奏细至单条焊缝，要求索引的分片与检索效率匹配高频场景，防止检索延迟影响异常报告的起草效率。文档多涉及刚性约束的资质与工艺参数，检索结果需保证关联精度，确保核验环节的可靠性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配焊接工艺文档中单段专业内容的合理长度，避免语义割裂 |
| 重叠长度 | 100–200 字符 | 覆盖焊缝编号、工艺参数等跨分块的关键标识，防止检索遗漏 |
| 相似度阈值 | 0.75–0.85 | 适配工业专业术语的语义匹配精度，过滤低关联的检索结果 |
| 单次搜索上限 | 前 10 条 | 匹配焊缝核验、返修单关联的批量数据需求，避免冗余信息干扰 |
| `maxToken` | 4096 token | 适配单份焊接工艺评定报告的总长度需求 |
| `defaultToken` | 256 token | 适配单条检索结果的核心信息展示长度 |

## 容易做错的三处
- 现象：知识库问答开启重排后检索耗时过长，界面显示超时状态码。原因：未针对焊接结构件文档的短平快特征调整单次搜索上限，导致过多冗余数据参与重排计算。
- 现象：配置阿里千问text-embedding-v3模型时，提示无可用渠道。原因：未在分组配置中开启对应大模型的接入权限，或第三方代理渠道的配置未同步至FastGPT的模型列表。
- 现象：检索结果中出现与当前焊缝无关的其他批次工艺文档。原因：分块长度设置过大，导致跨批次的工艺内容被合并分块，或相似度阈值设置过低，引入低关联匹配结果。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，上传一份典型的焊接工艺规程文档，检查分块后的内容是否保留焊缝编号、焊材型号等关键标识，无明显语义断裂。
- 输入一条针对特定焊缝的检索问题，核对返回结果的条数与单次搜索上限的设置逻辑一致。
- 查看向量模型的调用日志，确认无模型接入报错或向量生成失败的记录。
- 提交一份异常报告起草的模拟任务，检查检索结果是否覆盖所需的焊材资质、工艺参数等核心信息。
