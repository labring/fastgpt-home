# 焊接结构件制造的工艺文件与异常报告起草：文档解析与分块

## 这个品类的数据长什么样
焊接结构件制造的日常文档包含焊接工艺评定、焊接工艺规程、焊材领用记录、焊工资格记录、焊缝检验报告、返修单等。数据来源涵盖设计图纸、材料质保书、焊接设备参数、焊材库、无损检测系统及人员资质台账。文档结构差异明显，既有段落式的工艺描述，也有表格密集的记录文件，字段包含焊缝编号、焊材牌号、检测结果、人员资质编号等，单位随文档类型变化，更新频率为每条焊缝或每批、每班。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档类型多样、结构差异大，且更新频率高，对文档解析与分块环节带来多重约束。首先，不同文档的结构差异要求解析引擎需适配段落、表格等多种格式，部分无损检测报告还包含图像，需保留图像与关联文本的绑定关系，避免拆分关键信息；其次，高频更新的文档需要快速完成解析，避免影响后续生产流程；再者，部分文档包含刚性约束的资质与工艺参数，分块时需保留上下文关联，确保检索时可完整获取关键信息；最后，多来源的文档可能存在格式差异，需统一解析逻辑以保证字段提取的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 焊接结构件的文档既有段落式工艺描述，也有表格密集的检验记录，该区间可平衡上下文完整性与检索精度 |
| `chunkSplitter` | 按段落+标题分层 | 日常文档包含工艺规程、检验报告等多种结构，按标题分层可保留文档逻辑结构，避免拆分关键关联信息 |
| `customPdfParse` | 启用 | 该品类文档多为PDF格式，包含焊缝探伤图表、工艺参数表格，启用自定义解析可保留表格结构与图表关联文本 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120–180 秒` | 单份无损检测报告可能包含多幅探伤图像，解析耗时较长，该区间可避免超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 批量上传的焊材领用台账、焊工资质汇总文件可能体积较大，该上限可适配批量上传需求 |
| `chunkSettingMode` | 手动配置 | 不同文档类型（如工艺评定与返修单）的分块需求存在差异，手动配置可灵活调整参数 |

## 容易做错的三处
- 现象：将Java接口文档修改为TXT格式上传后，解析结果为空，无有效接口参数字段。原因：修改文件后缀未改变文件实际格式，文档解析引擎无法识别Java接口的结构化语法，仅按纯文本处理导致关键信息丢失。
- 现象：使用chunk模式调用pushdata API上传文档后，长期处于索引状态，无进度更新。原因：未正确配置`chunkSize`与文档结构匹配，导致分块数量过多超出系统处理队列上限，或`PARSE_FILE_TIMEOUT_SECONDS`设置过短导致解析中断后重试循环。
- 现象：上传javadoc生成的HTML接口文档后，无有效解析内容。原因：HTML文档的标签结构复杂，未开启自定义解析配置，导致引擎无法提取接口定义的结构化参数与说明文本。

## 怎么确认配好了
- 上传单份典型文档（如焊接工艺规程PDF），在FastGPT v4.17.0的文档管理界面查看解析后的分块列表，确认每个分块包含完整的逻辑段落或表格单元。
- 上传批量的焊材领用记录文件，检查上传进度与解析耗时，确认未触发超时或文件大小超限提示。
- 上传包含图像的无损检测报告，确认解析结果中包含图像关联的检测数值与焊缝编号信息。
- 调用chunk模式的pushdata API上传测试文档，查看索引进度日志，确认无长期挂起的状态。
