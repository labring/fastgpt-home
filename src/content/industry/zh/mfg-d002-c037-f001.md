# 生产计划与车间排程的工艺文件与异常报告起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的核心数据来自企业ERP系统的订单与库存、BOM清单与工艺路线、设备产能台账、人员班次表、在制品库存及供应商到货记录。日常产出的文档包括销售订单、主生产计划、物料需求计划、周日排产表、生产工单、缺料清单、交期变更单等。数据更新频率随业务场景变化，包含每日汇总更新、每周排程更新，以及订单变更、异常发生时的实时更新。数据字段覆盖订单编号、物料编码、工序名称、设备编号、产能负荷、交期要求等，需匹配各企业的生产管理规范。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的数据来源分散且格式不统一，要求HTTP接口需支持多数据源的拉取与格式适配，避免强制要求下游系统统一数据结构。数据更新的非周期性，要求接口支持按需触发，适配订单变更、异常发生时的实时调用需求。日常文档的字段数量多且差异大，要求接口参数需覆盖核心业务字段的灵活传入，同时返回结构化的排程与异常结果，便于下游系统直接解析。此外，异常场景下的实时性要求较高，接口需支持低延迟的响应，避免影响车间调度的即时决策。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {企业API密钥}` | 符合HTTP接口鉴权标准，适配企业内部ERP或生产系统的鉴权规则 |
| `variables` | 传入工单ID、物料编码、设备编号等核心业务字段 | 精准匹配生产计划的上下文数据，确保接口返回对应工序的排程结果 |
| 单次请求最大数据量 | `5000 条` | 匹配车间排程数据的单次拉取上限，避免因数据量过大导致请求超时 |
| `responseData` | 返回排程结果、异常报告的结构化字段 | 适配下游系统的解析格式，减少二次处理的工作量 |
| 超时时间 | `300 秒` | 处理复杂排程计算的合理时长，避免中途中断请求导致数据不完整 |
| 触发时机 | 按订单变更、异常发生时触发 | 匹配数据更新频率，减少无效请求的资源消耗 |

## 容易做错的三处
- 现象：接口调用返回200状态码但无有效排程数据。原因：未在`variables`中传入核心业务字段，导致接口无法匹配对应生产计划的上下文。
- 现象：连续调用多个接口时出现超时或结果错乱。原因：未等待前一个接口的`responseData`返回后再发起下一次请求，同时并发请求超出企业系统的限流阈值，导致数据处理异常。
- 现象：收到`403 Forbidden`报错。原因：未正确配置`Authorization`参数，使用了过期的API密钥或未添加允许的调用IP白名单。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本的接口配置逻辑。
- 发起单次测试请求，传入已知的有效工单ID，检查`responseData`是否返回对应工序的排程信息与异常标记。
- 模拟订单变更事件，触发接口调用，确认返回的异常报告包含缺料、设备故障等对应业务场景的内容。
- 验证`Authorization`参数的格式，通过接口鉴权测试，确认返回200状态码且无权限报错。
- 连续发起多次请求，观察返回结果的一致性，确认限流与重试配置生效，无重复或丢失数据的情况。
