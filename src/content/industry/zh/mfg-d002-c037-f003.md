# 生产计划与车间排程的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自ERP订单与库存系统、BOM清单、工艺路线表、设备产能台账、人员班次表、在制品库存及供应商到货记录。日常产出的文档包含销售订单、主生产计划、物料需求计划、周日排产表、生产工单、缺料清单、交期变更单。数据更新频率随业务场景变化，包含每日、每周、订单下达或异常发生时触发的即时更新。文档字段包含订单编号、物料编码、产能单位、排程时段、物料数量等，各字段匹配企业内部标准化的单位与命名规则。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新节奏不固定，要求多轮对话必须跟踪最新的业务数据版本，避免使用过期的排程或物料信息。文档类型多样且结构差异大，提示词需要明确指定当前处理的文档类型，防止模型混淆不同业务文档的字段规则。字段存在标准化的单位与命名，提示词需强制要求输出匹配企业内部的字段格式，确保生成的工艺文件与异常报告可直接导入系统。多轮对话需处理频繁的业务变更，需要在会话中保留关键的排程约束条件，避免重复询问已确认的参数。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的功能逻辑制定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | `8000–12000 token` | 覆盖单批次销售订单、对应工单及排程表的核心数据，避免上下文溢出 |
| 单次对话轮次上限 | `10–15 轮` | 限制冗余历史数据加载，防止对话响应超时 |
| `variables` 绑定规则 | 绑定当日ERP最新的产能、库存、工单数据 | 确保对话始终使用实时业务数据，避免生成过时的工艺文件 |
| 异常响应配置 | 当模型返回空结果时，返回「无法生成当前排程报告，请检查数据绑定」 | 处理大模型返回empty的场景，替代前端直接返回空白 |
| `chatId` 会话隔离 | 按生产工单ID划分独立会话 | 区分不同排程任务的对话上下文，防止数据混淆 |
| `messages` 历史截断 | 保留最近`3 轮`对话记录 | 过滤非关键历史信息，降低上下文处理负载 |

## 容易做错的三处
- 对话时间过长，现象为界面显示请求超时或等待超过`600 秒`未返回结果，原因是未限制上下文长度，加载了过多历史排程数据与非相关文档。
- 图表工具生成空结果，现象为调用图表工具后返回空白生产排程图，原因是未在提示词中明确要求使用当前绑定的`variables`中的产能、工单数据作为图表数据源。
- 对话内容导出失败，现象为无法导出完整的排程起草对话记录，原因是未开启会话上下文的持久化存储配置，未绑定对应会话的`chatId`进行导出。

## 怎么确认配好了
- 输入一份测试销售订单，验证对话能自动关联对应工单、缺料清单等绑定数据，生成符合格式的工艺文件草稿。
- 发起多轮排程调整请求，检查响应时间符合业务场景设定的合理阈值。
- 触发模拟异常场景，如输入缺料信息，验证模型能生成符合要求的异常报告。
- 测试会话导出功能，确认能导出完整的对话历史与绑定的排程相关数据。
