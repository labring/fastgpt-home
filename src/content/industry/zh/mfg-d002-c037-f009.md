# 生产计划与车间排程的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来自企业ERP订单与库存系统、BOM清单、工艺路线表、设备产能台账、人员排班表、在制品台账及供应商到货记录。日常产出的文档包含销售订单、主生产计划、物料需求计划、周日排产表、生产工单、缺料清单、交期变更单等，字段涵盖订单编号、物料编码、产能工时、排程优先级、交期日期等，更新频率为每日、每周，或在订单、异常情况发生时实时更新。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据来源分散且格式各异，模型接入需适配多源数据的统一解析；文档长度与内容复杂度较高，需预留足够的上下文处理空间以避免截断核心排程、工单拆解等关键信息；异常触发无固定规律，要求模型调用支持实时响应；同时生产数据涉及企业核心业务，需确保接入过程符合内网隔离与权限管控要求，避免敏感数据外泄。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配生产计划类文档的长上下文需求，避免截断核心排程、工单拆解等关键信息 |
| `maxTokens` | 4000 token | 匹配工艺文件与异常报告的输出长度，覆盖完整的工序说明、排程调整建议等内容 |
| `temperature` | 0.2–0.4 | 保持生产文档的严谨性，避免生成不符合生产规范的参数或排程方案 |
| `AIPROXY_API_ENDPOINT` | 填写企业内网代理地址或官方模型接入地址 | 适配生产环境的网络隔离要求，确保核心生产数据不流出企业内网 |
| `AIPROXY_API_TOKEN` | 按业务角色分配的专属密钥 | 区分不同车间调度、PMC等角色的调用权限，避免密钥共享导致的数据访问越权 |

## 容易做错的三处
- 现象：模型测试返回「[] is too short - 'messages'」报错。原因：未传入有效业务上下文，仅提交了空的任务指令或仅包含占位符的生产数据。
- 现象：升级至FastGPT v4.17.0后，无法在界面看到新增的模型配置项，重启服务后仍未恢复。原因：未将模型配置参数正确写入系统配置文件，或前端缓存未触发更新导致界面加载异常。
- 现象：通过代理接入的模型无法正常连接。原因：代理地址或密钥配置错误，或企业网络防火墙拦截了模型调用的出站请求。

## 怎么确认配好了
- 执行模型连通性测试，确认返回无报错且响应时间符合业务预期。
- 上传一份测试用的销售订单与周日排产表，验证模型能否生成符合格式的工艺文件草稿。
- 配置用户权限分组，测试不同角色能否调用专属的模型密钥并生成对应业务的文档。
- 模拟缺料异常场景，上传测试用的缺料清单，验证模型能否生成符合要求的异常报告。
