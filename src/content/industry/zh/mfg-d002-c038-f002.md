# 生物制品与无菌生产的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自细胞库与种子批、过程分析系统、洁净区监测记录、MES、LIMS及设备完整性测试结果。日常文档包含细胞库或种子批记录、培养纯化记录、无菌灌装记录、环境监测数据、培养基模拟灌装报告、无菌检验结果及批放行资料。数据更新节奏为每批生产、实时监测数据上传及按固定监测计划更新，文档字段包含批次标识、培养温度、沉降菌浓度、设备运行时长等，部分字段需匹配无菌生产的合规性记录格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据多源分散，包含结构化合规记录与非结构化监测日志，要求向量索引支持多源数据关联检索。数据更新节奏兼具实时性与批量性，需索引支持增量更新以避免全量重建的耗时。文档字段需匹配无菌生产合规要求，部分字段存在固定格式约束，向量模型需适配长文本与结构化字段的混合向量化。同时，工艺文件与异常报告的检索结果直接关联生产合规性，要求召回结果具备高置信度，避免低相关性内容干扰判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类长文档的合规记录，避免单块内容割裂关键工艺参数 |
| 重叠长度 | 100–150 字符 | 覆盖跨块的工艺参数关联逻辑，防止关键步骤被分块截断 |
| 相似度阈值 | 0.75–0.85 | 匹配无菌生产数据的严谨性要求，过滤低相关性的非合规记录 |
| 单次搜索上限 | 前10条 | 控制检索结果规模，避免过多数据干扰异常报告的快速定位 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| 最大上下文 | 6000 token | 结合`defaultToken`设置，平衡检索召回与模型处理能力 |

## 容易做错的三处
- 现象：向量索引构建失败，返回状态码500。原因：未适配本品类多源数据的格式差异，直接使用通用分块规则处理结构化合规记录，导致分块时丢失关键字段关联。
- 现象：重复查询时响应耗时过长。原因：未配置缓存机制，每次查询都直接访问向量数据库，未复用已检索的结果。
- 现象：调用创建训练订单接口后，知识库未生成对应索引。原因：未明确训练订单与集合添加数据的差异，训练订单用于批量处理多源异构的生产数据向量化，集合添加数据仅支持单条或少量文本的直接索引创建。

## 怎么确认配好了
- 导入一批本品类的典型文档，检查分块后的文本是否完整保留关键工艺参数与合规字段。
- 发起两次相同的查询，确认第二次查询的响应耗时显著低于第一次，验证缓存机制生效。
- 检索异常报告相关关键词，检查返回结果的相关性是否符合本品类的严谨性要求，调整相似度阈值至合适区间。
- 调用创建训练订单接口，确认对应索引任务正常启动并生成可追溯的任务记录，验证接口功能匹配业务需求。
