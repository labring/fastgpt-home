# 电机与发电机制造的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
该品类数据来自电机厂绕线、绝缘、总装与试验部门的日常业务文档，包括绕组工艺卡、绝缘处理记录、动平衡报告、耐压绝缘测试记录、型式与出厂试验报告。数据来源涵盖电磁设计数据、铜线和绝缘材料批次信息、绕线设备运行数据、平衡机检测结果、电气试验台参数及ERP/MES系统记录，更新频率为每台或每批产出一次，每次型式变更后同步更新。文档包含绕组匝数、接线方式、浸漆工艺参数、振动温升数据、试验结果等字段，关联物料批次与设备运行日志。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的业务数据关联单台/单批物料与设备日志，溯源环节需精准匹配到具体批次的文档块与原始生产数据，避免泛化引用。文档更新随批次和型式变更触发，需支持增量同步知识库并在溯源时优先匹配最新版本的文档。专业字段如绕组匝数、耐压试验结果需关联对应文档类型的字段权重，确保引用的相关性。同时，因异常后果严重，溯源需完整展示引用来源的具体字段与来源文档，不能省略关键信息，还需适配工作流中动态传入知识库变量的调用需求，以及控制引用列表的返回格式。

## 配置怎么定
基于FastGPT v4.17.0版本的配置逻辑，以下为适配该品类的配置方案：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 字符` | 该品类的工艺文件与试验报告单块内容较长，需容纳完整的工艺参数或试验结果片段 |
| `responseData` | `返回引用来源列表+原始文本片段` | 需向工艺起草人员展示引用的具体字段与来源文档，满足溯源需求 |
| `detail` | `开启` | 该品类的异常报告需关联具体的试验数据或设备日志，开启后可展示更详细的引用上下文 |
| 单次搜索上限 | `前 6 条` | 该品类的文档类型较多，需筛选最相关的6份文档用于溯源，避免信息过载 |
| 引用展示长度 | `300–500 字符` | 工艺与异常报告的引用需清晰展示关键参数，过长的片段会干扰阅读 |
| 知识库增量同步频率 | `每 4 小时` | 该品类的文档更新随批次与变更触发，每4小时同步可兼顾实时性与系统负载 |

## 容易做错的三处
- 现象：返回的引用列表为空或仅包含无关文档。原因：未针对该品类的文档类型配置字段权重，导致搜索时未优先匹配绕组匝数、试验结果等核心字段。
- 现象：工作流调用时传入的知识库变量未生效，无法切换对应批次的文档库。原因：未将知识库选择节点配置为支持动态变量引用，仅绑定了固定知识库。
- 现象：引用的文本片段超出预期长度，导致工艺文件排版混乱。原因：未设置`quoteMaxToken`的合理取值，默认参数过长，未适配该品类文档的单块内容长度。

## 怎么确认配好了
- 发起单台电机的工艺起草请求，检查返回结果中是否包含关联的绕组工艺卡、试验报告的引用来源。
- 调用工作流并传入自定义知识库变量，确认搜索节点可读取对应知识库的文档内容。
- 查看返回的引用列表，确认`detail`参数已开启，展示了引用文本的具体字段信息。
- 触发异常报告起草请求，检查引用来源是否关联了对应的振动温升数据或设备日志。
