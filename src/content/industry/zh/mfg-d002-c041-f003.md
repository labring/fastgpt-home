# 电镀与化学表面处理的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自客户表面处理规范、槽液化验记录、整流器运行数据、在线水质监测结果与危废管理台账。日常生成的文档包含槽液分析记录、工艺参数卡、挂具台账、膜厚与附着力报告、危废处置记录、废水监测报表。数据更新频率覆盖每槽次、每班及固定监测周期，文档字段包含槽液成分参数、电流温度数值、挂具使用情况、膜厚检测结果、排放指标等，部分字段带有专用单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据更新频率高且覆盖多类业务场景，多轮对话需支持实时调用最新的槽液化验、在线监测数据，避免使用过时参数生成文件。文档字段包含专业工艺参数与合规指标，提示词需明确限定召回文档的类型与字段范围，防止混入无关数据。不同来源的数据格式差异较大，对话流程需适配槽液记录的单次槽次数据、危废台账的周期汇总数据等不同结构，确保生成内容的字段匹配业务要求。

以下配置基于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 按对话会话自动生成 | 用于绑定单槽次或单批次的专属数据上下文，避免跨会话数据混淆 |
| `messages` | 保留最近20轮对话内容 | 适配工艺调整的多轮迭代需求，保留参数修改历史 |
| `variables` | 绑定槽液化验、在线监测等专属变量 | 自动调用当前批次的实时数据，减少手动输入 |
| 单次召回上限 | 前8条 | 匹配该品类单批次文档的平均数量，避免冗余数据干扰 |
| 上下文窗口大小 | 8000–12000 token | 适配多类文档的字段与参数总量，确保完整召回关键信息 |
| 提示词模板 | 限定仅使用槽液分析记录、工艺参数卡等指定文档 | 对齐该品类的业务文档类型，确保生成内容合规 |

## 容易做错的三处
- 现象：对话中出现知识库关联报错，预览模式无异常。原因：未限定仅调用该品类专属的槽液、废水监测类文档，混入了跨品类的无关知识库数据。
- 现象：生成的工艺文件字段缺失或单位错误。原因：提示词未明确指定需匹配专用参数格式，未限定文档字段范围。
- 现象：多轮对话后生成内容卡顿或截断。原因：未限制`messages`保留的对话轮次，导致上下文窗口过载。

## 怎么确认配好了
- 发起测试对话，输入当前槽次的槽液参数，核对生成的工艺文件是否自动调用了对应的数据。
- 查看对话上下文面板，确认`chatId`绑定了当前会话的专属标识，未与其他会话混淆。
- 触发异常报告生成，检查召回的文档是否仅包含该品类的槽液分析、废水监测等指定类型。
- 调整对话轮次至20轮以上，确认上下文窗口未出现溢出提示，生成流程正常。
