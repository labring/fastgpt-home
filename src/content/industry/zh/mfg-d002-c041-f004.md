# 电镀与化学表面处理的工艺文件与异常报告起草：工作流编排

## 这个品类的数据长什么样
该品类的日常文档包含槽液分析记录、工艺参数卡、挂具记录、膜厚与附着力报告、危废台账、废水监测记录。数据来源包括客户表面处理规范、槽液化验结果、整流器运行数据、在线水质监测记录、危废管理台账。数据更新频率为每槽次、每班或按固定监测周期要求。单份文档字段包含槽号、分析时间、金属离子浓度（单位g/L）、pH值、电流密度（单位A/dm²）、电镀时长（单位min）等，格式与字段定义严格匹配现场生产规范。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据拉取需要配置对应不同数据源的节点，需按数据类型分配权限与拉取规则。高频更新的槽次数据要求工作流支持事件触发，避免固定轮询带来的冗余计算。字段的专属单位与固定命名要求变量提取时严格匹配字段名与格式，防止参数误用。异常后果严重的特性要求工作流中设置异常终止与告警节点，在检测到镀层缺陷、排放超标等异常时快速中断流程。同时，单批次数据量有限但更新频繁，需合理配置循环体与单次处理量，避免节点过载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 循环体结束条件 | 检测到`variables.镀层缺陷`字段非空时终止 | 匹配电镀异常判定规则，快速终止无效循环 |
| 变量引用格式 | `{{variables.槽号}}` | 兼容FastGPT v4.17.0的变量语法，准确提取槽次数据 |
| 数据源触发时机 | 按槽次完成事件触发 | 对应数据按每槽次更新的频率，避免冗余拉取 |
| 单次处理数据量 | 前10条 | 匹配单批次槽液分析记录的常规数量，降低节点负载 |
| 超时阈值 | 300秒 | 适配单槽次全流程数据处理的耗时区间 |
| 上下文长度 | 8000 token | 覆盖工艺参数卡、异常报告的完整内容长度 |

## 容易做错的三处
- 循环体持续执行超出预设次数，日志显示节点状态为运行中未终止，原因是未正确绑定`variables`中的异常字段作为循环结束的判断条件。
- 部署Marker后处理槽液分析PDF时返回500状态码，原因是环境变量未配置文档解析的正确路径或权限。
- 大模型提示词中引用`{{槽号}}`未生效，输出结果未带入对应槽次数据，原因是未使用FastGPT标准的`{{variables.字段名}}`格式。

## 怎么确认配好了
- 手动触发一次单槽次数据的工作流，查看循环体是否在检测到`variables.镀层缺陷`字段非空时终止运行。
- 在测试节点中输入预设的变量值，验证`{{variables.槽号}}`格式的引用能否正确输出对应字段内容。
- 查看数据源节点的触发规则，确认与数据更新的频率与触发条件匹配。
- 模拟超时场景，验证节点在达到预设阈值后能否触发异常处理逻辑。
