# 电镀与化学表面处理的工艺文件与异常报告起草：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来自电镀厂、电子连接器与五金件表面处理车间的日常生产记录，核心文档包括槽液分析记录、工艺参数卡、挂具记录、膜厚与附着力报告、危废台账、废水监测记录。数据按每槽次、每班或固定监测要求更新，文档多为结构化表格或表单，字段包含槽号、分析时间、金属离子浓度（g/L）、pH值、镀层厚度（μm）、工件编号、排放指标等专业参数，格式统一且字段边界明确。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据更新频率高且来源分散，工具调用需适配按槽次、班次的触发节奏，避免延迟或重复拉取实时生产数据。专业字段的单位与取值范围固定，工具调用的函数参数需严格匹配槽液浓度、膜厚等专属字段，无法泛用通用参数模板。危废与废水数据需关联合规校验逻辑，插件需嵌入对应检测环节，同时异常报告需快速关联多源数据生成整改建议，对工具调用的上下文承载能力有明确要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 自动匹配多源生产数据的调用需求，适配槽次、班次的更新节奏 |
| `functionCall` | 启用 | 支持传递槽液浓度、膜厚等专业字段的结构化参数 |
| 工具调用触发条件 | 按槽次完成后10分钟内 | 匹配本品类每槽次的数据更新频率 |
| 函数参数映射规则 | 绑定槽号、离子浓度、膜厚等专属字段 | 对应本品类的文档结构与数据字段 |
| 单次工具调用返回上限 | 前10条记录 | 平衡数据加载量与流程处理效率 |
| 上下文窗口大小 | 4000 token | 承载多份生产文档的字段信息与关联数据 |

## 容易做错的三处
- 部分浏览器无法显示工具调用嵌入的应用图像与头像，仅夸克等少数浏览器可正常加载。原因是未配置适配通用浏览器的跨域白名单规则，导致跨域资源请求被拦截。
- 两层workflow的工具调用中，第一层AI返回的内容被自动打印输出。原因是未关闭中间步骤的输出开关，导致流程执行时暴露非必要的中间数据。
- 调用Qwen2.5模型的工具功能时返回报错，提示不支持函数调用。原因是未在FastGPT v4.17.0的模型配置中启用`functionCall`参数，未适配该模型的工具调用格式。

## 怎么确认配好了
- 发起模拟单槽次的工艺文件起草请求，检查工具是否自动拉取对应槽号的槽液分析数据与工艺参数。
- 触发异常报告生成流程，检查是否调用合规性检查插件关联废水与危废台账数据。
- 配置Qwen2.5模型的工具调用任务，发起测试请求，确认返回结果符合预设的参数映射规则。
- 查看workflow执行日志，确认两层流程中第一层的中间输出未被打印，且执行顺序符合依赖设置。
