# 石油炼制的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
石油炼制的工艺文件与异常报告数据来自DCS/APC控制系统、LIMS实验室信息管理系统、罐区计量系统、原油评价报告、设备管理系统与能源管理系统。数据更新节奏涵盖实时、每班、每日三类，其中实时数据包含装置运行参数，每班数据包含交接班记录与物料平衡表，每日数据包含质量报告与变更管理文件。日常文档包含操作规程、生产方案、联锁台账等，字段涵盖工艺参数、设备状态、质量指标等，单位包含流量、温度、浓度、时间等类型。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多套连续装置通过物流与氢气网络耦合，原料性质波动大，要求多轮对话需跟踪不同装置的关联参数，避免上下文混淆。多类数据源的更新节奏差异较大，提示词需明确区分实时、批量数据的调用时机，确保起草的工艺文件与异常报告数据时效性匹配。文档类型多样且字段复杂，提示词需指定不同文档的处理规则，例如从原油评价报告提取硫含量参数，从DCS系统提取装置负荷数据。异常报告处置需关联多系统数据，多轮对话需支持实时拉取不同数据源的信息，确保内容准确完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前炼油装置组的唯一标识 | 炼油多装置耦合运行，需通过`chatId`区分不同装置组的对话上下文，避免跨装置参数混淆 |
| `messages` | 保留最近30轮对话内容，总长度不超过12000 token | 工艺参数关联紧密，需保留多轮的原油性质调整、装置负荷变更记录，确保上下文连贯 |
| `variables` | 配置原油密度、硫含量、装置负荷率为可调用变量 | 炼油工艺核心参数来自原油评价与DCS系统，需在提示词中直接引用这些变量生成合规文档 |
| 最大上下文长度 | 8000–12000 token | 工艺文档与实时数据总长度较大，需限制上下文长度避免模型处理溢出 |
| 对话超时时间 | 600秒 | 异常报告起草需等待多系统数据拉取，该时长可覆盖多数数据汇总场景，避免过长占用资源 |

本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 无法获取每一轮对话的问题内容，现象是对话组件返回的上下文仅包含最新提问，原因是未正确绑定`chatId`参数，未保留完整对话历史。
- 配置大模型时无法设置温度参数，现象是界面无温度设置按钮，原因是未开启自定义模型配置开关，或未在变量配置中添加温度参数的引用入口。
- 对话回传耗时远超调用分组时长，现象是单次对话耗时600秒以上但调用分组仅显示1分钟，原因是未配置实时数据拉取的超时重试逻辑，导致等待系统数据时超时。

## 怎么确认配好了
- 发起一轮包含原油硫含量、催化装置负荷的提问，查看对话上下文是否包含历史提问与响应内容，确认`chatId`绑定生效。
- 在大模型配置界面检查是否存在温度参数设置项，或在变量配置中确认已添加温度变量的引用入口。
- 发起异常报告起草的请求，查看对话耗时是否符合预设的超时阈值，确认实时数据拉取逻辑正常。
- 配置数据库连接插件后执行模拟查询，检查是否能返回对应系统的工艺数据，确认连接参数与表字段规则配置正确。
