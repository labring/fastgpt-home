# 石油炼制的工艺文件与异常报告起草：工具调用与插件

## 这个品类的数据长什么样
石油炼制场景的数据来源包括DCS/APC控制系统、LIMS实验室管理系统、罐区计量系统、原油评价数据库、设备管理系统与能源管理系统。数据更新节奏分为实时（装置运行参数）、每班（交接班记录、物料平衡数据）、每日（馏出口质量报告、变更管理文件）三类。日常文档涵盖操作规程、生产方案、物料平衡表、馏出口质量报告、联锁台账、交接班记录与变更管理文件，字段包含原油密度（单位kg/m³）、装置负荷（单位t/h）、馏程温度（单位℃）、物料流量（单位m³/h）与操作时间戳等。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源异构数据的更新节奏差异，要求工具调用需支持按不同周期拉取数据，避免因数据时效性不足导致工艺文件错误。文档结构与字段的多样性，要求插件需适配不同文档的解析规则，准确提取对应字段用于报告起草。多装置耦合的业务逻辑，要求工具调用需同时关联多套系统数据，避免单一数据源的片面性。实时性要求高的场景，要求工具调用需配置超时与重试机制，应对系统临时波动。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多工具调用场景，自动选择工艺数据拉取、异常分析等所需工具，覆盖工艺文件与异常报告起草的全流程 |
| 工具调用超时时间 | `600 秒` | 石油炼制数据拉取涉及多系统交互，600秒可覆盖DCS、LIMS等多源数据的完整获取周期 |
| 工具调用重试次数 | `2–3 次` | 实时数据源可能出现临时网络波动，重试可降低数据拉取失败概率 |
| `functionCall` | 强制指定工艺数据拉取、异常分析两个工具 | 石油炼制场景需固定调用特定系统数据，避免工具调用偏离业务目标 |
| 多数据源并行调用上限 | `前 3 条` | 多装置耦合的炼制场景，并行拉取过多会增加系统负载，3个可平衡效率与资源占用 |
| 异常报告触发阈值 | 按实测标定 | 需结合装置联锁、质量偏差等实际业务规则，调整触发异常报告的参数条件 |

## 容易做错的三处
- 调用`api/v1/chat/completions`接口时出现跨域报错，前端控制台显示CORS相关提示。原因是未在FastGPT后端配置允许的跨域来源与请求头。
- 工具调用返回空结果或长错误代码，无法拉取DCS或LIMS数据。原因是未正确配置aiproxy的API密钥转发规则，导致系统无法获取模型调用权限。
- 新版本部署后工具调用失败，提示未找到MCP服务。原因是未部署MCP server并在FastGPT后台关联对应服务地址。

## 怎么确认配好了
- 调用`api/v1/chat/completions`接口，检查返回结果中是否包含工具调用的日志与数据拉取记录。
- 模拟工艺异常场景，触发异常报告起草，确认工具是否自动拉取对应数据源的实时数据。
- 查看FastGPT后台的工具调用监控面板，确认重试次数与超时时间的配置已生效。
- 测试跨域请求，确认前端调用接口时不再出现CORS报错。
