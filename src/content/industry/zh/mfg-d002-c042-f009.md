# 石油炼制的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
石油炼制场景的数据来自DCS/APC控制系统、LIMS化验系统、罐区计量系统、原油评价数据库、设备管理系统与能源管理系统。日常生成的文档包含操作规程、生产方案、物料平衡表、馏出口质量报告、联锁台账、交接班记录、变更管理文件。数据更新节奏覆盖实时、每班、每日三类，字段包含原料性质、装置负荷、产品馏分、异常告警代码与处置记录等，单位涉及温度、压力、流量、物料占比等工业标准单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
石油炼制场景的多源异构数据来源，要求模型接入环节需兼容不同工业系统的接口格式，避免出现适配性错误。实时、每班、每日的差异化更新节奏，需对应配置不同的数据同步周期参数，保障文档与报告的时效性。多类型专业文档的处理需求，要求配置足够的上下文窗口以容纳长文本内容。专业字段与工业单位的规范要求，需关联预设的业务知识库，确保生成内容符合行业标准。多装置耦合的业务逻辑，需配置工具调用的优先级规则，保障生成内容匹配全流程协同要求。

## 配置怎么定
本文基于FastGPT v4.17.0版本配置说明。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配石油炼制长文档如物料平衡表、交接班记录的处理需求，避免截断关键业务信息 |
| `maxTokens` | 2000–3000 token | 限制单轮异常报告起草的输出长度，确保内容聚焦具体处置方案 |
| `quoteMaxToken` | 1500 token | 限定引用的源数据长度，保障生成内容与原始业务数据的关联性 |
| `toolChoice` | auto | 自动选择工具调用，适配多装置耦合的工艺文件起草场景，自动关联多系统业务数据 |
| `temperature` | 0.2–0.4 | 降低生成内容的随机性，保障工艺文件与异常报告的规范性与一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境的实际地址填写 | 适配本地部署或商业版渠道的接口地址，确保模型连接正常 |

## 容易做错的三处
- 出现404 status code（no body）报错。原因是`AIPROXY_API_ENDPOINT`配置错误，未指向正确的模型接口地址，或接口未开放访问权限。
- 商业版部署后渠道模型仅显示重排模型选项。原因是未正确配置语言模型的接入凭证，或未开启对应模型的权限设置，导致系统无法识别可用的语言模型类型。
- 本地部署ollama与docker版FastGPT无法建立连接。原因是未将ollama的接口地址配置为可被Docker容器访问的地址，或未开放本地端口的网络权限，导致连接超时或失败。

## 怎么确认配好了
- 调用测试接口生成一份模拟异常报告，核对输出内容是否包含装置负荷、异常代码等石油炼制专属字段。
- 查看渠道模型列表，确认已配置的语言模型均显示在可选列表中，无缺失或异常状态。
- 测试数据同步功能，验证从DCS、LIMS等系统拉取的业务数据是否能正常关联到模型生成的文档中。
- 查看系统日志，确认无模型调用超时、接口连接失败等报错信息，符合配置的超时阈值要求。
