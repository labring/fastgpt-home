# 精细化工间歇合成的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
该品类的典型主体为涂料、树脂、助剂、农化中间体和专用化学品企业。日常产生的文档包括批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据来源涵盖配方与工艺库、原料批次数据、反应釜DCS系统、称量系统、LIMS系统与仓储系统。数据更新频率为每批生产或每个关键工艺步骤一次。业务流程中，按顺序和条件复核多种投料、判断反应终点切换后处理、防止换品清洗残留与交叉污染为核心耗时环节。

## 这些特征在「向量模型与索引」这一环带来什么约束
多批次、多步骤的文档更新要求索引支持增量同步，避免全量重建带来的性能损耗。单批文档包含多类结构化与半结构化字段，如投料量、反应温度、反应时长等，向量模型需适配混合字段的语义提取，需通过`defaultToken`调整单块的语义覆盖范围。频繁的批次级更新会带来索引写入压力，需限制单次索引的文档规模。不同批次的工艺参数存在差异，索引的召回逻辑需兼顾批次特异性与跨批次参考价值。工艺文档涉及配方保密内容，索引的访问权限需与生产系统权限绑定。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配单份工艺文档的单步骤内容长度，避免块内跨步骤语义断裂 |
| 重叠长度 | 100–200 字符 | 保留相邻投料、反应环节的关联语义，防止分块后丢失关键上下文 |
| 相似度阈值 | 0.75–0.85 | 匹配工艺参数与异常场景的语义相似度，避免召回无关批次的文档 |
| 单次搜索上限 | 前 10 条 | 兼顾异常报告起草时的参考覆盖范围与检索效率 |
| 最大上下文 | 4000 token | 适配工艺文档的批量引用需求，符合主流向量模型的输入限制 |
| `defaultToken` | 1000 | 适配单份异常报告的基础参考长度 |
| `maxToken` | 16000 | 支持长文档的完整索引，覆盖单批生产的全流程记录 |

## 容易做错的三处
- 现象为调用知识库接口创建索引时耗时过长，界面显示队列等待时长超过300秒。原因是未针对批次级增量更新配置分块规则，导致全量扫描多批次文档。
- 现象为更换向量模型后，已导入的知识库无法生成新索引，尝试重新导入时出现重复文件报错。原因是未开启增量索引的版本标记功能，系统无法识别旧模型生成的向量与新模型不匹配。
- 现象为知识库搜索返回的结果排序与语义相似度不符，异常报告起草时优先召回了低相关性的历史文档。原因是未配置重排环节，系统仅基于初始召回的相似度排序，未结合工艺文档的步骤优先级调整顺序。

## 怎么确认配好了
- 查看索引生成日志，确认分块后的文档块数量与原文档的步骤数匹配。
- 手动上传单份异常报告模板，测试搜索召回的结果是否包含同工艺步骤的参考文档。
- 检查索引的更新记录，确认新生成的批次文档能被增量同步至索引中。
- 验证向量模型的调用日志，确认使用的模型与配置一致。
