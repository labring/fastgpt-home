# 纸浆造纸的工艺文件与异常报告起草：工作流编排

## 这个品类的数据长什么样
纸浆造纸的工艺与异常数据来自木浆废纸批次台账、DCS/QCS控制系统、纸机在线测量设备、实验室检测系统、能源与水处理系统。数据更新节奏覆盖实时（如纸机运行参数）、每班（如班组生产记录）、每卷（如成品纸批次记录）。典型文档包含配浆单、打浆操作记录、纸机运行日志、在线质量曲线、实验室检测报告、断纸与换品台账，字段包含浆料配比数值、打浆度°SR、纸幅克重g/㎡、运行温度℃、断纸时长分钟等。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源分散且格式差异大，不同系统输出的字段命名、单位存在不一致，要求工作流编排时配置多源数据拉取与格式对齐节点。数据更新节奏覆盖实时、每班、每卷，对应工作流需区分触发规则，实时参数需配置高频触发节点，批量记录需配置定时触发节点。高速连续幅材生产的特性，要求异常类工作流需在断纸、换品事件发生后快速启动，避免延迟生成报告影响生产调整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按`variables`定义的事件类型触发，实时参数用秒级轮询，批量记录用每班/每卷定时 | 匹配纸浆造纸数据的多更新节奏，`variables`可灵活绑定不同数据源的触发条件 |
| 数据源节点 | 拉取对应系统的台账与实时数据，关联`nodeId`绑定的权限配置 | 确保工作流仅调用授权范围内的生产数据，`nodeId`可精准定位单个数据源节点 |
| 上下文长度 | 800–1200 字符 | 适配单卷纸机运行记录的文本长度，避免上下文溢出影响生成质量 |
| 输出聚合规则 | 仅保留最终节点的生成结果，隐藏前置AI调用输出 | 符合工艺文件与异常报告的输出要求，避免冗余信息干扰生产人员 |
| 失败重试次数 | 3 次，间隔 60 秒 | 应对生产系统临时波动导致的数据拉取失败，保障工作流稳定性 |
| 版本兼容 | FastGPT v4.17.0 | 适配最新工作流编排的节点配置与权限管理功能，避免旧版本兼容性问题 |

## 容易做错的三处
- 现象：工作流运行后输出包含前置AI节点的生成内容，仅保留最终聚合结果的配置未生效。原因：未在工作流中配置输出聚合规则，未关闭前置节点的输出展示开关。
- 现象：无法在新版本中找到工作流导入功能，旧版本的导入路径不再可用。原因：新版本将工作流导入入口调整至团队空间的资源管理模块，未适配旧版本的操作逻辑。
- 现象：通过API调用工作流时，用户选择与表单输入组件未弹出交互提示。原因：未在工作流配置中开启API访问的交互节点开关，或未在API请求中携带交互所需的参数。

## 怎么确认配好了
- 触发预设的生产事件，如模拟断纸或上传单卷生产记录，查看工作流运行日志，确认触发节点正常启动并拉取对应数据。
- 导入测试用的纸机运行记录与配浆单数据，检查格式对齐节点是否正确转换字段单位与命名，无格式错误。
- 运行完整工作流，查看最终输出内容，确认仅保留聚合后的工艺文件或异常报告，无前置AI节点的冗余输出。
- 通过API调用配置完成的工作流，验证用户选择与表单输入组件是否正常弹出交互提示，符合预期交互逻辑。
