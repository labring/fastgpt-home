# 纺纱与织造的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档包含配棉配料单、工艺上机单、设备运转记录、纱线与坯布检验报告、疵点台账。数据来源涵盖原纤维检验数据、ERP系统、纺机织机实时采集数据、条干仪、验布机检测结果以及订单规格要求。数据更新随每批原料、每班生产、每匹布产出同步触发，文档字段包含纤维细度、纺纱捻度、织造组织参数、疵点类型与位置等，部分字段带有纺织行业专用单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据更新频率高且来源分散，要求模型接入环节支持多源数据的实时或批量同步，需适配多类型文档的字段结构。单份文档包含的专业参数较多，需配置模型能准确识别专用字段与单位，避免参数解析错误。连续生产产生的批量数据会带来上下文负载，需限制模型单次处理的文本上限，防止超时或内容截断。另外，疵点记录多为非结构化文本，需配置合适的模型能力以完成异常分类与标准化报告生成。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单班生产产生的工艺与检验文档总长度，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 满足工艺参数计算与异常报告的输出长度需求，兼顾生成效率 |
| `temperature` | 0.3–0.5 | 保持专业参数解析与异常分类的准确性，降低生成随机性 |
| `AIPROXY_API_ENDPOINT` | 本地模型部署地址，如 `http://localhost:11434/v1` | 适配纺纱织造场景下的本地模型部署需求，减少网络延迟 |
| `AIPROXY_API_TOKEN` | 本地模型生成的访问密钥 | 保障模型接入的安全性，防止未授权访问 |
| 多源数据同步频率 | 每4小时 | 匹配每班生产的更新节奏，确保知识库数据时效性 |

## 容易做错的三处
- 现象：添加本地ollama部署的大语言模型与嵌入模型后，创建知识库时文本理解模型下拉框无对应选项。原因：未将嵌入模型配置到FastGPT的模型渠道关联列表中，仅单独配置了大语言模型渠道。
- 现象：连接本地DeepSeek模型后，调试预览时自动切换为其他公开模型导致无法对话。原因：未正确绑定自定义模型的API密钥与端点，系统默认调用了预设的外部模型。
- 现象：接入Xinference部署的模型后，生成批量工艺报告时频繁出现内容截断错误。原因：未调整`maxContext`参数适配批量文档的总长度，超出模型预设的上下文上限。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型渠道管理页面，确认已添加的大语言模型与嵌入模型均显示正常在线状态。
- 创建测试知识库，上传单份配棉单与疵点记录，触发文本理解流程，确认模型可正常解析纤维细度、捻度等专业字段。
- 发起工艺参数计算与异常报告生成的测试请求，查看生成结果是否包含符合纺织行业规范的参数与分类内容。
- 检查多源数据同步日志，确认ERP与设备采集的数据可正常同步至对应知识库。
