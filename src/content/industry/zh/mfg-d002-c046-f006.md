# 肉制品与屠宰加工的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据涵盖动物检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告等。数据来源包括动物检疫信息、供应商批次档案、生产追溯台账、实时温度采集数据、金属检测结果与实验室检验报告。更新节奏按生产批次、每班作业频次执行，冷链温度数据为连续采集更新。文档字段包含批次编号、检疫编号、温度阈值、检验指标与结果等，部分记录需绑定对应原料或成品的唯一标识。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类数据需绑定唯一批次标识，引用溯源时需确保每条引用内容可追溯至对应生产批次的原始记录，因此需要精准匹配来源与引用内容的关联关系。连续采集的冷链温度数据更新频率高，需支持实时或近实时检索，避免引用过期数据。原料检疫与生产记录的强绑定要求，需在检索时优先关联同批次的多类文档，避免跨批次引用导致的溯源错误。同时，生熟分区的生产流程要求引用时需区分原料与成品的记录分类，防止交叉污染相关的溯源混淆。数据字段的特异性，如温度值、检验结果需准确对应原始采集节点，不能泛化引用。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的功能逻辑制定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | 该品类单批次相关文档总长度较高，需覆盖检疫、生产、检验等多类记录的完整内容 |
| `responseData` | 包含批次编号、来源文档类型、采集时间 | 匹配该品类溯源所需的批次绑定与时间校验需求 |
| `detail` | 完整 | 需保留原始记录的字段细节，用于后续溯源核对 |
| 单次召回上限 | 前10条 | 平衡检索效率与溯源所需的多类文档覆盖 |
| 检索范围过滤 | 按当前生产批次执行 | 避免跨批次无关文档被纳入引用范围 |

## 容易做错的三处
- 现象：检索返回的引用条数与界面显示的上下文窗口条数不一致，例如界面显示上下文仅30条但实际检索到310条。原因：未正确绑定检索范围与当前生产批次，导致跨批次无关文档被纳入上下文。
- 现象：设置了引用上限后，知识库中超过上限的文档块仍被引用。原因：未将文档块按生产批次进行分块，单块内容超过上限但未拆分至对应批次维度。
- 现象：引用内容无法关联到具体检疫或生产记录。原因：未在返回数据中包含批次编号等唯一标识字段，导致溯源时无法匹配原始记录。

## 怎么确认配好了
- 触发一次工艺文件起草请求，核对返回的引用来源是否包含当前生产批次的所有相关文档类型。
- 查看检索日志，确认返回的引用条数与设置的上下文窗口匹配，无跨批次无关内容。
- 导出引用溯源报告，核对每条引用内容是否带有批次编号、采集时间等必要标识字段。
- 模拟异常报告起草场景，验证引用的冷链温度数据是否为对应时段的连续采集记录。
