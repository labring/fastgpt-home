# 肉制品与屠宰加工的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
该品类数据包含检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告等。数据来源为动物检疫信息、供应商批次台账、生产追溯系统、温度采集设备、金属检测设备及实验室检验结果。更新按生产批次、每班频次触发，冷链温度记录为连续采集。文档字段包含批次号、检疫日期、温度阈值、微生物检测指标、工位编号等，部分字段带有单位，如温度为摄氏度、重量为千克。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据关联多环节且存在严格的批次绑定要求，模型接入时需适配多源数据的批次对齐逻辑。连续采集的冷链温度数据会产生高频增量内容，需限制模型上下文的处理长度避免过载。异常报告起草需关联检疫证明、生产记录等多文档内容，模型的上下文窗口需支持跨文档的信息整合。部分字段带有明确单位与合规标识，模型需准确识别字段属性，避免混淆生熟分区、温度阈值等关键参数的取值逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多批次生产记录、检疫证明的跨文档整合需求，避免因上下文溢出丢失关键批次关联信息 |
| `maxTokens` | 1500–2000 字符 | 匹配单份异常报告或工艺文件的起草长度，避免输出内容超出业务文档格式要求 |
| `temperature` | 0.2–0.4 | 降低生成随机性，确保检疫标识、温度阈值等合规字段的取值准确 |
| `vision` | 启用 | 支持解析检疫证明、检验报告中的图片类附件内容，匹配品类内文档的图片格式占比 |
| `AIPROXY_API_ENDPOINT` | 本地部署节点的11434端口地址 | 适配品类内企业常见的本地模型部署场景，确保模型服务正常连通 |
| `AIPROXY_API_TOKEN` | 应用特定密钥 | 区分生产与测试环境的访问权限，保障业务数据的访问安全 |

## 容易做错的三处
- 配置`AIPROXY_API_ENDPOINT`时填写错误端口或地址，出现连接超时报错（状态码504或ECONNREFUSED），原因是未正确匹配本地部署模型的实际监听端口，或未开放对应端口的网络访问权限。
- 启用`vision`功能后上传检疫证明图片，返回结果中图片对应字段为空，原因是未正确配置模型的视觉能力依赖，或上传的图片格式超出模型支持范围。
- 使用通用密钥调用模型生成工艺文件，结果中未关联对应批次的检疫信息，原因是未使用对应生产环境的应用特定密钥，权限范围无法访问批次关联的业务数据。

## 怎么确认配好了
- 调用模型接口测试单份检疫证明的文本提取，核对返回结果是否包含批次号、检疫日期等关键字段，字段完整性按业务文档的必填项要求标定。
- 输入连续温控记录的批量内容，检查模型输出的上下文处理结果是否完整，未出现内容截断或丢失的情况。
- 生成单份异常报告草稿，核对生成内容是否关联了对应批次的生产记录与检验数据，字段单位与业务要求一致。
- 测试`vision`功能上传检疫证明的图片附件，确认返回结果能准确提取图片中的文字与标识信息。
