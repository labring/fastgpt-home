# 计量器具与实验室管理的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自企业计量室、质量实验室、CNAS体系实验室的日常工作文档，包括量具台账、校准计划、校准证书、期间核查记录、试验原始记录、标准物质台账与偏离处置文件。数据来源涵盖内部计量管理系统、外部校准机构证书、标准器数据、LIMS系统与环境监测记录。更新节奏随校准周期、单次试验完成或异常事件触发，文档包含量具编号、量程、精度等级、测量值、不确定度、有效期等专业字段，附带明确的单位标识。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源数据的接入要求索引支持跨系统的元数据关联，确保检索结果能溯源至原始计量文档。非固定的更新节奏需要索引支持增量同步与按需触发，避免全量重建带来的资源消耗。专业字段与单位的存在要求向量模型适配计量领域的专业术语编码，避免语义匹配偏差。工艺文件与异常报告起草的场景需要检索结果能关联到具体的校准数据与试验记录，因此索引需要保留文档的元数据信息，支持精准的溯源查询。同时，文档的严谨性要求检索结果的过滤需严格匹配专业相关性，避免无关内容干扰起草工作。

以下配置适用于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配校准证书、试验记录的单段专业内容长度，避免拆分关键测量数据与溯源编号 |
| 重叠长度 | 100–150 字符 | 保留跨分块的溯源关联信息，确保校准周期、偏离处置等跨段落内容的语义完整性 |
| `maxToken` | 按所选嵌入模型/服务支持的输入上限设置 | 这是嵌入模型配置中的最大 token 数，不是检索或 LLM 上下文；请核对所选模型或服务商文档。参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx) |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配的非专业计量内容，确保检索结果的专业相关性 |
| 单次搜索上限 | 前 6 条 | 控制检索结果的信息量，避免过载影响异常报告的起草效率 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 现象：检索结果无法显示对应校准证书的文件名与编号。原因：未开启文档元数据的向量索引关联，仅对文本内容进行了向量编码。
- 现象：向量检索返回结果条数远低于预期。原因：相似度阈值设置过高，过滤了符合专业匹配度的计量数据，例如将正确的校准结果判定为低相关性内容。
- 现象：导入外部校准机构证书后文本似乎被截断。检查提取文本、样本文本分块、嵌入请求长度与服务日志，区分解析、分块或嵌入请求问题。`maxToken`应按所选模型/服务输入上限设置，不是 LLM 上下文。

## 怎么确认配好了
- 上传一份校准证书与试验原始记录，检查分块后的文本是否保留了关键的测量值与溯源编号。
- 发起一个关于“某量具失准影响的产品范围”的查询，检查检索结果是否附带对应文档的元数据信息。
- 抽查样本文档分块，确认`defaultToken`效果；另行查看索引任务资源指标，`defaultToken`不是服务器内存上限。
- 测试导入不同来源的计量文档，确认索引能正确识别并关联多源数据。
