# 设备点检与预防维修的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类的数据覆盖制造企业设备管理全流程，来源包括EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史档案、备件库存清单及特种设备检验记录。日常文档包含设备台账（含设备编号、额定参数）、点检表（含测点、实测值及单位）、保养计划、维修工单、故障分析报告、备件清单等。数据更新频率覆盖每班点检、日/周/月保养计划更新，以及故障发生时的实时上报。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据格式与更新节奏，要求向量索引支持结构化数值、半结构化清单及非结构化文本的混合索引。实时传感数据与故障发生时的临时上报需要低延迟的增量更新能力，避免索引队列积压。设备编号、测点单位等字段的强关联性，要求索引绑定元数据以确保检索结果可关联至具体设备或文档。不同更新频率的数据源需要适配差异化的索引刷新策略，避免高频数据覆盖低频的历史记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配点检表、维修工单的单条记录长度，保留设备编号、故障代码等关键字段关联 |
| 重叠长度 | 100–150 字符 | 避免跨分块的关键元数据被截断，确保上下文连贯 |
| 相似度阈值 | 0.75–0.85 | 区分设备正常运行参数与异常阈值，适配点检数据的精度要求 |
| 单次搜索上限 | 前10条 | 覆盖同设备的近期点检、维修记录，满足故障定位的信息需求 |
| `defaultToken` | 4096 | 适配设备台账、故障分析的长文本内容，符合FastGPT v4.17.0的参数范围 |
| `maxToken` | 8192 | 支持整合多份关联文档，满足维修方案生成的上下文需求 |

## 容易做错的三处
- 现象：索引创建后长期显示未就绪状态，无法触发检索。原因：未适配设备传感数据的实时更新频率，增量索引任务未按每班或故障触发的节奏配置，导致索引队列积压。
- 现象：检索结果未关联具体文档来源，无法回溯点检记录或维修工单。原因：未开启元数据绑定配置，未将设备ID、文档类型作为索引元数据字段存储。
- 现象：嵌入模型调用失败，提示不支持当前模型。原因：未确认所选嵌入模型适配设备数据的字段类型，或未按要求配置模型接口参数。

## 怎么确认配好了
- 手动上传一份典型点检表文档，等待索引完成后，检索该文档内的异常测点数值，确认检索结果包含该文档内容。
- 查看索引状态面板，确认索引进度符合配置的更新频率，无长期积压的待处理任务。
- 调用检索接口，检查返回结果中是否包含文档元数据字段，例如设备编号、文档创建时间。
- 测试使用嵌入模型生成设备台账的向量，确认生成的向量无格式报错，可正常参与检索。
