# 设备点检与预防维修的工艺文件与异常报告起草：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源包括EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史档案、备件库存清单及特种设备法定检验记录。数据更新节奏覆盖每班点检、日/周/月保养计划更新、故障发生时的即时上报。日常文档包含设备台账、点检表、分级保养计划、维修工单、故障分析报告、备件清单与特种设备检验记录，字段包含设备编号、点检点位、参数阈值（如温度、振动值）、维修工时、备件型号等，对应单位包括摄氏度、毫米、小时等。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据的接入要求工具调用需适配不同系统的接口格式，避免因数据格式不匹配导致检索失败。不同更新频率的数据源需要对应不同的触发时机，例如每班点检数据需按日触发调用，故障发生时需即时调用传感数据。文档字段与单位的特异性要求工具返回结果需严格匹配预设的设备数据字段，确保生成的工艺文件与异常报告符合企业内部的文档规范。同时，故障处理的时效性要求工具调用需具备低延迟特性，避免因响应过慢影响生产排产与维修进度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 让模型自主选择适配当前设备点检场景的工具，无需手动指定调用目标，适配多数据源的检索需求 |
| `functionCall` | 开启 | 要求模型严格按照预设的设备数据字段格式生成调用参数，确保返回结果匹配点检文档的字段与单位要求 |
| 工具调用超时时间 | `30-60 秒` | 适配EAM/CMMS系统的常规接口响应延迟，避免故障场景下因超时延误异常报告起草 |
| 工具返回结果过滤规则 | 保留与当前设备编号匹配的前3-5条记录 | 减少上下文冗余，提升模型生成工艺文件与异常报告的准确性 |
| 工具调用最大上下文长度 | `8000-12000 token` | 适配设备点检数据的文档长度，避免上下文溢出导致工具调用失败 |
| 插件数据源权限 | 仅开放对应车间的生产数据 | 限制敏感设备数据的访问范围，符合生产内部的数据安全规范 |

## 容易做错的三处
- 现象：调用MCP插件后返回结果为空，日志显示请求成功但无有效数据。原因：未正确配置插件的后端代理地址，导致工具无法连接到对应车间的EAM/CMMS数据源，无法检索到指定设备的点检或维修数据。
- 现象：模型调用工具时触发超时报错，界面显示请求未完成。原因：工具调用超时时间设置过短，未适配EAM/CMMS系统的接口响应延迟，或网络波动导致请求中断。
- 现象：生成的异常报告中备件型号与实际库存不符。原因：未在工具调用配置中加入备件库存数据的检索参数，导致模型仅调用了维修历史数据，未同步核对当前库存的备件信息。

## 怎么确认配好了
- 手动触发工具调用，输入指定设备的编号，检查返回的点检记录是否与EAM/CMMS系统中的实际数据一致。
- 模拟故障发生场景，触发异常报告起草流程，确认工具是否按预设规则调用对应数据源的记录。
- 查看插件运行日志，确认每次工具调用的请求参数包含当前设备的专属字段（如设备编号、车间代码），无遗漏或错误。
- 调整工具调用超时时间为超出常规响应时长的数值，测试是否触发合理的超时报错提示，确认配置生效。
