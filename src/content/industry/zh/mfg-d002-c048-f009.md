# 设备点检与预防维修的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自EAM/CMMS系统、设备传感终端、操作员点检记录、维修历史档案、备件库存清单与特种设备法定检验记录。日常文档包含设备台账、点检表、保养计划、维修工单、故障分析报告、备件清单与检验记录，各文档字段包含设备编号、点检位置、参数阈值、维修时间、备件型号等，单位涵盖摄氏度、毫米、小时等具体计量类型。数据更新频率覆盖每班点检、日/周/月保养、故障发生时的实时上报。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求配置支持跨格式的文档解析与字段对齐，避免不同系统的设备信息出现格式冲突。差异化的更新频率需要配置适配动态更新的数据集，确保召回的点检、维修数据为最新状态。多样的文档类型与专属字段要求配置限定召回范围，避免无关文档干扰生成结果。法定检验记录的时效性要求配置添加过期数据过滤规则，防止生成不符合合规要求的维修计划与报告。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配设备台账、维修工单、点检记录等多文档的上下文总量，覆盖典型维修场景的信息需求 |
| `quoteMaxToken` | 1500 token | 匹配设备点检单条关键记录的长度，避免召回内容过长影响异常报告的生成效率 |
| `temperature` | 0.2–0.4 | 保障维修方案与报告的严谨性，减少无关或主观化的生成内容 |
| `AIPROXY_API_ENDPOINT` | 填写私有部署的FastGPT API地址 | 适配本地或企业内网的设备管理数据调用，避免敏感设备信息外泄 |
| 工作流/API 工具选择配置 | auto | 支持自动调用检索工具获取最新点检与维修数据，适配动态更新的设备状态 |
| `maxTokens` | 2000–3000 token | 满足异常报告与点检计划的完整内容长度需求，覆盖故障分析与维修方案的完整描述 |

## 容易做错的三处
- 检索结果包含多个无关设备的文档，无法精准召回指定设备的点检数据。原因是未通过配置限定召回的数据源范围，未关联设备台账的唯一标识字段，导致模型随机召回无关设备的信息。
- 本地部署环境下调用FastGPT接口返回401身份验证失败。原因是未正确配置`AIPROXY_API_TOKEN`与私有部署的API地址，未完成调用权限的绑定设置。
- 生成的维修计划包含逾期的特种设备检验记录。原因是未配置过期数据过滤规则，未根据法定检验记录的更新时间筛选有效数据，导致生成不符合合规要求的内容。

## 怎么确认配好了
- 提交包含特定设备编号的查询，核对检索结果是否仅包含该设备的点检、维修与检验文档，无无关设备的信息。
- 调用FastGPT测试接口生成一份异常报告，验证返回结果的生成时长符合预期，无超时报错。
- 检查配置的`temperature`参数取值，确认生成的维修方案与报告内容严谨，无冗余或主观化的描述。
- 导入测试用的过期检验记录，验证配置是否自动过滤该类数据，确保生成的计划不包含逾期信息。
