# 设备点检与预防维修的工艺文件与异常报告起草：知识库检索与召回

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的典型数据来自制造企业设备部、车间维修班组的日常业务文档，包括设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录。数据来源覆盖EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史、备件库存及法定检验信息，更新频率涵盖每班、日/周/月周期及故障发生时的实时更新。文档结构包含结构化表格与非结构化报告，字段涉及设备编号、点检参数、故障代码、备件型号等具体属性。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源要求检索功能支持跨系统、跨格式的内容召回，避免遗漏关键设备相关信息。多样的更新频率需要知识库适配不同同步周期，确保最新点检记录、维修工单可及时被检索到。混合的文档结构（结构化表格与非结构化报告）要求检索逻辑同时适配字段匹配与语义理解，提升多类型文档的召回精度。故障类文档的实时性需求，要求召回结果优先匹配近期维修记录与最新故障分析，保障异常处理的时效性。多字段的结构化文档（如备件清单）要求分块时保留关键属性，避免检索时丢失核心匹配信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 适配设备点检表、维修工单等文档的语义匹配精度，过滤低相关的召回结果 |
| `limit` | 前10条 | 覆盖车间维修班组日常检索的常用文档数量，减少人工筛选的额外成本 |
| `searchMode` | 全文检索 | 适配多类型混合文档的检索需求，支持从设备台账、故障分析中提取关键信息 |
| `usingReRank` | 开启 | 解决长文档召回后排序失效的问题，对初始召回结果按相关性重新排序 |
| `datasetSearchUsingExtensionQuery` | 开启 | 优化检索词表述，将点检、维修需求转化为更匹配知识库文档的检索逻辑 |
| `collectionIds` | 按车间/设备类型分组配置 | 精准绑定对应设备类的知识库集合，避免跨车间、跨设备类型的无关文档干扰 |

## 容易做错的三处
- 调用对话接口时无法关联新建的设备类知识库，返回空结果。原因：未在接口配置中指定`collectionIds`参数，未绑定对应车间或设备类型的知识库集合。
- 长文档召回后排序结果不符合业务预期，未触发重排模型。原因：未开启`usingReRank`配置，直接返回初始召回的无序结果，导致长内容的相关性排序混乱。
- 上传多列Excel点检表或备件清单时，仅识别两列内容导致检索精度下降。原因：未按设备字段拆分文档块，未保留多列关键属性，检索时无法匹配完整的点检参数或备件信息。

## 怎么确认配好了
- 发起模拟点检需求的检索请求，检查返回结果是否包含对应设备的点检表、维修工单等目标文档。
- 查看检索结果的排序逻辑，确认长文档结果的相关性符合业务预期，验证重排功能生效。
- 调用接口关联指定的车间知识库集合，检查返回结果是否仅包含对应设备类的文档，无跨品类干扰内容。
- 上传多列Excel备件清单，检查知识库分块后是否保留所有关键字段，验证检索时可匹配到完整的备件型号、库存信息。
