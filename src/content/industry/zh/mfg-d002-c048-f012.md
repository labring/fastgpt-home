# 设备点检与预防维修的工艺文件与异常报告起草：部署与升级

## 这个品类的数据长什么样
该品类的数据来自制造企业设备部、车间维修班组与公用工程部门的日常业务产出，包含设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录等文档。数据来源覆盖EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史、备件库存与法定检验信息，更新频率覆盖每班点检、日/周/月保养计划更新、故障发生时的即时上报。文档字段覆盖设备编号、点检位置、参数值、异常阈值、工单编号、故障描述、处理时长、备件型号与检验有效期等，随文档类型灵活调整。

## 这些特征在「部署与升级」这一环带来什么约束
该品类数据来源分散且更新节奏多样，部署时需支持多数据源的定时同步与实时增量接入，保障班前点检记录、设备传感数据的实时性与故障发生时维修工单的即时上报。文档类型与字段结构差异较大，升级时需兼容多格式文档的解析与自定义字段映射，避免异常报告缺失关键维修信息。由于出错后果直接关联非计划停机、安全事故，部署环节需强化数据校验与权限管控，确保特种设备检验记录等敏感文档的访问合规。同时维修窗口需服从生产排产，部署时需预留知识库与生产排程系统的关联配置接口，保障维修计划与生产节奏匹配。

## 配置怎么定
本页配置适用于FastGPT v4.17.0

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:yourpass@host:27017/fastgpt_device?authSource=admin` | 存储设备台账、故障分析等半结构化文档数据，需配置正确的认证信息保障数据访问安全 |
| `PG_URL` | `postgresql://device_user:yourpass@host:5432/device_maintain` | 存储点检表、保养计划等带时序属性的结构化数据，PostgreSQL适配多字段关联查询需求 |
| `REDIS_URL` | `redis://:yourpass@host:6379/0` | 缓存实时设备传感数据、班前点检记录，降低数据库查询压力，支持高频数据访问 |
| `STORAGE_S3_ENDPOINT` | `按企业内部对象存储服务地址配置` | 存储特种设备检验记录、备件清单等大体积文档，适配企业现有存储架构 |
| `DB_MAX_LINK` | `20–50 个` | 该品类数据访问峰值集中在班前点检、故障上报时段，限制连接数避免数据库资源耗尽 |
| `FILE_TOKEN_KEY` | `按企业密钥管理规范生成的随机32位字符串` | 保护上传的点检记录、维修工单等敏感文档的访问权限，防止未授权访问 |

## 容易做错的三处
- 现象：多节点部署后不同节点无法共享点检记录与维修工单数据，原因：未正确配置`STORAGE_S3_ENDPOINT`或`REDIS_URL`实现跨节点数据同步与存储。
- 现象：本地部署开启团队管理功能后无法正常访问设备文档，原因：未正确配置`FILE_TOKEN_KEY`或`ROOT_KEY`导致权限校验失败。
- 现象：故障发生时生成的异常报告缺失备件库存字段，原因：未将EAM数据源的备件清单表正确关联至知识库文档解析规则，导致字段映射不全。

## 怎么确认配好了
- 访问`FE_DOMAIN`配置的域名，登录系统后查看设备台账列表是否正常加载，无加载失败提示。
- 上传一份纸质点检表扫描件或电子点检表文档，检查解析后是否包含点检位置、参数值、异常阈值等必填字段。
- 触发模拟故障上报流程，查看生成的异常报告是否关联了对应维修工单与备件清单数据。
- 查看后台系统日志，确认`MONGODB_URI`、`PG_URL`与`REDIS_URL`的连接状态均为正常，无超时或认证失败报错。
