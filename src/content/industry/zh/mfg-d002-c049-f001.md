# 过程质量与成品放行的工艺文件与异常报告起草：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据来自制造企业的MES系统、在线检测设备、实验室系统、工艺参数数据库、客户质量标准库与历史缺陷库。数据更新节奏随生产批次、班组班次持续采集，覆盖在制品到成品的全流程质量相关文档，包括控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单与质量月报。数据字段包含检验项参数、检测数值、判定结果、异常类型、批次信息与责任人标识，部分字段需匹配客户标准的单位要求。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据来源分散且需对接多类外部系统，要求接口支持多源数据拉取与格式适配；高频持续的更新节奏要求接口具备低延迟与高并发处理能力，避免影响生产节拍；文档类型多样且字段复杂，需接口支持动态参数匹配不同文档模板的字段要求；数据关联批次与责任人的特性，要求接口传输时需携带唯一标识以保证数据溯源。同时，异常报告与放行单涉及质量判定权限，接口需携带验证信息确保调用合法性。

## 配置怎么定
以下配置项适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带 Bearer 前缀的固定密钥 | 匹配外部系统的接口鉴权要求，保障调用合法性 |
| `variables` | 包含批次号、检验类型、客户标准ID的键值对 | 适配多类质量文档的动态字段填充需求 |
| `responseData` | 按质量文档模板映射的字段集合，包含异常等级、隔离范围 | 确保返回数据可直接用于异常报告与放行单生成 |
| 接口超时阈值 | 600 秒 | 适配实验室检测数据的采集延迟，避免因超时中断数据拉取 |
| 并发请求上限 | 前 20 条 | 匹配班组每班的检验批次处理量，避免超出外部系统负载 |
| 单次数据拉取上限 | 800–1200 字符 | 适配单批次检验记录的长度，避免数据过载 |

## 容易做错的三处
- 现象：接口返回状态码403，且日志显示鉴权失败。原因：未正确配置`Authorization`参数，未携带符合外部系统要求的鉴权信息。
- 现象：调用后生成的异常报告字段为空。原因：未在`variables`中配置批次号、检验类型等必填字段，导致无法匹配文档模板的动态填充项。
- 现象：接口响应耗时明显高于直接调用外部系统的耗时，且curl测试时响应正常。原因：未合理设置接口超时阈值，或并发请求超出外部系统负载导致排队延迟。

## 怎么确认配好了
- 调用配置好的接口，拉取一条已知批次的检验数据，检查返回字段是否包含预设的异常等级、隔离范围等内容。
- 查看接口调用日志，确认`Authorization`参数已正确携带，且未出现鉴权失败的报错。
- 模拟批量调用接口，观察响应耗时是否符合生产节拍的要求，调整并发请求上限与超时阈值。
- 对比直接调用外部系统接口与通过FastGPT调用的返回结果，确认数据一致性。
