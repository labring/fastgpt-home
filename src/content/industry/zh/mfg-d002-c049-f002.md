# 过程质量与成品放行的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自制造企业的MES系统、在线检测设备、实验室系统、工艺参数库、客户标准及历史缺陷库。日常生成的文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审、放行单、质量月报。数据更新节奏为每批生产、每班巡检持续采集，文档字段包含检验项目、公差范围、检验频次、检测数值、批次号、缺陷描述、处理意见等，部分字段带有固定单位如毫米、百分比、小时。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源高频更新的数据要求索引支持增量刷新，避免全量重建带来的性能损耗；多样的文档结构需要适配灵活的分块策略，确保控制计划的检验项、不合格品评审的缺陷描述等关键信息不被截断；带固定单位的字段需在向量建模时保留语义关联，避免因单位缺失导致相似度匹配偏差；单批次生产数据的关联性强，召回时需优先匹配同批次的检验记录，因此索引需支持按批次维度的定向检索。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配巡检记录、SPC报表等单文档的平均长度，避免分块过碎丢失上下文关联 |
| 重叠长度 | 50–100 字符 | 保留相邻分块的工艺参数或检验序列信息，适配连续型质量数据的语义连贯性 |
| 相似度阈值 | 0.75–0.85 | 区分合格与异常的检验记录，匹配质量数据的语义相似度判断需求 |
| 单次搜索上限 | 前 10 条 | 覆盖单批次生产的典型关联数据量，避免冗余召回影响起草效率 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 16384 | 支持长文本的异常报告起草，容纳多批次的关联检验与缺陷数据 |

## 容易做错的三处
- 现象：Docker部署集成索引模型时出现连接超时报错。原因：未配置内网环境下的模型访问白名单，或端口映射未正确绑定至容器内部端口。
- 现象：导出的dataset.csv仅包含index字段无content字段。原因：导入知识库时未正确关联原始文档的文本内容，仅同步了索引元数据信息。
- 现象：使用bge-large向量模型导入文本时，分段后出现关键检验项断裂。原因：未调整分块长度适配工艺文件的长段落结构，默认分段截断了包含公差范围的完整检验项描述。

## 怎么确认配好了
- 导入单份控制计划文档，查看分块后的文本片段是否保留完整的检验项与公差范围信息。
- 发起异常报告起草请求，核对召回的关联数据条数符合单次搜索上限的配置要求。
- 查看FastGPT v4.17.0的索引更新日志，确认每批次生产数据完成后自动触发增量索引更新。
- 测试`defaultToken`与`maxToken`配置，确认长文本的不合格品评审报告可完整加载并生成关联向量。
