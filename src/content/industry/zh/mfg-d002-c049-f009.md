# 过程质量与成品放行的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
本品类的数据主要来自MES系统、在线检测设备、实验室仪器、工艺参数记录、客户质量标准及历史缺陷库。数据更新按生产批次、班组频次执行，部分在线检测数据持续采集。日常产出的文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单及质量月报，数据字段包含检验阈值、批次标识、缺陷代码、合格判定结果、工艺参数值等，单位依具体检测项匹配。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据来源分散且格式多样，包含结构化报表、半结构化记录及非结构化文档，要求模型接入配置适配多源数据解析。数据更新频率高且批次关联紧密，需配置合理的上下文窗口以关联当前批次与历史质量数据。文档字段包含专业检测术语与行业标准代号，需配置模型支持专业术语识别与标准匹配。不合格评审与放行环节需关联历史缺陷库，要求模型接入支持外部知识库快速调用，避免单次推理数据过载。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配本品类多批次历史数据关联的需求，避免截断关键质量记录 |
| `maxTokens` | 4000 token | 控制单轮推理输出长度，适配工艺文件与异常报告的结构化生成需求 |
| `quoteMaxToken` | 2000 token | 限制引用的历史质检数据长度，确保推理过程聚焦当前批次的质量判定 |
| `temperature` | 0.2–0.4 | 降低随机生成概率，保证质量判定与放行建议的一致性，符合生产场景的严谨要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写私有API地址 | 适配制造企业私有化部署需求，确保数据不流出企业内网 |
| `AIPROXY_API_TOKEN` | 按企业权限规则生成专属令牌 | 保障API调用的安全性，符合生产数据的权限管控要求 |

## 容易做错的三处
- 配置`AIPROXY_API_ENDPOINT`时填写错误的API地址，导致界面显示文本理解模型列表为空。原因是未匹配企业私有大模型的实际部署地址，未完成网络连通性校验。
- 未设置合理的`maxTokens`参数，导致生成的异常报告超出预设长度，无法完整嵌入生产系统的审批流程。原因是未结合本品类文档的标准篇幅调整参数阈值。
- 未调整`temperature`参数至合理区间，导致生成的质量判定结果出现随机偏差，不符合生产场景的严谨要求。原因是误将通用对话场景的参数值直接套用至质量管控场景。

## 怎么确认配好了
- 进入模型接入配置页面，确认`AIPROXY_API_TOKEN`与部署的API服务密钥一致，发起测试调用并返回有效响应。
- 上传一份本品类典型的成品检验报告文档，验证模型能否正确提取检验阈值、批次信息与合格判定结果。
- 配置`temperature`为0.3后，连续生成3份同批次的异常报告，确认输出内容的一致性符合生产场景要求。
- 检查`maxContext`参数设置，确保上传的历史缺陷库数据不会被截断，可被模型正常关联引用。
