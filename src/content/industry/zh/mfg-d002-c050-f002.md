# 通用机械设备装配的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
通用机械设备装配场景的典型主体为泵、阀、压缩机、减速机、机床及非标设备制造商。日常产生的文档包含装配工艺卡、BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单。数据主要来源于PLM/ERP系统、零件检验数据、装配工具采集设备、试验台、MES系统及客户技术协议。数据更新频率为每台设备或每订单一次，文档包含明确的技术参数字段，如扭矩值、间隙数值、同轴度指标等，且不同文档间存在强关联关系，例如BOM需与装配工艺卡对应，试运行报告需关联扭矩与间隙记录。

## 这些特征在「向量模型与索引」这一环带来什么约束
多订单多台的更新频率要求索引支持增量更新，避免全量重新索引占用过多计算资源。文档类型多样且包含结构化技术参数，需要分块策略适配不同文档长度，例如装配工艺卡可按段落分块，单条扭矩记录可按单次采集数据分块。数据来源涉及多系统异构格式，需在索引前完成格式统一预处理，确保向量生成的语义一致性。强关联文档的存在要求索引环节保留文档间的关联元数据，以便后续检索时能联动返回相关文档，例如检索间隙调整记录时同步返回对应BOM信息。

## 配置怎么定
本配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配装配工艺卡、试运行报告等长文档的语义完整性，同时控制向量生成的计算量 |
| 重叠长度 | 100–150 字符 | 避免分块破坏跨段落的技术参数关联，确保语义连贯性 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的检索结果，聚焦与装配异常或工艺要求强相关的文档 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 8192 | 支持包含多层BOM、多组试验数据的长文本向量生成 |
| 单次搜索上限 | 前 10 条 | 平衡检索效率与结果覆盖度，避免返回过多冗余文档 |

## 容易做错的三处
- 现象：创建知识库时文本理解模型下拉框无可选模型，原因：未将索引模型绑定至对应知识库的向量配置环节，仅在全局模型渠道添加未关联至当前场景。
- 现象：索引过程耗时过长，原因：分块长度设置超过1500字符且未启用增量索引，全量索引时单次处理数据量过大。
- 现象：向量化数据集后检索结果为空，原因：相似度阈值设置过高，导致符合业务语义的匹配结果被过滤，或未正确配置文档字段与检索关键词的映射关系。

## 怎么确认配好了
- 上传单份装配工艺卡至知识库，检查向量生成日志无报错，确认模型调用正常。
- 发起检索测试，输入“减速机装配间隙调整要求”，确认返回结果包含对应工艺卡及间隙调整记录。
- 新增一份订单的BOM文档，触发增量索引，检查索引任务状态显示完成。
- 进入知识库配置页面，确认已添加的ollama qwen2.5语言模型和bge-m3索引模型处于可用状态。
