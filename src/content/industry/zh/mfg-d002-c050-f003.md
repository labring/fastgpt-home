# 通用机械设备装配的工艺文件与异常报告起草：多轮对话与提示词

## 这个品类的数据长什么样
通用机械设备装配的日常文档包含装配工艺卡、多层BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单。数据来源涵盖PLM/ERP系统、零件检验数据、装配工具采集数据、试验台测试数据、MES系统及客户技术协议。数据更新频率为每台设备或每订单一次，字段包含设备型号、订单号、扭矩值（单位N·m）、间隙值（单位mm）、同轴度参数（单位μm）等，不同文档的字段结构随装配环节变化。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据按每台设备或每订单更新，多轮对话需要绑定专属标识以避免跨单数据混淆。多层BOM与多类装配记录的结构，要求提示词需明确分类调用对应数据源，避免混淆不同环节的文档内容。字段附带特定单位的要求，使得提示词需引导输出匹配单位的工艺与异常报告内容。单台装配的多步骤流程，决定了对话上下文需保留关键环节的记录，同时需控制上下文规模以保证响应效率。

## 配置怎么定
本文基于FastGPT v4.17.0版本配置。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前装配订单的唯一标识 | 确保对话上下文仅关联对应订单的装配数据，避免跨单混淆 |
| `messages` | 保留最近20轮对话内容 | 平衡上下文完整性与响应速度，适配单台装配的多步骤流程 |
| `variables` | 存储设备型号、订单号、扭矩阈值（如120 N·m）等关键参数 | 快速调用预设的装配标准与订单信息，无需重复查询 |
| 最大上下文窗口 | 8000–12000 token | 容纳多层BOM、多份装配记录的文本内容，避免截断关键信息 |
| 单次工具调用上限 | 前3条匹配数据 | 聚焦最相关的装配工艺与异常数据，减少冗余信息干扰 |

## 容易做错的三处
- 现象：调用数据库工具时返回400 status code (no body)。原因：未在`variables`中配置数据库连接的订单专属参数，导致调用时缺少对应数据源的标识。
- 现象：对话上下文丢失部分装配记录。原因：未绑定`chatId`，导致不同订单的对话上下文被混合加载，关键装配数据被覆盖。
- 现象：生成的异常报告单位不匹配。原因：提示词未明确要求匹配装配记录的N·m、mm等单位，导致输出结果与现场数据不一致。

## 怎么确认配好了
- 发起测试对话，输入某台设备的订单号，检查`variables`中是否自动加载对应设备的BOM与工艺卡数据。
- 连续发起多轮关于间隙调整、扭矩校验的提问，确认上下文未丢失之前的对话内容。
- 调用数据库工具查询装配记录，检查返回结果是否仅包含当前订单的相关数据。
- 生成异常报告草稿，核对报告中的单位是否与现场记录的N·m、mm等一致。
