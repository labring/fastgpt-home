# 通用机械设备装配的工艺文件与异常报告起草：文档解析与分块

以下配置基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
通用机械设备装配品类的日常文档包含装配工艺卡、BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单。数据来源多为PLM/ERP、零件检验数据、装配工具采集系统、试验台、MES及客户技术协议。文档更新频率为每台设备或每订单一次，部分字段带有专业单位，如扭矩值（N·m）、间隙值（mm）、同轴度公差（μm），且不同订单的文档结构存在差异。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档多为按订单定制的结构化内容，不同订单的工艺卡、检验单格式存在差异，因此分块需保留文档的原始层级与逻辑结构，避免通用分块导致工序或检验项被拆分断裂。同时，文档中包含大量带专业单位的数值数据，解析时需完整保留字段与单位，否则后续检索与异常报告起草会出现匹配错误。此外，单份文档可能包含多页内容，部分大型非标设备的装配文档篇幅较长，解析与分块需适配不同的文档长度，避免超时或解析不完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 该品类文档包含工序描述、检验数据等长文本，800–1200字符可保留单工序或单检验项的完整逻辑，避免拆分断裂 |
| `chunkSplitter` | `markdown` | 该品类文档多从PLM导出为带层级标题的格式，按markdown标题分块可保留文档的原始结构 |
| `customPdfParse` | 开启 | 该品类PDF文档常包含内嵌表格（如扭矩记录、间隙调整记录），开启后可保留表格的结构化数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型装配工艺卡或多页试运行报告解析耗时较长，600秒可覆盖多数常规文档的解析需求 |
| `chunkSettingMode` | `custom` | 该品类不同订单的文档格式差异较大，自定义分块规则可适配各类文档类型 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 大型非标设备的装配文档集合可能包含多页图纸与配套记录，1000 MB可覆盖常规上传需求 |

## 容易做错的三处
- 现象：调用创建文件集合的API时，PDF解析结果丢失内嵌表格内容，无明确报错提示。原因：未在API参数中指定`customPdfParse`为开启状态，默认解析模式无法保留表格的结构化信息。
- 现象：近期PDF解析任务频繁报错，日志显示超时状态。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`至适配大型文档的取值，原有短超时设置无法完成多页试运行报告的完整解析。
- 现象：上传多个订单的装配文档后，检索结果混杂不同订单的内容，无法精准匹配目标设备。原因：未为上传文件添加对应订单标识的元数据，分块时未保留文档来源信息，导致解析结果无法区分。

## 怎么确认配好了
- 上传一份包含内嵌扭矩表格的PDF文档，检查解析后的文本是否保留表格行列结构与专业单位（如N·m）。
- 调用解析接口时，查看返回参数中是否包含`customPdfParse`的配置标识，确认参数已生效。
- 上传2份不同订单的装配工艺卡，检索对应订单的专属关键词，确认返回结果仅包含目标订单的文档内容。
- 上传一份超过500页的大型装配手册，检查解析任务是否在600秒内完成，无超时报错。
