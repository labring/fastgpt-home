# 金属切削加工的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES系统及量检具数据。日常文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表及量具校准记录。数据更新随每笔工单、每件工件、抽检批次或刀具更换触发，文档包含数控程序代码、刀具参数、尺寸偏差值、检验结果等结构化与非结构化字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据格式混杂，包含数控程序代码、结构化参数表格与自然语言描述文档，且随工单、刀具更换高频更新。多源数据的格式差异要求索引环节支持多模态文本解析，高频更新则需要适配增量索引策略，避免全量重建的资源消耗。文档内包含工序关联信息与尺寸偏差等关键异常数据，向量模型需适配代码类文本与结构化参数的语义编码，需确保`maxToken`配置足够覆盖长文本片段，避免截断关键G代码与工序参数。

## 配置怎么定
本配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配工艺文件、数控程序的单段语义完整性，避免跨工序信息割裂 |
| 重叠长度 | 100–150 字符 | 保留工序间的关联上下文，防止分块后丢失基准与装夹方案的关联信息 |
| 相似度阈值 | 0.72–0.85 | 按实测标定，过滤低匹配度的异常报告与工艺文件，避免误匹配刀具磨损与尺寸漂移数据 |
| 单次搜索上限 | 前 10 条 | 匹配车间巡检、首件检验的单批次数据量，确保召回结果覆盖典型异常场景 |
| `maxToken` | 8000 | 适配数控程序与工艺路线的长文本处理，避免截断关键G代码与工序参数 |
| `defaultToken` | 4096 | 适配基础文本片段的向量编码余量 |
| 重排 | 开启 | 优化异常报告的语义排序，优先召回与当前异常类型匹配的历史处理文档 |

## 容易做错的三处
- 现象为知识库导入文本数据集后，数据集状态持续显示为索引中。原因是未适配高频更新的金属切削数据，采用了全量索引策略，未配置增量索引逻辑，导致大体积的数控程序与工艺文件集合索引耗时过长。
- 现象为自定义向量模型请求始终触发大模型调用。原因是未在渠道配置中正确绑定向量模型的专属调用路径，将向量模型与LLM渠道混淆配置。
- 现象为向量模型返回的语义相似度数值超出0-1区间。原因是未调整向量模型的输出归一化配置，直接使用了未校准的相似度得分，无法适配FastGPT的过滤逻辑。

## 怎么确认配好了
- 上传单份包含G代码的数控程序文档，查看索引完成时间是否符合预期，确认增量索引触发逻辑正常。
- 输入包含刀具磨损或尺寸漂移描述的查询词，查看召回结果的相似度得分是否落在0-1区间内。
- 配置多副本部署后，发起批量索引请求，确认各副本的索引进度同步一致。
- 切换至自定义向量模型渠道，发起向量查询请求，确认返回结果仅包含向量匹配数据，未触发LLM生成逻辑。
