# 金属切削加工的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
数据来源包括产品图纸与三维模型、CAPP/CAM系统、机床采集终端、MES系统、量检具数据。更新节奏为每工单、每件工件、抽检批次或刀具更换时触发。日常文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表等，字段包含刀具寿命（单位：分钟）、工序尺寸公差（单位：mm）、切削转速（单位：r/min）、进给量（单位：mm/r）等专业参数。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的文档包含长文本数控程序、带单位的专业参数、多源异构的实时生产数据，高频更新的特性要求模型接入需适配高并发调用。长文档如数控程序易超出模型上下文限制，需针对性配置上下文参数；多源数据的格式差异要求接入配置支持多类型数据的统一解析；专业字段的单位与精度要求模型需保留参数的原始表述，避免自动转换导致的误差。同时车间工单的批量处理需求，要求配置需适配高并发场景下的资源分配。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体参数设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–16000 token | 适配数控程序、工艺路线等长文档的上下文需求，匹配金属切削加工单工单文档的平均长度 |
| `maxTokens` | 2000–3000 token | 满足异常报告起草的输出长度要求，同时避免超出模型调用的单请求限制 |
| `quoteMaxToken` | 1000–1500 token | 限定引用的工艺文件、机床采集数据的长度，防止上下文溢出导致调用失败 |
| 工作流/API 工具选择配置 | auto | 自动选择工具处理结构化的刀具、工序数据，适配工艺文件起草的多步骤内容生成需求 |
| `temperature` | 0.3–0.5 | 保持工艺参数的准确性，避免异常报告的描述出现过度发散的偏差 |
| `AIPROXY_API_ENDPOINT` | 按部署服务器实际地址填写 | 适配本地模型服务器的接入需求，解决高并发下的响应延迟问题 |
| `AIPROXY_API_TOKEN` | 按实际生成的密钥填写 | 保障接入的安全性，防止未授权的API调用 |

## 容易做错的三处
- 上传产品三维模型或工序图纸时出现报错，返回400状态码或空结果。原因是未开启`vision`配置项支持图像解析，或未正确配置图像格式的读取规则。
- 共享页面高并发测试时，超出60并发后出现无应答情况，本地服务器资源未达极限。原因是`AIPROXY_API_ENDPOINT`未配置并发适配规则，或`maxTokens`设置过高导致单请求占用资源过多。
- 上传数控程序后模型无法读取其中内容，<FilesContent>标签内存在有效文本但返回空字段。原因是`quoteMaxToken`取值过小，导致截取的文本超出有效范围，或未开启自动内容提取的前置逻辑。

## 怎么确认配好了
- 上传单份长度约5000 token的数控程序，检查模型能否正确提取切削参数、工序要求，无报错返回。
- 模拟100并发请求调用异常报告起草接口，检查无超时或无应答情况，本地服务器资源使用率符合预期。
- 上传带图像的首件检验记录，检查模型能否正确识别图像中的尺寸标注并生成对应描述。
- 查看平台日志，确认所有API调用均携带正确的`AIPROXY_API_TOKEN`，无未授权访问记录。
