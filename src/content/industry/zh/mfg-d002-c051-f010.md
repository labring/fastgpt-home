# 金属切削加工的工艺文件与异常报告起草：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据主要来自产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES系统及量检具数据。日常文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表与量具校准记录。数据更新随工单执行、零件加工、抽检环节及刀具更换触发，文档字段涵盖加工参数、刀具寿命、检验结果等，单位包含毫米、转每分钟、小时等加工专用单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类数据来源分散且更新触发节点多，要求知识库支持多格式批量导入与增量更新，避免召回过时的工艺参数或检验记录。文档包含结构化表格、数控代码、检验表单等多种格式，字段多为加工专用术语，要求检索环节适配专业词汇匹配，同时区分不同文档类型的召回权重。单次加工工单关联多类文档，检索需精准匹配当前工序的装夹方案、刀具参数等核心信息，避免召回无关内容影响起草效率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配金属切削加工的专业术语精度，避免召回无关工序或刀具信息 |
| `limit` | 前8条 | 覆盖当前工序的工艺路线、刀具清单等多类文档，同时控制上下文长度 |
| `searchMode` | `mixedRecall` | 适配数控程序代码、工艺表格、检验表单等混合格式的金属切削文档检索需求 |
| `usingReRank` | 开启 | 对召回结果重新排序，优先匹配当前工单的装夹方案、刀具参数等核心信息 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户输入的异常报告需求，自动扩展检索刀具磨损、尺寸漂移、表面粗糙度异常等历史文档 |
| `collectionIds` | 按车间工序分组配置 | 区分不同机加车间的工艺数据，避免跨车间文档混淆 |

## 容易做错的三处
- 现象：调用对话接口传入`collectionIds`参数时返回参数错误。原因：未将知识库ID转换为字符串格式，或传入的ID未对应当前启用的数据集。
- 现象：检索结果返回条数远少于预期，无法覆盖当前工序的工艺路线、刀具清单等必要文档。原因：`limit`参数设置过低，未匹配到多类工艺相关文档。
- 现象：修改知识库内容后，导出的数据集仍为旧版本内容。原因：未在知识库管理页触发完整的索引更新，直接导出的是缓存的旧数据。

## 怎么确认配好了
- 输入当前工序的刀具型号、装夹方案关键词，核对召回结果中是否包含对应刀具清单、切削参数文档。
- 传入预设的`collectionIds`参数，检查检索结果是否仅包含指定分组的工艺数据。
- 触发知识库完整更新后导出数据集，对比修改后的文档是否出现在导出文件中。
- 开启`usingReRank`后，检查召回结果的排序首位是否为当前工单最核心的工艺文件。
