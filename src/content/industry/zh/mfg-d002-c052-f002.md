# 钢材轧制与精整的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与MES系统。日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书。数据更新节奏为每卷或每支钢产品实时生成，字段包含钢卷批次号、加热温度、压下率、厚度偏差、表面缺陷类型等，对应单位为摄氏度、毫米、百分比等。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时更新的单卷级数据要求索引支持增量同步，避免全量重索引带来的性能损耗。多类型工业文档的长度差异大，从简短的加热制度到数千字符的表面质量报告，需要适配不同长度的文本分块。工业术语如压下率、板形缺陷等的语义特殊性，要求向量模型适配工业场景的文本编码。批量数据生成的特点，要求索引支持单次处理十万级以上的结构化与非结构化混合数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配钢材轧制与精整场景的向量模型与索引需求。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配轧制规程、表面质量报告等文档的典型长度，避免单块内容语义断裂 |
| 重叠长度 | 100–150 字符 | 覆盖跨分块的工业术语关联，如连续的加热温度曲线描述 |
| 相似度阈值 | 0.75–0.85 | 区分合格与异常工艺参数的语义相似度，适配钢材轧制的质量判定需求 |
| 单次导入上限 | 5000 条 | 平衡导入速度与系统负载，适配十万级数据的分批处理 |
| `defaultToken` | 8192 | 适配长文档的上下文编码，覆盖完整的轧制计划内容 |
| `maxToken` | 16384 | 支持超长的质保书文本向量化，避免内容截断 |

## 容易做错的三处
- 现象为知识库上传PDF后向量化耗时过长，原因是未针对长文档调整分块长度，导致单块token超出模型上限，触发多次分段编码。
- 现象为导入十万条CSV数据后，最终向量数据仅九万余条，缺失数千条，原因是未设置合理的单次导入上限，部分批次数据未完成索引就被后续任务覆盖。
- 现象为本地运行向量索引正常，打包为Docker镜像后向量得分一致，原因是镜像中未正确加载工业场景的词表文件，导致语义编码出现偏差。

## 怎么确认配好了
- 导入单卷的表面质量报告PDF，检查分块后的文本块无语义断裂，无内容截断。
- 导入十万条结构化CSV数据，核对导入完成后向量集合的条目数与源数据条数一致。
- 提交异常报告的查询请求，查看返回的相似文档的相似度值符合预设阈值区间。
- 启动增量同步任务，验证新生成的钢卷数据可自动添加到索引中。
