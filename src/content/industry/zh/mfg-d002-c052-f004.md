# 钢材轧制与精整的工艺文件与异常报告起草：工作流编排

## 这个品类的数据长什么样
钢材轧制与精整的数据来源于板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与MES系统。数据更新频率为每卷或每支钢料实时更新，日常产出轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书等文档。文档字段包含批次号、加热温度（单位℃）、轧制压下量、厚度（单位mm）、宽度（单位mm）、表面缺陷类型、硬度值等，不同文档的字段关联依赖钢料批次标识。

## 这些特征在「工作流编排」这一环带来什么约束
实时且按批次更新的数据要求工作流需支持按钢料批次触发执行，避免固定周期轮询导致的延迟。多源数据输入需工作流整合不同节点的采集数据，确保轧制规程、在线检测结果与MES记录的字段匹配。单卷或单支钢料的文档量适中但关联紧密，工作流需保留完整字段关联，不能随意拆分数据。异常判定需直接关联实时检测数据，若工作流环节出错，会直接导致钢卷降级、设备损伤等后果，因此需配置明确的异常分支与重试机制。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量更新触发方式 | 按`variables`变更触发 | 适配实时更新的批次数据，避免固定轮询带来的延迟，确保工艺文件更新与钢料进度同步 |
| 单节点上下文长度 | 800–1200字符 | 匹配单卷轧制记录的典型字符量，避免超出AI上下文上限导致处理失败 |
| 异常重试次数 | 3次 | 平衡异常处理效率与设备、批次的损失风险，避免过度重试占用生产资源 |
| 异常分支触发条件 | 按`nodeId`执行失败状态码 | 精准定位轧制、检测等具体环节的异常，触发对应异常报告起草流程 |
| 批次数据关联规则 | 按钢料批次号匹配 | 确保不同来源的检测、计划数据关联到对应钢卷，避免数据张冠李戴 |

## 容易做错的三处
- 现象为全局`variables`值未自动更新，原因是未配置按变量变更触发的工作流节点，仅设置了固定轮询的执行周期。
- 现象为工作流执行超时，原因是未限制单批次数据的处理长度，导入的完整轧制记录超出AI上下文上限。
- 现象为异常报告分类错误，原因是未关联轧机自动控制的实时数据作为分类依据，仅使用静态的历史文档模板。

## 怎么确认配好了
- 触发单卷钢料的变量更新，检查`variables`字段是否同步更新为当前批次的最新数据。
- 模拟异常节点执行失败，确认工作流是否自动跳转至异常分支，触发异常报告起草流程。
- 导入单批次完整的轧制记录文档，检查工作流是否完整加载所有字段并完成关联匹配。
- 查看工作流执行日志，确认触发条件与配置的`variables`变更、`nodeId`状态一致。
