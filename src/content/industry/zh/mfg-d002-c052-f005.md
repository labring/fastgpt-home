# 钢材轧制与精整的工艺文件与异常报告起草：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源于板坯或钢坯批次、加热炉、轧机自动控制、在线测厚测宽、表面检测系统及MES系统。数据更新频率为每卷或每支钢的实时更新，日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书。文档字段包含钢卷批次号、加热温度、轧制速度、厚度偏差、表面缺陷类型等，对应单位为毫米、摄氏度、米每秒等，单卷文档内容长度随轧制流程复杂度变化。

## 这些特征在「工具调用与插件」这一环带来什么约束
品类数据的实时更新要求工具调用需适配高频、小批量的请求节奏，避免因请求超时影响生产流程。单卷钢的全流程文档包含多类业务字段，工具调用需准确识别并关联对应字段，否则会导致异常判定或报告起草错误。数据按卷或支更新的特性，要求工具调用需支持按批次维度筛选数据，无法适配跨批次的无差别查询。同时，文档内容长度波动较大，工具调用需具备灵活的上下文适配能力，避免长文本截断关键业务信息。

## 配置怎么定
本配置方案适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配轧制规程、表面质量报告的单段内容长度，避免截断厚度、缺陷类型等关键业务字段 |
| `toolChoice` | auto | 适配多环节工具调用需求，自动匹配批次数据查询、异常判定、报告生成等工具 |
| 单次调用上下文上限 | 15000 token | 匹配单卷钢的全流程数据量，避免上下文溢出导致调用失败 |
| 超时时间 | 30–60 秒 | 适配在线检测数据的实时响应节奏，避免因等待过久中断生产流程 |
| 异常结果校验规则 | 按实测标定 | 匹配板形、厚差的行业判定标准，确保异常报告的准确性 |
| 结果返回格式 | 结构化JSON | 适配后续报告生成的自动化处理需求，便于提取字段生成正式文档 |

## 容易做错的三处
- 现象为长文档（如完整轧制规程）调用打分工具后结果为空或偏差大，原因是未针对轧制类文档的长文本做分块配置，导致关键业务字段被截断。
- 现象为定时执行工具调用任务无响应，积分扣除后无结果返回，原因是未配置工具调用的触发条件与执行周期，或未绑定对应MES数据接口。
- 现象为表面缺陷判定工具调用后返回错误状态码，原因是未将工具入参匹配钢卷批次、在线检测数据的字段格式，导致参数不合法。

## 怎么确认配好了
- 上传单卷钢的完整表面质量报告，验证工具调用可正确提取厚度、缺陷类型等预设业务字段。
- 触发单次工具调用，确认返回结果的响应时长符合预设配置的时间范围。
- 配置`toolChoice`为auto后，测试多工具联动场景下的自动匹配逻辑是否适配轧制流程。
- 提交多批次测试数据，核对工具调用的结果与原始业务数据的匹配度，调整校验规则至符合行业判定标准。
