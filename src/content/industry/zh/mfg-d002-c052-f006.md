# 钢材轧制与精整的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来自板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与MES系统。日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告与质保书，字段含唯一批次号、温度值、厚度参数、缺陷等级、生产速度等，更新频率为每卷或每支钢料实时更新，文档结构按生产批次与工序节点分层存储。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的实时卷级更新、多源异构数据结构与强批次绑定需求，对引用溯源带来三点约束。需以唯一生产批次号作为溯源锚点，避免跨批次数据混淆；需统一多源数据的关联规则，将自控系统数值、检测报告文本与MES工单绑定至对应工序节点；需确保引用时的数据源版本与当前生产批次匹配，避免引用过期的工序参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配单卷生产记录的文本长度，避免截断关键批次信息与参数 |
| `responseData` | 开启 | 启用知识库返回引用来源的元数据，用于绑定生产批次标识 |
| `detail` | 开启 | 启用详细溯源信息，展示具体检测设备与工序节点内容 |
| 单次搜索上限 | 前6条 | 覆盖单卷生产涉及的轧制、检测、质保等多环节文档，避免遗漏关键记录 |
| 批次关联开关 | 开启 | 绑定唯一生产批次号作为溯源锚点，防止跨批次引用混淆 |
| 引用匹配阈值 | 按实测标定 | 适配轧制参数的数值精度与文本表述差异 |

## 容易做错的三处
- 配置`responseData`后引用无效果：现象为界面显示引用标记但未返回具体来源文档的元数据或链接，原因是未将生产批次相关的元数据字段添加至知识库的元数据映射规则中，无法绑定溯源锚点。
- 知识库仅返回文本数据集：现象为引用结果仅包含纯文本内容，未展示检测设备、工序节点等信息，原因是未开启`detail`配置，未启用多源数据的详细溯源展示。
- 答案与知识库内容不匹配：现象为生成的工艺文件或异常报告未包含知识库中的轧制参数，原因是`quoteMaxToken`取值过小，截断了关键的批次信息与参数内容。

## 怎么确认配好了
- 发起单卷生产批次的查询，检查返回结果中是否包含对应批次的板形厚度记录、表面质量报告等文档的元数据或关联链接。
- 查看FastGPT v4.17.0版本的知识库引用日志，确认是否绑定了唯一生产批次号作为溯源标识。
- 调整`quoteMaxToken`取值后，验证返回的引用内容是否完整包含轧制参数与工序节点信息，无截断情况。
- 测试通过API传入生产批次参数，确认工作流可正确调用对应批次的知识库内容，生成匹配的工艺文件。
