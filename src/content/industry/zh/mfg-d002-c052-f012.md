# 钢材轧制与精整的工艺文件与异常报告起草：部署与升级

## 这个品类的数据长什么样
本品类数据来自热轧、冷轧、型钢、钢管企业的板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与MES系统。日常生成的文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书，数据按每卷或每支钢件实时更新，文档字段涵盖工艺参数、质量检测结果与批次标识，对应单位包含摄氏度、百分比、毫米等。

## 这些特征在「部署与升级」这一环带来什么约束
本品类数据按卷级实时更新且来源分散，部署时需支持对接多类设备与系统的实时数据接入，避免全量同步带来的性能损耗。卷级追溯要求数据关联精度高，配置环节需保障批次标识的唯一性绑定。日常文档类型多样，需适配轧制规程、质量报告等不同格式的文档解析与存储。升级过程中需兼顾现有生产系统的连续性，避免因配置变更影响实时工艺数据流转。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30 个` | 本品类数据按卷级实时更新，高频数据写入与查询需适配合理的数据库连接池规模 |
| `REDIS_URL` | `主节点 + 1 个备节点` | 实时工艺与质量数据需低延迟缓存，保障卷级数据的快速检索与关联 |
| `STORAGE_S3_ENDPOINT` | `工业级分布式存储端点` | 本品类文档与质量数据体量较大，需稳定的分布式存储支撑批量文件存储 |
| 单次文件上传上限 | `1000 MB` | 单份轧制规程或质保书文档可能包含多页检测数据，需支持大文件上传 |
| `FILE_TOKEN_KEY` | 按实测标定 | 需保障文档访问令牌的安全性，适配企业内部的权限管控规则 |
| `ROOT_KEY` | 按实测标定 | 保障系统内部接口调用的权限安全，适配企业级部署的权限体系 |

## 容易做错的三处
- 现象：界面无法找到文件加工插件，插件列表中无对应选项。原因：部署时未安装对应版本的插件包，或FastGPT版本与插件版本不匹配。
- 现象：使用URL创建知识库时报错，后台日志显示`cannot fetch internal url`。原因：升级后未正确配置内部服务的访问地址，导致系统无法正常拉取内部资源。
- 现象：执行docker run命令部署图片解析组件时出现报错。原因：未正确指定GPU映射参数，或本地GPU驱动版本与镜像版本不兼容，导致组件无法正常启动。

## 怎么确认配好了
- 运行数据库连接测试脚本，验证配置的连接池规模可适配当前业务并发，阈值按实际生产中的数据流转量标定。
- 上传一份包含多页检测数据的轧制规程文档，确认文件上传与存储流程正常，无大小限制相关报错。
- 查看系统后台日志，确认缓存节点与存储端点的连接状态正常，无超时或权限异常提示。
- 测试通过内部数据源URL创建知识库的流程，确认资源拉取功能正常，无内部访问报错。
