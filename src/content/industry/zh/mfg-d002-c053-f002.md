# 钢铁冶炼与连铸的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来源包括铁水与废钢数据、L2过程控制系统、化验室检测数据、MES生产管理系统、能源介质系统与设备状态监测数据。更新节奏为每炉次生成炉次计划与配料单，实时同步转炉冶炼记录、连铸工艺数据，每班汇总板坯判定单与成分报告。文档包含固定字段，如炉次计划的浇次编号、钢种牌号，冶炼记录的冶炼时长、终点温度，字段单位包含摄氏度、吨、米每分钟等物理量。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时与每炉次的更新频率要求索引支持增量同步，避免全量重建带来的耗时与业务中断风险。文档多为结构化半结构化数据，分块需匹配文档的字段边界，避免拆分导致语义断裂。数据包含大量物理参数，向量模型需适配数值型特征的编码逻辑，确保检索精度。高温连续流程的业务特性要求索引具备高可用性，不能因配置问题导致检索中断影响生产调度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配转炉冶炼记录、连铸工艺记录的单条文档长度，避免语义拆分 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文，防止关键工艺参数被拆分在不同块中 |
| 相似度阈值 | 0.75–0.85 | 匹配钢铁成分、温度等数值型数据的匹配精度，过滤低相关结果 |
| 单次搜索上限 | 前 10 条 | 适配生产调度的检索需求，避免返回过多冗余数据 |
| `defaultToken` | 5000 token | 适配单条长文档的基础上下文长度，满足成分报告的完整读取 |
| `maxToken` | 12000 token | 适配连铸全流程记录的最大token数量，避免关键内容被截断 |

## 容易做错的三处
- 现象：自定义索引配置后检索结果为空。原因：未按照冶炼类文档的固定字段结构配置分块，误将长文档随机拆分导致语义断裂，无法匹配检索请求。
- 现象：检索请求返回超时。原因：未开启增量索引同步，每次检索都触发全量数据扫描，无法适配实时更新的炉次数据规模。
- 现象：向量模型调用返回参数错误。原因：未将成分、温度等数值型数据归一化处理，导致向量维度与配置要求不匹配。

## 怎么确认配好了
- 上传单条完整的转炉冶炼记录文档，检查分块预览界面，确认关键字段如终点温度、出钢量未被拆分到不同分块。
- 提交包含目标钢种成分参数的检索请求，查看检索结果的相似度得分，确认得分落在预设的阈值区间内。
- 模拟生成一条新的炉次异常报告，等待1分钟后提交检索请求，确认该报告已被索引并出现在结果列表中。
- 查看FastGPT v4.17.0的系统日志，确认向量模型调用的token消耗未超过`maxToken`的配置值，无截断报错。
