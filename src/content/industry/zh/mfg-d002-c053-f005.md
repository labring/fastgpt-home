# 钢铁冶炼与连铸的工艺文件与异常报告起草：工具调用与插件

FastGPT v4.17.0版本的配置需适配该品类的生产特征，以下为具体说明。

## 这个品类的数据长什么样
该品类的数据来源包括铁水与废钢入库数据、L2过程控制系统、化验室检测结果、制造执行系统、能源介质监控系统与设备状态监测系统。数据更新节奏为每炉次生成炉次计划与配料单，实时同步转炉冶炼、连铸工艺过程数据，每班汇总板坯判定单与异常记录。日常文档包含标准化字段，如炉次编号、铁水重量、吹炼时长、拉速、板坯厚度，对应单位分别为六位数字、吨、分钟、米每分钟、毫米。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的实时性与强耦合特征，要求工具调用需支持低延迟拉取L2过程控制的实时数据，避免使用超过10分钟的历史数据支撑工艺文件起草。多类型文档与固定字段结构，要求插件需预先匹配炉次计划、成分报告等文档的字段映射规则，无法直接适配无固定结构的通用文档。高温连续流程的特性，要求工具调用需在异常触发时快速生成处置建议，避免流程中断。数据更新频率高且来源分散，要求插件需整合多系统数据接口，避免单数据源缺失导致的起草失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 工具调用触发时机 | 按炉次计划生成后触发 | 匹配该品类按炉次组织生产的标准流程 |
| 单次工具调用超时时间 | 600 秒 | 适配多系统数据拉取的耗时需求 |
| `toolChoice` | 自动 | 允许模型自主选择适配工艺与异常场景的工具 |
| 文档字段映射插件 | 绑定板坯判定单与冶炼记录的固定字段 | 匹配该品类文档的标准化结构 |
| 最大上下文长度 | 8000–12000 token | 容纳多份炉次相关文档的完整内容 |
| `functionCall` | 开启 | 强制模型调用指定工具完成数据整合与文档生成 |

## 容易做错的三处
- 导入工艺文档时返回500错误。原因：未预先配置该品类文档的字段映射规则，或嵌入模型处理的文档长度超出适配范围。
- 调用第三方大模型时返回仅允许当前使用的报错信息。原因：未在平台中完成第三方模型的权限配置，或接口参数填写不符合要求。
- 联网工具拉取数据后结果为空。原因：未匹配该品类数据来源的接口格式，或超时时间设置过短导致数据未完整拉取。

## 怎么确认配好了
- 上传一份真实的炉次计划文档，检查嵌入后字段是否正确映射到插件预设的参数中。
- 触发工具调用，查看返回的工具调用日志，确认`toolChoice`自动选择了适配当前场景的工具。
- 调用第三方大模型时，验证接口返回的响应格式符合预设的插件调用要求。
- 模拟异常触发场景，检查生成的异常报告是否包含板坯判定单的相关字段。
