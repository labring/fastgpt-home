# 铸造（砂型、精密、压铸）的工艺文件与异常报告起草：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源包括ERP物料主数据、熔炼炉测温仪、光谱仪、MES炉次记录、模具管理系统、客户图纸与技术条件。数据更新节奏为每炉次、每批或每日，日常文档涵盖铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告、不合格品评审单。数据字段包含合金成分占比、熔炼温度、浇注时长、炉次号、模次、缺陷类型等，对应常规单位为摄氏度、秒、百分比等。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据按炉次、批次更新且分散在多个系统中，要求工具调用必须以炉次号作为唯一关联标识，避免跨批次数据混淆。多源数据的字段存在明确单位与固定格式，工具调用需精准匹配字段名与单位，防止参数错误。异常报告需追溯缺陷到对应炉次与模次，工具调用需同时对接模具管理系统、MES系统与质量记录系统，整合关联数据。数据异常会导致整炉报废或后续索赔，工具调用需增加前置参数校验环节。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | auto | 适配多工具动态选择，根据当前任务自动匹配所需的数据源与处理工具 |
| `functionCall` | enabled | 启用显式函数调用模式，确保工具调用的参数格式符合各系统接口要求 |
| 工具调用重试次数 | 2–3 次 | 应对临时网络波动或系统响应延迟，避免单次调用失败导致流程中断 |
| 多模态工具调用开关 | 开启 | 支持对铸造缺陷图像的识别，匹配多模态调用需求 |
| 上下文窗口上限 | 8000–12000 token | 容纳单炉次的全部记录、图纸与检验文档，避免内容截断 |
| 超时阈值 | 60 秒 | 适配熔炼参数获取的实时性要求，避免过长等待导致流程阻塞 |

## 容易做错的三处
- 现象为未获取到分段流式的生成内容，原因是未配置流式响应的回调链路，未启用流式输出的相关设置。
- 现象为生成的工艺文件中未包含当前炉次的熔炼时间参数，原因是未绑定获取实时参数的工具插件，未正确配置时间获取的调用逻辑。
- 现象为异常报告中缺陷类型与炉次不匹配，原因是未按炉次号作为关联键调用多系统数据，混入了其他批次的检验记录。

## 怎么确认配好了
- 发起模拟单炉次数据的工具调用请求，检查返回的合金配料比例、熔炼温度等参数是否与预设的ERP、熔炼炉数据一致。
- 上传铸造缺陷的示例图像，触发多模态工具调用，检查是否能识别缩孔、气孔等典型缺陷并关联对应炉次信息。
- 测试工艺文件生成流程，检查是否能分段返回流式输出内容，验证前端回调链路是否正常。
- 触发异常报告生成，检查是否能自动关联模具履历、首件检验记录等多系统数据，确保数据关联准确。
