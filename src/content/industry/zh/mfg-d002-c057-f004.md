# 锻造与模锻的工艺文件与异常报告起草：工作流编排

## 这个品类的数据长什么样
锻造与模锻的日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告。数据来源覆盖原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图。数据更新频率为每件、每批或每炉次，核心字段包含炉批号、锻造比、纤维方向、锻件尺寸、缺陷类型，单位涵盖毫米、摄氏度、吨等。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源涉及多套工业系统，工作流需支持跨系统数据拉取与字段映射，避免手动录入导致的错误。数据按单件、批次或炉次高频更新，工作流需支持单次触发式生成文档，确保每次生成的文件匹配最新的生产数据。日常文档结构多样，需按不同文档类型调用对应字段组合，例如工艺规程需绑定锻造比与加热区间，异常报告需关联无损检测缺陷数据。同时，出错后果直接关联锻件报废与服役安全，工作流需加入异常校验环节，确保关键字段完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量绑定规则 | 按炉批号、锻件批次关联`variables` | 数据按炉批与批次更新，需精准匹配对应生产环节的数据源 |
| 节点触发条件 | 接收`nodeId`为3的上游节点完成信号 | 需等待上游数据采集节点完成后再启动文档生成流程 |
| 超时阈值 | 600 秒 | 跨系统数据采集与文档生成需预留足够处理时间 |
| 异常触发规则 | 当`variables`中缺陷字段非空时触发 | 自动跳转至异常报告生成环节 |
| 模板字段映射 | 绑定下料卡的下料重量、加热炉的加热温度区间 | 匹配锻造工艺规程的必填字段要求 |

## 容易做错的三处
- 现象：调用发布后的工作流接口时，全局变量未生效，返回字段为空。原因：未在工作流配置中开启外部传入全局变量的权限，未将`variables`绑定到对应节点的参数入口。
- 现象：文本拼接结果与预设文档格式不一致，自定义变量未被正确替换。原因：未按锻造文档的字段命名规则配置`variables`，变量名与文档模板中的占位符不匹配。
- 现象：多层异常分支逻辑中断，无法按问题树推进异常处理流程。原因：未将`nodeId`按分支节点顺序绑定，上游节点未正确传递触发信号给下游分支节点。

## 怎么确认配好了
- 触发一次单炉次的锻造流程，检查工作流是否自动拉取对应加热炉记录、原材料质保书的字段到工艺文件模板。
- 模拟异常场景，如检测到折叠缺陷，确认是否自动跳转至异常报告生成节点，生成包含对应缺陷信息的超声检测报告。
- 调用外部发布接口，传入预设的`variables`参数，如锻件批次号、缺陷类型，检查返回的文档是否正确替换占位符。
- 查看FastGPT v4.17.0的工作流日志，确认`nodeId`触发顺序与预设的流程步骤一致，无超时或节点未执行情况。
