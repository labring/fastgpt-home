# 锻造与模锻的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
锻造与模锻的核心数据来自原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图。日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告。数据按每件锻件、每批物料或每炉次更新，字段包含炉批号、锻造比、加热温度、压力吨位、检测缺陷类型等，单位涉及摄氏度、吨、次等专业参数。

## 这些特征在「引用来源与溯源」这一环带来什么约束
锻造与模锻的数据按炉批号、批次绑定，引用溯源需精准匹配单炉次或单批次的关联数据，避免跨批次混淆。日常文档类型多且专业字段复杂，需准确识别工艺规程、检测报告等不同文档的专属标识。不同于铸造的凝固缺陷控制，锻造需严格控制金属流线与锻造比，因此溯源需关联原材料与加工过程的全链路数据。编制变形工步、加热区间及核对炉批批次是日常最耗时环节，溯源逻辑需支持快速检索关联数据源。一旦溯源出错，可能导致锻件报废、疲劳寿命不足或关键承载件服役断裂，因此需保留完整的引用链路与元信息。

## 配置怎么定
本页配置基于FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配锻造工艺文档的单段常规长度，避免截断关键参数 |
| `quoteMaxToken` | 1500 token | 覆盖典型异常报告中引用的多段数据源内容长度 |
| `responseData` | 开启 | 保留原始数据源的完整元信息，包括炉批号、检测编号等标识 |
| `detail` | 开启 | 展示引用来源的具体字段与对应批次信息，便于人工核对 |
| 单次搜索上限 | 前6条 | 匹配每炉次关联的加热、压力、检测等数据源的合理数量 |

## 容易做错的三处
- 现象：选择知识库后变量引用无可选值，原因：未将数据源的炉批号、批次号等字段配置为可引用变量，或未绑定对应知识库的字段映射规则
- 现象：控制台报错Cannot redefine property: toString，原因：自定义引用逻辑与平台内置的toString方法冲突，未正确隔离函数执行上下文
- 现象：引用结果包含无关批次的数据源，原因：未以炉批号作为核心检索关键词，仅使用通用文本匹配导致结果混杂

## 怎么确认配好了
- 输入指定锻件的炉批号，核对检索返回的数据源是否仅包含该炉次的加热炉记录、压力机数据与检测报告
- 查看对话生成的工艺文件或异常报告，确认每处引用都标注了来源文档类型、编号与对应批次信息
- 运行测试用例触发异常报告起草流程，检查无`Cannot redefine property`类报错
- 调整引用参数，验证`quoteMaxToken`的取值是否影响引用内容的完整性
