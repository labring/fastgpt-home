# 锻造与模锻的工艺文件与异常报告起草：模型接入与配置

## 这个品类的数据长什么样
该品类数据来自原材料质保书、加热炉系统、压力机采集系统、MES系统、无损检测仪及客户锻件图。日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告。数据按每件/每批、每炉次更新，文档包含锻造比、纤维方向、炉批号、锻件尺寸等专业字段，单位涵盖毫米、摄氏度、吨等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据按炉次、批次高频更新，且来源覆盖多套工业系统，要求模型接入需支持按批次拉取关联数据，避免跨批次数据混淆。多源异构的文档结构与专业工艺字段，需模型接入配置适配金属成形领域术语的理解能力。高频更新的单炉次数据量波动较大，要求配置项需支持灵活调整上下文长度，适配不同批次的数据token规模。同时，异常报告需快速关联原材料质保书、无损检测结果等跨文档数据，需配置支持多文档上下文联动的参数。

## 配置怎么定
本配置指南适用于FastGPT v4.17.0版本，以下为针对锻造与模锻场景的具体配置项建议：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写对应大模型服务商的工业场景专属接入地址 | 适配锻造车间多系统的数据接口权限与格式要求，避免通用接口的兼容性问题 |
| `AIPROXY_API_TOKEN` | 填写厂商分配的专属鉴权令牌 | 确保多源生产数据的权限隔离，防止未授权访问核心工艺数据 |
| `maxContext` | 8000–12000 token | 适配单炉次锻造工艺文档与检测报告的总token规模，避免上下文内容被截断 |
| `maxTokens` | 4000–6000 token | 满足异常报告起草时的长文本输出需求，覆盖完整的工艺整改与缺陷分析内容 |
| `temperature` | 0.2–0.4 | 控制工艺文档生成的严谨性，避免金属成形专业术语的随意变更 |
| `quoteMaxToken` | 1000–1500 token | 限制引用的单份文档token数，确保上下文关联的精准性，减少无关数据干扰 |

## 容易做错的三处
- 现象：调用大模型时返回「请求不兼容」报错，无法生成工艺文件或异常报告。原因：未针对锻造场景配置适配的模型输入格式，未对齐工业文档的字段结构与专业术语要求。
- 现象：Docker Compose部署后无法找到oneapi相关配置入口，无法接入内部大模型服务。原因：未在部署配置中添加`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的环境变量声明，导致配置项缺失。
- 现象：生成的异常报告文本被提前截断，仅输出前4000 token的内容。原因：未调整`maxTokens`参数，沿用默认的4000 token上限，未适配长文本起草的实际需求。

## 怎么确认配好了
- 查看模型接入日志，确认多源工业数据可以按炉次拉取并完成关联，验证数据接入的正确性。
- 提交一份典型的单炉次锻造工艺文档，检查模型输出的文本长度符合预期，确认`maxTokens`配置生效。
- 调用异常报告起草功能，查看返回结果中是否包含锻造比、纤维方向等专业工艺字段，验证模型的领域适配性。
- 检查Docker Compose的环境变量配置文件，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`已正确声明，验证鉴权配置生效。
