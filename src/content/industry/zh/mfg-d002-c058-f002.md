# 预制混凝土构件的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
预制混凝土构件相关数据来自BIM或深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检测报告及二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据更新随单件构件、每批物料或每窑养护流程触发，无固定周期。文档包含精准的几何尺寸、物料参数、工序节点记录等字段，部分字段关联现场吊装位置信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的多类型结构化/半结构化文档、非固定周期的更新节奏及关联现场位置的字段特征，对向量模型与索引环节带来多重约束。多样化的文档格式需要适配的分块规则，避免拆分破坏构件几何参数或工序关联逻辑。非固定更新频率要求索引系统支持按单件、批次或窑次触发增量更新，不采用全量重建的方式。关联现场吊装位置的字段需要在向量编码时保留关联关系，避免检索时丢失位置匹配能力。同时，数据出错会导致严重生产损失，要求索引召回的精度需匹配工序校验需求。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本的向量模型与索引模块。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配构件深化图、下料单等文档的文本密度，避免拆分破坏工序关联逻辑 |
| 重叠长度 | 50–100 字符 | 保留相邻分块的上下文关联，避免关键工序节点被拆分到不同块中 |
| 相似度阈值 | 0.75–0.85 | 匹配预制混凝土构件工艺数据的校验精度需求，过滤低关联的冗余记录 |
| 单次搜索上限 | 前 10 条 | 兼顾检索效率与召回覆盖，满足工艺文件与异常报告的多维度校验需求 |
| maxToken | 8192 | 适配主流大语言模型的上下文窗口限制，完整承载构件参数与工序记录的关联信息 |
| defaultToken | 2048 | 平衡单条向量的信息密度与检索速度，适配批量数据的向量化处理 |

## 容易做错的三处
- 现象：向量化任务报错，日志显示速率超限。原因：未结合该品类单件、每批的更新节奏调整向量化并发配置，导致短时间内发起过多请求超出服务限制。
- 现象：知识库检索响应耗时超出预期。原因：未适配该品类的多类型文档调整分块与索引配置，导致单批次召回的向量数据量过大，增加检索负载。
- 现象：索引任务长期处于“索引中”状态，无法就绪。原因：未配置合理的分块长度，导致单条分块数据过长，向量编码与索引构建耗时超出阈值。

## 怎么确认配好了
- 上传单份典型文档组合（如构件深化图搭配钢筋下料单），验证分块结果未破坏关键工序或几何参数的关联逻辑。
- 模拟批量数据向量化，观察任务队列的并发状态与速率，确认未触发超限报错。
- 发起工艺文件校验类检索，核对召回结果的数量与关联度，调整阈值至符合业务校验需求。
- 查看数据集索引条目，确认增量更新仅新增最新批次的构件数据，无重复索引条目。
