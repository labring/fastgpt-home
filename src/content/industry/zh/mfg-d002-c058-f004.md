# 预制混凝土构件的工艺文件与异常报告起草：工作流编排

## 这个品类的数据长什么样
本品类数据来自BIM深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行日志、试验室检验报告及构件二维码追溯系统。日常生成的文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据更新节奏随单件构件、每批物料或每窑养护流程触发，文档字段包含构件编号、钢筋规格、浇筑强度、养护时长、检验结果等，单位涵盖毫米、兆帕、小时、批次号等。

## 这些特征在「工作流编排」这一环带来什么约束
因数据来源分散且更新触发节点多样，工作流需支持多源数据拉取触发，避免遗漏单件、每批或每窑的更新内容。构件深化图需拆分为构件与预埋件清单，工作流需配置拆分节点匹配不同构件类型的拆解规则。钢筋、套筒与预埋位置的核对需关联多维度数据，工作流需嵌入跨文档字段校验环节。异常报告需关联追溯数据，工作流需绑定二维码溯源信息，确保异常记录与对应构件一一对应，防止错位、强度不足等问题引发报废或工期延误。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定构件编号、钢筋批次号、养护窑ID | 匹配本品类按单件、每批、每窑的更新节奏，关联多源分散数据 |
| `nodeId` | 绑定深化图拆分节点、数据校验节点、报告生成节点 | 明确各环节的执行顺序与依赖关系，避免流程混乱 |
| 文件上传节点超时时间 | 600秒 | 适配大型构件深化图、批量检验记录的上传时长 |
| 单文件上传上限 | 1000 MB | 适配大型BIM深化图的存储需求 |
| 上下文窗口大小 | 800–1200 token | 适配单份检验报告与溯源数据的拼接长度 |
| 知识库绑定 | 预制混凝土构件工艺知识库 | 覆盖深化图拆解、工艺标准、检验规范等专属文档 |

## 容易做错的三处
- 工作流上传文件时弹出Failed to create post presigned url报错，原因是未配置正确的对象存储密钥与权限，或节点超时设置过短导致上传中断。
- 知识库搜索模块的变量引用未正确绑定构件编号，导致搜索结果匹配错误的工艺文件，原因是未将`variables`中的构件编号字段与搜索参数关联。
- 工作流未配置跨文档校验节点，导致钢筋下料单与深化图的预埋件位置不一致，引发后续生产异常，原因是未嵌入跨源数据核对环节。

## 怎么确认配好了
- 触发一次单件构件的生产节点，检查工作流是否自动拉取对应深化图、下料单与检验记录。
- 模拟上传大型构件文件，确认文件上传节点在600秒内完成且无报错。
- 调整`variables`中的构件编号，检查知识库搜索结果是否随编号变化而更新。
- 查看工作流日志，确认`nodeId`对应的各环节按预设顺序执行，无跳过或重复。
