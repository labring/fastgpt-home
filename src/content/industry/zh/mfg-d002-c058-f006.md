# 预制混凝土构件的工艺文件与异常报告起草：引用来源与溯源

## 这个品类的数据长什么样
预制混凝土构件的日常数据来源包括BIM深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检验报告、出厂二维码追溯数据。数据更新节奏为单件构件、每批次物料、每窑养护周期对应一次更新。典型文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告，字段包含构件编号、钢筋直径、混凝土强度等级、养护时长、模台编号等，单位多为毫米、立方米、小时、兆帕。

## 这些特征在「引用来源与溯源」这一环带来什么约束
预制混凝土构件的单件性与批次关联性要求溯源信息必须精准到单构件或单批次，避免跨批次混淆。异构文档类型（从图纸到台账）需要溯源系统能关联不同文档中的同一构件编号与物料批次。高频更新的特性要求溯源数据能实时匹配最新的养护、检验记录，确保异常报告起草时使用最新有效数据。同时，出错后果严重的业务特性要求溯源信息必须完整覆盖从设计到出厂的全流程，确保可追溯所有关键环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `quoteMaxToken` | 1200–1800 token | 预制混凝土构件的工艺文档与溯源数据内容较长，需覆盖完整的批次与检验信息 |
| `responseData` | 包含文件路径与构件编号 | 需明确标注溯源文档的存储位置与对应构件的唯一标识 |
| `detail` | 开启 | 需展示溯源文档的完整字段，如钢筋批次号、养护窑编号、脱模强度值 |
| 分块长度 | 4000–5000 字符 | 预制混凝土构件的文档包含大量图纸参数与批次信息，需保证单块内容完整 |
| 单次召回条数 | 前6–8条 | 预制混凝土构件的溯源数据分散在多个记录中，需覆盖设计、生产、检验全流程 |
| 超时等待时长 | 30–60 秒 | 预制混凝土构件的文档包含大量图纸数据，需保证足够的检索时间 |

## 容易做错的三处
- 现象：检索到知识库切块但返回结果无文件来源地址。原因：未开启`responseData`配置项，未指定返回溯源信息的关联字段。
- 现象：引用内容被截断，丢失关键的养护时长或强度等级信息。原因：未根据预制混凝土构件的文档长度调整`quoteMaxToken`取值，沿用通用场景的较小阈值。
- 现象：多知识库搜索后，不同来源的溯源数据无法关联到同一构件。原因：未在配置中指定统一的构件编号作为关联字段，导致不同知识库的检索结果无法匹配。

## 怎么确认配好了
- 发起包含具体构件编号的查询，检查返回结果中是否包含对应文档的路径与字段信息。
- 调整`quoteMaxToken`为测试阈值，验证返回的引用内容长度符合预期设置。
- 模拟异常报告起草场景，确认检索结果中同时包含浇筑记录、养护记录等多类溯源文档。
