# 预拌混凝土生产的工艺文件与异常报告起草：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来自工程订单、砂石水泥外加剂检验报告、骨料含水率测定数据、搅拌站生产控制系统日志与试验室试验记录。日常文档包含配合比通知单、开盘鉴定、生产运输单、原材料检验记录、试块成型记录与强度报告。配合比通知单标注胶凝材料、骨料、用水量（单位：千克/立方米），开盘鉴定记录搅拌时长（单位：秒），试块记录标注成型日期与养护条件，强度报告标注龄期与抗压强度（单位：兆帕）。数据更新频率为每车生产任务、每批原料进场、每日试验室检验。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。高频更新的生产与检验数据，要求索引支持增量同步逻辑，避免全量重建带来的处理延迟。多源分散的数据源格式，要求索引兼容生产控制系统日志、试验室试验记录、工程订单等不同结构的文档。带特定单位的结构化字段，要求向量模型适配数值与单位组合的语义，避免纯文本处理带来的偏差。跨文档关联的检索需求，要求索引支持配合比、检验记录与试块数据的联动匹配，同时需限制单批次检索的返回范围，避免超出`defaultToken`的配置容量。

## 配置怎么定
本配置基于FastGPT v4.17.0

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类长文本的配合比与试块记录，覆盖完整语义单元，避免语义割裂 |
| 重叠长度 | 100–150 字符 | 保持短文档（如生产运输单）的上下文关联，避免分块截断关键信息 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 8192 | 覆盖异常报告起草时整合多份检验记录与生产数据的最大容量需求 |
| 相似度阈值 | 0.75–0.85 | 精准匹配配合比与检验数据，避免低匹配度的无关数据干扰 |
| 单次搜索上限 | 前 6 条 | 仅返回核心关联数据，减少上下文处理负担 |

## 容易做错的三处
- 现象：自定义索引配置后检索结果无匹配内容，结果条数为0。原因：未按照该品类的文档字段结构设置分块规则，导致分块后的文本无法匹配检索语义。
- 现象：接入腾讯混元向量模型后调用返回认证错误。原因：未按照模型要求配置接口参数，未适配该品类数据的字段格式。
- 现象：接入外部向量数据库后无法同步实时生产数据。原因：未适配该品类每车、每批原料的高频更新节奏，增量同步逻辑未匹配实际更新频率，导致数据滞后。

## 怎么确认配好了
- 上传单份配合比通知单与对应生产运输单，发起检索，核对返回结果是否包含关联的原材料检验记录。
- 查看索引同步记录，确认每车生产任务、每批原料进场后，索引是否完成增量更新。
- 调整相似度阈值，验证检索结果的匹配度是否适配工艺文件与异常报告的起草需求。
- 测试`defaultToken`与`maxToken`的配置，确认多份关联文档拼接后的检索内容无截断。
