# 饮料与瓶装水的工艺文件与异常报告起草：工作流编排

## 这个品类的数据长什么样
该品类日常文档包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验、成品检验。数据来源为水源与原料检测、配方系统、在线糖度酸度监测、灌装设备、视觉检测系统及LIMS系统。数据更新节奏为每批、每班或连续采集，单份文档字段涵盖投料参数、水质指标、灌装参数、检验结果、批号与保质期等，单位涉及kg、°Brix、℃、mm、bar等。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据多源且更新节奏差异大，工作流编排需适配多数据源的定时拉取与实时同步逻辑。文档字段含特定单位与批次绑定属性，工作流需配置字段校验规则，确保投料参数、水质指标等符合预设范围。高速灌装与多产品切换的特性，要求工作流支持快速切换配置参数，同时需关联批号实现异常报告与对应生产数据的精准绑定。连续采集的实时数据需工作流具备低延迟处理能力，避免异常信息积压延误处理。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量配置 | 绑定`variables`为批次号、糖度值、杀菌温度等字段 | 适配品类文档的固定字段结构，支持动态调用生产数据 |
| 节点ID设置 | 为每个数据源与处理节点分配唯一`nodeId` | 便于精准定位异常环节，排查日志时可快速关联对应组件 |
| 数据源同步周期 | 实时触发、每15分钟、每批触发三类 | 匹配不同数据的更新节奏，水处理记录用实时，配方单按每批同步 |
| 字段校验规则 | 校验`variables`绑定的参数区间与单位格式 | 避免配方或添加剂超限的出错风险 |
| 异常触发阈值 | 灌装液位偏差±2mm、封口压力偏差±0.1bar | 贴合高速瓶装水灌装的工艺参数要求 |
| 日志留存时长 | 7天 | 满足异常排查的日志查阅需求 |

## 容易做错的三处
- 现象：工作流运行后异常报告的落款时间字段为空。原因：未正确配置提示词中使用`{{平台的时间变量}}`，未绑定系统当前日期的变量调用规则。
- 现象：查看MCP服务日志时无法定位具体环节。原因：未为每个节点分配唯一`nodeId`，导致日志无法精准关联对应组件。
- 现象：同任务的对话工作流调试速度慢于直接调用。原因：未按数据更新节奏配置数据源同步周期，工作流反复拉取冗余历史数据，增加处理耗时。

## 怎么确认配好了
- 进入工作流的变量配置界面，确认已绑定批次号、糖度值等品类专属字段。
- 检查各处理节点的`nodeId`，确认每个节点的ID唯一且可对应到具体生产环节。
- 提交一次模拟生产数据，验证异常报告的落款时间与系统当前日期一致。
- 打开MCP服务日志面板，确认可查看对应节点的详细运行信息。
