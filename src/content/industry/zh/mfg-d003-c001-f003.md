# PCB制造的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
PCB制造的工艺与标准问答关联的数据，来源涵盖客户交付的Gerber文件、钻带、BOM清单，以及工厂内部CAM系统数据、设备运行参数、槽液化验结果、AOI与电测报告、切片分析记录等。日常文档包含工程制作指示、钻孔层压工艺参数、药水配比记录、品质检测报告等。数据更新随生产批次、班组班次实时或连续采集，不同业务岗位对应不同维度的业务数据字段，无统一固定的通用文档结构，需按具体业务环节匹配对应数据项。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
PCB制造的数据来源分散且覆盖多业务环节，多轮对话需按上下文关联不同岗位的业务数据，提示词需明确指定数据所属的生产模块。数据随生产批次、班次更新，提示词需包含批次维度的参数校验逻辑，避免引用过期记录。文档结构无统一格式，多轮对话需逐步引导用户明确数据对应的工序与批次，避免混淆不同环节的参数。连续采集的实时数据要求对话系统支持动态加载最新记录，提示词需限定查询的时间范围，防止返回冗余信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 适配PCB制造多工序关联数据的上下文长度，避免超出模型处理上限 |
| 单次召回条数 | 前6条 | 匹配单工序数据的典型条目数，减少冗余信息干扰 |
| `variables` | 按生产批次、工序类型预设 | 用于绑定对话中的批次与工序参数，确保查询指向准确的业务数据 |
| 对话历史截断阈值 | 最后20轮对话 | 聚焦当前生产环节的上下文，避免历史数据混淆当前查询 |
| `messages` | 按业务环节顺序拼接 | 确保多轮对话的上下文按PCB制造的工艺逻辑组织，提升信息匹配精度 |
| `chatId` | 绑定生产批次编号 | 隔离不同生产批次的对话上下文，避免跨批次数据混淆 |

## 容易做错的三处
- 对话返回结果末尾出现未定义的格式符号，无法通过常规操作关闭。原因是未在提示词中配置结果收尾规则，FastGPT v4.17.0版本的默认输出逻辑会追加系统校验标识。
- 多轮对话中查询的工艺参数或检测报告内容显示不全。原因是提示词未限定查询的生产批次与工序范围，导致模型调用了跨批次的冗余数据，超出上下文处理上限。
- 对话请求长时间无响应，返回超时状态码。原因是未按生产批次绑定`chatId`，导致单对话加载过多PCB制造的历史数据，超出系统处理时长限制。

## 怎么确认配好了
- 发起包含生产批次与工序关键词的多轮对话，检查返回结果是否仅关联对应批次的工艺参数与检测数据。
- 查看对话上下文的截断逻辑，确认仅保留最近指定轮次的对话内容，无冗余历史信息干扰当前查询。
- 验证`variables`参数是否能正确绑定对话中的批次与工序变量，确保每次查询都指向准确的业务数据。
- 检查提示词配置，确认未包含未定义的格式规则，结果末尾无额外的系统校验符号。
