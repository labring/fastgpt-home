# SMT贴片与电子组装的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
这个品类的核心数据来自客户交付的BOM、Gerber坐标文件、MES系统、贴片机、SPI/AOI检测设备与回流焊炉温记录等。日常维护的文档包含换线表、钢网使用记录、首件确认报告、焊点缺陷分析报告、元件追溯标签等。数据更新节奏为每生成一张工单、每次产线换线时实时更新，单份文档包含料号、位号、元件批次、炉温曲线参数、贴装坐标等结构化与半结构化字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时更新的工单数据要求索引支持增量构建与快速同步，避免全量索引带来的性能损耗。多类型文档混合的场景要求向量模型同时适配文本与数值类字段的语义编码，确保料号、坐标等关键信息的向量表达准确。高频的换线与工单更新会产生大量增量数据，需要合理规划索引分片以平衡检索速度与存储占用。同时，业务中需要精准匹配料号、位号等强关联字段，对向量召回的精度提出了较高要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配单份BOM、炉温记录等文档的常规长度，避免关键参数被跨块拆分 |
| 重叠长度 | 100–200 字符 | 覆盖换线表、首件报告中跨块的关联信息，防止料号与对应贴装要求分离 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 匹配SMT场景中料号、位号的精准匹配需求，减少非关联数据的误召回 |
| `defaultToken` | 4096 | 承载单份完整工艺规程的上下文，满足长文档的向量编码需求 |
| `maxToken` | 8192 | 支持整合多份SPI/AOI报告、维修记录的关联分析，适配复杂查询的上下文长度 |
| 单次搜索上限 | 前10条 | 覆盖单工单下多份关联文档的检索需求，避免冗余数据占用上下文空间 |

## 容易做错的三处
- 现象：向量索引构建超时，返回504状态码。原因：未配置增量索引模式，全量索引处理了历史积累的大量工单数据，超出系统处理阈值。
- 现象：检索结果中出现非本次工单的元件批次信息。原因：相似度阈值设置过低，召回了超出业务范围的历史数据，不符合换线防错的精准需求。
- 现象：外部索引模型接入后无有效返回结果。原因：未按FastGPT v4.17.0的接口规范配置模型调用参数，导致请求超时或字段格式不匹配。

## 怎么确认配好了
- 上传一份完整的工单BOM与首件确认报告，检查向量索引生成状态是否显示为已完成。
- 输入包含具体料号与贴装要求的查询语句，核对检索结果是否包含对应文档的关键参数。
- 模拟一次实时换线数据的上传，检查索引是否在预设时间内完成更新。
- 查看向量数据库的存储占用情况，确认符合当前产线数据的更新规模。
