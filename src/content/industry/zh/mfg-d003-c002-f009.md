# SMT贴片与电子组装的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
SMT贴片与电子组装的业务数据来自客户提供的BOM、Gerber文件、元件坐标表，以及MES系统、贴片机、SPI/AOI检测设备、回流焊炉的实时采集数据。日常文档包含工单级BOM、换线表、钢网参数记录、炉温曲线报告、首件确认单、缺陷维修记录及追溯标签。数据按每工单、每次换线实时更新，字段包含料号、位号、元件批次、炉温设定值与实测值、坐标偏移量等，单位涵盖毫米、摄氏度、批次编号等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类数据按工单、换线实时更新，单次工艺问答需关联多份短周期文档，因此模型接入时需限定上下文覆盖范围，避免冗余数据干扰。数据包含结构化表格、坐标文件、温度日志等多格式内容，模型配置需适配多类型文档的解析逻辑。工艺问答需精准引用原始文档片段，避免无依据推导，因此需配置参数锁定原文引用的提取规则。换线与工单切换频繁，多轮对话需绑定当前工单上下文，避免跨工单数据混淆，同时需控制模型调用频率，适配设备数据的实时采集节奏。

## 配置怎么定
本文档适配FastGPT v4.17.0版本，以下配置项基于业务特征制定：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单工单内的BOM、换线表、炉温报告等多份文档的总长度，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 满足工艺问答中缺陷分析、参数调整的完整回复需求，避免截断关键说明 |
| `quoteMaxToken` | 1500–2000 字符 | 限定单条引用的原始文档片段长度，确保回复中引用的内容完整且不占用过多上下文 |
| `temperature` | 0.1–0.3 | 工艺规程问答需精准匹配标准参数，较低的温度值可减少模型的随机性输出，避免错误推导 |
| `AIPROXY_API_ENDPOINT` | 按部署节点的实际接口地址填写 | 适配本地部署的FastGPT节点，确保模型调用的路由正确 |
| `AIPROXY_API_TOKEN` | 按平台生成的专属令牌填写 | 验证模型调用的身份合法性，避免未授权访问 |

## 容易做错的三处
- 现象：本地部署FastGPT新增模型后测试返回403 status code (no body)。原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致身份验证失败或路由指向错误。
- 现象：尝试接入GPT-5模型时，渠道配置界面无对应选项，无法完成接入。原因：未通过自定义`AIPROXY_API_ENDPOINT`配置第三方兼容接口，依赖平台内置的渠道选项导致无法适配。
- 现象：调用MySQL业务数据后，回复未包含数据库原文片段。原因：未配置`quoteMaxToken`参数或参数取值不符合文档片段长度要求，无法提取并返回完整的原始内容。

## 怎么确认配好了
- 执行单工单的工艺问答测试，核对回复中是否包含指定的原始文档片段，确认`quoteMaxToken`的取值符合当前文档的长度要求。
- 发起多轮连续问答，核对模型是否能关联当前工单的历史数据，确认`maxContext`的范围适配当前业务场景。
- 检查模型调用的日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置未出现格式错误，无身份验证失败的报错。
- 调整`temperature`参数后发起缺陷分析问答，核对回复的一致性，确认参数取值符合工艺问答的精准性需求。
