# 仓储、批次与厂内物流的工艺规程与技术标准问答：工具调用与插件

## 这个品类的数据长什么样
通常该品类的数据覆盖原材料库、线边库、成品库及物控部门的日常流转记录，包含收货单、上架单、领退料单、批次台账、盘点表等文档。数据主要来自ERP/WMS系统、条码或RFID采集设备、生产工单、库位配置、AGV输送系统与称重设备。更新节奏涵盖实时同步库位变动、每日更新批次效期与库存数量、月度完成全量盘点核对。核心字段包含物料编码、批次号、库位编码、效期日期、检验状态与流转数量，单位多为件、托盘或千克。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散且更新节奏差异大，工具调用需适配ERP、WMS、采集设备等多种数据源的接口格式，需针对性配置请求参数以匹配不同系统的字段规则。核心字段如批次号、效期的准确性直接影响业务合规性，因此插件需严格校验返回字段的存在性与格式。实时类数据的调用需设置合理超时阈值，避免因AGV或称重设备的临时延迟导致流程中断；月度盘点类数据可降低调用频率，减少资源消耗。同时，物料流转的全链路追溯要求工具返回结果需关联工单与库位信息，确保数据可交叉验证。本场景的配置基于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `functionCall` | 强制启用 | 确保工具调用返回结构化数据，可直接提取批次、库位等核心业务字段 |
| 请求超时时间 | 30–60 秒 | 适配ERP、WMS接口的常规响应时长，避免因网络延迟导致流程中断 |
| 批量返回上限 | 前20条 | 匹配仓储台账单次查询的合理规模，防止返回数据过多占用上下文 |
| 字段校验规则 | 校验批次号、效期字段 | 确保返回数据包含仓储业务必需的核心信息，避免无效结果 |
| 重试触发条件 | 超时或5xx状态码 | 应对接口临时抖动或服务不可用的场景，提升调用稳定性 |

## 容易做错的三处
- 现象：工作流中执行MCP工具调用后，后续节点无法获取返回的库位或批次数据。原因：未在工具配置中启用结果输出到上下文的开关，导致工具返回的结构化数据未被写入工作流变量池。
- 现象：调用HTTP接口获取仓储盘点的PPT格式报告后，无法将文件交付给提问用户。原因：未配置文件存储与返回插件，仅将二进制响应内容存入上下文，未生成可访问的文件链接。
- 现象：调用ERP接口查询物料批次信息时，工作流统计的token消耗与实际API调用的token消耗不一致。原因：工具调用的前置提示词包含冗余业务文本，未做精简处理，额外的非查询内容被计入token消耗。

## 怎么确认配好了
- 触发一次工具调用，查看返回结果是否包含批次号、库位编码等核心业务字段，确认字段校验配置生效。
- 模拟接口超时或5xx状态码，查看是否触发预设的重试机制，确认重试配置生效。
- 查看工作流变量池，确认工具调用的返回数据已被正确写入，确认结果透传配置生效。
- 触发文件存储插件调用，查看是否生成可访问的文件链接，确认文件交付配置生效。
