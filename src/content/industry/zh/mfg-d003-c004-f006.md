# 仓储、批次与厂内物流的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
本品类数据覆盖原材料库、线边库、成品库及物流物控部门的日常运营信息，日常文档包含收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录。数据通常来自ERP/WMS系统、条码或RFID设备、采购与工单数据、库位信息、AGV或输送系统、称重数据。更新节奏分为实时（如库位变动）、每日（如领退料统计）、月度盘点（如账实核对），字段包含物料编码、批次号、库位、效期、检验状态等，无统一固定单位，随文档类型调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且实时性要求不同，需精准匹配对应文档的更新时间戳，避免引用过期的盘点数据。批次与效期字段是核心溯源依据，需确保引用内容包含完整的批次号与库位信息，否则无法完成物料流向追溯。日常文档数量多且字段差异大，需限定引用范围仅覆盖仓储物流相关文档，防止混入非品类数据。启用`detail`参数时，需确保知识库分块保留核心字段，否则溯源信息将缺失关键内容。FastGPT v4.17.0的溯源功能需适配本品类的多维度数据特征，否则无法满足账实核对与批次追溯的需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 仓储物流文档单条内容通常较长，需覆盖完整批次、库位等关键字段 |
| `responseData` | 开启完整溯源模式 | 需返回知识库ID与文档路径，匹配账实核对的追溯需求 |
| `detail` | 设为`true` | 启用详细溯源信息，包含文档更新时间与字段详情，满足批次流向追溯要求 |
| 文档召回范围 | 仅选择仓储物流类知识库 | 避免混入非品类数据，确保溯源内容精准 |
| 单次召回上限 | 前5条 | 控制返回内容体量，防止冗余信息干扰核心追溯逻辑 |
| 上下文窗口大小 | 10000 字符 | 适配多批次、多库位的连续追溯场景 |

## 容易做错的三处
- 对话返回结果未显示知识库ID或文档路径。原因：未开启`responseData`配置，或未在知识库设置中启用溯源开关。
- 引用的文档与实际查询的仓储物流内容不符，混入了生产工单文档。原因：未限定文档召回范围为仓储物流类知识库，召回了非目标品类的内容。
- 启用`detail`参数后返回字段缺失。原因：未在知识库分块时保留批次号、效期等核心字段，导致溯源信息不完整。

## 怎么确认配好了
- 发起一次仓储物流相关的查询，查看返回结果中是否包含知识库ID与文档路径。
- 检查返回的溯源信息中是否包含批次号、库位等核心字段，确认与查询内容匹配。
- 调整单次召回上限，验证返回的引用文档数量符合预期设定。
- 查看知识库的配置列表，确认仅仓储物流类知识库被纳入当前应用的召回范围。
