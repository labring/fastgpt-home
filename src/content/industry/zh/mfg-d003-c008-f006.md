# 化妆品生产的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
该品类数据来自注册备案配方、原料安全资料、称量乳化设备、ERP/MES系统、实验室检测记录及包材版本文件。日常文档包含配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品与成品检验报告及标签审核文档。数据更新频率为每批生产或每次换线时触发，文档字段包含原料配比、工艺参数、检验指标、批号、包材信息等，字段单位随文档类型灵活变化，无统一固定格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
每批换线的高频更新要求溯源数据必须匹配当前生产批次的最新版本，避免引用过期文档导致工艺偏差。多源异构的文档类型需要溯源系统支持识别不同文档的字段格式，比如配方工艺单的原料配比字段与检验报告的微生物指标字段需分别关联对应溯源路径。单次生产涉及多环节文档，需确保引用的来源能覆盖投料、乳化、检验全流程，且不能遗漏批次关联信息。同时，化妆品备案合规要求溯源数据需可追溯至官方注册备案文件，避免引用未合规的内部文档。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 化妆品生产单批次核心工艺与检验文档的token总量多在此区间，可覆盖关键溯源内容，避免截断重要参数 |
| `responseData` | 返回引用来源详情 | 需在回复中展示文档名称、批次、更新时间等溯源字段，满足合规复核与工艺追溯需求 |
| `detail` | 开启 | 可提取文档中的具体参数如乳化温度、原料投料量，支撑工艺问答的精准溯源 |
| 单次搜索上限 | 前6条 | 单批次生产涉及的核心文档不超过6份，过多引用会导致上下文冗余，影响问答逻辑 |
| 最大上下文 | `2000–3000 字符` | 覆盖多环节文档的关联内容，确保问答中工艺逻辑的连贯性 |

## 容易做错的三处
- 现象为调试页面显示引用文档列表，但正式聊天页面引用字段为空。原因是未开启`responseData`对应的返回配置，仅在调试模式下加载溯源数据，正式环境未同步启用该设置。
- 现象为文本内容提取组件无法选择知识库引用作为数据源。原因是组件默认仅支持原生文本输入，未关联知识库溯源模块的输出字段，无法获取引用文档的内容。
- 现象为引用条数超过预设限制但未触发截断。原因是未正确配置`quoteMaxToken`参数，或取值区间未匹配单批次文档的总token量，导致条数限制未生效。

## 怎么确认配好了
- 发起针对单批次化妆品生产工艺的问答，检查回复末尾是否展示关联文档的名称、批次号等溯源信息。
- 调整`quoteMaxToken`参数取值，验证回复中引用的文档条数是否随配置变化，确认条数限制生效。
- 进入调试模式，触发问答后查看返回的`responseData`字段，确认包含完整的溯源文档列表。
- 使用文本内容提取组件，选择知识库引用作为数据源，验证组件能否提取引用文档中的具体字段内容。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
