# 化妆品生产的工艺规程与技术标准问答：文档解析与分块

本页面适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类数据来自护肤、洗护、彩妆及特殊化妆品生产企业的注册备案配方、原料安全资料、称量乳化设备、ERP/MES系统、实验室记录与包材版本文件。日常文档包含配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品成品检验报告与标签审核文件，字段含原料名称、配比、操作温度、批号、检验指标等，单位涉及克、毫升、摄氏度、批次号，更新频率为每批生产或每次换线时触发。

## 这些特征在「文档解析与分块」这一环带来什么约束
高频更新的生产文档要求解析流程适配批量快速处理，避免拖慢工艺问答的响应速度；多类文档结构差异显著，需精准匹配不同文档的层级与字段提取逻辑，确保核心信息不丢失；原料配比、操作温度、批号等字段的准确性直接关联合规性与生产安全，要求分块保留字段与上下文的关联关系；多源数据格式混杂，需兼容不同来源文档的编码与排版差异；标签审核文件含合规性文本，需保留与备案信息的对应分块逻辑，便于后续问答匹配。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 匹配该品类文档中单条工艺步骤、原料配比的文本长度，避免拆分破坏操作逻辑 |
| `chunkSplitter` | 按段落+标题分隔 | 适配配方工艺单、检验报告的层级结构，保留操作步骤与字段的上下文关联 |
| `customPdfParse` | 开启 | 适配多源文档的非标准排版，准确提取标签审核、清场记录中的字段信息 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容单批次生产的多份文档打包上传需求，避免因文件过大被拦截 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对复杂配方文档的解析耗时，防止因超时中断解析流程 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型调整分块规则，适配原料配比、操作记录等差异化内容 |

## 容易做错的三处
- 解析文档时提示“the argument ‘windows-1252’ is invalid encoding”，原因是未配置自定义文件解析地址，或未指定兼容的文档编码规则，导致部分非UTF-8格式的生产记录无法正常解析。
- 工作流中调用文档解析工具后返回空结果，原因是未正确设置`UPLOAD_FILE_MAX_SIZE`参数，或上传文件超出配置上限，导致解析任务被拦截。
- 分块后单条工艺步骤被拆分为多个独立片段，原因是`chunkSize`设置过小，破坏了操作流程的上下文完整性。

## 怎么确认配好了
- 上传一份典型的配方工艺单，检查解析后的文本是否保留了原料配比、操作温度等核心字段的完整上下文。
- 调整`chunkSize`参数后，对比不同取值下的分块结果，确认分块长度符合当前文档的内容结构。
- 上传单份最大预期体积的文档，验证解析流程是否能正常完成，无超时或报错提示。
- 配置`customPdfParse`后，检查标签审核文件中的合规性文本是否被完整提取，无字段缺失。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
