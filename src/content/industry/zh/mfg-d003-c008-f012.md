# 化妆品生产的工艺规程与技术标准问答：部署与升级

## 这个品类的数据长什么样
本品类数据来自护肤、洗护、彩妆及特殊化妆品生产企业的日常生产文档，包括配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验报告、标签审核材料。数据来源涵盖注册或备案配方、原料安全资料、生产设备数据、ERP/MES系统、实验室记录及包材版本信息，更新频率为每批生产或每次换线。数据字段包含原料限用物质信息、生产参数、批号、包材宣称内容等，需严格匹配备案管理要求。

## 这些特征在「部署与升级」这一环带来什么约束
本品类数据高频更新且来源分散，部署时需配置多数据源同步适配，确保每批生产或换线后的数据可快速接入。数据需匹配备案合规要求，存储与检索环节需保留完整的批次溯源信息，升级过程中需避免破坏历史数据的关联关系。多类型文档的解析需求，要求部署时配置适配不同文档结构的预处理规则，避免升级后出现解析异常。同时，因侧重生产参数与感官检验的检索，需确保升级后检索逻辑可覆盖该类细分字段。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–200 个连接` | 适配生产设备、ERP、实验室等多数据源的并发访问需求，避免连接耗尽 |
| `MONGODB_URI` | `指向备案配方与检验记录集合的专属数据库地址` | 化妆品生产数据需严格区分备案合规数据与日常生产数据，避免混淆 |
| `REDIS_URL` | `配置为本地缓存实例地址，缓存有效期设为 300 秒` | 高频检索的生产参数可通过缓存提速，300秒适配每批生产的间隔周期 |
| `STORAGE_S3_ENDPOINT` | `指向企业内部对象存储服务的端点地址` | 存储清场记录、包材版本等大体积文档，适配企业现有存储架构 |
| `ROOT_KEY` | `按企业内部权限管理规则生成专属密钥` | 控制管理接口的访问权限，避免非授权人员修改工艺规程相关配置 |

## 容易做错的三处
- 执行升级命令后返回`500 Internal Server Error`，且日志显示数据库连接超时。原因是未正确配置`MONGODB_URI`或`PG_URL`参数，升级过程中无法读取或写入生产数据。
- 升级至FastGPT v4.17.0后，第三方模型调用失败，界面显示`model not found`。原因是升级后未同步更新第三方模型的接口配置，或`FILE_TOKEN_KEY`参数未匹配第三方平台的校验规则。
- 升级后新生产批次的数据无法自动同步至问答系统，检索结果仅包含升级前的历史数据。原因是未配置`DB_MAX_LINK`的合理取值，导致新数据源的连接被拒绝，增量同步任务中断。

## 怎么确认配好了
- 执行数据源连接测试，确认`MONGODB_URI`、`PG_URL`等参数指向的服务可正常读写，无连接报错。
- 提交一条模拟生产批次的测试数据，验证增量同步任务可正常完成，数据可在检索界面查询到。
- 调用管理接口，确认`ROOT_KEY`可正常鉴权，无权限拒绝提示。
- 触发一次模型调用测试，确认第三方模型的连接配置可正常生效，无调用失败提示。
