# 化学药制剂生产的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
化学药制剂生产的相关数据来自经批准的处方工艺、物料批次信息、MES电子批记录、设备与环境监测数据、LIMS系统及质量管理系统。日常文档包含主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差/CAPA/变更文件及批放行审核表。数据更新频率为每生产批次、每个关键工艺步骤执行时同步更新，同时按固定监测计划完成设备与环境数据的更新。文档包含结构化参数字段与非结构化操作描述，核心字段包括物料批号、工艺参数值、检验结果等。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据按生产批次与关键步骤高频更新，要求索引支持增量追加，避免全量重建占用过多存储与计算资源。文档包含结构化参数与非结构化操作描述，分块时需兼顾单块内容完整性与检索颗粒度，防止截断核心工艺参数或操作流程。数据关联GMP合规要求，检索结果需覆盖足够上下文以支撑合规性判断，同时需控制检索延迟以适配生产现场的实时复核需求。高频更新的结构化数据需精准匹配字段信息，避免因分块不当导致参数检索错位。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配化学药制剂批记录的单段内容长度，避免截断工艺参数、物料批号等核心合规信息 |
| 重叠长度 | 100–150 字符 | 覆盖工艺步骤的衔接内容，防止检索时遗漏跨分块的关键操作描述 |
| 相似度阈值 | 0.75–0.85 | 区分相似工艺参数与合规性要求，降低误召回概率 |
| `defaultToken` | 4096 | 适配主流API模型的输入长度限制，容纳单轮问答的上下文内容 |
| `maxToken` | 8192 | 容纳多份批记录与工艺规程的完整上下文，支撑复杂合规性判断 |
| 单次搜索上限 | 前 10 条 | 平衡检索效率与召回覆盖范围，避免过多文档拖慢响应速度 |

## 容易做错的三处
- 建索引时一直停在最后一组，界面显示索引进度无更新、无报错。原因是未配置增量索引逻辑，全量重建索引时未适配批量的批记录数据，导致索引任务堆积无法推进。
- 混合检索响应时间超过10秒，纯向量检索响应约8秒。原因是同时启用了全文检索与向量检索，且未限制单次搜索的文档数量，超出API调用的响应阈值。
- 无法正确创建知识库，卡在「建索引」步骤无任何反馈。原因是未调整分块长度适配长文档的批记录，分块时内存占用过高导致进程阻塞。

## 怎么确认配好了
- 查看FastGPT v4.17.0的索引分块日志，确认每批次文档的分块数量符合预设的字符长度范围。
- 发起一条工艺规程相关的问答，验证纯向量检索的响应时间符合预期。
- 检索结果中需包含物料批号、工艺参数等核心字段，匹配度符合预设的相似度阈值区间。
- 提交一份新的批记录进行增量更新，确认索引可以正常完成追加且无进度停滞。
