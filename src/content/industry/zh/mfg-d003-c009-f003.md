# 化学药制剂生产的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类的日常文档包含主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差/CAPA/变更文件及批放行审核表。数据来源于经批准的处方工艺、物料批次信息、MES系统、电子批记录、设备与环境监测数据、LIMS及质量管理系统。数据更新随每批生产、关键工艺步骤执行及监测计划推进，字段包含工艺参数范围、物料批号、检验结果、偏差描述等，无统一固定单位，随对应文档字段调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类数据随每批生产动态更新，多轮对话需通过`chatId`绑定当前批次专属上下文，避免跨批次数据混淆。文档字段无统一单位且包含工艺参数、物料批号等敏感信息，提示词需明确指定提取当前批次的对应字段，防止输出无效或不合规内容。由于出错后果直接关联批次放行与监管合规，对话过程需保留历史交互记录，确保复核环节可追溯。同时，复杂的汇总与复核任务需通过多轮对话逐步拆解，避免单次请求超出模型处理范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 按当前生产批次预定义专属字段，示例为`{"batchNo": "P2024051201", "materialLot": "M2024042803"}` | 该品类数据需绑定当前批次，确保问答指向正确的生产记录 |
| 多轮对话上下文保留时长 | 7200秒 | 单批生产的工艺执行周期通常覆盖数小时，需保留该时段内的交互记录 |
| 单次返回文档条数 | 前3条 | 该品类文档包含大量专业参数，过多条目会超出模型处理范围，避免混淆 |
| `messages` | 按交互轮次追加系统提示词与用户/助手消息，不截断历史有效上下文 | 工艺问答需依赖前期复核的历史信息，确保回答逻辑连贯 |
| 单次请求最大token数 | 按实测标定，不超过8000 token | 该品类文档内容较多，需控制上下文长度以保证模型处理效率 |
| FastGPT版本 | v4.17.0 | 该版本优化了多轮对话上下文绑定与变量替换的稳定性 |

## 容易做错的三处
- 现象：配置rerank模型后，外网可ping通模型，但对话详情未展示rerank后的排序结果。原因：未将rerank配置绑定到当前工艺问答的检索环节，或系统提示词未指定使用rerank结果生成回答。
- 现象：传入`variables`参数后，提示词占位符未被替换，返回内容与目标批次无关。原因：未在提示词中正确声明占位符格式，或API调用时未将`variables`参数与对话请求绑定，导致变量未生效。
- 现象：用户输入后，文本内容提取节点未返回预期字段，触发指定回复后流程停滞。原因：未配置多轮对话的回溯引导机制，未提示用户补充缺失的批次信息或工艺参数，导致流程无法继续推进。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本发起包含当前生产批次信息的测试请求，检查返回内容是否精准关联该批次的工艺参数与记录。
- 查看对话详情页，确认`messages`参数完整保留了历史交互的系统提示词与用户消息，未被意外截断。
- 传入预设的`variables`参数，验证提示词中的占位符是否被正确替换为对应字段值。
- 模拟文本提取失败的场景，确认流程会触发指定回复并引导用户补充必要信息。
