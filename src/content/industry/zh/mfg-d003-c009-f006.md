# 化学药制剂生产的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
本品类数据主要来自经批准的处方工艺文件、MES电子批记录、LIMS检验系统、质量管理系统。日常文档包含主生产文件、批生产/包装/清场记录、检验记录、偏差/CAPA/变更文件、批放行审核表。数据更新随每批生产流程、关键工艺步骤及监测计划执行，字段涵盖物料批次信息、工艺参数、设备运行记录、检验结果与放行审批状态，无额外自定义统计数字。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的批次化更新、多类型合规文档、分散系统来源及GMP合规要求，为引用溯源带来多重约束。需绑定具体生产批次作为溯源锚点，避免通用数据混淆；需支持关联多类文档的精准条目，确保引用指向明确；需整合MES、LIMS等不同系统的数据源，确保溯源链路完整；需关联文档的审批与放行状态，保障引用内容的合规性与可信度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | 适配本品类单条工艺或批记录条目的长度，确保引用内容完整且不超出上下文窗口 |
| `responseData` | 仅返回关联生产批次的文档条目 | 精准匹配本品类的批次化数据需求，避免泛化内容干扰问答 |
| `detail` | 开启 | 展示具体工艺参数与审批状态，满足溯源的合规性要求 |
| 单次搜索上限 | 前3条 | 控制返回结果数量，降低合规审核的负担 |
| 最大上下文长度 | 4000–6000 字符 | 容纳多份核心文档内容，保障问答逻辑连贯 |
| 超时阈值 | 300 秒 | 适配本品类多系统数据整合的耗时需求，避免查询中断 |

## 容易做错的三处
- 现象：界面显示引用了文档，但回答内容未匹配知识库中的合规工艺或批记录内容。原因：未绑定具体生产批次作为溯源锚点，导致模型匹配到无关的通用数据。
- 现象：调用API传入知识库后无法触发引用检索。原因：未将知识库ID正确传入工作流的上下文参数，未建立问答与对应批次文档的关联。
- 现象：溯源列表仅展示文本格式的文档，其他类型的检验记录、变更文件未被检索到。原因：未配置支持多文档格式的索引规则，仅对文本数据集进行了嵌入处理。

## 怎么确认配好了
- 发起包含具体生产批次的工艺问答，检查返回结果中是否关联了对应批次的批记录条目。
- 查看溯源面板，确认包含检验记录、变更文件等非文本格式的文档条目。
- 调用API接口，检查返回的结构化数据是否包含本品类的合规文档标识。
- 验证问答内容是否包含具体的工艺参数与审批状态，符合溯源的精度要求。
