# 化学药制剂生产的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来自经批准的处方工艺、物料批次台账、MES系统、电子批记录、LIMS实验室管理系统及质量管理系统。日常文档包含主生产文件、批生产/包装记录、清场记录、检验记录、偏差/CAPA/变更文件及批放行审核表。数据更新随每批生产、关键工艺步骤执行及定期环境监测完成，字段包含物料批号、工艺参数阈值、偏差处置记录等，需与生产操作同步留存。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的批次化数据结构要求模型接入时需限定单轮上下文的范围，避免混入无关批次的记录。多系统来源的数据需通过统一接口拉取，需配置适配多源数据的检索规则。GMP要求的数据可追溯性，要求模型调用的全流程日志需完整留存。工艺参数的精准匹配需求，要求检索时优先关联经批准的处方工艺字段，同时需适配偏差、变更等动态更新的文档内容，避免使用过期的工艺标准。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单批生产记录的总长度，避免截断关键工艺参数与批放行信息 |
| `maxTokens` | 2000–3000 token | 控制单轮回答的输出长度，确保工艺问答的结果可完整嵌入批记录审核流程 |
| `quoteMaxToken` | 1500 token | 限定检索引用的文档片段总长度，保证引用内容的工艺参数与偏差记录完整且不冗余 |
| `temperature` | 0.1–0.3 | 降低回答的随机性，确保工艺标准与合规要求的回答准确一致 |
| `AIPROXY_API_ENDPOINT` | 按企业部署的大模型网关地址填写 | 适配企业内部统一的模型调用入口，符合GMP下的系统管控要求 |
| `AIPROXY_API_TOKEN` | 按企业分配的专属接口密钥填写 | 保障模型调用的权限管控，避免未授权访问合规数据 |

## 容易做错的三处
- 调用时出现“failed to get gpt-3.5-turbo token encoder”报错，原因是未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，导致无法正常初始化模型的编码模块。
- 模型流响应为空，原因是`maxContext`设置超出了企业网关的限流阈值，或代理配置未开启流式数据转发支持。
- 检索工艺标准时响应延迟过高，原因是未限定`quoteMaxToken`的取值范围，导致检索返回的文档片段过长，增加了模型的上下文加载耗时。

## 怎么确认配好了
- 手动输入单批生产的工艺参数查询问题，检查模型返回的回答是否引用了正确的批记录字段与经批准的工艺标准。
- 查看FastGPT后台的模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置已被正确加载，无认证报错。
- 触发多轮问答，检查模型是否能正确关联历史偏差记录与当前工艺问题，且回答未出现无关批次的内容。
- 测试流式输出功能，确认模型回答能以分段形式逐步返回，无空响应或截断情况。
