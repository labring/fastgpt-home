# 医疗器械装配与洁净生产的工艺规程与技术标准问答：工作流编排

## 这个品类的数据长什么样
本品类数据来自设计历史文件、器件与材料批次、MES系统、洁净环境监测设备、灭菌设备及检验校准系统。日常文档包含生产工艺规程、批生产记录、洁净区运行记录、灭菌批记录、检验报告、软件版本记录、不良事件与追溯资料。数据更新节奏为每批产品或每台器械同步，洁净环境监测数据按固定计划更新。文档字段包含唯一器械标识、材料批次号、灭菌参数、洁净区温湿度值、检验结果等，未包含无依据的统计数值。

## 这些特征在「工作流编排」这一环带来什么约束
本品类数据关联每批产品的唯一标识与批次信息，要求工作流需通过`variables`绑定批次变量动态匹配对应数据源，避免跨批次数据混淆。数据更新节奏随生产批次灵活变动，工作流需支持按需触发。文档字段包含灭菌参数、洁净温湿度等合规性关键项，工作流需配置字段校验节点，拦截不符合工艺规程的异常数据。同时因出错后果涉及患者安全与产品召回，工作流需增加异常分支处理环节，确保流程中断时可触发告警。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定当前生产批次、器械唯一标识、洁净区编号等业务变量 | 用于动态匹配对应批次的工艺规程与检测数据 |
| 循环节点最大运行次数 | 10–30 次 | 匹配医疗器械装配的标准工序数量，避免无效循环 |
| 批量执行节点最大输入长度 | 800–1200 字符 | 适配单批生产记录的文本长度，避免节点过载 |
| 工作流最大运行次数 | 1000 次 | 匹配FastGPT v4.17.0的默认配置，满足多批次批量处理需求 |
| `nodeId` | 绑定飞书Webhook节点的唯一标识 | 用于在异常分支中触发告警通知 |
| 节点超时时间 | 600 秒 | 适配灭菌、洁净环境监测等耗时较长的设备数据拉取环节 |

## 容易做错的三处
- 现象为通过DB节点查询数据库后返回结果为JSON或JSON数组，文本拼接节点无法直接读取字段值。原因为未通过`variables`配置节点输出字段映射，未将数据库查询结果的字段绑定到工作流变量中。
- 现象为并发调用量达到1秒2-3次时，MCP节点返回空值。原因为未配置节点的并发限制参数，高并发下触发FastGPT的调用限流机制。
- 现象为循环节点后拼接文本再调用飞书Webhook时，无法发送消息。原因为未在循环节点后添加变量合并步骤，拼接后的文本未正确写入工作流全局变量，导致Webhook节点读取为空。

## 怎么确认配好了
- 手动触发单批次工作流，检查`variables`绑定的业务变量是否正确匹配当前生产批次的工艺规程文档。
- 模拟高并发调用，观察节点返回结果是否存在空值或异常报错，调整并发限制参数至符合业务需求。
- 测试循环节点拼接文本后调用飞书Webhook，检查消息内容是否包含循环节点的输出结果。
- 查看工作流运行日志，确认所有节点的执行时长未超过预设的超时时间。
