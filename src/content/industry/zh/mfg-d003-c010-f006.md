# 医疗器械装配与洁净生产的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
本品类数据来自一次性耗材、植介入器械、诊断设备及有源器械制造商的生产全流程，包含生产工艺规程、批生产记录、洁净区环境记录、灭菌批记录、检验报告、软件版本记录等文档。数据来源覆盖设计历史文件、器件与材料批次台账、MES系统、洁净环境监测设备、灭菌设备及检验校准系统。数据更新按每批产品或每台设备执行，洁净环境监测数据按既定计划更新。单条文档包含唯一器械标识、批次号、工艺参数、检验结果等结构化字段，以及对应生产环节的详细操作要求。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类数据按批次与生产环节绑定，引用时需精准匹配唯一器械标识与批次号，避免跨批次混淆工艺要求。多源数据的关联需明确标注来源系统与更新时间，确保溯源可查。数据更新频率较高，需保证检索结果为最新的有效记录。单条数据量较大，引用时需兼顾内容完整性与上下文长度限制，防止因截断丢失关键合规性参数。出错后可能引发无菌失效、追溯失败等严重后果，因此溯源信息的准确性与完整性为核心约束。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | 该品类单条批记录数据量较大，需覆盖完整工艺步骤与批次参数，避免关键信息截断 |
| `responseData` | 返回批次号、来源系统、更新时间字段 | 本品类需绑定唯一标识与溯源信息，便于追溯生产环节与数据有效性 |
| `detail` | 开启 | 需展示完整的工艺规程条款与检验报告细节，满足合规性要求 |
| 单次搜索上限 | 前10条 | 该品类数据按批次分类，过多结果易混淆不同批次的工艺要求 |
| 结果重排 | 按来源更新时间倒序 | 最新的批记录与环境监测数据为当前装配工序的参考依据 |
| FastGPT 版本 | v4.17.0 | 该版本优化了多源数据溯源的字段映射逻辑 |

## 容易做错的三处
- 现象：界面显示的上下文窗口仅展示30条结果，但实际检索到的文档条数为310条，发送至调用端的结果同样为310条。原因：未在FastGPT v4.17.0中配置`responseData`的前端渲染字段，导致前端仅加载部分结果进行展示。
- 现象：设置`quoteMaxToken`为1500 token后，知识库中超过该长度的文档块仍被成功引用。原因：`quoteMaxToken`仅限制单条召回文档块的token上限，未结合单次搜索上限限制总上下文长度，导致超长块被单独纳入上下文。
- 现象：将知识库检索结果传入HTTP请求后，AI对话环节无法正确关联引用来源。原因：未按照FastGPT要求的`responseData`格式传递来源字段，导致对话模块无法识别溯源信息。

## 怎么确认配好了
- 发起针对具体批次的工艺提问，查看回复中是否附带对应批次号、来源系统名称与更新时间。
- 调整`quoteMaxToken`的取值，观察上下文总长度是否随之变化。
- 开启`detail`配置后，确认回复中包含完整的工艺规程条款与检验细节。
- 模拟多批次数据检索，检查结果是否按更新时间倒序排列且无跨批次的内容混淆。
