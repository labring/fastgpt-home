# 半导体封装测试的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类的核心数据源包括晶圆测试图、MES系统、键合机与塑封设备、ATE测试机、X-ray/SAM检测设备及客户规格书。日常生成的文档涵盖封装流程卡、键合与塑封参数表、晶圆来料图、测试程序版本、良率报告、失效分析报告，文档字段包含批次标识、工序参数、裸晶坐标、测试bin值等。数据更新频率覆盖单颗芯片测试、每生产批次及每日汇总，单批次数据随生产进度实时更新。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新频繁，要求对话上下文需严格绑定当前生产批次的专属数据，避免跨批次混淆。多轮对话中需保留当前批次的晶圆来料图、测试程序版本等核心信息，防止上下文过载导致检索错误。提示词需限定检索范围为当前工序的工艺文档，避免误用失效分析报告等非目标文档。同时，需动态关联设备参数的最新版本，确保对话中调用的键合、塑封参数为当前批次的有效配置。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配半导体封装测试场景的工艺问答需求：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前生产批次的唯一标识 | 用于关联该批次的晶圆来料图、测试程序版本等专属数据，避免跨批次混淆 |
| `variables` | 预设为当前批次号、ATE机型编号 | 用于在提示词中动态插入检索范围，限定调用对应批次的工艺文档 |
| `messages` | 单轮对话保留不超过8轮上下文 | 半导体工艺数据更新频繁，过长上下文会引入旧批次数据，影响检索准确性 |
| 问题优化 | 开启 | 工艺文档包含键合拉力、塑封回流温度等专业术语，优化后可提升检索匹配度 |
| 最大上下文 | 按实测标定，不超过8000 token | 单条典型工艺文档长度约1000字符，8000 token可容纳8条核心文档，避免上下文过载 |
| 单次搜索上限 | 前6条 | 覆盖当前工序的核心参数，避免冗余数据干扰对话结果 |

## 容易做错的三处
- 现象：知识库搜索调试正常，AI对话时未参考知识库内容。原因：未在`messages`中绑定当前批次的检索范围，导致对话上下文未关联预设的知识库筛选条件。
- 现象：无法将程序执行结果作为背景知识输入到下一个AI对话模块。原因：未通过`variables`将执行结果绑定为对话变量，未在提示词中引用该变量传递内容。
- 现象：多轮对话中出现跨批次的工艺数据，导致参数调用错误。原因：未在初始对话时绑定`chatId`关联当前生产批次，上下文残留之前批次的文档数据。

## 怎么确认配好了
- 发起测试对话，输入“当前批次的键合参数”，检查检索结果是否包含当前`chatId`绑定的批次文档。
- 查看对话上下文面板，确认`variables`中的批次号、ATE机型编号已正确插入到系统提示词中。
- 连续发起3轮不同工序的对话，检查上下文是否仅保留当前批次的工艺数据，未引入旧批次内容。
- 触发程序执行模块生成测试结果，检查后续对话是否引用了该结果作为背景知识。
