# 半导体封装测试的工艺规程与技术标准问答：部署与升级

## 这个品类的数据长什么样
半导体封装测试场景的核心数据来源于MES系统、键合机与塑封设备、ATE测试机、X-ray/SAM检测设备及客户规格文档。日常维护的文档包括封装流程卡、键合与塑封参数表、晶圆来料图、测试程序版本清单、良率报告、失效分析报告。数据更新频率覆盖每批晶圆、每颗芯片测试、每日汇总，字段包含封装温度、键合压力、测试bin码等带明确单位的工业参数，与晶圆制造前道工序的微细加工数据存在明确差异，聚焦裸晶封装为可装联器件后的电测分档环节。

## 这些特征在「部署与升级」这一环带来什么约束
该场景的数据来源多为工业设备与业务系统，需支持多源异构数据的统一接入，因此部署环节需适配工业级数据库与存储配置。高频次的更新要求问答系统需支持近实时的文档索引同步，避免数据滞后影响问答准确性。结构化的工业参数与批次关联数据，要求知识库需保留元数据的关联关系，升级环节需兼容旧版文档的索引结构。同时，出错后果涉及芯片封装失效与不良品流出，部署需保障高可用性，升级需最小化业务中断风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://fastgpt:your_secure_pass@192.168.1.20:5432/fastgpt?sslmode=disable` | 封测场景的结构化文档如测试程序版本、良率报告需关系型数据库的事务性存储，适配多批次数据的关联查询 |
| `REDIS_URL` | `redis://:redis_secure_pass@192.168.1.21:6379/0` | 高频问答的会话缓存与向量检索加速需低延迟的内存存储，适配每颗芯片测试级别的数据更新频率 |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.22:9000` | 封装流程卡、失效分析报告等文档体积较大，需分布式存储支持批量上传与跨节点读取 |
| `DB_MAX_LINK` | `200–300 个连接` | 多台封测设备同步数据时的并发连接需求，避免数据库连接耗尽导致服务中断 |
| `ROOT_KEY` | 随机生成的32位字符串 | 管理后台的权限校验，防止未授权访问配置与知识库数据 |

## 容易做错的三处
- 现象：FastGPT v4.17.0的Docker本地部署每隔数小时出现数据库连接报错，日志显示「FATAL:  too many connections」，需删除PG容器重新部署才能恢复服务。原因：未配置`DB_MAX_LINK`参数，并发连接数超过PostgreSQL默认上限，导致数据库容器异常退出。
- 现象：问答系统无法召回特定批次的晶圆来料图文档，返回结果无对应批次信息。原因：未将`STORAGE_S3_ENDPOINT`配置为与封测MES系统兼容的存储端点，导致文档元数据与实际存储路径不匹配。
- 现象：升级后原有测试程序版本的问答无法召回正确参数。原因：直接跨多个版本升级未执行知识库元数据迁移脚本，导致旧版文档的索引结构与新版系统不兼容。

## 怎么确认配好了
- 登录FastGPT管理后台的数据库监控面板，查看`PG_URL`与`REDIS_URL`配置的连接状态，确认无超时或连接拒绝报错。
- 上传一份封装流程卡文档，验证`STORAGE_S3_ENDPOINT`配置的存储路径可正常读取文件内容与元数据。
- 发起一条关于键合参数的测试问答，确认返回结果关联的文档元数据与MES系统的批次信息一致。
- 发起100个并发问答请求，确认`DB_MAX_LINK`配置的连接数未触发数据库连接耗尽报错。
