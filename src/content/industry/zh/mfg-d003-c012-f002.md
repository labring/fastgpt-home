# 半导体晶圆制造的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自晶圆厂工艺整合、设备、良率等部门的日常产出，涵盖工艺流程卡、批次运行记录、设备配方、SPC统计图表、异常处置单、缺陷图谱、良率报告等。数据来源包括MES系统、设备FDC模块、缺陷检测与量测设备、晶圆图文件、工艺配方库及实验数据，更新节奏覆盖每批晶圆产出、实时参数上报及每日汇总归档，字段多包含纳米级工艺参数、批次编号、缺陷坐标等专业内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的超长工艺链、高频更新特性及专业字段结构，对向量模型与索引环节带来多重约束。海量工序文档与跨模块耦合的工艺数据，要求索引需支持分层检索与上下文关联匹配；实时、按批次的更新节奏，要求索引支持增量同步以避免全量重建的耗时；纳米级工艺参数与缺陷坐标等专业字段，要求向量模型需适配高维度专业语义的编码精度，同时需保留字段间的关联逻辑。

## 配置怎么定
本配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 晶圆制造文档多包含连续工艺步骤，该长度可保留工序上下文且避免单块过载 |
| 重叠长度 | 100–200 字符 | 工艺参数与工序存在前后关联，重叠可避免上下文断裂 |
| `maxToken` | 8192 token | 需适配包含多页工艺卡的长文本块，避免截断关键参数 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| 单次召回上限 | 前 8 条 | 晶圆制造工艺关联节点较多，需保留足够候选结果用于后续筛选 |
| 相似度阈值 | 0.72–0.80 | 专业术语匹配需较高精度，避免误召回无关工艺文档 |

## 容易做错的三处
- 知识库上传后状态长时间停留在索引中。原因是未配置增量索引更新规则，全量重建索引时适配海量晶圆批次数据耗时过长。
- 向量化时出现embedding速率超限报错。原因是未调整线程数，并发请求超出向量服务的调用限制，可通过降低线程数缓解。
- 设置分块长度为3000字符时出现文本块丢失。原因是长文本块拆分时未保留工艺逻辑边界，部分跨工序的关联参数被错误截断后无法被正确识别。

## 怎么确认配好了
- 上传单份典型工艺流程卡，检查分块结果是否保留连续工序的上下文，无明显截断或拆分错误。
- 提交包含专业工艺参数的查询，核对召回结果的匹配精度是否符合预设的专业场景需求。
- 查看索引更新日志，确认实时上传的批次数据可在设定的时间窗口内完成增量同步。
- 测试不同分块长度下的向量化成功率，确认配置的分块规则未触发文本丢失或异常报错。
