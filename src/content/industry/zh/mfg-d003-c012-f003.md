# 半导体晶圆制造的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
半导体晶圆制造场景的业务数据通常来自晶圆厂工艺整合、设备、良率与制造部门，核心来源包括MES系统、设备FDC数据、缺陷检测与量测设备输出、晶圆图、工艺配方库与实验数据。日常文档涵盖工艺流程卡、批次运行记录、设备配方、SPC图、异常处置单、缺陷图谱与良率报告。数据更新频率随晶圆批次推进、实时参数变化与每日汇总更新，覆盖数百道工序的耦合参数与返工路径信息。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
超长工艺链与纳米级参数耦合特性，要求多轮对话必须精准限定上下文范围，避免冗余信息干扰关键判断。实时更新的批次数据与有限的返工窗口，要求对话响应速度需匹配生产节奏，过长的上下文处理会拖慢响应效率。多源异构的数据格式，要求提示词需明确指定数据关联维度，避免跨批次、跨工序的参数混淆。同时，工艺处置的严谨性要求对话过程中不能遗漏关键异常信息，需通过多轮追问补全缺失的批次与工序细节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 保留前10轮对话上下文 + 最新2条用户提问 | 晶圆制造工艺步骤较多，过长的历史对话会干扰当前工序的精准判断，限定轮次可提升提示词聚焦度 |
| `variables` | 绑定晶圆批次号、当前工序节点ID | 精准匹配对应批次的运行记录、设备配方与良率数据，避免跨批次的参数混淆 |
| 最大上下文长度 | 8000–12000 字符 | 单批次完整工艺文档通常较长，该区间可覆盖关键工序、异常处置与配方信息，同时控制提示词长度 |
| 单次召回上限 | 前6条匹配结果 | 工艺参数存在纳米级耦合性，过多召回结果会导致提示词冗余，影响推理准确性 |
| 对话超时时间 | 300 秒 | 匹配晶圆制造有限的返工窗口，确保快速返回处置建议，避免延误生产节奏 |
| FastGPT版本 | FastGPT v4.17.0 | 该版本支持`variables`的精准绑定与`messages`的轮次限定配置，适配本场景的多轮对话需求 |

## 容易做错的三处
- 现象：API调用对话应用时，对话日志中出现未预期的非目标标题内容；原因：未在`variables`中过滤非目标上下文字段，导致无关元数据被带入提示词。
- 现象：多轮对话后返回的工艺建议包含中间工序的冗余信息；原因：未限制`messages`的上下文轮次，导致历史对话干扰当前工序的判断。
- 现象：对话超时未返回结果；原因：未设置合理的对话超时时间，超出晶圆制造返工窗口的响应要求。

## 怎么确认配好了
- 发起包含特定晶圆批次号的提问，核对返回结果是否仅关联该批次的工艺文档与运行记录。
- 查看对话日志，确认仅目标上下文被带入`messages`字段，无冗余的中间步骤或非关联元数据。
- 模拟多轮递进提问，核对提示词是否会根据上一轮回答补充追问缺失的工序或参数细节。
- 测试超时场景，确认响应时间符合生产场景的窗口要求，可根据实际业务调整阈值。
