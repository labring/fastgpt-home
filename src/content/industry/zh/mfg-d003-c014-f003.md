# 印染与后整理的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自染整厂、面料企业的染色、定形、实验室与质量部门，日常文档包含染色配方、称化料记录、染缸曲线、打样确认、色差报告、定形工艺单、污水台账。数据来源覆盖客户色样、配方库、染化料批次、染缸控制系统、测色仪、定形机及环保监测设备，更新频率为每缸、每批、每班一次，文档字段包含工艺参数、批次编号、检测数值、排放指标等，单位涉及温度、浓度、时间、色差ΔE值等专业参数。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的高频更新与专业参数特征，要求多轮对话需跟踪当前加工批次的上下文，避免跨缸、跨批数据混淆。专业文档中的温度、色差、浓度等参数需在提示词中明确限定场景，防止模型调用无关知识库内容。频繁更新的数据需在对话初始环节引导用户提供缸号、批次编号，以匹配最新的工艺记录与检测报告。同时，因出错后果涉及整缸报废或环保超标，多轮对话需逐步校验关键工艺参数，确保每一步推导符合当前批次的技术标准。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 预设缸号、批次类型、工艺环节三类变量 | 可快速定位对应批次的工艺文档与检测数据 |
| `chatId` | 绑定当前加工缸的唯一标识 | 确保多轮对话上下文不跨缸混淆 |
| `messages` | 限制单轮对话历史不超过15条 | 避免上下文过载影响专业参数推导 |
| 上下文窗口大小 | 8000–12000 token | 印染工艺参数多为连续批次数据，需保留多轮对话中的关键上下文 |
| 单次搜索上限 | 前5条 | 本品类单批次相关文档量有限，过多召回会稀释有效信息 |
| 知识库同步频率 | 每班一次 | 匹配本品类数据按批次更新的节奏 |
| FastGPT版本要求 | v4.17.0及以上 | 支持当前配置项的完整功能 |

## 容易做错的三处
- 现象：在线对话与API调用返回结果差异显著，API开启stream为false、detail为true时结果偏差更明显；原因：未在配置中统一绑定`chatId`与批次标识，导致API调用时上下文未关联当前缸号，在线对话则自动绑定会话ID。
- 现象：迁移知识库后，知识库页面可查看全部内容，但对话时模型提示知识库为空；原因：未重新生成对应知识库的向量索引，或未在对话配置中关联迁移后的知识库ID。
- 现象：工作流AI对话组件的注释触发时机与预期不符，提前触发或延迟触发；原因：未明确配置stream输出的触发逻辑，默认触发规则与工艺问答的分步校验需求不匹配。

## 怎么确认配好了
- 发起包含缸号、工艺阶段的测试对话，核对模型是否能召回对应批次的染色配方与染缸曲线。
- 调用API与在线对话分别发起相同问题，核对两次返回的工艺参数结果是否一致。
- 迁移知识库后重新生成向量索引，发起测试对话确认模型可正常检索到知识库内容。
- 测试多轮对话中上下文是否保留当前缸号信息，跨缸提问时模型是否提示切换批次。
