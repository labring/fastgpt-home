# 原料药与医药中间体生产的工艺规程与技术标准问答：工具调用与插件

## 这个品类的数据长什么样
该品类的典型数据来自合成、发酵、精制、质量与注册支持部门的日常文档与系统数据，包括批生产记录、物料平衡数据、反应与精制记录、清洁记录、杂质谱报告、偏差与变更文件。数据来源涵盖注册工艺文档、原料批次记录、DCS系统、称量系统、LIMS、色谱数据系统、QMS，更新频率为每批、每步骤。单份文档包含批次号、反应温度、杂质残留量、溶剂残留ppm等专业字段，单位涉及mg、℃、ppm等。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源异构的系统数据来源要求工具调用插件需配置多接口映射规则，适配不同系统的返回格式。按每批、每步骤更新的数据特性，要求工具调用必须指定批次号作为核心查询参数，避免查询过期或无效数据。专业字段的标准化要求工具调用需对返回结果做格式校验，确保杂质含量、溶剂残留等数值符合行业常规单位。出错后果严重的业务特性，要求工具调用增加失败重试与异常拦截机制，防止无效请求触发批次报废等风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 工作流/API 工具选择配置 | `auto` | 适配工艺问答中随机触发的多数据源查询需求，自动匹配对应插件 |
| 工作流/API 函数调用配置 | 启用 | 支持将自然语言工艺问题解析为结构化查询，匹配批次号、杂质参数等专业字段 |
| 多数据源适配配置 | 按LIMS、DCS、QMS系统分别配置接口映射 | 覆盖该品类多系统数据来源的查询场景 |
| 批次参数强制校验 | 开启，要求输入必须包含有效批次号 | 匹配该品类按每批更新的数据特征，确保查询的是当前有效批次数据 |
| 多模态文件上传阈值 | 200 MB | 适配杂质谱报告等单份文档的常规大小，避免触发文件超限报错 |
| 工具调用结果缓存时长 | 300 秒 | 平衡数据实时性与接口调用频率，适配每步骤更新的业务节奏 |

## 容易做错的三处
- 调用apiCollection接口上传工艺文档时返回Invalid URL, code: 500：未正确配置对接LIMS、色谱数据系统的接口地址，或接口地址包含非法字符，导致请求无法正常发起。
- 上传杂质谱报告等多模态文件时返回InternalError.Algo.InvalidParameter: Multimodal file size is...：未按该品类单份文档的常规大小配置上传阈值，导致超规格文件被拦截。
- 输入的工艺查询文本（如“分享XX批次的收率数据”）被错误解析为类似“分交”的乱序文本：未配置专业术语的分词校验规则，工具调用的输入预处理未过滤非标准输入字符，导致文本解析异常。

## 怎么确认配好了
- 发起包含有效批次号的工艺查询，核对工具调用是否能返回对应批次的批生产记录或杂质谱数据。
- 上传符合200 MB阈值的杂质谱报告，核对上传接口是否正常返回成功状态。
- 配置`toolChoice`为`auto`后，发起涉及多系统数据的查询，核对工具是否能自动选择匹配的数据源插件。
- 在工作流中关闭工具调用结果自动回显，核对工具调用的输出是否不会自动展示在对话界面。
