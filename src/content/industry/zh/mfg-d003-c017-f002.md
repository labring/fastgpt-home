# 喷涂与涂装的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据覆盖汽车、家电、工程机械、金属家具涂装线场景，日常文档包含涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账。数据来自涂料供应商TDS/SDS、喷房与烘炉设备、色差仪、膜厚仪、环境监测系统及MES系统，更新频率随每批涂料、每班作业及连续采集的设备数据变动，字段包含工艺参数、检测数值、批次信息等，单位涵盖微米、秒、毫克每立方米等。

## 这些特征在「向量模型与索引」这一环带来什么约束
涂装类数据包含静态工艺文档与实时设备采集数据的混合结构，要求索引支持多字段关联召回与多模态内容适配。高频更新的涂料批次、设备运行数据需要适配增量索引逻辑，避免全量重建的耗时损耗。多字段关联的业务需求（如膜厚数值对应喷涂参数）要求索引保留字段级关联规则，防止召回结果脱离业务上下文。不同文档的长度差异显著，短如调漆记录仅数十字符，长如烘炉曲线可达数千字符，需适配灵活的分块逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配涂装工艺卡、烘炉曲线等长短不一的文档内容，避免单块信息断裂 |
| 重叠长度 | 100–150 字符 | 保留跨块的工艺参数关联，确保膜厚、固化温度等连续信息不被拆分 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关的历史数据，匹配涂装场景的精准问答需求 |
| 单次搜索上限 | 前 8 条 | 覆盖主要工艺环节的关联数据，避免冗余信息干扰结果 |
| `maxToken` | 3000–4000 token | 容纳完整的烘炉曲线、调漆记录等长文档片段，满足上下文召回要求 |
| `defaultToken` | 1024 token | 适配基础问答的上下文填充，平衡召回精度与响应速度 |

## 容易做错的三处
- 现象：知识库返回与提问无关的涂装数据，原因：未配置字段级过滤规则，导致全量索引召回非关联的VOCs台账或无关烘炉历史数据。
- 现象：索引状态长时间未就绪，原因：未启用增量索引模式，对连续采集的设备数据执行全量重建，引发索引构建超时。
- 现象：检索结果仅返回单条短文档，无法覆盖完整工艺窗口，原因：分块长度设置过小，将完整的喷涂固化流程拆分为过多碎片块，导致召回信息不完整。

## 怎么确认配好了
- 导入单份涂装工艺卡，执行对应工艺问题的检索测试，检查返回结果是否包含匹配的工序要求与参数。
- 上传连续采集的烘炉曲线数据，验证索引是否能在合理时间内完成更新，无超时或报错提示。
- 针对涂装缺陷类问题，核对召回结果是否包含对应的缺陷返修单与工艺调整记录。
- 查看索引状态面板，确认索引已标记为就绪，无异常报错信息。
