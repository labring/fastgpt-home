# 基础化工连续生产的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
基础化工连续生产品类的数据来源包括DCS/SIS系统、在线分析仪、LIMS实验室管理系统、设备状态监测模块、能源计量装置与原料储罐数据。数据更新节奏分为实时、每班、每日三类。日常文档涵盖操作规程、工艺指标卡、DCS趋势图、化验报告、联锁旁路记录、特殊作业票与班报，字段包含工艺温度（摄氏度）、反应压力（兆帕）、物料流量（立方米每小时）、联锁触发阈值等标准化参数。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
实时更新的DCS与在线分析数据要求对话上下文需支持高频刷新，避免调用过期的稳态参数。每班、每日更新的班报与作业票需要对话能关联特定周期的文档片段，确保查询结果匹配当前作业时段的要求。多字段带单位的文档要求提示词需明确指定参数单位，防止混淆不同工况下的数值。强联锁控制的文档需要对话能快速定位联锁旁路记录，同时需限制上下文长度避免无关数据干扰判断。连续生产的稳态维持需求要求多轮对话可逐步拆解问题，先确认当前工况再逐步核对指标。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 800–1200 字符 | 匹配基础化工连续生产文档中单段工艺描述的平均长度，避免上下文溢出导致信息截断 |
| 历史会话绑定 | 绑定`chatId`参数 | 确保同工况下的多轮对话复用历史会话的全局变量，比如当前储罐液位、当班能耗数据，避免重复输入基础信息 |
| 全局变量存储 | 按`variables`参数绑定周期数据 | 关联每班更新的班报、联锁记录与能源计量数据，确保对话可调用最新的周期内参数 |
| 对话消息上下文 | 绑定`messages`参数 | 确保多轮对话的历史消息被正确传递，支持上下文延续，比如先确认当前反应釜温度再核对联锁状态 |
| 工具调用超时 | 600 秒 | 匹配DCS数据查询与化验报告调取的平均耗时，避免短超时导致有效查询中断 |
| 单次召回文档条数 | 前6条 | 覆盖单轮对话可能涉及的工艺、设备、计量三类核心数据，避免召回过多无关文档 |

## 容易做错的三处
- 现象：调用MySQL数据库工具时返回400 status code (no body)。原因：未在`variables`参数中绑定数据库连接的认证字段，导致请求缺失必要参数。
- 现象：多轮对话中无法加载之前会话保存的全局变量。原因：未通过`chatId`参数绑定对应会话的上下文存储，导致会话上下文未被关联。
- 现象：对话结果中出现非当前工况的工艺参数。原因：未限制最大上下文长度，导致召回了过期的班报或异常工况的历史数据。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，发起一轮针对当前工艺指标的查询，确认返回结果包含当前工况的温度、压力等带单位参数。
- 发起第二轮查询，补充询问联锁旁路的最新状态，确认对话上下文保留了第一轮的工况信息。
- 调用数据库工具执行一次数据查询，确认返回结果符合预期且无报错。
- 切换会话ID发起新对话，确认新会话不会加载旧会话的全局变量。
