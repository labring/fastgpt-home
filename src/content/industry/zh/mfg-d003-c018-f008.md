# 基础化工连续生产的工艺规程与技术标准问答：文档解析与分块

## 这个品类的数据长什么样
基础化工连续生产的数据来源包括DCS/SIS系统、在线分析仪、LIMS实验室管理系统、设备状态监测模块、能源计量系统与原料储罐监控数据。日常文档涵盖操作规程、工艺指标卡、DCS趋势图、化验报告、联锁旁路记录、特殊作业票与班报。数据更新频率分为实时（如DCS趋势）、每班（如班报）与每日（如化验报告）。文档包含工艺温度（℃）、压力（MPa）、流量（m³/h）等带明确单位的数值字段，以及联锁逻辑、作业步骤等结构化与半结构化内容。

## 这些特征在「文档解析与分块」这一环带来什么约束
实时高频更新的DCS趋势与班报要求解析流程具备低延迟特性，避免因超时导致数据滞后。多类型文档混合存在，既有结构化的工艺指标卡，也有半结构化的特殊作业票，需要分块逻辑适配不同文档结构。强联锁相关的关键内容需保留完整逻辑，不能被随意拆分，否则会影响后续问答的准确性。带单位的数值字段需与对应参数绑定，防止解析后丢失单位信息导致数据失真。批量上传的大型归档文档需限制单文件大小与解析时长，避免任务失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 基础化工文档包含长文本工艺步骤与短数值参数，该区间可平衡上下文完整性与检索精度 |
| `chunkSplitter` | 按段落+固定字符边界 | 工艺规程有明确段落结构，同时需避免拆分联锁逻辑等关键连续内容 |
| `customPdfParse` | 启用结构化解析模式 | 适配DCS趋势图、化验报告中的图表与数值字段，保留原始数据与单位的关联 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 兼容批量上传的大型DCS趋势归档文件，避免上传环节失败 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 处理包含多页联锁记录的大型PDF文档，预留足够的解析与渲染时间 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（如工艺卡、作业票）调整分块参数，适配场景差异化需求 |

## 容易做错的三处
- 执行`docker run --gpus all -itd -p 7231:7231`命令时出现容器启动或镜像拉取报错，原因是未正确配置宿主机GPU驱动权限，或使用了与FastGPT v4.17.0不兼容的marker_images版本。
- FastGPT v4.8.12版本中无法正常解析PDF内的复杂化学公式，而v4.9.0版本可正常返回解析结果，原因是不同版本的内置PDF解析模块对公式渲染逻辑的支持存在差异。
- 知识库里的PDF文件点击分块预览时显示无法读取该文件内容，原因是未启用`customPdfParse`配置，或单文件大小超过`UPLOAD_FILE_MAX_SIZE`限制，或`PARSE_FILE_TIMEOUT_SECONDS`设置过短导致解析中断。

## 怎么确认配好了
- 上传一份典型的工艺指标卡PDF，检查分块预览是否完整保留了工艺参数与对应单位，无内容缺失或乱码。
- 上传包含DCS趋势图的文档，确认解析后的分块中包含图表标注与对应数值，无字段丢失。
- 上传单份大小接近`UPLOAD_FILE_MAX_SIZE`的归档文件，确认解析任务可正常完成，无超时报错提示。
- 调整`chunkSize`参数后，对比分块后的文本长度，确认符合场景需求的上下文覆盖范围。
