# 安全环保与特殊作业管理的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自法规标准、在线环保监测设备、气体检测仪、人员资质档案、设备隔离清单及监管平台。日常文档包含风险辨识记录、动火/受限空间/吊装等作业票、环境监测记录、危废台账、排放监测数据、事故与隐患整改报告。数据更新随单次作业完成、监测要求实时更新或定期检查更新，文档字段含作业类型、气体检测值、人员资质编号、隔离设备编号，对应单位包括ppm、立方米、小时等。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据更新随单次作业完成、监测要求实时更新或定期检查更新，且文档结构差异大，包含结构化字段与半结构化文本，对索引的实时性与适配性提出约束。数据涉及安全环保与作业许可，需严格控制召回结果的相关性，避免无关内容干扰风险判断。危废、排放监测等数据带有明确单位字段，向量索引需保留字段关联以防止语义混淆。高频更新的作业票与监测数据，要求索引支持增量更新，避免全量重索引带来的资源占用与查询延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配作业票、监测记录等文本的语义完整性，避免过短导致语义断裂，过长增加向量计算负担 |
| 重叠长度 | 50–100 字符 | 保留跨块的上下文关联，防止作业步骤、监测序列被分块割裂 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性结果，避免无关作业票或监测数据干扰安全判断，适配本品类高置信度要求 |
| 单次搜索上限 | 前 8 条 | 平衡查询速度与召回覆盖，确保核心风险相关文档被优先召回 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 512 token | 适配结构化字段的短文本向量化，确保人员资质、设备编号等字段的语义一致性 |

## 容易做错的三处
- 现象：查询结果返回大量无关的历史作业票，无有效风险辨识内容。原因：未设置合理的相似度阈值，或未开启重排功能，导致低相关性内容被优先召回。
- 现象：部署后磁盘占用快速增长，远超原文件总大小。原因：未清理过期的作业票、监测记录等数据，同时未配置向量索引的增量更新策略，导致重复存储分块文本与嵌入向量。
- 现象：首次查询时出现超时报错，返回状态码504。原因：分块长度设置过大，或单次搜索上限过高，导致向量计算与上下文拼接超出模型处理上限，引发超时。

## 怎么确认配好了
- 查看向量索引的更新日志，确认新增的作业票、监测记录等数据能自动完成增量索引，无需全量重建。
- 输入典型安全问题，核对返回结果的相关性，调整相似度阈值与单次搜索上限至符合业务需求的范围。
- 检查磁盘占用统计，确认嵌入向量与分块文件的占用比例符合预期，无重复存储的冗余数据。
- 验证FastGPT v4.17.0版本的索引模型渠道配置路径，确保可正常调用指定的向量模型。
