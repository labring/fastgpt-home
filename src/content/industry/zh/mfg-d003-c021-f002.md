# 家具与木制品制造的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
这个品类的核心数据通常来自订单设计系统、板材与木材批次台账、数控开料钻孔设备日志、ERP/MES系统及含水率检测记录。日常文档通常包含拆单图、开料清单、封边与钻孔程序、涂装工艺规范、五金配件清单、试装及包装记录。数据更新随订单生成、每日设备日志同步、每批材料批次更新，文档字段包含板件尺寸、纹理色号、孔位参数、五金型号、含水率指标，单位多为毫米、千克、百分比等。

## 这些特征在「向量模型与索引」这一环带来什么约束
定制订单驱动的板件多且个性化，拆单生成的拆单图、开料清单等文档数量随订单规模激增，需索引支持高并发召回。板材与木材批次的含水率、纹理色号等精细参数，要求向量模型能捕捉细微文本差异。数据更新频率差异大，需支持增量索引，避免生产间隙的索引延迟。板件孔位、五金匹配的精准性要求，需限制无效召回结果，同时保留跨订单的相似工艺参考。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配拆单图、开料清单等文档的单块信息密度，避免块内信息割裂 |
| 重叠长度 | 100–150 字符 | 覆盖板件尺寸、孔位参数等跨块关联字段，防止关键信息被截断 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非工艺相关结果，保障工艺规程问答的精准性 |
| 单次搜索上限 | 前 20 条 | 保留足够的工艺参考样本，同时避免上下文过载 |
| `defaultToken` | 按实测标定 | 适配工艺文档的基础文本长度，保障基础召回的稳定性 |
| `maxToken` | 4000 | 容纳多份开料清单、涂装工艺的组合信息，支撑复杂工艺问题的解答 |

## 容易做错的三处
- 界面提示“外部索引服务未响应”，原因是在将索引存储从默认PGSQL迁移至目标服务时，未正确配置连接参数，导致服务无法建立连接。
- 召回结果仅包含零散板件参数，未覆盖完整工艺规程，原因是分块长度设置过短，导致工艺规范文本被拆分后丢失关联逻辑。
- 无法启用私有化重排模型，原因是未在配置中指定私有化模型的本地部署地址，误使用公共模型调用路径，导致模型接入失败。

## 怎么确认配好了
- 上传一份真实的开料清单文档，检索“18mm板件开料参数”，核对返回结果是否包含文档内的板件尺寸、切割参数。
- 模拟批量上传10份不同订单的拆单图，查看索引同步进度是否随数据更新自动完成，无全量重建延迟。
- 调用测试接口传入“孔位偏移导致安装失败”的问题，查看返回结果是否包含涂装、五金匹配的关联工艺信息。
- 检查索引存储的磁盘占用，确认未出现因分块过大导致的存储空间异常增长。
