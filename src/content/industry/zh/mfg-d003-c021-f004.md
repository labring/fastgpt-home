# 家具与木制品制造的工艺规程与技术标准问答：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自订单设计系统、板材与木材批次台账、数控开料与钻孔设备、ERP/MES系统及含水率检测设备。数据更新节奏随订单、每日或每批材料变动。日常文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金物料清单、试装与包装记录，字段涵盖板件尺寸、板材批次号、工艺参数、五金型号等，单位包含毫米、立方米、件等。

## 这些特征在「工作流编排」这一环带来什么约束
定制订单驱动的业务模式要求工艺数据匹配个性化设计，需精准关联每一批板材、每一个板件的参数。板件数量多且文档体量较大，大体积文档的处理需适配拆分逻辑。数据随订单、批次或每日更新，工作流需支持实时同步最新台账与工艺文件。板件尺寸错误、色差等出错后果直接影响交付，工作流需强化结果校验环节，避免不合格参数流入生产环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配开料清单、工艺文件的单段内容长度，避免单块包含跨页逻辑 |
| 重叠长度 | 50–100 字符 | 保留块间上下文关联，确保工艺步骤的连贯性 |
| `variables` | 绑定当前订单的板材、五金参数 | 确保问答调用的参数与当前生产批次匹配 |
| `nodeId` | 绑定对应工艺环节的唯一标识 | 精准匹配工作流节点与实际生产步骤 |
| 单次问答上限 | 前 3 条 | 匹配单批次生产的核心参数范围，避免冗余信息干扰 |
| 错误重试次数 | 2 次 | 平衡响应速度与问答成功率，避免长时间阻塞工作流 |

## 容易做错的三处
- 现象：工作流执行时出现循环体嵌套报错，状态码返回参数非法。原因：未按FastGPT v4.17.0的规则配置多层循环的触发条件，导致嵌套层级超出限制。
- 现象：导入10万中文字word或15000行excel文档后，问答结果出现字段缺失。原因：未设置合理的分块长度，导致长文档被错误拆分，丢失关键工艺参数。
- 现象：工作流生成的多轮问答结果包含全部历史回复，未仅返回最后一次回答。原因：未正确配置上下文保留条数，或未在节点中设置仅输出当前节点结果的规则。

## 怎么确认配好了
- 上传单份10万中文字的工艺文档，检查工作流分块后的内容是否完整保留关键板件尺寸参数。
- 触发多轮问答流程，验证仅最后一次节点的回复被输出，历史上下文不混入最终结果。
- 配置循环体后，执行嵌套测试，确认无参数非法报错，循环逻辑正常触发。
- 查看生成文件的引用标记，确认已关闭额外引用内容的输出。
