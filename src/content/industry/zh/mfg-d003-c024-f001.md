# 工艺变更与工程变更的工艺规程与技术标准问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据来自PLM、ERP、MES、供应商资料、验证试验及客户特殊要求，更新随每次工艺或工程变更不定期触发。日常文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本记录、工艺验证报告、生产切换计划、库存处置单及客户批准文件。数据字段包含变更编号、版本号、生效日期、关联工序/物料清单、审批状态与验证结果，无统一固定的批量更新节奏，每份文档绑定明确的版本切换节点。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于数据来源覆盖多套生产管理系统，接口需支持跨系统鉴权与格式适配，避免因数据格式不统一导致的解析失败。变更触发的不定期更新要求接口支持事件驱动同步或按需拉取最新版本数据。每份文档绑定明确的版本切换节点，接口需携带版本标识参数以确保返回对应版本的工艺规程内容。数据关联多部门审批流程，接口需同步传递审批状态字段，避免返回未完成审批的变更内容。多系统数据的关联性要求接口需支持批量拉取关联文档，避免单次请求返回过多冗余数据。

## 配置怎么定
本配置基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization`头配置 | 携带Bearer类型令牌，绑定企业统一鉴权密钥 | 适配多生产系统的跨域鉴权需求，避免跨域报错 |
| `variables`参数 | 传入变更编号、版本号、生效日期三个核心变量 | 确保接口返回对应版本的工艺规程与标准内容 |
| `responseData`过滤 | 提取审批状态、关联工序字段，丢弃冗余附件信息 | 匹配变更管理团队的核心查询需求 |
| 超时阈值 | 30秒 | 适配多系统数据拉取的平均响应时长 |
| 重试次数 | 2次，间隔5秒 | 应对临时的跨系统网络波动 |
| 单次查询条数 | 前10条 | 匹配单次变更关联文档的平均数量 |

## 容易做错的三处
- 前端调用接口时返回CORS跨域报错，状态码为403或405。原因是未在FastGPT配置中添加前端域名到允许跨域列表，或未正确配置`Authorization`头的鉴权格式。
- 调用接口后无法获取有效鉴权密钥，提示数据库查询相关报错。原因是未明确密钥的存储位置与查询规则，未关联对应数据库表的查询逻辑。
- 调用接口后未按预期拦截指定关键词并调用外部系统。原因是未在对话流程中配置关键词触发规则，或未正确绑定外部系统的接口地址与参数。

## 怎么确认配好了
- 使用前端测试工具发送携带`Authorization`头的请求，检查是否返回正常的工艺规程内容，无跨域报错。
- 传入不同的变更编号与版本号参数，核对返回的文档内容是否匹配对应版本的ECN/ECR表单。
- 触发变更事件后，检查外部系统是否收到同步的接口请求，携带正确的审批状态与关联字段。
- 模拟超时场景，检查接口是否按配置的重试次数自动重试，无阻塞现象。
