# 工艺变更与工程变更的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
制造企业变更管理团队日常产生的文档包含ECN/ECR、变更评估报告、图纸与BOM版本、工艺验证报告、切换计划、库存处置单、客户批准文件。数据来源覆盖PLM、ERP、MES、供应商资料、验证试验记录与客户特殊要求，更新节奏为不定期，每次工艺或工程变更触发一次更新。文档包含结构化的BOM字段与非结构化的验证报告文本，无统一固定字段，需适配多格式数据的统一处理。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求向量索引支持跨系统数据的统一预处理与增量同步，避免因数据格式差异导致嵌入失败。不定期的更新节奏需要索引配置适配非周期性触发的增量更新，避免全量索引占用过多资源。文档包含结构化与非结构化内容，要求分块策略兼顾不同格式的语义完整性。变更涉及多类关联文档，要求索引保留版本关联元数据，以便检索时区分新旧版本的变更内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配ECN、工艺验证报告等非结构化文档的语义完整性，避免块内语义断裂 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工艺步骤与变更关联信息，防止变更描述被截断 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 区分工艺变更的核心关联与边缘关联，适配变更场景下的精准检索需求 |
| 单次搜索上限 | 前 8 条 | 覆盖变更涉及的多类文档（BOM、图纸、验证报告）的关联结果 |
| 最大上下文 | 4000 token | 适配变更评估报告的长文本整合需求，满足FastGPT v4.17.0的默认上下文上限 |

## 容易做错的三处
- 接入第三方向量模型时返回401状态码。原因：未正确配置模型的API访问密钥，或密钥未被授权执行向量嵌入操作。
- 自定义切分文档后，知识库自动删除重复块导致检索顺序与切分结果不匹配。原因：开启了知识库的全局重复块去重功能，未保留切分顺序的关联元数据。
- 配置向量索引后，检索响应超时。原因：未根据变更文档的更新频率调整增量索引的触发间隔，全量索引频繁触发导致资源占用过高。

## 怎么确认配好了
- 提交向量模型接入测试请求，确认返回的嵌入向量格式符合平台要求，无401、超时等报错。
- 上传一份包含重复内容的变更文档，检查知识库是否保留了切分后的块顺序，或根据配置调整去重规则。
- 发起工艺变更相关的检索请求，确认返回结果的数量与单次搜索上限的配置一致。
- 查看索引更新日志，确认增量索引仅在变更文档上传后触发，未出现无意义的全量更新。
