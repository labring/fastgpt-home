# 工艺变更与工程变更的工艺规程与技术标准问答：模型接入与配置
本文适配FastGPT v4.17.0版本的模型接入配置流程。

## 这个品类的数据长什么样
本品类的数据来自PLM、ERP、MES、供应商资料、验证试验及客户特殊要求，更新节奏为不定期，随每次工艺或工程变更触发。日常文档包含ECN/ECR、变更评估报告、图纸与BOM版本、工艺验证报告、切换计划、库存处置单、客户批准文件，字段涵盖变更单号、版本号、生效日期、物料编码等，部分文档附带图形化参数，无统一固定单位，随文档类型适配。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求配置适配不同系统的文档格式解析规则；不定期的更新节奏需要支持增量同步的触发逻辑，避免冗余数据加载；包含图纸与文本的混合文档结构，要求模型支持视觉解析能力；关联文档多且关联性强的特点，要求配置足够的上下文承载量，避免关键变更信息截断；同时，数据错误会直接导致生产风险，要求模型输出的版本、参数等信息具备高准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 承载ECN、BOM版本等多份关联文档的完整内容，避免截断关键变更信息 |
| `maxTokens` | 2000–3000 token | 控制单轮回答长度，确保工艺变更的详细步骤、切换计划等内容完整输出 |
| `quoteMaxToken` | 1500–2000 token | 限定引用的源文档片段长度，匹配工艺规程单条标准内容的常见篇幅 |
| `vision` | 开启 | 处理图纸、验证报告中的图形化工艺参数与标注，适配品类内的非文本数据 |
| `temperature` | 0.1–0.3 | 降低回答随机性，确保变更单号、版本号、生效日期等关键信息输出准确 |
| `AIPROXY_API_TOKEN` | 按系统授权生成并限定长度 | 避免令牌长度超出存储字段限制，保障接入安全 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应节点 | 适配多系统接入的API路径，确保数据同步与调用正常 |

## 容易做错的三处
- 现象：保存模型配置后，发起聊天时自动切换为其他大模型。原因：未将`AIPROXY_API_TOKEN`与指定模型绑定，或配置了多组令牌未明确生效范围。
- 现象：上传ECN、图纸等文档后处理速度过慢。原因：未调整`maxContext`或`quoteMaxToken`参数，导致模型对长文本的解析负载过高。
- 现象：添加令牌时提示Data too long for column 'models'。原因：未按系统要求截断令牌长度，或配置的模型列表超出字段存储上限。

## 怎么确认配好了
- 发起工艺规程相关的查询，核对返回内容中引用的文档版本、变更单号与源数据一致。
- 上传包含图纸的验证报告，确认模型能正确识别图纸中的工艺参数与标注。
- 测试多轮变更问答，确认上下文未出现版本混淆或关键信息截断。
- 检查API调用日志，确认令牌验证通过，无长度超限或路径错误提示。
