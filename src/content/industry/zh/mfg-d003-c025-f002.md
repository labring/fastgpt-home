# 工装夹具与检具制造的工艺规程与技术标准问答：向量模型与索引

本页面所有配置建议均适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的日常文档包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历。数据来源涵盖产品数模与GD&T、工艺路线、三坐标数据、现场试用反馈及计量系统。数据更新按项目推进，伴随每次产品变更与定期校准执行。文档包含结构化的形位公差参数、坐标测量值，以及半结构化的操作说明与变更记录，字段涉及毫米级公差值、校准日期、检测次数等专业内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据类型多样，包含结构化的公差参数、半结构化的操作说明与图纸转写内容，且更新频率随项目与产品变更波动。这要求向量索引支持增量更新，适配不同格式的数据分块。同时，专业术语如GD&T、定位基准的语义精度要求高，检索时需过滤低相关结果，避免因误匹配导致工艺方案偏差。此外，长文档如完整验收报告的拼接需求，要求向量模型的上下文处理能力适配较长的输入长度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 覆盖工装需求书、夹具图说明等单块文本的合理长度，避免分块过碎或过长 |
| 重叠长度 | 100–150 字符 | 保留定位基准、工艺路线等连续内容的上下文关联，防止关键信息被分割 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.85–0.90 | 匹配工装数据的高精度要求，过滤低相关的检索结果 |
| 单次搜索上限 | 前3条 | 工艺方案具有唯一性，过多结果会增加工程师的筛选成本 |
| 问题优化 | 开启 | 修正工装术语的口语化表述，提升检索匹配精度 |

## 容易做错的三处
- 检索结果出现大量不相关的检具操作书内容，原因是分块重叠长度设置过小，导致定位基准的上下文被割裂，无法匹配到精准结果。
- 使用m3e embedding模型时检索精度不足，原因是未针对GD&T、三坐标数据这类专业术语调整分块策略，导致专业语义未被正确编码。
- 提交工装变更数据后调用创建训练订单，未生成更新后的索引，原因是未将变更履历、校准记录等数据正确关联到训练任务，导致索引未同步更新。

## 怎么确认配好了
- 上传一份包含工装需求书和夹具图说明的混合文档，检查分块后的文本块长度落在预设的800–1200字符区间内。
- 发起一次包含“定位基准方案”的测试查询，查看检索结果的相似度分值是否符合预设的0.85–0.90阈值范围。
- 发起两次完全相同的工艺查询，确认第二次查询的响应时间明显短于第一次，验证缓存机制生效。
- 提交一份工装变更履历的更新数据，等待训练订单完成后，发起对应查询，确认检索结果包含更新后的变更内容。
