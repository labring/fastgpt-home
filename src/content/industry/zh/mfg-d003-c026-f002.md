# 有色金属冶炼与电解的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自铜、铝、铅锌等冶炼企业的熔炼、电解、化验与调度部门，日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账。数据来源于精矿与辅料分析、DCS系统、槽电压电流监测、化验室检测、能源与环保监测设备，更新频率随每批原料、每炉或每槽作业实时变动，文档包含成分参数、工况数值、质量指标等字段，单位涉及品位、安培、伏特、吨等。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时高频的更新节奏要求索引支持增量同步与批量重索引，避免全量重建占用过多计算资源。多源异构的数据类型，既有数值型工况记录也有文本型台账文档，需要统一的分块与向量化适配规则。文档字段多涉及专业工业参数，对向量召回的术语匹配精度要求较高，需选择适配流程工业专业语料的向量模型。单批作业文档量随生产节奏波动，需配置合理的索引分片策略以平衡检索效率与资源占用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配冶炼行业单段专业内容的长度，避免跨作业单元的内容拼接，保障工艺问答的语义完整性 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，适配电解槽况、熔炼记录的连续工况语义召回 |
| `maxToken` | 8192 | 适配FastGPT v4.17.0支持的主流开源embedding模型token上限，覆盖单批次作业的完整记录内容 |
| 相似度阈值 | 0.75–0.85 | 平衡专业术语召回的精准度与覆盖率，适配冶炼场景下工艺规程问答的业务需求 |
| 单次搜索上限 | 前 8 条 | 匹配多工况关联的检索需求，避免冗余结果干扰核心工艺问题的解答 |
| `defaultToken` | 2048 | 设置基础分块的token基准值，适配短文本类的化验报告、环保台账等文档 |

## 容易做错的三处
- 现象：批量重新嵌入知识库后，多语言工艺问答的召回率未达标，检索结果偏离专业术语。原因：未针对冶炼行业的专业语料调整embedding模型适配配置，直接更换通用模型导致专业语义丢失。
- 现象：手动插入的工艺文档索引在数小时后自动消失，后台日志显示索引分片丢失。原因：未配置索引的持久化存储策略，实时更新的作业数据触发了系统默认的索引清理机制。
- 现象：上传化验报告后界面长期显示“索引中”状态，无进度更新。原因：选用的`maxToken`设置超出了当前绑定的embedding模型支持上限，导致分块向量化任务阻塞。

## 怎么确认配好了
- 随机选取10份覆盖不同类型的生产文档，执行分块测试，确认分块长度覆盖文档核心内容且无冗余拼接。
- 发起包含专业术语的工艺问答，核对检索结果的召回条数与相似度分布，调整阈值至符合业务需求的区间。
- 上传一份实时更新的电解槽况记录，确认索引在10分钟内完成同步，无长期挂起状态。
- 查看向量数据库的索引分片状态，确认所有文档的索引条目均已正常生成且无丢失。
