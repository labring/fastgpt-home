# 有色金属冶炼与电解的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
有色金属冶炼与电解的日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账。数据来源涵盖精矿与辅料分析报告、DCS系统数据、槽电压电流监测数据、化验室检测结果、能源与环保监测记录。数据更新频率随生产节点变化，每批原料、每炉熔炼或每槽电解均会生成新数据，部分监测项为实时更新。文档字段包含原料杂质占比、槽运行电压、电流强度、金属回收率、污染物排放值等，对应单位涉及吨、克/升、毫伏、安培等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类数据来源分散且更新频繁，多轮对话需限制历史上下文的长度，避免冗余数据干扰模型判断。文档包含大量专业工艺字段，提示词需明确要求模型仅引用对应品类的文档内容，不得臆造未提及的参数。实时更新的槽况、熔炼数据要求对话链路能快速召回最新文档，多轮对话的历史轮次需匹配生产节奏，避免过多旧数据影响当前问题的解答。同时，杂质控制、金属平衡等核心业务点需在提示词中明确优先级，确保模型聚焦关键指标。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配该品类单份文档的平均长度，避免单块包含无关业务字段 |
| 重叠长度 | 150–200 字符 | 确保相邻文档块的工艺细节不被截断，维持配料、槽况等流程的连贯性 |
| 最大上下文 | 3000–5000 token | 限制多轮对话的历史数据量，适配该品类实时更新的高频数据特征 |
| 单次召回上限 | 前 6 条 | 匹配该品类单轮生产相关的核心文档数量，避免过多冗余数据干扰模型 |
| 历史对话保留轮次 | 前 3 轮 | 限制`messages`数组的历史内容，匹配生产流程的单批原料或单槽的对话逻辑 |
| 对话会话标识 | `chatId`绑定当前会话 | 用于区分不同生产批次的对话上下文，确保多轮对话的上下文一致性 |

本文基于FastGPT v4.17.0版本配置。

## 容易做错的三处
- 对话请求接口返回结果无cite引用id。原因是未关联该品类的工艺文档库，未开启文档元数据的引用标识生成。
- 多轮对话无法以历史问题作为关键词展开回复。原因是未限制`messages`数组的历史轮次，或提示词未明确要求绑定上下文关键词。
- 代理运行时输出思考过程但对话记录不展示。原因是未在`variables`中配置隐藏思考过程的参数，或代理配置未同步至对话链路。

## 怎么确认配好了
- 发起包含电解槽电压、原料杂质占比的提问，检查返回结果是否附带对应文档的来源标识。
- 发起连续多轮提问，验证下一轮回复是否关联上一轮提及的工艺细节或问题关键词。
- 查看代理运行日志，确认思考过程是否按配置隐藏，未出现在公开对话记录中。
- 导入一批同品类的熔炼记录，测试对话是否能召回对应批次的配料数据与检测结果。
