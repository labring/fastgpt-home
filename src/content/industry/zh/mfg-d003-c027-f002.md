# 服装裁剪与缝制的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自服装OEM/ODM车间、品牌供应链的生产环节，包含工艺单、样板参数、排料图、裁剪单、首件封样记录、工序质量表、包装配码单等文档。数据来源涵盖订单尺码表、CAD样板文件、面辅料检验记录、吊挂系统生产数据、验针机检测结果及客户封样要求。数据更新频率为每订单、每款、每批，单份文档包含裁片编号、面料方向、尺码配比、工序步骤等精准字段，无通用统计类抽象字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。首先，多来源的混合格式数据（结构化工序表与非结构化工艺描述）要求分块时保留字段关联性，避免破坏裁片、尺码等关键关联信息。其次，高频更新的订单级数据要求索引支持增量同步，避免全量重建带来的性能损耗。再者，单款服装的工艺细节差异细微，要求向量模型的语义匹配精度足够，同时索引需支持按订单、款号等维度过滤检索范围。最后，面料裁片的不可逆属性要求检索结果的准确性，避免因分块或匹配错误导致生产偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxToken` | 8192 token | 适配当前主流向量模型的上下文上限，覆盖服装工艺单的完整段落长度 |
| 分块长度 | 800–1200 字符 | 匹配工艺单中单工序描述的常规长度，避免切分破坏裁片编号、面料要求等关键信息 |
| 重叠长度 | 50–100 字符 | 保留跨块的裁片编号、尺码配比等关联字段，确保语义检索的连贯性 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 区分相似工艺单的细微差异，避免误匹配非目标款的工序要求 |
| 单次搜索上限 | 前 10 条 | 聚焦精准匹配的工艺结果，避免过多冗余信息干扰问答判断 |
| `defaultToken` | 1024 token | 适配用户工艺提问的常规输入长度，符合FastGPT v4.17.0版本的模型调用要求 |

## 容易做错的三处
- 现象：更换非ada-002的向量模型时出现“undefined model must match”报错。原因：未在FastGPT平台配置对应模型的API密钥，或未开通对应模型的调用权限。
- 现象：单款服装的裁片、工艺单等关联数据无法匹配到同一检索结果，检索分数很高但不符合实际工艺要求。原因：分块时未保留面料方向、尺码配比等核心字段，或相似度阈值设置过低导致无关结果被优先召回。
- 现象：单份数据仅能绑定一组向量模型，无法配置多组关联向量。原因：未开启FastGPT的多向量集功能，或未按版本要求配置关联数据的字段映射规则。

## 怎么确认配好了
- 上传单份完整工艺单文档，检查分块结果是否保留了工序编号、面料要求、裁片数量等核心字段，无关键信息被截断的情况。
- 提交包含具体工艺要求的提问，查看检索结果的分块来源是否与原始文档的结构匹配，无跨无关工序的错误匹配。
- 更换不同的向量模型进行测试，确认无模型适配报错，检索结果的一致性符合预期，阈值可根据实际召回效果调整。
- 上传批量更新的订单数据，检查索引是否自动完成增量更新，无重复或遗漏的文档条目。
