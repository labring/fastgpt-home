# 来料检验与供应商质量的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来自采购订单、图纸与规格文件、供应商质保书、检验设备采集数据、历史质量记录及供应商门户。日常文档包含检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D整改记录与让步接收审批单。数据更新随每批来料、每月或季度供应商评价、不定期审核同步推进。文档多包含批次号、抽样量、不合格项等级、供应商编码等字段，单位涉及件、批次、ppm等。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散于多个系统，要求索引支持多源数据的统一接入与元数据关联。更新频率波动大，既有每批来料的高频增量更新，也有季度级的批量同步，需适配增量索引与全量索引的切换。文档结构多样，包含纯文本、表格与嵌入图片，需支持不同格式的分块与向量化。关键字段如批次号、供应商编码需作为检索过滤条件，要求索引支持元数据筛选功能。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的功能逻辑，具体如下：
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 来料检验相关文档多为短段落搭配结构化表格，该长度可保留单份检验规范或抽样方案的完整上下文 |
| 重叠长度 | 100–200 字符 | 批次号、抽样规则等关键信息常跨段落分布，重叠分块可避免关键信息被截断 |
| 相似度阈值 | 0.75–0.85 | 需区分合格与不合格判定标准的细微差异，该区间可平衡检索准确率与召回率 |
| 单次搜索上限 | 前 10 条 | 来料检验的决策仅依赖少量高匹配度的规范与历史记录，过多结果会干扰快速判定 |
| `defaultToken` | 2000 token | 适配单份工艺规程或检验报告的常规向量化长度，避免单次请求超出模型限制 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 混淆创建训练订单与集合添加数据的功能，现象为重复执行训练订单创建导致索引冗余，原因为未明确训练订单用于批量同步供应商质保书、历史质量数据等增量更新场景，误将单条文本添加也走训练订单流程。
- 图片向量化后无法关联检索，现象为检索结果仅返回文本片段，无对应图片的关联信息，原因为未在分块时将图片元数据与对应检验规范的编号绑定，未配置图片向量化的索引关联规则。
- 模型选择受限，现象为无法选择指定的Embedding模型，原因为未在FastGPT配置中更新对应的模型映射列表，或本地部署时未正确配置oneAPI的模型端点权限。

## 怎么确认配好了
- 上传一份供应商审核报告，检查分块后的文本是否完整保留了批次号、抽样量等关键字段。
- 发起一次来料检验标准的检索，确认返回结果的相似度处于预设阈值区间内。
- 查看训练订单的执行日志，确认增量更新的历史质量数据已正确同步至索引中。
- 测试图片向量化上传，确认检索结果中附带图片的关联元数据信息。
