# 来料检验与供应商质量的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据覆盖制造企业来料检验、供应商质量相关的多类文档，包括检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告及让步接收审批文件。数据来源包含采购订单、产品图纸与规格、供应商质保书、检验设备记录、历史质量数据及供应商门户信息。更新节奏随每批来料生成新数据，每月或季度完成供应商评价更新，不定期开展审核类数据迭代。文档字段包含批次号、AQL抽样值、不合格项分类、供应商资质编号等，部分文件需关联版本号与批次信息匹配校验。该品类的质量控制对象来自外部供应商，与内部过程检验的数据源逻辑存在差异，需严格区分外部供应商的专属数据范围。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据分散于采购订单、供应商门户等多类来源，且更新频率随每批来料、季度评价动态变化，要求多轮对话需关联上下文参数锚定当前批次或供应商的专属数据。文档包含批次号、AQL值等专属字段，需在对话中明确匹配版本与批次信息，避免跨批次规则混淆。多类文档的字段逻辑差异较大，提示词需引导用户指定查询的文档类型，同时限制单次召回的文档数量，防止冗余信息干扰对话判断。此外，历史质量数据与当前检验结果的关联需求，要求对话上下文保留足够的历史交互信息用于追溯。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配检验规范、抽样方案等文档的段落长度，避免拆分关键字段 |
| 重叠长度 | 100–150 字符 | 保留跨块的批次号、版本号等关联信息，防止字段被拆分断裂 |
| 单次搜索上限 | 前 6 条 | 匹配该品类单批次检验相关的文档数量，避免召回过多非关联的历史数据 |
| 最大上下文 | 4000 token | 承载多轮对话中的批次信息、历史检验结果，确保交互逻辑连贯 |
| `chatId` | 绑定当前检验批次的唯一标识 | 区分不同来料批次的对话上下文，避免跨批次数据混淆 |
| `variables` | 预设批次号、供应商名称变量 | 自动带入对话上下文，减少用户重复输入的操作成本 |

## 容易做错的三处
- 上传检验规范或供应商质保书后，数据处理环节返回空结果。原因是分块长度设置过大或过小，导致包含批次号、AQL值的关键段落无法被完整索引。
- 知识库搜索调试正常，但AI对话返回的答案未关联上传的来料报告内容。原因是未绑定`chatId`参数，导致对话上下文未关联当前批次的知识库数据。
- 登录数据库后无法查询到指定批次的对话历史记录。原因是未正确配置对话历史的存储规则，导致`messages`参数未被正确写入对应集合。

## 怎么确认配好了
- 上传一份包含明确批次号的来料报告文件，发起查询该批次抽样规则的对话，验证返回结果包含报告中的AQL值内容。
- 发起两轮以上的对话，每次提及不同的来料批次，验证系统能正确区分两次对话的上下文，返回对应批次的检验规则。
- 调用对话接口发起请求，检查返回结果中是否包含`chatId`字段，且字段值与当前检验批次的标识一致。
- 查看数据处理日志，确认上传的文档已被成功拆分并生成索引条目，无空索引记录。
