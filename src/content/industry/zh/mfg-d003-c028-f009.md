# 来料检验与供应商质量的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来源包括采购订单、图纸和规格、供应商质保书、检验设备、历史质量数据、供应商门户。数据更新随每批来料、每月或季度供应商评价、不定期审核变动。日常文档涵盖检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D整改报告、让步接收审批单，包含来料批次号、抽样量、不合格项、供应商编码等字段，单位涉及件、批次、天等。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且多为外部供应商相关文档，需配置多源数据接入路径以覆盖不同供应商的质保文件与检验记录。更新频率随来料批次高频变动，需适配增量更新的触发逻辑，避免全量重建带来的资源消耗。文档包含批次、抽样量等特定业务字段，需匹配字段提取与结构化处理的配置，确保问答能精准关联对应批次的检验标准。质量风险关联生产环节，需严格控制模型输出的严谨性，避免因配置不当导致误判或漏判。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 来料检验相关文档多为批次级详细内容，需覆盖完整的工艺规程与技术标准上下文 |
| `temperature` | 0.1–0.3 | 该场景需严谨的标准引用与判定，避免输出出现偏差 |
| `maxTokens` | 2000–3000 token | 需完整输出检验判定依据、整改建议与相关文档引用 |
| `quoteMaxToken` | 前6条召回文档 | 需覆盖多份抽样方案、历史检验数据与供应商审核记录 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或云端的模型调用路径，匹配FastGPT v4.17.0的代理配置规范 |
| `AIPROXY_API_TOKEN` | 按实际申请的密钥填写 | 确保模型调用的身份验证有效 |

## 容易做错的三处
- 现象为对话响应超时，日志显示`ETIMEDOUT`状态码，原因是未适配该场景高频的批次级数据召回，未调整`maxContext`或超时相关配置。
- 现象为对话与工作区的模型返回结果不一致，原因是未统一配置`temperature`与`maxTokens`参数，导致不同应用实例的生成逻辑出现差异。
- 现象为OneApi调用报错，提示未授权或路径错误，原因是未正确填写`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`，混淆了本地部署与第三方代理的配置路径。

## 怎么确认配好了
- 上传一份来料检验规范文档，触发召回测试，核对召回文档的数量与内容匹配度，调整相关配置以符合业务需求。
- 发起一次抽样方案相关的问答，核对输出是否包含准确的字段引用，调整生成类配置参数以优化结果严谨性。
- 模拟批量来料的更新场景，验证向量库的增量更新是否正常触发，适配数据更新频率的变动。
- 调用配置的代理接口，验证返回结果与FastGPT工作区的一致性，核对API配置项的正确性。
