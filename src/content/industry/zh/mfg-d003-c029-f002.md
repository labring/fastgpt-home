# 模具设计制造的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
典型主体为注塑、冲压、压铸模具企业及制造企业模具中心，日常文档包含模具设计任务书、DFM报告、零件图、加工工艺卡、试模报告、改模通知、模具履历。数据来源涵盖客户产品模型、模流或成形仿真结果、CAD/CAM文件、机加工与测量数据、试模样件，更新按项目节点、每次试模或改模触发，文档包含长文本、结构化参数与非结构化缺陷描述等混合类型。

## 这些特征在「向量模型与索引」这一环带来什么约束
日常文档的混合类型导致分块策略需适配长文本与短文档的差异，避免工艺步骤被割裂；按项目与高频改模的更新节奏，要求索引支持增量更新，避免全量重建带来的服务负载过高；数据来源包含CAD导出的长文本内容，需适配大token量的向量生成；模具工艺的步骤关联性强，向量召回需结合上下文关联与关键词匹配，确保召回内容符合工艺逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配模具设计任务书、DFM报告等长文档的文本密度，避免单块内容割裂工艺步骤 |
| 重叠长度 | 100–150 字符 | 覆盖试模报告、改模通知等短文档的上下文关联，防止关键信息被分块截断 |
| 相似度阈值 | 0.75–0.85 | 匹配模具工艺规程中精准的步骤描述与试模缺陷的对应关系，避免无关召回 |
| 单次搜索上限 | 前8条 | 适配模具设计的多零件装配精度校验需求，覆盖关联的工艺卡与零件图信息 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 512 token | 适配常规工艺卡的短文本向量生成，平衡生成效率与召回精度 |

## 容易做错的三处
- 现象：启动向量服务时报错提示「索引连接失败」，状态码返回503。原因：未按照模具数据的增量更新频率配置索引的自动同步周期，导致外部索引库与本地文档库的版本不一致引发连接校验失败。
- 现象：召回结果中出现大量不相关的试模报告内容，结果条数远低于预期。原因：未设置合理的相似度阈值，将低匹配度的非工艺类文档纳入召回范围，未结合模具数据的结构化字段做过滤。
- 现象：导入CAD导出的工艺文件后，向量索引生成超时。原因：未调整`maxToken`和`defaultToken`参数适配长文本，导致单块文本超出模型支持的token上限，触发超时报错。

## 怎么确认配好了
- 导入一份典型的模具设计任务书，检查向量分块后的文本是否完整保留工艺步骤，无明显内容截断。
- 发起一条关于试模缺陷整改的查询，核对召回结果的条数与单次搜索上限的配置一致。
- 查看向量索引的更新日志，确认每次改模或试模后，关联文档能自动触发增量索引更新。
- 测试外部索引库的连接，确认服务启动后无连接报错提示。
