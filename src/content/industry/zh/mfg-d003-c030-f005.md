# 橡胶混炼与制品硫化的工艺规程与技术标准问答：工具调用与插件

## 这个品类的数据长什么样
该品类的核心数据来自配方系统、原材料批次台账、密炼机运行日志、门尼粘度仪、流变仪、硫化机记录及实验室成品性能报告。日常产出的文档包含配方单、称量记录、混炼曲线、胶料快检结果、硫化工艺卡、模具使用记录、成品性能检测报告。数据更新节奏为每车原材料批次、每批胶料生产、每模次硫化作业各生成一次对应记录。单份文档包含明确的字段，如混炼温度、硫化时间、胶料门尼值等，不同设备导出的记录格式存在差异。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且更新频率高，要求工具调用需支持动态拉取不同设备的实时或近实时日志，避免因数据滞后导致工艺查询结果不准确。多格式的文档要求插件需适配多种数据源的解析规则，无法通过单一模板完成所有数据的提取。严格的出错后果要求工具调用需具备参数校验与失败重试机制，防止因错误的工艺参数调用导致胶料报废或制品失效。按批次、模次更新的数据要求工具调用的查询范围需绑定当前生产批次，避免跨批次数据混淆。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动匹配工艺规程与技术标准相关的工具，无需手动指定调用目标 |
| `functionCall` | `enabled` | 开启函数调用能力，支持调用混炼曲线查询、硫化参数匹配等专用工具 |
| 工具调用超时阈值 | `300 秒` | 适配密炼机、硫化机日志的加载与解析耗时，避免因数据量大导致请求中断 |
| 工具调用重试次数 | `2 次` | 应对原材料批次数据接口临时波动，降低单次请求失败的概率 |
| 上下文窗口大小 | `8000–12000 token` | 覆盖完整的工艺规程文档与多批次数据，确保查询时的上下文完整性 |
| 查询结果返回条数上限 | `前 5 条` | 避免过多历史数据占用上下文窗口，保证查询效率 |

## 容易做错的三处
- 调用工具时返回{"code":514,"statusText":"unAuthApiKey"}，原因是未正确绑定工具调用所需的API密钥，或密钥已过期未完成更新。
- 工具调用中更新的全局变量未在后续环节生效，原因是未开启全局变量同步开关，导致变量作用域未覆盖工具调用流程。
- 配置`toolChoice`为`auto`后，工具未触发预期的硫化工艺查询，原因是未在系统中绑定对应品类的专用工具，导致自动选择的工具与业务场景不匹配。

## 怎么确认配好了
- 发起包含“查询当前批次胶料的混炼温度参数”的测试请求，检查工具是否返回对应密炼机的运行日志数据。
- 查看工具调用日志，确认无unAuthApiKey报错，且API密钥状态正常。
- 手动更新原材料批次的全局变量后，发起硫化工艺查询，检查结果是否包含最新批次的对应参数。
- 配置`functionCall`为`enabled`后，发起包含多参数的工艺查询，检查工具是否返回结构化的结果数据。
