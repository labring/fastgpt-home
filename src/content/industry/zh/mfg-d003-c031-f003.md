# 水泥熟料与粉磨的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源包括在线成分分析设备、DCS控制系统、化验室、窑磨生产设备、原燃料台账与能源计量系统。数据更新节奏覆盖实时、每班与每日三类。日常文档包含生料配料方案、窑炉操作记录、化验报告、质量控制通知单、设备巡检记录与能源消耗报表。数据字段涵盖原燃料理化参数、窑温工况指标、粉磨细度参数、能耗数值与质量检验结果，单位包含摄氏度、吨、兆焦等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
实时更新的工况数据要求多轮对话需保留近期有效上下文，避免引用过期的窑炉热工参数。多类文档的字段差异要求提示词需明确指定检索范围，仅调用对应业务场景的文档内容。每班与每日更新的报表数据，要求对话过程中可按需调取指定周期的历史记录。原燃料波动下的配料调整场景，要求多轮对话可逐步传递原燃料成分参数，逐步迭代生成适配的生料配料方案。同时需严格匹配工艺规程与技术标准的表述，避免生成不符合生产规范的内容。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按会话自动生成唯一标识 | 实现多轮对话的上下文隔离与关联，确保不同会话的数据互不干扰 |
| `messages` | 保留最近15–20轮对话内容 | 适配实时工况数据的时效性，避免引用过期的窑炉或粉磨参数 |
| `variables` | 绑定当前生产班次与车间参数 | 快速调取对应周期的巡检记录、能耗报表与质量检验数据 |
| 最大上下文长度 | 8000–12000 token | 覆盖生料配料、窑炉热工调节、粉磨参数调整等完整业务场景 |
| 单次检索上限 | 前5–7条匹配文档 | 控制返回内容的信息量，避免冗余数据干扰对话逻辑 |
| 问题优化 | 开启 | 自动将口语化提问转换为符合工艺规程与技术标准的专业表述 |

## 容易做错的三处
- 调用对话接口返回422错误。原因：未正确传递`messages`参数，或参数格式不符合系统要求，或未绑定对应生产场景的知识库变量。
- 多轮对话出现上下文共享问题。原因：未设置唯一`chatId`标识，或未使用`variables`参数传递用户标识，导致不同会话的对话记录互相干扰，未做用户隔离配置。
- 文件上传后无法检索到对应内容。原因：未配置支持生料配料方案、化验报告等品类专属文档的格式，仅开放了部分基础格式。

## 怎么确认配好了
- 发起测试对话，输入“查询今日生料配料方案”，核对返回内容包含对应班次的参数，且无过期数据。
- 发起两轮以上独立对话，检查不同会话的上下文不会互相干扰，确认`chatId`生效。
- 上传生料配料方案文档，发起相关提问，确认系统可检索到对应内容。
- 调用对话接口测试，检查返回结果无422错误，确认参数传递正确。
