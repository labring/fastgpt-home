# 水泥熟料与粉磨的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
该品类数据覆盖水泥企业矿山、生料、烧成、粉磨、质量和能源部门，日常文档包含生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录、能源报表。数据来源包括在线成分分析系统、DCS控制系统、化验室检测数据、窑磨设备运行数据、原燃料台账、能源计量报表，更新节奏涵盖实时、每班、每日。文档字段包含物料成分占比、设备运行参数、检测结果数值、能耗指标，单位涉及百分比、吨、千瓦时、MPa等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
数据来源分散且更新节奏差异大，实时类的窑磨运行数据需保障溯源时的时间戳匹配，避免跨批次引用混淆。多部门文档结构差异明显，需明确对应知识库的分类标签以精准关联来源。化验报告、质量控制通知单等带检测数值的文档，需保留原始字段与单位避免溯源时信息失真。原燃料台账与能源报表的批量数据，需在溯源时区分单条记录的归属批次，防止错误关联。同时，因出错后果直接关联熟料质量与生产停机，溯源环节需确保引用来源的唯一性与可追溯性，避免模糊关联。

## 配置怎么定
本页配置适用于FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配该品类单份文档的平均长度，保障完整引用关键参数与检测结果 |
| `responseData` | 开启并包含引用源元数据 | 满足工艺规程问答需明确标注来源文档类型、检测批次与所属部门的需求 |
| `detail` | 开启 | 允许返回引用文档的原始字段与单位，避免信息截断导致的参数歧义 |
| 单次搜索上限 | 前6条 | 覆盖单轮问答涉及的配料、窑操作、化验等多类文档的核心引用需求 |
| 引用来源展示粒度 | 按文档分类 | 匹配该品类按部门、文档类型划分的知识库结构，便于生产人员快速定位来源 |

## 容易做错的三处
- 现象：问答返回结果中引用源字段为空。原因：未开启`responseData`配置项，未启用引用源返回开关。
- 现象：调用API时可返回的引用条数不足，无法覆盖所需的工艺参数。原因：`quoteMaxToken`设置区间过窄，无法加载多份关联文档的来源信息，导致系统截断来源数据。
- 现象：引用文档无法下载查看原始内容。原因：未配置引用源的文件存储路径权限，或未关联知识库的原始文档上传记录。

## 怎么确认配好了
- 发起一条包含生料配料参数的测试问答，检查返回结果中是否包含明确的引用源文档名称与来源部门。
- 调用问答API，查看返回的JSON结构中是否包含`responseData`字段，且字段内包含引用源的详细元数据。
- 调整`quoteMaxToken`的取值，验证引用文档的展示长度是否匹配设置的token区间。
- 测试引用文档的下载链接，确认可正常访问原始上传的化验报告或设备巡检记录。
