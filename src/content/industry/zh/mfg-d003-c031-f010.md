# 水泥熟料与粉磨的工艺规程与技术标准问答：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来自水泥企业矿山、生料、烧成、粉磨、质量和能源部门，涵盖生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检、能源报表等文档。数据来源包括在线成分分析系统、DCS控制系统、化验室、窑磨设备、原燃料台账与能源计量装置，更新频率覆盖实时、每班、每日。文档字段包含配料比例、窑温、投料量、熟料游离钙、水泥强度等，单位涉及℃、t/h、%、MPa等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源导致不同文档的字段格式存在差异，需要统一映射为标准化的工艺参数字段，避免检索时出现匹配偏差。不同更新频率的文档需要适配增量更新策略，实时数据需高频同步，每班/每日数据需按固定周期触发更新。多样的文档类型需要匹配不同的分块规则，例如配料方案需按参数组分块，操作记录需按班次分块。工艺问题多围绕原燃料波动调整、热工制度稳定、强度控制展开，检索需精准匹配专业术语与操作场景，同时需保证召回结果的置信度，避免引入错误的工艺参数引发生产异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 匹配水泥工艺参数的精度要求，过滤低匹配度的无效结果 |
| `limit` | `前10条` | 控制单轮检索返回的结果数量，避免上下文过载影响后续处理 |
| `usingReRank` | 开启 | 工艺文档包含大量专业术语，重排可提升相关结果的排序准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 适配原燃料波动场景，扩展配料调整相关的查询词范围 |
| `searchMode` | 语义检索 | 工艺问题多为非结构化的操作描述，语义检索匹配更贴合业务需求 |

## 容易做错的三处
- 现象为应用内开启`usingReRank`后检索无结果，但知识库测试界面返回正常结果。原因是应用的重排模型配置未同步到知识库检索链路，或重排模型的上下文长度未适配工艺文档的分块大小。
- 现象为知识库搜索耗时超过10秒。原因是未设置合理的`limit`参数，召回了过多非相关文档，导致检索与重排环节的计算量增加。
- 现象为知识库始终无内容显示。原因是未正确配置`collectionIds`参数，未关联对应工艺文档的数据集，或增量更新任务未按预设频率触发。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理界面，核对`collectionIds`参数关联的数据集是否包含生料配料方案、窑操作记录等目标文档。
- 触发一次工艺相关的检索请求，查看返回结果的`similarity`分值是否符合预设区间，确认`usingReRank`功能正常生效。
- 模拟原燃料波动的查询场景，验证`datasetSearchUsingExtensionQuery`是否扩展了相关配料调整的查询词，返回匹配的工艺文档。
- 查看检索日志，确认单次检索返回的结果条数不超过预设的`limit`值，无明显超时或字段缺失报错。
