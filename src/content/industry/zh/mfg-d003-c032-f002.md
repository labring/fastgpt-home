# 汽车整车总装的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
汽车整车总装场景的数据来源覆盖ERP/MES系统、VIN与配置系统、供应商批次管理系统、拧紧工具终端、EOL检测线及质量追溯系统。日常文档包含生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录与一致性放行文件。数据更新频率涵盖每车级的实时写入、每班级的批量同步，核心字段包含VIN码、零件编号、扭矩值、检测项编号与批次号，不同文档的结构差异较大，既有结构化的拧紧数据，也有非结构化的作业指导书文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
该场景的混线生产模式要求索引支持按VIN码精准隔离不同车型的工艺数据，避免跨车型的配置混淆。实时更新的拧紧数据与下线检测报告需要索引支持增量同步，避免全量索引重建带来的性能损耗。多类型文档的混合索引需要兼容结构化字段与非结构化文本的向量编码，确保工艺要求与检测数据的关联准确性。同时，工艺问答的出错后果直接关联车辆下线与安全质量，要求向量召回的精度需匹配业务的严格管控需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配装配作业指导书的标准段落长度，避免跨工位工艺信息被割裂 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工序关联信息，比如拧紧工序的前置扭矩要求 |
| `defaultToken` | 4096 token | 匹配整车工艺文档的平均长度，支持完整读取单工位的全部工艺要求 |
| `maxToken` | 8192 token | 支持完整读取多工位的联合工艺要求与整车级配置信息 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 平衡召回准确率与召回量，避免错配低关联的工艺条款 |
| 单次搜索上限 | 前 8 条 | 适配单工位的工艺项数量，避免上下文过载影响模型理解 |
| 重排 | 私有化部署专业重排模型 | 针对汽车工艺的专属术语优化排序精度，提升高关联结果的优先级 |

## 容易做错的三处
- 现象：向量召回结果中出现非当前工位的工艺要求。原因：未按VIN维度构建分块索引，混线生产时未隔离不同车型的配置数据，导致跨车型的工艺信息被错误召回。
- 现象：向量查询出现超时或连接报错。原因：未开启增量索引更新，实时写入的拧紧数据与下线报告未按批次分片，触发全表扫描或存储连接异常。
- 现象：返回的工艺标准与实际作业要求不符。原因：未使用适配汽车专业术语的重排模型，通用模型无法识别扭矩、VIN匹配等专属字段的优先级，导致排序偏差。

## 怎么确认配好了
- 导入单台整车的VIN与对应工位的作业指导书，发起工艺问答，核对召回结果是否包含当前工位的明确要求。
- 查看索引更新日志，确认实时写入的拧紧数据、返修记录能完成索引同步。
- 测试向量存储连接，确认配置的存储服务能正常接收查询请求，无连接异常报错。
- 调整相似度阈值，观察召回结果的数量变化，确认阈值设置符合业务的精度管控要求。
