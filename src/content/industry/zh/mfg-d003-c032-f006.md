# 汽车整车总装的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
汽车整车总装的核心数据来自ERP、MES系统、VIN与配置系统、拧紧工具、EOL检测线及质量追溯系统。日常文档包含生产订单、VIN清单、装配作业指导书、拧紧扭矩数据（单位N·m）、下线检测报告、返修记录与一致性放行文件。数据更新节奏为每车级实时更新、每班级批量更新，字段包含VIN码、扭矩阈值、工位编号、检测批次号与返修单号，单篇作业指导书通常覆盖10-20项装配步骤。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于总装以VIN为单车主线进行混线生产，引用溯源必须精准绑定单台车的配置与装配数据，不能跨VIN召回无关文档。实时拧紧数据与下线检测报告的时效性要求极高，需在问答响应周期内完成最新数据的匹配与溯源。单台车涉及数百项装配配置，引用内容需控制在合理范围，避免过载干扰对话逻辑。一旦引用错误，可能导致错配漏装、车辆无法下线甚至安全召回，因此溯源必须明确到具体工位、工具与批次，不可模糊引用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 8000–12000 token | 单篇总装作业指导书通常超过2000字符，需足够token承载完整引用内容，避免截断关键工艺步骤 |
| 单次搜索上限 | 前8条 | 单台车总装核心工艺文档约6-7项，过多召回会引入无关供应商批次数据，干扰核心问答逻辑 |
| `responseData` | 开启VIN关联过滤 | 混线生产场景下，需仅召回与当前问答绑定VIN匹配的配置、零件与工艺文档，避免跨车引用 |
| 相似度阈值 | 0.72–0.78，按实测标定 | 总装文档术语专业且重复性高，该区间可过滤低相关的通用文档，保留精准的工位级工艺内容 |
| `detail` | 开启完整引用路径展示 | 需展示数据源所属工位、拧紧工具ID、检测批次号等字段，满足总装质量追溯的要求 |
| 重排规则 | 按工位时间戳排序 | 总装工艺按工位顺序执行，优先展示当前及前序工位的工艺标准，符合装配人员的使用习惯 |

以上配置逻辑基于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：对话中显示本地知识库未收录的引用内容。原因：未配置`responseData`的VIN关联过滤，混线生产时跨VIN的历史文档被意外召回。
- 现象：知识库引用排序不符合工艺逻辑，未按工位顺序展示。原因：未启用按工位时间戳重排，仅使用基础相似度排序，导致无关后续工位的文档优先展示。
- 现象：引用内容被截断无法查看完整工艺步骤。原因：`quoteMaxToken`设置低于8000 token，未匹配总装文档的字符长度，导致关键扭矩参数或步骤被截断。

## 怎么确认配好了
- 发起绑定已知VIN的工艺问答，核对引用内容是否仅包含该VIN对应的装配作业指导书与检测数据，无跨VIN的无关文档。
- 查看引用模块的排序，确认前序工位的工艺文档优先于当前及后续工位的内容，符合总装装配顺序。
- 检查引用卡片是否包含完整的数据源路径，如工位编号、拧紧工具ID或检测批次号，无模糊的数据源标注。
- 测试引用展示开关，确认可按需隐藏或展示知识库引用内容，无强制展示的冗余信息。
