# 汽车零部件批量制造的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
汽车零部件批量制造的核心数据来自制动、转向等系统供应商的日常生产文档，包括控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料及8D报告。数据来源涵盖客户图纸与特殊特性清单、ERP/MES系统、量检具、设备过程参数及供应商质保书，更新频率为每批、每班持续采集，文档结构包含工序参数、质量特性、异常记录等固定字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源与高频更新节奏，要求向量索引支持增量同步与多格式文档解析，避免因数据更新不及时导致工艺问答失效。不同文档的固定字段（如特殊特性、SPC参数）存在非标准化的数值与单位，需要向量模型适配非归一化的向量输出，同时配置`defaultToken`作为短文本查询的基准，适配工艺问题的短关键词检索。工序关联的连贯性要求分块逻辑避免断裂关键工艺步骤，强合规性约束下，召回结果需严格匹配客户指定的质量体系文档，对相似度阈值与召回条数设置提出明确要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配作业指导书、控制计划等文档的单段有效信息长度，符合FastGPT v4.17.0的向量模型输入限制 |
| 重叠长度 | 100–200 字符 | 避免分块断裂工序步骤、质量记录等连贯信息，提升检索完整性 |
| 相似度阈值 | 0.75–0.85 | 精准匹配特殊特性、工艺参数等关键信息，适配批量制造的质量合规要求 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 归一化配置 | 开启 | 适配未归一化的embedding模型，满足向量匹配的一致性要求 |

## 容易做错的三处
- 现象：切换知识库向量模型后界面显示无进度，且无法重新切换。原因：未在索引管理中先清空原有向量库，直接触发模型切换导致同步任务阻塞。
- 现象：配置豆包embedding API后测试返回"404 page not found"。原因：未正确填写模型接入的专属域名路径，或API密钥权限未开放向量模型调用权限。
- 现象：检索结果缺失首件巡检记录的完整参数。原因：分块长度设置过短，将单条巡检记录的参数拆分到多个分块中，导致向量匹配时无法关联完整信息。

## 怎么确认配好了
- 查看向量索引的同步日志，确认所有配置的数据源均已完成首次索引，无失败记录。
- 发起测试查询，输入工艺规程或质量记录相关关键词，核对返回结果的文档类型与数据源匹配度符合预设要求。
- 测试向量模型切换功能，确认新模型加载后同步任务正常启动，无阻塞报错。
- 检查归一化配置开关状态，确认与当前使用的embedding模型适配要求一致。
