# 烘焙与方便食品的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
本品类的典型数据来自原辅料合格证明、ERP/MES系统、称量设备、烤炉或油炸线、实验室检测设备及食品追溯台账。日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据更新频率为每批、每班或每日，其中配方与投料单随换线更新，生产记录随班次更新，烘烤曲线随单批次生成。文档字段包含原料名称、用量、温度、时间、过敏原标注、检测结果等，部分文档带有明确的单位标注。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于数据高频更新且换线频繁，索引需支持增量同步以避免全量重建的耗时；文档包含结构化的配方字段与半结构化的时序曲线，分块时需保留字段关联，避免切断过敏原、投料顺序等关键信息；高风险内容如异物控制、过敏原标注需精准匹配，因此向量召回的相关性要求更高；单条长文档如完整烘烤曲线的内容长度较大，需适配token长度限制，同时短文档如金属检测记录需适配基础token配置。此外，多批次的关联文档需被同时召回，因此索引的召回范围需覆盖近期生成的多份文档。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配烘焙配方、烘烤曲线等文档的内容长度，保留关键字段的完整上下文 |
| 重叠长度 | 100–150 字符 | 避免分块切断过敏原标注、投料顺序等跨块关联信息 |
| 相似度阈值 | 0.75–0.85 | 精准匹配高风险内容如异物控制、过敏原相关的查询，过滤低相关结果 |
| 单次搜索上限 | 前 8 条 | 覆盖换线频繁场景下多批次的关联文档，满足工艺复核的信息需求 |
| `maxToken` | 4096 token | 适配完整烘烤曲线等长文本文档的内容长度，避免分块被截断 |
| `defaultToken` | 512 token | 适配金属检测记录、清洁消毒记录等短文档的内容长度，优化索引存储 |

## 容易做错的三处
- 现象：搜索结果相关性偏低，关键信息未被召回。原因：分块重叠长度设置不足，切断了过敏原标注与对应投料记录的关联，导致向量无法捕捉跨块的关键关联。
- 现象：索引中无数据或部分文档未被收录。原因：未配置增量更新触发规则，仅执行全量索引任务，无法适配每批、每班的高频更新节奏。
- 现象：搜索请求无法返回最后一组分块结果或返回空内容。原因：`maxToken`设置小于单条长文档的token数量，导致长文本分块无法被正确加载与索引。

## 怎么确认配好了
- 上传1份典型的配方与投料单文档，查看分块预览是否保留了原料名称、用量、过敏原标注等关键字段的完整上下文。
- 触发1次增量同步任务，检查索引更新日志中是否包含近24小时内生成的生产记录文档。
- 输入高风险查询如「本次批次的过敏原物料清单」，核对返回结果的分块是否覆盖了对应投料单的关联内容。
- 上传1份完整的烘烤曲线文档，确认索引中存在对应分块的向量数据。
