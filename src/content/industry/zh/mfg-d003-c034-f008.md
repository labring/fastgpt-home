# 烘焙与方便食品的工艺规程与技术标准问答：文档解析与分块

## 这个品类的数据长什么样
面包糕点、饼干、方便面和速冻面点工厂的日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源包括原辅料合格证明、ERP/MES、称量系统、烤炉或油炸线、实验室、食品追溯台账。更新频率为每批、每班或每日。文档结构多为结构化表格、带时间轴的曲线文件、标准化表单，字段包含物料编码、批次号、工艺参数区间、检验结果等，单位涉及克、摄氏度、分钟、保质期天数等。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类文档包含大量结构化表格与非结构化工艺说明，普通文本分块会割裂表格内的字段关联，需适配表格解析逻辑；多批次的生产记录按时间或批次更新，分块需保留批次与时间戳的关联信息；烘烤或蒸煮曲线为非结构化文件，需支持曲线数据的提取与关联；过敏原标注字段属于合规关键信息，需在分块时精准保留，避免丢失；频繁换线带来多版本文档，需支持按批次或时间戳关联对应分块内容。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 该品类文档包含长文本工艺说明与结构化表格，该区间可保留单批次投料单或单段烘烤参数的完整信息 |
| `chunkSplitter` | `按段落+表格块拆分` | 日常文档混合了非结构化文本与结构化表格，该拆分方式可兼顾文本逻辑与表格完整性 |
| `customPdfParse` | `启用表格识别模式` | 日常文档包含烘烤曲线、投料单等带表格的PDF文件，启用后可保留表格的行列字段关联关系 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120–180 秒` | 大型生产记录PDF或多批次Excel文件解析耗时较长，该区间可覆盖多数文档的解析需求 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 该品类需上传多批次归档的生产记录与检验报告，该上限可满足批量文件的上传需求 |
| `chunkSettingMode` | `手动配置` | 该品类文档结构差异较大，需针对不同文档类型调整分块规则 |

## 容易做错的三处
- 现象：上传Excel格式的投料单后，检索时返回的国外产地物料条目少于源文件。原因：默认分块未保留表格的完整列关联，导致产地字段被拆分丢失，匹配时无法完整召回对应条目。
- 现象：上传docx格式的工艺规程后，RAG检索结果未包含章节标题。原因：分块配置未开启章节标题绑定，导致标题与正文被拆分至不同分块，检索时无法关联匹配。
- 现象：上传超过500MB的烘烤曲线PDF后，解析任务超时失败。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以完成大型非结构化PDF的解析。

## 怎么确认配好了
- 上传单批次投料单Excel文件，查看解析后的分块内容，确认物料名称、用量、过敏原标注等字段完整关联，无拆分丢失。
- 上传包含表格的烘烤曲线PDF，启用`customPdfParse`后，确认解析结果保留表格的行列结构与数值信息。
- 上传500MB以内的多批次生产记录归档文件，确认解析任务在180秒内完成，无超时报错。
- 检索过敏原相关问题，确认检索结果包含对应章节的标题与正文内容，无字段遗漏。
