# 烘焙与方便食品的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来自面包糕点、饼干、方便面及速冻面点工厂的多系统与电子/纸质文档，包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告等。数据来源覆盖原辅料合格证明、ERP/MES系统、称量设备、烤炉或油炸线、实验室检测及食品追溯台账，更新节奏随生产批次、班次或每日变动，文档字段包含过敏原标识、投料重量、烘烤温度窗口、保质期、清洁消毒频次等，部分文档需关联多批次生产数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类多批次、高频更新的文档，要求模型接入时需适配增量同步逻辑，避免全量刷新占用过多资源；丰富的细分字段（如过敏原标识、投料重量、烘烤温度窗口）要求检索时需精准匹配字段维度，避免泛化召回无关内容；直接食用的产品属性让过敏原、异物控制相关问答的准确性要求更高，需限制模型调用的冗余数据；换线频繁的特点要求配置支持快速切换不同产品线的知识库文档集，避免跨品类数据干扰生产工艺的问答准确性。

## 配置怎么定
本配置指南基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配该品类长文档的工艺规程与生产记录，避免截断关键参数内容 |
| `maxTokens` | 2000–3000 token | 匹配工艺参数解释类问答的内容需求，平衡响应速度与信息完整性 |
| `quoteMaxToken` | 1500–2000 token | 限制单条引用的文档长度，避免过长引用混淆过敏原、烘烤窗口等关键信息 |
| `temperature` | 0.1–0.3 | 降低回答随机性，确保工艺参数、过敏原标识等确定性内容的回答准确一致 |
| 工作流/API 工具选择配置 | auto | 按需调用检索工具，适配不同工艺问答的实时数据调用需求 |
| `AIPROXY_API_ENDPOINT` | 按所选模型服务商提供的地址填写 | 适配模型接入的网络调用规则，确保数据传输正常 |

## 容易做错的三处
- 现象：语义检索得分0.77，但模型返回找不到相关信息。原因：检索召回的文档未截取关键字段，或引用的token超出配置限制，导致模型无法提取有效信息。
- 现象：知识库查询流量较大时出现响应超时。原因：未合理限制`maxContext`或`quoteMaxToken`的取值，导致每次调用传输过多token，超出模型接口的流量承载范围。
- 现象：模型混淆不同产品线的过敏原标识。原因：未按产品线拆分知识库文档集，导致检索召回跨品类的冗余数据，干扰模型判断。

## 怎么确认配好了
- 发起一条过敏原相关的工艺问答，核对模型引用的文档是否来自当前生产批次的相关记录。
- 调整`temperature`参数后，发起多条相同的工艺参数问答，确认回答内容的一致性。
- 模拟高流量场景下的调用，检查接口响应时间是否符合业务预期的阈值要求。
- 切换不同产品线的知识库配置，确认问答内容自动匹配对应产品线的工艺文档。
