# 热处理的工艺规程与技术标准问答：向量模型与索引
本文适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据源包括材料牌号标准、客户技术条件、温控仪表原始数据、炉温均匀性测试报告、硬度计与金相设备检测结果、车间MES系统记录。数据更新频率为每炉次或每批次，单批次关联文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单等类型。文档字段包含加热温度（单位℃）、保温时间（单位h或min）、冷却介质、硬度值（单位HV或HRC）、炉温偏差值等，部分文档包含时间-温度对应曲线的结构化片段。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据按炉次或批次更新，单次工艺问答需关联多份同批次文档，因此索引需支持按批次维度的精准召回。文档包含大量带数值的工艺参数与结构化曲线片段，向量模型需适配数值型字段的语义匹配，避免切片时破坏温度与时间的对应关系。部分数据来自设备仪表的原始日志，格式与标准化工艺卡存在差异，索引需兼容多格式文本的嵌入处理。同时，工艺参数的细微偏差会直接影响零件力学性能，检索结果的精准度要求高于通用场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配热处理工艺卡、炉温曲线的单段文本长度，避免拆分破坏温度-时间对应关系 |
| 重叠长度 | 100–150 字符 | 保留相邻炉次/批次的工艺衔接信息，防止切片切断装炉位置描述 |
| 相似度阈值 | 0.75–0.85 | 区分工艺参数的细微差异，避免误匹配不同材料牌号的热处理制度 |
| `defaultToken` | 1024 | 控制单段嵌入的token数量，适配热处理文档的单段文本长度 |
| `maxToken` | 8000 | 适配检索时的上下文长度要求，覆盖单炉次的全部关联文档 |
| 单次搜索上限 | 前6条 | 覆盖单炉次的关联文档，比如工艺卡、炉温曲线、硬度报告 |

## 容易做错的三处
- 检索结果返回多条无关的轴承热处理工艺，原因是相似度阈值设置过低，将相近温度参数的不同工件工艺误匹配，可能导致后续工艺执行错误。
- 检索时出现超时报错，错误代码显示请求耗时超出阈值，原因是单次搜索上限设置过高，同时加载了过多跨批次的炉温曲线数据。
- 嵌入后的向量无法匹配工艺卡中的保温时间参数，原因是分块长度设置过短，拆分时切断了温度与时间的对应关联，导致语义信息丢失。

## 怎么确认配好了
- 上传单份热处理工艺卡，执行检索测试，检查返回结果的分块是否保留了完整的加热-保温-冷却流程描述。
- 输入包含具体温度与时间的查询，核对返回结果的相似度分值是否落在预设的0.75–0.85区间内。
- 模拟异常查询（如某炉次的硬度异常），确认检索结果包含对应的异常处置单与金相报告。
- 查看嵌入任务的日志，确认未出现token超出限额的报错，符合`defaultToken`与`maxToken`的配置设置。
