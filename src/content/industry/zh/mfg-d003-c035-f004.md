# 热处理的工艺规程与技术标准问答：工作流编排

## 这个品类的数据长什么样
热处理场景的数据来源于材料牌号档案、客户技术条件、温控仪表、炉温均匀性测试设备、硬度计与金相设备，以及车间MES系统。数据按每炉次、每批更新，涵盖热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单等文档。核心字段包含材料牌号、加热温度、保温时长、冷却速度、硬度值、炉号等，单位涉及摄氏度、小时、HV硬度单位等。

## 这些特征在「工作流编排」这一环带来什么约束
热处理数据按炉次更新的特性要求工作流需绑定单炉次的触发时机，避免跨批次数据混淆。多类型文档与多数据源的组合，要求工作流需适配结构化数据库、时序曲线文件、质检报告等不同格式的输入。核心工艺参数校验耗时较长的环节，要求工作流需拆分校验步骤并设置合理的超时节点。出错后果严重的特性，要求工作流需配置异常分支跳转与校验环节，避免不合格流程流入后续环节。

## 配置怎么定
本文基于FastGPT v4.17.0版本配置。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源触发时机 | 每炉次数据同步完成后触发 | 匹配热处理数据按炉次更新的更新节奏 |
| 变量绑定规则 | 绑定`variables`中定义的材料牌号、炉温参数 | 工艺规程与技术标准问答依赖固定核心字段 |
| 节点超时设置 | 120–180秒 | 适配炉温数据采集与参数校验的常规耗时 |
| 历史上下文限制 | 前8条历史问答记录 | 匹配单炉次问答的场景边界 |
| 异常分支跳转 | 绑定`nodeId`为异常处理节点 | 规避热处理工艺出错导致的批量不合格风险 |
| 日志输出路径 | 工作流执行日志目录 | 便于排查数据库连接、参数校验类问题 |

## 容易做错的三处
- 现象：数据库连接报错Failed to connect to jyfkk:1433 - 38BBDDC3AF7F0000，原因：未配置正确的MSSQL实例地址与端口，或网络策略限制了1433端口访问。
- 现象：代码运行模块的console.log日志无法在前端控制台查看，原因：未开启工作流详细日志开关，或日志未同步至前端展示界面。
- 现象：工作流执行超时终止，原因：未设置匹配热处理工艺校验的超时时间，导致关键参数校验环节被强制中断。

## 怎么确认配好了
- 触发一次模拟炉次数据同步，检查工作流是否按配置的时机自动启动。
- 查看工作流执行日志，确认`variables`绑定的核心字段与`nodeId`关联的异常节点均正常生效。
- 模拟输入不符合工艺要求的参数，检查异常分支是否按配置触发跳转。
- 验证数据库连接配置，确认能正常拉取热处理工艺卡、炉温曲线等对应数据。
