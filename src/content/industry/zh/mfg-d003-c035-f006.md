# 热处理的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
专业热处理厂、汽车、轴承零部件厂的热处理车间日常数据包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单。数据来源覆盖材料牌号、客户技术条件、温控仪表、炉温均匀性测试设备、硬度计与金相设备、生产执行系统，更新频率为每炉次、每批。文档包含明确的字段与单位，如工艺卡标注加热温度、保温时间，硬度报告标注洛氏硬度或维氏硬度，炉温曲线包含时间轴与实时温度数值。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据更新频率高且单批次数据关联紧密，要求溯源必须精准匹配具体炉次或批次，避免泛化召回。文档类型多样，包含文本、表格、曲线等格式，要求溯源支持多格式源数据的片段提取与关联。数据来源涵盖设备自动采集与人工填写两类，要求溯源清晰标识数据的生成渠道与录入主体。单份数据包含专业参数与明确单位，要求溯源需展示具体字段与数值，辅助业务人员核对。同时，出错后果严重，要求溯源环节必须确保引用的内容与实际生产数据完全一致，杜绝无关或错误的引用。

## 配置怎么定
本配置适用于FastGPT v4.17.0

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.85–0.92 | 匹配热处理工艺的专业术语，避免低相关的召回结果 |
| 最大上下文 | 8000–12000 token | 容纳炉温曲线、工艺卡等多段文本的完整内容 |
| `quoteMaxToken` | 1500 字符 | 限制单条溯源内容的长度，适配热处理文档的单页或单段片段 |
| `responseData` | 仅返回源数据 | 确保回答仅使用知识库内的原文答复，不生成额外内容 |
| `detail` | 开启完整溯源 | 展示源文档的具体字段与单位，如加热温度、硬度值等 |
| 召回结果条数 | 前3–5条 | 覆盖同炉次相关的工艺卡、装炉图、炉温曲线等多份文档 |

## 容易做错的三处
- 现象：返回的回答未直接使用知识库内的原文答复，出现非预设的生成内容。原因：未正确配置`responseData`参数，未锁定仅返回源数据的模式。
- 现象：界面显示已关联源数据，但回答中未附带具体的文档片段或参数细节。原因：未开启`detail`配置，或召回结果条数设置过少，导致溯源信息未被完整提取。
- 现象：配置索引相关参数后系统长时间无响应，注释对应配置并重启服务后问题仍未解决。原因：未针对热处理文档的多格式特征调整分块策略，导致索引构建时出现异常，或系统资源被过量的单炉次数据占用。

## 怎么确认配好了
- 发起包含具体热处理参数的查询，核对回答是否与知识库内的原文答复完全一致。
- 查看回答附带的溯源信息，确认是否包含源文档的具体字段与单位，如加热温度、保温时间、硬度值等。
- 检查系统日志，确认未出现token溢出或索引构建异常的报错信息。
- 测试多份不同炉次的查询，确认溯源信息能准确关联到对应的工艺卡、炉温曲线等文档。
