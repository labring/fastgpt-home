# 热处理的工艺规程与技术标准问答：文档解析与分块

## 这个品类的数据长什么样
本品类数据来自专业热处理厂、汽车与轴承零部件厂热处理车间，日常文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单，部分文档为多页汇总报表，单份页数可达千级。数据来源覆盖材料牌号、客户技术条件、温控仪表、炉温均匀性测试设备、硬度计与金相设备、MES系统，更新频率为每炉次、每批。文档字段包含工艺参数（加热温度、保温时长、冷却速率）、设备编号、测试数值（硬度值、金相组织等级）、异常描述与处置方案，单位多为摄氏度、小时、兆帕、HV等。

## 这些特征在「文档解析与分块」这一环带来什么约束
本品类数据的高频更新、多文档类型与专用字段特征，对文档解析与分块带来多重约束。需区分单炉次数据与批量汇总内容，避免跨炉次参数合并分块；需绑定工艺参数与对应单位，防止解析后数据与单位分离；针对Excel格式的点检表、硬度报告，需精准识别表头与数据行的对应关系，避免块内混入无关行；针对长文档如年度炉温汇总报表，需定位单炉次段落，防止跨批次内容被合并。同时需兼容PDF格式的装炉图、炉温曲线等非文本类文档的解析关联，确保图片与对应文本参数绑定。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 热处理文档包含连续的单炉次工艺参数与测试数据，该区间可保证单块包含完整的工艺单元，避免参数拆分 |
| `chunkSplitter` | 按段落+固定字符截断 | 热处理文档的工艺段落、测试报告段落结构清晰，按段落拆分可保留语义完整性，固定字符截断可适配长文档的批量处理 |
| `customPdfParse` | 启用炉号识别+页眉页脚过滤 | 热处理PDF文档多包含炉号、批次号等标识，启用该配置可过滤无关页眉页脚，精准定位单炉次内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 长文档如年度炉温汇总报表解析耗时较长，该时长可覆盖单份千页文档的完整解析 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量上传的年度汇总报表与多批次文档，避免大文件上传失败 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（工艺卡、炉温曲线、Excel点检表）可分别调整分块参数，适配专用字段结构 |

本配置基于FastGPT v4.17.0版本

## 容易做错的三处
- 现象：Excel格式的点检表、硬度报告解析后返回不完整命令提示。原因：未针对Excel文档配置表头识别与行分组规则，导致大模型无法识别数据结构。
- 现象：长文档如年度炉温汇总报表解析超时。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`至足够时长，或未适配长文档的解析规则。
- 现象：分块颗粒度过大，包含多炉次的工艺内容。原因：`chunkSize`设置超出单炉次工艺参数的长度范围，未结合炉号标识进行分块。

## 怎么确认配好了
- 上传单份热处理工艺卡PDF，检查解析后分块是否包含完整的加热温度、保温时长、冷却速率参数，无页眉页脚残留。
- 上传Excel格式的点检表，检查分块是否按表头分组，每行数据与对应表头绑定，无缺失字段。
- 上传千页级的年度炉温汇总报表，检查解析过程未触发超时，分块按炉号或批次进行划分。
- 测试多类型文档混合上传，确认不同文档类型的分块规则自动适配，无跨类型内容合并。
