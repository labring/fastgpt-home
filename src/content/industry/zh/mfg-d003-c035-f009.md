# 热处理的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
热处理场景的数据来源包括材料牌号标准、客户技术条件、炉温控仪表、炉温均匀性测试记录、硬度计与金相设备检测报告、车间MES系统。数据更新频率为每炉次、每批。日常文档包含热处理工艺卡、装炉布置图、炉温曲线图表、硬度与金相分析报告、设备点检表、异常处置单。字段包含炉温（℃）、保温时长（小时）、冷却速率（℃/min）、硬度值（HV）、金相组织类型等，部分文档附带工艺相关的图像资料。

## 这些特征在「模型接入与配置」这一环带来什么约束
热处理场景的数据更新频率高，单炉次数据需实时纳入上下文，因此配置需适配高频的文档索引与更新。文档包含结构化工艺参数与非结构化图像、曲线，要求模型支持多模态内容识别与结构化信息提取。专业字段带有明确的工程单位，问答需严格匹配既定参数，因此需限制模型的自由生成空间。部分数据涉及零件服役安全，问答结果需可追溯至原始文档，因此需配置足够的上下文引用长度。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 热处理场景需容纳多份炉次工艺卡、炉温曲线等文档的完整内容，避免关键上下文被截断 |
| `quoteMaxToken` | 2000–3000 token | 需完整引用单份工艺文档的核心参数，确保问答结果可追溯至原始数据 |
| `temperature` | 0.1–0.3 | 工艺规程与标准问答需严格匹配既定参数，降低模型自由生成的偏差 |
| `vision` | 开启 | 热处理文档包含装炉布置图、金相显微照片等图像资料，需模型识别图像中的工艺信息 |
| `AIPROXY_API_ENDPOINT` | 部署节点的专属API地址 | 实现模型的定向调用，避免全局配置的干扰 |
| `AIPROXY_API_TOKEN` | 对应模型的访问密钥 | 保障API调用的权限安全，防止未授权访问 |

## 容易做错的三处
- 现象：保存模型配置后，发起聊天时自动切换为未指定的大模型。原因：未在应用层级锁定配置的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，导致调用全局默认的模型配置。
- 现象：上传金相报告、炉温曲线等图像文档时，处理耗时过长。原因：未配置本地预处理加速节点，或开启了非必要的多模态预处理流程，增加了文档解析负担。
- 现象：问答结果出现与实际工艺参数不符的偏差。原因：`temperature`取值过高，导致模型生成偏离既定标准的内容，无法准确匹配热处理工艺要求。

## 怎么确认配好了
- 上传一份标准热处理工艺卡与对应炉温曲线，发起「确认本次炉次的加热保温制度」的查询，检查返回结果是否完整引用了文档中的关键参数。
- 查看FastGPT应用的模型调用日志，确认调用的API端点与配置的`AIPROXY_API_ENDPOINT`完全一致。
- 上传一张金相显微照片，发起「描述该试样的金相组织类型」的查询，检查模型是否能准确识别图像中的组织特征。
- 调整`temperature`取值为0.2，发起三次相同的工艺问答查询，检查返回结果的一致性是否符合预期。
