# 焊接结构件制造的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自设计图纸、材料质保书、焊接设备参数、焊材库、无损检测系统及人员资质台账。日常生成焊接工艺评定、焊接工艺规程、焊材领用记录、焊工资格记录、焊缝检验报告、返修单等文档。数据更新以每条焊缝、每批物料或每班操作为节点，单条文档多包含焊接参数、资质编号、检验结果等结构化字段与对应数值单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据更新频率高且粒度细，要求索引支持高频增量更新，避免全量重建占用过多系统资源。多类业务文档混合存储，需按文档类型设置分类索引规则，避免不同业务场景的向量特征混淆，影响检索精准度。文档包含焊接参数、资质编号等结构化字段，需确保向量模型能捕捉数值与文本的关联特征，避免出现无关匹配结果。返修单与检验报告关联度高，需支持跨文档关联检索，确保工艺问题能联动对应整改与检验记录。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置逻辑，具体配置项及建议如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 焊接工艺规程等文档多包含连续工艺步骤描述，该长度可完整覆盖单段焊接流程，避免语义割裂 |
| 重叠长度 | 50–80 字符 | 弥补长文本分块后的语义断层，确保焊缝检验报告的前后关联内容能被完整检索 |
| 相似度阈值 | 按实测标定 | 需匹配焊工资质、焊接参数等精准检索需求，避免阈值过高漏检或过低引发无关匹配 |
| 单次搜索上限 | 前 8 条 | 覆盖单条焊缝关联的工艺、资质、检验等多类文档，避免结果过多干扰核心匹配 |
| `defaultToken` | 4000 | 适配焊接工艺评定等长文档的上下文承载，确保问答时能完整调用关联文档内容 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 接入本地embedding模型后界面显示索引中长时间无响应：原因是未配置模型的本地调用端口与权限，导致向量生成进程无法正常拉取文档数据。
- 使用embedding-2模型时出现报错：原因是未正确配置模型的OpenAPI渠道认证信息，或模型部署时未开放对应访问接口。
- 自定义索引配置后检索无结果：原因是未将索引规则与文档类型绑定，导致焊接工艺规程的内容未被匹配到对应的索引分类中。

## 怎么确认配好了
- 上传单份焊接工艺规程文档，检查向量生成日志是否显示无异常报错，确认模型调用正常。
- 发起包含焊工资质编号的检索请求，核对返回结果是否包含对应焊工资格记录文档。
- 提交批量返修单数据，检查索引更新进度是否按预设频率完成，无全量重建触发。
- 调整相似度阈值后发起检索，观察返回结果的匹配精度变化，确认阈值配置生效。
