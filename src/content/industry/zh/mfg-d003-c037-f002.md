# 生产计划与车间排程的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据通常来自制造企业PMC、计划、车间调度与物控部门，日常覆盖销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单等文档。数据来源包含ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品及供应商到货信息，更新节奏为每日、每周，或随订单、异常情况触发更新。数据字段包含订单编号、物料编码、产能数值、排产时段、交期等，无统一固定单位，随不同文档类型调整。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据分散多源且更新节奏不均，要求向量索引支持增量同步与按需重建的灵活配置。文档类型多样且字段差异明显，需适配不同文档结构的分块规则，避免破坏业务关联逻辑。数据关联度高，如订单对应工单、排程绑定产能信息，向量检索需保留字段关联关系，防止检索结果脱离业务上下文。同时数据量随订单与异常情况波动，需适配动态调整的索引存储阈值，应对突发读写压力。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配工单、排产表等文档的段落长度，保留业务语义完整性 |
| 重叠长度 | 100–200 字符 | 避免分块破坏跨段落的业务关联，如订单与对应工序的关联 |
| 相似度阈值 | 0.72–0.85 | 过滤低关联结果，适配生产计划类数据的严谨性要求，按实测标定 |
| 单次召回上限 | 前10条 | 控制检索结果规模，避免超出上下文长度限制 |
| `maxToken` | 8000 token | 适配生产计划文档的总长度，保证关联信息完整纳入上下文 |
| `defaultToken` | 1024 token | 适配基础语义向量生成的默认长度，保证基础业务字段的向量完整性 |
| 最大上下文长度 | 4000–6000 字符 | 平衡检索结果丰富度与模型处理能力 |

## 容易做错的三处
- 升级新版本后执行向量库迁移失败，提示无法识别旧版索引格式。原因是未按照新版本的增量同步规则迁移存量数据，直接全量替换导致格式不兼容。
- 尝试重建所有知识库索引时，服务器读写资源被耗尽。原因是未设置分批次重建的阈值，全量索引任务同时占用大量内存与磁盘IO，超出服务器承载上限。
- 调用接口创建索引后返回400状态码且无响应体。原因是未正确配置索引关联的向量模型参数，导致请求体格式不符合接口要求。

## 怎么确认配好了
- 查看向量索引的分块日志，确认分块长度与重叠长度符合预设配置，无异常截断的业务字段。
- 执行一次测试检索，核对召回结果的数量与相似度匹配度，调整阈值至符合业务严谨性要求。
- 检查索引更新任务的触发规则，确认可按订单、异常情况等场景触发增量更新，全量更新仅在必要时执行。
- 查看服务器资源监控面板，确认索引任务执行时的内存与磁盘IO占用处于合理区间。
