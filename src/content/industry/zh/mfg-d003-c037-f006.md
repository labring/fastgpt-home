# 生产计划与车间排程的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
典型服务于制造企业PMC、计划、车间调度和物控部门，数据来源包含ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。日常处理的文档包括销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单。数据更新频率为每日、每周，或随订单、异常情况实时更新，字段包含订单号、工序号、设备编号、产能单位等，需按关联关系匹配引用。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源且高频更新的数据要求溯源必须关联准确的文档版本，避免使用过期的排程参数。复杂的关联文档结构（如工单关联多道工序的工艺规程）要求溯源需精准匹配文档间的关联关系，不能仅依赖关键词匹配。单任务涉及多份文档的特性要求溯源需限制返回条数，避免信息过载影响车间调度人员的判断。数据异常直接导致交期延误或在制品堆积的特性，要求溯源必须保留可核对的原始数据路径，支撑排程结果的验证。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 900–1100 字符 | 适配生产计划与排程类文档的单段有效内容长度，避免截断工单编号、产能参数等核心信息 |
| `responseData` | 启用 | 保留关联文档的字段信息，支撑排程环节的交叉校验与溯源核对 |
| `detail` | 开启 | 展示引用文档的更新时间与完整来源路径，适配高频更新的生产数据场景 |
| 单次搜索上限 | 前6条 | 覆盖单排程任务涉及的多工序工艺规程与关联文档 |
| 引用展示位置 | 对话末尾 | 符合车间调度人员的阅读习惯，便于快速核对数据来源 |
*本配置基于FastGPT v4.17.0版本*

## 容易做错的三处
- 对话末尾未展示任何引用来源，原因是误将`responseData`配置项关闭，未开启溯源数据返回。
- 引用内容截断了工单编号、设备产能等核心排程参数，原因是`quoteMaxToken`取值低于生产计划文档的单段有效长度。
- 溯源展示的文档为一周前的旧版本，原因是未设置按最新更新时间筛选引用源，导致调用过期数据。

## 怎么确认配好了
- 发起包含具体工单编号的工艺规程问答，检查回复末尾是否展示对应文档的来源路径与更新时间。
- 提交包含多工序排程的测试问题，核对引用内容未出现关键参数截断，确认`quoteMaxToken`取值适配文档长度。
- 模拟插入异常订单的场景，检查溯源是否关联最新的交期变更单或缺料清单数据。
- 查看FastGPT v4.17.0版本的模块配置面板，确认`responseData`与`detail`均处于启用状态。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
