# 生产计划与车间排程的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
该品类的日常业务文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单。数据来源涵盖ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。更新节奏分为每日、每周，或随订单、异常情况触发更新。文档字段包含订单号、物料编码、工序工时、设备编号、班次数量等，单位涉及小时、件、日期等。本文基于FastGPT v4.17.0版本编写。

## 这些特征在「模型接入与配置」这一环带来什么约束
品类数据来源分散且更新频率不固定，要求模型接入配置支持动态同步多源业务数据；文档结构多样且包含专业字段，需要在配置中明确字段映射规则以确保问答的准确性；排程任务涉及多维度资源约束，单轮问答需覆盖较多上下文信息，对模型的上下文窗口与token限制提出要求；异常情况触发的数据更新，要求配置具备快速响应的调用机制，避免延误排程调整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 品类数据包含多份工单、排程表等文档，单轮工艺问答需覆盖至少3份完整业务文档以支撑准确判断 |
| `maxTokens` | `1500–2000 token` | 工艺规程与技术标准问答需输出详细的排程调整建议，避免截断关键参数与操作步骤 |
| `quoteMaxToken` | `3000–4000 token` | 需引用BOM、工艺路线等长文档片段作为问答依据，确保引用内容完整 |
| `temperature` | `0.1–0.3` | 工艺标准问答需严格匹配既定规程，避免生成偏离标准的内容 |
| `AIPROXY_API_ENDPOINT` | 按所接入模型的官方端点填写 | 确保模型调用请求的路由路径正确，避免请求无法送达目标模型 |
| `AIPROXY_API_TOKEN` | 填写对应模型的授权密钥 | 完成模型接入的身份验证，确保调用权限有效 |

## 容易做错的三处
- 现象：在第三方渠道配置的模型，在FastGPT的问答模块模型选择下拉框中无法显示。原因：未在FastGPT的模型接入配置中完成对应渠道的绑定，或未勾选生产计划与车间排程品类的业务权限。
- 现象：问答返回结果被截断，缺失关键的排程参数或工艺步骤。原因：`maxTokens`取值过小，未适配工艺规程与排程数据的整体长度要求。
- 现象：调用模型时提示渠道不存在或认证失败。原因：`AIPROXY_API_TOKEN`配置错误，或未完成目标模型的渠道权限开通流程。

## 怎么确认配好了
- 在FastGPT的模型管理页面，查看已接入模型的状态是否显示为正常可用。
- 导入一份真实的周日排产表作为上下文，发起包含物料需求查询的测试问答，检查返回结果是否能准确提取对应字段的信息。
- 调整`temperature`参数至0.2后发起测试，确认返回结果的严谨性符合工艺标准的要求。
- 触发一次模拟的订单变更请求，检查模型是否能正常加载更新后的业务数据并完成问答。
