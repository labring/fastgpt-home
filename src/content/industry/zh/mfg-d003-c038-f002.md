# 生物制品与无菌生产的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
该品类的日常文档包含细胞库或种子批记录、培养纯化记录、无菌灌装记录、环境监测数据、培养基模拟灌装结果、无菌检验报告、批放行资料等。数据来源涵盖细胞库与种子批、过程分析系统、洁净区监测系统、MES、LIMS、设备完整性测试结果。数据更新按每批生产、实时监测、固定监测计划执行，单份文档包含批次号、操作时间、工艺参数、检验结果、合规状态等字段，参数通常带有明确单位，如培养温度37℃、pH值7.2。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据更新频率高且与生产批次强绑定，要求索引支持增量更新以适配实时或按批的同步需求。文档包含大量专业工艺参数与合规性描述，分块时需保留参数与关联说明的完整性，避免拆分关键信息。数据的合规性要求极高，召回结果需精准匹配目标批次与工艺环节，不能引入无关批次的文档内容。同时，单份文档的专业字段较多，索引需支持元数据关联以快速过滤非目标数据。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 该品类文档包含专业参数与长句说明，该长度可保留参数与关联约束的完整性，避免拆分关键工艺逻辑 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的专业术语与上下文关联，防止跨分块的参数关联丢失 |
| 相似度阈值 | 0.75–0.85 | 需精准召回无菌控制、工艺参数相关内容，避免引入无关批次或非目标环节的文档 |
| 单次搜索上限 | 前3条 | 工艺规程的关键步骤与参数集中在少量文档中，过多召回会引入冗余信息 |
| `maxToken` | 4000 token | 适配主流大模型的上下文窗口，避免截断包含多组工艺参数的完整检索结果 |
| `defaultToken` | 按实测标定 | 不同embedding模型的token处理逻辑存在差异，需根据实际部署的模型调整取值 |

## 容易做错的三处
- 文件上传后长期处于“索引中”状态，无明确报错日志。原因是未正确配置embedding模型的部署地址或调用权限，导致索引任务无法完成。
- 检索结果返回多个不相关生产批次的工艺规程内容。原因是未在索引阶段绑定批次元数据字段，导致召回时未过滤非目标批次的文档。
- 检索到的工艺参数不完整，缺失关联的操作条件或单位。原因是分块长度设置过小，拆分了包含参数、单位和约束条件的完整文本块。

## 怎么确认配好了
- 查看FastGPT v4.17.0后台的索引任务日志，确认embedding模型调用成功，无超时或报错信息。
- 上传一份测试用的无菌灌装记录文档，检索“培养基模拟灌装合格标准”，确认召回结果包含对应的文档片段。
- 检查索引后的文档元数据，确认批次号、操作时间等字段已正确关联至检索结果。
- 调整相似度阈值，验证召回结果的数量符合业务场景的筛选需求。
