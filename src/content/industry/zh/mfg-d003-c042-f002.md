# 石油炼制的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
石油炼制场景的工艺规程与技术标准数据，主体来自生产运行、工艺、调度、设备与化验部门。日常文档包含操作规程、生产方案、物料平衡、馏出口质量报告、联锁台账、交接班记录、变更管理文件。数据来源覆盖DCS/APC、LIMS、罐区计量、原油评价、设备管理系统、能源系统，更新节奏涵盖实时、每班、每日。文档结构差异明显，操作规程含装置编号、操作步骤、联锁参数等字段，交接班记录记录当班参数与异常情况，馏出口质量报告标注产品密度、硫含量等带单位的检测指标。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引需支持混合格式的文本与结构化数据嵌入，区分实时DCS数据流与静态规程文档的存储策略。结构化数据如DCS的实时参数需要单独提取字段嵌入，与纯文本规程的分块策略区分。不同更新频率需要索引支持增量刷新，适配每班、每日的批量更新与实时的参数变更同步，避免全量重建索引带来的性能损耗。文档长度跨度大，既有数百字符的联锁台账条目，也有数千字符的长文本生产方案，需要灵活适配分块逻辑，兼顾语义完整性与嵌入效率。带单位的工艺参数字段要求嵌入时保留文本语义完整性，避免因单位缺失导致匹配偏差。多装置耦合的业务特性决定了单次召回需覆盖多源信息，需控制索引返回结果的数量与上下文长度，避免超出模型处理上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配炼油规程的单装置单步骤操作说明与配套参数文本，避免将跨装置的工艺逻辑拆分到不同块中 |
| 重叠长度 | 100–150 字符 | 保留跨块的工艺参数关联，比如联锁值的前后说明，避免关键参数被分割在两个块内 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非工艺相关文档，避免干扰调度决策与工艺分析 |
| 单次搜索上限 | 前 8 条 | 匹配炼油多装置耦合的多源信息需求，控制上下文长度符合模型处理要求 |
| maxToken | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| defaultToken | 1024 | 统一单块的向量生成token数，保证嵌入向量的一致性与检索效率 |

## 容易做错的三处
- 现象：知识库磁盘占用远超预期，界面显示的原文件大小与实际占用差距较大。原因：未区分原文件、分割块与嵌入向量的存储路径，未开启向量数据的自动清理策略。
- 现象：搜索结果返回大量无关的交接班记录，返回条数远超预设的单次搜索上限。原因：未正确配置单次搜索上限参数，或未启用相似度阈值过滤，导致低相关性的短文本条目被优先召回。
- 现象：调用索引模型时返回连接失败提示，无法选择指定的嵌入模型作为索引渠道。原因：未在AIProxy中配置对应向量模型的渠道参数，未完成FastGPT v4.17.0的模型渠道绑定。

## 怎么确认配好了
- 查看知识库存储路径的磁盘占用统计，确认包含原文件、分割块与嵌入向量三类数据。
- 发起一条工艺相关查询，核对返回结果的相似度分值是否落在预设阈值区间内。
- 检查AIProxy的配置日志，确认索引模型渠道已正常连接且无报错。
- 导入一份新的联锁台账文档，确认索引自动完成更新且无异常报错。
- 核对单次搜索返回的结果条数，确认与预设的单次搜索上限一致。
