# 石油炼制的工艺规程与技术标准问答：引用来源与溯源

本页面适配 FastGPT v4.17.0。

## 这个品类的数据长什么样
该品类数据覆盖炼油企业生产运行、工艺、调度、设备与化验部门的日常文档，包括操作规程、生产方案、物料平衡表、馏出口质量报告、联锁台账、交接班记录与变更管理文件。数据来源包含DCS/APC系统、LIMS实验室管理系统、罐区计量系统、原油评价报告、设备管理系统与能源管理系统，更新节奏覆盖实时、每班与每日。文档字段包含带明确单位的工艺参数，如馏程的摄氏度、物料量的吨，以及联锁触发的时间戳等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源异构的数据结构，要求溯源环节需区分结构化系统导出字段与非结构化文档段落的不同溯源路径，避免混淆不同来源的信息。实时、每班、每日的更新频率，要求溯源关联的知识库需支持增量同步与版本标记，确保引用的内容为最新有效版本。多套连续装置通过物流与能源网络耦合的业务特点，要求溯源时需关联跨装置的关联文档，保障问答内容的上下文完整。带明确单位的工艺字段，要求溯源时需保留原始单位信息，避免单位转换导致的信息偏差。

## 配置怎么定
需配置`quoteMaxToken`、`responseData`、`detail`三个核心参数，结合中文界面设置项完成整体配置，具体如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配炼油工艺文档的段落结构，保留完整工艺步骤 |
| 重叠长度 | 150–200 字符 | 避免跨分块的工艺逻辑被截断，保障溯源连贯性 |
| 单次召回上限 | 前 6–10 条 | 覆盖多装置耦合的关联文档范围 |
| `quoteMaxToken` | 1200–1800 token | 适配炼油工艺规程的长文本溯源需求 |
| `responseData` | 开启 | 保留原始文档的结构化字段与单位信息 |
| `detail` | 完整 | 输出溯源文档的完整路径与更新时间 |

## 容易做错的三处
- 现象：调用时弹出红色数字串的报错弹窗，原因：未正确配置溯源绑定的知识库路径，导致系统无法匹配原始文档的存储节点。
- 现象：问答输出未附带任何溯源来源信息，原因：未开启`detail`参数的完整展示，或配置的分块长度过小导致溯源段落无法被完整召回。
- 现象：关联多个炼油工艺知识库后出现加载失败，原因：未根据企业文档总量调整单次召回上限，或未设置合理的知识库总字数阈值。

## 怎么确认配好了
- 发起一条关于某装置操作规程的问答，检查输出结果是否附带原始文档的名称与具体段落位置。
- 查看知识库管理页面，确认已配置的溯源绑定路径与实际存储路径一致。
- 触发问答后，检查系统日志是否包含溯源文档的版本与更新时间信息。
- 调整单次召回上限后，测试加载多套装置的知识库是否正常加载。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
