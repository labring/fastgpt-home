# 纸浆造纸的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
通常，纸浆造纸细分场景的数据来自备料、制浆、抄纸、质量与能源部门，涵盖配浆单、打浆记录、纸机运行记录、在线质量曲线、实验室报告、断纸与换品记录等文档。数据来源包括木浆废纸批次台账、DCS/QCS系统、纸机在线测量设备、实验室检测系统、能源和水处理系统。更新节奏覆盖实时、每班、每卷三个层级，单份文档包含浆料配比、打浆度、克重、水分等带明确单位的字段，部分在线质量曲线为时序数值格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于数据更新频率覆盖实时到每卷级别的差异，索引任务需要适配不同的调度策略，避免实时数据处理阻塞批量任务。在线质量曲线、断纸记录等时序类文档的结构与常规文本不同，分块时需保留关键参数的完整性，防止跨块拆分导致检索信息断裂。多部门的跨系统数据会产生大量重复或关联条目，索引时需要统一文档唯一标识规则，避免重复检索结果。同时，单卷生产数据的体量较大，需控制单批次索引的资源占用，保证检索响应速度符合工艺问答的实时性需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配配浆单、打浆记录等单页文本的字段长度，避免跨浆料配比、打浆度等关键参数分块 |
| 重叠长度 | 100–150 字符 | 覆盖打浆参数、纸机运行参数的跨块关联，防止关键时序信息断裂 |
| 相似度阈值 | 0.72–0.85 | 适配在线质量曲线的数值匹配精度，避免误召回无关批次的生产数据 |
| 单次搜索上限 | 前 8 条 | 匹配每班/每卷的记录数量，保证检索结果覆盖完整生产批次的关联信息 |
| defaultToken | 4096 | 适配实验室报告的长文本内容，满足单块最大token限制，避免长文档截断 |
| maxToken | 8192 | 适配多块拼接后的上下文长度，支持完整抄纸流程的检索结果整合 |

## 容易做错的三处
- 配置多个索引关联同一文档块后，检索结果出现重复条目。原因是未开启重复结果去重开关，或索引时未按文档唯一标识进行去重处理。
- 单卷纸机运行记录的索引耗时超过600秒。原因是分块长度设置过大，且未开启异步索引任务队列，导致实时数据处理阻塞批量索引任务。
- 误将开源版本的`阿里-emb3`模型与商用版本混淆。原因是未确认模型开源仓库的标注信息，直接使用非授权的模型参数进行配置。

## 怎么确认配好了
- 上传单份配浆单文档，检查分块后的文本是否完整保留浆料配比、打浆度等关键字段，无截断或跨块断裂的情况。
- 发起包含“当前打浆参数”的测试查询，核对返回结果的相似度得分是否符合预设区间，且无无关的断纸或换品记录。
- 模拟实时上传一条新的纸机运行记录，检查索引状态是否在合理时间内变为完成，无长期pending的状态。
- 查看FastGPT v4.17.0的模型配置面板，确认`阿里-emb3`模型的开源版本参数已正确加载，无缺失的模型文件引用。
