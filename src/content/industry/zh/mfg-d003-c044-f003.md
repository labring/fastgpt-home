# 纸浆造纸的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
纸浆造纸的工艺相关数据通常来自木浆废纸批次台账、DCS/QCS控制系统、纸机在线测量设备、实验室检测系统、能源与水处理系统。日常留存的文档包括配浆单、打浆操作记录、纸机运行日志、在线质量曲线、实验室质检报告、断纸与换品台账。数据更新节奏涵盖实时、每班、每卷，单条记录包含浆料配比、打浆度、克重、水分、幅宽等字段，对应不同的计量单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
纸浆造纸的多轮对话与提示词配置需要适配数据的多来源、多更新节奏与文档特征。实时类数据要求对话能快速关联最新批次的参数，避免使用过期数据；多更新频率意味着对话需区分实时、每班、每卷的文档维度，不能混淆不同周期的记录。单卷纸的长时序质量数据会占用较多上下文空间，需支持文档切片与上下文截断；多文档场景下需精准指定召回目标文档的批次或卷号，避免召回无关的实验室报告或其他卷的运行记录。多轮追问需绑定对话上下文，确保后续问题能关联前序提及的浆料批次、纸机参数等信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配单条打浆记录、在线质量曲线的常规长度，避免单块内容过于分散 |
| 重叠长度 | 100–200 字符 | 保留跨分块的关键参数（如批次号、打浆度），防止分块截断关键信息 |
| 最大上下文长度 | 4000–8000 token | 适配多轮对话的历史追问与多文档召回的总内容量，适配FastGPT v4.17.0的常规上下文上限 |
| 单次召回文档数 | 前 5 条 | 平衡召回精度与响应速度，覆盖单轮工艺问答所需的核心文档 |
| 对话上下文绑定 | 启用`chatId`参数 | 确保多轮对话的历史消息存储在同一会话下，避免跨会话混淆上下文 |
| 提示词变量配置 | 传入`variables`参数，指定目标批次号、卷号 | 精准定位需召回的特定文档，避免召回无关内容 |

## 容易做错的三处
- 上传长文档后触发上下文溢出报错，返回空结果或截断内容。原因是未配置分块与重叠长度参数，未对长时序在线质量曲线进行合理切片。
- 多轮追问出现答非所问，第二个问题开始脱离前序提及的浆料批次或纸机参数。原因是未启用`chatId`绑定对话上下文，或对话历史保留条数设置过低。
- 指定召回特定文档失败，召回结果包含无关的实验室报告或其他卷的运行记录。原因是未通过提示词或`variables`参数传入目标批次号、卷号等定位字段。

## 怎么确认配好了
- 上传单条长在线质量曲线文档，发起多轮追问，验证回答是否关联前一轮提及的批次号与实时测量参数。
- 上传多个配浆单文档，通过提示词传入目标木浆批次号，验证召回结果仅包含对应批次的配浆单内容。
- 发起连续3轮以上的工艺问题，验证`messages`字段包含完整的历史对话内容，无关键参数截断。
- 查看对话日志，确认`chatId`参数在多轮对话中保持一致，未出现会话切换导致的上下文丢失。
