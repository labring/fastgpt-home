# 纸浆造纸的工艺规程与技术标准问答：文档解析与分块

## 这个品类的数据长什么样
纸浆造纸场景的核心数据来自木浆废纸批次、DCS/QCS系统、纸机在线测量设备、实验室检测、能源与水处理系统。日常文档包含配浆单、打浆记录、纸机运行记录、在线质量曲线、实验室报告、断纸与换品记录。数据更新节奏涵盖实时、每班、每卷，文档字段包含打浆浓度、纸机车速、克重、水分等，附带专用单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
实时、每班、每卷的更新节奏要求分块不能过大，避免召回滞后于工艺调整需求。配浆单、打浆记录等单行单条的文档格式，需要精准识别换行作为分块边界，防止多行数据合并为单个分块。在线质量曲线、实验室报告中的结构化表格数据，需要保留字段与单位的关联关系，否则无法支撑工艺问答的精准匹配。高速连续生产的工艺记录具有强连贯性，分块不能打断打浆、抄纸等完整工序步骤。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 匹配单条工艺记录的长度，避免拆分打浆、抄纸等连续工序的完整步骤 |
| `chunkSplitter` | 按换行+段落分隔 | 适配配浆单、打浆记录的单行单条格式，解决Excel导入时多行数据合并问题 |
| `customPdfParse` | 启用表格结构化解析 | 准确提取在线质量曲线、实验室报告中的数值与关联单位 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 适配大体积纸机运行日志文件的解析耗时，避免超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配单卷纸机运行日志的最大文件体积 |
| `chunkSettingMode` | 手动配置 | 针对记录类、报告类等不同文档类型，灵活调整分块参数 |

## 容易做错的三处
- Excel导入的配浆单被合并为单个chunk：现象是上传的Excel配浆单每行一条记录被自动合并为一个分块，原因是未将`chunkSplitter`配置为按换行分隔，默认分块逻辑未识别单行数据边界。
- 相同匹配内容无法召回：现象是特定知识库中与问题完全一致的分块未被检索到，新建相同配置的知识库后恢复正常，原因是首次导入时未启用`customPdfParse`，导致文档解析不完整，分块丢失关键匹配字段。
- 多PDF上传后无法逐一提取：现象是批量上传的纸机运行记录PDF无法按单卷文档拆分提取信息，原因是未配置`chunkSplitter`按文档元数据分隔，默认按全局内容统一拆分。

## 怎么确认配好了
- 上传单条配浆单Excel文件，检查分块结果是否为每行一条独立记录，核对`chunkSplitter`配置是否生效。
- 上传包含在线质量曲线的PDF报告，查看解析后的分块是否保留了克重、水分等字段的完整数值与对应单位。
- 上传单份纸机运行日志文件，确认解析耗时未超过`PARSE_FILE_TIMEOUT_SECONDS`设置的120秒，无超时报错。
- 导入与工艺问题匹配的分块内容，发起相同问题的召回测试，确认分块被正确检索到。
