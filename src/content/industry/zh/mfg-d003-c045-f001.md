# 纺纱与织造的工艺规程与技术标准问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
纺纱与织造品类的日常数据通常来自原纤维检验、ERP系统、纺机与织机运行数据、条干仪、验布机等设备。数据更新节奏随生产批次、班次、匹布变动，每批原料、每班生产、每匹布产出时都会生成新的文档与记录。常见文档包括配棉或配料单、工艺上机单、设备运转记录、纱线检验单、坯布检验单、布面疵点记录，字段包含纤维细度（单位dtex）、纺纱捻度（单位捻/米）、布面疵点等级、订单门幅、纱支规格等专属参数。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
该品类的数据具有批次化、高频更新、字段带专属单位的特征，对HTTP接口提出多重约束。首先，多批次高频的生产数据要求接口支持分页拉取或批量同步，避免单次请求数据量过大导致阻塞。其次，字段包含专属单位与工艺参数，接口需要支持传递精准的过滤参数，确保召回的工艺规程与技术标准匹配当前生产批次的需求。此外，实时性较强的疵点记录与设备运转数据，要求接口设置合理的超时阈值，避免因等待响应导致生产数据丢失。同时，多用户同时调用接口的场景，需要支持用户标识的传递，实现聊天上下文的隔离。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 携带`Bearer `前缀的FastGPT API密钥 | 符合FastGPT v4.17.0的鉴权规范，匹配业务系统的密钥分发规则 |
| `variables` | 传入`{"materialType":"棉纺","batchNo":"B20240501"}`格式的参数 | 用于过滤纺纱批次的专属工艺数据，缩小召回范围，适配配棉与工艺上机的场景 |
| `responseData` | 仅返回`processParam,defectRecord,inspectResult`字段 | 减少无效数据传输，适配业务系统的字段映射需求，避免冗余数据占用带宽 |
| 单次请求数据条数 | 前100条 | 匹配每匹布的检验数据量，避免接口过载导致超时 |
| 超时时间 | 30–60秒 | 适配设备数据采集的延迟，避免长时间等待响应体返回 |
| 用户会话标识 | 按业务系统的user_id传递 | 区分不同用户的聊天上下文，匹配多租户业务需求 |

## 容易做错的三处
- 调用接口后长时间等待响应体返回，状态码显示200但无有效内容。原因是未设置合理的超时时间，且未对批量生产数据做分页处理，导致接口在拉取多批次工艺数据时阻塞。
- 使用`Authorization`参数时未添加`Bearer `前缀，或密钥格式错误，触发鉴权失败报错。原因是未遵循FastGPT的鉴权规范，混淆了不同场景的密钥传递规则。
- 未传递`variables`参数过滤数据，导致返回的工艺规程包含其他批次的无关内容，无法匹配当前纺纱批次的生产需求。原因是未结合纺纱织造的批次化生产特征配置参数，扩大了召回范围。

## 怎么确认配好了
- 调用接口后检查`responseData`返回的字段是否仅包含预设的工艺参数、疵点记录、检验结果内容，无多余字段。
- 传入不同的`variables`参数，验证返回的工艺数据是否匹配传入的原料类型、批次号等过滤条件。
- 模拟多用户传入不同的user_id，检查聊天上下文是否按用户隔离，无跨用户数据混淆的情况。
- 连续调用接口10次，确认响应时间稳定在设定的超时范围内，无长时间阻塞的情况。
