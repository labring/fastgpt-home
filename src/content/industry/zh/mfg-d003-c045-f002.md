# 纺纱与织造的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
这个品类的日常文档包括配棉或配料单、工艺上机单、设备运转记录、纱线检验、坯布检验、疵点记录。数据来源覆盖原纤维检验、ERP系统、纺机与织机实时数据、条干仪、验布机采集数据及订单规格文件。数据更新节奏随生产批次、班组班次和布匹匹数变动，每批原料、每班、每匹布均会产生新的业务数据。文档字段多包含纤维指标、工艺参数、疵点类型等，部分参数带有专属行业单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据更新频率高且分散，每批原料、每班、每匹布均有新数据，要求索引支持高频增量更新，避免全量重建耗时过长。日常文档类型多样且格式差异大，配棉单的纤维指标与疵点记录的缺陷描述格式不同，需适配多类型文本的分块与向量化。设备采集的实时数据与ERP的静态订单数据并存，需兼顾结构化字段与非结构化文本的索引适配。同时，疵点记录与对应工艺参数的关联度高，索引需支持跨文档关联检索，确保问答时能匹配到完整的业务链路数据。

## 配置怎么定
本页配置基于 FastGPT v4.17.0 版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配工艺单、检验记录的常规文本长度，避免单块包含过多不相关参数 |
| 重叠长度 | 100–150 字符 | 覆盖跨块的工艺参数关联，确保疵点记录与对应上机单的检索连贯性 |
| `defaultToken` | 2000 token | 匹配单批配棉单的核心字段长度，保障基础问答的上下文完整性 |
| `maxToken` | 8000 token | 适配多文档拼接的检索结果，覆盖工艺参数、检验数据的完整关联信息 |
| 相似度阈值 | 0.75–0.85 | 区分工艺参数与疵点描述的匹配精度，避免无关结果混入检索列表 |
| 单次搜索上限 | 前 8 条 | 平衡检索效率与结果完整性，适配该品类多文档关联的检索需求 |

## 容易做错的三处
- 现象：混合检索请求耗时超过10秒，远高于纯向量检索的8秒左右耗时。原因：该品类索引包含多类型业务文档且关联度强，混合检索需同时调用多个索引分支，拉长了检索链路。
- 现象：系统卡在最后一组索引的建索引步骤，无法完成知识库初始化。原因：未启用增量更新模式，全量遍历每批原料、每班产生的海量小文件数据，导致建索引任务阻塞。
- 现象：部分配棉单、疵点记录无法被正确向量化，检索结果为空。原因：分块参数设置不合理，短文本文档被拆分过碎或合并过长，导致向量化特征丢失。

## 怎么确认配好了
- 上传1份典型的工艺上机单与对应疵点记录，执行检索测试，核对返回结果是否包含匹配的工艺参数与疵点描述。
- 模拟高频增量上传新的配棉数据，观察建索引任务的完成速度，确认无阻塞情况。
- 调整相似度阈值，验证检索结果的匹配精度是否符合业务需求，确认阈值设定合理。
- 测试混合检索与纯向量检索的耗时差异，确认混合检索耗时未超出业务可接受范围。
