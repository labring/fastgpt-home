# 纺纱与织造的工艺规程与技术标准问答：工具调用与插件

## 这个品类的数据长什么样
该品类数据来自棉纺、化纤纺、机织和针织企业的日常生产文档与设备采集数据，日常文档包含配棉或配料单、工艺上机单、设备运转记录、纱线与坯布检验记录、疵点记录。数据来源涵盖原纤维检验报告、ERP系统、纺机与织机实时数据、条干仪、验布机检测结果、订单规格要求。数据更新频率随生产批次、班次、布匹匹次变动，单篇文档多包含纤维类型、工艺参数、检验数值、匹号等字段，部分字段带有明确的物理单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据更新随生产批次、班次、布匹匹次变动，工具调用需适配实时性要求较高的数据源拉取逻辑，避免使用过长的缓存周期。多源数据的字段差异要求工具调用配置需支持跨系统字段映射，确保不同来源的工艺参数、检验数据能被统一识别。单篇文档的工艺参数与检验记录长度适中，但批量数据量较大，工具调用需限制单次拉取的文档数量，避免超出上下文承载上限。此外，疵点记录与布匹匹号强绑定，工具调用需支持按匹号精准关联对应检验数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | `auto` | 适配工艺参数查询、疵点分析两类不同场景的工具调用需求 |
| 工作流/API 函数调用配置 | `enabled` | 支持调用外部设备数据接口与自定义模型API |
| 单次搜索上限 | `前6条` | 纺纱织造工艺文档单篇长度适中，过多结果会超出上下文窗口 |
| 最大上下文 | `8000–12000 token` | 可容纳多批次配棉、上机参数与检验记录的完整内容 |
| 工具调用超时 | `300 秒` | 适配设备数据接口的采集与返回周期 |
| 知识库匹配阈值 | `按实测标定` | 匹配工艺参数与检验记录的精准度需结合生产场景调整 |

## 容易做错的三处
- 启动项目时返回`400 <400> InternalError.Algo.InvalidParameter: messages with role`报错，Mongo可视化工具可正常连接。原因是工具调用配置中未正确格式化角色参数，导致模型无法识别传入的上下文角色。
- 将HTTP返回的设备数据作为知识库分析时结果偏差较大。原因是未通过工具调用配置映射HTTP返回的字段与纺纱织造工艺文档的标准字段，导致参数匹配错误。
- 调用不在模型列表中的API时无响应。原因是未正确配置`toolChoice`为自定义调用模式，未补充对应模型的接口参数与验证信息。

## 怎么确认配好了
- 发起单批次配棉参数查询，检查工具调用是否返回对应批次的纤维指标与混配记录。
- 触发指定匹号的疵点分析任务，确认工具调用是否能拉取对应验布机的检测数据。
- 测试调用自定义模型API，检查是否能正常返回工艺参数的分析结果。
- 查看FastGPT v4.17.0的工具调用日志，确认超时时间与上下文配置符合设定值。
