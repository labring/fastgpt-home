# 纺纱与织造的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
该品类主体为棉纺、化纤纺、机织和针织企业，日常生产文档包含配棉或配料单、工艺上机单、设备运转记录、纱线检验、坯布检验、疵点记录等。数据来源覆盖原纤维检验、ERP系统、纺机与织机实时数据、条干仪、验布机检测结果以及订单规格要求。数据更新随每批原料进厂、每班生产推进、每匹布产出完成同步触发，文档字段包含原料指标、工艺参数、检验结果与设备运行数据，无统一固定格式，随具体生产环节有所调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据来源分散且更新频率高，引用溯源需同时关联多系统、多设备的实时与历史数据，对召回的精准度要求较高。单批次生产关联的文档数量较多，需限定召回范围以避免冗余信息干扰。文档字段多为专业工艺参数，需准确匹配字段名称与单位才能完成有效溯源。此外，疵点记录与生产环节强绑定，溯源需关联对应批次的原料、上机工艺与设备数据，无法仅通过单一文档完成完整校验，因此需支持多文档关联溯源的功能。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 8000–12000 token | 适配纺纱工艺文档的长文本结构，覆盖配料、上机、检验全流程参数 |
| 知识库最大引用 | 前6条 | 匹配单批次生产关联的配棉单、检验记录、设备数据等文档总量 |
| 最大响应tokens | 1500–2000 字符 | 确保工艺解答包含完整溯源信息与参数细节 |
| `quoteMaxToken` | 1000 字符 | 限定单条引用的展示长度，避免界面出现冗余过长的溯源内容 |
| `responseData` | 开启 | 保留完整引用元数据，用于后续溯源校验与日志排查 |
| `detail` | 开启 | 展示引用的文档来源路径与更新时间，强化溯源可信度 |

## 容易做错的三处
- 现象：引用内容中出现未转换的\n文本，无法正常换行展示。原因：未开启`detail`配置的格式解析功能，导致原始文档的换行标记未被正确转换。
- 现象：召回的引用条数超出预期，且包含不相关的历史批次数据。原因：未合理设置知识库最大引用的取值范围，未绑定生产批次的过滤条件。
- 现象：无法隐藏问答结果中的引用内容。原因：误将`responseData`配置为关闭，或未在问答插件配置中正确勾选引用隐藏选项。

## 怎么确认配好了
以下核对动作需基于FastGPT v4.17.0版本完成：
- 发起一条关于特定纱线捻度设置的工艺问答，检查返回结果中是否包含对应工艺上机单、设备运转记录的溯源信息。
- 查看引用内容的换行效果，确认无\n文本残留，格式符合文档原始排版。
- 调整知识库最大引用的取值，验证召回的引用条数是否随配置变化，符合单批次生产的文档数量范围。
- 测试开启引用隐藏功能，确认问答结果不再附带任何引用相关的内容与链接。
