# 纺纱与织造的工艺规程与技术标准问答：部署与升级

## 这个品类的数据长什么样
该品类的数据主要来自原纤维检验、ERP系统、纺机与织机运行数据、条干仪、验布机及订单规格文档。日常留存配棉或配料单、工艺上机单、设备运转记录、纱线检验表、坯布检验表、疵点记录单。数据更新随每批原料、每班生产及每匹布产出同步调整，单份文档包含纤维指标、纺纱捻度、织造组织参数、疵点类型与位置等字段，字段单位涵盖捻/米、厘米等。

## 这些特征在「部署与升级」这一环带来什么约束
该品类数据更新频率高，随每批原料、每班生产及每匹布产出同步更新，部署时需适配高频增量同步的存储配置，避免全量索引拖慢检索速度。文档类型涵盖结构化配料单、半结构化疵点记录及非结构化工艺说明，部署需兼容多格式解析适配。生产环节的参数与疵点数据强绑定生产批次，升级时需保留历史批次的关联检索逻辑，避免影响过往工艺数据的溯源查询。单批次数据量随设备头数增加而扩大，需预留合理的存储扩容空间。

## 配置怎么定
本文适配FastGPT v4.17.0版本的部署与升级流程，以下配置项需结合该品类的业务特征调整：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:port/fastgpt_spinning?authSource=admin` | 存储工艺文档、检验记录等非结构化数据，指定专属业务数据库避免与其他业务混淆 |
| `PG_URL` | `postgresql://username:password@pg-host:5432/fastgpt_spinning` | 存储系统配置、用户权限等结构化数据，使用专属PostgreSQL数据库 |
| `REDIS_URL` | `redis://:your_password@redis-host:6379/1` | 缓存高频检索的工艺参数与生产批次关联数据，数据库索引划分至1号库隔离业务缓存 |
| `DB_MAX_LINK` | `20–30 个并发连接` | 适配该品类高频数据更新与检索的并发需求，避免连接池耗尽影响生产环节查询 |
| `STORAGE_S3_ENDPOINT` | `http://local-s3-endpoint:9000` | 存储批量上传的设备运转记录、疵点照片等附件，匹配本地对象存储服务的访问地址 |
| `ROOT_KEY` | `自定义32位随机字符串` | 配置系统后台的最高权限密钥，用于初始化部署后的管理员访问 |

## 容易做错的三处
- 现象：通过docker-compose部署后修改config.json配置，前端模型列表未同步更新。原因：未重启对应服务容器，配置变更未生效。
- 现象：点击知识库模块触发报错，界面返回500状态码。原因：未正确配置`PG_URL`或`MONGODB_URI`，数据库连接失败。
- 现象：问答流程结束后无前端输出，需进入详情页才能查看完整内容。原因：未配置正确的`FE_DOMAIN`，前端无法接收后端推送的流式响应内容。

## 怎么确认配好了
- 查看服务容器的运行日志，确认数据库连接、缓存服务连接无报错。
- 上传一份工艺上机单文档，验证系统可正确提取纺纱捻度、织造组织等核心字段。
- 发起针对疵点记录的检索请求，确认结果可按生产批次进行过滤。
- 发起完整问答流程，确认前端可正常展示输出内容，无需进入详情页查看。
