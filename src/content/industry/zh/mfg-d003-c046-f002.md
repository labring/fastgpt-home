# 肉制品与屠宰加工的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
典型主体为屠宰场、熟肉与冷冻调理食品企业，日常文档包含检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告。数据来源涵盖动物检疫信息、供应商批次台账、生产追溯记录、实时温度采集数据、金属检测结果与实验室检验报告。更新按生产批次、班次执行，冷链温度记录为连续采集更新。文档多关联批次号、检疫编号等唯一标识，字段包含时间戳、数值型参数与合规性说明，无统一固定格式，随生产环节差异有所变化。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的高频更新特性要求索引支持增量更新，避免全量重建占用过多服务器资源。强关联的批次、检疫标识要求分块时保留上下文关联，防止拆分后丢失关键匹配信息。多类型文档与带单位的数值字段，要求向量模型适配混合文本与数值型内容的向量化处理。合规性相关的关键信息需高准确率召回，因此索引的过滤规则需严格匹配业务需求，无法依赖通用阈值。此外，连续采集的温控数据存在大量时序字段，需避免分块破坏时序关联，确保检索时可匹配完整的温度变化链条。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 该品类文档多为带唯一标识的结构化记录，过长分块会破坏批次关联，过短会拆分单条完整记录 |
| 重叠长度 | 100–200 字符 | 需保留批次号、检疫编号等跨分块的关键信息，确保分块后仍可匹配上下文 |
| 相似度阈值 | 0.75–0.85 | 涉及检疫、温度等合规关键信息，需严格过滤低匹配结果，避免误召回无关记录 |
| 单次搜索上限 | 前 8 条 | 兼顾召回覆盖率与响应速度，避免过多结果导致上下文溢出 |
| `maxToken` | 8000 token | 该品类合规文档多为多页记录，需保证上下文可完整承载关键批次与检验信息 |
| `defaultToken` | 1500 token | 日常工艺问答多为单条记录查询，匹配常规单文档分块的向量长度 |

## 容易做错的三处
- 现象：FastGPT更新至v4.17.0后，原索引的知识库无法返回搜索结果，界面显示「向量检索无结果」。原因：未适配新版本的向量模型输入格式，旧索引的分块token长度与当前配置不匹配。
- 现象：服务器重启后知识库卡在「未就绪」状态，无法自动完成索引。原因：未开启增量索引自动恢复配置，全量索引任务未随服务启动自动触发。
- 现象：批量上传多份生产批次记录后，系统出现超时报错，日志显示「分块处理超时」。原因：分块长度设置过大，超出单任务处理的时间阈值，导致批量上传时触发服务器负载过高。

## 怎么确认配好了
- 上传单份检疫证明文档，发起「该批次是否符合检疫要求」的查询，确认返回结果包含文档内的关键检疫信息。
- 查看知识库索引状态，确认重启FastGPT v4.17.0服务后，自动完成索引重建，无需手动触发分块与向量化操作。
- 批量上传10份连续批次的生产记录，验证系统无超时报错，且索引进度条正常推进。
- 调整相似度阈值后，验证低匹配度的无关记录不再被召回。
