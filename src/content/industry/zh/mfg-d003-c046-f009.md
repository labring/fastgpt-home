# 肉制品与屠宰加工的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自屠宰场、熟肉与冷冻调理食品企业的日常生产文档，包括检疫证明、屠宰分割记录、配料腌制记录、热加工记录、冷链温度记录与微生物检验报告。数据来源涵盖动物检疫信息、供应商批次、生产追溯系统、温度采集设备、金属检测结果与实验室检验数据。更新节奏按生产批次、班次执行，冷链温度记录为连续采集，各文档字段包含批次号、检疫编号、温度值、检验指标等，部分数据需匹配原料批次与检疫信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据包含生物安全相关的检疫信息与实时温控数据，要求模型接入时需严格限定上下文范围，避免无关数据泄露或错误关联。批次与检疫信息的强绑定需求，要求配置时需确保检索结果的批次字段匹配准确。连续采集的温控数据更新频率高，需限制单次检索的文档数量与上下文长度，避免加载过期或冗余数据。生熟分区与杀菌温度的管控需求，要求配置的模型能精准识别温度阈值与操作规范，因此需调整模型参数适配专业术语的理解精度。

## 配置怎么定
本文档适配 FastGPT v4.17.0 版本，以下配置项均基于该版本的界面与参数逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 该品类文档包含多批次关联的检疫与生产数据，需保留足够上下文确保批次与检疫信息的准确匹配，适配业务场景的信息需求 |
| `temperature` | `0.1–0.3` | 工艺规程与技术标准问答需严格匹配规范，避免生成偏离标准的内容，保障生产操作的准确性 |
| `quoteMaxToken` | `2000–3000 token` | 需保留足够的原始文档片段用于佐证检疫、温控等关键数据，确保回答的可追溯性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接入地址 | 确保模型调用的网络稳定性，适配企业内部网络与安全策略 |
| `AIPROXY_API_TOKEN` | 绑定企业专属调用密钥 | 限制未授权的模型调用，保障生产数据与业务流程的安全 |
| `toolChoice` | `auto` | 让模型自主选择是否调用检索工具获取工艺与标准数据，适配不同场景的信息获取需求 |

## 容易做错的三处
- 现象：界面显示“当前分组 default 下对于模型 gpt-4o-mini 无可用渠道”，原因：未在当前分组下配置`AIPROXY_API_TOKEN`或接入端点，导致模型调用权限未完成绑定。
- 现象：检索返回的温控数据与当前生产批次不匹配，原因：未限制`maxContext`的范围，导致旧批次的冗余数据被优先召回，干扰模型匹配逻辑。
- 现象：应用调用的结果直接作为最终输出，未作为检索资料喂给大模型，原因：未正确配置应用的调用链路，将结果输出节点与检索节点未做分离。

## 怎么确认配好了
- 执行模型调用测试，输入工艺相关的问题，检查是否能正常返回符合企业标准的内容，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置有效。
- 检索特定批次的检疫证明与生产记录，检查召回结果的批次字段是否与检索关键词匹配，确认上下文范围限制生效。
- 调整`temperature`参数并对比生成结果，确保生成内容的专业术语与企业标准一致，确认参数适配业务需求。
- 查看系统日志，确认模型调用的请求无报错，且检索返回的文档数量符合业务场景的预期。
