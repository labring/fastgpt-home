# 计量器具与实验室管理的工艺规程与技术标准问答：工作流编排

## 这个品类的数据长什么样
本品类数据来自企业计量室、CNAS体系实验室的日常业务文档，包括量具台账、校准计划、校准证书、期间核查记录、试验原始记录、标准物质台账与偏离处置文件。数据来源覆盖计量管理系统、LIMS平台、外部校准机构证书、标准器及环境监测数据，更新节奏随校准周期、单次试验完成或异常情况触发，字段包含器具唯一编号、校准有效期、测量不确定度、溯源链信息与环境参数等。

## 这些特征在「工作流编排」这一环带来什么约束
本品类数据来源分散且格式差异大，工作流编排需适配多数据源接入逻辑，避免数据抓取遗漏。更新节奏随校准周期、试验或异常触发，需配置触发式更新节点，不宜使用固定周期同步。字段包含溯源链、测量不确定度等强关联信息，工作流需保留字段间的关联关系，避免拆分后丢失上下文。异常场景下的出错后果影响质量判定，需在工作流中增加前置校验环节，确保输入数据合规。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定器具唯一编号、校准有效期、溯源链ID三类变量 | 本品类数据需关联强标识字段，确保问答匹配精准对应目标计量器具 |
| `nodeId` | 为校准证书解析节点分配固定`nodeId` | 需固定节点标识以关联历史记录与校验逻辑，避免节点变更导致数据丢失 |
| 问题分类触发规则 | 按文档类型触发分类 | 本品类包含校准证书、试验记录等多类文档，需按文档类型匹配对应分类逻辑 |
| 文本提取超时时间 | 600秒 | 校准证书与试验原始记录可能包含多页内容，预留充足的内容解析时长 |
| 单次文本提取上限 | 前10条文档 | 本品类单次查询最多涉及10份关联校准文件，避免上下文过载 |
| 上下文窗口大小 | 8000 token | 本品类的计量文档包含多段长文本，需预留充足的上下文空间以保留溯源链信息 |

## 容易做错的三处
- 新建问题分类节点时，使用初始化AI模型未做修改，运行或保存发布时弹出参数校验失败提示，节点状态显示异常。原因是初始化AI模型的默认prompt未适配计量专业术语与文档结构，导致分类逻辑无法匹配本品类的业务规则。
- 工作流文本内容提取节点的输出JSON为空，日志显示无有效匹配内容。原因是未针对校准证书、试验原始记录等结构化文档配置对应的解析规则，导致无法提取有效字段。
- 工作流全局变量的历史记录面板中，未显示指定回复组件的输出内容，仅保留用户提问。原因是未在工作流中开启全局变量的回复内容绑定逻辑，导致AI回复未被写入历史存储。

## 怎么确认配好了
以下核对动作适配FastGPT v4.17.0。
- 运行工作流，输入已知的计量器具编号，核对返回结果是否包含对应校准证书的有效期、测量不确定度与溯源链信息。
- 查看全局变量的历史记录面板，确认包含用户提问与AI回复的完整内容。
- 切换回初始化AI模型，运行问题分类节点，确认无报错且分类结果符合本品类的文档分类规则。
- 上传一份校准证书的PDF文件，触发文本提取节点，核对输出JSON包含校准日期、器具编号等核心字段。
