# 设备点检与预防维修的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
该品类数据涵盖设备台账、点检表、保养计划、维修工单、故障分析、备件清单及特种设备检验记录等文档。数据来源包括EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史档案、备件库存数据与法定检验信息。更新节奏覆盖每班、日/周/月周期及故障突发场景，字段包含设备编号、点检点位、参数阈值、维修周期、备件型号等，附带毫米、小时、次等标准单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源异构的数据来源要求溯源系统支持区分静态文档与实时传感数据的关联逻辑，避免混淆离线点检记录与在线监测参数。多样的文档类型与差异化字段，需要针对点检表、维修工单等不同文档配置专属的元数据提取规则，确保溯源信息匹配对应文档的结构。高频更新节奏要求溯源环节自动关联最新版本的文档数据，避免引用过期的保养计划或检验记录。同时，非计划停机等严重出错后果，要求溯源结果必须精准绑定原始数据条目，无法依赖模糊匹配逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配点检表、维修工单等文档的单条内容长度，避免截断关键参数 |
| 重叠长度 | 100–150 字符 | 覆盖点检点位的跨块关联信息，防止溯源时丢失上下文 |
| 单次搜索上限 | 前 5–7 条 | 匹配设备管理场景下的常用数据源数量，平衡召回精度与响应速度 |
| `quoteMaxToken` | 3000–4000 token | 预留足够的溯源文本长度，支撑复杂故障分析的完整引用 |
| `responseData` | 开启 | 直接绑定文档的元数据与内容片段，确保溯源信息完整 |
| `detail` | 开启 | 展示文档的来源路径与版本信息，符合设备管理的合规要求 |

## 容易做错的三处
- 现象：返回的溯源信息仅显示知识库分类名称，未绑定具体文档名称与内容片段位置。原因：未配置文档元数据的提取规则，未关联设备编号、文档版本等专属标识字段。
- 现象：调用工作流时传入的知识库筛选变量无法生效，返回无关的设备文档数据。原因：未将变量正确绑定到知识库搜索节点的数据源配置项，未校验变量的合法性与格式。
- 现象：溯源结果出现过期的点检表或保养计划数据，未更新至最新版本。原因：未配置数据源的版本校验逻辑，未自动过滤超过更新周期的旧文档记录。

## 怎么确认配好了
- 提交包含具体设备编号或点检点位的测试问题，核对返回结果中是否显示对应文档的名称与片段内容。
- 查看工作流节点的配置面板，确认知识库筛选变量已正确绑定到搜索范围的配置项中。
- 模拟故障突发场景，提交包含实时传感数据关键词的问题，核对溯源信息是否关联最新的维修工单或检验记录。
- 检查系统日志，确认溯源请求未出现超时、空字段或参数错误的报错信息。
