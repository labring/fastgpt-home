# 设备点检与预防维修的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据覆盖制造企业设备部、车间维修班组、公用工程部门等主体，日常文档包含设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录。数据来源包括EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史、备件库存及法定检验信息，更新节奏覆盖每班、日/周/月周期及故障发生时的即时同步，文档字段包含设备编号、点检项、故障代码、备件型号等结构化内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新节奏差异大，要求模型接入时支持多源数据同步配置，需适配不同更新频率的数据源接入规则。文档字段多为设备相关的结构化编码类内容，需配置匹配结构化数据的召回逻辑，避免非结构化文本的无效召回。故障发生时的即时数据需低延迟接入，对模型调用的响应时长有明确约束。法定检验记录需严格匹配合规性校验，需配置固定字段的验证规则。维修工单与备件清单关联紧密，需支持跨文档的关联召回配置，保证维修建议的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写本地部署大模型的API访问地址，如`http://192.168.1.100:8000/v1` | 适配本地部署模型的访问需求，满足设备点检场景的私有部署合规要求 |
| `AIPROXY_API_TOKEN` | 填写本地模型的访问密钥，无密钥时留空 | 适配不同部署模型的访问鉴权规则，满足企业内部访问的安全要求 |
| `maxContext` | 8000–12000 token | 适配设备台账、点检记录等多文档的上下文召回需求，避免超出模型上下文窗口 |
| `maxTokens` | 2000–3000 token | 匹配维修工单、故障分析等单文档的内容长度，保证问答结果的完整性 |
| `temperature` | 0.2–0.4 | 降低随机生成概率，保证工艺规程与技术标准问答的准确性，符合设备维修的严谨性要求 |
| `toolChoice` | auto | 自动选择是否调用工具，适配多源设备数据的实时召回需求 |

## 容易做错的三处
- 现象：调用本地部署大模型时返回连接超时错误。原因：未正确配置`AIPROXY_API_ENDPOINT`的访问地址，或本地模型服务未开放对应端口。
- 现象：在FastGPT后台添加模型后，知识库问答中无法选中该模型。原因：未正确配置`AIPROXY_API_TOKEN`，或模型权限未开放给当前使用的知识库。
- 现象：问答结果中未召回设备点检表的核心点检项与标准要求。原因：`maxContext`取值过小，导致召回的上下文未覆盖点检表的完整字段内容。

## 怎么确认配好了
- 访问配置的`AIPROXY_API_ENDPOINT`地址，验证本地模型服务是否正常响应。
- 在FastGPT后台发起模型测试调用，检查返回结果是否符合设备点检与维修相关的问答逻辑。
- 上传一份标准设备点检表文档，发起关联问答，确认召回的内容与文档中的点检项、标准要求匹配。
- 查看FastGPT v4.17.0的模型调用日志，确认`maxContext`、`maxTokens`等参数的实际取值符合配置要求。
