# 过程质量与成品放行的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来源于制造企业的MES系统、在线检测设备、实验室系统、工艺参数库、客户标准及历史缺陷库。数据更新节奏为每生产批次、每班持续采集，或随工艺调整实时更新。日常文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审记录、放行单及质量月报，字段涵盖检验批次号、缺陷代码、放行阈值、工艺参数值等，附带对应的计量单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源且实时更新的数据要求多轮对话需保留批次、检验项等上下文信息，避免重复提问；多样的文档结构要求提示词需明确指定提取字段与单位，确保问答结果符合业务格式；高频更新的工艺与标准要求提示词可自动适配最新阈值，无需手动调整；多类型字段要求对话流程需校验单位一致性，防止因单位错误导致放行判断失误。FastGPT v4.17.0的上下文管理功能可适配该类约束，但需针对性配置参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 6000–10000 字符 | 承载多份检验报告、SPC报表的完整文本内容 |
| 单次对话历史保留条数 | 前 8 条 | 聚焦当前检验批次的上下文，避免冗余信息干扰 |
| `variables` 绑定 | 绑定批次号、放行阈值变量 | 自动关联业务数据，简化用户提问输入 |
| 上下文召回上限 | 前 6 条 | 匹配最相关的工艺标准与历史缺陷数据 |
| 问题优化开关 | 开启 | 将口语化的检验提问转换为标准技术术语 |
| 最大响应 token 数 | 2000  token | 覆盖不合格评审的完整分析与判定内容 |

## 容易做错的三处
- 现象：多轮对话仅响应首次提问，后续提问无法关联前序的批次或检验项信息，界面无明显报错。原因：未正确配置`messages`的上下文传递规则，导致对话历史未被系统保留。
- 现象：调用模型后返回结果与配置的本地模型不符，无法正常调用部署的本地大语言模型。原因：代理配置参数未锁定目标模型，或环境变量存在冲突导致模型被替换。
- 现象：输入包含JSON格式的检验记录或SPC报表后，对话返回结果截断或提示字符超限。原因：最大上下文长度设置未适配JSON文本的字符规模，超出预设限制。

## 怎么确认配好了
- 发起包含具体批次号与检验项的提问，发起后续关联该批次的补充提问，确认回答可基于前序上下文给出对应结果。
- 查看应用的模型配置列表，确认仅显示目标部署的模型类型，无其他无关模型选项。
- 上传包含JSON格式的检验记录文件，确认对话可完整解析文本并返回相关的工艺标准与历史缺陷参考。
- 测试多轮连续提问，确认每次回答均未脱离当前检验批次的业务范围。
