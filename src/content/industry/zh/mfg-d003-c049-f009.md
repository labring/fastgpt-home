# 过程质量与成品放行的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自制造企业的MES系统、在线检测设备、实验室记录、工艺参数库、客户标准文档及历史缺陷库。日常产出的文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单与质量月报。数据更新节奏随生产批次、班次持续采集，单条数据包含检验项、缺陷类型、放行阈值、批次标识、检测数值等字段，单位涵盖件、ppm、小时等。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据来源分散且更新节奏频繁，要求模型接入环节支持多源数据的批量同步与增量更新。不同类型的质量文档结构差异较大，配置环节需适配控制计划、检验报告等多种格式的内容解析。数据包含特定专业字段与单位，配置需确保模型可准确识别检验项、放行阈值等专业内容，避免出现单位混淆或判定偏差。同时，过程质量与成品放行的出错后果直接关联生产停线与客户风险，因此模型调用的稳定性与结果置信度需纳入配置约束。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多份质量文档与检测记录的上下文整合，避免截断关键标准与检验数据 |
| `maxTokens` | 4000 token | 控制单轮问答的输出长度，确保工艺规程解读、异常判定的结果完整且聚焦 |
| `temperature` | 0.1–0.3 | 降低随机输出，保障专业判定的一致性，符合质量管控的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写官方或自定义代理地址 | 适配多模型接入需求，解决跨区域调用延迟问题 |
| 工作流/API 工具选择配置 | auto | 允许模型自主选择是否调用工具，适配从标准文档中提取检验项、关联历史缺陷的场景 |
| `quoteMaxToken` | 1500 token | 限制引用文档的长度，确保上下文精准匹配当前问答的质量判定需求 |

## 容易做错的三处
- 界面显示“当前分组 default 下对于模型 gpt-4o-mini 无可用渠道”，原因是未在对应分组中配置该模型的接入密钥或代理地址，或渠道配置未通过连通性测试。
- 调用时返回身份验证失败报错，原因是未正确配置`AIPROXY_API_TOKEN`，或密钥与接入地址不匹配，导致无法完成模型调用。
- 模型输出的检验项与文档实际内容不符，原因是`maxContext`取值过小，截断了关键的工艺标准文本，导致模型无法完整匹配判定规则。

## 怎么确认配好了
本核对流程基于FastGPT v4.17.0版本。
- 进入模型管理页面，检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置值与实际接入信息一致。
- 发起单轮测试问答，输入“请提取控制计划中的首件检验项”，核对模型输出是否包含文档内的专业检验项内容。
- 触发多文档上下文测试，上传同批次的巡检记录与成品检验报告，确认模型可关联两类数据完成异常判定。
- 调用测试工具验证模型响应时长，确认在生产节奏允许的时间范围内返回结果。
