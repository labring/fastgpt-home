# 钢材轧制与精整的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据覆盖热轧、冷轧、型钢、钢管生产全流程。日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书。数据来源包括板坯或钢坯批次信息、加热炉运行参数、轧机自动控制数据、在线测厚测宽结果、表面检测记录、MES系统数据。数据更新频率为每卷或每支产品批次级实时更新，文档字段包含钢卷号、批次号、加热温度、轧制压下率、厚度偏差、表面缺陷等级等，附带对应物理单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时批次级更新的数据要求索引支持增量更新，避免全量重建带来的性能损耗。多源异构数据格式需统一预处理，确保向量生成的一致性。单批次数据量小但总数据量随生产规模增长，需适配动态扩容的索引结构。板形、厚度等数值型字段与工艺规程文本需分别处理，避免特征混淆。卷级追溯需求要求索引保留批次关联信息，确保召回结果可绑定到具体生产单元。同时，高频调用下需保证检索延迟符合实时问答的响应要求。

## 配置怎么定
本配置建议基于FastGPT v4.17.0 版本进行调整，具体参数如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配轧制规程、质保书等长文本的语义完整性，避免关键工艺参数被拆分 |
| 重叠长度 | 100–200 字符 | 保留跨分块的工艺关联信息，如加热制度与后续轧制步骤的衔接 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非工艺相关文档，确保召回结果贴合技术标准要求 |
| 单次搜索上限 | 前10条 | 控制返回结果规模，避免过载且覆盖主要工艺参考依据 |

## 容易做错的三处
- 本地部署环境下无法自动索引表面质量报告中的图片附件。原因：未安装对应图片解析依赖包，或未启用知识库的图片索引开关。
- Embedding模型调用失败，返回OneAPI相关报错。原因：未在FastGPT配置中正确填写嵌入模型的接口地址与密钥，或使用的嵌入模型不支持当前部署环境的硬件加速。
- 开启重排模型后在线召回测试结果未发生变化。原因：未在知识库索引环节同步开启重排开关，或重排模型的调用参数未适配品类文档的长度要求。

## 怎么确认配好了
- 导入一份典型的轧制规程文档，执行分块测试，确认关键工艺参数如加热温度、轧制压下率未被截断。
- 调用嵌入模型接口，验证返回的向量数据格式符合FastGPT要求，无报错返回。
- 发起针对某一具体缺陷判定标准的检索，确认召回结果包含对应的表面质量报告或技术标准文档。
- 开启重排功能后，对比开启前后的检索结果，确认结果排序发生变化。
