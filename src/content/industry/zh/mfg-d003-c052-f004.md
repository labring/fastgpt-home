# 钢材轧制与精整的工艺规程与技术标准问答：工作流编排

## 这个品类的数据长什么样
本品类数据来源于板坯或钢坯批次台账、加热炉运行参数、轧机自动控制日志、在线测厚测宽设备数据、表面检测结果、生产执行系统（MES）。日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、产品质保书。数据更新频率为每卷或每支钢坯实时同步，支持卷级全链路追溯，文档字段包含工艺参数、检测数值、批次标识等，采用毫米、摄氏度、米每秒等工业标准单位。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的实时卷级数据与多源文档特征，对工作流编排带来三点核心约束。第一，数据实时更新的节奏要求工作流触发时机匹配单卷或单支钢坯的生产节点，不采用固定周期调度方式。第二，卷级追溯的需求要求工作流将批次ID作为`variables`参数动态绑定，确保检索与处理的文档完全对应目标生产批次。第三，多源异构的工艺与检测文档类型，要求工作流配置多节点并行检索不同文档类型，再聚合结果输出。同时，工艺参数异常可能导致钢卷降级或设备损伤，工作流需嵌入异常判定节点，匹配行业常规参数阈值。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量`variables` | 绑定轧制批次ID、钢卷规格参数 | 匹配卷级追溯需求，确保检索与处理的文档对应目标生产批次 |
| 节点ID`nodeId` | 为加热制度、轧制规程、检测报告节点分配唯一标识 | 区分多源检索节点，避免数据聚合时出现混淆 |
| 单次检索的上下文长度 | 800–1200 字符 | 适配工业工艺文档的单段信息量 |
| 单次检索上限 | 前5条 | 控制返回结果数量，避免冗余数据干扰判定 |
| 超时阈值 | 600秒 | 匹配工业生产的常规响应时效要求 |
| 日志留存周期 | 30天 | 符合工业生产的合规追溯要求 |

本配置示例基于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：HTTP请求节点传递TXT格式工艺文档时返回400错误。原因：未正确配置`variables`参数绑定文件流，仅传递了文件名，未传递实际文件内容。
- 现象：工作流无法检索到对应钢卷的工艺规程。原因：未将批次ID作为`variables`参数动态传入检索节点，导致检索结果匹配错误批次数据。
- 现象：Bot中无法挂载多个工作流，仅支持单一工作流独立运行。原因：未在Bot配置中开启多工作流挂载功能，错误将工作流作为单一功能模块绑定。

## 怎么确认配好了
- 触发模拟批次创建事件，检查工作流是否自动启动并检索对应批次的工艺文档。
- 查看`variables`参数是否正确绑定当前批次的ID与规格参数，无空值或错误字段。
- 验证HTTP请求节点可正常传递TXT格式文档至后端，返回结果符合预期。
- 确认Bot配置中已挂载该工作流，可通过对话触发工作流执行并返回结果。
