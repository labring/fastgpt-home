# 钢材轧制与精整的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
该品类数据主要来自板坯或钢坯批次台账、加热炉运行参数、轧机自动控制日志、在线测厚测宽设备数据、表面检测报告及制造执行系统（MES）。日常文档包含轧制计划、加热制度、轧制规程、单卷板形厚度记录、表面质量报告与质保书。数据更新频率为每卷或每支钢卷实时同步，字段包含批次号、加热温度、压下率、厚度偏差、表面缺陷等级等，单位涵盖摄氏度、毫米、百分比等。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据按单卷/单支实时更新且批次关联性强，模型接入需支持高频小批量数据读取，避免批量拉取导致的延迟。多类型结构化与半结构化文档混合，要求配置适配不同格式的文本解析，且需保留批次关联字段用于全流程溯源。单卷数据量有限但总数据量随产能增长，需控制上下文窗口规模防止溢出。工艺规程与标准依赖精确参数匹配，若出现字段错位或单位混淆，会直接导致问答结果失效。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单批次轧制全流程文档的总长度，避免上下文溢出 |
| `maxTokens` | 1200–1500 token | 保证回复能完整覆盖工艺规程的关键步骤，同时控制生成延迟 |
| `quoteMaxToken` | 180–220 token | 限定单段引用文档的长度，匹配单卷表面质量报告或厚度记录的典型段落 |
| `toolChoice` | auto | 允许模型自主判断是否调用检索工具，适配需要匹配实时批次数据的问答场景 |
| `temperature` | 0.1–0.3 | 降低生成随机性，确保工艺参数与标准要求的一致性 |
| `AIPROXY_API_ENDPOINT` | 按企业内部模型部署地址填写 | 对接大模型的官方接入地址，适配钢材轧制场景的专用模型需求 |

## 容易做错的三处
- 现象为平台模型列表无对应模型显示，原因是`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`配置错误，未正确指向部署的大模型服务地址。
- 现象为问答结果未引用正确的单卷工艺文档，原因是`maxContext`配置取值过小，未加载全批次相关的关联文档。
- 现象为生成的工艺步骤出现参数偏差，原因是`temperature`取值过高，导致模型生成不符合标准要求的参数内容。

## 怎么确认配好了
- 登录FastGPT v4.17.0平台，在模型管理页面查看已配置的模型是否显示在线状态。
- 输入单卷钢坯的批次号，发起工艺规程查询，核对返回结果是否包含对应批次的加热温度、压下率等核心参数。
- 发起表面缺陷判定相关的问答，核对返回结果是否引用了正确的表面质量报告内容。
- 连续发起10次高频查询，检查接口响应是否符合业务实时性要求。
