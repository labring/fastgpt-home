# 钢铁冶炼与连铸的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
这个品类的核心数据来自铁水与废钢数据、L2过程控制、化验室、MES、能源介质系统、设备状态。日常产生的文档包括炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单。数据更新频率为每炉次、实时、每班，文档包含炉次标识、工艺参数、成分数值、设备状态等字段，对应单位包括摄氏度、百分比、吨、米每秒等。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于数据按每炉次、实时、每班更新，向量索引需要支持增量更新，避免全量重建带来的资源消耗。由于文档包含炉次与浇次的强关联信息，分块时需保留相邻环节的上下文，避免断裂导致的工艺逻辑丢失。由于数据来源多系统且字段类型多样，索引需适配结构化参数与非结构化文本的混合检索。同时，工艺数据的准确性直接影响生产结果，检索环节需严格控制低相关结果的召回率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配单炉次工艺记录的段落长度，保留核心工艺参数的上下文 |
| 重叠长度 | 100–150 字符 | 避免炉次计划与对应配料单的分块断裂，关联相邻工艺环节的信息 |
| maxToken | 8192 token | 适配阿里text-embedding-v3等主流embedding模型的最大输入限制 |
| 相似度阈值 | 0.78–0.82 按实测标定 | 过滤钢铁冶炼场景下的低相关工艺文档，避免误匹配干扰生产决策 |
| 单次搜索上限 | 前15条 | 适配炼钢与连铸的多环节检索需求，控制上下文总长度不超出模型限制 |
| 重排模块 | 内置语义重排 | 优化多字段混合数据的排序准确性，贴合工艺参数的关联逻辑 |

## 容易做错的三处
- 更换embedding模型后，原有知识库检索报错或无结果。原因：未执行增量索引重建流程，原有向量数据仍基于旧模型生成，未同步更新。
- 知识库搜索结果排序不符合语义相关性预期。原因：未启用重排模块，或重排模块未适配钢铁冶炼场景下多参数混合的文档结构，仅依赖初始召回的相似度得分。
- 检索返回的语义匹配分数很高，但实际文档与查询问题无关。原因：相似度阈值设置过低，未过滤低相关的工艺记录，或分块长度过长导致冗余上下文干扰匹配精度。

## 怎么确认配好了
- 上传单份转炉冶炼记录文档，检查分块后的内容是否保留炉次号、成分数值等核心字段，无明显断裂。
- 更换embedding模型后，执行增量索引重建，检查原有知识库的向量生成进度是否正常，无报错提示。
- 发起包含具体工艺参数的查询，检查检索结果的排序是否符合业务逻辑，可通过调整重排模块参数优化匹配效果。
- 查看系统运行日志，确认模型接入参数配置正确，无“模型未匹配”类报错信息。
