# 钢铁冶炼与连铸的工艺规程与技术标准问答：工作流编排

## 这个品类的数据长什么样
钢铁冶炼与连铸的业务数据来源包括铁水与废钢数据、L2过程控制数据、化验室成分报告、MES系统、能源介质系统与设备状态数据。数据更新频率覆盖每炉次、实时与每班三个层级，日常文档包含炉次计划、配料单、转炉冶炼记录、连铸工艺记录、板坯判定单等，字段包含碳含量、出钢温度、浇铸速度等带明确单位的业务指标，单篇文档长度多在千字符以上。

## 这些特征在「工作流编排」这一环带来什么约束
数据按炉次、浇次分组且更新频率多样，要求工作流触发节点需绑定炉次事件或实时数据更新信号，避免固定周期触发导致的无效执行。多源异构数据与长文档结构，要求工作流需支持多节点并行拉取数据，并限定知识库搜索的文件集合范围。强耦合的冶炼连铸流程，要求工作流编排时需关联炼钢与连铸环节的节点，避免流程割裂。高风险的出错后果，要求工作流需配置失败重试与结果校验环节，减少异常炉次的损失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 知识库搜索范围 | 仅包含当前炉次关联的文件集合 | 钢铁冶炼连铸数据按炉次、浇次归档，限定范围可排除无关工艺文档 |
| 单次搜索返回条数 | 前8条 | 单篇工艺文档长度较长，过多结果会超出上下文承载上限 |
| 批量执行节点循环触发 | 按每班炉次数量上限 | 匹配单班次的生产处理规模，避免无效循环 |
| `variables` | 绑定炉次ID、浇次号、成分指标 | 用于精准检索对应炉次的工艺记录与标准 |
| `nodeId` | 绑定专属工艺知识库节点ID | 确保工作流调用指向已上传冶炼连铸标准的知识库 |
| 超时阈值 | 600秒 | 适配多源数据拉取与长文档检索的耗时需求 |
| 最大上下文长度 | 8000 token | 适配冶炼工艺文档的长文本检索需求 |

## 容易做错的三处
- 工作流中无法获取目标知识库的关联ID，界面显示对应字段为空。原因是未在工作流配置中绑定对应钢铁冶炼连铸工艺知识库的访问权限，或未正确配置`nodeId`参数指向目标知识库节点。
- 批量执行节点在线调试可完成全流程，但通过API调用时无法执行全部循环。原因是API请求未配置批量执行的超时阈值，或并发请求数量超出系统承载上限，导致部分炉次处理未完成。
- 变量引用模式下大模型温度参数的设置按钮消失，无法直接配置。原因是FastGPT v4.17.0中，变量引用模式需通过`variables`传入temperature参数，直接在节点界面设置无法生效。

## 怎么确认配好了
- 触发工作流后，查看知识库搜索节点的返回结果，确认仅包含当前炉次关联的工艺文档。
- 调用API执行工作流，查看批量执行节点的运行日志，确认所有炉次循环均完成且无超时报错。
- 检查`variables`参数是否正确绑定炉次ID、浇次号等业务字段，确认大模型调用的温度参数已通过变量传入。
- 查看工作流的状态监控面板，确认节点运行时长未超过预设的600秒超时阈值。
