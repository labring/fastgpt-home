# 钢铁冶炼与连铸的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据覆盖钢铁联合企业炼铁、炼钢、连铸、质量与调度部门的日常业务文档，包括炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单。数据来源涵盖铁水与废钢数据、L2过程控制系统、化验室检测结果、MES系统、能源介质系统及设备状态监测数据，更新频率包含每炉次、实时、每班三种节奏，数据字段包含炉号、成分含量、温度、浇次编号等工业专用字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的高实时性、多源异构数据特征，对模型接入配置带来多重约束。多源数据包含不同系统的格式差异，需通过明确的配置参数统一不同系统的数据解析逻辑。每炉次、实时的更新节奏要求模型上下文长度需适配单次业务流程的信息范围，避免上下文溢出导致响应失败。数据字段包含工业专用术语，需确保模型能准确识别并关联对应工艺规程内容。同时，流程中断或缺陷传递会造成大额损失，需配置稳定的模型接入链路与错误处理机制。

## 配置怎么定
本文档基于FastGPT v4.17.0版本，以下为针对钢铁冶炼与连铸场景的模型接入配置建议：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配钢铁冶炼连铸单炉次或单浇次的完整业务文档长度，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 匹配工业场景下标准问答的输出长度需求，避免过长响应影响实时性 |
| `quoteMaxToken` | 1500 token | 限制引用的业务文档片段长度，确保检索结果与问答的匹配精度 |
| `temperature` | 0.1–0.3 | 降低随机输出，确保工艺规程与技术标准问答的准确性，符合工业场景的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 适配接入的第三方模型服务链路，确保数据传输正常 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具，适配多源数据检索的需求 |

## 容易做错的三处
- 现象：模型接入后返回401未授权报错。原因：未正确配置`AIPROXY_API_TOKEN`参数，或令牌未获得对应服务权限。
- 现象：视觉模型接入后无法处理连铸坯表面缺陷图像。原因：未开启`vision`参数，或未匹配模型支持的图像输入格式。
- 现象：无法统计单应用的token消耗数量。原因：未在FastGPT后台启用对应应用的token统计模块，或未关联对应模型的接入链路。

## 怎么确认配好了
- 提交测试用的标准炉次计划文档与对应工艺问题，检查模型返回结果是否包含正确的工艺参数与标准要求。
- 查看模型接入的日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置无错误，无连接超时或授权失败记录。
- 开启token统计功能，验证每次问答的token消耗数据是否正常生成。
- 测试视觉模型接入，上传连铸坯表面图像，检查模型是否能正确识别并关联对应工艺标准。
