# 钣金下料折弯的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自CAD/CAM设计文件、订单BOM、板材库存台账、激光切割机与折弯机运行日志、MES生产系统。日常产出的文档包含零件展开图、数控下料程序、折弯工艺卡、套料图、首件检验记录、工序流转卡。数据更新随订单交付、每日生产排班或每次模具换型触发，字段多包含板材厚度、折弯系数、孔径尺寸、折弯角度等，单位以毫米、度为主。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据更新频率高且触发节点分散，要求索引支持增量更新以避免全量重建的资源消耗。文档类型多样，既有带专业参数的工艺卡长文本，也有数控代码类的结构化短文本，还有Excel格式的BOM与库存数据，不同文档的合理分块长度差异较大。部分文档包含折弯系数、孔径公差等专业字段，分块时需保留字段关联性，避免破坏工艺逻辑。同时多品种小批量的生产模式导致单批次数据量波动明显，索引的召回上限需适配不同规模的查询请求。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配折弯工艺卡、套料图等长文本的专业参数完整性，避免破坏工艺逻辑 |
| 重叠长度 | 50–80 字符 | 保留相邻分块的折弯系数、工序顺序等关键信息，防止分块截断导致的工艺逻辑断裂 |
| `maxToken` | 8192 | 适配Qwen/Qwen3-Embedding-8B的模型输入上限，兼容数控代码与工艺卡的混合文本长度 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配度的非工艺类结果，确保召回内容与钣金下料折弯的工艺问题强相关 |
| 单次搜索上限 | 前8条 | 适配多品种小批量的单订单工艺查询场景，避免召回过多无关文档 |
| `defaultToken` | 1024 | 匹配基础查询的向量生成需求，平衡召回精度与计算资源消耗 |

## 容易做错的三处
- 现象：新增同名称的嵌入模型配置后，原有配置被覆盖。原因：未为不同业务场景配置唯一的模型标识，导致同名配置项冲突。
- 现象：查询召回的结果颗粒度过大，无法精准匹配具体工序的工艺问题。原因：分块长度设置过大，未拆分到适合工艺问答的最小粒度。
- 现象：向量生成时出现截断报错，返回结果为空或字段不完整。原因：未设置`maxToken`适配模型输入上限，长文本未被正确截断。

## 怎么确认配好了
- 查看平台的嵌入模型配置列表，确认所有模型标识唯一，无重复名称。
- 上传单份折弯工艺卡文档，手动查看分块结果，检查关键工艺参数是否完整保留在分块内容中。
- 发起工艺类查询，核对召回结果的数量与相似度阈值的匹配逻辑是否符合预期。
- 测试长文本的向量生成，确认无截断报错，生成的向量符合模型规格。
