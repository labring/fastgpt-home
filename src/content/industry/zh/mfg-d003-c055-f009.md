# 铸造（砂型、精密、压铸）的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来自ERP物料主数据、熔炼炉与测温仪、光谱仪、MES炉次记录、模具管理系统、客户图纸与技术条件。日常文档包含铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告、不合格品评审单。数据更新频率为每炉次、每批或每日，包含合金配料数值、温度参数、缺陷类型、炉次号、模次等字段，无统一固定格式，随生产节点动态生成。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且更新频率高，要求模型接入环节支持多源异构数据的快速同步。日常文档无统一格式，配置时需适配非结构化的工艺卡、不合格品评审单等内容。生产相关参数包含专业术语与特定单位，要求模型能准确识别并关联对应业务逻辑。频繁的炉次级更新也要求上下文配置能适配动态新增的业务数据，避免因数据过期导致判断失误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配铸造工艺文档的长上下文需求，覆盖单炉次全流程数据 |
| `maxTokens` | 2000–3000 token | 满足工艺参数解读与缺陷追溯的输出长度需求，避免截断关键结论 |
| `quoteMaxToken` | 1500–2000 字符 | 确保召回的工艺卡、炉次记录等源数据完整，支撑问答依据的准确性 |
| 工作流/API 工具选择配置 | auto | 适配配料核对、参数判读等工具调用需求，自动触发对应功能 |
| `vision` | 开启 | 支持客户图纸、金相照片等图片资料的解析，覆盖多模态问答场景 |
| `temperature` | 0.1–0.3 | 降低随机输出，保证工艺参数判断的一致性与准确性 |

## 容易做错的三处
- 配置`toolChoice`为auto后，工具调用无响应。原因是未匹配到该模型的工具调用适配规则，或模型本身不支持结构化输出格式。
- 接入自定义API网关时返回400错误。原因是请求参数格式不符合对接要求，或API端点与令牌配置不匹配。
- 修改docker部署的配置文件后模型列表未更新。原因是未重启FastGPT容器，或配置文件写入路径存在偏差。

## 怎么确认配好了
- 发起包含合金配料核对的测试提问，检查模型是否能召回对应炉次的配料单数据并生成结论。
- 上传客户图纸或金相照片，验证模型是否能正确解析图片内容并关联工艺参数。
- 查看FastGPT后台的模型调用日志，确认`maxContext`、`toolChoice`等配置参数被正确传递。
- 重启FastGPT v4.17.0部署容器后，检查模型列表是否包含配置的目标模型。
