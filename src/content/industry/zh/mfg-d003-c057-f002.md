# 锻造与模锻的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
锻造与模锻场景的数据源包含原材料质保书、加热炉系统采集数据、压力机运行数据、MES系统记录、无损检测仪报告与客户锻件图。日常生成的文档包括锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单与超声检测报告。数据更新频率为每件锻件、每批物料或每炉次，文档包含锻造比、纤维方向、加热温度、炉批号等专业字段，单位涵盖摄氏度、吨、毫米等工业标准单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据高频更新的特性要求索引支持增量同步，避免全量重建带来的资源消耗。多类型文档混合的场景需要适配结构化质保书与非结构化工艺规程的分块规则，防止锻造比、纤维方向等专业术语被错误拆分。锻件质量与检索结果强相关的特性要求向量匹配需严格过滤低置信度结果，同时需适配工业专属术语的语义表达，避免不同工艺环节的描述出现语义混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配锻造工艺规程的标准段落长度，避免将连续的加热区间与变形工步拆分 |
| 重叠长度 | 50–80 字符 | 保留跨分块的工艺步骤上下文，确保检索时能关联完整的工序逻辑 |
| maxToken | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关文档，避免召回错误的工艺参数，适配锻件质量管控的严格要求 |
| 单次搜索上限 | 前6条 | 覆盖单批次锻件的下料、加热、锻造、检测等全环节工艺要求 |

## 容易做错的三处
- 现象：调用知识库接口生成索引后提示模型变更异常，或存量embedding-ada-002数据无法匹配新的embedding-3检索结果。原因：未统一配置embedding模型，且未执行存量知识库的批量重索引操作。
- 现象：通过OpenAPI创建的QA拆分文件集合检索延迟超过10秒，返回结果耗时过长。原因：未调整分块长度与单次搜索上限，导致索引分片冗余或召回数据量超出合理范围。
- 现象：检索结果中出现混淆锻造比与铸造缩孔的描述，或混入无关的铸造工艺文档。原因：未针对工业专业术语设置合理的相似度阈值，且未限定检索的文档类型范围。

## 怎么确认配好了
- 查看索引生成日志，确认分块长度与重叠长度符合预设配置，无异常拆分的专业术语段落。
- 发起测试检索，输入“某型号航空锻件的加热区间与变形工步”，核对返回结果的文档类型均为锻造工艺规程与过程卡。
- 测试存量数据的重索引操作，确认无需重新导入原始文件即可完成向量更新。
- 查看检索结果的相似度得分，确认均落在预设的阈值区间内。
