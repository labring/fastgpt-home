# 锻造与模锻的工艺规程与技术标准问答：工作流编排

## 这个品类的数据长什么样
该品类数据涵盖锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告等。数据来源于原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图，更新频率为每件、每批或每炉次。数据字段包含锻造比、金属纤维方向、炉批号、锻件尺寸公差、加热温度区间等，单位涉及毫米、摄氏度、吨等，需匹配各生产环节的实时采集与纸质归档信息。

## 这些特征在「工作流编排」这一环带来什么约束
该品类数据来源分散，包含实时系统采集与纸质归档文档，要求工作流支持多数据源对接与格式统一处理。数据更新频率随每件、每批或每炉次变动，需工作流支持按生产批次触发知识库增量更新。专业字段如锻造比、金属纤维方向的校验需求，要求工作流内置专业术语匹配逻辑。出错后果涉及锻件报废与安全风险，需工作流配置异常校验与告警环节，确保工艺与标准的一致性。同时，多批次并行生产的场景，要求工作流支持会话级别的参数隔离，避免不同生产任务的参数混淆。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` 隔离规则 | 按使用者ID隔离同名全局变量 | 不同锻件批次的工艺参数需独立存储，避免跨会话参数混淆 |
| 历史上下文加载节点 | 绑定`nodeId`为历史会话存储节点 | 支持在新对话中加载之前保存的全局变量 |
| 自定义回复引导语 | 配置AI回复后追加的专属引导语 | 匹配锻造工艺场景的业务引导需求 |
| 工作流超时阈值 | 600秒 | 需处理多源数据匹配与专业校验，预留足够处理时长 |
| 知识库更新触发 | 按炉次/生产批次触发 | 匹配该品类数据按每件、每批或每炉次更新的节奏 |

## 容易做错的三处
- 现象：工作流调用API时返回结果无上下文关联，界面显示上下文配置已开启。原因：未将`variables`绑定到会话隔离规则，导致上下文未按使用者ID隔离。
- 现象：AI回复后仅显示系统预设的猜你想问内容，无法生成定制化引导语。原因：未配置AI回复后的自定义引导语节点，仅依赖系统默认设置。
- 现象：不同使用者发起的查询出现参数混淆，同名全局变量被覆盖。原因：未开启`variables`的使用者ID隔离，全局变量作用域未按会话拆分。

## 怎么确认配好了
- 发起两次不同使用者ID的会话，验证同名全局变量的取值是否独立，确认隔离规则生效。
- 触发一次工作流，查看AI回复后是否追加了自定义引导语，确认引导语配置生效。
- 模拟按炉次触发知识库更新，验证工作流是否自动同步最新的加热炉记录与工艺规程数据。
- 调用工作流API，验证返回结果包含历史会话的全局变量，确认上下文加载正常。
