# 锻造与模锻的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
锻造与模锻场景的核心数据来自原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图。日常运维与生产文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告。数据更新以每件锻件、每批物料或每炉次为单位，字段包含锻造比、纤维方向、炉批号、模具编号、检测数值等，单位涵盖毫米、摄氏度、吨等物理量。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据按单件、单批或单炉次更新，溯源需精准绑定对应批次的生产节点，避免跨批次引用混淆。多类型文档的结构差异要求溯源系统能识别不同文档的字段规范，比如下料卡的炉批号与超声检测报告的检测编号需对应匹配。多数据源的采集链路要求溯源信息可追溯至原始系统，不能仅依赖二次加工的文档。同时，锻件失效后果严重，溯源需确保引用内容完整对应生产环节的实际参数，不能出现信息截断或模糊匹配。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 锻造工艺参数精度要求高，需过滤低匹配度的无关文档 |
| 单次召回上限 | 前8条 | 锻造相关文档数量集中，过多召回会超出上下文承载限制 |
| `quoteMaxToken` | 1200–1500 token | 锻造工艺规程文本较长，需保留完整的引用片段 |
| `responseData` | 开启原始引用字段 | 需直接返回知识库问答对的原文答复，不做AI改写 |
| `detail` | 开启溯源详情 | 需展示引用文档的来源节点与批次信息 |
| 分块重叠长度 | 50–80 字符 | 覆盖工艺规程中连续的工步描述，避免分块截断关键参数 |

## 容易做错的三处
- 现象：工作流中AI返回结果未携带查询到的知识库内容，仅返回通用提示。原因：未开启`responseData`配置项，系统未保留原始问答对的答复内容。
- 现象：服务启动后长时间无响应，请求触发超时。原因：单次召回上限设置过高，且`quoteMaxToken`取值过大，超出系统上下文承载上限。
- 现象：引用内容被截断，无法看到完整的加热区间或变形工步参数。原因：`quoteMaxToken`取值过小，未覆盖完整的工艺规程片段。

## 怎么确认配好了
- 发起包含具体锻件炉批号的查询，核对返回结果中是否包含对应知识库问答对的原文答复。
- 查看返回结果的溯源详情字段，确认是否关联到原材料质保书、加热炉记录等指定的生产数据源。
- 测试不同批次的锻件查询，验证召回结果仅匹配对应批次的工艺文档，无跨批次混淆。
- 调整`quoteMaxToken`的取值，检查引用片段的完整性是否符合生产文档的阅读需求。
