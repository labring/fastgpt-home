# 预制混凝土构件的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
预制混凝土构件相关数据来自BIM深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检验报告及二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣日志、养护参数记录、脱模与出厂检验报告。数据按单件构件、每批次物料、每一窑养护批次更新，字段包含构件编号、钢筋规格、养护温度、脱模强度值等，单位涵盖毫米、兆帕、摄氏度等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
预制混凝土构件的数据来源分散且按单件、批次、窑次高频更新，要求多轮对话需绑定当前会话的构件编号与批次信息，确保每次追问都匹配对应范围的文档。日常文档包含专业工程图纸与检验数据，提示词需限定调用该品类专属的工艺规程与技术标准内容，避免引入无关领域信息。字段含明确工程单位，对话交互需保留参数的单位关联，防止单位混淆导致的错误。同时，出错后果直接关联构件报废与工期延误，需在对话中强化内容校验逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的交互逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前构件的唯一标识 | 确保多轮对话上下文关联对应构件的专属数据 |
| `messages` | 保留前 10 轮对话内容 | 覆盖构件从深化设计到出厂检验的全流程交互 |
| `variables` | 传入当前构件编号、批次号、养护窑号 | 精准匹配对应批次的文档与检验数据 |
| 最大上下文长度 | 8000–12000 字符 | 容纳多份构件文档与完整对话历史 |
| 输出格式控制 | 禁用Markdown语法，输出纯文本 | 适配工厂现场终端的显示与录入要求 |
| 会话保持时长 | 7200 秒 | 覆盖单批次构件的全流程咨询周期 |

## 容易做错的三处
- 现象：对话中出现`Unexpected end of JSON input`报错。原因：未正确绑定`variables`参数，导致传入的构件批次信息为空，触发模型格式异常。
- 现象：对话结果未直接在对话框内展示，需手动在侧边栏查看。原因：未配置会话上下文的实时同步逻辑，导致返回内容未挂载到当前对话窗口。
- 现象：每次发起对话都需新建会话，无法延续之前的交互。原因：未正确使用`chatId`绑定当前构件的唯一标识，系统默认每次请求生成新会话。

## 怎么确认配好了
- 发起测试对话，输入某构件的编号，验证返回内容仅关联该构件的工艺规程与检验数据。
- 连续发起3次追问，检查对话上下文是否保留之前的构件信息与交互内容。
- 调整输出格式配置，验证返回结果是否符合预设的纯文本要求。
- 查看会话标识，确认每次关联同一构件的对话均使用相同的`chatId`。
