# 预制混凝土构件的工艺规程与技术标准问答：工作流编排

## 这个品类的数据长什么样
该品类数据来自BIM深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检验报告及二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验单、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据按单件构件、每批次物料、每窑养护单元更新，字段包含构件编号、钢筋规格、混凝土强度等级、养护时长、脱模强度值，单位涵盖毫米、兆帕、小时等。

## 这些特征在「工作流编排」这一环带来什么约束
该品类数据来源分散，覆盖设计、生产、检验多环节，要求工作流需支持对接多源数据节点同步实时信息。数据按单件、每批、每窑高频更新，要求工作流节点触发逻辑绑定对应数据更新事件，避免使用固定周期同步导致的数据滞后。日常文档类型多样，需适配深化图、下料单、检验报告等多格式解析。同时，数据出错会引发构件报废或工期延误，工作流需嵌入前置校验环节，对钢筋规格、强度参数等关键字段进行一致性核对。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.75–0.85 | 预制混凝土构件工艺参数精度要求高，需过滤低匹配度的非标准内容 |
| 单次搜索上限 | 前8条 | 匹配构件专属的深化图、检验记录等多源文档，避免冗余结果干扰 |
| 最大上下文 | 1200–1500 字符 | 适配钢筋下料单、养护记录等单份文档的长度，避免上下文溢出 |
| 节点超时时间 | 600 秒 | 处理大型深化图解析时，预留足够的加载与解析时间 |
| `variables` | 绑定构件编号、混凝土强度等级 | 匹配单件构件的专属生产数据，实现精准问答 |
| `nodeId` | 绑定校验节点ID | 触发后置校验环节，对提取的参数进行一致性核对 |

## 容易做错的三处
- 现象：工作流配置问题优化功能后，无法获取历史问答记录。原因：未将`variables`绑定历史会话ID参数，导致节点无法读取会话上下文。
- 现象：AI对话节点后接入代码运行节点，调试时成功移除think标签，正式运行时仍显示思考内容。原因：未在代码节点中配置全局输出过滤逻辑，仅在调试环境生效，正式运行时未覆盖原始输出。
- 现象：尝试通过项目备份恢复数据后，知识库与智能体未正常加载。原因：备份恢复仅覆盖项目基础配置，未同步关联的知识库文件索引，需手动重新绑定数据源。

## 怎么确认配好了
- 输入单件预制构件的编号，验证问答结果是否返回该构件专属的钢筋下料单参数、养护记录数据。
- 触发工作流运行，检查代码节点输出是否已移除思考标签内容，无额外冗余信息。
- 导入备份文件后，查看知识库数据源是否正常关联，智能体列表是否完整显示。
- 提交包含模糊或错误参数的提问，验证相似度阈值过滤功能是否生效，低匹配度内容未被返回。
