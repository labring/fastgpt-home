# 预制混凝土构件的工艺规程与技术标准问答：引用来源与溯源

## 这个品类的数据长什么样
预制混凝土构件的核心数据来自BIM深化设计、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检验报告及构件二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣日志、养护周期记录、脱模与出厂检验报告。数据更新节奏为单件、每批、每窑，每份文档对应专属构件或生产批次，字段包含钢筋规格、养护龄期、强度等级、模台编号等带明确单位的参数。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于每份数据对应专属构件或生产批次，引用溯源需精准匹配构件ID与文档的关联关系，避免跨批次引用错误文档。高频更新的浇筑、养护记录要求溯源系统实时关联最新版本数据，无法依赖静态缓存的旧文档。多类型业务文档需按生产环节分类索引，确保工艺规程问答能快速定位到对应工序的文档。出错后果严重的属性要求溯源信息必须包含明确的批次、检验项等字段，无法仅返回模糊的文档名称。

## 配置怎么定
本页配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配预制构件单份文档的典型段落长度，确保引用内容完整覆盖工艺参数 |
| 单次搜索上限 | 前6条 | 覆盖单个构件对应的深化图、下料单、养护记录等多份关联文档 |
| `responseData` | 开启 | 启用引用来源的详细数据返回，支持展示文档的批次、检验项等核心字段 |
| 重排 | 开启 | 优先匹配与当前构件ID强关联的文档，提升溯源准确性 |
| `detail` | 开启 | 输出引用来源的完整元数据，包括文档类型、生成时间等信息 |
| 最大上下文 | 3500–4500 字符 | 承载预制构件工艺规程的完整上下文，避免关键参数丢失 |

## 容易做错的三处
- 现象为工作台知识库简单应用中每次仅返回1条引用，原因是单次搜索上限配置过低，未匹配到该构件对应的多份关联文档。
- 现象为配置模型后测试提示报错，强行忽略后可运行但引用溯源字段为空，原因是未开启`responseData`配置项，未启用引用数据返回。
- 现象为导入预制构件的知识库后，系统默认文档选择框为空，需手动逐个选择文档，原因是未按构件ID对文档进行分类索引，无法匹配到对应品类的专属文档。

## 怎么确认配好了
- 输入预制构件的钢筋下料单相关问题，查看返回结果是否附带对应文档的名称、批次号等溯源信息。
- 调整`quoteMaxToken`参数后，测试长文档的引用拆分是否符合预期。
- 导入多份预制构件的养护记录文档，验证检索时是否能匹配到对应批次的文档。
- 检查`detail`配置项是否开启，确认返回结果中包含完整的引用元数据。
