# 预制混凝土构件的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
预制混凝土构件相关数据来源于BIM深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检验报告及产品二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验单、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据更新随单件构件、每批物料或每窑养护批次触发，核心处理环节包含工程图拆分为构件与预埋件清单、核对钢筋套筒及预埋位置、管控浇筑养护与脱模强度。

## 这些特征在「模型接入与配置」这一环带来什么约束
构件深化图等文档包含大量结构化图纸参数与离散的批次、窑次数据，模型需适配多类型文档的混合输入。数据更新频率高且粒度细，需确保模型接入时的上下文同步时效性。预埋位置、强度要求等核心字段的准确性直接关联现场安装与产品报废风险，要求模型对专业术语的识别精度更高。不同文档的字段单位存在差异，如钢筋直径以毫米计、养护时长以小时计，需模型可区分不同文档的字段规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配构件深化图、钢筋下料单等长文档的上下文存储需求，覆盖多批次数据的关联查询 |
| `maxTokens` | `2000–3000 token` | 满足工艺规程问答的完整输出长度，避免因输出截断导致养护参数、脱模要求等关键信息缺失 |
| `quoteMaxToken` | `1500 字符` | 限制引用文档的片段长度，匹配单份检验记录、下料单的典型段落长度 |
| `temperature` | `0.1–0.3` | 降低回答的随机性，确保工艺参数、安装要求等专业内容的输出一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署实例填写 | 适配FastGPT v4.17.0的代理接口规范，确保模型调用链路正常 |
| `AIPROXY_API_TOKEN` | 按授权密钥填写 | 完成模型接入的身份验证，保障接口调用权限合规 |

## 容易做错的三处
- 现象：调用后返回内容长度过短，无法覆盖完整工艺要求。原因：`maxTokens` 配置取值过低，或版本更新后默认参数被重置。
- 现象：知识库无法正常加载构件深化图类PDF文档。原因：未确认`vision`配置是否开启，或本地部署的markpdf镜像未完成模型下载。
- 现象：问答结果未引用对应批次的养护记录数据。原因：`maxContext` 配置未覆盖多批次数据的关联上下文，导致召回范围不足。

## 怎么确认配好了
- 上传单份构件深化图与钢筋下料单，测试问答返回的内容是否包含图纸中的预埋件位置参数。
- 调整`temperature`参数后，多次发起相同工艺问答，核对返回结果的专业表述是否保持一致。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置未出现格式错误。
- 触发批量文档导入任务，检查是否有因上下文超限导致的导入失败提示。
