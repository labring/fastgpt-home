# 预制混凝土构件的工艺规程与技术标准问答：部署与升级

## 这个品类的数据长什么样
预制混凝土构件相关数据来源于BIM深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检验报告及二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据更新随单件构件、每批物料、每一窑养护流程触发，核心字段含构件编号、预埋件位置、混凝土强度等级、养护时长等，需匹配现场吊装位置与工程需求。

## 这些特征在「部署与升级」这一环带来什么约束
预制混凝土构件的文档多为结构化工程图纸与批次台账，单份文档体积较大且字段关联紧密，部署时需适配大文件解析与关联数据召回。数据更新频率高且触发节点分散，需配置适配实时增量同步的存储与检索链路。不同构件的检验记录与溯源数据格式存在差异，升级时需兼容多数据源的字段映射规则，避免检索时出现匹配偏差。同时，问答结果直接影响构件生产质量与工程进度，部署环节需强化权限控制与日志留存，确保结果的可追溯性。

## 配置怎么定
以下配置项基于FastGPT v4.17.0版本，适配预制混凝土构件工艺规程问答的部署需求：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 15–25 条 | 适配预制混凝土构件多批次、高并发的检索请求，避免数据库连接耗尽 |
| `MONGODB_URI` | 指向预制构件专属文档集合的连接串 | 隔离工程文档与通用业务数据，提升检索精准度 |
| `REDIS_URL` | `redis://localhost:6379/0` | 缓存高频查询的养护记录与检验标准，降低数据库负载 |
| `STORAGE_S3_ENDPOINT` | 企业自有对象存储的接入地址 | 存储构件深化图、下料单等大体积工程文档，适配本地部署的存储需求 |
| `ROOT_KEY` | 按团队权限生成专属密钥 | 控制工艺规程问答的访问范围，避免无关人员接触涉密工程数据 |

## 容易做错的三处
- 执行`docker-compose up`后出现数据库连接超时报错。原因是未正确配置`MONGODB_URI`或`REDIS_URL`，未匹配预制构件数据专属的存储节点地址。
- 配置第三方模型对接后，平台未显示可用模型。原因是仅修改了基础连接参数，未同步适配预制构件文档的上下文长度要求，导致模型调用失败。
- 部署后检索结果条数不足。原因是未调整`DB_MAX_LINK`参数，默认值无法覆盖多批次构件的关联数据召回需求。

## 怎么确认配好了
- 执行`docker ps`命令，确认FastGPT相关容器与数据库、缓存容器均处于运行状态。
- 访问`FE_DOMAIN`配置的域名，进入工艺规程问答模块，输入测试查询词，验证是否能召回预制构件的养护记录与检验标准。
- 上传一份预制构件深化图，验证系统是否能正确解析并关联对应的钢筋下料单数据。
- 查看后台日志，确认检索请求的响应时长符合预设要求，无频繁的数据库连接报错。
