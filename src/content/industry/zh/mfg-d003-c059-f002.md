# 预拌混凝土生产的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据主体为商品混凝土搅拌站、工程项目试验室及质量调度部门。日常文档包含配合比通知单、开盘鉴定、生产运输单、原材料检验记录、试块留存记录、强度检验报告。数据来源覆盖工程订单、砂石水泥外加剂进场检验、骨料含水率测定、搅拌站控制系统数据、试验室试验记录。数据更新节奏为每车生产记录、每批原料检验结果、每日试验室台账更新。

## 这些特征在「向量模型与索引」这一环带来什么约束
频繁的增量更新需求要求索引支持轻量化的增量同步，避免全量重建带来的过长耗时。文档中包含大量工程专业字段，如坍落度、水灰比、养护龄期等，向量模型需适配专业术语的语义编码，`maxToken`设置需覆盖完整的专业文档长度。单条文档体量较小但总数据量随生产批次持续增长，需控制分块粒度以避免语义割裂。试块记录、强度报告需与对应生产批次关联，索引需支持元数据过滤，实现按生产批次精准召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配单份生产单据的完整语义，避免跨文档拆分关键信息 |
| 重叠长度 | 50–80 字符 | 衔接相邻分块的语义，防止配合比、含水率修正等关键内容被截断 |
| `maxToken` | 8192 token | 适配专业文档的长文本编码需求，覆盖完整的配合比与检验记录内容 |
| 相似度阈值 | 0.72–0.80 区间 | 过滤低匹配度的非工艺相关内容，保留关键场景的召回结果 |
| 单次搜索上限 | 前 8 条 | 覆盖单批次生产涉及的原料检验、配合比、试块记录等多类文档 |
| `defaultToken` | 4096 token | 适配日常问答的输入长度，平衡语义完整性与模型加载效率 |

本配置基于 FastGPT v4.17.0 版本验证。

## 容易做错的三处
- 现象：切换知识库向量模型后界面显示无进度，且无法回到原模型配置页。原因：未先清空原有向量索引缓存，导致系统锁定当前模型配置。
- 现象：配置豆包embedding API后测试返回“404 page not found”报错。原因：API接口路径填写错误，未使用平台指定的官方接入地址。
- 现象：批量重新嵌入知识库后多语言场景召回率无改善。原因：未针对预拌混凝土的专业术语调整分块与相似度阈值，导致多语言语义编码失效。

## 怎么确认配好了
- 上传单份配合比通知单，核对向量分块的语义完整性，确认分块长度符合预设区间。
- 发起工艺规程相关提问，检查召回结果包含对应原材料检验、试块记录的元数据标签。
- 切换向量模型后，触发增量索引更新，确认系统显示更新进度正常。
- 批量导入历史生产数据，检查索引更新耗时符合预设节奏。
