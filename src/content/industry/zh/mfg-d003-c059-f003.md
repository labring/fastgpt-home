# 预拌混凝土生产的工艺规程与技术标准问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据来自工程订单、砂石水泥外加剂检验、含水率测定、搅拌站控制系统与试验室。日常文档包含配合比通知单、开盘鉴定、生产运输单、原材料检验记录、试块台账与强度报告。数据更新按单批次原料、每车生产任务、每日试验室检测节奏推进，单份文档包含原料参数、配比数值、搅拌参数、运输时效、试块强度等结构化字段与对应检测单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据更新频率高且粒度细，多轮对话需支持实时同步最新含水率、订单变更等信息，避免调用过时配比数据。文档类型多且结构差异大，提示词需明确区分原料检验、生产调度、质量追溯三类场景的检索规则。单份文档包含多组数值参数，多轮对话需保留上下文关联，避免重复询问已确认的项目编号或原料批次。试块强度数据需按龄期归档，对话流程需支持按时间范围筛选历史记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次搜索上限 | 前6条 | 单份生产文档的核心参数不超过5组，前6条可覆盖完整检索需求 |
| 重叠长度 | 150-200 字符 | 配合比通知单的标题与参数段间距约120字符，重叠可避免分割后参数断裂 |
| `variables` | 包含项目编号、原料批次、浇筑部位的固定变量 | 多轮对话需快速关联当前任务的专属参数 |
| `messages` 上下文窗口 | 前8轮对话 | 预拌混凝土生产的决策流程通常不超过7个关键步骤，前8轮可覆盖完整上下文 |
| 最大上下文 | 3000-4000 token | 单份完整生产台账约2500字符，3000-4000 token可容纳3-4份核心文档 |
| 提问优化 | 开启 | 现场调度人员的口语化提问易包含模糊表述，优化后可提升检索准确性 |

## 容易做错的三处
- 现象为调用AI对话模块时返回422状态码，原因是未正确配置`variables`中的必填项目参数，导致检索请求缺少关联字段。
- 现象为长文档分割后检索结果零散，原因是使用标题层级作为分隔符时，未匹配配合比通知单的分段逻辑，导致单段包含跨类参数。
- 现象为新对话弹窗无法关闭，原因是未修改前端初始化代码中的弹窗触发逻辑，导致FastGPT v4.17.0私有部署版本默认加载该组件。

## 怎么确认配好了
- 发起包含原料含水率修正的提问，核对返回结果是否包含当前任务对应的最新参数。
- 发起多轮连续提问，核对`chatId`是否保持一致，上下文是否被正确保留，未出现重复询问已确认信息的情况。
- 上传一份完整的配合比通知单，核对检索结果是否覆盖所有核心配比与检测参数。
- 触发新对话流程，核对是否未出现未配置的弹窗组件。
