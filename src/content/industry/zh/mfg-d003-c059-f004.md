# 预拌混凝土生产的工艺规程与技术标准问答：工作流编排

## 这个品类的数据长什么样
本品类数据来自工程订单、砂石水泥外加剂检验记录、骨料含水率测定报告、搅拌站控制系统日志、工程项目试验室档案。数据更新节奏为每车生产批次、每批原料进场、每日汇总统计。日常文档包含配合比通知单、开盘鉴定表、生产运输单、原材料检验报告、试块养护记录、混凝土强度报告，核心字段包含配合比参数、骨料含水率、坍落度指标、设计强度等级，单位涉及千克、立方米、百分比、兆帕。

## 这些特征在「工作流编排」这一环带来什么约束
每车级别的高频更新要求工作流需实时拉取最新的骨料含水率数据，避免配料计算偏差。多源异构的文档类型要求工作流需适配不同格式的检验报告、通知单内容提取。核心业务环节的强约束要求工作流嵌入参数校验逻辑，对配合比、坍落度等指标做合规性检查。试块强度报告的滞后性要求工作流预留异常回溯的变量存储节点，关联生产批次与强度结果。跨部门协同的需求要求工作流支持调度、试验室、搅拌站的节点权限配置。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 问题分类节点 | 切换至通用专业问答模型 | 适配工艺规程、技术标准的多分类场景 |
| 文本内容提取组件 | 单次提取上限为8000字符 | 覆盖单份开盘鉴定表的完整内容长度 |
| `variables` 配置 | 绑定生产批次号与骨料含水率 | 关联每车生产的核心参数，支持跨节点调用 |
| `nodeId` 绑定 | 绑定搅拌站节点与试验室节点 | 实现生产流程的全链路数据关联 |
| 全局变量历史记录 | 保留最近25条交互记录 | 匹配单日多批次生产的上下文需求 |
| 异常校验触发 | 当坍落度偏差超过2%时触发 | 符合预拌混凝土生产的工艺合规要求 |

## 容易做错的三处
- 使用初始化AI模型的问题分类节点，运行或保存发布时弹出报错提示。原因：默认初始化模型未适配工艺规程与技术标准的专业问答场景，无法完成分类逻辑的初始化校验。
- 文本内容提取组件返回的结果JSON为空。原因：未限定提取字段范围，或设置的提取长度超出组件单次处理上限，导致解析失败。
- 全局变量历史记录中未显示指定回复组件的输出。原因：未将该组件的输出绑定至全局变量存储节点，导致上下文未被正确捕获。

## 怎么确认配好了
- 新建问题分类节点，切换至通用专业问答模型后运行，确认无报错提示。
- 上传单份开盘鉴定表至文本内容提取组件，确认返回的JSON包含配合比、含水率等核心字段。
- 发起三次以上模拟生产问答交互，查看全局变量历史记录，确认包含所有交互与组件输出内容。
- 输入坍落度偏差超标的模拟参数，确认异常校验节点触发告警逻辑。
