# 预拌混凝土生产的工艺规程与技术标准问答：模型接入与配置

## 这个品类的数据长什么样
该品类数据来自工程订单、砂石水泥外加剂检验记录、骨料含水率测定报告、搅拌站控制系统日志、工程项目试验室档案。更新节奏随生产流程变化：每车混凝土生成对应生产运输单，每批原料进场生成原材料检验记录，每日汇总试块记录与强度报告。文档包含配合比通知单、开盘鉴定表、试块强度报告等，字段涵盖配料参数、检验数值、生产时间、运输调度信息，随搅拌站与试验室的记录习惯略有差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类高频更新的生产与检验数据，要求模型接入环节支持增量索引配置，避免全量重索引占用过多资源。分散的文档字段与非统一格式，要求配置时限定召回的文档类型范围，减少无关内容干扰。单次生产数据量有限但整体数据规模随订单增长，需适配合理的上下文承载上限。同时，工艺与标准问答涉及质量责任，配置需保障召回内容的准确性，避免因参数不当导致召回内容缺失或错误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配预拌混凝土生产文档的单批次数据量与多文档拼接需求，避免上下文溢出 |
| `quoteMaxToken` | 1500–2000 token | 限制单条召回文档的引用长度，匹配配合比、试块报告等单文档的核心内容长度 |
| `temperature` | 0.1–0.3 | 保障工艺与标准问答的回答准确性，避免生成偏离实际生产要求的内容 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写本地ollama接口地址 | 适配本地部署的模型调用需求，确保模型接入路径正确 |
| `AIPROXY_API_TOKEN` | 按部署配置填写对应密钥 | 完成本地模型的身份验证，保障调用权限合法 |
| `maxTokens` | 2000–3000 token | 限制单轮回答的输出长度，避免生成过长的工艺说明超出工程应用场景的阅读需求 |

## 容易做错的三处
- 在线召回测试时未触发Rerank模型。原因是知识库索引环节开启Rerank的配置未关联到当前应用的问答流程，或Rerank模型的部署路径未正确填写。
- 配置`maxContext`超过阈值后上下文未发送给大模型。原因是应用的上下文承载上限与`maxContext`参数未匹配，或系统对单轮上下文的总长度存在隐性限制，超出后自动截断未传递内容。
- 对话时频繁出现Request Time报错。原因是本地ollama模型的响应超时设置过短，或`AIPROXY_API_ENDPOINT`的网络延迟过高，未配置合理的超时重试机制。

## 怎么确认配好了
- 进入知识库的召回测试界面，输入工艺相关问题，查看召回结果的条数与内容是否匹配预设的文档范围。
- 调整`temperature`参数后发起测试问答，观察回答的严谨性变化，确认参数生效。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的调用请求无认证或路径错误。
- 配置`maxContext`为上限值后发起长上下文问答，确认大模型能完整接收拼接后的召回内容，无截断提示。
