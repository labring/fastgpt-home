# 饮料与瓶装水的工艺规程与技术标准问答：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自水源与原料检测、配方系统、在线糖度酸度监测、灌装设备、视觉检测系统及LIMS系统。日常文档包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验记录、成品检验记录。数据更新节奏为每批、每班或连续采集，单条记录包含原料指标、工艺参数、检验结果、批次编号等字段，覆盖从原料到成品全流程的工艺与标准相关信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
高频连续更新的工艺与检验数据，要求索引支持增量同步机制，避免全量重建带来的性能损耗与延迟。多类型混合的文档结构，包含配方文本、数值型工艺参数、检验结果等内容，要求向量模型同时适配工艺描述文本与参数数值的语义匹配。单批次数据关联多环节记录的特点，要求索引支持按批次维度的关联检索，避免跨批次的无关结果干扰。同时，工艺与标准问答的严谨性要求，检索结果需匹配严格的工艺阈值，避免低置信度结果影响生产判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 该品类的单条工艺记录包含多组参数与文本描述，该长度可完整覆盖单环节工艺信息，避免语义割裂 |
| 重叠长度 | 150–200 字符 | 工艺记录的参数与前后环节存在关联，重叠长度可保留跨分块的语义关联，避免关键参数被拆分 |
| 相似度阈值 | 0.75–0.85 | 该品类工艺参数要求严格，阈值需过滤低匹配度的无关记录，同时保留符合工艺标准的候选结果 |
| 单次搜索上限 | 前 10 条 | 单批次工艺记录关联多环节，前10条可覆盖主要的工艺与标准相关内容，避免过多冗余结果 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 重排 | 开启 | 该品类的工艺参数存在数值与文本混合的情况，重排可提升高匹配度结果的排序优先级，优化检索准确性 |

## 容易做错的三处
- 现象：配置第三方嵌入模型时，界面提示无可用渠道或连接失败。原因：未在FastGPT v4.17.0的分组管理中为嵌入模型配置专属调用分组，默认分组未开通对应模型的渠道权限。
- 现象：开启重排功能后，工艺问答的响应时间过长。原因：分块长度设置超出该品类单环节工艺记录的合理范围，导致单批次数据被拆分为过多分块，加重重排阶段的计算负担。
- 现象：检索返回的结果中混入大量无关的通用检测记录，未匹配到目标工艺规程。原因：选择的嵌入模型未适配该品类的工艺参数与标准文本的混合结构，无法精准匹配工艺相关的语义需求。

## 怎么确认配好了
- 上传单批次的工艺记录文档，检查分块结果是否完整覆盖单环节的工艺信息，无关键参数被拆分的情况。
- 发起一条工艺参数查询，核对返回结果的排序是否符合工艺关联的优先级，可通过调整相似度阈值适配检索严格度。
- 测试增量更新单条新的班次记录，确认索引可自动同步新数据，无需手动触发全量重建。
- 检查嵌入模型的调用日志，确认无连接失败或限流报错，模型调用状态正常。
