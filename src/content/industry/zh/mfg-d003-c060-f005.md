# 饮料与瓶装水的工艺规程与技术标准问答：工具调用与插件

## 这个品类的数据长什么样
该品类数据来源包括水源与原料检测、配方系统、在线糖度酸度监测、灌装设备、视觉检测、LIMS系统。数据更新节奏分为每批生成的配方单、包材检验记录，每班更新的调配记录，以及连续采集的水处理、杀菌或无菌灌装实时数据。日常文档包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验、成品检验，字段涵盖原料批次号、糖度、酸度、灌装液位、封口参数、标签批号等，部分数据带有固定格式要求。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的多源实时与批量混合数据特征，要求工具调用插件支持同时对接配方系统、LIMS、灌装设备等多个数据源。连续采集的实时数据要求工具调用可在短时间内拉取最新监测值，避免使用过期的历史数据。固定格式要求要求工具调用参数需匹配对应字段的类型与格式，防止投料参数偏差。每批更新的文档数据需要工具调用支持按批次号精准检索，避免跨批次数据混淆。同时，由于出错后果严重，工具调用需附带参数校验逻辑，提前拦截超限的投料、液位等参数。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，具体参数设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多工具并行调用场景，匹配多数据源的工艺数据检索需求 |
| `functionCall` | 按实测标定 | 适配不同复杂度的工艺参数查询，支持精准调用指定工具 |
| 单次工具调用超时时间 | 30 秒 | 匹配实时灌装、水处理数据的拉取延迟要求 |
| 工具调用结果缓存时长 | 5 分钟 | 平衡实时性与系统负载，适配每班更新的调配记录需求 |
| 批次号匹配精度 | 完全匹配 | 避免跨批次数据混淆，符合每批独立的文档更新规则 |
| 参数校验开关 | 开启 | 提前拦截超限的糖度、液位等工艺参数，规避生产风险 |

## 容易做错的三处
- 现象：调用MCP服务时，参数类型被固定为`string`，无法匹配糖度、灌装液位等非字符串字段。原因：未在插件配置中启用自定义参数类型映射，默认强制使用字符串类型传递工艺参数。
- 现象：工具调用后返回空响应，无任何工艺数据结果。原因：未按批次号精准匹配数据源，或超时时间设置过短，无法拉取连续采集的实时灌装数据。
- 现象：工具调用的流输出无法关闭，导致工作流节点返回冗余的流式片段。原因：未在工作流的工具调用模块中关闭流式输出开关，沿用了默认的流式配置。

## 怎么确认配好了
- 发起糖度参数的工具调用请求，核对返回的参数类型是否为匹配字段要求的格式。
- 模拟超标的投料量参数发起调用，确认系统触发参数校验拦截，返回异常提示。
- 输入指定批次号发起工艺记录检索，确认仅返回对应批次的文档数据，无跨批次混淆。
- 关闭工具调用的流输出开关，运行工作流节点，确认返回完整的非流式结果内容。
