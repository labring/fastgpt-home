# 饮料与瓶装水的工艺规程与技术标准问答：文档解析与分块

## 这个品类的数据长什么样
本品类数据主要来自水源与原料检测、配方系统、在线糖度酸度监测设备、灌装设备、视觉检测系统与LIMS系统。日常生成的文档包括配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验报告、成品检验报告。数据更新节奏为每批生产对应更新一次配方与检验记录，水处理、灌装等实时环节数据连续采集，每班汇总归档。文档多为批次绑定的结构化记录，字段包含投料量、浊度、灌装液位、封口合格率、批号等，部分文档附带设备运行参数的数值项。

## 这些特征在「文档解析与分块」这一环带来什么约束
品类的批次绑定文档要求分块需保留单批次工艺的完整关联信息，避免拆分破坏批次数据的上下文完整性。连续采集的实时环节数据条目密集，单文档可能包含大量短数值类记录，需合理控制分块边界，防止单块混入多批次无关数据。不同文档类型字段差异显著，配方单含投料配比参数，灌装记录含液位、封口参数，分块逻辑需适配结构化与半结构化文档的解析规则，避免遗漏关键工艺项。高频更新的批次文档需匹配合理的超时阈值，防止批量解析任务因数据量大中断。无菌控制相关的检验记录需完整保留合规字段，分块不能截断关键检测项。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，针对饮料与瓶装水品类的工艺文档特征制定：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配品类内多批次短记录的文档，避免单块包含过多无关批次数据，同时保留单条工艺规程的完整上下文 |
| `chunkSplitter` | 按段落+固定长度混合 | 适配结构化记录与半结构化工艺文档，先按段落拆分保留语义，再用固定长度补全边界 |
| `customPdfParse` | 开启 | 品类内文档多含标准化格式的检验报告与批次记录，开启自定义PDF解析可精准提取表格与字段信息 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单批次全流程文档包的上传，适配工厂批量归档的文档需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 匹配品类内大体积批量文档的解析时长，防止因数据量过大导致解析中断 |
| `chunkSettingMode` | 按文档类型自定义 | 针对配方单、灌装记录等不同文档类型设置差异化分块规则，适配字段差异 |

## 容易做错的三处
- 现象：上传PPT或Word文档时出现“the argument ‘windows-1252’ is invalid encoding”报错。原因：未适配品类内文档可能包含的多语言混合字符与非标准编码格式，默认解析编码未覆盖工厂文档常用的编码类型。
- 现象：本地部署后启用工作流文件上传，调用文档解析工具时返回地址解析失败。原因：未正确配置`CUSTOM_READ_FILE_URL`环境变量，或未将文件存储路径与解析工具的访问路径对齐，无法匹配品类内批量文档的存储与解析流程。
- 现象：批量解析多批次灌装记录时，部分文档解析结果为空或字段缺失。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值过小，未匹配品类内大体积批量文档的解析时长，导致任务提前中断。

## 怎么确认配好了
- 上传单份品类内典型文档（如单批次水处理记录），检查解析结果是否完整提取所有字段与批次关联信息。
- 调整`chunkSize`参数后，对比不同取值下的分块结果，确认单块未混入多批次无关数据。
- 验证`customPdfParse`开启后，PDF格式的检验报告是否能精准提取表格内的数值与参数。
- 上传批量归档文档包，确认解析任务未出现超时中断，且所有文档均完成解析。
