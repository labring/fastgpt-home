# PCB制造的技术文档交叉审查：引用来源与溯源

## 这个品类的数据长什么样
本品类的典型主体为印制电路板工厂的工程、生产、品质与实验室部门。日常处理的文档包括工程制作指示、Gerber解析记录、钻孔和层压参数文件、药水分析报告、AOI检测报告、电测报告与切片报告。数据来源涵盖客户提供的Gerber、钻带、BOM文件，CAM生成的工作稿，设备采集的运行参数，槽液化验结果与实验室检测数据。更新频率按生产批次、每班班次或连续采集，文档字段包含坐标值、孔径参数、缺陷尺寸、药水浓度等，无统一固定格式，随文档类型差异较大。与电子制造下的SMT品类不同，本品类的文档核心围绕多层图形与孔的互连参数，聚焦生产制程的参数管控与质量检测。

## 这些特征在「引用来源与溯源」这一环带来什么约束
PCB制造的文档多源且更新频繁，要求引用溯源必须精准匹配生产批次与文档版本，避免跨批次的错误参数引用。不同类型文档的字段差异大，需针对工程参数、检测报告等不同文档设置差异化的召回规则。连续采集的实时数据要求溯源系统支持近实时的向量库更新，确保引用内容与当前生产状态一致。一旦出现参数错误，需快速定位到原始文档与生产环节，因此溯源信息必须包含完整的元数据与文件标识，以便回溯具体的生产步骤，降低异常风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前6条 | 覆盖单生产批的核心文档数量，避免召回无关的历史批次数据 |
| 相似度阈值 | 0.75–0.85 | 匹配PCB参数的精确性，避免召回错误的钻孔孔径或层压温度数据 |
| 最大上下文长度 | 1500–2000 字符 | 保留完整的工程制作指示和Gerber解析片段 |
| `quoteMaxToken` | 900–1100 token | 适配单段生产参数的长度，防止截断关键的药水浓度或AOI缺陷描述 |
| `responseData` | 包含source_id、文件路径、检测时间 | 确保溯源信息包含可追溯的生产批次和文档版本 |
| `detail` | 开启 | 保留原始文档的元数据，比如CAM文件的生成时间、设备运行日志的时间戳 |

## 容易做错的三处
- 现象为调整相似度阈值和引用上限后，召回内容数量无变化，始终保持固定值。原因是未关闭上下文缓存，导致每次调用都复用了之前的召回结果，无法重新检索当前生产批次的文档。
- 现象为输出内容保留Markdown语法符号，未按预期渲染为可读格式。原因是未在提示词中明确要求格式化输出，或未开启内容格式化的相关配置。
- 现象为溯源时无法找到对应文档的数据库字段信息。原因是上传文档时未启用元数据提取功能，导致sourceid无法关联到数据库中的文件字段。

## 怎么确认配好了
- 上传一份测试用的Gerber解析记录和AOI报告，发起包含具体参数查询的测试问题，检查返回结果中是否包含source_id和文件名称等溯源信息。
- 调整`quoteMaxToken`的取值，观察返回内容的长度变化，确认参数已生效。
- 上传不同生产批次的同类型文档，发起查询，确认召回结果仅匹配当前批次的文档，无跨批次的干扰数据。
- 查看FastGPT的运行日志，确认每次调用都生成了新的溯源信息，无缓存复用的标记。
