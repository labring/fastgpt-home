# SMT贴片与电子组装的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自客户提供的BOM、Gerber文件、坐标文件，以及工厂内MES系统、锡膏与元件批次记录、贴片机、SPI/AOI检测设备、回流焊炉温采集系统。日常文档包含BOM与坐标文件、换线表、钢网与炉温记录、首件确认报告、SPI/AOI检测报告、维修记录与追溯标签。数据按每工单、每次换线实时更新，文档字段包含料号、位号、元件规格、坐标位置、缺陷类型、批次号等，部分文档带有毫米、摄氏度等单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。高频实时更新的工单与换线数据，要求索引支持增量同步，避免全量重建带来的性能损耗。多类型文档并存，包含结构化的BOM、半结构化的检测报告与非结构化的换线记录，要求向量模型适配不同格式的文本特征。文档字段包含料号、位号、坐标、温度等带单位的信息，索引需保留字段元数据，防止匹配时混淆单位导致错误关联。单工单关联数据量随复杂度提升，单次检索需处理较多文档，对索引的召回效率提出要求。同时，错误关联会引发批量错料或焊点失效，要求检索结果的准确性需符合业务校验标准。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 该品类文档多包含结构化字段与长文本描述，分块过长会丢失局部关联，过短会破坏字段完整性 |
| 重叠长度 | 100–200 字符 | BOM、坐标文件等文档的字段关联紧密，重叠分块可保留跨块的字段上下文 |
| 相似度阈值 | 按实测标定 | 该品类检索需匹配料号、位号等精准字段，阈值需结合业务校验逻辑调整 |
| 单次搜索上限 | 前 10 条 | 单工单关联文档量适中，过多结果会增加重排耗时，过少会遗漏关键信息 |
| 重排 | 开启 | 多类型文档混合检索时，重排可过滤无关结果，提升匹配准确性 |
| `maxToken` | 8192 | 适配FastGPT v4.17.0的默认上限，满足该品类文档的总上下文长度需求 |

## 容易做错的三处
- 现象：配置阿里千问text-embedding-v3时，界面提示无可用渠道。原因：未在分组配置中开启对应embedding模型的访问权限，或转发配置未正确关联该模型的API路径。
- 现象：开启重排后检索耗时过长，界面显示超时状态。原因：分块长度设置过长或单次搜索上限过高，导致重排阶段需处理过多文档片段。
- 现象：检索结果中出现料号与坐标混淆的匹配项。原因：未保留字段元数据的索引配置，或相似度阈值设置过低，导致无关字段的向量匹配被误判为有效。

## 怎么确认配好了
- 导入一份单工单的典型文档，执行检索测试，核对返回结果是否包含对应料号、位号的关联文档。
- 查看索引同步日志，确认增量更新任务是否按工单、换线事件触发，无全量重建的异常记录。
- 调整相似度阈值，对比不同阈值下的检索结果，确认匹配结果符合业务校验逻辑。
- 测试embedding模型的调用链路，确认无接口报错或超时提示。
