# SMT贴片与电子组装的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
SMT贴片与电子组装的技术文档包含BOM与坐标文件、换线表、钢网与炉温记录、首件确认报告、SPI/AOI检测报告、维修记录与追溯标签。数据来源包括客户提供的BOM、Gerber与坐标文件，以及MES系统、锡膏和元件批次台账、贴片机、SPI/AOI设备、回流焊炉温采集数据。数据更新频率为每工单、每次换线时更新，部分设备数据实时同步。文档字段包含料号、位号、元件批次、炉温参数、坐标值等，单位涉及摄氏度、毫米、批次编号等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据按工单与换线节点隔离更新，且单工单关联多类型专业文档，因此多轮对话需绑定当前工单的唯一标识，避免跨工单数据混淆。文档字段多且具备专业属性，提示词需明确限定检索范围为当前工单的特定文档类型，防止模型调用无关数据。实时更新的设备数据要求对话上下文能及时同步最新参数，多轮对话需按审查步骤逐步拆解问题，依次确认料号、位号、炉温等核心信息，确保审查逻辑连贯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前工单的唯一标识，如工单编号 | SMT工单数据按工单隔离，用`chatId`绑定可确保对话上下文仅关联当前工单的文档，避免数据交叉混淆 |
| 最大上下文长度 | 800–1200 字符 | SMT单份核心技术文档多为数百字符，该范围可覆盖单工单的关键文档，避免上下文过载影响推理效率 |
| `variables` | 传入当前工单的料号、换线时间、炉温区间等参数 | 可让提示词精准匹配当前工单的特定属性，缩小检索范围，提升审查准确性 |
| 历史会话召回上限 | 前5条 | SMT技术文档交叉审查的多轮对话通常不超过5轮，召回过多会增加推理延迟与资源消耗 |
| `messages` | 按先系统提示、再用户问题、再历史对话的顺序排列 | 符合大模型对话逻辑，确保系统提示的审查规则优先级高于历史上下文 |
| 超时设置 | 600 秒 | SMT文档交叉审查涉及多份报告比对与参数校验，需足够时间完成全量文档检索与推理 |

## 容易做错的三处
- 现象：调用API发起对话时返回404状态码。原因：未正确配置`variables`中的自定义标识，导致系统无法匹配对应工单的数据源。
- 现象：获取历史对话时仅返回默认会话的记录，无法筛选出当前工单的对话内容。原因：未使用`chatId`绑定当前工单，而是使用系统默认会话ID，导致上下文隔离失效。
- 现象：对话生成的结果未包含当前工单的首件确认报告数据。原因：未在系统提示中限定检索范围为当前工单的文档，而是检索了全量历史数据。

## 怎么确认配好了
- 发起测试对话，传入测试工单的`chatId`与`variables`参数，基于FastGPT v4.17.0版本的配置，检查返回结果是否仅包含该工单的BOM、换线表等指定文档内容。
- 调用历史记录接口，传入测试工单的`chatId`，确认仅返回该工单下的对话记录，无其他无关会话数据。
- 发起多轮对话，依次提问料号、位号、炉温参数，检查模型是否能逐步关联对应文档的具体内容，逻辑连贯。
- 模拟大文档比对场景，发起包含多份报告的查询，确认对话未在600秒内中断，且返回结果完整。
