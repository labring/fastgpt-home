# 乳制品加工的技术文档交叉审查：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的核心数据来自奶源检测、MES系统、均质与热处理设备、在线温度与流量监测、CIP系统及LIMS。日常文档涵盖原奶验收记录、标准化配料单、巴氏或UHT杀菌记录、CIP清洗记录、灌装记录、留样与微检报告。数据更新以每奶罐、每批为单位，部分在线监测数据实时同步。文档字段包含原奶抗生素与理化指标、热处理时间温度、清洗参数、灌装参数及微生物检测结果。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据特征对接口调用带来多重约束。数据按单奶罐、单批实时更新，接口需支持按批次维度触发调用，避免跨批次数据混淆。文档关联多系统的结构化字段，接口需支持传递完整的字段参数，确保交叉审查时能匹配全量业务数据。出错后果涉及整罐拒收或大范围召回，接口需内置失败重试与异常上报机制，保障数据传输稳定性。在线监测数据实时同步，接口需适配短间隔批量请求，避免数据积压。同时，多源数据需对齐格式，接口需支持统一的数据解析规则，保障交叉审查的数据源一致性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | 固定前缀加有效API密钥，如`Bearer sk-xxxxxx` | 用于接口身份验证，符合FastGPT的API调用规范 |
| `variables` | 传递单批原奶或灌装任务的唯一标识、数据来源系统标签 | 匹配按批次触发的调用需求，限定审查范围为当前批次文档 |
| `responseData` | 包含审查结果、异常字段标识、批次状态 | 标准化返回交叉审查的核心结果，便于外部系统解析 |
| 超时设置 | 600–1200 秒 | 适配单批文档的交叉审查时长，避免因批处理复杂任务触发超时断开 |
| 重试次数 | 前 3 次 | 应对网络波动或短暂系统异常，保障数据传输成功率 |
| 单次请求数据量 | 1–5 份单罐或单批文档 | 匹配实时更新的批次规模，避免请求过载 |

## 容易做错的三处
- 现象：非流式请求返回Error: write EPROT或请求超过180秒自动断开。原因：未调整接口超时阈值，沿用默认短超时设置，无法适配乳制品单批文档的交叉审查时长。
- 现象：接口调用返回字段为空或数据不完整。原因：未通过`variables`传递正确的批次标识参数，导致审查范围匹配错误，遗漏单罐或单批的核心文档数据。
- 现象：接口调用后未触发异常上报，出现数据传输中断未被感知。原因：未配置接口的异常重试与上报机制，未匹配乳制品加工场景下的高可靠性要求。

## 怎么确认配好了
- 发起单罐原奶验收记录的接口请求，核对`responseData`返回的字段与预设的业务字段一致。
- 模拟长时间批处理请求，验证接口未在预设阈值内自动断开，确认超时设置符合当前场景需求。
- 触发一次异常请求，确认外部系统能接收到对应的异常上报信息，验证重试与上报机制生效。
- 调用接口传递错误的`Authorization`参数，确认返回身份验证失败的提示，验证身份校验配置正确。
