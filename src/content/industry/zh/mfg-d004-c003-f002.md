# 乳制品加工的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
本品类数据覆盖液态奶、酸奶、奶粉及乳配料生产全链路，日常文档包含原奶验收记录、标准化配料单、巴氏/UHT灭菌记录、CIP清洗记录、灌装操作记录、留样与微生物检测报告。数据来源涵盖奶源检测系统、生产执行系统（MES）、均质与热处理设备、在线温流量采集模块、CIP清洗系统、实验室信息管理系统（LIMS）。更新节奏按单奶罐、生产批次实时触发，单份文档包含原奶抗生素与理化指标、热处理参数、清洗验证数据等结构化字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时更新的单罐/单批数据要求索引支持高频增量写入，避免全量重建带来的耗时过长问题。多源异构数据包含设备采集的时序参数、实验室检测的定性定量结果、纸质转电子的历史记录，需要向量模型适配混合字段的语义与数值关联。原奶验收、灭菌验证等核心环节的文档关联度高，索引需支持按生产批次、奶源批次的精准过滤，避免无关数据干扰交叉审查。易腐原料的生产链路无逐批隔离冗余，索引召回的准确性直接关联生产合规性，需严格控制误召回比例。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配原奶验收记录、灭菌记录等典型文档的内容密度，避免拆分破坏字段关联 |
| 重叠长度 | 100–200 字符 | 保留跨分块的语义连续性，适配配料单、灌装记录的长参数序列 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 匹配原奶指标、灭菌参数的语义匹配精度，控制误召回比例 |
| 单次搜索上限 | 前 8 条 | 适配单批生产数据的关联文档数量，避免冗余加载 |
| `defaultToken` | 8192 | 适配实验室检测报告、CIP清洗记录的长文本内容 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 向量数据库选择 | 支持 PostgreSQL、Milvus 等兼容向量检索的数据库 | 适配乳制品加工多源异构数据的存储与检索需求 |

## 容易做错的三处
- 界面显示“503 当前分组 default 下对于模型 text-embedding”报错。原因是向量模型的调用超时或配额耗尽，未针对乳制品加工的高频实时数据调整模型调用重试策略。
- 知识库持续处于索引中状态。原因是未配置增量索引模式，每次数据更新都触发全量重建，未适配单罐/单批的实时更新节奏。
- 检索结果混入无关的食品生产文档。原因是未按生产批次、奶源批次设置索引过滤规则，未绑定乳制品加工专属的数据源标签。

## 怎么确认配好了
- 查看索引日志，确认单批生产数据的增量写入耗时符合实时更新要求。
- 发起原奶抗生素指标的交叉审查检索，核对返回结果仅包含同批次的相关文档。
- 测试长文本的CIP清洗记录检索，确认未出现上下文截断报错。
- 验证向量模型调用的返回结果符合设定的相似度阈值范围。
