# 乳制品加工的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
乳制品加工的典型数据来自奶源检测、MES系统、均质和热处理设备、在线温度流量采集系统、CIP清洗系统、LIMS实验室管理系统。日常文档包含原奶验收记录、标准化配料单、巴氏或UHT热处理记录、CIP清洗记录、灌装记录、留样与微生物检测报告。数据更新频率为每奶罐、每批或实时，核心字段涵盖原奶抗生素与理化指标值、热处理参数、清洗参数等，单位包含℃、秒、CFU/mL等专业计量标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
乳制品加工的技术文档交叉审查需高频处理单批或单罐的实时数据，因此模型调用需适配小批量、低延迟的请求节奏。多源异构的专业文档字段要求模型能准确识别并关联不同系统的参数，因此需配置合理的上下文长度与引用片段长度。同时，乳制品生产的出错后果直接关联产品安全，要求模型输出需严格匹配原始文档的字段与单位，因此需调整模型生成的严谨性参数，且离线部署场景下需避免依赖外部API服务的默认配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖单罐原奶从验收至灌装的全流程文档总token量，保证交叉审查的上下文完整性 |
| `maxTokens` | 2000–3000 token | 满足专业判定的详细输出要求，避免因输出长度不足遗漏关键审查结论 |
| `quoteMaxToken` | 1500–2000 token | 完整引用单条设备记录或检测报告的核心字段，保证审查结论的可追溯性 |
| `temperature` | 0.1–0.3 | 降低模型生成的随机性，保证专业文档审查的严谨性，避免偏离原始数据的判定结果 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写，例如http://127.0.0.1:8080 | 适配离线或在线部署的模型服务地址，确保模型调用链路正确 |
| `AIPROXY_API_TOKEN` | 按平台生成的密钥或自定义密钥填写 | 保证模型接入的安全性，避免未授权的访问请求 |

## 容易做错的三处
- 现象：升级至FastGPT v4.17.0后离线配置重排模型，点击模型测试提示请求错误。原因：未将`AIPROXY_API_ENDPOINT`指向本地重排模型的容器端口地址，或未配置正确的`AIPROXY_API_TOKEN`。
- 现象：配置自定义模型时未关闭one API服务依赖，导致请求被错误路由。原因：默认启用one API服务的配置未调整，直接使用自定义模型接入引发链路冲突。
- 现象：模型返回的交叉审查结果缺失文档字段或专业单位。原因：未设置`temperature`为0.1–0.3的严谨区间，导致模型生成不符合乳制品专业文档规范的内容。

## 怎么确认配好了
- 进入模型配置页面，点击模型测试按钮，查看返回结果是否包含原奶验收记录、热处理参数等乳制品专业文档片段。
- 检查`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置值，确认与部署的模型服务地址、密钥一致。
- 上传单批乳制品的典型文档，运行交叉审查任务，查看返回结果的字段完整性与专业匹配度。
- 查看系统日志，确认模型调用请求无超时或路由错误的记录。
