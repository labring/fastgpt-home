# 仓储、批次与厂内物流的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类的数据通常来自ERP、WMS系统，条码或RFID设备，采购工单、库位管理、AGV输送系统与称重设备。日常文档包含收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录，字段涵盖物料编码、批次号、库位编号、效期、物料数量、关联工单编号等，单位涉及件、千克、立方米等。数据更新节奏包含实时（如扫码入库）、每日（如库存汇总）与月度（如年度效期排查）。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征会对向量模型与索引环节带来多重约束。首先，文档兼具结构化字段（如批次号、库位编号）与半结构化长文本（如盘点差异说明），需适配不同长度的文本处理逻辑。其次，数据更新节奏差异显著，实时扫码入库数据需支持高频增量索引，月度盘点数据则可采用批量索引构建。再者，物料、批次与工单的强关联信息需在检索中优先匹配，避免无关内容干扰交叉审查结果。同时，数据规模随库存周转动态变化，需平衡索引存储开销与检索响应速度，确保批量单据审查时的稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类单据的平均长度，兼顾结构化字段完整性与向量检索精度 |
| 重叠长度 | 100–200 字符 | 避免跨分块的关联信息（如批次号跨两行文本）被截断 |
| `defaultToken` | 512 token | 匹配多数仓储类文档的核心字段长度，降低向量生成的冗余计算 |
| `maxToken` | 4096 token | 支持长文本类盘点表的完整向量生成，覆盖多数业务场景的文本长度 |
| 单次搜索上限 | 前10条 | 平衡检索召回率与审查效率，避免过多无关结果干扰交叉审查 |
| 相似度阈值 | 0.75–0.85 | 针对批次号、库位这类精准匹配字段，过滤低相关性的检索结果 |

## 容易做错的三处
- 现象：短结构化字段（如批次号、库位编号）被分块截断，检索时无法精准匹配对应单据。原因：分块长度设置过小，未兼顾结构化字段的完整性需求。
- 现象：分块后的长文本超出向量模型支持的最大token限制，生成向量时报错或返回空结果。原因：未设置`maxToken`参数适配业务文档的平均长度，强行分块长文本导致格式异常。
- 现象：实时更新的入库数据未同步到索引，交叉审查时出现账实不符的匹配结果。原因：未配置增量索引更新规则，仅依赖全量索引构建流程。

## 怎么确认配好了
- 上传单份典型单据（如领退料单），检查分块后的文本是否保留完整的批次号、工单关联信息，无关键字段截断。
- 模拟实时数据更新，验证索引是否在FastGPT v4.17.0设定的时间窗口内完成增量同步，无明显延迟。
- 输入批次号、库位编号这类精准匹配字段，检查检索结果的相关性是否符合业务预期，可通过调整相似度阈值优化匹配精度。
- 导入批量月度盘点表，验证向量生成与索引构建的耗时是否符合业务审查的时间要求。
