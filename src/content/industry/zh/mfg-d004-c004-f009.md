# 仓储、批次与厂内物流的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据覆盖原材料库、线边库、成品库及物流物控部门的日常业务。日常文档包含收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录。数据来源包括ERP/WMS系统、条码或RFID设备、采购与工单信息、库位档案、AGV或输送系统数据、称重计量数据。数据更新节奏涵盖实时（如AGV调度数据）、每日（如领退料记录）与月度盘点数据，核心字段包含物料编码、批次号、库位编号、效期及对应数量单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据特征对模型接入与配置带来多重约束。多源且更新节奏差异大的数据，要求模型能兼容实时调度数据与静态盘点数据的比对逻辑。多类型的仓储文档，要求模型可适配收货单、批次台账等不同格式的字段提取规则。核心字段如批次号、效期的精准匹配需求，限制了模型的发散性输出参数。现场单据常以图片形式上传，要求模型支持视觉解析能力，以读取条码或手写记录的内容。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写，具体配置项及建议取值如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 仓储交叉审查需比对多份单据的批次、库位信息，需保留足够上下文完成跨文档校验 |
| `maxTokens` | 2000–3000 token | 单份仓储单据的内容长度集中在1000–2000字符，输出校验结果需预留足够token空间 |
| `temperature` | 0.1–0.3 | 交叉审查需严格匹配字段规则，避免生成不符合业务逻辑的校验结论 |
| `vision` | 开启 | 适配现场上传的条码、RFID标签图片格式单据，支持直接解析图片中的关键信息 |
| `AIPROXY_API_ENDPOINT` | 按部署的代理地址填写 | 解决国内大模型的访问限制问题，支持通义千问等国内模型的接入 |
| `AIPROXY_API_TOKEN` | 按代理服务提供的密钥填写 | 完成模型调用的身份验证，确保接口调用权限有效 |

## 容易做错的三处
- 现象：界面模型下拉列表仅显示海外大模型，无法选择通义千问等国内模型。原因：未配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，未通过代理接入国内大模型服务。
- 现象：调用Xinference部署的Qwen模型时返回兼容错误。原因：未正确设置`toolChoice`参数，或未适配模型的函数调用格式，导致模型无法识别交叉审查的指令。
- 现象：上传的仓储单据图片无法被解析，日志显示image_url字段格式异常。原因：未将图片转换为符合要求的base64编码格式，或未正确传递至模型输入参数。

## 怎么确认配好了
- 测试导入一份收货单与对应批次台账，检查模型是否能提取物料编码、批次号、库位号并完成交叉核对。
- 调用配置好的模型接口，查看返回结果是否包含预设的校验字段，无异常报错。
- 切换不同类型的仓储文档（如盘点表、移库单），验证模型是否能适配不同文档的字段结构。
- 查看系统日志，确认模型调用的请求参数与配置项一致，无参数缺失或格式错误。
