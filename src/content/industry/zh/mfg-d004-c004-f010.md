# 仓储、批次与厂内物流的技术文档交叉审查：知识库检索与召回

## 这个品类的数据长什么样
仓储、批次与厂内物流品类的数据来自ERP/WMS系统、条码/RFID设备、采购工单、库位管理、AGV调度系统与称重设备。日常文档包含收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录，字段涵盖物料编码、批次号、库位号、效期、数量（单位为件、托盘或千克）等。数据更新频率分为实时（如AGV调度、称重数据）、每日（如领退料记录）与月度（如盘点表）。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源要求检索需覆盖不同系统的文档格式，兼顾结构化字段与非结构化文本的匹配。不同更新频率的文档需要配置增量同步与全量更新的混合策略，避免检索到过期数据。批次、库位等强关联业务字段要求检索需支持多条件精准匹配，无法仅依赖通用语义检索。跨工序的物料流向管理需要检索能够关联批次台账与物流单据，覆盖完整的业务链路。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配物料编码、批次号等强关联业务字段，过滤低相似度的无关结果 |
| `limit` | 前10条 | 单次召回覆盖工单齐套、账实核对所需的多份单据与台账数据 |
| `searchMode` | 向量+关键词混合检索 | 适配多来源的结构化与非结构化文档，兼顾语义理解与字段精准匹配 |
| `usingReRank` | 开启，重排前5条 | 优先展示效期、库位等核心业务字段的匹配结果，提升业务审查效率 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索范围，覆盖批次台账与物流单据的关联数据 |
| `collectionIds` | 按业务域指定仓储、批次相关知识库ID | 限定检索范围，避免无关文档干扰业务审查 |

## 容易做错的三处
- 检索结果中出现非仓储域的文档，且外部发布渠道无法正常引用结果。原因是未正确指定`collectionIds`参数，或发布渠道的API配置未绑定对应知识库权限。
- 检索返回的结果附带段落ID字段，干扰批次、库位等核心业务信息的展示。原因是未关闭段落ID输出开关，未针对结构化业务文档做字段过滤配置。
- 检索无法覆盖跨工序的物料流向数据，比如未同时召回批次台账与AGV调度记录。原因是未开启`datasetSearchUsingExtensionQuery`，或仅配置纯向量检索模式，未启用关键词匹配。

## 怎么确认配好了
- 手动输入物料编码+批次号的查询词，检查返回结果是否仅包含仓储、批次相关文档，无无关内容。
- 查看检索结果的返回字段，确认未包含段落ID等非业务必要信息。
- 模拟工单齐套场景，输入包含工单编号与物料需求的查询词，检查返回结果的条数是否满足业务核对需求。
- 测试外部渠道调用API，确认返回结果可正常解析并展示。
