# 光伏电池片制造的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
数据主要来自硅片来料台账、车间MES系统、扩散炉/镀膜设备/印刷机的运行日志、EL与IV测试报告、实验室品质分析数据。更新节奏覆盖每生产批次、每片产品检测、每日汇总。日常文档包含工艺卡、扩散与镀膜参数表、印刷烧结作业记录、EL缺陷检测文档、IV性能分档数据、良率分析报告。文档字段包含批次编号、设备运行参数、检测点位坐标、作业时间戳等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类高频次、细粒度的数据更新要求索引支持增量同步，避免全量重建带来的资源消耗与延迟。片级与批次级的多维度文档结构，要求分块策略匹配最小业务单元，确保检索时能精准关联单批次或单产品的工艺信息。多源异构的文档类型与字段，要求索引构建前完成统一的字段映射与格式标准化，防止检索时出现字段不匹配的问题。工艺参数与检测结果的强关联属性，要求向量模型能够捕捉数值型参数与业务场景的语义关联，提升交叉审查的匹配精度。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配单批次工艺文档的平均长度，避免跨批次内容混杂 |
| 重叠长度 | 100–200 字符 | 覆盖工艺参数的跨块关联，防止关键参数被分块截断 |
| `maxToken` | 8192 | 适配主流向量模型的输入上限，避免截断核心工艺信息 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 平衡工艺参数的精确匹配与异常偏差的识别 |
| 单次召回上限 | 前10条 | 覆盖单批次关联的多类文档，避免检索结果过多干扰审查 |
| `defaultToken` | 512 | 作为默认分块的基础长度，适配通用工艺参数类文本的语义提取 |

## 容易做错的三处
- 现象：选择非预设的向量模型时，出现“undefined model must match”类报错。原因：未在系统配置中提前添加对应模型的API密钥与权限，或模型输入格式与系统预设的分块规则不匹配。
- 现象：语义检索分数较高但交叉审查结果出现无关工艺参数。原因：未针对光伏电池片的工艺字段做专属的字段映射，向量模型捕捉到了非核心参数的无关语义关联。
- 现象：单组批次数据生成多组不关联的向量结果。原因：未设置统一的分块长度与重叠规则，或未对多源数据做统一的批次编号字段绑定。

## 怎么确认配好了
- 导入单批次的工艺文档与检测数据，执行检索测试，核对召回结果是否覆盖该批次的核心业务字段。
- 查看向量模型的调用日志，确认所有配置的模型均能正常返回嵌入结果，无异常报错。
- 调整分块相关参数，对比不同配置下的检索匹配结果，确认参数取值符合业务数据的长度特征。
- 测试多组关联数据的检索结果，确认批次编号等关联字段能被正确匹配。
