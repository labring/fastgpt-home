# 光伏电池片制造的技术文档交叉审查：多轮对话与提示词
本配置说明基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据主要来自硅片来料记录、车间MES系统、扩散炉/镀膜设备/印刷机的运行日志、EL与IV测试设备的检测结果，以及实验室存档的工艺数据。数据更新节奏覆盖每生产批次、每片电池片的检测节点，以及每日的汇总统计。日常文档包含工艺卡、扩散与镀膜参数表、印刷烧结操作记录、EL缺陷检测图、IV分档数据表、良率分析报告，字段包含工艺参数数值、设备运行时长、检测区域坐标、电性能指标等，单位涵盖摄氏度、秒、平方毫米等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散、更新节奏密集，且包含多格式的工艺、检测与汇总文档，会对多轮对话与提示词环节带来多重约束。不同批次的生产数据字段格式存在差异，提示词需明确指定字段提取规则与单位对齐要求。片级与批次级数据混合存储，需通过`chatId`与`messages`参数区分对话上下文，避免跨批次数据干扰。非结构化的EL检测图相关描述与半结构化的IV数据需在多轮对话中逐步引导模型对齐文档格式，防止提取结果偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定生产批次唯一标识 | 区分不同生产批次的对话上下文，避免跨批次数据混淆 |
| `messages` | 每15–20轮对话自动截断旧上下文 | 适配该品类高频更新的生产数据，防止上下文溢出 |
| `variables` | 预设生产批次号、检测日期、设备型号变量 | 快速定位对应批次的工艺与检测文档 |
| 最大上下文长度 | 8000–12000 token | 覆盖单批次完整的工艺、检测与汇总文档总量，按实测标定 |
| 上下文保留时长 | 7200 秒 | 匹配每日汇总数据的更新间隔，避免过期数据干扰当前对话 |
| 提示词更新周期 | 每日1次 | 适配每日汇总数据的更新节奏，确保提示词匹配当日文档格式 |

## 容易做错的三处
- 模型输出的Markdown表格无法正常渲染，展示内容被截断。原因是未在提示词中明确指定表格的兼容格式，且未限制单表格的最大字符长度。
- 对话中出现`...[hide 38432 char ｜ insufficient_quota 当前分组上游负载已饱和，请稍后再试`报错。原因是未配置合理的上下文截断规则，导致单次请求的token总量超出负载上限。
- 客户端直接关闭SSE连接后，对应对话记录未存入数据库。原因是未启用`messages`参数的自动落盘配置，仅在请求完整返回后才保存对话数据。

## 怎么确认配好了
- 输入一条包含具体生产批次号的查询，核对对话上下文是否仅关联该批次的文档数据。
- 连续发起多轮对话，验证当对话轮次达到预设阈值后，旧上下文是否被自动截断。
- 发起包含Markdown表格的查询，核对输出格式是否符合预设的兼容规则。
- 模拟客户端断开SSE连接的场景，核对对话记录是否已存入数据库。
