# 光伏组件封装的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类的日常文档包含排版图、材料批次记录、层压工艺记录、EL图、IV测试报告、绝缘耐压记录、包装清单。数据来源涵盖电池片分档、玻璃胶膜背板批次数据、MES系统、串焊与层压设备采集数据、EL/IV测试仪输出数据。数据更新节奏为每块组件、每批材料生成对应记录，文档包含批次号、电流档位、工艺参数、测试数值等字段，部分图文类文档需关联对应批次的文字记录。

## 这些特征在「向量模型与索引」这一环带来什么约束
每块组件、每批材料的高频更新，要求索引支持低延迟写入与查询，保障交叉审查的实时性。多类型文档混合存储，需索引适配文本、测试报告、EL图元数据等不同格式的向量映射逻辑，避免跨类型匹配失效。批次号、组件ID等强关联字段，需建立二级索引实现快速关联召回，支撑同批次材料与组件工艺的交叉校验。单条数据长度跨度大，从数十字符的批次记录到数百字符的工艺参数，需向量模型适配不同输入长度，保障特征提取完整性。

## 配置怎么定
以下配置基于FastGPT v4.17.0的向量模型与索引设置界面制定。若需使用免费的索引模型，可选择开源的向量模型与重排模型进行本地部署。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| maxToken | 8192–16384 token | 光伏组件工艺记录、EL图元数据的文本长度多在数千token区间，适配该范围可完整提取特征 |
| defaultToken | 4096 token | 短文本的批次记录、包装清单无需占用过多token资源，保障基础匹配效率 |
| 分块长度 | 800–1200 字符 | 单块组件的工艺记录、测试报告拆分后可保留完整语义单元，避免跨块信息丢失 |
| 重叠长度 | 100–150 字符 | 避免分块后相邻块的语义断裂，保障跨块关联的向量匹配一致性 |
| 相似度阈值 | 0.72–0.80 | 需区分电池片电流档位的细微差异，过高会漏判有效匹配，过低会引入无效关联 |
| 单次搜索上限 | 前20条 | 同批次材料与组件的关联文档数量通常在10-15条区间，覆盖全量关联数据的同时避免冗余计算 |

## 容易做错的三处
- 现象：向量召回结果中未包含同批次材料的关联记录，返回结果条数远低于预期。原因：未建立批次号字段的二级索引，或向量存储后端未正确配置为目标集群地址，导致索引无法快速定位同批次关联数据。
- 现象：界面返回`413 Request Entity Too Large`报错。原因：未设置合理的`maxToken`参数，输入的EL图元数据或长文本工艺记录超出模型允许的最大token限制。
- 现象：交叉审查匹配出大量无关的电池片分档记录，误判率偏高。原因：未接入私有化重排模型，或相似度阈值设置过低，将不满足工艺匹配要求的弱关联结果纳入审查范围。

## 怎么确认配好了
- 上传单条组件的全量关联文档，执行交叉审查查询，核对返回结果是否包含该组件对应的所有批次材料记录与工艺参数。
- 查看向量模型的调用日志，确认输入文本的token数未超出设置的`maxToken`范围，无截断报错。
- 调整相似度阈值，对比不同阈值下的召回结果数量，确认阈值区间符合当前业务的匹配精度要求。
- 检查向量存储后端的连接状态，确认迁移自PGSQL的配置已正确更新为目标集群地址。
- 调用重排模型接口，核对返回的排序结果是否符合光伏组件工艺匹配的优先级要求。
