# 光伏组件封装的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
光伏组件封装环节的数据覆盖串焊、层压、装框、测试部门的多类文档，包括排版图、材料批次记录、层压工艺记录、EL图、IV测试报告、绝缘耐压记录、包装清单。数据来源包含电池片分档数据、玻璃胶膜背板批次信息、工厂MES系统、串焊与层压设备日志、EL/IV测试仪输出结果。数据更新频率为每块组件生成一套专属文档，每批材料同步更新批次维度记录，字段包含专业参数如电流档位、功率值、隐裂坐标，单位涵盖瓦、伏特、毫米等。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源分散在多套系统与设备中，要求工作流支持跨数据源的批量拉取与整合。实时更新的特性要求工作流需适配触发式执行，以匹配每块组件、每批材料的即时更新节奏。多类型文档的存在要求工作流配置适配不同格式的解析规则，兼顾图表与文本内容的提取。专业字段与单位的要求则需要工作流内置对应参数的提取规则，避免不同批次、不同组件的数据混淆。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工作流编排规则制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源关联配置 | 绑定MES系统、EL测试仪、层压设备的API接口 | 匹配该品类分散的多源数据来源 |
| 变量提取规则 | 提取`variables`中的批次号、功率值、隐裂坐标字段 | 适配光伏组件封装的专业数据字段与业务需求 |
| 节点触发条件 | 按设备上报数据的时间戳触发 | 匹配每块组件、每批材料的实时更新频率 |
| 异常重试次数 | 3次，间隔60秒 | 应对设备上报的临时网络波动与数据延迟 |
| 上下文窗口大小 | 800–1200字符 | 适配单块组件对应文档的平均数据长度 |
| 节点ID配置 | 按`nodeId`标记串焊、层压、测试等业务环节 | 明确工作流各节点的业务归属 |

## 容易做错的三处
- 工作流运行时弹出未捕获的异常，日志提示配置文件不正确。原因是私有部署时未正确配置数据源的API密钥与访问权限。
- 工作流节点无法选择预设的专业AI模型，仅显示简易模型选项。原因是未在配置中开启对应业务场景的模型调用权限，导致模型选项未加载。
- 工作流执行超时，返回请求超时状态码。原因是未设置合理的重试间隔与次数，导致设备上报数据延迟时未触发自动重试。

## 怎么确认配好了
- 手动触发一条串焊环节的测试数据，检查工作流是否自动拉取对应批次的材料记录与EL图。
- 查看工作流的节点日志，确认`variables`中提取的电池片电流档位、功率值等字段完整且符合预设单位要求。
- 模拟设备上报的临时网络波动，检查工作流是否按配置的重试规则自动发起重试。
- 检查各环节的`nodeId`标记是否与串焊、层压、测试等部门的业务节点一一对应。
