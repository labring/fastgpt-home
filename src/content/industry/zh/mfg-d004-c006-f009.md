# 光伏组件封装的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
光伏组件封装场景下，数据来自电池片分档系统、玻璃胶膜背板批次台账、车间MES系统、串焊与层压设备终端、EL缺陷检测仪及IV功率测试仪。日常产生的文档包含排版图、材料批次记录、层压工艺参数记录、EL缺陷图像、IV测试报告、绝缘耐压检测记录、成品包装清单。数据更新节奏为每一块组件对应一套检测记录，每一批次原材料同步生成批次台账，单份文档字段包含材料规格、设备参数、检测数值、批次编号等，格式随生产环节差异有所不同。

## 这些特征在「模型接入与配置」这一环带来什么约束
该场景的数据来源分散且格式差异大，包含多模态的图像与结构化报表，要求模型接入配置支持多模态输入能力。单份文档对应单块组件，数据更新频率高，需配置适配短周期批量文档处理的上下文参数。同时，核心校验环节聚焦电池片电流档位匹配、层压工艺合规性，模型需精准关联材料批次与设备参数，因此配置需强化上下文关联的参数设置，避免跨批次数据混淆。另外，封装环节的出错后果直接影响产品长期可靠性，需配置平衡准确性与灵活性的参数，保障审查结果的严谨性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 该场景需处理EL缺陷图像、IV测试报告等多模态文档，需模型具备图像识别能力 |
| `temperature` | 0.2–0.4 | 需精准匹配电池片档位、层压工艺参数等标准化内容，避免输出过度发散 |
| `maxContext` | 8000–12000 token | 单份组件关联的材料批次、设备记录、检测报告总长度适配该上下文区间 |
| `maxTokens` | 2000–3000 token | 单轮技术文档交叉审查的输出内容长度需求 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的地址填写 | 对接第三方模型的接入地址要求 |
| `AIPROXY_API_TOKEN` | 按部署分配的密钥填写 | 对接第三方模型的身份验证要求 |

## 容易做错的三处
- 界面加载模型厂商图标失败：未在FastGPT v4.17.0版本中配置模型厂商的静态资源路径，导致图标资源无法正常拉取。
- 大模型节点返回500 Gateway forwarding error：模型服务未正常启动或与FastGPT的连接中断，未配置健康检查机制导致请求转发失败。
- 使用SSE协议封装的自定义模型无法被识别：未按照FastGPT要求的协议格式配置模型接入，误将SSE模式绑定到不支持的节点类型，导致协议校验不通过。

## 怎么确认配好了
- 检查多模态输入测试：上传单份EL图与对应IV测试报告，验证模型能否正确识别图像内容并关联结构化数据。
- 验证模型响应稳定性：连续发起批量文档审查请求，确认无重复报错或响应中断。
- 核对接口密钥配置：对比部署文档与当前配置的`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`，确保参数匹配。
- 调整参数后复测：修改`temperature`或`maxContext`参数，验证审查结果的一致性与准确性是否符合预期。
