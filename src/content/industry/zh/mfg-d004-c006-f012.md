# 光伏组件封装的技术文档交叉审查：部署与升级

## 这个品类的数据长什么样
光伏组件封装场景的业务数据来自电池片分档系统、玻璃胶膜背板批次台账、MES生产系统、串焊与层压设备、EL/IV测试仪等多类数据源。日常需处理的文档包含排版图、材料批次记录、层压工艺记录、EL图、IV测试报告、绝缘耐压记录、包装清单。数据更新频率为每块组件、每批材料生成对应记录，单份文档包含材料批次号、电流档位、层压参数、测试结果等结构化与非结构化字段。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构数据的同步需求要求部署环节支持对接多类数据源接口，需适配不同格式的文档上传与解析。高频次的单组件级数据更新，要求升级环节保证服务无间断或快速切换，避免影响生产流程中的实时审查。多部门并发访问的场景，要求配置项支持调整并发连接上限。文档类型覆盖图形与结构化表格，要求部署时适配不同文件的解析规则。同时，出错后果直接关联产品功率与客户索赔，要求升级后的审查逻辑需经过验证后再全量部署。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://fastgpt:securepass@10.0.0.5:5432/pv_doc_review` | 光伏组件封装的批次记录、测试报告为结构化数据，PG适合稳定存储与查询 |
| `REDIS_URL` | `redis://:redispass@10.0.0.6:6379/1` | 缓存实时更新的组件数据与会话信息，适配高频访问场景 |
| `FILE_TOKEN_KEY` | `32位随机十六进制字符串` | 保护文档上传与鉴权，防止未授权访问生产文档 |
| `DB_MAX_LINK` | `20–30` | 适配串焊、层压、测试等多部门的并发访问需求 |
| `FE_DOMAIN` | `https://pv-doc-review.manufacturing.example.com` | 绑定专属部署域名，区分其他场景的FastGPT服务 |
| `ROOT_KEY` | `64位随机安全密钥` | 管理系统的最高权限鉴权，保障配置修改的安全性 |

## 容易做错的三处
- 现象：开源版本部署后无法启用身份鉴权功能，原因：未正确配置`FILE_TOKEN_KEY`或`ROOT_KEY`参数，未开启对应鉴权开关。
- 现象：升级FastGPT后，工作流AI对话无法获取代码运行输出的文档内容，原因：未同步更新`PG_URL`指向的向量数据库索引，或未适配新的文档存储路径规则。
- 现象：Docker部署过程中无法拉取fastgpt-sandbox镜像，原因：未配置正确的镜像仓库地址，或未开通镜像拉取的网络权限。

## 怎么确认配好了
- 执行`curl ${FE_DOMAIN}/api/health`，返回200状态码则基础服务正常。
- 上传一份光伏组件的EL图测试文件，检查鉴权流程通过且文件能正常解析。
- 查看`PG_URL`对应的数据库，确认批次记录与测试数据已按预设规则同步写入。
- 触发一次文档交叉审查任务，核对返回结果的匹配逻辑符合预设的校验规则。
