# 冲压与板材成形的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自汽车覆盖件、家电钣金、五金件冲压车间，涵盖冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录等文档。数据来源包括钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、MES系统、三坐标及检具检测数据。数据更新节奏随卷料批次、生产批次及换模操作触发，单次更新包含单批次生产关联的全部文档及设备采集字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据更新频率随生产批次动态触发，要求索引支持增量更新，避免全量重建占用过多计算资源。多源异构数据包含文本、数值、设备日志等不同格式，需要统一的向量嵌入适配逻辑，需合理配置`defaultToken`与`maxToken`以适配多类型字段的嵌入需求，确保不同类型字段的语义关联被正确捕捉。单批次数据量随换模操作波动，索引分片需支持动态扩容，避免峰值时段检索延迟。同时，文档间存在强关联（如换模记录对应模具点检表），交叉审查需要保留文档间的关联索引，独立分块存储会破坏关联语义。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的功能逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配冲压作业指导书单段操作描述的长度，避免跨工序语义断裂 |
| 重叠长度 | 150–200 字符 | 覆盖换模记录与后续首末件记录的关联字段，防止跨块语义丢失 |
| 相似度阈值 | 0.75–0.85 | 过滤重复的模具点检表条目，同时保留不同批次材料利用率表的合理差异 |
| 单次搜索上限 | 前 10 条 | 适配冲压车间单批次生产的关联文档数量，避免检索结果冗余 |
| `defaultToken` | 2048 | 适配尺寸检验报告的数值与描述字段的嵌入长度需求 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 现象：知识库索引合并后出现重复文档块，且自定义切分的文档顺序丢失。原因：未配置按文档ID关联的去重规则，仅按文本相似度去重导致同批次不同文档的相似字段被误删。
- 现象：调用向量模型时返回401状态码。原因：未在FastGPT配置中正确绑定向量模型的API密钥，或密钥权限未覆盖embedding接口。
- 现象：自定义添加的向量模型请求被识别为LLM调用。原因：未在渠道配置中明确标记该渠道为向量模型专用，导致请求被路由到LLM服务。

## 怎么确认配好了
- 上传单批次冲压生产的关联文档，检查索引分块的长度是否符合预设范围，无异常截断。
- 提交重复内容的模具点检表，验证索引去重后保留的文档块数量与预期一致。
- 调用向量嵌入接口，确认返回的embedding结果无空字段或格式错误。
- 配置交叉审查的检索任务，检查检索结果的排序与文档关联度匹配。
