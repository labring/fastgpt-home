# 冲压与板材成形的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
本品类数据来自钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、MES系统、三坐标或检具检测数据。日常文档包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录。数据更新随每卷料、每批生产或每次换模触发，文档字段包含钢卷牌号、板材厚度、模具编号、拉延筋参数、尺寸偏差值等，单位涵盖毫米、牛顿、平方米等。

## 这些特征在「工作流编排」这一环带来什么约束
每卷料、每批、每次换模的高频更新要求工作流需支持实时触发与上下文变量同步。多源异构数据的接入需适配不同文档格式与字段结构，避免跨数据源的字段不匹配。冲压与板材成形的文档关联逻辑需严格绑定模具、材料批次与生产批次，工作流节点需按生产环节顺序串联，确保交叉审查时能匹配对应批次的所有文档。出错后果关联批量生产损失，工作流需设置明确的失败分支与校验节点，拦截异常数据进入后续环节。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工作流逻辑制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` 动态绑定 | 绑定当前生产批次、钢卷号、模具编号 | 本品类数据随每卷料、每次换模更新，需动态关联生产上下文 |
| 工具调用模型选择 | 使用支持多意图识别的大模型 | 需识别不同文档的关联关系与异常参数 |
| 表单输入配置 | 设置生产批次、钢卷号为必填项，格式限定为8位字母数字组合 | 本品类文档需绑定对应生产批次与材料批次，避免关联错误 |
| 失败分支阈值 | 超时阈值设为600秒，字段为空时触发告警 | 高频更新的数据若超时或缺失会引发批量生产风险 |
| `nodeId` 节点流转 | 按`nodeId`顺序串联模具点检、材料校验、尺寸检验节点 | 冲压生产需按换模、材料验收、首件检验的顺序执行交叉审查 |
| 上下文长度配置 | 限定为800–1200字符 | 本品类文档多为参数类内容，过长上下文会干扰异常识别 |

## 容易做错的三处
- 现象：工作流中配置的表单输入字段在对话界面无交互内容显示。原因：未将表单输入节点的输出绑定至AI对话节点的上下文变量，导致交互时无法加载配置项。
- 现象：`variables`参数仅支持写入固定值，无法随生产批次或换模时间动态更新。原因：未配置变量的动态绑定规则，未关联对应生产系统的实时数据推送。
- 现象：高级编排的工具调用节点无法自动选择后续要执行的工具。原因：未配置工具调用的意图识别规则，或未选择适配多意图判断的模型。

## 怎么确认配好了
- 触发一次模拟换模或生产批次更新，检查`variables`参数是否同步更新为对应批次的编号。
- 运行工作流并传入超出合理范围的参数，检查是否触发预设的失败分支与告警。
- 打开对话界面，确认表单输入字段可正常显示并接收输入内容。
- 调整节点流转顺序，验证工作流是否按`nodeId`配置的顺序执行各环节。
