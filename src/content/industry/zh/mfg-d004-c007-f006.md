# 冲压与板材成形的技术文档交叉审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来自钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、MES系统、三坐标或检具检验报告。日常文档包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录。数据更新随每卷料、每批生产任务、每次换模操作触发，文档字段包含钢卷牌号、板材厚度、模具编号、检验尺寸偏差值等，对应单位为毫米、牛、吨等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源且高频更新的数据要求溯源时精准匹配生产批次与换模节点，避免跨批次数据混淆。文档类型涵盖长文本作业指导书与结构化表格，要求分块逻辑适配不同格式的内容完整性。字段包含特定专业单位，需在溯源时关联对应字段的精确值以保证审查准确性。单次生产相关的文档数量较多，需控制召回范围以避免冗余信息干扰交叉审查的效率与精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配冲压作业指导书的工序段落与结构化表格切片，避免拆分跨换模的完整说明 |
| `quoteMaxToken` | 1500–2000 token | 保留材料利用率表、尺寸检验报告的完整字段内容，避免截断关键生产数据 |
| 引用返回开关 | 开启 | 对应`responseData`参数配置，确保返回结果包含引用片段的原文档信息 |
| 详情展示 | 开启 | 对应`detail`参数，展示原文档的路径与切片前的上下文内容 |
| 单次召回上限 | 前6条 | 匹配单批次冲压相关的多类文档，避免引入无关的历史换模记录 |

## 容易做错的三处
- 调用API发布的终端回复无引用片段：原因是未开启引用返回开关或未正确配置`responseData`参数，导致未返回引用元数据。
- 无法查看引用片段对应的原文件在线预览：原因是分块时未保留原文档的路径元数据，或切片逻辑未关联导入前的原始文件。
- 召回的引用片段与当前审查问题不匹配：原因是分块长度过长，导致切片包含无关的其他批次生产数据，或单次召回上限设置过高引入冗余内容。

## 怎么确认配好了
- 上传一份冲压作业指导书与材料利用率表，发起包含具体生产批次的测试提问，检查返回结果中是否包含引用片段的原文档名称与路径。
- 调用FastGPT v4.17.0对应的API接口，验证返回字段中是否包含`detail`与`responseData`相关的内容。
- 导入一份包含单条换模记录的文档，调整分块长度后，查看知识库分块预览，确认切片未拆分该换模记录的完整内容。
- 在知识库管理界面开启引用展示开关后，发起测试问答，确认终端回复中显示了引用来源的详细信息。
