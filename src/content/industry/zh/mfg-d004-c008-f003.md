# 化妆品生产的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自注册或备案配方、原料安全资料、称量与乳化设备日志、ERP/MES系统、实验室检验记录及包材版本文件。数据更新随每批生产、每次换线完成。日常文档包含配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验报告、标签审核表。核心字段包括原料INCI名称、投料重量、生产批次、乳化温度、均质时长、包材型号，无额外百分比类统计数据。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类数据随每批生产实时更新，且覆盖多类分散文档，要求多轮对话可动态调取对应批次的备案配方、设备日志等最新数据，避免使用静态知识库内容。多类文档的字段存在差异，需通过提示词引导AI整合不同来源的信息，例如关联投料记录的重量与备案配方的允许用量。生产合规要求严格，出错后可能引发下架召回，多轮对话需逐步验证原料合规性、生产参数匹配度及标签宣称一致性，同时无需涉及药品类治疗相关验证逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工作流节点设置。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 传入当前生产批次号、车间ID、操作人员ID | 适配每批生产的动态数据调取需求，确保对话关联对应批次的备案与生产记录 |
| `chatId` | 绑定当前生产工单ID | 实现对话日志与工单的关联，便于后续追溯审查过程 |
| `messages` | 按文档类型分组拼接历史对话与当前请求 | 确保多轮对话的上下文连贯，便于AI逐步完成交叉审查 |
| 单次对话最大token数 | 8000–12000 token | 覆盖多类文档的字段整合与合规校验所需的信息长度，按实测标定 |
| 对话超时设置 | 600秒 | 匹配生产环节的平均审查时长，避免因等待过长影响工单进度 |
| 最大重试次数 | 3次 | 应对单次校验中出现的字段不匹配或数据缺失问题 |

## 容易做错的三处
- 现象：批量执行多轮对话时，部分节点返回的校验结果与目标生产批次不匹配。原因：未为每个执行节点分配独立的`chatId`，导致不同工单的对话上下文互相干扰。
- 现象：对话日志中无法关联到具体生产工单或操作人员。原因：未将`variables`中的工单ID、操作人员信息传入对话节点，日志仅记录通用对话内容。
- 现象：AI无法识别上传的jpg格式包材设计图。原因：未在对话节点前接入支持图片解析的工具节点，仅传入了文本格式的审核参数，导致图片信息未被读取。

## 怎么确认配好了
- 发起一次测试工单的审查对话，检查对话日志中是否包含当前测试工单的相关标识，确认`chatId`绑定逻辑生效。
- 上传对应批次的备案配方与投料记录，发起多轮校验，检查AI是否能自动关联两类文档的字段，确认`variables`动态参数生效。
- 上传jpg格式的包材设计图，检查对话节点是否能正确解析图片内容并纳入校验范围，确认图片工具节点配置正确。
- 触发批量执行任务，检查每个子节点的对话日志是否独立，无上下文混淆情况，确认`chatId`分配逻辑正确。
