# 化学药制剂生产的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据来自经批准处方工艺、MES电子批记录、LIMS、质量管理系统等系统。更新节奏为每生产批次、每个关键工艺步骤、按环境与设备监测计划执行。日常文档包含主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差CAPA变更、批放行审核表，字段涵盖物料批次标识、工艺执行参数值、偏差描述、检验结果数值，单位涉及质量单位、温度、时间区间等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据分散于多个系统且更新频率高，多轮对话需限定上下文范围，避免加载过期批次的冗余数据。文档结构包含多类合规性文件，提示词需明确指定需审查的文档类型与对应字段，确保检索范围精准。每批次的审查需关联物料、工艺、检验等多维度数据，多轮对话需支持按批次ID关联上下文，避免跨批次数据混淆。同时，合规要求下的审查需完整记录每一轮交互的依据，提示词需引导输出可追溯的审查节点。

## 配置怎么定
本配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话上下文窗口 | 前 10 条交互记录 | 避免加载过多过期批次的冗余数据，适配单批次审查场景 |
| `variables` 绑定 | 绑定批次ID、文档类型变量 | 按生产批次关联对应数据，避免跨批次数据混淆 |
| `chatId` 关联 | 绑定生产批次的唯一标识 | 确保同批次审查的对话历史统一，满足合规追溯要求 |
| 检索范围限定 | 限定当前批次的800-1200字符的文档片段 | 缩小检索范围，提升审查精准度，适配单批次文档长度 |
| 交互超时时间 | 600 秒 | 适配复杂文档交叉审查所需的思考时长 |

## 容易做错的三处
- 配置对话开场白快捷按键时，未绑定对应审查场景的预设提示词。原因是未将快捷按键与`variables`绑定的批次变量关联，导致触发时无法加载对应批次的文档上下文。
- 无登录状态下查看对话历史时，关联的文档截图无法加载。原因是未配置`chatId`与批次ID的绑定逻辑，导致上下文无法匹配对应批次的存储数据。
- 在工作流中调用其他应用或插件时，对话日志未被记录。原因是未开启`messages`的日志同步配置，导致交互记录未被归档。

## 怎么确认配好了
- 输入测试批次ID，检查对话上下文是否仅关联该批次的文档。
- 触发嵌套应用场景，确认表单输入节点的对话框是否按配置隐藏。
- 调用关联插件，检查对话日志是否被同步记录。
- 查看配置项的取值是否符合预设的合规审查要求。
