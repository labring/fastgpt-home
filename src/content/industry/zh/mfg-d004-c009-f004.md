# 化学药制剂生产的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
化学药制剂生产的技术文档包括主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差/CAPA/变更、批放行审核表。数据来源涵盖经批准处方工艺、物料批次、MES/电子批记录、设备与环境监测、LIMS、质量管理系统。数据更新节奏为每批生产、每个关键工艺步骤、按固定监测计划执行。文档字段包含物料批号、工艺参数值、检验结果、偏差描述等，对应单位涵盖千克、摄氏度、小时等。

## 这些特征在「工作流编排」这一环带来什么约束
数据按单批次更新，要求工作流需绑定唯一批次标识触发，避免跨批次数据混淆。文档类型多且字段存在明确合规要求，工作流需配置变量匹配不同文档的专属字段，确保审查内容精准对应。审查环节耗时占比高且出错后果严重，工作流需设置失败回退、告警节点，同时需限制单次检索的文档数量，避免处理超时。GMP合规要求下，工作流需完整记录每一步审查动作，不可跳过关键环节。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发条件 | 按批次编号触发 | 匹配数据按每批更新的节奏，确保审查范围对应单批次生产流程 |
| variables | 绑定物料批号、工艺参数、检验结果字段 | 依据文档包含的专属字段结构，实现精准的数据匹配与检索 |
| 单次搜索上限 | 前6条 | 覆盖核心审查文档的数量，避免检索资源浪费 |
| 最大上下文 | 8000 token | 按实测标定，适配长文档的完整审查需求 |
| 超时等待时间 | 300 秒 | 依据文档审查的常规耗时，避免单次异常导致流程中断 |
| nodeId | 绑定批放行审核表节点 | 匹配审查流程的收尾环节，完成最终合规校验 |

## 容易做错的三处
- 现象：工作流分支无法跳转至指定表单节点，配置后无响应。原因：未正确配置`nodeId`指向目标节点的唯一标识，导致分支跳转逻辑失效。
- 现象：调用工作流返回空值，知识库检索无结果。原因：未在`variables`中绑定批记录的核心查询参数，导致检索范围缺失。
- 现象：执行时提示quote type error。原因：未按文档字段格式传入变量，导致变量引用类型不匹配。

## 怎么确认配好了
- 触发一次模拟批次的工作流，检查`variables`是否正确加载对应批次的物料、工艺数据。
- 查看工作流运行日志，确认分支跳转时`nodeId`匹配目标节点。
- 验证检索结果是否覆盖批生产记录、检验记录等核心审查文档。
- 触发异常场景测试，确认失败处理节点正常触发告警或回退流程。
