# 医疗器械装配与洁净生产的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自设计历史文件、器件与材料批次记录、MES系统、洁净环境监测设备、灭菌设备、检验校准系统。日常文档包含生产工艺规程、批生产记录、洁净区记录、灭菌批记录、检验报告、软件版本记录、不良事件与追溯资料。数据更新以每批或每台产品为周期，同时按洁净环境监测计划同步更新。文档包含受控装配要求、材料唯一标识、灭菌参数、洁净环境监测数据等字段，部分记录需关联批次与设备编号。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据分散于多系统，包含结构化批次记录与非结构化工艺文档，要求索引同时支持结构化元数据与非结构化文本的向量关联。数据按批次或监测计划高频更新，需适配增量索引逻辑以避免全量重建耗时过长。文档需关联唯一器械标识、灭菌参数等特定字段，向量检索需保留元数据用于精准回溯。部分记录涉及受控合规内容，索引需支持按文档类型与批次范围过滤检索结果。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类工艺规程、批记录的单段合规文本长度，避免块内关联信息被割裂 |
| 重叠长度 | 120 字符 | 保留批次唯一标识、灭菌参数等跨块关联的关键字段，防止检索时丢失跨批次关联信息 |
| 相似度阈值 | 0.78–0.82 | 匹配本品类合规审查的严格标准，过滤低相关性的非受控文档与无效记录 |
| 单次搜索上限 | 前 8 条 | 控制召回结果数量，适配批次关联检索的精准性需求，避免冗余结果干扰合规审查 |
| `maxToken` | 3500 token | 适配本品类文档的关联信息总长度，支持完整展示工艺要求与对应检验记录的关联内容 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 现象：Embedding模型调用OneAPI时返回连接超时或404报错。原因：未适配本品类文档的字段格式，导致OneAPI校验不通过，或配置的模型名称与OneAPI挂载的模型不匹配。
- 现象：开启重排配置后，在线召回测试返回的结果未按重排排序。原因：未在索引构建阶段同步启用重排关联设置，或重排模型的调用参数未匹配本品类文档的长度要求。
- 现象：选择开源索引模型后，检索速度无法满足批次化审查的实时需求。原因：未根据本品类数据的更新频率调整索引的增量刷新周期，导致全量索引重建占用过多系统资源。

## 怎么确认配好了
- 执行单批次文档的索引构建，查看索引日志中是否包含该批次的唯一标识与关联元数据。
- 发起针对特定灭菌参数的检索请求，验证召回结果是否包含对应批次的灭菌批记录。
- 触发增量索引更新，检查系统是否仅同步更新新增的批记录与环境监测数据，不执行全量重建。
- 调用Embedding模型接口，验证返回的向量数据格式是否与系统预设的向量维度匹配。
