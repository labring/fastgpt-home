# 医疗器械装配与洁净生产的技术文档交叉审查：工具调用与插件

本配置基于 FastGPT v4.17.0 版本制定

## 这个品类的数据长什么样
本品类数据来源为设计历史文件、器件与材料批次台账、生产执行系统（MES）、洁净环境监测设备、灭菌设备、检验校准系统。数据更新节奏为每生产批次或单台设备完成时同步，洁净环境监测数据按既定计划定期更新。日常文档包含生产工艺规程、批生产记录、洁净区运行记录、灭菌批记录、检验报告、软件版本日志、不良事件与追溯档案，字段包含唯一器械标识、材料批次号、洁净环境参数、灭菌参数、检验结果、软件版本号等。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类数据来源分散且覆盖多类生产与质量系统，工具调用需支持对接多数据源接口以同步不同类型文档。数据按生产批次或定期更新，工具需支持按批次号、时间范围筛选检索结果，避免引入过期或不匹配的生产数据。文档字段包含专用医疗器械标识与洁净环境参数，工具调用需能识别并校验这些专属字段格式，确保检索结果与审查需求匹配。涉及追溯与合规审查，工具返回的结果需附带关联的批次、灭菌参数等核心字段，支撑交叉校验逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配本品类多类型文档的自动工具选择，覆盖生产工艺规程、洁净区记录等不同数据源 |
| 单次搜索上限 | 前10条 | 匹配单批次生产文档的核心检索量，避免冗余数据干扰交叉审查 |
| 最大上下文 | 8000 token | 适配单批次文档的总字符规模，满足完整工艺与批记录的检索需求 |
| 单次检索数据量 | 1000 MB | 适配单批次文档的存储规模，避免超出系统内存限制 |
| `functionCall` | 开启强制校验 | 确保工具调用返回结果包含唯一器械标识、灭菌参数等必填合规字段 |
| 超时阈值 | 600 秒 | 覆盖多数据源同步与复杂文档解析的耗时，避免审查流程中途中断 |

## 容易做错的三处
- 现象：工具调用返回的结果缺少唯一器械标识、灭菌参数等必填字段，返回数据无法支撑追溯审查。原因：未开启`functionCall`强制校验，未指定检索所需的字段规则，导致返回结果不符合合规审查要求。
- 现象：自行搭建的前端对接页面样式异常，无法匹配平台原生交互逻辑。原因：未使用官方推荐的嵌入方案，直接调用接口未适配平台的交互规范。
- 现象：调用接口时返回401未授权错误。原因：未正确配置验证token的调用规则，token格式或有效期设置不符合平台要求。

## 怎么确认配好了
- 手动发起一次针对指定生产批次的工具调用，核对返回结果是否包含预设的必填字段。
- 查看工具调用的运行日志，确认超时阈值设置匹配当前对接数据源的响应时长，无频繁超时记录。
- 对比检索结果与实际生产批次的文档内容，确认仅返回当前批次范围内的数据，无过期历史内容。
- 调整`toolChoice`参数值，验证自动工具选择功能是否能覆盖生产工艺规程、洁净区记录等不同类型的文档，无调用失败提示。
