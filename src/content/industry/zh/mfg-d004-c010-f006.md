# 医疗器械装配与洁净生产的技术文档交叉审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来源包括设计历史文件、器件与材料批次记录、MES系统、洁净环境监测设备、灭菌设备及检验校准系统。日常文档涵盖生产工艺规程、批生产记录、洁净区环境记录、灭菌批记录、检验报告、软件版本记录与不良事件追溯资料。数据更新按每批产品或每台设备执行，洁净环境监测按固定计划更新。文档字段包含唯一器械标识、材料批次号、灭菌温度与时长、洁净区温湿度、软件版本号等，部分字段需匹配医疗器械注册要求的可追溯格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据分散于多类系统与文档，引用溯源需跨设计、生产、检验等多数据源关联。按批次或固定计划的高频更新，要求引用时精准匹配批次号、唯一器械标识等核心字段。文档需满足医疗器械追溯的合规要求，引用内容必须可直接对应到具体生产批或环境监测节点。字段单位与格式需严格匹配注册资料，引用过程中需校验字段一致性，避免出现跨批次不兼容的引用内容。同时，一旦溯源出错可能引发产品召回或患者伤害，需确保引用来源的精准性与可追溯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.7–0.9 | 匹配医疗器械专业文档的术语密度，过滤与当前装配审查无关的通用文档 |
| `quoteMaxToken` | 800–1200 token | 覆盖单份批生产记录或灭菌批记录的核心追溯字段，避免截断关键批次信息 |
| 单次搜索上限 | 前6条 | 匹配单批次生产涉及的工艺、检验、灭菌等多类文档数量，确保覆盖全环节数据 |
| `responseData` | 开启 | 仅返回与当前审查任务直接相关的数据源内容，过滤冗余的历史批次数据 |
| 上下文缓存时长 | 24–48 小时 | 匹配该品类按批次更新的数据周期，避免加载过期的环境监测或灭菌记录 |
| 重排 | 开启 | 优先排序与当前技术审查任务直接相关的文档 |
| 引用来源展示 | 开启 | 按FastGPT v4.17.0版本的标准格式展示来源文档的唯一标识与批次信息 |
| `detail` | 开启 | 展示引用文档的完整字段细节，便于核对追溯信息 |

## 容易做错的三处
- 现象：设置相似度阈值为1后，仍出现大量非关联的洁净区记录或灭菌记录。原因：未结合医疗器械文档的专业术语权重调整阈值，单纯的字面匹配无法区分同批次与跨批次的文档内容。
- 现象：引用来源中缺少关键的唯一器械标识字段。原因：`quoteMaxToken`取值过小，截断了包含标识的文档尾部内容，导致溯源字段丢失。
- 现象：无法关联到Notion格式的灭菌设备校准记录。原因：未配置知识库支持外部非标准网页类文档的链接同步，仅支持预设的本地文档或通用网页链接。

## 怎么确认配好了
- 手动输入单批次生产的审查问题，核对返回结果中引用的文档是否匹配当前任务的批次范围，调整相似度阈值以控制关联度。
- 查看引用来源的展示内容，确认包含唯一器械标识、批次号等核心追溯字段，调整`quoteMaxToken`以确保字段完整显示。
- 导入多类同批次的文档，验证单次搜索上限可覆盖所需的文档数量，避免遗漏关键数据。
- 测试引用溯源路径，确认可通过展示的来源信息直接定位到对应生产批或环境监测节点。
