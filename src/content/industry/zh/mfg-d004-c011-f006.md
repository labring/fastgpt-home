# 半导体封装测试的技术文档交叉审查：引用来源与溯源

## 这个品类的数据长什么样
半导体封装测试的技术文档包含封装流程卡、键合与塑封参数、晶圆来料图、测试程序版本、良率报告、失效分析报告。数据来源覆盖晶圆测试图、MES系统、键合与塑封设备、ATE测试机、X-ray/SAM检测设备及客户规格要求。数据更新随生产批次、单颗芯片测试及每日运维同步，文档字段包含批次标识、工艺参数、测试结果、设备编号等，需匹配对应设备或系统的原始字段格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
半导体封装测试的多源异构数据特征，要求引用溯源需精准绑定生产批次、设备编号与晶圆标识，避免跨批次混淆。高频更新的单颗测试数据与每日运维日志，要求溯源逻辑需支持按生产节点快速定位最新关联文档。不同类型文档的字段差异，比如封装参数表的数值型字段与失效分析报告的文本描述，要求溯源时需匹配对应文档的专属标识字段。同时，该环节需对齐晶圆图与实物批次的关联关系，为后续失效分析提供可追溯的原始数据链路。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | 封装测试文档包含长参数表与失效分析报告，需完整保留引用内容 |
| `responseData` | 返回原始来源ID与批次号 | 需绑定生产批次与设备编号，满足溯源核心需求 |
| `detail` | 开启 | 需展示引用文档的具体字段，如ATE测试bin码、塑封温度参数 |
| 单次搜索上限 | 前6条 | 每批生产的关联文档数量有限，避免冗余引用干扰结果 |
| 上下文窗口 | `1500–2000 字符` | 需整合晶圆来料图与测试程序的关联信息，保证上下文逻辑完整 |

## 容易做错的三处
- 现象：配置知识库搜索环节时，选择变量引用无可选值。原因：未在对话流程中前置配置变量输出节点，或未将变量绑定到搜索环节的输入参数。
- 现象：线上环境触发Cannot redefine property: toString报错。原因：自定义代码块中重复声明了toString全局方法，或引入的扩展与FastGPT v4.17.0的内置原型方法冲突。
- 现象：返回的引用溯源信息仅包含文档正文内容，未关联生产批次与设备ID。原因：未在知识库引用模板中配置来源字段的提取规则，仅提取了文档核心文本。

## 怎么确认配好了
- 发起包含生产批次关键词的测试提问，检查返回结果中是否附带原始来源的批次号与设备标识。
- 调整`quoteMaxToken`的取值，验证返回的引用内容长度是否符合预期。
- 触发线上环境的测试请求，确认无Cannot redefine property: toString类报错。
- 对比提示词与知识库引用模板的配置，确认两者的作用范围与格式要求已明确区分。
