# 半导体封装测试的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
半导体封装测试场景的日常文档包含封装流程卡、键合与塑封参数、晶圆来料图、测试程序版本、良率报告、失效分析报告。数据来源覆盖晶圆测试图、MES系统、键合机与塑封设备、ATE测试机、X-ray/SAM检测设备及客户规格文件。数据更新频率随生产节奏调整，包含每批物料的批次数据、每颗芯片的测试数据，以及每日汇总的设备运行与良率统计数据。文档字段包含工序编号、参数阈值、测试bin码、失效类型标识等专业内容，部分参数带有明确的行业单位，如压力、温度等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该场景的数据来源分散且格式多样，要求模型接入环节兼容多系统导出的文件格式，避免因格式不匹配导致数据解析失败。高频率的生产数据更新要求配置支持近实时的向量同步与文档刷新，确保审查结果匹配最新的生产数据。多类型文档的结构差异要求配置适配不同的内容拆分逻辑，避免关键参数被错误截断。专业字段的单位约束要求模型具备精准的参数识别能力，防止因单位混淆引发混批、错程序等生产风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数逻辑制定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 本地大模型部署的`http://{本地部署IP}:{端口}/v1/chat/completions` | 适配半导体封装测试场景的本地数据隐私要求，避免敏感制程数据外流 |
| `AIPROXY_API_TOKEN` | 本地大模型生成的访问密钥 | 验证模型调用权限，防止未授权访问引发数据泄露 |
| `maxContext` | `8000–12000 token` | 覆盖多批次的测试报告与晶圆图数据，确保上下文对齐晶圆实物与批次信息 |
| `temperature` | `0.1–0.3` | 保障技术文档审查的准确性，降低参数解读的随机偏差 |
| `maxTokens` | `2000–3000 token` | 确保单条审查结果包含完整的参数对比与失效分析结论，避免关键信息被截断 |
| `toolChoice` | `none` | 聚焦文档内容的交叉校验，无需调用外部工具即可完成参数比对与合规检查 |

## 容易做错的三处
- 现象：调用本地大模型接口连通但返回content为空。原因：未正确配置`AIPROXY_API_TOKEN`，或模型返回格式未符合FastGPT要求的JSON结构。
- 现象：AI对话节点返回empty或报错状态码。原因：未设置`maxTokens`参数限制输出长度，导致大模型生成内容超出阈值被截断，触发解析失败。
- 现象：开启问题优化和结果重排后响应超时。原因：未调整`maxContext`适配当前多批次文档的上下文长度，或重排环节的模型调用参数未匹配本地算力规格。

## 怎么确认配好了
- 发起POST请求测试`AIPROXY_API_ENDPOINT`，验证返回的JSON结构包含content字段且无空值。
- 设置`temperature`为0.2，输入一段封装流程卡的参数内容，核对模型返回的参数校验结果符合专业逻辑。
- 导入3个连续批次的测试报告，调整`maxContext`为10000 token，验证上下文未被强制截断且完整加载。
- 开启问题优化和结果重排功能，监控单次请求的响应时长，调整`maxTokens`或上下文参数使时长符合业务预期。
