# 半导体晶圆制造的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
数据来源包含晶圆厂MES系统、设备实时监控FDC模块、缺陷量测设备、工艺配方库与实验数据集；更新节奏随每批晶圆流转、设备参数实时刷新、每日汇总良率与异常数据；文档类型涵盖标准化工艺流程卡、单批次运行日志、设备参数配方、空间分布型缺陷图谱、异常处置工单；字段包含纳米级工艺参数、晶圆批次标识、工序节点记录、缺陷坐标信息，单位涵盖纳米、毫秒、批次编号等。

## 这些特征在「工作流编排」这一环带来什么约束
晶圆制造的超长工艺链与跨部门文档联动需求，要求工作流编排支持多节点串行与并行组合，覆盖工艺整合、设备、良率等多部门文档；实时更新的设备参数与批次数据，要求工作流节点支持动态变量调用，避免固定上下文过期；纳米级工艺参数与空间分布型缺陷图谱的精确匹配需求，要求配置环节锁定字段映射规则，防止参数漂移误判；有限返工窗口要求工作流设置快速异常触发分支，缩短审查周期。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 变量绑定 | 绑定`variables`中的晶圆批次号、工艺节点ID | 匹配每批晶圆的动态数据，避免跨批次文档混淆 |
| 节点超时设置 | 60–120 秒 | 适配实时设备数据的刷新节奏，防止因数据延迟导致流程中断 |
| 并行节点数 | 前3个核心部门文档 | 覆盖工艺、设备、良率三个核心审查维度，避免节点过多导致卡顿 |
| 字段映射规则 | 锁定纳米级参数、缺陷坐标字段 | 匹配晶圆制造文档的专属字段特征，提升交叉审查精度 |
| 触发条件 | 按`nodeId`匹配工序节点 | 精准触发对应工序的文档审查流程，适配超长工艺链的节点顺序 |
| 上下文缓存 | 1000–1500 字符 | 适配单批次工艺文档的长度，避免上下文溢出影响响应速度 |

## 容易做错的三处
- 现象：工作流画布拖动卡顿，批量节点运行响应延迟数秒。原因：并行节点数设置未按工艺维度拆分，超出当前版本的适配阈值。
- 现象：工作流运行预览正常，但聊天页面无返回结果。原因：未正确绑定`variables`中的晶圆批次参数，导致上下文无法匹配对应批次的文档数据。
- 现象：HTTP请求节点无法发送文件类型的form-data参数。原因：未正确映射表单字段与晶圆批次的日志文件，未关联对应文档路径。

## 怎么确认配好了
- 手动触发对应工艺节点的工作流，检查是否自动调取该节点的工艺流程卡与设备配方文档。
- 模拟异常参数输入，验证工作流是否触发对应异常处置单的审查分支。
- 调整并行节点数，观察工作流画布拖动与运行响应速度是否符合预期。
- 确认当前使用FastGPT v4.17.0版本，检查`variables`与`nodeId`的绑定配置是否与当前晶圆批次字段匹配。
