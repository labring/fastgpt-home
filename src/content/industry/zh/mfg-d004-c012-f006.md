# 半导体晶圆制造的技术文档交叉审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来源包括MES系统、设备FDC采集模块、缺陷检测与量测设备、工艺配方库等。日常文档涵盖工艺流程卡、批次运行记录、设备配方、SPC图、异常处置单、缺陷图谱、良率报告，包含纳米级工艺参数、晶圆批次号、缺陷空间坐标、良率占比等字段。数据更新节奏随晶圆批次推进，关键设备参数实时采集，常规报表每日更新。

## 这些特征在「引用来源与溯源」这一环带来什么约束
超长工艺链与纳米级参数耦合的特征，要求引用溯源必须精准绑定对应晶圆批次与工序节点，避免跨批次参数混淆。实时采集的设备数据与每日更新的良率报表并存，需区分不同更新频率的数据源优先级，确保溯源指向最新有效版本。洁净室作业的返工窗口有限，要求溯源响应速度匹配现场决策节奏，且异常处置单的引用需关联对应缺陷图谱，避免归因偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1500–2000 token | 匹配单份晶圆制造文档的平均token量，避免上下文溢出 |
| `responseData` | 开启 | 需在正式聊天页面展示引用文档的来源信息，满足业务溯源要求 |
| `detail` | 完整字段 | 需展示文档的批次号、所属系统等专属字段，便于现场人员核对 |
| 搜索过滤 | 按晶圆批次筛选 | 匹配晶圆制造按批次管理的业务逻辑，缩小溯源范围 |
| 单次搜索上限 | 前3–5条 | 核心工序归因仅需少量关键文档，避免无关信息干扰 |
| 最大上下文 | 8000–12000 token | 匹配单批次晶圆文档的总token量，避免截断关键参数 |

## 容易做错的三处
- 现象：正式聊天页面未展示引用文档的来源信息，仅调试页面可见。原因：未开启`responseData`配置项，仅在调试模式下保留溯源数据。
- 现象：知识库搜索返回结果条数符合设定，但实际token超出阈值。原因：未合理设置`quoteMaxToken`，仅限制返回条数未限制单条文档的token占用。
- 现象：工作流中执行的程序结果无法作为背景知识输入后续模块。原因：未将执行结果的输出字段绑定至知识库的上下文输入节点，未完成数据流转配置。

## 怎么确认配好了
本文基于FastGPT v4.17.0版本配置逻辑编写，可通过以下动作核对配置效果：
- 进入正式发布的聊天页面，发起与晶圆批次参数相关的查询，检查回复下方是否展示引用文档的来源路径与专属字段。
- 调整`quoteMaxToken`配置项至不同区间，发起包含多份工艺文档的查询，核对返回的引用文档token总量是否符合设定值。
- 配置按晶圆批次的搜索过滤规则，输入特定批次号，检查返回的文档是否仅关联该批次的运行记录与报表。
- 进入工作流配置页面，绑定程序执行的输出结果至知识库搜索的上下文输入节点，运行工作流验证数据流转正常。
