# 印染与后整理的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来自染整厂、面料企业的染色、定形、实验室与质量部门的日常产出与生产设备数据。日常文档包含染色配方、称化料记录、染缸曲线、打样确认单、色差报告、定形工艺单、污水台账等。数据来源涵盖客户色样、配方库、染化料批次记录、染缸控制系统、测色仪、定形机、环保监测设备。数据更新频率为每缸、每批、每班，单份文档包含具体工艺参数、批次信息、检测结果等字段，部分设备导出数据带有标准化单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类高频次、多维度的生产数据特征，对向量模型与索引环节带来多重约束。首先，每缸每批的实时更新数据，要求索引支持增量同步与低延迟刷新，避免因数据滞后影响交叉审查效率。其次，文档包含结构化工艺参数、非标准化检测描述、设备导出的时序曲线等混合格式内容，要求向量模型适配多类型数据的向量化转换，同时索引需兼容结构化字段的精准匹配与语义检索。此外，单份文档关联具体生产批次，索引需建立批次维度的关联映射，便于按生产单元快速定位相关文档。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 该品类文档多包含连续工艺参数与完整检测记录，该区间可保留单组工艺逻辑的完整性 |
| `maxToken` | 16384 token | 适配染色配方、染缸曲线等长文档的向量化需求，避免截断关键参数 |
| `defaultToken` | 512 token | 用于色差报告、定形工艺单摘要等短文本的高效向量化 |
| 相似度阈值 | 0.72–0.85 | 平衡召回准确率与召回数量，避免误召回非同一生产批次的无关文档 |
| 单次搜索上限 | 前10条 | 覆盖同批次、同工艺的相关文档，满足交叉审查的文档覆盖需求 |
| 重排 | 开启 | 优化设备导出时序数据与文本描述的语义关联排序，提升审查准确性 |

## 容易做错的三处
- 现象：索引召回结果中混入非同一批次的染缸曲线数据，返回条数超出设定上限。原因：未按生产批次建立索引关联，且单次搜索上限配置未与业务场景匹配。
- 现象：调用向量模型时提示token超出限制，无法完成长文档向量化。原因：`maxToken`设置未匹配文档实际长度，长文档被截断导致参数异常。
- 现象：多模态向量模型调用失败，无法处理设备导出的色样图片数据。原因：未正确配置多模态模型的调用参数，或未兼容设备导出的图片格式。

## 怎么确认配好了
- 上传一份完整的染色配方文档，查看向量化后的token数量是否符合配置区间，无截断报错提示。
- 发起一次同批次的交叉审查请求，核对召回的文档是否均属于同一生产批次，数量符合单次搜索上限的设定。
- 调整相似度阈值，验证召回结果的相关性变化是否符合业务预期，无明显误召回或漏召回情况。
- 测试多模态向量模型对色样图片的向量化调用，确认无格式报错与调用失败提示。
