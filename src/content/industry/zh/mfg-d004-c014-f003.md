# 印染与后整理的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
印染与后整理的业务数据来源包括客户色样、配方库、染化料批次、染缸控制设备、测色仪、定形机与环保监测系统。日常文档涵盖染色配方、称化料记录、染缸曲线、打样确认单、色差报告、定形工艺单与污水台账。数据更新频率为每缸、每批或每班，单批次文档包含染料比例、温度曲线、保温时长等字段，单位涉及摄氏度、分钟、千克等工业常用计量标准，且随生产流程实时更新。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的批次性高频数据与多样文档格式，对多轮对话与提示词配置带来多重约束。首先，单缸/单批的专属数据需通过`chatId`绑定，避免跨批次的配方与工艺参数混淆。其次，文档包含长表格、曲线数据与结构化台账，提示词需明确限定输出格式，防止关键参数被截断。再者，数据来源多为工业设备与实时台账，提示词需严格限定仅使用当前批次的上传文档，禁止引入外部无关信息。最后，生产调整的多轮过程需完整保留对话历史，确保`messages`数组覆盖完整的工艺修正流程，避免调整记录丢失。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前染缸编号与生产批次号，例如`染缸C03_202506151000` | 确保多轮对话仅关联当前批次的文档数据，避免跨批次的配方混淆 |
| `messages` | 保留最近15–20轮对话内容，上限为`10000 token` | 覆盖单缸从打样到投产的完整调整流程，避免关键调整记录丢失 |
| `variables` | 注入当前批次的染色配方、染缸曲线、色差报告，取值为`前3条最相关的文档片段` | 限定对话仅使用当前生产批次的有效数据，减少无关信息干扰 |
| 超时设置 | `120 秒` | 适配染缸参数查询的响应时长，避免因等待过久中断对话 |
| 输出格式校验 | 开启，强制完整输出Markdown表格 | 适配印染工艺参数的表格化展示需求，避免数据截断 |

## 容易做错的三处
- 现象：AI输出的Markdown工艺参数表格被截断，末尾显示`...[hide X char]`。原因：配置的输出长度限制过短，未适配印染工艺文档的长表格内容。
- 现象：对话返回`insufficient_quota 当前分组上游负载已饱和，请稍后再试`报错。原因：未配置请求限流规则，短时间内多缸生产的审查请求超出分组配额。
- 现象：客户端关闭SSE连接后，对话记录未存入数据库。原因：未启用对话数据持久化配置，中断请求时未触发`messages`数组的自动保存逻辑。

## 怎么确认配好了
- 发起单缸染色配方的审查对话，检查`chatId`是否绑定了当前批次的唯一标识，确认对话历史完整记录在`messages`数组中。
- 输入包含色差描述的查询，检查AI输出的结果是否包含当前批次的染缸曲线与色差报告数据，未引入无关外部信息。
- 尝试中断正在进行的对话，检查关闭SSE连接后，对话记录是否自动存入数据库。
- 生成包含多组工艺参数的Markdown表格，检查输出是否完整展示所有参数，未出现截断提示。
