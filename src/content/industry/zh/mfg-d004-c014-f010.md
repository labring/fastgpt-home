# 印染与后整理的技术文档交叉审查：知识库检索与召回

## 这个品类的数据长什么样
这个品类的典型数据来自染整厂、面料企业的染色、定形、实验室与质量部门，日常文档包含染色配方、称化料记录、染缸曲线、打样确认、色差报告、定形工艺单、污水台账。数据来源于客户色样、配方库、染化料批次、染缸控制设备、测色仪、定形机、环保监测系统，更新频率为每缸、每批、每班。文档字段包含缸号、工艺温度、保温时长、染化料配比、色差ΔE值等，对应常规单位为℃、分钟、g/L、ΔE单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据更新频率为每缸、每批、每班，检索召回环节需支持高频增量同步，避免出现数据滞后的情况。文档包含结构化数值报告与非结构化工艺描述，需兼顾语义匹配与精准字段匹配，适配不同格式的检索需求。多源设备数据与人工记录混合，需兼容不同来源的文本与结构化字段检索。单缸、单批数据关联性强，需支持按缸号、批次快速关联召回相关文档，避免无关数据干扰检索结果。

## 配置怎么定
本配置基于FastGPT v4.17.0版本

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 匹配染色配方、色差报告的精准数值与工艺描述，避免低匹配度的无关文档混入 |
| `limit` | 前6–10条 | 单缸关联的有效文档数量集中在5-9条，过多会增加上下文冗余，影响检索效率 |
| `searchMode` | `mixedRecall` | 兼顾语义匹配与结构化字段匹配，适配工艺单、染缸曲线、色差报告的混合检索需求 |
| `usingReRank` | 开启 | 多源文档混合时，重排可提升高相关的染缸控制数据、色差报告的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 优化行业专有术语的查询表述，提升专有工艺文档的召回精准度 |
| `collectionIds` | 绑定染色、定形、实验室三个专属集合 | 仅召回本部门的有效文档，避免跨车间、跨环节的无关数据干扰检索 |

## 容易做错的三处
- 现象：执行检索请求后GPU资源未被调用，界面显示搜索无响应。原因：未正确配置检索引擎的GPU加速参数，或未为知识库集合绑定支持GPU的向量库。
- 现象：检索结果未包含PDF文档中的图片内容，仅返回文字片段。原因：未开启多模态召回配置，或未上传支持图文解析的文档格式。
- 现象：保存检索配置后，页面刷新后参数恢复为默认值。原因：未正确提交配置变更，或浏览器缓存导致界面显示异常，未实际写入知识库配置。

## 怎么确认配好了
- 检查知识库集合的配置项，确认`similarity`、`limit`等参数已保存为预设值。
- 输入一条行业专有查询，核对检索结果包含对应缸号或批次的相关文档。
- 上传一份测试用的染缸曲线PDF，验证检索结果可同时召回文档文字与图片内容。
- 重启FastGPT服务后，再次打开配置页面，确认参数未恢复为默认值。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
