# 原料药与医药中间体生产的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
原料药与医药中间体生产的技术文档包含批生产记录、物料平衡表、反应与精制记录、清洁验证记录、杂质谱报告、偏差与变更文件等。数据来源覆盖注册工艺文档、原料批次台账、DCS系统、称量系统、LIMS实验室信息管理系统、色谱数据系统与QMS质量管理系统。文档按每生产批次、每工艺步骤更新，字段包含批次编号、反应温度、收率数据、杂质含量、溶剂残留量等，格式多为结构化表格与半结构化文本。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的文档来源分散、更新频率高且包含大量专业化学术语与合规相关字段，对模型接入配置提出多重约束。多系统异构数据需要配置兼容的输入格式适配不同数据源的输出，高频更新的批次文档要求模型上下文长度足够覆盖多份关联的工艺与质量记录，专业术语的准确理解要求模型参数设置偏向严谨，避免生成不符合合规要求的审查结果。同时，审查失误可能导致批次报废或合规风险，要求模型调用的稳定性与身份验证的准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配原料药与医药中间体生产的技术文档交叉审查场景：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 覆盖多步反应记录、杂质谱报告与关联批次文档的总长度 |
| `maxTokens` | `2000–3000 token` | 限制单批次审查结果的输出长度，避免超出模型限额 |
| `quoteMaxToken` | `1500 token` | 限定单份引用文档的最大截取长度，确保审查依据完整 |
| 工作流/API 工具选择配置 | `auto` | 自动触发文档交叉引用与合规校验工具，提升审查准确性 |
| `temperature` | `0.1–0.3` | 降低生成随机性，保证专业审查结果的严谨性与一致性 |
| `AIPROXY_API_ENDPOINT` | `部署的OneAPI接口地址` | 指向自建模型的代理接口，实现本地模型接入 |
| `AIPROXY_API_TOKEN` | `从OneAPI获取的有效密钥` | 完成模型调用的身份验证，确保接口访问权限合法 |

## 容易做错的三处
- 配置`toolChoice`为`false`，导致审查结果未自动关联关联文档，现象是输出中未引用杂质谱报告或批次台账内容，原因是未开启工具调用权限，无法完成交叉文档校验。
- 配置`AIPROXY_API_TOKEN`与实际部署的OneAPI密钥不匹配，现象是返回401状态码，原因是身份验证失败，虽然Postman测试密钥可用，但未在FastGPT的配置中正确填入对应密钥。
- `maxContext`设置为`4000 token`以下，导致多步反应记录被截断，现象是审查结果遗漏中间反应步骤的合规性判断，原因是上下文长度不足以覆盖完整的工艺文档。

## 怎么确认配好了
- 调用配置的`AIPROXY_API_ENDPOINT`，使用配置的`AIPROXY_API_TOKEN`发起基础文本生成请求，确认返回200状态码与正常响应内容。
- 上传单批次的批生产记录与杂质谱报告，触发技术文档交叉审查任务，确认输出结果中包含明确的文档引用片段。
- 调整`temperature`参数至`0.5`，观察审查结果的表述变化，确认参数修改后模型输出产生对应调整。
- 查看FastGPT后台的模型调用日志，确认无401、超时或上下文截断相关的错误记录。
