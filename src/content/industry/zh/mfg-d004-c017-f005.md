# 喷涂与涂装的技术文档交叉审查：工具调用与插件

## 这个品类的数据长什么样
本品类的业务数据覆盖汽车、家电、工程机械、金属家具的涂装线场景，日常文档包含涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账。数据来源包括涂料供应商TDS/SDS、喷房与烘炉采集数据、色差仪、膜厚仪、环境监测设备及MES系统。更新节奏为每批涂料、每班生成对应批次文档，喷房、烘炉数据连续采集。文档字段含工艺温度（单位摄氏度）、喷涂压力（单位兆帕）、涂料黏度（单位涂4杯秒）、膜厚（单位微米）等。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据多源且更新节奏差异大，多批次文档与实时采集数据需同时纳入审查范围，要求工具调用支持多数据源并行拉取。文档字段含特定单位与工艺参数，工具调用需内置字段校验逻辑，避免单位不匹配或参数格式错误。高频更新的烘炉、喷房数据要求工具调用触发频率适配生产节拍，单次调用的上下文长度不宜过大。关联审查需匹配前处理、喷涂、固化环节的文档，工具调用需支持跨文档关联查询，将工艺卡与烘炉曲线绑定检索。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配涂装审查中既有内置参数校验又有外部数据源拉取的混合场景，自动选择调用方式 |
| 单次召回文档上限 | 前10条 | 单批次涂装相关文档不超过12份，过多召回会增加上下文处理负载 |
| 工具调用超时时间 | 600秒 | 需拉取MES、仪器数据与多份批次文档，较长超时可覆盖跨源数据获取的耗时 |
| 上下文窗口长度 | 8000–12000 token | 单份涂装文档长度约1000–2000字符，关联审查需纳入3–5份文档的完整内容 |
| 本地模型调用开关 | 开启 | 适配本地部署大模型的使用需求，支持私有模型的工具调用 |
| 插件触发规则 | 按文档类型触发 | 调漆记录需调用黏度校验插件，烘炉曲线需调用固化参数校验插件，匹配不同文档的审查需求 |

## 容易做错的三处
- 现象：工具调用返回的膜厚结果为空，原因：未配置膜厚仪数据的插件拉取权限，导致无法获取实时测量数据。
- 现象：并发调用时出现超时报错，原因：涂装场景需拉取多源数据，未调整超时时间至适配生产节拍的时长，单次调用耗时超过系统默认限制。
- 现象：VOCs台账审查结果出现单位不匹配错误，原因：未在工具调用中配置字段校验逻辑，未对不同单位的参数做统一转换处理。

## 怎么确认配好了
- 查看工具调用日志，确认每次审查都能拉取到对应类型的涂装文档与实时数据，核对拉取的字段单位与文档要求一致。
- 模拟单批次涂装任务发起调用，检查`toolChoice`参数是否根据任务自动切换内置工具与外部插件。
- 调整召回文档数量，观察上下文负载变化，确认召回上限设置适配当前场景的文档总量。
- 测试不同类型的涂装文档触发插件，确认调漆记录调用黏度校验插件、烘炉曲线调用固化参数校验插件的逻辑生效。
