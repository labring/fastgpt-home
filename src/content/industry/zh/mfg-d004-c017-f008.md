# 喷涂与涂装的技术文档交叉审查：文档解析与分块

## 这个品类的数据长什么样
本品类的典型数据来源包括涂料供应商TDS/SDS文件、喷房与烘炉实时采集数据、色差仪/膜厚仪检测报告、环境监测台账及MES工单。日常文档涵盖涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账等。数据更新频率为每批涂料、每班或连续采集，文档包含批次号、检测数值（如膜厚μm、色差ΔE、烘炉温度℃）、时间戳等专属字段，格式覆盖PDF、结构化表格与纯文本。

## 这些特征在「文档解析与分块」这一环带来什么约束
多源异构的数据来源与混合格式的文档，要求解析环节需同时支持结构化表格与非结构化文本的切分。高频更新的特性意味着分块需适配增量上传场景，避免重复解析全量数据。专属字段与单位的存在，要求解析过程需保留字段与单位的绑定关系，不可随意打散参数组合。此外，涂装流程需匹配前处理、喷涂与固化窗口，分块时需保留相邻工艺步骤的上下文关联，防止破坏工艺逻辑的完整性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 涂装工艺卡包含连续的工艺步骤与参数，过长分块会丢失上下文，过短会破坏参数关联，按实测标定适配多类型文档 |
| `chunkSplitter` | 按段落+固定字符边界 | 涂装文档既有结构化表格（如烘炉曲线）又有流程型文本，混合切分可兼顾表格解析与文本连贯性 |
| `customPdfParse` | 启用表格结构化解析 | 涂装报告、工艺卡多含膜厚、色差等表格数据，启用后可保留字段与单位的对应关系 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 180–240 秒 | 大型烘炉曲线PDF或多批次台账解析耗时较长，避免超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 单批次涂料的多文档打包上传时，限制单文件大小适配批量解析场景 |
| `chunkSettingMode` | 手动配置 | 需针对不同文档类型（如TDS与现场报告）调整切分规则，自动模式无法适配特定字段要求 |

## 容易做错的三处
- 现象：上传涂装工艺卡PDF后，解析出的chunk中膜厚数值与单位分离。原因：未启用`customPdfParse`的表格结构化解析，导致表格字段被打散。
- 现象：前端页面展示的chunk ID无法被选中复制。原因：未开启前端的chunk ID复制控件配置，符合实际落地中的常见问题。
- 现象：自定义切分的涂料批次单上传后，知识库自动删除重复chunk导致索引顺序错乱。原因：未关闭知识库的自动去重功能，或未在分块时保留批次号作为唯一标识。

## 怎么确认配好了
- 上传一份标准涂装工艺卡PDF，查看解析后的chunk是否保留了膜厚、烘炉温度等字段与单位的对应关系。
- 上传一份超过50MB的VOCs台账，确认解析任务未触发超时错误。
- 自定义切分一批涂料批次单，验证上传后知识库未自动删除重复的有效chunk。
- 查看chunk列表中的ID项，确认可通过选中操作进行复制。
