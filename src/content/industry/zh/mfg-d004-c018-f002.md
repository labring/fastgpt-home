# 基础化工连续生产的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自氯碱、合成氨等基础化工企业的生产系统，包含操作规程、工艺指标卡、DCS趋势、化验报告、联锁旁路记录、特殊作业票、班报等文档。数据来源覆盖DCS/SIS系统、在线分析仪、LIMS系统、设备状态监测、能源计量装置与原料储罐管理模块。更新节奏涵盖实时、每班、每日三类，其中联锁旁路记录与DCS趋势为实时更新，班报为每日更新。文档包含数值型参数、时间戳、设备编号、作业审批状态等字段，部分附带工业专用单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的文档类型要求向量模型与索引支持混合格式的文本编码，兼顾长文本操作规程与短参数类文档的语义一致性。实时与高频更新的数据需要索引支持增量更新机制，避免全量重建带来的性能损耗。工业专用字段与单位要求向量模型适配工业场景的分词规则，避免参数语义被错误拆分。关键联锁文档的高优先级属性，要求索引可配置召回权重，确保核心审查内容优先被检索到。不同更新频率的文档需要分类索引策略，平衡实时数据的检索时效性与历史数据的存储成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配既有长文本操作规程又有短参数卡的文档结构，避免工艺逻辑被割裂 |
| 重叠长度 | 50–100 字符 | 保留跨块的工艺关联信息，防止连续生产的连锁逻辑被分块打断 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的无关文档，确保关键联锁与工艺内容的检索准确率 |
| 单次搜索上限 | 前10条 | 覆盖多类审查文档的同时，避免冗余结果干扰交叉审查流程 |
| `defaultToken` | 按实测标定 | 适配不同嵌入模型的分词规则，优化工业专用术语的向量编码效果 |

## 容易做错的三处
- 现象：FastGPT v4.17.0升级后，原已创建的知识库无法返回向量检索结果。原因：新版本调整了默认分块的字符长度阈值，未兼容旧版配置下的长文本化工文档，导致分块后的文本无法被正确编码。
- 现象：导入CSV格式的化验报告后，索引创建过程报错。原因：未将CSV中的结构化数值转换为带单位的文本描述，直接导入导致向量模型无法识别参数语义。
- 现象：检索联锁相关问题时，优先召回的是班报等非关键文档。原因：未针对高优先级的联锁旁路记录配置专属召回权重，通用检索规则无法区分文档的重要性层级。

## 怎么确认配好了
- 上传一份典型的工艺指标卡，查看分块预览结果，确认完整保留了压力、温度等参数及对应单位。
- 发起一条包含「联锁旁路」关键词的检索，确认召回结果中包含联锁旁路记录类文档。
- 上传一份实时更新的DCS趋势数据，检查索引状态页，确认增量索引任务可正常触发并完成。
- 调整相似度阈值后，验证检索结果的匹配度是否符合预设的审查精度要求。
