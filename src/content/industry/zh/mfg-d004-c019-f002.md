# 塑料注塑成型的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类日常文档包含注塑工艺卡、原料干燥记录、模具履历、首件检验、巡检表、换料清机记录。数据来源为树脂批次和物性表、注塑机参数、模温机、MES系统、尺寸与外观检测设备。更新频率为每生产批次、每次换模换料、每班结束后更新。文档字段涵盖干燥温度、保压压力、模温、批次号、回料比例等，单位包含摄氏度、兆帕、千克等，单份文档的参数段落长度差异明显。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据更新频率高且触发节点明确，要求索引支持增量刷新以匹配换模换料、批次生产的节奏，避免全量重建带来的资源消耗。文档字段包含大量数值型工艺参数，向量模型需适配文本与数值混合的内容，避免参数关联被拆分。单份文档的参数段落长度差异大，分块时需保留相邻工艺步骤的上下文，否则会导致充填保压冷却窗口、原料干燥条件等关键信息断裂。不同文档的字段结构差异明显，索引需支持按字段维度过滤召回结果，以精准匹配注塑缺陷排查的需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配注塑文档中工艺参数段落的常规长度，避免拆分破坏保压、冷却等工艺步骤的关联 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文，确保充填窗口与原料干燥记录的参数关联不被截断 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.72–0.85 | 适配注塑工艺参数的精度要求，过滤低匹配度的无关文档，避免缺陷排查出现偏差 |
| 单次搜索上限 | 前 10 条 | 覆盖注塑缺陷排查所需的多维度工艺记录，避免召回过多冗余数据 |
| `defaultToken` | 按实测标定 | 适配所选用向量模型的token限制，匹配导入文档的总长度需求 |

## 容易做错的三处
- 现象：导入文档后生成的dataset.csv仅包含index字段，无content字段。原因：未开启文档内容提取开关，仅同步了索引元数据，未完整抓取注塑文档的工艺参数内容。
- 现象：内网部署FastGPT时，向量模型调用出现超时报错。原因：未配置内网环境下的模型访问代理，或未调整超时参数适配内网网络延迟。
- 现象：使用默认分块长度导入长段落注塑工艺卡时，出现参数截断。原因：未调整分块长度适配注塑文档的长参数段落，导致充填保压冷却窗口等关键信息被拆分。

## 怎么确认配好了
- 导入单份注塑工艺卡，查看知识库的分块预览界面，确认工艺参数未被截断，相邻段落的关联信息保留完整。
- 导出当前知识库的dataset.csv文件，检查文件中是否同时包含index和content字段，且content字段包含完整的工艺参数内容。
- 发起针对注塑缺陷的查询，确认召回结果包含对应模具履历、原料干燥记录等相关文档的内容。
- 查看FastGPT的系统日志，确认向量模型调用无超时报错，索引刷新操作按预设节奏完成。
