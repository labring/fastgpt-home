# 塑料注塑成型的技术文档交叉审查：文档解析与分块

## 这个品类的数据长什么样
该品类的核心数据来自树脂批次物性表、注塑机参数、模温机、MES系统及尺寸外观检测结果，日常文档包含注塑工艺卡、原料干燥记录、模具履历、首件检验表、巡检表与换料清机记录。文档结构随类型差异明显：工艺卡包含充填保压冷却窗口的压力、温度参数，干燥记录标注干燥温度与时长，模具履历记录换模次数与维护周期。数据更新频率随生产节奏调整，每批次原料、每次换模换料及每班生产结束后均会生成新文档，字段多带有明确单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
高频更新的多类型文档要求解析分块适配不同结构，避免拆分关键工艺参数。注塑类文档包含大量带单位的数值字段，分块时需保留参数与对应单位的关联，否则交叉审查无法匹配原料物性与工艺要求。大型模具履历与多批次干燥记录文件体积较大，解析时长较长，需适配更长的超时阈值。结构化表格类文档的字段需完整提取，避免因默认解析逻辑丢失关联数据，否则会遗漏混料、模具损伤等风险点。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配注塑工艺卡的单段参数长度，避免拆分充填保压冷却窗口等核心工艺信息 |
| `chunkSplitter` | 按段落+语义分割 | 适配多类型文档的结构差异，保留干燥记录、模具履历的完整业务逻辑 |
| `customPdfParse` | 启用表格识别模式 | 适配巡检表、换料清机记录的结构化表格数据，避免提取字段时丢失数值与单位 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 180 秒 | 适配大型模具履历或多批次干燥记录的解析时长，避免触发超时报错 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 适配批量上传的树脂物性表合集，满足多批次生产数据的导入需求 |
| `chunkSettingMode` | 手动配置 | 针对注塑文档的特定字段调整分块边界，确保关键参数不被拆分 |

## 容易做错的三处
- 现象：上传多批次注塑工艺卡或大型模具履历后，界面显示超时报错，状态码504。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`取值，默认时长不足以解析大型文件。
- 现象：上传结构化巡检表或换料清机记录后，解析结果中检测数值与对应单位字段为空。原因：未启用`customPdfParse`的表格识别模式，默认解析逻辑无法提取表格内的结构化数据。
- 现象：将知识库导出后导入新服务器，回料比例、原料干燥参数等关键配置缺失。原因：分块时未保留参数关联上下文，拆分了包含完整配置的段落。

## 怎么确认配好了
- 上传单份注塑工艺卡，检查解析后的分块是否保留完整的充填保压冷却窗口参数与对应单位。
- 上传结构化巡检表，确认解析结果中包含所有检测数值与对应字段。
- 上传500 MB以内的模具履历合集，检查解析过程未触发超时报错。
- 导出当前知识库配置，导入至测试环境后，确认回料比例等关键参数未丢失。
