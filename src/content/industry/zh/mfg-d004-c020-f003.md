# 安全环保与特殊作业管理的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自法规标准、在线环保监测设备、气体检测仪、人员资质档案、设备隔离清单及监管平台。日常文档包含风险辨识记录、动火/受限空间/吊装等作业票、监测记录、危废台账、排放监测数据、事故与隐患整改报告。数据更新随单次作业完成、实时监测要求或定期检查推进，文档字段包含作业类型、监护人员资质编号、气体检测浓度、隔离设备状态等，部分字段带ppm、立方米等专属单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类数据来源分散且更新频繁，多轮对话需逐步调取不同系统的作业票、监测记录等文档，避免一次性加载过量数据导致超时。不同文档的专属字段与单位要求提示词精准匹配校验规则，防止遗漏资质、浓度等关键信息。单次作业的实时数据需在对话中实时拉取，无法依赖静态缓存，同时需通过多轮追问逐步确认隔离状态、人员资质等否决项，确保审查结果符合安全环保要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 前8000–12000字符 | 本品类单套关联文档总长度适配该区间，避免截断作业票、资质证明等关键内容 |
| 单次搜索上限 | 前6条 | 覆盖单次作业的核心关联数据，避免冗余信息干扰审查 |
| `variables` | 传入当前作业ID、作业类型 | 精准定位对应作业的专属文档与实时监测数据 |
| `messages` | 按对话轮次追加校验记录 | 保留每一轮审查过程，便于回溯与复核 |
| 最大等待时长 | 600秒 | 适配跨系统调取数据的延迟，防止请求超时失败 |
| `chatId` | 绑定当前会话的唯一标识 | 关联对话历史与专属作业数据 |

## 容易做错的三处
- 现象：尝试上传作业票、监测记录等附件时，界面提示“fail to create post presigned url”，文件无法提交。原因：未在系统配置中正确配置存储服务的访问密钥与路径，或版本升级后配置项未完成迁移。
- 现象：多轮对话返回的审查结果未包含气体检测浓度、作业隔离状态等专属字段。原因：提示词未明确指定需校验的字段范围，导致遗漏关键数据。
- 现象：对话返回的审查结果混淆不同作业的内容，无法对应到指定作业。原因：未通过`variables`或`chatId`传入作业专属标识，导致调用的文档范围过大。

## 怎么确认配好了
- 发起一次模拟作业审查对话，检查返回结果是否包含当前作业的专属文档内容，确认参数配置生效。
- 上传多份关联文档，验证附件上传流程是否正常，无预设报错提示。
- 发起多轮追问，检查对话历史是否被完整保留，确认`messages`参数配置正确。
- 核对审查结果的字段，确认包含作业类型、气体浓度等本品类专属数据。
