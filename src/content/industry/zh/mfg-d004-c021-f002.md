# 家具与木制品制造的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类的典型主体为板式家具、实木家具、定制家居和木门企业。日常生产相关文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金物料清单、试装与包装记录。数据主要来自订单设计系统、板材与木材批次台账、数控开料钻孔设备、ERP/MES系统及含水率检测设备。更新节奏随订单生成、每日设备日志同步、每批材料入库完成更新。文档字段包含板件尺寸、板材含水率、五金型号、工艺参数等，部分文档附带可视化图纸关联信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的文档多包含结构化字段与可视化关联内容，且随订单、批次高频更新，单批次数据量随定制订单规模扩大而增加。结构化开料清单与非结构化工艺文档混合存在，要求向量模型同时适配文本与结构化字段的语义提取。高频更新的特性要求索引支持增量同步，避免全量重索引带来的耗时问题。定制订单驱动的板件数量多且关联关系紧密，需确保向量索引保留板件与订单、批次的关联维度，避免交叉审查时丢失上下文关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 该品类文档包含结构化板件参数与连贯工艺文本，该长度可保留单块内的语义关联，避免拆分破坏板件与工艺的绑定关系 |
| 分块重叠长度 | 100–150 字符 | 跨分块的板件尺寸、工艺参数关联较多，重叠长度可保留上下文衔接信息，提升交叉审查的匹配准确性 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.72–0.85 | 该品类需严格匹配板件尺寸与工艺要求，阈值过低会引入无关板件数据，过高则无法召回正确关联项 |
| 单次索引上限 | 10000 条/批次 | 该品类单批次数据量随定制订单波动，该取值可平衡索引速度与系统负载 |
| 增量索引开关 | 开启 | 数据随订单、批次高频更新，增量索引可避免全量重索引的耗时问题 |

## 容易做错的三处
- 现象：上传十万条级别的csv物料清单后，向量完成后数据总量少数千条。原因：部分行包含未转义的特殊字符（如板材名称中的双引号），导致解析失败未被纳入索引。
- 现象：创建集合显示创建成功，但页面上索引状态一直显示未建立。原因：未开启对应文档类型的解析插件，或拆单图等可视化文档未正确关联文本元数据，导致索引生成环节无法推进。
- 现象：向量计算返回的相似度分数异常偏大，且不同文档的分数差异极小。原因：分块长度设置不符合品类文档结构，单块包含过多不相关内容，语义嵌入出现偏差。

## 怎么确认配好了
- 上传单份典型开料清单文档，检查分块后的文本是否保留完整的板件尺寸与工艺参数，无明显截断或拆分错误。
- 执行一次小规模索引测试，核对索引生成的条数与源文档条数一致，无异常丢失。
- 检索预设的板件尺寸关键词，检查返回结果的相似度分数符合业务匹配逻辑，可根据实际审查需求调整阈值。
- 开启增量索引开关后，新增一条测试订单数据，检查索引是否自动同步更新，无延迟或阻塞。
