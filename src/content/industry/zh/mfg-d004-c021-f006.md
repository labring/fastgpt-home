# 家具与木制品制造的技术文档交叉审查：引用来源与溯源
本文基于FastGPT v4.17.0版本的配置逻辑，针对家具与木制品制造的技术文档交叉审查场景，梳理引用来源与溯源的落地细节。

## 这个品类的数据长什么样
该品类的典型主体包含板式家具、实木家具、定制家居和木门企业，日常生产相关文档涵盖拆单图、开料清单、封边与钻孔程序、涂装工艺、五金清单、试装与包装记录。数据主要来自订单设计系统、板材和木材批次记录、数控开料与钻孔设备、ERP/MES系统以及含水率检测设备。数据更新频率随生产节奏调整，包含每订单生成的定制板件参数、每日更新的工艺参数、每批材料对应的批次信息。文档字段包含板件尺寸、板材批次号、含水率数值、五金型号等，单位多为毫米、百分比、件数等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
定制订单驱动的生产模式决定了每一份板件都对应唯一的订单与批次信息，因此引用溯源需要精准绑定订单号与板件编号，避免跨订单的文档混淆。多类型且高频更新的文档要求溯源环节支持跨文档关联，例如核对开料清单与封边程序的尺寸匹配。板件数量多且依赖现场空间尺寸的特性，要求引用时需保留完整的上下文参数，不能截断关键尺寸或批次信息。与标准家电等固定BOM品类不同，该品类的文档无统一模板，因此溯源配置需适配多样化的文档元数据格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 字符 | 匹配单份家具生产文档的平均长度，避免截断板件尺寸、板材批次等关键信息 |
| `responseData` | 开启 | 要求返回引用来源的原始文档元数据，包含板材批次号、开料程序编号等该品类特有字段 |
| `detail` | 完整 | 展示引用片段的完整上下文，便于交叉审查时核对孔位、五金与现场安装的匹配关系 |
| 单次搜索上限 | 前8条 | 覆盖定制订单的多份配套生产文档，避免遗漏关键工序参数 |
| 最大上下文 | 6000 字符 | 承载多份板件文档的关联信息，支持跨文档的交叉审查比对 |

## 容易做错的三处
- 配置测试提示错误但强行运行后引用功能异常：原因是未正确绑定该品类特有的元数据字段，导致引用时无法匹配板材批次或订单编号信息。
- 知识库检索仅返回单条文档：原因是单次搜索上限配置过低，或未开启多文档关联召回逻辑，未适配定制订单多配套文档的生产场景。
- 引用来源字段为空：原因是未开启`responseData`配置项，未要求系统返回原始文档的元数据信息，无法完成溯源校验。

## 怎么确认配好了
- 导入该品类的典型文档，包括拆单图、开料清单与涂装工艺记录，发起包含板件尺寸、板材批次的查询，检查返回结果是否包含对应文档的引用标记。
- 调整`quoteMaxToken`配置后，验证长文档的引用片段是否完整，未出现截断的关键参数。
- 发起跨文档的交叉查询，例如核对开料清单与封边程序的尺寸匹配性，检查是否能召回多份关联文档。
- 查看系统返回的引用元数据，确认包含板材批次号、订单编号等该品类特有的字段信息。
