# 家具与木制品制造的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
该品类的典型主体为板式家具、实木家具、定制家居及木门企业，日常产生的文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金清单、试装与包装记录。数据主要来自订单设计系统、板材与木材批次台账、数控开料钻孔设备、ERP/MES系统及含水率检测设备，更新节奏随订单、每日或每批材料触发，文档多包含尺寸参数、批次编号、工艺要求等字段，单位涉及毫米、立方米、千克等。

## 这些特征在「模型接入与配置」这一环带来什么约束
定制订单驱动的生产模式带来单批次文档数量多且个性化差异大的特点，要求模型上下文窗口需适配多份短文档的批量输入。拆单图、开料清单等文档包含精确尺寸与孔位信息，要求模型召回的片段需保留字段完整性，避免截断关键参数。多来源数据的格式差异，要求配置需兼容不同格式的文档导入，同时需限制单次处理的数据量以避免超时。含水率检测数据的实时性要求，需配置合理的更新触发机制，确保模型调用时使用最新批次的材料参数。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多份拆单图、开料清单等文档的批量输入，覆盖单订单的全量技术文档 |
| `maxTokens` | 1500–2000 token | 满足工艺描述、尺寸核对的输出长度需求，避免截断关键结论 |
| `temperature` | 0.1–0.3 | 降低随机输出，确保尺寸、孔位等参数的核对结果准确一致 |
| `quoteMaxToken` | 2000–3000 token | 保留足够的文档片段细节，用于交叉核对开料与涂装工艺的匹配性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配企业内部的代理访问路径，确保模型调用的稳定性 |
| `AIPROXY_API_TOKEN` | 按权限分配的密钥 | 保障模型调用的访问安全，避免未授权接入 |

## 容易做错的三处
- 现象：同一问题在FastGPT网页调试与其他接入场景下返回结果不一致。原因：未统一配置`maxContext`与`temperature`参数，不同接入端的默认参数存在差异。
- 现象：添加模型后测试不通过，返回连接失败或权限报错。原因：未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，导致无法正常访问模型服务。
- 现象：召回的文档片段缺失尺寸或孔位等关键信息。原因：`quoteMaxToken`取值过低，截断了包含核心字段的文档内容。

## 怎么确认配好了
- 进入模型调试界面，输入单订单的拆单图与开料清单相关问题，核对返回结果是否覆盖预设的核对维度。
- 切换不同的接入场景，验证同一问题的返回结果是否保持一致。
- 查看模型调用日志，确认每次调用的参数配置与预设值匹配。
- 导入测试用的板材批次数据，验证模型是否能正确关联对应的工艺参数。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
