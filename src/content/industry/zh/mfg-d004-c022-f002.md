# 家用电器整机制造的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
家用电器整机制造的技术文档涵盖配置BOM、装配作业书、制冷剂充注记录、电气安全测试报告、性能抽检报告及返修记录。数据来自ERP/MES系统、零部件批次台账、拧紧与充注设备日志、安规测试仪、性能实验室数据及售后故障档案。更新节奏按单台产品、每班生产批次或抽检计划执行，单份文档包含型号规格、工艺参数、测试结果、批次编号等字段，部分文档附带物理单位如兆帕、摄氏度、毫安。

## 这些特征在「向量模型与索引」这一环带来什么约束
单台家用电器对应多份关联文档，数据更新频率高且批次关联强，要求索引支持按批次、型号快速精准召回。文档包含大量结构化工艺参数与非结构化测试描述，向量模型需适配混合内容的编码需求。安规与性能测试文档的合规性要求向量召回的精准度需匹配工艺公差范围，避免混线错装风险。多型号混线生产的场景下，索引需支持按产品型号做维度隔离，防止不同型号的文档交叉干扰。同时，批量文档的高频更新要求索引的增量同步效率适配每班的生产节奏。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配装配作业书、测试报告的单段文本长度，避免拆分破坏工艺参数的关联性 |
| `maxToken` | 4096 token | 匹配家用电器文档中长段性能测试数据的编码需求，避免截断关键参数 |
| 相似度阈值 | 0.75–0.85 | 区分同型号不同批次的文档差异，防止混线装配时的型号误匹配 |
| 单次搜索上限 | 前10条 | 覆盖单台产品关联的多份文档数量，保证召回的全面性 |
| `defaultToken` | 1024 token | 适配短文档如零部件批次记录的编码长度，平衡计算效率与召回精度 |
| 重排 | 开启 | 优化召回结果的排序，突出安规、性能测试等核心审查文档 |

## 容易做错的三处
- 现象：Docker容器中仅识别到一张3090显卡，向量模型加载时显存占用仅为单卡容量，第二张卡无负载。原因：未在docker run命令中添加`--gpus all`参数，或未在FastGPT系统配置中启用多GPU并行调度。
- 现象：调用百度embedding-v1接口时返回404 Not Found，日志显示接口路径不存在。原因：未正确配置OneAPI的模型映射路径，或未开通对应模型的调用权限。
- 现象：无GPU环境下尝试添加向量模型失败，系统提示硬件不支持CUDA加速。原因：未选择适配CPU的向量模型，或未在容器启动命令中指定CPU运行模式。

## 怎么确认配好了
- 上传一份典型的家用电器装配作业书，检查向量索引拆分结果，确认无关键工艺参数被截断。
- 发起针对特定型号家电的技术文档检索，确认召回结果包含对应型号的BOM、安规报告及装配作业书，结果数量符合预期。
- 查看FastGPT系统的硬件监控面板，确认多块GPU均被正常调用，显存使用率符合配置预期。
- 测试调用配置的向量模型接口，确认返回的向量数据无异常，且无报错日志生成。
