# 家用电器整机制造的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
该品类数据涵盖空调、冰箱、洗衣机、小家电等整机的配置BOM、装配作业书、制冷剂充注记录、电气安全测试报告、性能抽检报告及返修记录。数据来源包括ERP/MES系统、零部件批次台账、拧紧与充注设备、安规测试仪、性能实验室数据及售后故障记录。更新节奏随单台整机、每班生产批次或抽检计划执行，文档多包含工艺参数、检测结果与零部件批次的关联字段。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的多源异构数据来源要求工作流支持对接ERP/MES、设备日志、售后系统等不同格式的数据源；高频更新的单台/批次级数据要求工作流触发逻辑绑定生产节点，避免数据滞后；混线装配的生产模式要求工作流可按整机型号、零部件批次筛选对应文档；安规、性能与售后数据的交叉校验需求，要求工作流整合多类文档的字段关联规则，避免错装或工艺偏差引发安全风险；大批量生产的特性则要求工作流可高效处理单批次多台整机的批量校验任务。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 传入整机型号、零部件批次号、生产班次ID | 匹配对应型号的专属BOM、装配作业书等文档，避免混线错配 |
| `nodeId` | 绑定生产工位触发节点ID | 按生产节拍触发工作流，适配单台/批次级数据的实时更新需求 |
| 单次搜索上限 | 前8条 | 覆盖同型号的多份检测报告、工艺记录与售后关联数据 |
| HTTP请求超时时间 | 600秒 | 适配安规测试、性能检测等较长的设备数据返回周期 |
| 循环嵌套配置 | 按批次循环执行 | 适配每班多批次的生产数据批量校验需求 |
| 知识库变量引用 | 按实测标定 | 适配多字段关联的文档交叉校验逻辑 |

## 容易做错的三处
- 现象：调用工作流API返回空值，或知识库变量引用触发`quote type error`报错。原因：未在FastGPT v4.17.0及以上版本中正确配置嵌套知识库的变量传递规则，或输入的变量未匹配文档的关联字段格式。
- 现象：工具调用模块同时输出AI回复与触发下一级分支执行。原因：未正确设置分支的触发条件，将工具调用的输出同时绑定了多路径执行逻辑。
- 现象：HTTP请求超时时间无法调整至适配生产需求的时长，或循环嵌套中无法嵌入HTTP请求节点。原因：未在工作流的HTTP配置面板中修改超时参数，且未确认循环模块支持外部请求的嵌套调用。

## 怎么确认配好了
- 手动触发工作流，传入指定整机型号与批次号，核对返回的关联文档是否仅包含对应型号的专属内容。
- 查看工作流的执行日志，确认HTTP请求的超时时间已修改为适配生产需求的时长，且循环节点按批次触发执行。
- 模拟变量引用操作，输入测试字段，确认未触发`quote type error`报错，且变量可正确关联到对应文档。
- 测试工具调用模块，确认仅输出工具执行结果或仅触发下一级分支，无并行执行的情况。
