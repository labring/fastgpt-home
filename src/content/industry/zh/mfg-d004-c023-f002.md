# 工业仪器仪表制造与校准的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
本品类数据来源包括设计文件、标准器和环境监测数据、校准软件、实验室信息系统及客户量程要求。日常生成的文档包含装配调试单、校准规程、原始校准记录、误差曲线、计量证书、软件版本记录。数据按每台设备、每次校准更新，单份校准记录包含仪器编号、校准日期、标准器参数、误差值、计量证书编号等字段，单位涵盖帕斯卡、摄氏度、流量单位等计量专用标识。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据包含大量带计量专用单位的精确数值、溯源编号及结构化参数，同时存在非结构化的误差曲线说明文档，且按每台设备、每次校准高频更新。多源异构的数据格式要求索引需兼容结构化字段与非结构化文本的混合检索。技术文档交叉审查需关联同批次校准的多份文档，索引需支持按仪器编号、校准日期等字段做精准过滤。高频更新的数据会带来索引刷新频率的约束，需平衡检索效率与数据时效性，同时计量数据的精确性要求向量模型对数值语义的匹配需符合校准误差的容忍范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配校准记录、误差曲线的文本长度，避免分割破坏计量参数的完整性 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的计量编号关联信息，防止跨块检索丢失溯源链 |
| 相似度阈值 | 0.75–0.85 | 匹配计量数据的精确性要求，过滤低相关性的非校准文档 |
| 单次搜索上限 | 前10条 | 控制交叉审查的候选文档数量，避免过多冗余数据干扰溯源链审核 |
| `maxToken` | 4000 token | 适配单批次校准文档的总上下文长度，满足FastGPT v4.17.0版本的拼接需求 |
| 最大上下文 | 10000 字符 | 承载多份校准记录的拼接内容，支持完整的溯源链比对 |

## 容易做错的三处
- 现象：知识库磁盘占用远超预期，界面显示的原文件、分割块与嵌入向量占比与实际统计不符。原因：未按校准记录的更新频率设置索引刷新周期，高频更新的校准数据未及时清理旧版本嵌入向量，导致冗余数据堆积。
- 现象：检索结果中出现无关的非校准类文档，无法筛选到指定仪器编号的记录。原因：未配置按仪器编号的字段过滤规则，仅依赖全局相似度检索，未结合品类特有的结构化字段做精准匹配。
- 现象：向量检索超时，返回状态码504或空结果。原因：单次搜索上限设置过高，同时未限制检索的文档总数量，导致大量校准记录的嵌入向量被同时加载计算，超出系统处理阈值。

## 怎么确认配好了
- 查看知识库的磁盘占用统计，核对原文件、分割块与嵌入向量的占比，确认与配置的分块策略匹配。
- 输入一条校准相关的查询，验证检索结果可按仪器编号、校准日期等字段做筛选，确认过滤规则生效。
- 提交批量校准文档的交叉审查任务，检查检索耗时符合预期，未出现超时报错。
- 查看向量模型的调用日志，确认`maxToken`等参数的实际取值与配置一致。
