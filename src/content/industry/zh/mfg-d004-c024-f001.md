# 工艺变更与工程变更的技术文档交叉审查：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据来源于PLM、ERP、MES、供应商资料、验证试验及客户特殊要求，更新节奏为每次工艺或工程变更触发，无固定周期。日常处理的文档包含ECN/ECR、变更评估报告、图纸与BOM版本文件、工艺验证报告、切换计划、库存处置单、客户批准文件，核心字段包括变更编号、版本号、生效日期、关联物料编码、审批状态，版本号以Vx.y格式标注，生效日期采用YYYY-MM-DD格式。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据来源要求接口需适配不同外部系统的鉴权规则，需通过`Authorization`参数传递标准化的认证凭证。文档类型多且单次变更数据量差异大，需通过`variables`配置动态适配不同文档的字段映射规则。变更触发无固定周期，接口需支持按需调用，且需处理大型图纸、BOM文件的传输与解析，因此需要合理配置请求时长。同时，变更数据的准确性直接影响生产环节，需通过`responseData`校验核心字段以规避版本混用等风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 按对接系统生成的Bearer令牌格式填写 | 适配PLM、ERP等外部系统的统一鉴权要求 |
| 请求超时 | 600秒 | 处理大型BOM文件、工艺验证报告等文档需要较长处理周期 |
| `variables` | 按变更类型预设字段映射规则 | 适配ECN/ECR、切换计划等不同文档的字段结构差异 |
| `responseData` | 提取version、effectiveDate、approvalStatus字段校验 | 确保返回的变更数据版本与审批状态准确 |
| 单次请求关联文档数 | 前5条 | 避免单次请求数据量过载影响接口稳定性 |

## 容易做错的三处
- 现象：接口返回的`responseData`中version字段为空，原因：未在`variables`中配置版本字段的映射规则，导致外部系统返回的版本信息未被正确提取。
- 现象：批量生产环节出现新旧版本物料混用，原因：未通过`responseData`校验变更生效日期，导致未及时同步最新版本的工艺文档到生产系统。
- 现象：接口调用返回504超时状态码，原因：未将请求超时配置调整至合适时长，无法完成大型BOM文件的解析与同步。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的接口调试工具，调用测试接口，检查`Authorization`参数是否能正常通过外部系统鉴权，返回有效数据。
- 提交包含大型BOM文件的变更请求，确认接口响应时长未超过预设的600秒阈值。
- 查看`responseData`返回结果，确认version、effectiveDate等核心字段已被正确提取并完成校验。
- 触发变更同步动作，检查外部系统返回的关联文档条数是否符合预设的前5条上限。
