# 工艺变更与工程变更的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据由制造企业变更管理团队产生，涵盖ECN/ECR、变更评估表、图纸与BOM版本、工艺验证报告、切换计划、库存处置单及客户批准文件。数据来源包括PLM、ERP、MES系统、供应商资料、验证试验记录与客户特殊要求，更新随每次变更不定期触发，无固定周期。每份文档包含变更原因、影响范围、新旧版本标识、验证结果等字段，部分图纸类文档带有尺寸、公差等工程单位字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散于多类工业系统且格式差异大，接入时需配置支持异构数据源的适配规则。不定期的变更更新要求模型接入环节采用增量同步逻辑，避免全量拉取占用过多资源。文档包含工程字段与专业单位，需配置适配专业术语的上下文长度参数，防止关键信息被截断。多文档关联的变更审查场景，需限制单次处理的文档条目数，避免上下文溢出。客户批准文件的合规校验需固定调用逻辑，需配置工具调用的触发规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多份变更文档与关联图纸的上下文长度，避免关键工程信息截断 |
| `maxTokens` | 2000–3000 token | 控制单轮审查的输出长度，确保变更影响分析的完整输出 |
| `quoteMaxToken` | 1500 token | 限制知识库引用内容的长度，匹配变更文档的单段内容规模 |
| 工作流/API 工具选择配置 | auto | 自动触发合规校验工具，适配多类型变更文档的审查需求 |
| `AIPROXY_API_ENDPOINT` | 按FastGPT v4.17.0平台提供的专属地址填写 | 确保模型调用的链路稳定，适配企业内部网络环境 |
| `temperature` | 0.2–0.4 | 降低输出随机性，确保工程审查结果的一致性与准确性 |

## 容易做错的三处
- 现象：审查结果中出现新旧版本混用的文档条目，且未标记版本差异。原因：未配置`maxContext`参数的合理区间，导致旧版本文档的上下文被截断，无法识别版本标识。
- 现象：调用模型后返回状态码429，且无有效返回结果。原因：未设置合理的`maxTokens`取值，单次请求的token超限导致接口限流。
- 现象：客户批准文件的合规性校验未触发，返回结果中无相关判断。原因：`toolChoice`参数被设置为none，未启用自动工具调用逻辑，无法调用合规校验工具。

## 怎么确认配好了
- 上传一份完整的ECN文档与关联的BOM版本文件，检查模型是否能识别新旧版本的差异。
- 触发一次变更审查任务，查看接口返回的状态码是否符合预期，无异常报错。
- 配置测试用的客户批准文件，确认模型是否自动调用合规校验工具生成判断结果。
- 调整`temperature`参数的取值，观察输出结果的一致性变化，确认参数生效。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
