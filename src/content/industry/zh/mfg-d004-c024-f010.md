# 工艺变更与工程变更的技术文档交叉审查：知识库检索与召回

## 这个品类的数据长什么样
这个品类的核心数据来自制造企业PLM、ERP、MES系统，以及供应商资料、验证试验文件、客户特殊要求文档。日常产出的文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本文件、工艺验证报告、切换计划、库存处置单、客户批准文件，字段包含版本号、变更节点、物料编码、工艺参数、审批状态等，更新节奏为每次变更触发的不定期更新，无固定周期。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多来源的异构数据（结构化BOM、半结构化工艺记录、非结构化图纸与PDF报告）要求检索适配不同格式的内容解析；不定期的变更触发更新，需要支持增量同步与实时召回；文档包含表格、长文本、版本标识等专业字段，要求检索的语义匹配精度匹配行业术语；单次变更涉及多类关联文档，需要精准召回所有相关项，避免遗漏连锁影响的文件；客户特殊要求与供应商资料的跨数据源检索，需要打通不同系统的数据集关联。

## 配置怎么定
在FastGPT v4.17.0版本中，可通过以下配置项适配该品类的检索需求：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 匹配工艺参数、版本号等专业字段的语义一致性，过滤低相关的非变更文档 |
| `limit` | 前8条 | 覆盖单次变更涉及的多类文档（BOM、图纸、验证报告），避免召回冗余内容 |
| `searchMode` | hybrid | 结合关键词匹配与语义检索，适配ECN表单中的物料编码与工艺描述的混合查询 |
| `usingReRank` | 开启 | 对召回结果按变更关联度重排序，优先返回与当前变更直接相关的新版本文档与验证报告 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于当前变更主题自动扩展查询词，覆盖客户特殊要求、供应商资料等关联数据源 |
| `collectionIds` | 指定变更管理专属数据集ID | 限定检索范围仅为变更管理相关文档，避免混入其他品类的非关联数据 |

## 容易做错的三处
- 上传的ECN、BOM表格无法被完整分块召回，检索结果中缺失表格内的物料编码与工艺参数。原因是未针对表格类文档配置适配的分块规则，导致表格内容被截断或拆分错误。
- 检索时弹出“没有选择知识库”的提示，无法返回任何变更相关文档。原因是未在检索入口指定对应变更管理数据集的`collectionIds`，或未将目标文档绑定到正确的数据集。
- 召回结果中旧版本与新版本文档混排，未优先展示最新的验证报告与切换计划。原因是未开启`usingReRank`，或`similarity`阈值设置过低，无法区分版本关联度。

## 怎么确认配好了
- 上传一份ECN表格与BOM版本文档，执行基于当前变更主题的检索，检查表格内容是否被完整召回且分块合理。
- 在检索界面指定变更管理专属数据集的`collectionIds`，确认检索时不会弹出“没有选择知识库”的提示。
- 对比开启与关闭`usingReRank`后的召回结果顺序，确认新版本文档与工艺验证报告优先展示。
- 调整`similarity`参数区间，检查低相关的非变更文档是否被有效过滤。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
