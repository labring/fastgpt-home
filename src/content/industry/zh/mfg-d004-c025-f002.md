# 工装夹具与检具制造的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
本品类的数据主要来自汽车、航空、机械装配企业工装部门及专用工装供应商的日常产出，包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历等文档。数据来源涵盖产品数模与GD&T、工艺路线、三坐标数据、现场试用反馈、计量系统，更新按项目节点、每次产品变更及定期校准节奏推进，文档包含定位基准参数、干涉验证记录、重复性再现性数据等专属专业字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的多模态、专业参数密集型数据特征，对向量模型与索引环节带来多重约束。首先，文档包含工程图纸标注、计量数值等多模态内容，需适配支持专业工程文本与数值的向量模型，避免专业参数的语义丢失；其次，数据按项目动态更新，单项目数据集规模随产品复杂度波动，索引需支持增量更新与版本关联，确保交叉审查时仅调用当前有效数据；再者，文档存在时序性的变更履历，索引需保留版本标识以区分新旧数据；最后，包含GD&T公差、三坐标测量值等带单位的精确参数，向量提取需保留单位关联以确保检索匹配精度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配夹具图说明、校准记录等单文档段落长度，避免跨块拆分定位基准等关键专业参数 |
| 重叠长度 | 100–150 字符 | 保留跨段落的定位夹紧逻辑关联信息，防止关键验证逻辑被拆分断裂 |
| `maxToken` | 4096 token | 匹配多模态文档嵌入的最大输入限制，适配包含图纸标注文本的长段落内容 |
| `defaultToken` | 512 token | 用于短文档如单次校准记录的基础嵌入，平衡计算效率与语义完整性 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关文档，确保交叉审查时仅召回同项目或同类型工装数据 |
| 单次搜索上限 | 前10条 | 控制检索结果规模，适配工装审查的多文档关联验证需求 |

## 容易做错的三处
- 现象：索引过程耗时远超预期，单项目数据集完成索引超过2小时。原因：未根据单文档长度调整分块参数，导致分块数量过多，向量生成与索引写入的批量调度不合理。
- 现象：docker-compose部署环境中无法正常触发索引任务，界面显示索引任务状态为空。原因：未在docker-compose配置文件中挂载对应数据卷，导致索引脚本无法读取本地文档数据源。
- 现象：检索结果混入大量旧版本变更记录，导致交叉审查时误判当前工装的合规性。原因：未在索引配置中关联文档版本字段，导致新旧数据的向量相似度无法区分，混入无效历史数据。

## 怎么确认配好了
- 上传单份典型工装需求书，执行向量生成任务，检查分块结果是否保留完整的定位基准参数，无跨关键参数的拆分。
- 发起一次多文档交叉检索，核对返回结果的数量与配置的单次搜索上限一致，且结果匹配度符合预设的相似度区间。
- 查看索引日志，确认增量更新任务可按项目变更节点自动触发，无重复索引或遗漏文档的情况。
- 测试带标注的夹具图文档的嵌入生成，确认无报错且向量生成耗时符合预期。
