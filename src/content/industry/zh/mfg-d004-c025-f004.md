# 工装夹具与检具制造的技术文档交叉审查：工作流编排
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的日常文档包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历。数据来源为产品数模与GD&T、工艺路线、三坐标数据、现场试用反馈、计量系统。数据更新按项目节点、每次产品变更、定期校准执行。文档字段包含GD&T公差值、三坐标测量的毫米单位参数、校准周期标识，单份文档字符量随项目复杂度跨度较大。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且关联紧密，工作流需整合多源异构文档，需设置跨节点数据拉取规则。更新频率随项目与变更触发，需配置按需触发的节点规则，适配项目节点与变更事件。文档包含高精度公差参数，审查环节需保留原始字段关联，不能丢失毫米单位、校准周期等关键信息。单份文档跨度较大，需适配不同长度的文档处理，避免截断关键公差描述。多源数据的字段格式不统一，需在工作流前置配置字段标准化转换步骤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定工装ID、项目编号、校准日期三类核心字段 | 匹配品类文档的固定关联字段，实现跨节点数据联动 |
| `nodeId` | 绑定每个审查节点的唯一标识 | 便于追踪多文档审查的执行日志与结果关联 |
| 代码执行模块依赖安装路径 | FastGPT容器内的`/app/custom_lib`目录 | 适配容器化部署的标准自定义库路径，避免依赖丢失 |
| 工具调用触发条件 | 检测到文档中存在GD&T公差字段时触发 | 精准匹配工装夹具与检具的核心校验场景 |
| 并行AI对话节点数量 | 前3个节点 | 适配单项目下多文档并行审查需求，避免资源过载 |
| 超时阈值 | 600秒 | 覆盖复杂工装图纸的审查处理时长，按实测标定 |
| 单次文档处理字符上限 | 8000-12000字符 | 适配品类文档的平均字符跨度，避免截断关键公差内容 |

## 容易做错的三处
- 代码执行模块运行报错，控制台提示“ModuleNotFoundError: No module named 'xxx'”。原因是未将依赖库安装至FastGPT容器内的`/app/custom_lib`目录，导致运行时无法加载自定义依赖。
- 工具调用模块无返回结果，节点状态显示“未触发”。原因是未配置检测GD&T公差字段的触发条件，导致工装审查场景未被识别。
- `variables`绑定的工装ID、项目编号字段为空，后续节点无法获取核心项目信息。原因是未在工作流起始节点完成变量与文档字段的映射配置。

## 怎么确认配好了
- 上传预设了工装ID、项目编号的测试工装需求书，检查`variables`绑定的字段是否正确传递至后续工作流节点。
- 运行包含自定义库调用的代码执行模块，确认控制台无依赖报错，模块正常执行。
- 上传包含GD&T公差字段的检具操作书，确认工具调用模块正常触发并返回审查结果。
- 同时启动3个配置好的AI对话节点，确认节点无资源冲突且均完成执行。
