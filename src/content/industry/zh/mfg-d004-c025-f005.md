# 工装夹具与检具制造的技术文档交叉审查：工具调用与插件

## 这个品类的数据长什么样
工装夹具与检具制造的核心数据覆盖工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历等文档。数据来源于产品数模与GD&T规范、工艺路线、三坐标测量数据、现场试用反馈及计量系统。数据更新按单个项目推进，伴随产品变更触发更新，同时按定期校准周期同步更新。

## 这些特征在「工具调用与插件」这一环带来什么约束
品类文档类型多样，包含结构化的校准记录、工艺路线，与非结构化的夹具图、检具操作书，要求工具调用同时支持结构化数据解析与非结构化内容提取。数据按项目与产品变更触发更新，工具调用需适配动态更新的数据集，避免调用过时的基准或校准数据。数据来源涉及计量系统与现场反馈，工具调用需兼容工业计量接口的调用格式，确保获取的测量数据准确。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 函数调用配置 | 强制模式 | 限定模型仅调用预设工具完成文档交叉审查，防止生成非预期内容 |
| 工具调用超时时间 | 120 秒 | 适配夹具图解析、三坐标数据校验的处理时长，避免任务中断 |
| 单次工具调用上限 | 前 6 条 | 匹配单项目关联文档的数量规模，减少无效调用 |
| 上下文窗口限制 | 8000–12000 token | 承载工装需求书、校准记录等多份文档的完整内容 |
| 工具触发规则 | 按项目文档集 | 匹配品类按项目管理数据的更新节奏，避免跨项目数据混淆 |

## 容易做错的三处
- 调用工具接口返回413错误。原因是单次上传的工装文档总大小超出接口允许的载荷阈值，未对上传文件做分块处理。
- 使用通义千问3系列模型时，工具调用未按预期触发，模型仍生成自主推理内容。原因是未将`toolChoice`配置为强制调用模式，模型保留了自主推理权限。
- 工具调用未触发MCP streamable HTTP的流式响应，或无法识别MCP协议的调用请求。原因是当前版本未适配该流式协议，或配置未启用对应支持。

## 怎么确认配好了
- 发起单项目文档的测试调用，检查工具调用日志中是否仅触发预设的审查工具，无自主生成内容。
- 查看工具调用的耗时记录，确认未出现超时中断，调整超时时间至符合当前处理场景的时长。
- 核对工具返回的结果，确认仅包含当前项目关联的工装文档数据，无跨项目的冗余内容。
- 验证接口载荷限制配置，上传单项目最大文档包，确认未触发异常报错。
