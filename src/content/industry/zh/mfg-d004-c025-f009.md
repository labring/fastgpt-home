# 工装夹具与检具制造的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
工装夹具与检具制造的业务数据包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历。数据来源为产品数模与GD&T、工艺路线、三坐标数据、现场试用反馈、计量系统。更新按项目节点、每次产品变更、定期校准的节奏执行。文档包含定位基准参数、夹紧力数值、校准周期、干涉验证记录等字段，单位涵盖毫米、牛顿、小时等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且包含工程专业参数，模型接入需兼容多格式文档解析，适配GD&T、三坐标数据等专业格式。更新节奏不固定，需支持按需触发数据同步，适配项目变更后的实时更新。文档字段包含高精度数值与专业术语，模型输入需限制上下文长度避免混淆，同时需确保检索结果匹配专业字段。各文档间存在强关联，比如变更履历需关联原夹具图，配置时需保留文档间的关联关系，避免检索结果脱节。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配工装文档的多字段关联内容，避免截断专业参数 |
| `maxTokens` | 2000–3000 token | 覆盖检具操作书、验收报告等长文档的完整审查逻辑 |
| `temperature` | 0.1–0.3 | 保持专业术语与数值的一致性，降低随机偏差 |
| `AIPROXY_API_ENDPOINT` | 按部署节点填写对应地址 | 适配企业内部模型代理的访问路径 |
| `AIPROXY_API_TOKEN` | 与代理服务绑定的密钥 | 确保接入权限的安全性 |

## 容易做错的三处
- 现象：调用Azure OpenAI模型时返回协议不兼容报错，状态码400。原因：使用通用接入格式，未配置为Azure专属的API地址。
- 现象：模型输出结果遗漏校准记录、变更履历等关键文档内容。原因：`maxContext`取值过小，截断了多文档关联的上下文信息。
- 现象：检索返回的夹具图字段与定位基准方案不匹配。原因：未保留文档间的关联关系，配置时未关联变更履历与原设计文档。

## 怎么确认配好了
- 上传一份完整的夹具图与对应变更履历，检查模型是否能关联两者的变更内容。
- 调用测试接口，查看返回结果中是否包含GD&T参数、夹紧力数值等专业字段。
- 调整`temperature`参数，验证输出结果的一致性是否符合预期。
- 查看代理服务日志，确认`AIPROXY_API_TOKEN`的调用请求无权限报错。
