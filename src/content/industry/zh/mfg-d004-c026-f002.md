# 有色金属冶炼与电解的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来自精矿与辅料分析报告、DCS系统、槽电压电流监测数据、化验室产出报告、能源与环保监测装置。日常留存的文档包括配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账。数据更新节奏随每批原料、每炉或每槽作业完成触发，部分槽况与能耗数据为实时更新。文档字段包含原料成分占比、炉温参数、槽电压电流值、金属回收率指标，单位多为百分比、摄氏度、伏特、安培等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据多源且更新频繁，部分槽况与能耗数据为实时更新，要求向量索引支持高频增量同步与低延迟召回。文档包含原料成分占比、炉温、槽电压电流等多字段内容，单位类型多样，需要向量模型适配多字段混合编码逻辑。不同文档结构差异明显，配料单为短字段清单，熔炼记录与槽况记录为长文本序列，需要统一的分块规则适配不同长度的内容。核心指标如金属回收率、杂质含量的匹配精度要求较高，需确保索引召回时不会遗漏关键异常数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配熔炼记录、槽况记录的长文本内容，避免单块内容超出模型输入限制 |
| 重叠长度 | 100–150 字符 | 覆盖跨块的关键指标，确保配料单、化验报告中的连续字段不会被截断 |
| 相似度阈值 | 0.72–0.80 | 匹配金属回收率、杂质含量等核心指标的精度要求，过滤低相关性的历史记录 |
| `maxToken` | 4096 token | 适配主流向量模型的输入长度限制，符合FastGPT v4.17.0的参数规范 |
| `defaultToken` | 1024 token | 作为默认上下文长度，平衡召回内容的完整性与系统响应速度 |
| 单次搜索上限 | 前 8 条 | 覆盖单炉次或单槽位的关联记录数量，避免召回过多无关数据 |

## 容易做错的三处
- 尝试接入自建Qdrant向量数据库时提示无法连接，或知识库无法加载已有数据。原因：未在FastGPT平台正确配置自定义向量数据库的连接地址与权限参数，未同步数据库内的现有文档向量。
- 启用腾讯混元向量模型后，搜索结果为空或匹配度极低。原因：未正确配置模型渠道的API密钥与访问端点，未开启向量模型的索引启用开关。
- 配置索引模型后，系统提示超时或召回结果条数异常。原因：未根据实时数据更新频率调整索引刷新周期，单次搜索上限设置过低导致关键记录未被召回。

## 怎么确认配好了
- 查看向量数据库连接日志，确认无连接超时或权限报错，核对已同步的文档数量与实际存储数量一致。
- 输入核心指标关键词（如“铜回收率”“槽电压异常”），测试搜索结果的召回条数符合单次搜索上限的设置范围。
- 上传一份近期的熔炼记录，验证系统能正确召回同批次原料的关联历史文档。
- 检查模型配置页面，确认向量模型与索引模型的渠道参数已正确填写，无空值或格式错误。
