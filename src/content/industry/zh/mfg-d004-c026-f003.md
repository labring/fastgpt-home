# 有色金属冶炼与电解的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据通常来自精矿与辅料分析、DCS系统、槽电压电流监测、化验室、能源与环保监测设备。数据更新频率覆盖每批原料、每炉或每槽工况，部分指标实时更新。日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账，字段涵盖原料成分参数、炉温参数、槽体电压电流值、化验检测指标、环保监测数值。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据更新节奏多样且专业字段密集，多轮对话需同步保留近实时的槽况、炉温等参数，避免上下文脱节。文档字段覆盖生产全流程，提示词需明确限定检索范围为冶炼相关的配料、炉况、化验与环保记录，防止无关内容干扰检索结果。单批原料或单槽的文档关联性强，多轮对话需按批次或槽号关联上下文，避免跨批次的参数混淆。此外，环保台账与生产记录需联动检索，提示词需指定同时匹配生产与环保字段的规则，确保交叉审查的全面性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `messages` | 保留最近20轮对话上下文 | 冶炼数据多为批次关联，过多旧上下文会干扰当前槽况或炉号的参数匹配 |
| `variables` | 绑定当前批次号、槽号参数 | 限定检索范围为对应批次的生产与化验文档，避免跨批次数据混淆 |
| 单次搜索上限 | 前8条检索结果 | 该品类文档字段多，过多结果会超出模型处理上限 |
| 最大上下文 | 8000–12000 token | 专业术语多，需足够上下文承载多轮对话的参数关联，需符合FastGPT v4.17.0的上下文处理规则 |
| `chatId` | 按生产批次生成唯一ID | 隔离不同批次的对话历史，避免数据串扰 |
| 问题优化开关 | 开启专业术语优化 | 适配冶炼领域的专属术语，提升检索与回答的准确性 |

## 容易做错的三处
- 现象：本地部署后上传技术文档后，数据处理步骤显示为空。原因：未正确配置检索字段与该品类的文档结构匹配，导致系统无法识别配料单、槽况记录等目标文档。
- 现象：调用对话接口可返回模型问答结果，但AI对话环节未参考知识库内容。原因：未在`variables`中绑定对应批次或槽号的检索限定参数，导致检索范围覆盖了无关文档。
- 现象：MongoDB数据库中无法查询到对话历史记录。原因：未开启对话历史存储的配置开关，或`chatId`生成规则不符合系统存储要求。

## 怎么确认配好了
- 发起多轮对话，输入当前批次的槽号参数，核对检索结果是否仅包含对应批次的熔炼、化验文档。
- 调用`messages`相关接口，验证上下文是否仅保留指定轮次的对话内容，无冗余旧数据。
- 检查`variables`参数是否绑定了当前生产场景的专属字段，确保检索范围精准。
- 查看MongoDB存储目录，确认存在以`chatId`为标识的对话历史记录条目。
