# 有色金属冶炼与电解的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账。数据来源覆盖精矿与辅料分析、DCS系统、槽电压电流监测、化验室数据、能源与环保监测平台。更新节奏分为每批原料、每炉或每槽、实时三类。文档字段包含品位、含水率、投料量、炉温、槽电压、电流值等，对应单位多为百分比、吨、摄氏度、伏特、安培。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源导致不同文档的字段格式、单位存在差异，需要模型接入时适配多源数据对齐，因此需调整上下文拼接的参数限制。实时更新的槽况数据要求模型响应速度匹配生产节奏，不能设置过大的上下文窗口。不同文档的更新频率差异，需要配置灵活的上下文刷新规则，避免冗余数据占用模型资源。合规类的环保台账文档要求输出格式固定，需限制模型的自由生成空间，保障审查结果符合业务规范。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配多源文档的字段拼接，避免超出模型上下文限制，覆盖单批次生产的全量核心文档 |
| `maxTokens` | 2000–3000 token | 匹配单份技术文档的审查输出长度，平衡响应速度与内容完整性，适配生产节奏要求 |
| `quoteMaxToken` | 1500 token | 限制引用源文档的token占比，确保审查逻辑聚焦品位、槽电压等核心业务字段 |
| `temperature` | 0.2–0.4 | 保障审查结果的一致性，避免因参数波动导致杂质核算、金属回收率计算出现偏差 |
| 工作流/API 工具选择配置 | auto | 自动选择是否调用工具处理多源数据对齐，适配不同文档格式的格式差异 |
| `AIPROXY_API_ENDPOINT` | 按企业内网部署节点配置 | 适配企业内网的模型访问路径，保障敏感生产数据的传输安全 |

## 容易做错的三处
- 现象：模型调用返回的运行时间统计异常，离线模型显示总耗时，在线模型仅显示首token耗时，无法统一查看。原因：未统一配置`AIPROXY_API_ENDPOINT`的响应解析规则，不同模型的返回格式未做适配。
- 现象：调用工作流时返回API Key错误提示，提示使用了错误的密钥类型。原因：混用了全局通用API Key与应用专属密钥，未按要求配置对应权限的密钥。
- 现象：审查结果中部分核心字段（如槽电压、品位）缺失。原因：未调整`maxContext`参数，导致多源文档拼接后超出上下文限制，部分字段被截断。

## 怎么确认配好了
- 上传单份配料单与电解槽况记录，检查模型返回的审查结果是否包含所有核心业务字段，无缺失或截断情况。
- 调用工作流测试，查看返回的运行时间统计是否统一显示总耗时，无首token单独显示的异常情况。
- 验证API Key配置，使用应用专属密钥发起调用，确认无权限错误提示。
- 调整`temperature`参数至0.3，多次上传同一份文档，检查结果波动是否在可接受范围内，无明显偏差。
