# 服装裁剪与缝制的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
该品类的日常文档包含工艺单、CAD样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等。数据来源包括订单与尺码表、CAD设计文件、面辅料检验记录、车间吊挂系统数据、验针机检测结果及客户封样件信息。数据更新随每笔订单、每款服装、每批生产批次同步调整，文档字段包含具体尺码、面料色号、裁片数量、工序质检标准等，格式随订单需求灵活调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类文档类型多且随订单高频更新，要求多轮对话需绑定当前订单的专属上下文，避免跨订单数据混淆。裁片不可逆的特性要求审查结果需精准匹配工艺要求，提示词需明确校验核心业务字段。工序拆解依赖多维度文档，多轮对话需按工序节点逐步引导用户补充信息，避免一次性输入过多内容导致遗漏。不同来源的数据格式差异较大，提示词需统一字段提取规则，确保跨系统数据的一致性校验。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前订单ID | 确保多轮对话上下文仅关联当前订单的文档数据，避免跨订单干扰 |
| `messages` | 按工序节点分段传入 | 适配品类文档多且单条内容较长的特征，避免模型过载 |
| `variables` | 注入当前订单的尺码表、排料图ID | 精准调用专属业务数据，匹配订单个性化需求 |
| 最大上下文长度 | 2500–3000 token | 覆盖单订单核心审查文档的完整信息，适配业务文档总量 |
| 召回结果数量 | 前6–10条 | 覆盖当前订单的核心文档，避免冗余数据干扰审查逻辑 |
| 响应token上限 | 1000–3000 token 按实测标定 | 因单条审查内容长度差异较大，需结合实际场景调整 |

本配置基于FastGPT v4.17.0版本

## 容易做错的三处
- 调试预览界面对话出现报错，提示缺少必要字段。原因是未通过`variables`注入当前订单的专属数据，导致对话无法调用对应订单的工艺单、排料图等文档。
- 部分问题的最大响应token自动变为200，生成内容过短。原因是未明确配置响应token上限，或上下文长度超出预设范围，触发了系统自动截断。
- 对话过程中无法关联到当前订单的知识库内容。原因是未通过`chatId`绑定当前订单的上下文，导致对话调用了其他订单的知识库数据。

## 怎么确认配好了
- 发起绑定当前订单ID的测试对话，核对对话上下文是否仅包含该订单的相关文档，未混入其他订单数据。
- 输入不同复杂度的审查问题，确认响应内容长度符合预期，未出现无提示的自动截断情况。
- 尝试在对话中补充新的质检结果，确认系统可将信息关联到当前订单的专属知识库条目。
- 检查对话过程中是否自动提取了文档中的核心字段，如尺码、面料色号等，未出现字段遗漏。
