# 服装裁剪与缝制的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
该品类的日常文档包含工艺单、CAD样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等。数据来源包括订单与尺码表、CAD设计文件、面辅料检验记录、车间吊挂系统数据、验针机检测结果、客户封样资料。数据更新节奏为每订单、每款、每批调整，单份文档包含版型参数、工序要求、尺码配比、面料规格等字段，单位涵盖厘米、克重、件数等。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的多源异构文档与高频更新特性，要求工作流需适配不同格式的工艺单、排料图等文件读取。裁片不可逆且工序密集的特点，要求工作流需覆盖版型、工序、包装配比的全链路交叉审查，避免遗漏关键环节。款式多、季节性强的属性，要求工作流支持快速切换不同款的审查规则，无需重复配置。同时，数据来源涉及车间设备与客户封样，需在工作流中配置权限隔离，确保敏感数据不被越权访问。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本界面。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 该品类单份完整工艺单的平均字符数处于该区间，可覆盖全量审查所需的文档内容 |
| `variables`绑定规则 | 绑定订单号、面料批次号 | 关联对应订单的专属工艺单、排料图数据，避免跨订单数据混淆 |
| `nodeId`配置 | 指向文本内容提取节点的`nodeId` | 精准定位需要抽取的工艺单、排料图核心字段 |
| 超时时间 | 600 秒 | 多源文档交叉审查需处理CAD样板与检验记录，耗时较长，该时长可覆盖常规审查流程 |
| 单次召回文档上限 | 前 8 条 | 该品类单订单关联的审查文档数量通常不超过8份，可覆盖全量审查所需数据 |
| 结果重排 | 开启 | 按工序优先级排序审查内容，确保版型、裁片配比等关键环节优先校验 |

## 容易做错的三处
- 现象：工作流在完成首次文档审查后，无法承接后续用户的关联问题，上下文未延续。原因：未在工作流中绑定`variables`参数存储对话上下文，或未配置聊天记录调用规则。
- 现象：文本内容提取节点未正确返回排料图的裁片配比数据，字段为空。原因：未将`nodeId`指向正确的文档解析节点，或绑定的`variables`未关联对应订单的排料图文件。
- 现象：工作流执行超时，返回异常状态码。原因：未调整超时时间，或召回的文档数量超出预设上限，导致处理时长超出阈值。

## 怎么确认配好了
- 触发工作流，输入某订单的工艺单相关问题，核对返回的审查结果是否包含该订单专属的面料批次、尺码配比信息。
- 测试多轮对话场景，输入第二个关联问题，核对上下文是否延续首次审查的订单信息。
- 模拟异常输入，比如输入超出预设上下文长度的内容，核对工作流是否按配置触发对应处理逻辑。
- 查看工作流运行日志，核对`nodeId`与`variables`参数是否正确绑定，无配置错误。
