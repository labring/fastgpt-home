# 服装裁剪与缝制的技术文档交叉审查：知识库检索与召回

## 这个品类的数据长什么样
该品类的典型主体为服装OEM/ODM工厂、品牌供应链部门及裁剪缝制车间。日常产生的文档包含工艺单、样板文件、排料图、裁剪单、首件封样记录、工序质量表及包装配码单。数据来源涵盖订单与尺码表、CAD样板文件、面辅料检验记录、吊挂系统数据、验针机记录及客户封样物料。数据更新频率为每订单、每款、每批更新一次，单款文档包含明确的尺码、裁片数量、面料方向等字段，部分文档包含非结构化的图像内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据高频更新的特性要求知识库支持按订单款号的增量同步，避免全量重建索引的耗时。多类型文档并存的特征要求检索同时适配文本关键词与语义向量，覆盖工艺单的文字要求与样板的图像细节。单款文档包含的特定字段（如尺码、裁片方向）要求检索关键词需精准匹配业务字段，避免召回无关款式的文档。出错后果严重的特性要求检索召回的结果需具备较高置信度，避免因错误参考文档导致批量生产偏差。工序密集的特性要求检索召回的结果需控制在合理数量内，避免超出上下文窗口导致关键信息丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 服装工艺单的关键词与语义匹配需要较高置信度，避免召回非当前款号的无关文档 |
| `limit` | `前6条` | 单款工艺相关文档数量较多，过多召回会超出对话上下文窗口，过少会遗漏关键工序要求 |
| `searchMode` | `vector+keyword` | 该品类既有文本类工艺要求（如“双针车缝份1cm”），又有语义类需求（如“首件封样的色差标准”），适配多类型文档检索 |
| `usingReRank` | 开启 | 该品类文档字段关联紧密，重排可过滤语义相似但工序不匹配的结果，提升召回准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 订单尺码表、排料图的字段需扩展检索，例如将“裁片配套”扩展为“裁片数量匹配、面料方向一致” |
| `collectionIds` | 按当前订单款号绑定的知识库集合ID | 该品类按订单款独立更新数据，限定集合ID可避免召回其他款式的无关文档 |

## 容易做错的三处
- 现象为AI对话中返回的结果未引用知识库内容，调试界面检索正常但对话阶段无召回结果。原因是未将`collectionIds`配置为当前订单款号的绑定集合，导致检索范围覆盖全量知识库，召回了无关款的文档。
- 现象为检索返回的结果条数不符合预期，无法按固定数量限制，仅能通过分数阈值控制。原因是误将分数阈值作为条数限制依据，未正确配置`limit`参数指定召回条数。
- 现象为文本文件中嵌入的图片无法被知识库识别并生成索引，无法通过图片内容完成检索。原因是未开启多模态检索配置，或未通过FastGPT的图片预处理工具将图片转换为可索引的格式。

## 怎么确认配好了
使用FastGPT v4.17.0版本的知识库检索功能完成以下核对动作：
- 进入知识库检索调试界面，输入当前订单的工艺关键词（如“160/84A 左前片”），确认召回的文档均属于当前款号的绑定集合。
- 调整`similarity`参数的取值，验证返回结果的匹配度是否符合工艺单的要求，无明显无关的跨款文档。
- 开启`usingReRank`功能后，对比重排前后的结果顺序，确认高相关的工序文档排在前列。
- 上传包含裁剪样板图片的工艺单文本，确认知识库生成的索引中包含图片的语义描述，可被正常召回。
