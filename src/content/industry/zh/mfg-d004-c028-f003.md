# 来料检验与供应商质量的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来自采购订单、图纸规格、供应商质保书、检验设备、历史质量数据及供应商门户。日常处理的文档包含检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告及让步接收审批单。数据更新随每批来料产生新记录，每月或季度完成供应商评价更新，不定期开展专项审核。文档包含批次号、抽样比例、不合格项类型、供应商代码等字段，部分文档附带量化检测数值与单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据随每批来料、月度/季度评价及不定期审核更新，多轮对话需严格区分不同批次、周期的上下文，避免跨批次或跨周期数据混淆。不同文档类型对应专属字段，提示词需明确指定当前审查对应的文档类型，防止提取错误字段。临时异常联络单与常规供应商审核报告的时效性差异，要求多轮对话中标记当前任务的时间范围，避免数据误用。数据来源包含外部供应商门户内容，需在对话中限定检索范围为当前关联供应商的历史数据，确保审查范围准确。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前来料批次的唯一字符串 | 确保多轮对话上下文仅关联当前批次的检验与审查数据，避免跨批次混淆 |
| `messages` | 保留前10轮交互内容 | 覆盖单次来料检验的完整审查流程，覆盖从抽样判定到异常处理的全步骤 |
| `variables` | 预设供应商代码、批次号为固定变量 | 自动带入当前审查的核心参数，减少重复输入与参数错误 |
| 最大上下文窗口 | 8000–12000 token | 容纳多份检验规范、抽样方案及历史报告的核心内容，满足交叉审查的信息需求 |
| 单次搜索上限 | 前5条 | 限定检索历史质量数据的范围，避免冗余信息干扰审查逻辑 |
| 问题优化 | 按实测标定 | 适配该品类文档的专业术语与字段规则，提升提示词的识别精度 |

## 容易做错的三处
- 对话运行时出现`Cannot read properties of null (reading 'q')`报错。原因是未正确配置`chatId`参数，导致系统无法识别当前对话的会话上下文。
- 多轮对话中全局变量无法在会话间保持一致。原因是未将供应商代码、批次号等核心参数写入`variables`配置，导致每次交互重置变量值。
- 工作流中问题分类结果偏差较大。原因是提示词未限定审查范围为来料检验与供应商质量的专属文档，未明确字段提取规则，导致模型混淆其他品类的业务逻辑。

## 怎么确认配好了
- 发起模拟来料审查对话，核对`chatId`参数是否与当前批次绑定，确保上下文仅关联当前任务。
- 查看多轮对话记录，确认`variables`参数中的核心字段在会话间未被重置，保持一致。
- 输入测试查询，验证模型是否仅检索当前供应商的历史质量数据与文档，未引入无关内容。
- 确认当前使用的FastGPT版本为v4.17.0，确保配置项符合版本规范。
