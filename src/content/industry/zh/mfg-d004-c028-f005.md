# 来料检验与供应商质量的技术文档交叉审查：工具调用与插件

## 这个品类的数据长什么样
该品类数据来源涵盖采购订单、图纸规格、供应商质保书、检验设备日志、历史质量台账及供应商门户文档。日常生成检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告、让步接收审批单等文档。数据更新随每批来料同步生成对应报告，每月或季度完成供应商质量评价，不定期开展审核更新。文档包含批次号、检验参数、合格判定结果、供应商编码等字段，部分文档关联图纸版本与抽样标准编号。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且更新无固定周期，工具调用需支持多数据源同步拉取，避免因数据源更新不及时导致审查偏差。文档类型多样且字段差异大，需配置适配不同文档结构的解析规则，确保跨文档字段关联的准确性。来料批次关联的文档需绑定唯一批次标识，工具调用时需传入批次参数过滤对应数据，防止跨批次数据混淆。供应商质量数据需关联历史异常记录，工具调用需支持跨知识库关联查询，保障根因分析的完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配检验报告、8D报告等多类型文档的自动函数调用，无需手动指定调用目标 |
| 文档分块规则 | 按文档类型区分：检验报告500–800字符，8D报告按章节分块 | 匹配不同文档的结构特征，保障跨文档字段关联的上下文完整性 |
| 单次搜索上限 | 前10条 | 覆盖该品类需关联的供应商、历史质量、来料批次等多维度数据，避免信息遗漏 |
| `functionCall` | 开启必填字段校验 | 确保调用工具时传入批次号、供应商编码等核心字段，防止无效审查 |
| 上下文窗口上限 | 8000 token | 覆盖图纸规格、历史异常记录、当前来料报告等关联文档的完整审查需求 |
| 数据源同步频率 | 按实测标定 | 适配每批来料、季度评价等非固定更新节奏，避免数据过期或冗余 |

## 容易做错的三处
- 调用工具时返回「缺少必填字段」报错，原因是未在`functionCall`配置中开启必填字段校验，未强制传入批次号或供应商编码。
- 工作流调用API上传文件后无法关联对应知识库，原因是未将知识库ID配置为全局变量，或传入参数的格式不符合系统要求。
- 搜索结果条数与预期不符，原因是单次搜索上限设置过低，未覆盖多维度关联数据的检索需求。

## 怎么确认配好了
- 上传一份标准来料报告与对应供应商质保书，触发工具调用，检查返回结果中是否包含批次号、检验参数等核心字段。
- 调用工作流API上传文档，查看系统日志中是否正确关联了目标知识库ID与全局变量参数。
- 模拟跨文档关联查询，验证是否能检索到对应供应商的历史8D报告与异常记录。
- 在FastGPT v4.17.0的调试界面中，手动触发工具调用，确认`toolChoice`自动匹配的函数与当前审查任务类型一致。
