# 来料检验与供应商质量的技术文档交叉审查：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据主要来自采购订单、图纸和规格、供应商质保书、检验设备、历史质量数据、供应商门户。日常处理的文档包含检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告、让步接收审批。数据更新随每批来料产生新记录，每月或季度完成供应商评价更新，不定期开展专项审核更新数据。文档包含批次号、供应商信息、检验项、合格判定结果等字段，无统一强制单位，随具体文档类型调整。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据特征对引用来源与溯源环节带来多重约束。首先，数据来源分散且更新节奏灵活，每批来料、月度评价及临时审核均会产生新数据，需确保检索时可精准匹配当前批次、供应商等核心关联信息，避免跨批次、跨供应商的无效引用。其次，日常处理的文档类型多样，不同文档的字段逻辑差异显著，需准确识别检验项、合格判定结果等专属字段用于溯源，无法依赖通用文档的字段规则。另外，部分临时审核数据需快速纳入溯源范围，要求配置支持动态加载最新更新的文档，保障溯源结果的时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前5-8条 | 匹配该品类多来源、多批次的检索需求，避免过多冗余引用干扰质量判定 |
| `quoteMaxToken` | 800–1200 token | 适配该品类单份检验或审核文档的平均长度，确保完整引用关键检验、审核信息 |
| 返回引用详情 | 开启（返回每条引用的前200字符内容） | 展示批次号、供应商信息等专属字段，同时控制返回数据大小 |
| `responseData` | 结构化返回 | 按元数据与内容分离的格式返回引用数据，便于关联批次、供应商等核心信息 |
| `detail` | 完整字段返回 | 保留原始文档的字段格式，避免因字段缺失导致溯源信息不完整 |
| 动态数据加载延迟 | 30–60秒 | 适配临时审核数据的快速加载，确保新生成的审核文档可被及时检索 |

## 容易做错的三处
- 现象：检索结果返回的引用文档与当前来料批次不匹配，批次号字段为空。原因：未正确配置基于批次号、供应商信息的检索变量，导致无法精准匹配当前来料的关联文档。
- 现象：配置`quoteMaxToken`后，部分长文档的关键检验项被截断，无法完成完整溯源。原因：`quoteMaxToken`取值区间设置过小，未适配该品类长文档的平均长度。
- 现象：无法从知识库引用结果中提取批次号、合格判定结果等专属字段，溯源信息不完整。原因：未开启`detail`配置项，或未配置对应字段的提取规则，导致引用数据仅返回非结构化摘要。

## 怎么确认配好了
以下核对动作需基于FastGPT v4.17.0版本执行。
- 上传一份当前批次的来料报告与供应商审核报告，执行检索，核对返回的引用文档是否包含当前批次的关键信息。
- 调整`quoteMaxToken`的取值，验证长文档的关键检验项是否完整显示，无截断情况。
- 检查返回的引用数据是否包含批次号、供应商信息等专属字段，确认`detail`配置项已开启。
- 提交临时审核生成的新文档，验证检索结果是否可覆盖该新文档，确认动态加载配置生效。
