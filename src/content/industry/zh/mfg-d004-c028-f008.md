# 来料检验与供应商质量的技术文档交叉审查：文档解析与分块

## 这个品类的数据长什么样
这个品类的核心数据来自采购订单、图纸规格、供应商质保书、检验设备记录、历史质量数据与供应商门户。日常处理的文档包含检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D整改单与让步接收审批单。数据更新随每批来料、每月或季度供应商评价、不定期审核推进，文档结构包含批次号、送检数量、检验项目、合格判定项、供应商编号等字段，部分文档附带数值型参数与单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的数据具备多来源与多格式的特性，要求解析环节需兼容xlsx、pdf、ppt、word等多种文档类型，同时需适配不同供应商提交文档的格式差异。高频更新的业务节奏，要求解析与分块流程具备时效性，避免因解析延迟影响来料检验进度。文档中包含批次号、供应商编号等强关联字段，分块需保留这些关键标识，确保后续交叉审查可精准溯源至对应文档与供应商。此外，业务出错后果严重，解析环节需规避编码错误、分块丢失核心字段等问题，保障审查依据的完整性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 来料检验文档包含短字段与长文本说明，该区间可平衡字段完整性与语义连贯性 |
| `chunkSplitter` | 按段落+语义边界 | 供应商文档格式多样，段落拆分可保留检验规范、异常联络单等文档的逻辑结构 |
| `customPdfParse` | 启用自动编码检测 | 可避免部分供应商提交的pdf文档出现`the argument ‘windows-1252’ is invalid encoding`类编码报错 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 批量来料文档体积较大，该时长可覆盖多格式文件的完整解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持供应商提交的批量图纸、质保书等大体积文档上传 |
| `chunkSettingMode` | 手动配置 | 可针对xlsx表格、ppt审核报告等品类专属文档调整分块规则，适配不同文档结构 |

## 容易做错的三处
- 上传xlsx格式的来料报告后，分块结果缺失表头字段，原因是未开启表格专属分块配置，默认分块规则未识别表格结构，导致核心检验信息丢失。
- 解析ppt格式的供应商审核报告时，界面弹出`the argument ‘windows-1252’ is invalid encoding`报错，原因是未启用自动编码检测，直接使用默认编码解析非标准编码的ppt内嵌文本。
- 批量上传多份供应商质保书后，解析任务超时失败，原因是`PARSE_FILE_TIMEOUT_SECONDS`设置过短，未覆盖大体积批量文档的解析时长。

## 怎么确认配好了
- 上传单份xlsx格式的来料报告，检查分块结果是否包含送检批次、检验结果等核心字段。
- 上传一份使用非标准编码的pdf文档，确认解析过程未出现编码报错。
- 调整`chunkSize`参数后，对比不同取值下的分块语义完整性，选择符合品类文档逻辑的取值。
- 批量上传10份供应商审核报告，确认上传与解析流程未触发文件大小或超时限制报错。
