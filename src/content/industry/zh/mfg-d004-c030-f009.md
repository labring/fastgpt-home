# 橡胶混炼与制品硫化的技术文档交叉审查：模型接入与配置
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类数据来自配方系统、原材料批次记录、密炼机、门尼与流变仪、硫化机及实验室检测设备。日常文档包含配方单、称量记录、混炼曲线、胶料快检表、硫化工艺卡、模具台账与成品性能报告。数据更新随每车胶料、每批原材料、每模次生产同步生成，单份文档包含精确的投料量、工艺参数与检测数值，字段多带专用单位如千克、摄氏度、分钟。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类数据更新频率高且单条记录参数密集，要求模型接入时需适配高频更新的短周期文档，同时需处理包含多维度工艺参数的长文本内容。由于数据关联生产全流程，交叉审查需对齐多来源文档的参数一致性，因此配置需优先保障上下文召回的准确性与实时性。另外，该品类工艺不可逆交联的特性决定了生产错误无法返工，配置需强化参数校验的严谨性，避免因模型输出偏差导致批量报废。同时，多源异构的文档格式要求配置需兼容文本与可视化数据的解析需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 该品类单份关联文档组（配方+混炼+硫化记录）的总token量通常在此区间，保障完整召回审查所需的历史数据 |
| `maxTokens` | `4000–6000 token` | 交叉审查需同时比对多份文档的参数，避免因token溢出截断关键工艺数值 |
| `quoteMaxToken` | `1500 token/条` | 单份工艺文档（如硫化工艺卡）的核心参数段长度集中，精准截取可提升审查精度 |
| `temperature` | `0.1–0.3` | 交叉审查需严格对齐参数一致性，不宜采用高随机性输出 |
| `vision` | 开启 | 该品类包含混炼曲线、检测报告图片等可视化数据，需通过视觉模型解析图表数值 |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的专属地址填写 | 适配国内或海外模型调用的网络环境要求，保障接口连通性 |

## 容易做错的三处
- 现象：设置了较大的`maxTokens`仍出现token溢出报错，部分文档无法完成审查。原因：未同步调整`maxContext`参数，上下文召回的总token量超过模型上限。
- 现象：上传混炼曲线图片时部分成功部分失败，界面返回参数错误提示。原因：未开启`vision`配置，或上传图片的分辨率超出模型支持的范围。
- 现象：模型输出的审查结果参数偏差较大，与实际工艺要求不符。原因：将`temperature`设置过高，导致模型输出随机性超出审查所需的严谨性要求。

## 怎么确认配好了
- 导入单份完整的配方单与对应混炼记录，检查模型是否能完整召回所有字段参数，无截断情况。
- 上传混炼曲线图片，验证模型是否能正确识别图表中的温度、时间数值，无识别失败情况。
- 发起一次交叉审查任务，核对模型输出的参数比对结果与原始文档的一致性。
- 查看接口调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置无误，无连接超时报错。
