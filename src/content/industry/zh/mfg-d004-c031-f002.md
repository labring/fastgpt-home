# 水泥熟料与粉磨的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类数据覆盖水泥企业矿山、生料、烧成、粉磨、质量和能源部门的日常文档，包括生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录与能源报表。数据来源涵盖在线成分分析系统、DCS控制系统、化验室设备、窑磨设备台账、原燃料登记本与能源计量装置。更新节奏包含实时的设备运行数据、每班的巡检与操作记录、每日的化验报告与能源报表。文档结构多为结构化表格与段落式记录，字段包含原燃料成分、窑温参数、熟料强度指标等，对应单位为吨、摄氏度、兆帕等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的多源异构数据、差异化更新节奏与专业参数特征，为向量模型与索引环节带来多重约束。在线成分分析、DCS系统的实时数据与纸质巡检记录、手工台账的格式差异，需要在索引前完成统一格式预处理，避免嵌入向量出现偏差。实时、每班、每日的混合更新节奏，要求区分增量索引与批量索引的处理逻辑，混合执行会拖慢整体索引效率。文档中包含大量工业专业参数与数值型字段，向量模型需适配这类参数的语义与数值关联，否则无法准确匹配交叉审查的逻辑需求。跨部门文档的关联属性，也要求索引支持跨文档关联检索，以覆盖交叉审查的完整场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 该品类文档多为段落式业务记录与结构化表格，该区间可保留单条业务逻辑的完整性 |
| 重叠长度 | 100–150 字符 | 避免分块破坏跨段落的专业参数关联，保障向量嵌入的语义连贯性 |
| maxToken | 8192 token | 适配该品类长段落的窑操作记录、配料方案文档，避免截断关键参数内容 |
| defaultToken | 4096 token | 平衡向量嵌入效率与多数短文档的内容覆盖需求 |
| 相似度阈值 | 0.72–0.85 | 区分工业专业参数的匹配精度，避免误匹配或漏匹配交叉审查的关联文档 |
| 单次搜索上限 | 前 10 条 | 覆盖该品类跨部门文档的多数关联场景，满足交叉审查的检索需求 |

## 容易做错的三处
- 现象：索引任务耗时远超预期，后台日志显示分块处理进度长时间无更新。原因：未按更新节奏区分增量索引与批量索引，混合处理实时数据与每日批量数据导致资源竞争。
- 现象：创建知识库时，文本理解模型下拉框未显示已添加的ollama qwen2.5模型。原因：未完成语言模型与索引模型的关联配置，或模型部署路径未正确同步至系统。
- 现象：交叉审查返回的结果中包含大量不相关的文档片段，无法匹配业务逻辑。原因：分块长度设置不符合该品类文档的业务逻辑长度，导致专业参数的语义关联被破坏。

## 怎么确认配好了
- 进入FastGPT v4.17.0的索引管理页面，查看任务进度，确认实时数据与批量数据的索引任务按预设节奏执行。
- 在模型配置页面验证，确认已添加的ollama qwen2.5模型与bge-m3模型均显示在对应配置项中。
- 输入一条包含熟料强度参数的查询，检查返回结果是否包含化验报告与质量控制通知单等相关文档。
- 查看系统日志，确认未出现向量嵌入失败或索引超时的报错信息。
