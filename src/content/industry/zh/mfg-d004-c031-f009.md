# 水泥熟料与粉磨的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
这个品类的日常文档包含生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检、能源报表。数据来源为在线成分分析、DCS系统、化验室、窑磨设备、原燃料台账、能源计量设备。数据更新节奏分为实时、每班、每日三类，其中窑操作记录与在线成分分析数据为实时更新，设备巡检记录按每班归档，能源报表与质量控制通知单按每日生成。文档字段包含原料掺加参数、烧成温度、粉磨比表面积、强度检测值等，对应单位分别为无（参数项）、摄氏度、平方米每千克、兆帕。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源与差异化的更新节奏，要求模型接入配置需适配不同时效性的文档片段，避免因上下文加载滞后导致审查结果偏差。专业文档包含大量专有参数与术语，需配置对应的模型识别规则，确保交叉审查时能准确匹配配料、窑炉、粉磨相关的核心字段。不同文档的内容长度差异较大，需合理限制上下文与引用片段的token数量，避免超出模型的处理上限。同时，该品类的审查结果直接关联熟料质量与设备运行安全，配置需保障结果的一致性与准确性，不宜过度放宽参数波动范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 水泥熟料相关文档包含多段配料、窑炉、粉磨数据，需容纳多份巡检、化验报告的核心片段 |
| `temperature` | `0.1–0.3` | 专业文档交叉审查需保持结果一致性，避免参数波动导致的专业判断偏差 |
| `quoteMaxToken` | `1500–2000 token` | 单份化验报告或窑操作记录的核心内容长度区间 |
| `toolChoice` | `auto` | 需根据文档类型自动适配审查逻辑，处理配料、巡检、报表等不同类型的文档 |
| `AIPROXY_API_ENDPOINT` | `企业内部合规代理地址` | 需对接自有DCS、化验室数据源，保障数据访问的安全与合规 |
| `AIPROXY_API_TOKEN` | `企业身份认证生成的专属密钥` | 限制未授权的数据源访问，保障数据链路的权限安全 |

## 容易做错的三处
- 现象：调用时提示“无可用向量模型”，原因是未将适配水泥熟料成分分析的向量模型添加至API渠道配置，或配置路径错误。
- 现象：测试模型时提示‘KokoroModel’ object has no attribute 'mode'，原因是未在API渠道配置中启用对应模型的适配参数，导致模型调用链路异常。
- 现象：从生料配料方案文档中提取参数返回空值，原因是未针对专有字段配置对应的识别规则，导致模型无法匹配文档中的专业参数。

## 怎么确认配好了
- 查看FastGPT v4.17.0的API渠道管理页面，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置状态为正常连接。
- 上传单份生料配料方案文档触发审查，核对模型返回的引用片段长度是否符合`quoteMaxToken`的配置区间。
- 提交多份不同类型的文档（巡检记录、化验报告），确认模型的审查逻辑与`toolChoice`的配置规则一致。
- 调整`temperature`参数后，提交同一文档进行两次审查，核对两次结果的一致性，确认参数生效。
