# 汽车整车总装的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类数据来源包括ERP/MES系统、VIN与配置系统、供应商批次管理系统、拧紧工具终端、EOL检测线及质量追溯系统。日常文档涵盖生产订单、VIN清单、装配作业指导书、拧紧数据、下线检测报告、返修记录与一致性放行文件。数据更新节奏为每车级实时更新、按班批量同步。文档字段包含VIN码、工位编号、扭矩值、检测项编号等，对应单位包括牛米、毫秒等。

## 这些特征在「向量模型与索引」这一环带来什么约束
以VIN为核心的单车主线数据，要求索引需支持按VIN快速过滤匹配，避免跨车辆数据干扰。实时更新的拧紧、检测数据，要求索引支持增量同步，降低全量重建的耗时。多类型文档混合入库，要求索引结构兼容结构化字段与非结构化文本，同时保留字段关联关系。高节拍混线生产带来的文档总量随产能线性增长，要求索引的检索响应速度匹配生产节拍，避免拖慢审查流程。一致性放行文件的合规性审查需求，要求向量检索的召回精度匹配业务校验标准。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配装配作业指导书的段落长度，避免块内关键信息断裂 |
| 重叠长度 | 100–200 字符 | 保留跨块的VIN码、扭矩参数关联，防止核心关联信息被分割 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 512 token | 作为单条短文档的默认分词上限，平衡检索效率与信息完整性 |
| `maxToken` | 8192 token | 针对一致性放行文件等长文本文档，扩展上下文审查长度 |
| 相似度阈值 | 0.75–0.85 | 区分合规与异常的拧紧数据、检测结果，适配总装环节的精度要求 |

## 容易做错的三处
- 切换知识库索引时出现60秒超时。原因是未配置增量索引同步，全量重建索引时未拆分批次，超出系统响应阈值。
- 知识库显示长时间处于训练或重建状态。原因是未按VIN维度拆分索引集合，全量导入多车级文档导致索引构建耗时过长。
- 批量为集合块添加索引时请求参数格式错误。原因是未指定VIN作为关联索引字段，直接上传原始文档导致无法按单车主线匹配审查内容。

## 怎么确认配好了
- 导入单条包含VIN码的装配作业指导书，验证索引可按VIN关键词快速召回关联的拧紧数据文档。
- 触发一次增量索引同步，检查系统日志中无全量重建的耗时告警，确认更新节奏符合实时要求。
- 发起跨文档的交叉审查请求，核对返回结果包含对应工位的作业指导、历史返修记录与一致性文件。
- 查看索引集合的字段映射配置，确认VIN码、扭矩值等核心字段已被正确关联到索引维度。
