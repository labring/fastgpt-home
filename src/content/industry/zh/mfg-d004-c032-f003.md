# 汽车整车总装的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据围绕单台车辆的VIN展开，日常文档包含生产订单、VIN清单、装配作业指导书、拧紧数据、下线检测报告、返修记录、一致性与放行文件。数据来源覆盖ERP/MES系统、VIN与车辆配置系统、供应商批次管理、车间拧紧工具、EOL下线检测线以及质量追溯系统。数据更新频率按单台车辆执行，关键拧紧、检测数据实时同步，批量配置与放行文件按每班更新，整体数据体量随生产节拍动态变化。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类以VIN为单台车辆的唯一标识，混线生产模式下需区分不同车辆的审查会话，因此多轮对话需绑定`chatId`实现会话隔离。单台车辆关联数百项配置与文档，多轮对话的上下文窗口需限制合理范围，避免加载过量数据导致响应卡顿。实时更新的拧紧、检测数据要求提示词明确引导优先调用最新数据源，同时需在多轮交互中动态加载当前车辆的专属配置信息。复杂的扭矩控制与缺陷追溯逻辑，要求提示词拆分审查步骤，先提取VIN再匹配对应文档，防止混淆不同车辆的审查数据。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按单台车辆VIN生成唯一值 | 绑定单台车辆的审查会话，避免混线生产时的会话混淆 |
| `messages` | 保留最近10轮对话上下文，按实测标定token上限 | 平衡上下文完整性与响应速度，适配单台车辆的多轮审查需求 |
| `variables` | 预设VIN匹配规则、文档分类标签 | 快速引导模型定位单台车辆的专属文档，减少无效检索 |
| 最大上下文token数 | 8000–12000 token | 覆盖单台车辆的数百项配置文档与多轮对话内容，避免截断关键审查信息 |
| 单次搜索上限 | 前8条匹配结果 | 适配单台车辆的配置项数量，避免过多冗余信息干扰审查逻辑 |
| 问题优化 | 开启自动拆分长问题 | 将复杂的跨工位缺陷审查拆分为多轮小问题，提升模型理解精度 |

## 容易做错的三处
- 现象：开启输入引导并配置自定义词库后，调试预览界面出现报错。原因：未校验自定义词库的格式与编码，导致模型无法正确加载词库规则，触发语法错误。
- 现象：配置的最大响应token为3000以上，但特定复杂问题的响应被截断为200 token。原因：未设置全局上下文token限制，或上下文窗口被过量的历史对话与文档数据占满，导致剩余token不足以支撑完整响应。
- 现象：无法在对话过程中动态将新的返修记录或检测数据加入知识库。原因：未配置动态知识库更新的触发规则，或未将当前车辆的VIN作为知识库的分类标识，导致新数据无法关联到对应审查会话。

## 怎么确认配好了
- 发起单台车辆的VIN查询，核对对话历史中`chatId`是否与该车辆的VIN一致，确认会话隔离生效。
- 输入包含复杂配置匹配的问题，查看响应的token消耗统计，确认未出现意外的token截断。
- 上传新的返修记录，触发对话流程，核对模型是否能调用新上传的数据完成审查。
- 检查调试预览界面的词库加载提示，确认自定义词库已成功导入，无格式报错。
