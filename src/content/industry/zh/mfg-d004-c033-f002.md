# 汽车零部件批量制造的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类的日常文档包含控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料、8D报告等，数据来源包括客户图纸、特殊特性清单、ERP/MES系统、量检具数据、设备过程参数及供应商质保书。数据更新节奏为每批生产、每班巡检及持续采集设备参数，文档结构涵盖表格、段落、结构化表单等类型，字段包含零件号、工序号、公差值、检验频次、设备编号等，附带毫米、牛米、小时等行业专用单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
文档类型多样且结构差异明显，既有规整的表格类控制计划，也有长段落的8D报告，要求向量模型与索引支持灵活的分块策略以适配不同文档结构。数据来源分散且更新频繁，需支持增量索引更新以适配每批、每班的实时数据采集。字段附带行业专用单位，索引需保留元数据以确保召回结果的精准匹配。批量生产产生的文档总量较大，索引的分片与召回效率需适配批量审查的高并发需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类文档的平均篇幅，覆盖多数字段与段落内容 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工序关联信息，避免关键关联内容被截断 |
| `maxToken` | 8192 token | 适配篇幅较长的PPAP资料，确保完整内容被向量生成覆盖 |
| 相似度阈值 | 0.75–0.85 | 匹配汽车零部件文档对召回精度的严格要求，过滤低关联结果 |
| 单次搜索上限 | 前 10 条 | 适配批量审查的快速定位需求，避免过多冗余结果干扰判断 |
| `defaultToken` | 4096 | 匹配日常技术文档的平均token消耗，优化向量生成效率 |

## 容易做错的三处
- 切换向量模型后知识库无进度且无法切回，界面显示向量任务状态停滞，控制台返回404错误。原因是未正确配置模型渠道的API密钥与访问路径，导致模型调用失败。
- 批量重新嵌入时部分文档无向量结果，嵌入任务日志中部分文档对应字段为空。原因是未处理文档中的特殊字符与非标单位，导致向量生成流程中断。
- 召回结果未命中目标工序文档，搜索结果匹配度偏低。原因是分块长度设置过大，导致关键工序的公差、检验要求等信息被截断。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库设置页面，检查向量模型配置的API密钥与模型名称是否与申请的资源一致。
- 上传一份典型的控制计划文档，发起手动嵌入任务，查看任务进度是否正常更新，无报错日志。
- 输入一条包含零件号与工序要求的查询，查看召回结果的数量与匹配度是否符合预设阈值。
- 执行批量重新嵌入操作，检查任务日志中是否存在异常报错，确认所有文档均生成有效向量。
