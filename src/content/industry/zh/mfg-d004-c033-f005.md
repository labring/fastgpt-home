# 汽车零部件批量制造的技术文档交叉审查：工具调用与插件

## 这个品类的数据长什么样
本品类数据来自客户图纸、特殊特性清单、ERP/MES系统、量检具、设备过程参数及供应商质保书。日常生成控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料、8D报告等文档。数据更新随生产批次、班次触发，部分设备参数持续采集。文档包含特殊特性编号、工序参数阈值、检测数值、整改措施等字段，部分需匹配客户指定的单位格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类数据来源分散且更新节奏差异明显，要求工具调用需支持多数据源同步拉取，插件需适配ERP、MES、量检具等不同系统的接口格式。文档类型多样且字段要求严格，需插件支持按控制计划、8D报告等文档类型触发差异化审查规则。批量生产特性要求工具调用支持批量文档并行处理，避免单批次审查延迟。受整车客户强质量约束，工具返回结果需保留原始文档的字段关联，匹配客户指定的单位与格式要求。

本配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 自动匹配本品类的控制计划、8D报告等多类型文档的审查工具，无需手动配置 |
| `functionCall` | `disabled` | 避免手动调用工具时误触发非必要的审查逻辑，适配本品类的自动审查需求 |
| 单次工具调用上限 | 前5–7条 | 匹配单批次生产的常规文档数量，避免超出系统资源承载能力 |
| 批量并行处理数 | 2–4 批 | 适配本品类的批量生产节奏，平衡处理效率与资源占用 |
| 上下文窗口大小 | 8000–12000 token | 容纳批量文档的元数据、客户特殊特性要求及审查规则，适配长文本处理需求 |
| 最大响应超时 | 300 秒 | 覆盖批量文档交叉审查的常规耗时，避免生产节奏被中断 |

## 容易做错的三处
- 现象：调用工具返回的文本流仅显示为无格式纯文本，无法区分审查项与结论。原因：未开启工具调用的markdown输出配置，导致结构化审查结果无法按格式渲染。
- 现象：通过中间服务转发FastGPT接口时，流数据接收断开后页面数据固定无法恢复。原因：未配置流数据断点续传逻辑，中间服务未保留会话上下文。
- 现象：docker部署的FastGPT无法加载自定义插件。原因：未在容器内创建packages/plugins/register目录，或未挂载对应插件配置文件。

## 怎么确认配好了
- 进入FastGPT配置界面，确认`toolChoice`参数设置为`auto`，与配置表中的建议取法一致。
- 上传单份控制计划文档触发审查，检查返回结果是否按markdown格式排版展示。
- 上传多份不同类型的生产文档，验证工具调用是否能并行处理且未出现超时。
- 登录docker部署的FastGPT容器，确认packages/plugins/register目录存在且配置文件已挂载。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
