# 汽车零部件批量制造的技术文档交叉审查：引用来源与溯源

## 这个品类的数据长什么样
汽车零部件批量制造的主体为制动、转向、底盘、内外饰及动力系统供应商，日常产生的文档包括控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料、8D报告等。数据来源包含客户图纸与特殊特性清单、ERP/MES系统、量检具数据、设备过程参数、供应商质保书。数据更新频率为每批、每班或持续采集，文档字段包含特殊特性编号、公差值、CPK值、抽样频次等，单位涉及毫米、百分比、件/小时等，单份文档长度跨度较大。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源且高频更新的数据要求引用溯源必须精准匹配文档版本与生产批次，避免引用过时的控制计划或异常记录。文档类型多样，需按文档类别关联对应审查环节，例如引用PPAP资料时需关联客户批准状态。批量制造的特性要求溯源结果需覆盖单批次全工序关联文档，避免遗漏关键参数。同时受整车客户强约束，引用内容必须严格对应客户要求的特殊特性，溯源路径需可追溯至原始客户交付文档，确保合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 汽车零部件单份文档片段较长，需保留足够token以完整展示引用的控制计划或SPC报表内容 |
| `responseData` | 开启 | 需返回原始文档的引用源数据，用于向审查人员展示原文片段 |
| `detail` | 完整文档路径+更新时间 | 需明确溯源的文档版本与来源，满足整车客户的质量体系合规要求 |
| 单次召回引用上限 | 前6条 | 批量制造的关联文档数量较多，避免过多引用导致回答冗余影响审查效率 |
| 上下文窗口长度 | 10000–15000 字符 | 支持多轮交叉审查对话的上下文关联，保留前期引用的文档信息 |
| 免登录引用权限 | 按场景开启 | 适配不同访问场景的溯源需求，例如车间现场的无账号访问 |

## 容易做错的三处
- 免登录分享链接访问应用时，引用功能显示无法查看原文。原因是未在应用配置中开启免登录场景下的引用溯源权限，或错误关闭了`responseData`配置项。
- 知识库回答的段落末尾未显示引用标记。原因是未开启`detail`配置项，或`quoteMaxToken`取值过小导致无法提取有效引用片段。
- 连续发起多轮审查提问后，后续问题无法关联前期引用的文档内容，出现答非所问的情况。原因是未配置足够大的上下文窗口长度，未开启多轮上下文关联的引用溯源设置。

## 怎么确认配好了
- 上传一份汽车零部件控制计划文档，发起关于特殊特性要求的提问，检查回答末尾是否带有明确的引用来源标识。
- 点击回答中的引用标识，验证跳转后可查看原始文档的对应片段，包含文档类型、更新时间等关键信息。
- 发起两轮连续审查提问，检查第二轮提问时系统可关联第一轮引用的文档内容，完成交叉审查。
- 生成FastGPT v4.17.0版本的免登录分享链接，访问后验证引用功能可正常查看原文，无权限报错。
