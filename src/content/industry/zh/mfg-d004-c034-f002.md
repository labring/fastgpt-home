# 烘焙与方便食品的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自面包糕点、饼干、方便面及速冻面点工厂的日常生产文档，涵盖配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告等。数据来源包括原辅料合格证明、ERP/MES系统、称量系统、生产设备、实验室检测结果及食品追溯台账。数据以每批、每班或每日为更新节奏，文档包含投料量、烘烤温度、时间、过敏原标识、清洁频次等字段，单位涉及克、摄氏度、分钟、批次号等。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于本品类文档包含过敏原、生产参数等敏感且高频变更的内容，索引需支持高频增量更新，避免全量重建占用过多资源。配方与投料单的字段多为数值与文本混合，向量模型需适配混合字段的编码逻辑，确保关键信息的语义一致性。换线频繁导致文档批次差异显著，索引需支持按批次维度过滤召回结果，缩小交叉审查的范围。每日或每班的更新节奏要求索引的实时性配置匹配生产节拍，避免数据滞后影响审查效率。同时，产品直接食用的属性要求交叉审查的召回结果精准度更高，需限制无关文档的干扰。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配本品类文档中配方、生产曲线等长文本段落的自然分段，避免语义割裂 |
| 重叠长度 | 100–150 字符 | 覆盖生产参数、过敏原标识等跨块关键信息，防止块边界截断重要审查内容 |
| `defaultToken` | 4096 | 适配本品类文档中批量投料单、检测报告的总token量，保证完整语义输入 |
| `maxToken` | 8192 | 支持长批次生产记录的完整向量编码，避免截断关键追溯数据 |
| 相似度阈值 | 0.75–0.85 | 过滤无关文档，精准召回同配方、同生产流程的交叉审查目标 |
| 单次搜索上限 | 前 10 条 | 控制检索结果规模，适配生产场景下快速复核的响应需求 |

## 容易做错的三处
- 现象为知识库上传后显示未索引状态，向量编码日志中出现字段不兼容报错。原因是未针对本品类的混合字段（如投料量与文本说明）配置适配的预处理逻辑，导致部分字段无法正确生成向量。
- 现象为界面提示m3e无可用频道，无法选择embedding模型完成向量化。原因是未按照官方文档配置m3e模型的部署地址与访问权限，或容器网络策略限制了模型调用。
- 现象为检索结果条数与预期不符，仅返回少量相关文档或返回大量无关内容。原因是未调整相似度阈值或单次搜索上限，导致过滤规则过严或检索范围过大。

## 怎么确认配好了
- 上传一份典型的配方文档，查看系统索引状态是否显示为已完成。
- 输入过敏原物料名称作为检索词，核对召回结果是否包含同批次的清洁消毒记录与投料单。
- 检查向量模型的调用日志，确认`defaultToken`与`maxToken`的配置未触发截断报错。
- 批量上传当日的生产记录，验证索引更新速度是否匹配每班的生产节奏。
