# 烘焙与方便食品的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
该品类的核心数据来自面包糕点、饼干、方便面及速冻面点工厂的多套系统与记录。日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量设备、烤炉或油炸线、实验室检测数据及食品追溯台账。数据更新以每批生产为核心节奏，辅以每班的生产记录更新与每日的清洁、检验归档。文档字段包含批次号、过敏原标识、投料重量、烘烤温度与时长、清洁消毒时间等，部分文档需匹配单位如克、千克、摄氏度、分钟，确保数据校验的准确性。

## 这些特征在「工作流编排」这一环带来什么约束
该品类配方数量多、产品换线频繁，且直接面向消费者，对过敏原管控、异物控制要求严格，因此工作流需支持快速切换不同产品的审查节点。多源数据的拉取需求，要求工作流配置适配不同系统的变量绑定规则，避免数据错位。按每批、每班的更新节奏，工作流需匹配生产节点触发，不使用固定定时触发，确保审查时机与数据更新同步。同时，出错后果涉及产品召回与口感不合格，工作流需配置明确的失败分支与校验环节，保障交叉审查的完整性。该品类的过敏原管控与清洁切换要求高于其他食品品类，因此工作流需单独配置过敏原核对与清洁状态校验的分支节点。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发时机 | 按生产批次完成节点触发 | 匹配每批更新的数据节奏，避免无效审查 |
| 变量配置 | 绑定`variables`为批次号、过敏原清单、投料重量 | 覆盖核心审查所需的动态数据，适配多产品换线场景 |
| 模型调用超时 | 600秒 | 覆盖多源数据拉取与交叉校验的整体耗时 |
| 日志存储上限 | 1000 MB | 留存多批次审查日志且不占用过多存储空间 |
| 节点ID标识 | 按`nodeId`绑定过敏原审查环节 | 便于快速定位对应审查节点，便于排障 |
| 重试次数 | 2次 | 应对临时设备数据拉取失败的偶发场景 |

## 容易做错的三处
- 工作流无法添加连接线，节点间无连接小圆圈。原因：未开启FastGPT v4.17.0的工作流节点激活状态，部分自定义节点默认未启用连接功能。
- 无法查看工作流中组件的模型ID。原因：未在`variables`中绑定模型调用的配置项，导致界面未加载对应展示字段。
- 同样任务对话工作流比调试模式运行慢。原因：工作流配置了多源数据拉取环节，调试模式跳过了非必要的数据源校验，正式运行时需完整拉取ERP、设备日志等数据。

## 怎么确认配好了
- 手动触发一次测试批次的工作流，检查节点间连接线是否正常显示，无断开或无法连接的情况。
- 查看工作流的`variables`配置项，确认已绑定批次号、过敏原清单等核心审查字段。
- 进入对应节点的日志页面，确认可拉取到该节点的详细运行日志。
- 对比调试模式与正式运行的任务耗时，确认配置的超时参数符合实际运行节奏。
