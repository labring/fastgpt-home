# 热处理的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
热处理场景的核心数据来自材料牌号、客户技术条件、温控仪表、炉温均匀性测试设备、硬度计、金相设备与生产MES系统。日常文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单，字段包含加热温度（单位℃）、保温时长（单位分钟）、硬度值（单位HV或HRC）、装炉位置编号等。数据更新频率为每炉次、每批，单批次文档数量随炉次规模变化。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据源要求工作流需支持串联不同类型的节点，分别对接设备数据、业务文档与客户要求。每炉次的动态更新数据要求工作流需支持按批次触发执行，避免固定周期的冗余校验。文档字段的非标准化格式要求工作流需支持灵活绑定多字段变量，适配不同客户的工艺要求。出错后果的严重性要求工作流需配置分支处理与失败重试机制，避免异常流转至后续环节。

## 配置怎么定
FastGPT v4.17.0 下的配置项说明如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量引用配置 | 绑定`variables`中的炉温、保温时长、硬度值等多字段 | 热处理文档需交叉校验多维度参数，单变量无法覆盖全部校验需求 |
| 节点超时阈值 | `600 秒` | 单炉次文档的全量校验需控制在合理时长内，避免占用生产环节的调度资源 |
| 分支触发规则 | 按`nodeId`标记的异常校验节点结果触发回滚流程 | 需在发现参数异常时及时终止当前炉次的校验流程，避免错误流转 |
| 重试次数上限 | `2 次` | 应对温控仪表、硬度计等设备偶发的临时数据波动，无需过度重试延误生产 |
| 结果输出配置 | 仅输出`500–1000 字符`的最终校验报告，隐藏中间节点的执行日志 | 适配业务人员仅需最终校验结论的使用习惯，避免冗余信息干扰 |

## 容易做错的三处
- 现象为调试节点时无法停止当前调试模式，日志返回节点ID匹配失败。原因是未正确配置`nodeId`参数与实际执行节点的对应关系。
- 现象为变量引用下拉菜单仅可选择单个变量，无法绑定多字段参数。原因是未开启`variables`的多变量绑定配置。
- 现象为工作流仅调用单个模型，无法实现分步处理。原因是未配置多节点串联的执行链路，仅绑定了单一模型节点。

## 怎么确认配好了
- 上传单炉次的热处理工艺卡、炉温曲线等全套文档，触发工作流执行，检查是否自动调用多维度校验节点。
- 查看变量绑定面板，确认可同时选择炉温、硬度、工艺参数等多个字段。
- 模拟异常参数（如炉温超出设定阈值），确认工作流触发分支回滚流程。
- 查看最终输出结果，确认仅展示最终校验报告，无中间步骤的冗余信息。
