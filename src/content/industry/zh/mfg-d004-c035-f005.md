# 热处理的技术文档交叉审查：工具调用与插件

## 这个品类的数据长什么样
热处理场景的技术文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单。数据来源包括材料牌号标准、客户技术条件、温控仪表、炉温均匀性测试设备、硬度计与金相设备、车间MES系统。数据按每炉次、每批更新，单炉次文档包含加热温度、保温时长、炉温采样值、硬度检测值等字段，温度单位为摄氏度，时长单位为分钟，硬度值采用HRC或HV标准单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据按每炉次、每批更新，工具调用需支持实时拉取最新的设备与检测数据，避免使用过期的历史文档。文档类型包含结构化表格与非结构化图表，需配置适配多格式的解析插件。出错后果涉及整炉零件性能不合格，要求工具调用的结果具备高准确性，需对跨文档的字段进行交叉校验。同时，单车间的炉次批次较多，工具调用频率较高，需配置限流规则避免触发平台报错，且不同炉次批次的API调用权限需独立维护，防止配置覆盖导致的权限混乱。

## 配置怎么定
本文基于 FastGPT v4.17.0 版本配置。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配热处理场景下多类型文档的自动工具选择需求 |
| `functionCall` | 开启 | 支持结构化文档的字段提取，满足交叉审查的数据校验需求 |
| API密钥分组 | 按业务场景拆分 | 区分不同炉次批次的API权限，避免配置覆盖 |
| 工具调用超时时间 | 300 秒 | 适配大体积文档的解析耗时 |
| 单轮调用文档上限 | 前 3 条 | 限制调用数量，规避限流报错 |
| 当前时间工具触发规则 | 按校验节点自动触发 | 满足实时对比炉温采样时间的需求 |

## 容易做错的三处
- 新建模型配置后原有API密钥被覆盖：未开启多场景API密钥分组配置，使用全局单密钥存储逻辑，导致新配置覆盖旧配置。
- 工具调用返回429状态码报错：未设置单轮调用文档上限，单轮调用的文档数量超过平台限流规则，触发调用频率限制。
- 工具无法加载炉温曲线图片：未配置图片拉取的出站访问规则，导致无法访问设备上传的图片资源，返回加载失败提示。

## 怎么确认配好了
- 提交单炉次的工艺卡与炉温曲线，检查工具是否自动调用对应的数据解析插件，完成字段提取与交叉校验。
- 新建两个独立的业务场景配置，分别填入不同的API密钥，发起调用测试，确认两个场景的密钥未被相互覆盖。
- 发起包含4条文档的批量调用测试，检查返回的结果条数为3条，符合预设的单轮调用上限。
- 触发当前时间工具调用，检查返回的时间与系统当前时间一致，满足炉温采样时间的校验需求。
