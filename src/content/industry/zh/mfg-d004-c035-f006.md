# 热处理的技术文档交叉审查：引用来源与溯源
本页面适配FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据来源包括材料牌号、客户技术条件、温控仪表、炉温均匀性测试数据、硬度计与金相设备数据、MES系统数据。日常文档涵盖热处理工艺卡、装炉图、标注℃与分钟单位的炉温曲线、含HV/HRC硬度值与金相组织评级的硬度与金相报告、含设备编号与点检时间的设备点检表、异常处置单。数据更新频率为每炉次、每批，单炉次关联文档关联度高且数量固定。

## 这些特征在「引用来源与溯源」这一环带来什么约束
首先，数据按炉次更新，要求溯源必须精准绑定单炉次的所有关联文档，避免跨炉次数据混淆。其次，文档包含带明确单位的数值与评级字段，引用时需匹配字段单位与参数，防止出现硬度值单位混淆、炉温时间不匹配的问题。再者，数据源分散于设备与系统，需对接多源数据的唯一标识（如炉次号、设备编号），确保溯源时可追溯至原始采集设备。最后，单炉次关联文档数量固定，要求上下文召回需限定范围，避免冗余数据干扰审查结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | 单炉次热处理核心文档总字符量覆盖该区间，可容纳工艺卡、炉温曲线、硬度报告的核心字段 |
| `responseData` | 开启 | 需返回炉次号、材料牌号、设备编号等唯一标识，支撑跨文档溯源 |
| `detail` | 开启 | 需展示每条引用对应的文档类型、生成时间与数据来源设备 |
| 单次召回上限 | 前6条 | 单炉次关联有效文档不超过6类，避免上下文过载 |
| 溯源匹配阈值 | 按实测标定 | 匹配热处理文档的字段相似度要求，适配多源数据的关联逻辑 |
| 来源校验开关 | 开启 | 验证引用数据的炉次号与设备编号一致性，防止跨炉次误关联 |

## 容易做错的三处
- 现象：回答正文未包含匹配到的本地知识库文档内容，但引用列表中存在对应文档条目。原因：未开启`detail`配置，未将知识库文档的核心字段注入回答上下文。
- 现象：调用API引用私人知识库时返回无匹配结果提示。原因：未配置知识库的炉次号与工艺卡的绑定索引，无法匹配用户问题中的炉次标识参数。
- 现象：交叉审查结果出现跨炉次的错误关联，比如将A炉的炉温曲线与B炉的工艺卡绑定。原因：未开启来源校验开关，仅按关键词召回导致无关文档被错误匹配。

## 怎么确认配好了
- 上传一份单炉次的热处理工艺卡、炉温曲线和硬度报告，发起交叉审查请求，检查回答正文是否包含三类文档的核心字段。
- 调用API传入包含明确炉次号的问题，检查返回结果的引用列表是否包含对应炉次的文档，且正文匹配相关内容。
- 查看系统运行日志，确认每次请求的上下文召回条数不超过设定的单次召回上限，且无超时报错。
- 手动核对返回的引用来源信息，确认文档类型、数据来源设备编号与实际上传的文档一致。
