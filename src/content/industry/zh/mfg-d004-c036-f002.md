# 焊接结构件制造的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
焊接结构件制造的核心数据来自设计图纸、材料质保书、焊接设备参数、焊材库、无损检测系统及人员资质台账。日常产出的文档包括焊接工艺评定、焊接工艺规程、焊材领用记录、焊工资格记录、焊缝检验报告及返修单，每条文档关联具体焊缝编号、焊材批号、焊工ID等字段。数据更新频率为每条焊缝或每批、每班，单条焊缝关联的文档数量有限但更新频次高。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引需按焊缝ID进行分组关联，避免跨批次文档被误召回。高频更新的特性要求索引支持增量更新逻辑，适配不同向量存储的增量同步需求，同时支持本地部署的轻量化配置。不同文档类型的长度差异较大，如焊接工艺规程可达数千字符，而焊工资格记录仅数百字符，需适配灵活的分块规则。刚性资质要求的业务场景，要求检索需精准匹配资质字段，不能泛化召回无关文档，否则会引发质量风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配焊接工艺规程、焊缝检验报告等主流文档的平均长度，保留完整业务逻辑 |
| 重叠长度 | 100–200 字符 | 避免截断焊缝编号、焊材批号等关键关联字段，保障跨分块的上下文连贯性 |
| 相似度阈值 | 0.75–0.85 | 适配刚性资质审查和精准检索的需求，最大程度召回有效文档，可搭配私有化部署的重排模型使用 |
| 单次搜索上限 | 前 10 条 | 匹配单条焊缝关联的文档数量范围，避免过多文档占用上下文资源 |
| `maxToken` | 8000 token | 符合 FastGPT v4.17.0 的默认上下文上限，适配多文档拼接后的总长度，支持本地部署环境 |
| `defaultToken` | 1500 token | 匹配单条分块文档的平均token数，适配向量存储的单条数据限制，支持增量同步需求 |

## 容易做错的三处
- 检索结果中出现非当前焊缝关联的焊材领用记录，原因是未按焊缝ID为索引添加分组维度，导致跨批次文档被召回。
- 向量索引更新超时，原因是未配置增量更新逻辑，每次全量索引覆盖高频更新的焊缝数据，超出处理时限。
- 检索返回的焊工资格记录缺失资质有效期字段，原因是分块时截断了包含有效期的文档末尾内容，未保留关键资质信息。

## 怎么确认配好了
- 上传单条焊缝的全套关联文档，执行技术文档交叉审查检索，核对返回结果仅包含该焊缝对应的文档。
- 模拟更新一条焊缝的焊材领用记录，触发索引更新后再次检索，确认更新后的文档已被正常召回。
- 调整相似度阈值，验证返回结果的匹配度符合预设的精度要求，无过度召回或召回不足的情况。
- 查看FastGPT v4.17.0的向量存储监控，确认单条分块文档的token占用未超过配置的`defaultToken`限制。
