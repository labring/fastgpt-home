# 生产计划与车间排程的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类的日常文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单，数据来源涵盖ERP订单与库存、BOM、工艺路线、设备产能、人员班次、在制品及供应商到货信息。数据更新节奏随业务触发，包括每日、每周的固定刷新，以及订单变更、异常插单时的实时更新。文档多包含结构化字段与文本描述，字段涉及订单号、物料编码、产能单位、排程时段等特定标识与单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
品类内的数据来源分散且更新频率不均，要求索引支持增量刷新与多源数据聚合，避免重复构建全量索引。文档同时包含结构化表格（如排程表、工单）与非结构化文本（如交期变更说明），需要向量模型兼顾文本语义与表格结构的解析能力。数据字段带有特定业务单位与标识，向量索引需保留字段关联关系，防止跨业务语义的错误匹配。单次审查需覆盖多份关联文档，要求索引的召回能力适配多文档关联查询的需求，需合理配置`defaultToken`与`maxToken`参数，适配品类内文档的长度需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数逻辑制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配品类内文档的段落与表格单元长度，避免跨语义块拆分核心业务内容 |
| 重叠长度 | 100–150 字符 | 弥补分块边界的语义断裂，覆盖排程表的跨行关联内容 |
| 相似度阈值 | 0.72–0.80 | 匹配订单、排程数据的语义相似度区间，减少非关联文档的误匹配 |
| 单次搜索上限 | 前8条 | 适配品类内单次审查需覆盖的多份工单与排程表数量 |
| defaultToken | 8192 | 适配主生产计划文档的总内容长度，满足完整上下文输入要求 |
| maxToken | 16384 | 预留异常场景下的扩展空间，应对插单后新增的交期变更单内容 |

## 容易做错的三处
- 现象：调用向量模型时返回500状态码，界面显示「模型配置无效」。原因：未正确绑定第三方向量模型渠道，或选择的模型无法适配品类内的结构化文档解析需求。
- 现象：索引构建完成后，搜索结果仅返回少量文本内容，无表格相关匹配项。原因：未开启多模态向量支持，无法解析排程表、工单中的结构化表格字段。
- 现象：执行交叉审查时出现超时错误，日志显示上下文溢出。原因：未合理设置`maxToken`参数，导致长文档的完整排程内容无法加载。

## 怎么确认配好了
- 上传单份测试工单与周日排产表，等待索引构建完成，确认界面无异常提示。
- 输入针对性查询，验证返回结果覆盖品类文档的核心字段与关联业务内容。
- 检查向量模型配置项，确认已完成渠道绑定与参数设置，无报错日志。
- 触发增量更新操作，验证新增的缺料清单可被正确索引。
