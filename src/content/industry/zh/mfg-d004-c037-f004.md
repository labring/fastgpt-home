# 生产计划与车间排程的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
该品类的数据来源包括ERP订单与库存、BOM清单、工艺路线、设备产能、人员班次、在制品库存、供应商到货信息。数据更新频率为每日、每周，或随销售订单、交期变更单、缺料清单等文档产生时触发。日常处理的文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单，核心字段包括订单编号、物料编码、产能工时、在制品数量、交期日期，单位涉及工时、件、天等。

## 这些特征在「工作流编排」这一环带来什么约束
通常多源且非固定周期更新的数据，要求工作流支持事件触发与定时触发结合的模式，避免无效执行。多类型文档的字段结构差异较大，要求工作流中配置可灵活调整的文档解析规则，适配不同业务文档的字段提取需求。排程计算依赖实时的产能、物料约束数据，要求工作流节点间的数据传递具备实时性，避免使用过期的业务信息。异常场景如插单、缺料、设备故障的触发无规律，要求工作流内置可配置的异常分支处理逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按文档字段映射为`["orderNo", "materialCode", "capacityHour", "deliveryDate"]` | 匹配生产计划类文档的核心字段，便于后续校验与排程计算 |
| `nodeId` | 为数据校验节点、排程计算节点、异常处理节点分别配置唯一ID | 便于定位工作流执行日志与错误节点，快速排查问题 |
| 触发方式 | 按数据更新事件触发，固定周期触发用于常规周度排程任务 | 适配订单、异常变更的实时触发需求，兼顾常规排程的执行效率 |
| 全局变量初始化 | 初始值设为ERP同步的当日库存数据 | 覆盖基础物料与产能约束，减少实时查询次数，提升执行速度 |
| 文档解析规则 | 按文档类型分别配置字段提取规则 | 适配销售订单、工单、缺料清单的不同字段结构，确保数据提取准确 |
| 节点超时设置 | 600秒 | 匹配排程计算的常规耗时，避免节点阻塞导致工作流中断 |

本页面基于FastGPT v4.17.0编写。

## 容易做错的三处
- 现象：全局变量字符串数组赋值后，后续节点读取到的数组包含重复的历史内容。原因：未在`variables`配置中明确初始化数组为空，导致每次执行时AI回复的内容被追加到原有数组中。
- 现象：点击导出工作流后，生成的配置文件无法在其他环境正常加载。原因：导出时未勾选包含关联的数据源配置项，导致目标环境无法识别数据来源。
- 现象：通过API访问工作流时，传入的全局变量未被节点正确读取。原因：未按照`variables`要求的格式在请求体中传递业务数据，导致节点无法获取订单、产能等核心信息。

## 怎么确认配好了
- 手动触发工作流，查看节点日志中`variables`对应的字段是否与当前业务数据一致。
- 模拟异常订单变更，验证工作流是否触发预设的异常处理分支。
- 导出工作流配置文件，检查文件中是否包含所有配置的节点与变量规则。
- 调用API测试，确认请求体中的参数被工作流节点正确解析。
