# 生产计划与车间排程的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。日常处理的文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单，包含订单号、物料编码、工序工时、设备编号、班次数量等字段，单位涵盖件、小时、天等。数据更新频率为每日、每周，或随订单、异常情况实时触发。

## 这些特征在「模型接入与配置」这一环带来什么约束
生产计划与车间排程的文档长度差异显著，短则数十字的缺料清单，长则数千字符的周日排产表，要求模型上下文配置需适配不同长度的输入内容。多源异构的数据结构要求模型调用时需精准召回关联文档片段，而数据更新频率高、触发场景随机，需确保配置能支持动态的文档同步与实时调用。此外，排程审查需保持结果的一致性，避免因模型随机性导致不符合生产约束的建议，同时需支持工具自主调用以处理插单、缺料、重排等动态生产场景。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写第三方大模型平台提供的官方接入端点 | 适配目标模型的请求路径，确保调用请求能正确转发 |
| `AIPROXY_API_TOKEN` | 填写平台生成的有效API访问密钥 | 完成身份验证，获取模型调用的合法权限 |
| `maxContext` | 8000–12000 token | 匹配生产计划类文档的平均长度，避免上下文截断丢失订单、BOM等核心约束信息 |
| `maxTokens` | 2000–3000 token | 适配排程分析结果的输出长度，确保完整返回工序规划、调整建议等内容 |
| `quoteMaxToken` | 1500–2000 token | 足够拉取关联的工单、物料清单等文档片段，支撑技术交叉审查的依据匹配 |
| `temperature` | 0.2–0.4 | 降低模型输出的随机性，确保排程相关的审查结果保持一致性，符合生产约束要求 |
| 工作流/API 工具选择配置 | auto | 允许模型自主识别需要调用的工具，适配插单、缺料、重排等动态生产场景 |

## 容易做错的三处
- 调用模型返回401状态码，提示密钥无效。原因是未正确填写`AIPROXY_API_TOKEN`，或使用了过期的第三方平台密钥。
- 模型输出的排程建议缺失关键物料约束信息。原因是`maxContext`取值过小，导致ERP订单、BOM等核心文档被截断。
- 工具调用失败，无法触发知识库召回。原因是`toolChoice`被错误设置为固定模式，限制了模型自主调用工具的能力。

## 怎么确认配好了
- 发起测试请求，输入包含订单号和缺料情况的查询，确认接口返回正常响应，无报错信息。
- 查看模型输出内容，确认包含关联的工单、排产表片段，验证`quoteMaxToken`的召回范围符合预期。
- 调整`temperature`取值，对比两次相同查询的输出，确认结果一致性符合生产审查的稳定要求。
- 触发插单场景的测试请求，确认模型能自主调用工具生成调整后的排程方案，验证`toolChoice`配置生效。
