# 生产计划与车间排程的技术文档交叉审查：部署与升级

## 这个品类的数据长什么样
生产计划与车间排程的技术文档覆盖销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单等。数据来源包括ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。更新节奏随业务场景变化，每日同步基础产能与库存数据，每周更新排产计划，订单或异常发生时实时触发交期变更、缺料清单等文档更新。数据字段包含订单编号、物料编码、工序工时、设备负载、班次时长等，横跨全产品与工序，关联资源约束与交付承诺。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的数据来源要求部署时需支持对接ERP、设备管理系统等多个数据源，需配置不同的连接协议与认证规则。差异化的更新频率要求系统支持灵活的增量同步任务配置，兼顾实时性与资源占用。多类型且字段复杂的文档，要求向量库索引需覆盖订单、排程表等不同文档的专属字段，避免检索精度下降。数据规模随订单量与异常事件波动，部署时需预留足够的存储与计算资源，升级过程中需保证数据同步不中断，避免影响车间排程的正常运行。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 填写生产环境独立集群的连接串，包含数据库认证信息 | 排程数据涉及订单、工单等核心业务数据，需高可用的非关系型存储支撑多类型文档的快速检索 |
| `PG_URL` | 填写关联ERP系统的只读实例连接地址 | 需同步ERP的订单、库存数据，只读实例避免对业务生产系统造成性能影响 |
| `REDIS_URL` | 配置为本地缓存集群，缓存时长设为300-600秒 | 高频查询的设备产能、人员班次数据需要低延迟访问，缓存降低数据库查询压力 |
| `DB_MAX_LINK` | 取值为20-30 | 同时处理多工单、排程重排任务的数据库连接需求，避免连接耗尽导致服务中断 |
| `STORAGE_S3_ENDPOINT` | 填写自建对象存储的访问端点 | 生产文档需本地存储，避免公网传输延迟与数据安全风险 |
| `FE_DOMAIN` | 填写内部访问的私有域名 | 仅车间调度、PMC等内部部门使用，无需公网暴露降低安全隐患 |

## 容易做错的三处
- 现象：调用接口返回500错误，curl测试无法正常响应。原因：未正确配置`REDIS_URL`或`PG_URL`，导致依赖的缓存或数据库连接失败，FastGPT v4.17.0版本中该类错误会直接阻断文档交叉审查的前置数据加载。
- 现象：离线部署后无法加载全部生产文档。原因：未调整`DB_MAX_LINK`适配离线环境的存储资源，或未限制文档加载的单次上限，导致内存溢出，无法完成全量文档的索引构建。
- 现象：升级后排程数据同步中断。原因：未保留原有`ROOT_KEY`配置，导致系统无法识别原有权限规则，同步任务被阻断，无法正常拉取ERP的最新订单数据。

## 怎么确认配好了
- 执行FastGPT内置的数据库连接测试工具，验证`MONGODB_URI`和`PG_URL`的连接状态，确认无认证或网络错误。
- 提交一份测试用的工单文档，观察缓存数据的更新延迟，确认`REDIS_URL`的缓存时长符合业务的实时性要求。
- 上传一份测试用的周日排产表，验证`STORAGE_S3_ENDPOINT`的存储和读取功能正常，文档可正常被索引。
- 访问内部域名`FE_DOMAIN`，确认前端页面可正常加载排程相关的文档列表，无加载失败提示。
