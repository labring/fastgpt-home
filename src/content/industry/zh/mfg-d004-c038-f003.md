# 生物制品与无菌生产的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
本品类的典型主体为疫苗、抗体、血液制品及无菌注射剂企业，日常文档涵盖细胞库或种子批记录、培养纯化记录、无菌灌装记录、环境监测数据、培养基模拟灌装报告、无菌检验结果及批放行资料。数据来源包括细胞库与种子批系统、过程分析平台、洁净区监测系统、MES、LIMS及设备完整性测试工具。数据更新按生产批次执行，关键过程数据实时同步，环境监测数据按既定计划更新。文档字段包含批次号、温度（℃）、时间（小时）、沉降菌数（cfu/皿）等专业参数。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源异构的数据来源要求对话上下文需关联不同系统的文档，`messages`参数需按对话轮次保留跨系统的关联信息。按批次、实时更新的数据特征，要求`variables`参数动态绑定当前批次的专属参数，避免上下文混淆。文档结构不统一且包含大量专业术语，提示词需在每轮对话中明确字段提取规则，确保审查的一致性。严重的出错后果要求多轮对话需逐步校验关键参数，避免单一环节的错误扩散。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 保留最近20轮对话上下文，每轮不超过1500字符 | 适配本品类文档的单条长度，避免上下文溢出 |
| `variables` | 绑定当前批次号、洁净区编号等全局参数 | 关联实时或按批更新的业务数据，确保上下文一致性 |
| `chatId` | 按生产批次生成唯一标识 | 隔离不同批次的审查上下文，避免数据交叉污染 |
| 最大上下文 | 8000–12000 token | 覆盖单批次全套核心文档的内容范围 |
| 问题优化 | 按实测标定 | 适配本品类的专业术语与文档结构 |

## 容易做错的三处
- 现象：调用接口时返回`400 Bad Request`，提示`appId`字段缺失。原因：未正确配置工作流调用的参数，混淆了工作流ID与应用ID的传递规则。
- 现象：多轮对话后全局变量丢失，无法关联当前批次的专属数据。原因：未通过`variables`参数在对话间传递固定业务参数，导致上下文重置。
- 现象：上传的无菌灌装记录未被检索到，审查结果为空。原因：未在提示词中明确指定文件的字段匹配逻辑，或未开启文件与对话上下文的绑定设置。

## 怎么确认配好了
- 发起测试对话，输入当前批次的细胞库记录关键词，检查返回的上下文是否包含对应批次的专属参数。
- 查看FastGPT v4.17.0的调用日志，确认`chatId`、`messages`、`variables`参数均被正确传递。
- 上传一份培养基模拟灌装记录，触发审查流程，检查是否能正确提取其中的沉降菌数等专业字段。
- 连续发起3轮相关提问，检查上下文是否保留了前几轮对话中的批次信息与关联数据。
