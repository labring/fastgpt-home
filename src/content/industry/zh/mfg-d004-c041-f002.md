# 电镀与化学表面处理的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类的典型数据来源包括客户表面处理规范、槽液化验报告、整流器运行数据、在线水质监测记录、危废管理台账等。日常生成的文档包含槽液成分参数卡、挂具使用记录、膜厚与附着力检测报告、槽液分析日志、废水排放台账等。数据更新频率随生产节奏而定，包括每槽次更新的挂具与槽液参数、每班生成的工艺记录，以及按监测要求提交的危废与水质数据。文档字段多包含具体数值与单位，如槽液浓度（g/L）、工作温度（℃）、镀层厚度（μm）、排放限值（mg/L）等，部分文档同时包含文本说明与结构化参数。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源且高频更新的数据，要求索引需支持增量更新以避免全量重建的耗时问题。结构化数值与文本混合的文档结构，要求向量模型需同时适配参数语义与数值逻辑，避免单一语义匹配导致的偏差。不同来源的文档存在字段命名差异，如部分记录将「膜厚」标注为「镀层厚度」，需在索引前完成字段标准化，否则会导致召回精度下降。危废与水质监测数据的合规性要求，需索引具备高召回率以覆盖所有合规相关文档，同时需避免无关数据混入上下文。随生产规模扩大，文档总量与更新频次持续增长，需合理配置索引分片与召回上限，防止搜索超时或资源占用过高。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 该品类文档多为单条工艺记录或监测报告，800–1200字符可完整保留单条数据的参数与说明逻辑 |
| 重叠长度 | 200–300 字符 | 槽液参数、工艺卡等内容存在连续关联逻辑，重叠长度可避免跨块信息断裂 |
| maxToken | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 单次搜索上限 | 前 10 条 | 该品类查询多为精准参数匹配，过多结果会增加上下文冗余，影响响应速度 |
| 相似度阈值 | 0.75–0.85 | 工艺参数与合规记录的匹配需较高置信度，避免误匹配非目标文档 |
| defaultToken | 1024 | 适配单条核心文档块的token占比，平衡向量召回的精度与响应速度 |

## 容易做错的三处
- 现象：搜索时出现60秒超时报错，或返回结果条数远低于预期。原因：未根据该品类高频更新的多源数据调整单次搜索上限与maxToken，导致向量召回与上下文拼接耗时过长。
- 现象：知识库索引重建超过24小时未完成，界面持续显示「索引重建中」。原因：未配置增量索引模式，采用全量重建处理每槽次的高频更新数据，导致重建任务堆积。
- 现象：批量添加索引的请求返回参数错误。原因：未按该品类文档的字段结构配置索引映射，遗漏槽液浓度、膜厚等核心参数的索引标记，导致校验失败。

## 怎么确认配好了
- 进入FastGPT v4.17.0的集合管理页面，查看索引重建日志，确认单批次重建耗时符合生产节奏，无持续堆积的未完成任务。
- 输入工艺参数相关的测试查询词，核对返回结果的相似度得分是否落在0.75–0.85区间内，无明显误匹配内容。
- 提交批量添加索引的测试请求，确认返回结果无参数校验失败的提示，索引状态同步更新。
- 配置两个测试知识库的优先级，发起跨库查询，确认优先返回指定知识库的匹配结果，验证优先级配置生效。
