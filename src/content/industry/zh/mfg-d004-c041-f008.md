# 电镀与化学表面处理的技术文档交叉审查：文档解析与分块

## 这个品类的数据长什么样
该品类的典型主体为电镀厂、电子连接器与五金件表面处理车间，日常产生的文档包括槽液分析记录、工艺参数卡、挂具记录、膜厚与附着力报告、危废台账、废水监测记录。数据来源涵盖客户表面处理规范、槽液化验结果、整流器运行数据、在线水质监测结果与危废管理台账。更新频率随业务场景变化，包括每槽次、每班及按固定监测周期要求。文档包含结构化数值字段与长文本记录，字段单位涉及行业专用计量标识。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档更新频率高、类型多样且包含专用字段，对解析与分块环节带来多重约束。首先，多类型文档需适配不同解析规则，无法仅依赖通用解析器完成结构化提取；其次，高频更新的批量文档需支持大文件上传与长时解析，避免中途中断；第三，专用字段与单位需在分块时保留关联关系，确保后续检索时可匹配槽液参数与对应的膜厚检测结果；最后，解析结果的准确性直接影响后续交叉审查的有效性，需避免字段割裂或遗漏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 文档包含短数值字段与长文本记录，该区间可平衡语义完整性与检索效率，避免割裂同一批次的工艺参数与检测结果 |
| `chunkSplitter` | 按标题+段落拆分 | 适配工艺参数卡、槽液分析记录等带结构化标题的文档，保留标题与对应字段的关联关系 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 批量上传的月度危废台账、废水监测汇总文件体积较大，该时长可避免单文件解析超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 车间需上传整月的槽液分析excel汇总文件，该取值可覆盖多数业务场景的文件大小需求 |
| `customPdfParse` | 启用自定义解析规则 | 针对固定格式的膜厚与附着力报告，可提取指定字段并保留单位信息，提升解析准确率 |
| `chunkSettingMode` | 手动配置 | 需针对不同文档类型调整分块参数，适配槽液记录、危废台账等多类业务文档 |

## 容易做错的三处
- 现象：上传excel槽液分析记录后无解析内容，后台无报错。原因：未启用`customPdfParse`配置excel结构化提取规则，默认解析器无法识别表格内的槽液浓度、批次号等专用字段。
- 现象：批量上传多份月度废水监测记录时中途中断，重启docker后无法继续解析。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`至合理区间，或`UPLOAD_FILE_MAX_SIZE`取值过小，导致大型汇总文件解析超时或超出上传限制。
- 现象：解析后的分块无法关联槽液参数与膜厚数据，模型回答偏离文档内容。原因：`chunkSize`取值过大，导致不同批次的槽液记录与对应膜厚报告被合并为同一分块，丢失字段关联关系。

## 怎么确认配好了
- 上传一份标准的槽液分析excel文件，检查解析后的文本是否包含槽液浓度、化验时间等指定字段。
- 上传一份超过500 MB的危废台账文件，确认解析进度未出现超时中断提示。
- 调整`chunkSize`至800字符，验证分块后的文本未割裂同一批次的工艺参数与膜厚检测结果。
- 查看FastGPT v4.17.0的后台解析日志，确认未出现文件解析超时或字段缺失的报错记录。
