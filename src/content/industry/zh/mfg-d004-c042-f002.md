# 石油炼制的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来自炼油企业生产运行、工艺、调度、设备与化验部门，日常文档包含操作规程、生产方案、物料平衡、馏出口质量报告、联锁台账、交接班记录、变更管理文件。数据来源覆盖DCS/APC、LIMS、罐区计量、原油评价、设备管理系统、能源系统，更新节奏涵盖实时、每班、每日。文档多包含装置编号、工艺参数、质量指标、操作节点等字段，单位涉及温度、压力、流量、物料量等工业标准单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。多源异构的数据来源与差异更新节奏，要求支持增量索引与全量索引的灵活切换，避免实时数据触发全量重建耗时过长。文档包含大量炼油专业术语与带单位的工艺参数，向量模型需适配工业领域的专业语义，同时保留单位信息以保证检索匹配的准确性。多套连续装置通过物流网络耦合的业务逻辑，要求索引保留文档间的关联关系，避免检索结果割裂装置间的协同关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 炼油类文档多包含长段落的工艺描述与参数表格，该长度可覆盖完整的工艺逻辑单元 |
| 重叠长度 | 100–200 字符 | 避免跨分块的工艺参数被割裂，保证检索时的语义连贯性 |
| `maxToken` | 8000–12000 token | 炼油专业文档的长文本需足够的token空间保留完整语义，适配FastGPT v4.17.0的模型输入上限 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非专业文档，保留与工艺问题强相关的检索结果，按实测标定可调整 |
| 单次搜索上限 | 前10条 | 炼油业务的问题多关联多套装置的协同数据，10条结果可覆盖主要的关联文档 |
| 重排 | 开启 | 专业术语的语义匹配易受表面关键词干扰，重排可提升结果的相关性排序准确性 |

## 容易做错的三处
- 现象：建索引流程停在最后一组文档的处理步骤，界面持续显示“索引构建中”无进度更新。原因：未针对炼油企业的多源异构数据配置增量索引策略，全量索引处理大批量实时更新的文档时出现阻塞。
- 现象：混合检索响应时长超过10秒，单次检索返回结果耗时显著高于纯向量检索。原因：未根据炼油文档的专业语义特征调整混合检索的权重分配，额外的关键词检索环节引入了不必要的计算开销。
- 现象：部分工艺流程图、联锁逻辑图无法被正确向量化，知识库中无对应检索结果。原因：仅支持文本类文档的向量化配置，未添加炼油行业常用的CAD图纸、PDF格式工艺流程图的解析支持。

## 怎么确认配好了
- 导入一批典型的炼油工艺文档，执行检索测试，核对返回结果是否包含与查询问题相关的装置编号、工艺参数等字段。
- 查看索引构建日志，确认增量索引仅处理更新后的文档，未触发全量重建。
- 调整配置项参数，对比不同参数下的检索响应时长与结果相关性，确定符合业务需求的取值区间。
- 测试不同类型的炼油文档（如交接班记录、联锁台账）的向量化结果，确认所有支持的文档类型均可被正确解析。
