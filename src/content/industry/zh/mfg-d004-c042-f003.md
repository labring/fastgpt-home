# 石油炼制的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
石油炼制的技术文档涵盖操作规程、生产方案、物料平衡、馏出口质量报告、联锁台账、交接班记录、变更管理文件。数据来源包括DCS/APC系统、LIMS实验室管理系统、罐区计量系统、原油评价数据库、设备管理系统与能源管理系统。数据更新频率覆盖实时、每班、每日，文档字段包含装置负荷率、馏程参数、硫含量、罐容、联锁触发时间等，不同文档的单位与格式差异明显，部分实时数据需按秒级刷新，批量报告则按班次汇总。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
石油炼制的多源异构数据与高频更新特性，要求多轮对话必须过滤冗余实时数据，避免超出模型上下文上限。多样的文档结构与字段单位，需要提示词明确指定文档分类规则与单位统一要求，确保交叉审查时的参数一致性。多套连续装置通过物流与能源网络耦合的业务逻辑，要求多轮对话跟踪不同装置的交互上下文，避免跨装置的参数混淆。实时处置工艺波动的需求，要求提示词优先返回可直接用于调度的结论。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定唯一会话标识 | 确保多轮对话的上下文关联正确，避免跨会话的参数混淆 |
| `messages` | 保留最近10条交互记录 | 覆盖核心业务交互，控制上下文总长度不超过模型上限 |
| `variables` | 绑定装置编号、原油类型、罐区编号等业务变量 | 自动填充上下文的专属参数，提升交叉审查的准确性 |
| 分块重叠长度 | 150-200 字符 | 避免跨块的装置编号、馏程参数等关键工艺信息丢失，适配石油炼制长文档的交叉审查需求 |
| 最大上下文长度 | 8000-12000 token | 适配石油炼制长文档与多轮交互的总字符量，适配FastGPT v4.17.0的模型上下文上限 |

## 容易做错的三处
- 现象：对话中第二个问题开始答非所问。原因：未正确绑定`chatId`参数，未跟踪`messages`参数的历史交互记录，导致上下文关联断裂。
- 现象：上传超过模型支持上下文的文档后触发报错。原因：未设置文档分块参数，未对长文档进行自动切片，导致数据加载超出上下文上限。
- 现象：工具调用后输出冗余的工具调用日志。原因：未配置`variables`参数过滤非必要的调用信息，导致返回内容包含工程师不需要的调试日志。

## 怎么确认配好了
- 导入一份石油炼制的物料平衡报告，发起连续3个关联问题，检查回答是否正确引用历史交互中的装置负荷数据。
- 上传一份超过10000字符的操作规程，检查系统自动拆分文档并完成检索，无上下文溢出报错。
- 发起包含工具调用的请求，检查返回结果仅包含AI对话内容，无冗余的工具调用日志。
- 查看对话日志存储设置，确认保留时长与条数符合业务需求，无无效日志堆积。
