# 精细化工间歇合成的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类主体为涂料、树脂、助剂、农化中间体及专用化学品企业，日常产生批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差变更单等文档。数据来源于配方与工艺库、原料批次台账、反应釜DCS系统、称量系统、LIMS系统及仓储系统，更新频率为每批生产或每个关键工艺步骤触发。文档包含工艺参数、批次信息、操作记录等字段，单位涉及温度、压力、投料量等工业标准单位，单批次数据关联完整工艺链路。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据来源分散且格式混杂，包含结构化工艺参数与非结构化操作记录，需适配多源数据接入。按批次触发的高频更新要求索引支持增量同步，避免全量重建耗时过长。多品种切换生产的场景下，需按批次或产品类型隔离向量数据，防止跨批次污染。文档关联工艺全链路的特性，要求分块逻辑保留工艺步骤的上下文完整性，避免拆分关键参数组合。同时因涉及配方保密，向量存储需满足私有部署要求，禁止跨域数据传输。本页面适配 FastGPT v4.17.0 版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配单批次工艺步骤的完整上下文，避免拆分关键反应参数组合 |
| 重叠长度 | 100–150 字符 | 保留相邻工艺步骤的关联信息，防止分块破坏反应逻辑链路 |
| 相似度阈值 | 0.75–0.85 | 匹配精细化工工艺参数的精度要求，过滤无关批次的历史数据 |
| 单次搜索上限 | 前 10 条 | 控制检索范围，适配多批次切换下的精准定位需求 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 150 token | 匹配单条工艺记录的典型长度，优化小文档的向量生成效率 |

## 容易做错的三处
- 检索结果返回跨批次的工艺数据，导致清洗残留判断失误。原因是未按批次标签隔离向量索引，不同产品的工艺向量混合存储。
- 解析文档时出现上下文截断报错，无法完整加载反应过程记录。原因是未根据文档长度调整`maxToken`配置，超出预设阈值。
- 增量同步延迟过高，无法匹配每批生产的更新节奏。原因是未开启增量索引模式，每次同步执行全量向量重建。

## 怎么确认配好了
- 上传单批次的完整工艺文档，检查向量分块结果是否保留了连续的工艺步骤描述，无关键参数拆分。
- 触发增量同步任务，核对仅新增批次的文档生成了对应向量，未触发全量重建。
- 输入工艺复核问题，检查检索结果仅返回当前批次的关联文档，无跨批次数据混入。
- 测试批量上传多格式文档，确认所有文档均完成向量生成与索引绑定，无异常报错。
