# 精细化工间歇合成的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自配方与工艺库、原料批次记录、反应釜DCS数据、称量系统日志、LIMS系统、仓储库存数据。日常文档包含批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据更新随每一批次生产、每个关键工艺步骤触发，覆盖多品种小批量的间歇合成流程，需重点保障配方保密与换品清洗确认环节的文档完整性。

## 这些特征在「模型接入与配置」这一环带来什么约束
多系统来源的文档格式差异，要求配置环节兼容结构化与非结构化数据的统一解析。按批次与关键步骤更新的数据，要求限制单轮上下文的总长度，避免冗余数据干扰审查逻辑。多品种切换的生产场景，要求配置能够按批次隔离文档数据，防止不同批次的配方与清场记录混淆。配方保密的要求，需限制知识库的调用范围，避免敏感工艺数据泄露。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配单批次生产的完整文档集合，避免截断关键复核信息 |
| `maxTokens` | 2000–3000 token | 覆盖完整的交叉审查结论输出需求 |
| `quoteMaxToken` | 1500 token/条 | 保障每条引用文档的关键内容完整，避免断章取义 |
| `temperature` | 0.1–0.3 | 降低随机输出，保障审查结论的一致性 |
| `AIPROXY_API_ENDPOINT` | 按企业内部部署环境填写 | 适配企业私有模型代理的访问路径 |
| `AIPROXY_API_TOKEN` | 按企业权限规则配置 | 保障模型调用的访问安全 |

## 容易做错的三处
- 现象：大模型调用后返回空响应，日志显示上下文长度超限。原因：未按本品类单批次文档量调整`maxContext`参数，导致批量生产的完整文档被截断，模型无法获取足够的审查依据。
- 现象：相同问题在不同批次审查中返回不一致答案。原因：未配置按批次隔离的知识库权限，不同批次的文档数据被混合调用，导致检索结果混乱。
- 现象：语音功能开启后无法正常调用语音模型。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或未遵循平台支持的语音模型接入规范。

## 怎么确认配好了
- 上传单批次完整生产文档集合，测试调用后检查上下文引用是否覆盖所有关键文档，无截断情况。
- 针对同一批次的同一复核场景，多次发起调用，确认输出结论的一致性。
- 配置知识库按批次标签隔离，验证不同批次的审查任务仅能调用对应批次的文档数据。
- 检查模型代理的访问日志，确认调用请求的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置与部署环境匹配。
