# 精细化工间歇合成的技术文档交叉审查：知识库检索与召回

## 这个品类的数据长什么样
该品类的典型主体为涂料、树脂、助剂、农化中间体及专用化学品生产企业。日常产生的文档包括批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据来源涵盖配方与工艺库、原料批次信息、反应釜DCS数据、称量系统、LIMS系统及仓储系统。数据更新频率为每批生产或每个关键工艺步骤，且因多品种、按批次切换生产，需严格区分不同批次的文档与数据，同时涉及配方保密相关的权限控制。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多批次、多文档类型的特征要求检索需按批次、工艺步骤精准匹配，避免跨批次混淆。高频按步骤更新的数据要求检索链路支持增量同步，确保召回内容与当前生产环节的最新数据匹配。多来源的结构化与非结构化混合数据，要求检索需兼容不同格式的文档与系统导出数据，同时需支持按字段条件过滤，比如原料批次号、反应釜编号。多品种切换生产的场景要求检索需支持快速切换知识库集合，适配当前生产品类的文档范围，同时需满足配方保密的权限要求。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写，以下配置均针对该版本的检索模块调整。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配精细化工工艺文档的严谨性要求，过滤低相关性的通用描述，保留与具体投料、反应步骤强相关的内容 |
| `limit` | 前8条 | 覆盖单批次生产的核心文档类型数量，避免上下文过载影响大模型处理 |
| `searchMode` | semantic | 适配多来源混合的工艺文档，优先召回语义匹配的内容，支持结构化与非结构化数据的统一检索 |
| `usingReRank` | 开启 | 对召回的初始结果进行重排序，修正单一相似度计算的偏差，确保反应过程记录、投料复核单等高优先级文档排在前列 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户的技术审查问题自动扩展查询词，补充工艺参数、批次编号等关键字段的检索，提升召回精准度 |
| `collectionIds` | 按当前生产品类绑定的集合ID | 仅检索当前生产批次对应的知识库集合，避免跨品类文档的干扰，符合配方保密的需求 |

## 容易做错的三处
- 现象：添加知识库后调用报错，日志显示字段解析失败或上下文超限。原因：未针对精细化工多类型、多批次的文档调整召回条数与重排参数，导致召回的文档总长度超出大模型支持范围。
- 现象：检索结果包含非当前生产批次的文档，批次号字段为空或不匹配。原因：未正确配置`collectionIds`参数，检索范围覆盖了无关的知识库集合，未按生产批次过滤文档内容。
- 现象：回答未严格引用知识库中的工艺内容，出现知识库外的描述。原因：未设置合理的`similarity`阈值，或未开启`usingReRank`，导致召回了低相关性的通用文档，干扰大模型输出。

## 怎么确认配好了
- 手动输入单批次的投料复核问题，检查召回结果的文档类型是否包含投料复核单、批生产指令等核心文档。
- 查看检索日志，确认仅返回当前绑定的`collectionIds`对应的知识库内容，无跨品类或跨批次的文档。
- 调整`similarity`的取值区间，验证召回结果的相关性是否符合工艺审查的严谨性要求。
- 开启`usingReRank`后，检查反应过程记录、清场记录等高优先级文档是否排在召回结果的前列。
