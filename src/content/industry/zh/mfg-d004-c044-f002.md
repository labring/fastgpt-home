# 纸浆造纸的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
典型数据来源包括木浆废纸批次台账、DCS/QCS系统数据、纸机在线测量记录、实验室检测报告、能源与水处理系统日志。日常生成的文档包含配浆单、打浆操作记录、纸机运行日志、在线质量曲线数据、实验室检测报告、断纸与换品台账。数据更新节奏涵盖实时、每班、每卷生产周期。文档字段多为工艺参数读数，包含打浆度、浆料配比、纸幅厚度、能耗数值等，部分为时序曲线类非结构化数据，无统一标准化格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
高频更新的实时、每班、每卷数据，要求索引支持增量更新，避免全量重建占用过多计算资源。多来源、混合结构化与非结构化的文档格式，要求向量模型兼顾工艺参数语义与文本内容的对齐能力。跨文档的工艺关联性强，比如配浆单与打浆记录、断纸台账与质量曲线，要求索引支持跨文档关联召回，防止遗漏关键信息。工艺参数的细微波动会影响生产结果，要求向量模型的匹配精度适配工艺参数的差异范围。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配纸机运行记录、实验室报告的单段文本长度，避免跨工艺环节的语义割裂 |
| 重叠长度 | 100–150 字符 | 覆盖配浆单、打浆记录的跨段落关联信息，防止分块丢失工艺上下文 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 匹配纸浆造纸工艺参数的细微差异，避免误判相似文档或遗漏关键关联 |
| 单次搜索上限 | 前 8 条 | 覆盖单卷生产的关联文档数量，平衡召回精度与响应速度 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 接入第三方向量模型时提示401状态码。原因是未正确配置API密钥与调用地址，或未授权对应向量服务权限。
- 自定义文档切分后，索引存储时重复块被自动删除，导致原切分顺序丢失。原因是系统默认开启了全局去重配置，未保留自定义切分的块顺序。
- 使用转发工具接入向量模型时，请求被错误路由到LLM接口。原因是未在渠道配置中明确指定该渠道为向量服务渠道。

## 怎么确认配好了
- 上传单份纸机运行记录文档，检查嵌入任务的状态是否显示成功，查看嵌入后的向量维度是否与所选模型匹配。
- 提交包含打浆度、纸幅厚度等工艺参数的查询，检查召回结果是否包含配浆单、打浆记录、断纸台账等目标品类文档，数量是否符合预期。
- 提交增量更新的单卷生产文档，检查索引是否仅新增了对应数据，未触发全量重建。
- 查看向量模型调用日志，检查是否存在401、超时、路由错误等异常返回。
