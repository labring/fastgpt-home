# 纸浆造纸的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
纸浆造纸场景的技术文档来源涵盖木浆废纸批次、DCS/QCS系统、纸机在线测量设备、实验室检测系统、能源和水处理系统。日常文档包含配浆单、打浆记录、纸机运行记录、在线质量曲线、实验室报告、断纸与换品记录，字段涉及浆料配比、打浆度、克重、水分、厚度等，单位包含吨、秒、g/㎡、%等。数据更新频率分为实时（如断纸记录）、每班（如能源消耗统计）、每卷（如单卷纸质量报告）三类。

## 这些特征在「工作流编排」这一环带来什么约束
数据多源且更新节奏差异大，要求工作流支持按实时、定时、按生产节点三种触发方式，适配不同文档的处理时效。文档类型包含结构化文本、曲线图表等，要求工作流配置多格式解析节点，适配不同字段的校验规则。纸浆造纸为高速连续幅材生产，出错后果直接关联纸卷降级、停机等，要求工作流配置失败重试与异常告警环节。特定字段的单位与业务逻辑绑定，要求工作流的参数校验环节匹配纸浆、纸张类的专用单位，避免参数不匹配导致的审查失效。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 循环触发时机 | 按每卷生产完成触发，或每班8小时定时触发 | 匹配纸浆造纸按卷生产、每班交接班的业务节奏 |
| 单次会话上下文长度 | 8000–12000 token | 适配配浆单、打浆记录等多文档的交叉审查需求 |
| 失败重试次数 | 2–3次 | 应对DCS系统临时波动导致的节点调用失败 |
| `variables` | 绑定`[batchNumber, pulpRatio, moistureContent, grammage]` | 关联纸浆造纸场景的核心业务字段 |
| `nodeId` | 绑定打浆记录节点、质量检测节点、断纸记录节点的ID | 确保工作流节点按业务逻辑依次执行 |
| 搜索触发条件 | 当配浆单配比偏差超出常规范围时触发 | 定向触发交叉审查，减少无效调用 |

## 容易做错的三处
- 循环运行时输出数组为空，现象为循环节点未执行预期的批量处理，日志显示输入参数为空。原因是未将`variables`绑定的批次数组正确传入循环节点的输入端。
- 工作流无法导出，现象为导出按钮置灰或弹出导出失败提示。原因是未在FastGPT v4.17.0版本中开启工作流的共享导出权限开关。
- 关闭模型思考输出开关后仍出现`<think>`标签，现象为问答结果中包含`<think>xxxxx</think>`格式的内容。原因是未在工作流中添加预处理节点过滤模型原生的思考输出内容。

## 怎么确认配好了
- 触发测试用的单卷生产数据，检查工作流是否按配置的循环次数执行绑定的节点。
- 查看工作流节点日志，确认`variables`参数正确绑定了批次号、浆料配比等核心业务字段。
- 触发配浆比异常的测试场景，确认搜索节点自动调用并返回相关的质量检测记录。
- 关闭模型思考输出开关，验证生成的审查结果中无`<think>`格式的标签内容。
