# 纸浆造纸的技术文档交叉审查：文档解析与分块

## 这个品类的数据长什么样
纸浆造纸行业的技术文档来源涵盖木浆废纸批次台账、DCS/QCS系统数据、纸机在线测量记录、实验室检测报告、能源水处理系统报表等。日常文档包含配浆单、打浆记录、纸机运行日志、在线质量曲线、断纸换品记录等，更新节奏分为实时、每班、每卷三类。文档结构包含结构化字段（如浆料配比、打浆度、克重、水分）与时序数据、表格、图像内嵌文本等，字段多附带专用单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
实时更新的在线质量曲线需要分块保留时序连续性，避免拆分破坏数据关联；每班/每卷的批量文档需要适配不同长度的内容，既不能因分块过小增加索引负担，也不能因分块过大丢失业务细节。结构化配浆单的多字段组合需要解析时保留字段对应关系，否则无法支撑后续交叉审查的逻辑校验。大体积的纸机历史记录会占用较长解析时长，需控制分块与解析流程的资源占用，避免超时或解析失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配配浆单、纸机运行记录的字段密度与业务逻辑关联长度 |
| `chunkSplitter` | 按段落+语义边界 | 保留在线质量曲线、断纸记录的时序与业务上下文 |
| `customPdfParse` | 开启 | 准确提取实验室报告、质量曲线的嵌入表格与图像文本 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配单卷纸机记录的大文件解析时长 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 容纳多班次的批量历史文档上传 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（配浆单/质量曲线）调整分块参数 |

## 容易做错的三处
- 现象：升级FastGPT v4.17.0后上传配浆单CSV文件报错，提示分块参数异常。原因：旧版本默认分块参数未适配纸浆造纸文档的字段密度，升级后默认参数变更导致不匹配。
- 现象：尝试接入minerU文档解析节点时，解析结果无法匹配纸浆造纸文档的字段格式。原因：未在节点配置中适配纸浆造纸文档的结构化字段规则，沿用了通用解析模板。
- 现象：调用知识库创建文件集合API时，未指定PDF解析参数导致内嵌表格字段丢失。原因：未在API请求中配置对应解析参数，沿用了系统默认的简化解析规则。

## 怎么确认配好了
- 上传单份配浆单CSV文件，检查解析后分块是否完整保留浆料配比、打浆度等字段的对应关系。
- 上传包含时序质量曲线的PDF文件，检查分块是否保留曲线的时间轴与数值关联，未出现内容拆分断裂。
- 调用FastGPT v4.17.0的知识库创建文件集合API，传入测试文档并指定`customPdfParse`参数，验证返回的分块结果包含内嵌表格内容。
- 上传1000 MB以内的批量历史纸机记录，检查解析任务未出现超时报错，且分块数量符合预期。
