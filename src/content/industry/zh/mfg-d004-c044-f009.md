# 纸浆造纸的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
纸浆造纸场景的技术文档包含配浆单、打浆记录、纸机运行记录、在线质量曲线、实验室报告、断纸与换品记录。数据来源覆盖木浆废纸批次、DCS/QCS系统、纸机在线测量设备、实验室、能源和水处理系统。数据更新节奏分为实时在线测量、每班班组记录、每卷纸生产收尾记录三类。单份文档包含生产批次、工艺参数、检测结果等字段，格式随部门和记录类型存在差异，无统一固定标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
多来源、多更新节奏的文档要求模型调用能够适配混合时序的文档关联，避免遗漏跨班次、跨设备的工艺关联信息。单卷纸生产的全流程文档数量较多，需要模型能够承载足够的上下文长度以覆盖完整工艺链路。专业工艺字段的识别需要模型保持输出的一致性，避免出现不符合造纸工艺逻辑的校验结论。同时生产数据的安全性要求模型调用链路不暴露内网生产数据，需限制访问权限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配单卷纸全流程生产文档的上下文需求，覆盖配浆、打浆、抄纸等多环节的关联校验 |
| `maxTokens` | 2000–3000 token | 满足单条交叉审查结果的输出长度，包含工艺调整建议与文档校验结论 |
| `quoteMaxToken` | 1500 token | 限制引用的单份文档片段长度，适配在线质量曲线、打浆记录这类长文本片段的提取 |
| 工作流/API 工具选择配置 | auto | 允许模型自主选择关联跨部门文档，适配配浆单与断纸记录的交叉校验场景 |
| `temperature` | 0.2–0.4 | 保证工艺建议的一致性，避免出现不符合造纸工艺常识的输出 |
| `AIPROXY_API_ENDPOINT` | 部署节点的内网访问地址 | 确保生产数据传输的安全性，避免公网暴露敏感生产信息 |
| `AIPROXY_API_TOKEN` | 与部署节点绑定的专属令牌 | 限制模型调用的访问权限，防止未授权访问生产数据 |

## 容易做错的三处
- 配置`AIPROXY_API_TOKEN`时填入无效令牌，界面显示模型测试失败，返回1742438308259968类错误码。原因是令牌与部署节点不匹配，或令牌已过期。
- 设置`maxContext`超过部署节点的内存上限，模型调用超时，返回504状态码。原因是未根据部署资源调整上下文长度，超出硬件承载能力。
- 未设置`toolChoice`为auto，模型无法自动关联跨部门的配浆单与断纸记录，导致交叉审查结果遗漏关键关联信息。原因是强制模型使用固定工具调用逻辑，无法适配动态关联的文档场景。

## 怎么确认配好了
- 在FastGPT v4.17.0的模型渠道测试页填入配置参数，发起测试调用，确认返回无报错且结果包含工艺参数校验内容。
- 上传单卷纸的完整生产文档集合，发起交叉审查任务，确认任务在合理时长内完成。
- 查看模型调用日志，确认`quoteMaxToken`限制生效，引用的文档片段未超出设定长度。
- 对比不同温度参数下的输出结果，确认`temperature`取值范围内的结果一致性符合工艺校验需求。
