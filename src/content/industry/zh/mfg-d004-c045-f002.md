# 纺纱与织造的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
纺纱与织造企业的日常技术文档包含配棉或配料单、工艺上机单、设备运转记录、纱线检验、坯布检验、疵点记录。数据来源涵盖原纤维检验报告、ERP系统、纺机与织机实时数据、条干仪、验布机采集结果、订单规格文件。数据更新频率随生产节奏变动，每批原料、每班生产、每匹布产出都会生成新的记录，部分工艺参数文档会随生产调整实时更新。文档字段包含纤维细度、捻度、匹长、疵点等级等带单位的业务参数，单份文档长度跨度从数十字符的短记录到数千字符的完整工艺方案。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据高频更新的特性要求索引支持增量同步，避免全量重建带来的性能损耗，适配每批原料、每班生产的新数据生成节奏。文档长度跨度大且包含带单位的专业参数，向量编码时需要保留字段标识以避免语义混淆，例如区分纤维细度的tex与dtex单位。疵点记录、工艺参数类文档存在大量强关联的连续内容，分块索引时需要保留足够的上下文重叠，防止捻度、匹长等关键参数被拆分在不同分块中。不同来源的数据格式差异较大，需要索引配置适配多类型文档的解析规则，确保专业字段的向量编码一致性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配配棉配料单、设备运转记录的单段内容长度，避免过度拆分工艺参数 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工艺参数关联信息，防止捻度、匹长等关键参数被拆分 |
| `defaultToken` | 8192 | 承载长工艺上机单的完整上下文，确保向量编码覆盖完整业务逻辑 |
| `maxToken` | 4096 | 控制单轮检索的向量调用成本，平衡检索精度与性能 |
| 相似度阈值 | 0.72–0.78 | 区分纱线疵点、工艺参数的有效匹配结果，过滤低相关性的历史记录 |
| 单次搜索上限 | 前 8 条 | 匹配纺机设备的多头数据关联需求，覆盖多台设备的参数对比场景 |

## 容易做错的三处
- 现象：调用知识库接口生成索引后，检索结果条数远少于预期。原因：未适配纺纱织造文档的高频更新节奏，未开启增量索引配置，导致新生成的疵点记录未被纳入索引。
- 现象：更换embedding模型后，已导入的知识库无法直接重建索引，必须重新上传源文件。原因：未提前配置索引版本关联机制，未保留原始文件与向量索引的映射关系。
- 现象：检索工艺参数时出现响应超时。原因：分块长度设置超过`defaultToken`的承载范围，导致向量编码耗时过长，超出接口响应阈值。

## 怎么确认配好了
- 上传单份完整的工艺上机单，查看分块后的片段数量是否符合分块长度设置的预期区间。
- 更换embedding模型后，执行批量重建索引任务，确认无需重新上传原始源文件即可完成索引更新。
- 模拟批量导入10份坯布检验记录，查看检索响应时长是否符合业务场景的使用要求。
- 检索特定纱线疵点的历史记录，确认相似度阈值过滤后的结果符合业务匹配的精度要求。
