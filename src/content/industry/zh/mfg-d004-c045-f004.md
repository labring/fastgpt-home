# 纺纱与织造的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
本品类数据主要来自原纤维检验报告、ERP生产系统、纺机与织机实时采集数据、条干仪、验布机等设备输出。日常文档包含配棉或配料单、工艺上机单、设备运转记录、纱线检验单、坯布检验单、疵点台账。数据更新节奏随每批原料、每班生产、每匹布产出同步调整，文档字段包含纤维品级、纱线捻度、织机转速、疵点编码等，对应单位包括tex、转/分钟、克/平方米等。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据随每批原料、每班、每匹布高频更新，工作流需支持按新文档上传或定时触发执行。品类文档字段多且关联紧密，需通过`variables`提取关键参数用于交叉校验。设备采集数据与人工填报文档存在格式差异，工作流需配置格式转换节点统一数据结构。单批次生产关联多类文档，需按生产节点顺序编排工具调用，避免跨批次数据混淆。疵点记录与工艺参数的关联校验需固定逻辑，无法通过通用规则覆盖。

## 配置怎么定
本页面配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `nodeId` | 绑定品类专属文档存储节点ID | 精准触发对应纺纱织造文档的校验流程 |
| `variables` | 按文档类型预设纤维、工艺、检验字段映射 | 适配配棉单、工艺单的固定参数结构 |
| 工具调用顺序 | 按配料→上机→检验的环节依次执行 | 贴合纺纱织造的生产逻辑 |
| 超时设置 | 600秒 | 容纳多份文档的读取与校验时长 |
| 重试机制 | 失败后重试2次，间隔60秒 | 应对设备数据临时传输异常 |
| 单次匹配上限 | 前8条召回结果 | 覆盖单批次生产的关联文档数量 |
| 上下文窗口 | 最大2000 token | 容纳单批次多份文档的关联内容 |

## 容易做错的三处
- 现象：工作流中配置的多行文本输出仅显示单行内容。原因：未开启`variables`的多行文本解析设置，换行符被自动过滤。
- 现象：问题分类节点执行耗时超出预期。原因：单次匹配上限设置过高，未针对品类文档做预筛选，导致大量无关文档参与匹配。
- 现象：工具未按预设顺序执行，部分工具未触发。原因：未通过`nodeId`配置前序节点依赖，未指定当前工具需等待前序节点完成后启动。

## 怎么确认配好了
- 上传一份配棉单与工艺上机单的组合文档，检查工作流是否自动触发执行。
- 查看工作流运行日志，确认工具按配料→上机→检验的顺序依次启动。
- 提取`variables`字段，核对提取的纤维品级、纱线捻度参数与原文档一致。
- 模拟工具调用失败场景，确认工作流触发重试机制，重试间隔符合预设设置。
