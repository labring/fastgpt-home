# 纺纱与织造的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
数据来源包括原纤维检验报告、ERP系统、纺机与织机运行数据、条干仪检测结果、验布机记录、订单规格文件。日常文档涵盖配棉或配料单、工艺上机单、设备运转记录、纱线检验单、坯布检验单、疵点记录。数据更新随每批原料、每班生产、每匹布产出同步推进。文档字段包含纤维断裂强度、捻度、布面疵点类型等，附带对应纺织行业通用单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求配置环节适配不同格式的文档导入与解析规则。高频更新的生产数据要求上下文窗口设置匹配实时检索的节奏，避免过期数据干扰审查结果。不同文档的专用字段与单位，需要在配置中明确关联规则，确保模型能准确识别配棉单的纤维指标、工艺单的捻度参数等专业内容。连续生产的批次关联性，要求召回的文档需绑定对应生产批次，避免跨批次数据混淆。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 按模型服务商提供的专属接口地址填写 | 适配阿里云、通义千问等模型的接入路径，避免404或400类接入报错 |
| `AIPROXY_API_TOKEN` | 填写平台生成的专属访问密钥 | 完成模型调用的身份验证，保障接入安全性 |
| `maxContext` | `8000–12000 token` | 适配纺纱织造多文档关联审查的上下文需求，覆盖单批次生产全流程文档 |
| `quoteMaxToken` | `1500–2000 token` | 限制单条召回文档的引用长度，避免冗余内容干扰模型判断 |
| `temperature` | `0.1–0.3` | 降低随机输出概率，确保技术审查结果的一致性与准确性 |
| `toolChoice` | `auto` | 自动选择是否调用检索工具，适配多文档交叉审查的动态需求 |

## 容易做错的三处
- 调用阿里云模型时返回400错误，原因是未正确配置`AIPROXY_API_ENDPOINT`的地域参数，或`AIPROXY_API_TOKEN`权限不足。
- 添加通义千问3-235b模型时出现404 page not found报错，原因是`AIPROXY_API_ENDPOINT`填写的路径与模型部署的实际接口不符。
- 索引到相关文档但模型未引用，原因是`maxContext`设置过小，无法容纳召回的关联文档内容，或`quoteMaxToken`限制过严截断了有效信息。

## 怎么确认配好了
- 进入模型接入页面，核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容与服务商提供的信息一致。
- 发起一次测试调用，查看返回的日志中是否包含正常的模型响应，无400、404类报错。
- 上传单份配棉单与工艺单，发起交叉审查测试，确认模型输出中引用了上传的文档内容。
- 进入团队管理页面，查看模型调用的记录，确认测试调用已被正常记录。
