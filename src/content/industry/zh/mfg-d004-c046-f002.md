# 肉制品与屠宰加工的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类的典型数据来自屠宰场、熟肉与冷冻调理食品企业，日常文档包含检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告。数据来源涵盖动物检疫信息、供应商批次、生产追溯系统、温度采集设备、金属检测设备与实验室检测结果。数据更新按每批、每班节奏执行，连续温控记录为实时更新。文档字段包含批次号、检测数值（如温度℃、菌落总数CFU/g）、检测时间、检疫编号等，部分为结构化字段，部分为自由文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据按批次关联且更新节奏差异大，要求索引系统支持按批次维度的元数据过滤，避免不同批次的文档向量混淆。连续温控记录为高频时序数据，索引的更新频率需要匹配每班、每批的更新节奏，避免数据滞后影响审查准确性。文档包含生物风险相关的检疫、检验内容，向量匹配需要更高的语义精度，避免错误关联无关批次的风险数据。生熟分区的文档存在明确的场景差异，索引需要支持按生产场景分类，提升检索的针对性。此外，部分文档为自由文本，需要适配灵活的分块策略，避免语义断裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配该品类单条文档的平均文本长度，避免分块断裂语义 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，适配屠宰记录、检验报告的长句结构 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的结果，避免将非对应批次的检疫文档误召回 |
| 单次搜索上限 | 前 20 条 | 适配该品类单次审查的文档数量需求，避免冗余结果 |
| 嵌入模型 | 阿里-emb3 | 开源版本下的高语义精度适配该品类的生物风险与生产文档的语义匹配需求 |
| `defaultToken` | 8192 token | 适配长文档如完整检疫证明的向量生成需求 |
| `maxToken` | 16384 token | 支持批量索引时的长文本处理上限 |

## 容易做错的三处
- 现象：索引任务长时间停留在“处理中”，界面返回超时状态码。原因：未按批次拆分索引任务，单批次包含过多温控记录与检验文档，导致索引耗时超出合理范围。
- 现象：检索结果中出现跨批次的文档，批次号字段为空或与查询条件不符。原因：未为文档添加批次号元数据，向量匹配未关联批次维度，导致不同批次的文档混淆。
- 现象：增强索引配置后检索精度未提升，返回结果包含无关的生熟分区文档。原因：未针对生熟分区的文档类型调整分块策略，导致语义匹配出现偏差。

## 怎么确认配好了
- 登录FastGPT v4.17.0的管理后台，查看索引任务列表，确认单批次文档的处理耗时符合预期。
- 输入指定批次号的检索条件，验证返回结果的批次号与查询条件完全匹配。
- 检索连续温控记录，确认返回结果的时间顺序与实际生产时间一致。
- 查看向量模型配置页面，确认`defaultToken`与`maxToken`的取值与预设配置一致。
