# 肉制品与屠宰加工的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据涵盖屠宰场、熟肉与冷冻调理食品企业的日常业务文档，包括检疫证明、屠宰分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告。数据来源于动物检疫信息、供应商批次台账、生产追溯系统、实时温度采集设备、金属检测设备与实验室检测结果。更新节奏为每生产批次、每班更新生产记录，冷链温度记录为连续采集更新。文档包含批次号、检疫编号、温度参数、检测指标等固定字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类数据按生产批次、班次高频更新，且关联检疫、温控、检测等多类文档，多轮对话需绑定特定生产批次的上下文，避免跨批次数据混淆。数据包含时序性的冷链温度记录，多轮对话需按时间维度整理信息，确保温度阈值判断准确。文档包含专属业务字段，提示词需明确指定提取对应字段，避免与其他品类数据混淆。实时更新的生产记录要求对话调用最新数据，需限制上下文缓存的过期时间，防止使用过时的批次信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前生产批次的唯一编号 | 确保多轮对话上下文仅关联对应批次的文档，避免跨批次数据混淆 |
| `messages` | 保留最近20条对话与文档引用 | 覆盖单批次生产全流程的审查需求，同时控制上下文体积 |
| `variables` | 注入当前批次的检疫编号、生产班次 | 让提示词精准匹配该批次的专属文档数据 |
| 单次搜索上限 | 调用前8条相关文档 | 匹配该品类多类关联文档的检索需求，避免遗漏关键记录 |
| 最大上下文长度 | 8000–12000 token | 适配多类文档的字段与内容长度，满足批次全流程审查的上下文需求 |
| 平台版本 | FastGPT v4.17.0 | 确保配置项与当前平台版本兼容 |

## 容易做错的三处
- 现象：对话响应耗时较长。原因：未限制单次检索的文档数量，加载了过多非关联的历史批次数据。
- 现象：返回`Unexpected end of JSON input`报错。原因：未正确配置`variables`注入批次专属参数，导致模型调用时传入格式错误的上下文数据。
- 现象：每次发起对话需重新创建会话，无法延续之前的审查上下文。原因：未绑定固定`chatId`到当前生产批次，导致每次对话生成新的会话ID，上下文无法复用。

## 怎么确认配好了
- 发起针对某生产批次的审查对话，确认上下文自动关联该批次的检疫、温控等文档。
- 输入包含批次号的查询，确认返回结果包含对应批次的专属字段数据。
- 连续发起多轮对话，确认`chatId`保持一致，上下文未被重置。
- 触发模型调用，确认未出现格式错误类的报错。
