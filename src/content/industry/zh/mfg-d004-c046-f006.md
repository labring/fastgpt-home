# 肉制品与屠宰加工的技术文档交叉审查：引用来源与溯源

## 这个品类的数据长什么样
该品类的核心数据涵盖动物检疫信息、供应商批次、生产追溯、温度采集、金属检测、实验室检验六大类来源。日常产出的文档包括检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告，每份文档绑定唯一批次号、温度值（℃）、检测时间、检疫编号等字段。数据更新节奏为每批生产对应更新一次批次关联文档，连续温控数据则按每班或实时更新。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的生物风险管控与全程追溯要求，使得引用来源与溯源环节需精准绑定单批生产数据。批次化的文档更新要求溯源时必须匹配唯一批次号，避免跨批次数据混淆。连续温控的实时性要求检索时需优先返回近时段的温度记录，确保生产过程的温控合规。多类文档的关联需求意味着溯源需同时覆盖检疫、生产、检验三类文档，且需保留字段的原始单位与标识，便于监管核查。生熟分区的生产要求，引用时需区分生肉与熟制品的文档，防止交叉污染相关数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 8000–12000 token | 匹配单批生产涉及的所有文档总长度，避免截断关键信息 |
| `quoteMaxToken` | 1500 字符 | 保留单份核心文档（如检疫证明、微生物检验报告）的关键内容 |
| 引用数据返回条数 | 前6条 | 覆盖单批生产涉及的多类文档，避免冗余信息过多 |
| `responseData` | 携带原始文档id与批次号 | 满足溯源时的精准关联与批次验证需求 |
| `detail` | 开启完整字段展示 | 保留温度值、检测时间等带单位的业务字段，便于监管核查 |
| 引用去重 | 按批次号去重 | 避免同批次重复文档被多次引用，确保溯源准确性 |

## 容易做错的三处
- 现象：批量上传100份批次文档后，近半数训练状态异常。原因：未为每份文档绑定唯一批次号作为标识，导致知识库索引时出现数据冲突。
- 现象：引用内容中出现重复的同批次检疫证明。原因：未配置按批次号的去重规则，或分块时未按批次维度过滤重复内容。
- 现象：使用变量引用模式时，无法找到温度参数设置入口。原因：未在对话组件中开启高级参数配置，导致温度设置按钮隐藏。

## 怎么确认配好了
- 上传单份带批次号的检疫证明文档，触发检索后检查引用结果是否包含批次号与检疫编号字段。
- 批量上传同批次的多类文档，验证引用结果中无重复的同批次内容。
- 触发对话检索，查看返回的`responseData`是否携带原始文档的唯一id与批次信息。
- 切换至变量引用模式，确认温度参数设置按钮正常显示并可调整取值。
- 在FastGPT v4.17.0版本中，测试单批文档的检索与溯源流程，确保所有配置项生效。
