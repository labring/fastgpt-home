# 肉制品与屠宰加工的技术文档交叉审查：模型接入与配置

本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的日常文档包含检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告等。数据来源包括动物检疫信息、供应商批次、生产追溯系统、温度采集设备、金属检测设备与实验室检测结果。数据更新按每批、每班执行，冷链温度记录为连续采集更新。文档字段包含批次号、检疫编号、温度值（单位℃）、检测结果、加工时间等，不同文档的字段结构存在差异，部分记录为结构化数值，部分为文本描述。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据按批次、班次更新且包含连续采集的温控数据，要求模型接入支持小批量高频数据处理；多类型文档的字段结构差异较大，要求配置适配不同格式的文档提取与关联；数据涉及生物风险相关的敏感信息，要求接入配置具备权限隔离能力；批次与检疫证明的关联是核心耗时环节，要求模型能快速匹配关联字段，避免过长的上下文处理导致延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 该品类单批次审查需关联多份文档，需容纳完整的批次溯源上下文 |
| `temperature` | `0.1–0.3` | 技术文档交叉审查需高一致性，避免生成错误的关联或提取结果 |
| `toolChoice` | `auto` | 需自动调用文档提取工具处理结构化与非结构化的生产记录 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接入地址 | 确保模型请求路由到正确的服务节点，避免接入异常 |
| `AIPROXY_API_TOKEN` | 绑定专属访问密钥 | 隔离不同生产批次的文档访问权限，保护敏感生产数据 |
| `maxTokens` | `1500–2000 token` | 单批次审查的输出内容需控制长度，保证处理速度与可读性 |

## 容易做错的三处
- 现象：调用模型时返回`'KokoroModel' object has no attribute 'mode'`类报错，原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，导致模型接入链路异常。
- 现象：知识库检索时提示“无可匹配内容”，原因：`maxContext`设置过小，未容纳完整的批次关联文档，导致模型无法关联检疫证明与生产记录。
- 现象：从冷链温度记录中提取的温度值返回空，原因：未针对带单位的数值字段配置正确的提取规则，导致模型无法识别`℃`单位后的数值内容。

## 怎么确认配好了
- 执行单批次文档的关联测试，核对模型返回的批次与检疫证明的对应关系是否符合实际业务逻辑，调整相关参数直至结果匹配。
- 调用测试接口传入异常格式的温度记录，确认模型能正确提取数值与单位，验证`toolChoice`配置是否生效。
- 检查接入日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置无误，无401或404类接入报错。
- 批量导入连续3个班次的冷链记录，确认模型处理耗时符合业务预期，调整`maxTokens`参数平衡处理速度与输出完整性。
