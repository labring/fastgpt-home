# 计量器具与实验室管理的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自企业计量室、CNAS体系实验室的计量管理系统、LIMS平台、外部校准机构证书及环境监测记录。日常文档包含量具台账、校准计划、校准证书、期间核查记录、试验原始记录、标准物质台账与偏离处置文件。数据更新随校准周期、单次试验完成或异常情况触发，单份文档包含器具编号、校准日期、测量值、测量不确定度、溯源链信息等字段，字段单位随测量对象匹配对应计量标准。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且格式多样，要求索引系统兼容多类型文档导入与结构化字段提取。更新节奏随校准周期、试验或异常触发，非固定周期更新，需支持增量索引以避免全量重建的耗时。文档包含专业计量术语与带单位的测量值，向量模型需适配工业计量领域的专业语义，避免语义混淆。同时，数据关联到质量判定环节，索引召回的准确性直接影响审查结果可信度，需严格控制召回的冗余与遗漏。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配计量文档中长段落的校准证书、原始记录，避免专业术语被拆分断裂 |
| 重叠长度 | 100–150 字符 | 保留跨分块的溯源链、测量不确定度等关键信息，防止语义割裂 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的非计量类文档，确保召回结果聚焦校准、溯源相关内容 |
| 重排 | 前 3 条 | 优先展示最相关的校准证书与溯源信息，匹配审查场景的核心需求 |
| `maxToken` | 4000–6000 token | 容纳多份校准证书与台账的关联内容，支持完整的交叉审查上下文 |
| `defaultToken` | 1000 token | 控制单条向量的存储开销，平衡检索效率与信息完整性 |

## 容易做错的三处
- 现象：索引构建进度卡在最后一组文档，界面进度条长时间无更新。原因：单批次导入的校准证书、原始记录数量过多，未配置增量索引模式，全量索引构建耗时超出系统处理阈值。
- 现象：混合检索请求响应时长超过10秒，无法返回有效结果。原因：未限制单次召回的文档数量，同时召回了大量非核心的计量辅助文档，导致模型处理负载过高。
- 现象：知识库创建时卡在索引步骤，界面显示字段解析失败。原因：导入的量具台账、标准物质台账存在未标准化的单位字段，系统无法完成结构化向量转换。

## 怎么确认配好了
- 导入单份校准证书文档，验证向量检索可召回同类型的校准计划与溯源记录。
- 触发增量更新任务，验证仅新增的期间核查记录被纳入索引，无需全量重建整个知识库。
- 调整相似度阈值，观察召回结果的相关性变化，确认阈值符合业务审查的实际需求。
- 发起混合检索请求，确认响应时长符合业务场景的可接受范围。
