# 设备点检与预防维修的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
这个品类的数据来自EAM/CMMS系统、设备传感采集终端、操作员点检记录、维修历史台账、备件库存清单与法定检验档案。数据更新节奏覆盖每班点检提交、日/周/月保养计划下发、故障发生时实时上报。日常业务文档包含设备台账、点检表、保养计划、维修工单、故障分析报告、备件清单、特种设备检验记录，字段包含设备编号、额定运行参数、点检点位实测值、备件型号与库存数量，单位涉及毫米、帕斯卡、运行小时数等。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源分散且更新频率差异大，要求工作流支持多数据源按不同时机触发，比如每班点检触发常规审查、故障发生时触发紧急校验。文档格式与结构多样，需工作流适配不同类型的业务文档解析，避免因格式不兼容丢失关键参数。由于出错后果严重，工作流必须加入交叉校验环节，比如核对备件库存与维修需求、校验法定检验记录的时效性。同时维修窗口需服从生产排产，工作流需支持与生产调度节点联动，确保审查环节不占用核心生产时间。

## 配置怎么定
当前版本为FastGPT v4.17.0，以下配置基于该版本的工作流模块设计：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 文件链接 | 绑定对应设备组的台账、点检表、备件清单数据源路径 | 覆盖该品类核心业务文档，确保审查数据完整 |
| 用户问题 | 预设「核对当前点检记录与设备台账参数是否匹配」「备件库存是否满足维修需求」 | 贴合设备点检与预防维修的业务场景，减少无效检索 |
| 知识库选择 | 绑定对应设备组的专属知识库，通过`variables`传入设备ID筛选 | 精准匹配该设备的历史文档与检验记录，避免跨设备数据干扰 |
| 全局变量赋值 | 以`nodeId`为标识，将维修工单编号、点检时间写入全局变量 | 实现跨节点数据传递，统一审查流程的上下文 |
| 单次搜索上限 | 前5条 | 匹配该品类单设备关联文档量适中的场景，避免冗余数据干扰审查 |
| 最大上下文 | 800–1200字符 | 适配设备文档字段密集的特点，保留关键参数与异常记录 |

## 容易做错的三处
- 工作流执行后返回结果条数不足3条，界面显示「检索结果为空」。原因是未绑定对应设备的专属知识库，仅使用全局知识库检索，无法匹配该品类细分的设备专属文档。
- 工作流触发后超时，日志显示超时状态码。原因是未按设备点检的更新频率配置触发时机，同时未限制单次搜索的返回条数，导致加载过多传感数据与历史工单。
- 全局变量未正确传递维修工单编号，导致审查结果无法关联对应维修任务。原因是未将`nodeId`绑定到工单编号的字段，变量赋值格式不符合系统要求。

## 怎么确认配好了
- 手动触发对应设备的点检审查工作流，检查返回的检索结果是否包含该设备的台账、点检表与备件清单。
- 查看全局变量面板，确认`variables`中的设备ID与`nodeId`标识已正确写入当前审查上下文。
- 模拟故障触发场景，验证工作流是否按预设的故障发生时的更新频率启动审查环节。
- 检查工作流的异常提醒节点，确认是否能在法定检验记录逾期时触发告警。
