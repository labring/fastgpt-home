# 设备点检与预防维修的技术文档交叉审查：模型接入与配置
本页适用FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类数据来自制造企业设备部、车间维修班组、公用工程部门的日常产出与系统存储，包含设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录等文档。数据来源覆盖EAM/CMMS系统、设备传感采集、操作员点检记录、维修历史档案、备件库存数据与法定检验信息，更新频率涵盖每班、日/周/月周期及故障发生时的即时更新。文档字段包含设备编号、额定功率、点检点位、实测数值、保养周期、故障代码等，部分字段附带单位标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
多来源、多更新节奏的数据要求配置支持跨系统数据拉取与增量同步适配；多类型文档的混合处理，需要配置兼容不同格式的解析规则，确保点检表、工单等结构化文档的字段识别准确性；字段附带的单位标识要求模型能精准匹配对应数值的单位，避免交叉审查时出现参数不匹配问题；核心业务环节的高风险属性，要求配置优先保障审查结果的一致性与准确性，降低非计划停机、安全事故等风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 设备相关文档包含台账、工单等多类长文本，需容纳足够上下文完成跨文档交叉校验 |
| `maxTokens` | `2000–3000 token` | 单份点检或维修工单的核心信息长度适中，避免输出冗余内容影响审查效率 |
| `quoteMaxToken` | `500 token/条` | 需精准引用设备台账、备件清单的具体字段内容，控制引用长度以保障可读性 |
| 工作流/API 工具选择配置 | `auto` | 需根据审查任务自动调用文档解析、数据查询工具，适配多文档交叉校验的复杂场景 |
| `temperature` | `0.1–0.3` | 技术文档审查需高一致性与准确性，降低随机输出带来的参数匹配错误风险 |
| `AIPROXY_API_TOKEN` | 按部署生成的密钥填写 | 完成接口身份验证，保障调用安全性 |

## 容易做错的三处
- 现象：调用Qwen3系列模型时返回不支持思考开关的提示，原因：未在模型接入配置中启用对应模型的专属思考模式参数，导致模型无法触发预设的思考逻辑。
- 现象：解析excel格式的点检表时返回通用提示文案，原因：未正确配置文档解析的表格识别规则，导致表格字段无法被完整提取，模型无法获取有效审查依据。
- 现象：本地部署的模型接入后无法使用工具调用功能，原因：未在配置中开启工具调用权限，或模型端点未正确映射function call接口，导致模型无法触发工具调用。

## 怎么确认配好了
- 上传单份设备点检表与对应设备台账，触发交叉审查任务，核对输出内容是否准确引用了文档中的具体字段与数值。
- 调用测试接口，查看返回的日志是否包含正确的模型调用参数与文档解析结果，确认参数配置已生效。
- 模拟故障发生时的文档提交场景，验证模型是否能快速定位关联的维修历史与备件库存信息。
- 检查配置页面的API端点与密钥是否与部署的模型服务一致，避免身份验证失败导致的调用异常。
