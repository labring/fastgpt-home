# 过程质量与成品放行的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
这个品类的核心数据来自制造企业的MES系统、在线检测设备、实验室检测系统、工艺参数文档、客户质量标准以及历史缺陷库。日常处理的文档包括控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单和质量月报。数据更新节奏覆盖每批生产、每班巡检以及持续采集的工艺参数，单份文档包含批次号、检验项、偏差值、评审结论等字段，部分结构化数据附带物理单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求向量模型需同时适配结构化的检验参数与非结构化的评审文本，高频更新的批次数据要求索引支持增量刷新，避免占用过多计算资源。不同文档类型的长度差异较大，控制计划单段内容可达千字符，而巡检记录单条仅数十字符，需要灵活调整分块规则以保留上下文完整性。同时，成品放行的关联判定需要精准匹配同批次的多份文档，对检索的召回准确率与相关性排序有较高要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类文档的常见内容密度，覆盖控制计划、SPC报表的单段信息 |
| 重叠长度 | 100–150 字符 | 避免分块切断工艺参数、检验项的完整逻辑，保留上下文关联 |
| 相似度阈值 | 0.75–0.85 | 精准匹配放行标准与检验记录的偏差项，降低不合格品相关文档的误召回率 |
| 单次搜索上限 | 前 10 条 | 该品类的关联文档多为同批次的检验、评审材料，无需过多冗余结果 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 界面显示文件持续处于索引中，现象为上传后索引状态长时间未更新，原因是未配置增量索引触发规则，且全量索引未适配高频更新的批次数据。
- 向量检索结果与本地测试结果不一致，现象为服务器端召回的文档与本地切分后的结果不匹配，原因是本地与服务器使用了不同的向量模型，未对齐嵌入维度与分块规则。
- 单批次数据无法关联多组向量，现象为同批次的多份文档生成的向量无法被统一检索到，原因是未为批次字段配置元数据索引，仅按单份文档独立生成向量。

## 怎么确认配好了
- 上传一份控制计划文档，查看索引完成状态是否在合理时间内变更，确认分块规则与索引刷新配置生效。
- 输入一条包含检验偏差的查询，核对召回的文档是否包含同批次的检验记录与评审材料，确认相似度阈值与搜索上限配置正确。
- 切换向量模型后上传同一份文档，对比生成的向量哈希值，确认嵌入维度与`defaultToken`参数匹配。
- 上传一份更新后的巡检记录，查看索引是否自动刷新，确认增量更新配置生效。
