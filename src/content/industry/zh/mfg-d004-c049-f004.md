# 过程质量与成品放行的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
本品类数据来自MES系统、在线检测设备、实验室台账、工艺参数库、客户验收标准及历史缺陷库。更新节奏按生产批次、每班频次持续采集。日常文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单及质量月报。数据字段包含检验项目、公差范围、批次标识、缺陷代码、评审结论等，单位随文档类型匹配，例如长度单位、重量单位或缺陷等级标识。

## 这些特征在「工作流编排」这一环带来什么约束
数据多源且按批次、频次更新，要求工作流支持按生产批次触发执行，同时适配多数据源的异步调用与结果聚合。文档类型多样，需为不同文档类型配置专属的检索匹配规则，避免跨类型数据干扰。过程涉及不合格评审与放行权限校验，需在工作流中嵌入权限验证节点，确保操作合规。数据关联的质量风险较高，需配置失败回滚与日志留存节点，便于异常追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| variables | 绑定批次号、检验标准ID两个核心变量 | 匹配本品类按批次触发的更新节奏，精准关联对应批次的检验数据与标准 |
| nodeId | 按文档类型分配专属节点ID | 区分控制计划、成品检验报告等不同文档的处理逻辑，避免配置冲突 |
| 超时时间 | 600秒 | 适配多数据源调用与复杂评审逻辑的执行时长，避免因数据量大导致任务中断 |
| 分支触发规则 | 按检验结果状态分支 | 对应不合格品评审与放行的不同处理路径，实现流程自动化分流 |
| 重试次数 | 2次 | 平衡任务成功率与资源消耗，应对临时的数据源调用波动 |
| 上下文调用上限 | 前8条历史记录 | 控制工作流的上下文规模，避免冗余数据影响处理效率 |

本配置规则适用于FastGPT v4.17.0及以上版本。

## 容易做错的三处
- 现象为工具调用模块同时输出AI回复与触发下一级分支，原因是未正确配置分支触发的执行条件，导致并行执行了两个逻辑分支。
- 现象为执行时弹出quote type error报错，原因是未按要求将变量绑定至`variables`参数，输入格式不符合系统校验规则。
- 现象为http请求任务在300秒内未完成被强制终止，原因是未调整默认超时配置，且循环嵌套内未设置合理的任务间隔，导致任务超时或资源占用过高。

## 怎么确认配好了
- 触发一次按批次的测试任务，核对绑定的核心变量是否正确传递至各节点。
- 检查节点ID配置，确认不同文档类型的处理逻辑未出现交叉覆盖。
- 模拟异常场景，验证重试机制与分支触发是否按预期执行。
- 查看工作流日志，确认所有数据源调用的结果均被正确聚合，且上下文规模符合预设要求。
