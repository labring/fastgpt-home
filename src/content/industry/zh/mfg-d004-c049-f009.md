# 过程质量与成品放行的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
该品类的数据覆盖从在制品到成品的全流程质量相关内容，来源包括MES系统、在线检测设备、实验室检测结果、工艺参数库、客户质量标准及历史缺陷记录。数据按生产批次、班组周期持续采集更新，日常处理的文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单及质量月报，字段包含检验项、参数阈值、缺陷类型、放行判定结果等核心质量信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据多源且更新频繁，对模型接入的稳定性和响应速度提出明确要求。多类型文档的结构差异要求配置适配不同格式的文本解析逻辑，专业质量术语则需要模型具备精准的语义识别能力。生产批次级别的数据更新要求模型调用链路支持低延迟处理，避免影响放行审核的整体节奏。不合格品误放行的风险要求配置需兼顾上下文完整性与结果准确性，同时需适配多来源数据的统一检索与审查逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多份SPC报表、检验报告、放行单拼接后的上下文长度，覆盖单批次全流程质量文档的核心审查内容 |
| `maxTokens` | 2000–3000 token | 平衡模型输出长度与响应速度，满足不合格评审结论、放行判定的详细输出需求 |
| `quoteMaxToken` | 1000–1500 字符 | 限定单条引用文档的长度，避免过长内容干扰重排模型的排序逻辑，适配品类文档的常见长度 |
| `temperature` | 0.1–0.3 | 降低随机输出概率，保证质量判定结论的一致性，符合合规审查的严谨要求 |
| `AIPROXY_API_ENDPOINT` | 按企业内部部署实例填写 | 适配内部大模型服务地址，确保质量数据传输的安全性与可控性 |
| `toolChoice` | auto | 允许模型自主选择是否调用检索工具，适配多源质量数据的动态调用需求 |

## 容易做错的三处
- 现象：模型调用后响应超时，日志显示`request timeout`。原因：未根据品类多文档拼接的特性调整`maxContext`参数，导致上下文长度超出模型响应阈值。
- 现象：重排模型部署测试正常，但每次检索返回结果均为false。原因：未配置`quoteMaxToken`限制单条引用长度，过长的检索内容超出重排模型的输入上限，导致模型无法正常处理。
- 现象：知识库检索内容过长后，重排模型未被触发调用。原因：未结合品类批量更新的文档特性调整上下文分段逻辑，长文档未被正确拆分后送入重排环节。

## 怎么确认配好了
- 测试单批次质量文档的模型调用响应时间，确认符合业务审核的时间要求，调整参数至符合预期节奏。
- 提交包含不合格评审记录的测试用例，核对模型输出的判定结论与文档内容的一致性，验证`temperature`参数的设置效果。
- 导入多份拼接后的质量文档，检查重排模型是否正常触发并返回有效排序结果，确认`quoteMaxToken`的配置适配文档长度。
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置，验证模型服务的连通性，确保数据链路正常。
