# 通用机械设备装配的技术文档交叉审查：HTTP 接口与外部系统

## 这个品类的数据长什么样
通用机械设备装配的日常文档包含装配工艺卡、BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单。数据来源通常为PLM/ERP、零件检验数据、装配工具采集设备、试验台、MES系统及客户技术协议。数据更新节奏为每台设备或每订单一次，单份文档包含设备型号、订单号、物料编码、扭矩值（单位N·m）、间隙值（单位mm）、同轴度公差等结构化字段，部分文档附带非结构化的装配步骤描述与试验照片。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源分散的数据来源要求接口支持跨系统拉取数据，需兼容不同外部系统的鉴权与数据格式。单台设备或每订单的更新节奏，要求接口支持按设备ID或订单号精准定位数据，避免拉取冗余的历史文档。结构化字段附带特定单位的要求，需在接口配置中定义严格的字段映射规则，防止单位不匹配导致的校验失败。多层BOM与实物齐套的核对需求，要求接口返回层级化的BOM数据结构，便于逐层核对物料匹配情况。

## 配置怎么定
本配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| API请求超时时间 | 600秒 | 适配多源数据拉取的耗时需求，避免因数据量较大导致请求中断 |
| `Authorization` | Bearer {固定令牌} | 符合外部系统通用的接口鉴权标准，保障数据访问安全 |
| `responseData` 字段过滤 | 仅返回装配工艺卡、BOM、扭矩记录、间隙调整记录 | 减少无效数据传输，提升接口响应速度 |
| 单次接口返回上限 | 前20条 | 匹配单台设备关联文档的常规数量规模，避免返回过多数据占用资源 |
| `variables` 传入参数 | 包含设备型号、订单号 | 精准定位对应设备或订单的专属文档数据 |
| 接口重试次数 | 3次 | 应对临时网络波动或外部系统短暂响应延迟的场景 |

## 容易做错的三处
- 调用`/api/v1/chat/completions`接口时未传入正确的appId参数，导致无法关联对应知识库的装配文档。原因是未按照品类的单设备/单订单需求，将设备ID或订单号绑定到appId配置中，仅使用默认全局配置。
- 接口返回的扭矩记录字段未做单位校验，出现扭矩值单位与本地校验规则不符的报错。原因是未在接口配置中指定字段的单位映射规则，直接使用外部系统返回的原始数据，未统一转换为标准N·m单位。
- 接口请求超过预设超时时间，返回504状态码。原因是未设置合理的超时时间，未配置重试机制，无法应对多源数据拉取的耗时场景。

## 怎么确认配好了
- 调用配置好的接口，传入测试用的设备型号和订单号，检查返回的文档字段是否包含BOM、扭矩记录、间隙调整记录等核心内容。
- 查看接口鉴权日志，确认`Authorization`头的格式正确，未出现401鉴权失败报错。
- 触发一次交叉审查流程，检查是否能拉取到对应设备的装配工艺卡和出厂检验单数据，完成多层BOM的自动核对。
- 模拟临时网络中断，检查接口是否触发重试机制，未出现直接的请求失败报错。
