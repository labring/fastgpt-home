# 通用机械设备装配的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
数据来源包括PLM/ERP系统、零件检验数据、装配工具采集记录、试验台数据、MES系统及客户技术协议。日常文档包含装配工艺卡、BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单，字段含物料编码、扭矩值（单位N·m）、同轴度数值（单位mm）、拧紧时间等，更新节奏为每台设备或每订单一次。

## 这些特征在「向量模型与索引」这一环带来什么约束
品类按订单多品种装配的特性，要求索引需按订单维度拆分集合，避免不同订单的文档块混淆。高频次的单台设备级更新，要求索引支持增量更新，减少全量重建的耗时。多类型带单位的结构化字段，要求向量模型适配结构化元数据的编码，提升关联匹配精度。多源异构的数据格式，要求索引前的预处理环节统一字段命名与单位规范，降低后续关联的误差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配装配工艺卡、BOM等文档的单段信息密度，避免块内信息分散 |
| 重叠长度 | 50–80 字符 | 保留扭矩记录、间隙调整记录等分段内容的上下文关联 |
| 相似度阈值 | 0.75–0.85 | 匹配装配工艺与实物检验数据的关联度，过滤低相关性内容 |
| 单次搜索上限 | 前10条 | 适配单台设备装配的文档关联规模，避免冗余信息干扰审查 |
| `maxToken` | 4000 token | 适配批量文档入库的token限制，符合FastGPT v4.17.0的参数要求 |
| 最大上下文 | 3500 token | 覆盖单台设备全流程文档的关联信息长度 |

## 容易做错的三处
- 现象：切换知识库索引时界面显示“请求超时”或返回504状态码，原因是未按订单维度拆分索引集合，单批次索引数据量超出系统处理阈值。
- 现象：知识库内容不多但持续处于“重建中”状态超过24小时，原因是未启用增量索引更新，每次触发重建时全量处理所有装配文档，而该品类文档按单台设备高频更新，全量重建耗时过长。
- 现象：批量添加索引时接口返回“缺少必填字段”的报错，原因是未按照品类文档的专属字段结构配置块元数据，遗漏扭矩值、同轴度等关键字段的映射。

## 怎么确认配好了
- 手动上传一份装配工艺卡与对应的扭矩记录，查看索引生成后的块关联结果，确认相似度匹配度符合预期阈值。
- 发起单台设备文档量的小批量索引重建，查看系统耗时与状态，无超时报错或异常停留。
- 检查索引集合的元数据字段，确认包含BOM物料编码、扭矩值单位等品类专属信息。
- 调用批量添加索引的测试接口，传入符合品类文档结构的样本数据，确认接口返回成功且元数据完整。
