# 通用机械设备装配的技术文档交叉审查：引用来源与溯源

## 这个品类的数据长什么样
通用机械设备装配的核心数据来自PLM/ERP、零件检验数据、装配工具采集系统、试验台、MES及客户技术协议。日常文档包含装配工艺卡、BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单，每台设备或每订单更新一次。文档字段包含物料编码、扭矩值、同轴度数值、预紧力单位（N·m）等，不同文档的字段结构差异明显。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源分散的数据需要关联不同系统的唯一标识，确保溯源时能精准匹配到对应文档。按订单/设备更新的频率要求溯源逻辑需动态绑定当前业务上下文，不能使用全局固定的知识库。多样的文档类型与差异化的字段结构，要求引用规则需按文档类型配置，避免混淆不同字段的含义。同时，装配失误的高后果要求溯源结果的准确性，需严格关联实物与文档的对应关系。

## 配置怎么定
针对通用机械设备装配的场景，需结合品类特征调整核心配置，其中`quoteMaxToken`、`responseData`、`detail`三个参数需重点匹配业务需求，具体配置如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文token数 | 8000–12000 token | 适配装配文档的长文本特征，避免截断BOM、工艺参数等关键内容 |
| 分块长度 | 300–500字符 | 平衡文档完整性与召回精度，避免单块内容过于零散或过长 |
| 单次搜索上限 | 前6条 | 覆盖单台设备的核心装配文档，避免冗余信息干扰交叉审查 |
| 缓存有效期 | 24小时 | 适配每订单更新的频率，确保召回的是当前订单的最新文档 |
| 引用来源返回开关 | 开启 | 需将PLM/ERP的sourceid与文档字段绑定，确保溯源可查 |
| 详情展示开关 | 按文档类型配置 | 扭矩记录需展示扭矩值与拧紧时间，BOM需展示物料编码与数量，适配不同文档的字段需求 |

## 容易做错的三处
- 现象：部分提问无法召回对应装配文档，召回结果为空。原因：未配置按订单ID关联数据源的规则，仅使用全局知识库召回，无法匹配当前设备的专属文档。
- 现象：上下文引用的文档无法渲染为Markdown格式，仅展示纯文本分块内容。原因：知识库分块时未保留文档的格式标记，导致引用时无法还原原始文档排版。
- 现象：返回的引用结果未携带sourceid字段，无法溯源到原始文档。原因：未开启引用来源返回的配置，未绑定数据库字段与文档元数据，导致无法输出溯源信息。

## 怎么确认配好了
- 上传单台设备的装配工艺卡、BOM等专属文档，发起包含物料编码或扭矩值的提问，验证召回结果包含当前订单的文档。
- 查看返回结果的元数据部分，确认存在sourceid字段，可关联到原始上传的文档。
- 检查引用的文档片段，确认格式与原始Markdown文档一致，无纯文本乱码或缺失标记。
- 调整最大上下文token数至不同区间，验证长文档的召回完整性，确认无关键内容被截断。
