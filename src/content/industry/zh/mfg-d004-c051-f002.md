# 金属切削加工的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES系统及量检具数据。日常文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表及量具校准记录。数据更新随每工单、每件工件、抽检批次或刀具更换触发，文档字段包含刀具编号、切削转速、进给量、尺寸公差值等，单位多为毫米、转每分钟、毫米每分钟。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且格式多样，包含结构化切削参数、半结构化工艺文档与数控程序代码文本，需适配混合格式的向量提取规则。更新频率高且触发节点分散，索引任务需支持增量更新，避免全量重建带来的重复计算。单份文档内容差异显著，数控程序可能包含大量代码行，工艺卡则为段落式说明，需灵活调整分块规则适配不同文本长度。字段包含精密数值类参数，向量提取需保留数值关联特征，防止专业工艺逻辑的语义丢失。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本的界面规则制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配数控程序与工艺卡的混合文本长度，避免单块内容过载 |
| 重叠长度 | 100–200 字符 | 保留跨块的工艺步骤关联信息，防止分块断裂关键逻辑 |
| `defaultToken` | 按实测标定 | 适配文档内的专业术语与数值参数的向量编码阈值 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 单次召回上限 | 前 8 条 | 匹配机加工文档的关联密度，覆盖相邻工序的交叉审查需求 |
| 重排开关 | 开启 | 过滤无关的刀具参数或机床日志，提升交叉审查的精准度 |

## 容易做错的三处
- 索引任务长时间无进度，界面显示未完成状态。原因是未配置增量索引触发规则，全量扫描高频更新的工艺文档与数控程序，导致计算资源被耗尽。
- 调用上传文件API后无法获取索引完成的判断依据。原因是未启用索引状态的轮询参数，未绑定任务完成回调的接口规则。
- 向量召回结果与实际工艺需求偏差较大。原因是未针对机加工文档的数值字段调整向量模型的编码规则，导致专业切削参数的语义关联被弱化。

## 怎么确认配好了
- 上传一份包含数控程序与工艺卡的混合文档，查看分块预览界面的内容完整性，确认分块规则适配文档特征。
- 调用上传文件API后，通过系统提供的任务状态接口轮询，验证是否能获取到索引完成的状态标识。
- 切换不同的向量模型，对比召回结果中切削参数的关联度，确认模型适配机加工专业文本的编码效果。
- 提交交叉审查任务，查看返回结果的关联文档数量，确认单次召回上限符合业务场景需求。
