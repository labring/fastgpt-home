# 金属切削加工的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
金属切削加工的业务数据覆盖机加工车间全流程，日常文档包括工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表、量具校准记录。数据来源涵盖产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES系统、量检具数据终端。数据更新随工单、单件加工、抽检及刀具更换触发，单篇文档包含工序号、G代码、刀具直径、进给率、尺寸公差等字段，单位多为毫米、转每分钟、小时等加工专用单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多类型、高更新频率的业务数据要求对话需精准匹配当前工单的专属文档，避免跨工单数据混淆。多源数据的字段差异，要求提示词需明确区分工艺参数、数控代码、检验记录等不同文档类型，防止字段匹配错误。高频更新的数据需限制上下文长度，避免历史冗余数据干扰当前审查。此外，加工过程的出错后果直接关联审查结果的严谨性，对话需逐步引导用户提供完整的工序与检验信息，避免遗漏关键校验项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 适配金属切削单篇文档的字符长度，保留多轮对话的工序参数与校验记录 |
| `variables` | 注入工单ID、刀具编号 | 关联对应工单的专属文档数据，避免检索到无关工单的工艺记录 |
| `chatId` | 绑定当前工单唯一标识 | 区分不同工单的对话上下文，确保日志与会话数据持久化关联 |
| `messages` | 保留最近10轮对话 | 避免过多历史加工文档数据干扰当前审查 |
| 问题优化 | 按实测标定 | 适配多类型加工文档的字段提取需求，避免泛化提问导致的匹配偏差 |
| 单次匹配文档上限 | 前3条 | 聚焦当前审查的核心文档，避免过载导致的处理延迟 |

## 容易做错的三处
- 现象：对话日志无记录或自动清空。原因：未绑定`chatId`参数，系统无法持久化会话关联数据，导致日志未正常保存。
- 现象：工作流执行至AI对话环节后中断，无报错提示。原因：未通过`variables`注入当前工单的专属标识，系统无法检索到对应工序卡、数控程序等数据，导致流程终止。
- 现象：流式输出延迟过长或无分段返回。原因：未设置合理的上下文截断阈值，系统处理过多历史对话数据，无法及时返回流式片段。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本，绑定工单ID发起对话，检查会话列表中是否存在对应`chatId`的专属记录。
- 注入刀具编号变量，发起「检查当前刀具的校准记录」提问，检查检索结果是否包含对应刀具的量具校准数据。
- 触发流式输出功能，检查是否按字符分段返回内容，无整体延迟卡顿。
- 发起多轮对话，先询问当前工序的装夹方案，再询问对应数控程序的合规性，检查系统是否保留前一轮的工序信息进行交叉校验。
