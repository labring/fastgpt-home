# 金属切削加工的技术文档交叉审查：引用来源与溯源

本页面适配 FastGPT v4.17.0

## 这个品类的数据长什么样
金属切削加工的技术文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表、量具校准记录等。数据来源覆盖产品图纸与三维模型、CAPP/CAM系统、机床采集数据、刀具管理系统、MES系统与量检具数据。文档更新随工单、单件加工或抽检、刀具更换触发，单份文档包含工序号、刀具编号、尺寸公差、进给参数等字段，单位涵盖毫米、转每分钟、毫米每齿等加工专用计量标准。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源异构的数据来源要求引用溯源必须关联各系统的唯一标识，避免不同文档的同名称字段混淆。高频更新节奏要求溯源环节能实时拉取最新的刀具磨损、量具校准数据，确保审查依据为当前有效版本。长文本类文档如数控程序、工序卡的存在，要求溯源环节需适配大token量的文本拼接，同时避免截断关键尺寸参数。出错后果严重的业务特性，要求溯源必须精准绑定文档版本与加工工单，防止引用过期或错误数据引发工件报废。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `8000–12000 token` | 金属切削加工的数控程序、工序卡单条分块长度普遍在此区间，可避免截断关键尺寸、进给参数等核心审查内容 |
| `responseData` | 完整源数据 | 需溯源量具校准记录的校准日期、刀具寿命、机床运行参数等非文本字段，确保溯源信息完整 |
| `detail` | 开启 | 需展示工序卡的基准选择说明、装夹方案细节，满足交叉审查的详细验证需求 |
| 单次搜索上限 | 前20条 | 单工单关联的技术文档数量通常在15-25条范围内，覆盖工艺、刀具、检验等核心审查依据 |
| 最大上下文 | `15000 token` | 适配多份工序卡、数控程序拼接后的总token量，满足长文本交叉审查的场景需求 |
| 重排规则 | 按源文档更新时间排序 | 优先检索并引用最新版本的文档，如刀具更换后的巡检表、最新版工艺路线，确保审查依据有效 |

## 容易做错的三处
- 现象：界面显示的模型上下文token数与实际传入AI的源文档token数不符。原因：未正确配置`quoteMaxToken`，导致部分长文档块被提前截断，仅保留部分内容传入。
- 现象：设置了`quoteMaxToken`为1500，但知识库内超过该长度的文档块仍被引用。原因：未将文档分块长度设置为适配`quoteMaxToken`的区间，导致单块内容超出限制后仍被整体传入。
- 现象：HTTP请求处理后的知识库引用数据无法被AI识别。原因：未按要求配置`responseData`为标准格式，缺失源文档的唯一标识字段。

## 怎么确认配好了
- 查看知识库分块后的预览界面，确认单块文档的token数不超过`quoteMaxToken`的设置值。
- 发起一次测试工单审查请求，对比FastGPT界面显示的上下文token数与日志中记录的传入token数，确认数值一致。
- 检查引用溯源的展示模块，确认每个引用条目都附带了源文档的更新时间、唯一编号等标识。
- 模拟刀具更换后的工单审查，确认最新的刀具管理系统数据被优先检索并展示在引用列表中。
