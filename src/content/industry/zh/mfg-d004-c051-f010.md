# 金属切削加工的技术文档交叉审查：知识库检索与召回

## 这个品类的数据长什么样
金属切削加工的业务数据来自产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES系统、量检具数据。日常生成的文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表、量具校准记录。数据更新随每工单、每件工件加工、抽检结果、刀具更换触发。文档字段包含刀具直径、切削速度、进给量、公差值等，单位多为mm、m/min、mm/r。

## 这些特征在「知识库检索与召回」这一环带来什么约束
由于数据来源分散且更新频率高，知识库需支持高频增量同步，避免召回过时的工艺或检验记录。文档类型涵盖结构化参数、代码类数控程序、非结构化巡检记录，检索需兼顾关键词匹配（如刀具型号）与语义理解（如装夹方案）。字段的特定单位要求检索时需匹配单位关联参数，否则会召回不适用的内容。同时，业务核心环节的文档需优先召回，需配置精准的召回权重。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75-0.85 | 匹配金属切削文档的参数严谨性，过滤低相关的非工艺类内容 |
| `limit` | 前10条 | 覆盖核心工艺环节的参考文档，避免过多冗余数据占用上下文 |
| `searchMode` | `mixedRecall` | 兼顾数控程序的型号关键词匹配与工序卡的语义逻辑理解 |
| `usingReRank` | 开启 | 对召回结果重新排序，优先展示装夹方案、数控程序等核心业务文档 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展用户检索词，补充刀具型号、工序编号等业务专属关键词 |
| `collectionIds` | 绑定对应车间的专属ID | 限定检索范围，避免跨车间的无关文档被召回 |

## 容易做错的三处
- 现象：检索结果与知识库内的工艺文档内容不一致，返回旧版工序卡参数。原因：未开启`datasetSearchUsingExtensionQuery`，且`similarity`阈值设置低于0.7，召回了未更新的旧文档。
- 现象：调用知识库检索接口返回空结果，无匹配内容。原因：未配置`collectionIds`，检索范围覆盖了无关的非金属切削类知识库集合。
- 现象：检索响应超时，或返回结果条数远低于预期。原因：`limit`设置为前20条以上，且未开启`usingReRank`，导致大量低相关文档被加载处理。

## 怎么确认配好了
- 上传一份测试用的数控程序文档，检索关键词“T10刀具切削参数”，查看召回结果是否包含该文档的切削速度、进给量等核心参数。
- 检查`usingReRank`开关状态，查看检索结果的排序是否将装夹方案、数控程序等核心业务文档放在前列。
- 查看FastGPT v4.17.0的知识库同步日志，确认数据更新频率匹配工单、刀具更换的触发节奏。
- 传入指定的`collectionIds`调用接口，验证返回结果仅来自目标车间的知识库集合，无跨车间无关内容。
