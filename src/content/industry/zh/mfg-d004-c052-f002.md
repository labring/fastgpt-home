# 钢材轧制与精整的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
热轧、冷轧、型钢、钢管企业的日常技术文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书。数据来源覆盖板坯或钢坯批次、加热炉、轧机自动控制、在线测厚测宽、表面检测、MES系统。数据更新频率为每卷或每支实时更新，文档按卷级关联，核心字段包含厚度、温度、批次号、板形等级、缺陷类型等，需支持卷级全流程追溯。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时更新的卷级数据要求索引支持增量同步，避免全量重建消耗过多计算资源；专业字段与工业术语需要向量模型适配特定工艺语义，通用模型可能无法准确匹配板形缺陷、厚度偏差等业务查询；卷级追溯的业务需求要求索引支持按批次号关联多份文档，确保全流程数据可被统一检索；多样的文档类型（长规程、短检测报告）要求分块策略适配不同长度，避免拆分关键工艺参数或丢失短文档的完整语义。

以下配置基于FastGPT v4.17.0版本，适配钢材轧制与精整场景的技术文档交叉审查需求：
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配轧制规程、加热制度等长文档的语义完整性，避免专业工艺术语被拆分 |
| 重叠长度 | 50–80 字符 | 保留相邻分块的上下文关联，确保板形、厚度等跨块参数的语义连贯 |
| 相似度阈值 | 0.72–0.85 | 过滤大量重复的批次通用参数，精准匹配具体卷号的异常记录与定制化规程 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 16000 | 覆盖热轧、冷轧全流程的技术文档总长度，避免截断关键工艺参数 |
| 单次搜索上限 | 前10条 | 平衡召回效率与业务需求，覆盖多维度的工艺参数关联记录 |

## 容易做错的三处
- FastGPT界面显示索引中超过30分钟无进度。原因：未针对实时更新的卷级数据配置增量索引，全量重建索引扫描大量历史数据，耗时超出预期。
- 自定义索引配置后返回无匹配结果。原因：未适配钢材轧制文档的专业字段与术语，通用分块策略拆分了连续的工艺参数描述，导致向量语义丢失。
- 接入本地m3e向量模型后出现请求超时。原因：未设置`maxToken`合理上限，单批次关联的多份文档总长度超出模型处理能力，触发请求超时。

## 怎么确认配好了
- 查看索引任务日志，确认增量同步触发规则已绑定卷级数据更新节点，无全量扫描任务积压。
- 输入轧制厚度偏差、表面缺陷类型等专业查询词，核对返回结果是否包含对应卷号的检测报告与规程文档。
- 检查向量模型调用日志，确认`defaultToken`与`maxToken`的取值未触发模型截断报错。
- 验证自定义索引字段是否包含批次号、钢卷规格等核心业务字段，确保关联查询可正常执行。
