# 钢材轧制与精整的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
该品类的典型主体为热轧、冷轧、型钢、钢管企业，日常产生的文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书。数据来源覆盖板坯或钢坯批次、加热炉、轧机自动控制、在线测厚测宽、表面检测、MES系统。数据更新频率为每卷或每支钢件实时生成，文档字段包含批次号、加热温度、厚度偏差、表面缺陷等级等，对应单位为毫米、摄氏度、等级标识等。本文基于FastGPT v4.17.0版本完成配置说明。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且包含自动化设备采集的结构化数据、人工填写的纸质文档，要求配置支持多源数据接入与格式兼容。实时且卷级的更新节奏，要求配置适配高频增量索引与批次关联的上下文管理。文档包含工艺规程、检测记录、质保书等多类型内容，且需关联同一批次的全部文档完成交叉审查，要求配置足够的上下文容纳空间。表面质量报告包含图片类内容，要求配置支持多模态向量的模型接入能力。工艺审查结果直接关联生产质量，要求配置严谨的生成参数降低随机性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启 | 需处理表面质量报告中的缺陷检测图片，支持多模态文档索引与审查 |
| `temperature` | 0.1–0.3 | 工艺参数审查需保持严谨，降低生成结果的随机性 |
| `maxContext` | 8000–12000 token | 需关联同一钢卷批次的轧制计划、加热制度、检测记录等全部关联文档 |
| `maxTokens` | 2000–3000 token | 满足生成完整交叉审查结论的长度需求 |
| `quoteMaxToken` | 500–800 token | 提取单份文档的有效审查片段，避免冗余内容干扰审查逻辑 |
| `AIPROXY_API_ENDPOINT` | 按代理服务实际部署地址填写 | 适配多模型接入与代理转发需求 |
| `AIPROXY_API_TOKEN` | 按代理服务分配的密钥填写 | 完成模型调用的身份验证 |

## 容易做错的三处
- 配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`后，调用返回404 body not found。原因：代理服务与其他模型转发服务共存时，未单独为钢材轧制场景配置模型路由规则，导致请求被错误转发。
- 开启`vision`配置后，无法接入多模态向量模型。原因：未在代理层配置多模态模型的专属转发规则，仅按通用格式转发请求，导致模型不兼容。
- 交叉审查结果未关联同一钢卷的完整文档。原因：`maxContext`取值过小，截断了批次关联的轧制规程、厚度记录等必要文档内容。

## 怎么确认配好了
- 查看模型接入日志，确认`vision`配置已生效，多模态文档的向量索引成功生成。
- 发起单钢卷的交叉审查请求，核对返回结果中关联的文档数量与预设的`maxContext`范围匹配。
- 验证代理配置，确认调用`AIPROXY_API_ENDPOINT`时能正常返回模型响应，无404类报错。
- 调整`temperature`参数后，观察审查结论的严谨性变化，确认参数生效。
