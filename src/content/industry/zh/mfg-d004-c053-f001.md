# 钢铁冶炼与连铸的技术文档交叉审查：HTTP 接口与外部系统

## 这个品类的数据长什么样
数据来源包括铁水与废钢采集数据、L2过程控制数据、化验室成分报告、MES系统数据、能源介质系统数据与设备状态数据。更新节奏为每炉次、实时或每班更新。日常关联文档包含炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单。文档字段包含炉次标识、工艺参数、成分数据、设备状态值，单位匹配工业计量标准。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
钢铁冶炼与连铸的生产流程无随意停机窗口，因此HTTP接口需适配高频率、低延迟的调用需求，避免长时间阻塞生产节奏。多源异构的数据来源要求接口支持对接多个外部系统，需通过统一的鉴权机制管理访问权限。每炉次关联的文档数量固定且有限，接口请求的负载需匹配该场景的文档规模，避免过载。同时，文档交叉审查的结果直接影响炉次质量，接口需具备可靠的失败处理与状态反馈能力，确保异常可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | Bearer {企业专属API密钥} | 符合工业系统API安全规范，避免未授权访问外部生产数据 |
| `variables` | 绑定炉次号、浇次号、成分阈值变量 | 匹配钢铁冶炼文档的核心标识字段，实现精准的文档交叉匹配 |
| `responseData` | 返回审查结果、匹配文档ID、差异字段列表 | 满足调度部门快速定位异常文档与工艺偏差的需求 |
| 单次请求最大文档数 | 前10条 | 适配每炉次关联文档的平均数量，避免请求超时 |
| 请求超时时间 | 30-60秒 | 匹配钢铁冶炼数据的采集与处理周期，不阻塞生产流程 |
| 失败重试次数 | 2次 | 应对短暂的网络波动，不影响生产节奏 |

## 容易做错的三处
- 现象：通过创建文件集合API上传的文档与平台直接上传的文档分段不一致。原因：API上传时未适配钢铁冶炼文档的固定分段规则，导致chunk划分逻辑与平台默认逻辑产生偏差。
- 现象：调用API发起审查请求后，无法快速中断生成过程。原因：未配置`responseData`的实时状态回传逻辑，导致请求阻塞直到完整生成结果。
- 现象：API请求返回状态码400且提示必填字段缺失。原因：未在`variables`中绑定炉次号等核心标识字段，导致系统无法匹配对应文档集。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的接口调试工具发起测试请求，上传单份转炉冶炼记录文档，核对`responseData`返回的文档ID与实际上传的文档一致。
- 模拟短间隔发送多个审查请求，验证接口可以快速响应并支持实时状态反馈。
- 查看接口日志，确认`Authorization`校验通过，无未授权相关报错。
- 对比API上传与平台直接上传的同一份文档，确认分段结果完全一致。
