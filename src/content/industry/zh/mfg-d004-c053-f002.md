# 钢铁冶炼与连铸的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
钢铁联合企业炼铁、炼钢、连铸、质量与调度部门的日常文档包括炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单。数据来源涵盖铁水与废钢数据、L2过程控制、化验室、MES、能源介质系统、设备状态。更新频率为每炉次生成、实时同步、每班汇总归档。文档包含成分数值、工艺参数、设备状态等字段，结构随作业环节动态调整。

## 这些特征在「向量模型与索引」这一环带来什么约束
每炉次实时生成的高频小批量数据，要求索引支持低延迟的增量更新，避免影响作业节奏。多类型结构化文档的混合输入，要求向量模型适配不同字段的语义编码，确保成分、工艺、设备数据的关联一致性。炉次与浇次的强耦合关系，要求索引能够建立跨文档的关联索引，便于交叉审查时快速定位关联作业数据。数据来源分散且更新频繁，要求统一的索引入口与权限控制，防止数据遗漏或重复索引。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配单份炉次文档的平均长度，避免跨字段语义断裂 |
| 重叠长度 | 100–150 字符 | 保留相邻作业环节的关联语义，防止分块切断连铸流程上下文 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关的历史文档，聚焦当前炉次的核心审查数据 |
| 单次搜索上限 | 前10条 | 匹配单炉次交叉审查的文档数量上限，避免冗余信息干扰 |
| 重排 | 开启 | 针对多源异构文档排序，优先匹配审查关注的成分、温度参数 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 512 | 作为单文档分块的默认token基数，适配小字段文档的编码需求 |

## 容易做错的三处
- 现象：开启重排模型后在线召回测试无生效结果。原因：未在索引环节同步绑定重排模型，或重排模型的输入长度与当前文档分块长度不匹配。
- 现象：索引构建过程中出现字段为空的报错。原因：未过滤L2过程控制数据中的临时缓存字段，导致空值无法生成有效向量。
- 现象：召回结果包含大量跨炉次的冗余文档。原因：未限定搜索范围为当前作业炉次的关联数据，相似度阈值设置过低。

## 怎么确认配好了
- 上传单份炉次成分报告与连铸工艺记录，执行在线召回测试，检查返回结果包含对应文档且排序符合预期。
- 查看索引构建日志，确认无字段空值、分块长度超限的报错信息。
- 调整相似度阈值，验证召回结果的数量随阈值变化符合预期逻辑。
- 配置`maxToken`为4096后，合并3份以上关联文档，确认上下文加载无截断情况。
