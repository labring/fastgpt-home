# 钢铁冶炼与连铸的技术文档交叉审查：文档解析与分块

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
钢铁联合企业炼铁、炼钢、连铸、质量与调度部门的日常文档包含炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单。数据来源涵盖铁水与废钢数据、L2过程控制、化验室、MES、能源介质系统、设备状态。更新频率覆盖每炉次、实时、每班，文档包含明确的工艺参数、时间节点、设备状态标识字段，部分文档带有标准化表格结构，字段单位涉及吨、摄氏度等。

## 这些特征在「文档解析与分块」这一环带来什么约束
日常文档类型多样，既有纯文本的冶炼记录，也有标准化表格类的配料单、成分报告，要求解析逻辑适配不同格式的精准字段提取。高频更新的文档覆盖每炉次、实时、每班生成，要求解析流程具备低延迟特性，避免耗时过长影响业务调度。炉次与浇次耦合紧密的业务特性，要求分块时保留同炉次文档的上下文关联，避免拆分破坏工艺逻辑。多来源的数据要求解析过程保留原始文档元数据，支撑后续的文档溯源需求，同时需避免解析错误引发业务风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | `800–1200 字符` | 适配日常文档的单炉次内容长度，避免分块过碎丢失工艺参数的上下文关联 |
| `chunkSplitter` | 按自然段落拆分，超出`chunkSize`时按语义边界截断 | 贴合钢铁冶炼文档的工艺步骤、参数条目结构，保留业务逻辑完整性 |
| `customPdfParse` | 启用 | 针对标准化报表类文档，精准提取表格字段，避免通用解析导致的格式错乱 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120–180 秒` | 适配单炉次多文档合集的解析耗时，防止因超时导致解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 容纳单班次的多炉次文档批量上传，匹配高频更新的数据节奏 |
| `chunkSettingMode` | 手动配置 | 支持针对表格类、文本类文档分别调整分块规则，适配不同业务文档的结构 |

## 容易做错的三处
- 现象：上传XLSX格式的配料单后，解析结果中多行表格的单元格内容被拆分到不同分块。原因：未针对表格类文档配置专用分块规则，默认分块逻辑按字符截断破坏了表格行的完整性。
- 现象：上传PPT格式的连铸工艺记录时，界面返回“the argument ‘windows-1252’ is invalid encoding”报错。原因：未配置自定义编码解析规则，默认编码适配与文档实际编码不匹配。
- 现象：检索返回结果未显示对应分块的来源文档名称与标识。原因：未开启分块时保留原始文档元数据的配置，导致分块丢失来源关联信息。

## 怎么确认配好了
- 上传单份炉次计划文档，检查解析后的分块是否保留了完整的浇次编号、时间节点字段。
- 上传PPT格式的连铸工艺记录，确认解析过程无编码报错，且文本内容完整提取。
- 发起检索测试，确认返回结果附带对应的文档来源信息。
- 批量上传多份同炉次的文档，检查解析耗时未超过设定的`PARSE_FILE_TIMEOUT_SECONDS`阈值。
