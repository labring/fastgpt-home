# 钢铁冶炼与连铸的技术文档交叉审查：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自铁水与废钢数据、L2过程控制、化验室、MES、能源介质系统、设备状态。日常文档包含炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单，各文档含炉次号、浇次号、成分参数、工艺参数、设备状态码等字段，更新频率为每炉次、实时或每班更新，数据以结构化表格与文本记录为主，伴随少量设备告警日志。

## 这些特征在「知识库检索与召回」这一环带来什么约束
每炉次、实时或每班的高频更新要求检索环节支持低延迟召回，避免影响炼钢与连铸的实时调度。多源异构的文档类型（结构化配料单、文本冶炼记录、设备日志）需要兼容混合检索模式，兼顾语义匹配与全文精准匹配。炉次与浇次强耦合的业务逻辑要求检索结果需按炉次或浇次维度聚合，避免跨批次数据干扰当前工艺判断。高温连续流程下的出错后果严重，要求检索需严格过滤不相关内容，保障召回结果与当前工艺场景强匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | 匹配钢铁冶炼工艺参数的精度要求，过滤低相关的非炉次级文档 |
| `limit` | 前8条 | 覆盖单炉次关联的多类文档，避免结果过多超出上下文窗口 |
| `searchMode` | `mixedRecall` | 适配结构化配料单与文本冶炼记录的混合检索需求，兼顾语义与全文匹配 |
| `usingReRank` | 开启 | 过滤召回阶段的冗余结果，聚焦与当前工艺问题强相关的文档 |
| `datasetSearchUsingExtensionQuery` | 开启 | 补充炉次号、浇次号等业务关键词扩展，提升精准召回 |
| `collectionIds` | 按绑定的冶炼与连铸知识库集合填写 | 限定检索范围，避免跨品类数据干扰 |

## 容易做错的三处
- 现象：在线召回测试时返回大量不相关的跨品类文档，无法精准定位当前炉次的工艺记录。原因：未配置`collectionIds`，检索范围覆盖了无关的知识库集合。
- 现象：检索耗时超过10秒，在Tesla V100-SXM2-32GB硬件上表现明显。原因：未调整`limit`参数，召回过多结果导致重排与上下文拼接耗时增加。
- 现象：开启`usingReRank`后，召回结果未按相关性排序，仍保留低相关条目。原因：未在知识库索引阶段同步开启重排模型配置，或重排模型的调用参数未适配冶炼文档的字段特征。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库检索测试界面，输入炉次号关键词，核对检索结果是否仅包含对应炉次的文档。
- 查看检索耗时日志，确认耗时符合业务场景的实时响应要求，可根据硬件配置调整`limit`参数优化。
- 开启`usingReRank`后，对比召回与重排后的结果排序，确认高相关文档排在前列。
- 输入工艺问题关键词，核对系统是否自动补充了炉次、浇次等业务相关的扩展查询词。
