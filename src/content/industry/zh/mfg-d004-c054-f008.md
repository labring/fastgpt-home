# 钣金下料折弯的技术文档交叉审查：文档解析与分块

## 这个品类的数据长什么样
该品类的核心数据来自CAD/CAM软件、订单BOM、板材库存系统、激光切割机与折弯机设备日志、MES生产管理系统。日常文档包含三维件展开图、数控下料程序、折弯工艺卡、套料图、首件记录、工序流转卡。数据更新随订单生成、每日库存变动、生产换型实时调整。文档字段包含板材厚度、折弯系数、孔位尺寸、下料规格、工序编号等，单位多为毫米、平方米、件。

## 这些特征在「文档解析与分块」这一环带来什么约束
不同文档类型的结构差异较大，CAD导出的展开图含矢量标注与尺寸参数，数控程序为纯代码格式，工艺卡则包含表格与文字说明，常规分块逻辑无法适配所有文档类型。多品种小批量的生产模式导致单订单文档结构不统一，无法依赖通用分块规则覆盖全部场景。高频更新的数据要求解析流程具备实时性，延迟解析会影响生产环节的交叉审查效率。关键参数的丢失会直接导致后续装配错误或板材浪费，因此分块必须保留参数间的关联逻辑，不能割裂工艺步骤与尺寸数据。

## 配置怎么定
本文档基于FastGPT v4.17.0版本配置说明。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 钣金文档包含折弯系数、板材尺寸等关键参数，过长分块会丢失关联信息，过短会破坏工艺逻辑 |
| `chunkSplitter` | 按段落+表格拆分 | 钣金文档有大量工艺卡表格和数控程序段落，按固定字符拆分会割裂表格内容 |
| `customPdfParse` | 启用矢量文本提取 | CAD导出的PDF图纸含矢量标注，启用后可保留尺寸字段的原始格式，避免解析乱码 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 大型套料图或数控程序文件解析耗时较长，超时会导致解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配大型套料图文件的上传需求，避免因文件过大无法解析 |
| `chunkSettingMode` | 手动配置 | 不同订单的文档差异较大，手动调整分块参数可适配单订单文档结构 |

## 容易做错的三处
- 现象：上传多列下料清单Excel后，自动分块结果杂乱，无法将每行数据作为独立分段。原因：未关闭默认的字符分块模式，未配置按行拆分表格内容的规则，导致Excel表格被按字符随机拆分。
- 现象：配置板材库存数据库连接后，查询返回空结果，无法关联下料文档的板材参数。原因：未在`customPdfParse`配置中添加库存表的字段映射，解析时未提取板材厚度、库存数量等关联字段，导致检索时无法匹配数据库数据。
- 现象：上传整份折弯工艺卡PDF后，问答准确度较低，无法准确回答折弯顺序或补偿系数相关问题。原因：分块时未保留工艺步骤与参数的关联信息，将完整工艺逻辑拆分为零散片段，导致检索时无法匹配完整的工艺链条。

## 怎么确认配好了
- 上传一份典型的折弯工艺卡PDF，查看解析后的分块结果，确认每张工艺表格与对应文字说明作为关联分块。
- 上传一份多列的下料清单Excel，验证分块是否按每行数据生成独立分段，无零散字符拆分的情况。
- 上传一份超过500MB的套料图文件，确认解析过程未触发超时错误，文件成功导入知识库。
- 关联板材库存数据库后，提交包含指定板材厚度的查询，验证返回结果包含正确的库存参数与关联下料信息。
