# 铸造（砂型、精密、压铸）的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来自ERP物料主数据、熔炼炉、光谱仪、MES炉次记录、模具管理系统及客户图纸技术条件。更新节奏为每炉次、每批或每日。日常文档包含铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告与不合格品评审单。数据字段包含合金配料参数、炉温数值、浇注温度、模次编号、缺陷类型等，单位涉及摄氏度、千克、毫米等。

## 这些特征在「向量模型与索引」这一环带来什么约束
每炉次的高频更新要求索引支持增量同步，避免全量重建占用计算资源。多源异构数据的字段差异，要求向量模型需适配结构化数值与非结构化文本混合输入。文档中包含大量工艺参数与缺陷关联记录，需确保索引能精准匹配参数阈值与缺陷类型的语义关联。批量数据的更新频率要求索引的批量处理能力适配每日、每批的更新量，防止索引延迟影响交叉审查效率。同时，铸件质量追溯需关联炉次、模次与检验记录，索引需保留多文档间的关联关系，避免信息割裂。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配铸造文档中工艺卡、炉次记录的单块内容长度，避免块内语义割裂 |
| 重叠长度 | 50–80 字符 | 保留跨块的工艺参数关联信息，防止参数拆分后无法匹配 |
| 相似度阈值 | 0.75–0.85 | 匹配合金配料、炉温等数值关联的语义相似度，过滤无效匹配结果 |
| 单次搜索上限 | 前 10 条 | 覆盖同炉次、同模次的关联文档，满足交叉审查的多文档核对需求 |
| maxToken | 8192 | 适配长文档的向量编码需求，覆盖完整的工艺卡与检验报告内容 |
| defaultToken | 1024 | 适配短文本的向量编码基础长度，满足配料单等短文档的需求 |
| 重排 | 开启 | 优化缺陷类型与工艺参数的匹配排序，提升交叉审查的精准度 |

## 容易做错的三处
- 调用向量模型时返回401错误。原因是未正确配置向量模型的API密钥，或密钥权限未开放对应向量服务。
- 知识库索引合并后仍存在重复文档。原因是未开启文档去重配置，或去重阈值设置过高，无法识别内容相似的炉次记录与检验单。
- Ollama部署的向量模型在FastGPT中调用被拒绝，curl测试正常。原因是FastGPT的向量模型调用超时设置过短，或代理配置未正确映射Ollama的本地服务端口。

## 怎么确认配好了
- 上传单份炉次记录文档，检查向量编码完成状态，确认无超时或编码失败日志。
- 输入合金配料比例查询语句，核对返回结果的相似度分值是否符合预设阈值区间。
- 导入多份同炉次的关联文档，检查索引合并后是否保留文档间的关联关系。
- 切换至不同的向量模型，验证调用是否正常，确认API密钥与配置参数无误。
