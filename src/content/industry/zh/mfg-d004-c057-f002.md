# 锻造与模锻的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图。日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单与超声检测报告。数据按每件锻件、每批物料或每炉次更新，文档字段包含锻造比、纤维方向、炉批号、加热温度区间、压力参数等，部分文档附带数值型检测数据与标准化工艺步骤。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据按炉次、批次高频更新，需支持增量索引配置，避免全量重建带来的长时间阻塞。多类文档结构差异明显，长文本工艺规程与短文本检测报告需适配差异化分块规则。文档包含锻造比、纤维方向等工业专业术语，向量模型需适配该领域语义特征。单条数据体量偏小但总数据量随生产批次增长，需合理设置索引分片参数以平衡查询效率与存储占用。同时，交叉审查需关联炉批号与锻件批次，索引需支持多维度字段绑定，确保检索结果可匹配对应生产批次。

## 配置怎么定
本页面适配FastGPT v4.17.0版本的向量模型与索引配置。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配锻造工艺规程的长文本结构，避免关键工艺步骤的语义断裂 |
| 重叠长度 | 50–100 字符 | 覆盖跨分块的工艺步骤关联，满足交叉审查的上下文连贯性要求 |
| `defaultToken` | 2000–3000 token | 适配单批次文档的总长度，平衡向量生成质量与计算开销 |
| `maxToken` | 4000–6000 token | 满足长文档的向量生成需求，避免截断重要参数与流程说明 |
| 单次搜索上限 | 前10条 | 匹配单炉次相关文档的常规数量，避免冗余结果干扰交叉审查 |
| 相似度阈值 | 按实测标定 | 适配工业术语的语义相似度判断，结合实际审查场景调整 |

## 容易做错的三处
- 切换知识库索引时返回60秒超时错误，或界面显示索引重建未完成。原因是未启用增量索引配置，全量重建时未限制单批次处理数据量，导致索引构建任务阻塞。
- 知识库仅包含少量文档，但长期处于训练或重建状态，超过24小时未完成。原因是分块长度设置过小，生成的分块数量远超系统处理上限，导致任务堆积。
- 批量添加索引时请求参数配置错误，或错误为每个文档单独创建索引。原因是未结合锻造生产的批次关联需求，统一索引更利于跨文档交叉审查，错误配置会破坏批次关联逻辑或导致索引关联失效。

## 怎么确认配好了
- 执行单炉次文档的批量索引入库，查看系统任务日志，确认无超时报错。
- 检索包含锻造比、纤维方向的专业术语，查看返回结果的分块语义连贯性是否符合工艺逻辑。
- 切换索引后，等待系统加载完成，验证检索响应时长符合生产节奏要求。
- 检查索引配置，确认采用统一集合索引，且已绑定炉批号、锻件ID等专属业务字段。
