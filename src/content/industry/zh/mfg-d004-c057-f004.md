# 锻造与模锻的技术文档交叉审查：工作流编排

## 这个品类的数据长什么样
锻造与模锻的日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告。数据来源包括原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪、客户锻件图。数据更新频率为每件锻件、每批物料或每炉次生产周期。文档字段包含锻造比、金属纤维方向、炉批号、锻件批次号、加热温度区间、检测缺陷类型等，单位涉及摄氏度、吨、毫米等。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的分散采集要求工作流配置对接不同系统的节点，避免数据遗漏。高频更新的生产数据要求工作流轻量化，减少冗余步骤以适配单炉次的快速审查需求。特定字段的校验需求要求工作流针对锻造比、纤维方向等核心参数设置固定校验逻辑，不能通用化处理。严重的出错后果要求工作流配置完整的失败处理与追溯机制，确保异常可被及时发现与定位。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 开启自定义变量，设置是否跳过知识库检索的开关、文件流处理阈值 | 适配用户选择是否跳过检索的需求，同时限定文件流处理的最大体积 |
| `nodeId` | 绑定异常告警与日志留存节点，关联锻造比校验、炉批号匹配失败的节点ID | 确保核心校验失败时触发告警与数据追溯，符合出错后果严重的业务要求 |
| 工作流节点顺序 | 按数据源采集→字段校验→交叉审查→结果输出的顺序编排 | 匹配数据更新的实时性要求，先获取最新生产数据再执行校验 |
| 超时时间 | 300-600秒 | 适配超声检测报告等较大文件的传输与处理时长 |
| 单批次处理量 | 不超过20条炉次数据 | 匹配每炉次的生产更新频率，避免工作流过载 |
| 上下文长度 | 按实测标定，8000-12000字符 | 适配锻造工艺规程与检测报告的内容长度 |

## 容易做错的三处
- 现象：工作流中处理超声检测报告的HTTP请求节点返回图片文件流后，节点状态显示「数据格式不兼容」，后续审查节点无法获取文件内容。原因：未针对锻造超声检测报告的图片流配置二进制数据接收逻辑，仅配置了文本数据解析规则。
- 现象：工作流未触发用户选择是否跳过知识库检索的交互弹窗，用户无法自定义审查逻辑。原因：未正确绑定`variables`配置项，未将检索开关关联到可编辑的用户输入变量。
- 现象：炉批号与锻件批次不匹配的校验失败后，工作流直接终止未触发告警。原因：未将该校验节点的`nodeId`绑定到异常告警节点，未设置强制校验规则。

## 怎么确认配好了
- 进入FastGPT v4.17.0的工作流编辑页面，检查`variables`配置项是否包含用户选择跳过知识库检索的开关变量。
- 上传一份模拟的锻造下料卡与超声检测报告，触发工作流执行，查看节点日志是否正确采集了加热炉温度、炉批号等核心字段。
- 测试HTTP请求节点，传入模拟的图片文件流，查看节点是否正常接收并传递数据至后续环节。
- 手动修改炉批号为与锻件批次不匹配的数值，触发校验失败，查看是否触发绑定的`nodeId`异常告警。
