# 锻造与模锻的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告。数据来源包括原材料质保书、加热炉系统、压力机采集数据、MES、无损检测仪、客户锻件图。数据更新频率为每件或每批、每炉次，文档字段包含锻造比、纤维方向、炉批号、锻件重量、检测缺陷类型等，对应单位涵盖吨、摄氏度、毫米等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源导致文档格式、字段命名存在差异，要求模型接入配置需支持多类型文档的解析，包括带图像的超声检测报告。高频更新的业务节奏要求配置需适配单批次文档的有限长度，避免上下文溢出。需严格核对炉批号与锻件批次的对应关系，要求模型输出具备高准确性，同时需支持多模态输入以处理图像类检测报告。此外，不同文档的字段差异要求配置需精准匹配业务所需的核心信息提取维度。本文基于FastGPT v4.17.0版本编写。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启 | 该品类需审查超声检测报告等带图像的文档，需支持视觉输入能力 |
| `maxContext` | 8000–12000 token | 适配单批次锻件相关文档的总长度，避免超出模型上下文限制 |
| `maxTokens` | 2000–3000 token | 控制单轮审查输出的长度，保证覆盖所有核心审查要点且无冗余 |
| `quoteMaxToken` | 1500 token | 仅引用文档中的核心片段，减少无关内容对模型审查的干扰 |
| `temperature` | 0.1–0.3 | 降低模型幻觉概率，保证批次核对、缺陷识别等业务场景的结果准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 适配本地或云端部署的各类模型服务 |

## 容易做错的三处
- 现象：视觉模型接入后无法解析超声检测报告图像，界面提示不支持视觉输入。原因：未正确开启`vision`配置项，或未选择具备视觉能力的模型。
- 现象：单批次审查任务超时，返回504状态码。原因：`maxContext`设置超出模型服务的响应阈值，未结合该品类高频更新的文档长度调整参数。
- 现象：无法准确统计单批次审查的tokens消耗，结果与实际调用量偏差较大。原因：未设置`quoteMaxToken`限制引用片段长度，导致模型token计算逻辑出现偏差。

## 怎么确认配好了
- 上传一份包含超声检测报告图像的测试文档包，触发审查流程，查看是否能正确提取图像中的缺陷标注信息，验证`vision`配置生效。
- 查看模型调用日志，核对实际使用的tokens数量处于`maxContext`与`maxTokens`的设置范围内，验证上下文与输出长度限制生效。
- 手动输入一组炉批号与锻件批次不匹配的测试数据，查看审查结果是否能准确识别不匹配项，验证`temperature`参数的约束效果。
- 测试本地部署的模型服务连接，确认`AIPROXY_API_ENDPOINT`配置的地址可正常访问，无身份验证报错。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
