# 锻造与模锻的技术文档交叉审查：部署与升级

## 这个品类的数据长什么样
锻造与模锻的日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告等。数据来源包括原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪、客户锻件图。数据更新频率为每件锻件或每批物料、每炉次生产周期。文档字段包含炉批号、锻造比、模具使用次数、检测结果等，其中锻造比以数值加比例符号为单位，炉批号为12-18位的字符序列。

## 这些特征在「部署与升级」这一环带来什么约束
高频次、多批次的数据更新要求部署时配置适配批量检索的连接池参数，避免并发访问耗尽数据库资源。多源异构的数据格式需要统一预处理规则，确保不同系统导出的文档字段映射一致。关键业务字段（如炉批号、锻造比）的精准匹配需求，要求检索配置优先关联核心字段。同时，锻件出错后果严重，部署时需配置完善的失败重试与告警机制，保障审查流程不中断。FastGPT v4.17.0的部署模板需适配厂内私有网络环境，避免公网访问带来的安全风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 100–200 并发连接 | 适配锻造厂多批次并行的文档检索需求，避免数据库连接耗尽 |
| `MONGODB_URI` | 本地私有部署地址，绑定100 GB以上专用存储卷 | 存储批量生成的锻件文档元数据，保障多炉次数据的持久化与访问速度 |
| `REDIS_URL` | 本地Redis实例，配置10分钟过期策略 | 缓存高频检索的加热炉记录、工艺规程数据，降低数据库访问压力 |
| `STORAGE_S3_ENDPOINT` | 厂内私有对象存储端点地址 | 存储超声检测报告、热处理委托单等大体积文档，统一管理非结构化数据 |
| `FE_DOMAIN` | 厂内私有域名或内网IP | 限定前端访问范围，保障涉密锻件文档的访问安全 |

## 容易做错的三处
- 现象：Docker镜像部署后，向量检索结果得分完全一致，无法区分不同锻件文档。原因：镜像打包时未正确挂载本地向量库配置文件，导致所有检索调用默认使用同一预训练模型的固定嵌入向量。
- 现象：首次调用检索正常，后续带多轮上下文的请求触发报错。原因：未配置`REDIS_URL`的会话缓存机制，多轮对话的上下文数据溢出导致服务中断。
- 现象：混合检索响应时长超过15秒，无法满足现场审查需求。原因：未限制单次检索的文档条数，同时加载了全量历史锻件文档进行比对。

## 怎么确认配好了
- 登录FastGPT后台，查看`MONGODB_URI`的连接状态面板，确认显示正常连接。
- 上传一份典型的锻造工艺规程文档，发起关键词检索，确认返回结果的得分存在差异且匹配炉批号、锻造比等核心字段。
- 部署Docker镜像并挂载对应配置卷，发起3轮以上带上下文的检索请求，确认无报错且单轮响应时长稳定在10秒以内。
- 查看`REDIS_URL`的监控指标，确认缓存命中次数随检索频次提升，无明显缓存未命中堆积。
