# 预制混凝土构件的技术文档交叉审查：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据来自BIM深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检测报告及产品二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据更新节奏随单件构件、每批物料、每窑养护批次变动，字段包含构件编号、钢筋规格与直径、预埋套筒位置坐标、混凝土强度等级、养护时长、脱模强度值，单位涵盖毫米、兆帕、天等，且每件构件的文档需与现场吊装点位一一对应。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据更新节奏随单件、批次变动，且多源分散，要求多轮对话需精准绑定当前审查的构件ID，避免调用过期或非目标构件的文档。不同类型的日常文档字段差异显著，提示词需针对深化图、下料单、养护记录等分别设定校验规则，例如核对钢筋下料单的规格与深化图的匹配度，核查养护记录的时长与强度是否达标。单件构件需与现场吊装点位一一对应，对话过程中需逐步调取关联的模台、试验室数据，防止上下文过载导致信息混乱。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 字符 | 适配多份构件关联文档的拼接需求，避免上下文溢出 |
| `messages` 上下文拼接规则 | 仅保留当前构件审查的3轮对话历史 | 过滤无关历史，聚焦当前审查任务 |
| `variables` 变量绑定方式 | 绑定当前构件ID与批次号 | 精准调用对应构件的深化图、下料单等专属数据 |
| `chatId` 绑定规则 | 与当前构件ID一一对应 | 确保对话上下文与目标构件绑定，避免跨构件混淆 |
| 单次搜索上限 | 前6条检索结果 | 匹配该品类单批次文档的平均数量，避免冗余信息干扰 |
| 最大响应token数 | 2000–3000 token | 覆盖完整的审查结论与校验细节，防止响应截断 |

## 容易做错的三处
- 现象：调试预览界面对话出现报错，提示知识库关联字段为空。原因：未通过`variables`绑定当前构件的专属ID，导致系统无法匹配对应批次的深化图或下料单数据。
- 现象：部分问题的最大响应token自动变为200，回复内容截断。原因：未固定配置最大响应token的取值区间，系统触发了默认的短响应限制，未适配预制混凝土构件审查所需的长文本输出需求。
- 现象：对话过程中无法将新的模台检测数据同步至知识库。原因：未配置对话过程中的数据写入触发规则，仅支持静态知识库导入，未实现实时数据追加。

## 怎么确认配好了
- 发起针对指定构件深化图的校验提问，确认系统能调取对应批次的钢筋下料单等关联数据。
- 发起长文本审查提问，确认响应token数符合预设的配置区间，未自动触发短响应限制。
- 提交新的养护记录数据至对话界面，确认数据可被同步至知识库的对应构件条目下。
- 切换至不同构件ID的审查任务，确认系统不会混淆不同构件的文档内容。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
