# 预制混凝土构件的技术文档交叉审查：模型接入与配置

## 这个品类的数据长什么样
预制混凝土构件的数据来自BIM深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检测报告及产品二维码追溯系统。日常生成的文档包括构件深化图、钢筋下料单、模具检验表、浇筑振捣记录、养护日志、脱模与出厂检验报告。数据更新节奏为单件构件、每批物料、每窑养护周期对应生成，字段包含构件编号、钢筋直径、设计强度、养护时长等，单位多为毫米、兆帕、小时。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的文档格式要求模型接入配置需兼容矢量图纸文本、表格台账、日志记录等多种数据类型。不同于按车交付的流态建材，预制混凝土构件的单件属性要求每批次的校验需覆盖单构件的全部关联参数。高频次的单件/批/窑级更新，要求配置的上下文窗口可承载单批次构件的全量关联文档。构件出错会导致现场安装偏差或报废，因此模型输出需具备高准确性，同时需限制生成的随机性。此外，跨系统的数据溯源需求，要求配置中需保留原始文档引用的关联路径。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单批次预制构件的关联文档总长度，避免截断核心校验信息 |
| `maxTokens` | 2000–3000 token | 控制单轮审查结果的输出长度，确保覆盖构件尺寸、钢筋配置等关键校验项 |
| `quoteMaxToken` | 1500 字符 | 保留原始文档的完整引用片段，便于追溯钢筋下料单、养护记录等校验依据 |
| `temperature` | 0.1–0.3 | 降低生成随机性，提升技术文档校验的准确性，避免出现不符合行业规范的输出 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写实际代理地址 | 适配外部模型或本地部署的模型调用路径，确保请求可正常转发 |
| `AIPROXY_API_TOKEN` | 从代理服务获取的有效令牌 | 完成身份验证，允许调用配置的大模型接口 |

## 容易做错的三处
- 调用本地ollama部署的模型时返回空内容。原因是未正确配置`AIPROXY_API_ENDPOINT`指向ollama的代理转发地址，或令牌未匹配ollama的本地服务权限。
- 模型上下文被意外截断导致校验不完整。原因是`maxContext`取值过小，未覆盖单批次构件的全部关联文档长度。
- 外部模型调用失败提示身份验证错误。原因是`AIPROXY_API_TOKEN`填写错误，或未在代理服务中绑定对应的模型权限。

## 怎么确认配好了
- 进入FastGPT的模型管理页面，查看已配置的外部模型列表，确认目标模型已添加并显示正常状态。
- 上传单份预制构件的钢筋下料单与深化图，触发一次测试审查，查看返回结果是否包含明确的校验结论与引用来源。
- 查看代理服务的日志，确认无401身份验证错误或超时报错，接口请求的响应时长符合预期。
- 在工作流中配置模型节点，选择已接入的模型，测试调用后返回非空的有效内容，无格式异常。
