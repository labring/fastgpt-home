# 预制混凝土构件的技术文档交叉审查：部署与升级

## 这个品类的数据长什么样
该品类数据来自BIM深化设计、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检验报告及二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验表、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据更新节奏为单件构件、每批物料、每窑养护周期同步更新，字段包含构件编号、钢筋直径（mm）、混凝土强度等级（MPa）、养护温度（℃）、批次号等，格式涵盖结构化表格与非结构化图纸。

## 这些特征在「部署与升级」这一环带来什么约束
该品类单件、每批、每窑级的高频数据更新，要求部署时保障数据库的持久化存储与高并发读写能力。多源异构的数据来源与多样的文档格式，要求配置兼容结构化表格与非结构化图纸的导入、存储能力。业务出错会导致构件报废或工期延误的特性，要求升级过程中不丢失历史数据，同时需保障权限管控的安全性。多账号协作访问的需求，要求部署配置支持统一的访问入口与权限共享机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://fastgpt:SecurePass123@mongodb:27017/pc_doc_review?authSource=admin` | 存储构件深化图、检验记录等结构化与非结构化数据，适配高频读写需求 |
| `REDIS_URL` | `redis://:CachePass456@redis:6379/1` | 缓存高频查询的构件编号映射、批次信息，降低数据库访问延迟 |
| `STORAGE_S3_ENDPOINT` | `http://internal-storage:9000` | 存储大体积的深化设计图纸、养护记录文件，兼容多格式上传 |
| `FE_DOMAIN` | `https://pc-component-review.your-org.com` | 绑定专属部署域名，支持多账号协作访问同一知识库 |
| `ROOT_KEY` | `按实测生成的32位随机密钥` | 配置系统最高权限凭证，保障部署升级时的操作权限安全 |
| `DB_MAX_LINK` | `200 个` | 限制数据库连接数，避免多批次构件数据导入时的连接溢出 |

## 容易做错的三处
- 现象：执行`docker compose down`后重启服务，发现构件数据、知识库集合丢失。原因：未挂载数据库持久化卷，升级时直接覆盖了本地容器内的数据库文件。
- 现象：调用文档审查接口返回`401 Unauthorized`，无法访问指定知识库集合。原因：未正确配置`ROOT_KEY`或`FILE_TOKEN_KEY`，权限校验失败。
- 现象：批量导入钢筋下料单时，仅部分文档被索引，剩余文档无搜索结果。原因：未设置合理的`DB_MAX_LINK`参数，连接数不足导致部分数据导入中断。

## 怎么确认配好了
- 执行`docker compose up -d`后，查看数据库与缓存容器日志，确认无连接超时或认证失败报错。
- 上传一份预制构件深化图，在知识库中搜索构件编号，确认能检索到对应文档。
- 登录系统后台，验证多账号可同时访问同一知识库并编辑文档集合。
- 调用系统版本接口，确认当前运行版本为FastGPT v4.17.0。
