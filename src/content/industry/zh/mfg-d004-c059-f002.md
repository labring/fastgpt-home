# 预拌混凝土生产的技术文档交叉审查：向量模型与索引

## 这个品类的数据长什么样
本品类的数据主体来自商品混凝土搅拌站、工程项目试验室及质量调度部门。日常文档包含配合比通知单、开盘鉴定、生产运输单、原材料检验记录、试块测试记录、强度报告等。数据来源覆盖工程订单、砂石水泥外加剂检验、骨料含水率测定、搅拌站控制系统、试验室检测系统。更新频率按单批次原料、每车生产任务、每日检测结果滚动更新。文档字段包含批次编号、检测数值、时间戳、操作标识等，单位随文档类型匹配，如质量类用千克、强度类用兆帕。

## 这些特征在「向量模型与索引」这一环带来什么约束
高频率的更新要求索引支持增量生成，避免全量重建占用过多资源；多类型文档的混合输入需要向量模型兼容结构化检测数据与非结构化文本内容；不同文档的长度差异大，从简短的配合比通知单到长达数页的强度报告，要求分块策略具备灵活性；关键参数如骨料含水率、坍落度的审查精度直接关联生产质量，要求索引召回的关联文档具备高相关性，不能遗漏核心逻辑；多来源的数据格式差异，需要索引适配不同系统导出的文档结构。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，涉及`defaultToken`与`maxToken`两个核心参数，具体配置项及建议如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配配合比通知单、试块强度报告等不同长度的文档，避免分块破坏关键参数的关联逻辑 |
| 重叠长度 | 50–100 字符 | 衔接相邻分块的关联信息，比如骨料含水率修正前后的生产逻辑 |
| 相似度阈值 | 按实测标定 | 匹配预拌混凝土生产中对坍落度、强度等关键指标的精度审查要求 |
| 单次搜索上限 | 前 10 条 | 控制返回结果数量，避免冗余信息干扰技术交叉审查的判断 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 500 | 适配单份文档的基础分块token消耗，避免超出模型输入限制 |

## 容易做错的三处
- 现象：调用知识库索引生成接口时返回模型不匹配报错，文案包含`undefined model must match "^(text`。原因：未在配置中选择平台支持的嵌入模型，或输入了未定义的模型名称。
- 现象：更换嵌入模型后，已导入的知识库无法直接复用现有索引，需重新生成向量数据。原因：不同嵌入模型生成的向量空间存在差异，现有索引无法匹配新模型的向量特征。
- 现象：知识库搜索返回结果的排序与预期相似度不符。原因：未开启重排配置，或未正确设置排序逻辑，导致仅按原始召回顺序返回结果。

## 怎么确认配好了
- 查看嵌入模型配置项，确认选择的模型与平台支持的列表一致，无未定义的模型名称。
- 上传一份配合比通知单文档，执行索引生成测试，检查分块长度是否符合预设值，向量生成过程无报错。
- 发起一次针对骨料含水率修正逻辑的检索请求，核对返回结果的数量与单次搜索上限的设置一致。
- 检查`defaultToken`的配置是否符合当前导入文档的平均token消耗需求，避免出现分块截断或索引失败。
