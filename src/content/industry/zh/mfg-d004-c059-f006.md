# 预拌混凝土生产的技术文档交叉审查：引用来源与溯源

## 这个品类的数据长什么样
该品类数据来源包含工程订单、砂石水泥外加剂检验记录、骨料含水率测定数据、搅拌站控制系统日志、试验室试验报告。日常生成配合比通知单、开盘鉴定、生产运输单、原材料检验台账、试块抗压记录、强度验证报告等文档。数据更新节奏为每车生产批次、每批原料进场、每日试验室检测周期。文档字段包含配合比参数、原料检验指标、生产计量数值、试块强度结果，部分字段对应行业通用物理单位，如坍落度以毫米计、抗压强度以兆帕计。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类按车、批、日更新的数据特征，要求引用溯源需绑定唯一批次标识，避免跨生产批次的文档混淆。日常覆盖多类型技术文档的场景，需精准匹配文档与对应生产环节的关联关系，防止交叉引用错位。原料检验数据与生产计量数据同源，需确保引用的检验结果未超出对应原料批次的有效周期。试块强度报告需关联对应浇筑批次，溯源链条需覆盖从原料进场到成品验证的全环节，且因产品性能需龄期验证，需保留长期可追溯的节点。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的规则制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 配合比通知单、原材料检验报告等单份技术文档的平均token数区间，适配多文档交叉引用的长度需求 |
| `responseData` | 仅返回核心答案与溯源文档标识 | 避免输出冗余的工具调用过程日志，贴合工程技术人员对简洁结果的使用需求 |
| `detail` | 开启 | 需展示溯源文档的关联生产批次、原料检验指标等细节，满足质量追溯的详细要求 |
| 单次召回文档上限 | 前6条 | 预拌混凝土生产的核心技术文档类型约5种，召回6条可覆盖原料、生产、试块检验的全环节关联数据 |
| 溯源绑定规则 | 按生产批次绑定 | 该品类数据按车、批、日更新，生产批次标识可精准关联原料进场、生产计量与试块记录的全链条数据 |
| 溯源数据保留周期 | 180天 | 试块强度报告需至少28天龄期验证，需保留对应批次的溯源数据至验证完成后覆盖全周期 |

## 容易做错的三处
- 现象：工作流调用后，回答中出现知识库搜索的input与response过程字段。原因：未配置仅返回核心内容的输出规则，导致工具调用的中间步骤被同步至最终回答。
- 现象：引用溯源时出现部分文档字段为空的情况。原因：未按生产批次绑定溯源标识，导致跨生产批次的文档关联错位，无法匹配到对应批次的有效数据。
- 现象：召回的溯源文档数量过多或过少，无法覆盖全环节需求。原因：未根据该品类的核心技术文档类型调整单次召回上限，导致召回数据冗余或遗漏关键关联文档。

## 怎么确认配好了
- 发起一次针对配合比调整的查询，核对回答中是否仅包含核心结论与溯源文档标识，无冗余的工具调用过程内容。
- 查看溯源绑定的批次标识，确认其与当前生产批次的编号一致，无跨批次的关联数据。
- 核对召回的溯源文档类型，确认覆盖原料检验、生产计量、试块记录等核心环节，数量符合当前查询的需求。
- 检查`quoteMaxToken`的配置，确认单份溯源文档的引用内容未被截断，可完整展示关键参数。
