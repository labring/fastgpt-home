# 预拌混凝土生产的技术文档交叉审查：部署与升级

## 这个品类的数据长什么样
预拌混凝土生产的技术文档包括配合比通知单、开盘鉴定、生产运输单、原材料检验、试块记录、强度报告。数据来源为工程订单、砂石水泥外加剂检验、含水率测定、搅拌站控制系统、试验室。更新频率为每车生产数据、每批原料检验结果、每日汇总报表。文档字段包含砂石水泥用量（kg/m³）、骨料含水率、坍落度（mm）、试块龄期（天）、强度等级（MPa），不同文档的核心字段差异显著。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据更新频繁且实时性要求高，每车生产数据、每批原料检验结果都会触发文档更新，部署时需配置足够的并发连接支撑读写请求。文档字段差异大且包含专业工程参数，部署时需适配不同文档的解析规则，升级时需避免破坏现有字段映射逻辑。敏感质量数据需保障存储安全，不宜使用公共云存储，同时需配置可靠的备份机制，防止数据丢失影响工程质量。部署环境需与生产控制系统、试验室设备网络隔离，避免干扰生产流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150 个连接` | 预拌混凝土生产的数据更新频繁，每车每批都产生新数据，需要足够的数据库连接池支撑并发读写 |
| `MONGODB_URI` | `mongodb://192.168.1.100:27017/concrete_docs` | 该品类的文档和生产数据需与业务系统隔离，避免干扰正常生产流程 |
| `REDIS_URL` | `redis://:securepass@192.168.1.101:6379/0` | 需要缓存高频读取的配合比、含水率数据，降低数据库压力，适配实时更新的业务节奏 |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.102:9000` | 该品类的试验报告、试块记录等文件体积较大，本地存储可保障数据安全并降低传输成本 |
| `FILE_TOKEN_KEY` | 随机生成的32位字符串 | 对上传的生产文档生成安全访问令牌，防止未授权访问敏感质量数据 |

## 容易做错的三处
- 现象：本地部署打包后启动报错，提示数据库连接超时。原因：未按品类数据的并发需求调整`DB_MAX_LINK`参数，默认连接数不足以支撑每车实时产生的文档读写请求。
- 现象：打包成功运行后，修改的配合比文档解析规则未生效。原因：未在部署时同步更新前端静态资源缓存，或未正确配置`FE_DOMAIN`指向本地部署地址，导致前端加载旧版代码。
- 现象：批量上传原材料检验报告时，部分文档未被索引。原因：未正确配置`STORAGE_S3_ENDPOINT`，导致存储端点无法访问，文件无法被系统读取解析。

## 怎么确认配好了
- 登录FastGPT v4.17.0后台，查看数据库连接面板，确认`MONGODB_URI`和`REDIS_URL`的连接状态为正常。
- 上传一份近期的配合比通知单，检查系统是否能正确提取砂石用量、含水率、坍落度等字段，验证文档解析规则生效。
- 调用系统批量导入接口，上传10份试块记录，确认导入过程无报错，检查`DB_MAX_LINK`的连接数未被耗尽。
- 访问`FE_DOMAIN`配置的地址，确认前端页面加载的是最新修改的配置界面，无缓存残留。
