# SMT贴片与电子组装的投标文稿与报价编制：HTTP 接口与外部系统

## 这个品类的数据长什么样
SMT贴片与电子组装的业务数据来源包括客户提供的BOM、Gerber文件、坐标文件，以及MES系统、贴片机、SPI/AOI检测设备、回流焊炉温记录等生产系统数据。日常文档涵盖BOM清单、换线表、钢网与炉温记录、首件确认报告、SPI/AOI检测报告、维修记录与追溯标签。数据按每工单、每次换线实时更新，核心字段包含料号、位号、元件批次、贴装坐标、炉温参数等，需匹配客户指定的格式与单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的业务数据来源分散且更新实时，要求接口调用需适配多系统的数据格式与鉴权规则。不同工单的BOM、检测数据结构差异较大，需接口支持动态请求体与字段提取。实时性要求意味着接口超时需控制在合理区间，避免阻塞投标报价的编制流程。同时，数据错误会引发批量生产失效，接口调用需具备重试与错误捕获机制，保障数据获取的稳定性与准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工具调用逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 鉴权配置 | 携带Bearer格式的API密钥 | 符合外部系统的标准鉴权要求，适配OneAPI接入场景 |
| 请求变量 | 传入工单ID、元件批次号 | 绑定实时工单数据，支撑投标报价的动态计算 |
| 响应数据提取 | 仅保留料号校验结果、报价明细字段 | 过滤冗余数据，适配投标文稿生成的字段需求 |
| 重试次数 | 3次 | 应对网络波动导致的接口调用失败，保障数据获取稳定性 |
| 请求超时时间 | 30 秒 | 匹配SMT工单数据的实时更新节奏，避免阻塞流程 |

## 容易做错的三处
- 调用接口返回401状态码，Postman调用正常。原因是FastGPT配置的鉴权参数与外部系统要求的格式不匹配，未正确携带`Authorization`头的Bearer标识。
- 无法从接口获取到元件批次数据，返回字段为空。原因是请求的`variables`未传入正确的工单ID参数，导致外部系统无法匹配对应数据。
- 配置自定义模型接口后无法调用，工具调用参数未生效。原因是未在FastGPT的工具配置中正确关联模型，或未开启对应调用权限。

## 怎么确认配好了
- 在FastGPT的调试面板中发起测试调用，查看返回的`responseData`是否包含预期的料号、报价明细字段。
- 模拟工单触发接口调用，检查鉴权参数是否正确生成，确认无401或403报错。
- 调整请求变量中的工单ID参数，验证外部系统是否能返回对应工单的元件批次数据。
- 查看接口调用日志，确认重试策略在网络波动时正常触发，无连续失败情况。
