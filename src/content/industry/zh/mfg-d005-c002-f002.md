# SMT贴片与电子组装的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
SMT贴片与电子组装的业务数据来自客户提供的BOM、Gerber文件、元件坐标，以及MES系统、贴片机、SPI/AOI检测设备、回流焊炉温记录等。日常文档包含BOM与坐标文件、换线表、钢网参数、炉温曲线、首件确认报告、SPI/AOI缺陷报告、维修记录与追溯标签。数据更新频率为每工单、每次换线实时同步，部分批次元件记录随来料批次更新。文档字段包含元件料号、位号、贴装坐标、炉温参数、缺陷类型等，部分工程文件为二进制格式，包含加密的贴装参数。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的高频实时更新、多类型混合文档、精准字段匹配需求，对向量模型与索引环节带来多重约束。实时同步的工单与换线数据要求索引支持增量更新，避免全量重建消耗过多资源。混合格式的工程文件、结构化参数表与缺陷报告，要求索引适配多源数据的文本提取与结构化解析。料号、位号等核心业务字段的精准匹配需求，要求向量模型侧重实体关联与语义一致性，降低模糊匹配误差。跨工单的投标数据整合需求，要求索引支持关联检索不同批次的业务记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配SMT工单文档的平均长度，避免分块过碎或过长影响向量提取精度 |
| 重叠长度 | 100–150 字符 | 保留跨分块的料号、位号等核心业务字段的上下文关联，避免实体断裂 |
| `defaultToken` | 1024 | 匹配FastGPT v4.17.0的默认嵌入模型的token上限，确保文本完整嵌入 |
| `maxToken` | 2048 | 容纳完整的BOM条目或炉温记录的核心信息，避免关键参数被截断 |
| 相似度阈值 | 0.75–0.85 | 区分业务相关与无关的检索结果，适配投标报价的精准匹配需求 |
| 单次搜索上限 | 前10条 | 筛选核心历史工单数据，避免冗余结果干扰报价编制逻辑 |

## 容易做错的三处
- 现象：知识库索引完成后，搜索投标相关的BOM数据时返回空结果。原因：未针对料号、位号等核心字段优化分块策略，导致关键实体被拆分在不同分块中，向量嵌入丢失关联信息。
- 现象：索引过程出现超时报错，状态码显示504。原因：未启用增量索引配置，全量索引数十万条SMT工单数据时超出系统响应阈值。
- 现象：检索结果中混入大量非相关的炉温记录。原因：相似度阈值设置过低，将语义相似度不达标的非业务关联数据纳入结果集。

## 怎么确认配好了
- 上传单条完整的BOM文件，检查分块后的文本是否保留核心料号、位号字段，无明显截断或断裂。
- 执行一次针对已知料号的检索测试，核对返回结果的数量与业务相关性，调整相似度阈值至符合需求的区间。
- 导入10条模拟工单数据，验证增量索引是否仅更新新增数据，无需全量重建索引。
- 查看向量存储的占用情况，确认分块长度与`maxToken`设置未导致存储空间过度占用。
