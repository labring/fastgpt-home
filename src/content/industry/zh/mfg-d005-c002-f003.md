# SMT贴片与电子组装的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
SMT贴片与电子组装的业务数据来自客户提供的BOM、Gerber文件、坐标文件，以及MES系统、贴片机、SPI/AOI检测设备、回流焊炉温采集设备的实时数据。日常涉及的文档包含BOM与坐标文件、换线表、钢网与炉温记录、首件确认报告、SPI/AOI缺陷报告、维修记录与追溯标签。数据更新频率为每工单、每次换线时实时更新，字段包含料号、位号、替代料、元件批次、炉温参数等，对应单位包括毫米、摄氏度等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据实时性强、更新频率高，且涉及多类细分文档与字段，对多轮对话与提示词配置带来明确约束。首先，实时更新的工单数据要求对话能动态拉取最新的MES、设备参数，避免使用过期的炉温、元件批次信息。其次，多类文档与细分字段要求提示词明确指定不同文档的调用规则，防止混淆BOM数据与缺陷报告内容。再者，核心字段校验需求要求多轮对话逐轮确认料号、位号等信息，降低错装、虚焊等风险。最后，独立的投标项目要求对话绑定唯一标识，避免不同项目的上下文串扰。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 匹配单份投标文稿所需的多类文档总数据量，避免截断核心BOM、坐标文件内容 |
| 单次对话知识库召回数 | 前6条 | 覆盖单份投标文稿需要的BOM、换线表、炉温记录等关联文档的合理数量 |
| variables | 按工单ID传递 | 绑定当前投标对应的具体工单数据，确保调用的是实时更新的MES、贴片机参数 |
| chatId | 绑定投标项目唯一标识 | 区分不同投标项目的对话历史，避免上下文混淆 |
| 对话历史截断阈值 | 最后20轮对话 | 聚焦当前投标的最新需求，过滤冗余的前期沟通内容 |
| 输出格式校验开关 | 开启 | 过滤非业务必要的格式符号 |

## 容易做错的三处
- 现象：对话返回内容携带大量#、*等无意义标点。原因：未开启输出格式校验开关，且提示词未明确要求过滤非业务必要的符号。
- 现象：调用对话接口未返回引用的知识库ID。原因：未启用对话溯源配置，或提示词未要求模型标注引用来源的文档标识。
- 现象：知识库内的图片URL无法在对话结果中正常展示。原因：提示词未明确要求将图片URL转换为可识别的输出格式，未配置图片链接的自动解析规则。

## 怎么确认配好了
- 发起包含BOM料号查询的测试对话，检查返回内容无多余格式符号。
- 查看对话接口返回的字段，确认包含引用的知识库关联标识。
- 上传包含图片URL的测试文档，发起查询，检查对话结果中正确展示图片链接。
- 切换不同投标工单的chatId，确认对话上下文不会混淆不同项目的数据。
