# 乳制品加工的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据来自奶源检测、MES系统、均质与热处理设备、在线温度流量监测、CIP清洗系统、LIMS实验室管理系统。数据更新以每奶罐、每批为节点，部分实时监测参数的同步频率可达秒级。日常文档包含原奶验收记录、标准化配料单、巴氏或UHT热处理记录、CIP清洗记录、灌装记录、留样与微生物检测报告，字段涵盖批次号、理化指标数值、温湿度参数、检测结果等，对应单位包含摄氏度、千克、菌落总数单位等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据按奶罐、批次实时更新且包含敏感理化指标，要求多轮对话需绑定对应批次的`chatId`，避免跨批次数据混淆。日常文档字段多且带专属单位，多轮交互需逐步引导用户明确批次号、指标类型，减少参数歧义。同时，投标报价需基于真实批次的检测与生产数据，提示词需限定模型仅调用知识库内的有效批次内容，不得生成未验证的数值或结论，防止因错误数据导致投标失误。另外，数据来源覆盖多设备系统，需确保检索范围仅包含当前项目关联的奶源、生产与检测记录，避免无关数据干扰。

## 配置怎么定
本文基于FastGPT v4.17.0版本配置。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前投标项目的原奶批次编号 | 确保多轮对话上下文仅关联对应批次的生产与检测数据，避免跨批次信息干扰 |
| `messages` | 按对话轮次追加批次上下文 | 确保每一轮对话都携带最新的批次参数，维持上下文一致性 |
| 单次搜索上限 | 前6条 | 匹配单份投标文档所需的典型数据条目数量，避免冗余信息过载 |
| 最大上下文长度 | 800–1200 字符 | 适配单批次生产与检测文档的平均长度，确保对话上下文完整且不超出模型处理阈值 |
| `variables` | 预设当前项目的奶源批次号与检测类型 | 让模型在检索与生成时自动绑定指定参数，减少用户重复输入 |
| 超时时间 | 600 秒 | 避免对话因等待数据超时中断 |
| 知识库存储上限 | 1000 MB | 适配单批次的所有生产与检测文档 |
| 重排 | 开启 | 对检索到的批次数据按检测时间排序，确保最新的原奶验收与热处理数据优先被调用 |

## 容易做错的三处
- 现象：检索返回的知识库结果附带段落id（如原奶批次的内部编号），被自动写入投标文稿。原因：未在提示词中明确要求过滤知识库的元数据标识，导致模型抓取了非业务字段内容。
- 现象：对话界面无法显示原奶检测报告的配套图片。原因：未配置知识库支持的图片存储与引用规则，导致模型无法正确调用可视化内容。
- 现象：自定义部署的模型在对话与工作区中出现配置不一致。原因：未通过`variables`传递项目专属的批次参数，导致不同场景下的模型调用上下文出现偏差。

## 怎么确认配好了
- 发起一轮包含指定原奶批次号的查询，核对返回的检索结果是否仅包含该批次的生产与检测数据。
- 输入包含专业术语的查询，确认对话界面的优化后的查询是否符合乳制品加工的业务逻辑。
- 测试多轮对话，验证`chatId`绑定的批次号是否在整个对话过程中保持一致，未出现跨批次数据调用。
- 检查自定义模型的配置，确认对话与工作区的模型参数是否同步，无遗漏的预设变量。
