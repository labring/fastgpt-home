# 仓储、批次与厂内物流的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
这个品类的典型数据来自ERP/WMS系统、条码或RFID采集设备、采购工单、库位档案、AGV输送系统及称重设备。日常生成的文档包括收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录，包含物料编码、批次号、库位编码、效期日期、库存数量等核心字段。数据更新节奏涵盖实时（如AGV调度的库位变动）、每日（如领退料统计）与月度盘点（如库存复盘），部分单据包含非结构化备注内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
仓储、批次与厂内物流的数据来源分散且更新频率差异大，需针对实时变动的库位、批次信息配置增量索引，避免全量重建的延迟。核心字段如批次号、效期日期与投标需求强关联，索引需保留元数据标签，确保检索时可精准匹配投标中的物料批次要求。多类型单据的字段长度差异明显，分块时需兼顾结构化单据的字段完整性与非结构化备注的上下文连贯性，防止拆分后丢失跨单据的批次流转关联信息，需合理配置`defaultToken`与`maxToken`参数，确保上下文覆盖完整的批次流转信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 品类单据多为结构化格式，单单据字段较多，该区间可保证批次号、效期等核心元数据完整关联，避免分块断裂 |
| 重叠长度 | 50–80 字符 | 跨单据的批次流转信息需要上下文衔接，该区间可平衡上下文连贯性与索引存储成本 |
| `defaultToken` | 1024 token | 投标文稿需关联的物料信息较多，该取值可覆盖完整的批次台账与库存变动记录 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.75–0.85 | 仓储数据的物料编码、批次号等字段精准性要求高，该区间可过滤无关库存记录，提升检索匹配度 |
| 单次搜索上限 | 前 10 条 | 投标报价需核对多维度物料信息，该上限可控制人工核对的工作量，避免冗余结果干扰 |

## 容易做错的三处
- 现象：知识库重建超过24小时未完成，索引切换按钮置灰无法操作。原因：品类数据包含实时更新的库位与批次信息，未配置增量索引触发规则，全量重建时未限制并发写入线程，导致资源占用过高。
- 现象：批量添加索引时返回参数错误，提示必填字段缺失。原因：未正确映射仓储单据的批次号、库位编码等核心元数据字段，入库请求未携带对应参数，导致索引生成失败。
- 现象：检索结果无法精准匹配投标要求的批次信息，返回大量无关库存记录。原因：未设置相似度阈值，或阈值设置不符合仓储数据的精准性要求，未区分物料编码与批次号的关联权重。

## 怎么确认配好了
- 查看FastGPT v4.17.0的知识库管理界面，确认分块长度、重叠长度等配置与预设取值一致，且已勾选批次号、效期日期等核心元数据字段。
- 上传一份测试用的收货单与批次台账，发起批量入库请求，验证无参数报错，索引生成进度正常。
- 模拟投标文稿的检索需求，输入包含特定批次号与库位的查询语句，核对返回结果的字段匹配度，调整相似度阈值至符合业务需求。
- 模拟一次实时库位变动的单据上传，查看索引监控面板，确认索引在10分钟内完成更新，无延迟或报错。
