# 仓储、批次与厂内物流的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
仓储、批次与厂内物流场景的数据来自ERP/WMS系统、条码或RFID采集设备、采购工单、库位档案、AGV输送系统与称重设备。日常产生的文档包括收货单、上架单、领退料单、移库单、盘点表、批次台账，以及先进先出与效期管控记录。数据更新节奏覆盖实时（如AGV调度数据）、每日（如领退料统计）与月度（如全盘账实核对）三类，核心字段包含物料编码、批次号、库位编号、效期日期与检验状态，无统一固定单位，随物料类型与管理要求变化。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该场景的数据来源分散且更新节奏差异显著，多轮对话需依次区分实时调度数据与历史台账信息，避免混淆不同时间维度的物料状态。核心文档包含批次、效期等敏感管控字段，提示词需明确指定提取范围，防止无关信息干扰投标文稿与报价的生成。账实一致与批次流向是核心管理目标，对话流程需校验物料身份与批次的匹配性，确保生成的投标内容符合实际仓储状态。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配领退料单、批次台账等文档的单页内容长度，避免跨文档分块破坏字段完整性，符合FastGPT v4.17.0的文档分块规则 |
| 单次搜索上限 | 前5条 | 限制返回的仓储数据条目，防止过多历史数据干扰当前投标报价的物料核对 |
| 上下文保留时长 | 600 秒 | 覆盖投标文稿编制的完整对话周期，确保多轮沟通中批次、库位等关键信息不丢失 |
| 知识库关联范围 | 1000 MB 以内 | 限定关联的仓储类文档大小，避免加载冗余数据影响对话响应速度 |
| `variables` | 预设物料字段清单 | 提前定义需提取的物料编码、批次号等核心字段，统一多轮对话的提取标准 |
| `messages` | 按会话存储历史交互 | 保留每轮对话的物料核对记录，确保后续报价生成时关联正确的批次与库位信息 |

## 容易做错的三处
- 现象：对话中调用文本内容提取时，无法识别批次号、库位编号等核心字段，返回空值。原因：提示词未明确指定从仓储类文档中提取指定字段，未关联对应品类的文档模板。
- 现象：模型输出语言与预设英文prompt不符，仅返回中文内容。原因：未在`variables`中配置语言约束参数，或知识库未正确关联英文仓储文档，导致模型优先使用训练数据中的中文生成内容。
- 现象：上传盘点表后触发解析报错。原因：未针对领退料单、批次台账等该品类专属文档配置专属的文本提取规则，通用分块逻辑破坏了盘点表的表格字段结构。

## 怎么确认配好了
- 发起测试对话，输入「生成针对XX工单的投标报价文稿」，检查对话过程中是否依次确认了物料编码、批次号与库位信息，`messages`中是否完整保留了交互记录。
- 触发文本提取功能，上传一份模拟收货单，确认提取的核心字段完整且无遗漏，验证分块长度与文档结构的适配性。
- 配置英文prompt并发起对话，确认模型输出语言符合预设要求，验证`variables`中的语言约束参数生效。
- 查看会话日志，确认`chatId`正确关联当前会话，上下文保留时长覆盖完整的投标文稿编制流程。
