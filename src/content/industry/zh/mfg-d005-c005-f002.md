# 光伏电池片制造的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
晶硅电池片制造企业的工艺、设备、品质部门日常产生的文档，数据来源包括硅片来料记录、MES系统、扩散炉/镀膜设备/印刷机的运行参数、EL与IV测试结果、实验室检测数据。更新频率为每批物料、每片检测、每日生成报告。文档类型涵盖工艺卡、扩散和镀膜参数记录、印刷烧结日志、EL检测图、IV分档数据、良率报告，包含设备运行参数、检测结果数值、工序流程节点等字段，兼具结构化表格、半结构化文本与图像类型，无固定统一的格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
光伏电池片制造的业务数据兼具多类型格式与高频更新特性。处理图像前需确认当前版本、套餐与向量模型的支持范围；图像会先持久化，再按索引生命周期处理，不能仅凭上传完成判断可检索。工序连续的生产特性要求分块时保留相邻工序的上下文关联，避免割裂工艺参数的逻辑链条。片级数据的细粒度字段较多，向量模型需要适配多字段拼接的文本输入，确保投标文稿与报价编制时能准确关联工艺参数与成本核算依据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配光伏电池片工艺文档的单工序参数长度，避免分块割裂工艺逻辑 |
| 重叠长度 | 100–200 字符 | 保留相邻工序的上下文关联，防止分块后丢失工艺参数的前后联系 |
| `defaultToken` | 按样本设置直接分块的默认 token 数 | 该字段用于分块，不代表模型 ID 或向量维度；需用工艺记录验证效果 |
| `maxToken` | 按所选向量模型/服务支持的最大 token 数设置 | 该上限取决于模型与部署，不预设固定值 |
| 相似度阈值 | 按实测标定 | 匹配光伏电池片工艺参数的匹配精度要求，适配投标时的参数对比需求 |
| 单次搜索上限 | 前 5 条 | 控制投标文稿生成时的上下文长度，避免冗余数据干扰报价计算 |

## 容易做错的三处
- 升级后文件上传成功但索引任务失败：仅凭这一现象不能归因于`defaultToken`取值范围变化。检查完整任务日志、实际分块配置、输入字段长度及所选模型/服务支持范围。
- 索引任务长时间未完成：先根据日志确认处理阶段，再检查文件格式、模型上限、服务状态与资源；不要假定部署包含断点续索引开关。
- 切换向量模型后引用结果异常：知识库引用返回空结果，前端显示无匹配内容。原因是未同步更新向量模型的维度配置，原有索引向量与新模型的向量空间不匹配。

## 怎么确认配好了
- 上传单份标准工艺卡文档，查看分块预览界面，确认分块后的文本长度符合配置的分块长度区间。
- 若部署通过自定义向量模型配置这些字段，核对`defaultToken`为直接分块默认 token 数，且`maxToken`不超过所选模型/服务支持上限；再用工艺样本验证。
- 上传部署支持的EL检测图样本，等待知识库训练与索引流程完成后，再检索图像关联内容并核对结果；若当前部署或模型不支持该输入类型，按支持范围替换样本。
