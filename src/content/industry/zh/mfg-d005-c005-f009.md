# 光伏电池片制造的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自硅片来料台账、生产MES系统、扩散炉/镀膜设备/印刷机的运行日志、EL与IV检测设备输出、实验室品质分析报告。数据更新节奏为每生产批次、每片检测节点、每日汇总。日常文档包含工艺卡、扩散与镀膜参数表、印刷烧结记录、EL检测图像、IV分档数据集、良率分析报告，字段涵盖工艺参数数值、电性能指标、外观缺陷标识等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据类型要求模型接入需同时适配结构化参数、时序日志与图像类输入；高频更新的生产数据要求模型调用延迟匹配生产节点节奏，防止投标数据出现滞后；单批次数据量较大且包含细分字段，需限制单次输入的上下文长度，防止超出模型阈值；投标文稿需整合多工序数据，模型需支持跨文档关联提取，同时需适配批量数据处理的并发场景。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 需处理EL检测图、IV测试图像等视觉数据，支撑缺陷识别与指标提取 |
| `maxContext` | 8000–16000 token | 适配单批次生产数据与投标文稿的总文本长度，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 控制单轮回复的输出长度，确保投标文稿的报价与说明内容完整且简洁 |
| `quoteMaxToken` | 1500 token | 限制引用的源文档内容长度，防止冗余信息干扰投标文稿的核心逻辑 |
| `temperature` | 0.3–0.5 | 保持报价与工艺参数的准确性，避免生成偏离实际数据的内容 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或云端的模型服务地址，确保数据传输正常 |
| `AIPROXY_API_TOKEN` | 按权限申请的密钥 | 保障模型调用的身份合法性，防止未授权访问 |

## 容易做错的三处
- 上传EL检测图像时触发视觉模型调用报错，返回格式不支持或400错误。原因：未开启`vision`配置项，或未指定适配视觉任务的模型后端，导致无法解析图像格式。
- 共享页面并发超过60时出现无应答，本地模型服务器资源未达瓶颈。原因：未合理配置并发调用的资源阈值，或未设置请求队列限流，导致模型服务过载。
- 上传包含IV分档数据的大文档时，返回400错误，或<FilesContent>标签内有数据但模型未提取到有效内容。原因：未设置`maxContext`限制，单次输入的文档总长度超出模型支持的上下文上限；或未对长文档进行预处理拆分，导致模型无法完整读取内容。

## 怎么确认配好了
- 上传单份EL检测图像与对应工艺卡文档，验证模型能否正确识别图像中的缺陷标识并关联工艺参数。
- 模拟多并发请求，观察模型服务的响应状态，调整配置以匹配实际并发需求。
- 上传超过常规单批次数据量的文档，检查是否触发上下文溢出报错，确认`maxContext`配置合理。
- 查看模型调用日志，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置是否正常完成身份验证。
