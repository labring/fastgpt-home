# 化妆品生产的投标文稿与报价编制：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据来自护肤、洗护、彩妆及特殊化妆品生产企业的注册备案配方、原料安全资料、称量乳化设备、ERP/MES系统、实验室记录与包材版本库。日常文档包含配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品与成品检验报告、标签审核表，字段含原料成分、限用物质含量、生产批号、包材规格、宣称内容等，更新频率为每批生产或每次换线时触发。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据来源分散，涉及生产设备、ERP/MES、实验室等多个系统，需要通过HTTP接口对接多源数据。高更新频率要求接口能够及时拉取最新的备案配方、包材版本等信息，避免投标文稿使用过期数据。字段受备案约束且包含限用物质等敏感内容，接口传递的字段必须准确无误，否则可能引发合规风险。出错后果直接关联产品下架召回，要求接口具备失败重试与数据校验能力，保障数据一致性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ------------ |
| `Authorization` | 携带`Bearer {oneapi生成的令牌}` | 用于对接外部模型渠道，完成接口鉴权 |
| `variables` | 传入`{"recipe_version": "{{备案配方版本}}", "pack_material": "{{包材版本}}"}` | 传递化妆品生产专属的业务变量，确保投标数据与最新备案一致 |
| `responseData` | 提取`quote_content, tender_document` | 匹配投标文稿与报价编制所需的核心返回字段 |
| 接口超时阈值 | 30–60 秒 | 适配多系统数据拉取的平均耗时，避免请求中断 |
| 失败重试次数 | 2 次 | 应对临时网络波动或外部系统短暂不可用 |
| 字段校验开关 | 开启 | 校验返回数据是否包含限用物质、生产批号等必填内容 |

## 容易做错的三处
- 调用时返回「渠道不可用」报错，排查发现oneapi渠道配置的令牌未在FastGPT中正确绑定`Authorization`参数。
- 接口返回字段为空，原因是未通过`variables`传入正确的业务变量，导致外部系统无法匹配对应生产批次的配方与报价数据。
- 调用后返回令牌无效提示，原因是未使用oneapi生成的有效令牌，或令牌未携带正确的Bearer前缀。

## 怎么确认配好了
- 执行接口测试请求，查看返回结果是否包含配方成分、包材规格等化妆品生产专属字段。
- 触发一次完整的投标文稿生成流程，核对生成内容是否与ERP系统中的最新备案配方一致。
- 模拟oneapi渠道鉴权失败场景，确认系统会触发对应报错提示并记录日志。
- 调整`variables`中的业务变量值，验证接口返回的报价与文稿内容会随变量变化更新。
