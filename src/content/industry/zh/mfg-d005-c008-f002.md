# 化妆品生产的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
化妆品生产企业的日常文档包含配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验报告、标签审核文件等。数据来源包括注册或备案配方、原料安全资料、ERP/MES系统、实验室检测数据、包材版本文件。数据更新频率为每批生产或每次换线时更新，文档字段包含原料名称、用量、备案编号、生产批号、检验指标等，部分文档带有重量、温度、时间等单位参数。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于数据按生产批次和换线节奏高频更新，索引环节需要支持增量更新以避免重复全量索引，提升处理效率。不同文档的结构差异较大，如配方工艺单为步骤式文本，检验报告为表格化数据，分块时需要适配不同文档的内容长度，避免拆分关键业务步骤。备案配方、原料安全资料等内容对匹配精度要求较高，索引需要过滤低相关性的冗余数据，防止投标文稿出现配方或宣称错误。多来源数据的字段格式不统一，索引前需要完成字段映射与标准化处理，保证向量嵌入的一致性，避免匹配偏差。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配化妆品生产文档的段落长度，避免拆分连续的配方工艺步骤 |
| 重叠长度 | 100–200 字符 | 保留工艺步骤、原料清单的上下文连贯性，防止关键信息被截断 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关文档，避免投标文稿中出现错误的原料或备案信息 |
| `defaultToken` | 4096 | 适配批量导入的配方文档总长度，符合FastGPT的基础token限制 |
| 单次搜索上限 | 前 10 条 | 控制召回的文档数量，避免生成投标文稿时引入冗余信息 |
| 最大上下文 | 8000 字符 | 整合投标所需的配方、原料、备案等核心信息，保证内容完整 |

## 容易做错的三处
-  知识库导入后长期显示索引中状态。原因是未配置增量索引触发规则，或导入的单份文档（如批量配方单）超过`maxToken`限制，导致索引任务阻塞。
-  替换embedding模型后相似度数值异常偏高。原因是未统一配置embedding模型的归一化参数，导致向量空间尺度不一致，出现相似度超出合理范围的结果。
-  无法找到m3e模型的可用频道。原因是未在系统设置中添加自定义embedding模型的部署节点，或节点配置未指向正确的m3e服务地址。

## 怎么确认配好了
-  上传单份典型文档（如单批次配方工艺单），查看索引完成状态是否在合理时间内更新为已完成。
-  输入测试查询（如「某备案原料的限用要求」），查看召回的文档是否包含对应品类的备案数据，且排序符合业务逻辑。
-  检查系统设置中的embedding模型配置，确认已添加正确的模型频道地址，无报错提示。
-  导入批量文档（如10份配方单），验证索引任务是否能按批次完成，无阻塞或失败日志。
