# 化妆品生产的投标文稿与报价编制：工作流编排

## 这个品类的数据长什么样
化妆品生产的投标与报价相关数据，来源包括注册或备案配方、原料安全资料、称量与乳化灌装设备数据、ERP/MES系统、实验室检验记录、包材版本档案。日常文档包含配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品与成品检验报告、标签审核文档。数据更新频率为每批生产或每次换线，字段涵盖批次号、原料用量、备案编号、限用物质含量，单位包括g、mL、有效期等。

## 这些特征在「工作流编排」这一环带来什么约束
化妆品生产的投标与报价工作流需匹配数据来源分散、更新频率随批次变化的特征。多数据源需从ERP、MES、实验室等不同系统拉取数据，要求工作流支持多节点拉取并绑定批次号作为关联参数，确保数据对应正确生产批次。每批换线触发数据更新，要求工作流按生产事件触发，匹配每批换线的更新节奏。配方与标签需符合备案要求，工作流需增加备案数据校验节点，避免出现配方与备案不一致的风险。投标文稿需关联实际生产数据，要求工作流整合多环节的字段校验，确保数据准确。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定批次号、备案配方编号、原料安全资料版本、上下文参数设置为1000 token | 投标文稿需关联对应批次的备案数据与实际生产参数，控制每个AI节点的token使用上限 |
| 节点触发规则 | 按生产批次完成后触发 | 匹配化妆品生产每批换线的数据更新频率，符合业务节奏 |
| `nodeId` | 绑定原料校验节点、标签审核节点、报价计算节点的ID | 编排多节点按顺序执行，确保校验与报价流程正确 |
| 单次调用超时 | 600秒 | 平衡ERP/MES接口调用的等待时间与流程效率 |
| 单次数据库查询上限 | 前5条 | 匹配投标文稿所需的核心数据量 |
| 重试次数 | 3次 | 处理临时接口调用失败的重试次数 |

## 容易做错的三处
- 编排多个AI大模型对话节点时，出现token累加超出限制。现象为节点执行报错提示token不足。原因是未对每个节点的`variables`配置独立上下文参数，导致多个节点的token数共享累加。
- 调用指定数据库时返回查询结果为空。现象为数据库查询节点输出无数据。原因是未正确绑定`variables`中的查询条件，未关联对应批次的生产数据。
- 发布渠道链接后，返回“undefined”is not valid json报错。现象为接口返回格式不符合标准JSON结构。原因是工作流输出未统一为标准格式，本地测试时未校验输出结构。

## 怎么确认配好了
- 检查`variables`配置的参数，确认绑定了当前生产批次的备案配方编号、原料用量等数据，与ERP/MES中的批次数据匹配。
- 触发工作流后，查看每个节点的执行日志，确认原料校验、标签审核节点的执行结果符合预期。
- 生成渠道链接并调用，确认返回结果为标准JSON格式，无缺失字段或undefined值。
- 模拟换线后触发工作流，确认工作流按预设顺序执行所有编排节点。
