# 化妆品生产的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自护肤、洗护、彩妆及特殊化妆品生产企业的日常业务文档，包括配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品成品检验报告与标签审核文件。数据来源于备案注册配方、原料安全资料、生产设备、ERP/MES系统、实验室数据及包材版本信息，更新频率为每批生产或每次换线。文档包含配方原料、限用物质、生产参数、包材宣称与批号等字段，需严格匹配备案要求。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据的批次化更新、备案约束性与多文档关联特征，对模型接入配置带来多重约束。批次化数据要求配置支持动态读取最新生产批次文档，避免使用过期备案或生产数据。备案匹配字段的严格校验需求，要求模型精准识别配方原料、限用物质与标签宣称等关联字段，防止出现备案不一致风险。单批次文档与历史数据的叠加易超出模型上下文上限，需配置合理的上下文截断与切片规则。工具调用需适配原料复核、参数校验等细分场景，确保调用逻辑匹配业务环节。

## 配置怎么定
本配置基于FastGPT v4.17.0版本制定，具体参数如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单批次生产文档、历史备案数据与投标文稿的叠加上下文，避免超出模型支持上限 |
| `maxTokens` | 2000–3000 token | 控制单条输出内容长度，确保生成的投标文稿与报价符合格式规范与内容完整性要求 |
| `quoteMaxToken` | 1500 token | 限制引用的业务文档片段长度，优先保留配方原料、限用物质、备案宣称等核心校验字段 |
| `toolChoice` | auto | 支持自动识别业务需求对应的工具，适配配方复核、参数校验、标签核对等不同投标环节 |
| `temperature` | 0.2–0.4 | 降低输出随机性，确保备案匹配、字段校验等关键环节的结果一致性与准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或私有部署的API访问路径，保障业务数据的安全传输 |

## 容易做错的三处
- 现象：上传多份批次配方、备案文档后，对话界面返回上下文溢出报错。原因：未针对化妆品生产的批次化多文档特征配置适配的`maxContext`参数，直接沿用通用场景的上下文阈值，未对长文档进行合理切片。
- 现象：生成的投标文稿中出现配方原料与备案要求不符的字段错误。原因：`temperature`取值超出0.2–0.4区间，导致模型输出随机性过高，无法严格匹配备案数据的精准字段要求。
- 现象：工具调用仅触发单一校验环节，无法自动识别需要同时复核的配方与标签宣称。原因：`toolChoice`被固定为指定工具，未适配多环节联动的投标需求。

## 怎么确认配好了
- 上传单批次的配方工艺单与备案文件，核对生成的上下文片段是否包含核心业务字段，确认上下文长度符合配置要求。
- 触发工具调用动作，确认系统可自动识别并调用匹配的校验工具，覆盖原料复核、标签宣称核对等投标所需环节。
- 生成多条测试性投标文稿片段，核对输出结果的字段一致性，确认`temperature`取值符合业务精度要求。
- 测试API接口的访问与权限校验，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置可正常调用目标模型。
