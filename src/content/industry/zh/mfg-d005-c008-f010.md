# 化妆品生产的投标文稿与报价编制：知识库检索与召回

## 这个品类的数据长什么样
典型主体为护肤、洗护、彩妆及特殊化妆品生产企业，日常文档包含配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验报告、标签审核文档。数据来源涵盖注册或备案配方、原料安全资料、称量与乳化设备数据、ERP/MES系统、实验室检测结果、包材版本文件。数据更新频率为每批生产或每次换线时更新，文档字段包含原料名称、限用物质含量、乳化温度、批号、包材版本号等，单位涉及摄氏度、克、毫克等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
化妆品生产的投标与报价编制需依赖合规的备案数据与生产记录，数据高频更新的特性要求检索系统需支持实时或准实时的文档同步，避免使用过期的配方或标签内容。多类型且字段细分的文档结构，要求检索需精准匹配业务字段，例如限用物质含量、包材版本号等，避免泛化匹配导致的合规风险。投标场景下需快速定位与当前项目匹配的文档，因此召回范围需限定在对应品类的备案库与生产记录库，避免无关文档干扰复核流程。

## 配置怎么定
本配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 过滤低匹配度的非合规文档，避免投标时误用未备案的配方或标签内容 |
| `limit` | `前10–15 条` | 控制召回结果数量，减少投标文稿复核的工作量，同时覆盖核心合规依据 |
| `searchMode` | 语义+关键词混合模式 | 同时匹配配方文本与备案的精准字段，例如原料名、限用物质含量，提升检索精准度 |
| `usingReRank` | `开启（重排窗口为前20 条）` | 按投标项目的品类（如彩妆、护肤）对召回结果重新排序，优先返回与当前项目匹配的文档 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展查询词，例如将“配方”扩展为“备案配方、工艺单”，覆盖投标所需的全部合规文档类型 |
| `collectionIds` | `绑定5–8 个指定文档集合` | 限定检索范围，避免召回无关品类的文档，提升检索效率与合规性 |

## 容易做错的三处
- 现象为检索结果包含非当前投标项目的包材版本文档，原因是未配置`collectionIds`限定检索范围，误将全量知识库内容纳入召回。
- 现象为飞书知识库的最新备案配方未被检索到，原因是未配置自动同步触发规则，仅手动更新知识库集合，无法获取最新的生产或换线数据。
- 现象为检索请求返回429状态码或耗时超过30 秒，原因是未按项目调整检索频次配置，超出当前知识库的调用上限，未合理限制单次检索的请求频率。

## 怎么确认配好了
- 输入投标项目的备案配方编号，检查检索结果中是否优先返回对应配方工艺单、原料安全资料。
- 查看检索日志，确认仅包含当前绑定的`collectionIds`对应的文档集合，无无关品类的文档。
- 测试开启`usingReRank`后，彩妆类投标的结果是否优先返回彩妆相关的检验记录与包材文档。
- 输入“标签”查询词，确认检索结果包含标签审核文档与备案宣称内容，验证`datasetSearchUsingExtensionQuery`是否生效。
