# 化学药制剂生产的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
化学药制剂生产相关数据来自经批准的处方工艺、物料批次信息、MES电子批记录、设备与环境监测数据、LIMS系统及质量管理系统。日常文档包含主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差/CAPA/变更文件及批放行审核表。数据更新频率为每批生产、每个关键工艺步骤、按环境与设备监测计划执行，字段涉及批次标识、物料参数、工艺执行数据、检验结果等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据按批次独立更新且关联紧密，要求索引需支持按批次维度隔离与关联检索，避免跨批次数据混淆。文档兼具结构化字段与长文本工艺描述，分块操作需避免破坏字段完整性，否则会影响检索匹配精度。高更新频率要求索引支持增量更新，避免全量重建带来的资源消耗。同时投标文稿需汇总多批次合规数据，向量索引需能快速关联不同文档中的对应批次信息，支撑快速复核与报价编制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配批记录中单条工艺或检验记录的长度，避免破坏字段完整性 |
| 重叠长度 | 100–200 字符 | 衔接跨块的工艺步骤描述，确保上下文关联完整 |
| `defaultToken` | 4096 token | 适配单批次核心文档的文本长度，平衡向量生成质量与调用成本 |
| `maxToken` | 8192 token | 支撑投标文稿汇总的长文本处理需求，避免截断关键合规信息 |
| 单次召回上限 | 前 5 条 | 聚焦最相关的批次数据，避免冗余信息干扰投标报价编制 |
| 索引更新触发规则 | 按单批次完成后触发 | 匹配数据按批次更新的节奏，减少无效索引操作 |

## 容易做错的三处
- 知识库上传后状态长时间停留在索引中，原因是未适配按批次触发的增量索引逻辑，批量上传多批次数据时线程资源耗尽。
- 向量化时报错提示速率超限，原因是未调整`defaultToken`对应的并发请求配置，导致调用向量模型的请求频率超出限制。
- 分块设置为3000字符时出现文本块丢失，原因是批记录中存在长字段（如完整工艺步骤），分块时截断了字段边界导致解析失败。

## 怎么确认配好了
- 上传单批次的完整批生产记录，检查分块后的文本块是否保留了完整的物料称量、工艺参数字段，无截断或丢失。
- 查看FastGPT v4.17.0的向量模型调用日志，确认请求速率未触发超限报错，且`maxToken`设置适配了上传文档的最大长度。
- 发起与投标文稿相关的检索请求，验证召回结果包含对应批次的检验记录、偏差处理记录等关联数据。
- 模拟批量上传3–5批次的文档，确认索引状态可在合理时间内完成更新，无长时间停滞。
