# 化学药制剂生产的投标文稿与报价编制：工作流编排

## 这个品类的数据长什么样
化学药制剂生产的相关数据来自经批准的处方工艺、物料批次信息、MES系统、电子批记录、设备与环境监测数据、LIMS系统及质量管理系统。日常生成的文档包含主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差/CAPA/变更文件及批放行审核表。数据更新随每批生产流程、各关键工艺步骤及既定监测计划执行，文档字段包含物料批号、工艺参数值、检验结果数值、偏差描述等，单位涵盖质量单位、体积单位、温度单位等。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新频次随生产批次动态变化，要求工作流需支持对接多系统的实时数据拉取，避免手动录入导致的延迟。文档结构包含多类合规性记录，工作流需按GMP要求串联各环节数据，确保投标文稿与报价编制时可调用完整的批记录、检验结果及偏差处理文件。不同批次的物料参数、工艺数据存在差异，工作流需支持动态读取对应批次的变量数据，不宜使用固定模板覆盖全场景。同时，数据需经质量放行环节校验后才可纳入编制流程，需在工作流中嵌入合规校验节点。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定每批次物料批号、工艺参数、检验结果为独立变量，取值为对应批次的实际数据，按实测标定 | 化学药制剂生产的每批次数据存在差异，需动态调用对应批次的`variables`完成投标文稿与报价的参数填充 |
| `nodeId` | 为合规校验节点、数据拉取节点分配唯一`nodeId`，取值为自定义的节点标识字符串 | 便于工作流中精准定位各环节节点，实现按节点触发数据更新与校验 |
| 全局变量 | 预设GMP合规校验规则、标准物料单价库，取值为固定合规规则库与经审批的单价区间，按实测标定 | 投标文稿需符合GMP合规要求，标准单价库可快速生成报价的基础数据 |
| 工具调用超时 | 600秒 | 多系统数据拉取及合规校验需较长处理时间，避免因超时中断工作流 |
| 工作流分支触发 | 按批放行状态触发后续编制节点 | 未通过质量放行的批次数据不可用于投标编制，需确保仅合规数据进入后续环节 |

## 容易做错的三处
- 现象：工作流执行后，全局变量未按工具调用结果更新，对应字段为空或保留初始值。原因：未在工具调用节点中正确配置`variables`的更新绑定逻辑，导致变量未被同步修改。
- 现象：无法找到自定义引用模板与提示词的配置入口，仅能调整少量基础参数。原因：使用的FastGPT版本低于v4.9.7，该功能在该版本及FastGPT v4.17.0中均已支持。
- 现象：工作流拉取的多系统数据出现重复或错位，导致投标文稿出现参数错误。原因：未为各数据拉取节点分配唯一`nodeId`，导致节点间数据调用出现混淆。

## 怎么确认配好了
- 手动触发工作流，检查各数据拉取节点是否能正确拉取对应批次的物料、工艺与检验数据。
- 调用工具节点后，查看`variables`变量是否同步更新为工具返回的实际数据。
- 触发分支节点，验证仅通过质量放行的批次数据才可进入后续的文稿与报价编制环节。
- 检查全局变量中的合规规则与单价库是否与经审批的标准一致。
