# 医疗器械装配与洁净生产的投标文稿与报价编制：工作流编排
本文适配FastGPT v4.17.0版本

## 这个品类的数据长什么样
该品类的日常文档包含生产工艺规程、批生产记录、洁净区记录、灭菌批记录、检验报告、软件版本记录、不良事件与追溯资料。数据来源为设计历史文件、器件与材料批次、MES系统、洁净环境监测设备、灭菌设备、检验和校准系统。数据更新频率为每批或每台产品产出时，以及按洁净环境监测计划定期更新。数据字段包含唯一器械标识、材料批次号、洁净环境参数、灭菌参数、检验结果等，无统一固定的单条数据长度。

## 这些特征在「工作流编排」这一环带来什么约束
该品类数据来源分散且关联要求严格，工作流编排需对接多类异构数据源节点，确保完整拉取生产、环境、灭菌等多维度数据。数据按批次更新的特性，要求工作流需支持按单批或多批生产任务触发，避免冗余执行。文档与追溯资料的强合规要求，使得工作流需保留各环节的参数溯源路径，便于投标时的合规性核查。同时，数据字段的非标准化特性，要求工作流需配置灵活的参数映射规则，适配不同批次的文档结构差异。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 变量定义 | `variables` 绑定唯一器械标识、材料批次号、灭菌参数字段 | 投标文稿需关联对应生产数据，确保报价与实际生产信息匹配 |
| 节点ID绑定 | `nodeId` 按数据源类型命名，如mes-data、sterilize-record | 便于工作流调试与溯源，快速定位数据拉取节点 |
| 触发规则 | 按每批生产完成后触发 | 匹配数据更新频率为每批或每台的业务特性 |
| 循环处理范围 | 遍历前100条批次数据 | 适配单次投标覆盖的生产批次规模，避免系统资源过载 |
| 文档映射长度 | 800–1200 字符 | 符合医疗器械投标文档的排版规范 |
| 超时设置 | 600 秒 | 为复杂数据校验与合规核查预留合理时长 |
| 参数校验阈值 | 按实测标定 | 符合医疗器械数据的合规性校验要求 |

## 容易做错的三处
- 工作流中添加自定义插件后无输入输出参数，日志无报错。原因是未在`variables`中声明插件所需的输入字段，导致参数未被系统加载。
- 循环运行时数组参数未被正确遍历，输入端仅显示数组整体。原因是未将循环体的输入配置为数组拆分后的单元素节点，直接绑定了原始数组。
- 工作流无法导出配置文件。原因是未开启工作流的全局导出权限开关，或节点中包含未保存的临时配置。

## 怎么确认配好了
- 触发一次测试批次的工作流，检查`variables`中是否正确加载了对应批次的生产数据字段。
- 运行循环节点，确认数组元素被逐个传入后续的AI会话或数据处理模块。
- 验证自定义插件的输入输出字段在节点配置面板中正常显示。
- 尝试导出工作流配置，确认导出流程无报错且生成的配置文件完整。
