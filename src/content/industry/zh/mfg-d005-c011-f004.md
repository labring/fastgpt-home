# 半导体封装测试的投标文稿与报价编制：工作流编排

## 这个品类的数据长什么样
半导体封装测试环节的数据来自晶圆测试图、MES系统、键合与塑封设备、ATE测试机、X-ray/SAM检测设备及客户规格文件。数据更新频率覆盖每批物料、每颗芯片测试、每日运维节点。日常涉及的文档包含封装流程卡、键合与塑封工艺参数表、晶圆来料图、测试程序版本清单、良率报告、失效分析报告，各文档包含工艺参数、批次编号、测试bin值、失效点位等字段，单位涵盖微米、伏特、批次号等。

## 这些特征在「工作流编排」这一环带来什么约束
半导体封装测试的数据多源异构且更新频次多样，工作流编排需适配每批、单颗测试、每日三类更新节奏，分别触发对应的数据拉取与校验环节。日常文档包含大量专业字段，工作流需配置精准的`variables`映射规则，将晶圆来料图的点位、ATE测试的bin分布数据准确关联到投标文稿的报价分项。同时，需确保数据来源与MES、ATE设备的输出格式兼容，避免因格式不匹配导致的参数错位，且需在流程中嵌入客户规格校验节点，防止错用工艺程序或批次。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配半导体封装测试的投标报价工作流编排需求。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发节点 | 按批次触发、单颗测试触发、每日定时触发三档 | 匹配封装测试每批、每颗测试、每日的更新频率，确保对应环节的参数实时更新 |
| `variables`映射规则 | 将晶圆来料图的点位ID、ATE测试的bin值、良率报告的合格数与投标文稿的报价字段一一绑定 | 确保专业数据准确映射到报价分项，避免信息错位 |
| 单次数据拉取上限 | 500条 | 适配单批次测试数据的规模，避免接口过载 |
| 可见度配置 | 敏感工艺参数关闭查看原文，通用报价信息开放查看来源 | 兼顾信息安全与投标文稿的可追溯性要求 |
| 代码运行节点 | 启用Python脚本执行权限，执行超时设置为300秒 | 适配封装测试的bin分布分析、批次对齐等自定义计算逻辑 |
| `nodeId`校验 | 绑定对应设备的唯一节点标识 | 确保从MES、ATE测试机拉取的数据归属正确，避免混源错误 |

## 容易做错的三处
- 现象：工作流中代码运行节点执行Python脚本时弹出权限报错，或脚本运行无输出。原因：未在FastGPT平台开启Python代码运行的权限配置，或脚本中引用了未授权的依赖库。
- 现象：配置的可见度规则未生效，敏感工艺参数仍可被非授权账号查看原文。原因：未按内容属性区分配置开关，误将封装流程卡等敏感文档的权限设置为开放。
- 现象：导入工作流模板后界面显示导入成功，但画布内无任何节点或配置丢失。原因：模板文件中的`nodeId`配置与当前平台的节点标识规则不匹配，或导入过程中出现数据截断。

## 怎么确认配好了
- 触发对应更新节奏的节点，检查拉取的数据是否与MES、ATE设备的实时输出一致。
- 测试`variables`映射规则，输入模拟的晶圆来料图数据，确认投标文稿的报价分项是否正确生成。
- 验证可见度配置，以非授权账号登录平台，检查敏感工艺参数是否无法查看原文。
- 运行代码运行节点，确认Python脚本可正常执行并输出预期的bin分布分析结果。
