# 半导体封装测试的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
该品类日常文档包含封装流程卡、键合与塑封参数、晶圆来料图、测试程序版本、良率报告、失效分析报告。数据来源于晶圆测试图、MES系统、键合机与塑封设备、ATE测试机、X-ray/SAM检测设备及客户规格要求。数据更新频率为每批晶圆、每颗芯片测试结果及每日设备运行参数更新，单份文档包含设备参数编号、批次号、良率数值、失效类型等字段，单位随文档类型匹配对应计量标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类多源异构的业务数据来源，要求模型接入需支持跨系统数据的结构化提取与关联，配置时需兼顾不同数据源的格式兼容。高频次的更新节奏，要求上下文配置需适配实时或准实时的数据同步需求，避免因上下文过期导致批次对齐错误。投标场景需严格保留原始文档的参数、批次信息，模型输出不得擅自修改字符格式或字段单位，同时需应对并发请求下的资源占用问题，避免延时过高。此外，本地模型部署的需求在Linux环境下较为常见，需配置适配本地API的接入规则。

以下配置适配FastGPT v4.17.0版本，基于半导体封装测试的业务特征制定。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 该品类业务数据多源且按批次/每日更新，需保留足够的历史批次、测试参数上下文，避免关键对齐信息丢失 |
| `temperature` | 0.1–0.3 | 投标场景需严格匹配原始文档格式与参数，不宜生成发散内容，保持输出一致性 |
| `quoteMaxToken` | 1500–2000 token | 需完整引用晶圆来料图、测试程序版本等长文档内容，避免截断关键参数或批次标识 |
| `AIPROXY_API_ENDPOINT` | `http://localhost:11434/v1` | 适配Linux环境下本地ollama部署的大模型调用，降低公网传输延时 |
| `maxTokens` | 2500–3500 token | 单份投标文稿与报价的输出长度需覆盖完整封装方案与报价明细，避免内容被强制截断 |
| 工作流/API 工具选择配置 | auto | 自动触发文档引用工具，对齐晶圆图与实物批次信息，无需手动配置调用规则 |

## 容易做错的三处
- 现象：配置本地重排模型后返回请求错误。原因：未正确匹配重排模型的API地址与认证参数，或未在FastGPT中开启本地模型的网络访问权限。
- 现象：并发请求上升时，模型回答延时显著升高，且后台日志显示频繁查询与写入MongoDB。原因：未限制`maxContext`的合理取值，导致每次请求都加载过量历史数据，触发MongoDB的高频读写操作。
- 现象：调用大模型时，输出内容出现多余空格、字母被改为大写的问题。原因：未将`temperature`设置为较低区间，且未配置严格的格式约束，导致模型擅自调整原始文档的字符格式。

## 怎么确认配好了
- 发起单条测试请求，核对输出内容是否完整引用了配置的业务文档字段，无擅自修改的字符格式或参数错误。
- 模拟并发请求，观察后台资源占用情况，确认延时未随并发数上升出现无规律升高。
- 检查模型API的调用日志，确认请求地址、认证参数与配置项一致，无无效的网络报错。
- 验证本地模型部署的连通性，确认Linux环境下的模型服务可被FastGPT正常访问，无连接超时问题。
