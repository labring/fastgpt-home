# 印刷与包装加工的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
印刷与包装加工品类的日常数据覆盖印前文件、拼版单、印刷工艺单、油墨配色记录、首件签样、条码检测、模切与复合记录等。数据来源包括客户稿件、色彩管理系统、印刷机运行数据、油墨与基材批次台账、分光仪检测结果、条码检测仪读数等。数据更新随每笔订单、每批次生产或每次印版更换触发，单次更新内容包含单批次生产的工艺参数、质量检测记录与对应客户需求文档。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据更新频率高，单次订单、批次或换版均会触发新数据生成，要求索引支持高频小批量增量更新，避免全量索引带来的性能损耗。数据来源覆盖多类生产与检测设备输出，包含文本格式的工艺要求、数值型的印刷参数、检测类的条码与质量记录，要求向量模型兼容混合格式数据的向量化处理，同时索引需支持多字段关联存储，确保投标文稿与报价编制时可精准匹配对应生产数据。不同文档的字段结构差异明显，需避免统一分块规则导致的语义割裂，因此索引分块策略需适配单文档的字段特征。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配印刷工艺单、拼版单等文档的单段语义完整性 |
| 重叠长度 | 100–150 字符 | 避免跨分块的工艺参数、条码信息被割裂 |
| 相似度阈值 | 0.75–0.85 | 确保匹配的生产数据与投标需求的语义一致性 |
| `defaultToken` | 4096 token | 覆盖单份完整投标文稿的向量存储需求 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 单次召回上限 | 前6条 | 匹配该品类单订单关联的生产数据量 |

## 容易做错的三处
- 现象：向量索引构建过程长时间无进度，界面显示请求超时或进程无日志输出。原因：未针对该品类高频小批量的更新特性配置增量索引，采用全量索引策略导致系统资源被耗尽。
- 现象：创建索引后调用语言模型时，返回空结果或提示模型未配置。原因：错误将索引模型与语言模型的服务地址绑定为同一入口，未分离向量检索与生成推理的链路。
- 现象：召回的生产数据与投标需求匹配度偏低，出现大量不相关的批次记录。原因：分块长度设置不符合该品类文档的语义单元特征，导致向量化后的语义关联出现偏差。

## 怎么确认配好了
- 上传一份该品类的拼版单与印刷工艺单，检查分块后的文本是否保留完整的工艺参数与尺寸信息。
- 发起一次投标文稿的检索请求，核对召回的结果条数符合配置的单次召回上限。
- 查看系统日志，确认索引更新仅针对新增的订单或换版数据，未触发全量重建。
- 在FastGPT v4.17.0的系统配置页面，检查索引模型的访问地址与密钥已正确绑定。
