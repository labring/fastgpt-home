# 印染与后整理的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
这个品类的主体为染整厂、面料企业的染色、定形、实验室与质量部门。日常产生的文档包含染色配方、称化料记录、染缸曲线、打样确认、色差报告、定形工艺单、污水台账。数据来源涵盖客户色样、配方库、染化料批次、染缸控制设备、测色仪、定形机、环保监测装置。数据更新频率为每缸、每批、每班，单次更新的文档包含具体的工艺参数、批次编号与检测结果。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的高频次、批次化更新特性要求向量索引支持增量更新，避免全量重建带来的性能损耗。文档中包含大量专业工艺参数与时序数据，分块操作不能破坏跨字段的业务关联，比如升温曲线与对应加料量的绑定关系。多来源的数据格式差异，要求索引兼容手工记录的文本与仪器输出的结构化文本，确保向量编码的一致性。同时，投标文稿与报价编制需要快速召回多份关联文档，索引的召回精度需要匹配专业工艺的匹配逻辑，避免无关数据干扰检索结果。向量模型的编码长度需匹配`maxToken`的设置，避免超出系统限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配染色配方、染缸曲线等单份文档的核心业务字段长度，避免拆分破坏工艺参数关联 |
| 重叠长度 | 100–150 字符 | 覆盖跨块的工艺参数关联信息，比如升温曲线的前后段衔接 |
| `maxToken` | 4096 token | 适配投标文稿中批量引用的染缸参数、色差数据的总长度限制，符合FastGPT v4.17.0的通用配置标准 |
| `defaultToken` | 2048 token | 作为单条索引文本的默认长度阈值，平衡检索效率与信息完整性 |
| 相似度阈值 | 0.75–0.85 | 匹配印染工艺参数的专业匹配精度，避免误匹配相似色号或工艺曲线 |
| 单次搜索上限 | 前8条 | 覆盖投标报价中需要参考的多缸工艺、多批次染化料数据的检索需求 |

## 容易做错的三处
- 现象：检索结果中出现不相关的染缸曲线数据，返回条数超出预期。原因：未设置合理的相似度阈值，导致低匹配度的非目标工艺数据被召回。
- 现象：增量索引更新失败，日志显示字段为空。原因：未正确映射染化料批次、缸号等必填业务字段，导致增量索引无法读取有效数据。
- 现象：检索响应超时，耗时超过预设阈值。原因：分块长度设置过大，导致单批次索引的向量计算量超出系统承载上限，引发性能瓶颈。

## 怎么确认配好了
- 上传单份标准染色配方文档，核对索引分块是否完整保留温度、浓度、保温时间等核心工艺参数，无强制截断。
- 发起基于色差报告的检索，确认返回结果的相似度符合预设的匹配精度区间。
- 执行增量索引更新，检查日志中无字段为空或更新失败的报错信息。
- 发起批量检索多缸工艺数据，确认响应耗时符合业务处理的时间要求。
