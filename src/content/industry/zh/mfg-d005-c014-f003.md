# 印染与后整理的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来自客户色样、配方库、染化料批次记录、染缸控制系统、测色仪、定形机及环保监测设备。日常产出的文档包含染色配方、称化料台账、染缸运行曲线、打样确认单、色差报告、定形工艺单、污水排放台账。数据更新节奏为每缸生产、每批物料、每班作业完成后同步更新。数据字段包含物料批次号、染色参数、色差数值、工艺温度曲线、排放指标等，单位涵盖克、升、摄氏度、秒等加工与检测常用单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据更新频繁且按缸、批、班同步，要求多轮对话能实时调取最新批次的染化料参数、染缸运行曲线，避免使用过时生产数据。文档包含大量专业检测数值与工艺参数，提示词需精准匹配染色、色差、定形等细分场景的术语，避免混淆其他品类的织物结构描述。投标报价需关联单缸或单批的成本核算，多轮对话需逐步引导输入订单色样要求、批量规模，同时调用对应批次的生产数据，约束了上下文`messages`的分段整理规则，需按业务环节拆分对话轮次，避免上下文过载。此外，生产出错涉及整缸报废或排放超标，提示词需包含异常校验逻辑，确保报价与文稿中的工艺参数匹配实际生产数据。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 上下文窗口长度 | 8000–12000 token | 需容纳单缸染整工艺参数、多轮投标需求及历史对话内容，避免关键数据截断 |
| `variables` 绑定字段 | 绑定染化料批次单价、染缸单位能耗、打样成本 | 确保多轮对话中可实时调用最新生产数据，匹配`variables`的参数调用规则 |
| 历史对话传递开关 | 开启 | 需通过`messages`传递前序投标需求、工艺确认细节，避免重复询问用户已知信息 |
| 提示词触发时机 | 按用户输入轮次触发 | 确保每轮对话都加载当前订单对应的品类专属工艺规则，符合多轮交互逻辑 |
| 异常日志存储开关 | 开启 | 记录对话失败时的`chatId`与请求内容，便于排查部署或调用问题 |
| 单次对话最大等待时长 | 600 秒 | 匹配染整缸体运行的常规时长，避免因超时中断关键报价计算 |

## 容易做错的三处
- 现象：工作流对话显示失败，但模型后台有响应日志。原因：未正确绑定`variables`对应的品类专属数据字段，导致对话调用时无法获取染化料批次或工艺参数，触发内部校验失败。
- 现象：调用对话节点时无法传递历史对话内容。原因：未开启历史对话传递开关，或未在`messages`中正确格式化前序交互内容，导致上下文丢失。
- 现象：对话异常报错后无日志记录。原因：未开启异常日志存储配置，导致`chatId`与请求详情未被留存，无法定位部署或参数错误。

## 怎么确认配好了
- 发起模拟投标需求对话，输入单缸染色的基础参数，核对对话返回的报价内容是否关联当前绑定的`variables`数据字段。
- 发起多轮对话，先提交订单色样要求，再补充批量规模参数，确认对话能保留前序输入的上下文内容。
- 触发模拟异常场景，比如输入不符合染整工艺的参数，检查系统是否生成对应`chatId`的日志记录。
- 查看配置项中的上下文窗口长度，确认取值覆盖当前业务所需的对话轮次与数据量，按需调整。
