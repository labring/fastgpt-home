# 印染与后整理的投标文稿与报价编制：工作流编排

## 这个品类的数据长什么样
该品类的数据来自客户色样、配方库、染化料批次台账、染缸运行数据、测色仪输出、定形机参数及环保监测记录。数据更新节奏为每缸、每批或每班。日常文档包含染色配方、称化料记录、染缸温度曲线、打样确认单、色差报告、定形工艺单、污水排放台账。字段包含染料浓度（g/L）、染缸升温速率（℃/min）、色差值ΔE、染化料批次号、环保排放浓度（mg/L）等，随各加工环节实时生成。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据实时性强、更新频次高，要求工作流支持按加工批次实时触发执行。日常文档类型多样且结构差异明显，需为染色配方、色差报告、污水台账等不同文档配置专属的读取与解析节点。专业字段带专属单位，变量提取环节需精准匹配对应字段的命名规则。环保监测数据需同步纳入报价校验，工作流需嵌入合规性检查节点。打样放大与缸体加工的关联数据需跨环节传递，需配置节点间的参数绑定逻辑，确保数据流转准确。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定当前缸次的染料浓度（g/L）、染缸温度（℃）、色差值ΔE等实时参数 | 该品类数据随加工缸次实时生成，需同步调用最新业务数据 |
| 知识库访问权限 | 仅开放对应客户的色样库、专属配方文档 | 客户业务数据需隔离，避免跨客户信息泄露 |
| HTTP请求节点 | 设置超时时间为120秒，请求体携带当前批次的染化料批次号 | 染缸参数读取需适配设备响应耗时，批次号用于匹配对应加工数据 |
| 日志收集与管理 | 记录节点执行结果与字段值，保留7天的执行日志 | 需回溯配方放大、色差校验的异常环节，7天周期覆盖常规问题排查 |
| `nodeId` | 为染色配方解析、色差校验、报价生成节点分配唯一标识 | 不同文档需绑定专属处理逻辑，避免节点执行混淆 |
| 文档管理方式 | 按加工批次分类存储染色配方、污水台账等文档 | 该品类数据按缸次更新，分类存储便于快速检索调用 |

## 容易做错的三处
- 现象：HTTP请求节点返回400状态码，无法传递染缸曲线文件。原因：未正确配置请求头的文件传输格式，未将对应文档绑定为请求参数。
- 现象：工作流调用的`variables`参数为空，报价数据与当前加工批次不匹配。原因：未在触发节点绑定实时生成的缸次参数，错误使用未更新的全局默认变量。
- 现象：多个工作流节点执行顺序混乱，导致报价数据生成错误。原因：未为节点分配唯一`nodeId`，未配置正确的节点触发依赖关系。

## 怎么确认配好了
- 触发测试用的缸次数据，检查工作流的`variables`参数是否正确加载了当前批次的专业字段与参数。
- 查看HTTP请求节点的执行日志，确认请求体携带了正确的批次标识与文件参数。
- 核对知识库返回的匹配结果，确认仅包含当前客户的专属业务文档。
- 检查所有节点的执行状态，确认按预设顺序完成，无异常报错。
