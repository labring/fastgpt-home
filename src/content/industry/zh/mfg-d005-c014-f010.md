# 印染与后整理的投标文稿与报价编制：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自染整厂、面料企业的染色、定形、实验室与质量部门，涵盖染色配方、称化料记录、染缸曲线、打样确认、色差报告、定形工艺单、污水台账等文档。数据来源包括客户色样、配方库、染化料批次、染缸控制设备、测色仪、定形机及环保监测系统，更新频率为每缸、每批或每班，单条数据包含工艺参数、检测结果、批次编号等字段，单位涉及温度、浓度、时间、克重等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
高频次的按缸、按批更新，要求知识库检索与召回环节支持增量索引同步，避免检索到过期的染色配方或染缸参数；多类型文档混合覆盖工艺、检测、合规等维度，需要适配不同字段的解析逻辑，确保色差报告、定形工艺单等数据可被精准拆分与关联；单条数据包含温度、浓度、批次编号等带单位的字段，检索时需保留字段关联性以支撑投标文稿中的工艺说明与报价依据；环保监测与污水台账数据需与合规要求绑定，召回结果需同时匹配工艺与合规维度的查询需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.72–0.80` | 染色配方等工艺数据需要较高的匹配精度，避免低相似度的无关数据混入，FastGPT v4.17.0版本针对工艺类数据优化了匹配逻辑，此区间适配本品类需求 |
| `limit` | `前8条` | 投标文稿与报价编制需要覆盖多维度工艺参考，同时控制上下文长度，避免超出模型输入限制 |
| `searchMode` | `vector` | 结构化的工艺数据更适合向量检索，可精准关联批次编号、温度等字段，提升检索结果的关联性 |
| `usingReRank` | `开启` | 多类型文档混合时，重排可优化检索结果的排序逻辑，过滤掉低相关性的污水台账等非目标数据 |
| `datasetSearchUsingExtensionQuery` | `开启` | 投标查询常包含工艺+合规的复合需求，扩展查询可覆盖更多关联数据，提升检索全面性 |
| `collectionIds` | `按部门划分的专属集合ID` | 区分染色、定形、实验室等部门的数据，避免跨部门无关数据被召回，确保检索结果贴合当前业务场景 |

## 容易做错的三处
- 调用`pushData`接口批量上传染缸曲线、染色配方数据后，仅少量条目被成功索引。未按接口限定的单批数据量配置上传参数，超出允许的单批数据组数，导致接口未完整处理上传内容。
- 配置外网网页链接可正常提取文本，内网Confluence页面无法被解析获取内容。未配置内网访问权限或代理规则，导致检索模块无法连通内部Confluence服务器，无法拉取页面数据。
- 检索投标相关的工艺需求时，返回大量不相关的历史检测报告。将`similarity`阈值设置过低，未结合印染品类数据的精度要求调整匹配度，导致低匹配度的无关数据被召回。

## 怎么确认配好了
- 查看知识库集合的索引状态，确认所有按缸、按批更新的文档已完成增量索引同步。
- 发起一条包含染色配方关键词的测试查询，核对返回结果是否包含批次编号、温度、浓度等品类专属参数。
- 调用`pushData`接口上传单批200组测试数据，确认接口返回成功且数据可被正常检索。
- 对比开启与关闭`usingReRank`后的检索结果排序，确认重排逻辑优化了结果的相关性。
