# 原料药与医药中间体生产的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
该品类的日常文档包含批生产记录、物料平衡台账、反应与精制步骤日志、清洁验证记录、杂质谱报告、偏差与变更申请文件。数据来源涵盖注册工艺文档、原料批次台账、DCS生产控制系统、称量系统数据、LIMS实验室信息管理系统、色谱数据系统及QMS质量管理系统。数据更新频率为每生产批次、每工艺步骤触发。文档字段包含工艺参数、收率数据、杂质含量、溶剂残留量、变更审批状态等，单位涉及摩尔百分比、毫克/升、批次编号等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据多为结构化工艺记录与半结构化报告，且按批次与步骤高频更新，需保留细粒度的工艺细节以支撑投标报价的精准性。杂质谱、收率等混合了数值与文本的字段特征，要求索引支持多类型内容的关联召回。每批次的独立数据结构，需避免跨批次数据的向量混淆，同时需适配快速增量索引更新。投标文稿与报价编制需关联历史工艺合规数据，索引需精准召回特定批次的工艺参数与审批记录，因此对召回的精准度与分块的粒度有明确约束。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 该品类文档多为单步工艺描述与数值记录，800–1200字符可完整覆盖单步工艺逻辑，避免割裂关键参数 |
| 重叠长度 | 100–150 字符 | 减少连续工艺步骤被分块割裂的概率，保留跨分块的参数关联信息 |
| 最大段落深度 | 3 | 匹配业务文档三级结构的工艺步骤层级，避免跨层级的内容合并分块 |
| `defaultToken` | 4096 token | 适配主流嵌入模型的输入文本上限，满足单块工艺文档的嵌入需求 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 单次召回条数 | 前3–5条 | 精准匹配投标报价所需的特定批次工艺数据，避免过多无关内容干扰召回结果 |

## 容易做错的三处
- 点击启用嵌入模型后，填写自定义请求地址与API密钥，测试时直接报错。原因是未校验嵌入模型的请求格式与FastGPT的接口规范匹配，或密钥未开放嵌入调用权限。
- 在FastGPT的知识库设置中，未为表格类的杂质谱报告开启多向量支持，导致表格数据无法被正确索引。原因是未配置表格数据的多向量关联规则，导致表格内容被当作普通文本分块。
- 页面提示检测到没有可用的索引模型，但服务与对话Agent测试正常。原因是未在知识库设置中绑定当前使用的嵌入模型，或模型配置未同步至系统缓存。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库设置页面，确认已启用的嵌入模型与当前配置的模型一致。
- 上传一份典型的批生产记录文档，执行分块预览测试，查看分块结果是否匹配设置的分块长度与重叠长度。
- 发起一次针对特定批次工艺参数的召回测试，确认召回的内容包含目标批次的收率数据与杂质谱信息。
- 检查`defaultToken`与`maxToken`的配置值，确保其不超过当前使用嵌入模型的输入上限。
