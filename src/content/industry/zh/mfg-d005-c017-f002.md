# 喷涂与涂装的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
本品类数据覆盖汽车、家电、工程机械、金属家具的涂装线相关业务。日常文档包含涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账。数据来源包括涂料供应商TDS/SDS文件、喷房与烘炉实时采集数据、色差仪、膜厚仪、环境监测设备及MES系统。数据更新节奏为每批涂料、每班生成新记录，部分监测数据连续采集。

## 这些特征在「向量模型与索引」这一环带来什么约束
多类型文档混合带来的文本结构差异，要求索引同时适配结构化字段与非结构化文本，支持统一索引存储多类涂装业务数据。高频更新的涂料批次、每班记录及连续采集的设备数据，要求索引支持增量更新，不执行全量重建。涂装相关字段包含膜厚、色差、VOC浓度等带单位的专业参数，向量模型需能准确理解这类带量化信息的文本，支持国产开源向量模型适配。投标场景需快速匹配工艺窗口与报价依据，索引召回的结果需覆盖关键业务字段，避免遗漏核心参数。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配涂装工艺卡、烘炉曲线等长文本的语义完整性，避免切割关键工艺参数 |
| `maxToken` | 4096 token | 匹配多数开源向量模型的输入上限，容纳单块涂装文档的完整语义，适配国产模型的token要求 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 过滤低匹配度的涂料批次或工艺记录，适配涂装业务的专业语义差异 |
| 单次搜索上限 | 前 10 条 | 控制返回结果的数量，避免投标文稿编制时冗余信息过多 |
| `defaultToken` | 按文档实际长度调整 | 适配不同类型文档的分词需求，确保调漆记录、VOCs台账等短文本的语义完整 |
| 最大上下文 | 8000 字符 | 整合多份相关文档的信息，支撑投标报价的多维度依据匹配 |

## 容易做错的三处
- 现象：检索结果中出现大量不相关的涂料批次记录，返回结果的匹配度低于预设阈值但未被过滤。原因：未针对涂装专业语义调整相似度阈值，使用通用阈值导致无效匹配。
- 现象：通过外部系统如MongoDB新增涂料批次记录后，检索无法召回。原因：未配置向量库与外部系统的同步机制，仅依赖FastGPT内置的索引流程。
- 现象：调用向量模型时返回400错误，提示输入token超出限制。原因：未设置合理的`maxToken`参数，将过长的烘炉曲线文本直接传入模型，未适配模型的token上限。

## 怎么确认配好了
- 上传一份完整的涂装工艺卡，检查分块后的文本是否保留完整的工艺参数与单位，无截断情况。
- 发起针对“某批次环氧涂料的喷涂工艺要求”的检索，核对返回结果的数量与匹配度符合预设阈值。
- 新增一条测试用的调漆记录，检查索引是否自动完成增量更新，检索时可正常召回该记录。
- 调用`defaultToken`参数关联的分词工具，验证短文本如VOCs台账条目可被完整分词。
