# 喷涂与涂装的投标文稿与报价编制：工具调用与插件

## 这个品类的数据长什么样
本品类数据覆盖汽车、家电、工程机械等涂装线场景，日常文档包含涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账。数据来源于涂料供应商TDS/SDS、喷房与烘炉采集数据、色差仪、膜厚仪、环境监测设备及MES系统，更新节奏为每批涂料、每班及连续采集模式，核心字段包含涂料黏度参数、膜厚数值、烘炉温度曲线、VOCs排放数据等。

## 这些特征在「工具调用与插件」这一环带来什么约束
涂装品类的文档多为带实测参数的工艺类文件，且数据更新频率高，工具调用需频繁拉取最新的涂料批次、烘炉曲线等数据。不同批次涂料的参数差异要求工具调用时需精准匹配当前项目的涂料TDS数据，避免调用过时的历史数据。连续采集的环境与设备数据需按时间范围筛选，工具调用的上下文需限定在当前投标项目的周期内，防止混入其他批次的无效数据。同时，VOCs台账的合规性数据需同步校验，工具调用需关联合规数据源，避免生成不符合要求的投标内容。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，具体参数设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | 设为`auto`并绑定涂装专用工具集合 | 依据投标场景需调用涂料参数、设备数据等专用工具，自动选择匹配的工具提升调用准确率 |
| `functionCall` | 开启强制工具调用模式 | 依据需严格按业务数据生成报价，避免模型自由生成不符合涂装工艺的内容 |
| 单次工具调用上限 | 前3次 | 依据涂装数据更新频繁，限制调用次数避免加载过时的多批次数据 |
| 工具调用超时时间 | 600 秒 | 依据烘炉曲线、膜厚数据等采集的等待周期，确保获取完整的业务数据 |
| 最大上下文长度 | 1200–1500 字符 | 依据单份投标文稿的核心参数篇幅，避免上下文过长导致工具调用超时 |
| 历史对话保留轮次 | 2轮 | 依据投标项目的单次调用逻辑，避免保留过多历史数据干扰当前工具调用的参数匹配 |

## 容易做错的三处
- 现象：工具调用返回报错，提示无法匹配指定数据。原因：未配置按当前投标项目的涂料批次筛选数据的参数，调用了全量历史数据导致匹配失败。
- 现象：工具调用输出无思考过程内容。原因：开启了`functionCall`但未同时配置输出思考的开关，导致工具调用仅返回结果未生成中间逻辑说明。
- 现象：多次调用后出现历史数据混杂。原因：未限定对话保留轮次，导致前序项目的涂装数据被带入当前调用，干扰参数匹配。

## 怎么确认配好了
- 触发工具调用后，检查返回的涂料参数是否与当前投标项目的涂料批次单一致。
- 查看工具调用日志，确认已调用的工具集合包含涂装工艺、VOCs台账等相关数据源。
- 模拟多次调用，确认每次调用的上下文仅保留当前项目的相关数据，无历史项目的冗余信息。
- 验证工具调用超时设置，在采集烘炉曲线数据时，等待时间不超过配置的阈值。
