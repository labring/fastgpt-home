# 喷涂与涂装的投标文稿与报价编制：知识库检索与召回

## 这个品类的数据长什么样
这个品类的核心数据来自涂料供应商TDS/SDS文档、喷房与烘炉运行数据、色差仪/膜厚仪采集的检测数据、环境监测记录以及车间MES系统。日常文档包含涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账。数据更新按涂料批次、生产班次触发，部分设备数据连续采集，字段包含涂料批次号、黏度参数、膜厚数值、烘炉温度节点、VOCs排放浓度、缺陷类型与修复方案等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据更新频率不均，部分设备数据连续生成，需支持增量式召回以避免加载冗余历史数据。文档类型多样，包含结构化检测数值与非结构化工艺步骤，需兼顾两类内容的检索匹配精度。字段多涉及生产合规与质量参数，检索结果需优先匹配当前批次的涂料、设备运行参数，同时覆盖VOCs合规要求。投标文稿与报价编制需精准关联工艺、成本与合规要求，检索范围需限定在涂装专属文档，避免混入其他品类的无关数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配涂装工艺参数、涂料批次信息时，需保证召回结果与查询的语义重合度达标，避免无关的缺陷返修记录混入 |
| `limit` | 前10条 | 投标报价需要兼顾全面性与可读性，过多结果会增加文稿编制负担，过少则可能遗漏关键工艺参数 |
| `searchMode` | `mixedRecall` | 喷涂涂装的文档包含结构化数据（如膜厚数值）与非结构化文本（如工艺卡步骤），混合检索可同时覆盖两类内容 |
| `usingReRank` | 开启 | 涂装相关的检索结果存在相似参数易混淆的情况，重排可修正初始召回的排序偏差 |
| `datasetSearchUsingExtensionQuery` | 开启 | 投标查询常包含复合需求，如「某批次涂料的喷涂工艺+VOCs要求」，扩展查询可补充隐含的关联参数 |
| `collectionIds` | 按绑定的涂装专属知识库ID填写 | 避免召回其他品类的文档，保证检索范围精准 |

## 容易做错的三处
- 现象：知识库搜索响应超时，日志显示向量检索耗时超过30秒。原因：未针对涂装类高频更新的批次数据配置增量同步，全量检索时加载了过多历史文档。
- 现象：开启`usingReRank`后排序无变化，返回结果与初始召回顺序一致。原因：未配置重排模型的调用密钥或配额不足，系统自动跳过了重排环节。
- 现象：检索结果中VOCs台账条目排在工艺参数之前，不符合业务优先级。原因：未调整`similarity`阈值或未开启重排，初始召回的语义匹配权重分配不合理。

## 怎么确认配好了
- 上传一份最新的涂料批次单与调漆记录，发起包含「该批次涂料的喷涂工艺参数」的查询，核对召回结果是否包含对应文档的核心字段。
- 查看检索日志，确认`usingReRank`的调用记录存在，且返回结果的排序与初始召回结果存在差异。
- 测试不同查询词，如「膜厚不合格的返修方案」「烘炉曲线参数」，核对召回结果是否覆盖对应品类的专属文档。
- 验证FastGPT版本为v4.17.0，确认当前配置的参数在该版本中支持生效。
