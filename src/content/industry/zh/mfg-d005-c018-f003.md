# 基础化工连续生产的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
基础化工连续生产品类的数据来源包括DCS/SIS系统、在线分析仪、LIMS实验室管理系统、设备状态监测模块、能源计量节点与原料储罐传感器。数据更新节奏覆盖实时、每班、每日三类。日常文档包含操作规程、工艺指标卡、DCS趋势图、化验报告、联锁旁路记录、特殊作业票与班报，字段多带标准化单位，如工艺温度为摄氏度、物料流量为立方米每小时、压力为兆帕。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
实时更新的DCS数据与按周期生成的班报、化验报告，要求多轮对话上下文需支持按更新时间筛选关联文档，避免调用过期数据。多类业务文档的差异化结构，要求提示词需明确指定不同文档的字段提取规则，例如从联锁旁路记录中提取隔离介质与操作时限。强联锁控制的业务特性，要求多轮对话中需保留历史校验逻辑，防止遗漏关键联锁条件。不同数据源的更新频率差异，要求`variables`参数可动态绑定最新数据源标识，确保调用数据的时效性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定DCS实时数据、班报的最新时间戳 | 匹配实时、每班、每日的更新节奏，确保调用数据的时效性 |
| `messages` | 保留最近10轮对话上下文 | 覆盖多轮核对联锁条件、调整报价参数的业务流程，避免关键上下文丢失 |
| `chatId` | 绑定当前投标项目的唯一标识 | 区分不同投标项目的对话上下文，避免数据混淆 |
| 单次搜索上限 | 前8条 | 匹配单份投标文稿需关联的工艺文档数量，过滤冗余信息 |
| 最大上下文 | 8000–12000 token | 适配多类业务文档的总字符量，满足完整工艺逻辑的对话需求 |
| 超时时间 | 600 秒 | 匹配实时数据的查询响应要求，避免长时间等待 |
| 问题优化 | 按实测标定 | 适配基础化工专业术语的表达习惯，优化对话理解精度 |

## 容易做错的三处
- 现象：镜像打包部署后，上传的工艺文档无法被对话识别，无报错提示。原因：部署时未正确配置`variables`绑定的文件路径映射，导致系统无法访问本地存储的文档资源。
- 现象：对话中调用`variables`绑定的实时DCS数据时，返回的字段与实际工艺参数不符。原因：未指定数据的更新时间戳过滤规则，导致调用了过期的历史数据。
- 现象：多轮核对联锁条件后，后续报价参数未关联前期的隔离要求。原因：未配置`messages`参数保留完整对话上下文，丢失了关键的联锁校验信息。

## 怎么确认配好了
- 调用`variables`绑定的数据源接口，检查返回的时间戳与当前系统时间的匹配度，确认数据时效性。
- 上传一份典型的工艺指标卡，触发对话查询，检查返回的文档内容与上传文件的匹配度，确认上下文调用逻辑正常。
- 模拟多轮对话，依次提交联锁校验、报价调整的问题，检查系统是否保留了前期的关键信息，确认`messages`参数配置生效。
- 查看对话日志，确认`chatId`绑定的投标项目标识未出现混淆，各配置项参数均被正确加载。
