# 基础化工连续生产的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
基础化工连续生产品类的核心数据来自DCS/SIS系统、在线分析仪、LIMS实验室管理系统、设备状态监测模块、能源计量系统及原料储罐数据接口。数据更新节奏覆盖实时、每班、每日三个层级。日常关联文档包含操作规程、工艺指标卡、DCS趋势图、化验报告、联锁旁路记录、特殊作业票、班组运行班报。数据字段对应工艺控制参数、计量数值、设备状态及作业审批信息，无额外非业务必需的自定义字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的实时性数据要求模型接入环节需支持高频数据拉取，因此配置需适配短周期上下文更新。多类型工艺文档的结构化差异，要求模型配置需兼容不同格式的文档拆分与关联。强联锁控制与危险介质特性，要求模型输出的投标与报价内容需严格匹配工艺参数，不可出现偏差。数据来源分散的特点，要求配置环节需明确各数据模块的调用优先级，避免无关数据干扰生成结果。同时，投标与报价文档的合规性要求，需确保模型调用的所有数据均来自官方授权的系统接口。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 覆盖实时DCS数据、当班班报及近7日工艺指标卡的总内容量，确保生成内容可关联最新工艺参数 |
| `maxTokens` | `4000–6000 token` | 适配单份投标文稿或报价表的完整输出长度，避免内容被截断 |
| `quoteMaxToken` | `1500–2500 token` | 限定报价明细的输出长度，确保核心参数清晰展示 |
| `temperature` | `0.1–0.3` | 匹配基础化工场景的严谨性要求，降低生成内容的随机性，避免工艺参数出现偏差 |
| `toolChoice` | `auto` | 自动调用关联的工艺数据接口，确保生成内容可引用实时的原料储罐、能源计量数据 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的模型服务地址填写，如`http://localhost:11434/v1` | 对接大模型服务，适配基础化工场景的隐私数据保护要求 |
| `AIPROXY_API_TOKEN` | 按实际申请的密钥填写 | 用于验证模型服务的访问权限，确保配置合法有效 |

本文适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 界面显示未捕获异常，调用本地模型时无响应。原因是未正确配置`AIPROXY_API_ENDPOINT`指向本地模型的服务地址，且未验证`AIPROXY_API_TOKEN`的有效性。
- 生成的投标文稿中仍包含`<think>`标签内容。原因是未将`temperature`设置为符合严谨场景的低区间，且未关闭模型原生的思考输出配置。
- 生成的报价数据与实际原料储罐计量值不符。原因是未将`maxContext`配置为包含实时储罐数据的范围，导致模型调用过时的历史数据。

## 怎么确认配好了
- 调用FastGPT内置的模型测试接口，检查返回的响应状态码为200，且无未捕获异常日志。
- 生成一段测试用的投标文稿片段，检查输出内容中无`<think>`标签。
- 导入一组实际的工艺指标卡与储罐计量数据，检查生成的报价数据与导入的计量值匹配。
- 查看模型接入的配置面板，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`已正确填写。
