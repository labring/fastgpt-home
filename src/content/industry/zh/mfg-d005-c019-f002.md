# 塑料注塑成型的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来源包括树脂批次物性表、注塑机运行参数、模温机记录、MES系统数据、尺寸与外观检测表单。日常文档涵盖注塑工艺卡、原料干燥记录、模具履历、首件检验报告、巡检表、换料清机记录。数据更新节奏为每生产批次、每次换模换料、每班结束后更新。文档字段包含树脂牌号、干燥温度、保压压力、模腔温度、检测尺寸公差、回料比例等，多为半结构化的工艺与生产记录。

## 这些特征在「向量模型与索引」这一环带来什么约束
半结构化的工艺与生产记录需要保留字段关联，切分时不能破坏参数与对应记录的绑定关系；高频更新的生产数据要求索引支持增量更新，避免全量重建的耗时；树脂牌号、工艺参数等工业字段的语义差异需要更精准的向量匹配，避免通用模型的语义误判；投标场景下需关联历史工艺与报价数据，索引需支持多文档块的关联检索，不能仅按单块文本匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配注塑工艺卡的单段参数描述长度，避免切割关键工艺参数 |
| 重叠长度 | 100–150 字符 | 保留换料清机记录的前后关联字段，防止切分后丢失回料比例与模具状态的关联 |
| 相似度阈值 | 0.7–0.9 | 区分不同树脂牌号的物性差异，避免误匹配相似但不同的原料参数 |
| 单次搜索上限 | 前 10 条 | 匹配投标所需的历史工艺与报价数据量，平衡检索效率与召回完整性 |
| `maxToken` | 4096 | 适配工业文档的长文本拼接，避免超出模型上下文限制 |
| `defaultToken` | 256 | 适配单块注塑工艺记录的基础嵌入请求长度 |
| 最大上下文 | 8000 token | 容纳多份注塑工艺卡与报价单的关联数据，支撑投标文稿的参数引用 |

## 容易做错的三处
- 自定义切分的文档块导入后顺序错乱。现象为检索结果的文档块顺序与自定义切分的顺序不一致。原因是系统默认开启全局去重逻辑，删除了重复块的同时打乱了自定义切分的块顺序。
- 向量模型调用走LLM通道。现象为检索结果不符合语义匹配要求，或返回报错信息。原因是自定义渠道配置时未将向量模型绑定到知识库索引环节，误将LLM渠道作为向量入口。
- 批量导入数据时索引速度过慢。现象为导入多份注塑机参数记录时出现超时。原因是未配置增量索引更新，每次导入都执行全量索引重建。

## 怎么确认配好了
- 导入单份注塑工艺卡，检查切分后的块数与自定义切分的块数一致，无自动去重导致的块丢失。
- 发起针对树脂牌号或工艺参数的检索请求，查看返回的相似度数值在0-1区间内，符合设置的阈值范围。
- 批量导入多份换料清机记录，检查索引更新耗时符合预期，未出现超时报错。
- 确认FastGPT v4.17.0版本下的向量模型渠道配置，检查请求参数未关联到LLM通道。
