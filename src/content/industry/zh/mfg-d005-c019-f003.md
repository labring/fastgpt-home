# 塑料注塑成型的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来自树脂批次与物性表、注塑机参数、模温机、生产执行系统（MES）及尺寸外观检测设备。企业日常留存的文档包含注塑工艺卡、原料干燥记录、模具履历、首件检验报告、巡检表、换料清机记录。数据更新节奏为每生产批次、每次换模换料操作、每班结束时同步更新。数据字段包含原料牌号、干燥温度与时长、注塑机螺杆转速、保压压力、模腔温度、塑件尺寸公差等，单位涵盖摄氏度、兆帕、转每分钟、毫米等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据更新频率高且来源分散，要求多轮对话需实时关联最新的生产数据，避免调用过期的工艺或设备记录。日常文档字段多且专业，提示词需明确指定需调取的文档类型与对应字段，例如原料干燥记录的回料比例、注塑工艺卡的充填保压参数。投标报价需整合跨源数据核算成本，多轮对话需逐步引导明确投标项目的塑件类型、批量，再关联对应模具履历与原料物性数据，避免遗漏关键的成本核算维度。同时需限制对话上下文的有效范围，防止调用与当前投标项目无关的历史批次数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 与当前投标项目绑定的唯一标识 | 确保同项目的多轮对话上下文连贯，避免跨项目数据混淆 |
| `messages` | 保留前18轮对话内容 | 覆盖单次投标项目的完整沟通流程，防止关键上下文被截断 |
| `variables` | 预设树脂牌号、注塑机型号、模具编号三类变量 | 快速调取对应品类的专属生产数据，减少重复输入步骤 |
| 最大上下文窗口 | 前12000 token | 适配塑料注塑成型的多维度数据量，平衡上下文完整性与响应速度 |
| 对话日志保留时长 | 180 天 | 满足投标项目的追溯需求，匹配生产数据的常规留存周期 |
| 数据召回上限 | 前7条最新生产记录 | 避免冗余数据干扰对话聚焦，聚焦当前投标项目的有效核算依据 |

## 容易做错的三处
- 现象：提示词无法正确识别原料牌号中的空格，导致无法调取对应树脂物性表数据。原因：提示词未明确指定字段需保留空格，未对特殊格式的字段做格式说明。
- 现象：通过API发布渠道调用应用时，多轮对话无法延续，每次请求均为新对话。原因：未在API请求中携带`chatId`参数，无法关联历史对话上下文。
- 现象：部分历史对话日志无法查看，界面显示为空或报错。原因：docker配置未正确挂载日志存储卷，或对话日志留存规则未匹配业务需求。

## 怎么确认配好了
- 发起模拟投标对话，输入目标塑件类型与生产批量，核对系统是否自动关联预设的专属变量，调取对应品类的生产数据。
- 发起两次连续的对话请求，使用相同的`chatId`，核对上下文是否连贯，未出现重复要求输入相同信息的情况。
- 检查系统配置，确认对话日志的留存规则与业务追溯需求匹配，可正常查询历史对话记录。
- 验证提示词引导流程，核对生成的投标文稿是否包含注塑工艺参数、原料成本核算等专属品类的核心内容。
