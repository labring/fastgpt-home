# 塑料注塑成型的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
该品类数据覆盖注塑件生产全流程，日常文档包含注塑工艺卡、原料干燥记录、模具履历、首件检验、巡检表、换料清机记录。数据来源包括树脂批次与物性表、注塑机参数、模温机、MES系统、尺寸与外观检测结果。数据更新随生产批次、换模换料操作及每班生产节奏触发，不同文档对应注塑参数、原料指标、模具状态、检测结果等字段，单位涵盖温度、压力、时间、重量等注塑行业标准单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据更新频率随生产批次、换模换料及每班触发，要求模型接入配置支持实时或近实时数据同步，避免使用过期生产参数。多类文档的字段差异要求配置中明确不同数据源的字段映射规则，防止参数混淆。注塑行业对原料干燥、回料比例等参数精度要求高，模型调用需保留原始数据的单位与精度，不可随意转换。不同生产环节的检测数据需关联对应批次，配置中需支持按批次维度关联文档内容，提升投标文稿与报价的准确性。FastGPT v4.17.0版本的配置逻辑适配该类多源数据的关联需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 需容纳多批次注塑工艺、模具履历等多文档内容，避免上下文截断 |
| `maxTokens` | `4000–6000 token` | 投标文稿与报价编制需生成完整参数说明与报价明细，控制生成长度避免冗余 |
| `quoteMaxToken` | `1500–2000 token` | 需引用注塑工艺卡、原料物性表等长文档片段，保留足够引用内容的完整性 |
| `temperature` | `0.2–0.4` | 投标文稿需严谨准确，降低随机性，确保参数与生产数据一致 |
| `AIPROXY_API_ENDPOINT` | 按部署实际填写 | 适配不同环境的代理地址，确保模型调用通路正常 |
| `AIPROXY_API_TOKEN` | 按授权密钥填写 | 完成代理通道的身份验证，保障调用权限 |

## 容易做错的三处
- 现象：调用时返回code500 Cannot read p，原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，导致代理通道身份验证或地址解析失败。
- 现象：模型测试返回400错误，原因：`maxContext`取值超出模型支持的上下文上限，或未匹配注塑数据的字段映射规则导致参数格式异常。
- 现象：添加指定模型渠道测试返回404 page not found，原因：`AIPROXY_API_ENDPOINT`指向的代理服务未部署对应模型接口，或渠道配置的模型标识与代理服务不匹配。

## 怎么确认配好了
- 执行代理接口的基础测试，确认返回结果符合预期，调整`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`至测试通过。
- 导入单份注塑工艺卡与原料物性表，测试模型调用，确认生成内容包含正确的参数字段与单位，调整`temperature`至符合严谨性要求的区间。
- 导入多批次生产数据，测试上下文加载，确认`maxContext`取值未触发上下文截断，调整取值至覆盖所有导入文档的总token数。
- 模拟投标文稿生成流程，确认引用的注塑检测数据与模具履历准确关联，调整`quoteMaxToken`至覆盖所需引用片段的长度。
