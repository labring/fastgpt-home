# 安全环保与特殊作业管理的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
该品类的典型文档包括风险辨识清单、动火/受限空间/吊装等作业票、环境监测记录、危废台账、排放监测数据、事故与隐患整改报告。数据来源涵盖行业法规标准、在线环保监测系统、气体检测仪、作业人员资质文件、设备隔离清单及监管平台。数据随单次作业完成实时提交，或按监测周期定期上传，部分合规记录需留存备查。文档包含作业编号、检测数值、资质有效期、隔离状态等带单位的结构化字段，以及作业流程描述等非结构化文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据更新频率高且类型多样，要求索引系统支持增量更新与多类型文档的混合向量化。结构化字段（如检测数值、资质有效期）需与文本内容绑定索引，避免拆分后丢失业务关联。敏感的安全环保数据需保障向量化过程的本地部署兼容性，防止数据外泄。长文本的事故整改报告与投标整合文稿，要求向量模型支持足够的输入token上限，同时分块策略需保留跨作业的流程上下文，防止风险辨识逻辑断裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配作业票、监测记录等单篇文档的平均长度，避免拆分破坏业务逻辑 |
| 重叠长度 | 100–200 字符 | 保留跨分块的作业流程上下文，防止风险辨识逻辑断裂 |
| `defaultToken` | 4096 token | 适配Qwen3-Embedding-8B的输入上限，保障长文本风险报告的完整向量化 |
| `maxToken` | 8192 token | 满足投标文稿中整合多份作业票与法规的长文本需求 |
| 相似度阈值 | 0.75–0.85 | 区分作业票的合规性差异，避免误判风险等级 |
| 单次搜索上限 | 前10条 | 覆盖投标所需的典型作业合规依据，控制检索成本 |

## 容易做错的三处
- 现象：配置Qwen3-Embedding-8B后再次添加同名模型，原有配置被覆盖且无法恢复。原因：FastGPT系统默认仅允许单个embedding模型处于启用状态，未提供多模型并行配置的切换选项。
- 现象：本地部署M3E模型后，FastGPT无法加载索引数据，界面显示连接超时。原因：未正确配置模型本地端口与FastGPT的环境变量映射，导致服务无法建立正常通信。
- 现象：检索投标相关的合规依据时，仅返回作业票文档，未包含危废台账或监测记录。原因：分块长度设置过大，导致危废台账的时序数据被合并为单个分块，未被索引系统完整识别与存储。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型配置页面，确认目标embedding模型已启用且无重复配置条目。
- 上传单份动火作业票文档，触发向量化任务，查看后台日志确认分块参数与token计数符合预设值。
- 输入投标相关的风险辨识查询，检索结果包含作业票、监测记录等对应品类的文档类型。
- 测试增量更新功能，上传新的受限空间作业票，确认索引库自动新增对应分块数据。
