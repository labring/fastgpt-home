# 安全环保与特殊作业管理的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据来自制造企业EHS部门与检维修团队的日常工作产出及监管对接系统，包含风险辨识清单、动火/受限空间/吊装等作业票、危废台账、排放监测记录、事故与隐患整改报告等文档。数据字段涵盖作业类型、作业时间、监护人员资质、设备隔离状态、污染物排放数值、隐患整改闭环状态等，单位涉及作业时长、气体浓度、排放浓度值、整改周期等。数据更新随单次作业完成、实时监测上传或定期检查推进。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类数据来源分散且关联紧密，多轮对话需关联作业票、人员资质、监测数据等跨文档信息，无法割裂上下文单独提问。数据更新频率动态且无固定周期，提示词需支持动态加载最新的作业或监测数据，确保投标文稿与报价的时效性。文档字段多且附带专属单位，提示词需明确字段提取规则，避免混淆不同作业类型的参数。投标场景需整合多类作业的合规信息，多轮对话需逐步引导补充缺失的作业项、资质信息，同时关联历史合规数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 前12000 token | 适配作业票、监测记录等多文档拼接的上下文长度，避免超出大模型窗口限制 |
| `variables` 变量绑定 | 绑定作业类型、危废类别、排放限值等预设字段 | 确保多轮对话中自动带入EHS相关业务字段，减少重复输入 |
| 问题优化 | 按作业场景拆分提问 | 针对动火、受限空间等不同作业类型优化提示词结构，聚焦对应作业票的风险与资质校验 |
| `messages` 历史消息截断 | 保留最近30条对话消息 | 过滤冗余历史，避免长上下文导致的响应延迟 |
| 单次召回上限 | 前8条匹配文档 | 匹配作业相关的风险辨识、资质清单等数据，平衡召回精度与响应速度 |
| `chatId` 会话隔离 | 按作业项目绑定会话ID | 确保不同投标项目的对话上下文互不干扰，避免数据混淆 |

## 容易做错的三处
- 对话响应超时，界面显示请求超时状态码。原因是未限制上下文长度，绑定了过多历史作业文档与监测数据，导致大模型处理负载过高。
- 调用图表工具后输出空白图片。原因是提示词未明确要求绑定作业对应的排放监测数值、危废台账数据，工具无法获取有效参数生成图表。
- 大模型返回empty或报错后直接返回前端空字段。原因是未配置异常处理逻辑，未对`chatId`关联的对话异常状态做捕获与提示。

## 怎么确认配好了
- 发起包含作业类型、资质信息的多轮对话，核对对话中自动带入的预设业务变量是否符合当前项目要求。
- 测试长上下文输入，观察响应时间是否符合预期，确认未出现超时错误。
- 触发异常输入场景，确认系统会捕获大模型返回的empty或报错状态并给出对应提示。
- 调用图表工具，核对生成的图表是否关联了当前作业对应的监测数据与合规限值。
