# 家具与木制品制造的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
通常服务于板式家具、实木家具、定制家居和木门企业，日常产生的文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺、五金清单、试装与包装记录。数据主要来自订单设计系统、板材和木材批次台账、数控开料与钻孔设备、ERP/MES系统、含水率检测设备。数据更新频率通常为每订单、每日或每批材料，部分字段包含具体尺寸、批次号、工艺参数等明确单位的信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的文档兼具结构化清单、半结构化工艺说明与图纸类非结构化数据，向量索引需同时适配不同格式的内容。高频更新的板材批次与订单数据要求索引支持增量更新，避免全量重建带来的额外耗时。板件数量多且关联字段复杂，分块处理时需避免跨订单的内容混杂，同时需保证尺寸、五金型号等关键字段的向量语义准确。投标文稿需关联具体订单的生产数据，索引需支持多文档间的字段关联检索，提升匹配精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 该品类的拆单清单与工艺文档通常单段内容长度适中，此区间可保证向量语义完整且避免分块过大 |
| 重叠长度 | 100–150 字符 | 可保留相邻分块的上下文关联，避免关键信息被分割在两个分块中 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关文档，保证投标文稿检索的相关性 |
| 单次搜索上限 | 前 20 条 | 该品类的生产数据条目较多，限制返回条数可提升检索效率 |
| maxToken | 8192 token | 适配长文档的投标文稿与拆单图集，保证完整的上下文输入 |
| defaultToken | 256 token | 平衡短文本的向量生成效率与语义完整性 |

## 容易做错的三处
- 现象：索引任务长时间处于待处理或运行中状态，无进度更新。原因：单批次导入的拆单清单、工艺文档数量过多，未拆分批次导致索引队列阻塞。
- 现象：调用嵌入模型时提示模型未找到或无法加载。原因：未在FastGPT v4.17.0的模型配置中正确加载阿里-emb3的开源适配包，或配置路径错误。
- 现象：检索返回的投标文稿片段不完整，关键尺寸或工艺参数缺失。原因：未根据文稿的实际token长度调整`maxToken`取值，导致长文档被截断。

## 怎么确认配好了
- 查看FastGPT v4.17.0的索引任务日志，确认单批次导入的文档数量未超过配置的单次处理上限，无队列超时报错。
- 测试检索包含特定五金型号的投标文稿，确认返回结果的字段匹配度符合业务预期，无大量不相关数据。
- 验证`defaultToken`的取值，确认短文本的向量生成无语义缺失，分块后的内容连贯。
- 检查增强索引的配置开关，确认已关联拆单数据与报价数据的字段关联，提升检索精度。
