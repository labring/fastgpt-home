# 家具与木制品制造的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
家具与木制品制造的投标相关数据多来自订单设计系统、板材与木材批次台账、数控开料/钻孔设备日志、ERP/MES系统及含水率检测记录。数据更新节奏随订单、每日或每批材料调整，核心文档包含定制拆单图、开料清单、封边与钻孔程序、涂装工艺规范、五金物料清单、试装及包装记录。数据字段包含板件尺寸参数、板材含水率、五金型号与用量、生产工序要求等，无统一固定格式，随定制订单个性化调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类数据分散且个性化程度高，多轮对话需要逐步拉取不同来源的拆单图、五金清单等信息，因此需通过`chatId`绑定单订单会话上下文，避免跨订单数据混淆。数据更新频率高，每次投标对应的板件参数、物料清单均有变化，提示词需每次调用时加载最新的`variables`参数传递定制化业务数据。板件数量多且与现场安装尺寸强关联，多轮对话中需反复核对孔位、尺寸与工艺要求，因此需保留完整的`messages`历史对话记录，确保每一轮提示词都能承接前序核对结果。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 随每笔订单生成唯一标识 | 绑定单定制订单的所有对话与数据，避免跨订单混淆 |
| `messages` | 保留前5条对话内容 | 承接前序核对的板件尺寸、五金参数等信息 |
| `variables` | 传入当前订单的拆单图、五金清单数据 | 加载本次投标所需的个性化业务数据 |
| 上下文保留时长 | 300–600 秒 | 匹配单份投标文稿的编制周期，避免过期数据干扰 |
| 表单渲染规则 | 按家具品类字段映射 | 确保拆单数据、工艺要求在对话界面正常展示 |

## 容易做错的三处
- 调用API时未正确传递`chatId`，导致后台日志显示会话关联失败，对话上下文丢失。原因是未将`chatId`作为请求必填参数携带，或参数格式不符合平台要求。
- 表单节点未按家具品类字段映射，导致对话界面显示的板件尺寸、五金清单出现格式错乱。原因是未针对定制家具的个性化数据结构调整表单渲染规则。
- 免登录链接用户删除对话后后台日志同步删除，导致历史投标数据无法追溯。原因是未配置会话数据持久化存储规则，默认删除逻辑同步清理了日志记录。

## 怎么确认配好了
- 发起测试对话，携带`chatId`参数，检查后台日志是否正确关联对应会话标识。
- 提交包含板件尺寸、五金清单的测试数据，确认对话输出的报价参数与输入数据一致。
- 生成免登录测试链接，删除对话后检查后台日志是否保留会话记录。
- 发起两轮以上测试对话，确认第二轮对话能正确承接第一轮的板件核对结果。
