# 家具与木制品制造的投标文稿与报价编制：工具调用与插件
本文基于FastGPT v4.17.0版本编写，面向家具与木制品制造企业的技术落地工程师，针对投标文稿与报价编制环节的工具调用与插件配置展开说明。

## 这个品类的数据长什么样
该品类的数据主要来自订单设计系统、板材与木材批次台账、数控开料钻孔设备、ERP/MES系统及含水率检测设备。日常文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金物料清单、试装与包装记录。数据更新节奏随订单生成、每日物料盘点及每批材料检测同步，字段涵盖板件尺寸、板材含水率、五金型号、生产批次等，单位多为毫米、百分比、件数。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类定制订单驱动、板件数量多且现场空间尺寸直接影响生产的特征，要求工具调用需精准匹配订单设计与现场安装数据。多类异构文档（拆单图、工艺文件等）需插件统一提取结构化字段，避免人工整理的误差。高频更新的物料与生产数据要求插件调用时实时拉取最新台账，防止使用过期板材批次或五金型号。板件尺寸与现场安装的强关联，要求工具调用返回的报价与文稿需同步关联对应拆单数据，避免出现尺寸不符的报价项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` 或绑定「家具拆单数据提取」插件 | 自动匹配适配该品类的插件，或指定绑定专属数据提取工具 |
| `functionCall` | `enabled` | 强制启用结构化工具调用，确保报价字段可自动写入投标文稿模板 |
| 全局变量传入 | 绑定订单ID与板材批次ID | 关联实时ERP与MES数据，避免使用过期物料信息 |
| 工具调用超时设置 | `300 秒` | 等待数控设备数据拉取与拆单解析完成 |
| 单次工具调用返回条数 | `前3条` | 聚焦当前订单的核心板件与五金数据 |
| 问题优化 | 按实测标定 | 适配家具投标场景的专业术语修正 |

## 容易做错的三处
- 插件名称显示不一致：系统插件列表显示代码中定义的内部名称，前端页面显示创建时填写的展示名称，未提前核对会导致调用时匹配错误。
- 工具调用返回结果附加冗余字符：调试时出现非预期的`0`字符，多因插件返回的结构化数据未正确格式化，被模型额外拼接。
- 指定回复被工具调用覆盖：设置了固定回复内容后，工具仍自动触发AI生成回答，未关闭默认的自动回复开关，导致内容冲突。

## 怎么确认配好了
- 触发工具调用，检查返回的结构化数据是否包含当前订单的板件尺寸、五金型号等核心字段。
- 对比系统插件列表与前端展示的插件名称，确认调用的插件与预期一致。
- 模拟投标文稿生成流程，验证工具调用返回的数据是否自动填入对应模板位置。
- 触发超时测试，确认工具调用在`300 秒`内完成返回，无异常中断。
