# 家具与木制品制造的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
该品类以板式家具、实木家具、定制家居及木门生产企业为典型主体，数据来自订单设计系统、板材与木材批次台账、数控开料钻孔设备、ERP/MES系统及含水率检测设备。日常文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金物料清单、试装与包装记录。数据更新随订单生成、每日生产进度及每批次材料进场同步调整，字段包含板件尺寸、材质色号、五金型号、含水率参数等，单位多为毫米、立方米、千克。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类以定制订单为核心驱动，最耗时的拆单环节会产生大量板件关联数据，要求模型接入时需适配多源异构数据，包括结构化的板件尺寸参数与非结构化的工艺文件。高频次的订单、生产及材料数据更新，要求配置环节预留灵活的数据同步适配接口。板件数量多且关联关系复杂，需确保模型上下文能承载足够的关联信息，避免截断关键生产参数。同时，品类特有的含水率、孔位匹配等专业字段，要求配置时明确识别规则，防止模型混淆非标准字段与通用参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配多板件拆单数据与关联工艺文档的总长度，避免关键信息截断 |
| `maxTokens` | 3000–4000 token | 匹配投标文稿与报价单的输出长度需求，确保完整呈现报价明细与方案说明 |
| `quoteMaxToken` | 1500 token | 限制引用内容的token占用，平衡回答完整性与上下文承载能力 |
| `temperature` | 0.3–0.5 | 降低随机输出概率，保障板件尺寸、五金型号等专业参数的输出准确性 |
| `AIPROXY_API_ENDPOINT` | 按私有化部署节点实际地址填写 | 适配企业内部网络环境，确保模型调用的稳定性 |
| `AIPROXY_API_TOKEN` | 按企业获取的实际密钥填写 | 基于FastGPT v4.17.0版本的密钥管理逻辑，确保API调用的身份验证有效 |

## 容易做错的三处
- 现象：调大`quoteMaxToken`后，模型输出未引用任何召回内容。原因：引用上限设置超出上下文承载阈值，导致系统无法正确匹配引用与回答内容的关联关系。
- 现象：配置联网工具后，生成的投标文稿中未显示参考链接的可点击渲染格式。原因：未开启对应工具的结果渲染配置，或接口返回的reference字段未正确映射到输出模板。
- 现象：模型输出的板件尺寸与实际拆单数据存在偏差。原因：未配置品类专属的字段识别规则，导致模型混淆通用尺寸单位与品类特有的毫米、立方米参数。

## 怎么确认配好了
- 上传单份定制家具的拆单图与开料清单，触发报价文稿生成，核对输出内容是否包含所有板件的尺寸参数。
- 调整`quoteMaxToken`的取值，验证召回内容是否随参数变化合理调整占比，确认引用逻辑正常生效。
- 调用私有化部署的API接口，检查返回结果是否包含完整的reference链接字段，确认渲染配置无误。
- 模拟高频数据更新场景，验证模型接入的数据源同步延迟是否符合生产节奏要求。
