# 家用电器整机制造的投标文稿与报价编制：HTTP 接口与外部系统

## 这个品类的数据长什么样
家用电器整机制造的生产与检测数据来源于ERP、MES系统、拧紧与充注设备、安规测试仪、性能实验室及售后故障记录。日常文档包含机型配置BOM、装配作业书、制冷剂充注记录、电气安全测试报告、性能抽检报告与返修记录。数据更新频率为单台产品级、班组级或按抽检计划执行，字段包含零部件批次号、充注量、拧紧扭矩、测试电压等，单位涵盖克、牛米、伏特等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源分散的数据来源要求接口需适配不同类型外部系统的认证与数据格式；单台、班组级的高频更新节奏，要求接口支持低延迟的批量数据拉取，避免延迟影响投标报价的时效性；复杂的文档结构与细分字段，要求接口的`responseData`需支持精准过滤与字段映射，防止混线错装的错误数据流入；面向消费者的大批量混线装配场景，要求接口需按机型维度过滤数据，确保投标报价仅关联对应机型的合规参数；安规、性能等强制检测数据的要求，要求接口需校验数据的合规性，避免不合格项进入投标文稿。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 接口认证方式 | 配置`Authorization`头为Bearer {ERP专属密钥} + Basic {设备凭证} | 对接多类型外部系统需匹配不同认证规则 |
| 全局变量配置 | 绑定机型、批次号、安规检测项 | 投标报价需精准关联对应机型的生产数据 |
| 响应数据处理 | 过滤不合格检测记录与冗余字段 | 确保投标文稿仅包含合规且必要的信息 |
| 请求超时设置 | 600 秒 | 安规测试、性能实验室数据上传耗时较长 |
| 重试次数配置 | 3 次 | 应对设备接口偶发的网络波动或超时 |
| 证书挂载路径 | /etc/fastgpt/certs/ | 实现HTTPS访问外部系统，保障数据传输安全 |

## 容易做错的三处
- 现象：接口请求返回SSL证书无效报错，状态码403或SSL handshake failed。原因：未在docker-compose.yml中正确配置证书挂载路径，导致FastGPT无法读取本地证书文件。
- 现象：拉取的BOM数据与投标机型不匹配，出现多型号混装的字段。原因：未在`variables`配置中绑定机型过滤参数，导致跨机型数据被拉取。
- 现象：响应数据中包含不合格的安规测试结果，导致投标文稿出现合规风险。原因：未在响应数据处理配置中添加合格项过滤规则，直接使用原始检测数据。

## 怎么确认配好了
- 发起单次接口请求，核对返回的`responseData`是否与绑定的`variables`参数匹配。
- 查看容器运行日志，确认证书文件已成功挂载，无SSL相关报错信息。
- 模拟多次接口请求，验证重试机制是否在接口波动时正常触发。
- 导出测试用的投标文稿片段，确认所有关联的生产数据均为对应机型的有效记录。
