# 家用电器整机制造的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
本品类数据覆盖空调、冰箱、洗衣机及小家电整机制造场景，日常文档包含配置BOM、装配作业指导书、制冷剂充注记录、电气安全测试报告、性能抽检报告与返修记录。数据来源涵盖ERP/MES系统、零部件批次台账、拧紧与充注设备日志、安规测试仪数据、性能实验室检测结果及售后故障档案。更新节奏按单台产品、每班生产批次或抽检计划执行，单条数据包含零部件型号、工艺参数、检测结果、批次编号等字段，部分字段带有单位标识。

## 这些特征在「向量模型与索引」这一环带来什么约束
单台家电产品对应多维度工艺与检测数据，且更新频率高，要求索引支持高频增量更新，避免全量重建占用过多计算资源。混线装配场景下，不同型号家电的BOM、工艺文档差异细微，向量模型需具备区分度高的语义编码能力，避免相似型号数据混淆。安规、性能检测数据包含数值型参数与定性描述，索引需同时支持结构化数值与非结构化文本的向量映射，确保检索时能关联工艺与合规结果。投标与报价需关联历史批次数据，索引需保留批次与产品型号的关联字段，避免检索时跨型号匹配错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配家电BOM、工艺文档的段落长度，避免单块包含跨型号数据 |
| 重叠长度 | 100–200 字符 | 覆盖工艺步骤的衔接内容，防止拆分后丢失装配工序关联信息 |
| `maxToken` | 8192 | 适配安规测试报告的长文本内容，确保完整编码单份检测文档 |
| 相似度阈值 | 0.75–0.85 | 区分同品类不同型号家电的工艺参数，避免混线匹配错误 |
| 单次搜索上限 | 前 10 条 | 平衡检索效率与投标报价所需的历史数据覆盖范围 |
| `defaultToken` | 1500 | 适配返修记录的短文本编码，减少冗余计算 |

## 容易做错的三处
- 现象：导出知识库生成的dataset.csv仅包含index字段，无content字段。原因：未正确关联家电整机文档的装配作业书、检测报告等源数据字段，仅导入了索引元数据。
- 现象：自定义索引无法关联到正确的家电文档数据，检索结果为空。原因：未正确配置FastGPT索引与MongoDB对应表的字段映射，未绑定源文档的文本字段。
- 现象：向量检索结果混入非目标型号的家电工艺数据。原因：相似度阈值设置过低，无法区分同品类不同型号的细微参数差异。

## 怎么确认配好了
- 手动导入一份家电配置BOM文档，检查向量生成结果是否包含零部件型号、工艺参数等核心字段的语义编码。
- 提交包含“空调冷媒充注参数”的检索请求，核对返回结果是否仅关联空调类文档，无冰箱、小家电等非目标品类数据。
- 查看FastGPT v4.17.0的索引日志，确认增量更新任务按每台产品、每班批次的节奏执行，无全量重建的异常触发。
- 导出知识库的dataset.csv，检查是否同时包含index与content字段，且content字段包含源文档的完整文本内容。
