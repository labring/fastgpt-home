# 家用电器整机制造的投标文稿与报价编制：工具调用与插件

## 这个品类的数据长什么样
该品类的核心数据覆盖空调、冰箱、洗衣机及小家电整机的生产全链路。日常文档包含配置BOM、装配作业指导书、制冷剂充注记录、电气安全测试报告、性能抽检报告与返修记录。数据来源包括ERP/MES系统、零部件批次台账、拧紧与充注设备日志、安规测试仪数据、性能实验室检测结果及售后故障档案。数据更新节奏按单台产品、每班生产批次及固定抽检计划执行。

## 这些特征在「工具调用与插件」这一环带来什么约束
家电整机制造的投标文稿与报价编制需关联多维度生产合规数据，工具调用需直接对接ERP的BOM数据、安规测试结果与售后返修记录。单台产品的实时数据更新要求工具调用需支持低延迟同步，避免因数据滞后导致报价偏差。混线生产的多型号并行处理要求插件需支持按产品型号筛选数据源，防止不同品类的参数混淆。投标文件的合规性校验需工具调用后自动匹配强制要求，需预先配置数据校验规则，确保符合家电产品的安规与性能标准。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 支持自动选择合适的工具完成报价与文稿生成，适配多数据源的调用需求 |
| `functionCall` | 开启强制模式 | 确保工具调用严格按预设规则执行，避免生成不符合投标要求的内容 |
| 工具调用超时时间 | 600 秒 | 适配ERP与安规测试仪的数据拉取延迟，防止因超时中断报价编制流程 |
| 数据库连接超时时间 | 300 秒 | 适配Oracle数据库的数据拉取延迟 |
| 数据源筛选规则 | 按产品型号+生产批次筛选 | 匹配家电整机混线生产的多型号并行处理需求，避免不同品类的数据混淆 |
| 结果返回条数 | 前 3 条 | 控制投标文稿的信息密度，确保核心数据准确且不冗余 |
| 上下文窗口大小 | 8000 token | 适配多文档拼接的投标文稿内容 |
| 插件触发条件 | 按投标项目类型触发 | 区分家用空调、冰箱等不同品类的投标模板，适配差异化的编制要求 |

## 容易做错的三处
- 调用自有系统接口时提示`Error: write EPROT`，原因是未在FastGPT中配置正确的HTTPS证书信任规则，导致接口握手失败。
- 尝试接入openrouter的qwen next thinking模型时无法正常调用，原因是未在插件配置中正确填写模型的接口地址与密钥，且未开启`functionCall`适配模型的工具调用能力。
- 配置Oracle数据库连接插件后无法读取数据，原因是未配置数据库访问的白名单权限，或字段映射与家电整机的BOM、抽检报告字段不匹配。

## 怎么确认配好了
- 触发一次模拟投标项目的工具调用，检查返回的数据源是否仅包含指定型号的家电整机数据。
- 查看工具调用日志，确认接口请求与响应的格式符合预设规则，无超时或报错信息。
- 生成一份测试用的投标文稿，核对其中的报价数据与安规测试结果是否与ERP导出的原始数据一致。
- 测试不同品类的触发条件，确认插件仅在匹配的投标项目类型下启动，避免跨品类的数据干扰。
