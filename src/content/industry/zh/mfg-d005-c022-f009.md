# 家用电器整机制造的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
这个品类的典型主体为空调、冰箱、洗衣机及小家电生产企业。日常产生的文档包含配置BOM、装配作业书、制冷剂充注记录、电气安全测试报告、性能抽检报告、返修记录。数据来源覆盖ERP/MES系统、零部件批次台账、拧紧与充注设备日志、安规测试仪数据、性能实验室报告及售后故障数据库。数据更新频率按单台产品、每班生产批次及抽检计划执行，不同文档的字段包含型号标识、零部件编号、测试参数、故障类型等，单位涵盖电压、流量、能效等级等专业参数。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的实时数据要求模型能够快速整合不同系统的字段信息，避免因数据割裂导致投标文稿中的报价与实际生产参数不符。单台级别的更新频率意味着模型需要处理高频变化的零部件批次数据，因此上下文窗口需覆盖足够的历史数据以保证报价准确性。安规、性能测试等合规性文档的存在，要求模型输出的投标内容需严格匹配文档中的实测数据，不能出现参数偏差。大批量混线生产的特性，要求模型能够准确区分不同型号的BOM与作业要求，避免在文稿中出现型号混淆的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 投标文稿需整合多份BOM、安规报告及抽检数据，该长度可覆盖完整的关联文档内容 |
| `maxTokens` | 15000–20000 token | 完整的投标文稿包含产品介绍、报价明细、合规说明等模块，需保证生成内容无截断 |
| `quoteMaxToken` | 3000–4000 token | 报价部分需精准计算零部件成本与批次价格，限制该长度可避免生成冗余内容影响报价准确性 |
| `temperature` | 0.2–0.4 | 投标与报价内容需保持严谨性，较低的温度参数可减少随机偏差，确保数据匹配度 |
| 工作流/API 工具选择配置 | auto | 允许模型自动调用工具获取实时零部件批次数据，适配按生产批次更新的报价需求 |
| `AIPROXY_API_TOKEN` | 企业专属加密令牌 | 用于安全传输安规、售后等敏感生产数据，避免数据泄露 |

## 容易做错的三处
- 工作流中问题分类模块返回结果条数不足，原因是未调整`maxContext`参数，导致无法加载完整的型号相关文档，无法准确识别分类维度。
- 尝试在工作流中接入MCP功能时返回接口授权失败，原因是未正确填写`AIPROXY_API_TOKEN`参数，或`AIPROXY_API_ENDPOINT`未配置为企业内部合规的代理地址。
- 启用语音识别功能后弹出浏览器不支持语音输入的提示，原因是未在FastGPT v4.17.0的前端配置中开启跨域语音传输权限，或当前浏览器未授予麦克风使用权限。

## 怎么确认配好了
- 上传一份指定型号的空调BOM与安规测试报告，检查生成的投标文稿是否正确引用了对应型号的零部件编号与测试参数。
- 触发工作流中的MCP插件调用，确认返回结果包含零部件批次、生产时间等预设字段，无缺失或错误。
- 调整`temperature`参数至0.3后，连续生成3份同型号产品的报价文本，检查内容是否保持一致的严谨性，无明显随机差异。
- 在FastGPT v4.17.0的测试环境中启用语音输入功能，使用支持语音识别的浏览器录入指令，确认无浏览器兼容性报错。
