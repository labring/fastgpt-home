# 工艺变更与工程变更的投标文稿与报价编制：知识库检索与召回

## 这个品类的数据长什么样
本品类服务于制造企业研发、工艺、质量、生产、采购共同参与的变更管理团队，数据来自PLM、ERP、MES系统、供应商资料、验证试验记录与客户特殊要求文件。日常文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本记录、工艺验证报告、生产切换计划、库存处置单及客户批准文件。数据更新无固定周期，每次工艺或工程变更触发更新。文档字段包含变更编号、版本号、生效日期、物料编码、工艺参数、验证结果等，无统一固定单位，随对应业务文档格式调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散于多业务系统，检索需跨源整合不同类型的文档，因此召回配置需支持多数据集关联与混合内容检索。数据更新无固定周期，需保证索引的实时性，检索时需优先匹配最新版本的变更相关内容。文档类型包含结构化表单与非结构化图纸，需适配不同格式内容的向量召回逻辑。变更关联的内容关联性强，检索需精准匹配变更编号、版本号等核心字段，避免召回无关的历史变更内容。投标场景下需快速定位客户批准文件、工艺验证结果等核心资料，检索优先级需向业务关键字段倾斜。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，具体参数取值可根据实际业务场景微调。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 匹配变更相关的专业术语与版本信息，避免召回无关历史变更 |
| `limit` | 8条 | 覆盖ECN/ECR、验证报告、客户文件等多类型文档，适配投标场景的信息密度 |
| `searchMode` | `fullTextRecall` | 适配图纸、BOM等非结构化内容与结构化表单的混合检索需求 |
| `usingReRank` | 开启 | 提升变更关联内容的排序准确性，避免核心验证报告被低相关结果挤占 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动补充变更编号、版本号等字段的扩展检索词，提升召回精准度 |
| `collectionIds` | 指定变更相关数据集ID | 限定检索范围至ECN/ECR、验证报告等核心变更文档，避免无关数据干扰 |

## 容易做错的三处
- 现象：检索结果条数固定在预设上限，无法通过调低`similarity`或调大`limit`参数实现召回内容增长。原因：未正确配置多数据集关联的变量映射规则，或系统默认限制了单会话的总召回条数。
- 现象：检索结果未包含供应商资料、客户特殊要求等辅助数据。原因：未将对应数据源添加至关联数据集，或未开启`datasetSearchUsingExtensionQuery`配置。
- 现象：无法准确识别空检索结果，导致投标文稿遗漏必要的验证文件。原因：仅使用基础判断器检测结果为空，未结合变更生效日期字段过滤过期无效内容。

## 怎么确认配好了
- 上传一份最新的ECN文档与一条历史变更记录，执行检索后查看返回结果是否优先展示最新版本的内容。
- 调整`similarity`参数至0.65与0.85，对比检索结果的相关性与条数变化，确认配置生效。
- 测试调用多数据集关联的检索流程，验证是否能同时召回PLM系统的BOM数据与ERP系统的库存处置单。
- 查看系统日志，确认检索请求携带了正确的`collectionIds`参数与扩展检索词。
