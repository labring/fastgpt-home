# 工艺变更与工程变更的投标文稿与报价编制：部署与升级

## 这个品类的数据长什么样
该品类的数据由制造企业研发、工艺、质量、生产、采购共同组成的变更管理团队产生，日常文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本文件、工艺验证报告、新旧版本切换计划、库存处置单及客户批准文件。数据来源包括PLM、ERP、MES系统、供应商资料、验证试验记录与客户特殊要求，更新频率随每次工艺或工程变更不定期触发。数据字段涵盖变更编号、版本号、生效日期、影响范围、审批状态等，单位涉及件、批次、日期等。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据来源涉及多系统对接，部署时需配置跨系统数据同步的适配参数，避免不同系统间的数据格式不兼容问题。因变更触发无固定周期，需支持动态加载最新变更文档，升级时需保证增量数据同步不中断，防止投标文稿与报价编制使用过期数据。文档包含结构化表单与非结构化图纸，需适配多类型文件的索引与检索，部署时需预留足够的存储资源。变更数据关联复杂连锁影响，检索时需保证关联数据的准确性，升级时需验证关联检索逻辑的稳定性，避免出现新旧版本混淆的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 20–30 条 | 适配多系统同步的变更数据连接需求，避免连接池耗尽影响检索 |
| `REDIS_URL` | 本地Redis实例或专属缓存集群 | 用于缓存高频访问的变更文档元数据，提升投标文稿生成时的检索速度 |
| `STORAGE_S3_ENDPOINT` | 企业自建对象存储端点 | 适配图纸、BOM等大体积变更文档的存储与快速读取 |
| `FE_DOMAIN` | 企业内网或公网访问域名 | 用于配置前端界面的访问路径，保障变更文档的权限校验 |
| 单次搜索上限 | 前 8 条 | 匹配变更文档的关联检索范围，平衡检索效率与投标内容生成的完整性 |
| 文件存储配额 | 1000 GB 按实测标定 | 容纳长期积累的变更文档与验证报告，满足多批次变更的存储需求 |

## 容易做错的三处
- 现象：reranker组件调用接口返回成功但检索结果为false。原因：未配置`FILE_TOKEN_KEY`校验参数，导致文档权限校验失败，返回无效结果。
- 现象：升级到FastGPT v4.17.0后，插件编辑界面始终显示“未保存”状态。原因：前端缓存与后端配置未同步，升级后未清理浏览器缓存或重置前端配置。
- 现象：私有化部署时，将自定义检索数量设置为6条后无法生效。原因：未调整`DB_MAX_LINK`的配置值，限制了检索结果的返回上限。

## 怎么确认配好了
- 执行跨系统数据同步测试，验证PLM、ERP等来源的变更文档能否正常加载至系统中。
- 上传一份ECN文档，检索时确认返回结果包含关联的BOM版本与工艺验证报告，验证关联检索逻辑正常。
- 调整单次搜索上限参数，验证返回结果条数符合配置值，确认检索上限生效。
- 重启服务后检查`REDIS_URL`的连接状态，确认缓存服务正常运行，元数据检索无延迟。
