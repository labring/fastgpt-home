# 工装夹具与检具制造的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源于产品数模与GD&T规范、工艺路线文件、三坐标测量数据、现场试用反馈及计量系统记录。日常生成的文档包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录与变更履历。数据更新按单个项目推进，伴随产品变更或定期校准触发。文档包含定位基准坐标、形位公差参数、测量结果数值等结构化字段，以及配套的工程图纸与操作说明。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据包含多模态工程图纸与结构化测量参数，且更新频率随单个项目推进与产品变更波动，要求模型接入环节支持多源数据的统一解析。专业文档中的GD&T规范、定位基准参数等领域内容，需要模型具备精准的专业语义理解能力，避免基准转换或方案生成错误。同时，投标文稿需关联最新的校准记录与变更履历，要求配置环节支持关联历史版本数据，且需控制上下文长度以避免不同项目的参数混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启，支持PNG、STEP格式文件 | 本品类包含夹具图、检具操作书等工程图纸，需模型解析图像内容，本配置适用于FastGPT v4.17.0版本 |
| `maxContext` | 8000–12000 token | 单次项目的文档总长度通常在该区间，避免超出上下文限制导致内容截断 |
| `temperature` | 0.2–0.4 | 投标文稿与报价需保持专业严谨，避免生成偏离实际参数的内容 |
| `toolChoice` | auto | 需模型自主选择是否调用工具解析工程数据，适配不同类型的输入内容 |
| `AIPROXY_API_TOKEN` | 使用应用特定key | 本品类的项目数据具有专属属性，应用特定key可隔离不同项目的配置与数据 |
| `maxTokens` | 2000–3000 token | 单次投标文稿生成的输出长度需控制在合理区间，避免冗余内容 |

## 容易做错的三处
- 现象：调用模型生成投标文稿时，未解析上传的夹具图或检具操作书，返回内容仅包含文本信息。原因：未开启`vision`参数，或未配置支持多模态输入的模型环境。
- 现象：创建索引模型后，调用语言模型时提示缺少必要的模型资源。原因：误将索引模型与语言模型的配置分离，未同时关联两类模型的资源。
- 现象：生成的报价内容出现与实际工艺参数不符的偏差。原因：`temperature`参数取值过高，导致模型生成的内容偏离专业规范与实际数据。

## 怎么确认配好了
- 上传一张本品类的夹具图或检具操作书，发起测试调用，检查返回内容是否包含对图像内容的解析描述。
- 输入包含GD&T参数的文本提问，检查返回的投标文稿是否准确关联了对应的参数内容。
- 使用应用特定key发起调用，对比不同项目的测试结果，确认数据未出现跨项目混淆。
- 调整`temperature`参数后发起测试，观察生成内容的严谨性变化，确认参数取值符合业务需求。
