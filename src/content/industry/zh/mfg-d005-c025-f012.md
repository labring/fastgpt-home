# 工装夹具与检具制造的投标文稿与报价编制：部署与升级

## 这个品类的数据长什么样
该品类的核心数据来自产品数模与GD&T规范、工艺路线文件、三坐标测量数据、现场试用反馈及计量系统记录。日常生成的文档包含工装需求书、定位基准方案、夹具设计图、检具操作指导书、验收报告、校准记录与变更履历。数据更新按单个项目推进，伴随产品变更或定期校准动作触发，单次更新关联单套工装或检具的全生命周期节点信息。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的文档多为结构化工程图纸与计量记录，且数据更新关联单个项目节点，部署时需适配多源异构数据的接入格式。因数据按项目和变更触发更新，升级环节需保证历史项目的文档索引不丢失，避免投标时调用失效的旧数据。同时，单套工装的关联数据量随项目推进逐步积累，部署的存储与索引资源需预留足够扩容空间，防止因数据量增长导致检索延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | `http://内部对象存储IP:9000` | 工装夹具的图纸、校准记录等文件需存储在可内部访问的对象存储中，匹配企业现有运维习惯 |
| `REDIS_URL` | `redis://:{自定义密码}@redis服务地址:6379/0` | 用于缓存投标文档的检索结果与临时会话数据，默认0号库可隔离业务数据 |
| `PG_URL` | `postgresql://{数据库用户名}:{数据库密码}@pg服务地址:5432/fastgpt_tooling` | 存储项目关联的投标文稿、报价数据与工装变更履历，专用库可避免与其他业务数据冲突 |
| `ROOT_KEY` | 32位随机字符串 | 用于系统内部接口鉴权，保障投标相关敏感数据的访问安全 |
| `DB_MAX_LINK` | `20` | 适配该品类单项目多文档的并发检索需求，避免数据库连接耗尽 |

## 容易做错的三处
- 现象：升级到FastGPT v4.17.0后，上传工装图纸或校准记录文件时提示Failed to create post presigned url。原因：未正确配置`STORAGE_S3_ENDPOINT`及关联的存储密钥，导致对象存储无法生成预签名上传链接。
- 现象：迁移部署后，无法检索到原有项目的工装文档。原因：未同步迁移`PG_URL`关联的PostgreSQL数据库与`REDIS_URL`关联的缓存数据，导致历史索引丢失。
- 现象：创建投标文稿知识库时出现worker terminated due to reaching memory limit报错。原因：未调整`DB_MAX_LINK`参数，并发检索导致数据库连接占用过多内存，超出服务器分配阈值。

## 怎么确认配好了
- 执行单文件上传测试，上传单套夹具的设计图，确认无预签名链接报错，文件可正常存储并关联到对应项目。
- 导入原有项目的工装变更履历数据，通过知识库检索功能验证可正常返回关联文档。
- 发起批量并发检索测试，同时调用5个检索请求，确认无内存溢出或连接耗尽报错。
- 检查`ROOT_KEY`配置，使用内部接口调用测试鉴权逻辑，确认敏感接口可正常拦截未授权访问。
