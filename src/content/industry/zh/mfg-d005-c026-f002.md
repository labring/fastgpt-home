# 有色金属冶炼与电解的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
该品类的日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账。数据来源覆盖精矿与辅料分析报告、DCS生产系统、槽电压电流监测数据、化验室检测结果、能源与环保监测设备。更新节奏随每批原料投入、每炉熔炼或每槽电解作业实时更新，单份文档包含原料成分占比、炉况参数、槽体电压电流、金属回收率、污染物排放指标等字段，部分字段需匹配对应批次的生产流程编号。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时更新的多源数据要求索引支持高频增量写入，避免全量重建带来的性能损耗。多字段混合的文档结构需要向量模型适配多模态字段的语义关联，同时支持按生产批次、槽号等结构化字段做过滤检索。单份文档的字段复杂度较高，分块时需保留关键生产标识，避免语义割裂。投标报价需关联历史批次数据，索引需支持按时间范围、原料类型的精准召回，同时平衡召回速度与召回精度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配，具体如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配单份生产文档的典型段落长度，保留完整生产参数语义 |
| 重叠长度 | 100–150 字符 | 衔接相邻分块的生产批次编号、槽号等关键标识，避免语义割裂 |
| `maxToken` | 4096 token | 适配主流向量模型的上下文长度限制，完整加载投标关联的多份生产文档 |
| 相似度阈值 | 0.72–0.80 | 过滤低关联的历史生产数据，确保报价计算的参数匹配精度 |
| 单次搜索上限 | 前 8 条 | 覆盖典型投标所需的历史批次样本量，平衡检索效率与召回完整性 |
| `defaultToken` | 256 token | 配置检索结果的默认返回token长度，适配投标文稿的摘要生成需求 |
| 向量数据库适配 | 支持结构化过滤与增量写入 | 匹配该品类实时多源数据的检索与更新需求，可对接自定义向量数据库 |

## 容易做错的三处
- 现象：检索结果中混入非对应批次的生产数据，原因：未配置按生产槽号、原料类型的结构化过滤条件，导致召回范围超出投标所需的样本池。
- 现象：向量模型生成的嵌入结果与实际生产参数语义偏差较大，原因：未针对冶炼行业的专业术语（如槽电压、阳极泥含量）做自定义适配，导致模型语义理解出现偏差。
- 现象：索引写入超时，原因：未开启增量索引模式，对实时更新的电解槽况记录执行全量索引重建，超出系统处理上限。

## 怎么确认配好了
- 上传单份典型电解槽况记录，检查分块后的文本是否保留了槽号、电压电流等关键生产标识。
- 发起包含指定原料配比或炉况参数的检索请求，核对召回结果的相似度是否符合预设区间。
- 提交实时更新的配料单数据，检查索引是否在合理时间内完成增量写入。
- 调用模型生成投标报价相关的内容摘要，检查返回内容的长度是否符合配置的token限制。
