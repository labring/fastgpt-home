# 有色金属冶炼与电解的投标文稿与报价编制：工作流编排

## 这个品类的数据长什么样
该品类数据来自精矿与辅料分析报告、DCS系统、电解槽电压电流监测数据、化验室检测结果、能源与环保监测台账。日常生成配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账等文档。数据更新节奏随每批原料投料、每炉熔炼周期、每槽电解工况实时推进，单份文档包含原料成分、槽体参数、金属回收率、污染物排放等字段，单位涵盖质量百分比、电流强度、吨数等。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新实时，要求工作流支持多数据源并行拉取。文档字段多且关联紧密，需在`variables`中绑定跨节点的字段映射关系，确保跨环节数据流转一致。更新节奏随投料、炉次、槽况实时推进，工作流触发需匹配生产事件节点。涉及金属平衡与副产物核算的环节，需固定字段校验规则，避免数据偏差影响报价准确性。投标文稿需关联历史生产数据，要求工作流支持历史工况数据的关联查询与调用。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定原料成分、槽电压、化验结果等核心字段 | 匹配该品类文档的核心数据字段，确保跨节点数据流转一致 |
| 触发方式 | 按生产事件节点触发 | 匹配实时更新的生产节奏，避免无效运行 |
| 单次请求超时 | 600秒 | 适配多数据源拉取的耗时需求，按实测标定 |
| 文件上传参数 | 按表单格式配置文件类型字段 | 支持熔炼记录、化验报告等文档的批量上传与传输 |
| `nodeId` | 绑定数据校验节点与报价核算节点 | 确保核心核算环节的节点执行顺序与逻辑匹配 |
| 失败重试策略 | 重试2次，间隔30秒 | 适配实时数据拉取的偶发网络波动，避免工作流中断 |

## 容易做错的三处
- 现象：工作流在运行预览页面正常执行，聊天页面无对应输出内容。原因：未在工作流中配置公开输出节点，或未绑定聊天窗口的`variables`参数映射。
- 现象：http请求节点配置form-data时，设置文件类型参数后发送失败。原因：未正确绑定本地文件路径或未选择对应文档类型的上传控件，导致参数格式不匹配。
- 现象：上传生产文档时提示Load file error，知识上传可正常完成。原因：工作流节点的文件读取权限未配置，或文档字段包含未支持的特殊字符，导致文件解析失败。

## 怎么确认配好了
- 触发一次模拟生产事件，检查工作流各节点的日志是否显示正确的数据源拉取结果。
- 调用测试用的配料单、化验报告文档，验证`variables`字段的映射是否完整且无缺失。
- 配置文件上传测试，确认form-data参数的文件类型字段可正常发送文档。
- 查看工作流的状态监控面板，确认节点执行顺序与预设配置一致。
