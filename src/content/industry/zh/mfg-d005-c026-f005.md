# 有色金属冶炼与电解的投标文稿与报价编制：工具调用与插件

## 这个品类的数据长什么样
有色金属冶炼与电解的业务数据来自精矿与辅料分析报告、DCS生产控制系统、槽电压电流监测系统、化验室检测结果、能源与环保台账。日常生成的文档包括配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账。数据更新随每批原料投料、每炉熔炼完成、每槽工况变化实时推进。核心字段包含原料成分占比、槽电压电流值、金属回收率、副产物含量，单位多为百分比、安培、伏特、吨等。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据随批次实时更新，工具调用需绑定当前批次的最新数据接口，避免使用过期的历史记录导致报价与文稿内容不符。多类文档的字段结构存在差异，插件在读取数据时需配置对应文档的字段映射规则，无法统一套用固定模板。电解槽群的实时监测数据量较大，插件调用的频率需适配批次更新节奏，避免频繁触发导致系统资源占用过高。同时，金属平衡与副产物去向的核算依赖多源数据聚合，工具需支持跨数据源的字段关联查询，确保核算结果准确。需正确配置`toolChoice`与`functionCall`参数，确保工具调用的灵活性与结果格式合规。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ----------- |
| `toolChoice` | `auto` | 适配多源数据的动态调用需求，自动选择匹配的工具处理配料核算、槽况分析、金属平衡计算等不同任务 |
| 单次工具调用超时 | 300–600 秒 | 匹配电解槽况核算、金属平衡计算的耗时区间，避免因复杂运算提前中断调用 |
| 工具调用上下文上限 | 前 8 条历史批次数据 | 限制单次调用的历史数据量，适配多批次数据聚合的内存占用要求 |
| `functionCall` | 开启 | 强制以结构化格式返回核算结果，便于投标文稿中自动插入标准化的报价与成分数据 |
| 插件触发规则 | 按批次触发 | 匹配原料、炉槽的更新节奏，避免无意义的重复调用 |

本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 插件点击无响应，查看界面或日志显示返回字段为空。原因是未配置对应文档的字段映射规则，工具无法从配料单、槽况记录中提取所需的成分与质量数据。
- 半夜持续触发插件调用导致API余额耗尽。原因是未设置按批次触发的规则，插件被配置为定时轮询实时数据，无新批次更新时仍反复调用接口。
- 单次对话多次弹出插件调用提示。原因是未关闭对话内的自动插件调用开关，导致每轮回复都重复请求工具调用，不符合单个对话仅提示一次的需求。

## 怎么确认配好了
- 手动触发一次插件调用，检查返回结果是否包含当前批次的配料成分、槽电压电流等核心业务字段。
- 查看工具调用日志，确认仅在有新的原料批次或炉槽数据更新时触发调用，无定时无意义的调用记录。
- 提交测试用的投标文稿需求，检查插件返回的核算结果是否以结构化格式输出，可直接插入预设的文稿模板。
- 模拟异常场景触发调用，确认插件返回合理的提示信息，不会出现空值或异常报错，且未意外引入无关数据。
