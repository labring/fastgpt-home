# 有色金属冶炼与电解的投标文稿与报价编制：部署与升级

## 这个品类的数据长什么样
该品类的日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账，数据来源涵盖精矿与辅料分析、DCS系统、槽电压电流监测、化验室数据、能源与环保监测系统。数据更新节奏随生产流程而定，每批原料、每炉熔炼或每台电解槽均会生成新数据，部分监测指标为实时更新。文档多包含工艺参数、质量指标与环境数据，字段与单位需匹配冶炼生产的标准规范。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的生产数据来源要求部署时需支持多系统数据接入，避免额外的数据同步开发成本。高频实时更新的业务数据要求数据库连接池与缓存服务具备高并发承载能力，防止生产数据延迟或丢失。品类专属的文档结构与字段要求知识库解析规则需适配配料单、槽况记录等特定格式，通用解析模板无法覆盖全部业务场景。升级过程中需兼容历史生产数据的存储格式，避免因版本变更导致历史投标报价数据无法复用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `10–15` | 该品类数据更新频繁且来源多样，稳定的数据库连接池可避免生产环境的连接耗尽问题 |
| `STORAGE_S3_ENDPOINT` | `企业内部对象存储的域名或IP:端口` | 日常生产文档需存储于内部合规的存储服务，保障数据安全与访问稳定性 |
| `REDIS_URL` | `企业内部Redis集群地址，配置600秒过期时间` | 实时更新的槽况、化验数据需缓存以减少重复查询，降低生产系统压力 |
| `MONGODB_URI` | `绑定生产环境MongoDB副本集地址` | 多批次的熔炼、电解记录需高可用的文档型数据库存储，保障数据持久化 |
| `PG_URL` | `配置为企业生产库的只读实例地址` | 投标报价需调取历史精矿、能源数据，只读实例可避免影响核心生产业务 |
| `FE_DOMAIN` | `企业内部FastGPT访问域名` | 内部部署场景下需限定访问范围，防止生产数据被未授权访问 |

## 容易做错的三处
- 现象：调用外部模型生成报价时返回`400 Bad Request`，提示业务字段格式错误。原因：未针对有色金属冶炼品类的专属字段（如槽电压、精矿品位）调整提示词模板，导致传入的业务数据与模型预期格式不匹配。
- 现象：升级到FastGPT v4.17.0后，历史电解槽况记录无法正常加载。原因：未提前备份旧版数据库关联的生产库表结构，升级后版本适配的字段映射规则变更导致数据读取失败。
- 现象：知识库召回结果为空，无法检索到熔炼记录。原因：未正确配置`FILE_TOKEN_KEY`，导致上传的结构化生产文档未被正确解析，无法生成对应的向量索引。

## 怎么确认配好了
- 访问`FE_DOMAIN`对应的前端页面，上传一份电解槽况记录文档，确认上传成功且无解析报错。
- 调用数据库连接测试接口，查看`DB_MAX_LINK`对应的连接池使用率处于正常区间，无连接超时或断开报错。
- 提交一份包含精矿成分、熔炼参数的投标报价生成请求，查看返回结果包含对应品类的业务字段，无缺失或格式错误。
- 检查`STORAGE_S3_ENDPOINT`对应的存储桶，确认上传的生产文档已按预设分类存储，路径符合业务规则。
