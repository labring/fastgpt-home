# 服装裁剪与缝制的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自服装OEM/ODM、品牌供应链及裁剪缝制车间的日常业务系统与硬件设备，包括工艺单、CAD样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等文档。数据来源涵盖订单与尺码表、面辅料检验记录、吊挂系统工序数据、验针机检测结果及客户封样资料，更新节奏为每订单、每款、每批触发一次，数据结构围绕版型参数、工序要求、尺码配比、面辅料规格展开，且因面料裁片不可逆的特性，数据需严格匹配生产批次。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据高频增量更新、多维度分散的特性，对向量索引带来多重约束。每订单每款的更新节奏要求索引支持增量同步，避免全量重建占用过多资源；围绕版型、工序、尺码的多字段数据结构，需要向量模型精准捕捉细分工艺语义，防止不同款型的参数混淆；面料裁片不可逆的特性，要求索引元数据必须绑定生产批次与订单号，避免数据错位影响报价准确性；投标场景下需快速召回历史同类型订单的工艺与报价数据，索引需支持按款号、订单维度的精准过滤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 匹配服装工艺单、排料图等文档的单段语义长度，避免拆分破坏工序描述的完整性 |
| 重叠长度 | 50–80 字符 | 保留相邻分块的重叠内容，防止跨块的工艺参数被拆分丢失 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配度的历史工艺数据，适配服装品类多款式但工艺细节差异大的特征 |
| 单次搜索上限 | 前 10 条 | 控制召回的历史订单数量，避免上下文过长影响投标文稿的生成效率 |
| `maxToken` | 按所选嵌入模型/服务支持的输入上限设置 | 这是嵌入模型配置中的最大 token 数，不是索引批次处理上限；请核对所选模型或服务商文档。参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx) |
| `defaultToken` | 用代表性工艺单样本实测校准 | 这是文本切分时使用的默认 token 数；请检查代表性原文的分块结果。参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx) |

## 容易做错的三处
- 现象：创建索引模型后，语言模型无法读取召回的向量数据。原因：未完成索引模型与语言模型的绑定配置，导致向量检索结果无法流入语言模型环节，无法支撑投标文稿的工艺描述与报价逻辑。
- 现象：向量存储从PGSQL迁移后，历史订单相关的工艺数据无法被召回。原因：未同步迁移索引绑定的元数据字段（如款号、订单批次），导致新存储无法按业务维度过滤匹配数据。
- 现象：索引任务超时。先检查任务日志、文档解析与分块结果，以及嵌入服务的错误和耗时，再调整 token 配置。`defaultToken`控制默认文本切分 token 数，不是批次处理超时阈值。

## 怎么确认配好了
- 在FastGPT v4.17.2版本中，上传单份工艺单文档，执行向量索引创建，查看界面返回的索引状态为成功。
- 输入包含某款服装尺码要求的查询词，验证召回结果中包含对应款号的历史工艺数据。
- 调整相似度阈值后，对比召回结果的数量变化，确认阈值配置生效。
- 查看任务日志中的索引错误；按所选嵌入模型/服务核对`maxToken`，并抽查文本分块，确认`defaultToken`达到预期效果。
