# 服装裁剪与缝制的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
服装裁剪与缝制领域的投标与报价相关数据，通常来自服装OEM/ODM厂商、品牌供应链、裁剪缝制车间的日常业务文档。日常文档包含工艺单、CAD样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等。数据来源覆盖订单与尺码表、面辅料检验记录、吊挂系统数据、验针机记录、客户封样文件。数据更新频率为每订单、每款、每批，字段包含尺码规格、面料米数/千克数、裁片件数、工序工时、包装配码比例等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据更新频繁且每批次存在差异，因此多轮对话的上下文需限定有效范围，避免调用过期的历史订单数据。日常文档类型多样，包含非结构化的工艺单与结构化的尺码表，提示词需明确区分不同文档的调用规则，确保提取的字段匹配当前投标项目的要求。裁片不可逆且工序密集的特性，要求多轮对话中需反复核对尺码、面料批次、包装配码等关键字段，避免出现批量偏差或错箱问题。同时，投标文稿需贴合客户封样的细节，提示词需关联客户封样的专属数据，确保内容匹配客户要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages`上下文长度限制 | 前10轮对话 | 匹配该品类每订单每款的业务更新节奏，避免调用过期数据 |
| `variables`数据绑定规则 | 绑定当前订单的尺码表、工艺单、排料图数据 | 确保实时拉取最新的业务数据，适配频繁更新的特征 |
| `chatId`绑定规则 | 绑定当前订单的唯一标识 | 确保每笔投标报价的对话上下文独立，避免跨订单数据混淆 |
| 对话历史保留时长 | 72小时 | 覆盖单款服装从投标到报价的完整周期，避免丢失关键沟通记录 |
| 快捷触发配置 | 预设3-5个高频查询按键 | 提升工程师的操作效率，适配多轮对话的高频查询场景 |
| 文件上传大小限制 | 1000 MB | 适配该品类CAD样板、排料图等文件的常见存储与传输大小 |

## 容易做错的三处
- 现象：对话回复末尾附加「没有权限操作此对话记录」的提示，无法手动取消。原因：未在系统配置中关闭对话引用的强制展示规则。
- 现象：点击对话开场白的快捷按键后，未自动填充并发送预设问题。原因：未将快捷按键与`messages`的初始消息配置绑定。
- 现象：调用对话API时无法上传排料图、工艺单等文件。原因：未开启对话API的文件上传权限配置。

## 怎么确认配好了
- 发起测试对话，输入与投标报价相关的问题，检查回复末尾是否无强制引用提示。
- 点击对话开场白的快捷按键，确认预设问题自动填充并发送至对话窗口。
- 调用对话API，上传工艺单PDF文件，检查接口是否正常接收并处理文件内容。
- 查看`variables`绑定的数据，确认实时拉取的是当前订单的最新尺码表与排料图数据。
