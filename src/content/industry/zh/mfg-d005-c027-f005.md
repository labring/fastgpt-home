# 服装裁剪与缝制的投标文稿与报价编制：工具调用与插件

## 这个品类的数据长什么样
该品类的数据通常来自服装OEM/ODM、品牌供应链及裁剪缝制车间的日常业务系统。日常文档包含工艺单、样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等。数据核心来源为订单与尺码表、CAD样板、面辅料检验记录、吊挂系统数据、验针机记录及客户封样，更新频率为每订单、每款、每批。数据字段包含版型参数、尺码规格、面辅料批次、工序工时、包装配比等，单位多为厘米、件、批次号等。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据更新频率随订单、款式、批次变动，要求工具调用需支持按单次业务场景拉取最新数据，避免复用旧批次信息导致报价偏差。日常文档类型多样，插件需适配工艺单、排料图、包装配码单等不同文档的字段映射规则，例如从排料图提取裁片数量、从工艺单拆解工序工时。由于面料裁片不可逆且人工工序密集，工具调用的输出需包含多维度校验逻辑，核对尺码、色批与包装配比，防止出现错码错箱或批量瑕疵。同时，需整合吊挂系统、验针机等多系统数据，确保投标文稿与报价的成本核算贴合实际生产流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 工作流/API 工具选择配置 | `auto` | 适配服装品类多工序的动态调用需求，无需手动指定工具 |
| 超时时间 | 1200 秒 | 应对多文档解析与跨系统数据拉取的耗时场景 |
| 上下文窗口大小 | 8000–12000 token | 容纳工艺单、排料图等多文档的完整内容 |
| 插件调用次数上限 | 前 8 条 | 匹配单批次订单的核心数据字段数量 |
| 工作流/API 函数调用配置 | 启用 | 支持结构化输出报价与投标文稿的字段校验 |
| 结果校验开关 | 启用 | 自动核对尺码、包装配比等核心业务字段 |

## 容易做错的三处
- 现象为调用本地模型时工具调用无响应，返回空结果或状态码500；原因是未在模型配置中开启工具调用开关，或本地模型未正确加载函数调用插件。
- 现象为重复调用时历史记录丢失，无法复用已生成的报价草稿；原因是未开启会话历史保存配置，或配置的保存路径未指向业务数据目录。
- 现象为使用通用账户KEY作为BASE_URI时插件调用失败，返回权限或连接错误；原因是通用账户KEY未配置对应品类的插件调用权限，或BASE_URI未指向私有部署的FastGPT实例。

## 怎么确认配好了
- 在FastGPT v4.17.0版本下，发起一次测试调用，传入单批次订单的工艺单与尺码表，检查工具是否自动调用对应插件解析数据。
- 查看会话日志，确认`toolChoice`参数生效，工具调用流程符合配置的次数上限。
- 核对输出结果，检查是否包含该品类特有的字段，如裁片数量、面辅料批次。
- 模拟重复调用，检查历史会话是否保留已生成的投标文稿草稿，确认配置生效。
