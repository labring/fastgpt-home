# 服装裁剪与缝制的投标文稿与报价编制：知识库检索与召回

## 这个品类的数据长什么样
该品类的日常文档包含工艺单、样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等，数据来源于订单与尺码表、CAD样板、面辅料检验记录、吊挂系统数据、验针机记录、客户封样。数据更新频率为每订单、每款、每批，不同款式的版型、工艺要求差异明显，字段包含尺码参数、面料规格、工序要求、包装配比等，单位多涉及厘米、克重、件数等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类数据更新频率高且单款定制化强，知识库需支持高频增量更新，避免召回过时的工艺或尺码数据。文档类型包含非结构化的工艺描述、结构化的尺码表与排料图，需适配多格式内容的检索。因款式多、季节性强，检索需精准匹配当前投标项目的品类与尺码范围，避免召回不相关的过往批次数据。同时裁片不可逆的特性要求检索结果需严格对应面料色批、裁片配套要求，降低出错风险。

## 配置怎么定
FastGPT v4.17.0 下的配置需结合该品类特征调整，具体如下表：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 服装品类的工艺与尺码要求需较高匹配度，避免低相关结果混入投标编制内容，对应参数`similarity` |
| 单次搜索上限 | 前8–12条 | 平衡检索全面性与上下文窗口占用，避免过多冗余内容干扰文稿撰写，对应参数`limit` |
| 扩展查询字符上限 | 800–1200 字符 | 扩展投标项目的款式、尺码关键词时，控制扩展长度以覆盖相关工艺术语，对应参数`datasetSearchUsingExtensionQuery` |
| 搜索模式 | 向量+关键词混合 | 适配该品类结构化尺码表与非结构化工艺文档混合的检索需求，对应参数`searchMode` |
| 重排开关 | 开启 | 对多款式召回结果按相关性排序，确保核心工艺与尺码要求优先被调用，对应参数`usingReRank` |
| 知识库集合ID | 绑定当前投标项目专属知识库集合 | 隔离不同项目的数据，避免召回不相关的过往批次内容，对应参数`collectionIds` |
| 知识库容量上限 | 10 GB | 适配该品类多款式文档的存储需求，避免因容量不足导致召回失败 |

## 容易做错的三处
- 现象：生成的投标文稿中未附带知识库文档的来源标识，无法确认内容是否来自知识库。原因：未开启知识库溯源配置，或提示词未明确要求标注来源。
- 现象：单次知识库检索返回的结果条数远超或远低于预设的单次搜索上限，或出现大量与当前投标项目无关的过往批次服装工艺文档。原因：未绑定当前投标项目的专属知识库集合，或`limit`参数配置错误导致跨品类召回。
- 现象：检索返回的工艺要求或尺码数据与当前投标项目的最新版本不符，或检索耗时超出业务处理阈值。原因：未按订单、款式的更新频率同步知识库数据，或未开启`usingReRank`优化召回结果。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理界面，查看当前绑定的知识库集合是否为当前投标项目专属的集合，核对`collectionIds`参数是否正确配置。
- 发起一次模拟检索，输入投标项目的核心关键词（如某款服装的尺码、工艺要求），核对返回结果的相关性与数量是否符合预设要求。
- 查看检索结果的溯源标识，确认每条召回内容均标注了来源知识库的文档信息，验证溯源配置是否生效。
- 检查知识库的更新日志，确认最新的订单、款式数据已同步至当前绑定的知识库集合，验证增量更新配置是否正确。
