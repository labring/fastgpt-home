# 服装裁剪与缝制的投标文稿与报价编制：表单与交互

## 这个品类的数据长什么样
典型主体为服装OEM/ODM厂商、品牌供应链车间与裁剪缝制班组，日常文档包含工艺单、排料图、裁剪单、首件封样资料与包装配码单。数据主要来自订单与尺码表、CAD样板系统、吊挂生产系统、面辅料检验记录与客户封样件，更新频率为每订单、每款、每批更新一次。字段包含尺码规格、面料幅宽、裁片数量、工序工时与包装配比规则，单位涵盖厘米、件、工时小时与配码比例范围。

## 这些特征在「表单与交互」这一环带来什么约束
品类款式多、季节性强，且面料裁片不可逆、人工工序密集，因此表单交互需支持多批次多尺码的快速切换，避免重复录入。数据更新频率高，表单需支持实时同步结构化业务数据，减少手动输入环节。工序拆解与裁片配套环节耗时较长，表单校验需覆盖尺码匹配、面料参数一致性等核心规则，防止后续出错。若用户在表单交互过程中发送新消息，未处理的交互状态会导致流程中断，需配置对应的状态重置与超时机制。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` 模块配置 | 绑定订单尺码表、工艺单的结构化字段，设置字段必填规则 | 品类数据多来自订单与CAD系统等结构化业务源，绑定后可减少手动录入，必填规则覆盖尺码匹配、面料参数等核心校验项 |
| `userSelect` 模块配置 | 预设3-5个按品类分类的报价模板，设置超时自动提交时间为600秒 | 款式多季节性强，分类模板可快速切换；600秒的超时时间适配工序拆解的耗时节奏，防止流程中断 |
| 表单分块设置 | 按面料参数、工艺要求、报价明细分为3个分页 | 贴合品类日常文档的结构逻辑，降低用户填写负担 |
| 表单校验触发 | 提交前触发全量字段校验，校验失败时展示对应字段的错误提示 | 覆盖裁片配套、尺码匹配等核心校验需求，避免后续出错 |
| 交互超时处理 | 未操作超时时间设为900秒，超时后自动重置交互状态 | 适配品类订单处理的周期，防止用户发送新消息导致流程卡住 |

## 容易做错的三处
- 现象：配置`formInput`模块时未绑定结构化数据源，导致表单字段为空，无法生成对应投标文稿内容。原因：未关联品类专属的订单、工艺单等业务数据，仅使用默认空表单模板。
- 现象：`userSelect`模块触发后，用户发送新消息未处理，流程无法正常推进。原因：未配置超时自动重置或强制提交机制，交互状态未随新消息更新。
- 现象：配置表单结果重排时无法勾选已加载的模型选项，导致无法调整报价明细的排序逻辑。原因：未在FastGPT后台开启重排模型的权限配置，前端未渲染可选模型列表。

## 怎么确认配好了
- 导入测试用的服装订单尺码表与工艺单，检查`formInput`模块是否自动填充对应字段，无遗漏或错误。
- 触发`userSelect`模块后，等待超过900秒未操作，检查是否自动重置交互状态，可正常发起新的交互。
- 提交配置完成的表单，检查生成的投标文稿是否包含品类专属的工艺要求、裁片数量等内容，格式符合业务习惯。
- 查看后台配置日志，确认所有绑定的业务数据源均已同步最新数据，无连接报错。
