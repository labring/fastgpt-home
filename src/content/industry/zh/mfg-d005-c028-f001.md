# 来料检验与供应商质量的投标文稿与报价编制：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据覆盖制造企业IQC、SQE等部门的日常质量文档，包括检验规范、抽样方案、来料报告、供应商审核报告等。数据来源包含采购订单、图纸规格、供应商质保书、检验设备、历史质量数据及供应商门户。更新节奏随来料批次触发，或按月度/季度供应商评价、不定期审核执行。数据字段包含来料批次号、检验日期、缺陷项数量、抽样样本量、整改周期等，无固定统一格式，需按业务场景提取核心信息。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据来源分散且格式不统一，要求HTTP接口支持多数据源的灵活拉取与格式适配。更新节奏无固定周期，需支持按需触发调用，避免冗余数据拉取。数据字段需贴合投标文稿与报价的核心需求，仅提取与质量合规、供应商能力相关的内容。同时，接口调用失败可能导致投标延误或质量风险，需配置失败重试与鉴权校验机制，保障数据获取的稳定性。

以下配置基于FastGPT v4.17.0版本制定。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | `Bearer {{variables.supplierApiToken}}` | 供应商门户接口普遍采用Bearer令牌鉴权，匹配品类数据源的鉴权要求 |
| 变量模板 | `{ "inspectBatch": "", "supplierCode": "" }` | 适配来料批次、供应商编码等品类专属的动态参数需求 |
| `responseData` | `仅保留检验合格数、不合格项清单、整改时限` | 过滤非投标所需的冗余数据，聚焦报价与文稿的核心质量信息 |
| 请求超时阈值 | 30 秒 | 来料检验数据体量较小，超时会延误投标文稿的编制节奏 |
| 请求重试次数 | 2 次 | 抵消临时网络波动或接口短暂不可用的影响 |
| 数据源协议 | RESTful API | 匹配检验设备、供应商门户等系统的通用接口协议 |

## 容易做错的三处
-  接口返回字段为空，仅返回数据库连接结构。原因是未正确配置`responseData`提取规则，误将数据源的连接元数据作为返回内容。
-  调用接口时自动携带额外的Bearer令牌，导致返回401鉴权失败。原因是未关闭平台默认的Bearer令牌自动补充逻辑，与自定义鉴权配置冲突。
-  无法传入不同的token调用外部接口，所有请求使用固定token。原因是未通过`variables`配置动态参数模板，导致token值无法动态替换。

## 怎么确认配好了
-  触发接口调用，查看返回结果是否仅包含检验合格数、不合格项清单等投标所需字段，验证`responseData`配置生效。
-  传入不同的供应商token值，调用接口确认鉴权成功，验证`variables`配置的动态参数生效。
-  模拟网络波动，观察接口是否自动重试，验证请求重试次数配置生效。
-  检查接口响应时长是否符合预设阈值，验证请求超时阈值配置生效。
