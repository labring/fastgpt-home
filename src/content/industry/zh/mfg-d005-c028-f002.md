# 来料检验与供应商质量的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据覆盖制造企业来料检验（IQC）、供应商质量工程（SQE）等部门的日常质量文档与业务数据。数据来源包含采购订单、图纸规格、供应商质保书、检验设备采集数据、历史质量记录及供应商门户信息。更新节奏随每批来料、月度/季度供应商评价及不定期审核变动。文档类型涵盖检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D整改报告及让步接收审批单，包含批次标识、检验参数、判定结果、供应商资质、整改记录等字段，部分字段带有对应业务单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引支持跨系统、跨格式的数据整合，避免出现信息孤岛。高频次的更新节奏需要适配增量索引机制，减少全量重建的资源消耗。多样的文档结构与特定业务字段，要求分块策略需兼顾长文档的信息完整性与短文档的语义连贯性。质量场景的专业术语与关联逻辑，要求向量模型需具备对应领域的语义理解能力，同时索引需支持按批次、供应商等关键字段进行过滤检索，保障投标与报价环节的信息精准性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配检验规范、抽样方案等文档的单块信息密度，避免块内关键业务信息割裂 |
| 重叠长度 | 100–150 字符 | 保留跨块的批次号、检验项、供应商编号等关键字段，防止核心信息被截断 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 区分合格与不合格的质量描述语义，适配质量场景的精准匹配需求 |
| 单次搜索上限 | 前 10 条 | 覆盖同批次来料的多份关联文档，避免召回冗余的历史数据 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 重排 | 开启 | 优化跨文档的质量相关信息排序，提升投标报价关联的精准度 |

## 容易做错的三处
- 现象：在FastGPT v4.17.0的知识库创建页面，文本理解模型下拉框无可选目标。原因：未在模型渠道完成嵌入模型与语言模型的关联绑定，或模型部署未通过健康检查。
- 现象：向量索引召回结果条数与预期不符，混入无关批次的质量数据。原因：未配置按来料批次、供应商编号的过滤规则，导致检索范围覆盖全量历史数据。
- 现象：无法批量触发向量模型重训练，仅支持单文件手动调整参数后上传。原因：未开启知识库的增量更新配置，或未设置批量任务的触发阈值，系统默认仅支持单文件处理。

## 怎么确认配好了
- 上传一份标准来料检验报告，查看向量入库日志，确认分块长度与设置值匹配。
- 输入包含特定供应商编号的检索词，检查召回结果是否包含对应供应商的审核报告与整改记录。
- 测试批量上传3-5份历史质量文档，确认索引任务自动完成且无报错提示。
- 进入FastGPT v4.17.0的模型管理页面，确认已配置的嵌入模型与语言模型均显示为可用状态。
