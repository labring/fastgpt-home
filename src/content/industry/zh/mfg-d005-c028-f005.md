# 来料检验与供应商质量的投标文稿与报价编制：工具调用与插件

## 这个品类的数据长什么样
该品类的数据来源包括采购订单、图纸与规格要求、供应商质保书、检验设备采集数据、历史质量记录及供应商门户信息。更新节奏随每批来料产生新检验记录，每月或季度完成供应商评级更新，不定期开展专项审核。日常文档包含检验规范、抽样方案、来料检验报告、供应商审核报告、异常联络单、8D整改报告及让步接收审批单。数据字段包含来料批次标识、抽样检验的实际件数、不合格项类型、整改完成状态、供应商评级等级等。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据分散于采购、检验、供应商管理等多个环节，工具调用需适配多数据源的格式差异，需配置兼容不同接口的插件以拉取所需的质量相关信息。数据更新随每批来料产生新记录，工具调用需支持按来料批次触发执行，避免重复处理历史数据。日常文档类型多样且字段不统一，插件需支持解析检验报告、整改报告等不同文档结构，精准提取批次号、不合格项等核心字段。质量数据关联生产保供与风险控制，工具调用需严格匹配检验批次与供应商信息，防止数据错位影响投标报价的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用触发方式 | 按来料批次触发 | 匹配该品类按批检验的更新节奏 |
| 单次调用返回条数 | 前3条供应商历史数据 | 覆盖主要供应商质量参考依据 |
| 插件超时时间 | 300–600 秒 | 适配多文档解析与跨系统拉取的耗时需求 |
| `toolChoice` | auto | 允许模型自主选择合适的工具完成报价编制 |
| 字段提取规则 | 匹配检验报告的批次号字段 | 确保数据与对应来料批次绑定 |
| 失败重试次数 | 2次 | 应对临时接口波动，避免单次调用失败终止流程 |

## 容易做错的三处
- 现象：私有部署环境导入自定义插件时，界面返回internal server error。原因：未配置插件的本地执行权限，或环境变量未正确加载插件依赖的运行环境。
- 现象：使用SSE协议封装的MCP工具发起调用，模型提示不支持当前连接方式。原因：当前FastGPT版本仅支持stdio进程类型的MCP插件，未兼容SSE协议的工具配置。
- 现象：调用HTTP组件获取供应商质量数据后，无法提取到对应批次的不合格项字段。原因：字段提取规则未匹配检验报告中的实际字段名，或接口返回的JSON结构与预设提取路径不一致。

## 怎么确认配好了
- 手动触发一次按来料批次的工具调用，查看插件返回的数据源是否包含当前批次的检验数据。
- 检查插件的日志输出，确认调用时使用的协议为stdio，未出现SSE相关的报错信息。
- 验证字段提取规则，输入一份模拟的检验报告文本，确认提取的字段与预设规则一致。
- 确认当前FastGPT版本为v4.17.0，适配当前配置的插件类型与调用逻辑。
