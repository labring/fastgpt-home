# 模具设计制造的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
该品类数据来源包括客户产品模型、模流或成形仿真文件、CAD/CAM图纸、机加工与测量数据、试模样件相关记录。日常文档包含模具设计任务书、DFM报告、零件图、加工工艺卡、试模报告、改模通知与模具履历。数据更新按项目节点触发，每次试模或改模后同步更新，字段包含脱模斜度、缩水率、装配公差、缺陷等级等工程专属参数。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据包含多格式的专业工程文件与结构化参数，模型接入时需适配CAD、仿真结果等非纯文本格式。按项目与试模改模的高频更新节奏，要求上下文窗口需匹配单项目的完整数据量，避免截断关键参数。同时投标文稿需严谨匹配模具设计的专业术语，配置时需确保模型能识别专属工程字段，且需支持多源数据的统一索引。

以下配置基于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配单项目模具设计的完整文档与参数总量，避免截断试模报告、改模记录等关键内容 |
| `maxTokens` | 4000 token | 适配投标文稿与报价表的输出长度，确保完整生成报价明细与设计说明 |
| `quoteMaxToken` | 1500 token | 限制单条引用的文档长度，优先提取DFM报告、零件图参数等核心内容 |
| `temperature` | 0.2–0.4 | 降低随机输出概率，确保投标文稿的专业术语与参数准确匹配模具设计标准 |
| `vision` | 开启 | 支持解析CAD零件图、试模样件照片等视觉类数据，补充文本之外的工程信息 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或云端的大模型接入地址，确保请求正常路由 |
| `AIPROXY_API_TOKEN` | 按授权要求填写 | 完成模型接入的身份验证，保障请求权限合规 |

## 容易做错的三处
- 现象：调用大模型时出现GPU资源未被调用，CPU单核占用达100%。原因：未正确配置`AIPROXY_API_ENDPOINT`指向本地部署的大模型服务，导致请求路由至CPU执行。
- 现象：生成的投标文稿中模具参数出现偏差，如脱模斜度、缩水率不符合行业通用标准。原因：`temperature`取值过高，模型生成内容偏离专业规范。
- 现象：生成的报价表中缺少试模缺陷的整改要求。原因：`quoteMaxToken`取值过小，截断了长文档中的核心整改记录。

## 怎么确认配好了
- 提交包含CAD零件图与试模报告的测试数据，查看模型是否能正确识别视觉类内容，验证`vision`配置生效。
- 生成一份模拟投标文稿，核对其中的专业参数是否与预设的模具设计标准一致，验证`temperature`配置的合理性。
- 查看模型引用的上下文内容，确认是否包含完整的DFM报告、改模通知等核心文档，验证`maxContext`与`quoteMaxToken`的取值适配。
- 检查API请求日志，确认请求已正确路由至指定的大模型服务，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置无误。
