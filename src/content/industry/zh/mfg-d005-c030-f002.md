# 橡胶混炼与制品硫化的投标文稿与报价编制：向量模型与索引

本文适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
这个品类的数据来自配方系统、原材料批次记录、密炼机、门尼与流变仪、硫化机及实验室检测设备。日常文档包含配方单、称量记录、混炼曲线、胶料快检报告、硫化工艺卡、模具台账、成品性能报告。数据更新随每车原材料、每批胶料、每模次生产同步，字段包含胶种配比数值、称量偏差范围、混炼温度区间、硫化时长参数、成品硬度指标等，单位涉及千克、摄氏度、分钟、邵氏硬度单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据更新频率高且单条数据体量小但批次多，向量模型与索引需适配高频写入需求。多源异构数据格式差异大，需统一字段映射规则避免索引混乱。配方、工艺类文档的关键参数（如混炼温度、硫化时长）需作为核心检索字段，索引需优先关联高权重字段。单次检索需覆盖多批次历史数据，索引的召回范围需适配生产全流程的历史记录关联，同时需控制索引加载速度以匹配投标报价编制的实时性要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配单条混炼曲线、硫化工艺卡的文本长度，避免块内关键参数拆分 |
| 重叠长度 | 50–80 字符 | 保留跨块的工艺参数关联，防止检索时丢失混炼温度与硫化时长的上下文 |
| `maxToken` | 4096 token | 匹配主流向量模型的输入上限，适配批量配方单的批量检索需求 |
| 相似度阈值 | 0.75–0.85 | 过滤低关联的历史数据，聚焦匹配投标需求的合规工艺参数 |
| 单次搜索上限 | 前 10 条 | 控制检索结果体量，适配投标文稿快速编制的响应速度 |
| `defaultToken` | 1024 token | 配置默认检索上下文长度，平衡检索精度与系统资源占用 |

## 容易做错的三处
- 检索结果出现非对应批次的混炼曲线，原因是未按原材料批次字段配置索引关联规则，导致跨批次数据混淆，可能引发投标文稿中的工艺参数匹配错误。
- 检索请求返回超时错误，原因是单次搜索上限设置过高，且未限制索引扫描的历史数据范围，超出系统响应阈值，影响投标报价的编制效率。
- 配方单检索结果字段为空，原因是未将称量记录、胶料快检的核心字段纳入索引映射，导致向量嵌入时丢失关键检索信息，无法匹配投标所需的工艺合规性要求。

## 怎么确认配好了
- 上传单条混炼曲线文档，检查向量嵌入后的块拆分是否保留完整温度、时长参数，无关键内容截断。
- 输入包含特定硫化工艺参数的检索词，核对检索结果的召回条数是否符合单次搜索上限的设置。
- 模拟批量配方单上传，观察索引更新的耗时是否符合生产数据的更新频率要求。
- 检查配置页面的`maxToken`与`defaultToken`参数是否与当前使用的向量模型输入上限匹配。
