# 水泥熟料与粉磨的投标文稿与报价编制：工作流编排

## 这个品类的数据长什么样
该品类的数据来源包括在线成分分析装置、DCS系统、化验室检测设备、窑磨运行设备、原燃料管理台账、能源计量装置。数据更新节奏分为实时、每班、每日三类。日常文档涵盖生料配料方案、窑炉操作记录、熟料化验报告、质量控制通知单、设备巡检日志、能源消耗报表。文档字段围绕生产核心参数设置，无额外自定义内容。

## 这些特征在「工作流编排」这一环带来什么约束
该品类数据来源分散且更新节奏差异大，实时运行数据需触发式拉取，定时类数据需按班次或每日同步，工作流需适配多数据源的触发规则。日常文档结构多样，需针对配料方案、化验报告等不同文档类型配置差异化的解析规则。核心业务环节依赖实时参数与历史质检数据，工作流需关联对应数据节点自动调用关联文档，同时需配置校验环节规避质量指标偏差引发的风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 配置knowledgeSearch为动态传入的原燃料台账ID与化验报告批次号 | 该品类需动态关联实时或历史业务文档，确保搜索匹配精准 |
| 单次搜索上限 | 前6条 | 该品类核心业务文档量集中，过多条目会超出上下文限额 |
| 最大上下文长度 | 8000–12000 token | 需容纳生料配料方案、窑操作记录、化验报告三类核心文档的完整内容 |
| 触发节点规则 | 按实时数据更新触发，间隔15分钟重试失败任务 | 实时运行参数需及时同步到报价编制流程，保障投标文稿时效性 |
| 文档导出格式 | docx | 投标文稿需符合行业通用的标准交付格式 |
| 版本适配 | FastGPT v4.17.0的工作流节点 | 该版本支持动态变量与多数据源联动，适配品类复杂的数据需求 |

## 容易做错的三处
- 现象：知识库搜索返回空结果，无匹配文档。原因：未在`variables`中正确配置knowledgeSearch的动态传入参数，导致搜索未关联当前项目的原燃料台账或化验报告数据。
- 现象：工作流执行后未生成Word下载链接。原因：未添加内置的文档转换与导出节点，或未配置导出格式为docx。
- 现象：工作流节点迁移后无法正常运行。原因：未重新绑定原有的`nodeId`对应的数据源与变量配置，导致节点参数在新版本环境中失效。

## 怎么确认配好了
- 手动触发工作流，检查`variables`中的knowledgeSearch参数是否正确传入当前项目的业务ID。
- 运行工作流后查看知识库搜索结果，确认返回的文档包含生料配料方案、化验报告等品类核心文档。
- 验证文档导出节点是否生成可下载的docx文件，检查文件内容是否覆盖投标所需的业务数据。
- 查看工作流日志，确认触发节点按预设规则执行，失败任务按配置进行重试。
