# 汽车整车总装的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据通常以VIN为单车主线，包含生产订单、VIN清单、装配作业指导书、拧紧数据、下线检测报告、返修记录、一致性与放行文件等文档。数据来源于ERP/MES系统、VIN与配置系统、供应商批次数据、拧紧工具、EOL检测线及质量追溯系统，更新频率覆盖每车、实时及每班周期，数据字段包含VIN码、零件编号、扭矩值、检测结果等标准化标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于该品类以VIN为单车主线进行大规模混线配置，模型接入时需确保检索数据严格匹配单台车辆的VIN维度，避免跨车辆配置混淆。实时更新的拧紧数据、下线检测报告要求模型响应延迟符合生产节拍，需限制上下文加载时长。大量零件配置项需足够的上下文窗口容纳历史数据，同时需严格控制输出精度，避免错配漏装导致的停线或召回风险。

## 配置怎么定
本文档基于FastGPT v4.17.0编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 12000–16000 token | 需容纳多台车辆的VIN清单、装配要求及历史报价数据，确保检索覆盖完整业务场景 |
| `maxTokens` | 3000–4000 token | 匹配单份投标文稿或报价单的标准输出长度，避免截断关键配置信息 |
| `quoteMaxToken` | 800–1200 token | 适配零件清单、报价明细等单段内容的输出长度，保证信息完整 |
| `toolChoice` | auto | 自动调用文档检索工具匹配VIN对应的零件配置，减少人工干预误差 |
| `temperature` | 0.2–0.4 | 控制输出随机性，确保投标与报价内容严谨一致，符合合规要求 |
| `AIPROXY_API_ENDPOINT` | 企业专属内部代理地址 | 保障数据传输符合内部网络安全规则，避免外部接口泄露生产数据 |

## 容易做错的三处
- 现象：切换知识库向量模型后界面显示切换成功，但检索无进度且无法切换回原模型。原因：未清理旧模型的向量缓存，新旧模型的索引冲突导致系统无法正常加载检索数据。
- 现象：日志出现chat:LLM_model_response_empty字段，大模型调用后返回空内容。原因：`maxContext`设置过高导致模型上下文溢出，或`temperature`参数超出合理区间引发异常退出。
- 现象：相同VIN配置问题多次返回不同的零件清单。原因：未固定`temperature`参数，或未按VIN维度拆分检索上下文，导致匹配到不相关的历史数据。

## 怎么确认配好了
- 提交包含测试VIN的样本数据，核对模型返回的零件配置、拧紧参数与ERP系统导出的原始数据是否一致。
- 查看接口调用日志，确认`AIPROXY_API_TOKEN`验证通过，且无超时或权限报错。
- 连续提交3次相同的测试问题，确认输出结果无明显随机性，配置信息保持一致。
- 调整`maxContext`参数至合理区间，验证上下文加载时长符合生产节拍要求。
