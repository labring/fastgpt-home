# 汽车零部件批量制造的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自客户图纸、特殊特性清单、ERP/MES系统、量检具数据、设备过程参数及供应商质保书。日常文档包含控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料、8D报告。数据按每批、每班或持续采集更新，单份文档包含版本号、工序标识、特性参数、批次编号等字段，部分参数附带公差范围与计量单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来多重约束。数据按批次、班次持续更新，需支持增量索引更新以避免全量重建的耗时。文档类型覆盖结构化报表与非结构化工艺文件，需适配不同格式的文本拆分逻辑。部分文档包含带公差的特性参数与计量单位，向量编码需保留参数与单位的关联信息，避免语义丢失。投标与报价编制需关联历史批次的合规资料，索引需支持按批次、工序维度的精准召回，同时满足整车客户的质量体系约束要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类包含公差参数的文档长度，避免拆分破坏特性参数的语义完整性 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工序与批次信息，防止关键关联内容被拆分截断 |
| 相似度阈值 | 按实测标定 | 需匹配本品类对合规文档的召回精度要求，避免误召回非关联批次的资料 |
| 单次搜索上限 | 前 10 条 | 平衡投标文稿编制的信息完整性与检索效率 |
| `defaultToken` | 4096 token | 适配PPAP资料、8D报告等长文档的向量编码上限 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 导出知识库生成的dataset.csv仅包含index字段，无content字段。原因是未正确配置分块后的文本提取规则，导致向量索引未关联原始文档内容。
- 向量检索结果未返回带公差的特性参数。原因是未针对带单位的结构化字段做特殊处理，向量编码丢失了参数与单位的关联信息。
- 增量索引更新触发超时报错。原因是未配置增量更新策略，每次更新触发全量索引重建，超出本品类高频更新的数据节奏带来的时间限制。

## 怎么确认配好了
- 上传一份典型的PPAP资料，在FastGPT v4.17.0环境下检查向量索引生成后是否能正确提取特性参数与批次信息。
- 执行一次增量索引更新，确认仅新增批次的文档被处理，无全量重建的系统日志。
- 发起一次针对特定工序的检索，验证召回结果包含对应工序的控制计划与巡检记录。
- 拼接检索结果与投标文稿模板，确认总上下文长度未超出配置的`maxToken`限制。
