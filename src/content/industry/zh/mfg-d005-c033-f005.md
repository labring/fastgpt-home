# 汽车零部件批量制造的投标文稿与报价编制：工具调用与插件

## 这个品类的数据长什么样
数据来源包括客户图纸、特殊特性清单、ERP生产管理系统、MES过程监控系统、量检具读数、设备运行参数、供应商质保文件。数据更新节奏为每生产批次、每班实时采集，部分过程参数持续采集同步。日常关联文档包含控制计划、过程流程图、作业指导书、首件与巡检记录、SPC统计报表、PPAP资料、8D整改报告。数据字段包含特殊特性编号、工序公差值、批量生产数量、设备运行时长、质保检验结果等，部分字段带有工程单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据多源且更新频繁，工具调用需支持多数据源的实时同步与批量拉取，避免因数据滞后导致报价偏差。工程类文档包含大量带公差、参数的专业字段，工具调用需精准识别并关联对应业务逻辑。受整车客户强质量约束，工具输出的投标文稿与报价需匹配预设的质量体系格式，需校验特殊特性参数与客户要求的一致性。批量生产的大数据量要求工具调用需适配单批次数据规模，避免单次请求超时或数据截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配多工具调用场景，自动匹配投标文稿生成、数据拉取的工具需求 |
| `functionCall` | 开启 | 强制模型按预设函数格式输出，确保报价参数的结构化提取 |
| 单次请求超时时间 | 120 秒 | 匹配批量生产数据拉取的耗时需求，避免因数据量大导致请求中断 |
| 知识库召回上限 | 前 8 条 | 覆盖批量制造的常用工艺、质保文档，避免冗余信息干扰 |
| 全局变量赋值规则 | 按批次关联参数 | 适配每批生产的动态数据，确保报价与对应批次的工艺参数匹配 |
| 最大上下文长度 | 8000–10000 token | 承载完整的客户图纸要求、批量数据与历史投标模板，避免信息截断 |

## 容易做错的三处
- 现象：调用API时返回的结构化数据中全局变量字段为空，或生成的投标文稿缺少客户要求的特殊特性参数。原因：未配置全局变量与ERP/MES的批次数据关联，导致动态参数未正确赋值。
- 现象：模型未自动触发工具调用，仅输出无工具关联的通用回复内容。原因：未开启`functionCall`强制触发逻辑，或`toolChoice`设置为`none`，未激活工具调用流程。
- 现象：上传量检具的CSV或PDF记录文件时返回400格式错误。原因：未正确配置HTTP请求的多部分表单参数，未按要求封装文件流数据。

## 怎么确认配好了
1. 提交包含批量生产参数的测试请求，检查工具调用返回的结构化数据是否包含对应批次的特殊特性与工艺参数。
2. 查看工具调用日志，确认`functionCall`已触发，模型输出符合预设的函数格式要求，当前FastGPT v4.17.0版本可在工具配置面板直接查看该日志。
3. 上传单批次的SPC报表与客户图纸，验证知识库召回的文档是否覆盖测试场景。
4. 模拟10批次的批量数据请求，检查单次请求是否在120秒内完成，无超时报错。
