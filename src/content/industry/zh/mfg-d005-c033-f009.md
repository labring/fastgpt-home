# 汽车零部件批量制造的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自客户图纸与特殊特性清单、ERP/MES系统、量检具、设备过程参数及供应商质保书。日常处理的文档包括控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料及8D报告。数据更新节奏为每批生产、每班作业同步更新，关键过程参数持续采集。数据字段包含零件编号、特殊特性参数、工序要求、检测结果、质保等级等，单位涵盖毫米、牛米、百分比等行业标准单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的多源异构数据结构、高频更新特性及强合规要求，对模型接入与配置带来多重约束。多源数据需统一格式适配模型输入，高频采集的实时参数要求模型支持增量数据处理。特殊特性参数的精度要求需匹配模型上下文长度，避免截断关键信息。合规性要求下，模型需关联对应文档的版本与审批状态，确保投标文稿与报价的内容符合整车客户的质量体系规范。同时，批量制造的标准化流程需模型输出的报价与文稿匹配工序参数，避免出现字段不一致的情况。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的界面与参数逻辑。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配本品类多文档拼接的上下文需求，避免截断特殊特性、工序参数等关键内容 |
| `maxTokens` | 4000 token | 匹配投标文稿与报价单的常规输出长度，确保完整生成报价明细与合规说明 |
| 工作流/API 工具选择配置 | auto | 支持自动调用工具处理ERP数据提取、SPC报表分析等投标所需的结构化信息 |
| `vision` | 开启 | 支持解析客户图纸、PPAP资料中的图片类附件，匹配品类内图片化文档的处理需求 |
| `temperature` | 0.3–0.5 | 降低输出随机性，确保投标文稿与报价的内容符合行业标准与客户要求的一致性 |
| `quoteMaxToken` | 1500 token | 限定报价明细部分的输出长度，聚焦核心参数与成本核算内容 |

## 容易做错的三处
- 现象为模型调用后返回内容为空，界面显示无有效响应。原因是未正确配置`AIPROXY_API_ENDPOINT`，或本地ollama服务未启动，导致模型请求无法正常送达。
- 现象为上传PPAP资料、SPC报表等文档后出现解析失败报错。原因是未开启`vision`配置，无法处理文档内嵌的图纸图片附件，导致解析中断。
- 现象为配置`toolChoice`为auto后，无法触发工具调用提取ERP数据。原因是本地部署的deepseek-r1:70b模型未预装工具调用插件，或未在FastGPT中关联对应工具节点。

## 怎么确认配好了
- 发起测试请求，输入包含客户特殊特性参数的问题，核对模型返回内容是否包含对应字段与单位。
- 上传包含图片的PPAP资料，检查模型是否能正确提取图片中的标注信息。
- 配置`toolChoice`为auto，发起包含数据提取需求的测试，核对是否触发对应工具调用。
- 调整`temperature`参数，对比不同取值下的输出一致性，确认符合业务要求的取值区间。
