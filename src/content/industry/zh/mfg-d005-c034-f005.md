# 烘焙与方便食品的投标文稿与报价编制：工具调用与插件

## 这个品类的数据长什么样
该品类数据来自面包糕点、饼干、方便面及速冻面点工厂的日常生产与合规文档，包含配方与投料单、生产记录、烘烤/蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告等。数据来源涵盖原辅料合格证明、ERP/MES系统、称量设备、烤炉/油炸线、实验室检测系统及食品追溯台账，更新频率按生产批次、班次或每日更新，核心字段包含过敏原物料清单、生产参数、检验结果与保质期信息。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于该品类数据按生产批次、班次或每日更新，工具调用需绑定实时数据源以拉取最新批次的配方、检验与报价相关数据。过敏原物料清单是核心校验字段，工具调用需精准匹配对应字段，避免遗漏合规信息。生产记录中的烘烤/油炸时序曲线数据，要求插件支持读取分段时序数据片段。多文档核对环节需同时拉取ERP报价数据、实验室检验报告等多类来源，工具调用需支持并行拉取不同数据源的内容。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | auto | 适配多工具并行调用的投标文稿编制场景 |
| 工作流/API 函数调用配置 | 强制触发 | 确保合规数据工具被调用，覆盖过敏原校验环节 |
| 并行调用上限 | 2 个 | 匹配该品类需同时拉取配方与检验数据的需求 |
| 数据源拉取范围 | 近 7 天批次数据 | 适配数据按批次、班次更新的频率 |
| 响应超时设置 | 600 秒 | 预留批量拉取生产时序数据的耗时空间 |
| 上下文窗口长度 | 8000–12000 token | 容纳多份投标相关文档的完整内容 |

## 容易做错的三处
- 调用时返回状态码429，现象为接口返回请求过多错误，原因是并行调用数量超过配置上限。
- 流式输出的内嵌链接仅覆盖当前页面无法跳转，现象为点击链接无新页面弹出，原因是未配置链接的新窗口触发规则。
- 部分区域无法完成API调用，现象为调用时返回连接超时错误，原因是未配置适配的网络访问规则。

## 怎么确认配好了
- 触发一次投标文稿生成流程，检查工具调用拉取的数据是否匹配当前投标批次的生产记录。
- 查看工具调用日志，确认`toolChoice`与`functionCall`参数的配置符合预设规则。
- 测试流式输出的内嵌链接，确认跳转行为符合业务需求。
- 核对工具返回的过敏原信息，确认与数据源中的记录一致。
