# 烘焙与方便食品的投标文稿与报价编制：文档解析与分块

## 这个品类的数据长什么样
该品类的核心数据来自原辅料合格证明、ERP/MES系统、称量系统、烤炉或油炸线、实验室及食品追溯台账。日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据更新频率为每批、每班或每日，字段包含投料量、烘烤温度、时长、过敏原标识等，多以文本段落、表格、时序曲线形式存在。

## 这些特征在「文档解析与分块」这一环带来什么约束
品类内存在10万中文字级的word投标文稿、15000行级的excel生产记录，对分块的语义完整性与处理效率提出要求。高频更新的多源数据需要解析逻辑适配不同文档结构，避免拆分关键业务单元。过敏原标识、投料参数等敏感字段需保留上下文关联，不能因分块断裂导致业务校验出错。大体积文档的批量处理需预留足够解析时间，同时适配向量模型的输入窗口限制。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配烘焙配方、生产记录等文本的语义完整性，同时匹配多数向量模型的输入窗口限制 |
| `chunkSplitter` | 按段落+固定长度混合 | 适配既有文本段落（如投料说明）又有表格数据（如15000行excel）的文档，避免拆分跨语义单元 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 处理10万字符word或15000行excel时，预留足够的解析时间，避免中途超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 10240 MB | 支持上传大体积的生产记录归档与投标文稿，适配批量业务场景 |
| `chunkSettingMode` | 自定义模式 | 针对过敏原标识、投料参数等关键字段，单独调整分块重叠率，保留上下文关联 |
| `customPdfParse` | 启用 | 针对烘烤或蒸煮曲线类文档，自定义解析规则保留图表数据的字段关联，适配品类内的特殊文档格式 |

## 容易做错的三处
- 现象：上传10M以上文件时生成1000+块后出现向量化异常，重试后部分恢复。原因：未针对该品类的长文本文档调整`chunkSize`与分块重叠率，导致部分块超出向量模型输入限制。
- 现象：从DB节点查询的ERP/MES数据返回JSON数组后，无法直接关联至文档分块。原因：未启用`customPdfParse`或未配置对应的数据映射规则，无法将结构化数据库字段与文档分块绑定。
- 现象：15000行的excel生产记录被拆分为过小的块，导致过敏原物料的核对逻辑无法跨块关联。原因：`chunkSplitter`仅使用固定长度分块，未结合段落或行级拆分，破坏了excel中连续投料批次的语义关联。

## 怎么确认配好了
- 上传预设的10万字符级word投标文稿，核对分块列表的长度范围，匹配配置的`chunkSize`区间。
- 导入15000行的excel生产记录，检查分块是否保留了连续投料批次的上下文关联，无跨块断裂的关键业务字段。
- 运行大文件上传任务，确认解析耗时未超过配置的`PARSE_FILE_TIMEOUT_SECONDS`，无超时报错。
- 测试DB节点查询ERP数据，确认返回的结构化数据可直接绑定至对应文档分块，无需额外代码处理。
