# 烘焙与方便食品的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
该品类数据来自面包糕点、饼干、方便面及速冻面点工厂的日常业务，包含配方与投料单、生产记录、烘烤/蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告等。数据来源涵盖原辅料合格证明、ERP/MES系统、称量系统、烤炉/油炸线设备、实验室检测结果及食品追溯台账。数据更新频率按每批、每班或每日执行，文档包含物料名称、投料量、烘烤温度、保质期、过敏原标识等字段，单位涉及千克、摄氏度、天等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多批次高频更新的业务数据要求模型接入时支持增量同步，避免全量拉取占用过多系统资源。多样的文档类型需要配置适配多格式的解析规则，确保配方、检测记录等不同结构的文件可被正确读取与解析。过敏原标识、保质期等敏感字段的准确性要求配置环节开启字段校验，防止投标文稿中出现错标或遗漏。频繁的产品换线带来的文档变更，要求模型上下文配置可灵活调整，以适配不同批次的业务数据规模。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 覆盖多批次配方、生产记录等业务文档的上下文长度，适配投标文稿的全量数据引用 |
| `maxTokens` | 2500 token | 控制单份投标报价或文稿的输出规模，符合行业文档的段落级输出要求 |
| `quoteMaxToken` | 1200–1800 token | 限制业务数据引用的长度，确保原辅料合格证明、检测记录等内容的完整且合规展示 |
| 工作流/API 工具选择配置 | auto | 自动触发工具调用，适配投标过程中实时查询生产数据、保质期信息的需求 |
| `temperature` | 0.4 | 平衡生成内容的准确性与灵活性，避免过敏原、保质期等关键信息出现偏差 |
| `AIPROXY_API_TOKEN` | 按平台分配值填写 | 完成模型接入的身份验证，确保调用权限符合平台规范 |

## 容易做错的三处
- 现象：工作流中调用MCP功能时提示未配置或无法触发。原因：未在模型接入环节开启工具调用权限，或未将MCP插件关联至当前配置的模型。
- 现象：语音识别功能打开后显示浏览器不支持语音输入。原因：未在平台配置中启用语音识别的浏览器兼容模式，或当前浏览器版本不支持Web Speech API。
- 现象：配置重排模型后，问答环节返回重排结果为false。原因：未将重排模型关联至当前知识库的检索链路，或知识库的召回结果条数未达到重排模型的最低输入要求。

## 怎么确认配好了
- 确保当前使用的FastGPT版本为v4.17.0，避免因版本差异导致配置不生效。
- 提交测试用的投标文稿模板，检查生成内容中是否正确引用了配方、保质期等业务字段，核对字段的单位和数值是否符合预期。
- 触发工具调用测试，验证是否能正确调取ERP/MES中的实时生产数据，确认调用链路无报错。
- 调整`temperature`参数后观察生成内容的一致性，确认参数调整对输出的影响符合预期。
