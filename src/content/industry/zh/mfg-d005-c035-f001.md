# 热处理的投标文稿与报价编制：HTTP 接口与外部系统

## 这个品类的数据长什么样
热处理场景的业务数据来源于材料牌号档案、客户技术要求文档、温控仪表、炉温均匀性测试设备、硬度计与金相检测设备，以及车间MES系统。数据更新频率为每炉次或每生产批次，包含热处理工艺卡、装炉布置图、实时炉温曲线、硬度与金相检测报告、设备点检记录、异常处置单等文档。核心字段包括材料牌号、加热保温温度、保温时长、冷却方式、炉号、批次号、硬度检测值，单位涵盖摄氏度、小时、HRC硬度值等行业标准单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该场景的数据按炉次/批次更新且结构包含多类型文档与标准化字段，要求HTTP接口支持按炉号或批次号精准拉取实时数据。多源数据来源需要接口适配对接MES、检测设备等多个外部系统，需支持多字段映射与格式转换。文档中的图片类数据（如装炉图、炉温曲线）要求接口支持二进制或多格式内容传输，避免数据丢失。同时，投标文稿生成需批量关联多炉次数据，接口需支持批量请求或分页拉取，适配高频次的业务调用节奏。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {API_KEY}` | 符合HTTP接口鉴权的通用规范，适配FastGPT平台的接口鉴权要求 |
| `variables` | `{"batch_no": "", "furnace_no": "", "hardness_hrc": ""}` | 匹配热处理投标所需的批次、炉号、硬度核心字段，与业务数据结构对齐 |
| 请求超时时间 | `300–600 秒` | 覆盖单炉次数据拉取、多源数据聚合的合理处理时长，避免短超时导致请求中断 |
| `responseData` | 标准化JSON格式 | 便于投标文稿生成工具直接解析核心字段，减少额外代码转换成本 |
| 上下文绑定规则 | 按炉号关联历史工艺数据 | 确保生成的投标文稿与对应批次的热处理数据精准匹配 |

## 容易做错的三处
-  调用接口返回401未授权错误，现象是控制台返回「Invalid Authentication」，原因是`Authorization`参数未使用`Bearer {API_KEY}`的标准格式，仅传入了原始API密钥。
-  DB节点查询的热处理原始数据无法直接用于文稿生成，现象是返回的`responseData`未映射为投标所需的标准化字段，需要额外编写代码解析原始日志格式。
-  循环节点拼接多炉次数据后调用接口超时，现象是请求无响应或返回504错误，原因是未配置合理的超时时间，且批量传入的炉次数据未做分页处理，超出接口单次请求的容量限制。

## 怎么确认配好了
-  调用鉴权接口，传入配置的`Authorization`参数，确认返回200状态码且无鉴权相关报错。
-  传入测试用的有效炉号，查看`responseData`返回的字段是否包含材料牌号、加热温度、硬度值等投标所需的核心内容。
-  发送批量炉次数据请求，确认接口在设定的超时时间内返回完整的`variables`映射结果，无字段缺失。
-  对接外部文档生成工具，验证传入的`responseData`和`variables`参数能正确生成包含热处理数据的投标文稿片段。
