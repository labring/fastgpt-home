# 热处理的投标文稿与报价编制：工具调用与插件

## 这个品类的数据长什么样
本品类数据来自专业热处理厂、汽车及轴承零部件厂热处理车间的生产与质控环节，日常文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单。数据来源于材料牌号库、客户技术要求、温控仪表、炉温均匀性测试结果、硬度计与金相设备检测数据、MES系统，按每炉次、每批实时更新，单份文档包含工艺参数、检测数值、设备状态等明确字段，单位涵盖温度（℃）、硬度（HV/HRC）、时间（小时/分钟）等。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类数据按炉次、每批实时更新且来源分散，要求工具调用需绑定实时数据接口，避免使用过期的工艺参数或检测结果。多类文档需交叉核对，插件需支持同时检索工艺卡、装炉图、炉温曲线等多源数据。字段单位多样，插件需自动适配参数校验逻辑。投标报价需结合单炉成本与批量系数，工具调用需关联MES系统的设备稼动率数据，确保报价参数与实际生产能力匹配。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本调整。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多源生产数据的检索需求，自动选择合适的工具调用逻辑 |
| 单次工具调用上限 | 前3条 | 单炉次生产数据量有限，过多检索结果会增加上下文冗余 |
| 工具调用超时阈值 | 120 秒 | 需等待温控仪表、硬度计等设备数据的返回，过长超时影响投标效率 |
| `functionCall` | `enabled` | 强制触发结构化工具调用，确保投标文稿的参数格式统一规范 |
| 工具调用重试次数 | 2次 | 避免单次调用失败导致流程中断，同时防止过度消耗接口额度 |
| 知识库关联范围 | 仅绑定热处理工艺与检测文档库 | 避免引入无关知识库内容干扰报价编制的准确性 |

## 容易做错的三处
- 现象：工具调用按钮点击后无响应，界面无报错提示。原因：未正确配置`toolChoice`参数为`auto`或`enabled`，导致系统无法识别工具调用触发逻辑。
- 现象：后台日志显示非工作时段持续触发工具调用，接口额度被快速消耗。原因：未设置插件触发时机的时间限制，或绑定的数据源接口未做权限校验，导致外部请求绕过配置直接调用。
- 现象：生成投标文稿时意外引入了非热处理相关的知识库内容。原因：未限定知识库关联范围，导致系统自动检索了全部绑定的知识库资源。

## 怎么确认配好了
- 发起模拟投标报价请求，查看工具调用日志，确认仅检索了热处理工艺、检测文档库的内容。
- 手动触发工具调用，检查返回结果的格式是否符合结构化要求，参数单位是否与实际生产数据匹配。
- 模拟非工作时段发起请求，确认工具调用未被触发，接口额度未被消耗。
- 测试单次对话流程，确认工具提示仅在报价参数校验阶段出现一次。
