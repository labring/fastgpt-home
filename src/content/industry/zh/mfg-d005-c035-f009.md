# 热处理的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自专业热处理厂、汽车及轴承零部件厂热处理车间的生产与业务系统。日常文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单，字段涵盖材料牌号、加热保温冷却参数、装炉位置、炉温记录、检测结果等，单位涉及温度（℃）、时间（小时）、硬度（HV）等。数据按每炉次、每批更新，直接关联客户投标用的技术参数与报价依据。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据按炉次批量更新且字段多为技术参数，要求模型接入时支持小批量高频数据调用。多类型文档混合输入的场景，包括文本与图像类文档，需要配置适配多模态输入的参数。数据关联客户技术条件与投标报价，要求模型输出的内容需严格匹配给定字段与单位，避免参数偏差。炉次数据的时效性要求配置项需支持快速更新上下文窗口，同时需限制单次处理的token数量，防止超出模型负载。投标场景的严谨性要求配置稳定的错误重试机制，避免因单炉数据异常导致报价或文稿出错。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配单炉次多文档（工艺卡、装炉图、炉温曲线等）的总内容长度，避免上下文溢出 |
| `maxTokens` | `2000–3000 token` | 限制单份投标文稿与报价的输出长度，匹配企业内部文档排版规范 |
| `quoteMaxToken` | `1500 token` | 限定知识库引用的热处理相关文档总token数，确保引用内容聚焦工艺参数与检测结果 |
| `temperature` | `0.1–0.3` | 降低输出随机性，保证投标参数的准确性，避免出现不符合工艺规范的数值 |
| `vision` | `开启` | 支持解析装炉图、炉温曲线等图像类文档，提取其中的温度、装炉位置等关键参数 |
| `AIPROXY_API_ENDPOINT` | `按部署环境填写` | 匹配FastGPT v4.17.0版本的代理地址，确保模型调用链路正常 |

## 容易做错的三处
- 配置`AIPROXY_API_TOKEN`时填写错误，出现403 status code (no body)报错。原因是代理令牌与模型服务商的验证要求不匹配，或令牌未正确配置到FastGPT渠道设置中。
- 对话模型提示词未适配空格识别，导致热处理工艺参数（如保温时间）被错误拆分。原因是提示词未明确要求保留文本中的空格，或未使用支持空格识别的模型配置。
- 尝试接入未在渠道列表中出现的模型版本，无法完成配置。原因是FastGPT渠道配置仅支持已收录的模型类型，未通过自定义接口方式添加未支持的模型。

## 怎么确认配好了
- 测试调用单炉次的热处理文档组合，检查模型返回的输出长度是否符合配置的`maxTokens`限制。
- 提交包含装炉图、炉温曲线的图像文档测试用例，确认模型能够正确提取图像中的参数信息，验证`vision`配置生效。
- 查看FastGPT v4.17.0版本的模型调用日志，确认请求地址与`AIPROXY_API_ENDPOINT`一致，且返回状态码为200。
- 调整`temperature`参数并对比输出结果，确认输出的随机性随参数调整发生符合预期的变化。
