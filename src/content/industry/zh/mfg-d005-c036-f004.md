# 焊接结构件制造的投标文稿与报价编制：工作流编排
本页面基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
数据来源包括设计图纸、材料质保书、焊接设备参数、焊材库、无损检测系统、人员资质台账。日常生成的文档包含焊接工艺评定、焊接工艺规程、焊材领用记录、焊工资格记录、焊缝检验报告、返修单。数据更新节奏为每条焊缝或每批、每班。字段包含焊缝编号、母材牌号、焊材型号、焊工证号、检测结果等，对应单位包括毫米、千克、小时等，结构固定且具有刚性约束。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的整合需求要求工作流支持跨系统拉取不同类型的文档数据。高频更新节奏要求工作流适配批量触发或实时触发，避免数据滞后。固定且刚性的字段结构要求工作流配置严格的字段校验规则，防止无效数据进入报价与文稿生成环节。严重的出错后果要求工作流设置异常分支处理，及时响应裂纹、返修超限等质量问题，确保投标资料符合验收要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按焊缝批次触发 | 匹配每条焊缝或每批的更新节奏，适配投标文稿按批次汇总的需求 |
| `variables` 映射规则 | 绑定母材牌号、焊材型号、焊工证号等字段 | 对应日常文档的固定字段结构，确保数据准确性 |
| 节点超时时间 | 300–600 秒 | 覆盖跨系统拉取焊接设备参数、无损检测数据的耗时 |
| `nodeId` 绑定规则 | 按文档类型绑定对应节点 | 区分焊接工艺评定、焊缝检验报告等不同文档的处理流程 |
| 异常分支配置 | 触发后推送告警至指定节点 | 应对裂纹、返修超限等出错后果，符合质量刚性约束的要求 |

## 容易做错的三处
- 工作流执行至某节点后停滞，无报错日志。原因：未配置`variables`的跨系统字段映射，节点等待未传入的必填参数超时后静默终止。
- 节点返回Premature close错误。原因：拉取无损检测系统数据时，单次请求数据量超出接口限制，连接被提前关闭。
- 调用飞书多维表格接口失败，无报错提示。原因：未在`nodeId`绑定规则中配置飞书接口的鉴权参数，请求未携带有效令牌。

## 怎么确认配好了
- 触发一次测试批次的工作流，检查`variables`是否正确映射了母材牌号、焊材型号等字段。
- 查看节点日志，确认无Premature close类错误，异常分支触发后推送告警。
- 验证飞书多维表格接口调用，确认数据成功写入对应工作表的指定列。
- 模拟返修超限的异常场景，确认工作流触发异常分支处理。
