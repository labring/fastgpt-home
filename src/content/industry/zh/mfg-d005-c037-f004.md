# 生产计划与车间排程的投标文稿与报价编制：工作流编排

## 这个品类的数据长什么样
该品类的数据来源于ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。更新节奏随日常业务变动，包含每日、每周更新，以及订单生成、异常发生时的即时更新。日常处理的文档包括销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单，字段涵盖订单编号、物料编码、工序工时、设备负载率、在制品数量等，单位包含件、小时、台套等。FastGPT v4.17.0 支持针对该品类数据的多节点工作流编排。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源跨多业务系统，要求工作流配置多节点分别拉取不同数据源的信息，避免单一节点负载过高。更新节奏不固定，需支持动态触发，防止固定周期拉取导致数据过时影响排程准确性。文档间存在强关联关系，比如工单需绑定BOM与工艺路线，工作流需通过变量传递关联字段，确保数据一致性。此外，排程需应对插单、缺料等异常场景，工作流需支持分支编排以适配不同业务分支的处理逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量绑定规则 | 按`variables`绑定订单编号、物料编码、工序工时等多字段 | 品类数据关联多文档，需通过变量统一传递关联字段，避免数据断裂 |
| 节点触发时机 | 按`nodeId`绑定前序节点完成信号 | 排程数据依赖前置工单、物料清单，需等待前序节点拉取完成后执行，确保数据完整 |
| 重试策略 | 重试3次，间隔60秒 | ERP接口调用可能偶发超时，重试可降低失败率，适配生产数据的实时性要求 |
| 单次数据拉取上限 | 前5条 | 适配ERP接口单次返回数据量，避免接口过载 |
| 结果缓存阈值 | 800–1200字符 | 投标文稿需整合多工序排程数据，缓存长度适配文档拼接与展示需求 |
| 结果输出配置 | 仅保留最终报价与排程说明节点 | 投标文稿仅需展示最终结果，中间排程计算过程无需对外呈现 |

## 容易做错的三处
- 现象：工作流节点下拉菜单仅显示单个变量选项，无法绑定多文档字段。原因：未正确配置`variables`的多字段绑定规则，仅选择了单一关联字段。
- 现象：调试节点时无法停止当前调试模式，界面出现无响应状态。原因：未设置节点超时参数，长时间占用运行资源导致进程阻塞。
- 现象：工作流仅调用单一大模型处理全量排程与报价数据，无法分步处理中间结果。原因：未拆分工作流节点，将排程计算、报价生成合并为单个节点，未配置分步执行逻辑。

## 怎么确认配好了
- 测试拉取ERP订单数据，检查工作流中绑定的`variables`是否包含订单编号、物料编码等多个字段。
- 模拟插单场景触发工作流，确认节点按`nodeId`绑定的前序信号依次执行，无提前或延迟运行情况。
- 提交测试用的排程数据，确认最终输出节点仅展示报价与投标文稿内容，中间工序数据未对外暴露。
- 模拟ERP接口超时场景，检查工作流是否按配置的重试次数自动重试，未出现直接失败的情况。
