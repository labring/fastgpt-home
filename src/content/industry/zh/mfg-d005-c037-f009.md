# 生产计划与车间排程的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单。数据取自ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。数据更新节奏为每日、每周，或随订单、异常情况触发更新。文档字段包含订单编号、物料编码、产能单位、工序耗时、在制品数量等，无统一固定格式，随企业ERP系统配置存在差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且更新节奏灵活，要求模型接入配置需适配多格式输入与动态数据加载。多源异构的文档结构会增加模型的上下文处理压力，需合理限制单次输入的内容规模。投标场景下的报价与排程结果需具备较高一致性，对模型输出的稳定性有明确要求。同时，数据更新频率较高，配置需支持快速同步最新的订单、产能信息，避免因数据滞后导致的排程偏差。此外，不同企业的文档字段存在差异，配置需具备一定的灵活性以适配不同的输入格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 该品类数据包含多份关联文档，需容纳足够的上下文信息以关联订单、排程与产能数据 |
| `maxTokens` | `4000 token` | 限制单次输出长度，避免生成的投标文稿与排程内容超出排版规范 |
| `temperature` | `0.2–0.4` | 降低输出随机性，保障排程参数与报价逻辑的一致性，适配投标场景的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 填写本地部署的模型API地址 | 适配企业内部部署的生产计划相关模型，保障数据不出企业内网 |
| `AIPROXY_API_TOKEN` | 按实际生成的密钥填写 | 验证模型调用权限，防止未授权访问 |

## 容易做错的三处
- 现象：调用本地部署的m3e模型时返回调用失败，日志显示连接超时。原因：FastGPT v4.17.0版本中，`AIPROXY_API_ENDPOINT`配置未正确指向本地模型的openapi端口，或端口权限未开放。
- 现象：接入oneapi embedding模型时出现报错，无法单独配置索引模型。原因：未正确区分对话模型与索引模型的配置入口，误将embedding模型配置到了对话模型的参数栏中。
- 现象：调用模型后返回的排程结果字段缺失，如工序耗时、物料编码未正常生成。原因：`maxContext`取值过小，未能完整加载关联的BOM与工艺路线数据，导致模型无法提取必要字段。

## 怎么确认配好了
- 执行模型调用测试，输入一份模拟销售订单与产能数据，检查返回的排程结果包含工序、物料、交期等核心字段。
- 查看系统日志，确认无`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`相关的权限、连接报错。
- 导入多份不同类型的日常文档，如工单、缺料清单，验证模型能正确关联不同数据源的信息。
- 调整`temperature`参数至0.3，连续调用3次相同输入，确认输出结果的差异在可接受范围内。
