# 生产计划与车间排程的投标文稿与报价编制：知识库检索与召回

## 这个品类的数据长什么样
这个品类的典型数据来自制造企业的PMC、计划、车间调度与物控部门，日常生成的文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单等。数据多取自ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品及供应商到货信息。数据更新频率通常为每日、每周，或随订单、异常情况实时更新。文档多包含订单编号、物料编码、工序名称、设备型号、产能数值、交期节点等字段，单位涉及件、小时、台、天等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
品类数据包含多维度的生产与订单关联信息，且字段多为结构化数值与编号，要求检索需精准匹配业务字段，避免无关文档混入。高频实时更新的数据会带来知识库增量同步的压力，需适配动态更新的召回逻辑，确保召回内容为最新的产能、排程与订单信息。不同文档的字段格式差异较大，如排产表与工单的字段维度不同，需支持多文档结构的统一召回与整合。投标与报价场景需快速关联历史订单、产能数据，对检索的响应速度有明确要求，且需限定检索范围至品类相关的业务数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本设定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 品类数据多为结构化字段，需过滤低匹配度的非业务相关文档，该区间可平衡召回精度与覆盖范围 |
| `limit` | 前8–12条 | 投标与报价场景需快速整合有限的核心生产数据，过多召回会超出上下文窗口限制 |
| `searchMode` | `embedding` | 品类数据包含大量数值与编号字段，向量搜索可精准匹配业务关联的生产计划与订单信息 |
| `usingReRank` | 开启 | 多文档召回后需按业务相关性重排，确保优先返回与当前投标订单匹配的产能、排程数据 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可基于投标订单关键词扩展查询，补充关联的物料需求、设备产能等隐性关联数据 |
| `collectionIds` | 绑定生产计划与车间排程专属知识库集合 | 避免召回非生产类文档，确保检索范围仅覆盖品类相关的业务数据 |

## 容易做错的三处
- 单对话关联知识库数量超出限制：界面返回“关联知识库已达上限”报错，原因是未提前规划专属知识库集合，将无关文档混入导致配额耗尽。
- 召回结果总字数超出上下文窗口：返回结果被截断或无法生成完整报价，原因是未设置合理的`limit`参数，召回过多文档导致上下文溢出。
- 召回结果排序混乱：返回的排程数据与当前投标订单无关，原因是未启用`usingReRank`，未按业务相关性对召回结果进行重排。

## 怎么确认配好了
- 检查知识库集合绑定：确认仅绑定生产计划与车间排程相关的知识库，无无关文档混入。
- 测试检索匹配度：输入某订单编号，验证召回结果包含该订单对应的物料需求、设备产能等字段，且过滤后的结果符合`similarity`阈值要求。
- 验证重排功能：输入插单场景的查询词，确认召回结果优先返回最新的设备班次与产能数据。
- 确认扩展查询生效：输入投标交期关键词，验证自动关联了交期变更单、周日排产表等相关文档。
