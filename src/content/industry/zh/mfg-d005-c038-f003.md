# 生物制品与无菌生产的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源包括细胞库与种子批、过程分析、洁净区监测、MES、LIMS、设备完整性测试。更新节奏为每批生产、实时监测数据、按固定监测计划更新。日常文档涵盖细胞库或种子批记录、培养纯化记录、无菌灌装记录、环境监测、培养基模拟灌装、无菌检验、批放行资料，包含批次标识、监测点位编号、检测数值、时间戳、设备编号等字段，单位涉及菌落形成单位每平方米、摄氏度、小时等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
品类数据分散于多个系统，多轮对话需精准匹配不同数据源的对应记录，避免跨模块数据混淆。实时与按计划更新的监测数据要求上下文需按批次隔离历史对话，确保不同生产批次的参数不被混用。专业文档包含大量细分检测字段与单位，提示词需明确限定调用的文档类型与字段范围，防止生成不符合生产规范的内容。同时，无菌生产的出错后果严重，对话生成的文稿需严格锚定真实检测数值，避免出现与实际数据不符的表述。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配生物制品与无菌生产的投标场景需求：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 匹配单批次生物制品核心文档的数据量，避免截断关键检测记录 |
| 历史对话隔离规则 | 按`chatId`分组 | 确保不同用户或生产批次的对话数据互不干扰，符合数据安全要求 |
| 变量绑定配置 | 绑定`variables`为生产批次号 | 精准调用对应批次的细胞库、灌装记录等文档，缩小检索范围 |
| 历史对话召回条数 | 前3条 | 减少冗余历史对当前生成逻辑的干扰，聚焦当前投标任务 |
| 会话超时时间 | 600 秒 | 适配多轮编辑与数据校验的时长，避免中途中断 |
| 提示词上下文裁剪 | 按生产批次筛选 | 仅保留当前投标对应批次的检测数据，优化提示词输入的信息质量 |

## 容易做错的三处
- 现象：API调用后响应预览中`Human`字段为空。原因：未正确传递`messages`参数的用户消息结构，导致对话历史的用户端内容未被记录。
- 现象：多用户共享同一应用时，无法查看各自的历史对话记录。原因：未启用按`chatId`隔离会话的配置，导致所有用户的对话数据被合并存储。
- 现象：生成的投标报价包含非当前批次的检测数据。原因：未绑定`variables`为对应生产批次号，导致检索范围覆盖了无关批次的文档记录。

## 怎么确认配好了
- 发起一次测试对话，输入指定生产批次的查询，核对生成内容是否仅包含该批次的文档数据。
- 切换不同的测试账号，核对各自的历史对话是否仅显示自身的交互记录。
- 调用API获取对话数据，核对返回的`messages`参数中是否包含完整的用户与助手对话内容。
- 模拟多轮编辑操作，核对会话是否在合理时长内正常完成，未触发意外中断。
