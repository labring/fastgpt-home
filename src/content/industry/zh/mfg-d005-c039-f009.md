# 电机与发电机制造的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
电机与发电机制造的业务数据来自电磁设计数据、铜线和绝缘材料批次、绕线设备、平衡机、电气试验台、ERP/MES系统。数据按每台或每批电机更新，每次型式变更后同步更新。日常文档包含绕组工艺卡、绝缘处理记录、动平衡报告、耐压绝缘测试记录、型式与出厂试验报告，字段涵盖绕组匝数、绝缘厚度、试验电压、温升数值等，对应单位为匝、毫米、千伏、摄氏度。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据按单台或每批电机更新，且包含电磁、绝缘、机械平衡三类专业字段，模型接入时需限定上下文范围，避免冗余数据干扰专业字段的解析。由于文档来源覆盖多类设备与系统，需适配多源数据的接入格式，同时控制单次调用的token上限，避免因数据量过大导致超时。由于投标文稿需严格匹配专业数值，需降低生成过程的随机性，保障数据准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本说明。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 匹配单台电机投标所需的试验报告、工艺卡等文档总长度，避免超出模型上下文限制 |
| `maxTokens` | 2000–3000 token | 满足投标文稿与报价的生成长度需求，同时控制单次调用成本 |
| `quoteMaxToken` | 1500 token | 限定召回的专业文档（如绕组工艺卡）的最大长度，确保核心数据优先被引用 |
| `temperature` | 0.2–0.4 | 降低生成随机性，保障绕组匝数、试验电压等专业数值的准确性 |
| `AIPROXY_API_ENDPOINT` | 按模型服务商提供的官方地址填写 | 适配接入的各类大模型的接口路径 |
| `AIPROXY_API_TOKEN` | 按申请的专属密钥填写 | 完成模型调用的身份验证，保障接口安全 |

## 容易做错的三处
- 现象：调用模型时返回`Cannot read properties of null (reading 'q')`，原因：未正确配置`AIPROXY_API_TOKEN`或接口地址，导致模型返回空的响应字段
- 现象：接入DeepSeek Code模型时生成的报价内容偏离电机专业数据，原因：未限定`maxContext`范围，混入了无关的代码训练数据
- 现象：无法正常接入指定模型，原因：未确认模型是否支持通过FastGPT代理接口调用，或未正确配置`AIPROXY_API_ENDPOINT`的适配路径

## 怎么确认配好了
- 核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容，与模型服务商提供的官方信息一致
- 发起一次测试调用，查看返回内容中是否包含绕组匝数、试验电压等电机制造专业字段的准确引用
- 检查上下文召回的文档数量，确保仅包含当前投标项目对应的绕组工艺卡、试验报告等数据
- 查看调用日志，确认无`Cannot read properties of null`类的报错信息
