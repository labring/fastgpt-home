# 电池PACK与储能系统集成的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据主要来自电芯分容数据、生产执行系统（MES）、焊接设备、扭矩工具、BMS软件版本库及EOL试验台。日常文档包含电芯配组规则、物料清单（BOM）、焊接与扭矩作业记录、BMS刷写日志、绝缘耐压检测报告、EOL测试数据、系统配置清单。数据更新频率为每台电池包或储能柜产出时更新一次，同时伴随BMS软件版本变更同步更新。数据字段包含电芯参数、装配扭矩值、检测电压、软件版本号等，无统一跨厂商格式，需针对单批次生产文档提取对应字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据分散于多类生产设备与系统，且单批次数据更新频率高，多轮对话需支持跨数据源的上下文关联，确保每次提问都能调用最新的批次文档。不同类型的生产文档字段差异较大，提示词需明确指定各文档的提取规则，避免混淆不同文档的参数。投标文稿与报价编制需核对多维度参数，多轮对话需保留历史核对记录，防止重复输入相同信息导致的错误。同时，数据无统一格式，提示词需适配单批次文档的字段结构，确保提取内容符合投标要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话历史保留时长 | 7200 秒 | 覆盖单批次电池包投标从需求提交到定稿的完整周期 |
| 上下文窗口大小 | 8000–12000 token | 适配多份生产文档、BOM与检测报告的内容加载 |
| 变量绑定规则 | 按生产批次关联`variables` | 确保每次调用都能提取对应批次的专属生产数据 |
| 多轮对话历史调用 | 启用`messages`历史记录 | 保留每一轮参数核对的过程，避免重复输入相同信息 |
| 对话ID管理 | 按投标项目ID生成`chatId` | 区分不同投标项目的对话内容，便于后续归档与查询 |
| 提示词模板更新 | 随BMS版本变更同步更新 | 适配最新的软件配置参数要求 |

## 容易做错的三处
- 现象：配置多轮对话后，无法在数据库中检索到对应`chatId`的对话记录。原因：未按投标项目ID生成唯一`chatId`，导致对话记录未正确归档，无法通过项目维度查询。
- 现象：知识库搜索调试正常，但正式AI对话时未返回知识库匹配的内容。原因：未在提示词中明确关联`variables`绑定的生产文档作为参考依据，导致对话上下文未加载对应数据。
- 现象：程序执行模块生成的结果无法作为背景知识传入AI对话模块。原因：未将程序输出结果绑定到`variables`变量中，导致对话上下文无法获取该内容。

## 怎么确认配好了
- 发起一轮针对单批次生产参数的提问，检查对话界面中是否保留`messages`历史记录，确认每一轮的输入与输出均被正确存储。
- 查看`chatId`是否与当前投标项目ID一致，确认不同项目的对话记录未发生混淆。
- 调用程序执行模块生成测试数据，将其绑定到`variables`变量后发起提问，确认AI对话能正确引用该测试数据。
- 调整上下文窗口大小，验证加载的生产文档数量与内容符合当前投标需求，无截断或遗漏。
