# 电镀与化学表面处理的投标文稿与报价编制：文档解析与分块

## 这个品类的数据长什么样
该品类的数据来自客户表面处理规范、槽液化验结果、整流器运行数据、在线水质监测记录与危废管理台账。更新节奏覆盖每槽次、每班及固定监测周期。日常文档包含槽液分析记录、工艺参数卡、挂具使用记录、膜厚与附着力报告、危废台账、废水监测记录。文档字段多为工艺参数、监测数值与合规记录，单位涉及浓度、温度、电流、膜厚、重量等类别。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档更新频率高且类型多样，覆盖槽液记录、工艺卡、合规台账等多类格式，文档解析需适配结构化与半结构化内容，避免分块破坏工艺参数与对应监测数据的绑定关系。不同文档的字段单位存在差异，分块时需保留数值与单位的关联，防止后续调用时出现参数匹配错误。危废与废水相关记录涉及合规要求，分块需确保合规条目不被拆分至不同块中，避免投标时合规信息缺失。同时，数据来源分散导致文档排版不统一，需适配非标准化表格，防止解析时丢失关键字段。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 该品类文档包含多组连续的工艺参数与监测数据，该区间可保留单组数据的完整性，避免参数拆分 |
| `chunkSplitter` | 按段落+表格拆分 | 适配槽液记录、工艺卡等混合格式文档，保留段落与表格内数据的关联 |
| `customPdfParse` | 启用 | 该品类PDF文档多为带格式的工艺卡与监测报告，启用后可保留原始排版与字段结构 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 部分大型危废台账或批量监测记录文件体积较大，该时长可覆盖完整解析流程 |
| `chunkSettingMode` | 手动配置 | 需针对不同文档类型调整分块规则，手动配置可灵活适配多类文档格式 |

## 容易做错的三处
- 现象：PDF解析过程中出现报错，日志显示解析失败。原因：未启用`customPdfParse`配置，默认解析逻辑无法适配带复杂表格的电镀工艺与监测PDF文档。
- 现象：上传的文件未直接传递给大模型，而是被系统转为纯文本后发送。原因：未开启`customPdfParse`配置，触发了通用文本解析流程，未保留原始文档的排版与字段结构。
- 现象：解析后的分块结果中，膜厚数值与对应单位被拆分至不同块中。原因：`chunkSize`取值过小，导致连续的工艺参数与单位被拆分，破坏了数据的绑定关系。

## 怎么确认配好了
- 上传一份典型的电镀工艺PDF文档，查看解析后的文本是否保留了表格内的槽液浓度、温度等字段与单位的绑定关系。
- 在文件集合创建API请求中添加`customPdfParse`参数，确认接口返回的解析配置与预设值一致。
- 调整`chunkSize`取值后，对比不同分块长度下的文档拆分结果，确认单组工艺参数未被拆分。
- 上传单份大型危废台账文档，确认解析耗时未超过`PARSE_FILE_TIMEOUT_SECONDS`的配置值，无超时报错。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
