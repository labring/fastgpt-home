# 电镀与化学表面处理的投标文稿与报价编制：表单与交互

## 这个品类的数据长什么样
该品类的数据来自客户表面处理规范、槽液化验报告、整流器运行数据、在线水质监测记录与危废管理台账。数据按每槽次、每班或监测要求更新，核心文档包含槽液成分参数卡、挂具使用记录、膜厚与附着力检测报告、废水排放台账。字段包含槽液离子浓度、pH值、挂具数量、膜厚（μm）、电流（A）、排放浓度（mg/L）等，需按单次投标的客户要求调整字段维度，无统一固定格式。

## 这些特征在「表单与交互」这一环带来什么约束
数据的多来源与按批次更新要求，要求表单需支持快速关联不同周期的工艺与监测数据，避免手动重复录入。字段的特定单位与非统一格式，要求交互环节需内置单位校验与格式适配逻辑，防止参数不匹配。危废与排放数据的合规性关联，要求表单需在提交前触发合规性检查，避免投标文件出现超标数据。同时，投标文稿需快速调用最新的槽液与客户规范数据，要求交互环节支持按投标项目分类存储与调用历史数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `formInput` | 绑定客户规范、槽液参数、膜厚数据的自动填充 | 减少手动录入误差，确保投标数据与实际工艺一致 |
| `userSelect` | 按槽次分类召回前10条历史工艺记录 | 快速调用常用投标所需的历史数据，避免过多冗余信息 |
| 单次召回上限 | 5条 | 限制背景知识范围，避免无关数据干扰报价计算 |
| 上下文长度 | 8000 token | 覆盖完整的工艺参数、客户规范与监测记录 |
| 字段校验触发时机 | 表单提交前实时校验 | 提前发现单位或格式错误，降低投标文件出错概率 |
| 超时阈值 | 300秒 | 适配多文档加载的耗时，避免提交失败 |

## 容易做错的三处
- 现象：对话返回的报价中混入了过期3个月的槽液数据，原因：未限定`userSelect`的召回时间范围，调用了非本次投标周期的历史记录。
- 现象：大模型输出的投标文稿包含未关联的危废排放超标数据，原因：未配置`formInput`仅绑定投标所需的合规字段，混入了无关监测数据。
- 现象：提交表单后出现无明确提示的校验失败，原因：未设置字段校验的专属报错文案，仅返回通用错误提示。

## 怎么确认配好了
- 提交包含非标准单位的膜厚值，检查是否触发字段校验提示，校验规则需按当前投标的客户要求调整。
- 选择单条历史槽次记录，检查是否仅调用该记录的工艺数据，未混入其他批次的信息。
- 测试调用客户表面处理规范字段，检查是否正确关联到报价计算的逻辑中。
- 提交完整表单，检查返回结果的耗时是否符合预期，超时阈值需按实际文档加载情况调整。
