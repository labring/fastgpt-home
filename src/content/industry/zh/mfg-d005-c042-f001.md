# 石油炼制的投标文稿与报价编制：HTTP 接口与外部系统

## 这个品类的数据长什么样
石油炼制场景的业务数据来自生产运行、工艺、调度、设备与化验部门的日常文档，包括操作规程、生产方案、物料平衡、馏出口质量报告、联锁台账、交接班记录、变更管理文件。数据来源覆盖DCS/APC、LIMS、罐区计量、原油评价、设备管理系统、能源系统，更新频率涵盖实时、每班、每日。业务上存在多套连续装置通过物流与氢气能源网络耦合、原料性质波动大的特征，区别于精细化工的多品种间歇批次生产模式。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源异构的数据来源要求接口需兼容不同系统的返回格式，例如LIMS的质量检测数据与DCS的工艺运行数据字段结构差异较大，需针对性配置数据提取规则。混合更新频率要求接口适配不同的拉取周期，避免过度占用系统资源或遗漏关键数据。多装置耦合的业务逻辑要求接口支持联动拉取多装置的负荷、物料平衡数据，确保投标文稿中的数据关联性准确。原料性质波动大的特点要求接口能动态适配不同原油对应的参数范围，避免返回数据不符合投标需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | `Bearer {企业内部API密钥}` | 对接炼油企业内部异构系统需进行身份验证，确保数据访问权限合规 |
| `variables` | `{原油评价数据, 装置负荷数据, 馏出口质量数据, 知识库查询上下文}` | 包含投标所需的核心业务数据与知识库查询的上下文信息 |
| `responseData` | 提取物料平衡、馏出口质量报告、文件集合ID字段 | 提炼投标与知识库查询所需的核心数据，过滤冗余信息 |
| 单次数据拉取上限 | 前10条 | 炼油业务数据条目较多，限制返回条数避免接口过载 |
| 接口超时设置 | 5-10秒 | 适配DCS、LIMS等系统的实际响应延迟，按实测标定 |
| 知识库绑定配置 | 绑定两个目标业务知识库 | 满足同时查询同一账号下两个知识库的需求 |

## 容易做错的三处
- 现象为oneapi测试接口失败，返回连接超时或403状态码。原因是未配置正确的企业内部系统地址，或`Authorization`参数格式不符合系统验证要求。
- 现象为多分支流程中重复发起HTTP请求，总耗时超过预期。原因是未将HTTP请求节点前置，未通过`variables`复用请求结果，导致每个问题分类分支都单独调用接口。
- 现象为返回的知识库查询结果未包含文件集合ID。原因是未配置`responseData`提取规则，未指定提取文件集合ID字段。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本。
1. 调用配置完成的HTTP接口，检查`Authorization`验证是否通过，返回的`responseData`是否包含预期的炼油业务字段。
2. 模拟不同更新频率的数据源（实时、每班、每日），验证接口是否能稳定拉取对应周期的数据。
3. 测试多分支问题分类流程，确认所有分支都能复用已发起的HTTP请求结果，避免重复调用。
4. 触发接口异常场景，检查重试机制是否按配置触发并生效。
