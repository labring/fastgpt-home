# 石油炼制的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
石油炼制领域的业务数据来自DCS/APC、LIMS、罐区计量、原油评价、设备管理系统、能源系统，更新节奏覆盖实时、每班、每日。日常业务文档包含操作规程、生产方案、物料平衡、馏出口质量报告、联锁台账、交接班记录、变更管理文件，文档字段涵盖原料性质参数、装置运行参数、质量检测指标、设备状态标识等，对应单位包含质量、体积、温度、压力等工业常用单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引系统兼容结构化报表与非结构化工艺文档的混合输入，避免格式解析错误。差异化的更新节奏需要索引支持增量同步与批量更新并行的模式，分别适配实时工艺数据与每日报表的同步需求。投标文稿需关联原油性质、装置负荷等精准业务数据，要求向量索引能关联特定业务字段的语义匹配，确保召回内容贴合投标所需的生产参数。多装置耦合的业务逻辑要求索引保留跨文档的工艺关联特征，避免召回孤立的单一装置数据，保障投标方案的完整性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，具体设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配炼油工艺文档中单段操作说明、物料平衡表的常规长度，避免语义断裂 |
| 重叠长度 | 100–150 字符 | 覆盖跨块的工艺关联逻辑，比如联锁条件与操作步骤的衔接 |
| `maxToken` | 4096 token | 适配bce-embedding-v1模型的输入上限，兼容长文档分块后的总长度 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非工艺相关文档，确保召回内容贴合投标所需的生产参数 |
| 单次搜索上限 | 前 8 条 | 平衡召回精度与投标文稿的篇幅限制，避免冗余数据混入 |
| `defaultToken` | 按实测标定 | 适配自定义嵌入模型的默认输入参数，避免token溢出 |

## 容易做错的三处
- 调用chunk模式的pushdata api上传数据后，界面持续显示索引中状态无变化。原因是未配置对应数据更新频率的索引同步规则，多系统实时数据堆积导致索引队列阻塞。
- 嵌入模型调用返回`该令牌无权使用模型：text-embedding-3-large`的报错。原因是未切换为适配的bce-embedding-v1模型，或未正确配置嵌入模型的访问密钥权限。
- 索引召回的内容包含大量非工艺相关的行政文档，无法匹配投标所需的生产参数。原因是分块长度设置过长导致语义切割错误，或相似度阈值设置过低，召回了低匹配度的无关数据。

## 怎么确认配好了
- 上传单份原油评价文档，检查索引完成状态是否在10分钟内更新完成，匹配实时数据的同步要求。
- 调用嵌入模型测试接口，输入物料平衡表片段，确认返回的向量数据无token溢出报错，匹配`maxToken`的配置值。
- 发起「某原油牌号的投标报价所需生产方案」的检索，检查召回结果是否包含对应装置负荷、馏出口质量指标的关联文档。
- 查看索引队列监控面板，确认多系统数据同步时无堆积报错，符合实时、每班、每日的更新节奏要求。
