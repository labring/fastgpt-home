# 石油炼制的投标文稿与报价编制：工作流编排

## 这个品类的数据长什么样
石油炼制场景的核心数据来自DCS/APC控制系统、LIMS实验室管理系统、罐区计量系统、原油评价报告、设备管理系统及能源管理系统。日常文档涵盖操作规程、生产方案、物料平衡表、馏出口质量报告、联锁台账、交接班记录与变更管理文件。数据更新频率覆盖实时、每班与每日，字段包含原油馏程、装置负荷、产品馏分指标、罐区液位等，部分字段带有专属单位，如馏程以摄氏度计量，物料平衡以吨为单位。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构数据的更新节奏差异，要求工作流支持混合触发规则，兼顾实时装置数据与每日更新的原油评价数据。多套连续装置通过物流与能源网络耦合，工作流需串联多个数据拉取节点，确保各环节参数联动一致。文档类型多样且专业字段多，工作流需适配不同文档的解析逻辑，精准提取投标所需的核心指标。数据异常可能引发严重生产风险，工作流需配置明确的失败处理与告警链路，保障编制过程的稳定性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按实时数据更新触发 + 每日定时触发 | 匹配装置运行数据的实时更新与原油评价报告的每日更新节奏 |
| `variables` | 包含原油性质、装置负荷、产品质量指标的变量组 | 为投标文稿与报价提供动态代入的核心业务参数 |
| 节点超时设置 | 600 秒 | 覆盖多装置数据拉取与复杂物料平衡计算的耗时需求 |
| 知识库检索标签筛选 | 启用，按文档类型匹配 | 精准调取操作规程、物料平衡等专业文档，避免无关内容干扰 |
| 失败重试次数 | 2–3 次 | 应对实时数据拉取的临时网络波动或系统短暂异常 |
| `nodeId` | 绑定核心数据节点与报价生成节点 | 确保工作流中参数传递的准确性与链路完整性 |

## 容易做错的三处
- 现象：工作流调试时出现两次思考过程输出。原因：未关闭工具调用节点的自动追问配置，导致工具调用后触发额外思考环节。
- 现象：API调用无法获取工作流执行中的MCP工具调用记录。原因：未在工作流配置中开启工具调用日志采集开关，导致日志未生成。
- 现象：代码运行组件报错，提示输入参数格式异常。原因：未将炼油场景的专业字段（如馏程数据）转换为统一格式，导致组件无法识别。

## 怎么确认配好了
- 触发预设的触发规则，验证工作流是否按预期启动。
- 检查工作流输出的文稿与报价内容，确认是否包含当前业务场景下的核心参数。
- 模拟数据异常场景，验证失败重试与告警触发是否正常生效。
- 调用指定API接口，验证是否能获取到工作流执行过程中的工具调用日志。
