# 精细化工间歇合成的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
精细化工间歇合成的业务数据来源于配方与工艺库、原料批次台账、反应釜DCS系统、称量系统、LIMS实验室管理系统及仓储系统。数据更新节奏为每批生产、每个关键步骤触发一次，日常文档包含批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据字段包含批次号、投料量、反应温度、反应时长、清洗确认记录等，其中配方参数属于保密内容，需严格限定访问范围。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类按批次切换生产的特性，要求多轮对话必须锁定单批次的上下文数据，避免跨批次的工艺参数混淆。高频更新的生产数据需要对话系统实时拉取最新的投料、反应记录，提示词需限定仅调用当前批次的文档内容。多环节的生产流程要求对话按投料复核、反应终点判断、清场确认等步骤引导，提示词需嵌入各环节的校验规则。保密的配方参数要求对话系统对敏感字段做权限过滤，防止非授权访问。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定当前投标项目对应的批次号、原料批次ID、清场记录ID | 该品类数据按批次关联，需锁定单批次的生产文档，避免调用错误的历史数据 |
| `messages` | 保留前10轮对话上下文，截断超出8000 token的历史内容 | 投标沟通需保留历史报价、技术参数的对话记录，同时控制上下文长度以保证响应速度 |
| 最大上下文 | 6000–10000 token | 该品类单批次的工艺文档、检验报告数据量较大，需适配长上下文的处理需求 |
| 问题优化 | 开启，按实测标定 | 投标文稿需精准匹配招标方的技术参数要求，优化后的提示词可提升内容的准确性与合规性 |
| `chatId` | 绑定当前投标项目的唯一标识 | 需区分不同投标项目的对话历史，避免跨项目的数据混杂与干扰 |

## 容易做错的三处
-  现象为对话返回结果末尾出现类似「参考文档：XXX」的固定格式追溯展示符号，原因是未关闭系统默认的提示词追溯展示开关。
-  现象为高并发调用时，部分对话返回空结果，原因是未限制单`chatId`的并发请求上限，导致上下文资源被抢占。
-  现象为生成的投标文稿未包含当前批次的专属工艺参数，原因是未正确绑定`variables`中的批次标识，导致调用了错误的历史文档。

## 怎么确认配好了
-  发起单轮测试对话，检查返回结果末尾无类似「参考文档：XXX」的追溯展示符号。
-  发起3轮以上的多轮对话，验证`messages`上下文会被正确保留，且不会出现其他投标项目的历史数据混杂。
-  调用`variables`绑定的批次标识，检查生成的投标文稿中包含对应批次的投料量、反应参数等专属内容。
-  发起每秒2-3次的并发测试请求，验证单`chatId`的请求不会出现空结果返回。
