# 纸浆造纸的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
这个品类的日常文档包含配浆单、打浆记录、纸机运行记录、在线质量曲线、实验室报告、断纸与换品记录。数据主要来自木浆废纸批次、DCS/QCS系统、纸机在线测量设备、实验室检测结果、能源和水处理系统。数据更新节奏涵盖实时、每班、每卷三种维度，不同文档的字段与单位存在差异，例如配浆单包含浆料配比、添加量，单位多为吨、千克；在线质量曲线记录克重、水分、厚度，单位分别为克/平方米、百分比、毫米。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。多更新节奏的数据源要求索引支持增量更新，避免使用全量重建的方式，减少实时数据同步延迟。多样的文档结构与字段单位，要求分块时保留业务字段关联，避免拆分破坏配浆、质量控制等业务逻辑。时序类文档如在线质量曲线长度较短，长文本类如实验室报告则篇幅较长，需要适配的分块参数区间。投标报价编制需关联历史生产数据与当前批次参数，索引需支持跨文档的关联召回，同时需优先召回断纸、换品等异常记录对应的业务数据。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本适配：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类长文本类文档如实验室报告，同时避免时序类文档被过度拆分 |
| 重叠长度 | 100–150 字符 | 保留跨分块的业务关联，例如配浆单的连续配比记录 |
| 相似度阈值 | 0.75–0.85 | 区分浆料性质、纸机参数等业务相关度，避免召回无关的历史批次数据 |
| 单次搜索上限 | 前 8 条 | 平衡投标报价编制的召回效率与信息完整性，覆盖主要生产环节数据 |
| `maxToken` | 4000  token | 适配长文档的上下文拼接，满足投标文稿中多环节数据的整合需求 |
| 增量更新开关 | 启用 | 适配实时、每班的更新节奏，避免全量重建的时间消耗 |

## 容易做错的三处
- 现象：单个文件长时间处于索引中，界面显示索引进度停滞。原因：该文件包含超长时序数据如连续多卷的在线质量曲线，分块时未设置适配的长度参数，导致分块任务堆积。
- 现象：切换知识库索引时出现60秒超时报错。原因：未启用增量更新，全量重建该品类多更新节奏的数据集，超出系统默认超时阈值。
- 现象：设置知识库优先级后，仍召回低优先级知识库的内容。原因：未关闭跨知识库的全局召回开关，导致系统同时检索所有绑定的知识库资源。

## 怎么确认配好了
- 上传单份典型文档如配浆单，确认索引完成后无报错，且分块数量符合业务文档的常规长度区间。
- 输入包含浆料配比或纸机运行参数的查询语句，核对召回结果的相似度得分是否落在预设阈值区间内。
- 触发知识库增量更新，修改一条实时生产数据，验证后续查询可召回更新后的内容。
- 测试带优先级设置的跨知识库检索，确认仅召回指定优先级知识库的相关内容。
