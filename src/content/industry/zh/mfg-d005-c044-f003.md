# 纸浆造纸的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
纸浆造纸品类的业务数据来源包括木浆废纸批次台账、DCS/QCS系统、纸机在线测量设备、实验室检测报告、能源与水处理系统。数据更新节奏涵盖实时、每班、每卷三个维度，日常文档包含配浆单、打浆记录、纸机运行记录、在线质量曲线、断纸与换品记录等。单份文档包含浆料配比、克重、水分、厚度、能耗等字段，单位涉及吨、克/平方米、立方米、千瓦时等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
纸浆造纸的投标报价需整合多批次、多维度的生产数据，实时性要求较高的纸机运行参数需在对话中即时拉取。多轮对话需保留不同部门提交的配浆、断纸记录等历史参数，避免重复确认相同信息。不同数据源的字段与单位存在差异，提示词需明确区分在线质量曲线与实验室报告的格式，防止参数混用。投标文稿需覆盖多卷纸的生产参数，对话需逐步收集不同生产环节的记录，逐步完善报价与文稿内容。

## 配置怎么定
本配置适用于FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前投标项目的唯一标识 | 区分不同投标项目的对话上下文，避免跨项目数据混淆 |
| `messages` | 保留前20条对话历史 | 适配纸浆造纸投标需逐步确认多批次浆料、纸机参数的场景，避免上下文溢出 |
| `variables` | 绑定配浆单、纸机运行记录的专属字段 | 快速调用品类专属数据填充报价与文稿内容 |
| 最大上下文长度 | 8000–12000 token | 容纳多批次浆料参数、质量曲线数据的文本内容 |
| 工具调用超时 | 600秒 | 等待DCS系统返回纸机实时运行数据的合理时长 |
| 历史对话归档 | 按投标项目维度存储 | 方便项目完结后回溯调整文稿与报价内容 |

## 容易做错的三处
- 配置`chatId`时未绑定投标项目唯一标识，出现对话历史与其他项目混淆的现象。原因是未通过`chatId`隔离不同项目的上下文，导致多轮对话的参数出现跨项目串用。
- 调用数据库工具时返回400 status code (no body)报错。原因是未正确配置工具调用的数据源权限，或未将品类专属的配浆单、纸机运行记录字段映射到工具查询语句中。
- 尝试清除对话记录时无法按项目维度删除。原因是未通过`variables`绑定项目标识，系统无法识别需删除的对话所属投标项目，只能批量清除所有历史记录。

## 怎么确认配好了
- 发起包含“查询指定木浆批次参数”的提问，查看对话是否能正确调用绑定的数据源返回对应内容。
- 发起多轮提问，先确认配浆单参数，再补充纸机运行数据，查看`messages`是否保留了前序提问的上下文，未出现参数丢失的情况。
- 触发工具调用后，等待不超过600秒，确认能正常返回纸机在线测量的实时数据，无超时报错。
- 导出对话记录，确认仅包含当前投标项目的对话内容，无其他项目的历史数据。
