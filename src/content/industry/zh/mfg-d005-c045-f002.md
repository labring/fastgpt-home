# 纺纱与织造的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
纺纱与织造的日常文档包含配棉或配料单、工艺上机单、设备运转记录、纱线检验、坯布检验、疵点记录等。数据来源涵盖原纤维检验报告、ERP系统、纺机与织机实时数据、条干仪检测结果、验布机记录等。数据更新频率随生产节奏调整，每批原料、每班生产、每匹布产出均会生成新的业务数据。文档字段包含纤维指标、纺纱捻度、织造组织参数、疵点类型与位置等，部分字段带有专用单位，如纱支数、织物幅宽、捻度系数等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的业务数据兼具结构化参数与非结构化记录特征，高频更新的特性要求索引支持增量同步与批量处理。专业工艺字段与疵点描述需要向量模型适配行业术语，避免语义匹配偏差。多源数据的格式差异会增加向量化的预处理成本，过长的单份文档（如批量配棉方案）会超出基础向量化的上下文限制。同时，设备头数多导致的数据集规模扩大，要求索引结构兼顾召回精度与检索效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配单份工艺单、检验记录的常规内容长度，避免拆分跨工艺逻辑的段落 |
| 重叠长度 | 100–150 字符 | 覆盖配棉参数、捻度设置这类跨块关联的工艺信息，防止上下文断裂 |
| `defaultToken` | 8192 token | 匹配多数工业文本的上下文长度需求，适配投标文稿的长文档处理 |
| `maxToken` | 16384 token | 支持完整的批量报价单、多批次配棉方案的向量化处理 |
| 相似度阈值 | 0.72–0.85 | 区分工艺参数的精准匹配与疵点描述的模糊匹配需求 |
| 单次搜索上限 | 前10条 | 平衡检索效率与投标报价所需的工艺数据覆盖范围 |

以上配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 向量化任务触发embedding速率超限报错，原因是未限制单批次向量化的数据量，且未调整并发处理线程参数，导致接口调用频率超出阈值。
- 知识库检索速度慢，原因是未根据工业数据的分块特征优化索引层级，导致召回链路过长，无法快速匹配工艺参数与检验记录。
- 数据集中的业务数据自动重复生成多组索引，原因是增量索引时未配置去重规则，导致重复上传的配棉单、疵点记录被多次向量化并索引。

## 怎么确认配好了
- 上传单份标准配棉配料单，检查向量化后的分块数与文档实际段落数匹配，无过度拆分或遗漏。
- 输入典型工艺参数进行检索，检查返回结果的相似度分值落在预设阈值区间内，且包含相关的工艺与检验数据。
- 上传两份完全一致的疵点记录，检查索引后仅生成单条向量数据，无重复条目。
- 查看系统运行日志，确认向量化任务的执行速率未触发超限报错，检索响应时长符合预期。
