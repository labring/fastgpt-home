# 纺纱与织造的投标文稿与报价编制：工具调用与插件

## 这个品类的数据长什么样
该品类数据主要来自棉纺、化纤纺、机织和针织企业的日常业务文档，包括配棉或配料单、工艺上机单、设备运转记录、纱线检验单、坯布检验单与疵点记录。数据来源涵盖原纤维检验报告、ERP系统、纺机与织机运行数据、条干仪检测结果、验布机输出数据。数据更新随每批原料、每班生产、每匹布产出同步进行，不同文档的字段与单位存在差异，如配棉单需标注纤维品级、混配比例，工艺单需明确捻度、组织参数等。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据特征对工具调用与插件环节带来多重约束。多源分散的数据来源需要配置可对接多系统的插件，拉取原纤维检验、ERP、纺机设备等不同渠道的字段。高频更新的业务数据要求工具调用触发逻辑匹配生产节奏，避免使用过期的原料品级、设备运转参数。不同文档的字段与单位差异大，工具调用需支持动态解析适配，不能使用固定解析模板。同时工艺参数与疵点记录强关联，工具调用需联动校验纺纱捻度、织造组织参数与疵点数据，确保投标文稿与报价的工艺匹配性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 支持大模型自主选择是否调用工具，适配多源数据拉取的动态需求 |
| `functionCall` | 开启 | 需要大模型严格按照预设工具参数调用，避免生成不符合格式的调用指令 |
| 工具调用超时时间 | `30–60 秒` | 多源数据拉取需等待不同系统响应，超时时间过短会导致部分数据源未拉取完成 |
| 工具调用重试次数 | `2 次` | 部分纺机设备数据接口可能存在临时波动，重试可降低调用失败概率 |
| 上下文窗口大小 | `8000–12000 token` | 需容纳多份工艺单、检验记录与订单数据，确保大模型获取完整业务信息 |
| 召回结果条数 | `前 5 条` | 需覆盖单批生产的主要工艺参数，避免过多数据占用上下文 |

## 容易做错的三处
- 现象：大模型输出的投标文稿中出现「引用标记：［1］」字样。原因：未配置工具调用后的结果格式化规则，直接将知识库的引用标记带入最终输出内容。
- 现象：触发用户指定的关键词后未拦截AI回答，直接返回默认回复。原因：未将关键词拦截规则绑定到自定义接口调用的工具节点，触发逻辑未正确配置。
- 现象：工具调用返回的坯布检验数据字段为空。原因：未适配该品类验布机输出的疵点记录字段格式，工具解析模板未匹配实际业务文档的字段名称与结构。

## 怎么确认配好了
- 发起模拟投标需求请求，检查工具调用日志是否拉取到对应批次的配棉单、工艺上机单数据，确认数据源匹配度符合业务要求。
- 触发预设的关键词拦截测试，检查是否调用绑定的自定义接口并返回对应回复，确认拦截规则生效。
- 查看大模型输出的投标文稿与报价内容，确认未包含知识库引用标记，检查格式化规则是否正确过滤了冗余标识。
- 模拟多源数据拉取超时场景，检查工具是否按配置的重试次数进行重试，确认超时与重试逻辑正常运行。
