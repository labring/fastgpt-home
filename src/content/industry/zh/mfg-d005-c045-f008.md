# 纺纱与织造的投标文稿与报价编制：文档解析与分块

## 这个品类的数据长什么样
棉纺、化纤纺、机织和针织企业的日常文档包含配棉单、工艺上机单、设备运转记录、纱线检验、坯布检验、疵点记录等。数据来源于原纤维检验、ERP系统、纺机与织机数据采集设备、条干仪、验布机及订单规格文件，更新频率为每批原料、每班生产或每匹布产出一次。文档包含结构化数值字段，如纱线支数、坯布幅宽、捻度、设备运行时长，部分文档附带疵点实拍图片，格式覆盖PDF与Excel，部分字段带有专属单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
品类文档的高频更新要求分块逻辑适配小批量、多批次的上传场景，避免因分块规则僵化导致重复解析或资源浪费。多类型文档混合上传的场景，要求解析逻辑同时兼容结构化表格与带图片的PDF文件，且需保留专业字段的完整性。专属的纺织术语与单位，要求解析模块具备专业术语识别能力，避免字段拆分时破坏参数绑定关系，如捻度与对应纱线型号的关联。不同文档的结构差异较大，配棉单为多列数值表格，工艺上机单为段落式参数列表，疵点记录为图文混合文档，分块规则需适配不同结构的文档，避免跨类型内容被错误拆分。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配工艺上机单、配棉单的参数段长度，避免拆分捻度、幅宽等关联参数 |
| `chunkSplitter` | 按段落+表格边界拆分 | 匹配品类文档的混合结构，保留Excel配棉单、工艺单的表格完整性 |
| `customPdfParse` | 启用OCR模式 | 适配带疵点实拍图片的PDF文档，实现文字与图片文本同时召回 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 处理批量设备运转记录PDF时，避免因单任务时长过长导致解析中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配整批原料的批量文档上传需求，支持多份小文件合并上传 |
| `chunkSettingMode` | 手动配置模式 | 针对不同文档类型调整分块参数，适配图文混合与纯表格文档的差异化需求 |

## 容易做错的三处
- 现象：上传带疵点图片的PDF后，仅召回文字内容，图片中的疵点描述文本未被提取。原因：未启用`customPdfParse`的OCR模式，未配置图片文本解析开关。
- 现象：Excel格式的配棉单上传后，表格列被拆分到不同分块，检索时无法匹配完整的纤维用量参数。原因：`chunkSplitter`配置为仅按字符拆分，未开启表格边界识别规则。
- 现象：批量上传多台织机的运转记录PDF时，解析任务超时失败。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置过低，未适配单批次批量文档的处理时长。

## 怎么确认配好了
- 上传单份带疵点实拍图片的PDF文档，检查检索结果是否包含图片中的疵点描述文本。
- 上传Excel格式的配棉单，检索完整的纤维类型与对应用量参数，确认参数未被拆分到不同分块。
- 上传批量的设备运转记录PDF，检查解析任务是否在设定的`PARSE_FILE_TIMEOUT_SECONDS`内完成。
- 调整`chunkSize`参数后，对比不同长度的工艺单分块结果，确认关联的工艺参数未被拆分。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
