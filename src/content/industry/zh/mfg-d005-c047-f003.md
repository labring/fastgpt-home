# 计量器具与实验室管理的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据涵盖企业计量室、CNAS体系实验室的日常业务文档，包括量具台账、校准计划、校准证书、期间核查记录、试验原始记录、标准物质台账与偏离处置文件。数据来源为计量管理系统、外部校准机构证书、标准器、LIMS系统及环境监测记录，更新节奏随校准周期、单次试验完成或异常情况触发。文档字段包含器具编号、校准有效期、测量不确定度、溯源链信息，单位涉及长度、力值、温度等计量专用单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散且更新无固定周期，多轮对话需先明确触发对应数据源的调用逻辑，避免使用过期的校准证书或台账数据。文档字段包含计量专用单位与复杂溯源信息，提示词需预设计量术语识别规则，确保对话中可准确解析测量值、不确定度等内容。最耗时的溯源链维护环节要求多轮对话按顺序引导用户补充器具校准、溯源路径信息，防止生成的投标文稿出现溯源缺失问题。同时，出错后果严重，对话需在生成报价前校验数据合规性，避免因参数错误导致投标无效。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定计量器具台账ID、校准周期阈值（365天） | 用于在对话中快速调用对应品类的专属业务数据，避免跨实验室数据混淆 |
| `messages` | 按「系统提示词+历史对话+当前请求」顺序拼接，保留最近20条对话 | 避免上下文过长导致计量术语混淆，适配多轮投标报价的分步沟通 |
| `chatId` | 绑定实验室唯一标识与计量器具分类标签 | 区分不同实验室的投标报价数据，确保生成内容符合对应实验室的计量体系要求 |
| 最大上下文长度 | 8000–12000 token | 覆盖校准证书、溯源链等长文本的完整信息，防止截断关键计量参数 |
| 单次对话返回token上限 | 2000–3000 token | 适配投标文稿分段生成的需求，避免返回内容过长导致格式异常 |
| 问题优化开关 | 开启 | 对投标报价相关的计量术语问句进行优化，提升检索与生成准确性 |

## 容易做错的三处
- 调用对话接口返回`unAuthChat`状态码。原因：未正确绑定计量品类专属的API密钥权限，或密钥配置时未关联LIMS、计量管理系统的数据源权限。
- 生成的投标文稿中包含换行符导致JSON请求失败。原因：未配置对话返回内容的转义规则，未对计量参数中的换行符进行预处理。
- 全局变量未识别到系统侧传递的参数。原因：未将计量器具编号、校准有效期等品类专属参数绑定至`variables`配置项，导致系统参数无法被正确加载。

## 怎么确认配好了
- 发起包含具体计量器具编号的测试对话，核对返回结果中是否正确调用了对应台账的校准信息。
- 提交包含换行符的测试文本，检查生成的请求体是否为合规JSON格式。
- 查看`variables`与`chatId`配置项，确认已绑定计量品类专属的业务数据参数与实验室标识。
- 发起多轮连续对话，核对上下文是否保留了最近的计量术语对话内容，未出现关键信息截断。
