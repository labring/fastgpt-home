# 设备点检与预防维修的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自企业EAM/CMMS系统、设备传感采集终端、操作员点检表单、维修工单、备件库存清单及特种设备检验记录。日常文档包含设备台账（含设备编号、型号、安装位置字段）、点检表（含点检项、实测值、判定结果）、保养计划、故障分析报告等。数据更新节奏随业务场景变化：点检记录每班更新，保养计划按周/月更新，故障工单与检验记录在事件发生时即时更新。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引支持跨格式数据的统一向量化处理，避免因文档格式差异导致特征丢失。高频更新的点检、工单数据要求采用增量索引策略，避免全量重建带来的额外耗时。设备数据附带明确的物理量单位与字段关联，分块时需保留字段上下文，防止拆分后丢失设备编号、实测值等关键关联信息。嵌入模型的`maxToken`应按其文档中的输入上限设置；多文档检索量与 LLM 上下文预算应另行评估，并为提示词、历史对话、召回文本和回答预留空间。特种设备检验记录的法定属性要求索引优先召回高优先级合规数据，避免检索结果遗漏关键合规信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配设备点检表、维修工单的单条记录长度，保留设备编号、实测值等关键字段的上下文 |
| 重叠长度 | 100–150 字符 | 避免跨块的设备关联信息被截断，确保分块后仍可识别目标设备 |
| maxToken | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非关联设备数据，确保检索结果聚焦目标设备 |
| 单次搜索上限 | 前 10 条，按代表性查询实测校准 | 控制召回量；需按相关性验证结果，并另按所选 LLM 的上下文窗口预算召回文本 |
| defaultToken | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 现象：检索结果中出现大量非目标设备的点检记录，字段为空或匹配度极低。原因：未设置合理的相似度阈值，或分块时未保留设备编号关联信息，导致索引召回无关数据。
- 现象：增量索引更新耗时过长，甚至触发超时报错。原因：未采用增量索引策略，对全量设备数据进行周期性重建，未匹配高频更新的业务节奏。
- 现象：检索结果仅返回扁平化的单文档内容，无法关联设备、备件、故障的实体关系，无法支撑复杂投标逻辑。原因：未启用跨文档实体关联配置，仅使用基础扁平化索引，未适配业务所需的关系型检索需求。

## 怎么确认配好了
- 上传单条设备点检记录与维修工单，验证检索结果是否仅召回同设备的关联文档。
- 触发增量索引更新，核对更新耗时是否符合业务预期，未出现超时报错。
- 配置相似度阈值后，检索目标设备的故障记录，验证低匹配度的无关数据是否被过滤。
- 核对FastGPT v4.17.0的版本标识，确认当前部署版本支持配置的实体关联与增量索引功能。
