# 设备点检与预防维修的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
本品类的日常文档包含设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录。数据来源包括EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史、备件库存及法定检验信息。更新节奏覆盖每班、日/周/月周期，以及故障发生时的即时更新。文档字段包含设备编号、点检点位参数、备件编码与库存数量、检验有效期等，单位涵盖毫米、摄氏度、件、小时等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
分散的多源数据要求多轮对话需先通过分类节点划分分支，精准调用对应设备类型的知识库。动态更新的数据需提示词支持实时拉取最新库存、检验状态，避免使用过期信息。编制分级点检与停机保养计划的高耗时环节，要求多轮对话引导用户逐步输入设备型号、点检周期、项目排产窗口等参数。严重的出错后果要求提示词内置校验逻辑，核对备件替代方案与法定检验要求，确保投标内容合规。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 问题分类节点 | 按设备类型、点检类型划分分支 | 设备点检数据按设备分类存储，分类后可精准调用对应知识库 |
| 知识库关联 | 绑定设备台账、点检表、备件清单、特种设备检验记录知识库 | 投标文稿与报价需覆盖设备基础信息、点检标准、备件成本与法定检验要求 |
| 最大上下文 | `8000–12000 字符` | 设备相关文档包含多份工单与检验记录，需保留完整历史对话与引用内容 |
| 单次搜索上限 | `前6条` | 设备数据条目清晰，过多检索结果会干扰内容精准性 |
| `variables` | 传递设备编号、点检周期、投标项目名称变量 | 多轮对话需动态填充个性化投标内容与参数 |
| `chatId` | 自动生成会话唯一标识 | 多轮对话需绑定专属上下文，避免不同会话内容混淆 |
| 对话超时 | `300 秒` | 设备数据查询与知识库调用需一定时间，超时会中断交互流程 |

## 容易做错的三处
- 现象为HTTP编排节点执行后，对话界面无对应输出字段显示。原因是未在配置中开启变量回传至对话上下文，导致输出未被挂载到`messages`参数中。
- 现象为多轮对话完成分支调用后，无法回到问题分类节点触发下一轮交互。原因是未在工作流末端配置循环触发节点，导致流程执行完毕后终止。
- 现象为生成的投标文稿未包含特种设备检验记录相关内容。原因是提示词未指定绑定法定检验信息的知识库，导致遗漏强制要求的合规内容。

## 怎么确认配好了
- 触发问题分类节点，选择指定设备类型，核对对话是否自动关联对应设备的知识库文档。
- 发起包含备件价格核对的交互，核对输出是否动态使用了预设的变量参数。
- 测试多轮连续对话，核对历史交互内容是否被完整保留在上下文窗口中。
- 触发超时场景，核对系统是否按配置的时长返回对应提示。
