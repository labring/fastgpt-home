# 设备点检与预防维修的投标文稿与报价编制：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自EAM/CMMS系统、设备传感采集终端、操作员点检记录、维修工单、备件清单、特种设备检验记录等。更新节奏覆盖每班点检提交、日周度保养计划更新、故障发生时的即时工单录入。文档包含结构化表格与文本两类，字段含设备编号、点检点位、备件型号、检验有效期、维修时长等，单位涉及毫米、小时、次等设备运维专用标识。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源与不均的更新频率，要求检索环节需按更新时间过滤召回结果，优先获取最新的点检与维修数据。结构化表格类文档占比高，需支持表格内容的精准索引与匹配。设备编号、备件型号等精准字段的检索需求，要求调整匹配权重，避免泛化匹配引入无关数据。投标场景需快速定位历史维修案例与备件替代方案，对召回的时效性与相关性有明确要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | 匹配设备点检的精准字段，避免无关设备数据混入投标文稿 |
| `limit` | 前8条 | 控制检索结果数量，避免投标文稿中引用过多冗余的维修案例 |
| `searchMode` | `mixedRecall` | 结合本地知识库的设备数据与联网的行业维修标准，适配投标场景的多源信息需求 |
| `usingReRank` | 开启 | 对召回的点检表、工单内容重新排序，优先匹配投标场景的高优先级维修需求 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展备件型号的检索词，匹配替代备件的清单数据 |
| `collectionIds` | 指定设备点检与维修知识库的集合ID | 限定检索范围，排除其他业务品类的文档干扰 |

## 容易做错的三处
-  配置`usingReRank`后出现显存持续占用现象，表现为检索完成后重排模型进程未自动退出，原因是未配置检索流程结束后自动卸载重排模型的逻辑。
-  导入点检表类表格文档后检索结果为空，表现为匹配字段无有效返回内容，原因是未开启表格内容的分块与索引配置。
-  启用`datasetSearchUsingExtensionQuery`后抛出Invalid array length报错，表现为检索时界面弹出数组长度无效的提示，原因是扩展查询的词表格式不符合系统校验规则。

## 怎么确认配好了
-  上传单份标准化点检表文档，执行包含点检点位的检索测试，查看返回结果是否包含表格内的具体内容。
-  查看系统显存监控面板，确认重排模型在检索完成后自动卸载，无持续占用显存的情况。
-  输入包含特定设备编号的查询词，验证返回结果的`similarity`分值是否落在预设的0.72–0.85区间内。
-  执行备件型号相关的检索测试，确认可匹配到扩展后的查询结果与联网补充的行业标准内容。
