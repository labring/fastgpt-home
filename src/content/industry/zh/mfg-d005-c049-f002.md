# 过程质量与成品放行的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自制造企业IPQC、FQC、质量工程及实验室团队，日常文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单及质量月报。数据来源于MES系统、检测设备、实验室记录、工艺参数文件、客户标准及历史缺陷库，更新节奏为每生产批次、每班持续采集，文档结构多为结构化字段搭配自由文本描述，字段包含检验项、参数阈值、判定结果、批次编号等，无统一固定格式，部分文档附带检测数值与单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引支持跨系统数据的统一向量化处理，避免因数据格式差异导致的检索偏差。高频次的批量更新需要索引具备增量同步能力，避免全量重建带来的性能损耗。混合结构化与自由文本的文档结构，要求分块策略兼顾字段边界与语义单元完整性，防止跨字段截断或语义断裂。投标场景下需关联历史缺陷库与客户标准，要求索引支持多文档关联召回，确保检索结果覆盖业务所需的全部维度。同时，批次级的更新粒度要求索引能够按生产批次快速定位关联文档，避免无效检索。

本配置指南适用于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配巡检记录、SPC报表等文档的语义单元长度，避免跨字段截断 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的语义关联，防止分块间的信息断裂 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 匹配制造类文档的语义相似度分布，过滤无效召回结果 |
| 单次搜索上限 | 前 8 条 | 适配投标文稿编制时的多源参考需求，平衡检索效率与结果覆盖度 |
| `maxToken` | 8000 | 适配多文档拼接后的上下文长度，满足复杂评审场景的信息输入 |
| `defaultToken` | 1024 | 控制单条向量化文本的输出长度，适配多数索引模型的输入限制 |

## 容易做错的三处
- 现象：单文档上传后显示分块数与最终就绪后分块数不一致，出现重复分块。原因：未配置增量索引的去重规则，或分块重叠长度设置过大导致相邻分块语义重叠被重复识别。
- 现象：添加的ollama qwen2.5语言模型与bge-m3索引模型在可用模型列表中可见，但创建知识库时文本理解模型下拉框无对应选项。原因：未将索引模型关联至知识库的文本理解配置项，或模型渠道的权限未同步至知识库模块。
- 现象：仅支持单文件调整训练参数后重新上传，无法批量触发向量模型重训练。原因：未启用知识库的批量重训练功能，或未配置批量处理的触发条件与范围。

## 怎么确认配好了
- 上传单份典型文档（如成品检验报告），查看分块结果是否符合预设的分块长度与重叠长度要求。
- 发起一次检索测试，输入与历史缺陷库相关的查询词，核对召回结果的数量与相关性是否符合业务预期。
- 提交批量文档上传任务，查看索引更新的进度与最终分块数是否一致，无重复分块。
- 切换至知识库的模型配置页面，确认已添加的索引模型与语言模型均出现在对应下拉选项中。
