# 过程质量与成品放行的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源于MES系统、在线检测设备、实验室系统、工艺参数库、客户质量标准及历史缺陷库。数据更新节奏为每生产批次、每班轮换，或持续采集实时检测数据。日常文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单、质量月报，字段含检验批次号、不合格项编码、放行阈值、缺陷类型、检测时间等，无统一固定单位，具体字段单位随文档类型变化。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且实时性要求高，多轮对话需关联不同系统的同源数据，提示词需明确区分在制品与成品的检验逻辑。更新频率的差异要求对话上下文需动态适配不同时间粒度的文档，批次级数据需关联单批检验记录，持续采集的检测数据需实时拉取。文档结构多样，提示词需适配不同文档的字段提取规则，避免混淆放行单与不合格评审单的字段。历史缺陷库的关联要求多轮对话需保留上下文以追踪缺陷关联关系，防止重复调用无关数据。

## 配置怎么定
FastGPT v4.17.0 下的配置项参考如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 适配多份检验报告、评审单与质量月报的总内容长度，避免上下文溢出 |
| 对话历史保存时长 | 30–90 天 | 匹配生产批次的追溯周期，满足内部质量审核与投标文档溯源需求 |
| 单次对话召回上限 | 前 5 条 | 限制历史缺陷库与检验记录的召回数量，避免信息过载干扰提示词逻辑 |
| `variables` 绑定规则 | 按文档类型匹配 | 自动关联控制计划或放行单的专属字段，提升提示词的字段提取准确性 |
| `chatId` 配置 | 绑定生产批次号 | 确保同批次的对话上下文关联，避免跨批次数据混淆 |
| `messages` 上下文截断阈值 | 保留最近 10 轮对话 | 聚焦当前投标文稿编制的最新需求，过滤过期的历史对话内容 |

## 容易做错的三处
- 现象：对话响应时长超过10秒，界面显示加载超时状态。原因：未限制单次召回的文档数量，导致系统拉取过多历史检验数据与缺陷记录，模型处理耗时过长。
- 现象：无法查询指定生产批次的对话日志，或对话日志提前丢失。原因：未正确配置`chatId`与生产批次号的绑定关系，或对话历史保存时长设置短于生产追溯周期。
- 现象：提示词提取的字段与实际文档不符，比如将放行单的合格阈值错提取为巡检记录的不合格数。原因：未按文档类型配置`variables`的匹配规则，导致不同文档的字段混淆。

## 怎么确认配好了
- 发起一次模拟对话，输入某生产批次的检验需求，核对返回的上下文是否仅包含该批次的相关文档。
- 查看对话历史列表，确认对应`chatId`的会话可正常查询，且保存时长符合生产追溯要求。
- 调整单次召回上限参数，验证返回的历史数据条数符合预设的数量限制。
- 测试不同类型的文档输入，确认`variables`能自动匹配对应文档的专属字段。
