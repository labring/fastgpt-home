# 过程质量与成品放行的投标文稿与报价编制：模型接入与配置
本页基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类数据来自MES系统、在线检测设备、实验室报告、工艺参数库、客户质量标准及历史缺陷档案。数据更新节奏为每生产批次、每班轮换及持续采集。日常文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单及质量月报，字段含检验项编号、缺陷类型、判定结果、工艺参数值，关联批次号与客户订单号。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据来源分散且实时更新，要求模型接入配置需支持多源数据的同步拉取与合理的上下文截断，避免冗余数据干扰生成。文档格式多样，包含结构化报表、非结构化评审记录等，配置时需适配不同格式的文本解析逻辑，确保关键字段被准确提取。投标文稿需关联历史缺陷档案与客户质量标准，要求配置中保留足够的引用token额度，保障内容的可追溯性。同时，质量判定环节需严谨，需控制生成结果的随机性，避免误判。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配本品类多源质量文档的上下文长度，避免关键检验记录与客户标准被截断 |
| `maxTokens` | 2000–3000 token | 满足投标文稿中报价项、检验项的完整生成需求 |
| `quoteMaxToken` | 1500–2000 token | 保障历史缺陷报告、客户标准等引用内容的完整展示 |
| `temperature` | 0.1–0.3 | 控制质量判定与文稿生成的严谨性，降低随机误差 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的代理地址填写 | 适配多源数据接入的代理配置，确保不同系统的数据可正常同步 |
| `toolChoice` | auto | 允许模型按需调用工具处理结构化数据，提升检验项转换的准确性 |

## 容易做错的三处
- 尝试调用DeepSeek-R1等非平台官方大模型时，接口返回`{"object":"error","message":"Only allowed now"}`，原因是未开启自定义模型接入权限，或代理配置未正确绑定允许的模型列表。
- 本地部署的vLLM服务添加至OneAPI时，提示connection refused错误，原因是代理地址未配置正确的端口，或本地防火墙拦截了通信端口。
- 导入质量文档后生成的投标文稿中检验项字段为空，原因是未配置足够的`maxContext`额度，导致原始文档中的检验项参数被截断丢失。

## 怎么确认配好了
- 上传单份成品检验报告，核对生成的投标文稿中是否准确提取了检验项与判定结果，确认上下文截取逻辑符合预期。
- 配置自定义模型接入地址后，发起一次测试调用，检查返回结果是否包含预期的质量判定内容，验证代理配置生效。
- 导入历史缺陷库与客户标准文档，检查生成的报价项是否关联了对应的质量要求，确认引用token配置合理。
- 查看系统日志，确认多源数据拉取无超时或连接错误，验证接入配置的稳定性。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
