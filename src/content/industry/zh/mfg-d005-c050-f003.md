# 通用机械设备装配的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
通用机械设备装配的投标相关数据，主要来自PLM/ERP、零件检验数据、装配工具采集、试验台、MES及客户技术协议。数据按单台设备或每订单更新，日常文档包含装配工艺卡、BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单。数据字段包含物料编码、装配力矩（单位N·m）、间隙值（单位mm）、试验参数等，不同定制订单的文档结构略有调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据按单台或订单更新，要求多轮对话必须绑定对应订单的专属数据，避免跨订单数据混淆。文档类型多且字段带特定单位，提示词需明确要求保留单位并区分不同文档的用途。装配调试数据与投标要求的匹配需要多轮上下文支撑，`messages`参数需维护历史对话的订单信息与调整记录，`variables`需传入订单号以关联PLM中的对应BOM和工艺文件，防止出现数据错位。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 适配多份装配文档、投标文稿及历史对话的总长度 |
| 单次召回结果上限 | 前10条 | 匹配单台装配数据的常规条目规模，避免冗余信息干扰 |
| `variables`参数配置 | 传入当前订单号 | 关联PLM/ERP中对应订单的BOM与装配工艺数据 |
| `messages`参数处理 | 按轮次追加系统提示与用户输入 | 维护投标过程中多轮报价调整的上下文一致性 |
| 超时阈值 | 600秒 | 适配复杂BOM核对、多文档召回的耗时需求 |
| 变量传入开关 | 开启 | 实现订单专属数据的动态绑定 |

## 容易做错的三处
- 调用对话组件时返回未捕获的异常，日志显示无法加载对应订单的装配数据，原因是私有部署环境下未正确配置`variables`参数的绑定路径，导致无法关联PLM中的专属数据。
- 生成的投标文稿未引用知识库中的装配成本数据，回复未包含BOM中的物料单价，原因是提示词未明确要求优先使用当前订单的BOM字段进行计算，未关联`messages`中的历史上下文。
- 对话页面出现崩溃，浏览器控制台显示渲染超时，原因是单次召回的文档数量设置过高，超出FastGPT v4.17.0的页面渲染缓存阈值。

## 怎么确认配好了
- 传入测试订单号，检查对话是否能自动关联对应BOM和装配工艺卡的字段，返回结果包含正确的物料编码与装配力矩单位。
- 发起多轮报价调整请求，检查`messages`参数是否正确追加了每一轮的对话内容，历史订单信息未丢失。
- 触发复杂BOM核对任务，检查返回结果是否包含对应文档的字段，未出现数据缺失或单位错误。
- 查看系统运行日志，确认未出现未捕获的异常报错，页面加载无崩溃现象。
