# 通用机械设备装配的投标文稿与报价编制：部署与升级

## 这个品类的数据长什么样
通用机械设备装配品类的核心数据来自PLM、ERP、零件检验系统、装配工具采集终端、试验台、MES及客户技术协议。数据更新随每台设备订单完成节点触发，包含装配工艺卡、多层级BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单与装箱清单。数据字段包含物料编码、扭矩值（单位N·m）、间隙公差（单位mm）、同轴度要求（单位μm）等，单份投标关联数据量随订单复杂度波动。

## 这些特征在「部署与升级」这一环带来什么约束
该品类多订单并行生成投标文稿的场景，要求部署时需支撑高并发的多数据源调取。数据随订单动态更新的特性，要求升级过程中不能中断正在运行的任务，需支持灰度发布。多类型文档与结构化数据并存的特点，要求配置适配不同数据格式的存储与索引规则，避免数据读取延迟。同时，投标文稿需严格匹配客户技术协议的字段要求，部署时需确保数据源的权限配置符合内部数据安全规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–200` | 该品类每订单对应多份装配文档与BOM数据，高并发下需足够连接池支撑多用户同时生成投标文稿 |
| `MONGODB_URI` | 按PLM/ERP导出的数据集地址配置 | 品类核心BOM与工艺卡数据存储于PLM系统的MongoDB实例，需直接对接获取结构化数据 |
| `REDIS_URL` | `本地6379端口默认配置` | 需缓存高频调取的客户技术协议与历史投标模板，降低数据库查询压力 |
| `STORAGE_S3_ENDPOINT` | 企业内部对象存储节点地址 | 品类装配文档与检验记录体积较大，需统一存储并支持跨节点调用 |
| `FILE_TOKEN_KEY` | 随机生成32位字符串 | 需加密存储投标文稿的临时下载链接，防止未授权访问内部文档 |
| `FE_DOMAIN` | 企业官网投标系统的二级域名 | 需将生成的投标文稿链接绑定至内部业务域名，符合内部使用规范 |

## 容易做错的三处
- 现象：升级至FastGPT v4.17.0后，config.json中的`systemEnv`相关配置项无法找到，导致投标文稿的BOM数据调取失败。原因：该版本配置结构调整，未将原有配置迁移至指定的环境变量文件。
- 现象：通过Vercel自动化部署后，访问投标文稿生成页面返回404 Not Found错误。原因：未正确配置`FE_DOMAIN`与后端服务的路由绑定，静态资源与API接口路径未匹配。
- 现象：免登录分享的投标文稿中，引用原文功能无法按配置关闭。原因：未正确设置`FILE_TOKEN_KEY`的访问权限，导致分享链接的文件访问令牌未绑定预期的有效期与权限规则。

## 怎么确认配好了
- 登录FastGPT后台，查看数据库连接监控面板，确认`DB_MAX_LINK`的配置值与预设值一致，无持续连接超时报错。
- 上传一份标准装配工艺卡至系统，通过`STORAGE_S3_ENDPOINT`对应的存储节点验证文件上传、下载与预览功能正常。
- 生成一份测试用投标文稿，核对调取的BOM数据与PLM系统导出的原始数据字段完全匹配。
- 生成免登录分享链接，测试链接的访问权限是否符合预设的关闭原文查看的配置要求。
