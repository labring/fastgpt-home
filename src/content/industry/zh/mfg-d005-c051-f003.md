# 金属切削加工的投标文稿与报价编制：多轮对话与提示词
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
金属切削加工的业务数据来源包括产品图纸与三维模型、CAPP/CAM系统、机床采集数据、刀具管理系统、MES系统及量检具校准记录。数据更新随加工工单、工件批次、抽检环节及刀具更换触发，日常文档涵盖工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表与量具校准记录，字段包含刀具寿命（单位小时）、工序转速（单位转每分钟）、进给率（单位毫米每转）等工艺参数。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据随工单动态更新且包含专属工艺参数，多轮对话需绑定当前工单的唯一标识，避免混淆不同工件的刀具清单与工艺路线。文档类型多样且字段单位统一要求严格，提示词需明确调用对应工序的数控程序、首件检验记录等专属数据，无法依赖通用知识库。多轮交互需限制上下文范围，防止冗余历史数据干扰当前投标文稿与报价的编制逻辑，同时需统一工艺术语的表述规范。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前加工工单的唯一标识 | 金属切削加工数据随工单动态更新，需关联对应工单的工艺、刀具等专属数据 |
| `variables` | 预设刀具寿命、工序转速、进给率等变量 | 快速调用工序卡、刀具清单中的标准化工艺参数 |
| `messages` | 限制上下文窗口为前10轮对话 | 避免冗余历史工单数据干扰当前文稿与报价编制 |
| 最大上下文 | 800–1200 token | 匹配金属切削加工工艺参数与文档的常规长度 |
| 问题优化 | 开启 | 优化提示词表述，匹配金属切削加工的专业术语规范 |

## 容易做错的三处
- 出现401 No auth credentials found报错，原因是未正确配置当前应用的API密钥，或`chatId`关联的会话权限未完成绑定。
- 生成的投标文稿遗漏工件的尺寸公差参数，原因是未在`variables`中预设工序卡中的公差字段，导致提示词无法调用对应数据。
- 对话结果出现冗余的历史工单内容，原因是未限制`messages`的上下文轮次，引入了无关加工批次的历史数据。

## 怎么确认配好了
- 发起测试对话，输入“编制当前工件的投标报价与文稿”，检查返回结果是否包含当前工单的刀具清单、工艺路线等专属数据。
- 查看会话日志，确认`chatId`绑定了正确的工单标识，无权限报错信息。
- 连续发起3次参数调整请求，检查对话上下文是否保留有效历史且无冗余的非当前工单数据。
- 开启问题优化功能后，检查生成的文稿是否使用了金属切削加工的专业规范术语。
