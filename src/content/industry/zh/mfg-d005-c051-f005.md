# 金属切削加工的投标文稿与报价编制：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源于产品图纸与三维模型、CAPP/CAM、机床采集系统、刀具管理系统、MES及量检具数据。日常文档涵盖工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表、量具校准记录。数据更新随每工单、单件加工、抽检或刀具更换触发，字段包含刀具型号、切削参数、尺寸公差、检验结果等，对应单位为转速r/min、进给量mm/r、公差mm等。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类数据来源分散且格式多样，工具调用需适配多系统接口与多类型文档解析，确保拉取的工艺路线、刀具清单等数据准确。数据更新随工单、刀具更换等频繁触发，工具需支持按需触发数据同步，避免使用过期的切削参数或检验记录。字段附带明确单位，工具调用时需自动匹配单位规则，防止报价计算出现单位偏差。投标文稿需整合多维度数据，插件需支持自动提取字段生成标准化的工艺说明与成本明细条目。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 函数调用配置 | 开启并绑定专用工具组 | 金属切削加工投标报价需调用刀具清单、工艺参数等结构化数据，functionCall支持精准绑定并调用指定工具 |
| 工具调用超时时间 | 600 秒 | 机床数据拉取、数控程序解析可能耗时较长，600秒可覆盖多数常规场景，按实测标定可调整 |
| 单次工具调用返回条数 | 前 3 条 | 投标报价仅需最新的刀具寿命、工序工时等核心数据，过多条目会增加上下文冗余 |
| 工作流/API 工具选择配置 | auto | 工具调用需根据投标文稿的不同模块自动选择对应工具，auto模式可适配多场景调用需求 |
| 工具参数校验开关 | 开启 | 切削参数、公差数值需符合行业规范，校验可避免无效数据进入报价计算 |
| 上下文拼接长度 | 800–1200 字符 | 投标文稿的工艺说明模块需保留关键参数，过长会干扰工具调用的意图识别 |

## 容易做错的三处
- 现象：调用工具时返回「function call not supported」报错。原因：使用的大模型服务未正确适配`functionCall`格式，或未开启对应工具调用权限。
- 现象：拉取的刀具清单数据缺失寿命参数。原因：工具未正确绑定刀具管理系统的字段映射，未提取单位为分钟的刀具寿命数据。
- 现象：工具调用超时，返回「请求超时」提示。原因：工具调用超时时间设置过短，未覆盖机床数据拉取或复杂数控程序解析的耗时。

## 怎么确认配好了
- 发起测试提问，指定生成投标用的工序成本明细，核对工具是否自动调用绑定的专用工具并返回匹配的结构化数据。
- 查看工具调用日志，确认`functionCall`触发逻辑正常，无格式错误类报错。
- 模拟长耗时的工具调用场景，核对超时阈值是否适配当前业务的实际处理节奏。
- 输入包含切削参数的提问，核对工具是否自动校验参数格式并返回符合行业规范的结果。
