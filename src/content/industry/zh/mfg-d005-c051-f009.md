# 金属切削加工的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
金属切削加工的数据来源包括产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES系统、量检具校准记录。数据更新频率为每工单、每件工件、抽检批次或刀具更换时触发。日常生成的文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表、量具校准记录，字段涵盖刀具型号、切削转速、进给量、工序尺寸公差、机床编号等，单位多为毫米、转每分钟、毫米每齿等。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据分散于多个异构系统，需要配置适配多源数据的接入规则，确保不同系统的工艺、刀具、机床数据可同步至知识库。高更新频率要求向量库更新策略匹配工单、刀具更换等触发节点，避免召回过时数据。文档包含结构化工艺参数、非结构化数控程序与三维模型截图，需要支持混合格式的内容解析。同时，金属切削加工的工艺数据关联性强，单一工序的参数变更会影响整体报价，因此模型输出的严谨性要求较高。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 金属切削加工的工艺文档、数控程序内容较长，需要完整召回相关工序、刀具参数等核心内容，避免关键信息截断 |
| `maxTokens` | 4000–6000 token | 投标报价文稿需要包含完整的工艺说明、报价明细与合规说明，该取值可保证输出内容完整无截断 |
| `quoteMaxToken` | 2000 token | 需保留引用的工艺路线、刀具清单等核心文档的完整片段，确保报价依据可追溯 |
| 工作流/API 工具选择配置 | `auto` | 可根据输入的图纸、工序卡、数控程序等不同类型内容，自动调用适配的处理逻辑生成文稿 |
| `temperature` | 0.2–0.4 | 投标文稿需要严谨准确，该取值区间可降低模型生成偏离实际工艺参数的内容概率 |
| `AIPROXY_API_ENDPOINT` | 按实际部署环境填写接入地址 | 保证模型调用的链路正常，匹配FastGPT v4.17.0的代理接入规范 |
| `AIPROXY_API_TOKEN` | 按授权配置填写有效令牌 | 验证模型调用的权限，确保服务调用合法有效 |

## 容易做错的三处
- 现象：调用模型返回503状态码，one api链路测试正常但当前分组调用失败。原因：`AIPROXY_API_TOKEN`配置错误或服务节点负载过高，导致无法正常建立连接。
- 现象：召回的工艺数据存在片段截断，报价文稿缺失关键工序参数。原因：`maxContext`取值过小，未完整召回关联的工艺路线、刀具清单等内容。
- 现象：生成的报价参数与实际工艺不符，出现不合理的切削转速或进给量。原因：`temperature`取值过高，模型生成了偏离实际金属切削工艺要求的内容。

## 怎么确认配好了
- 测试调用`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的连通性，确认返回正常的响应格式。
- 上传一份完整的工序卡与刀具清单，检查召回内容的完整度，确认无关键字段或参数缺失。
- 生成一份模拟投标报价文稿，核对输出的工艺参数与上传的文档内容匹配度，调整`temperature`至合适区间。
- 测试上传数控程序或三维模型截图，确认模型可以识别并提取相关切削参数与工序要求。
