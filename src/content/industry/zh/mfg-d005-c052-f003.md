# 钢材轧制与精整的投标文稿与报价编制：多轮对话与提示词

本配置基于FastGPT v4.17.0版本，适配钢材轧制与精整场景的投标文稿与报价编制需求。

## 这个品类的数据长什么样
钢材轧制与精整的业务数据来源于板坯或钢坯批次、加热炉、轧机自动控制、在线测厚测宽、表面检测及MES系统。数据更新频率为每卷或每支实时同步，日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书。数据字段包含批次标识、工艺温度、压下量、轧制速度、几何尺寸、表面缺陷等级等，单位涵盖毫米、摄氏度、米每分钟等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据按每卷或每支实时更新，多轮对话的上下文窗口需限制范围，避免加载过时或冗余的历史数据。业务文档包含大量专业工艺术语，提示词需明确指定可识别的字段与单位，确保AI输出符合行业规范。数据关联批次维度，多轮对话需支持绑定当前投标的钢卷批次号，精准匹配对应批次的工艺与质量数据。复杂工艺计算需较长处理时长，对话超时阈值需适配业务需求，避免中断流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 适配单卷轧制相关文档的总字符量，避免上下文溢出 |
| 知识库召回条数 | 前6条 | 覆盖单批次对应的轧制规程、质量报告等核心文档 |
| 提示词变量绑定 | 启用`variables` | 绑定投标涉及的钢卷批次、材质参数，精准匹配业务数据 |
| 对话上下文`messages`保留轮次 | 最近3轮 | 减少冗余历史，聚焦当前报价与文稿编制的需求 |
| 会话标识`chatId`绑定 | 绑定当前投标项目ID | 区分不同投标项目的对话上下文，避免数据混淆 |
| 超时阈值 | 600秒 | 适配复杂工艺数据的检索与计算流程 |
| 文档分块长度 | 1000–1500 字符 | 适配轧制规程的单段内容长度，提升检索精度 |

## 容易做错的三处
- 现象：对话日志中出现非业务字段的错误标注，如将设备IP地址标记为轧制参数。原因：未在提示词中限定标注的字段范围，导致无关数据被误识别。
- 现象：AI对话的输出实时显示在工作流页面，打断后续的文本拼接步骤。原因：未配置对话输出的延迟触发规则，直接返回实时生成结果。
- 现象：知识库检索的质保书数据传入AI对话后，无法被正确引用。原因：未在HTTP请求处理环节标准化质保书的字段格式，导致AI无法匹配业务上下文。

## 怎么确认配好了
- 发起包含指定钢卷批次号的测试对话，检查AI是否能关联对应批次的轧制规程与质量报告数据。
- 测试多轮对话的上下文传递，确认第一轮生成的报价参数可作为第二轮对话的输入。
- 触发完整工作流，检查AI输出是否在文本拼接组件完成后再返回指定结果。
- 查看对话日志，确认标注的字段仅包含业务相关的工艺参数与质量数据。
