# 钢材轧制与精整的投标文稿与报价编制：工作流编排

## 这个品类的数据长什么样
本品类数据来自板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与MES系统。日常生成的文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书。数据更新以每卷或每支钢卷为单位，部分参数实时同步，字段包含批次号、厚度公差、表面缺陷等级、温度曲线等，随生产批次动态调整。

## 这些特征在「工作流编排」这一环带来什么约束
本品类数据以单卷或单支钢卷为更新单元，且部分参数实时同步，要求工作流节点触发时机需匹配生产批次的节点事件，避免跨批次数据混用。多类业务文档需按投标需求拼接整合，要求工作流支持按字段规则自动提取对应文档片段。板形、厚度等核心参数需实时校验，要求工作流内置实时数据调用节点，且参数校验逻辑需适配动态更新的批次数据。质保书、轧制规程等文档需关联对应生产批次，要求工作流中需绑定`variables`存储批次标识，确保数据溯源准确。

## 配置怎么定
本页面基于FastGPT v4.17.0版本的配置规则说明。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按生产批次标识初始化，取值范围为`0001–9999` | 匹配本品类单卷/单支钢卷的批次编号规则，确保数据溯源准确 |
| 节点触发时机 | 绑定生产批次完成事件，延迟`30–60 秒`执行 | 适配本品类数据实时同步的节奏，避免获取未完成的生产数据 |
| 文档提取规则 | 按字段匹配轧制计划、表面质量报告的对应字段，单次提取`1000–1500 字符` | 匹配投标文稿的内容长度要求，避免冗余信息干扰 |
| 全局变量更新阈值 | 按实测标定 | 本品类数据更新频率动态，需根据实际生产节奏调整更新阈值 |
| `nodeId` | 为每个文档拼接节点分配唯一`nodeId` | 区分不同业务文档的拼接逻辑，避免节点执行冲突 |

## 容易做错的三处
- 现象：工作流配置保存后无法定位存储位置。原因：未在系统设置中配置工作流默认存储目录，导致配置文件未按预期路径保存。
- 现象：从简易任务上传的文件无法将链接作为参数传入工作流工具。原因：未将上传文件的路径参数与工作流的输入节点正确绑定，未启用文件链接映射规则。
- 现象：修改全局变量后，下一节点调试时提示输入为空。原因：未将更新后的`variables`参数同步至后续节点的输入配置，导致变量未正确传递。

## 怎么确认配好了
- 手动触发一次工作流，查看节点日志中是否正确提取了对应批次的轧制计划、表面质量报告片段。
- 上传测试用的钢卷批次数据，确认全局变量`variables`中的批次标识是否正确传递至所有后续节点。
- 调用工作流工具，验证上传文件的链接是否正确传入对应节点，无参数缺失报错。
- 检查工作流的触发时机是否与生产批次完成事件匹配，无延迟或提前执行的情况。
