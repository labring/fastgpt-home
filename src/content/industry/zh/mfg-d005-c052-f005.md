# 钢材轧制与精整的投标文稿与报价编制：工具调用与插件

## 这个品类的数据长什么样
本品类数据来自板坯或钢坯批次、加热炉、轧机自动控制、在线测厚测宽、表面检测系统及MES。数据更新节奏为每卷或每支钢产品产出时实时同步，核心文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书。数据字段包含钢卷编号、厚度公差（单位mm）、宽度（单位mm）、表面缺陷等级、批次关联信息等，支持卷级全链路追溯。

## 这些特征在「工具调用与插件」这一环带来什么约束
卷级实时更新的数据要求工具调用需支持动态拉取单批次或多批次的工艺、质检数据，无法依赖静态缓存。多类型文档的结构化差异要求插件需适配不同字段的拼接与格式转换，避免投标文稿出现字段错位。投标需整合多维度的轧制参数，工作流需串联多个数据源工具，同时需设置异常捕获机制，应对数据缺失等风险，避免因单环节出错导致报价偏差。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | `auto` | 适配多工具调用场景，自动匹配轧制数据查询、报价计算、文档生成插件 |
| 工作流/API 函数调用配置 | `enabled` | 支持结构化输出投标所需的钢卷参数、质检结果等专属字段 |
| 工作流节点超时时间 | `300 秒` | 预留足够时间等待实时数据接口响应，适配在线测厚、表面检测的实时返回节奏 |
| 工具调用重试次数 | `2 次` | 应对实时数据的临时波动，避免单次调用失败导致工作流中断 |
| 上下文窗口大小 | `8000–12000 token` | 需整合轧制规程、质保书等多份文档内容，保证投标文稿的信息完整性 |

## 容易做错的三处
- 接口调用工作流后，对话日志中的运行数据为空。原因是未绑定对应轧机、MES的数据源插件，或未正确传递钢卷批次参数。
- 自定义插件运行后输出下载地址持续跳动，最终才给出结果。原因是插件需聚合多批次实时数据，未设置等待聚合节点，导致分批返回结果。
- 工作流A调用工作流B无法执行完整。原因是工作流B未配置输入参数校验，或未开启完整执行模式，导致中途终止预设环节。

## 怎么确认配好了
- 触发测试工作流，核对日志中是否包含轧制计划、质保书等本品类专属的数据源返回内容。
- 运行自定义插件，检查输出结果是否包含钢卷编号、厚度公差等专属字段，格式符合投标文稿要求。
- 验证嵌套工作流调用时，子工作流是否完整执行所有预设环节，无中途终止情况。
- 测试工具调用重试配置，模拟数据临时波动场景，确认重试机制正常触发。
