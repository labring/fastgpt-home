# 钢材轧制与精整的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
该品类数据来自板坯或钢坯批次台账、加热炉运行参数、轧机自动控制日志、在线测厚测宽数据、表面检测报告及MES系统。日常文档包含轧制计划、加热制度、轧制规程、单卷板形厚度记录、表面质量报告与成品质保书。数据更新频率为每卷或每支钢产品产出时实时同步，单条数据包含批次号、规格参数、温度曲线、缺陷等级、检验数值等字段，字段单位涵盖毫米、摄氏度、平方米等工业常用单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的投标文稿与报价编制需要关联单卷或单支钢产品的全链路数据，因此模型接入需支持批量读取多维度实时数据。数据更新频率高且单条数据体量较小，要求配置需适配高频小批量数据调用，避免超时。不同文档包含的字段差异较大，例如轧制规程包含压下率参数，质保书包含力学性能指标，配置需支持多文档结构的自适应解析。投标报价涉及跨部门数据整合，模型需关联多系统数据源，因此接入配置需预留多API对接端口。本配置基于FastGPT v4.17.0版本完成适配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配单卷钢产品的全链路文档与数据总量，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 匹配投标报价文稿的单段输出长度，满足多批次数据的整合需求 |
| `quoteMaxToken` | 1500 token | 限制引用的轧制数据与质保书内容的总长度，确保上下文合理性 |
| `temperature` | 0.3–0.5 | 控制报价与文稿的严谨性，避免参数浮动超出工业标准范围 |
| `AIPROXY_API_ENDPOINT` | 企业内部部署的FastGPT代理地址 | 适配钢材轧制企业的内网数据访问安全要求 |
| `AIPROXY_API_TOKEN` | 企业专属认证令牌 | 实现数据源的权限控制，防止未授权访问生产数据 |

## 容易做错的三处
- 现象：页面嵌入FastGPT聊天框时无法加载内容，控制台返回跨域错误。原因：未在`AIPROXY_API_ENDPOINT`的配置中添加前端域名至跨域白名单，导致请求被拦截。
- 现象：批量上传轧制文档时，仅前十几条数据被正常处理，后续条目无返回结果。原因：`maxContext`参数设置过小，无法容纳多批次数据的上下文总量，触发自动截断逻辑。
- 现象：尝试接入casdoor身份验证时配置失败，提示权限不足。原因：未在FastGPT v4.17.0的身份认证模块中绑定企业组织ID，导致身份校验无法通过。

## 怎么确认配好了
- 访问FastGPT v4.17.0的模型接入管理页面，核对`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置值与企业内部参数一致。
- 上传单卷钢产品的轧制计划与质保书文档，触发模型生成报价片段，检查输出是否包含正确的批次号与规格参数。
- 批量上传10份以上的轧制文档，确认所有条目均被解析，无截断或遗漏情况。
- 测试casdoor账号登录，确认可正常访问模型配置与数据调用功能。
