# 钢材轧制与精整的投标文稿与报价编制：部署与升级

## 这个品类的数据长什么样
数据来自板坯或钢坯批次、加热炉、轧机自动控制、在线测厚测宽、表面检测与MES系统。日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书。更新节奏为每卷或每支钢料的实时更新。文档字段包含批次标识、温度参数、厚度宽度数值、表面缺陷等级、力学性能指标等，对应工业生产的标准单位。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据为每卷或每支钢料的实时更新内容，且来自多套工业生产系统，部署时需要适配多源异构数据的接入逻辑，无法直接使用通用文档解析流程。投标文稿编制需要结合实时轧制参数与历史批次数据，因此向量库与数据库的配置需要支持高频小批量数据的同步与查询。由于涉及轧制规程、质保书等专业工业文档，部署时需要适配行业专属术语的向量建模逻辑。升级过程中需要保证原有对接的MES系统接口不中断，避免影响生产数据的实时同步。同时，由于数据出错会引发钢卷降级、设备损伤等后果，部署的稳定性要求较高，需要配置完善的失败重试与数据校验机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 条` | 适配每卷钢料的实时数据连接数，避免数据库连接耗尽 |
| `PG_URL` | `postgresql://用户名:密码@服务器地址:5432/steel_roll_db` | 存储轧制规程、质保书等结构化工业文档与投标历史数据 |
| `REDIS_URL` | `redis://:自定义密码@服务器地址:6379/0` | 缓存实时轧制批次数据与会话状态，适配高频小批量数据更新 |
| `STORAGE_S3_ENDPOINT` | 按企业内部对象存储服务地址配置 | 存储大体积的轧制记录、表面检测报告等工业文档 |
| `ROOT_KEY` | 按平台安全规范生成随机字符串 | 用于平台内部接口鉴权，避免未授权访问部署后的系统 |
| `FILE_TOKEN_KEY` | 与对象存储服务一致的加密密钥 | 用于生成文档访问令牌，保障工业文档的访问安全 |

## 容易做错的三处
-  修改前端相关配置后，平台前端无法加载可用模型列表。原因是未正确配置`ROOT_KEY`导致后端接口鉴权失败，无法返回模型信息。
-  新部署的快速体验版启动后出现连接报错。原因是`PG_URL`或`REDIS_URL`的连接参数错误，未正确匹配数据库的用户名、密码与端口。
-  执行`docker run --gpus all -itd -p 7231:7231`启动marker_images容器后服务异常。原因是未正确挂载本地工业文档目录到容器内，或容器内的CUDA版本与主机驱动不匹配。

## 怎么确认配好了
-  登录FastGPT v4.17.0管理后台，运行数据库连接测试工具，确认配置的`PG_URL`与`REDIS_URL`可正常建立连接。
-  上传一份轧制质量报告文档，验证`STORAGE_S3_ENDPOINT`配置的存储服务可正常完成文件上传与下载。
-  使用配置的`ROOT_KEY`发起内部接口请求，确认鉴权流程无异常。
-  模拟多批次钢料的数据同步请求，检查数据库连接数未超过`DB_MAX_LINK`的设置阈值。
