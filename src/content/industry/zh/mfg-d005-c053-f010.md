# 钢铁冶炼与连铸的投标文稿与报价编制：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来源包括铁水与废钢基础数据、L2过程控制实时数据、化验室成分检测报告、MES生产管理数据、能源介质系统参数及设备状态记录。日常文档包含炉次计划、配料单、转炉冶炼记录、连铸工艺记录、板坯判定单等。数据更新频率覆盖每炉次生成、实时同步及每班汇总更新，字段包含炉次标识、工艺参数、成分检测项、设备运行状态等，单位随对应业务场景调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据的炉次绑定更新特性要求检索召回需精准匹配对应炉次或浇次的上下文，避免跨炉次数据混淆。多源异构的文档与数据格式（如结构化报表、过程日志、检测报告）要求检索模式需支持混合类型内容召回。每班汇总的批量数据需限定检索范围，避免冗余信息干扰投标文稿与报价的精准性。成分指标与工艺参数的强关联特性要求检索优先召回同工艺场景下的历史数据，提升匹配度。实时数据的高频更新要求知识库索引支持增量同步，避免检索到过期数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配钢铁冶炼工艺参数的强关联特性，过滤低匹配度的无关数据 |
| `limit` | `前6条` | 平衡投标文稿的内容全面性与篇幅限制，避免冗余信息过多 |
| 分块长度 | `800–1200 字符` | 适配冶炼记录、成分报告等单条文档的长度特征 |
| 检索超时时间 | `30 秒` | 适配实时工艺数据的检索响应需求，避免超时中断 |
| 最大上下文长度 | `4000 token` | 适配投标文稿的整体篇幅需求 |
| `usingReRank` | 开启 | 提升高语义复杂度的工艺数据检索结果相关性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 覆盖工艺术语的多表达形式，提升召回覆盖度 |
| `collectionIds` | 绑定冶炼连铸业务域的知识库集合 | 限定检索范围至专属文档，避免跨品类数据干扰 |

## 容易做错的三处
- 检索结果中公式显示为乱码或纯文本片段。原因是知识库导入文档时未启用公式解析适配，导致数学表达式无法被正确识别渲染。
- 同一查询多次检索后返回结果不一致。原因是未固定检索召回的结果范围，或本地部署的模型未开启确定性生成配置。
- 检索召回覆盖全量业务表数据，未限定有效范围。原因是未配置`collectionIds`绑定专属知识库集合，导致跨品类或冗余数据被纳入检索结果。

## 怎么确认配好了
- 执行单次检索，核对返回结果的条数与`limit`配置的取值一致。
- 查看检索结果的相似度得分，确认符合`similarity`配置的取值区间。
- 导入包含工艺公式的测试文档，执行检索，确认公式可正常渲染显示。
- 执行同一查询多次，确认返回结果的Top条目无明显变化，验证检索与生成的确定性。
