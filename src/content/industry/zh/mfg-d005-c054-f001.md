# 钣金下料折弯的投标文稿与报价编制：HTTP 接口与外部系统

## 这个品类的数据长什么样
钣金下料折弯类厂商的核心数据来自CAD/CAM软件、订单BOM、板材库存系统、激光切割机、折弯机与MES系统。日常产出的文档包含工件展开图、数控下料程序、折弯工艺卡、套料图、首件记录与工序流转卡。数据更新随订单生成、每日库存盘点与生产换型触发，字段包含板材厚度、折弯角度、孔位坐标、下料尺寸与工件编号，单位多为毫米、度与平方米。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多数据源的接入需求要求接口支持从不同系统拉取对应数据，需统一的参数标识来关联订单与工件信息。不同更新频率的业务数据，要求接口支持按需触发与定时拉取两种模式。钣金工件的多品种小批量特征，要求接口单次请求的工件数量不宜过多，避免接口过载。同时，数据字段的单位一致性要求接口需对传入的图纸、库存数据做格式校验，防止因单位不匹配导致的下料错误与板材浪费。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 接口超时时间 | 600 秒 | 钣金下料折弯的展开、套料计算耗时较长，需预留足够响应时长，适配FastGPT v4.17.0版本的接口调用规范 |
| 授权校验配置 | `Authorization` 头携带 Bearer 令牌 | 符合工业API安全通用规范，适配多外部系统的接入要求 |
| 请求参数封装 | 以 `variables` 字段携带业务数据 | 统一参数结构，便于外部系统解析投标所需的板材、工序与图纸信息 |
| 响应数据返回规则 | 完整返回 `responseData` 字段 | 便于外部系统校验报价数据的完整性与正确性 |
| 单次请求工件上限 | 不超过20个工件 | 匹配钣金多品种小批量的业务特征，避免接口过载 |
| 触发时机配置 | 按订单提交后触发 | 贴合厂商投标流程的节点顺序，减少无效调用次数 |

## 容易做错的三处
- 接口返回的折弯系数字段为空，导致投标报价的下料尺寸计算错误。原因是未在请求参数中携带工件的材质与厚度信息，无法触发对应折弯补偿数据的拉取逻辑。
- 接口调用返回504超时状态码，无法生成完整的投标文稿。原因是未配置足够长的超时时间，而钣金套料、展开计算的耗时超出默认接口时限。
- 提交的套料图数据无法被解析，导致投标文稿缺少下料清单。原因是未按照约定的参数规则封装`variables`字段，导致外部系统无法关联对应图纸信息。

## 怎么确认配好了
- 调用模拟测试接口，携带真实订单的工件信息，检查返回的`responseData`是否包含完整的下料尺寸、折弯角度与板材用量字段。
- 配置接口触发时机为订单提交后，通过外部系统的调用日志查看接口是否在订单生成后自动发起请求。
- 模拟无效令牌的调用场景，确认接口返回401状态码，验证`Authorization`校验配置生效。
- 调整单次请求的工件数量，检查接口是否在超过上限时返回参数错误提示，验证单次请求上限配置生效。
