# 铸造（砂型、精密、压铸）的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自ERP物料主数据、熔炼炉与测温仪、光谱仪、MES炉次记录、模具管理系统及客户图纸与技术条件。日常文档包含铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告、不合格品评审单，数据按每炉次、每批或每日更新。数据包含合金配料参数、熔炼温度、炉次标识、模具编号、客户技术要求条目等字段，覆盖结构化业务单据与非结构化工艺文档两类格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据更新频率高且按炉次批次触发，要求索引支持增量更新以避免全量重建的资源消耗，适配铸造生产的实时性要求。文档类型包含结构化单据与非结构化工艺内容，需适配不同长度的文本分块规则，确保关键业务标识不被拆分丢失。客户技术要求与自身工艺参数的匹配精度直接影响投标报价的准确性，需针对合金配料、熔炼温度等特定字段优化向量召回的匹配规则，避免无关数据干扰检索结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配铸造工艺卡、配料单的常规段落长度，避免关键工艺参数被拆分 |
| 重叠长度 | 100–150 字符 | 保留跨段落的工艺关联信息，防止分块后丢失炉次与模具的对应关系 |
| 相似度阈值 | 0.75–0.85 | 匹配铸件工艺参数的精度要求，过滤低相关性的历史炉次数据 |
| 单次搜索上限 | 前 10 条 | 覆盖投标所需的典型工艺参考范围，避免过多冗余数据干扰报价计算 |
| `defaultToken` | 用代表性工艺文档样本实测校准 | 这是直接文本切分使用的默认 token 数；请抽查样本文档的分块结果。参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx) |
| `maxToken` | 按所选嵌入模型/服务支持的输入上限设置 | 这是嵌入模型配置中的最大 token 数，不是检索或 LLM 上下文；请核对所选模型或服务商文档。参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx) |

## 容易做错的三处
- 出现503状态码，提示当前分组无可用text-embedding-v3模型渠道。原因：未为text-embedding-v3模型配置对应调用渠道，或渠道配额耗尽。
- 启动FastGPT容器后出现API密钥验证失败的提示。原因：未在docker-compose.yml中正确配置CHAT_API_KEY环境变量，或未重建容器使配置生效。
- 无法通过检索测试界面直接调整索引参数，需进入对应知识库的内容管理页面修改。原因：平台已移除检索测试界面的直接编辑按钮，索引参数调整需通过知识库配置入口完成。

## 怎么确认配好了
- 上传一份铸造工艺卡与配料单，执行检索测试，查看召回结果是否包含匹配的炉次参数与模具信息。
- 检查向量索引的更新日志，确认新上传的炉次记录在指定时间内完成索引同步。
- 使用代表性工艺文档检查文本切分结果以验证`defaultToken`，再按所选嵌入模型/服务输入上限核对`maxToken`。
- 输入客户技术要求的关键词，确认召回结果包含对应的材质报告与不合格品评审记录。
