# 铸造（砂型、精密、压铸）的投标文稿与报价编制：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据来自ERP物料主数据、熔炼测温设备、光谱分析仪、MES系统、模具管理系统及客户技术图纸。日常文档包含铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告与不合格品评审单。数据更新随炉次、批次或每日完成，文档包含炉次编号、浇注温度、合金配料参数、模具使用次数等字段，无统一固定格式，随生产环节动态生成。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源导致检索时需统一字段映射规则，避免跨系统数据的匹配混乱。高频更新节奏要求召回逻辑适配动态生成的炉次、批次数据，防止调用过期的工艺或报价信息。专业字段多且业务关联紧密，需严格限定召回范围至铸造品类的专属文档，避免无关内容干扰结果。投标场景依赖精准的历史工艺与报价匹配，对召回的相关性要求高于通用检索，需过滤非目标文档。

## 配置怎么定
本页面适配FastGPT v4.17.0版本，以下配置项基于该版本的功能逻辑设定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.82 | 匹配铸造专业术语与业务参数的精度要求，兼顾召回覆盖率与相关性 |
| `limit` | 前10–15条 | 控制单次召回的文档数量，避免超出投标文稿的上下文承载上限 |
| `usingReRank` | 开启 | 对召回结果按业务相关性重排，优先展示炉次、配料相关的核心文档 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展专业术语查询，覆盖铸造领域的专业表述，比如将“缩孔”关联至内部缺陷评审单 |
| `collectionIds` | 仅包含铸造工艺、报价、炉次记录的知识库集合ID | 限定召回范围，排除其他品类的文档，避免无关内容混入 |
| `searchMode` | `embedding` | 适配铸造专业文档的语义特征，匹配工艺参数与历史报价的关联逻辑 |

## 容易做错的三处
- 现象：检索结果中混入非铸造品类的文档，或召回了与当前投标项目无关的炉次记录。原因：未限定`collectionIds`的范围，召回了其他知识库集合的内容。
- 现象：线上部署的知识库导入后出现乱码，本地部署无异常。原因：线上环境的文件编码未适配铸造文档的专业符号，未统一设置编码格式。
- 现象：无法选择100到900之间的`limit`参数取值，仅能选择100或900档位。原因：当前FastGPT版本的界面配置项未开放该区间的自定义输入，仅提供固定档位选项。

## 怎么确认配好了
- 输入一条铸造专业问题（如“某型号铸件的合金配料参数与浇注温度”），检查召回结果是否仅包含铸造品类的文档。
- 查看检索结果的数量，确认符合`limit`参数的设定范围。
- 检查回答中是否存在乱码或多余的分隔符，确认格式过滤已生效。
- 对比不同检索请求的结果，确认重排逻辑优先展示核心业务文档。
