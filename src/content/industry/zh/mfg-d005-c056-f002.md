# 锂离子电芯制造的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自原材料批次台账、生产MES系统、浆料与涂布检测设备、车间露点监测装置、化成分容柜及实验室测试设备。日常文档包含配料记录、涂布辊压参数台账、卷绕或叠片工序记录、注液量登记、化成分容数据报表、OCV与安全测试报告。数据更新节奏为每生产批次、每只电芯生成对应记录，部分车间露点、浆料状态数据为实时更新。文档字段包含物料批次号、工艺参数数值、测试结果数值、设备运行状态标识等，单条记录的长度差异较大。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且更新频率不均，实时数据与批量归档数据需区分处理，索引时需适配不同更新节奏的数据源。单条记录长度差异大，部分工艺参数类记录较短，测试报告类记录较长，会影响分块后的向量匹配一致性。锂离子电芯的电化学体系对数据精度要求高，参数数值的细微偏差会影响投标报价的工艺合理性，向量模型需准确捕捉参数间的关联逻辑。不同设备导出的文档格式不统一，索引前需统一字段映射规则，避免向量索引出现字段缺失或错位。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面设置项制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类单条工艺记录与测试报告的长度范围，避免分块破坏参数关联逻辑 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的工艺参数上下文，防止跨分块的关键关联信息丢失 |
| `defaultToken` | 4096 token | 覆盖多数工艺参数与测试数据的向量编码长度需求，适配基础嵌入模型的输入限制 |
| `maxToken` | 8192 token | 应对较长的安全测试报告或批次汇总文档，避免截断关键数据 |
| 相似度阈值 | 0.75–0.85 | 筛选匹配度较高的历史工艺数据，保障投标文稿的工艺合理性与报价准确性 |
| 单次召回上限 | 前 8 条 | 平衡索引效率与数据覆盖度，避免过多冗余数据干扰向量匹配结果 |

## 容易做错的三处
- 界面显示索引任务持续处于运行中状态，无进度更新。原因：未适配该品类实时更新的化成分容数据，索引任务未设置增量更新规则，持续全量扫描全量数据导致阻塞。
- 调用嵌入模型时返回503状态码。原因：未配置合理的模型调用超时阈值，或`defaultToken`设置超出模型实际支持的最大长度，导致模型服务无响应。
- 索引结果中缺失部分工艺参数字段。原因：未统一不同设备导出文档的字段映射规则，部分非标格式的测试报告未完成字段提取，导致向量编码时丢失关键信息。

## 怎么确认配好了
- 查看索引任务日志，确认分块长度与重叠长度的设置与当前品类文档长度匹配，无大量截断或分块过细的提示。
- 测试嵌入模型调用，验证`defaultToken`与`maxToken`的设置未超出所接入模型的输入限制，无报错返回。
- 抽样调取历史工艺数据的向量索引结果，确认所有关键字段均被正确编码，无缺失或错位情况。
- 对比不同批次数据的索引耗时，确认单次召回上限的设置未导致索引任务超时。
