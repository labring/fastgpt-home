# 锻造与模锻的投标文稿与报价编制：部署与升级

本页配置基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
锻造与模锻场景的核心数据来自原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图。日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单与超声检测报告。数据更新以每件锻件、每批物料或每炉次为节奏，核心字段包含锻造比、纤维方向、炉批号、加热区间参数与缺陷检测结果。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的数据来源要求部署时支持对接不同系统的接口，高频次的按批/按炉更新需要配置近实时的数据同步机制。核心字段的专业性要求索引时匹配锻造比、纤维方向等专属参数，避免通用字段匹配偏差。内网部署的常见场景需要适配无公网环境的存储与连接配置，同时需保证数据一致性以防止锻件报废、批次隔离等严重后果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:pass123@192.168.1.20:27017/fastgpt?authSource=admin` | 存储超声检测报告、锻造工艺规程等文档与结构化锻件批次数据 |
| `REDIS_URL` | `redis://:redisPass@192.168.1.21:6379/1` | 缓存炉批号、锻造比等高频查询字段，支撑快速报价核对 |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.22:9000` | 存储大体积检测报告与工艺文档，适配内网无公网部署场景 |
| `DB_MAX_LINK` | `20–30` | 支撑多批次锻件数据的并发查询，避免连接耗尽 |
| `ROOT_KEY` | 自定义强复杂度字符串，如`aB3!kL9@mN7` | 管理内网部署的FastGPT后台权限，防止未授权访问 |
| `FE_DOMAIN` | `http://fastgpt-fe:8080` | 配置前端访问域名，适配内网访问路径 |

## 容易做错的三处
- 现象：使用docker-compose部署rerank模型后，FastGPT后台未显示该模型。原因：未在`REDIS_URL`配置中分配专属数据库索引缓存模型参数，或模型容器挂载路径未与FastGPT容器共享。
- 现象：配置模型为v2版本并在后台选中对应名称，但调用时仍使用v1版本。原因：未同步更新`MONGODB_URI`对应的模型配置集合，或环境变量未覆盖默认模型配置。
- 现象：内网离线部署后，OneAPI容器持续重启，日志提示启动失败。原因：未将离线导出的镜像正确加载至内网Docker环境，或`PG_URL`配置指向公网数据库地址导致无法建立连接。

## 怎么确认配好了
- 登录FastGPT后台系统设置页面，查看数据库与存储连接状态，确认`STORAGE_S3_ENDPOINT`对应的对象存储可正常上传下载超声检测报告文件。
- 发起一次模拟锻件报价查询，核对返回的锻造比、炉批号等字段与内网MES系统中的数据一致。
- 重启FastGPT容器后，检查日志中无数据库连接超时、模型加载失败的报错信息。
- 使用`ROOT_KEY`以外的密钥尝试访问后台管理界面，确认无法进入系统。
