# 预制混凝土构件的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
预制混凝土构件的数据来自BIM深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行日志、试验室检验记录及产品二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验报告、浇筑振捣记录、养护周期记录、脱模与出厂检验单。数据按单件构件、每批物料、每窑养护批次更新，字段包含构件编号、钢筋规格型号、混凝土强度等级、养护时长、脱模强度值等，单位涵盖毫米、兆帕、小时等。

## 这些特征在「向量模型与索引」这一环带来什么约束
预制混凝土构件的数据分散且按单件、每批物料、每窑养护批次更新，要求索引支持增量更新与多源异构数据的批量导入。构件数据包含工程图纸文本、钢筋规格、强度参数等混合内容，向量模型拆分文本时需避免破坏钢筋位置、构件尺寸这类关键信息，防止拆分后的片段丢失业务关联信息。同时，投标报价需快速匹配同项目同类型构件的历史数据，索引召回需限定在对应投标项目的构件清单范围内，避免无关数据干扰召回结果，且需适配高频更新的台账数据，保障索引实时性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的界面与参数逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 预制混凝土构件的深化图、下料单等文档长度较长，分块需保留钢筋位置、构件编号等关键信息，避免拆分断裂业务逻辑 |
| `maxToken` | 4096 token | 适配多数主流向量模型的输入上限，保障构件参数与文档片段的完整嵌入 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 匹配构件的规格参数与历史报价数据的相似度，避免过低导致无关召回或过高遗漏有效匹配 |
| 单次搜索上限 | 前 10 条 | 控制投标报价编制时的召回结果数量，避免过多数据干扰人工核对 |
| `defaultToken` | 1536 维 | 适配主流向量模型的输出维度，保障索引的召回精度与存储效率 |
| 最大上下文 | 60000 字符 | 覆盖单份投标项目的构件清单与历史报价文档的总长度，保障召回内容的完整性 |

## 容易做错的三处
- 现象：索引状态显示未就绪，无法发起检索请求。原因：未按单件构件、每批物料的更新节奏配置增量索引触发规则，全量索引加载时因数据量过大超时未完成。
- 现象：检索结果包含大量跨项目的无关构件数据，无法匹配当前投标项目的需求。原因：未将索引范围限定在当前投标项目的构件清单内，直接导入全表数据作为索引源，未做项目维度的过滤配置。
- 现象：检索结果无法匹配指定的向量模型输出，或提示模型不兼容。原因：未确认所选向量模型支持当前索引的嵌入维度，错误配置了与`defaultToken`取值不一致的向量模型参数。

## 怎么确认配好了
- 查看索引管理界面的状态标识，确认状态为就绪，核对索引包含的文档数量与导入的构件清单数量一致。
- 输入单条构件的钢筋规格与强度参数作为检索词，检查召回结果是否包含同类型的历史构件数据，调整相似度阈值至符合业务需求的区间。
- 测试增量导入单批养护窑的日志数据，确认索引自动更新且未出现数据丢失或格式错误。
- 核对向量模型的嵌入维度与配置项中`defaultToken`的取值一致，确保嵌入结果符合预期。
