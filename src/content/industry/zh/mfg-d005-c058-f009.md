# 预制混凝土构件的投标文稿与报价编制：模型接入与配置
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
预制混凝土构件的业务数据来源于BIM深化设计、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检验报告及二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣日志、养护周期记录、脱模与出厂检验报告。数据更新频率随构件单件、生产批次及养护窑批次变动，字段包含构件编号、外形尺寸、钢筋规格、预埋件位置、混凝土强度等级、生产批次号等，单位多为毫米、立方米、兆帕。不同于预拌混凝土按车交付的流态材料，该品类需精准匹配现场吊装位置的参数。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散于设计、生产、检验多个环节，单份投标可能关联多件不同规格的预制构件，数据总量较大且部分为带标注的图纸类文档。高频更新的批次数据要求模型上下文及时匹配最新生产参数，而预埋件位置、强度要求等关键信息的准确性直接影响投标可行性。若参数设置不当，可能出现预埋错位、强度参数偏差等问题，导致构件报废或工期延误。因此模型接入配置需兼顾长上下文承载、视觉信息解析及数据一致性控制，避免关键信息遗漏或输出偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配单份投标关联的构件深化图、下料单、检验记录的总文本与视觉信息长度，避免关键数据截断 |
| `maxTokens` | 2000 token | 控制单轮报价明细的输出长度，适配投标文稿的分段编制与审核流程 |
| `quoteMaxToken` | 1500 token | 限制知识库引用内容的token总量，避免混入非当前构件的养护窑或批次数据 |
| `vision` | 开启 | 用于解析构件深化图中的预埋件位置、尺寸标注等视觉信息，补充文本数据的细节内容 |
| `temperature` | 0.3–0.5 | 降低输出随机性，保证投标报价的钢筋用量、强度等级等参数与设计文档一致 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或云端的模型调用地址，确保数据链路通畅 |
| `AIPROXY_API_TOKEN` | 按部署权限填写 | 适配本地或云端模型的调用权限，确保数据链路的安全性与连通性 |

## 容易做错的三处
- 现象：知识库分块内容超过`maxContext`限制后，出现预埋件位置信息截断。原因：未根据预制构件单份文档的实际长度调整`maxContext`参数，强行塞入超量数据。
- 现象：调用本地部署的m3e-large模型时返回连接超时或403状态码。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或token权限未覆盖模型调用范围。
- 现象：生成的投标报价中混凝土用量与下料单不符。原因：`temperature`取值过高，导致模型生成的参数出现随机偏差，未匹配构件的固定生产规格。

## 怎么确认配好了
- 上传单份预制构件的深化图与钢筋下料单，检查模型输出的上下文提示是否覆盖全部上传文档，无截断报错。
- 调用配置后的模型生成1份构件的报价明细，核对钢筋规格、混凝土强度等级与原始文档的字段一致性。
- 测试本地模型接入流程，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无连接超时或权限异常提示。
- 调整`temperature`参数至0.1与0.7，对比两次输出的报价数据，确认参数调整生效且符合预期的随机性控制。
