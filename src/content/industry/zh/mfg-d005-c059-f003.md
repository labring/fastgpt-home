# 预拌混凝土生产的投标文稿与报价编制：多轮对话与提示词

## 这个品类的数据长什么样
数据来源包括工程订单、砂石水泥外加剂检验记录、含水率测定报告、搅拌站控制系统日志、试验室试块记录。更新节奏为每车生产数据、每批原料检验数据、每日汇总报表。日常文档包含配合比通知单、开盘鉴定、生产运输单、原材料检验报告、试块记录、强度报告，核心字段涵盖强度等级、坍落度、骨料含水率、运输时长、龄期强度，单位涉及立方米、千克、百分比、天等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
预拌混凝土生产的业务数据更新频率差异大，多轮对话需跟踪不同时间维度的参数，如每车的实时含水率和每日的原料汇总数据，因此上下文管理需精准区分数据时效。大体积文档（如多批次配合比合集）的解析会占用较多资源，需避免在对话中一次性加载全部冗余数据。提示词需明确限定查询范围，区分投标报价所需的合规性文档和实时生产数据，否则会导致结果混淆。试块强度的龄期关联要求对话能回溯历史记录，且该品类不同于预制构件在工厂完成成形养护，性能需通过龄期试块验证，因此上下文的留存规则需匹配业务数据的更新周期。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 单次文档解析分块长度 | 800–1200 字符 | 预拌混凝土文档多包含连续的配比参数与检测记录，分块过短会割裂参数关联，过长会增加解析耗时 |
| 最大上下文长度 | 前 4000 字符（按实测标定） | 投标报价需关联多份配合比通知单与近期原料检验数据，上下文过长会导致响应延迟 |
| 问题优化开关 | 开启 | 预拌混凝土的报价问题常包含多个关联参数，优化后可精准提取核心查询条件 |
| 知识库关联匹配上限 | 前 6 条 | 单批次混凝土的关联数据不超过5份，匹配过多会干扰核心结果 |
| 对话超时阈值 | 120 秒 | 大文件解析与多批次数据检索需要较长处理时间，过短会导致未完成响应就中断 |

## 容易做错的三处
- 现象：10几M的Word文档解析时出现超时报错，状态码显示504。原因：未针对预拌混凝土的长文档调整分块配置，单块数据过大导致解析线程阻塞。
- 现象：调试预览中输入引导配置后触发报错，提示「字段格式异常」。原因：未将输入引导的关键词限定为配合比通知单、坍落度、龄期等预拌混凝土专属术语，导致系统无法匹配合法字段。
- 现象：问题优化耗时超过10秒，远超出预期。原因：未限制优化的上下文范围，引入了无关的试块强度历史数据，增加了处理负载。

## 怎么确认配好了
使用FastGPT v4.17.0版本的系统执行以下核对动作：
- 上传一份包含配合比通知单和生产运输单的10M Word文档，检查解析完成耗时是否符合预期。
- 输入「帮我调整C30混凝土的用水配比」，检查系统是否能自动提取坍落度、骨料含水率等核心参数。
- 开启输入引导功能，在调试预览中输入关键词，检查是否能正确触发关联的知识库文档。
- 查看对话历史的`messages`字段，确认多轮对话中保留了当前批次的原料检验数据。
- 检查`variables`字段是否正确存储了当前查询的工程订单编号，避免上下文混淆。
- 确认不同对话的`chatId`字段互不干扰，避免跨对话的数据串扰。
