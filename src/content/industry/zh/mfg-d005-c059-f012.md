# 预拌混凝土生产的投标文稿与报价编制：部署与升级

本页配置适用于FastGPT v4.17.0。

## 这个品类的数据长什么样
预拌混凝土生产的相关数据来源于商品混凝土搅拌站、工程项目试验室、质量与调度部门。日常处理的文档包含配合比通知单、开盘鉴定表、生产运输单、原材料检验记录、试块留存记录、强度检测报告。数据来源覆盖工程订单、砂石水泥外加剂检验报告、含水率测定记录、搅拌站控制系统数据、试验室台账。更新节奏按每车生产批次、每批原料进场、每日台账更新，数据字段包含工程编号、原料批次、含水率数值、浇筑部位、强度等级、运输时长等。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据按车、批、日高频更新，部署时需适配高并发的实时数据同步需求，避免因连接池不足导致写入失败。多类异构文档格式不统一，升级时需兼容不同模板的字段提取逻辑，确保投标文稿的信息完整性。数据来源包含现场控制系统与试验室台账，部署需打通跨系统的数据拉取权限，避免数据孤岛。投标报价需关联精准的原料成本与运输时效，升级时需验证跨模块数据联动的稳定性，防止出现报价偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30 个连接` | 该品类数据更新频繁，每车/每批数据都会触发数据库写入，需保证连接池足够支撑并发请求 |
| `REDIS_URL` | `redis://:自定义密码@redis主机地址:6379/0` | 需缓存高频查询的原料价格、工程订单信息，降低数据库负载，配置访问密码保障缓存数据安全 |
| `STORAGE_S3_ENDPOINT` | `按企业自建对象存储地址填写` | 该品类的检测报告、运输单等文档需统一存储，需适配企业现有存储服务的端点地址 |
| `FE_DOMAIN` | `https://企业内部投标系统域名` | 需将FastGPT生成的报价文档同步至内部投标平台，配置合法的前端域名实现跨域访问 |
| `ROOT_KEY` | `随机生成的32位字符串` | 需保障后台管理接口的访问安全，避免未授权的配置修改 |
| `FILE_TOKEN_KEY` | `随机生成的16位字符串` | 用于加密上传的文档附件，防止未授权访问扫描件等敏感文件 |

## 容易做错的三处
- 现象：执行`docker-compose up`时镜像拉取超时，日志显示连接GitHub镜像源失败。原因：未配置国内镜像源加速拉取，该品类的业务镜像依赖较多基础组件，拉取耗时较长。
- 现象：调用知识库检索接口时返回反序列化错误，前端页面无法展示结果。原因：未正确配置`FILE_TOKEN_KEY`导致文档附件解析失败，该品类的检测报告包含二进制格式的扫描件，解析异常会触发字段反序列化失败。
- 现象：K8s部署多个副本后，部分节点无法同步最新的原料数据。原因：未配置`REDIS_URL`的共享缓存，各副本的本地缓存不一致，导致数据更新不同步。

## 怎么确认配好了
- 执行`docker-compose pull`命令，确认所有业务镜像可在5分钟内完成拉取。
- 登录FastGPT后台管理界面，上传一份预拌混凝土的配合比通知单，确认文档可正常解析并提取工程编号、原料批次等字段。
- 启动2个K8s副本，提交一条新的原料检验数据，确认两个副本均可检索到该数据。
- 调用生成投标文稿的接口，确认返回的文档包含正确的原料成本、浇筑时效等字段。
