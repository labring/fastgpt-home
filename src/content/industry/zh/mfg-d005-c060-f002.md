# 饮料与瓶装水的投标文稿与报价编制：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自碳酸、果汁、茶饮、功能饮料及包装饮用水工厂的多类业务文档，包括配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验报告与成品检验报告。数据采集自水源与原料检测系统、配方管理系统、在线糖度酸度监测设备、灌装设备、视觉检测装置与LIMS系统，更新节奏以每批生产批次、每班作业为单位，部分在线设备数据连续采集，文档字段包含原料批次、参数数值、检验结果、设备运行状态等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的高频连续采集数据与批次化更新文档，要求向量索引支持动态增量更新与批量重索引操作。多类异构文档的字段差异，要求索引配置适配不同文档结构的分块规则，避免长文本截断或短文本拆分过度。在线设备的实时数据与静态检验报告的混合存储，要求索引同时支持低延迟实时召回与长文本精准匹配。投标场景下的报价与文稿关联数据，要求索引保留字段级的精准匹配能力，避免召回无关的跨品类生产数据。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxToken` | 8192 token | 该品类的批量投标文稿通常包含多份生产记录的汇总，适配长文本嵌入的最大长度限制 |
| `defaultToken` | 1024 token | 该品类单份基础业务文档的平均token数，适配通用嵌入的默认参数 |
| 分块长度 | 800–1200 字符 | 匹配该品类检验报告与配方单的平均长度，提升嵌入精度 |
| 重叠长度 | 100–150 字符 | 保留连续采集的在线设备数据的时序上下文关联 |
| 相似度阈值 | 0.75–0.85 | 适配投标场景下的精准匹配需求，避免无关数据召回 |
| 单次搜索上限 | 前10条 | 控制上下文冗余，聚焦核心关联的生产批次数据 |

## 容易做错的三处
- 现象：更换多语言embedding模型后，批量重嵌入任务持续显示「索引中」超过2小时。原因：未针对该品类的连续采集数据配置增量索引，全量重嵌入时加载了过量的在线设备实时数据流。
- 现象：手动上传的单份包装水成品检验报告，对应的索引在3小时后从知识库中消失。原因：未为批次化更新的文档配置持久化索引策略，临时索引未绑定生产批次ID导致被系统自动清理。
- 现象：搜索投标报价关联的配方数据时，召回了大量果汁类产品的调配记录。原因：索引未配置品类专属的字段过滤规则，未限定仅召回饮料与瓶装水品类的生产文档。

## 怎么确认配好了
- 查看批量重嵌入任务的日志，确认每个文档分块的token数未超过配置的`maxToken`值，调整分块长度至符合要求。
- 手动插入单份水处理记录，等待索引完成后执行针对性搜索，确认召回结果包含该文档且无无关品类的数据。
- 检查知识库的索引管理界面，确认所有生产批次的文档均绑定了持久化索引标签，无临时索引条目。
- 执行多语言搜索测试，确认不同语言的查询均可召回匹配的生产文档，验证新embedding模型的召回效果。
