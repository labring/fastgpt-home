# 饮料与瓶装水的投标文稿与报价编制：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验报告、成品检验报告。数据来源涵盖水源与原料检测结果、配方系统数据、在线糖度酸度监测数据、灌装设备运行数据、视觉检测数据、LIMS系统记录。数据更新节奏为每批生产、每班巡检、连续采集设备实时数据。部分文档包含明确的数值字段与对应单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的多来源、高频率更新的实时数据与结构化文档，对模型接入与配置带来多重约束。连续采集的设备数据与按批更新的生产记录会产生大量待处理语料，需匹配合适的上下文长度限制以完整覆盖生产全流程信息。不同来源的数据格式差异较大，需确保配置适配多类型文档的解析逻辑。部分文档包含精确的工艺参数与质量指标，对模型输出的准确性要求较高，需调整对应参数以平衡生成精度与调用效率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖单批生产的完整记录与关联检验报告，避免截断关键工艺参数 |
| `temperature` | 0.1–0.3 | 匹配投标文稿与报价编制对准确性的要求，减少无关参数的随机生成 |
| `AIPROXY_API_ENDPOINT` | 对应服务商的官方接入地址 | 确保模型调用的稳定性与合规性 |
| `AIPROXY_API_TOKEN` | 按服务商要求生成的专属令牌 | 保障调用权限的安全性，避免令牌过长触发存储限制 |
| `maxTokens` | 2000–3000 token | 控制单条生成内容的长度，适配投标文稿的段落式输出需求 |
| 工作流/API 工具选择配置 | auto | 让模型自主选择是否调用知识库工具，获取最新的生产数据与报价依据 |

## 容易做错的三处
- 现象：上传单份超过5000字符的水处理记录或成品检验报告时，解析耗时超过120秒。原因：未针对该品类的长文本结构化文档优化marker的解析逻辑，触发了额外的格式校验步骤。
- 现象：配置`AIPROXY_API_TOKEN`后，系统返回Error 1406 (22001): Data too long for column 'models'。原因：所使用的令牌内容长度超出系统存储字段的预设上限。
- 现象：尝试接入MemoRAG后，检索返回的灌装液位数据与当前生产批次不匹配。原因：未调整检索逻辑以适配该品类按批更新的数据特征，导致召回了过期的历史数据。

## 怎么确认配好了
- 上传一份典型的配方单与水处理记录，检查解析后的文本是否完整覆盖所有字段与数值，无明显截断。
- 发起一次报价编制请求，核对生成内容中引用的工艺参数是否与上传的生产记录一致。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的调用请求均成功返回有效结果。
- 调整`temperature`参数后，对比两次生成的投标文稿内容，确认参数调整对输出准确性的影响符合预期。
