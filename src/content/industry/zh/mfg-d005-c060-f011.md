# 饮料与瓶装水的投标文稿与报价编制：表单与交互

## 这个品类的数据长什么样
数据来源包括水源与原料检测、配方系统、在线糖度酸度监测、灌装设备、视觉检测系统与LIMS系统。日常文档包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验记录、成品检验记录。数据更新节奏为每批、每班或连续采集。字段包含投料参数、检测指标、设备运行参数、批次标识与合规校验项，单位匹配品类生产场景，如投料量、浊度、液位等对应生产场景专用单位。

## 这些特征在「表单与交互」这一环带来什么约束
该品类多源分散的数据来源，要求表单与交互环节支持跨系统数据拉取与自动关联，避免重复录入。高频的批次、班次级更新节奏，要求表单可动态加载对应生产批次的最新数据，防止使用过时信息。品类特有的合规校验需求，如浓缩液与添加剂投料范围、水处理指标阈值，要求表单内置对应字段的实时校验逻辑。频繁的产品切换场景，要求表单可快速切换适配不同品类的字段配置，减少重复调整。高速液体灌装的生产节奏，要求表单交互响应符合实时性要求，避免影响投标文稿编制效率。

## 配置怎么定
本配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 绑定对应生产批次的配方、水处理等历史数据，单次加载不超过15条批次记录 | 品类数据按批次更新，需关联对应批次的真实生产数据，避免冗余数据拖慢交互 |
| `userSelect` | 提供三类数据源切换选项，分别对应水源检测、配方系统、灌装设备知识库 | 品类数据来源分散为三类，需支持按数据源自动切换检索内容 |
| 表单校验规则 | 开启浓缩液、添加剂投料量的区间校验，阈值按实测标定 | 品类最耗时的复核环节为投料校验，需提前在表单中拦截超限风险 |
| 循环体配置 | 设置循环下标步长为1，绑定单批次的检验记录组 | 品类需按批次处理多组检验数据，循环下标需准确匹配批次顺序 |
| 交互响应超时 | 设置为30秒 | 高速生产节奏下，需控制交互响应时长，避免延误投标文稿编制 |

## 容易做错的三处
- 现象：循环体执行后返回字段为空的null值。原因：未绑定单批次检验记录组作为循环数据源，下标步长设置未匹配数据结构。
- 现象：用户选择是否跳过知识库检索的操作无响应。原因：未将`userSelect`的选择结果同步到检索触发逻辑，无法识别用户的选择参数。
- 现象：切换数据源分类时出现报错。原因：未将分类名称与品类的数据源绑定，导致检索时无法匹配对应的数据来源。

## 怎么确认配好了
- 选择对应生产批次后，核对`formInput`加载的历史数据是否包含该批次的配方、水处理等记录。
- 操作`userSelect`的数据源切换选项，确认检索流程是否随选择的分类调整对应知识库。
- 运行循环体测试流程，确认下标值按1递增，返回的检验记录组与批次匹配。
- 触发校验与检索动作，确认交互响应未出现明显延迟，符合生产场景的实时性要求。
