# PCB制造的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来自客户提供的Gerber文件、钻带、BOM，以及工厂内部CAM产出资料、设备运行参数、槽液化验结果、AOI检测报告、电测报告、实验室切片记录等。日常文档包含工程制作指示、钻孔层压参数日志、药水分析报表等。数据更新频率随生产批次、班组班次变动，部分设备数据为连续采集，单批次生产全流程会产生多类关联文档，每份文档包含专属工艺参数、检测结果与批次标识字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类多源异构的数据特征，对向量索引与模型环节带来多重约束。多类文档格式差异显著，需适配不同结构的分块规则，避免拆分破坏工艺参数的关联性。连续采集的设备数据更新频繁，索引需支持增量同步，减少全量重建的资源消耗。单批次生产关联多份文档，索引需支持按批次标识快速精准召回。Gerber与CAM类文件含精密工艺参数，分块时需保留参数关联逻辑，防止拆分导致工艺信息断裂。部分文档含数值型检测结果与定性描述，需统一嵌入格式以保证检索一致性。

## 配置怎么定
FastGPT v4.17.0 版本下的配置参考如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配PCB文档长段工艺参数与检测记录的结构，保留参数关联性 |
| 重叠长度 | 100–150 字符 | 弥补长文档分块后的上下文衔接缺口 |
| `defaultToken` | 8192 | 匹配多数PCB文档的token长度需求，平衡嵌入精度与计算效率 |
| 相似度阈值 | 0.72–0.80 | 满足PCB工艺参数匹配的精度要求，过滤低相关检索结果 |
| 单次搜索上限 | 前 8 条 | 覆盖单批次生产的核心工艺与检测文档 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 知识库上传后状态长时间停留在索引中。原因是未配置增量索引规则，且单批次上传的多源文档数量过多，导致全量索引计算耗时过长。
- 向量化过程中出现embedding速率超限报错。原因是未调整并行线程参数，默认线程数过高导致调用频率超出限制，可通过调整线程数降低速率。
- 分块长度设置为3000字符时出现块丢失。原因是单段文本超过`defaultToken`的上限，导致系统自动截断部分内容未被正确嵌入。

## 怎么确认配好了
- 上传单份典型PCB工艺文档，查看分块预览结果，确认分块长度符合预设区间且未出现内容丢失。
- 发起检索请求，核对返回结果的相似度分值是否落在预设阈值区间内，过滤无关结果。
- 模拟连续上传多份同批次文档，查看索引更新状态，确认增量同步功能正常生效。
- 查看向量化日志，确认embedding调用频率符合预设限制，未出现速率超限报错。
