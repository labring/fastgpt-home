# PCB制造的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自客户提供的Gerber文件、钻带、BOM，以及工厂内部CAM系统、生产设备参数、槽液化验结果、AOI检测报告、电测报告、切片分析报告等。数据更新覆盖每生产批、每班及连续采集场景，文档包含工程制作指示、钻孔层压参数、药水分析记录等多类结构化与半结构化文件，字段涵盖孔径、铜厚、检测点位、异常类型等生产与质检相关内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散且格式多样，涵盖结构化参数、半结构化检测报告与原始文件，要求模型接入配置适配多类型输入；数据更新具有批次性与实时性，需模型调用响应匹配生产节拍，避免延迟影响流程推进；文档包含大量PCB专属专业术语与细分字段，需足够的上下文长度以承载专业内容与历史审核记录；异常问题关联多环节生产参数，需配置支持多源数据关联的模型调用逻辑，确保审核准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 承载PCB专业文档、历史审核记录与多源检测数据，避免截断关键专业内容 |
| `maxTokens` | 2000–3000 token | 适配单批次PCB检验报告的审核输出长度，满足异常标注与原因分析的内容需求 |
| `quoteMaxToken` | 1500 token | 限制引用源文档的长度，聚焦当前批次的生产与检测数据，避免无关内容干扰 |
| `temperature` | 0.1–0.3 | 保持审核逻辑的严谨性，减少专业术语的随机偏差，符合质检场景的确定性要求 |
| `toolChoice` | auto | 自动触发工具调用以关联钻孔参数、槽液化验结果等多源数据，提升异常原因定位准确性 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 按FastGPT v4.17.0版本的模型接入规范填写，适配工厂内网的安全传输要求 |
| `AIPROXY_API_TOKEN` | 按模型服务的访问密钥填写 | 确保模型调用的身份验证有效，避免因权限不足导致调用失败 |

## 容易做错的三处
- 现象：在第三方模型代理平台配置后，FastGPT页面调用时返回404或模型未找到错误。原因：未正确填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或代理平台的模型名称与FastGPT配置的模型标识不匹配。
- 现象：工作流中前一个AI模型的输出结果无法被更新为空值，变量仍保留历史内容。原因：未正确配置变量更新的触发条件，或未清空变量的默认缓存值，导致旧数据未被覆盖。
- 现象：本地部署的ollama模型在思考设置中无法生效，调用时返回模型加载失败。原因：未将`AIPROXY_API_ENDPOINT`指向ollama的本地服务地址，或未配置正确的模型访问权限。

## 怎么确认配好了
- 测试调用单份PCB钻孔参数文档，检查模型输出是否包含正确的孔径、层别等专业字段，确认上下文与输出长度配置未截断关键内容。
- 提交包含异常标记的AOI报告，观察模型是否自动关联对应生产环节的参数，确认工具调用配置生效。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置与部署的模型服务一致，无网络或权限报错。
- 测试更新工作流变量为空值，确认变量内容被清空，验证变量配置逻辑正常。
