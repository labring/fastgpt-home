# PCB制造的检验与过程记录审核：知识库检索与召回

## 这个品类的数据长什么样
印制电路板工厂的工程、生产、品质与实验室产生的数据，来源包括客户提供的Gerber文件、钻带、BOM，以及工厂内部CAM产出文件、设备运行参数、槽液化验结果、AOI检测报告、电测报告与切片分析记录。日常文档涵盖工程制作指示、钻孔和层压参数台账、药水分析报表、各类检测报告等。数据更新频率为每生产批、每班或连续采集，覆盖从客户资料转换到成品检测的全流程，字段与单位随文档类型变化，无统一固定标准。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且格式多样，既有结构化的工艺参数文档，也有非结构化的检测报告，要求检索系统兼容多格式数据解析。数据更新频率高且与生产批次强绑定，需精准匹配批次标识，避免跨批次数据混淆。单批次数据量随生产规模波动，需控制检索返回结果的量级，防止上下文过载干扰审核判断。核心环节聚焦工程资料转换与电气连通，检索需优先关联Gerber解析、钻孔参数等关键工艺文档，以支撑检验与审核的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 匹配PCB工艺参数与检测报告的精度要求，避免低匹配度的无关数据干扰审核 |
| `limit` | 前10条 | 控制单批次检索返回的文档数量，防止上下文溢出影响审核逻辑 |
| `searchMode` | `fullTextRecall` | 适配多格式文档的混合检索需求，覆盖结构化参数与非结构化报告内容 |
| `usingReRank` | 开启 | 对初始检索结果进行二次排序，优先返回与工艺参数、电气连通相关的高价值文档 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户问题自动扩展关联批次标识、Gerber编号等关键词，解决指代消除问题 |
| `collectionIds` | 按生产批次绑定的知识库集合 | 精准限定检索范围，避免跨批次数据混淆，提升审核针对性 |

## 容易做错的三处
- 上传HTML格式的接口文档后检索无返回结果。原因：未启用FastGPT内置的HTML文档解析插件，或上传时未选择适配的解析模式。
- 检索结果未关联生产批次信息，导致跨批次工艺数据混淆。原因：未通过`collectionIds`绑定当前生产批次的专属知识库集合，未开启`datasetSearchUsingExtensionQuery`自动扩展批次关键词。
- 触发知识库检索后GPU资源未被占用。原因：未在FastGPT v4.17.0版本中配置向量库的GPU加速参数，或向量库后台服务未正常启动。

## 怎么确认配好了
- 上传一份测试用的PCB钻孔参数HTML文档，执行检索后查看是否返回对应解析结果。
- 输入包含生产批次标识的查询语句，确认检索结果是否自动关联对应批次的文档集合。
- 查看向量库监控面板，确认检索请求触发后GPU资源使用率出现对应波动。
- 测试包含指代性的查询（如“上次的AOI报告”），确认检索结果返回了正确的批次对应文档。
