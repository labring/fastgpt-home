# SMT贴片与电子组装的检验与过程记录审核：多轮对话与提示词

## 这个品类的数据长什么样
SMT贴片与电子组装的检验与过程记录数据，来源包括客户提供的BOM、Gerber坐标文件、MES系统、锡膏与元件批次记录、贴片机、SPI/AOI设备及回流焊炉温数据。数据更新频率为每工单、每次换线及实时，核心文档包含换线表、钢网记录、首件确认单、SPI/AOI报告、维修记录与追溯标签。字段涵盖料号、位号、元件批次、炉温参数、坐标位置等，单位涉及摄氏度、毫米、批次编号等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且更新实时，要求多轮对话需实时拉取最新的炉温、元件批次等数据，避免使用过期信息。多份文档的字段差异，要求提示词需明确指定对应文档的校验规则，例如BOM的料号匹配与SPI报告的缺陷判定。工单级别的数据关联，要求对话需绑定唯一工单标识，确保同工单的检验上下文不混淆。高频更新的特性也要求对话上下文不能无限制累积，需合理截断冗余内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token 按实测标定 | 单工单涉及BOM、SPI/AOI报告等多份文档，需覆盖核心校验内容 |
| `variables` | 绑定当前工单的料号、元件批次号 | 匹配SMT检验的核心校验字段，实现对话上下文与工单数据联动 |
| `chatId` | 绑定工单唯一编号 | 确保同工单的对话历史不被混淆，支持跨会话追溯检验记录 |
| `messages` 截断规则 | 保留前15轮有效交互内容 | 避免上下文过载导致校验逻辑混乱 |
| 对话历史保留时长 | 72 小时 | 覆盖单次换线到全工单完成的完整周期 |
| 提示词模板嵌入字段 | 嵌入炉温阈值、换线表版本号 | 直接调用工单专属配置数据，减少手动输入错误 |

## 容易做错的三处
- 后台日志随免登录对话删除：后台操作日志显示对话内容为空，无法追溯检验记录，原因是未配置对话日志与`variables`绑定，免登录会话未关联唯一工单标识。
- 调用MySQL工具返回400状态码（no body）：运行数据库查询节点后无响应内容，原因是未正确配置`variables`参数，未传入工单专属的数据库查询条件。
- 工作流无法加载历史全局变量：工作流节点读取的历史全局变量字段为空，原因是未通过`chatId`关联历史会话，未正确绑定全局变量的作用域。

## 怎么确认配好了
- 发起检验对话，输入工单编号，确认对话自动加载对应BOM、换线表的核心字段。
- 删除免登录会话的对话内容，检查后台日志是否保留该会话的检验记录。
- 运行数据库查询节点，确认返回的元件批次、炉温数据与当前工单匹配。
- 切换工单编号发起新对话，确认上下文不会与前一个工单的内容混淆。
