# SMT贴片与电子组装的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
SMT贴片与电子组装的业务数据来源于客户BOM、Gerber文件、坐标文件、MES系统、贴片机、SPI/AOI检测设备及回流焊炉温记录。日常文档包含BOM表、换线表、钢网与炉温记录、首件确认单、SPI/AOI报告、维修记录与追溯标签。数据更新频率为每工单、每次换线及实时同步。文档字段包含料号、位号、元件批次、炉温参数、坐标值等，对应单位为件、摄氏度、毫米、批次号与工单编号。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类数据更新频繁且字段精准，要求溯源环节需实时匹配最新工单与设备数据，避免使用过期文档。多类型文档并存，需支持多格式索引与精准字段召回，确保能定位到料号、位号等关键信息。出错后果直接影响整机质量，溯源环节必须保证引用来源与实际生产数据完全一致，不可出现错配或遗漏。同时，单份文档内容较长，需合理控制引用片段长度，避免无关信息干扰结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配SMT单份文档的核心内容长度，避免截断料号、批次等关键溯源字段 |
| `responseData` | 开启 | 强制返回引用来源的原始数据，满足检验记录的溯源要求 |
| `detail` | 完整字段展示 | 展示文档中的全部关键字段，便于核对料号、元件批次等信息 |
| 单次召回上限 | 前5条 | 匹配SMT工单的单批次数据量，避免冗余召回干扰核心结果 |
| 文档分块长度 | 800 字符 | 适配BOM表、SPI报告的内容结构，保证分块后仍保留完整的字段关联 |
| 变量引用格式 | 系统预设标准格式 | 适配FastGPT的变量调用规则，确保能正确绑定数据源 |

## 容易做错的三处
- 返回引用内容但未开启引用开关：页面显示已返回引用片段，但全局引用开关处于关闭状态，原因是FastGPT v4.17.0版本升级后默认配置变更，未检查全局设置项。
- 知识库引用文件与实际业务文档不符：查询返回的溯源文件并非当前工单对应的最新文档，原因是未按工单维度更新索引，未绑定实时同步的MES与设备数据源。
- 变量引用格式无效：输入`[{datasetId: xxx}]`格式无法调用目标知识库，原因是使用了非标准的变量语法，未遵循系统预设的变量调用规则。

## 怎么确认配好了
- 上传一份测试用的SPI报告，发起包含报告中缺陷描述的查询，检查返回结果是否包含该报告的文件名与对应字段。
- 进入配置页面查看`quoteMaxToken`参数，确认取值处于800–1200 token区间内。
- 输入预设的变量引用格式，发起测试查询，确认能正确调用绑定的数据源内容。
- 模拟换线场景更新对应文档，发起包含换线要求的查询，确认召回的是最新版本的换线表。
