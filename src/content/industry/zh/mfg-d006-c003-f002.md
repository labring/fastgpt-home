# 乳制品加工的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据覆盖液态奶、酸奶、奶粉及乳配料生产全流程，日常文档包含原奶验收记录、标准化配料单、巴氏/UHT处理记录、CIP清洗记录、灌装记录、留样与微检报告。数据来源涵盖奶源检测系统、MES生产管理系统、均质与热处理设备、在线温度流量监测装置、CIP清洗系统及LIMS实验室管理系统，更新节奏按单奶罐、生产批次实时同步，单份文档包含检测数值、工艺参数、操作时间等结构化字段与原始记录文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据的实时批次更新、多源异构属性及密集结构化字段，对向量模型与索引环节带来多重约束。多源数据需统一嵌入格式以保证向量一致性，批次级更新要求支持增量索引以避免全量重处理耗时过长。单份文档包含大量连续工艺参数与短文本检测记录，分块时需避免拆分关键参数组，同时需适配不同来源数据的长度差异。高风险审核场景要求召回精度优先，需限制无效分块的混入，防止错误审核引发生产风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配单份文档中连续工艺参数组的长度，避免拆分关键批次参数 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工艺上下文，防止关键参数被分块截断 |
| `defaultToken` | 按实测标定 | 适配不同来源文本的token占比，平衡结构化字段与自由文本的嵌入效果 |
| `maxToken` | 4096 token | 匹配主流嵌入模型的最大输入限制，避免长文档分块溢出 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关记录，适配乳制品加工中高风险参数的审核精度要求 |
| 单次搜索上限 | 前8条 | 兼顾召回覆盖度与响应速度，满足批量审核的并行处理需求 |

## 容易做错的三处
- 现象：上传Excel格式的配料单或原奶验收记录后，向量化完成后索引结果字段缺失或数值匹配错误。原因：未针对结构化Excel文件开启列级解析配置，导致混合文本与数值的字段被错误合并为单一分块。
- 现象：单批次生产记录上传后，界面显示分块数与实际文本段数不符，出现重复索引条目。原因：未调整重叠长度参数，导致相邻工艺段落的重叠部分被识别为独立分块，或增量索引时未清理旧版本缓存。
- 现象：从旧版本升级至FastGPT v4.17.0后，原有可查询的CIP记录无法被召回。原因：新版本嵌入模型的token计算规则更新，原有分块长度设置超出新模型的输入限制，导致对应分块未被正确索引。

## 怎么确认配好了
- 上传单份典型文档（如单罐原奶验收记录），检查分块预览界面的段落拆分是否保留了连续的工艺参数组。
- 提交模拟审核查询（如“验证该批次巴氏杀菌的时间温度是否符合要求”），核对召回结果的分块是否包含完整的工艺参数。
- 执行批量上传测试，检查索引完成后的分块总数与预期一致，无重复条目。
- 调整配置后，查询原有历史文档，确认召回结果未出现异常缺失。
