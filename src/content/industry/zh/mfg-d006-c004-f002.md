# 仓储、批次与厂内物流的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
典型主体涵盖原材料库、线边库、成品库及物流物控部门，日常文档包含收货单、上架单、领退料单、移库单、盘点表、批次台账等，涉及物料身份、批次号、库位、效期、检验状态等字段。数据来源包括ERP/WMS系统、条码或RFID设备、采购与工单信息、库位记录、AGV或输送系统、称重数据，更新节奏涵盖实时、每日同步及月度盘点周期。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的多源异构数据结构与更新节奏，对向量模型与索引配置提出明确约束。实时同步的AGV、条码数据需要支持增量索引以避免全量重建的资源消耗；批次号、效期、库位等高频关联字段，需要针对性设置索引权重以提升核心信息的召回精度；结构化文档与非结构化记录混合的场景，需要适配不同的分块规则以保留上下文关联；月度归档的盘点数据需要冷数据索引策略，避免热索引过载影响实时查询性能。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配收货单、盘点表等文档的字段密度，避免单块包含过多批次号与效期信息 |
| 重叠长度 | 100–150 字符 | 保留批次台账跨块的关联信息，防止上下文断裂 |
| 相似度阈值 | 0.72–0.85 | 匹配物料身份、批次等强关联字段的检索精度需求 |
| 单次搜索上限 | 前 8 条 | 覆盖工单齐套配送所需的多物料关联记录 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 1000 token | 作为单条非结构化文档的默认分块token上限 |

## 容易做错的三处
- 现象：检索到相关批次台账，但大语言模型未引用其中内容作答，提示未找到匹配信息。原因：未针对批次号、效期等核心字段设置索引权重，导致向量召回的优先级不足。
- 现象：知识库查询耗时过长，超出预设响应阈值。原因：未限制`maxToken`的实际调用量，导致每次检索都加载全量归档的月度盘点数据。
- 现象：新增AGV实时物流数据后，索引更新无响应。原因：未开启增量索引配置，仅执行全量索引导致资源占用过高。

## 怎么确认配好了
- 上传单份批次台账文档，检索包含特定批次号的查询词，核对返回结果的命中条数与预期一致。
- 查看FastGPT v4.17.0的索引监控面板，确认实时更新的条码数据可在5分钟内完成索引同步。
- 调整相似度阈值后，对比检索结果的命中精度变化，确认阈值设置符合业务需求。
- 测试批量领退料单的检索请求，确认`maxToken`的实际调用量未超出预设区间。
