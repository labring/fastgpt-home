# 仓储、批次与厂内物流的检验与过程记录审核：工具调用与插件

## 这个品类的数据长什么样
该品类的核心数据来自ERP、WMS系统、条码/RFID设备、采购工单、库位管理记录、AGV输送系统及称重设备。日常文档包含收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录。数据更新节奏分为实时（AGV位置、称重数据）、每日（库位变动、工单领用记录）、月度盘点（全库物料状态）。核心字段包括物料编码、批次号、库位号、效期天数、检验状态、称重数值，对应单位为件、千克、天等。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据来源要求工具调用需支持对接不同系统的接口，需处理格式各异的单据数据；不同更新节奏要求工具调用的触发时机与数据拉取频率匹配，例如实时数据需高频拉取，月度盘点数据可按需触发。多样的单据结构要求插件需支持自定义字段提取规则，精准匹配不同单据的必填项。核心字段的重要性要求工具调用需增加字段校验逻辑，避免错漏关键信息导致后续业务风险。

## 配置怎么定
本页面基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | 按场景自动选择 | 适配收货、盘点、移库等不同单据的工具调用需求 |
| `functionCall` | 开启强制字段匹配 | 确保提取的物料编码、批次号等核心字段符合业务要求 |
| 工具调用超时 | 300–600 秒 | 覆盖多源数据拉取、账实比对的正常业务耗时 |
| 插件上下文上限 | 前 10 条历史单据 | 避免过多历史数据干扰当前单据的字段提取 |
| 字段提取规则 | 按实测标定 | 适配不同单据的自定义字段组合与格式 |
| 错误重试次数 | 2–3 次 | 应对网络波动或临时接口调用失败 |

## 容易做错的三处
- 现象：应用转为团队插件后无法调用工具，返回结果为空或报错。原因：未在插件配置中开启`toolChoice`参数，导致工具调用权限未正确绑定。
- 现象：调用接口创建的CSV集合与界面生成数据不一致，字段顺序或数值格式出错。原因：未指定CSV文件的字段分隔符与编码格式，导致解析逻辑与界面默认配置不匹配。
- 现象：插件预览获取内容后，最终输出无结果。原因：未在插件配置中开启`functionCall`参数，导致提取的内容未被正确整合到输出逻辑中。

## 怎么确认配好了
- 触发对应单据的工具调用，检查返回结果是否包含物料编码、批次号、库位号等核心业务字段。
- 模拟多源数据拉取场景，验证工具调用超时设置是否能覆盖正常业务耗时。
- 触发插件异常调用，检查是否按照配置的重试次数执行重试操作。
- 对比接口创建的CSV集合与界面生成数据，确认字段解析逻辑与配置要求一致。
