# 仓储、批次与厂内物流的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类涉及原材料库、线边库、成品库及物流物控部门，日常处理的文档包括收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录。数据来源覆盖ERP/WMS系统、条码或RFID设备、采购与工单信息、库位数据、AGV或输送系统、称重数据，更新节奏包含实时同步、每日汇总及月度盘点更新，核心字段包含物料编码、批次号、库位、效期、检验状态及账实差异记录。

## 这些特征在「模型接入与配置」这一环带来什么约束
基于FastGPT v4.17.0版本的配置逻辑，多源异构的数据来源要求模型接入环节支持跨系统数据拉取与格式适配，避免因数据格式不统一导致检验审核出错。不同更新频率的数据需要匹配对应的同步周期配置，实时数据如AGV输送状态需高频调用，月度盘点数据则可按固定周期同步。核心文档的字段复杂度要求模型需精准识别批次号、效期等关键信息，配置时需预留足够的上下文长度以覆盖多份关联文档的关联校验。同时，该场景的出错后果直接关联生产停线或库存损失，要求模型输出具备较高严谨性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写对应厂商的API接入地址，如`https://api.example.com/v1` | 适配仓储场景多源数据调用需求，保障模型能正常拉取ERP、WMS等系统数据 |
| `AIPROXY_API_TOKEN` | 填写申请的专属密钥 | 保障模型调用的权限安全，避免未授权访问核心仓储数据 |
| `maxContext` | 8000–12000 token | 覆盖批次台账、收货单、移库单等多份关联文档的上下文关联，支持跨单据的批次流向校验 |
| `maxTokens` | 2000–3000 token | 满足检验结果、账实差异说明、批次合规性判断的输出长度需求 |
| `temperature` | 0.1–0.3 | 保持检验审核的严谨性，减少随机偏差，避免模型生成不符合仓储规范的判断结果 |
| 工作流/API 工具选择配置 | auto | 自动调用工具处理条码、AGV数据的解析需求，提升复杂数据的处理效率 |

## 容易做错的三处
- 现象：调用模型时返回`Api response error: /api/core/ai/model/test?model=xxx`，原因：未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，导致模型调用链路中断。
- 现象：聊天对话框切换AI模型后无响应，原因：未在配置中开启多模型切换权限，或未为切换的模型配置正确的接入参数。
- 现象：模型输出包含未预期的`<think>`标签内容，原因：未正确关闭模型的思考输出开关，或配置的`temperature`参数过高导致模型生成额外内容。

## 怎么确认配好了
- 测试调用指定API端点，查看是否返回正常的模型响应，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`配置正确。
- 上传一份仓储收货单样本，查看模型输出的字段提取结果是否包含批次号、库位、效期等核心信息，确认`maxContext`和`maxTokens`配置适配文档长度。
- 切换不同的AI模型，验证是否能正常加载并完成检验审核任务，确认多模型配置生效。
- 模拟账实差异场景，查看模型输出是否符合仓储检验的严谨逻辑，确认`temperature`参数配置合理。
