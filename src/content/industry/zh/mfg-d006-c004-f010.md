# 仓储、批次与厂内物流的检验与过程记录审核：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来源于ERP/WMS系统、条码或RFID设备、采购与工单单据、库位管理记录、AGV或输送系统数据、称重计量数据。日常文档包括收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录，核心字段包含物料编码、批次号、库位号、检验状态、效期、数量及对应单位。数据更新节奏分为实时（如条码扫描、AGV调度）、每日（如库存盘点汇总）、月度（如全库盘点台账）三类。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据来源分散且更新节奏差异大，要求检索系统需支持多数据源的增量同步与增量召回，避免全量检索带来的性能损耗。文档与批次强绑定，核心匹配字段为批次号、库位号等唯一标识，要求检索需精准匹配关联字段，防止错配不同批次的物料数据。日常文档数量随批次规模增长，需控制单次检索的结果数量，避免超出上下文处理上限。同时，业务场景涉及跨工序的物料流向追溯，要求检索结果需关联工单、库位等多维度信息，仅返回单张单据内容无法满足需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 该品类需严格匹配批次号、库位号等核心字段，阈值过低会引入无关物料数据，过高会遗漏匹配的效期或检验状态信息，按实测标定 |
| `limit` | 前8–12条 | 该品类单批次关联文档较多，过多结果会超出上下文处理上限，过少会遗漏齐套配送所需的多个单据信息 |
| `searchMode` | `fullTextRecall` | 查询示例侧重标识符或专业术语；请用代表性数据实测该模式，不将其视为产品默认值。 |
| `usingReRank` | 开启 | 该品类文档字段关联性强，重排可过滤掉仅匹配关键词但批次不匹配的结果，提升最终回复的精准度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 该品类存在大量专业业务术语，如AGV调度、呆滞物料、效期预警等，扩展查询可补充同义词或关联术语，提升召回覆盖范围 |
| `collectionIds` | 绑定对应仓储、批次管理的数据集ID | 缩小检索范围，避免检索到无关的生产工单或通用质检文档，确保结果仅覆盖当前品类的业务数据 |

## 容易做错的三处
- 现象：知识库导入静态页面后，页面内容更新后无法自动同步。原因：未配置自动更新触发规则，仅使用手动导入方式，未对接数据源的增量更新接口。
- 现象：首次提问回答正确，同窗口二次提问答非所问。原因：未设置上下文自动清理或上下文长度限制，导致历史会话上下文干扰新问题的检索召回，模型混淆了前后问题的关联逻辑。
- 现象：检索结果无法精准匹配目标批次的效期信息。原因：未开启`usingReRank`或`datasetSearchUsingExtensionQuery`，导致召回结果未经过重排优化，且未补充业务术语的扩展查询，召回结果相关性不足。

## 怎么确认配好了
- 查看FastGPT v4.17.0的数据集更新日志，确认静态页面或ERP数据源的更新任务按预设频率（实时/每日/月度）自动触发。
- 发起测试提问，输入特定批次号，核对检索结果是否包含该批次对应的收货单、盘点表等关联文档，且结果条数符合预设的`limit`范围。
- 切换`searchMode`为模糊匹配与精准匹配模式，对比检索结果的匹配精度，确认当前设置符合业务需求。
- 发起连续多轮提问，确认会话上下文不会干扰后续问题的检索召回，二次提问的结果与当前问题强相关。
