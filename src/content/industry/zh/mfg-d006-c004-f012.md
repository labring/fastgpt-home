# 仓储、批次与厂内物流的检验与过程记录审核：部署与升级

本页面适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的数据通常来自ERP/WMS系统、条码或RFID识别设备、采购与工单数据、库位管理数据、AGV或输送系统、称重设备。日常文档包括收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录，字段包含物料编码、批次号、库位号、检验状态、效期、数量等。数据更新节奏分为实时（如AGV位置、实时称重数据）、每日（如库位变动、领退料记录）、月度（如月度盘点数据），且需与生产工单、采购订单等多维度关联，形成完整的物料流向链路。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据来源分散且更新节奏差异较大，部署时需要对接多类型数据源的适配，包括ERP/WMS的结构化数据、条码RFID的实时流数据等。文档字段多且关联关系复杂，部署时需要准确匹配字段以确保检验与审核的准确性，避免字段错位导致的审核错误。实时数据的同步频率需要根据业务场景调整，比如AGV的位置数据需要实时同步，而月度盘点数据可以按日同步，避免数据延迟导致的审核滞后。同时，该品类的出错后果直接影响生产流程，部署时需要配置数据校验环节，防止错料、过期物料使用、停线缺料等问题。此外，跨工序的批次流向管理，需要部署链路配置以确保追溯链完整，避免追溯中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–20 | 适配仓储、批次数据的并发读写需求，避免数据库连接耗尽 |
| `MONGODB_URI` | 按ERP/WMS导出的数据源地址 | 存储批次台账、盘点表等文档的持久化存储 |
| `REDIS_URL` | 本地Redis服务地址或云Redis实例地址 | 缓存实时库位、AGV状态数据，降低数据库查询压力 |
| `FE_DOMAIN` | 部署节点的公网域名或内网IP | 供前端页面访问接口，实现检验记录的可视化审核 |
| `FILE_TOKEN_KEY` | 按实测生成的随机字符串 | 加密上传的收货单、盘点表等文件的访问权限 |

## 容易做错的三处
- 服务出现无限重启日志：`DB_MAX_LINK`配置值低于实际并发连接需求，数据库连接池耗尽，服务反复重启。
- 知识库数据无法同步：`MONGODB_URI`配置错误，无法连接到部署的数据库实例，导致文档无法同步到知识库。
- 界面提示quota相关报错：未配置`REDIS_URL`，缓存机制未启用，请求限流触发报错。

## 怎么确认配好了
- 检查数据库连接日志，确认`DB_MAX_LINK`的连接数符合配置的范围，无连接失败的情况。
- 上传一份收货单文档，确认`FILE_TOKEN_KEY`验证通过，文件可正常访问。
- 访问`FE_DOMAIN`对应的前端地址，确认界面可正常加载检验记录审核页面。
- 触发一次实时数据同步，确认批次台账的数据同步成功。
