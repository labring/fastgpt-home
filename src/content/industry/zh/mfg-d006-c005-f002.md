# 光伏电池片制造的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
数据来源包括硅片来料记录、MES生产系统、扩散炉/镀膜设备/印刷机的运行日志、EL与IV测试数据、实验室质检报告；更新节奏为每生产批次、每片检测即时更新，每日汇总全车间数据；文档包含工艺卡、扩散与镀膜参数表、印刷烧结记录、EL检测图像、IV分档数据、良率汇总文档；字段涵盖工艺温度、设备运行时长、缺陷位置坐标、电性能参数数值等，无统一固定单位，随检测项变化。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的高频更新、多源异构数据特征，对向量模型与索引环节带来多重约束。每片级的即时检测数据会快速推高索引规模，需要支持增量索引与批量更新的适配逻辑；文本、数值与EL检测图像混合的多源数据，要求向量化流程兼容不同格式的特征提取；工艺参数与缺陷数据的强上下文关联，需要避免过度拆分文档导致关联信息丢失；细粒度的单条数据长度差异大，需要灵活调整分块规则适配不同数据类型。

## 配置怎么定
`defaultToken` 和 `maxToken` 是配置向量化长度与上下文限制的核心参数，以下配置适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配工艺卡、参数表等文本数据的常规长度，避免单块超出向量化模型的输入限制 |
| 重叠长度 | 50–100 字符 | 保留相邻块的工艺参数与工序上下文，避免拆分后丢失关联信息 |
| 相似度阈值 | 按实测标定 | 适配光伏电池片检测数据的语义关联特征，灵活匹配不同类型的审核需求 |
| 单次搜索上限 | 前 20 条 | 控制单轮检索的返回数据量，适配车间端的低延迟调用要求 |
| `maxToken` | 8192 | 适配多段拼接后的总长度限制，避免上下文溢出导致向量化失败 |
| `defaultToken` | 按数据最长文本段设置 | 统一向量化的基础长度，适配不同文档的格式差异 |

## 容易做错的三处
- 数据集导入后长期处于索引中状态。原因：未针对高频更新的光伏电池片检测数据配置增量索引，全量重建索引时数据量过大导致进程阻塞。
- 切换向量模型后语义相似度数值异常偏高。原因：未调整相似度计算的标准化规则，直接使用原始模型输出的非标准化数值作为匹配依据。
- 索引速度无法匹配生产实时需求。原因：未启用多副本部署的索引调度逻辑，单进程处理能力不足以支撑每片级的即时数据更新。

## 怎么确认配好了
- 查看索引任务的运行日志，确认无文档拆分失败的报错，且分块长度与导入数据的实际长度匹配。
- 执行检索测试，对比不同类型数据的返回结果，确认相似度阈值的配置符合当前审核的匹配要求。
- 导入单批次测试数据，确认索引完成耗时符合生产调度的时间限制，无长期处于索引中的情况。
- 查看集群节点的资源占用情况，确认多副本部署的索引任务可正常分配资源，无进程阻塞。
