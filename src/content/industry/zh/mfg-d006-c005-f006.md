# 光伏电池片制造的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
该品类数据主要来自硅片来料、MES系统、扩散炉/镀膜设备/印刷机的运行日志、EL与IV测试设备、实验室检测数据。日常生成工艺卡、扩散和镀膜参数表、印刷烧结记录、EL检测图像、IV分档数据、良率报告等文档。数据更新节奏按生产批次、单片检测结果、每日汇总更新。数据字段包含工艺参数值、设备运行时长、检测图像编号、电性能数值、批次标识等，部分字段带有物理单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
光伏电池片制造的数据具有多源、高频、多模态的特征，工艺参数与检测结果强关联，需要精准匹配批次与工序。多源数据的溯源要求引用来源需明确关联设备、测试环节与生产批次，避免跨批次混淆。高频更新的单片检测数据需支持细粒度检索，长文档如EL检测图的文本描述需准确对应原始文件。不同工序的参数差异要求检索范围限定在对应生产环节，同时需兼容数值型与图像类数据的溯源逻辑，确保引用来源与实际生产环节一一对应。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配工艺卡、IV分档数据等长文档的段落结构，避免关键参数被截断 |
| 重叠长度 | 100–200 字符 | 保留跨分块的工序关联信息，防止工艺参数与批次标识被分割丢失 |
| `quoteMaxToken` | 1500–2000 token | 容纳EL检测图的描述文本与批次溯源信息，确保引用内容完整 |
| 单次搜索上限 | 前 8 条 | 匹配多工序的多源数据，覆盖不同设备与测试环节的生产记录 |
| 重排 | 开启 | 优先关联批次号与工序字段，提升溯源结果的精准度 |
| 最大上下文 | 4000–6000 字符 | 整合多份关联文档，完整呈现生产过程的溯源链条 |

## 容易做错的三处
- 配置后调用接口未返回引用文献细节。原因是未开启`responseData`参数的关联配置，或未正确绑定知识库变量到检索环节。
- 嵌入页面无法展示引用内容。原因是未关闭默认的引用弹窗开关，或未在iframe参数中配置允许引用内容渲染。
- 长文档分割后检索丢失工艺关联。原因是使用标题级分隔符拆分跨工序的参数表，导致分块丢失工序与批次的关联信息。

## 怎么确认配好了
- 上传一份完整的工艺卡文档，发起检索，查看返回结果中是否包含对应工序的参数记录与批次标识。
- 调用接口获取返回内容，检查是否包含`detail`字段的引用来源信息，确认与上传文档的元数据一致。
- 动态传入批次号作为检索变量，验证返回结果是否仅关联对应批次的生产数据，无跨批次的无关记录。
- 嵌入iframe并加载问答页面，确认页面中可展开查看引用的原始文档片段与来源信息。
