# 光伏组件封装的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据来自电池片分档系统、玻璃胶膜背板批次台账、工厂MES系统、串焊与层压生产设备、EL及IV测试仪。日常产出的文档包含组件排版图、材料批次记录、层压工艺参数记录、EL缺陷图、IV功率测试报告、绝缘耐压检测记录、成品包装清单。数据更新节奏为每一块组件对应一套过程记录，每批次原材料同步更新批次台账，字段包含设备运行参数、检测数值、批次编号、操作人员信息等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
单组件、每批次的高频更新特性，要求引用溯源系统需支持精准匹配单组件的全链路过程记录，避免跨批次或跨组件的信息混淆。文档类型涵盖排版图、EL缺陷图等图文类文件与IV测试报告等数值类文件，需系统支持多模态数据源的关联引用与精准匹配。数据来源覆盖生产设备与管理系统，需确保引用内容可追溯至原始采集节点，保证信息的原始性。字段包含设备运行参数、检测数值、批次编号等，要求溯源时能精准提取对应字段的原始内容，满足审核的精准性要求。

## 配置怎么定
FastGPT v4.17.0
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 900–1100 token | 适配单组件全链路过程文档的总长度，避免截断关键工艺参数与检测数据 |
| `responseData` | 包含EL图元数据、IV测试报告原文 | 满足审核时需调取原始检测记录的需求 |
| `detail` | 开启 | 展示引用来源的具体字段、采集时间与设备编号，便于追溯过程细节 |
| 单次召回引用条数 | 前4–6条 | 匹配单组件的核心过程文档数量，避免冗余信息干扰审核 |
| 引用相似度阈值 | 0.72–0.88 按实测标定 | 过滤与当前组件无关的批次记录，确保引用内容精准匹配 |
| 上下文窗口长度 | 1500–2000 字符 | 容纳单组件的多份关联文档内容，保证审核逻辑的连贯性 |

## 容易做错的三处
- 检索时未关联对应组件的专属知识库，却返回了其他批次的材料记录且显示引用来源。原因是未配置基于组件批次ID的过滤规则，导致跨批次的无关数据被召回。
- 设置了引用条数上限，界面却返回超出上限的引用内容。原因是未在检索流程中添加引用条数截断逻辑，导致召回的原始数据未被正确过滤。
- 在应用中调用知识库引用变量时，返回参数错误的报错文案。原因是未正确绑定组件批次ID与知识库的检索参数，导致变量传递格式不符合系统要求。

## 怎么确认配好了
- 发起单组件的审核请求，核对返回的引用来源是否仅包含该组件对应的过程文档，调整引用过滤阈值直至匹配预期范围。
- 查看每条引用的详情内容，确认是否展示了原始检测报告、EL图元数据等配置项要求的内容，验证`detail`与`responseData`的配置生效。
- 统计返回的引用条数，确认符合配置的单次召回引用条数要求，验证`quoteMaxToken`相关的截断逻辑正常运行。
- 模拟应用变量传递流程，确认调用知识库引用时无参数报错，验证变量与检索参数的绑定规则正确。
