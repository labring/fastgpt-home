# 光伏组件封装的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
光伏组件封装环节的数据来自电池片分档记录、玻璃胶膜背板批次台账、MES系统、串焊与层压设备、EL/IV测试仪。数据更新频率为每块组件、每批材料生成对应文档，涵盖排版图、材料批次记录、层压工艺记录、EL隐裂图、IV测试报告、绝缘耐压记录、包装清单。文档字段包含电池片电流档位、层压温度与时长、EL隐裂位置、IV功率值、绝缘耐压数值等，对应单位为安培、摄氏度、秒、瓦特、兆欧等。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据按单组件、单批次高频更新，模型接入需支持实时同步多源异构数据；文档包含文本类工艺记录、数值类测试报告与视觉类EL图，需适配多模态数据处理；字段关联紧密（如电池片档位直接影响IV功率），需保证上下文匹配的精准度；不同设备输出的数据格式存在差异，需配置兼容的接入规则，避免数据解析错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 匹配单块组件关联的多份文档总长度，避免上下文溢出 |
| `vision` | 开启 | 支持解析EL隐裂图、IV测试报告图表等视觉类文档 |
| `temperature` | 0.1–0.3 | 保证检验结果的一致性，降低对隐裂、功率档位判断的随机性 |
| `toolChoice` | auto | 自动判断是否调用工具处理设备原始数据，适配多源数据接入需求 |
| `AIPROXY_API_ENDPOINT` | 按实际部署地址填写 | 对接第三方代理服务，适配跨区域数据传输场景 |
| `quoteMaxToken` | 1500 token | 限制单条引用文档的长度，聚焦核心检验相关内容 |

## 容易做错的三处
- 现象：调用模型时返回上下文溢出报错，状态码为413。原因：未根据组件关联文档的总长度调整`maxContext`参数，超出模型支持的最大上下文长度。
- 现象：应用仅能检索知识库内容，无法调用联网工具补充最新工艺参数。原因：未正确配置工具调用权限，或未在应用设置中开启对应工具的接入开关。
- 现象：EL隐裂图无法被正确解析，输出结果未提及视觉相关内容。原因：未开启`vision`参数，或未配置视觉模型的接入密钥。

## 怎么确认配好了
- 上传单块光伏组件的EL图与IV测试报告，验证模型能否正确识别隐裂位置并匹配对应电流档位与功率值。
- 查看FastGPT v4.17.0的应用日志，确认`maxContext`参数生效，未出现上下文溢出的报错。
- 测试调用联网工具，验证能否获取最新的层压工艺参数并融入检验结果。
- 配置`temperature`为0.1，多次输入相同的检验数据，确认输出结果保持一致。
