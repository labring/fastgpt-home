# 冲压与板材成形的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自汽车覆盖件、家电钣金、五金件企业的冲压车间，包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录等文档。数据来源覆盖钢卷标签与质保书、冲床和送料机实时数据、模具管理系统、MES系统、三坐标或检具检测数据，更新节奏为每卷料、每批生产或每次换模时同步更新，文档字段包含材料牌号、模具编号、检测尺寸、换模时间等核心生产信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类高频小批量的数据更新节奏，要求向量模型与索引环节支持快速增量更新，避免全量重索引带来的性能损耗。多类型文档的混合输入，需要向量模型兼顾非结构化文本（如作业指导书）与结构化字段（如检测尺寸、换模时间）的编码一致性。生产环节强关联的字段属性，要求索引需绑定批次、模具编号等元数据，确保检索时可精准关联对应生产场景，减少跨批次或模具的无效匹配。同时，数据来源分散的特性，要求索引支持多数据源的向量统一接入与管理。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配冲压作业指导书、检测报告的文本长度，避免块内关键生产信息断裂 |
| 重叠长度 | 50–100 字符 | 保留跨块的模具编号、换模时间等元数据，防止关键生产标识被分割丢失 |
| 相似度阈值 | 0.75–0.85 | 匹配冲压检验的精准度要求，避免误匹配不同批次或模具的检测数据 |
| 单次搜索上限 | 前10条 | 覆盖单次换模或生产批次的关联记录量，避免冗余检索带来的性能浪费 |
| `defaultToken` | 按实测标定 | 适配bce-embedding-v1等嵌入模型的输入令牌默认限制，避免基础请求超限 |
| `maxToken` | 8192 token | 匹配主流开源嵌入模型的最大输入token数，兼容多类型文档的完整编码需求 |

## 容易做错的三处
-  界面报错提示“该令牌无权使用模型”或显示无可用渠道。原因是未在FastGPT中正确配置嵌入模型的接入方式，未跳过One API直接绑定模型专属密钥，或渠道权限未正确开放。
-  检索结果中出现跨批次的冲压检测数据。原因是未在索引中绑定批次、模具编号等元数据字段，导致向量匹配未关联生产场景属性，出现无效匹配。
-  生成向量时出现令牌超限报错。原因是未正确设置`maxToken`参数，输入文本长度超出模型支持的最大token限制。

## 怎么确认配好了
-  查看FastGPT嵌入模型配置页面，确认已正确填入对应模型的接入信息，无渠道权限报错提示。
-  上传一份冲压换模记录文档，触发向量生成流程，检查生成的向量数据无截断或丢失模具编号、换模时间等关键元数据。
-  发起一次检验记录审核的检索请求，核对返回结果的数量与单次搜索上限的设置一致。
-  测试不同批次的检测数据检索，确认返回结果仅包含对应批次的关联记录。
