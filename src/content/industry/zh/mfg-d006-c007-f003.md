# 冲压与板材成形的检验与过程记录审核：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、MES系统、三坐标或检具检验数据。日常文档包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录，字段涵盖料号、模具编号、检验尺寸、换模时间、材料消耗数值等，更新频率为每卷料、每批工件或每次换模时同步更新。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据更新频繁且批次关联性强，要求对话上下文需按批次隔离，避免跨批次数据混淆。多类数据源与文档结构要求多轮对话需逐步调取不同系统的信息，不可一次性加载全量数据，否则会增加响应延迟。专业字段较多且格式固定，提示词需精准匹配文档字段，否则无法准确提取或审核数据。不同换模批次的参数差异较大，需在对话中动态调整校验逻辑，避免套用固定规则。

## 配置怎么定
本页面基于FastGPT v4.17.0版本的配置逻辑编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定每卷料/每次换模的唯一标识 | 冲压批次数据更新频繁，需隔离不同批次的对话上下文，避免数据混淆 |
| `messages` | 保留最近5轮对话消息 | 冲压检验审核的多轮对话通常不超过5轮，过长消息会降低对话处理效率 |
| 最大上下文长度 | 800–1200 字符 | 冲压单批次相关文档数据量适中，过长上下文会降低对话响应速度 |
| `variables` | 预设冲压料号、模具编号、换模时间等固定字段 | 减少多轮对话中重复录入基础信息的步骤，提升审核效率 |
| 单次对话返回结果上限 | 前3条 | 冲压检验记录单批次条目有限，过多结果会干扰对话逻辑 |
| 超时阈值 | 600 秒 | 冲压数据调取通常需要一定时间，600秒可覆盖多数场景的响应需求 |

## 容易做错的三处
- 现象：调用API时传入`chatId`后，后台日志未关联对应标识。原因：未在对话配置中开启`chatId`参数的绑定逻辑，或传入的`chatId`格式不符合平台要求。
- 现象：对话界面的表单节点无法正常渲染字段，显示异常。原因：未按照冲压文档的字段结构配置表单参数，导致HTML渲染匹配失败。
- 现象：免登录链接用户删除对话内容后，后台日志同步删除。原因：未在系统配置中关闭免登录对话的日志同步删除规则，保留了对话与日志的绑定关系。

## 怎么确认配好了
- 发起一次针对某批次冲压件的检验对话，查看后台日志是否携带正确的`chatId`标识。
- 提交模拟的换模记录数据，验证对话是否能正确提取预设的`variables`字段。
- 调整最大上下文长度参数，测试对话响应时间是否符合业务实际需求。
- 创建免登录测试链接，删除对话后检查后台日志是否保留对应记录。
