# 冲压与板材成形的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来源包括钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、车间MES系统、三坐标测量或检具检测数据。日常文档涵盖冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录。数据更新节奏为每卷料、每批投产或每次换模时更新，字段包含材料牌号、厚度、冲床压力、模具间隙、压边力参数、尺寸偏差值等，无统一固定格式，随各车间实际管理流程调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类数据更新频率高且来源分散，要求模型接入配置需支持高频增量同步与多源数据字段映射；日常文档格式不统一，需配置适配异构文档的解析规则；单次审核任务常关联多份跨系统文档（如换模记录与尺寸检验报告），需限制单轮上下文承载量，避免模型超出处理上限；部分数据为设备直连的结构化数值，需配置结构化数据提取的匹配规则，适配不同设备输出的字段差异。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 单次审核常关联多份跨系统文档，需承载足够的上下文信息 |
| `maxTokens` | `2000–3000 token` | 检验与过程记录审核的输出需涵盖详细分析，预留足够生成空间 |
| `quoteMaxToken` | `1500 token` | 限制引用文档的总长度，避免上下文过载影响模型处理 |
| `temperature` | `0.1–0.3` | 审核任务需严谨结论，降低随机生成概率以保证结果一致性 |
| `toolChoice` | `auto` | 按需调用工具处理结构化设备数据，适配多源数据校验需求 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 适配本地或远程模型的接入路径，确保调用正常 |

## 容易做错的三处
- 当输入包含多份冲压车间跨系统文档内容时，模型返回固定报错格式无有效分析内容。原因：未正确配置`maxContext`参数，导致上下文承载量不足触发异常。
- 混合检索响应时长超出常规审核场景的可接受范围。原因：未合理限制`quoteMaxToken`，导致过多文档被加载至上下文增加处理负担。
- 部署本地模型后，首次调用正常但输入其他内容时触发模型调用报错。原因：未校验`maxContext`的取值范围，超出模型支持的上下文上限。

## 怎么确认配好了
- 提交包含多份冲压车间文档的测试请求，检查上下文是否正常加载无截断。
- 调用模型生成检验审核结论，确认输出符合专业审核的严谨性要求。
- 验证模型服务地址的连通性，确认无调用失败或超时情况。
- 检查结构化设备数据的提取结果，确认字段映射符合车间数据格式。
