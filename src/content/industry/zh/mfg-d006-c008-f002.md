# 化妆品生产的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据覆盖护肤、洗护、彩妆及特殊化妆品生产企业的全流程文档，包括配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验报告、标签审核文件。数据来源涵盖注册备案配方、原料安全资料、生产设备MES/ERP系统、实验室检测记录及包材版本档案，更新频率为每批生产或每次换线时触发，单份文档包含原料参数、生产参数、批号、备案编号等明确字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据的多源性、高频更新与强合规要求，对向量模型与索引环节形成多重约束。多源数据包含结构化参数与非结构化文本，需适配不同长度的分块规则；高频更新要求支持增量索引以避免全量重建耗时；备案数据的严格一致性要求，需提升匹配阈值以过滤非合规内容；不同文档的字段差异，需在分块时保留元数据以支持后续溯源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配配方工艺单、检验记录的常规文本长度，避免关键参数被拆分到不同块中 |
| 重叠长度 | 100–200 字符 | 保留跨块的上下文关联，例如连续的称量步骤与温度变化记录 |
| 相似度阈值 | 0.85–0.92 | 匹配备案配方的严格一致性要求，过滤非合规的原料与参数内容 |
| 单次搜索上限 | 前 6 条 | 覆盖单批生产涉及的关联文档数量，避免冗余结果干扰审核 |
| `defaultToken` | 4096 | 适配单份文档的嵌入处理长度，满足长文本的嵌入需求 |
| `maxToken` | 8192 | 满足召回后上下文拼接的总长度要求，支持完整的审核依据展示 |

## 容易做错的三处
- 现象：召回的文档块未显示对应生产批号或备案编号，字段为空。原因：未在分块阶段嵌入文档元数据，导致后续溯源环节无法关联具体生产批次与合规文件。
- 现象：索引构建任务返回504超时状态码。原因：未启用增量索引模式，每次更新均执行全量索引重建，超出系统处理时限。
- 现象：匹配结果包含未备案的原料参数。原因：相似度阈值设置低于0.85，无法区分备案与非备案的原料内容，导致审核失效。

## 怎么确认配好了
- 上传单份完整的配方工艺单，检查分块后的文本块是否保留原料名称、用量、生产参数等核心信息。
- 发起备案配方匹配查询，验证返回结果的相似度分值处于预设的0.85–0.92区间内。
- 上传换线后的新生产记录，验证系统仅增量更新索引，无全量重建的日志记录。
- 查看FastGPT v4.17.0的系统配置日志，确认`defaultToken`与`maxToken`的配置未触发嵌入长度超限报错。
