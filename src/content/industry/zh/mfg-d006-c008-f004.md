# 化妆品生产的检验与过程记录审核：工作流编排

## 这个品类的数据长什么样
本品类数据来自护肤、洗护、彩妆及特殊化妆品生产企业的注册备案配方、原料安全资料、称量乳化设备、ERP/MES系统、实验室检测记录与包材版本库。日常文档包含配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品成品检验报告与标签审核表。数据按每生产批次、每次换线更新，字段涵盖配方编号、原料限用物质含量、生产参数阈值、检验合格标识与备案关联编号。

## 这些特征在「工作流编排」这一环带来什么约束
本品类数据按生产批次、换线节点更新，要求工作流触发绑定对应生产批次节点，避免跨批次数据混淆。多源数据来源需在工作流中配置多节点拉取不同系统数据，需适配不同格式的检验报告与工艺记录。配方与标签受备案约束，不同于药品以治疗作用为核心的监管要求，工作流需加入备案信息校验环节，确保参数与备案内容一致。生产参数如乳化温度、均质时间需绑定设备采集的实时数据，需配置参数阈值触发校验。出错后果涉及下架召回，工作流需设置复核环节的强制校验，未通过则阻断后续流程。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按生产批次节点触发 | 匹配本品类按批次更新的数据特征，避免跨批次数据混淆 |
| 变量配置 | `variables` 绑定备案配方ID、生产批次号 | 用于关联多源数据的批次与备案信息，确保校验准确性 |
| 节点ID配置 | `nodeId` 绑定设备数据采集节点、实验室检验节点 | 区分不同来源的业务数据，避免节点混淆 |
| 超时阈值 | 600 秒 | 适配ERP/MES、实验室系统的数据拉取延迟，按实测标定 |
| 单次拉取条数 | 前10条 | 适配实验室检验报告的批量拉取需求，按实测标定 |
| 异常拦截配置 | 当参数超出阈值时阻断流程 | 对应生产参数的校验需求，及时拦截异常流程 |

## 容易做错的三处
- 现象：运行代码`localStorage.getItem('userId')`时出现`localStorage is no`报错。原因：FastGPT工作流运行环境无浏览器上下文，无法调用浏览器内置的localStorage对象。
- 现象：工作流中获取图片url后无法在对话界面显示图片。原因：未配置图片渲染节点，或未将图片url绑定至正确的输出字段。
- 现象：调用API-发起会话-请求工作流时返回结果无思考过程字段。原因：未在工作流的大模型节点中配置开启思考过程输出，或未将思考过程绑定至API输出链路。

## 怎么确认配好了
- 触发测试：手动触发对应生产批次的工作流，检查是否仅拉取该批次的相关文档与数据。
- 变量校验：查看`variables`绑定的字段，确认备案配方ID、生产批次号与测试批次一致。
- 节点配置核对：检查`nodeId`绑定的设备、实验室节点，确认数据来源与实际业务一致。
- 异常流程测试：模拟参数超出阈值的场景，检查工作流是否触发校验与阻断。
