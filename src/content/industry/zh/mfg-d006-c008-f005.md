# 化妆品生产的检验与过程记录审核：工具调用与插件

## 这个品类的数据长什么样
该品类数据来源包括注册或备案配方、原料安全资料、称量与乳化设备、ERP/MES系统、实验室检测结果及包材版本文件。数据更新节奏为每生产批次、每次产线换线时更新。日常文档包含配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验报告、标签审核表。核心字段包括原料限用物质含量、乳化温度、生产批号、包材版本号，对应单位为百分比、摄氏度、批次编号、版本字符串。

## 这些特征在「工具调用与插件」这一环带来什么约束
每生产批次、每次换线的高频更新特性，要求工具调用需支持实时拉取最新批次的配方、检验记录与包材版本，避免调用过期缓存数据。多源数据来源要求插件兼容结构化的ERP/MES数据、非结构化的实验室检测报告，需明确配置不同数据源的拉取权限与格式转换规则。配方与标签的备案约束要求工具调用需关联备案数据库完成字段校验，需配置校验触发的前置条件。单次生产批次的数据量需限制插件返回结果的范围，防止上下文过载导致执行异常。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，针对化妆品生产的检验与过程记录审核场景定制。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | `auto` | 支持自动匹配多源数据调用需求，适配配方校验、记录审核等不同工具场景 |
| 工作流/API 函数调用配置 | `开启` | 强制模型通过函数调用执行工具，确保检验逻辑可追溯，符合生产合规要求 |
| 工具调用超时时间 | `600 秒` | 兼容实验室检测报告解析、备案数据库查询等耗时操作，避免流程中断 |
| 插件数据源拉取范围 | 当前批次关联数据 | 匹配每批换线的更新节奏，仅拉取当前生产批次的文档与数据，减少上下文冗余 |
| 校验规则触发时机 | 每批次生产完成后 | 贴合化妆品批次化管理逻辑，确保每批产品的检验与记录都经过合规校验 |

## 容易做错的三处
- 现象：自定义插件运行后输出下载地址持续跳动后才返回结果。原因：未配置数据源拉取的触发时机，插件反复拉取过期批次的数据导致执行延迟。
- 现象：工作流A调用工作流B后，工作流B无法执行完整流程。原因：未在工作流B中配置必要的前置步骤，且未设置调用结果的返回触发条件，导致流程中途中断。
- 现象：调用第三方接口时提示Error: write EPROT。原因：未正确配置FastGPT与第三方系统的HTTPS证书校验规则，或网络连接存在权限限制，导致数据传输失败。

## 怎么确认配好了
- 触发一次模拟批次生产流程，检查工具调用是否仅拉取当前批次的关联数据，无过期数据混入。
- 运行检验审核任务，确认模型通过函数调用执行工具，可通过系统日志查看具体的调用记录。
- 调用第三方接口完成一次数据交互，确认无权限或证书相关的报错信息，符合预设的校验规则。
- 模拟耗时的实验室数据解析操作，确认工具调用流程未因超时中断，符合配置的时间阈值。
