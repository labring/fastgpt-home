# 化学药制剂生产的检验与过程记录审核：向量模型与索引

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的数据主要来自经批准的处方工艺、MES电子批记录、LIMS系统与质量管理系统。日常文档包含主生产文件、批生产记录、清场记录、检验记录、偏差与变更文件等，包含物料批次、工艺执行参数、检验结果、环境监测数据等字段，单位涉及批次号、摄氏度、千克、小时等。数据更新随生产批次、关键工艺步骤及监测计划执行，每批生产对应完整的记录集合。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的批次化结构化数据与高频更新特性，要求向量索引支持按生产批次快速过滤召回；专业的工艺参数、检验结果字段，需要适配医药领域语义的向量模型，避免通用模型的语义偏移问题；单批生产对应完整的记录集合，需确保索引召回的关联记录无遗漏，支撑批记录审核的全量关联查询；高频新增的批次数据场景下，索引需支持增量更新，避免全量重建带来的额外耗时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配批记录中单段工艺描述的长度，避免块内信息断裂 |
| 重叠长度 | 100–200 字符 | 保留相邻块的上下文关联，确保工艺步骤的连贯性 |
| `maxToken` | 8192 token | 匹配医药领域嵌入模型的最大输入限制，覆盖长文档的分块需求 |
| `defaultToken` | 按实测标定 | 适配单批次记录的总token规模，避免截断关键检验与工艺信息 |
| 相似度阈值 | 0.75–0.85 | 过滤低关联的非工艺相关记录，确保审核检索的精准度 |
| 单次搜索上限 | 前 20 条 | 覆盖单批审核所需的关联记录数量，避免冗余数据加载 |

## 容易做错的三处
- 现象：界面返回503错误，提示指定embedding模型无可用渠道。原因：未单独配置embedding模型渠道，仅使用默认的oneapi配置导致模型调度失败。
- 现象：docker部署后无法建立知识库索引，宿主机无GPU资源。原因：未适配无GPU环境的向量模型加载，依赖GPU的嵌入模型无法正常初始化。
- 现象：配置环境变量后索引仍无法生成，日志显示字段为空。原因：未重建容器使新配置的环境变量生效，原有容器仍使用旧的配置参数。

## 怎么确认配好了
- 检查向量模型的加载日志，确认无初始化失败的报错信息。
- 上传单份批记录文档，执行检索测试，确认返回的关联结果与文档内容匹配。
- 配置按生产批次过滤的检索条件，验证索引是否支持按批次快速召回数据。
- 查看索引更新记录，确认新增的测试数据已被正确索引。
