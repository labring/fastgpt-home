# 医疗器械装配与洁净生产的检验与过程记录审核：部署与升级

## 这个品类的数据长什么样
本品类数据涵盖生产工艺规程、批生产记录、洁净区监测记录、灭菌批记录、检验报告、软件版本记录及不良事件追溯资料。数据来源包括设计历史文件、器件与材料批次台账、MES系统、洁净环境监测设备、灭菌设备及检验校准系统。数据更新以每批产品或每台器械为周期，同时按固定环境监测计划同步更新。文档包含受控装配检验要求、关键材料唯一标识、清洁灭菌参数、软件版本记录等字段，需关联生产批次与全链路追溯信息。

## 这些特征在「部署与升级」这一环带来什么约束
由于本品类数据以单批/单台为更新单位且关联全链路追溯要求，部署时需支持按批次关联文档的权限控制，避免跨批次数据混淆。多源异构数据来自不同设备与系统，需配置兼容多格式数据导入的适配层，确保灭菌参数、洁净环境数据等字段准确映射。固定周期的环境监测数据需设置定时同步任务，保障审核环节的数据时效性。同时，检验与过程记录的受控属性要求部署后保留完整操作日志，便于追溯配置变更与审核流程，且需适配每批数据的独立校验规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 部署专属副本集连接串，配置读写分离 | 本品类数据按批次存储，读写操作分离可避免单批数据写入阻塞审核查询 |
| `PG_URL` | 配置为带连接池的专用数据库地址，连接池大小设为20–30 | 需存储大量批次关联的检验记录与追溯数据，连接池适配并发的批次查询需求 |
| `REDIS_URL` | 启用持久化存储，配置内存上限为8000 MB | 用于缓存洁净环境监测的实时数据与批次校验规则，持久化保障断电后不丢失缓存配置 |
| `STORAGE_S3_ENDPOINT` | 绑定兼容S3协议的对象存储服务端点 | 用于存储灭菌批记录、检验报告等大体积文档，适配多批次文档的批量上传需求 |
| `ROOT_KEY` | 设置为复杂度不低于16位的随机字符串 | 用于生成系统级权限令牌，保障核心配置接口的访问安全，符合FastGPT v4.17.0的权限配置规范 |
| `DB_MAX_LINK` | 配置为15–25 | 限制数据库并发连接数，避免多批次同时发起审核请求导致数据库过载 |

## 容易做错的三处
- 登录界面加载后无法完成注册，提示系统无初始用户。原因是未正确配置`ROOT_KEY`生成初始管理员令牌，或未执行初始化脚本生成默认用户。
- 接入外部模型平台时接口调用超时，返回504状态码。原因是未配置跨域访问白名单，或请求超时阈值设置低于模型响应时长。
- 批量导入灭菌批记录时出现部分文档丢失，系统日志显示连接池溢出。原因是`DB_MAX_LINK`设置过高导致数据库连接数超限，或未按批次拆分导入任务触发并发限制。

## 怎么确认配好了
- 执行初始用户生成脚本，验证登录界面可使用预设管理员账号完成登录，确认`ROOT_KEY`配置生效。
- 导入一份模拟灭菌批记录文档，检查存储路径与`STORAGE_S3_ENDPOINT`配置的端点一致，确认文档上传无异常。
- 发起10个并发的批次检验记录查询请求，观察数据库连接数未超过`DB_MAX_LINK`的配置值，确认连接池配置合理。
- 配置定时同步洁净环境监测数据的任务，检查任务日志中无格式映射错误，确认多源数据适配配置生效。
