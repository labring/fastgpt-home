# 半导体晶圆制造的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
典型主体为晶圆厂的工艺整合、模块、设备、良率与制造部门，日常文档涵盖工艺流程卡、批次运行记录、设备配方、SPC图、异常处置单、缺陷图谱、良率报告。数据来源包括MES系统、设备FDC、缺陷检测与量测设备、晶圆图、工艺配方库与实验数据。更新频率覆盖每批晶圆、实时与每日，字段包含晶圆批次号、纳米级工艺参数、缺陷空间坐标、良率数值等，不同文档的单位与精度差异显著。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的多源异构数据结构、高频更新节奏与纳米级精度要求，对向量模型与索引环节带来多重约束。多源混合的文本、数值与图表数据，需要嵌入模型支持跨类型特征的语义对齐；每批晶圆的实时更新与每日批量同步，要求索引支持增量构建与快速刷新；数百道工序的长流程关联，需要合理的分块策略避免上下文断裂；跨模块良率归因的需求，要求索引存储完整的元数据关联信息，确保检索结果可溯源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配晶圆工艺文档的单工序描述长度，避免跨工序上下文断裂 |
| 重叠长度 | 100–150 字符 | 保留相邻工序的关联信息，提升跨步骤检索准确性 |
| maxToken | 4096 | 匹配主流嵌入模型的输入上限，适配包含缺陷图谱文本的长文档 |
| 相似度阈值 | 0.75–0.85 | 区分工艺参数漂移与正常波动，适配纳米级参数的匹配精度 |
| 单次搜索上限 | 前 8 条 | 覆盖数百道工序的关联检索需求，避免遗漏关键批次记录 |
| defaultToken | 2048 | 控制单批次检索结果的上下文长度，适配洁净室环境下的快速响应要求 |

## 容易做错的三处
- 索引状态长时间显示未就绪，无法触发检索。原因是未配置增量索引适配实时更新的晶圆批次数据，导致全量索引构建耗时过长。
- 嵌入模型无法正常调用Doubao-embedding格式的请求。原因是未调整嵌入模型的输入格式以适配晶圆参数数值与文本混合的多模态数据结构。
- 检索结果无法显示对应的文档来源信息。原因是未开启文档溯源的索引配置，导致向量索引未存储原始文档的元数据字段。

## 怎么确认配好了
- 上传一份标准晶圆工艺流程卡，等待FastGPT v4.17.0的索引完成后，查看界面状态确认显示为就绪。
- 输入一条工艺参数漂移的查询语句，查看检索结果是否返回对应的设备FDC记录与批次运行日志。
- 点击检索结果的溯源按钮，确认能跳转至对应的原始文档并显示批次号、设备编号等元数据信息。
- 测试嵌入模型调用，确认返回的向量结果维度与预设参数一致。
