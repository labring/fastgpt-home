# 印刷与包装加工的检验与过程记录审核：工具调用与插件

## 这个品类的数据长什么样
本品类数据来自彩印、标签、纸箱、软包装及药包材等包装加工主体的业务文档与设备输出，包含印前文件、拼版单、印刷工艺单、油墨配色记录、首件签样、条码检测、模切与复合记录等类型。数据来源覆盖客户稿件、色彩管理系统、印刷机运行数据、油墨与基材批次台账、分光仪及条码检测仪输出。数据按每订单、每批或每次换版更新，单份文档包含版本号、色彩参数、批次信息、检测结果等字段，无统一固定单位，字段单位随对应业务环节调整。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据按订单、批次或换版更新，工具调用需支持按单次业务节点触发，避免跨批次数据混淆。多类异构文档（从文本格式的工艺单到设备输出的数值型检测数据）要求插件兼容不同格式的输入解析，需适配印前文件的矢量格式、分光仪的数值输出等。条码、模切等检测数据的实时性要求，需工具调用的响应延迟匹配生产节拍，同时需支持批量关联同批次多环节数据，确保审核时可调用完整的首件签样、油墨记录等关联信息。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `toolChoice` | auto 或 指定自定义工具 | 本品类需调用分光仪数据、条码检测仪数据等专属工具，auto可自动匹配可用工具，指定自定义工具可锁定合规工具集 |
| `functionCall` | 开启，单次调用不超过3个工具 | 单批次审核需关联拼版单、油墨记录、条码检测3类数据，过多调用会增加生产节拍延迟 |
| 工作流节点超时时间 | 600–1200 秒 | 部分印前文件解析需较长时间，且批次数据关联需等待多设备数据同步 |
| 工具调用触发时机 | 按订单批次触发 | 本品类数据按订单、批次更新，避免跨批次数据混用 |
| 上下文窗口大小 | 8000–12000 token | 单批次审核需关联拼版单、工艺单、多份检测记录，需足够上下文承载完整业务信息 |

## 容易做错的三处
- 现象：调用FastGPT API发送连续业务请求时，后发请求需等待前序生成完成，无法实时中断生成过程。原因：未正确配置`toolChoice`参数，未启用请求中断触发逻辑，导致服务端按队列顺序处理请求。
- 现象：使用自定义URL传入印前文件、拼版单等文档时，工具返回空结果且无报错信息。原因：未将对应URL域名加入工具调用白名单，或未配置插件适配本品类的矢量格式文档解析规则。
- 现象：使用API调用服务时，出现跨域访问报错或请求被拦截。原因：未在服务端配置允许的跨域来源，未添加本品类业务域名到跨域白名单。

## 怎么确认配好了
- 发起连续的模拟订单请求，验证后发请求可实时中断前序生成过程，确认`toolChoice`配置生效。
- 传入自定义URL的印前文件，检查工具返回的解析结果是否包含版次、色彩参数等本品类专属字段，确认白名单与解析规则配置正确。
- 运行完整工作流，检查模型输出是否自动触发文档生成插件，并生成符合归档要求的文件，确认`functionCall`与插件绑定配置正确。
- 查看服务端跨域配置日志，确认允许的来源包含业务域名，跨域请求可正常发起。
