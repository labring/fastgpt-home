# 印刷与包装加工的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
典型主体为彩印、标签、纸箱、软包装和药包材企业，日常文档包含印前文件、拼版单、印刷工艺单、油墨配色记录、首件签样、条码检测、模切与复合记录。数据来源覆盖客户稿件、色彩管理系统、印刷机数据、油墨与基材批次记录、分光仪及条码检测仪。更新节奏为每订单、每批、每次换版触发更新，文档字段包含版次、批次号、色彩参数、条码内容与生产环节时间戳，部分为图像类签样文件，部分为结构化文本记录。

## 这些特征在「引用来源与溯源」这一环带来什么约束
由于数据按订单、批次与换版频次高频更新，溯源需精准绑定特定版次与批次的文档，避免跨订单混淆。文档同时包含文本与图像类内容，溯源需同时支持文本元数据与图像文件的关联引用。多来源的数据需整合不同系统的字段，溯源配置需兼容跨系统的元数据匹配。生产环节出错后果严重，溯源需快速定位原始文档与生产节点，确保审核时可追溯每一步操作依据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 相似度阈值 | 0.72–0.85 | 匹配印刷工艺单、首件签样等带格式的文本与图像元数据 |
| 单次搜索上限 | 前8条 | 覆盖单订单多批次的关联文档数量 |
| 最大上下文 | 12000–15000 字符 | 容纳拼版单、油墨记录等多文档拼接的完整内容 |
| `quoteMaxToken` | 4000–6000 token | 提取首件签样、条码检测报告的完整溯源内容 |
| 重排 | 按生产时间排序 | 匹配印刷与包装加工的流程先后顺序 |
| `detail` | 开启 | 展示溯源文档的具体字段与版本信息 |

## 容易做错的三处
- 现象：检索知识库时仅返回1条引用文档，结果条数与实际关联文档数量不符。原因：单次搜索上限配置过低，未覆盖单订单下多批次的关联文档。
- 现象：配置模型后点击测试弹出报错，强行忽略后可正常运行。原因：未正确配置`responseData`的返回格式，导致初始校验逻辑触发异常。
- 现象：导入JSON格式的知识库后目录为空，需手动选择目标文档。原因：未绑定订单版次与知识库目录的自动匹配规则，未开启按生产批次自动关联知识库的功能。

## 怎么确认配好了
- 上传单订单的全量关联文档，发起溯源查询，核对返回的引用文档数量是否匹配订单批次数。
- 调用溯源功能，检查返回结果中是否包含印版版次、油墨批次等印刷包装加工专属的元数据字段。
- 修改单次搜索上限配置，验证检索结果的条数随配置参数变化。
- 开启`detail`参数，确认引用来源中展示了原始文档的具体内容与版本信息。
- 使用FastGPT v4.17.0版本的测试工具，模拟首件审核场景，验证溯源结果可关联到对应的油墨配色记录与签样文件。
