# 印刷与包装加工的检验与过程记录审核：知识库检索与召回

## 这个品类的数据长什么样
本品类典型主体为彩印、标签、纸箱、软包装及药包材加工企业。日常业务文档包含印前文件、拼版单、印刷工艺单、油墨配色记录、首件签样、条码检测记录、模切与复合记录。数据来源涵盖客户稿件、色彩管理系统、印刷机运行数据、油墨与基材批次台账、分光仪检测结果、条码检测仪读数。数据更新频率为每订单、每批或每次换版，文档字段包含版次、批次号、色彩参数、条码内容等核心业务标识。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据更新频率高、来源分散且文档类型多样，不同于仅提供基材的造纸品类，需同时处理内容版本、颜色与包装结构的多维度校验，对检索召回环节带来多重约束。高频更新要求检索结果需优先匹配最新的订单、批次或换版后的文档，避免调用过期的工艺或配色记录。多类型文档包含文本参数、检测数值、批次台账等不同字段，需支持按业务标识（如版次、条码编号）限定检索范围。不同来源的数据格式存在差异，需兼容非结构化文本与结构化参数的匹配逻辑，同时适配业务中对术语匹配的灵活需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配本品类的版次、条码编号等精准业务标识，兼顾召回范围与结果相关性，避免漏检关键的首件签样或配色记录 |
| `limit` | `前8–12条` | 覆盖单订单下的多类文档（如拼版单、工艺单、检测记录），避免单次上下文超出模型处理上限 |
| `searchMode` | `mixedRecall` | 适配本品类既有文本术语又有数值参数的文档类型，同时支持关键词匹配与语义召回，覆盖拼版单的文字内容与分光仪的色彩数值 |
| `usingReRank` | `开启，按实测标定权重` | 对召回的多类型文档进行重排序，优先展示与检验审核场景强相关的首件签样、配色记录，提升校验效率 |
| `datasetSearchUsingExtensionQuery` | `开启` | 扩展业务查询的匹配范围，适配客户稿件中的异形术语与印刷行业专用词汇，支持拼音匹配需求 |
| `collectionIds` | `按当前订单标签筛选` | 限定检索范围为当前订单关联的文档集合，避免跨批次的无效召回，确保审核结果仅针对当前生产任务 |

## 容易做错的三处
- 检索结果未限定在指定订单的文档范围内，出现跨批次的拼版单与工艺单。原因是未正确配置`collectionIds`参数，未绑定当前业务的文档集合。
- 输入拼音缩写（如“YS”对应“油墨”）无法召回对应的配色记录。原因是未开启`datasetSearchUsingExtensionQuery`，未启用拼音匹配扩展逻辑。
- 运行插件验证时出现 MongoServerError。该报错本身不足以证明 MongoDB 4.4.29 与 FastGPT 不兼容；请查看完整日志，核对插件发起的数据库请求和账户权限。FastGPT v4.17.2 官方部署配置为不支持 AVX 的 CPU 标注了 4.4.29 回退（见[官方部署配置](https://github.com/labring/FastGPT/tree/v4.17.2/deploy/version/main)）。

## 怎么确认配好了
- 执行带当前订单版次、批次号的查询，核对返回结果是否仅包含当前订单关联的文档。
- 测试拼音术语查询，确认是否能召回对应的业务文档，如输入“youmo”可匹配油墨配色记录。
- 导出与导入知识库，核对不同业务集合是否保持独立的文件结构，未被合并为单个文件。
- 运行插件验证流程后查看完整错误与服务日志，确认 MongoDB 实际镜像版本、CPU 是否支持 AVX 及插件请求/账号权限；兼容性边界需按实际部署配置核验，不以单一 FastGPT 版本要求判断。
