# 印染与后整理的检验与过程记录审核：引用来源与溯源

本文基于FastGPT v4.17.0版本的配置逻辑编写。

## 这个品类的数据长什么样
该品类的日常文档包含染色配方、称化料记录、染缸曲线、打样确认、色差报告、定形工艺单、污水台账。数据来源覆盖客户色样、配方库、染化料批次、染缸控制设备、测色仪、定形机与环保监测装置。数据更新频率为每缸、每批或每班，单批次数据包含缸号、染料配比、染缸温度、保温时长、排放浓度等字段，部分字段带有明确单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
高频的缸、批、班级更新要求溯源信息精准绑定具体缸号与批次，避免跨批次的工艺记录混淆。湿化学工艺的文档多包含结构化数值参数与设备运行曲线，需支持对精准片段的溯源定位。数据来源覆盖人工记录与设备采集的混合格式，需兼容不同元数据的关联逻辑。出错后果涉及整缸返修报废与环保合规，要求溯源信息可直接追溯至原始记录，无需二次验证。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | 匹配染缸曲线、工艺单等单段文档的平均长度，避免截断关键工艺参数 |
| `responseData` | 开启 | 启用后可在回复中返回引用片段的元数据，满足溯源需求 |
| `detail` | 开启 | 关联引用片段与原文档的完整路径与切片位置，支持原文档预览 |
| 最大召回条数 | 前6条 | 单缸相关的工艺记录与台账数量有限，过多召回会干扰上下文准确性 |
| 上下文窗口 | 2000–2500 token | 覆盖单批次的工艺参数、批次信息与质检记录的总长度 |

## 容易做错的三处
- 现象：终端回复未显示引用来源模块。原因：未开启`responseData`配置项，或未启用知识库的引用展示开关。
- 现象：引用报错红色数字串。原因：未正确绑定染整专属知识库的数据源，或批次号、缸号等核心字段未映射到知识库切片的元数据中。
- 现象：无法预览切片前的原文档详情。原因：知识库导入时未保留原文档的完整存储路径与版本信息，或未开启`detail`配置项关联原文档位置。

## 怎么确认配好了
- 发起包含具体缸号或染化料批次号的查询，检查回复末尾是否显示引用来源模块。
- 点击引用来源模块的跳转链接，确认跳转至导入知识库时的原文档对应切片位置。
- 查看已导入的知识库切片元数据，确认包含染化料批次、缸号、生产班组等核心字段。
- 模拟异常查询场景，确认引用报错信息清晰可读，无红色数字串类的无意义报错。
