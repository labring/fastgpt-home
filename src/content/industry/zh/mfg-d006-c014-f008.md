# 印染与后整理的检验与过程记录审核：文档解析与分块

## 这个品类的数据长什么样
本品类数据来自染整厂、面料企业的染色、定形、实验室与质量部门，日常文档包含染色配方、称化料记录、染缸曲线、打样确认、色差报告、定形工艺单、污水台账。数据来源涵盖客户色样、配方库、染化料批次、染缸控制设备、测色仪、定形机与环保监测装置，更新频率为每缸、每批、每班。文档多为结构化表格、时序曲线文本与字段化记录，包含ΔE色差值、染缸温度、化料用量等专业参数，单位涵盖℃、g/L、mg/L等。

## 这些特征在「文档解析与分块」这一环带来什么约束
高频更新的单缸/单批数据要求分块需保留核心参数的上下文关联，避免拆分关键参数组合。结构化表格与时序曲线类文档，要求解析工具需适配非纯文本内容，完整提取表格字段与时序数据。专业参数与单位、批次的绑定要求分块时不能割裂关联关系，否则会影响后续审核校验。批量多文档的处理需求，要求解析配置需兼顾单文档完整性与批量处理效率。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，适配印染与后整理场景的文档解析与分块需求：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配染色配方、色差报告等单文档核心参数组合的上下文完整性，避免拆分染料用量、工艺温度等关联字段 |
| `chunkSplitter` | 按段落+表格块拆分 | 适配染缸曲线时序数据、定形工艺单的结构化表格，保留每行表格的完整参数关联 |
| `customPdfParse` | 启用结构化解析模式 | 针对染缸曲线PDF、定形工艺单的内嵌表格与图片内嵌文本，提取原始字段与专业参数，保留单位与批次关联 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配含大量时序数据的染缸曲线PDF解析时长，避免大文件解析中断 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 适配批量上传的染缸曲线PDF包与多份台账文档，避免超过上传限制导致失败 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型的差异化分块需求，灵活调整参数适配配方单、污水台账等不同场景 |

## 容易做错的三处
- 现象：上传Word格式的定形工艺单后，解析分块丢失内嵌的工艺参数表格与图片内嵌的色差数值。原因：未启用`customPdfParse`的结构化解析模式，默认仅提取纯文本段落，无法识别Word内嵌表格与图片文本内容。
- 现象：批量上传多缸染缸曲线PDF时触发解析超时。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`至合理时长，沿用默认短时长导致大文件解析未完成即中断。
- 现象：分块后的内容无法关联染色配方与对应称化料记录。原因：`chunkSize`设置过小，拆分了配方与化料批次的关联内容，导致审核时无法匹配对应参数。

## 怎么确认配好了
- 上传一份典型的染色配方单PDF，检查解析后的分块是否保留了染料名称、用量、工艺温度的完整组合。
- 上传一份含时序数据的染缸曲线PDF，检查解析结果中是否包含完整的温度、时间序列数据，无字段丢失。
- 批量上传3-5份同类型文档，验证解析耗时未超过预设的`PARSE_FILE_TIMEOUT_SECONDS`时长，无超时报错。
- 查看分块后的内容，确认染化料批次号与对应缸号出现在同一块文本中，无拆分割裂。
