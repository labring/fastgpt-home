# 印染与后整理的检验与过程记录审核：部署与升级

## 这个品类的数据长什么样
该品类的数据来自客户色样、配方库、染化料批次、染缸控制设备、测色仪、定形机及环保监测装置。日常生成染色配方、称化料记录、染缸曲线、打样确认单、色差报告、定形工艺单、污水台账等文档。数据更新频率为每缸、每批或每班，字段包含染缸温度、化料配比、色差ΔE值、排放COD值等，对应单位为℃、g/L、无单位、mg/L等。文档以结构化表单与非结构化时序曲线为主，单缸生产产生的文档数量随加工复杂度波动。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的高频小批量文档更新、非结构化时序数据与合规性文档并存的特征，对部署与升级带来多重约束。首先，每缸/批产生的多份文档会带来突发的并发读写请求，需保障数据库与存储的稳定性。其次，染缸曲线等时序非结构化文件体积较大，需适配大文件上传与解析的配置。再者，污水台账等合规文档需严格保留原始字段与元数据，避免解析过程中丢失关键信息。最后，数据随生产班次波动的特性，要求部署环境具备弹性调整能力，适配不同时段的资源需求。升级过程中需避免中断生产相关的文档存储与调用，需提前做好配置备份。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 个连接` | 该品类单缸/批产生多份文档，并发连接需求随生产班次波动，该取值可避免连接池耗尽 |
| `STORAGE_S3_ENDPOINT` | `本地对象存储地址，按实测标定` | 染色曲线、色差报告等非结构化文件体积较大，需适配本地存储的访问配置 |
| `REDIS_URL` | `本地 Redis 服务地址，端口默认 6379` | 缓存高频调用的配方、色样数据，降低数据库的重复查询压力 |
| `FILE_TOKEN_KEY` | `随机生成的 32 位字符串` | 保护文件上传接口安全，避免未授权访问生产相关的染整文档 |
| `MONGODB_URI` | `配置副本集地址，设置连接超时为 600 秒` | 存储大量批次化的染整文档，副本集保障数据可用性，超时设置适配大文件解析的延迟 |

## 容易做错的三处
- 升级后容器启动失败，现象是执行docker compose up命令后出现依赖版本冲突报错，原因是未使用对应版本的配置文件覆盖原有配置，未提前备份数据库配置。
- 上传大体积文件返回413错误，现象是上传染缸曲线等大文件时界面返回413 Request Entity Too Large，原因是docker部署环境中未调整上传文件大小限制，默认限制无法适配染整文档的体积。
- 调用ollama模型返回空结果，现象是配置ollama的api地址后发起测试调用无有效返回，原因是ollama服务未开放本地网络端口，或配置的地址未包含正确的端口号。

## 怎么确认配好了
- 执行docker compose ps命令，确认FastGPT相关容器及依赖的数据库、缓存容器均处于运行状态。
- 上传一份100MB左右的染缸曲线文件，确认上传成功且解析后可在知识库中正常查看。
- 在FastGPT v4.17.0的管理后台配置DeepSeek的api key，发起一次测试调用，确认返回正常的模型结果。
- 查看数据库连接日志，确认当前连接数未超过`DB_MAX_LINK`的设置值。
