# 原料药与医药中间体生产的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
原料药与医药中间体生产的核心数据来自合成、发酵、精制、质量与注册支持部门，包含批生产记录、物料平衡表、反应与精制记录、清洁记录、杂质谱报告、偏差与变更文件等。数据来源覆盖注册工艺文档、原料批次台账、DCS系统、称量系统、LIMS、色谱数据系统及QMS，更新频率为每生产批次、每工艺步骤一次。文档多为长段落专业文本，包含反应参数、杂质含量、溶剂残留量、批次编号等专属字段，核心聚焦多步化学路线与杂质谱管控，与制剂生产品类的差异显著。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引系统兼容不同格式的文本导入，避免专业字段的格式丢失。高频次的按批次更新要求支持增量索引与批量重建索引的灵活切换，减少重复计算的资源消耗。长段落的专业文档需要合理的分块逻辑，避免拆分反应步骤或杂质分析的完整上下文。专属字段与专业术语的语义匹配要求向量模型适配医药化工领域的专业词汇，提升检索的精准度。出错后果的严重性也要求索引召回的结果需覆盖足够的关联信息，避免遗漏关键工艺参数或偏差记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配批生产记录的单段落专业文本长度，避免跨步骤逻辑断裂 |
| 重叠长度 | 150–200 字符 | 保留反应步骤间的上下文关联，确保检索时可获取完整工艺链 |
| `maxToken` | 8192 token | 适配多步反应记录的总长度，符合主流Embedding模型的输入限制 |
| `defaultToken` | 按实测标定 | 适配不同Embedding模型的token计数规则，避免文本截断异常 |
| 单次搜索上限 | 前 8 条 | 覆盖多步工艺的关联信息，满足工艺变更与杂质追踪的检索需求 |
| 相似度阈值 | 0.75–0.85 | 匹配医药化工领域的专业术语语义精度，过滤低相关的检索结果 |

## 容易做错的三处
- 现象：分块预览显示反应步骤被拆分，检索时无法获取完整的投料参数与反应条件。原因：未设置合理的重叠长度，导致相邻段落的关联信息被割裂，同时误将最大段落深度设置为3，未覆盖长反应流程的层级结构。
- 现象：接入多模态Embedding模型时返回Invalid报错，无法完成索引创建。原因：未在FastGPT v4.17.0中启用多模态输入适配开关，或未将输入文件转换为模型支持的格式。
- 现象：执行向量库迁移后，旧批次的杂质谱报告无法被新的检索逻辑匹配。原因：迁移过程中未保留原有的批次关联元数据，导致专业字段的语义上下文丢失，无法与新的工艺参数形成关联。

## 怎么确认配好了
- 上传一份完整的批生产记录文档，查看分块预览界面，确认反应步骤与杂质分析内容未被不合理拆分。
- 输入一条工艺相关的查询，核对返回结果的条数是否符合单次搜索上限的设置，且检索结果的语义匹配度符合预期。
- 执行向量库迁移操作，验证迁移后的旧数据可正常被当前的向量模型检索，无格式或内容丢失。
- 触发全量重建索引任务，检查任务进度日志无报错，且所有文档均完成索引更新。
