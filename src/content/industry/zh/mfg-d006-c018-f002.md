# 基础化工连续生产的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
基础化工连续生产场景的数据来源包括DCS/SIS系统、在线分析仪、LIMS系统、设备状态监测模块、能源计量装置与原料储罐数据终端。日常产生的文档涵盖操作规程、工艺指标卡、DCS趋势曲线、化验报告、联锁旁路记录、特殊作业票与班报。数据更新节奏覆盖实时、每班与每日三类，其中DCS趋势与在线分析仪数据为实时更新，班报与化验报告按每日或每班提交，联锁旁路记录与特殊作业票随流程触发生成。文档字段包含工艺参数实测值、操作时间戳、设备状态标识与作业审批信息，单位涵盖兆帕、摄氏度、吨每小时等工业常用计量标准。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时更新的DCS与在线分析仪数据要求索引支持低延迟的增量同步，避免数据滞后导致的审核偏差。多类型文档的混合存在，需要分块策略适配不同长度的文本与结构化数值块，防止工艺逻辑被截断。不同更新频率的数据需要分层索引策略，平衡实时数据的查询性能与批量文档的存储成本。高风险的联锁旁路记录与特殊作业票，要求索引配置更高的召回优先级，确保审核时无遗漏。同时，工艺参数的数值特性要求向量生成需兼顾结构化数据与非结构化文本的语义一致性，避免匹配逻辑失效。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配工艺指标卡、班报等非结构化文本的平均长度，同时兼容DCS趋势的结构化数值块 |
| 重叠长度 | 50–100 字符 | 避免跨分块的工艺逻辑被截断，确保联锁逻辑的完整语义 |
| 相似度阈值 | 按实测标定 | 需匹配基础化工工艺参数的波动范围，避免误判正常波动为异常 |
| 单次搜索上限 | 前 8 条 | 覆盖当班所有关键工艺参数的关联记录，平衡查询效率与召回完整性 |
| `defaultToken` | 4096 | 适配DCS趋势、化验报告等长文档的上下文承载，满足多段数据的关联审核 |
| `maxToken` | 8192 | 支持特殊作业票、联锁旁路记录等复杂文档的完整向量生成，避免内容截断 |

## 容易做错的三处
- 现象：索引召回结果中缺少部分实时DCS趋势数据，检索延迟超出业务容忍范围。原因：未针对实时数据流配置增量索引触发规则，仅执行全量索引任务，导致新数据无法及时被检索。
- 现象：界面弹出向量生成失败提示，日志显示token超限错误。原因：未正确设置`maxToken`参数，未对超长文档进行合理分块，导致单段文本超出模型支持的token上限。
- 现象：混用不同向量模型生成工艺参数与文本文档的向量后，检索匹配度波动较大。原因：未针对基础化工场景的结构化与非结构化数据分别配置专用向量模型，混用模型破坏了语义空间的一致性。

## 怎么确认配好了
- 查看FastGPT v4.17.0的索引同步日志，确认实时DCS数据的更新延迟符合业务要求，无连续超时或丢包记录。
- 随机抽取一份联锁旁路记录，执行审核检索，核对返回结果的条数与覆盖范围是否符合预设的单次搜索上限。
- 上传一份超长的特殊作业票，检查向量生成结果是否完整，无内容截断提示。
- 对比不同文档类型的检索匹配结果，确认结构化工艺参数与非文本操作记录的召回逻辑符合预期。
