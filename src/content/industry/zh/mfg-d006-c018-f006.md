# 基础化工连续生产的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
基础化工连续生产品类的日常文档包含操作规程、工艺指标卡、DCS趋势、化验报告、联锁旁路记录、特殊作业票、班报。数据来源覆盖DCS/SIS、在线分析仪、LIMS、设备状态、能源计量、原料储罐，更新节奏涵盖实时、每班、每日。数据字段附带明确的单位标识，如工艺压力为MPa、温度为℃、物料流量为t/h，化验数据包含采样时间与合格阈值，联锁记录标注触发条件与动作时间。

## 这些特征在「引用来源与溯源」这一环带来什么约束
实时更新的DCS趋势与在线分析仪数据，要求溯源时匹配精确的时间戳，确保引用的是当前检验节点的对应数据。每班、每日生成的班报与化验报告，需要按生产批次关联引用，避免跨批次数据混淆。多源分散的数据来源，要求整合不同系统的文档格式与字段规则，统一溯源的匹配逻辑。带单位的工艺参数字段，要求匹配时校验单位一致性，防止将不同量级的参数数据混淆。强联锁记录的精准关联，要求引用时绑定设备、时间与动作信息，满足合规审核的溯源需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配工艺规程、DCS趋势片段的自然分段，避免截断关键参数与逻辑描述 |
| 重叠长度 | 100–200 字符 | 覆盖跨块的联锁逻辑与工艺关联信息，防止溯源时丢失关键上下文 |
| 相似度阈值 | 0.75–0.85 | 校验参数单位的一致性，避免将不同量级的同名称参数数据误匹配 |
| `quoteMaxToken` | 3500–4500 token | 限制单轮引用的总长度，适配长文档的完整引用需求，避免上下文溢出 |
| `responseData` | 仅返回带校验标记的文档 | 过滤过期的归档数据，确保引用的是当前生产周期内的有效文档 |
| `detail` | 显示完整引用字段 | 展示化验数据的采样时间、合格阈值等细节，满足审核溯源的完整信息需求 |

## 容易做错的三处
- 现象为知识库返回结果的排序不符合预期，未按与检验问题的匹配度呈现。原因是未针对基础化工数据的单位特征调整相似度匹配规则，导致不同单位的同名称参数数据优先级混乱。
- 现象为对话中显示了未匹配到本地知识库的引用条目。原因是未关闭冗余引用开关，且未过滤来自离线归档的过期数据。
- 现象为多知识库分支调用后，不同分类的结果未统一引用格式。原因是未在工作流中配置统一的引用合并节点，导致各分支的溯源展示格式不一致。

## 怎么确认配好了
- 上传一份包含MPa单位的工艺压力数据的DCS趋势文档，在FastGPT v4.17.0环境中发起工艺校验请求，核对返回的引用中包含正确的单位标识与时间戳。
- 发起包含联锁旁路记录的审核请求，核对返回的引用中包含触发条件、动作时间与设备编号字段。
- 调整`quoteMaxToken`参数的取值，验证返回的引用总长度符合设定的区间范围。
- 关闭引用显示开关，发起测试请求，确认对话中不再显示知识库引用条目。
