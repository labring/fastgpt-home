# 安全环保与特殊作业管理的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自法规标准、在线环保监测设备、气体检测仪、人员资质档案、设备隔离清单及监管平台。日常文档包含风险辨识记录、动火/受限空间/吊装等作业票、环境监测记录、危废台账、排放监测数据、事故与隐患整改报告。数据更新随单次作业完成、实时监测结果或定期检查推进，文档字段包含作业时间、气体浓度值、资质有效期、隔离点位编号等，附带ppm、天等专属单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据兼具结构化监测数值与非结构化文档内容，且更新频率随作业、实时监测或定期检查变动，要求向量模型与索引适配混合数据格式与高频更新节奏。文档包含专业作业术语与专属单位，需向量模型准确捕捉行业语义特征。同时作业审核的否决权要求高，召回结果的精准性需匹配业务决策需求，避免误召回或漏召回影响安全合规。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配作业票、监测记录的单段有效内容长度，保障向量编码的语义完整性 |
| 重叠长度 | 100–200 字符 | 避免跨块语义断裂，维持上下文连贯性 |
| 相似度阈值 | 0.72–0.85 | 过滤低相关内容，匹配安全审核的高置信决策要求 |
| 单次搜索上限 | 前 10 条 | 平衡召回效率与业务参考的合理范围 |
| `maxToken` | 8000 token | 适配长文档的上下文整合，覆盖多数事故整改报告的长度 |
| `defaultToken` | 按实测标定 | 适配不同来源数据的编码基准，兼容结构化与非结构化内容 |
| embedding模型 | shaw/dmeta-embedding-zh | 适配中文专业作业文档的语义编码，覆盖行业常用的术语与单位识别需求 |

## 容易做错的三处
- 现象：知识库搜索响应超时，日志显示单次检索耗时超过60秒。原因：未针对高频更新的作业数据配置增量索引，全量索引重建占用过多计算资源。
- 现象：检索结果中混入无关的产品质检记录，未过滤非安全环保类文档。原因：未配置基于数据来源或文档类型的索引过滤规则，导致跨品类数据被召回。
- 现象：自定义索引创建失败，界面提示字段格式不匹配。原因：直接复用通用文档的索引模板，未适配本品类数据的专属单位与字段结构。

## 怎么确认配好了
- 使用FastGPT v4.17.0的索引管理模块执行单次检索测试，核对返回结果的文档类型是否均为安全环保与特殊作业相关内容，调整相似度阈值至符合业务需求的区间。
- 模拟单次作业完成后的文档上传，验证索引是否在合理时间内完成增量更新，确认更新节奏匹配业务实际频率。
- 查看向量模型的编码日志，确认专业术语与专属单位被正确识别，无语义编码偏差。
- 核对`maxToken`配置是否适配当前导入的最长文档长度，避免出现上下文截断问题。
