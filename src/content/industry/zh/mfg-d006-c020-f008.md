# 安全环保与特殊作业管理的检验与过程记录审核：文档解析与分块

## 这个品类的数据长什么样
本品类数据来自化工、冶金等制造企业EHS部门与检维修团队，涵盖风险辨识记录、动火/受限空间作业票、环境监测台账、危废处置清单等文档。数据来源包含法规标准、在线环保监测系统、气体检测仪、人员资质文件、设备隔离清单及监管平台。更新频率覆盖每次作业生成新记录、实时同步监测数据、定期完成台账更新。文档包含结构化表格与非结构化文本，字段包含作业编号、气体浓度值、资质有效期、处置量等，附带ppm、立方米、天等单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
多类型文档混合（结构化表格与非结构化文本）要求分块规则兼顾字段完整性，避免拆分破坏作业票、台账的关联信息；多样的数据来源与高频更新节奏，要求解析流程具备高效批量处理能力，同时需控制单文件解析时长；明确的业务字段与单位要求分块时保留上下文关联，确保检索时精准匹配作业编号、监测数值等关键信息；不同格式的导入需求（如PDF作业票、Excel监测表）要求解析工具适配多格式，避免字段丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配作业票、监测记录的文本长度，保留单条作业的完整上下文 |
| `chunkSplitter` | 按段落+表格拆分 | 区分结构化表格数据与非结构化文本，避免拆分破坏字段关联 |
| `customPdfParse` | 启用 | 准确提取作业票、整改报告中的表单字段，保留格式与内容关联 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 适配批量上传的季度监测报告、年度危废台账，避免上传失败 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 处理包含多页监测数据的PDF或大型Excel表格，避免解析超时 |
| `chunkSettingMode` | 手动配置 | 针对作业票、台账、监测数据等不同文档类型调整分块规则，匹配业务字段 |

## 容易做错的三处
- 上传Excel格式的危废台账后，知识库检索时无法提取表格内的危废产生量数值。原因是未配置按表格拆分的分块规则，仅按文本行拆分导致表格字段丢失。
- 上传的动火作业票PDF在知识库中显示正常，但生成回复时未包含作业票内的气体检测值内容。原因是未启用`customPdfParse`，导致PDF中的表单字段未被完整解析。
- 上传本地用某向量模型切分后的文档到FastGPT v4.17.0服务器，使用另一向量模型时，检索结果出现大量无关内容。原因是本地分块的上下文边界与服务器模型的嵌入逻辑不匹配，导致语义关联断裂。

## 怎么确认配好了
- 上传单份动火作业票PDF，检查解析后的文本是否包含作业票编号、气体检测值、审批人等完整字段。
- 导入危废台账Excel文件，检索时验证是否能提取表格内的危废名称、产生量、处置单位等结构化数据。
- 批量上传10份不同类型的EHS文档，检查上传和解析任务是否在`PARSE_FILE_TIMEOUT_SECONDS`设定的时间内完成。
- 切换向量模型后，检索同一文档片段，验证语义匹配结果的相关性符合业务预期。
