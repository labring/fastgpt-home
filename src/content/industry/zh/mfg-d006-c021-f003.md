# 家具与木制品制造的检验与过程记录审核：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据通常来自订单设计系统、板材与木材批次台账、数控开料与钻孔设备日志、ERP/MES系统、现场生产检测设备。更新节奏随单生成、每日同步、按材料批次更新。日常文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺要求、五金配件清单、试装与包装记录，包含板件尺寸、配件型号、生产工序编号等字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类定制属性强，单订单板件数量多，多轮对话需持续关联订单专属的尺寸、工序参数，避免上下文丢失。日常文档类型多样，提示词需明确区分拆单图、开料清单等不同文档的提取规则，确保信息匹配准确。数据更新节奏频繁，多轮对话需调用最新的板材批次、设备日志数据，避免使用过期信息。板件尺寸与现场安装直接绑定，对话过程中需逐轮校验前后环节的尺寸一致性，防止累积误差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `messages` | 前8–12条对话记录 | 该品类单订单板件多，需保留足够的工序校验上下文，避免关键参数丢失，适配FastGPT v4.17.0版本的对话存储逻辑 |
| `variables` | 绑定订单专属的板件尺寸、五金清单变量 | 定制订单参数差异大，需通过变量传递实时更新的生产数据，确保多轮对话的信息一致性 |
| 最大上下文长度 | 8000–12000 token | 日常文档包含拆单图、开料清单等多类内容，需足够长度承载完整的生产信息 |
| 单次搜索上限 | 前5–8份关联文档 | 该品类生产文档数量多，需限制搜索范围，避免系统加载过多非必要数据 |
| 触发条件 | 按工序节点触发对话 | 生产流程分拆单、开料、封边等环节，需按节点校验对应数据，避免无效调用 |
| `chatId` | 绑定订单唯一标识 | 需区分不同订单的对话上下文，避免跨订单参数混淆，保障多轮对话的专属逻辑 |
| 结果校验阈值 | 按实测标定 | 不同工厂的工序标准存在差异，需结合现场生产数据调整校验规则 |

## 容易做错的三处
- 现象：工作流中嵌入文本内容提取节点并配置聊天记录条数后，无法实现多轮对话。原因：未绑定`chatId`参数，导致系统无法关联对应订单的对话上下文，仅保留单轮输入信息。
- 现象：调用多模态模型处理拆单图等图片文档时，提示格式错误。原因：未在提示词中明确指定支持的文档解析规则，或未对图片内容做结构化转换。
- 现象：线上对话环节持续触发知识库搜索且无响应。原因：未设置单次搜索上限，导致系统加载过多非必要的生产数据，超出处理负荷。

## 怎么确认配好了
- 发起首轮对话输入订单基础信息，查看系统是否保留该订单的专属变量数据。
- 触发多轮对话后，检查系统是否能关联前一轮的校验结果，继续推进工序审核流程。
- 调用多模态模型处理拆单图，确认返回的提取结果符合预设的文档解析规则。
- 测试单次搜索功能，确认仅返回指定数量的关联文档。
- 测试工作流节点的触发逻辑，确认仅在指定工序节点时启动对话流程。
