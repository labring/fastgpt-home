# 家具与木制品制造的检验与过程记录审核：部署与升级

## 这个品类的数据长什么样
家具与木制品制造的生产数据通常来自订单设计系统、板材与木材批次台账、数控开料/钻孔设备、ERP/MES系统、含水率检测设备。日常生产文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金配件清单、试装与包装记录。数据更新节奏为每订单、每日或每批材料更新，字段包含板件尺寸（单位毫米）、板材含水率检测数据、五金型号、订单编号等，随定制订单的个性化需求变化。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的多源生产数据、高频更新节奏与个性化文档结构，对部署与升级环节带来多重约束。多系统数据源需适配不同格式的同步请求，部署时需配置兼容多接口的连接参数；定制订单驱动的板件数量多、文档结构不固定，升级时需验证非标准化文档的解析逻辑；板材批次、含水率等检测数据的实时性要求高，需保障数据库连接稳定，避免数据同步中断；板件尺寸、孔位等字段精度要求严格，升级后需校验字段映射规则，防止参数错位影响生产。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 100–150 个 | 适配多设备、多订单系统的并发数据请求，避免连接池耗尽 |
| `MONGODB_URI` | 包含认证信息与读写分离地址 | 适配生产数据的批量读写需求，保障ERP、数控设备数据同步稳定 |
| `FE_DOMAIN` | 企业内网专属域名 | 限制前端访问范围，适配定制家具企业的内网部署场景 |
| `STORAGE_S3_ENDPOINT` | 企业自建对象存储地址 | 存储拆单图、开料清单等大体积生产文档，满足高频存储需求 |
| `FILE_TOKEN_KEY` | 按实测标定 | 用于生产文档的安全校验，适配企业内部的权限管控规则 |

## 容易做错的三处
- 升级后前端版本显示异常：升级到FastGPT v4.17.0后，前端控制台显示版本仍为旧版，原因是未执行前端静态资源的构建打包步骤，仅更新了后端服务代码。
- MongoDB连接间歇性中断：部署初期数据库连接正常，数小时后出现连接超时报错，原因是未配置`DB_MAX_LINK`的合理阈值，导致连接池被并发请求耗尽。
- 跨版本升级跳过无脚本版本失败：跳过中间无升级脚本的版本直接升级后，系统无法正常启动，原因是未按版本顺序执行数据库结构变更脚本，导致数据结构不匹配。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`配置的地址可正常读写生产数据，无连接报错。
- 上传一份拆单图文档，确认`STORAGE_S3_ENDPOINT`配置的存储服务可正常存储与读取该文档。
- 访问`FE_DOMAIN`配置的地址，确认前端页面加载正常且版本显示为FastGPT v4.17.0。
- 模拟多订单数据同步请求，确认`DB_MAX_LINK`配置的连接数可支撑并发请求，无连接耗尽情况。
