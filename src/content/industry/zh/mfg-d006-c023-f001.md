# 工业仪器仪表制造与校准的检验与过程记录审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类数据来自流量、压力、温度、分析仪器制造商及计量实验室的装配调试单、校准规程、原始校准记录、误差曲线、计量证书及软件版本记录，数据来源涵盖设计文件、标准器和环境监测数据、校准软件输出、实验室信息系统及客户量程要求。每台被测仪器每次校准生成专属数据集，字段包含溯源编号、校准环境温湿度、多点测量误差值、合格判定结果，单位涉及℃、kPa、ppm等计量专用单位，更新频率随单次校准流程完成即时生效。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
本品类的数据特征对HTTP接口与外部系统环节带来多重约束。单台仪器每次校准生成专属数据集，接口请求需绑定单台仪器的溯源标识，不得混发多台仪器的记录。字段包含计量专用单位与溯源编号，接口需支持自定义字段映射规则，避免单位转换或溯源信息丢失。校准记录作为核心交付物，接口传输需配合鉴权机制保证数据完整性，同时需对接实验室信息系统同步校准流程节点信息，单次请求的数据量规模需适配单台仪器的校准数据量。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {实验室专属API密钥}` | 本品类校准数据需严格权限管控，使用专属密钥鉴权可避免未授权访问 |
| `variables` | `{"unit_mapping": {"℃": "摄氏度", "kPa": "千帕斯卡"}}` | 适配计量专用单位的字段展示需求，确保外部系统接收的单位符合行业规范 |
| `responseData` | `仅返回status和trace_id字段` | 本品类接口仅需确认请求接收状态与溯源标识，无需返回冗余数据，降低传输负载 |
| 请求超时时间 | 600 秒 | 单台仪器的完整校准数据处理需较长周期，避免因超时中断校准记录同步流程 |
| 批量请求阈值 | 1 条/次 | 本品类数据随单次校准生成，单批次仅可同步单台仪器的记录，避免不同仪器的校准数据混淆 |

本文档基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 现象：配置飞书Webhook后，单独测试hook_url可正常发送消息，但加入循环节点拼接的校准记录后无法触发推送。原因：未在接口配置中绑定动态变量，导致循环生成的多段校准数据无法传入请求体。
- 现象：Docker Compose部署后无法找到OneAPI相关配置参数，外部系统转发请求失败。原因：未在docker-compose.yml文件中添加OneAPI的地址与鉴权参数，导致接口转发链路缺失配置。
- 现象：使用多字段表格的Webhook时，仅能接收单一条校准记录，无法同步多点测量的误差数据。原因：未开启接口的多行数据解析开关，导致循环节点生成的多组数据被截断为单条记录。

## 怎么确认配好了
- 调用FastGPT内置的测试接口，传入单台流量分析仪的校准记录数据，查看外部对接的实验室信息系统是否收到完整的字段与单位信息。
- 检查FastGPT的日志模块，确认接口请求的鉴权参数、变量映射规则均已正确加载。
- 触发一次完整的校准流程，查看外部系统是否同步生成对应的校准记录与溯源标识。
- 调整循环节点的拼接内容，验证动态变量是否能正确带入接口请求体。
