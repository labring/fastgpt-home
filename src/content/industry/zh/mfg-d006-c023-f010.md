# 工业仪器仪表制造与校准的检验与过程记录审核：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自流量、压力、温度、分析仪器制造商及计量实验室，核心文档包含装配调试单、校准规程、原始校准记录、误差曲线、计量证书、软件版本记录。数据来源覆盖设计文件、标准器监测数据、校准软件输出、实验室信息系统及客户量程要求，更新频率为每台仪器每次校准时生成新记录。单条校准记录包含仪器编号、校准日期、环境参数、误差值、溯源编号等字段，不同文档的字段格式与单位匹配仪器品类特性。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的文档多为单次校准生成的结构化与半结构化混合文档，高频更新的特性要求检索系统支持增量同步，避免数据滞后影响审核效率。分散的多源数据来源需要检索系统兼顾结构化字段匹配与非结构化语义理解，确保溯源链、误差计算等关键信息被准确召回。单台仪器的校准相关文档数量有限，但审核需覆盖全流程的规程、记录与证书，因此检索范围需精准绑定核心数据集，同时需过滤无关文档，避免干扰审核判断。此外，校准结果直接关联客户生产流程，召回的准确性直接影响审核通过率，需严格控制检索阈值与排序逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 校准记录的溯源信息、误差值匹配要求高，阈值过低会引入无关文档，过高会遗漏有效校准记录 |
| `limit` | `前8条` | 单台仪器的校准相关文档数量有限，过多会超出上下文窗口，过少无法覆盖多维度的校准要求 |
| `usingReRank` | 开启 | 校准记录的误差判断、溯源链验证需要精准排序，避免低相关文档干扰审核流程 |
| `searchMode` | 向量检索+关键词混合 | 既有结构化的仪器编号、校准日期字段，也有非结构化的误差曲线描述，混合模式能兼顾精准匹配和语义理解 |
| `datasetSearchUsingExtensionQuery` | 开启 | 用户输入的审核需求可能未明确提及仪器型号，通过扩展查询补充量程、校准标准等关键词，提升召回覆盖率 |
| `collectionIds` | 绑定校准记录、校准规程、计量证书三个数据集 | 这些是检验与过程记录审核的核心文档来源，可过滤非必要的无关数据 |

## 容易做错的三处
- 现象：调用工具时未显示知识库选择选项，原因：未在系统配置中绑定对应品类的数据集集合，或未开启数据集检索权限。
- 现象：重排模型部署后测试通过，但每次检索结果`usingReRank`返回false，原因：未将重排模型与对应校准类数据集绑定，或部署的重排模型未正确适配FastGPT的接口格式。
- 现象：在线聊天与API调用的检索结果差异显著，原因：API调用未携带正确的`collectionIds`参数，或未开启`datasetSearchUsingExtensionQuery`功能，导致检索范围与在线聊天不一致。

## 怎么确认配好了
- 检查数据集绑定：确认`collectionIds`参数指向校准记录、校准规程、计量证书三个核心数据集，无无关数据集混入，FastGPT v4.17.0版本支持批量绑定数据集集合。
- 验证检索阈值：输入包含仪器型号、校准日期的审核需求，核对返回结果的`similarity`得分是否落在预设区间内，确认无异常低得分的无关文档被召回。
- 测试重排功能：触发检索后查看返回结果的排序逻辑，确认高相关的误差曲线、计量证书文档排在前列，验证`usingReRank`功能正常生效。
- 对比调用结果：使用相同的查询文本和参数，分别通过在线聊天和API发起检索，核对召回结果的条数、相关性是否一致，确保API与在线聊天的检索配置同步。
