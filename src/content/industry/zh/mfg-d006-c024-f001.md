# 工艺变更与工程变更的检验与过程记录审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据由制造企业变更管理团队产生，来源覆盖PLM、ERP、MES、供应商资料、验证试验及客户特殊要求。日常文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本记录、工艺验证报告、生产切换计划、库存处置单及客户批准文件，每次变更触发不定期更新。数据字段包含变更编号、版本号、生效时间、影响范围、验证状态，无统一固定单位，随对应文档类型调整。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据来源分散且关联多系统，要求接口支持跨系统数据拉取与同步。文档类型多样且结构差异大，接口需适配不同字段格式的请求与响应。更新无固定周期，接口需支持按需触发。变更关联的验证、审批状态需实时同步，接口需保障数据一致性。出错后果影响生产与客户合规，接口需支持失败重试与异常告警机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | 携带 Bearer 令牌，有效期 7 天 | 保障接口访问权限，符合企业内部系统的安全规范 |
| `variables` | 绑定变更编号、生效时间为动态变量 | 适配每次变更的个性化参数，无需重复配置接口 |
| `responseData` | 过滤出变更状态、版本号字段 | 仅提取业务所需数据，减少传输与解析开销 |
| 接口超时时间 | 600 秒 | 覆盖跨系统拉取验证报告、客户审批文件的最长耗时 |
| 请求重试次数 | 3 次，间隔 60 秒 | 应对临时网络波动或外部系统短暂不可用 |
| 响应数据格式 | JSON 格式 | 适配多数企业PLM、ERP系统的标准数据交互格式 |

本配置基于FastGPT v4.17.0版本的接口功能实现。

## 容易做错的三处
- 接口返回`401 Unauthorized`状态码，且变更数据未同步。原因是`Authorization`令牌过期未更新，未配置令牌自动刷新机制。
- 同步的BOM版本字段为空，导致生产现场使用旧版本物料。原因是未在`responseData`中配置对应字段的提取规则，遗漏了BOM版本的映射配置。
- 接口调用超时触发失败，未生成异常告警。原因是未配置超时后的告警触发规则，无法及时通知变更管理团队处理异常。

## 怎么确认配好了
- 手动触发一次变更数据同步，检查接口返回的`responseData`是否包含变更编号、版本号等核心字段。
- 验证`Authorization`令牌过期后，接口是否返回正确的权限异常状态码。
- 模拟外部系统短暂不可用的场景，检查接口是否按配置的重试次数发起请求。
- 对比同步后的本地数据与PLM系统的原始数据，确认字段映射与数据一致性。
