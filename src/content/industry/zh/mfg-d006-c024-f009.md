# 工艺变更与工程变更的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据由制造企业研发、工艺、质量、生产、采购共同组成的变更管理团队产生，来源覆盖PLM、ERP、MES、供应商资料、验证试验及客户特殊要求。日常文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本文件、工艺验证报告、切换计划、库存处置单及客户批准文件。数据更新无固定周期，每次工艺或工程变更触发时同步更新，文档字段包含变更编号、版本号、涉及物料、验证结果等核心信息，无统一标准化单位，需按具体文档类型匹配对应字段规则。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入需适配不同系统的接口格式，避免数据同步异常或缺失。不定期的更新节奏要求配置需支持动态加载最新变更文档，防止使用旧版本数据进行审核，影响变更的时效性。文档类型多样且篇幅差异较大，需合理控制上下文长度，避免超出模型处理上限导致审核中断。核心字段无统一单位的特性，要求模型需针对单文档类型进行字段匹配，无法依赖通用字段规则完成审核。同时，变更审核的严谨性要求需限制模型输出的随机性，确保结果符合制造行业的合规标准。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配ECN、BOM等多文档的总长度，避免上下文溢出导致审核中断 |
| `maxTokens` | 3000–5000 token | 控制单轮输出长度，确保变更审核的详细反馈符合工艺文档的篇幅要求 |
| `quoteMaxToken` | 1000–2000 token | 限制引用源文档的内容长度，确保引用内容完整且不超出单页文档的标准范围 |
| `toolChoice` | auto | 允许模型自主调用工具完成跨系统数据查询，适配PLM、ERP等多数据源的联动需求 |
| `temperature` | 0.2–0.4 | 降低生成内容的随机性，确保变更审核结果的严谨性，符合制造行业的合规要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属地址 | 适配本地或云端部署的模型接入，满足制造企业数据本地化的安全需求 |

## 容易做错的三处
- 现象：模型输出中残留<think>标签或无法正确识别reasoning_c标记。原因：未按FastGPT v4.17.0的要求配置模型输出格式，未适配本地部署模型的特殊推理标记规则。
- 现象：配置多数据源后模型无法召回PLM中的BOM版本数据。原因：未正确设置`AIPROXY_API_ENDPOINT`指向内部数据源网关，导致跨系统访问权限不足。
- 现象：模型生成的变更建议与实际文档字段不匹配。原因：`temperature`取值过高，导致生成内容偏离既定的变更文档规范，影响审核准确性。

## 怎么确认配好了
- 发起模拟变更审核请求，检查输出内容中是否正确引用了对应ECN文档的编号与版本信息。
- 查看模型调用日志，确认未触发`maxContext`相关的上下文溢出报错。
- 测试多数据源接入流程，验证模型能否正确拉取PLM和ERP中的关联变更数据。
- 调整`temperature`参数至不同区间，对比输出内容的严谨性，确认符合审核要求。
