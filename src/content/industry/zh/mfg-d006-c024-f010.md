# 工艺变更与工程变更的检验与过程记录审核：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据由制造企业研发、工艺、质量、生产、采购共同参与的变更管理团队产生，日常文档包含ECN/ECR、变更评估表、图纸与BOM版本文件、工艺验证报告、生产切换计划、库存处置单、客户批准文件等。数据来源覆盖PLM、ERP、MES系统、供应商资料、验证试验记录及客户特殊要求文档，更新频率为不定期，伴随每次工艺或工程变更触发，文档多带版本号、生效日期、关联物料编码等字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类数据的多系统来源、不定期更新、多类型文档结构及版本化字段，要求检索召回环节需支持跨数据源关联匹配，优先召回最新版本的文档。文档包含图纸、BOM、验证报告等多格式内容，需适配不同类型文件的分块与嵌入规则。变更触发的不定期更新，要求检索链路支持增量同步机制，避免召回过时的旧版本文件。同时，变更需关联物料、工艺、检验的连锁影响，检索需精准匹配关联字段，确保召回内容覆盖变更涉及的全链条文档。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 该品类文档需匹配版本号、关联物料编码等精准字段，阈值过低会引入无关变更文档，过高则遗漏有效关联内容 |
| `limit` | 前8–12条 | 变更审核需覆盖全链条关联文档，该区间可平衡召回数量与上下文长度 |
| `searchMode` | 向量+关键词混合检索 | 该品类文档包含结构化字段与非结构化文本，混合检索可同时匹配语义与精准关键词 |
| `usingReRank` | 开启 | 多源召回的文档排序需结合语义相关性与版本新旧，重排可优化结果优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 变更需求常包含隐含关联，扩展查询可补充匹配未直接提及的关联文档 |
| `collectionIds` | 指定变更管理专属集合ID | 避免召回非相关的生产排程、库存常规文档，缩小检索范围 |

## 容易做错的三处
- 现象：检索结果中未包含图片格式的ECN文档，原因：私有部署环境未开启图片数据集支持配置，无法导入或召回图片类变更文档。
- 现象：无法查看单篇资料的历史调用日志，原因：未启用检索日志采集功能，调用记录未被系统留存。
- 现象：检索任务返回包含`$schema`字段的异常报错，原因：数据集内的文档元数据存在非法的schema定义，导致嵌入流程解析失败。

## 怎么确认配好了
- 发起一条关联特定物料编码的检索请求，核对召回结果是否包含对应变更的ECN、工艺验证报告，确认检索范围与配置一致。
- 查看检索结果的排序，确认最新版本的文档排在前列，验证重排与相似度配置的作用。
- 检查系统日志，确认检索调用的记录已被正常采集，验证日志相关配置生效。
- 导入一张格式合规的图纸文档，确认可被成功索引并召回，验证数据集配置覆盖对应文件类型。
