# 工装夹具与检具制造的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
这个品类的核心数据来自汽车、航空、机械装配企业工装部门或专用工装供应商的业务流程，包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历等文档，数据来源覆盖产品数模与GD&T、工艺路线、三坐标数据、现场试用反馈、计量系统。数据更新按项目节点、每次产品变更、定期校准执行，单份文档包含专业几何公差、计量数值、工序步骤等专属字段，各文档结构随项目类型有所差异。

## 这些特征在「向量模型与索引」这一环带来什么约束
品类内文档包含多类型结构化与非结构化内容，既有包含GD&T几何公差参数的图纸元数据，也有纯文本的操作说明，不同文档的长度差异显著。数据更新无固定周期，需支持按项目动态新增索引。专业字段的语义关联性较强，需要模型准确捕捉几何基准与定位夹紧方案的对应逻辑。辅助数据如现场试用反馈的冗余度较高，需明确区分核心业务文档与非核心数据的索引范围，避免干扰检索结果。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面逻辑制定，适配工装夹具与检具制造的业务数据特征。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配夹具图元数据、验收报告的平均长度，避免单块内容过载 |
| `maxToken` | 4096 token | 匹配当前主流向量模型的输入上限，适配最长的变更履历文档 |
| 相似度阈值 | 0.72–0.85 | 过滤低关联的通用文档，保留与工装检验强相关的内容 |
| 单次搜索上限 | 前 8 条 | 符合现场检验人员的信息获取习惯，避免结果过多导致筛选负担 |
| `defaultToken` | 512 token | 作为短文本如校准记录的默认分块参数，保证小文档的语义完整性 |
| 重排 | 开启 | 修正原始相似度排序的偏差，优先展示与检验需求直接相关的文档 |

## 容易做错的三处
- 建立知识库时未适配向量模型格式，出现`undefined model`报错。原因是未将所选向量模型的名称按平台要求的格式填写，或未在模型白名单中添加对应模型。
- 检索结果排序不符合业务优先级，高相似度的非核心文档排在前列。原因是未开启重排配置，仅依赖原始向量相似度进行排序，未结合业务场景调整权重。
- 检索时因`maxToken`设置过小导致文档截断，关键几何参数丢失。原因是未根据品类内最长文档的长度调整`maxToken`参数，导致部分内容无法完整向量化。

## 怎么确认配好了
- 核对当前绑定的向量模型名称与配置项中的设置一致，确认模型支持当前文档的语义类型。
- 执行一次检索测试，验证返回结果条数不超过单次搜索上限的设定值。
- 上传一份测试用的辅助数据，确认检索结果中未出现该数据的关联条目。
- 检查`maxToken`参数是否覆盖当前最长文档的token数量，避免出现截断丢失关键信息的情况。
