# 工装夹具与检具制造的检验与过程记录审核：工具调用与插件

## 这个品类的数据长什么样
该品类的数据来源于产品数模与GD&T参数、工艺路线文件、三坐标测量数据、现场试用反馈及计量系统输出。日常生成的文档包括工装需求书、定位基准方案、夹具装配图、检具操作指导书、验收报告、校准记录与变更履历。数据更新按项目节点、每次产品变更触发，或按定期校准周期执行，文档字段包含基准公差、夹紧力参数、校准周期、变更版本号等，单位多为毫米、牛顿、天。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源包含工程数模、计量检测数据与现场反馈，格式差异大，要求工具调用支持解析GD&T参数、三坐标测量CSV等非标工程格式。数据更新无固定周期，需动态加载最新校准记录与变更履历，插件需支持按需拉取最新文档版本。文档字段多为毫米、牛顿等工程专业单位，工具需适配非通用文本的参数提取逻辑。同时因出错会导致批量加工超差，工具调用需增加参数校验与失败重试环节。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的插件与工具调用逻辑：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 自动匹配工装检验与记录审核所需的专用工具调用逻辑 |
| `functionCall` | `enabled` | 启用专用插件解析工程文档与计量数据 |
| 单次调用超时 | `120–180 秒` | 适配三坐标数据、GD&T参数解析的较长处理耗时 |
| 插件响应格式校验 | `开启` | 校验工程参数的单位与公差范围合法性 |
| 动态文档拉取 | `开启` | 按需加载最新的校准记录与变更履历 |
| 参数重试次数 | `2 次` | 避免单次解析或网络请求失败导致流程中断 |

## 容易做错的三处
- 调用工装校准数据的HTTP接口时无法正确解析Set-Cookie字段，导致后续请求无法获取接口权限，原因是通用HTTP请求插件未针对工程接口的会话机制做适配，默认未开启Cookie持久化。
- 插件调用后返回的校准记录条数仅为前2条，不符合该品类多批次数据的需求，原因是未调整插件的结果返回上限参数，沿用了通用场景的默认取值。
- 发起解析请求后出现超时错误，原因是未设置符合工程数据处理需求的超时参数，默认超时时长不足以完成三坐标数据的完整解析。

## 怎么确认配好了
- 发起一次工装夹具校准记录的解析请求，检查返回结果是否包含完整的校准日期、公差值与变更版本号字段。
- 调用专用插件解析GD&T文档，确认能正确提取基准公差、夹紧力参数并匹配毫米、牛顿等对应工程单位。
- 模拟一次API调用失败场景，检查是否触发预设的重试机制并生成可追溯的失败日志。
- 上传最新的工装变更履历，确认插件能自动拉取并关联最新的校准数据版本。
