# 工装夹具与检具制造的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
这个品类的日常文档包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历，数据来源为产品数模与GD&T、工艺路线、三坐标数据、现场试用反馈、计量系统。数据字段包含形位公差参数、三坐标测量值、校准周期、版本号等，单位涉及毫米、微米、小时等工程通用单位。数据更新按项目节点、每次产品变更、定期校准执行，无固定周期，单份文档内容跨度从单页图纸到数十页的多环节记录。本页面基于FastGPT v4.17.0编写。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据兼具结构化数值、半结构化工程文档与图纸，且更新无固定周期，单轮审核需关联多份历史校准、变更记录。因此模型接入需支持混合格式数据解析，上下文长度需适配多文档关联需求，同时需调用工具完成公差比对、数据校验等工程任务。工程类数据对输出严谨性要求较高，需限制模型生成的发散程度，避免因参数设置不当导致检验结果偏差。本地部署模型时需适配工程数据的token消耗规模，避免因上下文截断丢失关键形位公差、三坐标测量等核心信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启 | 需处理夹具图、检具操作书等带图纸的文档，提取图形标注、公差标注等关键信息 |
| `maxTokens` | 8000–12000 token | 单份工装审核文档包含GD&T参数、三坐标数据等长文本内容，需足够token生成完整审核结果 |
| `maxContext` | 10000–15000 token | 需关联多份变更履历、校准记录等历史文档，避免上下文截断导致关键信息丢失 |
| `quoteMaxToken` | 1500–2000 token | 提取文档中的关键校准记录、验收数据作为引用依据，确保审核内容有明确来源 |
| 工作流/API 工具选择配置 | auto | 需调用工具完成三坐标数据比对、公差计算等工程专属任务，提升审核准确性 |
| `temperature` | 0.2–0.4 | 检验审核需严谨的结果，避免生成过度发散或不符合工程规范的内容 |

## 容易做错的三处
- 现象：本地接入DeepSeek-R1:7B后测试返回`model response empty`，原因：未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或模型加载未完成。
- 现象：上传夹具图纸后，大模型输出未包含图纸相关分析内容，原因：未开启`vision`配置项，或上传的图纸格式不符合视觉模型的解析要求。
- 现象：API文件库上传至最后一步时出现异常，原因：未正确配置`AIPROXY_API_ENDPOINT`的路径格式，或URL包含多余空格导致接口调用失败。

## 怎么确认配好了
- 检查`vision`配置项是否开启，上传一份标准格式的夹具图纸，查看模型输出是否包含图纸标注、公差参数的分析内容。
- 调用本地部署的模型接口，验证`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`配置正确，查看接口返回是否有正常的模型响应。
- 上传包含多份变更履历的文档，核对模型输出是否关联了历史变更的关键信息，未出现上下文截断导致的内容缺失。
- 调整`temperature`至0.3左右，生成检验审核结果，查看输出是否符合工程严谨性要求，无过度发散内容。
