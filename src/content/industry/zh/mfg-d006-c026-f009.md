# 有色金属冶炼与电解的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
通常包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账等文档，数据来自精矿与辅料分析、DCS系统、槽电压电流监测、化验室、能源与环保监测系统。更新节奏按每批原料、每炉或每槽触发，部分实时监测数据更新频次更高。字段包含原料成分占比、炉温、槽电压电流、化验结果数值、环保排放指标等，多带百分比、电压、电流、质量等级等单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且更新节奏差异明显，部分监测数据实时更新，部分按炉槽批次生成，因此模型接入需适配多源异构数据的批量处理与实时调用逻辑，配置时需调整上下文窗口参数匹配不同更新频率的数据处理需求。同时文档包含专业检测数值与单位，模型需支持有色金属冶炼专业术语识别与格式校验，需调整参数提升长文本处理能力。此外数据关联逻辑复杂，原料成分、炉况、化验结果相互影响，需限制单次调用的上下文总量避免信息过载。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 该品类文档多为多批次多槽位的关联数据，需承载足够的历史记录与实时监测数据，避免关键校验信息被截断 |
| `maxTokens` | `2000–3000 token` | 检验与审核任务多为单批次或单槽况的校验，无需过长的生成内容，合理控制计算资源消耗 |
| `quoteMaxToken` | `4000–6000 token` | 需召回足够的配料单、化验报告等关联文档，覆盖原料成分、炉况参数等核心校验依据 |
| `toolChoice` | `auto` | 需根据任务自动选择调用文档检索或数据查询工具，适配多源数据的校验与关联分析需求 |
| `temperature` | `0.1–0.3` | 检验与审核任务需严谨的结果输出，避免生成内容出现随机偏差 |
| `AIPROXY_API_ENDPOINT` | 填写企业内部代理服务的实际部署地址 | 统一管理模型调用，适配企业内部网络环境与访问权限策略 |
| `AIPROXY_API_TOKEN` | 填写对应代理服务的访问密钥 | 保障模型调用的安全性，限制未授权的访问请求 |

## 容易做错的三处
- 模型调用返回“模型不存在或无法访问”报错，原因是未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或代理服务未同步对应模型的部署地址与访问密钥。
- 工作流中无法调用数据库或工具，原因是未正确设置`toolChoice`参数为`auto`，或未在配置中绑定对应的数据查询工具权限，导致工具调用被阻断。
- 审核结果出现关键信息截断，原因是`maxContext`取值过小，未适配该品类多批次、多文档关联的长文本处理需求，导致核心校验数据被遗漏。

## 怎么确认配好了
- 调用模型测试接口，输入包含配料单与化验报告的模拟文本，检查返回结果是否包含原料成分校验、炉况分析等对应内容，确认上下文加载正常。
- 触发工具调用测试，验证是否能自动检索关联的电解槽况记录与环保台账数据，确认`toolChoice`与工具绑定配置生效。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的请求格式正确，无401或404类访问错误。
- 调整`temperature`参数至0.2，生成多条审核结果，确认输出内容保持严谨一致，无随机偏差。
