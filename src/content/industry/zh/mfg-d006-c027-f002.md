# 服装裁剪与缝制的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自服装OEM/ODM、品牌供应链及裁剪缝制车间的日常业务流，包含工艺单、样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等文档。数据来源涵盖订单与尺码表、CAD设计文件、面辅料检验记录、吊挂系统工序数据、验针机检测结果及客户封样资料。数据更新随每笔订单、每款产品、每批次生产同步调整，无固定周期，且裁片相关数据不可逆，需严格匹配版型与工序要求。

## 这些特征在「向量模型与索引」这一环带来什么约束
品类内款式多、季节性强的特点，要求向量索引支持高频更新的小批量数据，避免单次索引过大导致服务器资源过载。裁片数据不可逆且人工工序密集，需确保每块chunk的语义与原始工序、版型要求严格绑定，防止拆分时丢失关键关联信息。多来源的异构数据（CAD图纸、文本单据、检测记录）要求索引适配不同格式的文本拆分逻辑，同时因出错后果严重，需保证检索结果的精准匹配，避免模糊召回导致质检疏漏。每订单每款的更新节奏，要求索引支持增量更新，避免全量重建的操作，降低重复索引的资源消耗。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配工艺单、工序质量表等文本的语义完整性，避免拆分破坏版型、工序的关联逻辑 |
| 重叠长度 | 100–200 字符 | 保留相邻工序、裁片描述的上下文关联，防止chunk间出现语义断层 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 8192 | 支持完整的排料图、包装配码单等长文本的向量化处理 |
| 单次搜索上限 | 前 10 条 | 覆盖多工序质检的多维度召回需求，避免遗漏关键瑕疵记录 |

## 容易做错的三处
- 现象：上传10M以上文件时被拆分为1000余块后，部分chunk向量化失败，反复点击重试后部分恢复但仍有残留异常。原因：品类内的CAD样板、排料图等文件包含大量非标准格式文本与图形注释，分块时未适配异构内容的语义边界，导致部分chunk无法被向量化模型正常解析。
- 现象：服务器因批量上传文件崩溃重启后，知识库无法自动完成索引，长期处于未就绪状态。原因：未开启增量索引的自动触发配置，且未设置定时扫描任务，重启后系统无法识别待索引的未完成任务队列。
- 现象：更新FastGPT版本后，原索引的知识库无法返回有效检索结果。原因：版本升级后向量模型的嵌入维度发生变更，原有索引的向量库与新模型的嵌入维度不匹配，导致检索时无法正确匹配语义特征。

## 怎么确认配好了
- 上传单份10M左右的工艺单文件，查看分块日志中的chunk数量与语义完整性，确认分块长度符合预设配置。
- 触发一次批量索引任务，监控服务器资源占用情况，确认未出现过载崩溃现象。
- 检索预设的质检关键词，对比检索结果与原始文档的匹配度，确认重排配置生效后结果排序符合业务逻辑。
- 重启服务器后查看知识库状态，确认自动索引任务是否正常启动，未出现卡滞现象。本流程适用于FastGPT v4.17.0版本。
