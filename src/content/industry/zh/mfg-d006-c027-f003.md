# 服装裁剪与缝制的检验与过程记录审核：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自订单与尺码表、CAD样板、面辅料检验记录、吊挂系统数据、验针机检测结果及客户封样。日常文档包含工艺单、样板、排料图、裁剪单、首件封样、工序质量表、包装配码单。数据更新以每订单、每款、每批为节奏，核心字段包含尺码规格、裁片数量、工艺要求、面料批次、包装配比等，裁片数据不可逆且随生产进度实时同步。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据按订单、款式、批次更新，多轮对话需通过`chatId`绑定对应生产批次的上下文，避免跨订单数据混淆。因核心文档包含多类工艺与质检字段，需通过`variables`传递当前订单的尺码表、工艺单等专属参数，确保审核提示词精准匹配当前款要求。裁片数据不可逆的特性要求每轮对话需校验当前环节的合规性，防止后续无法修正的偏差。同时款式多、季节性强的特点，要求提示词每次调用需明确绑定当前生产款的规则，避免跨款数据干扰。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定生产订单编号 | 区分不同订单的上下文，避免跨批次数据混淆 |
| `variables` | 传入当前款的工艺单、尺码表ID | 精准传递当前生产款的专属参数，无需重复录入 |
| `messages`上下文保留条数 | 前3轮有效对话 | 过滤冗余历史，聚焦当前审核环节的对话内容 |
| 单次对话最大token数 | 8000 token | 适配工艺单、排料图等长文档的内容输入 |
| 超时阈值 | 600 秒 | 等待多轮校验的工序数据同步完成 |
| 上下文输入上限 | 10000 字符 | 适配多份工艺文档的拼接输入 |

## 容易做错的三处
- 现象：工作流中前一个AI对话的回复作为第二个对话的输入，最终结果包含第一轮对话内容。原因：未在对话配置中设置上下文过滤规则，导致历史消息未被截断。
- 现象：工作流配置了http请求用于联网搜索，实际执行时直接调用AI对话。原因：未将http请求节点设置为前置触发节点，或节点间的流转逻辑配置错误。
- 现象：容器部署环境中无法调用语音输入相关工具。原因：未在容器权限配置中开放安装依赖的权限，或未正确挂载工具依赖包。

## 怎么确认配好了
- 新建一个测试订单的对话，传入对应款的`variables`参数，检查对话上下文是否仅关联当前订单的工艺要求。
- 触发工作流，查看节点流转日志，确认http请求节点先于AI对话节点执行并返回有效数据。
- 测试多轮对话，输入不同批次的质检数据，检查系统是否能正确区分不同批次的参数。
- 检查容器权限配置，确认依赖工具的安装路径正确且可被调用。
