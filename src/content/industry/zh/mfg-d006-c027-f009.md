# 服装裁剪与缝制的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据通常来自服装OEM/ODM车间、品牌供应链环节，日常文档包含工艺单、CAD样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等。数据来源覆盖订单与尺码表、CAD设计文件、面辅料检验记录、吊挂生产系统数据、验针机检测结果及客户封样资料。数据更新频率为每订单、每款、每批，不同订单的版型、工序要求、包装配比差异明显，单份文档字段包含尺码参数、面料规格、工序节点、检验标准等，无统一固定的字段格式，需适配多类型非结构化与半结构化数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的多批次、多款式特性要求模型配置需支持动态适配不同订单的字段规则，非结构化的工艺单、样板图片等数据需要模型具备视觉理解能力。频繁的订单级更新要求配置的上下文窗口可灵活调整，避免因固定上下文无法容纳单订单的全量工艺与检验数据。多来源的半结构化数据需要配置适配混合输入的参数，同时需兼容验针机、吊挂系统的标准化输出与手工填写的工序表的非标准化格式，避免模型无法正确解析字段差异。此外，裁片不可逆的业务特性要求审核环节的模型输出需具备高准确性，需严格控制生成结果的偏差范围。

## 配置怎么定
本页面适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启 | 该品类存在大量CAD样板、首件封样等图片类业务文档，需通过视觉模型解析图片内容 |
| `maxContext` | 8000–12000 token | 单订单的工艺单、排料图、工序质量表等文档总长度较长，需容纳全量业务上下文 |
| `temperature` | 0.1–0.3 | 检验与审核环节需输出严谨、无偏差的判断结果，降低随机生成概率 |
| `AIPROXY_API_ENDPOINT` | 按私有部署的代理地址填写 | 适配本地或私有部署的大模型服务，避免公网请求的延迟与安全风险 |
| `toolChoice` | auto | 自动适配文本与图片混合的输入场景，灵活调用对应处理工具 |

## 容易做错的三处
- 现象：离线接入reranker模型时提示`rerank error fastgpt`，原因：未将reranker模型的依赖包正确安装至FastGPT运行环境，或配置的模型路径与实际部署路径不匹配。
- 现象：上传服装样板图片后界面按钮无法触发，日志显示上传成功但无响应，原因：`vision`配置未正确关联视觉模型接口，或接口请求超时未设置合理时长。
- 现象：使用`bge-m3`类向量模型时语义检索值异常偏大，或通过curl请求部署的向量模型返回报错，原因：未配置正确的向量归一化参数，或输入文本与检索库的字段匹配逻辑不符合该品类多尺码、多工序的字段规则，或未正确配置请求头部与端口映射。

## 怎么确认配好了
- 上传单份服装工艺单图片，触发视觉解析，检查是否能正确提取版型、工序要求等关键信息。
- 输入某订单的尺码表与包装配码单文本，调用模型审核，检查输出的审核结果是否符合该订单的字段规则。
- 测试reranker模型接入，使用20条以上的业务文档片段作为输入，检查是否能正常返回重排后的结果且无报错。
- 测试向量模型接入，使用curl请求部署的向量服务，检查是否能正常返回向量结果，且无权限或连接错误。
