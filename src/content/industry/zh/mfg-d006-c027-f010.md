# 服装裁剪与缝制的检验与过程记录审核：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据通常来自服装OEM/ODM车间的订单与尺码表、CAD样板文件、吊挂生产系统、验针机数据与客户封样。日常文档包含工艺单、排料图、裁剪单、首件封样、工序质量表与包装配码单。数据更新频率为每订单、每款、每批，单份文档包含尺码、裁片数量、色批号、工序要求等字段，单位多为厘米、件数、米。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类款式多、季节性强，且裁片不可逆，要求知识库检索结果需精准匹配当前订单的工艺要求，避免批量偏差。数据更新频率高，需支持按订单、按款快速更新索引，避免旧数据干扰审核。文档包含CAD排料图等非结构化内容，需适配非文本字段的召回逻辑。同时工序拆分细致，检索需支持按工序编号、尺码等细分字段精准匹配，确保检验与审核环节的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 服装裁剪文档需精准匹配工艺要求，避免低相似度的无关排料图或工艺单混入结果，基于FastGPT v4.17.0版本的参数规则调整 |
| `limit` | 前8条 | 该品类单订单工序较多，需召回足够的关联文档，同时控制上下文长度，避免超出系统处理上限 |
| `searchMode` | `mixedRecall` | 兼顾文本关键词匹配（如工序编号）与语义匹配（如工艺要求），适配多类型文档的检索需求 |
| `usingReRank` | 开启 | 对召回结果二次排序，过滤掉与当前订单尺码、色批不匹配的内容，提升检索精准度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索词，覆盖工艺单中的缩写术语，提升非标准术语的匹配成功率 |
| `collectionIds` | 按订单归属车间指定 | 限定检索范围仅为当前批次的工艺、排料文档，避免跨订单数据干扰审核 |

## 容易做错的三处
- 检索结果中出现重复的裁剪单，且自定义切分的文档索引顺序与召回结果不符。原因是未正确配置去重逻辑，导致重复文档被同时召回，打乱原有索引顺序。
- 检索时返回请求超时报错，无法获取目标工艺单内容。原因是未限定`collectionIds`检索范围，一次性检索全车间的历史文档，超出系统处理阈值。
- 召回结果中混入其他批次的排料图，导致审核时出现尺码偏差。原因是未开启`usingReRank`参数，未对召回结果按订单专属字段进行二次过滤。

## 怎么确认配好了
- 上传一份测试用的裁剪单与对应排料图，发起检索，核对召回结果中是否包含目标文档，且重复文档仅出现一次。
- 查看检索日志，确认返回结果的条数符合`limit`参数的设定值。
- 手动调整`similarity`参数的取值区间，观察召回结果的数量变化，验证参数生效。
- 切换不同订单的测试数据，确认检索结果仅包含当前订单的相关文档，未混入其他批次内容。
