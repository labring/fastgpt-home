# 来料检验与供应商质量的检验与过程记录审核：工作流编排

## 这个品类的数据长什么样
该品类的数据来自采购订单、图纸与规格文件、供应商质保书、检验设备采集数据、历史质量台账及供应商门户。日常文档包含检验规范、抽样方案、来料检验报告、供应商审核报告、异常联络单、8D整改报告及让步接收审批单。数据更新随每批来料完成、每月或季度供应商评价、不定期专项审核推进。核心字段包含批次号、检验项、合格判定结果、抽样数量、供应商编码，单位涉及件、批次、工作日等。

## 这些特征在「工作流编排」这一环带来什么约束
多源分散的数据来源要求工作流配置多节点数据拉取与整合，适配不同数据源的调用逻辑。不定时的业务更新节奏要求工作流支持事件触发，匹配每批来料、月度评价等不同触发时机。多样的文档格式要求工作流集成多类型文档解析节点，确保各类业务文件均可被正确读取。核心字段的关联性要求工作流绑定`variables`中的批次、供应商等字段，保障跨节点数据一致性。异常处理的必要性要求工作流配置分支判断节点，区分合格与不合格流程，触发对应处理环节。质量控制对象来自外部且需兼顾生产保供与风险，不同于过程检验可直接调整自有设备参数，该品类工作流需聚焦外部供应商数据的整合与异常流转。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按业务事件触发（每批来料、月度评价节点） | 适配该品类不定时的业务更新节奏，避免无效执行 |
| `variables`绑定 | 绑定批次号、供应商编码字段 | 匹配该品类数据核心关联字段，确保跨节点数据一致性 |
| 分支判断节点 | 按合格判定结果分支 | 区分合格/不合格流程，触发对应异常处理或放行环节 |
| 节点超时 | 600秒 | 覆盖多源数据拉取、文档解析的常规耗时，按实测标定调整 |
| HTTP请求输出配置 | 开启上下文输出 | 确保http请求的返回结果可在工作流节点中查看，便于排查异常 |
| `nodeId`绑定 | `nodeId`绑定指定检验设备节点 | 精准调用对应设备的检验数据，避免跨节点混淆 |
| Python代码节点 | 按实测标定 | 用于自定义数据清洗、格式转换，适配该品类多样的文档处理需求 |

## 容易做错的三处
- 现象：HTTP请求节点的输出结果未在工作流对话中展示。原因：未开启上下文输出配置，导致节点返回数据未被纳入工作流可见范围。
- 现象：工作流循环体无法按批次遍历来料数据。原因：未正确绑定`variables`中的批次列表字段，导致循环触发条件不匹配。
- 现象：工作流节点执行超时报错。原因：未根据实际业务场景调整节点超时配置，超出预设阈值。

## 怎么确认配好了
- 触发一次模拟来料检验事件，核对工作流是否按预设分支执行合格或不合格流程。
- 查看HTTP请求节点的上下文输出，确认返回的检验数据是否正确展示。
- 检查`variables`绑定的字段是否与当前业务数据的核心字段一致。
- 运行Python代码节点，确认自定义处理逻辑是否按预期生效。
