# 来料检验与供应商质量的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
这个品类的数据涵盖多类业务文档与系统数据，日常文档包括检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告、让步接收审批单；数据来源包含采购订单、产品图纸与规格书、供应商质保书、检验设备记录、历史质量数据库、供应商门户数据。数据更新频率随业务场景变化：每批来料生成对应检验报告与记录，每月或季度开展供应商整体评价，不定期开展专项审核。文档字段包含批次号、供应商编号、检验日期、不合格项描述、整改措施等，无统一固定格式，部分文档需关联多维度数据完成溯源。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据特征对溯源环节带来多重约束：多源分散的数据来源要求溯源系统需同时关联采购订单、供应商门户、检验设备记录等多类数据源，避免遗漏关键信息；高频更新的业务数据要求溯源逻辑需实时匹配最新批次与评价数据，确保引用内容的时效性；多样的文档结构与非统一字段要求溯源规则需适配不同文档的专属字段，例如批次号、供应商编号等，无法依赖通用匹配逻辑；多维度的关联需求要求溯源结果需同时展示文档来源、更新时间与核心字段，支撑审核人员完成完整的质量追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | `8000–12000 token` | 来料检验相关文档单批数据量较大，需覆盖多份检验报告、8D报告等内容，避免截断关键溯源信息 |
| `responseData` | 开启并返回完整源数据片段 | 需精准展示来料批次、供应商编号等专属字段，支撑审核人员核对溯源细节 |
| `detail` | 开启 | 需展示引用文档的来源路径、更新时间，匹配供应商质保书、历史质量数据的更新节奏 |
| 单次召回引用条数 | `前3–5条` | 来料检验相关引用需聚焦核心批次、供应商信息，过多条目会增加上下文处理负担 |

## 容易做错的三处
- 现象：工作流中调用知识库工具后，返回结果未关联对应来料检验文档，核心字段为空。原因：未开启`responseData`配置以返回源数据，或未配置匹配批次号、供应商编号的专属检索规则。
- 现象：AI输出结果中出现未闭合的引用标记，后续自动修正为标准引号。原因：未开启`detail`配置的引用格式校验，或未匹配文档的标准引用字段格式。
- 现象：知识库检索超时，或单轮上下文被强制截断。原因：将`quoteMaxToken`设置为超出系统处理上限的数值，例如`50000 token`，超出FastGPT v4.17.0的单轮token承载范围。

## 怎么确认配好了
- 发起一次针对特定来料批次的模拟查询，检查返回结果中是否包含对应供应商的质保书、来料检验报告片段。
- 查看输出结果的引用标记，确认格式符合标准引号，无未闭合的异常标记。
- 查看单轮查询的上下文日志，确认token数未超过预设的`quoteMaxToken`上限。
- 测试工作流调用知识库工具，确认返回结果中包含批次号、检验日期等专属业务字段。
