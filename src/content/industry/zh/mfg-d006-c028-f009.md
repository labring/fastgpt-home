# 来料检验与供应商质量的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自采购订单、图纸规格、供应商质保书、检验设备、历史质量数据及供应商门户。日常处理的文档包括检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告及让步接收审批文件。数据更新节奏随每批来料产生新记录，每月或季度完成供应商评价，不定期开展专项审核。文档多包含批次号、检验项、判定结果、整改要求等字段，部分附带量化检验参数与单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散来自多类外部及内部系统，更新频率随来料批次、供应商评价周期波动，要求模型接入配置支持多源数据的快速同步与增量更新。文档包含结构化字段与长文本描述，部分存在跨页关联内容，需适配长上下文与结构化数据解析。检验与审核场景对结果准确性要求较高，需约束模型生成的严谨性，避免无关内容输出。数据更新的实时性要求会影响模型调用的频率与缓存策略。

## 配置怎么定
FastGPT v4.17.0版本支持以下模型接入配置项：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配来料报告、8D报告等长文档的上下文需求，避免截断关键检验信息 |
| `maxTokens` | 2000–3000 token | 满足检验判定、整改建议等输出内容的长度要求，避免生成不完整 |
| `temperature` | 0.2–0.4 | 降低生成随机性，保障检验结论的严谨性，符合质量审核的合规要求 |
| `quoteMaxToken` | 500–800 token | 限制引用文档的最大长度，避免冗余信息混入 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接入地址 | 适配多源数据对接的网络环境，保障数据传输稳定性 |
| `AIPROXY_API_TOKEN` | 绑定专属服务密钥 | 隔离不同场景的调用权限，保障供应商质量数据的安全 |

## 容易做错的三处
- 调用模型时返回Unexpected end of JSON input报错。原因是部分开源模型的API返回格式不符合预设规范，未正确闭合JSON结构，在使用chatglm2等开源模型时易出现该问题。
- 处理长文档如完整供应商审核报告时，生成内容答非所问。原因是`maxContext`配置值不足，无法承载长文本的完整上下文，导致模型丢失关键前置信息。
- 基于上传的QA知识库生成回复时，输出超出预设范围的额外内容。原因是未通过参数约束模型的生成边界，导致冗余信息输出。

## 怎么确认配好了
- 调用测试接口，输入单份来料报告的核心内容，核对模型返回的检验判定结果与文档内的实际参数是否匹配。
- 模拟多批次来料数据的批量调用，检查接口返回的JSON结构是否完整，无截断或格式错误。
- 调整`temperature`参数后，多次调用同一测试用例，确认生成内容的一致性符合场景要求。
- 对接供应商门户的数据源，验证增量更新配置下的新数据是否能被模型正常检索与解析。
