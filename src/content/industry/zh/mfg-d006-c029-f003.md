# 模具设计制造的检验与过程记录审核：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的典型主体为注塑、冲压、压铸模具企业及制造企业模具中心，日常文档包含模具设计任务书、DFM报告、零件图、加工工艺卡、试模报告、改模通知、模具履历。数据来源涵盖客户产品模型、模流或成形仿真、CAD/CAM、机加工与测量数据、试模样件，更新节奏按项目推进，每次试模或改模都会触发数据更新。文档字段包含模具编号、型腔数、材料牌号、脱模角度、试模缺陷项等，单位多为毫米、兆帕、件次等模具加工专业单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
模具设计制造的业务数据分散且迭代频繁，多轮对话需保留改模、试模的历史上下文，才能连贯开展检验与审核工作。不同来源的文档格式差异较大，部分CAD导出文本存在专业术语嵌套，提示词需适配模具行业的专业表述规则。每次试模或改模都会更新数据，对话上下文需绑定当前项目标识，避免关联无关项目的模具数据。检验环节需聚焦脱模、缩水、成形可行性等核心指标，对话逻辑需限制检索范围至当前项目的专属文档，防止冗余信息干扰审核结果。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 当前模具项目唯一标识字符串 | 绑定同项目的多轮对话历史，避免跨项目数据混淆 |
| `messages` | 保留最近15–20轮对话内容 | 适配模具改模迭代的多轮追溯需求，按实测标定 |
| `variables` | 注入模具编号、材料牌号、试模批次 | 精准匹配对应项目的工艺卡、试模报告等专属数据 |
| 最大上下文窗口 | 8000–12000 token | 承载CAD文本、工艺参数等多类文档的专业内容 |
| 单次召回上限 | 前5–7条 | 过滤冗余召回结果，聚焦当前检验环节的核心文档 |
| 问题优化 | 开启 | 自动优化专业提问的检索逻辑，适配模具行业术语规则 |

## 容易做错的三处
- 现象：通过API调用时，对话日志中出现未关联当前项目的模具文档标题。原因：未通过`variables`注入当前模具的唯一标识，导致检索范围覆盖全量知识库文档。
- 现象：多轮改模相关对话中，反复出现相同的脱模缺陷分析结论。原因：未限制`messages`的保留轮次，过多历史上下文导致检索结果重复匹配。
- 现象：上传10M以上的模具工艺卡文档后，对话响应超时。原因：未设置合理的最大上下文窗口，加载过多文档文本导致资源占用过高。

## 怎么确认配好了
- 发起包含当前模具编号的测试提问，核对返回结果仅匹配该模具的专属文档。
- 查看API调用日志，确认`chatId`参数已正确传入，未出现空值或错误标识。
- 发起多轮改模相关提问，核对对话上下文仅保留当前项目的历史内容。
- 上传10M以上的模具设计文档，核对对话响应未出现超时提示。
