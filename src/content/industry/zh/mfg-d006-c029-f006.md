# 模具设计制造的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
该品类数据主要来自客户产品模型、模流/成形仿真文件、CAD/CAM设计源文件、机加工与三坐标测量数据、试模样件检测记录。日常文档包含模具设计任务书、DFM报告、零件加工图、工艺卡、试模报告、改模通知、模具履历表。数据更新按单个项目推进，每次试模、改模或装配调试后都会新增或修改内容，文档字段包含模腔参数、材料牌号、缺陷整改记录等专属信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据来源分散且格式多样，包含结构化工艺卡、非结构化试模报告、CAD二进制文件等，要求引用溯源环节需适配多类型数据源的解析与分块规则。数据更新频率随项目迭代波动，单次试模或改模都会产生新的溯源节点，需确保索引更新与项目进度同步。不同文档的业务权重差异明显，模具履历表的历史改模记录、试模缺陷整改数据是审核核心依据，需在召回阶段优先匹配高权重文档内容。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `quoteMaxToken` | 800–1200 token | 模具设计文档单块内容较长，需保证引用片段完整覆盖工艺参数或缺陷整改记录 |
| 上下文召回条数 | 前6–8条 | 单个模具项目涉及设计、加工、试模多阶段文档，需覆盖全流程的溯源依据 |
| 溯源详情展示 | 开启 | 需向审核人员展示引用来源的文档类型、生成时间，匹配模具项目的追溯需求 |
| 引用来源排序 | 按文档业务权重 | 试模报告、改模通知等核心文档优先展示，符合模具审核的业务逻辑 |
| `responseData` | 包含sourceMetadata字段 | 需保留引用来源的文档ID、更新时间等元数据，用于后续溯源核查 |
| `detail` | 开启完整字段 | 展示引用片段的上下文内容，避免断章取义，适配模具审核的严谨性要求 |

## 容易做错的三处
- 现象：调整`quoteMaxToken`参数后，大模型能够召回模具知识库内容，但回答正文未展示任何引用来源。原因：未开启`detail`配置项，未将引用片段纳入大模型生成的上下文范围。
- 现象：调大上下文召回条数后，无法召回任何与当前模具项目相关的文档。原因：未按单个项目对知识库文档进行分组，导致跨项目的无关数据干扰召回匹配。
- 现象：API调用私人知识库时无法获取模具设计相关的溯源内容。原因：未正确配置`responseData`的返回字段，未开启元数据返回导致接口无法返回有效召回结果。

## 怎么确认配好了
- 发起包含模具工艺参数或试模缺陷的查询，检查回答正文是否附带引用来源的文档名称与生成时间。
- 调整`quoteMaxToken`参数后，验证引用片段的长度是否覆盖完整的工艺卡或试模报告内容。
- 通过API调用接口，确认返回结果包含`responseData`字段下的溯源元数据信息。
- 测试多次改模后的查询，验证召回的文档是否包含最新的改模通知与试模报告内容。
