# 模具设计制造的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档包含模具设计任务书、DFM报告、零件图、加工工艺卡、试模报告、改模通知、模具履历。数据主要来自客户产品模型、模流或成形仿真结果、CAD/CAM文件、机加工与测量数据、试模样件检测数据。数据更新按单个项目推进，每次试模或改模后均会产生新的记录与文档，各文档包含脱模角度、成形缺陷、装配精度要求等专属行业字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据多源且结构各异，包含结构化参数与非结构化报告内容，要求模型接入配置需兼容多格式数据解析。数据按项目迭代更新，每次试模或改模后新增记录，配置需支持动态关联最新的项目文档。模具专属字段如脱模角度、缩水率、装配精度等，要求配置中需优化模型对行业术语的识别能力。多环节的过程记录需关联校验，配置需保证上下文能覆盖完整的项目流程数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的参数逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配多份试模报告、加工工艺卡等长文档的上下文存储需求，覆盖完整项目流程数据 |
| `maxTokens` | `2000–3000 token` | 满足模具检验结论、改模方案等长输出内容的生成需求，避免输出被截断 |
| `quoteMaxToken` | `1500 token` | 限制单条引用文档的长度，避免过长内容干扰模型对模具专属参数的审核 |
| `temperature` | `0.2–0.4` | 降低随机输出概率，保证检验与审核结果的一致性与准确性 |
| 工作流/API 工具选择配置 | `auto` | 自动判断是否调用工具处理结构化数据的校验，适配模具参数的自动化审核 |

## 容易做错的三处
- 现象：本地部署后新增模型测试时返回403 status code (no body)。原因：未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`参数，导致请求未通过身份验证。
- 现象：对话模型无法识别文档中用空格分隔的模具参数，导致脱模角度、缩水率等字段识别错误。原因：提示词未明确指定空格作为参数分隔符，或未对结构化数据的格式做约束。
- 现象：模型生成的改模建议与历史加工工艺卡内容冲突。原因：`maxContext`设置过小，未加载完整的项目历史记录，导致模型无法关联之前的工艺要求。

## 怎么确认配好了
- 上传单份模具设计任务书与试模报告，触发检验审核，检查模型是否能正确识别脱模角度、缩水率等专属字段。
- 发起两次连续的模型调用，验证上下文是否能保留前一次对话中的检验结论与改模要求。
- 调整`temperature`参数后发起测试，检查输出结果的一致性变化是否符合预期。
- 配置身份验证参数后发起模型调用，确认无身份验证类报错。
