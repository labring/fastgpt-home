# 橡胶混炼与制品硫化的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自配方系统、原材料批次管理、密炼机、门尼与流变仪、硫化机及实验室检测环节。日常文档包含配方单、称量记录、混炼曲线、胶料快检报告、硫化工艺卡、模具使用记录、成品性能报告。数据更新频率为每车原材料批次、每批投料、每模次生产，单条文档包含原料配比份数、投料时间、温度曲线节点、硫化时长温度等字段，单位涵盖摄氏度、分钟、批次号、重量单位等。

## 这些特征在「向量模型与索引」这一环带来什么约束
高频次的按批次、按模次更新要求索引支持增量同步，避免全量重索引的资源消耗与耗时。多类型文档并存的结构，要求分块策略适配不同文档的长度特征，例如混炼曲线的时序文本与配方单的结构化字段需统一分块逻辑，避免关键信息断裂。数据间存在强关联，例如同一批次的称量记录与混炼曲线需在向量空间中保持关联，因此索引需保留文档间的批次关联元数据。同时，检验与审核环节对召回结果的置信度要求较高，需确保向量检索的匹配精度符合工艺判定标准，避免误判或漏判。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类单份文档的平均长度，涵盖混炼曲线的单段时序数据与配方单的完整字段组，避免分块过短导致向量碎片化 |
| 重叠长度 | 100–150 字符 | 保留相邻批次或同批次不同文档间的关联信息，避免分块断裂导致的关联丢失 |
| `defaultToken` | 2048 | 匹配该品类多数文档的token占用量，适配通用embedding模型的输入限制 |
| `maxToken` | 4096 | 覆盖长文档如完整混炼曲线的token需求，避免截断关键工艺数据 |
| 相似度阈值 | 0.75–0.85 | 区分合格与不合格工艺参数的匹配精度，适配检验与审核的判定要求 |
| 单次搜索上限 | 前 6 条 | 匹配该品类检验环节需参考的关联文档数量，避免冗余召回干扰判定 |

## 容易做错的三处
- 现象为调用embedding模型返回503错误，原因是未正确配置模型分组，默认分组未绑定可用的text-embedding模型。
- 现象为docker部署的FastGPT中索引任务持续处于运行状态无进度，原因是分块长度设置过大，单批次文档处理超时，未适配该品类高频更新的节奏。
- 现象为对话模型可正常调用但索引无进展，原因是未为索引环节单独配置专用embedding模型，误用了对话模型的参数导致向量生成失败。

## 怎么确认配好了
- 查看FastGPT v4.17.0的向量索引任务日志，确认每个批次的文档均成功生成向量并写入索引，无报错信息。
- 测试检索特定批次的配方单与混炼曲线，确认召回结果包含关联文档，匹配业务逻辑。
- 验证embedding模型调用的返回状态码为200，无超时或分组错误提示，根据业务需求调整相似度阈值的具体数值。
- 对比增量更新与全量更新的索引耗时，确认适配该品类每车、每批、每模次的更新频率。
