# 水泥熟料与粉磨的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
水泥熟料与粉磨场景的数据覆盖水泥企业矿山、生料、烧成、粉磨、质量和能源部门的日常业务文档，包括生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录与能源报表。数据来源涵盖在线成分分析系统、DCS控制系统、化验室、窑磨设备、原燃料台账与能源计量装置，更新频率包含实时、每班与每日三类，文档包含固定字段的数值类记录与灵活格式的操作类文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且更新节奏差异明显，实时DCS数据与离线化验报告需分别适配增量与批量索引需求。文档包含游离钙、比表面积、热工制度等工业专业术语，要求向量模型适配流程工业语义。多部门的业务文档关联需求，要求索引支持跨部门文档的联合召回。不同更新频率的数据需配置差异化的索引同步规则，避免数据滞后或索引冗余。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配生料配料方案、窑操作记录等长短不一的文档，平衡向量片段的语义完整性与索引存储效率 |
| 重叠长度 | 100–150 字符 | 保留跨块的配料参数、热工参数等关键关联信息，避免跨文档关联时出现语义断裂 |
| `defaultToken` | 按行业术语库校准 | 适配水泥工业专有名词的token拆分规则，减少专业术语的错误拆分 |
| `maxToken` | 4000–6000 token | 支持整合多份化验报告、能源报表的上下文，满足检验与审核的跨文档关联需求 |
| 单次搜索上限 | 前10条 | 平衡召回精度与检索效率，适配多源数据的批量审核场景 |
| 重排模型 | dengcao/Qwen3-Embedding-8B:F16 | 适配水泥行业专业语义，提升检验记录与审核标准的匹配精度 |

## 容易做错的三处
- 向量召回结果与专业语义匹配度偏低，原因是未适配水泥行业专业术语选择索引模型，仅使用通用向量索引导致游离钙、热工制度等关键词的匹配精度不足。
- 界面显示token统计异常，原因是未通过`defaultToken`校准专业术语拆分，导致专有名词被错误拆分。
- 索引存储占用超出预期，原因是未根据生料配料方案的文档长度调整分块长度，生成过多冗余的向量片段。

## 怎么确认配好了
- 查看FastGPT v4.17.0的索引更新日志，确认实时数据与离线文档的同步频率符合配置要求。
- 输入窑操作记录中的专业关键词，核对召回结果包含对应部门的业务文档，验证语义匹配精度。
- 调整分块长度参数，观察向量片段的生成数量变化，确认符合预期的存储效率。
- 查看token统计界面，验证专业术语的拆分结果符合校准后的规则。
