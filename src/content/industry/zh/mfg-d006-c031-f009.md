# 水泥熟料与粉磨的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来自水泥企业矿山、生料、烧成、粉磨、质量及能源部门，涵盖生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录与能源报表。数据来源包括在线成分分析系统、DCS控制系统、化验室数据、窑磨设备传感器、原燃料台账及能源计量装置，更新节奏覆盖实时、每班及每日。文档多为结构化表格与文本记录，字段包含物料配比、温度参数、强度指标、能耗数值等，单位涉及百分比、摄氏度、兆焦、兆帕等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入时适配多格式文档解析规则，保障不同来源数据的统一索引；实时、每班、每日的混合更新节奏，需要配置适配不同频率的向量同步触发机制，避免数据滞后或冗余；文档包含物料配比、温度参数、强度指标等多维度专业字段，要求模型索引时保留字段元数据以支撑精准审核；不同部门的文档关联度高，需配置合理的上下文关联规则，避免审核逻辑割裂；数据更新频率差异大，需匹配对应的召回与处理延迟阈值，保障审核时效性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配，需匹配平台各容器的运行逻辑：mongo存储会话数据、mysql存储系统配置、pg存储向量索引、oneapi作为模型代理服务。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配水泥生产多文档关联审核的上下文需求，覆盖生料、烧成、粉磨全流程关联数据 |
| `maxTokens` | 2000–3000 token | 保障单轮审核响应包含完整的化验报告、操作记录等关键内容，避免截断专业字段 |
| `quoteMaxToken` | 1500–2000 token | 限制召回文档的总token量，匹配水泥生产数据的单文档平均长度，避免冗余信息干扰 |
| `temperature` | 0.1–0.3 | 降低审核结果的随机性，保障质量控制指标判断的一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配不同模型服务的接入地址，支持Azure OpenAI、qwen3-embedding-8b等多类型模型部署，需匹配oneapi等代理服务的配置 |
| `AIPROXY_API_TOKEN` | 按实际生成的密钥填写 | 保障模型接入的身份验证安全，需遵循平台要求的模型id命名规则，仅允许授权服务访问 |

## 容易做错的三处
- 配置`maxContext`取值过小，导致审核时无法召回完整的窑操作记录与配料方案关联数据，界面返回结果字段为空，原因是未匹配水泥生产多文档关联的上下文需求。
- 未根据数据更新频率配置向量同步规则，导致实时生成的化验报告未及时进入索引，审核结果中出现历史数据，表现为返回结果条数与实际更新数据不符。
- 错误设置`temperature`为高于0.5的数值，导致审核时对强度指标的判断出现随机偏差，引发熟料质量判定不一致的问题，对应原燃料波动下配料调整的业务风险。

## 怎么确认配好了
- 上传单份生料配料方案与窑操作记录，验证模型能否正确召回关联文档，核对召回结果的文档类型与来源是否匹配预设配置。
- 模拟实时数据更新，检查向量索引的同步状态，确认更新频率符合预设的实时、每班或每日节奏。
- 发起多轮审核请求，核对响应结果的字段完整性与逻辑一致性，确认`maxContext`、`maxTokens`等参数未出现截断或冗余问题。
- 查看模型服务的调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无认证失败或超时报错。
