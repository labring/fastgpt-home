# 汽车整车总装的检验与过程记录审核：部署与升级

## 这个品类的数据长什么样
通常，汽车整车总装场景的检验与过程记录数据来源包括ERP/MES系统、VIN与配置系统、供应商批次管理系统、拧紧工具、EOL检测线及质量追溯系统。数据更新节奏为每车实时生成、每班汇总归档，涵盖生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录、一致性与放行文件等文档。单车辆数据包含数百项配置与零件匹配字段，字段格式包含17位VIN码、扭矩值（牛米）、检测结果标识等。

## 这些特征在「部署与升级」这一环带来什么约束
该场景的数据高频实时产生且字段复杂度高，部署时需适配高并发读写需求，因此需要配置高可用的数据库与缓存服务。混线生产模式下数据量波动幅度大，需预留足够的连接池容量应对峰值流量。多源数据接入要求部署时提前配置数据格式校验规则，避免无效数据写入。内网部署场景下无法拉取公开镜像，需提前导出所有依赖组件的镜像包。升级过程需采用滚动更新策略，防止停线影响生产节拍。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配汽车整车总装场景的部署需求。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 内网集群地址，连接池最大连接数设为`200 个` | 支撑每车实时产生的拧紧、检测数据高频写入 |
| `REDIS_URL` | 内存不低于`1000 MB`的内网缓存实例 | 缓存VIN与配置的匹配结果，降低重复计算开销 |
| `DB_MAX_LINK` | `150–250` | 适配混线生产时的并发连接波动 |
| `STORAGE_S3_ENDPOINT` | 内网对象存储的访问地址 | 存储下线检测报告、返修记录等大体积文档 |
| `FILE_TOKEN_KEY` | 随机生成的32位字符串 | 加密文件下载链接，防止未授权访问 |
| `FE_DOMAIN` | 内网服务访问的域名或IP地址 | 配置前端与后端服务的统一访问入口 |

## 容易做错的三处
- 部署rerank模型后前端模型列表无对应条目：docker-compose配置中未将模型容器端口映射至主机网段，或FastGPT服务与模型容器未处于同一内网网络。
- 选择v2版本模型但实际调用v1版本算力：配置文件修改后未重启FastGPT服务，或`FE_DOMAIN`参数未指向v2模型的部署地址。
- 内网部署后日志提示启动失败：导出的docker镜像未包含所有依赖组件，或内网环境无法访问必要的配置资源。

## 怎么确认配好了
- 访问`FE_DOMAIN`配置的地址，进入模型管理页面，确认已部署的rerank模型列表中存在对应条目。
- 发起一次模拟VIN匹配查询，查看服务日志中数据库连接数是否处于`DB_MAX_LINK`配置的区间内。
- 上传一份下线检测报告，确认文件可正常存储并通过授权链接下载，验证`STORAGE_S3_ENDPOINT`配置生效。
- 修改任意配置项后重启FastGPT服务，等待10分钟后查看监控面板，确认数据库、缓存的连接状态正常。
