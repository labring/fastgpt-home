# 汽车零部件批量制造的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来源包括客户图纸与特殊特性清单、ERP/MES系统、量检具、设备过程参数及供应商质保书。日常文档涵盖控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料与8D报告。数据更新节奏为每批、每班或持续采集，单条记录包含零件编号、工序编号、检测数值、时间戳与批次号等字段，部分文档附带公差要求与单位信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据来源分散且格式多样，包含结构化报表、非结构化作业文档与实时采集的设备参数，要求向量模型与索引支持多源数据的统一向量化与存储。高频更新特性要求索引支持增量同步，避免全量重建带来的性能损耗。单批次数据包含精密公差、检测数值等带单位的字段，需确保向量化时保留关键属性的语义关联。同时受整车客户质量体系约束，检索结果需严格匹配特定工序与批次范围，索引需支持按批次、零件编号的精准过滤。

## 配置怎么定
FastGPT v4.17.0 版本下的配置参考如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配作业指导书、SPC报表等文档的单段语义完整性，避免跨工序信息混淆 |
| 重叠长度 | 100–150 字符 | 保留相邻块间的工序关联信息，防止检测流程的上下文断裂 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非相关记录，适配精密制造场景下的高匹配精度要求 |
| 单次搜索上限 | 前 20 条 | 平衡检索效率与结果覆盖度，满足批量审核时的多记录参考需求 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 现象：导出知识库生成的dataset.csv仅含index字段，无content字段。原因：未正确配置分块后的文本提取规则，仅同步了索引元数据而未抓取原始文档内容。
- 现象：检索结果返回大量不相关的跨批次记录。原因：未设置按批次、零件编号的过滤条件，未利用索引的结构化字段关联能力，导致审核时出现批量不良风险。
- 现象：嵌入任务出现token超限报错，返回状态码413。原因：未设置`maxToken`限制，长文档的向量化超出模型上下文窗口。

## 怎么确认配好了
- 随机抽取单批次的首件记录与SPC报表，执行检索验证，确认返回结果包含对应工序与批次的文档内容。
- 检查索引存储的字段完整性，确认已同步零件编号、批次号等结构化元数据。
- 测试增量更新流程，提交新的巡检记录，验证索引是否自动同步更新。
- 调整相似度阈值与单次搜索上限，匹配业务场景下的检索精度与效率要求。
