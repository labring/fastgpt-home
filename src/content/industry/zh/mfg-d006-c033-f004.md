# 汽车零部件批量制造的检验与过程记录审核：工作流编排

## 这个品类的数据长什么样
这个品类的主体为制动、转向、底盘、内外饰和动力系统零部件供应商，日常文档包含控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料、8D报告。数据来源包括客户图纸和特殊特性清单、ERP/MES系统、量检具、设备过程参数、供应商质保书，更新频率为每批、每班或持续采集。数据字段包含特殊特性参数、批次编号、检测数值、设备运行状态等，单位涵盖毫米、牛米、批次号等标准化工业参数格式。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的接入要求工作流配置多节点对接不同系统，避免数据遗漏或格式不统一。高频更新的业务数据要求节点触发条件匹配每批、每班的生产节奏，确保流程仅在有效数据生成后启动。多样的业务文档要求工作流适配不同格式的输入，同时保留完整的追溯字段以满足整车客户的质量体系要求。批量一致性的业务目标要求工作流包含异常校验节点，确保每批次零部件的检验参数统一。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 系统配置节点Base URL | 对应企业内部MES系统的API根地址，格式为`http://[域名]/api/v1` | 对接业务数据源的标准配置要求 |
| HTTP响应JSONPath提取规则 | 按业务字段层级配置，例如`$.inspection.batchNo` | 精准提取批次号与检测数值等核心字段 |
| 变量定义`variables` | 按批次、检测项、异常类型分类，最多20个变量组 | 区分不同零部件品类的检验参数，便于下游节点调用 |
| 节点触发条件`nodeId` | 绑定首件检测完成节点的ID | 确保流程仅在首件合格后启动批量检验流程 |
| 工作流导出设置 | 勾选完整日志与变量记录，导出文件大小不超过1000 MB | 满足整车客户的质量追溯与合规要求 |
| 问题分类节点背景知识 | 导入控制计划与特殊特性清单的结构化内容 | 匹配业务场景的分类规则，提升分类准确率 |

## 容易做错的三处
- 现象：系统配置节点报错提示连接超时，或无法获取业务数据。原因：未正确填写Base URL，或未配置对应系统的访问权限，未匹配FastGPT v4.17.0的API对接规范。
- 现象：HTTP请求节点提取的变量为空，下游节点无法正常调用。原因：未正确配置JSONPath提取规则，或未在`variables`中声明提取的变量，导致变量未被系统识别。
- 现象：工作流导出后无法在其他产线复用，或缺少关键追溯字段。原因：未勾选完整日志与变量记录的导出选项，未将特殊特性字段纳入`variables`配置。

## 怎么确认配好了
- 触发首件检测节点，检查工作流是否按配置的`nodeId`自动启动后续批量检验流程。
- 向HTTP请求节点发送模拟检测数据，验证是否能通过JSONPath提取到正确的变量并传递到下游节点。
- 导出工作流配置，检查是否包含所有配置的`variables`与节点设置。
- 在测试环境导入工作流，验证是否能正常运行并生成符合业务要求的检验记录。
