# 汽车零部件批量制造的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
该品类数据来源包括客户图纸、特殊特性清单、ERP/MES系统、量检具读数、设备过程参数及供应商质保书。日常文档涵盖控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料与8D报告，数据按每批、每班或持续采集更新。文档字段包含特殊特性编号、工序参数、检验结果、批次号与时间戳，单位涵盖毫米、牛米、批次编号等工业标准单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源分散的数据要求溯源必须精准绑定至具体批次与工序，避免跨批次混淆导致的批量不良追溯失误。高频更新的实时数据需要检索系统支持近实时同步，确保引用内容与当前生产状态一致。多样的文档结构需要系统适配不同格式的字段提取，确保特殊特性、检验结果等核心质量信息完整。受整车客户强约束的质量体系要求，引用溯源必须可追溯至原始文档与采集节点，无法省略关键元数据，否则无法通过客户审核。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1800 token | 适配批量制造文档的单块平均长度，避免截断关键特殊特性字段 |
| `responseData` | 包含批次号、工序ID、检验时间 | 满足溯源需要的核心元数据字段要求 |
| `detail` | 开启 | 展示完整的检验记录原文，符合客户质量体系审核的可追溯要求 |
| 单次搜索上限 | 前10条 | 匹配批量生产的多工序检验数据规模，避免冗余信息干扰 |
| 分块长度 | 800–1200 字符 | 适配控制计划、SPC报表的段落结构，确保字段完整性 |

## 容易做错的三处
- 现象：设置`quoteMaxToken`为1500，仍有超1500字符的块被引用。原因：系统按分块后内容匹配，仅限制总上下文token数，未限制单块引用的字符上限。
- 现象：知识库检索到匹配内容，但AI对话仅返回引用标识，未展示具体检索结果。原因：未在工作流中配置将检索结果传入AI对话的输入字段，导致对话环节无法获取具体内容。
- 现象：创建插件后在其他工作流引用时点击输入报错。原因：未正确配置插件的输入参数映射，未将知识库检索的输出字段绑定至对话环节的输入。

## 怎么确认配好了
- 上传单份PPAP资料，发起包含特定特殊特性查询的提问，检查返回结果中是否包含完整的引用来源文档名与批次号。
- 调整`quoteMaxToken`为不同区间，验证返回引用内容的截断情况是否符合预期设置。
- 运行包含检索-HTTP处理-AI对话的工作流，检查对话环节是否携带检索到的元数据信息。
- 查看FastGPT v4.17.0的系统日志，确认检索请求中携带的配置参数与手动设置一致。
