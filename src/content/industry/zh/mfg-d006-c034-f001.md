# 烘焙与方便食品的检验与过程记录审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
烘焙与方便食品的检验与过程记录涉及面包糕点、饼干、方便面和速冻面点工厂。日常需处理的文档包括配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量系统、烤炉或油炸线、实验室检测设备、食品追溯台账。数据按每批、每班或每日更新，核心耗时环节包括复核配方与过敏原物料、控制醒发或烘烤油炸窗口、核对异物控制结果与包装日期保质期。因产品直接食用且换线频繁，过敏原与清洁切换的校验需求更为突出，出错后可能引发口感不合格、过敏原错标、产品召回等问题。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的多源数据来源、高频次批次更新与严格校验需求，给HTTP接口与外部系统对接带来多重约束。频繁的产线换线要求接口支持动态绑定批次专属参数，避免复用旧批次配置；多系统数据同步需接口兼容不同数据源的格式与返回节奏，适配烤炉、实验室等设备的数据上传延迟；过敏原与清洁校验的高优先级要求接口强制校验必传字段，减少不合格数据流入审核流程；直接食用的产品属性要求接口返回的数据需经过严格合规校验，确保无违规内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | `Bearer {工厂专属API密钥}` | 对接ERP、称量系统等外部系统时的身份校验 |
| `variables` | 绑定生产单号、过敏原清单、烘烤窗口阈值 | 适配频繁换线的批次动态参数需求 |
| `responseData` | 仅返回校验通过的字段与批次唯一标识 | 减少无效数据传输，降低系统负载 |
| 接口超时时间 | 30–60 秒 | 等待烤炉、实验室检测数据的返回时长 |
| 必传字段校验 | 强制包含过敏原清单与包装日期早于保质期72小时以上 | 匹配该品类的核心校验需求 |
| 接口重试次数 | 2次 | 应对临时网络波动导致的接口调用失败 |

## 容易做错的三处
- 调用对接的MES系统接口时返回`408 Request Timeout`，原因：未设置匹配生产数据返回节奏的超时时长，等待烤炉曲线上传的时间超出默认限制。
- 批量提交生产记录时部分批次的过敏原字段缺失，原因：未在`variables`中配置过敏原清单为必传参数，导致换线时遗漏关键校验项。
- 调用实验室金属检测数据接口后返回结果条数与实际批次不符，原因：未通过`responseData`过滤无效数据，导致冗余的历史检测记录混入当前批次。

## 怎么确认配好了
- 调用测试用的生产批次接口，检查`Authorization`参数是否被正确携带，返回的身份校验结果为通过。
- 提交一组包含过敏原清单的测试数据，检查`variables`参数是否被正确绑定到当前批次的审核逻辑中。
- 触发一次接口调用，检查`responseData`返回的字段仅包含当前批次的有效数据，无冗余历史记录。
- 模拟临时网络中断后重试接口，确认重试机制正常触发且未重复提交重复数据。
