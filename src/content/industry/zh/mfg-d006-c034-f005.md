# 烘焙与方便食品的检验与过程记录审核：工具调用与插件

## 这个品类的数据长什么样
该品类数据主要来自面包糕点、饼干、方便面及速冻面点工厂的原辅料合格证明、ERP/MES系统、称量设备、烤炉/油炸线、实验室与食品追溯台账。日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据按每批、每班或每日更新，字段包含过敏原物料清单、烘烤/油炸窗口参数、异物检测结果、包装日期与保质期等。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的多批次快速换线需求，要求工具调用支持快速切换不同产品的配方与生产记录数据源。过敏原管控与清洁切换的高频需求，要求工具能精准提取文档中的过敏原物料清单、消毒记录字段。多来源数据（ERP、设备日志、实验室报告）的异构性，要求插件适配不同格式的数据解析。按每批、每班更新的频率，要求工具调用能实时拉取最新生产与检验数据，保障审核的时效性。同时，出错可能导致食品召回，要求工具调用的结果需经过基础校验，避免遗漏关键字段。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 函数调用配置 | 强制开启 | 该品类审核需精准提取过敏原、生产参数等特定字段，强制开启可保障工具调用的稳定性 |
| 工作流/API 工具选择配置 | auto | 支持根据审核任务自动匹配对应文档的解析工具，适配快速换线的需求 |
| 单次工具调用返回条数 | 前3条 | 单批次审核涉及的文档数量有限，限制条数可避免上下文过载 |
| 工具调用超时时间 | 600秒 | 需整合多设备日志与实验室报告数据，较长超时可保障数据完整 |
| 最大上下文长度 | 8000 token | 适配多文档整合后的内容长度，保障审核信息完整 |
| 工具结果校验规则 | 按实测标定 | 不同产品的文档格式存在差异，需根据实际场景调整校验逻辑 |

## 容易做错的三处
- 现象：调用工具时返回Cannot read properties of undefined (reading)报错。原因：未正确配置工具调用的基础链路参数，导致工具请求无法正常发起。
- 现象：工具调用返回的结果未包含过敏原物料清单字段。原因：未针对该品类的文档结构配置对应的字段提取规则，导致关键信息未被识别。
- 现象：部署的LLM无法触发`functionCall`功能。原因：未开启LLM的工具调用支持开关，或代理配置未适配工具调用协议。

## 怎么确认配好了
- 手动上传一份该品类的生产记录文档，触发工具调用，核对返回结果是否包含预设的关键字段。
- 配置测试用的单批次审核任务，观察工具调用的返回时长是否符合预设的超时设置。
- 切换不同产品的配方文档，验证`toolChoice`是否能自动适配不同的文档解析逻辑。
- 检查工具调用的日志，确认`functionCall`的请求参数已正确携带，无缺失字段。
