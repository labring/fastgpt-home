# 烘焙与方便食品的检验与过程记录审核：引用来源与溯源

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
这个品类的典型主体为面包糕点、饼干、方便面与速冻面点工厂。日常产生的文档包括配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源涵盖原辅料合格证明、ERP/MES系统、称量系统、烤炉或油炸线、实验室检测数据与食品追溯台账。数据更新按每批、每班或每日进行，核心字段包含物料批号、温湿度参数、检测结果、包装日期与过敏原标注信息。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的多批次高频更新特征要求溯源环节支持按生产批次快速定位关联文档。过敏原与配方的强合规性需求，要求引用来源必须精准匹配对应物料的合格证明与生产记录，避免跨批次混淆。多文档关联场景下，需确保溯源结果可同时关联投料、检测、生产曲线等多类数据。此外，直接食用的属性强化了对异物、保质期等字段溯源的严谨性，需限制跨品类数据的无效引用，确保审核结果符合食品生产的合规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配单批次生产相关文档的总长度，确保完整召回溯源所需信息 |
| `responseData` | 包含文件名、批次号、检测结果字段 | 贴合工厂一线审核人员的快速查看需求，聚焦核心溯源内容 |
| `detail` | 开启 | 支持展开查看单份文档的完整内容，用于过敏原与配方的精准复核 |
| 单次搜索上限 | 前5条 | 覆盖单批次涉及的投料、检测、清洁等多类文档，避免冗余信息干扰 |
| 上下文召回窗口 | 24 小时 | 匹配该品类每班或每日的更新节奏，确保召回当日或当批的最新数据 |

## 容易做错的三处
- 报错提示`quote type error`，且无法正常返回引用内容。原因是输入的变量格式不符合配置要求，未正确绑定生产批次、文档类型等对应字段，导致系统无法识别溯源关联关系。
- 搜索结果仅返回单份文档，无法关联多类生产数据。原因是未配置按批次筛选的召回规则，导致召回范围覆盖全量文档，无法精准匹配当前审核批次的信息。
- 引用内容截断不完整，无法查看完整的烘烤曲线数据。原因是`quoteMaxToken`设置值过小，截断了单批次生产记录与检测报告的关联信息。

## 怎么确认配好了
- 上传单批次的配方、金属检测与生产记录文档，发起检验审核请求，查看返回的引用列表是否仅包含该批次的关联文档。
- 点击引用条目，确认是否可以展开查看完整的文档字段内容，无截断或缺失。
- 输入过敏原复核类问题，检查返回的引用是否包含对应原辅料的合格证明与投料记录。
- 查看系统日志，确认未出现`quote type error`类报错，且请求响应符合业务预期。
