# 烘焙与方便食品的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类数据覆盖面包糕点、饼干、方便面及速冻面点工厂的生产全流程，日常文档包含配方与投料单、生产记录、烘烤/蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源涵盖原辅料合格证明、ERP/MES系统、称量设备、产线传感器、实验室台账及食品追溯系统，更新节奏按生产批次、班次或每日触发，核心字段包含过敏原物料清单、工艺窗口参数、异物检测结果与保质期标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的多源异构数据、高频更新节奏与敏感字段属性，对模型接入配置提出明确约束。分散的ERP、产线传感器、实验室数据格式差异较大，需要配置适配多源数据解析的模型接入逻辑；生产批次与班次的高频更新，要求配置支持实时或准实时的数据同步规则；过敏原物料、工艺窗口参数等核心字段的高识别精度需求，需要调整模型参数以保障结果一致性；长时序的烘烤/蒸煮曲线文档，需要配置足够的上下文窗口以完整解析全量时序数据。

## 配置怎么定
本文适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单批次完整生产记录、烘烤曲线等长文档的上下文解析需求，覆盖多段工艺数据与字段校验 |
| `temperature` | 0.1–0.3 | 降低随机输出概率，保障过敏原识别、工艺参数核对等场景的结果一致性 |
| `maxTokens` | 2000–3000 token | 限制单轮输出长度，避免审核结果过长导致的解析异常，适配检验报告的结构化输出要求 |
| `quoteMaxToken` | 1500–2000 token | 限定引用源数据的最大长度，确保审核时能精准匹配配方与投料单的对应字段 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属端点 | 适配国内或海外部署的访问需求，保障数据传输的稳定性 |
| `AIPROXY_API_TOKEN` | 绑定专属访问密钥 | 限制接口访问权限，避免未授权调用引发的数据泄露风险 |

## 容易做错的三处
- 现象为钉钉接入时提示“接收消息地址校验失败”，原因为未配置公网可访问的端点，或未正确填写`AIPROXY_API_ENDPOINT`对应的公网地址，未按提示启用SSL证书校验导致匹配失败。
- 现象为模型输出的过敏原识别结果遗漏部分物料，原因为`temperature`参数设置过高，导致模型输出随机性增强，无法精准匹配配方中的敏感字段。
- 现象为长时序烘烤曲线的解析结果缺失中间时段数据，原因为`maxContext`参数设置过小，无法覆盖完整的时序文档内容。

## 怎么确认配好了
- 上传单批次完整生产记录文档，核对模型输出的过敏原清单与原始文档中的物料字段是否一致。
- 调用专属接口测试钉钉接入功能，确认接收地址可正常响应校验请求，无报错提示。
- 调整`temperature`参数至0.2，连续三次运行同一配方审核任务，核对输出结果的一致性。
- 上传长时序烘烤曲线文档，确认模型输出的工艺窗口参数覆盖完整的时段范围。
