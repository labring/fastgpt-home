# 热处理的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来自材料牌号档案、客户技术要求文档、温控仪表采集数据、炉温均匀性测试报告、硬度计与金相设备输出结果、工厂MES系统。日常产生的文档包括热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单。数据更新频率为每炉次或每生产批次，单份文档包含明确的工艺参数、检测数值与操作记录字段，部分文档附带时序化的温度变化数据。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的高频小批量更新、多源异构文档结构与时序化数据特征，对向量索引环节带来多重约束。每炉次的实时数据更新要求索引支持增量同步，避免全量重建的延迟。时序化的炉温曲线数据需要在分块时保留局部时序关联，避免拆分破坏温度变化的逻辑连续性。多源数据的格式差异要求向量模型适配不同字段的语义映射，同时索引需要支持混合类型数据的快速检索。单炉次数据的出错后果严重，也要求索引的召回精度匹配业务审核的需求。

## 配置怎么定
本页面配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配热处理工艺卡、检测报告的单段语义完整性，避免拆分破坏工艺参数的关联 |
| 重叠长度 | 100–150 字符 | 保留炉温曲线的时序跨块关联，防止温度变化逻辑被分块打断 |
| `defaultToken` | 8192 | 适配多段工艺参数与检测报告的总token长度，满足长文档的向量嵌入需求 |
| `maxToken` | 4096 | 适配单批次检索结果的token长度，避免超出向量模型的输入限制 |
| 相似度阈值 | 0.72–0.85 | 匹配热处理异常数据的语义相似度判定，过滤低相关性的历史记录 |
| 单次搜索上限 | 前 8 条 | 平衡检索效率与审核所需的历史数据覆盖范围 |
| 最大上下文 | 4000 字符 | 限制传入大模型的上下文长度，避免超出模型处理上限 |

## 容易做错的三处
- 提示401认证失败。原因是向量模型的接入密钥配置错误，或自定义渠道的请求路径未匹配模型官方接口规范。
- 知识库自动删除重复文档块导致索引顺序错乱。原因是未关闭系统默认的重复块去重开关，自定义切分的块顺序未被保留。
- 索引构建速度缓慢。原因是未配置合理的分块参数，或未启用批量索引构建的并行处理机制，导致单批次处理数据量过大。

## 怎么确认配好了
- 导入单份热处理炉温曲线文档，检查分块后的块数与预期一致，无跨块拆分的时序数据断裂情况。
- 尝试接入指定向量模型，发起一次检索请求，确认返回状态码为200且无认证报错。
- 开启重复块保留开关，导入自定义切分的文档，检查知识库中块的顺序与切分后的原始顺序一致。
- 模拟多炉次数据的批量导入，确认索引构建过程无超时或资源占用异常。
