# 热处理的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
热处理场景的业务数据来源于材料牌号档案、客户技术要求文件、温控仪表、炉温均匀性测试设备、硬度计、金相检测设备以及车间MES系统。数据更新节奏为每炉次、每批，单炉次关联的业务文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单。文档字段涵盖加热温度、保温时长、冷却速率、检测数值、时间戳等，单位包含摄氏度、分钟、兆帕等，部分文档为带坐标的图表格式。

## 这些特征在「引用来源与溯源」这一环带来什么约束
单炉次的业务数据具有唯一性，因此溯源环节需精准绑定唯一炉次标识，避免跨批次数据混淆。多类型文档的混合存在，要求溯源系统支持结构化文本与图表类数据的同时召回与展示。字段与单位的严格要求，使得溯源结果需匹配对应字段的单位与数值精度，确保审核的准确性。数据源来自多类设备与系统，需保证数据对接的稳定性，避免溯源时出现数据缺失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 按单炉次关联文档总字符数的1.2倍，按实测标定 | 单炉次关联文档包含工艺卡、炉温曲线、报告等，总字符量波动较大，需覆盖全量关联数据 |
| `quoteMaxToken` | 8000–12000 token | 单炉次关联文档的总token量通常处于该区间，避免截断有效溯源信息 |
| `responseData` | 开启结构化字段映射 | 热处理数据包含温度、时长等结构化字段，开启后可精准匹配溯源字段 |
| `detail` | 开启完整来源展示 | 需展示炉温曲线的时间戳、硬度报告的检测日期等细节，满足审核溯源要求 |
| 单次搜索上限 | 前6条关联文档 | 单炉次关联文档通常不超过6类，覆盖全量业务文档 |
| 重排 | 按文档关联炉次ID排序 | 确保同炉次的文档优先召回，提升溯源准确性 |

## 容易做错的三处
- 现象：生成的溯源结果中未包含炉温曲线的时间戳字段。原因：未开启`detail`配置项，导致仅返回文档标题未展示结构化细节。
- 现象：配置变量引用功能后，温度参数的设置按钮消失，无法调整参数。原因：在启用`responseData`映射时，未正确绑定温度字段的参数入口，导致配置入口被覆盖。
- 现象：搜索召回的文档跨多个炉次，无法精准定位当前审核批次的溯源数据。原因：未设置按炉次ID作为重排依据，导致召回结果混杂不同批次的文档。

## 怎么确认配好了
- 上传单炉次的全量关联文档，触发溯源查询，检查返回结果是否包含所有关联文档类型。
- 查看溯源结果的详情，确认包含温度、时间戳等结构化字段，且单位匹配业务要求。
- 测试跨炉次的文档查询，确认仅召回指定炉次的关联数据，无混杂情况。
- 在FastGPT v4.17.0版本中，调整`quoteMaxToken`的取值，检查是否会截断关键溯源信息。
