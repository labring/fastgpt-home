# 热处理的检验与过程记录审核：知识库检索与召回

## 这个品类的数据长什么样
该品类数据来源于材料牌号标准、客户技术要求、温控仪表、炉温均匀性测试报告、硬度计与金相设备检测结果、车间MES系统。日常文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单。数据按每炉次、每批更新，字段包含炉温区间（单位℃）、装炉重量（单位kg）、硬度值（单位HV或HRC）、保温时长（单位分钟）等，结构随文档类型差异明显，工艺卡多为流程化条目，炉温曲线为时序数据。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类数据按炉次批量更新，单炉次关联数据量小但更新频率高，需支持按炉次、批次快速定位目标文档。文档类型多样，结构化的工艺卡与时序类的炉温曲线需匹配不同检索逻辑，硬度、炉温等数值型字段需支持精确匹配与区间检索。客户技术条件与材料牌号关联紧密，需支持跨知识库关联检索。单条数据的专业术语密度高，需优化检索的语义匹配精度，避免无关结果混入。同时，异常处置单的时效性强，需优先召回近期的异常处理记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 匹配热处理专业术语的语义相似度，过滤低相关结果，避免误召回非目标炉次的工艺数据 |
| `limit` | `前8–12条` | 单炉次关联文档数量有限，控制召回条数避免上下文过载，适配车间审核的快速查阅需求 |
| `searchMode` | `semantic + keyword` | 兼顾工艺卡、装炉图的结构化关键词匹配与炉温曲线的语义时序匹配，覆盖多类型文档 |
| `usingReRank` | `开启` | 热处理数据专业术语多，重排可优化召回结果的排序精度，优先返回与当前审核问题最相关的炉温、硬度数据 |
| `datasetSearchUsingExtensionQuery` | `开启` | 自动扩展用户输入的材料牌号、工艺参数等关键词，匹配关联的客户技术条件与设备点检记录 |
| `collectionIds` | `按车间/产线分组配置` | 区分不同热处理产线的知识库，避免跨产线的无关数据被召回，适配多车间并行生产场景 |

## 容易做错的三处
- 检索结果为空且无报错提示。原因是未开启`datasetSearchUsingExtensionQuery`，无法扩展用户输入的材料牌号等关键词，导致匹配不到对应工艺卡数据。
- 对话中时而触发知识库检索时而不触发。原因是未固定配置`collectionIds`的分组范围，或未在工作流中添加强制检索节点，导致系统根据上下文自动判断是否触发检索。
- 单轮对话多次提问后检索耗时过长。原因是未限制`limit`的召回条数，且未开启重排结果的缓存机制，重复加载大量时序类炉温曲线数据导致延迟。

## 怎么确认配好了
- 输入某炉次的材料牌号，检查召回结果中是否包含对应的工艺卡与客户技术条件文档。
- 调整`similarity`的取值，观察召回结果的相关度变化，验证阈值设置是否适配专业术语匹配。
- 在工作流中添加强制知识库检索的节点，发起多轮连续提问，检查检索耗时是否稳定在合理区间。
- 切换不同产线的`collectionIds`配置，确认仅召回对应产线的热处理数据，无跨产线的无关结果混入。
