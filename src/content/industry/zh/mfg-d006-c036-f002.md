# 焊接结构件制造的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自钢结构、压力容器、工程机械和轨道车辆结构件制造企业的多类业务系统与台账。日常文档包含焊接工艺评定、焊接工艺规程、焊材领用记录、焊工资格记录、焊缝检验报告、返修单，字段含焊缝编号、焊材牌号、焊工证号、检测缺陷类型等，单位涉及毫米、千克、小时等业务常用计量标准。数据更新频率为每条焊缝或每批、每班，单条记录体量小但单批次批量高，来源覆盖设计、生产、检测全流程环节。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据分散于设计、生产、检测等多系统，要求索引支持跨数据源关联检索；更新频率为每条焊缝或每批、每班，高频小批量写入需适配增量更新机制；文档含焊缝编号、焊工证号、焊材牌号等结构化标识，向量检索需结合结构化字段过滤以提升准确性；单条记录体量小但总数量庞大，分块策略需适配短文本特征，避免无效索引冗余。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| :--- | :--- | :--- |
| 分块长度 | 800–1200 字符 | 适配本品类短文本为主的焊接类文档，避免分块破坏焊缝编号、工艺参数等关键信息完整性 |
| 重叠长度 | 50–100 字符 | 弥补短文本分块的上下文断裂问题，确保焊缝检验记录的连续语义关联 |
| `defaultToken` | 2048 token | 匹配多数焊接文档的平均语义长度，平衡检索精度与资源占用 |
| `maxToken` | 4096 token | 覆盖完整的焊接工艺评定文档长度，避免截断关键判定依据 |
| 相似度阈值 | 0.75–0.85 | 适配焊接类文档的专业术语匹配精度，过滤低相关性的历史记录 |
| 单次搜索上限 | 前10条 | 控制检索结果体量，适配焊缝检验审核的单批次核验需求 |

## 容易做错的三处
- 现象为导入的知识库未按预设规则提取焊接工艺、焊缝检验等目标内容，混入无关文档片段。原因是未配置合理的分块与字段过滤参数，导致系统抓取了文档中非审核相关的冗余内容。
- 现象为检索结果条数超出预期，单次返回超过预设数量的记录。原因是未设置单次搜索上限，导致系统返回过多低相关性的历史焊接记录，增加审核负担。
- 现象为向量数据库连接超时，检索响应耗时过长。原因是未适配本品类高频更新的数据集，未开启增量索引更新，导致全量索引扫描占用过多资源。

## 怎么确认配好了
- 上传单份典型焊接工艺规程文档，检查分块后的向量索引片段是否包含焊缝编号、焊材牌号等关键字段。
- 提交一条焊缝检验审核的查询语句，核对检索结果的条数是否符合预设的单次搜索上限要求。
- 导入一批连续更新的焊材领用记录，检查增量索引是否能及时同步新数据，无遗漏或重复。
- 查看向量数据库的资源占用情况，确认检索响应耗时未超出业务允许的范围。
