# 焊接结构件制造的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
焊接结构件制造的检验与过程记录数据，来源涵盖设计图纸、材料质保书、焊接设备参数、焊材库、无损检测系统、人员资质台账。数据更新按每条焊缝或每批、每班执行，核心文档包括焊接工艺评定、焊接工艺规程、焊材领用记录、焊工资格记录、焊缝检验报告、返修单。每份文档包含专属字段，如焊缝编号、焊材批号、焊工证号、无损检测结果、返修次数等，单份文档关联多条焊缝或单批次生产数据。

## 这些特征在「引用来源与溯源」这一环带来什么约束
单条焊缝关联多份分散在不同系统的文档，要求溯源系统需精准匹配关联字段，避免召回范围过大。高频更新频率要求溯源系统支持实时或近实时同步数据，确保引用的文档为最新版本。刚性约束的资质与工艺字段，要求溯源结果必须严格匹配焊工资质、工艺评定的合规性，不能出现错配。多源数据的分散存储，要求溯源系统可跨系统调取对应数据来源，确保溯源链路完整。

## 配置怎么定
本页面基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 1200–1800 token | 匹配单份核心焊接文档的平均token长度，确保引用内容完整无截断 |
| `responseData` | 开启 | 用于返回溯源文档的完整元数据，包括文档来源、更新时间、关联焊缝编号 |
| `detail` | 开启 | 用于提取文档关联的焊缝编号、焊材批号等字段，精准限定召回范围 |
| 单次搜索上限 | 前8条 | 单条焊缝关联的文档通常不超过8份，避免召回结果冗余 |
| 最大上下文长度 | 4000–6000 字符 | 整合单条焊缝关联的所有文档的总长度，确保上下文逻辑连贯 |

## 容易做错的三处
- 现象：溯源结果中出现非关联焊缝的文档被召回。原因：未开启`detail`参数，未限定关联焊缝编号字段，导致召回范围覆盖全品类下的所有文档。
- 现象：工作流中上传文件时，无法正常触发溯源。原因：未按要求配置上传链接形式的文件路径，引用本地变量会导致溯源无法正常触发。
- 现象：返回的溯源文档字段为空。原因：未开启`responseData`参数，未配置元数据提取规则，导致无法获取文档的关联字段。

## 怎么确认配好了
- 导入单份焊缝检验报告与对应焊材领用记录，执行溯源查询，检查召回结果仅包含该焊缝关联的文档。
- 查看返回结果中包含`responseData`字段，确认包含文档来源、更新时间、关联焊缝编号等元数据。
- 调整`quoteMaxToken`参数配置，检查单份文档的引用内容完整，无截断情况。
- 测试关联多条文档的焊缝溯源，确认召回结果的文档均属于该焊缝的所有关联记录。
