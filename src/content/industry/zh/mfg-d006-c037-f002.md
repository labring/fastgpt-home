# 生产计划与车间排程的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来自制造企业ERP系统、工艺路线文档、设备产能台账、人员排班表、在制品库存记录与供应商到货通知。日常处理的文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单与交期变更单，字段涵盖订单编号、物料编码、产能数值、班次时段、交期日期与物料数量，单位涉及件、小时、天与千克等。数据更新频率随业务节奏变化，包含每日的产能与库存更新、每周的排程计划调整，以及订单变更、缺料或设备故障时的实时更新。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源且高频更新的数据要求索引支持增量更新，避免全量重建带来的性能消耗。文档类型包含结构化表格（如排产表）与非结构化文本（如工单），需要适配混合内容的分块逻辑，防止拆分关键工序关联信息。字段包含数字、日期与文本等多种格式，要求向量模型能够兼容混合字段的语义编码，确保检验审核时的匹配精度。同时，业务场景对召回内容的关联性要求较高，需限制无关数据的召回量，避免干扰审核判断。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配生产计划类文档的段落密度，避免拆分工单、排产表的关键工序信息 |
| 重叠长度 | 50–80 字符 | 保留跨分块的工序衔接信息，防止检验审核时遗漏关联逻辑 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的冗余排程数据，确保召回的内容与审核需求强相关 |
| 单次搜索上限 | 前6条 | 适配车间排程的多约束场景，避免召回过多无关工单或物料数据 |
| maxToken | 4096 | 适配生产计划文档的整体长度，确保完整传递排程约束与检验规则 |
| defaultToken | 1024 | 平衡单条召回内容的细节与上下文连贯性，适配工单、缺料清单的审核需求 |

## 容易做错的三处
- 索引后文档分段数异常增加，界面显示原始分块数与最终分块数不符。原因：未关闭自动分块优化开关，系统对排产表的表格结构重复拆分了单元格内容。
- 向量模型批量训练无法触发，仅支持单文件调整参数后上传。原因：未开启批量索引的批量训练开关，系统默认仅处理单文件的向量生成任务。
- 升级版本后原有可查询的排程数据无法召回。原因：新版本向量模型的分块规则更新，原有索引的分块逻辑与新规则不匹配，需重新生成索引。

## 怎么确认配好了
- 上传一份典型的周日排产表，查看分块预览界面，确认关键工序行未被错误拆分。
- 提交一个检验审核类查询，检查召回结果的分段数与预期一致，无重复内容。
- 触发一次增量索引，验证新增的交期变更单是否自动被纳入索引库。
- 查看向量模型的配置日志，确认maxToken与defaultToken的取值与预设一致。
