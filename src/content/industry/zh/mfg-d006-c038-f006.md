# 生物制品与无菌生产的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
该品类数据来自细胞库与种子批、过程分析系统、洁净区监测设备、MES、LIMS及设备完整性测试工具。日常文档包含细胞库或种子批记录、培养纯化记录、无菌灌装记录、环境监测报告、培养基模拟灌装记录、无菌检验报告及批放行资料。数据更新节奏为每批生产周期、实时监测数据及按固定监测计划更新，文档字段包含批次号、操作参数、检测结果、时间戳、设备编号等，单位涵盖摄氏度、菌落形成单位、时间单位等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的文档多为批次绑定的结构化与半结构化数据，且需严格关联特定生产批次，因此溯源环节需精准匹配批次号与数据来源。多源数据更新节奏差异大，实时监测数据与批记录需分别适配检索时效，避免检索到过期或不相关批次的数据。无菌生产的合规性要求数据不可篡改，因此溯源环节需验证数据来源的完整性与可追溯性，同时需处理跨系统数据的格式统一问题，确保不同来源的检测、过程记录可被统一关联。此外，该品类的审核需覆盖全流程数据，因此溯源环节需支持批量关联多类型文档，避免遗漏关键合规信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 8000–12000 token | 适配单批生产相关文档的总字符量，避免截断合规审核所需的关键数据 |
| `quoteMaxToken` | 500–800 token | 限定单条引用内容的长度，便于审核时快速定位核心信息 |
| 检索匹配阈值 | 0.85–0.90 | 精准匹配批次号、设备编号等关联字段，避免跨批次的无效关联 |
| `responseData` | 仅返回原始数据字段+批次号 | 确保溯源时可直接关联到对应生产批次的完整原始记录 |
| `detail` | 开启全字段溯源 | 覆盖检验、过程记录的所有合规字段，满足无菌生产的审核要求 |
| 单次召回上限 | 前10条 | 控制检索结果数量，减少冗余信息对审核的干扰 |
| FastGPT 版本 | v4.17.0 | 确保配置项的功能与当前系统兼容 |

## 容易做错的三处
- 现象：检索结果中出现非当前生产批次的历史数据，批次号与当前审核批次不匹配。原因：未设置精准的批次号匹配规则，导致检索范围覆盖了无关批次的文档。
- 现象：在自定义工作流中调用溯源工具时，无法通过变量绑定原始文档路径，仅支持上传固定链接。原因：未正确配置工具调用的参数规则，未开启变量引用权限。
- 现象：调用溯源工具时返回“数据格式不支持”的报错。原因：未按要求配置`responseData`参数，返回了非预设的字段组合，无法被审核系统识别。

## 怎么确认配好了
- 手动输入某一批次的批次号，检索对应文档，核对返回结果的批次号是否与输入内容完全一致。
- 调用溯源工具，查看返回的引用数据字段是否包含所需的原始记录与批次关联信息。
- 触发一次完整的检验审核流程，检查是否有冗余或不相关的引用数据被纳入审核范围。
- 验证自定义工作流中是否支持通过变量绑定文档路径，完成溯源工具的调用。
