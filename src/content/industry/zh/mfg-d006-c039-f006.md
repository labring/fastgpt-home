# 电机与发电机制造的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
该品类的数据来自电磁设计文档、铜线与绝缘材料批次台账、绕线设备运行日志、平衡机检测数据、电气试验台记录，以及ERP/MES系统的生产工单。日常文档包含绕组工艺卡、绝缘处理记录、动平衡报告、耐压绝缘测试记录、型式与出厂试验报告，字段包含匝数、线径、绝缘等级、不平衡量、耐压值、温升参数等，更新频率为每台产品或每批次生产后，每次产品型式变更时同步更新。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的数据分散于设备日志、系统台账与多类专业文档，溯源环节需实现跨数据源的精准关联。单台或每批次的更新频率，要求溯源匹配需绑定具体生产批次与对应工序记录。专业文档的特定字段与单位，要求引用识别需匹配绕组匝数、不平衡量、耐压值等专属参数。同时多重约束的业务特性，要求溯源覆盖绕线、绝缘、试验全流程数据，避免单一来源的片面性。

## 配置怎么定
本文适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 适配绕组工艺卡、试验报告等长文档的内容长度，避免截断关键参数 |
| `responseData` | 包含完整引用源 | 满足多环节检验记录的溯源需求 |
| `detail` | 展示原始字段 | 便于核对匝数、耐压值等专业参数 |
| 单次召回上限 | 前5条 | 覆盖绕线、绝缘、试验三大核心工序的关联文档 |
| 上下文拼接长度 | 按实测标定 | 适配多源数据的总长度限制 |

## 容易做错的三处
- 现象：调用接口后先返回引用列表，未直接展示回答正文。原因：未调整`responseData`的返回优先级配置，默认优先加载引用源数据。
- 现象：关联本地知识库后，引用列表显示正确但回答正文未包含知识库内容。原因：未开启`detail`参数的正文嵌入配置，仅召回源数据未拼接至回答。
- 现象：本地部署后无法调用知识库内容，引用列表第一条匹配正确。原因：未配置合理的上下文拼接长度，导致知识库内容超出截断阈值未被纳入。

## 怎么确认配好了
- 发起针对绕组匝数的查询，检查返回结果中是否包含对应工艺卡的引用源。
- 查看响应数据的结构，确认引用源与回答正文的关联逻辑符合配置要求。
- 模拟单台电机的检验审核查询，核对召回的文档是否覆盖绕线、绝缘、试验环节。
- 检查接口返回的参数是否匹配预设的`quoteMaxToken`取值，确认符合业务需求。
