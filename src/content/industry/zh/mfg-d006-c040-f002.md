# 电池PACK与储能系统集成的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
该品类主体为动力电池包、储能柜和BMS系统制造商，日常文档涵盖配组规则、BOM、焊接和扭矩记录、BMS刷写记录、绝缘耐压报告、EOL测试、系统配置清单。数据来源包括电芯分容数据、MES系统、焊接设备、扭矩工具、BMS软件版本、EOL试验台，更新频率为每包或每柜生成一次，每次BMS软件版本变更时同步更新。数据包含结构化数值字段、半结构化测试报告与长文本规则文档，单条数据的字段数量和格式随业务环节存在差异。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且格式多样，既有短时序的设备记录，也有长文本的配组规则，需适配不同长度的文本向量生成。更新频率高且单批次数据量较大，要求索引支持增量更新以避免全量重建的耗时。结构化字段的精确匹配需求较高，向量模型需保留数值与规则类文本的语义特征，避免因分块不当丢失关键业务信息。此外，单条数据的错误会直接影响后续审核结果，需确保向量索引的召回精度符合业务校验标准。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配电池PACK配组规则、EOL测试报告的常见长度，避免单块文本超过`maxToken`限制 |
| 重叠长度 | 100–200 字符 | 保留跨分块的上下文信息，确保焊接记录、扭矩数据的语义连贯性 |
| `maxToken` | 1024 | 匹配多数开源embedding模型的输入长度限制，适配该品类单条业务数据的平均长度 |
| 相似度阈值 | 0.75–0.85 | 平衡匹配精度与召回数量，满足绝缘测试、BMS配置的审核校验需求 |
| 单次搜索上限 | 前 8 条 | 覆盖该品类单批次审核所需的关联记录数量，避免冗余结果干扰判断 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 现象：上传Excel格式的BOM或焊接记录后，知识库分块后的片段数远超预期，消耗大量计算资源。原因：未按单条业务记录拆分数据，直接以整表或整行数据作为分块单元，导致单块文本超过`maxToken`限制。
- 现象：发起检验审核查询时，返回的匹配结果仅包含少量字段，无法关联到完整的电芯配组规则。原因：分块重叠长度设置过低，丢失了跨分块的关联信息。
- 现象：本地部署ollama模型后，向量索引生成失败，报错提示连接超时。原因：未在docker-compose.yml中开放向量模型的访问端口，或未正确配置`defaultToken`适配本地模型的上下文窗口。

## 怎么确认配好了
- 上传单条1000字符的配组规则文档，查看FastGPT v4.17.0后台的分块预览，确认片段数符合预期。
- 发起测试查询，输入「检查对应批次的电芯扭矩记录」，验证返回结果包含对应业务字段与关联信息。
- 上传新的BMS刷写记录，检查向量索引的更新日志，确认新数据已被正确索引。
- 调整相似度阈值，观察返回结果的数量变化，确认符合业务审核的匹配精度要求。
