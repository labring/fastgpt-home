# 电池PACK与储能系统集成的检验与过程记录审核：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据来自电芯分容数据、MES系统、焊接设备、扭矩工具、BMS软件版本记录、EOL试验台。日常文档包含配组规则、BOM清单、焊接与扭矩记录、BMS刷写记录、绝缘耐压报告、EOL测试结果、系统配置清单。数据更新频率为每台电池包或储能柜生成一次，每次BMS软件版本变更时同步更新。文档字段包含电芯分容参数、扭矩值、测试电压、BMS版本号等，不同厂商的文档格式存在细微差异。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散且格式不统一，多轮对话环节需分步调取不同设备、系统的记录，避免单次请求过载。高频更新的单包/单柜数据要求对话上下文仅加载当前批次的关联文档，防止历史数据干扰当前审核。不同厂商的文档字段存在差异，提示词需明确指定匹配当前批次的字段规则，避免跨品类或跨厂商的字段混淆。检验审核需核对多维度关联数据，多轮对话需按流程依次触发参数核对、记录校验、结果汇总环节，确保逻辑连贯。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前批次的电芯SN码+生产时间戳 | 确保同批次检验的对话上下文不与其他批次混淆，符合会话标识的校验需求 |
| `messages` | 限制上下文为当前批次的前10条对话历史 | 单批次数据关联项有限，过长上下文会导致提示词混淆，适配检验审核的短流程特性 |
| `variables` | 预定义当前批次的BOM编号、电芯SN码、测试电压阈值 | 快速调用批次专属数据，避免重复输入字段，提升审核效率 |
| 最大上下文长度 | 800–1200字符 | 适配单批次文档的总字符量，防止上下文溢出导致提示词失效 |
| 问题优化 | 按实测标定 | 不同厂商的文档格式差异较大，需根据实际场景调整问题拆解逻辑 |
| 对话日志持久化 | 开启 | 匹配免登录场景下的日志留存需求，避免用户端删除操作同步清除后台记录 |

## 容易做错的三处
- 现象：调用API时传入`chatId`参数，后台对话日志未显示对应标识。原因：未将`chatId`与当前批次的唯一标识绑定，系统无法识别会话归属。
- 现象：免登录链接用户删除对话后，后台日志同步被清除。原因：未开启对话日志持久化配置，导致用户端删除操作同步触发后台日志删除。
- 现象：工作流节点无法加载历史对话中的全局变量。原因：未在工作流中配置历史会话与当前批次的关联规则，无法调用对应批次的全局变量数据。

## 怎么确认配好了
- 发起测试请求，传入`chatId`参数，查看后台日志是否显示对应标识。
- 输入测试问题，查看对话上下文是否仅加载当前批次的文档数据，无历史无关内容。
- 检查预定义的`variables`参数是否包含当前批次专属字段，通过对话回复验证字段调用是否正常。
- 模拟免登录用户删除对话，查看后台日志是否保留对应记录，验证持久化配置是否生效。
