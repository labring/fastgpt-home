# 电镀与化学表面处理的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
该品类的典型主体为电镀厂、电子连接器与五金件表面处理车间，日常文档包含槽液分析记录、工艺参数卡、挂具记录、膜厚与附着力报告、危废台账、废水监测记录。数据来源涵盖客户表面处理规范、槽液化验结果、整流器运行数据、在线水质监测数据与危废管理台账，更新频率涵盖每槽次、每班及固定监测周期要求。文档字段包含pH值、温度、电流值、膜厚（单位μm）、重金属浓度等量化指标，以及工艺说明、异常处置记录等文本内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且更新频繁，要求索引支持增量更新以适配每槽次、每班的高频数据写入。文档同时包含量化指标与文本说明，要求向量模型兼顾结构化数值与非结构化文本的语义对齐。高风险的出错后果要求检索结果具备较高置信度，需严格控制召回阈值。此外，槽液状态与前处理数据为核心审核依据，需为相关字段配置合理的语义权重，避免与非核心数据混淆影响审核准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配槽液分析记录、工艺参数卡等单条文档的平均长度，避免块内关键信息割裂 |
| 重叠长度 | 100–150 字符 | 覆盖槽液成分、温度电流等跨块关联的核心参数，防止上下文断裂影响检索精度 |
| 相似度阈值 | 0.75–0.85 | 匹配镀层缺陷、超标排放等高风险审核场景的检索置信度要求 |
| 单次搜索上限 | 前 8 条 | 平衡检索效率与召回覆盖，适配高频的槽液异常排查场景 |
| `maxToken` | 4000–6000 token | 适配危废台账、季度废水监测报告等长文档的上下文拼接需求 |
| `defaultToken` | 1000 token | 适配单条槽液记录、挂具记录等短文档的基础检索上下文 |

## 容易做错的三处
- 现象：Docker打包镜像后向量检索得分全部一致，原因：未正确挂载本地向量缓存目录，导致模型调用参数被镜像封装覆盖，无法正常加载配置的检索规则。
- 现象：混合检索耗时超过10秒，原因：未关闭非必要的文档类型索引，同时未调整单次搜索上限适配槽液数据的小批量召回需求，导致冗余数据参与检索。
- 现象：索引构建任务长期停留在最后一组，原因：未配置增量更新触发条件，全量索引时未跳过已完成的槽次记录，导致重复处理已有数据造成阻塞。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的知识库管理界面中，上传一条异常槽液分析记录，检索后确认返回结果的得分存在明显差异，无全量一致的情况。
- 分别执行单向量检索与混合检索测试，确认混合检索耗时未超过单向量检索的2倍，符合商用场景的效率要求。
- 查看索引构建日志，确认任务无长期停留在某一组的情况，且进度随时间正常推进。
- 上传膜厚报告、危废台账等指定文档类型，确认知识库可正常识别并完成向量化处理。
