# 石油炼制的检验与过程记录审核：多轮对话与提示词

## 这个品类的数据长什么样
石油炼制的检验与过程记录审核相关数据来自DCS/APC控制系统、LIMS化验管理系统、罐区计量系统、原油评价数据库、设备管理系统与能源管理系统。数据更新节奏包含实时、每班、每日三类，日常文档涵盖操作规程、生产方案、物料平衡表、馏出口质量报告、联锁台账、交接班记录与变更管理文件。数据字段包含装置负荷、馏程数值、罐区液位、化验指标值等，对应单位包括MPa、℃、吨、ppm等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多系统来源的数据要求提示词明确指定数据的调用来源，避免混淆不同系统的指标。不同更新频率的数据需要在多轮对话中区分历史归档数据与实时采集数据的使用场景，确保审核逻辑的准确性。多样的文档类型要求提示词根据任务类型匹配对应文档，比如校验联锁台账需调用联锁文件，核算物料平衡需调取生产方案与计量数据。复杂的字段与单位要求提示词统一单位转换规则，避免因单位不一致导致的审核误差。同时，多装置耦合的业务特性要求多轮对话保留前序对话中的装置参数与协调逻辑，支撑跨装置负荷调整的审核。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 覆盖当班交接班记录、当日物料平衡表等多份核心文档的内容 |
| `variables` | 包含装置ID、化验批次号、当班班组标识 | 精准匹配对应炼油装置的实时数据与历史检验记录 |
| `messages` | 按数据来源分组展示上下文 | 区分DCS系统的工艺数据与LIMS系统的化验数据，提升审核准确性 |
| 对话超时时间 | 600秒 | 支撑复杂的多装置负荷协调与物料平衡核算的计算时长 |
| `chatId` | 绑定当班班组的唯一标识 | 保留同班组多轮对话的上下文，确保审核逻辑连贯 |
| 提示词模板 | 限定调用指定系统的字段与单位 | 统一数据格式，避免因单位或字段不匹配导致的审核错误 |

## 容易做错的三处
- 出现404 Invalid URL (POST /api/chat/completions)报错，原因是未正确配置FastGPT的大模型接口地址，导致对话请求无法到达目标服务。
- 工作流执行至AI回复后直接中断，原因是未在`messages`中配置下游流程的触发参数，导致对话上下文未传递至后续节点。
- 对话频繁超时，原因是未设置合理的超时时长，或多轮对话中调用了过多跨系统的数据查询，超出了预设的响应上限。

## 怎么确认配好了
- 检查`chatId`是否绑定了当班班组的唯一标识，确保同班组的多轮对话上下文可以连贯调用。
- 验证`variables`中包含的字段是否与当前炼油装置的实际数据字段一致，确保数据调用的精准性。
- 测试`messages`的分组逻辑，确认不同来源的工艺数据与化验数据可以被正确区分与调用。
- 调整对话超时时间，确保复杂的物料平衡计算可以在设定时长内完成。
