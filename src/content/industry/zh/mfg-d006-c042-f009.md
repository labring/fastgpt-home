# 石油炼制的检验与过程记录审核：模型接入与配置

本文适配FastGPT v4.17.0版本的模型接入配置逻辑。

## 这个品类的数据长什么样
该品类的数据来自DCS/APC控制系统、LIMS化验系统、罐区计量系统、原油评价数据库、设备管理系统及能源管理系统。日常文档涵盖操作规程、生产方案、物料平衡表、馏出口质量报告、联锁台账、交接班记录、变更管理文件等。数据更新节奏包含实时、每班、每日三类，不同类型文档对应不同更新周期，字段包含工艺参数、物料组分、设备状态、质量指标等，单位涉及温度、压力、流量、组分占比等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求接入配置适配不同系统的接口规范，实时类数据需支持低延迟调用以匹配工艺波动的响应需求。多类型文档的结构差异，要求配置适配不同字段的解析规则，覆盖步骤化的操作规程文本、量化的质量报告指标等格式。原油性质波动与多装置耦合的业务特征，需要配置足够的上下文长度承载跨装置关联数据。不同更新频率的数据源，需配置适配实时/批量数据的触发逻辑，避免数据过载或滞后影响模型调用的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配炼油多装置耦合的跨环节关联数据，承载交接班记录、物料平衡等长文档内容 |
| `maxTokens` | 4000–6000 token | 满足馏出口质量报告、联锁台账等量化分析类文本的生成与理解需求，避免截断关键工艺参数 |
| `quoteMaxToken` | 1500–2000 token | 限定知识库召回内容的长度，适配原油评价、设备管理系统的结构化数据片段 |
| `toolChoice` | auto | 支持根据检验审核任务自动选择工具，适配多源数据调用需求 |
| `temperature` | 0.1–0.3 | 降低工艺审核场景的随机性，确保检验结果与操作规程的一致性 |

## 容易做错的三处
- 现象：模型回答未引用导入的中英文对照知识库内容，界面显示知识库关联成功但检索结果为空。原因：未配置`quoteMaxToken`适配中英文混合的知识库片段长度，导致召回内容被截断后无法被模型读取。
- 现象：调用Qwen3模型时出现非流式调用报错，agent节点执行异常。原因：未确认模型接口的流式支持参数，且未将`toolChoice`配置为适配agent流式调用的模式。
- 现象：rerank模型未按预期生效，检索返回的工艺数据排序不符合质量指标优先级。原因：未在检索配置中正确绑定rerank模型的调用路径，导致重排环节未被触发。

## 怎么确认配好了
- 测试调用包含工艺参数的prompt，检查返回结果中是否包含预设的知识库内容，确认配置的参数适配当前知识库片段长度。
- 提交实时DCS数据相关的审核请求，检查模型调用的延迟是否符合业务响应要求，确认上下文配置适配多源数据的承载需求。
- 触发agent节点的多工具调用测试，检查模型是否能自动选择合适的工具完成检验审核任务，确认工具调用配置正确。
- 查看模型调用日志，确认接口地址与令牌配置无误，无接口调用报错。
