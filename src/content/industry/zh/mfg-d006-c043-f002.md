# 精细化工间歇合成的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自配方与工艺库、原料批次台账、反应釜DCS系统、称量系统、LIMS实验室管理系统、仓储系统。日常生成的文档包括批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据更新以每批产品为周期，每个关键反应步骤都会生成新的记录。文档字段包含批次号、投料量（单位为千克或升）、反应温度（摄氏度）、反应时长（小时）、清场检查项等，部分文档附带设备运行参数截图。

## 这些特征在「向量模型与索引」这一环带来什么约束
多批次、多类型的文档结构要求向量索引支持按批次号、文档类型进行分组检索，避免不同批次的记录混淆。高频次的增量更新需要索引适配实时或准实时的文档写入，避免全量重建索引带来的延迟。文档中包含带单位的数值字段与工艺参数，向量模型需要保留这些语义关联，确保检索时能准确匹配相同参数的历史记录。单份文档长度差异较大，从简短的投料复核单到长达数页的反应过程记录，需要灵活的分块策略适配不同长度的文本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类单份文档的平均段落长度，避免关键工艺参数被拆分 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，确保检索时能完整获取投料、反应的连续步骤信息 |
| 相似度阈值 | 0.75–0.85 | 区分有效关联的工艺记录与无关文档，避免检索结果混杂低相关性的批次数据 |
| 单次搜索上限 | 前 5 条 | 匹配该品类复核时需要核对的关联单据数量，避免结果过多干扰审核判断 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 1500 token | 适配单份检验报告或清场记录的典型长度，确保单文档检索时的完整语义 |

## 容易做错的三处
- 现象：界面提示“向量模型连接失败”，或检索时返回空结果。原因：未正确配置云上向量模型的API密钥与访问端点，或未在FastGPT渠道管理中启用对应模型。
- 现象：分块后的文本丢失投料量、反应温度等关键数值字段。原因：分块长度设置过小，将包含单位与参数的完整语句拆分为多个独立块，破坏语义关联。
- 现象：检索结果混杂多个批次的工艺记录，无法精准匹配目标批次。原因：未配置按批次号进行索引分组，导致所有批次的文档混合检索。

## 怎么确认配好了
- 上传一份典型的投料复核单与反应过程记录，检查分块预览界面是否完整保留批次号、投料量等关键字段。
- 输入包含具体批次号与工艺参数的检索词，检查返回结果是否仅包含对应批次的关联文档，无无关批次的记录。
- 测试使用不同的向量模型，分别检索带设备截图的清场记录，确认多模态模型可正确关联图片标注内容与文本信息。
- 查看FastGPT v4.17.0的向量索引监控面板，确认增量更新任务正常运行，无报错日志。
