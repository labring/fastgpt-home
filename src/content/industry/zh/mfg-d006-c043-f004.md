# 精细化工间歇合成的检验与过程记录审核：工作流编排

## 这个品类的数据长什么样
本品类数据来自涂料、树脂、助剂、农化中间体及专用化学品企业的生产全流程。日常文档包含批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据来源覆盖配方与工艺库、原料批次、反应釜DCS、称量系统、LIMS、仓储系统，每批生产或每个关键步骤完成后更新。数据按批次绑定多环节字段，包含投料量、反应温度、清场状态等带单位的具体参数，且存在配方保密与跨批次清洗残留的校验需求。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的批次化更新、多环节多数据源、保密与校验需求，为工作流编排带来多重约束。需绑定批次ID作为`variables`中的核心标识，关联对应批次的原料、反应、检验数据。需按生产步骤顺序编排节点，依次调用各系统接口拉取对应数据。需配置权限隔离的`variables`参数，限制配方相关数据的访问范围。需设置分支节点，根据清场记录、投料复核结果触发不同校验逻辑，避免跨批次污染或投料错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按批次绑定`nodeId`关联的数据源字段，设置权限隔离范围 | 本品类需按批次管理数据，且存在配方保密需求 |
| 工作流触发规则 | 按上一生产环节完成后触发 | 本品类数据按关键步骤更新，需匹配生产流程顺序 |
| 分支节点条件 | 按清场记录、投料复核单字段匹配校验逻辑 | 需避免跨批次污染与投料错误，符合业务校验要求 |
| 超时设置 | 600秒 | 覆盖多系统接口调用的平均耗时，按实测标定调整 |
| 节点调用顺序 | 按投料复核→反应过程→清场记录→检验报告的顺序编排 | 匹配精细化工间歇合成的生产流程先后逻辑 |

## 容易做错的三处
- 现象：调用工作流时返回身份验证失败提示，要求使用应用密钥，不能使用账号密钥。原因：未使用应用密钥进行接口调用，误用了账号密钥，导致身份验证失败。
- 现象：工作流运行耗时超出预期，界面显示执行状态长时间未更新。原因：未合理设置超时参数，且未优化多系统调用的并行逻辑，导致整体耗时超出系统承载范围。
- 现象：FastGPT v4.17.0中全局变量仅显示两个，无法添加更多自定义变量。原因：未在工作流编辑页的全局配置菜单中开启高级变量编辑模式，或升级后配置缓存未完成同步。

## 怎么确认配好了
- 核对工作流的`variables`配置，确认已绑定对应批次的数据源字段，且权限范围符合保密要求。
- 触发一次测试批次的工作流，查看各节点的调用日志，确认执行顺序与触发逻辑匹配生产流程。
- 调整超时设置至符合当前系统调用的平均耗时，确保工作流运行不出现无故中断。
- 验证分支节点的校验逻辑，输入异常清场记录字段，确认触发对应校验提示。
