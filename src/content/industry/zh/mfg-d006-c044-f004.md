# 纸浆造纸的检验与过程记录审核：工作流编排

## 这个品类的数据长什么样
纸浆造纸的检验与过程记录数据来自木浆废纸批次台账、DCS/QCS控制系统、纸机在线测量设备、实验室检测系统、能源与水处理系统。日常生成的文档包含配浆单、打浆记录、纸机运行记录、在线质量曲线、实验室检测报告、断纸与换品记录。数据更新节奏分为实时（在线测量值）、每班（班组生产台账）、每卷（单幅纸卷的全流程参数）。数据字段包含浆料配比、克重、水分、厚度、纸病类型等，对应单位为%、g/㎡、mm等。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流需支持跨系统的变量聚合与字段映射，避免数据错位。实时更新的在线测量数据要求触发节点需匹配数据刷新节奏，无法依赖固定周期调度。单卷级别的数据更新要求工作流需按批次关联上下文，避免跨卷数据混淆。复杂的质量参数与异常事件（如断纸、换品）要求工作流需配置分支跳转逻辑，适配不同生产场景的处理流程，适配FastGPT v4.17.0的节点绑定规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量绑定 | `variables`按批次字段映射 | 匹配纸浆造纸单卷级别的数据关联需求，确保同批次数据上下文一致 |
| 流程触发方式 | 实时数据变更触发 | 适配在线测量数据的实时更新频率，避免延迟处理 |
| 节点间参数传递 | 按`nodeId`绑定上下游字段 | 确保各工作流节点的参数传递准确，避免数据丢失 |
| 异常分支配置 | 断纸/换品事件触发分支 | 覆盖业务中最耗时的异常处理环节，适配生产波动 |
| API调用超时设置 | 600秒 | 匹配实验室报告的常规生成周期，避免不必要的中断 |
| 检索结果条数限制 | 前10条 | 缩小检索边界，提升匹配效率 |
| 提示词长度配置 | 800-1200字符 | 适配纸浆造纸业务参数的描述长度，提升AI理解精度 |

## 容易做错的三处
- 现象为工作流执行至知识库搜索节点后无后续响应，状态码显示参数错误。原因是未在`variables`中配置当前批次的关联字段，导致检索时未限定范围，返回无效结果。
- 现象为流程启动时调用第三方API失败，返回字段为空。原因是未在流程开始节点绑定`nodeId`对应的API调用权限，导致请求未通过校验。
- 现象为历史生产记录无法作为变量传入代码节点，全局变量列表无对应选项。原因是未在`variables`中配置历史记录的存储映射，仅依赖默认的全局变量池，未绑定业务专属的上下文数据。

## 怎么确认配好了
- 打开`variables`配置面板，确认所有纸浆造纸业务字段已绑定对应数据源，无空映射项。
- 模拟断纸事件触发工作流，检查分支节点是否正常跳转至异常处理流程。
- 调用测试API，确认流程启动节点能正确获取返回值并写入`variables`变量池。
- 运行单卷生产数据的测试用例，验证全流程节点是否按顺序执行完成，无中途中断。
