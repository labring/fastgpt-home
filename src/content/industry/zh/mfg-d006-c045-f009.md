# 纺纱与织造的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
纺纱与织造品类的典型数据来自棉纺、化纤纺、机织与针织企业，日常文档包含配棉/配料单、工艺上机单、设备运转记录、纱线/坯布检验记录、疵点台账。数据来源覆盖原纤维检验报告、ERP系统、纺机与织机实时数据、条干仪、验布机采集数据及订单规格文件，更新节奏为每批原料、每班生产周期及每匹布产出时更新。单份文档的字段包含纤维品级、混配比例、捻度参数、疵点类型与位置等，不同来源的数据格式差异明显。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据更新频率高且来源分散，要求模型接入环节需适配多格式数据的同步解析，避免因数据截断丢失关键工艺参数。单份文档的字段数量多且专业性强，需限制模型输出的提取范围，防止冗余信息干扰审核结果。设备头数多导致单批次数据量较大，需控制上下文窗口的总长度，避免模型加载超时。同时，疵点记录的判定需保持一致性，不宜出现随机化的分类偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单批次原料、当班设备记录与多份检验文档的总文本长度，避免截断关键工艺参数 |
| `maxTokens` | 2000–3000 token | 控制单条审核任务的输出长度，确保覆盖疵点判定、参数匹配与整改建议的完整内容 |
| `quoteMaxToken` | 1500 字符 | 限定模型引用原始文档的片段长度，匹配单张验布机记录或工艺单的典型字段总量 |
| `temperature` | 0.1–0.3 | 降低模型输出的随机度，确保疵点分类与参数匹配的结果保持一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署节点填写对应地址 | 适配多源数据接入的跨域访问需求，保障模型调用的稳定性 |
| `AIPROXY_API_TOKEN` | 绑定部署实例的专属密钥 | 保障模型接入的权限安全性，防止未授权访问 |

## 容易做错的三处
- 现象：审核结果遗漏配棉单中的混配比例参数，原因：`maxContext`取值过小，截断了包含关键配料信息的长文本片段。
- 现象：平台模型列表无新增接入的大模型，原因：修改`AIPROXY_API_ENDPOINT`后未重启部署容器，或`AIPROXY_API_TOKEN`配置有误。
- 现象：疵点判定结果出现随机分类偏差，原因：`temperature`取值过高，导致模型输出的分类逻辑不稳定。

## 怎么确认配好了
- 上传单份配棉单与工艺上机单，检查模型输出是否包含纤维品级、混配比例、捻度参数等核心字段。
- 提交包含多条疵点记录的批量文档，核对输出的疵点分类数量与原始记录条数一致。
- 查看FastGPT v4.17.0的部署日志，确认无`maxContext`溢出或`AIPROXY_API_TOKEN`验证失败的报错。
- 调整`temperature`至0.2后重复提交相同测试文档，确认输出结果无明显差异。
