# 肉制品与屠宰加工的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自屠宰场、熟肉与冷冻调理食品企业的日常生产与检验文档，包括检疫证明、屠宰分割记录、配料腌制日志、热加工参数记录、冷链温度台账、微生物检验报告。数据按每批原料、每班生产流程更新，连续温控数据实时生成。文档字段包含批次号、检疫编号、温度数值、检测结果、时间戳，部分文档附带检测附件，单位涵盖摄氏度、批次编号、菌落总数单位等。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据存在批次强绑定、高频实时更新、多类型字段混合的特征。批次绑定要求索引需按生产批次关联向量，避免跨批次的检验记录混淆；高频温控数据的连续更新要求索引支持增量同步，减少全量重建的资源消耗；多字段混合的文档需优先提取检疫编号、批次号等核心标识生成向量，防止非关键字段干扰相似度匹配；附带检测附件的文档需过滤二进制内容，仅提取文本字段用于向量化。需设置`defaultToken`适配单字段的最小向量化长度，确保核心标识的向量完整。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配本品类文档中批次号、检测结果等核心字段的单段长度，避免跨字段拆分 |
| 重叠长度 | 100–150 字符 | 保留批次号等关联标识的上下文，防止跨块的批次信息丢失 |
| `defaultToken` | 512 token | 适配本品类单字段的最小向量化长度，确保核心标识的向量完整 |
| `maxToken` | 4096 token | 适配本品类单文档的平均文本长度，确保完整嵌入核心检验与生产记录 |
| 相似度阈值 | 0.75–0.85 | 区分同类检验记录的细微差异，避免误匹配不同批次的检测结果 |
| 单次搜索上限 | 前 10 条 | 覆盖单批次生产的常见检验记录数量，确保召回结果完整 |

## 容易做错的三处
- 现象为上传单份批次检疫证明时，界面显示分8段，后续刷新后变为13段且存在重复条目。原因是本品类的批次关联文档存在重复的批次号字段，分块时未按批次号作为分隔标识，导致同一段内容被多次拆分索引。
- 现象为从旧版本升级后，原有可查询的冷链温度记录无法被搜索召回。原因是升级后默认的分块参数发生变化，原有的温控数据分块长度不再适配，导致部分文本未被正确向量化。
- 现象为Excel格式的配料记录上传后，索引预览内容与实际表格字段不符。原因是未开启Excel表格的表头识别配置，导致混合了表头与数据行的内容被统一向量化，出现字段错位。

## 怎么确认配好了
- 上传单份典型批次检疫证明，查看分块预览界面，确认核心批次号、检疫编号未被跨块拆分。
- 执行批量上传同批次的3至5份文档，检查索引列表中的条目数量与实际上传数量一致，无重复条目。
- 升级版本后，重新上传1份连续温控记录，验证搜索功能可正常召回对应内容。
- 上传Excel格式的配料记录，对比索引预览与原始表格的字段顺序，确认表头与数据行的关联正确。
