# 肉制品与屠宰加工的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
典型主体为屠宰场、熟肉及冷冻调理食品生产企业，日常文档包含动物检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告。数据来源涵盖动物检疫信息、供应商批次档案、生产追溯台账、实时温度采集数据、金属检测结果及实验室检验报告。更新节奏按生产批次、班次执行，冷链温度记录为连续实时更新。文档字段包含批次编号、检测时间、温度值、检验结果等，无统一标准化格式，部分手写记录需转换为电子文档。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类的溯源需求需精准匹配生产批次与检疫信息，连续更新的冷链温度记录要求检索结果可定位到具体时间节点，多类型文档的混合检索需避免跨批次、跨工序的信息混淆。生物风险管控要求溯源结果覆盖所有关键文档，不能遗漏检疫证明或温度异常记录。不同生产环节的文档字段差异较大，需确保检索时可准确识别批次、时间等核心标识，避免误匹配不同车间或生熟批次的内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 4000–6000 字符 | 适配单份肉制品加工文档的内容长度，避免跨批次切割导致溯源混乱 |
| `quoteMaxToken` | 1200–1500 token | 匹配该品类文档的信息密度，避免超出上下文限制导致关键内容截断 |
| `responseData` | 仅返回核心业务字段 | 减少冗余信息，聚焦批次号、检测时间等溯源关键内容 |
| `detail` | 按需开启完整字段返回 | 当需要完整溯源信息时，保留所有原始文档的全部字段 |
| 检索相似度阈值 | 0.75–0.85 | 精准区分不同批次的记录，避免生熟批次或不同车间的文档误匹配 |
| 单次检索召回条数 | 前 8 条 | 覆盖单批次多份关联文档的检索需求，确保检疫证明、生产记录等关键信息不遗漏 |

本配置基于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：检索到的切块内容超出`quoteMaxToken`设置的上限，仍被纳入最终引用。原因：切块大小设置大于`quoteMaxToken`上限，且未对检索结果进行前置截断。
- 现象：知识库引用合并模块返回的结果条数与设置的单次检索召回条数不符。原因：未按批次号过滤无关文档，导致非目标批次的记录混入结果。
- 现象：工作流中不同分支的检索结果无法统一聚合处理。原因：未为各分支的检索结果添加统一的批次标识字段，导致后续逻辑无法识别分组依据。

## 怎么确认配好了
- 上传单份批次屠宰记录文档，输入包含对应批次号的查询词，测试检索后查看引用内容的token数是否符合`quoteMaxToken`的设置。
- 查看检索结果的字段，确认是否包含批次号、检测时间等核心业务字段，匹配`responseData`或`detail`的配置要求。
- 触发多知识库检索的工作流分支，确认各分支返回的结果可按批次号聚合，实现统一逻辑处理。
- 调整检索相似度阈值，测试输入相似批次号的查询词，确认返回结果仅包含目标批次的文档。
