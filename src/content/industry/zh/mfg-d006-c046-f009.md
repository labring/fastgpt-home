# 肉制品与屠宰加工的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自动物检疫信息、供应商批次、生产追溯系统、温度采集设备、金属检测设备与实验室检测结果。日常文档包含检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告。数据更新按生产批次、班组班次执行，连续温控数据为实时同步。数据字段包含批次编号、检疫编号、温度值、检测时间、检测结果等，单位涵盖摄氏度、批次号、检测指标名称等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的批次绑定型数据要求模型上下文需覆盖完整的单批次关联记录，避免出现批次与检疫信息不匹配的问题。连续温控数据的实时性要求模型支持时序数据的快速解析，因此需合理设置上下文加载的参数上限。多类型文档混合输入的场景，要求模型同时支持文本与视觉类文档的处理，需开启视觉识别能力。高风险的检验审核需求，要求模型输出的审核结果具备较高的一致性，需降低生成结果的随机性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 单批次关联的文档数量较多，需覆盖完整的检疫、生产与检测记录 |
| `temperature` | `0.1–0.3` | 检验与审核需高准确性，降低生成结果的随机性 |
| `AIPROXY_API_ENDPOINT` | 填入OneAPI代理的访问地址 | 对接第三方模型代理服务，实现跨平台模型调用 |
| `AIPROXY_API_TOKEN` | 填入OneAPI生成的有效令牌 | 完成代理服务的身份验证，获取模型调用权限 |
| `vision` | 开启 | 需识别检疫证明、温度记录截图等视觉类文档内容 |
| `maxTokens` | `2000–3000 token` | 满足单条审核报告的输出长度需求 |

## 容易做错的三处
- 配置重排序模型后提示没有可用模型，原因是未在OneAPI平台中配置对应重排序模型的API密钥与访问地址，导致FastGPT无法获取模型资源。
- 输入OneAPI令牌后返回空结果，原因是未正确配置`AIPROXY_API_ENDPOINT`指向OneAPI的代理地址，或令牌未开放对应模型的调用权限。
- 模型审核结果遗漏部分批次关联记录，原因是`maxContext`设置值过小，未覆盖完整的单批次关联文档，导致关键信息丢失。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本执行。
- 检查`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置值与OneAPI后台的实际参数一致，发起测试调用查看返回状态码为200。
- 上传单批次的检疫证明与冷链温度记录，触发审核任务，查看模型是否正确提取批次编号、检疫编号与温度数据。
- 调整`temperature`参数的取值，对比两次审核结果的一致性，确认符合检验审核的准确性需求。
- 上传检疫证明的图片文件，触发视觉识别任务，查看模型是否能正确识别图片中的关键文字信息。
