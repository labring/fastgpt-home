# 肉制品与屠宰加工的检验与过程记录审核：部署与升级

## 这个品类的数据长什么样
该品类的数据主要来自动物检疫信息、供应商批次台账、生产追溯系统、冷链温度采集设备、金属检测设备与实验室检验结果。日常生成的文档包含检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告。数据更新节奏按生产批次、班组班次执行，连续温控数据实时更新。数据字段包含批次编号、检疫标识、温度数值、检测结果、生产环节标识等，对应单位涵盖摄氏度、批次号、检测时间等。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据特征对部署与升级带来明确约束。高频实时的冷链温控数据需要低延迟的读写能力，部署时需保障数据库的并发处理性能。多来源的批次关联数据要求配置精准的字段匹配规则，升级过程中不能破坏已建立的生产溯源链路。合规性文档如检疫证明的存储需要符合食品行业数据安全要求，需配置加密存储参数。不同更新节奏的文档（实时温控与批量班组记录）需要拆分处理队列，避免资源争抢。同时，跨系统的数据导入需适配多格式的输入，部署时需预留格式转换的适配空间。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150` | 该品类存在高频实时温控数据与批量批次文档，需适配高并发数据库连接需求 |
| `PG_URL` | 专用PostgreSQL实例地址，分配1000 MB 存储空间 | 该品类的批次溯源数据需结构化存储，需预留足够的结构化数据空间 |
| `STORAGE_S3_ENDPOINT` | 合规云存储节点地址 | 需存储检疫证明等合规文档，需选择符合食品行业数据安全要求的存储节点 |
| `FILE_TOKEN_KEY` | 32位随机字符串 | 保障文档上传与下载的令牌安全，避免未授权访问合规文档 |
| `REDIS_URL` | 本地Redis集群地址，按实测标定 | 实时温控数据的缓存需要低延迟的键值存储，保障快速读取 |

## 容易做错的三处
- 现象：部署后数据库连接报错，状态码503，无法读取批次数据。原因：未按要求配置`DB_MAX_LINK`参数，连接数超出数据库承载上限，导致高并发的温控数据请求被拒绝。
- 现象：iOS设备访问部署后的界面显示白屏，macOS与Windows设备可正常访问。原因：未正确配置`FE_DOMAIN`参数，未适配跨终端访问的域名规则，导致跨域请求被拦截。
- 现象：大模型调用时GPU使用率偏低，CPU单核占用过高。原因：未针对该品类的批量文档处理优化部署资源分配，未启用GPU加速的文档解析模块，导致计算资源分配不合理。

## 怎么确认配好了
- 执行数据库连接测试，验证配置的`DB_MAX_LINK`参数可支撑设定的并发请求数，确认连接无报错。
- 上传一份检疫证明文档，验证`FILE_TOKEN_KEY`配置可生成有效访问令牌，文档可正常存储与读取。
- 访问配置的`FE_DOMAIN`域名，在不同终端设备上验证界面可正常加载，无白屏或加载失败情况。
- 查看实时温控数据的缓存状态，验证`REDIS_URL`配置的缓存服务可正常读取与更新数据。
