# 设备点检与预防维修的检验与过程记录审核：工作流编排

## 这个品类的数据长什么样
本品类的核心数据来自制造企业设备部、车间维修班组与公用工程部门的日常运维文档与系统数据。日常文档包含设备台账、点检表、保养计划、维修工单、故障分析、备件清单及特种设备检验记录，字段涵盖设备编号、安装位置、点检时间、异常记录、备件编码等。数据来源包括EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史、备件库存及法定检验信息，更新频率覆盖每班、日/周/月及故障发生时的实时更新。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据来源多样、更新节奏不均且文档字段丰富，要求工作流需支持多数据源节点的灵活配置，以适配EAM系统、传感数据与人工点检的不同接入方式。不同文档的更新频率差异，要求工作流可配置定时触发或事件触发的启动规则，匹配每班点检、月度保养等不同场景。核心运维环节的复杂度，要求工作流需编排分级审批、故障排查、备件校验等分支逻辑，同时需配置失败告警节点以规避非计划停机等风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按设备台账预设设备编号、点检周期、备件编码等字段 | 匹配日常运维文档的核心字段结构，实现数据自动映射 |
| 触发方式 | 定时任务或事件触发，按实测标定 | 适配每班点检、故障实时上报等不同更新频率的业务场景 |
| 节点分支规则 | 按异常等级分为3级处理逻辑 | 匹配设备点检的异常分级运维流程 |
| 超时设置 | `600 秒` | 覆盖设备故障排查的平均响应时长，避免工作流无故中断 |
| 数据映射规则 | 将EAM系统字段与工作流变量一一对应 | 实现多数据源的统一调用与处理 |
| 告警节点 | 触发时推送至对应维修班组群组 | 匹配设备运维的响应流程，及时通知异常 |

## 容易做错的三处
- 现象：接口调用时返回密钥无效的报错提示。原因：配置外部接口节点时，使用了账号密钥，未使用应用密钥进行凭证配置。
- 现象：工作流运行时指定的HTML输出节点无内容，直接进入后续分支。原因：未正确设置节点触发条件，导致分支判断逻辑跳过了输出节点的执行。
- 现象：工作流执行超过预设时长后中断。原因：未配置合理的超时阈值，默认超时时长不足以覆盖设备故障排查的平均耗时。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的工作流编辑器，检查`variables`配置是否包含设备编号、点检周期等核心字段，且与EAM系统的字段名称一致。
- 触发测试工作流，调用外部接口时无授权报错，验证密钥配置正确，未使用账号密钥。
- 模拟不同等级的异常场景，检查分支节点是否按预设逻辑触发对应处理步骤。
- 查看工作流运行日志，确认超时阈值设置符合业务需求，无异常中断记录。
- 配置测试用的HTML输出节点，验证内容可正常展示，无跳过执行的情况。
