# 设备点检与预防维修的检验与过程记录审核：模型接入与配置

本页面基于FastGPT v4.17.0版本配置规则编写。

## 这个品类的数据长什么样
本品类的核心数据来自制造企业设备部、车间维修班组与公用工程部门的日常运维文档，包括设备台账、点检表、保养计划、维修工单、故障分析、备件清单及特种设备检验记录。数据来源覆盖EAM/CMMS系统、设备传感采集终端、操作员点检记录、历史维修档案、备件库存台账与法定检验报告。数据更新频率涵盖每班巡检、日/周/月保养计划更新，以及故障发生时的实时记录。文档字段包含设备编号、点检时间、运行参数、维修人员、备件编码、检验有效期等，无统一的标准化格式，部分字段需跨系统关联提取。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源与差异化的更新节奏，要求模型接入配置需适配不同数据的访问权限与更新延迟。设备传感数据的实时性要求配置需支持低延迟的上下文调用，而法定检验记录的合规性要求配置需锁定特定文档的引用范围。多类文档的非标准化字段，要求配置需支持精准的字段提取与关联，避免混淆设备编号与备件编码等相似字段。跨系统的数据访问需求，要求配置需适配内部代理服务的接入规则，保障数据安全。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖单次班组交接班的完整点检、维修与保养记录，确保多文档上下文的完整性 |
| `maxTokens` | 2000–3000 token | 满足故障分析、备件替代建议的详细回复需求，适配多数大模型接口的输出限制 |
| `temperature` | 0.1–0.3 | 保持点检记录审核的严谨性，减少无关发散内容，符合设备运维的合规要求 |
| `quoteMaxToken` | 1500–2000 token | 确保召回的点检表、维修工单等核心文档内容不被截断，保障审核依据的完整性 |
| `AIPROXY_API_ENDPOINT` | 企业内部部署的代理服务地址 | 适配EAM/CMMS等内部系统的数据访问，规避跨网访问的权限限制 |
| `AIPROXY_API_TOKEN` | 与代理服务绑定的访问密钥 | 保障内部设备运维数据的访问安全，防止未授权访问 |

## 容易做错的三处
- 现象：模型返回的审核结果未引用点检表中的具体运行参数值。原因：未正确配置`quoteMaxToken`参数，导致召回的上下文被截断，无法提取文档中的核心字段信息。
- 现象：多轮对话中无法延续上一轮的设备故障问题展开分析。原因：未调整`maxContext`参数覆盖多轮交互的历史记录，导致上下文丢失，无法关联前期提问的故障场景。
- 现象：调用模型时返回权限错误。原因：未正确配置`AIPROXY_API_TOKEN`，或代理服务地址未开放内部EAM系统的访问权限，导致数据访问被拦截。

## 怎么确认配好了
- 上传单份完整的设备点检表与对应维修工单，触发模型审核，核对返回结果是否提取了文档中的核心字段信息。
- 发起两次连续的设备故障相关提问，核对第二次回复是否关联第一次提出的故障场景。
- 调用配置的代理接口，核对接口返回状态与权限验证结果是否符合预期。
- 调整模型温度参数，核对生成的审核意见是否保持严谨的表述风格，无主观发散内容。
