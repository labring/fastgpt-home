# 设备点检与预防维修的检验与过程记录审核：知识库检索与召回

## 这个品类的数据长什么样
本品类数据覆盖制造企业设备部、维修班组的生产资产相关内容，日常文档包含设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录。数据来源包括EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史、备件库存及法定检验信息，更新频率覆盖每班、日/周/月及故障发生时。文档字段包含设备编号、点检周期、故障代码、备件规格等，单位涉及台、次、天、件等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源混合的数据结构要求检索同时支持结构化字段匹配与非结构化文本语义关联；多样的更新频率需要适配不同同步节奏，避免过期数据被召回；丰富的文档字段需要精准匹配业务关键词，避免泛化检索引入无关内容；高风险的业务后果要求召回结果具备较高置信度，需严格过滤低相关性数据；专属的业务场景需隔离生产资产数据与其他业务内容，确保检索范围聚焦。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 设备点检数据的字段精准度要求高，过低会引入无关维修记录，过高会遗漏匹配的点检项 |
| `limit` | 前8条 | 维修班组需要快速浏览多份关联工单、点检表，过多会超出上下文窗口，过少会覆盖不全故障关联数据 |
| `searchMode` | 混合检索 | 数据包含结构化的EAM字段和非结构化的故障分析文本，混合检索可同时匹配关键词和语义关联 |
| `usingReRank` | 开启 | 设备故障的语义关联复杂，重排可过滤低相关性的备件清单条目，提升结果准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 点检术语多为行业黑话，扩展查询可补充同义词，提升召回覆盖范围 |
| `collectionIds` | 绑定设备点检专属知识库集合 | 隔离生产资产数据与其他业务数据，避免召回无关的产品工艺文档 |

## 容易做错的三处
- 现象：知识库生成的回答段落末尾无引用标识。原因：未开启回答引用配置项，未关联对应知识库集合的引用权限。
- 现象：同一会话窗口内连续提问，后续回答出现答非所问的情况。原因：未限制会话上下文的召回范围，或未设置单次检索的上下文长度上限，导致历史冗余数据干扰当前检索。
- 现象：静态页面导入的知识库内容更新后，平台内数据未同步更新。原因：未配置定时增量同步任务，或未设置触发更新的事件规则。

## 怎么确认配好了
- 提交包含具体设备故障的查询，检查回答末尾是否显示关联的知识库文档引用标识。
- 在同一会话窗口依次提交两台不同设备的点检问题，检查两次回答均聚焦对应设备的相关数据。
- 修改静态页面内的点检表内容，触发同步任务后检索该内容，确认已更新为最新版本。
- 进入FastGPT v4.17.0的检索配置面板，核对`similarity`、`limit`等参数的取值与预设配置一致。
