# 过程质量与成品放行的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自制造企业IPQC、FQC、质量工程及实验室，涵盖控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审、放行单、质量月报等文档。数据来源于MES系统、检测设备、实验室系统、工艺参数库、客户标准及历史缺陷库，更新频率为每批、每班或持续采集。文档包含检验项、参数阈值、检测结果、判定结论、审批流程等字段，单位涉及数值型参数的公差范围、缺陷等级编码等。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据来源分散且更新频繁，要求向量索引支持增量同步以避免全量重建的资源消耗。文档类型覆盖标准化报表与自由文本记录，分块策略需适配不同结构的内容，避免拆分检验项与对应判定结果的关联。字段包含数值公差、缺陷等级等结构化信息与审批流程文本，向量模型需兼顾结构化特征与非语义内容的编码。历史缺陷库数据体量较大，需限制单批次索引的存储上限以保障检索效率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配本品类的特征需求。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配巡检记录、SPC报表等文档的单段落长度，避免拆分检验项与判定结果的关联 |
| 重叠长度 | 100–200 字符 | 保留跨分块的检验流程上下文，防止关键判定逻辑被截断 |
| `defaultToken` | 4096 | 匹配多数多模态Embedding模型的输入上限，适配含检测设备原始数据的长文本 |
| `maxToken` | 8192 | 适配成品检验报告与不合格品评审的完整内容编码需求 |
| 单次搜索上限 | 前 10 条 | 控制检索结果的上下文长度，避免超出模型输入限制 |
| 最大上下文 | 8000 token | 综合检验项、历史缺陷与审批信息的检索需求，保障决策所需的完整信息 |

## 容易做错的三处
- 现象：刷新页面后弹出“检测到没有可用的索引模型”报错。原因：未将过程质量相关的检验记录、放行单等数据源关联至索引任务，或索引任务未完成初始化即发起检索。
- 现象：调用多模态Embedding模型时返回Invalid错误。原因：未匹配模型要求的输入格式，或传入的检测设备原始数据超出`maxToken`限制。
- 现象：升级新版本后老向量库数据无法检索。原因：未按照新版本的索引格式要求完成数据迁移，或迁移过程中丢失了历史缺陷库的特征编码关联。

## 怎么确认配好了
- 进入索引管理页面，确认已关联控制计划、巡检记录、成品检验报告等本品类核心数据源。
- 发起一次增量索引任务，查看任务日志中无分块失败、编码异常提示，确认索引生成进度正常。
- 输入检验项相关的查询词，核对检索结果包含对应文档的判定结论与审批流程内容，调整相似度阈值至符合业务需求的范围。
- 导出部分索引元数据，确认字段包含公差范围、缺陷等级等本品类特有的结构化信息。
