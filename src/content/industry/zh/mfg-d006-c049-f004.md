# 过程质量与成品放行的检验与过程记录审核：工作流编排

## 这个品类的数据长什么样
该品类的数据来源包括MES系统、在线检测设备、实验室检测系统、工艺参数数据库、客户质量标准库及历史缺陷库。数据更新节奏为每生产批次、每班或持续采集。日常产出的文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单及质量月报，字段涵盖检验项编号、实测数值、判定结果、生产批次号、关联设备ID、不合格类型等，单位包含长度、重量、缺陷等级等计量或分类标识。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据来源分散且涉及多系统对接，要求工作流需配置多节点分别拉取不同数据源的信息。数据更新频率匹配生产节奏，需支持按批次或定时触发流程，避免遗漏未审核的生产批次。文档结构多样且字段差异明显，需通过变量配置适配不同文档的字段映射规则。流程出错会引发批量不良或不合格品放行风险，需配置明确的失败处理与告警机制，确保异常可被及时干预。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 按生产批次号、关联设备ID映射对应数据源字段 | 匹配品类数据的核心关联字段，实现MES、检测设备数据的精准关联 |
| 触发方式 | 按生产批次完成事件触发，间隔10-15分钟轮询未审核批次 | 适配每批、每班的更新频率，匹配生产节拍 |
| 节点超时 | 600秒 | 覆盖跨多数据源拉取、报表解析的常规耗时需求 |
| 知识库关联 | 关联前5条历史缺陷记录 | 匹配品类历史缺陷库的数据规模，为审核提供参考 |
| 文件存储配额 | 1000 MB | 适配检验报告、SPC报表等文档的存储需求 |
| 失败处理策略 | 触发告警并回退至待审核节点 | 避免不合格品误放行，符合品类出错后果的风险防控要求 |
| 工具调用输出 | 隐藏工具调用原始回复，仅保留自定义判定结果 | 适配质量审核场景的输出规范，避免冗余信息干扰审核人员 |
| `nodeId` | 绑定至成品放行审核节点的唯一标识 | 确保流程中各节点的调用关系准确，避免节点混淆 |

## 容易做错的三处
- 现象：代码执行节点有输出，但下游指定回复节点无法打印该结果。原因：未将代码执行节点的输出绑定到`variables`中，导致下游节点无法读取对应数据。
- 现象：工作流无法正常拉取存储在minio中的检测报告。原因：未更新适配FastGPT v4.13.0及以上版本的环境变量配置，导致存储权限验证失败。
- 现象：工作流运行后显示工具调用的原始回复，无法隐藏。原因：未配置隐藏工具调用输出的开关，保留了工具调用的默认输出设置。

## 怎么确认配好了
- 触发一次模拟生产批次的工作流，检查是否自动拉取对应批次的MES数据、检测设备检验报告及历史缺陷信息。
- 查看`variables`配置项，确认上游节点的输出字段已正确映射到下游节点的输入参数。
- 模拟一次检验不合格的场景，检查是否触发失败告警并回退至待审核节点。
- 确认工作流运行结果仅显示自定义的检验判定与放行建议，未出现工具调用的原始回复内容。
