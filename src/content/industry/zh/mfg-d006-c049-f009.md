# 过程质量与成品放行的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源包括生产执行系统（MES）、检测设备、实验室系统、工艺参数记录、客户质量标准及历史缺陷库。数据更新节奏按生产批次、班次执行，或持续采集生成。日常产出的文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单及质量月报，各文档包含检验项、参数阈值、缺陷类型、判定结果等字段，无统一固定单位，随检测项类型变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新节奏差异大，需配置多源数据接入适配不同采集频率的数据源。文档类型多样且字段无统一格式，需模型支持多结构文本解析。历史缺陷库与实时检验数据的关联分析，要求模型能处理跨文档的关联查询。不合格品评审与放行单的闭环关联，需模型保留上下文以关联历史判定结果。检验项的标准转换需模型准确匹配工艺参数与客户要求，需限制上下文长度避免冗余信息干扰，同时需支持多模型切换适配不同检测场景的需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 适配多源检验记录、历史缺陷库的总文本长度，避免超出模型上下文窗口 |
| `maxTokens` | 2000–3000 token | 满足单批次成品检验报告的完整判定与评审输出需求 |
| `quoteMaxToken` | 1500–2000 token | 限定引用的检验文档片段长度，确保关联信息精准且不冗余 |
| `temperature` | 0.3–0.5 | 平衡检验判定的严谨性与结果一致性，减少随机偏差 |
| `AIPROXY_API_ENDPOINT` | 按部署模型的局域网地址填写 | 适配本地或局域网部署的模型接入场景 |
| `AIPROXY_API_TOKEN` | 按模型服务商提供的密钥填写 | 完成模型接入的身份验证 |

## 容易做错的三处
- 配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`时填写错误，返回401状态码或连接超时。原因：未正确匹配部署模型的身份验证密钥与地址，或混淆了不同模型的接入参数。
- 设置多模型接入时，未正确切换模型调用配置，导致调用的模型与预期不符。原因：未按不同模型的要求更新`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或未在模型选择界面完成对应配置。
- 相似度过滤配置异常，返回结果条数不符合预期。原因：未适配本品类检验数据的语义特征，错误使用非0-1区间的阈值配置，或未参考历史检验数据的语义相似度分布调整。

## 怎么确认配好了
- 提交单批次成品检验报告的解析请求，核对模型输出的检验项判定结果与原始文档一致。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置已生效，无连接超时或身份验证报错。
- 测试多模型切换，确认不同模型的调用参数配置正确，返回结果符合预期。
- 测试多源数据关联查询，确认模型能正确关联历史缺陷库与当前检验记录的信息。
- 检查发布渠道的访问配置，确认授权范围符合业务要求。
