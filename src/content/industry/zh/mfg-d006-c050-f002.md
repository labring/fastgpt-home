# 通用机械设备装配的检验与过程记录审核：向量模型与索引

本文基于FastGPT v4.17.0版本的向量模型与索引配置逻辑编写。

## 这个品类的数据长什么样
该品类数据主要来自PLM/ERP、零件检验数据、装配工具采集系统、试验台、MES及客户技术协议。日常文档包含装配工艺卡、BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单与装箱清单。数据更新以单台设备或每订单为单位，字段包含设备型号、订单编号、扭矩值（单位N·m）、间隙值（单位mm）、同轴度参数（单位μm）等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的多源异构数据来源、按单台/订单的更新节奏，以及带物理单位的字段特征，会对向量模型与索引环节带来多重约束。不同来源的文档格式差异，要求分块时保留字段关联逻辑，避免语义割裂；按单台更新的数据特性，需要配置增量索引机制，避免全量重建带来的计算资源浪费；带扭矩、间隙等单位的字段，需要在嵌入前统一关联单位语义，提升检索匹配精度；随订单增长的数据集规模，要求索引结构适配动态扩容，保障召回效率。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配装配工艺卡、BOM等文档的语义单元长度，避免块内语义断裂 |
| 重叠长度 | 100–150 字符 | 保留跨块的装配步骤、参数关联信息，提升检索连贯性 |
| 相似度阈值 | 0.72–0.85 | 适配带物理单位的字段匹配，过滤低相关性的非装配类文档 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 单次搜索上限 | 前10条 | 平衡召回精度与计算开销，适配多订单并行检索的场景 |

## 容易做错的三处
- 现象：导入BOM与扭矩记录后，检索时无法关联对应装配工序的参数。原因：分块时未保留BOM条目与装配步骤的上下文关联，仅单独嵌入了字段文本。
- 现象：检索扭矩记录时出现大量无关的零件加工文档。原因：未在嵌入阶段统一关联物理单位语义，导致不同场景的参数被误判为相似。
- 现象：全量索引重建耗时过长，无法按时完成单批次订单的更新。原因：未配置增量索引机制，每次更新都重建全量数据集，占用过多计算资源。

## 怎么确认配好了
- 导入一份完整的装配工艺卡与对应扭矩记录，检索指定设备的装配参数，检查返回结果是否包含完整的工艺步骤与关联字段内容。
- 模拟单台设备的增量更新操作，核对索引中仅新增该订单的相关文档，未覆盖历史数据。
- 检索跨文档的关联内容，比如BOM中特定零件对应的装配工序，检查返回结果是否覆盖相关文档的关联信息，且上下文长度未超过`maxToken`设定的阈值。
- 查看向量数据库的索引状态，确认增量更新的触发逻辑与配置的更新规则一致。
