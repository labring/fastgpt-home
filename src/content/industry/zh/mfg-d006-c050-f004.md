# 通用机械设备装配的检验与过程记录审核：工作流编排

## 这个品类的数据长什么样
通用机械设备装配的日常文档包含装配工艺卡、BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单。数据来源覆盖PLM/ERP系统、零件检验数据、装配工具采集终端、试验台、MES系统及客户技术协议。数据更新频率为每台设备、每订单一次，核心字段包含扭矩值（单位牛米）、间隙数值（单位毫米）、同轴度检测数据、预紧力参数等，单台设备的检验与过程记录会随装配工序逐步生成并归档。

## 这些特征在「工作流编排」这一环带来什么约束
该品类多品种按订单装配的特性，要求工作流需绑定单台设备的专属变量，避免不同订单的数据混淆。多数据源的采集逻辑要求工作流按装配工序顺序依次拉取数据，防止未完成的工序数据干扰校验环节。单台设备的检验记录需逐一闭环，因此工作流需设置节点校验流程，确保所有必填文档上传完成后再进入审核环节。此外，装配环节的出错后果直接影响后续安装与运行，工作流需加入异常拦截与重试机制，应对工具断连、数据传输延迟等临时问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 数据源绑定规则 | 关联PLM/BOM、MES装配记录、扭矩采集数据三个数据源 | 覆盖该品类核心检验与过程记录的数据来源 |
| 全局变量绑定 | 绑定`variables`中的单台设备序列号、订单号 | 匹配每台每订单的更新频率，实现单实例数据隔离 |
| 节点ID配置 | 按工序顺序绑定`nodeId`为1到7的唯一标识 | 贴合装配工序的先后逻辑，避免节点执行顺序错乱 |
| 节点执行间隔 | 10-15秒每次工序节点 | 贴合装配工序的实际操作节奏，等待工具数据完成上传 |
| 异常重试次数 | 3次，每次间隔60秒 | 应对装配工具临时断连、数据传输延迟的场景 |
| 上下文长度配置 | 8000 token | 适配检验报告生成的长文本输出需求 |
| AI会话节点温度配置 | 温度开关关闭，或温度开关打开并设置为0 | 适配检验报告生成的确定性输出需求 |

## 容易做错的三处
- 导出工作流及关联JSON文件导入其他环境后，引用的插件无法找到。原因是导出时未包含插件的本地部署配置信息，仅同步了工作流节点逻辑。
- 使用text2sql节点生成SQL时，返回结果与预期不符。原因是未绑定`variables`中的专属表结构变量，导致SQL查询范围错误。
- AI会话节点返回的字符串开头带有换行符。原因是节点默认开启了格式补全逻辑，未关闭自动换行配置。

## 怎么确认配好了
- 触发工作流执行，查看各数据源节点是否成功拉取对应装配单的BOM、扭矩记录等数据，核对拉取字段与预设配置一致。
- 模拟未上传间隙调整记录的场景，确认工作流是否触发异常拦截并提示缺失必填文档。
- 调用AI会话节点生成检验报告，确认返回内容无多余换行符，且输出符合检验单的格式要求。
- 导出工作流并导入FastGPT v4.17.0的测试环境，确认所有关联插件均能正常加载并执行节点逻辑。
