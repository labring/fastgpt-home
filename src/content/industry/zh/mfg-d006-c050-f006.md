# 通用机械设备装配的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
该品类数据主要来自PLM/ERP系统、零件检验台账、装配工具采集数据、试验台监测数据、MES生产执行系统及客户技术协议。数据更新以单台设备或每订单为节奏，涉及装配工艺卡、BOM清单、扭矩拧紧记录、间隙调整记录、试运行报告、出厂检验单、装箱清单等文档。文档字段包含物料编码、拧紧扭矩值、间隙公差、同轴度参数等，对应单位多为牛米、毫米、百分比等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
该品类多订单定制化装配的特征，要求引用溯源需精准绑定单台设备的生产批次与订单信息，避免跨单数据混淆。文档类型多样且字段差异大，不同环节的记录（如扭矩记录、间隙调整单）对装配质量的参考权重不同，需针对性配置召回优先级。数据更新频率随单台设备完成节点触发，需确保溯源时调用的是最新版本的装配数据。多层BOM结构要求溯源覆盖从部件到整机的全链路文档，需支持分层级的来源关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | 匹配该品类单台设备装配文档的平均总长度，避免截断关键的扭矩、间隙参数 |
| `detail` | true | 要求返回完整的来源元数据，支持多层BOM与多文档的层级溯源 |
| `responseData` | 开启 | 同步展示文档的存储路径、版本号与关联订单号，满足精准溯源需求 |
| 单次召回上限 | 前6条 | 覆盖单台设备核心装配文档的数量，避免冗余信息干扰审核逻辑 |
| 引用来源排序 | 按关联度降序 | 优先展示扭矩记录、间隙调整单等直接影响装配质量的文档 |
| 适配版本 | FastGPT v4.17.0 | 适配当前版本的参数配置逻辑，避免版本兼容性问题 |

## 容易做错的三处
- 现象：返回的引用文件与目标设备的装配文档不匹配，混入了其他订单的零件加工记录。原因：未配置文档分类过滤规则，将非装配环节的文档纳入了溯源范围。
- 现象：FastGPT v4.17.0版本中，未开启引用展示开关仍返回引用内容。原因：该版本默认调整了引用配置的全局默认值，需手动验证并调整应用级参数。
- 现象：解析`detail`参数返回的流式结果时，无法关联到单台设备的唯一批次标识。原因：未在溯源配置中绑定订单号与设备编号的关联字段，导致来源信息缺少关键关联维度。

## 怎么确认配好了
- 提交单台设备的装配审核查询，检查返回的引用列表是否包含该设备对应的BOM、扭矩记录、间隙调整单等核心文档。
- 开启`detail`参数，验证返回结果中是否包含文档的存储路径、版本号与关联订单号等元数据。
- 模拟跨订单的查询场景，确认返回的引用未混入其他订单的装配数据。
- 检查应用配置中的引用开关，确认仅在开启对应配置时才展示引用内容，避免默认返回的情况。
