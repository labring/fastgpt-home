# 通用机械设备装配的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
通用机械设备装配的检验与过程记录数据，通常来自PLM/ERP、零件检验数据、装配工具采集系统、试验台、MES及客户技术协议。数据按每台设备、每订单更新，涵盖装配工艺卡、BOM表、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单等文档。字段包含物料编码、装配扭矩值（单位N·m）、间隙尺寸（单位mm）、同轴度公差等，不同文档的字段格式与更新节点存在差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类按订单多品种装配的特性，要求模型接入需适配单台/单订单的小批量、多类型数据。多源异构的数据来源，要求配置环节需兼容不同系统导出的文档格式与字段规则。数据更新频率与装配进度强绑定，需确保模型调用的上下文能覆盖当前装配环节的全部有效数据。同时，检验与审核环节对数值准确性要求高，模型的参数配置需兼顾严谨性与处理效率，避免因参数不当导致漏判或误判。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 覆盖单台设备全流程装配文档的总token量，避免上下文截断导致关键信息丢失 |
| `temperature` | 0.2–0.4 | 适配检验审核的严谨需求，降低随机输出偏差，确保数值核对与规则匹配的准确性 |
| 工作流/API 工具选择配置 | auto | 自动调用工具处理扭矩、间隙等数值类字段的比对，减少人工干预的误差 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的代理地址填写 | 对接第三方模型的访问路径，确保模型调用链路正常 |
| `AIPROXY_API_TOKEN` | 对应模型平台的访问密钥 | 完成身份验证，保障模型接入的安全性与合法性 |

## 容易做错的三处
- 界面显示“当前分组default下对于模型gpt-4o-mini无可用渠道”，原因是未正确配置`AIPROXY_API_TOKEN`或代理地址无效，导致模型调用身份验证失败。
- 配置`maxContext`设为低于5000 token，导致单台设备的BOM表与装配记录无法完整传入模型，出现漏装错装的审核漏判。
- 将`temperature`设为0.7以上，导致模型对扭矩、间隙等数值的判断出现随机偏差，引发检验结果不一致。

## 怎么确认配好了
- 在FastGPT v4.17.0的模型管理页面，测试指定模型的调用，查看返回结果是否包含正确的检验审核逻辑。
- 导入单台设备的装配文档与检验记录，触发审核流程，核对输出结果是否覆盖全部输入文档的关键字段。
- 检查模型渠道的状态标识，确认无“不可用”报错，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置有效性。
- 模拟不同订单的装配数据输入，确认模型能适配不同BOM结构与检验记录的格式差异。
