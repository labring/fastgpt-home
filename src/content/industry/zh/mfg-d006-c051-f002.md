# 金属切削加工的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
金属切削加工的业务数据来自产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES系统与量检具数据。日常文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表与量具校准记录，字段包含工序编号、刀具寿命、尺寸偏差、检验结果等。数据更新频率为每工单、每件工件、抽检批次或刀具更换时触发。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且字段维度多样，需统一字段语义以保证向量生成的一致性。高频更新的工单与刀具更换记录要求索引支持增量触发，避免全量重建的资源消耗。不同文档类型的长度差异显著，短文本的检验记录与长文本的数控程序需适配不同的分块规则。工序执行的时序逻辑与工艺关联要求索引保留上下文关联，避免分块切断连续的加工链路，否则将影响审核的准确性。同时，数据的精度要求直接决定向量匹配的阈值设定，需严格控制误匹配率。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配工序卡、数控程序的单段工艺内容体量，匹配金属切削文档的单工序信息范围 |
| 重叠长度 | 100–150 字符 | 保留工序间的工艺关联，避免分块切断连续的加工逻辑 |
| `maxToken` | 4096 token | 适配主流向量模型的输入上限，满足长文本数控程序的分块向量生成需求 |
| `defaultToken` | 256 token | 适配短文本检验记录、量具校准记录的向量生成需求，平衡精度与资源占用 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非关联记录，避免检验审核出现误判 |
| 单次搜索上限 | 前 10 条 | 匹配机加工工单的常规工序数量范围，控制检索上下文的总长度 |

## 容易做错的三处
- 现象：检索结果的工序顺序与实际加工流程不符，部分关联工艺记录缺失。原因：未配置分块重叠长度，或启用自动去重时未保留工序时序的索引关联。
- 现象：调用向量模型时返回大语言模型生成的结果，未得到向量检索结果。原因：未正确绑定向量模型的调用渠道，检索请求被错误路由至大语言模型节点。
- 现象：检索返回结果条数远低于预期，或出现资源占用过高的报错。原因：未根据工单更新频率配置增量索引，频繁触发全量索引任务消耗系统资源。

## 怎么确认配好了
- 上传单份工序卡文档，检查分块后的文本片段是否保留工序编号与工艺描述的关联，验证分块逻辑符合`maxToken`的配置要求。
- 提交包含刀具更换记录的工单数据，验证索引是否在数据更新后触发，无延迟或遗漏的记录。
- 调整相似度阈值，检查检索结果的匹配度是否符合业务预期，无过度匹配或匹配不足的情况。
- 查看系统日志，确认向量模型的调用请求未被错误路由至其他节点，符合配置要求。
