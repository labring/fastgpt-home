# 金属切削加工的检验与过程记录审核：工具调用与插件

## 这个品类的数据长什么样
金属切削加工的检验与过程记录数据，来源包括产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES系统及量检具数据。数据更新随每工单、每件工件加工、抽检环节或刀具更换触发。日常文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表及量具校准记录，字段包含刀具寿命（单位：分钟）、工序尺寸公差（单位：毫米）、检验结果、数控程序编号等。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据接入要求工具需支持对接不同系统的API接口，适配各类数据格式差异。高频更新特性要求工具调用触发时机需与工单、刀具更换等业务节点绑定，避免冗余请求。多样的文档结构要求工具需针对数控程序、检验记录等不同类型文档设置专属解析规则。带单位的字段要求工具调用后需完成单位校验与转换，确保提取数据的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `toolChoice` | `auto` | 适配金属切削加工场景下工序卡、检验记录、刀具数据等多类型工具调用需求 |
| `functionCall` | 启用 | 需调用外部系统获取实时刀具磨损、机床加工参数等业务数据 |
| 工具调用超时时间 | 120–180 秒 | 机床、刀具管理系统接口存在一定响应延迟，预留充足数据拉取时间 |
| 并发调用上限 | 前 3 条 | 单工单关联的检验、工序、刀具数据量有限，避免超出系统限流阈值 |
| 工具调用上下文长度 | 8000–12000 token | 适配FastGPT v4.17.0版本的上下文处理规则，覆盖完整工单关联数据 |
| 工具结果后处理规则 | 按实测标定 | 不同车间的检验记录格式存在差异，需根据实际文档调整字段抽取逻辑 |

## 容易做错的三处
- 现象：调用本地部署大模型时返回连接超时错误。原因：未正确配置本地大模型的API访问地址与端口，或未开放对应网络权限。
- 现象：工具调用结果不稳定，返回字段为空或格式混乱。原因：未针对金属切削加工的工序尺寸、刀具磨损等专属字段设置抽取规则，导致无法精准提取有效数据。
- 现象：并发调用时返回429状态码。原因：并发调用上限设置过高，超出了MES或刀具管理系统的接口限流阈值。

## 怎么确认配好了
- 提交单工单测试请求，查看工具调用返回结果是否包含刀具寿命、工序尺寸公差等金属切削加工专属字段。
- 模拟多工单并发请求，检查接口返回状态码是否正常，无限流报错。
- 调整`toolChoice`参数为`auto`，验证工具是否能自动匹配对应数据源的API完成数据拉取。
- 查看工具调用日志，确认超时时间设置符合实际接口响应时长，无频繁超时提示。
