# 金属切削加工的检验与过程记录审核：文档解析与分块

注：本页配置适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的典型数据来自机加工厂、精密零部件厂及装备企业机加车间，日常文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表、量具校准记录。数据来源覆盖产品图纸与三维模型、CAPP/CAM系统、机床采集数据、刀具管理系统、MES系统及量检具数据。更新频率随工单、单件工件、抽检批次或刀具更换动作触发，文档多包含工序尺寸、刀具寿命、检验参数等带特定单位的结构化字段。

## 这些特征在「文档解析与分块」这一环带来什么约束
本品类的文档特征对解析分块带来多重约束。首先，文档类型多样，包含文本、表格、数控代码等多种格式，需适配不同拆分逻辑；其次，更新频率高且单份文档可能随工单迭代调整，需支持快速解析；再者，结构化字段多且带特定单位，分块需保留字段关联避免信息断裂；最后，部分文档体积较大，需支持大文件解析而不破坏内容完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 金属切削加工文档多含连续的工序参数、尺寸公差，该长度可保留工艺逻辑关联，避免分块过碎或过长 |
| `chunkSplitter` | 按段落+表格拆分 | 适配工艺路线、巡检表的表格格式与数控程序的代码块格式，保留结构化内容完整性 |
| `customPdfParse` | 开启 | 针对工序卡、检验记录等PDF格式文档，保留表格结构与字段关联，避免解析后内容混乱 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持大型数控程序、完整工艺手册上传，适配车间批量工单文档的上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 大型加工文档解析耗时较长，该时长可避免超时中断，保障完整解析 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（工序卡、数控程序）调整分块参数，适配品类特性 |

## 容易做错的三处
- 10M以上文件上传后生成1000+块，部分chunk向量化异常。现象为上传大体积工艺手册或数控程序后，知识库分块列表出现大量短块，部分块内容为空或无法正常向量化。原因是未针对品类文档调整`chunkSize`参数，分块过碎导致向量化时上下文断裂，无法关联连续的工艺参数。
- 反复点击重试后异常消失。现象为上传异常后多次点击重试按钮，异常状态消失但未根治。原因是解析过程受临时节点负载或网络波动影响，临时重试可绕过临时故障，但未修复分块逻辑的适配问题。
- 飞书在线表格导入后字段为空。现象为导入飞书巡检表或量具校准表格后，知识库中仅保留表头，无具体检验数据。原因是未开启结构化解析配置，无法正确提取表格中的带单位结构化字段。

## 怎么确认配好了
- 上传一份典型的工序卡PDF，检查分块后是否保留了工序号、尺寸公差、检验标准等连续字段。
- 上传单份100MB以上的数控程序文件，确认解析进度未出现超时报错。
- 查看知识库分块列表，确认每个chunk的内容未出现表格断裂、代码块截断的情况。
- 触发一次批量上传测试，检查多份工单文档的分块数量与内容完整性是否符合预期。
