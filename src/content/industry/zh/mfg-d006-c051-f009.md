# 金属切削加工的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
金属切削加工的数据来源包括产品图纸与三维模型、CAPP/CAM系统、机床采集数据、刀具管理系统、MES系统、量检具校准记录。数据更新节奏为每工单、每件工件、抽检批次或刀具更换时触发。日常文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表、量具校准记录，包含工序编号、刀具型号、检验尺寸、偏差值、量具编号等字段，单位多为毫米、转每分钟、进给量毫米每转等加工专属单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且更新频繁，每工单、刀具更换或抽检批次均会产生新文档，要求模型接入配置需适配多源异构数据的上下文长度。专业文档包含数控程序、量具校准记录等带专属单位的字段，需保证模型输出格式与原始文档一致，避免随意修改符号、大小写或空格。高频更新的数据会带来较大的上下文负载，需限制单轮处理的文档总量，同时适配不同类型文档的输入长度，避免因上下文超限导致处理失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配该品类多工序文档、数控程序的总长度，避免单轮处理上下文超限 |
| `maxTokens` | 2000–3000 token | 满足检验记录审核、偏差分析的输出长度需求，避免截断关键结论 |
| `quoteMaxToken` | 1500 token | 限制单条引用文档的长度，适配工序卡、刀具清单等单文档的字符量 |
| `temperature` | 0.1–0.3 | 保证输出格式严谨，避免随意修改原始文档的符号、大小写或空格 |
| 工作流/API 工具选择配置 | none | 该场景无需调用外部工具，仅需基于知识库文档完成审核与记录整理 |
| `vision` | 开启 | 适配产品三维模型、首件检验照片等视觉类文档的识别与审核 |

## 容易做错的三处
- 模型输出时出现多余空格或字母大写。原因：未将`temperature`设置为较低区间，导致模型随意修改原始文档的格式与符号。
- 本地部署模型对接后返回500错误。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或本地模型端口未开放访问权限。
- 上下文处理超时或文档截断。原因：`maxContext`设置过大，超出FastGPT v4.17.0的单轮处理上限，或未限制`quoteMaxToken`导致单条引用过长。

## 怎么确认配好了
- 上传单份工序卡与数控程序文档，触发审核任务，检查输出结果是否保留原始文档的符号、大小写与空格。
- 调用本地部署的模型接口，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无500报错返回。
- 导入多份同工单的关联文档，检查上下文加载无截断，输出结果覆盖所有关联文档的关键信息。
- 调整`temperature`参数，对比不同取值下的输出格式稳定性，确认取值区间符合严谨性要求。
