# 钢材轧制与精整的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自热轧、冷轧、型钢、钢管企业的板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与MES系统。日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书，数据按每卷或每支钢坯更新，部分参数为实时同步。数据字段包含批次编号、加热温度、轧制压下量、厚度公差、表面缺陷等级等，对应单位为摄氏度、毫米、百分比等，文档以结构化表格与非结构化报告形式并存。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时或按卷级更新的数据会带来高频索引更新需求，需适配小批量、高频率的向量入库操作，避免单次入库耗时过长影响生产数据同步。多类型文档结构要求索引同时支持结构化字段关联与非结构化文本语义召回，避免单一索引维度的召回偏差。每卷或每支的细粒度数据需保留批次溯源关联，索引需绑定批次编号作为元数据字段，确保召回结果可追溯至对应钢卷。同时，表面质量报告、质保书等非结构化文档的长文本内容，需适配合理的分块规则，避免语义断裂影响召回精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配轧制规程、表面质量报告等长文本的语义完整性，避免单块内容断裂 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的语义关联，适配实时更新的短周期数据块衔接 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 匹配钢材检验中缺陷判定的严格度，避免误召回或漏召回 |
| `defaultToken` | 4096 | 适配质保书等长文档的最大输入限制，符合FastGPT v4.17.0的默认配置 |
| 最大上下文 | 8000 字符 | 整合多份关联文档的检验与过程记录，支撑全批次追溯的语义召回 |
| `maxToken` | 8192 | 匹配向量模型的最大输入token上限，确保长文本分块后可完整嵌入向量空间 |

## 容易做错的三处
- 现象：手动插入的检验记录文档对应的索引在数小时后自动消失。原因：未配置索引的持久化存储策略，FastGPT默认的临时索引缓存未绑定批次元数据，导致随内存回收被清除。
- 现象：更换embedding模型后，全量历史轧制数据的召回率无明显提升。原因：未执行全量数据的批量重嵌入流程，仅更新了新增文档的向量，历史数据仍使用旧模型生成的向量，新旧向量空间不匹配。
- 现象：表面质量报告的向量生成失败，检索时出现报错提示。原因：未按`maxToken`配置截断长文本分块，超出本地embedding模型的输入限制，导致模型无法处理输入内容。

## 怎么确认配好了
- 上传一份轧制计划文档，查看向量生成日志，确认分块长度、重叠长度与配置值一致，验证`defaultToken`与`maxToken`的匹配性。
- 手动触发单批次钢坯数据的索引更新，检查知识库索引列表中是否保留该批次的编号标签，确认索引未被自动清除。
- 更换embedding模型后，执行全量数据的重嵌入操作，查看知识库的向量更新状态，确认所有历史文档均完成重嵌入。
- 发起一次检验记录检索，设置批次编号过滤条件，检查返回结果是否仅包含目标批次的相关文档，确认相似度阈值的过滤逻辑生效。
