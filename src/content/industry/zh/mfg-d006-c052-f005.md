# 钢材轧制与精整的检验与过程记录审核：工具调用与插件

## 这个品类的数据长什么样
钢材轧制与精整的检验数据来源包括板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与MES系统。日常产出的文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书，字段涵盖批次号、炉号、板形偏差、厚度公差、表面缺陷等级等，单位包含毫米、微米、吨等。数据更新频率为每卷或每支钢坯/钢卷实时更新，支持卷级全链路追溯。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据具有实时性强、卷级粒度细、专业字段多且单位特定的特征，要求工具调用需适配高频小批量的数据拉取需求，避免批量拉取导致的资源占用过高。同时，专业文档的字段格式固定，插件需具备解析特定业务字段的能力，确保审核时能准确提取板形、厚度等核心检验数据。此外，数据出错会导致钢卷降级、设备损伤等严重后果，工具调用需配置校验逻辑与重试机制，保障数据准确性与流程稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | `auto` | 适配多工具并行调用的轧制检验场景，自动选择匹配的工具完成数据拉取与审核 |
| 工作流/API 函数调用配置 | `required` | 强制调用工具完成检验与记录审核，避免纯文本回答无法覆盖专业业务逻辑 |
| 单次工具调用超时 | `30–60 秒` | 匹配轧机数据拉取、MES查询的常规响应时长，避免过长等待影响实时审核流程 |
| 工具调用重试次数 | `2 次` | 应对临时网络波动或接口抖动，同时避免重试过多导致的流程阻塞 |
| 上下文窗口大小 | `8000–12000 token` | 适配轧制检验文档的多字段数据长度，容纳完整的批次检验记录 |
| 工具返回结果过滤规则 | 保留核心检验字段 | 减少冗余数据占用上下文窗口，聚焦板形偏差、厚度公差、表面缺陷等关键审核项 |

## 容易做错的三处
- 现象：调用本地部署的m3e模型后返回空结果或加载失败，日志显示参数校验不通过。原因：FastGPT v4.17.0及以上版本中，openapi部署本地模型的路径校验逻辑更新，未同步调整自定义配置中的模型路径参数。
- 现象：searxng插件调用后搜索结果为空，界面显示无匹配内容。原因：未配置searxng的数据源过滤规则，导致检索范围未覆盖轧制工艺相关的行业文档。
- 现象：图表工具调用后生成的轧制趋势图为空。原因：未指定正确的时间粒度字段，如未绑定每卷轧制的时间戳字段，导致工具无法匹配到有效数据序列。

## 怎么确认配好了
- 发起一次模拟的单卷钢坯检验请求，查看工具调用日志是否正确拉取对应批次的MES系统数据与在线检测记录。
- 进入模型配置页面，确认本地m3e模型的部署路径与配置参数一致，无校验报错提示。
- 手动触发searxng插件调用，输入「热轧板形控制规程」等行业关键词，查看是否返回匹配的专业文档。
- 触发图表工具调用，确认传入的参数包含板形偏差、轧制时长等有效业务字段，无空值或非法格式数据。
