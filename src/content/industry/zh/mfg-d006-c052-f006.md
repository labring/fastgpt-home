# 钢材轧制与精整的检验与过程记录审核：引用来源与溯源

## 这个品类的数据长什么样
本品类数据主要来自热轧、冷轧、型钢、钢管生产环节，涵盖轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书等文档。数据来源包含板坯/钢坯批次信息、加热炉运行参数、轧机自动控制数据、在线测厚测宽结果、表面检测结果及MES系统记录。数据更新频率为每卷或每支实时更新，文档字段包含批次编号、工艺参数、检测数值、缺陷位置与等级等，单位多为毫米、摄氏度、平方米等工业标准单位。

## 这些特征在「引用来源与溯源」这一环带来什么约束
本品类的实时卷级更新、多源工业数据关联、批次强绑定的特征，对引用溯源环节带来多重约束。首先，需精准匹配板坯/钢坯批次号，避免跨批次引用不相关的工艺或检测数据，防止溯源结果出现偏差。其次，实时更新的在线检测数据需与离线质保书等文档同步关联，确保溯源结果覆盖从原料到成品的全流程环节。此外，卷级追溯的核心需求要求引用结果必须绑定具体卷号，不能泛化引用通用工艺规程，需明确区分通用规则与单卷实际执行参数。

## 配置怎么定
FastGPT v4.17.0 下的配置参考如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `quoteMaxToken` | 8000–12000 token | 匹配单卷全流程文档的总长度，避免截断关键批次与检测数据 |
| 单次搜索上限 | 前8条 | 覆盖同批次下多源检测与工艺记录的数量，避免遗漏关键溯源信息 |
| `responseData` | 开启来源文件名与卷号字段 | 直接提取文档中绑定的卷号与来源标识，无需额外解析 |
| `detail` | 完整模式 | 保留原始文档的字段层级，便于核对缺陷位置、工艺参数等溯源细节 |
| 最大上下文 | 600 秒 | 适配工业数据实时更新的节奏，确保检索时调用最新的批次关联数据 |
| 重排 | 按批次优先级排序 | 优先返回同批次的文档，缩短溯源匹配的时间 |

## 容易做错的三处
- 检索结果仅返回1条文档。原因是未调整单次搜索上限的取值，默认配置限制了召回数量，无法覆盖同批次多源数据。
- 调用时知识库为空，需手动选择目标数据集。原因是未配置默认绑定的卷号关联知识库，系统无法自动匹配对应批次的文档集合。
- 引用的来源文档无法下载。原因是未开启`responseData`的完整字段提取，未保留文档的原始存储路径与访问权限标识。

## 怎么确认配好了
- 发起针对某卷号的溯源查询，核对返回结果中是否包含该卷号的所有关联文档。
- 查看返回结果的来源字段，确认是否包含完整的文件名、卷号与数据来源标识。
- 测试调整`quoteMaxToken`的取值，验证是否能完整返回长文档的全部内容。
- 检查检索结果的排序逻辑，确认同批次文档优先展示。
