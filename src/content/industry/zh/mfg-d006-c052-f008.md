# 钢材轧制与精整的检验与过程记录审核：文档解析与分块

## 这个品类的数据长什么样
本品类数据来自热轧、冷轧、型钢、钢管生产企业的生产全流程，核心文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告与质保书。数据来源覆盖板坯/钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与MES系统，更新频率为每卷或每支钢件实时生成，文档字段包含毫米级厚度值、表面缺陷等级、生产批次编号与工艺参数，格式涵盖PDF报表、XLS生产台账与PPT工艺说明。

## 这些特征在「文档解析与分块」这一环带来什么约束
高频实时的单卷/单支文档生成要求解析与分块支持快速批量处理，避免单文件解析超时。多格式文档覆盖PDF工艺报表、XLS生产台账、PPT工艺说明，要求适配不同结构的解析规则，尤其是XLS多行表格与PPT图文混排内容。卷级追溯的业务需求要求分块保留生产批次关联信息，避免跨批次内容混杂。文档中包含毫米级厚度值、缺陷等级等带明确单位的字段，要求解析时保留字段单位与对应数值的绑定关系，确保分块后语义完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配本品类带单位的工艺参数与批次信息的语义完整性，避免单块内容拆分断裂 |
| `chunkSplitter` | 按段落+语义边界 | 适配轧制规程、表面质量报告等带逻辑段落的文档，保留工艺说明的连贯性 |
| `customPdfParse` | 启用表格结构化解析 | 适配本品类PDF报表中的板形厚度记录、质保书等多列表格，提取完整字段与数值 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单批次批量上传的大尺寸质保书与轧制计划台账 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配高频实时生成的单卷文档解析，避免小批量多文件处理超时 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（XLS台账、PPT工艺说明）调整分块参数，适配本品类多格式文档特征 |

本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：上传PPT工艺说明时，解析过程抛出“the argument ‘windows-1252’ is invalid encoding”报错。原因：未配置适配中文内容的编码解析规则，默认编码无法识别中文文本导致解析失败。
- 现象：上传XLS生产台账后，分块结果中多行表格的批次号与厚度值拆分错位。原因：未启用`customPdfParse`的XLS结构化解析功能，默认按行拆分破坏了表格的关联逻辑。
- 现象：批量上传单卷钢件的多份文档时，部分解析任务超时失败。原因：未将`PARSE_FILE_TIMEOUT_SECONDS`调整至符合高频实时文档处理的取值，默认阈值无法覆盖多文件并行解析的耗时。

## 怎么确认配好了
- 上传一份本品类典型的XLS生产台账，检查分块结果中是否保留了批次号、厚度值的完整关联，无字段错位情况。
- 上传一份包含中文工艺说明的PPT文档，确认解析过程无编码报错，分块内容覆盖完整的工艺段落。
- 批量上传10份单卷钢件的文档，检查解析任务是否在`PARSE_FILE_TIMEOUT_SECONDS`设定的阈值内完成，无超时失败。
- 调整`chunkSize`至不同取值，验证分块后的内容是否保留了工艺参数与单位的绑定关系，无语义断裂。
