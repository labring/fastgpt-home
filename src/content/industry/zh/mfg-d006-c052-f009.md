# 钢材轧制与精整的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自板坯或钢坯批次、加热炉、轧机自动控制、在线测厚测宽、表面检测、MES系统，更新节奏为每卷或每支钢料实时生成。日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书，文档字段包含批次标识、工艺参数、检测数据、质量判定结果等，涵盖数值型检测值与文本型判定结论两类内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据按单卷或单支钢料实时生成，单批次文档包含多维度工艺参数与检测结果，且需关联批次全流程数据完成审核。该特征带来三方面约束：一是单批次数据量较大，需合理配置上下文窗口避免截断有效信息；二是数据实时更新，需保证模型接入时的检索响应匹配生产节奏；三是文档包含混合格式内容，需适配结构化检测数据与文本判定的处理逻辑，同时需满足审核环节对结果准确性的严格要求，避免因配置不当导致判定偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 单批次轧制相关文档的总token数通常在该区间，避免截断关键工艺与检测数据 |
| `maxTokens` | `2000–3000 token` | 审核结论需包含缺陷判定、批次追溯说明，该长度可覆盖完整输出需求 |
| `quoteMaxToken` | `1500 token` | 需保留检测数据原文作为审核依据，避免引用内容过长导致上下文溢出 |
| `temperature` | `0.1–0.3` | 审核环节需保证判定结果的一致性，较低温度可减少随机偏差 |
| `AIPROXY_API_ENDPOINT` | 企业内部工业网络专属代理地址 | 本品类核心数据存储于内网系统，需通过代理实现安全且合规的模型接入 |

## 容易做错的三处
- 现象：上传批量轧制相关文档后，语料处理耗时显著超出预期。原因：未针对该品类文档的多字段混合结构选择适配的预处理方式，导致预处理模块重复解析冗余内容。
- 现象：配置`AIPROXY_API_TOKEN`时，界面返回Error 1406 (22001): Data too long for column 'models'。原因：令牌参数值过长，超出系统存储字段的预设长度限制。
- 现象：尝试接入MemoRAG扩展功能后，模型无法正常检索表面检测数据。原因：未确认FastGPT v4.17.0版本对MemoRAG的适配兼容性，直接导入未兼容的扩展代码。

## 怎么确认配好了
- 上传单卷钢料的完整文档集合，查看模型输出的审核结果是否包含批次标识、工艺参数、检测数据等核心字段。
- 模拟实时上传新生成的表面质量报告，检查检索响应时间是否匹配生产节奏。
- 输入包含长文本判定结论的测试问题，确认模型输出长度未超出`maxTokens`配置的限制。
- 检查`AIPROXY_API_ENDPOINT`的网络连通性，确保内网数据可正常同步至模型服务。
