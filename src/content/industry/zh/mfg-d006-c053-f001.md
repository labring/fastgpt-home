# 钢铁冶炼与连铸的检验与过程记录审核：HTTP 接口与外部系统

## 这个品类的数据长什么样
钢铁冶炼与连铸的检验与过程记录审核涉及多部门协同，日常文档包含炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单。数据来源覆盖铁水与废钢采集系统、L2过程控制系统、化验室检测系统、MES生产管理系统、能源介质系统与设备状态监测系统。数据更新节奏分为三类：每炉次生成冶炼与连铸的实时过程数据，每班汇总板坯质量判定结果，关键指标实时同步。数据字段包含炉次编号、铁水重量、冶炼时长、拉速、成分指标等，单位涵盖吨、分钟、米/分钟、摄氏度。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据来源要求接口需支持跨系统的数据拉取与推送，适配不同系统的鉴权与数据格式。差异化的更新节奏要求接口配置灵活的触发机制，既支持实时同步L2过程数据，也支持按炉次或班次触发批量同步。关联紧密的文档结构要求接口传递关联字段，确保不同系统的文档可通过炉次编号等标识匹配。高温连续生产的特性要求接口具备高可用性，避免因接口异常中断生产流程，同时需校验数据完整性，防止错误数据引发炉次降级或报废。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer ${token}，有效期按1小时标定` | 适配钢铁厂L2系统的鉴权规则，避免鉴权失效导致接口调用失败，符合FastGPT v4.17.0的鉴权逻辑 |
| `variables` | `包含炉次编号、拉速阈值、成分指标范围，按实测标定` | 传递该品类特有的业务变量，实现不同系统文档的关联匹配 |
| `responseData` | `仅返回有效炉次的非空字段，过滤异常数据` | 减少无效数据传输，提升审核流程的效率与准确性 |
| 重试次数 | 3次，间隔10秒 | 应对临时网络波动或系统延迟，保障高温生产场景下的数据同步不中断 |
| 触发时机 | 每炉次冶炼结束后、每班汇总前 | 匹配该品类的更新频率，确保审核数据及时同步至目标系统 |

## 容易做错的三处
- 接口返回`401 Unauthorized`状态码，原因是未按L2系统的鉴权周期更新`Authorization`令牌，导致鉴权失效。
- 同步的板坯判定单字段为空，原因是未正确传递炉次编号作为`variables`参数，无法匹配对应炉次的冶炼记录。
- 接口调用超时，原因是未设置合理的超时阈值，钢铁厂L2系统的批量数据响应延迟超过默认调用时长，引发生产流程中断风险。

## 怎么确认配好了
- 调用测试接口，检查`responseData`返回的字段是否包含该品类特有的炉次编号、冶炼时长等内容，调整字段过滤规则至符合业务需求。
- 模拟炉次结束触发接口调用，核对`Authorization`令牌的有效期是否匹配系统要求，调整刷新周期适配实际场景。
- 查看接口调用日志，确认重试次数符合预设配置，排查临时网络波动下的自动重试逻辑是否生效。
- 对比MES系统的炉次记录与接口同步的数据，确认关联字段匹配无误，调整`variables`参数的传递规则。
