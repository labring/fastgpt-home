# 铸造（砂型、精密、压铸）的检验与过程记录审核：文档解析与分块

## 这个品类的数据长什么样
本品类的主体为铸造厂、压铸车间及装备零部件供应商的铸造工艺与质量部门，日常产生的文档涵盖铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告、不合格品评审单。数据来源包括ERP物料主数据、熔炼炉与测温仪、光谱仪、MES炉次记录、模具管理系统、客户图纸与技术条件，更新频率为每炉次、每批或每日。文档包含结构化的工艺参数、质量检测字段，涉及合金配比、熔炼温度、浇注参数、缺陷类型等内容。

## 这些特征在「文档解析与分块」这一环带来什么约束
文档类型多样且包含大量结构化表格，要求解析工具能准确识别表格结构并保留字段关联关系。高频更新的文档（如每炉次生成的炉次记录）要求分块规则适配快速迭代的内容，避免因分块不当导致关键工艺数据被拆分。不同来源的文档存在编码差异，部分老旧归档文档可能使用非标准编码，增加解析容错难度。单份文档篇幅跨度大，从单页配料单到多页模具履历均有覆盖，要求分块配置兼顾短文档与长文档的处理需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配铸造文档中工艺参数、缺陷记录的字段长度，避免拆分关键参数组合 |
| `chunkSplitter` | 按表格+段落拆分 | 适配配料单、炉次记录的多行表格结构，保留数据关联性 |
| `customPdfParse` | 开启 | 适配铸造工艺卡、材质报告的复杂排版，提取结构化字段 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 覆盖熔炼记录、模具履历等多页文档的解析耗时 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单炉次的多份归档文档批量上传 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（如xlsx表格、pdf工艺卡）调整分块规则 |

## 容易做错的三处
- 现象：上传xlsx配料单后，表格字段为空或拼接混乱。原因：未配置按表格拆分的分块规则，默认分块拆分了表格的行与列关联关系。
- 现象：解析pdf炉温记录时抛出“the argument ‘windows-1252’ is invalid encoding”报错。原因：未指定适配铸造文档的编码格式，默认编码无法识别文档中的特殊工艺符号。
- 现象：批量上传多份炉次记录时解析超时。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以处理多页归档文档。

## 怎么确认配好了
- 上传一份标准铸造配料单xlsx，检查解析后的分块是否保留了每行配料的完整参数组合。
- 上传一份带特殊字符的pdf炉温记录，确认无编码报错且内容完整提取。
- 上传一份超过默认上传大小的模具履历文档，确认上传成功且解析完成。
- 调整`chunkSize`参数后，对比不同分块长度下的分块结果，确认符合业务字段的拆分逻辑。
