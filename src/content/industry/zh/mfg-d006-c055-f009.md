# 铸造（砂型、精密、压铸）的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档包含铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告、不合格品评审单。数据来源于ERP物料主数据、熔炼炉与测温仪、光谱仪、MES炉次记录、模具管理系统及客户图纸与技术条件。数据更新以每炉次、每批为基础，每日同步汇总，字段包含合金配料比例、熔炼温度、浇注参数、缺陷类型等，附带质量单位与工艺参数单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据高频更新、多源异构且包含专业工艺字段，要求模型接入配置适配高频数据同步需求，支持多数据源的上下文拼接。专业术语与单位的准确识别需要配置匹配铸造行业的模型微调适配，炉次、模次的追溯需求则要求配置支持长上下文的关联查询能力。同时，不同文档的字段格式差异，要求配置可灵活适配多类型文档的解析规则，避免因字段不匹配导致的解析错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配铸造文档的长上下文拼接需求，覆盖炉次记录、工艺卡等多文档关联的内容长度 |
| `maxTokens` | 2000–3000 token | 满足专业工艺参数与缺陷判读的输出长度需求，避免截断关键判定信息 |
| `quoteMaxToken` | 1500–2000 字符 | 限制引用源文档的长度，确保检索结果与上下文匹配的精准度 |
| `temperature` | 0.2–0.4 | 降低随机性，保证工艺参数核对与缺陷判定的结果一致性 |
| `AIPROXY_API_ENDPOINT` | 按对接模型的官方接入地址填写 | 适配不同大模型的接入路径，确保模型调用的连通性 |
| `AIPROXY_API_TOKEN` | 按平台生成的有效令牌填写 | 完成模型接入的身份验证，保障调用权限合法 |

## 容易做错的三处
-  配置`AIPROXY_API_ENDPOINT`时填写错误的接入地址，导致调用时返回「找不到渠道」报错。原因是未匹配对应大模型的官方接入路径，或遗漏了路径中的版本标识参数。
-  未正确配置`toolChoice`参数，导致文本提取模块仅显示GPT系列模型选项。原因是未绑定GLM等其他模型的适配标识，默认仅加载了通用大模型的适配规则。
-  配置`maxContext`时取值过大，导致单次调用超时。原因是超出了模型本身的上下文窗口限制，或FastGPT v4.17.0的上下文拼接逻辑未做分段优化。

## 怎么确认配好了
-  发起一次炉次记录的解析测试，检查模型返回的配料比例核对结果是否包含文档中的原始字段值，确认`maxContext`与`maxTokens`配置未截断关键信息。
-  调用模型进行缺陷追溯测试，检查是否能关联炉次记录与不合格品评审单的内容，确认多源上下文拼接配置生效。
-  查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置已完成身份验证，无连接报错。
-  调整`temperature`参数并对比两次判读结果，确认参数配置对输出随机性的影响符合预期。
