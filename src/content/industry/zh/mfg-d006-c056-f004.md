# 锂离子电芯制造的检验与过程记录审核：工作流编排

## 这个品类的数据长什么样
锂离子电芯制造的检验与过程记录数据，来源包括MES生产系统、浆料与涂布检测设备、露点监测仪、化成分容柜、实验室OCV与安全测试报告。数据更新节奏为每批次电芯、每只成品电芯实时生成。日常文档包含配料记录、涂布辊压参数、卷绕或叠片记录、注液记录、化成分容数据、OCV测试报告，字段包含批次号、电芯编号、浆料固含量、涂布面密度、压实密度、露点温度、内阻、容量等，各文档关联唯一的原材料批次与电芯标识。

## 这些特征在工作流编排这一环带来什么约束
该品类的数据实时性强且按批次/单电芯生成，要求工作流需绑定唯一标识触发，避免不同批次的审核流程混淆。多源数据来自不同设备与系统，需配置节点间的字段映射规则，确保不同格式的检验记录可统一关联。电化学体系对水分、洁净度敏感，需在工作流中加入阈值校验节点，确保环境与工艺参数符合要求。数据关联的一致性直接影响电池安全与寿命，需配置失败分支的回溯与告警机制，避免不合格记录流入后续环节。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，具体如下表：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次搜索上限 | 前5条 | 锂离子电芯的单批次检验记录字段较多，过多搜索结果会占用上下文，影响审核效率 |
| 变量存储方式 | 全局持久化`variables` | 每批次电芯的标识需跨节点保留，避免节点运行时重置临时变量 |
| 节点触发规则 | 按`nodeId`绑定批次ID触发 | 数据按批次更新，需确保每个批次的审核流程独立不被其他批次干扰 |
| 失败重试次数 | 2次，间隔60秒 | 设备数据拉取可能出现临时网络波动，重试可减少无效的流程中断 |
| 节点超时时间 | 300秒 | 单批次检验数据的拉取与审核需要一定时长，避免过早超时中断流程 |
| 上下文长度 | 800–1200 token | 单批次检验记录的内容量适中，合适的上下文可确保审核逻辑完整且不溢出 |

## 容易做错的三处
- 现象：工作流中知识库搜索节点返回空结果，或配置应用变量时出现报错。原因：未将`variables`中的批次ID正确绑定到知识库检索条件，或未开启全局变量持久化导致批次标识丢失。
- 现象：Http请求后的多变量无法正确关联到指定知识库。原因：未按`nodeId`为每个批次的变量分配独立标识，导致多个批次的变量混淆匹配。
- 现象：工作流运行后全局变量被清空，无法跨节点保留批次信息。原因：未配置`variables`的持久化存储，默认配置下每次节点运行会重置临时变量。

## 怎么确认配好了
- 手动触发单批次电芯的审核流程，检查各节点的变量是否正确传递，确认`variables`中的批次ID在后续节点中正常显示。
- 模拟设备数据拉取失败的场景，检查失败分支是否触发重试或告警流程，确认失败重试配置生效。
- 对比多源数据的字段，检查字段映射规则是否将不同系统的记录按批次号正确关联，确认关联逻辑无误。
- 运行多批次并行的审核流程，检查每个批次的变量是否独立存储，未出现跨批次混淆的情况。
