# 锻造与模锻的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
该品类的数据覆盖锻造全流程，来源包括原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图。日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告。数据更新以每件锻件、每批物料或每炉次为节奏，字段涵盖锻件批次号、炉批号、变形工步参数、检测缺陷数值等，既有结构化的采集数据，也有非结构化的工艺与检测文档。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据高频更新、多类型混合且业务关联性强，对向量模型与索引环节带来多重约束。高频的单件/单炉次更新要求索引支持增量更新，避免全量重索引的额外耗时。结构化采集数据与非结构化工艺、检测文档并存，要求向量模型适配混合格式的语义提取，同时需关联炉批号、锻件批次等元数据实现精准过滤。强业务关联的字段要求匹配逻辑需结合业务主键，避免语义相似但业务无关的记录被召回，同时需满足高准确率要求以规避锻件报废等风险。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配锻造工艺规程、超声检测报告的单段内容长度，避免语义断裂 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工艺参数、检测序列的上下文关联 |
| 相似度阈值 | 0.75–0.85 | 匹配锻件批次、炉批号这类强关联字段，降低误匹配概率 |
| `maxToken` | 4096 token | 容纳单批次锻件的全流程记录与多份检测报告内容 |
| `defaultToken` | 2048 token | 满足常规检验审核的上下文调用需求 |
| 单次搜索上限 | 前 8 条 | 覆盖同炉次、同批次的关联数据，避免遗漏关键记录 |

## 容易做错的三处
- 现象：索引召回结果中出现非当前炉次的锻件记录，业务字段为空。原因：未针对锻件批次、炉批号设置专属元数据过滤，仅依赖向量语义匹配导致误召回。
- 现象：配置界面无法选择目标索引模型，弹出参数格式错误提示。原因：未按照要求配置`defaultToken`与`maxToken`的合法取值区间，触发平台校验拦截。
- 现象：批量索引单炉次锻件数据时出现超时，单次索引耗时超过300秒。原因：分块长度设置过大，导致单分块向量生成与索引写入耗时过长，未适配高频更新的数据节奏。

## 怎么确认配好了
- 上传单份锻造过程卡与超声检测报告，查看索引生成日志，确认分块数量与预期内容长度匹配。
- 输入包含目标炉批号或锻件批次的查询语句，查看召回结果的元数据标签，确认仅包含目标批次的关联记录。
- 测试调用索引接口，检查返回结果的字段完整性，确认`defaultToken`与`maxToken`的配置未截断关键工艺或检测内容。
- 模拟批量上传同批次锻件的多份记录，查看索引更新状态，确认增量更新功能正常生效。
