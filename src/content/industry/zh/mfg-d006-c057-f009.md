# 锻造与模锻的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源包括原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪、客户锻件图。数据更新按每件锻件、每生产批次或每炉次执行。日常生成的文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告，各文档对应炉批编号、锻件批次、工艺参数、检测结果等专属字段，无通用化的固定统计格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据多源异构且按生产批次更新，要求模型接入的上下文需精准匹配对应批次的全部关联文档，避免跨批次数据混淆。多来源的文档格式差异，要求模型输入需完成字段对齐与格式统一，否则会导致审核判定出现偏差。高频的生产数据更新节奏，要求模型接口的响应延迟需适配车间生产流程，避免阻塞检验环节。检验审核需核对材料炉批与锻件批次的对应关系，模型需具备关联多文档关联字段的能力，确保审核依据的准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的模型接入流程。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 需覆盖单炉次所有相关文档的总内容量，匹配锻造批次的完整审核需求 |
| `maxTokens` | `2000–3000 token` | 适配单批次检验审核的结果输出长度，避免截断关键判定内容 |
| `quoteMaxToken` | `1500 token` | 保留足够的原始文档引用片段，支撑审核结论的溯源验证 |
| `temperature` | `0.1–0.3` | 保障检验审核的判定结果严谨一致，降低随机偏差 |
| `AIPROXY_API_ENDPOINT` | 部署节点的内网访问地址 | 保障生产环境的数据传输安全，避免公网暴露敏感生产数据 |
| `AIPROXY_API_TOKEN` | 绑定专属调用权限的令牌 | 限制仅授权的锻造车间系统可调用模型接口，防止未授权访问 |

## 容易做错的三处
- 现象：调用模型时出现`connection refused`或`token encoder error`，原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或代理节点与模型服务的网络连通性异常。
- 现象：模型输出的审核结论缺失关键依据，原因：`maxContext`设置过小，未覆盖单炉次的全部关联文档，导致部分必要的工艺或检测数据未被纳入上下文。
- 现象：同批次锻件的审核结果出现随机差异，原因：`temperature`设置过高，导致模型输出的判定逻辑出现不必要的波动，不符合检验的严谨要求。

## 怎么确认配好了
- 调用模型接口，查看返回的响应状态码为200，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置有效。
- 输入单炉次的典型文档集合，检查模型输出的上下文覆盖范围符合`maxContext`的设置，无关键文档内容被截断。
- 输入多组同批次的测试数据，对比模型输出的判定结果一致性，确认`temperature`的取值符合严谨审核的需求。
- 上传包含标注信息的超声检测报告图片，启用`vision`配置，检查模型可正确识别并解析图片中的检测内容。
