# 预制混凝土构件的检验与过程记录审核：多轮对话与提示词

## 这个品类的数据长什么样
预制混凝土构件的数据来源于BIM深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行日志、试验室检验报告以及产品二维码追溯系统。日常业务文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据更新节奏为单件、每批或每窑一次，核心字段包含构件编号、钢筋规格型号、浇筑强度、养护温度与时长、脱模强度等，单位涵盖MPa、立方米、小时等工程常用单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
预制混凝土构件的多源分散数据要求对话需跨不同业务系统调取信息，多轮对话需保留从下料到脱模的完整环节上下文，避免关联错误。高频次的单件/批更新要求对话上下文不能无限制累积，需及时截断非关联历史记录。复杂的文档结构要求提示词需明确区分构件类型、检验环节与业务规则，防止流程偏移。同时，每个构件对应现场唯一吊装位置，对话需绑定专属标识，确保检验记录与对应构件精准匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按构件批次+模台编号生成唯一值 | 匹配预制混凝土构件按批、按模台生产的特征，确保同批次构件的对话上下文不与其他批次混淆 |
| `messages` | 保留最近20条对话+关联的3条历史检验记录 | 覆盖从钢筋下料到脱模检验的关键业务环节，控制上下文长度避免响应延迟 |
| `variables` | 预设构件编号、浇筑强度阈值、养护温度区间 | 快速调用品类专属业务参数，减少重复输入内容，提升对话效率 |
| 最大上下文 | 前 10000 字符 | 适配构件深化图与检验记录的文本长度，按实测标定调整具体取值 |
| 问题优化 | 开启 | 自动拆解复杂检验问题为分步校验逻辑，匹配多轮对话的流程化需求 |

## 容易做错的三处
- 对话被执行到错误流程操作，问题分类模块匹配失效。原因是未将`chatId`绑定对应构件批次，导致上下文混入其他构件的检验规则，触发错误分类逻辑。
- 对话无法正常使用，界面提示无响应。原因是未限制`messages`的保留长度，上下文数据量过大导致超时，匹配高频更新的检验记录特征。
- API调用后多出一条额外历史记录。原因是未在请求中正确传递`chatId`，系统自动生成了新的对话会话，导致重复记录。

## 怎么确认配好了
- 在FastGPT v4.17.0环境中，发起针对特定构件的检验对话，查看`chatId`是否包含对应批次和模台编号，确认上下文隔离生效。
- 调用API发起多轮对话，检查返回的`messages`列表长度符合预设的保留条数，无额外冗余记录。
- 模拟不符合规则的检验输入，验证对话是否触发正确的校验流程，确认问题分类逻辑匹配品类业务规则。
- 提交对话反馈，查看后台是否能将反馈绑定到对应`chatId`的会话中，确认点赞点踩功能正常。
