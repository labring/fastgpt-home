# 预制混凝土构件的检验与过程记录审核：工具调用与插件

## 这个品类的数据长什么样
预制混凝土构件的数据来源包括BIM或深化设计文件、钢筋与混凝土批次台账、模台与养护窑生产日志、试验室检测报告、产品二维码追溯系统。数据更新节奏按单件构件、每生产批次、每养护窑批次触发。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。字段包含构件唯一标识、钢筋规格、混凝土强度等级、养护周期、脱模强度值，单位涉及毫米、立方米、小时、兆帕。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散，涉及设计、生产、检测等多个独立系统，工具调用需适配多源接口对接。更新节奏按单件、批次触发，工具需支持按需调用，适配实时更新的生产与检测数据。文档类型包含图纸、台账、检测报告等多种格式，插件需兼容不同格式的内容解析。构件与现场吊装位置一一对应，工具返回的结果需绑定唯一构件标识，避免跨批次数据混淆。生产环节出错后果明确，工具调用需附带参数校验与失败重试逻辑，确保数据准确性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `["getBIMData", "getProductionLog", "getTestReport"]` | 预制混凝土构件的检验审核需同时拉取设计数据、生产记录与检测报告，指定工具列表可避免无效调用 |
| `functionCall` | 开启 | 需将检验审核的多步骤拆解为工具调用序列，自动调度对应插件完成数据拉取与校验 |
| HTTP请求超时 | 30-60秒 | 部分试验室检测接口响应较慢，该区间可覆盖多数正常请求时长，按实测标定 |
| 基础图表插件数据源绑定 | 关联构件唯一标识字段 | 需将图表生成与特定构件绑定，避免跨批次数据混淆 |
| reranker插件触发阈值 | 0.75-0.85 | 需过滤低相关性的检验记录数据，保留与当前构件强相关的检测报告，按实测标定 |
| 多模型请求头配置 | 按目标模型要求添加 | 不同多模态模型的参数格式存在差异，需匹配对应协议以避免参数报错 |

## 容易做错的三处
- 基础图表插件生成结果无对应构件数据。现象：图表展示的数据与当前审核的构件不匹配，字段为空或跨批次。原因：未将插件数据源绑定到构件唯一标识字段，导致数据拉取时未做精准匹配。
- HTTP模块调用外部接口失败，Postman可正常获取结果。现象：界面返回请求超时或403状态码，日志显示请求头缺失。原因：未在FastGPT配置中添加接口要求的身份验证参数，或未正确配置请求格式，导致接口拒绝访问。
- reranker插件调用成功但返回结果为false。现象：插件执行状态显示成功，但过滤后的结果为空或不符合预期。原因：输入的数据源相关性评分阈值设置不合理，或未将检验记录的核心字段传入插件，导致误判过滤。

## 怎么确认配好了
- 手动触发工具调用，输入指定构件的唯一标识，检查拉取的BIM数据、生产记录是否与该构件匹配。
- 复制Postman中可正常调用的接口请求，导入FastGPT的HTTP模块配置，执行调用验证返回结果一致。
- 调整reranker插件的阈值参数，观察过滤后的检验记录条数变化，确认阈值生效。
- 开启`functionCall`功能，提交检验审核任务，检查是否自动调度了预设的工具序列完成数据校验。
