# 预制混凝土构件的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来源包括BIM或深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行日志、试验室检测报告，以及构件二维码追溯数据。日常生成的文档涵盖构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据更新随单件构件、每批物料、每一养护窑批次触发，包含构件编号、钢筋规格、浇筑强度、养护时长、检验结果等字段，采用毫米、兆帕、小时等工程领域通用单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且更新频率高，单件构件、每批物料、每一养护窑批次均会触发数据更新，要求模型接入环节支持多源数据同步拉取。日常文档包含工程图纸与结构化台账两类格式，需要适配不同的解析逻辑。数据字段涉及工程专业参数，需确保模型调用时能准确识别构件编号、强度指标等关键信息，避免因配置不当导致解析遗漏或错误。此外，数据更新的实时性要求，会对上下文窗口的刷新逻辑带来约束。

## 配置怎么定
本页适用FastGPT v4.17.0

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多源文档的上下文长度，覆盖深化图解析、多批次数据的关联校验 |
| `maxTokens` | 2000–3000 token | 限制单轮输出长度，避免结构化结果被截断 |
| `toolChoice` | auto | 自动选择调用工具处理图纸解析、台账查询等任务，适配多类型文档 |
| `vision` | 开启 | 用于解析构件深化图、钢筋下料单等带图形的文档，提取尺寸与预埋件位置信息 |
| `temperature` | 0.1–0.3 | 降低随机性，确保检验审核结果的一致性，避免专业参数解读偏差 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或云端的代理服务地址，确保模型调用链路正常 |
| `AIPROXY_API_TOKEN` | 按实测标定 | 匹配代理服务的认证凭证，保障接口调用的安全性 |

## 容易做错的三处
- 调用自定义工具时出现调用失败。现象：界面显示工具调用超时或返回认证失败。原因：未正确配置`AIPROXY_API_TOKEN`导致接口认证失败，或未开启`toolChoice`为auto导致工具调用未触发。
- 处理文件解读时出现两次请求且第二次Authorization字段错误。现象：日志显示两次请求，第二次请求的Authorization字段为空或无效。原因：上下文窗口配置不当导致请求分片后，后续请求未正确继承认证参数，或`maxContext`设置过小导致分片逻辑异常。
- 对话中出现`Unexpected end of JSON input`报错。现象：控制台返回该报错文案。原因：模型返回的解析结果未正确闭合JSON结构，或`maxTokens`设置过小导致输出被截断，未完成完整的结构化返回。

## 怎么确认配好了
- 上传单份构件深化图，检查模型是否能正确提取钢筋规格、预埋件位置等关键信息，确认`vision`配置生效。
- 发起包含多源数据的校验请求，检查模型是否自动调用对应工具拉取台账数据，确认`toolChoice`配置正确。
- 连续发起多批次构件的审核请求，检查接口响应是否稳定，确认`maxContext`配置适配数据更新频率。
- 查看模型输出的结构化结果，检查是否包含完整的检验项与判定结论，确认`temperature`取值符合校验一致性要求。
