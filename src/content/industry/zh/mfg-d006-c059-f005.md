# 预拌混凝土生产的检验与过程记录审核：工具调用与插件

## 这个品类的数据长什么样
这个品类的数据来自工程订单系统、砂石水泥外加剂检验设备、骨料含水率测定仪器、搅拌站生产控制系统与工程项目试验室。数据更新节奏为每车生产批次、每批原料进场、每日汇总。日常文档包含配合比通知单、开盘鉴定记录、生产运输单、原材料检验报告、试块留存记录与强度检测报告，字段涵盖原料批次号、实测含水率、搅拌参数、坍落度指标、试块强度等级与运输时长等，无额外预设统计数值。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据按单批次生产、单原料批次更新，工具调用需支持单次拉取单批次的生产与检验数据，避免跨批次数据混淆。多来源的数据采集需求要求插件需适配不同系统的API格式，对接搅拌站控制系统与试验室检测系统时需分别配置请求参数。业务文档的特定字段要求工具调用需明确指定提取目标字段，例如坍落度、试块强度等级，无法仅通过通用文本提取获取符合业务要求的信息。高频更新的特性也要求工具调用的上下文缓存需按生产批次隔离，避免旧数据干扰当前审核流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `["functionCall"]` | 强制调用指定工具完成检验记录审核，避免通用问答干扰业务流程，符合FastGPT v4.17.0版本的工具调用规则 |
| `functionCall` | `{"name": "extract_concrete_check_data", "parameters": ["batch_id", "slump", "strength"]}` | 针对预拌混凝土的特定业务字段提取数据，确保审核所需的关键信息完整 |
| 单次请求超时时间 | `60–90 秒` | 单批次混凝土生产数据量较小，超时时间过长会占用系统资源，过短会导致未完成的数据拉取失败 |
| 数据源对接配置 | 按实测标定 | 不同搅拌站控制系统与试验室系统的API格式存在差异，需根据实际对接的系统调整请求头与参数格式 |
| 批次隔离开关 | 开启 | 每车生产数据独立更新，隔离批次可避免跨批次数据混淆，确保审核结果准确 |

## 容易做错的三处
- 调用文本提取工具时返回400 Invalid JSON payload. Unknown name错误，原因是传递的参数包含插件未定义的字段名，未严格匹配业务文档预设的字段列表。
- 调用工作流API时无法获取预设的上下文信息，原因是请求中未携带会话标识参数，或未开启工作流的上下文传递配置。
- 工具调用结果中未包含试块强度数据，原因是字段提取规则未指定试块强度等级的提取路径，遗漏了业务关键字段。

## 怎么确认配好了
- 发起单批次混凝土生产数据的工具调用请求，检查返回结果是否包含预设的业务字段，例如批次号、坍落度、试块强度等级。
- 调用工作流API时携带会话标识，检查返回结果是否包含历史会话的上下文信息。
- 查看工具调用的日志，确认请求参数未包含未定义的字段，无400类错误返回。
- 测试不同生产批次的调用请求，确认结果未出现跨批次的数据混淆。
