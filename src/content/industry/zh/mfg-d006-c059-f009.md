# 预拌混凝土生产的检验与过程记录审核：模型接入与配置

## 这个品类的数据长什么样
预拌混凝土生产的数据来源包括工程订单、砂石水泥外加剂检验记录、骨料含水率测定数据、搅拌站控制系统日志、工程项目试验室台账。数据更新频率为每车生产批次、每批原料进场、每日汇总。日常文档包含配合比通知单、开盘鉴定表、生产运输单、原材料检验报告、试块养护记录、强度检测报告，各字段对应明确的物理单位与业务标识，涵盖原料型号、配合比参数、生产时间、运输里程、试块养护龄期、检测数值等内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类高频小批量的更新节奏要求模型接入需适配短周期、高并发的调用场景，避免上下文溢出。多类型文档与多源数据的混合输入，要求配置需明确不同文档的字段映射规则，防止入参混淆。滞后的试块强度验证需求，要求模型可关联历史生产与检测数据进行审核，需配置合理的上下文长度。不同于预制构件的工厂化生产，预拌混凝土的现场浇筑与运输过程存在变量，因此模型需适配动态变化的输入数据。多系统数据来源则要求入参格式需统一匹配各系统的输出字段，减少格式转换成本。出错后果包括坍落度不符导致退料、结构强度不足、工程停工返工等，因此配置需保障审核逻辑的严谨性。

以下配置基于FastGPT v4.17.0版本的逻辑制定。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多源文档的批量输入，覆盖单批次生产、原料检验与试块记录的完整数据量 |
| `maxTokens` | 1500–2000 token | 满足检验记录审核的文本输出长度，避免截断关键审核结论 |
| `temperature` | 0.1–0.3 | 保持审核逻辑的一致性，减少随机偏差，保障质量判断的稳定性 |
| `AIPROXY_API_ENDPOINT` | 按平台分配的专属节点 | 适配预拌混凝土场景的专用调用链路，保障高频数据传输的稳定性 |
| `quoteMaxToken` | 400–600 token | 限定引用源文档的片段长度，避免冗余内容干扰审核逻辑 |
| `toolChoice` | auto | 自动适配工具调用需求，用于骨料含水率修正后的配料参数计算 |

## 容易做错的三处
- 现象：调用模型时返回入参缺失报错，状态码400。原因：未正确映射预拌混凝土场景的专属字段，如骨料含水率、配合比参数等未纳入入参范围。
- 现象：连续调用多批次数据时出现超时，接口返回504。原因：`maxContext`配置值过高，导致模型处理上下文的时间超出预设阈值。
- 现象：模型输出的审核结果与实际试块强度报告不符。原因：`temperature`配置值过高，导致审核逻辑出现随机偏差，未严格匹配业务规则。

## 怎么确认配好了
- 查看模型调用日志，确认入参包含配合比通知单、原料检验记录等预拌混凝土场景的专属文档字段。
- 发起单批次生产数据的测试调用，核对输出结果的审核逻辑与业务规则匹配度。
- 验证接口响应时间符合业务场景的实时需求，调整`maxContext`等参数适配响应速度。
- 检查`AIPROXY_API_TOKEN`配置的有效性，确认无权限或鉴权失败的报错信息。
