# 饮料与瓶装水的检验与过程记录审核：向量模型与索引

## 这个品类的数据长什么样
该品类的主体为碳酸、果汁、茶饮、功能饮料及包装饮用水工厂，日常产生的文档包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验报告、成品检验报告。数据来源覆盖水源与原料检测、配方系统、在线糖度酸度监测设备、灌装设备、视觉检测系统及LIMS系统，更新节奏为每批、每班或连续采集。单条记录包含糖度、酸度、灌装液位、封口参数、批号等字段，对应不同的业务单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
高频连续的更新节奏要求索引支持增量触发，避免全量重复执行占用系统资源。多来源的混合数据类型需要向量模型兼容结构化参数与非结构化日志，确保不同类型的检验数据都能生成有效表征。单批次记录的字段密度较高，分块时需保留跨环节的上下文关联，否则会丢失配方与灌装参数的对应关系。高速灌装带来的批次切换频繁特性，要求索引的检索速度适配单班次的异常排查需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配单批次检验记录的字段密度，避免跨批次内容混杂 |
| 重叠长度 | 100–150 字符 | 保留相邻环节的衔接信息，防止关键参数被截断 |
| 相似度阈值 | 0.75–0.85 | 匹配检验结果的细微偏差，区分正常与异常业务参数 |
| maxToken | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 单次搜索上限 | 前10条 | 覆盖单班次的异常记录数量，避免冗余结果干扰排查 |
| defaultToken | 2048 | 处理单条检验记录的基础长度，平衡检索精度与响应速度 |

## 容易做错的三处
-  索引任务一直显示在索引中，无进度更新。原因：未针对连续采集的高频数据配置增量索引触发规则，全量索引重复执行导致系统阻塞。
-  搜索结果相关性普遍偏低，无法匹配目标检验参数。原因：分块时未保留糖度、酸度等核心业务字段的上下文，向量表征丢失关键匹配信息。
-  最后一组索引数据无法完成入库。原因：未校验灌装液位、封口参数的字段格式，存在非法字符导致索引流程中断。

## 怎么确认配好了
-  上传单批次的完整检验记录，查看分块预览是否保留了配方、水处理、灌装的完整字段信息。
-  触发一次增量索引任务，确认任务在预设时间内完成，无超时报错提示。
-  输入异常参数的检索词，查看返回结果是否优先匹配对应批次的检验记录。
-  检查索引入库的日志，确认无字段格式错误或数据截断的提示信息。
