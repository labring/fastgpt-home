# PCB制造的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来自客户提供的Gerber文件、钻带、BOM，以及工厂内部的CAM文件、设备运行参数、槽液化验记录、AOI检测报告、电测报告与实验室切片报告。数据更新频率为每生产批、每班或连续采集，覆盖工程制作指示、钻孔层压参数、药水分析结果等多类文档。字段包含工艺参数的具体数值、检测结果的坐标与缺陷类型，单位涵盖转速、浓度、长度等工业标准单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源且高频更新的数据要求索引支持增量更新，避免全量重建带来的时间损耗。不同类型文档的结构差异，要求向量分块需适配工艺参数的短字段与检测报告的长段落，防止关键信息被割裂。生产台账汇总需关联多环节的工艺数据，对向量召回的准确率有较高要求，需避免无关批次数据被错误匹配。同时，数据中包含大量精密数值与参数差异，嵌入模型需适配工业场景的细微特征区分。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | PCB工艺文档包含短参数记录与长检测报告，该区间可覆盖完整工艺节点信息 |
| 重叠长度 | 100–200 字符 | 避免跨分块的工艺逻辑被割裂，保障向量关联的连贯性 |
| `maxToken` | 8192 token | 适配FastGPT v4.17.0支持的主流嵌入模型上下文上限，覆盖完整生产台账的汇总需求 |
| 相似度阈值 | 0.72–0.85 | 需区分同类型工艺参数的细微差异，避免误关联不同批次的生产数据 |
| 单次搜索上限 | 前 10 条 | 生产台账汇总需覆盖核心工艺环节，过多结果会增加报告生成的冗余信息 |

## 容易做错的三处
- 现象：调用知识库接口生成索引时返回模型不匹配报错，或索引生成后向量结果与预期不符。原因：未固定嵌入模型版本，或使用了与PCB工艺数据适配性差的通用嵌入模型。
- 现象：通过OpenAPI创建的QA拆分文件集合，索引查询响应超时。原因：未调整分块长度与搜索上限参数，导致单批次索引数据量过大，向量召回链路负载过高。
- 现象：生成的生产台账报告中出现重复的工艺参数条目。原因：相似度阈值设置过低，导致相似但属于不同生产批次的参数被错误关联汇总。

## 怎么确认配好了
- 上传单份钻孔参数文档，检查分块后的向量片段是否完整包含转速、进给率等核心字段。
- 调用知识库搜索接口，验证返回结果的条数符合单次搜索上限的设置。
- 对比不同嵌入模型生成的向量相似度，确认选用的模型可区分同类型工艺参数的细微差异。
- 运行连续生产批次的索引增量更新任务，检查更新耗时符合预期。
