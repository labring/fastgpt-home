# PCB制造的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
PCB制造的生产台账数据来源涵盖客户提供的Gerber文件、钻带、BOM清单，CAM解析记录，钻孔、层压等设备的实时参数，槽液化验结果，以及AOI、电测、实验室切片的检测报告。数据按生产批次、每班或连续采集更新，日常文档包含工程制作指示、钻孔参数表、层压工艺记录、药水分析单、缺陷检测报告等。单批次台账包含多类结构化与半结构化字段，涉及孔径、铜厚、检测缺陷数等具体参数，所有数据均绑定对应生产批次标识。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
PCB制造的台账数据来源分散且格式多样，要求多轮对话需逐步引导收集不同类型的业务数据，避免遗漏关键参数。数据按生产批次高频更新，对话上下文需严格绑定批次标识，防止跨批次数据混淆。单批次数据量较大，提示词需明确指定不同文档的字段提取规则，确保汇总时仅纳入当前批次的有效数据。同时，台账异常可能导致整批板报废，对话需校验字段完整性，主动询问缺失的关键参数。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话ID配置 | 为每个生产批次的对话分配唯一`chatId` | 区分不同批次的对话历史，避免跨批次数据混淆 |
| 变量传入配置 | 通过`variables`参数传入生产批次ID、Gerber版本号，取值为键值对对象 | 精准定位对应生产批次的台账数据 |
| 上下文窗口大小 | 8000–12000 token，按实测标定 | 单批次PCB台账包含多份设备报告与检测记录，需足够上下文容纳完整数据 |
| 多轮对话历史保留条数 | 前30条对话记录 | 限制历史数据规模，防止干扰当前批次的台账生成 |
| 超时等待配置 | 600秒，按实测标定 | 适配PCB台账收集的多步骤特征，预留足够时间补充缺失数据 |
| 提示词模板变量绑定 | 将Gerber解析记录、AOI报告等文档字段映射为提示词占位符 | 明确指定需提取的台账字段，确保汇总内容符合业务要求 |

## 容易做错的三处
- 现象：调用API传入`variables`参数后，生成的生产台账未关联指定的PCB生产批次。原因：未将`variables`中的批次标识绑定到提示词的检索过滤条件中。
- 现象：文本内容提取失败后触发指定回复，未等待用户补充输入就直接终止对话。原因：未配置多轮对话的等待触发规则，仅执行单次提取操作。
- 现象：模型输出中文，但提示词要求英文输出。原因：未在`messages`参数中明确指定输出语言规则，且未校验知识库与模型的语言配置一致性。

## 怎么确认配好了
- 测试传入`variables`参数携带指定PCB生产批次号，核对生成的台账是否仅包含该批次的设备参数与检测报告数据。
- 模拟文本提取失败的场景，确认系统会返回预设提示并等待用户补充必要的生产数据。
- 配置英文提示词模板后，核对模型输出的报告是否符合指定语言要求。
- 连续发起多轮对话切换不同生产批次，核对每次生成的台账仅关联当前批次的数据源。
