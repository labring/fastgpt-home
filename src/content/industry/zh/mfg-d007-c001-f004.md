# PCB制造的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
PCB制造的生产台账数据来源涵盖客户提供的Gerber文件、钻带、BOM清单，CAM生成的工程工作稿，钻孔、层压等设备的实时参数，槽液化验结果，AOI、电测报告及实验室切片报告。数据按生产批、每班或连续更新，单批次台账包含钻孔孔径、层压压力、药水浓度、缺陷类型等字段，单位涵盖毫米、兆帕、ppm、件等。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据源格式差异要求工作流中配置多格式解析节点，适配Gerber二进制文件、CSV格式的设备参数、PDF格式的AOI报告等不同输入。高频更新的节奏要求工作流支持定时或事件触发模式，避免手动触发延迟。单批次数据量较大的特点要求工作流拆分大任务为子节点，避免单节点超时。台账数据需关联多工序参数与报告，需通过`variables`传递批次标识，确保数据关联的准确性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 工作流触发方式 | 按生产批完成事件触发，绑定`variables`中的生产批次号 | 匹配PCB制造按生产批更新台账的业务节奏，通过`variables`传递批次ID关联多工序数据 |
| 单次处理数据上限 | 10–20 万条 | 匹配PCB单生产批的典型数据规模，避免节点内存溢出 |
| 节点超时时间 | 300–600 秒 | 覆盖单批次数据汇总、多格式文档解析的处理时长 |
| 代码运行节点日志输出 | 输出到工作流节点控制台 | 便于排查数据转换、参数计算的异常，适配生产台账汇总的复杂计算场景 |
| 失败分支配置 | 触发告警节点并记录`nodeId` | 定位异常节点，快速定位PCB生产台账生成的故障环节 |
| 模型选择配置 | 按实测标定，优先选择支持长文本解析的模型 | 处理Gerber解析记录、AOI报告等多文档的汇总需求 |
| 变量传递范围 | 限定为当前生产批的`variables`数据 | 避免跨批次数据混淆，保证台账数据的准确性 |

## 容易做错的三处
- 工作流运行后代码运行节点无日志输出，控制台无法查看。原因是未开启对应节点的日志采集配置，导致计算过程的打印信息未被捕获。
- 工作流的AI模型选择下拉列表为空。原因是未在平台配置对应文本生成模型的接入密钥，或未开启模型的可用状态。
- 工作流执行时出现参数格式错误的报错。原因是未通过`variables`正确绑定生产批的数据源字段，导致节点无法读取对应PCB生产数据。

## 怎么确认配好了
- 触发一次模拟生产批的工作流，查看代码运行节点的控制台是否有对应日志输出。
- 检查工作流的模型选择下拉列表，确认已加载可用的文本生成模型选项。
- 手动传入一组测试用的PCB生产数据，验证工作流是否能正确生成台账的初步汇总内容。
- 触发一次异常测试，确认失败分支的告警节点是否正常触发。
