# PCB制造的生产台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
该品类数据主要来自客户提供的Gerber文件、钻带、BOM，以及工厂内部CAM系统、生产设备参数、槽液化验结果、AOI检测报告、电测报告与实验室切片报告。数据更新节奏随生产批、班次连续采集，不同岗位产生的文档结构差异明显：工程岗产出工程制作指示、Gerber解析记录，生产岗记录钻孔、层压参数，品质岗输出AOI、电测报告与切片报告，字段包含工艺参数、检测数值、批次编号与客户标识，无统一通用字段格式。

## 这些特征在「知识库检索与召回」这一环带来什么约束
PCB制造的多源异构数据结构与高频更新特性，要求知识库检索需适配不同文档的字段差异，避免跨类型文档的检索混淆。连续采集的实时数据需要支持增量召回，避免全量检索带来的性能损耗。不同岗位的专属文档需要按角色权限限定检索范围，确保生产、品质等团队仅能访问对应岗位的台账数据。批次关联的字段要求检索时需绑定生产批编号，避免跨批次的文档误匹配，保障台账汇总的准确性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的知识库检索逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 匹配PCB制造的工艺参数与检测报告的字段精度，避免低相似度的无关文档混入检索结果 |
| `limit` | 前8条 | 覆盖单生产批的多类型文档数量，同时控制上下文长度符合台账汇总的处理需求 |
| `searchMode` | semantic | 适配多源异构的工艺与检测文档，实现语义关联的参数召回 |
| `usingReRank` | 开启 | 对初始检索结果按文档与生产批次的关联度二次排序，修正语义检索的偏差 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动补充生产批编号、客户标识等字段作为扩展查询条件，提升检索的精准度 |
| `collectionIds` | 按岗位绑定对应知识库集合 | 限定工程、生产、品质团队仅能访问各自的台账文档，符合权限控制要求 |

## 容易做错的三处
- 现象：团队成员配置了写权限后无法创建台账相关知识库文档。原因：未将知识库集合绑定到对应岗位的角色权限组，仅开放了基础浏览权限。
- 现象：检索返回的AOI报告与钻孔参数混淆，结果条数超出预期。原因：未设置`similarity`阈值或阈值设置过低，同时未开启`datasetSearchUsingExtensionQuery`补充批次字段过滤。
- 现象：全局变量的“选择知识库”无法动态匹配当前生产批次。原因：未将生产批编号作为扩展查询参数绑定到检索逻辑，导致无法自动切换对应批次的知识库集合。

## 怎么确认配好了
- 提交一条包含生产批编号的查询，核对检索结果是否仅返回该批次的钻孔、层压参数与检测报告。
- 切换不同岗位的账号，验证是否仅能访问对应岗位配置的知识库集合。
- 调整`similarity`阈值，观察检索结果的匹配精度是否符合工艺文档的识别要求。
- 开启`usingReRank`后，对比二次排序前后的结果顺序，确认重排逻辑生效。
