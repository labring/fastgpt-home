# SMT贴片与电子组装的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来源包括客户提供的BOM、Gerber与坐标文件，工厂MES系统、锡膏与元件批次台账，贴片机、SPI/AOI检测设备及回流焊炉温记录。日常文档涵盖换线表、钢网档案、首件确认单、缺陷检测报告、维修记录与追溯标签。数据更新节奏为每工单、每次换线实时同步，单条数据包含料号、位号、元件批次、炉温参数、缺陷坐标等字段，单位涉及摄氏度、毫米等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据高频实时更新的特性，要求向量索引支持增量同步，避免全量重建带来的性能损耗。多维度字段（如元件坐标、炉温参数、缺陷位置）的存在，需要向量模型能够捕捉跨字段的语义关联，确保检索时能关联匹配相关生产环节数据。文档类型覆盖结构化台账与非结构化检测报告，索引需兼容不同格式的文本解析逻辑。追溯类数据对字段关联性要求高，索引需兼顾语义检索与精准字段匹配能力，防止错配不同工单的生产数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配SMT台账与检测报告的单段语义完整性，避免跨工单信息混淆 |
| 重叠长度 | 50–80 字符 | 保留换线、工单衔接处的上下文关联，防止语义断裂 |
| 相似度阈值 | 0.72–0.85 | 匹配元件料号、缺陷描述的语义相似度，兼顾召回率与准确率 |
| 单次搜索上限 | 前20条 | 覆盖单工单关联的多台设备检测数据，避免冗余结果 |
| `defaultToken` | 1024 token | 控制单段向量的维度上限，适配工厂台账的常规文本长度 |
| `maxToken` | 4096 token | 满足多份检测报告拼接后的上下文长度需求 |

## 容易做错的三处
- 现象为重复查询生产台账时出现向量数据库超时报错。原因是未配置缓存机制，每次查询都触发全量向量检索，高频查询下资源占用过高。
- 现象为创建训练订单后集合添加数据无索引更新提示。原因是混淆了训练订单与集合数据添加的触发逻辑，训练订单用于批量预处理非结构化文档，单条数据索引无需通过训练订单触发。
- 现象为上传缺陷图片后检索结果为空或匹配度极低。原因是未针对SMT的缺陷图片配置专用的图像向量化配置，仅使用默认文本向量化模型处理图片数据，无法提取图像特征。

## 怎么确认配好了
- 发起一次模拟工单查询，核对返回结果的字段是否包含料号、位号等核心生产信息，确认语义匹配逻辑生效。
- 查看向量索引的更新日志，验证高频更新的换线数据是否能在合理时间内完成索引同步，确认增量更新配置生效。
- 测试不同类型文档（如BOM表格、SPI检测报告）的检索结果，确认不同格式数据的解析与向量化逻辑适配。
- 调整相似度阈值后观察检索结果的数量变化，确认阈值配置符合当前业务的匹配需求。
