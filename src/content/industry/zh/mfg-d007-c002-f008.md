# SMT贴片与电子组装的生产台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
SMT贴片与电子组装的生产数据来源包括客户BOM、Gerber坐标文件、MES系统、锡膏与元件批次记录、贴片机、SPI/AOI检测设备、回流焊炉温数据。数据更新频率为每工单、每次换线实时生成，日常文档包含BOM表格、换线表、钢网记录、炉温日志、首件确认单、SPI/AOI缺陷报告、维修记录与追溯标签。文档字段包含料号、位号、元件批次、温度参数、缺陷类型等，坐标文件使用毫米为单位，炉温记录使用摄氏度为单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
高频实时的更新节奏要求文档解析需支持快速批量处理，避免延迟影响台账汇总效率。多类型混合的文档结构，既有结构化表格又有长文本段落，要求分块逻辑需适配不同格式，避免破坏字段关联。特定的业务字段如料号、位号需完整保留，分块不能割裂跨字段的关联关系。单工单多文档的组合上传需求，要求解析流程需适配较大的文件容量，同时控制分块大小避免上下文溢出。

## 配置怎么定
本文适配FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | SMT文档既有密集字段的BOM表格，又有长文本的炉温记录，该区间可保留完整业务字段同时避免分块断裂 |
| `chunkSplitter` | 按表格+段落混合拆分 | 适配SMT文档混合结构化表格与非结构化段落的特征，确保各类数据均能被完整提取 |
| `customPdfParse` | 启用 | 精准提取SPI/AOI报告、首件确认单中的表格化字段，避免默认解析逻辑遗漏业务关键数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 单工单多文档合集的解析时长通常较长，该区间可覆盖完整解析流程，避免超时失败 |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | 适配批量上传工单文档的常见容量需求，按实测标定合理上限 |
| `chunkSettingMode` | 手动模式 | 针对BOM表格、炉温记录等不同文档类型，可单独调整分块参数，适配SMT场景的多结构文档 |

## 容易做错的三处
- 上传包含元件外观图片的SPI/AOI报告PDF后，解析结果未提取图片关联的缺陷描述。原因是未启用对应解析配置，默认仅提取文本内容。
- 批量上传3份以上SPI/AOI报告PDF时，解析任务返回超时错误。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`，默认时长不足以处理多份高频更新的文档合集。
- 将旧服务器知识库导出为单Excel文件导入新服务器后，部分换线表的元件批次数据丢失。原因是未按工单维度拆分文档，分块时合并了跨工单的关联数据，导致字段关联断裂。

## 怎么确认配好了
- 上传一份标准SMT BOM表格，检查解析后的分块是否保留完整的料号、位号、替代料字段。
- 上传一份包含SPI/AOI缺陷数据的PDF文档，检查解析结果是否包含表格化的缺陷类型、数量字段。
- 上传一份500 MB的工单文档合集，确认解析任务在预设的`PARSE_FILE_TIMEOUT_SECONDS`内完成。
- 切换至`chunkSettingMode`手动模式，调整`chunkSize`后再次上传测试文档，确认分块长度符合预期。
