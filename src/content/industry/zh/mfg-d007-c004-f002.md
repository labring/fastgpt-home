# 仓储、批次与厂内物流的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据主要来自ERP/WMS系统、条码或RFID设备、采购工单、库位管理记录、AGV输送系统与称重设备。日常生成的文档包括收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录。数据更新节奏包含实时（如AGV实时位置、称重数据）、每日（如领退料汇总）与月度盘点三类。文档字段包含物料编码、批次号、库位编号、效期、物料数量、检验状态等，单位涉及件、千克、天等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且更新节奏差异大，实时产生的数据要求索引支持增量更新与低延迟同步，避免账实数据脱节。核心业务字段如批次号、效期、物料编码的准确性直接影响台账核对结果，要求向量模型能精准捕捉结构化字段的语义关联，避免因字段截断导致匹配失效。多类型文档的混合导入需要索引适配不同的文档结构，同时账实一致、批次追溯的业务需求要求检索召回的精度与完整性，不能遗漏关键关联记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配收货单、批次台账等文档的单条记录长度，避免拆分核心业务字段 |
| 重叠长度 | 50–80 字符 | 保留批次号、效期等跨分块的关键信息，防止字段被截断导致匹配失效 |
| 相似度阈值 | 0.75–0.85 | 保障物料身份、批次等核心字段的检索匹配精度，适配账实核对的高要求 |
| 单次搜索上限 | 前 10 条 | 覆盖多库位、多批次的关联检索需求，避免遗漏关联台账记录 |
| `defaultToken` | 1024–1536 token | 适配批量导入的仓储单据内容，平衡上下文完整性与检索速度 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 现象：检索响应超时，单次检索耗时超过 30 秒。原因：分块长度设置过大，导致单批次向量数据量过高，索引加载与检索计算压力陡增。
- 现象：检索结果中批次号、效期字段为空或匹配错误。原因：分块时未保留足够重叠长度，导致核心业务字段被拆分截断，向量无法准确关联对应信息。
- 现象：检索结果条数远低于预期，无法覆盖关联的移库、盘点记录。原因：相似度阈值设置过高，过滤掉了部分弱匹配但实际关联的台账数据。

## 怎么确认配好了
使用FastGPT v4.17.0版本的平台执行以下核对动作：
- 上传单份标准收货单文档，查看分块预览界面，确认物料编码、批次号等核心字段完整保留，无截断情况。
- 模拟检索“线边库2024年第二季度的批次台账”，查看检索响应耗时，确认符合业务预期无明显超时。
- 调整相似度阈值前后各执行一次相同检索，对比结果条数变化，确认阈值设置匹配业务匹配精度要求。
- 导入批量仓储单据，检查索引更新状态面板，确认实时数据的同步延迟符合业务需求。
