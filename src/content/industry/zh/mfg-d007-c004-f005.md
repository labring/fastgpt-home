# 仓储、批次与厂内物流的生产台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
该品类数据来源包含ERP/WMS系统、条码或RFID采集设备、采购与生产工单、库位管理模块、AGV输送系统及称重设备。日常生成的文档包括收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录。数据更新节奏分为实时（如扫码入库）、每日（如库存日报）、月度盘点（如全库账实核对）。单条数据字段包含物料编码、批次号、库位编号、出入库数量、效期、检验状态及关联工单编号，单位涵盖件、千克、区位号、日期等。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散且字段要求严格，要求工具调用时需支持多源数据的并行或顺序拉取，需预先配置各数据源的字段映射规则。批次与效期的强校验需求，要求插件调用时需指定特定字段的校验逻辑，避免错漏。实时更新的数据场景，要求工具调用的超时设置需适配短周期数据拉取，防止数据滞后。账实一致的核心目标，要求工具返回的台账数据需包含完整的关联关系，如工单、库位与物料批次的绑定信息，同时需支持异常数据的识别与提取。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数逻辑制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多插件并行调用的场景，自动选择匹配当前台账拉取需求的工具 |
| `functionCall` | 开启 | 强制工具返回结构化数据，便于批次、效期等字段的标准化解析 |
| 工具调用超时设置 | 30–60 秒 | 适配实时/每日更新的数据拉取节奏，避免长周期等待导致的台账数据滞后 |
| 多源数据源映射 | 按ERP/WMS、条码采集、AGV系统分别配置字段对应关系 | 解决该品类数据来源分散的问题，确保跨系统数据的字段一致性 |
| 批次字段校验规则 | 开启物料编码、批次号、效期的必填校验 | 符合该品类账实一致与批次管理的核心业务要求 |
| 异常数据提取开关 | 开启账实差异、呆滞物料、过期批次的识别 | 直接提取台账中的高风险数据，简化报告生成流程 |

## 容易做错的三处
- 调用外部MCP插件时返回504超时错误。原因是未适配该品类实时数据拉取的节奏，超时设置过短，无法完成多源数据的批量拉取。
- 调用绑定工单的工作流时返回未找到关联数据。原因是未正确获取并传入对应工单的工作流ID参数，导致工具无法匹配目标台账数据。
- 调用API调试接口时返回参数格式错误。原因是未按照该品类的文档字段要求传递物料编码、库位编号等必填参数，导致接口校验失败。

## 怎么确认配好了
- 执行单次工具调用测试，检查返回的结构化数据是否包含物料编码、批次号、效期等核心业务字段。
- 模拟多源数据拉取场景，验证ERP/WMS、条码采集系统的数据字段映射是否正确匹配。
- 触发异常数据提取逻辑，确认是否能识别账实差异、过期批次等目标异常数据。
- 调整工具调用超时设置，测试不同时长下的数据拉取结果，确认符合业务更新节奏。
