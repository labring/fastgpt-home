# 仓储、批次与厂内物流的生产台账汇总与报告生成：文档解析与分块

本页面的配置方案适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
该品类的典型数据来自ERP、WMS系统、条码/RFID采集设备、AGV输送系统及称重设备，日常文档包含收货单、上架单、领退料单、盘点表、批次台账、效期记录等。数据更新节奏涵盖实时（如AGV调度数据）、每日（如领退料汇总）与月度盘点三类。文档通常包含固定表头与多行业务数据，核心字段包括物料编码、批次号、库位、效期、工单关联信息，单位涵盖件、千克、立方米等不同计量类型。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的业务数据存在单文件行数多、字段关联紧密、更新节奏差异大的特征，对文档解析与分块带来多重约束。首先，15000行以上的Excel台账或10万字符级的PDF台账，要求解析流程具备足够的文件承载能力与处理时长；其次，批次、库位与工单的关联信息属于核心业务数据，不能被随意拆分，否则会影响后续台账汇总与物料追溯；最后，实时更新的仓储调度数据需要解析流程具备较高的处理效率，避免延迟影响账实核对的及时性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 匹配仓储类文档单条业务记录的长度，避免拆分批次与库位的关联信息 |
| `chunkSplitter` | 按表头+行分组分块 | 保留领退料单、盘点表的表头与对应业务数据的关联关系 |
| `customPdfParse` | 启用结构化解析 | 适配收货单、批次台账的固定格式PDF，提升字段提取准确率 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持月度盘点汇总的大型Excel或PDF文档 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配15000行Excel台账的完整解析耗时 |
| `chunkSettingMode` | 手动配置 | 针对仓储文档的特殊字段结构调整分块规则 |

## 容易做错的三处
- 现象：使用默认`chunkSize`参数解析10000行以上的Excel台账时，单块数据量过大，导致向量生成耗时增加且检索精度下降。原因：未针对仓储文档的单条业务记录长度调整分块阈值，默认分块未匹配该品类的业务数据结构。
- 现象：上传10万中文字符的批次台账PDF时，解析任务触发超时。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以完成大型文档的全量解析。
- 现象：解析领退料单时，物料批次与库位字段被拆分到不同分块中。原因：使用默认的按字符分块规则，未启用按结构化表头分组的分块逻辑，导致关键关联信息断裂。

## 怎么确认配好了
- 上传单份15000行的Excel仓储台账，确认解析任务在`PARSE_FILE_TIMEOUT_SECONDS`设定的时长内完成，无超时报错。
- 随机抽取3份不同类型的仓储文档（如收货单、盘点表、批次台账），验证分块后仍保留物料批次与库位的关联信息。
- 调整`chunkSize`参数至800–1200字符区间，对比分块后的内容长度，确认单块数据符合单条业务记录的合理范围。
- 查看FastGPT v4.17.0的解析日志，确认结构化字段（如批次号、效期、库位编码）的提取准确率符合业务校验要求。
