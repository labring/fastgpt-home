# 仓储、批次与厂内物流的生产台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
该品类的典型数据来自ERP/WMS系统、条码/RFID设备、采购工单、库位管理、AGV输送系统与称重设备。日常文档包含收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录，字段涵盖物料编码、批次号、库位编号、库存数量、检验状态、效期日期等，单位涉及件、千克、立方米、天等。数据更新节奏分为实时（如AGV物流轨迹、称重数据）、每日（如领退料单汇总）与月度盘点（如库存对账表）。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据多源且更新节奏差异大，要求检索系统支持多源数据导入与增量/全量更新结合的同步策略。文档以结构化单据与台账为主，包含大量精准匹配字段（如批次号、库位），要求检索兼顾语义理解与精准字段匹配。最耗时的核对环节涉及物料身份、批次与检验状态，要求检索能快速召回关联台账，避免冗余结果干扰核心信息。跨工序的物料位置管理需求，要求检索支持按工单、工序关联的上下文查询，确保账实一致与批次流向的完整追溯。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 该品类数据多为结构化单据，该区间可平衡召回精度与覆盖范围，避免漏召回批次号、库位等关键字段的匹配结果 |
| `limit` | 前8–12条 | 仓储物流台账数据条目较多，过多结果增加模型处理负担，过少则可能遗漏齐套物料的相关记录 |
| `searchMode` | `mixedRecall` | 该品类既有结构化的物料编码、批次号，又有非结构化的效期说明、盘点备注，混合检索可兼顾精准匹配与语义理解 |
| `usingReRank` | 开启 | 多源数据召回的结果可能存在冗余，重排可优先返回与生产台账汇总关联度更高的批次、库位信息 |
| `datasetSearchUsingExtensionQuery` | 开启 | 生产台账的查询常需关联工单、AGV物流轨迹等延伸数据，扩展查询可补充关联上下文 |
| `collectionIds` | 按仓储、批次、厂内物流分别配置专属集合ID | 该品类数据按业务模块划分，专属集合可避免无关数据干扰检索结果 |

## 容易做错的三处
- 现象：语义检索返回的批次台账得分0.77，但模型最终回答显示找不到相关信息。原因：未开启`datasetSearchUsingExtensionQuery`，无法关联工单、库位等延伸数据，无法匹配用户的台账汇总查询需求。
- 现象：单次语义检索返回超过15条不同库位的物料台账，无法快速定位当前工单需要的齐套物料信息。原因：未正确配置`limit`参数，或未启用`usingReRank`对结果进行优先级排序。
- 现象：上传Excel格式的领退料单或盘点表后，在知识库检索界面无法搜索到对应文件内容。原因：未启用Excel文件解析适配，或未将文件导入专属的仓储物流数据集合。

## 怎么确认配好了
- 检查`similarity`参数的配置值，确认在0.72–0.80区间内。可通过测试查询批次号为“L20240512001”的台账，验证召回结果的匹配度是否符合预期。
- 验证`limit`参数的配置，执行批量检索工单关联的物料台账，确认返回结果条数在8–12条范围内。
- 测试`usingReRank`功能，上传多份同类型的盘点表，确认检索结果优先返回与当前查询关联度最高的批次效期记录。
- 确认`collectionIds`配置了专属仓储物流数据集合，上传Excel格式的领退料单后，可通过关键词检索快速召回对应记录。
