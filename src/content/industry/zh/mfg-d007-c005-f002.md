# 光伏电池片制造的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
通常数据来源包括硅片来料记录、车间MES系统、扩散炉/镀膜设备/印刷机的实时运行参数、EL缺陷检测图、IV性能测试数据及实验室质检报告。数据更新节奏一般为每批次生产更新一次工艺参数，每片电池片生成检测记录，每日汇总当日良率与分档数据。台账文档通常涵盖工艺卡、工序参数表、检测图像、分档报表等，字段包含扩散温度、镀膜厚度、EL缺陷坐标、IV转换效率等，对应单位为摄氏度、微米、像素、百分比等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的高频片级检测数据与多模态图文混合台账，通常要求向量索引支持增量更新与多模态匹配；专业参数的精细粒度与固定单位，需要向量模型适配归一化配置以保证匹配精度；每日汇总的批量数据与高检索流量，要求控制单任务的token消耗与检索返回量；跨工序的关联数据需要合理的分块与重叠设置，避免关键上下文被割裂。此外，组件端的缺陷追溯需求，通常要求索引保留片级数据的精准关联，不能过度聚合导致信息丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配工艺卡、扩散参数记录的标准文本长度，避免单块内容跨工序拆分 |
| 重叠长度 | 100–200 字符 | 保留工序间的关联上下文，防止关键工艺参数被分割在不同分块中 |
| 相似度阈值 | 0.75–0.85 | 匹配电池片专业参数的精准度需求，过滤无关的低匹配度结果 |
| 单次搜索上限 | 前 10 条 | 控制检索返回的向量数据量，降低`defaultToken`的整体消耗 |
| `defaultToken` | 4000 token | 适配单批次生产台账的汇总上下文长度，满足基础报告生成需求 |
| `maxToken` | 16000 token | 覆盖多批次跨周期报告生成的总上下文需求，避免任务中途中断 |

## 容易做错的三处
- 现象：检索任务频繁超时，日志显示上下文token超限。原因：未根据单批次台账的实际数据规模调整`maxToken`取值，使用了过小的通用配置。
- 现象：切换向量模型后索引进度无更新，且无法恢复到原模型配置。原因：未在切换前清理旧模型的索引缓存，或未遵循FastGPT v4.17.0的版本适配要求执行强制重置。
- 现象：EL检测图的检索匹配结果不符合预期，相似度波动较大。原因：未开启向量模型归一化配置，导致未归一化的图像向量与模型输入要求不匹配。

## 怎么确认配好了
- 查看FastGPT索引管理界面的进度条，确认单批次数据的向量生成任务在10分钟内完成。
- 发起一次针对扩散炉温度参数的检索，核对返回结果的字段与原始台账的专业参数完全匹配。
- 调整`defaultToken`配置后，验证上下文加载的token数符合设定值，无超支或截断情况。
- 确认当前FastGPT版本为v4.17.0，适配当前配置的向量模型归一化要求。
