# 冲压与板材成形的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
冲压与板材成形车间的核心数据来自钢卷标签与质保书、冲床和送料机运行日志、模具管理系统、MES系统、三坐标尺寸检验数据。日常文档包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录。数据更新频率为每卷钢料、每批次生产、每次模具更换时触发。单条文档字段包含钢卷编号、模具型号、压边力参数、换模时间、材料厚度、检验偏差值等，单位涵盖毫米、小时、吨、千牛等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据更新频率高且关联强，每卷料、每次换模都会产生新的台账记录，要求向量索引支持增量更新，避免全量重建，避免占用过多计算资源。单条文档包含多维度关联字段，如模具编号与换模记录绑定、材料批次与利用率数据关联，索引需保留字段级元数据以支持精准检索。此外，车间生产中排样、调试拉延筋等环节依赖历史台账数据，索引的召回速度与准确性直接影响生产效率，需匹配生产环节的响应要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配冲压台账单条记录的平均长度，避免拆分模具编号、换模时间等关键关联字段 |
| 重叠长度 | 50–80 字符 | 保留跨块的模具、材料批次等关联信息，防止分块破坏数据上下文 |
| maxToken | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.75–0.85 | 区分不同模具、材料批次的台账记录，降低误召回概率 |
| 单次搜索上限 | 前10条 | 匹配车间日常检索的常用结果量，避免返回过多冗余数据 |
| defaultToken | 1000 | 设定单条向量化文本的最大token数，适配冲压台账的短文本特征 |

## 容易做错的三处
- 现象：重复发起相同的生产台账汇总查询时，系统响应延迟超过预期。原因：未配置向量检索缓存机制，每次请求都重新遍历索引并计算相似度，未复用历史检索结果。
- 现象：调用知识库接口创建训练订单后，集合添加换模记录失败。原因：混淆了训练订单与增量索引的触发逻辑，未按生产批次关联对应的数据文件，导致索引元数据缺失。
- 现象：检索结果中未包含尺寸检验报告的图片附件。原因：未开启图片向量化配置，或未将图片元数据与文本索引绑定，无法实现图文联合检索。

## 怎么确认配好了
- 查看向量索引的元数据标签列表，确认包含钢卷编号、模具型号、换模时间等冲压车间专属字段。
- 批量导入单批次的换模记录与材料利用率表，检查索引更新状态是否在设定的增量更新周期内完成。
- 发起包含特定模具编号的检索请求，核对返回结果的数量与相关性是否符合设定的相似度阈值。
- 重复发起两次相同的台账汇总查询，确认第二次响应延迟明显低于第一次，验证缓存配置生效。
