# 冲压与板材成形的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
该品类数据来自钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、MES系统、三坐标或检具检验结果。日常生成的文档包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录。数据更新节奏为每卷料、每批生产批次、每次换模时触发更新，各文档字段包含材料牌号、厚度、冲床参数、模具编号、检验尺寸偏差值等，随文档类型匹配对应计量标准。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据按卷料、批次、换模节点更新，工作流需支持按触发条件绑定对应数据源，避免跨批次数据混淆导致的批量尺寸偏差。多类型文档的字段差异要求工作流支持分类型解析，需预设不同文档的提取规则，防止字段匹配错误。冲床与检具的实时数据需同步接入，工作流需配置短周期数据拉取节点，保障台账时效性，避免滞后数据影响模具或冲床的运维判断。换模记录与首末件数据关联紧密，工作流需设置节点间的依赖关系，确保换模后的数据同步更新至对应台账，防止装配间隙超差导致返工。同时，不同检验报告的格式差异要求工作流支持自定义字段映射规则，适配多源异构数据的汇总逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发条件设置 | 绑定卷料批次、换模事件，或每30分钟轮询 | 匹配数据按卷料、批次、换模更新的节奏 |
| `variables` 配置 | 包含材料牌号、冲床运行参数、检验尺寸偏差 | 覆盖核心台账提取字段 |
| 单次数据拉取超时 | 600 秒 | 适配冲床与检具实时数据的拉取延迟 |
| 节点依赖规则 | 按数据生成时序设置先后顺序 | 避免跨批次数据混淆 |
| `nodeId` 配置 | 为每个数据源分配唯一标识 | 区分多源异构数据的来源 |
| 自定义字段映射 | 按实测标定 | 适配不同企业的文档格式差异 |

## 容易做错的三处
- 文本分类提取节点返回空结果。原因是未按文档类型配置`variables`的字段映射，导致无法匹配冲压作业指导书、检验报告的专属字段。
- 工作流应用导入失败。原因是未确认FastGPT版本兼容性，开源版升级后需检查节点配置的版本适配性。
- 基础图表轴变量引用错误。原因是未绑定对应`nodeId`的数据源，导致x轴或y轴无法获取对应批次的冲压参数数据。

## 怎么确认配好了
- 手动触发一次卷料批次的工作流，检查提取的字段是否包含预设的`variables`内容。
- 查看各数据源节点的`nodeId`标识，确认无重复或缺失的情况。
- 模拟换模事件触发工作流，检查节点间的依赖是否按时序执行。
- 导出生成的台账报告，核对是否包含对应批次的材料利用率、检验偏差等数据。
