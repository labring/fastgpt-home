# 化妆品生产的生产台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据来自注册或备案配方、原料安全资料、称量与乳化设备、ERP/MES系统、实验室检测数据及包材版本文件。日常文档包含配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验记录、标签审核文件。数据更新节奏为每批生产或每次换线时更新，字段涵盖原料批次号、投料量、生产批号、限用物质含量、检验指标数值及包材版本号等，需与备案信息保持一致。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的数据按批或换线更新，且需与备案信息严格匹配，这为HTTP接口带来多重约束。接口需支持按生产批次、换线时间作为触发条件拉取数据，避免重复拉取全量历史数据。传输的字段需包含与备案一致的限用物质含量、标签宣称内容等字段，确保数据合规。同时需整合多来源的结构化数据，接口需支持接收设备、ERP、实验室等不同系统输出的标准化数据，并校验各来源字段的一致性，防止数据冲突影响台账准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 鉴权方式 | 采用`Authorization`头携带Bearer令牌 | 符合FastGPT v4.17.0的接口调用规范，保障数据传输安全 |
| 触发参数 | 传入生产批次号、换线时间作为`variables` | 精准定位对应批次的生产台账数据，避免拉取无关数据 |
| 响应数据格式 | 固定为JSON结构化格式 | 便于快速解析台账中的配方、检验、投料等多类字段 |
| 响应字段过滤 | 仅返回`responseData`中备案匹配的字段 | 减少无效数据传输，提升接口调用效率 |
| 超时时间 | 按实测标定（建议60-120秒） | 适配多来源数据整合的耗时，避免因数据拉取延迟导致调用失败 |
| 请求重试策略 | 出现5xx状态码时重试2次 | 应对外部系统临时波动，保障数据拉取稳定性 |

## 容易做错的三处
- 现象：调用接口后每次请求均无上下文关联，每次调用均返回独立结果。原因：未在请求中传递会话标识参数，导致每次调用被视为全新会话，无法复用历史台账数据。
- 现象：响应返回的`responseData`中存在与备案不一致的配方字段，导致台账审核不通过。原因：未配置响应字段过滤规则，返回了超出备案范围的非合规数据。
- 现象：接口调用返回402状态码，提示额度不足。原因：未配置请求频率控制，且未关联企业自有API额度监控，导致超额消耗触发扣费。

## 怎么确认配好了
- 发起一次按生产批次触发的接口请求，检查请求头中是否携带`Authorization`鉴权信息，确认鉴权配置生效。
- 查看响应体中的`responseData`字段，确认仅包含备案匹配的台账字段，验证字段过滤配置生效。
- 模拟两次连续的同批次接口请求，检查第二次请求是否复用第一次的上下文数据，验证会话配置生效。
- 观察接口调用日志，确认触发5xx状态码时自动重试，验证异常处理配置生效。
