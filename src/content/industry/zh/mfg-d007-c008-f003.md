# 化妆品生产的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据来自护肤、洗护、彩妆及特殊化妆品生产企业的日常生产文档，包括配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品与成品检验报告、标签审核资料。数据来源涵盖注册备案配方、原料安全资料、生产设备、ERP/MES系统、实验室数据及包材版本信息，更新节奏为每生产一批或每次换线时更新，字段包含原料成分、投料量、生产参数、检验结果、批号与包材信息等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据按批次或换线更新，且涉及备案合规要求，要求多轮对话需绑定具体生产批次上下文，避免跨批次数据混淆。日常文档包含多类结构化与非结构化字段，提示词需引导用户按生产环节依次提供投料、检验、清场等完整数据，防止遗漏配方成分、限用物质含量等关键信息。同时，数据来源覆盖多系统，提示词需支持关联不同来源的台账数据，确保汇总时的一致性，且需在对话中嵌入合规性校验提示，减少配方与备案不符、错标等风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 对话上下文窗口 | 保留最近 20 条 `messages` | 单批次生产的全流程对话数据量适中，20条足够覆盖从投料到成品检验的完整提问链 |
| 会话标识绑定 | 按`chatId`归档对话记录 | 匹配生产批次的独立管理需求，便于后续追溯对应批次的台账汇总过程 |
| 全局变量配置 | 绑定`variables`中的生产批号、车间信息 | 确保每轮对话关联对应生产场景的专属数据，避免不同批次的台账混淆 |
| 工具触发规则 | 检测到配方、检验或清场关键词时触发 | 自动调用对应生产环节的台账文档，提升汇总效率 |
| 空结果处理 | 当`messages`返回空时提示补充关键信息 | 对应实际使用中出现的空结果问题，避免前端展示空白 |
| 上下文长度限制 | 按实测标定 8000–12000 token | 覆盖多类生产文档的完整内容，避免截断关键合规信息 |
| 超时设置 | 设为 60 秒 | 匹配生产设备、ERP系统数据返回的常规延迟 |

## 容易做错的三处
- 现象：AI对话节点返回empty或报错提示，前端展示空白结果。原因：未配置针对`messages`为空或大模型调用失败的分支处理逻辑，直接透传原始返回结果。
- 现象：调用图表工具生成生产台账图表时，图表显示为空。原因：未在提示词中明确绑定对应批次的`variables`数据，工具无法获取正确的台账参数。
- 现象：尝试删除对话记录无法完成，请求返回异常状态码。原因：未正确关联`chatId`参数，系统无法定位目标对话记录。

## 怎么确认配好了
- 发起单批次生产台账的提问，检查对话上下文是否保留了该批次的关键信息。
- 触发工具调用，验证是否能正确获取绑定的`variables`字段数据。
- 模拟大模型返回empty的场景，检查是否触发预设的报错提示逻辑。
- 发起对话后，通过对话管理界面验证`chatId`是否正确关联当前会话。
