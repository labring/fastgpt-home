# 化妆品生产的生产台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
该品类数据涵盖护肤、洗护、彩妆及特殊化妆品生产企业的全流程文档，包括配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验报告、标签审核文档。数据来源包括注册或备案配方、原料安全资料、生产设备、ERP/MES系统、实验室数据及包材版本信息，更新频率为每批生产或每次换线时更新，核心字段包含备案编号、原料批次、生产参数、检验结果、包材批号等。

## 这些特征在「数据库与运维」这一环带来什么约束
每批或换线的高频更新要求数据库支持低延迟写入与批量操作，避免阻塞生产流程。多来源的异构数据需兼容结构化参数与非结构化文档存储，同时需关联备案编号、批次号等唯一标识，确保数据可追溯。受备案约束的配方与标签数据需保证强一致性，防止出现与备案信息不一致的记录，且需支持按批次快速查询历史台账，满足合规性核查需求。

## 配置怎么定
本配置基于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://prod_user:secure_pass@db-host:27017/cosmetic_prod?authSource=admin` | 适配多类型生产文档的存储与关联查询，支持批量写入台账数据 |
| `PG_URL` | `postgresql://meta_user:secure_pass@meta-host:5432/cosmetic_meta?sslmode=require` | 存储强一致性的备案元数据、检验报告等需合规追溯的结构化数据 |
| `DB_MAX_LINK` | `20–30 个连接` | 匹配每批生产的并发写入与查询请求，避免数据库连接耗尽 |
| `REDIS_URL` | `redis://cache_user:secure_pass@cache-host:6379/0` | 缓存高频查询的备案配方、批次关联信息，降低数据库查询延迟 |

## 容易做错的三处
- 现象：通过docker部署后修改数据库密码，无法正常连接数据库，控制台返回认证失败报错。原因：未同步更新`MONGODB_URI`配置中的密码参数，导致连接校验不通过。
- 现象：开启问题优化与结果重排功能后，生产台账报告生成超时，响应时长超过30秒。原因：未调整`DB_MAX_LINK`参数，数据库连接池无法支撑高频并发的检索请求。
- 现象：工具选择环节出现重复调用，生成多份内容一致的台账报告。原因：工作流未配置任务去重逻辑，导致同一批次的生产数据被多次触发汇总任务。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`与`PG_URL`配置的连接有效性，确认无认证失败报错。
- 模拟单次换线后的批量数据写入，检查`DB_MAX_LINK`参数是否支撑并发写入请求，无连接耗尽提示。
- 查看Redis缓存的备案配方数据，确认`REDIS_URL`配置的缓存命中正常，无频繁穿透数据库的日志。
- 触发一次台账报告生成任务，检查是否出现重复任务或超时情况，确认工作流逻辑正常。
