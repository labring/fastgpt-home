# 化学药制剂生产的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源为经批准处方工艺、MES电子批记录、设备与环境监测数据、LIMS系统、质量管理系统。数据按每批生产、关键工艺步骤执行及监测计划更新。日常文档包含主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差/CAPA/变更文件及批放行审核表。数据字段包含物料批次号、称量投料数值、工艺参数、偏差描述、检验结果等，关联单位包括千克、摄氏度、小时等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
每批独立的生产数据要求对话上下文需绑定指定批次标识，避免跨批次数据混淆。多类专业文档与字段要求提示词需明确限定调用的文档类型与字段范围，确保返回内容匹配生产台账的合规格式。按步骤与批次更新的数据节奏，要求多轮对话保留历史交互记录以支撑回溯复核。严格的合规要求需对话工具在生成报告前校验数据来源的关联性，避免遗漏偏差或检验记录。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| chatId | 绑定当前生产批次的唯一ID | 隔离不同批次的对话上下文，避免数据串用 |
| messages | 以「批次标识+指定文档类型+任务指令」为固定开头 | 统一输入格式，确保模型精准匹配台账范围 |
| variables | 预设物料批次号、偏差类型等核心参数 | 简化多轮对话的重复输入步骤 |
| 单次回复最大token数 | 8000–12000 token | 适配单批次批记录汇总的长文本输出需求 |
| 上下文保留轮次 | 近3轮交互+本批次全量文档 | 覆盖当前任务所需的历史操作与全部关联数据 |
| 文件上传校验规则 | 按文件类型过滤批记录类文档 | 确保仅导入合规的生产台账文件 |

## 容易做错的三处
- 现象：上传批记录文件时提示fail to create post presigned url，无法完成附件加载。原因：S3存储配置的签名参数未同步完成迁移，导致预签名URL生成失败。
- 现象：多轮对话生成的报告未按要求返回指定格式，字段缺失或结构混乱。原因：提示词未明确指定输出的字段与格式约束，未引导模型遵循合规文档结构。
- 现象：对话中调用的台账数据与当前生产批次不匹配，出现跨批次的错误内容。原因：未绑定chatId或chatId未关联当前生产批次，导致上下文串用不同批次的数据。

## 怎么确认配好了
- 发起包含目标生产批次标识的测试对话，核对返回的台账数据是否仅关联指定批次的文档。
- 上传测试用批记录文件，确认文件可正常加载且无格式报错。
- 触发报告生成任务，检查输出内容是否符合预设的文档结构与字段要求。
- 测试多轮交互的上下文保留，确认历史对话的参数与指令可被正确调用。
