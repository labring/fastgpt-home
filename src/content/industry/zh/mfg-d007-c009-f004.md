# 化学药制剂生产的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
化学药制剂生产的台账数据来源包括经批准处方工艺、物料批次、MES/电子批记录、设备与环境监测、LIMS及质量管理系统。数据更新频率为每批生产、每个关键工艺步骤执行时，以及按固定监测计划更新。日常文档涵盖主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差/CAPA/变更文件及批放行审核表，字段包含物料批次号、工艺参数值、检验结果、偏差描述等，单位涉及千克、摄氏度、小时等计量标准。

## 这些特征在「工作流编排」这一环带来什么约束
多源分散的数据来源要求工作流需对接多个独立节点拉取不同类型台账数据。按批次与关键步骤的更新节奏，要求工作流需绑定批次维度触发，适配单次批次全流程的数据汇总需求。多样的文档结构要求工作流需支持不同格式数据的适配解析。GMP合规要求下，数据需与操作同步，工作流需加入数据校验环节避免不一致。耗时的台账复核汇总环节，要求工作流可自动整合分散数据，减少人工复核工作量，同时需配置失败处理逻辑应对数据异常。

## 配置怎么定
本页面基于FastGPT v4.17.0版本的工作流配置逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按批次编号触发 | 匹配每批生产的台账数据更新频率，符合批次追溯要求 |
| `variables` | 绑定批次号、物料批次、工艺参数字段 | 确保各节点精准调用对应批次的生产数据 |
| 节点输入校验 | 开启必填字段校验 | 避免缺失物料批次、检验结果等关键数据影响后续流程 |
| HTTP请求超时时间 | 300 秒 | 适配多数据源拉取的耗时，避免因数据未完全拉取导致流程中断 |
| 最大上下文长度 | 8000 token | 适配长文本台账的汇总需求 |
| `nodeId` | 为每个数据源节点配置唯一标识 | 便于排查数据流转异常 |

## 容易做错的三处
- 工作流运行时弹出「Cannot convert undefined or null to object」报错，原因是未配置`variables`绑定批次号等必填字段，导致节点接收空数据。
- AI对话生成的内容直接展示在页面弹窗中，无法通过指定组件输出最终报告，原因是未关闭默认对话输出开关，未配置文本拼接与指定回复节点的流转链路。
- 知识库检索结果无法被AI对话正确引用，原因是未将检验记录、偏差数据转换为结构化字段格式，不符合AI对话的引用数据要求。

## 怎么确认配好了
- 输入测试批次编号，触发工作流运行，检查各数据源节点是否正确拉取对应批次的台账数据。
- 查看工作流流转日志，确认`variables`绑定的字段是否正常传递到后续所有节点。
- 故意缺失某一必填字段后运行工作流，确认触发对应报错提示，验证失败处理逻辑生效。
- 查看文本拼接后的内容，对照GMP台账报告的格式要求，调整拼接规则至符合预期。
