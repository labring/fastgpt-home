# 化学药制剂生产的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
化学药制剂生产的数据来源包括经批准处方工艺、物料批次信息、MES电子批记录、设备与环境监测数据、LIMS检验结果、质量管理系统中的偏差与变更记录。数据更新节奏为每生产批次、每个关键工艺步骤执行时更新，或按固定监测计划同步。日常文档包含主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差/CAPA/变更文件及批放行审核表，文档字段涵盖物料批次号、工艺参数数值、检验结果、偏差描述等，对应单位包括批次编号、摄氏度、千克、百分比等。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且关联多系统，要求模型接入配置需适配多源数据的拉取与关联逻辑；每批数据更新且需严格合规，要求配置的上下文窗口需适配单批次完整数据量，避免截断关键信息；文档字段多且包含专业医药生产术语，要求模型配置需适配专业表述的理解与生成；批记录审核需严格数据完整性，要求模型输出需附带明确的引用来源，确保可追溯。同时，变更与偏差记录需实时纳入汇总，要求配置的模型响应延迟需匹配生产节奏，避免影响放行流程。

## 配置怎么定
以下配置项适用于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单批次完整生产台账的上下文长度，避免截断关键工艺与检验数据 |
| `maxTokens` | 2000–3000 token | 控制单份报告生成的输出长度，确保覆盖完整的批记录汇总与放行判断逻辑 |
| `quoteMaxToken` | 1500 token | 限定引用源数据的长度，保证引用内容准确且不干扰主报告逻辑 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保医药生产相关的专业表述与合规性判断准确一致 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 对接本地或云端的大模型服务，适配企业内部网络环境 |
| `AIPROXY_API_TOKEN` | 按部署生成的密钥填写 | 验证模型服务的访问权限，确保数据交互的安全性 |

## 容易做错的三处
- 调用模型时返回404状态码，原因是未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，或部署的模型服务未开放对应访问端口。
- 生成的报告截断了关键工艺数据，原因是`maxContext`或`maxTokens`取值过小，未覆盖单批次完整台账数据。
- 输出结果一致性差，专业表述或合规判断出现随机偏差，原因是`temperature`取值过高，超出适配医药生产场景的合理区间。

## 怎么确认配好了
- 输入单批次的典型台账数据片段，触发汇总报告生成，检查输出是否包含所有关键字段的汇总内容。
- 查看模型服务的访问日志，确认无`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`相关的认证失败记录。
- 生成报告后，核对引用的源数据片段是否与输入的台账内容一致，确认`quoteMaxToken`配置生效。
- 调整`temperature`取值并对比输出结果，观察生成逻辑的一致性变化，确认配置符合预期。
