# 医疗器械装配与洁净生产的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源于设计历史文件、器件与材料批次记录、MES系统、洁净环境监测设备、灭菌设备、检验校准系统。数据按每批产品或每台设备生成更新，同时按洁净区环境监测计划定期同步。日常文档包含生产工艺规程、批生产记录、洁净区运行记录、灭菌批记录、检验报告、软件版本记录、不良事件与追溯资料。数据字段包含器械唯一标识、材料批次号、灭菌参数、洁净区温湿度、软件版本号等，对应单位为℃、Pa、分钟、批次号等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据来源分散且跨多业务系统，要求多轮对话需关联不同数据源的台账内容，避免上下文断裂。单批数据量较大且更新频率高，需动态加载最新的批生产记录与灭菌数据，确保对话内容与当前生产批次匹配。文档字段多且带有专业合规要求，提示词需精准匹配灭菌参数、洁净度指标等专属字段，无法泛化处理。同时产品追溯要求严格，对话需保留历史批次的关联信息，确保多轮交互的上下文连贯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 token | 匹配单批医疗器械台账的典型数据量，避免超出模型输入上限 |
| 历史消息保留条数 | 前20条 | 覆盖单批生产流程的核心环节，确保多轮对话的上下文完整 |
| 输入内容拦截阈值 | 15000字符 | 提前拦截超出模型承载范围的输入，避免无意义报错 |
| 对话上下文标识 | `chatId`绑定生产批次ID | 确保同批次的多轮对话共享连贯的上下文，符合追溯要求 |
| 提示词变量绑定 | 绑定`variables`中的批次号、灭菌参数 | 精准调用品类专属的台账数据，提升回复的合规性与准确性 |
| FastGPT版本 | FastGPT v4.17.0 | 适配多轮对话与提示词的最新配置逻辑 |

## 容易做错的三处
- 输入内容超过模型输入上限时返回空白或“输入过长”报错，原因是未配置输入长度拦截规则，直接提交超出阈值的`messages`数组。
- 对话请求未返回cite引用id，原因是提示词未明确要求关联台账的具体文档来源字段，未开启溯源绑定配置。
- 多轮对话无法基于历史问题展开新回复，原因是未使用`chatId`参数绑定生产批次上下文，导致每次对话的历史`messages`未被保留。

## 怎么确认配好了
- 上传单批医疗器械台账数据，构造超过15000字符的输入内容，确认界面触发输入拦截提示。
- 发起两轮以上对话，输入历史批次相关问题后，确认下一轮回复关联了历史对话中的批次信息。
- 查看对话接口返回结果，确认包含台账文档来源的引用标识。
- 配置`variables`绑定灭菌参数与洁净区记录字段，测试提示词输出包含对应专业数据的内容。
