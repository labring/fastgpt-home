# 半导体封装测试的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
半导体封装测试的生产数据来源覆盖晶圆测试图、MES系统、键合机与塑封设备日志、ATE测试机数据、X-ray/SAM检测报告及客户规格文件。数据更新节奏按生产批次、单颗芯片测试结果、每日设备运行状态分三级。日常文档包含封装流程卡、键合与塑封参数表、晶圆来料图、测试程序版本文件、良率汇总报告及失效分析报告，字段涵盖工序ID、批次标识、测试参数、失效点位坐标等，为多源异构的非统一格式数据。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据类型要求向量模型同时支持文本与图表类数据的向量化处理；高频更新的生产数据需要适配增量索引构建逻辑，避免全量重建带来的性能损耗；批次关联字段（如批次号、测试程序版本）需作为元数据绑定至向量索引，确保检索时可精准关联同批次的多类文档；单颗测试的细粒度数据需合理控制分块长度，避免拆分关键关联信息；每日汇总的台账数据需保证上下文长度足够，支撑完整的报告生成逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `defaultToken` | 4096 | 适配良率报告、失效分析报告的常规token长度，保证关键参数不被截断 |
| 分块长度 | 800–1200 字符 | 适配封装流程卡、测试程序版本文件的单段文本长度，避免拆分核心工序信息 |
| 重叠长度 | 100–150 字符 | 保留批次号、测试参数等跨块关联字段的上下文，提升检索精准度 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的设备日志与测试报告，减少无关召回结果 |
| 单次搜索上限 | 前10条 | 控制单轮召回的文档数量，适配生产台账的批量汇总需求 |
| 最大上下文 | 16000 字符 | 容纳多份关联台账的汇总内容，满足完整报告生成的上下文要求 |

## 容易做错的三处
-  界面显示“检索结果为空”，原因是未将晶圆批次号作为元数据绑定至向量索引，无法关联晶圆来料图与生产台账数据。
-  调用时提示“模型不可选”，原因是未配置对应Embedding模型的API访问权限，或本地部署时未正确映射模型服务端口。
-  导入索引时出现“字段格式不匹配”报错，原因是未统一封装流程卡、测试程序版本的字段命名规则，导致向量化时无法识别关联字段。
-  检索结果未附带晶圆测试图，原因是未开启多模态向量化配置，未将图片数据单独存入向量索引并关联批次元数据。

## 怎么确认配好了
-  上传单份封装流程卡，检查分块后的文本是否保留完整的工序参数与批次标识。
-  发起包含指定晶圆批次号的检索请求，核对召回结果是否包含对应批次的所有关联文档。
-  查看FastGPT v4.17.0的向量模型运行日志，确认未出现模型调用超时或参数不兼容报错。
-  导入一批测试生产数据，检查索引创建进度是否匹配预设的每批/每日更新节奏。
