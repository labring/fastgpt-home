# 印刷与包装加工的生产台账汇总与报告生成：数据库与运维

本文为对应场景的数据库与运维配置指南，适用于 FastGPT v4.17.0 版本。

## 这个品类的数据长什么样
本品类数据涵盖印前文件、拼版单、印刷工艺单、油墨配色记录、首件签样、条码检测、模切与复合记录等日常文档。数据来源包括客户稿件、色彩管理系统、印刷机运行数据、油墨与基材批次记录、分光仪检测结果、条码检测仪读数。数据更新节奏为每订单、每生产批次、每次印版更换时触发。数据字段包含订单标识、印版版本号、油墨批次编码、基材型号、色差参数、条码可读性数值、生产时长等，部分字段为字符串类型，部分为数值型检测结果，无统一固定单位。

## 这些特征在「数据库与运维」这一环带来什么约束
数据高频且多节点更新，要求数据库支持高并发写入与事务一致性，避免换版或批次切换时的数据冲突。数据来源分散且包含多类型内容，需兼容结构化的台账字段与非结构化的图像、时序文档存储。单次生产批次的数据量随订单复杂度提升，需预留足够的存储容量应对峰值写入。数据关联关系复杂，需建立订单号与各环节文档的关联索引，便于台账汇总时快速关联全流程数据。同时，因错版、条码异常等问题会导致整批报废，需保留完整数据审计轨迹，便于追溯问题源头。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配印刷工艺单、拼版单等文档的文本长度，确保索引覆盖完整内容 |
| 单次搜索上限 | 前 150 条 | 匹配批次级生产数据的查询规模，避免返回过多冗余数据 |
| `MONGODB_URI` | 填写自建或托管的 MongoDB 连接字符串 | 用于存储印前文件、首件签样等非结构化文档数据 |
| `PG_URL` | 填写 Supabase 或自建 PostgreSQL 连接地址 | 用于存储结构化的油墨批次、条码检测数值等台账字段 |
| `DB_MAX_LINK` | 12–18 个 | 适配高频的换版、批次更新数据写入，防止连接池耗尽 |
| `REDIS_URL` | 填写本地缓存服务地址 | 缓存高频查询的订单关联数据，降低数据库查询延迟 |

## 容易做错的三处
- 现象：MongoDB 连接失败，返回连接超时或认证失败错误，即使按照官方文档配置仍无法恢复。原因：未适配印刷包装加工场景的高频写入需求，连接池配置不足，或认证信息中未包含正确的数据库访问权限。
- 现象：PostgreSQL 连接 Supabase 后无法查询批次数据，返回权限不足或表不存在错误。原因：未在 Supabase 中配置对应数据库的访问白名单，或未授予台账数据的读写权限。
- 现象：知识库查询时报错 `text index required for $text query`，无法生成生产报告。原因：未为存储印刷工艺单、拼版单的字段创建全文索引，导致文本查询无法正常执行。

## 怎么确认配好了
- 执行数据库连接测试，验证`MONGODB_URI`与`PG_URL`的配置可正常建立连接并读取测试表数据。
- 提交一笔模拟生产批次的测试数据，验证数据可按配置的更新节奏写入数据库并完成关联。
- 触发生产台账汇总任务，核对返回的字段包含订单号、油墨批次、检测结果等品类专属数据。
- 运行文本查询测试，验证已创建的全文索引可正常返回印刷工艺单、拼版单的匹配结果。
