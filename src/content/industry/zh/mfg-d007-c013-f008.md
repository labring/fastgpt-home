# 印刷与包装加工的生产台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
该品类主体为彩印、标签、纸箱、软包装和药包材加工企业，日常生产台账涵盖印前文件、拼版单、印刷工艺单、油墨配色记录、首件签样、条码检测、模切与复合记录等文档。数据来源包括客户稿件、色彩管理系统、印刷机运行数据、油墨与基材批次记录、分光仪检测结果、条码检测仪读数等。数据更新频率为每订单、每批生产任务或每次印版更换时更新，文档包含版次、批次号、色彩参数、基材克重、条码编号等专属字段，部分文档附带扫描图像与检测数值。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的高频更新与多类型文档特征，要求文档解析需支持批量任务处理与多格式兼容。专属字段与图像类文档的存在，要求分块逻辑需保留字段关联，避免拆分关键的批次、版次信息。扫描版首件签样、条码检测记录等图像类文档，需要解析工具支持图像文本提取，否则会丢失核心检测数据。同时，印版错误会导致整批报废的业务特性，要求解析结果需准确匹配订单与对应台账内容，避免跨订单内容混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 字符` | 该品类台账文档包含单批次完整的工艺参数与批次信息，该分块长度可适配单订单台账的信息完整性，避免拆分关键字段 |
| `chunkSplitter` | 按页眉页脚+批次号拆分 | 日常台账文档按订单或换版生成带版次、批次号的页眉，按此规则拆分可准确区分不同订单的台账内容 |
| `customPdfParse` | 启用 | 该品类存在扫描版首件签样、条码检测记录等图像类PDF文档，启用自定义解析可提取图像中的文本与条码信息 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300–600 秒` | 批量上传多份工艺单、拼版单时，解析耗时随文件数量增加，该区间可覆盖常规批量任务的解析需求 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 该品类的印前文件可能包含高清图像素材，需支持大文件上传以完整解析全部内容 |
| `chunkSettingMode` | 手动配置 | 该品类文档结构差异较大，手动配置可适配不同类型的台账文档，优化分块准确性 |

## 容易做错的三处
- 上传多个订单的台账文件后，分块结果中出现跨订单的内容拼接。未配置`chunkSplitter`按订单批次号拆分，默认分块逻辑按字符长度拆分，未区分不同文档的边界。
- 知识库搜索测试无法命中扫描版首件签样的内容。未启用`customPdfParse`，未提取扫描图像中的文本与条码信息，导致搜索无匹配结果。
- 批量上传大尺寸印前文件时出现解析超时报错。`PARSE_FILE_TIMEOUT_SECONDS`配置值低于实际解析耗时，未覆盖多文件批量处理的时间需求。

## 怎么确认配好了
FastGPT v4.17.0版本下，可通过以下动作核对配置效果：
- 上传单份包含版次、批次号的台账文件，检查分块结果中是否按订单边界拆分，无跨订单内容拼接。
- 上传扫描版首件签样文件，确认解析结果中包含图像中的文字与条码信息，无内容丢失。
- 批量上传3-5份不同订单的文件，检查解析任务是否在`PARSE_FILE_TIMEOUT_SECONDS`配置的区间内完成，无超时报错。
- 调整`chunkSize`配置值后，对比不同配置下的分块结果，确认分块长度适配单批次台账的信息完整性。
