# 印染与后整理的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自染整厂、面料企业的染色、定形、实验室与质量部门，涵盖染色配方、称化料记录、染缸运行曲线、打样确认单、色差报告、定形工艺单、污水台账等文档。数据来源包含客户色样、配方库、染化料批次记录、染缸控制系统、测色仪、定形机参数及环保监测数据。数据更新频率为每缸、每批、每班，单条数据包含工艺参数、批次信息、检测结果、排放指标等字段，单位涵盖温度、浓度、批次编号、检测数值等。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类多源异构的数据结构，包含仪器导出的曲线文件、手工填写的纸质台账扫描件、结构化的检测数值，要求向量模型与索引支持混合格式的内容解析与向量化。高频更新频率要求索引适配增量写入逻辑，避免全量重建带来的性能损耗。单条数据包含工艺参数、批次编号、检测结果等密集字段，要求索引的召回逻辑兼顾工艺参数匹配与语义关联。污水台账的溯源需求要求索引保留完整的批次关联字段，支持按生产周期精准过滤。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配本品类单条台账的字段密度，避免单块包含过多跨批次关联信息 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的工艺衔接信息，避免染缸曲线、配方调整的上下文断裂 |
| 相似度阈值 | 0.75–0.85 | 匹配工艺参数与历史记录的相似程度，兼顾召回精度与覆盖范围 |
| 单次搜索上限 | 前 10 条 | 限制返回结果数量，适配生产台账的批量查询场景 |
| `maxToken` | 8000 | 适配长文档的向量化处理，满足染缸曲线完整段落的输入需求 |
| 最大上下文 | 4000–6000 字符 | 控制召回内容的总长度，避免超出模型处理上限 |

## 容易做错的三处
- 界面索引模型下拉列表无选项可选择。原因是未在系统配置中启用对应嵌入模型的本地部署或远程调用权限，导致可选列表未加载。
- 召回结果中缺失染缸曲线的关键参数段。原因是分块长度设置过小，将完整的升温曲线拆分为多个不关联的分块，导致语义断裂。
- 生成的报告中出现批次关联错误。原因是未开启按生产批次过滤的索引配置，召回结果混入了非当前订单的生产台账数据。

## 怎么确认配好了
- 上传单份染缸曲线文档，检查分块后的内容是否保留完整的升温、加料、保温阶段信息。
- 发起包含具体染缸参数的查询，核对召回结果的条数是否符合单次搜索上限的设置。
- 导入历史污水台账数据，验证索引是否支持按生产班次、批次编号进行精准过滤。
- 检查`maxToken`的配置是否匹配上传文档的最大长度，避免出现内容截断提示。
