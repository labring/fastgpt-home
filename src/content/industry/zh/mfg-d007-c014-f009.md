# 印染与后整理的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自染整厂染色、定形、实验室与质量部门，涵盖染色配方、称化料记录、染缸运行曲线、打样确认单、色差报告、定形工艺单、污水台账等文档。数据来源包含客户色样、配方库、染化料批次记录、染缸控制系统、测色仪、定形机参数及环保监测数据，更新节奏按每缸、每批或每班触发，单条数据包含工艺参数、批次信息、检测结果等字段，单位涉及温度、浓度、批次编号、排放值等。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据按缸、批、班高频更新，模型接入需支持短周期增量数据同步，避免全量拉取占用过多资源。多类型异构文档（如曲线类、数值类、文本类）要求配置适配混合格式的上下文处理能力。单缸数据量有限但批次关联紧密，需限定上下文窗口避免冗余信息干扰。环保监测数据需严格匹配合规字段，模型调用需保留原始数据的关联标识，防止字段丢失。同时，色差报告等依赖专业判断的文档，需配置合适的参数平衡准确性与响应速度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单缸关联的染色配方、染缸曲线、色差报告等多份文档的上下文长度，避免截断关键工艺数据 |
| `maxTokens` | 4000 token | 控制单份生产台账报告的输出长度，匹配染整行业汇总文档的常规信息密度 |
| `temperature` | 0.2–0.4 | 平衡工艺参数的准确性与格式规范性，减少专业术语的生成偏差 |
| `toolChoice` | auto | 自动触发函数调用，完成染缸曲线、测色数据的结构化解析与汇总 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或云端的大模型接入路径，确保请求正常路由 |
| `AIPROXY_API_TOKEN` | 按实际生成的密钥填写 | 完成身份验证，防止未授权访问模型接口 |

## 容易做错的三处
- 调用时返回`400 Bad Request`，提示上下文长度超限。原因是未针对染整批次关联的多份文档调整`maxContext`参数，导致单次请求的总token数超出模型限制。
- 无法通过OneAPI调用部署的Ollama模型完成函数调用。原因是未将`toolChoice`配置为`auto`，且未在模型接入配置中开启函数调用支持。
- 生成的台账报告缺失染化料批次信息。原因是未在上下文配置中保留原始数据的关联标识，导致模型在汇总时遗漏批次字段。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的界面，上传单缸的染色配方、染缸曲线与色差报告，测试模型生成汇总文档，检查是否包含所有必填字段。
- 查看接口调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置未出现拼写错误，无请求超时记录。
- 调整`temperature`参数至0.3左右，对比两次生成的报告，确认专业术语的一致性符合预期。
- 开启函数调用测试，验证模型能否自动解析染缸曲线中的升温数据并生成结构化汇总。
