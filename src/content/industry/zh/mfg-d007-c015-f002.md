# 原料药与医药中间体生产的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来源包括注册工艺文档、原料批次台账、DCS系统运行数据、称量系统记录、LIMS检测报告、色谱数据系统文件及QMS偏差与变更文件。数据更新节奏为每生产批次、每工艺步骤触发。日常文档涵盖批生产记录、物料平衡表、反应与精制日志、清洁验证记录、杂质谱报告、偏差与变更申请文件，字段包含批次编号、反应温度、收率数值、杂质含量、溶剂残留量等，附带大量医药化工专业术语与精准工艺参数。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据按批次与工艺步骤高频更新，要求向量索引支持增量嵌入，避免全量重嵌带来的冗余处理。文档包含大量医药化工专业术语与结构化工艺参数，需选用适配专业领域的embedding模型，保障专业文本的召回精度。单批次文档长度跨度较大，从简短的清洁记录到完整的杂质谱报告均有覆盖，索引拆分策略需适配不同长度的文本。同时数据关联批次元数据，索引需支持按批次维度过滤检索，提升台账汇总的精准性。

本配置基于FastGPT v4.17.0版本适配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配批生产记录、杂质谱报告的常规文本长度，避免专业术语被截断 |
| 重叠长度 | 100–150 字符 | 保留跨块的反应步骤、杂质关联信息，提升召回结果的连贯性 |
| `defaultToken` | 4096 token | 匹配医药专业文本的平均token密度，适配多数文档的拆分需求 |
| `maxToken` | 8192 token | 覆盖完整的反应与精制记录全文，避免截断关键工艺参数 |
| 相似度阈值 | 按实测标定 | 适配杂质谱、偏差记录的专业文本相似度匹配精度 |
| 单次搜索上限 | 前10条 | 平衡召回覆盖率与检索效率，适配多批次台账的快速汇总 |

## 容易做错的三处
- 现象：更换embedding模型后，旧台账文档的索引召回结果异常，批量重嵌耗时过长。原因：未配置增量索引更新策略，触发全量重嵌处理所有历史文档。
- 现象：手动插入的批生产记录文档，索引状态显示正常后数小时自动消失。原因：未开启索引持久化存储，或批次元数据未正确关联至索引条目。
- 现象：接入qwen3-embedding-8b模型后，杂质谱报告的文件状态持续显示“索引中”。原因：embedding模型的输入token上限与文档分块长度不匹配，导致处理超时。

## 怎么确认配好了
- 上传单份完整的杂质谱报告，检查索引生成耗时符合预期。
- 更换embedding模型后，手动触发单文档重嵌，验证多语言文本的召回结果一致性。
- 查看索引存储目录，确认新生成的索引文件随文档更新同步生成。
- 检索特定批次的工艺参数，验证召回结果包含对应批次的元数据信息。
