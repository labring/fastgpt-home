# 原料药与医药中间体生产的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
原料药与医药中间体生产的台账数据来源覆盖注册工艺文档、原料批次记录、DCS系统、称量系统、LIMS、色谱数据系统及QMS。数据更新以每生产批次、每工艺步骤为节奏，包含批生产记录、物料平衡文档、反应与精制记录、清洁验证记录、杂质谱报告、偏差与变更文件等。核心字段包含批次标识、投料量、反应时长、精制参数、杂质峰数据、偏差描述等，单位涉及千克、小时、毫升等专业生产计量标准。

## 这些特征在「模型接入与配置」这一环带来什么约束
多系统异构数据源要求模型接入时需兼容不同格式的台账数据，避免格式解析错误。单批次数据量较大且包含专业化工术语，需限制模型输出的随机性以保障关键字段的准确性。高频次的批次级更新要求配置项能快速适配单批次的上下文规模，同时需保障数据传输的隐私性，避免敏感生产信息泄露。此外，杂质谱、收率等核心业务字段的提取精度直接影响报告合规性，需对模型的生成逻辑做针对性配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单批次生产台账的多文档拼接，覆盖批记录、杂质谱、偏差文件等全量关联数据 |
| `maxTokens` | 4000–6000 token | 满足长报告生成的输出长度，容纳汇总的收率、杂质、转序等核心业务信息 |
| `temperature` | 0.1–0.3 | 降低模型输出的随机性，确保批次号、杂质含量等关键专业字段的提取一致性 |
| 工作流/API 工具选择配置 | auto | 自动调用知识库检索，匹配多系统来源的异构台账数据，提升信息召回的完整性 |
| `AIPROXY_API_ENDPOINT` | 按FastGPT v4.17.0平台提供的专属地址填写 | 对接合规的模型调用链路，适配医药生产数据的隐私保护要求 |
| `AIPROXY_API_TOKEN` | 按FastGPT平台生成的专属密钥填写 | 保障模型调用的身份验证与数据传输的安全性 |

## 容易做错的三处
- 现象：大模型调用后返回空响应，或生成的报告缺失杂质谱相关字段。原因：`maxTokens`设置过低，无法容纳完整的杂质谱报告内容，导致模型截断输出或无有效内容生成。
- 现象：相同问题多次调用返回不一致的私有知识库答案。原因：`temperature`设置过高，模型对专业术语的提取出现随机偏差，且未限定`toolChoice`为固定检索模式，导致调用逻辑不稳定。
- 现象：配置语音模型后无法正常触发任务。原因：未在FastGPT v4.17.0的语音配置模块中绑定对应`AIPROXY_API_TOKEN`，或选择了平台未支持的语音模型类型。

## 怎么确认配好了
- 上传单批次的完整生产台账文档，触发台账汇总任务，检查输出报告是否包含预设的核心业务字段，如批次号、投料量、反应时长等。
- 多次触发相同的汇总请求，核对输出结果的一致性，确认`temperature`参数的取值符合业务对精度的要求。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置无格式错误，且调用链路返回正常状态码。
- 测试语音接入功能，输入语音指令触发台账汇总，确认能正确解析指令并返回对应报告内容。
