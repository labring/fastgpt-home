# 原料药与医药中间体生产的生产台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
该品类数据来自注册工艺文档、原料批次台账、DCS系统、称量系统、LIMS、色谱数据系统与QMS。日常生成的文档包括批生产记录、物料平衡表、反应与精制过程记录、清洁验证记录、杂质谱报告、偏差与变更文件。数据更新频率为每生产批次、每工艺步骤触发，文档包含工艺参数、批次编号、杂质含量、溶剂残留量、收率数据等字段，单位多涉及重量、浓度、反应温度与时间等专业工业参数。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据源导致数据格式不统一，需匹配不同系统的字段映射才能召回有效内容。高频次的按批次更新要求检索系统支持增量召回与实时同步，避免数据滞后。杂质谱、收率等专业字段的精准匹配需求，要求检索模型适配化工医药领域的专业术语与数值关联逻辑。多部门协同的文档类型覆盖，需支持按文档类别筛选召回结果，确保质量与注册部门能快速定位合规相关内容。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配原料药与医药中间体生产场景的台账检索需求。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配原料药工艺参数与杂质谱的专业术语，避免过低导致无关召回，过高遗漏有效批次记录 |
| `limit` | 前8条 | 覆盖单批次多步骤的台账文档数量，满足生产汇总报告的基础数据需求 |
| `searchMode` | vector+keyword | 结合语义检索与关键词匹配，精准召回批生产记录中的反应温度、收率等关键数值 |
| `usingReRank` | 开启 | 对召回的多源文档按专业相关性重排，优先展示杂质谱、物料平衡等核心报告 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展工艺相关的同义词，比如将“发酵”匹配“生物转化”，覆盖注册工艺的术语差异 |
| `collectionIds` | 按部门绑定对应知识库 | 区分合成、质量、注册部门的专属文档，避免跨部门无关数据干扰检索 |

## 容易做错的三处
-  界面展示仅显示检索结果，未展示知识库引用来源。原因是未开启知识库引用展示开关，默认配置下部分场景会隐藏引用信息。
-  特定知识库无法召回内容，新建知识库可正常召回。现象为检索结果条数为0，日志显示无匹配向量。原因是原知识库的文档分块未匹配医药专业文档的长度，或嵌入模型未适配化工术语的向量空间。
-  对话过程中无法主动将新台账信息加入知识库。现象为调用知识库更新接口后检索仍无新数据。原因是未配置增量同步触发机制，或更新的文档未上传至对应`collectionIds`绑定的知识库集合。

## 怎么确认配好了
-  输入单批次的工艺参数关键词，核对召回结果的文档类型与字段是否匹配目标台账内容。
-  查看检索结果的引用来源，确认是否展示对应知识库的文档路径与批次编号。
-  上传一份新的杂质谱报告，触发知识库同步后执行检索，确认新文档被成功召回。
-  调整`similarity`参数的取值，验证召回结果的数量与相关性是否符合预期。
