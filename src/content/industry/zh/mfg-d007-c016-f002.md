# 变压器与高压电器制造的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自设计BOM、硅钢片与绝缘材料入库数据、真空干燥设备日志、绝缘油化验报告、高压试验站记录。数据更新以单台产品或每批原材料为单位，每完成一台变压器或一批绝缘材料加工即生成新数据。日常文档包含绕制与器身装配记录、真空干燥流程记录、绝缘油性能报告、局放与耐压试验报告、产品铭牌参数表，字段涵盖绝缘含水量、局放峰值、耐压等级、引线连接参数等，各文档通过批次编号与产品唯一标识建立关联。

## 这些特征在「向量模型与索引」这一环带来什么约束
单台/每批的更新节奏要求索引支持增量同步，避免全量重建带来的资源消耗。多类型文档（结构化参数表、半结构化试验报告、非结构化设备日志）要求向量模型适配混合格式文本，同时索引需建立批次与产品编号的关联字段，实现跨文档关联检索。绝缘与高压试验数据的精度要求高，且出错后果严重，需确保向量召回的匹配精度，同时分块策略需保留关键参数的完整性，避免拆分导致核心信息丢失。此外，单台产品的关联文档数量有限，需合理设置召回上限以平衡检索效率与结果相关性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 该品类文档包含长段试验记录与参数表，该长度可保留单组试验数据的完整性，避免关键参数被拆分 |
| 重叠长度 | 50–80 字符 | 跨分块的关联参数（如批次编号、试验时间）需被相邻分块覆盖，确保检索时关联信息不丢失 |
| 相似度阈值 | 0.75–0.85 | 高压试验数据的精度要求高，需过滤低匹配度的无关历史数据，同时避免遗漏异常工况的匹配结果 |
| 单次搜索上限 | 前 10 条 | 单台产品的关联文档数量有限，过多召回会增加上下文处理负担 |
| `defaultToken` | 4096 | 该品类的试验报告与装配记录的总token数通常不超过该值，适配FastGPT v4.17.0主流向量模型的输入限制 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 现象：切换知识库向量模型后界面显示无进度且无法切换回原模型，原因是未开启强制索引重置配置，旧索引资源未释放，新模型的索引任务陷入阻塞。
- 现象：调用豆包embedding接口返回404错误，原因是未正确配置模型的API访问路径与版本标识，导致请求指向无效的服务端点。
- 现象：汇总报告中混入非目标批次的试验数据，原因是未建立批次与产品编号的关联索引字段，导致召回结果未按生产批次过滤。

## 怎么确认配好了
- 上传一份单台变压器的绝缘油报告与试验记录，执行关联检索，核对召回结果是否包含同批次的其他关联文档。
- 配置豆包embedding模型并发起测试请求，确认接口返回正常无404错误。
- 修改相似度阈值并执行检索，观察召回结果的数量变化是否符合预期调整逻辑。
- 查看FastGPT v4.17.0的索引任务日志，确认增量同步任务仅针对新上传的单台产品数据，未触发全量重建。
