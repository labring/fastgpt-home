# 基础化工连续生产的生产台账汇总与报告生成：向量模型与索引
本页面适配 FastGPT v4.17.0。

## 这个品类的数据长什么样
本品类数据来源包括DCS/SIS系统、在线分析仪、LIMS系统、设备状态监测模块、能源计量装置与原料储罐数据采集节点。数据更新节奏覆盖实时（如DCS参数）、每班（如班报、特殊作业票）、每日（如化验报告、工艺指标卡）。日常文档包含操作规程、工艺指标卡、DCS趋势图、化验报告、联锁旁路记录、特殊作业票、班报，字段包含设备编号、时间戳、工艺参数数值、操作记录，单位涵盖MPa、℃、m³、小时等工业常用单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引支持混合更新模式，兼容实时流式数据与定时批量数据的同步。不同文档类型的结构差异，要求向量分块策略适配结构化参数文本与非结构化操作记录的不同长度。更新节奏的差异，需要区分实时参数的增量索引与班报、化验报告的定时全量索引。`defaultToken`的配置需要匹配基础化工文档的平均编码需求，确保核心工艺内容被完整编码，避免关键联锁逻辑被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配DCS趋势、化验报告等文档的平均内容长度，避免单块内容过载 |
| 重叠长度 | 50–80 字符 | 保留跨块的工艺参数关联信息，防止分块切断关键联锁逻辑描述 |
| `defaultToken` | 4096 | 匹配基础化工文档的平均编码需求，覆盖单批次台账的核心内容 |
| `maxToken` | 8192 | 支持包含多份班报、联锁记录的长上下文检索，适配汇总报告生成需求 |
| 相似度阈值 | 0.72–0.80 按实测标定 | 过滤低相关的非工艺类文档，精准匹配工艺指标与异常记录 |
| 单次搜索上限 | 前10条 | 控制检索结果规模，避免报告生成时的上下文溢出 |

## 容易做错的三处
- 检索结果条数远低于预期，界面显示索引状态正常但无匹配数据。原因是未配置原始文档与向量数据的关联存储，仅将向量嵌入存入向量库而丢失原始文本的元数据标识，导致检索时无法正确关联到源文档。
- 语义检索返回的相似度分值普遍高于0.9，超出合理范围。原因是未对带单位的工艺参数文本做标准化处理，向量模型将不同单位的同类参数编码为高度相似的向量，导致分值异常偏高。
- 调用大模型生成报告时无法触发检索流程，正常问答环节无异常但报告生成环节无检索数据。原因是未将检索配置绑定到生产台账汇总的prompt模板，系统未触发向量索引的检索流程。

## 怎么确认配好了
- 查看向量库的关联元数据，确认原始文档的标识信息与嵌入向量一一绑定。
- 选取一份典型的工艺指标卡作为测试输入，发起检索，核对返回结果的相似度分值分布符合预设区间。
- 触发一次生产台账汇总任务，查看系统日志，确认检索环节被正常调用且返回了匹配文档。
- 检查混合更新任务的运行记录，确认实时流式数据与定时批量数据的同步均正常完成。
