# 塑料注塑成型的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类的数据覆盖注塑全流程，来源包括树脂批次物性表、注塑机运行参数、模温机数据、MES系统记录、尺寸外观检测结果。日常文档包含注塑工艺卡、原料干燥记录、模具履历、首件检验表、生产巡检表、换料清机记录。数据更新节奏为每生产批次、每次换模换料触发，每班汇总巡检与检测数据，字段包含原料含水率、注塑压力、模温、模具使用次数、产品尺寸偏差值等，带明确物理单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的高频更新、多格式混合的数据特征，对向量模型与索引环节带来多重约束。首先，每批、换模换料触发的实时更新，要求索引支持增量同步，不进行全量重建，避免影响生产节奏。其次，结构化参数与非结构化记录并存的文档结构，需要适配不同分块逻辑，确保工艺参数与巡检描述的向量编码匹配业务语义。最后，单批次数据量随生产规模扩大而累积，需限制单索引分片的存储容量，保障检索响应速度。

## 配置怎么定
本配置基于FastGPT v4.17.0版本适配

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配注塑工艺卡、巡检表的单页文本长度，避免块内语义断裂 |
| 重叠长度 | 100–150 字符 | 保留跨块的工艺参数关联信息，防止分块切断关键生产数据 |
| 相似度阈值 | 0.72–0.85 | 区分注塑缺陷的相似描述，避免将不同类型的缩水、飞边误判为同类 |
| 单次搜索上限 | 前 8 条 | 覆盖单批次生产台账的核心关联数据，减少冗余检索结果 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 150 token | 用于单条台账的基础向量编码，平衡语义精度与存储开销 |

## 容易做错的三处
- 界面长期显示「索引中」状态无更新。原因是未配置增量同步触发规则，全量索引扫描了历史累积的注塑生产台账数据，超出`defaultToken`的单批次处理上限导致超时。
- 自定义索引配置后检索结果无关联。原因是未将注塑台账的批次号、模具ID作为元数据绑定到向量块，导致检索无法匹配特定生产批次的关联文档。
- 自定义向量库接入后检索为空。原因是未将注塑台账的字段映射为向量库支持的元数据格式，导致检索时无法关联业务实体。

## 怎么确认配好了
- 上传单份注塑原料干燥记录，查看向量检索结果是否匹配同批次的注塑工艺卡数据。
- 模拟换模换料后触发索引更新，查看界面索引状态是否在10分钟内完成同步。
- 调整相似度阈值后，验证不同缺陷描述的检索结果是否符合业务语义区分。
- 查看向量库存储占用，确认单分片数据量未超过1000 MB阈值。
