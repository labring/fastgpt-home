# 塑料注塑成型的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源包括树脂批次与物性表、注塑机运行参数、模温机数据、MES生产系统、首件检验记录、换料清机记录等。数据更新节奏为每批生产、每次换模换料、每班巡检后生成。日常文档包含注塑工艺卡、原料干燥记录、模具履历、首件检验表、换料清机记录，字段涵盖树脂熔融温度、保压压力、干燥时长、模具使用次数等，部分文档需关联对应生产批次号与时间戳。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类数据更新频率高且来源分散，要求模型接入配置需适配多源异构数据的批量处理，避免因上下文过长超出模型限额。专业字段的单位与参数范围需模型准确识别，因此需确保配置的模型支持工业领域专业术语解析。生产台账的批次关联要求模型输出需绑定对应生产标识，配置时需明确上下文关联规则，防止跨批次数据混淆。同时，单次处理的生产数据量较大，需合理限制单次请求的token消耗，避免超时或调用失败。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 对应私有化部署的大模型接入地址 | 适配本品类多源工业数据的专属模型调用需求 |
| `AIPROXY_API_TOKEN` | 私有化部署模型生成的访问密钥 | 保障模型调用的权限安全，避免未授权访问 |
| `maxContext` | 8000–12000 token | 适配单批次生产台账的总数据量，避免上下文溢出 |
| `maxTokens` | 2000–3000 字符 | 限制单轮报告生成的输出长度，适配生产台账汇总的输出需求 |
| `temperature` | 0.2–0.4 | 降低输出随机性，确保工业参数汇总的准确性 |
| `quoteMaxToken` | 1500 token | 限制引用源数据的token消耗，优先保留核心工艺与检验数据 |

## 容易做错的三处
- FastGPT后台的文本理解模型列表为空，无法选择自定义模型。原因是未配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或接入的自定义模型未完成权限校验。
- 生成生产台账报告时触发超时报错。原因是`maxContext`取值超出当前调用模型的最大上下文限额，导致请求未完成响应。
- 汇总结果中出现非本次生产批次的冗余参数或格式混乱。原因是未限制`quoteMaxToken`的取值，模型引入了无关的历史数据。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置值，确保与私有化部署的大模型地址和密钥一致。
- 发起一次单批次生产台账的测试调用，核对模型返回的汇总内容是否包含注塑工艺卡、原料干燥记录的核心字段。
- 查看调用日志，确认单次请求的token消耗未超出模型限额，无超时或报错记录。
- 调整`temperature`参数后，对比两次输出结果，确认汇总内容的准确性符合预期。
