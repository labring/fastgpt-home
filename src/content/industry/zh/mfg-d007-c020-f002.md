# 安全环保与特殊作业管理的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自制造企业的EHS部门与检维修团队，涵盖风险辨识记录、动火/受限空间等作业票、在线环保监测数据、危废台账、人员资质清单、监管平台上报信息等。文档包含作业类型、作业时间、监护人、审批状态、危废类别、产生量等字段，更新节奏覆盖每次作业后即时录入、在线监测实时推送、定期法规文档更新，数据来源分散且格式存在差异。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源分散的数据格式要求向量流程需适配不同文档类型的字段关联，避免语义断裂。高频更新的作业与监测数据要求索引支持增量构建，减少全量重建的资源消耗。作业票、事故整改报告等长文档需保留完整上下文，防止关键风险信息被截断。同时，本品类数据关联人身与环境安全，索引召回的准确率需满足高置信度要求，避免误召回无关数据。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本适配，具体参数可按实测标定调整：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配作业票、监测记录等文档的语义完整性，避免单块内容断裂 |
| 重叠长度 | 100–150 字符 | 保留跨块的作业时间、审批人等关键字段的上下文关联 |
| 相似度阈值 | 0.75–0.85 | 平衡风险辨识、作业票的召回准确率，避免误召回无关的危废或人员资质数据 |
| 单次索引上限 | 5000 条/次 | 适配十万级台账数据的分批导入，避免单次索引超时 |
| `maxToken` | 8192 token | 适配法规标准、事故整改报告等长文档的向量生成，避免截断关键内容 |
| 重排 | 开启并取前3条 | 优先召回高相关的作业许可、监测数据，满足EHS部门快速核验作业合规性的需求 |

## 容易做错的三处
- 导入十万条CSV台账后，向量完成后剩余九万余条，少了数千条。部分作业票、危废台账的字段存在空值或格式不符合向量模型要求，被自动过滤。
- 集合创建返回成功，但索引管理页显示索引状态一直为「待构建」。多源数据（在线监测数据与本地作业票）的格式未统一，索引构建时出现格式冲突。
- 本地运行向量索引结果正常，打包为Docker镜像后，所有文本的向量得分完全一致。Docker环境中未正确配置模型API的请求参数，导致模型调用失败后 fallback 到默认向量，得分无差异。

## 怎么确认配好了
- 导入单条标准化作业票文档，核对向量生成结果的语义是否匹配作业类型、审批状态等关键字段信息。
- 分批导入十万级台账数据，核对导入前后的条目数差异是否符合配置的过滤规则。
- 测试纯向量检索与混合检索的响应时间，确认符合业务场景的延迟要求。
- 模拟包含空字段、格式错误的异常记录导入，确认系统是否按配置完成过滤或标记。
