# 家具与木制品制造的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
通常面向板式家具、实木家具、定制家居和木门企业，日常生产台账相关文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺、五金清单、试装与包装记录。数据一般来自订单设计系统、板材和木材批次记录、数控开料与钻孔设备、ERP/MES系统以及含水率检测设备，更新节奏为每订单、每日或每批材料更新一次，不同来源的文档字段格式存在差异，核心字段包括板件尺寸、材料批次号、工艺参数、五金型号等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来源分散且格式不统一，多轮对话需要支持不同系统字段的映射与统一，避免出现数据混淆。高频更新的台账内容要求对话能够实时拉取最新的板材批次、设备运行数据，因此需要在对话流程中嵌入数据校验环节。多份板件文档与定制订单的强关联，要求提示词能够精准定位当前订单的专属台账信息，避免跨订单数据干扰。同时，板件数量多且依赖现场空间尺寸的特点，要求多轮对话能够逐步拆解需求，避免一次性加载过多数据导致对话卡顿。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口大小 | 8000–12000 字符 | 适配多份板件文档的字段长度，避免截断拆单图、开料清单中的关键尺寸信息 |
| 单次对话召回上限 | 前6条历史消息 | 匹配生产台账按订单批次更新的节奏，避免堆积过往订单的冗余信息 |
| 变量绑定规则 | 按订单ID关联`variables` | 精准拉取对应批次的板材、设备数据，避免跨订单混淆台账内容 |
| 多轮对话触发逻辑 | 按`messages`序列逐步验证字段 | 逐步核对拆单、开料等环节的台账信息，减少一次性输入错误 |
| 超时阈值 | 300 秒 | 适配数控设备数据拉取的耗时，避免因数据加载中断对话 |
| 提示词绑定规则 | 绑定`chatId`关联当前订单 | 确保每轮对话都基于当前订单的专属上下文，生成对应报告 |

## 容易做错的三处
- 对话返回401 No auth credentials found报错。原因是未正确绑定ERP/MES系统的访问凭证到`variables`参数，导致对话过程中无法拉取生产台账数据。
- 知识库引用的上下文包含无关板件数据。原因是未限制单次召回的历史消息条数，导致多轮对话中堆积了过往订单的台账信息，干扰当前任务。
- 生成的报告缺失试装与包装记录字段。原因是未在提示词中明确指定提取该类文档的关键内容，导致对话过程中遗漏对应信息。

## 怎么确认配好了
- 发起单订单的测试对话，输入指定的订单ID，核对返回的台账数据是否包含该订单的拆单图、开料清单等对应文档内容。
- 连续发起3轮递进式提问，核对`messages`序列是否正确保留了前序对话的关键信息，未出现冗余或截断。
- 模拟凭证异常场景，验证是否触发预期的权限报错，确认`variables`参数的绑定逻辑生效。
- 生成一份报告草稿，核对是否包含涂装工艺、五金清单等要求的字段，确认提示词的提取规则正确。
