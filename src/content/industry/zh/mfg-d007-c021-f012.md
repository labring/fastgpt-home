# 家具与木制品制造的生产台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
通常家具与木制品制造企业的生产台账数据来自订单设计系统、板材与木材批次记录、数控开料钻孔设备日志、ERP/MES系统及含水率检测数据。日常文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金物料清单、试装与包装记录。数据按订单、每日或每批材料节点更新，字段包含板件尺寸、材质批次、加工参数、五金型号、含水率数值等，单位多为毫米、立方米、百分比。

## 这些特征在「部署与升级」这一环带来什么约束
定制订单驱动的生产模式导致板件数量多且个性化程度高，部署时需适配多源异构文档的解析规则；数据更新频率不一，需配置支持按节点触发的增量同步机制；五金、工艺等字段标准化程度低，需预留自定义字段映射的配置空间；设备日志与ERP数据格式差异较大，需支持灵活的结构化数据接入适配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `120–150 个连接` | 单订单对应多块板件，高频访问数据库需维持稳定连接池 |
| `STORAGE_S3_ENDPOINT` | `企业内部对象存储接入地址` | 需存储拆单图、工艺文件等大体积生产文档 |
| `REDIS_URL` | `本地私有Redis实例地址` | 需缓存高频调用的板材批次、五金清单数据，降低数据库负载 |
| `FILE_TOKEN_KEY` | `32位随机加密字符串` | 需安全校验拆单图、试装记录等敏感文档的访问权限 |
| `PG_URL` | `按实测标定` | 需对接ERP/MES的结构化生产台账数据，适配企业现有数据库架构 |

## 容易做错的三处
- 调用reranker组件返回结果为false，日志显示调用成功但无有效输出，原因是未配置对应模型的访问密钥，或文档解析格式与reranker的输入要求不匹配。
- 通过API设置自定义检索数量为6条时无法生效，系统仍返回固定条数，原因是未调整`DB_MAX_LINK`等配置项对应的检索池上限参数。
- 升级到FastGPT v4.17.0后，生产台账的同步任务无法正常触发，原因是未查看版本更新说明中关于增量同步规则的调整内容，未更新对应配置。

## 怎么确认配好了
- 提交测试订单，验证系统自动拉取对应拆单图、开料清单等文档并完成索引。
- 调用台账汇总接口，确认返回字段与原始生产数据一致。
- 查看缓存实例状态，确认高频访问的板材批次、五金清单数据已被正常缓存。
- 测试文档重排功能，验证返回结果为有效排序后的生产文档列表。
