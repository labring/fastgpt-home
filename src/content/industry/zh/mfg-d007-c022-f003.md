# 家用电器整机制造的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据涵盖空调、冰箱、洗衣机及小家电生产全流程，日常文档包含配置BOM、装配作业书、制冷剂充注记录、电气安全测试报告、性能抽检报告与返修记录。数据来源包括ERP/MES系统、零部件批次台账、拧紧与充注设备日志、安规测试仪数据、性能实验室报告及售后故障记录。数据更新节奏按单台产品、每班生产批次或抽检计划执行，字段包含物料编码、设备编号、测试参数、返修原因等，单位涉及压力值、电流值、抽检批次号等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
单台产品的高频数据与批量混线装配的场景，要求多轮对话需精准匹配不同型号的BOM与工艺参数，避免混线错装。按单台、每班的更新节奏，需要对话上下文能快速关联最新的设备日志与抽检结果，提示词需明确区分不同型号的字段规则。多源数据来自设备、系统与售后，需提示词引导对话整合跨来源的台账信息，同时需限制上下文长度，避免混入无关的历史批次数据。安规、泄漏等风险要求对话优先校验关键参数的合规性，比如制冷剂充注量与安规测试结果的匹配度，防止出现批量返修或召回风险。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文窗口大小 | 8000–12000 token，按实测标定 | 适配每班生产台账的更新频率，控制冗余数据的干扰 |
| `variables` 变量绑定 | 自动提取对话中提及的家电型号 | 匹配不同型号的BOM与工艺文档，避免混线错装 |
| `messages` 历史截断阈值 | 保留最近10条对话消息 | 聚焦当前生产批次的台账数据，避免历史批次的无关信息 |
| 问题分类节点 | 按装配/测试/返修环节划分分支 | 对应不同的台账数据源与文档类型，精准调用知识库 |
| `chatId` 会话标识绑定 | 关联单台产品的批次号 | 精准追踪单台设备的全流程台账数据，确保报告的唯一性 |
| 输出格式控制 | 固定为结构化文本格式 | 方便后续ERP系统导入，符合生产报告的标准化要求 |

## 容易做错的三处
- 现象：工作流经过问题分类节点进入对话分支后，AI返回结果无法触发后续分类校验，导致流程卡住。原因：未在对话节点配置`messages` 历史上下文的分类关联规则，未将对话结果同步回分类节点的输入参数。
- 现象：HTTP请求编排的输出内容未在对话界面展示，仅在后台日志可见。原因：未开启对话节点的`variables` 输出同步配置，未将HTTP返回值映射为对话可展示的内容。
- 现象：多轮对话中调用模型时，无法处理安规测试的图片数据，仅返回文本结果。原因：未配置全模态调用的参数绑定，未在提示词中明确要求处理多模态输入。

## 怎么确认配好了
- 发起包含特定家电型号的测试对话，验证对话是否自动关联对应型号的配置BOM与工艺文档。
- 运行包含HTTP请求编排的工作流，确认对话界面展示HTTP请求的返回内容。
- 测试连续多轮对话，确认上下文窗口仅保留与当前生产批次相关的台账数据。
- 触发包含异常参数的测试请求，确认输出格式符合预设的报告规范。
