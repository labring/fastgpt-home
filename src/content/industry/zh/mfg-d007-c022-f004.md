# 家用电器整机制造的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
本品类数据覆盖空调、冰箱、洗衣机及小家电生产全流程，来源包括ERP/MES系统、零部件批次台账、拧紧与制冷剂充注设备日志、电气安全测试仪记录、性能实验室报告及售后故障数据。日常文档包含配置BOM、装配作业指导书、工艺参数记录、安规检测报告、功能抽检表与返修台账。数据按单台产品、每班生产批次或抽检计划更新，字段包含零部件批次号、工艺参数值、检测结果、返修原因等，涉及压力、电流、容积等物理量单位。

## 这些特征在「工作流编排」这一环带来什么约束
多型号混线生产要求工作流按`nodeId`区分不同家电品类的台账采集节点，避免数据串混。多源异构数据需要通过`variables`配置字段映射规则，将不同设备输出的格式统一为台账标准结构。按单台、批次更新的数据要求工作流支持按生产节拍触发，避免冗余汇总。安规、性能检测等关键数据的校验环节，需要串联多节点完成跨数据源的一致性核对，确保异常数据及时拦截。生产台账需关联售后故障数据，工作流需配置跨系统的数据拉取节点，覆盖全生命周期的台账内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按生产班次结束时间触发，间隔不超过 4 小时 | 匹配每班更新的数据节奏，避免遗漏批次数据 |
| variables | 配置零部件批次号、工艺参数、检测结果为映射字段 | 统一多源设备输出的字段格式，适配本品类多数据来源特征 |
| nodeId | 为空调、冰箱、小家电分别设置独立节点ID | 区分不同机型的台账采集逻辑，避免混线生产的数据串扰 |
| 最大重试次数 | 3 次，重试间隔 60 秒 | 应对设备日志上传失败的临时故障，减少工作流中断概率 |
| 上下文窗口 | 按实测标定，范围 8000–12000 token | 适配多文档拼接后的报告生成需求，FastGPT v4.17.0 |
| 节点超时阈值 | 300 秒 | 匹配安规测试等环节的标准耗时，避免无效等待 |

## 容易做错的三处
- 工作流部署后容器重启出现配置空白。现象为界面节点列表为空、知识库下拉框无可选选项，接口调用可正常返回结果。原因是部署时未挂载持久化存储目录，容器重启后配置文件丢失。
- 选择知识库时未通过`variables`配置变量引用规则，导致无法动态绑定生产批次对应的专属知识库。现象为搜索结果匹配全量知识库内容，无法筛选对应机型的专属文档。
- 工作流仅支持单次提问无法实现多轮反问。现象为用户输入多轮问题后仅返回首次提问的结果，无法跟进追问交互。原因是未配置多轮对话的上下文传递节点，未保留历史交互的`variables`参数。

## 怎么确认配好了
- 手动触发一次工作流，查看节点运行日志，确认`nodeId`对应机型的采集节点未出现数据串扰。
- 调用工作流接口，传入测试用的零部件批次号，确认返回的台账字段包含`variables`配置的映射项。
- 模拟设备上传失败的场景，确认工作流触发重试机制，达到设定的最大重试次数后生成异常告警。
- 查看生成的最终报告，确认包含安规检测、性能抽检等本品类专属文档的内容，无缺失字段。
