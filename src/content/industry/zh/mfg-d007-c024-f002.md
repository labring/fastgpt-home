# 工艺变更与工程变更的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类数据由制造企业变更管理团队产生，来源覆盖PLM、ERP、MES系统及供应商资料、验证试验文件、客户特殊要求文档。日常文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本记录、工艺验证报告、生产切换计划、库存处置单、客户批准文件。数据更新无固定周期，每次工艺或工程变更触发更新，文档包含变更单号、版本标识、生效节点等核心字段，无统一标准化格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来多重约束。多源异构的文档来源与非统一格式，要求索引模块支持跨系统文档解析与格式适配。无固定周期的更新触发，需支持增量索引逻辑，避免每次全量重建带来的资源浪费。文档包含图纸、BOM清单等非纯文本内容，需适配多模态向量生成能力。变更关联多环节数据的特性，要求索引能精准关联变更单号、版本标识等核心字段，确保检索时覆盖全部关联文件。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配ECN/ECR、工艺验证报告等文档的段落长度，避免块内信息割裂 |
| 重叠长度 | 100–150 字符 | 保留跨块的变更单号、版本标识等关键信息，防止关联内容被截断 |
| `defaultToken` | 4096 token | 匹配多数开源嵌入模型的输入token上限，适配变更文档的总长度 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.72–0.80 按实测标定 | 过滤低匹配度的无关文档，避免检索结果混入非关联的日常生产文件 |
| 单次搜索上限 | 前 10 条 | 控制检索结果数量，适配变更管理场景下的关联文件量级 |

## 容易做错的三处
- 现象：本地部署FastGPT v4.17.0后，上传ECN图纸等图片类文档时，无自动索引选项，知识库索引结果仅包含文本内容。原因：未启用多模态索引相关的部署配置，或部署包未包含对应模型依赖。
- 现象：配置Embedding模型连接OneAPI后，出现连接报错，日志显示模型调用失败。原因：未正确配置OneAPI的接口地址与认证密钥，或嵌入模型名称与OneAPI中配置的模型名不匹配。
- 现象：检索变更关联的BOM版本文件时，结果条数远低于预期，部分关键文档未被召回。原因：相似度阈值设置过高，或分块重叠长度不足导致关键变更单号字段被截断。

## 怎么确认配好了
- 上传一份标准ECN文档与对应图纸，查看索引生成的向量块是否包含变更单号、版本标识等核心字段。
- 测试调用Embedding模型接口，确认FastGPT能正常获取向量返回结果，无连接报错。
- 输入测试检索词“变更单号XXX”，核对检索结果是否包含该单号关联的所有文档，无明显遗漏。
- 查看知识库索引日志，确认增量索引任务能正常触发，无全量重建的重复执行记录。
