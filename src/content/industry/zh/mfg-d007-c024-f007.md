# 工艺变更与工程变更的生产台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
本品类的数据来自PLM、ERP、MES、供应商资料、验证试验及客户特殊要求，由研发、工艺、质量、生产、采购团队共同维护。日常文档包含ECN/ECR、变更评估报告、图纸与BOM版本、工艺验证报告、切换计划、库存处置单及客户批准文件。数据更新无固定周期，每次变更触发一次同步。字段包含变更编号、版本号、生效日期、影响物料编码、审批状态等，其中版本号采用语义化格式，生效日期为标准日期型字段，审批状态为固定枚举值。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构的数据来源要求数据库支持跨系统数据同步与关联查询，需合理配置连接池以应对不同系统的并发请求。无固定更新频率导致数据体量波动较大，需预留弹性存储容量。变更关联多类文档与业务数据，需建立针对性索引以保障查询效率。同时，变更数据出错会引发批量生产风险，需配置完善的数据校验与备份机制，确保台账数据的准确性与可追溯性。本指南适用于FastGPT v4.17.0版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[username]:[password]@host:port/fastgpt_ecn?authSource=admin` | 对应存储ECN/ECR等非结构化变更文档的业务库，指定认证源避免连接失败 |
| `PG_URL` | `postgresql://[username]:[password]@host:port/fastgpt_ecm?schema=change_management` | 存储结构化变更台账字段，关联ERP/MES的物料与生产数据，通过schema隔离业务数据 |
| `DB_MAX_LINK` | `20–30 个` | 应对多系统同步时的并发连接，避免超出数据库连接上限导致服务中断 |
| `REDIS_URL` | `redis://:[password]@host:port/0` | 缓存变更审批状态、版本映射关系，降低重复查询数据库的开销 |

## 容易做错的三处
- 现象：通过MongoDB Compass连接FastGPT本地MongoDB数据库时，弹出“连接超时”或“认证失败”的报错弹窗。原因：未在`MONGODB_URI`中配置正确的认证源参数，或数据库防火墙限制了本地访问端口。
- 现象：生成的台账报告中部分关联的BOM版本字段为空。原因：未按变更数据的更新节奏配置数据库同步任务，导致跨系统的BOM数据未及时同步至FastGPT数据库。
- 现象：批量导入变更文档时出现内存溢出报错。原因：未限制单次导入的文档数量，或未配置合理的`DB_MAX_LINK`参数导致数据库连接资源耗尽。

## 怎么确认配好了
- 执行`MONGODB_URI`对应的数据库连接测试，验证是否能成功读取ECN文档集合中的测试数据。
- 发起一次模拟变更同步任务，检查`PG_URL`对应的结构化台账表是否能正确写入变更编号、生效日期等字段数据。
- 查看Redis缓存的变更审批状态数据，确认缓存过期时间符合业务更新的无固定周期特性。
- 模拟多系统并发同步场景，检查`DB_MAX_LINK`配置是否能支撑并发请求且不出现连接拒绝报错。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
