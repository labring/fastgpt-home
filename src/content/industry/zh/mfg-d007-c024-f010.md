# 工艺变更与工程变更的生产台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
这个品类的数据由制造企业变更管理团队产生，日常文档包含ECN/ECR、变更评估报告、图纸与BOM版本文件、工艺验证报告、切换计划、库存处置单、客户批准文件等。数据来源覆盖PLM、ERP、MES、供应商资料、验证试验记录及客户特殊要求，更新频率为每次变更触发的不定期节奏。文档结构包含变更编号、版本号、生效日期、涉及物料/工艺/检验项等字段，版本号以V+数字序列为标准单位，日期采用ISO 8601格式。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据特征对检索召回环节带来明确约束。多源异构的数据来源要求检索覆盖跨系统数据集，避免遗漏PLM中的图纸版本、ERP中的物料关联信息，否则会导致台账汇总出现数据缺口。不定期的更新节奏要求检索配置支持增量同步，确保每次变更后最新文档能被及时召回，避免使用过期版本的内容。文档类型包含结构化表格、工程图纸与纯文本报告，需要同时支持全文内容检索与元数据字段匹配，确保变更编号、版本号等关键信息被精准识别，避免检索结果偏离变更主题。单次变更涉及的文档数量波动较大，需限制召回结果的总条数，避免台账汇总出现冗余内容影响阅读效率。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体配置项及说明如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配工艺变更相关文档的精准度需求，过滤低相关的日常生产文档 |
| `limit` | 前10条 | 控制单次召回结果数量，适配生产台账汇总的篇幅要求，避免返回内容超过2000字符 |
| `searchMode` | `fullTextRecall` | 使用全文检索召回文本内容；字段、元数据、批次和文档类型条件需另行配置过滤，不能由该模式保证。 |
| `usingReRank` | 开启 | 对召回结果按变更生效优先级重排，确保最新版本的文档优先展示 |
| `collectionIds` | 绑定PLM、ERP、MES对应数据集ID | 覆盖变更管理全链路的数据来源，确保检索范围包含所有相关文档 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展检索词的同义词范围，覆盖“工艺变更”“工程变更”等相关表述，提升召回覆盖度 |

## 容易做错的三处
- 现象：检索时返回空结果，或提示无法加载外部数据源内容。原因：未将PLM、ERP等对应数据源的数据集绑定到当前知识库集合，或未开启跨数据源检索配置。
- 现象：生成报告时出现Validation failed: name: Path `name` is required.报错。原因：未正确配置检索时的元数据字段映射，变更编号、版本号等必填字段未被纳入检索范围。
- 现象：检索结果中混入过期版本的工艺文档，且未按生效时间排序。原因：未开启`usingReRank`配置，或`similarity`取值过低导致无关结果被召回。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理界面，检查绑定的数据集是否包含PLM、ERP、MES等变更相关数据源。
- 发起一条测试检索，输入“ECN变更编号”，查看返回结果是否包含对应元数据字段的匹配内容。
- 生成一份模拟变更台账报告，检查结果中是否按版本优先级排序，且无过期文档混入。
- 查看检索日志，确认每次召回的结果条数符合`limit`配置的取值。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
