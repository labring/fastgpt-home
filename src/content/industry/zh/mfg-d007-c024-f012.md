# 工艺变更与工程变更的生产台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
这个品类的数据来自PLM、ERP、MES、供应商资料、验证试验、客户特殊要求。更新节奏为每次变更触发，无固定周期。日常生成的文档包含ECN/ECR、变更评估、图纸与BOM版本、工艺验证报告、切换计划、库存处置单、客户批准文件。核心字段包含变更标识、版本编号、生效节点、关联物料清单、审批状态等，无统一自定义单位，字段随变更类型灵活调整。

## 这些特征在「部署与升级」这一环带来什么约束
由于数据来源覆盖多套异构系统，部署时需适配多源数据拉取的接口配置，避免跨系统数据同步失败。由于更新无固定周期且单次变更关联多类文档，升级时需优化增量同步逻辑，防止重复或遗漏台账条目。由于文档包含审批状态、生效节点等结构化字段，部署前需明确字段映射规则，确保台账汇总的字段完整性。由于变更出错后果直接影响生产，升级时需保留数据备份与回滚节点，保障部署过程的稳定性。同时，由于文档体积差异较大，部署时需配置适配的存储资源，避免大文件上传失败。

## 配置怎么定
本配置指南适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://postgres:${自定义密码}@pg:5432/fastgpt?sslmode=disable` | 适配多源PLM/ERP数据的结构化存储，默认端口5432符合通用部署规范 |
| `STORAGE_S3_ENDPOINT` | 企业现有存储服务地址，如`https://s3.cn-north-1.amazonaws.com.cn`或本地MinIO endpoint | 存储ECN文档、BOM版本图纸等大体积文件，匹配企业现有存储架构 |
| `DB_MAX_LINK` | `20–30 个` | 应对多系统同步时的并发连接需求，避免连接池耗尽 |
| `REDIS_URL` | `redis://:${自定义密码}@redis:6379/0` | 缓存变更台账的增量同步状态，降低多源数据拉取的延迟 |
| `ROOT_KEY` | 按企业安全策略生成的随机字符串 | 保障系统后台配置的访问权限，防止未授权修改台账生成规则 |

## 容易做错的三处
- 现象：PostgreSQL容器启动失败，日志显示“role "postgres" does not exist”。原因：部署时未初始化PostgreSQL数据库的默认角色与库表，或`PG_URL`配置的用户名与初始化脚本不匹配。
- 现象：升级后生产台账汇总结果为空或缺失核心变更记录。原因：未配置PLM、ERP等多源系统的数据同步映射规则，或增量同步逻辑未适配变更触发的更新节奏。
- 现象：台账生成任务执行超时。原因：`DB_MAX_LINK`配置值过低，导致多系统同步时连接池耗尽，无法拉取全量变更数据。

## 怎么确认配好了
- 执行`docker logs pg`命令，检查PostgreSQL容器无角色缺失或连接失败报错，确认`PG_URL`配置的用户名与密码正确。
- 手动触发一次变更台账的汇总任务，检查生成的报告包含ECN编号、BOM版本等核心字段，确认字段映射配置生效。
- 登录`STORAGE_S3_ENDPOINT`对应的存储桶，确认ECN文档、工艺验证报告等文件已正常上传并可访问。
- 测试多源数据同步接口，确认PLM、ERP系统的变更记录可正常拉取并写入台账数据库。
