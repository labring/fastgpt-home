# 工装夹具与检具制造的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自汽车、航空、机械装配企业工装部门及专用工装供应商的日常业务文档，包括工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历，同时关联产品数模与GD&T、工艺路线、三坐标测量数据、现场试用反馈、计量系统输出结果。数据更新按单个项目推进、每次产品变更触发、定期校准执行，文档包含GD&T公差字段、三坐标测量值（单位mm）、校准周期（单位天）等结构化与非结构化内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
品类数据包含图纸、测量数据、文档等多格式内容，且关联结构化元数据，要求向量模型需适配混合格式的文本与数值字段转换。数据更新无固定周期，需支持增量索引以避免全量重嵌的资源消耗。不同文档的字段单位与业务逻辑存在差异，索引构建时需保留元数据关联，确保检索结果可匹配具体工装项目的台账信息。同时，该品类的核心业务环节耗时较长，索引需关联多份文档的关联关系，避免检索结果割裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配夹具图说明、校准记录等单份文档的文本长度，避免分块过碎破坏业务逻辑 |
| 重叠长度 | 50–80 字符 | 保留跨分块的定位基准、公差关联信息，提升检索连贯性 |
| 相似度阈值 | 0.75–0.85 | 按实测标定，适配工装台账的专业术语匹配精度 |
| 单次搜索上限 | 前10条 | 匹配单个工装项目关联的台账文档数量，避免结果冗余 |
| `maxToken` | 4096 | 适配Qwen系列嵌入模型的输入限制，兼容长文档的向量生成 |
| `defaultToken` | 1024 | 适配单条结构化台账字段的文本长度，确保元数据可完整转换为向量 |

## 容易做错的三处
- 现象：批量重新嵌入知识库后耗时远超预期，界面显示索引进度停滞。原因：未配置增量索引规则，触发全量重嵌，未按变更范围更新向量。
- 现象：检索检具校准记录时，返回结果未关联对应三坐标测量数据。原因：未开启元数据关联索引，仅基于纯文本向量检索，丢失字段关联关系。
- 现象：FastGPT v4.17.0版本接入qwen3-embedding-8b后，文件状态持续显示“索引中”。原因：未匹配新模型的向量维度参数，导致索引构建失败且无明确报错提示。

## 怎么确认配好了
- 上传单份夹具图文档，检查向量生成状态是否在预设时间内完成。
- 检索“定位基准方案”关键词，检查返回结果是否包含对应工装需求书、校准记录等关联文档。
- 切换嵌入模型后，重新嵌入批量文档，检查向量维度是否与新模型参数匹配。
- 查看索引监控面板，确认增量更新任务按项目变更频率自动触发。
