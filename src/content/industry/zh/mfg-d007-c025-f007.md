# 工装夹具与检具制造的生产台账汇总与报告生成：数据库与运维

本场景的数据库与运维配置适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类的数据覆盖工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历等多类文档。数据来源包括产品数模与GD&T、工艺路线、三坐标数据、现场试用反馈、计量系统。更新节奏按项目推进、每次产品变更触发、定期校准执行。字段包含工装编号、校准日期、三坐标测量值、变更版本号等，其中测量值以毫米为单位，日期采用标准公历格式。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构的数据类型要求数据库同时支持非结构化文档存储与结构化数据查询。按项目与变更的不定时更新，要求数据库支持灵活的版本管理与增量同步机制。多样的文档结构与字段差异，要求运维环节具备动态字段适配能力。数据关联到加工与检验环节，出错会导致批量超差或误判，因此需要完善的数据备份与校验机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/fixture_db?authSource=admin` | 存储工装需求书、夹具图等多类型非结构化与半结构化文档 |
| `PG_URL` | `postgresql://user:pass@host:5432/metric_db` | 存储三坐标测量值、校准记录等结构化计量与工艺数据 |
| `DB_MAX_LINK` | `10–15` | 适配多部门同时访问台账与校准数据的并发需求，避免数据库连接耗尽 |
| `REDIS_URL` | `redis://:pass@host:6379/0` | 缓存高频访问的检具参数、定位基准方案，降低数据库负载 |
| 数据备份触发规则 | 按项目完成、每月定期 | 适配按项目和定期校准的更新节奏，保障数据安全 |
| 字段校验开关 | 开启 | 校验工装编号、测量值等字段格式，避免无效数据入库 |

## 容易做错的三处
- 配置`MONGODB_URI`后出现连接超时报错，日志显示认证失败。原因是未将工装台账数据库的认证源指定为admin，或连接字符串中未正确填写用户名与密码。
- 尝试通过API调用创建数据集时返回403状态码。原因是未在FastGPT后台配置对应API密钥的访问权限，或请求头未携带正确的认证参数。
- 导入三坐标数据后字段为空。原因是未匹配数据字段与台账模板的映射关系，导致结构化计量数据无法正确写入数据库。

## 怎么确认配好了
- 运行FastGPT内置的数据库连通性测试工具，输入配置的`MONGODB_URI`与`PG_URL`，确认返回连接成功提示。
- 上传一份工装校准记录文档，检查数据库中是否生成对应的结构化条目，字段与上传内容一致。
- 发起一次台账汇总请求，确认返回的报告包含工装需求书、三坐标数据等关联文档的摘要信息。
- 查看系统日志，确认无数据库连接耗尽、缓存击穿类的报错信息。
