# 有色金属冶炼与电解的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类的日常数据来源包括精矿与辅料分析报告、DCS系统采集的炉温、槽压等运行数据、化验室出具的质量检测单据、能源与环保监测记录。日常文档涵盖配料单、熔炼记录、电解槽况记录、阳极阴极质量台账、环保排放日志等，单份文档包含原料成分参数、炉况指标、槽电压电流数值、能耗数据等字段，更新频率随生产批次、炉次或槽况实时变动，部分台账按每炉、每槽周期归档。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据更新频率高且实时性强，要求向量索引支持增量同步与低延迟刷新，避免台账数据滞后于生产进度。文档包含大量专业工艺参数与术语，分块长度需适配单份文档的字段密度，避免拆分破坏工艺逻辑关联。多源数据的字段差异会导致向量特征分散，需配置合理的索引维度适配多类型字段的嵌入需求。同时，生产台账的准确性直接关联生产合规性与金属回收率，索引召回的精准度需匹配业务校验要求，降低误召回风险。

## 配置怎么定
以下配置方案适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配冶炼台账的单份文档字段密度，避免拆分破坏工艺逻辑关联 |
| 重叠长度 | 50–80 字符 | 衔接相邻分块的工艺参数，保留跨块的逻辑关联 |
| `defaultToken` | 8192 | 覆盖单份台账文档的完整字段内容，适配专业术语的嵌入需求 |
| `maxToken` | 16384 | 支持批量嵌入多份跨批次的台账数据，满足汇总场景的上下文需求 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配度的非工艺相关文档，保障召回结果的业务相关性 |
| 单次搜索上限 | 前10条 | 限制召回结果数量，适配生产台账的多源数据关联分析 |

## 容易做错的三处
- 现象：批量重新嵌入多语言台账后，专业术语的召回率未达到业务要求。原因：未针对冶炼行业的专业术语调整嵌入模型的分词规则，导致多语言术语的向量特征出现偏差。
- 现象：手动插入的环保台账索引在数小时后自动消失。原因：未配置增量索引的持久化存储策略，临时索引缓存未正确写入持久层存储目录。
- 现象：接入指定嵌入模型后，上传的台账文件状态持续显示“索引中”。原因：嵌入模型的输入token上限与台账文档的分块长度不匹配，导致嵌入任务超时未完成。

## 怎么确认配好了
- 随机抽取3份不同批次的熔炼记录、电解槽况记录文档，执行嵌入任务，检查分块后的内容是否保留完整的工艺参数关联。
- 触发批量嵌入操作后，查看系统日志的嵌入进度，确认`defaultToken`与`maxToken`的配置未触发文本截断报错。
- 输入冶炼工艺相关的查询语句，验证召回结果的相似度分值落在预设阈值区间内，且无无关的非冶炼类文档。
- 等待24小时后检查索引存储目录，确认手动插入的台账索引未被自动清理，持久化配置生效。
