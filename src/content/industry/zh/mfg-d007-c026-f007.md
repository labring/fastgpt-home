# 有色金属冶炼与电解的生产台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
该品类数据主要来自精矿与辅料分析报告、DCS系统、电解槽电压电流监测数据、化验室检测结果、能源与环保监测装置。日常文档涵盖配料单、熔炼记录、电解槽工况记录、化验报告、阳极阴极质量台账、环保排放台账。数据更新频率随原料批次、熔炼炉次或电解槽工况实时变动，单条记录包含原料成分、工艺参数、检测指标、批次标识与时间戳，字段多涉及金属含量、电流电压值、物料重量等专业计量项。

## 这些特征在「数据库与运维」这一环带来什么约束
该品类数据的实时性、多源分散性与专业计量属性，对数据库运维带来多重约束。多源高频更新要求数据库连接池需适配高并发写入请求，避免连接耗尽导致部分数据抓取失败。专业计量字段的格式校验需贴合冶炼行业标准，防止非规范数据进入知识库。数据更新随炉次、槽况动态变动，需支持按批次增量同步，避免全量同步占用过多资源。同时，数据异常会直接影响金属平衡核算与产品质量，需配置实时数据校验与异常告警机制。

## 配置怎么定
以下配置说明适配 FastGPT v4.17.0 版本：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | 专用冶炼台账数据库的副本集连接串 | 适配多源分散的生产数据存储，保障高并发写入的数据一致性 |
| `PG_URL` | 关联历史报告与统计指标的关系型数据库地址 | 结构化存储汇总报告的元数据与统计结果，便于按批次快速检索 |
| `DB_MAX_LINK` | 200–300 个 | 匹配多工位实时数据写入的并发需求，避免连接池溢出 |
| `REDIS_URL` | 配置为缓存高频槽况、化验数据的服务地址，缓存过期时间设为 600 秒 | 降低数据库重复查询压力，加快台账汇总的响应速度 |
| 增量同步触发规则 | 按单炉/单槽完成节点触发，同步间隔不超过 300 秒 | 贴合冶炼生产的批次式更新节奏，避免无效同步占用资源 |

## 容易做错的三处
- 现象：仅抓取到部分生产台账数据，知识库中存在字段缺失或记录不完整。原因：未配置按批次增量同步规则，全量同步时因并发过高导致部分连接超时，未触发重试机制。
- 现象：高并发场景下请求成功率偏低，日志出现连接超时报错。原因：`DB_MAX_LINK`配置值过低，无法支撑多工位实时数据写入的并发需求，连接池耗尽后新请求被拒绝。
- 现象：导出的知识库数据集csv文件仅包含index字段，无content字段内容。原因：未正确关联台账数据的存储表与索引映射关系，未配置content字段的自动同步逻辑。

## 怎么确认配好了
- 执行一次单炉次的台账数据同步任务，检查数据库连接日志中无连接超时报错。
- 导出知识库的数据集文件，核对是否包含预设的content字段与对应台账数据。
- 模拟多工位并发写入请求，观察数据库连接池的使用状态是否符合预期配置。
- 触发异常数据校验规则，确认告警机制能正常触发对应提示。
