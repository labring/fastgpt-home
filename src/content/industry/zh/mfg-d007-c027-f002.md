# 服装裁剪与缝制的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类的日常数据涵盖工艺单、CAD样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等文档，数据来源包括订单与尺码表、CAD设计文件、面辅料检验记录、车间吊挂系统数据、验针机记录及客户封样资料。数据更新以每订单、每款、每批为节奏，字段包含尺码规格、裁片数量、工序节点、面料批次、包装配码等，且裁片相关数据不可逆，工序记录多为人工与设备联动生成。

## 这些特征在「向量模型与索引」这一环带来什么约束
品类内款式多、季节性强，单批次数据量随订单规模波动，且裁片、工序数据关联紧密，需精准匹配关联字段。数据更新频率高，要求索引支持准实时增量更新，避免全表重复扫描。文档类型包含结构化表格与非结构化图纸，需适配混合格式的文本与图像特征提取。由于裁片数据不可逆且工序密集，索引需保留全量历史关联数据，不能仅保留最新批次，同时需确保召回数据覆盖完整工序与物料链路，避免遗漏关键校验字段。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配工艺单、工序质量表等文档的单块文本长度，避免跨工序信息断裂 |
| 重叠长度 | 100–150 字符 | 保留工序节点、尺码规格等跨块关联信息，防止关键字段被拆分在不同块中 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 匹配服装品类的工艺描述、尺码参数等相似性较高的字段，避免误召回或漏召回 |
| 单次搜索上限 | 前 10 条 | 覆盖单订单的多工序、多裁片关联数据，避免单次召回过多冗余信息 |
| `maxToken` | 4096 token | 适配批量台账汇总的长文本生成需求，确保包含完整的订单、裁片、包装信息 |
| 最大上下文 | 8000 字符 | 保留多批次的关联数据，支持跨订单的工艺对比与校验 |

## 容易做错的三处
- 现象为索引未显示就绪状态，无法发起检索请求。原因是未正确配置向量模型的接入参数，或增量更新任务未完成初始化。
- 现象为检索结果包含全表无关字段，无法精准匹配目标台账内容。原因是未设置合理的相似度阈值，或分块长度过大导致关联信息被冗余包裹。
- 现象为检索返回字段为空，无法提取裁剪单、包装配码的关键数据。原因是未将目标字段纳入向量化索引的提取范围，或数据更新未同步至索引节点。

## 怎么确认配好了
- 进入FastGPT v4.17.0的索引管理页面，确认目标索引的状态显示为就绪，检查向量模型接入配置是否与所选模型匹配。
- 输入单订单的工艺描述作为检索词，验证检索结果包含对应裁剪单、工序质量表的关联字段，确认字段提取范围符合需求。
- 提交批量台账汇总的生成请求，查看返回内容是否覆盖当前批次的所有关键数据，验证参数取值适配长文本生成需求。
- 模拟一次数据增量更新，确认索引状态未报错且新数据可被正常检索。
