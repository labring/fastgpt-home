# 服装裁剪与缝制的生产台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
这个品类的日常文档包含工艺单、样板排料图、裁剪单、首件封样记录、工序质量表、包装配码单等，数据来自订单与尺码表、CAD样板系统、面辅料检验记录、吊挂生产系统、验针设备及客户封样文件。数据更新随每款服装订单、每批生产批次实时调整，单份文档常包含版型参数、工序要求、尺码配比、面料规格等字段，单位涉及厘米、克重、件数、批次号等，文档结构随订单款式差异存在明显变化。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的文档随订单款式差异较大，且包含CAD绘图、工序清单等混合格式内容，对解析的格式适配性要求更高。实时更新的生产数据要求解析环节支持快速响应，避免拖慢台账汇总流程。多字段混合的文档结构，需要分块时保留字段关联性，避免拆分后丢失尺码、批次等关键关联信息。面料裁片不可逆的业务特性，要求解析后的分块数据准确对应生产批次，防止出现数据错位导致的批量偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配该品类文档中版型参数、工序描述的混合长度，避免拆分后丢失单工序完整逻辑 |
| `chunkSplitter` | 按语义分块 | 匹配多字段混合的服装生产文档结构，保留工艺要求与尺码配比的关联关系 |
| `customPdfParse` | 开启结构化解析 | 适配CAD样板、排料图等非纯文本PDF内容，提取可复用的版型参数与裁片数量信息 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 180–240 秒 | 应对单份大尺寸排料图或多页工艺单的解析耗时，避免超时中断解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配大尺寸排料图或多页工艺单的上传需求，避免因文件过大无法解析 |
| `chunkSettingMode` | 手动配置 | 适配不同款式订单的文档差异，灵活调整分块规则以匹配各类生产文档结构 |

## 容易做错的三处
- 调用API解析文件显示调用成功但无回传结果：原因是未正确配置`PARSE_FILE_TIMEOUT_SECONDS`参数，超时后未触发结果回传逻辑。
- 解析日志提示split相关报错：原因是`chunkSplitter`配置为按固定长度分块，拆分CAD绘图相关的矢量内容时出现格式断裂。
- 文档解析模块无数据传入：原因是未开启`customPdfParse`的结构化解析开关，CAD样板、排料图等非纯文本类文档无法被正确读取。

## 怎么确认配好了
- 上传单份工艺单PDF，查看解析后的分块结果，确认每个分块包含完整的工序描述或尺码配比信息。
- 调用FastGPT v4.17.0的文件解析API，等待`PARSE_FILE_TIMEOUT_SECONDS`预设时长后检查回传的分块数据是否完整。
- 上传包含CAD排料图的文档，确认解析结果中提取了面料规格、裁片数量等结构化字段。
- 调整`chunkSize`参数后上传同类型测试文档，验证分块长度是否符合预设的取值区间。
