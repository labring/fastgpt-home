# 来料检验与供应商质量的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来自采购订单、图纸和规格、供应商质保书、检验设备、历史质量数据及供应商门户。日常文档包含检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告、让步接收审批。数据更新随每批来料触发，伴随每月或季度供应商评价、不定期审核同步更新。数据字段包含来料批次号、供应商编号、检验项参数、不合格项描述、整改状态等，附带检验数值单位、时间戳等基础信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
每批来料的高频更新要求索引支持实时增量同步，避免全量重索引带来的额外耗时。多类型文档结构差异显著，检验规范等短文本与8D报告等长文本需适配不同分块规则，防止语义割裂。数据需绑定来料批次号、供应商编号等元字段，检索时需按业务维度精准过滤，确保结果关联对应供应商与批次。非结构化的不合格项描述、整改记录需要向量模型准确捕捉语义关联，同时兼容设备导出的数值数据与人工填写的文本数据，保障多源异构数据的统一索引。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配来料报告、8D报告等业务文档的常见文本长度，避免单块内语义割裂 |
| 重叠长度 | 100–150 字符 | 保留跨分块的上下文关联，保障不合格项描述、整改记录的语义完整性 |
| `maxToken` | 4096 token | 适配主流开源向量模型的输入长度限制，匹配业务文档分块后的平均token占比 |
| 相似度阈值 | 0.72–0.85 | 区分合格与不合格检验记录的语义差异，适配供应商质量检索的精度需求 |
| 单次搜索上限 | 前 10 条 | 匹配SQE、IQC人员日常检索的结果量级，减少无效信息干扰 |
| `defaultToken` | 1024 token | 作为默认分块的基准参数，适配多数业务文档的初始分块配置 |

## 容易做错的三处
1. 检索结果条数不符合预期，仅返回少量无关结果或包含跨供应商的无关文档，原因是未按业务维度绑定来料批次号、供应商编号元字段进行过滤，导致检索范围超出业务需求。
2. 自定义向量模型接入失败，例如多模态向量模型无法正常发起调用，原因是未正确配置模型接入的授权参数与接口格式，未适配多模态向量的输入要求。
3. 向量模型调用时出现token超限报错，原因是未正确配置`maxToken`参数，导致分块后的文本超出模型输入限制。

## 怎么确认配好了
1. 上传单份来料检验报告，查看分块后的文本是否完整保留核心语义，无明显断裂。
2. 输入供应商审核相关的检索词，验证检索结果是否仅关联对应供应商的历史文档，无跨供应商的无关结果。
3. 接入指定的向量模型，发起测试调用，确认模型返回的向量数据格式符合系统要求。
4. 调整相似度阈值参数，验证检索结果的匹配精度是否符合业务预期。
