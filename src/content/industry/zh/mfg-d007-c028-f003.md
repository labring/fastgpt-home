# 来料检验与供应商质量的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据来自采购订单、图纸规格、供应商质保书、检验设备、历史质量数据与供应商门户。日常关联文档包括检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告与让步接收审批单。数据更新节奏为每批来料同步、每月或季度供应商评价更新、不定期审核触发更新。数据字段包含批次标识、检验日期、供应商编码、不合格项类型、整改状态等，无固定统一单位，部分字段关联设备采集的原始检测数值。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据分散来自采购、设备、供应商门户等多渠道，且更新节奏不固定，因此多轮对话需支持跨源数据的上下文关联，避免跨批次、跨周期的数据混淆。日常关联文档类型多样，格式差异明显，提示词需适配不同文档的字段映射规则，确保台账字段提取的一致性。同时，业务需平衡供应商质量风险与生产保供需求，对话流程需支持动态调整判定逻辑，适配每批来料的临时抽检需求与季度供应商评价的批量汇总要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前来料批次ID | 确保多轮对话关联同一批次的检验数据，避免跨批次混淆 |
| `messages` | 强制校验为标准 JSON 格式 | 避免对话返回的换行符导致请求失败，适配接口的参数格式要求 |
| `variables` | 绑定供应商编码、检验规范版本 | 传递业务核心参数，确保提示词适配当前检验规则 |
| 上下文窗口长度 | 8000–12000 字符 | 覆盖多批次历史数据与当前检验流程的完整上下文 |
| 多轮对话触发轮次 | 3–5 轮后触发台账汇总 | 匹配该品类单次来料检验的典型步骤数 |

## 容易做错的三处
- 现象：调用对话接口时返回 unAuthChat 状态码，已正确填写apikey。原因：未将`variables`绑定的供应商数据与当前会话的权限范围关联，导致接口校验失败。
- 现象：对话返回内容包含换行符，导致`messages`参数的JSON请求格式校验失败。原因：未开启`messages`的强制格式校验配置，未对返回内容做转义处理。
- 现象：上传来料报告、供应商审核报告等文档时触发报错，但文本输入对话可正常运行。原因：未配置该品类专属的文档解析规则，导致检验规范、8D报告等非通用文档格式无法被正确识别。

## 怎么确认配好了
以下核对动作需基于 FastGPT v4.17.0 版本执行。
- 发起一轮模拟来料检验对话，检查`chatId`是否绑定了正确的批次ID，上下文是否包含关联的供应商信息。
- 构造包含换行符的测试对话内容，验证`messages`参数的格式校验是否生效，请求是否正常提交。
- 上传该品类典型文档（如来料报告、8D报告），确认解析后的字段可被`variables`正确提取。
- 发起3–5轮连续对话，检查上下文是否保留了前序检验步骤的关键信息，未出现跨批次混淆。
