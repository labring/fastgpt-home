# 来料检验与供应商质量的生产台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
该品类的数据来自采购订单、图纸规格、供应商质保书、检验设备、历史质量数据与供应商门户。日常生成的文档包含检验规范、抽样方案、来料报告、供应商审核报告、异常联络单、8D报告与让步接收审批单。数据更新随每批来料产生新记录，每月或季度完成供应商质量评价，不定期开展专项审核。数据字段包含批次号、检验项、判定结果、供应商信息、异常类型等，单位多为批次、件数、检验项名称等。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且更新频次不均，工具调用需支持多源数据拉取，需适配不同格式的文档解析。批次化的更新要求工具调用触发逻辑绑定来料批次标识，避免跨批次数据混淆。多类型文档的结构差异，要求插件配置支持自定义字段提取规则，适配检验报告、8D报告等不同文档格式。供应商质量评价的周期性更新，需工具支持定时触发汇总任务，同时保留历史版本追溯能力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 工具调用触发时机 | 按来料批次标签触发 | 匹配该品类按批次产生数据的更新节奏，避免跨批次数据混杂 |
| 单次调用历史数据上限 | 前10条 | 适配单批次检验数据的关联分析范围，避免上下文过载 |
| 插件文档解析规则 | 按文档类型自定义字段映射 | 适配检验报告、8D报告等多类文档的结构差异 |
| `toolChoice` | auto | 允许模型自主选择合适的工具完成台账汇总与报告生成 |
| 超时设置 | 600 秒 | 适配多源数据拉取与复杂报告生成的耗时需求 |
| 最大上下文长度 | 8000 token | 容纳多批次来料数据与历史质量记录的完整信息 |

## 容易做错的三处
- 插件暴露内部端口后触发安全告警。现象为调用时返回权限拒绝状态码，原因是未配置端口访问白名单，直接暴露内部端口扩大了攻击面。
- 台账汇总结果字段为空。现象为生成的报告中供应商质保书信息缺失，原因是未配置对应文档类型的字段提取规则，无法匹配该品类特有的质保书字段。
- 工具调用超时中断。现象为生成季度供应商质量报告时返回超时错误，原因是超时设置未适配多源数据拉取的耗时需求，超出预设的等待时长。

## 怎么确认配好了
- 手动触发一次来料批次的台账汇总任务，检查生成的报告是否包含对应批次的检验项、判定结果与供应商信息。
- 查看工具调用日志，确认触发时机与来料批次标签绑定正确，未出现跨批次数据混杂的情况。
- 测试暴露端口的访问权限，确认仅授权IP可访问插件接口，符合安全配置要求。
- 使用FastGPT v4.17.0版本的curl命令发起测试请求，验证工具调用的返回格式与预设的台账字段一致。
