# 来料检验与供应商质量的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自采购订单、图纸规格、供应商质保书、检验设备采集数据、历史质量记录及供应商门户。数据更新随每批来料完成、每月或季度供应商评价、不定期审核同步推进。日常文档包含检验规范、抽样方案、来料检验报告、供应商审核报告、异常联络单、8D整改报告及让步接收审批单，数据字段包含批次标识、检验参数、供应商信息、不合格项记录及判定结果，字段单位随对应文档项匹配。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源分散的数据来源要求配置支持跨格式的文档接入，适配文本、图片等多种类型的检验记录。高频更新节奏要求配置适配近实时的索引刷新，避免台账数据滞后于实际来料情况。多样的文档类型与结构化字段要求模型具备准确提取关键参数的能力，同时需控制输出偏差以防止质量判定失误。此外，不良后果的严重性要求严格限定上下文与引用片段的长度，确保关键信息不被遗漏或截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启 | 来料检验报告常包含设备拍摄的物料外观、缺陷图片，需模型识别图片内容，适配FastGPT v4.17.0的视觉接入规范 |
| `temperature` | 0.1–0.3 | 需稳定输出结构化的检验台账数据，避免随机偏差影响质量判定结果 |
| `maxContext` | 8000–12000 token | 单批来料关联的采购订单、历史检验记录、供应商审核报告总长度较长，需足够上下文承载全部关联信息 |
| `quoteMaxToken` | 2000–3000 字符 | 需保留足够的原始文档片段用于台账汇总，避免截断关键检验参数或供应商信息 |
| `AIPROXY_API_ENDPOINT` | 填写对应模型服务的访问地址 | 适配不同部署方式的模型调用路径，支持本地或云端模型接入 |
| `AIPROXY_API_TOKEN` | 填写对应服务的访问令牌 | 完成模型调用的身份验证，确保访问权限合规 |

## 容易做错的三处
- 现象：在线召回测试时配置的重排功能未生效，返回结果条数不符合预期。原因：未在知识库索引环节同步开启重排配置，仅在应用环节设置未生效。
- 现象：设置`quoteMaxToken`为3000以上时，大模型无法接收到完整的上下文片段。原因：超出了模型自身的上下文窗口限制，未同步调整`maxContext`参数适配。
- 现象：上传的来料检验图片无法被模型识别，输出结果未包含图片内容。原因：未开启`vision`配置项，模型仅支持文本输入处理。

## 怎么确认配好了
- 上传单份包含文本和图片附件的来料检验报告，发起测试提问，查看模型输出是否包含图片中的缺陷描述内容，确认`vision`配置生效。
- 调整`quoteMaxToken`参数后，查看知识库召回的原始文档片段长度，确认未被过度截断。
- 发起包含多批次来料数据的提问，查看输出的台账汇总是否覆盖了所有关联的供应商、检验日期、判定结果等字段，确认上下文承载正常。
- 验证`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`配置，发起测试调用，确认模型返回正常的响应结果，无身份验证错误。
