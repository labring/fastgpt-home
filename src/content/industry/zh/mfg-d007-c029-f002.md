# 模具设计制造的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类的日常文档包含模具设计任务书、DFM报告、零件图、加工工艺卡、试模报告、改模通知、模具履历。数据来源包括客户产品模型、模流或成形仿真文件、CAD/CAM输出文件、机加工与测量数据、试模样件的扫描数据。数据更新按单个项目周期推进，每次试模或改模后同步新增或修改对应文档。单份文档的字段包含项目编号、模具型号、加工参数、缺陷记录等，无统一固定单位，随文档类型变化。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源多样，包含二进制CAD文件、结构化仿真结果、文本型工艺记录等，要求向量模型支持多类型内容的向量化处理；更新频率不固定且单次修改范围覆盖单个项目全周期，索引需要支持增量更新以避免全量重建的耗时；文档类型多且字段不统一，分块策略需适配不同文档的语义完整性，避免拆分破坏加工参数、缺陷描述的关联；试模改模产生的高频新增数据，需要控制索引写入延迟，确保台账汇总的时效性；模具编号、项目编号等唯一标识需作为元数据索引，便于精准召回对应项目的全量文档。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面参数：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配模具图纸文本、试模报告段落的语义完整性，避免拆分破坏加工参数的关联逻辑 |
| 重叠长度 | 100–150 字符 | 保留跨分块的试模缺陷描述、改模记录的上下文关联，避免语义断裂 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配度的非相关工艺卡、图纸片段，减少无效召回对报告生成的干扰 |
| `maxToken` | 4096 token | 适配DFM报告、模流仿真结果的长文本向量输入限制，避免长内容被截断 |
| 单次召回上限 | 前 8 条 | 覆盖单个模具项目的多类文档，避免召回冗余数据导致报告生成冗余 |
| 元数据索引开关 | 开启 | 基于模具编号、项目编号快速定位对应台账数据，提升召回精准度 |

## 容易做错的三处
- 现象：配置Embedding模型对接OneAPI时，控制台返回`model not supported`报错或请求超时。原因：未按照OneAPI的映射规则配置通义多模态向量模型的调用参数，未正确设置模型名称与接口路径的映射关系。
- 现象：开启重排模型并完成配置后，在线召回测试返回的结果排序与未开启时一致，未按相关性重新排序。原因：未在知识库索引环节绑定对应重排模型，或单次召回上限设置过高导致重排逻辑未触发。
- 现象：选择开源索引模型后，导入CAD图纸文本时，召回结果中缺失加工参数、缺陷记录等结构化字段。原因：未针对结构化文档配置元数据索引，仅对纯文本内容生成向量，未保留字段关联信息。

## 怎么确认配好了
- 上传单份试模报告，查看向量生成日志，确认元数据字段（如模具编号、试模次数）已正确提取并关联至索引。
- 发起针对特定模具编号的召回测试，确认结果仅包含对应项目的文档，无跨项目的冗余数据。
- 开启重排模型后，对比召回结果的排序逻辑，确认高相关性文档的位置符合预期。
- 测试长文本的DFM报告导入，确认未出现文本截断报错，向量生成流程正常。
