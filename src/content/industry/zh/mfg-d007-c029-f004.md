# 模具设计制造的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
模具设计制造的生产台账数据来源包括客户产品模型、模流或成形仿真文件、CAD/CAM导出文件、机加工与测量数据、试模样件检测记录。数据更新节奏按项目推进，每次试模或改模后均需同步更新。日常涉及的文档包含模具设计任务书、DFM报告、零件图、加工工艺卡、试模报告、改模通知、模具履历，核心字段包括模具编号、项目编号、加工参数、试模缺陷记录、改模次数，单位涵盖毫米、小时、次数等工业常用标准单位。

## 这些特征在「工作流编排」这一环带来什么约束
模具设计制造的多源异构文档格式要求工作流需适配不同类型的工业文件提取逻辑，避免单一规则无法兼容CAD图纸、仿真报告等异构数据源。非固定的更新节奏要求工作流支持按需触发，匹配试模、改模后的临时更新需求。全生命周期的台账关联要求工作流节点需绑定模具编号、项目编号等唯一标识，确保数据按模具维度准确汇总。较长的文档内容与复杂的字段结构要求工作流需合理拆分文本、控制上下文长度，避免节点执行超时影响整体流程。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配模具图纸、工艺卡的单页文本长度，避免单块内容过长导致解析失败 |
| 单次提取上限 | 前6条 | 匹配单项目下的核心文档数量，避免冗余数据干扰汇总逻辑 |
| 上下文窗口 | 4000–6000 token | 容纳DFM报告与试模报告的合并内容，确保大模型可获取完整的工艺与缺陷信息 |
| variables | 绑定`模具编号`、`项目编号` | 确保台账数据按模具维度汇总，避免跨项目数据混淆 |
| 节点重试次数 | 2次 | 应对大模型调用偶发失败，减少流程中断概率 |
| 触发时机 | 按项目节点完成触发 | 匹配试模、改模后的更新节奏，确保台账实时同步 |

## 容易做错的三处
- 文本提取组件返回空内容，删除后重新配置同参数组件可正常获取内容。现象为节点输出字段为空数组。原因是首次配置时未正确关联模具文档的实际存储路径，导致数据源绑定失效。
- 部分大模型无法正常提取文本内容，不同大模型调用同一提取节点结果差异显著。现象为部分大模型调用后输出无有效工业文档内容。原因是不同大模型对结构化工业图纸、工艺卡的语义解析能力存在差异。
- 对话节点无法获取用户输入内容。现象为对话节点返回未识别到有效问题的提示。原因是未正确绑定`variables`中的用户问题变量名，导致输入参数缺失。

## 怎么确认配好了
- 手动触发工作流，检查文本提取节点的输出是否包含模具设计任务书、试模报告中的核心字段。
- 切换不同大模型运行工作流，确认文本提取节点均能返回有效内容。
- 查看工作流日志，确认`variables`中的模具编号、项目编号已正确绑定到台账汇总节点。
- 模拟改模后的文档更新，触发工作流后检查台账数据是否同步更新。
