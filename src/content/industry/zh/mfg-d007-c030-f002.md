# 橡胶混炼与制品硫化的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自配方系统、原材料批次台账、密炼机、门尼流变仪、硫化机及实验室检测设备。日常文档包含配方单、称量记录、混炼曲线、胶料快检报告、硫化工艺卡、模具使用记录、成品性能报告。字段包含批次号、胶种占比（单位：份）、混炼温度（单位：℃）、硫化时间（单位：分钟）等工艺参数与检测结果。数据更新频率为每车胶、每批原料或每模次生产，更新频次高且单条数据体量小但总量庞大。

## 这些特征在「向量模型与索引」这一环带来什么约束
高频更新的生产数据要求索引支持增量更新逻辑，避免每次生成报告都全量重建索引，降低计算开销。多类型工艺参数与检测结果的混合字段，需要向量模型适配数值型与文本型混合输入，确保不同字段的语义关联被正确编码。批次号、模具号等关联元数据需随文档一同存入索引，便于后续按生产批次快速筛选召回。单条数据体量小但总量庞大，需合理设置分块规则，避免索引文件过大影响检索速度。时序类的混炼曲线、硫化参数数据，需索引支持时序关联召回，提升报告生成时的参数匹配精度。

## 配置怎么定
本配置基于 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配单条生产文档的平均长度，避免分块过碎导致语义断裂或过长导致向量编码偏差 |
| 重叠长度 | 50–100 字符 | 保留跨分块的工艺参数关联，避免混炼曲线、硫化时序数据被分块截断 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的历史数据，确保召回的台账数据与当前生产需求的关联性 |
| `maxToken` | 4096 token | 适配向量模型的最大输入长度限制，避免编码时溢出 |
| `defaultToken` | 1024 token | 作为单条文档默认编码的token上限，平衡编码精度与计算速度 |
| 单次召回上限 | 前 20 条 | 控制单次检索返回的数据量，避免生成报告时上下文过长 |

## 容易做错的三处
- 调用知识库接口生成索引时出现超时报错。原因是未针对高频更新的小体量数据设置增量索引，每次触发全量索引重建导致耗时过长。
- 导入混炼曲线文档后，检索结果中缺失扭矩、温度等数值字段的关联信息。原因是分块长度设置过大，将多组时序数据合并为一个分块，导致向量编码无法精准匹配单段工艺参数。
- 更换向量模型后，原有导入的文档无法匹配新的向量空间，检索结果为空。原因是未对已导入的知识库文档重新生成索引，新旧模型的向量编码规则不一致。

## 怎么确认配好了
- 上传单份混炼曲线文档，查看索引生成日志，确认分块数量符合预期，无过度截断或冗余分块。
- 发起检索请求传入硫化工艺关键词，检查返回结果的相似度分值处于预设阈值区间内。
- 执行增量更新操作，查看索引更新进度，确认仅新增数据被处理，未触发全量重建。
- 更换向量模型后，执行批量重新索引任务，确认原有文档的向量编码完成更新。
