# 橡胶混炼与制品硫化的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据来源于配方管理系统、原材料批次台账、密炼机采集数据、门尼粘度仪、硫化机运行日志及实验室性能检测报告。数据更新频率为每车原材料投料、每批胶料生产、每模次制品成型。日常文档包含配方单、称量记录、混炼曲线、胶料快检报告、硫化工艺卡、模具使用记录与成品性能报告，字段包含批次编号、投料重量、混炼温度、硫化时长、胶料硬度等，附带对应计量单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据更新频率高、粒度细且文档类型多样，对多轮对话与提示词配置带来多重约束。首先，数据按单批次、单模次更新，多轮对话需通过`chatId`绑定当前会话的生产批次，避免跨批次数据混淆；其次，文档包含混炼曲线、硫化工艺卡等不同格式的内容，提示词需明确指定提取字段的范围与优先级，防止字段混乱；再者，单批次关联的文档数量较多，需限制检索与上下文的长度，避免超出模型处理上限；最后，不同文档的字段单位存在差异，提示词需强制要求输出时附带标准计量单位，确保报告可读性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 会话上下文窗口 | 保留最近8轮对话 + 绑定`chatId`的批次数据 | 数据更新频率高，需精准绑定当前生产会话的专属台账 |
| 文档分块规则 | 按“批次编号”与层级标题分割知识库文档 | 文档以批次为核心标识，层级标题区分配方、混炼、硫化等不同类型内容 |
| 检索匹配上限 | 前6条匹配结果 | 单批次关联文档数量适中，避免过多内容导致上下文过载 |
| `variables` 绑定设置 | 绑定当前会话的生产批次变量 | 需自动关联对应批次的配方、工艺与检测台账数据 |
| 最大生成长度 | 10000 token | 报告需整合混炼曲线、硫化参数、性能检测等多类数据，需足够的输出空间 |
| 提示词模板 | 固定提取指定字段并按生产流程排序 | 文档字段多样，需统一输出格式以生成结构化的生产报告 |

## 容易做错的三处
- 现象：调用AI对话模块时返回422状态码。原因：未正确整理`messages`参数的对话历史格式，导致传入的上下文数据不符合接口规范。
- 现象：生成的生产报告中混杂不同批次的生产数据。原因：未按“批次编号”作为核心标识拆分知识库文档，导致跨批次的台账数据被错误关联。
- 现象：私有部署后无法修改新对话弹窗样式。原因：未定位到前端代码中对应弹窗组件的文件路径进行自定义修改。

## 怎么确认配好了
- 输入指定生产批次的编号关键词，检查检索返回的文档仅包含对应批次的内容。
- 发起多轮对话，查看会话绑定的`chatId`是否持续关联当前批次的生产数据。
- 生成生产报告后，核对提取的字段与预设的文档字段完全匹配，且附带标准计量单位。
