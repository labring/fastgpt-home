# 橡胶混炼与制品硫化的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
该品类数据来自配方系统、原材料批次记录、密炼机、门尼与流变仪、硫化机及实验室检测设备。日常文档包含配方单、称量记录、混炼曲线、胶料快检报告、硫化工艺卡、模具记录与成品性能报告。数据更新频率为每车胶、每批原料或每模次生产，字段包含密炼温度（℃）、硫化时间（分钟）、胶料批次号、模具编号等，部分文档包含结构化表格与可视化曲线数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据格式与高频更新节奏，要求模型接入支持结构化数据解析与低延迟调用，避免因延迟错过实时台账汇总需求。多份文档关联单批次生产的特征，要求配置项需适配多上下文合并处理，防止关键工艺参数被截断。带特定单位的字段要求模型能准确识别并关联对应业务逻辑，降低输出错误率。严重的出错后果要求配置的模型输出稳定性更高，需限制输出随机性，避免工艺参数错配导致的报废风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `temperature` | 0.1–0.3 | 该品类台账汇总需准确匹配工艺参数，低温度值可降低输出随机性，避免工艺参数错配 |
| `maxContext` | 8000–12000 token | 覆盖单批次多份文档（配方单、混炼曲线、硫化卡）的总内容量，避免上下文截断丢失关键数据 |
| `toolChoice` | auto | 支持自动调用SQL生成工具处理结构化台账数据，适配多源数据汇总需求 |
| `AIPROXY_API_ENDPOINT` | 按所选国内模型服务商提供的地址填写 | 适配无需依赖OpenAI的国内模型接入需求，符合实际使用场景 |
| `maxTokens` | 2000–3000 token | 限制单批次报告生成的输出长度，避免长文本处理超时或格式混乱 |
| `vision` | 开启 | 用于解析混炼曲线、硫化工艺卡中的图表数据，提取关键工艺参数 |

## 容易做错的三处
- 现象：生成的SQL语句仅移除换行符未补充空格，执行时报错“near 连续字符语法错误”。原因：未配置模型输出的文本格式化规则，仅执行了换行符清理操作。
- 现象：调用HTTP API接入国内模型时，返回结果为空或状态码403。原因：未正确配置`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`，或未切换至非OpenAI的代理地址。
- 现象：长文本台账汇总时，模型输出被截断，无法生成完整报告。原因：未调整`maxTokens`参数至适配单批次报告的输出长度，或`maxContext`设置过小导致上下文溢出。

## 怎么确认配好了
- 测试调用单批次的混炼与硫化数据，检查生成的SQL语句是否包含必要空格，无语法错误。
- 查看FastGPT v4.17.0的模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`已正确配置，无连接报错。
- 测试多文档合并输入，检查生成的报告未被截断，输出长度符合单批次生产的汇总需求。
- 验证工具调用功能，确认模型能自动触发SQL生成或内容提取适配逻辑，无字段为空的情况。
