# 水泥熟料与粉磨的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据覆盖水泥生产从矿山配料到粉磨出厂的全流程，来源包括在线成分分析设备、DCS控制系统、化验室、窑磨设备、原燃料台账与能源计量系统。数据更新节奏分为实时（设备运行参数）、每班（巡检记录、班组操作台账）、每日（化验报告、质量控制通知单与能源汇总报表）。日常文档包含生料配料方案、窑操作记录、化验报告等，字段涵盖原料掺加量、烧成温度、粉磨细度、能耗值等，对应单位分别为吨、摄氏度、平方米每千克、千瓦时。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于该品类数据来源分散且更新节奏差异显著，多轮对话需明确区分实时设备参数、班组台账与每日汇总报表的上下文范围，避免跨时间粒度的参数混淆。由于日常文档类型多样，提示词需指定对应文档的字段规则，例如将生料配料方案的原料掺加量与化验报告的强度指标分开定义。由于部分参数单位存在差异，提示词需统一单位转换逻辑，避免结果出现单位混乱。回转窑热工制度的调整依赖连续历史数据，多轮对话需保留最近3班的操作记录上下文，确保参数调整的连续性。

## 配置怎么定
本文基于FastGPT v4.17.0版本配置说明编写，具体配置项如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按会话生成的唯一标识绑定 | 确保多轮对话的上下文关联到对应水泥生产会话，避免跨会话数据混淆 |
| `messages` | 包含最近3班操作记录+当日化验报告的上下文组 | 匹配回转窑热工制度调整所需的连续历史数据范围 |
| `variables` | 预设生料配比阈值、烧成温度区间等品类专属变量 | 快速调用品类通用参数，减少重复输入 |
| 最大上下文长度 | 8000–12000 token | 覆盖多班台账与单日报表的完整内容，避免上下文截断 |
| 单次搜索上限 | 前6条 | 匹配日常台账的单批次文档数量，避免冗余结果干扰汇总 |
| 对话超时设置 | 300 秒 | 匹配台账汇总的常规处理时长，避免因数据量过大导致超时 |

## 容易做错的三处
- 现象：对话过程中出现Request Time报错，状态码为504。原因：未配置合理的对话超时时长，台账汇总涉及多源数据拉取时超出预设时长阈值。
- 现象：对话返回的台账数据字段单位混乱，例如同时出现吨与千克的掺加量数值。原因：提示词未明确统一单位转换规则，未指定文档字段的单位格式要求。
- 现象：多轮对话上下文丢失，无法延续之前的台账汇总请求。原因：未绑定`chatId`参数，导致每次对话生成新的会话标识，无法关联历史上下文。

## 怎么确认配好了
- 发起包含实时窑磨参数与当日化验报告的多轮查询，核对返回结果是否关联对应会话的唯一标识。
- 输入模糊的台账查询需求，确认系统是否自动优化为明确的字段检索指令。
- 发起覆盖多班台账的汇总查询，确认返回结果未出现上下文截断或单位混乱问题。
- 测试连续3次同主题的对话，确认上下文可正常延续，未出现会话绑定失效问题。
