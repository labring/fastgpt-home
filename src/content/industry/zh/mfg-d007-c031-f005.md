# 水泥熟料与粉磨的生产台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源于在线成分分析设备、DCS系统、化验室、窑磨设备、原燃料台账及能源计量装置。数据更新节奏分为实时、每班、每日三类，覆盖生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录、能源报表等多类文档。字段包含原料配比参数、设备运行读数、化验指标数值、能耗统计项，不同文档的字段结构与命名存在差异，无统一固定格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据来源分散且更新节奏多样，要求工具调用需适配多系统数据拉取与不同频率的触发需求。多类文档的字段结构差异较大，需插件配置灵活的字段映射规则，以准确提取不同文档中的目标参数。数据异常可能引发熟料质量波动或设备停机，要求工具调用需配置完善的失败重试与异常告警机制。此外，部分工具采用stream流或sse协议模式，需适配对应的通信与结果接收逻辑，避免出现结果缺失或无法拼接的问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | 按台账类型指定 | 适配不同文档的工具调用需求 |
| `functionCall` | 按字段映射规则配置 | 精准提取台账中的目标参数 |
| HTTP请求超时 | 600秒 | 匹配DCS系统的实时数据更新间隔 |
| 单次工具调用返回条数 | 前20条 | 适配单份台账的字段数量上限 |
| 插件导入路径 | 本地插件包目录 | 适配FastGPT v4.17.0及以上私有部署版本的目录规范 |
| 上下文承载量 | 8000 token | 承载多份台账的汇总数据 |

## 容易做错的三处
- 现象：调用HTTP接口时将stream参数设为true后无法获取完整最终结果。原因：未配置等待stream流结束的逻辑，未正确拼接分段返回的数据。
- 现象：私有部署的FastGPT版本导入插件时提示internal server error。原因：插件包的目录权限未匹配私有部署的服务器配置，或使用了不兼容的插件格式。
- 现象：使用sse协议封装的MCP工具时，系统提示仅支持stdio进程。原因：未在插件配置中正确指定通信协议类型，未适配工具的实际运行方式。

## 怎么确认配好了
- 执行单份台账的工具调用测试，检查返回结果是否包含预设的目标字段。
- 导入插件后查看系统日志，确认无internal server error类报错信息。
- 开启stream调用模式，验证是否能完整接收接口返回的全部分段数据。
- 配置字段提取规则后，对比台账文档的实际内容，确认提取结果与预期一致。
