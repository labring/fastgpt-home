# 水泥熟料与粉磨的生产台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
本品类数据来自水泥企业矿山、生料、烧成、粉磨、质量和能源部门，涵盖生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检、能源报表等日常文档。数据来源包括在线成分分析、DCS系统、化验室设备、窑磨运行设备、原燃料台账、能源计量装置。更新频率覆盖实时（在线成分分析、喂料数据）、每班（设备巡检记录）、每日（质量化验报告、能源报表）。字段包含原燃料入库量（吨）、窑筒体温度（摄氏度）、配料偏差值（千克）、电耗（千瓦时）等，不同文档的字段结构存在差异。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构的数据来源与差异较大的字段结构，要求数据库同时支持结构化与非结构化数据存储，避免硬编码固定表结构。不同更新频率的数据需要分层存储，实时采集的高频数据需分配高性能存储节点，冷数据需定期归档以释放存储空间。数据一致性要求较高，任何台账数据的丢失或偏差都可能引发熟料质量波动、窑系统结皮停机等问题，需保障数据写入与同步的可靠性。并发写入峰值较高，需合理配置数据库连接数以避免服务中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://fastgpt:xxxx@db-host:27017/fastgpt_clinker?authSource=admin` | 存储非结构化的巡检记录、化验报告等文档，适配多类型非结构化数据存储 |
| `PG_URL` | `postgresql://fastgpt:xxxx@db-host:5432/fastgpt_clinker` | 存储结构化的配料方案、能源报表、台账数据，支持复杂关联查询 |
| `DB_MAX_LINK` | `25–35 个` | 匹配水泥生产数据的并发写入峰值，避免数据库连接耗尽 |
| `REDIS_URL` | `redis://:xxxx@cache-host:6379/1` | 缓存实时采集的DCS、在线成分分析数据，降低主数据库查询压力 |
| 数据归档周期 | 每日凌晨 2:00 执行 | 将超过7日的历史台账数据归档至冷存储，释放主数据库存储空间 |

## 容易做错的三处
- 现象：启动FastGPT v4.17.0后，MongoDB数据目录未自动生成，同级目录无mongo/data文件夹。原因：未在配置文件中指定`MONGODB_URI`的挂载路径，或容器部署时未映射数据卷。
- 现象：使用mongorestore导入生产台账数据后，查询结果为空。原因：导入时未指定正确的数据库认证源，或数据导入后未重建索引。
- 现象：FastGPT v4.17.0 插件加载时出现包含 `$` 前缀字段提示的 MongoServerError。先核对插件生成的字段名、数据库请求和完整日志；该错误本身不足以证明 MongoDB 4.4.29 与 FastGPT 存在版本兼容冲突。v4.17.2 官方部署配置为不支持 AVX 的 CPU 标注了 4.4.29 回退（见[官方部署配置](https://github.com/labring/FastGPT/tree/v4.17.2/deploy/version/main)）。

## 怎么确认配好了
- 登录数据库管理工具，验证`MONGODB_URI`和`PG_URL`对应的数据库可以正常连接并写入测试数据。
- 查看Redis监控面板，确认`REDIS_URL`配置的缓存节点正常接收实时数据请求。
- 检查数据库连接数，确认当前连接数低于`DB_MAX_LINK`的设定值。
- 执行一次手动数据归档任务，确认归档流程正常触发且历史数据被正确转移。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
