# 水泥熟料与粉磨的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据来自在线成分分析系统、DCS集散控制系统、化验室检测、窑磨设备运行记录、原燃料台账与能源计量装置。日常文档包括生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录、能源报表。数据更新节奏涵盖实时（设备运行参数）、每班（巡检与班组记录）、每日（能耗与质量汇总）。数据字段包含原料标识、投料参数、操作时间、化验指标数值、设备运行温度、能耗读数，无统一固定单位，随指标类型变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类多源异构的数据来源、差异化更新节奏与多样的文档结构，对模型接入配置提出明确约束。多数据源需适配不同的接入协议与同步频率，因此需在配置中区分实时、每班、每日数据的触发规则；混合结构化与非结构化的文档类型，需模型支持多模态解析，因此需开启对应处理参数；无统一单位的字段要求模型自动适配单位标注，需在配置中启用单位识别逻辑；实时数据的低延迟需求，需限制模型上下文与生成token的上限，避免响应超时影响生产台账汇总效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多源生产数据的总长度，避免截断关键台账信息 |
| `maxTokens` | 2000–3000 token | 匹配单份报告生成的长度需求，平衡响应速度与内容完整性 |
| `quoteMaxToken` | 1500 token | 限制引用的原始台账片段长度，确保上下文关联清晰 |
| `temperature` | 0.3–0.5 | 降低生成结果的随机性，保证生产台账汇总的准确性与一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 指向实际运行的大模型服务地址，确保请求能正常送达 |
| `toolChoice` | auto | 允许模型自动选择是否调用工具，适配多源数据的汇总与解析需求 |

## 容易做错的三处
- 配置Ollama类模型时，返回结果与生产台账知识库无关联。原因是未正确配置`maxContext`参数，导致模型无法获取足够的知识库上下文片段，仅使用自身预训练知识生成内容。
- 无法找到rerank相关配置项。原因是未在FastGPT v4.17.0的模型配置页面中开启高级设置面板，该功能需在高级配置中展开后可见。
- 接入第三方API渠道时测试报错，强行启动后运行异常。原因是未正确填写`AIPROXY_API_TOKEN`参数，导致模型请求无法通过身份验证，部分请求被静默忽略。

## 怎么确认配好了
- 导入单份生料配料方案文档，触发模型生成台账摘要，核对摘要是否包含文档中的关键原料与参数信息。
- 提交包含不同更新节奏数据的测试请求，检查模型响应是否符合生产场景的延迟要求。
- 验证多源数据混合输入时，模型是否能正确关联不同来源的台账信息并生成汇总报告。
- 检查模型生成的报告是否自动标注了对应数据的来源与更新时间，确保信息可追溯。
