# 汽车整车总装的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
汽车整车总装的生产台账数据来源包含ERP/MES系统、VIN与车辆配置系统、拧紧工具、EOL下线检测线、质量追溯系统。日常文档涵盖生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录、一致性放行文件。数据更新频率覆盖每车实时上报、每班批量汇总两类，单条台账以VIN为唯一标识，关联数百项车辆配置、零件批次、工位操作记录与质量检测结果。

## 这些特征在「向量模型与索引」这一环带来什么约束
由于单条台账以VIN为唯一标识且关联多源数据，索引需要支持按VIN快速关联跨文档的台账信息，避免检索时出现数据割裂。混线生产模式下数据实时批量流入，索引需适配增量更新以避免全量索引的性能损耗。高精度扭矩数据与多字段配置信息的混合存储，要求分块策略兼顾数值精度与上下文完整性，避免因分块不当丢失关键关联信息。同时，台账汇总与报告生成需要召回大量关联数据，索引的召回上限与相似度阈值需适配多源数据的匹配精度要求，保证汇总结果的准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配装配作业指导书与拧紧数据的单块信息量，避免块丢失 |
| 重叠长度 | 100–150 字符 | 衔接VIN关联的多工位操作记录，保证上下文连贯性 |
| `maxToken` | 8192 token | 匹配整车台账汇总内容的最大长度限制 |
| 相似度阈值 | 0.72–0.78 | 适配混线生产下VIN匹配的精度要求，平衡召回率与准确率 |
| 单次搜索上限 | 前8条 | 平衡多源台账的召回数量与检索响应速度 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 索引上传后状态长时间卡在索引中。原因是混线生产下多源数据并发同步，未配置增量索引触发规则，导致全量索引任务堆积。
- 分块长度设置为3000字符时出现文本块丢失。原因是单块内容超出`maxToken`限制，模型自动截断后丢失部分字段信息。
- 向量化过程中出现embedding速率超限报错。原因是未限制向量化并发线程数，导致API调用频率超出平台限额。

## 怎么确认配好了
- 上传单份VIN清单文档，检查索引完成状态是否在5分钟内更新为就绪。
- 输入包含具体VIN的检索指令，确认检索结果中包含对应车辆的拧紧数据与检测记录。
- 调整分块长度为3000字符，上传装配作业指导书，检查系统是否弹出块丢失提示。
- 查看向量化日志，确认无embedding速率超限的报错记录。
