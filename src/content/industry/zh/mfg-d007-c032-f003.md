# 汽车整车总装的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
数据来源包括ERP/MES系统、VIN与车辆配置系统、拧紧工具、EOL下线检测线、质量追溯系统。更新节奏为每台车生成专属台账，实时同步拧紧数据与下线检测结果，每班汇总班组生产记录。日常文档涵盖生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录、一致性放行文件，字段包含唯一VIN码、扭矩值（单位牛·米）、检测项合格状态、供应商批次号、工位编号等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
以VIN为核心的单台车台账匹配要求对话必须先明确VIN码，否则无法精准定位对应生产数据。实时更新的拧紧与检测数据要求多轮对话支持实时数据源拉取，避免使用过期缓存。多类长文档的汇总需求需要足够的上下文承载能力，防止关键信息被截断。混线生产的场景要求提示词需区分不同车型的配置规则，防止跨车型数据混淆。同时，台账错误会引发车辆下线停滞或安全风险，对话环节需加入必填字段校验逻辑。

## 配置怎么定
本页面适用FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话上下文窗口 | `8000–12000 token` | 承载VIN清单、多份检测报告等长文本数据 |
| `messages`参数配置 | 保留最近15–20轮对话 | 过滤冗余历史，聚焦当前单台车台账的查询需求 |
| `variables`参数绑定 | 绑定VIN码、扭矩合格阈值 | 以VIN为核心精准匹配单台车专属生产台账 |
| 工具调用超时 | 600 秒 | 适配多源ERP、MES数据拉取的耗时要求 |
| 问题自动优化 | 开启 | 简化用户模糊提问，自动补全VIN相关的查询条件 |
| `chatId`参数隔离 | 按班组/班次隔离 | 避免跨会话的上下文干扰，保证单台车查询的独立性 |

## 容易做错的三处
- 对话界面未显示HTTP编排的输出内容。现象为执行编排后返回结果为空，查看会话日志发现`variables`字段未包含接口返回数据。原因是未将HTTP接口的输出正确绑定到对话变量中。
- 本地部署场景下无法读取上传的生产台账文件。现象为知识库上传文件正常，但对话调用时无法解析文件内容。原因是未配置对话场景下的文件读取权限。
- 向量索引进度长时间停滞。现象为索引任务始终处于运行状态，无进度更新。原因是未针对VIN码等长唯一标识字段调整分块规则，导致分块处理超时。

## 怎么确认配好了
- 发起包含具体VIN码的测试对话，检查返回结果中是否包含对应车型的拧紧数据、下线检测报告等内容。
- 触发HTTP编排请求，查看会话日志中`messages`和`variables`字段是否携带预期的接口输出数据。
- 上传一份测试用的返修记录文件，在对话中发起内容查询，确认可以提取到文件中的返修工位、缺陷类型等字段信息。
- 启动向量索引任务，观察任务进度是否在合理时间内完成，无异常报错提示。
