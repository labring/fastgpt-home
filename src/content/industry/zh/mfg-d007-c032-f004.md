# 汽车整车总装的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
汽车整车总装的生产数据以单台车辆的VIN码为唯一主线，日常文档包含生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录、一致性放行文件。数据来源覆盖ERP/MES系统、VIN与配置系统、供应商批次系统、拧紧工具、EOL检测线及质量追溯系统，更新节奏涵盖单台车实时生成、工位级实时更新、班组每班汇总。核心字段包含VIN码、扭矩值（单位N·m）、检测项合格状态、零件批次号，部分文档为结构化表格格式，部分为原始设备采集的时序数据。

## 这些特征在「工作流编排」这一环带来什么约束
由于以VIN为唯一标识进行混线生产，工作流需支持按单台车动态匹配专属配置与数据，避免跨车辆的配置错配。多源异构的数据来源要求工作流集成不同格式的数据源节点，需统一数据映射规则。实时与高频的更新节奏要求工作流支持触发时机灵活配置，既可响应单台车工位完成事件，也可按班组周期汇总数据。严格的质量要求意味着工作流需内置校验与失败处理逻辑，避免错误数据流入台账生成环节。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工作流功能制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发方式 | 按VIN生成触发 + 每日定时汇总 | 匹配整车总装混线生产的实时节拍与班组台账汇总需求 |
| 变量引用 | 按`variables`绑定VIN、扭矩阈值、检测项清单 | 实现单台车专属数据的动态调用，避免硬编码适配不同车型 |
| 节点超时设置 | 600秒 | 覆盖跨多系统拉取ERP、拧紧工具、EOL检测数据的平均耗时区间，按实测标定 |
| 上下文长度限制 | 800–1200字符 | 匹配单台车台账数据的典型长度，避免超出大模型上下文导致报错 |
| 失败重试配置 | 最多3次，间隔30秒 | 适配总装线节拍要求，覆盖临时网络波动或系统短暂响应延迟 |

## 容易做错的三处
- 现象：工作流运行后输出多段独立的AI对话结果，未合并为完整的生产台账报告。原因：未在串联的AI节点间配置结果聚合逻辑，直接展示了每个节点的输出内容。
- 现象：上传大体积的拧紧数据或VIN清单时，返回400错误。原因：未在工作流中加入文件预处理节点，未对超长文本进行截取或分块处理，超出大模型上下文限制。
- 现象：生成的台账报告中未正确匹配VIN对应的零件配置与扭矩要求。原因：未使用`nodeId`绑定对应工位的数据源节点，导致变量引用混乱，匹配到错误的车辆数据。

## 怎么确认配好了
- 触发单台车的工作流实例，核对输出结果中是否包含该VIN对应的专属装配数据、扭矩值与检测项合格状态。
- 上传超出常规长度的台账文件，检查是否触发预处理逻辑且无400报错，输出内容为截取后的有效数据。
- 模拟节点失败场景，检查是否按配置触发重试，重试失败后是否生成对应日志记录。
- 查看`variables`绑定的参数是否正确映射了VIN、扭矩阈值等核心字段，无参数缺失或错误绑定。
