# 汽车整车总装的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
汽车整车总装的生产台账数据来源包括ERP/MES系统、VIN与车辆配置系统、拧紧工具、EOL下线检测线、质量追溯系统。数据更新频率为每车生成核心台账，拧紧数据、下线检测结果实时同步，返修记录与放行文件按每班汇总。日常生成的文档包括生产订单、VIN清单、装配作业指导书、单台拧紧扭矩数据、下线检测报告、返修记录、一致性放行文件，字段包含VIN码、零件批次号、扭矩值、检测项结果、工位编号、时间戳，单位涉及牛米、毫秒、标准日期时间格式。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类以VIN为单车主线开展混线生产，单台车辆需匹配数百项零件配置与作业数据，对模型的上下文精准匹配能力要求较高。实时同步的拧紧、检测数据要求模型调用具备低延迟特性，避免影响生产节拍。多维度、多来源的台账文档需要模型能够正确关联不同系统的字段，避免错配漏装。同时，台账数据涉及车辆一致性与安全，模型输出的汇总报告需具备严谨性，任何数据错漏都可能导致停线或召回风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000-12000 token | 需容纳单台车辆的全部关联台账、拧紧数据与检测报告，避免关键配置信息被截断 |
| `maxTokens` | 2000-3000 token | 适配单台车辆汇总报告的标准输出长度，确保覆盖所有必填统计项 |
| `quoteMaxToken` | 1500-2000 token | 预留足够空间引用拧紧扭矩、下线检测等核心佐证数据，满足合规追溯要求 |
| `temperature` | 0.1-0.3 | 生成严谨的合规报告，避免发散性内容，保障数据一致性 |
| `AIPROXY_API_TOKEN` | 专属加密密钥 | 隔离不同产线的调用权限，保障生产数据的访问安全 |

## 容易做错的三处
- 现象为知识库查询能返回匹配结果，但模型输出为空。原因是未正确配置`maxContext`的取值区间，导致多工位的台账数据被截断，无法完成VIN关联匹配。
- 现象为本地测试正常，但外部发布渠道无法引用知识库内容。原因是未正确配置`AIPROXY_API_ENDPOINT`指向部署环境的代理地址，或密钥未授予外部调用权限。
- 现象为升级到4.8.21版本后模型调用失败。原因是未按新版要求调整`temperature`的取值区间，或未匹配兼容的模型参数格式，导致模型无法正常解析配置。

## 怎么确认配好了
- 上传单台车辆的完整台账数据包，触发汇总生成任务，检查输出是否包含所有预设的核心字段，如VIN码、零件清单、扭矩统计值。
- 模拟跨工位返修场景，输入对应VIN的返修记录查询指令，验证模型是否能正确关联历史检测数据与当前返修台账。
- 调用外部发布接口，检查返回结果中是否包含知识库引用的原始数据片段，确认权限与链路配置正常。
- 升级到FastGPT v4.17.0后，核对`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置内容，确保与部署环境的参数一致。
