# 汽车零部件批量制造的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
这个品类的数据来自客户图纸与特殊特性清单、ERP系统、MES系统、量检具、设备过程参数及供应商质保书。日常产生的文档包括控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料、8D报告。数据更新节奏为每批生产、每班作业及持续采集设备与检测参数。台账字段包含批次号、工序参数、检测数值、供应商信息等，对应文档的标准格式与字段要求需严格匹配客户特殊特性。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流需支持跨系统拉取数据，需配置统一的字段映射规则。高频更新的节奏要求工作流触发时机需匹配生产批次与班次，避免数据滞后。丰富的文档类型与严格的客户特殊特性要求，需在工作流中按文档类别配置不同的检索与汇总逻辑，确保输出符合整车客户的质量体系要求。出错后果严重的特性要求工作流需配置失败重试与异常告警环节，避免批量不良流入下游。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本界面。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 变量配置 | 绑定`variables`为批次号、工序参数、检测值、供应商质保书编号 | 匹配汽车零部件批量制造台账的核心字段，确保工作流可精准定位对应批次的生产数据 |
| 节点触发规则 | 按`nodeId`绑定ERP、MES、量检具三个数据节点，触发时机设为每批生产完成后 | 贴合该品类按批次更新台账的业务节奏，确保数据采集完整 |
| 上下文窗口 | 设置为8000–12000 token | 容纳多份PPAP、SPC报表及过程流程图的完整内容，满足汇总报告的信息需求 |
| 问题优化组件位置 | 放在用户输入节点之后 | 提前整理台账查询指令，修正模糊表述，提升检索准确性 |
| 最大重试次数 | 设置为2次 | 控制批量制造场景下的异常重试节奏，避免影响批次交付周期 |
| 超时设置 | 设置为600秒 | 预留足够时间拉取多源异构的生产台账数据，避免因超时导致工作流失败 |

## 容易做错的三处
- 工作流对话显示失败但模型后台有响应日志，原因是`variables`未正确绑定台账批次号字段，导致节点无法匹配对应批次的生产数据。
- 系统提示词调用顺序不符合预期，原因是工作流节点的执行顺序未按数据拉取、变量绑定、提示词调用的逻辑配置，导致提示词未获取到有效台账数据。
- 检索结果条数不符合预期，原因是将问题优化组件放在了检索节点之后，无法提前修正台账查询的模糊表述，导致检索范围偏离需求。

## 怎么确认配好了
- 核对`variables`绑定的字段与当前批次的台账数据字段是否一致，确认匹配规则正确。
- 触发一次测试工作流，查看各节点的输入输出日志，确认数据拉取、变量绑定环节无异常。
- 检查问题优化组件的触发时机，确认在检索节点之前执行。
- 模拟数据拉取失败的异常场景，验证工作流的重试与告警逻辑是否生效。
