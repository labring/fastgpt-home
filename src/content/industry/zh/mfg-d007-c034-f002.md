# 烘焙与方便食品的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类的主体为面包糕点、饼干、方便面及速冻面点工厂，日常产生配方与投料单、生产记录、烘烤/蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验等文档。数据来源覆盖原辅料合格证明、ERP/MES系统、称量系统、生产设备、实验室及食品追溯台账，更新频率按每批、每班或每日执行。文档包含过敏原标识、工艺参数、检验结果、保质期等字段，部分文档如烘烤曲线存在时序性数值记录，不同来源数据格式存在差异。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据更新频率高且单批生产关联多环节文档，要求索引支持增量更新以适配频繁的台账同步需求。文档包含过敏原、工艺参数等关键敏感字段，需保证向量检索的精准度，避免匹配偏差引发后续质量问题。换线频繁带来的文档类型与内容差异，要求分块规则适配短文本（如金属检测记录）与长文本（如完整烘烤曲线）的混合场景。多来源数据的格式差异，需在索引前完成统一的字段映射与清洗，否则会导致向量生成异常或检索结果失真。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类配方单、生产记录的平均文本长度，避免单块内容过于分散 |
| 重叠长度 | 100–150 字符 | 保留跨块的过敏原标识、工艺参数等关键信息，防止检索时丢失上下文 |
| 相似度阈值 | 0.75–0.85 | 匹配该品类对关键字段的检索精度要求，降低误匹配概率 |
| 单次搜索上限 | 前 10 条 | 平衡检索效率与结果覆盖度，适配多台账的批量核对场景 |
| `defaultToken` | 1000 token | 适配单份短文档（如金属检测记录）的向量生成需求 |
| `maxToken` | 8000 token | 覆盖长文本（如完整烘烤曲线）的向量生成上限 |

## 容易做错的三处
- 调用chunk模式的pushdata api上传数据后，界面持续显示索引中。原因是未配置与数据更新频率匹配的索引同步周期，或未开启增量索引触发规则。
- 接入bce-embedding-v1模型时出现模型权限报错。原因是未在FastGPT平台配置对应模型的有效密钥，或密钥未绑定指定模型权限。
- 直接调用embedding模型未通过one API时，出现「该令牌无权使用模型」的报错文案。原因是未绑定对应模型的有效访问令牌，或令牌未开通对应模型的使用权限。

## 怎么确认配好了
- 上传单份配方文档，查看FastGPT v4.17.0的索引状态是否在合理时间内完成更新。
- 检索包含过敏原标识的关键词，检查返回结果的匹配度符合预设的精度要求。
- 调用pushdata api上传测试数据，确认无权限、令牌或模型调用相关报错。
- 查看向量模型调用日志，确认成功生成并存储对应文档的向量数据。
