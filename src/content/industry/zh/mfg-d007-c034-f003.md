# 烘焙与方便食品的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据主体为面包糕点、饼干、方便面及速冻面点工厂。日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量系统、生产设备、实验室检测数据及食品追溯台账。更新节奏按每批、每班或每日执行，字段包含投料量、烘烤时长、包装日期、保质期等，单位多为千克、分钟、天等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类数据来源分散、更新频率高且字段关联强，对多轮对话与提示词配置带来多重约束。首先，多源数据需通过多轮对话逐步对齐ERP、生产设备、实验室的字段差异，避免跨系统数据冲突。其次，频繁的产品换线与批次更新要求上下文窗口限制在合理范围，防止冗余数据干扰当前批次的台账汇总。再者，过敏原管控与异物核查的优先级要求提示词需先引导输入批次标识，再针对性拉取对应生产记录、检测报告，确保核心环节的核对效率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 前8轮对话上下文 | 本品类批次更新频繁，过长上下文会干扰当前批次数据识别，8轮可覆盖单批次的多环节核对流程 |
| `variables` | 绑定批次号、产线编号2个必填变量 | 本品类换线频繁，需通过变量锚定对应批次的生产台账、检测报告，避免数据混淆 |
| 最大上下文长度 | 1200–1500 字符 | 单批次核心台账数据量适中，该区间可完整承载配方、烘烤曲线、检测报告的关键信息，同时避免冗余 |
| 对话触发规则 | 按批次号触发 | 本品类数据按批次更新，按批次触发可精准拉取对应产线的生产记录，避免跨批次数据混杂 |
| `chatId` | 绑定当前产线会话ID | 多产线同时运行时，需通过`chatId`隔离不同产线的对话上下文，防止数据串扰 |

## 容易做错的三处
- 现象：调用外部应用或插件后，对话日志未被记录。原因：未在工作流配置中开启对话日志同步开关，导致跨应用调用的交互未被纳入当前会话上下文。
- 现象：表单输入节点在独立工作流中对话框隐藏，嵌套到其他工作流后对话框仍显示。原因：未在嵌套工作流的节点配置中设置适配嵌入场景的显示参数，导致未遵循外层工作流的交互规则。
- 现象：尝试在对话框中渲染网页或输出文生图结果时，界面无对应内容展示。原因：未开启对话窗口的富文本渲染配置，且未配置文生图模型的调用绑定，无法生成或渲染非文本内容。

## 怎么确认配好了
- 输入测试批次号，核对对话是否自动拉取对应批次的配方、生产记录等数据，确认变量绑定生效。
- 调用外部插件后，查看会话日志是否完整记录本次交互，确认对话日志同步配置正确。
- 在嵌套工作流中测试表单输入节点，确认对话框是否按预期隐藏或显示，验证嵌入场景的配置适配性。
- 尝试发送包含富文本或图片请求的指令，确认对话窗口可正常渲染对应内容，验证富文本与模型绑定配置。
