# 烘焙与方便食品的生产台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
本品类数据来自面包糕点、饼干、方便面、速冻面点工厂的多类业务文档与系统。日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量设备、烤炉/油炸线、实验室检测系统及食品追溯台账。数据更新按生产批次、班次或每日进行，核心字段包含批次号、投料量、加工温度、过敏原标识、包装日期与保质期。

## 这些特征在「工具调用与插件」这一环带来什么约束
多数据源的存在要求工具调用需支持对接ERP、生产设备、实验室系统等不同类型的API，需提前配置各数据源的权限与字段映射规则。按批次、班次的高频更新节奏，要求工具调用触发时机需绑定生产批次节点，避免重复拉取过期数据。品类内配方多、换线频繁的特点，要求工具调用需校验配方与过敏原标识的关联关系，防止错配。直接食用的产品属性，要求工具调用生成的报告需包含异物控制、清洁记录等合规字段，确保数据完整性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | auto | 适配多数据源的自动工具选择，无需手动指定调用工具 |
| 工具调用触发时机 | 按生产批次触发 | 匹配本品类按批次更新台账的业务节奏 |
| 单次工具调用返回条数 | 前8条 | 覆盖单批次核心的配方、生产、检测等台账文档 |
| 工具调用超时时间 | 120秒 | 适配多数据源同步的平均耗时 |
| 工作流/API 函数调用配置 | 开启字段校验 | 确保过敏原、保质期等品类特有字段的格式与内容合规 |
| 单次调用token上限 | 8000 token | 适配生产台账汇总报告的内容长度 |

## 容易做错的三处
- 现象：导入导出的工作流JSON后，界面提示「未找到指定插件」。原因：导出工作流时未同步携带插件的本地配置信息，仅导出了流程逻辑结构。
- 现象：工具调用返回的过敏原标识字段为空。原因：未在工具调用配置中指定需要拉取的过敏原台账字段，默认仅返回基础批次信息。
- 现象：工具调用返回结果条数不足，仅返回2条文档。原因：未调整单次工具调用返回条数的配置，使用了默认的低条数阈值。

## 怎么确认配好了
- 手动触发一次工具调用，检查返回结果是否包含配方、烘烤曲线、金属检测记录等本品类特有台账字段。
- 导入导出的工作流JSON文件，查看插件列表是否完整，无缺失的配置参数。
- 模拟单批次生产数据输入，验证工具调用是否按批次触发并生成对应内容的报告。
- 查看工具调用日志，确认参数传递格式正确，无字段缺失或格式错误。
