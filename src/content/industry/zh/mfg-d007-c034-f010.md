# 烘焙与方便食品的生产台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
烘焙与方便食品生产场景的核心数据来自面包糕点、饼干、方便面与速冻面点工厂的日常业务文档，包括配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量设备、烤炉/油炸线、实验室检测系统与食品追溯台账。数据更新频率为每批、每班或每日，文档字段包含批次号、投料量、烘烤温度与时长、过敏原标识等，部分文档附带数值曲线与图片素材。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的高频更新节奏要求检索链路适配增量同步与实时召回，避免因数据滞后导致台账汇总错误。多类型混合文档（文本、数值曲线、图片）需要检索同时覆盖语义匹配与结构化字段匹配，无法仅依赖纯文本语义检索。频繁的产品换线与过敏原管控需求，要求检索精准限定范围，避免跨批次、跨车间的无关文档干扰。同时，产品直接面向消费者，检索结果的准确性直接关联食品安全风险，需严格控制低匹配度结果的召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 平衡检索的召回率与精准度，避免将非本批次的生产记录、清洁文档混入结果 |
| `limit` | 前8条 | 覆盖单批次生产台账的核心字段，控制上下文长度，适配台账汇总与报告生成的上下文窗口 |
| `searchMode` | hybrid | 同时匹配文本语义与数值特征，适配烘烤曲线、投料量这类带结构化数值的业务文档 |
| `usingReRank` | 开启 | 过滤低相关召回结果，优先返回与过敏原管控、批次校验相关的高价值内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 扩展检索词范围，补充批次号、车间编号、产品类型等字段的匹配，提升精准度 |
| `collectionIds` | 按车间/产品线分组 | 限定检索的知识库集合，避免跨批次、跨产品线的文档干扰检索结果 |

## 容易做错的三处
- 上传含图片的配方或生产记录文档后，检索结果未返回图片内容。原因：未启用知识库图片解析配置，仅提取了文档内的文本信息。
- 升级至FastGPT v4.17.0后使用URL创建知识库报错，后台日志提示cannot fetch internal url。原因：内部业务系统URL未添加至允许访问白名单，或网络代理配置未覆盖内部接口请求。
- 本地部署开源版FastGPT后，可创建的知识库数量无法调整至预设上限以上。原因：未修改配置文件中的默认知识库数量限制参数。

## 怎么确认配好了
- 上传单批次的配方与生产记录文档，发起包含批次号关键词的检索请求，核对返回结果的数量与`limit`配置一致。
- 输入包含过敏原关键词的检索词，确认返回结果包含对应批次的清洁消毒记录与过敏原管控文档。
- 查看后台检索日志，确认`usingReRank`与`datasetSearchUsingExtensionQuery`的调用状态为正常执行。
- 上传含图片的文档，发起检索请求，确认结果中包含图片链接或解析后的图片描述文本。
