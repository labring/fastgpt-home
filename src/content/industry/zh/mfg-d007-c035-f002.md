# 热处理的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类的数据覆盖专业热处理厂、汽车及轴承零部件厂热处理车间的全流程台账。日常文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单。数据来源包括材料牌号、客户技术条件、温控仪表、炉温均匀性测试设备、硬度计与金相设备、MES系统。更新频率为每炉次、每批，单条数据包含炉号、批次号、加热温度、保温时长、冷却速率、硬度值、金相组织类型等字段，附带摄氏度、分钟、HV、HRC等标准单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来多重约束。首先，高频次的每炉次更新要求索引支持增量触发，避免全量重建的资源消耗；其次，多类型混合文档（表格类工艺卡、曲线类炉温数据、文本类异常处置单）要求分块策略适配不同文档结构，避免拆分破坏逻辑关联；第三，带特定单位的字段（如HV硬度值、摄氏度温度）要求向量建模时保留单位关联，防止不同单位的同类数据被错误匹配；最后，异常处置单的非结构化内容需要精准分块，避免混淆不同炉次的异常信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配热处理工艺卡、炉温曲线文本的单段逻辑完整性，避免拆分工艺步骤 |
| 重叠长度 | 100–150 字符 | 保留跨分块的炉号、批次号等关联信息，确保同炉次数据的向量索引可被正确关联 |
| 相似度阈值 | 0.75–0.85 | 区分同批次不同炉次的细微工艺参数差异，避免召回无关数据 |
| 单次搜索上限 | 前 8 条 | 覆盖单炉次关联的工艺卡、炉温曲线、硬度报告等多类文档 |
| `defaultToken` | 4096 token | 适配单炉次全量台账的基础上下文长度，满足常规汇总需求 |
| `maxToken` | 8192 token | 容纳报告生成时的多文档汇总文本，避免上下文溢出 |

## 容易做错的三处
- 调用chunk模式的pushdata api上传数据后，界面长期显示「索引中」状态。原因：未适配热处理数据的高频更新节奏，索引触发阈值设置过高，导致增量数据堆积未触发实际索引构建。
- 问答拆分后最后一组索引无法通过校验。原因：分块时未保留炉号、批次号等核心关联字段，导致向量索引无法匹配同炉次的多类文档，校验环节判定为无效索引。
- 搜索结果返回大量非目标炉次的工艺数据。原因：相似度阈值设置过低，无法区分不同批次的工艺参数差异，召回了无关炉次的台账信息。

## 怎么确认配好了
- 上传单炉次的完整台账数据，查看FastGPT v4.17.0的索引构建日志，确认分块后的数据包含炉号、批次号等关联字段。
- 输入单炉次的工艺参数关键词，检查搜索结果的召回条数符合单次搜索上限的设置。
- 输入批量炉次的汇总查询指令，确认生成的报告未出现上下文溢出的报错。
- 对比同批次与异批次的搜索结果，确认相似度阈值可有效区分两类数据的召回优先级。
