# 热处理的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类数据围绕金属材料热处理过程产生，不改变或少量改变工件几何形状，核心聚焦组织与力学性能调整。数据来源包括材料牌号档案、客户技术要求、温控仪表、炉温均匀性测试设备、硬度计、金相检测设备及车间MES系统。数据按每炉次、每批更新，日常文档包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表与异常处置单。数据字段包含炉温数值（℃）、保温时长、硬度检测值（HV）、金相组织类型、异常处置记录等，格式随设备与工单类型略有差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据按每炉次、每批高频更新，包含多源异构的结构化文档与非标准化异常记录，要求模型接入配置适配快速迭代的工单数据。炉温曲线、金相报告等包含图像与专业术语的内容，要求配置支持多模态数据解析的能力。数据字段随设备与客户要求存在差异，需配置灵活的字段映射规则，避免固定模板导致的解析失败。高频次的炉次数据处理要求限制上下文长度，防止模型响应超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `vision` | 开启 | 需解析炉温曲线、金相报告等图像类文档 |
| `maxContext` | 8000–12000 token | 适配单炉次多文档的上下文汇总需求 |
| `temperature` | 0.1–0.3 | 保证专业术语解析与台账格式的一致性 |
| `quoteMaxToken` | 2000–3000 token | 限制引用的原始文档片段长度，避免上下文溢出 |
| `AIPROXY_API_ENDPOINT` | 填写本地部署的模型访问地址 | 适配Ollama、Xinference等本地模型的调用需求 |
| `AIPROXY_API_TOKEN` | 填写对应平台的访问密钥 | 完成模型调用的身份验证 |

## 容易做错的三处
- 现象：本地部署Ollama模型后，调用时返回无关内容或无法匹配预设的台账格式。原因：未在模型配置中添加针对热处理业务的系统提示词，导致模型输出偏离业务需求。
- 现象：配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`后，界面返回认证失败提示。原因：密钥填写错误或代理地址未开放对应端口的访问权限。
- 现象：通过域名访问平台时，模型配置参数无法保存且解析结果与IP访问不一致。原因：域名解析未正确指向平台服务端口，或平台跨域配置未覆盖域名访问路径。

## 怎么确认配好了
- 上传单份包含炉温曲线图片与工艺卡的工单，验证模型能否准确提取炉温数值与保温时长。
- 提交包含异常处置单的台账数据，验证模型能否正确映射异常类型与处置措施字段。
- 连续提交3份不同炉次的台账数据，检查模型响应时长符合业务处理要求。
- 使用FastGPT v4.17.0版本的模型调试工具，验证调用日志与配置参数一致。
