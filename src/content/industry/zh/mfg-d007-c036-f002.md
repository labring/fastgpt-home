# 焊接结构件制造的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
焊接结构件制造的日常业务文档包含焊接工艺评定、焊接工艺规程、焊材领用记录、焊工资格记录、焊缝检验报告、返修单等。数据来源涵盖设计图纸、材料质保书、焊接设备参数、焊材库管理系统、无损检测系统、人员资质台账等。数据更新频率为每条焊缝或每批、每班，单条记录包含焊缝标识、材料参数、人员资质编号、检测结果、返修记录等字段，兼具结构化表格与非结构化文本类型。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据更新频率高且粒度细，要求索引支持增量更新与细粒度分块，避免全量重建带来的性能损耗。文档兼具结构化与非结构化类型，需适配混合格式的向量化处理，确保表格类焊材领用记录、文本类工艺规程的向量提取一致性。业务数据关联度高，如同焊缝的多类台账需关联召回，需精准控制召回范围，避免无关数据混入汇总结果。多系统来源的数据需统一字段映射，防止索引时出现字段混乱导致的检索偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配单条焊缝关联台账的信息密度，避免拆分破坏工艺参数、检测结果的完整性 |
| 重叠长度 | 100–150 字符 | 保留跨分块的焊缝编号、焊材牌号等关键关联信息，防止上下文断裂 |
| 相似度阈值 | 0.75–0.85 | 匹配焊缝检验报告、返修记录等高关联度业务数据，降低无关记录的召回率 |
| 单次搜索上限 | 前 10 条 | 覆盖同批次或同焊缝的多类台账记录，满足生产台账汇总的信息需求 |
| `defaultToken` | 8192 | 适配焊接工艺规程、无损检测报告类长文档的向量化处理 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 现象：从FastGPT v4.9.0升级到v4.9.3后，原有上传的焊接台账文档无法被检索到。原因：未执行增量索引同步，旧版本的索引结构与新版本不兼容，需重新构建全量或增量索引。
- 现象：上传焊材领用记录的Excel文件后，向量化后索引内容缺失字段或格式混乱。原因：未开启Excel表格的结构化解析配置，未指定表头对应的业务字段映射，导致向量提取不完整。
- 现象：使用知识库搜索引用合并功能后，生成的生产汇总报告出现内容冗余。原因：未正确配置引用合并的匹配规则，导致同一条台账的不同分块被多次引用。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，上传单条焊缝对应的焊材领用记录、无损检测报告，执行关键词检索，确认能召回对应文档。
- 调整相似度阈值，验证高关联度的焊缝数据能优先召回，低关联度数据不被误召回。
- 上传同批次的多类台账文档，执行生产汇总查询，确认返回的内容覆盖所有关联记录且无明显重复。
- 验证长文档（如完整焊接工艺规程）的向量化结果，确认关键工艺参数未被截断。
