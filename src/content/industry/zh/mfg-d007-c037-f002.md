# 生产计划与车间排程的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
通常服务于制造企业PMC、计划、车间调度和物控部门，日常处理的文档涵盖销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单。数据来源于ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货，更新节奏包含每日、每周，以及订单或异常发生时的即时更新。文档字段多包含编号、时间、数量、设备标识、工序参数等，单位涉及件、小时、班次等。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据来源分散且字段类型多样，需针对不同文档类型适配差异化的分块规则；更新频率不均，需支持增量索引与全量索引的灵活切换；文档包含多维度业务关联参数，向量模型需适配长文本与结构化字段混合的编码逻辑。单次处理的数据量较大，需限制分块的token上限避免超出模型处理能力。生产排程相关数据的业务关联度高，索引需保留跨文档的语义关联，避免碎片化的检索结果影响业务判断。同时，实时更新的需求要求索引任务的延迟需控制在业务可接受的范围内。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配生产排程文档的单段业务逻辑长度，避免拆分工序、订单的完整语义 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工序关联信息，避免相邻分块出现语义断裂 |
| 相似度阈值 | 0.72–0.78 | 过滤低关联的排程异常、物料数据，保留核心业务匹配结果 |
| 单次搜索上限 | 前 8 条 | 生产数据关联度较高，少量高匹配结果即可覆盖业务需求，避免冗余信息干扰 |
| `maxToken` | 4096 token | 适配FastGPT v4.17.0内置嵌入模型的输入上限，避免超出处理范围 |
| `defaultToken` | 200 token | 保留基础业务字段的语义编码长度，兼顾检索精度与处理效率 |

## 容易做错的三处
-  文档索引长时间未完成。现象为界面显示索引进度停滞超过30分钟，日志返回分块处理超时。原因是未根据生产排程文档的长文本特征调整分块长度，导致单分块token超出模型上限，反复重试触发超时。
-  嵌入模型匹配偏差。现象为检索工单信息时返回大量不相关的设备班次记录，或无法准确匹配交期变更单的核心内容。原因是未正确配置`defaultToken`长度，导致结构化业务字段的语义编码出现偏差，或未适配业务场景的嵌入模型参数。
-  增强索引配置后检索精度未提升。现象为开启增强索引后，检索排程变更单的结果无明显优化。原因是未将增强索引的关联范围限定在同订单、同工序的文档内，导致跨无关业务的冗余关联被引入，反而干扰检索结果。

## 怎么确认配好了
-  上传一份典型的周日排产表文档，查看分块预览界面，确认分块长度符合设定范围，且工序、订单信息未被拆分断裂。
-  发起一次工单查询，检查检索结果的相似度分值，确认分值落在设定的阈值区间内。
-  模拟一次异常插单的文档更新，查看索引任务的完成时长，确认未出现长时间停滞。
-  开启增强索引后，再次查询同一排程相关的问题，对比检索结果的关联度，确认结果更聚焦于目标业务场景。
