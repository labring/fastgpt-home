# 生产计划与车间排程的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来源涵盖ERP订单与库存、BOM清单、工艺路线、设备产能、人员班次、在制品库存及供应商到货信息。日常处理的文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单。数据更新频率为每日、每周，或随订单、异常情况触发更新。文档字段包含工序编号、产能单位、交期日期、物料编码、库存数量等，部分字段需匹配跨部门的协同数据格式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源分散的数据来源要求多轮对话需逐步引导用户明确具体文档类型与查询范围，避免跨数据源的无效匹配。非固定更新频率意味着提示词需支持动态调用最新的订单、排产或异常数据，需在对话流程中加入数据时间范围的确认环节。跨部门协同的字段格式差异，要求对话环节预设基础字段校验规则，减少因格式不匹配导致的查询偏差。同时，该品类需处理工序、产能等细分维度，多轮对话需支持逐步拆解复杂需求，例如先确认统计周期，再明确需汇总的资源类型。

FastGPT v4.17.0 版本下的配置需遵循以下规则：
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 对话上下文窗口 | 前 10 轮对话或 8000–12000 字符 | 需容纳多轮生产计划、排程相关的长文本交互，避免关键上下文丢失 |
| `variables` 预设变量 | 包含统计周期、文档类型、资源类型的固定选项 | 快速引导用户明确查询范围，减少无效交互 |
| `messages` 初始提示词 | 预设包含数据来源说明、字段校验规则的开场话术 | 对齐该品类的文档与数据特征，降低用户输入偏差 |
| `chatId` 绑定规则 | 绑定至对应车间或生产计划组的专属索引 | 确保对话仅调用该组的台账与排程数据，避免跨组数据混淆 |
| 单次查询返回上限 | 前 3 条匹配文档 | 适配工单、排程表的单条数据量，避免返回过多冗余信息 |
| 上下文超时时间 | 600 秒 | 给足跨部门数据协同的查询与整理时间 |

## 容易做错的三处
- 对话界面显示404 status code（no body）。原因是未正确绑定生产计划与车间排程的专属索引，或模型调用链路中存在未配置的数据源权限。
- 对话开场白未预设多个可选问题。原因是未在`messages`初始提示词中加入引导性的预设选项，导致用户需自行拆解复杂的台账汇总需求。
- 刷新页面后弹出“检测到没有可用的索引模型”提示。原因是索引模型的绑定配置未持久化保存，或后台索引更新任务出现异常中断。

## 怎么确认配好了
- 发起测试对话，输入预设的查询需求，确认开场白显示预设的多个可选问题。
- 查看对话返回结果，确认结果附带对应文档的来源元数据，可追溯至工单或排产表等原始文档。
- 刷新对话页面，确认未弹出“检测到没有可用的索引模型”提示，且会话绑定的索引信息未丢失。
- 模拟包含异常参数的查询请求，确认对话流程会引导用户修正或补充必要的查询信息。
