# 生产计划与车间排程的生产台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据通常来自ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。日常处理的文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单。数据更新节奏为每日、每周，或随订单、异常情况实时触发。文档字段包含订单编号、物料编码、工序工时、设备编号、班次时段、在制品数量等，单位涉及件、小时、台、天等。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据特征要求检索环节需适配不同格式的文档字段，避免因字段不匹配导致召回结果偏差。高频更新的特性要求召回逻辑需支持实时或准实时同步最新的排程、工单与异常数据，确保检索结果贴合当前生产状态。多样的文档类型覆盖结构化表单与非结构化说明，需针对性调整检索匹配规则，优先召回与生产计划、资源约束强相关的内容。同时，生产排程的核心诉求是精准匹配工序、设备与物料信息，检索召回的结果需严格关联当前工单的具体参数，避免无关数据干扰排程决策。

## 配置怎么定
FastGPT v4.17.0 版本中，可通过以下配置项调整生产计划与车间排程场景下的知识库检索与召回逻辑：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 匹配生产计划的精准字段关联需求，避免召回低相关的非排程类文档 |
| `limit` | 前8条 | 控制单次召回的结果数量，适配生产台账汇总的有限上下文长度要求 |
| `searchMode` | hybrid | 结合关键词与语义检索，覆盖结构化工单字段与非结构化排程说明 |
| `usingReRank` | 开启 | 对召回结果二次排序，优先保留与当前排程任务强相关的内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展检索关键词，覆盖工单编号、物料编码等核心字段的同义表述 |
| `collectionIds` | 绑定生产计划与车间排程专属数据集 | 限定检索范围，避免混入其他品类的非生产数据 |

## 容易做错的三处
-  部署后检索时持续出现`slow operation xxxxms`日志。原因是未限定检索的数据集范围，导致系统遍历全量知识库文件，超出MongoDB响应阈值。
-  部分文件未生成问答对直接写入原文。原因是未针对结构化的排程表、工单设置专属的分块规则，系统无法识别结构化字段的语义边界。
-  检索时返回`insufficient_quota 当前分组上游负载已饱和，请稍后再试`报错。原因是未配置合理的检索参数，单次召回请求携带过多上下文，触发平台配额限制。

## 怎么确认配好了
-  手动上传一份测试用的工单文档，执行检索后查看召回结果的字段是否与测试文档匹配。
-  查看检索日志，确认`slow operation`报错不再出现，验证数据集范围限定生效。
-  触发一次台账汇总任务，核对召回的文档数量是否符合设定的检索上限要求。
-  提交包含异常排程场景的查询，确认重排功能是否优先召回相关的缺料清单、交期变更单文档。
