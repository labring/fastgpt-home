# 电机与发电机制造的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自电磁设计文档、铜线与绝缘材料批次记录、绕线设备日志、动平衡机数据、电气试验台报告，以及ERP与MES系统。日常文档包含绕组工艺卡、绝缘处理记录、动平衡报告、耐压绝缘测试记录、型式与出厂试验报告。数据按单台电机、每批产品或每次型式变更更新，字段包含匝数、绝缘厚度、测试电压、温升数值等，附带对应设备编号与生产批次号。

## 这些特征在「向量模型与索引」这一环带来什么约束
单台或批次级的高频更新要求索引支持增量同步，避免全量重建占用过多计算资源。多类型文档的混合存储需要索引区分工艺类、测试类数据的字段权重，绕组匝数、绝缘厚度等数值型字段需适配向量模型的数值编码逻辑。型式变更带来的文档结构调整，要求索引支持动态字段适配，无需重新构建全量向量库。不同设备日志与批次的关联需求，要求向量检索时需同步关联批次维度过滤，缩小检索范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配绕组工艺卡、耐压测试报告的单页内容长度，避免单块包含跨工序的无关信息 |
| 重叠长度 | 100–150 字符 | 保留绕组匝数、生产批次号等关键关联字段的上下文，防止分块断裂导致检索丢失核心参数 |
| 相似度阈值 | 0.72–0.80 | 过滤低匹配度的非相关测试记录，精准召回同批次、同工序的有效业务数据 |
| 单次搜索上限 | 前 8 条 | 平衡检索效率与召回完整性，覆盖同批次多台产品的测试与工艺数据 |
| `defaultToken` | 2000 token | 适配单份试验报告的向量编码长度，避免截断匝数、测试电压等核心参数 |
| `maxToken` | 4000 token | 控制汇总报告生成时的上下文总长度，符合大模型的输入长度限制 |

## 容易做错的三处
- 现象：向量模型配置完成后，执行入库任务提示「无可用渠道」或向量同步状态显示失败。原因：未将embedding模型权限绑定到对应业务分组，仅在default分组配置了模型访问权限。
- 现象：检索结果包含大量无关的通用机械文档，未精准召回电机制造的绕组、测试类数据。原因：未针对电机制造的专属字段（如匝数、绝缘厚度）配置向量索引，未开启批次维度的过滤规则。
- 现象：检索任务耗时过长，页面出现超时提示。原因：分块长度设置超过1500字符，或单次搜索上限配置超过10条，导致向量库扫描与重排计算量过大。

## 怎么确认配好了
- 上传一份完整的绕组工艺卡与耐压测试报告，执行向量入库操作，查看任务日志显示入库成功且无内容截断提示。
- 输入「2024年第03批次电机的绕组匝数是否符合工艺要求」，查看检索结果包含对应批次的工艺卡与测试记录，且无无关文档混入。
- 调整相似度阈值至0.75，验证检索结果的匹配度符合业务预期，无过多低匹配度的无效条目。
- 确认当前使用FastGPT v4.17.0版本，查看向量库监控面板，确认增量同步任务的执行频率与单台/批次更新节奏匹配。
