# 电机与发电机制造的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自电磁设计文档、铜线与绝缘材料批次记录、绕线设备运行日志、平衡机检测数据、电气试验台报告，以及ERP/MES系统的生产工单。数据按单台电机或每批发电机更新，每次工艺型式变更时同步更新。日常文档包含绕组工艺卡、绝缘处理记录、动平衡报告、耐压绝缘测试记录、型式与出厂试验报告，核心字段含绕组匝数、浸漆烘干温度、动平衡剩余不平衡量、耐压测试电压值，单位覆盖匝、摄氏度、克·厘米、千伏等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
单台/单批数据的强绑定特性要求对话需通过`chatId`关联对应批次的台账上下文，避免跨批次数据混淆。多类型专业文档的字段差异与专业单位要求，提示词需明确指定不同文档的提取规则与单位匹配逻辑。高频更新的分散数据源会导致上下文长度快速膨胀，需限制对话历史的有效范围，防止模型调用冗余数据。专业测试数据的精度要求，需在提示词中明确异常值的判定维度，避免模糊匹配导致的错误结论。

## 配置怎么定
本页面的配置示例基于FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 单台电机/发电机的生产工单编号 | 绑定单批次专属台账上下文，避免跨批次数据混淆 |
| `messages` | 仅传递当前批次的对话历史与对应台账文档 | 避免引入无关批次的上下文，确保模型调用数据的精准性 |
| 最大上下文长度 | 8000–12000 token | 控制对话历史与文档的总长度，适配专业数据的处理负载 |
| `variables` | 预设绕组匝数合格范围、耐压测试合格电压区间 | 将业务规则固化为可复用变量，简化提示词的规则描述 |
| 单次搜索上限 | 前4条匹配文档 | 过滤非核心的历史记录，聚焦当前批次的有效生产数据 |
| 超时时间 | 600秒 | 避免长时间等待导致的对话中断，匹配专业数据的搜索与计算耗时 |

## 容易做错的三处
- 现象：对话发起后长时间无响应，界面持续显示“正在搜索知识库”且无结果返回。原因：未通过`chatId`绑定单批次台账，导致搜索范围覆盖全量历史数据，超出系统负载阈值。
- 现象：模型无法关联上一轮对话的上下文，无法延续当前批次的台账分析。原因：未正确配置`messages`参数的上下文传递规则，或最大上下文长度设置过小，截断了有效对话历史。
- 现象：生成的报告字段格式混乱，未匹配业务文档的单位与精度要求。原因：提示词未明确指定专业字段的单位与取值范围，未通过`variables`固化业务规则。

## 怎么确认配好了
- 发起针对单台电机绕组匝数的提问，核对模型返回的结果是否匹配该工单的专属台账数据。
- 发起两轮连续提问，核对模型是否能关联上一轮的提问上下文，延续当前批次的分析逻辑。
- 触发生产台账汇总报告的生成请求，核对输出的字段是否包含预设的专业术语与单位，格式符合业务要求。
- 模拟多并发的对话请求，观察系统响应是否稳定，无异常报错。
