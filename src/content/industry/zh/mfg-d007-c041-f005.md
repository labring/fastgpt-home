# 电镀与化学表面处理的生产台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
该品类的核心数据来自电镀厂、电子连接器与五金件表面处理车间的日常生产与合规记录，包含槽液分析记录、工艺参数卡、挂具使用记录、膜厚与附着力检测报告、危废管理台账、在线水质监测记录。数据来源覆盖客户表面处理规范、槽液化验结果、整流器运行数据、车间在线水质监测设备、危废存储台账。数据更新频率随生产节奏调整，包括每槽次更新的挂具与膜厚数据、每班更新的槽液浓度与温度数据、按固定监测周期更新的废水与危废记录。数据字段包含槽液浓度（单位g/L）、整流电流（单位A）、膜厚（单位μm）、废水重金属含量（单位mg/L）等专业参数。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的多源异构数据、高频更新节奏与专业参数特征，对工具调用与插件配置带来多重约束。多来源的生产与合规数据需要插件支持跨系统拉取，无法仅依赖单一数据源的通用调用逻辑。高频的槽次与班次更新要求工具调用具备实时性，需匹配生产节奏的触发时机，避免数据滞后影响台账汇总。专业参数的固定单位与字段名称，要求插件配置严格的参数映射规则，无法直接使用通用字段模板。危废与废水数据的合规属性，要求工具调用过程中保留完整的溯源记录，确保生成的报告符合生产规范。

## 配置怎么定
本配置基于FastGPT v4.17.0版本完成。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `"auto"` | 适配多源生产数据的自动路由，无需手动指定调用工具 |
| `functionCall` | 开启参数校验 | 匹配电镀专业参数的单位与字段名称，避免格式错误 |
| 工具调用超时设置 | `300 秒` | 匹配槽液数据每班更新的周期，避免因数据拉取延迟导致汇总失败 |
| 批量拉取数据上限 | `前 20 条` | 覆盖单次班次的典型槽次数量，避免拉取过多数据导致超时 |
| 参数映射规则 | 按槽液浓度g/L、膜厚μm匹配字段 | 贴合该品类数据的专业单位与字段定义 |
| 错误重试次数 | `3 次` | 应对在线水质监测数据的临时波动，保障数据拉取成功率 |

## 容易做错的三处
- 现象：调用插件返回`{"result": "Failed to get the VQD for query"}`，原因：未配置电镀专业术语的字段映射，导致工具无法识别槽液浓度、膜厚等专属关键词，无法完成参数匹配。
- 现象：返回`400 InternalError.Algo.InvalidParameter`错误，原因：传入的参数单位不匹配，例如将膜厚的μm误写为mm，未按品类数据的专业单位完成校验。
- 现象：对话应用无法正常对接集成插件，原因：未正确配置`toolChoice`为自动模式，仅开启了手动调用，无法自动触发多源数据的拉取与汇总。

## 怎么确认配好了
- 发起包含槽液浓度查询的测试请求，核对工具返回的参数是否包含g/L单位的数值，确认字段映射生效。
- 模拟单次槽次更新的触发场景，检查工具是否在`300 秒`内完成数据拉取与台账汇总，确认超时设置合理。
- 传入不符合单位的参数（例如将膜厚参数写为“10mm”），确认触发参数校验报错，确认`functionCall`的校验功能正常。
- 查看插件运行日志，确认每次调用都完整记录了数据来源与更新时间，确认合规溯源配置生效。
