# 电镀与化学表面处理的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
该品类的日常数据包含槽液分析记录、工艺参数卡、挂具记录、膜厚与附着力报告、危废台账、废水监测记录。数据来源覆盖客户表面处理规范、槽液化验结果、整流器运行数据、在线水质监测记录与危废管理台账，更新频率为每槽次、每班或按固定监测周期要求。单份台账数据包含槽号、药剂浓度、温度、挂具编号、膜厚数值、危废产生量等结构化字段，部分检测报告为格式化表格形式。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散在化验、整流器、在线监测、危废管理等多个系统中，要求模型接入支持多源数据的拉取与整合；高频的更新频率意味着模型调用需适配实时或近实时的台账汇总需求，不能存在过长的等待延迟；丰富的结构化字段与多份报告的组合，要求模型上下文容量需覆盖完整的台账数据，避免内容截断；同时该品类的出错后果直接关联生产返工与环保处罚，要求模型调用的稳定性与数据准确性有严格保障，需通过统一的代理管理密钥与调用权限。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 该品类单批次台账包含多份槽液记录、检测报告与危废数据，需容纳完整的结构化内容 |
| `maxTokens` | 2000–3000 token | 生产报告需涵盖工艺参数、膜厚结果与环保数据，输出长度需匹配汇总需求 |
| `quoteMaxToken` | 1000–1500 token | 用于提取单份检测报告的核心内容，避免冗余数据占用上下文 |
| `temperature` | 0.1–0.3 | 工艺与环保数据汇总需保持严谨，避免生成非结构化的偏差内容 |
| `AIPROXY_API_ENDPOINT` | 填写OneAPI部署的专属接入地址 | 通过代理统一管理多模型的调用密钥，适配该品类多源数据的模型调用需求 |
| `AIPROXY_API_TOKEN` | 填写OneAPI生成的对应模型密钥 | 确保FastGPT与OneAPI的调用权限匹配，避免密钥不匹配导致的调用失败 |
| 工作流/API 工具选择配置 | auto | 自动调用工具完成多源台账数据的拼接与格式整理，适配分散的数据源结构 |

## 容易做错的三处
- 现象：重排序模型测试时弹出“没有可用模型”报错，其他平台配置可正常调用。原因：未在OneAPI中完成重排序模型的API密钥配置，或FastGPT中未关联该模型的代理密钥。
- 现象：填入OneAPI令牌密钥后，模型调用返回空结果。原因：未在FastGPT的模型配置中正确匹配`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的对应关系，或密钥权限未开放对应模型调用。
- 现象：生成的生产报告遗漏部分膜厚或危废数据。原因：`maxContext`取值过小，未完整加载多份检测报告的总长度，导致部分数据被截断。

## 怎么确认配好了
- 登录FastGPT后台，进入模型配置页面，核对`AIPROXY_API_ENDPOINT`与OneAPI的部署地址一致，`AIPROXY_API_TOKEN`与OneAPI生成的密钥匹配。
- 上传单批次的槽液分析记录与膜厚报告，触发模型调用，检查返回结果是否包含所有上传数据的字段内容。
- 启动重排序模型测试，确认无“没有可用模型”报错，且返回的排序结果符合台账数据的关联逻辑。
- 查看模型调用日志，确认`maxContext`与`maxTokens`的实际使用值未超过配置上限，无数据截断提示，且调用耗时不超过60秒。
