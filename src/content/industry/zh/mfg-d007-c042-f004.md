# 石油炼制的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
石油炼制的生产台账数据来源包括DCS/APC控制系统、LIMS实验室信息管理系统、罐区计量系统、原油评价数据库、设备管理系统与能源管理系统。数据更新节奏分为实时、每班、每日三类，日常覆盖操作规程、生产方案、物料平衡表、馏出口质量报告、联锁台账、交接班记录、变更管理文件等文档。数据字段涵盖装置负荷、物料流量、产品馏分、化验指标、设备运行状态等，对应单位包含立方米每小时、摄氏度、吨、千克每立方米等。

## 这些特征在「工作流编排」这一环带来什么约束
多数据源的差异化更新节奏，要求工作流支持按实时、每班、每日分别配置节点触发时机，避免提前拉取未更新的数据。多源异构的台账文档结构差异较大，要求工作流通过`variables`配置适配不同数据源的字段格式，确保数据能被正确解析。多套连续装置通过物流与能源网络耦合，要求工作流设置跨装置的物料平衡校验节点，避免单装置数据偏差引发整体逻辑错误。数据波动与出错后果严重，要求工作流配置失败重试机制与异常告警节点，保障流程稳定性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 变量配置 | 按数据源类型拆分`variables`，对应原油评价、DCS数据等专属字段 | 适配多源异构台账的字段差异，避免数据解析错误 |
| 节点触发条件 | 按`nodeId`绑定对应数据源的更新节点 | 匹配实时、每班、每日的差异化更新节奏 |
| 问题优化组件位置 | 放在数据拉取节点之后 | 先清洗原始台账的冗余与异常数据，再执行后续汇总 |
| 最大上下文长度 | 8000–12000 token | 容纳多装置的物料平衡表、交接班记录等长文档内容 |
| 失败重试次数 | 2–3次，间隔60秒 | 应对DCS临时通信波动、系统临时卡顿等异常场景 |
| 并行拉取上限 | 前6个节点并行 | 匹配炼油企业常见的装置数量规模，避免资源过载 |

## 容易做错的三处
- 工作流对话显示失败，但模型后台有响应日志。原因是未通过`variables`配置适配炼油台账的多字段格式，导致模型输出无法匹配下游汇总逻辑。
- 智能体运行报错提示字段为空。原因是未按`nodeId`绑定数据源的更新节点，导致拉取的罐区计量数据未完成更新就进入汇总环节。
- 提示词未按节点顺序执行。原因是未正确设置节点间的依赖关系，导致问题优化组件在数据拉取前运行，无法有效清洗原始台账数据。

## 怎么确认配好了
- 触发工作流，查看各数据源节点的拉取日志，确认对应字段均有符合预期的返回数据。
- 运行问题优化组件，检查原始台账数据的冗余字段、异常值已被清理。
- 模拟数据波动场景，验证失败重试机制触发后流程可恢复正常运行。
- 核对最终生成的报告字段，与原始台账的字段单位保持一致。
