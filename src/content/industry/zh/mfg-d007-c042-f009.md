# 石油炼制的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
数据来源涵盖DCS/APC控制系统、LIMS实验室信息管理系统、罐区计量系统、原油评价数据库、设备管理系统与能源管理系统。更新节奏包含实时、每班、每日三类。日常文档包含操作规程、生产方案、物料平衡表、馏出口质量报告、联锁台账、交接班记录、变更管理文件。数据字段包含工艺参数、物料流量、产品质量指标、设备状态、能源消耗等，对应单位涉及吨/小时、立方米、ppm、kg/m³等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入环节支持适配不同系统的输出格式，避免数据解析报错。不同更新节奏的台账数据，需要配置对应触发频率的同步任务，保障实时数据及时接入、每班与每日报表按时汇总。多样的文档类型要求模型支持结构化表格、半结构化记录与纯文本的混合处理。多样的字段与单位要求模型具备基础的单位识别与转换能力，避免跨系统数据计算偏差。多装置耦合的业务逻辑要求模型能够关联跨系统的台账条目，保障汇总报告的逻辑完整性。

## 配置怎么定
本文档适配 FastGPT v4.17.0 版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配炼油台账多源数据的上下文长度需求，避免截断关键工艺参数与跨装置关联记录 |
| `maxTokens` | 4000 token | 控制单份报告生成的输出长度，适配每班/每日汇总报表的内容规模 |
| `quoteMaxToken` | 1500 token | 限定引用的原始台账数据长度，保障生成报告时引用内容完整且不冗余 |
| `temperature` | 0.2–0.4 | 降低生成随机性，保障工艺参数、物料流量等数值类内容的准确性 |
| `AIPROXY_API_ENDPOINT` | 按企业实际部署的代理地址填写 | 适配内部网络环境，解决外部API访问限制问题 |
| `AIPROXY_API_TOKEN` | 按分配的专属密钥填写 | 保障模型调用的身份合法性，避免未授权访问 |

## 容易做错的三处
- 现象：添加第三方模型渠道时显示渠道不可用，即使在独立代理工具中测试通过。原因：未在FastGPT配置中正确填写`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或代理地址未开放企业内部网络访问权限。
- 现象：调用模型生成报告时返回“当前分组无可用渠道”的报错，附带指定request id。原因：未将配置好的模型渠道绑定至对应业务分组，或渠道密钥过期、配额耗尽。
- 现象：生成的物料平衡报告中出现跨装置数据关联错误或单位混乱。原因：未调整`maxContext`参数至适配多装置台账的长度，导致原始关联数据被截断，无法识别单位转换规则。

## 怎么确认配好了
- 执行模型渠道自带的测试功能，查看返回结果，根据测试结果调整`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容。
- 导入一份典型的炼油台账样本，触发汇总报告生成，检查生成内容是否包含完整的工艺参数、物料流量与质量指标。
- 查看模型调用日志，确认上下文长度与输出token数未超出配置范围，根据日志调整`maxContext`与`maxTokens`的取值。
- 模拟跨装置数据关联场景，验证生成的报告是否能正确匹配多系统的台账条目，根据验证结果调整上下文配置。
