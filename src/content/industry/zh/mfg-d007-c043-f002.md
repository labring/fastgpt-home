# 精细化工间歇合成的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类主体为涂料、树脂、助剂、农化中间体和专用化学品企业，日常产生的文档包括批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据来源涵盖配方与工艺库、原料批次信息、反应釜DCS系统、称量系统、LIMS系统及仓储系统，更新频率为每批生产或每个关键步骤触发。数据结构随生产步骤动态变化，包含批次号、原料批号、反应温度、投料量、时间戳等字段，且因多品种、按批次切换生产的特点，不同批次的文档字段存在差异，同时涉及配方保密与清洗确认等敏感信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。首先，多源异构的数据来源要求索引支持跨系统数据的统一向量映射，避免因数据格式差异导致的向量偏差。其次，按批次与关键步骤的高频更新，要求索引具备快速增量更新能力，避免全量重建带来的性能损耗。再者，动态变化的文档结构与敏感字段，要求向量分块时需保留关键业务标识，同时对敏感内容做合规处理。最后，多品种切换带来的文档差异，要求索引的召回规则需适配不同批次的文档特征，避免跨品类数据的误匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类单份文档的平均长度，平衡向量表征精度与索引效率 |
| 重叠长度 | 100–200 字符 | 保留跨分块的关键业务关联信息，避免因分块断裂丢失投料顺序、反应阶段等关键线索 |
| `defaultToken` | 1024 | 匹配该品类常用embedding模型的输入token上限，确保单分块内容完整嵌入 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的历史批次数据，适配多品种切换后的召回精度要求 |
| 单次搜索上限 | 前 5 条 | 聚焦最相关的生产记录，避免冗余数据干扰台账汇总逻辑 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 使用chunk模式调用pushdata API上传生产台账后，长期显示索引中未完成。原因是未根据该品类按批次拆分的文档粒度调整分块参数，导致分块数量超出系统默认处理上限，触发索引排队。
- 控制台返回“该令牌无权使用模型”报错，无法生成向量。原因是未在FastGPT中配置对应embedding模型的合法密钥，或选择了未授权的模型如text-embedding-3-large，导致调用失败。
- 向量召回结果包含无关批次的生产记录，台账汇总出现错误。原因是未根据该品类多品种切换的特点调整相似度阈值，导致阈值设置过低，误匹配其他批次的非相关数据。

## 怎么确认配好了
- 登录FastGPT后台，检查向量模型配置项是否选择了目标模型，如bce-embedding-v1，且密钥配置正确。
- 上传单份批次文档后，查看分块预览，确认分块长度、重叠长度符合预设参数，无内容截断情况。
- 执行台账汇总测试，检查召回结果的批次号、原料信息与上传的原始文档一致，无无关数据混入。
- 查看系统日志，确认无索引排队、模型权限报错等异常记录。
