# 精细化工间歇合成的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自配方与工艺库、原料批次、反应釜DCS、称量系统、LIMS、仓储系统，日常文档包含批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据按每批、每个关键步骤更新，包含批次号、原料批次标识、投料量、反应温度与时长、检验结果、偏差记录等字段，字段单位随各系统定义，不同批次的文档结构存在细微差异，且涉及配方保密内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类多批次切换、数据来源异构且更新频繁的特征，对模型接入与配置带来多重约束。首先，多份分散的系统数据需要统一接入，需配置适配多源异构数据的工具调用规则；其次，每批数据的保密要求需限制数据流出范围，需配置内网代理与数据脱敏规则；第三，按批次更新的特性要求上下文需按批次隔离，避免跨批次数据混淆；第四，关键步骤的实时数据需适配高频更新的接入频率，平衡响应延迟与数据时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 容纳单批次全部台账文档的上下文，避免截断关键投料、反应参数等核心信息 |
| `maxTokens` | `4000–6000 token` | 平衡单批次报告的输出完整性与响应速度，适配台账汇总的内容长度 |
| `temperature` | `0.1–0.3` | 保障台账汇总的准确性，降低虚构内容生成概率，符合生产数据的严谨性要求 |
| 工作流/API 工具选择配置 | `auto` | 自动判断是否触发数据库查询、系统调用等工具，适配多源数据的聚合需求 |
| `quoteMaxToken` | `2000–3000 token` | 保留足够的数据库原文片段，实现类似RAG知识库的引用效果 |
| `AIPROXY_API_ENDPOINT` | 企业内部专用代理地址 | 适配内网部署环境，保障配方等保密数据不流出企业网络 |
| `AIPROXY_API_TOKEN` | 企业分配的专属访问密钥 | 验证模型调用权限，保障接入安全 |

## 容易做错的三处
- 现象：Function CALL调用数据库后，返回结果未包含原始数据库的原文片段，仅展示汇总内容。原因：未配置`quoteMaxToken`参数，或取值过小导致原始数据片段被截断。
- 现象：渠道配置列表中无法找到指定的新版模型版本，无法完成模型接入。原因：未通过`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置自定义模型渠道，仅依赖内置的固定渠道列表。
- 现象：多轮对话中出现跨批次的台账数据混淆，不同批次的投料、反应参数被混合展示。原因：未按批次维度划分上下文范围，或`maxContext`参数未限制单批次上下文的最大长度。

## 怎么确认配好了
- 发起单批次台账的汇总请求，检查返回结果是否覆盖所有要求的文档字段，如投料量、反应参数、偏差记录等。
- 调用Function CALL工具查询指定数据库表，确认返回结果中包含原始数据库的原文片段，符合引用要求。
- 发起两轮连续的跨批次对话，验证上下文仅保留当前批次的相关数据，无其他批次的冗余信息。
- 查看FastGPT v4.17.0的模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无网络连接报错。
