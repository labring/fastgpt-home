# 纸浆造纸的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自制浆造纸企业的备料、制浆、抄纸、质量与能源部门，包含配浆单、打浆记录、纸机运行记录、在线质量曲线、实验室报告、断纸与换品记录等文档。数据来源覆盖木浆废纸批次、DCS/QCS系统、纸机在线测量设备、实验室、能源和水处理系统，更新节奏涵盖实时、每班、每卷三个层级，单条记录包含投料参数、运行数值、检测指标等字段，部分字段带有明确的物理单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据更新节奏覆盖实时、每班、每卷，要求索引支持增量入库与批量入库任务结合的模式。多来源的文档包含不同物理单位的字段，分块时需保留同业务场景下的上下文关联，避免拆分跨业务逻辑的记录。单卷纸的生产记录为连续时序数据，索引需按生产批次建立关联维度，防止不同批次的生产数据混淆。同时单条记录的字段数量较多，向量建模时需优先保留影响生产质量的核心字段，避免冗余特征干扰匹配精度。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配单条生产记录的完整业务逻辑，避免拆分关键投料或运行参数 |
| 重叠长度 | 100–150 字符 | 保留跨分块的时序关联，防止连续生产记录的上下文断裂 |
| 相似度阈值 | 0.75–0.85 | 匹配生产台账的核心指标，过滤低相关性的历史生产记录 |
| 单次召回上限 | 前 20 条 | 覆盖单班次的典型生产数据量，避免召回过多导致上下文溢出 |
| `defaultToken` | 4096 | 适配生产台账的整体文本长度，确保核心信息完整加载 |
| `maxToken` | 8192 | 支持批量报告生成的上下文需求，容纳多批次的汇总数据 |

## 容易做错的三处
- 批量添加索引时返回400状态码的参数错误提示，无法完成入库。原因是未按生产批次拆分批量任务，将跨班次的记录合并提交，超出了单次入库的有效范围。
- 所有生产文档存入同一索引库后，无法按纸卷批次筛选相关数据。原因是未为索引配置批次维度的元字段，导致检索时无法区分不同生产单元的记录。
- 通过第三方系统管理向量库时出现嵌入向量字段为空的情况。原因是未同步FastGPT生成的标准化向量格式，直接修改或新增字段破坏了向量索引的关联关系。

## 怎么确认配好了
- 提交单条配浆单的入库任务，检查索引生成日志中是否包含正确的浆料投料参数字段。
- 发起生产台账汇总的检索请求，确认召回结果的数量符合单次召回上限的配置。
- 查看向量库的元数据，确认每条记录都关联了对应的生产批次编号。
- 测试批量入库任务，检查是否能按批次完成所有记录的索引创建，无报错返回。
