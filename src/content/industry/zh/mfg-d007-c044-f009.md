# 纸浆造纸的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
通常纸浆造纸企业的生产台账数据来自木浆废纸批次、DCS/QCS系统、纸机在线测量设备、实验室、能源与水处理系统。日常文档包含配浆单、打浆记录、纸机运行记录、在线质量曲线、实验室报告、断纸与换品记录。数据更新节奏涵盖实时、每班、每卷三个层级，不同文档的字段与单位差异明显，例如质量曲线包含克重、水分、厚度的实时采样值，配浆单标注浆料配比与批次号。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的台账数据与差异化的更新节奏，要求模型接入时需适配不同长度的文档片段，避免因上下文容纳不足导致关键数据丢失。实时数据的高频更新要求配置项需支持快速召回最新记录，而跨部门文档的联合检索则需要合理设置上下文与检索token上限。此外，纸浆造纸生产对报告严谨性要求较高，模型参数需兼顾数据准确性与生成效率，避免因参数设置不当导致报告偏差或超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 纸浆造纸台账包含多源实时数据、历史记录与质量曲线，需容纳足够多的上下文片段 |
| `temperature` | 0.2–0.4 | 生产台账报告需保持严谨性，避免生成无关或偏差内容 |
| `quoteMaxToken` | 1500–2000 字符 | 适配单份纸机运行记录、配浆单或实验室报告的长度 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型节点填写 | 适配接入的第三方模型服务 |
| 工作流/API 工具选择配置 | auto | 自动调用文档检索工具获取最新台账数据 |
| `maxTokens` | 2000–3000 token | 满足单份生产汇总报告的生成长度需求 |

## 容易做错的三处
- 知识库搜索耗时超过40秒，界面显示超时提示或日志返回408状态码，原因是`maxContext`设置过小导致检索片段过多，或未配置合理的接口超时限制。
- 生成的报告与网页调试结果不一致，跨平台返回的内容存在字段缺失，原因是未在`quoteMaxToken`中适配多部门文档的联合检索长度，或`toolChoice`未开启自动召回全量台账。
- 使用BAAI/bge-large-zh-v1.5模型时召回结果条数异常，返回的检索条目不足预设数量，原因是未正确匹配`quoteMaxToken`与模型的token限制，或`maxContext`未预留足够的嵌入空间。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本导入单份配浆单与纸机运行记录，触发台账汇总，核对生成内容包含所有必填字段。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`返回的响应时间符合业务实时性要求。
- 调整`temperature`参数，对比不同取值下的报告严谨性，确定适配当前场景的取值区间。
- 测试跨部门数据联合检索，确认`toolChoice`自动召回了备料、制浆、质量部门的所有相关文档。
