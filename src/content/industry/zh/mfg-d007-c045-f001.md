# 纺纱与织造的生产台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据主要来自原纤维检验报告、ERP系统、纺机与织机实时采集数据、条干仪检测结果、验布机记录及订单规格文件。日常台账包含配棉配料单、工艺上机单、设备运转日志、纱线检验单、坯布检验记录与疵点台账。数据更新随每批原料、每班生产及每匹布产出同步完成，字段涵盖纤维指标、纺纱捻度、织造组织参数、疵点类型与位置等，单位涵盖支数、米、克、次等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的数据来源分散，覆盖检验设备、生产系统、ERP等多类终端，且更新随每批原料、每班生产及每匹布产出同步，对接口的触发逻辑提出具体约束。多源数据的格式与字段单位存在差异，接口需预设字段映射规则，确保跨系统数据兼容。高频次的更新需求要求接口支持按需拉取与定时同步结合的模式，同时需兼容结构化台账与非结构化疵点记录等不同类型的数据格式。另外，生产环节的异常数据（如断头、疵点）需实时推送，接口需具备低延迟响应能力。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {企业API密钥}，有效期设为7天` | 适配多系统对接的权限管控，符合企业级接口安全规范 |
| 接口超时设置 | `300–600 秒` | 适配生产数据的批量拉取时长，避免因设备响应延迟导致调用失败 |
| 数据拉取触发方式 | 按批次、班次、匹次触发 | 匹配该品类的数据更新节奏，确保台账数据的实时性 |
| `variables` | 绑定纤维指标、捻度、疵点类型等自定义字段 | 适配该品类台账的专属字段需求，实现精准数据汇总 |
| `responseData` | 返回结构化JSON格式，包含校验通过的台账字段与异常标记 | 便于外部系统直接解析生产台账数据，简化后续报告生成逻辑 |
| 重试策略配置 | 失败后重试2次，间隔60 秒 | 应对纺机设备临时离线的场景，减少接口调用失败率 |

## 容易做错的三处
- 现象：配置HTTP接口时无法添加自定义入参变量，界面提示字段不存在。原因：未提前在`variables`配置项中绑定纺纱、织造专属的自定义字段（如纱线支数、疵点编码），导致系统无法识别非预设参数。
- 现象：接口调用返回状态码401，无法正常拉取生产数据。原因：`Authorization`参数未正确配置Bearer前缀或密钥有效期过期，未匹配企业级接口的权限校验规则。
- 现象：汇总后的生产报告数据缺失疵点记录。原因：未在`responseData`中配置疵点字段的返回规则，或拉取触发方式未覆盖疵点台账的更新节点。

## 怎么确认配好了
- 调用配置完成的HTTP接口，传入单批次原料的测试数据，检查返回的`responseData`是否包含预设的生产台账字段。
- 模拟外部系统的临时离线场景，触发接口调用，确认系统会执行配置的重试逻辑。
- 调整数据拉取的触发节点，验证是否能按配置的规则拉取对应生产环节的台账数据。
- 检查接口的权限配置，确认使用`Authorization`参数发起的请求能通过系统校验。
