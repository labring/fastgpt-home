# 纺纱与织造的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
通常服务于棉纺、化纤纺、机织和针织企业，日常产生配棉或配料单、工艺上机单、设备运转记录、纱线检验、坯布检验、疵点记录等文档。数据来源包括原纤维检验结果、ERP系统、纺机与织机实时数据、条干仪、验布机采集数据、订单规格参数。更新频率随每批原料、每班生产、每匹布产出同步更新，字段涵盖纤维指标、设备运行参数、检验结果、疵点类型与位置等，单位随对应业务环节适配。

## 这些特征在「工作流编排」这一环带来什么约束
多来源的数据接入要求工作流配置多类型输入节点，分别对接ERP、设备传感器与检验系统。高频更新的生产数据要求工作流支持按生产批次、班次或匹数触发执行，避免数据滞后或重复汇总。多样的文档格式需要工作流预设不同的格式解析规则，适配配棉单的文本参数、设备记录的数值数据、检验报告的结构化结果。设备头数多带来的数据体量波动，要求工作流配置可调整的并行处理阈值，适配不同规模的生产台账汇总需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发规则 | 按生产批次、班次或匹数触发 | 匹配数据更新频率，避免滞后或重复汇总 |
| 输入节点配置 | 分别对接ERP、条干仪、验布机的3个独立端口 | 适配多来源的数据接入需求 |
| 超时阈值 | 600 秒 | 适配设备数据采集的延迟波动 |
| `variables` 绑定 | 关联检验结果、设备参数、订单规格字段 | 确保工作流内数据准确传递与引用 |
| 错误重试次数 | 3 次 | 应对设备数据临时中断的异常场景 |
| `nodeId` 配置 | 绑定台账汇总与报告生成节点的唯一标识 | 确保工作流节点调用精准无误 |

## 容易做错的三处
- 工作流中代码运行结果无法传入AI模型，AI调用时提示`chat:ai_input_is_e`报错。原因是未通过`variables`配置项将代码节点的输出结果绑定到AI输入参数，导致模型无法获取有效输入内容。
- 使用数据库连接插件对接PostgreSQL时，工作流校验失败，界面提示“工作流校验失败，请检查是否缺失、缺值，连线是否正常”。原因是未正确填写数据库连接的必填配置项，或节点间的数据流转连线未覆盖完整链路，导致系统无法识别有效连接配置。
- 知识库变量引用格式错误，无法正常调用对应数据集。原因是未遵循标准的变量引用规则，错误使用非规范格式模板，导致系统无法识别变量对应的目标内容。

## 怎么确认配好了
- 触发工作流执行一次，查看各输入节点是否成功拉取对应系统的最新数据，核对数据字段与业务文档一致。
- 检查`variables`绑定的参数是否覆盖了所有需要传递的业务字段，确认代码节点或数据节点的输出已正确关联到后续处理节点。
- 运行工作流并查看校验日志，确认数据库连接、节点调用无报错，触发规则与更新频率匹配业务节奏。
- 查看最终生成的台账报告，确认所有业务环节的参数、检验结果、疵点记录均已正确汇总，格式符合预设要求。
