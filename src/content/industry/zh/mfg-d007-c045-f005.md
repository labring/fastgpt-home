# 纺纱与织造的生产台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
这个品类的数据通常来自原纤维检验报告、ERP生产系统、纺机与织机实时采集数据、条干仪、验布机检测结果及订单规格文档。日常生成的文档包括配棉配料单、工艺上机单、设备运转记录、纱线检验单、坯布检验单与疵点台账。数据更新节奏随生产批次、班组班次及每匹布产出同步推进，字段涵盖纤维成分占比、纱线捻度、布面疵点位置与类型、设备开机时长等，部分字段带有明确单位，如千米疵点数、开机小时数。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据特征对工具调用与插件环节带来多重约束。首先数据源分散，涵盖离线纸质记录、工业设备实时采集数据、ERP结构化数据与检验报告，插件需兼容多格式数据源接入，支持跨系统拉取异构信息。其次数据更新粒度细、频率高，随每批原料、班组班次及单匹布产出同步更新，工具调用需适配高频触发与批量数据处理，避免单批次调用超时。此外字段带有特定单位，插件在汇总台账时需自动识别并统一单位格式，防止数据错位。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | `auto` | 适配多工具调用场景，自动匹配台账汇总所需的数据拉取、格式转换工具 |
| 单次工具调用超时 | 600 秒 | 适配单批次多源数据拉取的时长需求，避免因设备数据延迟导致调用失败 |
| 插件返回结果条数 | 前 10 条 | 匹配单班组或单批次生产台账的核心数据量，避免冗余信息干扰汇总 |
| 上下文窗口大小 | 8000 token | 容纳多份工艺单、检验记录的文本内容，满足跨文档关联分析需求 |
| 工作流/API 函数调用配置 | 启用 | 支持精准调用指定工具完成特定字段的台账汇总，如疵点数据统计 |

本文基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 现象：调用markdown转文件插件时，暴露内部端口后出现未授权访问的异常日志。原因：未配置端口访问白名单，导致外部可直接触发文件生成操作。
- 现象：无法查看知识库资料的历史调用日志，或日志列表中对应条目为空。原因：未开启工具调用日志留存配置，或日志留存时长设置不符合高频调用的数据保留需求。
- 现象：使用curl调用FastGPT接口时，返回包含`$schema`前缀字段的格式错误提示。原因：请求体中携带了未被接口支持的`$schema`前缀字段，不符合参数格式规范。

## 怎么确认配好了
- 发起一次单批次生产台账的工具调用请求，检查返回结果中包含配棉比例、纱线捻度、疵点记录等核心字段，且字段单位符合预期。
- 查看插件调用日志，确认多源数据拉取、格式转换等步骤均正常完成，无超时或报错记录。
- 测试markdown转文件插件，确认生成的文件格式正确，且包含汇总后的台账内容，端口访问限制配置生效。
- 调用`functionCall`工具，确认可精准触发指定的统计操作，如单批次疵点数量统计，返回结果与实际生产数据匹配。
