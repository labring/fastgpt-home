# 纺纱与织造的生产台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
该品类的数据主要来自原纤维检验、ERP系统、纺机与织机实时采集数据、条干仪、验布机及订单规格文档。日常生成配棉配料单、工艺上机单、设备运转记录、纱线检验报告、坯布检验记录、疵点台账等文档。数据更新节奏随生产流程推进，每批原料、每班生产、每匹布产出均会生成新数据。数据字段包含原料批次、工艺参数、设备运行时长、检验结果、疵点类型与位置、订单规格等，需按生产环节拆分存储，无统一固定的多字段聚合格式。

## 这些特征在「数据库与运维」这一环带来什么约束
多来源的异构数据需要适配不同格式的写入接口，对数据库的兼容能力提出要求。高频次的更新会带来高并发写入请求，需配置合理的连接池上限避免连接耗尽。不同生产环节的数据关联逻辑复杂，需建立清晰的关联索引，保障台账汇总时的关联查询效率。疵点记录与检验数据的非结构化特征，需预留灵活的字段扩展空间，避免后续新增检验项时频繁修改表结构。同时，数据需按生产批次、时间范围快速检索，需针对常用查询维度建立二级索引。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://dbuser:dbpass@dbhost:5432/spinning_weaving_db?sslmode=disable` | 适配纺纱织造台账的结构化存储需求，支持复杂关联查询与向量扩展 |
| `DB_MAX_LINK` | `20–30` | 匹配每批原料、每班生产的高频写入并发，避免连接池耗尽 |
| `REDIS_URL` | `redis://redispass@redishost:6379/0` | 缓存高频查询的工艺参数、疵点分类数据，降低主数据库负载 |
| `MONGODB_URI` | `mongodb://mongouser:mongopass@mongohost:27017/weaving_logs?authSource=admin` | 存储非结构化的疵点照片、原始检验数据，适配灵活的字段扩展 |

## 容易做错的三处
- 配置数据库连接后无法执行SQL提取结果，原因是未适配纺纱织造台账的多数据源格式，连接字符串未指定对应生产库的实例路径，或未授予用户访问检验数据、设备记录等核心表的权限。
- 数据库连接频繁超时，原因是`DB_MAX_LINK`配置值过低，无法匹配每批原料、每班生产带来的高并发写入请求，导致连接池耗尽。
- 进入pgvector镜像后无法执行SQL命令，原因是未在连接参数中启用vector扩展，或未配置正确的数据库端口与访问白名单，导致镜像内无法访问外部数据库实例。

## 怎么确认配好了
- 执行FastGPT内置的数据库连通性测试工具，验证`PG_URL`、`MONGODB_URI`等配置的连通性，确认无认证或网络错误。
- 插入一条模拟的配棉配料单数据，查询后确认数据写入与读取正常，验证读写权限配置正确。
- 调整`DB_MAX_LINK`配置后，模拟多并发写入请求，确认无连接超时或拒绝错误。
- 查看数据库运行日志，确认无频繁的连接断开或权限报错，验证运维配置的稳定性。
