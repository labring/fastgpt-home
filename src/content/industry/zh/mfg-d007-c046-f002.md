# 肉制品与屠宰加工的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类主体为屠宰场、熟肉与冷冻调理食品企业，日常文档包含动物检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告。数据来源涵盖动物检疫信息、供应商批次、生产追溯系统、温度采集设备、金属检测设备与实验室检测结果。更新频率按生产批次、班组班次执行，冷链温度记录为连续采集。文档字段包含批次号、检疫编号、时间戳、温度数值、菌落总数等，部分文档需关联生物风险标识与生熟分区标签。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据结构要求索引支持文本与数值字段的混合向量编码，单一向量编码适配所有数据类型会导致匹配偏差。高频更新的批次数据需要增量索引机制，确保新生成的台账能快速纳入检索范围。批次与检疫信息的强关联要求索引按批次分组存储，防止跨批次的无关记录被召回。连续采集的温度数据存在大量时序重复项，需通过分块规则避免冗余向量生成。生熟分区的管控需求要求索引支持按分区字段进行过滤检索，缩小召回范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配单批次台账的平均文本长度，避免跨批次信息截断 |
| 重叠长度 | 50–100 字符 | 保留批次关联信息的上下文连续性，防止分块破坏关联逻辑 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的非关联检测记录，提升检索精准度 |
| 单次搜索上限 | 前10条 | 控制单批次检索返回的记录数量，避免上下文过载 |
| `defaultToken` | 8192 | 适配单批次多份台账合并后的总token长度 |
| `maxToken` | 16384 | 预留报告生成阶段的上下文扩展空间 |

## 容易做错的三处
- 现象：控制台返回503错误，提示当前分组default下无text-embedding-v3可用渠道。原因：未在FastGPT v4.17.0中配置对应嵌入模型的渠道密钥，或密钥配置格式不符合要求。
- 现象：检索结果包含跨批次的无关台账记录。原因：未按批次字段配置索引过滤规则，导致召回范围超出目标生产批次。
- 现象：无法在检索测试页直接调整索引匹配规则，需进入知识库内容管理页面配置。原因：沿用旧版本操作逻辑，未适配FastGPT v4.17.0的界面更新。

## 怎么确认配好了
- 查看嵌入服务运行日志，确认无503错误或密钥加载失败的提示。
- 输入单批次的检疫编号作为检索关键词，验证返回的记录仅包含该批次的台账数据。
- 测试单批次多份台账合并后的总token数，确认不超过`maxToken`的设置值。
- 调整相似度阈值，验证检索结果的匹配度符合预设的筛选标准。
