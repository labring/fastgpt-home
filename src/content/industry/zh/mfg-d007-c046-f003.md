# 肉制品与屠宰加工的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
数据来源包括动物检疫信息、供应商批次、生产追溯记录、温度采集数据、金属检测结果、实验室微生物检验报告。日常文档包含检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录。数据按每批、每班或连续温控触发更新，字段包含批次号、检疫编号、温度值、检测结果、时间戳，单位涉及摄氏度、批次编号、检验合格标识等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据按批次、班次更新且包含生物风险相关的检疫、温控记录，多轮对话需固定关联当前生产批次的上下文，避免跨批次数据混淆。提示词需明确限定仅调用该批次的检疫、温度、检测文档，防止混入无关批次数据。连续温控数据的高频更新要求对话上下文能快速加载最新的温度记录，且需限制对话轮次内的数据加载量，避免超时。同时，需在提示词中明确区分生熟加工的分区数据，防止交叉污染相关记录混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前生产批次的唯一标识 | 确保多轮对话仅关联该批次的台账数据，避免跨批次混淆 |
| `messages` | 仅保留当前班次/批次的30条以内对话历史 | 控制上下文加载量，适配高频更新的温控与检测数据，防止超时 |
| `variables` | 传入批次号、检疫编号、加工时段三个核心变量 | 让提示词精准定位对应生产环节的文档，缩小检索范围 |
| 最大上下文 | 800–1200 字符 | 适配该品类单批次台账的平均数据长度，避免加载冗余信息 |
| 单次搜索上限 | 前 3 条 | 优先匹配最相关的检疫、温度、检测记录，减少无关数据干扰 |
| 问题优化 | 开启 | 将用户的口语化查询转换为针对批次台账的精准检索指令，提升匹配精度 |

## 容易做错的三处
- 现象：对话返回的检疫证明相关图片显示不全。原因：提示词未明确指定图片的完整字段名与存储路径，导致仅加载了部分缩略数据。
- 现象：多轮对话超过10分钟未完成响应。原因：未限制`messages`的加载数量，导致加载了过多历史批次的台账数据，超出系统处理上限。
- 现象：模型返回结果末尾出现规则展示符号。原因：未在提示词中明确要求隐藏系统预设的规则说明，导致模型附带输出了配置中的追溯规则内容。

## 怎么确认配好了
- 输入当前生产批次的查询，核对返回的台账数据是否仅包含该批次的检疫、温度、检测记录。
- 发起连续5次相同查询，核对响应时间是否稳定在合理区间，无明显超时。
- 检查返回结果末尾是否无额外的规则展示符号，确认提示词配置生效。
- 上传测试批次的台账数据，核对对话是否能正确关联`variables`中传入的批次号变量。
- 确认当前使用FastGPT v4.17.0版本，确保配置项兼容当前系统版本。
