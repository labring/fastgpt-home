# 肉制品与屠宰加工的生产台账汇总与报告生成：工具调用与插件

## 这个品类的数据长什么样
数据来源包括动物检疫信息、供应商批次、生产追溯、温度采集、金属检测、实验室检验结果。日常文档涵盖检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告。数据更新节奏为每批生产、每班作业更新，冷链温度为连续采集。字段包含批次号、检疫编号、温度值（℃）、检测结果、时间戳、操作人员标识等，部分记录需关联生物安全等级标识。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于需维持原料批次与检疫证明的对应关系，工具调用需保证同批次数据处理处于同一会话上下文，避免信息割裂。连续采集的冷链温度数据频次高，需控制单次调用的数据量与请求间隔，防止接口过载。生熟分区与杀菌温度的严格管控要求，工具调用需校验字段合法性，防止错误数据进入汇总流程。生物风险导致的出错后果严重，需配置失败重试与异常捕获机制，避免不合格原料流入后续环节。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `"function"` | 强制调用预设的台账处理工具，避免自由生成偏离业务需求 |
| `functionCall` | 绑定肉制品专用台账解析函数 | 确保调用逻辑匹配品类的检疫、溯源与温控要求 |
| 会话上下文时长 | 3600 秒 | 覆盖单批次生产的完整周期，保证同批次台账调用处于同一会话 |
| API请求超时时间 | 15–30 秒 | 适配冷链温度等高频采集数据的传输延迟，避免超时中断 |
| 批量调用批次大小 | 前 10 条 | 控制单次调用的数据量，匹配系统单次处理的合理负载 |
| 字段校验规则 | 按检疫编号关联批次号 | 匹配品类的溯源要求，确保数据关联逻辑正确 |

## 容易做错的三处
- 现象：多次API调用无法关联同批次生产台账，返回结果中批次号为空。原因：未配置会话上下文绑定，每次调用生成独立会话，无法保留批次关联信息。
- 现象：HTTP请求组件未携带预设的温度值参数，返回参数错误提示。原因：未在插件配置中绑定台账字段到请求参数，导致采集的数值未正确传递。
- 现象：连续10分钟以上的温控数据调用返回504状态码。原因：单次调用加载了超过系统处理上限的历史温度记录，超出响应阈值。

## 怎么确认配好了
- 发起同批次生产的三次台账调用，检查返回结果是否关联同一检疫编号与批次号。
- 模拟提交一条冷链温度记录，查看HTTP请求日志，确认携带预设的温度值与批次参数。
- 加载10条连续温控记录发起调用，确认请求未触发超时报错。
- 查看工具调用日志，确认每次调用均触发预设的肉制品台账处理函数，未出现自由生成内容。
