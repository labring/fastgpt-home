# 肉制品与屠宰加工的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
该品类的典型主体为屠宰场、熟肉与冷冻调理食品企业，日常台账文档包含检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告。数据来源涵盖动物检疫信息、供应商批次、生产追溯系统、温度采集设备、金属检测设备与实验室检验结果。数据按每批、每班更新，冷链温度记录为连续实时更新，字段包含批次号、检疫编号、温度值、检验时间、检测结果等，部分字段需与对应批次的其他文档关联匹配。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的台账数据需按批次与班次关联，且包含生物检疫、温控等敏感且结构化的信息，要求模型接入配置需保障跨文档的精准关联。连续更新的温控数据需模型支持时序信息的提取与整合，避免混淆不同时段的记录。多类型文档的混合使用，要求配置适配多格式文档的解析与字段标准化。数据更新频率较高，需配置匹配的知识库同步节奏，保障汇总报告的时效性。同时，数据出错会引发产品安全风险，需严格限制模型生成内容的随机性，避免出现批次关联错误或信息遗漏。

## 配置怎么定
本章节配置适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖多批次文档的关联召回需求，避免截断跨批次的检疫、温控等关键关联数据 |
| `temperature` | 0.1–0.3 | 降低生成内容的随机性，保障批次关联、检疫信息匹配等关键环节的准确性 |
| `quoteMaxToken` | 1500–2000 字符 | 保留完整的冷链温度记录、微生物检验报告等长文本细节，避免关键信息被截断 |
| `toolChoice` | auto | 自动适配多类型台账文档的解析与关联任务，无需手动切换工具 |
| `AIPROXY_API_ENDPOINT` | 按本地部署环境填写 | 适配自建模型的接入路径，保障模型调用的连通性 |
| `AIPROXY_API_TOKEN` | 按平台生成的密钥填写 | 完成模型接入的身份验证，保障调用安全 |

## 容易做错的三处
- 知识库回答出现截断，返回内容不完整。原因是`maxContext`或`quoteMaxToken`取值过小，未保留完整的批次关联文档或长时序温控记录。
- 导入台账文档时返回500错误。原因是未适配肉制品台账的专属字段结构，文档解析时无法识别批次号、检疫编号等关键标识。
- 模型接入后无响应，无法生成台账汇总内容。原因是`AIPROXY_API_TOKEN`配置错误，或`AIPROXY_API_ENDPOINT`指向的模型未完成连通验证。

## 怎么确认配好了
- 上传单份检疫证明与对应批次的屠宰记录，核对模型是否能正确关联批次号与检疫编号。
- 输入包含特定温控时段的查询，确认返回结果包含完整的温度采集数据，无异常截断。
- 调用模型生成月度生产台账汇总报告，检查是否自动关联各批次的检验结果与冷链记录。
- 验证`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`的配置，确保能正常调用模型生成基础的台账内容。
