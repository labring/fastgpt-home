# 肉制品与屠宰加工的生产台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
该品类的数据主要来自动物检疫信息、供应商批次记录、生产追溯系统、温度采集设备、金属检测设备与实验室检验结果。日常生成的文档包含检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度记录、微生物检验报告。数据更新按生产批次、每班工作周期推进，冷链温度数据为连续采集更新。数据字段包含批次号、检疫编号、加工环节参数、温度值、检测结果与时间戳，单位涵盖℃、批次编号、标准时间格式等。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据来源分散且包含连续采集的实时冷链温度数据，部署时需配置稳定的数据库连接与足够的存储容量以支撑高频并发读写。数据包含合规性强的检疫、检验文档，部署环节需提前定义统一的字段映射规则，确保不同来源的结构化与非结构化数据可被正确识别与关联。升级过程中需避免中断连续采集的冷链温度数据，需配置支持断点续传的任务机制，同时确保升级后原有批次与检疫信息的关联关系不被破坏。另外，生熟加工分区的记录需单独分类存储，部署时需提前规划数据分区策略，避免数据交叉污染相关的记录混淆。

## 配置怎么定
本配置指南基于FastGPT v4.17.0版本编写，以下配置项适配该品类的生产台账场景：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `200–300 个连接` | 支撑多来源高频数据的并发读写，避免连接耗尽，适配该品类的批量数据导入需求 |
| `PG_URL` | 指向专属PostgreSQL实例，配置连接超时为`60 秒` | 存储批次关联、检疫编号等结构化数据，超时配置适配批量导入时的长连接需求 |
| `REDIS_URL` | 配置为独立Redis实例，内存阈值设为`8 GB` | 缓存连续采集的冷链温度数据与临时任务状态，降低数据库的实时读写压力 |
| `STORAGE_S3_ENDPOINT` | 适配合规云存储或本地对象存储端点 | 存储检疫证明、检验报告等文档类数据，满足该品类的合规存储要求 |
| `ROOT_KEY` | 按部署环境生成强随机字符串 | 管控平台后台权限，避免未授权访问配置与核心生产数据 |

## 容易做错的三处
- 现象：Docker本地部署后每隔数小时出现数据库连接报错，需删除PostgreSQL容器重新部署才可恢复。原因：未配置`DB_MAX_LINK`的合理阈值，高频数据读写导致连接池耗尽，未启用连接自动回收机制。
- 现象：在华为欧拉arm64架构系统部署时，容器启动失败。原因：未使用适配arm64架构的FastGPT镜像，或未配置`PG_URL`对应的arm64兼容数据库实例。
- 现象：尝试直接升级到最新版后，部分历史台账的汇总逻辑异常。原因：未按版本迭代说明执行分步升级，跳过了中间版本的数据库迁移脚本，导致批次数据的关联字段不兼容。

## 怎么确认配好了
- 执行批量导入模拟生产批次数据，检查数据库连接日志无连接耗尽报错，确认`DB_MAX_LINK`配置生效。
- 上传一份检疫证明文档，检查存储路径与`STORAGE_S3_ENDPOINT`配置的存储端点匹配，确认文档可正常读取与关联。
- 启动连续温度数据采集模拟任务，检查Redis缓存中临时任务状态更新正常，确认`REDIS_URL`配置生效。
- 尝试通过未授权的密钥访问平台配置页面，确认无权限访问，验证`ROOT_KEY`配置生效。
