# 计量器具与实验室管理的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来自计量管理系统、外部校准机构证书、标准器数据、LIMS系统及环境监测记录。日常文档包含量具台账、校准计划、校准证书、期间核查记录、试验原始记录、标准物质台账、偏离处置单等。数据更新节奏为按校准周期、每次试验或异常情况触发。字段包含器具编号、校准日期、测量值、不确定度、溯源编号、环境参数等，部分字段需匹配法定计量要求的单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
计量类数据的多源特性要求对话上下文需严格限定在指定业务数据集内，避免无关系统数据干扰。非固定更新频率意味着需支持动态拉取最新校准记录，提示词需适配不同类型的文档结构。字段的法定计量要求决定了提示词必须明确指定校验环节，如溯源链、不确定度复核。数据出错会导致质量判定失效，因此多轮对话需保留完整的上下文用于回溯校验。

## 配置怎么定
本页面基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 前7000–9000 字符 | 计量类单份台账平均长度约1200字符，保留6-7份完整记录用于多轮校验 |
| `variables` 绑定范围 | 仅加载当前会话关联的计量台账、校准证书数据集 | 避免无关系统数据混入对话上下文，确保提示词聚焦业务内容 |
| `chatId` 生成规则 | 按「器具编号+校准周期起始日期」生成 | 确保同器具同校准周期的对话上下文连贯，便于溯源 |
| `messages` 截断规则 | 保留最近10轮对话+3份完整校准记录 | 平衡上下文完整性与响应速度，避免会话超时 |
| 对话超时阈值 | 600 秒 | 校准证书数据拉取和计算需较长时间，避免会话中断 |
| 提示词模板预设 | 固定包含「器具溯源链校验」「不确定度复核」字段要求 | 匹配计量管理的强制审查环节，减少人工补全 |

## 容易做错的三处
- 现象：嵌套工作流中调用表单输入节点时，对话框持续显示，单个工作流调用时正常。原因：未在嵌套配置中关闭「外部调用时隐藏对话框」开关，导致外层工作流未覆盖该设置。
- 现象：提示词配置中`variables`绑定的计量字段为空，生成的报告缺失校准不确定度数据。原因：未在变量配置中指定具体台账字段的映射规则，导致系统无法提取正确数据。
- 现象：尝试在对话框中渲染网页或文生图内容，界面未正常展示。原因：未开启「富文本渲染」开关，且未配置允许的媒体输出类型，不符合计量报告的标准格式要求。

## 怎么确认配好了
- 发起包含「校准证书溯源链」的查询，核对返回结果中是否包含预设的计量字段。
- 切换嵌套工作流与独立工作流模式，检查表单输入节点的对话框显示状态是否符合预期。
- 查看会话日志，确认`chatId`是否按「器具编号+校准周期起始日期」的规则生成。
- 测试超时场景下的会话恢复，确认关联的计量数据是否能正常加载。
