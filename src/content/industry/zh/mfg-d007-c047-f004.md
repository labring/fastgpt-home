# 计量器具与实验室管理的生产台账汇总与报告生成：工作流编排
本文档适配FastGPT v4.17.0版本的工作流编排功能。

## 这个品类的数据长什么样
本品类数据来自计量管理系统、外部校准机构证书、标准器、LIMS、环境监测设备。日常文档包含量具台账、校准计划、校准证书、期间核查记录、试验原始记录、标准物质台账、偏离处置单等。字段包含器具编号、校准日期、测量值、测量不确定度、溯源编号、环境温湿度等，单位涵盖毫米、牛顿、摄氏度等。数据更新按校准周期、单次试验完成或异常事件触发，无固定批量更新节奏。

## 这些特征在「工作流编排」这一环带来什么约束
本品类数据分散多源且格式混合，要求工作流需支持多类型数据源接入节点，适配不同系统的API或文件导入逻辑。日常文档字段多且带专属专业单位，工作流需配置字段映射与单位校验环节，确保汇总数据格式统一。数据更新无固定周期，工作流无法依赖定时触发，需支持按业务事件或手动触发。核心数据需支撑质量判定，工作流需串联溯源校验、结果审查等节点，保障数据合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源接入节点 | 按数据源类型分别配置计量管理系统、LIMS、外部证书解析节点 | 本品类数据来源分散，需适配不同系统的接入格式 |
| 字段映射规则 | 按器具编号、校准日期、测量值、测量不确定度等核心字段建立固定映射 | 日常文档字段多且带专属单位，需统一字段用于汇总 |
| 触发条件配置 | 按校准完成事件、试验提交事件或手动触发 | 数据更新无固定周期，需匹配实际业务触发逻辑 |
| 校验节点逻辑 | 配置溯源链校验、测量不确定度校验环节 | 本品类数据需支撑质量判定，需确保溯源合规与数据准确 |
| 失败重试配置 | 单次重试`3次`，间隔`60秒` | 外部校准证书解析可能因网络波动失败，合理重试降低异常率 |
| 全局变量存储 | 用`variables`参数配置溯源变量池 | 需保留器具溯源链数据用于后续报告关联，`variables`支持跨节点数据复用 |

## 容易做错的三处
- 工作流中问题分类节点识别准确率低，提示词未包含品类专属术语。原因：未结合测量不确定度、溯源编号等专业术语配置提示词，通用模型无法精准识别品类专属字段。
- 工作流无法接入外部MCP插件，节点未完成授权绑定。原因：未在对应节点中配置MCP插件的接入参数，未完成插件与工作流的权限关联。
- 代码运行节点持续不生效，返回空日志或执行超时。原因：代码中未适配计量数据的单位校验逻辑，或未设置合理的超时阈值，导致处理大体积校准证书时阻塞。

## 怎么确认配好了
- 手动触发一次工作流，检查多数据源节点是否能正常拉取量具台账、校准证书等对应数据。
- 查看字段映射节点输出，确认核心字段已完成格式统一与单位匹配。
- 触发异常事件，如手动修改校准日期为过期日期，确认校验节点能拦截异常数据并触发预警。
- 模拟外部接口调用失败场景，确认失败节点按配置的重试次数与间隔执行重试。
