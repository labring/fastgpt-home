# 设备点检与预防维修的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据覆盖制造企业设备部、车间维修班组、公用工程部门的生产支持类文档，包括设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录。数据来源包含EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史、备件库存数据及法定检验信息。更新节奏覆盖每班、日/周/月周期及故障发生时。数据字段包含设备编号、点检时间、点检项状态、维修工单编号、备件编码、库存数量等，对应单位包括小时、件、套等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类数据来源分散且更新节奏多样，要求多轮对话需支持跨数据源的实时数据拉取，提示词需明确指定不同文档的调用规则。多类文档的字段与单位存在差异，对话交互需引导用户明确指定设备编号、时间范围等筛选条件，避免字段混淆。法定检验类文档需固定校验逻辑，提示词需嵌入合规性检查的固定步骤。维修工单与点检记录的关联需对话流程支持逐层追溯，从当前点检异常跳转至对应历史维修记录。跨部门的数据共享需对话支持权限过滤，确保仅对应班组可查看自身负责的设备数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 对话历史保留条数 | 前20条 | 本品类数据更新频繁，过长历史会干扰当前会话的精准性，20条可覆盖最近的点检与维修上下文 |
| 上下文窗口大小 | 8000–12000 token | 适配多类文档的字段长度，避免因内容截断丢失关键设备信息，适配FastGPT v4.17.0版本的窗口限制 |
| `variables` 预设 | 设备编号、点检周期、检验到期时间 | 覆盖本品类核心数据字段，减少用户手动输入频次 |
| `chatId` 绑定 | 绑定车间设备分组 | 确保对话仅调用对应车间的点检与维修数据，避免跨车间数据混淆 |
| 单次对话返回文档数 | 前5条 | 控制返回内容体量，避免信息过载影响理解 |
| 超时设置 | 300秒 | 适配EAM系统的数据拉取延迟，确保完整获取历史维修与点检记录 |

## 容易做错的三处
- 现象：调用对话接口返回400状态码，提示“上下文格式错误”。原因：未按要求将`messages`参数按角色（用户/助手）分层传递，混入了未标记的非结构化数据。
- 现象：调用对话记录接口仅返回10条内容，无法获取全量历史对话。原因：未配置`chatId`对应的全量拉取逻辑，默认仅返回最近会话片段。
- 现象：对话无法调取预设的备件清单知识库内容。原因：未将知识库与当前`chatId`绑定的应用关联，导致会话无法调用指定知识库数据。

## 怎么确认配好了
- 发起包含具体设备编号与点检时间的查询，核对返回结果是否仅包含对应车间的设备相关数据。
- 调用对话记录接口，确认可获取指定`chatId`下的全量历史对话内容。
- 输入包含专业字段的查询，核对返回结果是否准确识别设备异常等级、备件编码等核心字段。
- 触发合规性相关查询，核对返回结果是否包含法定检验的相关校验逻辑。
