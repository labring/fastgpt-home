# 设备点检与预防维修的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自企业EAM/CMMS系统、设备传感采集终端、操作员点检记录、维修历史档案、备件库存台账及法定特种设备检验文件。日常文档包含设备台账、点检表、保养计划、维修工单、故障分析报告、备件清单与特种设备检验记录。数据更新节奏覆盖每班点检、日/周/月定期保养、故障发生即时同步，字段包含设备唯一编号、点检时间、故障类型、备件编码、检验有效期等，单位涉及台、次、小时、天等。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散、格式异构，要求模型接入时需配置多源数据的字段映射规则，确保不同系统的设备台账、点检记录可统一识别。数据更新节奏差异大，需适配每班、定期及故障触发的不同同步触发逻辑，避免冗余或遗漏。文档包含法定检验记录等强时效性内容，需配置针对时间字段的校验逻辑，确保报告中引用的检验信息在有效期内。多文档汇总的场景要求上下文承载能力适配多份工单、点检表的联合分析需求，避免因上下文不足导致分析缺失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配多份点检表、维修工单的联合汇总需求，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 匹配单份生产台账报告的标准生成长度 |
| `quoteMaxToken` | 1500 token | 限制单条源文档引用的长度，确保生成内容可追溯对应点检记录或维修工单 |
| `toolChoice` | auto | 允许模型自主判断是否调用工具查询设备关联的备件库存或检验信息 |
| `temperature` | 0.2–0.4 | 降低生成随机性，保障设备编号、检验有效期等结构化信息的准确性 |
| `AIPROXY_API_TOKEN` | 按实测标定的有效密钥 | 确保接口调用的权限合法性与数据传输安全 |

## 容易做错的三处
- 现象：调用接口返回401未授权错误，或生成内容无法关联设备备件信息。原因：未正确配置`AIPROXY_API_TOKEN`，或密钥权限未覆盖设备台账、备件库存的数据源访问范围。
- 现象：生成的报告中包含过期的特种设备检验记录。原因：未配置针对时间字段的校验逻辑，未限制引用检验记录的有效期范围。
- 现象：接口调用超时，或生成内容被截断。原因：未合理设置`maxContext`或`maxTokens`参数，导致上下文过长超出模型承载上限。

## 怎么确认配好了
- 导入单份点检表与维修工单，触发台账汇总任务，检查生成内容是否包含设备编号、点检时间、故障描述等核心字段。
- 导入包含法定检验记录的文档，触发报告生成，检查生成内容是否对检验有效期进行了关联校验。
- 配置多源数据同步规则，等待对应更新节奏的触发，检查数据源的字段映射是否正确，无缺失或错位。
- 查看FastGPT v4.17.0的接口调试日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置信息已正确加载。
