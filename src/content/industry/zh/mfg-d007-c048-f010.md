# 设备点检与预防维修的生产台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来自制造企业设备部、维修班组、公用工程部门的日常产出与系统录入，涵盖设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录。数据来源包括EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史档案、备件库存数据与法定检验信息，更新频率覆盖每班、日/周/月周期及故障发生即时触发，文档结构包含设备唯一标识、点检项、故障代码、备件型号、检验有效期等字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的文档类型要求检索需支持跨文档字段关联，例如通过设备唯一标识关联点检记录、维修工单与备件清单。高频更新的点检与故障数据要求检索结果需优先返回近期录入的有效内容，避免过时信息干扰决策。特种设备检验记录的法定属性要求检索需识别并优先召回临近有效期的文档，辅助合规检查。同时，维修场景下需快速匹配设备型号、故障代码等精准字段，避免泛化检索返回无关内容，影响维修决策效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | `0.75–0.85` | 设备点检与故障相关的文本语义相似度需维持在合理区间，避免过低返回无关内容或过高遗漏有效维修记录 |
| `limit` | `前8–12条` | 维修场景下需兼顾信息完整性与响应速度，单次召回过多会增加上下文处理负担，过少则无法覆盖多维度维修参考信息 |
| `searchMode` | `mixedRecall` | 设备相关文档包含标准化编号（如设备型号、故障代码）与自然语言描述的故障分析，混合模式可同时匹配结构化字段与语义内容 |
| `usingReRank` | `开启` | 设备故障与点检记录的语义相似度判断易受专业术语干扰，重排可过滤低质量召回结果，提升精准度 |
| `datasetSearchUsingExtensionQuery` | `开启` | 维修场景下可通过扩展原问题（如补充设备型号、故障类型）召回更匹配的历史工单与保养计划，提升检索覆盖度 |
| `collectionIds` | `绑定对应设备管理知识库的集合ID` | 限定检索范围至本品类专属文档，避免混入其他品类的无关数据 |

## 容易做错的三处
- 现象：API上传含中文文件名的知识库文件后，检索时无法匹配到对应文档内容。原因：未正确配置文件名编码参数，导致文件元数据与实际内容关联断裂。
- 现象：检索返回结果条数远低于设定的`limit`值。原因：未开启`datasetSearchUsingExtensionQuery`，且原问题未包含足够的设备专属标识字段，导致召回范围过窄。
- 现象：单次检索耗时超过10秒。原因：未开启`usingReRank`且未限定`collectionIds`，导致检索范围覆盖全平台知识库，增加了计算负载。

## 怎么确认配好了
- 上传含中文文件名的测试文件，通过FastGPT v4.17.0的API检索该文件名关键词，确认可正常返回对应文档内容。
- 设定`similarity`为0.8，检索已知的设备故障代码，核对返回结果的相关性是否符合预期。
- 查看检索日志，确认返回结果的条数符合`limit`的设定区间，且仅包含绑定知识库内的文档。
- 模拟维修场景提问，核对返回结果中是否包含设备台账、维修工单、备件清单等多类型文档。
