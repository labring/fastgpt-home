# 过程质量与成品放行的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来源包括MES系统、在线检测设备、实验室报告、工艺参数文档、客户质量标准及历史缺陷库。数据更新节奏为每生产批次、每班持续采集，部分月度报表按周期更新。日常文档涵盖控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单及质量月报，字段包含生产批次标识、检验参数、判定阈值、检测数值、评审结论等，单位随文档类型匹配对应工艺或质量标准单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
高频小批量的数据更新节奏要求索引支持增量写入与快速同步，避免全量重建带来的性能损耗。多类型文档的混合存在，要求向量分块适配不同长度的文本内容，既适配短文本的巡检记录，也适配长文本的不合格品评审单。质量相关的专属字段（如不合格项代码、批次标识）需要作为元数据绑定至索引，便于后续检索时按业务维度过滤。同一文档块的多个索引需绑定统一的业务元数据，检索时按元数据维度聚合结果，避免重复或无效召回。数据的批次强关联性要求索引支持按生产批次关联召回，避免跨批次的无效结果返回。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配本品类常见的巡检记录、检验报告的文本长度，避免分块破坏检验逻辑关联 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的上下文关联，确保长文本的检验项、评审意见不被割裂 |
| 相似度阈值 | 按实测标定 | 适配不同企业的质量标准匹配精度，避免误召回不合格项或遗漏有效历史数据 |
| 单次搜索上限 | 前 20 条 | 控制检索返回量，适配生产台账汇总时的批量处理需求 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 8192 | 适配月度质量月报等长文档的索引需求，同时匹配阿里-emb3的扩展窗口上限，避免截断关键评审内容 |

## 容易做错的三处
- 检索结果包含非当前生产批次的质量数据：原因是未将生产批次标识作为元数据绑定至索引，未配置按业务维度过滤的检索规则。
- 索引任务持续长时间未完成：原因是未启用增量索引模式，对全量生产台账数据执行全量索引，导致系统队列积压。
- 检索返回的检验记录缺少检测数值字段：原因是分块时未保留结构化数据的字段映射，导致向量索引丢失关键业务字段。

## 怎么确认配好了
- 查看索引元数据列表，确认生产批次标识、不合格项代码等专属字段已绑定至每条索引记录。
- 执行单次检索测试，验证结果可按生产批次进行过滤，仅返回当前指定批次的质量数据。
- 提交不同类型的文档进行索引，确认分块长度适配短文本巡检记录与长文本质量月报的处理需求。
- 查看索引任务日志，确认增量索引模式正常触发，无全量索引积压的情况。
