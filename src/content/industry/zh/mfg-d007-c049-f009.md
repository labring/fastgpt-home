# 过程质量与成品放行的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来源包括MES系统、在线检测设备、实验室检测记录、工艺参数库、客户验收标准及历史缺陷库。数据更新节奏为每生产批次、每班轮换时同步，或持续采集在线检测数据。日常产出的文档涵盖控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单及质量月报，数据字段包含检验批次号、不合格项编码、放行状态、工艺参数阈值、客户验收指标等，对应单位包括件、ppm、摄氏度、毫米等专业生产质量领域的字段单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入环节需支持对接多类API接口，适配不同系统的数据格式与字段规范。高频更新的生产数据要求配置的上下文窗口需覆盖近期批次的完整台账，避免遗漏关键质检信息。多样的文档结构需要模型能适配不同格式的质检文档解析，需明确指定字段映射规则。专业的质量字段与单位要求模型具备生产质量领域的术语理解能力，需在配置中加入领域适配的prompt模板。同时，该品类出错后果直接关联产品放行风险，因此配置环节需加入严格的校验与失败回退机制。

## 配置怎么定
本配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 覆盖3-5个生产批次的巡检记录、SPC报表等完整台账数据，避免上下文溢出导致信息丢失 |
| `maxTokens` | `2000–3000 token` | 适配单份质量月报或成品放行报告的生成长度，满足业务输出的完整度要求 |
| `temperature` | `0.1–0.3` | 降低生成结果的随机性，保证专业质量术语与字段的一致性，避免出现错误的质量判定表述 |
| 工作流/API 工具选择配置 | `auto` | 自动触发历史缺陷库检索工具，辅助识别异常趋势与不合格项的关联关系 |
| `AIPROXY_API_TOKEN` | 按平台分配的专属密钥填入 | 完成模型调用的身份校验，确保接口访问权限合法有效 |
| `AIPROXY_API_ENDPOINT` | 按所选模型的官方端点填入 | 建立正确的模型调用链路，避免连接错误或请求无法送达 |

## 容易做错的三处
- 现象：使用阿里云百炼或Ollama模型时触发报错，界面显示API认证失败或连接超时。原因：未正确填写`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，密钥内容或端点地址配置错误。
- 现象：模型生成的台账汇总结果与实际生产数据无法匹配，字段映射不生效。原因：未在prompt中明确指定该品类的专属字段（如不合格品评审编号、放行单状态）与模型输出的映射规则。
- 现象：多业务系统对接时，不同用户的聊天记录或生成报告混为一谈。原因：未在FastGPT API请求中携带唯一用户身份标识，未配置用户隔离的基础规则。

## 怎么确认配好了
- 填入`AIPROXY_API_TOKEN`和`AIPROXY_API_ENDPOINT`后，调用模型测试接口，确认返回正常的模型响应，无认证类报错。
- 上传一份控制计划与当班巡检记录，触发台账汇总功能，检查生成结果是否包含该品类要求的核心字段，如检验批次号、不合格项信息、放行状态标识。
- 调整`maxContext`参数至配置值，上传多批次的历史质检数据，确认生成的报告内容完整，未出现上下文溢出导致的内容截断。
- 模拟两个不同用户的API请求，传入唯一身份标识，确认生成的台账与报告按用户隔离，无数据混淆情况。
