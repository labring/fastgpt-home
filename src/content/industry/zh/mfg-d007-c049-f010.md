# 过程质量与成品放行的生产台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来源包括MES系统、在线检测设备、实验室报告、工艺参数文档、客户质量标准及历史缺陷库。数据更新节奏为每生产批次、每班结束同步更新，检测类数据持续采集。日常文档涵盖控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单及质量月报，字段包含批次标识、检验项名称、实测数值、判定结果、责任班组等，无额外统计百分比类指标。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类数据多源异构且更新节奏紧密绑定生产批次，要求检索召回需支持按生产批次、班组范围过滤数据。日常文档类型覆盖检验规范、记录报告等多类格式，需适配不同文档结构的字段匹配逻辑。数据包含实测数值、判定结果等精准字段，检索需关联对应检验项与历史缺陷案例，支撑异常识别与评审。同时，放行审核环节对检索准确性要求较高，需避免无效召回干扰审核流程。

## 配置怎么定
本文档适配FastGPT v4.17.0版本。以下为针对本品类的检索配置建议：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | 本品类需精准匹配检验项与缺陷描述，该区间可平衡召回覆盖率与检索准确性 |
| `limit` | 前10条 | 生产台账汇总需兼顾信息全面性与响应速度，过多结果会增加汇总与报告生成耗时 |
| `searchMode` | 向量+关键词混合检索 | 本品类数据包含结构化实测数值与非结构化文本，混合模式可覆盖不同类型的检索需求 |
| `usingReRank` | 开启 | 多源召回结果需按相关性排序，辅助快速定位关键检验标准与历史缺陷案例 |
| `datasetSearchUsingExtensionQuery` | 开启 | 生产类文档常包含专业工艺术语，扩展查询可提升对控制计划、SPC报表等文档的匹配度 |
| `collectionIds` | 绑定本生产质量知识库的专属集合ID | 限定检索范围至本品类专属文档，避免无关数据干扰质量审核与台账汇总 |

## 容易做错的三处
- 出现`Query read timeout`报错。原因是检索范围覆盖了过多历史批次数据，单次召回数据量超出系统处理阈值，导致请求超时。
- 传入知识库ID后无搜索结果。原因是未将`collectionIds`配置为对应生产质量知识库的集合ID，或配置的ID对应文档未包含控制计划、检验报告等本品类专属文档。
- API调用返回`Invalid URL, code: 500`错误。原因是知识库文件上传时的接口路径配置错误，或未正确关联本品类的专属知识库集合，导致请求无法匹配有效资源。

## 怎么确认配好了
- 发起一次检索请求，检查返回结果是否包含控制计划、成品检验报告等本品类专属文档，确认检索范围符合预期。
- 调整`similarity`参数区间，验证召回结果的相关性是否匹配当前检索的检验项或缺陷类型，确认阈值设置合理。
- 查看检索耗时，确认未出现超时情况，验证`limit`与`searchMode`配置对响应速度的影响符合业务需求。
- 上传一份本品类的测试文档，发起检索，确认文档可被正常召回，验证`collectionIds`配置正确。
