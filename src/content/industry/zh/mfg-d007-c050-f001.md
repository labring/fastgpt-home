# 通用机械设备装配的生产台账汇总与报告生成：HTTP 接口与外部系统

## 这个品类的数据长什么样
通用机械设备装配场景的数据来源涵盖PLM/ERP系统、零件检验采集数据、装配工具实时记录、试验台测试数据、MES生产执行数据以及客户技术协议文件。日常产生的文档包括装配工艺卡、多层级BOM清单、扭矩拧紧记录、间隙调整记录、空载/负载试运行报告、出厂检验单与装箱清单。数据更新节奏以单台设备或单个订单为单位，每完成一台装配或一笔订单交付，对应台账数据即完成一次更新。数据字段包含部件型号、拧紧扭矩值、间隙参数、试验结果、检验编号等，部分参数需匹配设备专属的技术规格单位。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
多源异构的数据来源要求HTTP接口需支持对接不同系统的格式，兼容PLM的结构化BOM数据、装配工具的时序扭矩记录、试验台的二进制测试报告等不同格式。按单台/单订单更新的节奏，接口需支持低频但高并发的批量请求，避免重复拉取冗余数据。多层级BOM与实物齐套核对的耗时环节，要求接口返回的台账数据需包含层级化的部件关联信息，且需支持按订单号、设备编号快速检索。同时，装配过程的临时调整记录需实时同步，接口需具备符合业务需求的响应能力，避免影响现场装配进度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {企业专属API密钥}` | 对接外部系统时通过该参数完成身份校验，防止未授权访问 |
| `variables` | `{"order_no": "", "equipment_model": ""}` | 用于传递订单号、设备型号等业务标识，实现按单台/单订单拉取对应台账数据 |
| `responseData` | 仅返回装配工艺卡、扭矩记录、检验单字段 | 过滤冗余数据，减少接口传输量，提升响应速度 |
| 接口超时时间 | `300 秒` | 装配过程的试验数据可能较大，需预留足够的传输与处理时间，避免超时中断 |
| 请求重试次数 | `2 次` | 应对网络波动导致的请求失败，避免重复拉取大量数据造成系统负载过高 |
| 数据拉取触发规则 | 按订单完成事件触发 | 匹配该品类按单台/单订单更新数据的节奏，避免无效拉取 |

## 容易做错的三处
- 现象：接口返回502 Bad Gateway状态码，原因：未正确配置外部系统的网络访问权限，导致FastGPT容器无法连通PLM或MES系统。
- 现象：调用接口后返回的`responseData`字段为空，原因：未在`variables`中传入正确的订单号或设备型号参数，导致无法匹配对应台账数据。
- 现象：并发调用时出现请求超时，原因：未设置合理的接口超时时间，且未配置请求重试机制，无法应对多请求并发时的网络延迟。

## 怎么确认配好了
- 调用接口并传入合法的`variables`参数，检查返回结果是否包含预期的装配工艺卡、扭矩记录等业务字段。
- 模拟网络波动场景，调用接口并验证是否触发配置的重试机制，且最终返回正常结果。
- 对比接口返回的`responseData`与PLM系统导出的原始台账数据，确认字段匹配度符合业务要求。
- 连续发起多次并发调用，检查接口是否能稳定返回正常结果。
