# 通用机械设备装配的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
通用机械设备装配的台账数据来自泵、阀、压缩机、减速机等制造商的生产流程，包含装配工艺卡、BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单等文档。数据来源涵盖PLM/ERP、零件检验数据、装配工具采集、试验台、MES及客户技术协议，更新频率为每台设备或每订单一次。台账字段包含物理参数（如扭矩N·m、间隙mm）、工序编号、检验日期、客户信息等，既有结构化的BOM层级数据，也有非结构化的工艺描述文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的台账数据更新频繁且类型多样，要求向量索引支持增量更新以适配每台/每订单的高频更新节奏。多类型文档混合的特征要求分块策略需兼顾结构化BOM的层级完整性与非结构化工艺文本的语义连贯性，避免拆分后丢失关键装配参数。物理参数与单位绑定的字段特征，要求向量模型需保留单位信息以避免语义混淆，同时索引的召回逻辑需支持层级关联匹配，以满足BOM与实物齐套的核对需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配装配工艺卡、扭矩记录等单文档的语义完整性，避免跨块割裂关键装配工序描述 |
| 重叠长度 | 100–150 字符 | 保留相邻块间的BOM层级关联信息，防止装配流程的上下文被分块截断 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性的台账记录，适配扭矩、间隙等物理参数的精准匹配需求 |
| 单次搜索上限 | 前6条 | 覆盖单台设备的核心台账条目，避免冗余数据干扰生产报告生成 |
| `maxToken` | 4096 token | 适配装配报告的长文本生成需求，避免参数描述被截断 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 索引无数据：分块长度设置过短，将单条扭矩记录或间隙调整记录拆分为多个语义不完整的块，部分块无法被向量模型正确编码，导致检索时无匹配结果。
- 搜索结果相关性不足：未针对物理参数（如扭矩N·m、间隙mm）配置适配的向量模型，导致召回的台账与查询的装配要求语义匹配度偏低。
- 最后一组索引无法通过：问答拆分时未调整重叠长度，导致最后一组分块的上下文缺失，无法通过索引校验，触发检索失败。

## 怎么确认配好了
- 上传单台设备的完整台账样本，执行检索测试，核对返回结果是否包含该设备的所有核心文档。
- 输入包含物理参数的查询，确认返回结果的字段匹配度符合预设的校验逻辑。
- 上传新生成的订单台账，执行增量索引操作，验证新数据是否能被正常检索。
- 查看FastGPT v4.17.0的索引日志，确认无分块失败、编码错误的提示。
