# 通用机械设备装配的生产台账汇总与报告生成：工作流编排
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
通用机械设备装配的生产台账数据，通常来自PLM系统、ERP系统、MES系统、装配工具采集终端、试验台及客户技术协议。数据更新节奏为每台装配完成的设备或每订单批次更新。日常文档包含装配工艺卡、多层级BOM清单、扭矩拧紧记录、间隙调整记录、试运行报告、出厂检验单、装箱清单，各文档字段包含设备型号、部件序列号、拧紧扭矩值（单位为牛米）、间隙调整值（单位为毫米）、试验参数、检验结果等，覆盖部件配合与调试的全流程记录。

## 这些特征在「工作流编排」这一环带来什么约束
通用机械设备装配的台账数据特征，对工作流编排带来多重约束。多层级BOM与分散的装配记录需要跨系统拉取数据，要求工作流支持多数据源并行调用。单台设备的台账数据量随装配步骤递增，大节点数据结构易超出AI上下文长度，需配置合理的上下文限制。每订单或每台设备的更新节奏要求工作流支持按触发条件自动执行。装配过程中的扭矩、间隙等带单位的数值字段，要求工作流在汇总时保留字段格式与单位，避免数据失真。通用机械设备装配多为按订单定制的多品种生产，不同于单一零件加工，台账数据需覆盖部件配合与调试的全流程记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| variables | 绑定装配BOM、扭矩记录、检验单的数据源变量 | 适配通用机械设备装配的多源台账数据拉取需求 |
| nodeId | 依次绑定BOM校验、扭矩汇总、报告生成的工作流节点 | 按装配流程顺序编排任务节点，确保数据流转逻辑匹配装配工序 |
| 单次调用token上限 | 8000–12000 token | 适配单台设备台账数据的平均规模，避免上下文超限 |
| 多数据源并行调用数 | 前3条 | 平衡数据拉取效率与系统负载，适配PLM、MES、装配工具三类数据源 |
| 变量自动更新触发条件 | 按装配节点完成状态 | 匹配每台设备的更新节奏，确保台账数据随装配进度实时同步 |
| 上下文窗口裁剪策略 | 保留最近10条装配记录 | 聚焦当前装配批次的核心数据，避免冗余信息干扰汇总结果 |

## 容易做错的三处
- 现象：工作流执行后`variables`字段未自动更新，查看系统日志显示变量值与预设初始值一致，未发生变化。原因：未将变量更新节点绑定至对应装配节点的完成事件，仅配置了手动触发更新逻辑。
- 现象：调用多层BOM数据时，系统返回「上下文长度超限」的报错提示。原因：未配置合理的单次调用token上限，未对大节点数据进行分块裁剪处理。
- 现象：分类统计装配工序调用次数时，工具节点执行完成后，全局计数变量未同步更新。原因：未在工具节点的输出配置中绑定`variables`参数，未将计数结果写入全局变量池。

## 怎么确认配好了
- 触发一次模拟装配节点完成的事件，查看工作流执行日志，确认`variables`参数中的台账数据已按装配进度同步更新。
- 导入单台设备的完整多层BOM数据，测试工作流执行，确认无上下文长度超限报错。
- 依次检查每个`nodeId`对应的工作流节点，确认数据流转顺序与装配工序一致，无节点错位或数据遗漏。
- 查看自动生成的台账报告，确认扭矩、间隙等字段保留了原始牛米、毫米单位与对应数值格式。
