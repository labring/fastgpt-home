# 通用机械设备装配的生产台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
该品类数据主要来自PLM/ERP系统、零件检验数据、装配工具采集终端、试验台、MES系统及客户技术协议。日常文档包含装配工艺卡、多层BOM、扭矩记录（单位N·m）、间隙调整记录（单位mm）、同轴度检测记录（单位μm）、试运行报告、出厂检验单与装箱清单。数据按每台设备或每订单更新，包含订单号、设备型号、装配班组、关键工序参数、检验结果等字段。

## 这些特征在「数据库与运维」这一环带来什么约束
多层级BOM与多源数据的关联需求，要求数据库支持嵌套查询与多表关联操作，避免数据冗余。按单或按设备的更新频率，要求数据库支持按订单号、设备序列号等唯一标识快速定位与更新单条记录。非结构化的工艺卡、报告与结构化的扭矩、间隙参数并存，需要数据库同时兼容结构化存储与非结构化文件存储。高频的装配工序参数采集，要求数据库具备高并发写入能力，避免数据丢失或延迟。多源系统的数据对接需求，要求数据库支持标准协议的外部连接。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:securepass@db.example.com:27017/assembly_db?authSource=admin&retryWrites=true` | 支持非结构化装配文档与结构化工序参数的混合存储，适配FastGPT v4.17.0的多类型数据处理逻辑 |
| `PG_URL` | `postgresql://dbuser:dbpass@pg.example.com:5432/assembly_bom` | 存储多层BOM与订单关联数据，支持嵌套查询与多表关联操作 |
| `DB_MAX_LINK` | `18–22` | 匹配每台设备高频参数采集的并发写入场景，避免数据库连接池耗尽 |
| `REDIS_URL` | `redis://:redispass@redis.example.com:6379/0` | 缓存高频查询的订单与设备映射信息，降低主数据库负载 |
| 数据库连接重试次数 | `3 次` | 适配多源系统对接的网络波动，减少数据写入失败概率 |

## 容易做错的三处
- 工作流调用数据库工具时弹出“认证失败”或“连接超时”报错，或查询结果为空。原因：未正确填写`MONGODB_URI`中的用户名、密码与认证源参数，或部署环境未开放数据库对应端口。
- 高频装配参数写入时出现连接等待超时。原因：`DB_MAX_LINK`取值低于实际并发写入的需求，导致数据库连接池耗尽。
- 多层BOM的关联查询返回数据缺失或层级混乱。原因：使用仅支持扁平结构的数据库存储BOM数据，未通过`PG_URL`配置支持嵌套查询的关系型数据库。

## 怎么确认配好了
- 登录FastGPT后台的数据库配置页面，测试`MONGODB_URI`的连通性，查看是否返回连接成功提示。
- 创建测试工作流，调用数据库工具查询单条装配记录，核对返回字段与预设的设备参数、订单信息是否一致。
- 模拟高频写入操作，查看数据库连接池的占用情况，确认`DB_MAX_LINK`的取值满足当前并发需求。
- 导入一份多层BOM数据，通过关联查询验证层级结构是否完整，确认`PG_URL`对应的数据库配置生效。
