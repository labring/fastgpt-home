# 通用机械设备装配的生产台账汇总与报告生成：文档解析与分块

## 这个品类的数据长什么样
通用机械设备装配品类的日常文档包含装配工艺卡、BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单。数据来源覆盖PLM/ERP系统、零件检验数据、装配工具采集终端、试验台、MES系统及客户技术协议。文档更新频率为每台设备或每订单一次，单订单文档集合包含多份结构化与非结构化文件，部分字段带有专业单位，如扭矩值以牛·米为单位、间隙调整值以毫米为单位，BOM包含物料编码、数量、供应商等关联字段。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的多品种按订单装配特性，导致单订单文档结构存在差异，无法使用通用分块规则适配所有文档类型。多来源的文档格式差异，要求解析模块具备灵活的适配能力，避免因格式不兼容导致字段丢失。高频次的单订单更新，要求解析与分块流程具备高效性，减少重复处理耗时。专业字段与单位的存在，要求分块时保留上下文关联，避免拆分破坏工序、检验项的逻辑完整性，区别于以单一尺寸数据为主的零件加工品类。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配装配工艺卡、BOM的字段密度，避免拆分破坏工序或物料关联 |
| `chunkSplitter` | 按段落+标题拆分 | 匹配装配文档的层级结构，保留工艺步骤、检验项的完整上下文 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 覆盖大体积试运行报告、试验台日志的解析耗时 |
| `customPdfParse` | 启用 | 适配PLM导出的加密或非标准PDF格式，保留原有字段排版 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 容纳单订单的全套装配文档包，包含多份检验单与日志文件 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（BOM、扭矩记录）调整分块规则，适配多格式输入 |

## 容易做错的三处
- 现象：调用文件解析接口后返回空结果，日志提示split相关错误。原因：未启用`customPdfParse`配置，或`chunkSplitter`参数配置错误，无法适配PLM导出的非标准PDF格式。
- 现象：Docker部署后解析的文件内容未传入知识库。原因：未正确挂载解析模块的文件存储卷，或`UPLOAD_FILE_MAX_SIZE`设置过小导致大文件被截断。
- 现象：解析大体积的试运行报告时出现超时错误。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值低于实际解析耗时，未覆盖复杂文档的处理周期。

## 怎么确认配好了
在FastGPT v4.17.0版本中，可通过以下可执行动作确认配置生效：
- 上传一份典型的装配工艺卡PDF，检查解析后的文本是否保留工序号、操作要求等核心字段，无明显拆分断裂。
- 上传单份100–200MB的试运行报告，验证解析耗时是否符合预设的`PARSE_FILE_TIMEOUT_SECONDS`范围，无超时报错。
- 检查知识库索引列表中是否包含上传文档的完整内容，无字段缺失或格式混乱。
- 对比不同文档类型（BOM、扭矩记录）的分块结果，确认分块规则适配当前业务的文档结构。
