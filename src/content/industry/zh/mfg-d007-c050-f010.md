# 通用机械设备装配的生产台账汇总与报告生成：知识库检索与召回

## 这个品类的数据长什么样
通用机械设备装配场景的数据通常来自PLM/ERP系统、零件检验数据、装配工具采集终端、试验台、MES系统及客户技术协议。日常文档包含装配工艺卡、BOM表、扭矩记录、间隙调整记录、试运行报告、出厂检验单与装箱清单。数据更新以单台设备或每笔订单为节奏，文档字段包含物料编码、拧紧扭矩值、同轴度参数、检验结果等，部分文档带有明确的单位约束，例如扭矩记录标注牛米，间隙调整记录标注毫米。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据来源分散且更新节奏频繁，要求知识库检索环节支持多源数据的关联匹配，避免因数据源割裂导致的信息缺失。文档类型涵盖结构化BOM表与非结构化工艺记录，检索逻辑需兼顾字段匹配与全文语义匹配的双重需求。单台设备的文档与订单强绑定，检索时需优先召回与当前订单参数匹配的内容，同时需处理高频更新带来的索引延迟问题，确保召回内容与最新生产数据同步。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 适配装配文档中字段匹配与语义关联的双重需求，避免召回无关的BOM或工艺内容 |
| `limit` | 前6条 | 控制单轮检索返回的文档数量，适配装配台账汇总时的信息密度要求 |
| `searchMode` | hybrid | 兼顾结构化字段匹配与全文语义检索，适配BOM表与工艺卡混合格式的文档特征 |
| `usingReRank` | 开启，保留前3条重排结果 | 过滤初始召回的冗余内容，优先返回与装配参数匹配度更高的文档 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 该品类文档多与订单强绑定，无需额外扩展查询词，避免引入无关信息 |
| `collectionIds` | 按订单绑定的知识库集合 | 限定检索范围，仅召回当前订单关联的装配文档 |

## 容易做错的三处
-  现象：知识库上传3MB的PDF文件后弹出模型调用异常的报错提示。原因：未针对该品类的结构化文档（如BOM表）配置合适的分块规则，大文件解析时触发模型上下文长度限制。
-  现象：Docker部署的知识库持续处于索引中状态，无进度更新。原因：未限定检索的知识库集合，系统尝试全量扫描分散的装配文档，导致索引任务积压。
-  现象：AI对话返回的台账内容被调整整理，未严格匹配原始文档的参数表述。原因：开启了`datasetSearchUsingExtensionQuery`或未关闭结果整理开关，导致模型对召回内容进行了二次加工。

## 怎么确认配好了
-  上传单台设备的装配工艺卡与BOM表，执行检索测试，核对返回结果是否包含当前订单关联的文档。
-  查看知识库索引日志，确认仅扫描当前配置的`collectionIds`对应集合，无冗余扫描任务。
-  输入包含扭矩参数的查询词，核对召回结果的匹配度是否符合预设要求。
-  触发一次台账汇总任务，确认返回的内容未被二次调整，与原始文档的字段表述一致。
