# 金属切削加工的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES平台及量检具数据。日常文档包含工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表、量具校准记录，字段含工序编号、刀具型号、切削参数、尺寸公差、检验结果等，单位多为毫米、转每分钟、米每分钟。数据更新随每工单、单件加工、抽检及刀具更换触发，无固定周期。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据来源分散且格式多样，既有结构化的工艺参数、检验结果，也有非结构化的数控程序文本与三维模型标注，需适配多模态向量处理逻辑。数据更新无固定周期，随工单、单件加工、抽检及刀具更换触发，需支持增量索引，避免全量重建的高耗时操作。文档包含刀具型号、尺寸公差、切削参数等精准字段，向量分块需保留关键工艺关联信息，避免拆分破坏工序逻辑。机床采集的实时数据与台账类静态数据需区分索引优先级，确保检索时工艺关联数据优先召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 本品类文档含数控程序、工艺路线等长文本，分块过长会丢失局部关联，过短会破坏工序逻辑，适配FastGPT v4.17.0的默认分块规则 |
| 重叠长度 | 100–150 字符 | 需保留工序间的工艺衔接信息，避免分块断裂导致检索时工艺逻辑不完整 |
| `defaultToken` | 1024 token | 适配本品类常见的工艺参数与程序文本的向量编码长度，避免截断关键信息 |
| 相似度阈值 | 0.75–0.85 | 本品类需精准匹配刀具型号、公差要求等字段，阈值过低会引入无关结果，过高会遗漏有效关联数据 |
| 单次搜索上限 | 前 8 条 | 需兼顾工艺台账的多维度关联，单次召回过多会超出上下文限制，过少则无法覆盖全量关联工序 |
| `maxToken` | 4096 token | 适配多文档汇总时的上下文长度要求，确保生产台账报告生成时可纳入足够的关联数据 |

## 容易做错的三处
- 现象为导入生产台账数据后，自定义的刀具型号、工序编号字段未被索引，检索结果无对应内容。原因是未在导入配置中指定需提取的自定义字段范围，仅默认加载了基础文本内容。
- 现象为模型选择界面无法找到指定的Embedding模型，弹出配置错误提示。原因是未在系统设置中配置对应模型的API访问参数，或当前FastGPT版本未适配该模型的接口格式。
- 现象为向量化包含数控程序截图的台账文档后，检索时仅返回文本片段，无图片关联结果。原因是未开启多模态向量处理配置，未对图片数据单独配置向量化规则。

## 怎么确认配好了
- 上传单份工序卡文档，查看索引预览界面，确认自定义字段如刀具型号、公差值已被正确提取并向量化。
- 发起包含刀具型号关键词的检索，核对返回结果的字段匹配情况，调整配置项至符合业务需求的范围。
- 上传包含数控程序截图的文档，验证检索结果是否包含图片关联的文本信息，确认多模态配置生效。
- 查看系统运行日志，确认向量模型调用无认证错误或超时提示，核对`defaultToken`与`maxToken`的配置参数与取值一致。
