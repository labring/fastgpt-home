# 钢材轧制与精整的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来自板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与制造执行系统（MES）。更新节奏为每卷或每支钢产品对应一次数据提交，核心生产环节数据实时更新。日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书，核心字段包含卷号、批次标识、加热温度、轧制速度、厚度偏差，对应单位为℃、m/s、mm等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据按卷或支拆分且实时更新，多轮对话需精准跟踪单批次钢产品的全链路台账，需避免不同卷号的字段混淆。日常文档类型多样，提示词需适配轧制计划、表面质量报告等不同文档的字段格式，提取对应卷号、温度、厚度偏差等信息。实时更新的特性要求对话上下文需限制历史消息的保留时长，防止过期数据干扰当前汇总。卷级追溯的核心需求，使得多轮对话需反复确认批次标识，确保汇总范围准确。同时，异常数据的判定需嵌入提示词规则，匹配业务中的降级、断带等风险场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 前1000–1500 字符 | 适配单卷钢产品的台账数据总量，避免上下文溢出导致的解析失败 |
| 历史消息保留条数 | 前5条 | 匹配实时数据的更新节奏，减少过期批次数据的干扰 |
| 交互超时阈值 | 300–600 秒 | 适配实时数据的交互响应需求，避免因数据加载过久导致对话中断 |
| 提示词变量绑定 | `variables` 绑定卷号字段 | 精准定位单批次钢产品的台账数据，避免跨卷汇总错误 |
| 会话持久化配置 | 绑定`chatId` | 实现跨会话的批次信息留存，满足卷级追溯的业务需求 |
| 结果格式校验 | 启用JSON格式校验 | 适配台账汇总的结构化报告生成需求，确保输出符合业务标准 |

## 容易做错的三处
- 现象：对话节点输出内容直接混入全局返回结果，无法单独提取台账报告。原因：未配置对话节点的输出映射规则，将对话结果直接挂载到默认返回字段。
- 现象：多轮对话无法跨会话保留单卷钢产品的批次信息，每次重启需重新输入卷号。原因：未绑定会话`chatId`实现上下文持久化，导致会话状态未被存储。
- 现象：生成的台账报告JSON格式不符合业务标准，字段缺失或类型错误。原因：未在提示词中明确指定JSON Schema的字段要求，未启用格式校验配置。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的对话节点，输入指定卷号的测试数据，核对对话返回的台账数据是否仅包含该卷号的相关字段。
- 重启对话后，验证是否能自动识别之前输入的卷号，无需重复提交批次标识。
- 生成报告后，检查输出格式是否符合预设的JSON结构，字段是否完整且符合业务要求。
- 查看对话日志，确认`messages`参数仅保留必要的历史交互内容，无冗余的跨批次数据。
