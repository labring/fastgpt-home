# 钢材轧制与精整的生产台账汇总与报告生成：数据库与运维

## 这个品类的数据长什么样
该品类数据来源于热轧、冷轧、型钢、钢管企业的板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与MES系统，涵盖轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书等文档。数据按每卷或每支钢坯更新，更新节奏实时，字段包含批次编号、加热温度、轧制速度、厚度偏差、表面缺陷等级等，对应单位涵盖摄氏度、米每秒、毫米等业务通用单位。

## 这些特征在「数据库与运维」这一环带来什么约束
实时高频的卷级数据更新，要求数据库连接池需支持高并发短连接，避免连接耗尽。多源异构的数据来源，要求数据库需兼容结构化与半结构化数据的混合存储。卷级全链路追溯的核心业务需求，要求数据写入需保证强一致性，避免批次关联错误。单批次数据量稳定但总数据量随产能扩张持续增长，需提前规划索引与分表策略，否则会导致查询延迟。生产台账的不可缺失性，要求数据库运维需配置自动备份与故障切换机制，防止数据丢失引发钢卷降级或设备事故。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://<user>:<pass>@<host>:27017/steel_rolling_prod?authSource=admin` | 存储半结构化的表面质量报告、质保书等非标准化台账文档 |
| `PG_URL` | `postgresql://<user>:<pass>@<host>:5432/steel_prod_db?sslmode=require` | 存储结构化的轧制计划、厚度记录、加热制度等带明确字段的业务数据 |
| `DB_MAX_LINK` | `200–300 个连接` | 匹配实时高频的卷级数据写入与查询并发量，避免连接耗尽 |
| `REDIS_URL` | `redis://:<pass>@<host>:6379/0` | 缓存高频访问的轧制批次关联元数据，降低数据库查询延迟 |
| 自动备份周期 | `每6小时一次` | 匹配生产中断的容忍窗口，保障核心台账数据安全 |

## 容易做错的三处
- 现象：执行SQL查询时偶发失败，返回连接超时或权限错误。原因：未根据实时高频的卷级数据更新调整`DB_MAX_LINK`配置，导致连接池耗尽，部分查询无法获取数据库连接。
- 现象：MongoDB连接节点启动后无报错，但无法读取表面质量报告数据。原因：连接串中未指定`authSource`参数，导致数据库身份验证失败，无法访问对应库表。
- 现象：工具调用节点执行到数据库查询环节后停滞，无返回结果。原因：未配置Redis缓存或连接参数错误，导致高频查询未命中缓存，拖慢整体执行链路。

## 怎么确认配好了
- 执行预设的轧制批次查询SQL，验证结构化数据可正常读取，查询延迟符合业务预期阈值。
- 调用MongoDB连接测试接口，验证半结构化的表面质量报告文档可正常写入与读取。
- 查看数据库连接池监控指标，确认当前活跃连接数未达到配置的`DB_MAX_LINK`上限。
- 触发自动备份任务，验证备份文件生成正常且可恢复核心台账数据。
