# 钢铁冶炼与连铸的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自铁水与废钢投料记录、L2过程控制系统、化验室成分报告、MES生产管理系统、能源介质监控及设备状态传感器。日常文档包含炉次计划、配料单、转炉冶炼记录、连铸工艺记录、板坯判定单等，涵盖炉温、投料量、成分检测值、浇铸速度、设备工况等字段，单位涉及摄氏度、吨、米每秒等。数据更新频率为每炉次生成专属台账、过程数据实时上传、每班完成汇总统计，单条记录长度跨度较大。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据更新频率高且实时性强，要求向量索引支持增量更新，避免频繁全量索引带来的性能损耗。多类型文档混合存在，需向量模型适配结构化字段与半结构化文本的混合特征，确保不同格式的台账数据均能生成有效向量。炉次与浇次强耦合的业务逻辑，要求索引支持跨文档关联检索，避免拆分数据破坏业务关联关系。数据字段包含特定物理量与单位，分块处理时需保留字段完整性，防止关键业务信息被截断。

## 配置怎么定
本页面适用于FastGPT v4.17.0版本，以下配置基于该版本的界面与参数逻辑：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配炉次台账单条记录的长度范围，避免拆分破坏配料单与冶炼记录的字段关联 |
| 重叠长度 | 50–80 字符 | 保留跨分块的工艺步骤关联信息，防止关键浇铸环节被分块截断 |
| 相似度阈值 | 按实测标定 | 适配钢铁生产数据的特征分布，避免误匹配或漏匹配异常工况数据 |
| 单次搜索上限 | 前10条 | 匹配连铸流程多环节关联检索的需求，覆盖炉次到板坯的完整业务链 |
| `defaultToken` | 16000 | 适配多文档汇总的上下文长度，覆盖单炉次全流程数据的检索需求 |
| `maxToken` | 32000 | 支持完整生产报告生成所需的上下文总量，避免生成过程触发长度限制 |

## 容易做错的三处
- 现象：手动插入的炉次台账索引数小时后自动消失。原因：未配置增量索引的持久化存储，实时更新的台账数据未正确写入向量数据库索引文件。
- 现象：文件状态持续显示“索引中”，无法完成索引构建。原因：嵌入模型与FastGPT版本不兼容，未按要求配置`defaultToken`参数适配钢铁数据的字段长度。
- 现象：检索结果仅返回单条炉次记录，无法关联对应连铸工艺数据。原因：分块长度设置过短，拆分时破坏了炉次与浇次的关联字段，导致向量无法匹配跨文档的关联信息。

## 怎么确认配好了
- 上传单条完整炉次台账，等待索引构建完成后，检索该炉次的配料单字段，确认返回结果包含完整关联字段。
- 等待24小时后查看已插入的台账索引列表，确认所有实时更新的记录索引未丢失。
- 调用检索接口，验证返回结果条数符合单次搜索上限的配置值。
- 生成生产报告，检查报告中包含的上下文长度未触发`maxToken`参数限制。
