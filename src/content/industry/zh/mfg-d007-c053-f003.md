# 钢铁冶炼与连铸的生产台账汇总与报告生成：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据来自铁水与废钢采集系统、L2过程控制节点、化验室检测系统、生产制造执行系统（MES）、能源介质监控系统与设备状态监测模块。数据更新节奏包含每炉次生成的炉次计划与配料单、实时同步的冶炼与连铸过程参数、每班汇总的能源消耗与设备运行记录。日常文档包含标准化的炉次台账、配料明细、冶炼过程记录、成分检测报告、连铸工艺参数日志与板坯质量判定单，字段包含炉次编号、冶炼时长、过程温度、设备运行参数与质量检测值，对应单位为分钟、摄氏度、毫米等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的高频实时更新与多源异构数据特征，要求多轮对话需逐步引导用户明确查询的炉次编号或时间区间，避免调用过期或不相关的生产数据。固定格式的台账文档结构，要求提示词需明确指定匹配的文档字段与分类，防止生成混淆的汇总内容。每炉次生成的独立台账，要求对话上下文需绑定当前会话对应的炉次标识，避免跨炉次数据串用。实时同步的过程参数，要求对话响应需优先返回最新采集的节点数据，确保汇总报告的时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前查询的炉次编号作为唯一标识 | 每炉次生产数据独立，避免跨炉次数据串用 |
| `messages` | 限制单轮对话上下文保留最近3轮交互与2份炉次台账 | 减少冗余数据干扰，提升响应准确性 |
| `variables` | 预设炉次编号、检测时间范围两个必填变量 | 明确多源生产数据的查询维度，缩小检索范围 |
| 最大上下文token数 | 按实测标定，不超过12000 token | 单炉次台账与过程数据总量较大，平衡上下文完整性与响应速度 |
| 单次召回文档数 | 前6条 | 单炉次关联文档不超过5份，保留合理冗余空间 |
| 问题优化开关 | 开启 | 生产专业术语较多，优化用户问题与台账字段的匹配精度 |

## 容易做错的三处
- 现象：开启输入引导并配置自定义词库地址后，调试预览对话出现报错。原因：未将自定义词库与`variables`绑定的炉次编号变量关联，导致词库无法匹配当前生产场景的专业术语。
- 现象：设置最大响应token为3000以上，但特定生产问题的响应长度仅为200。原因：对话上下文触发了内置的上下文截断规则，或未绑定当前炉次的完整台账数据，导致检索范围受限。
- 现象：无法在对话过程中向知识库添加实时采集的生产数据，或无法查看会话的token统计值。原因：未配置基于`messages`的实时数据同步触发逻辑，且未找到全局token统计的查看入口。

## 怎么确认配好了
- 进入FastGPT v4.17.0 版本的会话配置页面，查看`chatId`是否绑定了炉次编号字段，确认变量列表中包含预设的炉次编号与时间范围参数。
- 发起包含具体炉次编号的测试对话，检查响应是否仅返回该炉次的相关台账与过程数据，无跨炉次数据混入。
- 测试不同长度的查询问题，确认响应token数符合预设上限，无异常截断情况。
- 尝试在对话中提及实时生产数据，确认系统可同步更新知识库中的对应内容，且可在全局配置页面查看token统计值。
