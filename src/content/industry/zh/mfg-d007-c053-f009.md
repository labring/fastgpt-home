# 钢铁冶炼与连铸的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据涵盖铁水与废钢投料数据、L2过程控制实时数据、化验室成分检测报告、MES生产调度数据、能源介质系统运行数据及设备状态监测数据。日常台账文档包括炉次计划、配料单、转炉冶炼记录、连铸工艺参数记录、板坯质量判定单等。数据更新频率覆盖每炉次、实时及每班，字段包含炉次编号、铁水重量、碳硅锰含量、出钢温度、连铸拉速、板坯厚度等，单位涵盖吨、百分比、摄氏度、米/分钟、毫米。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入环节支持跨系统数据的批量拉取与格式整合，避免因数据源分散导致的解析遗漏。高频的实时、炉次级更新频率要求配置足够大的上下文窗口，以容纳单炉次全流程的台账数据。多样的文档结构要求模型具备结构化字段识别能力，适配炉次计划、成分报告等不同格式的台账。高温连续流程下数据出错后果严重，要求配置稳定的调用超时与重试机制，防止单炉次数据异常中断生产流程。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本，具体配置项及建议如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写企业内网专属的模型代理地址 | 适配跨系统数据接入的跨域请求限制，保障数据传输安全 |
| `AIPROXY_API_TOKEN` | 绑定生产环境专属服务密钥 | 隔离不同炉次批次的调用权限，避免数据混淆 |
| `maxContext` | 8000–12000 token | 容纳单炉次全流程的台账文档与实时监测数据，防止上下文截断 |
| `maxTokens` | 2000–3000 token | 保证生成的汇总报告包含完整的工艺参数与质量判定结果 |
| `temperature` | 0.2–0.4 | 保持台账数据解析的准确性，避免生成冗余或偏离实际的内容 |
| `toolChoice` | auto | 自动适配多格式台账的解析需求，无需手动切换工具 |

## 容易做错的三处
- 现象：上传单炉次完整台账后，模型返回的汇总报告缺失部分字段内容。原因：未正确配置`maxContext`参数，上下文窗口过小导致单炉次全量数据被截断。
- 现象：多轮对话中修改全局变量后，后续调用未生效且数据混乱。原因：未在模型接入配置中开启上下文持久化绑定，导致多轮会话的变量状态丢失。
- 现象：模型调用耗时超出600秒且被强制终止。原因：`maxContext`配置过大，导致模型解析上下文的时间超出阈值。

## 怎么确认配好了
- 上传单炉次的完整台账文档，核对模型返回的汇总内容是否包含所有预设的字段。
- 发起多轮对话修改全局变量，核对后续调用中变量值是否保持一致。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的请求参数无异常。
- 模拟异常数据输入，核对模型是否能正确识别字段格式并生成符合要求的报告。
