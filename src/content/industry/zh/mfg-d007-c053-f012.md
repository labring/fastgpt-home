# 钢铁冶炼与连铸的生产台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
数据来自铁水与废钢投料数据、L2过程控制系统、化验室成分报告、MES系统、能源介质监控系统与设备状态采集节点。更新节奏覆盖每炉次、实时与每班三类。日常文档包含炉次计划、配料单、转炉冶炼记录、成分分析报告、连铸工艺参数记录与板坯质量判定单。数据结构包含结构化数值字段与非结构化扫描文档，字段单位涵盖温度、成分占比、流量等工业标准单位。流程为高温连续作业，炉次与浇次耦合紧密，无法随意停机调整数据采集逻辑。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的数据来源要求部署阶段需支持多系统接口对接，避免硬编码的数据源配置。实时与高频更新的数据要求数据库连接池需适配高并发写入，升级过程中需保证数据写入不中断。炉次与浇次的强耦合关系要求台账汇总的时间窗口需严格匹配生产节拍，升级时不能随意调整数据聚合逻辑。高温连续流程的特性要求升级操作采用灰度发布模式，避免全量升级导致生产中断。非结构化文档的存储需求要求需配置专用的对象存储服务，与结构化数据存储分离。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 20–30 个连接 | 适配每炉次实时写入的并发需求，避免数据库连接耗尽 |
| `PG_URL` | 包含端口与认证信息的MES台账数据库连接串 | 存储结构化的转炉冶炼记录、成分报告与连铸工艺数据 |
| `REDIS_URL` | 配置缓存过期时间为 600 秒 | 缓存每班更新的调度协调数据，平衡实时性与资源占用 |
| `STORAGE_S3_ENDPOINT` | 绑定带宽不低于 100 MB/s 的工业对象存储节点 | 存储非结构化的炉次计划、板坯判定单等扫描文档 |
| `ROOT_KEY` | 按企业IAM体系生成专属密钥 | 管控系统最高权限访问，符合流程工业数据安全规范 |
| `FE_DOMAIN` | 配置为企业内部二级域名，端口为 8080 | 对外提供台账查询与报告生成的访问入口 |

## 容易做错的三处
- 现象：重启服务器后，容器内存储的台账历史数据与系统配置项全部丢失。原因：未将数据库、缓存与文档存储目录挂载到宿主机持久化存储卷，导致容器重启后数据随容器实例销毁。
- 现象：执行多炉次台账汇总任务时频繁出现连接超时错误，日志返回504状态码。原因：`DB_MAX_LINK`配置值过低，并发连接数超过上限导致请求排队超时。
- 现象：生成的连铸工艺报告中缺失部分时段的能源介质消耗数据。原因：未配置全量的数据源对接接口，仅同步了部分生产节点的数据。

## 怎么确认配好了
- 执行`docker ps`命令，确认FastGPT v4.17.0相关容器与挂载的持久化存储卷处于运行状态。
- 发起一次单炉次的台账数据同步任务，检查目标数据库中是否写入对应炉次的完整结构化记录。
- 访问`FE_DOMAIN`配置的域名，登录系统后查看历史台账列表，确认所有类型的文档均可正常加载与预览。
- 触发一次月度生产报告生成任务，检查输出的报告是否包含炉次计划、冶炼记录、连铸工艺参数与质量判定结果的完整内容。
