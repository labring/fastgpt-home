# 钣金下料折弯的生产台账汇总与报告生成：模型接入与配置

本文基于FastGPT v4.17.0版本的配置逻辑编写。

## 这个品类的数据长什么样
钣金下料折弯品类的核心数据通常来自CAD/CAM软件、订单BOM、板材库存系统、激光切割机、折弯机及车间MES。日常文档通常包含展开图、数控下料程序、折弯工艺卡、套料图、首件记录与工序流转卡，字段通常涵盖板材规格、折弯系数、下料尺寸、工序编号、流转时间等，单位多为毫米、千克、小时。数据更新节奏通常随生产流程调整：按订单生成时更新BOM与展开图，每日同步板材库存与设备运行数据，每次换型时更新折弯工艺参数与套料方案。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类多品种小批量的生产模式，要求模型可灵活适配不同规格的钣金图纸与工序数据；高频次的更新节奏，需模型上下文可快速加载最新的生产记录；多样的数据源类型，要求接入配置兼容CAD导出的结构化数据与设备采集的时序数据；核心环节的折弯补偿与套料精度要求，需模型可精准关联图纸与工序台账，避免生成偏差。同时，出错后果直接关联板材浪费与装配误差，要求配置需保障检索与生成的准确性，不可过度依赖模糊匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 钣金台账需整合展开图、工序流转卡等多类数据，该取值可覆盖单批次完整生产上下文 |
| `quoteMaxToken` | `2000–3000 token` | 套料图、折弯工艺卡的文本与可视化描述内容较长，需保留足够引用细节以支撑汇总 |
| `temperature` | `0.2–0.4` | 台账汇总与报告生成需保持内容准确性，较低温度可降低生成偏差 |
| `AIPROXY_API_ENDPOINT` | 按厂商提供的专属接入地址填写 | 需兼容钣金设备与系统的专用数据格式，保障数据拉取与同步正常 |
| `vision` | 开启 | 需处理展开图、套料图等可视化图纸数据，开启视觉能力可识别图纸中的尺寸与折弯标记 |
| `maxTokens` | `4000–6000 token` | 报告生成需整合多工序数据，该取值可避免关键信息被截断 |

## 容易做错的三处
- 现象：语义检索匹配度达标但模型返回未找到相关生产数据。原因：`maxContext`参数取值不足，未将检索到的展开图、工序流转卡等有效数据纳入模型上下文。
- 现象：单次台账生成任务耗时过长。原因：`quoteMaxToken`设置过大，导致模型加载过多套料图、折弯工艺卡的冗余数据，拖慢处理速度。
- 现象：无法正常调用外部钣金设备的API接口。原因：未正确配置`AIPROXY_API_TOKEN`，或未遵循Basic Auth的认证规则完成接口接入。

## 怎么确认配好了
- 上传单份折弯工艺卡与套料图，触发台账汇总任务，检查生成的报告是否包含板材规格、折弯系数、下料尺寸等核心字段。
- 模拟高流量查询场景，查看接口响应时间无明显异常，符合业务处理节奏要求。
- 验证外部API接入状态，确认可正常拉取激光切割机的下料数据与MES的工序流转记录。
- 调整`temperature`参数至0.1与0.5，对比两次生成的台账内容，确认结果稳定性符合业务需求。
