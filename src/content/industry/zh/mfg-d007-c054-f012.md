# 钣金下料折弯的生产台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
该品类的数据通常来自CAD/CAM软件、订单BOM系统、板材库存台账、激光切割机与折弯机设备日志、车间MES系统。日常产生的文档包括钣金展开图、数控下料程序、折弯工艺卡、套料图、首件检验记录、工序流转卡。数据更新节奏随订单交付、每日生产排班、设备换型调整，字段通常包含板材规格、折弯补偿系数、工序流转状态、设备运行参数、订单编号，单位多为毫米、千克、件、小时。

## 这些特征在「部署与升级」这一环带来什么约束
钣金下料折弯的多源异构数据特征，要求部署时需适配CAD图纸、设备日志、BOM等多种格式的数据接入，需提前配置跨数据源的统一解析规则。高频更新节奏要求部署时调整数据同步频率，平衡实时性与服务器资源占用，避免因频繁同步导致性能下降。多品种小批量的业务模式，导致台账字段不固定，需配置灵活的元数据适配能力，支持按需新增台账字段。大尺寸工程图纸的存储与解析需求，要求升级时调整文件存储和索引的配置参数，避免因文件过大导致处理失败。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `REDIS_URL` | `redis://default:yourpassword@redis-server:6379/0` | 用于缓存套料计算结果、实时工序状态，保障低延迟的台账查询，适配高频数据更新需求 |
| `STORAGE_S3_ENDPOINT` | `http://minio.internal:9000` | 存储钣金展开图、套料图等大尺寸工程文件，适配私有云部署的存储需求 |
| `DB_MAX_LINK` | `20–30` | 适配多源数据库并发访问，避免连接池耗尽导致的台账生成失败 |
| 文件上传大小限制 | `1000 MB` | 兼容大型CAD图纸与套料图的上传需求，匹配该品类的文档尺寸特征 |
| 数据同步周期 | `每15分钟` | 匹配订单、换型的更新节奏，平衡实时性与服务器资源占用 |
| `FE_DOMAIN` | `https://fastgpt.yourdomain.com` | 配置前端访问地址，保障台账报告的正常生成与展示 |

## 容易做错的三处
- 现象：执行`docker-compose pull`时镜像下载超时或中断，耗时远超预期。原因：未配置国内镜像源加速拉取，私有部署时未提前缓存依赖镜像。
- 现象：启动多个服务副本后，出现台账数据重复生成的情况。原因：未配置`REDIS_URL`实现分布式锁，导致并发任务重复执行。
- 现象：上传套料图后，知识库索引速度过慢，无法及时生成对应台账。原因：未针对大尺寸工程图纸调整索引参数，导致解析与索引耗时过长。

## 怎么确认配好了
- 执行`docker-compose up -d`后，使用`docker ps`查看所有容器状态均为healthy，无异常退出日志。
- 上传一张钣金展开图，确认系统能正常解析并生成包含板材规格、折弯系数的台账字段，无解析失败报错。
- 启动2个服务副本，提交3个不同订单的台账生成任务，确认无重复数据或任务冲突。
- 访问`FE_DOMAIN`对应的前端页面，能正常加载预设的台账报告模板，并关联对应数据源生成完整报告。
