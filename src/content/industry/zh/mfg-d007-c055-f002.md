# 铸造（砂型、精密、压铸）的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类的数据覆盖铸造全流程的多源异构信息。数据来源包括ERP物料主数据、熔炼炉与测温仪、光谱仪、MES炉次记录、模具管理系统及客户图纸与技术条件。日常文档包含铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告、不合格品评审单，字段涵盖合金成分占比、熔炼温度、浇注参数、炉次号、模次、缺陷类型等，更新频率为每炉次、每批或每日。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据结构要求索引支持混合类型数据的向量转换，包括结构化的配料参数、半结构化的炉次记录及非结构化的缺陷评审文档。高频更新节奏要求索引支持增量更新，避免全量重建带来的性能损耗。字段的专业性较强，如合金成分、熔炼温度等参数的语义匹配需要适配铸造行业的术语体系，普通通用向量模型可能无法准确捕捉专业语义。同时，数据间存在强关联，如炉次与对应模具、缺陷的绑定关系，仅使用扁平化实体索引无法完整体现业务关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配铸造炉次记录、工艺卡等文档的平均长度，匹配`maxToken`的兼容范围 |
| 重叠长度 | 150–200 字符 | 保留跨分块的关键关联信息，如炉次号与对应缺陷的描述 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 150 | 适配单条结构化参数（如合金配料单）的关键字段token数，保证语义完整性 |
| 相似度阈值 | 0.72–0.80 | 平衡铸造专业参数的语义匹配精度与召回率，过滤无关的通用文档 |
| 单次搜索上限 | 前 8 条 | 匹配每炉次关联的模具、检验记录的常规数量，保证检索结果的相关性 |

## 容易做错的三处
- 现象：不同向量模型生成的结果无法统一匹配，检索结果出现语义偏差。原因：混用了语义维度不一致的向量模型，未统一使用适配铸造专业文本的模型。
- 现象：检索炉次与缺陷的关联关系时无结果返回。原因：仅使用了扁平化的实体索引，未配置实体关联索引，无法体现炉次、模次与缺陷的业务绑定关系。
- 现象：PDF格式的炉次记录解析后配料单字段为空。原因：未开启PDF增强解析的表格提取功能，导致结构化的配料数据无法被正确提取并生成向量。

## 怎么确认配好了
- 上传单条炉次记录的PDF文档与结构化配料数据，检查索引生成的向量是否包含合金成分、炉次号等关键业务字段。
- 输入包含专业术语的查询，如“某炉次的缩孔缺陷对应熔炼参数”，检查检索结果是否覆盖关联的模具履历、检验记录等数据。
- 查看索引任务的运行日志，确认增量更新的触发频率匹配每炉次的业务更新节奏。
- 测试多组不同语义的查询，确认检索结果的排序符合铸造业务的关联逻辑。
