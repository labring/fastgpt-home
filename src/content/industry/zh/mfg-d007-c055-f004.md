# 铸造（砂型、精密、压铸）的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
本品类数据来源包括ERP物料主数据、熔炼炉与测温仪、光谱仪、MES炉次记录、模具管理系统、客户图纸与技术条件。更新节奏为每炉次、每批或每日。日常文档涵盖铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告、不合格品评审单，包含合金元素含量数值、炉温、浇注温度、模次、回炉料占比、缺陷类型等字段，单位包含摄氏度、千克、件数。

## 这些特征在「工作流编排」这一环带来什么约束
多源分散的数据来源要求工作流需配置多个跨系统对接节点，确保各环节数据准确拉取。高频更新节奏要求工作流触发机制匹配炉次、批次或每日的更新周期，避免数据滞后或重复处理。专业字段的特殊性要求变量映射需严格对应合金成分、炉温、浇注参数等铸造专属参数，避免字段不匹配导致汇总错误。复杂的核对与追溯环节要求工作流需串联数据拉取、校验、汇总、追溯全流程，覆盖异常数据的拦截逻辑，确保台账数据的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据源节点配置 | 按ERP、熔炼设备、光谱仪、MES各创建1个独立节点 | 覆盖本品类全量数据来源，避免单节点故障影响全流程 |
| `variables`映射规则 | 按炉次ID、合金成分、炉温、模次映射为固定变量 | 匹配铸造台账的核心字段，确保汇总时参数准确关联 |
| `nodeId`绑定规则 | 按数据拉取、校验、汇总、报告生成依次绑定节点ID | 明确工作流执行顺序，避免节点执行逻辑混乱 |
| 超时阈值 | 300–600 秒 | 适配熔炼、光谱检测等设备数据拉取的实际耗时 |
| 异常触发节点 | 当配料比例异常、温度超出区间时触发告警节点 | 拦截不合格数据，避免后续汇总错误 |
| 输出格式配置 | 按结构化文档格式生成报告，包含炉次明细页 | 匹配铸造厂质量部门的常规归档与查看需求 |

## 容易做错的三处
- 工作流跨版本导入后变量映射丢失，现象为导入FastGPT v4.17.0版本后部分`variables`映射字段为空。原因是未保留铸造专属字段的映射关系，未校验节点间的变量绑定一致性。
- 基础图表无法正确引用台账变量，现象为图表显示无数据或字段名不匹配。原因是未将炉次ID、炉温等核心字段正确绑定到图表的轴变量，未匹配铸造台账的字段命名规则。
- HTTP请求节点的output未在执行结果中显示，现象为运行后无对应输出内容。原因是未在工作流中配置输出节点关联HTTP请求的返回数据，或未开启变量的输出开关。

## 怎么确认配好了
- 手动触发一次工作流，核对拉取的数据源是否包含本次炉次的配料单、炉温记录等对应文档。
- 检查`variables`映射的字段是否与铸造台账的核心字段一致，无字段名不匹配的情况。
- 模拟异常数据（如配料比例超出常规范围），确认异常触发节点是否正常启动告警流程。
- 查看工作流执行日志，确认各节点的`nodeId`执行顺序与配置一致，无超时或报错信息。
