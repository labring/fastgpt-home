# 铸造（砂型、精密、压铸）的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源包括ERP物料主数据、熔炼炉与测温仪、光谱仪、MES炉次记录、模具管理系统、客户图纸与技术条件。日常文档涵盖铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告、不合格品评审单，包含结构化与半结构化两类格式。数据更新以每炉次、每批为核心节奏，辅以每日汇总更新。数据字段包含炉次编号、模次、合金配料参数、测温数值、浇注参数、缺陷类型等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源与动态更新节奏，要求模型接入环节支持批量拉取不同系统的结构化与半结构化文档。单炉次数据的高频更新，会导致上下文总量快速膨胀，需限制单轮处理的最大上下文长度。专业术语如合金配料比例、浇注温度的表述存在行业专属定义，需配置问题优化环节完成指代消除与扩展，避免检索时出现指代不明确的问题。炉次与模次的关联关系是台账汇总的核心，需确保检索时能精准匹配相关字段，防止出现结果关联错误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的功能进行说明。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单炉次相关文档的总长度，避免因上下文溢出导致任务中断 |
| `temperature` | 0.1–0.3 | 保持合金、浇注等专业术语与数据的准确性，降低生成内容的随机性 |
| `quoteMaxToken` | 1500–2000 token | 确保检索到的炉次、模具相关文档片段能完整纳入上下文 |
| 问题优化 | 开启指代消除与问题扩展 | 解决行业术语与指代不明确的问题，提升检索匹配精度 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应地址 | 适配FastGPT的代理接入规范，确保模型请求正常路由 |
| `AIPROXY_API_TOKEN` | 填写申请的代理密钥 | 完成模型接入的身份验证，保障请求合法性 |

## 容易做错的三处
- 检索结果条数不符合预期，仅返回少量无关文档。原因是未开启问题优化环节，未完成指代消除与扩展，导致检索关键词匹配精度不足，无法精准关联炉次、模次等核心字段。
- 模型请求返回身份验证失败或401状态码。原因是`AIPROXY_API_TOKEN`配置错误，或未正确填写`AIPROXY_API_ENDPOINT`，导致请求无法通过身份校验。
- 生成的台账报告出现字段为空或数据关联错误。原因是未限制`maxContext`的长度，导致上下文过载覆盖了关键炉次、模次字段的关联逻辑，或检索时未匹配到对应文档片段。

## 怎么确认配好了
- 发起一次单炉次的台账汇总测试，检查生成报告中是否包含该炉次的所有核心字段数据。
- 查看模型请求日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置与部署环境匹配。
- 输入包含指代的查询，如“本次炉次的不合格品情况”，检查是否能正确关联到对应炉次的相关文档。
- 调整`temperature`参数，观察生成内容的专业术语表述是否保持稳定，无明显随机偏差。
