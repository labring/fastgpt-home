# 锻造与模锻的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
锻造与模锻的生产数据来自原材料质保书、加热炉系统、压力机采集数据、MES、无损检测仪、客户锻件图等多类来源。日常需处理的文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告等。数据更新频率为每件、每批或每炉次一次，核心字段包含锻件批次号、炉批号、加热温度、保温时长、压力参数、模具编号、检测缺陷类型及寿命周期，单位涵盖℃、min、MPa等。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流需对接多个独立采集节点，避免不同系统的数据格式冲突。高频更新节奏要求工作流支持批量并发处理，适配每炉次、每批次的快速台账生成需求。丰富的文档与字段要求需精准配置变量映射规则，确保核心关联字段（如锻件批次号）贯穿全流程。同时，锻件缺陷处理的严格要求需加入校验与失败重试环节，防止不合格数据流入后续报告生成步骤。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 数据源节点配置 | 按原材料质保书、加热炉系统等6类数据源分别创建独立节点 | 匹配该品类多源异构数据的采集需求 |
| 并发执行阈值 | 5–10 条/次 | 适配每炉次/每批锻件的批量数据处理节奏 |
| `variables` 映射规则 | 将锻件批次号、炉批号设为全局变量 | 统一贯穿全工作流的核心关联字段 |
| 错误重试次数 | 2–3 次 | 应对临时的系统连接波动 |
| 节点超时设置 | 600 秒 | 匹配加热炉记录、超声检测报告的常规生成周期 |
| `nodeId` 绑定规则 | 按锻件批次号绑定对应节点实例 | 避免批量运行时的节点冲突 |

## 容易做错的三处
- 工作流节点出现`500 Gateway forwarding error because service is disconnected`报错，原因是未为每个锻件批次绑定独立`nodeId`，批量运行时服务连接被重复占用断开。
- 工作流模型图标不显示且文件上传提示网络错误，原因是未清理前端缓存且节点超时设置未适配超声检测报告等大文件的上传节奏。
- 工作流运行时出现offset类数据偏移错误，原因是`variables`映射时未匹配下料卡与锻造过程卡的字段对应关系，导致数据读取位置异常。

## 怎么确认配好了
- 手动输入单炉次锻件的测试数据，运行工作流，检查各数据源节点是否正常拉取对应文档。
- 配置批量运行阈值为5条/次，提交5个批次的测试数据，确认节点并发执行无冲突。
- 查看`variables`全局变量面板，确认锻件批次号、炉批号等核心字段已正确映射。
- 模拟单次节点断开场景，检查是否触发错误重试机制并恢复运行。
