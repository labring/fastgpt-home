# 锻造与模锻的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来源包括原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图。日常文档涵盖锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单与超声检测报告。数据按每件、每批或每炉次更新，字段包含锻件批号、加热温度（℃）、成型压力（kN）、模具使用次数、检测缺陷类型等，部分文档附带结构化参数与非结构化检测图像。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源与按炉次、批次的更新节奏，要求模型接入时需支持跨系统数据的关联匹配。日常文档包含结构化参数与非结构化检测图像，需配置适配多格式内容的解析逻辑。字段包含温度、压力等数值型数据与缺陷类型等枚举项，需明确字段映射规则以保证台账汇总的准确性。高频更新的单批次数据量有限，需限制单次处理的上下文规模，避免超出模型承载上限。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vision` | 开启，仅绑定超声检测报告图像 | 该品类的超声检测报告包含非结构化缺陷图像，需启用视觉能力解析相关信息 |
| `maxContext` | 8000–12000 token | 单炉次关联的台账数据量适中，该区间可覆盖完整批次的关联文档，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 单份生产台账汇总报告的输出长度需适配内容规模，防止输出内容被截断 |
| `quoteMaxToken` | 500–800 token | 限制引用的单份文档片段长度，保证上下文整洁性与数据关联准确性 |
| `temperature` | 0.1–0.3 | 生产台账汇总需保持数据准确性，不宜使用过高的随机性参数 |
| `AIPROXY_API_ENDPOINT` | 填写国内合规的代理接口地址 | 符合数据本地化要求，规避跨境数据传输的合规风险 |
| `AIPROXY_API_TOKEN` | 填写对应代理接口的认证令牌 | 完成模型调用的身份验证 |

## 容易做错的三处
- 现象：模型无法解析超声检测报告中的图像，或解析结果为空。原因：未启用`vision`配置项，或未指定图像绑定的文档类型，导致视觉能力未被触发。
- 现象：调用模型时返回认证失败提示，或接口返回401/403状态码。原因：`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`配置错误，未匹配当前使用的模型服务的认证信息与接口地址。
- 现象：生成的生产台账中部分字段缺失或单位标注错误。原因：`maxContext`配置区间过小，导致部分关联的工艺参数、检测数据未被纳入上下文，模型无法完整提取信息。

## 怎么确认配好了
- 上传一份包含超声检测图像的锻造过程卡，检查模型是否能识别并提取图像中的缺陷描述。
- 调用模型生成单炉次的台账汇总，核对输出内容是否包含所有配置的字段信息。
- 查看模型调用日志，确认`vision`、`AIPROXY_API_TOKEN`等配置项的参数值与预设一致。
- 测试多批次数据的关联汇总，确认模型能正确匹配不同来源的同批次锻件数据。
