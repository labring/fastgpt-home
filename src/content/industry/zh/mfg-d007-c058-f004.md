# 预制混凝土构件的生产台账汇总与报告生成：工作流编排

## 这个品类的数据长什么样
预制混凝土构件的生产数据来源包括BIM或深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检验报告及二维码追溯数据。日常生成的文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据更新节奏为单件、每批或每窑同步更新，字段涵盖构件编号、钢筋规格型号、混凝土强度等级、养护时长、脱模强度值、出厂检验编号等，单位涉及MPa、小时、件等。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据来源分散且更新节奏各异，工作流需支持多数据源节点的并行拉取与整合，避免单节点阻塞导致流程中断。不同构件的字段关联逻辑复杂，例如脱模强度需匹配对应养护窑的时长参数，工作流需绑定`variables`存储关联规则，防止字段错位。单件、每批的更新要求工作流支持按触发节点灵活启动，不采用固定周期触发，同时需内置校验环节，对缺失的钢筋下料单或检验记录进行拦截，避免无效台账生成。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量 | 绑定`variables`存储构件编号、混凝土批次号等核心字段 | 适配多数据源的字段关联需求，避免重复录入与字段错位 |
| 节点触发条件 | 按`nodeId`绑定模台完成、养护窑完成节点 | 匹配单件、每批的更新节奏，按需启动工作流 |
| 表单输入节点 | 隐藏嵌套应用中的对话框 | 解决应用嵌套时的弹窗显示问题，符合台账录入的静默需求 |
| 自定义代码调用 | 绑定本地Python代码函数处理钢筋下料单校验 | 实现业务逻辑的自定义扩展，适配预制构件的专属校验规则 |
| URL参数传递 | 支持通过分享URL带入`variables`参数 | 实现跨应用的参数传递，适配多场景的台账汇总 |
| 工作流超时时间 | 300–600 秒 | 适配单批次构件的台账汇总与报告生成时长，避免流程阻塞 |
| 单次校验上限 | 按实测标定 | 适配不同规模的构件批次校验需求 |

## 容易做错的三处
- 现象：嵌套应用内的表单输入节点弹窗持续显示，无法自动隐藏。原因：未针对嵌套工作流配置弹窗隐藏规则，导致默认弹窗逻辑未适配子应用场景。
- 现象：通过分享URL带入的全局变量未生效，台账字段为空。原因：未将`variables`参数正确绑定到URL传递配置中，导致参数无法被工作流读取。
- 现象：自定义Python代码函数执行失败，工作流报错。原因：未在工作流中配置代码节点的触发依赖，导致流程未按预期调用代码逻辑。

## 怎么确认配好了
- 触发绑定了`nodeId`的模台完成节点，检查工作流是否自动启动且无弹窗弹出。
- 生成带测试参数的分享链接，打开后检查台账中是否正确带入对应全局字段。
- 运行自定义代码节点，查看工作流日志是否显示代码执行成功。
- 核对生成的台账报告，确认所有来源的文档数据均已正确整合。
