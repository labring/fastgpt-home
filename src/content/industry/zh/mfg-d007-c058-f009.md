# 预制混凝土构件的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
预制混凝土构件的生产数据来源包括BIM深化设计文件、钢筋下料单、模具检验记录、浇筑振捣日志、养护台账、脱模与出厂检验报告。数据从BIM或深化设计系统、钢筋与混凝土批次管理、模台与养护窑设备、试验室检测记录、二维码追溯系统采集，更新频率为每件构件、每批物料、每窑养护周期。数据字段包含构件编号、强度等级、浇筑时间、养护时长、脱模强度、预埋件位置等，单位涉及MPa、立方米、小时、件等，单批次数据涵盖多份关联文档，且与现场吊装位置一一对应。

## 这些特征在「模型接入与配置」这一环带来什么约束
预制混凝土构件的多源、分批次更新的数据特征，要求模型接入配置需适配多文档上下文的整合能力。单批次数据涵盖深化图、下料单等多份关联文档，需配置足够的上下文窗口，避免截断关键台账字段。数据更新频率为每件、每批，需匹配实时或准实时的调用需求，需限制模型调用的响应时长。数据字段包含强度、时长等严谨数值，需保障数据提取与汇总的准确性，需限制模型生成报告的内容符合工程字段的严谨性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写绑定自定义量化模型的OneAPI中转地址 | 实现预制混凝土构件台账场景的大模型接入 |
| `AIPROXY_API_TOKEN` | 填写对应平台生成的访问密钥 | 完成模型接入的身份验证 |
| `temperature` | 0.1–0.3 | 保障台账数据的数值提取与汇总准确性，适配预制构件强度、批次等严谨字段的处理 |
| `maxContext` | 8000–12000 token | 覆盖单批次构件的深化图、下料单、养护记录等多文档上下文 |
| `maxTokens` | 2000–3000 token | 限制单条台账报告的生成长度，适配预制构件台账的常规输出规模 |
| `quoteMaxToken` | 1500–2000 token | 限制引用的台账原始文档的最大token数，避免上下文过载 |

## 容易做错的三处
- 更换模型后仍提示原模型错误，界面显示模型加载失败。原因是配置文件中`llmModels`数组未正确更新，仅保留了第一个模型的配置，未替换全部模型条目，导致系统仍调用初始模型。
- 部署后无法加载配置文件中的模型，页面显示接口无响应。原因是`AIPROXY_API_ENDPOINT填写错误，未匹配自定义模型的接口地址，或`AIPROXY_API_TOKEN未验证通过。
- 台账报告生成后出现截断，输出内容不完整。原因是`maxTokens设置值过小，未覆盖预制构件台账的完整输出长度，或`maxContext未适配多源文档的上下文总量。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型管理页面，查看已配置的模型列表，确认目标模型已正确显示。
- 发起单批次预制构件台账的测试提问，观察模型是否能正确提取构件编号、强度等级等字段，无报错信息。
- 生成完整台账报告，检查输出长度是否符合预设阈值，无截断情况。
- 验证OneAPI接口的调用日志，确认每次提问均能正常返回响应数据。
