# 预制混凝土构件的生产台账汇总与报告生成：部署与升级

## 这个品类的数据长什么样
预制混凝土构件的生产数据来源包括BIM或深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检测报告及二维码追溯系统。日常生产文档涵盖构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据更新频率为单件构件、每批物料、每窑养护周期同步更新，字段包含构件编号、钢筋用量、混凝土强度、养护时长、脱模日期等，对应单位涵盖MPa、立方米、天等。

## 这些特征在「部署与升级」这一环带来什么约束
预制混凝土构件的生产数据来源分散且更新频繁，部署时需配置多源数据接入适配项，保障各系统台账的同步效率。由于数据更新频率覆盖单件、每批、每窑，高频的写入操作会增加数据库负载，需提前调整连接池参数避免性能瓶颈。同时生产文档包含工程图纸、检测记录等多格式非结构化与结构化数据，存储配置需兼容多类型文件上传。此外构件与现场吊装位置一一对应，台账字段需精准映射，升级时需预设字段匹配规则避免数据错位，防止出现预埋错位、构件报废等风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–15 | 适配预制混凝土构件高频更新的台账数据，避免数据库连接池耗尽 |
| `PG_URL` | postgresql://username:password@host:5432/pc_component_db | 存储结构化台账数据，匹配钢筋用量、养护记录等业务字段结构 |
| `REDIS_URL` | redis://:password@host:6379/0 | 缓存高频查询的构件溯源二维码关联数据，降低数据库读写压力 |
| `STORAGE_S3_ENDPOINT` | s3-cn-east-1.qiniucs.com | 存储构件深化图、浇筑记录等非结构化文档，兼容多格式文件上传 |
| `FILE_TOKEN_KEY` | 按实测标定 | 加密台账文件访问令牌，保障脱模检验报告等敏感文档的访问安全 |
| `ROOT_KEY` | 随机生成32位字符串 | 配置平台管理员初始权限，符合预制构件工厂的权限管控要求 |

## 容易做错的三处
- 访问台账生成接口返回504 Gateway Timeout，原因是未调整`DB_MAX_LINK`参数，高频更新的台账数据导致数据库连接池耗尽，请求无法及时响应。
- 知识库同步后无法检索到钢筋下料单，原因是未正确配置`STORAGE_S3_ENDPOINT`，非结构化文档未成功上传至指定存储节点，导致同步任务失败。
- 生成的报告中预埋位置信息缺失，原因是预设的字段映射规则未覆盖BIM深化图的预埋坐标字段，导致数据未正确关联至生产台账。

## 怎么确认配好了
- 执行数据库连接测试，验证`PG_URL`和`DB_MAX_LINK`配置可正常建立并维持10–15个连接。
- 上传一份钢筋下料单至平台，检查`STORAGE_S3_ENDPOINT`配置下的存储节点是否成功接收该文件。
- 触发一次台账汇总任务，检查生成的报告中是否包含构件编号、混凝土强度等预设业务字段。
- 登录FastGPT v4.17.0平台后台，使用`ROOT_KEY`验证管理员权限配置是否生效。
