# 预拌混凝土生产的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自商品混凝土搅拌站控制系统、工程项目试验室、质量与调度部门，涵盖配合比通知单、开盘鉴定、生产运输单、原材料检验报告、试块记录、强度报告等文档。数据更新频率为每车生产记录、每批原料检验结果、每日汇总台账，字段包含原料批次编号、含水率数值、坍落度指标、强度检测值等，单位涉及千克、立方米、兆帕等，单份文档内容随生产流程动态更新。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类高频次、多维度的数据特征，对向量模型与索引环节带来多重约束。数据按每车、每批原料高频更新，要求索引支持增量同步机制，避免全量重建带来的计算开销。文档涵盖结构化数值与非结构化描述，需配置兼容混合字段的向量化规则，确保不同类型数据的向量表达一致性。批量生产记录与检验报告的总数据量较大，需限制单批次索引的总容量，防止服务器负载过载。同时，需建立批次编号与文档的关联索引，保障台账汇总时可快速匹配对应生产环节的全量数据。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配预拌混凝土生产台账中单份文档的平均长度，避免单块包含过多跨批次数据 |
| 重叠长度 | 100–200 字符 | 保留相邻块的批次编号关联信息，防止索引时丢失生产环节的上下文关联 |
| 相似度阈值 | 0.75–0.85 | 区分不同生产批次的台账数据，避免将相似的原料检验记录误关联 |
| 单次搜索上限 | 前 20 条 | 匹配搅拌站日常查询的常用数据量，平衡检索效率与结果完整性 |
| `defaultToken` | 1024 token | 符合主流向量模型的输入限制，适配台账文档的分块内容长度 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 现象：上传10M以上的原材料检验报告或生产运输单时，部分chunk显示向量化异常，界面显示向量生成失败的状态标记。原因：未按照适配场景的分块长度配置参数，部分分块内容超出`defaultToken`的1024 token限制，导致模型无法完成向量化。
- 现象：Ubuntu系统下部署的本地向量服务重启后，已上传的预拌混凝土台账知识库显示未就绪，无法自动恢复索引流程。原因：未配置索引断点续传与自动重试规则，服务器异常中断后未保留未完成的索引进度，导致需手动触发重建。
- 现象：汇总多车生产台账时，检索到的关联试块记录出现遗漏，检索结果条数与实际匹配数量不符。原因：单次搜索上限设置过低，未覆盖当前批次生产对应的全部关联文档，导致检索结果不完整。

## 怎么确认配好了
- 上传一份单批次的生产运输单文档，检查分块后的每个chunk的内容长度是否符合预设的分块参数，无超长块提示。
- 触发一次台账汇总任务，查看向量检索环节的日志，确认无向量化失败的chunk记录，索引进度正常完成。
- 检索特定批次编号的生产数据，核对返回的关联文档数量与实际生成的文档数量一致，确认关联索引生效。
- 调整`maxToken`参数后，测试加载多份关联文档，确认生成的汇总报告可覆盖全部关联数据，无内容截断。
