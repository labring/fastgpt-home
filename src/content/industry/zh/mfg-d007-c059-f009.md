# 预拌混凝土生产的生产台账汇总与报告生成：模型接入与配置

本文档基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
预拌混凝土生产的数据来源包括工程订单、砂石水泥外加剂检验记录、含水率测定数据、搅拌站控制系统、工程项目试验室台账。数据更新频率覆盖每车生产记录、每批原料检验、每日汇总统计。日常文档包含配合比通知单、开盘鉴定、生产运输单、原材料检验报告、试块记录、强度报告，字段涉及配合比参数、骨料含水率、坍落度要求、强度等级、运输车次、浇筑时间等，单位包含立方米、千克、百分比、兆帕等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类数据来源分散，覆盖生产、检验、运输多业务环节，高频更新的特性要求模型接入环节支持实时或近实时的数据同步。文档包含大量工程专业术语与结构化字段，要求模型能精准识别并关联不同来源的台账信息。动态变化的运输与浇筑数据，要求模型能关联时序化的生产记录生成报告。同时工程质检报告需符合固定格式，对模型输出的格式稳定性有较高要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 绑定搅拌站中控系统的专属代理地址 | 适配多数据源的权限隔离需求，保障生产数据调用安全 |
| `AIPROXY_API_TOKEN` | 与搅拌站系统绑定的专属访问密钥 | 限制仅授权的生产台账数据可被模型调用 |
| `maxContext` | 8000–12000 token | 容纳单批次原料检验、3-5车运输记录、当日试块报告的完整上下文 |
| `maxTokens` | 2000–2500 字符 | 满足工程质检报告的完整输出长度，避免截断关键专业参数 |
| `temperature` | 0.1–0.3 | 降低输出随机性，保障配合比、坍落度等核心参数的准确性 |
| `toolChoice` | auto | 自动调用工具获取实时骨料含水率数据，修正配合比计算结果 |

## 容易做错的三处
- 模型输出的Markdown格式不稳定，出现配合比参数换行错位、强度报告字段缺失。原因是未设置合理的`maxTokens`参数，导致输出被强制截断破坏格式。
- 配置`AIPROXY_API_TOKEN`后仍无法调用模型。原因是未将代理地址与对应生产系统的访问权限绑定，导致请求被拦截。
- 多用户并发调用时出现请求超时。原因是`maxContext`设置过大，导致上下文加载耗时超出系统阈值。

## 怎么确认配好了
- 上传单批次原料检验单与对应生产运输单，触发台账汇总任务，检查输出的Markdown格式是否完整，无字段缺失。
- 调用代理地址与密钥发起测试请求，确认返回结果包含搅拌站系统的实时含水率数据。
- 发起3-5个并发测试请求，确认无超时报错且输出结果一致。
- 调整`temperature`参数至0.2，多次触发同一份台账的报告生成，确认输出的专业参数无明显偏差。
