# 饮料与瓶装水的生产台账汇总与报告生成：向量模型与索引

## 这个品类的数据长什么样
该品类覆盖碳酸、果汁、茶饮、功能饮料及包装饮用水工厂，日常文档包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验单、成品检验单。数据来源包括水源与原料检测系统、配方管理系统、在线糖度酸度监测设备、灌装生产线、视觉检测装置及LIMS系统。数据更新节奏为每批生产、每班运维及连续采集模式，字段包含投料量、检测数值、设备运行参数、批次编号与检测时间，附带对应计量单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。多源异构的数据来源导致字段格式不统一，需明确标准化的字段映射规则，确保嵌入向量的一致性。高频连续采集的生产数据会生成大量小型文档，需调整分块逻辑避免索引存储冗余。批次关联的生产数据要求索引支持按批次维度的精准召回，便于台账汇总时快速关联同批次全流程记录。高精度计量数值与文本描述混合的文档，需适配兼顾结构化与非结构化数据的嵌入模型。核心环节的异常数据需实时检索，索引的召回延迟需匹配生产运维的响应要求。

## 配置怎么定
本配置适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配单批次生产记录的完整内容，避免割裂同批次关联数据 |
| 重叠长度 | 100–200 字符 | 保留批次编号、核心参数等跨块关联信息，防止关键字段截断 |
| 相似度阈值 | 0.75–0.85 | 过滤低相关性历史台账，避免汇总时混入无关批次记录 |
| 最大上下文 | 4000–6000 token | 适配多份检验记录与生产参数的合并召回，满足报告生成需求 |
| defaultToken | 1024 | 控制单条嵌入向量输出长度，平衡索引存储与检索精度 |
| maxToken | 8192 | 适配批量台账的向量嵌入上限，满足高频数据的批量处理需求 |

## 容易做错的三处
- 检索生产台账时返回大量无关批次的记录。原因是相似度阈值设置过低，未过滤低相关性的历史数据。
- 向量模型配置后无法正常启动，界面显示配置报错。原因是未按品类的多源异构字段结构调整嵌入映射规则，导致字段格式不兼容。
- 批量导入多份检验记录时出现超时错误。原因是未调整`defaultToken`与`maxToken`参数，单条嵌入长度超出系统默认限制，导致处理延迟。

## 怎么确认配好了
- 导入单批次的完整生产记录，执行台账汇总测试，检查召回的文档是否仅包含该批次的相关数据。
- 查看索引存储占用情况，确认分块长度与`defaultToken`的设置未导致存储资源过载。
- 模拟异常数据检索场景，验证相似度阈值的设置是否能过滤无关的历史台账内容。
- 批量导入多份不同班次的生产记录，确认索引支持按批次维度的精准召回。
