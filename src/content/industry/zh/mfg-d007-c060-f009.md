# 饮料与瓶装水的生产台账汇总与报告生成：模型接入与配置

## 这个品类的数据长什么样
该品类的生产数据来源包括水源与原料检测、配方系统、在线糖度酸度监测、灌装设备、视觉检测系统与LIMS系统。日常台账文档包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验单、成品检验单，字段涵盖糖度值、酸度值、灌装液位参数、批号、无菌参数等，更新频率为每批、每班或连续采集，单批次台账数据量随生产节奏快速累积，部分记录需关联多系统的同步数据。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的台账数据来源分散且更新节奏快，需同时处理多份来自不同系统的文档，因此模型输入的上下文容量需适配单批次全流程的总数据量。字段多为带单位的精准数值与生产标识，生成报告时需严格匹配字段定义，因此模型生成的精度要求较高。连续采集的实时数据会随生产节奏快速累积，需限制单次调用的token消耗，避免超出模型上下文上限。部分记录涉及无菌控制与添加剂投料，需确保解析结果的准确性，因此模型的随机性参数需控制在较低区间。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配单批次全流程包含多份台账的总数据量，避免输入截断 |
| `maxTokens` | `4000–6000 token` | 匹配生产汇总报告的常规生成长度，避免输出被强制截断 |
| `temperature` | `0.1–0.3` | 降低生成随机性，确保台账字段与数值的准确性，符合生产合规要求 |
| `vision` | 关闭 | 该品类台账文档多为文本格式，无内嵌图片或视觉解析需求，避免无效解析消耗资源 |
| `AIPROXY_API_ENDPOINT` | 填写本地部署大模型的API访问地址 | 实现本地大模型的接入，适配企业内部部署的部署需求 |
| `AIPROXY_API_TOKEN` | 填写本地模型的访问密钥 | 验证模型接入权限，确保合法调用本地部署的大模型 |

## 容易做错的三处
- 界面显示请求失败，上传台账后解析耗时超过2分钟后终止。原因是`maxContext`设置未覆盖单批次全流程台账的总数据量，导致模型无法加载完整输入，或本地模型的`AIPROXY_API_ENDPOINT`配置错误，无法建立连接。
- 模型调用提示token超出限制，生成报告失败。原因是未按本地模型的token计数规则配置`maxTokens`与`maxContext`，导致实际输入输出的总token数超出模型支持范围。
- 开启`vision`后上传内嵌图片的文档无解析结果。原因是未配置视觉解析模型的接入参数，或该品类台账无需图片解析功能，开启后会尝试解析无效内容导致任务异常。

## 怎么确认配好了
- 上传单份标准配方单文档，触发台账汇总任务，检查任务状态显示完成且无报错提示。
- 查看FastGPT v4.17.0的模型调用日志，确认实际使用的上下文与token值未超出配置的上限范围。
- 输入包含添加剂投料字段的查询，确认返回结果包含准确的字段名称与对应数值单位。
- 测试本地模型接入，检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的连接状态正常，无权限报错。
