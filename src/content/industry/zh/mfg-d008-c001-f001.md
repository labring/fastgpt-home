# PCB制造的设备点检与维修问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类的数据来自客户提供的Gerber文件、钻带、BOM，以及CAM系统、生产设备参数、槽液化验结果、AOI检测报告、电测报告与实验室切片报告。日常文档包含工程制作指示、钻孔与层压参数、药水分析记录、故障维修台账等。数据更新随生产批、每班频次触发，部分设备参数与检测数据连续采集。数据字段涵盖图形尺寸、孔位坐标、槽液浓度、检测缺陷类型、维修记录编号等，无统一固定单位，随对应文档场景调整。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的数据来源分散且格式多样，HTTP接口需兼容结构化的CAM参数、时序化的设备采集数据、半结构化的检测报告等多种格式，需内置基础的格式解析适配逻辑。数据更新频次差异显著，接口需支持按需触发与定时拉取两种调用模式，匹配生产批、每班的更新节奏。数据字段无统一单位，接口返回需保留原始文档的字段与单位标识，避免二次转换误差。同时因出错后果严重，接口的超时与重试配置需匹配生产流程的容忍阈值，防止异常中断生产环节。

## 配置怎么定
本页面基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | 固定Bearer令牌加工厂专属密钥 | 用于禁止匿名访问，匹配PCB工厂的安全管控要求 |
| `variables` | 传入`{"device_type": "钻孔机", "report_type": "AOI"}`的固定键值 | 限定接口调用的检索范围，聚焦对应设备的点检与维修数据 |
| `responseData` | 仅返回`device_id, fault_time, repair_record`字段 | 减少无效数据传输，适配生产场景下的快速检索需求 |
| 最大上下文 | 前 2000 字符 | 保留足够的设备历史参数与检测记录，支撑维修问答的上下文关联 |
| 单次搜索上限 | 前 10 条 | 控制返回结果的数量，避免过多数据占用接口带宽与处理时间 |
| 超时时间 | 60 秒 | 匹配生产流程的响应容忍度，防止因接口卡顿中断点检流程 |

## 容易做错的三处
- 现象：接口调用返回数据库连接失败的状态码500，重启服务后仍无法恢复。原因：未配置生产环境MySQL的访问权限，或连接字符串中的端口、账号参数填写错误。
- 现象：调用接口后返回`401 Unauthorized`报错，无法完成问答交互。原因：未正确设置`Authorization`参数，或使用了与FastGPT平台不匹配的令牌密钥。
- 现象：并发调用接口时出现部分请求被丢弃或超时。原因：未根据生产场景的并发需求调整接口的并发处理阈值，导致请求队列溢出。

## 怎么确认配好了
- 调用配置好的HTTP接口，传入合法的`Authorization`令牌与`variables`参数，检查返回的`responseData`是否包含预期的设备点检与维修记录。
- 模拟生产场景下的并发请求，观察接口的响应状态，调整相关配置直至无明显超时或报错。
- 检查外部系统的对话页面，确认可以正常加载接口返回的维修记录与参数数据，无字段缺失或格式异常。
- 调用接口时传入错误的`Authorization`参数，确认返回`401 Unauthorized`报错，验证匿名访问拦截功能生效。
