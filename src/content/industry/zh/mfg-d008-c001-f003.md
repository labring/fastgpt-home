# PCB制造的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自印制电路板工厂的工程、生产、品质与实验室团队，日常文档包含工程制作指示、Gerber解析记录、钻孔与层压参数、药水分析报告、AOI检测报告、电测报告及切片报告。数据来源覆盖客户Gerber文件、钻带、BOM清单、CAM文件、设备运行参数、槽液化验结果、AOI与电测设备采集数据及实验室检测记录，更新节奏为每生产批、每班或连续采集，字段包含工艺参数、检测结果、设备运行状态等，随生产环节动态变化。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据来源分散，包含工程图纸、工艺参数、检测报告等多类文档，多轮对话需明确提示词区分不同文档的调用优先级，避免混淆不同环节的工艺要求。数据更新频率随生产批、班次动态变化，对话上下文需限定在当前生产批次的有效数据范围内，防止调用过期参数导致错误。同时，设备点检与维修涉及整批报废风险，多轮对话需保留历史交互记录，用于追踪异常的连续变化过程，辅助定位故障根源。

以下配置基于FastGPT v4.17.0版本。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前生产工单ID | 区分不同生产批次的对话上下文，避免跨工单数据混淆 |
| `messages` | 保留最近10轮交互与当前生产批数据 | PCB工艺异常需追踪多步骤排查过程，避免上下文溢出 |
| `variables` | 传入当前工单的Gerber编号、设备型号 | 精准匹配对应生产数据与设备点检记录 |
| 最大上下文长度 | 800–1200 字符 | 平衡单轮对话信息承载量与响应速度，适配PCB工艺参数的文本长度 |
| 输入长度拦截 | 1500 字符阈值 | 防止超出AI模型输入上限触发报错，符合用户实际输入场景 |

## 容易做错的三处
- 现象：对话请求接口返回结果无cite引用id字段。原因：未开启对话上下文的源数据关联配置，未绑定对应文档的引用标识。
- 现象：输入文本超过预设阈值后触发接口报错，无提前拦截提示。原因：未配置输入长度校验规则，直接提交请求至AI模型。
- 现象：无法直接接入jpg格式的设备点检照片。原因：未添加文件转文本的前置处理节点，仅开放了纯文本输入通道。

## 怎么确认配好了
- 发起包含Gerber编号与设备型号的测试对话，确认`variables`参数已正确传入，对话上下文能关联对应生产数据。
- 输入超过预设阈值的测试文本，确认系统提前拦截并提示输入超限，未触发接口报错。
- 上传jpg格式的点检照片，确认系统能完成解析并将文本内容纳入对话上下文。
- 发起多轮排查对话，确认`chatId`绑定当前工单ID，历史交互记录能正常保留与调用。
