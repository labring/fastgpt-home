# PCB制造的设备点检与维修问答：工具调用与插件

## 这个品类的数据长什么样
这个品类的数据来自印制电路板工厂的工程、生产、品质与实验室岗位，日常文档包含工程制作指示、Gerber解析记录、钻孔和层压参数、药水分析、AOI报告、电测报告、切片报告。数据来源覆盖客户Gerber/钻带/BOM、CAM、设备参数、槽液化验、AOI、电测和实验室数据，更新频率为每生产批、每班或连续采集，字段包含设备编号、检测批次、参数值、检测结果等，单位随对应生产环节的标准调整。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散且更新频率高，要求工具调用需支持对接多类数据源插件，确保能实时获取最新的设备参数、检测报告等信息。多类型的文档结构要求工具调用的参数需精准匹配对应文档的字段，避免因字段不匹配导致数据读取错误。连续采集的生产数据要求工具调用的触发时机需与生产节拍对齐，避免过度调用占用生产网络资源。出错会导致整批板报废或高额索赔，要求工具调用需具备失败重试与数据校验机制，保障调用结果的准确性。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配多数据源的设备点检场景，自动匹配Gerber解析、槽液化验、AOI检测等对应工具 |
| 单次工具调用超时 | 600 秒 | 对应钻孔、层压参数查询的复杂数据返回节奏，避免因数据量较大导致超时中断 |
| 工具调用失败重试次数 | 3 次 | 应对车间网络波动或设备数据接口临时不可用的场景，保障调用成功率 |
| 上下文窗口大小 | 8000–12000 token | 容纳多份AOI报告、电测报告的完整内容，避免因上下文截断丢失关键信息 |
| `functionCall` | 强制校验参数格式 | 确保传入的设备ID、检测批次号符合PCB制造的字段规范，避免无效参数调用 |
| 插件数据源白名单 | 仅开放生产相关插件 | 限制非授权工具调用，避免泄露或误操作生产数据 |

## 容易做错的三处
- 现象：调用设备参数查询工具时返回空字段。原因：未在插件配置中绑定对应PCB制造的设备ID、检测批次等字段映射规则，导致工具无法匹配正确的数据源。
- 现象：部署MinIO存储插件后无法访问内网生产数据。原因：未正确配置插件的内网访问权限，误开启公网强制校验，不符合车间内网部署的实际场景。
- 现象：工具调用响应耗时超过预设阈值。原因：未设置合理的超时阈值，且未开启工具调用的异步队列，导致批量生产数据查询阻塞主线程。

## 怎么确认配好了
- 触发一次设备点检工具调用，核对返回的钻孔参数、槽液化验数据与本地生产记录一致。
- 模拟内网环境访问MinIO插件存储的AOI报告，确认可正常拉取文件。
- 查看工具调用日志，确认`functionCall`参数格式校验通过，无异常报错。
- 批量触发3次工具调用，确认响应时间符合生产节奏的要求。
