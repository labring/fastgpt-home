# PCB制造的设备点检与维修问答：表单与交互

## 这个品类的数据长什么样
这个品类的数据来自印制电路板工厂的工程、生产、品质与实验室岗位，日常文档包含工程制作指示、Gerber解析记录、钻孔和层压参数、药水分析、AOI报告、电测报告、切片报告。数据来源涵盖客户Gerber/钻带/BOM、CAM、设备参数、槽液化验、AOI、电测和实验室数据，更新频率为每生产批、每班或连续采集，字段包含工艺参数、检测结果、设备状态等，无统一固定单位，字段与单位随文档类型动态调整。

## 这些特征在「表单与交互」这一环带来什么约束
由于数据来源覆盖多岗位多系统文档，且更新频率随生产批次、班次变化，表单与交互环节需支持多源字段的关联绑定，避免重复录入同一生产批次的关联数据。不同文档的字段结构差异大，交互需提供自定义字段模板，适配工程制作指示、AOI报告等不同类型的点检维修文档。生产数据出错会导致整批板报废，表单需添加实时校验逻辑，对异常参数触发提醒。连续采集的设备状态数据需支持流式录入，适配实时点检场景。

## 配置怎么定
本文适配FastGPT v4.17.0版本，以下配置基于该版本的表单与交互模块：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 绑定设备编号、点检时间、生产批次字段 | 适配PCB制造设备点检的标准化录入需求，确保数据可关联到对应生产环节 |
| `userSelect` | 预设维修班组、故障类型、设备型号选项 | 匹配工厂现有运维人员分工与PCB设备的分类体系 |
| 分块长度 | 800–1200字符 | 适配PCB制造文档的单页参数长度，避免分割破坏工艺参数的完整性 |
| 重排 | 开启，取前6条结果 | 针对多源检索的冗余信息，优化问答匹配精度，适配工厂点检维修的短查询场景 |
| 单次搜索上限 | 10条 | 控制检索返回量，避免过多无关数据干扰问答结果 |
| 最大上下文 | 6000 token | 容纳多层PCB的工程参数与多份检测报告的完整内容 |

## 容易做错的三处
- 现象：开启重排功能后，设备点检问答的响应时间明显延长。原因：未根据PCB文档的分块长度调整检索上限，导致过多冗余数据参与重排流程。
- 现象：添加团队成员时输入对应账号后提示用户名无效。原因：未配置工厂内部运维账号的映射规则，仅支持公开平台的账号格式匹配。
- 现象：导入Gerber或AOI报告时，页数持续刷新无法选择目标页面。原因：未启用PCB专用文档的解析适配开关，系统无法识别非通用文档的分页结构。

## 怎么确认配好了
- 导入单份标准PCB钻孔参数文档，核对表单字段是否与文档内容自动匹配绑定。
- 发起针对层压参数异常的问答，验证检索结果是否覆盖对应生产批次的设备参数与检测报告。
- 测试团队成员添加流程，确认输入工厂内部对应账号后无无效提示。
- 导入多页AOI报告，确认分页加载正常，可选择指定目标页面。
