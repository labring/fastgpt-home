# 乳制品加工的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
乳制品加工的设备点检与维修问答数据，来源包括奶源检测系统、生产MES系统、均质与热处理设备、在线温度流量监测装置、CIP清洗系统与LIMS实验室信息管理系统。数据更新节奏为每奶罐、每批实时同步，覆盖原奶验收记录、标准化配料单、巴氏或UHT热处理记录、CIP清洗记录、灌装生产记录、留样与微生物检测报告。文档结构以半结构化的批次关联数据为主，字段包含理化指标数值、设备运行参数、批次编号、检测结果等，单位随对应参数而定。

## 这些特征在「向量模型与索引」这一环带来什么约束
乳制品加工的实时高频更新、批次强关联的特征，要求向量索引支持增量更新与批次维度的精准过滤，避免冗余索引与跨批次干扰。半结构化的多类型文档混合场景，要求分块策略需兼顾单批次单设备参数的完整性与跨块关联信息的保留，防止关键故障排查线索被分割。数据出错后果严重的业务属性，要求向量召回的精度需严格控制，过滤低相关的历史日志与非目标批次数据。连续生产的流程特性，要求索引需关联批次与设备的唯一标识，确保点检问答能快速定位对应环节的历史记录。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面与参数规则：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 乳制品加工文档多为半结构化批次数据，单块覆盖单批次单设备的完整参数与操作记录 |
| 重叠长度 | 100–200 字符 | 保留批次关联信息与设备运行的连续上下文，避免跨块检索时丢失关键线索 |
| 相似度阈值 | 0.75–0.85 | 按实测标定，过滤低相关的历史日志与非目标批次数据，保障点检问答的精准性 |
| 单次搜索上限 | 前10条 | 设备点检与维修问答需快速定位同类故障，限制返回结果数量以提升响应速度 |
| `defaultToken` | 4096 | 适配乳制品加工批量文档的总长度，平衡索引存储与检索效率 |
| `maxToken` | 8192 | 匹配主流嵌入模型的上下文窗口，确保完整召回关联的批次与设备数据 |

## 容易做错的三处
- 现象为辅助数据未被纳入检索结果，界面搜索结果缺失原奶验收记录或留样检测报告。原因是未将非设备日志类的辅助数据源添加至索引配置范围，仅上传了设备运行日志文件。
- 现象为单组数据生成多组向量，检索结果出现跨批次的无关数据，且界面向量模型选项仅显示单一模型。原因是未按批次拆分数据块，错误将多批次的混合数据合并为单个索引块，导致向量关联逻辑混乱。
- 现象为本地生成的向量文档上传至服务器后无法正常检索，返回空结果或低匹配度内容。原因是本地与服务器使用了不同的向量模型，未统一嵌入维度与分词规则，导致向量空间不兼容。

## 怎么确认配好了
- 上传单批次的原奶验收记录与对应设备的热处理日志，等待索引生成进度完成后，检索该批次的抗生素指标关键词，确认召回结果包含目标文档。
- 调整分块长度与重叠长度参数后，检索同一设备的连续运行日志，验证召回结果覆盖相邻块的关联操作记录。
- 切换嵌入模型后，上传同一份CIP清洗记录文档，验证向量生成后的相似度计算结果符合预设的阈值规则。
- 上传多批次混合数据，检索特定奶罐的唯一标识，确认召回结果仅关联该奶罐的所有生产与检测记录，无跨批次干扰。
