# 仓储、批次与厂内物流的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
仓储、批次与厂内物流场景的核心数据通常来源于ERP/WMS系统、条码或RFID设备、采购工单、库位档案、AGV或输送系统、称重设备。日常交互涉及的文档包括收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录。数据更新节奏覆盖实时（如AGV状态、条码扫描数据）、每日（如盘点差异统计）、月度（如效期物料汇总），核心字段包含物料编码、批次号、库位号、效期、数量单位等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据来源分散且更新节奏差异大，多轮对话通常需跟踪不同时间维度的业务信息，避免重复确认批次、库位等核心字段。核心文档的字段结构固定，提示词需精准引导提取物料身份、效期等关键信息。跨工序的物料流向管理要求对话上下文保留历史库位、工单关联信息，确保账实一致的校验逻辑连贯。同时，账实差异、呆滞物料处理等场景通常需批量执行节点，对上下文的变量隔离有明确要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 保留最近10轮对话上下文 | 仓储、批次场景需跟踪批次号、库位变更等多轮交互的历史信息，避免重复确认 |
| `variables` | 绑定批次号、库位号、效期三个核心变量 | 品类核心数据字段为物料编码、批次、库位，需在对话中实时传递和校验 |
| 最大上下文长度 | 800–1200 字符 | 匹配日常仓储单据单条记录的长度，避免上下文过载影响回复准确性 |
| 工作流最大运行次数 | 1000 | 覆盖批量处理盘点差异、移库单审核等场景的节点执行需求 |
| 输入引导词库 | 绑定收货单、移库单等品类专属文档关键词 | 引导对话聚焦仓储业务场景，减少无关回复 |

## 容易做错的三处
- 对话界面未展示配置的预期引导问题。原因是未开启输入引导的前端渲染配置，或词库未绑定仓储品类专属的单据关键词。
- API调用返回的变量结果包含前一轮对话的内容叠加。原因是未正确重置`variables`的上下文缓存，导致多轮交互中历史变量值被重复带入。
- 无法复述上传的XLSX知识库内容。原因是未配置文档解析适配仓储表格的字段提取规则，导致知识库内容未被正确索引。

## 怎么确认配好了
- 发起包含批次号、库位号的多轮对话，检查对话上下文是否保留了历史交互的核心信息。
- 调用API测试变量传递，确认`variables`仅包含当前对话的核心字段，无历史内容叠加。
- 上传品类专属的XLSX单据文件，发起复述请求，确认知识库内容被正确识别。
- 触发批量执行节点，检查工作流运行次数未超过配置的上限。
