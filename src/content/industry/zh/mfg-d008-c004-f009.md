# 仓储、批次与厂内物流的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
通常覆盖原材料库、线边库、成品库及物流物控部门的业务数据。日常文档包含收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录。数据来源包括ERP/WMS系统、条码或RFID设备、采购与工单信息、库位记录、AGV输送系统及称重数据。更新节奏涵盖实时、每日同步及月度盘点，核心字段包含物料身份、批次编号、库位、效期及工单关联信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且更新节奏差异大，需适配多源数据的同步与关联，因此模型接入时需支持多数据源的格式转换。核心字段的关联性强，需确保检索内容覆盖物料批次、库位与效期信息，因此上下文窗口需足够容纳多类文档片段。出错后果直接影响生产流程，需严格校验检索结果的准确性，避免生成与实际仓储状态不符的点检建议。同时，文档类型多样，需配置合适的检索范围以覆盖不同业务场景的文档。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 需覆盖批次台账、库位信息、效期记录等多类文档，足够关联物料身份与工单信息 |
| `maxTokens` | 2000–3000 token | 设备点检与维修问答需输出详细排查步骤，避免截断关键操作指引 |
| `quoteMaxToken` | 1500–2000 字符 | 需引用收货单、盘点表等文档片段，确保检索内容完整覆盖物料批次与库位数据 |
| `toolChoice` | auto | 允许模型自主选择是否调用检索工具，适配多源数据关联的复杂问答场景 |
| `temperature` | 0.3–0.5 | 需保持检索结果的准确性，避免生成与实际物料批次、库位不符的内容 |
| `AIPROXY_API_TOKEN` | 按平台分配的专属密钥 | 适配多源数据接入的权限校验需求，确保数据调用安全 |

## 容易做错的三处
- 现象：模型生成的点检建议未关联当前工单的物料批次与库位信息，检索结果与实际仓储场景不符。原因：`maxContext`取值过小，未覆盖批次台账、库位记录等关键上下文数据。
- 现象：部署FastGPT v4.17.0后，OneApi页面无法加载，界面提示接口错误。原因：`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`配置错误，导致无法与模型提供商建立连接。
- 现象：新增默认模型提供商时无法通过界面直接操作，需提交PR修改代码。原因：未开启FastGPT的可视化模型管理功能，或未配置模型提供商的接入入口。

## 怎么确认配好了
- 提交包含物料批次与库位的点检问题，检查模型输出是否关联了对应批次台账与库位信息。
- 访问OneApi页面，确认页面正常加载，无接口报错提示。
- 测试接入的模型是否能正常生成带检索依据的维修建议，无截断或空结果。
- 调整`temperature`参数后，检查输出结果的一致性，确认配置生效。
