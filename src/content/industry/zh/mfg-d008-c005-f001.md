# 光伏电池片制造的设备点检与维修问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
光伏电池片制造的设备点检与维修问答相关数据，通常来自硅片来料、MES系统、扩散炉/镀膜设备/印刷机等生产设备、EL与IV测试设备及实验室数据。日常文档包含工艺卡、扩散和镀膜参数、印刷烧结记录、EL检测图、IV分档数据、良率报告。数据更新节奏覆盖每片检测、每批生产及每日汇总，字段包含批次编号、工艺参数、电性能得分、缺陷类型等，部分检测图为二进制格式文件。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
光伏电池片制造的数据来源分散且更新频率不均，要求HTTP接口支持多源数据的并发调用与格式兼容。不同类型文档的字段差异较大，部分数据包含二进制检测图，接口需支持多格式请求与返回。高频的每片检测数据会产生大量请求，接口需适配短周期的数据采集节奏，避免超时或限流。同时，设备点检与维修的结果直接影响生产工艺窗口，接口的稳定性直接关联产品转换效率与外观质量，需配置可靠的失败处理机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| Authorization | `Bearer {external_service_token}` | 符合HTTP标准认证格式，适配外部系统的鉴权要求 |
| variables | 传入`{"batch_no": "xxx", "iv_score": "xx.x", "defect_type": "xxx"}` | 匹配光伏电池片的批次、电性能与缺陷数据，贴合点检场景的参数需求 |
| responseData | 提取`{"repair_opinion": "xxx", "error_code": "xxx"}`字段 | 结构化返回维修建议与状态码，便于后续AI对话引用 |
| 令牌持久化配置 | 开启持久化存储 | 避免重启后渠道与令牌配置丢失，匹配生产环境的稳定运行需求 |
| 接口超时时间 | `30–60 秒` | 适配设备数据采集与维修建议生成的常规延迟 |
| 上下文传入方式 | 通过`variables`字段传入自定义上下文 | 替代系统历史拼接，满足特定点检场景的上下文需求 |

本配置适用于FastGPT v4.17.0。

## 容易做错的三处
- 现象：重启系统后，外部系统的渠道配置与令牌信息丢失，无法正常发起接口调用。原因：未开启FastGPT的持久化存储配置，配置仅保存在内存中。
- 现象：AI对话无法正确引用知识库检索后的结果，显示内容为空或格式混乱。原因：未按`responseData`格式返回结构化的检索内容，仅返回纯文本。
- 现象：自定义上下文未被AI正确使用，仍调用系统历史记录拼接上下文。原因：未通过`variables`字段传入自定义上下文参数，错误使用系统默认的上下文逻辑。

## 怎么确认配好了
- 调用测试接口，检查请求头中是否携带正确的`Authorization`认证信息。
- 传入预设的光伏电池片批次与检测数据，检查`variables`参数是否被正确解析并应用到检索流程。
- 触发设备点检流程，检查`responseData`返回的维修建议与状态码是否符合预期格式。
- 重启系统后，验证外部系统的渠道与令牌配置是否保留，确认持久化存储生效。
