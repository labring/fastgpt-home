# 光伏电池片制造的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自硅片来料、MES系统、扩散炉/镀膜设备/印刷机、EL与IV测试设备及实验室数据。更新节奏覆盖每批生产、每片检测及每日汇总。日常文档包含工艺卡、扩散和镀膜参数表、印刷烧结记录、EL检测图、IV分档数据、良率报告，字段包含设备运行温度、镀膜厚度、隐裂坐标、电性能参数、批次编号等，单位随数据类型变化，无统一固定标准。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类混合存在高频实时检测数据（如每片EL图、IV数据）与批次级汇总文档（如工艺卡、良率报告），要求索引系统同时支持小体量单文件与大体量批次数据的快速检索。多源异构数据的字段差异显著，需在向量建模时兼容不同格式的结构化与非结构化内容。每日批量更新的数据会带来索引刷新压力，需配置增量索引机制，避免全量重建耗时过长。设备点检与维修问答需关联具体设备参数与历史故障记录，要求向量召回结果需精准匹配设备编号与生产批次，避免跨批次数据混淆。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配该品类的工艺参数表、EL检测图标注文本等常见文档长度，避免块内信息断裂 |
| 重叠长度 | 100–200 字符 | 减少跨块信息丢失，适配批次汇总文档的连续参数记录 |
| 相似度阈值 | 0.75–0.85 | 平衡召回精度与召回量，匹配设备点检问题的精准匹配需求 |
| 单次搜索上限 | 前 10 条 | 控制上下文长度，避免超出模型输入限制 |
| `maxToken` | 4096 token | 适配光伏电池片制造场景的多文档合并检索需求，覆盖典型批次数据的总token量 |
| `defaultToken` | 256 token | 用于设备点检短问题的向量生成，平衡召回效率与语义完整性 |

## 容易做错的三处
- 现象：PG数据库docker部署时，知识库索引无法建立成功，宿主机为8c16G无GPU虚拟机。原因：未配置向量插件的CPU加速模式，导致索引计算超时或内存占用过高。
- 现象：导入飞书文件夹下的excel文件和多维文档后，索引中未包含文档内容。原因：未开启对应文件格式的解析适配，未配置光伏品类专属的字段映射规则。
- 现象：设备点检问答的召回结果缺少关键工艺参数。原因：分块长度设置过短，将连续的工艺参数记录拆分为多个块，导致关键信息分散。

## 怎么确认配好了
- 上传一份典型的工艺卡文档，检查分块后的文本是否完整保留连续的参数记录，无明显断裂。
- 发起一条设备点检问题，核对召回结果的设备编号与生产批次是否与问题描述匹配，调整相似度阈值至符合业务需求。
- 查看索引刷新日志，确认每日批量更新的数据仅触发增量索引，未触发全量重建。
- 测试外接API调用，确认向量生成与检索流程的响应时间符合业务预期，调整`maxToken`与`defaultToken`配置适配模型限制。
