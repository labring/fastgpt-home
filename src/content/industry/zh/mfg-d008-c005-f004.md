# 光伏电池片制造的设备点检与维修问答：工作流编排

## 这个品类的数据长什么样
该品类的数据主要来自硅片来料台账、车间MES系统、扩散炉/镀膜设备/印刷机的运行日志、EL与IV测试报告、实验室工艺检测数据。日常文档包含工艺卡、扩散与镀膜参数表、印刷烧结工序记录、EL检测图、IV分档数据、批次良率报告。数据更新节奏为每生产批次同步、单片检测实时更新、每日汇总生产与品质数据，字段覆盖工艺参数、设备运行状态、单片检测结果、批次追溯标识等。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新节奏差异大，导致工作流需支持多源数据的定时拉取与实时同步。单片级检测数据的高频更新，要求工作流节点支持细粒度的参数匹配与结果校验。多类型文档的混合调用，需要工作流配置不同节点处理结构化参数表与非结构化检测图。批次追溯的业务需求，要求工作流中嵌入`variables`与`nodeId`关联的上下文传递逻辑，确保每一步操作可绑定对应生产批次。同时，设备点检与维修的场景需快速响应异常，工作流需预设异常分支的触发条件，适配不同工序的异常判定规则。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量配置 | 绑定生产批次ID、设备编号为`variables` | 适配光伏电池片制造的批次追溯需求，确保每轮问答关联对应生产数据 |
| 工作流触发周期 | 10–30分钟 | 匹配设备运行日志、检测数据的更新节奏，避免无效调用 |
| 上下文窗口大小 | 前800–1200字符 | 适配工艺卡、EL检测图等文档的单份内容长度，保留关键参数与异常信息 |
| 异常分支触发规则 | 匹配EL异常标记、IV效率下降阈值 | 基于该品类的出错后果，快速触发维修问答流程 |
| 历史记录存储 | 按生产批次归档，保留7天 | 符合数据更新频率，便于追溯点检与维修的历史操作 |
| 节点跳转配置 | 关联`nodeId`绑定工序节点 | 确保工作流按电池片制造工序顺序执行，避免流程混乱 |

## 容易做错的三处
- 工作流运行时出现未配置的GPT-4o-mini调用报错日志。原因是未关闭全局默认模型调用开关，导致工作流节点自动触发未配置的模型请求。
- 无法修改工作流中的全局变量历史记录。原因是未开启工作流的变量编辑权限，或未通过`variables`配置项绑定可编辑的历史记录字段。
- 无法通过工作流节点获取用户上传的附件类检测资料。原因是未配置文件上传节点的接收类型与存储路径，未关联对应的数据提取规则。

## 怎么确认配好了
- 手动触发工作流，检查触发节点是否按预设周期或事件启动，确认无额外的未配置模型调用日志。
- 进入全局变量配置页面，验证生产批次ID、设备编号等`variables`是否已正确绑定，可通过测试节点查看变量取值。
- 模拟异常场景，触发预设的异常分支，确认工作流是否跳转至维修问答节点。
- 上传测试用的EL检测图或工艺参数文档，验证上下文窗口是否正确截取符合业务需求的内容。
