# 光伏组件封装的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
光伏组件封装环节的数据来自电池片分档系统、玻璃胶膜背板批次台账、车间MES系统、串焊与层压设备运行日志、EL/IV测试仪导出文件。日常留存的文档包含设备排版图、材料批次记录、层压工艺参数表、EL隐裂图像、IV测试报告、绝缘耐压检测记录、成品包装清单。数据更新节奏为每一块组件对应一份检测记录，每一批次原材料同步生成批次台账，单条数据关联设备运行参数与产品质检结果。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据包含结构化台账、图像文件与时序日志，混合类型数据要求索引支持多模态关联与跨文档上下文匹配。高频更新的单组件级数据会导致索引增量同步压力提升，需适配小批量高频写入的索引策略。EL图与IV测试报告的字段关联紧密，需保留跨文档的上下文关联能力，避免检索时割裂参数与图像的对应关系。设备日志的时序性要求索引支持按时间范围过滤，以匹配点检场景下的历史数据查询需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的向量模型与索引功能编写。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配层压工艺记录、IV测试报告的单段参数长度，避免拆分跨关键参数的文本块 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文关联，确保EL图判读相关的连续文本不被割裂 |
| 相似度阈值 | 0.72–0.85 | 匹配设备点检场景下的精准检索需求，过滤低相关的批次记录 |
| 单次搜索上限 | 前 8 条 | 适配维修问答的轻量化检索，避免返回过多冗余的设备日志 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 按平台配置填写 | 确保向量模型调用的身份验证有效，适配本地部署与云端部署的不同场景 |

## 容易做错的三处
- 界面显示「训练订单创建失败」，返回状态码400。原因是未正确关联光伏组件封装专属的材料批次记录与设备日志数据源，导致索引构建时缺失关联字段。
- 检索结果仅返回文本数据，未关联对应的EL图像。原因是未开启多模态索引配置，未将EL图文件纳入向量模型的向量化范围。
- 本地部署时提示「向量模型不可用」，尽管oneAPI已连通。原因是未将`defaultToken`配置为对应Embedding模型的合法令牌，或未在集合设置中指定光伏组件场景的检索范围。

## 怎么确认配好了
- 上传一份层压工艺记录与EL图的组合文档，执行检索测试，检查返回结果是否包含关联的批次记录与设备日志。
- 查看索引构建日志，确认单条数据的分块长度符合预设范围，无异常拆分的关键参数文本。
- 核对向量模型的令牌配置，确保`defaultToken`与调用接口中配置的令牌一致。
- 执行故障关键词检索，检查返回结果的排序是否优先匹配设备点检的高频故障场景。
