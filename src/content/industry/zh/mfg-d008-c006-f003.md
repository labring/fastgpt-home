# 光伏组件封装的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
光伏组件封装的设备点检与维修相关数据，来源包括电池片分档记录、玻璃胶膜背板批次台账、车间MES系统、串焊与层压设备运行日志、EL/IV测试仪检测报告、绝缘耐压测试记录与成品包装清单。数据按单块组件、每批材料更新，文档包含结构化工艺记录、可视化EL缺陷图、功率测试报告等，字段含设备运行参数、材料批次号、测试档位、缺陷位置与判定结果，部分文档为二进制图像格式，无统一固定排版。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
单块组件级的高频更新数据要求对话上下文需实时关联最新批次与测试结果，避免调用过时数据。多类型文档（结构化记录与图像文件）要求提示词需明确区分文本检索与图像判读的触发逻辑。设备点检的多轮交互需保留历史操作记录，`chatId`需绑定单台设备的全生命周期点检流程，防止上下文混淆。材料批次与设备参数的强关联要求提示词需嵌入字段映射规则，确保检索结果匹配当前点检的设备与材料批次。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` 绑定规则 | 绑定单台设备ID+当日点检批次 | 确保多轮对话仅关联当前点检的设备与批次数据，避免跨设备上下文干扰 |
| `messages` 上下文截断阈值 | 保留前20轮有效交互 | 单块组件点检流程通常不超过15轮，保留20轮可覆盖完整交互链路且不占用过多资源 |
| 分块长度 | 800–1200 字符 | 适配层压工艺记录、EL图标注文本等单段文档的平均长度，减少分块断裂 |
| 单次检索上限 | 前6条检索结果 | 光伏封装相关文档字段集中，6条结果可覆盖设备参数、材料批次与测试记录的全部关联信息 |
| `variables` 注入规则 | 注入当前设备ID、材料批次号 | 强制提示词关联当前点检场景的专属数据，避免检索无关批次的记录 |

本配置项适配FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：调用智能体回复图文操作指引时返回422状态码。原因：未在提示词中明确指定图文内容的检索优先级，导致系统尝试解析非结构化图像文件时触发格式校验失败。
- 现象：知识库使用#/##等标题分隔符后检索结果混乱。原因：光伏封装文档包含大量EL图标注文本与工艺参数行，标题分隔符无法区分结构化记录与非结构化图像注释，导致分块错误。
- 现象：私有部署后新对话弹窗无法隐藏，修改代码无预期效果。原因：未在前端代码的`messages` 初始化模块中注释弹窗渲染逻辑，直接修改静态文件未触发构建更新。

## 怎么确认配好了
- 发起单台串焊设备的点检对话，检查上下文参数是否包含当前绑定的设备ID与材料批次号。
- 上传一份层压工艺记录与EL图，检索后确认返回结果包含对应批次的材料信息与缺陷标注。
- 发起多轮交互，验证上下文是否保留前序点检的设备参数，无跨批次数据混入。
- 测试图文操作指引的回复，确认无异常状态码返回，格式符合预设要求。
