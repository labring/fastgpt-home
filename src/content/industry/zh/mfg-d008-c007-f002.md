# 冲压与板材成形的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据主要来自钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、MES系统、三坐标或检具检验数据。日常文档包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录。数据更新随每卷料、每批生产任务、每次换模操作触发，文档字段包含模具编号、冲压节拍、材料厚度、尺寸偏差值、换模耗时等，附带毫米、次、小时等单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据更新频率高且粒度细，要求索引支持增量更新以适配每卷、每批、每次换模的新数据。文档包含结构化表格与非结构化文本，需适配混合格式的分块与向量化处理。数据字段附带专用单位，向量建模需保留字段与单位的关联特征，避免语义混淆。不同换模批次的数据差异显著，索引召回需优先匹配当前生产批次关联的文档，减少无关结果干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配冲压文档的段落与表格行长度，避免分块截断模具编号、材料规格等关键参数 |
| 分块重叠长度 | 100–150 字符 | 保留跨分块的模具编号、换模时间等关联信息，避免上下文断裂 |
| `defaultToken` | 2000 token | 匹配单份冲压文档的平均文本长度，确保核心业务内容完整向量化 |
| `maxToken` | 4000 token | 限制单条上下文的总长度，避免超出外接模型的调用上限 |
| 相似度阈值 | 0.72–0.78 | 过滤低匹配度结果，聚焦关联模具点检、维修作业的有效内容 |
| 单次搜索上限 | 前10条 | 适配车间点检的高频查询场景，控制返回结果的信息量与响应速度 |

## 容易做错的三处
- 现象：PG数据库docker部署时，知识库索引建立失败，宿主机为8c16G无GPU虚拟机。原因：未配置PG向量扩展插件，或分块长度设置过大导致单次索引写入数据量超出内存阈值。
- 现象：外接API调用向量模型时，出现超时报错。原因：未调整`maxToken`适配外接模型的上下文限制，导致请求内容超出模型支持范围触发超时。
- 现象：导入飞书多维文档后，检索结果中材料厚度、尺寸偏差等字段为空。原因：分块时未保留结构化表格的字段与单位关联，导致向量化时丢失关键业务信息。

## 怎么确认配好了
- 上传单份冲压作业指导书，检查分块后的文本是否保留模具编号、材料规格等核心字段。
- 发起“模具磨损如何处理”的查询，核对返回结果的相似度得分是否落在预设的阈值区间内。
- 新增一份换模记录文档，触发增量索引后，再次发起关联查询，确认新文档已被正确召回。
- 确认当前FastGPT版本为v4.17.0，确保配置项的兼容性。
