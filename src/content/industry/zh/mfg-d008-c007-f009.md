# 冲压与板材成形的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、MES系统、三坐标或检具检测结果；日常关联文档包括冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录。数据更新节奏为每卷钢料、每批次生产、每次模具更换时同步更新；文档字段包含材料牌号、冲压工艺参数、模具磨损量、检验尺寸偏差、换模时间等，无额外自定义统计单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据更新频率高且分批次，要求模型上下文不能过长，避免截断换模、检验报告等关键批次信息；多源异构数据覆盖设备运行参数、纸质文档、检测结果等格式，需适配不同输入类型的处理逻辑；每次换模后模具参数、生产要求同步变更，需确保模型能动态调用对应批次的关联文档；专属业务字段如拉延筋间隙、压边力参数等，需要模型能准确识别并关联对应规范；高频批量的问答请求，需限制单轮资源消耗，避免服务器过载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配多批次生产数据的上下文长度，避免截断换模、检验报告等关键信息 |
| `maxTokens` | 2000–3000 token | 限制单轮回答长度，适配设备点检维修问答的简洁性需求，避免资源占用过高 |
| `quoteMaxToken` | 1500 token | 限定引用文档的总token数，确保每卷料、每次换模的关联文档都能被完整引用 |
| `temperature` | 0.3–0.5 | 降低随机性，确保维修点检建议的规范性，符合冲压车间的标准化作业要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应地址 | 适配FastGPT v4.17.0的代理配置要求，确保模型调用链路正常 |
| `AIPROXY_API_TOKEN` | 由部署方生成的专属密钥 | 保障模型调用的安全性，避免未授权访问 |

## 容易做错的三处
-  配置`maxContext`超过15000 token后，模型调用出现504超时错误，同时GPU使用率无法有效提升，CPU单核占用达100%。原因是上下文过长时，模型优先使用CPU进行分词处理，未充分调用GPU显存资源，超出部署环境的内存阈值。
-  未限定`quoteMaxToken`时，返回结果中出现过期钢卷的材料利用率数据。原因是未过滤旧批次的引用文档，导致模型调用无关的历史生产数据，影响回答准确性。
-  配置`temperature`高于0.7时，生成的维修建议出现与冲压作业指导书不符的拉延筋间隙参数。原因是高随机性导致模型偏离标准化作业规范，产生不符合工艺要求的调试建议。

## 怎么确认配好了
-  查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置无拼写错误，无401或404报错。
-  发起一次包含当前换模记录、模具点检数据的测试问答，检查返回结果中是否引用了对应批次的关联文档。
-  监控模型调用的资源占用情况，确认GPU使用率随问答请求提升，CPU单核占用未持续达到100%。
-  对比生成的维修建议与冲压作业指导书的工艺参数，确认建议符合标准化作业要求。
