# 冲压与板材成形的设备点检与维修问答：部署与升级

## 这个品类的数据长什么样
该品类的数据覆盖冲压车间全流程，来源包括钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、MES系统、三坐标或检具检验数据。日常维护与生产文档包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录。数据更新随每卷料、每批生产任务、每次换模操作触发，核心字段涵盖材料牌号、模具间隙值、压边力参数、尺寸偏差量、换模耗时等，未添加额外统计数值或百分比内容。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据高频更新、多源异构且文档结构多样，为部署与升级带来多重约束。高频随卷料、换模更新的数据要求部署时配置适配增量同步的机制，避免全量拉取占用存储与带宽资源。多来源的设备、质检与生产数据要求提前配置对应系统的接入权限与数据格式转换规则，确保不同数据源的字段可统一映射到检索知识库中。多样的文档类型要求升级时保留兼容多格式解析的插件，同时需针对设备点检、维修类短文本问答优化检索上下文的截取逻辑，避免无关数据干扰精准匹配。此外，工业场景的运维数据需保障安全性，部署时需配置符合工业数据安全标准的访问控制规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150 条` | 该品类单轮设备点检与维修问答需关联多份模具点检、换模记录等文档，100-150条可覆盖典型检索需求，避免过多冗余数据影响响应速度 |
| `REDIS_URL` | `redis://:自定义密码@部署主机:6379/0` | 高频更新的冲压生产数据需缓存检索结果与会话信息，使用标准Redis服务可降低重复查询压力，端口6379为行业通用默认端口 |
| `STORAGE_S3_ENDPOINT` | 按实测标定 | 该品类需存储钢卷质保书、尺寸检验报告等多格式文件，需根据部署的对象存储服务地址配置，适配不同云环境或本地存储方案 |
| `ROOT_KEY` | `32 位随机字符串` | 该场景涉及设备运维权限管控，高强度密钥可保障API调用与后台配置的安全性，符合工业场景的数据安全要求 |
| `FILE_TOKEN_KEY` | `16 位随机字符串` | 需为上传的模具点检表、换模记录等文件生成安全访问令牌，16位长度兼顾安全性与传输效率 |

## 容易做错的三处
- 现象：docker部署的reranker组件调用返回结果为false，但接口调用状态显示成功。原因：未将reranker服务地址正确配置到FastGPT的检索链路中，导致结果未正常返回至前端或调用方。
- 现象：升级到FastGPT v4.17.0版本后，插件编辑页面始终显示未保存状态，无论是否点击保存按钮均无法消除提示。原因：升级过程中前端静态资源未完整覆盖，导致前端状态同步逻辑出现异常。
- 现象：通过API调整自定义检索数量超过5个后，请求无法生效，检索条数仍保持默认限制。原因：未正确修改`DB_MAX_LINK`的配置值，默认参数限制导致检索条数无法突破预设阈值。

## 怎么确认配好了
- 调用FastGPT的数据源接入测试接口，验证钢卷标签、模具管理系统等多源数据的读取权限与格式转换正常。
- 上传模具点检表、换模记录等典型文档，确认解析后的文本字段与预设的业务字段匹配一致。
- 调整`DB_MAX_LINK`配置后，发起检索请求，验证返回的关联文档条数符合设定的取值范围。
- 重启FastGPT服务后，检查前端页面的插件编辑状态是否正常，无未保存提示异常。
