# 化妆品生产的设备点检与维修问答：工作流编排

## 这个品类的数据长什么样
该品类数据来自注册或备案配方、原料安全资料、称量与乳化设备、ERP/MES系统、实验室记录及包材版本文件。日常文档包含配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验报告及标签审核材料。数据按每批生产、每次换线更新，字段涵盖限用物质含量、乳化温度、包材批号、生产批号等，单位包含摄氏度、千克、批次号等。

## 这些特征在「工作流编排」这一环带来什么约束
该品类数据更新频率高且按生产批次绑定，要求工作流支持实时拉取对应批次的设备、ERP及实验室数据。多源数据来源需要工作流完成跨系统数据的格式统一与字段映射，避免因数据错位引发合规问题。字段包含限用物质含量、乳化温度等合规相关参数，要求工作流的`variables`能准确绑定特定字段，确保参数校验逻辑匹配业务要求。单次生产的出错后果直接关联合规风险，工作流需配置明确的失败分支与异常告警触发条件。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 全局变量绑定 | 按生产批次匹配对应字段 | 适配品类数据按批次更新的特征，确保每次运行加载最新业务数据 |
| 节点ID触发 | 绑定设备点检节点的`nodeId` | 精准触发维修问答的上下文调用，避免误触发无关节点 |
| 上下文长度 | 800–1200 字符 | 覆盖单批次生产的核心文档内容，避免上下文溢出或不足 |
| 调试超时阈值 | 600 秒 | 适配多源数据拉取的耗时需求，避免因数据加载过久中断流程 |
| 变量校验规则 | 按实测标定 | 匹配限用物质、乳化温度等特定字段的合规范围 |

## 容易做错的三处
- 现象为点击按钮获取流程中的`variables`时返回未赋值的空值。原因是未在工作流启动前完成对应批次数据的变量绑定，导致节点调用时未加载目标数据。
- 现象为工作流调试时弹出`workflow error {"message":"Dangerous behavior"}`报错。原因是未配置合规的分支触发逻辑，触发了平台的安全校验机制。
- 现象为工作流返回base64格式的维修指导内容无法正常展示。原因是未在节点中配置格式转换步骤，未将base64内容映射至对应展示节点的参数。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的工作流调试工具运行单次测试批次，检查`variables`是否加载了对应批次的配方、设备参数等数据。
- 触发模拟异常场景，确认工作流跳转至预设的告警分支并生成对应日志。
- 验证base64格式的维修指导内容是否能正确转换为可展示的格式。
- 核对节点`nodeId`是否与设备点检节点的标识一致，确保触发逻辑准确。
