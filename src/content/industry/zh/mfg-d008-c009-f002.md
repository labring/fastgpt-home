# 化学药制剂生产的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
数据来源包括经批准的处方工艺、MES电子批记录、LIMS系统、质量管理系统及设备环境监测数据。日常文档涵盖主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差CAPA变更文件及批放行审核表。数据更新频率为每生产批次、每个关键工艺步骤，以及按设备环境监测计划执行。字段包含物料批次号、工艺参数值、设备运行数据、检验结果数值、偏差描述等，涵盖质量单位、体积单位、温度压力参数单位等。

## 这些特征在「向量模型与索引」这一环带来什么约束
品类数据按批次与关键步骤更新，且需保留历史版本用于GMP合规追溯，因此索引需支持按批次维度的增量更新，避免全量重新索引引发的性能损耗。文档包含结构化参数与非结构化维修描述，向量模型需兼顾结构化字段的语义匹配与非结构化文本的理解能力。设备点检维修相关内容多关联特定设备型号与故障代码，索引需支持语义与关键词的混合召回，提升精准度。同时，数据涉及合规性要求，召回内容需可追溯至原始文档批次与版本，确保审核可查。

## 配置怎么定
本文档的配置建议适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配批记录等长文档的语义完整性，避免单块包含跨工艺步骤的内容 |
| 重叠长度 | 100–200 字符 | 保留相邻工艺步骤的上下文关联，防止拆分后丢失设备维修的流程逻辑 |
| 相似度阈值 | 0.72–0.85 | 区分设备故障描述与普通工艺参数描述，降低非相关内容的误召回 |
| 单次搜索上限 | 前 8 条 | 匹配GMP批记录审核的单批次数据量范围，避免冗余信息干扰问答生成 |
| maxToken | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| defaultToken | 2000 token | 作为默认召回内容的长度基准，平衡信息丰富度与响应速度 |

## 容易做错的三处
- 现象：配置第三方嵌入模型渠道后，系统提示无可用渠道。原因：未在FastGPT系统中配置对应模型的调用密钥，或渠道地址未适配嵌入模型的接口规范。
- 现象：知识库搜索响应时长超出预期，硬件配置为8核64G内存加RTX2070仍出现卡顿。原因：未按品类数据特征调整分块长度与单次搜索上限，导致召回的文档数量过多超出硬件处理能力。
- 现象：向量召回结果包含大量非维修相关的工艺参数记录，匹配度偏低。原因：未设置符合品类数据的相似度阈值，未能有效区分设备点检内容与普通生产参数内容。

## 怎么确认配好了
- 导入单批次的批生产记录与设备点检文档，执行一次设备故障相关的查询，核对召回结果是否包含对应设备的维修步骤内容。
- 查看系统索引日志，确认仅对新增的批次文档执行增量索引，未触发全量重新索引操作。
- 检查嵌入模型的调用状态，确认无连续的调用失败日志，且返回的向量数据格式符合系统要求。
- 调整相似度阈值的测试区间，验证召回结果的匹配度是否符合业务场景的预期。
