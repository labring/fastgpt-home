# 化学药制剂生产的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
化学药制剂生产的设备点检与维修相关数据，来源包括经批准处方工艺、MES电子批记录、LIMS系统、质量管理系统与设备监测数据。数据更新节奏为每批生产、每个关键工艺步骤执行时同步更新，或按设备点检监测计划定期更新。日常关联文档包含主生产文件、批生产记录、清场记录、检验记录与偏差CAPA文件，字段涵盖物料批次号、工艺参数区间、设备运行时长、环境监测值与检验结果，无额外自定义非标准字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的设备点检与维修问答需绑定当前生产批次的专属数据，因此多轮对话必须通过`chatId`关联对应批次的上下文，避免跨批次数据混淆。数据更新频率高且关联文档结构复杂，提示词需明确限定仅调用当前批次的批记录与设备档案，不得引用过期或非当前批次的内容。GMP要求数据可追溯，因此对话过程中的`messages`字段需完整留存每一轮交互的设备状态与维修建议，不得随意删减关键字段。`variables`需预设当前批次的设备编号、物料批次等固定参数，减少交互中的重复输入。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 2000–4000 token | 适配qwen2.5-14b-int4的上下文承载能力，避免截断批次记录关键内容 |
| 问题优化开关 | 开启 | 自动将设备点检的口语化提问转换为符合GMP文档规范的查询指令，提升召回准确性 |
| 单次回复token上限 | 1500 token | 控制维修建议的输出长度，避免超出模型量化版本的输出限制 |
| 对话日志保留时长 | 72小时 | 符合GMP数据追溯的最短留存要求，同时避免存储空间过度占用 |
| 知识库召回条数 | 前6条 | 平衡召回精度与上下文长度，确保覆盖当前批次设备的点检标准与维修历史 |
| 版本适配 | FastGPT v4.17.0 | 确保`chatId`、`messages`、`variables`参数的原生支持与兼容性 |

## 容易做错的三处
- 现象：工作流运行时仍显示think标签内的思考内容，调试阶段正常。原因：代码运行节点未正确过滤`messages`字段中的思考内容，仅在调试环境生效。
- 现象：知识库回答出现截断，简单模式对话可正常输出。原因：单次回复token上限设置未适配qwen2.5-14b-int4的量化版本输出限制，未匹配实际召回的文档长度。
- 现象：无法批量清理指定批次的对话日志。原因：未通过`variables`预设`chatId`关联参数，导致系统无法定位对应批次的对话日志。

## 怎么确认配好了
- 发起包含当前批次设备编号的多轮点检提问，检查`messages`字段是否完整包含该批次的批记录关联参数。
- 触发问题优化功能，查看生成的查询指令是否包含GMP文档要求的字段规范。
- 运行包含think标签过滤的工作流，确认最终输出内容仅包含设备维修建议，无思考环节内容。
- 按`chatId`筛选对应批次的对话日志，验证是否可执行批量删除操作。
