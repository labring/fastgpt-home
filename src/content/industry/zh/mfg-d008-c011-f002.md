# 半导体封装测试的设备点检与维修问答：向量模型与索引

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类数据主要来自晶圆测试图、生产执行系统（MES）、键合机与塑封设备、ATE测试机、X-ray/SAM检测设备及客户规格文档。日常生成的文档包括封装流程卡、键合与塑封参数表、晶圆来料图、测试程序版本文件、良率报告与失效分析报告。数据更新按生产批次、单颗芯片测试结果及每日运维节奏推进，覆盖从晶圆来料到成品测试的全流程记录。

## 这些特征在「向量模型与索引」这一环带来什么约束
晶圆来料图与实物批次的对齐需要精准匹配坐标与批次信息，要求索引对结构化字段与非结构化文档的混合特征有良好支持；每日高频更新的ATE测试数据与良率报告，要求索引支持增量更新以避免全量重建耗时；不同批次的封装参数差异较大，需要向量模型能捕捉细微参数差异对应的设备状态；失效分析报告包含大量专业术语与失效模式，要求索引对领域术语的向量表征准确性更高。同时多源异构数据的混合存储会增加索引的检索复杂度，需针对性优化分块与匹配逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 封装流程卡与参数表单页内容长度多在该区间，避免分块破坏参数关联 |
| 重叠长度 | 100–150 字符 | 覆盖跨分块的参数连续性，防止键合参数的上下文断裂 |
| `maxToken` | 4096 token | 适配bce-embedding-v1的最大输入长度，避免截断关键失效分析内容 |
| `defaultToken` | 按实测标定 | 针对单颗测试的短文本数据，调整默认token阈值以平衡检索精度与速度 |
| 相似度阈值 | 0.72–0.80 | 半导体领域专业术语的向量匹配需要较高阈值，过滤无关的设备点检记录 |
| 单次搜索上限 | 前 8 条 | ATE测试数据的批次关联性强，少量高匹配结果即可覆盖典型维修场景 |

## 容易做错的三处
- 现象：使用chunk模式调用pushdata api上传数据后，界面长期显示「索引中」状态无更新。原因：未配置增量更新触发规则，或分块长度超出模型支持上限导致分块解析失败。
- 现象：问答拆分后的最后一组索引无法完成向量化。原因：最后一组分块的token数超出`maxToken`限制，且未触发自动截断或补全逻辑。
- 现象：接入bce-embedding-v1后检索结果匹配度偏低。原因：未调整相似度阈值适配该模型的向量分布特征，或未对齐模型的输入token要求。

## 怎么确认配好了
- 上传单份封装流程卡文档，检查分块结果是否保留完整的参数条目与流程步骤。
- 调用pushdata api上传增量测试数据，核对索引更新进度是否符合预期节奏。
- 输入设备点检相关的专业问题，验证检索结果是否包含对应批次的良率报告与失效分析内容。
- 查看向量模型调用日志，确认`defaultToken`与`maxToken`的实际使用值符合配置要求。
