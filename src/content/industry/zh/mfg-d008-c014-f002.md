# 印染与后整理的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自客户色样、配方库、染化料批次记录、染缸控制系统、测色仪、定形机及环保监测设备。日常文档包含染色配方、称化料记录、染缸运行曲线、打样确认单、色差报告、定形工艺单、污水台账。数据更新频率为每缸、每批或每班，单条数据包含工艺参数、检测结果、批次标识等字段，部分参数带有明确单位，如温度单位为摄氏度、色差单位为ΔE、污水浓度单位为mg/L。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的高频实时更新数据要求索引支持增量同步，避免全量重建带来的资源消耗。多类型结构化与半结构化文档混合，要求索引适配不同字段的向量提取逻辑，避免非结构化文本与结构化参数的向量对齐偏差。单缸数据关联多环节文档，如染缸曲线对应染色配方、色差报告对应打样记录，要求索引支持跨文档关联召回，确保问答时能调取完整关联数据。批次化数据的唯一性要求索引对批次标识字段做精准索引，避免召回非对应批次的无效数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 该品类文档包含长段染缸曲线数据与工艺文本，800–1200字符可完整覆盖单段工艺逻辑且避免分块过碎 |
| 重叠长度 | 100–150 字符 | 避免跨分块的工艺逻辑被割裂，确保染缸升温曲线等连续数据的向量连贯性 |
| 相似度阈值 | 0.72–0.80 | 该品类工艺参数精度要求高，阈值过低会召回无关批次数据，过高则可能遗漏有效关联配方 |
| 单次搜索上限 | 前6条 | 单缸关联数据多为3-5条相关文档，前6条可覆盖全部有效关联内容且避免冗余召回 |
| `maxToken` | 4096 token | 该品类问答需整合染缸参数、色差报告与工艺单，4096 token可承载完整关联上下文 |
| `defaultToken` | 512 token | 用于处理用户提问的上下文补全，确保基础提问可被正确解析 |

## 容易做错的三处
- 自定义索引配置后检索无结果，现象为界面返回空结果数组或状态码200但无匹配数据，原因是未将批次标识字段加入索引映射，导致无法关联对应缸次的工艺数据。
- 向量检索超时，现象为接口返回504超时错误，原因是未配置增量索引，全量重建索引时占用过多资源，无法响应实时查询。
- 混用通用向量模型，现象为检索结果色差参数匹配偏差，原因是未使用适配工业工艺参数的向量模型，导致结构化参数的向量表示与实际业务逻辑不符。

## 怎么确认配好了
- 上传单缸的染色配方与染缸曲线，执行对应缸次的点检问答，核对返回结果包含该缸的完整工艺参数。
- 模拟延迟更新的批次数据，触发增量索引同步，验证新上传的污水台账可被快速检索到。
- 调整相似度阈值，观察检索结果的匹配精度变化，确认阈值处于合理区间内符合业务需求。
- 查看FastGPT v4.17.0的索引监控面板，确认增量同步的耗时在可接受范围内，无全量重建的异常任务。
