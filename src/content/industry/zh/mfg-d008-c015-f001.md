# 原料药与医药中间体生产的设备点检与维修问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
数据来源涵盖注册工艺文档、原料批次台账、DCS控制系统、称量系统、LIMS实验室信息管理系统、色谱数据系统、QMS质量管理系统；更新节奏为每生产批次、每工艺步骤触发更新；日常文档包含批生产记录、物料平衡报表、反应与精制过程记录、清洁验证记录、杂质谱报告、偏差与变更管理文件；数据字段包含工艺参数、批次标识、杂质检测值、清洁验证结果、质量偏差记录等，无统一固定单位，随对应业务场景匹配。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类的数据来源分散且覆盖多类业务系统，HTTP接口需要支持对接异构数据源的拉取请求；更新节奏为每批次、每工艺步骤触发，接口需支持按需触发查询或短周期定时同步，避免数据滞后；文档结构复杂且字段不统一，`responseData`需支持嵌套字段解析，适配不同业务文档的字段格式；业务数据关联批次与工艺节点，接口需支持按批次标识、工艺节点ID作为查询参数；同时因涉及合规相关数据，`Authorization`校验需严格使用应用级密钥。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `Authorization` | 使用应用级API密钥 | 该品类数据涉及合规管理，应用级密钥可限制访问范围，保障数据安全 |
| `variables` | 配置为批次ID、工艺节点ID作为查询变量 | 数据按生产批次与工艺步骤更新，通过变量可精准匹配对应业务数据 |
| `responseData` | 开启嵌套字段解析模式 | 日常文档包含多类嵌套结构的业务数据，该配置可完整提取所需字段 |
| 请求超时时间 | 60–120 秒 | 对接多源异构系统时，需预留足够时间完成数据拉取与解析 |
| 单次查询上限 | 前 10 条数据 | 避免单次请求返回过多冗余数据，适配单批次工艺步骤的查询需求 |
| 上下文窗口大小 | 8000–12000 token | 适配多类业务文档的内容长度，保障完整的上下文信息 |

## 容易做错的三处
- 接口返回`400 do request failed`报错，且日志显示密钥校验失败。原因是使用了全局通用API密钥，未使用应用级密钥，不符合该品类合规数据的访问权限要求。
- 接口返回的`responseData`字段为空。原因是未配置`variables`为批次ID或工艺节点ID，无法精准匹配对应生产批次的业务数据。
- 接口请求超时。原因是未合理设置请求超时时间，对接多源异构系统时未预留足够的拉取与解析时间。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的平台，调用接口传入测试批次ID，核对返回的`responseData`是否包含对应批次的工艺参数与杂质检测数据。
- 检查接口请求头中的`Authorization`字段是否为应用级API密钥。
- 模拟多源系统对接场景，验证接口是否能在预设超时时间内完成数据返回。
- 调整`variables`参数的取值，核对查询结果是否随批次ID或工艺节点ID的变化而更新。
