# 原料药与医药中间体生产的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自注册工艺文档、原料批次记录、DCS控制系统、称量系统、LIMS实验室信息管理系统、色谱数据系统及QMS质量管理系统。日常文档包含批生产记录、物料平衡表、反应与精制步骤记录、清洁验证记录、杂质谱报告、偏差与变更文件。数据更新以每生产批次、每工艺步骤为节奏，字段包含批次号、反应参数、收率、杂质含量等专业内容，文档结构随工艺环节不同存在差异。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引需支持跨系统格式适配，避免专业字段解析错误。高频次的按批更新要求索引需配置增量同步机制，减少全量扫描的资源消耗。长文本的工艺记录与专业术语密集的杂质谱报告，要求分块策略需兼顾内容完整性与检索精度，防止关键维修逻辑被截断。同时，设备点检与维修问答需关联工艺合规性数据，要求检索召回的结果需具备足够的专业相关性，避免无关内容干扰判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 该品类文档多为完整工艺片段或杂质分析内容，此区间可覆盖单步反应、单批次维修记录的核心信息 |
| 重叠长度 | 100–150 字符 | 避免跨工艺步骤的关联逻辑被分块截断，保障维修问答中上下文的连贯性 |
| 相似度阈值 | 0.75–0.85 | 过滤专业术语匹配度不足的检索结果，聚焦与设备点检、维修直接相关的工艺文档 |
| 单次搜索上限 | 前 10 条 | 控制检索返回结果的数量，避免多源数据下的结果过载影响响应速度 |
| `maxToken` | 8000 token | 设备维修问答需关联多步工艺记录，此取值可容纳足够的上下文信息支撑逻辑推导 |
| `defaultToken` | 按实测标定 | 适配不同批次文档的长度差异，避免超出模型上下文限制 |

## 容易做错的三处
- 现象：知识库检索响应超时，界面显示请求耗时超过60秒。原因：未针对该品类按批更新的节奏配置增量索引，频繁触发全量索引扫描导致资源占用过高。
- 现象：索引状态长期显示“索引中”无法就绪，日志提示embedding处理阻塞。原因：未配置合理的批处理参数，单批次处理包含多源异构数据的索引任务超出模型处理能力。
- 现象：数据集中自动生成多组重复索引条目。原因：未关闭重复数据自动匹配开关，该品类文档中固定出现的批次号、原料名称等字段导致系统误判为新数据。

## 怎么确认配好了
- 查看系统运行日志，确认索引同步仅在每批生产完成后触发增量更新，无全量扫描的高频触发记录。
- 测试检索专业设备维修相关术语，核对返回结果的相关性符合预设的相似度阈值区间。
- 检查数据集中的索引条目数量，确认无自动重复生成的条目，单次数据导入后索引条目数量符合预期。
- 查看系统版本信息，确认当前运行的FastGPT版本为v4.17.0。
