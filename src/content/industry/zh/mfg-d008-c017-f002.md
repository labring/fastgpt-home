# 喷涂与涂装的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
喷涂与涂装场景的核心数据覆盖汽车、家电、工程机械、金属家具的涂装线，日常文档包含涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账。数据来源包括涂料供应商TDS/SDS文件、喷房与烘炉实时采集数据、色差仪、膜厚仪、环境监测设备及MES系统。数据更新节奏覆盖每批涂料批次、每班生产节点及连续的设备运行采集，文档字段包含膜厚、色差ΔE值、烘炉温度、涂料黏度等专业参数，部分为表格化的参数记录，部分为文本格式的工艺描述，无统一通用结构。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且更新频率差异明显，连续采集的设备数据需支持增量索引，避免全量扫描拖慢检索速度。文档结构不统一，既有表格化的参数记录，也有文本化的工艺描述，分块时需兼顾参数完整性与上下文关联。专业参数如膜厚、色差ΔE值的语义关联需被准确捕捉，向量模型需适配工业工艺类文本的专业术语。同时，检索结果需关联前处理、喷涂、固化全流程的参考数据，单次召回的结果需覆盖维修决策所需的完整工艺逻辑，避免遗漏关键环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配涂装工艺卡、烘炉曲线等文档的段落长度，保留前处理、喷涂、固化的完整工艺窗口 |
| 重叠长度 | 100–150 字符 | 避免分块切断连续的工艺参数，如调漆黏度与对应喷涂压力的关联 |
| 相似度阈值 | 0.75–0.85 | 区分涂装缺陷的相似描述，如橘皮与流挂的特征差异，避免误匹配无关文档 |
| 单次搜索上限 | 前 10 条 | 涂装场景下关键参考数据集中在10条以内，避免冗余结果干扰维修决策 |
| `maxToken` | 4096 token | 适配主流大语言模型的上下文窗口，完整加载工艺卡与缺陷报告的关联内容 |
| `defaultToken` | 512 token | 用于向量模型的文本截断，平衡专业参数的完整性与检索速度 |

## 容易做错的三处
- 现象：知识库搜索响应超时，日志显示向量匹配耗时超过60秒。原因：未针对每批涂料、每班更新的批次单与设备数据设置增量索引，全量索引在低配置硬件下扫描全量历史数据。
- 现象：搜索结果中出现大量无关的VOCs台账文档，无法召回涂装缺陷的维修方案。原因：相似度阈值设置过低，未结合涂装场景的工艺参数权重调整匹配规则。
- 现象：问答拆分后将烘炉温度与对应膜厚要求拆分到不同文本块。原因：分块长度设置过短，切断了工艺关联的连续参数，破坏了维修方案的完整逻辑。

## 怎么确认配好了
- 登录FastGPT v4.17.0的索引管理界面，确认增量索引已开启，更新频率匹配每批涂料、每班的生产节奏。
- 输入涂装缺陷关键词（如橘皮、流挂），核对返回结果的文档类型是否包含涂装工艺卡、缺陷返修单等对应品类文档。
- 测试单次搜索响应时间，确认在RTX2070硬件下的耗时符合预期。
- 随机抽取分块后的文本片段，确认膜厚、烘炉温度等专业参数未被分块切断。
