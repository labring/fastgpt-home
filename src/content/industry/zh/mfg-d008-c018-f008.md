# 基础化工连续生产的设备点检与维修问答：文档解析与分块

## 这个品类的数据长什么样
基础化工连续生产品类的核心数据来自DCS/SIS系统、在线分析仪、LIMS系统、设备状态监测模块、能源计量系统与原料储罐监测模块。日常文档涵盖操作规程、工艺指标卡、DCS趋势图、化验报告、联锁旁路记录、特殊作业票与班报。数据更新节奏涵盖实时（如DCS趋势）、每班（如班报）、每日（如化验报告）。文档字段包含工艺参数（温度、压力、流量，单位对应℃、MPa、m³/h）、联锁状态位、班次标识与时间戳，混合文本、表格与时序数据，无统一固定格式。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的数据来源分散且格式多样，实时更新的DCS趋势与每班生成的班报需要分块保留时序与班次上下文，避免拆分后无法关联对应参数。混合格式的文档包含文本、表格与内嵌图片，解析与分块需同时适配结构化表格与非结构化文本，不能仅按固定字符长度拆分。强联锁相关的文档如联锁旁路记录需保留完整的操作上下文，分块不能割裂联锁编号与对应的处置流程。高频更新的实时数据若分块过大，会导致检索时无法匹配最新的工艺指标变化。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的官方规则制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chunkSize` | 800–1200 字符 | 适配混合格式的文档，既可以完整容纳单条工艺指标卡的内容，也不会让长文本的操作规程分块过于零散 |
| `chunkSplitter` | 按段落+标题层级 | 适配包含章节结构的操作规程与时序化的DCS趋势，保留文档的逻辑上下文 |
| `customPdfParse` | 启用 | 解析带格式的化工工艺PDF文档，保留表格、文本层级与内嵌图片的基础结构 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 避免大型归档班报或DCS趋势文件在解析过程中出现超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持上传包含多批次归档文档的压缩包，适配连续生产的长期数据留存需求 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（如班报、联锁记录）调整分块规则，满足细分场景的上下文保留需求 |

## 容易做错的三处
- 现象：上传包含内嵌图片的docx操作规程时，返回`Invalid image file`报错。原因：未启用`customPdfParse`配置，无法识别化工文档中常见的内嵌矢量图格式。
- 现象：解析知识库时日志报`slow operation xxxxms`，MongoDB本身响应正常。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值过低，大型DCS趋势归档文件未完成完整解析即触发超时。
- 现象：Markdown格式的化验报告输出被截断，无法展示完整的检测数据行。原因：`chunkSize`设置过小，将完整的表格行拆分到不同分块中，导致检索时无法关联完整数据。

## 怎么确认配好了
- 上传一份包含工艺指标卡表格、DCS趋势文本与内嵌图片的测试文档，检查解析后的分块是否保留表格的完整行与时序数据的连续块。
- 上传1000 MB以内的归档班报压缩包，确认上传与解析流程无超时类报错。
- 查看解析日志，确认无`Invalid image file`或`slow operation`相关的异常记录。
- 手动调整`chunkSize`为800–1200字符区间，验证长文本操作规程的分块未割裂关键操作步骤。
