# 基础化工连续生产的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
基础化工连续生产品类的核心数据来源包括DCS/SIS系统、在线分析仪、LIMS系统、设备状态监测模块、能源计量系统与原料储罐管理模块。数据更新节奏分为实时、每班、每日三类，对应工艺参数、设备振动值、班报等内容。日常文档涵盖操作规程、工艺指标卡、DCS趋势图、化验报告、联锁旁路记录、特殊作业票与班报，字段包含温度、压力、流量、振动幅值等，对应单位为摄氏度、帕斯卡、立方米每小时、毫米每秒等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据实时性要求高，部分工艺参数需在秒级内完成响应，因此模型接入需适配低延迟的调用链路。多类数据更新节奏差异大，需配置增量同步与全量更新的混合策略，避免冗余请求。文档类型包含结构化参数表、半结构化趋势图与合规性记录，模型需支持多格式文本的解析与关联。强联锁控制相关的文档需严格限制上下文范围，防止生成不符合安全规范的处置建议。

## 配置怎么定
本页面适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配DCS趋势、工艺指标卡等长文档的上下文承载需求 |
| `maxTokens` | 2000–3000 token | 满足维修问答的详细回复要求，避免截断关键处置步骤 |
| `quoteMaxToken` | 1500 token | 优先引用联锁旁路记录、特殊作业票等合规性文档片段 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具处理点检数据查询 |
| `temperature` | 0.2–0.4 | 降低随机输出，确保维修建议符合操作规程的严谨性 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 对接本地部署的兼容模型服务 |
| `AIPROXY_API_TOKEN` | 按服务生成的密钥填写 | 完成模型服务的身份验证 |

## 容易做错的三处
- 界面显示`AIPROXY_API_TOKEN`字段为空，模型调用失败。原因是未正确导入OneAPI的密钥，或密钥格式包含特殊字符未转义。
- 调用模型时返回格式不兼容报错。原因是使用Xinference部署的Qwen模型，未适配FastGPT的模型调用协议，导致请求参数不匹配。
- 检索结果仅返回少量非关键文档。原因是未设置合理的`quoteMaxToken`，或上下文长度限制过窄，无法加载完整的工艺指标卡、联锁记录等核心数据。

## 怎么确认配好了
- 发起模拟点检问题查询，检查返回结果是否包含对应品类的操作规程、联锁处置步骤等内容，确认上下文加载正常。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的请求参数无缺失，返回状态码为200。
- 测试多轮问答场景，检查模型是否能关联历史对话中的设备状态数据，确认上下文传递正常。
- 上传单份DCS趋势文档，检索后确认返回的引用片段包含正确的时间戳与参数值，验证文本解析适配性。
