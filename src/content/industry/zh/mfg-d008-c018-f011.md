# 基础化工连续生产的设备点检与维修问答：表单与交互

## 这个品类的数据长什么样
基础化工连续生产的主体包括氯碱、合成氨、甲醇、纯碱等企业，日常运维文档涵盖操作规程、工艺指标卡、DCS趋势、化验报告、联锁旁路记录、特殊作业票、班报。数据来源覆盖DCS/SIS系统、在线分析仪、LIMS、设备状态监测、能源计量、原料储罐，更新节奏包含实时、每班、每日。数据字段多绑定固定单位，如压力MPa、温度℃、流量m³/h，工艺指标卡包含明确阈值，联锁旁路记录记录操作时间与执行人信息。

## 这些特征在「表单与交互」这一环带来什么约束
多源且更新节奏不一的数据，要求表单支持实时数据联动与定时刷新配置，适配不同类型文档的录入需求。文档类型多样且包含强联锁相关记录，表单需要针对关键参数配置校验规则，避免误输入引发安全风险。点检维修流程涉及多环节关联，交互设计需要支持问题间的上下文传递，确保维修问答的连贯性。同时，故障后果严重，表单需增加二次确认步骤，降低操作失误概率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 按字段类型配置输入框，数值字段绑定单位校验 | 基础化工数据包含大量带单位的工艺参数，需避免输入错误 |
| `userSelect` | 预设联锁状态、作业类型选项，关联对应文档库 | 点检维修常涉及固定作业场景与联锁操作，减少手动输入误差 |
| 问题优化 | 开启，模型选择通用问答模型 | 需将点检问题转化为标准化查询，匹配工艺文档内容 |
| 最大上下文 | 800–1200 token，按实测标定 | 需包含DCS趋势、工艺指标等多类文档的关键信息，避免上下文溢出 |
| 单次搜索上限 | 前6条 | 基础化工文档量适中，过多结果会干扰问答精准性 |

## 容易做错的三处
- 现象：上一个问题的结论未被带入下一个问题的提示词。原因：未配置`formInput`的上下文绑定规则，导致问答流程脱节。
- 现象：选择模型的界面元素持续跳动。原因：未配置模型的环境变量绑定，导致前端反复请求接口刷新状态。
- 现象：输入知识库内容后返回格式错误的结果。原因：未按工艺文档的字段结构配置`userSelect`的选项关联，导致召回文档与问题不匹配。

## 怎么确认配好了
- 发起两个关联的点检问题，确认第二个问题的提示词包含第一个问题的结论。
- 查看模型配置页面，确认已绑定正确的环境变量，界面无持续跳动的状态。
- 录入带单位的工艺参数，确认表单会触发单位校验提示。
- 检索联锁旁路记录文档，确认召回结果与当前作业类型的`userSelect`选项匹配。
