# 塑料注塑成型的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
本品类的核心数据来自注塑件生产企业的多类业务文档与设备数据源。日常文档包含注塑工艺卡、原料干燥记录、模具履历、首件检验表、巡检表、换料清机记录，字段涵盖充填保压冷却窗口参数（单位为秒、兆帕）、原料含水率、模次、巡检温度（摄氏度）等。数据来源包括树脂批次物性表、注塑机实时参数、模温机数据、MES系统记录、尺寸外观检测结果，更新频率为每批生产、每次换模换料、每班巡检时更新。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据多源且更新频繁，要求索引支持增量更新以适配每班、每批的高频数据变动。不同文档类型的信息长度差异较大，工艺卡段落较长而巡检表条目较短，需适配分块策略避免跨语义截断。数据包含明确的单位与批次标识，向量建模时需保留元数据以关联溯源信息。注塑场景的错误后果严重，需严格控制召回结果的相关性，避免低匹配度数据干扰维修决策。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配注塑工艺卡、模具履历等文档的单段信息长度，避免拆分关键工艺参数 |
| 重叠长度 | 100–150 字符 | 保留换模换料、班次交接的上下文关联，防止流程信息被截断 |
| 相似度阈值 | 0.72–0.85 | 适配注塑设备参数、工艺规则的语义匹配精度，过滤低相关召回结果 |
| 单次搜索上限 | 前6条 | 匹配注塑场景常见问题的关联文档数量，避免冗余信息干扰决策 |
| maxToken | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| defaultToken | 2048 | 控制单条向量的最大token数，平衡召回精度与索引存储成本 |

## 容易做错的三处
- 现象：界面索引模型下拉框无可用选项。原因：未提前配置本地向量模型的运行环境，或FastGPT v4.17.0版本的模型映射配置未正确写入系统。
- 现象：召回结果未附带具体文档来源信息。原因：向量入库时未在元数据中嵌入文档文件名、生产批次等标识字段，导致溯源信息丢失。
- 现象：搜索结果条数与设置的单次搜索上限不符。原因：未针对注塑场景的高频更新数据调整索引分片策略，导致分片内召回数量未达预期。

## 怎么确认配好了
- 上传一份注塑工艺卡文档，触发向量入库流程，检查界面中该文档的元数据是否包含文件名、上传时间等标识。
- 输入注塑设备常见维修问题（如“模温过高导致产品缩水”），查看召回结果是否附带对应的文档来源信息。
- 调整相似度阈值的设置，验证搜索结果的相关性是否随阈值变化合理调整。
- 上传多份不同类型的注塑场景文档（如模具履历、巡检表），确认索引可同时召回多源关联数据。
