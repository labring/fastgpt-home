# 塑料注塑成型的设备点检与维修问答：工作流编排

## 这个品类的数据长什么样
该品类的数据覆盖注塑全流程环节，日常文档包含注塑工艺卡、原料干燥记录、模具履历、首件检验记录、巡检表、换料清机记录。数据来源包括树脂批次与物性表、注塑机运行参数、模温机数据、生产执行系统（MES）、尺寸与外观检测结果。数据更新频率为每生产批次、每次换模换料操作、每班巡检周期，文档字段包含设备编号、工艺参数阈值、原料含水率、模具使用次数等，字段单位涵盖摄氏度、兆帕、秒、毫米等。

## 这些特征在「工作流编排」这一环带来什么约束
数据更新频率高且触发场景分散，要求工作流支持按事件触发，不使用固定周期调度。多类型异构数据源需要工作流整合不同格式的文档与实时设备数据，需配置统一的参数映射规则。单次生产批次关联的文档量随换模换料波动，需限制工作流单次调用的上下文加载上限，避免资源过载。设备点检与维修的问题需关联特定模具、批次原料的历史数据，要求工作流节点支持绑定`variables`与`nodeId`参数传递上下文，确保每个流程实例关联对应生产场景的专属数据。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 触发条件 | 按`variables`传递的生产批次号匹配 | 仅在对应批次的换模换料或巡检节点触发工作流，减少无效运行 |
| 工具执行顺序 | 按节点配置的执行序号依次运行 | 确保巡检数据调取、工艺参数校验、维修方案生成按逻辑顺序执行 |
| 上下文加载上限 | 前8条关联历史文档 | 匹配单次生产批次关联的文档规模，控制内存占用 |
| 响应文本过滤 | 移除系统自带的平台声明语句 | 贴合设备维修问答的专业场景，避免输出无关内容 |
| 超时阈值 | 600秒 | 适配注塑设备数据调取与问题分析的平均耗时 |
| 上下文绑定 | 绑定`nodeId`传递当前注塑机ID | 确保每个工作流节点关联对应设备的历史履历与运行数据 |

## 容易做错的三处
- 现象：工作流中多工具节点未按预期顺序执行，部分工具未触发调用。原因：未配置工具执行序号，或序号配置重复，导致系统无法识别执行优先级。
- 现象：AI生成的维修回答末尾附带未配置的系统声明语句。原因：未开启响应文本过滤配置，默认保留了平台自带的输出内容。
- 现象：问题分类节点响应耗时波动较大，无法匹配巡检周期要求。原因：未按`variables`传递的场景参数过滤关联文档，导致每次调用加载的文档量差异过大。

## 怎么确认配好了
- 手动触发对应换模换料事件的工作流，检查工具是否按配置顺序依次执行。
- 查看AI生成的维修回答，确认未出现未配置的系统声明内容。
- 查看工作流运行日志，确认节点调用耗时符合预设的超时阈值范围。
- 检查`variables`与`nodeId`参数是否正确传递了生产批次与设备ID信息。
