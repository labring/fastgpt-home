# 家具与木制品制造的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据通常来自订单设计系统、板材与木材批次记录、数控开料与钻孔设备、ERP/MES系统及含水率检测设备。日常文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金清单、试装与包装记录。数据更新随订单、每日或每批材料触发，文档多包含板件尺寸、工艺参数、五金型号等字段，无统一固定格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散且更新频繁，要求索引支持增量更新以避免全量重建耗时过长。文档包含结构化清单与非结构化工艺文件，分块时需保留业务关联信息，避免拆分破坏板件尺寸、孔位等关键内容。定制订单驱动的单批次板件数量较多，需限制单次召回的结果数量以适配上下文窗口。不同来源的文档格式差异大，需兼容多类型文件的向量化处理。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配该品类开料清单、工艺文件的单段业务逻辑长度，避免拆分破坏板件尺寸、五金关联信息 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的上下文，防止拆单图的孔位、工艺步骤信息被拆分断裂 |
| 相似度阈值 | 0.75–0.85 | 设备点检与维修问答需精准匹配设备型号、工艺参数，阈值过低易引入无关结果，过高则召回不足 |
| 单次搜索上限 | 前 10 条 | 单订单板件数量较多，限制初始召回量以控制上下文总长度 |
| `maxToken` | 4000 token | 适配 FastGPT v4.17.0 的上下文窗口，避免超出模型处理上限 |
| `defaultToken` | 按实测标定 | 不同批次的板材、工艺文档长度差异较大，需根据实际上传文档调整基础 token 分配 |

## 容易做错的三处
- 现象：上传文档时界面显示分8段，后续查看变为13段，出现重复片段。原因：未设置固定分块长度，文档内的换行、空格触发自动重新分块，且增量索引未清理旧版本片段。
- 现象：从旧版本升级到 FastGPT v4.17.0 后，原有可查询的设备维修内容无法检索到。原因：升级后索引格式发生变更，未重新生成向量索引。
- 现象：上传 Excel 格式的开料清单后，向量化后的索引结果匹配错误。原因：未清理 Excel 内的合并单元格、隐藏列，分块时提取了无效的空白字段。

## 怎么确认配好了
- 上传单份开料清单文档，查看分块预览，确认每段包含完整的板件尺寸、工艺参数信息，无断裂拆分。
- 执行两次相同的设备点检问题查询，对比返回的片段数量，确认无重复索引片段。
- 升级 FastGPT 版本后，对原有设备维修文档执行重新索引操作，验证可正常检索到内容。
- 上传 Excel 格式的五金清单，检查分块预览是否提取了有效字段，无空白或错误内容。
