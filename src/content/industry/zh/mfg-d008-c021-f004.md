# 家具与木制品制造的设备点检与维修问答：工作流编排

## 这个品类的数据长什么样
家具与木制品制造的设备点检与维修问答相关数据，主要来自订单设计系统、板材与木材批次台账、数控开料与钻孔设备日志、ERP/MES系统、板材含水率检测设备。数据更新节奏随业务节点变化，每生成一张订单就更新拆单图与开料清单，每日同步设备运行日志与涂装工艺参数，每批原材料入库时更新批次信息与检测记录。日常业务文档包含拆单图、开料清单、封边与钻孔加工程序、涂装工艺卡、五金配套清单、试装与包装记录，各文档字段包含板件尺寸（毫米）、加工工序编号、板材批次号、涂装厚度（微米）、五金型号等，需按订单维度关联各类型数据。

## 这些特征在「工作流编排」这一环带来什么约束
这些数据特征对工作流编排带来明确约束。首先，按订单维度关联的多类型文档，要求工作流需通过`variables`传入订单ID作为分组标识，避免跨订单数据混淆。其次，不同数据源的更新节奏差异，要求工作流节点配置触发条件，区分实时设备日志调用与批量订单文档处理。再者，多类型业务文档的字段差异，要求工作流中配置不同的解析节点，适配拆单图的尺寸参数、设备日志的运行时长等不同字段。最后，定制化订单驱动的生产模式，要求工作流支持动态传入个性化参数，不适合使用固定参数模板。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 按订单ID、板材批次号定义全局变量，取值为`订单ID: 字符串, 板材批次号: 字符串` | 适配FastGPT v4.17.0版本的变量管理规则，匹配按订单分组的业务数据关联需求，避免数据混淆 |
| `nodeId` | 绑定设备点检节点与对应工序节点，取值为`设备日志节点ID + 工序编号` | 将设备运行数据与生产工序精准关联，匹配业务数据的订单维度关联规则 |
| 触发条件 | 按订单生成时间触发，取值为`每日0点批量处理前一日设备日志，实时触发新订单的点检请求` | 匹配不同数据源的更新节奏，区分实时与批量处理，适配业务节点的更新频率 |
| 上下文窗口 | 8000–12000 token | 适配多类型业务文档的内容长度，避免上下文溢出，适配家具木制品制造的多文档场景 |
| 节点超时时间 | 600秒 | 适配大型开料设备日志的解析与检索时长，避免超时中断 |
| 单次检索上限 | 前20条 | 适配板件数量多的场景，避免过多数据占用上下文，提升检索效率 |

## 容易做错的三处
- 现象：工作流中运行自定义代码时，出现`localStorage is not defined`报错。原因：工作流运行环境不支持浏览器端的localStorage对象，需改用FastGPT内置的`variables`存储临时数据。
- 现象：工作流中配置多语言开场白时，仅显示单一语言内容。原因：未在`variables`中传入语言标识参数，导致无法根据请求动态切换开场白。
- 现象：通过API发起工作流请求后，未获取到思考过程内容。原因：未在工作流节点中开启思考过程输出配置，或未在API请求参数中指定返回类型。

## 怎么确认配好了
- 发起测试订单的工作流请求，检查`variables`中传入的订单ID是否正确关联到对应的拆单图与设备日志数据。
- 运行工作流节点，验证自定义代码模块是否能正确读取`variables`中的临时数据，无报错信息。
- 调用API发起工作流请求，检查返回结果是否包含预期的设备点检与维修问答内容，以及配置的思考过程输出。
- 查看工作流运行日志，确认节点超时时间设置符合实际业务场景，未出现频繁超时中断。
