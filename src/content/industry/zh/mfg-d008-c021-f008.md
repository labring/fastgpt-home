# 家具与木制品制造的设备点检与维修问答：文档解析与分块

## 这个品类的数据长什么样
该品类数据主要来自订单设计系统、板材与木材批次记录、数控开料钻孔设备、ERP/MES系统及含水率检测设备。日常文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金清单、试装与包装记录。数据更新随订单、每日或每批材料触发，字段包含板件尺寸、木材含水率、五金型号、订单编号等，单位涵盖毫米、百分比、件数等。

## 这些特征在「文档解析与分块」这一环带来什么约束
定制订单驱动的生产模式带来大量个性化板件数据，单份文档常包含上万行表格或十万级中文字符内容，对分块粒度与解析效率提出明确要求。多样的文档结构混合了表格参数、工艺文本与程序代码，需保留不同类型内容的上下文关联。高频更新的生产数据要求解析流程具备足够容错性，避免因超时或分块不合理导致生产环节数据丢失，同时需确保个性化字段的准确匹配。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配单块板件参数、五金清单等短字段，避免单块包含过多跨订单数据导致上下文混乱 |
| `chunkSplitter` | 按段落+表格拆分 | 适配拆单图、工艺文档的混合结构，保留工艺步骤与板件参数的逻辑关联 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 处理10万中文字word文档或15000行excel数据时，避免解析过程超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单批次订单的全套生产文档批量上传 |
| `chunkSettingMode` | 手动细分 | 针对定制化订单文档，灵活调整分块粒度以匹配设备点检与维修的查询场景 |

## 容易做错的三处
- 解析excel文档后返回不完整命令提示，原因是默认`chunkSize`设置过大，单块包含上万行数据导致上下文溢出，模型无法识别有效内容。
- 解析大体积word文档时出现解析失败状态，原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认时长不足以完成十万级字符的完整解析流程。
- 分块后丢失板件与对应工艺的关联信息，原因是未选择按段落+表格拆分的`chunkSplitter`，直接按纯字符拆分破坏了文档的逻辑结构。

## 怎么确认配好了
- 上传单份10万中文字word文档，确认解析状态在`PARSE_FILE_TIMEOUT_SECONDS`设定时长内完成。
- 上传15000行excel测试文件，检查分块后每个块的字符数是否落在`chunkSize`设定区间内。
- 随机抽取分块结果，确认每个块都包含完整的板件参数、工艺步骤或五金清单条目。
- 提交设备点检相关的查询，验证返回的分块内容与查询问题的匹配度符合预期。
