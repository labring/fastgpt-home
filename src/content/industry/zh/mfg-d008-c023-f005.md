# 工业仪器仪表制造与校准的设备点检与维修问答：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来自设计文件、标准器和环境监测数据、校准软件导出内容、实验室信息系统及客户量程要求。单台设备每次校准都会更新对应数据，日常文档包含装配调试单、校准规程、原始校准记录、误差曲线、计量证书、软件版本记录。数据字段包含校准日期、标准器编号、被测件量程、误差值、计量证书编号，单位涉及压力、温度、流量等物理量的标准计量单位。

## 这些特征在「工具调用与插件」这一环带来什么约束
因数据按单台设备每次校准更新，工具调用需绑定设备唯一标识，避免跨设备数据混淆。因文档包含误差曲线、计量证书等结构化与非结构化内容，插件需适配多格式文档解析。因数据溯源要求严格，工具调用需自动校验计量证书编号等溯源字段的合法性。因校准流程包含多点误差采集与溯源链审核，工具调用需覆盖较长的耗时场景。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | 设为`auto`并绑定设备唯一标识 | 精准匹配单台仪器的校准记录，避免跨设备数据调用错误 |
| `functionCall` | 开启，指定误差曲线解析、计量证书校验函数 | 适配本品类需解析多类型校准文档的需求 |
| 工具调用超时 | 600秒 | 覆盖建立标准器连接、多点误差采集、溯源链审核的耗时流程 |
| 自定义渠道配置 | 按实测标定 | 适配不同校准软件、实验室信息系统的接口格式 |
| 单次调用最大上下文 | 16000 token | 适配本品类校准文档的总长度要求 |
| 多结果聚合逻辑 | 按校准日期降序取前3条 | 聚焦最新校准数据，符合计量溯源的时效性要求 |

## 容易做错的三处
- 现象：配置自定义渠道后调用返回报错或空结果。原因：未匹配对应校准软件的接口鉴权参数或字段格式要求。
- 现象：工具调用后未返回预期的校准记录内容。原因：未绑定设备唯一标识，导致工具无法精准匹配单台仪器的对应数据。
- 现象：工作流中多个AI节点的输出全部出现在最终回复中。原因：未配置结果聚合环节的前置输出过滤规则，未按校准数据的时效性筛选有效内容。

## 怎么确认配好了
- 发起单台仪器的点检问题测试，检查工具调用是否返回对应设备的校准记录。
- 查看工具调用日志，确认`toolChoice`和`functionCall`参数的配置与预期一致。
- 触发自定义渠道调用，验证接口返回的字段是否包含计量证书编号、误差值等本品类核心数据。
- 运行包含多知识库搜索的工作流，确认仅聚合后的校准数据出现在最终回复中。
