# 工艺变更与工程变更的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类的数据来自PLM、ERP、MES、供应商资料、验证试验及客户特殊要求。更新节奏为不定期，每次工艺或工程变更触发更新。日常文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本文件、工艺验证报告、新旧版本切换计划、库存处置单及客户批准文件。数据字段包含变更唯一编号、版本号、生效日期、涉及物料/工艺/设备清单、验证结果等，无统一固定单位，随文档类型调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据来源分散且关联紧密，多轮对话需先拉取对应变更单的跨系统关联数据，因此需要绑定唯一标识关联上下文。文档结构复杂且包含多份附件，提示词需引导提取特定字段，避免冗余信息干扰分析。更新无固定周期，对话需支持实时查询最新版本的变更文件。连锁影响识别环节要求多轮对话按步骤拆解变更点，逐步引导用户补充信息，支撑完整的影响分析。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定变更单唯一标识 | 确保对话上下文仅关联当前变更单，避免跨单数据混淆 |
| `messages` | 保留前20条历史对话 | 覆盖变更流程中多角色、多步骤的交互信息，支撑连锁影响分析 |
| `variables` | 预设变更编号、当前版本号、生效日期变量 | 快速调用对应PLM/ERP系统中的变更文档数据，减少手动输入 |
| 超时时间 | 600 秒 | 适配内部系统数据调用的响应时长，避免长流程对话超时 |
| 最大上下文 | 8000–12000 token | 覆盖变更相关的多份文档内容，避免截断关键验证或审批信息 |
| 单次搜索上限 | 前8条 | 平衡召回精度与对话响应速度，避免过多无关数据干扰分析 |

## 容易做错的三处
- 现象：对话返回`connection error`报错，开启代理后仍无法恢复。原因：未将PLM、MES等内部系统的访问地址配置到FastGPT的代理规则中，导致对话调用内部数据失败。
- 现象：配置多轮对话后，中间分析步骤的输出内容无法隐藏。原因：未正确过滤`messages`参数中的中间思考内容，误将非展示内容纳入可输出列表。
- 现象：对话无法自动提取变更单的版本号字段。原因：未在`variables`中预设对应字段的映射规则，导致提示词无法获取上下文变量信息。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，发起对应变更单的对话，检查对话绑定的`chatId`是否与变更单唯一标识一致，确认上下文关联正确。
- 触发对话后，查看返回内容是否包含预设的`variables`变量值，验证变量调用正常。
- 模拟多轮变更分析对话，检查历史消息是否按顺序保留，确认`messages`参数配置生效。
- 调用内部系统数据接口，确认无`connection error`报错，验证系统连通性配置正确。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
