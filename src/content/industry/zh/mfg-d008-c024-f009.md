# 工艺变更与工程变更的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
本品类的数据由制造企业研发、工艺、质量、生产、采购共同参与的变更管理团队产生，数据来源包括PLM、ERP、MES系统、供应商资料、验证试验记录及客户特殊要求文件。日常产出的文档包含ECN/ECR表单、变更评估报告、图纸与BOM版本文件、工艺验证报告、生产切换计划、库存处置单及客户批准文件。数据更新随每次变更不定期触发，文档字段包含变更编号、版本标识、生效节点、关联物料编码、检验结果等，无统一固定单位，随文档类型变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且涉及多系统，需配置适配不同系统导出格式的拉取规则，确保跨源数据的一致性。文档类型多样且结构差异较大，需配置适配不同文档长度与字段结构的分块策略，避免分块破坏变更关联信息的完整性。数据更新无固定周期，需配置按需触发的同步机制，确保调用模型时使用最新的变更相关文档。文档包含客户批准文件等敏感内容，需配置权限控制规则，限制敏感数据的访问范围。变更关联的物料、工艺信息关联性强，需配置上下文关联规则，确保问答时能准确匹配变更相关的所有文档内容。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体配置项及建议如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配ECN/ECR、BOM版本等多文档拼接的上下文长度需求，避免截断关键变更关联信息 |
| `maxTokens` | 2000–3000 token | 匹配设备点检与维修问答的单次回复长度需求，确保变更相关的详细说明可完整输出 |
| `quoteMaxToken` | 1500–2000 token | 限制引用文档的单段长度，避免引用内容过长导致上下文溢出 |
| `temperature` | 0.3–0.5 | 降低随机输出概率，保证变更流程、文档版本等信息的准确性 |
| `AIPROXY_API_ENDPOINT` | 企业内部代理地址 | 适配分散的多系统数据拉取需求，实现跨源数据的安全转发 |
| `AIPROXY_API_TOKEN` | 企业专属鉴权令牌 | 确保仅授权的变更管理团队可调用模型服务，保护敏感的客户批准文件等数据 |

## 容易做错的三处
- 现象：调用模型时返回`do_request_failed`报错。原因：未正确配置`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`，导致无法完成跨系统数据拉取或模型调用。
- 现象：问答结果中出现新旧版本混用的内容。原因：未配置`maxContext`适配多文档上下文，导致模型调用时截断了版本切换的关键节点信息。
- 现象：返回结果中未引用客户批准文件相关内容。原因：未配置权限控制规则，导致敏感文档未被纳入召回范围。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置，发起测试请求，确认无连接报错。
- 输入包含变更版本关联的测试问题，核对返回结果中是否包含正确的ECN编号与BOM版本信息。
- 导入一份客户批准文件的测试文档，确认问答时可正确引用该文档的内容。
- 调整`temperature`参数，核对输出结果的一致性，确认参数生效。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
