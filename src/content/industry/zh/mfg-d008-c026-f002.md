# 有色金属冶炼与电解的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据覆盖铜、铝、铅锌等冶炼企业的熔炼、电解、化验与调度部门，日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账。数据来源涵盖精矿与辅料分析结果、DCS系统数据、槽电压电流监测数据、化验室检测报告、能源与环保监测数据。更新节奏随原料批次、炉次或电解槽工况实时调整，部分台账按固定周期归档。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类多源异构的数据特征要求索引支持混合格式内容的分块与关联存储，实时更新的工况数据需要适配增量索引机制，避免全量重建的耗时。不同文档的字段差异显著，如槽况记录包含槽电压、电流等带单位的数值字段，配料单标注原料成分占比，分块时需保留字段与上下文关联，避免拆分破坏业务逻辑。高频更新的实时数据与低频归档的台账并存，需配置分层索引策略以平衡检索效率与存储成本。同时，设备点检与维修问答的业务需求要求检索结果需精准匹配炉况、槽况等核心工况信息，对召回精度有较高要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 覆盖单条电解槽况记录或配料单的核心业务字段，避免拆分破坏上下文关联 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的业务衔接信息，防止跨块检索丢失关联逻辑 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 200 token | 保留单条设备点检记录的核心参数，避免截断关键业务信息 |
| 相似度阈值 | 0.72–0.85 | 过滤低相关的非工况类文档，精准召回炉况或槽况相关内容 |
| 单次召回上限 | 前 8 条 | 匹配调度与点检人员的日常检索需求，避免过多冗余结果干扰判断 |

## 容易做错的三处
- 现象：配置百度embedding-v1后返回404报错，无法完成索引模型绑定。原因：未正确配置接口路由与密钥权限，导致嵌入模型调用链路中断。
- 现象：无GPU环境下部署m3e模型后，无法在FastGPT界面添加为索引模型。原因：未开启CPU模式运行嵌入模型容器，或未在配置中指定CPU适配的模型运行参数。
- 现象：检索结果中出现跨炉次的不相关槽况数据，召回条数不符合预期。原因：分块长度设置过小，拆分了单炉次的完整工况记录，导致上下文关联丢失。

## 怎么确认配好了
- 上传单条电解槽况记录，基于FastGPT v4.17.0的界面查看分块后的文本，确认保留槽号、电压、电流等核心字段，无截断或错误拆分。
- 发起“检查今日1号电解槽工况”的检索，核对召回结果的相似度评分是否落在配置的阈值区间内。
- 导入一批实时DCS系统数据，查看索引是否自动完成增量更新，无全量重建的提示。
- 测试调用嵌入模型接口，确认返回的向量维度与FastGPT配置的嵌入模型维度一致。
