# 有色金属冶炼与电解的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据覆盖铜、铝、铅锌等冶炼企业的熔炼、电解、化验与调度部门，日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账。数据来源包括精矿与辅料分析结果、DCS系统、槽电压电流监测数据、化验室报告、能源与环保监测系统。数据更新频率随每批原料、每炉或每槽调整，部分关键参数如槽电压、电流为实时更新。文档字段包含配料比例、炉温、槽况参数、金属品位、杂质含量等，需匹配对应文档类型识别字段与单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
实时更新的工况数据要求多轮对话可快速拉取最新的炉况、槽况参数，避免使用过期数据开展点检。多类专业文档的细分字段需要提示词明确指定检索范围，例如仅从电解槽况记录中召回相关内容。复杂的金属平衡与杂质控制流程需要保留多轮对话上下文，避免点检人员重复输入设备编号、原料批次等参数。同时，该品类出错后果直接关联金属回收率与环保指标，提示词需加入工况校验逻辑，确保提问匹配实际设备状态。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按点检工单绑定唯一设备编号 | 区分不同熔炼炉、电解槽的对话上下文，避免跨设备信息混淆 |
| `messages` | 保留前20轮对话内容 | 覆盖单炉/单槽的完整点检流程，避免关键工况参数丢失 |
| 最大上下文长度 | 8000–12000 token | 适配有色金属冶炼专业文档的长内容召回与对话上下文存储，符合FastGPT v4.17.0的规范 |
| 问题优化 | 开启 | 将点检人员的口语化提问转化为匹配专业文档的规范查询 |
| 单次搜索上限 | 前8条召回结果 | 平衡专业文档的召回精度与对话响应速度 |

## 容易做错的三处
- 现象：工作流运行至AI对话环节后无响应，复现特定问题时触发。原因：未绑定`variables`参数传递当前点检设备的槽号或炉号，导致知识库无法定位对应品类的专属文档，流程中断。
- 现象：API方式调用对话无流式输出，前端无法逐步展示回复内容。原因：未开启对话的流式返回配置，或未按标准格式封装响应数据。
- 现象：对话日志的标注功能无法生效，标注内容未同步至知识库。原因：未开启对话日志的自动同步配置，或标注范围未覆盖设备点检相关的对话片段。

## 怎么确认配好了
- 发起针对特定电解槽的点检提问，检查对话上下文是否保留前序输入的槽号、当前槽电压等参数。
- 调用API发起对话，验证响应是否按流式分段返回，前端可逐步接收内容片段。
- 进入对话日志页面，尝试标注一段设备点检相关的对话内容，确认标注可正常保存且无报错。
- 触发完整工作流，从问题优化、知识库搜索到AI对话环节依次执行，无中途中断现象。
