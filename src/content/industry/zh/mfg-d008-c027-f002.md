# 服装裁剪与缝制的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自服装OEM/ODM车间、品牌供应链环节，日常文档包含工艺单、CAD样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等。数据来源覆盖订单与尺码表、面辅料检验记录、吊挂系统运行数据、验针机检测结果及客户封样文件。数据更新随每笔订单、每款服饰、每批生产批次触发，文档字段包含具体尺码、面料色号、裁片编号、工序要求等，无统一固定的字段顺序，随订单需求动态调整。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据随订单、款式、批次高频更新，要求索引支持增量同步与快速更新。文档字段分散且无统一格式，部分文档包含CAD样板的坐标参数与裁剪比例数据、吊挂系统的工序节点数据，向量模型需适配非标准化文本与结构化参数混合的内容。裁片不可逆的特性要求检索结果需精准匹配工序要求与尺码规格，避免模糊匹配导致的生产偏差。多来源数据的格式差异，要求索引配置需兼容不同类型的文本与数值类输入。

## 配置怎么定
本页面配置规则基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配工艺单、排料图等文档的单段内容长度，避免跨工序信息被拆分 |
| 重叠长度 | 100–200 字符 | 保留工序间的关联信息，防止裁片配套要求被分块截断 |
| 相似度阈值 | 0.75–0.85 | 匹配服装尺码、色号等精准字段的要求，过滤低相关的维修参考内容 |
| `maxToken` | 4096 token | 适配设备点检手册、长工序说明等长文本内容，确保完整加载维修步骤 |
| 单次搜索上限 | 前10条 | 覆盖同款式不同尺码的维修参考，避免结果过多导致筛选困难 |
| 重排 | 按检索分数降序 | 优先展示与设备型号、工序要求匹配度最高的内容 |

## 容易做错的三处
- 检索结果排序不符合预期，部分与当前订单尺码、工序匹配度高的内容排在较后位置。原因：未配置针对工序、尺码字段的二次重排，仅依赖初始检索分数排序，未适配服装品类的精准匹配需求。
- 调用向量模型时出现“undefined model”报错。原因：未选择官方支持的向量模型，或输入的模型名称格式不符合要求，部分非标准模型无法被系统识别。
- 辅助数据被错误纳入索引导致检索冗余。原因：未区分核心维修文档与辅助的面辅料检验记录，将非维修相关的辅助数据一并向量化，增加了无效检索结果。

## 怎么确认配好了
- 上传一份包含具体尺码和工序要求的工艺单，查看系统分块后的文本是否完整保留了裁片配套、色号要求等关键信息，验证分块长度与重叠长度的配置效果。
- 输入设备点检相关的查询，检查检索结果的排序是否优先匹配当前订单的款式与尺码，验证相似度阈值与重排配置的合理性。
- 提交新增的维修文档，查看索引是否在合理时间内完成更新，验证增量同步配置的有效性。
- 测试不同官方支持的向量模型的调用，确认无模型格式错误的报错，验证模型配置的正确性。
