# 服装裁剪与缝制的设备点检与维修问答：文档解析与分块

## 这个品类的数据长什么样
该品类的日常文档包含工艺单、样板、排料图、裁剪单、首件封样、工序质量表、包装配码单。数据来源为订单与尺码表、CAD样板、面辅料检验记录、吊挂系统数据、验针机数据及客户封样信息。数据更新随每订单、每款、每批进行，文档多包含尺码参数、面料方向要求、裁片数量、包装配比等字段，部分CAD导出的样板文件格式与通用办公文档存在差异。

## 这些特征在「文档解析与分块」这一环带来什么约束
该品类的多类型文档结构差异显著，CAD样板、排料图等文件与通用办公文档格式存在区别，解析时需适配不同文件的字段逻辑。数据更新频率高，单批订单的文档需在短时间内完成解析与分块，避免影响后续工序衔接。裁片数量、尺码参数、面料方向等关键信息需完整保留上下文，分块时不能拆分跨字段的关联内容，否则会导致后续点检与维修问答无法匹配对应工艺要求。部分文档包含图形化数据，解析时需兼顾文本与图形关联信息的提取。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配该品类文档中包含多字段的段落长度，避免拆分关键工艺与尺码关联信息 |
| `chunkSplitter` | 按段落+语义分块 | 适配工艺单、排料图等文档的结构化段落，保留跨字段的上下文关联 |
| `customPdfParse` | 启用CAD格式适配模式 | 针对导出的CAD样板PDF文件，修正通用解析对图形关联文本的提取偏差 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 容纳单批订单包含的多份大尺寸排料图、样板文件，避免上传被拦截 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配几百页的批量工艺单解析时长，避免因文件过大触发超时错误 |
| `chunkSettingMode` | 自定义模式 | 针对不同文档类型切换分块规则，适配工艺单与包装配码单的结构差异 |

## 容易做错的三处
- 现象：调用doc2x解析几百页的排料图PDF时触发报错，几十页文件可正常解析。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，大文件解析耗时超出默认阈值，触发超时中断。
- 现象：本地部署的FastGPT v4.17.0无法启用文件解析功能。原因：未正确配置`customPdfParse`的依赖环境，或未开放对应端口权限。
- 现象：启用pdf-marker后，大尺寸工艺单解析时一直等待结果，无法完成解析。原因：未设置解析任务排队机制，多任务同时提交导致资源耗尽，无法及时返回解析结果。

## 怎么确认配好了
- 上传单份500页的工艺单PDF，检查解析进度是否在600秒内完成，无超时报错。
- 上传CAD导出的样板文件，核对解析结果中是否保留了面料方向、裁片数量等关键字段的关联内容。
- 提交多份不同类型的文档，确认解析任务按顺序执行，无任务堆积或无响应情况。
- 调整`chunkSize`参数后，验证分块结果未拆分同一尺码对应的工艺段落，符合分块逻辑要求。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
