# 服装裁剪与缝制的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
这个品类的日常文档包含工艺单、CAD样板、排料图、裁剪单、首件封样、工序质量表、包装配码单等。数据来源涵盖订单与尺码表、CAD设计文件、面辅料检验记录、吊挂系统运行数据、验针机检测结果及客户封样资料。数据更新节奏为每订单、每款、每批调整，款式多、季节性强，裁片不可逆且人工工序密集，与面料本体加工品类存在明显差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
品类的多批次、高频更新的数据要求模型接入时适配动态文档结构，避免固定分块逻辑导致的关键工序信息丢失。裁片不可逆的属性要求点检维修问答的知识库召回需精准匹配版型、工艺细节，因此需严格限制上下文与召回内容的冗余度。人工工序密集的特点意味着需处理大量工序质量相关的文本与数值数据，模型配置需兼顾长文本解析与字段提取能力。同时，季节性款式变化要求配置支持快速切换知识库数据源，适配不同批次的工艺要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 适配品类多工序、长文档的上下文需求，避免关键工艺信息被截断 |
| `maxTokens` | `4000 token` | 控制单轮回答长度，适配工序质量表、排料图等文档的解析输出 |
| `quoteMaxToken` | `2000 token` | 限制知识库召回的总字符数，避免冗余内容干扰维修点检的精准判断 |
| `temperature` | `0.3–0.5` | 降低随机输出概率，确保工艺参数、尺码要求等内容的一致性 |
| `toolChoice` | `auto` | 自动选择是否调用工具，适配设备点检中需要调取历史维修记录的场景 |
| `AIPROXY_API_TOKEN` | 按部署环境填写对应密钥 | 确保模型调用的身份验证有效，避免权限异常 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写对应接口地址 | 适配本地或云端部署的模型调用路径，确保接口连通性 |

## 容易做错的三处
- 配置`AIPROXY_API_TOKEN`时未正确关联环境变量，导致模型调用返回403 status code (no body)。原因是未在部署配置中加载对应密钥的环境变量，或参数填写错误。
- 工作流中的对话提示词无法正确识别空格，导致工艺单中的尺码组合（如「S/M」）被错误拆分。原因是提示词未明确指定保留文本中的空格格式，或分块配置未保留原始文本间距。
- 尝试切换知识库关联的模型时出现召回异常。原因是未同步更新对应模型的调用参数，导致匹配逻辑与当前模型不兼容。

## 怎么确认配好了
- 发起包含工艺单关键参数的测试提问，核对模型返回内容是否准确匹配文档中的工序要求。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`的配置已成功建立连接，无报错信息。
- 调整`temperature`参数后，多次发起同类提问，核对返回结果的一致性是否符合预期。
- 导入一批测试用的裁剪单与工序质量表，验证知识库召回的内容是否与输入文档匹配。
