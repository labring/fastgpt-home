# 来料检验与供应商质量的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据来自采购订单、图纸规格、供应商质保书、检验设备采集数据、历史质量台账与供应商门户。日常处理的文档包含检验规范、抽样方案、来料检验报告、供应商审核报告、异常联络单、8D整改报告与让步接收审批单。数据更新节奏随来料批次触发，每月或季度完成供应商整体评价，不定期开展专项审核。数据字段包含来料批次号、供应商编号、检验项参数、不合格判定结果与整改记录，部分字段带有物理单位或时间戳。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源的数据来源要求配置支持多渠道数据接入，确保采购、检验设备与供应商门户的信息均可被检索到。不定时的更新节奏需要配置支持增量同步，避免重复加载全量历史数据。多样的文档类型需要适配不同的分块规则，保证检验规范的长文本与整改报告的短文本均可被正确解析。专属的批次与供应商字段要求检索时关联对应标识，提升匹配精度，同时严格的质量后果要求配置保证模型输出的一致性与准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 来料检验与供应商质量场景需关联多批次数据与历史整改记录，需保留足够上下文窗口 |
| `maxTokens` | 2000–3000 token | 需输出完整的检验判定建议、整改方向与引用依据，避免截断关键内容 |
| `temperature` | 0.2–0.4 | 需保证检验判定与整改建议的一致性，避免随机化结果影响质量管控 |
| `quoteMaxToken` | 1500 字符 | 需引用完整的检验规范或供应商审核报告片段，确保引用内容准确无遗漏 |
| `toolChoice` | auto | 按需调用检索工具获取最新来料数据或供应商历史记录，适配场景的动态信息需求 |

## 容易做错的三处
- 现象为知识库检索返回结果正常，但模型生成内容为空或无引用。原因是未正确配置`maxContext`参数，导致检索到的文档片段未被纳入模型上下文窗口。
- 现象为FastGPT升级到v4.17.0后，外部发布渠道无法调用生成结果，本地测试正常。原因是未更新`AIPROXY_API_ENDPOINT`或`AIPROXY_API_TOKEN`的适配配置，新版本接口路径或验证方式发生变更。
- 现象为检索结果无法匹配对应批次的来料检验数据。原因是未针对来料批次号、供应商编号等专属字段设置检索关联规则，导致匹配精度不足。

## 怎么确认配好了
- 上传一份最新的来料检验报告与供应商审核报告，发起设备点检相关问答，检查模型是否能正确引用报告中的检验项与供应商历史异常记录。
- 调整`temperature`参数至不同区间，对比两次生成的检验判定结果，确认结果一致性符合场景要求。
- 发布测试链接至外部渠道，发起测试问答，检查外部调用是否能正常返回带引用的完整结果。
- 查看系统日志，确认检索到的文档片段长度未超过`quoteMaxToken`的配置值，无内容截断情况。
