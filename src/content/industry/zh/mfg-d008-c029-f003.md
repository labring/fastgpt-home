# 模具设计制造的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的数据通常来自客户交付的产品模型、模流或成形仿真文件、CAD/CAM工程文件、机加工与尺寸测量记录、试模样件及检测报告。日常维护的文档包含模具设计任务书、DFM报告、零件加工图、工艺卡、试模报告、改模通知、模具履历表。数据更新按单个项目推进，每次试模、改模或量产节点变更时同步更新。数据字段包含模具编号、型腔数量、加工公差、材料牌号、试模缺陷记录等，无统一固定格式，随项目需求调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据格式多样且无统一标准，包含矢量工程文本、缺陷描述、检测记录等多种类型，因此多轮对话的提示词需要明确指定适配不同文档格式的提取规则，避免解析混乱。数据按项目迭代更新，每次试模、改模都会产生新内容，因此`chatId`需绑定单个项目会话，确保上下文仅关联当前模具的全生命周期数据，避免跨项目干扰。核心业务聚焦脱模缺陷、合模精度等点检维修场景，提示词需聚焦模具相关的设备类型与常见问题，同时需按试模、改模、量产等项目阶段组织上下文，确保对话逻辑贴合业务流程。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定单个模具项目的唯一标识 | 确保多轮对话上下文仅关联当前模具的全生命周期数据，避免跨项目信息干扰 |
| `variables` | 预设模具编号、试模批次、缺陷类型等项目专属变量 | 适配品类数据按项目更新的特征，提升问答的精准匹配度 |
| `messages` | 保留前20轮对话的上下文 | 覆盖模具项目多轮试模、改模的完整流程，确保对话逻辑连贯 |
| 最大上下文长度 | 8000–12000 字符 | 容纳单项目的设计文档、试模报告、改模记录等多类内容 |
| 提示词模板 | 前置指定「基于当前模具的试模报告、加工工艺卡回答点检与维修问题」 | 聚焦模具设计制造的专属业务场景，避免泛化问答 |
| 变量引用设置 | 开启替换后保留参数配置入口 | 支持动态调整对话相关参数，适配不同项目的调试需求 |

## 容易做错的三处
- 变量引用配置完成后，温度参数设置按钮消失，无法调整对话温度。原因是未在变量引用开启后保留参数配置入口，导致界面交互逻辑被覆盖。
- 调用接口绑定`chatId`后，对话日志中的运行数据为空。原因是`messages`参数未正确关联当前项目的上下文数据，导致系统无法调取对应记录。
- 在文本内容提取模块的提示词中传入any参数，提取代码块内容时返回undefine。原因是提示词未明确指定代码块的格式范围，无法匹配品类文档中多样的工程代码片段。

## 怎么确认配好了
- 发起针对单台模具的点检问题，核对对话上下文是否仅包含该模具的相关文档与历史对话。
- 测试变量引用功能，确认参数配置入口未被隐藏，可正常调整对话相关参数。
- 调用接口生成对话，检查日志中是否包含对应项目的运行数据与上下文记录。
- 输入包含代码块的试模缺陷描述，核对文本提取结果是否正确返回代码块内容。
