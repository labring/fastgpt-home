# 橡胶混炼与制品硫化的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来自配方系统、原材料批次记录、密炼机、门尼粘度仪、硫化机及实验室检测设备。日常文档包含配方单、称量记录、混炼曲线、胶料快检报告、硫化工艺卡、模具使用记录、成品性能报告。数据更新节奏为每车原料批次、每批胶料、每模次制品。字段涵盖配方组分占比、投料顺序、混炼温度与时长、硫化时间与压力、模具编号等，单位包含摄氏度、分钟、批次号等。

本文基于 FastGPT v4.17.0 版本的配置逻辑编写。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据更新频率高、文档类型多样且与设备运行强绑定，对向量模型与索引环节带来多重约束。高频更新要求索引支持增量同步，避免全量重建带来的性能损耗。多类型文档（如时序混炼曲线、文本工艺卡）需要适配不同的分块逻辑，确保特征提取完整。设备点检与维修的关联需求，要求索引能够精准绑定设备参数、工艺记录与维修历史字段，避免无关召回。同时数据错误会直接导致制品报废，需严格控制索引的召回准确率，减少无效返回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配混炼曲线、工艺卡等不同文档的文本长度，确保单块内包含完整的工艺节点或曲线片段 |
| 重叠长度 | 50–100 字符 | 保留相邻块之间的工艺关联信息，避免分块切断混炼温度变化、硫化时序等关键逻辑 |
| 相似度阈值 | 0.75–0.85 | 过滤与设备点检维修问题无关的配方、原材料批次记录，减少无效召回 |
| 单次搜索上限 | 前 8 条 | 匹配该品类高频的设备故障排查场景，控制返回结果的信息量，避免上下文过载 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 问题优化 | 开启 | 补充设备型号、工艺参数等上下文，让向量模型更精准匹配混炼、硫化环节的维修场景 |

## 容易做错的三处
- 现象：针对混炼温度异常的点检问题，知识库返回原材料批次的无关记录。原因：未设置合理的相似度阈值，或未对文档按设备点检维修场景做字段过滤。
- 现象：索引状态显示未就绪，无法触发搜索。原因：未配置增量同步的触发规则，或高频更新导致索引构建未完成。
- 现象：使用全表数据作为知识库时，返回结果与问题无关联。原因：未对索引的召回范围做限定，未提取与设备维修强相关的字段作为索引特征。

## 怎么确认配好了
- 提交混炼温度异常、硫化欠硫等典型点检维修问题，核对返回结果是否包含混炼曲线、硫化工艺卡等相关文档。
- 查看索引状态，确认显示就绪后再发起搜索测试。
- 调整相似度阈值，验证返回结果的相关性是否符合业务需求。
- 测试当日新生成的混炼记录、工艺卡等高频更新文档，确认是否能被正确索引并召回。
