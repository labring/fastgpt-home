# 橡胶混炼与制品硫化的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据主要来自轮胎、密封件、胶管等橡胶制品企业的配方系统、原材料批次台账、密炼机、门尼粘度仪、硫化机及实验室检测设备。日常文档包含配方单、称量记录、混炼曲线、胶料快检报告、硫化工艺卡、模具使用记录、成品性能报告，字段涵盖物料配比、温度参数、时间阈值、批次编号等，更新频率为每车原材料、每生产批次、每模次制品成型后同步更新。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据更新频率高且粒度细，要求多轮对话上下文需按批次或模次隔离，避免跨批次数据混淆；文档类型多样且字段专业，提示词需明确指定检索文档的字段范围，减少无关内容干扰；单次对话需关联多类数据（如混炼曲线与硫化工艺卡），需在多轮交互中逐步引导用户补充关键参数，避免单次请求过载。同时，该品类设备故障与工艺参数强绑定，提示词需优先关联当前生产批次的设备点检记录，聚焦专属生产数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配该品类的业务数据特征：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 传入当前生产批次、模具编号、设备运行参数，格式为`{"batchNo": "XXXX", "moldId": "XXXX"}` | 该品类数据按批次/模次更新，通过`variables`传入专属参数可精准匹配对应文档，避免检索跨批次的无效数据 |
| `messages` | 保留最近3轮对话内容，单轮`messages`数组总字符数不超过8000字符 | 混炼与硫化的业务数据更新频繁，精简上下文可减少冗余干扰，适配多轮交互的实时性要求 |
| 重排 | 开启，保留前3条重排结果 | 该品类文档包含多类专业字段，重排可过滤低相关的通用设备文档，聚焦当前批次的点检与维修记录 |
| 最大上下文 | 6000-12000 token，按实测标定 | 多轮对话需关联混炼曲线、硫化工艺卡、成品性能报告等多类文档，合理的上下文长度可覆盖完整业务场景 |
| `chatId` | 按生产批次生成唯一`chatId` | 该品类数据更新粒度细，唯一`chatId`可隔离不同批次的对话上下文，避免数据混淆 |

## 容易做错的三处
- 现象：调用API传入`variables`参数后，提示词内的变量未被替换，返回内容与预设的混炼/硫化场景无关。原因：未按FastGPT要求的JSON格式传递`variables`，或未在提示词中正确使用变量占位符。
- 现象：开启重排配置后，对话详情页未显示重排后的结果，检索结果条数与预设配置不符。原因：未正确完成重排模型的绑定配置，或重排请求超时未触发重试逻辑。
- 现象：多轮对话中触发文本内容提取节点未提取到有效内容，使用指定回复后未等待用户后续输入。原因：未配置多轮对话的上下文延续规则，未绑定`messages`的轮次保留逻辑。

## 怎么确认配好了
- 传入预设的批次与设备参数作为`variables`，发起测试对话，验证返回内容是否关联当前批次的专属文档。
- 查看对话详情页，确认上下文保留的轮次符合配置要求，无跨批次的历史数据干扰。
- 开启重排配置后，核对检索结果的筛选逻辑是否生效，过滤无关的通用设备文档。
- 配置英文提示词与英文知识库后，发起测试请求，确认输出内容符合预设的语言与专业场景要求。
