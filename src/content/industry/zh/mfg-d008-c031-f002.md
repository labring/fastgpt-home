# 水泥熟料与粉磨的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据来源包括在线成分分析系统、DCS集散控制系统、化验室检测数据、窑磨设备运行日志、原燃料台账与能源计量报表。数据更新节奏覆盖实时（如窑温、喂料量）、每班（如巡检记录）、每日（如化验报告、质量通知单）。日常文档包含生料配料方案、窑操作记录、熟料化验报告、设备巡检单、能源消耗报表，字段多带明确单位，如温度（℃）、喂料量（t/h）、抗压强度（MPa），部分台账含物料批次与进厂时间标识。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据的多来源、多更新节奏与多样文档结构，对向量索引环节带来多重约束。实时性的DCS与在线成分数据需支持增量索引，避免全量重建占用过多系统资源；每班生成的设备巡检单、每日产出的化验报告与质量通知单，需按更新频率配置分层索引策略，保障检索时效性。文档包含结构化字段（如设备编号、温度读数、物料批次）与非结构化操作描述，分割时需保留字段与对应内容的绑定关系，避免拆分后丢失关键关联信息；同时，原燃料台账与窑磨运行数据的关联需在索引阶段完成，确保维修问答可匹配到对应工况下的设备问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类生料配料方案、设备巡检单的平均文本长度，避免块丢失 |
| 重叠长度 | 100–150 字符 | 保留连续工况描述的上下文关联，适配窑操作记录的长文本场景 |
| 相似度阈值 | 0.72–0.80 按实测标定 | 匹配故障描述与历史维修记录的精准度，适配本品类设备问题的语义差异 |
| 单次搜索上限 | 前 6–10 条 | 覆盖本品类常见的关联数据量，避免冗余信息干扰 |
| 最大上下文 | 3000–4000 字符 | 适配设备点检问答的上下文长度需求，符合FastGPT v4.17.0的默认适配范围 |
| 单块最大Token数 | 8192 | 适配本品类长文档如窑系统完整操作日志的嵌入需求 |
| 默认嵌入Token数 | 2048 | 适配常规巡检单、化验报告的嵌入需求，平衡精度与资源占用 |

## 容易做错的三处
- 现象：设置分块长度为3000字符后，部分长文档的文本块出现丢失。原因：未配置合理的重叠长度，导致长文本分割时首尾关键信息未被覆盖，或超出系统单块嵌入的最大限制。
- 现象：批量上传每日化验报告与能源报表后，知识库索引状态持续处于「索引中」无进展。原因：未按文档更新频率配置分层索引策略，全量索引任务占用过多资源，未设置合理的任务分片规则。
- 现象：配置m3e向量模型时，无法正常生成文档嵌入向量。原因：未正确配置向量模型的调用地址，混淆了不同代理服务的路径格式，导致服务连接失败。

## 怎么确认配好了
- 上传单份典型文档（如完整窑操作记录），检查分割后的文本块数量与文档长度匹配预期，确认分块与重叠配置生效。
- 触发一次批量索引任务，查看系统日志中的索引进度，确认任务按配置规则执行，无长时间停滞。
- 发起设备点检相关的测试提问，检索返回的结果条数符合单次搜索上限的配置范围，确认相似度阈值与搜索上限生效。
- 验证向量模型调用链路，上传一份小型文档后，查看嵌入生成的日志，确认服务连接正常无报错。
