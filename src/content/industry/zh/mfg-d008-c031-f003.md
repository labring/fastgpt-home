# 水泥熟料与粉磨的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据来源包括在线成分分析系统、DCS集散控制系统、化验室检测数据、窑磨设备运行日志、原燃料台账与能源计量报表。数据更新节奏覆盖实时（如窑温、磨音数据）、每班（如巡检记录）、每日（如质量控制通知单）。日常文档包含生料配料方案、窑操作记录、化验报告、设备巡检台账，字段涉及物料配比、热工参数、强度指标、设备振动值，单位涵盖摄氏度、吨/小时、兆帕等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
实时性数据要求对话上下文需保留近15分钟的窑磨参数，避免因数据滞后导致建议偏差。多源数据的字段差异需要提示词明确指定仅调用对应部门的文档，例如询问粉磨设备点检时仅检索设备巡检台账。每班/每日更新的文档需在检索时标注更新时间，帮助模型匹配当前生产周期的配料方案。长上下文的多轮对话需限制历史消息长度，避免超出模型处理上限，同时针对水泥熟料矿物成分、粉磨细度等专业指标，需在提示词中固定字段的单位与计算逻辑。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前生产班组的专属会话ID | 确保多轮对话上下文仅关联对应班组的巡检与操作记录，避免跨班组数据混淆 |
| `messages` | 保留近10轮历史消息，截断超出2000字符的早期对话 | 适配水泥生产实时数据的时效性，避免过长上下文导致模型响应延迟 |
| `variables` | 预设当前窑号、磨台号、巡检周期变量 | 让模型自动匹配对应设备的点检标准与维修文档 |
| 单次搜索上限 | 前6条检索结果 | 匹配该品类日常文档的体量，避免冗余信息干扰专业判断 |
| 最大上下文长度 | 8000–12000 token | 适配生料配料、热工制度等多环节的专业对话需求，按实测标定调整 |
| 问题优化 | 开启专业术语标准化 | 统一水泥生产相关术语的表述，避免歧义 |

## 容易做错的三处
- 现象：使用严格问答模板检索知识库时，返回“未找到答案”且知识库包含图片地址。原因：严格问答模板默认仅匹配文本格式的知识库条目，未适配图片类巡检记录或设备图纸的检索与解析。
- 现象：短时间内连续发送多个问题时，后续请求需等待前序请求完成。原因：未配置`chatId`的会话并发限制，导致同一会话的请求队列阻塞。
- 现象：调用API时返回“没有权限操作此对话记录”。原因：未在请求参数中绑定对应班组的`variables`权限标识，或会话ID超出当前应用的授权范围。

## 怎么确认配好了
- 发送包含窑温、磨台号的问题，核对模型返回的检索结果是否仅关联当前预设的`variables`参数对应的设备文档。
- 连续发送3个不同的点检问题，确认多轮对话的上下文保留历史消息且未出现响应延迟。
- 上传一张设备巡检图片到知识库，使用严格问答模板提问，确认模型能正确解析图片关联的点检标准。
- 检查API请求日志，确认`chatId`与`variables`参数已正确携带，未出现权限报错。
