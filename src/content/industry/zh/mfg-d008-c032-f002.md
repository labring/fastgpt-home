# 汽车整车总装的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
汽车整车总装场景的数据主要来自ERP/MES系统、VIN与配置系统、拧紧工具、EOL检测线、质量追溯系统等。日常文档包含生产订单、VIN清单、装配作业指导书、拧紧数据、下线检测报告、返修记录、一致性放行文件等。数据更新频率覆盖每车、实时、每班三类，核心字段包含唯一VIN码、扭矩参数、检测结果、工位编号等，不同文档的结构差异明显，既有结构化的数值类数据，也有非结构化的操作指导文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
以VIN为单车主线的混线生产模式，要求向量索引需支持按VIN精准关联对应批次的文档，避免跨车辆的召回干扰；高频实时的更新频率，要求索引支持增量嵌入与快速同步，避免因数据延迟导致点检结果失效；多类型文档混合的特征，要求分块规则需适配不同文档的结构，避免拆分作业指导书的连续操作步骤，或破坏拧紧数据的数值关联性；同时，`maxToken`的设置需适配多文档拼接后的总长度，避免超出大模型的处理上限，出错后果严重的业务属性也要求召回结果的置信度需严格匹配预设阈值，降低错配漏装相关的召回风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配装配作业指导书的单段操作描述长度，避免跨工位步骤拆分 |
| `maxToken` | 4096 token | 匹配主流大模型的上下文窗口限制，适配总装场景下多文档拼接的长度需求 |
| 相似度阈值 | 0.75–0.85 | 按实测标定，平衡结构化拧紧数据与非结构化指导文本的召回精度 |
| 单次搜索上限 | 前 10 条 | 总装场景下单VIN关联的文档数量有限，避免冗余召回干扰核心结果 |
| 重排 | 开启 | 按工位优先级对召回结果排序，适配设备点检的操作顺序逻辑 |
| `defaultToken` | 1000 token | 为未指定上下文长度的查询设置默认值，覆盖单工位点检的常规信息需求 |

## 容易做错的三处
- 配置豆包embedding API后测试返回404 Not Found，原因是未正确配置API端点地址或未为密钥开放对应向量服务的权限，未匹配FastGPT要求的接口格式。
- 批量更换embedding模型后，旧知识库的多语言召回率未达标，原因是未对现有知识库文档执行全量重新嵌入，仅更新了新上传文档的向量数据。
- 手动插入的总装文档生成的默认索引在数小时后消失，原因是未开启索引持久化配置，系统触发了临时索引的自动清理阈值，与总装场景下高频更新的索引清理规则冲突。

## 怎么确认配好了
- 进入FastGPT v4.17.0的向量模型配置页面，确认已选择目标embedding模型并填写了正确的API信息，发起测试接口调用，验证返回正常的向量数据。
- 上传一份典型的总装装配作业指导书，查看分块预览结果，确认内容未跨工位步骤拆分，符合预设的分块长度规则。
- 发起一条针对拧紧数据异常的点检查询，查看召回结果的相似度得分处于预设阈值区间内，且关联了正确的VIN与工位信息。
- 等待12小时后查看知识库的索引列表，确认手动插入的文档索引未被自动清理，验证持久化配置生效。
