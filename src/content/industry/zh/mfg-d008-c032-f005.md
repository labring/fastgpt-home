# 汽车整车总装的设备点检与维修问答：工具调用与插件

## 这个品类的数据长什么样
该品类的数据以车辆识别码（VIN）为核心主线，来源涵盖ERP/MES系统、VIN与配置管理系统、拧紧工具终端、EOL下线检测线、质量追溯系统及供应商批次数据库。日常文档包含生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录与一致性放行文件。数据更新频率覆盖每车级实时同步、每班批量更新两类场景，单条数据包含VIN、配置项、扭矩参数、检测结果等专属字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
以VIN为核心的混线生产模式，要求工具调用需实时匹配当前工位的VIN对应专属配置，因此插件需支持动态拉取与VIN绑定的作业文件。高频的拧紧数据、下线检测数据更新，要求工具调用的接口响应需匹配生产节拍，避免延迟影响工位进度。多系统分散的数据源，要求插件需兼容跨系统的权限校验与数据聚合逻辑。单台车数百项配置的匹配需求，要求工具调用的单次返回数据量需适配总装工位的信息规模，避免过载打断生产流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | `auto` | 适配总装线动态切换工位的工具调用需求，自动匹配当前场景对应的函数 |
| `functionCall` | 按实测标定 | 针对单VIN匹配的复杂任务，限制单次调用的函数数量，避免上下文溢出 |
| 最大上下文 | 8000–12000 token | 容纳单台车的完整装配、检测与返修历史数据，适配总装场景的信息规模 |
| 单次工具调用上限 | 前3条 | 匹配总装工位的单工位多工具联动场景，避免返回过多无关信息 |
| 超时阈值 | 600秒 | 适配跨ERP、MES系统的数据拉取响应时长，避免打断生产节拍 |
| 问题优化 | 开启 | 针对VIN相关的复杂查询，先优化问题表述再触发工具调用，提升匹配精度 |

本页面基于FastGPT v4.17.0版本的工具调用配置规范。

## 容易做错的三处
- 调用工具API时返回400状态码且无响应体。原因是未正确配置`functionCall`的参数格式，未携带符合总装场景的VIN匹配字段。
- 自定义代码调用工具时出现AggregateError Code:ETIMEDOUT。原因是未设置适配总装系统数据拉取的超时阈值，导致跨ERP、MES系统的请求超时。
- 混淆工具调用环节的模型职责，将分类模型误用于问答任务。原因是未明确工作流中工具调用的模型功能边界，未区分分类与问答的配置要求。

## 怎么确认配好了
- 输入测试VIN，触发工具调用，核对返回的装配作业指导书是否与该VIN对应的配置一致。
- 模拟高频工具调用请求，检查响应时长是否符合预设的超时阈值，无超时报错。
- 查看工具调用日志，确认`toolChoice`自动匹配的函数与当前工位的任务类型匹配。
- 测试跨系统数据拉取，确认能同时获取拧紧数据与返修记录，无字段缺失。
