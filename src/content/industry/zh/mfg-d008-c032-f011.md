# 汽车整车总装的设备点检与维修问答：表单与交互

## 这个品类的数据长什么样
该品类的数据以单车辆VIN为核心主线，来源涵盖ERP/MES系统、VIN与车辆配置系统、拧紧工具、EOL下线检测线及质量追溯系统。日常文档包含生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录与一致性放行文件。数据更新频率覆盖每车级实时更新、每班批量更新两种节奏，字段多关联车辆专属配置与工位操作记录。

## 这些特征在「表单与交互」这一环带来什么约束
以VIN为核心的混线生产模式，要求表单需支持按VIN快速匹配专属作业指导书与点检项，避免错配漏装。实时的拧紧数据、下线检测数据要求表单支持实时录入与跨系统校验，防止操作超时或数据丢失。多来源的跨系统数据需要表单支持多字段联动，比如匹配VIN后自动带出对应工位的点检项与历史返修记录。总装线的高节拍要求表单操作流程简洁，避免冗长步骤影响工位效率，同时需严格关联车辆专属数据，防止不同车辆的点检记录混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `formInput` | 绑定VIN字段为必填项，开启实时校验 | 总装线以VIN为核心，需先匹配车辆专属点检项，避免错配漏装 |
| `userSelect` | 预设10-20个按工序分组的点检项，按工位自动展开 | 总装工位点检项多按工序划分，减少用户查找时间 |
| 语音输入触发 | 响应延迟设置为500-800毫秒 | 适配总装线工位快速操作的节奏，满足语音点检的实时性要求 |
| 表单提交校验 | 开启必填字段校验，关联拧紧数据比对 | 拧紧扭矩为关键质量项，需校验输入值与系统存储数据一致 |
| 历史记录调用 | 调用前5条同VIN的返修记录 | 总装返修记录需关联原车辆数据，快速获取历史维修信息 |
| 超时阈值 | 600秒 | 预留足够时间跨系统调取VIN关联的作业指导书与历史数据 |

## 容易做错的三处
- 现象：语音录入时界面无SenseVoiceSmall模型可选，无法完成语音点检。原因：未在FastGPT v4.17.0系统配置中加载该语音模型的适配项，未开启语音输入功能的模型绑定开关。
- 现象：表单提交后返回空结果，未生成匹配的维修问答内容。原因：未配置`formInput`的上下文关联逻辑，未绑定VIN对应的作业指导书数据。
- 现象：高级编排中工具调用无法自动选择对应工位的维修工具配置项。原因：未将点检表单的VIN字段与工具调用节点联动，未设置`userSelect`的分组触发规则。

## 怎么确认配好了
- 输入测试VIN，核对表单是否自动带出对应工位的点检项与关联的作业指导书链接。
- 开启语音录入功能，检查是否可选择预设的语音识别模型，完成单次语音输入并提交测试。
- 提交一条模拟点检记录，核对系统是否返回匹配的维修问答内容与同VIN的历史返修记录。
- 切换模拟工位，检查表单是否自动切换对应分组的点检项，无字段校验报错或异常提示。
