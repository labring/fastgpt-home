# 汽车零部件批量制造的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
这个品类的核心数据来自客户图纸、特殊特性清单、ERP/MES系统、量检具、设备过程参数及供应商质保书，日常文档包含控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料与8D报告。数据更新节奏为每批生产、每班巡检及持续采集设备参数，文档结构多为结构化表格、流程类文本与标准化报告，字段包含工序编号、特性参数、检测数值、批次号等，单位多为毫米、牛米等汽车制造行业通用的工业标准单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。多源异构的文档类型，包含结构化表格、流程文本、标准化报告与实时设备参数，要求索引支持混合数据类型的向量编码，避免仅适配纯文本的索引逻辑。高频更新节奏，即每批、每班及持续采集的参数，要求索引支持增量更新，减少全量重建的耗时。强合规性的文档如PPAP、8D报告，要求索引保留原始文档的元数据关联，便于后续溯源。批次化的生产数据，要求索引按批次维度划分分区，便于按生产批次快速检索关联文档。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 该品类的作业指导书、SPC报表等文档单段有效信息长度多在该区间，避免分块破坏结构化字段的关联性 |
| 重叠长度 | 100–200 字符 | 高频更新的设备参数文档需保留相邻分块的上下文关联，确保检索时的信息完整性 |
| `defaultToken` | 4096 | 该品类的合规文档如PPAP资料篇幅较长，需适配足够的token长度承载完整上下文 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 单次搜索上限 | 前 8 条 | 设备点检的问题多关联单工序或单批次的有限文档，过多结果会增加推理耗时 |
| 相似度阈值 | 按实测标定 | 该品类的检测参数数值差异较小，需根据实际检索场景调整阈值确保召回精准度 |

## 容易做错的三处
- 现象为在FastGPT知识库设置中启用豆包Doubao-embedding-large嵌入模型，填写自定义请求地址与API密钥后，点击测试直接弹出报错提示。原因是未确认自定义地址与API密钥的适配性，或嵌入模型的接口返回格式不符合FastGPT的向量编码要求。
- 现象为知识库中导入表格数据后，检索时无法匹配表格内的结构化字段内容。原因是未开启表格数据的多向量支持配置，仅对纯文本内容进行了向量编码，未针对表格单元格、行列信息单独生成向量。
- 现象为配置完成嵌入模型并通过Agent测试正常回答后，刷新知识库页面仍弹出“检测到没有可用的索引模型”提示。原因是索引模型的配置未保存至知识库的生效配置中，或系统缓存未同步最新的模型配置信息。

## 怎么确认配好了
- 进入知识库的向量模型配置页面，确认已选择适配的嵌入模型，且自定义请求地址与API密钥填写无误。
- 导入一份该品类的典型文档如作业指导书或SPC报表，执行手动分块与索引，查看分块结果是否符合预设的长度与重叠规则。
- 发起一次设备点检相关的测试查询，查看检索结果是否包含关联的文档片段，且数量符合单次搜索上限的设定。
- 刷新知识库页面，确认页面不再弹出索引模型相关的报错提示，系统正常加载配置信息。
