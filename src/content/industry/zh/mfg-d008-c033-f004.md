# 汽车零部件批量制造的设备点检与维修问答：工作流编排

## 这个品类的数据长什么样
该品类的数据覆盖制动、转向等汽车零部件供应商的全流程业务，日常文档包含控制计划、过程流程图、作业指导书、首件与巡检记录、SPC报表、PPAP资料及8D报告。数据来源包括客户图纸与特殊特性清单、ERP/MES系统、量检具、设备过程参数、供应商质保书，更新节奏为每批、每班及持续采集。数据字段包含设备运行温度、压力、时长，特殊特性公差范围等，单位涵盖摄氏度、帕斯卡、小时、毫米等。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据多源且更新频繁，要求工作流编排需支持多数据源实时拉取，避免因数据滞后影响点检与维修判断。多样的文档结构要求工作流节点适配不同格式的业务文档解析，保障信息提取准确性。受整车客户质量体系强约束，工作流输出需符合预设的质量文档规范，不得包含非授权内容。批量制造的高风险特性要求工作流配置失败重试与异常告警节点，降低批量不良风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 需承载多批次设备参数、SPC报表等多文档内容，避免上下文溢出 |
| 问题分类阈值 | 0.75–0.85 | 适配汽车零部件业务的专业术语识别，过滤低匹配度的非设备类问题 |
| 失败重试次数 | 3次 | 应对设备参数拉取、文档解析的偶发异常，保障工作流稳定性 |
| 变量绑定 | 绑定`variables`中的设备参数字段 | 直接调用源数据中的温度、压力等实时参数，提升回复准确性 |
| 节点超时时间 | 600秒 | 适配多文档解析与跨系统数据拉取的耗时需求，避免任务强制中断 |
| 分类结果上限 | 前3条 | 聚焦最相关的设备点检与维修分类结果，符合批量制造的快速决策需求 |

## 容易做错的三处
- 现象：工作流中AI会话节点输出结果末尾固定附带“FastGPT 是一个基于大语言模型(LLM)的知识库问答系统”。原因：未在会话节点的系统提示词中配置禁止输出官方标识的要求，且未过滤预设回复内容。
- 现象：工作流中温度开关关闭与设置为0时，触发逻辑出现差异。原因：未明确温度开关的触发条件与阈值绑定逻辑，混淆了禁用开关与阈值为0的触发边界。
- 现象：问题分类节点处理延迟过高，单批次任务耗时超出预期。原因：未限制分类节点的输入文档长度，且未绑定`nodeId`对应的专属数据源缓存，导致重复拉取数据。

## 怎么确认配好了
- 启动FastGPT v4.17.0的测试工作流，检查AI会话节点的输出是否包含预设的业务文档内容，无额外官方标识。
- 模拟异常设备参数输入，验证温度开关节点的触发逻辑符合配置要求，确认关闭与阈值为0的触发效果一致。
- 查看工作流运行日志，确认问题分类节点的处理耗时在预设范围内，分类结果上限为前3条。
- 绑定`variables`中的设备参数字段，验证工作流中变量调用的参数值与源数据一致。
