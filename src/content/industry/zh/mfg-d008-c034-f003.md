# 烘焙与方便食品的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类的典型主体为面包糕点、饼干、方便面与速冻面点工厂。日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源涵盖原辅料合格证明、ERP/MES系统、称量系统、烤炉或油炸线、实验室与食品追溯台账。数据更新按生产批次、班次或每日进行，文档字段包含批次号、过敏原标注、温度时间参数、投料量等，单批次文档结构随产品换线频繁变更。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类换线频繁、数据按批次/班次更新且过敏原与清洁要求突出，对多轮对话与提示词配置带来明确约束。需通过`chatId`绑定不同生产场景的会话，避免跨班次、跨批次的上下文混淆。需通过`variables`传递当前批次的专属参数，确保提示词精准调取对应配方、烘烤曲线与清洁记录。需限制`messages`的历史轮次，防止过长上下文引入无关批次的冗余数据，影响点检与维修问答的精准性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 当前会话的唯一标识（如工厂ID+班次ID） | 区分不同生产班次的会话历史，避免上下文跨批次混淆 |
| `messages` | 保留前3–5轮对话内容 | 适配该品类频繁换线的场景，避免过长上下文引入冗余数据 |
| `variables` | 传入当前批次的配方ID、烘烤温度区间、清洁班次时间 | 精准调取当前生产场景的专属文档与参数 |
| 最大上下文token数 | 8000–12000 token | 平衡检索效率与上下文完整性，FastGPT v4.17.0版本下该取值适配多数生产场景 |
| 问题优化 | 开启 | 针对换线频繁的场景，优化后的问题能精准匹配当前批次的生产记录 |
| 单次检索上限 | 前4条结果 | 该品类文档按批次更新，过多结果会干扰当前会话的精准判断 |

## 容易做错的三处
- 现象：仅能单次提问，无法延续上一轮的设备状态或批次信息进行反问。原因：未启用`messages`参数传递历史对话上下文，导致系统无法记住之前的提问背景。
- 现象：工作流中所有AI对话节点的回复都会出现在最终会话界面中，无法隐藏指定节点的输出内容。原因：未配置节点的上下文隐藏规则，或未通过`variables`过滤非必要的输出字段。
- 现象：检索到的设备维修建议与当前批次的过敏原要求不匹配。原因：未在提示词中通过`variables`绑定当前批次的过敏原参数，导致检索到无关批次的清洁与维修记录。

## 怎么确认配好了
- 发起一次设备点检提问，输入当前批次的设备型号与班次信息，查看系统是否能延续该信息进行后续反问。
- 触发工作流运行，检查配置为隐藏的AI对话节点输出是否未出现在最终会话界面中。
- 传入当前批次的过敏原变量，确认检索到的设备维修建议匹配该批次的清洁消毒要求。
- 切换不同班次的`chatId`发起会话，确认两个会话的历史上下文不会互相干扰。
