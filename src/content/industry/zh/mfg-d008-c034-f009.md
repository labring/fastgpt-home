# 烘焙与方便食品的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
该品类的典型主体为面包糕点、饼干、方便面及速冻面点工厂，日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量系统、烤炉或油炸线设备、实验室检测数据及食品追溯台账，更新频率为每批、每班或每日。文档字段包含过敏原物料标识、醒发/烘烤/油炸窗口参数、包装日期与保质期等，需按单份文档的原始记录适配字段与单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求模型接入需兼容不同格式的设备日志、生产记录与实验室数据；高频更新的业务数据要求上下文配置需适配快速刷新的文档内容，避免召回过时信息；过敏原管控、换线频繁的业务特点要求模型需精准召回特定字段的关联数据，同时需保证维修问答的严谨性，避免生成无关内容。此外，直接食用的产品属性要求模型输出的点检与维修建议需符合食品生产的卫生规范，不能引入潜在污染风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 字符 | 适配该品类单批生产记录、完整烘烤曲线等长文档的上下文承载需求 |
| `temperature` | 0.2–0.4 | 保证设备点检与维修问答的答案严谨准确，避免生成无关或发散的内容 |
| `AIPROXY_API_ENDPOINT` | 按部署的大模型服务地址填写 | 适配本地或私有部署的大模型调用场景，满足食品工厂的数据隐私要求 |
| `quoteMaxToken` | 1500–2000 token | 召回的文档片段需匹配单份配方或清洁消毒记录的核心内容长度 |
| 工作流/API 工具选择配置 | auto | 允许模型自主选择是否调用工具处理点检参数查询、设备状态判断等场景 |

## 容易做错的三处
- 调用本地大模型时返回参数不匹配报错。原因是未根据本地模型的实际上下文窗口调整`maxTokens`取值，直接沿用线上API的默认参数导致超出模型承载上限。
- 接入mineru工具时出现版本不兼容提示。原因是直接安装官方最新版mineru，未使用与FastGPT v4.17.0适配的版本，导致接口调用逻辑不匹配。
- 配置`vision`参数后无法解析生产曲线图片。原因是未上传符合规范的烘烤或蒸煮曲线图片，或未在配置中开启视觉工具的食品生产文档专用适配规则。

## 怎么确认配好了
- 提交一条设备点检相关的查询，验证返回结果中包含对应批次的生产记录或烘烤曲线片段。
- 测试调用大模型接口，确认返回响应的格式与字段符合预设的设备维修问答要求。
- 检查配置的`AIPROXY_API_TOKEN`是否与部署的大模型服务密钥一致，避免认证失败导致的调用中断。
- 触发一次过敏原管控相关的查询，验证模型是否召回了清洁消毒记录中的过敏原物料管控数据。
