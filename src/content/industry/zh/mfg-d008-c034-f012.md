# 烘焙与方便食品的设备点检与维修问答：部署与升级

## 这个品类的数据长什么样
该品类主体为面包糕点、饼干、方便面、速冻面点工厂，日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源涵盖原辅料合格证明、ERP/MES系统、称量系统、烤炉或油炸线设备、实验室检测数据、食品追溯台账。数据更新频率按生产批次、每班、每日滚动更新，字段包含过敏原物料清单、烘烤温度与时长、包装日期、保质期等直接关联食品安全的内容。

## 这些特征在「部署与升级」这一环带来什么约束
由于该品类配方多、产品换线频繁且直接面向消费者，设备点检与维修问答的知识库需高频更新过敏原清单、换线标准等敏感内容，同时需保障检索结果的精准性以规避食品安全风险。多源异构的数据来源要求部署环节需兼容不同系统的字段格式，避免数据同步缺失。高频更新的特性则要求升级环节支持增量同步配置，减少全量数据迁移的时间成本。此外，直接食用的属性让问答结果的准确性直接关联召回风险，部署时需增加配置验证环节。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体参数如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–20 并发连接 | 适配多源设备数据的高频读写需求，避免连接池耗尽导致检索中断 |
| `MONGODB_URI` | 指向工厂ERP/MES同步后的文档库地址 | 存储批量生产记录、烘烤曲线等非结构化业务文档 |
| `REDIS_URL` | 本地部署的Redis服务地址，配置1000 MB内存配额 | 缓存高频检索的过敏原清单、换线标准参数，降低主数据库的访问压力 |
| `STORAGE_S3_ENDPOINT` | 适配工厂现有对象存储的端点地址 | 存储清洁消毒记录、出厂检验报告等附件类文件 |
| `FE_DOMAIN` | 绑定工厂内网访问的专属域名 | 限定部署服务的访问范围，保障生产内网的访问安全 |
| `ROOT_KEY` | 按企业内部权限规范生成的随机32位字符串 | 管控部署后的后台访问权限，防止未授权修改核心配置 |

## 容易做错的三处
- 现象为创建知识库时无法选择本地部署的ChatGLM2模型，界面无对应选项。原因是未将本地模型的接入地址正确配置到关联的模型配置表中，或未通过oneapi完成模型路由的权限配置。
- 现象为数据库查询返回空结果，检索到的生产记录字段缺失。原因是未按生产批次的更新频率配置增量同步任务，导致ERP/MES的最新数据未完整导入知识库。
- 现象为语音生成功能调用失败，控制台返回模型加载超时错误。原因是未为`REDIS_URL`配置足够的内存配额，导致模型缓存被挤兑，无法正常加载所需的语音模型文件。

## 怎么确认配好了
- 登录FastGPT后台的数据库管理页面，查看`DB_MAX_LINK`的并发连接数未触发告警阈值，确认连接正常。
- 上传一份近期的烘烤曲线文档，执行设备点检相关的检索，确认能匹配到对应生产批次的记录与参数。
- 调用本地部署的模型接口，输入预设的设备维修问题，确认能返回符合工厂业务逻辑的回答，验证模型接入配置正确。
- 访问`FE_DOMAIN`绑定的内网地址，确认无权限拦截，可正常进入系统并完成知识库的基础操作。
