# 热处理的设备点检与维修问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
该品类数据来自材料牌号档案、客户技术要求、温控仪表、炉温均匀性测试设备、硬度计与金相检测设备、车间MES系统。日常文档包含热处理工艺卡、装炉布局图、实时炉温曲线、硬度与金相检测报告、设备点检表、异常处置单。数据按每炉次、每批更新，单条数据包含加热温度、保温时长、冷却参数、装炉位置、检测结果等字段，单位涵盖摄氏度、小时、HV硬度值等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
该品类数据按炉次、每批更新，接口需支持按炉次ID、批次号精准查询，避免返回无关数据。多类型文档的元数据需通过接口传输，需兼容不同字段的格式校验。数据来源包含车间仪表、MES系统等多类外部系统，接口需统一鉴权逻辑。高频更新的特性要求接口具备低延迟响应能力，同时需支持异常请求的重试机制，防止因单次请求失败影响点检流程。设备点检与维修的问答数据需关联异常处置单，接口需支持跨文档的关联查询。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {预配置的API密钥}` | 符合工业外部接口的标准鉴权格式，保障接口调用安全 |
| 请求超时时间 | `30–60 秒` | 热处理炉温曲线、点检记录的传输延迟通常在数秒内，预留网络波动缓冲时间 |
| 并发请求上限 | `3–5 个` | 匹配多数车间工业设备的并发承载能力，避免触发429异常 |
| 单次返回数据量 | `不超过 1000 字符` | 减少无效数据传输，提升问答响应速度，适配轻量化检索场景 |
| `variables` | 预设炉次ID、材料牌号为全局调用变量 | 简化设备点检与维修问答的参数传递，适配单炉次专属数据查询需求 |
| `responseData` | 仅返回点检结果、异常代码、维修建议字段 | 过滤非必要数据，聚焦维修问答所需的核心信息 |

## 容易做错的三处
- 接口返回429状态码异常。原因：未配置并发请求上限，超过外部接口的并发限制。
- 数据库工作流无法查询到数据。原因：未按炉次ID作为查询条件，直接调用全量数据接口，或数据库连接的鉴权参数配置错误。
- 接口返回字段为空。原因：未正确传递`variables`中的炉次ID参数，导致无法匹配到对应热处理炉的点检与维修数据。

## 怎么确认配好了
- 发起单条炉次数据的接口调用，检查返回的`responseData`是否包含预期的点检、维修相关字段。
- 模拟多并发请求，观察是否触发429异常，调整并发上限至符合外部接口的承载能力。
- 连接测试数据库，执行预设的SQL查询语句，确认可正常返回对应热处理炉的检测数据。
- 检查`Authorization`鉴权参数的格式，确认符合外部接口的鉴权要求，避免鉴权失败。
