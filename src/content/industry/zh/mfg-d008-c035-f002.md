# 热处理的设备点检与维修问答：向量模型与索引
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
这个品类的数据主要来自专业热处理厂、汽车及轴承零部件厂热处理车间的日常文档，包括热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单。数据来源覆盖材料牌号、客户技术条件、温控仪表、炉温均匀性测试设备、硬度计与金相设备、MES系统。数据更新频率为每炉次、每批，单份文档包含温度数值（单位℃）、硬度数值（单位HV）、金相组织描述、点检项目与异常记录等结构化与非结构化字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
这些数据特征对向量模型与索引环节带来多重约束。首先，数据更新频率高且单炉次关联多份文档，要求索引支持增量更新与批量关联索引；其次，文档包含长时序炉温曲线、专业金相描述，要求分块策略适配长文本语义完整性；第三，字段包含专业工程参数与离散异常记录，要求元数据提取覆盖炉号、材料牌号等关键标识，避免召回时丢失业务关联信息；最后，异常处置单与工艺卡的强关联属性，要求索引支持跨文档语义关联召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配热处理工艺卡、炉温曲线的长文本长度，避免语义断裂 |
| 重叠长度 | 100–150 字符 | 覆盖装炉图、炉温曲线的跨块关联信息，保留时序连续性 |
| maxToken | 8192 token | 匹配bce-embedding-v1的最大输入限制，适配金相报告的长文本内容 |
| defaultToken | 按实测标定 | 适配热处理设备点检表的短文本字段，优化小体量数据的向量生成效率 |
| 相似度阈值 | 0.72–0.80 | 过滤低匹配度的异常处置单与工艺卡关联结果，提升召回精准度 |
| 单次搜索上限 | 前6条 | 覆盖单炉次的多维度点检与维修数据，避免冗余信息干扰 |

## 容易做错的三处
- 调用pushdata api上传chunk模式数据后，界面持续显示“索引中”状态无更新。原因是未将索引触发时机配置为与炉次更新同步，增量索引的轮询间隔与每炉次的数据生成节奏不匹配，导致数据堆积未完成索引。
- 调用embedding模型时返回报错提示“该令牌无权使用模型”。原因是未正确配置`defaultToken`对应的密钥权限，未绑定所选embedding模型的使用权限，导致接口调用被拦截。
- 输入设备异常维修问题后，召回结果未包含对应炉次的炉温曲线。原因是未配置元数据提取规则，未将炉号、材料牌号作为索引关联字段，导致召回结果与业务场景脱节。

## 怎么确认配好了
- 上传单份完整的炉温曲线文档，查看索引完成状态是否在合理时间内完成，无持续堆积提示。
- 调用embedding测试接口，输入一段热处理工艺卡文本，验证返回的向量数据格式符合要求，无截断报错。
- 输入“某炉次硬度异常”的问题，查看召回的文档是否包含对应炉号的点检表与异常处置单。
- 检查`maxToken`参数是否与所选embedding模型的输入限制匹配，避免长文本被截断导致语义丢失。
