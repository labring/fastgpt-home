# 热处理的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来自材料牌号标准、客户技术要求、车间温控仪表、炉温均匀性检测设备、硬度计、金相分析设备及生产管理系统。日常文档包含热处理工艺卡、装炉布局图、实时炉温曲线、硬度与金相检测报告、设备点检记录表、异常处置单。数据更新频率为每炉次或每生产批次，单条数据包含工艺参数、设备运行状态、检测结果等字段，部分文档附带温度曲线图表与检测数值单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源涉及多类设备与系统，需适配结构化的参数数据与非结构化的图像、曲线文档，因此模型接入需支持多源数据解析。更新频率高且单批次数据关联紧密，要求上下文窗口需适配单炉次全流程数据，避免跨批次数据干扰。文档包含温度曲线、金相图像等非文本内容，需配置视觉模型支持图像解析。异常处置单与点检表的字段标准化程度高，需确保模型能准确提取设备编号、故障描述等关键字段，同时需控制上下文长度避免冗余。

## 配置怎么定
本文适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单炉次热处理全流程数据的上下文长度，避免截断关键工艺与检测信息 |
| `maxTokens` | 2000–3000 token | 满足维修问答场景下对异常分析、处置方案的输出长度需求 |
| `temperature` | 0.2–0.4 | 降低随机输出，确保点检与维修建议的严谨性，符合工艺要求 |
| `quoteMaxToken` | 1500–2000 字符 | 限制引用的文档内容长度，避免上下文过载 |
| `vision` | 开启 | 支持解析炉温曲线、金相图像等视觉类文档，适配品类内的非文本数据 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写本地模型地址 | 适配离线部署场景，确保数据在本地流转 |

## 容易做错的三处
- 模型测试页面点击测试后提示请求错误，curl直接调用本地模型接口正常。原因是未正确配置`AIPROXY_API_TOKEN`参数，或部署容器未开放模型接口的访问权限。
- 知识库查询后返回结果无整理，仅罗列零散的文档片段。原因是`quoteMaxToken`参数设置过大，导致上下文过载，大模型无法有效整合引用内容。
- 向量模型接入失败，LLM模型可正常完成接入流程。原因是未开启`vision`参数，或向量模型的部署方式与FastGPT的多模态解析要求不匹配。

## 怎么确认配好了
- 进入FastGPT的模型测试界面，输入典型的热处理设备点检问题，核对返回结果是否包含设备状态、工艺修正建议等关键内容。
- 上传单炉次的炉温曲线图片，测试模型是否能识别温度超标的时间段，确认视觉解析功能正常生效。
- 触发知识库查询，选择热处理工艺卡作为数据源，查看返回结果是否准确引用了工艺参数与检测标准。
- 查看FastGPT的系统日志，确认模型调用无频繁超时或参数错误的记录，确认配置参数生效。
