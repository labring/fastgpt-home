# 热处理的设备点检与维修问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的服务主体为专业热处理厂、汽车与轴承零部件厂热处理车间，数据来自材料牌号标准、客户技术条件、现场温控仪表、炉温均匀性测试设备、硬度计与金相设备，以及车间MES系统。日常文档涵盖热处理工艺卡、装炉布局图、实时炉温曲线、批次硬度与金相检测报告、设备点检记录表、异常处置工单。数据更新节奏为每炉次或每批更新，文档包含温度参数、装炉位置、检测数值、点检时间等字段，部分文档附带批次编号与时间戳。

## 这些特征在「知识库检索与召回」这一环带来什么约束
高频更新的每炉次/每批数据要求检索系统支持增量同步，避免全量索引耗时过长。多类型文档混合存在，包括文本类工艺卡、表格类检测报告、曲线类炉温数据，需要适配不同格式的召回逻辑，比如提取表格关键数值、匹配曲线时间区间。数据与炉次、批次强关联，检索需精准匹配批次参数，防止跨批次数据混淆。设备点检与异常处置的时效性要求召回结果优先关联近批次工单，支撑快速排查现场问题。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 热处理数据需匹配精准的工艺参数与设备状态，该区间可过滤低相关的非炉次数据，避免召回无关的通用工艺内容 |
| `limit` | 前8条 | 单炉次相关文档数量有限，召回过多会增加上下文处理压力，过少则遗漏关键点检或异常处置信息 |
| `usingReRank` | 开启 | 多类型文档混合召回时，重排可优先筛选与设备点检、维修问题强相关的片段，修正初始召回的相关性偏差 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可将用户的点检或维修问题扩展为包含工艺参数、设备型号的查询词，匹配更精准的工艺卡与点检表内容 |
| `collectionIds` | 绑定专属热处理设备点检与维修知识库集合 | 避免召回其他品类的文档，确保检索范围仅覆盖当前车间的工艺、点检与异常数据 |

## 容易做错的三处
- 开启`usingReRank`后检索结果为空。现象：界面返回无匹配片段，日志显示初始召回条数正常但重排后结果为0。原因：重排阈值设置过高，过滤了初始召回的有效结果，或`similarity`阈值与重排阈值未匹配，导致所有初始结果被排除。
- 召回结果包含跨批次的文档。现象：查询当前炉次的点检问题时，返回了其他批次的炉温曲线或工艺卡。原因：未正确配置`collectionIds`，检索范围覆盖了多个车间的知识库集合，未绑定专属热处理车间的数据集。
- 检索未命中异常处置工单。现象：查询设备维修问题时，未召回对应异常处置工单内容。原因：未开启`datasetSearchUsingExtensionQuery`，未将维修问题扩展为包含异常处置关键词的查询，导致无法匹配工单文档。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本实现。
- 上传1份测试用的炉温曲线文档与设备点检表，发起对应关键词查询，核对召回结果是否包含该文档的关键片段。
- 调整`similarity`参数区间，验证不同阈值下的召回条数变化，确认结果符合业务需求。
- 开启`usingReRank`后，对比开启前后的结果排序，确认高相关内容优先展示。
- 检查知识库集合绑定情况，确认检索范围仅覆盖热处理车间的专属文档，无跨品类召回内容。
