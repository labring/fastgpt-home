# 焊接结构件制造的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据来源包括设计图纸、材料质保书、焊接设备参数、焊材库台账、无损检测系统记录、焊工资质台账等。日常生成的文档涵盖焊接工艺评定、焊接工艺规程、焊材领用记录、焊工资格记录、焊缝检验报告、返修单。数据更新节奏为每条焊缝、每批物料或每班作业完成后更新，单条数据包含焊缝编号、焊材牌号、设备运行参数、检测结果等字段，字段多关联工艺要求与质量验收标准。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据更新频率高且关联单条焊缝或批次物料，要求索引环节支持增量同步，避免全量重建带来的耗时问题。多类文档混合存储，需按文档类型设置差异化分块规则，确保工艺参数与检验记录的语义关联不被破坏。字段多关联刚性工艺要求，索引时需保留字段间的关联逻辑，避免专业语义断裂。焊缝相关数据的工业专业术语占比高，需匹配适配工业场景的向量模型，确保专业语义的向量表达准确。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 焊接工艺文档单段内容长度适中，避免跨焊缝的语义拼接 |
| 重叠长度 | 100–150 字符 | 焊缝工艺步骤存在连贯性，重叠保留上下文关联，确保问答时的逻辑完整 |
| 相似度阈值 | 0.72–0.85 | 工业场景对专业语义匹配精度要求高，过滤低匹配度的无效结果 |
| 单次搜索上限 | 前 8 条 | 焊接维修问答需聚焦核心工艺参数，过多结果会干扰现场决策 |
| 重排 | 开启 | 原始召回结果可能存在专业术语匹配偏差，重排可优化结果的优先级 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 现象：配置通义多模态向量模型时，调用OneAPI返回报错，提示不兼容OpenAI调用格式。原因：未修改模型调用的接口路径与请求头，直接套用通用OpenAI向量模型的配置参数。
- 现象：开启重排配置后，在线召回测试未生效，返回结果未按重排优先级排序。原因：未在知识库索引环节绑定重排模型的调用密钥，或未开启召回阶段的重排触发开关。
- 现象：增量索引任务耗时超过600秒，日志显示重复索引同批次焊缝数据。原因：未按焊缝编号设置增量更新的唯一标识，导致系统无法识别已索引数据，重复执行索引流程。

## 怎么确认配好了
- 执行单条焊缝的设备点检或维修问答测试，核对返回结果是否包含对应的焊接工艺参数、焊材要求或设备故障排查步骤。
- 查看索引任务日志，确认增量更新仅处理新增的焊缝数据，无重复索引记录。
- 调用测试接口，验证重排后的结果排序与原始召回结果存在差异，符合专业语义匹配的优先级。
- 检查向量模型的调用日志，确认无连接报错，模型返回的向量维度与配置要求一致。
