# 焊接结构件制造的设备点检与维修问答：工作流编排

## 这个品类的数据长什么样
焊接结构件制造的设备相关数据来源包括设计图纸、材料质保书、焊接设备参数、焊材库、无损检测系统、人员资质台账。数据更新节奏为每条焊缝或每批、每班。日常文档包含焊接工艺评定、焊接工艺规程、焊材领用记录、焊工资格记录、焊缝检验报告、返修单。数据字段包含焊缝编号、母材牌号、焊材牌号、焊工资格证号、焊接电流电压、检测缺陷类型、返修次数等，无额外统计数值或百分比数据。

## 这些特征在「工作流编排」这一环带来什么约束
焊接结构件制造的设备点检与维修工作流，需匹配单条焊缝或每批的专属数据，避免跨批次数据混淆。数据更新频率为每条焊缝或每批、每班，工作流需支持按触发条件实时调用最新数据。刚性约束要求工作流需包含焊工资质、焊接工艺评定的校验环节，出错后需触发对应返修流程。多数据源对接需求要求工作流支持多个组件串联调用，且需保证数据传递的准确性，避免影响后续流程。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 前6–10条 | 焊接结构件点检问答的上下文量适中，过多会引入冗余信息，按实测标定 |
| 循环触发条件 | 当校验结果不符合要求 | 适配循环修正点检结果，满足多次校验需求 |
| `variables`绑定 | 绑定焊缝编号、焊材牌号、焊工资质字段 | 匹配单条焊缝的专属数据，避免跨批次数据混淆 |
| 多代码组件启用 | 开启多个代码运行组件 | 支持对接焊材库、无损检测系统等多数据源 |
| 文件直传配置 | 直接上传原始检测文件 | 避免默认解析破坏原始检测数据的格式 |
| `nodeId` | 按点检、校验、维修的顺序设置节点ID | 确保工作流按业务逻辑顺序执行 |

## 容易做错的三处
- 工作流进入死循环或提前终止，原因是未正确设置循环触发的校验条件，无法正确判断点检结果是否符合要求。
- 对话明细中上下文条数与配置不符，回复无法关联上下文，原因是未正确配置上下文的调用参数，实际调用的上下文条数不足。
- 节点接收的文件为空或格式异常，原因是未开启文件直传配置，使用系统默认的文本解析，丢失原始检测数据的格式。

## 怎么确认配好了
- 手动触发工作流，检查对话明细中显示的上下文条数与配置的最大上下文条数一致。
- 触发循环校验流程，检查当校验结果不符合要求时，工作流自动进入下一轮循环，符合要求时终止。
- 上传原始检测文件，检查节点接收的文件为原始格式，未被解析为纯文本。
- 启用多个代码组件，检查组件可以同时运行，无冲突报错。
