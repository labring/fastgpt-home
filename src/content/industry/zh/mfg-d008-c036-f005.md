# 焊接结构件制造的设备点检与维修问答：工具调用与插件

## 这个品类的数据长什么样
焊接结构件制造的设备点检与维修相关数据，来源涵盖设计图纸、材料质保书、焊接设备参数台账、焊材库存记录、无损检测系统数据、焊工资质档案等。数据更新以每条焊缝或每批工件、每班作业为节奏，涉及焊接工艺评定报告、焊接工艺规程、焊材领用单、焊工资格记录、焊缝检验报告、返修单等文档。文档包含焊缝编号、焊材牌号与规格、母材材质、焊接电流电压、焊工证号、检测缺陷类型、返修次数等固定字段，无额外非标准自定义字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且涉及多类系统，要求工具调用需支持对接不同类型的数据源插件，同步获取实时的焊材库存、焊工资质、设备参数等信息。数据更新频率高，需确保插件调用能匹配每条焊缝或每批工件的更新节奏，避免获取过时数据。文档字段具有刚性约束，工具调用需严格校验焊材牌号、焊工证号等字段的格式与合法性，防止无效信息进入问答流程。一旦调用失败或返回错误数据，可能导致焊接工艺偏差或结构失效风险，需配置完善的失败重试与告警机制。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工具调用模式 | 自动触发 | 匹配设备点检的实时响应需求，无需手动触发即可根据用户问题调用对应数据源 |
| `functionCall` | 启用 | 支持结构化返回焊接工艺、设备参数等结构化数据，便于后续校验与落地 |
| 最大上下文长度 | 8000–12000 字符 | 可容纳单条焊缝的完整工艺评定、检验报告等关联文档，满足问答的信息完整性要求 |
| 插件调用超时时间 | 600 秒 | 适配多数据源同步的耗时需求，避免因对接焊材库、无损检测系统等环节超时导致调用失败 |
| 单次召回结果条数 | 前 8 条 | 匹配焊接结构件单批次工件的关联文档数量，避免冗余信息干扰问答准确性 |
| 重排模型开关 | 启用 | 对召回的文档按相关性排序，优先返回与当前点检问题最相关的焊材领用、焊工资质等信息 |

## 容易做错的三处
- FastGPT插件编辑页面顶部始终显示“未保存”提示，无论是否点击保存按钮。原因是未正确关联焊接结构件专属的数据源插件，导致页面配置状态无法与后端同步。
- 调用多模态模型时持续报参数错误。原因是未按焊接结构件的文档字段格式调整模型入参，未匹配焊材牌号、焊缝编号等专属字段的命名规则。
- reranker插件调用成功但返回结果为false。原因是未配置插件触发条件与焊缝检测报告的更新频率匹配，导致传入的文档格式不符合插件的校验要求。

## 怎么确认配好了
- 手动触发针对特定焊缝的点检问答，查看是否能准确拉取该焊缝对应的焊材领用记录、焊工资格信息与焊接设备参数。
- 查看插件调用日志，确认每次调用的参数均包含焊缝编号、焊材牌号等焊接结构件专属字段，且格式符合要求。
- 模拟参数错误场景，例如传入无效的焊工证号，验证是否触发预设的失败处理逻辑并返回明确的错误提示。
- 保存插件配置后刷新页面，确认页面顶部的“未保存”提示消失，配置内容正常存储。
