# 生产计划与车间排程的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自制造企业PMC、计划、车间调度和物控部门的日常文档，包括销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单。数据来源覆盖ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。数据更新频率包含每日、每周，以及订单或异常发生时的实时更新。文档结构包含纯文本、表格两类，字段涵盖订单编号、产能数值、交期时间、物料编码等，随业务场景动态调整。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据来源分散、更新节奏不一，且包含大量结构化表格与非结构化文本，对向量模型与索引环节带来多重约束。首先，多源数据的字段差异要求向量化过程需覆盖订单、产能、交期等核心业务字段，避免遗漏关键约束条件。其次，实时更新的异常数据（如缺料清单、交期变更单）要求索引支持增量更新，避免全量重建带来的性能损耗。另外，文档的混合结构需要分块规则适配不同长度的文本与表格内容，确保向量嵌入的完整性与准确性。最后，跨工序的资源约束数据要求召回结果需同时匹配订单与设备信息，避免单一维度的召回偏差。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配工单、排产表的单段文本与表格行组的常规长度 |
| 重叠长度 | 50–100 字符 | 避免跨分块的业务逻辑被截断，确保产能、交期等关联字段的向量完整性 |
| `maxToken` | 8000 | 容纳主生产计划、完整工单等长文本的上下文信息，满足复杂查询的需求 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的无关数据，确保召回结果与设备点检、排程约束的相关性 |
| 单次搜索上限 | 前 10 条 | 平衡查询响应速度与召回覆盖范围，适配车间调度的实时决策需求 |
| `defaultToken` | 100 | 控制单条向量嵌入的基础长度，适配短文本类的缺料清单、交期变更单 |

## 容易做错的三处
- 现象：在FastGPT知识库设置中，启用豆包Doubao-embedding-large索引模型，填写自定义请求地址和apikey后点击测试直接报错。原因：未正确匹配模型的官方请求路径格式，或apikey字段携带了多余的空格与换行符。
- 现象：知识库中的表格数据未生成对应向量，搜索结果无法提取表格内的产能、物料数量等字段信息。原因：未开启表格数据的多向量支持，或分块规则未适配表格的行列结构，导致表格内容被整体截断。
- 现象：搜索返回的结果条数与配置的单次搜索上限不符，出现结果过多或过少的情况。原因：未在向量索引配置中正确设置召回数量阈值，或索引更新时未同步最新的排程与工单数据。

## 怎么确认配好了
- 上传一份测试用的工单与周日排产表，检查FastGPT v4.17.0后台的向量生成任务状态是否显示为成功。
- 输入测试问题，比如“当前工单的设备产能约束是什么”，检查返回结果是否包含来自ERP的设备产能字段信息。
- 修改一份测试用的交期变更单，触发索引增量更新，确认搜索结果能匹配最新的交期数据。
- 进入知识库设置页面，检查所有配置项的参数是否与预设值一致，未出现丢失或篡改的情况。
