# 生产计划与车间排程的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据主要来自ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。日常文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单。数据更新频率为每日、每周，或随订单、异常情况触发更新。字段包含订单编号、物料编码、工序产能、计划开工完工时间、物料可用量等，单位涵盖小时、件、天等业务常用计量标准。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
品类数据来源分散且更新触发时机不固定，多轮对话需过滤过期的排程与点检数据，避免干扰当前请求。文档结构多样且字段关联紧密，提示词需适配不同文档的字段格式，确保问答能准确提取订单、设备相关信息。业务横跨全工序与资源约束，多轮对话需关联多维度数据，不能仅聚焦单工序点检。同时排程计算依赖实时数据，对话上下文需及时同步最新的产能、物料状态。

本配置基于FastGPT v4.17.0版本
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 上下文窗口最大token数 | 8000–12000 token | 品类文档包含多维度排程与点检数据，需覆盖完整业务上下文 |
| 多轮历史消息保留 | 保留最近20条`messages` | 排程数据更新频繁，过长历史会稀释当前请求的有效信息 |
| 会话变量绑定 | 绑定`variables`中的订单号、设备ID字段 | 品类业务依赖特定订单与设备的关联数据 |
| 会话超时时间 | 600秒 | 排程计算需加载多源ERP与设备数据，耗时较长 |
| 提示词模板匹配 | 按`chatId`关联的工单类型匹配 | 不同工单的点检与排程逻辑存在差异，需精准适配当前场景 |

## 容易做错的三处
- 现象：上传附件或文本数据集时提示`fail to create post presigned url`，模板导入功能可正常上传文件。原因：未正确配置会话关联的存储桶权限，或`variables`中未绑定存储路径参数。
- 现象：多轮对话中排程结果与实际工单不匹配。原因：保留的`messages`历史过长，混入了过期的排程数据，导致上下文关联错误。
- 现象：会话中途断开无法恢复。原因：未设置合理的会话超时时间，或未通过`chatId`持久化会话上下文，导致会话状态丢失。

## 怎么确认配好了
- 测试上传小型附件，确认无`fail to create post presigned url`报错，验证存储配置生效。
- 发起包含订单号、设备ID的多轮对话，检查`variables`是否正确绑定对应字段，对话上下文关联正确的业务数据。
- 发起耗时较长的排程计算请求，确认会话未在600秒内强制断开，超时配置符合预期。
- 切换不同工单类型的会话，确认提示词模板按`chatId`正确匹配，问答逻辑适配当前工单类型。
