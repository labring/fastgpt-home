# 生产计划与车间排程的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
该品类的日常文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单。数据来源为ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。更新频率为每日、每周，或在订单、异常情况发生时触发更新。数据字段涵盖订单编号、物料编码、产能工时、班次人数、缺料数量等，单位涉及件、小时、天等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且更新节奏不稳定，需要模型接入环节支持多系统数据的跨源调用与增量同步。日常文档结构差异较大，长文本与短字段混合，要求配置环节能适配不同文档的上下文截断规则。异常触发的更新场景需要配置实时响应的调用逻辑，避免排程调整滞后。同时，数据涉及产能、物料等约束性数值，要求模型接入环节能正确识别并处理带单位的字段信息，保证回复的准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配生产计划类文档的长上下文需求，覆盖订单、排程表等多类长文本数据 |
| `maxTokens` | 2000–3000 token | 满足设备点检维修问答的回复长度，覆盖工序说明、故障排查步骤等内容 |
| `quoteMaxToken` | 1500–2000 token | 限定引用的生产文档片段长度，避免引入无关的排程冗余数据 |
| `temperature` | 0.2–0.4 | 降低随机输出，保证排程建议、故障排查方案的一致性 |
| `AIPROXY_API_ENDPOINT` | 填写部署的代理地址 | 适配多数据源对接的跨域访问需求 |
| `AIPROXY_API_TOKEN` | 按实际生成的密钥填写 | 保障接口调用的安全性 |

## 容易做错的三处
- 现象为`undefined 当前分组 default 下对于模型 gpt-4o 无可用渠道`，原因是未在对应分组中配置适配生产计划数据的模型渠道，或渠道配置的API参数与生产数据调用要求不匹配。
- 现象为创建应用时配置结果重排无法勾选模型，原因是未在配置文件中正确配置重排模型的调用权限，或重排模型的参数未匹配生产文档的字段格式。
- 现象为fastGPT报错提示无可用embedding渠道，原因是oneapi中配置的bce-embedding渠道未绑定到生产计划场景的模型分组，或渠道的访问权限未开放。

## 怎么确认配好了
- 调用测试接口，输入生产排程相关的问题，检查返回结果是否包含正确的工单分解、设备产能匹配内容。
- 查看渠道管理页面，确认对应生产场景的模型渠道状态为可用，无报错提示。
- 上传测试用的销售订单、排程表文档，检查模型能否正确提取物料需求、缺料清单等字段信息。
- 触发异常更新场景（如模拟插单），检查模型能否实时响应并生成调整后的排程建议。
