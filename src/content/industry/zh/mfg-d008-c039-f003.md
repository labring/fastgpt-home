# 电机与发电机制造的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自电机与发电机制造企业的绕线、绝缘、总装与试验部门，核心文档包含绕组工艺卡、绝缘处理记录、动平衡报告、耐压绝缘测试记录、型式与出厂试验报告。数据来源涵盖电磁设计数据、铜线与绝缘材料批次台账、绕线设备运行参数、平衡机检测数据、电气试验台测试结果，以及ERP/MES系统的生产批次信息。数据更新频率为每台成品或每批生产任务更新一次，每次产品型式变更时同步更新全部关联文档。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据按生产批次与产品型式独立更新，多轮对话需精准绑定对应批次的生产文档与测试记录，避免跨批次调用过期数据。专业文档包含绕组匝数、浸漆工艺参数、动平衡余量、耐压测试值等细分字段，提示词需明确限定对话仅调用当前会话关联的生产批次数据，防止混淆不同产品的工艺要求。高频更新的特性要求多轮上下文需过滤非当前会话的历史批次数据，确保每次问答仅关联当前讨论的电机或发电机型号。

## 配置怎么定
本配置基于FastGPT v4.17.0版本的界面设置项制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配绕组工艺卡、测试报告的单段有效内容长度 |
| 重叠长度 | 150 字符 | 衔接相邻工艺环节的参数描述，避免内容断裂 |
| 相似度阈值 | 0.78–0.82 | 区分同型号不同批次的测试数据，过滤无关文档 |
| 单次搜索上限 | 前 4 条 | 单批次核心文档包含绕组工艺、绝缘记录等4类核心文件 |
| 最大上下文长度 | 5000 token | 保留3-4轮多轮对话的`messages`历史记录 |
| 历史记忆过滤 | 按`chatId`关联会话，用`variables`传递批次ID | 隔离不同会话的冗余数据，精准绑定对应批次的文档 |

## 容易做错的三处
- 模型输出时多插入空格、将字母改为大写，导致源文档引用格式错误。原因是提示词未明确限定输出需严格匹配源文档的字符与格式规范。
- 无法调起文件解析工具读取指定试验报告。原因是知识库配置的文档路径未绑定对应生产批次，或`variables`未传递正确的文档关联ID。
- 历史记录携带指定回复插件的冗余内容，干扰多轮对话逻辑。原因是未配置`messages`过滤规则，未排除非业务对话的插件交互记录。

## 怎么确认配好了
- 发起针对特定生产批次电机的绕组匝数核对对话，检查返回结果仅关联该批次的工艺卡与测试数据。
- 发起两轮连续对话后切换会话参数，确认新会话的历史记录未携带前序会话的冗余内容。
- 上传一份新增的试验报告并发起相关问答，确认工具能正确调用并解析新增文档。
- 检查模型输出内容，确认未出现多余空格或字母大写错误，格式匹配源文档规范。
