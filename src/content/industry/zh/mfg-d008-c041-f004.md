# 电镀与化学表面处理的设备点检与维修问答：工作流编排

## 这个品类的数据长什么样
本品类数据来自电镀厂、电子连接器与五金件表面处理车间的日常生产文档，包含槽液分析记录、工艺参数卡、挂具记录、膜厚与附着力报告、危废台账、废水监测记录。数据来源涵盖客户表面处理规范、槽液化验结果、整流器运行数据、在线水质监测数据与危废管理台账，更新频率覆盖每槽次、每班及固定监测周期。文档包含槽温、电流密度、膜厚值、挂具使用频次、排放浓度等结构化字段，不同文档的字段格式存在差异，需按类型分别匹配调用。

## 这些特征在「工作流编排」这一环带来什么约束
本品类的数据来源分散、更新频率不均，要求工作流需按槽次、班次、监测节点分别配置触发时机，避免调用过期或不相关数据。多类型文档的结构化字段差异较大，需为不同文档单独配置变量映射规则，确保工作流节点能准确提取所需参数。同时，设备点检与维修涉及合规性校验，工作流需关联危废、废水监测数据，不能仅依赖单一设备参数，且需在流程中加入异常校验环节，防止因参数错误导致批量返工或合规处罚。

## 配置怎么定
本配置适用于FastGPT v4.17.0
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量配置 | 按文档字段映射为`variables`内的槽号、槽温、膜厚值 | 匹配槽液分析记录、膜厚报告的结构化字段，便于工作流节点精准调用 |
| 节点ID绑定 | 绑定槽液检测、维修问答、合规校验三个`nodeId`节点 | 按点检、维修、合规的业务顺序串联流程，确保环节不遗漏 |
| 触发时机 | 按槽次完成、每班结束、监测超标触发 | 对应数据更新频率，保障工作流调用的始终是最新有效数据 |
| 上下文长度 | 800–1200字符 | 容纳单槽次的工艺参数与历史点检记录，避免关键信息被截断 |
| 单次调用条数 | 前3条 | 匹配每班的挂具更换记录、危废台账条目，过滤冗余数据干扰 |
| 失败重试次数 | 2次，间隔60秒 | 应对在线水质监测、整流器数据的临时网络波动，保障流程不中断 |

## 容易做错的三处
- 现象：工作流调用知识库时返回字段为空，界面显示变量解析失败。原因：未按要求配置`variables`的映射格式，错误使用了非标准的变量引用写法。
- 现象：工作流无法固定数据分析操作到指定工单节点，触发后无对应执行日志。原因：未正确绑定`nodeId`到数据分析节点，未在工作流编排中设置触发条件关联工单ID。
- 现象：工作流执行超时，返回504状态码。原因：未设置合理的超时间隔，同时调用了多个跨数据源的查询，超出系统处理上限。

## 怎么确认配好了
- 手动触发工作流，传入模拟槽号与工艺参数，检查`variables`是否正确映射到对应文档字段。
- 查看工作流节点日志，确认`nodeId`绑定的节点按顺序执行，无跳过或报错。
- 模拟数据更新场景，检查触发时机是否符合预设的槽次、班次或监测要求。
- 故意传入异常参数，验证失败重试机制是否按配置触发，确认流程中断前的重试次数符合预期。
