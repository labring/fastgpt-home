# 石油炼制的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据来自炼油企业生产运行、工艺、调度、设备与化验部门，日常文档包含操作规程、生产方案、物料平衡、馏出口质量报告、联锁台账、交接班记录、变更管理文件。数据来源包括DCS/APC、LIMS、罐区计量、原油评价、设备管理系统、能源系统，更新节奏涵盖实时、每班、每日。部分文档带有明确的工艺参数单位，如温度、压力、馏程数值。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引支持结构化与非结构化数据的混合接入，适配从实时DCS数据到离线台账的不同格式。差异化的更新节奏需要配置增量索引与批量索引结合的策略，分别处理实时数据与周期性更新的文档。多样的文档类型需要适配不同的文本分块规则，避免长文本的工艺描述或设备参数被截断。设备点检数据与工艺参数的强关联属性，要求索引保留字段关联关系，确保问答时可关联设备状态与对应的工艺指标。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配炼油文档中长文本的工艺描述与设备参数，避免关键信息截断 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工艺关联逻辑，防止分块后丢失联锁、负荷协调的上下文 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| 单次搜索上限 | 前 6 条 | 控制返回结果的信息量，避免冗余的多装置数据干扰核心问题 |
| 相似度阈值 | 0.75–0.85 按实测标定 | 匹配炼油工艺参数的精度要求，过滤低关联的非工艺类文档 |

## 容易做错的三处
- 现象：索引完成后搜索结果条数远低于预期，或返回无关联的非工艺文档。原因：未针对炼油场景的多源数据配置分块规则，导致长文本的工艺参数被截断，无法匹配检索关键词。
- 现象：实时DCS数据更新后无法及时出现在检索结果中。原因：未配置增量索引策略，仅使用全量索引更新，无法适配炼油场景的实时数据更新节奏。
- 现象：检索结果中设备信息与工艺参数无法对应。原因：未保留文档字段的关联关系，分块时丢失了设备ID与工艺指标的对应逻辑。

## 怎么确认配好了
- 查看索引任务日志，确认所有配置的数据源均被成功接入并完成索引。
- 提交设备点检相关的测试问题，核对返回结果包含对应文档的字段信息。
- 调整相似度阈值，验证检索结果的关联度符合预设的业务要求。
- 触发增量索引任务，确认实时更新的工艺数据可被正常检索到。
