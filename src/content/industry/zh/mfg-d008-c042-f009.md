# 石油炼制的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源包括DCS/APC系统、LIMS系统、罐区计量系统、原油评价数据库、设备管理系统及能源管理系统。数据更新节奏覆盖实时、每班、每日三个层级。日常文档包含操作规程、生产方案、物料平衡报表、馏出口质量报告、联锁台账、交接班记录、变更管理文件，字段涉及设备振动值、工艺温度压力、原油物性参数、物料流量等，带有明确的行业专属单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据来源分散且更新频率差异明显，实时工艺数据与每日报表需分别适配不同的上下文处理逻辑，对模型接入的上下文窗口提出明确要求。文档类型多样且结构差异大，需配置适配不同文档格式的拆分规则，避免上下文碎片化。行业专属字段与单位的存在，要求模型在接入时需优先适配行业术语的语义映射，确保问答结果的严谨性。多装置耦合的业务特性，也要求配置环节支持跨系统数据的关联调用约束。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配炼油行业多文档拼接的上下文需求，覆盖操作规程、联锁台账等多类型文档的完整关联信息 |
| `maxTokens` | 2000–3000 token | 匹配设备点检问答的单次回复长度需求，避免超出接口返回限制 |
| `quoteMaxToken` | 1500–2000 token | 确保召回的行业文档片段足够支撑设备故障排查的细节描述 |
| `temperature` | 0.2–0.4 | 降低随机输出概率，保障设备维修建议的严谨性与准确性 |
| `AIPROXY_API_ENDPOINT` | 按所选模型服务商的官方接口填写 | 适配不同模型的调用路径，确保请求能正确送达模型服务 |
| `AIPROXY_API_TOKEN` | 按服务商生成的有效密钥填写 | 完成模型调用的身份验证，保障接口访问安全 |

## 容易做错的三处
-  模型映射配置后不生效，界面显示参数未同步。原因是未在配置页完成模型与业务知识库的关联绑定，仅填写了接口密钥未指定对应知识库的映射规则。
-  调用模型时返回报错，商用大模型服务或本地部署的开源模型镜像均出现异常。原因是`AIPROXY_API_ENDPOINT`配置的接口路径未适配模型的实际部署地址，或`AIPROXY_API_TOKEN`存在字符遗漏、过期的情况。
-  业务系统对接后，不同用户的聊天记录未完成隔离。原因是未在API调用时传入用户标识参数，导致会话上下文未按用户维度拆分。

## 怎么确认配好了
-  调用模型测试接口，输入设备点检相关的行业术语，核对返回结果是否包含正确的工艺参数与设备名称。
-  上传一份炼油行业的操作规程文档，测试文档解析与召回功能，确认召回的文档片段与问题匹配度符合预期。
-  传入不同的用户标识参数，发起多轮对话，核对会话上下文是否按用户维度独立存储。
-  检查接口返回的日志，确认`AIPROXY_API_TOKEN`验证通过，无权限报错或参数缺失提示。
