# 石油炼制的设备点检与维修问答：部署与升级

## 这个品类的数据长什么样
石油炼制场景的数据覆盖炼油企业生产运行、工艺、调度、设备与化验部门的日常文档，包括操作规程、生产方案、物料平衡、馏出口质量报告、联锁台账、交接班记录、变更管理文件。数据来源包含DCS/APC、LIMS、罐区计量、原油评价、设备管理系统、能源系统，更新节奏涵盖实时、每班、每日，文档按生产流程与设备管理分类，字段包含设备编号、运行参数、检测指标、维护记录等，单位涉及压力、温度、流量等工业标准单位，单份文档体积从几十KB到数MB不等。

## 这些特征在「部署与升级」这一环带来什么约束
多源数据的更新节奏差异大，要求部署阶段适配实时、每班、每日的不同同步频率，避免数据延迟或数据库连接过载。多类型文档的结构与字段差异，需要在部署时配置针对性的文本处理规则，适配不同文档的格式与单位。实时数据的高频更新，要求预留足够的系统资源处理实时请求，升级时需验证实时数据接入的稳定性。设备点检与维修相关文档关联性强，部署时需配置关联检索逻辑，确保维修问答能快速匹配对应设备的历史记录与操作规程，提升检索准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 100–150 连接 | 适配多源数据的实时、每班、每日更新频率，避免数据库连接过载 |
| `MONGODB_URI` | 指向独立部署的高可用副本集地址 | 存储设备台账、维修记录等非结构化文档，保障多类型数据的读写稳定性 |
| `REDIS_URL` | 配置为带持久化的集群地址 | 缓存实时设备参数与检索结果，匹配实时更新的数据节奏 |
| `STORAGE_S3_ENDPOINT` | 对接企业内部对象存储服务的内网地址 | 存储大体积的原油评价报告、联锁台账等文档，适配工业场景的大文件存储需求 |
| `ROOT_KEY` | 按企业内部权限规则生成 | 保障系统部署后的访问权限安全，符合炼油企业的信息安全要求 |

## 容易做错的三处
- 现象：返回引用内容但未开启引用开关。原因：FastGPT v4.17.0版本升级后，默认引用逻辑的配置项未同步更新，导致参数与版本不匹配。
- 现象：工具调用判断逻辑异常，部分模型无法调用预设工具。原因：部署时未配置`ROOT_KEY`对应的权限校验规则，导致工具调用权限受限。
- 现象：非Docker部署的Ollama接入失败。原因：部署时未正确配置`FE_DOMAIN`与内部服务的网络互通规则，导致跨服务请求被拦截。

## 怎么确认配好了
- 执行数据库连接测试，验证`DB_MAX_LINK`配置的连接数是否能支撑多源数据的同步请求。
- 提交不同类型的炼油设备文档，检查检索结果是否能正确匹配对应文档的字段与单位。
- 触发实时设备参数的检索请求，确认响应延迟符合业务场景的实时性要求。
- 验证工具调用逻辑，确认配置的权限规则能正常拦截未授权的访问请求。
