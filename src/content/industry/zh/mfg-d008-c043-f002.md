# 精细化工间歇合成的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类主体为涂料、树脂、助剂、农化中间体及专用化学品企业，日常文档包含批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据来源于配方与工艺库、原料批次、反应釜DCS、称量系统、LIMS、仓储系统，更新频率为每批及每个关键步骤。业务流程中按顺序复核投料、判断反应终点切换后处理、防止换品清洗残留为最耗时环节，且多品种多批次切换、配方保密与清洗确认要求高于基础化工连续生产品类。

## 这些特征在「向量模型与索引」这一环带来什么约束
多批次高频更新的文档要求索引支持增量更新，避免全量重建占用生产系统资源；多品种切换带来的文档字段差异与化工专业术语，要求索引支持按生产批次、产品品类分组检索，防止跨品类数据干扰；投料、反应终点、清洗等关键环节的文档需高置信度匹配，要求向量模型对专业术语的编码精度更高；不同来源的时序数据与报表数据格式差异，要求预处理环节统一字段结构，确保向量编码的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 该品类的工序文档单条内容长度适中，分块后可保留完整的专业语义，适配FastGPT v4.17.0的分块逻辑 |
| 重叠长度 | 100–150 字符 | 工序间存在逻辑关联，重叠分块可保留上下文连贯性，避免关键步骤的语义断裂 |
| 相似度阈值 | 0.75–0.85 | 需过滤低匹配度的非专业文档，避免误召回无关品类的设备数据，具体阈值按实测标定 |
| 单次搜索上限 | 前 5 条 | 关键工序的检索结果需精准，过多结果会增加上下文负荷，影响推理效率 |
| `defaultToken` | 4096 token | 该品类的单份工序文档上下文长度通常在该范围内，可覆盖完整的工序信息 |
| `maxToken` | 8192 token | 需容纳多份关联文档的检索结果，支持复杂问题的跨工序推理 |

## 容易做错的三处
- 现象：调用向量模型时返回503错误，提示对应模型无可用渠道。原因：未针对化工专业场景选择适配的嵌入模型，或模型渠道配置未绑定该品类专属的知识库权限。
- 现象：检索结果包含无关品类的设备点检文档，字段匹配混乱。原因：未按生产批次、产品品类设置分组索引，导致跨品类数据被召回，干扰专业检索结果。
- 现象：检索结果超时，无法在生产要求的时间内返回结果。原因：未限制单次搜索上限，或分块长度设置过大导致向量计算负荷过高，超出系统处理能力。

## 怎么确认配好了
- 上传1份典型的反应过程记录文档，执行设备点检相关的检索，核对返回结果是否包含该品类专属的工序术语与数据字段。
- 模拟批量更新1批生产的关联文档，检查索引是否仅增量更新该批次数据，未触发全量重建。
- 查看系统日志，确认向量模型调用未出现503类的渠道错误，且检索响应时间符合生产环节的等待要求。
- 调整相似度阈值，验证返回结果的数量随阈值变化符合预期，无过多无关结果或过少有效结果。
