# 精细化工间歇合成的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来自配方与工艺库、原料批次、反应釜DCS、称量系统、LIMS及仓储系统，更新节奏为每批生产或每个关键步骤触发。日常留存的文档包含批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单，各文档绑定专属批次号，包含投料量、反应温度、清洗残留检测值等字段，无统一跨系统格式，需按批次维度关联整合。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的多批次切换生产模式、异构多源数据结构及高风险生产场景，为模型接入与配置带来多重约束。按批次更新的专属文档需严格绑定对应批次上下文，避免跨批次数据干扰设备点检逻辑。异构来源的文档需配置统一的格式适配规则，保障模型可准确解析不同系统的字段信息。高风险的生产要求需限制模型输出的随机性，同时控制上下文长度以避免关键信息截断，保障点检结果的准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配单批次完整生产流程的上下文长度，避免截断投料、反应步骤等关键信息 |
| `temperature` | 0.2–0.4 | 降低模型输出的随机性，保障设备点检逻辑的一致性，适配化工场景的严谨要求 |
| `toolChoice` | auto | 自动触发工具调用，适配多维度设备参数核查、历史文档召回的复杂需求 |
| `quoteMaxToken` | 1500 token | 优先召回单批次内的关联文档，避免跨批次无关数据干扰点检结果 |
| `AIPROXY_API_TOKEN` | 对应模型服务的有效令牌 | 用于安全对接合规的模型接口，保障数据传输的合法性 |
| `AIPROXY_API_ENDPOINT` | 部署的代理服务专属地址 | 适配多系统数据接入的统一调用路径，简化配置复杂度 |

## 容易做错的三处
- 现象：工具调用结果偏离设备点检逻辑，输出与实际生产流程不符，甚至给出错误的维修建议。原因：`temperature`取值过高，导致模型输出随机性过强，未贴合化工场景的严谨要求。
- 现象：Rerank模型占用显存持续上升，最终触发内存溢出报错，无法继续处理请求。原因：未配置上下文自动截断规则，多批次生产数据持续加载导致显存资源无法自动释放。
- 现象：OneAPI页面无可用渠道列表，无法选择目标模型。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或代理服务未正常启动。

## 怎么确认配好了
- 输入单批次投料复核类问题，验证模型是否召回对应批次的投料复核单、反应过程记录等关联文档。
- 触发工具调用测试，确认`toolChoice`自动选择对应工具的逻辑符合设备点检的核查需求。
- 监控模型服务的显存占用，确认在多批次测试后未出现持续上升的异常情况。
- 查看OneAPI渠道列表，确认对应模型渠道已正常显示并可正常调用。
