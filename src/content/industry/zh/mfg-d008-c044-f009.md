# 纸浆造纸的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
纸浆造纸品类的业务数据主要来自木浆废纸批次、DCS/QCS系统、纸机在线测量设备、实验室、能源和水处理系统。日常文档包含配浆单、打浆记录、纸机运行记录、在线质量曲线、实验室报告、断纸与换品记录。数据更新节奏涵盖实时、每班、每卷三个维度，字段涉及浆料性质、纸机运行参数、纸张质量指标与设备运行状态，无统一固定的单文档规模。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类数据来源分散且更新节奏差异显著，要求模型接入环节需兼容多源数据的批量读取与实时同步；在线质量曲线、断纸记录等非结构化数据与配浆单、打浆记录等结构化数据并存，需配置适配混合格式数据的处理逻辑；高速连续幅材生产带来的业务数据密度较高，模型上下文窗口需匹配业务数据的更新节奏，避免因上下文溢出导致关键点检与维修信息遗漏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配当班配浆单、打浆记录、纸机运行记录的总长度，避免上下文溢出导致关键点检与维修信息丢失 |
| `temperature` | 0.2–0.4 | 设备点检与维修问答需严谨准确，较低温度可降低回答的随机性，匹配工业场景的可靠性要求 |
| `AIPROXY_API_ENDPOINT` | 填写部署所在区域的官方接入地址 | 适配多源工业数据的跨节点同步需求，确保模型调用的稳定性 |
| `AIPROXY_API_TOKEN` | 按企业内部权限生成的专属令牌 | 保障模型接入的安全性，避免未授权调用影响生产数据 |
| `maxTokens` | 1000–1500 token | 控制单轮回答的输出长度，匹配设备维修方案的简洁性要求，避免冗余信息干扰现场操作 |

## 容易做错的三处
- 现象：配置第三方模型接入地址后调用报错404。原因：未正确匹配模型的实际接入端点，导致请求无法被目标服务识别。
- 现象：设置`temperature`参数过高，设备点检问答出现不一致的维修方案建议。原因：高温度参数会放大模型回答的随机性，不符合工业场景的严谨性要求。
- 现象：配置`maxContext`参数过小，多卷纸机的运行记录无法完整传入模型，导致点检结果遗漏断纸相关信息。原因：未适配纸浆造纸业务中多份历史记录的总长度，上下文窗口不足。

## 怎么确认配好了
需结合FastGPT v4.17.0版本的界面操作完成以下核对动作：
- 填写`AIPROXY_API_ENDPOINT`和`AIPROXY_API_TOKEN`后，发起一次模型调用测试，确认返回正常的设备点检相关回答，无报错信息。
- 上传一份当班的配浆单和纸机运行记录，测试`maxContext`参数是否能完整加载文档内容，无截断提示。
- 设置`temperature`为0.3，连续发起三次同类故障的问答测试，确认回答结果差异在可接受范围内。
- 配置`maxTokens`参数后，验证单轮回答的输出长度符合业务场景的信息展示需求。
