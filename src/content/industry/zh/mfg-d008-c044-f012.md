# 纸浆造纸的设备点检与维修问答：部署与升级
FastGPT v4.17.0

## 这个品类的数据长什么样
纸浆造纸品类的业务数据来源包含木浆废纸批次、DCS/QCS系统、纸机在线测量设备、实验室、能源和水处理系统。数据更新节奏分为实时（纸机运行参数、在线质量曲线）、每班（打浆记录、配浆单）、每卷（断纸与换品记录）。日常文档包含结构化的配浆单、打浆记录，以及非结构化的在线质量曲线、实验室报告，字段涵盖浆料配比、打浆度、纸幅克重、水分含量、断纸时长等，单位涉及g/㎡、%、分钟等。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的数据结构要求部署时配置灵活的字段映射规则，适配结构化的运行记录与非结构化的曲线报告。不同更新频率的数据源需要设置差异化的同步任务，实时数据需配置低延迟的缓存链路，避免影响设备点检的响应速度。每卷生成的断纸记录需关联对应设备ID，部署时需确保数据源的唯一标识一致性。升级过程中需兼容旧版数据格式，防止因格式变更导致历史点检记录无法检索，同时需控制升级窗口时长，避免中断高速连续生产的业务流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10 条 | 限制单次召回的设备相关文档数量，避免上下文过载影响模型生成质量 |
| `MONGODB_URI` | `mongodb://[username:password@]host1:port1,host2:port2/[authSource=admin]` | 存储多源历史点检记录、断纸与换品记录，支持横向扩展存储容量 |
| `REDIS_URL` | `redis://:your_password@host:port/0` | 缓存实时设备状态与向量召回结果，将检索延迟控制在 2 秒以内 |
| `STORAGE_S3_ENDPOINT` | 企业内部对象存储专属域名 | 存储在线质量曲线、实验室报告等非结构化文档，适配大体积文件的读写需求 |
| `FILE_TOKEN_KEY` | 32 位随机加密字符串 | 保护文档下载链接的安全性，防止未授权访问生产敏感数据 |

## 容易做错的三处
- 现象：Windows环境下编译项目失败，终端提示缺少必要的编译依赖。原因：未安装符合要求的Visual Studio版本，未配置正确的系统编译环境变量。
- 现象：本地部署使用大语言模型后，相同设备点检问题返回结果不一致。原因：未配置`REDIS_URL`缓存对话上下文，导致每次请求重新检索全量数据，模型生成逻辑出现波动。
- 现象：本地镜像打包时弹出WARNING: current commit information was not captured by the。原因：未在项目根目录初始化Git仓库，导致打包脚本无法获取版本信息，影响镜像构建的完整性校验。

## 怎么确认配好了
- 登录FastGPT v4.17.0管理后台，进入数据源管理页面，检查DCS、实验室系统等配置的数据源同步状态，确认数据更新频率符合预设规则。
- 发起测试提问，比如「某型号纸机的断纸记录有哪些」，验证返回结果包含配浆单、断纸与换品记录等对应品类的文档内容。
- 查看系统运行日志，确认`MONGODB_URI`、`REDIS_URL`等配置项的连接状态正常，无超时或认证失败报错。
- 模拟配置升级流程，执行滚动升级操作并验证回滚功能可正常执行，不影响现有设备数据的检索服务。
