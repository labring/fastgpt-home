# 纺纱与织造的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自棉纺、化纤纺、机织与针织企业的配棉配料单、工艺上机单、设备运转记录、纱线/坯布检验单、疵点台账，数据来源涵盖原纤维检验报告、ERP系统、纺机织机实时采集数据、条干仪、验布机检测结果与订单规格文件。数据更新节奏随生产批次、班组班次与布匹产出同步，每批原料、每班生产、每匹布产出均会生成新的业务数据，文档结构多包含工艺参数、检测数值、设备运行状态与疵点描述等字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类多源混合的数据结构，要求向量索引需同时适配结构化参数数据与非结构化的检验、疵点文本；高频更新节奏要求索引支持增量同步，避免全量重索引占用资源；设备运行数据与疵点记录的专业术语密集，要求向量模型适配工业场景语义，同时分块时需保留专业表述的完整单元；单批次数据量随设备头数增长，需要控制向量化并发规模，避免超出接口调用限额。

## 配置怎么定
本页基于FastGPT v4.17.0版本的配置逻辑，具体配置如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类工艺单、疵点记录的常见文本长度，避免割裂专业术语组合 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的语义关联，防止工艺参数、疵点描述被分块截断 |
| `maxToken` | 8192 | 适配多数工业场景文本的token上限，匹配主流开源向量模型的输入限制 |
| `defaultToken` | 按实测标定 | 适配单批次向量化的总token调用量，避免超出API调用限额 |
| 单次召回条数 | 前6–10条 | 匹配设备点检与维修的多关联故障查询需求，覆盖常见异常组合 |
| 索引刷新周期 | 每班一次 | 匹配该品类每班更新生产数据的节奏，平衡实时性与索引资源消耗 |

## 容易做错的三处
- 现象：知识库上传后，索引状态长时间停留在「索引中」无法完成。原因：未匹配该品类高频更新的数据节奏，设置了过长的全量索引周期，或并发向量化线程数过高导致调用超时。
- 现象：设置分块长度为3000字符时，部分长文本如工艺上机单出现块丢失。原因：未结合向量模型的`maxToken`限制调整分块参数，过长的分块超出模型输入上限，导致系统自动跳过部分分块。
- 现象：向量化过程中触发embedding速率超限报错，日志显示调用频率超出接口限制。原因：未调低并发向量化线程数，或未设置合理的批次调用间隔，导致向量模型API调用超出限额。

## 怎么确认配好了
- 上传单份典型文档如配棉配料单，检查生成的文本块数量与预期一致，无明显截断或丢失。
- 发起设备点检相关的查询，核对召回的文本块包含对应的工艺参数、疵点记录等业务内容。
- 查看向量模型调用日志，确认调用频率未超出接口限额，无频繁报错记录。
- 等待一个生产班次后，检查新增的业务文档是否自动完成索引同步。
