# 纺纱与织造的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
纺纱与织造品类的日常数据来自原纤维检验、ERP、纺机与织机数据、条干仪、验布机、订单规格。数据更新随每批原料、每班、每匹布推进，日常文档包含配棉或配料单、工艺上机单、设备运转记录、纱线检验、坯布检验、疵点记录。数据字段包含纤维指标、纺纱捻度、织造组织参数、疵点类型、机台编号等，单位涵盖支数、米、小时等。通常这类数据按生产批次、机台、检验环节分类存储。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
品类数据更新频率高且按生产环节拆分，多轮对话需严格控制上下文范围，避免引入跨批次的无关数据。多源数据包含大量专业术语与细分字段，提示词需明确区分不同文档的调用规则，防止混淆配棉单与疵点记录的内容。设备头数多且疵点可连续传播，对话需回溯历史点检记录时，需通过分组管理不同场景的历史数据，避免上下文过载影响回复准确性。同时，单批文档长度有限但更新频繁，需限制对话轮次与上下文总长度，确保每次调用的知识库内容与当前问题匹配。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体设置如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按点检工单、疵点记录、工艺参数分为3组，每组绑定对应知识库 | 品类数据按生产环节拆分，分组变量可避免不同场景的历史数据混淆 |
| `messages` | 保留最近10轮对话，截断超出8000字符的历史内容 | 单批数据更新频繁，过长上下文会引入无关历史记录，影响当前回复准确性 |
| 最大上下文 | 6000–10000字符 | 品类单批文档长度多在1000字符内，10轮对话总长度控制在该区间内可避免过载 |
| 问题优化 | 开启，按设备型号、疵点类型补充前置条件 | 品类设备型号多、疵点类型细分，优化后可精准召回对应知识库内容 |
| 词库绑定 | 绑定纺纱捻度、布面疵点、机台编号专属词库 | 品类有大量专业术语，词库可统一术语表述，避免歧义 |

## 容易做错的三处
- 现象：对话输出的回复内容叠加了前一轮的结果。原因：未对`variables`做分组绑定，多轮对话中历史变量值被带入当前上下文。
- 现象：配置了输入引导与词库，但对话界面未显示预期引导问题。原因：未开启输入引导的主动触发开关，或词库未关联到当前应用的知识库范围。
- 现象：上传的xlsx知识库文件，无法被复述其中的内容。原因：未配置xlsx的分块解析规则，或知识库导入时未正确提取表格字段与对应文本。

## 怎么确认配好了
- 发起包含配棉单纤维指标的测试对话，通过`chatId`查看上下文日志，检查回复中仅调用对应分组的`variables`数据，无无关历史内容残留。
- 触发输入引导功能，确认界面显示按设备型号、疵点类型分类的预设问题。
- 上传测试用xlsx文件，发起复述文件内容的要求，确认回复包含表格内的字段与对应数值。
- 发起连续10轮的模拟点检对话，检查上下文未超出设定的最大长度，且每轮回复仅关联当前轮次的问题。
