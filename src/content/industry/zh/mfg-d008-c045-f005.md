# 纺纱与织造的设备点检与维修问答：工具调用与插件

## 这个品类的数据长什么样
本品类的数据主要来自原纤维检验报告、ERP系统、纺机与织机实时采集数据、条干仪、验布机检测结果及订单规格文档。更新节奏随每批原料、每班生产及每匹布产出同步调整。日常文档包含配棉或配料单、工艺上机单、设备运转记录、纱线检验单、坯布检验单、疵点台账，字段覆盖纤维指标、工艺参数、设备运行状态、检验结果，单位包含克/米、捻次/米等。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的数据更新频率高、来源分散且文档类型多样，对工具调用与插件配置带来多重约束。首先，高频更新的原料、生产及检验数据要求插件支持实时数据拉取，避免使用静态缓存导致的参数过时。其次，多源数据流转逻辑要求插件按ERP、纺机设备、检验设备的顺序配置数据源，贴合业务流程。另外，多类型业务文档需要插件支持关联不同知识库，匹配配棉单、工艺单等核心文档的查询需求。同时，设备头数多且疵点数据连续传播的特点，要求工具调用支持批量设备数据拉取与跨批次疵点关联分析。

## 配置怎么定
本页面配置适用于FastGPT v4.17.0及以上版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | `auto` | 适配设备点检、故障排查、参数查询等多场景的自动工具调用 |
| 工作流/API 函数调用配置 | `enabled` | 强制触发工具调用，确保维修问答环节调用设备参数与工艺知识库 |
| 工具调用超时阈值 | `300 秒` | 本品类设备数据拉取、检验结果查询通常耗时100-200秒，预留合理缓冲 |
| 多源数据源配置顺序 | 按ERP、纺机采集设备、检验设备的顺序配置 | 贴合本品类从原料到成品的数据流转逻辑 |
| 知识库关联范围 | 绑定配棉单、工艺上机单、疵点记录知识库 | 匹配本品类日常业务文档的核心类型 |
| 工具返回内容过滤规则 | 仅展示最终维修建议 | 避免中间调用的冗余日志影响维修人员判断 |

## 容易做错的三处
- 现象：调用应用时提示密钥无效，界面返回调用失败。原因：未使用应用专属的app key，误用了账号级别的account key进行鉴权。
- 现象：通过API调用嵌套了知识库助手的工作流，返回结果为空值。原因：当前FastGPT版本低于v4.8.10，不支持工作流嵌套知识库助手的API调用逻辑。
- 现象：工作流中两层工具调用的中间返回内容被打印展示，干扰最终结果查看。原因：未配置工具返回内容的过滤规则，默认展示所有层级的调用日志。

## 怎么确认配好了
- 发起一次设备点检相关的查询，验证工具调用是否自动拉取对应纺机的实时运行数据。
- 调用API触发工作流，检查返回结果是否包含知识库匹配的工艺参数内容，无空值返回。
- 查看iframe嵌入的应用界面，确认应用图像与用户头像在常用浏览器中正常显示。
- 触发两层工具调用的工作流，验证第一层的中间调用内容未被直接展示。
