# 纺纱与织造的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
通常纺纱与织造品类的日常文档包含配棉或配料单、工艺上机单、设备运转记录、纱线检验、坯布检验、疵点记录。数据来源涵盖原纤维检验、ERP、纺机与织机数据、条干仪、验布机、订单规格。更新节奏随每批原料、每班、每匹布调整。文档字段包含纤维指标、纺纱捻度、织机转速、疵点类型、检验数值等，单位多为克、米、转/分钟、匹等。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据更新频率高且覆盖多批次、多班次的动态变化，要求模型接入配置支持实时加载最新的工艺与检验数据。文档类型多且字段差异明显，需要配置适配多源异构文档的解析逻辑，确保不同类型的业务文档都能被有效关联。设备头数多且疵点存在连续传播特性，要求模型能关联多设备的点检记录，输出具备全局关联性的维修建议。同时纤维配料、参数设定等环节的错误会直接影响成品质量，需要配置确保模型输出的结果可追溯至原始业务文档。

## 配置怎么定
本配置指南适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配多源文档的长上下文需求，覆盖单批次原料到成品的全链路业务数据 |
| `temperature` | 0.2–0.4 | 降低随机输出偏差，确保维修建议与工艺参数的一致性，符合纺纱织造的严谨性要求 |
| `quoteMaxToken` | 1500–2000 token | 保留足够的原始文档片段作为依据，支撑点检与维修建议的可追溯性 |
| 工作流/API 工具选择配置 | auto | 自动匹配问答场景，适配设备参数查询、疵点分析等不同类型的业务需求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属节点 | 适配企业内网或公有云的部署场景，确保数据传输的安全性与稳定性 |
| `AIPROXY_API_TOKEN` | 与对应模型绑定的专属密钥 | 确保模型调用的权限合规，避免未授权的访问请求 |

## 容易做错的三处
- 现象：部分大模型无法正常加载并调用，界面显示模型不可选或调用报错。原因：未在`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置中添加对应模型的专属接入节点与密钥，或所选模型未在平台支持范围内。
- 现象：模型输出的维修建议与当前工艺参数不匹配，未引用最新的设备运转记录。原因：`maxContext`配置值过低，未能加载完整的工艺文档与实时数据，导致上下文缺失。
- 现象：批量导入多班次的设备点检数据时，出现响应超时错误。原因：未调整`maxTokens`适配批量数据的长度，超出平台单次处理的上限。

## 怎么确认配好了
- 上传单份配棉单与疵点记录文档，触发设备点检与维修问答请求，检查返回结果是否关联了文档中的具体纤维指标与疵点类型。
- 查看平台的模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置已正常连通，无认证或连接报错返回。
- 调整`temperature`参数值，验证输出结果的一致性是否符合预期，确保维修建议的严谨性。
- 导入多批次的设备运转数据，检查模型是否能正确关联不同班次的参数变化，输出连贯的点检建议。
