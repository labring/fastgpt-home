# 纺纱与织造的设备点检与维修问答：知识库检索与召回

## 这个品类的数据长什么样
该品类数据来自棉纺、化纤纺、机织与针织企业的多类业务系统与设备，包含配棉配料单、工艺上机单、设备运转记录、纱线检验报告、坯布检验台账、疵点处理记录等文档。数据来源覆盖原纤维检验结果、ERP系统、纺机与织机实时采集数据、条干仪、验布机输出信息，以及订单规格文件。更新节奏随每批原料投料、每班生产进度、每匹布产出同步更新，文档包含纤维指标、工艺参数、设备运行状态、疵点类型与对应修复方案等核心字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的业务与设备数据，要求检索召回需兼顾结构化参数匹配与非结构化文本检索，适配不同格式的文档内容。高频更新的实时数据，需支持增量同步机制，避免检索到过期的工艺参数或设备记录。单批原料、单匹布的专属参数，要求召回结果需关联对应订单的规格字段，避免跨批次参数混用。疵点记录与处理方案的强关联属性，需优先召回同类型疵点的历史处理结果，提升检索匹配的针对性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | 匹配疵点记录与工艺参数的精准度要求，避免过低引入无关结果，过高遗漏有效历史记录 |
| `limit` | 前8条 | 适配设备点检与维修问答的上下文长度限制，同时覆盖同类型疵点的多组处理方案 |
| `searchMode` | hybrid | 兼顾结构化设备参数与非结构化疵点文本的检索需求，适配多源数据特征 |
| `usingReRank` | 开启 | 对初始召回结果重排序，优先匹配当前生产批次的工艺参数与疵点类型 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户提问自动扩展相关工艺参数、设备型号的检索词，覆盖配料、捻度设置等高频业务场景 |
| `collectionIds` | 绑定纺纱织造专属知识库集合 | 隔离其他品类的知识库数据，避免检索到无关的染整或通用机械加工文档 |

## 容易做错的三处
- 现象：知识库调试阶段召回结果正常，但正式对话环节未返回知识库参考内容。原因：未在对话工作流中绑定对应纺纱织造的知识库集合，或未开启检索结果的上下文注入配置。
- 现象：检索结果条数与配置的`limit`参数不符，出现过多或过少的召回条目。原因：未正确设置`similarity`阈值，或混合检索模式下结构化与非结构化权重分配失衡。
- 现象：检索结果出现染整或其他品类的设备文档。原因：未隔离专属知识库集合，或`collectionIds`配置错误引入了跨品类数据。

## 怎么确认配好了
- 上传单份纺纱工艺上机单，发起对应疵点的提问，核对召回结果是否包含该文档的相关字段。
- 调整`similarity`参数区间，观察召回结果的匹配度变化，确认阈值生效。
- 检查工作流的检索节点，确认已绑定指定的纺纱织造知识库集合，无其他无关集合的关联。
- 发起包含设备型号、疵点类型的复合提问，验证`usingReRank`是否对结果进行了重排序，优先返回匹配度更高的内容。
