# 计量器具与实验室管理的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据覆盖企业计量室、CNAS体系实验室的计量管理全流程，核心文档包括量具台账、校准计划、校准证书、期间核查记录、试验原始记录、标准物质台账、偏离处置单。数据来源涵盖企业计量管理系统、LIMS平台、外部校准机构证书、环境监测数据，更新节奏随校准周期、单次试验完成、异常事件触发。文档字段包含器具唯一标识、校准有效期、测量不确定度、溯源标准器信息等，需匹配相关体系的格式要求。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类数据涉及专业计量术语与溯源链关联逻辑，多轮对话需准确匹配器具唯一标识，避免混淆不同批次校准的同类型器具。数据更新无固定周期，对话过程中需基于当前上下文的器具编号动态调用对应最新文档，无法依赖固定的历史数据缓存。出错后果直接关联质量判定，提示词需严格约束输出仅基于上传的台账、校准证书等官方文档，不得编造测量不确定度或溯源信息。长文本的溯源记录会占用大量上下文空间，需限制对话上下文的总长度，避免稀释关键专业字段。

## 配置怎么定
本配置方案基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文长度 | 800–1200 字符 | 该品类溯源链、校准证书等文档篇幅较长，过长上下文会稀释器具编号、校准日期等关键字段，按实测标定调整上限 |
| `chatId`绑定 | 绑定至器具唯一编号 | 计量器具需通过唯一标识区分，`chatId`绑定器具编号可确保同器具的对话上下文不与其他器具混淆 |
| `variables`变量注入 | 注入当前器具的台账编号、校准有效期 | 用于提示词中限定对话仅关联指定器具的文档数据，避免召回无关记录 |
| 历史消息`messages`截断 | 保留前3轮有效对话 | 该品类数据关联逻辑复杂，过多历史消息会引入无关字段，截断后可聚焦当前对话的器具与问题 |
| 对话超时时间 | 600 秒 | 该品类数据查询需加载多份校准、溯源文档，600秒可覆盖完整的召回与整理流程 |
| 问题优化 | 开启 | 该品类术语专业性强，问题优化可将口语化提问转换为符合文档字段的专业表述，提升召回准确率 |

## 容易做错的三处
- 现象：多轮对话后，针对同一器具的点检问题，回答出现混淆不同校准批次的校准日期。原因：未将`chatId`绑定至器具唯一编号，上下文累积了不同器具的历史数据，导致匹配错误。
- 现象：调用校准证书数据时，输出的测量不确定度与上传文档不符。原因：未通过`variables`注入指定器具的台账编号，导致召回了无关器具的校准数据。
- 现象：触发偏离处置时，历史上下文未自动清空，旧的正常校准数据干扰异常判断。原因：未设置按偏离处置单生成时机触发上下文清空，而是采用固定周期清空的规则，无法匹配该品类的异常更新节奏。

## 怎么确认配好了
- 发起针对特定计量器具的多轮对话，检查对话界面的上下文面板，确认仅展示该器具的台账、校准记录。
- 触发偏离处置场景，验证上下文面板的历史对话内容被清空。
- 输入口语化提问，比如“这个卡尺上次校准是什么时候”，检查系统是否转换为针对指定器具的专业查询。
- 切换至另一台计量器具发起对话，验证新对话的上下文不会包含前一台器具的历史数据。
