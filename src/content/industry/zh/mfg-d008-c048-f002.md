# 设备点检与预防维修的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自制造企业设备部、车间维修班组与公用工程部门的日常工作产出，包含设备台账、点检表、保养计划、维修工单、故障分析、备件清单及特种设备检验记录等文档。数据来源涵盖EAM/CMMS系统、设备传感采集数据、操作员点检记录、维修历史、备件库存信息与法定检验文件，更新频率覆盖每班、日/周/月周期及故障突发场景，字段包含设备编号、点检参数、维修时间、备件型号等，附带对应物理单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
多来源的异构数据包含短点检表、长维修工单等不同格式，要求分块策略兼顾不同文档的长度特征；高频更新的传感数据与突发故障记录，要求索引支持增量更新以避免全量重建的资源消耗；带物理单位的点检参数、备件型号等字段，需在分块时保留完整上下文，否则向量匹配会丢失关键判断依据；维修场景的实时响应需求，限制了检索返回的上下文总长度，需平衡召回数量与系统性能。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配设备台账、维修工单的典型文本长度，保留点检参数与单位的完整上下文 |
| 重叠长度 | 100–150 字符 | 避免分块切断单条点检项、故障描述等关键内容，保证向量召回的完整性 |
| 相似度阈值 | 0.72–0.80 | 区分正常点检记录与故障异常描述，减少无关工单的无效召回 |
| 单次搜索上限 | 前 8 条 | 匹配维修班组快速定位故障的使用场景，控制上下文总长度 |
| `maxToken` | 4096 token | 适配Qwen3-Embedding-8B的模型输入限制，避免截断关键备件型号与设备编号 |
| `defaultToken` | 按实测标定 | 适配本地部署M3E模型的中文文本编码长度，保证参数字段的向量准确性 |

## 容易做错的三处
- 配置同名索引模型导致覆盖原有设置：现象为新增qwen3-embedding-8b模型后，原有本地M3E配置丢失，界面显示模型名称重复提示。原因是未区分不同场景的模型配置，直接复用模型名称。
- 分块长度过短导致点检参数被截断：现象为知识库检索结果中缺少设备振动值、温度阈值等关键单位信息，无法支撑故障判断。原因是分块长度设置小于单条点检记录的内容长度。
- 未调整相似度阈值导致召回无关工单：现象为检索故障问题时，同时返回大量正常点检记录，无法快速定位故障分析文档。原因是相似度阈值设置过低，召回了过多低相关内容。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型配置页面，检查已添加的索引模型名称无重复，对应部署的qwen3-embedding-8b或M3E模型状态显示正常。
- 上传单条设备点检记录，执行分块测试，确认分块结果保留了设备编号、点检参数与单位等完整信息。
- 输入典型故障问题，执行检索，确认返回结果包含故障分析、维修工单等相关文档，且数量符合单次搜索上限设置。
- 查看知识库索引日志，确认增量更新任务按每班、故障触发等设定的频率正常执行。
