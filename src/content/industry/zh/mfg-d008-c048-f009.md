# 设备点检与预防维修的设备点检与维修问答：模型接入与配置
本文基于FastGPT v4.17.0版本的模型接入配置流程编写。

## 这个品类的数据长什么样
本品类的数据涵盖设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录。数据来源包括EAM/CMMS系统、设备传感采集数据、操作员手工点检记录、历史维修档案、备件库存数据及法定检验信息。更新节奏覆盖每班、日/周/月周期及故障突发场景，数据字段包含设备编号、额定功率、点检点位、实测参数、故障代码、备件型号等，附带明确的单位与状态标识。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求配置支持多文档并行召回，适配不同格式的点检记录、传感数据与工单档案。高频更新的实时传感数据与突发故障场景，要求模型接入配置支持低延迟响应，避免超时影响维修调度。设备字段附带的单位与专用代码，要求模型能准确识别并关联对应业务含义，需调整参数保证语义对齐。同时维修窗口需服从生产排产，配置需限制非必要的长上下文调用，避免占用过多资源影响并发。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配设备台账、点检记录、维修工单的批量拼接，覆盖多源业务文档的上下文需求 |
| `maxTokens` | 2000 token | 满足故障排查问答的输出长度，避免过长响应延误维修调度 |
| `quoteMaxToken` | 1500 token | 限制召回文档的引用长度，确保模型能聚焦核心业务字段与故障信息 |
| `temperature` | 0.3–0.5 | 保证业务回答的准确性，避免生成不符合设备参数规范的错误内容 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接口地址 | 适配企业内部网络环境，确保数据传输安全 |
| `AIPROXY_API_TOKEN` | 按实测标定的权限密钥 | 保证接口调用的合法性，避免未授权访问 |

## 容易做错的三处
- 模型测试返回上下文超限报错或空结果。原因：未根据品类的多源文档特征调整`maxContext`参数，导致传入的设备台账、点检记录等文档总长度超出配置上限。
- 共享页面并发超过设定阈值后无应答。原因：未结合设备点检场景的实时性需求，未合理设置`maxTokens`与接口响应参数，导致高并发下资源占用过载。
- 回答中出现错误的设备参数单位或非标准故障代码。原因：`temperature`参数设置过高，模型生成了不符合业务字段规范的内容，未准确匹配点检表、备件清单的业务标识。

## 怎么确认配好了
- 导入单份设备台账与点检表，测试模型能否准确提取设备编号、点检周期等核心字段，核对字段匹配度。
- 模拟突发故障场景发起查询，检查响应时长是否符合业务调度需求，确认未出现超时报错。
- 发起多并发测试，验证系统在业务峰值下能否稳定返回结果，调整参数适配并发要求。
- 若启用`vision`配置，上传设备传感数据图片，测试模型能否准确识别图片中的点检数值与异常标识。
