# 设备点检与预防维修的设备点检与维修问答：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据涵盖制造企业设备管理全链路内容，来源包括EAM/CMMS系统、设备传感采集数据、操作员点检记录、维修工单、故障分析报告、备件库存清单及特种设备检验记录。数据更新节奏覆盖每班点检提交、日周度保养计划更新、故障发生时的实时工单录入。文档结构包含结构化字段（如设备编号、点检温度、备件型号）与半结构化描述（如故障现象、维修步骤），字段附带专属单位，例如温度以℃为单位、库存以件为单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征对检索召回环节带来多重约束：首先，多源高频更新的数据要求检索系统支持增量刷新向量库，避免陈旧数据干扰结果；其次，结构化与半结构化混合的文档结构，需要检索模式适配不同字段的匹配逻辑，例如对设备编号的精确匹配与对故障描述的语义匹配；再者，专属字段与单位要求检索时需匹配对应标识，防止因单位不符引入无关结果；最后，故障处理的时效性要求，需控制检索耗时与结果条数，避免延误维修决策。

## 配置怎么定
本配置基于FastGPT v4.17.0版本，具体设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 相似度阈值 | 0.75–0.85 | 设备故障描述需较高精准度，过低会引入无关点检记录，过高会遗漏相似故障的有效结果 |
| 单次搜索上限 | 前8条 | 维修场景需快速定位核心信息，过多条目会增加token消耗，过少会遗漏关联故障记录 |
| 重排开关 | 开启 | 设备故障描述存在大量相似表述，重排可提升Top3结果的语义匹配准确率 |
| 查询扩展开关 | 开启 | 可补充点检、维修相关的同义词扩展，例如将“点检”扩展为“设备巡检”“日常检查”，覆盖更多专业表述 |
| 绑定知识库集合 | 仅绑定设备点检、维修相关的知识库 | 限定检索范围，避免引入其他品类的无关数据，确保结果仅来自本品类的业务文档 |
| 文档分块长度 | 800–1200字符 | 适配设备点检表、维修工单的典型内容长度，避免长文档无法生成有效向量 |

## 容易做错的三处
- 现象：检索返回数据过多导致token超出限制，原因：未设置单次搜索上限，或取值过高，引入了全量历史维修工单数据。
- 现象：非设备相关的闲聊问题仍返回结果，原因：未绑定专属知识库集合，或未开启查询扩展过滤逻辑，未过滤非设备点检相关的查询。
- 现象：长文档无法生成有效向量，原因：未按设备文档的典型长度设置分块参数，导致分块超出向量模型支持的长度限制。

## 怎么确认配好了
- 查看系统检索日志，确认返回结果仅来自绑定的专属设备点检、维修知识库，无跨品类数据混入。
- 测试非设备点检相关的闲聊查询，确认无匹配结果返回，过滤逻辑生效。
- 上传数千字的维修工单文档，确认向量生成成功，分块符合文档长度要求。
- 调整相似度阈值参数，验证召回结果的精准度符合设备故障排查的业务需求。
