# 过程质量与成品放行的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来自制造企业IPQC、FQC、质量工程与实验室团队的日常产出，包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单、质量月报等文档。数据来源覆盖MES系统、在线检测设备、实验室仪器、工艺参数库、客户标准库与历史缺陷库，更新节奏为每批生产、每班巡检后持续采集，文档结构以标准化检验项、异常记录、判定结论为核心字段，字段单位随具体检验项目、检测设备类型调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类数据的多源异构性要求多轮对话需适配不同格式的文档内容，提示词需明确区分在制品检验与成品放行的判定边界。高频更新的实时数据要求对话上下文需限制有效时长，避免过期的巡检记录或SPC报表干扰当前判定。标准化的检验项与历史缺陷库需通过提示词固定检索维度，确保多轮对话中能精准关联对应批次的检验数据。同时，不合格品评审与放行的权限关联要求对话中需明确传递当前批次的唯一标识，避免跨批次数据混淆。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类标准化文档的单检验项与异常记录长度，避免分块截断关键判定信息 |
| 单次召回上限 | 前6条 | 匹配本品类单批次检验相关的核心文档数量，减少冗余数据干扰对话上下文 |
| 上下文窗口 | 3000–4000 token | 覆盖单批次完整的检验记录、工艺参数与历史缺陷数据，确保多轮对话的信息完整性 |
| `messages` 上下文截断阈值 | 按实测标定 | 适配本品类高频更新的实时数据，避免过期的历史记录占用有效上下文 |
| 问题优化开关 | 开启 | 快速将用户的口语化点检问题转换为符合本品类标准的检索关键词，提升召回精度 |
| `variables` 变量绑定 | 绑定批次号、检验类型 | 确保多轮对话中精准关联当前生产批次的专属数据，避免跨批次混淆 |

## 容易做错的三处
- 现象：10几M的Word文档解析时加载超时，界面显示「请求超时」状态码。原因：未针对本品类的长文档调整分块参数，导致单块数据过大，解析与召回流程耗时过长。
- 现象：开启输入引导并配置自定义词库后，调试预览界面弹出报错提示，显示「参数格式错误」。原因：未按照本品类的检验项、放行流程关键词格式配置自定义词库，导致词库内容无法被系统正确解析。
- 现象：多轮对话中上下文丢失，后续提问无法关联前序的批次号信息。原因：未正确配置`chatId`参数，导致每次提问被识别为独立会话，无法保留历史对话上下文。

## 怎么确认配好了
- 上传单批次的成品检验报告与SPC报表，验证解析后的分块内容完整覆盖检验项与异常记录。
- 发起包含批次号的多轮提问，验证后续提问可关联前序的批次信息，上下文未丢失。
- 调整分块长度参数后，重新上传长文档，对比解析耗时变化，确认参数生效。
- 开启问题优化开关后，输入口语化点检问题，验证检索关键词自动匹配本品类的标准检验项。
