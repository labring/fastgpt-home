# 过程质量与成品放行的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据覆盖制造企业IPQC、FQC、质量工程与实验室的日常工作产出，包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审、放行单、质量月报等文档。数据来源包括MES系统、生产检测设备、实验室数据、工艺参数文件、客户标准及历史缺陷库，更新节奏按生产批次、每班频次持续采集，字段包含检验项、检测数值、判定结果、缺陷类型、放行权限标识等，无统一固定单位，随检测项目与客户标准动态调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且更新频繁，要求模型接入时需支持多源数据同步拉取，避免因数据滞后导致检验判定偏差。文档类型多样且字段动态变化，需配置适配非结构化文本的上下文处理规则，确保不同类型质检文档的信息提取准确性。历史缺陷库与实时检测数据关联度高，需限制单次上下文长度，防止冗余数据干扰模型推理。放行权限相关字段涉及生产合规，需严格配置模型调用的权限校验规则，避免敏感信息泄露或越权判定。

## 配置怎么定
本配置基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多份质检报告、SPC报表的拼接长度，避免因上下文溢出丢失关键检验数据 |
| `maxTokens` | 2000–3000 token | 平衡单轮推理速度与输出完整性，满足不合格品评审结论的详细描述需求 |
| `quoteMaxToken` | 1500 token | 限制引用源数据的长度，确保模型仅提取与当前检验判定直接相关的巡检记录、工艺参数内容 |
| `temperature` | 0.1–0.3 | 降低推理随机性，保障成品放行判定的一致性，符合质量管控的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接口地址 | 适配企业内部网络环境，确保数据仅在授权链路内传输，符合生产数据安全规范 |
| `AIPROXY_API_TOKEN` | 按企业权限体系生成专属令牌 | 限制模型调用权限，避免未授权访问敏感的放行权限、客户标准等数据 |

## 容易做错的三处
- 调用模型时返回`401 Unauthorized`报错，原因是未正确配置`AIPROXY_API_TOKEN`，或令牌权限未覆盖质检数据访问范围。
- 大模型输出的缺陷统计结果与SPC报表数值不一致，原因是`maxContext`取值过小，未完整引用多批次巡检记录的原始数据，导致推理时遗漏关键统计项。
- 模型无法准确识别不合格品评审中的指代性表述，原因是未启用问题优化配置，未在数据检索前完成指代消除与问题扩展，导致上下文指代对象不明确。

## 怎么确认配好了
- 发起针对单份成品检验报告的问答测试，验证模型能准确提取检验项、检测数值与判定结果。
- 调用模型接口查看返回的上下文引用日志，确认`quoteMaxToken`限制生效，仅返回指定长度的源数据片段。
- 模拟多源数据同步场景，检查模型是否能按时拉取最新的每班巡检记录与SPC报表数据。
- 验证`temperature`配置后，多次发起相同的不合格品评审问答，确认输出结果无明显随机偏差。
