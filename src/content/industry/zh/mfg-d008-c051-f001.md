# 金属切削加工的设备点检与维修问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
金属切削加工的业务数据来源包括产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES系统及量检具数据。日常维护相关文档涵盖工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表、量具校准记录。数据更新频率随工单、单件产品、抽检批次或刀具更换触发。数据字段包含机床编号、刀具磨损量、工序尺寸偏差、数控程序版本号等，单位涵盖毫米、转每分钟、分钟等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源异构的数据来源要求接口兼容不同系统的字段格式，需支持从刀具管理系统拉取刀具磨损数据、从MES拉取工单信息。高频更新的特性要求接口支持增量拉取或实时同步，避免重复传输全量数据。多类型文档（如数控程序、工艺路线）的体积差异大，要求接口支持大文件分片传输。业务出错后果严重，要求接口的认证、超时配置需符合工业系统的安全与可靠性要求。

## 配置怎么定
本文档基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | Bearer {FastGPT平台分配的API密钥} | 符合工业系统的安全认证规范，避免明文传输敏感信息 |
| `variables` | 绑定机床ID、刀具编号、工单编号等业务变量 | 匹配金属切削加工的工单数据，让问答结果贴合当前生产场景 |
| `responseData` | 返回点检结果、维修建议、关联工序卡ID、刀具清单ID | 贴合设备点检与维修的业务需求，直接输出可落地的业务信息 |
| 请求超时时间 | 10–60 秒 | 适配数控程序、工艺路线等文档的加载时长，避免因大文件传输触发超时 |
| 多文件传参配置 | 按messages数组嵌套content数组格式传递 | 支持同时上传巡检表、量具校准记录等多类型文档 |
| 认证刷新周期 | 按实测标定 | 适配企业内部系统的令牌过期规则，避免认证失效 |

## 容易做错的三处
- 现象：接口请求超过1分钟后触发超时，返回504状态码。原因：未根据金属切削加工的大体积数控程序、工艺路线等文档的加载时长调整超时配置，沿用通用默认阈值。
- 现象：`responseData`返回的维修建议未匹配当前工单的刀具信息，字段缺失。原因：未将机床采集的刀具磨损数据、工序卡信息注入`variables`变量，导致问答结果脱离实际生产场景。
- 现象：多文件上传时接口报错，巡检表、量具校准记录等文档未被正确识别。原因：未按正确的嵌套格式传递content数组内的文件信息，不符合接口的传参规范。

## 怎么确认配好了
- 调用接口传入测试工单ID，检查返回的`responseData`是否包含关联的工艺路线、刀具清单等业务字段。
- 发起未携带有效`Authorization`的请求，确认接口返回401未授权状态码，验证认证配置生效。
- 上传多份数控程序、巡检表文件，确认接口能正确接收并解析所有文件内容。
- 发起持续50秒的模拟请求，确认超时配置未触发异常，符合业务文档的加载需求。
