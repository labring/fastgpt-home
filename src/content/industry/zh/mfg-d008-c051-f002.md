# 金属切削加工的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据来源包括产品图纸与三维模型、CAPP/CAM系统、机床采集数据、刀具管理系统、MES系统及量检具记录。文档类型涵盖工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表与量具校准记录。更新频率随工单、单件加工或抽检、刀具更换触发，包含结构化字段与非结构化文本两类内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
混合类型的数据结构要求分块策略兼顾结构化字段的完整性与非结构化文本的上下文连贯性。高频更新的特性要求索引支持增量同步，避免全量重建带来的资源消耗。行业特有的专业术语与格式要求分块不能过细，防止拆分专业代码段；同时需适配主流向量模型的token限制，避免单块内容超出输入上限。不同文档的粒度差异较大，数控程序单段可达数百字符，而巡检表仅数十字符，固定分块参数易出现内容截断或冗余。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配金属切削文档的混合内容，避免数控程序的连续G代码被截断，同时控制单块token数不超过主流向量模型的`maxToken`限制 |
| 重叠长度 | 100–200 字符 | 保留跨块的专业术语与代码上下文，防止刀具型号、异常描述等关键信息被拆分 |
| maxToken | 1024 | 匹配指定向量模型的输入token上限，避免向量化过程中出现内容截断异常 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的点检异常描述，结合金属切削场景的异常特征精准召回相关文档 |
| 单次搜索上限 | 前8条 | 平衡召回覆盖率与响应速度，适配车间场景的快速问答需求 |
| defaultToken | 512 | 控制问答上下文的总token数，避免超出部署模型的上下文窗口 |

## 容易做错的三处
- 上传10M以上的数控程序文件后，系统提示部分chunk向量化异常，反复点击重试仍无法完全恢复 | 原因是分块长度设置未匹配`maxToken`限制，连续的G代码片段超出模型输入token上限，触发向量化失败，重试仅重置临时缓存，未修正根本配置问题
- 导入Excel格式的工序卡后，检索刀具磨损相关问题时召回结果混乱 | 原因是未针对结构化表格数据设置合理的分块规则，导致表头字段与对应数据行被错误拆分，专业字段的上下文关联被破坏
- 本地部署ollama后，设备点检问答的响应速度过慢 | 原因是未限制问答上下文的`defaultToken`长度，导致模型需要处理过多冗余的历史数据，超出本地CPU的推理能力

## 怎么确认配好了
- 上传单份典型文档（如完整数控程序），查看分块预览界面，确认连续的G代码段未被无意义截断
- 输入刀具磨损、尺寸漂移等典型点检问题，检查召回的chunk是否包含对应的工序卡、刀具清单或巡检表内容，匹配度符合预期阈值
- 在本地服务器上执行批量向量化测试，确认无连续的向量化异常报错
- 查看问答上下文的token消耗记录，确认未超出部署模型的上下文窗口限制
