# 钢材轧制与精整的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类主体为热轧、冷轧、型钢、钢管生产企业，日常数据涵盖轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书等文档。数据来源包括板坯或钢坯批次信息、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置及MES系统，更新频率为每卷或每支钢产品实时更新。文档包含温度参数、压下量、板形偏差、缺陷等级等字段，单位随对应生产指标而定，如温度以摄氏度计、厚度以毫米计。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时且按卷/支更新的数据要求索引支持增量更新，避免全量重建带来的性能损耗；多类型文档（长规程与短记录）并存的特征，要求分块策略适配不同文本长度，避免关键业务信息被截断；数据来自多台产线设备与MES系统，存在字段格式差异，要求预处理环节对齐字段标准；卷级追溯的业务需求，要求索引关联批次ID等关键标识，便于按生产批次召回关联数据；设备点检与维修的实时问答场景，要求向量召回的响应速度匹配产线运维的时效性要求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定，适配钢材轧制与精整品类的设备点检维修问答场景：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `defaultToken` | `8192 tokens` | 适配该品类轧制规程、质检报告等长文本的编码需求，避免超出模型输入上限 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 分块长度 | 800–1200 字符 | 适配该品类文档的平均长度，避免分块过碎导致上下文断裂，或过长导致编码失真 |
| 重叠长度 | 100–200 字符 | 保留分块间的轧制批次、温度参数等关键上下文关联，避免关键信息被截断 |
| 相似度阈值 | 0.72–0.80 | 匹配设备点检与维修相关的问题与文档，减少无关召回结果 |
| 单次搜索上限 | 前 8 条 | 平衡召回精度与响应速度，适配产线运维的实时问答需求 |

## 容易做错的三处
- 现象：调用embedding模型时出现503状态码报错，提示当前分组default下对于模型text-embedding无可用节点。原因：未配置专属的embedding模型分组，或分组内的模型节点未正常上线，导致调用请求无法被正确路由。
- 现象：Docker部署的知识库持续处于索引中状态，无进度更新。原因：接入的外部embedding模型网络连接不稳定，或索引分块设置过大，导致单批次索引任务耗时过长未完成。
- 现象：召回的设备点检结果与问题匹配度偏低，或出现大量炼钢工序相关的无关文档。原因：相似度阈值设置不合理，或未针对该品类的文档类型调整分块策略，导致向量编码无法准确匹配业务关键词。

## 怎么确认配好了
- 查看向量模型调用日志，确认无503、超时类报错，验证embedding模型接口调用正常。
- 手动上传一份轧制规程或质检报告文档，查看索引进度是否在合理时间内完成，确认增量索引逻辑生效。
- 输入设备点检相关的问题，核对召回结果的数量与匹配度，调整相似度阈值至符合业务需求的区间。
- 查看索引后的文档关联信息，确认卷号、批次ID等关键字段被正确嵌入向量，便于后续按生产批次追溯查询。
