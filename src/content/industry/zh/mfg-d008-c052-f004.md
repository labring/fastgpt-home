# 钢材轧制与精整的设备点检与维修问答：工作流编排

## 这个品类的数据长什么样
该品类数据来源于板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测系统与MES系统。日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书，字段涵盖批次号、加热温度、轧制速度、板形偏差值、缺陷类型等，单位包含摄氏度、米每秒、毫米等。数据更新频率为每卷或每支，部分关键运行参数实时同步。

## 这些特征在「工作流编排」这一环带来什么约束
该品类数据按卷/支维度生成且实时更新，要求工作流触发需绑定轧制批次的专属事件，采用触发式执行。结构化的工艺与质检参数要求工作流的变量需精准映射批次维度的字段，避免跨批次数据混淆。设备点检与维修需关联具体生产设备，要求工作流节点绑定对应设备的ID标识，同时需预留足够的接口调用时间以适配多系统协同的延迟。出错会导致钢卷降级、设备损伤等后果，要求工作流配置失败重试机制，降低异常中断风险。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定当前轧制批次的板坯号、加热温度、轧机型号 | 该品类数据按卷/支维度生成，需关联批次专属参数，避免数据混淆 |
| `nodeId` | 绑定加热炉、轧机、表面检测设备的对应节点ID | 设备点检需精准关联生产现场的实际设备，确保维修问答指向正确对象 |
| 触发时机 | 按轧制批次完成点检任务后触发 | 匹配数据每卷或每支的更新频率，避免无效执行 |
| 重试次数与间隔 | 3次，间隔120秒 | 设备临时异常可通过重试恢复，降低单次调用失败风险 |
| 超时阈值 | 600秒 | 适配跨MES与设备系统的接口响应时长，避免接口中断错误 |
| 上下文范围 | 仅包含当前批次的工艺与质检数据，范围限定为前800-1200字符，按实测标定 | 缩小检索范围，提升维修问答的准确性 |

## 容易做错的三处
- 现象：工作流节点返回Premature close错误，原因：未配置合理的超时阈值，导致接口响应超时被中断。
- 现象：节点输出的`variables`无法正确写入外部系统，原因：未绑定当前轧制批次的专属字段，导致变量映射不匹配。
- 现象：工作流调用搜索工具无有效结果，原因：未限定搜索范围为该品类的工艺文档与设备手册，检索结果与场景无关。

## 怎么确认配好了
本页面配置适用于FastGPT v4.17.0版本。
- 查看`variables`配置是否包含当前轧制批次的板坯号、加热温度等专属字段。
- 验证`nodeId`是否对应生产现场的加热炉、轧机等实际设备节点。
- 触发测试工作流，确认其按轧制批次完成点检任务后触发执行。
- 模拟跨系统接口调用，检查超时阈值设置符合系统响应时长要求。
