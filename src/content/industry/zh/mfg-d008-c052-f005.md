# 钢材轧制与精整的设备点检与维修问答：工具调用与插件

## 这个品类的数据长什么样
该品类的数据来源于板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与制造执行系统（MES）。数据更新节奏为每卷或每支钢材对应一次更新，部分在线检测数据为实时更新。日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告与质保书，字段包含批次号、卷号、厚度（单位毫米）、轧制速度（单位米每秒）与缺陷类型等。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类通过连续塑性变形控制几何和组织，卷级追溯特征明显，要求工具调用需支持按批次ID关联检索多源设备数据，避免跨卷数据混淆。多类型工艺与检测文档的结构差异，要求工具调用需适配不同字段的格式解析，保障维修问答的参数准确性。单卷数据量有限但更新频繁的特点，要求工具调用需优先拉取实时更新的在线检测与MES数据，不依赖静态缓存。严重的出错后果要求工具调用需增加参数校验环节，防止错误调用导致设备数据误匹配。

## 配置怎么定
本文基于FastGPT v4.17.0版本配置规则，具体配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | auto | 需要根据点检问题自动匹配对应的设备数据检索工具，适配实时更新的轧制与精整设备参数 |
| `functionCall` | 按实测标定 | 部分复杂维修问题需要强制调用指定工具，可根据实际场景调整 |
| 单次工具调用上限 | 前3条 | 单卷/单支钢材的关联数据条目有限，过多调用会增加响应延迟 |
| 工具调用超时时间 | 600秒 | 设备数据检索涉及多源MES与在线检测数据，需要充足时间完成跨源调用 |
| 上下文窗口大小 | 8000–12000 token | 需要承载轧制计划、加热制度等多份文档的上下文信息，保障问答逻辑连贯 |
| 工具调用数据预处理 | 启用 | 需要对检索到的板形厚度记录等数据进行转义处理，避免格式错误 |

## 容易做错的三处
- 现象：工具调用返回Invalid JSON报错，包含控制字符错误。原因：未启用工具调用数据预处理开关，检索到的板形厚度记录中存在未转义的换行符或制表符，直接传入工具调用参数。
- 现象：配置联网搜索工具后响应为空。原因：轧制与精整的设备维修问题多依赖内部工艺与检测数据，未配置内部设备知识库关联，导致搜索无匹配结果。
- 现象：工具调用节点执行超时。原因：未根据多源数据检索的需求调整超时时间，使用默认时长无法完成跨MES与在线检测系统的数据拉取。

## 怎么确认配好了
- 发起一条针对热轧板卷表面缺陷的点检问题，检查工具调用日志中是否自动匹配到对应的设备数据检索动作。
- 触发一次维修问答请求，确认返回结果中包含轧制规程、加热制度等品类专属文档的关联内容。
- 模拟包含未转义字符的输入，检查工具调用是否触发数据预处理环节，无格式报错。
- 查看工具调用的耗时统计，确认未超过预设的超时时间阈值。
