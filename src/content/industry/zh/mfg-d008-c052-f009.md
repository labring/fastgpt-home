# 钢材轧制与精整的设备点检与维修问答：模型接入与配置

本文档适用于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
本品类数据来源于板坯或钢坯批次记录、加热炉运行参数、轧机自动控制系统、在线测厚测宽设备、表面检测系统及MES系统。数据更新节奏为每卷或每支钢料实时生成，日常文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书。数据字段包含轧制温度、压下量、板形偏差、表面缺陷类型等，对应单位为摄氏度、毫米、米每秒等。

## 这些特征在「模型接入与配置」这一环带来什么约束
实时高频的单卷/单支钢料数据，要求模型接入配置适配短延迟调用，避免超时影响点检响应速度；卷级关联的全链路文档与批次数据，要求上下文长度配置匹配单卷数据的总字符量，确保模型能完整调用单卷的全链路点检与维修数据；多源异构的设备运行、在线检测数据，要求配置中明确工具调用权限，支持从不同数据源召回对应点检与维修文档；实时更新的参数需要配置支持动态同步知识库，确保模型调用时使用最新的加热、轧制参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | `http://192.168.1.100:11434/v1` 或对应oneAPI转发地址 | 匹配钢材轧制场景下本地部署的deepseek8b等模型的实际访问路径，适配oneAPI或ollama的转发规则 |
| `AIPROXY_API_TOKEN` | 本地模型访问密钥，如`ollama`或oneAPI生成的令牌 | 用于验证模型调用权限，适配本地部署模型的认证要求 |
| `maxContext` | 8000–12000 token | 匹配单卷钢料的轧制、质检文档总字符量，确保模型能完整调用单卷的全链路点检与维修数据 |
| `maxTokens` | 2000–3000 token | 限制单次维修问答的输出长度，避免超出设备点检场景的响应时效要求 |
| `quoteMaxToken` | 1000–2000 token | 限制单条召回文档的最大字符量，确保模型可同时关联多份关联文档 |
| `temperature` | 0.3–0.5 | 降低随机输出，确保维修建议与轧制规程、历史点检记录的一致性 |

## 容易做错的三处
- 测试调用时报权限错误或404状态码，原因是未正确配置`AIPROXY_API_TOKEN`，或`AIPROXY_API_ENDPOINT`未匹配本地模型的实际访问路径，导致认证失败或地址不匹配。
- 工作流中调用模型无法生成流式输出结果，原因是未在模型配置中启用流式响应选项，或代码运行模块未正确处理模型返回的流式数据格式。
- 问答结果未关联单卷钢料的历史点检记录，原因是`maxContext`或`quoteMaxToken`配置过小，无法召回足够的关联文档，导致模型无法参考完整的维修历史数据。

## 怎么确认配好了
- 执行模型连通性测试，观察界面返回的响应状态，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置可正常调用模型。
- 输入单卷钢料的典型点检问题，核对模型输出是否关联了对应轧制规程与历史维修记录，确认上下文与召回参数的配置可覆盖所需文档范围。
- 测试多轮问答的响应延迟，确认输出长度配置符合设备点检场景的时效要求。
- 查看知识库同步日志，确认实时更新的轧制与质检数据已正确同步至模型调用的知识库中。
