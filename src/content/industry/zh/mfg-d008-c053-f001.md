# 钢铁冶炼与连铸的设备点检与维修问答：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据来源于铁水与废钢采集系统、L2过程控制终端、化验室检测系统、制造执行系统（MES）、能源介质监控平台及设备状态监测装置。日常文档包含炉次计划、配料单、转炉冶炼记录、成分分析报告、连铸工艺参数记录、板坯质量判定单。数据更新节奏覆盖每炉次生成、实时推送及每班汇总归档，字段包含铁水温度、冶炼终点成分、连铸拉速、设备运行时长等，对应单位为摄氏度、百分比、米每分钟、小时。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
钢铁冶炼与连铸的实时性与炉次绑定特性，要求HTTP接口需支持低延迟数据拉取与单炉次精准查询。多源异构数据接入的需求，要求接口需兼容不同工业系统的字段格式，避免数据解析错误。高温连续流程无法停机的特性，要求接口具备重试机制与断点续传能力，防止单次请求失败影响炉次调度节奏。每班汇总的归档数据需求，要求接口支持按时间范围批量查询，适配调度部门的日常报表生成。板坯判定单等大尺寸质量文档的传输，要求接口支持多字段组合或大文件请求体，满足复杂数据传递需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 请求超时时间 | 30–60 秒 | 适配实时炉次数据的拉取延迟要求，避免阻塞生产流程 |
| 授权凭证配置 | `Authorization` 头携带固定令牌 | 符合FastGPT v4.17.0的工业场景安全配置规范 |
| 上下文变量绑定 | `variables` 绑定炉次号、浇次号参数 | 精准匹配单炉次或单浇次的设备点检与维修数据查询 |
| 响应数据处理 | `responseData` 过滤非必要字段并保留原始单位 | 适配内部MES系统的字段格式要求，减少数据转换开销 |
| 批量请求上限 | 前 20 条记录 | 平衡数据传输效率与生产系统的负载压力 |
| 单文件上传上限 | 1000 MB | 适配连铸工艺记录等大尺寸文档的传输需求 |
| 重试次数 | 3 次 | 应对临时网络波动，避免单次请求失败影响炉次调度 |

## 容易做错的三处
- 现象：接口无法接收多张图片或PDF文件，返回参数缺失报错。原因：未配置多文件上传的接口支持，未适配设备点检现场的多模态数据传输需求。
- 现象：接口返回状态码413，请求体字段为空。原因：未调整单请求数据量上限，超出接口允许的传输限制。
- 现象：流式响应中断，无法获取完整的设备维修问答结果。原因：未配置正确的流式传输参数，未适配工业场景下的长上下文问答需求。

## 怎么确认配好了
- 发起单炉次数据的查询请求，核对返回字段与内部MES系统的字段格式一致。
- 模拟临时网络中断，验证接口的重试机制是否正常触发并恢复数据获取。
- 上传符合生产文档格式的测试文件，确认接口可正常接收并返回处理结果。
- 配置批量请求参数，核对返回的记录条数与预设的批量上限匹配。
