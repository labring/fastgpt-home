# 钢铁冶炼与连铸的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自铁水与废钢采集系统、L2过程控制节点、化验室检测系统、MES生产管理系统、能源介质监控平台及设备状态传感器。日常文档包含炉次计划、配料单、转炉冶炼记录、成分分析报告、连铸工艺参数记录、板坯质量判定单。数据更新节奏按炉次、实时或每班触发，单份文档包含工艺参数、成分数值、设备运行状态等字段，单位涵盖温度、流量、成分占比等工业标准单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
数据按炉次批量更新且实时性要求高，要求索引支持增量更新，避免全量重建导致的高温连续流程中断。多源异构数据格式差异大，需统一字段映射后再进行向量化，防止语义检索出现偏差。炉次与浇次强耦合的业务逻辑，要求索引关联炉次、浇次、设备编号等关联字段，确保检索结果匹配实际业务场景。单份文档包含大量连续工业参数，需限制单块向量化文本的长度，避免超出模型的处理上限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 单份炼钢记录包含多组连续工艺参数，分块过长会破坏语义连贯性，过短会丢失工艺关联逻辑，按工业文档结构实测标定 |
| 重叠长度 | 50–80 字符 | 炉次数据存在跨块的工艺衔接逻辑，重叠长度覆盖关键衔接参数，避免语义断裂 |
| 相似度阈值 | 0.72–0.85 | 钢铁设备点检问题多涉及精准参数匹配，阈值过低会引入无关设备记录，过高会遗漏匹配结果，按业务场景实测标定 |
| 单次搜索上限 | 前 10 条 | 单炉次相关设备记录数量有限，过多结果会超出上下文窗口，影响模型推理准确性 |
| maxToken | 4096 token | 匹配FastGPT v4.17.0的默认模型支持上限，结合钢铁工艺文档的平均长度设置 |
| defaultToken | 2048 token | 适配常规点检问题的输入长度，确保检索请求的语义嵌入完整 |

## 容易做错的三处
- 向量库仅存储向量字段，无法关联原始文档文本，检索结果无法溯源验证具体工艺记录。原因：未配置原始文档与向量的关联存储逻辑，仅将向量数据写入向量数据库，未保留原始文本的关联索引。
- 使用bge-m3向量模型时，语义检索返回的相似度分值普遍偏高，超出正常业务区间。原因：未对多源异构数据的字段格式与单位进行统一映射，原始数据的单位差异导致嵌入向量的语义偏差被放大。
- 索引状态显示同步完成，但检索时无法匹配到对应炉次或设备的相关数据。原因：增量更新配置未绑定炉次、浇次、设备编号等关键业务字段，仅同步了非业务相关的系统日志，未覆盖核心业务文档。

## 怎么确认配好了
- 查看向量数据库存储内容，确认原始文档文本与向量字段同时存在，核对关联字段是否匹配业务数据。
- 输入典型点检问题，检索返回结果的相似度分值分布，调整阈值至符合业务需求的区间。
- 触发一次炉次数据更新，查看索引日志是否记录增量同步记录，确认关联字段已正确绑定。
- 测试检索模板与常规问答流程，确认两者返回结果的一致性，验证模板配置的适配性。
