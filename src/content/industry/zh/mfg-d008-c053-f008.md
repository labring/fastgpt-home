# 钢铁冶炼与连铸的设备点检与维修问答：文档解析与分块

## 这个品类的数据长什么样
本品类数据来自铁水与废钢数据、L2过程控制系统、化验室、MES系统、能源介质系统与设备状态监测模块。数据更新节奏覆盖每炉次、实时与每班周期。日常文档包含炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单，字段包含工艺参数、设备运行状态、检测结果，对应单位包括摄氏度、吨、米每分钟等。

## 这些特征在「文档解析与分块」这一环带来什么约束
多更新节奏的文档要求分块逻辑兼容短实时日志与长周期报表，避免适配成本过高。专业工艺字段与设备状态的关联需要分块保留上下文，防止拆分破坏工艺逻辑，影响后续检索准确性。单炉次文档的连续工艺记录可能超出理想分块长度，需调整分块规则适配长文本。同时，大体积的连铸工艺文档会增加解析耗时，需设置合理的超时与大小限制，避免任务中断影响业务流程。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配钢铁冶炼与连铸场景的文档解析与分块需求：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配单炉次工艺记录的字段关联长度，避免拆分破坏工艺逻辑 |
| `chunkSplitter` | 按固定分隔符+语义分段 | 匹配炉次计划、冶炼记录的结构化分段规则，保留工艺上下文 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大体积连铸工艺文档的解析耗时，避免超时中断任务 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 容纳单批次的多炉次汇总文档，满足批量上传需求 |
| `customPdfParse` | 开启结构化解析 | 适配转炉冶炼记录、成分报告的表格型文档，提取精准字段 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型调整分块参数，适配多更新节奏的数据特征 |

## 容易做错的三处
- 上传10几MB的PDF文档时提示超时错误。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认值不足以覆盖大体积连铸工艺文档的解析耗时。
- 个别DOCX文档无法完成解析。原因是未开启`customPdfParse`的兼容模式，无法识别钢铁行业文档中的非标表格与字段格式。
- 长工艺记录分段未被正确截断。原因是未配置`chunkSize`的合理区间，或未启用语义分段规则，导致超过长度的分段未被拆分。

## 怎么确认配好了
- 上传单份100MB以上的连铸工艺记录文档，检查解析任务是否在600秒内完成。
- 上传包含多炉次数据的配料单，检查分块结果是否保留单炉次的完整字段关联。
- 开启`customPdfParse`后，上传转炉冶炼记录PDF，检查解析结果是否提取出完整的成分与温度字段。
- 调整`chunkSize`为800字符，上传单段1500字符的工艺日志，检查分块结果是否被截断为两段并保留上下文。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
