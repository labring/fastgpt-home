# 钢铁冶炼与连铸的设备点检与维修问答：模型接入与配置

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
本品类数据来自钢铁联合企业炼铁、炼钢、连铸、质量与调度部门的多系统输出，日常文档包含炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单。数据来源覆盖铁水与废钢数据、L2过程控制数据、化验室检测结果、MES系统、能源介质系统及设备状态监测数据，更新节奏涵盖每炉次、实时及每班更新，数据字段包含炉次编号、成分含量、工艺参数、设备运行状态等，单位随对应文档场景灵活设定。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据的多源高频更新特性，要求模型接入时需适配实时同步与批量同步结合的知识库更新机制，避免检索到过期数据。多类型文档的字段差异与灵活单位设定，要求配置时需明确检索的文档范围与字段过滤规则，防止无关数据干扰问答结果。高温连续生产的业务属性，要求模型响应需控制在合理时长内，避免影响现场点检与维修决策的时效性。同时炉次与浇次的强耦合性，要求检索结果需关联对应炉次的完整工艺数据，需配置上下文关联逻辑以匹配业务场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 本品类单炉次完整工艺数据量较大，需覆盖多份关联文档的上下文，同时避免超出模型承载上限 |
| `maxTokens` | `4000–6000 token` | 设备点检与维修问答需简洁输出，同时保留足够上下文用于关联炉次、工艺及设备数据 |
| `quoteMaxToken` | `1500–2000 token` | 限制单条引用文档的长度，防止检索内容过长导致重排模型无法触发，适配现场问答的紧凑需求 |
| 工作流/API 工具选择配置 | `auto` | 让模型自主选择是否调用检索工具，适配点检、维修、工艺查询等多场景问答需求 |
| `temperature` | `0.2–0.4` | 设备维修与点检问答需严谨准确，降低随机性以保证输出的业务一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务内网地址填写 | 适配钢铁企业内网部署的安全要求，避免敏感数据外流 |

## 容易做错的三处
- 现象：模型响应时长超过预设阈值，日志显示检索环节耗时占比过高。原因：未合理限制`maxContext`取值，导致上下文窗口过大，模型加载与检索资源占用过高，无法满足现场实时决策的时效要求。
- 现象：重排模型部署测试通过，但实际检索时返回重排结果为`false`。原因：未配置`quoteMaxToken`限制单条引用长度，检索内容超出重排模型的输入上限，导致重排逻辑未触发。
- 现象：无法正常加载Qwen3-Reranker-8B重排模型。原因：未在模型接入配置中添加对应重排模型的注册信息，或未匹配模型的输入输出格式要求。

## 怎么确认配好了
- 执行一次针对转炉设备点检的问答，查看返回结果是否关联了对应炉次的冶炼记录与设备状态数据，确认上下文配置生效。
- 上传一份超过预设长度的连铸工艺记录文档，触发检索流程，检查重排模型是否正常返回排序结果，确认`quoteMaxToken`配置合理。
- 查看模型服务的资源占用日志，确认响应时长符合现场作业的时效要求，按需调整`maxContext`与`maxTokens`的取值范围。
- 检查API接口的调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无连接超时或权限报错。
