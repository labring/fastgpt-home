# 钢铁冶炼与连铸的设备点检与维修问答：知识库检索与召回

## 这个品类的数据长什么样
数据来源涵盖铁水与废钢投料数据、L2过程控制实时数据、化验室成分报告、MES生产调度数据、能源介质系统数据及设备状态监测数据。日常文档包含炉次计划、配料单、转炉冶炼记录、连铸工艺记录、板坯判定单等，字段包含炉次号、浇次号、钢水温度、元素成分、设备编号、点检时间等。更新节奏覆盖每炉次生成的冶炼记录、实时更新的设备状态数据，以及每班生成的板坯判定单，数据结构以结构化字段为主，部分记录包含多维度关联信息。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多来源、多更新节奏的数据要求检索系统支持增量同步与按数据源过滤，避免离线文档与实时数据的匹配冲突。炉次与浇次的强耦合关联，要求检索时需支持按炉次号、浇次号等关联字段进行精准过滤，防止召回无关炉次的文档。高温连续生产的特性要求检索过程不占用生产系统资源，且响应速度需匹配现场调度的实时性需求。结构化字段多且精度要求高，需避免低匹配度的冗余结果干扰点检维修的决策，同时需保证召回结果的字段与业务场景匹配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.82 | 钢铁冶炼与连铸的业务文档字段精度要求高，需过滤低匹配度的冗余记录，避免干扰点检维修的决策参考 |
| `limit` | 前8–12条 | 单炉次或连铸浇次的关联文档数量有限，过多召回会超出模型上下文窗口，影响输出准确性 |
| `usingReRank` | 开启 | 设备点检与维修的问题多涉及多字段关联，重排可提升高匹配度文档的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 现场点检人员的提问多为口语化描述，问题优化可将口语化表述转换为匹配结构化文档的关键词 |
| `searchMode` | 精准匹配模式 | 钢铁冶炼数据的唯一性强（如炉次号、设备编号），精准匹配可快速定位目标文档 |
| `collectionIds` | 按数据源分组指定 | 区分转炉冶炼记录、连铸设备点检等不同业务数据集，避免跨品类数据干扰检索结果 |

## 容易做错的三处
- 现象：知识库检索步骤返回了匹配结果，但最终生成的回答未包含检索内容。原因：未正确配置`usingReRank`或`limit`参数，导致召回的文档超出模型上下文窗口，或重排后高匹配文档被过滤。
- 现象：本地测试检索正常，但通过发布渠道调用时无法返回知识库内容。原因：未在发布渠道配置关联的知识库集合ID，或`collectionIds`参数未包含对应业务数据集的ID。
- 现象：检索返回的结果中包含段落内部ID字段。原因：未关闭段落ID的输出开关，或在配置时未排除非业务字段的元数据。

## 怎么确认配好了
- 手动输入典型点检维修问题，比如“连铸结晶器漏水的排查步骤”，核对检索返回的文档是否包含连铸工艺记录、设备点检记录，且匹配度符合`similarity`设定的阈值范围。
- 切换到FastGPT v4.17.0的外部发布渠道，发起相同的点检问题，核对返回的回答是否包含检索到的业务文档内容，与本地测试结果一致。
- 查看检索日志，核对召回的文档数量是否在`limit`设定的范围内，且未包含无关的段落ID字段。
- 模拟新增一条实时设备状态数据，核对知识库是否能同步召回该新文档，验证增量更新的配置有效性。
