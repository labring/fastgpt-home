# 钢铁冶炼与连铸的设备点检与维修问答：表单与交互

## 这个品类的数据长什么样
钢铁冶炼连铸的业务数据来源于铁水与废钢台账、L2过程控制系统、化验室检测数据、MES系统、能源介质系统与设备状态监测装置。日常生成的业务文档包含炉次计划、配料单、转炉冶炼记录、成分报告、连铸工艺记录、板坯判定单等。数据更新节奏随单炉次完成实时更新，每班汇总归档，字段覆盖炉次编号、冶炼时长、设备运行参数、成分检测值等核心信息。

## 这些特征在「表单与交互」这一环带来什么约束
由于业务数据按炉次组织且更新频率高，表单需支持按炉次号快速检索关联文档，避免手动输入的冗余操作。多类结构化文档的联动需求，要求表单支持字段联动，选择某类文档后自动带出对应关联字段。高温连续流程无法随意停机的特性要求交互步骤精简，减少点检人员的操作时间。同时，出错后果严重，表单需设置必填项校验，防止漏填关键检索条件导致无效查询。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `formInput` | 关联炉次号作为默认检索关键词 | 钢铁冶炼连铸的业务数据按炉次组织，可快速定位对应炉次的工艺、设备文档 |
| userSelect | 预设点检岗位、设备类型选项，支持多选 | 匹配炼铁、炼钢、连铸等不同岗位的点检查询需求 |
| 单次搜索上限 | 前10条 | 减少冗余结果，适配流程工业多源数据的检索场景 |
| 最大上下文 | 8000–12000 token | 覆盖炉次计划、冶炼记录、设备状态等多份关联文档的完整上下文 |
| 响应超时阈值 | 600 秒 | 适配钢铁冶炼连铸流程的实时数据检索需求，避免长时间等待 |
| 文件上传大小限制 | 1000 MB | 适配单份炉次计划、连铸工艺记录等文档的上传需求 |
| 文件上传格式 | 默认启用全部支持的格式 | 适配对接MCP导入各类业务文档的需求 |

## 容易做错的三处
- 现象：配置文件上传时未默认启用全部格式，导致对接MCP时无法自动识别配料单、连铸工艺记录等文档格式。原因：未将文件上传格式配置为默认全选，仅手动勾选部分格式。
- 现象：添加外部模型调用的配置后，输入密钥时报空错误。原因：未正确配置模型的API地址与密钥校验规则，或密钥未携带正确的权限标识。
- 现象：代码运行节点中无法选择知识库引用的变量。原因：未在表单交互环节提前绑定知识库检索结果作为全局变量，或变量作用域配置错误。

## 怎么确认配好了
- 输入任意已知炉次号，检查表单是否自动带出对应炉次的关联文档检索结果。
- 上传一份转炉冶炼记录文档，检查文件上传组件是否自动识别格式并完成上传。
- 调用模型查询某连铸设备的点检问题，检查是否能正常调用绑定的知识库并返回结果。
- 测试炉次号字段为空时提交表单，检查是否触发必填项校验提示。
