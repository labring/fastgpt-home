# 铸造（砂型、精密、压铸）的设备点检与维修问答：文档解析与分块

## 这个品类的数据长什么样
该品类的日常文档包含铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告、不合格品评审单。数据来源涵盖ERP物料主数据、熔炼炉与测温仪、光谱仪、MES炉次记录、模具管理系统及客户图纸。更新频率为每炉次、每批或每日，文档包含合金配料比例、熔炼温度、浇注参数、缺陷类型与对应炉次模次等字段，单位涉及重量百分比、摄氏度、毫米等。

## 这些特征在「文档解析与分块」这一环带来什么约束
每炉次、每批更新的炉次记录、配料单等文档更新频繁，要求分块工具支持高频增量解析。多类文档混合存在结构化字段与非结构化描述，需分块时保留字段关联性，避免拆分破坏配料比例、缺陷追溯的关联逻辑。模具履历、材质报告等文档存在固定格式的表头与明细行，需适配结构化解析以提取关键字段。跨来源的数据格式差异大，需配置灵活的分块规则适配不同文档类型，同时保证缺陷与炉次、模次的关联信息不被割裂。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配铸造类文档的字段长度与关联逻辑，避免拆分破坏配料比例、缺陷追溯的完整信息 |
| `chunkSplitter` | 按语义分块 | 适配工艺卡、炉次记录等混合结构化与非结构化的文档，保留内容关联性 |
| `customPdfParse` | 启用结构化解析 | 适配模具履历、材质报告等固定格式文档，精准提取表头与明细字段 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 覆盖单批次炉次记录、模具履历等批量上传文档的尺寸上限 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配熔炼数据、光谱仪导出的大体积日志文件的解析耗时 |
| `chunkSettingMode` | 手动配置 | 针对配料单、缺陷评审单等不同文档类型调整分块规则，适配业务需求 |

## 容易做错的三处
- 上传音视频文件后解析失败，提示不支持的文件格式。原因是未配置对应多媒体解析规则，且未启用非文档类文件的解析插件。
- 调用工作流API上传图片时返回参数错误，无法识别图片字段。原因是未按照平台要求的参数格式传递图片二进制数据或文件路径。
- 分块结果丢失炉次与缺陷的关联信息。原因是`chunkSize`设置过小，将同一条关联记录拆分至不同块中，破坏了业务逻辑关联性。

## 怎么确认配好了
本核对流程适用于FastGPT v4.17.0版本。
- 上传单份铸造配料单，检查分块结果是否保留合金配料比例与炉次编号的关联内容。
- 上传批量炉次记录文件，验证解析耗时是否符合预设的`PARSE_FILE_TIMEOUT_SECONDS`设置。
- 调用API上传测试文档，查看返回的分块数据是否包含完整的字段信息，无缺失或割裂。
- 检查知识库存储的分块数据，确认结构化文档的关键字段未被遗漏。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
