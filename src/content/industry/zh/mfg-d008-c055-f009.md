# 铸造（砂型、精密、压铸）的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来源包括ERP物料主数据、熔炼炉与测温仪、光谱仪、MES炉次记录、模具管理系统、客户图纸与技术条件。更新节奏为每炉次、每批或每日。日常文档涵盖铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告、不合格品评审单，字段包含炉号、模次编号、浇注温度、配料比例参数、不合格缺陷类型，单位涵盖摄氏度、件数、重量单位等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据特征对模型接入配置带来多重约束。多源工业系统与设备的数据格式存在差异，需配置适配多源数据的接入规则，统一字段映射逻辑以确保数据一致性。高频更新的炉次、批次数据要求配置支持近实时同步的触发机制，避免数据滞后影响点检响应的及时性。多样化的文档类型与工业字段，需明确匹配设备点检、维修问答的关键词映射规则，确保检索与问答的准确性。工业参数的单位与数值范围需严格对齐，防止因格式偏差导致问答结果出现错误。

## 配置怎么定
以下配置项适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配铸造工艺卡、炉次记录等多文档拼接的上下文长度需求 |
| `maxTokens` | 4000 token | 匹配单轮问答的输出长度，覆盖设备维修步骤、点检规范的完整说明 |
| `quoteMaxToken` | 2000 token | 限制召回文档的总长度，避免上下文过载影响模型推理效率 |
| `temperature` | 0.2–0.4 | 降低随机性，确保点检维修问答的结果符合工业规范的严谨性 |
| `AIPROXY_API_ENDPOINT` | 按实际部署的私有代理地址填写 | 适配工业场景下的私有部署代理配置 |
| `AIPROXY_API_TOKEN` | 按分配的认证令牌填写 | 完成私有代理的身份校验，避免未授权访问 |

## 容易做错的三处
- 部署重排模型后调用返回401 unauthorized，原因是未正确配置`AIPROXY_API_TOKEN`或代理地址，导致身份校验失败。
- 工作流的AI模型下拉列表为空，原因是未完成大模型平台的接入配置，或配置的令牌权限不足。
- 问答结果遗漏关键工艺参数，原因是未合理设置`maxContext`参数，导致上下文长度不足以承载多份炉次与模具履历数据。

## 怎么确认配好了
- 访问FastGPT的模型管理页面，确认配置的代理地址与令牌可正常访问，无报错提示。
- 创建测试工作流，选择已配置的模型分类，验证下拉列表可正常加载可选模型。
- 输入设备点检相关的测试问题，验证返回结果包含匹配的工艺与维修信息，无格式错误。
- 查看模型调用日志，确认`maxContext`、`maxTokens`等参数的取值符合配置要求，无异常截断。
