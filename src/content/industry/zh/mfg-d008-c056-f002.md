# 锂离子电芯制造的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自原材料批次台账、生产MES系统、浆料与涂布检测设备、车间露点监测装置、化成分容柜及实验室测试设备。数据更新节奏为每生产批次、每只电芯同步更新，部分实时监测数据秒级更新。日常文档包含配料记录、涂布辊压参数台账、卷绕/叠片工序记录、注液操作日志、化成分容数据报表、OCV与安全测试报告，字段涵盖工艺参数、检测数值、批次标识与时间戳，单位涉及质量、长度、温度、电压等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的高频实时更新数据，要求索引支持增量同步与低延迟查询，避免因全量重索引拖慢生产流程。多维度带单位的工艺与检测数值，要求向量模型在编码时保留参数与单位的关联特征，防止语义混淆。单批次数据量随生产规模扩大而增加，需限制单文档块的最大长度，避免向量嵌入时超出模型阈值。同时，批次与工序的强关联属性，要求索引在召回时保留上下文关联，确保检索结果匹配当前生产环节的需求。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的界面逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配该品类单条工艺记录的典型长度，避免块丢失与嵌入超限 |
| 重叠长度 | 100–200 字符 | 保留工序间的上下文关联，防止跨块语义断裂 |
| maxToken | 8192 token | 适配主流向量模型的输入上限，避免嵌入报错 |
| 单次召回上限 | 前 8 条 | 平衡检索精度与响应速度，适配车间终端的查询需求 |
| 线程数 | 2–4 线程 | 降低embedding速率超限的概率，适配企业服务器的并发负载 |
| 最大上下文 | 6000 字符 | 匹配设备点检问答的常见上下文长度，确保检索结果覆盖完整工艺场景 |

## 容易做错的三处
- 现象：设置分块长度3000字符时出现文本块丢失。原因：该品类单条工艺记录的实际长度多在800-1200字符区间，过大的分块长度会导致系统误判有效内容边界，触发块过滤逻辑。
- 现象：向量化过程中出现embedding速率超限报错。原因：未调整合理的线程数配置，并发嵌入请求超出模型服务的速率限制，导致请求被拦截。
- 现象：知识库检索速度慢，长时间处于索引中状态。原因：未限制单次召回上限，且未开启增量索引模式，全量索引在高频数据更新下无法及时完成同步。

## 怎么确认配好了
- 上传单条典型工艺记录，检查分块结果是否符合预期的长度区间，无异常块丢失。
- 模拟批量向量化操作，观察是否出现速率超限报错，调整线程数至无报错状态。
- 发起设备点检相关查询，核对检索结果的返回时间与召回条数，匹配预设的配置参数。
- 查看索引状态面板，确认增量同步任务可按时完成，无长期处于索引中的异常。
