# 锂离子电芯制造的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
数据来源包括原材料批次台账、车间MES系统、浆料与涂布检测设备、露点监测装置、化成分容柜及实验室测试报告。日常文档涵盖配料记录、涂布辊压参数表、卷绕/叠片工序记录、注液台账、化成分容数据、OCV与安全测试报告。数据更新节奏为每批次、单只电芯级实时同步，字段包含工序编号、设备运行参数、检测数值、批次标识等，无统一固定单位，随检测项对应调整。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据实时性强且按批次拆分，多轮对话需严格绑定当前作业批次的上下文，避免跨批次参数混淆。日常文档多为工序级参数与检测数值，提示词需明确限定设备所属的涂布、卷绕、化成等工序范围，缩小检索范围。数据来源分散且字段无统一格式，对话需引导用户补充工序编号、设备型号等关键标识，确保检索匹配准确。实时更新的数据要求对话上下文窗口不宜过大，避免加载过时的批次数据影响判断。

## 配置怎么定
FastGPT v4.17.0 下的配置可参考以下表格：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定当前作业批次号、工序类型 | 用于在多轮对话中锚定对应批次的检测数据与工序文档 |
| `chatId` | 绑定当前作业会话的批次标识 | 用于区分不同作业批次的对话上下文，避免跨批次参数混淆 |
| `messages` | 保留最近 15 条对话内容 | 匹配该品类单批次工序的对话交互节奏，避免冗余历史数据干扰 |
| 上下文窗口上限 | `5000 字符` | 匹配该品类单批次工序数据的体量，防止加载过多过时数据 |
| 单次检索返回条数 | `前 8 条` | 缩小检索范围，聚焦当前工序的核心设备文档与检测数据 |
| 会话超时时间 | `600 秒` | 匹配该品类设备点检的单次交互时长，避免会话提前终止 |

## 容易做错的三处
- 现象：对话框上传文件始终不解析，后台也没有报错。原因：未配置该品类专属的文档解析规则，无法识别配料记录、涂布参数表等电芯制造类文档的结构化字段。
- 现象：多轮对话中跨批次参数被混淆。原因：未通过`chatId`绑定当前作业批次标识，导致上下文加载了其他批次的历史数据。
- 现象：AI输出的维修建议未匹配当前工序。原因：提示词未限定设备所属的工序范围，检索到了无关工序的设备文档。

## 怎么确认配好了
- 发起一次针对涂布工序辊压机的点检对话，检查返回的文档是否仅包含涂布辊压相关的参数与检测数据。
- 切换作业批次后发起新的对话，检查上下文是否自动切换为新批次的相关数据，未保留旧批次内容。
- 上传该品类的配料记录文档，检查系统是否能正确解析其中的批次号与投料数据。
- 发起连续多轮交互，检查对话上下文是否保留最近15条内容，未加载过多历史数据。
