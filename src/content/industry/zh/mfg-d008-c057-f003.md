# 锻造与模锻的设备点检与维修问答：多轮对话与提示词

## 这个品类的数据长什么样
数据主要来自原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图。日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告。数据按每件锻件、每生产批次或每炉次更新，文档字段包含锻件编号、炉批号、压力参数、模具磨损量、检测缺陷类型等，单位涉及温度、压力、毫米、小时等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据按批次或炉次更新的特性，要求多轮对话需绑定对应批次的会话标识，避免跨批次数据混淆。多类专业文档与多字段参数的存在，要求提示词需限定检索范围至设备点检维修相关内容，防止无关信息干扰。高频更新的模具寿命、加热记录等数据，要求对话流程需实时调用最新数据，不能使用过期记录。处理折叠、裂纹等缺陷时，需逐步引导用户提供参数与缺陷信息，多轮对话需合理控制上下文长度，确保专业信息完整且不冗余。

## 配置怎么定
以下配置基于FastGPT v4.17.0制定：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 按用户会话生成唯一标识 | 确保不同用户的历史对话隔离，避免会话数据混淆，适配多用户使用场景 |
| `messages` | 保留最近20轮对话内容 | 锻造设备点检维修涉及多步骤参数核对，保留足够轮次可回溯历史操作记录，同时避免上下文过载 |
| `variables` | 预设锻件炉批号、设备型号变量 | 快速关联对应批次的加热炉记录、模具寿命数据，提升问答准确性 |
| 最大上下文长度 | 8000–12000 字符 | 锻造相关文档包含多组参数与检测数据，足够长度可承载完整的点检记录与维修流程信息 |
| 问题优化 | 按实测标定 | 锻造专业术语较多，优化后可提升模型对专业问题的理解精度 |

## 容易做错的三处
- 现象：调用API获取对话数据时，返回的`messages`字段中Human内容为空。原因：未在API请求的`messages`参数中正确填充用户输入内容，导致会话记录缺失用户侧输入。
- 现象：多用户使用应用时，不同用户可查看彼此的历史对话记录。原因：未为每个用户生成独立的`chatId`，会话数据未按用户标识隔离。
- 现象：对话中调用的模具寿命数据与当前锻件批次不匹配。原因：未在提示词中加入批次匹配的约束，或未通过`variables`绑定当前会话的炉批号参数。

## 怎么确认配好了
- 发起两次不同用户的API对话请求，检查各自返回的会话数据仅包含自身的对话内容，确认`chatId`绑定逻辑正确。
- 向应用输入锻造设备点检的专业问题，查看回复中是否关联了当前会话预设的`variables`参数内容，验证变量绑定生效。
- 连续发起多轮对话，检查`messages`参数保留的历史轮次符合预设数量，未出现上下文过度截断或冗余加载。
- 模拟API请求并完整填充用户与助手的对话内容，确认返回结果中`messages`字段包含全部有效对话记录，无空字段。
