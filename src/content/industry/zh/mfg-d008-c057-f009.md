# 锻造与模锻的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自锻造厂、航空航天与汽车锻件供应商、锻压车间的多类业务文档与系统采集数据。日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告；数据来源涵盖原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪、客户锻件图。数据更新频率为每件或每批、每炉次，字段包含炉温、保温时长、压力吨位、锻件尺寸公差、无损检测结果、炉批号、锻件批次号等。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类的数据特征对模型接入与配置带来多项约束。多源异构的数据来源要求配置适配不同系统格式的接入规则；高频的更新频率要求支持按炉次、批次触发的数据同步，避免过时数据影响点检结果；多样的文档结构需要适配不同长度与字段的文本拆分，确保炉批号、锻件批次号等关键标识不被截断；严重的出错后果要求配置高置信度的参数，确保维修与点检方案符合行业规范。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本，具体参数与建议取法如下：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配锻造工艺规程、超声检测报告等多源文档的总长度，支持跨批次、跨工序的上下文关联 |
| `maxTokens` | 2000–3000 token | 匹配设备点检与维修问答的单次回复长度需求，避免超出模型输出限制 |
| `quoteMaxToken` | 1500 字符 | 适配加热炉记录、热处理委托单等单段文档的有效长度，保留炉批号、锻件批次号等关键标识 |
| `temperature` | 0.2–0.4 | 确保维修与点检方案的准确性，避免生成不符合锻造工艺规范的内容 |
| `AIPROXY_API_ENDPOINT` | 按部署环境的代理地址填写 | 适配海外或本地部署的API访问路径，解决跨区域访问的网络问题 |
| `AIPROXY_API_TOKEN` | 填写分配的访问密钥 | 实现安全的API调用认证，防止未授权访问 |

## 容易做错的三处
- 现象：调用海外模型时返回`tls: failed to verify certificate: x509: certificate signed by unknown authority`报错。原因：未正确配置`AIPROXY_API_ENDPOINT`，或未适配部署环境的证书校验规则。
- 现象：向量召回结果条数远少于预期，无法覆盖当前点检的设备参数。原因：`maxContext`取值过小，导致系统未加载足够的历史锻件批次与设备数据。
- 现象：上传的加热炉记录、超声检测报告无法被正确关联到对应锻件批次。原因：未根据文档字段调整`quoteMaxToken`参数，导致关键的炉批号、批次号字段被截断。

## 怎么确认配好了
- 执行一次针对特定炉次加热参数的测试查询，核对返回内容中是否包含对应炉次的完整数据。
- 检查API调用日志，确认`AIPROXY_API_TOKEN`的认证请求返回正常状态码。
- 上传一批模拟的锻件检测报告，核对召回结果的范围与配置的上下文范围匹配。
- 调整`temperature`参数后，对比两次回复的差异，确认符合预期的严谨程度。
