# 预制混凝土构件的设备点检与维修问答：工作流编排

## 这个品类的数据长什么样
预制混凝土构件的日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据来源为BIM或深化设计文件、钢筋与混凝土批次台账、模台与养护窑运行数据、试验室检测记录，以及产品二维码追溯系统。数据更新随单件构件、每批物料、每窑养护批次同步完成，核心字段包含构件型号、钢筋规格、浇筑强度、养护时长、脱模检验结果等，与按车交付流态材料的品类不同，需匹配现场吊装位置的单件大型构件参数。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的多源异构文档与高频更新特性，要求工作流需支持多格式文档的自动解析与批次关联。单件构件的专属参数要求工作流节点需绑定对应二维码追溯ID，避免不同批次构件的参数混淆。高频更新的养护、检验数据，要求工作流的节点触发逻辑需支持实时同步最新台账。预埋位置、强度等核心校验字段的准确性要求，需在工作流中设置前置校验节点，拦截不符合要求的参数进入后续点检维修问答环节。同时，因构件需匹配现场吊装位置，工作流需保留构件与安装位置的关联字段，便于后续问答精准匹配对应场景。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量配置 | 在`variables`中绑定构件ID、批次号、养护强度字段 | 匹配预制混凝土构件的单件追溯与核心参数校验需求 |
| 触发时机配置 | 按脱模检验完成、每窑养护周期结束触发 | 匹配品类按每批、每窑的高频更新节奏 |
| 超时阈值 | 600秒 | 适配多源文档解析与参数校验的耗时需求 |
| 代码运行超时 | 300秒 | 适配代码解析多份构件文档的耗时需求 |
| 单次解析文档数上限 | 5份 | 适配单批次构件的配套文档数量范围 |
| 上下文调用上限 | 前8条 | 匹配单批次构件的关联数据量范围 |
| 核心节点ID | 绑定`nodeId`为点检与维修问答核心节点 | 便于工作流调试与日志定位 |

## 容易做错的三处
- 现象：代码运行节点的console.log日志未在检查控制台显示。原因：未开启工作流的调试日志开关，或节点未配置为允许输出运行日志。
- 现象：代码运行节点抛出执行报错。原因：未在`variables`中绑定构件ID、批次号等必填字段，导致代码调用的参数缺失。
- 现象：AI模型下拉列表为空。原因：未在平台后台配置对应大模型的访问密钥，或未开通该模型的工作流调用权限。

## 怎么确认配好了
- 手动触发工作流，传入测试用的构件批次数据，检查`variables`中的绑定字段是否正确加载。
- 运行代码运行节点，查看控制台是否输出预设的运行日志，确认日志可正常显示。
- 进入工作流配置页面，检查AI模型下拉列表是否加载出可用的大模型选项。
- 触发一次模拟的养护记录更新，确认工作流是否按预设时机自动启动。
