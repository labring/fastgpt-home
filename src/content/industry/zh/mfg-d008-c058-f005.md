# 预制混凝土构件的设备点检与维修问答：工具调用与插件

## 这个品类的数据长什么样
预制混凝土构件的生产数据来源于BIM深化设计文件、钢筋与混凝土批次台账、模台及养护窑运行日志、试验室检验报告与二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护周期记录、脱模与出厂检验报告。数据更新随单件构件、每批物料、每窑养护批次触发，覆盖从设计到出厂的全流程环节，字段包含构件编号、钢筋规格、预埋位置坐标、养护温度曲线等，单位涵盖毫米、立方米、摄氏度、小时等。

## 这些特征在「工具调用与插件」这一环带来什么约束
预制混凝土构件的设备点检与维修问答需调用模具、养护窑、钢筋加工设备的运维数据，数据来源分散在多系统且按单件或批次更新，要求工具调用需支持按构件编号精准关联对应批次的历史数据。构件深化图包含大量坐标与规格字段，工具调用需能解析结构化文档字段，避免非结构化内容干扰。出错后果直接关联工程现场安装与工期，要求工具调用的结果需附带数据来源的溯源标识，且响应需匹配生产节奏的时间窗口。不同构件的模具、养护参数差异较大，工具调用需支持动态加载对应构件的预设配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | `auto` | 预制混凝土构件的点检维修场景需动态匹配不同设备的运维工具，自动模式可适配PC构件、管桩等不同品类的调用需求，基于FastGPT v4.17.0版本的工具调用逻辑设计 |
| 工具调用超时时间 | `600 秒` | 养护窑的养护周期常达数小时，设备运维数据查询需足够的响应窗口，避免中途中断影响生产流程 |
| 单次工具调用返回条数 | `前 3 条` | 单批次构件的运维记录数量有限，过多返回结果会干扰问答逻辑，降低信息精准度 |
| 工作流/API 函数调用配置 | `enabled` | 需强制调用结构化工具解析构件深化图、钢筋下料单中的坐标、规格等字段，确保问答结果匹配实际生产数据 |
| 工具调用上下文最大长度 | `8000 字符` | 构件深化图的单页内容常达数千字符，需足够的上下文支持工具完整解析文档内容 |

## 容易做错的三处
- 现象：工具调用节点使用大模型时频繁返回429 Request rate increased too quickly报错。原因：未配置合理的调用频率限制，单批次构件的多轮点检问答触发了模型的速率阈值。
- 现象：新建工具调用配置后，原有同类型配置被覆盖。原因：未为不同构件场景的配置设置独立的命名与分组，导致配置项被统一覆盖。
- 现象：调用解析构件深化图的工具时，返回的预埋位置字段为空。原因：未开启`functionCall`强制结构化调用，模型未从文档中提取关键坐标信息。

## 怎么确认配好了
- 手动输入一个已知构件编号的点检问题，核对工具调用是否返回对应批次的养护记录与模具检验数据。
- 查看工具调用的日志，确认返回结果包含构件编号、数据来源标识等必填字段。
- 测试新建独立的配置项，确认原有配置未被覆盖，不同场景的配置可独立运行。
- 模拟多轮问答场景，确认未触发速率限制报错。
