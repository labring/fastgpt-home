# 预制混凝土构件的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
预制混凝土构件的数据来源于BIM或深化设计文件、钢筋与混凝土批次记录、模台与养护窑运行数据、试验室检验报告、产品二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据按单件构件、每批物料、每窑养护批次更新，字段包含构件编号、钢筋规格、养护时长、脱模强度等，单份文档结构无统一规范，需按独立文档的格式逐一解析。

## 这些特征在「模型接入与配置」这一环带来什么约束
预制混凝土构件的数据来源分散且更新频率高，单份文档的结构差异较大，需精准匹配不同文档的字段与内容。由于构件出错会导致现场安装失败或报废，模型输出的准确性要求较高，需严格控制回答的随机性。同时，部分文档包含图纸类视觉内容，需支持视觉解析能力。此外，数据按单件、每批更新，上下文关联范围需覆盖单构件的全流程文档，避免信息缺失导致的配置偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单件预制构件的多文档关联上下文需求，覆盖深化图、养护记录、下料单等全流程数据 |
| `maxTokens` | 4000 token | 控制单轮回答的输出长度，匹配预制构件点检维修问答的信息密度需求 |
| `quoteMaxToken` | 2000 token | 保留足够的原文片段，支撑维修步骤中对构件图纸、检验记录的精准引用 |
| `vision` | 开启 | 适配构件深化图、模具检验照片等视觉类文档的解析，满足点检中的外观缺陷识别需求 |
| `temperature` | 0.3–0.5 | 降低回答的随机性，保障维修步骤、点检标准的准确性 |
| `AIPROXY_API_TOKEN` | 填写本地代理生成的认证令牌 | 保障本地化模型接入的安全性，避免未授权访问 |

## 容易做错的三处
-  界面模型下拉列表为空。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，本地代理服务未正常连通。
-  调用模型时返回401 unauthorized报错。原因：`AIPROXY_API_TOKEN`填写错误，或本地代理服务未开启认证校验流程。
-  模型输出的维修步骤与构件实际参数不匹配。原因：`maxContext`取值过小，未加载完整的构件养护、下料单等关联数据，导致上下文信息缺失。

## 怎么确认配好了
-  进入FastGPT v4.17.0的模型管理页面，检查下拉列表是否显示已接入的本地化模型。
-  上传一份预制构件深化图，发起解析测试，确认返回结果中包含图纸的关键标注与尺寸信息。
-  查看模型调用日志，确认`maxContext`、`temperature`等参数的实际取值与配置内容一致。
-  输入针对特定构件的点检问题，验证返回结果是否引用了对应的养护记录、下料单等文档片段。
