# 预拌混凝土生产的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
预拌混凝土生产的数据来源包括工程订单、砂石水泥外加剂检验记录、含水率测定报告、搅拌站控制系统日志、试验室质量档案。更新节奏为每车生产批次、每批原料进场、每日汇总。日常文档包含配合比通知单、开盘鉴定、生产运输单、原材料检验记录、试块留存记录、强度检测报告。数据字段涵盖设备编号、运行时长、故障代码、原料配比参数、含水率数值、试块强度结果，单位包含小时、立方米、兆帕等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。高频更新的每车生产与每批原料数据，要求索引支持增量同步，避免全量重建带来的资源消耗。多类型文档长度差异显著，短至数十字符的配合比参数与长至数千字符的设备运行日志并存，需要适配可变长度的文本分块规则。多字段的结构化数据与非结构化维修记录混合，要求索引支持定向关联设备编号、故障代码等核心字段，提升检索精准度。数据量级可达十万级，需平衡索引构建效率与检索响应速度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配预拌混凝土生产的设备日志、维修记录等文档的平均长度，避免分块破坏语义完整性 |
| 重叠长度 | 50–100 字符 | 弥补分块边界的语义断裂，确保跨块的维修步骤、故障关联信息不被割裂 |
| `maxToken` | 4096 token | 匹配FastGPT v4.17.0支持的主流向量模型输入上限，适配配合比通知单、强度报告等短文档的完整语义加载 |
| `defaultToken` | 2048 token | 作为默认上下文长度，平衡检索结果的信息丰富度与响应速度 |
| 相似度阈值 | 0.72–0.85 | 过滤低匹配度的非相关维修方案，适配设备点检场景的精准检索需求 |
| 单次搜索上限 | 前10条 | 控制返回结果的数量，避免冗余信息干扰维修决策 |

## 容易做错的三处
- 向量处理十万级csv数据后，最终索引条目比源数据少数千条。未正确配置源数据的空字段过滤规则，或分块时未处理换行符、特殊字符导致部分条目被跳过，或向量模型接口的默认截断逻辑丢弃了超长文本条目。
- 创建向量集合时返回创建成功，但页面始终显示索引未建立。未正确开启自动索引构建开关，或索引构建任务因磁盘空间不足、API调用超时未完成，且未配置失败重试机制。
- 本地环境下向量检索结果符合预期，打包为Docker镜像运行后，不同查询的向量得分完全一致。未正确加载向量模型的配置参数，或环境变量未正确传递模型调用的身份凭证，导致所有查询调用了固定的默认向量输出。

## 怎么确认配好了
- 上传单条典型文档（如设备故障日志），检查分块后的文本片段是否完整保留核心语义，无明显截断或割裂。
- 执行批量导入测试数据，核对导入后的索引条目数量与源数据数量一致，无莫名丢失的条目。
- 发起针对已知故障代码的检索，确认返回结果的排序与匹配度符合预设的相似度阈值规则。
- 部署为Docker镜像后，发起多轮检索，确认不同查询的向量得分存在合理差异，无完全一致的异常情况。
