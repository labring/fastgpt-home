# 预拌混凝土生产的设备点检与维修问答：模型接入与配置

## 这个品类的数据长什么样
预拌混凝土生产的设备点检与维修问答数据，主要来自工程订单、砂石水泥外加剂检验记录、骨料含水率测定数据、搅拌站控制系统运行日志、工程项目试验室试验报告。数据更新频率为每车生产批次、每批原料进场、每日试验周期更新。核心文档包含配合比通知单、开盘鉴定记录、生产运输单、原材料检验报告、试块强度记录，数据按生产批次、原料批次、试验批次关联，包含原料参数、搅拌工艺参数、设备运行状态、试验检测数值等字段，无统一全局聚合的数据集。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据分散在多个独立系统中，需对接多源异构数据源的API接口，因此配置需支持多端点接入。高频次的小批量数据更新要求模型调用需适配低延迟的实时请求，避免因等待超时影响生产调度。按批次关联的文档结构要求模型上下文需绑定对应生产/试验批次的专属数据，不宜使用跨批次的全局上下文。同时，滞后生成的试块强度报告需与实时生产数据区分接入优先级，配置需支持按数据类型划分调用规则，防止非实时数据占用核心上下文资源。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的官方规则制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | 预拌混凝土生产的设备点检问答需关联单批次生产、原料检验与试验记录，上下文长度控制在该区间可避免冗余数据干扰 |
| `temperature` | `0.2–0.4` | 设备维修与点检问答需匹配精准的故障现象与解决方案，该取值区间可平衡回答的准确性与灵活性 |
| `AIPROXY_API_ENDPOINT` | 局域网搅拌站控制系统与试验室专用API地址 | 对接本地生产与试验数据，避免跨网传输带来的延迟与安全风险 |
| `quoteMaxToken` | `2000–3000 字符` | 引用配合比通知单、试块报告等核心文档内容时，控制引用长度以适配模型输入限制 |
| `AIPROXY_API_TOKEN` | 绑定专用设备服务账号的专属令牌 | 隔离生产数据访问权限，符合工程现场数据安全管理要求 |
| 工作流/API 工具选择配置 | `auto` | 支持模型自主选择是否调用内置的设备故障代码查询工具，适配不同型号搅拌设备的点检需求 |

## 容易做错的三处
- 外部请求返回403状态码，无法访问发布渠道。原因是未配置公开访问的反向代理规则，仅绑定了局域网监听地址，未开放公网访问权限。
- 切换向量模型后返回的相似度数值超出合理区间。原因是未调整对应搜索过滤的参数配置，误用了非标准化的相似度计算结果，未适配新模型的输出规则。
- 本地部署的GLM或Qwen模型调用失败，返回连接超时或密钥无效。原因是`AIPROXY_API_TOKEN`填写了通用模型密钥，未绑定对应本地部署模型的专属令牌，且未配置局域网访问的端点地址。

## 怎么确认配好了
- 发起单批次预拌混凝土生产的设备点检查询，核对返回结果中是否关联了对应批次的配合比通知单、骨料含水率检测数据与试块强度记录。
- 调用FastGPT提供的API测试接口，检查返回的响应状态码为200，且响应内容包含符合设备维修逻辑的具体建议。
- 查看模型调用日志，确认`maxContext`的实际使用长度未超过配置阈值，且引用的知识库内容未超出`quoteMaxToken`的限制。
- 切换不同的部署模型，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置是否生效，无连接报错或权限异常提示。
