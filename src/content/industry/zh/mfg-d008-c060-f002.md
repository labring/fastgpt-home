# 饮料与瓶装水的设备点检与维修问答：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自饮料工厂的配方系统、水处理记录、调配日志、无菌灌装记录、包材与成品检验报告，以及在线糖度酸度传感器、视觉检测设备、LIMS系统的连续采集数据。日常文档包含浓缩液投料复核单、水处理班次台账、灌装封口异常日志等。数据更新节奏随生产批次、班次实时或定时推送，产品切换时会同步更新配方与包装关联数据。

## 这些特征在「向量模型与索引」这一环带来什么约束
连续采集的高频传感器数据会带来单文档长度波动，需适配灵活的分块规则避免关键信息截断；多批次的配方与检验数据需按生产批次建立索引关联，防止跨批次检索混淆；高频更新的异常日志需要支持增量索引，避免全量重建带来的耗时；产品切换频繁的特性要求索引支持快速切换关联数据集，同时保留历史批次的检索能力；微生物污染、错标签等高风险场景的检索需优先关联对应批次的全链路数据，保障问答准确性。

## 配置怎么定
本配置适用于FastGPT v4.17.0。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类单份文档（如水处理记录、灌装日志）的平均长度，避免跨业务逻辑的块分割 |
| 重叠长度 | 100–150 字符 | 覆盖高频采集的传感器数据的连续片段，防止关键异常信息被分块截断 |
| 相似度阈值 | 0.72–0.85 | 区分设备正常运行与异常点检数据的匹配度，适配该品类高风险场景的检索精度要求 |
| 单次搜索上限 | 前 10 条 | 限制返回结果数量，避免大量历史数据干扰当前批次的点检维修问答 |
| 最大上下文 | 4000 token | 适配该品类单批次全链路数据的检索结果拼接长度，符合多数大语言模型的输入限制 |
| defaultToken | 2000 | 控制单条嵌入文本的最大token数，适配在线传感器数据的短文本与长日志的混合输入 |

## 容易做错的三处
- 现象：配置第三方嵌入模型渠道后，界面提示无可用渠道。原因：未针对该品类的专属文档字段规则绑定对应渠道，或渠道的token长度限制未适配该品类的长文本日志。
- 现象：8核64G内存搭配RTX2070显卡时，知识库检索耗时过长。原因：未针对该品类的高频传感器数据设置合理的分块长度与索引分片，导致向量计算时内存占用过高。
- 现象：检索结果中混入了非当前生产批次的设备数据。原因：未按生产批次建立索引分区，导致跨批次数据混淆。

## 怎么确认配好了
- 上传单份该品类的典型文档（如单班次水处理记录），验证分块后的文本长度符合预设范围。
- 检索同一生产批次的设备异常日志，确认返回结果仅包含该批次的关联数据。
- 测试第三方嵌入模型的调用，确认无渠道报错且返回的向量维度符合配置要求。
- 模拟高频数据更新，验证增量索引的加载速度符合业务响应要求。
