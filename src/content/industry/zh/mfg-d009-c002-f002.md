# SMT贴片与电子组装的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
SMT贴片与电子组装的业务数据来自客户BOM、Gerber坐标文件、MES系统、锡膏与元件批次台账、贴片机运行日志、SPI/AOI检测报告、回流焊炉温记录、首件确认单与维修追溯标签。数据更新节奏为每工单、每次换线实时同步，部分炉温与检测数据按秒级更新。单份文档包含料号、位号、元件批次号、炉温曲线参数、缺陷类型等结构化与半结构化字段，单工单关联的文档总量随生产规模动态变化。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时高频的更新要求索引支持增量同步，避免全量重建带来的性能损耗。多源异构的数据格式需要统一的分块规则，确保BOM的结构化字段与SPI报告的文本描述能被正确向量化。工单级的粒度要求分块需关联生产批次信息，避免跨工单的向量混淆。长文本的炉温曲线与AOI缺陷描述需要适配更大的上下文窗口，防止关键信息被截断。同时，大量重复的元件料号与缺陷类型文本，要求索引具备去重与相似度过滤能力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `defaultToken` | `8192` | 适配bge-m3模型的标准上下文窗口，匹配单份BOM与坐标文件的平均文本长度 |
| `maxToken` | `16384` | 覆盖带完整炉温曲线的AOI检测报告的最大文本长度，避免关键缺陷描述被截断 |
| 分块长度 | 800–1200 字符 | 适配SMT类文档的字段密度，确保每个分块包含完整的生产参数或缺陷记录 |
| 重叠长度 | 100–150 字符 | 避免跨分块的关键信息断裂，例如连续的元件位号与缺陷描述 |
| 相似度阈值 | 0.72–0.85 按实测标定 | 区分相似的元件批次与缺陷类型，减少追溯结果中的无关条目 |
| 单次搜索上限 | 前 10 条 | 匹配工单级数据的查询需求，平衡召回精度与响应延迟 |

## 容易做错的三处
- 现象：已添加ollama qwen2.5语言模型与bge-m3索引模型，可用模型列表显示但创建知识库时文本理解模型下拉框无对应选项。原因：未将模型绑定至知识库的文本理解模型权限组，仅完成了全局模型渠道添加。
- 现象：单份文档上传时显示分8段，显示就绪后再次查看变为13段且存在重复片段。原因：未配置增量索引的去重规则，实时更新的工单数据重复触发了分块任务，导致同一文档被多次索引。
- 现象：仅支持单文件调整向量模型训练参数并重新上传，无法批量处理全量工单文档。原因：未启用批量索引训练的批次任务配置，默认仅开启单文件操作模式。

## 怎么确认配好了
- 上传一份测试用的BOM与坐标文件，检查分块数量与预期一致，无重复片段。
- 发起一次质量缺陷追溯查询，确认返回的结果包含匹配的SPI/AOI报告片段，且相似度符合设定阈值。
- 查看模型绑定列表，确认已添加的ollama qwen2.5和bge-m3模型出现在文本理解模型下拉框中。
- 在FastGPT v4.17.0版本的批量任务管理页面，提交全量工单文档的索引任务，确认任务按批次执行，无重复分块日志。
