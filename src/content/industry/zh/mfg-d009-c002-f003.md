# SMT贴片与电子组装的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
SMT贴片与电子组装的业务数据涵盖多类结构化与半结构化文件，包括BOM与坐标文件、换线表、钢网与炉温记录、首件确认单、SPI/AOI检测报告、维修记录与追溯标签。数据来源覆盖客户交付的BOM、Gerber、坐标文件，以及MES系统、锡膏与元件批次台账、贴片机、SPI/AOI检测设备、回流焊炉温采集数据。数据更新随工单执行、换线操作实时完成，单工单数据字段包含元件位号、料号、批次号、检测坐标、炉温曲线参数等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据分散且实时更新，要求多轮对话可快速关联不同系统的批次、坐标与检测数据，避免跨数据源的信息割裂。文档类型多样，提示词需适配BOM、SPI报告、炉温曲线等不同文件的字段格式，准确提取元件位号、缺陷位置等关键信息。单工单数据随工单执行动态生成，多轮对话需支持按需加载指定工单的历史数据，避免加载非当前工单的全量历史上下文，防止信息过载。同时，质量追溯需逐层回溯全链路信息，对话流程需支持按追溯标签、批次号递进查询，确保每一轮对话的上下文聚焦当前追溯目标。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | 8000–12000 字符 | 适配FastGPT v4.17.0的上下文处理上限，匹配单工单多份文档的总字符量 |
| 对话记录保存时长 | 30–180 天 | 匹配EMS厂的工单交付与质量追溯周期要求 |
| `chatId` 绑定规则 | 按当前工单ID绑定 | 确保多轮对话的上下文仅关联当前工单数据，避免跨工单信息混淆 |
| `messages` 上下文截断 | 保留最近10轮对话 | 聚焦当前追溯流程，减少冗余信息干扰 |
| `variables` 预设字段 | 绑定当前工单的元件位号、批次号、追溯标签 | 快速调用品类专属数据字段，简化提示词编写 |
| 单次搜索召回条数 | 前5–8 条 | 适配SMT检测报告的单页缺陷数量，避免过多无效信息 |

## 容易做错的三处
- 现象：对话响应时长超过10秒，界面显示加载超时。原因：未按工单ID绑定`chatId`，每次对话加载全量历史上下文，触发上下文过载。
- 现象：无法查询指定工单的历史对话记录。原因：对话记录保存时长配置为小于当前业务的追溯周期，导致早期工单的对话日志被自动清理。
- 现象：分析结果中出现错误的元件位号或批次匹配。原因：未将`variables`绑定当前工单的专属字段，提示词调用了其他工单的料号、批次信息。

## 怎么确认配好了
- 发起针对单工单的多轮对话，检查上下文仅包含该工单的相关文档与历史对话，无其他工单的数据。
- 查看对话记录管理界面，确认指定工单的对话日志保存时长符合当前业务的追溯需求。
- 输入包含元件位号、批次号的查询，检查提示词能正确提取对应字段的信息，无跨工单数据混入。
- 模拟多次连续对话，检查响应时长符合业务使用的预期要求，无超出预期的超时。
