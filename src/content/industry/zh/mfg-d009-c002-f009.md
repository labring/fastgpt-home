# SMT贴片与电子组装的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
SMT贴片与电子组装的业务数据来源包括客户提供的BOM、Gerber文件、坐标文件，以及MES系统、贴片机、SPI/AOI检测设备、回流焊炉温记录、首件确认报告、维修记录与追溯标签。数据更新频率为每工单、每次换线实时更新，文档包含结构化的料号、位号、元件批次信息，以及非结构化的炉温曲线、缺陷图像报告，字段涵盖毫米级贴装坐标、摄氏度级炉温参数等专业单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据工单粒度细、更新实时，且同时包含结构化字段与非结构化图像，要求模型接入配置需适配短上下文快速响应、多模态数据处理与精准字段匹配的需求。多数据源的API接口需要独立配置访问凭证，避免权限混淆；单工单数据长度波动较大，需限制上下文与输出长度以避免调用超时；视觉类缺陷报告的处理需开启对应支持，确保能提取图像中的焊点偏移、虚焊等缺陷特征。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 800–1200 token | 适配单工单的BOM、换线记录与缺陷报告的总长度，避免上下文溢出 |
| `maxTokens` | 600–800 token | 限制单轮分析输出长度，匹配SMT缺陷分析的简洁性需求 |
| `vision` | 开启 | 适配SPI/AOI的图像缺陷报告，提取焊点偏移、虚焊等视觉特征 |
| `temperature` | 0.1–0.3 | 降低随机性，确保料号、位号等关键字段的匹配一致性 |
| `AIPROXY_API_ENDPOINT` | 按数据源配置对应端点 | 对接MES、贴片机、AOI设备的API接口，实现多源数据拉取 |
| `AIPROXY_API_TOKEN` | 按数据源生成专属令牌 | 隔离不同设备与系统的访问权限，避免配置冲突 |

## 容易做错的三处
- 现象：添加同名嵌入模型时，原有配置被自动覆盖。原因：平台默认以模型名称作为唯一标识，未配置自定义模型别名时会触发覆盖。
- 现象：调用知识库返回结果后，输出内容包含「引用标记：［1］」字样。原因：未调整知识库引用标记的生成规则，默认拼接了冗余的标记文本。
- 现象：发起缺陷分析请求时出现上下文长度超限报错。原因：未根据单工单数据量调整`maxContext`参数，导致传入的总数据长度超出限制。

## 怎么确认配好了
- 上传单工单的BOM与SPI/AOI报告，检查模型是否能正确提取料号、位号与缺陷类型。
- 尝试添加多个同名模型，验证是否会触发覆盖提示或保留原有配置（需提前配置自定义模型别名）。
- 发起一次完整的质量追溯分析请求，检查输出内容是否无冗余的引用标记。
- 查看FastGPT v4.17.0的API调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的请求能正常拉取对应数据源的数据。
