# 乳制品加工的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
该品类覆盖液态奶、酸奶、奶粉及乳配料生产企业，日常数据包含原奶验收记录、标准化配料单、巴氏/UHT热处理记录、CIP清洗记录、灌装台账、留样与微检报告。数据来自奶源检测系统、MES系统、均质及热处理设备、在线温流量采集模块、CIP系统与LIMS实验室管理系统，更新频率为每奶罐、每批或实时生成，数据为液态生物原料全流程的连续记录，无固态品类的逐批隔离条件。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类高频实时的更新节奏，要求向量索引支持增量更新以避免全量重建的冗余开销。全流程连续的液态原料数据，需在向量分块与索引时保留奶罐号、生产批次等关键关联标识，确保检索时可还原完整生产链路。多字段且强关联的业务文档，要求索引结构支持按批次、环节类型进行过滤检索，缩小召回范围。异常数据的时效性要求，需控制索引检索的响应延迟匹配生产节拍，避免影响现场决策。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配原奶验收、微检报告等单文档的平均字段长度，避免分块割裂关键信息 |
| 重叠长度 | 100–150 字符 | 保留跨分块的批次、罐号等关联标识，确保语义连贯性 |
| `defaultToken` | 按实测标定 | 适配LIMS微检报告的专业术语token占比，避免截断关键检测数据 |
| `maxToken` | 4096 token | 匹配主流Embedding模型的输入上限，覆盖单批次全流程记录的总token量 |
| 单次搜索上限 | 前10条 | 平衡检索召回率与响应速度，适配生产环节的实时查询需求 |
| 相似度阈值 | 0.75–0.85 | 区分正常生产数据与异常数据的语义相似度边界，符合食品加工的严谨性要求 |

*本文适配FastGPT v4.17.0版本的配置逻辑*

## 容易做错的三处
- 现象：知识库导出的dataset.csv仅包含index字段，无content字段。原因：分块配置时未开启内容提取开关，仅同步了索引元数据而未抓取原始文档文本。
- 现象：检索结果返回条数与单次搜索上限不符，出现大量跨批次的无关数据。原因：未配置按生产批次、罐号的过滤规则，导致召回范围超出目标生产链路。
- 现象：Embedding模型调用返回报错或生成的向量无有效语义。原因：未适配乳制品专业术语的token占比，`maxToken`设置过低导致文档截断，或`defaultToken`配置未匹配模型输入要求。

## 怎么确认配好了
- 上传一份典型的原奶验收记录文档，检查分块后的content字段是否完整保留了原奶批次、抗生素检测结果等关键信息。
- 发起一次针对“原奶抗生素超标”的检索，核对返回结果的数量符合单次搜索上限的配置，且结果均关联有效生产批次。
- 查看索引更新日志，确认高频更新的生产数据可自动触发增量索引，无需手动重建全量索引。
- 导出知识库数据集，确认生成的csv文件同时包含index与content字段，字段内容与原始文档一致。
