# 仓储、批次与厂内物流的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
这个品类通常包含原材料库、线边库、成品库及物流物控部门，日常产生收货单、上架单、领退料单、移库单、盘点表、批次台账、效期记录等文档。数据主要来自ERP/WMS系统、条码或RFID设备、生产工单、库位编码、AGV运行日志与称重数据，更新节奏涵盖实时、每日同步与月度盘点。数据多为结构化或半结构化格式，核心标识字段统一，包含批次号、库位编码、物料编码、检验状态、效期日期与重量等内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。首先，多源异构的结构化与半结构化数据格式，要求索引支持批次号、库位编码等字段的过滤检索，需保留核心元数据以确保检索精准性。其次，实时、每日同步与月度盘点混合的更新节奏，要求索引配置兼顾增量刷新与全量重建的适配性，避免账实数据出现不同步。另外，核心业务聚焦批次流向与账实一致性，要求向量检索的召回结果需直接关联仓储流程单据，聚焦批次流向与账实一致性相关的物料信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配批次台账、领退料单等仓储单据的平均长度，避免割裂批次关联信息，符合FastGPT v4.17.0版本的分块推荐规则 |
| 重叠长度 | 100–150 字符 | 保留批次号、库位编码等跨块关键元数据，确保分块后仍能完整关联物料的批次流向 |
| 相似度阈值 | 0.75–0.85 | 精准匹配批次、库位等核心标识，避免误召回无关仓储数据，适配质量追溯的高准确率要求 |
| 单次搜索上限 | 前 10 条 | 快速定位批次关联的仓储单据，减少后续人工分析的冗余信息 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 现象：向量检索返回空结果，无法找到对应批次的仓储单据。原因：分块时未保留批次号、库位编码等核心字段，导致向量无法关联仓储场景的关键标识。
- 现象：嵌入请求提示输入 token 超限。先核对所选嵌入模型/服务的输入上限，并查看发送给模型的单条输入。若是 LLM 上下文超限，应另查召回文本、提示词、历史对话与所选 LLM 的上下文窗口；嵌入`maxToken`不是上下文总上限。
- 现象：本地部署的向量模型无法正常索引。原因：未在FastGPT中正确配置向量模型的API地址与端口，或未开启模型的远程访问权限。

## 怎么确认配好了
- 上传单份批次台账文档，检索输入已知批次号，核对返回结果是否包含对应批次的所有关联单据。
- 按所选嵌入模型/服务文档核对配置的`maxToken`，再查看调用日志中的拒绝或超长输入记录。
- 模拟账实差异场景，检索对应库位的物料数据，确认检索结果的条数符合单次搜索上限的设置。
- 测试实时更新的AGV运行日志，确认数据提交后可在预设时间内被索引并检索到。
