# 仓储、批次与厂内物流的质量问题追溯与不良分析：文档解析与分块

## 这个品类的数据长什么样
该品类的典型数据通常来自ERP、WMS系统、条码/RFID设备、采购工单、库位管理、AGV输送系统与称重设备。日常产生的文档通常包含收货单、上架单、领退料单、移库单、盘点表、批次台账与效期记录，包含物料编码、批次号、库位编码、效期、数量等字段，单位涵盖件、千克、托盘数等。数据更新节奏通常覆盖实时（如AGV位置数据）、每日（如领退料记录）与月度盘点三类场景。

## 这些特征在「文档解析与分块」这一环带来什么约束
仓储类文档通常兼具结构化表单与台账两种形态，关键信息如批次号、效期需跨段落甚至跨页面保留关联性，分块时不能被随意拆分。不同更新频率的文档对应不同解析需求，实时类数据通常需要更快的解析响应，月度盘点表则可能存在较大体积。同时多来源的文档格式差异明显，ERP导出的PDF可能存在结构化加密，普通解析模式无法精准提取字段，这些特征要求分块配置需兼顾信息完整性、解析效率与格式适配性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配仓储类文档的字段密度，避免拆分批次号、效期等关键追溯信息 |
| `chunkSplitter` | 按段落+语义分块 | 匹配领退料单、盘点表的结构化段落结构，保留字段间的关联性 |
| `customPdfParse` | 启用结构化解析模式 | 适配ERP导出的PDF表单，精准提取物料编码、库位编码等核心字段 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 覆盖月度盘点表、批次台账等大体积文档的完整解析耗时 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 适配批量上传的仓储类文档包，避免因文件过大被拦截 |
| `chunkSettingMode` | 手动配置 | 针对收货单、盘点表等不同文档类型调整分块参数，满足追溯场景的信息完整性要求 |

## 容易做错的三处
- 分块预览时提示无法读取该文件内容，原因是未启用`customPdfParse`配置，无法解析ERP导出的结构化或加密PDF表单。
- 本地部署环境无法正常返回复杂公式，原因是部署的marker版本与FastGPT v4.17.0不兼容，未匹配对应ocr依赖包。
- 飞书知识库无法同步PPT和PDF文档，原因是未配置飞书文档的访问权限范围，未开启对应文件类型的同步开关。

## 怎么确认配好了
- 上传一份典型的月度盘点表PDF，检查分块预览是否保留了批次号、库位编码等关键字段的完整性，未出现关键信息被拆分到不同分块的情况。
- 查看解析任务日志，确认未触发`PARSE_FILE_TIMEOUT_SECONDS`对应的超时报错，匹配文档实际解析耗时。
- 测试上传收货单、移库单两类不同的仓储文档，验证`chunkSplitter`的分块逻辑是否适配对应文档的段落结构。
- 检查飞书知识库的同步配置，确认已开启PPT、PDF文件的同步权限，验证同步任务是否正常完成且文件内容可被正常解析。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
