# 仓储、批次与厂内物流的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
通常，该品类的数据来源包含ERP、WMS系统、条码或RFID设备、采购与工单信息、库位记录、AGV或输送系统数据、称重数据等。日常文档涵盖收货单、上架单、领退料单、移库单、盘点表、批次台账、先进先出与效期记录，核心字段包括物料编码、批次号、库位编号、效期日期、检验状态、关联工单编号等。数据更新频率覆盖实时（如AGV实时位置）、每日（如领退料记录）、月度盘点（如库存对账）。本页基于FastGPT v4.17.0版本的配置说明。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据多源异构且更新节奏差异大，要求检索系统支持多数据源的字段映射与实时同步，避免批次追溯时出现数据滞后。文档类型多样且核心字段集中于物料、批次、库位等精准标识，要求检索需兼顾关键词精准匹配与语义理解，避免召回无关单据。物料关联的全链路追溯需求，要求召回结果需覆盖从收货到出库的全流程单据，且排序需符合业务逻辑。同时，出错后果直接影响生产，要求检索结果具备较高的精准度与可靠性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 该品类核心检索字段为批次号、物料编码等精准标识，该取值区间可过滤低相似度的无关仓储单据 |
| `limit` | `前8–12条` | 仓储类文档单条内容较短，适量结果可覆盖全链路追溯所需的收货、领退料、盘点等单据类型 |
| `searchMode` | `vector+keyword` | 兼顾批次号等可通过关键词精准匹配的字段，与效期、物流状态等需要语义理解的内容 |
| `usingReRank` | 开启 | 多源召回的结果中，需按批次关联优先级重新排序，确保追溯链的逻辑顺序正确 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可将自然语言的追溯问题（如“某批次物料的入库记录”）扩展为批次号、库位等检索词，提升召回精准度 |
| `collectionIds` | 指定仓储、批次管理专属数据集ID | 限定检索范围，排除其他品类的文档干扰，提升检索效率 |

## 容易做错的三处
- 现象：配置仓储知识库后检索时出现参数错误提示，原因：未按照品类的字段特征配置检索参数，错误使用了非指定的参数名或取值范围。
- 现象：检索返回的结果条数过多或过少，影响追溯效率，原因：未设置合理的`limit`参数，取值未匹配仓储类文档的单条长度与检索需求。
- 现象：无法召回文档中的图片关联信息，仅获取到纯文本内容，原因：未开启文档图片的OCR解析配置，导致图片中的批次号、库位等关键信息未被索引。

## 怎么确认配好了
- 输入单一批次号进行检索，核对返回结果是否包含该批次的收货、领退料、盘点等全流程关联单据。
- 调整`similarity`参数的取值区间，验证召回结果的精准度是否符合业务对批次匹配的要求。
- 上传包含图片的仓储单据（如带条码的收货单），验证是否能召回图片中的文本信息。
- 检查检索结果的条数是否符合预设的业务需求，确认`limit`参数生效。
