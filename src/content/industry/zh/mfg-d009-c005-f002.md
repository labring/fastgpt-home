# 光伏电池片制造的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
光伏电池片制造的业务数据主要来自硅片来料台账、车间MES系统、扩散炉/镀膜设备/印刷机的运行日志、EL缺陷检测图像、IV电性能测试数据与实验室工艺卡。日常产出的文档包含工艺参数卡、工序运行记录、检测图像元数据、分档结果报表与良率统计。数据更新节奏为每生产批次同步参数、每片产品完成检测后上传对应记录，每日汇总生成全车间良率报告。数据字段包含批次标识、工艺温度/厚度数值、图像分辨率、电性能参数与缺陷坐标，混合半结构化与非结构化内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
光伏电池片制造的数据特征对向量模型与索引环节带来多重约束。混合结构化工艺参数、图像元数据与非结构化文本的内容，要求向量模型适配多模态输入，需针对不同类型数据制定差异化分块规则。每片产品的检测数据独立且更新频繁，索引需要支持高频增量写入，避免全量重建带来的性能损耗。批次与片级的关联需求，要求分块时必须保留批次号、设备编号等关联元数据，确保追溯时的精准匹配。高维度的图像向量数据，需限制单批次索引的总数据量，防止检索超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配工艺参数文本与检测报告的常规段落长度，避免单块内容过载 |
| 重叠长度 | 100–200 字符 | 保留跨块的工艺关联信息，防止分块切断批次号等关键元数据 |
| 相似度阈值 | 0.65–0.85 | 匹配光伏电池片缺陷检测的语义匹配精度，过滤低关联的历史记录 |
| 单次搜索上限 | 前 20 条 | 控制单轮检索的返回数据量，适配车间终端的检索响应延迟要求 |
| `defaultToken` | 4096 | 适配多模态向量的总长度限制，容纳图像元数据与工艺参数的组合内容 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
-  自定义分块后知识库自动删除重复文档，导致索引顺序与预期不符。原因是未关闭知识库的重复内容去重开关，系统默认按文本哈希自动过滤重复块，打乱了自定义分块的批次关联顺序。
-  配置自定义向量模型后，检索请求仍调用大语言模型。原因是未在检索链路中指定向量模型的调用优先级，系统默认使用内置大语言模型处理检索请求。
-  开启多副本部署后，知识库索引速度未提升反而下降。原因是未配置副本间的索引分片同步规则，导致多个副本重复写入相同数据，增加了磁盘IO负担。

## 怎么确认配好了
-  上传单批次的工艺卡与检测记录，查看分块结果是否保留了批次号、设备编号等关键元数据，分块长度符合预设区间。
-  发起一次缺陷追溯检索，查看返回结果的相似度分值是否落在预设的阈值区间内，无超出合理范围的异常分值。
-  查看系统日志，确认检索请求调用的是配置的自定义向量模型，未调用默认大语言模型。
-  在多副本部署环境中，查看各副本的索引写入日志，确认无重复写入的记录，且检索响应时间符合预期。
