# 光伏电池片制造的质量问题追溯与不良分析：多轮对话与提示词

本文适配 FastGPT v4.17.0 版本。

## 这个品类的数据长什么样
光伏电池片制造的业务数据多源且结构化特征明确，数据来源包括硅片来料记录、生产MES系统、扩散炉/镀膜设备/印刷机的运行参数、EL与IV测试报告、实验室质检数据。数据按生产批次、单片检测结果更新，日常文档包含工艺卡、扩散和镀膜参数、印刷烧结记录、EL检测图、IV分档数据、良率报告，核心字段包含扩散温度、镀膜厚度、EL缺陷坐标、转换效率等，对应单位包含摄氏度、微米、毫米、瓦/平方厘米等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据按批次与单片更新，多轮对话需要绑定对应生产批次的上下文，避免跨批次数据混淆。多模态的EL检测图与IV测试数据需要提示词明确指定解析规则，确保输出格式匹配业务字段。核心工艺参数的字段与单位严格，提示词需限定可查询的字段范围，防止出现参数混淆。高频更新的批次数据要求对话上下文不能过度冗余，需限制历史对话条数，避免过载影响响应速度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `messages` 历史条数 | 前6–10条 | 匹配单批次数据的更新节奏，避免上下文过载 |
| `chatId` 绑定 | 按生产批次绑定 | 确保对话关联同批次的工艺与检测数据，避免跨批次混淆 |
| 多模态输入支持 | 开启 | 支持解析EL检测图、IV测试数据等非文本类业务数据 |
| `variables` 字段限定 | 限定扩散温度、镀膜厚度等专属字段 | 匹配光伏电池片的工艺参数规范，防止参数混淆 |
| 最大上下文长度 | 1000–1500 token | 适配单批次业务数据的总字符量，平衡上下文完整性与响应速度 |
| 单次请求超时 | 600秒 | 适配多模态图片解析的耗时需求，避免提前触发超时 |

## 容易做错的三处
-  现象为工作流内多轮对话无法延续批次数据，原因是未通过`chatId`绑定对应生产批次的上下文。
-  现象为多模态图片对话触发格式报错，原因是提示词未明确指定EL检测图的解析字段与输出格式。
-  现象为线上对话长时间无响应，原因是未限制聊天历史条数，导致上下文过载触发超时。

## 怎么确认配好了
-  查看对话上下文是否自动关联当前生产批次的工艺参数与检测数据。
-  测试上传EL检测图并提问缺陷位置，确认能正确提取对应业务字段。
-  检查工作流节点的聊天历史配置，确认已绑定对应批次的`chatId`。
-  发起连续多轮提问，确认上下文能正确延续前序提问的批次信息与参数范围。
