# 光伏组件封装的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
光伏组件封装环节的数据来自电池片分档台账、玻璃胶膜背板批次记录、MES系统、串焊与层压设备运行日志、EL测试仪输出图、IV测试报告、绝缘耐压记录等。日常文档包含生产排版图、材料批次表、层压工艺参数表、EL缺陷图、包装清单等。数据按每块组件、每批材料实时更新，字段包含电池片电流档位、层压温度压力参数、EL隐裂位置、功率测试值等，文档结构随设备输出格式略有差异。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据按单组件、单批次高频更新，单条数据体量差异显著，包含结构化批次字段与非结构化图像、测试报告。检索环节需同时支持结构化字段精确匹配与非结构化文档全文召回，避免因数据更新不及时导致追溯偏差。同时，字段包含电池片电流档位、层压工艺参数等强关联质量的内容，需保证召回内容与当前待追溯组件的批次、工艺参数精准绑定，防止无关数据干扰分析结果。此外，跨部门的文档需按串焊、层压等环节分类，确保检索范围聚焦当前问题对应的生产环节。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 适配光伏组件封装的结构化批次字段与非结构化测试报告的匹配精度，平衡召回准确率与覆盖范围，按实测标定调整 |
| `limit` | 前8–12条 | 匹配单组件的多维度数据（批次、工艺、测试），避免过多冗余数据超出上下文窗口，同时覆盖足够的关联记录 |
| `searchMode` | hybrid | 同时支持结构化字段精确匹配与非结构化全文检索，适配该品类混合格式的文档数据 |
| `usingReRank` | 开启 | 对召回结果按与问题的相关性重排序，优化EL隐裂、功率测试等关键内容的展示顺序，提升分析效率 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户的追溯问题自动扩展相关工艺术语，关联层压工艺记录与材料批次数据 |
| `collectionIds` | 按生产环节绑定的知识库集合ID | 限定检索范围为串焊、层压、测试等对应部门的知识库，避免跨环节无关数据干扰 |

## 容易做错的三处
- 现象：调用知识库API时提示未授权，即使已配置有效API key。原因：未将当前应用绑定至对应光伏组件封装的知识库集合，或集合的访问权限未开放给当前API密钥。
- 现象：将`limit`参数调整至2000后，大模型回答未引用任何召回内容，检索详情显示已成功召回数据。原因：未开启`usingReRank`导致召回结果排序混乱，或上下文窗口超出限制后有效内容被自动截断，无法被大模型读取。
- 现象：基于本地文档搭建的知识库回答质量不佳，无法精准匹配电池片电流档位与功率测试结果。原因：未设置`similarity`参数的合理区间，导致召回结果包含大量无关的非结构化文档，或未按生产环节划分知识库集合导致检索范围过宽。

## 怎么确认配好了
- 发起针对特定组件批次的检索请求，核对召回结果中是否包含该批次的材料台账、层压工艺记录与EL测试报告。
- 查看API返回的召回结果列表，确认`limit`参数控制的召回条数符合预设范围，且`similarity`参数匹配结果的相关性符合业务预期。
- 启用`usingReRank`后，核对重排后的结果是否将与当前问题最相关的内容（如层压脱层对应的工艺参数）排在前列。
- 检查应用的权限配置，确认绑定的知识库集合ID正确，且API密钥拥有对应集合的访问权限。
