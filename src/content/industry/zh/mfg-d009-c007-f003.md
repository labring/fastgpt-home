# 冲压与板材成形的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据来源包括钢卷标签与质保书、冲床和送料机运行数据、模具管理系统、MES系统、三坐标或检具检测报告。数据更新节奏为每卷料、每批生产批次、每次换模时触发。日常关联文档包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录，字段涵盖钢卷牌号、冲床压力参数、模具间隙值、首件尺寸偏差值、换模耗时等，单位涉及MPa、mm、小时等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类数据更新频率高且关联多类异构文档，多轮对话需限定上下文范围以避免冗余信息干扰。不同批次钢卷、换模后的参数差异显著，提示词需明确绑定当前生产批次与模具信息的变量。数据字段涵盖设备参数、检测结果等多维度内容，多轮交互中需按业务逻辑逐步引导补充关键信息，避免一次性要求过多字段导致交互卡顿。单次调用的文档数据量较大，需限制上下文窗口的有效内容长度，确保响应速度适配冲压车间的实时分析需求。

## 配置怎么定
以下配置规则基于FastGPT v4.17.0版本制定：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定当前批次钢卷牌号、模具编号、换模时间 | 本品类数据随生产批次、换模操作动态更新，需精准关联当前生产上下文 |
| `messages` | 保留最近3轮交互与首条系统提示 | 冲压不良分析需聚焦当前问题与历史关键参数，过长上下文会拖慢响应速度 |
| `chatId` | 按生产班组+批次号生成唯一标识 | 区分不同生产批次的对话上下文，避免跨批次数据混淆 |
| 最大上下文长度 | 800–1200 字符 | 本品类单批次关联文档数据量较大，限定长度可保证实时分析的响应效率 |
| 问题优化 | 开启并限定优化范围为冲压质量术语 | 过滤无关表述，聚焦开裂、起皱、回弹等典型不良分析场景 |

## 容易做错的三处
- 现象：特定质量问题场景下，AI响应自动截断至200 token以内，即使配置了3000以上的最大回复上限。原因：未在提示词中明确限定冲压不良分析的输出长度，系统触发了默认的短响应保护规则。
- 现象：开启输入引导并配置自定义词库后，调试预览界面出现报错，输入引导无实际效果。原因：未将自定义词库关联至当前的冲压质量分析应用，或词库导入格式不符合系统要求。
- 现象：多轮对话的检索与响应耗时过长，超出车间实时分析的需求。原因：未限定上下文窗口的有效内容长度，系统调用了过多非当前批次的历史文档数据，导致检索与处理效率降低。

## 怎么确认配好了
- 发起一次模拟冲压开裂问题的对话，检查回复中是否自动关联了当前配置的`variables`参数，如钢卷牌号、模具编号。
- 调整最大上下文长度至1500字符，发起多轮交互，确认响应速度符合预期，无明显卡顿。
- 测试不同生产批次的对话，检查`chatId`是否正确区分了不同班组与批次的上下文，无跨批次数据混淆。
- 配置问题优化规则后，输入包含非冲压术语的提问，确认系统自动过滤无关内容，聚焦质量分析场景。
