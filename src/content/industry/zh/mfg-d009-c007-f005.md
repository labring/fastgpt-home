# 冲压与板材成形的质量问题追溯与不良分析：工具调用与插件

## 这个品类的数据长什么样
该品类数据来自冲压车间的钢卷标签与质保书、冲床与送料机运行数据、模具管理系统、MES系统、三坐标或检具检测报告。日常关联文档包含冲压作业指导书、材料利用率表、模具点检表、首末件记录、尺寸检验报告、换模记录。数据更新节奏随每卷钢料、每批次生产、每次换模操作触发，文档字段包含材料牌号、冲压参数、模具型号、检测尺寸、换模时间等，无额外统计数字或百分比。

## 这些特征在「工具调用与插件」这一环带来什么约束
高频更新的数据要求工具调用支持实时或近实时拉取，避免缓存过期导致追溯偏差。多源数据来源需要插件适配对接模具管理系统、MES、三坐标检测设备等不同接口，统一数据格式。多样的文档类型需要工具支持解析冲压作业指导书、尺寸检验报告等不同格式的文件，提取关键参数。换模与批次关联的追溯需求，要求工具调用时自动绑定对应批次的钢卷、换模记录与检测数据，确保关联逻辑准确。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | `auto` | 自动匹配质量追溯所需的多源数据工具，适配多场景调用需求 |
| 工作流/API 函数调用配置 | `enabled` | 启用结构化函数调用，确保工具返回的质量分析数据格式统一，便于后续追溯逻辑处理 |
| 单次工具调用上限 | 前6条 | 冲压场景下单批次关联的检测、换模数据量适中，过多会增加上下文处理负担，过少则无法覆盖质量追溯所需的全部信息 |
| 工具调用上下文缓存时长 | 15–30 分钟 | 匹配每批次生产的周期，避免缓存过长导致数据过期，过短则频繁触发调用影响效率 |
| 插件数据拉取频率 | 按生产批次触发 | 贴合该品类按卷、按批次、按换模更新数据的节奏，避免无效拉取 |
| 工具调用失败重试次数 | 2–3 次 | 应对冲床或模具系统临时波动导致的调用失败，避免过度重试占用资源 |

## 容易做错的三处
- 现象：工具调用返回的关联数据字段缺失，或钢卷牌号、换模时间与当前追溯批次不匹配。原因：未按生产批次触发数据拉取，拉取的是过期的历史数据，无法匹配当前追溯的生产批次。
- 现象：调用外部工具API时响应缓慢，远慢于直接curl调用。原因：未设置合理的上下文缓存时长，导致每次调用都重复拉取全量历史数据，或未限制单次工具调用的返回条数，增加系统处理负担。
- 现象：API调用未返回思维链过程内容。原因：未启用`functionCall`配置项，或未开启结构化输出开关，导致返回格式非结构化，无法提取思维链信息。

## 怎么确认配好了
- 执行单次工具调用测试，核对返回的工具数据是否包含当前批次的关键信息，确认拉取逻辑符合生产节奏。
- 模拟连续调用多个工具，观察响应时长变化，调整缓存时长与调用上限，确保不会出现过度加载或频繁触发的情况。
- 检查API返回结果是否包含结构化的思维链内容，确认`functionCall`配置项已正确启用。
- 模拟工具调用失败场景，观察系统是否按配置的重试次数执行重试，确认失败处理逻辑生效。
