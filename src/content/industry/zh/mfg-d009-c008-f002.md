# 化妆品生产的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自护肤、洗护、彩妆及特殊化妆品生产企业的多类业务文档，包括配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品与成品检验报告、标签审核文件。数据来源涵盖注册备案配方、原料安全资料、生产设备、ERP/MES系统、实验室数据及包材版本资料，更新节奏为每生产批次或每次换线时更新，单份文档包含原料清单、工艺参数、检验结果、批号关联信息等字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的多源异构数据结构、高频更新节奏与强合规关联要求，对向量模型与索引环节形成多重约束。备案配方、生产记录、检验报告等不同格式的数据源，需要索引支持跨格式字段的语义关联；每批次或换线的高频更新，要求索引适配增量同步逻辑，避免全量重建带来的性能损耗。单份文档包含原料清单、工艺参数、批号等强绑定字段，向量模型切片时需保留字段间的关联，防止切片破坏批次全链路信息。同时，质量问题追溯需覆盖完整合规链条，索引召回结果需关联备案、生产、检验全环节数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 匹配化妆品生产文档中工艺参数、检验记录的单段语义长度，避免切片破坏批次关联信息 |
| 重叠长度 | 150–200 字符 | 保留相邻分块间的批次号、原料名称等关键关联信息，防止召回时出现上下文断裂 |
| 相似度阈值 | 0.72–0.85 | 适配配方、检验报告等文本的语义相似度分布，过滤低相关的干扰结果 |
| 单次搜索上限 | 前 8 条 | 覆盖单批次生产的核心关联文档数量，避免召回过多冗余数据 |
| `maxToken` | 4096 token | 适配FastGPT v4.17.0的模型上下文上限，承载完整的批次关联分块内容 |
| `defaultToken` | 512 token | 作为基础检索的默认上下文长度，平衡召回精度与响应速度 |

## 容易做错的三处
- 检索指定批次的配方备案信息时，返回结果中备案配方字段为空。原因：未在索引配置中关联生产记录与备案数据的批次号字段，导致跨文档关联失效。
- 批量执行换线数据更新时，系统触发超时报错。原因：配置了全量索引同步逻辑，未适配每批次/换线的高频更新节奏，导致资源占用过高。
- 检索微生物不合格问题时，召回结果包含大量无关的包材版本文档。原因：相似度阈值设置过低，未过滤语义匹配度不足的干扰内容。

## 怎么确认配好了
- 导入单批次的完整生产文档，执行批次号检索，核对返回结果是否覆盖配方、投料、检验、包材的全链路关联数据。
- 模拟单次换线后的增量更新操作，验证索引仅同步新增数据，未触发全量重建流程。
- 调整相似度阈值，对比不同配置下的召回结果数量，确认匹配范围符合业务需求。
- 查看FastGPT v4.17.0的系统日志，确认向量模型与索引的调用参数与配置项一致。
