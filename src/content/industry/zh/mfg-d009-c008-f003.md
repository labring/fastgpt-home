# 化妆品生产的质量问题追溯与不良分析：多轮对话与提示词

以下配置基于FastGPT v4.17.0版本。

## 这个品类的数据长什么样
化妆品生产的质量追溯数据来源包括注册或备案配方、原料安全资料、称量与乳化设备日志、ERP/MES系统、实验室检验报告、包材版本记录。数据更新节奏为每批生产或每次换线触发，核心文档包含配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验报告、标签审核文件。数据字段包含配方组分占比、限用物质含量、生产批号、乳化温度、均质时长、包材版本号等，部分数据带有物理单位或版本标识。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
化妆品生产的质量数据按批次强关联，每批数据独立且更新频繁，要求多轮对话需精准绑定单批次的上下文信息，避免跨批次数据混淆。多源分散的文档类型需要提示词明确限定检索范围，仅调用当前批次的投料、检验等记录。限用物质、标签宣称等受监管约束的字段，需要提示词精准匹配数据字段，避免泛化检索。同时，每次换线或换配方的操作会改变生产状态，对话需跟踪历史换线信息，确保分析的连贯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `messages` | 保留当前批次的前2轮历史对话，过滤无关批次的上下文 | 化妆品生产批次数据独立，避免跨批次历史信息干扰当前分析 |
| `variables` | 绑定批次号、原料编码、生产设备编号3个核心变量 | 每批生产的配方、记录均与批次强关联，需精准匹配对应数据 |
| 单次搜索上限 | 前5–7条 | 化妆品生产单批次核心数据量有限，过多结果会稀释有效信息 |
| 最大上下文长度 | 800–1200 token | 平衡上下文信息完整性与模型推理效率，适配单批次数据规模 |
| 对话超时时间 | 600 秒 | 化妆品生产的质量分析需要检索多源分散数据，足够的超时时间可确保完整获取批次信息 |
| `chatId` | 绑定单批次生产流程的对话会话 | 完整关联投料、乳化、检验等环节的对话记录，避免会话混乱 |

## 容易做错的三处
- 现象：工作流运行后同时展示多轮AI对话的输出结果。原因：未配置`messages`的上下文过滤规则，保留了所有历史对话的输出。
- 现象：对接飞书或微信渠道时，对话结果携带大量#、*等标点符号。原因：未适配渠道的格式显示规则，导致提示词中的格式标记被直接返回。
- 现象：调用对话接口时，未返回本次对话引用的知识库信息标识。原因：未开启对话日志的知识库关联记录配置，未绑定`variables`的检索范围参数。

## 怎么确认配好了
- 发起单批次的质量追溯对话，检查输出仅包含当前批次的相关数据，无跨批次的历史信息。
- 对接飞书或微信渠道，发送测试对话，确认输出结果无多余的#、*等标点符号。
- 调用对话接口，检查返回结果中包含本次检索的知识库关联标识。
- 上传带图片的知识库文档，发起相关查询，确认模型可正确返回图片的URL链接。
