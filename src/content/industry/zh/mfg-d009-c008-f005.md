# 化妆品生产的质量问题追溯与不良分析：工具调用与插件

## 这个品类的数据长什么样
化妆品生产的质量追溯相关数据，来源包括注册或备案配方、原料安全资料、称量与乳化设备、ERP/MES系统、实验室检验记录、包材版本信息。数据更新节奏为每批生产完成或每次换线时更新。日常文档包含配方工艺单、称量投料记录、乳化或灌装记录、清场清洁记录、半成品与成品检验报告、标签审核文档。核心字段包括限用物质含量、乳化温度、批号、包材版本号、检验合格标识等。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散且更新频率随生产批次变化，要求工具调用需精准匹配每批生产的数据源与更新节点。多类文档的固定字段需严格提取，避免混入无关内容，同时备案配方与标签数据需与官方注册信息完全对齐，不能出现偏差。每批数据量随生产规模变化，工具调用需适配动态变化的内容长度，防止因数据截断导致追溯信息不全。换线时的临时数据需快速触发工具调用，确保不良分析的时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 单次调用超时时间 | 600 秒 | 匹配每批生产数据的生成与拉取周期，避免因设备响应延迟导致任务中断 |
| `toolChoice` | auto | 适配多数据源插件的自动调用逻辑，覆盖配方、设备、检验等多类生产文档 |
| 结果字段提取规则 | 按预设字段名精准匹配 | 严格对应配方工艺单、投料记录中的固定字段，确保提取内容与备案数据一致 |
| `functionCall` | 开启 | 强制按预设参数调用插件，避免返回未授权的敏感信息或无关内容 |
| 插件触发时机 | 按批次号触发 | 匹配每批生产的更新频率，仅在对应批次数据生成后调用工具 |
| 最大上下文长度 | 8000–12000 字符 | 容纳单批次的多类文档内容，避免截断关键追溯信息 |

## 容易做错的三处
- 调用接口时将`stream`设为`true`，无法正确接收最终结果。原因是未配置SSE协议的结果收尾标记，或未按逐行解析的方式处理返回内容。
- 私有部署FastGPT v4.14.1版本时，导入插件提示`internal server error`。原因是插件依赖包与当前运行环境版本不兼容，或端口映射配置存在错误。
- 使用SSE封装的MCP插件时，被提示仅支持stdio进程。原因是未将插件配置为stdio运行模式，或未在本地完成依赖安装与路径绑定。

## 怎么确认配好了
- 在FastGPT v4.17.0版本中，发起单批次生产数据的工具调用请求，检查返回结果是否包含对应批次的配方、投料、检验等核心字段。
- 导入插件后查看系统运行日志，确认无`internal server error`类报错信息。
- 测试`stream`模式调用接口，验证是否能完整接收并拼接所有返回内容，最终结果无缺失。
- 配置`functionCall`后，发起调用并检查返回内容是否仅包含预设提取的字段，未出现无关信息。
