# 化妆品生产的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
该品类数据覆盖护肤、洗护、彩妆及特殊化妆品生产全流程，日常文档包含配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品与成品检验报告、标签审核文件。数据来源涵盖注册备案配方、原料安全资料、生产设备、ERP/MES系统、实验室数据及包材版本信息，更新频率为每批生产或每次换线时更新，核心字段包含原料名称、用量、生产批号、检验指标、包材规格与宣称内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于数据按每批或换线更新，模型需支持高频增量数据接入，避免全量重扫带来的性能消耗。多类文档结构差异大，需适配不同字段的解析规则，比如配方单的原料用量字段需匹配备案数值，标签文件需核对宣称与备案一致。生产环节的关键参数如乳化温度、均质时间需绑定设备日志，模型调用需关联批次号实现数据溯源，同时需严格过滤与备案不符的内容，防止错误信息流入分析流程。适配FastGPT v4.17.0版本的模型接入规则，无需额外适配治疗相关数据模块，重点聚焦合规性与批次关联分析。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 匹配单批生产相关文档的总长度，覆盖配方、投料、检验等多类文件的上下文信息 |
| `maxTokens` | 2000–3000 token | 保障不良分析结果的详细程度，同时避免单次调用超时 |
| `quoteMaxToken` | 1500 字符 | 限定引用文档的片段长度，适配标签审核、配方单等短文档的精准匹配需求 |
| `temperature` | 0.2–0.4 | 降低分析结果的随机性，保障配方、合规性核对的准确性 |
| 工作流/API 工具选择配置 | auto | 允许模型自主选择是否调用工具，适配多文档关联的批次追溯需求 |
| `AIPROXY_API_ENDPOINT` | 按部署的模型服务地址填写 | 关联第三方模型的接入地址，保障模型调用链路正常 |

## 容易做错的三处
- 现象为在第三方API平台配置GPT-4o后，FastGPT页面调用返回401未授权错误。原因是未正确填写`AIPROXY_API_TOKEN`参数，或令牌未开放对应模型的调用权限。
- 现象为部署在本地的DeepSeek模型在模型思考设置中无法被选中。原因是未将`AIPROXY_API_ENDPOINT`配置为本地模型的API地址，或未开启模型的公开访问权限。
- 现象为工作流中前一个AI模型的输出结果无法通过变量更新置为空值，执行后仍保留旧数据。原因是未在变量更新节点中选择正确的作用域，或未触发变量的强制刷新机制。

## 怎么确认配好了
- 发起单批次生产文档的追溯测试，检查模型返回的结果是否关联了对应批次的配方、投料及检验数据。
- 模拟合规性核对场景，验证模型是否能准确匹配备案配方与实际投料记录的差异。
- 调用配置的模型服务，检查返回的响应状态码是否正常，且结果格式符合预期。
- 调整`temperature`参数，验证不同取值下的分析结果是否符合合规性核对的精度需求。
