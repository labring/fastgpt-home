# 化妆品生产的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自护肤、洗护、彩妆及特殊化妆品生产企业的多类业务文档，包括配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品与成品检验报告、标签审核文件。数据来源涵盖注册备案配方、原料安全资料、生产设备日志、ERP/MES系统、实验室数据及包材版本档案，更新节奏为每生产批次或每次换线时更新。文档字段包含原料名称、限用物质含量、生产参数、批号、包材型号等，核心字段均与生产合规流程强绑定。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的文档按生产批次和换线操作更新，单次质量追溯需关联多批次的配方、检验与记录数据，需精准匹配批次号、原料与备案合规信息。高频更新的生产数据要求检索系统支持实时或近实时同步，避免检索到过期数据。文档内容多涉及合规性要求，需严格匹配注册备案信息，避免出现与合规要求不符的召回风险。高并发的生产追溯查询会带来大量检索请求，需控制单批次检索的token消耗，避免超出模型处理上限。

## 配置怎么定
以下配置适配FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配化妆品生产中对配方、备案信息的精准合规要求，避免低相似度的无关文档被召回 |
| `limit` | 前8条 | 平衡检索召回的信息量与模型处理负载，符合单批次生产数据的常规文档量范围 |
| `usingReRank` | 开启 | 针对多维度的生产参数与合规字段，通过重排提升高相关文档的排序优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展批次号、原料名称等字段的检索语义，匹配生产记录中的关联信息 |
| `searchMode` | `embedding` | 适配化妆品生产中需匹配配方、检验结果的语义关联需求 |
| `collectionIds` | 按生产批次划分的知识库集合ID | 限定检索范围，避免跨批次的无关数据干扰，提升检索精准度 |

## 容易做错的三处
- 现象：单批次检索时固定设置5万token的检索引用上限，导致查询延迟过高。原因：未根据实际召回的文档量动态调整token阈值，固定设置大token上限，超出模型实际处理能力。
- 现象：语义检索返回多条匹配文档，但模型回复称未找到相关答案。原因：召回的文档未匹配到问题的核心关联字段（如生产批号、备案配方），或模型未正确加载全部召回的文档内容。
- 现象：AI生成的回复内容与知识库中存储的文档不一致。原因：未开启`usingReRank`或`datasetSearchUsingExtensionQuery`，导致召回的文档排序错误或语义匹配出现偏差，模型调用了非目标知识库的内容。

## 怎么确认配好了
- 查看检索日志，确认召回的文档均属于当前生产批次的知识库集合，核对`collectionIds`的配置是否正确。
- 测试不同生产批号的查询，确认检索结果的相似度符合预设范围，验证`similarity`的配置是否适配业务需求。
- 触发高并发检索请求，确认查询延迟符合业务要求，验证token阈值的设置是否匹配业务需求。
- 开启`usingReRank`后，对比重排前后的文档排序，确认重排功能正常生效。
