# 化妆品生产的质量问题追溯与不良分析：部署与升级

## 这个品类的数据长什么样
本品类数据覆盖护肤、洗护、彩妆及特殊化妆品生产企业，核心文档包含配方工艺单、称量投料记录、乳化灌装记录、清场清洁记录、半成品成品检验报告、标签审核文档。数据来源于注册备案配方、原料安全资料、生产设备日志、ERP/MES系统、实验室检测数据及包材版本记录，更新节奏为每生产批次或每次换线时更新。单份文档包含配方成分、投料量、生产参数、检验指标、批号、包材信息等字段，单位随对应生产环节文档要求调整。

## 这些特征在「部署与升级」这一环带来什么约束
本次部署基于FastGPT v4.17.0版本完成适配。由于数据按生产批次和换线更新，部署时需支持按批次维度同步文档，避免跨批次数据混淆。多源数据来自设备、ERP、实验室等不同系统，部署需兼容多格式接入，且需配置对应权限隔离不同部门数据。单次换线或批次更新频率高，升级时需保证数据同步链路不中断，避免生产环节数据缺失。配方和标签受备案约束，部署时需保留原始数据溯源路径，确保可回溯至备案信息，同时需限制非授权修改生产相关文档字段。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_URI` | 配置为独立集群的连接字符串，预留30%额外连接数 | 化妆品生产数据按批次存储，批次间数据量波动大，预留连接数可避免并发同步时连接耗尽 |
| `REDIS_URL` | 设置为集群模式，键过期时间为86400秒 | 批次数据临时缓存需按生产周期清理，过期时间匹配单日生产批次的处理周期 |
| `STORAGE_S3_ENDPOINT` | 配置为企业内部对象存储服务的端点地址 | 生产文档需本地存储保障合规，内部端点可避免外部网络延迟影响批量文件上传 |
| `DB_MAX_LINK` | 设置为150–200 | 匹配多设备、ERP、实验室的并发数据同步请求量，避免数据库连接池溢出 |
| `FE_DOMAIN` | 配置为企业内部生产管理系统的域名 | 确保溯源页面可与现有生产系统无缝集成，方便生产人员访问 |

## 容易做错的三处
- 本地部署新增模型后测试返回`403 status code (no body)`。原因是未正确配置`ROOT_KEY`权限校验参数，导致接口请求未通过身份验证。
- 调用上传文件API后无法确认文件数据与索引完成状态。原因是未配置对应回调或轮询机制，未绑定文件上传后的状态同步逻辑。
- 升级后无法找到文档界面的升级入口。原因是升级版本的后台配置项路径发生变更，未同步更新内部操作指引。

## 怎么确认配好了
- 尝试同步一批近期的生产批次文档，检查`MONGODB_URI`对应的数据库中是否生成对应批次的数据集合，无连接报错。
- 访问配置的`FE_DOMAIN`域名，确认可正常加载溯源页面且可调用内部生产系统的关联接口。
- 上传一份测试用的配方工艺单，检查`STORAGE_S3_ENDPOINT`对应的存储服务是否成功接收文件，无上传失败日志。
- 配置`REDIS_URL`的键过期时间后，等待对应时长，检查缓存键是否自动清理，无残留无效数据。
