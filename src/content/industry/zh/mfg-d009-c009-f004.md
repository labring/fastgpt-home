# 化学药制剂生产的质量问题追溯与不良分析：工作流编排

## 这个品类的数据长什么样
化学药制剂生产的质量追溯数据，来源包括经批准处方工艺、物料批次、MES/电子批记录、设备与环境监测、LIMS及质量管理系统。数据按每批生产、每个关键工艺步骤及监测计划更新，日常文档涵盖主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差/CAPA/变更文件及批放行审核表。数据字段包含物料批号、工艺参数值、检验结果、偏差描述等，对应单位包括℃、小时、批次号字符串等。

## 这些特征在「工作流编排」这一环带来什么约束
由于数据按批次和关键步骤更新，工作流需绑定批次维度的变量，确保仅检索对应批次的生产与质量数据。多源异构的数据来源要求工作流配置多数据源的关联逻辑，避免跨批次数据混淆。GMP合规要求下，工作流需严格限定文档检索范围，仅调用当前批次的合规文档，同时需设置异常分支，对应批次放行失败、数据完整性缺陷等风险场景。此外，数据更新的实时性要求工作流触发时机需匹配生产节点，确保追溯结果与生产流程同步。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 变量绑定 | 绑定`variables`中的批次号、物料批号字段 | 数据按每批生成更新，需精准关联对应批次的生产与质量数据 |
| 节点触发时机 | 按`nodeId`绑定的生产步骤事件触发 | 需匹配生产流程节点，确保数据调用与实际生产同步 |
| 知识库调用范围 | 限定检索当前批次的批记录、检验报告 | 符合GMP下数据溯源的严谨要求，避免无关文档干扰 |
| 单次执行超时 | 300–600 秒 | 覆盖批记录复核、偏差汇总的常规耗时区间 |
| 分支执行逻辑 | 按追溯结果状态触发对应分支 | 区分正常追溯与异常偏差的处理路径 |
| 异常处理配置 | 触发CAPA流程节点并推送告警 | 对应出错后需快速响应的业务要求 |

## 容易做错的三处
- 现象：使用API调用工作流嵌套知识库助手时返回空值；原因：未在`variables`中传入正确的批次号参数，导致知识库无法匹配对应批次的文档。
- 现象：知识库变量引用时提示`quote type error`；原因：未按要求将批次号作为字符串类型传入`variables`，格式不符合系统校验规则。
- 现象：工具调用模块同时打印AI回复并执行下一级分支；原因：未配置分支触发的条件判断逻辑，导致多路径并行执行。

## 怎么确认配好了
- 传入测试批次号，检查工作流是否能检索到对应批次的批生产记录、检验报告等文档。
- 模拟异常偏差场景，验证工作流是否触发预设的异常处理分支。
- 调用FastGPT v4.17.0版本的API，传入`variables`参数，确认返回结果不为空。
- 调整单次执行超时设置，验证工作流在预设时长内完成执行。
