# 化学药制剂生产的质量问题追溯与不良分析：数据库与运维

## 这个品类的数据长什么样
数据来源包括经批准的处方工艺、物料批次信息、MES系统的电子批记录、设备与环境监测数据、LIMS系统的检验结果、质量管理系统的偏差与CAPA记录。数据更新遵循每批生产、每个关键工艺步骤、按固定监测计划的节奏。日常文档包含主生产文件、批生产记录、批包装记录、清场记录、检验记录、偏差/CAPA/变更文件、批放行审核表，字段涵盖物料批号、工艺参数值、检验结果、偏差描述等，单位随参数类型变化，如工艺温度为摄氏度、物料重量为千克。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构的数据来源要求数据库支持结构化与非结构化数据的混合存储；高频次的按批、按步骤更新，要求数据库具备高并发写入性能，避免数据阻塞。复杂的文档结构与合规要求，需要数据库支持字段校验与审计追踪，确保数据不可随意篡改。GMP下的文件与操作同步要求，意味着数据库与生产流程的状态必须强一致，运维操作不能影响正在进行的生产批次。一旦数据出现异常，可能导致批次无法放行或召回，因此需要完善的备份与恢复机制，保障数据完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 数据库连接地址 | `mongodb://root:your_password@your_host:27017/fastgpt?authSource=admin` | 适配多源业务数据的持久化存储，支持批记录、LIMS数据的读写 |
| PostgreSQL连接地址 | `postgresql://fastgpt_user:your_password@your_host:5432/fastgpt?schema=public` | 存储结构化的偏差、CAPA与放行审核记录，支持复杂合规查询 |
| 数据库最大连接数 | 20–30 | 满足每批生产过程中的高并发写入需求，避免连接池耗尽 |
| 数据库连接超时时间 | 600 秒 | 避免长连接阻塞，适配生产环节的持续数据写入 |
| Redis缓存地址 | `redis://:your_password@your_host:6379/0` | 缓存实时的设备与环境监测数据，降低主数据库的查询压力 |
| 数据库备份周期 | 每日 0 点 | 保障批记录数据的可恢复性，符合合规要求 |

## 容易做错的三处
- 启动FastGPT时出现`init root user error`日志，无法完成数据库初始化。原因：未正确配置`MONGODB_URI`的认证参数，或MongoDB服务未正常启动。
- 源码部署后关联Docker部署的数据库，知识库内容未同步到目标实例。原因：未正确填写数据库连接地址，或未执行初始数据同步脚本。
- 批量发起数据库请求后出现连接超时报错。原因：未设置合理的数据库最大连接数，连接池耗尽导致新请求无法建立。

## 怎么确认配好了
- 执行数据库连接测试命令，验证配置的连接地址是否能正常建立连接，连接超时阈值按业务并发量标定。
- 导入一条模拟的批生产记录数据，检查数据库中是否能正确存储并检索到对应的字段信息。
- 查看FastGPT v4.17.0版本的系统监控面板，确认数据库连接数未超过配置的上限，连接状态稳定。
- 触发一次手动数据备份操作，确认备份文件生成正常，备份周期按合规要求设定。
