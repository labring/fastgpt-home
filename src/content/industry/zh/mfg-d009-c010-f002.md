# 医疗器械装配与洁净生产的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
本品类数据来源包括设计历史文件、器件与材料批次记录、MES系统、洁净环境监测设备、灭菌设备、检验校准系统。数据更新节奏为每批产品或每台设备生成一次，同时按环境监测计划定期更新。日常文档涵盖生产工艺规程、批生产记录、洁净区运行记录、灭菌批记录、检验报告、软件版本记录、不良事件与追溯资料，字段包含唯一器械标识、材料批次号、洁净环境参数、灭菌参数、检验结果等。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的批次化高频更新数据，要求向量索引支持增量同步机制，避免全量重建带来的服务器负载波动。多类型文档混合的特征，涵盖工艺规程文本、参数记录、监测数值等，要求索引能兼容非结构化文本与结构化字段的向量映射，同时匹配`maxToken`与`defaultToken`的设置以适配不同长度的文档。唯一器械标识、材料批次号等强关联字段，需要在索引阶段绑定对应元数据，以支撑后续的精准追溯。高精度的洁净环境、灭菌参数数值，要求向量模型适配数值型特征的编码精度，避免特征丢失。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配本品类的工艺规程与记录文本长度，避免块内关键信息断裂 |
| 重叠长度 | 100–200 字符 | 保留相邻块的上下文关联，覆盖批次号、灭菌参数等跨块关键信息 |
| 相似度阈值 | 0.75–0.85 | 平衡检索准确率与召回率，适配高精度的参数与标识匹配需求 |
| `maxToken` | 8192 token | 满足长文档如完整批生产记录的向量编码需求 |
| `defaultToken` | 2048 token | 适配单条非结构化记录的常规编码长度 |
| 单次召回上限 | 前 10 条 | 控制检索返回量，避免服务器过载，适配批量追溯的查询场景 |

## 容易做错的三处
- 现象：批量上传多份批生产记录与洁净区记录后，服务器重启，知识库状态显示未就绪且无自动索引动作。原因：未配置增量索引触发规则，全量索引任务在服务器异常重启后中断，未自动恢复。
- 现象：更新FastGPT版本后，原有灭菌批记录的索引无法返回检索结果。原因：旧版本索引的向量编码维度与新版本默认模型不匹配，未重新生成对应向量。
- 现象：检索不良事件追溯资料时，返回结果包含无关的工艺规程文本。原因：未绑定唯一器械标识的元数据过滤规则，导致向量检索未关联批次字段进行精准匹配。

## 怎么确认配好了
- 上传单份批生产记录，查看索引生成进度，确认无异常报错。
- 输入包含特定材料批次号的查询，核对检索结果是否关联对应批次的文档。
- 调整相似度阈值后，验证检索结果的数量变化是否符合预期。
- 重启服务器后，检查知识库状态是否自动恢复就绪，无需手动触发索引。
