# 医疗器械装配与洁净生产的质量问题追溯与不良分析：工具调用与插件

## 这个品类的数据长什么样
该品类的数据主要来自设计历史文件、器件与材料批次台账、MES系统、洁净环境监测设备、灭菌设备、检验校准系统。日常留存生产工艺规程、批生产记录、洁净区运行记录、灭菌批记录、检验报告、软件版本日志、不良事件与追溯档案。数据更新按每批产品或每台设备执行，同时按固定环境监测计划同步洁净区参数。数据字段包含唯一器械标识、材料批次号、灭菌温度与时长、洁净区温湿度、软件版本号、检验结果等，对应单位包括摄氏度、分钟、帕斯卡等。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据分散在多类系统与文档中，工具调用需支持对接多源数据接口，拉取关联批次的全量台账信息。数据更新频率按单批或单台设备执行，同时按固定周期同步洁净环境参数，工具调用需支持按批次触发查询，避免冗余拉取非关联数据。数据字段包含合规性强的唯一器械标识、灭菌参数等，工具调用需保留原始字段格式与单位，不能擅自修改。不良事件追溯需关联设计历史与生产记录，工具调用需支持跨文档的精准关联匹配，确保追溯链路完整。

以下配置基于 FastGPT v4.17.0 版本制定。
## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多源数据查询场景，自动判断是否触发工具调用以获取批次关联信息 |
| `functionCall` | `enabled` | 明确启用函数调用能力，确保合规字段如唯一器械标识、灭菌参数被正确提取 |
| 工具调用超时设置 | `120 秒` | 多源数据拉取需足够时间，避免因数据量大导致调用失败 |
| 单次工具返回上限 | `前 10 条` | 单批产品关联数据条目有限，避免冗余信息干扰不良分析 |
| 工具触发规则 | 按批次关键词匹配 | 该品类数据按批次组织，需精准匹配批次号触发工具调用 |

## 容易做错的三处
- 现象：尝试替换内置文档解析工具时，配置修改后未生效。原因：未同步更新`functionCall`中的工具绑定参数，系统默认调用初始配置的解析工具。
- 现象：调用OpenApi聊天接口时返回参数不合法报错。原因：未按要求格式设置`toolChoice`参数，导致系统无法识别工具调用请求。
- 现象：批量查询批次数据时，返回结果条数不足。原因：未调整单次工具返回上限配置，默认条数少于单批产品的关联数据条目。

## 怎么确认配好了
- 输入单批次的唯一器械标识关键词，核对工具调用返回的结果是否包含对应批次的生产记录、灭菌参数与不良事件档案。
- 调用OpenApi聊天接口，检查返回报文是否包含正确的`functionCall`参数标识，无格式错误。
- 查看系统工具调用日志，确认触发条件匹配预设的批次关键词规则，超时记录符合设置的时长。
- 切换`toolChoice`参数为`none`，核对系统是否停止自动调用工具，直接返回预设回答。
