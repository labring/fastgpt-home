# 半导体晶圆制造的质量问题追溯与不良分析：工作流编排

## 这个品类的数据长什么样
这个品类的数据通常来自MES系统、设备FDC监控模块、缺陷检测与量测设备、工艺配方库与实验数据库。日常文档包含工艺流程卡、晶圆批次运行记录、设备运行配方、SPC统计图表、异常处置单、晶圆缺陷图谱与良率报告。数据更新频率覆盖每批晶圆流转、设备实时运行状态、每日良率汇总。数据字段包含晶圆批次唯一标识、工艺节点参数、设备运行时长、缺陷空间坐标、良率损耗占比等，部分参数带有纳米、转每分钟、毫秒等专属单位。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据多源分散且更新节奏差异显著，要求工作流支持多源数据的异步拉取与实时对齐。超长工艺链与多返工路径的特性，需要工作流支持跨工序节点的回溯跳转与分支编排。晶圆批次的唯一标识属性，要求工作流绑定`variables`中的批次ID作为核心上下文传递。纳米级工艺参数的强耦合性，需要工作流配置多参数联合校验逻辑；同时有限的返工窗口要求工作流内置超时触发机制，避免无效等待占用生产资源。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的工作流功能设计：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定晶圆批次ID作为核心上下文变量 | 匹配晶圆制造的批次唯一标识属性，确保跨节点数据关联准确 |
| 节点超时设置 | 600–1200 秒 | 适配晶圆制造的单工序平均处理时长，避免因设备延迟触发无效超时 |
| 上下文缓存大小 | 1000–1500 MB | 适配多源工艺文档与批次数据的存储需求，避免缓存溢出 |
| 工具调用分支 | 按缺陷类型二选一触发 | 规避并发调用导致的参数冲突，符合工艺分析的单一判定逻辑 |
| `nodeId` | 绑定关键工艺节点的唯一标识 | 实现跨工序的追溯链路搭建，支持不良分析的节点回溯 |

## 容易做错的三处
- 现象：工作流执行后返回空结果或报错日志显示`empty response`，界面无明确异常提示。原因：未配置`variables`中的批次ID校验，导致多源数据关联失败，或未设置超时触发的兜底分支。
- 现象：工具调用节点出现并发执行，同时触发多个工艺分析分支。原因：未设置按缺陷类型二选一的分支触发规则，导致工作流同时匹配多个判定条件。
- 现象：跨工作流调用时无法精准定位目标节点，出现调用混乱。原因：未通过`nodeId`绑定唯一标识，导致多个工作流的节点参数混淆。

## 怎么确认配好了
- 验证`variables`绑定的批次ID是否能在跨节点调用中完整传递，可通过打印节点日志查看变量内容。
- 测试不同缺陷类型的触发逻辑，确认仅匹配对应分支执行，无并发调用情况。
- 调整节点超时设置，模拟设备延迟场景，确认超时触发的兜底分支正常启动。
- 核对`nodeId`绑定的工艺节点标识，确认跨工序追溯链路可正常跳转。
