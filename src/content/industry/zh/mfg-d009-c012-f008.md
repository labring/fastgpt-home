# 半导体晶圆制造的质量问题追溯与不良分析：文档解析与分块

## 这个品类的数据长什么样
本品类的数据主要来自晶圆厂的MES系统、设备FDC模块、缺陷检测与量测设备、工艺配方库及实验记录。日常产出的文档包含工艺流程卡、批次运行记录、设备配方、SPC控制图、异常处置单、缺陷图谱、良率报告等，部分文档包含纳米级参数字段、晶圆坐标点位及批次关联信息。数据更新节奏覆盖每批晶圆产出、实时设备参数上传及每日良率汇总，文档多为多页PDF格式，包含大量结构化表格与位图类缺陷图谱。

## 这些特征在「文档解析与分块」这一环带来什么约束
纳米级参数与批次绑定的字段要求分块时保留上下文关联，避免拆分跨批次的参数组合；多页结构化表格与位图类缺陷图谱的混合文档，易出现跨页表格拆分或位图解析失败；实时生成的批次运行记录要求解析超时匹配数据更新节奏，避免截断未完成的批次日志；文档来源多为扫描件或受控打印件，可能存在分辨率不足导致的OCR识别误差，需适配低质量文本解析逻辑；超长工艺链的文档结构要求分块时保留工序间的关联逻辑，避免破坏工艺追溯的完整链路。

## 配置怎么定
FastGPT v4.17.0版本下的配置项说明如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 匹配晶圆制造文档中单工序参数组、单页表格的信息密度，避免拆分跨批次关联字段 |
| `chunkSplitter` | 按页眉/页脚分隔优先 | 适配多页工艺流程卡的章节结构，保留单工序的完整上下文 |
| `customPdfParse` | 启用OCR增强模式 | 适配扫描版异常处置单、缺陷图谱的低质量文本与位图内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 180–240 秒 | 匹配每日批量上传的良率报告、多页批次记录的解析时长，避免超时截断 |
| `chunkSettingMode` | 手动配置 | 针对纳米级参数、批次ID等特殊字段，可手动调整分块边界以保留关联逻辑 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持单批次完整的设备配方库文档上传，避免拆分过大的工艺文件 |

## 容易做错的三处
- 上传的结构化表格文档无法正常分块：表现为表格内容被拆分至多个不连续的分块单元，原因是默认分块规则未适配跨页表格的页眉锚点，导致表格被强行按字符长度拆分。
- 部署后无法识别GPU并报显存溢出：表现为容器启动日志提示无可用GPU，或解析时出现显存不足报错，原因是Docker容器未正确挂载GPU驱动与CUDA环境，且`chunkSize`设置超出显卡可用显存阈值。
- Markdown导入后图片域名丢失：表现为生成的Markdown文本中图片仅保留本地相对路径，无原始外链域名，原因是文档解析时未保留原始图片的外链配置信息。

## 怎么确认配好了
- 上传单页SPC控制图文档，检查分块结果是否保留完整的控制限、采样点数据组合，无拆分异常。
- 查看容器启动日志，确认GPU驱动与CUDA版本匹配部署环境，无显存溢出报错。
- 导入含外链图片的Word文档，检查生成的Markdown文本是否保留完整的图片外链域名。
- 上传多页批次运行记录，检查解析日志是否未出现超时截断提示，匹配预设的`PARSE_FILE_TIMEOUT_SECONDS`时长。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
