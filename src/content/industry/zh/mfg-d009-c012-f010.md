# 半导体晶圆制造的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
半导体晶圆制造的日常文档包含工艺流程卡、批次运行记录、设备配方、SPC图、异常处置单、缺陷图谱、良率报告。数据来源包括MES系统、设备FDC模块、缺陷检测与量测设备、晶圆图文件、工艺配方库与实验数据。数据更新节奏为每批晶圆生成专属运行记录，设备参数实时同步，良率报告与工艺调整文档按每日更新。文档字段包含晶圆批次号、纳米级工艺参数、缺陷空间坐标、设备编号等，部分文档附带结构化的参数曲线与图像数据。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的超长工艺链与纳米级参数要求检索需兼顾精准匹配与广度覆盖。多来源的实时与批次级更新数据，要求检索系统支持按晶圆批次、设备编号的精确筛选，避免跨批次的无效数据干扰。结构化的参数曲线与缺陷图谱，要求检索同时支持语义匹配与关键词匹配，确保参数漂移、缺陷分布的查询能召回对应文档。跨模块的良率归因需求，要求召回结果覆盖多个工序的关联文档，同时控制单次检索的token消耗以适配工作流的时间限制。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 匹配晶圆制造的纳米级参数与缺陷描述的精准度，避免召回无关的通用工艺文档 |
| `limit` | 前8条 | 覆盖跨模块良率归因所需的足够上下文，同时控制单轮检索的token消耗 |
| `searchMode` | semantic + keyword | 兼顾工艺参数的语义匹配与晶圆批次号、设备编号的精确关键词匹配 |
| `usingReRank` | 开启 | 对召回的结果按缺陷图谱、良率报告的相关性重排，提升核心不良分析文档的优先级 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展晶圆批次号、工艺步骤的同义查询，比如将「刻蚀工序」扩展为「等离子刻蚀工艺」 |
| `collectionIds` | 按业务模块绑定 | 仅检索工艺整合、设备、良率相关的知识库集合，避免混入无关文档 |

## 容易做错的三处
- 检索结果条数不足，无法覆盖全工序的不良分析依据。原因是`limit`参数取值过低，未覆盖跨模块的工艺关联文档。
- 召回内容与当前问题不匹配，错误返回其他批次的良率报告。原因是未开启`searchMode`的关键词匹配，仅依赖语义召回导致批次号混淆。
- 检索耗时过长导致工作流超时。原因是未限定`collectionIds`范围，检索了全量知识库集合，增加了无效数据的处理开销。

## 怎么确认配好了
- 输入包含已知缺陷类型与晶圆批次号的查询，核对召回结果中是否包含对应的缺陷图谱、该批次的运行记录文档。
- 查看检索结果的排序，确认开启`usingReRank`后，核心的不良分析文档排在前列。
- 测试单轮检索的耗时，确认符合工作流的时间要求。
- 核对检索范围，确认仅返回绑定业务模块下的知识库文档，未混入无关集合的内容。
