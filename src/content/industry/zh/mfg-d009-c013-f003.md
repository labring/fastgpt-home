# 印刷与包装加工的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
本品类数据覆盖彩印、标签、纸箱、软包装及药包材加工全流程，来源包含客户稿件、色彩管理系统、印刷机运行数据、油墨与基材批次记录、分光仪检测结果、条码检测仪报告。日常文档包含印前文件、拼版单、印刷工艺单、油墨配色记录、首件签样、条码检测单、模切与复合台账。数据更新随每订单、每生产批次或每次印版更换触发，单份文档包含版本号、批次号、色彩参数、检测指标等明确字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据高频更新要求对话上下文仅保留近3轮生产相关记录，避免加载过期批次数据。多类型文档的字段差异要求提示词明确指定需匹配的文档类型，例如仅从印刷工艺单提取套准参数，防止混同首件签样的色彩数据。单份订单绑定多环节数据的特征，要求多轮对话中自动关联当前批次号，关联对应拼版单、模切记录等台账。复杂检测指标的提取需求，要求提示词细化字段释义，防止模型混淆条码可读性与封口性能的判定标准。依据FastGPT v4.17.0的上下文管理规则，需动态适配不同批次的文档加载需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 上下文保留轮次 | 前3轮生产对话记录 | 品类数据随订单、批次高频更新，避免加载过期批次的关联数据 |
| `variables`绑定规则 | 绑定当前订单批次号、印版版本号 | 依据FastGPT v4.17.0的变量绑定机制，品类多环节数据需通过批次号关联，精准定位对应拼版单、模切记录等文档 |
| 提示词模板 | 限定仅提取印前文件、印刷工艺单内的指定字段 | 品类包含多类型文档，字段差异大，防止混同色彩参数与条码检测指标 |
| `messages`格式 | 按[角色, 内容]结构传递批次上下文 | 多轮对话需关联历史批次信息，统一数据传递格式以确保模型正确识别 |
| `chatId`关联规则 | 绑定单个生产订单的`chatId` | 单订单绑定多环节数据，隔离不同订单的对话上下文，避免数据串用 |
| 超时设置 | 300–600 秒 | 品类需加载多维度生产数据，预留足够的文档读取与模型处理时间 |

## 容易做错的三处
- 调用对话节点后返回空内容或`empty`字段，原因是未绑定当前订单的`variables`参数，模型无法定位对应批次的生产文档。
- 对话无法读取飞书在线文档内容，原因是未配置文档读取的权限绑定规则，或未在提示词中指定飞书文档的读取格式。
- 开启猜你想问功能后未生成推荐问题，原因是上下文保留轮次设置过多，模型无法从冗余历史对话中提取用户核心诉求。

## 怎么确认配好了
- 手动传入测试订单的批次号，核对对话返回内容是否仅关联该批次对应的文档字段。
- 确认`chatId`与单个生产订单绑定，不同订单的对话会话不共享上下文数据。
- 触发未绑定`variables`参数的测试请求，验证系统是否返回明确的报错提示。
- 调整上下文保留轮次的设置，验证模型响应是否仅基于指定轮次的历史对话内容。
