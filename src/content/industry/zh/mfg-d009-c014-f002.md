# 印染与后整理的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自染整厂、面料企业的染色、定形、实验室与质量部门，涵盖染色配方、称化料记录、染缸曲线、打样确认、色差报告、定形工艺单、污水台账等文档。数据来源于客户色样、配方库、染化料批次、染缸控制设备、测色仪、定形机及环保监测系统，更新频率为每缸、每批或每班，数据包含批次编号、工艺参数、检测结果等字段，单位涉及温度、浓度、时间、色差数值等。

## 这些特征在「向量模型与索引」这一环带来什么约束
每缸每批的高频更新要求索引支持增量同步，避免全量重建耗时过长影响业务响应；多源异构数据（设备曲线、纸质记录、检测报告）需适配不同格式的文本拆分与向量化逻辑；染色配方、色差报告等强关联数据需保留批次与缸号的字段关联，避免向量检索时丢失业务上下文；湿化学加工的批次唯一性要求索引需精准匹配缸号、批次等唯一标识，防止跨批次数据混淆；实时采集的测色仪、环保监测数据需支持低延迟检索，以支撑不良分析的实时反馈。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 该品类文档包含染缸曲线、工艺单等长文本，800–1200字符可保留单缸工艺的完整上下文，避免块内信息断裂 |
| 重叠长度 | 100–150 字符 | 批次编号、缸号等关键标识常出现在块边界，重叠长度可确保关键信息被完整包含在相邻分块中 |
| 相似度阈值 | 0.72–0.85 | 色差报告、染色配方等数据的语义相似度需匹配业务可接受的偏差范围，避免误匹配或漏匹配 |
| 单次搜索上限 | 前8条 | 每缸工艺涉及多类关联文档，前8条可覆盖主要关联数据，同时控制检索耗时 |
| `defaultToken` | 4096 | 染缸曲线等长文本的向量化需适配模型最大token限制，4096可覆盖多数单缸数据的文本长度 |
| 最大上下文 | 按实测标定 | 不同场景下的不良分析需调用的关联文档数量不同，需结合实际业务场景调整 |

## 容易做错的三处
- 界面显示索引中状态长时间无变化。原因：未配置增量同步规则，全量重建高频更新的批次数据时耗时过长，超出系统默认超时限制。
- 自定义索引配置后检索结果无关联度。原因：未将缸号、批次号等唯一标识字段加入分块元数据，导致向量检索无法关联业务上下文，仅匹配零散文本。
- 接入本地m3e模型后检索报错。原因：未适配模型的输入token长度限制，分块长度超出模型支持范围，导致向量化失败。

## 怎么确认配好了
- 上传单缸染色配方与染缸曲线文档，检查分块后的文本是否保留缸号、批次号等关键标识，无明显信息断裂。
- 发起色差相关的检索请求，核对返回结果的关联文档是否属于同一缸号或批次，符合业务关联逻辑。
- 测试新增一批次的化料记录，检查索引是否自动同步更新，无需手动触发全量重建。
- 查看系统日志，确认向量化过程无token超限或格式解析错误的提示。
