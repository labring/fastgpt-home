# 印染与后整理的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类数据主要来自染整厂的染色、定形、质量实验室等部门，日常文档包含染色配方、称化料记录、染缸运行曲线、打样确认单、色差报告、定形工艺单、污水台账。数据来源涵盖客户色样、自有配方库、染化料批次台账、染缸控制系统、在线测色仪、定形机运行数据、环保监测记录。数据更新频率为每缸、每批或每班，单条数据包含批次编号、工艺参数、检测结果等结构化字段与原始曲线类非结构化文件。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于本品类数据更新频率高且单缸数据包含多维度工艺参数与检测结果，模型接入时需适配高频数据同步的上下文加载需求。多源异构的染缸曲线、色差报告等非结构化数据，要求配置支持多模态输入的模型调用参数。单条数据的批次关联性强，需确保模型调用时能精准绑定对应批次的会话上下文，避免跨批次数据混淆。同时，因不良分析需快速响应生产环节，模型调用的输出长度需匹配生产节拍，不宜过长或过短。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配本品类多批次关联的上下文需求，覆盖单缸全流程工艺与检测数据 |
| `vision` | 开启 | 支持解析染缸曲线、色差报告等图像类非结构化数据，匹配品类数据特征 |
| `temperature` | 0.2–0.4 | 降低随机输出，确保不良分析结果的工艺一致性，符合生产环节的严谨性要求 |
| `AIPROXY_API_ENDPOINT` | 填写私有化部署模型的接入地址 | 适配火山云等私有化部署场景的调用需求，符合行业数据安全要求 |
| `maxTokens` | 2000–3000 token | 控制单轮分析输出长度，避免超时，匹配生产环节的快速响应需求 |
| 工作流/API 工具选择配置 | auto | 自动选择是否调用工具，适配多源数据关联分析的场景 |

## 容易做错的三处
- 现象：调用模型时会话ID未正确传递，导致跨批次的分析结果混淆。原因：未在模型调用参数中绑定当前生产批次的会话标识，未遵循FastGPT的会话上下文传递规则。
- 现象：deepseek-r1 671b模型调用时返回伪造的引用ID，导致追溯结果无法匹配实际染缸批次。原因：未配置模型的引用ID校验逻辑，未绑定实际生产数据的批次编号作为引用依据。
- 现象：Docker本地部署的FastGPT无法连接火山云私有化模型，接口返回连接超时。原因：未正确配置`AIPROXY_API_ENDPOINT`的网络访问权限，未开放本地容器与火山云服务的端口映射。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本发起一次针对单缸染整数据的分析请求，检查模型返回结果中是否包含当前批次的会话标识，确认上下文绑定正确。
- 上传一张染缸曲线图片，验证模型是否能正确解析图像中的温度、加料量等参数，确认`vision`配置生效。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`的地址与火山云私有化部署的模型地址一致，无网络连接错误。
- 连续发起高频分析请求，检查模型返回结果的工艺一致性，确认`temperature`与`maxTokens`配置符合生产节奏要求。
