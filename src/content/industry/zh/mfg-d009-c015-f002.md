# 原料药与医药中间体生产的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
该品类的核心业务部门涵盖合成、发酵、精制、质量与注册支持模块，日常产生的文档包括批生产记录、物料平衡表、反应与精制记录、清洁验证记录、杂质谱报告、偏差与变更文件。数据来源覆盖注册工艺文档、原料批次台账、DCS系统、称量系统、LIMS实验室信息管理系统、色谱数据系统与QMS质量管理系统，更新频率为每生产批次、每工艺步骤一次。文档字段包含批次号、反应参数、杂质含量、溶剂残留量等专业内容，格式涵盖结构化表格与非结构化文本。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据多源异构且更新频率高，每批次生产都会产生新的文档与数据，需支持批量增量索引。文档包含长文本的反应记录与专业度较高的杂质谱报告，对文本拆分的连贯性要求较高。字段多为与质量强相关的专业参数，向量索引需精准匹配批次号、杂质含量等关键标识，避免泛化检索导致的无关结果。同时多系统来源的数据格式不一，需在索引前完成统一的字段映射与格式校验。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类包含长文本的反应记录与杂质谱报告，保证专业内容的拆分连贯性 |
| 重叠长度 | 100–150 字符 | 保留多步反应记录的步骤衔接上下文，避免拆分后丢失工艺关联逻辑 |
| `maxToken` | 8192 token | 适配专业术语密集的长文档解析，满足杂质谱报告等长文本的向量编码需求 |
| 相似度阈值 | 0.75–0.85 | 精准匹配批次号、杂质含量等关键质量字段，过滤低相关的检索结果 |
| 单次搜索上限 | 前 10 条 | 控制多源数据下的返回结果数量，保障质量追溯的检索效率 |
| 重排 | 按实测标定 | 结合该品类的批次关联、工艺步骤优先级调整排序规则，适配业务追溯逻辑 |

## 容易做错的三处
- 现象：调用知识库接口创建索引后检索速度变慢，返回结果条数超出预期。原因：未针对该品类的多源异构数据调整分块与搜索上限配置，导致索引分片过多且返回冗余数据。
- 现象：更换embedding模型后，已导入的文件集合无法快速重新生成索引，需重新导入全部文件。原因：未使用批量重新索引功能，仅通过单文件导入流程处理，未匹配该品类按批次批量更新的业务需求。
- 现象：检索结果排序不符合业务优先级，无法准确关联杂质超标与对应生产步骤。原因：未结合该品类的专业字段（如批次号、反应釜编号）调整排序逻辑，仅依赖通用相似度计算。

## 怎么确认配好了
- 查看FastGPT v4.17.0的索引生成日志，确认分块后的文本长度落在设定的分块长度区间内。
- 调用知识库接口执行测试检索，验证返回结果的数量不超过单次搜索上限的设定值。
- 对比更换embedding模型前后的检索结果，确认已完成批量重新索引操作，无需重新导入文件。
- 模拟杂质超标场景发起检索，验证结果优先关联对应批次的反应与精制记录，符合业务追溯逻辑。
