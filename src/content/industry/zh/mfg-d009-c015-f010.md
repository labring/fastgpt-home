# 原料药与医药中间体生产的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来自注册工艺文档、原料批次记录、DCS系统、称量系统、LIMS、色谱数据系统及QMS等多类业务系统。日常文档包含批生产记录、物料平衡表、反应与精制步骤记录、清洁验证记录、杂质谱报告、偏差与变更文件，字段包含批次号、反应温度、杂质含量、溶剂残留量、收率数据等，更新频率为每生产批次、每工艺步骤一次，数据结构随工艺路线与注册要求动态调整。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源要求检索功能需支持跨系统数据关联，避免仅检索单一文档类型导致追溯不全；高频次的批次级更新要求知识库需支持增量同步，确保检索结果与当前生产批次数据一致；专业文档如杂质谱报告、注册工艺文件的术语特殊性，要求检索需匹配高相关性的专业片段；出错后果严重的特性要求召回结果需具备较高置信度，避免错误关联导致偏差分析失误。同时，多步化学路线的追溯需求，要求检索结果需覆盖从原料到成品的全流程关联数据。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的逻辑制定：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配杂质谱、注册工艺等专业文档的高相关性要求，避免低匹配度的无关内容混入检索结果 |
| `limit` | 前10条 | 覆盖多步反应、转序环节的关联数据，同时控制上下文长度避免超出模型限制 |
| `searchMode` | `embedding` | 针对专业术语与长文本片段的匹配需求，优先使用向量检索模式 |
| `usingReRank` | `true` | 对召回的初始结果进行重排序，提升杂质谱、批生产记录等长文档的相关性排序准确性 |
| `datasetSearchUsingExtensionQuery` | `true` | 支持扩展关联批次号、DCS数据等多源业务字段，满足全流程追溯的查询需求 |
| `collectionIds` | 指定目标原料药生产知识库的集合ID | 隔离不同品类的知识库数据，确保检索仅覆盖当前业务场景的文档内容 |

## 容易做错的三处
- 调用`/api/v1/chat/completions`接口时传入appId后无法检索到已上传的知识库内容，原因是未通过`collectionIds`参数指定绑定的知识库集合ID。
- 设置`similarity`阈值后检索结果为空或条数过少，原因是阈值设置过高，过滤了符合专业匹配度的杂质谱、批生产记录等核心文档。
- 检索结果未关联原料批次或DCS系统的工艺数据，原因是未开启`datasetSearchUsingExtensionQuery`扩展查询功能，无法关联多源业务字段。

## 怎么确认配好了
- 调用FastGPT的知识库列表接口，确认目标原料药生产知识库的集合ID与配置的`collectionIds`参数一致。
- 输入测试问题，如“某批次原料药的杂质超标原因”，检查返回结果中包含批生产记录、杂质谱报告等对应文档片段。
- 调整`similarity`阈值，观察检索结果条数的变化符合预期，阈值降低时结果条数增加，阈值升高时结果条数减少。
- 开启`usingReRank`后，检查排序靠前的结果与测试问题的相关性高于初始召回结果。
