# 喷涂与涂装的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
这个品类的数据涵盖涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账等文档，数据来源包括涂料供应商TDS/SDS、喷房和烘炉设备采集数据、色差仪、膜厚仪、环境监测系统与MES系统。数据更新频率覆盖每批涂料、每班生产与连续设备采集场景，字段包含膜厚、色差ΔE、烘炉温度、涂料黏度等量化指标，以及工艺步骤、缺陷类型等文本描述。

## 这些特征在「向量模型与索引」这一环带来什么约束
涂装与喷涂场景的多源异构数据特征，对向量模型与索引环节带来多重约束。多类文档的长度差异大，长文档如烘炉曲线、工艺卡需要适配长文本编码，高频采集的设备数据需要避免过度分块导致工艺窗口断裂。批次级关联需求要求索引支持按涂料批次、生产班次的元数据过滤，防止跨批次的错误匹配。同时，缺陷分析需要关联外观描述与量化检测数据，向量编码需兼顾文本与结构化字段的语义对齐，且需支持增量更新以适配连续采集的设备数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配涂装工艺卡、调漆记录等单文档的平均长度，避免跨前处理、喷涂、固化窗口的无关内容被合并 |
| 重叠长度 | 100–200 字符 | 覆盖连续工艺步骤的关键信息，防止分块截断前处理、喷涂、固化的关联数据 |
| 相似度阈值 | 0.75–0.85 | 匹配色差、膜厚等量化检测数据的相似性，结合商业版语义增强索引提升跨文档关联精度，避免误关联非同类缺陷案例 |
| 单次搜索上限 | 前 10 条 | 控制召回的缺陷案例数量，适配涂装缺陷分析的小样本关联需求 |
| `defaultToken` | 4096 | 适配烘炉曲线、工艺卡等长文本的向量编码需求 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 现象：知识库显示文档分8段就绪后变为13段，出现重复索引条目。原因：未开启按文档粒度的去重校验，连续采集的喷房日志被重复上传时未自动合并同批次数据。
- 现象：从v4.9.0升级到v4.9.3后，原有可查询的缺陷追溯结果丢失。原因：版本迭代后默认向量模型的token截断逻辑变更，未重新索引的旧数据无法匹配新的编码规则。
- 现象：向量模型批量训练仅支持单文件调整参数，无法批量统一配置。原因：未配置批量索引的任务队列，未启用批次级的参数统一调整功能。

## 怎么确认配好了
- 上传单份涂装工艺卡，检查分块数量与文档结构匹配度，确认无跨工艺窗口的错误合并。
- 发起缺陷追溯查询，验证召回结果包含对应的膜厚、色差数据，且相似度阈值符合预设区间。
- 执行批量索引任务，确认所有同批次文档的分块数量一致，无重复索引条目。
- 调整`defaultToken`参数后，重新编码长文档，检查向量编码的完整性，无截断报错。
- 确认FastGPT v4.17.0的版本适配当前配置的参数范围，无版本兼容性报错。
