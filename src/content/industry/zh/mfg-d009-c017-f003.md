# 喷涂与涂装的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
该品类的数据覆盖汽车、家电、工程机械、金属家具的涂装生产线相关记录。日常文档包含涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账。数据来源包括涂料供应商TDS/SDS、喷房与烘炉实时采集数据、色差仪、膜厚仪、环境监测设备及MES系统。更新节奏随每批涂料、每班生产及连续采集的设备数据同步更新，字段包含工艺参数、批次编号、检测数值、时间戳等，部分检测数据带有专用单位如μm、ΔE。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据分散且类型多样，要求多轮对话需按业务流程分步引导，先确认核心标识如涂料批次号、生产班次，再逐步关联对应文档。高频更新的实时设备数据，要求对话上下文需限定在当前生产周期内，避免加载过期的烘炉曲线或调漆记录。专用检测字段如膜厚μm、色差ΔE，要求提示词需明确指定匹配对应单位的文档内容。同时，质量问题关联的环节多，多轮对话需覆盖前处理、喷涂、固化全窗口，逐步缩小问题范围，减少后续分析的误差。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables` | 绑定涂料批次、生产班次 | 快速过滤对应生产周期内的文档，缩小检索范围 |
| `messages` | 按生产班次顺序拼接最近3轮上下文，保留8000–12000 token | 保留业务逻辑，避免截断长文档 |
| `chatId` | 绑定车间编号、设备ID | 隔离不同涂装线的对话数据，防止跨车间文档混淆 |
| 单次召回上限 | 前6条 | 覆盖涂料批次单、膜厚色差报告、烘炉曲线等核心业务文档 |
| 语义优化 | 开启 | 针对流挂、橘皮、附着力等专业术语优化语义匹配 |
| 对话超时阈值 | 50–70秒 | 适配现场工程师的操作节奏，避免等待超时 |

## 容易做错的三处
- 对话超时：界面显示请求超时提示或返回504状态码，原因是未根据现场操作节奏调整对话超时阈值，设置的阈值过短导致未完成文档检索就中断流程。
- 误引入无关知识库内容：普通对话调用时返回非涂装类文档的结果，原因是未正确配置`variables`绑定规则，导致系统默认召回全量知识库内容。
- 重复触发提示词：多轮对话中反复弹出预设提示词，原因是未正确配置`messages`的上下文轮次限制，导致系统重复调用提示词模板。

## 怎么确认配好了
- 输入已知的涂料批次号，核对系统召回的文档是否包含对应批次的调漆记录与膜厚报告。
- 设置超时阈值后，模拟现场操作流程，确认对话等待时长符合预期，无超时报错。
- 测试多轮对话，依次询问问题类型、生产班次、检测数值，确认系统逐步优化检索范围并返回精准结果。
- 切换绑定的`chatId`为不同车间编号，确认系统仅召回对应涂装线的文档数据，无跨车间内容混入。
