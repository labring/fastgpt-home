# 喷涂与涂装的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据覆盖汽车、家电、工程机械、金属家具等涂装生产线的全流程。日常文档包含涂装工艺卡、涂料批次单、调漆记录、膜厚色差报告、烘炉曲线、缺陷返修单、VOCs台账。数据来源包括涂料供应商TDS/SDS、喷房与烘炉运行数据、色差仪、膜厚仪、环境监测设备及MES系统。更新节奏随每批涂料、每班生产及连续采集的设备数据推进，字段包含涂料批号、涂-4黏度秒数、膜厚μm值、烘炉温度时间参数、色差ΔE值等。

## 这些特征在「模型接入与配置」这一环带来什么约束
涂装场景的多源、高频更新数据特征，对模型接入配置带来多重约束。首先，多类结构化与非结构化数据混合，要求模型支持多模态输入或向量模型适配多字段索引；其次，高频更新的批次与设备数据，要求上下文长度匹配生产窗口的时序跨度，覆盖前处理、喷涂和固化的关联分析；第三，不同来源数据的字段单位差异，要求配置阶段明确数据映射规则，避免参数匹配偏差；第四，涉及VOCs台账等合规数据，需确保模型调用的权限与数据处理符合场景要求。此外，本地模型接入时需适配设备数据的采集频率，避免超时或索引不完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 匹配涂装全流程的单批次生产文档总长度，覆盖工艺卡、批次单与缺陷记录的关联分析 |
| `temperature` | 0.1–0.3 | 确保不良分析结果的一致性，避免因随机波动导致缺陷判定偏差 |
| `vision` | 开启 | 适配色差仪、膜厚仪生成的图像报告，支持直接解析图片格式的检测数据 |
| `quoteMaxToken` | 2000 字符 | 限制引用的单条文档长度，聚焦涂装工艺参数与缺陷关联的核心内容 |
| `AIPROXY_API_ENDPOINT` | 按部署的本地模型地址填写 | 适配ollama、阿里千问等本地或云端模型的接入路径，确保请求正确路由 |
| `AIPROXY_API_TOKEN` | 填写对应模型的授权密钥 | 完成模型身份验证，解决接入失败的权限校验问题 |

## 容易做错的三处
- 现象：配置`AIPROXY_API_ENDPOINT`时填写错误的ollama本地地址，向量模型接入失败，界面提示连接超时。原因：未匹配ollama默认的端口路径，或混淆了大模型与向量模型的接入地址。
- 现象：选择阿里千问text-embedding-v3时，提示无可用渠道。原因：未在专属分组中配置对应模型的调用权限，默认分组未开通该embedding模型的使用资格。
- 现象：本地ollama模型调用时返回token超限报错，或上传的色差仪图片未被解析。原因：未根据模型实际支持的最大token限制调整参数，或未开启`vision`配置适配图片输入。

## 怎么确认配好了
- 基于FastGPT v4.17.0版本的配置界面，发起一次模型测试调用，确认返回正常的文本或缺陷分析结果。
- 上传单份涂装色差仪拍摄的图片报告，验证`vision`配置是否生效，查看返回结果中是否包含图片解析的检测内容。
- 导入一批涂料批次数据，查看向量索引的更新状态，确认数据字段与配置的映射规则匹配。
- 调整`temperature`参数为不同区间，对比两次分析结果的一致性，确认配置符合场景的稳定性要求。
