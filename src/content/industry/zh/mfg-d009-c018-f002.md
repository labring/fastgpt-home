# 基础化工连续生产的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
基础化工连续生产的典型数据涵盖操作规程、工艺指标卡、DCS趋势、化验报告、联锁旁路记录、特殊作业票、班报等文档。数据来源包括DCS/SIS系统、在线分析仪、LIMS系统、设备状态监测、能源计量装置与原料储罐管理系统。数据更新频率覆盖实时、每班、每日三类，其中DCS趋势与在线分析仪数据为实时更新，班报与化验报告多为每班或每日更新。文档包含时间戳、带单位的工艺参数值、批次编号、操作记录等字段。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时高频的DCS与在线分析仪数据要求索引支持低延迟增量同步，避免全量重建的额外开销；多类型文档混合存在，既有结构化的参数表格与化验报告，也有非标准化的作业票与操作规程，需要适配不同格式的分块与向量生成规则；不同更新频率的数据需采用分层索引策略，区分实时数据与批量文档的索引触发逻辑；工艺数据包含明确的单位字段，向量生成时需保留单位信息以保证语义匹配的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配DCS趋势、化验报告的单段数据长度，避免跨批次语义断裂 |
| 重叠长度 | 50–80 字符 | 保留跨块的工艺关联信息，防止分块切断联锁报警的上下文 |
| 相似度阈值 | 按实测标定 | 适配基础化工工艺参数的语义匹配精度，平衡召回率与误报率 |
| 单次搜索上限 | 前10条 | 覆盖单批次质量问题的关联数据量，避免冗余信息干扰 |
| `defaultToken` | 4096 token | 匹配多模态Embedding模型的输入上限，适配长文档的向量生成 |
| `maxToken` | 8192 token | 支持完整的工艺联锁逻辑文本的向量编码 |

## 容易做错的三处
- 测试多模态Embedding模型时返回Invalid报错，原因是未保留工艺数据的单位信息（如MPa、℃），导致模型无法正确解析参数语义。
- 升级FastGPT v4.17.0后voyage索引无法使用并报400状态码无返回体，原因是未适配基础化工实时数据的更新节奏，增量索引触发频率超出接口限制。
- 尝试重建所有知识库文件索引后出现超时，原因是未对DCS实时数据与班报文档采用分批次索引配置，一次性加载过量数据导致资源耗尽。

## 怎么确认配好了
- 上传一份包含时间戳与工艺参数的DCS趋势文档，检查生成的向量是否包含关联语义信息。
- 发起针对某批次质量问题的追溯查询，核对返回结果中包含对应批次的化验报告与联锁旁路记录。
- 查看索引更新日志，确认实时DCS数据的增量同步延迟符合预设要求。
- 测试多模态Embedding模型的调用，确认返回结果无格式报错。
