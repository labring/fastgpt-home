# 基础化工连续生产的质量问题追溯与不良分析：工作流编排
本文适用于FastGPT v4.17.0。

## 这个品类的数据长什么样
基础化工连续生产的核心数据来源包括DCS/SIS系统、在线分析仪、LIMS系统、设备状态监测、能源计量装置、原料储罐传感器。数据更新节奏分为实时、每班、每日三类。日常关联文档包含操作规程、工艺指标卡、DCS趋势图、化验报告、联锁旁路记录、特殊作业票、班报。数据字段包含工艺参数（压力、温度、流量，单位对应MPa、℃、m³/h等）、批次号、检测时间、联锁位号、旁路时长等，不同文档的字段结构存在差异。

## 这些特征在「工作流编排」这一环带来什么约束
多数据源的更新频率差异要求工作流支持混合触发模式，既可以响应实时数据的触发，也可以按班次、每日周期执行批量任务。多样的文档结构与字段差异要求工作流内的组件需适配不同格式的输入，避免因字段不匹配导致解析失败。强联锁与实时工艺数据的高优先级属性，要求工作流中异常分析节点可被优先调度，且数据拉取需满足实时性要求。连续生产的闭环流程特性，要求工作流支持循环调用相关节点，完成多轮数据验证与分析。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 按数据源类型映射为批次号、工艺参数值、检测时间等核心字段 | 匹配基础化工连续生产质量追溯的核心业务字段，便于后续关联分析 |
| `nodeId` | 为DCS数据节点、化验报告节点、异常分析节点分配唯一标识 | 便于工作流循环调用时精准定位目标节点，避免触发混乱 |
| 循环触发间隔 | 10–30 秒（实时数据）、8 小时（班报数据） | 匹配对应数据源的更新频率，避免重复拉取或延迟处理 |
| 工作流超时时间 | 600 秒 | 适配多源数据拼接与大模型专业分析的耗时需求 |
| 大模型适配配置 | 按实测标定 | 针对化工专业文本的语义特点，选择适配的大模型参数 |

## 容易做错的三处
- 工作流循环调用HTTP接口时出现重复触发，原因是未为循环节点配置唯一`nodeId`，导致工作流无法精准终止循环流程。
- 文本内容提取组件返回空值，重新配置后可正常提取内容，原因是首次配置时未正确绑定`variables`中的化工专业字段，后续重新配置时修正了字段映射关系。
- 部分大模型无法正常提取工艺指标卡内容，原因是未针对化工专业术语优化输入上下文，部分大模型对长流程化工文档的语义理解存在局限。

## 怎么确认配好了
- 触发工作流后查看`variables`的字段列表，确认包含批次号、工艺参数值等核心业务字段，核对字段映射是否与配置一致。
- 测试循环调用HTTP接口，查看节点执行日志，确认触发间隔符合设定值，且无重复触发记录。
- 配置不同大模型运行文本提取组件，验证是否能正常提取化验报告、工艺指标卡中的专业内容。
- 查看工作流运行日志，确认未出现超过设定超时时间的异常中断。
