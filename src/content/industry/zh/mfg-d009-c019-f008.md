# 塑料注塑成型的质量问题追溯与不良分析：文档解析与分块

## 这个品类的数据长什么样
该品类的核心数据来自注塑件生产全流程，日常文档包含注塑工艺卡、原料干燥记录、模具履历、首件检验表、巡检记录表、换料清机记录等，数据来源覆盖树脂批次物性表、注塑机运行参数、模温机数据、MES系统、尺寸与外观检测结果。数据更新频率随生产节奏调整，每批原料投料、每次换模换料、每班巡检均会生成新文档。文档结构差异显著：工艺卡包含充填保压冷却窗口参数表，原料记录标注干燥温度与时长，模具履历记录使用次数与维护周期，巡检表则以短字段记录实时设备状态。

## 这些特征在「文档解析与分块」这一环带来什么约束
由于数据更新频率高且文档类型多样，解析环节需支持批量处理多批次生产文档，避免因单次解析量过大导致超时。不同文档的字段与单位存在明确场景特征，如模温使用摄氏度、注塑压力使用兆帕、干燥时长使用小时，分块时需保留字段与对应参数的关联关系，防止拆分后语义断裂。注塑场景的不良分析依赖完整的生产链路数据，解析环节需确保关键信息（如树脂批次号、模具编号）无丢失，否则将无法完成质量追溯。同时，部分文档包含复杂表格与表单，解析时需精准提取结构化内容，避免冗余或缺失的文本块影响后续分析。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配注塑场景文档的段落与字段长度，避免拆分关键工艺参数组 |
| `chunkSplitter` | 按段落+固定长度混合 | 兼顾长工艺段落与短巡检记录的语义完整性，适配多类型文档结构 |
| `customPdfParse` | 启用 | 支持提取注塑工艺卡、模具履历中的结构化表格与表单字段，提升解析准确性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 满足多批次生产文档、大型模具履历文件的解析耗时需求 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配批量导入多批次生产文档的场景需求 |
| `chunkSettingMode` | 手动模式 | 允许针对不同类型的注塑文档调整分块参数，适配场景化解析需求 |

## 容易做错的三处
- 批量上传注塑生产记录文档时，解析任务返回超时错误。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认配置的超时时长不足以处理多批次文档的解析流程。
- 启用`customPdfParse`后，解析得到的注塑工艺卡表格字段为空。原因：未针对注塑场景的PDF表单调整自定义解析规则，导致结构化参数提取失败。
- 使用FastGPT v4.17.0之前的部分版本时，对话中无法触发文件解析工具。原因：对应版本的内置PDF解析引擎与注塑场景的复杂文档适配性不足，需切换至兼容的解析方式。

## 怎么确认配好了
- 上传一份标准注塑工艺卡PDF，检查解析结果是否完整提取了充填压力、模温、冷却时间等核心参数字段。
- 查看解析任务的运行日志，确认`PARSE_FILE_TIMEOUT_SECONDS`参数生效，无超时类报错信息。
- 随机抽取一段分块后的文本，确认相邻分块包含关联的生产数据与工艺参数，无关键信息被拆分断裂的情况。
- 批量上传5份以上不同类型的注塑文档，确认所有解析任务均能正常完成，无字段丢失或解析失败的情况。
