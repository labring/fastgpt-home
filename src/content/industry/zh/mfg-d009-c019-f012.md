# 塑料注塑成型的质量问题追溯与不良分析：部署与升级

## 这个品类的数据长什么样
该品类的数据涵盖注塑工艺卡、原料干燥记录、模具履历、首件检验、巡检表、换料清机记录等文档，数据来源包括树脂批次和物性表、注塑机参数、模温机、MES系统、尺寸与外观检测设备。数据更新频率为每生产批次、每次换模换料、每班巡检节点，字段包含树脂批次号、模温参数、保压时长、检测尺寸公差等，对应单位为摄氏度、秒、毫米等，包含结构化时序参数与非结构化文档、图片两类数据。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据多源异构且更新频率高，部署时需适配多类数据源的接入格式，升级时需兼容历史生产数据的版本差异。由于数据包含非结构化的文档与图片，需配置适配的存储路径与访问权限；高频更新的时序数据需优化数据库连接配置，避免连接耗尽。同时，不同批次的注塑工艺参数格式存在细微差异，部署时需预设统一的字段映射规则，升级后需验证历史数据的读取兼容性，保障追溯逻辑的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–15 个 | 适配注塑数据每批更新的高频请求，避免数据库连接池耗尽 |
| `MONGODB_URI` | 配置读写分离后缀的连接串 | 存储模具履历、巡检表这类非结构化文档，适配多源数据并行写入 |
| `PG_URL` | 配置连接超时为 300 秒 | 存储注塑机参数、尺寸检测数据这类结构化时序数据，保障批量查询稳定性 |
| `REDIS_URL` | 配置内存上限 2000 MB | 缓存高频读取的树脂物性表、工艺卡模板，降低数据库访问压力 |
| `STORAGE_S3_ENDPOINT` | 按企业本地存储节点配置 | 存储换料清机记录、首件检验照片等文件类数据，适配现有存储架构 |

## 容易做错的三处
- 现象：导入的注塑工艺卡分块后内容丢失，原因：未按文档实际字段配置分块触发规则，误将文档内的普通换行符作为唯一分割符，导致长段落被截断。
- 现象：升级到FastGPT v4.17.0后，历史模具履历数据无法检索，原因：未更新`PG_URL`的连接配置，不兼容新版数据库的权限校验规则。
- 现象：生成应用Api Key时提示权限不足，原因：未配置`ROOT_KEY`作为全局管理密钥，未开启对应应用的密钥生成权限。

## 怎么确认配好了
- 登录管理后台，查看`REDIS_URL`的内存使用监控，确认内存占用符合配置的上限要求。
- 导入一份完整的注塑工艺卡，检查分块后的内容完整性，确认无段落丢失或截断情况。
- 触发一次批量同步模具履历数据，确认数据库连接无报错，数据同步完成。
- 生成应用Api Key，确认可以正常调用检索接口，返回有效结果。
