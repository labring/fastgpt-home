# 安全环保与特殊作业管理的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
本品类服务于化工、冶金、机械、轻工等制造企业的EHS部门与生产检维修团队，日常核心文档包括风险辨识清单、动火/受限空间/吊装等作业票、环境监测记录、危废台账、排放监测数据、事故与隐患整改报告。数据来源覆盖法规标准、在线环保监测设备、气体检测仪、作业人员资质档案、设备隔离清单与监管平台。数据更新节奏包含每次作业完成后更新作业票、实时同步在线监测数据、按固定周期更新资质与台账信息。文档字段包含作业类型、作业时间、监护人员资质、污染物排放数值、隔离措施清单等，部分为扫描件或非结构化文本。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的数据来源分散且包含实时监测、作业流程文档等多种类型，多轮对话需连贯关联作业全流程的上下文，比如从作业票申请到隐患整改的全链路信息。数据更新频率差异大，实时监测数据需在对话中即时调用，而历史台账数据需稳定关联，因此对话上下文不能无限制膨胀。文档多为非结构化或半结构化，提示词需明确指定字段提取规则，避免模糊解析。此外，本品类涉及安全环保责任，对话输出需严格匹配法规与作业要求，提示词需包含校验逻辑，确保追溯结果的严谨性。作业流程的多步骤特性要求多轮对话能逐步补充信息，比如先查询作业票信息，再关联监测数据验证合规性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 会话历史保留条数 | 前6–10条 | 匹配作业全流程的关键信息长度，避免上下文过载 |
| 上下文窗口大小 | 8000–12000 token | 适配多轮作业相关对话的信息总量，覆盖单次作业的完整流程 |
| `chatId`绑定规则 | 绑定同一会话的作业编号 | 确保多轮对话共享上下文，关联同一作业的所有文档 |
| `messages`参数配置 | 按对话顺序拼接历史消息 | 确保多轮对话的消息顺序正确，保留交互逻辑 |
| `variables`绑定范围 | 关联当前作业的作业票、监测记录、资质档案 | 让提示词能调用实时与历史数据 |
| 提示词模板加载规则 | 按作业类型加载对应风险辨识清单 | 匹配不同作业的合规校验要求 |

## 容易做错的三处
- 配置会话历史保留条数为6后，模型无法关联上一轮作业票查询的结果。原因是未通过`chatId`参数绑定同一会话，导致每次请求生成独立上下文，无法保留历史对话信息。
- 从扫描版作业票或非标准格式的监测记录中提取的信息显示乱码。原因是未对非结构化文档做文本标准化预处理，直接传入提示词解析，导致编码或格式识别错误。
- 调用对话接口后无点赞反馈。原因是未在FastGPT v4.17.0中配置自定义交互接口，默认未集成点赞功能，需自行实现对应交互逻辑。

## 怎么确认配好了
- 发起两次连续的作业相关查询，确认模型能关联上一轮查询的作业编号与相关信息。
- 传入一份非结构化的作业票文档，验证提示词能准确提取指定字段的信息，无乱码或缺失。
- 检查`variables`参数是否绑定了当前作业的实时监测数据与资质信息，确保对话中可调用对应内容。
- 验证上下文窗口大小设置后，多轮对话的总token数不会超出预设限制，避免信息截断。
