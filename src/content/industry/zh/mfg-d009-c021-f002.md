# 家具与木制品制造的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
该品类数据主要来自订单设计系统、板材与木材批次台账、数控开料钻孔设备日志、ERP/MES系统、含水率检测设备。日常文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金物料清单、试装与包装记录。数据更新按单、按日或按材料批次触发，字段包含板件尺寸、批次号、工艺参数、检测结果等，无统一固定单位，随文档类型变化。

## 这些特征在「向量模型与索引」这一环带来什么约束
定制订单驱动的多板件属性，要求索引需支持按批次、订单维度关联检索；板件数量多且单订单数据量大，需控制单批次索引的存储与检索效率；文档包含图文混合内容（拆单图、工艺文件），需适配多模态向量处理；高频更新的批次数据，需支持增量索引构建以避免全量重建耗时过长；现场安装关联的孔位、五金信息，要求向量检索需精准匹配字段关联关系。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配拆单图、开料清单的图文混合内容长度，避免块内关键信息断裂 |
| 重叠长度 | 100–150 字符 | 保留相邻块的关联信息，避免板件尺寸、批次号等字段被拆分 |
| 相似度阈值 | 0.75–0.85 | 过滤低匹配度的检索结果，适配单订单多板件的精准匹配需求 |
| 单次搜索上限 | 前 20 条 | 控制检索返回量，避免过多冗余数据干扰不良分析 |
| `defaultToken` | 4096 | 适配涂装工艺、试装记录等长文本的向量生成长度 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 界面提示向量模型配置失败，返回状态码400。原因是未适配该品类的图文混合文档，选择了仅支持纯文本的向量模型，未启用多模态向量支持。
- 检索结果条数远低于预期，仅返回1-2条匹配内容。原因是相似度阈值设置过高，过滤了部分符合要求的板件批次关联数据。
- 索引构建耗时过长，超出预设等待时间。原因是未启用增量索引模式，对全量订单数据进行全量重建，未按材料批次或订单维度拆分索引任务。

## 怎么确认配好了
- 上传一份单订单的拆单图与开料清单，检查向量生成状态是否显示完成，无报错提示。
- 输入“板件尺寸偏差”的检索词，查看返回结果的匹配度是否符合预设的相似度阈值区间。
- 批量导入10份同批次板材的检测记录，检查索引是否按批次完成增量更新，无全量重建提示。
- 查看向量模型的调用日志，确认`defaultToken`与`maxToken`的取值符合配置要求，无文本截断提示。
