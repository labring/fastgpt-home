# 家具与木制品制造的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
该品类的核心数据来自订单设计系统、板材与木材批次台账、数控开料钻孔设备日志、ERP/MES系统及含水率检测设备。数据更新节奏按单、按日或按材料批次执行。日常产出的文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺规范、五金物料清单、试装及包装记录。数据字段多包含板件尺寸、材料批次号、设备运行参数、含水率数值与安装匹配关系，随文档类型变化无统一固定单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据按单、按日或按材料批次更新，多轮对话需通过`chatId`绑定对应订单或批次数据，避免跨单数据混淆。日常文档类型多且结构差异大，提示词需先引导用户明确文档类型，再提取对应字段。板件数量多、安装关联关系复杂，多轮对话需逐步追问缺失参数，例如先确认订单号再调取对应开料清单。数据来源分散，提示词需明确指定检索的数据源范围，避免调用无关的非目标文档内容。定制订单驱动的特性也要求对话流程适配个性化拆单数据，不采用固定BOM的通用逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `chatId` 绑定规则 | 绑定当前订单或材料批次的唯一标识 | 匹配该品类按单/批次管理数据的特性，避免多轮对话跨单调用数据 |
| `variables` 参数配置 | 传入订单号、材料批次号、文档类型等自定义变量 | 帮助提示词精准定位目标数据，适配FastGPT v4.17.0的自定义变量绑定逻辑 |
| 单次搜索上限 | 前8条 | 该品类板件与文档数量较多，避免返回过多无关结果影响对话效率 |
| 最大上下文长度 | 8000–12000 字符 | 容纳多轮对话的历史记录与多份文档片段，适配复杂的质量追溯逻辑 |
| 问题优化开关 | 开启 | 对用户的口语化质量问题进行结构化转换，适配专业文档的检索逻辑 |
| 温度设置 | 0.6–0.8 按实测标定 | 平衡回答的准确性与灵活性，避免生成过于发散的追溯结论 |

## 容易做错的三处
- 现象：在对话中调用知识库时无法检索到指定集合的文档。原因：未在`variables`中传入集合标识参数，导致系统默认检索全量知识库，无法匹配该品类按订单划分的集合逻辑。
- 现象：设置变量引用后，温度设置控件消失无法调整。原因：部分界面逻辑未保留高级参数入口，未提前配置`variables`的同时锁定了温度调整权限。
- 现象：接口调用工作流后，对话日志中的运行数据为空。原因：未通过`chatId`绑定对话上下文，导致工作流返回的追溯数据未关联到当前会话，无法在日志中展示。

## 怎么确认配好了
- 发起测试对话，输入订单号与具体质量问题，检查返回的文档片段是否仅关联当前订单的数据。
- 配置变量引用后，查看对话界面是否保留温度设置控件，或通过调试日志确认温度参数已传入模型。
- 调用接口触发工作流，检查对话日志是否包含工作流运行的详细数据，确认`chatId`已正确绑定上下文。
- 复制对话生成的Markdown内容，检查是否带有正确的回车换行格式，确认前端渲染逻辑未丢失格式参数。
