# 家具与木制品制造的质量问题追溯与不良分析：数据库与运维

## 这个品类的数据长什么样
该品类的数据主要来自订单设计系统、板材与木材批次台账、数控开料钻孔设备、ERP/MES系统及含水率检测设备。日常留存的文档包括拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金配件清单、试装及包装记录。数据更新节奏随订单、批次或每日变化，字段包含订单标识、板件尺寸参数、板材批次编号、设备运行日志、涂装工艺参数、五金型号等，涉及毫米、百分比等单位。

## 这些特征在「数据库与运维」这一环带来什么约束
定制订单驱动的生产模式带来单订单板件数量多、关联数据分散的特点，要求数据库支持多源数据的关联存储与快速查询。多类数据更新节奏差异大，设备实时日志需低延迟写入，批次台账需批量同步，需适配混合读写的负载模式。数据关联依赖订单标识与板材批次号作为主键，需保证主键字段的唯一性与完整性。板件尺寸、涂装参数等数据直接影响最终质量，需避免字段缺失或格式错误，运维环节需定期校验数据一致性。

## 配置怎么定
以下配置均适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/furniture_trace?authSource=admin` | 适配拆单图、设备日志等非结构化数据存储，指定认证源保证访问安全 |
| `PG_URL` | `postgresql://user:pass@host:5432/furniture_erp?sslmode=require` | 存储订单、板材批次、五金清单等结构化关联数据，SSL模式保证传输安全 |
| `DB_MAX_LINK` | `200–300` | 适配多订单并发的批量写入与查询，避免连接耗尽影响生产环节 |
| `REDIS_URL` | `redis://:pass@host:6379/0` | 缓存高频查询的板件尺寸参数、订单关联关系，降低数据库负载 |

## 容易做错的三处
- 现象：数据库连接模块未显示Oracle选项，无法完成数据库配置。原因：当前版本仅内置MongoDB、PostgreSQL、Redis的官方驱动，未集成Oracle连接依赖。
- 现象：Linux环境下部署后连接MongoDB失败，返回连接超时错误。原因：Linux防火墙未开放MongoDB默认端口27017，或配置的`MONGODB_URI`中主机地址与实际部署地址不匹配。
- 现象：无法查询到应用相关的配置信息，提示数据不存在。原因：应用配置信息未正确存储至指定的PostgreSQL或MongoDB数据库中，配置路径与存储库不匹配。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`、`PG_URL`、`REDIS_URL`的连通性，确认无认证或地址错误。
- 导入一条测试订单的关联数据，包含板件尺寸、板材批次、五金清单等字段，校验数据存储格式与预期一致。
- 模拟多订单并发的写入请求，观察数据库连接数未超过`DB_MAX_LINK`的配置阈值，确认负载适配正常。
- 查看运维监控面板，确认数据更新频率与业务节奏匹配，无延迟或丢失情况。
