# 家具与木制品制造的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
该品类典型主体为板式家具、实木家具、定制家居及木门企业。日常产生的文档包含拆单图、开料清单、封边与钻孔程序、涂装工艺文件、五金清单、试装与包装记录。数据来源涵盖订单设计系统、板材与木材批次台账、数控开料与钻孔设备、ERP/MES系统、含水率检测设备。数据更新频率按订单、每日或每批材料执行，字段包含板件尺寸、批次号、工艺参数、检测结果等，需按生产环节适配不同单位体系。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的数据来源分散且格式多样，包含结构化的ERP批次数据与非结构化的工程图纸、程序文件，要求模型接入环节支持多源数据同步与格式适配。定制订单驱动的生产模式导致单批次数据量差异较大，需配置灵活的上下文长度适配不同规模的生产文档。数据更新频率不统一，需按订单、每日或批次设置增量同步规则，避免数据滞后影响追溯准确性。板件数量多且与现场安装尺寸强关联，要求模型召回的相关文档需精准匹配查询维度，减少冗余信息干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 家具制造的拆单图、开料清单等文档长度较大，需容纳多批次生产数据与工艺文档，避免上下文截断 |
| `maxTokens` | 2000–3000 token | 质量问题追溯需输出完整的路径分析，包含批次、工艺、检测等多环节信息，需预留足够输出长度 |
| `quoteMaxToken` | 1500–2000 token | 需完整引用数控程序、涂装工艺等长文本片段用于溯源，避免截断关键工艺参数 |
| `toolChoice` | auto | 需根据用户查询自动选择调用生产数据检索或文档查询工具，适配定制订单的多样化追溯需求 |
| `temperature` | 0.2–0.4 | 质量追溯需严谨结果，降低分析逻辑的随机性，确保追溯路径的一致性 |
| `AIPROXY_API_TOKEN` | 按对应模型的授权密钥填写 | 实现模型的安全接入，避免未授权调用 |

## 容易做错的三处
- 现象：配置知识库时仅同步云盘文件，未关联订单系统与ERP数据，导致追溯时缺失批次与工艺关联信息。原因是未正确配置多数据源同步规则，遗漏生产系统的核心关联字段。
- 现象：部署FastGPT v4.17.0后，OneAPI页面无可用渠道。原因是未正确配置`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`，或未完成模型渠道的绑定校验。
- 现象：工具调用工作流返回结果与预期不符，分析逻辑出现随机偏差。原因是`temperature`参数设置过高，未匹配质量追溯的严谨需求。

## 怎么确认配好了
- 执行测试查询，输入“某批次板件尺寸偏差的追溯路径”，检查返回结果是否关联对应板材批次、开料程序、检测数据与订单信息。
- 查看知识库同步日志，确认订单设计系统、数控设备数据按设定的订单、每日或批次频率完成增量更新。
- 测试工具调用功能，触发生产数据检索，检查是否能正确返回对应批次的五金清单与试装记录。
- 调整`temperature`参数后对比两次分析结果，确认低参数下结果一致性符合质量追溯的严谨要求。
