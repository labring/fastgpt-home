# 家用电器整机制造的质量问题追溯与不良分析：工作流编排
本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
家用电器整机制造的核心数据涵盖空调、冰箱、洗衣机及小家电的生产与售后全流程。日常文档包含配置BOM、装配作业书、制冷剂充注记录、电气安全测试报告、性能抽检报告、返修记录。数据来源包括ERP/MES系统、零部件批次台账、拧紧与充注设备、安规测试仪、性能实验室及售后故障数据库。数据更新频率为每台整机对应一次记录、每班同步工艺数据、按抽检计划生成批量检测报告，字段包含零部件批次号、充注量、测试电压、返修原因等。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的混线生产模式要求工作流需按机型精准过滤数据，避免多型号混线错装；高频次的实时数据更新要求工作流节点需支持动态拉取ERP/MES的最新批次与工艺参数；多类型文档的接入需求要求工作流需兼容上传文件、数据库查询、设备接口等多种数据源；安规、噪声与功能异常的综合判断要求工作流需串联多节点的分析逻辑，同时需确保全局变量的传递准确，避免追溯结果偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 全局变量配置 | 绑定ERP/MES的实时整机数据，按机型分类存储 | 家用电器整机按型号混线生产，需区分不同机型的BOM、批次数据 |
| 文件参数传递 | 开启上传文件的链接自动映射，关联至`variables`参数 | 售后返修记录、检测报告多为上传文件，需通过链接传递至工作流节点 |
| `nodeId`配置 | 绑定拧紧、充注设备的节点ID | 需关联设备实时采集的工艺参数，确保数据来源准确 |
| 节点超时设置 | 600秒 | 安规测试、性能抽检数据拉取需等待设备返回，耗时较长 |
| 变量引用配置 | 按对话上下文绑定当前整机的批次号 | 每台整机的追溯需关联唯一的生产批次数据 |
| 大模型温度设置 | 0.2–0.4 | 不良分析需保持结论严谨，减少随机性 |

## 容易做错的三处
- 现象：配置工作流作为工具调用时，简易任务上传的检测报告文件，无法将文件链接作为参数传入工作流节点。原因：未将上传文件的链接绑定至工作流的`variables`参数，导致节点无法获取传入的文件数据。
- 现象：首次设置的全局变量可在两个组件中正常显示，但在同一对话中修改该变量后，下游节点提示输入为空。原因：未在工作流中配置变量的实时更新触发，仅在初始节点绑定了静态初始值，未同步后续修改的全局变量。
- 现象：AI对话组件选择变量引用的方式指定大模型时，无法找到温度参数的设置入口。原因：未在配置面板中开启自定义温度的开关，默认使用平台预设值，未手动调整至对应区间。

## 怎么确认配好了
- 上传一份家用电器整机的电气安全测试报告文件，查看工作流节点的参数日志，确认文件链接已被正确传入。
- 修改全局变量中的零部件批次号，触发工作流运行，核对下游节点是否加载了更新后的批次数据。
- 打开AI对话组件的大模型配置界面，确认存在温度参数的输入区域，可手动设置数值区间。
- 运行包含混线机型过滤的工作流节点，查看过滤结果是否仅包含当前对话关联的家电型号数据。
