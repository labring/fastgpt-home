# 家用电器整机制造的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类数据涵盖空调、冰箱、小家电等整机产品生产相关的配置BOM、装配作业书、制冷剂充注记录、电气安全测试报告、性能抽检记录与返修档案。数据来源包括ERP/MES系统、零部件批次台账、拧紧与充注设备日志、安规测试仪、性能实验室数据及售后故障反馈。数据更新按单台产品、每班生产批次或抽检计划执行，字段包含零部件批次号、工艺参数、测试结果、返修原因等，随生产环节动态生成。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构数据来自不同设备与系统，格式差异较大，需配置适配多类型文档的解析规则，避免因格式不统一导致模型无法读取关键追溯信息。单台产品的高频更新数据要求模型上下文长度适配单批次生产数据量，防止因上下文溢出丢失关键字段。面向消费者的产品特性要求模型需同时处理安规、外观、功能多维度异常，配置需支持多任务对齐的prompt模板。返修记录与售后数据的关联需要模型具备跨文档关联能力，需合理设置上下文参数限制冗余信息加载，避免分析效率下降。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `AIPROXY_API_ENDPOINT` | 与部署模型的API访问地址一致，如`http://localhost:11434/api` | 适配ollama等本地部署模型的访问路径，确保请求能正确送达目标模型服务 |
| `AIPROXY_API_TOKEN` | 本地部署模型可留空，云端部署需填写对应平台生成的令牌 | 匹配模型服务的鉴权要求，避免鉴权失败导致的请求被拦截 |
| `maxContext` | 8000–12000 token | 适配单台整机的多环节生产数据量，避免上下文溢出丢失关键追溯字段 |
| `maxTokens` | 2000–3000 token | 控制单轮分析的输出长度，确保不良分析结果简洁且可追溯 |
| `temperature` | 0.1–0.3 | 提升不良分析的确定性，避免因随机性导致追溯结果出现偏差 |
| 工作流/API 工具选择配置 | auto | 支持模型自动选择工具处理多维度质量数据，适配多环节关联分析需求 |

## 容易做错的三处
-  配置`AIPROXY_API_ENDPOINT`时填写错误路径，界面返回404状态码。原因是未匹配本地部署模型的实际API访问地址，如ollama默认地址未正确填写端口或路径后缀。
-  工作流调用外部模型时无法实现流式输出，结果仅返回完整内容。原因是未在模型配置中开启流式输出开关，或代码运行模块未正确适配流式数据接收逻辑。
-  配置向量模型时持续报错，无法完成召回。原因是未明确模型的输入输出格式要求，或未按品类数据特征调整向量库的分块规则，导致数据嵌入失败。

## 怎么确认配好了
-  发起一次针对单台整机返修记录的测试调用，检查接口返回状态码是否为200，确认鉴权与地址配置正确。
-  导入单批次的生产测试数据，查看模型上下文加载的内容是否包含关键字段，确认上下文参数适配数据量。
-  提交安规与功能异常的联合分析请求，查看输出结果是否覆盖多维度异常关联，确认多参数配置符合需求。
-  启动流式输出测试，查看工作流是否逐段接收模型返回内容，确认流式配置生效。
