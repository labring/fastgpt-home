# 工艺变更与工程变更的质量问题追溯与不良分析：工具调用与插件

## 这个品类的数据长什么样
本品类的数据来源包括PLM、ERP、MES、供应商资料、验证试验、客户特殊要求，更新无固定周期，每次变更触发一次更新。日常文档包含ECN/ECR、变更评估报告、图纸与BOM版本、工艺验证报告、切换计划、库存处置单、客户批准文件。数据字段包含变更编号、版本号、生效日期、涉及物料/工艺项、审批状态等，版本号采用V.x.x格式，生效日期为标准日期格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源分散的数据来源要求工具调用需对接多个异构系统API，需针对每个系统配置专属调用参数。无固定更新周期要求触发逻辑绑定变更提交节点，需在变更提交后实时拉取最新数据。复杂的文档结构与版本管理要求工具调用需指定版本字段，避免拉取旧版本无效数据。严格的出错后果要求工具调用需配置失败重试与数据校验机制，防止无效数据流入生产环节。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 绑定变更提交节点触发 | 变更数据更新无固定周期，需在变更提交后实时拉取最新版本 |
| `toolChoice` | 设为`function`，启用工具调用 | 需调用PLM、ERP等系统API拉取变更关联数据 |
| `functionCall` | 配置为批量拉取关联文档 | 变更涉及多类文档，需一次性获取完整关联信息 |
| 插件超时时间 | 600 秒 | 跨系统拉取多源数据需较长响应时间 |
| 单次返回文档数 | 前15条 | 变更关联文档数量有限，过多会超出上下文承载上限 |
| 结果校验开关 | 开启必填字段校验 | 变更文档需包含变更编号、生效日期等必填项，防止无效数据 |

## 容易做错的三处
- 调用外部系统API返回514状态码，原因是未配置对应系统的身份校验参数，导致请求被目标系统拦截。
- 选用通用联网插件，未针对PLM、ERP等专属系统配置调用规则，导致无法拉取结构化变更数据。
- 在工作流中配置知识库搜索节点时，变量引用未绑定变更ID，原因是未将外部传递的变更ID作为参数传入，导致无法匹配对应变更的知识库文档。

## 怎么确认配好了
- 手动触发一次变更提交的模拟调用，检查是否能拉取到对应系统的ECN文档。
- 查看工具调用日志，确认`toolChoice`和`functionCall`参数已正确启用。
- 验证变量传递是否能正确绑定变更ID，检查知识库搜索结果是否仅包含当前变更的关联文档。
- 模拟超时请求，确认插件会触发预设的失败提示逻辑。
