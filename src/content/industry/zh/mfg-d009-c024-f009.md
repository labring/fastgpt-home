# 工艺变更与工程变更的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据来自PLM、ERP、MES、供应商资料、验证试验及客户特殊要求，更新节奏为每次变更触发的不定期更新。日常处理的文档包含ECN/ECR、变更评估报告、图纸与BOM版本文件、工艺验证报告、切换计划、库存处置单、客户批准文件，字段包含变更编号、版本号、生效日期、影响工序范围、验证结果及审批状态，无统一固定的单文档长度限制，部分文档包含结构化表格与工程图纸。

## 这些特征在「模型接入与配置」这一环带来什么约束
品类内数据来源覆盖多异构系统，文档包含结构化表格、工程图纸与文本内容，且更新无固定周期，这要求模型接入需适配多模态数据解析、多源数据关联分析的需求。同时变更关联的信息链路较长，需确保模型上下文窗口可容纳完整的变更相关文档片段，避免截断关键追溯信息。此外，变更分析结果直接影响生产排程与客户交付，需保证模型调用的稳定性与输出一致性，因此配置需兼顾灵活性与可控性。

## 配置怎么定
本文档适用于FastGPT v4.17.0版本，以下配置项基于该版本的模型接入界面设置：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 12000–15000 token | 适配ECN、BOM等多文档的关联上下文长度，避免截断关键变更与追溯信息 |
| `maxTokens` | 4096 token | 匹配工艺变更分析的输出长度需求，确保完整生成追溯路径与影响范围 |
| `quoteMaxToken` | 2000 token | 限定引用的文档片段长度，聚焦变更影响的核心工序与物料数据 |
| `toolChoice` | auto | 允许模型自主选择是否调用工具完成变更关联分析与数据提取 |
| `vision` | 开启 | 支持解析工程图纸、BOM表格的视觉内容，适配品类内的图纸类文档 |
| `temperature` | 0.3 | 降低随机性，确保变更追溯结果的一致性与准确性 |

## 容易做错的三处
- 配置自建VLLM模型时出现连接失败报错，原因是`AIPROXY_API_ENDPOINT`未正确填写模型部署的接口地址，或`AIPROXY_API_TOKEN`未匹配模型访问权限。
- 启用视觉分析功能后无法解析工程图纸，原因是未正确开启`vision`配置项，或接入的模型未支持视觉模态推理。
- 模型调用工具时输出中途中断，原因是`maxTokens`设置超出当前模型支持的最大输出上限，或请求过程中出现网络波动导致连接断开。

## 怎么确认配好了
- 访问配置的`AIPROXY_API_ENDPOINT`，验证模型接口可正常返回推理结果或嵌入向量。
- 上传一份ECN文档与关联的工程图纸，触发模型变更分析，检查是否能正确提取变更编号与影响工序信息。
- 发起一次完整的变更追溯请求，确认输出结果完整无截断，无报错日志。
- 调整`temperature`参数为0.3后，重复发起两次相同请求，确认输出结果的一致性。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
