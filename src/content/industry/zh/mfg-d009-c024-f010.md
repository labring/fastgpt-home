# 工艺变更与工程变更的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来源于PLM、ERP、MES、供应商资料、验证试验及客户特殊要求。日常文档包含ECN/ECR、变更评估报告、图纸与BOM版本文件、工艺验证报告、切换计划、库存处置单、客户批准文件。数据更新节奏为不定期，随每次变更流程触发。文档结构包含变更编号、版本号、生效日期、关联物料/工艺节点、审批状态等固定字段，部分文档包含二进制图纸附件。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据来源要求检索支持跨系统关联匹配，避免遗漏跨部门的变更关联信息。不定期的更新节奏要求配置增量同步机制，确保知识库仅包含最新版本的变更文档。文档包含变更编号、版本号等固定字段，要求检索优先匹配精准字段，避免召回无关的旧版本内容。文档关联的上下游影响要求检索覆盖关联物料与工艺节点，保证质量追溯的完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 变更类文档语义相似度要求较高，避免召回无关的旧版本变更内容 |
| `limit` | 前6条 | 变更文档关联项较多，单次召回过多会超出上下文窗口，影响回答连贯性 |
| `searchMode` | `mixedRecall` | 变更文档既有语义关联，又包含变更编号、版本号等明确关键词，混合模式可提升精准度 |
| `usingReRank` | 开启 | 过滤语义相似但版本不匹配的召回结果，确保仅返回目标变更相关内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展变更相关的上下游物料、工艺关键词，覆盖连锁影响的检索范围 |
| `collectionIds` | 指定对应PLM、MES的知识库集合ID | 限定检索范围，避免混入非变更类文档，解决必填字段校验报错 |

## 容易做错的三处
- 现象：查看聊天回答的知识库引用时出现Validation failed: name: Path `name` is required.报错。原因：未配置`collectionIds`参数，未限定检索的目标知识库集合，系统无法匹配必填的集合名称字段。
- 现象：回答中出现未预期的知识库搜索input和response引用内容。原因：未通过`limit`参数控制召回结果条数，或未关闭非必要的检索日志输出。
- 现象：召回结果包含与当前变更无关的旧版本文档。原因：`similarity`阈值设置过低，或未开启`searchMode`的关键词匹配模式，未过滤版本不匹配的内容。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理界面，核对`collectionIds`参数是否已填入对应PLM、MES的知识库集合ID。
- 发起一条包含变更编号的测试查询，检查返回结果的`similarity`分值是否在预设的0.75–0.85区间内。
- 查看回答的引用列表，确认仅包含ECN/ECR、工艺验证报告等目标品类的文档，无无关内容。
- 触发一次变更文档的增量同步，检查知识库是否能正常更新最新的变更版本内容。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
