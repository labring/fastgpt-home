# 工装夹具与检具制造的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自汽车、航空、机械装配企业的工装部门及专用工装供应商，日常产出的文档包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录、变更履历。数据来源涵盖产品数模与GD&T、工艺路线、三坐标数据、现场试用反馈及计量系统，更新按项目推进、伴随每次产品变更及定期校准执行，单份文档包含基准参数、尺寸公差、校准周期、变更节点等结构化字段与非结构化图纸内容。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据特征对向量模型与索引环节带来多重约束。首先，文档混合非结构化图纸描述、结构化公差参数与变更记录，需适配多格式内容的语义编码，避免丢失基准、公差等关键工程信息；其次，数据更新随项目、产品变更及定期校准波动，索引需支持增量更新，避免全量重建占用生产等待时间；三坐标测量数据与校准记录包含高精度尺寸字段，向量分块需保留完整参数语义，不可过度截断；多文档关联查询需求突出，索引需支持跨文档关联召回，确保追溯时可联动定位基准方案与验收结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 分块重叠长度 | `50–80 字符` | 工装文档包含连续的基准方案与变更记录，重叠分块可保留上下文关联，确保追溯时的逻辑连贯性 |
| 相似度阈值 | `0.72–0.85` | 需区分相似夹具定位方案与真实不良关联记录，避免误召回或漏召回关键文档 |
| 单次搜索上限 | 前10条 | 质量追溯仅需核心关联文档，过多结果会增加分析耗时，符合工程场景的检索效率要求 |
| 重排模型 | dengcao/Qwen3-Rerank | 该模型适配工程类文本的语义理解，可准确匹配不良分析的关键词与关联逻辑 |
| `defaultToken` | `2000 token` | 质量追溯需联动多份文档，需保留足够上下文以还原完整工艺与变更链路 |

## 容易做错的三处
- 现象：界面token统计结果与实际编码后的token数不一致，无法按应用维度完成token统计。原因：未针对该品类文档中的公差参数、图纸编号等工程专属字段调整计数规则，导致统计结果出现偏差。
- 现象：向量召回结果与不良品关联度不足，或索引存储占用超出服务器可用空间。原因：分块长度设置不符合该品类文档的语义单元特征，或索引分片未按项目维度规划，导致检索精度下降或资源浪费。
- 现象：向量检索服务无法正常启动，日志提示依赖组件加载失败。原因：直接复用通用向量库compose文件，未移除其中的PostgreSQL模块，导致端口冲突或依赖配置错误。

## 怎么确认配好了
- 上传单份包含GD&T参数的夹具图文档，检查向量分块是否保留了完整的公差参数与校准周期信息，无关键字段截断。
- 发起一次基于不良品编号的追溯查询，核对召回结果包含关联的定位基准方案与验收报告，且结果数量符合预设的单次搜索上限。
- 查看向量库的存储占用与更新日志，确认增量更新可随校准记录、变更履历的提交自动触发，无全量重建触发。
- 使用token统计工具，核对单份工装文档的token计数与实际工程字段的编码长度匹配。
