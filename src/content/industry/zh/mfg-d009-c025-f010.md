# 工装夹具与检具制造的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
本品类的核心数据来自产品数模与GD&T规范、工艺路线文件、三坐标检测数据、现场试用反馈及计量系统。日常文档包含工装需求书、定位基准方案、夹具图、检具操作书、验收报告、校准记录与变更履历。数据按项目交付、每次产品变更、定期校准的节奏更新，文档包含定位基准参数、夹紧方案细节、校准偏差值与变更版本标识，字段多涉及几何公差、检测数值与周期信息。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征对知识库检索召回带来多重约束。首先，文档包含GD&T公差、三坐标检测数值等专业术语，需保障语义检索的精准匹配度，避免泛化召回无关的工装设计文档。其次，单份文档如夹具设计图配套说明篇幅较长，需适配长文本的分块与向量生成逻辑，防止信息截断。再者，数据按项目、产品变更及定期校准更新，需支持按项目标识、变更版本筛选召回结果，确保检索范围贴合当前业务场景。另外，部分文档含计量类数值字段，需支持数值类关键词的精准匹配，提升不良分析的准确性。

## 配置怎么定
本文基于FastGPT v4.17.0版本配置说明，具体配置项及建议如下：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 匹配本品类专业术语的精准召回需求，避免召回无关的工装设计文档 |
| `limit` | 前6条 | 适配本品类单项目关联文档数量，控制上下文长度避免超出模型限制 |
| `searchMode` | `embedding` | 适配GD&T、校准记录等专业内容的语义匹配需求 |
| `usingReRank` | 开启 | 优化长文本分块后的召回排序，提升夹具设计、检具操作类文档的匹配准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 自动扩展专业术语查询，覆盖GD&T、三坐标检测等领域的同义词与规范表述 |
| `collectionIds` | 按项目分类的集合ID | 精准限定检索范围，避免跨项目的不相关文档被召回 |

## 容易做错的三处
- 现象：向量生成失败，或召回的夹具设计文档与查询语义偏差较大。原因：未对数千字的夹具图、校准记录等长文档进行合理分块，直接传入仅支持固定长度输入的向量模型，导致信息截断或匹配失效。
- 现象：检索结果未包含最新的工装变更履历或校准数据。原因：未配置按项目变更、定期校准触发的自动同步逻辑，仅手动上传全量文档，无法实现单个文档的部分内容更新。
- 现象：AI对话输出延迟明显，等待时间超过预期。原因：设置的`limit`参数过大，或未开启`usingReRank`，导致传入大语言模型的上下文长度过长，增加推理耗时。

## 怎么确认配好了
- 执行单项目的工装变更相关查询，核对检索结果是否仅包含当前项目的文档，无跨项目的无关内容。
- 上传一份数千字的夹具设计说明文档，检查向量生成是否成功，无截断报错。
- 发起一次包含GD&T公差关键词的查询，核对检索结果的排序是否符合专业匹配度，无明显无关结果。
- 测试检索后触发的AI回复，检查响应时间是否符合业务预期，无过长延迟。
