# 有色金属冶炼与电解的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据来源包括精矿与辅料分析报告、DCS系统采集的炉况与槽况数据、化验室出具的成分检测结果、能源与环保监测台账。日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账。数据更新节奏随每批原料、每炉或每槽作业完成实时更新，字段包含炉号、槽号、作业批次、成分检测值、温度、电流、电压等，随检测项匹配对应计量标准，无统一固定单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类数据来源分散且类型多样，包含结构化的DCS实时采集数据与非结构化的纸质、电子两类文档，要求模型接入环节需支持多格式数据的统一解析。实时更新的作业数据要求模型调用需适配短周期、高频次的请求，同时多批次、多槽位的海量数据需控制上下文窗口的合理占用。此外，成分检测与炉况数据的字段无统一固定格式，需在配置阶段预设字段映射规则，避免因数据格式不匹配导致调用失败。本页面基于FastGPT v4.17.0版本编写。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配多批次熔炼、电解槽况的历史数据拼接需求，避免上下文溢出 |
| `maxTokens` | 4000 token | 限制单轮回复长度，适配不良分析报告的结构化输出要求 |
| `quoteMaxToken` | 1500 token | 限定引用的原始文档片段长度，匹配化验报告、熔炼记录的单页内容规模 |
| `temperature` | 0.3–0.5 | 降低随机性，保证成分计算、炉况判断的结果一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属节点 | 适配企业内部网络的访问限制，确保数据传输安全 |
| `AIPROXY_API_TOKEN` | 按团队或应用独立生成 | 实现不同应用的模型调用隔离，便于费用核算与权限管理 |

## 容易做错的三处
- 现象：调用多模态Embedding模型时返回包含`Invalid`关键词的报错，测试流程无法通过。原因：未适配该品类下结构化与非结构化混合数据的输入格式，或未正确启用`vision`参数。
- 现象：新建模型配置后覆盖原有配置，不同应用无法独立维护API密钥。原因：未按团队或应用维度生成独立的`AIPROXY_API_TOKEN`，未开启调用隔离配置。
- 现象：模型调用超时或返回结果为空。原因：未根据实时作业数据的规模调整`maxContext`参数，导致上下文窗口占用超出限制，或API端点配置未适配企业内网访问规则。

## 怎么确认配好了
- 发起单批次熔炼数据的模型调用测试，检查返回结果是否包含成分追溯、炉况分析的核心字段，无格式报错。
- 配置两个独立应用的`AIPROXY_API_TOKEN`，分别发起调用，验证各自的调用记录与费用统计互不干扰。
- 调整`temperature`参数至不同区间，对比同一份测试数据的输出结果，确认结果一致性符合业务需求。
- 启用`vision`参数后上传电解槽况的实拍图片，验证模型是否能正确提取图片中的槽号、电压数值等信息。
