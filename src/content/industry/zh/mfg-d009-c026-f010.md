# 有色金属冶炼与电解的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
该品类的核心数据来自精矿与辅料分析、DCS系统、槽电压电流监测、化验室、能源与环保监测设备。日常文档包含配料单、熔炼记录、电解槽况记录、化验报告、阳极阴极质量记录、环保台账，字段覆盖品位、电流强度、槽号、杂质含量、回收率等，单位涉及百分比、千安、立方米立方米。数据更新频率随生产批次调整，部分关键参数实时更新。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源实时更新的数据要求检索环节需具备低延迟特性，以支撑炉况或槽况的即时追溯。文档类型多样且字段专业性强，需精准匹配专业术语与业务场景，泛化检索易引入无关数据。单批次生产关联多份文档（如同一炉次的熔炼记录、槽况数据、化验报告、配料单），检索需覆盖关联文档集合，同时避免冗余结果。数据更新频率高，需确保检索能及时召回最新上传的生产记录，适配实时分析需求。

## 配置怎么定
本配置适配FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 该品类需匹配精准的槽况、化验数据，阈值过低会引入无关杂质分析记录，阈值过高会遗漏关联历史数据 |
| `limit` | 前8–12条 | 该品类单批次生产关联多份文档，过多会超出上下文窗口，过少无法覆盖完整追溯链条 |
| `searchMode` | `semantic+keyword` | 该品类既有专业术语（如槽电压、阳极泥）的精准匹配，又需关联配料单的成分数据，混合模式兼顾语义与关键词召回 |
| `usingReRank` | 开启 | 该品类数据字段关联性强，重排可过滤语义相似但与当前问题无关的历史记录，提升追溯准确性 |
| `datasetSearchUsingExtensionQuery` | 开启 | 该品类需关联原料、炉况、化验的跨文档信息，扩展查询可补充隐含的关联条件 |
| `collectionIds` | 按文档类型分组配置 | 该品类文档分为熔炼、槽况、化验等类别，分组检索可减少无关数据的召回量 |

## 容易做错的三处
- 现象：知识库搜索报错invalid configuration parameter name "hnsw.max_scan_tuple"。原因：误将其他工具的参数名填入FastGPT配置项，未使用官方支持的参数清单。
- 现象：批量上传100份5kb的生产文档后，约半数文件训练异常，重新上传时出现重复引用。原因：未校验文件的批次标识与历史记录的匹配性，且未启用基于文件哈希的自动去重逻辑。
- 现象：设置`limit`参数为前20条以上，导致检索结果冗余，无法快速定位异常槽况，同时检索延迟超过5秒。原因：误以为引用上限越大召回越全面，未考虑该品类单批次生产关联文档的实际数量，未启用重排功能过滤冗余结果。

## 怎么确认配好了
- 发起针对某电解槽异常电流的检索，核对返回结果是否包含该电解槽的历史槽况记录、对应熔炼批次的配料单与化验报告。
- 查看检索日志，确认返回的文档数量符合`limit`参数的配置区间，且相似度分值落在`similarity`参数的设定范围内。
- 上传一份新增的电解槽况记录，发起关联检索，确认系统能召回该新增文档的内容，验证实时更新的适配性。
- 测试开启`datasetSearchUsingExtensionQuery`前后的检索结果，确认扩展后的查询能召回跨文档的关联数据，如原料成分与槽况异常的关联数据。
