# 有色金属冶炼与电解的质量问题追溯与不良分析：部署与升级

## 这个品类的数据长什么样
该品类的业务数据来源涵盖精矿与辅料分析报告、DCS系统采集的炉况与槽电压电流数据、化验室出具的成分检测结果、电解槽群的实时运行记录，以及能源与环保监测台账。数据更新节奏随业务节点变化，每批原料、每炉熔炼、每槽电解均生成独立记录，关键运行参数实时同步。日常文档包含配料单、熔炼日志、电解槽况表、阳极阴极质量报表、环保台账等，字段包含批次编号、炉号、槽号、成分检测数值、电压数值、电流数值等，部分文档为结构化表格，部分为非结构化文本。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的数据来源要求部署阶段需适配不同格式的数据源接入，避免遗漏精矿分析、槽况监测等核心业务数据。实时更新的业务特性要求向量数据库与业务数据库的连接稳定性达标，升级过程中不能中断实时数据同步，否则会导致质量追溯链路断裂。多样的文档结构要求系统支持多格式解析与字段映射，确保配料单、熔炼日志等不同类型的业务文档均可被正确索引。此外，该品类对杂质控制与金属回收精度要求较高，部署时需针对核心业务字段优化检索规则，升级时需保证原有索引的兼容性，避免影响已上线的质量分析流程。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://{user}:{pass}@{host}:5432/fastgpt?schema=metal_smelt` | 该品类核心业务数据多存储于PostgreSQL，需指定业务专属schema隔离数据 |
| `REDIS_URL` | `redis://:{pass}@{host}:6379/0` | 用于缓存实时电解槽况、批次数据，降低重复查询开销 |
| `DB_MAX_LINK` | `30–50` | 该品类实时数据写入频繁，避免数据库连接池耗尽 |
| `STORAGE_S3_ENDPOINT` | 按国内云服务商内网端点配置 | 批量上传化验报告、熔炼记录等大文件，降低外网传输延迟 |
| 分块长度 | `800–1200 字符` | 匹配配料单、熔炼记录等文档的平均长度，避免分块丢失上下文 |
| 单次搜索上限 | `前10条` | 覆盖多槽位、多炉次的关联数据，保证检索覆盖度 |

## 容易做错的三处
- 现象：部署时拉取DockerHub官方镜像失败，无法启动FastGPT容器。原因：未配置国内镜像源，国内网络无法直接访问DockerHub公共仓库。
- 现象：调用工作流返回空值，知识库检索无匹配结果。原因：未将`PG_URL`指向存储熔炼记录、化验报告的业务数据库，或向量数据库连接参数配置错误。
- 现象：向量检索结果匹配度不足，不良分析准确性下降。原因：未使用适配PostgreSQL 15版本的pgvector 0.7.4及以上版本，导致向量存储与检索出现异常。

## 怎么确认配好了
- 执行`docker ps`命令，确认FastGPT相关容器处于运行状态，无异常退出记录。
- 登录FastGPT后台，进入知识库配置页，上传一份电解槽况记录文档，确认文档解析成功且字段映射符合业务需求。
- 调用测试API，传入包含槽号、炉次的查询指令，确认返回非空的检索结果与关联业务数据。
- 查看数据库连接监控面板，确认连接数未达到`DB_MAX_LINK`的配置上限，连接池运行正常。
