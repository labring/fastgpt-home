# 服装裁剪与缝制的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
典型主体为服装OEM/ODM工厂、品牌供应链管理部门、裁剪缝制车间。日常产生的文档包括工艺单、CAD样板、排料图、裁剪单、首件封样、工序质量表、包装配码单。数据来源涵盖订单与尺码表、CAD设计文件、面辅料检验记录、吊挂生产系统数据、验针机检测结果、客户封样标准。数据更新频率为每订单、每款、每批一次，核心字段包含裁片编号、工序要求、尺码规格、批次号、检验结果等，单位随文档类型灵活变化，无统一固定标准。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据类型多样且更新频繁，每次新订单或款式变更都会产生全新数据集，要求索引支持增量更新，无需全量重建。裁片与工序关联紧密，分块时需保留跨文档的关联字段，避免拆分后丢失工艺匹配的核心信息。款式多、季节性强导致数据体量波动大，需适配短文本与长图转文本的混合输入。面料裁片不可逆的特性，要求向量检索结果需精准关联批次与工序，避免模糊匹配导致追溯错误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配服装工艺单、排料图的单页文本长度，避免拆分后破坏工序关联逻辑 |
| 重叠长度 | 100–150 字符 | 保留裁片编号、批次号等跨分块的核心标识，防止分块边界丢失关联信息 |
| `defaultToken` | 4096 | 匹配多数通用embedding模型的输入上限，适配单份工序质量表的文本长度 |
| `maxToken` | 8192 | 支持长排料图的完整文本向量化，避免因长度超限导致索引失败 |
| 相似度阈值 | 0.75–0.85 | 结合服装品类的工艺关键词权重，过滤低相关性的非目标批次数据 |
| 单次搜索上限 | 前 20 条 | 覆盖同批次、同工序的多份检测记录，保证追溯时可获取完整关联数据 |

## 容易做错的三处
- 现象：调用pushdata api以chunk模式上传数据后，界面持续显示「索引中」状态。原因：未配置`defaultToken`导致分块元数据缺失，索引任务无法完成校验。
- 现象：搜索返回的所有结果相关性相近，无法精准定位目标批次的质量问题。原因：相似度阈值设置不合理，未结合服装品类的工艺关键词调整匹配权重。
- 现象：接入bce-embedding-v1模型后，搜索结果为空或匹配度极低。原因：未对齐向量维度参数，导致索引向量与查询向量的空间映射不一致。

## 怎么确认配好了
- 上传单份完整工艺单，查看分块预览界面，确认裁片编号、工序要求等核心字段未被拆分丢失。
- 输入「某批次左袖色差」类精准问题，验证返回结果是否包含对应批次的面辅料检验记录、首件封样数据。
- 查看向量任务日志，确认`defaultToken`和`maxToken`参数未触发token溢出报错。
- 调整相似度阈值至0.78，验证搜索结果的排序是否优先匹配目标工序的质量记录。
