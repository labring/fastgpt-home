# 服装裁剪与缝制的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
服装裁剪与缝制场景的数据通常来自订单与尺码表、CAD样板、面辅料检验记录、吊挂系统数据、验针机日志、客户封样文件。日常文档包含工艺单、排料图、裁剪单、首件封样、工序质量表、包装配码单。数据更新频率为每订单、每款、每批，核心字段包含订单编号、尺码规格、面料批号、裁片数量、工序节点、不良类型与对应批次。单份文档的字段会随工序推进逐步补充，裁片相关数据不可逆，无法在裁剪后修改。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的多轮对话与提示词配置需要适配数据的高频更新、多字段关联与不可逆特性。首先，频繁的按单按批更新要求对话上下文需过滤冗余历史数据，避免干扰当前工序的不良分析。其次，多字段关联的需求要求对话必须绑定订单、面料批号、工序ID等全局变量，确保追溯结果精准对应具体批次。最后，裁片数据不可逆的特性要求多轮对话需保留完整的工序追溯链路，不能遗漏前置检验或裁剪记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前会话的订单编号作为唯一标识 | 确保多轮对话的上下文与当前订单强绑定，避免跨订单的信息干扰 |
| `messages` | 保留最近15-20条对话上下文，单条内容不超过800字符 | 服装工序节点多，过长的上下文会稀释关键不良信息，控制长度可避免超出模型token限制 |
| `variables` | 绑定订单号、面料批号、工序ID为全局变量 | 确保每次对话都关联具体业务批次，实现精准的质量追溯与不良分析 |
| 最大上下文长度 | 6000字符 | 覆盖当前订单的核心工序记录，同时不超过通用大模型的基础上下文上限 |
| 单次搜索上限 | 前3条匹配结果 | 该品类款式多、批次杂，过多的匹配结果会导致分析冗余，优先匹配最新工序与不良记录 |

## 容易做错的三处
- 现象：对话中上传附件时提示`fail to create post presigned url`，原因：未在FastGPT v4.14.3及以上版本中正确配置S3存储的跨域访问规则，或未更新存储密钥的权限范围。
- 现象：多轮对话返回结果未按JSON格式输出，原因：未在初始提示词中明确指定JSON结构要求，且未开启`messages`上下文的格式校验开关，导致模型输出格式混乱。
- 现象：对话界面的点赞/点踩按钮点击后无日志记录，原因：未开启对话反馈的上报开关，或未配置反馈数据的存储路径，导致用户反馈无法被采集。

## 怎么确认配好了
- 传入测试订单号、面料批号作为`variables`参数发起对话，确认返回结果中包含对应批次的工艺要求与历史不良记录。
- 上传测试用的排料图或工序质量表文件，检查是否能正常生成预签名URL并完成上传，无报错提示。
- 发起两轮以上的追问，确认对话上下文保留了前序工序的不良描述与处理建议，未丢失关键信息。
- 查看FastGPT v4.17.0的配置面板，确认`chatId`、`variables`参数已绑定所需的业务字段，未遗漏核心追溯维度。
