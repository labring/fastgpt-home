# 服装裁剪与缝制的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
通常该品类的主体为服装OEM/ODM工厂、品牌供应链裁剪缝制车间，数据来源涵盖订单与尺码表、CAD样板、面辅料检验记录、吊挂系统运行数据、验针机日志、首件封样文档等。日常产生的文档包括工艺单、排料图、裁剪单、工序质量表、包装配码单等，字段包含裁片编号、色批号、工序号、尺码规格、面料克重等，更新频率为每订单、每款、每批一次，单款服装的工序文档数量较多且分散。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类款式多、季节性强，数据更新频率高，要求知识库支持高频增量更新与快速切换批次数据。裁片不可逆且人工工序密集，检索需精准匹配裁片编号、色批号等唯一标识，避免跨批次、跨款的错误关联。单款工序文档分散在多份材料中，检索需召回多段相关内容但需控制结果长度，防止超出模型上下文上限。同时，行业存在大量缩略语与专属工艺术语，检索需兼顾结构化字段匹配与语义理解。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | 该品类的工艺描述、裁片特征需较高匹配精度，该区间可过滤无关的跨款、跨批次内容，按实测标定微调 |
| `limit` | 前8–12条 | 单款服装的工序文档分散在8-12段内容中，该取值可覆盖核心工艺要求，避免结果过多超出上下文长度 |
| `searchMode` | `mixedRecall` | 该品类既有CAD样板的结构化编号，又有工艺描述的非结构化文本，混合模式可兼顾精准匹配与语义召回 |
| `usingReRank` | 开启 | 该品类文档段相似度接近，重排可优先召回首件封样、核心工序等优先级更高的内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 该品类存在大量行业缩略语与专属术语，扩展查询可补充未直接提及的关联工艺要求 |
| `collectionIds` | 按订单批次绑定专属集合 | 该品类数据按订单、批次更新，专属集合可避免跨批次数据干扰检索精度 |

## 容易做错的三处
- 现象：搜索时报错`invalid configuration parameter name "hnsw.iter"`。原因：误用了FastGPT官方参数清单以外的配置项名称，导致配置校验失败。
- 现象：上传PDF后搜索无结果，仅显示错误提示。原因：未正确配置`searchMode`为混合模式，或上传的PDF未正确提取结构化字段，导致关键词检索与语义召回均失效。
- 现象：知识库分为多段后查询不全，仅返回部分结果。原因：未开启`datasetSearchUsingExtensionQuery`，且`limit`取值过低，未覆盖分散的工艺单段落。
- 现象：创建知识库时文本理解模型下拉框无指定模型。原因：未在模型管理中正确绑定索引模型到当前数据集集合，或未按要求配置模型渠道。

## 怎么确认配好了
- 上传单款服装的工艺单、排料图PDF，执行检索“左袖裁剪偏差”，核对返回结果包含对应工序的工艺要求。
- 检查模型管理与知识库配置页面，确认已绑定的索引模型与语言模型出现在对应下拉框中，且页面顶部显示FastGPT v4.17.0版本标识。
- 拆分同一份工艺单为多段内容，执行检索，确认返回结果覆盖所有相关段落，无遗漏。
- 测试跨批次数据检索，确认仅返回当前订单批次的文档内容，无跨批次干扰。
