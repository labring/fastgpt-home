# 来料检验与供应商质量的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
该品类的数据覆盖制造企业来料检验与供应商质量管理全流程，来源包含采购订单、图纸规格、供应商质保书、检验设备导出数据、历史质量台账及供应商门户提交的审核材料。日常产生的文档包括检验规范、抽样方案、来料检验报告、供应商审核报告、异常联络单、8D整改报告及让步接收审批单。数据更新频率随业务节点变化，每批来料产生新的检验数据，每月或季度完成供应商整体评价更新，不定期开展专项审核并生成对应文档。数据字段包含批次编号、供应商名称、检验参数、不合格类型、整改状态等，部分字段为枚举值或数值型。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引支持混合格式的向量嵌入，兼容结构化的采购订单数据与非结构化的检验报告文档。高频次的更新需求需要索引配置支持增量同步，避免每次全量重建带来的计算开销。不同文档的长度差异较大，检验规范为长文本、来料报告为短文档，需适配灵活的分块策略。字段中的批次、供应商等业务标识，要求索引支持基于元数据的过滤召回，提升检索的精准度，避免跨供应商的无效数据混入结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配来料报告、检验规范等文档的平均长度，避免分块过碎丢失上下文或过长超出模型限制 |
| 重叠长度 | 100–150 字符 | 保留相邻分块的关联信息，避免批次、供应商标识在分块间断裂 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 按实测标定 | 需结合来料检验的不合格判定标准调整，避免误召回合格批次数据或漏召回异常记录 |
| 单次搜索上限 | 前10条 | 匹配SQE团队日常追溯的批量数据处理规模，平衡检索效率与召回覆盖范围 |

## 容易做错的三处
- 现象：接入通义多模态向量模型时触发调用失败，返回不支持指定模型的报错。原因：未正确配置多模态模型的调用参数，或未在平台中注册对应模型的密钥与端点。
- 现象：混用不同类型的索引模型与文本向量模型后，检索结果出现明显偏差。原因：未统一向量嵌入的维度与相似度计算规则，导致跨模型的向量空间无法对齐。
- 现象：新批次的来料检验数据无法被快速检索到，检索结果为空。原因：未配置增量索引更新模式，每次索引更新执行全量重建，导致新数据未及时纳入索引范围。

## 怎么确认配好了
- 上传一份历史来料检验报告，执行关联检索，查看返回结果是否包含同供应商、同批次的相关记录。
- 发起一次基于供应商编号的批量检索，核对返回结果的数量与预设的单次搜索上限是否匹配。
- 提交一份新的异常联络单，等待索引更新完成后执行检索，确认新数据已被纳入检索范围。
- 查看FastGPT v4.17.0的向量模型调用日志，确认没有出现模型不支持、参数超限的报错信息。
