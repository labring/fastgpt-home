# 来料检验与供应商质量的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类的数据覆盖采购订单、图纸规格、供应商质保书、检验设备导出数据、历史质量记录、供应商门户提交的审核材料等多源信息。日常涉及的文档包括检验规范、抽样方案、来料检验报告、供应商年度审核报告、异常联络单、8D整改报告、让步接收审批单等，包含批次号、供应商编码、检验项、不合格描述、抽样数量、判定结果等字段，更新频率覆盖每批来料的即时录入、每月或季度的供应商质量评价、不定期的专项审核更新。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源要求配置项支持适配不同格式的文档解析，包括结构化的检验报表、半结构化的8D报告、非结构化的异常联络单以及图片类的质保书扫描件。高频更新的批次数据要求上下文窗口的配置需适配单批次关联文档的总长度，避免因上下文溢出导致的信息丢失。多样的文档结构与固定的业务字段要求模型需能准确识别批次、供应商等核心实体，因此需调整模型的上下文处理逻辑以匹配业务数据中批次与供应商的关联规则。此外，数据质量直接影响后续的追溯与分析结果，配置环节需加入对输入数据的格式校验逻辑，确保关联的批次与供应商信息准确无误。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000–12000 token | 适配单批次来料相关的检验报告、供应商审核材料的总长度，避免上下文溢出 |
| `maxTokens` | 2000–3000 token | 满足8D报告、异常联络单的不良分析与追溯结论的输出长度需求 |
| `vision` | 开启 | 支持解析供应商质保书的盖章扫描件、检验设备导出的图片检验报告 |
| `temperature` | 0.1–0.3 | 保证不良分析、追溯结论的一致性，避免主观偏差 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或私有部署的大模型接入地址，确保请求正确转发 |
| `AIPROXY_API_TOKEN` | 按权限生成的专属密钥 | 保障接入的安全性，限制非授权的访问请求 |

## 容易做错的三处
- 现象：聊天界面显示的模型与配置项不一致。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的关联参数，导致代理转发逻辑错误。
- 现象：无法解析供应商质保书的扫描图片内容。原因：未开启`vision`配置项，或未适配图片解码模型的专用编码器参数。
- 现象：模型输出的追溯结论与实际检验数据偏差较大。原因：`temperature`取值超出0.1–0.3的合理区间，导致模型生成的判定结果缺乏一致性。

## 怎么确认配好了
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置值，与部署的大模型服务信息完全一致。
- 上传一份供应商质保书的扫描图片，发起测试请求，确认模型可以正确提取图片中的检验项与批次信息。
- 导入单批次的全量来料文档，验证`maxContext`与`maxTokens`的配置未导致上下文截断或溢出报错。
- 调整`temperature`至0.2，多次测试同一来料异常场景，确认输出结论的一致性符合预期。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
