# 模具设计制造的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
该品类数据主要来自客户产品模型、模流或成形仿真文件、CAD/CAM输出件、机加工与测量记录、试模报告及改模通知。日常文档包含模具设计任务书、DFM报告、零件图、加工工艺卡、模具履历等。数据按项目更新，每次试模或改模后同步刷新，字段包含模具编号、制件材料属性、缺陷类型、改模次数等，涉及尺寸、力学性能等工程单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
模具设计制造的项目级数据格式多样，包含工程图纸、仿真文件、结构化报告等，要求模型接入支持多格式输入解析。数据更新频率随试模、改模节点变动，单次项目数据量随迭代次数增长，需限制上下文长度避免溢出。缺陷追溯需关联历史试模记录与改模文档，要求配置中保留关联历史数据的能力，同时需适配工装类数据的结构化字段与非结构化文本混合输入的场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配模具项目多轮试模、改模产生的多段历史数据，避免上下文溢出导致分析中断 |
| `maxTokens` | 2000–3000 token | 满足缺陷类型分析、改模方案建议的文本输出长度需求 |
| `quoteMaxToken` | 1500 token | 关联试模报告、DFM报告等引用文档的核心内容，保障追溯依据的完整性 |
| `temperature` | 0.3–0.5 | 保持缺陷分析的严谨性，避免生成无工程依据的改模建议 |
| `AIPROXY_API_ENDPOINT` | 按供应商官方文档填写 | 适配不同模型供应商的接口地址，确保请求正常发送至对应服务 |
| `AIPROXY_API_TOKEN` | 按供应商分配的密钥填写 | 完成模型调用的身份验证，保障接口访问的安全性 |

## 容易做错的三处
- 界面中body参数字段无法完全清除，提交后再次打开仍显示原有内容，原因是未保存配置变更或页面缓存未同步更新。
- 模型请求出错后节点直接终止，无错误日志或提示，原因是未配置异常捕获节点或未绑定错误处理分支。
- 添加同模型不同供应商的配置时，系统提示参数重复无法保存，原因是未为不同供应商的同模型分配唯一标识，仅依赖模型id作为唯一键导致冲突。

## 怎么确认配好了
在FastGPT v4.17.0版本中，可通过以下可执行动作核对配置：
- 检查`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的填写内容，确保与所选供应商的官方配置一致。
- 提交测试请求，查看接口返回状态码是否为200，无超时或认证错误提示。
- 调整`temperature`参数的取值，验证输出内容的严谨性是否符合缺陷分析的需求。
- 保存配置后重新进入页面，确认`maxContext`、`maxTokens`等参数的取值未发生异常变更。
