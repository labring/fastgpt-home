# 橡胶混炼与制品硫化的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
该品类的数据来自配方系统、原材料批次台账、密炼机、门尼粘度仪、硫化机及实验室检测设备。日常文档包含配方单、称量记录、混炼曲线、胶料快检报告、硫化工艺卡、模具使用记录、成品性能检测报告。数据更新频率为每车原材料批次、每批胶料、每模次制品。文档字段包含批次号、投料重量、混炼温度、硫化时长、成品拉伸强度等，部分数据为时序曲线格式。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类高频次的更新节奏要求向量索引支持增量同步，避免全量重建带来的性能开销。多样的文档格式需要在分块时保留批次号、模具编号、原材料批次号等关联字段，确保召回结果可直接关联到具体生产环节。多类型数据（文本记录、混炼时序参数、成品检测数值）要求向量模型适配混合格式的文本化转换，同时索引的维度需匹配模型输出的向量长度。此外，质量追溯的严谨性要求索引结果需保留原始数据的溯源字段，避免召回结果与生产批次脱钩，降低不良分析的准确性。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本的界面与参数逻辑。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配混炼曲线、工艺卡等长文本的语义完整性，避免跨块丢失关键生产参数 |
| 重叠长度 | 50–80 字符 | 保留批次号、模具编号等跨块关联字段，确保分块间的语义衔接 |
| 相似度阈值 | 0.75–0.85 | 匹配该品类对追溯准确性的要求，过滤低相关性的非生产环节数据 |
| `defaultToken` | 4096 | 适配单批次文档的总token长度，避免截断配方、工艺参数等核心内容 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 单次搜索上限 | 前10条 | 控制召回结果的数量，兼顾追溯效率与信息完整性 |

## 容易做错的三处
- 现象：上传混炼曲线、称量记录等文档后，向量库无对应索引条目，界面显示「索引失败」状态。原因：未在分块配置中保留批次号等溯源字段，导致分块数据无法匹配索引规则。
- 现象：调用m3e模型时提示「无可用频道」，无法生成向量。原因：未按照官方文档配置m3e的调用密钥与服务地址，或未开通对应模型的使用权限。
- 现象：重复执行相同的不良分析查询时，每次都触发向量库检索，未命中缓存。原因：未开启FastGPT的缓存优化配置，或缓存有效期设置过短，无法覆盖高频查询场景。

## 怎么确认配好了
- 上传一份标准配方单与混炼曲线文档，检查向量库索引列表中是否包含对应批次的文档条目。
- 执行一次不良分析查询，核对返回的召回结果是否包含批次号、硫化参数等关联字段。
- 查看模型调用日志，确认m3e模型的调用请求已成功生成向量，无频道报错。
- 重复执行相同的查询，确认检索结果的返回速度符合预期，未出现重复的向量库调用记录。
