# 橡胶混炼与制品硫化的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自配方管理系统、原材料批次台账、密炼机、门尼粘度仪、硫化机及实验室检测系统。日常文档包含配方单、称量投料记录、混炼温度曲线、胶料快检报告、硫化工艺卡、模具使用记录、成品性能检测报告。数据更新频率为每车原材料批次、每批混炼胶料、每模次硫化制品，字段包含带单位的工艺参数，如混炼温度（℃）、硫化时长（秒）、门尼粘度值等，批次标识关联多环节流转记录。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类高频率、多环节关联的数据特征，对模型接入配置带来多重约束。首先，每车、每批、每模次的高频更新要求配置适配短周期数据召回，避免上下文过载影响响应速度。其次，多源异构的工艺参数与批次数据，需要配置匹配字段关联规则，确保召回内容包含对应环节的完整参数。此外，带单位的工艺字段要求配置保留原始单位的召回逻辑，防止参数歧义。同时，跨设备的流转数据需配置关联批次的上下文拼接规则，保证追溯链路完整。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写企业私有部署的OneAPI转发地址 | 适配本品类多源批次数据的批量调用需求，避免公网接口延迟 |
| `AIPROXY_API_TOKEN` | 生成带车间数据隔离权限的专属令牌 | 防止跨车间的批次数据被未授权访问，符合生产数据安全要求 |
| `maxContext` | 8000–12000 token | 匹配每模次关联的混炼、硫化多环节文档长度，避免截断关键工艺参数 |
| `quoteMaxToken` | 1500–2000 token | 保留单条批次记录的完整字段，确保召回的配方、工艺内容无缺失 |
| `temperature` | 0.2–0.4 | 降低回答随机性，保证工艺参数与追溯结果的准确性 |
| `toolChoice` | auto | 自动触发召回关联的批次文档，适配多环节追溯的复杂查询 |

## 容易做错的三处
- 界面显示模型调用失败，返回401未授权状态码。原因是未在FastGPT配置中同步更新`AIPROXY_API_TOKEN`与`AIPROXY_API_ENDPOINT`，导致OneAPI转发链路中断。
- 知识库召回结果仅包含零散参数，未关联完整批次链路，回答内容过于精简。原因是`quoteMaxToken`取值过小，截断了单条文档的完整字段，无法输出具体工艺条款。
- 单次知识库搜索耗时超过30秒，或问答拆分未区分混炼与硫化环节。原因是`maxContext`设置过大导致上下文过载，或未将`toolChoice`配置为auto，未触发自动关联召回。

## 怎么确认配好了
- 调用FastGPT内置的模型测试接口，检查返回的`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置是否与私有部署的OneAPI参数一致。
- 提交包含具体混炼批次号的查询，确认召回结果包含对应批次的称量记录、混炼曲线与硫化工艺卡完整内容。
- 调整`temperature`参数至0.3，提交同一查询三次，确认回答内容一致性符合预期。
- 查看FastGPT v4.17.0的后台日志，确认模型调用的token消耗处于`maxContext`与`quoteMaxToken`设置的区间内。
