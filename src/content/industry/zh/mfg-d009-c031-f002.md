# 水泥熟料与粉磨的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
本品类数据来源包括在线成分分析设备、DCS控制系统、化验室检测系统、窑磨运行设备、原燃料台账与能源计量系统。日常文档涵盖生料配料方案、回转窑操作记录、熟料化验报告、质量控制通知单、设备巡检记录与能源消耗报表。数据更新节奏分为实时（设备运行参数、在线成分数据）、每班（巡检记录、能源报表）、每日（配料方案、质量管控文件），字段包含原燃料成分占比、设备运行温度、熟料强度指标、配料比例等。

## 这些特征在「向量模型与索引」这一环带来什么约束
实时设备与在线成分数据的高频更新，要求索引支持增量同步机制，避免全量重建占用过多计算资源。多源异构的数据类型，包括数值型参数、文本型记录与结构化报表，需要统一字段映射规则，确保不同来源数据的向量嵌入空间保持一致性。按生产周期划分的更新节奏，要求索引按批次或时间维度拆分，便于快速定位对应生产环节的质量问题。核心质量指标如熟料强度、游离氧化钙含量，需要在向量召回时设置字段权重，提升不良分析的精准度。长文本类的窑操作记录，需要适配合理的分块长度，避免嵌入过程丢失热工制度的关键信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配生料配料方案、窑操作日志等长文本的语义完整性，避免关键信息断裂 |
| 重叠长度 | 100–150 字符 | 确保相邻分块间的语义衔接，防止长文本的关键上下文被拆分 |
| `defaultToken` | 4096 | 适配FastGPT v4.17.0的嵌入接口规范，匹配单批次质量数据的嵌入需求 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 相似度阈值 | 0.72–0.85 | 过滤低相关的检索结果，适配熟料质量指标的细微差异识别 |
| 单次搜索上限 | 前10条 | 控制检索结果的返回数量，避免冗余信息干扰不良分析 |

## 容易做错的三处
- 现象：调用向量模型时返回401状态码，或通过Ollama部署的模型被FastGPT调用拒绝。原因：未配置向量模型的访问密钥，或密钥权限未覆盖生产数据的检索场景。
- 现象：知识库索引生成后出现重复文档块，且自定义切分的文档顺序与索引存储顺序不一致。原因：未关闭索引去重功能，或去重逻辑未保留原始文档的切分顺序。
- 现象：检索结果返回条数与单次搜索上限设置不符，或核心质量指标未被优先召回。原因：未正确设置字段权重，或检索参数未绑定熟料质量相关的字段规则。

## 怎么确认配好了
- 执行curl命令测试向量模型接口，确认返回的向量数据格式符合FastGPT的嵌入要求。
- 上传单份生料配料方案文档，检查索引生成的分块数量与设置的分块长度匹配。
- 模拟提交质量问题查询，核对返回的检索结果条数与单次搜索上限设置一致。
- 查看索引日志，确认增量同步功能在更新在线成分数据时正常触发，无全量重建报错。
