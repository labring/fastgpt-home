# 水泥熟料与粉磨的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
数据来源包括在线成分分析设备、DCS控制系统、化验室检测系统、窑磨运行设备、原燃料台账与能源计量系统。数据更新节奏分为实时（窑温、配料流量）、每班（巡检记录、能源报表）、每日（化验报告、质量控制通知单）。日常文档包含生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检日志、能源消耗报表，字段涵盖熟料游离钙、比表面积、窑炉热工参数、原燃料配比、设备运行时长等，需匹配对应数据源的计量标准，无统一固定单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
由于数据来源分散且更新节奏差异明显，多轮对话需要引导用户明确指定数据类型与时间范围，避免混淆实时运行数据与历史检测报告。提示词需明确区分不同文档的字段规则，例如化验报告的强度指标需匹配检测批次，DCS数据需关联具体设备编号。同时，质量追溯需关联多维度数据，多轮对话需保留历史交互参数，确保上下文连贯，避免重复请求用户补充相同信息。此外，生产数据存在权限限制，配置需绑定对应系统的访问规则，防止越权查询敏感生产信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文长度 | `15000–20000 字符` | 水泥熟料与粉磨的关联文档通常包含多期巡检、化验与配料数据，较长的上下文可覆盖完整追溯链条，适配FastGPT v4.17.0的会话存储上限 |
| 问题优化开关 | 开启 | 可自动补全用户未明确的参数，例如补充班次、设备编号，适配多轮对话的信息补全需求 |
| 单次召回上限 | `前8条` | 平衡数据相关性与响应速度，避免过多冗余信息干扰不良分析判断 |
| 上下文保留时长 | `72 小时` | 覆盖班组交接班的追溯周期，满足跨班次的质量问题追溯需求 |
| `variables`配置 | 绑定化验系统、DCS的访问密钥与权限范围 | 确保对话可安全调用对应系统的生产数据，避免权限报错 |
| `messages`管理 | 自动保留最近10轮交互内容 | 复用历史对话参数，减少用户重复输入信息的成本 |

## 容易做错的三处
- 对话返回401 No auth credentials found，原因是未在`variables`中配置关联化验系统或DCS的访问密钥，未完成生产系统的权限绑定。
- 多轮对话无法获取指定日期的质量数据，原因是提示词未引导用户补充班次、检测批次参数，未复用`messages`中的历史上下文信息。
- 对话中无法触发BLOB格式的化验报告下载，原因是未通过`chatId`绑定用户会话的文件访问权限，未配置HTTP节点的响应头参数。

## 怎么确认配好了
- 发起测试对话，输入“查询2024年6月15日回转窑的巡检记录”，验证是否能返回对应日期的文档片段且无权限报错。
- 测试多轮对话，先输入“查看当日熟料3天强度数据”，再补充“结合当日生料配料方案”，验证上下文是否被正确保留且能关联两份数据。
- 触发生成BLOB格式的化验报告请求，验证对话界面是否出现可点击的下载链接。
- 检查`variables`中的密钥配置，发起跨系统数据查询，确认无权限相关报错。
