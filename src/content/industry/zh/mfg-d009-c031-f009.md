# 水泥熟料与粉磨的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
水泥熟料与粉磨的数据来源包含在线成分分析、DCS系统、化验室、窑磨设备、原燃料台账、能源计量设备。日常文档涵盖生料配料方案、窑操作记录、化验报告、质量控制通知单、设备巡检记录、能源报表。数据更新节奏分为三类：实时更新的在线成分分析与窑磨运行参数、每班更新的设备巡检与窑操作记录、每日更新的化验报告与质量控制通知单。数据字段包含原料配比、窑温、生料细度、熟料矿物组成、水泥强度指标、设备运行电流、能源消耗数值等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源且更新频率各异的数据，要求配置支持多数据源同步与定时拉取规则，避免数据滞后或冗余。文档结构包含结构化工艺参数与非结构化文本记录，需适配混合格式的上下文调用，确保模型可同时读取结构化字段与描述性内容。数据字段涉及专业工艺指标，需精准匹配业务字段映射，防止参数混淆导致分析偏差。数据关联后果直接影响生产稳定性，需配置失败重试与异常告警机制，保障追溯流程可靠。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | 填写水泥行业专用模型代理地址 | 适配熟料粉磨工艺的专业模型接口，提升质量分析准确性，本页适配FastGPT v4.17.0版本 |
| `AIPROXY_API_TOKEN` | 绑定企业专属认证密钥 | 保障工业生产数据调用权限安全，符合生产数据保密要求 |
| `maxContext` | 8000–12000 token | 覆盖单班窑操作记录、化验报告与设备巡检的完整业务上下文 |
| `quoteMaxToken` | 1500–2000 token | 保留数据库原文片段的最大长度，匹配工艺参数与业务记录的字段长度 |
| `temperature` | 0.2–0.4 | 降低随机输出偏差，确保质量追溯结果的一致性与严谨性 |
| 工作流/API 工具选择配置 | auto | 自动触发多源数据查询工具，适配MySQL、PGVector等多类型数据源调用 |

## 容易做错的三处
- 调用MySQL数据库后，大模型未返回数据库原文片段，仅输出泛泛结论 | 未配置`quoteMaxToken`参数，未开启原文片段召回机制，导致无法提取数据库原文内容。
- 模型选择界面参数持续自动跳动，无法固定配置 | 未锁定`toolChoice`与`temperature`参数，每次调用自动重新匹配模型，导致配置失效。
- 工具调用流程出现混乱提示，如提及非预期的模型调用逻辑 | 未正确配置工具调用规则，导致模型尝试调用未适配的工具链，不符合水泥行业数据查询需求。

## 怎么确认配好了
- 发起熟料质量追溯请求，检查返回结果中是否包含数据库原文片段的引用内容，验证片段长度符合`quoteMaxToken`配置范围。
- 查看模型配置界面，确认`toolChoice`与`temperature`参数无自动变化，保持固定取值。
- 测试多源数据接入，验证在线实时数据、每班巡检记录、每日化验报告均可被正常调用与读取。
- 查看工具调用日志，确认MySQL、PGVector等工具被自动触发，符合`toolChoice`为auto的配置要求。
