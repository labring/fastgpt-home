# 汽车整车总装的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据来源包括ERP/MES系统、VIN与配置系统、供应商批次库、拧紧工具、EOL下线检测线及质量追溯系统。日常文档涵盖生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录与一致性放行文件。数据更新节奏为每车实时同步、每班批量更新，以VIN为单车主线，需匹配数百项车辆配置与对应零件信息，同时需管控关键连接工序的扭矩参数。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
以VIN为核心的单车主线数据，要求多轮对话需始终绑定对应VIN的上下文，避免跨车辆数据混淆。实时更新的拧紧、检测数据，要求提示词需支持动态加载最新工位数据，且对话上下文不能超出当前批次的时间范围。大规模混线装配的场景，要求提示词需明确区分不同车型的配置规则，同时多轮对话需保留工位操作的历史记录，便于回溯缺陷产生的工位环节。大量结构化的扭矩、检测数据，要求提示词需指定数据字段的解析规则，避免非结构化解读偏差。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本调试：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 绑定当前VIN的唯一标识 | 确保每台车辆的对话上下文独立，避免数据混淆 |
| `messages` | 保留最近20轮对话记录 | 覆盖单台车辆从装配到返修的全流程对话环节 |
| `variables` | 注入当前VIN、工位编号、批次号 | 让提示词能动态调用对应车辆的结构化数据 |
| 最大上下文长度 | 8000–12000 token | 适配单台车辆数百项配置与多工位数据的上下文需求 |
| 单次召回上限 | 前10条匹配数据 | 控制检索范围，避免无关历史数据干扰分析 |
| 问题优化 | 按实测标定 | 适配总装场景的缺陷描述习惯，优化多轮追问的精准度 |

## 容易做错的三处
- 现象：对话界面提示「没有权限操作此对话记录」。原因：未将当前VIN绑定的`chatId`与对应工位账号的权限配置关联，导致跨账号无法访问专属对话上下文。
- 现象：AI提示未上传文件，无法读取系统提示词中嵌入的装配作业指导书内容。原因：未将作业指导书按车型配置拆分嵌入`variables`变量，或文档分块未匹配提示词的读取规则。
- 现象：升级后刷新页面，当前车辆的对话记录消失，显示为新对话。原因：`chatId`未持久化绑定VIN标识，页面刷新后未自动加载对应VIN的历史对话数据。

## 怎么确认配好了
- 输入测试VIN，检查对话界面是否自动加载对应车型的配置、拧紧数据等关联信息。
- 发起多轮追问，确认对话上下文是否保留前序工位的缺陷描述与处理记录。
- 触发文档读取测试，确认系统提示词中嵌入的作业指导书内容可被正常调用。
- 刷新页面，确认当前VIN的对话记录未丢失，仍显示为历史会话内容。
