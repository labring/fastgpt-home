# 汽车整车总装的质量问题追溯与不良分析：模型接入与配置

本文基于FastGPT v4.17.0版本编写。

## 这个品类的数据长什么样
该品类的数据通常来自ERP/MES系统、VIN与车辆配置系统、拧紧工具、EOL下线检测线及质量追溯系统。日常文档包含生产订单、VIN清单、装配作业指导书、拧紧扭矩数据、下线检测报告、返修记录与一致性放行文件。数据更新频率按单车辆执行，关键扭矩与检测数据实时同步，批次与配置信息按每班更新。数据核心字段包含VIN码、零件批次号、扭矩参数、检测结果与返修工位信息。

## 这些特征在「模型接入与配置」这一环带来什么约束
由于该品类以VIN为单车主线进行混线生产，模型需精准匹配单车辆对应的数百项零件配置与工艺参数，因此上下文长度需适配单车辆全量关联数据的规模。实时同步的拧紧、检测数据要求模型调用延迟符合生产节拍，同时多源异构文档（含图文类作业指导书、检测照片）要求模型支持视觉输入与多格式解析。数据更新频率高且出错后果严重，因此模型接入需支持稳定的重试机制与权限控制，同时需适配本地部署的大模型调用需求，保障生产数据不外流。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单车辆数百项配置、关联文档的总上下文长度，避免截断关键VIN匹配信息 |
| `maxTokens` | 2000–3000 token | 满足单批次不良分析的结果输出长度，覆盖返修记录、检测数据的完整解读 |
| `vision` | 开启 | 适配装配作业指导书的图文解析、下线检测照片的缺陷识别需求 |
| `temperature` | 0.2–0.4 | 降低结果随机性，保障质量追溯结论的一致性与严谨性 |
| `AIPROXY_API_ENDPOINT` | 填写本地部署或云服务的专属接口地址 | 适配生产环境的数据安全要求，避免外部接口调用泄露车辆生产数据 |
| `AIPROXY_API_TOKEN` | 配置专属权限密钥 | 实现禁止匿名访问的权限控制，仅允许授权的生产系统调用模型服务 |

## 容易做错的三处
- 现象：开启`vision`配置后，模型仍仅返回文字结果，无法解析上传的检测照片或作业指导书图片。原因：未正确配置`vision`参数的启用开关，或绑定的大模型未适配视觉输入能力。
- 现象：调用本地部署的大模型时出现连接超时或404报错。原因：`AIPROXY_API_ENDPOINT`填写错误，未指向本地模型的实际运行端口，或未配置正确的`AIPROXY_API_TOKEN`进行权限校验。
- 现象：批量导入VIN清单时，模型无法匹配对应车辆的配置数据，返回空结果或错误匹配。原因：`maxContext`设置过小，截断了VIN与零件配置的关联信息，导致模型无法完成精准匹配。

## 怎么确认配好了
- 上传单车辆的VIN清单与对应拧紧扭矩数据，触发模型调用，检查返回结果是否包含VIN对应的零件配置匹配内容。
- 上传一张装配作业指导书的图片，验证模型是否能正确识别图中的文字与标注信息，确认`vision`配置生效。
- 调用本地部署的大模型接口，检查接口返回状态码是否符合预期，验证API地址与密钥配置正确。
- 使用未授权的密钥发起模型调用，确认接口返回权限错误，验证访问控制配置生效。
