# 汽车整车总装的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
汽车整车总装场景的数据以单台车辆的VIN码为核心主线，日常覆盖生产订单、VIN清单、装配作业指导书、拧紧数据、下线检测报告、返修记录等文档。数据来源涵盖ERP/MES系统、VIN与配置系统、供应商批次库、拧紧工具、EOL检测线及质量追溯系统，更新频率按单台车、实时及每班三种节奏。数据包含VIN码、扭矩值、检测项、零件批次等结构化字段，以及装配步骤、故障排查指南等非结构化内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
以VIN为核心的单台车数据特征，要求检索必须精准匹配当前车型的配置与零件信息，避免混线生产下的跨车型数据干扰。多源、多更新节奏的数据，要求知识库支持增量同步与实时召回，确保检索结果与生产节拍同步。结构化字段与非结构化文档并存的场景，要求检索同时支持关键词匹配与语义召回，兼顾精准性与内容完整性。单台车关联数百项配置数据的需求，要求召回结果需控制合理范围，避免超出模型上下文限制，同时覆盖必要的关联信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配VIN码、扭矩值等结构化字段的匹配精度，过滤低相关性的跨车型配置数据 |
| `limit` | 前10条 | 覆盖单台车核心关联数据的召回需求，同时控制单轮检索的上下文长度 |
| `searchMode` | `vector + keyword` | 同时匹配VIN等结构化关键词与语义内容，适配混线生产下的精准检索场景 |
| `usingReRank` | 开启 | 对召回结果按与当前VIN的匹配度重排，优先返回当前车型专属的作业指导书与检测标准 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于输入的VIN自动扩展检索关联的供应商批次、拧紧工具参数等关联数据 |
| `collectionIds` | 按车型/工位绑定指定知识库集合 | 限定检索范围，避免召回非当前工位或车型的无关文档，降低检索噪声 |

## 容易做错的三处
- 现象：检索结果仅包含文档文本，未召回装配作业指导书中的步骤图示。原因：未启用FastGPT的图文解析插件，仅对PDF文档的文本内容进行嵌入与召回。
- 现象：提交的检索配置保存后，重启服务后恢复为默认参数。原因：未将配置持久化存储到系统数据库，仅保存在本地临时缓存中。
- 现象：按VIN检索时返回大量无关车型的配置数据。原因：未配置`searchMode`为混合检索模式，仅依赖向量召回导致语义匹配偏差。

## 怎么确认配好了
- 上传一份带装配图示的总装作业指导书，输入目标VIN发起检索，确认返回结果包含文本内容与对应的图片链接。
- 手动修改检索配置参数并提交保存，重新进入配置页面，确认参数未恢复为默认值。
- 输入一台具体车型的VIN发起检索，核对返回结果中是否包含该车型对应的拧紧数据、下线检测报告等专属文档。
- 使用FastGPT v4.17.0版本的系统，查看系统检索日志，确认同时触发了向量检索与关键词检索，且重排功能正常生效。
