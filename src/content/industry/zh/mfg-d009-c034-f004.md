# 烘焙与方便食品的质量问题追溯与不良分析：工作流编排

## 这个品类的数据长什么样
该品类数据覆盖面包糕点、饼干、方便面及速冻面点工厂的生产全流程，日常文档包含配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源包括原辅料合格证明、ERP/MES系统、称量系统、烤炉或油炸线设备、实验室及食品追溯台账，更新频率按每批、每班或每日执行，字段包含物料名称、批次号、检测数值、时间戳等，无额外自定义单位。

## 这些特征在「工作流编排」这一环带来什么约束
由于该品类配方多、产品换线频繁，工作流需支持快速切换数据源与校验规则；多批次高频更新的数据要求工作流节点支持实时拉取，不缓存旧数据；过敏原与清洁切换的高频需求，要求工作流可通过变量动态绑定不同物料与清洁标准；直接食用的属性要求工作流需覆盖异物、微生物等全链路质量校验环节，且需严格匹配每批生产的溯源要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| variables | 按批次绑定原辅料、生产记录字段 | 匹配该品类多批次换线的配方与投料校验需求 |
| nodeId | 绑定烤炉、金属检测设备的节点ID | 对应实时拉取烘烤曲线与异物检测数据的场景 |
| 数据源触发时机 | 按每批生产完成后触发 | 匹配每批更新的数据频率 |
| 单次召回上限 | 前8条 | 适配单批生产记录与检测记录的数据量 |
| 超时设置 | 600秒 | 适配多源数据拉取的耗时需求 |
| 知识库绑定规则 | 按产品品类绑定对应知识库 | 匹配该品类多产品换线的知识库需求 |
*注：本页适配FastGPT v4.17.0版本*

## 容易做错的三处
- 工作流调用数据库时使用`variables`传入参数报错，手动执行SQL正常。原因：未将变量正确绑定到对应节点的参数入口，导致参数未完成传递。
- 工作流中无法实时切换知识库。原因：未配置节点间的知识库切换触发逻辑，固定绑定了单一知识库节点。
- 工作流调用工具后无返回结果，或返回结果格式不符合预期。原因：未正确设置`nodeId`绑定对应工具节点，或未配置输出格式校验规则。

## 怎么确认配好了
- 触发一次模拟批次生产的工作流，检查是否拉取到对应批次的配方与检测数据。
- 手动传入测试变量，验证数据库查询是否正常返回对应结果。
- 查看工作流节点日志，确认`variables`参数与`nodeId`配置正确匹配。
- 模拟过敏原物料切换场景，检查工作流是否触发对应校验环节。
