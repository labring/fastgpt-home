# 烘焙与方便食品的质量问题追溯与不良分析：工具调用与插件

## 这个品类的数据长什么样
该品类数据来自面包糕点、饼干、方便面及速冻面点工厂的多类业务文档，包括配方与投料单、生产记录、烘烤/蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源覆盖原辅料合格证明、ERP/MES系统、称量设备、生产产线、实验室及食品追溯台账，更新节奏按生产批次、班次或每日执行。数据字段包含过敏原物料标识、烘烤/油炸温度时长、异物检测结果、包装日期与保质期等具体业务信息。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类多批次、多文档的特征要求工具调用需支持按生产批次快速检索对应文档，避免跨批次数据干扰。过敏原与清洁切换的高频需求，要求插件需集成过敏原合规校验、产线清洁状态核对逻辑。多源数据来源带来的格式差异，要求工具调用需统一数据解析规则，适配不同系统导出的文档结构。同时，单批次数据量较大的特点，需限制单次工具调用返回的条目数，避免响应超时。

## 配置怎么定
本配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配多类插件的自动调用逻辑，无需手动指定工具类型 |
| `functionCall` | 开启 | 支持结构化返回工具调用结果，便于后续数据整理 |
| 单次搜索上限 | 前3条 | 匹配单批次核心业务文档，避免加载冗余数据 |
| 最大上下文 | 7000–9000 token | 容纳多份生产记录、检测报告的内容，按实测标定调整 |
| 超时阈值 | 15 秒 | 适配产线数据检索的响应速度要求，避免长时间等待 |
| 问题优化 | 开启 | 重构追溯查询语句，适配食品生产台账的专业字段命名规则 |

## 容易做错的三处
- 现象：工具调用模块持续输出详细运行记录，占用对话展示空间。原因：未关闭工具调用的日志输出配置，默认启用了全量日志打印。
- 现象：单次质量追溯查询耗时超过10秒，界面显示响应超时。原因：未限制单次搜索的返回条目数，加载了过多跨批次的冗余生产数据，或超时阈值设置不符合产线数据量要求。
- 现象：调用工具返回的结构化结果中，后一个字段的内容叠加了前一个字段的输出，例如过敏原校验结果与生产记录内容出现混叠。原因：未启用`functionCall`的参数校验逻辑，导致多轮工具调用的上下文未正确隔离，数据覆盖规则异常。

## 怎么确认配好了
- 发起一次针对某批次面包的过敏原追溯查询，检查工具调用是否自动匹配到对应的合规校验插件，无需手动选择工具类型。
- 查看工具调用的响应时长，确认在设定的超时阈值内完成返回。
- 导出工具调用的结构化结果，检查各字段内容无叠加或覆盖情况。
- 核对返回的文档条目数，确认与单次搜索上限的设置一致。
