# 烘焙与方便食品的质量问题追溯与不良分析：文档解析与分块

## 这个品类的数据长什么样
这个品类的典型主体为面包糕点、饼干、方便面和速冻面点工厂，日常文档涵盖配方与投料单、生产记录、烘烤或蒸煮曲线、金属检测记录、清洁消毒记录、出厂检验报告。数据来源包括原辅料合格证明、ERP/MES系统、称量系统、烤炉或油炸线、实验室检测设备及食品追溯台账。数据更新频率为每批、每班或每日，文档含明确的批次号、过敏原标注、检测数值及对应单位，如烘烤温度、投料重量、保质期时长等，结构覆盖文本段落、表格及图表。

## 这些特征在「文档解析与分块」这一环带来什么约束
品类高频的批次化更新要求分块需精准关联批次信息，避免跨批次内容混杂。多类型文档（文本、表格、图表图片）要求解析功能需适配不同格式，尤其是烘烤曲线类PDF图片需支持嵌入文本提取。频繁的产品换线导致配方与生产记录切换频繁，分块需保留文档间的上下文关联，确保检索时可快速定位对应批次的全量信息。过敏原管控的严格性要求分块不可拆分同一清洁或投料记录中的过敏原标注与检测结果，否则会影响追溯准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 烘焙文档多含批次信息、配方参数与检测数值，分块过长会丢失批次关联，过短会拆分同一检测记录的完整逻辑 |
| `chunkSplitter` | 按段落+语义拆分 | 生产记录、配方单有明确段落分隔，语义拆分可保留过敏原、批次等关键信息的完整性，适配品类文档的结构化特征 |
| `customPdfParse` | 开启图片文本提取模式 | 部分烘烤或蒸煮曲线以PDF图片形式存储，需提取图中的温度、时间等检测标注文本，确保解析覆盖全量文档类型 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 大型生产台账Excel或多页PDF文档的解析耗时较长，默认超时时长无法覆盖解析需求，避免中途中断 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 支持批量上传多批次生产记录文件，适配品类高频的小批量批量上传场景 |
| `chunkSettingMode` | 手动配置 | 不同文档类型（配方、检测记录、清洁台账）需差异化分块参数，自动模式无法适配品类专属的文档结构与业务需求 |

## 容易做错的三处
- 现象：上传含烘烤曲线的PDF图片后，知识库返回结果为空或无有效文本内容。原因：未开启`customPdfParse`的图片文本提取功能，无法解析嵌入的图表图片文本。
- 现象：提问Excel格式的投料单时，回答混淆不同批次的投料数据。原因：分块未按批次语义拆分，将跨批次的表格行拆入同一分块，导致上下文关联错误，无法精准定位目标批次信息。
- 现象：上传多页生产台账时触发解析超时报错。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`至适配的时长，默认超时设置无法覆盖多页文档的完整解析过程。

## 怎么确认配好了
以下核对动作基于FastGPT v4.17.0版本的知识库功能：
- 上传单份含烘烤曲线的PDF图片，检查解析结果是否包含图中的温度、时间等标注文本，确认图片文本提取功能生效。
- 上传批量Excel投料单，检索特定批次的投料数据，确认返回结果仅包含对应批次的内容，无跨批次混杂情况。
- 调整`chunkSize`至不同区间，对比检索结果的完整性与关联性，选择符合业务需求的取值范围。
- 上传最大允许尺寸的生产台账文件，确认解析过程未触发超时报错，验证超时设置的合理性。
