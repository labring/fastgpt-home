# 热处理的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
这个品类的数据来自材料牌号、客户技术条件、温控仪表、炉温均匀性测试设备、硬度计与金相设备、MES系统。数据按每炉次、每批更新，包含热处理工艺卡、装炉图、炉温曲线、硬度与金相报告、设备点检表、异常处置单等文档。其中结构化文档包含炉号、批次号、温度值、时间区间、硬度数值等字段，非结构化文档包含可视化的炉温曲线、金相显微图像，字段单位涵盖摄氏度、小时、HV硬度单位等。

## 这些特征在「模型接入与配置」这一环带来什么约束
单炉次数据的更新频率与文档体量要求模型上下文长度需适配单批热处理的全量关联数据，避免上下文溢出。多类型文档包含结构化表格与非结构化可视化内容，要求配置支持多模态解析的能力。数据来源多为企业内部设备与系统，要求模型接入需适配企业内部的鉴权规则与网络环境，同时需保障专业术语的解析准确性，避免因字段识别错误导致分析偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 企业内部部署的大模型服务完整API路径 | 适配热处理场景的企业内部模型调用需求，规避公网传输延迟 |
| `AIPROXY_API_TOKEN` | 企业内部模型分配的专属鉴权令牌 | 保障内部模型调用的安全性，符合企业数据合规要求 |
| `vision` | 开启 | 支持解析炉温曲线、金相显微图等非结构化可视化文档，适配多类型业务数据的解析需求 |
| `maxContext` | 8000–12000 token | 覆盖单炉次的工艺卡、装炉图、炉温曲线等全部关联文档的上下文长度 |
| `temperature` | 0.2–0.4 | 降低随机生成概率，保障不良分析结果的一致性与专业性 |
| `quoteMaxToken` | 1500–2000 token | 限制召回的上下文片段长度，避免冗余信息干扰模型分析 |

本文档适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 偶发返回空响应或调用后卡住10秒后报错。未正确配置`AIPROXY_API_TOKEN`或`AIPROXY_API_ENDPOINT`，导致企业内部模型调用失败，日志未正常生成。
- 接入向量模型时提示401错误。鉴权令牌配置错误，未匹配内部模型的鉴权规则，导致请求被拦截。
- 部署的OneAPI服务无限重启。容器挂载的配置文件权限不足，或`AIPROXY_API_ENDPOINT`指向的内部模型服务未正常启动。

## 怎么确认配好了
- 调用企业内部模型的测试接口，验证`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，返回正常的模型响应。
- 上传单炉次的热处理工艺卡与炉温曲线，验证`vision`配置生效，模型可正确解析可视化文档内容。
- 触发批量分析任务，验证`maxContext`配置适配单炉次数据量，无上下文溢出报错。
- 调整`temperature`参数，验证分析结果的一致性，无明显随机偏差。
