# 焊接结构件制造的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自设计图纸、材料质保书、焊接设备参数、焊材库管理系统、无损检测系统、人员资质台账。日常文档包含焊接工艺评定、焊接工艺规程、焊材领用记录、焊工资格记录、焊缝检验报告、返修单。数据更新节奏为每条焊缝、每批工件或每班作业。文档字段包含焊缝编号、焊材牌号、焊接电流电压、无损检测结果、焊工持证编号等，无额外自定义单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据来源分散且关联焊缝、批次、班组维度，要求模型接入时需支持多源数据的关联匹配逻辑。高频更新的焊缝、批次数据，需配置适配近实时调用的上下文加载规则。文档多为焊接专业术语，需确保模型支持对应专业领域的解析能力。返修单、无损检测报告存在固定格式，需配置对应格式的文本拆分规则，避免字段错位。人员资质、工艺评定的刚性约束要求模型输出需严格匹配合规字段，不可随意篡改数据项。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 按部署服务商提供的专属接入地址填写 | 用于指定模型调用的网络路径，适配多源焊接数据的跨系统调用需求 |
| `AIPROXY_API_TOKEN` | 为每个团队绑定专属密钥 | 支持模型费用按团队隔离统计，符合场景下的权限划分与成本核算需求 |
| `maxContext` | 8000–12000 token | 适配单批次工件的全部关联文档长度，覆盖焊缝、焊材、人员资质等全量数据 |
| `temperature` | 0.1–0.3 | 降低输出随机性，确保专业术语解析与合规字段匹配的准确性 |
| `vision` | 启用 | 支持无损检测图像、焊缝实拍图的多模态解析，适配场景下的图片分析需求 |
| `maxTokens` | 2000–3000 token | 限制单次模型输出长度，避免超出返修单、检验报告的标准字段解析范围 |

## 容易做错的三处
- 现象：调用多模态Embedding模型时返回`Invalid`格式报错，测试接口返回指定错误结构。原因：未启用`vision`参数，导致模型无法接收并解析焊接无损检测图像数据。
- 现象：团队内不同项目的模型调用费用无法按维度拆分统计。原因：未为每个团队配置独立的`AIPROXY_API_TOKEN`，未开启模型权限隔离配置。
- 现象：多人扫码接入同一工作流后，返回的追溯结果出现数据交叉混淆。原因：未针对单批次焊缝数据配置合理的`maxContext`取值，导致上下文覆盖范围超出单批次边界。

## 怎么确认配好了
- 进入FastGPT v4.17.0的模型接入配置页面，核对`AIPROXY_API_ENDPOINT`与部署地址一致，`AIPROXY_API_TOKEN`未泄露且绑定对应团队。
- 上传焊接无损检测图像作为测试输入，确认`vision`参数启用后模型可正常返回图像解析结果。
- 发起多用户同时调用测试，使用不同团队的`AIPROXY_API_TOKEN`，确认调用结果与费用统计可按团队隔离。
- 导入单批次工件的全部关联文档，确认`maxContext`与`maxTokens`配置后，模型可完整加载并解析所有字段。
