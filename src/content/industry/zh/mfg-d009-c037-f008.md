# 生产计划与车间排程的质量问题追溯与不良分析：文档解析与分块

## 这个品类的数据长什么样
这个品类的日常文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单等，数据来源覆盖ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。数据更新频率包含每日、每周、订单或异常发生时，文档结构多为固定字段组合的表格与文本混合格式，字段包含订单号、物料编码、产能数值、班次时段、交期等，对应单位涵盖件、小时、天、批次等。

## 这些特征在「文档解析与分块」这一环带来什么约束
日常文档包含复杂多行表格与固定业务字段，分块时不能割裂字段间的关联，否则会破坏排产表、工单的业务完整性。数据更新频率高且存在异常触发的更新，解析环节需支持批量快速处理，避免因超时导致解析失败。文档来源分散且格式多样，需兼容PDF、Word、Excel等多格式解析，同时保留文档溯源所需的来源标识。部分文档包含非标准编码字符，需适配特殊编码的解析需求，避免出现解析报错。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 该品类文档包含业务字段组合，过长会丢失上下文关联，过短会破坏工单、排产表的业务单元完整性 |
| `chunkSplitter` | 按段落+表格识别分块 | 日常文档包含多行表格与文本段落混合的内容，需保留表格行的关联关系，避免拆分单元格内的业务数据 |
| `customPdfParse` | 开启 | 部分主生产计划文档为带格式的PDF，开启后可保留字段排版与表格结构，提升分块准确性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 批量上传排产表、工单等文档时，大文件解析需足够时长避免超时失败 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 部分企业的月度排产汇总文件体积较大，需适配批量上传的文件大小需求 |
| `chunkSettingMode` | 自定义模式 | 该品类文档结构固定且业务关联性强，手动调整分块规则可更好适配业务字段的关联要求 |

## 容易做错的三处
- 上传xlsx格式的周日排产表后，分块结果拆分了同一行的设备、产能与班次内容，原因是未配置按表格识别的分块规则，默认按字符拆分破坏了表格行的业务关联。
- 上传PPT或Word格式的交期变更单时，界面弹出“the argument ‘windows-1252’ is invalid encoding”报错，原因是文档包含非标准编码的字符，未开启自定义编码解析适配。
- 批量上传10份以上的工单文件时，解析任务中途失败，原因是`PARSE_FILE_TIMEOUT_SECONDS`取值过低，未适配批量大文件的解析时长要求。

## 怎么确认配好了
- 上传一份典型的周日排产表xlsx文件，查看解析后的分块结果是否保留了每行设备、产能、班次的完整关联，未出现单元格内容被拆分的情况。
- 上传一份包含特殊字符的Word格式交期变更单，检查解析过程无编码报错提示，解析后的文本完整保留了原文档的业务内容。
- 上传单份100MB的主生产计划PDF文件，确认解析完成耗时未超过预设的`PARSE_FILE_TIMEOUT_SECONDS`时长，任务状态显示为成功。
- 进入知识库的文档溯源页面，查看任意分块内容，确认都标注了来源文档的文件名与上传时间，溯源信息完整。

文中的配置项名称与取值区间需以所用版本的实际界面与文档为准。
