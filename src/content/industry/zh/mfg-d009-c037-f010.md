# 生产计划与车间排程的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据主要来自ERP订单与库存、BOM和工艺路线、设备产能、人员班次、在制品和供应商到货。更新节奏为每日、每周，或在订单、异常发生时触发更新。日常文档包含销售订单、主生产计划、物料需求计划、周日排产表、工单、缺料清单、交期变更单，字段涵盖订单号、物料编码、产能数值、班次时段、工单状态等，单位包含件、小时、天等基础生产单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类多源异构的数据特征要求检索需精准关联对应数据源的知识库集合，避免混入非生产计划类的无关内容。不同更新频率的数据源需要匹配对应的同步策略，确保召回数据的时效性。多样的文档结构需要适配不同的拆分与解析规则，例如带合并单元格的排产表需特殊处理。此外，该品类需按工单、订单追溯质量问题，检索需支持按业务实体过滤，同时需平衡召回条数与4096 token的上下文窗口限制，避免超出处理能力。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本，单知识库最大支持1000 MB的文档存储，具体参数设置如下：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `collectionIds` | 填写生产计划、车间排程相关知识库的集合ID列表 | 该品类数据来自ERP订单、BOM、设备产能等独立数据源，需精准关联对应知识库集合避免检索无关内容 |
| `similarity` | 0.72–0.85 | 该品类文档包含结构化数值与业务规则，阈值过低会引入无关排程异常记录，过高则无法召回关联工单的历史不良数据 |
| `limit` | 前8–12条 | 车间排程的异常关联数据通常分布在多份工单与排产表中，足够覆盖关联维度且不会超出4096 token的上下文窗口限制 |
| `searchMode` | 实体关联检索模式 | 该品类需按工单或订单追溯质量问题，精确匹配业务实体可减少无效召回 |
| `usingReRank` | 开启 | 该品类数据包含大量资源约束与工序规则，重排可过滤低相关性的记录，提升召回准确率 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 该品类业务规则相对固定，无需额外扩展查询词，避免引入非生产计划类无关数据 |

## 容易做错的三处
-  配置问答拆分时触发`Invalid array length`报错。原因是未适配生产计划类文档的结构化特征，例如直接对带合并单元格的周日排产表按固定长度拆分，导致解析时数组格式异常。
-  调试预览可正常检索知识库，但部署到自有页面后无法触发检索。原因是未正确指定`collectionIds`参数，或调用时未携带对应生产计划知识库的合法标识。
-  知识库检索结果条数与预期不符，仅返回少量排程记录。原因是未设置合理的`similarity`阈值，或未开启`usingReRank`导致低相关性记录被保留，覆盖了有效召回内容。

## 怎么确认配好了
-  核对`collectionIds`参数是否与当前绑定的生产计划、车间排程知识库集合ID完全一致。
-  发起针对具体工单编号的检索，验证返回结果是否包含对应工单的关联排程、物料需求等文档内容。
-  查看检索结果的相关性排序，确认开启`usingReRank`后结果的相关性符合业务预期。
-  模拟异常场景发起检索，例如「插单导致的排程异常追溯」，确认召回内容与业务规则匹配。
