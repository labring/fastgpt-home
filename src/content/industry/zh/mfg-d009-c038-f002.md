# 生物制品与无菌生产的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
这个品类的典型数据来源包括细胞库与种子批、过程分析、洁净区监测、MES、LIMS、设备完整性测试。日常文档涵盖细胞库或种子批记录、培养纯化记录、无菌灌装记录、环境监测、培养基模拟灌装、无菌检验、批放行资料。数据更新节奏分为每批、实时、按监测计划三类。文档字段包含批标识、过程参数、监测时间、检验结论等，对应单位包括摄氏度、菌落形成单位/平方米、小时等。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源分散的数据来源要求索引支持跨系统数据的统一接入与关联。不同更新节奏的数据需要适配增量索引与全量索引的混合配置，避免实时监测数据滞后或批记录同步不及时。与批绑定的数据结构要求索引按批分区，确保召回结果仅关联当前问题批次的相关记录。依赖过程与环境数据的业务特性，要求向量模型能够关联不同类型的参数与检验结果，提升追溯的精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配该品类单份过程记录的平均长度，匹配主流向量模型的输入限制 |
| 重叠长度 | 100–150 字符 | 避免跨块的关键参数（如培养温度区间）丢失上下文关联 |
| `maxToken` | 4096 token | 适配主流向量模型的输入上限，匹配单批记录的总内容量 |
| 相似度阈值 | 0.75–0.85 | 过滤低关联的非目标批次数据，精准召回同批或同过程的异常记录 |
| 单次搜索上限 | 前10条 | 平衡召回效率与结果完整性，避免冗余数据干扰不良分析 |
| `defaultToken` | 按实测标定 | 适配不同向量模型的默认上下文窗口，避免截断关键批标识信息 |

## 容易做错的三处
- 现象：向量召回结果中混入非当前批的环境监测数据，原因：未按批编号对索引数据进行分区过滤，导致跨批数据被错误召回。
- 现象：ollama部署的BGE-M3模型接入失败，控制台返回调用超时错误，原因：未配置正确的ollama向量模型端口映射，或向量模型服务未完全启动就发起调用。
- 现象：腾讯混元向量模型配置后调用返回401未授权错误，原因：未在FastGPT供应商配置中填写正确的API密钥与地域参数。

## 怎么确认配好了
- 导入单份批记录样本，核对向量入库后的数据字段完整性，确认批编号、关键参数均被正确编码。
- 发起针对已知异常批的搜索请求，核对召回结果是否包含同批的过程与环境数据，调整相似度阈值至符合业务需求的区间。
- 查看FastGPT v4.17.0的索引监控面板，确认增量数据同步频率与配置的更新节奏一致。
- 测试向量模型调用链路，确认返回的嵌入向量维度与配置的向量模型维度匹配。
