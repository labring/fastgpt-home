# 电机与发电机制造的质量问题追溯与不良分析：工作流编排

## 这个品类的数据长什么样
该品类数据来自电磁设计数据、铜线与绝缘材料批次、绕线设备、平衡机、电气试验台及ERP/MES系统。日常文档包含绕组工艺卡、绝缘处理记录、动平衡报告、耐压绝缘测试记录、型式与出厂试验报告。数据按每台、每批或每次型式变更更新，字段包含绕组匝数、接线方式、浸漆烘干参数、振动值、温升、效率、绝缘电阻值等，对应单位为匝、%、mm/s、K、%、MΩ。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据特征对工作流编排带来多重约束。数据按单台/单批次更新，工作流需通过`variables`绑定批次号或设备ID作为检索锚点，确保仅调用对应生产单元的关联文档。文档类型多且字段差异大，工作流需按不同文档类型配置检索规则，区分工艺卡、试验报告的字段匹配逻辑。同时受电磁、绝缘、平衡三重约束，工作流需通过`nodeId`串联绕线、绝缘、总装、试验等多环节数据，不能仅依赖单一模块检索。数据更新频繁，工作流需支持实时拉取最新MES数据，避免使用过期历史内容。

## 配置怎么定
本配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 变量引用 | 绑定批次号、设备ID、试验日期 | 锚定单台电机或单批次生产的关联数据 |
| 节点执行顺序 | 按绕组→绝缘→总装→试验的工艺流转配置 | 匹配电机制造的标准业务流程 |
| 单次召回条数 | 前8条 | 覆盖单批次关联的工艺卡、试验报告等文档数量 |
| 上下文长度 | 1200–1800字符 | 容纳多份核心文档的关键字段内容 |
| 超时阈值 | 600秒 | 适配型式试验的常规耗时周期 |
| 重排阈值 | 0.7–0.9 按实测标定 | 优化检索结果的相关性排序 |

## 容易做错的三处
- 测试工作流时，输出结果末尾额外出现“FastGPT 是一个基于大语言模型(LLM)的知识库问答系统”。原因是未在系统提示词中禁用默认推广话术，导致大模型生成冗余内容。
- 配置多工具串联的工作流时，部分工具未执行且未按预设顺序运行。原因是未正确配置`nodeId`关联的执行链路，或未开启顺序执行开关。
- 使用docker-compose部署后，工作流与知识库配置变为空白，但接口可正常调用。原因是挂载的本地卷权限不足，导致配置文件无法持久化保存。

## 怎么确认配好了
- 触发测试工作流，输入指定批次号，核对检索到的文档是否仅关联该批次的工艺与试验记录。
- 查看工作流节点执行日志，确认所有配置的工具按预设顺序依次启动并完成调用。
- 检查系统提示词，确认未包含未授权的推广话术，输出结果无冗余内容。
- 验证超时阈值配置，模拟长耗时的试验数据检索环节，确认工作流未触发异常超时。
