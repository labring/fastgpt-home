# 石油炼制的质量问题追溯与不良分析：向量模型与索引
本文档基于FastGPT v4.17.0版本的界面与参数逻辑制定

## 这个品类的数据长什么样
石油炼制的业务数据覆盖生产运行、工艺、调度、设备与化验等部门，日常文档包含操作规程、生产方案、物料平衡表、馏出口质量报告、联锁台账、交接班记录、变更管理文件等。数据来源包括DCS/APC系统、LIMS实验室管理系统、罐区计量系统、原油评价数据库、设备管理系统与能源系统。数据更新节奏涵盖实时工况数据、每班交接班记录、每日物料平衡报告，字段包含工艺位号、馏程数值、联锁触发条件、班次信息等，部分数据带有明确的物理单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源异构的数据来源要求索引支持混合格式的文档解析，包括结构化的LIMS报表与非结构化的操作规程。实时更新的DCS数据需要索引支持增量同步，避免全量重索引带来的性能损耗。多套连续装置的耦合关系要求向量检索能够关联跨装置的工艺文档，因此索引需保留文档间的关联元数据。原料性质波动大的特点，要求向量匹配的阈值需适配不同工况的文本特征，同时交接班记录与变更文件的高频更新，需要控制单批次索引的文档数量与处理时长。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 分块长度 | 800–1200 字符 | 适配炼油工艺文档的单段内容长度，避免跨块丢失工艺关联信息 |
| 重叠长度 | 100–150 字符 | 保留跨分块的工艺参数与操作步骤关联，确保检索时覆盖完整的工艺逻辑 |
| 相似度阈值 | 0.75–0.85 | 匹配炼油工艺的严谨性要求，过滤低置信度的非相关文档 |
| 单次搜索上限 | 前 20 条 | 控制检索结果的信息量，适配多装置数据的关联展示需求 |
| 最大上下文 | 4000 token | 容纳多份工艺文档与实时数据的关联内容，满足质量追溯的上下文需求 |
| `defaultToken` | 按实测标定 | 适配LIMS系统导出的文本长度，确保嵌入向量的维度与索引库兼容 |

## 容易做错的三处
- 现象：某交接班记录文件始终显示在索引中，未完成索引。原因：该文件包含大量无意义的空行与重复换行，分块处理时触发了异常循环。
- 现象：切换知识库索引时出现60秒超时报错。原因：该知识库包含多套装置的实时DCS数据，数据量超出了单次索引的处理阈值。
- 现象：调用bge-large-zh-1.5时返回嵌入维度不匹配的提示。原因：未配置与模型嵌入维度一致的向量索引参数，或调用的第三方API返回的维度与平台要求不符。

## 怎么确认配好了
- 上传一份典型的馏出口质量报告，查看索引完成状态是否在预设的合理时间内更新。
- 发起针对某装置异常工况的质量追溯查询，检查返回的检索结果是否包含对应装置的操作规程、联锁台账与LIMS化验数据。
- 调整相似度阈值，验证检索结果的匹配度是否符合炼油工艺的业务判断逻辑。
- 测试`defaultToken`的配置参数，确认嵌入后的向量维度与索引库的存储要求一致。
