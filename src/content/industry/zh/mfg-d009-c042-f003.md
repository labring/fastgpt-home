# 石油炼制的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
石油炼制场景的数据来源覆盖DCS/APC实时工艺系统、LIMS化验系统、罐区计量系统、原油评价数据库、设备管理系统与能源管理系统。日常文档包含操作规程、生产方案、物料平衡表、馏出口质量报告、联锁台账、交接班记录与变更管理文件。数据更新节奏分为实时（工艺参数）、每班（交接班记录）、每日（物料平衡与质量报告），核心字段包含工艺温度、压力、流量，单位分别为℃、MPa、m³/h，以及油品硫含量、十六烷值、罐区液位与原油标号等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多套连续装置通过物流与氢气网络耦合的特征，要求多轮对话需关联不同装置的历史参数，避免孤立分析单装置数据。多源异构数据的更新节奏差异，要求提示词需明确指定数据的检索周期与来源系统，防止跨时间、跨系统的无效数据被召回。多样的文档类型与专属业务字段，要求提示词需预设原油标号、装置编号等核心变量，快速定位匹配的业务文档与数据。

## 配置怎么定
本配置基于FastGPT v4.17.0版本
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 上下文窗口大小 | 8000–12000 token | 覆盖多装置耦合的工艺数据与多轮追溯对话，避免关键信息丢失 |
| `chatId` | 绑定单生产装置的会话标识 | 区分不同单元的追溯数据，防止跨装置上下文混淆 |
| `messages` | 保留最近20轮对话与前3次核心工艺调整记录 | 关联前期操作与当前问题，支撑完整追溯逻辑 |
| `variables` | 预设原油标号、装置编号、化验日期变量 | 匹配炼油场景核心业务字段，快速定位关联数据 |
| 工具调用触发阈值 | 0.75–0.85 | 准确匹配工艺参数与问题的关联度，减少无效工具调用 |

## 容易做错的三处
- 配置MySQL工具调用后返回400 status code (no body)。原因是未正确绑定`variables`中的数据库连接参数，或`chatId`未携带合法会话标识导致请求格式不规范。
- 无法在当前对话中切换模型或添加联网调用按钮。原因是未在`messages`上下文配置中开启模型切换权限，或未预设对应模型的调用变量。
- 检索到的馏出口质量数据与实际不符。原因是未在提示词中限定`variables`中的化验日期范围，导致跨周期数据被召回。

## 怎么确认配好了
- 发起包含预设`variables`字段的查询，验证系统能否自动关联对应原油标号、装置编号的历史数据。
- 发起两轮以上的连续对话，检查`messages`上下文是否保留了指定轮次的历史记录，未出现不必要的信息截断。
- 调用配置好的数据库工具查询指定工艺参数，验证返回结果与DCS/APC系统的实时数据一致。
- 执行`chatId`维度的会话清理操作，验证对应会话的历史记录被彻底清除。
