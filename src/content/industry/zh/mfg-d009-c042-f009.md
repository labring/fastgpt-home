# 石油炼制的质量问题追溯与不良分析：模型接入与配置
本文基于FastGPT v4.17.0版本编写。
## 这个品类的数据长什么样
石油炼制场景的数据涵盖多系统来源，包括DCS/APC实时采集的装置运行参数、LIMS生成的馏出口质量报告、罐区计量的物料数据、原油评价报告、设备管理台账及能源系统能耗数据。日常文档包含操作规程、生产方案、物料平衡表、联锁台账、交接班记录与变更管理文件。数据更新节奏覆盖实时、每班及每日，字段包含原油密度、馏程、产品硫含量、装置负荷等，附带对应工程单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构数据的实时、分批更新要求模型接入时支持流式数据拉取与定时增量同步，避免全量拉取占用过多系统资源。多样的文档类型与字段需要配置适配不同数据结构的解析规则，确保质量报告中的硫含量、装置联锁日志等字段能被准确识别。连续耦合的装置流程要求模型上下文能覆盖多环节关联数据，同时需限制单轮处理的token数量，防止请求超时。此外，炼油场景的不良分析需关联历史联锁、物料平衡数据，要求配置项支持多源数据的关联召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 覆盖多装置耦合的流程数据与历史分析文档，避免关键上下文截断 |
| `maxTokens` | 4000 token | 控制单轮响应长度，适配炼油分析报告的详细输出需求，防止超时 |
| `quoteMaxToken` | 1500 字符 | 限制召回文档的单段长度，匹配炼油质量报告的单条记录字段长度 |
| `toolChoice` | auto | 允许模型自主选择工具调用，适配多源数据的关联查询需求 |
| `temperature` | 0.3–0.5 | 降低随机生成概率，确保不良分析结果的一致性与可追溯性 |
| `AIPROXY_API_TOKEN` | 与部署模型匹配的密钥 | 完成模型访问的身份验证，避免未授权请求被拦截 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配Ollama或其他本地部署的模型接入地址，确保模型调用连通性 |

## 容易做错的三处
- 配置`toolChoice`为`none`时，模型无法触发工具调用，表现为无法返回实时装置数据或历史联锁记录。原因是强制关闭了工具调用权限，未适配炼油场景需关联多系统数据的需求。
- 设置`maxContext`超过16000 token时，模型调用出现504超时错误。原因是本地部署的Ollama资源不足，无法承载过长上下文的处理请求。
- 未配置`AIPROXY_API_TOKEN`时，模型接入请求返回401未授权错误。原因是未正确填写模型访问的身份验证令牌，导致请求被拦截。

## 怎么确认配好了
- 发起包含多装置参数查询的测试请求，检查模型是否能召回对应DCS系统的实时数据，验证工具调用功能正常。
- 提交包含长文本的质量报告分析请求，检查响应是否在预设的`maxTokens`范围内，无截断或超时。
- 查看模型接入日志，确认请求能正确携带`AIPROXY_API_TOKEN`并返回200状态码，验证连通性。
- 调整`temperature`参数后发起重复测试，检查分析结果的一致性，确认参数生效。
