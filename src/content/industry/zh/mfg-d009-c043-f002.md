# 精细化工间歇合成的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
本品类的数据主要来自配方与工艺库、原料批次台账、反应釜DCS系统、称量系统、LIMS实验室信息管理系统、仓储管理系统。数据更新节奏为每生产批次、每个关键工艺步骤触发。日常文档包含批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单。数据字段包含批次号、投料量（千克/升）、反应温度（摄氏度）、反应时长（小时）、清场验证结果等，部分文档需关联多系统的跨字段信息。

## 这些特征在「向量模型与索引」这一环带来什么约束
多批次、高频次的更新节奏要求索引支持按批次维度快速精准召回，避免跨批次无关数据干扰追溯结果。跨系统的多文档关联特征，要求向量模型需支持跨字段语义关联，适配不同来源文档的关联匹配。单批次数据量虽不大但更新频繁，需控制单次写入的token消耗，避免超出`defaultToken`或`maxToken`限制。同时，配方与工艺的保密性要求索引的召回结果需严格限定权限范围，分块时需保留工艺步骤的上下文关联，避免拆分破坏反应逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 匹配本品类单份工艺记录的典型段落长度，避免拆分破坏反应步骤的语义连贯性 |
| 重叠长度 | 100–200 字符 | 保留相邻分块的工艺上下文，防止跨步骤的反应逻辑被分块截断 |
| 段落识别深度 | 3 | 适配本品类工艺文档的段落层级，精准识别反应步骤的上下文关联 |
| 向量维度 | 128 维 | 适配本品类常用的Embedding模型输出维度，平衡索引存储与召回精度 |
| 相似度阈值 | 按实测标定 | 需结合本品类的偏差记录、检验报告的语义特征调整，避免召回无关批次数据 |
| 单次搜索上限 | 前 8 条 | 适配本品类单批次问题的关联数据量，平衡召回精度与响应速度 |
| 重排开关 | 开启 | 针对多系统跨字段的关联数据，优化召回结果的语义相关性 |
| 最大上下文长度 | 4000–6000 token | 容纳单批次的多份关联文档，满足质量追溯时的全链路信息调用 |

## 容易做错的三处
-  刷新页面后提示“检测到没有可用的索引模型”，原因是未将本品类的工艺、检验类文档关联至指定的向量模型，或模型配置未保存生效。
-  接入多模态Embedding模型时返回格式错误，原因是未适配本品类文档的非文本字段（如DCS的温度曲线数据）的嵌入格式，导致模型无法正常解析输入。
-  升级新版本后老向量库数据无法正常召回，原因是新旧版本的分块规则或向量维度不匹配，未执行批次化的数据重索引流程。

## 怎么确认配好了
-  进入知识库管理页面，查看本品类关联的向量模型状态，确认模型处于可用且已授权状态。
-  上传一份本品类的典型投料复核单，执行手动分块测试，确认分块长度符合预设配置。
-  发起一次质量追溯的模拟查询，核对召回结果的批次号、工艺步骤是否与查询条件匹配。
-  查看索引写入日志，确认单次写入的token消耗未超出`maxToken`限制。
-  确认当前使用FastGPT v4.17.0版本，避免版本兼容性问题。
