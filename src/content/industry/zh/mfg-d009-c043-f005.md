# 精细化工间歇合成的质量问题追溯与不良分析：工具调用与插件

## 这个品类的数据长什么样
该品类数据来自涂料、树脂、助剂、农化中间体等精细化工企业的配方与工艺库、原料批次台账、反应釜DCS系统、称量系统、LIMS及仓储系统。日常文档包含批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单，字段涵盖原料批次号、投料量（千克）、反应温度（℃）、反应时长（小时）等。数据按每批生产任务、每个关键反应步骤更新，单批数据关联完整生产全流程节点信息。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类按单批、单步骤更新的多源异构数据特征，对工具调用与插件带来三点约束。第一，需按生产批次维度触发工具调用，避免跨批次数据混淆。第二，需适配多类型文档的解析需求，插件需分别支持结构化投料单、时序反应记录、清场记录的格式提取。第三，因涉及配方保密与生产合规，工具调用需绑定权限校验逻辑，仅允许授权角色调用敏感数据接口。此外，多步骤切换的生产流程要求插件按反应顺序依次调用对应系统的数据，可通过`functionCall`绑定批次号参数确保逻辑连贯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | 按`functionCall`强制触发 | 确保工具调用符合预设的质量追溯流程，避免大模型自主选择无关工具 |
| 单次工具调用超时 | 600秒 | 单批生产数据需拉取多系统信息，耗时较长，避免中途中断 |
| 工具返回结果条数 | 前3条 | 单批生产关联的关键节点数据有限，过多结果会增加分析冗余 |
| 工作流/API 函数调用配置 | 绑定批次号参数 | 确保每次工具调用仅拉取当前追溯批次的相关数据，防止跨批次混淆 |
| 工具调用上下文窗口 | 8000–12000 token | 按实测标定，适配多文档拼接后的内容长度 |
本配置适用于FastGPT v4.17.0版本。

## 容易做错的三处
- 现象：输出内容中出现「引用标记：［1］」字样。原因：工具调用未配置结果清洗步骤，未过滤原始文档的索引标记。
- 现象：用户输入指定关键词后，系统未触发自定义接口回复，直接返回默认回答。原因：未在插件配置中添加关键词触发规则，或规则未绑定到对应工具调用节点。
- 现象：调用自定义接口时返回400状态码，提示参数缺失。原因：工具调用未传递批次号、原料批次等必填参数，不符合自定义接口的入参要求。

## 怎么确认配好了
- 发起单批次质量追溯测试，检查输出内容中是否包含无关批次的系统数据。
- 触发工具调用，确认返回结果的条数符合预设配置。
- 输入包含敏感配方关键词的测试内容，检查是否触发权限拦截或自定义接口回复。
- 查看工具调用日志，确认每次调用均携带当前批次号参数，无跨批数据拉取。
