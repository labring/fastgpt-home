# 精细化工间歇合成的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类数据来自涂料、树脂、助剂、农化中间体等精细化工企业的多类业务系统与纸质文档。日常留存批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单等文档。数据来源覆盖配方与工艺库、原料批次台账、反应釜DCS系统、称量系统、LIMS实验室管理系统、仓储管理系统。数据更新以每批生产、每个关键反应步骤为节奏，字段包含投料量、反应温度、停留时间、清场验证结果等，单位涉及千克、摄氏度、小时等，且部分配方相关字段涉及保密要求。

## 这些特征在「模型接入与配置」这一环带来什么约束
多批次、多步骤的更新节奏要求模型接入时支持按批次维度拉取关联数据，避免跨批次数据混淆。涉及配方保密的字段需要在数据接入环节做脱敏处理，防止敏感信息泄露。数据来源分散于多个系统，需要配置跨源数据关联规则，确保投料、反应、检验等环节的数据能被模型统一调用。单批次数据量有限但字段关联性强，模型上下文长度需要适配单批次完整流程的文档长度，同时需限制非必要数据的召回范围，避免无效信息干扰分析。另外，清场验证、交叉污染风险等字段需要作为关键召回条件，模型工具调用需优先匹配这些字段。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 单批次精细化工反应流程的文档总token数通常处于该区间，可覆盖投料、反应、检验全流程的关联数据 |
| `temperature` | 0.2–0.4 | 质量追溯与不良分析需要严谨的逻辑推导，该取值区间可保证分析结论的一致性，避免过度随机性 |
| 工作流/API 工具选择配置 | auto | 适配多源数据关联的分析需求，支持模型自主调用数据查询、文档比对等工具完成不良分析 |
| `AIPROXY_API_ENDPOINT` | 企业专属代理地址 | 涉及配方保密数据，通过企业自有代理传输可避免敏感信息在公网传输泄露 |
| `AIPROXY_API_TOKEN` | 企业统一分配的鉴权令牌 | 实现接口访问的权限管控，防止未授权调用模型接口 |

## 容易做错的三处
-  配置模型时仅添加Ollama支持的模型，导致无法调用业务所需的专业模型。原因是未正确配置模型代理渠道，未将支持的模型接入对应API端点。
-  调用语音识别模型时出现“当前分组default下对于模型whisper-1无可用渠道”报错。原因是未在配置中为whisper-1模型绑定对应渠道，或渠道权限未正确分配。
-  配置TTS模型时未正确填写voices参数，导致语音生成失败。原因是未参考模型官方文档填写符合要求的语音标识列表，参数格式不符合接口要求。

## 怎么确认配好了
-  检查FastGPT v4.17.0的模型接入配置页面，确认已添加的模型列表包含业务所需的专业模型，且对应API端点与鉴权令牌有效。
-  发起单批次数据的关联查询测试，验证模型能否正确拉取投料、反应、检验等环节的关联数据，返回结果的字段覆盖关键业务参数。
-  触发一次不良分析模拟请求，确认模型能自主调用工具完成数据比对，且输出结果符合业务逻辑，无敏感信息泄露。
-  查看系统运行日志，确认接口调用无超时、权限报错等异常，模型响应时间符合业务预期。
