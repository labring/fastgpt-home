# 精细化工间歇合成的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
该品类数据来源包括配方与工艺库、原料批次记录、反应釜DCS数据、称量系统日志、LIMS系统、仓储库存数据。日常文档包含批生产指令、投料复核单、反应过程记录、清场记录、检验报告、偏差与变更单，每份文档包含批次号、投料量、反应温度、停留时间等字段，单位涵盖千克、摄氏度、小时等。数据更新频率为每生产批次或每个关键工艺步骤更新一次，且因多品种切换生产，单批次数据关联多套工艺与清场记录，需精准匹配生产节点的上下文信息。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多批次、多维度关联的工艺数据，要求检索需支持按批次号、工艺步骤、设备编号等多条件组合过滤，避免无关跨批次数据干扰召回结果。按单批次或关键步骤更新的动态数据，要求检索能匹配实时工艺节点的上下文，适配生产过程中的即时查询需求。文档中包含保密配方与敏感工艺参数，要求检索结果需做权限校验，仅返回授权范围内的内容。多品种切换生产带来的清场验证需求，要求检索能关联同设备不同批次的清洗记录，同时需保留文档原有的层级逻辑，避免结构丢失。

## 配置怎么定
本文基于FastGPT v4.17.0版本编写。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 精细化工工艺参数精度要求高，需过滤低相关性的通用工艺文档，保留匹配度达标且关联批次信息的结果。 |
| `limit` | `前6条` | 单批次工艺关联文档数量有限，过多召回会超出上下文窗口，影响大模型分析精度。 |
| `searchMode` | `mixedRecall` | 需同时匹配工艺参数的语义与批次号、设备编号等关键词，适配多条件检索需求。 |
| `usingReRank` | `开启` | 工艺文档相似度易受批次编号干扰，重排可修正初始召回的排序偏差，优先返回关联当前批次的结果。 |
| `datasetSearchUsingExtensionQuery` | `开启` | 生产问题描述常包含模糊表述，扩展查询可补充关联的工艺步骤、检验指标等关键词，提升召回覆盖率。 |
| `collectionIds` | `按当前生产批次绑定的知识库集合ID` | 需限定检索范围在当前批次关联的工艺、检验、清场文档集合内，避免跨品类无关数据干扰。 |

## 容易做错的三处
- 现象：检索结果丢失文档标题与从属分类的层级逻辑，无法关联对应工艺步骤。原因：未保留markdown文档的标题层级，仅按分段拆分数据，导致语义关联断裂。
- 现象：检索结果中数字与文字间出现多余空格，影响工艺参数读取。原因：知识库拆分时未处理原始文档的格式残留，未对齐数字与单位的显示规则。
- 现象：无法召回反应釜DCS的实时过程数据。原因：未配置`collectionIds`限定检索范围为绑定的实时数据集合，导致检索覆盖了无关文档。

## 怎么确认配好了
- 输入指定批次号与工艺步骤关键词，检查检索结果是否仅返回该批次关联的文档。
- 上传带标题层级的markdown工艺文档，验证检索结果是否保留了标题与内容的从属关系。
- 测试模糊问题描述，如“某批次反应异常”，检查是否能召回关联的偏差与变更单文档。
- 查看检索结果的相似度得分，确认得分落在预设的`similarity`区间内。
