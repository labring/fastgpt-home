# 纸浆造纸的质量问题追溯与不良分析：文档解析与分块

## 这个品类的数据长什么样
纸浆造纸行业的质量追溯相关数据通常来自木浆废纸批次、DCS/QCS系统、纸机在线测量设备、实验室、能源和水处理系统。日常文档包含配浆单、打浆记录、纸机运行记录、在线质量曲线、实验室报告、断纸与换品记录等，更新频率涵盖实时、每班、每卷。数据字段包含浆料配比、克重、水分、厚度等，部分文档带有时序坐标或卷号标识。

## 这些特征在「文档解析与分块」这一环带来什么约束
多来源、多格式的文档类型要求解析模块兼容结构化表格、时序记录与内嵌图表，避免丢失卷号、批次号等关键锚点。实时或高频更新的文档需要按时间切片或文档边界进行分块，防止跨批次数据混杂影响追溯准确性。单份文档可能包含单卷或多卷纸的质量数据，分块规则需匹配文档的分页或页眉标识，确保每个分块的上下文关联度符合质量分析的逻辑。

## 配置怎么定
以下配置基于 FastGPT v4.17.0 版本制定。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 适配纸浆造纸文档中结构化表格、时序记录的单块信息密度，避免单块包含跨批次数据 |
| `chunkSplitter` | 按段落+页眉页脚分割 | 匹配配浆单、纸机运行记录的分页逻辑，保留卷号、批次号等上下文锚点 |
| `customPdfParse` | 启用 | 适配在线质量曲线、实验室报告的PDF内嵌图表解析，保留原始数值坐标 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 覆盖单份大型纸机运行日志的解析耗时，避免超时中断 |
| `chunkSettingMode` | 手动配置 | 针对不同文档类型（如配浆单、断纸记录）调整分块规则，适配多格式文档场景 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配单卷纸机运行日志的文件大小上限，支持大型文档上传 |

## 容易做错的三处
- 上传的PDF解析后浆料配比、克重等数值字段为空，原因是未启用`customPdfParse`，内置默认解析器无法提取内嵌质量曲线的原始数值数据。
- 解析单份超过500MB的纸机运行日志时触发超时报错，原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`，默认超时阈值不足以覆盖大型文档的解析耗时。
- 分块结果包含不同卷号的质量数据，原因是未按页眉的卷号作为分割锚点，`chunkSplitter`配置为按固定字符分割导致上下文混杂。

## 怎么确认配好了
- 上传单份配浆单PDF，检查解析后是否保留了批次号、浆料配比等关键字段。
- 上传单份500MB的纸机运行日志，确认解析过程未触发超时报错。
- 查看分块结果，确认每个分块仅包含单卷纸的质量数据或单份文档的同一批次内容。
- 测试调用节点时，上传的文件可直接传入大模型上下文，无需经过系统默认的文本解析流程。
