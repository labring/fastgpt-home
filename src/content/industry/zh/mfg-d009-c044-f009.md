# 纸浆造纸的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
纸浆造纸场景的数据来自木浆废纸批次台账、DCS/QCS系统、纸机在线测量设备、实验室检测报告、能源与水处理系统，以及备料、制浆、抄纸环节的配浆单、打浆记录、纸机运行日志、断纸换品档案。数据更新节奏覆盖实时、每班、每卷，字段包含浆料配比、打浆度、克重、水分、厚度等工艺参数，以及对应批次的质量判定结果，单位多为%、g/m²、秒、米等工艺常用单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
纸浆造纸场景的数据来源分散且更新节奏差异显著，实时在线数据需高频接入，每班、每卷的批次数据需按生产链路关联，要求模型接入支持多数据源的定时拉取与实时同步。单批次数据包含多维度工艺参数与质量判定结果，模型输入需支持长上下文拼接，同时需按生产批次做数据分片，避免跨批次信息干扰。纸机在线质量曲线为时序数据，模型需适配时序特征解析，断纸、换品等异常事件需快速触发分析，因此配置需兼顾实时推理与批量回溯的兼容性。

## 配置怎么定
本配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单批次配浆、打浆、抄纸全链路的历史数据拼接需求，覆盖多份工艺记录与质量报告的上下文长度 |
| `maxTokens` | 2000–3000 token | 控制单轮分析的输出长度，避免因工艺参数过多导致推理超时，适配纸病追溯的短结论输出场景 |
| `quoteMaxToken` | 1500–2000 字符 | 限定召回的源文档片段长度，匹配在线质量曲线、打浆记录等单条文档的典型长度 |
| `temperature` | 0.2–0.4 | 降低随机输出，确保质量追溯结果的一致性，适配工艺参数与质量结果的精准匹配需求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写专属接入地址 | 适配纸浆造纸场景的私有部署或专线接入需求，避免公网延迟影响实时分析 |
| `toolChoice` | auto | 允许模型自主选择是否调用检索工具，适配不同类型的质量问题（如已知纸病匹配、未知异常溯源） |

## 容易做错的三处
- 配置`AIPROXY_API_ENDPOINT`时填写错误的地址，测试时返回404 page not found。原因是未匹配FastGPT部署环境对应的代理接口路径，导致请求无法正确路由到目标模型服务。
- 未按生产批次拆分召回数据，导致模型识别问题分类不灵活。原因是召回的上下文包含跨批次的无关工艺参数，干扰模型对当前异常的特征提取。
- 未调整`maxTokens`参数，上传批量工艺记录后触发请求失败。原因是单轮推理的输出上限未适配多份文档的解析需求，导致请求超时或被服务端拦截。

## 怎么确认配好了
- 发起单批次质量追溯测试，检查模型返回结果是否关联当前批次的配浆单、打浆记录等源文档。
- 模拟异常事件触发分析，确认模型是否能正确召回对应时间段的纸机运行数据与质量曲线。
- 查看FastGPT的日志面板，确认模型请求的响应状态码为200，无超时或路由错误。
- 调整`temperature`参数后，对比两次分析结果的一致性，验证参数配置是否生效。
