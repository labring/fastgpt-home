# 纺纱与织造的质量问题追溯与不良分析：向量模型与索引

本文适配FastGPT v4.17.0版本的向量模型与索引配置逻辑。

## 这个品类的数据长什么样
该品类数据主要来自棉纺、化纤纺、机织与针织企业的日常业务与设备采集，包含配棉配料单、工艺上机单、设备运转记录、纱线与坯布检验报告、疵点台账等文档。数据来源覆盖原纤维检验、ERP系统、纺机织机实时数据、条干仪、验布机及订单规格文件，更新节奏随每批原料、每班生产、每匹布产出同步更新，单份文档多包含纤维指标、工艺参数、检验数值、疵点类型等字段，部分设备数据带有时间戳与设备编号。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据更新节奏快、来源分散且字段类型多样，要求向量索引支持高频增量更新与多源数据融合。单份文档包含纤维指标、工艺参数、疵点类型等多维度信息，且疵点记录与生产批次、设备编号强绑定，需要索引支持按业务维度精准筛选召回。同时设备与检验数据多为结构化数值与短文本结合，需向量模型适配混合格式的文本编码，避免因数据颗粒度不匹配导致召回偏差，且因疵点会连续传播，需保证召回结果的时效性与关联性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类单份检验记录、工艺单的文本长度，避免单块包含过多无关业务字段 |
| 重叠长度 | 100–200 字符 | 覆盖跨块的工艺参数与疵点关联信息，避免关键关联内容被分割 |
| 相似度阈值 | 0.72–0.85 | 过滤低关联的疵点与工艺数据，适配连续布疵的精准追溯需求 |
| 单次搜索上限 | 前 10 条 | 平衡召回效率与结果完整性，匹配企业单批次疵点排查的样本量 |
| `maxToken` | 8192 | 适配Qwen/Qwen3-Embedding-8B的输入长度限制，避免文本截断导致信息丢失 |
| 分块策略 | 按业务节点拆分 | 以配棉批次、生产班次、布卷编号为拆分依据，保留业务关联完整性 |

## 容易做错的三处
- 现象：添加同名向量模型时，原有配置被覆盖，界面仅显示最新添加的模型。原因：未为不同部署实例或场景创建唯一的模型标识，导致同名配置项被系统覆盖。
- 现象：导入Excel格式的检验数据后，知识库分块过大，检索时返回结果颗粒度粗糙，无法定位单匹布的具体疵点。原因：未按业务节点调整分块参数，直接使用默认分块规则处理结构化的多行检验数据。
- 现象：本地Docker部署的M3E模型无法正常完成索引构建，检索时返回空结果。原因：未在FastGPT的模型配置中正确填写本地部署的API地址与端口，或未开启模型的跨域访问权限。

## 怎么确认配好了
- 上传单份配棉单文档，查看分块预览界面，确认分块长度符合预设值且未丢失关键纤维指标字段。
- 输入单条疵点查询词，查看检索结果列表，确认返回结果的数量与相似度符合预设的规则。
- 切换至本地部署的M3E模型，执行一次检索测试，确认模型返回结果无报错且匹配查询意图。
- 导入批量Excel检验数据，查看知识库的分块统计，确认分块粒度匹配业务排查的最小单元。
