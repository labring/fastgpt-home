# 纺纱与织造的质量问题追溯与不良分析：工具调用与插件

## 这个品类的数据长什么样
本品类数据主要来自原纤维检验、ERP系统、纺机与织机运行数据、条干仪、验布机及订单规格文档。更新节奏随每批原料、每班生产、每匹布产出同步推进。日常留存的文档包含配棉或配料单、工艺上机单、设备运转记录、纱线检验报告、坯布检验记录与疵点台账。字段涵盖纤维细度指标、纺纱捻度参数、织机转速、疵点类型、匹号与订单批次等，随生产环节不同存在格式差异。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据来源分散且更新频率高，工具调用需支持多数据源同步读取，避免单次调用超时。不同生产环节的文档格式不统一，插件需适配非结构化文本解析，无法依赖固定字段提取规则。每匹布的疵点记录与批次强绑定，工具调用时需传递完整的匹号与订单批次参数，否则无法完成精准追溯。同时，生产数据的实时性要求较高，插件调用的响应延迟需匹配生产节拍，不宜过长。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 工作流/API 工具选择配置 | `auto` | 适配多类型生产数据源的自动调用，无需手动指定工具 |
| 工作流/API 函数调用配置 | 开启 | 强制插件调用遵循标准化参数格式，降低解析出错概率 |
| 单次工具调用超时时间 | 600 秒 | 覆盖多设备数据批量拉取的耗时，匹配生产数据同步节奏 |
| 输入参数校验 | 开启匹号、订单批次字段校验 | 确保批次信息准确，支撑精准质量追溯 |
| 插件重试次数 | 2次 | 应对临时网络波动导致的调用失败，避免中断生产流程 |
| 上下文窗口大小 | 按实测标定 | 适配单批原料对应多工序文档的长度需求 |

## 容易做错的三处
- 工作流中工具调用在调试模式正常、运行模式报错。原因是运行模式下未配置生产环境的数据源访问权限，或环境变量未同步调试阶段的配置。
- 插件调用出现连接失败，本地部署时使用127.0.0.1无法访问。原因是容器内网络隔离，需使用容器内部服务域名或正确的宿主机映射端口。
- 工作流运行时出现未调用的模型报错日志。原因是工作流中残留了已删除的模型调用节点，或系统缓存了旧的工作流配置未更新。

## 怎么确认配好了
- 使用FastGPT v4.17.0版本的系统，手动触发一次工具调用，检查返回结果是否包含正确的匹号、订单批次信息，无缺失字段。
- 模拟生产环境的网络波动，观察插件调用是否按配置的重试次数自动重试，未出现直接报错。
- 对比调试模式与运行模式的工具调用日志，确认两者的参数传递、权限配置完全一致。
- 调整上下文窗口大小，验证长文档的解析与调用是否正常，无截断或超时问题。
