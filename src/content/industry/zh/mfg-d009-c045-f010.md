# 纺纱与织造的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
通常的文档包括配棉或配料单、工艺上机单、设备运转记录、纱线检验、坯布检验、疵点记录。数据来源涵盖原纤维检验、ERP系统、纺机与织机实时数据、条干仪、验布机检测数据、订单规格文件。更新节奏随每批原料、每班生产、每匹布产出同步更新，文档字段多涉及纤维指标、工艺参数、疵点类型与位置、检验数值等，无统一固定格式，多按生产环节拆分存储。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类数据更新频率高且按生产节点拆分，要求知识库检索需支持高频增量同步，避免召回过时的工艺或检验数据。多环节分散的文档结构，要求检索需按生产链路关联配棉、工艺、检验等不同类型文档。字段类型多样且无统一格式，要求召回规则需适配纤维指标、疵点描述、设备参数等多类字段。设备头数多导致疵点易连续传播，要求检索需同时关联上下游设备的运转记录，缩小追溯范围，提升分析效率。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | 适配疵点描述、工艺参数等多类文本的匹配精度，避免召回无关的检验记录 |
| `limit` | 前6–8条 | 纺纱织造的疵点与工艺关联项较多，限制召回条数避免上下文过载，影响分析逻辑 |
| `searchMode` | 全文检索 | 适配多字段、非结构化的生产文档，支持跨文档关联检索配棉、工艺、检验等环节的内容 |
| `usingReRank` | 开启 | 针对设备运转记录、疵点记录这类时序数据，重排可提升关联结果的排序准确性，优先返回与问题最相关的内容 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于配棉单、工艺单的关键词扩展检索，覆盖纤维指标、捻度等隐藏关联项，提升召回覆盖率 |
| `collectionIds` | 按生产环节分组配置 | 分别关联配棉配料、工艺上机、检验记录等独立知识库集合，缩小检索范围，减少无关结果 |

## 容易做错的三处
- 现象：检索结果中包含未配置的知识库文档，无明确错误提示但结果不符合生产链路逻辑。原因：未通过`collectionIds`指定需要检索的知识库集合，导致全量知识库被扫描召回。
- 现象：调用检索接口时返回`quote type error`报错。原因：传入的参数格式不符合要求，例如未按规范传递`similarity`的浮点数值，或未使用正确的数组格式传递`collectionIds`。
- 现象：输入与知识库某文本块完全一致的问题，却未召回该结果。原因：`similarity`阈值设置过高，或未开启`datasetSearchUsingExtensionQuery`导致关键词扩展不足，无法匹配到隐藏关联项。

## 怎么确认配好了
- 上传单份配棉配料单至指定知识库集合，输入“配棉比例不合格”，核对检索结果是否仅包含该文档的相关内容。
- 调整`similarity`参数至0.75，输入“纱线强力不足”，核对返回结果的排序是否符合疵点与工艺的关联逻辑。
- 开启`usingReRank`后，输入“坯布出现连续疵点”，核对召回结果中是否包含上下游设备的运转记录。
- 检查接口调用参数，确认`collectionIds`已传入正确的知识库集合ID，无空值或无效ID。
