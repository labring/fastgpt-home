# 肉制品与屠宰加工的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
本品类的数据主要来自动物检疫信息、供应商批次记录、生产追溯台账、冷链温度采集、金属检测数据及实验室微生物检验报告。日常文档包含检疫证明、屠宰与分割记录、配料腌制记录、热加工记录、冷链温度日志、微生物检验单。数据更新频率为每批生产、每班作业更新，冷链温度需连续采集存储。数据字段包含批次编号、检疫编号、温度值（℃）、检测时间、微生物指标数值等，部分文档为结构化表格与非结构化文本混合形式。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据更新频率高且关联批次维度，要求向量索引支持增量更新以适配每批、每班的高频写入。数据包含结构化的批次、温度字段与非结构化的检验记录，需要向量模型同时适配结构化语义与自然语言语义的匹配。冷链温度的连续采集会产生大量时序数据，索引需支持按时间范围快速筛选。此外，数据关联检疫、微生物检测等合规相关内容，对检索结果的准确性要求较高，需避免无关数据的误召回。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配屠宰记录、检疫证明的单份文档长度，避免跨批次分块导致关联断裂 |
| 重叠长度 | 100–150 字符 | 保留批次号、温度节点等关键上下文，确保分块间的语义连续性 |
| 相似度阈值 | 0.75–0.85 | 匹配微生物检测、检疫记录的语义一致性，降低误召回概率 |
| 单次搜索上限 | 前10条 | 覆盖单批次生产的关联数据量，避免检索结果冗余 |
| maxToken | 8000 token | 适配批量溯源的上下文长度要求，符合FastGPT v4.17.0 标准配置 |
| defaultToken | 2000 token | 单条检索结果的展示长度，满足现场快速查看核心信息的需求 |

## 容易做错的三处
- 启动docker-compose容器后出现503报错，提示当前分组default下对于模型text-embedding-v3无可用渠道。原因是未正确配置向量模型的API渠道绑定，未将text-embedding-v3关联至default分组。
- 检索结果无法关联到对应生产批次，出现批次号字段为空的情况。原因是分块时未保留批次号、供应商编码等关联字段，导致向量索引无法匹配批次维度。
- 检索调试时找不到编辑按钮，无法直接调整索引参数。原因是FastGPT v4.17.0 版本中检索调试入口已迁移至知识库内容管理页的检索配置模块。

## 怎么确认配好了
- 启动docker-compose容器后，检查环境变量CHAT_API_KEY是否已正确写入配置文件，无空值或格式错误。
- 上传一份检疫证明文档进行检索测试，确认返回结果中包含批次号、检测时间等关联字段，且结果条数符合单次搜索上限设置。
- 查看向量模型的调用日志，确认text-embedding-v3模型的请求已成功路由至default分组，无503报错记录。
- 调整相似度阈值后，验证检索结果的语义匹配度符合业务预期，无过度召回或召回不足的情况。
