# 肉制品与屠宰加工的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
该品类数据覆盖屠宰场、熟肉与冷冻调理食品企业的日常生产文档，包括动物检疫证明、屠宰分割记录、配料腌制台账、热加工参数记录、冷链温度日志、微生物检验报告。数据来源包含动物检疫信息、供应商批次台账、生产追溯系统、温度采集终端、金属检测设备与实验室检验结果。数据按生产批次、每班频次更新，冷链温度需连续采集记录，核心字段包含批次号、检疫编号、温度值、检测指标等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类按批次与连续温控更新的数据特征，要求多轮对话需精准绑定单批次的全链路数据，避免跨批次混淆。文档包含多类专业字段，提示词需明确指定提取批次号、检疫编号等核心信息，防止对话上下文混入无关内容。连续温控的高频数据会占用大量上下文配额，需限制有效上下文范围，仅保留与当前批次相关的对话与数据。生熟隔离与生物风险的业务要求，需在提示词中加入场景限定，确保分析聚焦当前批次的原料或成品质量问题。

## 配置怎么定
本配置适用于FastGPT v4.17.0
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 前30条对话及关联批次数据 | 适配该品类按批次管理的生产数据，避免跨批次冗余信息干扰分析 |
| 上下文绑定标识 | 绑定`chatId` | 依托`chatId`精准关联单批次的检疫、温度、检测等全链路生产记录 |
| 提示词字段限定 | 固定提取批次号、检疫编号、温度值 | 针对该品类核心文档字段设计，确保对话聚焦有效质量分析信息 |
| 中间结果存储 | 通过`variables`传递结论 | 支持多轮不良分析，将上一轮结果作为下一轮对话的提示词输入 |
| 超时阈值 | 600秒 | 适配该品类多类生产台账的调取与分析耗时，避免中途中断 |
| 对话消息格式 | 按`messages`格式组织内容 | 符合FastGPT的对话解析规则，确保上下文正确传递 |

## 容易做错的三处
- 对话明细仅显示少量上下文，无法关联对应批次的生产数据。原因是未绑定`chatId`，导致对话上下文仅保留临时会话内容，未关联单批次的全链路生产与检测记录。
- 循环功能无法将上一轮结论作为下一轮提示词输入。原因是未通过`variables`存储中间分析结果，导致下一轮对话无法获取前置判断依据。
- 对话结果混入非目标批次的文档信息。原因是提示词未明确限定提取当前批次的字段，导致关联到其他批次的检疫或温度记录。

## 怎么确认配好了
- 测试单批次的质量追溯对话，查看对话明细中是否包含该批次的检疫证明、温度记录等关联数据，确认上下文绑定标识生效。
- 触发循环分析流程，查看`variables`中是否存储了上一轮的分析结论，确认中间结果可被下一轮对话调用。
- 输入包含非目标批次字段的测试内容，确认对话仅提取当前批次的核心信息，未混入无关数据。
- 模拟长时间分析场景，确认对话未出现超时报错，验证超时阈值设置合理。
