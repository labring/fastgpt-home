# 肉制品与屠宰加工的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
该品类的核心数据来源包括动物检疫信息、供应商批次、生产追溯记录、温度采集数据、金属检测结果与实验室检验报告。日常文档涵盖检疫证明、屠宰分割记录、配料腌制记录、热加工记录、冷链温度日志、微生物检验单据。数据按生产批次、班次更新，连续温控数据实时采集。字段包含批次编号、检疫合格标识、加工温度、检测阈值、冷链点位编号，单位多为摄氏度、千克、批次号等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类数据包含生物风险相关的检疫标识、实时温控等时序数据，且批次关联要求严格，因此模型接入需优先保障批次字段的精准匹配。实时温控数据更新频率高，需配置适配高频小批量数据的读取逻辑。多类型文档混合的场景下，需限制模型处理的单批次数据总量，避免上下文溢出。同时，检疫证明等合规性文档的字段固定性强，需适配结构化数据的解析逻辑，减少非结构化解析的误差。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配多批次的检疫、生产记录混合上下文，避免超出模型承载上限 |
| `maxTokens` | 2000–3000 token | 保障不良分析结果的详细程度，同时控制单次请求耗时 |
| `quoteMaxToken` | 1500 字符 | 限定引用的生产文档长度，匹配该品类单批次文档的平均篇幅 |
| `toolChoice` | auto | 自动选择是否调用检索工具，适配多源数据的关联分析需求 |
| `temperature` | 0.2–0.4 | 降低结果随机性，保障质量追溯结论的一致性 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或云端的模型调用路径，保障模型接入稳定性 |
| `AIPROXY_API_TOKEN` | 按授权配置 | 保障模型调用的权限安全，避免未授权访问 |

## 容易做错的三处
- 现象：上传检疫证明后，返回的追溯结果未关联对应批次的生产记录。原因：未配置批次编号的精准匹配规则，模型无法建立原料批次与生产信息的关联。
- 现象：调用部署的模型时，解析冷链温度日志报错。原因：未调整`maxContext`适配该品类的高频时序数据，导致请求超出模型上下文上限。
- 现象：配置自有知识库后无法生成追溯结果。原因：未开启关联检索的自动调用，或未配置`quoteMaxToken`适配该品类的文档长度。

## 怎么确认配好了
- 上传单批次的检疫证明与屠宰分割记录，核对模型返回的追溯结果是否包含对应批次的所有关联文档。
- 提交包含微生物超标关键词的查询，核对返回结果的分析结论是否符合该品类的合规逻辑。
- 查看模型调用日志，确认`maxContext`与`maxTokens`的配置未触发上下文溢出报错。
- 测试不同温度区间的查询，核对返回的温控数据是否与实际采集的日志匹配。
