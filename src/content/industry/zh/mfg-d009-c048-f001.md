# 设备点检与预防维修的质量问题追溯与不良分析：HTTP 接口与外部系统

## 这个品类的数据长什么样
本品类的数据来源于EAM/CMMS系统、设备传感采集终端、操作员点检记录、维修历史档案、备件库存清单及特种设备法定检验记录。日常文档包含设备台账、点检表、保养计划、维修工单、故障分析报告、备件清单与特种设备检验记录。数据更新频率覆盖每班点检、日/周/月保养计划更新、故障发生时的实时上报。字段包含设备编号、安装位置、点检参数（如温度、振动值）、维修时长、备件领用数量等，单位随点检项与设备类型变化。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据来源要求接口支持多格式数据的拉取与推送，适配EAM系统、传感终端等不同外部系统的协议格式。多样的更新频率需要接口配置灵活的触发机制，支持定时同步与事件触发两种模式。复杂的文档结构与差异化字段要求接口参数需精准映射设备相关专属字段，避免数据错位。非计划停机与批量质量问题的出错后果，要求接口具备高可靠性，需配置合理的超时与重试机制，保障数据传输的稳定性。特种设备检验记录的合规性要求，需接口字段传递符合行业通用的设备管理规范。

## 配置怎么定
以下配置适用于FastGPT v4.17.0版本：
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 接口超时设置 | 300–600 秒 | 适配设备点检数据的实时传输与批量同步场景，避免阻塞维修工单流程 |
| 请求头配置 | 携带`Authorization`参数，取值为固定 Bearer Token | 保障与EAM、传感系统等外部对接的身份合法性 |
| 变量映射配置 | 按`variables`映射设备编号、点检结果、维修时长字段 | 匹配本品类文档的专属字段结构，确保数据准确传递 |
| 响应数据处理 | 按`responseData`提取故障分析、备件库存数据 | 适配不良分析所需的关联数据提取需求 |
| SSL证书配置 | 启用有效SSL证书，或按实测标定禁用证书校验 | 满足公网部署的安全要求，适配不同部署环境 |
| 重试机制配置 | 失败后重试2–3次，间隔10–30秒 | 应对设备传感数据临时中断的场景，保障数据同步成功率 |

## 容易做错的三处
- 现象为POST请求返回404状态码，日志显示`POST /api/admin/initv4818 404 in 76ms`，原因是Nginx反向代理未正确转发FastGPT的后台接口路径，未匹配到对应路由规则。
- 现象为钉钉机器人部署时提示“消息接收地址校验失败”，原因是外部系统的接收地址未配置公网可访问的有效链路，或未正确开放对应端口。
- 现象为调用接口后返回的响应数据中缺少设备点检相关字段，原因是未正确配置`variables`参数映射设备台账的专属字段，导致外部系统无法识别对应数据标识。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的接口调试面板中，发送测试请求携带`Authorization`参数，验证返回状态码为200。
- 查看接口返回的`responseData`，确认包含设备编号、点检结果等预设字段。
- 触发定时同步任务，核对拉取的点检表数据与外部EAM系统内的记录一致。
- 模拟设备故障触发事件，验证接口能实时推送维修工单信息到外部系统。
