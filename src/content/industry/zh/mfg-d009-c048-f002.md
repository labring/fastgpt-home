# 设备点检与预防维修的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
本品类的数据来自制造企业设备部、车间维修班组的日常产出，涵盖设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录等文档。数据来源包括EAM/CMMS系统、设备传感数据、操作员手工点检记录、维修历史档案、备件库存台账及法定检验信息。更新节奏覆盖每班巡检提交、日周月保养计划更新、故障发生时的即时记录，部分传感数据为实时流式更新。文档字段包含设备编号、型号、安装日期、点检点位参数、故障现象、处理措施、备件型号等，部分参数带有℃、mm/s等单位标识。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类的数据特征对向量模型与索引环节带来多重约束。首先，多源异构的数据格式（结构化台账、自由文本故障记录、流式传感数据）要求分块策略适配不同内容长度与结构，避免破坏专业语义关联。其次，差异化的更新频率（实时传感、定时点检、偶发故障）需要配置灵活的索引更新规则，区分全量重建与增量同步的触发场景。第三，带有单位的设备参数字段要求向量建模时保留语义细节，避免因单位缺失导致的检索歧义。最后，偶发的故障记录样本量波动，需要平衡召回的精准度与覆盖范围，防止过度召回无关的点检记录。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 设备台账、维修工单等文档多为结构化段落，该长度可保留完整的故障关联逻辑与设备参数信息 |
| 重叠长度 | 100–150 字符 | 点检表、保养计划的连续点位描述需上下文衔接，避免分块破坏操作逻辑 |
| 相似度阈值 | 0.75–0.85 | 按实测标定，适配设备故障描述、备件型号等专业语义的相似度区分 |
| 单次搜索上限 | 前 10 条 | 维修决策所需的关联信息有限，过多结果会增加上下文负担 |
| maxToken | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| defaultToken | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 现象为重复查询相同的设备故障描述时，每次都触发完整向量检索，响应耗时较长。原因是未启用查询缓存机制，未配置重复查询的缓存规则。
- 现象为执行集合添加数据操作后，无法通过训练订单关联生成设备相关的索引，界面提示“训练订单未完成”。原因是混淆了训练订单与集合添加数据的功能边界，训练订单用于批量结构化数据的索引构建，集合添加仅支持单条非批量文本导入。
- 现象为上传设备现场图片并向量化后，检索时无法关联返回对应的点检文本记录。原因是未配置多模态向量的元数据绑定，仅对图片单独生成向量，未建立图片与设备文档的关联关系。

## 怎么确认配好了
- 查看向量数据库的索引管理界面，确认已生成对应设备台账、维修工单等数据源的索引条目。
- 发起一条标准设备故障描述的查询，核对返回的关联文档条数与单次搜索上限的配置一致。
- 重复发起相同的设备点检查询，对比两次查询的响应时间，确认后续查询耗时显著降低。
- 检查嵌入模型的参数配置页面，确认maxToken与defaultToken的取值符合当前FastGPT版本的限制。
