# 设备点检与预防维修的质量问题追溯与不良分析：工具调用与插件

## 这个品类的数据长什么样
该品类的业务数据来源于EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史档案、备件库存清单及特种设备法定检验记录。数据更新节奏覆盖每班点检提交、日/周/月保养计划更新、故障发生时即时上报。日常文档包含设备台账、点检表、保养计划、维修工单、故障分析报告、备件清单、特种设备检验记录，其中设备台账包含设备编号、型号、安装日期字段，点检表包含点检时间、点检项、异常标记字段，维修工单包含工单编号、故障描述、处理措施字段，传感数据包含温度、振动加速度等实时监测数值。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源异构的数据格式要求工具调用需适配结构化数据库查询、半结构化文档读取及时序数据解析三类场景；高频更新的故障数据要求工具调用具备低延迟响应能力，避免延误维修调度；以设备为核心的关联逻辑要求工具调用必须绑定设备编号、工单ID等精准字段，避免泛化搜索返回无关结果；数据准确性直接影响非计划停机、批量质量问题等严重后果，要求工具调用结果需经过二次校验，确保与设备台账、库存记录一致。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `toolChoice` | 设置为`functionCall` | 需精准调用指定工具处理设备相关的结构化数据，避免泛化调用 |
| 插件数据绑定规则 | 绑定设备编号、工单ID字段 | 所有业务数据均以设备为核心关联，需精准匹配对应记录 |
| 超时阈值 | 30–60 秒 | 设备故障响应需快速，过长超时会延误维修调度 |
| 结果校验开关 | 开启 | 数据准确性直接影响维修决策，需验证返回结果与设备台账一致 |
| 单次调用数据条数 | 前 8–12 条 | 单条点检、维修记录数据量较小，过多会超出上下文承载上限 |
| 上下文承载上限 | 8000–10000 token | 适配设备数据的单批次查询量，避免超出模型上下文限制 |

## 容易做错的三处
- 现象：工具调用结果仅在重新进入会话时显示，首次调用无返回结果。原因：未配置会话上下文自动保存工具调用输出的规则，导致结果未被缓存。
- 现象：无法找到文件加工类插件。原因：使用的FastGPT v4.17.0版本未集成该插件，或未在插件管理页面开启对应权限。
- 现象：代码运行插件处理JSON数据时无法提取指定元素。原因：未正确配置数据提取的匹配字段，或未按设备数据的JSON结构调整提取规则。

## 怎么确认配好了
- 手动触发工具调用，查询指定设备的点检记录，核对返回结果与EAM系统导出的记录一致。
- 在插件管理页面确认已开启所需工具的权限，查看插件列表中是否包含目标工具。
- 提交包含设备编号的测试问题，验证工具调用结果是否正确绑定对应设备的工单、备件信息。
- 模拟设备故障触发工具调用，检查返回结果的超时时间是否符合预设的30–60秒阈值。
