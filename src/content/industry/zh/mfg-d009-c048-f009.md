# 设备点检与预防维修的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类数据涵盖设备台账、点检表、保养计划、维修工单、故障分析、备件清单、特种设备检验记录，来源包括EAM/CMMS系统、设备传感数据、操作员点检记录、维修历史库、备件库存系统及法定检验信息。数据更新节奏分为实时传感采集、每班点检提交、日/周/月保养计划更新，以及故障发生时即时生成的工单与分析文档。数据字段包含设备唯一标识、点检项参数、故障类型、备件编码、检验有效期等，格式随设备类型与车间管理规则调整。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据的分散来源、多更新节奏与字段差异，对模型接入与配置带来多重约束。多源异构的数据格式需配置适配不同结构的解析规则，确保设备传感数据、点检记录、维修工单均可被正确读取。不同更新频率的数据源需区分触发同步机制，实时传感数据需配置高频刷新的上下文加载规则，月度保养计划则可按固定周期同步。数据中包含需关联校验的特种设备检验记录，需限定模型输入的数据源范围，避免无关信息干扰故障分析。维修工单与故障分析的关联依赖字段匹配，需明确关联字段的优先级与匹配逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | 本品类数据包含多份点检记录、维修工单与传感数据，需容纳足够的历史上下文以完成跨文档的质量追溯，适配FastGPT v4.17.0版本的上下文加载规则 |
| `maxTokens` | `2000–3000 token` | 故障分析与追溯结果需包含故障原因、处理建议等内容，无需过长输出，避免占用过多推理资源 |
| `temperature` | `0.2–0.4` | 质量追溯与不良分析需结果精准，不宜过度随机，确保分析结论的一致性 |
| `AIPROXY_API_ENDPOINT` | 对应云平台的专属接入地址 | 适配私有化部署的网络环境与模型调用路径，确保请求可正确路由至目标模型 |
| `AIPROXY_API_TOKEN` | 从第三方平台获取的有效令牌字符串 | 用于模型调用的身份验证，确保访问权限合法有效 |
| `toolChoice` | `auto` | 根据任务自动选择是否调用知识库或工具，适配多源数据检索与关联分析需求 |

## 容易做错的三处
- 现象：在模型提供商页面添加已测试通过的模型后，测试时报错404。原因：未填写与第三方平台一致的模型ID，或代理API端点配置错误。
- 现象：接入指定大模型后，输出结果无思考过程。原因：`temperature`参数设置过高，或未在模型配置中启用关联分析的输出规则。
- 现象：私有化部署后，模型推理效率与平台版存在明显差异。原因：`maxContext`参数取值超出本地服务器可承载的范围，导致上下文加载耗时增加。

## 怎么确认配好了
- 执行模型提供商页面的测试连接功能，确认返回结果无报错。
- 导入单份设备点检数据与关联的维修工单，触发模型调用，核对输出结果包含相关的故障分析内容。
- 调整`maxContext`参数取值，观察上下文加载的耗时变化，确认取值适配当前部署环境的资源配置。
- 检查`AIPROXY_API_TOKEN`是否与第三方平台生成的令牌一致，确保身份验证配置正确。
