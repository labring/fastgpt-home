# 过程质量与成品放行的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自制造企业的MES系统、在线检测设备、实验室系统、工艺参数台账、客户质量标准及历史缺陷库。日常产出的文档包括控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单及质量月报。数据更新频率随生产批次、班次持续采集，单条数据包含检验项参数、缺陷类型、判定结果、关联工艺编号、批次号等字段，部分检测数据带物理单位如毫米、帕斯卡。

## 这些特征在「向量模型与索引」这一环带来什么约束
本品类数据分散于多系统，包含结构化检验参数与非标准化文本，要求索引支持混合数据类型关联存储。数据随生产批次、班次高频更新，需要索引支持增量同步以避免全量重建的性能损耗。文档包含工业检验专业术语与批次关联标识，向量模型需适配细分领域语义以保证检索精度。单批次数据量随生产规模动态波动，索引需支持弹性扩容适配不同产能场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配本品类文档的单段检验项或缺陷描述长度，避免语义割裂 |
| 重叠长度 | 100–150 字符 | 覆盖跨分块的批次号、工艺编号等关联信息，保证检索连贯性 |
| 相似度阈值 | 0.72–0.85 | 匹配工业缺陷描述的语义相似度区间，按实测标定 |
| `defaultToken` | 4096 | 适配本品类批量入库的文档总token上限，保证单批次索引请求的完整性 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |
| 单次搜索上限 | 前 10 条 | 覆盖典型不良分析所需的历史缺陷样本量，避免冗余数据干扰 |

## 容易做错的三处
- 现象：批量添加索引时返回参数错误，状态码400。原因：未按批次关联字段组织入库请求，将独立文档与批次数据混合提交。
- 现象：检索结果仅返回单条匹配数据，条数远低于预期。原因：未配置合理的分块重叠长度，导致批次关联信息被分割在不同分块中无法被完整检索。
- 现象：无法通过外部管理系统直接修改向量库数据。原因：未开启FastGPT v4.17.0的外部向量库集成权限，默认仅支持平台原生管理。

## 怎么确认配好了
- 提交单批次检验记录的入库请求，检查索引任务状态为成功，查看入库文档的分块信息与预设分块长度匹配。
- 输入不良缺陷描述进行检索，核对返回结果包含对应批次的关联数据，调整相似度阈值至符合业务判定标准。
- 尝试通过外部管理系统发起向量库的增删操作，验证权限配置是否生效，确认操作同步至FastGPT索引库。
- 模拟高频批量入库场景，查看系统资源占用情况，确认索引扩容配置适配当前数据更新频率。
