# 过程质量与成品放行的质量问题追溯与不良分析：数据库与运维

## 这个品类的数据长什么样
本品类数据涵盖控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审、放行单等文档，数据来源包括生产MES系统、在线检测设备、实验室检测系统、工艺参数库、客户质量标准及历史缺陷库。数据更新按生产批次、每班频次持续采集，字段包含检验项编号、公差范围、批次号、检验结果、统计量数值、合格判定标识等，附带mm、kg、小时等对应单位。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据接入要求数据库支持混合结构化与非结构化存储，适配MES系统、在线检测设备、实验室系统等不同格式的数据写入。按生产批次、每班的高频更新节奏，要求数据库连接池配置足够的并发连接数，避免批量写入时出现阻塞。多类型文档的元数据管理，需要明确的字段映射规则，确保不同来源数据的单位、合格判定标识等统一。历史缺陷库的长期留存需求，要求数据库支持热数据与冷归档数据分区，平衡存储成本与查询效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://fastgpt:xxxx@db-host:27017/quality?authSource=admin` | 适配FastGPT v4.17.0版本的多源结构化与非结构化质量数据存储，兼容控制计划、成品检验报告等文档的元数据与内容存储 |
| `DB_MAX_LINK` | `30–60 个` | 应对每批、每班的高频数据写入请求，避免连接池耗尽导致采集中断 |
| `REDIS_URL` | `redis://:xxxx@redis-host:6379/1` | 缓存高频访问的SPC报表、工艺参数数据，降低主数据库的查询压力 |
| 数据库批量写入阈值 | `100–200 条/次` | 匹配生产批次的批量数据上传节奏，平衡写入效率与资源占用 |
| 数据归档周期 | `按单批次生产周期标定` | 区分热数据与冷归档数据，优化历史缺陷库的查询性能 |

## 容易做错的三处
- 现象：启动docker容器后报错提示无法连接MongoDB，日志显示`Connection refused`。原因：未正确修改`MONGODB_URI`配置项，或容器内数据库连接参数与宿主机配置不匹配。
- 现象：通过MongoDB Compass连接本地FastGPT MongoDB实例失败，无法查看质量数据集合。原因：未开放MongoDB默认端口27017的防火墙权限，或认证用户名密码配置错误。
- 现象：批量导入巡检记录时出现部分数据丢失，查询结果条数不足。原因：未设置合理的`DB_MAX_LINK`参数值，连接数不足导致部分写入请求被丢弃。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`、`REDIS_URL`配置项可正常建立连接，无超时或认证失败提示。
- 导入单批次模拟巡检记录数据，检查数据库写入请求的响应时长，确认连接池未出现耗尽情况。
- 查看Redis缓存监控面板，确认高频查询的SPC报表、工艺参数数据已被正常缓存。
- 对比导入的文档元数据与原始数据的字段、单位，确认映射规则已正确生效。
