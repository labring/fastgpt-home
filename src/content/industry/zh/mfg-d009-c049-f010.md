# 过程质量与成品放行的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
本品类的数据来源包括MES系统、在线检测设备、实验室检测结果、工艺参数台账、客户质量标准、历史缺陷库。数据更新节奏为每生产批次、每班更新，部分实时采集的工艺与检测数据持续同步。日常文档包含控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审记录、放行单、质量月报，数据字段包含批次标识、检验项名称、缺陷类型、工艺参数值、检验结果、放行状态等，对应单位随检验项与工艺要求确定。

## 这些特征在「知识库检索与召回」这一环带来什么约束
本品类的数据特征对检索召回带来多重约束。多源分散且高频更新的数据，要求支持增量同步与权限隔离机制，确保检索范围覆盖最新的批次与缺陷数据。多样的文档格式，从结构化检验报表到非标准化评审记录，需要适配不同的文本拆分规则，避免拆分后丢失关键关联信息。字段随检验项动态调整，检索需精准匹配批次标识、缺陷类型等核心字段，过滤无关结果。同时，检索结果需关联成品放行的权限范围，防止越权访问未授权的质量文档。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配过程质量与成品放行场景的检索需求。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | 过滤低相关的质量文档，同时保留足够的缺陷案例与检验标准内容，适配本品类的语义匹配需求 |
| `limit` | 前10条 | 控制检索结果的上下文长度，避免超出模型输入限制，同时覆盖多批次的缺陷记录与检验项 |
| `searchMode` | `embedding` | 适配本品类核心的语义匹配需求，精准匹配缺陷类型、工艺参数等关联的质量数据 |
| `usingReRank` | 开启 | 修正多源数据的语义相似度偏差，提升结果与当前追溯问题的匹配精度 |
| `datasetSearchUsingExtensionQuery` | 开启 | 基于用户的追溯问题自动补充批次、缺陷类型等前置过滤条件，缩小检索范围 |
| `collectionIds` | 按业务部门与文档类型分组配置 | 精准限定检索范围，仅包含过程质量与成品放行相关的检验记录、评审记录、放行单等文档 |

## 容易做错的三处
- 现象：检索结果包含未授权的放行单文档，返回无有效内容的检验记录。原因：未配置`collectionIds`限定检索的数据集分组，未过滤无有效检验结果的文档。
- 现象：回答超出知识库内容，引入未收录的工艺标准或客户要求。原因：未严格限定检索范围，或未启用仅基于知识库内容回答的配置。
- 现象：检索结果条数远低于预期，无法覆盖同批次的历史缺陷数据。原因：`similarity`阈值设置过高，过滤了部分语义相关但相似度略低的历史缺陷记录。

## 怎么确认配好了
- 上传一批测试用的控制计划与同批次的缺陷记录，发起包含指定批次关键词的检索，核对返回结果仅包含该批次的相关文档。
- 发起无匹配内容的检索请求，确认返回预设的自定义回答，未引入知识库以外的信息。
- 查看数据集分组配置，确认检索范围仅包含过程质量与成品放行相关的文档集合，未包含无关的来料检验文档。
- 检查检索日志，确认`usingReRank`与`datasetSearchUsingExtensionQuery`已生效，检索结果按匹配度从高到低排序。
