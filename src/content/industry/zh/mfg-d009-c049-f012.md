# 过程质量与成品放行的质量问题追溯与不良分析：部署与升级

## 这个品类的数据长什么样
该品类的数据来自制造企业的MES系统、在线检测设备、实验室系统、工艺参数库、客户标准及历史缺陷库。日常关联文档包括控制计划、巡检记录、SPC报表、成品检验报告、不合格品评审单、放行单与质量月报。数据按生产批次、班次更新，或由检测设备持续采集，包含工艺参数、检验结果、缺陷类型、放行状态等字段，无统一固定单位，具体单位随检测项与文档类型变化。

## 这些特征在「部署与升级」这一环带来什么约束
该品类数据来源分散且更新频率高，部署时需适配多系统对接的存储配置，确保并发读写稳定。多样的文档结构要求系统支持多格式数据解析，需配置对应存储路径以管理检验报告等文件。涉及生产放行的权限管控，需明确系统权限配置逻辑。批量数据导入与持续采集的场景，要求数据库连接参数匹配高并发需求，避免因资源不足导致数据同步延迟或不合格品放行审核超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–50` | 适配FastGPT v4.17.0版本的连接池逻辑，支撑每批生产的批量数据导入与持续采集的并发需求，避免连接池耗尽 |
| `MONGODB_URI` | `mongodb://[用户名]:[密码]@[主机]:[端口]/fastgpt?authSource=admin` | 存储历史缺陷库、SPC报表等非结构化质量数据，支持灵活的多条件查询 |
| `PG_URL` | `postgresql://[用户名]:[密码]@[主机]:[端口]/fastgpt` | 存储控制计划、巡检记录等结构化业务数据，保障事务性操作的稳定性 |
| `STORAGE_S3_ENDPOINT` | 按企业自建对象存储地址填写 | 管理上传的成品检验报告、不合格品评审单等文件，适配多场景的存储需求 |
| `ROOT_KEY` | 随机生成的32位以上字符串 | 管控系统最高权限，仅用于质量管理人员的后台配置，保障放行审核权限的安全性 |
| `REDIS_URL` | `redis://[密码]@[主机]:[端口]/0` | 缓存高频查询的工艺标准、客户要求，降低数据库的查询负载 |

## 容易做错的三处
- 现象：批量导入巡检记录时系统回答延迟超过600秒，界面显示超时错误。原因：未调整`DB_MAX_LINK`参数，数据库连接池不足以支撑批量数据的并发读写。
- 现象：上传成品检验报告后系统报错，提示文件存储失败。原因：未正确配置`STORAGE_S3_ENDPOINT`，对象存储地址或权限设置错误，导致文件无法写入。
- 现象：调用质量标准相关问答时返回结果为空。原因：未配置`REDIS_URL`或参数错误，高频查询的工艺标准未被缓存，数据库查询超时导致结果无法返回。

## 怎么确认配好了
- 执行批量导入测试数据的操作，查看数据库连接日志，确认连接数未超过配置的`DB_MAX_LINK`上限。
- 上传一份成品检验报告，检查对象存储控制台是否生成对应文件，确认`STORAGE_S3_ENDPOINT`配置生效。
- 发起高频查询工艺标准的测试请求，查看缓存监控指标，确认`REDIS_URL`配置的缓存服务正常响应。
- 登录系统后台，使用`ROOT_KEY`验证最高权限配置是否仅开放给指定质量管理人员。
