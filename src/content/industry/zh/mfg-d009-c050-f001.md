# 通用机械设备装配的质量问题追溯与不良分析：HTTP 接口与外部系统

## 这个品类的数据长什么样
通用机械设备装配的质量追溯数据，通常来自PLM、ERP、零件检验系统、装配工具采集终端、试验台、MES及客户技术协议。数据按单台设备、每订单更新，包含装配工艺卡、BOM清单、扭矩记录、间隙调整记录、试运行报告、出厂检验单、装箱清单等文档。数据字段包含扭矩值、间隙值、同轴度公差等带单位的实测参数，以及设备序列号、订单编号等标识字段。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
按单台设备、每订单更新的数据特征，要求HTTP接口支持以设备序列号或订单编号作为精准查询参数，拉取单台设备的全链路装配数据。多来源的数据对接需求，要求接口兼容不同系统的字段格式，需配置参数映射规则实现字段对齐。带单位的实测数据字段，要求接口返回时保留明确的单位标识，避免追溯时的歧义。现场装配的实时性需求，要求接口响应时长需适配现场调试的等待节奏，不宜过长。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {外部系统访问密钥}` | 符合标准的接口身份验证要求，保障数据访问权限 |
| `variables` | `{"device_sn": "{{query.device_sn}}", "order_id": "{{query.order_id}}"}` | 适配按设备序列号、订单号查询的业务场景，支持从用户输入提取参数 |
| `responseData` | `保留BOM层级、扭矩值、间隙调整记录、检验结果` | 仅返回质量追溯所需的核心字段，优化数据传输效率 |
| 请求超时时间 | `30-60秒` | 适配装配现场的实时调试节奏，避免超时导致的追溯中断 |
| 重试次数 | `2次` | 应对临时网络波动，降低单次请求失败的影响 |
| 请求数据大小限制 | `1000 MB` | 适配装配数据的传输需求，避免因数据过大导致传输失败 |

## 容易做错的三处
- 现象：调用部署在阿里云的后端接口时返回403未授权错误，或提示无法解析花生壳生成的域名。原因：未正确配置`Authorization`参数，或域名未在外部系统的访问白名单中配置，导致访问被拦截。
- 现象：HTTP模块发起请求后返回的`responseData`字段为空。原因：未正确映射请求参数，或接口返回的字段名称与配置的提取规则不匹配，导致无法提取有效数据。
- 现象：发起接口请求后出现超时错误。原因：请求超时时间设置过短，或后端接口响应速度较慢，未适配装配现场的业务节奏。

## 怎么确认配好了
- 在FastGPT的HTTP模块配置页面，填入测试用的设备序列号和订单号，发起模拟请求，查看返回的`responseData`是否包含预期的装配数据字段。
- 检查请求头中是否正确携带`Authorization`参数，确认身份验证配置无误，可通过接口调试工具验证请求的合法性。
- 模拟网络波动场景，断开网络后恢复，查看接口是否自动重试，确认重试策略配置生效。
- 调整请求超时时间为不同取值，发起请求并记录响应时长，确认超时设置适配实际业务场景。
