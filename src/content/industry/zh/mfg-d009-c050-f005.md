# 通用机械设备装配的质量问题追溯与不良分析：工具调用与插件

## 这个品类的数据长什么样
通用机械设备装配场景的数据通常来自PLM/ERP、零件检验系统、装配工具采集终端、试验台、MES与客户技术协议。日常文档包含装配工艺卡、多层级BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单与装箱清单，字段包含工序号、操作人、实测扭矩（单位N·m）、间隙值（单位mm）、同轴度公差（单位μm）等。数据按单台设备、单订单更新，每完成一台装配或一笔订单交付即生成新的关联数据集。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于数据按单台设备、单订单更新，工具调用需绑定对应实例的上下文，避免跨订单数据混淆。该品类多品种按订单装配，依赖部件配合与调试，不同于单一零件加工的尺寸合格判定，因此工具调用需支持多层级BOM关联检索与多源工艺数据整合。带单位的工艺参数需工具调用准确匹配字段单位，否则会导致分析结果偏差。同时，装配试验的闭环故障分析需关联多系统数据，工具调用需支持跨数据源拉取。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | 适配不同质量追溯场景下的工具或知识库检索自动选择 |
| `functionCall` | `enabled` | 支持调用BOM查询、扭矩数据提取等装配场景专用工具 |
| 知识库绑定规则 | 按订单号/设备序列号变量匹配 | 数据按单台设备、单订单更新，需绑定对应实例上下文 |
| 单次工具调用返回条数 | 前 8 条 | 装配类文档层级多，控制返回量避免上下文溢出 |
| 工具调用超时时间 | 600 秒 | 装配试验闭环分析需检索多类日志数据，耗时较长 |
| 上下文窗口限制 | 8000 token | 适配装配场景多文档组合后的上下文长度，FastGPT v4.17.0默认上限可匹配该需求 |
| 变量映射校验 | 按实测标定 | 不同设备的字段命名、单位存在差异，需匹配业务实际 |

## 容易做错的三处
- 现象：工具调用返回结果与当前订单无关，或检索到冗余的跨订单数据。原因：未按订单号/设备序列号绑定对应知识库，未正确配置变量匹配规则。
- 现象：高级编排内的工具调用节点执行失败，无法触发外部工具。原因：未将`functionCall`配置为`enabled`，未启用工具调用功能。
- 现象：无法查看每次AI调用的request body，或调试日志为空。原因：未开启FastGPT的调试日志开关，或未在系统设置中启用请求日志记录。

## 怎么确认配好了
- 输入指定订单号与设备序列号，触发质量追溯查询，核对返回的知识库结果仅包含该订单的装配文档。
- 调用BOM查询工具，输入指定物料编码，核对返回的字段包含装配工艺要求的扭矩、间隙等参数。
- 触发工具调用节点，查看系统执行日志，确认`toolChoice`与`functionCall`的配置已生效。
- 调用本地模型插件，输入标准化测试prompt，核对返回结果符合预期且无超时报错。
