# 通用机械设备装配的质量问题追溯与不良分析：模型接入与配置

以下配置基于FastGPT v4.17.0版本制定。

## 这个品类的数据长什么样
通用机械设备装配品类的日常数据涵盖装配工艺卡、多层级BOM、扭矩记录、间隙调整记录、试运行报告、出厂检验单等。数据主要来自PLM/ERP系统、零件检验数据库、装配工具采集终端、试验台、MES系统及客户技术协议。数据更新以单台设备或单订单为节奏，每个装配批次对应专属的装配参数、检验记录与交付文档，字段包含物料编码、扭矩值（单位N·m）、间隙值（单位mm）、试验负载参数等。该品类通常为多品种按订单装配，最终性能依赖部件配合与现场调试，与单一零件加工品类的数据特征存在明显差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的多层级BOM与分散的装配检验数据，要求模型接入时需支持跨多源数据的关联召回，避免仅召回单条孤立记录。单台设备专属的装配参数与检验记录，要求配置需支持按订单维度隔离数据上下文，防止不同批次的装配数据混淆。高频更新的实时装配数据，要求模型调用的上下文窗口需适配单批次数据的体量，同时需保障调用效率以匹配现场分析的实时性需求。作为多品种按订单装配的品类，其数据的个性化特征要求配置需支持灵活的数据源绑定逻辑，适配不同订单的专属装配文档。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单台设备多层BOM、装配记录的总字符体量，覆盖完整装配链路的上下文信息 |
| `maxTokens` | 4000 token | 限制单轮不良分析的输出长度，避免生成冗余内容影响故障排查效率 |
| `quoteMaxToken` | 1500–2000 token | 限定召回的装配文档片段总长度，确保仅保留与当前质量问题强相关的记录 |
| `temperature` | 0.2–0.4 | 降低生成结果的随机性，保障质量追溯结论的严谨性，适配工程场景的确定性要求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写实际接口地址 | 对接本地或云端的大模型服务，保障数据调用的连通性 |
| `AIPROXY_API_TOKEN` | 与部署模型的访问密钥一致 | 验证模型调用权限，防止未授权访问干扰分析流程 |

## 容易做错的三处
- 现象：调用本地部署的大模型时返回连接超时或权限错误，无法正常获取装配相关数据。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，或本地模型的访问权限未开放至FastGPT服务。
- 现象：大模型生成的结果中未包含指定装配文档的URL链接，无法直接跳转查看原始记录。原因：未配置模型的文档引用格式，或`quoteMaxToken`设置过小，导致文档元信息被截断。
- 现象：配置了知识库模型后仍提示未配置，或无法召回BOM与装配记录。原因：未正确关联数据源与知识库的绑定关系，或`maxContext`未适配BOM的层级体量导致召回失败。

## 怎么确认配好了
- 手动触发一次针对特定订单的质量追溯任务，查看返回结果中是否包含该订单对应的BOM、扭矩记录等核心装配数据。
- 检查FastGPT的模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置未出现格式错误或字符遗漏。
- 调整`temperature`参数后对比两次分析结果，确认生成内容的随机性符合工程场景的严谨性要求。
- 验证多订单数据的隔离效果，确认不同批次的装配数据不会在同一次分析中被混淆调用。
