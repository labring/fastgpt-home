# 通用机械设备装配的质量问题追溯与不良分析：部署与升级

## 这个品类的数据长什么样
该品类的日常文档包含装配工艺卡、BOM清单、扭矩记录、间隙调整记录、试运行报告、出厂检验单与装箱清单。数据主要来自PLM/ERP系统、零件检验数据、装配工具采集记录、试验台数据、MES系统及客户技术协议。数据更新节奏为每台设备或每订单一次，字段包含部件编号、扭矩值、间隙参数、检验结果等，单位多为牛米、毫米、帕斯卡等物理量。

## 这些特征在「部署与升级」这一环带来什么约束
由于该品类数据按单或按台更新且关联多层BOM结构，部署时需预留多源异构数据的动态接入接口，适配PLM、MES等不同系统的数据格式。装配环节的扭矩、间隙等实时采集数据时效性要求较高，部署需配置低延迟的数据同步链路。日常文档包含多类型结构化与非结构化内容，升级知识库时需适配装配工艺卡、出厂检验单等不同格式的解析规则。多品种按订单装配的特性，要求部署的系统支持按订单维度隔离数据，避免不同批次的装配数据混淆。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30` | 适配每订单多份装配数据的并发查询需求，避免数据库连接耗尽 |
| `MONGODB_URI` | 指向存储装配BOM、检验记录的专属数据库实例 | 隔离设备装配业务数据与其他业务数据，保障查询效率 |
| `REDIS_URL` | 配置为本地缓存集群地址 | 缓存高频查询的装配工艺卡、扭矩阈值数据，降低数据库负载 |
| `STORAGE_S3_ENDPOINT` | 指向企业内部对象存储服务地址 | 存储装配过程中的试验台录像、扫描件等非结构化文档 |
| `ROOT_KEY` | 按企业权限管理规则生成专属密钥 | 管控系统后台的最高权限访问，避免未授权操作 |
| `PG_URL` | 指向存储工单、客户技术协议的关系型数据库 | 适配结构化工单数据的事务性查询需求 |

## 容易做错的三处
- 现象：docker部署的FastGPT，模型后台收到响应日志，但工作流对话显示失败。原因：未配置`FILE_TOKEN_KEY`或密钥不匹配，导致工作流无法传递模型响应的上下文数据。
- 现象：部署16B模型后，回答等待时间超过3分钟。原因：未调整`DB_MAX_LINK`配置，数据库并发连接不足导致数据查询延迟，拉长模型响应周期。
- 现象：从v4.9升级到v4.12.2后，原有装配工单数据丢失。原因：仅更新docker-compose文件后未挂载持久化存储卷，数据库数据未随容器保留。

## 怎么确认配好了
- 执行多源数据接入测试，验证PLM、MES系统的BOM、扭矩数据可正常同步至系统，核对数据字段与业务文档匹配。
- 提交模拟装配工单，触发质量追溯查询，确认系统可返回对应订单的全部装配记录与检验报告。
- 发起模型推理测试，验证响应符合业务场景要求，调整配置直至满足预期。
- 执行版本升级验证，确认升级过程中业务数据未丢失，服务可正常启动。
