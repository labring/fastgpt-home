# 金属切削加工的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
该品类数据来自产品图纸与三维模型、CAPP/CAM系统、机床采集终端、刀具管理系统、MES系统及量检具数据。日常生成工艺路线、工序卡、刀具清单、数控程序、首件检验记录、巡检表、量具校准记录等文档。数据更新随每工单、每件工件加工，或抽检、刀具更换时触发。数据字段包含工序编号、刀具型号、尺寸偏差值、表面粗糙度参数、机床运行参数等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据的多源分散、高频更新及多样文档类型，对向量模型与索引环节形成多重约束。多源异构数据需模型适配结构化参数与非结构化文本的混合编码，确保工序卡、数控程序、机床采集数据的向量空间一致性。高频更新场景要求索引支持增量同步，避免全量重建带来的性能损耗。不同工序的关联数据需保留顺序特征，同时过滤重复的巡检记录与校准数据，确保追溯链路的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 分块长度 | 800–1200 字符 | 适配工序卡、数控程序的文本长度，避免单块信息断裂 |
| 重叠长度 | 100–150 字符 | 保留工序间的关联上下文，防止跨块语义丢失 |
| 相似度阈值 | 0.75–0.85 | 过滤重复的巡检记录与校准数据，匹配金属切削参数的精度要求 |
| 单次搜索上限 | 前 10 条 | 适配单工单的工序数量，控制召回结果的冗余度 |
| `defaultToken` | 2000–3000 token | 适配数控程序的长文本编码需求，确保完整提取加工参数 |
| `maxToken` | 按所选嵌入模型/服务支持的最大输入 token 数设置 | `maxToken` 表示所选嵌入模型/服务支持的最大输入 token 数；请按模型或服务配置核对，参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不是检索/LLM 上下文，也不是 FastGPT 全局固定上限。 |

## 容易做错的三处
- 现象：调用向量模型时返回401状态码，提示认证失败。原因：未正确配置向量模型的API密钥，或密钥权限未覆盖向量编码请求。
- 现象：知识库中重复的工序记录未被过滤，召回结果出现大量冗余条目。原因：未开启索引去重配置，或去重阈值设置超出合理区间，无法匹配同工序的重复巡检数据。
- 现象：自定义切分的文档块顺序与原文档不一致，无法恢复加工工序的关联关系。原因：未保留分块重叠长度，或索引合并时未按原文档顺序存储向量数据。

## 怎么确认配好了
- 导入单份工序卡文档，检查向量编码后的分块数量与预期一致，无过度拆分或合并的情况。
- 提交包含刀具磨损参数的查询，确认召回结果包含同工序的关联记录，且顺序符合加工流程。
- 模拟刀具更换后的高频数据更新，检查索引是否能自动同步新增记录，无全量重建提示。
- 查看FastGPT v4.17.0的系统日志，确认向量模型调用无异常报错。
