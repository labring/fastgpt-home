# 金属切削加工的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类数据涵盖产品图纸与三维模型、CAPP/CAM文件、机床采集的运行日志、刀具管理系统的刀具清单与磨损记录、MES系统的工序数据，以及量检具校准记录与巡检表单。数据按工单、单件工件、抽检批次或刀具更换节点更新，包含工艺路线、工序卡、数控程序、首件检验结果等结构化与非结构化内容，字段包含尺寸偏差、刀具磨损量、工序耗时等加工专用参数。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据来源覆盖机床采集、刀具管理系统、MES系统与量检具记录，包含结构化参数与非结构化文档，且按工单、单件或刀具更换节点高频更新。单次加工任务关联的工序、刀具、检验数据量较大，模型接入配置需预留足够的上下文承载空间，避免丢失关键关联信息。同时质量追溯需关联多源历史数据，配置需适配多格式数据的混合处理逻辑，确保模型能准确匹配不良现象与对应加工环节的参数。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本制定。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 适配单工单多源数据的上下文承载需求，避免截断关键关联信息 |
| `maxTokens` | 4000 token | 控制单轮响应长度，适配质量分析报告的输出规范 |
| `quoteMaxToken` | 1500 token | 限定引用源数据的长度，确保引用内容聚焦于不良分析相关的加工参数 |
| `temperature` | 0.2–0.4 | 降低随机输出，保证质量追溯结论的一致性 |
| `toolChoice` | auto | 自动触发工具调用，适配多源数据的关联查询需求 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 匹配本地或第三方模型的接入地址 |
| `AIPROXY_API_TOKEN` | 按平台生成的密钥填写 | 完成模型接入的身份验证 |

## 容易做错的三处
- 现象：本地模型接入时提示端口占用，或模型无法正常加载。原因：未正确配置`AIPROXY_API_ENDPOINT`指向正确的本地模型服务端口，或端口被其他进程占用未释放。
- 现象：选择指定模型版本时提示无可用渠道，或模型列表中未显示目标模型。原因：未在分组配置中添加对应模型的渠道信息，或模型名称与部署版本不匹配。
- 现象：模型输出的追溯结论缺失关键加工参数，或上下文被截断。原因：`maxContext`取值过小，导致多源关联数据被截断，无法覆盖完整的加工环节信息。

## 怎么确认配好了
- 检查模型接入地址与密钥的填写内容，确认与本地或第三方模型的部署信息一致。
- 导入单份典型加工工单的关联数据，测试模型能否完整加载并关联多源文档内容。
- 设置测试用的不良分析查询，验证模型输出的结论是否覆盖对应加工环节的参数。
- 查看系统日志，确认无模型调用失败、上下文截断或参数校验错误的提示。
