# 钢材轧制与精整的质量问题追溯与不良分析：工作流编排

## 这个品类的数据长什么样
这个品类的数据来源于板坯或钢坯批次、加热炉、轧机自动控制系统、在线测厚测宽设备、表面检测装置与MES系统。数据更新节奏为每卷或每支钢材实时生成。日常关联文档包含轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告、质保书，核心字段包含批次标识、加热温度、轧制压下量、厚度偏差、表面缺陷类型与对应位置，单位涵盖摄氏度、毫米、米等。

## 这些特征在「工作流编排」这一环带来什么约束
该品类的数据实时性强且按单卷或单支钢材生成，要求工作流需绑定批次标识作为核心关联参数，避免不同钢卷数据混淆。多源异构数据来源需要工作流节点支持跨系统数据拉取与关联，需通过`variables`配置跨节点传递的核心参数。日常文档类型多样，工作流需适配不同格式的轧制计划、质量报告等数据源读取。出错后果直接影响产品等级与设备安全，工作流需设置异常分支与失败处理机制，确保流程中断时可触发告警或回滚。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 触发方式 | 按钢卷批次号触发 | 数据按单卷或单支生成，需以唯一批次标识启动流程 |
| `variables` 变量绑定 | 绑定批次号、加热温度阈值、表面缺陷判定阈值 | 用于跨节点传递核心业务参数，关联MES、在线检测等多源数据 |
| `nodeId` 节点绑定 | 为每个数据拉取节点分配唯一`nodeId` | 避免节点执行顺序混乱，确保数据按批次流转 |
| 工具调用超时 | 600 秒 | 在线检测数据实时生成，需预留足够的拉取与分析时间 |
| 节点失败重试次数 | 3 次 | 应对轧机自动控制系统临时断连的场景 |
| 原文件预览关联 | 关联导入知识库的原始质保书、轧制记录 | 实现对应片段的原文档在线查看 |

## 容易做错的三处
- 现象：生成的分享链接指向 `http://localhost:3000/chat/`，无法外部访问。原因：未配置工作流发布的自有域名，沿用了默认本地部署地址。
- 现象：执行工具调用节点后流程停滞，无返回结果。原因：未正确配置数据库连接的参数绑定，或未设置工具调用超时时间，导致连接超时后未触发异常分支。
- 现象：对话中无法查看对应片段的原始文档详情。原因：未关联导入知识库的原始质保书、轧制记录等数据源，仅导入了切片后的文本片段。

## 怎么确认配好了
- 触发测试：上传单卷钢材的批次数据，验证工作流是否自动启动，无跨批次数据混入。
- 超时与重试测试：模拟工具调用超时场景，验证流程是否触发重试或异常分支。
- 原文件预览测试：在对话界面点击质量报告片段，确认可跳转至导入的原始文档详情。
- 发布链接测试：生成分享链接，验证可通过外部网络访问对话界面，无本地地址报错。
