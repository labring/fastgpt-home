# 钢材轧制与精整的质量问题追溯与不良分析：工具调用与插件

## 这个品类的数据长什么样
本品类数据来源于板坯/钢坯批次标识、加热炉运行参数、轧机自动控制系统、在线测厚测宽设备、表面缺陷检测系统与制造执行系统（MES）。数据更新节奏为每卷或每支钢料实时生成，单次记录包含批次号、加热温度、轧制力、板形偏差值、表面缺陷位置与类型等字段。日常归档文档包括轧制计划、加热制度、轧制规程、板形厚度记录、表面质量报告与质保书，按钢卷批次进行结构化存储。

## 这些特征在「工具调用与插件」这一环带来什么约束
本品类的实时、卷级粒度的数据特征，要求工具调用需支持高频触发与小批量数据拉取。多源异构的数据来源，要求插件需适配不同协议的数据源对接，且需按批次维度关联不同系统的记录。实时更新的特性要求工具调用的超时阈值需匹配生产节奏，避免过长等待导致生产链路阻塞。卷级追溯的需求要求工具调用需支持按批次号作为唯一检索键，关联加热、轧制、检测各环节的全链路数据，确保不良分析时可完整追溯从钢坯到成品的全流程信息。同时，结构化的归档文档要求插件需支持解析标准化的轧制规程与质保书字段，提取关键分析参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `toolChoice` | `"auto"` | 适配多工具自动选择，匹配本品类多源数据的调用需求，FastGPT v4.17.0版本支持该参数的灵活配置 |
| 工具调用超时阈值 | `30–60 秒` | 匹配生产实时数据的更新节奏，避免过长等待阻塞轧制链路 |
| `functionCall` | `仅允许自定义函数` | 限制工具调用范围，确保仅调用与钢材轧制质量分析相关的插件，避免无关操作 |
| 数据源编码配置 | `强制UTF-8` | 解决数据库插件中文显示异常的问题，适配国内生产系统的编码标准 |
| 批次检索键配置 | `按钢卷批次号` | 匹配本品类数据按卷级存储的特征，确保全链路追溯的准确性 |
| 单次工具调用返回条数 | `前10条` | 适配卷级数据量有限的特点，避免过多冗余信息干扰不良分析 |

## 容易做错的三处
- 现象：Workflow中两层工具调用时，第一层调用的AI返回内容被打印输出，且同时触发下一级分支执行。原因：未关闭工具调用的日志输出开关，且未配置分支执行的触发条件，导致AI回复与分支执行同步触发。
- 现象：MySQL数据库插件连接后，查询结果无法显示中文，所有配置调整后仍未解决。原因：未在数据源配置中强制指定UTF-8编码，或数据库连接字符串未添加字符集参数，导致中文编码解析失败。
- 现象：调用Qwen2.5的工具调用功能时，无法触发函数调用逻辑。原因：未将`toolChoice`配置为符合要求的参数格式，或未在系统提示词中明确指定函数调用的格式要求，导致大模型无法正确识别调用指令。

## 怎么确认配好了
- 发起一次钢卷批次的质量追溯请求，查看工具调用日志，确认仅返回必要的分析数据，无冗余的AI回复内容。
- 执行包含中文字段的数据库查询，确认返回结果中的中文内容可正常显示。
- 配置Qwen2.5作为大模型，发起包含工具调用需求的测试请求，确认大模型可正确触发指定的插件函数。
- 模拟生产环境的实时数据触发工具调用，确认调用超时时间符合预设阈值，无链路阻塞情况。
