# 钢铁冶炼与连铸的质量问题追溯与不良分析：工作流编排

## 这个品类的数据长什么样
本品类的数据来源包括铁水与废钢台账、L2过程控制系统、化验室检测报告、MES生产管理系统、能源介质监控系统及设备状态监测系统。数据更新频率分为每炉次、实时、每班三类，覆盖炉次计划、配料单、转炉冶炼记录、成分分析报告、连铸工艺参数记录、板坯质量判定单等文档。单份文档包含炉次号、浇次号、温度参数、成分组分、拉速、设备运行时长等字段，字段单位涵盖摄氏度、米/分钟、千克等。

## 这些特征在「工作流编排」这一环带来什么约束
由于本品类为高温连续生产流程，炉次与浇次耦合性强，无法随意停机，因此工作流需绑定精准的炉次维度变量触发节点，避免无差别触发。多系统来源的数据存在字段命名差异，需在工作流中增加统一映射节点，确保不同系统的生产数据可被统一检索。数据更新频率快且出错后果严重，工作流需设置异常分支与重试逻辑，避免单次数据异常导致流程中断或错误追溯。同时，生产数据体量较大，需控制检索范围以避免流程超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `variables` | 绑定炉次号、浇次号、板坯号为全局变量，取值为当前触发流程的实时生产编号 | 炉次与浇次耦合性强，需精准关联各环节的生产记录与质量数据 |
| 节点超时设置 | 600秒 | 单炉次冶炼周期通常在数十分钟内，超时设置可避免流程长时间阻塞 |
| `nodeId` | 绑定化验室成分报告节点、连铸工艺记录节点的nodeId | 需按特定节点的执行结果触发后续追溯与分析逻辑 |
| 异常分支配置 | 3次重试+失败告警 | 生产数据可能存在临时网络波动或系统延迟，重试可降低误触发概率 |
| 单次检索上限 | 前10条 | 钢铁生产环节数据体量较大，控制检索范围可提升流程执行效率 |
| 变量映射规则 | 按实测标定的字段匹配关系 | 不同系统的字段命名存在差异，需统一匹配逻辑以确保数据关联准确 |

## 容易做错的三处
- 现象：执行工具调用节点后流程停滞，控制台显示无匹配数据。原因：未将`variables`绑定的实时炉次号作为检索关键词，导致无法从多系统数据中定位对应记录。
- 现象：工作流测试时无法打开原文件预览，提示文件路径无效。原因：未将知识库切片的原文件存储路径与`variables`中的文档路径做映射，导致检索结果无法关联原始文件。
- 现象：cosyvoice节点调用失败，返回连接超时错误。原因：未设置节点超时参数，或超时阈值设置过短，无法适配钢铁生产系统的响应延迟。

## 怎么确认配好了
- 在FastGPT v4.17.0版本的工作流编辑器中，触发模拟炉次流程，检查`variables`中的炉次号、浇次号是否自动加载为当前测试的生产编号。
- 调用工具节点，查看返回结果是否包含对应炉次的冶炼记录与成分报告，核对字段是否与预设的映射规则匹配。
- 手动触发异常分支，验证是否触发重试逻辑或告警通知。
- 点击工作流中配置的文件链接变量，确认可跳转至对应原文档的预览页面。
