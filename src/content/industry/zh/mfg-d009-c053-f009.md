# 钢铁冶炼与连铸的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源包括铁水与废钢投料数据、L2过程控制数据、化验室成分报告、MES生产数据、能源介质系统参数及设备状态监测数据。数据更新节奏覆盖每炉次、实时及每班频次。日常文档包含炉次计划、配料单、转炉冶炼记录、连铸工艺记录、板坯判定单，字段包含炉号、钢种、冶炼时长、终点温度、拉速、缺陷类型等，格式随产线调整略有差异。

## 这些特征在「模型接入与配置」这一环带来什么约束
本品类数据来源分散且更新节奏差异显著，模型接入环节需支持多数据源并行读取，适配实时流与批量归档数据的混合输入。日常文档格式不统一，需配置可自定义字段映射的解析规则，避免硬编码适配单类文档。炉次与浇次耦合性强，模型输入需关联上下游工序的关联ID，确保质量追溯链路完整。同时高温连续流程无法随意停机，配置变更需支持灰度发布与快速回滚，避免干扰生产节奏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配炉次关联的多文档总长度，覆盖转炉、连铸及板坯记录的核心字段 |
| `maxTokens` | 4000 token | 限制单轮分析输出长度，避免超出钢铁工艺分析的必要信息范围 |
| `quoteMaxToken` | 2000 token | 限定引用的源文档片段长度，确保仅保留与质量缺陷直接相关的工艺参数 |
| 工作流/API 工具选择配置 | auto | 自动选择工具适配多数据源读取与关联查询需求 |
| `temperature` | 0.2–0.4 | 降低随机性，确保工艺分析结果符合生产实际规则 |
| `AIPROXY_API_ENDPOINT` | 按产线部署的代理地址填写 | 适配企业内部网络隔离的访问需求 |

## 容易做错的三处
- 检索结果仅返回单炉次数据，无法关联上下游浇次信息。原因是未配置炉号、浇次号的关联字段映射规则，导致数据链路断裂。
- 调用外部工具时出现调用失败，返回状态码400。原因是未适配工具的sse协议格式，仅使用通用调用脚本。
- 模型分析结果出现不符合钢铁工艺逻辑的偏差。原因是`temperature`取值超出合理区间，导致分析随机性过高。

## 怎么确认配好了
- 导入单炉次的转炉冶炼记录与板坯判定单，核对模型是否能关联对应炉号的所有关联数据。
- 调用配置的外部工具，验证是否能正常返回工艺参数的查询结果。
- 调整`temperature`参数，观察分析结果的随机性变化，确认符合预期。
- 查看FastGPT v4.17.0的系统日志，确认无数据源读取或工具调用的报错信息。
