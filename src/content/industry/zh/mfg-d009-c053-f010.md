# 钢铁冶炼与连铸的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
该品类的数据来自铁水与废钢台账、L2过程控制系统、化验室检测报告、制造执行系统、能源介质监控平台及设备状态监测系统。日常文档包含炉次计划、配料单、转炉冶炼记录、成分检测报告、连铸工艺参数记录、板坯质量判定单。数据更新频率为每炉次、实时或每班更新。数据字段包含炉次编号、浇次编号、铁水温度、冶炼终点成分、连铸拉速、缺陷类型编码等，温度以摄氏度为单位，时间以分钟或小时为单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
该品类的数据更新频率高且多源异构，要求知识库检索需支持实时增量同步多系统数据，避免检索结果滞后于生产实际。炉次与浇次强耦合的业务逻辑，要求检索召回需关联炉次编号、浇次编号等关联字段，保证检索结果与当前生产批次匹配。结构化字段占比高的文档特征，要求检索需支持数值型字段的精准匹配，仅依赖文本关键词无法覆盖全部关键信息。同时，质量问题追溯涉及的后果影响范围广，要求检索召回的结果需具备较高的可信度，避免错误关联历史数据。

## 配置怎么定
本页面基于FastGPT v4.17.0版本的配置规则编写。

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `similarity` | 0.75–0.85 | 钢铁冶炼数据包含大量结构化数值字段，该阈值可过滤低相关的非生产类文档，同时保留关键工艺参数的匹配结果，按实测标定后可适配不同炉次类型。 |
| `limit` | 前8–12条 | 单炉次相关文档数量有限，该范围可保证上下文窗口适配，同时覆盖全部关键关联文档。 |
| `searchMode` | 语义匹配+结构化字段匹配 | 该品类数据包含大量结构化工艺参数，结合语义匹配可同时覆盖关键词与数值关联的检索需求。 |
| `usingReRank` | 开启 | 质量追溯需精准匹配缺陷类型与工艺参数，重排可提升高相关结果的排序优先级，降低错误关联的概率。 |
| `datasetSearchUsingExtensionQuery` | 开启 | 可基于炉次编号自动扩展检索关联的浇次、配料等文档，适配炉次与浇次强耦合的业务逻辑。 |
| `collectionIds` | 按生产车间/工序绑定对应知识库集合 | 钢铁冶炼各工序数据独立且更新频率不同，绑定对应集合可避免检索无关工序的历史数据。 |

## 容易做错的三处
- 现象：检索结果包含无关车间的冶炼记录，原因：未通过`collectionIds`绑定对应工序的知识库集合，导致检索范围覆盖全量生产数据。
- 现象：多级目录的连铸工艺文档未被完整召回，原因：未配置知识库的全目录递归解析规则，仅识别顶层目录的文档文件。
- 现象：检索触发后返回「common:core.chat」类报错，原因：未按实时更新的炉次批次调整`collectionIds`绑定的知识库集合，导致引用的集合不存在或权限配置异常。

## 怎么确认配好了
- 手动输入某炉次的编号与温度参数，核对检索结果是否包含对应炉次的冶炼记录与板坯判定单。
- 查看知识库配置的`collectionIds`列表，确认仅包含当前车间的工序文档集合。
- 开启`usingReRank`后，对比开启前后的检索结果排序，确认高相关文档的排名是否提升。
- 测试上传多级目录的连铸工艺文档，确认所有层级的文档均被纳入检索范围。
