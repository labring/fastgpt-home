# 钢铁冶炼与连铸的质量问题追溯与不良分析：部署与升级

## 这个品类的数据长什么样
本品类的数据覆盖铁水与废钢投料、L2过程控制、化验室成分报告、MES生产调度、能源介质消耗及设备运行状态。日常关联文档包含炉次计划、配料单、转炉冶炼记录、连铸工艺参数记录、板坯质量判定单。数据更新按单炉次完成后同步、关键工艺参数实时上传、每班能耗与设备状态汇总的节奏，包含炉次标识、冶炼时长、成分检测值、连铸拉速等核心字段。

## 这些特征在「部署与升级」这一环带来什么约束
本品类的多源异构数据、差异化更新节奏与强流程耦合特性，对部署与升级环节带来多重约束。多源数据需对接铁水投料、L2过程控制、化验室等不同类型的数据源，需提前配置兼容的数据库连接参数。实时上传的工艺数据要求部署节点具备低延迟响应能力，避免干扰连续生产流程。单炉次生成的结构化文档与实时时序数据需分别适配不同的存储策略，避免数据读写冲突。升级环节需采用滚动更新方式，避免中断生产，同时需保证新旧版本的数据兼容，防止流程中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30 个连接` | 本品类需同时对接铁水、L2、MES等多源数据，足够的连接数可避免连接耗尽，保障数据读取效率 |
| `MONGODB_URI` | `mongodb://[用户名]:[密码]@[主机地址]:[端口]/fastgpt?authSource=admin` | 本品类的板坯判定单、连铸工艺记录等非结构化文档适合存储在MongoDB，需配置正确的认证与目标库名 |
| `REDIS_URL` | `redis://:[密码]@[主机地址]:[端口]/0` | 本品类需缓存实时工艺数据与用户会话，使用独立数据库可避免与其他服务的缓存冲突 |
| `STORAGE_S3_ENDPOINT` | `http://[对象存储主机]:[端口]` | 本品类的大型冶炼记录、工艺文档需持久化存储，适配对象存储的标准接入格式 |
| `ROOT_KEY` | `随机生成的32位字符串` | 本品类涉及生产数据权限管控，强密钥可保障系统核心访问链路的安全 |

## 容易做错的三处
- 现象：调用向量模型接口返回404错误。原因：未正确配置向量模型的接入地址，或未将模型部署路径与代理路径对齐。
- 现象：系统响应速度缓慢，单轮问答耗时超过30秒。原因：未根据本品类的数据量调整`DB_MAX_LINK`参数，导致数据库连接耗尽，无法及时读取历史工艺数据。
- 现象：无法在系统管理界面中添加无GPU的向量模型。原因：未在部署向量模型时开启CPU推理模式，或未配置适配CPU环境的模型加载参数。

## 怎么确认配好了
- 使用FastGPT v4.17.0的系统管理工具，执行数据库连接测试，验证`MONGODB_URI`与`REDIS_URL`配置的连接是否正常。
- 上传一份模拟的转炉冶炼记录文档，检查系统是否能正确读取并存储，无格式或路径报错。
- 启动向量模型服务后，发起一次质量追溯查询，验证是否能返回匹配的工艺数据，无404或超时错误。
- 查看系统监控面板，确认数据库连接数稳定在`20–30`个连接区间内，无连接耗尽告警。
