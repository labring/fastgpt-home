# 钣金下料折弯的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
这个品类的核心数据来自CAD/CAM软件、订单BOM系统、板材库存台账、激光切割机与折弯机设备日志、车间MES系统。日常产出的文档包含三维件展开图、数控下料程序、折弯工艺卡、套料图、首件检验记录、工序流转卡。数据更新随订单交付、每日生产排班、每次工艺换型触发。字段包含折弯补偿系数、孔位公差值、板材厚度与材质规格，单位多为毫米、千克与批次号。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类的数据分散于多套系统，且随订单、换型高频更新，要求多轮对话必须关联当前批次的专属文档与参数。多品种小批量的业务模式，要求提示词需适配不同工件型号的折弯补偿、套料规则，无法使用通用模板。文档以图纸、工艺卡为主，对话需精准定位孔位错位、折弯误差等具体问题，因此上下文需限定在当前订单的工序流转范围内，避免混入过期数据。同时需通过对话流程明确追溯下料程序、折弯机参数等设备日志，确保分析依据的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chatId` | 绑定当前生产批次的唯一编号 | 确保对话历史仅关联对应批次的下料程序、折弯工艺卡与设备日志，避免跨批次数据混淆，符合FastGPT v4.17.0的会话管理规则 |
| `messages` | 保留当前订单的前20条对话消息 | 匹配该品类订单周期短的特征，防止上下文溢出无关历史，优化对话响应速度 |
| `variables` | 传入工件型号、板材厚度、折弯补偿系数 | 适配多品种小批量的业务模式，让提示词可精准调用对应订单的专属文档 |
| 单次召回上限 | 前6条相关文档 | 该品类文档类型集中，过多召回会干扰折弯误差、孔位错位的精准分析 |
| 上下文超时 | 300 秒 | 车间工人的追溯提问通常在5分钟内完成，超时可释放无效会话资源 |

## 容易做错的三处
- 现象：通过API创建的对话，在页面中无法查看对应历史记录。原因：未在请求中正确绑定`chatId`参数，导致会话与当前用户的会话池未关联。
- 现象：API响应的记录预览中，Human字段为null。原因：未在`messages`参数中正确传入用户的原始提问内容，导致对话链缺失用户输入节点。
- 现象：不同操作人员的对话历史互相可见。原因：未为每个会话绑定独立的`chatId`，导致不同用户的会话被归为同一上下文池。

## 怎么确认配好了
- 发起一次模拟追溯提问，查看返回的对话历史中是否仅包含当前批次的相关文档与提问记录。
- 调用API创建会话，传入指定`chatId`与`variables`参数，确认页面可加载对应会话的完整历史。
- 检查`messages`参数是否仅保留当前订单的对话内容，未混入其他批次的历史数据。
- 调整单次召回上限，验证返回的相关文档数量符合预设的取值范围。
