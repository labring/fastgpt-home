# 钣金下料折弯的质量问题追溯与不良分析：工作流编排
本文基于FastGPT v4.17.0版本编写

## 这个品类的数据长什么样
该品类的数据主要来自CAD/CAM生成的展开图、数控下料程序，订单BOM的物料清单，板材库存的批次与厚度数据，激光切割机、折弯机的加工日志，以及MES系统的工序流转记录。数据更新频率为每订单、每日、每次换型。日常文档包含展开图、折弯工艺卡、套料图、首件记录、工序流转卡，字段包含折弯补偿系数、下料尺寸、切割路径参数、板材批次号、工序流转节点时间、设备运行参数等。不同订单的文档格式与参数字段存在差异，需按订单维度进行数据隔离。

## 这些特征在「工作流编排」这一环带来什么约束
由于该品类多品种小批量、图纸驱动的特征，工作流需支持按订单或换型隔离`variables`，避免全局变量冲突。数据来源分散且更新频率高，需配置节点间的变量传递规则，确保每个加工环节读取对应批次的板材、工艺参数，避免跨批次数据混淆。折弯补偿系数校验为核心环节，需在工作流中嵌入参数比对节点，匹配展开图与加工日志的数值，防止孔位错位、外形偏差等问题。工序流转的顺序约束要求工作流节点需严格遵循工序流转卡的逻辑，不可随意调整执行顺序，避免干涉与累积误差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `variables`作用域 | 按订单ID或换型批次隔离 | 该品类多订单、多换型的特征，需避免不同订单的变量值冲突 |
| `nodeId`绑定 | 绑定工序节点的唯一标识 | 便于精准追溯每个加工环节的执行日志与设备数据 |
| 数据集ID引用配置 | 关联当前订单的专属数据集 | 质量追溯需匹配对应订单的下料、折弯工艺文档 |
| 超时阈值 | 600秒（按工序节拍实测标定） | 匹配钣金加工工序的常规节拍，超时可触发异常告警 |
| 单次知识库检索条数 | 前3条（按文档量实测标定） | 避免过多冗余结果干扰不良分析的准确性 |
| 参数校验触发条件 | 当工序流转卡参数更新时触发 | 确保折弯补偿系数、下料尺寸等关键参数实时校验 |

## 容易做错的三处
- 现象：工作流中不同订单的`variables`出现值覆盖，同一变量名在不同订单下返回相同结果。原因：未配置按订单ID隔离`variables`的作用域，使用全局变量导致数据混淆。
- 现象：工作流测试时，仅第一个问题触发知识库引用，后续问题无匹配结果。原因：未正确配置节点间的上下文传递，后续节点未加载当前订单的专属数据集。
- 现象：知识库检索节点无法引用全局配置的datasetid。原因：未在节点配置中绑定当前工作流的变量作用域，直接使用全局变量未完成作用域隔离。

## 怎么确认配好了
- 查看工作流的`variables`配置项，确认已按订单ID或换型批次设置隔离规则，可通过测试不同订单的变量值验证是否隔离。
- 检查每个工序节点的`nodeId`绑定，确认每个节点对应唯一的工序标识，可通过日志查看节点执行的关联数据是否匹配。
- 验证知识库检索节点的数据集引用，确认绑定的是当前订单的专属数据集，可通过触发检索查看返回的文档是否属于对应订单。
- 测试超时阈值的触发逻辑，确认当工序执行超过设定时长时，工作流会触发异常告警。
