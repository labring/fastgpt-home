# 钣金下料折弯的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
该品类数据主要来自CAD/CAM软件、订单BOM、板材库存系统、激光切割机与折弯机设备、MES生产管理系统。日常文档包含钣金件三维展开图、数控下料程序、折弯工艺卡、套料图、首件检验记录、工序流转卡。数据更新随每笔订单、每日生产进度或每次设备换型触发，整体以图纸驱动为核心，多品种小批量生产模式下数据维度随工序流转动态变化。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的多文档类型、动态更新频率决定了模型接入时需适配不同格式的结构化与非结构化数据。钣金图纸类文档含几何参数与工艺参数，需确保模型能准确解析展开图中的折弯系数、套料排样规则；高频更新的数据要求配置支持实时或准实时同步，避免检索到过期的工艺参数。同时多品种小批量带来的单次数据量波动，需限制单次送入模型的上下文规模，防止超出模型处理上限，且需针对工序流转卡、首件记录这类时序数据优化检索匹配逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本。

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配钣金下料折弯的多文档拼接需求，避免超出主流大模型的上下文窗口上限 |
| `quoteMaxToken` | 2000–3000 token | 限制单条检索引用的文本长度，适配折弯工艺卡、展开图的参数提取需求，防止冗余内容干扰模型判断 |
| `temperature` | 0.2–0.4 | 降低随机性，确保工艺参数、几何尺寸的检索结果准确一致，匹配质量追溯的严谨性要求 |
| 单次搜索上限 | 前6条 | 匹配多品种小批量的工序数据量，避免过多无关检索结果挤占上下文空间 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配企业内部网络环境，确保模型调用的稳定性与数据安全性 |

## 容易做错的三处
- 现象：语义检索返回多条结果，但模型提示未找到相关信息。原因：未限制`quoteMaxToken`，单条引用文本过长或总上下文超出`maxContext`上限，导致有效检索内容被截断，模型无法匹配到关键参数。
- 现象：模型调用频繁出现超时报错。原因：未合理设置`maxContext`，送入过多钣金图纸的展开数据，超出模型处理阈值，或未配置适配的API调用超时时长。
- 现象：检索得到的折弯系数与实际工艺卡参数存在偏差。原因：`temperature`取值过高，导致模型在解析结构化工艺参数时出现随机波动，无法匹配生产文档的精准要求。

## 怎么确认配好了
- 上传单份折弯工艺卡与展开图，触发检索后核对返回的引用文本是否包含准确的折弯系数与孔位参数。
- 模拟包含多份套料图与折弯工艺卡的批量检索请求，检查模型调用的响应时长与内容完整性，确认未出现上下文溢出或内容截断。
- 调整`temperature`参数至0.1与0.5，对比两次检索结果的一致性，验证参数对结果稳定性的影响。
- 查看系统日志，确认每次模型调用的`quoteMaxToken`与`maxContext`参数符合预设配置，无异常取值。
