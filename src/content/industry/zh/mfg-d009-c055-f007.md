# 铸造（砂型、精密、压铸）的质量问题追溯与不良分析：数据库与运维

## 这个品类的数据长什么样
该品类的数据来自ERP物料主数据、熔炼炉与测温仪、光谱仪、MES炉次记录、模具管理系统、客户图纸与技术条件。日常文档包含铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告、不合格品评审单。数据按每炉次、每批或每日更新，核心字段包括炉次编号、模次、合金成分参数、熔炼温度、浇注参数、缺陷类型，涵盖摄氏度、千克等单位。数据索引用于加速按炉次、模次的快速检索，提升追溯效率。该品类产品由液态金属成形，质量核心聚焦熔炼、浇注、凝固环节的内部缺陷，与依赖塑性变形的锻造品类数据特征差异明显。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构的数据来源要求数据库支持结构化与非结构化数据的混合存储，保障炉次记录、检测数据与文档的关联查询。每炉次高频更新的特点带来峰值写入压力，需要合理配置连接池以应对并发请求。缺陷追溯需关联炉次、模次、检测参数等多维度数据，对数据库的关联查询性能提出要求。不合格品评审单等非结构化文档需与结构化数据绑定存储，保障检索时的上下文完整性。数据更新频率不均，峰值时段的写入请求可能超出常规配置的连接数上限，需预留足够的连接资源。非结构化文档的语义检索需依赖向量数据库存储特征，保障检索的语义匹配准确性。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本，适配铸造场景的数据库与运维需求：

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://fastgpt:xxx@mongodb:27017/foundry_qc?authSource=admin` | 存储炉次记录、光谱仪检测数据等结构化多源数据，支持跨表关联查询 |
| `PG_URL` | `postgresql://fastgpt:xxx@postgres:5432/foundry_qc` | 存储模具履历、不合格品评审单等带元数据的文档，保障结构化检索性能 |
| `DB_MAX_LINK` | `15–25` | 适配每炉次高频写入的峰值连接需求，避免数据库连接耗尽 |
| `REDIS_URL` | `redis://:xxx@redis:6379/1` | 缓存热门炉次查询结果、模具状态信息，降低数据库重复访问开销 |
| 单次召回上限 | 前8条 | 匹配铸造场景下需关联的多维度参数条目规模，避免返回冗余内容 |

## 容易做错的三处
- 现象：数据库连接超时报错，状态码504。原因：未根据每炉次高频更新的特点调整`DB_MAX_LINK`取值，导致连接池耗尽无法新建连接。
- 现象：检索结果中缺少对应炉次的模具履历信息。原因：未正确配置`MONGODB_URI`的关联查询权限，未绑定炉次编号与模具模次的关联字段。
- 现象：Redis缓存过期导致重复查询压力过大。原因：未根据铸造数据的更新频率设置合理的缓存过期时间，未区分高频查询的炉次数据与低频的历史文档。

## 怎么确认配好了
- 执行模拟炉次数据写入操作，检查`MONGODB_URI`和`PG_URL`对应的数据库是否成功写入对应字段。
- 查看Redis连接日志，确认`REDIS_URL`配置的实例正常接收缓存请求，无连接拒绝报错。
- 发起缺陷追溯检索请求，核对返回结果是否包含炉次、模次、检测参数等核心字段，字段完整性符合业务要求。
- 模拟峰值写入场景，检查`DB_MAX_LINK`配置的连接数是否满足并发写入需求，无连接超时报错。
