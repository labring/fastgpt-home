# 铸造（砂型、精密、压铸）的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
本品类数据来自ERP物料主数据、熔炼炉测温仪、光谱仪、MES炉次记录、模具管理系统及客户技术图纸。日常文档包含铸造工艺卡、配料单、炉次记录、模具履历、首件检验记录、材质报告与不合格品评审单。数据更新按炉次、批次或每日执行，字段包含炉次编号、合金配料比例、熔炼温度、浇注参数、缺陷类型、模次编号等，未包含预设统计百分比类数值。

## 这些特征在「知识库检索与召回」这一环带来什么约束
数据按炉次、批次更新，需精准匹配炉次号、模次等唯一业务标识，检索环节需支持按此类字段过滤。文档类型涵盖结构化的炉次记录与非结构化的工艺卡，检索需兼容不同格式的内容。高频更新导致知识库增量同步需求频繁，需配置适配炉次级更新的同步规则。合金配料、熔炼温度等数值型字段需支持精确匹配与范围检索，适配缺陷追溯时的参数比对需求。跨文档的关联查询需支持炉次、模具、配料等字段的关联匹配，避免检索结果碎片化。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | 适配铸造参数的精确匹配需求，避免召回无关炉次记录或非目标缺陷文档 |
| `limit` | 前10条 | 覆盖单炉次关联的模具、配料、检验等多类文档，避免结果过载影响分析效率 |
| `searchMode` | vector_only | 优先匹配语义关联的工艺参数与缺陷描述，适配不良分析场景的语义检索需求 |
| `usingReRank` | 开启 | 对召回结果按缺陷严重程度、炉次优先级重排，提升关键文档的展示顺位 |
| `datasetSearchUsingExtensionQuery` | 关闭 | 铸造场景下业务术语固定，无需额外改写查询词，避免语义偏移导致检索偏差 |
| `collectionIds` | 按业务模块绑定 | 绑定炉次记录、工艺卡、模具履历专属集合，避免跨品类文档干扰检索结果 |

## 容易做错的三处
- 现象：重排模型配置完成后，问答流程中`usingReRank`返回false。原因：未在工作流的知识库节点中开启重排开关，或重排模型未绑定至当前使用的知识库集合。
- 现象：知识库搜索节点的引用变量下拉框为空，无法动态指定知识库。原因：未在全局变量中创建知识库ID类型的变量，或变量未配置为可被工作流节点引用的权限。
- 现象：检索结果未匹配到符合业务预期的文档，且发现召回逻辑使用了改写后的查询词。原因：开启了`datasetSearchUsingExtensionQuery`，铸造场景下业务术语固定，改写后的查询词偏离了原始业务语义，导致检索偏差。

## 怎么确认配好了
- 进入FastGPT v4.17.0的知识库管理页面，检查绑定的集合是否包含铸造工艺卡、炉次记录、模具履历等目标业务文档。
- 在工作流测试面板中输入模拟的缺陷追溯查询，查看检索结果的`similarity`分值分布，确认匹配度符合业务预期。
- 开启重排功能后，查看重排后的结果排序是否优先展示炉次号、模次匹配的核心文档。
- 配置动态变量后，在测试面板中传入预设的知识库ID变量，确认搜索节点可正常加载对应集合的文档内容。
