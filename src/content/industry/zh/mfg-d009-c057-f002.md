# 锻造与模锻的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
本品类数据来自锻造厂、航空航天及汽车锻件供应商的多源系统，包括原材料质保书、加热炉记录、压力机采集数据、MES系统、无损检测报告等。日常文档涵盖锻造工艺规程、下料卡、模具寿命记录、热处理委托单等，核心字段包含炉批号、锻件批次号、加热温度、成型压力、缺陷类型等，更新频率为每件、每批或每炉次一次，数据兼具结构化参数与非结构化报告两类形式。

## 这些特征在「向量模型与索引」这一环带来什么约束
多源混合的数据格式要求索引模块适配结构化参数与非结构化文档的分块规则；按炉批、批次的高频更新需求，要求索引支持增量触发以避免全量重复扫描；核心字段的强关联性（如炉批号与锻件批次）要求索引保留元数据关联，防止特征割裂；单次分析涉及的历史数据量集中，要求控制召回结果的规模以保障响应速度。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的向量模型与索引模块。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配锻造工艺规程、无损检测报告的段落结构，避免单块内容过长超出模型限制 |
| 重叠长度 | 100–150 字符 | 保留锻件批次号、炉批号等跨块关联的关键元数据，防止特征断裂 |
| `maxToken` | 4096 token | 适配主流嵌入模型的输入上限，完整承载加热温度、压力参数等核心业务字段 |
| 相似度阈值 | 0.75–0.85 | 区分折叠、裂纹等相似缺陷特征，降低不良分析的误召回概率 |
| 单次搜索上限 | 前10条 | 适配锻造批次数据集中的特性，避免过多结果拉长分析耗时 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |

## 容易做错的三处
- 现象：索引构建进度停留在最后一组，无明确报错提示。原因：未配置按炉批触发的增量索引规则，系统反复扫描全量锻造批次数据导致资源阻塞。
- 现象：知识库创建后无法正常完成索引，卡在「建索引」步骤。原因：未针对锻造数据的多源格式做分块适配，混合导入结构化MES数据与非结构化PDF检测报告，导致分块逻辑冲突。
- 现象：更换自定义嵌入模型后可完成索引，但搜索测试返回报错。原因：未同步调整`defaultToken`配置，新模型的输入token上限与原配置不匹配，引发向量查询截断异常。

## 怎么确认配好了
- 上传单份锻造工艺规程文档，检查分块后的片段是否完整保留炉批号、加热区间等关键元数据。
- 触发批量索引任务，观察进度条是否按批次有序推进，无长时间停滞在单一组的情况。
- 更换测试用的嵌入模型，完成索引后执行缺陷特征搜索，确认返回结果无报错且匹配度符合业务预期。
- 查看系统索引日志，确认`maxToken`配置未出现内容截断提示，所有核心业务字段均完成向量入库。
