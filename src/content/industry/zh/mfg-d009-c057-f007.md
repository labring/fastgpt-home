# 锻造与模锻的质量问题追溯与不良分析：数据库与运维

## 这个品类的数据长什么样
这个品类的数据覆盖锻造全流程，来源包括原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图。日常文档包含锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告。数据按每件锻件、每批次或每炉次更新，核心字段包括锻件批次号、材料炉批号、加热温度、成型压力、缺陷类型、模具使用次数，对应单位分别为批次号、炉批号、℃、MPa、缺陷类别、次。

## 这些特征在「数据库与运维」这一环带来什么约束
高频次的单件/批数据更新要求数据库支撑高并发写入，避免因连接耗尽导致数据丢失。多源异构的数据来源需要运维环节兼容不同格式的实时采集与批量导入，适配锻造流程中传感器、系统报表等不同类型的数据接入。锻件批次与材料炉批号的强关联查询需求，要求建立联合索引以提升追溯效率。离线部署的场景下，需要配置本地数据同步与备份策略，避免跨版本升级时的数据丢失风险。同时，数据留存周期需匹配锻件服役周期，满足质量追溯的业务需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 数据库连接地址 | `mongodb://admin:your_password@127.0.0.1:27017/forging_db?authSource=admin` | 适配本地win10部署的MongoDB连接，存储锻造过程的实时采集数据与批次关联信息 |
| 最大数据库连接数 | `80–120` | 匹配多源数据高频写入的并发连接需求，避免连接池耗尽 |
| 工具调用检索阈值 | `0.75–0.85` | 筛选知识库中匹配的锻造质量问题数据，匹配则返回关联答案，未匹配则返回预设提示内容 |
| 缓存服务地址 | `redis://127.0.0.1:6379/0` | 缓存高频查询的锻件批次关联数据，提升质量追溯的响应速度 |
| 元数据库地址 | `postgresql://admin:your_password@127.0.0.1:5432/forging_metadata` | 存储锻造工艺规程、检测报告等结构化元数据，与MongoDB形成冷热数据分离 |

## 容易做错的三处
- 现象：FastGPT控制台返回数据库连接失败报错，日志显示ECONNREFUSED。原因：未正确配置数据库连接地址，win10本地部署时未开放MongoDB默认端口27017的防火墙权限。
- 现象：工具调用检索返回的结果不符合预期，要么无匹配数据却返回答案，要么匹配度不足却返回结果。原因：未正确设置工具调用检索阈值，导致匹配逻辑不符合锻造质量追溯的业务需求。
- 现象：跨版本升级后无法读取历史锻造数据，或无法查看数据库表模型。原因：直接迁移数据库目录未导出元数据，导致FastGPT v4.6.7与FastGPT v4.8.10的数据库表结构不兼容，未保留原有的表定义信息。

## 怎么确认配好了
- 执行本地MongoDB连接测试，使用配置的数据库连接地址通过命令行工具验证连接可用性。
- 提交一条模拟的锻件批次查询请求，确认可以返回匹配的加热炉记录、超声检测报告等关联数据。
- 查看数据库连接池状态，确认当前活跃连接数未超过最大数据库连接数的配置值。
- 调整工具调用检索阈值，验证匹配度达标时返回知识库关联答案，未达标时返回预设提示内容。
- 查看数据库元数据，确认各表的字段与锻造业务需求匹配，可通过数据库客户端导出表结构定义。
