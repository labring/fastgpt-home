# 锻造与模锻的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
本品类数据来源包括原材料质保书、加热炉系统、压力机采集数据、MES系统、无损检测仪及客户锻件图。日常文档涵盖锻造工艺规程、下料卡、加热炉记录、锻造过程卡、模具寿命记录、热处理委托单、超声检测报告。数据更新按每件、每批或每炉次触发，核心字段包含炉批号、锻件批次、锻造比、金属流线状态等，单位涉及温度、压力、批次编号等。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据按炉次、批次更新且关联多系统异构日志，要求模型接入时需支持按批次维度关联多源数据。多源数据格式差异较大，需配置适配的字段映射规则。高频次的批次级更新要求配置项支持动态触发数据同步，避免分析延迟。核心字段如锻造比、金属流线需作为检索与分析的关键锚点，需在配置中明确关联字段的权重。同时，不良分析需回溯完整工艺链，要求上下文配置足够覆盖全流程数据。

## 配置怎么定
以下配置项适配锻造与模锻场景，基于FastGPT v4.17.0版本编写：

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | 覆盖单炉次全流程工艺记录、检测报告与批次关联数据，防止上下文截断丢失关键追溯信息 |
| `maxTokens` | 4000 token | 限制单轮分析输出长度，确保不良原因推导与追溯步骤清晰完整 |
| `temperature` | 0.2–0.4 | 贴合锻造工艺的确定性规则，保障不良分析结果的一致性与可追溯性 |
| 工作流/API 工具选择配置 | auto | 允许模型自主调用关联工具，完成多源数据的批次匹配与链路追溯 |
| `AIPROXY_API_ENDPOINT` | 按实际部署环境填写 | 适配aiproxy的接入地址，确保模型调用链路正常连通 |
| `AIPROXY_API_TOKEN` | 按平台分配的密钥填写 | 完成身份验证，保障模型调用的权限合规 |

## 容易做错的三处
- 出现MCP接入链路报错，无法连接到指定的模型服务。原因是未将FastGPT生成的SSE格式MCP适配到仅支持NPX的开发环境，未配置格式转换规则。
- 检索结果仅包含知识库静态数据，无法关联实时生产数据。原因是未配置多源系统的实时数据接入，仅绑定了静态知识库文件。
- 模型生成的分析结果中炉批号字段为空。原因是未在配置中明确关联炉批号的核心字段，导致模型无法提取对应批次信息。

## 怎么确认配好了
- 上传单炉次的完整工艺与检测数据，发起不良分析请求，检查返回结果是否覆盖全流程关键数据。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确，无连接报错。
- 调整`temperature`参数后发起多次分析，检查结果是否保持一致。
- 输入包含特定炉批号的查询，确认检索结果能关联对应批次的生产数据。
