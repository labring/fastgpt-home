# 预制混凝土构件的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
该品类的数据主要来自BIM深化设计、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检验报告及构件二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣日志、养护周期记录、脱模与出厂检验报告。数据更新节奏按单件构件、每批物料、每窑养护批次触发，覆盖从生产准备到出厂的全流程环节，数据字段包含构件编号、物料批次、养护时长、检验强度等，单位涵盖毫米、立方米、小时、兆帕等。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类的数据更新频率高且粒度细，每一件构件、每一批物料、每一窑养护批次均会生成新数据，对索引的增量更新能力有明确要求。日常文档包含长文本的构件深化图、短文本的检验记录，数据长度差异显著，需要适配不同长度的文本分块规则。数据与单件构件的二维码、批次编号强绑定，向量检索需关联溯源标识以精准定位问题来源。同时生产环节的出错后果直接关联工期与成本，检索响应速度需匹配业务处理节奏，避免因索引加载过慢影响追溯效率。FastGPT v4.17.0已支持向量模型归一化配置，可适配未归一化的embedding模型，保证检索精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| 最大上下文 | 8000–12000 token | 匹配预制混凝土构件深化图与多份关联记录合并后的文本长度，避免截断关键溯源信息 |
| 向量模型归一化配置 | 开启 | 适配未归一化的embedding模型，保证检索相似度计算的准确性 |
| 单次搜索上限 | 前10条 | 平衡检索召回率与响应速度，适配多文档关联的质量问题追溯需求 |
| `defaultToken` | 500 token | 作为单条分块的默认长度，适配短文本的检验记录与下料单片段 |
| `maxToken` | 1500 token | 限制最长分块长度，避免过长的构件深化图分块导致索引负载过高 |
| 相似度阈值 | 0.75–0.85 | 过滤低关联度的检索结果，聚焦与质量问题直接相关的生产记录 |

## 容易做错的三处
- 现象：切换知识库向量模型后，后台任务状态始终显示“进行中”且无进度，无法通过界面切换回原模型。原因：仅修改了向量模型配置项，未触发关联索引的重新生成，导致系统无法适配新模型的向量格式。
- 现象：检索结果返回大量无关的生产记录，且查询耗时超过30秒。原因：未设置合理的单次搜索上限与相似度阈值，同时未对长文本进行合理分块，导致索引负载过高。
- 现象：检索时触发token超限报错，或后台显示token使用量超出预设额度。原因：未配置`maxToken`与最大上下文参数，将完整的长文本构件深化图直接送入检索流程，导致token占用过高。

## 怎么确认配好了
- 进入向量模型配置页面，确认“向量模型归一化配置”开关处于开启状态。
- 提交一条质量问题查询，核对返回结果的条数与相似度评分，确认符合预设的单次搜索上限与相似度阈值。
- 查看后台任务日志，确认切换向量模型后索引重建任务正常启动并完成。
- 测试单条短文本的检验记录检索，确认`defaultToken`参数生效，分块长度符合预期。
