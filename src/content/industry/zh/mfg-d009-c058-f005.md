# 预制混凝土构件的质量问题追溯与不良分析：工具调用与插件

## 这个品类的数据长什么样
预制混凝土构件的数据来源于BIM或深化设计文件、钢筋和混凝土批次台账、模台与养护窑运行记录、试验室检测报告以及构件二维码追溯系统。日常维护的文档包括构件深化图、钢筋下料单、模具检验记录、浇筑振捣记录、养护记录、脱模与出厂检验报告。数据更新频率为每件构件、每批材料、每一窑养护批次对应一次更新，字段包含构件编号、钢筋批次号、模台ID、养护窑编号、强度检测值、二维码追溯码等，单位涉及MPa、吨、天等。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据来源分散，覆盖设计、生产、检测等多套独立系统，工具调用需支持对接多源插件拉取跨系统数据。数据更新频率高且与构件一一绑定，工具需实时获取最新的浇筑、养护及检测数据，避免使用过期信息。文档结构包含图纸、台账等多种格式，工具需适配不同格式的解析需求。此外，构件与现场吊装位置严格对应，工具调用需准确关联构件ID与现场位置信息，防止出现预埋错位等问题。

## 配置怎么定
本文适配FastGPT v4.17.0版本，以下配置基于该版本的插件与工具调用逻辑：
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| 单次召回上限 | 前10条 | 匹配构件关联的多源数据条目有限，避免冗余信息干扰分析 |
| 最大上下文长度 | 8000 token | 适配构件深化图、养护记录等长文本的解析需求 |
| `toolChoice` | 强制函数调用 | 确保工具调用返回标准化的结构化质量分析字段，仅返回预设的结构化内容 |
| `functionCall` | 启用参数校验 | 确保工具调用的输入参数符合预设的构件标识要求 |
| 超时阈值 | 600秒 | 等待多源数据拉取（BIM系统、试验室检测数据）的合理耗时区间 |
| 历史对话携带开关 | 开启 | 保留构件ID、批次号等关键标识，确保工具调用精准匹配对应数据 |

## 容易做错的三处
- 调用工具后返回空的质量追溯结果。原因是未正确关联构件二维码追溯码与对应数据源的批次字段，导致工具无法匹配到有效数据。
- 调用工作流后对话日志为空。原因是未开启历史对话携带配置，导致工具调用时未携带构件ID、批次号等关键参数。
- 工具调用返回格式不符合预设要求或接收无效参数。原因是未启用`functionCall`参数校验且未设置`toolChoice`为强制函数调用，导致返回非结构化内容或接收错误的构件标识。

## 怎么确认配好了
- 输入已知构件的二维码追溯码，触发工具调用，核对返回结果是否包含对应钢筋批次、养护记录的字段。
- 查看工作流运行日志，确认历史对话中的构件ID、批次号已被正确携带到工具调用参数中。
- 检查工具调用的返回格式，确认符合预设的结构化字段要求。
- 模拟提交新浇筑构件的养护记录，触发工具调用后核对返回数据是否为最新版本。
