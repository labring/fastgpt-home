# 预制混凝土构件的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
该品类数据来自预制混凝土构件工厂的BIM深化设计、钢筋与混凝土批次台账、模台与养护窑运行记录、试验室检测报告及构件二维码追溯系统。日常文档包含构件深化图、钢筋下料单、模具检验记录、浇筑振捣日志、养护周期记录、脱模与出厂检验报告。数据按单件构件、每批次原材料、每窑养护单元更新，字段包含构件编号、原材料批次号、养护时长、强度检测值等，单位涵盖毫米、立方米、小时、兆帕等。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类的多源异构数据、按单件/批次/窑炉的更新节奏，对模型接入与配置带来明确约束。构件深化图、养护记录等长文档需适配长上下文解析，因此需预留足够的上下文窗口；多维度溯源数据（原材料批次、养护记录、检测报告）要求模型能精准关联构件编号与对应信息，需配置支持多源数据关联的检索逻辑；大型单件预制构件的非标准化工程文档，需开启`vision`参数以解析图纸中的预埋位置、尺寸参数；同时因错误后果严重，需配置合理的错误重试机制，避免因单次调用失败导致追溯中断。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本的功能逻辑制定。
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | `8000–12000 token` | 构件深化图、养护记录等多文档拼接后的总长度通常在数千token区间，适配长上下文解析需求 |
| `maxTokens` | `2000–3000 token` | 单轮追溯结果需输出完整的溯源链条与不良分析结论，避免输出截断 |
| `vision` | 开启 | 需解析构件深化图、模具检验图纸中的预埋位置、尺寸参数，识别图纸类异常 |
| `temperature` | `0.1–0.3` | 追溯与分析需保持结果的准确性与一致性，避免随机性导致结论偏差 |
| `AIPROXY_API_ENDPOINT` | 按部署的代理服务实际地址填写 | 匹配模型调用的接入端点，确保请求路由正确 |
| `AIPROXY_API_TOKEN` | 按实际生成的代理令牌填写 | 完成身份校验，避免未授权调用报错 |

## 容易做错的三处
- 调用模型时出现`'KokoroModel' object has no attribute 'mode'`类报错，原因是将非文本分析类模型误接入质量追溯链路，未正确匹配模型功能类型。
- 知识库检索时提示无可调用模型，原因是未在渠道配置中正确绑定目标向量模型，或配置参数未与渠道同步更新。
- 文本提取功能返回空值，原因是未开启`vision`参数以解析带格式的工程文档，导致无法识别有效内容。

## 怎么确认配好了
- 测试调用配置的模型，输入单份构件养护记录，检查是否能正常返回结构化分析结果，确认上下文窗口配置适配输入文本长度。
- 上传一份构件深化图，触发图纸解析任务，检查是否能正常识别图纸中的预埋位置、尺寸参数，确认`vision`参数配置正确。
- 查看模型调用日志，确认请求能正确路由至配置的`AIPROXY_API_ENDPOINT`，且身份校验通过，无未授权报错。
- 输入包含不良现象的追溯问题，检查模型是否能关联对应批次的原材料、养护记录等数据，确认多源数据检索逻辑配置有效。
