# 预拌混凝土生产的质量问题追溯与不良分析：多轮对话与提示词

## 这个品类的数据长什么样
预拌混凝土生产的数据来自工程订单、砂石水泥外加剂检验、含水率测定、搅拌站控制系统与工程项目试验室。日常文档包含配合比通知单、开盘鉴定、生产运输单、原材料检验记录、试块记录与强度报告。数据更新节奏为每车生产批次、每批原料进场、每日汇总统计，字段包含坍落度、含水率、强度等级、发车时间、浇筑部位等，对应单位为毫米、百分比、兆帕、时分制时间、工程部位名称。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
该品类数据按车、批、日更新，多轮对话需精准匹配单次生产或原料批次的上下文，避免跨批次数据混淆。需调用的文档字段多且关联紧密，提示词需明确限定对话上下文仅关联当前工程订单与对应生产批次。试块强度报告需等待龄期验证，多轮对话需支持延迟查询关联数据，同时需处理不同来源数据的格式差异，如搅拌站控制系统的数值型数据与试验室的文本型检验记录。单轮对话需处理的参数数量较多，需通过多轮逐步引导用户补充必要字段，避免一次性输入过载。

## 配置怎么定
本页配置基于FastGPT v4.17.0版本。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 最大上下文 | 前 20 轮对话内容 | 预拌混凝土生产按批次关联数据，20轮可覆盖单订单全生产周期的对话逻辑，避免上下文冗余 |
| `variables` | 绑定工程订单号、浇筑部位 | 该品类核心关联字段为工程订单与浇筑部位，通过变量绑定可快速定位对应生产、检验数据 |
| `messages` | 按生产批次过滤历史消息 | 避免不同批次的生产数据在对话中混杂，确保多轮对话仅关联当前批次的上下文 |
| 单次搜索上限 | 前 8 条匹配数据 | 该品类单批次数据条目较少，8条可覆盖配合比、原料检验、试块记录等核心关联文档 |
| 问题优化 | 开启 | 将用户模糊提问（如「强度不够」）转化为可匹配具体批次、检验报告的精准查询 |
| `chatId` | 绑定当前工程会话ID | 确保多轮对话的上下文仅属于当前工程订单，避免跨会话数据干扰 |

## 容易做错的三处
- 现象：对话返回401 No auth credentials found，原因是未正确绑定`variables`中的会话权限参数，或未配置对应数据源的访问密钥。
- 现象：多轮对话中出现不同工程订单的生产数据混杂，原因是未使用`chatId`绑定当前会话的工程标识，导致上下文跨会话关联。
- 现象：通过HTTP节点获取的BLOB对象无法在对话框中下载，原因是未在`variables`中配置BLOB的下载链接字段，或未开启对话结果的附件展示配置。

## 怎么确认配好了
- 发起包含工程订单号的提问，确认对话上下文仅返回该订单对应的生产、检验数据。
- 测试多轮对话中补充浇筑部位、原料批次等字段，确认`variables`绑定的参数被正确传递到查询逻辑。
- 触发HTTP节点获取BLOB文件，确认对话框中出现可点击的下载按钮。
- 输入模糊提问如「坍落度不对」，确认对话自动优化为匹配当前批次的精准查询。
