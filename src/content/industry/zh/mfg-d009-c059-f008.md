# 预拌混凝土生产的质量问题追溯与不良分析：文档解析与分块

## 这个品类的数据长什么样
预拌混凝土生产的核心数据来自商品混凝土搅拌站控制系统、工程项目试验室、工程订单及原材料检验记录。日常文档包含配合比通知单、开盘鉴定、生产运输单、原材料检验报告、试块记录与强度报告，字段涵盖砂石水泥配比、含水率、坍落度、强度等级等，单位涉及kg/m³、%、mm、MPa等。数据更新频率为每车生产批次、每批原材料进场、每日试验室试验归档。

## 这些特征在「文档解析与分块」这一环带来什么约束
每车更新的生产运输单要求分块逻辑能快速处理高频新增文档，避免分块过大导致解析延迟；文档中大量结构化表格（如配合比表、试块记录）需要精准提取单元格内容，防止分块截断表格行或列；试块强度报告的28天龄期数据需保留前后关联的试验日期、批次信息，避免分块割裂关键上下文；多批次的原材料检验数据需按批次绑定，确保追溯时能关联到对应原料的进场记录。

## 配置怎么定
FastGPT v4.17.0 下的配置项如下：
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 预拌混凝土的单批次文档包含配料、试验的完整参数，该区间可避免截断关键字段，同时保证分块内上下文连贯 |
| `chunkSplitter` | 按段落+表格识别模式 | 文档包含非结构化试验记录与结构化表格，按段落分块保留上下文，表格识别模式可完整提取单元格内的批次信息 |
| `customPdfParse` | 启用pdf-marker解析 | 预拌混凝土的PDF文档多为带嵌套表格的试验报告，该解析模式可准确还原表格结构，避免内容丢失 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 秒 | 单批次完整档案包含多页报告与配料单，解析需较长时间，该区间可避免任务超时 |
| `chunkSettingMode` | 手动配置模式 | 需针对配合比单、试块报告等不同文档类型调整分块参数，适配品类的文档结构差异 |

## 容易做错的三处
- 现象：上传CSV格式的原材料检验表后，检索结果仅返回30余项数据，遗漏剩余批次条目。原因：未启用表格识别模式，默认分块逻辑截断了表格的后续行，未完整提取所有批次的检验参数。
- 现象：调用自定义PDF解析接口时返回404错误，无法找到`/v2/parse/file`路径。原因：未部署v2版本的pdf-marker服务，未在平台配置中开启`customPdfParse`对应的服务映射。
- 现象：批量上传多份生产运输单后，分块结果未按批次关联对应文档。原因：未按照正确的多文件传参格式绑定批次信息，导致分块与原始文档的关联关系丢失。

## 怎么确认配好了
- 上传一份完整的配合比通知单PDF，检查解析后的分块是否完整保留了砂石配比、含水率、坍落度等连续的关键参数，未出现表格拆分或内容截断。
- 查看解析任务的运行日志，确认`PARSE_FILE_TIMEOUT_SECONDS`的配置未触发超时错误，任务最终状态为成功完成。
- 传入3份不同批次的试块强度报告，检查返回的分块结果是否按批次区分，每个分块均包含对应批次的试验日期与强度数据。
- 调整`chunkSize`至1000字符，上传单日的生产汇总文档，确认分块未截断包含当日所有生产批次的连续段落。
