# 预拌混凝土生产的质量问题追溯与不良分析：模型接入与配置

## 这个品类的数据长什么样
该品类的数据主要来自工程订单、砂石水泥外加剂检验记录、骨料含水率测定数据、搅拌站控制系统日志、工程项目试验室试块与强度报告。日常关联文档包含配合比通知单、开盘鉴定表、生产运输单、原材料检验报告、试块留存记录。数据更新节奏按单批原料、每车生产任务、每日试验室检测频次推进，字段包含原料批次号、含水率数值、坍落度指标、试块强度等级、浇筑部位与时间，单位涵盖千克、立方米、兆帕、百分比、秒等。

## 这些特征在「模型接入与配置」这一环带来什么约束
数据的多源分散特性要求模型接入时需兼容不同格式的结构化与半结构化文档，需配置适配多数据源的读取逻辑。高频更新的每车生产数据要求上下文窗口需支持实时增量同步，避免因数据滞后导致追溯偏差。单批次原料与试块的强关联属性，要求模型在召回关联数据时需精准匹配批次号与浇筑时间字段，需限制无关数据的混入。试块强度需龄期验证的特性，要求模型配置中需保留历史数据的长期存储索引，避免因数据过期丢失追溯依据。

## 配置怎么定
本文基于FastGPT v4.17.0版本的配置逻辑编写。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | 适配单车生产数据+多批次原料检测记录的总长度，覆盖单次追溯所需的全部关联文档 |
| `maxTokens` | 4000 token | 限制单轮回答的输出长度，避免因冗长分析超出质量管理人员与调度人员的阅读效率 |
| `quoteMaxToken` | 1500 token | 限定召回引用的文档总字符数，匹配预拌混凝土生产中核心关联数据的典型长度 |
| `temperature` | 0.2–0.4 | 降低随机性，确保质量追溯结果的一致性，避免因波动导致的分析偏差 |
| `AIPROXY_API_ENDPOINT` | 按部署环境填写 | 适配本地或云端的模型调用地址，保障数据传输的安全性与稳定性 |
| `AIPROXY_API_TOKEN` | 按权限分配生成 | 限制模型调用的访问权限，防止未授权的质量数据查询操作 |

## 容易做错的三处
- 现象：reranker模型启动失败，控制台返回连接超时错误。原因：未正确配置`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`，导致模型调用链路中断。
- 现象：通过iframe集成的聊天窗口无法获取模型返回的输出内容。原因：未配置前端回调接口，未绑定模型输出的监听事件，导致数据无法同步到父页面。
- 现象：模型调用显示的token消耗与实际API账单存在差异。原因：未正确设置`maxContext`参数，导致召回的冗余数据被计入上下文token统计，与实际模型处理的token量不匹配。

## 怎么确认配好了
- 执行单批次原料的追溯测试，核对模型返回的关联文档是否包含正确的配合比通知单与含水率测定数据。
- 发起包含坍落度异常的分析请求，核对模型输出的分析逻辑是否匹配预拌混凝土生产的业务流程。
- 查看模型调用日志，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`的配置未出现格式错误。
- 测试iframe集成的聊天窗口，确认发起查询后能正常接收并展示模型返回的分析结果。
