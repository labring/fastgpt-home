# 饮料与瓶装水的质量问题追溯与不良分析：向量模型与索引

## 这个品类的数据长什么样
该品类的核心数据来自碳酸、果汁、茶饮、功能饮料及包装饮用水工厂的多系统，包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验、成品检验等文档。数据采集覆盖水源与原料检测、配方系统、在线糖度酸度监测、灌装设备、视觉检测及LIMS系统，更新节奏为每批、每班或连续采集，字段包含糖度、酸度、灌装液位、封口参数、产品批号等，部分数据带实时监测单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
该品类数据的多源、高频更新与批次关联特征，对向量模型与索引环节带来多重约束。多源数据包含结构化监测值与非结构化检验文本，需适配混合数据的向量生成逻辑；每批、每班的高频更新要求索引支持增量同步，避免全量重建的耗时；包装切换频繁导致产品批号关联数据量大，需优化索引的分组检索效率；实时在线监测数据的短周期更新，要求检索延迟控制在可接受范围，保障不良分析的时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| 分块长度 | 800–1200 字符 | 适配该品类单份文档（如单批水处理记录）的平均长度，覆盖完整业务节点信息 |
| 重叠长度 | 100–150 字符 | 避免批次关联数据被拆分导致的上下文断裂，保障检索连贯性 |
| `defaultToken` | 按代表性样本文档实测设置 | `defaultToken` 是直接文本分块使用的默认 token 数，请用本品类代表性原文实测调整；参见 [FastGPT v4.17.2 模型字段说明](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx)。它不表示向量维度、嵌入模型输入上限或检索/LLM 上下文。 |
| `maxToken` | 4096 | 适配单批次全量检验记录的文本长度，避免截断关键信息 |
| 相似度阈值 | 0.75–0.85 | 区分正常生产数据与异常不良数据的匹配度，适配该品类的检验误差范围 |
| 单次搜索上限 | 前20条 | 覆盖单批次内的关联异常记录，满足不良分析的复核需求 |

## 容易做错的三处
- 现象：使用bge-large模型导入文本数据时，出现分段丢失的异常。原因：未调整分块长度与重叠长度参数，导致长文档的批次关联信息被截断。
- 现象：本地部署时多块3090显卡无法被全部调用，检索任务仅使用单张显卡资源。原因：未在部署配置中指定显卡调度规则，默认仅启用单张显卡。
- 现象：配置百度embedding-v1作为向量模型时返回404错误，无法生成有效向量。原因：未正确配置模型的接口地址与权限参数，导致无法调用目标embedding服务。

## 怎么确认配好了
- 在FastGPT v4.17.0的控制台中，导入单份典型文档（如单批成品检验记录），检查向量生成的token数量是否符合`maxToken`的配置范围。
- 发起针对特定产品批号的检索请求，核对返回结果的数量是否匹配单次搜索上限的配置。
- 查看部署日志，确认向量模型的硬件资源被正常调用，无资源占用异常。
- 模拟异常数据的检索，检查相似度匹配结果是否符合预设的阈值逻辑。
