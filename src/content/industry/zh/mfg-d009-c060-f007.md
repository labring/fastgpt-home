# 饮料与瓶装水的质量问题追溯与不良分析：数据库与运维

## 这个品类的数据长什么样
该品类数据覆盖碳酸、果汁、茶饮、功能饮料及包装饮用水工厂的全流程，日常文档包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验记录、成品检验记录。数据来源包括水源与原料检测结果、配方系统数据、在线糖度酸度监测数据、灌装设备日志、视觉检测结果、LIMS系统数据。数据更新节奏为每批、每班或连续采集，字段包含投料参数、水质指标、灌装液位、封口强度、批号、保质期等，单位涵盖mg/L、%、mm、天等，且需同步关联包装与配方信息。

## 这些特征在「数据库与运维」这一环带来什么约束
该品类的连续采集设备数据、多源异构记录与批次化更新节奏，会对数据库运维带来多重约束。高速在线监测的实时数据会产生高频写入请求，需配置读写分离架构分担压力；按批号关联的批次数据要求建立按批次号的二级索引，确保质量追溯时可快速定位单批次全链路信息。多来源的理化、设备、LIMS数据需统一字段映射规则，避免跨源查询出现字段不匹配问题。频繁的产品切换要求数据库支持动态分区或快速表结构调整，适配不同品类的配方与检验字段差异。微生物污染相关的历史数据需保留足够时长，且需支持按时间范围快速检索。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://fastgpt:securepass@db-host:27017/fastgpt_db?maxPoolSize=60` | 存储设备日志、视觉检测结果等非结构化或半结构化数据，适配高并发写入需求 |
| `PG_URL` | `postgresql://lims_user:limspass@pg-host:5432/lims_db?sslmode=disable` | 存储配方单、检验记录等结构化批次数据，支持复杂关联查询 |
| `DB_MAX_LINK` | `60–100` | 适配每批、每班的批量数据写入与实时监测的并发请求，避免连接耗尽 |
| `REDIS_URL` | `redis://:redispass@redis-host:6379/0?maxmemory=1000 MB` | 缓存高频查询的批次信息与在线监测的实时数据，降低数据库读写压力 |
| 批量写入阈值 | 单批次不超过4000条 | 适配饮料工厂单批的检验记录与设备日志总量，避免单次写入超时 |

本文基于FastGPT v4.17.0版本编写。

## 容易做错的三处
- 现象：Docker部署时数据库持续高写入，硬盘占用快速增长，甚至触发硬盘空间耗尽报错。原因：未配置`DB_MAX_LINK`限制连接池大小，导致大量并发请求创建数据库连接，触发高频磁盘读写。
- 现象：Milvus部署容器启动失败，提示PG数据库连接认证错误。原因：误将非向量库的PG配置写入Milvus compose文件，未按品类需求仅配置必要的向量库与关联存储组件。
- 现象：批次追溯时无法找到对应配方数据，检索结果字段为空。原因：未统一多源数据的字段映射规则，导致LIMS系统的配方字段与FastGPT存储字段不匹配。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGODB_URI`、`PG_URL`的连接状态正常，无认证或地址错误。
- 模拟单批次数据写入，检查写入耗时与存储占用符合预期，确认`DB_MAX_LINK`的连接数未触发耗尽。
- 检索历史批次数据，验证多源数据的字段映射正确，可正常关联配方、检验与设备日志信息。
- 查看Redis缓存监控，确认高频查询的数据已被缓存，数据库读写压力符合配置预期。
