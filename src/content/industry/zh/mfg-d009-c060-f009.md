# 饮料与瓶装水的质量问题追溯与不良分析：模型接入与配置
本文基于FastGPT v4.17.0版本的功能逻辑编写。

## 这个品类的数据长什么样
该品类数据来自水源与原料检测、配方系统、在线糖度酸度监测、灌装设备、视觉检测系统及LIMS系统。日常文档包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验报告、成品检验报告。数据更新节奏为每批生产、每班巡检及连续在线采集，字段包含投料量、浊度、灌装液位、封口压力、批号、保质期等，对应单位涵盖千克、NTU、毫米、千帕、天等。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据且更新节奏差异显著，连续在线采集的高频数据需适配高频率的接口调用，批次数据需按生产批次建立关联索引，模型接入需支持多源结构化数据的映射规则。日常文档类型多样，不同文档的字段与单位存在差异，配置时需明确各文档的提取逻辑，避免单位转换错误。产品切换频繁导致数据批次跨度大，模型上下文需适配多批次数据的关联查询，同时需限定检索范围覆盖对应生产环节的数据集，确保不良分析的精准性。无菌灌装与水处理的关键数据要求高置信度关联，配置时需避免无关数据的干扰。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | `http://localhost:11434/v1` | 适配本地ollama部署的大模型标准接口路径，符合本地模型调用的通用格式 |
| `AIPROXY_API_TOKEN` | `空字符串` | 多数本地部署的ollama模型无需身份验证，留空即可完成基础调用 |
| `maxContext` | `8000–12000 token` | 适配饮料生产多批次关联数据的上下文长度，覆盖单班生产的核心记录数据 |
| `temperature` | `0.1–0.3` | 确保不良分析与追溯结果的一致性，避免因随机性导致的分析偏差 |
| `quoteMaxToken` | `1500–2000 token` | 限定检索返回的文档片段长度，匹配配方、检验记录的单条文档字符量 |
| 工作流/API 工具选择配置 | `auto` | 允许模型自主选择是否调用检索工具，适配多源数据的关联分析需求 |

## 容易做错的三处
- 调用本地ollama部署的模型时返回连接失败报错，界面提示无法解析接口地址。原因是未正确配置`AIPROXY_API_ENDPOINT`参数，将本地地址填写错误或遗漏端口号。
- 输入英文prompt并要求英文输出时，模型仍返回中文结果。原因是未匹配本地部署模型的语言默认设置，且未在配置中强制指定输出语言规则。
- 检索返回的文档片段过短，无法覆盖完整的生产批次记录。原因是未合理设置`quoteMaxToken`参数，取值区间过小导致截断关键信息。

## 怎么确认配好了
- 测试调用本地模型接口，查看返回的响应状态码为200，确认`AIPROXY_API_ENDPOINT`与`AIPROXY_API_TOKEN`配置正确。
- 输入预设的英文prompt，验证模型输出语言与要求一致，确认语言相关配置生效。
- 上传单条生产批次的文档，检索返回的片段长度符合预期，确认`quoteMaxToken`配置合理。
- 模拟多批次数据的关联查询，查看模型返回的结果覆盖对应生产环节的记录，确认`maxContext`配置适配数据规模。
