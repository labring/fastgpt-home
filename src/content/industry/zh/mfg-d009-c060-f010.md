# 饮料与瓶装水的质量问题追溯与不良分析：知识库检索与召回

## 这个品类的数据长什么样
该品类数据覆盖碳酸、果汁、茶饮、功能饮料及包装饮用水工厂的生产全流程。日常文档包含配方单、水处理记录、调配记录、杀菌或无菌灌装记录、包材检验与成品检验表单。数据来源涵盖水源与原料检测、配方系统、在线糖度酸度监测设备、灌装设备、视觉检测系统及LIMS系统。更新按生产批次、每班或连续采集，每份记录关联唯一生产批次号，包含批次号、时间戳、检测数值、设备编号等字段。

## 这些特征在「知识库检索与召回」这一环带来什么约束
按批次归档的结构化数据要求检索需优先匹配批次号字段，避免跨批次无关结果干扰。高频更新的连续采集数据要求知识库需支持增量同步，避免数据滞后。多品类切换带来的文档多样性，要求检索需覆盖不同配方、设备参数的关联记录。单批次关联多份检测记录的特征，单批次关联的文档数量通常在5-15份之间，要求召回结果需按批次聚合，避免分散的零散条目。同时，检测数值的精确比对需求，要求检索需兼顾语义匹配与数值字段的精准匹配逻辑。

## 配置怎么定
以下配置基于FastGPT v4.17.0版本适配。
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | 匹配批次号等精确字段的同时，覆盖配方、检测记录的语义关联 |
| `limit` | `前10–15条` | 单批次关联多份记录，平衡召回覆盖范围与检索响应速度 |
| `searchMode` | `mixedRecall` | 兼顾语义匹配与批次号、设备编号等关键词字段的精准匹配 |
| `usingReRank` | `开启` | 过滤高频更新的冗余检测记录，聚焦与质量问题直接相关的文档 |
| `datasetSearchUsingExtensionQuery` | `开启` | 自动扩展质量问题相关的关键词，覆盖不同品类饮料的配方术语 |
| `collectionIds` | `按生产批次绑定的知识库集合指定` | 限定检索范围，避免跨批次无关数据干扰召回结果 |

## 容易做错的三处
- 检索结果混杂多个生产批次的文档，且部分请求返回权限不足提示。原因是调用知识库API时使用了通用鉴权KEY，未绑定对应生产批次的知识库集合，导致检索范围超出预设权限。
- 导入修改后的csv知识库数据时触发训练报错，系统返回字段格式不匹配的提示。原因是未按目标FastGPT版本的csv模板调整批次号、检测数值等必填字段，比如将v4.9.2导出的旧格式数据直接导入v4.12.1版本。
- 检索高批次数据时仅返回少量结果，无法覆盖当前批次的全部检测记录。原因是本地部署的知识库搜索模块引用上限未按数据更新频率调整，导致结果截断。

## 怎么确认配好了
- 输入目标生产批次号作为检索关键词，核对返回结果是否仅包含该批次关联的文档。
- 触发一次增量同步，核对知识库是否按生产批次更新了最新的水处理、灌装记录。
- 查看检索日志，确认`usingReRank`和`datasetSearchUsingExtensionQuery`已生效，无冗余结果。
- 调整`similarity`参数，核对不同阈值下的召回结果是否符合预期的匹配精度。
