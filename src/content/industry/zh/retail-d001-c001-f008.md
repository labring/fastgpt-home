# B2B平台撮合交易的商品资料与选型问答：工作流编排

## 这个品类的数据长什么样

在B2B平台撮合交易的商品资料与选型问答中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

B2B平台的选型问题，常把供应商身份与商品说明放在同一次提问里。可先编一条普通文字测试记录：“企业资料已提供经营范围，报价材料给出型号，尚无该型号的用途限制说明。”工作流需要接收的是这几项文字及各自出处。表单提交后，逐项核对后续阅读步骤收到的内容，检查供应商名称有没有被当成商品型号，企业经营范围有没有被误写成商品技术能力。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 身份与商品分开 | 经营范围来自企业资料，型号来自报价材料 | 后续输入保留两种出处，没有互换含义 |
| 表单传值 | 型号原文及尚缺的用途限制说明 | 提交值与阅读步骤收到的文字对应 |
| 选项去向 | 补厂家规格，或只看现有报价描述 | 两个选择进入各自已连接路径 |
| 补充后复测 | 新增规格资料及原选型问题 | 答复引用新依据，未知项没有被猜补 |
| 外部业务 | 拟接库存或采购服务的真实契约 | 单独检查权限、响应及业务记录 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

若采购方追问该型号能否用于某项业务，应先明确还需要哪类商品依据，再设计人员选择的处理路径。例如，“补充厂家规格”与“只查看现有报价描述”意味着不同的后续输入。分别验证选项连接和实际接收值，不能让后一条路径生成前一条所缺的事实。资料负责人选择继续阅读，也不构成供应商资格、产品适用性或采购准入已经核定。 若企业经营范围被选型答复写成产品认证，应分别回查企业资料和型号说明所述对象；企业身份依据不提供商品认证，缺产品原文时撤去该项结论。

## 怎么确认配好了

验收可沿着原问题、提交文本、下一步输入和最后答复逐段回查：已有型号描述是否被准确承接，缺少的用途限制是否仍清楚列明。取得新规格资料后，再使用同一个问题检查来源变化。若流程还要查库存、生成采购申请或写入外部系统，应另外验证接口授权及真实业务返回；选型问答结束只表明本次交互完成，不证明交易动作已经发生。
