# B2B平台撮合交易的商品资料与选型问答：文档解析与分块

## 这个品类的数据长什么样

在B2B平台撮合交易的商品资料与选型问答中，本页说明FastGPT的文档解析与分块如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「文档解析与分块」这一环带来什么约束

B2B商品选型可用一段新拟询报价文字检查条件是否被拆散：“型号P采用接口甲；只有选购模块乙，才提供功能丙。”解析后的内容需要能回指型号、接口和这项条件。若功能丙被分成孤立短句，后续检索可能只取到功能名称，阅读者就看不到选购前提。先对照原文与解析输出，再用“型号P是否提供功能丙”检查取回片段，不预设任何分块长度。接口、选购项和功能分别属于这段自拟询报价，不能被概括成FastGPT的软件配置。验收时应保留其业务材料身份，检查问答实际取回的仍是同一条说明。

## 配置怎么定

| 核对项（含实施核对） | 本题输入或条件 | 回查线索 |
| --- | --- | --- |
| 解析输出 | 型号P、接口甲、模块乙和功能丙 | 确认选购前提未与功能文字分离。 |
| 条件完整性 | 只有选购模块乙才提供功能丙 | 自然问法需取回限制及被约束功能。 |
| 原数据与索引 | 新旧两份询报价各自留身份 | 不能将索引概括当成原文承诺。 |
| 样本检索 | 原词查询与型号功能问答 | 分别检查返回的实际原数据。 |
| 更新后复核 | 技术附图原来未提供 | 补入后核解析、训练及索引状态。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `原始资料核对` | 对照原文件与解析输出。 |
| `分段完整性` | 条件需与其主体保持可关联。 |
| `数据与索引` | 原数据与索引分别保留依据。 |
| `样本检索` | 用原文词句及自然问题复测。 |
| `更新后复核` | 更新后核训练或索引状态。 |

## 容易做错的三处

另拟一份旧询报价附页，单独写“功能丙为可选项”。这与新文字的关系需先核版本，不能在解析时合并成所有型号都带此功能。检查两份原数据是否保留各自身份，索引所作概括有没有遗漏“可选”或“只有”的限制。即使检索返回了索引文字，也要回到原数据确认实际出处，不能把搜索用短语当成报价原文或供货承诺。

## 怎么确认配好了

若询报价只提到“接口条件详见技术附图”，当前输入却没有附图，应先登记缺少哪份来源。解析正文不能生成图中未提供的规格，也不能因文件上传结束就验收问题已能回答。补入实际资料后，分别检查解析输出、训练或索引状态，再问同一选型问题，核对新增条件是否可回查；若原文已有而解析遗漏，保留具体原句及失败输出。
