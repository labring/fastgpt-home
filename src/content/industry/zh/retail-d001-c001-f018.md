# B2B平台撮合交易的商品资料与选型问答：重排与混合检索

## 这个品类的数据长什么样

在B2B平台撮合交易的商品资料与选型问答中，本页说明FastGPT的重排与混合检索如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「重排与混合检索」这一环带来什么约束

B2B选型问题要先分开“商品描述能否找到”和“供应主体是否具备资格”。自拟询报价单写有型号参数，认证资料写有经营范围，可将这两处原文标为本题所需候选。检查混合检索经RRF融合后是否同时保留它们，再观察完整问题下的重排次序。型号文字与经营范围接近，只能提供阅读线索，不能据此认定实际供货能力。测试记录可把“已找到型号说明”与“尚需资格核验”分列，明确一个问题已经取得哪类原文。这样返回报价并不会被误记为已完成供应主体审核。

## 配置怎么定

| 核对项（含实施核对） | 本题输入或适用条件 | 回查与验收线索 |
| --- | --- | --- |
| 融合候选 | 询报价单的型号说明；认证资料的经营范围 | 分别保留两份原文，检查双方是否进入候选。 |
| 完整问题 | 核对型号描述与经营范围文字，不直接认定供货资格 | 查看送入重排的问题是否保留两个阅读对象。 |
| 最低相关度 | 仅在语义检索或结果重排时生效 | 比较过滤前后经营范围片段是否仍可见。 |
| 引用token上限 | 型号条件与经营范围都需留在引用中 | 不能只留下报价名称而删掉范围限制。 |
| 缺资料复测 | 定制化功能尚无详细规格附件 | 补充规格后重复原题，追踪新增出处。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `混合检索` | 向量与全文结果通过RRF融合。 |
| `结果重排` | 按完整问题对候选再次排序。 |
| `最低相关度` | 过滤仅在语义或重排时生效。 |
| `引用上限` | 按token裁剪引用内容。 |
| `问题优化` | 比较优化前后主体与限制。 |

## 容易做错的三处

另一个自拟样例中，报价涉及的商品类别没有出现在认证资料的范围内。此时需要比较两个不同出处，不能把排位靠前的一段当成对方材料也采用的表述。保存排序前后的候选清单，查看经营范围这一侧是否最初就未召回，或在后续筛选中消失。即使两段均被引用，是否适用于该笔采购仍需另外核对主体、版本及所需资格依据。

## 怎么确认配好了

定制化功能问题则只提供了询报价单，缺少详细技术规格。重排可以改变现有报价文字的次序，无法提供尚未收到的规格附件。可先记录这道问题缺少的来源，再补入真实规格并重复原问题，逐项检查候选、过滤、排序和最后引用。最低相关度按语义检索或重排的生效条件核对，验收对象是所需规格能否回查，不能只看相关度数字。
