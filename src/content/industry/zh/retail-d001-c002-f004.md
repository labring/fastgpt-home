# MCN机构达人管理的商品资料与选型问答：向量模型与索引

## 这个品类的数据长什么样

在MCN机构达人管理的商品资料与选型问答中，本页说明FastGPT的向量模型与索引如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

MCN商品索引可以从一段新拟合同文字开始：“本场只演示清单中的护肤品；赠品以当次排期为准。”拟议搜索入口可以分别指向演示范围和赠品依据，但原数据本身没有列出赠品名称。核对每个索引所指原文时，应明确第一问能读到哪些范围，第二问还需哪份资料；同一原数据有多个索引，并不表示它已经包含所有被问到的商品信息。两个搜索入口也要核各自所支持的说法，不能因为均能命中同一合同，就认为赠品已经被列明。合同中的排期指向仍需实际排期内容承接。

## 配置怎么定

| 核对项（含实施核对） | 具体原数据或索引 | 验收线索 |
| --- | --- | --- |
| 关联模型 | 合同与排期若分库关联同一检索节点 | 核该节点关联库使用相同向量模型。 |
| 原文映射 | 合同只写演示范围及排期指向 | 每个索引回到其实际原句。 |
| 索引内容 | 演示范围与赠品依据两个入口 | 不能把演示改写成赠送。 |
| 同题复核 | 分别问演示物及赠品 | 注明现有资料能支持哪一问。 |
| 图片入库 | 缺少的排期清单若为图片 | 先核实际处理方式，再核对应输出与引用。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

第一处是拟议入口写“本场赠送的护肤品”，却只对应合同演示范围。应逐词比较索引与合同，核赠送说法是否无依据新增。第二处是取得排期清单后，赠品入口仍回到旧演示段；应核新清单原数据与入口目标，再看实际引用是否采用了清单，不能用已取得文件代替映射检查。第三处是清单来自图片就被当成已可检索。应先核实际处理方式：文字路径对照提取内容，只有实际图片检索才核描述或图片向量，再验证赠品问题引用；文件外观不能证明处理链已生效。

## 怎么确认配好了

排期清单未提供时，商品索引缺少赠品这一侧的原始来源。补充资料后，需核新增原数据与其索引的对应关系，并用原问题比较引用变化；不能只登记多了几个索引。若清单来自图片，先核实际采用的处理方式；走文字解析时对照提取文字与原清单，仅在实际图片检索路径中检查描述或图片向量，再追查提问引用。索引覆盖与资料授权分别确认，不由商品相关度认定已获推广许可。若清单补入后，同一赠品问题仍只引用旧合同，应同时核新增原数据是否存在、索引指向及实际候选，不能先断言重建已生效。把新增清单原句与本次返回并列，确认是未读取新来源、入口映射错误，还是返回中遗漏了该依据。
