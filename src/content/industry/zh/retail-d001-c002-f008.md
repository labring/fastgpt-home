# MCN机构达人管理的商品资料与选型问答：工作流编排

## 这个品类的数据长什么样

在MCN机构达人管理的商品资料与选型问答中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

MCN的商品问答可以先限定在“合同列出的可推广品类”这一阅读任务，避免把它扩大成对具体商品的全面推荐。自拟测试材料写明合同涉及美妆品类，排期记录另列某场直播内容。表单可收集合同原句、资料版本与本次问题，并传向后续核对步骤。这里收集的是已有文字，不表示系统已经审查商品成分、宣传用语或达人推广权限。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 限定问题 | 合同的可推广品类原句 | 回答没有扩展成商品全面推荐 |
| 提交内容 | 合同版本、原文与当前问题 | 后续步骤收到同一组资料身份 |
| 分支检查 | 补合作说明或回查合同范围 | 选择值与接收路径一一对应 |
| 型号资料缺口 | 品类范围之外的具体推广依据 | 补充前保留未知，补充后回查引用 |
| 排期或发布 | 业务负责人确认及实际操作记录 | 对话完成与外部动作分别验收 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

排期中的直播内容与合同品类描述不同，应先核对是否对应同一达人、同一合作范围及适用版本，再决定下一步。可分别设计“补充该场合作说明”和“回查合同范围”的人工选择，检查选项实际传到了哪个接收步骤。不能让分支选择直接修改合同含义，也不能把某个品类名称当成具体商品型号已经获准推广的凭证。 还可把另一达人的排期与当前合同并列，测试流程会不会把两人的合作范围混在一起。发现答复引用错人时，回看提交记录中的合作对象及引用段落，先移出无对应依据的排期，再要求补本次合作说明。资料之间能否对应，需要文字核实，不能从同属一个机构推定。

## 怎么确认配好了

如果问题进一步涉及某型号的推广限制，而现有材料只有品类范围，就要明确要求提供相应商品资料或合作依据。分别观察缺资料时的等待、补充后的传值以及最后引用，确认答复没有把宽泛品类扩写为商品承诺。账号排期更新、合同审批或对外发布如需执行，应另有实际业务流程与结果检查，不能从本次表单提交推定已经完成。
