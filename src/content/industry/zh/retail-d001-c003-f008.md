# Shopify独立站订单履约的商品资料与选型问答：工作流编排

## 这个品类的数据长什么样

在Shopify独立站订单履约的商品资料与选型问答中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟订单详情列有“夏季限定T恤”、L码、蓝色和一件，这些文字可作为工作流输入承接的检查样本。若由人员通过表单录入，应分别比较提交前的四项内容和后续节点收到的值，检查商品名称、尺码与数量有没有串位。此处验证的是信息传递；是否适合某种用途、材质是什么，都需要另有商品依据，不能由字段齐全直接推出。

## 配置怎么定

| 实施核对项 | 本题输入 | 验收线索 |
| --- | --- | --- |
| 表单输入 | 订单详情中本题需要的文字：订单详情附页中“商品名称”、“尺码”、“颜色”和“数量”字段 | 提交后的值仍能回查这份原文；不把填写完成当作业务审核。 |
| 后续传值 | 订单详情附页中“商品名称”、“尺码”、“颜色”和“数量”字段 | 比较收集值与下一步实际输入，保留材料身份与原文含义。 |
| 选择分支 | 围绕订单详情、发货标签核对：订单详情与发货标签附页中“商品描述”字段的差异 | 选项只决定已连接的处理路径，分别测试真实去向。 |
| 缺项补充 | 订单详情尚待核对的依据：尚缺商品材质、洗涤说明等详细资料，无法回答相关问题 | 指定资料提供者与接收步骤，分别观察等待和提交后的输入。 |
| 业务接收 | 本题候选来源：Shopify Admin、支付网关、承运商系统、库存地点数据 | 如需外部读写，先确认接口及授权，再验真实返回和业务记录。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

订单详情写“冬季毛衣”，发货标签写“春季外套”，先要保留两份材料各自的商品描述和身份。流程可以连接补原文、继续核对或交给资料负责人的选择路径，并逐项测试选项实际去了哪里；差异如何发现、材料能否比对，需要另有实现和判断。不能因操作人员选了一条分支，就认定发错商品或认定其中一份记录正确。 若文字核对结束就把订单写成已更正，还需另查实际订单修改接口的授权、返回与对应记录；本次分支输出没有这项回执时，应保留待办理状态。

## 怎么确认配好了

订单名称和数量不足以回答材质、洗涤说明等选型问题。应明确由哪个商品资料来源补充，验证等待输入、提交后的值以及回答步骤实际使用的文本。对于原文仍未说明的属性，保留缺项并检查回答有没有自行补写。若下一步还需更新商品系统，应另核接口权限、真实返回和业务记录，不能把问答或表单完成当作资料已经回填。
