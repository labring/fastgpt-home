# Shopify独立站订单履约的商品资料与选型问答：重排与混合检索

## 这个品类的数据长什么样

在Shopify独立站订单履约的商品资料与选型问答中，本页说明FastGPT的重排与混合检索如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「重排与混合检索」这一环带来什么约束

Shopify商品问答可先用订单附页中已写明的四项内容验证排序：夏季限定T恤、L码、蓝色和一件。这组自拟文字能回答购买内容，却不能说明商品材质或适用人群。检查混合检索候选是否保留商品名称与对应属性，再用包含尺码和颜色的完整问题重排；属性一旦脱离所指商品，即使排位靠前也不能作为本题依据。尺码、颜色与数量属于订单文字，材质和洗护属于另一组商品依据。核对清单应保留这一区别，避免因为前四项都能回查就把后两项也当成已有资料。

## 配置怎么定

| 核对项（含实施核对） | 本题输入或适用条件 | 回查与验收线索 |
| --- | --- | --- |
| 融合候选 | T恤名称与L码、蓝色、一件的对应关系 | 检查属性是否仍指向同一订单商品。 |
| 完整问题 | 订单的冬季毛衣与标签的春季外套 | 保留两个描述及对应材料身份。 |
| 最低相关度 | 仅按语义检索或重排的生效条件检查 | 过滤后仍需核订单与标签双方覆盖。 |
| 引用token上限 | 商品名称、尺码与颜色不能相互拆离 | 回查引用是否遗漏L码或蓝色。 |
| 缺资料复测 | 材质和洗涤说明不在订单附页中 | 补对应商品资料，禁止借入其他款式属性。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `混合检索` | 向量与全文结果通过RRF融合。 |
| `结果重排` | 按完整问题对候选再次排序。 |
| `最低相关度` | 过滤仅在语义或重排时生效。 |
| `引用上限` | 按token裁剪引用内容。 |
| `问题优化` | 比较优化前后主体与限制。 |

## 容易做错的三处

订单写冬季毛衣、发货标签写春季外套的样例，应先保留两个商品描述的来源。排序检查需要确认双方片段都已召回，并观察最终引用是否把两个名称混写成同一商品。文本不同本身还不足以认定实际错发，需再核是否同一订单及所用版本。重排只处理已有候选，缺少标签这一侧时，应先查召回范围，不能只换排序模型。

## 怎么确认配好了

订单附页只有名称和数量时，询问材质或洗涤方法仍缺商品说明。先查看回答有没有从其他款式的片段借入属性，再补充对应商品资料复测。把同一问题在补资料前后的候选及引用并排保存，可以检查证据何时进入链路；过滤阈值按实际生效条件核对，不能用一个更高分数替代尚未取得的材质或洗护依据。
