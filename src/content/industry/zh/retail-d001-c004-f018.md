# Temu半托管卖家运营的商品资料与选型问答：重排与混合检索

## 这个品类的数据长什么样

在Temu半托管卖家运营的商品资料与选型问答中，本页说明FastGPT的重排与混合检索如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「重排与混合检索」这一环带来什么约束

Temu半托管的商品资料测试，先围绕申报表中确有的名称和分类找候选。自拟表格还包含商品描述，但“内部规范是否满足”需要对应的规则依据，不能由字段存在直接推定。可用名称查询和分类问法分别检查初始召回，再将完整核对问题交给重排，观察较长描述有没有挤掉本题需要的分类文字，分别记录召回和次序变化。

## 配置怎么定

| 核对项（含实施核对） | 本题输入或适用条件 | 回查与验收线索 |
| --- | --- | --- |
| 融合候选 | 商品申报名称、分类及价格申报中的型号 | 分别回指申报表与价格申报原文。 |
| 完整问题 | 标准型号与升级型号是否为同一对象 | 保留型号限定，不改写成统一规格。 |
| 最低相关度 | 语义或重排下核实际过滤行为 | 检查型号片段是否在过滤前已存在。 |
| 引用token上限 | 型号描述需保留对应商品和资料条件 | 不能只留“升级”而丢失其来源。 |
| 缺资料复测 | 申报表没有质量检测报告或状态 | 检测依据另补，不从分类字段推定通过。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `混合检索` | 向量与全文结果通过RRF融合。 |
| `结果重排` | 按完整问题对候选再次排序。 |
| `最低相关度` | 过滤仅在语义或重排时生效。 |
| `引用上限` | 按token裁剪引用内容。 |
| `问题优化` | 比较优化前后主体与限制。 |

## 容易做错的三处

申报表写标准型号，价格申报写升级型号时，检查重点是两个型号描述是否仍与各自材料对应。候选应分别回查到商品申报和价格申报，不能因价格片段更接近提问就默认为商品型号已经升级。若只有一份材料被召回，先核数据范围；两边都在候选中，再观察重排及引用裁剪是否使其中一方的限定条件丢失。

## 怎么确认配好了

是否通过内部质量检测是另一道证据问题。现有自拟申报表没有检测状态或报告，商品分类的高相关片段也不能代替检测凭证。补充实际报告前，验收应检查回答是否把“已申报”写成“已检测”。取得对应来源后，用原问题重复测试并保存新增候选及引用；型号、分类和检测结果需各自有材料支持，不能由排序合并成一个结论。申报字段填写齐全与已具备检测证据是不同检查对象，候选清单应分别记录。商品名称、分类都能被取回时，仍要注明检测报告是否实际进入本题输入。
