# 一般贸易进口报关的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

一般贸易进口报关围绕完税价格、运保费与税费缴纳展开，每单产生进口报关单、商业发票、装箱单、提单与合同。商品资料与选型问答要在这批材料上回答归类、规格与申报要素问题，因此模型接入的第一件事是让语言模型与索引模型可用，系统至少需要一个语言模型和一个索引模型。资料每单更新，配置核对随每单材料走，不引入批量同步或实时触发。

## 这些特征在「模型接入与配置」这一环带来什么约束

从 V4.17.0 起 AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 都必须设置 `AIPROXY_API_ENDPOINT` 和非空 `AIPROXY_API_TOKEN`，缺少任一项启动校验失败，旧 OpenAI 环境变量或单模型自定义请求地址不能替代。模型 ID 是请求 Body 中 `model` 字段的值，全局唯一；模型渠道决定上游协议；模型映射把 FastGPT 请求的模型映射到上游实际模型，例如 `gpt-4o-test` 映射到 `gpt-4o`。检索是召回过程，不承担权限或实体隔离。

假设演练样本：某报关行关务经理在 2026 年 3 月 2 日核对一批进口不锈钢板材的申报资料。商业发票原文为「发票号 INV-2026-0302，成交方式 CIF，发票总价 USD 48,000，价格术语载明运费与保险费由卖方承担至上海港」。装箱单原文为「共 12 托盘，毛重 18,600 千克，净重 18,200 千克」。拟稿句为「本票货物成交方式为 CIF，运费与保险费已含在发票总价内」。待判定交接请求为「请确认该批板材的申报要素是否可直接引用发票与装箱单内容」。上述主体、对象、状态与日期范围仅用于本次纸面核对。

## 配置怎么定

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写 AI Proxy 服务根地址，不附加 `/v1` | 与部署实际地址逐字比对 |
| `AIPROXY_API_TOKEN` | 与服务端一致的非空管理员 Token | 确认非空且与 AI Proxy 配置一致 |
| 语言模型 | 启用一个支持工具调用的模型 | 在模型测试页发起一次请求并看返回 |
| 索引模型 | 启用一个索引模型并核对 `maxToken` | 比对模型配置中的最大 token 字段 |
| 模型映射 | 将 FastGPT 模型 ID 映射到上游模型 | 核对映射 JSON 的键值对应关系 |
| 模型探测 | 按 5～60 分钟整数设置探测间隔 | 在模型探测页保存后查看状态图 |

起点数值仅为本页假设试验所用，不是官方默认值。

## 容易做错的三处

1. 把 `AIPROXY_API_ENDPOINT` 写成带 `/v1` 的完整请求地址。输入为根地址加 `/v1` 的配置串，比较对象为文档要求的服务根地址，观察结果是两者不一致即需改正。
2. 把应用 API Key 填入 `AIPROXY_API_TOKEN`。输入为应用侧 Key，比较对象为 AI Proxy 管理员 Token，观察结果是两者来源不同，启动校验可能失败。
3. 在拟稿句中把发票载明的价格术语直接写成申报要素结论。输入为 INV-2026-0302 的 CIF 表述，比较对象为拟稿句的「已含在发票总价内」，观察结果是发票只支持价格术语，申报要素是否可直接引用仍待核实。

## 怎么确认配好了

1. 取 INV-2026-0302 原文与拟稿句，输入为两句文本，比较发票是否载明成交方式与运保费承担方，观察结果是拟稿句与发票表述一致时该句获支持，不一致时待核实。
2. 取装箱单原文与交接请求，输入为 12 托盘、毛重 18,600 千克、净重 18,200 千克，比较请求是否要求确认申报要素可引用，观察结果是装箱单只提供件重数据，引用结论未获支持。
3. 取模型配置页的模型 ID 与映射 JSON，输入为 FastGPT 侧模型 ID 与上游模型名，比较两者是否按映射对应，观察结果是映射键值一致时渠道测试可发起，键值不符时测试请求指向的模型与预期不同，需先核标识再排除不符者。

检索检查只记录实际观察：若纸面输入为空数组，下游设计按空结果承接；不保证首条命中或无关查询必为空。跨不同向量模型的库不可共同关联，只核标识并记录缺口。
