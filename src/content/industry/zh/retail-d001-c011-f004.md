# 仅退款争议处理的商品资料与选型问答：向量模型与索引

## 这个品类的数据长什么样

在仅退款争议处理的商品资料与选型问答中，本页说明FastGPT的向量模型与索引如何衔接资料。申请人希望的香型不能成为已售商品属性。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

仅退款商品资料自拟申请“希望无香款”、订单描述“清洁用品，香型另见明细”和售后备注“已收诉求”。问本单是否无香时，申请说明愿望，订单尚指向另一份明细，备注只有接收动作。入口若将希望无香概括成无香商品，会给原数据增加已售属性。应让愿望、购买对象和处理记录分别可回查，不把相同品名或诉求状态接成商品规格。

## 配置怎么定

| 原数据与索引核对 | 具体对象关系 | 验收动作 |
| --- | --- | --- |
| 愿望身份 | 希望无香 | 不改已售属性。 |
| 订单对象 | 香型另见明细 | 核本单对应。 |
| 接收动作 | 已收诉求 | 不证明已受理或商品规格。 |
| 跨单目标 | 别单明细可能混用 | 核交易身份。 |
| 重复证据 | 多个无香入口 | 核是否同一愿望段。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

第一处是希望被索引成订单实际香型，应核订单对应明细。第二处是香型问题回到已收诉求备注，应读目标是否含商品属性；接收不证明已受理，也不能代替商品明细。第三处是另一订单的无香明细被同名入口采用，应核交易对象与明细身份。三项分别核属性依据、来源类型和订单对应，不以诉求被接收证明主张已经核实，也不由缺明细认定本单一定有香或无香。

## 怎么确认配好了

验收分别问申请希望什么、订单实际列什么、香型依据是否提供，核每个入口指向的原句。可以说明无香需求与已收诉求，实际香型仍待对应明细，不写成真实检验结果。后补明细时检查实际处理及索引状态，复用原问题比较引用，防止旧诉求仍承担规格证明。即使几个入口都含无香一词，也要核它们是否重复同一愿望段，不能当成多份独立商品证据。
