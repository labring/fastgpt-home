# 仅退款争议处理的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

仅退款争议处理与普通退款退货的差别在于常无退件入仓，证据重点落在发货签收与商品价值。资料主要来自平台售后后台、承运商轨迹、客服聊天与仓库出库记录，日常文档包括仅退款申请、发货凭证、签收证明与申诉材料。这些材料按每单更新，商品资料与选型问答需要把材料原文与拟稿句放在同一主体、同一期间、同一字段下核对。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与 Admin 必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，前者填服务根地址，不附加 `/v1`。系统至少需要一个语言模型和一个索引模型。模型渠道、模型 ID、模型映射在管理员模型提供商页面配置；渠道测试与模型测试按页面提示执行。语义召回与相关度不承担权限或实体隔离职责，检索库同向量模型的要求不扩展到外部工商系统。空结果可承接明确的纸面输入 `[]` 核对下游设计。

假设演练样本：材料原文为“仅退款申请单号 A-2026-0417，买家主张商品与描述不符，申请仅退款；发货凭证显示 2026-04-10 由某仓库出库，承运商轨迹显示 2026-04-12 签收；客服聊天记录中买家未提供开箱照片。”待判定的拟稿句为“现有材料可确认商品与描述不符，同意仅退款。”该请求处于待审核状态，尚未获得任何授权执行。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式与依据 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 假设填 `http://aiproxy:3000` | 核对是否附加 `/v1`；文档要求根地址 |
| `AIPROXY_API_TOKEN` | 假设填非空管理员 Token | 与服务端一致；不能以应用 API Key 代替 |
| 语言模型与索引模型 | 各启用一个 | 文档要求系统至少各一个 |
| 模型映射 | 假设 `gpt-4o-test` 映射 `gpt-4o` | 核对请求模型与上游模型字段 |
| 渠道优先级 | 本次假设起点为 50 | 范围 1～100，与另一渠道值比较 |
| 模型探测间隔 | 本次假设起点为 15 分钟 | 文档支持 5～60 分钟整数 |

## 容易做错的三处

1. 把待审核的仅退款申请当成已批准执行。输入是申请单号 A-2026-0417 与状态字段；比较字段取值是否为“已批准”；只有状态字段明确为已批准才满足，当前材料未载明该状态。
2. 用客服聊天中买家未提供照片推断商品与描述不符。输入是聊天记录与申请主张；比较是否有开箱照片或质检记录；两者均缺失时属于未获支持，不能写成否定或冲突。
3. 将语义召回结果当作权限过滤。输入是检索返回的片段；比较片段所属主体与当前争议单主体是否一致；不一致的片段应排除并记录，检索本身不授予访问权。

## 怎么确认配好了

1. 输入假设材料原文与拟稿句“现有材料可确认商品与描述不符，同意仅退款。”；比较拟稿句结论与材料中“未提供开箱照片”的记载；只有材料含质检或照片证据支持该结论时才满足，当前为未获支持。
2. 输入 `AIPROXY_API_ENDPOINT` 假设值与 `AIPROXY_API_TOKEN` 假设值；比较端点是否含 `/v1`、Token 是否非空；两者均符合文档要求时，接入配置项通过核对。
3. 输入纸面空结果 `[]` 与下游回答设计；比较下游是否在无引用时给出明确提示；出现提示即符合空结果承接设计，未出现则记录缺口，不推断检索规则必然返回空。
