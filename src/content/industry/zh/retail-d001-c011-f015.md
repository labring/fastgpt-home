# 仅退款争议处理的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样

在仅退款争议处理的商品资料与选型问答中，本页说明FastGPT的知识库检索与召回如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

仅退款争议的商品检索可另拟申请：“涉及配件缺失，具体型号待补。”这只是申请人的问题表述，没有列明配件。先用缺失原词和“现有资料能确认什么商品”分别查询，核候选是否保留待补型号的限制。若回答从其他申请借入商品名称，就混淆了检索对象；应把原申请、被引用记录和提问并列，不将相近主题当成同一件商品。

## 配置怎么定

| 文档项或实施核对 | 本题材料与条件 | 取证动作 |
| --- | --- | --- |
| 检索范围（实施核对） | 申请、出货文字和替换请求 | 分别核资料所处业务角色。 |
| 搜索模式（语义/全文/混合） | 配件缺失及商品身份问题 | 不能借入其他申请的对象。 |
| 引用token上限 | 待补型号与请求语境 | 裁剪不能丢失未确定状态。 |
| 最低相关度 | 语义或重排下核相关度 | 共同召回不证明交易关联。 |
| 问题优化 | 追问更换哪种配件 | 不将未知对象扩成具体型号。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

另拟发货凭证列“主体及附件袋”，申诉材料则写“要求替换配件”。若答复把请求写成已经发生的出货事实，来源角色就被误用，应分别回查三份文字的实际用途。引用token上限还需保留请求和申请理由语境，不能只剩附件袋或替换配件。两份记录是否同一事项，要另核交易关联，不能由同时被召回就认定对应。

## 怎么确认配好了

具体型号、组成清单和交易关联依据都未提供，不能从主体或附件袋推算配件。追问该换哪种时，需核问题优化是否将未确定对象扩为指定商品，记录改写所添内容的来源。取得对应资料后，用原题检查新增引用并分开保留候选与参数变化。最低相关度只按生效条件核验，多个命中并不说明争议或商品身份已经确认。
