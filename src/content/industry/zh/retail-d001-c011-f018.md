# 仅退款争议处理的商品资料与选型问答：重排与混合检索

## 这个品类的数据长什么样

在仅退款争议处理的商品资料与选型问答中，本页说明FastGPT的重排与混合检索如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「重排与混合检索」这一环带来什么约束

仅退款申请写明商品A及“商品描述不符”，其中商品名称和申请理由是两项不同信息。问商品时，先核候选是否回到名称字段；问争议原因时，再确认理由原文有无进入候选。完整问题应保留这一区别，避免重排将一段语义相近的申诉概述置前后，就把申请人的表述写成已核实的商品问题。本例只有自拟申请文字，没有争议裁定结果。“申请理由”这一来源角色应在答复中保留，不能缩写成已成立的事实。商品名称的读取测试也与后续退款或申诉处理分开，不由检索排序决定处置。

## 配置怎么定

| 核对项（含实施核对） | 本题输入或适用条件 | 回查与验收线索 |
| --- | --- | --- |
| 融合候选 | 商品A名称及描述不符的申请理由 | 名称与申请人说法分别核对。 |
| 完整问题 | 申请商品B与申诉商品C的关联 | 不能由争议词相近合成同一商品。 |
| 最低相关度 | 语义或重排条件下查看过滤 | 候选保留不代表争议已被裁定。 |
| 引用token上限 | 商品名称及理由的来源角色 | 申请理由不能压缩成已确认缺陷。 |
| 缺资料复测 | 名称之外尚无型号和规格 | 取得对应资料后再作选型阅读。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `混合检索` | 向量与全文结果通过RRF融合。 |
| `结果重排` | 按完整问题对候选再次排序。 |
| `最低相关度` | 过滤仅在语义或重排时生效。 |
| `引用上限` | 按token裁剪引用内容。 |
| `问题优化` | 比较优化前后主体与限制。 |

## 容易做错的三处

申请附页写商品B、申诉材料写商品C，需要检查两份材料是否指向同一事项。候选与引用应保留各自名称，不能因两个片段都接近“商品争议”就合成一个对象。先看原始召回是否齐全，再检查重排次序有没有掩盖另一名称；若尚无订单或其他关联依据，保持对象待核，不由排序决定哪份材料应被采信。

## 怎么确认配好了

只提供名称而没有型号规格时，商品选型问答缺少相应依据。测试应检查最后的描述有没有从其他案例借入型号，或把退款理由扩写为具体性能。取得对应规格资料后，用同一问题复测并回查新增引用，分别记录候选覆盖与排序变化。最低相关度的生效条件需核清，不能把申请片段高分解释为选型资料已经齐全。
