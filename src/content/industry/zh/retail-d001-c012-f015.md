# 仓内拣货复核打包的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样

在仓内拣货复核打包的商品资料与选型问答中，本页说明FastGPT的知识库检索与召回如何衔接资料。同一纸面简称覆盖不同批次和口型，规格身份需逐项核对。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

仓内商品检索另拟四份普通纸面文字：拣货单写“青罐，春批，短口”，规格页写“青色玻璃罐短口型，适用春批”，外箱纸标写“青罐，秋批”，另一页写“青色玻璃罐长口型，适用秋批”。这些名称只是自拟纸面称呼，不是FastGPT参数。问春批短口青罐应查哪份规格时，简称相同仍需核批次和口型，不能让秋批纸标把两种规格连成一款。先分别查看原词候选，再用包含批次与口型的完整问题核引用对象。

## 配置怎么定

| 本题身份核对 | 自拟纸面文字 | 验收动作 |
| --- | --- | --- |
| 简称候选 | 青罐同时见于两批纸标 | 逐个保留来源身份。 |
| 完整对象 | 春批、短口、青色玻璃罐 | 核规格原文同时覆盖条件。 |
| 检索比较 | 原词与带批次整题 | 读实际候选，不承诺精确命中。 |
| 优化指代 | 这种罐仍指当前短口对象 | 查是否漏批次或新增长口。 |
| 引用限定 | 规格适用春批或秋批 | 核裁剪后批次与口型仍在。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

全文检索可用青罐、短口等纸面原词观察实际返回，语义整题则保留春批与所问规格关系；两种结果都要读原文，不承诺必然精确匹配。一个失败情形是仅取到秋批青罐纸标，回答却沿用春批规格；另一个是问题优化把“这种罐”扩成长口型，改变了当前拣货对象。应并列原题、优化文字、候选身份与实际引用，定位批次是在哪一步被漏掉、口型是否无据增加。名称相近只提供待核线索，不证明同批或适配。第三处是拿到正确春批短口规格，却在回答时只写青罐，导致后来者将结论沿用到秋批。应逐句比较答案与被引规格的适用条件，确认批次和口型都留在最终表述；候选身份正确不能代替输出范围检查。

## 怎么确认配好了

验收可分三问：纸面青罐能对应哪些候选，春批短口的完整条件指向什么规格，换成秋批后原引用是否仍适用。答案需要回到带适用批次与口型的规格原句，单有简称纸标不足以给规格。引用裁剪也应保留适用春批或秋批，不能只剩玻璃罐。若补入新的物料对照表，先核它的纸面对象与版本，再用相同问题比较新增候选，分开记录资料更新和设置变化。最低相关度只按适用的语义或重排条件核，不由相关度替代身份核对。
