# 便利店加盟门店督导的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

便利店加盟督导资料来自督导APP、POS销售、加盟系统与门店照片，按周或月更新。巡店表、加盟合同、整改通知与陈列标准为商品资料和选型问答提供依据，回答应保留资料日期与版本，逐项核选品、陈列及订货表述。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy 服务。自 V4.17.0 起，AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 为 App 与 Admin 共享的必填项，缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。系统至少需要一个语言模型和一个索引模型才能正常使用。索引模型决定商品资料能否被向量化检索，语言模型决定选型问答能否生成回答。两者缺一，问答链路无法完成。

假设演练样本：某加盟督导在纸面记录中持有以下材料原文——“2026年3月巡店表：A类门店饮料陈列层数由三层调整为四层，执行日期2026年3月10日至2026年4月10日。”“2026年2月陈列标准第4.2条：饮料区层数维持三层，未收到变更通知前按本标准执行。”拟判定句：“A类门店饮料陈列已按四层执行。”该拟判定句涉及巡店表与陈列标准两份材料，主体为A类门店，对象为饮料陈列层数，期间为2026年3月。巡店表载明调整期间，陈列标准载明维持三层。两份材料对同一字段给出不同取值，需要核对生效范围与优先关系，不能直接判定拟稿句成立。

## 配置怎么定

配置围绕商品资料检索与选型问答链路展开。以下为本次假设试验起点，用于核对配置是否覆盖主任务，不作为官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | `http://aiproxy:3000` | 文档要求填写服务根地址，不附加 `/v1`。与文档示例格式比较，确认无路径后缀。 |
| AIPROXY_API_TOKEN | 非空管理员 Token | 文档要求非空且与服务端一致。与 AI Proxy 服务端配置比较，确认一致。 |
| 语言模型 | 已启用一个语言模型 | 文档要求至少一个语言模型。在模型配置页面核语言模型类型、启用状态与渠道测试记录。 |
| 索引模型 | 已启用一个索引模型 | 文档要求至少一个索引模型。在模型配置页面核索引模型类型、启用状态与渠道测试记录。 |
| 知识库与向量模型 | 商品资料库使用同一索引模型 | 文档说明跨不同向量模型的库不可共同关联。核对库标识与索引模型标识，排除不符者。 |
| 文件解析并发 | DATASET_PARSE_MAX_PROCESS 为 `10` | 文档载明该变量控制知识库文件解析队列最大并发数。与当前队列积压情况比较，判断是否需要调整。 |

配置完成后需确认：检索只返回已授权范围内的商品资料，检索本身不构成授权。表单收集的字段值不自动触发审批或数据库写入，业务核验与外部同步需要下游实现。

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 填成完整模型请求地址。文档明确要求填写服务根地址，不附加 `/v1`。错误输入为 `http://aiproxy:3000/v1/chat/completions`，正确比较对象为文档示例 `http://aiproxy:3000`，先记录根地址格式不符，实际请求路径和响应待测试。

2. 用应用 API Key 充当 AIPROXY_API_TOKEN。文档要求管理员 Token 且必须与服务端一致。错误输入为应用侧生成的 API Key，比较对象为 AI Proxy 服务端管理员 Token，先记录凭证用途不符，实际鉴权结果待测试。

3. 将不同向量模型的库共同关联后直接比较检索结果。文档说明跨不同向量模型的库不可共同关联。错误操作为对两个使用不同索引模型的库发起联合检索，正确做法为先核对库标识与索引模型标识，排除不符合者，记录实际观察而不推断运行结果。

## 怎么确认配好了

1. 针对假设样本中的巡店表与陈列标准原文，向商品资料与选型问答发起拟判定句“A类门店饮料陈列已按四层执行”的核对请求。比较巡店表的四层调整期间与陈列标准的三层及变更条件；缺少生效范围和优先关系证据，拟稿句待核。

2. 输入陈列标准第4.2条并问“本条要求几层”，核回答是否引用三层及2026年2月版本。巡店表的四层调整需按前项另核，不能直接替换本条原文。

3. 针对假设样本的授权边界，发起请求“列出所有加盟门店的陈列调整记录”。输入为当前检索范围与用户授权范围。比较对象为请求覆盖范围与已授权资料范围。满足条件为回答仅返回授权范围内的材料，或明确说明部分范围不在当前检索范围内。若检索返回空结果，记录该结果并核对下游设计对空结果的处理，不推断虚构规则一定返回空数组。

以上为纸面核对，实际调用及返回尚待测试。
