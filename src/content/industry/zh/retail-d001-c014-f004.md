# 便利店鲜食订货的商品资料与选型问答：向量模型与索引

## 这个品类的数据长什么样

在便利店鲜食订货的商品资料与选型问答中，本页说明FastGPT的向量模型与索引如何衔接资料。拍摄用大份示意与订货单位不提供实际单份规格。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

鲜食商品索引自拟拍摄附注“大份仅作画面示意”，订货表写“按盒登记，份量见商品册”。问每盒是否就是图中大份时，画面示意与登记单位都没有给出实际份量。入口不能把大份词直接加到订货品名，也不能由盒这一单位换算成单份内容。应分别保留拍摄来源、订货对象及商品册指向，不能把同一菜品名称当作两种资料已经等同的依据。

## 配置怎么定

| 原数据与索引核对 | 具体对象关系 | 验收动作 |
| --- | --- | --- |
| 示意身份 | 大份为画面用途 | 不转销售份量。 |
| 登记单位 | 按盒 | 不自行换算内容。 |
| 规格来源 | 份量见商品册 | 取得实际条目。 |
| 期间对应 | 别日菜单可能不同 | 核品项及版本。 |
| 新条目采用 | 册补入后的实际目标 | 核原数据和引用。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

第一处是示意份量被索引成销售规格，应查商品册实际条目。第二处是每盒问题只回到按盒登记，应读原数据有无实际份量，单位本身不能说明内容。第三处是别日菜单的规格被用于本次订货，应核品项、期间与适用版本。三项分别查属性来源、信息覆盖及对象时间对应，不以展示画面或入口名决定实际规格，也不补重量、数量或质量结论。

## 怎么确认配好了

验收分别问附注说明什么、订货表如何登记、实际份量由哪份来源确认，核入口与引用保持范围。可说明画面与按盒单位，实际单份仍待商品册。资料补入后核对应品项和实际处理，再用同题检查索引是否回到新条目；上传不等于更新已被采用。多个索引即使都含盒或大份，也需逐个读原数据，重复拍摄附注不能当成多份规格证明。
