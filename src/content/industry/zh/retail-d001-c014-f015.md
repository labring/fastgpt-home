# 便利店鲜食订货的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样

在便利店鲜食订货的商品资料与选型问答中，本页说明FastGPT的知识库检索与召回如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

鲜食商品检索可新拟订货文字：“独立装三明治，按当日订货批次记录。”这里能读取的是单件包装和记录范围，不能说明每个运输箱有多少份。先用独立装及当日批次两个原词检查候选，再以售卖包装形式的完整问题比较搜索模式。资料属于普通文字测试，不提供现实商品的保存或食用建议，也不能把包装称谓扩成未给出的数量规格。

## 配置怎么定

| 文档项或实施核对 | 本题材料与条件 | 取证动作 |
| --- | --- | --- |
| 检索范围（实施核对） | 单件包装和处理批次分开 | 整箱记录不改写单件属性。 |
| 搜索模式（语义/全文/混合） | 独立装原词与包装形式问题 | 核每种模式的来源角色。 |
| 引用token上限 | 当日批次与待核条件 | 保留时间范围及未确认状态。 |
| 最低相关度 | 语义或重排下核过滤 | 高分片段不提供装箱份数。 |
| 问题优化 | 追问一箱多少份 | 保持商品和批次，不新增数量。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

另一份自拟临期处理表只记“整箱批次待核”，描述的层次与独立装不同。若回答由整箱两个字改写单件售卖包装，就是把运输或处理批次的表述混入商品属性，应回查两处来源。还需检查token引用是否漏掉当日或待核这些条件，避免把记录范围写成已确认状态。两份文字能同时存在，不由检索排序决定哪个包装层次才算实际商品。第三处是把临期表中的待核批次写成已决定按整箱处置。应找该批次实际处理决定并核其对象；待核说明与执行决定是两种证据，不能由记录层级直接补成处置动作。

## 怎么确认配好了

每箱份数及对应装箱规格未提供时，应明确缺少的资料，不能从独立装推算箱内数量。追问一箱多少份时，核问题优化是否仍保持同一商品和批次，没有补出数字。取得真实规格后，重复原问题检查新增候选及引用，分开记录资料和参数变化。最低相关度只在语义或重排条件下生效，单条高分结果不能替代装箱明细。
