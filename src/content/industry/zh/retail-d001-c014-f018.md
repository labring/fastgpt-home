# 便利店鲜食订货的商品资料与选型问答：重排与混合检索

## 这个品类的数据长什么样

在便利店鲜食订货的商品资料与选型问答中，本页说明FastGPT的重排与混合检索如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「重排与混合检索」这一环带来什么约束

鲜食问答的样例，订货单附页只对某款三明治写了零至四摄氏度的建议保存温度。重排测试应把商品名称、温度范围及“建议”一词一起作为阅读目标，先核候选是否完整保留。不能把其他商品的温度文字借给这款三明治，也不从自拟附页得出现实食品保存建议；本次检查仅确认回答是否忠实回到所提供的文字。

## 配置怎么定

| 核对项（含实施核对） | 本题输入或适用条件 | 回查与验收线索 |
| --- | --- | --- |
| 融合候选 | 三明治及零至四摄氏度的建议文字 | 保留商品与“建议”限定。 |
| 完整问题 | 饮品建议范围与记录范围 | 区分零至四的建议和零至六的记录。 |
| 最低相关度 | 实际使用语义或重排时查看 | 过滤不能认定现实保存是否适当。 |
| 引用token上限 | 温度数字及其语境同时保留 | 不能只剩范围而丢掉记录角色。 |
| 缺资料复测 | 甜点缺少过敏原信息 | 不能从品名或其他甜点借入成分。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `混合检索` | 向量与全文结果通过RRF融合。 |
| `结果重排` | 按完整问题对候选再次排序。 |
| `最低相关度` | 过滤仅在语义或重排时生效。 |
| `引用上限` | 按token裁剪引用内容。 |
| `问题优化` | 比较优化前后主体与限制。 |

## 容易做错的三处

饮品订货单的建议范围与温度记录的记录范围属于两种资料：前者写零至四，后者写零至六。两段应分别进入候选，先核是否同一商品及期间，再看排序有没有将记录范围写成建议标准。引用token上限也要核对，防止只留下数字而丢掉“建议”和“记录”的区别。实际保存是否符合要求，需要另以适用依据及完整记录核定。需要核对的还包括两段各自描述的情境；现有文字没有提供完整温度过程，不能扩写成持续达标或持续超标。回答应保留这项证据范围限制。

## 怎么确认配好了

甜点过敏原信息没有提供，订货单中的品名或温度不能代替成分依据。可检查高排位候选是否来自别的甜点，最终文字是否无出处地宣称含有或不含某成分。取得对应商品的实际资料后再问同题，记录新增来源是否进入引用，并检查过滤及排序各阶段；重排无法生成缺失的过敏原证据，不能据相关度对食品属性作确认。
