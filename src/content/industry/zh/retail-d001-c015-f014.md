# 信用证审单交单的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

信用证审单交单围绕单证一致展开，服务的是银行付款条件，税务匹配属于另一条线。每单都要处理信用证、商业发票、提单、保险单、汇票，数据来源包括开证行通知、UCP600条款、货代提单与银行交单记录。从业主体是外贸单证员、银行国际结算与出口商，出错会带来拒付、扣费与延迟收汇。这些材料按每单更新，模型接入与配置需要让商品资料与选型问答能引用上述单据文本，并保持对条款、单据字段与状态的区分。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务都需要设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会启动校验失败。AIPROXY_API_ENDPOINT 填写 AI Proxy 服务根地址，不附加 `/v1`。模型渠道、模型配置与应用侧参数分别核对，不能假设对话接口的同名字段会覆盖编排设置。

假设演练样本：某信用证要求提交商业发票、提单与保险单，发票须由受益人出具，提单收货人栏填写开证行指定名称，保险单币别与信用证一致。拟稿句为“本批货物已按信用证要求完成交单，单据一致”。该拟稿句未附交单记录或银行回执，属于待核实状态。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 根地址，不带 `/v1` | 与部署实际根地址逐字比较 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空管理员 Token | 与 AI Proxy 服务端配置比较 |
| 语言模型 | 选择可用语言模型并启用 | 在模型提供商页面确认启用状态 |
| 索引模型 | 选择可用索引模型并启用 | 系统至少需要一个语言模型和一个索引模型 |
| 模型渠道测试 | 对已配渠道执行模型测试 | 查看测试结果与请求时长 |
| 模型探测 | 按需开启自动探测并设置间隔 | 间隔为 5～60 分钟整数 |

上表数值为本次假设试验起点，选择理由是便于与文档说明的范围比较，不代表官方默认值。

## 容易做错的三处

1. AIPROXY_API_ENDPOINT 误填完整请求地址并附加 `/v1`。检查输入是否为服务根地址，与文档要求比较，观察是否出现启动校验失败。
2. 用应用 API Key 代替 AIPROXY_API_TOKEN。检查填入值是否为管理员 Token，与服务端配置比较，观察是否无法通过校验。
3. 将拟稿句“本批货物已按信用证要求完成交单，单据一致”当作已核实结论。检查是否附有交单记录或银行回执，与样本状态比较，观察该句是否仍属待核实。

## 怎么确认配好了

1. 输入假设样本中的信用证要求与三份单据字段，比较发票出具人、提单收货人栏与保险单币别是否与信用证一致，观察逐项比对结果，不将拟稿句视为证据。
2. 输入拟稿句“本批货物已按信用证要求完成交单，单据一致”，比较其是否附交单记录或银行回执，观察该句是否被标为待核实，缺失证据保持缺失。
3. 输入模型渠道配置，比较 AIPROXY_API_ENDPOINT 是否为不带 `/v1` 的根地址，观察模型测试结果与请求时长，未测试的模型不判定为可用。
