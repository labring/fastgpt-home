# 信用证审单交单的商品资料与选型问答：重排与混合检索

## 这个品类的数据长什么样

在信用证审单交单的商品资料与选型问答中，本页说明FastGPT的重排与混合检索如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「重排与混合检索」这一环带来什么约束

信用证审单的自拟发票，先提出商品描述与订单要求有定性差异，但现有样例没有展开订单原句。候选检查应先核订单是否实际提供，再看发票描述能支持哪些内容。完整问题要保留商品性质的比对目标，不能由一段“存在差异”的概述替代两方原文，更不能以排序结果直接形成审单结论。若订单原文尚未取得，回答应明确目前只能读取发票及样例说明。比较对象缺失与候选排序不理想是两类问题，不能通过提高发票片段排名将前者当成已经解决。

## 配置怎么定

| 核对项（含实施核对） | 本题输入或适用条件 | 回查与验收线索 |
| --- | --- | --- |
| 融合候选 | 发票商品描述；尚需取得订单原文 | “存在差异”概述不能代替双方条款。 |
| 完整问题 | 工业级与消费级传感器的限定 | 两个级别不能都缩写为传感器。 |
| 最低相关度 | 语义或重排条件下核过滤 | 只保留一方时仍需检查召回范围。 |
| 引用token上限 | 商品性质及对应单据身份 | 查看级别限定是否被截去。 |
| 缺资料复测 | 没有详细技术规格参数 | 名称或级别不能替代型号要求的依据。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `混合检索` | 向量与全文结果通过RRF融合。 |
| `结果重排` | 按完整问题对候选再次排序。 |
| `最低相关度` | 过滤仅在语义或重排时生效。 |
| `引用上限` | 按token裁剪引用内容。 |
| `问题优化` | 比较优化前后主体与限制。 |

## 容易做错的三处

工业级传感器与消费级传感器分别来自商业发票和信用证附页，两个限定词不能在重排后被省略为同一个“传感器”。先核候选是否同时包含各自商品性质，再比较最终引用的完整程度。若只召回一边，先查资料范围及检索；两边都在时，再看顺序与token裁剪，记录有无把一方描述误写为双方已经一致。

## 怎么确认配好了

型号和数量未必包含技术规格，缺少规格参数时，不能凭商品级别或名称接近确认其满足具体要求。取得对应技术资料后，可重复原问题检查新来源进入候选及引用的路径。最低相关度按语义或结果重排的条件验证，问题优化前后还要核商品主体和限制是否保持；本次测试不替代对单据适用版本及审单要求的专业核验。
