# 加盟商培训与开业辅导的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

加盟商培训与开业辅导的资料来自培训系统、督导APP、门店照片与总部SOP库。日常文档包括培训签到表、开业检查表、SOP手册与考核成绩，更新频率为每店每月。商品资料与选型问答要处理的是这些材料在模型接入后的检索与引用，材料本身带有门店、批次与日期范围，检索结果只呈现文本片段，不改变材料的授权状态。

## 这些特征在「模型接入与配置」这一环带来什么约束

从 V4.17.0 起，AI Proxy 为必需依赖。App 与复用 App/Service 配置的 Admin 服务都必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。系统至少需要一个语言模型和一个索引模型才能正常使用。语音识别模型仅生效一个，配置一个即可。

假设演练样本：某连锁品牌培训部拟核对一份开业辅导材料。材料原文为：“2026年3月批次华东区加盟商开业检查表，检查日期2026年3月10日，检查人区域督导李某，门店编号HD-0310，检查项包含收银操作与库存盘点，检查结论为待整改。”另一份材料为：“2026年3月批次华东区加盟商培训签到表，签到日期2026年3月8日，参训人员为HD-0310门店店主王某，培训内容为SOP手册第三章收银流程，签到状态为已签到。”待判定的拟稿句为：“HD-0310门店已完成开业整改并具备开业条件。”该拟稿句需要核对检查表结论与签到表状态是否支持“已完成整改”与“具备开业条件”。

## 配置怎么定

下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 核对说明 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写为 `http://aiproxy:3000` | 官方要求填写 AI Proxy 服务根地址，不附加 `/v1`。本次起点用于核对 App 与 Admin 是否一致。 |
| `AIPROXY_API_TOKEN` | 填写为与服务端一致的非空管理员 Token | 官方要求非空且与服务端一致，不能用应用 API Key 代替。 |
| 语言模型与索引模型 | 各启用一个 | 官方要求系统至少各有一个才能正常使用。本次起点用于核对两类模型均处于启用状态。 |
| 模型能力 | 按应用所需输入核对 | 多模态、工具调用及思考配置分别验证。样本为文本问答，不涉及图片输入。 |
| 应用参数 | 在应用或节点配置中设置 | 参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。 |
| 模型状态探测 | 探测间隔按 5～60 分钟之间的整数设置 | 官方支持该区间整数。本次起点用于核对已启用模型是否参与探测。 |

## 容易做错的三处

1. 将签到表的“已签到”状态当作开业整改完成的证据。签到表记载的是2026年3月8日培训签到，检查表记载的是2026年3月10日检查结论为待整改。两者主体相同、期间不同、字段不同，签到状态不能支持“已完成整改”。

2. 将检查表的“待整改”结论直接读作“已具备开业条件”。检查表原文只记录检查结论为待整改，未载明整改完成或开业条件已满足。该拟稿句的“已完成整改”与“具备开业条件”均未获支持。

3. 将检索命中视为授权或执行。检索返回材料片段只代表文本被召回，不代表整改已完成、开业已批准或任何业务动作已执行。待审核不证明缺少操作权限，待整改不证明整改未开始。

## 怎么确认配好了

1. 输入上述检查表原文与签到表原文，比较拟稿句“HD-0310门店已完成开业整改并具备开业条件”中的“已完成整改”与检查表结论字段。检查表结论为“待整改”，同主体、同期间、同一字段的取值与“已完成整改”不一致。观察结果为：该拟稿句未获检查表支持，需记录证据缺口。

2. 输入签到表原文，比较拟稿句中的“具备开业条件”与签到表记载的签到状态。签到表只记录培训签到，未载明开业条件。观察结果为：签到表不构成开业条件的证据，该部分待核实。

3. 输入上述两份材料与拟稿句，比较材料日期范围与拟稿句所涉期间。检查表日期为2026年3月10日，签到表日期为2026年3月8日，拟稿句未载明具体期间。观察结果为：在未补充整改完成记录或开业批准文件前，该拟稿句保持未获支持状态。若检索返回空结果，可用明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回空数组。
