# 加盟费与保证金结算的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

加盟费与保证金结算围绕资金和违约扣款展开，与特许加盟备案管理不同，不承担政府备案职责。主要数据来源为财务系统、加盟合同、银行流水和门店违规记录，日常文档包括加盟费发票、保证金台账、扣款通知和合同付款计划。典型从业主体有连锁财务、加盟管理部和加盟商，出错后果涉及资金争议、加盟诉讼和保证金退还纠纷。本页只处理商品资料与选型问答中的模型接入与配置，不构造无依据的业务功能。

## 这些特征在「模型接入与配置」这一环带来什么约束

假设演练样本：某连锁品牌加盟管理部拟核对一份扣款通知的模型选型。材料原文为：「2026年8月扣款通知，对象为华东区A加盟店，事由为合同第7.2条逾期付款违约金，金额人民币12,000元，状态为待加盟管理部复核。」另一份材料为：「保证金台账显示A加盟店截至2026年8月31日保证金余额为50,000元，其中30,000元处于冻结状态。」拟稿句为：「该扣款已从保证金中扣除并完成结算。」待判定请求为：「请将该扣款通知接入模型问答，确认保证金扣款是否已执行。」

模型接入与配置在此场景中的约束：系统至少需要一个语言模型和一个索引模型才能正常使用。AI Proxy 为必需依赖，App 和复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。模型 ID 是接口请求 Body 中 model 字段的值，全局唯一；模型名用于展示，可以自定义。模型渠道对应不同提供商协议，模型映射可将 FastGPT 请求的模型映射到具体提供的模型上。模型状态探测仅针对已启用的系统模型，未启用模型不参与探测。检索与相关度不负责权限或实体隔离，检索库同向量模型要求不能扩展为其他外部系统也要同模型。

## 配置怎么定

以下配置围绕本页样本的模型接入与配置核对，不把数据库内部实现抄成每页必配项。涉及数值时明确为本次假设试验起点，并说明选择理由与比较对象。

| 配置项 | 本次假设试验起点 | 核对方式与理由 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不附加 `/v1` | 按官方文档要求，App 与 Admin 均须配置；与文档示例 `http://aiproxy:3000` 比较格式 |
| AIPROXY_API_TOKEN | 非空管理员 Token，与服务端一致 | 官方文档要求不能为空；与文档说明比较，不能用应用 API Key 代替 |
| 模型渠道协议类型 | 按样本所需模型选择对应提供商协议 | 官方文档说明大多数提供 OpenAI 协议；与模型实际来源比较 |
| 模型映射 | 将 FastGPT 请求模型映射到上游实际模型 | 官方文档示例 `gpt-4o-test` 映射为 `gpt-4o`；与渠道配置比较 |
| 模型探测间隔 | 本次假设试验起点设为 30 分钟 | 官方文档支持 5～60 分钟整数；与文档范围比较，选择中间值便于观察 |
| 告警 Webhook 地址 | 本次假设试验起点填写内部回调 URL | 官方文档说明可选，支持 HTTP/HTTPS；与文档要求比较连通性 |

## 容易做错的三处

1. 将待审核状态当作已执行。样本中扣款通知状态为「待加盟管理部复核」，拟稿句称「已从保证金中扣除并完成结算」。待审核不证明缺少操作权限，也不等于扣款已执行；输入为扣款通知原文，比较对象为状态字段，预期现象是状态与拟稿句不一致时标注为未获支持。
2. 将检索结果当作授权依据。样本请求要求确认保证金扣款是否已执行，若仅凭检索到的台账余额记录回答，输入为台账原文，比较对象为台账是否载明扣款动作，预期现象是台账未载明扣款执行时记录证据缺口。
3. 将模型探测覆盖范围扩大。样本中若存在未启用的模型，输入为探测配置，比较对象为已启用模型列表，预期现象是未启用模型不产生探测记录，不能据其状态推断扣款业务是否完成。

## 怎么确认配好了

1. 输入样本扣款通知原文与拟稿句，比较拟稿句是否与通知状态字段一致，预期现象是拟稿句与「待复核」状态矛盾时判定为未获支持，不声称已实测。
2. 输入样本台账原文与待判定请求，比较台账是否载明扣款执行动作，预期现象是台账仅载明余额与冻结金额时，记录为证据缺口，不推断扣款已执行。
3. 输入模型探测配置与已启用模型列表，比较探测范围是否仅覆盖已启用模型，预期现象是未启用模型无探测记录，不据此判断业务动作是否完成。
