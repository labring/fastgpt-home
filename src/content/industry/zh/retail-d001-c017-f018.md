# 加盟费与保证金结算的商品资料与选型问答：重排与混合检索

## 这个品类的数据长什么样

在加盟费与保证金结算的商品资料与选型问答中，本页说明FastGPT的重排与混合检索如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「重排与混合检索」这一环带来什么约束

加盟费样例中的发票附页写明已开票，需要回查的是这项文字记录，不能顺带确认实际付款或收款。可先标注开票状态所在原句，检查候选是否与正确款项对应，再用完整问题观察重排。发票、台账和付款计划的用途不同，语义接近的结算片段不一定提供开票依据，最后回答应保留来源身份及其所能支持的范围。开票文字与支付凭证还应分别保存来源，避免最终摘要将“开票”压缩成“已收款”。重排检查的是原文取回和次序，摘要中的动词也需要回到对应证据核对。

## 配置怎么定

| 核对项（含实施核对） | 本题输入或适用条件 | 回查与验收线索 |
| --- | --- | --- |
| 融合候选 | 发票附页的已开票文字 | 与实际支付或收款凭证分开。 |
| 完整问题 | 发票甲方与付款计划乙方 | 核对主体及是否同一款项。 |
| 最低相关度 | 语义或重排条件下核过滤 | 高分不能改写原文的支付主体。 |
| 引用token上限 | 开票状态及主体来源 | 不得把已开票压缩成已收款。 |
| 缺资料复测 | 现有发票没有收款账户 | 补获授权来源，不从当事方名称推算。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `混合检索` | 向量与全文结果通过RRF融合。 |
| `结果重排` | 按完整问题对候选再次排序。 |
| `最低相关度` | 过滤仅在语义或重排时生效。 |
| `引用上限` | 按token裁剪引用内容。 |
| `问题优化` | 比较优化前后主体与限制。 |

## 容易做错的三处

甲方和乙方分别被写成发票附页及合同付款计划中的支付方，核对时应保留这两个主体。先看排序前的候选是否完整，再核两份材料是否指向同一笔款项及适用版本。不能因为合同片段更长或排名更高，就把发票中的主体改写成乙方。原文说法的差异可以列入待核，实际支付方仍需对应的业务凭证，不能由重排决定。

## 怎么确认配好了

收款账户没有在现有发票附页中提供，这项缺口不应由模型根据甲方、乙方或保证金台账名称补写。可检查候选与最终输出，确认有没有引入其他材料中不对应的账户。取得获授权的对应来源后，再重复原问题并回查新增引用。排序位置只表示当前候选的次序，不构成账户真实性、归属或结算完成的证明，核对记录应保持这些边界。
