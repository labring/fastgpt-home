# 区域经销商库存补货的商品资料与选型问答：向量模型与索引

## 这个品类的数据长什么样

在区域经销商库存补货的商品资料与选型问答中，本页说明FastGPT的向量模型与索引如何衔接资料。基础款与常规款是否同物，需有目录版本对应。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

区域经销商品索引自拟旧目录称“基础款”，新补货表称“常规款”，技术说明只列常规款的可折结构，尚无改名对应。问基础款能否折叠时，不能由两个日常称呼相近就迁移属性。索引可分别为旧名与新名提供入口，但应保留各自原数据和版本。基础款缺具体结构并不证明不可折，也不能将新表词语自动认作旧商品已经改名。

## 配置怎么定

| 原数据与索引核对 | 具体对象关系 | 验收动作 |
| --- | --- | --- |
| 旧款名称 | 基础款 | 保留旧来源身份。 |
| 新款属性 | 常规款可折 | 不迁给基础款。 |
| 名称关系 | 改名尚未对应 | 查实际关系文件。 |
| 入口目标 | 旧名可能指新页 | 核版本及产品。 |
| 补对应复测 | 新增关系与实际引用 | 确认原数据被采用。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

第一处是旧名入口直接写可折，应核属性是否有旧款原文支持。第二处是基础款入口指向新表却不标身份，应查目标版本与改名关系。第三处是补入对应说明后，旧入口仍指另一款技术页，应核映射对象和实际引用。三项分别核属性迁移、名称关系与更新目标，不以目录时间较新或经销商相同完成对应，也不把索引数量当作改名确认。

## 怎么确认配好了

验收分别问两份资料各叫什么、哪份写可折、是否有名称对应，核引用明确来源。当前可以分别描述称呼和新款结构，旧款问题保留关联待核。取得说明后先核它覆盖的产品与版本，再检查实际处理与索引，以同题确认是否真正采用。即使一个原数据可有多个入口，也不表示不同原数据里的近义名称一定是同一商品，需回到实际对应文件。
