# 即时零售门店履约的商品资料与选型问答：向量模型与索引

## 这个品类的数据长什么样

在即时零售门店履约的商品资料与选型问答中，本页说明FastGPT的向量模型与索引如何衔接资料。备选商品不自动继承原订单的成分描述。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

即时零售选型资料自拟订单“原味饼”、替代建议“可询问全麦款”和商品说明“原味配方另见原文”。问本次商品是否为全麦时，建议提出替代可能，没有说明买家接受或实际拣选；原味说明也不能给全麦款提供成分。入口若把两个商品合成原味全麦饼，会创造没有出处的名称。应保留订单、建议与配方来源，不由同类食品或同一订单讨论推定已更换。

## 配置怎么定

| 原数据与索引核对 | 具体对象关系 | 验收动作 |
| --- | --- | --- |
| 原订单身份 | 原味饼 | 不改为已购全麦。 |
| 替代状态 | 可询问 | 核实际选择依据。 |
| 配方对象 | 每款各有原文 | 不借别款成分。 |
| 映射分离 | 两款不合成新名 | 逐项核原数据。 |
| 变更边界 | 新增资料不等于订单改变 | 核引用与实际事件。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

第一处是替代建议被索引成已购全麦，应核实际选择或订单变更记录。第二处是全麦问法指向原味配方，应查目标商品及原文适用范围。第三处是新商品资料补入后，入口仍把两款合成一项，应逐一核原数据和最终引用中的名称。三项分别核业务选择、配方对象与映射合并，不从需求或相近品名补营养、口感或实际交付结论。

## 怎么确认配好了

验收分别问原订单是什么、建议替代什么、是否有实际变更依据，核答案引用保持三个对象。当前可说明建议可能，不能写成买家已接受。再问某款成分时，应回到该款对应原文，不借另一款配方。新增资料后检查实际处理与索引，用同题比较目标；上传成功不证明订单发生变化。一个原数据多个入口仍只证明它自己的内容，不把替代关系变成商品属性等同。
