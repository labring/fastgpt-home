# 即时零售门店履约的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

即时零售门店履约按分钟处理线上订单，门店库存、拣货清单、缺货报备与配送异常单在每单内更新。商品资料与选型问答需要把这些分钟级材料接入模型，回答拣货员关于规格、替代品与库存位置的询问。材料来源分散在平台后台与门店系统，模型接入与配置必须让问答在缺货替换与拣货路径上给出可核对的依据。

## 这些特征在「模型接入与配置」这一环带来什么约束

从 V4.17.0 起，AI Proxy 为必需依赖。App 与复用 App/Service 配置的 Admin 服务都必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。`AIPROXY_API_ENDPOINT` 填服务根地址，不附加 `/v1`。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。系统至少需要一个语言模型和一个索引模型才能正常使用。模型能力按应用所需输入核对，多模态、工具调用及思考配置分别验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。

假设演练样本：门店值班主管提交一份交接请求，附材料原文为“本店今日拣货清单第 12 行：鲜牛奶 950ml，库存 3 件，货位 A3-2；缺货报备单第 4 条：同规格商品今日 14:00 前无可替代到货。”拟判定句为“该门店今日可承诺鲜牛奶 950ml 替代品当日达。”该请求处于待审核状态，未获授权执行。

## 配置怎么定

| 配置项 | 本次假设起点 | 核对方式与理由 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://aiproxy:3000` | 官方示例根地址，确认不附加 `/v1`；与启动校验比对 |
| `AIPROXY_API_TOKEN` | 空，必填 | 与服务端配置一致且非空；用应用 API Key 代替不满足 |
| 语言模型 | 启用一个 | 系统至少需一个语言模型；在模型提供商页面确认已启用 |
| 索引模型 | 启用一个 | 系统至少需一个索引模型；确认模型 ID 与渠道模型一致 |
| 模型能力 | 按本任务输入核对 | 多模态、工具调用分别验证；不假设同名字段覆盖编排 |
| 应用参数 | 在应用或节点配置中设置 | 应用侧参数独立于兼容对话接口字段 |

## 容易做错的三处

1. 把 `AIPROXY_API_ENDPOINT` 填成带 `/v1` 的完整请求地址，启动校验比对时端点不匹配。
2. 用应用 API Key 充当 `AIPROXY_API_TOKEN`，与服务端配置比对时 Token 不一致。
3. 只启用语言模型，索引模型未启用，系统启动校验报缺少必需模型。

## 怎么确认配好了

1. 输入假设样本材料原文与拟判定句，比较拟判定句是否超出材料所载范围。材料只载明库存 3 件与 14:00 前无可替代到货，未载明当日达承诺，待核实。
2. 输入 `AIPROXY_API_ENDPOINT` 与 `AIPROXY_API_TOKEN`，比较端点是否为根地址、Token 是否非空且与服务端一致。两项均满足才通过启动校验。
3. 输入已启用模型列表，比较是否至少各有一个语言模型和索引模型。缺少任一类时启动校验失败，记录为未通过。
