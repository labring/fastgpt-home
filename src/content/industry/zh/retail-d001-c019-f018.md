# 即时零售门店履约的商品资料与选型问答：重排与混合检索

## 这个品类的数据长什么样

在即时零售门店履约的商品资料与选型问答中，本页说明FastGPT的重排与混合检索如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「重排与混合检索」这一环带来什么约束

即时订单的自拟附页写新鲜牛奶、全脂和两件，分别是名称、规格和数量。问商品基本信息时，候选应保持这三项与同一商品关联，再用完整问法检查重排。全脂这一规格不能扩写为原文没有的营养数值或适用人群，名称里“新鲜”也不等于已经核实实际品质；最终回答需要回到订单文字，保留它只是单据记录的范围。

## 配置怎么定

| 核对项（含实施核对） | 本题输入或适用条件 | 回查与验收线索 |
| --- | --- | --- |
| 融合候选 | 新鲜牛奶、全脂、两件 | 名称、规格、数量对应同一商品。 |
| 完整问题 | 订单一盒与拣货两盒鸡蛋 | 检查单位与订单关联，不直接断言多拣。 |
| 最低相关度 | 按语义或重排条件检查过滤 | 候选数量不代表实际配送数量。 |
| 引用token上限 | 两份数量原句及其资料角色 | 不静默把任一数值改成另一个。 |
| 缺资料复测 | 订单没有成分及保质期资料 | 其他商品的说明不能误归于本订单。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `混合检索` | 向量与全文结果通过RRF融合。 |
| `结果重排` | 按完整问题对候选再次排序。 |
| `最低相关度` | 过滤仅在语义或重排时生效。 |
| `引用上限` | 按token裁剪引用内容。 |
| `问题优化` | 比较优化前后主体与限制。 |

## 容易做错的三处

有机鸡蛋在订单中写一盒，在拣货清单中写两盒，需要核对单位、商品及对应订单。先确认双方数量原句都进入候选，再看重排及引用是否漏掉其中一边。不同数量可能涉及版本、拆分或其他业务记录，现有样例没有提供这些依据；因此应保留差异待核，不能直接写成门店多拣一盒，也不能用排名决定哪个数字代表实际完成量。订单要求与拣货记录应分别回查，不把其中一个数量自动改成另一个。若后续要确认实际配送数量，还需要配送相关记录，不能只在这两份单据之间选一个数。

## 怎么确认配好了

成分列表和保质期没有在现有订单中出现，商品名称与数量不能代替这两类资料。可用相关问题检查是否召回了其他商品说明，以及输出是否把它误归到本订单。取得对应来源后复测，核新增片段在过滤、排序和引用各阶段的位置，保留原文条件。结果相关度高不意味着商品属性已核全，仍需逐项检查实际证据支持了哪些内容。
