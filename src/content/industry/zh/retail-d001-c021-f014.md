# 品牌会员私域运营的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

会员私域运营的选型问答，材料来自 CRM 系统、企微、POS 消费记录和小程序行为数据，日常要处理会员标签表、触达计划、优惠券规则和隐私授权记录。商品资料与选型问答要回答某款商品是否适合某类会员，判断依据是标签、消费记录和授权状态三类材料。资料更新频率为日或周，本页不涉及批量同步机制。

选型回答的准确度取决于材料是否完整。CRM 标签表能说明会员分层，POS 记录能说明购买历史，隐私授权记录能说明触达是否被允许。三类材料缺任何一类，选型结论都只能标注为待核实。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入与配置决定问答能否读到正确的材料。AI Proxy 为必需依赖，App 和 Admin 服务都需要设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会启动校验失败。AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。

模型能力要按应用所需输入核对。多模态、工具调用和思考配置分别验证。参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。检索是取回材料的过程，不承担授权判断。相似度分数不构成实体或权限过滤，检索结果不能当作触达许可。

假设演练样本：某品牌 CRM 团队纸面核对一份会员标签表，原文为「会员编号 M-2041，标签为高复购母婴人群，最近一次 POS 消费日期为 2026-03-14，隐私授权记录中营销触达状态为已授权，授权有效期至 2026-12-31」。待判定的拟稿句为「M-2041 当前可接收新品纸尿裤的企微推送」。核对对象是标签、消费日期和授权状态三项字段，判定边界是授权有效期是否覆盖拟推送日期。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 文档要求根地址不附加 /v1，与带 /v1 的写法比较 |
| AIPROXY_API_TOKEN | 假设填非空管理员 Token | 文档要求非空且与服务端一致，与应用 API Key 比较 |
| 模型能力核对 | 假设核对语言模型与索引模型各一项 | 文档要求至少一个语言模型和一个索引模型 |
| 检索范围 | 假设限定该品牌会员标签库 | 与跨库检索比较，确认库标识一致 |
| 授权状态字段 | 假设读取隐私授权记录中的触达状态 | 与标签表字段比较，确认同主体同字段 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 填成带 /v1 的完整请求地址。文档要求根地址，附加路径会导致启动校验或调用失败。
2. 用应用 API Key 代替 AIPROXY_API_TOKEN。文档要求管理员 Token 且与服务端一致，两者来源不同。
3. 把检索命中当作触达授权。检索只取回材料，授权状态要读隐私授权记录中的字段，两者不能互相替代。

## 怎么确认配好了

1. 输入假设样本中的标签表原文与拟稿句，比较拟稿句的推送日期与授权有效期 2026-12-31。授权有效期覆盖推送日期时，拟稿句获得支持；未覆盖或授权字段缺失时，结论为待核实。
2. 输入 AIPROXY_API_ENDPOINT 的假设值与文档要求，比较是否附加 /v1。不附加且 AIPROXY_API_TOKEN 非空时，接入配置满足文档条件；附加路径或 Token 为空时，记录为不符合。
3. 输入假设样本中会员编号 M-2041 的检索请求，观察返回结果是否来自该品牌会员标签库。库标识一致时记录命中材料；返回为空或库标识不一致时，记录缺口，不推断授权状态。
