# 品牌全渠道库存调拨的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

全渠道调拨处理货品在门店与仓之间流动，不处理营销触达。日常材料包括调拨申请、库存快照、门店缺货清单、调拨物流单，来源为 ERP 库存、门店 POS、电商订单与 WMS。资料更新频率为日、周。商品资料与选型问答要回答的是：某份调拨申请涉及哪些商品、当前库存快照中可调数量是多少、缺货清单与申请是否指向同一商品。模型接入与配置决定这些问答能否稳定取到材料原文。

## 这些特征在「模型接入与配置」这一环带来什么约束

系统至少需要一个语言模型和一个索引模型才能正常使用。模型 ID 是请求 Body 中 model 字段的值，全局唯一；模型名仅用于展示。模型渠道按提供商协议区分，一个模型可配置在不同渠道实现负载均衡。渠道优先级范围 1～100，数值越大越容易被优先选中。模型映射把 FastGPT 请求的模型映射到上游实际模型，例如请求 gpt-4o-test、上游收到 gpt-4o。模型状态探测仅针对已启用模型，首次失败后最多重试 3 次，4 次全部失败判定异常；正常为响应延迟不超过 30s，高延迟为成功但超过 30s。检索是取回材料，不构成授权；相关度分数不承担实体或权限过滤。

假设演练样本：材料原文为「调拨申请单 TA-0417，申请主体：华东区门店组，商品对象：SKU-8823 与 SKU-8824，申请数量各 40 件，申请日期 2026-04-17，状态：待审核。」库存快照片段为「快照日期 2026-04-17，SKU-8823 可调 25 件，SKU-8824 可调 60 件。」待判定拟稿句为：「TA-0417 已批准，SKU-8823 可调数量满足申请。」该句涉及审批与数量两项事实。

## 配置怎么定

下表为本次假设试验的配置核对项，数值为演练起点，需与材料原文或渠道测试结果比较后确认，不属官方默认值。

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| 语言模型启用 | 一个已启用语言模型 | 在系统模型页确认启用状态，与问答所需能力比对 |
| 索引模型启用 | 一个已启用索引模型 | 确认启用，索引模型决定文本块检索 |
| 模型 ID | SKU 问答专用 ID | 与渠道内模型字段一致，全局唯一 |
| 渠道优先级 | 50 | 范围 1～100，与同模型其他渠道比较 |
| 模型探测间隔 | 30 分钟 | 文档支持 5～60 整数，与告警需求比对 |
| 告警 Webhook | 一个 HTTPS 地址 | 用测试按钮推送模拟异常与恢复 |

## 容易做错的三处

1. 把待审核当作已批准。样本中 TA-0417 状态为待审核，拟稿句写「已批准」，两者在同一字段上取值不同，属矛盾。
2. 把可调数量直接等同于满足申请。SKU-8823 可调 25 件、申请 40 件，数量字段不满足；SKU-8824 可调 60 件满足，两者需分别判定。
3. 把渠道测试成功当作业务授权。渠道测试只验证模型连通性，不改变调拨申请的审批状态，也不写入任何库存记录。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较「待审核」与「已批准」是否指向同一申请单的同一状态字段。若拟稿句保留「已批准」，判定为与原文矛盾；若改为「待审核，审批结果未载明」，则与原文一致。
2. 输入库存快照片段与拟稿句，比较 SKU-8823 可调 25 件与申请 40 件。若拟稿句称满足，判定为与数量字段矛盾；若分别写明 SKU-8823 不满足、SKU-8824 满足，则与原文一致。
3. 输入空检索结果，核对下游问答是否输出「未检索到相关材料」并保留证据缺口。若下游据此断言申请已批准或库存充足，判定为越出检索范围；若仅记录缺口，则符合预期。
