# 品牌售后维修服务的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样
品牌售后维修围绕保修责任与线下维修网点展开，与平台退款流程存在明显差别。售后系统、门店订单、维修网点反馈及国家三包目录共同构成资料基础，日常文档集中在保修卡、维修工单、检测报告与换货审批。商品资料与选型问答需要把保修范围、备件匹配、审批状态讲清楚，模型接入与配置的核对对象随之落在这些文档字段上。资料按每单与每日更新，该频率影响的是资料新鲜度核对时机，不改变本页的接入配置方法。

## 这些特征在「模型接入与配置」这一环带来什么约束
模型接入依赖 AI Proxy。App 与 Admin 都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项启动校验失败，旧 OpenAI 变量或单模型自定义地址不能替代。系统至少需要一个语言模型和一个索引模型。语音识别模型仅生效一个，配置一个即可。模型 ID 是请求 Body 中 model 字段的值，全局唯一；模型名可自定义。渠道测试与页面测试会实际发送请求，用于初步检查模型是否工作。模型状态探测仅覆盖已启用模型，首次失败后最多重试三次，四次全部失败才判定异常。检索与相似度不承担权限或实体隔离职责，检索库同向量模型的要求不扩展到外部系统。

假设演练样本。供核对的保修卡原文：“本机保修期自 2025 年 3 月 1 日起 12 个月，主板故障属保修范围，需提供购机发票。”维修工单原文：“2026 年 1 月 8 日受理，故障描述为主板不开机，客户未提供发票，工单状态为待检测。”拟交接句：“该单主板故障在保修期内，可直接安排免费换新。”待判定请求：把该拟稿句作为商品资料问答的回复内容提交人工复核。

## 配置怎么定
下表只列与本页主任务相关的官方已说明设置或实施核对项，数值为本次假设试验起点，并注明选择理由与比较对象。

| 设置或核对项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不附加 /v1 | 与文档“不要附加 /v1”的说明比较 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空管理员 Token | 与应用 API Key 区分，比较是否为空 |
| 语言模型与索引模型 | 各启用一个 | 与“至少一个语言模型和一个索引模型”比较 |
| 模型 ID 与模型名 | 模型 ID 全局唯一，模型名可自定义 | 与渠道内模型字段逐字比较 |
| 模型状态探测间隔 | 假设起点 30 分钟 | 文档支持 5～60 分钟整数，与上下限比较 |
| 检索范围核对 | 记录实际观察到的返回与空结果 | 与输入 [] 时的下游设计比较 |

## 容易做错的三处
1. 把 AIPROXY_API_TOKEN 与应用 API Key 混用。输入为环境变量配置项，比较对象是文档要求的管理员 Token，可观察结果是启动校验是否通过。
2. 把模型名当作请求标识。输入为拟稿句引用的模型展示名，比较对象是全局唯一的模型 ID，可观察结果是渠道测试中请求 Body 的 model 字段。
3. 把相似度当作权限或实体过滤。输入为一次检索请求，比较对象是文档说明的检索职责，可观察结果是返回记录是否经过独立授权核对。

## 怎么确认配好了
1. 针对假设样本的拟交接句，输入保修卡原文与维修工单原文，比较“保修期起点与时长”“是否提供发票”“工单状态”三项字段。满足条件为拟稿句的结论能被原文直接支持；本样本中发票缺失、工单为待检测，拟稿句未获支持，应记录证据缺口。
2. 针对模型接入，输入 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 配置值，比较是否为空及是否附加 /v1。满足条件为两项均非空且根地址不带 /v1；未满足时记录为配置缺口。
3. 针对检索核对，输入一次查询与明确的空结果 []，比较返回记录与下游设计。满足条件为记录实际观察到的返回内容，并另行核对授权范围；检索本身不构成授权，也不保证首条命中或全部召回。
