# 品牌商场专柜运营的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

商场专柜接受商场统一收银和扣点结算，销售小票由商场POS产生，品牌ERP与财务系统另记一套账。日频数据来自商场POS与销售小票，月频数据来自月结对账单。联营扣点合同与商场活动函是条款类材料，前者约定扣点与结算周期，后者约定活动期间的资源与费用分摊。商品资料与选型问答需要在这些材料之间做字段级核对：同一专柜、同一结算期间、同一扣点字段的取值是否一致。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务都必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。系统至少需要一个语言模型和一个索引模型才能正常使用。模型配置在管理员-模型提供商页面完成，渠道测试与模型测试是配置后的独立动作。

检索库与向量模型标识需要先核对。不同向量模型的库不可共同关联，应先核标识并排除不符合者，不执行跨模型检索来比较漏召回。相关度分数不承担权限或实体隔离职责，检索结果不构成授权。空结果可承接明确的纸面输入 `[]` 核对下游设计，不能声称虚构规则检索一定返回 `[]`。

假设演练样本：某品牌专柜2026年9月月结对账单原文载明“专柜号 A-021，结算期间 2026-09-01 至 2026-09-30，联营扣点 18%，活动费分摊 2400 元”。同月商场活动函原文载明“活动期间 2026-09-15 至 2026-09-17，活动费分摊上限 2000 元”。待判定拟稿句为“A-021 专柜9月活动费分摊 2400 元，与活动函上限一致”。

## 配置怎么定

| 配置项 | 本次假设试验起点及理由 | 与什么值比较 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填 AI Proxy 服务根地址，不附加 `/v1` | 与部署实际服务根地址比对 |
| `AIPROXY_API_TOKEN` | 填非空管理员 Token | 与 AI Proxy 服务端配置比对 |
| 语言模型 | 启用至少一个 | 与系统最低要求比对 |
| 索引模型 | 启用至少一个 | 与系统最低要求比对 |
| 向量库标识 | 记录本库所用向量模型标识 | 与待关联库的标识比对，不符者排除 |
| 模型测试 | 对已配置渠道逐项执行 | 与渠道测试结果比对 |

## 容易做错的三处

1. 把检索结果当成授权依据。检索命中的对账单片段只说明文本存在，不说明该专柜已获准执行某笔分摊。
2. 跨向量模型直接关联。两个库使用不同向量模型时，先核标识并排除不符合者，不执行跨模型检索来比较漏召回。
3. 把待审核状态写成已完成。活动函若仅载明“待商场确认”，该分摊金额处于待核实状态，不构成已批准。

## 怎么确认配好了

1. 输入假设样本中对账单原文“联营扣点 18%”与活动函原文“活动费分摊上限 2000 元”，比较拟稿句“分摊 2400 元，与活动函上限一致”。比较字段为活动费分摊金额与上限。观察结果：2400 元高于 2000 元上限，拟稿句的“一致”表述不成立，应记录为待核实。
2. 输入假设样本中活动函原文“活动期间 2026-09-15 至 2026-09-17”，比较拟稿句所称“9月活动费分摊”。比较字段为活动期间与结算期间。观察结果：活动函仅覆盖9月15日至17日，与整月结算期间不同，拟稿句将活动费分摊等同于整月分摊，缺少依据。
3. 输入纸面空结果 `[]`，比较下游问答在无检索命中时的输出设计。观察结果：下游应呈现无命中状态，不生成虚构条款；若输出中出现未在材料中载明的扣点或分摊数字，则记录为失败分支。
