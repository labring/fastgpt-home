# 商超供应商进场结算的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

商超供应商进场结算围绕购销或代销账款展开，供应商不一定驻场经营，日常材料集中在采购合同、送货验收单、返利协议与对账单四类。商品资料与选型问答要回答的是某个商品在某份合同下的结算条件、验收数量口径与返利扣点依据，答案来源分散在合同条款、验收记录和协议附件里。资料更新按周或按月推进，问答结果需与当期对账单口径一致。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。自 V4.17.0 起，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填服务根地址，不附加 `/v1`；AIPROXY_API_TOKEN 是管理员 Token，不能用应用 API Key 代替。系统至少需要一个语言模型和一个索引模型才能正常使用。模型能力按应用所需输入核对：多模态、工具调用与思考配置分别验证，参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。

假设演练样本：某供应商与某商超签订一份购销合同，合同编号 HT-2026-031，签署日期 2026-03-01，约定某商品结算账期为验收后 30 天，返利按季度销售额 2% 计。送货验收单 YS-2026-0412 记录 2026-04-12 验收 800 件，其中 20 件外包装破损退回。返利协议 FL-2026-007 载明季度返利以实际验收合格数量为基数。一条待判定拟稿句为：“该商品 2026 年 4 月结算数量为 800 件，返利基数为 800 件。”

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | `http://aiproxy:3000` | 文档示例形式，与附加 `/v1` 的错误写法比较 |
| AIPROXY_API_TOKEN | 假设填入非空管理员 Token | 与空值或应用 API Key 比较，确认启动校验通过 |
| 语言模型 | 启用一个已测试的语言模型 | 与未启用状态比较，确认问答可发起 |
| 索引模型 | 启用一个已测试的索引模型 | 与未启用状态比较，确认检索可用 |
| 模型测试 | 对渠道执行模型测试 | 与测试失败结果比较，确认渠道有效 |
| 模型映射 | 按渠道填写映射关系 | 与请求模型 ID 比较，确认上游收到实际模型 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 写成带 `/v1` 的完整请求地址。检查：读取该配置值，与文档要求的服务根地址形式比较，出现 `/v1` 后缀即不符合。
2. 用应用 API Key 充当 AIPROXY_API_TOKEN。检查：核对 Token 来源标识，与应用 API Key 记录比较，来源不符即不符合。
3. 将拟稿句中的 800 件直接当作结算与返利基数。检查：读取验收单 YS-2026-0412，与拟稿句数量比较，未扣除 20 件退回即与验收合格数量口径不一致。

## 怎么确认配好了

1. 输入假设样本中的拟稿句与验收单 YS-2026-0412 原文，比较拟稿句的 800 件与验收单的合格数量 780 件，拟稿句未体现退回扣减则判定为待修正。
2. 输入返利协议 FL-2026-007 中“季度返利以实际验收合格数量为基数”一句，比较拟稿句的返利基数 800 件与该条款基数口径，两者不一致则判定为未获支持。
3. 输入合同 HT-2026-031 的账期条款，比较拟稿句是否载明结算时点，拟稿句未提及账期则记录为证据缺口，保留待核实状态。
