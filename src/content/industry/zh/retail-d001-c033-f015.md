# 外汇收结汇与贸易名录的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样
本页处理外汇收结汇与贸易名录场景下，商品资料与选型问答的知识库检索与召回。该品类与信用证审单的差别在于：收结汇关注外汇资金与贸易背景真实性，不审全套信用证单据。资料以收汇水单、贸易合同、发票、外汇业务登记资料为主，来源包括国家外汇管理局政策、银行网银、企业财务账和海关出口数据。检索环节要面对主体名称、金额、币种、登记状态等字段在不同材料中的对应关系，这些字段的完整性直接决定召回内容能否支撑后续核对。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，操作时先核向量模型标识，排除不符合者，并记录实际观察。语义检索、全文检索与混合检索各自适用不同问法：编号、型号、专有名词适合全文或混合检索；自然语言问法适合语义或混合检索。最低相关度仅在语义检索或使用结果重排时生效，且它是过滤阈值，不承担权限或实体隔离功能。引用上限以 token 为单位，影响单次返回内容的完整程度。问题优化用于指代消除和问题扩展，会增加一次模型调用。图片检索须有图像输入及对应模型能力，重排须具备模型并按设置启用，文档列出的可选路径不表示每次请求全部执行。

假设演练样本：材料原文一：“境内收款人：华昌纺织有限公司；收汇金额：USD 48,200.00；收汇日期：2025年3月12日；交易附言：货款。”材料原文二：“出口商：华昌纺织有限公司；合同号：HC-2025-018；发票号：INV-0312；金额：USD 48,200.00。”待判定拟稿句：“华昌纺织有限公司该笔 USD 48,200.00 收汇对应合同 HC-2025-018，贸易背景已核实。”判定要点：两份材料主体一致、金额一致、期间一致，但“贸易背景已核实”属于业务结论，材料未载明核实动作与结论，该句未获支持。

## 配置怎么定
| 配置项 | 本页相关设置或核对项 | 与样本的对应 |
| --- | --- | --- |
| 关联的知识库 | 关联使用相同向量模型的知识库，逐个核对向量模型标识 | 收汇水单与合同资料须同模型方可共同关联 |
| 搜索模式 | 按测试问题比较语义、全文与混合检索 | 样本含合同号、发票号，适合全文或混合检索 |
| 引用上限 | 单位为 token，用长短不同的实际资料测试内容完整性 | 本次假设试验起点设为 2000 token，理由是该样本含两组材料；与 1000 token 比较内容是否被截断 |
| 最低相关度 | 仅在语义检索或使用结果重排时生效，先标注相关与无关样本再调阈值 | 本次假设试验起点设为 0.4，与 0.2 比较无关片段是否被过滤 |
| 问题优化 | 用于指代消除和问题扩展，比较原问题与优化后问题的主体是否被改错 | 追问“这笔对应哪个合同”时核对主体是否仍为华昌纺织 |
| 结果重排 | 须具备重排模型并按设置启用，重排得分用于过滤 | 候选较多时启用，核对合同号是否排在前面 |

## 容易做错的三处
1. 把最低相关度当作权限或实体过滤。输入样本问句“华昌纺织的收汇资料”，比较返回内容是否含其他主体记录，观察是否出现非华昌纺织的条目；相关度阈值不排除无关主体，需另接权限实现。
2. 跨向量模型强行共同关联。输入两个知识库的向量模型标识，比较是否一致，观察关联后检索是否可用；标识不同时排除该库，记录观察，不推断漏召回或冗余结果。
3. 把拟稿句中的业务结论当作已核实事实。输入材料原文与拟稿句，比较“贸易背景已核实”是否有材料依据，观察材料是否载明核实动作；未载明时记为未获支持，保留证据缺口。

## 怎么确认配好了
1. 输入假设样本两份材料原文与拟稿句，比较拟稿句的主体、金额、合同号是否与材料一致，观察“贸易背景已核实”是否有材料依据；一致部分通过，结论部分记为未获支持。
2. 输入样本问句并分别用全文检索与混合检索，比较合同号 HC-2025-018 是否出现在引用内容中，观察引用上限设为 2000 token 时两组材料是否完整返回；未返回时记录为未命中，不保证首条命中。
3. 输入明确的纸面空结果 `[]`，比较下游设计是否承接空引用链路，观察输出链路是否走通；不声称虚构规则检索一定返回 `[]`。授权状态、签署与合同生效是不同事实，检索结果不构成授权执行。
