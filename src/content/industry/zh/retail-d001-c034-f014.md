# 外贸出口退税申报的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

外贸出口退税申报在货物出口后做税务凭证匹配，主要数据来自电子税务局、出口退税申报系统、海关电子信息与财务账。日常文档包括出口退免税申报表、出口报关单、进货发票与收汇凭证。商品资料与选型问答要围绕这些文档做检索与回答，模型接入与配置决定回答能否引用正确字段。

## 这些特征在「模型接入与配置」这一环带来什么约束

系统至少需要一个语言模型和一个索引模型才能正常使用。AI Proxy 为必需依赖，App 和复用 App/Service 配置的 Admin 服务都必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。`AIPROXY_API_ENDPOINT` 填服务根地址，不要附加 `/v1`。模型渠道、模型映射与自定义请求地址在管理员-模型提供商页面配置。模型状态探测仅针对已启用的系统模型，探测间隔支持 5～60 分钟之间的整数。

假设演练样本：某外贸企业单证员在 2026 年 3 月整理一批出口货物资料，材料原文为“出口报关单号 20260301001，出口日期 2026-03-01，商品名称钢制紧固件，数量 12000 件；对应进货发票号 20260305002，开票日期 2026-03-05，金额与报关单一致”。待判定拟稿句为“该批货物已完成退税申报并取得退税款”。原文只含报关单与进货发票的匹配信息，未载明申报状态与退税到账记录，该拟稿句属于未获支持。

## 配置怎么定

下表围绕本页样本列出与本功能、主任务相关的官方已说明设置或实施核对项。假设试验起点仅用于本次纸面对照，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 假设填 `http://aiproxy:3000` | 核对不附加 `/v1`，与部署模板一致 |
| `AIPROXY_API_TOKEN` | 假设填非空管理员 Token | 与服务端配置比对，确认非空 |
| 语言模型 | 假设启用一个语言模型 | 核对模型类型为 llm 且状态为已启用 |
| 索引模型 | 假设启用一个索引模型 | 核对模型类型为 embedding 且状态为已启用 |
| 模型映射 | 假设将 `gpt-4o-test` 映射到 `gpt-4o` | 核对请求模型与实际上游模型对应关系 |
| 模型状态探测 | 假设探测间隔设为 30 分钟 | 核对为 5～60 分钟之间的整数 |

检索库与向量模型关联须先核标识。跨不同向量模型的库不可共同关联，只核标识、排除不符者并记录实际观察。检索不承担授权判断，相似度设置不排除无关业务或未授权记录。空结果可用明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回 `[]`。

## 容易做错的三处

1. 把 `AIPROXY_API_ENDPOINT` 填成带 `/v1` 的完整请求地址。输入为假设的 `http://aiproxy:3000/v1`，比较对象为文档要求的服务根地址，观察结果是该值附加了 `/v1`，与要求不符。
2. 将拟稿句“该批货物已完成退税申报并取得退税款”当作已确认事实。输入为上述材料原文与拟稿句，比较对象为原文是否载明申报状态与退税到账，观察结果是原文只含报关单与进货发票匹配信息，拟稿句未获支持。
3. 把检索命中的相似记录当作已授权操作。输入为一次检索返回的相似文档，比较对象为是否存在授权或审批记录，观察结果是仅有相似度分数，无授权依据，不能视为已授权。

## 怎么确认配好了

1. 输入假设的 `AIPROXY_API_ENDPOINT` 填写值，比较其是否为服务根地址且不带 `/v1`，观察结果为不带 `/v1` 且与部署模板一致时满足条件。
2. 输入上述材料原文与拟稿句，比较拟稿句是否被原文载明，观察结果为原文未载明申报状态与退税到账时，拟稿句应标记为未获支持。
3. 输入一次检索返回结果与对应授权记录，比较是否存在同主体、同期间的授权依据，观察结果为仅有相似度分数而无授权记录时，不得进入执行环节，记录为证据缺口。
