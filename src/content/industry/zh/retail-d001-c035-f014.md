# 外贸退运与索赔的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

退运索赔处理出口后的逆向物流与责任认定，资料来自客户邮件、质检报告、海关系统与保险理赔系统，日常文档包括退运协议、索赔函、质量报告与退运报关单。商品资料与选型问答要回答的是：某批货物能否退运、由谁承担费用、索赔依据哪些质量结论。这些资料按案更新，每案一次，不存在固定周期。

## 这些特征在「模型接入与配置」这一环带来什么约束

本页只解决模型接入与配置。资料中的主体、对象、状态与有效范围决定检索命中的内容能否用于回答，模型接入本身不产生授权。AI Proxy 为必需依赖，App 与 Admin 须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项会启动校验失败；旧 OpenAI 变量不能替代。模型渠道在管理员-模型提供商页面配置，模型 ID 是请求 Body 中 model 字段的值，全局唯一。系统至少需要一个语言模型和一个索引模型。检索结果与相似度不承担权限或实体隔离，跨不同向量模型的库不可共同关联。

假设演练样本：纸面材料一为《退运协议》摘录，甲方为某出口商，乙方为某境外买方，载明“本协议自双方签署之日起生效”，落款处甲方已签字，乙方签字栏空白。纸面材料二为《质量报告》摘录，检验对象为 2025 年 3 月批次货物，结论为“外观不符合合同附件二约定”。待判定拟稿句为“双方已达成退运协议，退运费用由买方承担”。该拟稿句含两项待核事实：协议是否生效、费用承担是否有依据。材料未载明费用条款。

## 配置怎么定

配置围绕上述样本核对，不把数据库内部实现当作每页必配项。表中数值为本次假设试验起点，说明选取理由与比较对象。

| 配置项 | 本次假设起点 | 核对理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | `http://aiproxy:3000` | 官方示例形式，不附加 `/v1`；与部署实际根地址比较 |
| AIPROXY_API_TOKEN | 非空管理员 Token | 官方要求与服务端一致；与应用 API Key 比较，二者不可互换 |
| 语言模型启用 | 启用一个 llm | 官方要求至少一个语言模型；与索引模型数量分别核对 |
| 索引模型启用 | 启用一个 embedding | 官方要求至少一个索引模型；与语言模型分别核对 |
| 模型渠道模型 ID | 与渠道内模型一致 | 官方说明模型 ID 全局唯一；与启用模型的模型 ID 比较 |
| 模型探测间隔 | 30 分钟 | 官方支持 5～60 分钟整数；与本次观察周期比较 |

## 容易做错的三处

1. 把 AIPROXY_API_TOKEN 填成应用 API Key。输入为部署配置中的 Token 值，比较对象为 AI Proxy 服务端管理员 Token，观察结果是启动校验是否通过；若不一致，启动校验失败。
2. 把“甲方已签字、乙方空白”读成协议已生效。输入为样本《退运协议》落款，比较对象为“自双方签署之日起生效”这一约定，观察结果是能否找到乙方签署记录；未找到时该事实未获支持。
3. 把《质量报告》的外观结论直接当作费用承担依据。输入为样本质量报告结论，比较对象为费用条款，观察结果是材料中是否存在费用约定；样本未载明，该拟稿句的费用部分待核实。

## 怎么确认配好了

1. 针对拟稿句“双方已达成退运协议”，输入为样本《退运协议》落款与生效条款，比较乙方签字栏是否空白，观察结果为：乙方签署记录缺失，该句所述“已达成”未获支持，应改为待核实。
2. 针对拟稿句“退运费用由买方承担”，输入为两份样本材料全文，比较是否存在费用承担条款，观察结果为：材料未载明费用条款，该部分保持未获支持，不补造授权或生效条款。
3. 针对模型接入，输入为 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 两项配置，比较其与服务端实际值是否一致，观察结果为：两项均非空且一致时启动校验通过；任一项缺失或为空时校验失败。检索环节只核对模型标识并排除不符合者，空结果以明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索必然返回空。
