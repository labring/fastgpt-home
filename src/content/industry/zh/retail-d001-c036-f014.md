# 多仓分仓与库存同步的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

在多仓分仓与库存同步的商品资料与选型问答中，本页说明FastGPT的模型接入与配置如何衔接资料。分仓资料选型保留库存时间、仓别与调拨阶段，不把可售同步当成现货承诺。所用场景为自拟文字测试。

## 这些特征在「模型接入与配置」这一环带来什么约束

假设库存同步表写甲仓快照，乙仓调拨单仅为申请，分仓规则要求先核收货地区。选型问答应检查接入模型是否实际收到仓别、快照时间和地区限制，同时检查是否仅收到同名商品而丢失这些限制。历史库存不能证明当前可用，调拨申请也不是收货入账。此例没有真实数量、调拨执行或平台库存接口调用，回答只解释现有材料怎样支持选仓判断，以及还缺哪些时点和收货信息。

## 配置怎么定

| 分仓选型输入 | 假设限制 | 复核线索 |
| --- | --- | --- |
| 甲仓 | 历史快照 | 保留记录时间 |
| 乙仓 | 调拨申请 | 核实际收货 |
| 地区 | 规则限定范围 | 对照收货地址 |
| 商品 | 同名不并仓 | 分别核仓别数量 |
| 输出 | 拟交系统 | 解析与事实分查 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `AI Proxy依赖` | 按实际版本核服务、渠道与应用。 |
| `AIPROXY_API_ENDPOINT` | 使用AI Proxy服务根地址。 |
| `AIPROXY_API_TOKEN` | 管理员Token非空且与服务端一致。 |
| `模型能力` | 按实际输入路径验证所需能力。 |
| `应用参数` | 接口同名字段未必覆盖应用设置。 |

## 容易做错的三处

- 同步表的快照时间未传入而回答承诺当前现货时，核请求字段与引用位置，补齐时间再问可确认范围。

- 乙仓调拨申请被当成甲仓可售库存时，对仓别、出入库方向和收货凭证，不能因商品同名合并数量。

- 规则的适用地区丢失而向所有地区推荐同仓时，逐句对收货地区条件与实际提问，查输出是否扩大适用对象。

## 怎么确认配好了

用同一商品的不同仓资料做对照，先问现有记录分别说明什么，再补对应收货记录。对比输出是否仅更新被新证据支持的仓别与阶段。文字表与文件上传路径分别测；结构化返回须同时核字段可解析及取值有据。模型连通不执行库存同步或调拨，真实写回要另外实现并核业务授权。
