# 多仓分仓与库存同步的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样
多仓分仓在订单路由阶段决定发货仓，资料来自 WMS、OMS、ERP 库存与平台库存接口，日常文档包括分仓规则、库存同步表、调拨单与缺货预警。检索问答要回答的是“某商品在某仓是否可售、按哪条规则选仓”，答案依赖主体、仓库、时间与状态字段齐全。资料更新频率为日或小时，本页功能不据此推导批量或实时机制。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的库；不同向量模型的库不能共同关联，需先核标识并排除不符合者，不执行跨模型检索来比较漏召回。语义检索、全文检索与混合检索按测试问题比较，不预设一种模式适合全部资料。混合检索经 RRF 融合多路结果，RRF 是融合过程，不是开关。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离，检索不构成授权。引用上限以 token 为单位。问题优化用于指代消除和问题扩展。图片检索须有图像输入及模型能力，重排须具备模型并按设置启用。节点输出为数组，长度可为 0。

假设演练样本：资料原文为“华东一号仓 2025-03-01 至 2025-03-31 对 SKU-A 可售，分仓优先级为华东一号仓先于华北二号仓；华北二号仓同期对 SKU-A 处于盘点冻结。”待判定拟稿句为“SKU-A 在 2025 年 3 月由华北二号仓优先发货。”核对主体、仓库、期间与状态字段，该拟稿句与原文同字段取值互斥，属未获支持。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 依据与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联同一向量模型的库 | 核向量模型标识，排除不符合者 |
| 搜索模式 | 先语义检索，再试全文与混合 | 按样本问题比较命中内容 |
| 引用上限 | 起点设为覆盖一条完整分仓规则的 token 量 | 比较长短资料是否被截断 |
| 最低相关度 | 起点 0.3 | 先标注相关与无关样本再调 |
| 问题优化 | 多轮追问场景开启 | 比较原问题与优化后问题主体 |
| 结果重排 | 候选较多时启用 | 比较重排前后排序 |

起点仅为本次假设试验值，非官方默认。

## 容易做错的三处
1. 把不同向量模型的库共同关联。输入为两个库的向量模型标识，比较两者是否一致，观察结果为标识不符时不可共同关联。
2. 把最低相关度当作权限过滤。输入为一条越权仓库的库存记录，比较检索结果与授权范围，观察结果为检索命中不表示有权执行。
3. 把待审核调拨单当作已生效。输入为状态字段为待审核的调拨单，比较状态与拟稿句表述，观察结果为拟稿句称已生效时不成立。

## 怎么确认配好了
1. 输入假设样本原文与拟稿句，比较拟稿句与原文的仓库、期间、状态字段，观察结果为拟稿句与原文互斥，判定未获支持。
2. 输入同一向量模型标识的两个库，比较标识是否一致，观察结果为一致时方可共同关联，不一致时记录并排除。
3. 输入明确的纸面空结果 []，比较下游节点是否仍走通，观察结果为引用长度可为 0 且链路继续，不声称虚构规则检索必返回 []。
