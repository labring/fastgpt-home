# 大卖场生鲜联营柜台的商品资料与选型问答：文档解析与分块

## 这个品类的数据长什么样
大卖场生鲜联营柜台常由供应商驻场经营并按销售分成，商品资料与选型问答需要同时面对联营合同、日销售报表、损耗单、食品进货查验记录。这些材料来源不同、责任主体不同，一份文档里可能同时出现商超生鲜部、联营供应商与门店店长的字段。日销售报表与食品进货查验记录按日或每批产生，资料更新频繁，解析与分块若把条件句与所约束的正文拆开，核对时容易把适用范围读错。食安处罚、毛利争议、顾客索赔是出错后的后果，因此分块要保留能回指原文的文档身份与版本。

## 这些特征在「文档解析与分块」这一环带来什么约束
FastGPT 的知识库由库、集合和数据组成，最小搜索单位是库，集合仅用于分类管理。向量检索使用 PostgresSQL 的 PG Vector 插件，索引为 HNSW，MongoDB 的 dataset.datas 表存储原数据，indexes 字段记录对应向量 ID，一组数据可对应多个向量。检索时先召回向量，再按向量 ID 去 MongoDB 找原数据，同一组原数据合并后向量得分取最高分。分段应按具体资料结构切分，让条件、说明与所约束的内容保持在一起。语义检索、全文检索、混合检索、结果重排、问题优化是可选路径，图片检索须有图像输入且模型具备相应能力，重排须具备模型并按设置启用。RRF 是混合结果的融合过程。相似度与相关度不承担权限或实体隔离，检索库同向量模型的要求不能扩展为外部系统也要同模型。

假设演练样本：供核对的联营合同原文为“甲方为某某商超生鲜部，乙方为某某蔬菜供应商，双方就某门店三楼生鲜联营柜台按销售分成经营，合同期间为某年某月某日至某年某月某日，损耗分摊按月度盘点结果结算”。待判定拟稿句为“该供应商已完成本月损耗分摊结算”。原文只载明结算方式与合同期间，未载明本月结算是否完成，该拟稿句未获支持。

## 配置怎么定
| 配置或核对项 | 本页对应设置 | 说明与边界 |
| --- | --- | --- |
| 知识库与集合 | 按资料类型建立集合，搜索以库为单位 | 集合仅分类，与搜索效果无关 |
| 向量检索器 | PostgresSQL 的 PG Vector，索引 HNSW | 仅用于向量检索 |
| 原数据存储 | MongoDB 的 dataset.datas | indexes 记录向量 ID |
| 多向量映射 | 一组数据可对应多个向量 | 得分取最高分 |
| 搜索模式 | 语义检索、全文检索或混合检索 | 混合检索经 RRF 融合 |
| 引用上限 | 以 tokens 计，非 top k | 本次假设试验起点可设为 2000 tokens，理由是该值便于观察长 chunk 被裁剪情况，与 1000 tokens 的结果比较 |

## 容易做错的三处
1. 把拟稿句中的“已完成本月损耗分摊结算”当作合同原文已载明的事实。检查时输入合同原文与拟稿句，比较主体、对象、期间、状态四个字段，只有原文同字段明确互斥取值才判矛盾，未载明则记为未获支持。
2. 把上传成功当作检索已更新。检查时输入变更后的资料与一次术语查询，比较实际训练与索引状态，观察到检索结果仍返回旧内容则记录待复核。
3. 用相似度分数排除无关业务或未授权记录。检查时输入一条自然语言查询，比较返回内容与目标检索范围，相似度不承担权限过滤，越权内容应通过访问控制处理。

## 怎么确认配好了
1. 输入假设样本中的合同原文与拟稿句，比较主体、对象、期间、状态字段，拟稿句在原文无对应载明时记为未获支持，满足条件即为通过。
2. 输入术语、编号与自然语言三类查询，比较分段是否保留条件与所约束内容，出现条件与正文被拆离即记录失败分支。
3. 输入明确的纸面空结果 [] 核对下游设计，比较下游是否按空引用处理，不声称虚构规则检索一定返回 []。检索观察只记录实际返回，不保证首条命中或全部召回。
