# 大卖场生鲜联营柜台的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

大卖场联营柜台由供应商驻场经营并按销售分成，商品资料、进货查验记录与损耗单分属商超生鲜部、联营供应商和门店店长三方掌握。商品资料与选型问答需要把联营合同、日销售报表、损耗单、食品进货查验记录作为知识来源，供门店人员查询单品规格、供货状态与凭证要求。资料按日或按批更新，问答结果只反映已入库文本的内容。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与 Admin 必须配置 AIPROXY_API_ENDPOINT 与非空 AIPROXY_API_TOKEN，缺少任一项启动校验失败。模型渠道在管理员-模型提供商页面创建，模型测试通过后才可启用。检索命中不等于授权：知识库相似度不承担门店权限或供应商归属的过滤职责，跨不同向量模型的库不可共同关联。

假设演练样本：某门店生鲜部留存一份纸质《联营柜台商品资料交接单》，正文写明“供应商甲自2026年3月1日起在A门店经营叶菜类柜台，供货品类为小白菜、菠菜；2026年3月5日供应商甲提交损耗单一份，数量3公斤，待生鲜部核对”。另有一条待判定拟稿句：“供应商甲已获准自2026年3月1日起经营A门店全部生鲜品类。”该句与原文的品类范围不一致，且原文未载明全品类授权。

## 配置怎么定

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 根地址，不带 /v1 | 与文档要求一致，比较是否附加了 /v1 或 /chat/completions |
| AIPROXY_API_TOKEN | 非空管理员 Token | 与服务端配置一致，比较是否误用应用 API Key |
| 语言模型 | 启用一个已测试通过的模型 | 系统至少需一个语言模型，比较渠道测试结果是否为成功 |
| 索引模型 | 启用一个已测试通过的模型 | 系统至少需一个索引模型，比较索引模型是否已启用 |
| 模型探测间隔 | 本次假设起点 30 分钟 | 文档允许 5～60 分钟整数，比较填写值是否落在该区间 |
| 探测告警 Webhook | 本次假设留空 | 留空时不推送，比较是否配置了接收端 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 填成完整对话请求地址并附加 /v1，启动校验会因地址形态不符而失败。检查输入是否为服务根地址，比较是否含 /v1 或 /chat/completions，观察启动日志是否报校验失败。
2. 用应用 API Key 充当 AIPROXY_API_TOKEN，Token 与服务端不一致。检查 Token 来源，比较两端配置值，观察模型调用是否返回鉴权错误。
3. 把检索命中的商品资料当作供应商授权凭证，据相似度结果判定供应商甲经营全品类。检查拟稿句的品类范围，比较原文“叶菜类”与拟稿“全部生鲜品类”，观察二者是否同字段互斥。

## 怎么确认配好了

1. 输入上述交接单原文与拟稿句，比较原文品类范围“小白菜、菠菜”与拟稿“全部生鲜品类”，若二者不一致则该拟稿句未获支持，应标记待核实。预期结果为范围不符，不声称已实测。
2. 输入交接单中“2026年3月5日损耗单数量3公斤，待生鲜部核对”，比较“待核对”与“已核对”，若原文只有待核对状态，则核对完成事实未获支持。预期结果为状态未确认。
3. 输入一条仅含供应商甲叶菜类范围的查询，比较返回片段是否落在该范围内；若返回空结果，以纸面输入 [] 核对下游展示逻辑，不推断规则检索必然返回空。预期结果为按实际返回记录，不保证首条命中或全部召回。
