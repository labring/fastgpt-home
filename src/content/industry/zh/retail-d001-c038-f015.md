# 大卖场生鲜联营柜台的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样

大卖场生鲜联营柜台常由供应商驻场经营并按销售分成，联营合同、日销售报表、损耗单与食品进货查验记录构成日常资料主体。这些资料来自POS系统、供应商送货单、食品安全台账和门店盘点，更新频率为日或每批。商品资料与选型问答需要从上述文档中检索规格、结算口径、损耗归属与查验状态，检索结果直接影响食安处罚、毛利争议与顾客索赔的后续处理。资料中的主体、对象、状态与有效范围是判断基础，检索环节只负责召回候选内容，不承担授权确认。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的库，跨不同向量模型的库不可共同关联。搜索模式可选语义检索、全文检索或混合检索，混合检索通过RRF融合多路结果，Rerank对候选文本二次排序，最低相关度仅在语义检索或使用结果重排时生效。引用上限以token为单位，空引用内容以数组输出且长度可为0。问题优化用于指代消除和问题扩展，会增加一次模型调用。检索不构成授权，相似度得分不承担实体隔离或权限过滤功能。

假设演练样本：某联营合同文本载明“甲方为××大卖场生鲜部，乙方为驻场供应商，柜台销售按日分成，损耗由乙方承担，合同有效期自2025年3月1日至2026年2月28日”。食品进货查验记录载明“2025年4月10日，批次A-0410，查验合格”。一条待判定拟稿句为“该供应商2025年4月损耗由甲方承担”。核对时需比较拟稿句与合同原文的损耗归属字段，合同明确损耗由乙方承担，拟稿句与原文同字段取值互斥，属于未获支持。

## 配置怎么定

| 配置项 | 本页相关设置或核对项 | 说明 |
| --- | --- | --- |
| 关联知识库 | 选择使用相同向量模型的知识库 | 跨模型库不可共同关联，先核标识并排除不符者 |
| 搜索模式 | 按测试问题比较语义、全文与混合检索 | 不预设一种模式适合全部资料 |
| 引用上限 | 本次假设试验起点设为2000 token | 选此值因联营合同段落较长，与1000 token比较内容完整性 |
| 最低相关度 | 先标注相关与无关样本再调阈值 | 仅在语义检索或结果重排时生效 |
| 问题优化 | 比较原问题与优化后问题 | 核对主体是否被改错，不保证首条命中 |
| 结果重排 | 具备模型且按设置启用 | 可选路径，不表示每次请求全部执行 |

## 容易做错的三处

1. 把检索得分当作权限过滤。输入为一条普通商品问题，比较检索返回内容与当前用户可访问范围，观察是否出现越权资料。相关度分数不承担实体隔离功能，检索库同向量模型要求不能扩展为外部系统也同模型。
2. 把待审核状态当作已批准执行。输入为一份待审核的损耗分摊单，比较其状态字段与“已批准”取值，观察是否被当作已完成分摊。待审核不证明缺少操作权限，也不等于批准。
3. 把报价有效期当作供货期限。输入为供应商报价单，比较报价有效期字段与合同供货期限字段，观察是否混用。两个字段不同，报价有效期不表示供货期限。

## 怎么确认配好了

1. 输入假设样本中的合同原文与拟稿句“该供应商2025年4月损耗由甲方承担”，比较损耗归属字段，若合同明确损耗由乙方承担，则拟稿句未获支持，需记录证据缺口。
2. 输入一份待审核损耗单，比较其状态字段与已批准取值，若状态为待审核，则不能判定为已完成分摊，需保留待核实结论。
3. 输入空引用内容数组[]，比较下游设计是否接受长度为0的输出，若下游未定义空结果处理，则记录该缺口，不声称检索一定返回空数组。
