# 天猫旗舰店日常运营的商品资料与选型问答：向量模型与索引

## 这个品类的数据长什么样

天猫旗舰店日常运营的商品资料与选型问答，围绕商品发布页、品牌授权书、发货承诺记录、售后工单展开。与京东POP店相比，天猫旗舰店更强调品牌授权、旗舰店身份和天猫积分赔付规则。资料来自天猫商家后台、天猫规则中心、ERP订单表与客服聊天记录，更新频率为日、每单。这些特征意味着，选型问答既要处理自然语言问法，也要处理编号、型号、专有名词等精确查询，检索结果需要回到原文核对，不能只看向量得分。

## 这些特征在「向量模型与索引」这一环带来什么约束

FastGPT 采用 Embedding 方案构建知识库，向量距离越小代表相似度越大。影响向量搜索精度的因素包括向量模型质量、数据质量与检索器精度。一组数据可以对应多个向量，索引内容更聚焦时检索精度提高，同时牺牲一定检索范围。检索时先召回向量，再按向量 ID 去 MongoDB 的 dataset.datas 表寻找原数据，同一组原数据被多路命中时合并，向量得分取最高。关联检索的知识库须使用相同向量模型，此处只核实际模型与输入类型，不把该要求扩展到外部系统。图片检索还取决于入库时是否生成图片描述或图片向量。

假设演练样本：某天猫旗舰店商品发布页草稿写明“本店销售某品牌保温杯，容量500毫升，发货承诺为付款后48小时内发出”，品牌授权书载明授权有效范围为2026年1月1日至2026年12月31日，售后工单记录“买家咨询是否支持七天无理由退货”。一条待判定拟稿句为“该商品支持七天无理由退货，发货承诺为48小时”。样本主体为店铺运营人员，对象为上述商品资料，状态为草稿与待核实，有效范围以授权书载明期间为准。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 样本同时含自然语言问法与容量、型号类精确词，与纯语义检索结果比对 |
| 引用上限 | 假设起点 3000 tokens | 因样本 chunk 长度差异大而设，与 2000、4000 两档比较引用原文完整度 |
| 最低相关度 | 假设起点 0.4 | 与 0.3、0.5 比较过滤后候选数量，仅在语义检索或结果重排时生效 |
| 问题优化 | 开启 | 样本含连续追问，与关闭状态比较指代消除后的检索词 |
| 结果重排 | 启用 | 候选较多时二次排序，与仅用 RRF 融合的结果比较排序 |
| 向量模型 | 与关联知识库一致 | 先核实际模型标识与输入类型，排除不一致者，不执行跨模型检索 |

## 容易做错的三处

1. 把向量得分当作授权或状态结论。样本中授权书有效范围与拟稿句的退货承诺属于不同字段，向量相似度高不代表拟稿句获得支持。检查输入为拟稿句与授权书原文，比较两者是否同主体、同期间、同字段，观察结果为拟稿句未获支持。
2. 把待审核状态写成已批准。样本商品发布页为草稿，品牌授权书为待核实材料，二者均不构成上架或赔付依据。检查输入为草稿状态标记与拟稿句，比较是否存在签署或生效记录，观察结果为证据缺口保留。
3. 把检索当作权限过滤。关联知识库须同向量模型，检索只返回引用内容，不判断运营人员是否有权查看某条记录。检查输入为关联库标识与访问范围，比较引用来源是否落在有访问权的范围内，观察结果为越界来源需另行核实。

## 怎么确认配好了

1. 输入假设样本的拟稿句“该商品支持七天无理由退货，发货承诺为48小时”，比较其与商品发布页草稿、品牌授权书原文的同字段取值，观察拟稿句中的退货承诺在原文中是否有对应载明；若原文未载明，记录为未获支持。
2. 输入样本中的售后工单问句，比较开启与关闭问题优化后的检索词，观察指代是否被补全为含主体与对象的完整问题；若检索词仍缺失主体，记录为待优化。
3. 输入样本的容量与型号类精确词，比较混合检索与纯语义检索返回的引用原文，观察编号、型号是否命中；若未命中，记录为需改用全文检索或混合检索，并核对入库索引是否已生成。
