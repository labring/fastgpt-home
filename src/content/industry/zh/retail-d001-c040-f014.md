# 客服咨询知识库维护的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

本页处理客服咨询知识库维护中的商品资料与选型问答，涉及 FAQ 条目、话术模板、商品参数表与升级工单。知识库维护属于前置问答资料整理，不直接审批退款，因此模型接入与配置的目标是让选型答复可追溯到已维护的商品参数与标准话术。资料更新按周或按月发生，接入配置的核对节奏跟随资料版本，不因资料变动自动触发模型调用。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。自 V4.17.0 起，App 与复用 App/Service 配置的 Admin 都必须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两项。AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。系统至少需要一个语言模型和一个索引模型。模型 ID 是请求 Body 中 model 字段的值，全局唯一；模型名可自定义。模型映射示例中，FastGPT 请求 gpt-4o-test，AI Proxy 向上游发送 gpt-4o。模型探测仅针对已启用模型，首次失败后最多重试 3 次，4 次全部失败才判定异常。检索与相似度不构成权限或实体隔离，检索库的向量模型一致性要求不能外推到外部系统。

## 配置怎么定

假设演练样本：知识库运营在 2026 年 10 月收到一条待判定拟稿句「A 型电水壶支持 1.7L 容量，可放入洗碗机清洗」。供核对的商品参数表原文为：「A 型电水壶，容量 1.7L，壶身材质 304 不锈钢，不支持洗碗机清洗，仅可手洗。」拟稿句与原文在清洗方式字段上取值互斥，容量字段一致。以下配置围绕该样本的核对动作。

| 配置或核对项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | http://aiproxy:3000 | 官方示例根地址，与附加 /v1 的写法比较 |
| AIPROXY_API_TOKEN | 非空管理员 Token | 与服务端配置值比较，排除空值 |
| 语言模型 | 一个已启用模型 | 与「至少一个语言模型」要求比较 |
| 索引模型 | 一个已启用模型 | 与「至少一个索引模型」要求比较 |
| 模型映射 | gpt-4o-test 映射 gpt-4o | 与请求 Body 中 model 字段比较 |
| 探测间隔 | 假设 30 分钟 | 位于 5～60 分钟区间，与区间边界比较 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 写成带 /v1 的完整请求地址。核对输入为环境变量值与官方根地址写法，观察是否出现路径后缀。
2. 用应用 API Key 充当 AIPROXY_API_TOKEN。核对输入为 Token 来源与服务端管理员 Token，观察两者是否一致且非空。
3. 把拟稿句中「可放入洗碗机清洗」当作已获参数表支持。核对输入为拟稿句与参数表清洗方式字段，观察两处取值是否互斥。

## 怎么确认配好了

1. 输入上述拟稿句与参数表原文，比较清洗方式字段。参数表载明「不支持洗碗机清洗」，拟稿句写「可放入洗碗机清洗」，同字段取值互斥，判定为矛盾，需退回改写。
2. 输入上述拟稿句与参数表原文，比较容量字段。参数表载明 1.7L，拟稿句写 1.7L，两者一致，该字段获支持。
3. 输入模型映射配置与请求 Body 中 model 字段，比较映射关系。配置为 gpt-4o-test 映射 gpt-4o，请求使用 gpt-4o-test，映射关系成立；上游实际模型标识需以调用日志观察，未观察到时记录为待核实。

模型探测的告警推送、Webhook 连通性与重试结果属于外部系统行为，未实际触发时保持未知。检索返回空结果时，可用明确的纸面输入核对下游设计，不推断虚构规则必返回空数组。
