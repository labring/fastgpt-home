# 平台促销报名与价格管理的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样
平台促销报名与价格管理围绕活动报名表、促销价审批单、库存锁定表、活动复盘表展开，核心数据是价格、库存和活动节奏。资料给出的更新频率为周和每场活动，日常处理的是报名、审批、锁定与复盘四类文档。商品资料与选型问答要求从这些材料中检索出可核对的字段，例如某场活动的报名状态、审批签署状态、库存锁定数量与价格有效期。检索结果只提供引用内容，不构成报名提交、审批通过或库存扣减。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的库，跨不同向量模型的库不可共同关联。搜索模式包含语义检索、全文检索与混合检索，混合检索通过 RRF 融合多路结果，RRF 是融合过程，不写成开启开关。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，会额外调用模型。空引用内容以数组输出，长度可以为 0，链路仍走通。

假设演练样本：材料原文为“2025年3月1日提交的华东区A商品活动报名表，报名状态为待审核，促销价审批单尚未签署，库存锁定表数量为0。”待判定拟稿句为“该活动报名已通过审批，库存已锁定。”原文只显示待审核与未签署，拟稿句声称已通过审批并锁定库存，两者在同一字段上取值互斥，属于未获支持。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联含活动报名表、审批单、锁定表、复盘表的同一向量模型库 | 跨模型库不可共同关联，先核向量模型标识 |
| 搜索模式 | 先分别用语义检索与全文检索测试同一问题 | 按测试问题比较两种模式，不预设一种适合全部资料 |
| 引用上限 | 以 token 为单位，用长短不同的实际资料测试内容完整性 | 比较返回内容是否截断，再调整上限 |
| 最低相关度 | 先标注相关与无关样本，再观察过滤效果 | 该值仅在语义检索或结果重排时生效 |
| 问题优化 | 对含指代的追问开启，对已明确问题关闭 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 在具备重排模型且按设置启用时使用 | 重排得分可用于过滤，不替代权限判断 |

## 容易做错的三处
1. 把检索命中当成审批或授权完成。输入为上述待审核报名表，比较报名状态字段与拟稿句，检索返回“待审核”原文时，拟稿句“已通过审批”未获支持。
2. 把最低相关度当成实体或权限过滤。输入为无关业务问题，比较返回内容与权限范围，相关度分数不排除未授权记录，权限需下游实现。
3. 把 RRF 写成可开启的开关。输入为混合检索配置，比较文档描述与配置项，RRF 是融合过程，不存在对应开关。

## 怎么确认配好了
1. 输入上述假设原文与拟稿句，比较报名状态与审批签署字段，观察检索返回原文是否含“待审核”与“尚未签署”，若含则拟稿句未获支持。
2. 输入明确纸面空结果 `[]`，比较下游设计是否按空引用内容继续走通链路，观察是否出现报错或中断。
3. 输入含指代的追问，比较原问题与优化后问题，观察主体是否被改错，若主体改变则问题优化结果需人工核对。
