# 平台多店铺矩阵管理的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

平台多店铺矩阵管理的数据来自各平台商家后台、ERP渠道价、品牌防伪系统与经销商报表。与单店广告投放相比，这一品类更关注跨店授权关系与价格秩序。店铺授权清单记录哪些店铺获得品牌方授权，价格管控表记录各渠道价格区间，窜货投诉单记录非授权店铺的销售线索，月度销售报表汇总各店出货情况。

这些材料在商品资料与选型问答中作为模型接入的输入文档。授权状态、价格区间、投诉处理进度分别来自不同文档，字段口径不一致时无法直接比对。数据更新频率为日、月两级，本页不据此推出批量同步或实时触发机制。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与 Admin 服务都需要设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填写 AI Proxy 服务根地址，不附加 /v1。旧 OpenAI 环境变量不能替代这两项配置。

模型能力需要按应用所需输入分别核对。多模态、工具调用与思考配置属于不同字段，不能假设同名对话接口字段会覆盖编排参数。检索与相关度评分不承担权限或实体隔离职责，店铺授权判断必须依据授权清单原文，不能由相似度结果代替。

假设演练样本：某品牌电商团队持有两份材料。材料一为店铺授权清单，原文写明“授权店铺：华东旗舰店，授权有效期至2026年12月31日，授权商品类目：家用电器”。材料二为价格管控表，原文写明“华东旗舰店，家用电器类目，最低零售价199元，价格管控生效期间2026年1月1日至2026年6月30日”。一条待判定的拟稿句为“华东旗舰店在2026年8月销售家用电器符合授权与价格管控要求”。核对时需比对授权有效期、价格管控生效期间与拟稿句所述日期。

## 配置怎么定

配置围绕上述样本的核对需求展开。下表列出与本功能、主任务相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不带 /v1 | 与文档要求比较，确认未附加路径后缀 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空 Token | 与应用 API Key 区分，比较两者是否混用 |
| 模型能力字段 | 按应用所需输入逐项核对 | 与文档字段说明比较，确认多模态与工具调用分别验证 |
| 知识库文件解析并发 | 采用 DATASET_PARSE_MAX_PROCESS 文档值 | 与文件解析队列实际并发比较，确认未超出配置 |
| 向量检索参数 | 采用 HNSW_EF_SEARCH 文档值 | 仅对 PG、OceanBase、openGauss 生效，比较向量库类型 |
| 模型探测间隔 | 填写 5～60 分钟之间的整数 | 与文档范围比较，确认取值在区间内 |

## 容易做错的三处

1. 将 AIPROXY_API_ENDPOINT 填写为完整模型请求地址并附加 /v1。文档要求填写服务根地址，附加路径会导致请求地址拼接错误。核对时比较填写值与文档示例格式，观察是否包含 /v1 或 /chat/completions。

2. 用应用 API Key 代替 AIPROXY_API_TOKEN。文档明确管理员 Token 必须与服务端配置一致且不能为空。核对时比较两处 Token 值，观察是否一致、是否为空。

3. 将检索相关度评分当作店铺授权判断依据。相关度评分反映文本相似程度，不承担权限或实体隔离职责。核对时比较授权清单原文中的店铺名称与有效期，观察拟稿句所述店铺是否在授权范围内、日期是否落在有效期内。

## 怎么确认配好了

1. 输入假设样本中的店铺授权清单原文与拟稿句。比较拟稿句所述日期“2026年8月”与授权有效期“至2026年12月31日”。若日期落在有效期内，授权维度满足条件；若超出有效期，授权维度未获支持。

2. 输入假设样本中的价格管控表原文与拟稿句。比较拟稿句所述日期“2026年8月”与价格管控生效期间“2026年1月1日至2026年6月30日”。若日期落在生效期间内，价格管控维度满足条件；若超出期间，价格管控维度未获支持。

3. 输入一条待核对的交接请求，内容为“请确认华东旗舰店2026年8月家用电器销售是否通过授权与价格管控审核”。比较该请求是否附有授权清单与价格管控表原文、是否标明审核结论来源。若请求仅包含店铺名称与日期、未附原文，该请求处于待核实状态，不能视为已通过审核。
