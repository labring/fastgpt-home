# 平台退款退货处理的商品资料与选型问答：工作流编排

## 这个品类的数据长什么样

在平台退款退货处理的商品资料与选型问答中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

退款申请中的商品问题描述，可用于了解这次反馈说了什么，不能直接代表所有同款商品的规格。自拟输入可以分别记录买家原句、对应商品的资料身份以及要核对的选型问题。表单提交后，检查这些内容在后续步骤仍分开保存，避免把“颜色与描述不符”等个体反馈写成整类商品的确定属性，也不要从申请理由直接推定商品责任已经认定。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 反馈范围 | 买家原句及对应商品身份 | 个体描述没有变成同款统一规格 |
| 选型传值 | 反馈、商品资料与当前属性问题 | 下游没有将三类内容混写 |
| 证据路径 | 看该件记录、补说明或交接 | 实际收到的材料与选择相符 |
| 图像及缺项 | 仅有照片或新资料尚未到达 | 另核读取实现，保留尚缺依据 |
| 外部动作 | 页面、退款或仓库的操作记录 | 分别检查授权与真实业务结果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

若已有质检照片或检测文字，应先核其对应对象，再让负责人选择查看该件商品证据、补原始商品说明或交接问题。逐一验证实际连接路径和接收内容；只有图片时，图片如何形成可供阅读的依据须另行实现，表单不会自动完成识别。选了查看照片，也不能当成质量结论已形成，原文与图像解释仍需相应人员核对。 若一张质检照片没有可辨认的商品对应关系，就无法支持“该型号普遍如此”的商品答复。应回查图片说明、申请中商品名称和资料覆盖范围，区分单件观察与型号说明。流程可以收集这些关联文字，但缺少关联时应要求补证，不把图片存在本身当成适用范围已确认。

## 怎么确认配好了

验收可固定一个属性问题，对照申请文字、补充说明及最后引用，检查是否把投诉、检测与商品介绍混在一起。新资料尚未送达时，应记录具体缺项，不能重复使用同一反馈冒充补充证据。若后续需要修改商品页面、批准退款或更新仓库记录，分别核实际业务授权和操作结果；选型问答完成不等于这些外部动作已经执行。
