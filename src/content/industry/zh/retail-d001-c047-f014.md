# 平台退款退货处理的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

平台退款退货处理按订单持续发生，不一定关联单场直播承诺，售后后台的退款申请、退货物流单、质检照片与退款审批各自独立留存。商品资料与选型问答要回答的是某笔订单当前处于什么状态、涉及什么商品、适用哪条规则，这些判断依赖订单号、商品标识、申请时间与审批结果等字段同时在场。资料按每单和每日更新，单笔申请的状态变化不自动汇入其他订单的结论。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入决定问答能否拿到商品资料，配置决定它按什么范围取用。AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败；旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。系统至少需要一个语言模型和一个索引模型才能正常使用，语音识别模型仅生效一个。

假设演练样本：某平台售后专员在 2026 年 3 月 10 日提交一笔退款申请，订单号 A-20260310-017，商品为某型号保温杯，申请原因写“收到时杯盖破损”。同日仓库质检照片备注“杯盖边缘有裂痕，杯身完好”，退款审批栏为“待审核”，退货物流单显示“已签收”。拟核对句：“该订单已完成退款，责任由仓库承担。”此句含主体、对象与状态，可逐项比对。

## 配置怎么定

配置围绕上述样本核对，不把数据库内部实现抄成必配项。数值为本次假设试验起点，说明选取理由与比较对象。

| 配置项 | 本次假设试验起点 | 选取理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址 | 按官方要求不附加 /v1 或 /chat/completions，与文档示例格式比较 |
| AIPROXY_API_TOKEN | 非空管理员 Token | 官方要求与服务端一致，与应用 API Key 区分核对 |
| 语言模型与索引模型 | 各启用一个 | 官方要求系统至少各需一个，与已启用清单比较 |
| 模型类型 | 按问答所需输入核对 | 多模态、工具调用分别验证，与模型 metadata 字段比较 |
| 引用内容上限 | 假设设为 120000 | 仅作本次试验起点，与样本资料长度比较 |
| 应用参数 | 在应用或节点配置中设置 | 不假设对话接口同名字段会覆盖编排，与节点配置比较 |

## 容易做错的三处

1. 把 AIPROXY_API_TOKEN 填成应用 API Key。输入为拟填 Token 与官方要求的管理员 Token 说明，比较两者身份，观察启动校验是否通过。
2. 把“待审核”当作已批准退款。输入为样本中退款审批栏“待审核”，比较拟核对句“已完成退款”，观察两者状态是否一致。
3. 用相似度分数当作权限过滤。输入为检索返回的相似度值与样本订单号，比较返回记录是否属于该订单，观察是否出现无关订单资料。

## 怎么确认配好了

1. 取样本原文“退款审批栏为待审核”与拟核对句“该订单已完成退款，责任由仓库承担”，比较审批状态字段，只有审批栏显示已批准且责任字段有明确记载时，该句才获支持；当前为待核实。
2. 取样本退货物流单“已签收”与质检照片“杯盖边缘有裂痕，杯身完好”，比较商品破损部位与申请原因，只有两者指向同一部位时破损描述才一致。
3. 取检索返回结果与订单号 A-20260310-017，比较记录归属，只有返回记录均属该订单才满足条件；若返回其他订单资料，记录为待核实，不据此判定权限或实体隔离。空结果可用纸面输入 [] 核对下游设计，不声称某规则检索一定返回空。
