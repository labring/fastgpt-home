# 平台退款退货处理的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样
平台退款按订单持续发生，不必然关联单场直播承诺，因此商品资料与选型问答要同时面对退款申请、退货物流单、质检照片、退款审批四类材料。它们由平台售后后台、客服聊天、WMS收货和支付退款记录分别产生，更新频率为每单或每日。资料以文本为主，质检照片可能带图片描述或图片向量索引，能否命中取决于入库时是否生成对应索引。客服提问常含指代和型号，检索词质量直接影响召回。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨模型库不能共同关联，只能核对标识并排除不符合者。搜索模式按测试问题在语义检索、全文检索与混合检索之间比较，不预设一种模式适合全部资料。语义检索依赖向量距离，全文检索适合编号、型号、专有名词。混合检索通过 RRF 融合多路结果，重排须具备 ReRank 模型并按设置启用。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，会增加一次模型调用。引用内容以数组输出，长度可以为 0，空结果链路仍走通。检索不承担授权职责，相似度不隔离无关业务或未授权记录。

假设演练样本：材料原文为“退款申请 R-2024-0517，订单商品为某型号净水器滤芯，退货物流单显示 2024 年 5 月 20 日仓库已签收，质检照片记录外包装破损、滤芯本体未拆封。退款审批栏状态为待审核。”待判定拟稿句为“该订单已完成退款，责任归属消费者。”此样本用于核对检索结果与拟稿句是否一致。

## 配置怎么定
下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，用于与另一取值比较后观察差异。

| 设置或核对项 | 本次假设试验起点及理由 | 比较与观察方式 |
| --- | --- | --- |
| 关联的知识库 | 选择一个向量模型一致的知识库，含退款申请与质检资料 | 核对各库向量模型标识，排除不一致者 |
| 搜索模式 | 先按语义检索与全文检索分别测试 | 用同一问题比较两路召回内容差异 |
| 引用上限 | 假设起点 2000 tokens，覆盖较长质检描述 | 与 1000 tokens 比较内容是否被截断 |
| 最低相关度 | 假设起点 0.4，先标注相关与无关样本 | 与 0.6 比较无关片段是否减少 |
| 问题优化 | 对含“该订单”的追问开启 | 比较原问题与优化后问题主体是否被改错 |
| 结果重排 | 具备 ReRank 模型时启用并观察得分 | 比较重排前后排序与过滤结果 |

## 容易做错的三处
1. 把跨向量模型的知识库直接共同关联。输入为两个向量模型标识不同的库，比较标识是否一致，观察结果是无法共同关联，应排除不符合者并记录实际观察。
2. 把最低相关度当作权限或实体过滤。输入为相似度得分与未授权记录，比较该设置是否改变记录范围，观察结果是记录范围不变，未授权记录仍需下游授权控制。
3. 把检索命中或空结果当作业务结论。输入为样本原文与拟稿句“已完成退款”，比较审批状态字段“待审核”与“已完成”，观察结果是该拟稿句未获支持，待审核不构成已完成退款。

## 怎么确认配好了
- 验证一：输入样本原文与问题“该订单退款状态如何”，比较召回内容是否包含“待审核”字段，观察结果是引用内容含该字段且未出现“已完成退款”表述。预期如此，未实测。
- 验证二：输入拟稿句“责任归属消费者”，比较原文是否载明责任判定字段，观察结果是原文未载明，该句待核实，不得判定为否定或冲突。
- 验证三：输入空引用数组 []，比较下游设计是否承接长度为 0 的输出，观察结果是链路走通且下游未把空结果当作业务拒绝。预期如此，未实测。
交接时须区分：节点已有行为、实际可配置字段、人工核对动作、需另接系统实现的业务动作。检索、表单和相似度得分不构成退款审批、责任判定或外部同步的授权。
