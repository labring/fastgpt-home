# 投诉举报与监管回复的商品资料与选型问答：工作流编排

## 这个品类的数据长什么样

在投诉举报与监管回复的商品资料与选型问答中，本页说明FastGPT的工作流编排如何衔接资料。投诉中的商品描述与质检结论分别取证，流程先保留陈述方和批次缺口。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟投诉摘录称包装颜色与页面图片不同，批次尚未登记；商品页仅写示意图。工作流先接收所指商品和陈述来源，把批次缺项传给后续核对，不能从投诉转述补出商品已检验。可先询问对应批次，也可在资料已有时整理图文差异，两路均应保留示意用途。分支选择只组织核对顺序，不判实物是否合格或投诉是否成立。

## 配置怎么定

| 投诉商品核对 | 本题材料 | 实际检查 |
| --- | --- | --- |
| 陈述方 | 买家所称 | 非质检结果 |
| 图片用途 | 仅作示意 | 保留限定 |
| 批次 | 当前未记 | 不借历史 |
| 核对路径 | 整理或补证 | 非结项 |
| 正式处理 | 独立流程 | 实际回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

买家陈述冒质检结论时，核实际检查依据；历史批次填入本件时，核当前对象；进入核对路径被写成投诉已结时，查真实处理记录。三处分别核证据性质、批次与事项阶段。

## 怎么确认配好了

验收逐项看提交材料、接收文字和回答对谁说了什么。新增本件资料先核批次，再比较变化；缺信息继续明示。实际投诉提交、回复或结项需独立业务流程与回执，节点执行不生成监管结论。 消费者描述、页面示意和批次查验各自保留来源，回复中的事实层级应能逐句追到材料，缺项继续列明。
