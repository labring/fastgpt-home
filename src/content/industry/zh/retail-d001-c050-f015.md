# 投诉举报与监管回复的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样
投诉举报与监管回复的资料以投诉工单、监管询问函、订单证据、整改报告为主，来源包括12315平台、平台投诉中心、客服聊天与订单系统。资料围绕具体案件生成，更新频率为不定期、每案。从业主体为客服主管、法务合规与店铺负责人，出错后果涉及行政调查、平台处罚与品牌舆情。商品资料与选型问答在此品类中承担一项具体工作：把商品信息、订单证据与整改口径组织成可检索的条目，供回复拟稿时引用。资料结构完整、主体明确、语义单一，向量搜索精度更高；编号、订单号、型号等精确查询依赖全文检索。同一组数据可对应多个向量，任一路召回即可带回该组原数据。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库。库是最小搜索单位，集合只作分类管理，与搜索效果无关。向量检索由 PostgresSQL 的 PG Vector 插件承担，索引为 HNSW；MongoDB 的 dataset.datas 表存储向量原数据，indexes 字段记录向量 ID，同一组原数据可对应多个向量，合并时向量得分取最高分。检索链路按输入与参数组合语义检索、全文检索、混合检索、问题优化、重排与图片检索，混合检索通过 RRF 融合多路结果。引用上限以 token 为单位，最低相关度仅在语义检索或启用结果重排时生效。空引用输出长度为 0，链路仍走通。检索本身不承担授权判断，相似度得分不区分案件归属、主体权限或业务类型；跨不同向量模型的库不可共同关联，需先核标识并排除不符者。

## 配置怎么定
以下为假设演练样本，用于说明核对方式，不代表真实记录或已完成的测试。材料原文：某店铺于假设日期2025年3月10日收到平台转办的工单，工单载明订单号A-0001，投诉事项为商品页面标注的规格与实物不符，处理状态为待店铺提交说明。待判定拟稿句：本店确认该订单已完成退款，规格问题不存在。核对要点：原文只载明待提交说明，未载明退款记录，也未载明规格核验结论，拟稿句的两个事实均未获支持。配置项围绕此样本设置。

| 配置项 | 与本页资料的关系 | 核对方式 |
| --- | --- | --- |
| 关联的知识库 | 选择存放投诉工单、监管询问函、订单证据、整改报告的知识库 | 核对各库向量模型标识一致，排除不一致者 |
| 搜索模式 | 订单号、型号用全文或混合检索，自然语言问题用语义或混合检索 | 用样本原文与拟稿句分别检索，观察候选内容 |
| 引用上限 | 单位为token，工单与整改报告篇幅差异大 | 设本次假设试验起点为2000token，与较短工单所需内容比较后调整 |
| 最低相关度 | 仅在语义检索或结果重排时生效 | 先标注样本中的相关与无关条目，再比较阈值 |
| 问题优化 | 用于指代消除与问题扩展 | 比较原问题与优化后问题，核对主体与订单号是否被改动 |
| 结果重排 | 需具备重排模型并按设置启用 | 观察重排得分与候选顺序，确认是否用于过滤 |

## 容易做错的三处
1. 把检索命中当作授权或事实确认。输入为样本原文与拟稿句，比较检索结果与原文载明事项，若拟稿句写入原文未载明的退款事实，属于超出证据范围。
2. 把最低相关度当作实体或权限过滤器。输入为同一批资料中的无关条目，比较得分与过滤条件，若认为阈值可排除其他主体或未授权记录，属于误用，检索不承担授权判断。
3. 对跨向量模型的库直接共同关联。输入为两个向量模型标识不同的库，比较标识字段，若直接关联并据此判断召回效果，属于越出文档条件，只应核标识并排除不符者。

## 怎么确认配好了
1. 输入样本原文与拟稿句，比较拟稿句中的退款事实与原文载明的待提交说明状态，若拟稿句不写入未载明事实、仅保留待核实表述，满足条件。
2. 输入样本中的订单号A-0001，比较全文检索与语义检索返回的候选内容，若编号类查询能带回含该编号的原数据条目，满足条件；未命中时记录为观察结果，不推断原因。
3. 输入一份明确标注为空的纸面输入[]，比较下游节点是否承接长度为0的引用，若链路继续执行且不产生虚构引用，满足条件；不声称任何规则检索必然返回空数组。
