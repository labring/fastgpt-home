# 拼多多低价活动店铺运营的商品资料与选型问答：文档解析与分块

## 这个品类的数据长什么样

拼多多低价活动店铺运营围绕低价资源位、活动库存和退款率波动展开，活动报名表、商品成本测算表、售后退款单与平台站内信构成日常资料主体。这些资料更新频率为日或每场活动，直接影响库存估算、异常退款跟踪与活动价毛利核对。文档解析与分块环节需要把活动价、报名数量、成本项、退款状态等字段从上述资料中稳定切出，使商品资料与选型问答能够回指到具体材料与版本。资料更新频繁意味着分块结果必须能区分同一商品在不同活动场次的报价与库存口径。

## 这些特征在「文档解析与分块」这一环带来什么约束

FastGPT 的知识库由库、集合和数据三部分组成，最小搜索单位是库，集合仅用于分类管理。在 MongoDB 的 dataset.datas 表中存储向量原数据，indexes 字段记录对应的向量 ID，一组数据可以对应多个向量。检索时先召回向量，再根据向量 ID 去 MongoDB 寻找原数据，对应同一组原数据则合并，向量得分取最高得分。分段需要保持条件、说明与所约束内容不被拆离，活动报名表中的价格条件与适用商品范围若被切散，选型问答就难以给出完整依据。语义检索依赖向量距离，全文检索适合编号、型号、专有名词等精确查询，混合检索通过 RRF 融合多路结果，Rerank 对候选文本二次排序。这些环节都不承担权限或实体隔离功能，检索结果不能替代授权判断。

## 配置怎么定

以下配置围绕假设演练样本，仅列与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，不属官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 样本含活动编号与自然语言问法，需同时覆盖语义与关键词命中，与单独语义检索结果比较 |
| 引用上限 | 假设起点 3000 tokens | 样本含多条成本与库存字段，需容纳完整分段，与较低值比较是否截断条件句 |
| 最低相关度 | 假设起点 0.5 | 样本问题明确，用于观察低相关片段是否被过滤，与不启用过滤的结果比较 |
| 问题优化 | 开启 | 样本含连续追问指代，需补全主体，与关闭时检索词比较 |
| 结果重排 | 启用 | 候选分段较多，需按重排得分过滤，与仅用向量得分排序比较 |
| 分段依据 | 按商品与活动场次 | 样本中同一商品存在不同活动价，需保持字段完整，与按固定长度切分比较 |

## 容易做错的三处

1. 把上传成功当作检索已更新。资料变更后需核对实际训练与索引状态，上传动作本身不表示新分段已可被召回。
2. 将语义召回或相关度分数当作权限或实体过滤。相似度设置不排除无关业务或未授权记录，检索结果仍需人工核对授权边界。
3. 把混合检索后的 RRF 融合写成可开启的独立开关。RRF 是结果融合过程，不是配置项，重排需具备模型并按设置启用。

## 怎么确认配好了

假设演练样本：材料原文为“活动报名表：商品A，活动编号HD-0715，报名价9.9元，报名数量500件，适用场次7月15日至7月17日。商品成本测算表：商品A单件成本8.2元，含物流1.1元。”待判定拟稿句为“商品A在HD-0715场次可按9.9元报名500件，毛利为负。”判定需比较报名价、成本项与数量是否同主体、同场次、同字段。

1. 输入拟稿句与材料原文，比较商品A的活动编号、报名价、成本项是否一致。若成本合计高于报名价，拟稿句的毛利判断获得支持；若成本字段缺失，记录为未获支持。
2. 输入“HD-0715”与“商品A报名价”分别检索，比较返回分段是否包含活动编号、报名价与场次范围。若分段完整保留条件句，满足核对条件；若条件与价格被拆离，记录分段问题。
3. 输入空结果承接场景，以明确的纸面输入[]核对下游展示设计，观察系统是否按空引用处理，不声称虚构规则检索一定返回[]。若下游设计未定义空结果行为，记录为待核实。
