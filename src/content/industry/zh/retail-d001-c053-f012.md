# 渠道应收账款催收的商品资料与选型问答：文档解析与分块

## 这个品类的数据长什么样

渠道应收账款催收处理赊销后的授信与现金回收，主要资料来自财务系统、银行回单、经销商订单和销售合同。日常文档包括应收账龄表、催款函、授信协议、发货冻结通知，更新频率为周或月。这些资料多为结构化表格与固定条款文本，解析时需保留账龄区间、授信额度、冻结触发条件等字段的完整语义。分块环节若将授信协议中的额度条件与豁免说明拆开，检索时可能只召回半句条件，导致选型问答给出不完整引用。

## 这些特征在「文档解析与分块」这一环带来什么约束

账龄表按周或月更新，分块需按经销商与账期组合保留行级语义，避免跨经销商合并。催款函含具体金额与截止日期，分块应保留金额、期限与对象在同一数据块内。授信协议中的额度、担保方式与生效条件属于同一约束组，拆离后检索结果无法回指完整条款。发货冻结通知包含触发原因与解除条件，分块需同时保留两者。FastGPT 中一组原数据可对应多个索引，同一数据块可生成多组向量，检索时命中任一索引即可召回该数据。知识库搜索以库为单位，集合仅作分类管理。向量检索由 PostgresSQL 的 PG Vector 插件与 HNSW 索引承担，MongoDB 的 dataset.datas 表存储原数据与 indexes 字段。检索时先召回向量，再按向量 ID 回 MongoDB 取原数据，同一组原数据合并后取最高得分。

## 配置怎么定

以下配置围绕本页文档解析与分块任务，列出官方已说明的设置或实施核对项。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 账龄表含编号与自然语言问法，混合检索同时使用语义与全文召回，再经 RRF 融合。与单独语义检索比较编号命中情况 |
| 引用上限 | 假设起点 3000 tokens | 账龄表与授信协议单块较长，需容纳完整条款。与 1500 tokens 比较是否截断条件说明 |
| 最低相关度 | 假设起点 0.4 | 该值仅在语义检索或结果重排时生效。与 0.2 比较无关片段是否减少 |
| 问题优化 | 开启 | 连续追问账龄口径时需补全指代。与关闭比较短问题召回完整性 |
| 结果重排 | 启用 ReRank | 混合检索后候选较多，需二次排序并按重排得分过滤。与不启用比较排序稳定性 |
| 分块完整性核对 | 人工检查 | 核对授信协议条件与豁免说明是否同块，账龄表行级语义是否保留 |

## 容易做错的三处

1. 将授信协议的额度条件与豁免说明拆入不同数据块。检索命中额度条件时无法同时取回豁免说明，选型问答引用不完整。检查方式：输入含额度条件的查询，比较召回块是否包含豁免说明原文。
2. 把上传成功当作检索已更新。资料变更后未核对实际训练与索引状态，检索仍返回旧块。检查方式：变更后以新术语检索，比较返回内容是否对应变更后原文。
3. 将最低相关度用于排除无关业务或未授权记录。该值是过滤阈值，不承担权限或实体隔离。检查方式：输入跨经销商查询，比较返回结果是否仍包含其他经销商数据，确认权限需另接系统实现。

## 怎么确认配好了

假设演练样本：材料原文为“经销商甲截至三月账龄九十天，授信额度五十万元，超授信发货冻结，解除条件为回款至额度内”。待判定拟稿句为“经销商甲已回款至额度内，冻结可解除”。判定需同主体、同期间、同一字段：原文仅载明解除条件，未载明回款事实，该拟稿句未获支持，应记录证据缺口。

- 验证一：输入“经销商甲 授信额度 冻结解除条件”，比较召回块是否同时含额度、冻结与解除条件。预期召回块与原文一致，不保证首条命中。

- 验证二：输入“经销商甲 已回款”，比较返回内容是否含回款记录。预期返回结果不含回款事实，若返回其他经销商记录则需核对分块与权限设置。

- 验证三：变更账龄表后以新账期检索，比较返回内容是否对应变更后原文。预期返回变更后块，若仍返回旧块则记录训练与索引状态待核。

空结果承接可用纸面输入[]核对下游设计，不声称虚构规则检索一定返回[]。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察。
