# 渠道应收账款催收的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样

渠道应收账款催收发生在赊销之后，核心是授信与现金回收，主要资料来自财务系统、银行回单、经销商订单和销售合同。日常处理的文档包括应收账龄表、催款函、授信协议和发货冻结通知，更新频率为周或月。商品资料与选型问答要回答的是型号、规格、账期条款、冻结条件这类问题，检索质量直接决定回答能否引用到正确条款。资料分散在多个文档类型中，同一经销商的账龄、授信与冻结状态需要按主体和期间对齐，检索环节只负责把候选原文召回，不负责判断授权状态。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的库，跨不同向量模型的库不可共同关联，需要先核对向量模型标识并排除不符合者。语义检索依赖向量距离，全文检索适合编号、型号、专有名词，混合检索通过 RRF 融合两路结果，Rerank 对候选文本二次排序。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不是权限或实体隔离手段。引用上限以 token 为单位，长短不一的资料需要实际测试内容是否完整。问题优化用于指代消除和问题扩展，会增加一次模型调用。输出引用内容为数组，长度可以为 0，空结果链路仍会走通。

假设演练样本：材料原文为“经销商甲，授信协议编号 A-001，账期 60 天，截至 2025 年 3 月 31 日应收账龄表列示逾期 45 天，发货冻结通知尚未签发。”待判定拟稿句为“经销商甲已触发发货冻结，可停止供货。”该句把尚未签发的冻结通知当作已执行状态，判定应记为未获支持。

## 配置怎么定

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| 关联知识库 | 仅关联向量模型标识一致的应收催收库 | 核对各库向量模型标识，排除不一致者 |
| 搜索模式 | 先分别用语义、全文、混合检索同一问题 | 比较三路召回内容与预期条款的对应 |
| 引用上限 | 假设起点 3000 token，因账龄表与授信协议段落较长 | 与 1500 token 结果比较内容是否被截断 |
| 最低相关度 | 假设起点 0.4，先标注相关与无关样本 | 与 0.2、0.6 比较误召与漏召 |
| 问题优化 | 多轮追问时开启，单轮明确问题关闭 | 比较原问题与优化后问题主体是否被改错 |
| 结果重排 | 候选较多且已配置重排模型时启用 | 比较重排前后排序与得分 |

以上数值为本次假设试验起点，依据是资料段落长度与样本标注，不构成官方默认值。

## 容易做错的三处

1. 把检索命中当作授权结论。输入“经销商甲冻结状态”，检索召回授信协议中“超授信可冻结”条款，若直接输出“已冻结”，混淆了条款授权与冻结通知已签发这一事实。检查：输入该问题，比较召回原文是否含冻结通知签发记录，仅含条款时结果应记为待核实。
2. 跨向量模型库共同关联。输入同一问题并勾选两个向量模型标识不同的库，若期望合并结果，属于超出文档说明的用法。检查：核对各库向量模型标识，排除不一致者，记录实际可关联范围。
3. 用最低相关度过滤无关业务。输入“经销商乙账龄”，把最低相关度调高，若认为可排除其他经销商记录，属于误用。检查：比较召回内容是否仍含其他主体，相关度不承担实体隔离。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句“经销商甲已触发发货冻结，可停止供货”，比较召回原文是否包含冻结通知签发记录。原文仅载明“尚未签发”时，判定应输出未获支持，出现“已冻结”即不满足。
2. 输入“授信协议编号 A-001 账期”，分别用全文检索与语义检索，比较召回是否命中该编号条款。全文检索命中编号而语义检索未命中时，说明精确查询宜用全文或混合检索，不保证首条命中。
3. 输入明确无对应资料的纸面问题，核对输出引用数组是否为长度 0 且下游链路继续。以纸面输入空数组核对下游设计，不声称虚构规则检索一定返回空数组。
