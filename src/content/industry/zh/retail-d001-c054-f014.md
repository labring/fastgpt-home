# 渠道窜货稽查的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

窜货投诉单、防伪码记录、处罚通知与调查照片构成主要材料，处理的是区域与价格秩序。同一批货的防伪码记录可能来自不同区域，投诉单与照片之间缺少统一编号时，核对只能停留在人工比对。资料更新多为周或不定期，本页不据此推出批量同步或实时触发机制。

## 这些特征在「模型接入与配置」这一环带来什么约束

商品资料与选型问答依赖语言模型与索引模型，系统至少需要一个语言模型和一个索引模型才能正常使用。多模态能力决定调查照片能否进入问答，工具调用能力影响分类与内容提取，这些能力须按应用所需输入分别核对，不能由对话接口同名字段推断编排行为。检索负责召回文本块，不承担授权判断，相似度设置不排除越权记录。

假设演练样本：某品牌渠道管控团队收到一份窜货投诉单，原文为“投诉对象：华东区域经销商甲；涉及商品：某型号商品；投诉事由：在华南电商店铺发现低于建议零售价的在售链接；附件：调查照片两张、防伪码记录一份；投诉单状态：待审核”。另有一条待判定拟稿句：“经销商甲已完成跨区销售，处罚通知已发出。”核对材料中投诉单状态为待审核，未见处罚通知文本，拟稿句的处罚事实未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填写为 AI Proxy 服务根地址，不附加 `/v1` | 与官方说明的根地址格式逐字比对 |
| AIPROXY_API_TOKEN | 假设填写为与服务端一致的非空管理员 Token | 确认非空，确认未使用应用 API Key 代替 |
| 语言模型 | 假设启用一个语言模型 | 确认已启用，确认模型 ID 与渠道中模型一致 |
| 索引模型 | 假设启用一个索引模型 | 确认已启用，确认模型 ID 与渠道中模型一致 |
| 模型能力 | 假设按本样本所需文本输入核对 | 对多模态、工具调用分别核对，不合并判断 |
| 模型状态探测 | 假设不开启自动探测 | 未开启时页面呈现未启用自动探测空状态 |

起点数值为本次假设试验设定，用于与官方说明的格式或状态比较，不代表官方默认值。

## 容易做错的三处

1. 把投诉单的待审核状态当作已确认窜货。输入为样本投诉单原文，比较对象为投诉单状态字段，待审核不构成已确认结论，拟稿句的处罚事实未获支持。
2. 把检索命中当作授权通过。输入为一次商品资料检索请求，比较对象为检索结果与访问权限，检索结果不证明该账号有权查看对应记录。
3. 把模型映射写成模型替换。输入为渠道配置中的模型映射，比较对象为 FastGPT 请求模型与上游实际模型，映射只改变上游请求的模型值，不改变系统内模型 ID。

## 怎么确认配好了

1. 输入样本投诉单原文与拟稿句，比较拟稿句是否出现处罚通知已发出，只有材料中出现处罚通知文本且状态支持时才满足条件，否则记录为未获支持。
2. 输入样本投诉单原文与一条询问经销商甲是否跨区销售的问题，比较回答是否引用待审核状态，回答把待审核表述为已确认时不满足条件。
3. 输入空结果承接场景的纸面输入 `[]`，比较下游设计是否按空结果处理，不声称虚构规则检索一定返回 `[]`；实际观察到的返回内容与错误信息如实记录，未观察到的部分保持未知。
