# 生鲜临期折价处理的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

临期折价处理围绕货架库存生命周期运转，与逐件称重分拣的作业方式不同。日常材料包括临期清单、折价审批、报损单、促销价签，数据来源涉及POS库龄、门店巡检、ERP库存与质检记录，更新频率为日或班次。这些材料进入商品资料与选型问答时，模型需要读取批次、日期范围、审批状态与价签内容，回答选型与资料核对问题。材料中的状态字段直接决定回答边界：审批未通过、终止未签署、报价单未确认，都不能当作已执行。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填写 AI Proxy 服务根地址，不附加 /v1。AIPROXY_API_TOKEN 填写与服务端一致的非空管理员 Token，不能用应用 API Key 代替。系统至少需要一个语言模型和一个索引模型才能正常使用。模型能力按应用所需输入核对，多模态、工具调用及思考配置分别验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。thinking budget 是思考预算，不能移作引用 token 上限。

假设演练样本：某门店 2026 年 3 月 10 日临期清单记载“鲜奶批次 A，保质期至 3 月 12 日，数量 12 盒，状态：待折价审批”。同日折价审批单记载“批次 A 折价申请已提交，审批人未签署”。一条待判定的拟稿句为“批次 A 折价已批准，可按新价签销售”。核对材料原文含主体、对象、状态与有效范围，但审批签署事实缺失，拟稿句不能成立。

## 配置怎么定

下表围绕样本，列出官方已说明的设置或实施核对项。假设试验起点仅用于本次纸面核对，不属官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填写 `http://aiproxy:3000` | 文档要求根地址不附加 /v1；与文档示例格式比较 |
| AIPROXY_API_TOKEN | 假设填写非空管理员 Token | 文档要求与服务端一致且非空；与空值比较 |
| 语言模型 | 假设启用一个已测试语言模型 | 文档要求至少一个语言模型；与未启用状态比较 |
| 索引模型 | 假设启用一个已测试索引模型 | 文档要求至少一个索引模型；与未启用状态比较 |
| 模型能力核对 | 假设对样本所需字段逐项核对 | 文档要求按应用所需输入核对；与缺失能力比较 |
| 应用参数位置 | 假设在应用或节点配置中设置 | 文档说明参数在应用或节点配置中设置；与对话接口同名字段比较 |

## 容易做错的三处

1. 把待折价审批当作已批准。样本中审批人未签署，拟稿句写“已批准”，输入是审批单状态字段，比较对象是签署事实，可观察结果是签署缺失被记录为未获支持。
2. 把 AIPROXY_API_TOKEN 留空或用应用 API Key 代替。输入是环境变量值，比较对象是文档要求的非空管理员 Token，可观察结果是启动校验失败或调用被拒。
3. 把 thinking budget 当作引用 token 上限。输入是模型思考配置字段，比较对象是文档对思考预算与引用上限的区分，可观察结果是配置项被错误映射到引用限制。

## 怎么确认配好了

1. 对样本拟稿句核对：输入为临期清单与折价审批单原文，比较审批签署字段与拟稿句“已批准”表述，只有审批签署事实存在且状态字段一致时，拟稿句才获支持；当前签署缺失，记录为未获支持。
2. 对模型接入核对：输入为 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 的配置值，比较文档要求的根地址格式与非空 Token，只有两项均满足且模型测试通过时，接入条件才成立；未测试时记录为待核实。
3. 对应用参数核对：输入为应用或节点中的参数设置，比较文档说明的参数位置，只有参数在应用或节点配置中设置且与对话接口同名字段区分时，才满足条件；未设置时记录为缺口。
