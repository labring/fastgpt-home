# 生鲜供应商索赔的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

生鲜供应商索赔追究到货质量责任，不处理门店自然损耗，因此商品资料与选型问答围绕质量异常单、照片证据、扣款通知、索赔对账单展开。资料按每批到货和月度对账两个节奏更新，同一批次的质检结论、验收数量与扣款金额需要保持对应。选型问答要回答的是某条索赔记录依据哪份材料、处于哪个处理阶段、当前由谁持有。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。自部署时 `AIPROXY_API_ENDPOINT` 填服务根地址，不附加 `/v1`；`AIPROXY_API_TOKEN` 填与服务端一致的非空管理员 Token。系统至少需要一个语言模型和一个索引模型。模型 ID 是请求体中 `model` 字段的值，全局唯一；模型名仅用于展示。模型映射把 FastGPT 侧模型 ID 映射到上游实际模型，例如 `gpt-4o-test` 映射为 `gpt-4o`。渠道优先级范围 1～100，数值越大越容易被优先选中。

检索环节中，向量检索的 `hnsw.ef_search` 仅对 PG、OceanBase、openGauss 生效，`HNSW_MAX_SCAN_TUPLES` 仅对 PG 生效。相关度分数是排序依据，不承担权限或实体隔离。跨不同向量模型的库不可共同关联，核对时先比对模型标识，排除不一致的库，并记录实际观察。

假设演练样本：某批次到货质量异常单载明“2026年3月12日到货批次 A-0312，抽检不合格，扣款通知已发出，供应商尚未确认”。待判定拟稿句为“该批次索赔已结案”。材料只说明扣款通知已发出、供应商未确认，拟稿句超出材料范围。

## 配置怎么定

下表为本次假设试验起点，数值仅用于核对方法，不作为官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://aiproxy:3000` | 官方示例格式，比较是否误加 `/v1` |
| `AIPROXY_API_TOKEN` | 假设非空字符串 | 与服务端配置比对是否一致 |
| 语言模型 | 假设启用一个 | 与索引模型配对，满足最低要求 |
| 索引模型 | 假设启用一个 | 与语言模型配对，满足最低要求 |
| 渠道优先级 | 假设设为 50 | 范围 1～100，比较同渠道其他取值 |
| `HNSW_EF_SEARCH` | 假设设为 100 | 官方默认值，仅对 PG、OceanBase、openGauss 生效 |

模型能力按应用所需输入核对，多模态、工具调用分别验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。检索或表单只收集与返回信息，业务核验、审批、数据库写入与外部同步需要各自的下游实现。

## 容易做错的三处

1. 把 `AIPROXY_API_ENDPOINT` 写成带 `/v1` 的完整请求地址。输入为环境变量值，比较官方示例格式，观察是否附加了 `/v1` 或 `/chat/completions`。
2. 把相关度分数当成权限过滤。输入为一次检索返回的分数列表，比较返回记录与当前账号可见范围，观察是否出现越权记录。
3. 把扣款通知已发出当成索赔已结案。输入为假设样本原文与拟稿句，比较主体、批次、状态字段，观察拟稿句是否超出材料载明范围。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句“该批次索赔已结案”，比较材料载明的状态字段。材料只写扣款通知已发出、供应商未确认，拟稿句未获支持，应记录为待核实。
2. 输入 `AIPROXY_API_ENDPOINT` 的实际取值，比较官方格式要求。取值不含 `/v1` 且服务启动校验通过时满足条件；含 `/v1` 时记录为配置不符。
3. 输入一次检索返回的记录与当前账号可见范围，比较两者是否一致。返回记录全部落在可见范围内时满足条件；出现范围外记录时记录为权限核对未通过。空结果可用纸面输入 `[]` 核对下游设计，不推断检索行为。
