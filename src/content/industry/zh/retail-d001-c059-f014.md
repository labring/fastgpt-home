# 生鲜冷链到店验收的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

在生鲜冷链到店验收的商品资料与选型问答中，本页说明FastGPT的模型接入与配置如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「模型接入与配置」这一环带来什么约束

送货单上的三文鱼段名称可作为模型文字输入的核对点，但它不能证明这批商品的品质、温控状态或来源。先看实际请求是否收到商品名称，再检查回答是否把名称中的描述扩成验收结论。生鲜冷链资料可能另有温度记录和质检照片，本次只验证已经提供的文字；不能从一次调用成功推定这些其他来源都已进入模型。应分别留存调用响应与原文送达记录。

## 配置怎么定

| 接入或实施核对项 | 选型文字中的对象 | 核对结果 |
| --- | --- | --- |
| 商品名称 | 送货单中的三文鱼段文字 | 是否确实进入模型请求 |
| 验收范围 | 名称不提供温控或品质证明 | 不扩展为到货验收结论 |
| 规格对照 | 两份单据的重量及单位 | 检查输入遗漏与生成覆盖 |
| 产地缺项 | 送货单未给来源说明 | 补资料后同题回查出处 |
| 其他输入路径 | 照片及温度记录需另核 | 不由文字调用推定已验证 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `AI Proxy依赖` | 按实际版本核服务、渠道与应用。 |
| `AIPROXY_API_ENDPOINT` | 使用AI Proxy服务根地址。 |
| `AIPROXY_API_TOKEN` | 管理员Token非空且与服务端一致。 |
| `模型能力` | 按实际输入路径验证所需能力。 |
| `应用参数` | 接口同名字段未必覆盖应用设置。 |

## 容易做错的三处

- 只传送货单却声称完成双份规格对照：保存资料清单及实际请求，先查验收单是否取得和传入，不能据输出遗漏直接判模型能力。

- 双方重量均已送达，输出覆盖其中一项：并列原字段、单位、批次与返回，定位生成丢失；实际重量及修订责任仍需收货依据确认。

- 从三文鱼名称或历史猜产地、品质或温控结论：逐句追查对应来源，送货名称不能提供验收证明；补资料后同题核新出处。

## 怎么确认配好了

送货单未提供原产地信息时，模型配置不能补出商品来源。应查看输出是否从名称、语言或其他历史内容猜测产地，并把无依据说法标出。补充来源说明后，用相同问题和应用设置核新材料是否送达，回答是否有对应出处。如果实际来源以照片提供，要按那个输入路径另测能力；文字测试的结果不能直接用于验证照片读取。
