# 生鲜冷链到店验收的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样
冷链到店验收的资料围绕运输温度、到货批次与品质抽检展开，与产地询价无关。主要来源为冷链车温控、WMS、门店收货系统与质检照片，日常文档包括冷链温度记录、到货验收单、拒收单、供应商送货单。资料按每批与每日更新，检索时同一批次的温度字段、验收结论与拒收原因需要保持主体一致。这些资料决定检索输入常包含批次号、车牌或温度区间等精确字段，也常包含“这批能不能收”一类自然语言问题，两类输入对召回路径的要求不同。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联，需要先核对向量模型标识并排除不符合者，不执行跨模型检索来比较漏召回。搜索模式分为语义检索、全文检索与混合检索，编号、批次号、专有名词更适合全文检索或混合检索，自然语言问法更适合语义检索或混合检索。混合检索通过 RRF 融合多路结果，RRF 是融合过程，不作为独立开关。最低相关度仅在语义检索或使用结果重排时生效，且属于过滤阈值，不承担权限或实体隔离。引用内容以数组输出，长度可以为 0，空结果链路仍然走通。图片检索需要相应图像输入及模型能力，重排需要具备模型并按设置启用，流程图中的可选路径不代表每次请求全部执行。

假设演练样本：某门店收货系统留存的《到货验收单》原文为“批次 LC2024-0312，冷链车温度记录显示到货温度 2℃，抽检三箱叶菜，两箱合格，一箱叶片萎蔫，验收结论为部分拒收，拒收原因为叶片萎蔫。”待判定的拟稿句为“该批次已整批拒收，供应商无争议。”该拟稿句与原文在验收结论字段上取值不同，属于同主体、同批次、同字段的互斥取值。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 依据与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联使用同一向量模型的冷链验收库 | 先核对向量模型标识，排除不同模型库 |
| 搜索模式 | 混合检索 | 用批次号问题与自然语言问题分别观察召回 |
| 引用上限 | 起点设为覆盖一份验收单全文的 token 量 | 该值为本次假设起点，与较短和较长资料比较完整性 |
| 最低相关度 | 起点设为 0.3 | 该值为本次假设起点，与已标注相关、无关样本比较 |
| 问题优化 | 对多轮追问开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型时启用 | 观察重排得分与候选排序变化 |

## 容易做错的三处
1. 把跨向量模型的库共同关联。输入为两个向量模型标识不同的知识库，比较标识是否一致，观察到的结果是标识不符者被排除，不执行跨模型检索。
2. 把最低相关度当成权限过滤。输入为同一批次资料与一条无关查询，比较阈值设置与返回内容，观察到的结果是阈值只影响相关度过滤，不排除未授权记录。
3. 把待审核的拒收单当成已完成拒收。输入为标注“待审核”的拒收单原文，比较状态字段与拟稿结论，观察到的结果是状态为待审核，拟稿中的已完成拒收未获支持。

## 怎么确认配好了
1. 输入假设样本中的验收单原文与拟稿句，比较验收结论字段取值，拟稿句与原文取值不同，判定为与原文不符，需按原文修正。
2. 输入批次号“LC2024-0312”与自然语言问题“这批叶菜能不能收”，比较两种输入下的召回内容是否包含该批次验收单，观察到的结果是两种输入均能召回同一批次资料，则混合检索对该样本可用。
3. 输入明确的纸面空结果数组 []，比较下游引用处理是否走通，观察到的结果是空结果链路仍可执行，不声称虚构规则检索一定返回 []。以上均为纸面核对，未实际部署或执行。
