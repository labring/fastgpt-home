# 生鲜水果门店采购的商品资料与选型问答：知识库检索与召回

## 这个品类的数据长什么样
生鲜水果门店采购的商品资料分散在采购单、验收单、农残检测报告与损耗记录中，更新频率为日或每批。采购单记录品名、档口报价与订货数量；验收单记录到货等级与扣重结果；农残检测报告按批次出具；损耗记录按门店与日期登记。选型问答需要在这些资料中检索同一水果品类的等级、产地、报价与检测状态，资料主体、批次与日期不一致时，检索结果不能直接合并。批发市场行情与供应商报价构成选型依据，门店销售数据用于判断补货方向。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，需先核验向量模型标识，排除不符合者，记录实际观察，不执行跨模型检索来比较漏召回。检索以库为最小搜索单位，集合仅作分类管理。搜索模式可选语义检索、全文检索或混合检索；混合检索经 RRF 融合多路结果，RRF 是融合过程，不是独立开关。语义检索与最低相关度不承担权限或实体隔离功能，检索结果不构成授权。引用上限以 token 为单位，输出引用内容可为长度 0 的数组。图片检索需有图像输入且模型具备相应能力，重排需具备模型并按设置启用，文档总流程图列出的路径不代表每次请求全部执行。问题优化用于指代消除与问题扩展，会增加一次模型调用。

## 配置怎么定
下表围绕生鲜水果门店采购的商品资料与选型问答，列出官方已说明的设置或实施核对项。数值为本次假设试验起点，用于与实测结果比较，不作为官方默认值。

| 配置项 | 本次假设试验起点及理由 | 核对方式 |
| --- | --- | --- |
| 关联的知识库 | 关联一个含采购单、验收单、检测报告、损耗记录的知识库，先确认向量模型标识一致 | 核对库标识与向量模型标识，排除不一致者 |
| 搜索模式 | 先用混合检索，兼顾品名编号与自然语言问法 | 分别用编号类与描述类问题比较召回内容 |
| 引用上限 | 起点设为覆盖一张验收单完整字段的长度，避免字段被截断 | 用长短不同的实际资料比较引用内容是否完整 |
| 最低相关度 | 先标注相关与无关样本，再设起点并比较过滤结果 | 观察被过滤内容与标注样本是否一致 |
| 问题优化 | 多轮追问与短问题场景开启，单轮明确问题可关闭 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 候选较多且问题明确时启用，核对重排得分 | 比较重排前后排序，记录得分区间 |

## 容易做错的三处
1. 将语义检索或最低相关度当作权限过滤。假设演练样本中，采购员仅被授权查看本门店验收单，检索却返回其他门店记录，此时错在把相似度阈值当成访问控制。检查输入为检索账号与目标库范围，比较返回记录的门店字段与授权范围，观察是否出现越范围记录。
2. 将不同向量模型的库共同关联。假设两个库分别使用不同向量模型，操作者直接勾选两者。检查输入为两个库的向量模型标识，比较标识是否一致，观察是否被排除或记录为不可共同关联。
3. 将待审核的采购请求当作已批准执行。假设演练样本中，一份采购单处于待审核状态，拟稿句写成“该批水果已完成采购”。检查输入为采购单状态字段，比较状态取值与拟稿句表述，观察拟稿句是否超出已载明状态。

## 怎么确认配好了
假设演练样本：验收单原文为“2025年3月12日，门店A验收档口B供货的砂糖橘一批，到货等级二级，扣重后净重300公斤，验收人张某。”农残检测报告原文为“2025年3月12日，批次C的砂糖橘样品检测结果合格，报告编号D。”待判定拟稿句为“门店A该批砂糖橘已完成采购并可上架销售。”

1. 引用完整性核对。输入上述验收单原文与拟稿句，比较拟稿句是否只使用原文载明的门店、日期、品名、等级与净重，观察拟稿句是否加入原文未载明的“可上架销售”结论。
2. 状态字段核对。输入上述采购单状态字段与拟稿句，比较状态取值与拟稿句表述，观察拟稿句是否将待审核表述为已完成采购。
3. 空结果承接核对。输入纸面空数组[]，比较下游设计是否按引用内容长度为0继续执行，观察下游是否将空结果当作无授权或检索失败。空结果仅表示本次未返回引用，不表示虚构规则检索一定返回空数组。
