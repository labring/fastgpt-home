# 生鲜称重分拣的商品资料与选型问答：文档解析与分块

## 这个品类的数据长什么样

生鲜称重分拣发生在仓内履约环节，核心是重量和规格。分拣任务单、称重标签、少称补偿单、质检记录构成日常要处理的文档，数据来源包括 WMS、电子秤、订单系统和质检照片。这些资料按每单或按日更新，出错会带来少发赔付、毛利损耗和顾客差评。

对文档解析与分块而言，这些特征意味着三点。第一，同一商品在不同单据里的表述可能只差规格或重量区间，分段需要保留判断所需的完整条件。第二，称重标签与少称补偿单常含编号和精确数值，适合全文检索命中。第三，质检记录含照片，图片能否参与检索取决于入库时是否建立了对应索引。

## 这些特征在「文档解析与分块」这一环带来什么约束

FastGPT 的知识库由库、集合和数据三部分组成，最小搜索单位是库。集合用于分类管理，与搜索效果无关。MongoDB 的 dataset.datas 表存储向量原数据，indexes 字段记录对应的向量 ID，一组数据可以对应多个向量。PostgresSQL 配合 PG Vector 与 HNSW 索引承担向量检索。检索时先召回向量，再按向量 ID 回 MongoDB 寻找原数据，同一组原数据被多路命中时合并，向量得分取最高得分。

分段完整性直接影响检索精度。当一段话的结构和语义完整且单一时，精度会提高。生鲜称重分拣的规格条件、重量区间与适用商品若被拆到不同分段，检索到的片段可能缺少判断所需的主体或范围。多向量映射允许为一组较长文本添加多组向量，只要其中一组被检索到，该数据也会被召回。

假设演练样本：供核对的材料原文为「分拣任务单 A 类：叶菜类按 300 克至 350 克区间称重，超出区间需贴标复核。称重标签编号以 SC 开头，少称补偿单编号以 BC 开头。质检记录含照片，照片索引在入库时生成。」一条待判定的拟稿句为「少称补偿单编号以 BC 开头，因此所有编号以 BC 开头的单据都属于少称补偿单。」该拟稿句把原文对编号前缀的描述扩展为分类判定，材料只说明编号前缀，未说明前缀与单据类型的唯一对应关系，属于未获支持。

## 配置怎么定

下表围绕上述样本列出与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，用于比较，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 样本含编号与自然语言问法，混合检索同时使用语义召回与全文召回，再经 RRF 融合，与单一模式比较命中情况 |
| 引用上限 | 假设起点 2000 tokens | 按 tokens 控制引用量，避免不同 chunk 长度差异导致不稳定；与更小值比较是否截断判断条件 |
| 最低相关度 | 假设起点 0.4 | 仅在语义检索或结果重排时生效；与更高值比较是否过滤掉含编号的片段 |
| 问题优化 | 开启 | 样本含连续追问可能，问题优化做指代消除与问题扩展；与关闭比较短问题检索效果 |
| 结果重排 | 启用 ReRank | 混合检索后范围较大，重排得分更精确，可按得分过滤；与不重排比较排序 |
| 图片索引核对 | 核对入库时是否生成图片向量索引 | 样本质检记录含照片，图片检索依赖入库索引与模型能力，核对标识并记录观察 |

## 容易做错的三处

1. 把编号前缀当作单据类型判定依据。样本原文只说明少称补偿单编号以 BC 开头，未说明所有 BC 开头单据都属于少称补偿单。错误做法是据此直接判定，正确做法是核对单据类型字段，缺失时记录待核实。
2. 把上传成功当作检索已更新。资料变更后需核对实际训练与索引状态，上传动作与索引更新是两个阶段，不能由上传成功推出检索结果已包含新内容。
3. 把检索结果当作权限边界。语义召回与相关度不承担实体隔离或授权判断，检索到某条内容不代表当前请求方有权使用该内容，授权状态需另行核对。

## 怎么确认配好了

1. 输入样本原文与拟稿句，比较拟稿句是否超出原文对编号前缀的描述范围。若检索结果只返回编号前缀说明而未返回单据类型唯一对应关系，拟稿句应判为未获支持，不得据此判定单据类型。
2. 输入含编号的查询与含自然语言的查询，比较两种查询在混合检索下的返回片段。若编号查询命中称重标签或补偿单片段，自然语言查询命中规格区间片段，说明分段保留了判断所需条件；若任一查询返回空结果，记录实际观察，不推断原因。
3. 输入明确纸面空结果 [] 核对下游设计，比较下游是否按空结果处理。空结果不表示虚构规则检索一定返回 []，仅用于核对下游对空引用的承接方式。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察，不执行跨模型检索比较漏召回。
