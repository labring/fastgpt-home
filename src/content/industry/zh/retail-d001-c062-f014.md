# 电商仓入库上架的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

入库上架处理货物进入仓库的第一道账实确认，数据来源包括 WMS、ERP 采购、供应商送货单与条码扫描，日常文档为采购到货单、入库验收单、上架任务与差异报告。商品资料与选型问答要回答的是到货商品的规格、包装、存储条件与库位适配问题，答案必须能追溯到具体单据。

模型接入与配置在此处的含义是：让问答所依据的商品资料可被模型读取、索引并检索，同时把模型能力与入库场景的输入形态对齐。资料更新频率为每批、日，本页不据此推导批量同步或实时触发机制。

## 这些特征在「模型接入与配置」这一环带来什么约束

系统至少需要一个语言模型和一个索引模型才能正常使用。索引模型对文本块进行索引，用于相关文本检索；语言模型进行文本对话，多模态模型支持图片识别。模型 ID 是接口请求 Body 中 model 字段的值，全局唯一；模型名仅用于展示。模型渠道可承载同一模型实现负载均衡。

从 V4.17.0 起 AI Proxy 为必需依赖，AIPROXY_API_ENDPOINT 填写服务根地址，不附加 /v1；AIPROXY_API_TOKEN 必须与服务端一致且非空。检索相似度不承担权限或实体隔离职责，检索结果不构成对供应商、库位或单据的授权。跨不同向量模型的库不可共同关联，须先核对标识并排除不符合者。

假设演练样本（纸面材料，非真实记录）：采购到货单载明“供应商甲，商品 A，规格 500ml×12，到货 40 箱，到货日期 2026-03-02”；入库验收单载明“商品 A，实收 38 箱，差异 2 箱，验收状态：待核实”。待判定拟稿句：“商品 A 已完成入库上架，库存 40 箱。”该句涉及主体、对象、数量与状态，可与上述两份材料逐字段比对。

## 配置怎么定

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设起点 http://aiproxy:3000 | 文档要求根地址，与附加 /v1 的写法比较 |
| AIPROXY_API_TOKEN | 假设起点为与服务端一致的非空值 | 文档要求非空且一致，与应用 API Key 比较 |
| 索引模型 | 假设启用一个索引模型 | 文档要求至少一个，与未启用状态比较 |
| 语言模型 | 假设启用一个语言模型 | 文档要求至少一个，与未启用状态比较 |
| 模型映射 | 假设将 gpt-4o-test 映射为 gpt-4o | 文档示例，与未映射时请求模型名比较 |
| 渠道测试 | 假设对渠道执行模型测试 | 文档提供测试入口，与未测试状态比较 |

以上数值为本次假设试验起点，不是官方默认值。

## 容易做错的三处

1. 把检索命中当作授权。输入：检索返回商品 A 的资料片段。比较：该片段与供应商甲、验收状态的字段归属。可观察结果：片段只说明文本相关，未载明授权，拟稿句中的“已完成入库上架”仍待核实。
2. 把待核实状态读成否定或冲突。输入：验收单“实收 38 箱，差异 2 箱，验收状态：待核实”。比较：同一字段的取值。可观察结果：待核实属于未获支持，与到货 40 箱不构成同字段互斥矛盾。
3. 跨向量模型库共同关联。输入：两个库的向量模型标识。比较：标识是否一致。可观察结果：标识不一致时排除该库，记录实际观察，不推断漏召回或冗余结果。

## 怎么确认配好了

1. 输入假设样本的采购到货单与入库验收单原文，比较拟稿句“商品 A 已完成入库上架，库存 40 箱”中的数量与状态字段。只有两份材料同主体、同期间、同字段载明一致且状态为已完成时，该句才满足条件；当前状态为待核实，判为未获支持。
2. 输入假设请求“请确认商品 A 的库位分配结果”。比较：材料中是否载明库位字段。只有采购到货单、入库验收单或上架任务载明库位且状态为已分配时，才满足条件；当前材料未载明，记录为证据缺口。
3. 输入空结果承接的纸面输入 []，比较下游问答是否按无资料处理。只有下游明确输出无资料可引用且不生成商品结论时，才满足条件；不声称虚构规则检索一定返回 []。

三项均为纸面核对，未实际执行测试，不构成对任何业务动作的确认。
