# 直播售后集中处理的商品资料与选型问答：向量模型与索引

## 这个品类的数据长什么样

直播售后集中处理的核心材料是直播订单清单、退款申请、补发单和话术模板。这些材料的共同特征是单场流量后集中出现，且与主播当场承诺强相关。选型问答要回答的问题通常落在具体商品、型号、批次或承诺口径上，检索词里会混入订单号、退款单号、补发原因等短而杂的片段。

材料更新按每场后和日的节奏发生。这一节奏影响的是索引需要覆盖的文本范围，不意味着存在批量同步或交易触发的自动机制。

## 这些特征在「向量模型与索引」这一环带来什么约束

FastGPT 的知识库由库、集合和数据组成，最小搜索单位是库，集合只作分类管理。向量存储使用 PostgresSQL 的 PG Vector 插件，索引为 HNSW；MongoDB 的 dataset.datas 表保存原数据，indexes 字段记录对应的向量 ID 数组，一组数据可以对应多个向量。检索时先召回向量，再按向量 ID 回 MongoDB 找原数据，同一组原数据合并后取最高得分。

关联检索的知识库须使用相同向量模型。这一条约束的是节点输入侧的选择范围，不能扩展为外部系统也须同模型。混合检索通过 RRF 融合语义与全文两路结果，RRF 是融合过程，不存在对应的开启开关。重排须具备 ReRank 模型并按设置启用，图片检索须有相应图像输入及模型能力，这些可选路径不代表每次请求全部执行。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离功能。

### 假设演练样本

以下材料与请求均为纸面假设，用于核对本页功能，不代表任何真实记录或已发生的操作。

材料原文（补发单备注，假设）：单号 BF-2024-0871，商品为某品牌便携榨汁机，型号 PZ-200，颜色白，故障为杯体卡扣断裂，客服已登记补发同型号同色一件。该单当前状态为待仓库确认库存。

材料原文（话术模板节选，假设）：涉及 PZ-200 卡扣问题的咨询，统一说明为已登记补发，补发时效以仓库出库通知为准。

待判定拟稿句（假设）：针对 PZ-200 卡扣断裂的退款申请，回复“已确认补发，无需再提交退款”。

判定要点：拟稿句把补发登记写成已确认，把退款申请的处理边界扩大为无需再提交。材料原文只显示待仓库确认库存，未载明补发已批准或退款申请已关闭。该拟稿句属于未获支持，须记录证据缺口。

## 配置怎么定

下表只列与本页主任务相关的官方已说明设置或实施核对项。涉及数值时明确为本次假设试验起点，并说明比较对象。

| 配置或核对项 | 本次假设取值或动作 | 依据与比较方式 |
| --- | --- | --- |
| 关联知识库 | 选取向量模型标识一致的知识库 | 节点要求相同向量模型，先核标识再排除不符者 |
| 搜索模式 | 混合检索 | 型号、单号类查询依赖全文命中，自然语言问法依赖语义召回 |
| 引用上限 | 假设起点 3000 tokens | 官方按 tokens 控制引用上限，与 2000 和 4000 两个起点比对引用原文完整度 |
| 最低相关度 | 假设起点 0.4 | 官方为 0-1 数值，仅在语义检索或重排时生效，与 0.3 和 0.5 比对过滤后剩余条数 |
| 问题优化 | 多轮追问场景开启 | 官方说明其增加一次模型调用并提升连续对话检索效果 |
| 重排 | 具备 ReRank 模型时启用 | 官方说明重排得分可用于过滤，与未启用时的排序比对 |

## 容易做错的三处

1. 把补发登记当成补发已确认。输入是材料原文中的“待仓库确认库存”，比较对象是拟稿句中的“已确认补发”，可观察结果是两者状态字段不一致，拟稿句未获支持。
2. 把检索结果当成授权依据。输入是知识库召回的补发单备注，比较对象是退款申请的处理动作，可观察结果是检索链路没有产生审批或关闭退款的记录，业务动作须由下游实现。
3. 把不同向量模型的知识库强行关联。输入是两个模型标识不同的知识库，比较对象是节点要求相同向量模型，可观察结果是标识不一致时应排除，不执行跨模型检索比较。

## 怎么确认配好了

1. 针对假设样本的拟稿句，输入材料原文与拟稿句，比较“待仓库确认库存”与“已确认补发”，当拟稿句被标为未获支持并记录证据缺口时，判定通过。
2. 针对假设样本的退款请求，输入拟稿句中的“无需再提交退款”，比较材料原文是否载明退款申请已关闭，当原文无此字段且结果记为待核实时，判定通过。
3. 针对关联知识库，输入两个模型标识不同的知识库，比较标识是否一致，当不一致者被排除且未执行跨模型检索时，判定通过。

引用内容以数组输出，长度可以为 0。用明确的纸面输入空数组核对下游设计即可，不声称任何虚构规则检索一定返回空。
