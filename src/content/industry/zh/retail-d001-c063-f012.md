# 直播售后集中处理的商品资料与选型问答：文档解析与分块

## 这个品类的数据长什么样
直播售后集中在单场流量后爆发，退款申请与补发单在同一时段大量进入，客服需要对照直播订单清单确认商品与承诺，再用话术模板统一解释。资料更新频率为每场后与日，文档解析与分块决定这些材料能否被准确召回。直播订单清单含订单号与商品名称，退款申请含申请原因与状态，补发单含补发对象与数量，话术模板含适用场景与措辞。资料结构与语义完整度直接影响检索精度。

## 这些特征在「文档解析与分块」这一环带来什么约束
FastGPT 的知识库由库、集合和数据组成，最小搜索单位是库，集合仅作分类管理，与搜索效果无关。一组数据可对应多个向量，向量得分取最高得分。检索时先召回向量，再按向量 ID 在 MongoDB 的 dataset.datas 中寻找原数据，对应同一组原数据则合并。分段应保持条件、说明与所约束内容同组，避免拆离。全文检索适合编号、型号与专有名词，语义检索适合自然语言问法。

假设演练样本：材料原文为“订单 A 的退款申请状态为待审核，申请原因为商品与直播展示不符；补发单 B 的补发对象为订单 A，数量一件，尚未出库。”待判定拟稿句为“订单 A 的退款已通过，补发单 B 已出库。”原文仅载明退款申请处于待审核，补发单尚未出库，拟稿句所述状态与原文不一致。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 资料含订单号与自然语言原因，与单独语义检索比较召回覆盖 |
| 引用上限 | 按 tokens 计，起点待定 | 官方以 tokens 控制引用，与不同 chunk 长度下的稳定性比较 |
| 最低相关度 | 0-1 数值，起点待定 | 仅在语义检索或结果重排时生效，与过滤前后结果比较 |
| 问题优化 | 按需开启 | 连续追问时补全指代，与关闭时耗时比较 |
| 结果重排 | 具备模型时启用 | 候选较多时二次排序，与重排前排序比较 |
| 分段核对 | 人工核对 | 检查条件与所约束内容是否同组，与原文结构比较 |

以上数值均为本次假设试验起点，不构成官方默认值。RRF 是混合结果融合过程，不设为开关。图片检索需有图像输入与相应模型能力，重排需具备模型并按设置启用。

## 容易做错的三处
1. 将上传成功当作检索已更新。资料变更后需核对实际训练与索引状态，上传动作与索引生效是两个事实。
2. 将检索或表单当作授权执行。检索不承担权限隔离，表单收集值，业务核验、审批与外部同步需另接系统实现。
3. 将待审核当作已通过。样本中退款申请状态为待审核，拟稿句写成已通过，属同字段取值矛盾。

## 怎么确认配好了
1. 输入样本原文与拟稿句，比较退款申请状态字段：原文为待审核，拟稿句为已通过，两者同字段互斥，判定为矛盾。
2. 输入样本原文与拟稿句，比较补发单出库状态：原文为尚未出库，拟稿句为已出库，判定为矛盾；若原文未载明出库状态，则记为未获支持。
3. 输入订单号与自然语言问法分别检索，观察返回内容是否指向同一组原数据；若返回为空，以明确纸面输入核对下游设计，不声称虚构规则必返回空。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察。
