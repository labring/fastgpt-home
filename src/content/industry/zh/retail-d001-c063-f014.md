# 直播售后集中处理的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样
直播售后集中在单场流量后爆发，退款申请、补发单与话术模板往往在同一时段内大量出现，客服需要按直播订单清单逐单核对商品资料。商品资料与选型问答要求回答能追溯到具体文档，例如退款申请中的商品名称、规格与话术模板中的承诺口径是否一致。数据来源包括抖店售后、客服IM、仓库WMS与物流轨迹，更新频率为每场后与每日。这一特征意味着模型接入与配置需要先保证资料可被检索到，再保证回答不越过授权边界。

## 这些特征在「模型接入与配置」这一环带来什么约束
模型接入依赖 AI Proxy。按 v4.17.2 文档，App 与复用 App/Service 配置的 Admin 服务都必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。模型类型至少需要语言模型与索引模型；语音识别模型仅生效一个。检索是资料召回过程，不承担权限或实体隔离职责，检索命中不等于获得退款、补发或对外承诺的授权。

假设演练样本（纸面核对，非真实记录）：材料原文一为退款申请：“订单号 A-001，商品为某品牌保温杯 500ml，买家申请退款，原因为杯盖漏水。”材料原文二为话术模板：“漏水类问题可先致歉并说明补发杯盖，补发需仓库确认库存。”待判定拟稿句：“订单 A-001 已批准退款，并已安排补发杯盖。”核对主体为售后客服，对象为订单 A-001，状态为退款申请待处理、补发未执行，有效范围为上述两份材料。

## 配置怎么定
配置围绕本页样本的模型接入与核对项展开，数值为本次假设试验起点，需与文档说明或实际观测值比较后决定是否沿用。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://aiproxy:3000` | 文档要求填服务根地址且不附加 `/v1`；与文档示例结构比较，确认无多余路径。 |
| `AIPROXY_API_TOKEN` | 非空管理员 Token | 文档要求与服务端一致且不能为空；与 AI Proxy 服务端配置逐字比较。 |
| 语言模型 | 已启用一个语言模型 | 文档要求系统至少一个语言模型；在模型列表核对 `isActive` 为启用状态。 |
| 索引模型 | 已启用一个索引模型 | 文档要求系统至少一个索引模型；在模型列表核对类型为索引模型。 |
| 模型测试 | 对已配置渠道执行模型测试 | 文档提供渠道测试与模型测试入口；比较测试输出与请求时长，不预设通过。 |
| 检索核对 | 用样本材料原文发起检索 | 观察返回内容是否包含订单 A-001 与杯盖漏水字段；空结果按空结果记录。 |

## 容易做错的三处
1. 把检索命中当成授权执行。输入为样本材料原文检索结果，比较对象为退款申请状态与补发执行记录，若检索返回杯盖漏水段落而拟稿句写“已批准退款”，则授权状态与拟稿不一致。
2. 把模型测试当成业务验证。输入为渠道测试输出，比较对象为退款申请与补发单的实际处理记录，测试成功只说明模型可调用，不说明订单已处理。
3. 把话术模板当成已执行补发。输入为话术模板中“补发需仓库确认库存”，比较对象为仓库WMS补发单记录，模板存在不表示补发单已创建或已出库。

## 怎么确认配好了
1. 核对拟稿句与材料原文。输入样本拟稿句“订单 A-001 已批准退款，并已安排补发杯盖”；比较退款申请状态“待处理”与补发执行记录“未执行”；若拟稿句声称已批准或已安排，则判定为未获支持，需改为待核实表述。
2. 核对模型接入配置。输入 `AIPROXY_API_ENDPOINT` 与 `AIPROXY_API_TOKEN` 的实际填写值；比较文档要求：根地址不附加 `/v1`、Token 非空且与服务端一致；若任一项不符，启动校验可能失败，需修正后重启再核对。
3. 核对检索与授权边界。输入样本材料原文发起检索；比较返回内容是否包含订单 A-001、杯盖漏水、补发需仓库确认等字段；若返回为空，按空结果记录并保留证据缺口，不推断退款或补发已执行。检索结果仅用于资料召回，退款批准、补发执行与对外承诺仍需对应业务系统与授权记录确认。
