# 直播间违规申诉的商品资料与选型问答：文档解析与分块

## 这个品类的数据长什么样

违规申诉处理的是已经发生的处罚，材料围绕违规通知、直播录屏、商品资质与申诉说明展开，需要能回指原文的证据链。这类材料的更新不定期，每次违规单独产生一批文件，因此解析与分块要保留文档身份与版本，便于把某段结论对应回具体通知或具体资质文件。商品资料与选型问答的主任务，是把商品资质、违规通知中的商品指向、申诉说明中的商品描述整理成可检索的分块，供后续问答引用。

## 这些特征在「文档解析与分块」这一环带来什么约束

分块要按材料自身结构切分，违规通知里的违规事实、处罚依据、申诉期限与商品对象属于同一组约束，拆离后单独一段无法支撑判断。商品资质常含编号、型号、有效期，语义检索对这类精确串的匹配不稳定，全文检索更适合编号与专有名词。同一组原数据可以对应多个索引，向量原数据存于 MongoDB 的 dataset.datas，indexes 字段记录其对应的向量 ID 数组；检索时先召回向量，再按向量 ID 回 MongoDB 取原数据，命中同一组原数据则合并，向量得分取最高。图片能否被检索，取决于入库时是否生成图片描述索引或图片向量索引，以及模型能力。

假设演练样本：一份标注为“某店铺 2025 年 3 月违规通知”的材料原文写有“本通知涉及商品编号 A-1024，违规事实为标题含禁用词，申诉期限为通知送达后七日”。同一批材料中一份商品资质写有“编号 A-1024，资质有效期至 2025 年 12 月”。待判定的拟稿句为“该商品资质在违规发生时已过期”。核对时比较拟稿句与两份原文：资质有效期覆盖违规发生月份，拟稿句主张的过期状态未获原文支持，属于待核实，需要补充能证明有效期的字段或另行说明。

## 配置怎么定

| 核对项 | 本页相关设置或动作 | 观察与比较 |
| --- | --- | --- |
| 文档身份与版本 | 保留通知编号、商品编号、资质版本 | 分块能否回指具体原文 |
| 分段完整性 | 按通知与资质结构切分 | 违规事实、期限、商品对象是否同段 |
| 索引建立 | 确认入库时是否生成文本、图片描述或图片向量索引 | 与 dataset.datas 的 indexes 记录比对 |
| 检索模式 | 编号类问题用全文或混合检索 | 编号、型号命中情况 |
| 引用上限 | 本次假设试验起点设为覆盖一份通知加一份资质的 tokens 量，理由是该组合构成一次完整判断所需材料，与仅覆盖单份通知的较小值比较 | 引用是否覆盖两份材料 |
| 更新后复核 | 资料变更后核对实际训练与索引状态 | 上传成功与检索已更新分开记录 |

## 容易做错的三处

1. 把上传成功当作索引已更新。输入是新版资质文件，比较上传记录与检索返回的分块内容，若检索仍返回旧版本文字，说明索引未反映变更，需重新核对训练与索引状态。
2. 把语义相似度当作权限或实体过滤。输入是某商品的编号查询，比较返回内容是否包含其他商品编号，若出现无关商品分块，说明相似度设置不承担实体隔离，需在检索范围或人工核对层面另行处理。
3. 把待审核的申诉请求当作已获授权。输入是标注“待审核”的申诉说明，比较其状态字段与已生效通知，若拟稿句据此声称申诉已受理，属于未获支持，需保留待核实。

## 怎么确认配好了

1. 输入假设样本中的商品编号 A-1024 与违规通知原文，比较返回分块是否同时含违规事实、期限与商品对象，三者同段出现且可回指原文，才满足分段完整性核对。
2. 输入假设样本中的拟稿句“该商品资质在违规发生时已过期”，比较其与资质原文的有效期字段，若原文有效期覆盖违规月份，则该拟稿句未获支持；若原文缺失有效期字段，记录为证据缺口。
3. 输入空引用列表 []，核对下游对空结果的承接设计，确认空结果有明确处理路径；不据此推断某虚构规则检索必然返回空。跨不同向量模型的库核对标识后排除不符合者，记录实际观察，不执行跨模型检索比较漏召回。
