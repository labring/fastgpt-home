# 直播间违规申诉的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

直播间违规申诉针对已发生的平台处罚展开，材料围绕违规通知、直播录屏、商品资质与申诉说明组织。商品资料与选型问答这一任务，需要把商品资质与申诉说明中的可核对条目整理成可检索、可引用的问答依据，供合规与运营在撰写申诉理由时定位片段。资料更新不定期，每次违规触发一轮材料归集，因此问答库的入库范围、模型能力与引用边界需要事先约定，避免把未收录的材料当作已核实依据。

## 这些特征在「模型接入与配置」这一环带来什么约束

约束集中在三点。其一，AI Proxy 自 V4.17.0 起为必需依赖，App 与复用其配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 与非空 AIPROXY_API_TOKEN，缺少任一项启动校验失败；旧 OpenAI 环境变量或单模型自定义请求地址不能替代。其二，系统至少需要一个语言模型和一个索引模型才能正常使用，语音识别模型仅生效一个。其三，模型 ID 为接口请求 Body 中 model 字段的值且全局唯一，模型名仅用于展示；模型映射把 FastGPT 请求的模型映射到上游实际模型，例如把 gpt-4o-test 映射为 gpt-4o。检索与相似度只承担召回，不承担权限或实体隔离，检索不构成授权。

假设演练样本：某店铺收到平台违规通知，称其直播间在 2025 年 3 月 12 日 20:00 至 21:00 的讲解中，对一款保温杯宣称“保温 24 小时”，商品资质库中该款保温杯的检测报告标注保温效能为 12 小时。待判定拟稿句为：“本次讲解所述保温时长与商品资质记载一致。”该样本仅用于纸面核对，未实际提交、未实际检索、未获任何审批。

## 配置怎么定

下表仅列与本页主任务相关的官方已说明设置或实施核对项。数值列中标注“假设起点”的为本次纸面演练的起始值，其选取理由与比较对象在说明列给出，不表示官方默认值。

| 项目 | 假设起点 | 说明 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设起点 `http://aiproxy:3000` | 填 AI Proxy 服务根地址，不附加 `/v1`；与文档示例形式比较，确认无多余路径。 |
| AIPROXY_API_TOKEN | 假设起点 非空字符串 | 需与服务端配置一致且不能为空；与应用 API Key 比较，确认二者不同。 |
| 模型类型 | 语言模型、索引模型各一 | 与“至少一个语言模型和一个索引模型”的要求比较，确认两类均已启用。 |
| 模型映射 | 假设起点 `{"gpt-4o-test":"gpt-4o"}` | 与渠道内上游实际模型名比较，确认映射目标存在。 |
| 渠道测试 | 逐模型执行“开始测试” | 与测试结果及请求时长比较，确认配置的模型有效。 |
| 模型探测 | 假设起点 关闭自动探测 | 与“仅针对已启用系统模型”的范围说明比较，确认未启用模型不产生记录。 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 写成含 `/v1` 或完整对话地址的 URL。检查：输入该变量值，与文档“不要附加 `/v1`”的表述比较，出现多余路径即不满足。
2. 用应用 API Key 充当 AIPROXY_API_TOKEN。检查：输入该 Token 与服务端管理员 Token，比较二者是否一致且非空，不一致或为空即不满足。
3. 把检索命中当作已核实依据。检查：输入拟稿句与检索返回片段，比较片段是否来自商品资质且字段为保温效能，仅凭相似度得分不构成核实。

## 怎么确认配好了

- 验证一：取假设样本中商品资质原文“检测报告标注保温效能为 12 小时”与拟稿句“本次讲解所述保温时长与商品资质记载一致”。比较二者在同一字段上的取值，12 小时与 24 小时为同字段互斥取值，拟稿句未获支持。若原文未载明保温效能，则记录为待核实，不判定为否定。

- 验证二：取交接请求“请将上述拟稿句提交平台申诉”。比较该请求是否附带已签署的申诉说明与授权记录。样本中未见签署与授权材料，该请求处于待授权状态，不构成已执行。

- 验证三：取纸面输入的空检索结果 `[]`，核对下游设计在无片段时是否输出“未找到依据”。若下游直接生成结论句，则与空结果承接要求不符；该空结果仅为纸面输入，不表示任何真实检索会返回空值。

以上均为纸面核对，未实际调用模型、未实际检索、未提交申诉、未获审批。
