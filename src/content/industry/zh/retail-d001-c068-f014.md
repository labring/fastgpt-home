# 社区团购预售集单的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

预售集单先收订单再组织采购履约，商品资料与选型问答要回答的问题集中在：某个预售商品在截单前是否还能成团、规格与到货批次如何对应、采购计划里该商品是否已有安排。日常文档包括预售商品表、集单结果、采购计划、截单通知。这些材料按日或按场更新，因此同一商品在不同场次的描述可能不同，核对时必须锁定同一场次、同一商品、同一字段。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。系统至少需要一个语言模型和一个索引模型才能正常使用。模型 ID 是请求 Body 中 model 字段的值，全局唯一；模型名仅用于展示。

检索结果的相关度不承担权限或实体隔离职责。知识库检索与授权是两个层面：检索命中不表示当前操作者有权查看或改动该商品资料。表单收集的是值，业务核验、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：供核对的预售商品表原文为三句——“场次：2026-09-23 早场。商品：A 规格 500g 冷冻虾仁。截单时间：2026-09-23 06:00。集单结果：该商品已集单 42 份，未达 50 份成团线。”一条待判定的拟稿句为：“A 规格 500g 冷冻虾仁本场已成团，可安排采购。”材料中只有集单份数与成团线，没有成团结论字段，也没有采购计划记录。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址 | 与文档要求一致，比较是否误加 /v1 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空 Token | 比较是否误用应用 API Key 代替 |
| 语言模型 | 启用一个已测试通过的语言模型 | 系统至少需要一个语言模型 |
| 索引模型 | 启用一个已测试通过的索引模型 | 系统至少需要一个索引模型 |
| 模型能力 | 按问答所需输入核对 vision、toolChoice | 比较模型能力与任务输入是否匹配 |
| 模型探测间隔 | 假设起点 30 分钟 | 文档允许 5～60 分钟整数，与告警时效比较 |

渠道优先级范围 1～100，数值越大越容易被优先选中。模型调用日志仅保留 1 小时，环境变量可配置。

## 容易做错的三处

1. 把检索命中当作授权。输入是检索返回的商品资料片段，比较对象是当前操作者的权限范围，可观察结果是片段是否落在有访问权的目标检索范围内。命中片段本身不构成改动或采购授权。
2. 把集单份数直接读成成团结论。输入是“已集单 42 份，未达 50 份成团线”，比较对象是材料中是否存在成团字段，可观察结果是该字段缺失。缺失时结论为未获支持。
3. 把模型测试通过当作业务可用。输入是渠道测试结果，比较对象是商品资料问答的实际输入输出，可观察结果是回答是否引用了材料原文。测试通过只说明连通性。

## 怎么确认配好了

1. 针对拟稿句“A 规格 500g 冷冻虾仁本场已成团，可安排采购”，输入为上述三句原文与这句拟稿，比较对象是原文是否含成团结论字段，可观察结果是原文只有份数与成团线。满足条件为判定该拟稿句未获支持，并记录成团字段缺口。
2. 针对采购安排请求，输入为同一场次与商品标识，比较对象是采购计划中是否存在该商品记录，可观察结果是采购计划未提供。满足条件为记录该请求处于待核实状态，不视为已安排。
3. 针对检索环节，输入为明确纸面输入 []，比较对象是下游对空结果的承接设计，可观察结果是空结果是否被单独处理。满足条件为确认空结果不被当作命中，也不据此推断商品不存在。

模型状态探测仅针对已启用模型，首次失败后最多重试 3 次，4 次全失败判定为异常；正常为延迟不超过 30s，高延迟为超过 30s。告警 Webhook 在状态边沿变化时推送。未启用自动探测时页面呈现空状态。
