# 跨境海外仓补货管理的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

跨境海外仓补货管理涉及第三方海外仓服务多个渠道，卖家需自行分配库存，主要数据来自海外仓WMS、ERP销售预测、货代系统与承运商账单，日常文档包括补货计划、入仓预约、库存库龄表和尾程派送单。这些文档在商品资料与选型问答中作为待核对材料，资料更新频率为周或日，本页不据此推出批量同步或交易触发机制。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy 服务。App 与 Admin 均须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项启动校验失败；旧 OpenAI 环境变量或单模型自定义请求地址不能替代。系统至少需要一个语言模型和一个索引模型。模型 ID 为请求 Body 中 model 字段的值，全局唯一；模型渠道可按协议类型配置，一个模型可配置在不同渠道实现负载均衡。模型探测仅针对已启用的系统模型，重试最多 3 次，单轮最多尝试 4 次，全部失败才判定异常；告警 Webhook 在状态边沿变化时触发。

假设演练样本：某跨境卖家提交一份待核对材料，原文为“本补货计划覆盖 2026 年 9 月 1 日至 9 月 30 日，涉及德国海外仓 SKU-A 与 SKU-B；入仓预约单号 RK-0912 状态为已提交，尚未取得仓库确认；库存库龄表显示 SKU-B 库龄 95 天。”一条待判定拟稿句为“RK-0912 入仓预约已获仓库批准，可安排尾程派送。”原文未载明批准字段，该拟稿句未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | `http://aiproxy:3000` | 文档说明为服务根地址，不附加 `/v1`；与文档示例格式比较 |
| AIPROXY_API_TOKEN | 非空管理员 Token | 文档要求与服务端一致且不能为空；与部署端配置比较 |
| 语言模型与索引模型 | 各启用一个 | 文档要求至少各一个才能正常使用；与已启用模型列表比较 |
| 模型探测间隔 | 30 分钟 | 文档允许 5～60 分钟整数；与允许区间比较 |
| 告警 Webhook 地址 | 本次假设填写一个 HTTPS 回调地址 | 文档支持 HTTP/HTTPS；用测试按钮验证连通性 |
| 模型映射 | `gpt-4o-test` 映射到 `gpt-4o` | 文档示例格式；与渠道内模型 ID 比较 |

## 容易做错的三处

1. 把 RK-0912 的“已提交”当作仓库批准。输入为原文“状态为已提交，尚未取得仓库确认”，比较对象为拟稿句“已获仓库批准”，可观察结果是原文缺少批准字段，拟稿句未获支持。
2. 用 AIPROXY_API_TOKEN 之外的应用 API Key 代替管理员 Token。输入为部署端 Token 与 App 配置值，比较两者是否一致且非空，可观察结果是任一为空或不等时启动校验失败。
3. 把模型探测的 4 次尝试全部失败误读为单次失败即异常。输入为探测 attempts 字段，比较其值与文档说明的 1～4，可观察结果是 attempts 小于 4 时不构成异常判定。

## 怎么确认配好了

1. 对拟稿句“RK-0912 入仓预约已获仓库批准”执行核对：输入为假设原文两句与拟稿句，比较原文是否载明批准状态字段，只有原文出现批准字段且主体、单号、期间一致时才满足支持条件，否则记录为未获支持。
2. 对 Token 配置执行核对：输入为 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 的实际填写值，比较 Token 是否非空且与服务端一致，只有两项均满足时启动校验通过，任一缺失时记录为配置未完成。
3. 对模型探测重试执行核对：输入为一次探测的 attempts 与 status，比较 attempts 是否达到 4 且 status 为 red，只有两者同时成立才判定异常；attempts 小于 4 时记录为未达异常判定条件。
