# 连锁总部选址开店的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样
选址开店发生在门店营业前，资料围绕租赁与工程交付展开：选址评估表、租赁意向书、装修预算、开业排期。这些文件按店产生，更新不定期。做商品资料与选型问答时，模型接入需要先解决两个问题：资料中的字段口径是否被模型正确读取，以及回答是否越出资料载明的状态。租赁意向书里的报价有效期与押金条款属于不同字段，意向书本身不表示租赁已生效。

## 这些特征在「模型接入与配置」这一环带来什么约束
本页只处理商品资料与选型问答的模型接入与配置。AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 服务都必须设置 `AIPROXY_API_ENDPOINT` 与非空 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。`AIPROXY_API_ENDPOINT` 填服务根地址，不附加 `/v1`。模型渠道、模型 ID 映射、启用状态在管理员-模型提供商页面配置，模型能力按应用所需输入核对。检索与相关度评分不承担权限或实体隔离，检索结果不构成授权。

假设演练样本：材料原文为「某意向书载明：承租方为甲连锁总部，标的为乙商场三层铺位，签署日期为 2026 年 3 月 10 日，报价有效期至 2026 年 4 月 30 日，押金条款待双方确认。」拟判定句为「甲连锁总部已完成该铺位租赁签约，可安排装修进场。」待判定点：意向书签署与租赁合同生效是两个事实，材料未载明合同已生效，拟判定句超出原文范围，属于未获支持。

## 配置怎么定
下表只列与本页主任务相关的官方已说明设置或实施核对项。数值一栏为本次假设试验起点，不是官方默认值。

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填服务根地址，不带 `/v1` | 与部署模板中的实际地址逐字符比对 |
| `AIPROXY_API_TOKEN` | 非空管理员 Token | 与服务端配置比对，确认非空 |
| 模型 ID 映射 | 请求模型 ID 与渠道模型名一致 | 对照渠道配置中的映射记录 |
| 模型启用状态 | 仅启用问答所需模型 | 在系统模型页核对启用列表 |
| 模型能力 | 按问答所需输入核对 | 对照模型配置中的能力字段 |
| 模型探测 | 按需开启，间隔取 5～60 整数 | 在模型探测页核对配置值 |

## 容易做错的三处
1. 把意向书签署当作租赁合同生效。输入为上述样本原文与拟判定句，比较对象是原文是否载明合同生效，原文未载明时判定为未获支持。
2. 用应用 API Key 代替 AI Proxy 管理员 Token。输入为两份凭证，比较对象是 `AIPROXY_API_TOKEN` 的取值来源，取值来自应用侧时判定为配置不符。
3. 把检索命中当作权限依据。输入为一次检索返回结果，比较对象是该结果是否附带授权记录，没有授权记录时不能据此执行任何业务动作。

## 怎么确认配好了
1. 输入样本原文与拟判定句，比较原文是否载明租赁合同生效，只有原文明确载明生效条件与生效状态时，拟判定句才满足条件。
2. 输入 `AIPROXY_API_ENDPOINT` 与 `AIPROXY_API_TOKEN`，比较地址是否为根地址、Token 是否非空且与服务端一致，两项同时满足才通过启动校验。
3. 输入一次问答请求，比较回答是否只引用材料载明字段，出现材料未载明的签约或进场结论时记为未获支持，保留证据缺口。
