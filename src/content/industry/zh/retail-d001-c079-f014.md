# 连锁统采统配的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

在连锁统采统配的商品资料与选型问答中，本页说明FastGPT的模型接入与配置如何衔接资料。对统采统配资料问答区分订购单位、可用包装与分店需求，不由型号一致推配货条件齐全。所用场景为自拟文字测试。

## 这些特征在「模型接入与配置」这一环带来什么约束

统采选型练习可拟总部需求单“门店按件申领，仓内按箱备货，拆箱规则待核”，供应方目录只列箱装型号。模型接入应测试这些计量层级是否与原句一同传入，能否解释现有包装资料和门店需求之间还差什么。箱装型号存在不证明可以拆零，门店按件申请也不意味着仓库已有可分发数量。选型答案可以列需要补查的拆箱说明与本批可用记录，不能自行补出包装换算关系或库存承诺。当前输入均为自拟文字，不是可执行采购单。

## 配置怎么定

| 统采选型核对 | 纸面条件 | 需查原文 |
| --- | --- | --- |
| 计量层级 | 门店按件仓内按箱 | 不自动换算 |
| 包装限制 | 拆箱规则待核 | 同型号包装说明 |
| 可用状态 | 备货意向 | 本批实际可用记录 |
| 配送状态 | 计划与门店回执分开 | 出库及收件凭证 |
| 输出使用 | 拟交后续系统 | 解析与事实各核 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `AI Proxy依赖` | 按实际版本核服务、渠道与应用。 |
| `AIPROXY_API_ENDPOINT` | 使用AI Proxy服务根地址。 |
| `AIPROXY_API_TOKEN` | 管理员Token非空且与服务端一致。 |
| `模型能力` | 按实际输入路径验证所需能力。 |
| `应用参数` | 接口同名字段未必覆盖应用设置。 |

## 容易做错的三处

- 拆箱待核句没进入请求而答案给出可按件发放时，核实际输入与源段清单，定位限制在传入路径的遗漏。

- 供应方箱装目录被当成门店单件需求已满足时，核计量对象及实际包装说明，不能以型号同名代替拆零依据。

- 仓内备货意向被答为各店已收到时，分别核总部计划、出库记录与门店回执，找配送完成的真实来源。

## 怎么确认配好了

验收固定这份需求单与目录，分别问订购单位、拆零条件和各店当前可确认的状态，保存模型采用的原句。补入拆箱说明后先核同一包装与型号，再用原题检查条件是否得到对应；补发货材料后另查门店和批次。切换模型或参数时保持资料与问题不变，记录差异所依托的实际输入，不能据文字流畅给出配送能力结论。若输出需要交后续系统，格式可解析与业务字段有据要分别核，解析成功不自动产生采购或配货。
