# 连锁门店闭店清算的商品资料与选型问答：模型接入与配置

## 这个品类的数据长什么样

闭店清算处理退出与资产回收，方向与选址开店相反。资料来自 POS 库存、固定资产系统、租赁合同与财务账，典型文档为闭店审批、库存清退单、租约解除协议与资产盘点表。这些材料按店、不定期更新，同一门店的库存数量、资产状态与租约条款分散在不同系统，商品资料与选型问答需要同时引用多份材料才能回答。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 与非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填写 AI Proxy 服务根地址，不附加 `/v1`。系统至少需要一个语言模型和一个索引模型才能正常使用。模型 ID 是请求 Body 中 `model` 字段的值，全局唯一；模型名仅用于展示。模型映射可将 FastGPT 请求的模型映射到上游实际模型，例如将 `gpt-4o-test` 映射为 `gpt-4o`。检索与授权是两件事：知识库检索返回相关文本块，不判断某位运营或财务是否有权查看某店租约，权限判断需要另接系统实现。同一向量模型下的库才可共同关联，跨不同向量模型的库不可共同关联，此时只能核对标识并排除不符合者。

## 配置怎么定

以下围绕假设演练样本设置，数值为本次假设试验起点，需与文档默认值或实际观察值比较。

假设演练样本：材料原文为“门店 A 闭店审批单载明：闭店日期 2025-06-30，状态为待区域运营复核。资产盘点表载明：货架 12 组，状态为已清点。租约解除协议载明：解除生效日为 2025-07-31，双方签署栏均为空白。”待判定拟稿句为“门店 A 已于 2025-06-30 完成闭店，租约已解除。”

| 配置项 | 本页设置或核对动作 | 依据与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 根地址，不带 `/v1` | 文档说明必填且不加 `/v1` |
| AIPROXY_API_TOKEN | 填写非空管理员 Token | 文档说明必填且不能为空 |
| 语言模型 | 启用至少一个语言模型 | 文档说明系统最低要求 |
| 索引模型 | 启用至少一个索引模型 | 文档说明系统最低要求 |
| 模型映射 | 核对 FastGPT 模型 ID 与上游实际模型对应关系 | 文档给出 `gpt-4o-test` 到 `gpt-4o` 示例 |
| 模型测试 | 在渠道页点击模型测试，观察每个模型的测试结果与请求时长 | 文档说明测试会实际发送请求 |

## 容易做错的三处

1. 把待审核状态当作已完成。闭店审批单状态为“待区域运营复核”，拟稿句写成“已完成闭店”，输入与比较对象是审批单状态字段与拟稿句中的完成表述，观察结果是两者不一致。
2. 把签署栏空白当作租约已解除。租约解除协议签署栏空白，拟稿句写成“租约已解除”，输入与比较对象是协议签署栏与拟稿句的解除表述，观察结果是拟稿句缺少签署证据支持。
3. 把同一向量模型库的关联能力扩展到外部系统。假设两个知识库使用不同向量模型，核对标识后应排除跨库共同关联，不能据此推断外部工商网站也需同模型。

## 怎么确认配好了

- 验证一：输入假设演练样本的材料原文与拟稿句，比较拟稿句“已完成闭店”与审批单“待区域运营复核”，观察结果为两者状态不一致，拟稿句未获支持。

- 验证二：输入租约解除协议原文与拟稿句“租约已解除”，比较签署栏空白与解除表述，观察结果为签署证据缺失，该表述待核实。

- 验证三：输入两个使用不同向量模型的知识库标识，核对向量模型字段，观察结果为标识不符，应排除共同关联，不执行跨库检索比较。

空结果承接可用明确的纸面输入 `[]` 核对下游设计，不能声称虚构规则检索一定返回 `[]`。模型探测的告警 Webhook 在状态边沿变化时触发，事件类型为 `model_status_error` 或 `model_status_recovered`，属于需另接系统实现的业务动作。
