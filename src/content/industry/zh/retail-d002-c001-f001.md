# B2B平台撮合交易的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
B2B平台撮合交易的企业认证资料、询报价单、电子合同与平台结算单，构成订单履约与售后答疑的主要文档对象。与批发市场档口交易相比，在线认证与电子合同更多，交易不依赖现场档口，因此订单状态、履约节点与售后请求需要经由 HTTP 接口在平台与外部系统之间传递。数据来源包括 B2B平台、国家企业信用信息公示系统、支付流水与物流轨迹，更新频率为日与每单。这些文档在接口环节表现为请求参数、请求体、请求头与返回值，核对重点落在材料所载主体、对象、状态与有效范围是否与外部接口契约一致。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params 为路径请求参数，Body 为请求体，Headers 为请求头。三种数据均可通过 `{{}}` 引用变量，URL 也可引用变量，变量来自全局变量、系统变量与前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime 与 histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 提取，输出类型选择字符串时会将对应 key 的值转为 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>。传入的 model、temperature 等字段无效，由编排决定。detail=true 可返回中间值，responseData 中保存模块状态与完整结果。交互节点返回的 interactive 只含 type 与 params，entryNodeIds、memoryEdges、nodeOutputs、nodeResponseId 等内部运行态字段不会返回。表单输入需将对象序列化成字符串作为 messages 值，并保持 chatId 一致。检索与相似度不承担权限或实体隔离，检索不是授权。

假设演练样本：某B2B平台运营人员交接一笔撮合订单的售后答疑，材料原文为“供应商甲于2025年3月10日提交企业认证资料，平台结算单显示该订单金额为人民币12万元，电子合同状态为待签署”。拟稿句为“该订单已完成签署，可执行退款”。此样本中主体为供应商甲，对象为该笔订单，状态为待签署，有效范围未载明。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选择，地址引用已提供变量 | 比对接口文档所载路径与方法 |
| Params 与 Headers | 鉴权凭证经安全配置注入 | 核对请求头字段与外部契约 |
| Body | 仅在相应请求类型下使用，核对 JSON 结构 | 比对字段名与值类型 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 逐项核对实际传入值 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 确认测试模式空值属预期 |
| 返回值提取 | 按 JSON path 提取，输出类型选择字符串 | 比对提取结果与响应原文 |

## 容易做错的三处
1. 将拟稿句“该订单已完成签署，可执行退款”当作既定事实。材料原文仅载明电子合同状态为待签署，签署、合作达成与合同生效是三个不同事实，待签署不构成已完成签署，退款亦无授权依据。
2. 把检索或表单收集当作授权执行。表单收集值，业务验证、审批、数据库写入与外部同步需要各自的下游实现，检索结果不构成权限或实体隔离。
3. 将测试模式下 chatId 与 responseChatItemId 的空值判定为业务故障。文档明确二者在测试模式下不存在，需与真实运行区分。

## 怎么确认配好了
1. 输入上述假设演练样本的材料原文与拟稿句，比较拟稿句所载“已完成签署”与原文“待签署”是否同主体、同期间、同一字段。原文状态为待签署，拟稿句为已完成签署，二者互斥，判定为未获支持。
2. 输入一条针对该订单的交接请求，比较请求所载授权状态与材料所载状态。材料未载明退款授权，请求若含退款执行，则超出授权边界，记录为待核实。
3. 输入测试模式下的一次 HTTP 调用，比较 chatId 与 responseChatItemId 的实际取值与文档说明。二者在测试模式下不存在，空值属预期现象，不判定为接口异常。
