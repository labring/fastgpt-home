# B2B平台撮合交易的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

B2B平台撮合交易的企业认证资料、询报价单、电子合同与平台结算单，构成订单履约与售后答疑的主要文档来源。与批发市场档口交易相比，本类业务的在线认证和电子合同更多，交易过程不依赖现场档口，对话记录因此承担了部分过程留痕职能。日常数据来自B2B平台、国家企业信用信息公示系统、支付流水与物流轨迹，更新频率为日或每单。这些事实影响本页任务的方式是：对话日志需要与上述文档在主体、对象、状态上可核对，而日志留存本身不完成业务审计。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话接口以 chatId 标识一个应用下的会话，dataId 标识会话下的对话。传入非空 chatId 时，系统从数据库取会话，messages 数组最后一个内容作为用户问题，其余 message 被忽略。传入 responseChatItemId 时，该值作为本次响应消息 ID 存入数据库，需在当前 chatId 下唯一。detail 控制是否返回中间值，非 stream 模式结果保存在 responseData 中。以上字段的实际返回内容需要逐项核对，未返回的业务数据不能推定已完整留存。

假设演练样本：某B2B平台运营于2025年6月10日处理一笔撮合订单的售后咨询。供核对的材料原文为三句：「供应商甲提交的企业认证资料显示统一社会信用代码尾号1234，认证状态为待复核。」「采购方乙的询报价单载明采购数量200件，报价有效期至2025年6月30日。」「双方电子合同处于已签署状态，平台结算单尚未生成。」待判定的交接请求为：「请确认该订单对话日志可否作为供应商甲主体资格已通过的审计依据。」此请求的授权边界是：对话日志只反映对话内容与运行记录，企业认证是否通过需由认证审核流程另行确认。

## 配置怎么定

| 配置或核对项 | 本页相关设定 | 依据与说明 |
| --- | --- | --- |
| appId 与 chatId | 请求中同时提供，chatId 需唯一且长度小于 250 | 文档说明 chatId 非空时使用数据库会话 |
| responseChatItemId | 本次假设试验起点设为「order-20250610-001」 | 选择该值是为与订单日期对应，便于与 chatId 下其他对话区分；文档要求其在当前 chatId 下唯一 |
| detail | 需要运行详情时设为 true | 文档说明 responseData 保存中间值 |
| messages 与 variables | 按对话或插件输入分别传入 | 文档说明 variables 替换输入框中的 [key] |
| 会话列表 source | 核对 API 创建会话时使用 source=api | 文档说明该值不获取页面上的会话 |
| 授权状态核对 | 将认证审核、合同签署、结算生成分别标注为独立状态 | 对话日志不承载上述业务动作的完成判定 |

## 容易做错的三处

1. 将对话日志中出现的认证资料描述当作认证已通过。输入是上述材料原文第一句，比较对象是认证状态字段「待复核」，可观察结果是状态与「已通过」不一致。
2. 将询报价单的报价有效期当作合同履行期限。输入是材料原文第二句，比较对象是电子合同的签署状态与结算单生成状态，可观察结果是报价有效期与合同状态属于不同文档的不同字段。
3. 将 responseChatItemId 的假设起点值当作官方默认值。输入是该假设值，比较对象是文档中未给出该字段默认值的说明，可观察结果是文档未定义默认值。

## 怎么确认配好了

1. 使用材料原文第一句与交接请求，输入为认证状态「待复核」，比较对象为「已通过」的判定条件，满足条件是确认两者不一致并记录认证审核需另行确认。
2. 使用材料原文第二句与第三句，输入为报价有效期与合同已签署状态，比较对象为结算单是否生成，满足条件是确认结算单尚未生成属于独立状态。
3. 使用假设起点值「order-20250610-001」，输入为该值，比较对象为文档中 responseChatItemId 唯一性要求，满足条件是确认该值在当前 chatId 下未与其他对话重复，且文档未声明其为默认值。
