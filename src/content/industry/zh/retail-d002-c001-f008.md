# B2B平台撮合交易的订单履约与售后答疑：工作流编排

## 这个品类的数据长什么样

在B2B平台撮合交易的订单履约与售后答疑中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

电子合同写了售后承诺，平台结算单显示完成且没有退货，这组文字仍未提供每项售后服务的执行凭证。拟议流程可以先请核对者提交要检查的承诺原文，再把提交内容传给下一步。检查表单时，应将实际填写的条款与后续收到的文字并列，确认核对对象没有从服务承诺变成交易状态。表单完成只表示收到了这次输入，承诺是否履行需要另取对应的业务记录。

## 配置怎么定

| 核对项 | 拟议输入或路径 | 验收线索 |
| --- | --- | --- |
| 表单输入节点 | 收集核对者选定的售后承诺原文 | 后续收到同一条款，未换成结算状态 |
| 用户选择节点 | 拟议选项：补维修材料或交售后核查 | 每个选项对应已连接分支 |
| 交互状态核对 | 分别测试等待提交和完成提交 | 输入确实进入接收步骤 |
| 输出承接核对 | 承诺、维修日期与选择分别核对 | 没有把进入分支写成确定违约 |
| 外部操作分工 | 物流查询及交接状态写入另接真实接口 | 外部响应、凭证缺项及记录分别保存 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

- 表单提交售后承诺，后续却收到交易完成状态时，逐项比较填写原句与接收值，定位核对对象被替换的环节。

- 质保期内维修被当成违约时，回查质保范围与维修记录；维修可能属于服务内容，不能由这两个词认定承诺冲突。

- 选择补交付凭证后仍没有物流或签收材料，流程却写成已履约时，核选择分支及实际收到的依据，不以继续运行代替交付记录。

## 怎么确认配好了

合同约定了交付时间，却没有物流跟踪或签收凭证时，后续步骤还缺实际交付依据。补资料路径应明确接收什么文本、由哪一步承接，再分别测试等待提交和提交后的传值。若方案还要查询物流或写入交接状态，需另接真实业务接口并核对响应及记录。验收不能只看连线和表单状态，还要说明哪些凭证确实收到、哪些仍待补充，以及外部操作究竟执行到了哪一步。
