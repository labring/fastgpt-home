# B2B平台撮合交易的订单履约与售后答疑：引用来源与溯源

## 这个品类的数据长什么样

在B2B平台撮合交易的订单履约与售后答疑中，本页说明FastGPT的引用来源与溯源如何衔接资料。账务关闭、咨询约定和请求转交不能合并为服务完成。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

B2B售后资料练习自拟合同条款“交付后提供使用咨询”、结算台账“往来已关闭”和服务登记“咨询请求已转交”。有人问服务义务是否履行完毕时，三份材料分别说明约定、账务状态与请求流转，尚没有咨询已答复的记录。来源追溯应把结论落在相应维度；账务关闭与服务继续处理可以同时成立，不能只因出现关闭二字就宣布售后事项全部结束。转交动作也未说明接收方是技术人员还是另一处理岗位，不能据此推定咨询已经由适格人员受理。若要说明服务进度，需查实际接收和答复记录；合同范围、请求去向与答复内容应保持为三个独立证据对象。

## 配置怎么定

| 本题核对项 | 材料条件 | 取证动作 |
| --- | --- | --- |
| 约定义务 | 交付后使用咨询 | 回指条款的服务范围。 |
| 账务状态 | 往来已关闭 | 限于台账维度。 |
| 流转动作 | 请求已转交 | 保留动作与对象。 |
| 执行缺口 | 尚无实际答复记录 | 补核咨询答复材料。 |
| 结论边界 | 多份引用仍缺服务结果 | 逐项核依据覆盖。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

常见错误是把结算来源当作咨询履行证明，或把合同承诺原句当作已经完成服务的事实。前者需要查实际服务过程，后者需要将约定与执行分开。FastGPT引用数组即使同时包含合同和台账，也没有自动填上答复记录。若片段只写已转交，要保留该动作的主语和范围；无法从请求流转推定对方已经收到解答，更不能自行裁定合同义务已解除。

## 怎么确认配好了

验收可问“约定提供什么”“请求目前到哪一步”“是否已有答复依据”。回答应分别回指咨询条款、转交登记，并对最后一问列出待补的实际答复材料。对照引用内容是否包含限定词，避免标题为售后记录就把整条链视为完成。空引用先查本次检索范围与传入片段；没有返回服务证据与服务从未发生，应保持为不同判断。
