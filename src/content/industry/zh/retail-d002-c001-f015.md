# B2B平台撮合交易的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

B2B平台撮合交易的企业认证资料、询报价单、电子合同与平台结算单，构成订单履约与售后答疑的主要文档来源。这些材料通常包含企业名称、统一社会信用代码、报价有效期、合同签署状态、结算周期等字段。与批发市场档口交易相比，B2B平台交易在线认证和电子合同更多，不依赖现场档口，因此检索请求多以文字描述与编号混合出现。企业认证资料的审核状态、电子合同的签署与生效状态、报价单的有效期，都属于不同字段的不同事实，检索结果不能把其中一个字段的值当作另一个字段的结论。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可以关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，实施时先核对向量模型标识，排除不符合者，不执行跨模型检索来比较漏召回。语义检索依赖向量距离，全文检索依赖关键词命中，混合检索通过 RRF 融合两路结果。最低相关度是过滤阈值，仅在语义检索或使用结果重排时生效，不承担权限或实体隔离功能。引用上限以 token 为单位，控制每次搜索最多引用的内容量。问题优化在检索前增加一次模型调用，用于指代消除和问题扩展。输出引用内容以数组格式返回，长度可以为 0，没有搜索到内容时输出链路仍然走通。图片检索需要相应图像输入及模型能力，重排需要具备模型并按设置启用，文档流程图列出的可选路径不代表每次请求全部执行。

## 配置怎么定

假设演练样本：某B2B平台运营人员处理一笔撮合订单的售后咨询。供核对的材料原文为：“供应商甲于2025年3月10日提交企业认证资料，认证状态为待审核；询报价单编号RFQ-20250310-07，报价有效期至2025年3月31日；电子合同编号CT-20250312-11，双方签署栏均为空白；平台结算单编号ST-20250315-03，结算状态为未结算。”待判定的拟稿句为：“该订单已完成企业认证，合同已生效，可以按结算单发起付款。”

| 配置项 | 本样本取值 | 理由与比较方式 |
| --- | --- | --- |
| 关联的知识库 | 订单履约与售后答疑库 | 先核对向量模型标识，确认与当前节点一致再关联 |
| 搜索模式 | 混合检索 | 样本含编号与自然语言，比较语义与全文两路结果 |
| 引用上限 | 本次假设试验起点设为 3000 tokens | 与样本四份材料合并长度比较，观察引用是否完整 |
| 最低相关度 | 本次假设试验起点设为 0.3 | 先标注相关与无关样本，再与过滤后结果比较 |
| 问题优化 | 开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 按设置启用 | 确认具备重排模型后，比较重排得分与向量得分 |

上述数值为本次假设试验起点，不是官方默认值。

## 容易做错的三处

1. 把“待审核”当作“已认证”。样本中企业认证资料的状态字段为待审核，拟稿句称已完成企业认证，同一字段的取值互斥，该句未获支持。
2. 把“签署栏空白”当作“合同已生效”。样本中电子合同双方签署栏均为空白，签署、合作达成、合同生效是三个不同事实，拟稿句称合同已生效缺少依据。
3. 把“报价有效期”当作“供货期限”。样本中报价有效期至2025年3月31日，该字段只说明报价有效范围，不表示供货期限，拟稿句据此发起付款属于跨字段推断。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较拟稿句中的认证状态与材料原文的认证状态字段，观察结果是否指出“待审核”与“已完成企业认证”在同一字段上互斥。满足条件时，核对结论应标注该句未获支持。
2. 输入样本材料原文与拟稿句，比较拟稿句中的合同状态与材料原文的签署栏字段，观察结果是否指出签署栏空白不构成合同生效。满足条件时，核对结论应保留证据缺口，不补造授权或生效条款。
3. 输入样本材料原文与拟稿句，比较拟稿句中的付款依据与材料原文的报价有效期、结算状态字段，观察结果是否指出报价有效期不表示供货期限、未结算不表示可付款。满足条件时，核对结论应记录待核实项。

纸面输入空数组 [] 时，可核对下游设计是否承接长度为 0 的引用输出，不声称虚构规则检索一定返回 []。检索或表单不构成授权执行，待审核不证明缺少操作权限，未签署不构成已完成终止。
