# MCN机构达人管理的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

MCN机构同时管理多位达人的长期账号合规，履约与售后问题分散在达人签约合同、培训记录、违规处理单和账号排期四类材料中。日更与周更的账号数据、平台违规通知和合同台账共同构成售后答疑的事实来源。订单履约环节的排期调整、内容审核结论和违规处置，往往需要向外部排期系统或合同台账系统发起请求，HTTP模块因此成为衔接内部编排与外部业务服务的通道。外部接口的返回值只说明接口按契约返回了内容，不说明账号状态、合同效力或授权已经成立。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP模块向对应地址发送请求，Params用于路径请求参数，Body用于请求体，Headers用于传递特殊信息，三者都可以通过双花括号引用变量。变量来自全局变量、系统变量和前方节点输出。系统变量中，chatId与responseChatItemId在测试模式下不存在，调试时出现空值属于测试环境特征，不构成业务故障。请求地址可以引用变量，鉴权凭证应通过安全配置注入，不写入公开样例。返回值解析通过JSON path提取，输出类型选择字符串时会把对应键的值转成JSON字符串。detail为true时返回中间值，非流式结果保存在responseData中；插件类应用默认detail模式，通过pluginData获取插件输出。这些能力只解决请求发送与结果提取，业务侧的授权、审批和数据库写入需要外部系统自身实现。检索与相似度不承担权限或实体隔离职责。

假设演练样本：某MCN机构运营人员提交一份达人排期调整交接请求，材料原文为“达人A于2026年3月10日至3月20日参与品牌B专场直播，账号排期表登记状态为待审核，达人签约合同签署日期为2026年3月1日，合同生效条款载明双方盖章后生效，违规处理单编号W20260301记录内容审核通过。”拟判定句为“达人A的排期调整已获批准，可通知外部排期系统执行变更。”该请求涉及主体达人A、对象品牌B专场、期间2026年3月10日至3月20日、状态待审核，授权边界为运营人员提交，未载明审批完成记录。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 引用前方节点输出的外部排期系统地址变量 | 与外部接口文档给出的地址逐字符比对，确认路径与方法一致 |
| 请求方法 | POST | 与外部接口文档声明的方法比对，不一致时记录差异 |
| Headers鉴权 | 通过安全配置注入Bearer凭证 | 核对凭证是否来自安全配置，不写入公开样例 |
| Body结构 | 按外部接口契约声明JSON字段 | 与外部接口文档字段清单逐项比对，缺失字段记录缺口 |
| 返回值提取键 | 按外部接口响应结构配置JSON path | 用假设响应样本核对提取路径与输出类型 |
| detail参数 | true | 与本次核对需要中间值的判断比对，确认是否需要responseData |

## 容易做错的三处

1. 把待审核排期状态当作审批完成。输入为假设样本中“账号排期表登记状态为待审核”，比较对象为“已获批准”的判定，可观察结果是排期调整请求缺少审批完成记录，待审核状态不构成批准。
2. 把合同签署日期当作合同生效。输入为假设样本中“签署日期为2026年3月1日”与“双方盖章后生效”，比较对象为合同生效事实，可观察结果是签署与生效属于不同事实，生效条件是否满足未载明。
3. 把HTTP返回值当作业务授权。输入为外部接口返回内容，比较对象为运营人员提交的交接请求，可观察结果是接口返回只说明请求按契约完成，不说明排期变更已获授权执行。

## 怎么确认配好了

1. 针对假设样本的待审核状态，输入排期表登记原文，比较“待审核”与“已获批准”两个字段取值，只有出现明确审批完成记录并载明同意变更时，才满足批准条件；当前样本记录为未获支持。
2. 针对假设样本的合同生效判断，输入签署日期与生效条款原文，比较签署事实与生效事实，只有出现双方盖章完成记录时，才满足生效条件；当前样本记录为待核实。
3. 针对拟判定句的交接请求，输入运营人员提交记录与外部排期系统返回内容，比较请求提交动作与执行结果，只有出现外部系统确认变更完成的记录时，才满足执行条件；当前样本未载明执行结果，缺口保留。
