# MCN机构达人管理的订单履约与售后答疑：工作流编排

## 这个品类的数据长什么样

在MCN机构达人管理的订单履约与售后答疑中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

达人合同写明的售后分工，回答的是合作方之间约定由谁处理哪些事项；消费者订单的实际状态需要另一组记录。可用一条自拟输入测试这种区分：“已提供达人合同的责任段，尚无本次消费者退货凭证。”表单接收责任原句和当前咨询，再向后续步骤传值。检查答复是否仍区分合同解释与订单查询，不能把达人承担某项责任写成这次退款已经处理。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 责任解释 | 达人合同的售后分工段 | 没有被改写为消费者订单处理结果 |
| 订单依据 | 当前咨询及尚缺的退货凭证 | 接收步骤保留合同与订单的区别 |
| 交接选择 | 补订单、查合同或交实际售后方 | 逐项记录选项去向及传入内容 |
| 规则补充 | 合同未覆盖的消费者退货退款政策 | 补充后引用对应规则，不引用佣金替代 |
| 办理结果 | 客服或订单系统实际返回 | 另核创建记录、审批及操作状态 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

违规处理单提到商品质量问题，也不能单独说明消费者应得到哪种售后结果。流程应先收集该处理记录与合同对应关系，再让资料负责人选择补订单证据、回查合作约定或交接给实际售后处理方。逐条验证选项连接，尤其检查“交接”路径实际发送了什么内容。选择转交不等于工单已创建，处理单上的责任表述也不能代替业务审批。 例如，问题询问消费者退款进度，接收步骤却只有达人佣金条款，应排查当前问题与传入资料之间的对应关系。将佣金解释留在其实际范围，另外收集本次订单的处理依据，再对比两次回答。不能把合同中的结算分工改写成消费者退款已到账的事实。

## 怎么确认配好了

现有合同若只说明佣金结算，缺少消费者退货退款规则，应把所需规则、来源提供者和接收步骤写清楚。补齐资料后重复原问题，核查后续输入和最终出处，避免将佣金条款当成消费者售后政策。需要向客服系统或订单系统提交处理请求时，另验真实接口、授权与业务返回；本次问答只能描述已经取得的依据和仍待办理的事项。
