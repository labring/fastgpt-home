# Shopify独立站订单履约的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

Shopify独立站由商家自行配置支付、运费和履约服务，不由平台统一自动退货。订单详情、运费模板、发货标签、退款记录构成日常处理的主要文档，数据更新频率为每单与每日。这些材料分散在Shopify Admin、支付网关、承运商系统和库存地点数据中，HTTP接口承担把外部系统返回值接入对话流程的职责。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP模块向对应地址发送请求，Params用于路径参数，Body用于请求体，Headers用于请求头。三种数据均可通过{{}}引用变量，URL同样可以引用。变量来源为全局变量、系统变量、前方节点输出。返回值通过JSON path提取，配置的key遵守JS对象取值规则。出参格式化在v4.6.8后加入，输出类型选择字符串时会将对应key的值转为json字符串。

对话接口使用APIKey鉴权，调用chat/completions时推荐在请求体传入body.appId；为兼容OpenAI SDK也支持Authorization: Bearer <apiKey>-<appId>。appId优先级为body.appId、<apiKey>-<appId>、apikey关联的appId。传入的model、temperature等参数字段无效，由编排决定。不会返回实际消耗Token值，设置detail=true后可手动计算responseData里的tokens值。chatId为测试模式下不存在，responseChatItemId同样在测试模式下不存在。authProxy代理团队成员身份需要团队所有者开启，代理身份仍需具备目标应用和会话权限。

假设演练样本：某独立站运营人员提交一份待核对材料，原文为“订单A于2025年3月10日创建，状态为已发货，承运商系统回传单号SF123456789。退款记录显示该订单无退款申请。”另有一条拟稿交接请求：“请将订单A的履约状态同步至外部系统，并确认退款记录为空。”

## 配置怎么定

| 配置项 | 本次假设起点 | 理由与比较方法 |
| --- | --- | --- |
| URL | 按外部接口文档填写地址 | 地址可引用变量，与外部接口契约核对 |
| 请求方法 | 按外部接口文档选择 | 与外部接口文档声明的方法比较 |
| Headers | Authorization: Bearer {{token}} | 凭证通过安全配置注入，不写入公开样例 |
| Body | 按外部接口契约构造JSON | 仅在相应请求类型下生效，核对字段结构 |
| 变量引用 | 引用前方节点输出 | 逐项核对实际传入值，与节点输出比较 |
| 返回值提取 | 配置key对应JSON path | 遵守JS对象取值规则，与接口响应结构比较 |

## 容易做错的三处

1. 将测试模式下不存在的chatId或responseChatItemId当作业务故障处理。输入为测试模式请求，比较对象为文档说明的测试模式不存在条件，观察结果为是否误判为故障。
2. 将节点已有行为与需另接系统实现的业务动作混同。输入为拟稿交接请求，比较对象为文档说明的节点行为范围，观察结果为是否把同步外部系统当作节点自动完成。
3. 将检索或表单收集的值当作授权执行依据。输入为表单输入内容，比较对象为文档说明的表单仅收集值，观察结果为是否把表单值直接当作授权执行。

## 怎么确认配好了

1. 输入假设演练样本中的材料原文与拟稿交接请求，比较拟稿句是否与材料原文同主体、同期间、同字段，观察结果是否出现未获支持或待核实的判定。
2. 输入一条引用前方节点输出的变量配置，比较实际传入值与节点输出值，观察结果是否一致；若不一致则记录缺口，不声称已实测。
3. 输入一条detail=true的请求，比较responseData中是否包含tokens值，观察结果是否可手动计算；不声称已实际执行。
