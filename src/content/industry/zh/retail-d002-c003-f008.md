# Shopify独立站订单履约的订单履约与售后答疑：工作流编排

## 这个品类的数据长什么样

在Shopify独立站订单履约的订单履约与售后答疑中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

独立站订单显示的状态、发货标签和承运商记录，需要在流程中保持各自来源。自拟文字样例可以写“标签已经生成，承运商揽收依据尚未提供”，用来检查输入接收是否准确。表单提交这段说明后，比较下一步实际得到的文字，确认“生成标签”没有被替换成“包裹已揽收”。商家配置的履约方式或运费信息，也不能单独证明这笔订单已经交付。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 标签与揽收 | 已生成标签，尚缺承运商接收依据 | 后续输入没有将两种状态合并 |
| 表单承接 | 订单来源及当前咨询原句 | 下一步收到原文和对应资料身份 |
| 售后分支 | 补承运商记录、查退款或读条款 | 各选择仅进入其已连接处理路径 |
| 送达与政策缺项 | 签收凭证及适用退换货依据 | 取得后复测原问题，保留尚未知项 |
| 实际操作 | 退货、退款或履约变更的业务响应 | 操作记录与对话完成分别核验 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

订单记录与部分退款记录可以描述同一交易的不同方面，应先核对应关系再决定售后路径。可设计让负责人选择补承运商证据、查看退款来源或继续核对服务条款，并逐个检查实际连接与接收值。一次选择只安排下一步阅读或交接，不负责裁定退款是否足额、商品是否签收，也不能直接触发未经确认的订单变更。 还应测试退款记录中的订单对应关系：若补入的是另一笔订单的处理记录，本次问题依旧无法得到进度依据。把订单详情与退款资料指向的对象并列核查，移出不对应的记录，再将缺少当前处理凭据的状态传给接收人，观察答复是否停止沿用错误进度。

## 怎么确认配好了

如果只有商品信息和收货地址，没有适用的退换货政策或签收凭证，流程应将这些缺项交给明确的资料提供者。补齐后，用原咨询复核历史输入和新材料是否被正确承接，检查回答有没有把地址当作已送达证据。需要创建退货、退款或修改履约状态时，应另外核对外部业务接口、操作权限和实际记录，不能由问答或表单结束推断办理完成。
