# Shopify独立站订单履约的订单履约与售后答疑：引用来源与溯源

## 这个品类的数据长什么样

在Shopify独立站订单履约的订单履约与售后答疑中，本页说明FastGPT的引用来源与溯源如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

自拟订单详情写明待交接，同时注明物流标识尚未提供。回答交付进度时，这两处文字都应能回指到订单附页；引用到商品或收货地址，并没有回答交接进度。检查时保存检索输出数组，再与回答环节收到的引用逐项比较，查看待交接状态和缺少物流标识的说明是否一并传入。最后将生成的进度表述与这份原文对照，记录其是否擅自写成已发货，整个测试只核文字依据。

## 配置怎么定

| 核对项 | 本题输入与条件 | 验收线索 |
| --- | --- | --- |
| 关联的知识库 | 自拟订单详情与退款记录；关联库须同向量模型 | 订单与退款各自出处 |
| 引用内容输出 | 分别测试有引用及空数组；空数组可继续传递 | 回答环节实际收到的值 |
| 引用输入承接 | 对照检索输出与回答输入 | 待交接和物流标识缺项同时保留 |
| 引用展示核对 | 逐状态回指来源 | 已完成与部分退款未被误写为互相否定 |
| 资料时效核对 | 政策来源与订单记录分别标明版本 | 缺少退换货政策时仍保留缺项 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

- 原文待交接且缺物流标识，答复却写已发货时，对照检索输出数组、回答收到的引用和进度句，定位新增事件。

- 已完成与部分退款被当成互斥状态时，分别回查订单和退款来源，不用其中一项抹掉另一业务维度。

- 退换货政策问题只引用商品和地址时，核引用是否真支持政策句；数组非空不等于依据适用，空数组也不预设链路自动停止。

## 怎么确认配好了

只有商品信息和收货地址的订单详情，无法提供退换货政策依据。用政策问题测试时，要检查返回引用究竟支持哪些句子；即使引用数组有内容，也可能只是订单文字。空数组同样允许链路继续，应观察回答实际拿到的输入及最终措辞。补充政策或交给售后核对的路径需要在方案中另行设计，验收要分别记录证据缺项、引用承接和该路径的接收结果。
