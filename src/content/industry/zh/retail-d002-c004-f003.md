# Temu半托管卖家运营的订单履约与售后答疑：分享与嵌入

## 这个品类的数据长什么样

在Temu半托管卖家运营的订单履约与售后答疑中，本页说明FastGPT的分享与嵌入如何衔接资料。以指定仓履约异常摘要核分享边界，保留库存、物流与平台处理的独立依据。所用场景为自拟文字测试。

## 这些特征在「分享与嵌入」这一环带来什么约束

自拟售后协作入口拟提供某仓履约异常摘要，不开放其他仓库存及内部采购测算。完整链接应在接收环境核商品、仓库与期间，再问受限来源测拒绝。若他仓数量或内部条件被回答转述，应保存完整返回查授权；同商品并不说明资料属于同一范围。入口标识不能识别真实仓库人员或赋予外部操作权，拟开放摘要要按实际读取结果确认。

## 配置怎么定

| 协作分享核对项 | 仓库履约摘要 | 实际验收 |
| --- | --- | --- |
| 摘要身份 | 商品、仓库和期间 | 接收环境原文 |
| 范围限制 | 他仓库存及内部测算排除 | 完整返回及拒绝 |
| 阶段证据 | 在库不证明已发运 | 承运原句与输出 |
| 设备承接 | 电脑到手机的订单及前问 | 缺对象补来源 |
| 业务执行 | 答复不改申报或同步WMS | 系统结果与入口条件另核 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `免登录窗口` | 复制生成的完整分享链接。 |
| `过期时间与QPM` | QPM指每用户每分钟访问上限。 |
| `积分上限` | 按入口及版本核用量与费用条件。 |
| `身份验证` | 第三方认证受商业版范围限制。 |
| `对话记录边界` | 匿名标识依赖同设备、同浏览器。 |

## 容易做错的三处

- 指定仓摘要带出别仓数量或内部测算：保留商品仓库期间及完整返回查范围，同一商品不构成全仓共享依据。

- 电脑问库存、手机问发货时缺订单历史：核实际带入的仓和前问，补来源；匿名标识不自动继承，不能据相似商品补主体。

- 在库被写成已发运或平台已处理：对照库存原句、承运及处理记录，区分未给结果与结果未传入；答复不自动同步WMS或提交申报。

## 怎么确认配好了

验收分别对指定摘要、其他仓表和内部测算做读拒测试，记录实际原文与版本适用的访问条件。需身份验证时另验商业版能力和返回。已有承运记录未进入输入与原记录未取得分开定位，分别查传递或补来源。答复可以整理异常所需材料，不同步WMS、不提交平台处理或修改申报；真实履约阶段与解决结果仍需实际系统及责任人确认。
