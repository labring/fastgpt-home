# Temu半托管卖家运营的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样
Temu半托管卖家运营与全托管供货的差别在于，卖家要自行维护海外库存并完成发货，信息来源分散在Temu Seller Center、境外仓WMS、物流轨迹和采购成本表之间。日常文档包括商品申报表、海外库存表、价格申报和平台履约单，更新频率为每日和每单。订单履约与售后答疑场景下，检索请求往往指向具体履约单、库存批次或申报条目，因此知识库中同一批材料可能同时存在申报值、库存值和平台回传值，检索环节需要保留这些来源标识，供后续人工核对时区分。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的库，跨不同向量模型的库不可共同关联；核对时应先确认各库的向量模型标识，将不符合者排除，记录实际观察结果。搜索模式分为语义检索、全文检索和混合检索，混合检索通过 RRF 融合多路结果，RRF 是融合过程，不是可开启的开关。最低相关度仅在语义检索或使用结果重排时生效，引用上限以 token 为单位。问题优化用于指代消除和问题扩展，会增加一次模型调用。输出引用内容为数组，长度可以为 0，空结果链路仍会走通。检索结果反映的是内容相似性，不承担权限或实体隔离，检索到某条记录不代表该记录已被授权使用。

假设演练样本：材料原文为“海外库存表 A 行：SKU-TM-0417，德国仓，可用数量 120，更新日期 2025-03-11。平台履约单 B 行：订单 8825001，SKU-TM-0417，状态待发货，创建日期 2025-03-11。价格申报 C 行：SKU-TM-0417，申报价 12.90 欧元，有效期至 2025-04-30。”待判定拟稿句为“SKU-TM-0417 德国仓库存充足，订单 8825001 可立即发货。”该拟稿句把库存数量与履约单状态合并成发货结论，材料未载明发货授权或库存冻结规则，因此属于未获支持。

## 配置怎么定
下表围绕上述样本列出与本功能相关的设置或核对项，数值为本次假设试验起点，用于与另一组取值比较，不作为默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 关联知识库 | 库存库与履约单库，先核向量模型标识 | 模型标识一致才可共同关联，与不一致的库比较 |
| 搜索模式 | 混合检索 | 样本含编号 SKU-TM-0417，与纯语义检索比较 |
| 引用上限 | 800 token | 样本三行合计较短，与 400 token 比较内容完整性 |
| 最低相关度 | 0.35 | 样本含相关行与无关行，与 0.5 比较过滤效果 |
| 问题优化 | 开启 | 样本问题含指代，与关闭时比较主体是否被改错 |
| 结果重排 | 启用并记录得分 | 样本候选较少，与不重排比较排序差异 |

## 容易做错的三处
1. 把检索命中当作授权。输入为查询“订单 8825001”，比较检索结果与授权状态字段，若结果只含履约单内容而无授权记录，可观察到的现象是检索返回了记录但授权仍未知。
2. 把库存数量直接推出可发货结论。输入为拟稿句“库存充足，可立即发货”，比较库存表与履约单状态字段，若履约单状态为待发货且无发货授权记录，可观察到的现象是拟稿句超出材料范围。
3. 把最低相关度当作实体过滤。输入为无关查询“其他卖家库存”，比较返回内容与查询主体，若返回了同库其他条目，可观察到的现象是相关度阈值未排除非目标主体。

## 怎么确认配好了
1. 输入假设样本三行原文与拟稿句，比较拟稿句中的“可立即发货”与材料是否载明发货授权，若材料未载明，则拟稿句应判为未获支持，需记录证据缺口。
2. 输入查询“SKU-TM-0417 德国仓库存”，比较返回内容是否包含库存表 A 行原文，若返回内容含该行且引用上限内完整，则视为该查询路径可用；若返回为空数组，则按空结果承接核对下游设计，不推断规则一定返回空。
3. 输入含指代的问题“这个订单能发吗”，比较问题优化前后主体是否仍指向订单 8825001，若优化后主体被替换为其他订单，则记录为问题优化引入的偏差，需人工复核。
