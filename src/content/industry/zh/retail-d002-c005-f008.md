# TikTok Shop美国店运营的订单履约与售后答疑：工作流编排

## 这个品类的数据长什么样

在TikTok Shop美国店运营的订单履约与售后答疑中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

售后流程需要把申请、退件资料和退款记录当作不同环节的证据。可编写一条自拟文本：“已取得退货申请，现有材料没有说明实物接收情况。”表单收集申请原句及当前咨询后，核对下一步收到的内容，避免把“提出申请”写成“退件已经验收”。平台记录、承运商轨迹和Return Grading材料要根据实际提供情况分别使用，不能从资料名称猜测状态。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 申请与收货区分 | 已给退货申请，实物接收尚无依据 | 申请没有被改写为验收完成 |
| 交互传递 | 当前咨询及申请资料身份 | 后续步骤收到同一商品的文字 |
| 证据分支 | 查轨迹、读规则或交实际质检方 | 逐项验证目的地和接收原文 |
| 待补依据 | 规则、实物记录或退款凭证 | 补齐后复核出处，不自动裁定争议 |
| 平台处理 | 上传、申诉或退款的实际返回 | 单独回查对应操作与处理记录 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

有Return Grading证据时，应先明确它对应哪件商品、记录了什么，再选择接下来的处理路径。可设计补承运商记录、回查平台售后规则或交给实际质检方的选项，并分别验证接收步骤。人员选择查看某份证据，不代表争议已经裁定，也不能让模型自行决定平台的退款结果。分支测试应保留所选动作与传入原文，防止不同商品的记录混用。 还可编一项错配测试：退货图片属于另一订单，当前申请只有文字说明。若回答借图认定本单商品状态，应排查图片对应对象和传入顺序，拆开两项记录再复问；当前订单没有检查依据的事实，应传给接收人继续核实，不能沿用错配的判定。

## 怎么确认配好了

缺少适用规则、实物记录或退款凭证时，应将所缺依据交给明确的提供者；补齐后再用原问题核对传值和最终出处。若需要上传证据、提交申诉或执行退款，必须另有获授权的业务接口及真实返回。即使工作流能继续回答，也只说明对话路径运行；实际平台处理结果需要回查对应记录，不能由节点连接或表单提交推定。
