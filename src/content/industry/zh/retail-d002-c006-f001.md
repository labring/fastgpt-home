# 一般贸易出口报关的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

一般贸易出口报关每单产生报关单、商业发票、装箱单和合同，数据来源包括中国国际贸易单一窗口、海关编码库、货代提单和企业 ERP。出口报关还牵动出口退税凭证匹配，申报差错会带来退单查验与退税受阻。本页只处理订单履约与售后答疑中 HTTP 接口与外部系统的对接条件：外部系统如何接收报关单与发票数据、如何回传状态，以及答疑时如何引用这些回传值。数据按每单更新，接口调用发生在单证流转的各个节点。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径参数，Body 用于 POST/PUT 请求体，Headers 用于请求头。三类数据与 URL 均可通过 {{}} 引用全局变量、系统变量和前方节点输出。系统变量含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 或 JS 对象取值规则提取，输出类型选字符串时会把对应 key 的值转成 json 字符串。对话接口调用 chat/completions 时推荐在请求体传 appId，鉴权用 APIKey；传入的 model、temperature 无效，由编排决定；detail=true 可取得 responseData 中的 tokens 并手动计算。交互节点返回的 interactive 只含 type 与 params，entryNodeIds、memoryEdges、nodeOutputs、nodeResponseId 等运行态字段不返回。表单输入继续运行时须保持 chatId 一致，并以对象序列化字符串作为 messages 内容。

假设演练样本：某外贸公司单证员在订单履约与售后答疑中，拟将一批出口报关数据推送至外部货代系统。供核对的材料原文为：“商业发票号 INV-2031，合同号 CT-2031，装箱单号 PL-2031，出口报关单号 D-2031，申报日期 2025 年 3 月 10 日，申报状态为已申报。”拟稿句为：“该批货物已完成放行，可安排出运。”待判定请求为：“请将上述已申报数据通过 HTTP 接口推送至货代系统，并回传受理结果。”原文只载明已申报，未载明放行、出运或受理结果；受理结果属于外部系统回传，需要接口实际返回才能确认。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式与依据 |
| --- | --- | --- |
| 请求地址与方法 | 按外部货代系统文档选择地址与方法 | 地址可引用变量，方法须与外部接口契约一致 |
| Headers 鉴权 | 以 Bearer 形式引用 token 变量 | 鉴权凭证通过安全配置注入，不写入公开样例 |
| Body 结构 | 按外部接口字段要求组织 JSON | 仅在 POST/PUT 下生效，逐字段核对契约 |
| 变量引用 | 引用前方节点输出的发票号、合同号、报关单号 | 逐项核对实际传入值，来源为全局变量、系统变量或前方节点输出 |
| 返回值提取 | 按 JSON path 提取受理状态字段 | 输出类型选字符串时转 json 字符串，key 按 JS 对象取值规则填写 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 测试模式空值不作为业务故障判断 |

## 容易做错的三处

1. 把“已申报”当作“已放行”。材料原文只写申报状态为已申报，未载明放行或出运。核对时比较原文状态字段与拟稿句结论，出现放行或出运字样而原文无对应记载，即为超出原文。
2. 把接口请求当作外部系统已受理。待判定请求要求回传受理结果，而请求发出不等于对方受理。核对时比较是否取得外部接口实际返回值，未取得返回值即受理状态未知。
3. 把测试模式下 chatId 为空当作会话故障。文档说明 chatId 与 responseChatItemId 在测试模式下不存在。核对时比较运行模式与字段取值，测试模式下的空值不作为业务异常。

## 怎么确认配好了

1. 输入为材料原文与拟稿句“该批货物已完成放行，可安排出运。”比较原文是否载明放行或出运，原文只载明已申报，拟稿句结论未获支持，应保留待核实。
2. 输入为待判定请求与外部接口返回情况。比较是否取得对方受理结果，未取得返回值时受理状态未知，不判定为已受理或已拒绝。
3. 输入为测试模式运行记录与 chatId、responseChatItemId 取值。比较运行模式与字段是否存在，测试模式下两字段不存在属文档已说明情形，不据此判定会话故障。
