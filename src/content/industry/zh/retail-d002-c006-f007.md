# 一般贸易出口报关的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

一般贸易出口报关每单都会产生报关单、商业发票、装箱单和合同，数据来自中国国际贸易单一窗口、海关编码库、货代提单与企业ERP。与进口报关相比，出口报关还会影响出口退税凭证匹配，因此对话日志若涉及单据字段，必须能回到具体单据与具体会话。日常最耗时的环节是归类商品编码、填制报关单、核对运费保费，这三类问题在售后答疑中反复出现，日志需要保留提问、回答与引用来源，才能支撑后续核对。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话接口以 chatId 标识一个会话，以 dataId 标识该会话下的一条对话。传入非空 chatId 时，系统从数据库取会话，messages 数组最后一个内容作为用户问题，其余 message 被忽略；不传 chatId 则完全由 messages 构建上下文。responseChatItemId 传入后作为本次响应消息的 ID 存入数据库，并要求在当前 chatId 下唯一。需要运行详情时按官方契约设置 detail，非流式结果保存在 responseData，流式通过 event 区分。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某外贸公司单证员在 chatId 为 “exp-chat-0007” 的会话中提交问题，材料原文为“出口报关单号 EXP-2024-0001，商业发票金额 12000 美元，装箱单件数 80 件，合同签署日期 2024 年 3 月 12 日”。拟稿句为“该单已通过出口退税凭证匹配”。待判定请求为“请确认这批货的报关单已放行”。原文含主体、对象与日期范围，未含放行状态与退税匹配结果。

## 配置怎么定

| 配置项 | 假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| chatId | exp-chat-0007 | 本次假设试验起点，与材料单号一一对应，便于按同一会话核对 |
| responseChatItemId | resp-0001 | 假设起点，要求在该 chatId 下唯一，与返回的 dataId 比较 |
| detail | true | 需要 responseData 中间值，与 detail=false 返回结构比较 |
| stream | false | 便于一次性读取 choices 与 responseData，与流式 event 比较 |
| source | api | 获取 API 创建的会话，与页面会话来源区分 |
| loadCustomFeedbacks | true | 读取自定义反馈，与不传该参数时的列表比较 |

## 容易做错的三处

1. 把检索或表单当成授权执行。检索只返回引用，不构成放行或退税匹配的授权，判定时须核对材料原文是否载明该状态。
2. 把不同 chatId 的会话混算。chatId 不同则上下文与历史不同，须先核标识再比较。
3. 把未返回字段推定为已留存。responseData 未出现的业务数据不能推定完整留存，须记录缺口。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句，比较拟稿句“已通过出口退税凭证匹配”与原文，原文未载明该状态，判定为未获支持，不称否定或冲突。
2. 输入待判定请求“请确认这批货的报关单已放行”，比较原文是否含放行状态，原文未载明，判定为待核实。
3. 输入同一 chatId 下两条对话记录，比较 dataId 是否唯一，若重复则说明 responseChatItemId 未满足唯一要求，记录观察结果，不推断系统报错原因。
