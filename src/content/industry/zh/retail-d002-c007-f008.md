# 一般贸易进口报关的订单履约与售后答疑：工作流编排

## 这个品类的数据长什么样

在一般贸易进口报关的订单履约与售后答疑中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

进口到港信息与收货验收应作为不同证据对象接收。可编一条自拟普通文本：“已提供到港通知，尚未提供收货方签收材料。”表单收集这段说明及具体咨询后，检查传给下一步的仍是资料现状，没有把“到港”改写成“客户已接收”。提单、合同和付款资料分别按其原文范围使用，不能由运输安排或付款方式推定全部交付与售后事项已经完成。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 到港与接收 | 到港通知已给，签收材料未给 | 接收步骤没有改写资料状态 |
| 单据承接 | 本批商品及提单、合同来源 | 后续值仍能回到对应材料 |
| 问题分流 | 查物流、核收货或交商品负责人 | 逐项核选项连接与接收内容 |
| 缺项补充 | 签收、验收或服务约定依据 | 补齐后回查引用及仍未知事项 |
| 实际任务 | 查询或售后业务接口真实返回 | 技术路径状态与办理结果分别记录 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

咨询若同时涉及运输状态和商品问题，可设计分别补物流记录、核收货材料或转交商品资料负责人的选择路径。检查每个选项连接及实际接收值，尤其保留本批商品与对应单据的关系。人员选择某条路径，不替代验收、责任确认或售后审批；即使接收步骤收到一段“同意处理”的文字，也要回查它来自谁、适用于什么范围。 若仓库接收记录只有汇总批次，客户询问的订单仍未关联，无法从该汇总说明判断订单已入库。回查记录覆盖的对象、订单与批次之间是否已有文字依据，保留未对应的部分。选择交仓库核对以后，还要看实际接收说明，不能把路径名称充作入库确认。

## 怎么确认配好了

缺少签收、验收或适用服务约定时，应将所缺依据与资料负责方一并记录。取得补充后，用同一问题验证后续输入和最终引用，检查还有哪些事项尚无证据。若需要生成运输查询或售后处理任务，应另验外部接口权限、返回和真实任务记录。工作流继续执行所表明的是技术路径状态，不能替代货物接收或业务办理的实际结果。
