# 一般贸易进口报关的订单履约与售后答疑：引用来源与溯源

## 这个品类的数据长什么样

在一般贸易进口报关的订单履约与售后答疑中，本页说明FastGPT的引用来源与溯源如何衔接资料。单证登记和名称更正都不能直接定位实物到仓。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

进口售后资料可自拟运单管理记录“单证已登记”、发票更正往来“货物名称待确认”和到货查询“暂未附卸货记录”。问这批货是否已经到仓时，单证登记只说明资料流转，名称待确认属于票据核对，缺卸货记录则是本组证据缺口。三者不能直接给出货物实际位置；尤其不能把登记动作解释成到货，也不能因发票待改就推定运输已经停止。名称更正还可能只涉及票据文字，本组没有说明货物本身发生改变。应把文件修订对象与实物状态分开，避免以待确认名称推导商品被调换或运输异常。对实物位置的回答仍需实际活动记录。

## 配置怎么定

| 本题核对项 | 材料条件 | 取证动作 |
| --- | --- | --- |
| 单证流转 | 登记属于资料动作 | 不推成货物到仓。 |
| 票据更正 | 名称仍待确认 | 核最终文字和更正关系。 |
| 位置依据 | 缺卸货与接收材料 | 列出应补的实际记录。 |
| 时间线索 | 新修改时间不等于确认 | 核状态原句。 |
| 引用内容 | 数组有文本也可能不含位置 | 逐段核证据覆盖。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

排查时区分两个风险：答案使用到仓结论，引用仅是运单登记；或者引用早期发票，把待确认名称当成现行已核名称。前者要补仓内接收或卸货依据，后者要核更正关系及最终文字。FastGPT的来源时间可以帮助找版本，但时间较新不必然代表确认完成。引用数组有材料时仍需检查其内容是否覆盖位置问题，不能把链接可访问作为物流事实的证明。

## 怎么确认配好了

验收可以分别问单证进度、名称更正进度、到仓证据。回答应回指登记动作与待确认状态，对到仓问题列明实际接收材料尚未取得。保留原始发票和更正往来各自身份，检查回答真正收到哪一段文字，防止遗漏待字。空引用时继续核本次范围与传入路径，不把运行中未返回材料改写成货物未到、单证未登记或更正已失败。
