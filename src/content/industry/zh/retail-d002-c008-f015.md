# 亚马逊FBA备货运营的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

FBA备货把库存前置到平台仓，入仓差异与库龄是主要风险，订单履约与售后答疑因此围绕入仓计划、箱唛、库存报告和赔偿申请四类材料展开。这些材料由运营、海外仓物流专员与采购分别维护，更新频率为日或周。检索环节要处理的正是这些材料的版本差异与状态差异：同一批货的入仓计划可能已确认，箱唛文件仍处于待审核，库存报告显示的收货数量与计划数量不一致，赔偿申请尚在平台受理中。检索结果只能呈现材料文本，不能替代对授权状态的判断。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的库，检索的最小单位是库，集合仅作分类管理。一次检索会按输入内容与搜索参数组合语义检索、全文检索、混合检索、问题优化与重排，再经相似度过滤与引用上限裁剪，输出引用内容数组，长度可以为 0。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。混合检索经 RRF 融合多路结果，重排得分可用于过滤。图片检索需要相应图像输入与模型能力，重排需要具备模型并按设置启用，这些路径并非每次请求都执行。检索与相似度得分不承担权限或实体隔离功能。

假设演练样本：某批 FBA 入仓计划原文为“计划编号 H-01，发运数量 600 件，目的仓为北美仓，状态为已确认；箱唛文件 B-01 状态为待审核；库存报告 R-01 记录已收货 540 件，差异 60 件待核实；赔偿申请 C-01 状态为平台受理中”。待判定拟稿句为“H-01 批次的 60 件差异已获平台赔偿”。该句涉及主体 H-01、对象为 60 件差异、状态为已获赔偿，与原文“待核实”“受理中”不一致，属未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联承载上述四类材料的同一向量模型库 | 先核各库向量模型标识，排除标识不符者，不执行跨模型共同关联 |
| 搜索模式 | 对编号类问题比较全文检索与混合检索 | 以 H-01、B-01 等编号为测试问题，观察命中片段是否含对应编号 |
| 引用上限 | 起点设为能容纳一份入仓计划完整字段的 token 量 | 用长短不同的实际材料测试内容完整性，再与相邻取值比较 |
| 最低相关度 | 起点设为 0.5，仅用于语义检索或重排 | 先标注相关与无关样本，比较不同阈值下的过滤现象 |
| 问题优化 | 对多轮追问开启，对编号明确的问题比较关闭效果 | 核对优化后问题的主体是否被改错 |
| 空结果承接 | 下游按引用内容为空数组设计 | 以纸面输入空数组核对下游分支，不声称虚构规则必返回空 |

## 容易做错的三处

1. 把待审核箱唛当作已审核并据此安排发货。输入为拟稿句“B-01 箱唛已审核，可安排入仓”；比较对象为原文“状态为待审核”；只有原文出现审核通过记录才满足条件，否则记为未获支持。
2. 把平台受理中的赔偿申请写成已获赔偿。输入为“C-01 已获赔偿”；比较对象为原文“受理中”；只有原文出现赔偿完成或到账记录才满足条件。
3. 用相似度得分排除无关业务记录。输入为“按最低相关度过滤掉其他店铺数据”；比较对象为文档说明的过滤阈值性质；只有存在明确权限字段与过滤实现才满足条件，检索得分本身不承担该功能。

## 怎么确认配好了

1. 将拟稿句“H-01 批次的 60 件差异已获平台赔偿”与原文“差异 60 件待核实”“C-01 状态为平台受理中”逐字段比较。输入为拟稿句与原文；比较主体、对象、状态三项；出现状态一致且均为已赔偿的原文才满足条件，本次记录为未获支持。
2. 以编号 H-01 为测试问题，在全文检索与混合检索下分别观察返回引用内容。输入为编号问题；比较命中片段是否含 H-01 及数量 600；出现编号与数量同时命中的片段为满足，未命中记为待查。
3. 以纸面输入空数组核对下游分支。输入为引用内容空数组；比较下游是否按长度可为 0 的链路继续执行；出现下游正常承接且不报错为满足，实际行为未观察时记为未知。
