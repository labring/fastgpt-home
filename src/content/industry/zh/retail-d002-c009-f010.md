# 亚马逊FBM自发货运营的订单履约与售后答疑：引用来源与溯源

## 这个品类的数据长什么样

在亚马逊FBM自发货运营的订单履约与售后答疑中，本页说明FastGPT的引用来源与溯源如何衔接资料。运单录入、承运等待揽收和买家询问各有范围。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

FBM售后查询自拟发货管理记录“运单信息已填”、承运查询摘录“等待揽收”和买家留言“请确认发出时间”。这三份材料没有实际揽收扫描或签收凭据。回答包裹走到哪一步时，应将运单信息准备与承运活动分开；填写信息能证明录入动作，等待揽收说明查询呈现的状态，买家问询则说明信息需求，不能把任何一项写成承运方已接到包裹。运单信息已填也没有说明所录编号是否已被承运活动关联。要回答实际揽收，应核对应事件与本件包裹身份；单有填写记录不足以建立这种关联，其他包裹的扫描也不能借相似时间移用到本件。

## 配置怎么定

| 本题核对项 | 材料条件 | 取证动作 |
| --- | --- | --- |
| 录入动作 | 运单信息已填 | 回指管理记录。 |
| 承运状态 | 摘录写等待揽收 | 保留查询时点。 |
| 问句身份 | 买家在请求确认时间 | 不把询问当答复。 |
| 发出依据 | 尚缺实际揽收事件 | 补核承运活动记录。 |
| 当前性 | 旧摘录不能证明状态未变 | 核更新材料再下结论。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

需要排查两种范围扩大：从已填运单推出实际发出，从买家确认问句推出已经确认发出时间。前者要查实际揽收材料，后者要找商家答复与其依据。FastGPT来源追溯应保留问句身份，不能只取发出时间几个字。引用数组如果只有管理记录，仍缺承运活动证明；若等待揽收摘录时间较早，也不能据此断言当前绝对没有变化。

## 怎么确认配好了

验收先问已知录入动作，再问现有承运状态，最后问实际发出时间的依据。答案分别回指已填信息与等待揽收，并注明当前时间结论需要更近的承运事件或答复证据。抽查实际引用是否保留摘录时间与来源身份，避免问句变陈述。空引用时核本次资料范围和传递路径，不把未返回片段解释成未创建运单，更不能补造运输进度。
