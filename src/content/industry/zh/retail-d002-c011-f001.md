# 仅退款争议处理的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

在仅退款争议处理的订单履约与售后答疑中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。仅退款答疑按配件、申请对象和补件提议分别查原文，不把等待意愿当平台撤单。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

本页自拟售后材料：买家说配件缺少，退款单尚未明确对应主商品还是配件，后续留言愿意等补件；商家回复只提议寄使用说明书，未给平台撤销记录或实际寄出凭据。HTTP读取应保留商品行、陈述方和每条动作，不能因在同一包裹就合并所有物品。愿等待是买家当前表态，说明书与实体配件也不是同一对象。本题无真实订单、金额或责任认定。

## 配置怎么定

| 仅退款事项HTTP | 自拟对象状态 | 核验动作 |
| --- | --- | --- |
| 买家所述 | 配件缺少 | 不扩大主商品 |
| 申请对象 | 商品行未明 | 保留行级缺项 |
| 后续留言 | 愿意等补件 | 不当平台撤销 |
| 商家提议 | 仅寄说明书 | 不当实体配件补齐 |
| 正式处理 | 撤销退款寄出另核 | 查询不执行 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

- 配件问题被答为整单主商品均已同意退款时，对申请对象、商品行与明确处理意见，不由同一订单扩大范围。

- 买家愿等补件被答成平台申请已撤销时，核留言原句和实际工单状态，沟通表态不执行平台操作。

- 商家寄说明书的提议被写成缺失配件已补齐时，对提议对象、买家所需物品及实际交接，不能把文档补发当实物修复。

## 怎么确认配好了

按真实接口契约核申请事项、订单行及消息范围，分别验证认证与业务访问，不填猜测参数。保存原始返回和答复出处；只返订单总状态时将具体申请对象列待核，不假装取得行级证据。补对象关系只修范围，平台撤销和补件执行仍各需材料。正式退款、撤销、发运与订单回写须授权流程及回执，查询只组织答疑，不代买卖方确认方案或发送消息。
