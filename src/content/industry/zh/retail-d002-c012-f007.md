# 仓内拣货复核打包的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

仓内拣货复核打包处理订单出库，不处理供应商到货，数据来源包括 WMS、订单系统、电子面单平台与称重设备，日常文档为波次拣货单、复核记录、面单与包装耗材单。出错后果是错发漏发、包裹破损与售后赔付，因此售后答疑需要把对话记录与具体订单的单据对应起来。数据更新频率为每单与小时，本页功能不依赖该频率，故不展开。

对话日志与审计在此环节的作用，是把一次售后问答与目标单据关联。对话接口的运行详情按官方契约通过 detail 参数控制，非 stream 模式结果保存在 responseData 中。日志存在本身不表示业务数据已完整留存，未返回的字段不能推定已保存。

## 这些特征在「对话日志与审计」这一环带来什么约束

会话身份以 chatId 区分，对话身份以 dataId 区分，应用身份以 appId 区分。不同入口创建的会话来源不同：source=api 只获取通过 API 创建的会话，清空应用会话仅清空通过 API Key 创建的会话，不会清空在线使用、分享链接等其他来源。核对时必须结合 chatId 确认目标对话，不把不同入口的会话混算。

需要运行详情时按官方契约设置 detail。detail=true 且 stream=false 时，responseData 中不同模块的响应值可能随版本有差异，应先记录再查看最新值。字段含义以接口实际返回为准。

检索与相似度不承担权限或实体隔离功能，检索本身不是授权。对账、留存与合规要求由完整业务方案另行落实。

假设演练样本（纸面材料，非真实业务）：

材料原文一，波次拣货单片段：“波次号 W-0311，订单 O-8821，商品 A 数量 2，拣货员已确认，状态为已拣货待复核。”

材料原文二，复核记录片段：“订单 O-8821，复核员确认商品 A 数量 2，称重 0.48 千克，状态为复核通过，时间 3 月 11 日 14 时。”

待判定拟稿句：“订单 O-8821 已完成打包出库，包裹已交付承运商。”

对照两份材料，主体为同一订单 O-8821，阶段为已拣货待复核与复核通过，均未载明打包完成、出库或交付承运商。该拟稿句超出材料所载状态。

## 配置怎么定

下表围绕上述样本，列出与本功能及订单履约售后答疑相关的官方已说明设置或实施核对项。数值为本次假设试验起点，不是官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| body.appId | 填入目标应用 ID | 官方说明推荐在请求体传入，用于确定应用身份 |
| chatId | 使用样本订单对应的会话 ID | 官方说明长度小于 250，需自行确保唯一 |
| responseChatItemId | 按样本对话设定唯一值 | 官方说明在当前 chatId 下需唯一 |
| detail | 设为 true | 需要运行详情时按官方契约设置 |
| stream | 设为 false | 与 detail=true 配合，结果保存在 responseData |
| loadCustomFeedbacks | 设为 true | 读取对话列表时按官方可选参数核对反馈 |

## 容易做错的三处

1. 把复核通过当作打包出库完成。样本材料只载明复核通过，未载明打包与交付。检查时输入两份材料原文与拟稿句，比较拟稿句所述状态是否出现在材料中，材料未载明即为未获支持。
2. 把不同来源的会话合并统计。样本若同时存在 API 来源与页面来源会话，检查时输入各自 chatId 与 source 取值，比较是否被归入同一会话集合，来源不同则不可混算。
3. 把检索相似度当作权限过滤。检查时输入一条无关订单查询，比较返回内容是否被相似度设置排除，相似度不承担实体或权限隔离，该预期不成立。

## 怎么确认配好了

1. 身份核对。输入样本的 appId、chatId 与 responseChatItemId，比较请求体字段与目标应用、目标会话是否一致，三者对应同一目标时满足条件。未提供时记录为缺口。
2. 运行详情核对。输入 detail=true、stream=false 的请求，比较返回中 responseData 是否包含对应模块记录，包含时满足条件。具体字段以实际返回为准，未返回的字段记为未知。
3. 拟稿句核对。输入材料原文一、材料原文二与待判定拟稿句，比较拟稿句所述主体、阶段、日期范围是否均被材料覆盖，覆盖时满足条件；样本中打包出库与交付承运商未被覆盖，判定为未获支持，保持待核实。

以上均为纸面核对设计，未实际执行测试，未发生部署、审批、退款或同步动作。
