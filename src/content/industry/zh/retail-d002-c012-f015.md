# 仓内拣货复核打包的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在仓内拣货复核打包的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。仓内售后检索需分开订单配置、样品拣货文字与当前包裹依据。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

仓内售后可拟订单“带盖杯”、样品拣货页“无盖样杯”和客服追问“请核本包裹版本”。客户问本单是否漏盖，当前资料既未给实际包裹内容，也没有样品与订单的关联。检索应分别找订单配置和本包裹记录，不能因无盖页相关就宣布漏装，也不能从带盖订单推现场一定装齐。按带盖杯、无盖样杯及完整漏盖问句比较实际候选，保留每段所指对象。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 订单配置 | 带盖杯原句 | 与实际包裹分证。 |
| 样品用途 | 无盖样杯 | 不当本单装箱。 |
| 改写对象 | 本单还是样杯 | 比前后完整问题。 |
| 引用承接 | 配置已在候选 | 查是否送给回答。 |
| 缺失依据 | 本包裹实际内容 | 未给继续待核。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是无盖样品页抢占订单依据，应核候选的文书用途和本包裹关联，不凭杯字命中采用。第二处是问题优化把本单漏盖改成样杯是否带盖，应保存前后问题，核交易对象有无变更。第三处是订单配置已召回却没交给回答，应对候选、实际引用及输出，区分未找到配置与找到后遗漏。三项分别查来源、改写主体和承接，不用提高相关度门槛裁掉另一方后称问题解决。

## 怎么确认配好了

验收分别问订单含什么、样品说明什么、包裹实际材料还缺什么，逐项读返回原句。语义、全文和混合检索可按同组问题比较，模式不替代包裹身份核验；引用按token受限时检查配置和对象限定是否完整保留。补入本包裹检查后只更新支持的内容，不由另一包裹照片补齐。本练习不确认漏装或责任、不执行补寄，未返回现场资料时应明确待核而不强行给出实物结论。
