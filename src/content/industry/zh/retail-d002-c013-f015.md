# 便利店加盟门店督导的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在便利店加盟门店督导的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。门店售后追问中的左右位置、整改范围和反馈阶段需要共同召回。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

加盟门店售后可拟通知“左侧货架标识待补”，反馈“右侧展示已补齐”，客服问“左侧现在怎样”。两段可能同时成立，右侧完成不反驳左侧缺项。检索需保留位置及来源身份，用左侧标识和完整追问检查候选；只搜补齐容易回到右侧结果。当前未给左侧后续记录，不能由同店或同一陈列任务推全店已完成，也不把左右差异直接判成资料冲突。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 通知位置 | 左侧货架 | 全文保留位置。 |
| 反馈范围 | 右侧完成 | 不扩全店。 |
| 提问优化 | 左侧限定 | 核前后是否仍在。 |
| 引用裁剪 | 已补齐前的右侧 | 查实际保留文本。 |
| 新增来源 | 本店左侧项目 | 核身份后更新。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是右侧反馈被当左侧结果，应对候选位置、通知对象和原句，不只看同门店命中。第二处是问题优化删去左侧限定，应保留前后问句并核实际检索对象。第三处是引用只保留已补齐而截去右侧，应核token限制下的实际文字，不能靠命中文档名判断条件完整。三项分别查对象、提问限定和引用裁剪，不由调阈值或切模式补左侧的实际处理结果。

## 怎么确认配好了

验收分别问通知指哪里、反馈完成哪里、左侧仍需什么依据，保存候选与回答实际采用的引用。对语义、全文和混合结果比较时，也保留未相关的右侧段作为辨别样本，不预设高分即本题。左侧新反馈取得后核同店与项目再复问，更新仅限其覆盖位置。本练习不执行巡店或验收，不声称实际整改通过；找不到后续来源时留待补，不能自动写成拒绝整改或已经完成。
