# 便利店鲜食订货的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在便利店鲜食订货的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。鲜食标签售后要检索商品标签与展示标识各自的处理对象。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

鲜食售后可拟顾客留言“这份三明治标签模糊”，门店记录“展示价签已重打”，值班备注“商品标签待核”。当前问商品标签是否已处理。检索要同时保留标签与价签、商品与展示两个对象，重打动作不能移用到随货标签。以三明治标签、展示价签和整题比较候选，可以检查相近用语是否混淆；现有文字未描述商品状态或标签实际改正，不据此推食品适售。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 诉求对象 | 随货商品标签 | 不扩商品质量。 |
| 重打对象 | 展示价签 | 不移用标签。 |
| 优化强度 | 仅问模糊标签 | 核前后问题。 |
| 待核采用 | 商品标签待核句 | 查引用与输出。 |
| 新处理来源 | 本份标签记录 | 核身份及阶段。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是展示重打页替代商品标签依据，应核候选类型和处理对象。第二处是问题优化将模糊标签扩成商品有问题，应对前后问句及原诉求，保留仅问标签的范围。第三处是待核备注在候选中却未被回答采用，应逐层对实际引用与输出，不以检索有结果就称已处理。三项分别查文书对象、问题强度和引用采用，不能由模式切换或更高相关度产生当前处理记录。

## 怎么确认配好了

验收分别问顾客描述什么、门店重打了什么、仍待核什么，展开返回原句。语义、全文与混合检索用同组问题核差异，相关价签段不能充当完成依据；引用上限按token时注意商品标签待核整句。补入本份标签记录后再问当前问题，只更新其真实支持的阶段。本练习不判商品质量、不建议处置，也不执行打印；未返回结果记录不说明没有处理，仍需追查范围和来源。
