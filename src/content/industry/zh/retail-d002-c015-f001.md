# 信用证审单交单的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

信用证审单交单服务于银行付款条件，审核重点落在单证一致。数据来源包括开证行通知、UCP600 条款、货代提单和银行交单记录，日常文档为信用证、商业发票、提单、保险单和汇票，更新频率为每单。这些材料决定 HTTP 模块在订单履约与售后答疑中的输入内容：请求体中的字段来自单据，返回值用于承接交单状态或答疑结果。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径参数，Body 用于请求体，Headers 用于请求头，三者均可通过 {{}} 引用全局变量、系统变量和前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime 和 histories；chatId 与 responseChatItemId 在测试模式下不存在。返回值按 JSON path 提取，输出类型选字符串时转为 json 字符串。对话接口以 APIKey 鉴权，appId 优先级为 body.appId、apiKey-appId、apikey 关联的 appId；model、temperature 等参数不生效，token 消耗需设 detail=true 后自行计算。

假设演练样本：某信用证项下，开证行通知列明最迟装运期为 2025 年 6 月 30 日，货代提单载明装船日期为 2025 年 6 月 28 日，商业发票金额与信用证一致。拟稿句为“本单已构成相符交单，银行付款条件已满足”。该句涉及主体、对象和状态，但材料未载明银行审单结论，属于待核实事项，不能作为已完成的付款条件确认。

## 配置怎么定

| 配置项 | 本页取值或核对项 | 说明 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选择，地址可引用变量 | 不预设具体地址 |
| Params 与 Headers | 分别核对请求参数与请求头 | 鉴权凭证经安全配置注入 |
| Body | 仅在相应请求类型下使用 | 核对 JSON 结构与外部接口契约 |
| 变量引用 | 逐项核对实际传入值 | 来源为全局变量、系统变量、前方节点输出 |
| 返回值提取 | 按 JSON path 配置 key 与输出类型 | 字符串类型转为 json 字符串 |
| 调试身份字段 | chatId、responseChatItemId 在测试模式下不存在 | 不把调试空值当成业务故障 |

## 容易做错的三处

1. 把拟稿句中的“已构成相符交单”当作银行审单结论。输入为样本拟稿句，比较对象为开证行通知与提单日期，观察结果是材料未载明银行结论，该句属待核实。
2. 在测试模式下把 chatId 缺失当成接口故障。输入为测试模式请求，比较对象为文档说明的“测试模式下不存在”，观察结果是该字段本就不存在，应改用非测试环境核对。
3. 把 HTTP 返回值直接当成授权或付款执行。输入为返回值中的状态字段，比较对象为交单记录与银行通知，观察结果是返回值仅反映接口响应，业务动作需下游实现。

## 怎么确认配好了

1. 输入样本拟稿句与材料原文，比较“已构成相符交单”与银行审单结论，观察是否出现材料未载明的结论；若未载明，记录为待核实。
2. 输入测试模式请求，比较 chatId 是否存在与文档说明，观察是否把调试空值当成业务故障；若存在空值，改用非测试环境核对。
3. 输入返回值提取配置，比较 key 与 JSON path 语法，观察输出类型为字符串时是否转为 json 字符串；若提取失败，记录实际响应并保留缺口。
