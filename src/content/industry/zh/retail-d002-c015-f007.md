# 信用证审单交单的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

信用证审单交单围绕开证行通知、UCP600条款、货代提单与银行交单记录展开，核心目标是单证一致，服务银行付款条件。与出口退税申报相比，本品类重点在单证匹配，不在税务匹配。日常文档包括信用证、商业发票、提单、保险单、汇票，数据按每单更新。对话日志与审计要回答的问题是：某笔审单交单的售后答疑发生在哪个会话，当时依据了哪些材料，系统实际留存了哪些字段。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份依靠 chatId 区分。chatId 为不传入时，FastGPT 不使用数据库上下文，完全由 messages 构建；chatId 为非空字符串时，系统从数据库取会话，并以 messages 数组最后一个内容作为用户问题，其余 message 被忽略。chatId 需唯一且长度小于 250。审计核对必须先确认目标对话的 chatId 与业务记录一致，不同入口的会话不能合并计算。

需要运行详情时，按官方契约设置 detail=true。非流式结果保存在 responseData 中，流式模式通过 event 区分。responseData 中不同模块的值可能有版本差异，需先记录并查看最新值。未在接口返回中出现的业务数据，不能推定已完整留存。

假设演练样本：材料原文为“开证行于2025年3月10日通知信用证L/C-2025-0310，要求提单收货人栏填写开证行名称，交单期为装运日后21天。”拟稿句为“该信用证允许提单收货人填写买方名称，交单期按装运日后30天掌握。”待判定该拟稿句是否与材料原文一致。

## 配置怎么定

| 配置项 | 本页相关设置或核对项 | 与本样本的关联 |
| --- | --- | --- |
| chatId | 非空字符串，长度小于250，需唯一 | 核对答疑会话身份 |
| detail | 需要运行详情时设为true | 检查responseData留存内容 |
| responseChatItemId | 传入后作为响应消息ID存入数据库，当前chatId下需唯一 | 定位具体对话记录 |
| source | 获取会话列表时source=api只取API创建会话 | 区分入口来源 |
| body.appId | 调用chat/completions时推荐传入 | 确认目标应用 |
| loadCustomFeedbacks | 获取对话列表时可选读取自定义反馈 | 核对反馈字段是否留存 |

表中数值为本次假设试验起点：chatId长度上限250来自官方文档说明，选择该值用于与拟用chatId比较长度；detail选择true用于与false比较返回内容差异。

## 容易做错的三处

1. 把不同 chatId 的会话合并计算。错误表现：将两个入口的对话记录当作同一笔审单交单的答疑。检查方法：输入两个不同 chatId 的会话列表，比较返回的 chatId 字段，观察是否被分别列出。

2. 把 detail=false 的返回当作完整运行详情。错误表现：依据 choices 中的回答文本推断模块运行状态。检查方法：分别以 detail=false 和 detail=true 调用，比较返回中是否出现 responseData，观察缺失的字段。

3. 把日志存在当作合规审计已完成。错误表现：认为接口返回了对话记录即满足对账、留存与合规要求。检查方法：核对业务方案中另行落实的对账与合规文件，比较日志字段与业务要求字段，观察缺口。

## 怎么确认配好了

1. 针对假设样本的拟稿句，输入材料原文与拟稿句，比较“提单收货人”字段：原文为开证行名称，拟稿句为买方名称，两者在同一字段上取值互斥，判定拟稿句与原文不一致。

2. 针对假设样本的交单期，输入材料原文与拟稿句，比较“交单期”字段：原文为装运日后21天，拟稿句为30天，同一字段取值不同，判定拟稿句未获原文支持。

3. 针对 chatId 唯一性，输入拟用的 chatId 与已有会话列表，比较长度是否小于250、是否已存在，观察是否满足唯一且长度合规；若无法取得完整会话列表，记录为未获支持，待核实。
