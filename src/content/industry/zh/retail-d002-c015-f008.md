# 信用证审单交单的订单履约与售后答疑：工作流编排

## 这个品类的数据长什么样

在信用证审单交单的订单履约与售后答疑中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

信用证相关履约咨询中，“资料已经交出”与“银行如何处理”需要各自的来源。可编写自拟输入：“已提供本次交单说明，尚未取得对应处理回复”，让表单收集原句、材料身份和当前问题。核对后续输入是否仍保留这个状态，不能将交出材料直接改写为已获接受或已完成付款；合同中的约定，也不能代替本次处理结果。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 提交与处理 | 交单说明已给，处理回复尚缺 | 下游没有把提交写成接受或付款 |
| 资料身份 | 本次交易及当前咨询原句 | 解释未混入其他交易文件 |
| 办理分支 | 补签收、查回复或交经办人 | 逐项验证接收步骤与原文 |
| 新增证据 | 运输记录或实际处理回复 | 同题复测后引用到对应来源 |
| 外部查询 | 接口范围、授权及真实业务返回 | 流程执行与实际办理分别确认 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

当咨询同时问到货物交付和单据办理，应分别设计补运输签收材料、回查银行回复或交接给实际经办人的选择。逐项测试接收步骤，并检查不同交易的文件有没有混入同一次解释。人员选择交给经办人，只安排下一步沟通；若尚无实际接收确认或业务记录，不能声称对方已办理，更不能用分支标签判定责任或售后方案。 若银行回复属于此前交易，却与本次交单说明一起进入回答，应先排查回复对象和本次材料身份。取出旧回复后复测缺回复情形，观察流程是否要求补充对应依据。只有本次对象能够核对时，才解释回复记载的处理状态，不把其他交易的结果沿用过来。

## 怎么确认配好了

补齐资料后重复原咨询，逐段比较提交文本、后续接收值和最后引用，确认新取得的是运输依据、处理回复还是其他材料。成本或结算问题若无相应明细，应继续登记缺口，不从单证齐全推出经营结论。需要发起交单查询或其他外部操作时，另外验证接口范围、授权与真实返回；流程走通不能作为银行或物流已经处理完成的证明。
