# 信用证审单交单的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在信用证审单交单的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。单据答疑中的收货人、通知方和修改说明需要按角色召回。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

审单答疑可拟问询“收货人别名待核”，回复“通知方名称已更正”，清单只列“相关页另附”。当前问收货人是否改妥。检索要保留字段角色与待核状态，不能因都是名称更正就以通知方回复作收货人结果。附件清单也没有实际修改正文。用收货人别名、通知方与完整改妥问句核候选，可检查角色相近时是否漏召原问询；本页不提供实际单证规则或银行认可判断。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 字段角色 | 收货人与通知方 | 候选带标题。 |
| 问询状态 | 别名待核 | 不优化成确定错误。 |
| 附件可见性 | 清单无正文 | 核实际引用。 |
| 模式比较 | 同题三类检索 | 分别对原文字段。 |
| 新增修改 | 本问询及版本 | 不接他笔来源。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是通知方结果被检索用于收货人，应核候选字段标题与原句。第二处是问题优化把别名待核改成名称错误，应对优化前后语气，资料待核不意味着已证错误。第三处是相关页标题被当作修改内容已经返回，应查看候选与实际引用覆盖，保留附件未读状态。三项分别查角色、问题性质和可见内容，不以文件数量、相关度或回答通顺代真实修改依据。

## 怎么确认配好了

验收分别问哪个角色已改、哪项仍待核、实际附件提供了什么，逐句读返回原文。语义、全文和混合检索以同题比较时保留字段标题，引用token限制也要让角色与状态一起进入。补入收货人页后核本次问询及版本再复测，不从另一交易同名页移用。本练习不执行单证修改或交单，不决定是否符合要求；没有返回附件应继续查范围与传递，不能直接判已拒或已获接受。
