# 加盟商培训与开业辅导的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

在加盟商培训与开业辅导的订单履约与售后答疑中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。参加培训、考核表现和现场检查需要不同依据，接口读取不能将阶段合并。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

加盟培训和开业咨询可先明确所问是参加、考核还是现场准备。自拟材料只有签到、手册说明和开业待查清单，没有实际考核或复核；HTTP拟读外部培训记录时，先核真实契约支持的门店、人员与版本，不能从文件标题推定全部资料已可查询。手册说明可以支持阅读，不等于人员已通过培训或本店已经获准开业。

## 配置怎么定

| 售后读取核对 | 本题自拟资料 | 所需证据 |
| --- | --- | --- |
| 门店身份 | 本店培训与开业问题 | 未读其他店结果 |
| 参加能力 | 签到有，实际考核缺 | 未直接判通过 |
| 清单性质 | 待查项目没有复核记录 | 未写成现场已完成 |
| 请求范围 | 人员版本与所问阶段 | 实际条件和返回对应 |
| 正式决定 | 认定开业或回写另验 | 读取未替代总部批准 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

门店返回错配：若返回属于其他门店，应核请求主体和资料来源；签到冒能力合格：若签到被报告为能力合格，应另取本学员考核内容；待查事项冒现场完成：若待查清单被写成检查完成，应核本店实际复核记录。三项分别核对象、人员表现和现场执行，接口成功不补出任何一项业务结果，也不能把资料更新时间当成正式批准时间。

## 怎么确认配好了

验收保留门店、问题阶段、适用SOP、实际发送条件和返回范围，补对应考核或现场来源后复问，看新资料是否进入解释。Params与Headers分别核，Body在契约适用时组织，不公开凭证。培训认定、开业批准及档案回写需另验业务权限和真实回执；本次读取不证明总部已作决定，也不由缺资料判定人员未参加。
