# 加盟商培训与开业辅导的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

本页处理加盟商培训与开业辅导场景下，订单履约与售后答疑环节的对话日志与审计。该品类与特许备案管理的区别在于，开业辅导是经营能力移交，材料围绕培训签到表、开业检查表、SOP手册、考核成绩展开。这些材料产生于培训系统、督导APP、门店照片与总部SOP库，出错会导致开业失败、顾客体验不一致与加盟投诉。

培训签到表与考核成绩属于逐店、逐月的记录，开业检查表与SOP手册在辅导期内反复引用。对话日志需要把一次问答与具体门店、具体辅导阶段对应起来，才能支撑履约与售后核对。

## 这些特征在「对话日志与审计」这一环带来什么约束

会话身份由 chatId 界定，dataId 指向会话下某一条对话。核对某门店的开业辅导问答时，先确认 chatId 对应的是该门店该阶段的会话，避免把不同入口的会话混算。需要运行详情时按官方契约设置 detail，并检查 responseData 中的模块响应，未返回的业务字段不能推定已完整留存。

日志存在不等于完成合规审计。对账、留存与合规要求由完整业务方案另行落实。检索库的相似度与相关度不承担权限或实体隔离功能，检索结果不构成授权。

假设演练样本：供核对的材料原文为三句。其一，签到表载明“2025年3月5日，A店加盟店主完成收银模块培训，签到有效”。其二，开业检查表载明“2025年3月20日，A店开业物料检查，状态为待复核”。其三，SOP手册载明“收银异常处理动作以总部现行版本为准”。一条待判定的拟稿句为：“A店收银培训与开业物料均已确认通过，可进入正式营业。”该句把签到有效与待复核混为已通过，且未给出SOP版本对应关系。

## 配置怎么定

下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。表中数值为本次假设试验起点，仅用于说明比较方法，不代表官方默认值。

| 配置项 | 本次假设试验起点 | 核对方式与理由 |
| --- | --- | --- |
| appId | 样本应用的 appId | 与 chatId 一并核对，确认会话归属该应用 |
| chatId | A店辅导会话标识 | 长度小于250且唯一，用于取该会话上下文 |
| detail | 设为 true | 需要运行详情时启用，检查 responseData |
| stream | 设为 false | 便于直接读取 choices 与 responseData |
| messages | 含一条 user 提问 | 与 chatId 配合，取最后一条为用户问题 |
| loadCustomFeedbacks | 设为 true | 读取对话列表时一并取自定义反馈 |

## 容易做错的三处

1. 把“待复核”当作“已通过”。样本中开业检查表状态为待复核，拟稿句写成已确认通过。检查时输入该检查表原文与拟稿句，比较状态字段取值，只有状态明确为通过才满足条件，待复核属于未获支持。

2. 把不同会话的问答合并计算。不同 chatId 属于不同会话，混算会使门店与阶段错位。检查时输入两个 chatId 及其各自对话，比较 dataId 归属，只有同一 chatId 下的记录才可归入同一辅导阶段。

3. 用相似度结果推断权限或实体归属。相关度不是权限或实体过滤。检查时输入检索返回的 score 与目标门店标识，比较返回记录的业务标识，score 高低不改变该记录是否属于目标门店，归属需另行核对。

## 怎么确认配好了

- 验证一：针对样本拟稿句，输入签到表原文、开业检查表原文与该拟稿句，比较拟稿句是否与两份原文的状态一致。开业检查表为待复核，拟稿句称已确认通过，该句不满足条件，应记录为未获支持。

- 验证二：针对样本会话，输入 chatId 与 detail=true 的请求，比较 responseData 中模块响应是否包含所需字段。若某业务字段未在返回中出现，记录为未知，不推定已留存。

- 验证三：针对空结果承接，输入纸面检索结果 []，比较下游设计在无引用时的输出行为。该输入仅用于核对承接逻辑，不表示虚构规则检索一定返回空。

以上验证为纸面核对，未实际执行，不构成测试、部署或批准结论。
