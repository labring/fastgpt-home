# 加盟商培训与开业辅导的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在加盟商培训与开业辅导的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。开业辅导售后的目录发送、链接访问与课程完成是不同检索目标。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

开业辅导售后可拟学员留言“课程链接打不开”，客服记录“资料目录已发送”，讲师便签“实操课程另排”。当前问链接问题是否已解决。目录发送是交付一种文字，另排课程是时间安排，均没有链接访问结果。检索可用打不开原话、目录发送和完整追问核候选，不能因都谈课程就将目录或实操安排作访问恢复，也不从曾经签到推当前已学完。所有文字均为自拟，不涉及真实学员账户。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 技术诉求 | 链接打不开 | 不改成学习完成。 |
| 目录动作 | 文字已发 | 不作访问修复。 |
| 班次来源 | 成功打开属何班 | 核链接身份。 |
| 引用条件 | 打不开与另排 | 保留主体。 |
| 后续证据 | 当前访问反馈 | 不扩大实操结果。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是目录发送代替访问结果，应核候选动作和链接对象，不以有相关文件就答已恢复。第二处是优化问题把链接访问改成课程是否完成，应比前后问句，保留技术诉求与学习阶段的区别。第三处是另一个班次的成功打开记录被采用，应核班次、链接及来源身份。三项分别查行为、提问对象和材料适用，不靠提高相关度裁掉原投诉后认定问题不再存在。

## 怎么确认配好了

验收分别问发了什么、原诉求是什么、访问结果还缺什么，展开实际引用而不只读文件名。用语义、全文、混合比较同组问题，引用token预算需保留打不开和另排的主体。新访问反馈取得后核当前链接与班次，只更新其支持的状态；不把访问成功扩成实操完成。本练习不修改链接权限或发送资料，也不评估学员能力，未返回结果时继续列待补而不自动写成已解决。
