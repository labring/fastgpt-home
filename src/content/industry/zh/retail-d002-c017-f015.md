# 加盟费与保证金结算的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在加盟费与保证金结算的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。加盟结算售后先检索款项类别与当前办理动作，避免把资料收悉写成资金退回。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

加盟结算售后可拟门店询问“保证金退回进度”、经办回复“附件已收悉”和另一页“服务费说明已发送”。当前未给保证金审核或支付记录。检索要保留保证金与服务费、附件与资金两个区别，已收悉只说明收到资料，不说明已受理、已批准或已支付。用保证金退回原话和整题比较候选，不能让重复出现的已发送说明替代本次进度，也不由缺结果推定退款一定被拒。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 款项类别 | 保证金与服务费 | 候选分别对应。 |
| 收件对象 | 附件资料 | 不当资金退回。 |
| 阶段增写 | 收悉不证受理 | 核优化前后。 |
| 引用裁剪 | 保留附件受词 | 不单取已收。 |
| 后续记录 | 门店及款项一致 | 仅改有证状态。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是服务费说明被采用为保证金处理，应核候选款项类别与本次问询。第二处是问题优化把附件收悉改成退款受理，应比前后问题，查是否增加办理阶段。第三处是引用截去附件只保留已收，应核实际交给回答的对象，资料收件不能作为资金收回。三项分别查类别、改写阶段和引用受词，不靠相关度分数决定退款状态；当前事实缺项仍需相应原文。

## 怎么确认配好了

验收分别问询问哪类款、经办收到了什么、服务费页支持什么，逐句检查实际引用。语义、全文和混合检索使用相同问题，保留同主体但不同类别作为区分样本。引用token限制下尤其核附件和保证金字样是否都在。后续付款记录加入后核本门店与款项，只更新证据支持的状态。本练习不决定退回条件或执行财务操作，不用一份收到附件的回复补审核、到账或真实结清结论。
