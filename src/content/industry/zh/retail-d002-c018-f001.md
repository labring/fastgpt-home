# 区域经销商库存补货的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

在区域经销商库存补货的订单履约与售后答疑中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。经销商主体、回款状态和订单出库粒度需要对应，汇总不直接说明本单执行。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

经销补货服务咨询可先问申请、库存、出库与回款各支持哪一步。自拟材料只有需求与计划，没有本次出库或银行依据，不能从申请存在推定已经履约。HTTP读取需先有真实契约说明经销商、商品及期间怎样查询，不预设品牌平台和ERP已经打通，也不从同商品名称合并不同主体记录；所取得的资料应按实际范围解释。

## 配置怎么定

| 售后读取核对 | 本题自拟资料 | 所需证据 |
| --- | --- | --- |
| 计划执行 | 回款安排与实际凭据分开 | 未由计划判到账 |
| 主体范围 | 经销商及发送对象 | 未借其他主体结果 |
| 记录粒度 | 商品汇总与订单出库 | 补本单关联及执行来源 |
| 真实读取 | 契约条件与实际请求 | 返回覆盖当前问题 |
| 后续办理 | 补货调整与确认另验 | 读取未代替履约或对账 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

回款计划冒到账：若回款计划被写成到账，应核原句性质与收款凭据；经销商响应错配：若其他经销商返回本问题，应核主体关系和发送值；商品汇总冒本单出库：若商品汇总库存被当成本单出库，应另查订单对应与实际出库记录。三项分别核执行、对象和粒度，接口正常返回不证明本次供货完成，也不自动补齐缺少的业务关系。

## 怎么确认配好了

验收保留经销商、订单需求、资料时间、实际请求和返回，补对应执行记录后复问，看结论是否仍限于本对象。Params、Headers及适用Body按外部契约核，不公开凭证。补货提交、库存调整或财务确认需另验权限与真实回执；读取结束不证明已下单、已扣库存或完成对账，也不能由缺返回断言供应商未办理。
