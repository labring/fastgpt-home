# 区域经销商库存补货的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样
区域经销商库存补货属于批发与经销商渠道下的日常滚动订单，与季节性集中订货存在节奏差异。补货申请、库存周转表、出库单、回款计划构成主要文档集合，数据来源涉及经销商ERP、品牌订货系统、仓库库存与销售回款。更新频率以周和月为主，这一节奏意味着对话日志与审计需要按同一业务期间归集材料。订单履约与售后答疑的对话记录，只有与补货申请、出库单、回款计划等材料在同一主体、同一期间下核对，才能形成可用的审计线索。对话日志本身不承载授权，检索命中记录不代表补货申请已获批准、出库单已执行或回款计划已落实。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话接口以 chatId 标识一个应用下的会话，dataId 标识会话下的对话。审计核对时须先确认 chatId 对应的业务入口，不把不同入口的会话混算。需要运行详情时按官方契约设置 detail，非 stream 模式结果保存在 responseData，stream 模式通过 event 区分。接口实际返回哪些字段决定日志留存范围，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，需分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。

假设演练样本：某区域经销商在补货申请中写明“申请补货A型号120件，申请日期为2025年3月10日，当前库存周转表显示该型号可售库存40件”。一条待判定拟稿句为“该补货申请已审批通过，出库单已生成”。核对材料原文后可知，申请与库存数据已载明，审批状态与出库单生成情况未在材料中出现，该拟稿句属于未获支持。

## 配置怎么定
| 配置项 | 官方已说明内容 | 与本页样本的核对方式 |
| --- | --- | --- |
| appId | 应用 ID，可在应用详情路径获取 | 核对样本对话归属的应用 |
| chatId | 会话 ID，非空字符串时从数据库取会话 | 核对补货答疑对话的会话标识 |
| dataId | 会话下某一对话的 ID | 定位待判定的拟稿句所在对话 |
| detail | 是否返回中间值，非 stream 存于 responseData | 需要运行详情时设置并检查返回 |
| source | source=api 获取通过 API 创建的会话 | 核对日志来源范围 |
| loadCustomFeedbacks | 是否读取自定义反馈（可选） | 核对对话反馈记录是否存在 |

以上均为官方已说明字段。本页不指定任何默认数值，样本中的数量与日期仅用于本次纸面核对。

## 容易做错的三处
1. 把检索命中当作授权执行。样本中补货申请已提交，检索到该申请记录，不能据此判定审批通过或出库单已生成。检查方式：输入样本申请原文，比较申请状态字段与审批、出库字段，观察是否存在审批通过或出库单生成的明确记录。
2. 把不同 chatId 的会话合并计算。补货答疑与售后答疑可能分属不同 chatId。检查方式：输入两个 chatId 及其对话列表，比较各自 dataId 与业务记录，观察是否出现跨会话混算。
3. 把未返回字段推定已留存。接口未返回的审批状态或出库信息，不能推定日志已完整保存。检查方式：输入 detail=true 的返回结果，比较 responseData 中实际字段与预期业务字段，观察缺失字段是否被误认为已留存。

## 怎么确认配好了
1. 输入样本补货申请原文与拟稿句，比较申请状态与审批、出库字段，若材料中无审批通过或出库单生成记录，则拟稿句判定为未获支持。
2. 输入样本 chatId 与另一会话 chatId，比较各自 dataId 及对应业务记录，若两者归属不同补货申请，则不合并计算。
3. 输入 detail=true 的返回结果，比较 responseData 实际字段与业务所需字段，若审批状态字段未出现，则记录为证据缺口，不推定已留存。

以上为纸面核对预期，未实际执行测试。检索与相似度不承担权限或实体隔离，未载明字段保持未知。
