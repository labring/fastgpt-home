# 区域经销商库存补货的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在区域经销商库存补货的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。经销售后中的外箱观察、换箱申请和实际补货要分别召回。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

经销售后可拟顾客留言“外箱受潮”、仓库记录“新外箱已申请”和物流摘要“早批货已发”。当前问替换箱是否已经寄到。观察描述外箱，申请说明拟采购或领取，早批发货又不是本次补件。检索需保留外箱及批次，不把受潮扩成内物损伤，也不从申请和历史发货拼成当前已到。用新外箱、替换箱寄到整题与历史批次文字检查候选，现有资料没有本次接收。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 观察对象 | 外箱 | 不扩内物损伤。 |
| 当前动作 | 已申请新箱 | 不改成发出。 |
| 物流批次 | 早批货 | 排除补件混用。 |
| 输出范围 | 箱与内物分开 | 核引用及新增句。 |
| 后续结果 | 本次发运或接收 | 分阶段更新。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是旧批物流记录承担当前替换箱进度，应核批次与物流对象。第二处是优化把新外箱已申请改成已发出，应对原问句与优化文本，保留申请阶段。第三处是当前申请已召回却答内物损坏，应核引用原句与输出新增对象，外箱观察不能证明里面情况。三项分别查来源批次、提问阶段和结论范围，不通过排除低分来源来补真正缺少的本次交接记录。

## 怎么确认配好了

验收分别问观察到什么、申请了什么、历史物流对应什么，再查实际引用。对语义、全文与混合结果用同题比较，保留早批物流作干扰样本；引用token预算应让批次及申请动作一起保留。补入本次箱件发运或签收材料后，只更新其覆盖阶段，不因已发推已到。本练习不认定内物质量、不下换箱单或执行赔付，没有接收材料时应列待核，保留本次接收缺项，不判断已拒发。
