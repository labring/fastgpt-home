# 即时零售门店履约的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

在即时零售门店履约的订单履约与售后答疑中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。资料时点、查询空值和待核状态分别查，保留本单还未取得的配送依据。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

即时零售咨询可先明确所问是拣货、骑手接收、配送还是实际处理结果。自拟输入只有门店缺货和骑手过程说明，没有最终送达凭据。HTTP拟读外部资料时，应核真实契约支持的订单、门店和时间，不预设一次读取能取全平台状态。客户陈述与实际业务记录保留各自性质，不从缺货上报直接判责任，也不由订单更新频繁推定返回已是当前状态。

## 配置怎么定

| 售后读取核对 | 本题自拟资料 | 所需证据 |
| --- | --- | --- |
| 时间范围 | 旧库存与本单时点 | 未直接倒推下单状态 |
| 空返回 | 骑手资料未返回 | 核定义权限和实际覆盖 |
| 待核状态 | 响应原句含资格说明 | 答复没有省成定论 |
| 同单补证 | 接收或处理新增原文 | 复问实际采用新依据 |
| 正式处置 | 换品退款或关闭另验 | 查询未代替平台决定 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

库存时间错用：若旧时点库存被当成本单下单状态，应核来源时间与请求条件；空骑手查询冒无配送：若空骑手返回被解释成没有配送，应核服务定义、权限和本次覆盖；响应待核性质丢失：若响应的“待核”被答复省掉，应对照完整原句恢复性质。三项分别核时间、查询含义和状态传承，不能把未取得资料改写成事件没有发生。

## 怎么确认配好了

验收保留订单、门店、资料阶段、真实请求和返回，补本单接收或处理依据后复问，核结论是否采用新来源。Headers、Params与适用Body按外部契约查，鉴权不公开。换品、退款或异常关闭需另验权限及真实业务回执；本次读取不证明处置已执行，也不能从过程文字推出买家已收到或平台已作裁定。
