# 即时零售门店履约的订单履约与售后答疑：分享与嵌入

## 这个品类的数据长什么样

在即时零售门店履约的订单履约与售后答疑中，本页说明FastGPT的分享与嵌入如何衔接资料。分享即时订单进度时保留本单身份，区分拣货、骑手承接和顾客接收。所用场景为自拟文字测试。

## 这些特征在「分享与嵌入」这一环带来什么约束

自拟协作入口可提供本单拣货说明与待确认承接，不放他店库存、无关订单或骑手个人资料。用完整链接查接收环境原句，保留门店、订单和资料时点，再请求限制来源测试范围。进入口令不证明真实顾客或配送身份，必要验证按商业版实际能力另核。资料说到哪个阶段就解释哪个阶段，链接有效和会话结束都不能补出骑手已接或顾客已收的真实记录。

## 配置怎么定

| 即时订单进度分享 | 本单可见范围 | 取证动作 |
| --- | --- | --- |
| 公开摘要 | 拣货及待确认承接 | 门店订单时点 |
| 受限来源 | 他店无关单及个人资料 | 完整回答和拒绝 |
| 跨设备 | 送达问题对应哪单 | 实际历史及补问 |
| 阶段区别 | 拣货承接接收分别核 | 本次各阶段依据 |
| 业务执行 | 分享不派单关单或改库存 | 记录权限及回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `免登录窗口` | 复制生成的完整分享链接。 |
| `过期时间与QPM` | QPM指每用户每分钟访问上限。 |
| `积分上限` | 按入口及版本核用量与费用条件。 |
| `身份验证` | 第三方认证受商业版范围限制。 |
| `对话记录边界` | 匿名标识依赖同设备、同浏览器。 |

## 容易做错的三处

- 本单进度返回他店库存或无关骑手信息：保存来源与完整回答查授权，同渠道或同商品不提供跨单共享依据，转述也检查。

- 电脑问订单、手机追问“送到了吗”缺本单身份：核实际历史补原问题，匿名标识不自动跨设备，不拿最近订单状态回答。

- 拣货完成被写成骑手已接或顾客已收到：分别取本次承接及接收依据，流程前后阶段不互为完成证明。

## 怎么确认配好了

验收测试本单摘要、他店来源和无关订单，记录实际原句、限制及拒绝。骑手记录已取得未入输入与本单尚无接收依据分别定位，不以分享续期或多轮追问生成事件。换设备复测缺对象问题，核是否索取门店订单及时间。分享不派单、改库存或关单；真实配送与顾客接收另据业务权限、实际记录和回执，未核阶段保留待确认，不把答复已给当问题已解决。
