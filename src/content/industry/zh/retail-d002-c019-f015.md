# 即时零售门店履约的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在即时零售门店履约的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。即时配送答疑需区分骑手到店、预计时点与顾客收到。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

即时零售售后可拟状态“骑手已到店”，客服话术“预计稍后送达”和顾客追问“我还没有收到”。当前问订单是否已送达。检索应找各段具体地点与说话方，已到店不等于到顾客处，预计也不记录实际发生。顾客主张还需对应订单核验，不能单凭该句反推其他记录造假。用已到店、未收到及完整送达问句比较候选，避免送达一词让预估话术覆盖现场事件。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 事件地点 | 到店 | 引用保留位置。 |
| 预估性质 | 预计稍后 | 不作实际发生。 |
| 任务保持 | 是否不变多久 | 核优化前后。 |
| 签收归属 | 本单及接收对象 | 排除他单。 |
| 结论范围 | 接收仍待核 | 不从分数判断。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是到店位置在引用中丢失，应核候选原句与实际交给回答的地点。第二处是优化把是否送达变为多久送达，应保留原题核实际状态，不能用预计答复回避。第三处是他单签收页被本次订单采用，应对订单、接收对象及版本。三项分别查引用地点、任务变化和来源身份，不以高相关度或签收标题决定本单状态，真实接收仍需对应材料。

## 怎么确认配好了

验收分别问骑手在哪、预计说明什么、当前顾客问什么，逐条展开引用。用语义、全文和混合检索比较同题，保留预估与实际消息作不同类型样本；token引用上限要留住到店这个位置。新增本单接收记录后再问，明确它能支持的事件，不由其他订单补齐。本练习不更改配送状态或联系骑手，不判责任或赔偿；材料仍缺时列待核，不能从一次检索结果宣布真实送达。
