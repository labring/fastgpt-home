# 原产地证书申办的订单履约与售后答疑：多轮对话与提示词

## 这个品类的数据长什么样

在原产地证书申办的订单履约与售后答疑中，本页说明FastGPT的多轮对话与提示词如何衔接资料。对证书更正请求逐轮保留客户所需内容、申请状态和生产依据，不把寄送或受理等同于结果。所用场景为自拟文字测试。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

自拟售后材料可先给一封客户来信，要求补正证书中的收货人名称，另有寄送记录显示原件已经发出。追问“是否已处理”时，回答需区分客户要求、寄件事件与证书更正结果。只有寄送信息不能证明内容已修改。若答案把已发出写成已更正，应逐句对照实际历史；缺少更正结果时，需要明确无法核实哪一项，不能靠提示词补成完成状态。

## 配置怎么定

| 售后对话核对项 | 证书更正材料 | 验收依据 |
| --- | --- | --- |
| 请求范围 | 来信要求改收货人名称 | 不扩成其他修改事项 |
| 事件区分 | 寄送、申请与签发分开 | 每轮实际采用的原句 |
| 指代承接 | 新的指哪份证书及版本 | 对照原问和优化问 |
| 结果缺项 | 未取得与未传入分别查 | 补来源或核输入 |
| 完成边界 | 更正结果与客户清关要求另核 | 不由对话生成确认资质 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `提示词与任务` | 说明资料、任务和缺证据处理。 |
| `历史记录` | 核实际提交的历史输入。 |
| `问题优化` | 指代消除与问题扩展需复核。 |
| `模型与长度` | 上下文与回复长度分别核对。 |
| `回复格式` | json_schema需给格式并验解析。 |

## 容易做错的三处

- 原件寄送被写成收货人名称已更正：并列来信、寄送记录与返回，核更正结果，寄件不证明证书内容改变。

- “新的一份”被优化到旧证书或另一客户：保留原问、优化问及证书标识，查实际历史和申请版本，不能靠增加历史代替对应关系。

- 更正申请已提交被写成已签发或可清关：查实际结果与客户要求；已得结果未传入与尚未取得分开定位，不能把申请升级为正式结论。

## 怎么确认配好了

验收可用原来信、寄送记录、申请材料逐步追加，检查回答是否始终区分各自支持的阶段，再在补入结果后复核同题。生产资料或原产规则没有提供时，客服整理可以列待核事项，不能宣称已确认原产资格。应记录每个结论采用的原句和仍缺的责任人确认，最终以实际签发及客户要求材料另核，不把对话结束当作更正业务完成。
