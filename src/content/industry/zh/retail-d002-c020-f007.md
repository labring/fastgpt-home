# 原产地证书申办的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样
原产地证书申办围绕原产地证申请、商业发票、装箱单、生产成本资料展开，服务进口国关税与清关，不必然受信用证约束。数据来自中国国际贸易单一窗口、贸促会系统、企业生产记录与客户清关要求，更新频率为每单。订单履约与售后答疑中，从业者需要判断原产规则、填报证书、寄送客户清关。对话日志与审计要处理的是：一次会话对应哪份证书申请、哪张发票、哪份装箱单，以及该会话在什么授权状态下产生。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话身份以 chatId 区分，同一应用下不同入口的会话不混算。需要运行详情时按官方契约设置 detail，并检查 responseData 中的模块响应。日志与接口实际返回哪些字段，只能按实际返回核对，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，输入、历史与返回内容分别核对。日志存在本身不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本。供核对的材料原文：商业发票载明发票号 INV-2024-0318，买方为境外进口商 A，货物为阀门配件，发票日期 2024 年 3 月 18 日。装箱单载明同一发票号，件数 40 箱，毛重 820 千克。原产地证申请草稿载明申请日期 2024 年 3 月 19 日，原产规则栏空白。待判定拟稿句：本会话对应的证书申请已完成原产规则判定并提交贸促会。判定所需证据为原产规则栏的填写结果与提交回执，材料中均未出现，该拟稿句属于未获支持。

## 配置怎么定
下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，并说明选取理由与比较对象。

| 配置项 | 本次假设起点 | 核对方式与比较对象 |
| --- | --- | --- |
| appId | 样本应用的应用 ID | 与请求体 body.appId 及会话列表返回的 appId 比较 |
| chatId | 样本会话的会话 ID | 与获取对话列表、获取运行详情请求中的 chatId 比较 |
| dataId | 样本对话的对话 ID | 与获取运行详情、更新反馈请求中的 dataId 比较 |
| detail | 设为 true | 与响应中是否出现 responseData 比较 |
| stream | 设为 false | 与响应是否为整体 JSON 比较 |
| loadCustomFeedbacks | 设为 true | 与对话列表返回的 customFeedbacks 字段比较 |

detail 设为 true 的理由是需要中间值与完整结果，比较对象为响应中 responseData 是否出现。stream 设为 false 的理由是便于逐字段核对，比较对象为响应形态。这些是本次假设试验起点，不代表官方默认值。

## 容易做错的三处
1. 把不同入口的会话混算。输入为页面会话与 API 会话各一条，比较对象为各自 chatId 与 source 取值，若把两者合并统计对话数，则与获取会话列表按 source 过滤的返回不一致。
2. 把日志存在当作合规审计完成。输入为样本对话列表与运行详情，比较对象为对账、留存要求所需字段是否在返回中出现，若直接判定审计完成，则缺少材料支撑。
3. 把检索或表单当作授权执行。输入为样本中的表单输入请求，比较对象为是否存在签署、提交回执等状态证据，若把表单填写视为已提交贸促会，则与材料中缺失回执的事实不符。

## 怎么确认配好了
1. 输入样本的 appId 与 chatId，调用获取对话列表，比较返回 list 中的 chatId 与 updateTime，返回中出现该 chatId 且时间可读，满足条件；返回为空则记录缺口。
2. 输入样本的 appId、chatId、dataId，调用获取运行详情，比较返回 data 数组中的 moduleType 与 runningTime，出现对应节点记录，满足条件；未出现则记录缺口。
3. 输入样本拟稿句与材料原文，比较原产规则栏与提交回执是否存在，两者均未出现时判定未获支持，满足条件；若出现填写结果或回执，则另行核对主体、期间与字段。以上均为纸面核对，不声称已实测。
