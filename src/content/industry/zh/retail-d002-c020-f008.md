# 原产地证书申办的订单履约与售后答疑：工作流编排

## 这个品类的数据长什么样

在原产地证书申办的订单履约与售后答疑中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

单证售后咨询可以先区分申请提交、签发结果和寄送接收分别有哪些资料。自拟文字写“申请材料已提交，目前没有签发回复和寄送凭证”，用于测试流程如何接收这类情况。表单传值后，比较下游实际收到的说明，确认“提交”没有被改成“已经签发”。商业发票和装箱单即使已齐，也只能提供相应交易信息，不能代替签发机构或寄送环节的记录。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 状态分段 | 已提交申请，签发与寄送依据尚缺 | 接收值没有将提交改为签发 |
| 资料对应 | 本次申请与已提供交易单据 | 没有混用旧证书或其他批次 |
| 服务分支 | 补签发回复、查寄送或交经办人 | 逐项核连接和实际收到的内容 |
| 补齐复问 | 新签发或寄送记录及原咨询 | 答案采用对应依据并列出未知 |
| 实际办理 | 修改、查询或重寄的业务返回 | 分别验授权、受理与操作结果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

客户询问未收到证书时，应先核对实际取得的材料，再选择补签发回复、查寄送记录或交经办人确认。每个选项都需检查连接与接收内容，不能因为选择查询寄送就默认原件已经发出。若材料出现不同版本，也应先确定本次咨询对应哪份申请，防止把旧证书或其他批次信息混入答复；流程选择不负责判定证书效力。 还应设置申请版本不一致的情形：经办说明讨论当前申请，附带证书却指向先前记录。并列查看两份材料所指对象，确认缺的是本次签发回复还是寄送凭证，再让人员选补对应资料；不能以已有一张证书为由跳过申请身份的核对。

## 怎么确认配好了

补齐后复问同一问题，检查新增依据是否真正进入回答，并列清尚未确定的环节。需要修改申请、重寄或向外部系统发起查询，应另核操作范围、授权和实际返回，不能由表单结束推定已经受理。面向客户的答复应区分“现有材料记载的状态”和“仍待经办方确认的事项”，不从一段普通工作记录推定签发、送达或清关已经完成。
