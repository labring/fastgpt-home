# 原产地证书申办的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在原产地证书申办的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。证书售后检索需保留草稿、客户收件和真实签发记录的区别。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

原产地资料售后可拟经办留言“草稿已下载”、客户回复“草稿收到了”和寄送申请“待附正式件”。当前问证书是否已经签发。下载与收件均针对草稿，申请也没有实际正式件。检索应保留每处草稿身份，不把收到两个字当发证结果。以正式件、草稿下载及完整签发问题比较候选，可检查旧证书页是否干扰；本题不判断原产资格或真实办理要求。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 文件阶段 | 草稿 | 引用不省略。 |
| 问题目标 | 签发与收件分开 | 对优化任务。 |
| 寄送缺项 | 待正式件 | 不当已寄。 |
| 证书归属 | 商品与批次 | 核实际来源。 |
| 新正式记录 | 当前版本 | 只更新有证事实。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是引用裁去草稿后写成证书收到，应核原句与实际引用，保留文件阶段。第二处是优化把已经签发改成客户是否收到，应比前后问题，收件任务不能替发证状态。第三处是另一批商品证书被当前问题采用，应对商品、批次和来源身份。三项分别查文件状态、问题目标和适用对象，不由多个收件片段或高分证书页推本次已有正式结果。

## 怎么确认配好了

验收分别问下载了什么、客户收了什么、寄送申请缺什么，查看回答真实引用。语义、全文与混合检索用同题核是否保留草稿和待附限定，token预算不应只剩已下载或已收。正式记录补入后核本次商品与版本再复问，不能沿用旧证书填缺。当前未返回正式件不证明被拒，也不执行签发或寄送。本练习只比较自拟文字，不声明现实证书已取得或任何资格已获核准。
