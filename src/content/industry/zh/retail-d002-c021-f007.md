# 品牌会员私域运营的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

会员私域运营围绕顾客数据与复购触达展开，不处理门店排班。主要数据来自 CRM 系统、企微、POS 消费记录与小程序行为数据，日常文档包括会员标签表、触达计划、优惠券规则与隐私授权记录。订单履约与售后答疑场景下，一次对话可能牵涉订单状态、退款进度、优惠券核销结果与授权范围。

对话日志与审计要处理的对象是：某次会话中用户提出的履约或售后问题、系统返回的回答、以及运行详情中的字段。行业事实中，触达骚扰投诉、券成本失控、会员流失是出错后果，这要求日志核对必须区分会话身份，不把不同入口的会话混算。资料更新频率为日、周，本页功能不依赖批量同步或实时触发，故不展开。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份需结合 chatId 核对目标对话与业务记录。运行详情需要时按官方契约设置 detail 并检查 responseData。字段含义须核对日志与接口实际返回字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能不同，分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。

假设演练样本（纸面材料，非真实记录）：

材料原文一：会员标签表载明「会员编号 M-2041，标签：待退款订单跟进，更新日期 2025-03-10」。
材料原文二：触达计划载明「计划编号 T-77，对象：M-2041，事项：订单履约答疑，状态：待审核」。
拟稿句：「M-2041 的退款已处理完成，触达计划 T-77 已执行。」

判定要点：材料仅显示标签与待审核状态，未载明退款处理结果，也未载明 T-77 已执行。拟稿句把待审核当成已执行、把标签当成退款完成，属于未获支持。另需核对 chatId 是否对应 M-2041 的会话；若 chatId 缺失，会话身份无法确认，记录缺口。

## 配置怎么定

| 配置项 | 官方已说明设置或实施核对项 | 与样本的关系 |
| --- | --- | --- |
| chatId | 非空字符串时按 chatId 取会话，长度小于 250，须自行确保唯一 | 核对 M-2041 会话身份，缺失即记录缺口 |
| detail | 需要中间值或完整结果时设置 detail=true | 检查 responseData 是否含履约答疑节点 |
| responseChatItemId | 传入则作为本次响应消息 ID，当前 chatId 下须唯一 | 用于关联拟稿句对应的响应项 |
| source | 获取会话列表时 source=api 表示仅取 API 创建的会话 | 区分入口，避免混算页面会话 |
| loadCustomFeedbacks | 读取对话列表时可选 | 核对反馈字段是否存在，不推定业务结论 |
| 假设试验起点 | 本次纸面核对取 pageSize=10 为起点，理由是样本仅两条记录，与 total 值比较 | 仅为本次假设，非官方默认 |

## 容易做错的三处

1. 把待审核当成已执行。材料二状态为待审核，拟稿句写「已执行」。检查：输入材料二原文，比较状态字段与拟稿句动词，状态为待审核时拟稿句不成立。
2. 把标签当成业务完成。材料一标签为「待退款订单跟进」，拟稿句写「退款已处理完成」。检查：输入材料一原文，比较标签文字与拟稿句结论，标签未载明处理结果时结论未获支持。
3. 用相似度代替身份核对。检索返回 score 字段，但 score 不承担会话身份或权限过滤。检查：输入 chatId 与目标会话，比较 chatId 是否一致，score 高低不改变身份判定。

## 怎么确认配好了

1. 输入材料一、材料二原文与拟稿句，比较拟稿句是否只陈述原文载明的主体、对象、状态；拟稿句出现「已处理完成」「已执行」而原文为待审核时，判定为未获支持。
2. 输入 chatId 与 M-2041 会话，比较会话身份是否对应；chatId 缺失或指向其他会话时，记录身份缺口，不推定日志完整。
3. 输入 detail=true 的纸面请求与返回的 responseData，比较是否含履约答疑节点字段；若返回中无对应节点，记录字段缺口，不推定业务数据已留存。空结果承接可用纸面输入 [] 核对下游设计，不声称检索必返回空。
