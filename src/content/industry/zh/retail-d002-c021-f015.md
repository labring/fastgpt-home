# 品牌会员私域运营的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在品牌会员私域运营的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。会员售后答疑应分开报名、资料发送与门店体验确认。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

会员售后可拟线上记录“报名已提交”、客服回复“活动资料已发”和门店便签“体验名额另核”。当前问是否已约好门店体验。三个动作的对象不同，提交不证明报名通过，发资料也不说明门店安排，名额仍待核。检索需找具体体验确认，核它覆盖本活动及门店，用门店体验原词和完整预约问题比候选。现有文字没有成员真实权限或安排结果，不因同一活动名就把线上与门店状态合并。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 线上动作 | 报名提交 | 不当通过。 |
| 资料动作 | 活动文字已发 | 不作门店安排。 |
| 优化目标 | 预约状态 | 不改成资料查询。 |
| 旧活动来源 | 活动门店成员范围 | 核实际对应。 |
| 新增确认 | 只覆盖对应对象 | 不扩全部会员。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是资料已发被采用为门店已约，应核候选动作与对象。第二处是优化把预约状态改成活动有什么资料，应保存完整前后题，检查信息目标是否偏离。第三处是旧活动的门店确认进入当前，应对活动、门店和成员范围，不由相似标题沿用。三项分别查来源动作、问题任务和记录身份，不以检索条数或相关度推实际名额和权益，当前缺确认仍需补来源。

## 怎么确认配好了

验收分别问提交了什么、发送了什么、门店还待核什么，展开实际引用。用语义、全文和混合检索核同组问题，token引用预算需保留线上与门店及另核条件。补入体验确认后核本活动和对应对象，再复问只改有证状态，不把某人的确认扩全部会员。本练习不预约、发通知或确认真实权益，也不作授权效力判断；无结果时保留待核，不能自动判已经拒约或已安排完成。
