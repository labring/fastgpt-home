# 品牌全渠道库存调拨的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

在品牌全渠道库存调拨的订单履约与售后答疑中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。地点角色、库存数量性质与物流接收分别核，不以正常响应推出调拨完成。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

调拨服务咨询可先问需求、申请、库存和运输资料各支持哪一阶段。自拟输入只有申请和快照，没有本次接收凭据，不能从申请存在推定已到店。HTTP读取要先核实际外部契约怎样对应商品与调出调入地点，再检查方法和条件；不预设ERP、WMS和渠道订单已经同步，也不由同名商品推定各处库存口径可以直接合并。

## 配置怎么定

| 售后读取核对 | 本题自拟资料 | 所需证据 |
| --- | --- | --- |
| 角色传递 | 调出调入原句及发送值 | 请求未颠倒地点 |
| 数量口径 | 快照余额与移动记录分开 | 未由余额推本次发生 |
| 接收阶段 | 运输资料有，门店接收缺 | 未改写为已到店 |
| 来源补齐 | 本次对应原文 | 复问引用实际新依据 |
| 业务结果 | 创建回写或对账另验 | 查询未代替渠道同步 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

调出调入发送颠倒：若请求把调出地点传成调入地点，应核角色原句与实际发送值；快照余额冒移动：若快照余额被当本次发生量，应查时点与对应移动记录；物流记录冒到店接收：若物流资料有记录就被回答为门店已收到，应补本次实际接收依据。三项分别核地点、数量性质和执行阶段，接口有响应不补出缺的业务关系。

## 怎么确认配好了

验收保留商品、地点角色、资料时间、真实请求和返回，补相应来源后复问，看解释实际采用哪份依据。Params、Headers与适用Body按真实契约查，不公开鉴权。调拨创建、库存回写、采购调整或对账另验权限与业务回执；本次读取不证明货物移动、渠道同步或账实已平，也不能从空返回推定没有库存。
