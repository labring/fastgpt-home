# 品牌全渠道库存调拨的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在品牌全渠道库存调拨的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。调拨售后中的仓库接收、门店自提和当前货品需要分别定位。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

全渠道售后可拟顾客问“这件可以到店取了吗”，调拨摘录“已到区域仓”，门店便签“仍等本批接收”。另存一份上轮门店自提通知。当前货品到仓不等于到店，旧通知也没有覆盖本批。检索要保留地点、批次和顾客所问阶段，不能只搜已到或自提就宣布可取。用到店取完整问句与区域仓原词比较候选，现有资料尚无本批门店接收或备妥证明。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 接收地点 | 区域仓与门店 | 候选分开。 |
| 服务阶段 | 顾客到店取 | 不改仓库查询。 |
| 通知轮次 | 旧自提页 | 核本批身份。 |
| 引用完整 | 地点和批次 | 检查保留。 |
| 后续结果 | 接收与可取及已领 | 各取对应依据。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是区域仓记录被当门店可取，应核候选地点及事件对象。第二处是问题优化将顾客到店取改成仓库有无库存，应比前后问题，不能换掉服务阶段。第三处是旧自提通知被当前批次采用，应对通知所指门店、货品与轮次。三项分别查位置、问题目标和来源适用，不以相关度高或标题写可取就决定现实取货安排，也不从资料不足推货物丢失。

## 怎么确认配好了

验收分别问到哪里、门店等待什么、旧通知属于何次，逐句看真实引用。语义、全文与混合结果按同题比较，保留仓到与店到作为不同事件；token引用预算需让地点和批次同在。新增本店接收材料后再核可取依据，接收也不自动说明顾客已经取走。本练习不通知顾客、不调拨或改库存，实际安排需对应业务记录；未返回当前通知时留待核，不能直接说已经拒绝自提。
