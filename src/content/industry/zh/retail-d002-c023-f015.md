# 品牌售后维修服务的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在品牌售后维修服务的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。维修答疑需召回检查项目和待测范围，不能把局部完成扩成恢复使用。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

品牌维修售后可拟工单“指示灯检查完毕”、检测稿“开机问题待测”和顾客追问“现在所有功能都恢复了吗”。当前资料明确局部检查与待测并存，没有全机恢复结果。检索应保留指示灯与开机两个项目，用完整追问和项目原词核候选。只回检查完毕不能覆盖所有功能，也不由开机待测反推商品一定故障；这个问题仍需要对应检查记录，不是更换措辞就能回答。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 检查范围 | 指示灯项目 | 不扩全功能。 |
| 待测项目 | 开机 | 引用保留。 |
| 优化范围 | 仍问所有功能 | 不缩小任务。 |
| 肯定词裁剪 | 完毕须带项目 | 核真实文本。 |
| 新增结果 | 本机项目与版本 | 只改相应范围。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是局部完毕被用作全功能恢复，应核候选检查项目和所述结论。第二处是优化把全部功能改成指示灯是否检查，应保存问句范围，不能缩小任务后答完成。第三处是待测条件在引用裁剪中消失，应对原稿和实际传入文本，保留未核项目。三项分别查证据范围、任务范围和引用完整性，不靠相关度、条数或更长答复补全机状态。

## 怎么确认配好了

验收分别问检查完哪项、哪项仍待测、全部恢复需要什么，展开真实引用。语义、全文和混合检索按相同问题比较，项目限定应与完毕或待测一起保留，token预算不能只留肯定词。新检测补入后核本机、项目和版本，更新只到它实际支持范围。本练习不诊断或指导维修，不决定保修责任，也不保证真实功能恢复；未给结果时保留待核，而不凭检索命中宣称可以使用。
