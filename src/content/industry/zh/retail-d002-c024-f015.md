# 品牌商场专柜运营的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在品牌商场专柜运营的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。专柜售后的柜台预留、提取方式和运输说明需要按本件召回。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

专柜售后可拟顾客留言“自取袋缺提绳”、门店回复“替换袋已留柜台”和商场通告“统一配送安排另见说明”。当前问替换袋是否寄出。柜台预留只说明留置，通告没有指本件，缺提绳也不证明整袋无法使用。检索需保留自取、柜台与寄出三个动作差异，用替换袋寄出整题和已留柜台原词比较候选，不将相关配送通告直接作为本件发运结果。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 门店动作 | 留柜台 | 不写寄出。 |
| 服务方式 | 原自取 | 优化不得变配送。 |
| 通告范围 | 统一说明未指本件 | 核实际适用。 |
| 旧袋记录 | 供应方发货 | 不代替换袋。 |
| 后续交接 | 本件与提取方式 | 分开发与收。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是预留被引用成寄出，应核门店动作原句与本件对象。第二处是优化把自取售后改成配送售后，应比前后任务及提取方式，避免自行补运输安排。第三处是旧供应商袋件发货记录被当前替换袋采用，应对收货对象、事件及版本。三项分别查行动、服务方式和来源身份，不由同商场或同袋名认定同一物流，也不把通告存在当后台已执行。

## 怎么确认配好了

验收分别问门店留了什么、顾客原来如何提取、通告实际覆盖谁，展开真实引用。语义、全文、混合检索用同组问题比对象，引用token预算要保留柜台与另见说明的限定。新交接记录取得后核本件及实际提取方式，不因一条发运文字推顾客已收到。本练习不安排寄送、不改提取方式或判售后责任；未返回本件记录时留待核，不自动说拒绝发出或已经送达。
