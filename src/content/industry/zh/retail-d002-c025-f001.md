# 品牌奥莱折扣运营的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

奥莱折扣运营以清理过季库存为目标，主要数据来自 ERP 库龄、POS 销售、奥莱商场活动与历史折扣，更新频率为周或月。订单履约与售后答疑要处理的文档是折扣审批、滞销清单、价签与毛利测算表。这些材料决定一次交接请求能否被外部系统受理：折扣审批体现授权状态，滞销清单体现对象范围，价签与毛利测算表体现字段取值。HTTP 接口只负责按外部契约发送请求并解析返回值，它不核验审批是否批准、不校验价签是否已打印、不写入业务数据库。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 为路径请求参数，Body 为请求体，Headers 为请求头，三者均可用 {{}} 引用变量，变量来自全局变量、系统变量与前方节点输出。URL 也可引用变量。返回值是解析规则，通过 JSON path 提取接口响应中的值，输出类型选字符串时会把对应 key 的值转成 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试时出现的空值属于环境差异。对话接口调用时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>；传入的 model、temperature 等字段无效，由编排决定。detail=true 时非流式结果保存在 responseData 中，流式通过 event 区分；交互节点返回的 interactive 只含 type 与 params。表单收集值，业务验证、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：材料原文为「折扣审批单：SKU A-1042，门店 M-07，申请折扣 4 折，审批状态：待审核，申请日期 2024-06-03」；「滞销清单：A-1042 库龄 210 天，建议清货」。待判定拟稿句为「A-1042 折扣已批准，请接口推送价签变更」。判定要点：审批状态为待审核，属于未获授权，拟稿句把待审核写成已批准，接口推送请求缺少授权依据。

## 配置怎么定

下表围绕上述样本，列出本功能相关的官方已说明设置或实施核对项。数值为本次假设试验起点，用于与样本材料比较，不作为官方默认值。

| 配置项 | 本次假设起点 | 核对依据 |
| --- | --- | --- |
| 请求地址与方法 | POST 至外部价签服务地址 | 按外部接口文档选择，地址可引用变量 |
| Headers 鉴权 | Authorization 引用已配置凭证变量 | 凭证通过安全配置注入，不写入公开样例 |
| Body 结构 | 含 SKU、门店、折扣与审批状态字段 | 仅在相应请求类型下使用，核对 JSON 契约 |
| 变量引用 | 引用前方节点输出的审批状态 | 逐项核对实际传入值 |
| 返回值解析 | key 取 data.status，输出类型字符串 | 通过 JSON path 提取，遵守 JS 对象取值规则 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 不把调试空值当成业务故障 |

## 容易做错的三处

1. 把待审核当成已批准。输入是样本审批单的「审批状态：待审核」，比较拟稿句「折扣已批准」，观察结果是二者状态取值不一致，拟稿句未获支持。
2. 把检索或表单当成授权执行。输入是滞销清单与表单收集的折扣值，比较是否具备审批通过记录，观察结果是仅有建议清货，接口推送缺少授权依据。
3. 把相似度或检索结果当成权限或实体过滤。输入是返回值中的 score 字段，比较其与授权状态字段，观察结果是 score 属于相关性度量，不能替代审批状态判断。

## 怎么确认配好了

1. 输入样本审批单原文与拟稿句，比较「待审核」与「已批准」，预期现象为识别出状态不一致，拟稿句判定为未获支持。
2. 输入样本滞销清单与接口推送请求，比较请求是否附带审批通过记录，预期现象为确认推送缺少授权依据，保持待核实。
3. 输入一条返回值样例，比较 data.status 的解析结果与原始响应，预期现象为提取值与响应一致；若响应中无该字段，记录缺口，不推断业务结果。
