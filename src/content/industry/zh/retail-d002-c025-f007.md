# 品牌奥莱折扣运营的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样
奥莱折扣运营以清理过季库存为目标，价格体系与毛利空间都较紧。订单履约与售后答疑环节的对话日志，往往同时牵涉折扣审批、滞销清单、价签与毛利测算表四类材料。从业主体包含品牌奥莱店、渠道清货组与财务BP，出错会带来价格体系受损、库存继续积压或毛利亏损。数据来源为ERP库龄、POS销售、奥莱商场活动与历史折扣，更新频率为周或月。

对话日志与审计在本环节的作用，是把一次履约或售后沟通中出现的材料、操作与请求状态固定下来，供交接核对。日志存在只说明发生过一次会话，不说明折扣已批准、价签已更换或毛利已复核。

## 这些特征在「对话日志与审计」这一环带来什么约束
结合chatId核对目标对话与业务记录，不把不同入口的会话混算。需要对话接口运行详情时，按官方契约设置detail并检查responseData。核对日志与接口实际返回字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。

假设演练样本：某品牌奥莱店渠道清货组在2025年3月10日提交一份折扣审批材料，原文为“SKU A-1042，库龄210天，现价签299元，申请折扣至199元，审批状态：待审核；审批人：未签署”。同日售后对话中，拟稿句为“该SKU折扣已批准，可按199元履约”。判定所需的主体、对象、状态与有效范围都在这两处原文内，待审核与未签署都不构成批准。

## 配置怎么定
下表围绕该样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，需与对照值比较后才能判断。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| appId | 样本应用ID | 用于定位该应用下会话，比较请求体与密钥关联值是否一致 |
| chatId | 样本会话ID | 长度小于250且唯一，比较目标对话与业务记录是否同一会话 |
| detail | true | 需查看responseData中间值，比较返回是否含节点响应 |
| responseChatItemId | 样本响应ID | 在同一chatId下唯一，比较是否与拟稿句对应 |
| source | api | 获取API创建的会话，比较列表是否遗漏页面会话 |
| loadCustomFeedbacks | true | 读取自定义反馈，比较反馈是否随对话记录返回 |

## 容易做错的三处
1. 把待审核当成已批准。样本原文写明“审批状态：待审核；审批人：未签署”，拟稿句却称已批准。检查方式：输入拟稿句与审批材料原文，比较状态字段取值，只有状态为已批准且审批人已签署才满足履约条件。
2. 把日志存在当成审计完成。官方文档说明detail=true时返回responseData，但未返回的业务数据不能推定已完整留存。检查方式：输入一次带detail=true的请求，比较responseData字段与业务所需字段清单，缺失字段记为证据缺口。
3. 把检索或表单当成授权执行。交互节点返回的userSelect与inputForm只是展示配置，表单收集值不等于业务验证或审批。检查方式：输入交互节点返回的params，比较其中是否含审批结论字段，未含则记录为待核实。

## 怎么确认配好了
1. 对拟稿句“该SKU折扣已批准，可按199元履约”，输入审批材料原文，比较审批状态与审批人字段，只有状态为已批准且审批人已签署才满足条件；样本中两者均为待审核与未签署，判定为未获支持。
2. 对同一chatId发起带detail=true的请求，比较responseData中是否含对应节点响应与quoteList，观察返回字段与业务所需字段的差异，缺失部分保持未知。
3. 对交互节点返回的userSelect选项，输入选项value与key，比较其是否包含授权结论，未包含则记录为表单收集值，业务验证与审批需另行落实。
