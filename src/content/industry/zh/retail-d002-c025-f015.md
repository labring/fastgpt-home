# 品牌奥莱折扣运营的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在品牌奥莱折扣运营的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。奥莱售后检索需区分故障主张、咨询指引和可见视频内容。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

奥莱售后可拟顾客留言“拉链卡住”，帮助页“可联系门店咨询”和客服记录“已收视频名称，内容待看”。当前问原因是否已确认。客户描述是主张，咨询指引只给联系动作，文件名也没有实际视频观察。检索应保留来源类型，用拉链卡住原话和完整确认问句比候选，不能从常见帮助页补维修诊断，也不因往季标签推定磨损或质量问题。当前未给本件实际检查。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 证据类型 | 一般咨询页 | 不作本件诊断。 |
| 问题强度 | 卡住主张 | 不改已证不合格。 |
| 可见内容 | 视频名称与内容分开 | 保留待看。 |
| 款式适用 | 另一款部件记录 | 核身份再用。 |
| 新检查 | 本件及项目范围 | 不扩全部结论。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是咨询页被用作原因结论，应核候选是否含本件观察，区分一般指引和具体检查。第二处是优化把卡住描述改成质量不合格，应比前后问题强度，不能增加已证事实。第三处是另一款拉链记录被同名问题采用，应核款式、部件及来源身份，视频标题也不能补内容。三项分别查证据类型、提问推断和适用对象，不用相关度高或检索条数认定真实故障原因。

## 怎么确认配好了

验收分别问顾客说了什么、帮助页建议什么、客服实际看见什么，逐句读真实引用。语义、全文和混合比较同组问题，token预算保留内容待看，不能只留已收视频。检查资料后补入时核本件及范围，不从单项结论推所有功能或责任。当前只测试文字来源，不假定视频解析已完成，也不指导实物维修；未返回原因证据时应继续待核，不能称商品不存在问题或已经解决。
