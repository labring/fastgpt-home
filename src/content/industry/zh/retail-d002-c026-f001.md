# 品牌直营门店运营的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
直营门店由品牌直接雇佣和核算，不通过加盟合同管理，订单履约与售后答疑所需的日销售报表、排班表、陈列照片、库存调拨单都在品牌内部系统产生。POS、会员CRM、ERP库存与门店巡检构成主要数据来源，更新频率为日或周。HTTP 接口与外部系统这一环，实际是把上述单据中的字段传给外部订单、库存或售后系统，并取回处理状态。资料给出的日更或每单节奏只说明单据生成节拍，不能据此推出批量同步、全量同步或交易触发机制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块可重复添加、手动配置、触发执行，向对应地址发送请求。Params 为路径请求参数，GET 请求中用得居多；Body 为请求体，POST/PUT 请求中用得居多；Headers 为请求头，用于传递特殊信息。三类数据均可通过 `{{}}` 引用变量，URL 也可引用变量，变量来自全局变量、系统变量与前方节点输出。系统变量包括 appId、chatId、responseChatItemId、variables、cTime 与 histories。chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于运行态差异。返回值配置决定如何解析接口响应，通过 JSON path 提取，输出类型选择字符串时会把对应 key 的值转成 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId；传入的 model、temperature 等参数字段无效，由编排决定。detail=true 时可从 responseData 取得中间值，但不会返回实际消耗 Token 值。交互节点返回的 interactive 是展示配置，只含 type 与 params，entryNodeIds、memoryEdges、nodeOutputs、nodeResponseId 等内部运行态字段不会返回。表单输入需将对象序列化成字符串作为 messages 值，并确保 chatId 一致。检索或表单只收集值，业务核验、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：以下为纸面材料，非真实记录。材料一（库存调拨单摘录）：“调拨单号 DB-0001，调出门店 A，调入门店 B，商品 SKU-001，数量 2 件，制单日期 2025-03-10，状态：待审核。”材料二（售后工单摘录）：“工单号 AS-0007，关联订单号 SO-0009，客户申请退货，申请日期 2025-03-11，处理状态：待核实。”待判定拟稿句：“DB-0001 已完成调拨，AS-0007 退货已批准，可通知客户退款。”

## 配置怎么定
下表仅列官方已说明的设置或本次实施核对项，数值均为本次假设试验起点，非官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址可引用变量 | 与外部接口契约逐字比较，确认方法匹配 |
| Params 与 Headers | 鉴权凭证经安全配置注入，样例不写明文 | 与接口文档要求的请求头字段比较 |
| Body | 仅在相应请求类型下使用，核对 JSON 结构 | 与外部接口契约的字段名和类型比较 |
| 变量引用 | 逐项核对全局变量、系统变量、前方节点输出 | 与实际传入值比较，确认引用可解析 |
| 返回值解析 | 按 JSON path 配置 key，输出类型选字符串 | 与接口响应示例结构比较，确认路径命中 |
| 调试身份字段 | chatId、responseChatItemId 测试模式下不存在 | 与正式会话取值比较，区分调试空值 |

## 容易做错的三处
1. 把待审核状态写成已完成。材料一状态为“待审核”，拟稿句称“已完成调拨”，比较对象是同一单据的同一状态字段，两者互斥，属于矛盾。
2. 把待核实写成已批准。材料二处理状态为“待核实”，拟稿句称“退货已批准”，同一工单同一字段取值互斥，属于矛盾。
3. 把表单收集值当成授权执行。拟稿句由表单或检索结果直接推出“可通知客户退款”，缺少退款审批与外部同步的下游实现证据，属于未获支持。

## 怎么确认配好了
1. 输入材料一原文与拟稿句前半段，比较调拨单状态字段“待审核”与“已完成”，观察结果为两者互斥，拟稿句该部分不成立。
2. 输入材料二原文与拟稿句中间段，比较工单处理状态“待核实”与“已批准”，观察结果为两者互斥，拟稿句该部分不成立。
3. 输入拟稿句末段“可通知客户退款”，比较其是否具备退款审批与外部同步的书面证据，观察结果为证据缺失，该结论待核实。若以纸面输入 `[]` 核对下游设计，只能确认空结果承接逻辑，不能声称某规则检索必然返回空。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察，不据此推断漏召回或冗余。
