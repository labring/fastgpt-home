# 品牌直营门店运营的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在品牌直营门店运营的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。直营门店售后中的简称、取货通知和统一营业说明需要核地点身份。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

直营门店售后可拟订单“南街店取货”、通知“南店自提”和统一说明“两个门店周末均营业”。顾客问南店是否就是南街店。当前材料没有简称映射或地址对应，营业说明也不解释名称关系。检索应分别保留两个店名，用原词和完整身份问题核候选，不能因南字相同或同一品牌就认作同一地点。通知可说明某店自提文字，不自动说明本订单应该去哪里。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 订单地点 | 南街店 | 保留完整名称。 |
| 通知地点 | 南店 | 不自动扩写。 |
| 证据内容 | 营业不证明简称 | 核实际对应原句。 |
| 引用地点 | 自提须带店名 | 查裁剪内容。 |
| 新增映射 | 发布者及店别范围 | 不接异地同名。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是统一营业页被当店名对应依据，应核候选是否实际包含简称或地址关系。第二处是问题优化直接将南店扩成南街店，应比前后实体，不能在检索前假定待证关系。第三处是引用只留自提而丢店名，应核实际文字保留的地点，不靠订单关联猜通知身份。三项分别查证据内容、实体改写和引用受词，不以高分或同品牌资料数量补缺失的名称映射。

## 怎么确认配好了

验收分别问订单指哪店、通知写哪店、营业页能说明什么，展开真实引用。语义、全文与混合比较同题，也保留两个名称作为不同实体待核；token预算应让完整门店名留下。新增简称说明后核发布者及适用门店再复问，不从别城市同名店移用。本练习不指引真实顾客前往任何地址、不更改订单或发送通知；名称关系未证时留待补，不能自动判通知错误或两店必然相同。
