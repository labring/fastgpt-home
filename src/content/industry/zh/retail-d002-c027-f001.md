# 品牌经销商订货会的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

品牌经销商订货会围绕线下经销商预订展开，不直接管理平台店铺。主要数据来自订货会系统、历史销售、经销商库存与财务授信，更新频率为季或年。日常文档包括订货手册、订货合同、样品清单与授信审批。这些材料决定订单履约与售后答疑时能引用哪些事实：订货手册说明政策与货期口径，订货合同记录签署与生效状态，样品清单对应实物与编号，授信审批体现额度是否获批。HTTP 接口与外部系统环节只负责把请求发往外部服务并解析响应，不替代上述材料的业务核验。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 为路径请求参数，Body 为请求体，Headers 为请求头，三者均可通过 `{{}}` 引用变量；URL 也可引用变量。变量来自全局变量、系统变量与前方节点输出。系统变量含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 提取，输出类型选字符串时会把对应 key 的值转成 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>；appId 优先级为 body.appId、<apiKey>-<appId>、apikey 关联的 appId。传入的 model、temperature 等参数无效，由编排决定。detail=true 时返回中间值，stream 模式通过 event 区分。交互节点返回的 interactive 只含 type 与 params，内部运行态字段不返回。表单输入续跑需保持 chatId 一致，并把对象序列化成字符串作为 messages 内容。这些能力都不构成授权：检索与表单只收集或传递值，审批、数据库写入与外部同步需另行实现。

假设演练样本：材料原文为“华东区订货会 2026 春季场，经销商编号 HZ-041，订货合同状态为待审核，授信审批意见栏为空，样品清单编号 YP-2026-018，对应样品为净水器滤芯组件。”拟判定句为“HZ-041 的授信额度已批准，可执行本次订单发货。”该请求的授权边界为：仅核对材料中已载明的状态，不补造审批结论。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 比较方法 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址引用已提供变量 | 与接口文档的路径、方法逐字比对 |
| Headers 鉴权 | Authorization 引用安全配置注入的 token | 检查凭证未写入公开样例 |
| Body 结构 | 按接口契约填写 JSON，字符串加引号 | 与接口文档字段名、类型比对 |
| 变量引用 | 逐项核对全局变量、系统变量、前方节点输出 | 对照实际传入值 |
| 返回值提取 | 用 JSON path 提取所需 key | 与响应示例的层级比对 |
| 调试身份字段 | 测试模式下 chatId、responseChatItemId 不存在 | 区分调试空值与业务故障 |

## 容易做错的三处

1. 把待审核状态当作已批准。样本中订货合同状态为待审核，授信审批意见栏为空，拟判定句却写授信额度已批准。输入为材料原文与拟判定句，比较两者对授信状态的表述，可观察结果是拟判定句包含原文未载明的结论。
2. 把检索或表单当作授权执行。样本中材料只记录编号与状态，未载明任何审批动作。输入为交接请求，比较其是否要求执行发货，可观察结果是请求要求了材料未授权的业务动作。
3. 把调试模式下的空值当作业务故障。样本未涉及真实接口调用。输入为测试模式下 chatId 不存在的说明，比较其与业务故障的差异，可观察结果是该空值属于文档已说明的调试条件。

## 怎么确认配好了

1. 输入样本材料原文与拟判定句，比较拟判定句中的授信结论与原文载明的状态，若原文仅写待审核且审批意见为空，则拟判定句未获支持，需记录证据缺口。
2. 输入交接请求，比较请求要求的动作与材料载明的授权范围，若材料未载明审批或发货授权，则该请求处于待核实状态，不能视为可执行。
3. 输入测试模式说明，比较 chatId 与 responseChatItemId 的存在条件，若处于测试模式，则两者不存在属于文档已说明的情况，需与真实业务故障区分。
