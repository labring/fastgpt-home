# 品牌经销商订货会的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

品牌经销商订货会面向线下经销商预订，不直接管理平台店铺。主要数据来自订货会系统、历史销售、经销商库存与财务授信，日常材料包括订货手册、订货合同、样品清单与授信审批。这一品类按季或按年更新，订单履约与售后答疑围绕合同数量、交期、样品与授信状态展开，对话日志需要与这些材料逐项对应。

对话身份以 chatId 关联目标会话与业务记录，不同入口的会话分别核对，不合并计算。运行详情按官方契约设置 detail，检查 responseData 中的节点输出。日志与接口实际返回的字段是核对对象，未返回的业务数据不能推定已完整留存。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。测试模式与正式调用的身份字段可能不同，分别核对输入、历史与返回内容。

## 这些特征在「对话日志与审计」这一环带来什么约束

假设演练样本：材料原文为“华东区订货会 2025 春季场，经销商编号 HZ-017，订货合同编号 DH-2025-0312，合同数量 1200 件，签署状态为待审核；授信审批单编号 SX-2025-0088，状态为已提交，未标注批复额度。”拟判定句为“HZ-017 的 1200 件订单已获授信批复，可以安排发货。”

核对时以 chatId 锁定该会话，调用对话接口并设 detail=true，在 responseData 中查找 moduleType=chatNode 与 pluginOutput 的元素。检索返回的 quoteList 中 score 与 similarity 是相关度数值，不承担实体或权限过滤功能，检索结果不构成授权。合同签署状态为待审核，授信审批单为已提交，两项都不构成批复或发货许可。拟判定句把待审核与已提交写成已获批复，属于未获支持的结论。材料未载明批复额度与发货授权，这部分证据缺口保留。

## 配置怎么定

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| chatId | 与本次订货会话一一对应 | 官方说明用于标识某应用下的会话，核对同一 chatId 下的记录 |
| detail | true | 官方说明可返回模块状态与完整结果，用于取 responseData |
| stream | false | 便于在 choices 与 responseData 中直接检查返回结构 |
| responseChatItemId | 本次会话内唯一值 | 官方要求同一 chatId 下唯一，便于定位单条响应 |
| loadCustomFeedbacks | true | 官方说明可读取自定义反馈，用于核对反馈字段 |
| pageSize | 10 | 本次假设起点，与返回 list 长度比较，判断是否需继续取数 |

上述数值为本次假设试验起点，不属官方默认值。接口传入的 model、temperature 由编排决定，不随 API 参数改变。交互节点返回的 interactive 只含 type 与 params，内部运行态字段不返回。

## 容易做错的三处

1. 把待审核签署状态或已提交授信审批单当作批复。输入为材料原文与拟判定句，比较合同签署状态与授信审批单状态字段，观察是否出现批复或发货许可的表述。
2. 把检索相关度数值当作权限或实体过滤。输入为 quoteList 中的 score 与 similarity，比较返回记录与目标经销商编号，观察是否把不相关记录当作已授权记录。
3. 把日志存在当作合规审计完成。输入为会话记录与业务对账材料，比较日志字段与对账所需字段，观察缺失字段是否被当作已留存。

## 怎么确认配好了

1. 输入假设材料原文与拟判定句，比较合同签署状态“待审核”、授信审批单状态“已提交”与拟判定句的“已获授信批复”，出现状态不符即记为未获支持，保留批复额度缺口。
2. 输入同一 chatId 下的会话记录与 quoteList，比较 score 数值与经销商编号字段，观察相关度数值是否被用于排除或放行记录；相关度不承担该功能，记录实际观察结果。
3. 输入会话记录与对账所需字段清单，比较日志实际返回字段与清单，观察缺失字段是否被标记为待核实；日志存在不表示合规审计已完成，缺失部分保留为缺口。
