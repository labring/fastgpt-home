# 品牌经销商订货会的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在品牌经销商订货会的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。订货售后的展样尺码、正式订货行与到货观察必须按对象检索。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

经销订货售后可拟展样卡“样衣为中码”、订货行“正式尺码另确认”和顾客追问“收到的是否也为中码”。当前没有到货标签或检查记录，样衣尺码不自动覆盖正式商品。检索可用样衣中码、正式尺码和完整到货问题比候选，保留样品与订货身份。即使产品名相同，也不能由展样卡证明收到的衣服是什么码，或从正式尺码待确认反推已经错发。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 样衣身份 | 展样中码 | 不当到货观察。 |
| 正式行 | 尺码另确认 | 保留状态。 |
| 优化目标 | 收到的尺码 | 不改目录选项。 |
| 来源事件 | 本场订单行 | 排除别场。 |
| 新增观察 | 本笔及单件范围 | 不扩整批。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是展样尺码被当到货依据，应核候选对象和本次交付关联。第二处是问题优化把收到的尺码改成样衣有哪些码，应比前后题，避免缩成容易回答的目录查询。第三处是别场订货确认被本场采用，应核活动、商品与订单行，不以同款或同经销商套用。三项分别查证据对象、问题目标和来源事件，不由相关度或多份尺码资料拼成现场观察。

## 怎么确认配好了

验收分别问样衣标什么、正式行还缺什么、实际到货证据在哪，逐句查看引用。语义、全文、混合检索用同组问题比较，token预算需保留样衣和另确认限定。新增标签或检查记录后核本笔商品再问，只更新它观察到的范围，不把单件推广整批。本练习不决定退换条件或执行补货，不声称现实尺码一致；未返回到货记录时继续待核，不能自动写成顾客误解或商品已无问题。
