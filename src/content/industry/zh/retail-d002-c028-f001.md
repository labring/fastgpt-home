# 品牌自播直播间运营的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
品牌自播由品牌自身承担话术、库存与售后，履约与答疑的原始材料分散在直播脚本、商品讲解卡、排班表和直播复盘中。订单成交明细与直播间评论按场次、按小时更新，售后问题往往在评论或讲解卡里先出现，再进入订单处理。HTTP 接口在这一环的作用，是把外部订单或工单系统的记录取回，或把核对后的字段送出。接口地址可引用变量，请求参数、请求头与请求体分别核对，鉴权凭证通过安全配置注入，不写入公开样例。变量来自全局变量、系统变量和前方节点输出，逐项核对实际传入值。测试模式下 chatId 与 responseChatItemId 不存在，调试空值不当作业务故障。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
接口只负责按外部契约发送请求并解析响应，不承担授权判断、审批或数据库写入。检索或表单收集到值，不等于业务已核验或已执行。请求体只在相应请求类型下生效，JSON 结构与外部接口契约逐字段比对。返回值通过 JSON path 提取，输出类型选择字符串时会把对应值转成 json 字符串。detail=true 时中间值保存在 responseData，stream 模式下通过 event 区分。以上都是节点已有行为或可配置字段，业务侧的下单、退款、同步需要外部系统自身实现。

假设演练样本：材料原文为“商品讲解卡 A-07 标注：本场次 20:00 至 22:00 有效，主体为品牌自播账号；售后说明栏写明‘七天无理由，以订单签收日计算’。”待判定的拟稿句为“本商品支持七天无理由，自签收日起算，请按讲解卡提交售后。”另有一条交接请求：“把本场订单状态同步到外部工单系统。”该请求只表明有人提出交接意向，未附授权记录或接口契约，处于待核实状态。

## 配置怎么定
下表围绕该样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，非官方默认。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 外部接口文档给出的地址，可含 `{{}}` 变量 | 与外部契约地址逐字符比对 |
| 请求方法 | 按外部接口文档选择 | 与文档标注的方法比对 |
| Headers 鉴权 | 通过安全配置注入 Bearer 凭证 | 与凭证发放记录比对，不写入样例 |
| Body 结构 | 按外部契约的 JSON 字段与类型 | 与契约字段名、类型逐项比对 |
| 返回值提取 | 用 JSON path 取所需 key | 与接口响应示例字段比对 |
| 输出类型 | 需要拼接时选字符串 | 与下游文本加工输入要求比对 |

## 容易做错的三处
1. 把检索或表单收集到的值当作授权已通过。输入是表单字段值，比较对象是授权记录，观察结果是授权记录缺失时该请求仍处于待核实，不进入执行。
2. 把接口返回的相似度或相关度当作权限或实体过滤。输入是 score 值，比较对象是业务权限清单，观察结果是两者不构成同一判断依据。
3. 把待审核的交接请求当作已执行同步。输入是“把本场订单状态同步到外部工单系统”这句话，比较对象是接口调用记录与授权记录，观察结果是两者均缺失时该同步未发生。

## 怎么确认配好了
1. 输入假设样本原文与拟稿句，比较拟稿句是否只使用讲解卡已载明的有效期、主体与售后口径，观察结果是拟稿句未新增未载明条件时通过。
2. 输入一条 `[]` 空结果，比较下游设计是否把空结果作为无记录处理，观察结果是下游未把空结果当作有记录时通过。
3. 输入交接请求文本，比较是否附有授权记录与接口契约，观察结果是两者缺失时记录为待核实、不标记为已同步。以上为纸面核对，未实际调用接口。
