# 品牌自播直播间运营的订单履约与售后答疑：分享与嵌入

## 这个品类的数据长什么样

在品牌自播直播间运营的订单履约与售后答疑中，本页说明FastGPT的分享与嵌入如何衔接资料。分享直播协作进度时核场次与商品限定，稿件、评论和真实播出结果分别取证。所用场景为自拟文字测试。

## 这些特征在「分享与嵌入」这一环带来什么约束

协作摘要可拟本场脚本待确认、商品卡已收的状态，不开放内部审核评论、其他场次资料或观众个人信息。完整链接核接收原句、场次与版本，再索取限制来源测试。入口口令不证明真实主播或运营身份，需要验证时按商业版实际能力核。商品卡支持哪些主张仍须看原句限定，脚本存在不说明主播已经说过，评论提到购买也不能代实际交易依据；分享仅说明收到哪些资料。

## 配置怎么定

| 直播协作分享 | 本场进度范围 | 验证线索 |
| --- | --- | --- |
| 公开摘要 | 脚本待确认商品卡已收 | 场次版本及原句 |
| 限制来源 | 他场内部意见和个人资料 | 完整回答与拒绝 |
| 设备追问 | 说过的具体场次和句子 | 实际历史及补问 |
| 结果证据 | 稿件评论不代播出成交 | 批准及交易记录 |
| 执行边界 | 分享不操作账号或订单 | 权限和实际回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `免登录窗口` | 复制生成的完整分享链接。 |
| `过期时间与QPM` | QPM指每用户每分钟访问上限。 |
| `积分上限` | 按入口及版本核用量与费用条件。 |
| `身份验证` | 第三方认证受商业版范围限制。 |
| `对话记录边界` | 匿名标识依赖同设备、同浏览器。 |

## 容易做错的三处

- 本场摘要返回其他场次内部意见或观众资料：保存来源身份及完整回答查授权，同商品同主播不提供跨场公开依据。

- 电脑问本场脚本、手机问“说过了吗”缺场次及原句：核实际历史补前问，匿名标识不自动跨设备，不拿上一场内容当本次。

- 稿件或评论被写成真实播出、宣传获准或已经成交：分别取本场播出、批准及交易依据，摘要展示不补这些事件。

## 怎么确认配好了

验收请求公开摘要、他场来源和内部意见，记录实际原句、版本及拒绝。商品依据已取得未进入输入与本场没有播出记录分开，不以入口续期生成结果。换设备测试缺对象追问，核是否补场次商品和所问句。分享不操作直播账号、批准宣传或修改订单；正式执行另验权限与真实记录，仍缺支持的主张继续待核，不能把链接可访问或讨论结束称本场业务已完成。
