# 品牌自播直播间运营的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在品牌自播直播间运营的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。自播售后需要并列口播、商品卡和本场确认，不由一句话代全部来源。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

品牌自播售后可拟口播摘录“套装含吸管”、商品卡“吸管另选”和场次便签“本场以确认页为准”。顾客问本单到底含不含吸管，当前确认页未给。口播与卡片是不同来源，可能版本或场次不同，检索应并列保留二者，核适用确认后再解释差异。用含吸管和另选原词及整题核候选，也不能由较新文件名推它一定适用；需要本场、本单的对应依据。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 并列来源 | 口播与卡片 | 核候选是否均有。 |
| 问题适用 | 本场本单 | 优化不泛化。 |
| 确认身份 | 当前场次 | 不由标题认定。 |
| 引用完整 | 含与另选及来源 | 保留限定。 |
| 当前缺项 | 适用确认未给 | 不自动选边。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是只召回口播而漏商品卡，应核查询范围、版本及原词覆盖，不以有答案片段就停止。第二处是优化把本单组成改成一般套装介绍，应比前后问句，保留场次和订单。第三处是确认页返回却来自另一场，应对事件身份及实际引用，不因都叫确认就采用。三项分别查双来源覆盖、提问适用和确认归属，不以相关度、文件时点或关键词重复代业务取舍。

## 怎么确认配好了

验收分别问两份文字各说什么、缺哪份确认、当前能支持到哪一步，保存实际候选与引用。语义、全文和混合检索按同题比较，token预算应让含、另选与来源身份保留。补本场确认后核它对应本单，再检查回答采用；未补前不由口播相关就宣布承诺有效或退差处理。本练习不配置赠品、不判责任或改订单，未返回来源不代表其不存在，仍需核范围与传递。
