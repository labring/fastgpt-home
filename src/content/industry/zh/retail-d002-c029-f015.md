# 售后维修与补寄的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

在售后维修与补寄的订单履约与售后答疑中，本页说明FastGPT的知识库检索与召回如何衔接资料。补寄售后要检索卡扣、盖片和具体包裹对象，避免同机型配件混用。所用场景为自拟文字测试。

## 这些特征在「知识库检索与召回」这一环带来什么约束

补寄售后可拟申请“卡扣断了”、配件说明“卡扣与盖片分列”和寄出记录“盖片已交寄”。顾客问卡扣是否寄出。当前寄出的是另一部件，机型相同也不证明卡扣包含其中。检索需保留配件层级及记录受词，用卡扣原词、盖片和完整寄出问句核候选。申请描述不自动构成检查结论，盖片发运也不能证明商品已经恢复使用；本题还缺本次卡扣记录。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 申请部件 | 卡扣 | 不变整套。 |
| 寄出受词 | 盖片 | 不代卡扣。 |
| 优化组成 | 未给配套关系 | 不新增包含。 |
| 物流归属 | 本次申请包裹 | 核身份及机型。 |
| 结果阶段 | 交寄与收到 | 分别取证。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `搜索模式` | 支持语义、全文与混合模式。 |
| `引用上限` | 引用上限按token计。 |
| `最低相关度` | 范围0–1，仅语义或重排时生效。 |
| `问题优化` | 用于指代消除与问题扩展。 |

## 容易做错的三处

第一处是盖片寄出被采用为卡扣进度，应对候选部件与原数据身份。第二处是优化把卡扣改写为整套配件，应比前后对象，不补未确认组成。第三处是另一申请的卡扣包裹被本次采用，应核申请、机型和物流对象，不能只按卡扣词匹配。三项分别查部件、改写范围和记录归属，不由同型号或高分物流片段推本单实际发运。

## 怎么确认配好了

验收分别问申请指什么、清单怎么分、记录寄了什么，逐句展开引用。语义、全文、混合检索用同题对返回来源，引用token预算要保留盖片和卡扣名称，不只留已寄出。新增本次卡扣记录后核申请及包裹再问，发出和顾客收到仍分开。本练习不创建补寄单、不安排承运或确认适配，也不认定实际故障；材料未给时保留待核，不从没有命中推供应方已经拒寄。
