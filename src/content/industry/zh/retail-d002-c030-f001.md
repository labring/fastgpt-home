# 商超供应商进场结算的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

商超供应商进场结算多为购销或代销账款，不一定有驻场经营，因此订单履约与售后答疑的核对对象集中在采购合同、送货验收单、返利协议、对账单四类材料。这些材料分属 ERP 采购、供应商门户、POS 销售、财务系统，数据按周或按月更新，跨系统取数时字段口径与期间范围容易不一致。核验收数量、返利与退货差异时，应保留单笔和整月范围。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，实际操作与 Postman、ApiFox 这类工具接近。Params 为路径请求参数，GET 请求中用得居多；Body 为请求体，POST/PUT 请求中用得居多；Headers 为请求头，用于传递特殊信息。三类数据均可通过 `{{}}` 引用变量，URL 同样可以引用变量，变量来源为全局变量、系统变量、前方节点输出。返回值配置说明响应解析规则，通过JSON path提取所需值；输出类型选择字符串时，会把对应 key 的值转成 json 字符串再输出。

HTTP节点的系统变量含appId、chatId、responseChatItemId、variables、cTime、histories。测试模式下chatId与responseChatItemId不存在；histories默认最多10条，长度不能修改。这些是节点可引用的输入，不能当作供应商接口必须返回的字段。FastGPT对话API的鉴权、detail及stream规则按该API单独核，不套用到外部结算接口。

订单履约与售后答疑涉及的验收数量、返利扣点、退货差异属于业务核对，HTTP 模块只负责按契约收发数据。检索与相似度不承担权限或实体隔离职责，检索结果不能当作授权依据。表单收集的是值，业务校验、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：某供应商与某商超签订采购合同（编号 HT-2024-031，签订日 2024-03-01，有效期至 2025-02-28），约定月度对账。假设送货验收单 YS-2024-0407 载明 2024 年 4 月 7 日到货 120 箱，单价 30 元；假设对账单 DZ-2024-04 载明该笔到货 100 箱，金额 3000 元；假设返利协议 FL-2024-01 约定月采购额满 30000 元返 2 个点。一条待判定的拟稿句为：“4 月 7 日到货 120 箱已全部计入 4 月对账。”该句涉及验收单与对账单两个不同字段，需先核对数量口径再判断。

## 配置怎么定

| 配置项 | 假设起点与理由 | 比较方法 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选择地址与方法，地址可引用已提供变量 | 与接口文档声明的地址、方法逐字比对 |
| Params 与 Headers | 分别核对路径参数与请求头，鉴权凭证经安全配置注入 | 与接口契约中参数名、类型、必填性比对 |
| Body | 仅在相应请求类型下使用，核对 JSON 结构与契约 | 与接口文档给出的请求体结构比对 |
| 变量引用 | 可引用全局变量、系统变量、前方节点输出 | 逐项核对实际传入值来源与预期来源 |
| 返回值解析 | 按 JSON path 提取，输出类型选择字符串时转为 json 字符串 | 与接口响应实际结构比对 key 路径 |
| 调试系统变量 | chatId、responseChatItemId测试模式下不存在 | 核运行模式及变量来源，外部响应另核 |

## 容易做错的三处

1. 把测试模式下 chatId 或 responseChatItemId 为空当成业务故障。输入为测试模式请求，比较对象为文档说明的“测试模式下不存在”，先核节点运行模式和可用系统变量，实际外部响应按其契约另核，不由缺少系统变量推断业务故障。
2. 把检索结果或相似度分数当成权限或实体隔离依据。输入为一次检索返回，比较对象为业务授权来源，可观察结果是授权结论是否另有独立来源，检索本身不产生授权效果。
3. 把表单收集到的值当成业务已校验或已写入。输入为交互节点表单提交内容，比较对象为下游校验、审批、写入与同步的实现，可观察结果是这些动作是否由其他环节完成。

## 怎么确认配好了

1. 输入假设样本中的送货验收单 YS-2024-0407 与对账单 DZ-2024-04，比较同一字段“到货数量”的两个取值 120 箱与 100 箱，可观察结果是两者不一致，拟稿句“已全部计入”未获支持，需标记待核实。
2. 输入返利协议与该笔3000元对账记录，分别核单笔金额和整月采购额。月汇总未给，无法确定是否达到30000元门槛；2个点的条件及计算另核，不能用单笔金额代表整月。
3. 核测试模式下HTTP节点可引用的系统变量，chatId与responseChatItemId按文档不存在，histories默认最多10条。记录实际带入的历史及模式，不要求外部结算接口返回这些字段，也不推断业务故障。
