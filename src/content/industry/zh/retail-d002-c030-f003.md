# 商超供应商进场结算的订单履约与售后答疑：分享与嵌入

## 这个品类的数据长什么样

在商超供应商进场结算的订单履约与售后答疑中，本页说明FastGPT的分享与嵌入如何衔接资料。分享商超供应商结算进度时核本批本期，区分签收、验收意见和双方对账确认。所用场景为自拟文字测试。

## 这些特征在「分享与嵌入」这一环带来什么约束

自拟协作摘要可列本批已到货、验收意见待补、本期对账待确认，不放内部结算意见、他供货方合同或真实财务凭据。完整链接核接收原句和本期对象，再请求限制资料测范围。口令不证明真实供应商身份，必要验证按商业版实际能力核。到货、验收通过和结算认可各有不同来源；即使摘要列三项，也不能把其中一项已发生扩成全部完成，合同存在还不提供实际执行结果。

## 配置怎么定

| 供应商结算分享 | 本批本期范围 | 检查动作 |
| --- | --- | --- |
| 公开摘要 | 到货验收待补对账待核 | 对象阶段原句 |
| 限制来源 | 他方协议和内部结算 | 完整回答与拒绝 |
| 设备追问 | 这批及所问验收阶段 | 历史批次及期间 |
| 确认区别 | 签收编制不代验收认可 | 本批本期真实依据 |
| 执行边界 | 分享不验收调账或收付 | 权限记录及回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `免登录窗口` | 复制生成的完整分享链接。 |
| `过期时间与QPM` | QPM指每用户每分钟访问上限。 |
| `积分上限` | 按入口及版本核用量与费用条件。 |
| `身份验证` | 第三方认证受商业版范围限制。 |
| `对话记录边界` | 匿名标识依赖同设备、同浏览器。 |

## 容易做错的三处

- 本供应商摘要返回他方协议或内部结算说明：保留主体和完整回答查授权，同商超不构成跨供货方公开依据。

- 电脑问本期对账、手机问“这批过了吗”缺批次及前文：核实际历史补具体问题，匿名标识不自动跨设备，不拿旧批意见当本题。

- 到货签收或对账编制稿被答成验收通过、双方已认可：分别取本批验收及本期确认，收材料与作决定不同。

## 怎么确认配好了

验收请求公开摘要、他方来源和内部意见，记录原句、版本与拒绝。本期确认已有未入输入与双方尚未确认分开定位，入口续期不生成结算结果。换设备复问缺对象追问，核是否补批次、期间和所问阶段。分享不执行验收、调整结算或处理收付；真实业务另验权限、记录及回执。仍缺材料的阶段保持待核，不因已提供答复就认定供应商或商超已正式接受。
