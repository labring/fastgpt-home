# 商超供应商进场结算的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

在商超供应商进场结算的订单履约与售后答疑中，本页说明FastGPT的对话日志与审计如何衔接资料。进场售后回看按供应主体、收货与结算阶段找原文，不由日志存在确认商超认可。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

假设进场清单属于供应商分支，商超收货说明仅确认货物收到，结算异议还在核对。售后追问是否结清时，先定位本次chatId和对应主体，再查输入历史及实际回答。运行详情按官方契约取得，返回字段不能证明全部合同、结算表和资金凭证均在上下文中，本例不提供真实金额。

## 配置怎么定

| 进场结算日志 | 纸面状态 | 原文核查 |
| --- | --- | --- |
| 供应分支 | 主体有限 | 核签约身份 |
| 商超收货 | 仅收到货物 | 非结清 |
| 结算异议 | 仍待核对 | 不写双方认可 |
| 资料覆盖 | 合同凭证另核 | 检查实际输入 |
| 资金确认 | 业务流程决定 | 日志不授权 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

分支材料被套另一法人时，核签约主体；收货被答结清时，核结算与资金凭证；异议待核被写双方认可时，对原文及确认材料。三处分别查身份、阶段和意见状态，不以日志留存替代对方认可。

## 怎么确认配好了

验收逐项标注结论使用的输入片段，调试与正式请求分别核对身份及历史。缺结算表时说明资料未核，不能由详情缺项推没有交易。补主体只改对应关系；对账、结算和资金确认仍由实际业务流程及凭据决定，日志回看不给支付授权。 商超确认原句保留确认对象，供应分支与签约主体的关系缺证时列为未决。
