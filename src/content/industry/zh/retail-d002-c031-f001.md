# 商超塑料袋与一次性用品报告的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

本页处理商超塑料袋与一次性用品报告在订单履约与售后答疑中的 HTTP 接口与外部系统实施。该品类围绕一次性塑料制品报告与环保监管，数据来源包括商务部报告系统、POS 塑料袋销售、采购系统与门店台账，日常文档为采购台账、销售凭证、半年报告与自律承诺，数据更新频率为半年与日。订单履约与售后答疑场景下，外部接口需要接收门店提交的采购台账、销售凭证或报告进度查询，并返回可核对的业务状态。接口传递的是材料与请求，不构成授权、审批或报送完成。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向目标地址发送请求，Params 用于路径参数，Body 用于 POST/PUT 请求体，Headers 用于传递特殊信息。三类数据与 URL 均可通过 `{{}}` 引用变量，变量来自全局变量、系统变量与前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories。chatId 与 responseChatItemId 在测试模式下不存在，测试环境取不到值属于文档已说明的条件，不能据此判定业务故障。返回值配置通过 JSON path 提取接口响应值，出参格式化在 v4.6.8 后可将 key 对应值转为 json 字符串。对话接口支持 detail 参数返回中间值，stream 模式下通过 event 区分，非 stream 模式结果保存在 responseData。插件类应用默认 detail 模式，通过 variables 传输入、pluginData 取输出。检索与相似度不承担权限或实体隔离职责，接口调用前需确认调用方是否具备目标应用与会话权限。

假设演练样本：某商超总部合规岗于 2025 年 3 月 10 日整理一份门店采购台账，材料原文为「2025 年 1 月 1 日至 6 月 30 日期间，XX 门店累计采购一次性塑料袋 12000 只，其中可降解材质 8000 只，普通塑料 4000 只，采购凭证编号 CG-2025-0310。」另有一份拟提交的半年报告草稿句：「本门店上半年一次性塑料袋使用量已全部回收，回收率 100%。」待判定问题：该草稿句是否与台账原文相符。台账原文只记录采购数量与材质分类，未记录使用量与回收量，草稿句中的使用量与回收率在原文中没有对应数据，属于未获支持，需补充使用与回收记录后再核对。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 按外部接口文档填写，可引用变量 | 地址来自接口文档，与文档给出的路径逐字比较 |
| 请求方法 | POST 用于提交台账查询 | 与接口文档声明的方法比较，不一致则调整 |
| Headers | 鉴权凭证通过安全配置注入 | 与接口文档要求的鉴权方式比较，凭证不写入公开样例 |
| Body 结构 | 按台账字段构造 JSON | 与接口契约字段逐项比较，核对字段名与类型 |
| 变量引用 | 引用前方节点输出的台账字段 | 与节点输出实际值比较，核对传入值是否为空 |
| 返回值提取 | 按 JSON path 配置 key | 与接口响应结构比较，核对提取路径是否命中 |

## 容易做错的三处

1. 把测试模式下 chatId 与 responseChatItemId 不存在当成业务数据缺失。文档已说明测试模式不产生这两个值，核对时应区分测试环境与正式环境，不能据此判定履约或售后记录丢失。
2. 将草稿句中的使用量与回收率直接视为台账已支持的事实。台账原文只记录采购数量与材质，使用量与回收量属于另一字段，需单独核对来源，未载明时记录为待核实。
3. 把接口返回的相似度或检索结果当成权限判定。相似度不承担实体或权限过滤，接口调用前需确认调用方具备目标应用与会话权限，检索结果不能替代授权。

## 怎么确认配好了

1. 输入假设样本中的台账原文与草稿句，比较草稿句的使用量、回收率字段与台账原文的采购数量、材质字段，观察草稿句是否出现原文未载明的数值。若草稿句数值在原文中无对应，记录为未获支持。
2. 输入一条待提交的半年报告请求，比较请求中的门店主体、期间范围与授权状态，观察请求是否在授权范围内。若请求超出授权范围，记录为待确认，不执行提交。
3. 输入测试模式下的接口调用，比较返回的 chatId 与 responseChatItemId 是否为空，观察是否与文档说明的测试模式条件一致。若为空且处于测试模式，记录为文档已说明条件，不判定为故障。
