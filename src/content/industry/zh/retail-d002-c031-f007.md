# 商超塑料袋与一次性用品报告的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

商超塑料袋与一次性用品报告围绕一次性塑料制品报告与环保监管展开，主要数据来源包括商务部报告系统、POS塑料袋销售、采购系统与门店台账，典型主体涉及商超门店、总部合规与行政采购。日常文档包含塑料袋采购台账、销售凭证、半年报告与自律承诺，最耗时的环节集中在统计使用量、核对销售凭证与报送回收情况。这些特征在订单履约与售后答疑中意味着：对话日志需要同时承载采购台账、销售凭证与半年报告的业务追问，日志记录本身只反映会话与运行轨迹，不对应监管报送或合规审计的完成状态。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话日志依赖 chatId、dataId、appId 三个标识定位会话与对话。chatId 为 undefined 时不使用上下文功能，仅通过传入 messages 构建上下文；chatId 为非空字符串时自动从数据库取会话，并以 messages 数组最后一个内容作为用户问题，其余 message 被忽略。responseChatItemId 在同一 chatId 下需保持唯一。detail=true 时，非 stream 模式在 responseData 中返回模块状态与完整结果，stream 模式通过 event 区分，event 取值包括 answer、flowNodeStatus、flowResponses、updateVariables、interactive、error 等。审计核对需要按这些字段定位输入与返回，未返回的业务数据不能推定已完整留存。检索与相似度不承担权限或实体隔离功能，日志存在不等于完成合规审计。

假设演练样本：某商超门店与总部合规之间，就一批塑料袋采购台账的售后答疑进行对话交接。供核对的材料原文为：“本批次塑料袋采购台账记录采购数量为 12000 只，采购日期为 2025 年 3 月 10 日，供应商为某包装厂，销售凭证编号为 XS-2025-0310。”交接请求拟稿句为：“请确认该批台账对应的销售凭证已全部核对，并授权报送半年报告。”该请求处于待确认状态，材料中未载明核对完成记录，也未载明报送授权。

## 配置怎么定

| 配置项 | 本页相关设置或核对项 | 与样本的对应关系 |
| --- | --- | --- |
| appId | 调用 chat/completions 时在请求体传入 body.appId | 标识该门店应用，与样本会话绑定 |
| chatId | 非空字符串，长度小于 250，需自行确保唯一 | 标识本次售后答疑会话 |
| dataId | 用于获取单个对话运行详情 | 定位台账追问的具体对话 |
| detail | 设为 true 时返回 responseData 中间值 | 核对本次答疑的模块状态与返回 |
| responseChatItemId | 传入后作为响应消息 ID 存入数据库，同一 chatId 下唯一 | 标记本次台账核对请求的响应 |
| loadCustomFeedbacks | 获取对话列表时可选读取自定义反馈 | 核对答疑反馈记录 |

样本起点为 detail=true、stream=false，选择理由是需要查看 responseData 中的模块状态与完整结果，与 detail=false 的仅返回最终回答进行对比。该起点为本次假设试验设置，非官方默认值。

## 容易做错的三处

1. 将 chatId 为 undefined 的请求与已有会话混算。输入为不传 chatId 的请求，比较对象为同一 appId 下已存在的 chatId 会话，观察结果是前者不读取数据库上下文、仅用 messages 构建上下文，后者自动取会话并忽略除最后一条外的 message。
2. 将 detail=false 的返回当作完整运行详情。输入为 detail=false 的调用，比较对象为 detail=true 的 responseData，观察结果是前者不返回模块状态与中间结果，后者才包含 moduleName、runningTime 等字段。
3. 将待确认的交接请求当作已授权报送。输入为样本拟稿句，比较对象为材料原文中是否载明核对完成与报送授权，观察结果是原文仅记录采购数量、日期、供应商与销售凭证编号，未载明核对完成或授权，该请求仍处于待核实状态。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较拟稿句中“已全部核对”“授权报送”与原文是否载明对应事实，观察结果为原文未载明核对完成与授权，判定为未获支持。
2. 输入 detail=true、stream=false 的调用，比较返回的 responseData 中是否存在 moduleName 与 runningTime 字段，观察结果为存在则说明中间值已返回，不存在则记录为未观察到。
3. 输入同一 chatId 下两次传入相同 responseChatItemId 的请求，比较两次响应是否指向同一响应消息 ID，观察结果为需保持唯一，若重复则记录实际观察到的返回，不推定自动拒绝或报错。
