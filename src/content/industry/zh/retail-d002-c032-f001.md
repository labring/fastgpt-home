# 商超收银与会员促销的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
商超收银与会员促销的订单履约与售后答疑，围绕促销价签、会员积分规则、收银日报、异常退款单展开。与便利店鲜食订货相比，这个品类关注价格与会员权益，不处理短保库存。数据来源包括 POS 系统、会员 CRM、支付平台与价签系统，更新频率为日或每班。HTTP 接口与外部系统这一环，要把外部请求的地址、方法、参数、鉴权与返回值解析逐项对齐到上述单据，任何一项错位都可能落到价格投诉、账款短溢或会员权益纠纷上。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP模块向指定地址发送请求。Params、Body、Headers与URL可用 `{{}}` 引用全局变量、系统变量或前方节点输出。响应解析通过JSON path提取值，选字符串输出时对应值转为json字符串。chatId及responseChatItemId为会话系统变量，测试模式下不存在；不能把它们当成外部退款接口必须返回的字段。FastGPT对话API的appId、detail及stream参数按该API另核。检索及表单不提供退款或同步授权。

假设演练样本：某门店收银主管在 2025 年 3 月 12 日班次交接时，持有一份促销价签原文“3 月 12 日全店会员价 9.9 元，收银小票打印原价 12.9 元与会员优惠 3 元”，以及一份异常退款单原文“3 月 12 日 14:20 订单号 A-0312-14，退款金额 9.9 元，状态为待审核”。拟稿句为“该笔退款已按会员价完成退款并同步至会员 CRM”。判定该句时，需比较退款单状态字段是否载明已完成、会员 CRM 是否载明已接收该笔记录；待审核不等于执行完成，未载明的同步结果保持未知。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址可引用变量 | 与外部接口契约逐字比对 |
| Headers 鉴权 | Authorization 使用 Bearer 加凭证变量 | 核对凭证注入位置，不写入公开样例 |
| Body 结构 | 按所选请求方法和外部契约确认，核JSON结构 | 核字段名、类型及必填条件 |
| 变量引用 | 引用全局变量、系统变量或前方节点输出 | 逐项核对实际传入值 |
| 返回值解析 | 用 JSON path 提取响应值，输出类型按需选择 | 核对 key 与响应结构对应 |
| 调试身份字段 | chatId 与 responseChatItemId 测试模式下不存在 | 不把调试空值当业务故障 |

本次假设试验起点的选择理由：请求地址与方法、Body 结构、返回值解析均取决于外部接口文档，无法预设固定值；变量引用与调试身份字段取决于当前编排与运行模式。所有起点均需与外部接口契约或实际运行模式比较，不构成官方默认值。

## 容易做错的三处
1. 把返回值配置当成接口返回值本身。返回值配置是通过 JSON path 提取响应值，若把提取 key 直接当作接口字段，会得到与响应结构不一致的结果。检查方式：输入一段接口响应示例，比较配置的 key 与 JSON path 提取结果，观察输出是否与预期字段一致。
2. 把节点缺少调试身份变量当成外部业务故障。先核运行模式及可用系统变量；测试模式下这两个变量按文档不存在，外部退款接口响应仍按其契约另核，不能只由响应缺字段反推运行模式。
3. 把待审核状态当作已完成退款。假设演练样本中退款单状态为待审核。检查方式：输入该退款单原文，比较状态字段取值与“已完成”表述，观察状态字段是否载明已完成；未载明时记录为待核实。

## 怎么确认配好了
1. 输入假设演练样本中的促销价签原文与拟稿句，比较拟稿句“已按会员价完成退款并同步至会员 CRM”与退款单状态字段及会员 CRM 记录，观察退款单状态是否载明已完成、会员 CRM 是否载明已接收；两项均未载明时，判定该句未获支持。
2. 输入假设演练样本中的异常退款单原文，比较状态字段取值与“已完成”表述，观察状态字段是否明确载明已完成；仅载明待审核时，记录为待核实，不判定为已完成或未完成。
3. 待接口方提供响应样例后，核JSON path是否存在、提取值及输出类型是否符合下游约定。当前未给响应样例，解析配置待核；路径或类型不匹配不能单独证明外部接口故障。

以上验证仅描述预期观察，不表示已实际执行。缺失证据保持缺失，待审核不构成批准，未载明的同步结果保持未知。
