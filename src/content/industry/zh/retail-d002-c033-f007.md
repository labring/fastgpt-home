# 外汇收结汇与贸易名录的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

收结汇场景的对话日志围绕收汇水单、贸易合同、发票、外汇业务登记资料展开，从业主体为外贸财务、银行客户经理、外汇专员，数据按每单和每月更新。与信用证审单相比，本品类关注外汇资金和贸易背景真实性，不审全套信用证单据，因此日志中出现的材料类型不同于单证审核场景。出错后果包括银行退单、外汇分类异常、资金无法入账，日志审计需要能定位到具体对话与具体单据的对应关系。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份依靠 chatId 区分。chatId 为非空字符串时，FastGPT 自动从数据库取会话，并以 messages 数组最后一个内容作为用户问题，其余 message 被忽略，需自行确保 chatId 唯一且长度小于 250。responseChatItemId 传入后作为本次响应消息 ID 存入数据库，需在当前 chatId 下唯一。需要运行详情时，对话接口按官方契约设置 detail=true，中间值与完整结果保存在 responseData 中；非 stream 模式下模块响应在 responseData 数组内，stream 模式下通过 event 区分，flowResponses 事件携带节点完整响应。日志中未返回的业务数据不能推定已完整留存。检索与相似度分数不承担权限或实体隔离职责，检索不构成授权。

假设演练样本：材料原文为“2025 年 3 月 12 日，A 公司向 B 公司出口一批货物，合同金额 50000 美元，收汇水单显示付款方为 C 公司，金额 50000 美元，到账日期 2025 年 3 月 20 日”。待判定拟稿句为“本次收汇主体与合同买方一致，贸易背景已核实”。判断所需主体为 A、B、C 三方，对象为 50000 美元收汇，状态为已到账，有效范围为 2025 年 3 月。该拟稿句超出材料支持范围，材料中付款方为 C 公司，与合同买方 B 公司不同，且材料未载明 C 公司与 B 公司的关系，也未载明任何核实结论。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| chatId 使用方式 | 每笔收汇业务对应一个唯一 chatId | 与业务单据一一对应，比较不同 chatId 是否混入同一单据的对话 |
| responseChatItemId | 按对话逐条传入唯一值 | 保证响应消息可定位，比较同一 chatId 下是否出现重复值 |
| detail 参数 | 需要运行详情时设为 true | 按官方契约获取 responseData，核对模块响应是否完整返回 |
| stream 参数 | 按调用端能力选择 true 或 false | stream 下从 event 取 flowResponses，非 stream 下从 responseData 取 |
| 会话来源 source | 取会话列表时传 source=api | 只获取通过 API 创建的会话，不混入页面会话 |
| 反馈字段 | 按需传 userGoodFeedback 或 userBadFeedback | 取消时不传对应参数，比较反馈状态是否与操作一致 |

上述数值为本次假设试验起点，不属官方默认值。配置项只覆盖官方文档已说明的设置，数据库写入、外部同步、审批与合规留存由完整业务方案另行落实。

## 容易做错的三处

1. 把不同入口的会话混算。输入为两个不同 chatId 的对话记录，比较是否被当作同一笔收汇业务的日志，可观察结果是同一单据出现跨 chatId 的对话内容。
2. 把未返回字段推定为已留存。输入为 detail=true 的 responseData，比较其中是否包含业务所需字段，可观察结果是字段缺失但被记录为已留存。
3. 把检索结果当作授权依据。输入为相似度分数较高的引用列表，比较该列表是否被用于判断某笔收汇已获批准，可观察结果是检索命中被写成审批通过。

## 怎么确认配好了

1. 使用假设样本中的材料原文与拟稿句，输入为“本次收汇主体与合同买方一致，贸易背景已核实”，比较材料中付款方 C 公司与合同买方 B 公司是否同一主体，若不同且无关系说明，则拟稿句未获材料支持，记录为待核实。
2. 使用同一假设样本，输入为 chatId 与 responseChatItemId，比较同一 chatId 下 responseChatItemId 是否唯一，若出现重复值，则该条响应消息无法唯一定位，需记录实际返回值。
3. 使用同一假设样本，输入为 detail=true 的请求，比较 responseData 中模块响应字段与业务审计所需字段，若所需字段未出现，则记录为未获支持，不推定已留存。
