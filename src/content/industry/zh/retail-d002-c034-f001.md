# 外贸出口退税申报的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

外贸出口退税申报在货物出口后做税务凭证匹配，主要数据来源为电子税务局、出口退税申报系统、海关电子信息与财务账，日常文档包括出口退免税申报表、出口报关单、进货发票、收汇凭证。这些材料的字段需要在订单履约与售后答疑环节通过 HTTP 接口与外部系统流转，接口传入值与材料原文之间必须逐项对应，不能由接口调用替代业务核对。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 为路径请求参数，Body 为请求体，Headers 为请求头，三者均可通过 `{{}}` 引用变量，变量来自全局变量、系统变量、前方节点输出。系统变量含 appId、chatId、responseChatItemId、variables、cTime、histories（默认最多取 10 条，无法修改长度）。chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 提取，输出类型选择字符串时按 json 字符串输出。对话接口调用 `chat/completions` 时推荐在请求体传入 `body.appId`，也支持 `Authorization: Bearer <apiKey>-<appId>`；传入的 model、temperature 等参数字段无效；detail=true 时中间值保存在 responseData。插件应用无需传入 chatId 与 messages，通过 variables 传输入，通过 pluginData 取输出。接口调用、检索与表单填写均不构成授权，业务验证、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：某外贸企业财务在订单履约与售后答疑中处理一笔出口退税申报，材料原文为「出口报关单：报关单号 HYP-2024-0417，出口日期 2024 年 4 月 17 日，商品为棉制女式衬衫，数量 1200 件。进货发票：发票号 FP-0417，开票日期 2024 年 4 月 20 日，对应报关单号 HYP-2024-0417。收汇凭证：凭证号 SH-0506，收汇日期 2024 年 5 月 6 日，金额与发票 FP-0417 一致。」待判定拟稿句为「该笔出口退税申报的进货发票与报关单已匹配，收汇凭证齐全，可提交申报。」该拟稿句声称匹配与齐全，但材料仅显示发票对应报关单号、收汇金额与发票一致，未载明申报表已生成、疑点已处理或授权已下达，属未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方法与理由 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选择，地址引用已提供变量 | 逐项核对地址、方法与接口契约是否一致 |
| Headers 鉴权 | 通过安全配置注入，不写入公开样例 | 核对鉴权凭证是否经安全配置传入 |
| Body 结构 | 仅在相应请求类型下使用 | 核对 JSON 结构与外部接口契约 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 逐项核对实际传入值 |
| 返回值提取 | 按 JSON path 配置 key | 核对提取结果与接口响应字段 |
| 调试身份字段 | chatId、responseChatItemId 测试模式下不存在 | 不把调试空值当成业务故障 |

## 容易做错的三处

1. 把接口调用当成授权执行。输入为上述拟稿句与材料原文，比较拟稿句声称的「可提交申报」与材料是否载明授权或申报表已生成，材料未载明，属未获支持。
2. 把检索或表单当成业务验证。输入为接口返回的发票号与报关单号，比较两者是否同主体同期同字段一致，未载明申报表字段时属待核实。
3. 把测试模式空值当成业务故障。输入为测试模式下 chatId 与 responseChatItemId 不存在，比较是否将调试空值判定为业务异常，文档说明测试模式下不存在，不构成业务故障。

## 怎么确认配好了

1. 输入上述材料原文与拟稿句，比较拟稿句声称的匹配与齐全是否在材料中有对应字段，只有材料载明申报表已生成且授权已下达才满足可提交条件，预期为未获支持。
2. 输入接口返回的发票号 FP-0417 与报关单号 HYP-2024-0417，比较两者是否同主体同期同字段一致，只有明确互斥取值才叫矛盾，未载明属待核实。
3. 输入测试模式下 chatId 与 responseChatItemId 不存在的场景，比较是否将空值判定为业务故障，文档说明测试模式下不存在，预期不构成业务故障。
