# 外贸出口退税申报的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样
外贸出口退税申报在货物出口后做税务凭证匹配，主要数据来自电子税务局、出口退税申报系统、海关电子信息与财务账，日常处理出口退免税申报表、出口报关单、进货发票、收汇凭证。订单履约与售后答疑这一环，会话记录会同时出现申报批次、报关单号、发票号码、收汇状态等业务线索。对话日志与审计要解决的是：这些线索在会话中如何被记录、如何按 chatId 与 dataId 定位、运行详情如何按官方契约取回。日志留存本身不完成合规审计，对账与留存要求由完整业务方案另行落实。

## 这些特征在「对话日志与审计」这一环带来什么约束
会话按 appId、chatId、dataId 三层定位。chatId 为空时不使用 FastGPT 上下文，完全以传入 messages 构建；chatId 为非空字符串时从数据库取会话，以 messages 最后一个内容作为用户问题。responseChatItemId 在当前 chatId 下需唯一。detail=true 时中间值进入 responseData，stream 模式通过 event 区分，非 stream 模式结果保存在 responseData。相似度与检索结果不构成权限或实体隔离，检索不是授权。交互节点等待时接口直接返回，entryNodeIds、memoryEdges、nodeOutputs、nodeResponseId 等内部运行态字段不返回。

假设演练样本：某外贸企业财务在订单履约与售后答疑中提交一条会话，材料原文为：“出口报关单号 2024XXXX，对应进货发票号 FP-001，收汇凭证显示 2024 年 3 月已收汇，申报批次 202403。”拟交接请求句为：“请把该批次的退税申报状态同步给售后答疑窗口。”该请求含主体、对象、状态与时间范围，用于核对会话记录与运行详情字段。

## 配置怎么定
下表围绕该样本，列出官方已说明的设置或实施核对项。

| 核对项 | 假设起点 | 比较与说明 |
| --- | --- | --- |
| appId | 样本应用 ID | 与会话列表返回的 appId 比较，确认同一应用 |
| chatId | 样本会话 ID | 长度小于 250，与 getHistories 返回比较 |
| dataId | 样本对话 ID | 与 getPaginationRecords 返回比较，定位单条对话 |
| detail | true | 需要运行详情时设置，检查 responseData |
| source | api | 取 API 创建的会话，与页面会话区分 |
| loadCustomFeedbacks | true | 读取自定义反馈，与记录返回比较 |

以上数值为本次假设试验起点，选择理由是需要定位单条对话并读取运行详情，比较对象为接口实际返回字段。

## 容易做错的三处
1. 把 chatId 为空与 chatId 非空两种模式混算。输入为空 chatId 的请求，比较是否仍从数据库取会话；若返回内容与传入 messages 一致，说明未使用上下文，不能据此认定会话已留存。
2. 把相似度当作权限过滤。输入样本批次查询，比较返回 quoteList 是否含其他批次；score 高低只表示相似程度，不能推断无关业务被排除。
3. 把交互节点返回当作已提交。输入含交互节点的请求，比较 choices[].message.content 中的 interactive 字段；接口返回展示配置，不表示表单已提交或业务已执行。

## 怎么确认配好了
1. 输入样本 chatId 与 dataId，调用 getResData，比较返回的 nodeId、moduleType、runningTime 是否与本次对话对应。出现 moduleType=chatNode 且 query 为样本问题，说明运行详情可取回。
2. 输入样本拟交接请求句，检查会话记录中 Human 与 AI 的 value 内容。比较记录中的批次、报关单号、发票号是否与材料原文一致；若记录缺失或字段为空，属于未获支持，需记录缺口。
3. 输入 detail=true 与 stream=false，比较 responseData 是否含中间值。若 responseData 为空或字段与文档不符，记录实际观察，不推定失败原因。检索检查只观察返回与失败分支，不保证首条命中或无关查询为空。
