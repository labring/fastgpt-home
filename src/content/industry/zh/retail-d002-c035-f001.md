# 外贸退运与索赔的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

退运索赔发生在出口之后，处理的是逆向物流与责任认定。日常材料包括退运协议、索赔函、质量报告和退运报关单，来源涉及客户邮件、质检报告、海关系统和保险公司理赔系统。这些材料按案产生，更新不定期，每案处理一次。

落到 HTTP 接口与外部系统这一环，材料形态决定请求形态。退运协议和索赔函属于双方文件，条款状态需要人工确认；质量报告和退运报关单带有编号、日期和数量，适合作为结构化字段传入。外部系统返回的内容属于对方系统输出，本平台只负责发起请求和解析响应，不对返回结果做业务认定。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径参数，Body 用于请求体，Headers 用于请求头。三类位置和 URL 都可以通过 `{{}}` 引用变量，变量来自全局变量、系统变量和前方节点输出。系统变量包括 appId、chatId、responseChatItemId、variables、cTime 和 histories。chatId 与 responseChatItemId 在测试模式下不存在，调试时读到空值属于环境差异。

返回值通过 JSON path 提取，输出类型选择字符串时会把对应值转成 json 字符串。对话接口调用时推荐在请求体传入 body.appId，也可用 `Authorization: Bearer <apiKey>-<appId>`。传入的 model、temperature 等字段无效，由编排决定。检索或表单收集只完成取值，业务核验、审批、数据库写入和外部同步需要各自的下游实现。

假设演练样本：某外贸售后人员处理一票退运，材料原文为“退运协议编号 TR-2024-018，签署日期 2024 年 3 月 12 日，退运数量 200 件，退运原因载明为外观划痕”，另有“索赔函编号 CL-2024-007，索赔金额待保险理赔系统核定”。待判定的交接请求为：“请把退运协议编号和退运数量写入外部理赔系统，并确认索赔已受理。”该请求中，协议编号与数量属于可直接取值字段；索赔是否受理属于外部系统状态，材料未载明，不能由本页请求推断。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 依据与比较方法 |
| --- | --- | --- |
| 请求地址 | 外部理赔系统提供的接口地址 | 按外部接口文档填写，地址可引用已提供变量 |
| 请求方法 | POST | 按外部接口文档选择，Body 仅在相应请求类型下生效 |
| Headers | 鉴权凭证通过安全配置注入 | 不写入公开样例，核对实际注入值 |
| Body 字段 | 退运协议编号、退运数量 | 引用前方节点输出，逐项核对实际传入值 |
| 返回值提取 | 按 JSON path 提取受理状态字段 | 输出类型选字符串时转为 json 字符串 |
| 调试身份 | chatId 与 responseChatItemId 留空 | 测试模式下这两个变量不存在，不当作业务故障 |

## 容易做错的三处

1. 把材料中未载明的状态当成已确认。样本中索赔函只写“索赔金额待保险理赔系统核定”，若在请求体里填入“已受理”，输入是材料原文，比较对象是索赔函载明状态，可观察结果是请求体出现原文没有的状态值。
2. 把检索或表单取值当成授权执行。样本的交接请求要求“确认索赔已受理”，输入是表单收集到的协议编号，比较对象是外部系统返回的受理字段，可观察结果是本页流程未产生受理结论。
3. 把测试模式下的空 chatId 当成接口故障。输入是测试模式发起的请求，比较对象是系统变量说明中 chatId 在测试模式下不存在，可观察结果是请求仍可发出，chatId 为空属于环境差异。

## 怎么确认配好了

1. 取样本原文“退运协议编号 TR-2024-018，退运数量 200 件”，将该编号与数量作为变量传入 Body，比较请求体中实际出现的值，两者与原文一致时满足条件；出现原文没有的字段值时不满足。
2. 取拟稿句“确认索赔已受理”，比较该句与索赔函原文“索赔金额待保险理赔系统核定”，拟稿句未把待核定写成已受理时满足条件；把待核定表述为已受理时不满足。
3. 取测试模式请求，比较 chatId 与 responseChatItemId 的实际取值，两者为空且请求正常发出时满足条件；把空值记录为业务故障时不满足。三项均为纸面核对，未实际执行。
