# 外贸退运与索赔的订单履约与售后答疑：分享与嵌入

## 这个品类的数据长什么样

外贸退运与索赔围绕出口后的逆向物流与责任认定展开，与一般出口报关的流程方向不同。日常材料包括退运协议、索赔函、质量报告、退运报关单，来源分散在客户邮件、质检报告、海关系统与保险公司理赔系统。这些材料按每案不定期更新，同一票货物在不同环节产生的文档状态并不一致。

在订单履约与售后答疑中，分享与嵌入把上述材料交给售后、关务、保险理赔等角色查看，并允许对方就退运原因、申报进度、索赔证据提问。材料本身存在版本先后与签署状态差异，分享入口只解决访问路径，不改变材料效力。

## 这些特征在「分享与嵌入」这一环带来什么约束

免登录窗口从应用详情的发布渠道创建，系统生成完整链接，链接标识用于访问，不能当成业务授权凭证。任何互联网用户拿到该地址即可使用，费用产生在应用归属团队下。身份验证栏填写的是 POST 请求根地址，初始化、开始对话、对话结束分别向该根地址下的接口发送请求，服务器返回 success 与 uid 即可。uid 用于拉取与保存对话记录，格式为不含 "|"、"/"、"\\" 且不超过 255 字节长度的字符串。匿名方式依赖同一设备同一浏览器，仅允许拉取近 30 天的 20 条记录，跨设备或清空缓存会丢失。

假设演练样本。 供核对的材料原文：某公司售后人员留存一份退运协议草稿，抬头写明发货方与收货方，正文写“双方同意就本批货物办理退运，具体数量与费用待质检报告确认后补充”，落款处无签署日期与签章。另有一封索赔函草稿，写“现就上述货物提出索赔，金额以保险公司核定为准”。一条待判定的交接请求为：“把该退运协议与索赔函通过免登录链接发给对方，视为已完成退运确认与索赔受理。”样本主体为假设的甲、乙两方，对象为该批退运货物，状态为草稿且未签署，日期与数量范围未载明，授权边界为仅供查看，不含确认或受理。

该请求把草稿状态当成已完成事实。退运协议未签署，索赔函金额未定，两者都不构成确认或受理。分享链接可以传阅材料，不能替代签署、核定或授权。

## 配置怎么定

围绕该样本，只列与本功能、主任务相关的已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 核对方式与理由 |
| --- | --- | --- |
| 名称 | 退运索赔材料传阅 | 仅用于记录展示，与业务授权无关 |
| 过期时间 | 设为材料复核期结束日 | 超过该时间链接无法使用，与样本未定日期区分 |
| QPM | 按参与人数设一个较小值 | 每用户每分钟最大访问次数，部分参数受版本限制 |
| 积分上限 | 按预估问答次数设一个上限 | 该链接产生的最大计费数据，费用归属团队 |
| 身份验证 | 填写第三方校验根地址 | 商业版范围，按返回 success 与 uid 判断 |
| 查看引用全文 | 按材料敏感度决定 | 引用片段与来源原文属发布参数，逐项确认 |

起点数值为本次假设试验设定，不属官方默认值。设定后与实际访问记录比较，观察是否触发限制。

## 容易做错的三处

1. 把链接标识或 authToken 当成业务授权。输入是分享链接与 authToken，比较对象是该链接对应材料的签署与核定状态，观察结果是链接可打开但材料仍为草稿。链接可用不表示退运确认或索赔受理已完成。
2. 把检索命中当成身份或权限过滤。输入是提问与检索结果，比较对象是结果条目所属数据集与访问范围，观察结果是命中条目与提问者无权查看的材料混在一起。相关度分数不承担实体隔离。
3. 把结果上报接口的调用当成扣款或结算已执行。输入是 responseData 中的 totalPoints 与 token，比较对象是实际余额变动记录，观察结果是上报请求发出但余额未变。上报接口无规定返回值，扣款需下游实现。

## 怎么确认配好了

1. 针对样本的交接请求，输入分享链接与 authToken，比较材料原文中的“待质检报告确认后补充”“以保险公司核定为准”与拟稿句中的“视为已完成退运确认与索赔受理”，观察是否出现草稿被表述为已完成。出现即说明分享入口被当作授权执行。
2. 针对样本材料，输入一条询问退运数量的问题，比较回答与材料原文，观察回答是否给出原文未载明的数量或金额。给出即说明回答超出材料范围，应记录为待核实。
3. 针对身份验证，输入 authToken 与校验根地址，比较返回的 success 与 uid 是否符合格式要求，观察失败分支是否提示错误。返回 success 为 true 且 uid 合规才允许继续；返回 false 时记录错误提示，不推断具体原因。

以上均为纸面核对与预期现象，未实际部署或测试。材料缺失的字段保持未知，待审核状态不构成操作权限，签署、核定与受理是三个不同事实。
