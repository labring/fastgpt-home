# 多仓分仓与库存同步的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
多仓分仓与库存同步的资料来自 WMS、OMS、ERP 库存与平台库存接口，更新频率为日或小时。分仓规则决定订单从哪个仓发货，库存同步表记录可售数量，调拨单与缺货预警反映仓间流转与缺口。这些资料在订单履约与售后答疑中支撑两类工作：核对某笔订单的应发仓与可售依据，以及判断售后请求涉及的库存状态。HTTP 模块在此承担向外部地址发送请求并解析响应的职责，请求可引用全局变量、系统变量与前方节点输出，返回值按 JSON path 提取。资料更新频率不改变本页的接口核对方式。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
外部接口契约决定地址、方法与字段结构，HTTP 模块按此发送请求，Params 多用于 GET，Body 多用于 POST/PUT，Headers 传递特殊信息。鉴权凭证通过安全配置注入，不写入公开样例。变量引用需逐项核对实际传入值，URL 与三类数据均可通过 {{}} 引用变量。测试模式下 chatId 与 responseChatItemId 不存在，调试空值不构成业务故障。返回值配置描述如何解析响应，输出类型选择字符串时会将对应 key 的值转为 JSON 字符串。

假设演练样本：供核对的材料原文为“2025 年 6 月 3 日华东仓分仓规则表第 4 行：SKU-A 可售 120 件，优先级 1；华南仓同 SKU 可售 35 件，优先级 2。”另一句为“同日缺货预警表记录 SKU-B 缺口 8 件，状态待处理。”拟稿句为“SKU-A 订单已按优先级 1 从华东仓发货，售后可按华东仓库存答复。”该拟稿句涉及主体、对象与状态，但材料未载明该订单实际路由结果与发货动作，属未获支持。

## 配置怎么定
配置围绕上述样本，仅列与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，选值理由与比较对象一并写明，不表示官方默认。

| 配置项 | 本次假设起点 | 核对方式与理由 |
| --- | --- | --- |
| 请求地址 | 外部接口文档给出的地址 | 地址可引用变量，与文档比对是否一致 |
| 请求方法 | 按外部接口契约选择 | 与文档标注的方法比对 |
| Headers 鉴权 | 安全配置注入凭证 | 核对注入来源，样例不写凭证 |
| Body 结构 | 按契约的 JSON 结构 | 与外部接口字段逐项比对 |
| 返回值 key | 按 JSON path 提取 | 与响应示例的实际层级比对 |
| 输出类型 | 字符串或对象 | 与下游节点所需类型比对 |

## 容易做错的三处
1. 将调试模式下 chatId、responseChatItemId 不存在当作业务故障。检查输入为测试模式请求，比较对象为文档说明的测试模式行为，现象为请求正常返回而无这两个字段。
2. 将返回值 key 写成接口未提供的路径。检查输入为样本响应结构与所配 key，比较对象为文档提取示例，现象为提取结果为空或与预期层级不符。
3. 将拟稿句中的“已按优先级 1 发货”当作已核实事实。检查输入为样本原文与拟稿句，比较对象为原文是否载明路由结果与发货动作，现象为原文未载明，判定为未获支持。

## 怎么确认配好了
1. 输入样本原文两句与拟稿句，比较拟稿句是否超出原文载明的可售数量与优先级，现象为拟稿句新增了发货事实，判定未获支持。
2. 输入一条假设请求，其 Body 引用变量 {{number}} 与 {{string}}，比较实际传入值与变量声明类型，现象为数字未加引号、字符串加引号，与文档示例一致即满足。
3. 输入假设响应与所配返回值 key，比较提取结果与响应层级，现象为 key 指向已存在路径时得到对应值；若 key 指向未提供路径，记录为空并保留为待核实，不推断为接口故障。

检索与相似度设置不构成权限或实体过滤，检索结果不代替授权。表单收集值，业务核验、审批、数据库写入与外部同步需各自的下游实现。空结果可用明确的纸面输入 [] 核对下游设计，不声称虚构规则检索必然返回空。跨不同向量模型的库不可共同关联，仅核对标识并排除不符合者。
