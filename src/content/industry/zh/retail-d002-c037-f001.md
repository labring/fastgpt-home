# 大促仓配排产的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

大促仓配排产围绕短期峰值产能与人车场安排展开，数据来源包括历史大促订单、平台活动报名、WMS产能与快递揽收能力。这些材料按场次和按日更新，订单履约与售后答疑环节需要把预测表、排班表、快递保障方案和异常日报串起来核对。HTTP 接口与外部系统在这一环承担的是把 FastGPT 编排结果送到外部业务服务、再把外部返回值带回对话的职责。材料本身只描述业务事实，接口调用是否被允许、表单是否已审批、外部系统是否已写入，都属于另一层事实，不能由检索命中或表单提交推断。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params、Headers、Body 三处均可通过 `{{}}` 引用全局变量、系统变量和前方节点输出，URL 同样可以引用变量。引用字符串时需要在 Body 中补 `""`，数字、布尔、数组和对象按 JSON 结构直接展开。返回值通过 JSON path 提取，输出类型选字符串时会把对应 key 的值转成 JSON 字符串。系统变量中 `chatId` 与 `responseChatItemId` 在测试模式下不存在，调试时出现的空值不能当成业务故障。`Authorization` 等鉴权凭证通过安全配置注入，公开样例不写入真实密钥。HTTP 模块只负责发出请求与解析响应，数据库写入、审批流转、外部同步需要外部服务自身实现，接口返回成功不代表业务动作已完成。

假设演练样本：某大促场次排产交接材料原文为「本次大促场次为 2025 年 6 月 18 日活动，仓库 A 的 6 月 17 日临时人员排班表已由仓库经理签字确认，快递保障方案中 6 月 18 日揽收车辆数为 12 辆，异常日报截至 6 月 16 日 18 时记录分拣线停机 1 次」。待判定拟稿句为「6 月 18 日揽收车辆已按保障方案全部到位」。该拟稿句把方案中的车辆数写成已到位事实，材料只证明方案中写了 12 辆，未提供到位确认记录。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 外部接口文档给出的地址 | 与接口文档逐字符比对，地址可含变量 |
| 请求方法 | 按外部接口契约选择 | 与接口文档声明的方法比对 |
| Headers 鉴权 | 通过安全配置注入 | 与密钥管理规范比对，公开样例不写真实值 |
| Body 结构 | 按外部接口契约的 JSON 结构 | 与接口文档字段逐项比对 |
| 变量引用 | 引用全局变量或前方节点输出 | 与实际传入值逐项比对，确认类型匹配 |
| 返回值提取 | 按 JSON path 提取目标字段 | 与接口响应示例比对路径与输出类型 |

以上数值为本次纸面演练的起点，不是官方默认值，比较对象是外部接口文档与本次材料原文。

## 容易做错的三处

1. 把方案中的车辆数当成已到位事实。输入是保障方案原文「6 月 18 日揽收车辆数为 12 辆」，比较对象是到位确认记录，若材料中不存在到位确认记录，则该拟稿句未获支持。
2. 把测试模式下的空 `chatId` 当成业务故障。输入是测试模式返回的空值，比较对象是正式会话中的 `chatId`，若测试模式下为空而正式调用中非空，则不属于业务故障。
3. 把 HTTP 返回成功当成外部业务动作已完成。输入是接口响应，比较对象是外部系统的业务状态记录，若外部系统无对应状态变更记录，则业务动作是否完成仍待核实。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句「6 月 18 日揽收车辆已按保障方案全部到位」，比较原文是否含到位确认记录，若原文只写车辆数而无到位确认，则该拟稿句未获支持。
2. 输入测试模式下 `chatId` 与 `responseChatItemId` 的空值，比较正式会话中同字段是否有值，若正式会话有值而测试模式为空，则确认该空值属于测试模式特性。
3. 输入 HTTP 响应与外部系统业务状态记录，比较两者是否指向同一业务动作，若响应成功而外部系统无状态变更记录，则业务动作完成情况仍待核实。
