# 大促仓配排产的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样
大促仓配排产围绕短期峰值产能和人车场安排展开，与多仓库存同步的日常均衡逻辑不同。主要资料来自历史大促订单、平台活动报名、WMS产能与快递揽收能力，日常处理大促预测表、人员排班、快递保障方案、异常日报。预测峰值、安排临时人员、协调快递车辆最耗时。这些资料每场大促更新，异常日报按日更新。资料主体是电商供应链、仓库经理与快递商务，出错会导致爆仓、发货超时、活动评分下降。检索环节需要面对同一场活动内多份互相引用的文档，以及售后答疑中用户对排产、揽收、超时责任的口头追问。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库由库、集合和数据三部分组成，最小搜索单位是库，集合仅用于分类管理，与搜索效果无关。知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联，只能核对标识并排除不符合者，不执行跨模型检索来比较漏召回。向量存储采用 PostgresSQL 的 PG Vector 插件，索引为 HNSW，MongoDB 的 dataset.datas 表存放原数据与 indexes 字段，一组数据可对应多个向量，命中同一组原数据时合并并取最高得分。检索链路包含问题优化、语义检索、全文检索、混合检索、图片检索、RRF 融合与 ReRank 二次排序，这些是可选路径，不代表每次请求全部执行；图片检索须有图像输入及相应模型能力，重排须具备模型并按设置启用。引用内容以数组输出，长度可以为 0，没有搜索到内容时输出链路仍走通。语义召回和相关度不负责权限或实体隔离，检索结果不构成授权依据。

## 配置怎么定
本次假设演练样本：某仓库一份《大促预测表》原文写“本次大促预计订单峰值集中在活动首日，临时人员排班覆盖首日与次日，快递保障方案按首日峰值向A快递申请加班揽收”。一条待判定拟稿句写“本次大促临时人员排班覆盖首日，A快递已确认加班揽收”。拟稿句与原文的差异在于排班覆盖范围与快递确认状态。下表为本次假设试验起点，不属官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联含预测表、排班、保障方案、异常日报且向量模型标识一致的库 | 逐库核对向量模型标识，排除不一致者 |
| 搜索模式 | 先按全文检索与混合检索各跑一轮 | 比较编号、日期、主体命中情况，再决定 |
| 引用上限 | 以 token 为单位，设一个覆盖完整段落的值 | 用长短不同的实际资料测试内容是否被截断，再调整 |
| 最低相关度 | 仅在语义检索或使用结果重排时生效，先标注相关与无关样本 | 观察过滤后引用是否仍含无关片段 |
| 问题优化 | 在连续追问、短问题场景开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 候选较多且已配置重排模型时启用 | 比较重排前后相关度得分与排序 |

## 容易做错的三处
1. 把跨向量模型的知识库一并关联。输入为两个向量模型标识不同的库，比较各自标识，若标识不一致仍尝试共同关联，则属配置错误，此时应排除不符合者并记录实际观察，不断言运行结果。
2. 把检索命中当作授权。输入为拟稿句“A快递已确认加班揽收”，比较原文“按首日峰值向A快递申请加班揽收”，原文只载明申请动作，未载明确认状态，拟稿句的确认结论未获支持。
3. 把最低相关度当作权限或实体过滤。输入为一条相似度较高的无关业务记录，比较该记录与当前授权范围，最低相关度是过滤阈值，不排除无关业务或未授权记录。

## 怎么确认配好了
1. 输入《大促预测表》原文与拟稿句“本次大促临时人员排班覆盖首日，A快递已确认加班揽收”。比较排班覆盖范围与快递状态两个字段。原文写覆盖首日与次日，拟稿句写覆盖首日，同字段取值互斥，构成矛盾；快递确认状态原文未载明，属未获支持。
2. 输入一条不含主体与日期的短问题，开启问题优化。比较优化后问题与原文主体、对象。若优化后主体被替换或日期被改写，则问题优化结果不可用于判定，需回到原问题核对。
3. 输入一个无匹配资料的纸面查询，预期引用内容为长度 0 的数组，核对下游链路是否仍走通。检索检查只记录观察与失败分支，不保证首条命中、全部召回或无关查询必为空，也不声称虚构规则检索一定返回空数组。
