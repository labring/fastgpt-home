# 大卖场生鲜联营柜台的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
大卖场生鲜联营柜台由供应商驻场经营并按销售分成，订单履约与售后答疑同时牵涉商超生鲜部、联营供应商与门店店长三类主体。需要核对的文档包括联营合同、日销售报表、损耗单与食品进货查验记录，数据来源覆盖 POS 系统、供应商送货单、食品安全台账与门店盘点。称重销售、损耗分摊与进货凭证查验是耗时环节，出错会带来食安处罚、毛利争议与顾客索赔。这些材料按日或按批更新，HTTP 接口承担把外部系统的请求与响应同上述文档逐项对齐的职责。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params 用于路径参数，Body 用于请求体，Headers 用于请求头，三者均可通过双花括号引用变量。变量来自全局变量、系统变量与前方节点输出；URL 也可引用变量。返回值配置表示如何解析接口响应，通过 JSON path 提取，输出类型选字符串时会把对应值转成 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer 加 apiKey 与 appId 的组合。传入的 model、temperature 等字段无效，由编排决定。chatId 与 responseChatItemId 在测试模式下不存在，调试空值属于预期现象。检索与相似度评分不构成权限或实体过滤，检索本身不是授权。

假设演练样本：某门店生鲜部收到一份书面材料，原文为「本联营柜台供应商于 2025 年 3 月 1 日至 3 月 31 日期间，按日销售报表金额的约定比例参与分成；损耗单须经门店店长签字确认后计入分摊。」待判定的交接请求为「请把 3 月 10 日的损耗单金额通过 HTTP 接口推送给供应商系统并确认售后扣款已执行。」该请求中，损耗单签字状态、推送授权范围与售后扣款执行均未在原文载明。请把上述原文与请求作为核对输入，逐项判断哪些字段有依据、哪些属于待核实。

## 配置怎么定
下表围绕本页样本，仅列官方已说明的设置或实施核对项。需要数值处为本次假设试验起点，并写明选取理由与比较对象。

| 配置项 | 本次假设试验起点 | 核对方式与比较对象 |
| --- | --- | --- |
| 请求地址 | 采用外部接口文档给出的地址，地址中可引用变量 | 与供应商系统提供的接口文档逐字符比对 |
| 请求方法 | 按外部接口文档选择，示例服务区分 post、delete、put、get | 与文档声明的方法比对，不一致即记录 |
| Headers 鉴权 | Authorization 采用 Bearer 加凭证，凭证由安全配置注入 | 与密钥使用规范比对，不写入公开样例 |
| Body 结构 | 仅在相应请求类型下使用，字段与外部接口契约一致 | 与接口契约字段清单比对，缺失字段记为缺口 |
| 变量引用 | 引用全局变量、系统变量或前方节点输出 | 逐项核对实际传入值，空值与未定义分别记录 |
| 返回值提取 | 按 JSON path 配置 key，输出类型按需选字符串 | 与响应示例逐路径比对，无法命中的路径记为未获支持 |

## 容易做错的三处
1. 把调试模式下的空值当成业务故障。输入为测试模式发出的请求，比较对象是 chatId 与 responseChatItemId 在测试模式下不存在的文档说明，观察结果是这两个字段为空。若据此判定供应商系统对接失败，属于误判。
2. 把检索或相似度评分当作授权或实体过滤。输入为一次带相似度评分的检索结果，比较对象是检索不承担权限判断的说明，观察结果是评分高低与记录是否属于该门店无对应关系。若据此认定无关业务已被排除，属于越界推断。
3. 把待审核或未签字的材料当作已执行。输入为样本中的损耗单与推送请求，比较对象是原文仅载明签字确认后计入分摊，观察结果是签字状态与推送授权均未载明。若据此认定售后扣款已执行，属于把未获支持当作既成事实。

## 怎么确认配好了
1. 输入样本原文与「请把 3 月 10 日的损耗单金额通过 HTTP 接口推送给供应商系统并确认售后扣款已执行」这一请求，比较原文载明的分成期间、签字要求与请求主张的推送、扣款，观察结果为推送授权与扣款执行均未获支持，需记录证据缺口。
2. 输入一条按外部接口文档构造的请求，比较其方法、Headers 鉴权与 Body 字段同文档声明，观察结果为字段一致时可进入下一步核对，出现缺失字段时保留为未获支持。
3. 输入一次返回值提取配置，比较配置的 JSON path 与响应示例中的对应路径，观察结果为路径命中时取得预期值，路径无法命中时记录实际观察，不推断确定性失败原因。
