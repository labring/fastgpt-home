# 大卖场生鲜联营柜台的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

大卖场生鲜联营柜台常由供应商驻场经营并按销售分成，订单履约与售后答疑因此同时牵涉商超生鲜部、联营供应商与门店店长。日常材料包括联营合同、日销售报表、损耗单与食品进货查验记录，数据来源覆盖 POS 系统、供应商送货单、食品安全台账与门店盘点。核对重量销售、处理损耗分摊、查验进货凭证是最耗时的环节，出错可能带来食安处罚、毛利争议与顾客索赔。对话日志与审计要围绕这些材料说明会话身份、运行详情与字段留存，不把日志存在等同于合规审计完成。

## 这些特征在「对话日志与审计」这一环带来什么约束

同一 chatId 对应一段会话，同一 dataId 对应其中一条对话。核对履约与售后记录时，须先结合 chatId 与 dataId 定位目标会话与目标对话，不把不同入口的会话混算。需要运行详情时按官方契约设置 detail，非流式结果保存在 responseData，流式结果通过 event 区分。接口实际返回哪些字段就以哪些字段为准，未返回的业务数据不能推定已完整留存。测试模式与正式调用的身份字段可能不同，须分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实。

假设演练样本。某门店生鲜部与驻场供应商就一批叶菜销售分成存在争议，需核对售后答疑会话。供核对的材料原文为：「联营合同约定叶菜按日销售报表金额分成，损耗单单独列示。」「2025 年 3 月 12 日日销售报表载明该柜台叶菜销售额 4,200 元。」「同日损耗单载明叶菜损耗 35 公斤，未载明损耗金额。」一条待判定的拟稿句为：「该供应商已确认 3 月 12 日损耗金额，同意按扣减损耗后金额分成。」材料只载明损耗重量，未载明损耗金额，也未载明供应商确认，该拟稿句缺少支持。

## 配置怎么定

下表围绕上述样本，列出与本功能、订单履约与售后答疑相关的官方已说明设置或实施核对项。

| 配置项 | 取值或状态 | 核对说明 |
| --- | --- | --- |
| appId | 假设演练样本中的应用标识 | 用于定位目标应用，与 chatId 配合核对会话 |
| chatId | 假设演练样本中的会话标识 | 长度小于 250，须自行确保唯一 |
| dataId | 假设演练样本中的对话标识 | 用于定位会话下具体对话 |
| detail | 本次假设试验起点设为 true | 选 true 是为取得 responseData 中间值，与 false 时仅返回 choices 的结果比较 |
| source | 假设试验起点设为 api | 用于获取通过 API 创建的会话，与页面会话区分 |
| loadCustomFeedbacks | 假设试验起点设为 true | 用于读取自定义反馈，与不读取时返回的 customFeedbacks 比较 |

## 容易做错的三处

1. 把损耗单载明的损耗重量当作损耗金额。材料原文只写「损耗 35 公斤，未载明损耗金额」，拟稿句却称「已确认损耗金额」。输入是损耗单原文，比较对象是「损耗金额」字段是否存在，观察结果是该字段未出现，判定为未获支持。
2. 把待审核的交接请求当作已获授权。若材料只显示某请求处于待审核，而拟稿句称供应商已确认，输入是请求状态文本，比较对象是「已确认」与「待审核」，观察结果是两者不同，判定为待核实。
3. 把检索命中当作权限或实体隔离依据。相似度分数只表示相关程度，不表示该记录属于当前主体或已获授权。输入是带 score 的 quoteList，比较对象是记录所属 datasetId 与目标范围，观察结果是范围不一致时须排除，不执行跨范围关联。

## 怎么确认配好了

1. 取假设演练样本的材料原文与拟稿句，输入为损耗单原文三句与拟稿句，比较「损耗金额」字段是否在原文出现，观察结果为原文未出现该字段，拟稿句判定为未获支持。
2. 取假设演练样本的会话请求，输入为 appId、chatId、dataId 与 detail=true，比较 responseData 中是否含目标对话的运行详情，观察结果为返回该对话的 moduleName、moduleType 与 runningTime，未返回时记录缺口。
3. 取假设演练样本的授权状态，输入为交接请求文本，比较「待审核」与「已确认」两种状态取值，观察结果为两者为互斥取值，请求处于待审核时不判定为已获授权。
