# 平台促销报名与价格管理的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

促销报名与价格管理围绕活动报名表、促销价审批单、库存锁定表、活动复盘表流转，核心数据是价格、库存与活动节奏。订单履约与售后答疑阶段，运营需要把报名记录、审批状态、锁库数量与成交价核对清楚。数据来源包括天猫营销后台、京东活动后台、ERP 库存与历史成交价，更新频率为周或每场活动。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params、Body、Headers 分别承载路径参数、请求体与请求头，均可通过 `{{}}` 引用全局变量、系统变量与前方节点输出，URL 同样可引用变量。chatId 与 responseChatItemId 在测试模式下不存在，调试空值不构成业务故障。返回值通过 JSON path 提取，输出类型选字符串时会将对应 key 的值转为 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId；传入的 model、temperature 等参数字段无效，由编排决定。authProxy 代理团队成员身份需团队所有者开启，代理身份仍需具备目标应用与会话权限。检索或表单只收集值，业务核验、审批、数据库写入与外部同步需要各自的下游实现。

## 配置怎么定

假设演练样本：某品牌销售计划员提交一份促销价审批单原文，内容为“活动对象：A 商品；报名渠道：天猫营销后台；促销价：99 元；库存锁定：200 件；审批状态：待审核；有效期：3 月 1 日至 3 月 7 日”。另有一条待判定的交接请求：“请通过 HTTP 接口把该审批单同步到 ERP 并锁定库存。”以下配置围绕该样本。

| 配置项 | 取值或核对内容 | 与样本的关系 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选择，地址可引用变量 | 需先确认 ERP 接口地址是否已提供 |
| Headers 鉴权 | Authorization 通过安全配置注入 | 凭证不写入公开样例 |
| Body 结构 | 仅在相应请求类型下使用，核对 JSON 契约 | 审批单字段需与 ERP 字段一一对应 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 促销价、库存锁定值逐项核对 |
| 返回值提取 | 按 JSON path 提取，输出类型可选字符串 | 核对 ERP 返回的锁定结果字段 |
| chatId 状态 | 测试模式下不存在，不作为业务判断依据 | 样本未提供 chatId，保持未知 |

## 容易做错的三处

1. 把审批单“待审核”当作已批准，直接触发同步请求。样本审批状态为待审核，未获授权执行。
2. 将检索或表单收集的促销价、库存值当作已核验数据写入 ERP。表单只收集值，业务核验与写入需下游实现。
3. 把 HTTP 模块返回值提取的字符串当作业务确认。返回值仅表示接口响应解析结果，不表示审批或锁库已完成。

## 怎么确认配好了

1. 输入样本审批单原文与交接请求，比较审批状态字段与授权边界。仅当审批状态明确为已批准且授权范围覆盖该对象时，才满足继续条件；待审核状态记录为未获授权。
2. 输入 Body 中引用的促销价与库存锁定值，比较 ERP 接口契约字段。仅当字段名、类型与取值逐项对应时，才满足请求构造条件；缺失字段记录为未获支持。
3. 输入 ERP 返回值，按 JSON path 提取锁定结果字段。仅当返回结构中存在对应字段且取值可解析时，才满足提取条件；返回为空或字段缺失时记录为待核实，不断言失败原因。
