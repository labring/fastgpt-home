# 平台商品标题与详情合规的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

平台商品标题与详情合规处理宣传真实性和资质展示，不处理包裹交付。主要材料来自平台规则中心、广告法合规清单、品牌素材库和质检机构报告，日常文档包括商品标题表、详情页素材、广告禁词清单和质检报告。订单履约与售后答疑环节需要把标题与详情中的宣传口径、资质编号和检测结论，与订单备注、售后工单中的实际描述对齐。资料更新频率为周和每次上新，本页不据此推导批量同步或实时触发机制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 为路径请求参数，Body 为请求体，Headers 为请求头，三者均可用 `{{}}` 引用全局变量、系统变量和前方节点输出。变量来自全局变量、系统变量、前方节点输出。系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值配置的是如何解析接口返回值，通过 JSON path 提取，输出类型选择字符串时会把对应 key 的值转成 json 字符串。对话接口使用 APIKey 鉴权，调用 `chat/completions` 时推荐在请求体传入 `body.appId`，也支持 `Authorization: Bearer <apiKey>-<appId>`。传入的 model、temperature 等参数字段无效，由编排决定。

假设演练样本：某商品运营提交一份待核对材料，原文为“本产品经某质检机构检测，报告编号 JC-2024-0317，检测项目为面料成分，结论为聚酯纤维 100%，报告日期 2024 年 3 月 20 日，有效期至 2025 年 3 月 19 日”。拟稿句为“本产品 100% 聚酯纤维，经权威机构检测认证”。待判定请求为：将该拟稿句中的成分结论与报告原文比对，确认是否可直接用于详情页。授权边界为：该材料仅用于标题详情合规核对，不构成对质检机构的资质认定，也不代表平台已批准该宣传。

## 配置怎么定

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| 请求地址 | 外部质检报告查询接口地址 | 按外部接口文档选择地址和方法，地址可引用已提供的变量 |
| 请求头 | `Authorization` 值为 `Bearer {{token}}` | 鉴权凭证通过安全配置注入，不写入公开样例 |
| 请求体 | 含报告编号与检测项目字段的 JSON | 仅在相应请求类型下使用，核对 JSON 结构与外部接口契约 |
| 变量引用 | 引用前方节点输出的报告编号 | 逐项核对实际传入值，确认与材料原文一致 |
| 返回值解析 | 提取结论字段，输出类型选字符串 | 按 JSON path 语法配置，核对提取结果与原文一致 |

上述起点为本次假设试验起点，选择理由是需要覆盖报告编号、检测项目和结论三类字段；比较对象为材料原文中的对应字段值。不把数据库内部实现抄成每页必配项。

## 容易做错的三处

1. 把检索或表单提交当成授权执行。输入为待判定拟稿句，比较对象为材料原文的授权范围，观察结果为拟稿句是否超出“仅用于标题详情合规核对”的边界。若超出，则记录为待核实，不认定平台已批准。
2. 把未载明的资质等级当作已确认。输入为拟稿句中的“权威机构”，比较对象为报告原文中仅出现的机构名称和报告编号，观察结果为原文未载明资质等级。缺失证据保持缺失。
3. 把测试模式下的空 chatId 当成业务故障。输入为测试模式下发起的一次请求，比较对象为文档说明的 chatId 在测试模式下不存在，观察结果为该字段为空属于文档已说明情形，不据此推断外部系统异常。

## 怎么确认配好了

1. 输入为假设样本中的报告原文和拟稿句，比较对象为原文结论“聚酯纤维 100%”与拟稿句“100% 聚酯纤维”，观察结果为两者成分结论一致；再比较拟稿句“经权威机构检测认证”与原文未载明认证字样，观察结果为该表述未获原文支持，记录为待核实。
2. 输入为一条引用报告编号的 HTTP 请求配置，比较对象为请求体中报告编号字段值与材料原文编号 JC-2024-0317，观察结果为两者一致；若不一致，则记录为输入差异，不推断外部系统返回结果。
3. 输入为一条返回值解析配置，比较对象为提取出的结论字段与原文结论字段，观察结果为字符串输出与原文一致；若解析结果为空，则记录为待核对，不认定外部接口无数据。检索与相关度不负责权限或实体隔离，缺失证据保持缺失。
