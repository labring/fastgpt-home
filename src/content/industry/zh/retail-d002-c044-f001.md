# 平台广告投放与站内流量的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

平台广告投放按流量和转化实时调价，数据来源包括巨量千川、京东快车、阿里妈妈与店铺成交数据，更新频率为日或小时。投放专员、品牌市场部与代运营投手日常处理投放计划、关键词报表、人群包说明与转化归因表。订单履约与售后答疑把退款、补发、物流异常等请求转成对外部系统的调用。HTTP 请求节点向指定地址发送请求，Params 用于路径参数，Headers 用于传递鉴权等特殊信息，Body 用于请求体，三者均可用 `{{}}` 引用全局变量、系统变量与前方节点输出。返回值通过 JSON path 提取，输出类型选字符串时会把对应 key 的值转成 json 字符串。对话接口以 APIKey 鉴权，appId 优先级为 `body.appId`、`<apiKey>-<appId>`、apikey 关联的 appId。`chatId` 与 `responseChatItemId` 在测试模式下不存在，调试时的空值不构成业务故障。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

接口调用只负责传递与取回数据。表单收集值，业务核验、审批、数据库写入与外部同步需要各自的下游实现。检索不是授权，相关度分数不承担权限或实体隔离。交互节点返回给外部调用方的 `interactive` 只含 `type` 与 `params`，`entryNodeIds`、`memoryEdges`、`nodeOutputs`、`nodeResponseId` 等内部运行态字段不返回。工作流遇到交互节点会直接返回，继续运行需按同接口再次发起会话，表单输入需把对象序列化成字符串作为 messages 内容，并保持 `chatId` 一致。文档列出的可选路径不表示每次请求全部执行。

假设演练样本：某投放专员在纸面上提交一条交接请求，材料原文为三句。其一，投放计划编号 AD-0715，投放期间 7 月 1 日至 7 月 31 日，状态为进行中。其二，关键词报表显示 7 月 10 日消耗 800 元，转化 12 单。其三，退款申请单 RF-2031 针对订单 SO-8842，申请时间 7 月 12 日，状态为待审核，未附审批结论。待判定的拟稿句为：该订单退款已执行，可同步至外部工单系统。判定需同主体、同期间、同一字段。退款申请单状态字段为待审核，与已执行属同字段互斥取值，拟稿句未获支持。签署、合作达成、合同生效是三个不同事实，此处均无证据。

## 配置怎么定

| 配置项 | 设定或核对内容 | 依据与比较方式 |
| --- | --- | --- |
| 请求地址 | 按外部接口文档填写，可引用变量 | 地址与文档一致，方法为 POST |
| Headers | 传递鉴权等特殊信息 | 凭证经安全配置注入，不写入公开样例 |
| Body | 仅在相应请求类型下使用 | JSON 结构与外部契约逐项核对 |
| 变量引用 | 全局变量、系统变量、前方节点输出 | 逐项核对实际传入值 |
| 返回值提取 | 用 JSON path 提取所需值 | 与接口响应示例比对 |
| 调试字段 | `chatId`、`responseChatItemId` | 测试模式下不存在，空值不判故障 |

本次纸面试验起点：把 `pageSize` 设为 10，理由是便于逐条核对会话列表，比较对象为响应中 `total` 与实际返回条数。该值为本次假设起点，非官方默认。

## 容易做错的三处

1. 把待审核状态当作已执行。输入为退款申请单 RF-2031 的状态字段，比较对象为同字段的互斥取值，观察结果是状态仍为待审核，拟稿句所述已执行未获支持。
2. 把检索结果当作授权依据。输入为一次带相似度的检索返回，比较对象为实际权限配置，观察结果是相似度分数不改变可访问范围。
3. 把调试空值当作业务故障。输入为测试模式下缺失的 `chatId`，比较对象为正式调用中传入的会话标识，观察结果是该字段在测试模式下本就不存在。

## 怎么确认配好了

1. 输入为假设样本三句原文与拟稿句，比较对象为退款申请单状态字段，观察结果为同字段取值互斥时拟稿句未获支持，证据缺口保留。
2. 输入为一条纸面检索返回，比较对象为权限配置，观察结果为相关度分数未产生实体或权限隔离效果。
3. 输入为一次空结果 `[]`，比较对象为下游设计，观察结果为下游按空结果处理，不推断虚构规则必然返回空数组。

跨不同向量模型的库不可共同关联，只核标识并排除不符合者，记录实际观察。
