# 平台店铺评价与体验分维护的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

评价维护关注售后履约完成后的消费者反馈，不直接决定活动价格。主要数据来源包括抖店体验分、天猫服务指标、京东售后评价与客服系统，日常文档为差评处理记录、体验分明细、服务诊断报告与整改台账。数据按日或周更新，HTTP 接口环节通常按单次请求核对，不据此推断批量同步或实时触发。

订单履约与售后答疑场景中，接口调用需要把订单号、售后状态、凭证链接等字段传给外部系统。这些字段来自前方节点输出或全局变量，接口本身不判断售后是否成立，也不改变订单状态。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params、Headers、Body 与 URL 均可通过 `{{}}` 引用变量。变量来自全局变量、系统变量与前方节点输出。系统变量包括 appId、chatId、responseChatItemId、variables、cTime 与 histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 提取，输出类型选择字符串时会将对应 key 的值转为 json 字符串。

对话接口使用 APIKey 鉴权，推荐在请求体传入 body.appId，也支持 `Authorization: Bearer <apiKey>-<appId>`。传入的 model、temperature 等参数字段无效，由编排决定。detail=true 时返回中间值，stream 模式下通过 event 区分。交互节点返回的 interactive 仅含 type 与 params，entryNodeIds、memoryEdges、nodeOutputs、nodeResponseId 等内部运行态字段不返回。

假设演练样本：某店铺运营在 2025 年 6 月 10 日整理一份差评处理记录，原文为“订单 A 于 6 月 3 日签收，6 月 5 日买家提交售后申请，客服于 6 月 6 日补充凭证链接，当前售后状态为待审核”。拟交接请求为“请通过 HTTP 接口把该订单售后状态更新为已完结，并同步至外部系统”。该请求涉及状态变更与外部同步，接口文档未说明此类业务动作由 HTTP 模块自动完成。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 外部接口文档给出的地址 | 与文档核对，地址可引用变量 |
| 请求方法 | 按外部接口契约选择 | 与文档核对，不凭经验指定 |
| Params | 按路径参数逐项填写 | 与接口文档的参数表比较 |
| Headers | Authorization 使用 Bearer 变量 | 与鉴权要求比较，凭证不写入样例 |
| Body | 按请求类型填写 JSON | 与接口契约比较字段与类型 |
| 返回值提取 | 按 JSON path 配置 key | 与响应示例比较提取结果 |

## 容易做错的三处

1. 把待审核状态当作已完结。样本中售后状态为待审核，拟交接请求要求更新为已完结。比较原文状态字段与请求目标值，二者不一致时请求缺少依据。
2. 把凭证链接当作售后成立证明。样本中客服于 6 月 6 日补充凭证链接，原文未说明凭证已通过审核。比较原文是否载明审核结论，未载明时该链接不构成售后成立证据。
3. 把 HTTP 接口调用当作外部系统同步完成。样本请求要求同步至外部系统，接口文档只说明发送请求与解析返回值，未说明同步结果。比较请求动作与文档说明范围，超出范围的部分属于未知。

## 怎么确认配好了

1. 输入样本原文与拟交接请求，比较原文售后状态字段与请求目标值。原文为待审核、请求为已完结时，判定为未获支持，记录证据缺口。
2. 输入样本原文，比较原文是否载明凭证审核结论。原文只写补充凭证链接、未写审核通过时，判定为待核实，不判定为否定。
3. 输入样本请求与接口文档说明，比较请求动作是否在文档说明范围内。文档只说明发送请求与解析返回值时，外部同步属于需另接系统实现的业务动作，不视为已执行。
