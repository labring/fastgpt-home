# 平台店铺评价与体验分维护的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

评价维护处理的是订单履约完成后的消费者反馈，与活动价格决策分开。日常材料包括差评处理记录、体验分明细、服务诊断报告与整改台账，更新频率为日或周。对话日志与审计这一环，实际核对的是售后答疑过程中产生的会话与对话记录，以及这些记录能否与业务材料对应。

## 这些特征在「对话日志与审计」这一环带来什么约束

会话由 chatId 标识，对话由 dataId 标识，两者属于不同层级，核对时必须同 appId、同 chatId 下取数。需要运行中间值时按官方契约设置 detail，非流式结果保存在 responseData 中。接口未返回的业务字段不能推定已完整留存。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某店铺客服主管在订单履约售后答疑中，需核对一条差评处理记录与对应会话。供核对材料原文为：“处理记录：订单 A 售后咨询已回复，处理人张明，状态为已回复。”“会话记录：chatId 为 C-001，dataId 为 D-009，客服回复内容为退换货说明。”待判定拟稿句为：“该订单已完成售后处理并关闭。”判定依据：材料仅载明已回复，未载明关闭动作或关闭时间，拟稿句超出材料范围。

## 配置怎么定

| 配置项 | 本页用途 | 核对方式 |
| --- | --- | --- |
| appId | 定位目标应用 | 与会话列表返回的 appId 一致 |
| chatId | 定位目标会话 | 长度小于 250，与业务记录逐一对应 |
| dataId | 定位目标对话 | 在对应 chatId 下唯一 |
| detail | 获取运行中间值 | 按官方契约设置，检查 responseData |
| responseChatItemId | 标记响应消息 ID | 在同一 chatId 下唯一 |
| loadCustomFeedbacks | 读取自定义反馈 | 按需设置，核对返回字段 |

## 容易做错的三处

1. 把会话列表中的 chatId 与对话 dataId 混用。输入：会话列表返回 chatId 为 C-001；比较：与业务记录中的对话标识比对；观察：若业务记录写的是 dataId，则不能以 chatId 替代。
2. 以相似度分值推断记录归属。输入：quoteList 中 score 为 0.89；比较：与业务归属字段比对；观察：分值不构成权限或实体过滤，归属仍待核实。
3. 把已回复状态写为已关闭。输入：材料原文“状态为已回复”；比较：拟稿句“已完成售后处理并关闭”；观察：关闭动作与时间未载明，拟稿句未获支持。

## 怎么确认配好了

1. 输入：材料原文两条与拟稿句一句；比较：拟稿句所述关闭动作与材料载明状态；观察：材料未载明关闭，判定为未获支持。
2. 输入：chatId 为 C-001、dataId 为 D-009；比较：两者层级与业务记录字段；观察：若业务记录仅写 dataId，则 chatId 不能替代该标识。
3. 输入：responseData 返回的模块字段；比较：业务方案要求的留存字段；观察：缺失字段记录为缺口，不推定已留存。
