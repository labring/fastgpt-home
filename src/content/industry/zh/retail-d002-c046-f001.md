# 平台类目资质准入的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

类目准入发生在商品上架与店铺入驻之前，核对对象是主体资质与授权链本身。营业执照确认经营主体，商标注册证确认权利归属，品牌授权链确认从权利人到入驻主体的逐级许可，行业许可证确认特定类目的经营资格。这些材料不定期更新，每次入驻都要重新收集。订单履约与售后答疑环节出现的问题，通常来自资质状态与外部系统记录不一致：招商页面展示的准入要求、公示系统里的登记状态、许可证系统里的有效范围，三者可能处于不同阶段。HTTP 接口在这一环承担的工作是把外部系统的查询结果取回，供人工比对，取回动作本身不改变任何资质状态。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP模块发送请求，Params、Body、Headers及URL可用 `{{}}` 引用全局变量、系统变量或前方节点输出。响应按JSON path提取，选字符串输出时对应值转为json字符串。chatId与responseChatItemId是会话系统变量，测试模式下不存在；外部资质接口字段应按自己的契约核。FastGPT对话API的model、detail、authProxy等规则仅适用于该API，不套成外部查询接口参数。检索相关度不能替代主体或权限核验。

假设演练样本：某入驻专员在订单履约与售后答疑流程中，需要核对一份授权材料。供核对的材料原文为：「授权方：某某品牌管理有限公司；被授权方：某某商贸有限公司；授权品牌：某某；授权类目：家用电器；授权期限：2024年1月1日至2026年12月31日；本授权书自双方盖章之日起生效。」另一份营业执照原文为：「名称：某某商贸有限公司；统一社会信用代码：略；登记状态：存续；经营范围：家用电器销售。」待判定的拟稿句为：「该店铺已取得家用电器类目的完整授权，可直接上架。」判定所需信息包括授权链是否逐级完整、被授权方名称与营业执照主体是否一致、授权期限是否覆盖拟上架期间。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址 | 外部系统查询接口地址，通过变量引用 | 地址按外部接口文档确定，比较对象为文档给出的正式地址 |
| 请求方法 | 按外部接口文档选择 | 与文档标注的方法逐项比对，方法不符时请求结果未知 |
| Headers 鉴权 | 通过安全配置注入凭证 | 凭证不写入公开样例，比较对象为鉴权是否生效 |
| Body 结构 | 按外部接口契约构造 JSON | 字段名与类型逐项比对，引用字符串时加引号 |
| 返回值解析 | 按 JSON path 提取目标字段 | 比较对象为响应中的实际字段路径 |
| 输出类型 | 字符串 | 需要拼接提示词时选字符串，比较对象为下游节点的输入格式 |

## 容易做错的三处

1. 把接口取回的材料内容当成资质已核准的结论。输入是 HTTP 模块返回的字段值，比较对象是材料原文中的主体、对象、状态与有效范围，观察结果是拟稿句是否超出原文支持的范围。样本中授权期限截至 2026 年 12 月 31 日，拟上架期间若超出该日期，拟稿句即缺少依据。
2. 从外部响应缺少chatId或responseChatItemId反推调试模式或业务故障。应直接核HTTP节点运行模式和可引用系统变量，供应商响应按其契约另核；不能把会话变量当成该接口必须返回的字段。
3. 用相似度分数推断资质归属。输入是检索返回的 score 字段，比较对象是材料原文中的被授权方名称，观察结果是分数高低是否被当作主体一致的证据。分数只反映文本相关程度，主体是否一致仍需比对原文。

## 怎么确认配好了

1. 输入两份原文与拟稿句，分别核主体名称、授权链、拟上架期间及双方盖章事实。名称在样本中可对应，但完整授权链、上架期间、盖章完成及平台上架依据未给；“完整授权、可直接上架”待核，不只凭期限和名称放行。
2. 待实际运行时分别记录测试与正式调用的节点上下文、变量来源及外部响应。按文档核测试模式下两项身份变量不存在；外部响应是否含同名字段由接口契约决定，不能据此确认运行模式或业务结果。
3. 若流程另接知识库检索，分别核其相关度及原文被授权方名称，不能用得分替代主体比对。外部资质接口是否有score字段及其含义仍需真实契约，当前不预设。
