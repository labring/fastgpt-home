# 平台类目资质准入的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

平台类目资质准入发生在商品上架或店铺入驻之前，核心材料是营业执照、商标注册证、品牌授权链和行业许可证。订单履约与售后答疑阶段的对话，围绕资质补正进度、授权链缺口、许可证匹配类目等问题展开。这类对话的数据有三个特征影响本页实施。其一，同一入驻主体的材料常由招商运营、入驻专员和品牌方渠道经理分别提供，对话身份必须结合 chatId 与业务记录核对，不同入口的会话不能混算。其二，资质材料状态会变化，对话日志记录的是某次问答的时点内容，日志存在不等于材料已通过审核。其三，审计对象是对话本身，对账、留存与合规要求由完整业务方案另行落实。

## 这些特征在「对话日志与审计」这一环带来什么约束

结合 chatId 核对目标对话与业务记录，是审计的第一步。通过对话接口获取运行详情时，按官方契约设置 detail，并在 responseData 中查看模块状态与完整结果；非 stream 模式结果保存在 responseData，stream 模式通过 event 区分。核对日志与接口实际返回字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，需分别核对输入、历史与返回内容。检索与相关度分数不承担权限或实体隔离职责，检索库同向量模型要求不能扩展为工商网站或其他外部系统也要同模型。

假设演练样本：某入驻专员提交一份品牌授权链材料，原文为“授权方甲，被授权方乙，授权品牌丙，授权期限自二零二五年一月一日至二零二五年十二月三十一日，授权范围限于中国大陆线上销售”。同日一条拟稿句为“乙已获得丙的完整授权，可立即上架全部类目”。待判定点：授权范围是否覆盖“全部类目”，授权期限是否支持“立即上架”的表述。

## 配置怎么定

| 配置项 | 官方已说明设置或实施核对项 | 与样本的关联 |
| --- | --- | --- |
| chatId | 非空字符串时使用数据库会话，长度小于 250 | 核对样本对话归属同一入驻主体 |
| detail | 设为 true 返回中间值与完整结果 | 查看授权链问答的模块响应 |
| responseChatItemId | 传入后作为响应消息 ID 存入数据库，当前 chatId 下需唯一 | 标记样本对话的响应记录 |
| stream | 区分 event 与 responseData 的取值方式 | 按实际调用方式核对返回内容 |
| authProxy | 需团队所有者开启，代理身份仍需目标应用与会话权限 | 确认交接操作的授权边界 |
| loadCustomFeedbacks | 可选，读取自定义反馈 | 核对样本对话的反馈记录 |

## 容易做错的三处

1. 把日志存在当成资质已通过。样本中授权链材料仅记录授权范围限于线上销售，拟稿句却称可上架全部类目。输入是拟稿句与材料原文，比较授权范围字段，观察结果是两者不一致。
2. 把检索分数当成权限过滤。输入是一条查询与返回的 score，比较该分数与业务授权记录，观察结果是分数不包含主体或类目权限信息。
3. 把测试模式身份字段与正式调用混用。输入是两次调用的 appId 与 chatId，比较两次的身份字段，观察结果是两者可能不同，需分别核对。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较授权范围与授权期限字段，拟稿句出现“全部类目”或“立即上架”而原文未载明时，判定为未获支持。
2. 输入一条查询与返回的 quoteList，比较 score 与业务授权记录，score 存在不表示该记录已获授权，需另行核对主体与类目。
3. 输入两次调用的 appId 与 chatId，比较身份字段与历史内容，两者不一致时分别记录，不合并计算。
