# 平台退款退货处理的订单履约与售后答疑：工作流编排

## 这个品类的数据长什么样

在平台退款退货处理的订单履约与售后答疑中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

普通平台退款应先区分申请提出、退件到达、质检材料和退款审批分别说明什么。可用自拟文本写“申请及退货物流单已提供，尚无仓库接收和付款退款记录”，让表单收集咨询范围及原文。比较后续输入，确认申请没有被改成已退款，运输资料也没有变成商品检验结论。收到了哪些文件与完成了哪些操作，需要分别保留证据。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 四类证据 | 申请、物流、质检及审批分别记录 | 资料接收没有被改写为操作完成 |
| 表单输入 | 已提供申请与物流，收货退款尚缺 | 下游准确接收当前证据状态 |
| 路径错接 | 补收货选择误到退款审批路线 | 核连接及接收值，修复后重测 |
| 复测关联 | 新增证据与本次订单及原咨询 | 最终引用对应同一处理对象 |
| 实际退款 | 获授权操作返回的真实记录 | 审批、付款与办结状态分别核验 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

当咨询要求决定下一步，可让负责人选择补仓库接收材料、核质检依据或查看退款审批，再逐项测试真实去向。若选择补收货却进入批准退款的处理路径，应检查连接和接收值，不能以流程继续运行掩盖错接。即使收货记录已有，也仍需区分实物到达、商品状态及审批结果；人员选项不会自动完成责任认定或授予退款权限。 可再测试审批原文“待核”在传值中丢失的情况：申请已提交，传给答复步骤的却只剩审批标题。对照完整原句与接收文本，找出遗漏位置，补回状态后重新询问退款进度；即使资料传递已修正，款项处理仍须另看支付侧的对应记录。

## 怎么确认配好了

补齐资料后复测原咨询，逐段核查新材料在提交、后续接收和最后答复中的对应关系。需要实际退款时，应由获授权的业务操作返回真实记录，再核其与本次订单的关联；审批文字不能单独证明付款已执行。若接口没有成功或未取得操作凭证，答复应保留未确认状态，不能用表单完成、节点执行或一段生成说明宣布售后已经办结。
