# 快递面单与揽收交接的订单履约与售后答疑：多轮对话与提示词

## 这个品类的数据长什么样

快递交接发生在包裹离仓节点，核心是承运商扫描责任。这个品类的资料以电子面单、交接清单、揽收扫描记录、异常件登记为主，来源是快递系统、WMS发运、承运商账单。资料按批按日更新，本页功能不依赖更新频率本身，依赖的是每批资料里主体、对象、状态是否写清。

对多轮对话与提示词来说，这意味着：模型回答发货超时、丢件争议、虚假发货这类问题时，必须能区分面单已打印、包裹已交接、揽收已扫描三种不同状态。三种状态在资料里是不同字段，不能互相替代。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

提示词需要写明资料范围、回答任务和缺证据时的处理方式，不让模型补写业务事实。历史记录要核对实际带入的上下文，区分新会话和继续会话的输入。问题优化只在知识库连续对话场景核对指代消除与问题扩展，不假设所有短问题都适用。模型与长度要核对模型支持的上下文和回复设置。回复格式按后续承接选择，选择 json_schema 时填写对应格式要求并验返回结构。

检索与相似度不承担权限或实体隔离。知识库搜索返回的 quoteList、score 只是召回结果，不代表某个包裹、某个网点或某条授权记录可用。交互节点返回的 interactive 是展示配置，只包含 type 和 params，表单收集值不等于业务已核验、已批准或已写入。

假设演练样本

供核对的材料原文（假设）：「电子面单 SF-0001 于 2025-03-01 打印，交接清单列明该单已交承运商网点 A。揽收扫描记录截至 2025-03-02 未出现 SF-0001。异常件登记无该单条目。」

一条待判定的拟稿句：「SF-0001 已由网点 A 揽收，属正常在途。」

判定：材料只支持「已打印、已列入交接清单」，揽收扫描记录未出现该单，异常件登记无条目。拟稿句把未获支持的状态写成已发生，不能采用。缺证据部分保留为待核实。

## 配置怎么定

| 配置项 | 本页取值或核对方式 | 依据与比较方法 |
| --- | --- | --- |
| AI 模型 | 选择支持所需上下文长度的模型 | 弹窗显示最大上下文与工具调用能力，按本页长对话需求比较 |
| 记忆轮数 | 本次假设试验起点取较小轮数 | 客服类应用通常保留少量历史轮数；与不传历史的新会话输入比较 |
| 回复上限 | 打开并按回答长度需要调节 | 设置过低会截断；与本页拟稿句长度比较 |
| 温度 | 取偏低值 | 客服、知识库问答建议偏低；与发散写作场景比较 |
| 回复格式 | 普通问答保持默认 | 仅当后续节点需读取固定结构时改用 json_schema 并填写格式要求 |
| 多模态识别 | 按模型能力决定是否开启 | 弹窗只显示模型支持的媒体类型；图片检索须有相应图像输入及模型能力 |

## 容易做错的三处

1. 把「已列入交接清单」写成「已揽收」。输入是材料原文与拟稿句，比较的是揽收扫描记录字段，观察结果是扫描记录未出现该单时拟稿句仍称已揽收。
2. 把知识库搜索返回的 score 当成权限过滤。输入是 quoteList 与 score，比较的是资料里有无授权字段，观察结果是 score 高低与授权状态无对应关系。
3. 把交互节点的表单收集当成业务已执行。输入是 interactive 的 type 与 params，比较的是资料里有无核验、批准或写入记录，观察结果是表单值存在但下游业务状态未变。

## 怎么确认配好了

1. 输入假设样本的材料原文与拟稿句，比较拟稿句是否与揽收扫描记录字段一致，观察结果为拟稿句被判定为未获支持、缺口保留。
2. 输入明确纸面空结果 []，比较下游承接设计是否按空结果分支处理，观察结果为下游不产生虚构条目。
3. 输入同一批资料中两个不同向量模型的库标识，比较标识是否一致，观察结果为标识不符者被排除，记录实际观察，不执行跨模型检索比较漏召回。
