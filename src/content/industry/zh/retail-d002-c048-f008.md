# 快递面单与揽收交接的订单履约与售后答疑：工作流编排

## 这个品类的数据长什么样

在快递面单与揽收交接的订单履约与售后答疑中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

快递售后需要区分面单生成、列入交接清单和承运商扫描记录。自拟输入可写“包裹已在交接清单列明，尚未取得相应揽收扫描依据”，用来检查流程能否保留当前资料状态。表单提交后，比较接收步骤是否仍把这两项情况分开；清单列名不能直接写成承运商已经接收，寄件方的准备记录也不能代替后续运输或妥投凭证。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 清单与扫描 | 交接清单已列，揽收依据尚缺 | 接收值没有把列名改成已接收 |
| 包裹身份 | 本次包裹及原咨询范围 | 没有混入其他批次记录 |
| 错路取证 | 查揽收却只返回面单文字 | 检查连接、映射及实际收到的来源 |
| 补记录复测 | 对应包裹和时间的扫描或交接资料 | 最终答复按各段证据保留缺项 |
| 物流操作 | 补发、改派等真实业务记录 | 与资料接收和对话结束分开核验 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

客户追问包裹位置时，可设计补承运商记录、核寄件方交接资料或交实际物流负责人的选择。逐条测试目的地和传入的包裹资料身份，避免把另一批次扫描内容加入解释。若选择查揽收却返回面单原文，应回查连接和输入映射，不能用已有文字填满答复就算查到了新状态；人工选择本身也不能确认包裹丢失或责任归属。 当交接清单列有包裹，但扫描记录中找不到对应对象时，两个步骤的证据并不一致。应核对面单身份、交接记录及扫描所覆盖的范围，交给实际经办人确认差异；在扫描依据补齐前，答复只能说明清单记载，不能将其直接写成承运方已经揽收。

## 怎么确认配好了

取得补充记录后重复原问题，核对记录对应的包裹与时间范围，再查最后答复引用了什么。扫描、交接和客户签收分别按实际证据说明，缺少哪一段仍要列明。若需补发、赔付或改派，应另有业务确认、授权接口和真实操作结果；工作流接到资料或完成对话，不等于运输状态已更新，更不能作为售后责任已经处理完的证明。
