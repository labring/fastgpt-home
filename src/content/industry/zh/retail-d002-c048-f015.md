# 快递面单与揽收交接的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

快递面单与揽收交接发生在包裹离仓节点，核心是承运商扫描责任。电子面单、交接清单、揽收扫描记录、异常件登记构成主要文档集合，来源包括快递系统、WMS发运与承运商账单。每批与每日更新意味着检索时必须按批次或日期限定范围，否则同一运单号在不同批次的状态可能被混用。本页只处理订单履约与售后答疑中的知识库检索与召回，检索结果与表单收集的值不构成授权，业务核验、审批、数据库写入与外部同步需要各自的下游实现。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联；应先核标识并排除不符合者，不执行跨模型检索来比较漏召回。引用内容以数组输出，长度可以为 0，即使没有搜索到内容，输出链路也会走通。搜索模式需按测试问题在语义、全文与混合检索之间比较，不预设一种模式适合全部资料。最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展。检索是召回，不承担权限或实体隔离。

假设演练样本：材料原文为「2025年3月10日发运批次B-0310，承运商为甲网点，交接清单列明包裹12件，揽收扫描记录显示当日扫描11件，异常件登记记录1件外包装破损待确认。」待判定拟稿句为「该批次12件已全部由甲网点揽收完成。」判断所需主体为批次B-0310与甲网点，对象为12件包裹，状态为扫描11件与异常1件，有效范围为2025年3月10日。拟稿句与材料原文在同主体、同期间、同字段上取值互斥，属于未获支持。

## 配置怎么定

| 配置项 | 本页取值或核对动作 | 依据与说明 |
| --- | --- | --- |
| 关联知识库 | 选择电子面单、交接清单、揽收扫描记录、异常件登记所在库，核对向量模型标识一致 | 节点可关联相同向量模型的知识库；跨模型不共同关联 |
| 搜索模式 | 对样本问题分别以语义、全文、混合检索比较 | 编号与批次类查询可优先全文或混合，自然语言问法可优先语义 |
| 引用上限 | 本次假设试验起点设为覆盖一条完整交接清单所需的 token 量，与长短不同的实际资料比较后再调整 | 单位为 token，用于控制引用内容长度，非官方默认值 |
| 最低相关度 | 先标注样本中相关与无关片段，再设阈值 | 仅在语义检索或结果重排时生效 |
| 问题优化 | 对「该批次扫描情况如何」这类短问题比较优化前后主体是否被改错 | 用于指代消除与问题扩展，会增加一次模型调用 |
| 重排 | 具备重排模型且按设置启用时，对候选文本二次排序 | 未启用时该路径不执行 |

## 容易做错的三处

1. 把检索命中当作授权。输入为样本原文与拟稿句，比较检索结果是否包含授权字段，观察结果是引用内容仅含扫描与异常记录，未含审批或放行字段，拟稿句仍属未获支持。
2. 跨向量模型共同关联。输入为两个向量模型标识不同的库，比较标识是否一致，观察结果是标识不符者被排除，记录实际观察，不断言漏召回或冗余。
3. 把待确认当作已完成。输入为异常件登记中「外包装破损待确认」，比较状态字段取值，观察结果是该件状态为待确认，拟稿句的「全部揽收完成」与同字段取值互斥。

## 怎么确认配好了

1. 输入样本原文与拟稿句，比较拟稿句主体、对象、期间、字段是否与原文一致，观察结果是同字段取值互斥时判定为未获支持，待核实项保留为缺口。
2. 输入一条无匹配内容的纸面查询，比较引用内容数组，观察结果为长度 0 时下游链路仍走通，不声称虚构规则检索一定返回空数组。
3. 输入含图像与文本的查询，比较是否配置视觉模型或支持图片的向量模型，观察结果为相应路径按能力执行，未配置时该路径不执行，不保证首条命中或全部召回。
