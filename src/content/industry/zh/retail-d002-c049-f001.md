# 批发市场档口交易的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

批发市场档口交易零散，现场议价与托运安排占去大量时间，进货单、手写销售单、摊位租赁合同、货款收据分散在纸质与聊天记录里。订单履约与售后答疑要处理的核心问题，是把这些材料中的主体、对象、状态与有效范围，通过 HTTP 请求送到外部系统，并核对返回结果。档口交易依赖现场议价，单据往往缺少统一编号，HTTP 模块的变量引用与返回值提取因此成为核对链条的关键环节。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params、Headers、Body 三处均可用 `{{}}` 引用全局变量、系统变量与前方节点输出，URL 同样可以引用变量。系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 或 JS 对象取值规则提取，输出类型选择字符串时会把对应 key 的值转成 json 字符串。对话接口调用时推荐在请求体传入 body.appId，鉴权也可用 Authorization: Bearer <apiKey>-<appId>，appId 优先级为 body.appId、<apiKey>-<appId>、apikey 关联的 appId。传入的 model、temperature 等参数字段无效，由编排决定。detail=true 时非流式结果保存在 responseData，可手动计算 tokens。

假设演练样本：某档口老板与采购商约定，2025 年 3 月 12 日交付一批货，采购商已通过微信支付部分货款，剩余尾款待托运单签收后结清。现有材料原文两句：「3 月 12 日装车，运费由采购商承担。」「尾款在托运单签收后三日内支付。」一条待判定的拟稿句：「采购商已结清全部货款，档口可安排发货。」核对对象为该拟稿句与上述材料原文，判断拟稿句是否与原文一致。原文只说明尾款支付条件，未载明已结清，拟稿句属于未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求方法 | POST | 与外部订单接口文档一致，比较实际文档标注的方法 |
| 请求地址 | 外部接口文档给出的地址 | 地址可引用变量，比较文档地址与配置值 |
| Headers | Authorization: Bearer {{token}} | 鉴权凭证通过安全配置注入，比较是否泄露到公开样例 |
| Body | 含订单对象与操作类型的 JSON | 仅在相应请求类型下生效，比较 JSON 结构与接口契约 |
| 返回值提取 | 按 JSON path 提取订单状态字段 | 比较提取结果与响应原文对应字段 |
| 变量来源 | 前方节点输出与全局变量 | 逐项核对实际传入值，比较配置引用与节点输出 |

## 容易做错的三处

1. 把测试模式下不存在的 chatId 或 responseChatItemId 空值当成业务故障。检查方式：输入测试模式请求，比较返回中是否出现这两个字段，观察为空时是否被误判为失败。
2. 把 similarity 或 score 当成权限或实体过滤条件。检查方式：输入一条与档口订单无关的查询，比较返回结果是否仍包含该记录，观察是否被错误排除或错误纳入。
3. 把待审核或待签收状态当成已完成。检查方式：输入拟稿句「采购商已结清全部货款」，比较材料原文，观察原文是否载明结清事实，未载明时记录为未获支持。

## 怎么确认配好了

1. 输入假设样本中的材料原文与拟稿句，比较拟稿句是否与原文一致，当原文未载明结清时，判定为未获支持，不判定为矛盾或否定。
2. 输入一条含订单状态的接口响应，按配置的 JSON path 提取状态字段，比较提取值与响应原文对应字段，当两者一致时视为提取配置生效。
3. 输入一条不含订单信息的查询，观察返回结果是否包含无关记录，当返回为空或仅含明确无关项时，记录实际观察，不保证无关查询必为空。
