# 批发市场档口交易的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

批发市场档口交易零散，依赖现场议价和托运，进货单、手写销售单、摊位租赁合同、货款收据分散在不同环节。订单履约与售后答疑中，一次对话可能同时涉及开单数量、托运安排和尾款催收，日志必须能按 chatId 定位到具体会话，再按 dataId 定位到单条对话。数据更新为日、每单，日志核对以单笔业务为粒度，不按批量口径推定。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话接口中，chatId 非空时从数据库取会话，messages 最后一个内容作为用户问题，其余 message 被忽略；chatId 不传时完全由 messages 构建上下文。responseChatItemId 在当前 chatId 下需唯一。detail=true 时返回中间值，非 stream 模式结果保存在 responseData，stream 模式通过 event 区分。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：档口老板与采购商就一批货款收据产生售后询问。供核对的材料原文为：“2025年3月12日手写销售单，货号A-17，数量30件，单价45元，合计1350元，采购商已提货。”“2025年3月14日微信收款记录，金额800元，备注尾款部分。”“摊位租赁合同期限2025年1月1日至2025年12月31日。”待判定的拟稿句为：“该笔货款已于3月14日结清。”判定需同主体、同期间、同一字段：销售单合计1350元与收款800元为同笔业务的金额字段，二者不一致，拟稿句未获支持。摊位租赁合同期限与货款结清无关，不构成证据。

## 配置怎么定

| 项目 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| chatId | 假设起点为“stall-20250312-01” | 长度小于250，与业务单号对应；比较不同入口会话是否混入同一chatId |
| responseChatItemId | 假设起点为“resp-20250314-01” | 需在当前chatId下唯一；比较重复请求是否复用同一值 |
| detail | 假设起点为true | 需核对responseData中间值；比较false时是否缺失模块状态 |
| stream | 假设起点为false | 便于保存完整响应；比较true时event区分是否影响日志留存 |
| source | 假设起点为api | 获取API创建的会话；比较页面会话是否被排除 |
| loadCustomFeedbacks | 假设起点为true | 读取自定义反馈；比较false时反馈字段是否缺失 |

以上均为本次假设试验起点，非官方默认值。配置项只涉及对话接口与对话CRUD已说明字段，不涉及数据库内部实现。

## 容易做错的三处

1. 把 chatId 不传时的 messages 构建上下文，当成已从数据库取会话。检查：输入同一 chatId 与不传 chatId 两次请求，比较返回的 historyPreview 是否一致，不一致说明上下文来源不同。
2. 把 detail=false 的响应当作完整运行详情。检查：输入 detail=false 与 detail=true 同一问题，比较 responseData 是否存在，缺失即未返回中间值。
3. 把相似度分数当作权限或实体过滤。检查：输入同一查询，比较 quoteList 中 dataset_id 是否均为有权访问的库，出现无权库即越界。

## 怎么确认配好了

- 验证一：输入假设样本原文与拟稿句“该笔货款已于3月14日结清”，比较销售单合计1350元与收款800元是否同字段，若不一致则拟稿句未获支持，需记录缺口。

- 验证二：输入 chatId“stall-20250312-01”与 responseChatItemId“resp-20250314-01”，比较同一 chatId 下是否重复，重复则唯一性不满足。

- 验证三：输入 detail=true、stream=false，比较 responseData 是否含模块状态与完整结果，缺失则中间值未返回，需核对请求参数。

空结果承接可用纸面输入[]核对下游设计，不声称虚构规则检索一定返回[]。跨模型不可共同关联，先核标识并排除不符合者。图片检索须有相应图像输入及模型能力，重排须具备模型且按设置启用。检索检查只写观察和失败分支，不保证首条命中或全部召回。
