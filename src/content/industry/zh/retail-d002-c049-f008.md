# 批发市场档口交易的订单履约与售后答疑：工作流编排

## 这个品类的数据长什么样

在批发市场档口交易的订单履约与售后答疑中，本页说明FastGPT的工作流编排如何衔接资料。档口履约答疑先核留货、提货人与交接记录，分别选择补身份或查交付资料。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟档口条写货已留待取、提货人仍需核对，旁边另档口便笺记某人已经领走。工作流先收本次档口与货品，再传递原条及身份缺项，可分别衔接补提货资料或查询交接。留货是纸面安排，不能说明实际库存已锁定；另一档口的领取也不属于本件。路径应把本条对象和待核状态带到下一环，不能由图上有分支推人员已验证。

## 配置怎么定

| 档口履约路径 | 自拟状态 | 核对动作 |
| --- | --- | --- |
| 留货条 | 待取安排 | 非交付凭证 |
| 提货人 | 身份待核 | 保留缺项 |
| 邻档口 | 另件领取 | 核对象 |
| 分支承接 | 本条与缺项 | 对实际输入 |
| 真实交接 | 业务另验 | 权限及凭证 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

留货冒交付时，核本件真实交接；他档口领取串入时，核货品与档口身份；身份待核却回复可放货时，对照缺项与实际授权依据。三处分别查阶段、对象和放行依据，连接状态不能补证。

## 怎么确认配好了

验收比较入口原条、分支接收和答复，分别问货留在哪、谁待核及是否有本件交接。补证后只更新对应项，真实库存占用、发货与交接仍要业务系统权限及凭证。流程运行不自动安排提货。 待领货单与领取人确认材料分开归档，下一次补件时先核档口、货物及本次领取事项，再判断是否可交接。

| 材料背景 | 适用范围 |
| --- | --- |
| 文档类型 | 进货单、手写销售单、摊位租赁合同、货款收据 |
| 候选来源 | 批发市场行情、档口库存、微信收款、物流托运单 |
