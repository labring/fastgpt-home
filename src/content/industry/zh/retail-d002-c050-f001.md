# 投诉举报与监管回复的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
投诉举报与监管回复围绕平台或监管机关的正式程序展开，材料以投诉工单、监管询问函、订单证据、整改报告为主。数据来源包括 12315 平台、平台投诉中心、客服聊天与订单系统。与售后维修补寄相比，本类工作要产出可提交的正式证据与整改文字，因此每份材料的主体、对象、时间范围与授权状态需要逐项核对。数据按每案更新，更新节奏不构成本页功能的触发条件。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向指定地址发送请求，Params、Headers、Body 分别承载路径参数、请求头与请求体，三者均可用 `{{}}` 引用全局变量、系统变量或前方节点输出，URL 同样可引用变量。返回值按 JSON path 提取，输出类型选择字符串时会把对应值转成 JSON 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取不到值属于文档已说明的情形。对话接口调用 `chat/completions` 时推荐在请求体传入 `body.appId`；如需通过 `authProxy` 代理团队成员身份，需团队所有者在创建或编辑该 key 时开启，代理身份仍需要具备目标应用和会话权限。传入的 `model`、`temperature` 等字段无效，由编排决定。检索与相似度设置不承担权限或实体过滤职责，检索本身也不构成授权。

假设演练样本：某店铺客服组收到一份监管询问函，函件载明“请就订单 A 于 2025 年 3 月 12 日的退款处理情况，于 2025 年 4 月 5 日前提交书面说明及证据材料”，落款为某市场监管所。订单系统记录显示该订单退款申请提交于 2025 年 3 月 13 日，状态为待审核。客服拟通过 HTTP 模块向内部工单服务提交一条交接请求，拟稿句为“订单 A 退款已完成，可提交监管回复”。该拟稿句与函件及订单记录均不一致：函件要求的是书面说明与证据，订单记录显示的是待审核，两者都不支持“退款已完成”。

## 配置怎么定
下表围绕上述样本，列出与本页主任务相关的官方已说明设置或实施核对项。数值一栏为本次假设试验起点，仅用于纸面对比，不代表官方默认值。

| 配置项 | 取值或核对方式 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址与方法 | 按外部工单服务接口文档填写 URL 与方法，URL 可引用变量 | 地址与方法须与外部接口契约一致，逐项比对文档 |
| Headers 鉴权 | Authorization 按接口要求注入凭证，凭证不写入公开样例 | 与接口文档声明的鉴权方式比较，确认字段名一致 |
| Body 结构 | 仅在对应请求类型下使用，字段名与外部契约逐项核对 | 与工单服务声明的字段清单比较，缺字段记为待核实 |
| 变量引用 | 引用全局变量、系统变量或前方节点输出，逐项核对实际传入值 | 假设起点为样本中的订单号与函件日期，与订单记录比较 |
| 返回值提取 | 按 JSON path 配置 key，输出类型按下游需要选择 | 与接口响应示例的层级结构比较，确认路径存在 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 测试模式取不到值属文档说明情形，与正式调用区分 |

## 容易做错的三处
1. 把拟稿句当作事实写入交接请求。样本中拟稿句写“退款已完成”，而订单记录状态为待审核，两者在同一字段上取值不同，构成矛盾；待审核不表示已批准，也不表示缺少操作权限。
2. 把检索或相似度结果当作授权依据。检索返回相关记录只说明匹配程度，不构成对目标应用或会话的权限，也不构成对监管材料的提交授权。
3. 把测试模式下的空值当作业务故障。chatId 与 responseChatItemId 在测试模式下不存在，属文档已说明情形，不能据此推断外部系统异常。

## 怎么确认配好了
1. 输入样本函件原文与订单记录原文，比较拟稿句中“退款已完成”与订单记录“待审核”是否在同一订单、同一字段上取值互斥。若两者互斥，判定拟稿句未获支持，需改为与记录一致的表述。
2. 输入一条引用 `{{appId}}` 的 Headers 配置与接口文档声明的鉴权字段，比较字段名与取值格式是否一致。若字段名或格式不符，判定鉴权配置待修正；若文档未载明，记录为证据缺口。
3. 输入测试模式下不含 chatId 的请求，观察返回值中该字段是否缺失。若缺失，符合文档说明的测试模式情形；若正式调用中仍缺失，记录实际观察并核对调用参数，不推断具体错误原因。
