# 投诉举报与监管回复的订单履约与售后答疑：分享与嵌入

## 这个品类的数据长什么样

在投诉举报与监管回复的订单履约与售后答疑中，本页说明FastGPT的分享与嵌入如何衔接资料。投诉答疑入口保留询问函与工单的对象，分享访问不构成监管答复授权。所用场景为自拟文字测试。

## 这些特征在「分享与嵌入」这一环带来什么约束

假设投诉工单记商家正在补订单证据，监管询问函要求说明指定事项，整改报告仍为内部草稿。分享答疑可用自拟文字解释材料缺口，但应区分内部协作人员与外部查看者。入口可提问不意味着允许查看整单顾客资料，更不表示商家已正式向监管回复。答案须保留询问事项与草稿状态，不按页面可访问推断投诉已经处理完毕。

## 配置怎么定

| 投诉分享范围 | 纸面条件 | 上线前核查 |
| --- | --- | --- |
| 工单 | 订单证据待补 | 不称结案 |
| 询问函 | 指定投诉事项 | 不混别案 |
| 整改 | 内部草稿 | 不称已发出 |
| 附件 | 同单顾客资料 | 按受众测权限 |
| 答复 | 拟对外解释 | 责任人另核授权 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `免登录窗口` | 复制生成的完整分享链接。 |
| `过期时间与QPM` | QPM指每用户每分钟访问上限。 |
| `积分上限` | 按入口及版本核用量与费用条件。 |
| `身份验证` | 第三方认证受商业版范围限制。 |
| `对话记录边界` | 匿名标识依赖同设备、同浏览器。 |

## 容易做错的三处

- 发布者可见订单附件但外部查看者也意外读到时，对预定受众、同单资源权限与引用链接，查暴露路径后再调整分享范围。

- 内部整改草稿被分享答复称为已提交监管时，核正式发出记录及报告状态，生成回答不是发送凭证。

- 另一投诉的订单证据被用来回复本函时，对投诉编号、订单及函件所问事项，不能按相同关键词混用。

## 怎么确认配好了

限定可公开的示例和内部协作材料，按实际部署分别测试页面、回答与原文引用访问。对公开入口只使用批准内容，真实个人资料另核授权；嵌入外部页面时仍检查身份和来源链接，不能依靠页面位置保护附件。发布前由责任人审询问范围及外部答复权限，本练习既不向顾客也不向监管发送消息。
