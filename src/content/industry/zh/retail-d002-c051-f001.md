# 抖音小店货架运营的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
货架运营的日常材料以商品资质页、体验分明细、发货违规申诉、店铺公告为主，更新频率为日或每单。订单履约与售后答疑的接口对接，需要把发货状态、缺货记录、申诉进度这些字段从店铺材料映射到外部系统请求。材料中的字段命名、状态取值与外部接口契约不一致时，请求体解析会得到与预期不同的结果。体验分明细与发货违规申诉属于两个不同文档，字段口径需要分别核对。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，实际操作方式与 Postman、ApiFox 接近。Params 用于路径请求参数，GET 请求中居多；Body 用于请求体，POST/PUT 请求中居多；Headers 用于传递特殊信息。三类数据均可通过 `{{}}` 引用变量，URL 同样可以引用变量。变量来源为全局变量、系统变量、前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在，histories 默认最多取 10 条且无法修改长度。返回值配置不代表接口返回值，而是通过 JSON path 语法提取响应值。输出类型选择字符串时，HTTP 对应 key 的值会转成 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId；appId 优先级为 body.appId、`<apiKey>-<appId>`、apikey 关联的 appId。传入的 model、temperature 等参数字段无效，由编排决定。detail=true 时返回中间值，非 stream 模式结果保存在 responseData 中。

假设演练样本：某抖店商家运营人员整理一份待交接的订单履约请求。材料原文为：「订单号 A-2024-0315-07，商品为夏季短袖，下单日期 2024 年 3 月 15 日，当前状态为已发货，物流单号未回传。店铺公告写明缺货商品需在 48 小时内发起申诉。」拟交接请求为：向外部系统发送 POST 请求，Body 中写入 `{"orderId":"A-2024-0315-07","status":"已发货"}`，Headers 中 Authorization 使用 Bearer 加凭证。待判定的是：该请求的 status 取值是否与材料原文一致，物流单号缺失是否属于材料未载明。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 按外部接口文档填写，不引用未提供变量 | 与外部接口契约逐字比对路径与方法 |
| Params | 本次样本不涉及路径参数 | 核对 GET 请求是否需要，缺失时记录 |
| Headers | Authorization 使用 Bearer 加凭证 | 凭证通过安全配置注入，不写入公开样例 |
| Body | `{"orderId":"A-2024-0315-07","status":"已发货"}` | 与材料原文逐字段比对，status 取值须一致 |
| 变量引用 | 不引用未提供的全局变量 | 逐项核对实际传入值，缺失时保留缺口 |
| 返回值提取 | 按 JSON path 配置 key | 与接口响应结构比对，不预设命中 |

本次假设试验起点仅用于说明核对方式，不表示官方默认值。数值选择理由为便于逐字段比对，比较对象为材料原文与外部接口契约。

## 容易做错的三处
1. 把调试模式下的 chatId 空值当成业务故障。输入为测试模式请求，比较对象为文档说明的「测试模式下不存在」，观察结果为 chatId 字段为空属于预期现象。
2. 把 Body 中字符串变量漏加引号。输入为 `"{{string}}"` 与 `{{string}}` 两种写法，比较对象为文档示例中字符串需加 `""` 的说明，观察结果为解析类型是否与预期一致。
3. 把返回值配置当成接口返回值本身。输入为 JSON path 提取配置，比较对象为文档中「返回值代表如何解析接口返回值」的说明，观察结果为提取结果是否与响应结构对应。

## 怎么确认配好了
1. 输入假设样本材料原文与拟交接请求，比较 status 取值与材料原文「已发货」是否一致，观察结果为两者一致时该字段通过核对。
2. 输入假设样本中物流单号缺失的情况，比较材料原文是否载明物流单号，观察结果为材料未载明时记录为证据缺口，不判定为故障。
3. 输入假设样本的 Body 字符串字段，比较是否按文档要求加引号，观察结果为解析类型与预期一致时该写法通过核对。

以上核对均为纸面推演，不表示已实际测试、部署或获得授权。待审核不证明缺少操作权限，材料未载明的字段保持未知。
