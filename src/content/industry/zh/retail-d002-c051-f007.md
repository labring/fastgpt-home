# 抖音小店货架运营的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

抖音小店货架运营围绕商品卡与店铺体验分展开，订单履约与售后答疑的对话记录来自抖店工作台、物流接口等入口。日更与每单更新的资料说明，履约状态和售后请求在单笔订单周期内持续变化。对话日志与审计要处理的材料包括商品资质页、体验分明细、发货违规申诉、店铺公告，这些材料分别对应不同的责任主体和有效范围。日志留存本身只说明系统记录了交互内容，业务对账、赔付判定与合规审计需要完整业务方案另行落实。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份以 chatId 区分某一应用下的会话，dataId 指向该会话内的具体对话。结合 chatId 核对目标对话与业务记录，不同入口创建的会话不混算。source=api 只获取通过 API 创建的会话，页面会话不在该范围。需要对话接口运行详情时按官方契约设置 detail，检查 responseData 中的模块状态与完整结果；detail=false 时中间值不返回。日志与接口实际返回字段是核对对象，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能不同，分别核对输入、历史与返回内容。

假设演练样本：某抖店商家就一笔订单的售后咨询向客服系统发起对话。材料原文为：店铺公告写明“本店退货申请须在签收后七日内提交”；体验分明细记录该订单签收日期为 3 月 2 日；发货违规申诉材料显示该订单物流揽收时间为 3 月 1 日。待判定拟稿句为：“该订单售后对话日志已完整留存，可支持退货时效判定。”请判定该拟稿句是否获得材料支持。

## 配置怎么定

| 配置项 | 本次假设起点或核对动作 | 选择理由与比较对象 |
| --- | --- | --- |
| appId | 使用该应用详情路径中获取的 AppId | 官方说明 AppId 在应用详情路径获取，作为请求身份标识 |
| chatId | 传入非空字符串，长度小于 250 | 官方说明非空时从数据库取会话，需自行确保唯一 |
| detail | 设为 true | 需要 responseData 中的模块状态与完整结果，与 detail=false 仅返回最终回答比较 |
| source | 获取 API 会话时传 api | 官方说明 source=api 不获取页面会话，与不传该参数的范围比较 |
| loadCustomFeedbacks | 获取对话列表时按需设为 true | 官方说明该参数决定是否读取自定义反馈 |
| dataId | 按会话内具体对话 ID 核对 | 官方说明 dataId 指一个会话下某一个对话的 ID |

## 容易做错的三处

1. 把日志留存当成审计完成。输入是对话记录，比较对象是业务对账、赔付判定与合规审计要求，观察结果是日志存在但业务动作未执行。日志留存与合规审计是两个不同事实。
2. 把检索或表单当成授权执行。输入是检索结果或表单提交，比较对象是授权边界，观察结果是表单收集了值但没有下游审批或数据库写入。表单收集值不产生授权效果。
3. 用相似度分数排除无关业务。输入是 score 或 similarity 值，比较对象是实体或权限过滤条件，观察结果是高分记录仍可能属于无关业务。相关度分数不承担权限过滤职责。

## 怎么确认配好了

1. 输入假设样本中的材料原文与拟稿句，比较拟稿句声称的“完整留存”与材料实际记载的公告、签收日期、揽收时间，观察材料是否包含对话日志留存范围的说明。材料未载明留存范围时，该拟稿句未获支持。
2. 输入 chatId 与 dataId，比较目标对话是否属于同一会话，观察返回记录是否与目标订单对应。不同入口会话混算时，核对结果不满足条件。
3. 输入 detail=true 的请求，比较 responseData 中是否包含所需模块状态，观察 detail=false 时中间值是否缺失。需要运行详情而未设置 detail 时，核对结果不满足条件。
