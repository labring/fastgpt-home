# 抖音小店货架运营的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

抖音小店货架运营围绕商品卡与店铺体验分展开，从业主体为抖店商家、内容电商运营与商品卡运营。日常需要处理的文档包括商品资质页、体验分明细、发货违规申诉与店铺公告，数据来源为抖店工作台、抖音电商学习中心、精选联盟数据与物流接口。订单履约与售后答疑的检索对象因此集中在资质状态、体验分构成、发货违规申诉材料与店铺公告口径。数据更新频率为日与每单，这一节奏决定检索所引用的资料存在版本先后，同一字段在不同日期的取值可能不同。检索环节本身不判断资质是否有效、申诉是否成立、赔付是否已执行，它只返回引用内容供后续环节使用。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可以关联一个或多个使用相同向量模型的库。语义检索依据向量距离计算相似度，全文检索依赖关键词命中，混合检索通过 RRF 融合两路结果，重排模型给出 0-1 得分用于过滤。最低相关度仅在语义检索或使用结果重排时生效。引用上限以 token 为单位。问题优化用于指代消除与问题扩展，在检索前额外调用模型。引用内容以数组输出，长度可以为 0，没有搜索到内容时输出链路仍然走通。这些条件说明检索结果是候选引用，不构成授权、审批或业务执行。

假设演练样本：某抖店运营人员在处理一笔订单售后交接时，手头材料写明“店铺公告（2024年3月版）载明：本店发货时效按商品卡页面标注执行，缺货订单在确认无货后由商家发起退款。体验分明细（2024年3月1日至3月31日）显示物流体验分项因一笔延迟发货被扣减。发货违规申诉记录显示该笔申诉状态为‘待审核’。”待判定的拟稿句为：“该店铺缺货订单已由商家完成退款，延迟发货申诉已通过，可解除相关限制。”该句涉及退款执行、申诉结果与限制解除三项事实，材料仅支持公告口径、扣减记录与待审核状态。

## 配置怎么定

| 配置或核对项 | 本次假设试验起点及理由 | 比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联使用同一向量模型的商品资质页、体验分明细、发货违规申诉、店铺公告四类资料库 | 核对各库向量模型标识是否一致，不一致者排除出关联范围 |
| 搜索模式 | 对“延迟发货扣减”类问题用全文检索，对“缺货退款流程”类问题用语义检索 | 用同一测试问题分别跑两种模式，比较引用内容是否覆盖主体与状态 |
| 引用上限 | 起点设为覆盖一条完整公告段落所需 token 量，理由是该类文本常跨句 | 用长短不同的公告与体验分明细段落测试，观察截断位置 |
| 最低相关度 | 仅在语义检索或重排启用时设置，起点依据已标注的相关与无关样本 | 用样本中相关与无关问题比较过滤结果，逐步调整 |
| 问题优化 | 对多轮追问中的短问题开启，对已含完整主体的单轮问题关闭 | 比较原问题与优化后问题，核对主体、期间是否被改写 |
| 结果重排 | 在具备重排模型且候选较多时启用 | 比较重排前后同一问题的引用顺序与得分 |

## 容易做错的三处

1. 把待审核申诉当成已通过。假设样本中申诉状态为“待审核”，拟稿句写成“申诉已通过”，输入是申诉记录状态字段，比较对象是“待审核”与“已通过”两个互斥取值，观察结果是拟稿句与材料不一致。
2. 把公告口径当成已执行退款。假设样本只载明缺货订单由商家发起退款，未载明该笔订单退款已完成，输入是公告原文与订单状态字段，比较对象是“发起退款”与“退款完成”，观察结果是拟稿句缺少执行证据。
3. 把检索命中当成授权解除。假设样本没有限制解除的授权记录，输入是检索返回的引用内容，比较对象是引用内容与授权字段，观察结果是引用内容不含授权信息，拟稿句的解除结论未获支持。

## 怎么确认配好了

1. 输入假设样本中的店铺公告、体验分明细与申诉记录三段原文，以及拟稿句。比较拟稿句中“已由商家完成退款”“申诉已通过”“可解除相关限制”三项与原文对应字段。只有原文明确载明退款完成、申诉通过、授权解除时，拟稿句才获支持；样本中三项均未获支持或待核实。
2. 输入假设样本的申诉状态字段“待审核”，比较“待审核”与“已通过”是否属于同一字段的互斥取值。观察结果是二者互斥，拟稿句的“已通过”与材料矛盾。
3. 输入一条明确纸面输入 `[]` 作为引用内容，核对下游设计在引用长度为 0 时是否仍走通输出链路。观察结果是下游是否按空引用处理，不推断虚构规则检索一定返回空数组。

跨不同向量模型的库不可共同关联，核对标识后排除不符合者，记录实际观察，不执行跨模型检索来比较漏召回。图片检索须有图像输入与相应模型能力，重排须具备模型并按设置启用。检索与相似度得分不承担权限或实体隔离职责，业务验证、审批、数据库写入与外部同步需要各自的下游实现。
