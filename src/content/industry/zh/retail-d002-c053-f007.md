# 渠道应收账款催收的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

渠道应收账款催收发生在赊销之后，核心是授信与现金回收，主要数据来自财务系统、银行回单、经销商订单与销售合同。这一品类日常处理的文档包括应收账龄表、催款函、授信协议与发货冻结通知，典型主体为品牌财务、销售内勤与经销商老板。对话日志与审计环节需要把订单履约与售后答疑过程中的会话记录、运行详情与反馈状态留存下来，供后续核对使用。数据更新频率以周、月为主，本页不依赖该频率做功能判断。

## 这些特征在「对话日志与审计」这一环带来什么约束

结合 chatId 核对目标对话与业务记录，不同入口的会话不应混算。需要对话接口运行详情时，按官方契约设置 detail 并检查 responseData。核对日志与接口实际返回字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，需分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，日志存在不表示完成合规审计。

假设演练样本：某品牌财务在内部核对渠道 A 的订单履约与售后答疑记录。供核对的材料原文为三句：一，授信协议载明渠道 A 授信额度为一批次，有效范围覆盖本季度；二，发货冻结通知载明该渠道在超授信情形下暂缓发货，状态为已发出通知，未载明恢复条件；三，应收账龄表载明该渠道一笔账款处于逾期阶段，未载明还款计划是否已确认。一条待判定的拟稿句为：渠道 A 已完成还款计划确认，可解除发货冻结。该请求处于待审核状态，未获授权执行。

## 配置怎么定

| 配置项 | 本页相关设置或核对项 | 与样本的关系 |
| --- | --- | --- |
| appId 与 chatId | 调用对话接口时传入 appId，用 chatId 定位会话 | 核对样本对话归属渠道 A 的会话 |
| detail | 需要运行详情时设置 detail 为真 | 检查 responseData 是否含所需节点信息 |
| responseChatItemId | 传入时作为本次响应消息 ID，同一 chatId 下需唯一 | 标记样本核对请求对应的响应 |
| variables | 对象形式，替换模块输入框中的 [key] | 传入渠道标识等核对用变量 |
| 会话列表 source | source=api 时获取通过 API 创建的会话 | 区分 API 会话与页面会话 |
| loadCustomFeedbacks | 读取对话列表时可选是否读取自定义反馈 | 核对样本相关反馈是否留存 |

假设本次试验起点将 detail 设为真，理由是样本需要运行详情来核对节点返回，比较方法为对照接口实际返回的 responseData 与所需字段是否一致。该起点为本次假设设定，非官方默认值。

## 容易做错的三处

1. 把检索或表单当成授权执行。样本中拟稿句称可解除发货冻结，但材料仅载明冻结通知已发出，未载明恢复条件，也未见授权。正确做法是核对授权状态，保留待核实结论。
2. 把不同入口的会话混算。若未按 chatId 区分 API 会话与页面会话，样本对话可能与其他渠道记录混同。应核对 chatId 后再比较。
3. 把日志存在当成合规审计完成。样本材料未载明对账与留存要求，日志存在不表示审计已完成。应记录证据缺口。

## 怎么确认配好了

1. 输入样本三句材料原文与拟稿句，比较拟稿句所称“已完成还款计划确认”与材料是否同主体、同期间、同字段。材料未载明还款计划确认，现象为未获支持，应记录待核实。
2. 输入样本 chatId 与 detail 为真，比较接口返回的 responseData 是否含所需节点字段。若字段缺失，现象为未返回，应记录缺口，不推定已留存。
3. 输入样本相关反馈核对请求，比较 loadCustomFeedbacks 读取结果与样本反馈状态。若返回为空，现象为未读取到，应保留未知，不声称反馈不存在。
