# 渠道窜货稽查的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样
渠道窜货稽查在订单履约与售后答疑中，主要处理防伪码记录、电商平台价格截图、经销商发货记录、市场巡检照片以及窜货投诉单。这些材料跨区域、跨批次，同一批货可能对应多个经销商发货记录和多个平台低价链接。材料更新以周和不定期为主，意味着检索时面对的是版本不一的投诉单、处罚通知和调查照片。知识库检索与召回要解决的是：从这些材料中召回与当前投诉单或售后请求相关的片段，供后续人工核对。检索本身不判断窜货是否成立，也不执行处罚。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，需先核标识并排除不符合者，不执行跨模型检索来比较漏召回。搜索模式按测试问题比较语义、全文与混合检索，不预设一种模式适合全部资料。引用上限单位为token，用长短不同的实际资料测试内容是否完整，再调整上限。最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，需比较原问题与优化后问题，核对主体是否被改错。混合检索通过RRF融合多路结果，RRF是融合过程，不是开关。图片检索须有相应图像输入及模型能力，重排须具备模型且按设置启用。检索或表单收集值，不构成授权、审批或数据库写入。

## 配置怎么定
以下配置围绕假设演练样本展开，样本内容为纸面构造，不代表真实客户或已发生业务。

假设演练样本：某品牌渠道管控团队收到一份窜货投诉单，原文为“投诉对象：华东区经销商A；涉及防伪码：FC-2024-8871；投诉事由：该码对应产品在电商平台店铺B以低于建议零售价销售；投诉日期：2024年6月3日；附件：平台价格截图一张、巡检照片两张”。一条待判定拟稿句为“经销商A已完成窜货处罚”。需核对的材料范围包括该投诉单、对应防伪码记录、处罚通知草稿。处罚通知草稿处于待审核状态，未签署，不构成已完成处罚。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
|---|---|---|
| 关联知识库 | 选择使用相同向量模型的窜货投诉库与防伪码记录库 | 先核两库向量模型标识是否一致，排除不一致者，不执行跨模型检索 |
| 搜索模式 | 对“FC-2024-8871”使用全文检索，对“低价销售投诉”使用混合检索 | 编号类问题比较全文命中，自然语言问题比较语义与全文融合结果 |
| 引用上限 | 起点设为1024 token | 用短投诉单与长巡检报告各一份比较召回内容是否被截断，再调整 |
| 最低相关度 | 起点设为0.5 | 先标注相关与无关样本，比较过滤后是否保留投诉单主体与防伪码 |
| 问题优化 | 对多轮追问开启，对单轮明确问题关闭 | 比较原问题与优化后问题，核对“该码”“该经销商”指代是否被改错 |
| 结果重排 | 候选较多时启用ReRank | 比较重排前后0-1得分，确认投诉单与防伪码记录排序是否更靠前 |

## 容易做错的三处
1. 将检索召回等同于授权执行。输入为投诉单中“经销商A低价销售”文字，比较对象为处罚通知草稿的待审核状态，若把召回内容当作处罚已生效，则混淆了检索与审批。可观察结果为：处罚通知草稿仍为待审核，未签署。
2. 跨向量模型关联知识库。输入为窜货投诉库与防伪码记录库的向量模型标识，比较两者是否一致，若标识不同仍尝试共同关联，则违反同向量模型要求。可观察结果为：两库模型标识不一致，应排除不符合者并记录。
3. 将最低相关度当作权限或实体过滤。输入为最低相关度0.5与一条无关经销商记录，比较该记录是否因相似度低被过滤，若认为该设置能排除未授权经销商，则误判了过滤性质。可观察结果为：过滤仅作用于相似度得分，不判断经销商授权范围。

## 怎么确认配好了
1. 验证全文检索对防伪码的召回。输入假设投诉单原文中的“FC-2024-8871”，比较全文检索结果是否包含该码对应记录，满足条件为召回内容中出现该防伪码及投诉单主体。若未出现，记录为未召回，检查数据是否完成训练及分词设置。
2. 验证拟稿句与原文的一致性。输入拟稿句“经销商A已完成窜货处罚”，比较处罚通知草稿状态，满足条件为草稿仍为待审核且未签署，拟稿句未获支持。若草稿已签署，需另行核对签署时间与授权范围。
3. 验证空引用输出的下游承接。输入纸面构造的空结果数组[]，比较下游节点是否按引用长度为0继续走通，满足条件为输出链路未中断且下游未将空结果当作已召回内容。此验证不声称虚构规则检索一定返回[]，仅核对空结果承接设计。
