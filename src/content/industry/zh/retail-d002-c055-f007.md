# 特许加盟备案管理的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

在特许加盟备案管理的订单履约与售后答疑中，本页说明FastGPT的对话日志与审计如何衔接资料。加盟服务答复的复核先区分提问、回复和外部备案结果，历史中有人说完成不等于已经查到办理证据。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

自拟对话里，门店人员问“资料发出就算完成吗”，助手回答“需核本店结果”，随后有人写“已经好了”却未说明来源。日志复核应先用会话标识关联门店与进入方式，再按实际详情响应查看谁说了什么。不能只搜索完成字样就判断服务答复正确，也不能预设外部附件或备案材料已经包含在返回内容里；缺的原始结果仍需另取。

## 配置怎么定

| 加盟服务历史 | 自拟消息 | 复核线索 |
| --- | --- | --- |
| 问题原句 | 发出是否等于完成 | 保留问句性质 |
| 后续自述 | 已经好了但无来源 | 不作为核实结论 |
| 门店关联 | 会话对应本店 | 排除另一加盟点 |
| 详情返回 | 按实际响应查角色 | 不假设附件完整 |
| 外部结果 | 本店结果缺失 | 另取真实依据 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

角色混读：若问句或人员自述被当成助手核实结论，应对照消息角色与上下文；门店串档：若另一加盟点历史用于本店，应查会话关联的实际业务对象；发送冒办理完成：若资料发出被答为本次备案结束，应取对应结果依据。三项分别核说话人、对象和办理阶段，对话时间不能补出外部结果。

## 怎么确认配好了

验收保留查询范围、会话标识、实际返回与待补证据清单，复核本店追问是否仍得到待核解释。补入对应结果后，要看新回复是否采用真实来源，不能沿用“已经好了”的自述。会话历史可用于定位这次答复经过，外部办理、身份认定和合规审计需另核相应记录；日志存在不证明备案真实完成或审核已经通过。
