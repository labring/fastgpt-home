# 生鲜临期折价处理的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

临期折价处理围绕货架库存生命周期展开，数据来源包括 POS 库龄、门店巡检、ERP 库存与质检记录，更新频率以日或班次为主。订单履约与售后答疑环节需要把临期清单、折价审批、报损单、促销价签四类材料串联到外部系统：门店确认批次进入临期状态后，折价审批结果需要落到促销价签，售后咨询需要核对报损单与折价审批是否处于同一授权状态。这些材料的授权状态、有效范围与主体信息，决定 HTTP 请求能否携带正确的对象标识。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params、Headers、Body 均可通过 `{{}}` 引用全局变量、系统变量或前方节点输出，URL 同样支持变量引用。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories；其中 chatId 与 responseChatItemId 在测试模式下不存在，调试空值不构成业务故障。返回值通过 JSON path 提取，输出类型选字符串时会将对应 key 的值转成 json 字符串。对话接口调用 `chat/completions` 时推荐在请求体传入 `body.appId`，也支持 `Authorization: Bearer <apiKey>-<appId>`，BaseUrl 出现 404 时可补充 `v1` 重试。传入的 model、temperature 等字段无效，由编排决定。交互节点返回的 interactive 只含 type 与 params，entryNodeIds、memoryEdges、nodeOutputs、nodeResponseId 等内部运行态字段不返回。

假设演练样本：某门店 2026 年 3 月 10 日班次巡检记录载明「批次 A 酸奶 12 盒，保质期至 3 月 14 日，货架剩余 12 盒，巡检员建议折价 30%」；同日折价审批单载明「批次 A 折价 30%，审批状态：已通过，审批人：店长李某，生效范围：3 月 10 日至 3 月 13 日」。拟稿交接请求为「请将批次 A 折价 30% 同步至外部促销系统，并回复顾客关于该批次是否可退换的咨询」。该请求的授权边界为折价审批已通过，报损单与退换规则未在材料中载明。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 外部促销系统提供的折价同步地址 | 按外部接口文档选择，与审批单载明的生效范围比对 |
| 请求方法 | POST | 按外部接口契约选择，与接口文档声明的方法比对 |
| Headers 鉴权 | Authorization 引用已配置变量 | 凭证通过安全配置注入，与接口文档要求的鉴权方式比对 |
| Body 结构 | 含批次标识、折价比例、生效起止 | 与审批单原文逐字段比对，缺字段记为缺口 |
| 变量引用 | 引用前方节点输出的批次标识 | 核对实际传入值，与巡检记录中的批次标识比对 |
| 返回值提取 | 按 JSON path 提取同步结果字段 | 与外部接口响应结构比对，不预设成功值 |

## 容易做错的三处

1. 把折价审批单的「已通过」当成报损单与退换规则的授权。审批单只载明折价 30% 与生效范围，报损单与退换规则未在材料中出现，售后答复缺少依据。
2. 把测试模式下 chatId 与 responseChatItemId 不存在当成业务故障。调试空值与业务授权状态无关，不能据此判断同步失败。
3. 把 interactive 返回的展示配置当成内部运行态。entryNodeIds、memoryEdges 等字段不返回，不能据此推断节点执行路径或审批已落地。

## 怎么确认配好了

1. 输入假设样本中的巡检记录与审批单原文，比较拟稿交接请求中的批次标识、折价比例、生效起止与审批单字段。若三者一致且审批状态为已通过，则请求的折价同步部分具备材料依据；报损单与退换规则字段在材料中缺失，记为未获支持。
2. 输入假设样本的拟稿交接请求，比较请求中「回复顾客关于该批次是否可退换的咨询」与材料中是否载明退换规则。若材料未载明退换规则，则该部分答复缺少依据，需记录证据缺口，不得推断退换已获授权。
3. 输入假设样本的审批单原文，比较审批单生效范围「3 月 10 日至 3 月 13 日」与请求发起日期。若请求日期落在生效范围内，则折价同步在时间维度上具备条件；若超出范围，则需核实是否有新的审批记录，不得沿用原审批。
