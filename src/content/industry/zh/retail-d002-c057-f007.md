# 生鲜临期折价处理的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

在生鲜临期折价处理的订单履约与售后答疑中，本页说明FastGPT的对话日志与审计如何衔接资料。临期商品咨询的复核要区分工作人员挪放、自拟处置说明与实际库存处理，不从聊天里的“已处理”推出商品状态。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

自拟工作人员在对话写“已移到待处理区”，随后问能否按原安排出售，助手却只答“已经处理”。日志应按会话标识与商品批次核历史上下文，看这个词究竟回应哪一步。待处理区是本题普通文字描述，不是软件状态字段；没有实际库存或销售记录时，聊天原句只能说明人员说做了什么，不能补出后续处置，也不提供真实可售判断。

## 配置怎么定

| 临期答复回看 | 本题自拟文字 | 核对方向 |
| --- | --- | --- |
| 人员陈述 | 移到待处理区 | 仅说明陈述的动作 |
| 模糊回复 | 已经处理 | 查究竟回应哪一步 |
| 批次关联 | 同名商品可能不同批 | 取原始业务对象 |
| 库存依据 | 详情只有聊天 | 另核实际扣减 |
| 复问结果 | 仍待处置时保留 | 不自动确认可售 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

词义跳步：若移放被解释成处置完成，应核前后消息所指动作；批次错联：若同名商品另一批的回复进入本次，应查会话对象与原始批次；库存凭据缺位：若助手宣称已扣减而响应只有聊天，应另取实际库存依据。三项分别核动作含义、业务归属与证据类型，历史可读不等于结果可证。

## 怎么确认配好了

验收保留完整追问、回答及实际返回范围，检查复问是否明确仍待处置。加入本批库存处理记录后，核新解释是否只覆盖对应动作；销售资格或其他处置仍缺时不要顺带确认。实际报损、库存调整与售卖决策由另接流程核记录，聊天时间和人员自述不替代这些结果，日志检查也不自动完成业务审计。
