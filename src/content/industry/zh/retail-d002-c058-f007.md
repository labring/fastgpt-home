# 生鲜供应商索赔的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

在生鲜供应商索赔的订单履约与售后答疑中，本页说明FastGPT的对话日志与审计如何衔接资料。鲜品索赔回复需要定位供应商到底确认了什么，收到异常通知与同意处理不是同一条证据。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

自拟服务对话引用供应商原话“已收到照片，待看实物”，助手却告诉客户索赔已接受。追查应先把会话标识关联送货事项，再按实际详情响应查看引用原句是否完整。收到照片只支持接收信息，不支持商议结果；若返回未含照片本身，也不能声称从日志看到了货品损伤。这里只复核答复推断，不据缺项断言索赔一定失败。

## 配置怎么定

| 索赔服务追查 | 自拟供应商回复 | 需要核实 |
| --- | --- | --- |
| 接收信息 | 照片已收到 | 不等于同意索赔 |
| 待办动作 | 待看实物 | 不可从引文省掉 |
| 图像内容 | 响应未必返回照片 | 不假装已看损伤 |
| 事件身份 | 同供应商多次异常 | 核本次送货关系 |
| 商议结果 | 缺明确处理回复 | 补证后限范围复问 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

接收冒同意：若待看实物被省掉，应对照供应商完整回复与助手结论；照片冒实物结论：若图片收到被写成品质已确认，应查实际检查依据；他次异常串入：若同供应商旧记录用于本次，应核送货对象与引用归属。三项分别核立场、证据性质和事件身份，供应商同名不能证明同案。

## 怎么确认配好了

验收保存提问、供应商原句和答复链，补本次检查或明确回复后复问，看结论是否限于新证据覆盖。只补收到通知的回信时，应仍留商议待定。扣减、补货、结算调整及争议关闭需另外的业务记录，日志可追到回答怎样形成，不能替供应商作接受决定，也不把会话关闭认作索赔关闭。
