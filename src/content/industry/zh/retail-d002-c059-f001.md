# 生鲜冷链到店验收的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
冷链验收环节的数据以批次为单位产生。冷链车温控记录、到货验收单、拒收单、供应商送货单构成一组围绕同一车次、同一门店、同一到货时间的材料。温度数值、抽检结论、拒收原因分别登记在不同单据上，登记动作发生在测量和抽检之后。这些材料的更新频率为每批或每日，验收结果直接影响供应商争议与食材处置。将上述材料接入外部系统时，需要先确认材料本身是否已经形成完整记录，再讨论接口传参。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向指定地址发送请求，Params 用于路径参数，Body 用于请求体，Headers 用于请求头，URL 也可通过 `{{}}` 引用变量。变量来源为全局变量、系统变量、前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 语法提取，输出类型选择字符串时会把对应 key 的值转为 json 字符串。对话接口使用 APIKey 鉴权，appId 优先级为 body.appId、`<apiKey>-<appId>`、apikey 关联的 appId。传入的 model、temperature 等字段由编排决定。交互节点返回的 interactive 只包含 type 和 params，内部运行态字段不返回。检索或表单只收集取值，业务核验、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：某门店收货系统生成一条待交接请求，拟通过 HTTP 模块提交至外部验收服务。样本材料原文为：「2025年3月10日，冷链车次 C-0310 到达 A 门店，温控记录显示到货温度为 4.2 摄氏度；到货验收单登记抽检批次 B-0310-02，结论为待质检员复核；拒收单尚未生成。」拟交接请求句为：「请将本次到货验收结论提交外部系统，并同步拒收原因。」该请求含主体（A 门店、车次 C-0310）、对象（批次 B-0310-02）、状态（待复核）与有效范围（2025年3月10日到货）。请求中要求同步的拒收原因在材料中不存在，故该项属于未获支持。

## 配置怎么定
下表围绕上述样本，列出与本功能及订单履约答疑相关的官方已说明设置或实施核对项。数值一栏为本次假设试验起点，仅用于比较，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 核对方式与理由 |
| --- | --- | --- |
| 请求地址与方法 | 按外部验收服务文档填写 URL 与 POST | 地址可引用变量；方法须与外部接口契约一致 |
| Params 与 Headers | Authorization 通过安全配置注入 | 核对请求头取值来源，凭证不写入公开样例 |
| Body 结构 | 引用车次、批次、到货时间字段 | 仅在 POST 下生效，逐项核对 JSON 键与外部契约 |
| 变量引用 | 引用前方节点输出的批次与温度 | 确认变量来自全局变量、系统变量或前方节点输出 |
| 返回值提取 | 配置 `$.data.result` 等 key | 按 JSON path 提取，输出类型按需选择字符串 |
| 调试身份字段 | chatId 与 responseChatItemId 留空 | 测试模式下这两个字段不存在，空值不作为业务故障 |

## 容易做错的三处
1. 把样本中「结论为待质检员复核」直接当作已完成的验收结论写入 Body。输入是拟交接请求句，比较对象是材料原文中的状态字段，可观察结果是请求体是否携带了已复核标记。材料只登记待复核，未载明复核完成，该字段属于未获支持。
2. 把拟交接请求中的「同步拒收原因」当作可提交字段。输入是请求句与拒收单状态，比较对象是拒收单是否已生成并载明原因，可观察结果是 Body 中是否存在拒收原因取值。拒收单尚未生成，该取值缺失。
3. 将测试模式下 chatId 为空解释为业务故障。输入是调试请求与系统变量说明，比较对象是测试模式与正式模式下 chatId 的存在条件，可观察结果是错误归因是否落在身份字段缺失上。文档说明测试模式下不存在该字段。

## 怎么确认配好了
1. 输入样本材料原文与拟交接请求句，比较请求 Body 中的验收结论字段是否与「待质检员复核」一致，可观察结果为：若请求体写入已复核结论，则与材料状态不符；若保持待复核，则与材料一致。
2. 输入拟交接请求句与拒收单状态，比较请求中是否要求提交拒收原因，可观察结果为：材料未生成拒收单，请求若携带该字段则缺少来源；记录该缺口，不推断拒收成立。
3. 输入调试请求，比较 chatId 与 responseChatItemId 是否为空，可观察结果为：测试模式下两字段不存在，空值属于文档说明的条件，不构成业务故障。若需判定外部系统是否接受该请求，属于另接系统实现的业务动作，本页不作断言。
