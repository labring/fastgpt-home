# 生鲜水果门店采购的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样
生鲜水果门店采购的日常资料以采购单、验收单、农残检测报告、损耗记录为主，来源包括批发市场行情、供应商报价、门店销售和检测报告。与便利店鲜食订货相比，水果采购更依赖批发市场行情和等级验收，缺少统一的总部标准餐食口径。资料更新频率为日或每批，这意味着检索到的验收等级、报价和检测结论都带有明确的时间与批次边界。订单履约与售后答疑中，采购人员需要核对某批到货的验收结论、某份检测报告对应的批次，以及损耗记录中的责任归属，这些判断都依赖资料原文中的主体、对象、状态和有效范围。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，操作时应先核对向量模型标识，排除不符合者，并记录实际观察，不执行跨模型检索来比较漏召回。搜索模式分为语义检索、全文检索与混合检索，应按测试问题比较，不预设一种模式适合全部资料。引用上限以 token 为单位，需用长短不同的实际资料测试内容是否完整。最低相关度仅在语义检索或使用结果重排时生效，属于过滤阈值，不是最终排序规则。问题优化用于指代消除和问题扩展，应比较原问题与优化后问题，核对主体是否被改错。图片检索须有相应图像输入及模型能力，重排须具备模型且按设置启用，文档总流程图列出的可选路径不代表每次请求全部执行。检索与相似度不承担权限或实体隔离功能，检索库同向量模型要求不能扩展为其他外部系统也要同模型。

## 配置怎么定
下表围绕本页假设演练样本，只列与本功能、主任务相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联一个含采购单、验收单、检测报告、损耗记录的库 | 先核对该库向量模型标识一致，再排除其他模型不符者 |
| 搜索模式 | 混合检索 | 与单独语义检索、单独全文检索比较同一测试问题的召回内容 |
| 引用上限 | 假设起点 2000 token | 用长短不同的验收单与检测报告比较内容是否被截断 |
| 最低相关度 | 假设起点 0.5 | 先标注相关与无关样本，再与 0.4、0.6 比较过滤结果 |
| 问题优化 | 开启 | 比较原问题与优化后问题，核对批次主体是否被改错 |
| 结果重排 | 按设置启用 | 具备重排模型时比较重排前后候选排序 |

## 容易做错的三处
1. 把检索或表单当作授权执行。假设演练样本中，采购主管提交一份售后答疑请求，材料写明“该批到货验收结论为待复核，检测报告编号对应批次已出具”，拟稿句写“该批已通过验收并可退款”。输入为这段原文与拟稿句，分别核验收结论与退款依据。待复核不支持已通过验收；已出具检测报告也未给报告结论或退款授权，退款主张另记待核，不能把整句当成一个字段。待审核不证明缺少操作权限，也不等于退款已执行。
2. 把最低相关度当作权限或实体过滤。输入为同一测试问题与开启最低相关度前后的召回列表，比较的是被过滤掉的内容是否属于无关片段，可观察结果是阈值变化只改变相关度过滤结果，不改变可访问范围。相似度设置不排除无关业务或未授权记录。
3. 把跨模型知识库强行共同关联。输入为两个向量模型标识不同的库标识，比较的是标识是否一致，可观察结果是标识不一致者应被排除并记录，不继续推断共同关联后的运行结果。

## 怎么确认配好了
1. 使用假设演练样本原文核对拟稿句。输入为“该批到货验收结论为待复核，检测报告编号对应批次已出具”与拟稿句“该批已通过验收并可退款”，分别列验收状态、检测报告结论及退款依据。原文只给待复核和报告已出具，未给通过结论及退款依据，拟稿的两项主张分别未获支持。
2. 使用明确纸面输入核对空结果承接。输入为引用内容数组长度 0 的纸面输入，比较下游链路是否仍走通，可观察结果是输出链路走通且引用长度为 0，不声称虚构规则检索一定返回空数组。
3. 使用同一测试问题比较三种搜索模式。输入为同一测试问题与同一知识库，比较语义检索、全文检索、混合检索各自返回的引用内容，逐条记录三种模式实际内容及有无差异，不预设必然不同，不保证首条命中或全部召回。
