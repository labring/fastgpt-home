# 电商仓入库上架的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
电商仓入库上架处理货物进入仓库的第一道账实确认，主要数据来源为 WMS、ERP 采购、供应商送货单与条码扫描，日常文档包括采购到货单、入库验收单、上架任务与差异报告。这些材料以每批、每日为更新节奏，HTTP 接口环节需要把外部系统的请求与这些单据逐项对应。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块可重复添加、手动配置、触发执行，通过 Params、Headers、Body 发送请求，三处均可通过 {{}} 引用全局变量、系统变量与前方节点输出，URL 也可引用变量。系统变量含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 语法提取，输出类型选择字符串时会转成 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>；传入的 model、temperature 等字段无效，由编排决定。检索与相似度分数不承担授权或实体过滤职责。

假设演练样本：某电商仓收货员于 2026 年 3 月 10 日处理一批采购到货单，材料原文为「采购到货单 PO-2026-0310，供应商送货数量 120 件，WMS 采购订单记录到货数量 120 件，入库验收单记录实收 118 件，差异 2 件待差异报告确认」。一条待判定的拟稿句为「本批到货数量与采购订单一致，可直接生成上架任务」。该请求处于待核对状态，未获授权执行上架。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址 | 外部接口文档给出的地址 | 与接口文档逐字比对 |
| 请求方法 | 按外部接口契约选择 | 与接口文档方法字段比对 |
| Params | 路径参数按接口文档填写 | 与接口文档参数表比对 |
| Headers | Authorization 使用 Bearer 加凭证 | 核对鉴权方式与凭证来源 |
| Body | 仅在相应请求类型下使用，核对 JSON 结构 | 与接口契约字段比对 |
| 变量引用 | 引用全局变量、系统变量或前方节点输出 | 核对实际传入值 |

上述数值为本次假设试验起点，选取理由是样本日期与数量已在材料原文中给出，比较对象为材料原文中的对应字段，不作为任何官方默认值。

## 容易做错的三处
1. 把材料原文中「实收 118 件」与「采购订单 120 件」当作同一字段，忽略差异 2 件待差异报告确认，导致拟稿句「到货数量与采购订单一致」缺乏支持。
2. 把测试模式下不存在的 chatId、responseChatItemId 空值当成业务故障，忽略文档已说明测试模式下不存在。
3. 把检索或相似度分数当成授权或实体过滤手段，忽略检索不承担授权职责，授权需另接系统实现。

## 怎么确认配好了
1. 输入上述假设样本材料原文与拟稿句，比较拟稿句「到货数量与采购订单一致」与原文「差异 2 件待差异报告确认」，观察是否出现同字段互斥取值；若拟稿句未覆盖差异字段，则判定为未获支持。
2. 输入上述假设样本中的采购到货单与入库验收单，比较两处数量字段与差异字段，观察差异 2 件是否已由差异报告确认；未确认时记录为待核实。
3. 输入上述假设样本的交接请求，比较请求状态与授权边界，观察是否出现签署、审批或执行记录；请求处于待核对状态时，记录为待核实，不判定为已授权执行。
