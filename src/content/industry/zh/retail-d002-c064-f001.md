# 直播选品与样品质检的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

选品质检发生在开播前，判断商品能否上播以及是否适合直播展示。日常材料包括样品评估表、质检报告、供应商资质与禁售清单，来源覆盖供应商资料、检测机构报告、平台负面目录和历史退货率。订单履约与售后答疑环节需要把样品评估结论、质检状态和售后口径通过 HTTP 接口传给外部订单或工单系统，接口返回的字段决定后续人工动作。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 用于路径参数，Body 用于 POST/PUT 请求体，Headers 用于传递特殊信息。URL、Params、Body、Headers 中均可用 `{{}}` 引用全局变量、系统变量与前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于环境差异，不构成业务故障。返回值通过 JSON path 提取，出参格式化可将选定 key 转为 json 字符串。

假设演练样本：一份待核对的样品评估表原文写「供应主体：某供应商；对象：批次 A 保温杯；质检状态：待复核；有效期范围：本批次送检样品」。一条拟稿交接请求写「将批次 A 保温杯标记为质检通过并同步至履约系统」。该请求把待复核写成已通过，把待同步写成已同步。HTTP 节点可以发送请求并解析响应，业务状态的确认、审批和写入需要下游系统实现，接口调用本身不产生授权。

## 配置怎么定

| 配置项 | 取值或核对内容 | 与本文档的关系 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选定，地址可引用变量 | 地址与动作须匹配履约系统契约 |
| Headers | 鉴权凭证经安全配置注入，不写入公开样例 | 用于传递身份信息 |
| Body | 仅在相应请求类型下使用，核对 JSON 结构 | 承载批次与质检字段 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 逐项核对实际传入值 |
| 返回值提取 | 用 JSON path 指定 key 并选择输出类型 | 决定下游可读取的字段 |
| 假设试验起点 | 本次假设以「待复核」作为状态起点值 | 选它是因为样本原文如此，与接口返回的质检状态字段逐项比较 |

## 容易做错的三处

1. 把假设样本中「待复核」直接当作已通过发出。输入是样本原文与拟稿请求，比较两者状态字段，观察到请求状态与原文不一致即判定错误。
2. 在测试模式下取到空的 chatId 或 responseChatItemId，就认定为接口故障。输入是调试响应，比较文档说明的测试模式条件，观察到测试模式即可解释空值。
3. 把 HTTP 返回的成功解析当作业务已同步。输入是响应内容，比较履约系统内的实际记录，观察不到对应记录即说明同步未完成。

## 怎么确认配好了

1. 取假设样本原文与拟稿请求，逐字比较主体、对象、质检状态与有效期范围。状态字段取值互斥时才算矛盾；原文写「待复核」而拟稿写「已通过」，属于同一字段的冲突。
2. 用 `{{}}` 引用变量后检查实际传入值。输入是节点配置与运行时的 variables，比较引用键与预期键，观察到键一致且值非空即满足条件；键缺失或值为空则记录缺口。
3. 核对返回值提取的 key 与输出类型。输入是接口响应示例与配置的 key，比较提取结果与响应结构中对应路径的值，观察到两者一致即满足条件；路径不存在时保持未知，不推断失败原因。

检索与相似度不承担权限或实体隔离职责，接口调用不构成授权。交互节点返回的展示配置只含 type 与 params，内部运行态字段不返回。待审核不证明缺少操作权限，待复核不表示已通过，请求发出不表示业务已同步。
