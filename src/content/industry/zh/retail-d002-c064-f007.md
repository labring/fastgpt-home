# 直播选品与样品质检的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

在直播选品与样品质检的订单履约与售后答疑中，本页说明FastGPT的对话日志与审计如何衔接资料。样品售后询问可能被误答成批量承诺，历史复核要保留样品、送检对象与实际采购批的区别。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

自拟客户问“收到的大货与样品一样吗”，助手引用样品评估中的“外观可继续观察”，却总结本批品质已确认。先关联会话标识与所问采购批，再按详情契约看返回了哪些评估片段。样品意见本来保留观察，不能扩大成批量验收；若没有本批检查材料，只能说明现有依据不足，不推定大货存在问题，也不承诺未来供货一致。

## 配置怎么定

| 样品售后复核 | 自拟输入范围 | 判断依据 |
| --- | --- | --- |
| 客户问题 | 大货是否与样品相同 | 核本次采购批 |
| 样品意见 | 继续观察 | 不写成验收通过 |
| 所指对象 | 送检样非全部到货 | 取批次对应 |
| 回复沿用 | 旧答未有新依据 | 查本次实际引用 |
| 主体资料 | 资质不证商品品质 | 不补缺失检查 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

样本换对象：若样品记录用于大货，应核报告所指与采购批关系；保留意见变通过：若继续观察被省掉，应对照完整评估原句与助手总结；旧回复冒本次复核：若历史答复直接沿用，应查本次新增证据及实际引用。三项分别核对象覆盖、结论强度和答复依据，资质标题不能替这些材料。

## 怎么确认配好了

验收保留样品原句、客户问法与引用范围，补本批检查后再追问，核回复是否明确哪项已获支持、哪项仍待核。只补供应商主体资料时，不应改变货品品质结论。采购退换、供应商处理和正式售后决定需另外的业务记录；日志用于复查解释边界，不自动完成质检，也不证明样品结果能推广到所有批次。
