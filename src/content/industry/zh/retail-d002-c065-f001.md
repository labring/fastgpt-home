# 直播间违规申诉的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

在直播间违规申诉的订单履约与售后答疑中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。直播申诉售后查询先核通知与商品对应，再看外部返回说明收到、受理还是已有结果，不能由响应成功补出结论。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

自拟咨询问某商品的申诉进展，拟查询材料却只给直播场次，商品与通知关系仍缺。接 HTTP 前应确认外部确有适用读取契约，按其地址、方法与范围传真实输入，不预设平台已经接通。场次能读到通知，不代表通知覆盖该商品；返回若只说明资料已收，回答应限于该阶段，不能因读取正常改成申诉获认可。

## 配置怎么定

| 申诉进展读取 | 自拟查询缺口 | 真实核对 |
| --- | --- | --- |
| 商品对应 | 仅给直播场次 | 补通知对象关系 |
| 发送条件 | 按实际读取契约 | 比较真实请求 |
| 返回阶段 | 材料收到 | 不称处理认可 |
| 未命中 | 范围权限仍待核 | 不说申诉不存在 |
| 正式动作 | 提交更新另接 | 响应非平台决定 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

范围不足强配：若只按场次返回就当本商品结果，应核通知对象与请求条件；收件冒受理结果：若材料收到变成已经处理，应查实际返回的原句及结果依据；空返回冒不存在：若未命中就说没有申诉，应查权限、范围和来源完整性。三项分别核对应、阶段和查询缺口，不能只看响应状态。

## 怎么确认配好了

验收保留发送前的业务原句、真实请求和响应，补商品通知对应后重查，看实际发送值是否改变。Params、Headers及适用Body依真实契约核，不展示凭证；前步值有内容也要查它是否支持该范围。正式提交、补料和结果更新需另接业务步骤核权限与回执，HTTP输出只证明取得了对应响应，不证明平台决定或申诉成功。
