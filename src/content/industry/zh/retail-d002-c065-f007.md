# 直播间违规申诉的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

直播间违规申诉针对已发生的处罚复盘证据链，主要材料来自平台违规中心、直播回放、客服记录与商品资质库，更新不定期，每次违规触发一轮。订单履约与售后答疑环节的对话日志因此带有两类内容：一类是围绕违规通知、录屏片段、资质文件与申诉说明的往来问答；另一类是订单履约状态与售后处理进度的问询。两类内容共用同一个 chatId 时，日志会把申诉证据讨论与售后进度混排在同一会话下，核对时须按 dataId 逐条区分对象。

## 这些特征在「对话日志与审计」这一环带来什么约束

约束一，对话接口的 messages 数组在传入非空 chatId 时，仅最后一个内容作为用户问题，其余 message 被忽略，日志核对须以实际入库记录为准，不能以请求体全量推定留存。约束二，detail 为 true 时才返回中间值与完整结果，非 stream 模式保存在 responseData，stream 模式通过 event 区分；未开启 detail 的轮次，模块状态与引用列表不在返回中。约束三，日志存在不等于完成合规审计，对账、留存期限与合规要求由完整业务方案另行落实。

假设演练样本。材料原文：某店铺于 2025 年 3 月 10 日收到平台违规通知，通知载明处罚对象为商品链接 A 的 3 月 8 日 20:00 至 21:00 直播场次，处罚状态为商品禁播，申诉窗口自通知送达起 48 小时内。客服记录显示，3 月 11 日用户就该商品订单 B 询问发货时间，客服回复发货时间以订单页为准。拟判定交接请求：运营拟将“商品禁播已解除”写入对用户的售后答复。核对要点：材料仅载明禁播与申诉窗口，未载明解除；该拟稿句缺少解除依据，属未获支持。

## 配置怎么定

| 核对项 | 与样本相关的取值或做法 | 判定方式 |
| --- | --- | --- |
| appId 与 chatId | 申诉答疑会话与售后会话分别使用独立 chatId | 按 chatId 拉取记录，确认两类内容未混入同一会话 |
| detail 设置 | 需要模块状态与引用列表时设为 true | 检查 responseData 是否含对应模块元素 |
| responseChatItemId | 在样本 chatId 下保持唯一 | 同一 chatId 内重复值视为输入不合规 |
| 会话来源 source | 按 api 拉取 API 创建的会话 | 与页面会话分别统计，不合并计数 |
| 反馈字段 | 需要时读取 loadCustomFeedbacks | 未开启时该字段不在记录中 |
| 检索引用 | 按 quoteList 与 score 记录 | 相关度字段不承担权限或实体筛选 |

## 容易做错的三处

1. 把同一 chatId 下的申诉讨论与售后进度合并计数。检查输入为样本 chatId 下的记录列表，比较每条 dataId 的 obj 与 value 对象，观察两类内容是否被计入同一业务口径。
2. 以请求体推定日志已完整留存。检查输入为一次未开启 detail 的调用，比较返回中是否存在 responseData，观察模块状态与引用列表是否缺失。
3. 把拟稿句当作已核事实。检查输入为“商品禁播已解除”这一句，比较材料原文只载明禁播与申诉窗口，观察该句是否缺少解除依据。

## 怎么确认配好了

1. 输入样本 chatId 与记录列表，比较申诉会话与售后会话的 chatId 是否分别对应，观察记录是否按会话隔离。
2. 输入一次 detail 为 true 的调用，比较返回中 responseData 的模块元素与 quoteList，观察模块状态与引用是否随设置出现。
3. 输入拟稿句“商品禁播已解除”，比较材料原文的处罚状态与申诉窗口表述，观察该句是否被标为未获支持并保留证据缺口。
