# 社区团购团长运营的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

团长运营围绕社区节点与佣金展开，与生鲜冷链验收分属不同环节，不直接承担冷链质检职责。日常材料包括团长协议、佣金表、提货清单、社群公告，数据来源覆盖社区团购后台、团长社群、订单明细与售后记录。订单履约与售后答疑中的对话日志，需要把某一次会话与对应的订单、售后记录对齐，才能用于核对。资料给出的更新频率为日、每团，本页不据此推出批量同步或实时机制。

## 这些特征在「对话日志与审计」这一环带来什么约束

会话身份由 chatId 界定，对话身份由 dataId 界定。同一 chatId 下 responseChatItemId 需唯一。日志中出现的字段以接口实际返回为准，未返回的业务数据不能推定已完整留存。检索结果的相关度分数不承担权限或实体过滤职责，检索动作本身不构成授权。

假设演练样本：某社区团购平台的团长运营人员提交一份纸面材料，内容为“团长协议编号 T-2024-031，签署日期 2024 年 3 月 10 日，协议处于待审核状态；对应提货清单编号 P-031，日期 2024 年 3 月 12 日，数量 40 份；售后记录编号 A-031，日期 2024 年 3 月 13 日，状态为已受理。”待判定拟稿句为“该团长协议已生效，可执行佣金结算。”判定所需主体为团长协议 T-2024-031，对象为佣金结算，状态为待审核，有效范围未载明。

## 配置怎么定

| 配置项 | 类型 | 说明 |
| --- | --- | --- |
| appId | 请求字段 | 应用 ID，调用对话接口时推荐在请求体传入 |
| chatId | 请求字段 | 会话 ID，非空字符串时从数据库取会话 |
| detail | 请求字段 | 设为 true 时返回中间值，非 stream 模式结果在 responseData |
| responseChatItemId | 请求字段 | 传入后作为本次响应消息 ID，同一 chatId 下需唯一 |
| dataId | 对话字段 | 会话下某一条对话的 ID，用于获取单个对话运行详情 |
| source | 会话列表字段 | source=api 表示获取通过 API 创建的会话 |

本次假设试验起点：将 detail 设为 true，用于观察 responseData 中节点响应。选择该值的原因是样本需要核对中间值，比较对象为 detail=false 时仅返回 choices 的响应。

## 容易做错的三处

1. 把待审核状态当作已生效。样本中团长协议 T-2024-031 处于待审核，拟稿句称已生效，二者状态不一致。核对输入为协议状态字段与拟稿句，比较对象为“待审核”与“已生效”，观察结果为状态取值不同。
2. 把检索结果当作授权依据。样本中提货清单 P-031 与售后记录 A-031 被检索到，检索动作本身不表示团长具备佣金结算权限。核对输入为检索返回记录与拟稿句，比较对象为记录存在与权限状态，观察结果为授权字段缺失。
3. 把不同入口会话混算。样本中 chatId 未载明，若将页面会话与 API 会话合并统计，会改变对话数量。核对输入为 source 取值与 chatId，比较对象为两类来源，观察结果为会话列表条目归属不同。

## 怎么确认配好了

1. 输入样本原文与拟稿句“该团长协议已生效，可执行佣金结算。”，比较协议状态“待审核”与“已生效”，当两者取值不同时，判定拟稿句未获支持。
2. 输入样本中提货清单 P-031 与售后记录 A-031，比较检索返回记录与佣金结算授权字段，当授权字段未出现在返回内容中时，记录为授权证据缺失。
3. 输入样本中未载明的 chatId 与 source=api，比较页面会话与 API 会话的列表归属，当两类会话分别列出时，记录为来源区分成立。

以上均为纸面核对，未执行实际调用，未产生业务动作。
