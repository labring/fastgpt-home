# 跨境商品合规与标签的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

在跨境商品合规与标签的订单履约与售后答疑中，本页说明FastGPT的对话日志与审计如何衔接资料。标签售后日志保留送核、当前版本和真实查验结果的区别，不由返回详情推合规结论。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

自拟标签记录说本版已送资料复核，查验结论仍待提供，历史说明属于另一批标签。售后追问本批是否已经通过时，先定位本次对话，再核送入模型的是哪版原文。日志里的说明文本可以展示曾收到什么，不能证明实物查验或官方决定。调试与正式调用的身份输入分别核；只有请求详情开关也不说明未返回的业务附件已完整留存。

## 配置怎么定

| 标签答疑日志 | 纸面状态 | 实际核验 |
| --- | --- | --- |
| 送核 | 仅提交复核 | 非已通过 |
| 批次版本 | 当前与历史分开 | 核实际传入 |
| 附件覆盖 | 可能只有名称 | 对原始内容 |
| 运行详情 | 按契约取得 | 不补业务材料 |
| 处理权限 | 实际流程另验 | 日志不授权 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

送核被答成通过时，核原文阶段与真实结论；旧批标签进入本批时，核版本和批次；附件名称被当完整正文时，核实际输入及返回。三处分别看状态、身份和资料覆盖。

## 怎么确认配好了

验收追到同一对话的输入、历史和答复，按官方契约核需要的detail与responseData。新结论补入后确认所属批次再比原题。标签审核、备案或售后处理由实际业务流程决定，日志存在不授予办理权限，也不替代真实凭证。
