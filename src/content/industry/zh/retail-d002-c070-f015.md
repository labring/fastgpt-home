# 跨境商品合规与标签的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

跨境商品合规与标签的资料围绕产品安全与标签证据展开，主要来源包括平台政策中心、检测机构报告、目的国法规库和供应商资料。日常处理的文档有产品测试报告、英文标签、MSDS和平台禁售清单。这些资料在订单履约与售后答疑中被检索，用于回答标签内容、报告覆盖范围和禁售清单归属等问题。资料更新不定期，每次上新都可能产生新版本，因此同一商品在不同时间可能存在多份测试报告或标签稿。检索结果需要区分资料对应的商品、目的国和版本，不能把一份报告的结论直接套到另一个商品或另一目的国。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，应先核标识并排除不符合者，记录实际观察，不能接着推断共同关联后的运行结果。检索以整个库为最小搜索单位，集合仅用于分类管理，与搜索效果无关。语义检索依赖向量距离，适合自然语言问题；全文检索适合编号、型号、专有名词和错误码；混合检索同时使用两路召回并通过RRF融合。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不负责权限或实体隔离，不能用来排除无关业务或未授权记录。引用上限以token为单位，长度差异大的资料需要分别核对内容完整性。问题优化用于指代消除和问题扩展，会额外调用模型，可能改变问题主体，需要比较原问题与优化后问题。

假设演练样本：某份英文标签稿载明“Product: Model A, Destination: Germany, Version: 2024-06”。一份测试报告载明“Model A, Test scope: EN 71-3, Report date: 2024-05-10”。一份平台禁售清单载明“Model B, Destination: Germany, Status: listed”。一条待判定拟稿句为“Model A 已完成德国目的国全部合规要求，可直接上架”。检索范围限定为上述三份资料所在的知识库。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联包含上述三份资料的同一向量模型库 | 先核向量模型标识，排除不同模型库，不执行跨模型检索比较 |
| 搜索模式 | 混合检索 | 样本含型号与目的国等精确词，也含自然语言拟稿句，比较语义、全文与混合三路召回差异 |
| 引用上限 | 本次假设试验起点设为覆盖三份资料全文所需token量 | 该值仅为起点，用长短不同的实际资料比较内容是否被截断，再调整 |
| 最低相关度 | 先标注相关与无关样本，再设一个起点值 | 仅在语义检索或结果重排时生效，比较过滤前后候选变化 |
| 问题优化 | 先关闭，用原问题检索一次 | 比较原问题与优化后问题的主体是否被改错，再决定是否开启 |
| 结果重排 | 具备重排模型时启用一次 | 比较重排前后得分与排序，确认候选是否足够 |

## 容易做错的三处

1. 把检索命中当作授权。拟稿句称Model A已完成德国全部合规要求，检索可能命中标签稿和测试报告，但测试报告仅覆盖EN 71-3，标签稿仅载明版本，均未载明目的国全部合规要求。检索是内容查找，不是授权或合规确认。
2. 把不同向量模型的库共同关联。若另一库使用不同向量模型，应先核标识并排除，记录实际观察，不能推断共同关联后会漏召回或返回冗余。
3. 把最低相关度当作实体或权限过滤。该值仅过滤低相关度结果，不能排除禁售清单中Model B或未授权记录。禁售清单载明Model B状态为listed，与Model A分属不同主体，不能混用。

## 怎么确认配好了

1. 输入上述三份资料原文和拟稿句，比较拟稿句中的“Model A”“德国”“全部合规要求”与原文载明的商品、目的国、测试范围。仅当原文明确载明同一商品、同一目的国、同一字段的互斥取值时，才可判定矛盾；未载明或仅有相关阶段证据，记录为未获支持或待核实。
2. 输入一份仅含Model B禁售清单的纸面输入，比较检索输出是否为明确的空结果数组[]，并核对下游设计是否承接空引用。不能声称虚构规则检索一定返回[]。
3. 输入原问题与问题优化后问题，比较两者主体是否一致。若优化后问题改变商品、目的国或版本，记录为待核实，不据此判定合规状态。
