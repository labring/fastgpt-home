# 跨境平台结算与汇兑的订单履约与售后答疑：多轮对话与提示词

## 这个品类的数据长什么样

在跨境平台结算与汇兑的订单履约与售后答疑中，本页说明FastGPT的多轮对话与提示词如何衔接资料。区分退款申请、登记与到账证据，核对这些状态在追问中是否仍归属于当前事项。所用场景为自拟文字测试。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

售后追问可另拟两份无金额文字：一份说明退款已经申请，另一份说明相关记录已进入结算核对。它们描述不同阶段，不足以单独证明款项已经到账。提示词应写清本轮需要解释的状态与可用来源，回答中的每一步进度都要回查相应原文。若只给申请记录却生成已完成退款，应保留该句与输入，记录事件依据缺失，不能让历史中的一次完成状态替代当前凭证。

## 配置怎么定

| 对话或实施核对项 | 退款追问的材料范围 | 应保存的证据 |
| --- | --- | --- |
| 状态含义 | 申请、结算核对、到账分开 | 每项进度对应的原文 |
| 历史主体 | 本轮事项及期间保持一致 | 原问、历史和优化后全文 |
| 条件承接 | 登记不能改写成到账 | 主体或状态丢失的具体位置 |
| 新增凭证 | 银行或支付资料实际进入下一轮 | 答案采用的来源 |
| 后续办理 | 对话返回与交接结果分别核验 | 不由格式齐全推定完成 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `提示词与任务` | 说明资料、任务和缺证据处理。 |
| `历史记录` | 核实际提交的历史输入。 |
| `问题优化` | 指代消除与问题扩展需复核。 |
| `模型与长度` | 上下文与回复长度分别核对。 |

## 容易做错的三处

- 退款申请或结算核对被写成款项到账：并列原记录、实际输入和完成句，核支付凭证，申请不证明退款执行。

- “这一笔也到了吗”串到另一交易或期间：保留结算主体、历史与优化问，对照仅含当前原文的新会话，记录错指阶段。

- 到账凭证已补入却未被本轮采用：先查实际输入及引用；原凭证未取得则补源，字段可解析或回复正常都不能代替到账取证。

## 怎么确认配好了

若银行或支付机构的到账凭证尚未提供，结算单里的状态说明不能补出凭证内容。补入新资料时，应记录它是否实际进入下一轮，并检查回答引用哪个来源。财务对账与外部办理的责任仍需实际方案明确；若设计了交接路径，应另核接收结果。结构化回复字段齐全或对话返回正常，均不能代替到账取证，也不能说明售后事项已全部办理。
