# 跨境平台结算与汇兑的订单履约与售后答疑：工作流编排

## 这个品类的数据长什么样

在跨境平台结算与汇兑的订单履约与售后答疑中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

跨境结算中的售后条目，需要先对应订单，再说明该条目记录的是哪种资金处理。自拟测试可以同时给出平台结算中的退款描述和收款对账中的相关条目，但不预设二者属于同一次处理。表单接收原文、资料日期与当前咨询后，检查下一步是否仍保留独立来源，不能把结算扣回、商家退款和客户实际收到款项合成一个已经完成的状态。

## 配置怎么定

| 核对步骤 | 本题自拟输入 | 应核对的实际结果 |
| --- | --- | --- |
| 事件区分 | 平台退款描述与收款对账条目 | 不同资金事件没有合成一个状态 |
| 提交来源 | 订单关联、资料日期及当前问题 | 后续值保留独立出处和范围 |
| 支付错路 | 查支付却只接到结算摘要 | 核路线与传值，保留凭证缺口 |
| 规则与凭证 | 实际退款依据及适用售后政策 | 不从汇率或服务费文字推定结论 |
| 外部请求 | 获授权处理返回及真实业务记录 | 与技术交互结束分别核验 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

需要继续追问时，可分别设计补支付处理记录、核平台条目对应关系或查看售后规则的人工选择。每项都要验证实际接收内容；选了查支付却仅收到结算摘要，就应回查路径和传值，保留到账凭证尚未提供的状态。人员确认两段文字可能有关联，也只为继续核对提供线索，不能直接判定退款是否执行、服务责任或资金结果。 如果冲回说明对应另一结算批次，借它解释本次客户是否收款就会造成对象不一致。应将批次关联、订单说明与收款记录逐项对照，标出尚未对应的条目并交经办方核实；补证后检查答复引用有没有换成当前记录，不能继续沿用此前的到账判断。

## 怎么确认配好了

取得补充后，用原订单问题对照新增来源和最终引用，检查资料身份与范围能否贯通。缺少实际退款凭证或适用政策时，应明确提供者与待核事项，不从汇率表或服务费发票推断售后结论。若还需提交处理请求或更新外部记录，另核业务授权、接口返回和真实记录；对话路径完成只能说明本次技术交互结束，不能作为资金处理或售后办结证明。
