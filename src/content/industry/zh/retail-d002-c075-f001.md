# 达人专场带货合作的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

在达人专场带货合作的订单履约与售后答疑中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。达人专场售后接口要核合作范围、物流来源和返回内容，接通接口不等于承诺已经兑现。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

假设合作说明只限某场展示，售后记录仅称商品已交仓，接口索引有附件名称却没有附件正文。按真实接口契约选地址、方法及参数，将场次和商品标识从前方节点逐项核对。凭证安全注入，请求鉴权与合作权限分别检查。接口返回成功只说明收到其定义的响应，不证明本场售后承诺已履行。

## 配置怎么定

| 专场售后HTTP | 假设证据 | 请求后核验 |
| --- | --- | --- |
| 场次范围 | 仅某场展示 | 对合作原句 |
| 商品标识 | 本场本件 | 核变量映射 |
| 物流阶段 | 交仓记录 | 非送达 |
| 附件内容 | 只有名称 | 查正文覆盖 |
| 业务办理 | 权限另核 | 读取不批准 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

某场展示被答长期售后承诺时，查合作原文；交仓被答送达时，查物流事件；附件名称被答已审全文时，查实际响应正文。三处分别看合作范围、履约阶段和数据覆盖，本例没有真实客户订单或处理效果。

## 怎么确认配好了

验收保存脱敏请求、原始响应和引用片段，确认Body结构及变量满足契约。调试中的身份空值按官方说明判断，不能据此认定业务记录缺失。补齐附件后重新核原问题，承诺确认、发货操作和售后决定需实际业务流程，HTTP读取不授予这些权限。 专场合作的适用页面与售后事项分开定位，承诺相关原句应能回到该场材料。
