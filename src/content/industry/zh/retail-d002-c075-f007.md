# 达人专场带货合作的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

达人专场带货合作的核心是外部达人履约与佣金结算。品牌商务、MCN机构与达人经纪围绕达人合作协议、佣金设置单、样品寄送单和直播战报推进一场合作。这些材料分散在精选联盟、巨量星图、达人历史数据和店铺成交明细中，每场更新战报、每周更新历史数据。订单履约与售后答疑环节的对话日志，需要把某一场合作、某一位达人与某一份结算材料对应起来，避免把不同入口的会话混算。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话日志的身份由 chatId 与 dataId 共同确定。chatId 标识一个应用下某个会话，dataId 标识该会话下某一条对话。核对履约与售后记录时，先按 chatId 定位目标会话，再按 dataId 取单条对话，不能把页面入口的会话与 API 创建的会话合并统计。需要运行详情时，按官方契约在请求中设置 detail，非 stream 模式的结果保存在 responseData 中，stream 模式通过 event 区分。日志中实际返回的字段构成可核对范围，未返回的业务数据保持未知。测试模式与正式调用可能使用不同的身份字段，分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，日志存在不表示合规审计已完成。

假设演练样本：某品牌商务与一位达人签订达人合作协议，协议载明合作对象为“达人A”，合作场次为“2025年6月18日专场”，佣金设置单载明该场佣金比例为“18%”。直播战报显示该场成交金额为“120000元”。现有一条拟稿句待判定：“达人A在2025年6月18日专场的佣金为21600元。”核对时取协议原文的主体与场次、佣金设置单的比例、战报的成交金额，按同一主体、同一场次、同一字段比对。比例与金额相乘得到的结果与拟稿句一致时，该句获得材料支持；任一字段缺失或场次不一致时，该句处于待核实状态。

## 配置怎么定

| 配置项 | 官方已说明内容 | 本页核对动作 |
| --- | --- | --- |
| chatId | 非空字符串时使用该会话，长度小于250 | 核对目标会话的 chatId 与业务记录一致 |
| dataId | 会话下某条对话的 ID | 按 dataId 取单条对话核对内容 |
| detail | 返回中间值，非 stream 存于 responseData | 需要运行详情时设置并检查 responseData |
| source | source=api 获取 API 创建的会话 | 核对会话来源，区分页面会话 |
| responseChatItemId | 传入后作为响应消息 ID 存入数据库 | 核对响应消息与业务记录的对应 |
| variables | 模块变量，替换输入框中的 [key] | 核对传入变量与材料字段的对应 |

假设试验起点：将 detail 设为 true，用于获取运行详情，与 detail 设为 false 时的返回内容比较，确认 responseData 是否出现。

## 容易做错的三处

1. 把页面入口的会话与 API 创建的会话合并统计。检查输入：分别取 source 为 api 与页面来源的会话列表；比较：两者的 chatId 集合；观察结果：若集合存在交集，说明来源区分未生效。
2. 用 chatId 代替 dataId 定位单条对话。检查输入：同一 chatId 下的多条对话；比较：按 dataId 取单条与按 chatId 取全部的结果；观察结果：若单条结果包含其他对话内容，说明定位字段用错。
3. 把日志中未返回的字段当作已留存。检查输入：一次 detail=true 的响应；比较：responseData 中实际出现的字段与业务需要的字段；观察结果：若业务字段未出现在响应中，该字段状态保持未知。

## 怎么确认配好了

1. 输入：假设样本中的协议原文、佣金设置单与战报；比较：拟稿句中的主体、场次、比例与金额；观察结果：三项字段与拟稿句一致时该句获得支持，任一缺失时记录为待核实。
2. 输入：同一 chatId 下按 dataId 取单条对话的请求；比较：返回内容与该 dataId 对应的业务记录；观察结果：内容一致时定位正确，出现其他对话内容时定位失败。
3. 输入：detail 设为 true 与 false 的两次请求；比较：两次返回中 responseData 的有无；观察结果：true 时出现 responseData、false 时不出现，说明该字段按契约生效；若两次均无 responseData，记录为未观察到，不推断原因。
