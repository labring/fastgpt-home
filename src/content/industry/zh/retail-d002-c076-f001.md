# 达人佣金结算与扣佣的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

达人佣金结算与扣佣发生在成交之后，核对对象是有效推广订单、退款扣佣明细、结算账单与发票。精选联盟后台、订单售后数据、财务系统与达人合同构成主要数据来源，更新频率为周或月。财务结算、精选联盟运营与达人商务共同处理这些文档，出错会带来达人纠纷、财务入账错误或合作停摆。本页只处理订单履约与售后答疑环节的 HTTP 接口与外部系统对接，不构造无依据的业务功能。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，实际操作与 Postman、ApiFox 这类工具接近。Params 为路径请求参数，GET 请求中用得居多；Body 为请求体，POST/PUT 请求中用得居多；Headers 为请求头，用于传递特殊信息。三种数据中均可以通过 `{{}}` 引用变量，URL 也可以通过 `{{}}` 引用变量，变量来自全局变量、系统变量与前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 语法提取，输出类型选择字符串时会把对应 key 的值转成 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>；传入的 model、temperature 等参数字段均无效。插件类型应用无需传入 chatId 与 messages，通过 variables 代表插件输入，通过 responseData 中 moduleType=pluginOutput 的元素获取插件输出。交互节点返回的 interactive 只包含 type 和 params，内部运行态字段不会返回。

假设演练样本：一份待核对的结算交接材料原文为「达人甲 2025 年 6 月有效推广订单 80 笔，退款扣佣 12 笔，结算账单金额 6400 元，发票已开具但未付款。」拟交接请求为「将达人甲 6 月结算账单推送至财务系统并标记为已付款。」材料只写到发票已开具、未付款，拟交接请求要求标记已付款，两者对付款状态这一字段的取值不同。材料未载明财务系统接口地址、鉴权方式与推送授权，该请求缺少可执行依据，属于待核实事项，不能视为已获授权。

## 配置怎么定

下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。表中数值为本次假设试验起点，用于与材料原文或接口文档比较，不代表官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 BaseUrl | 财务系统接口文档给出的地址 | 地址可引用变量，需与文档登记值逐字比较 |
| 请求方法 | POST | 推送结算账单属于写入类操作，与文档方法字段比较 |
| Headers 鉴权 | Authorization: Bearer 占位凭证 | 凭证通过安全配置注入，与接口文档鉴权要求比较 |
| Body 字段 | 账单编号、金额、付款状态 | 与材料原文的付款状态取值逐字段比较 |
| 返回值提取 key | data.result | 与接口响应 JSON path 实际结构比较 |
| 调试身份字段 | chatId 与 responseChatItemId 留空 | 测试模式下这两个变量不存在，不把空值当业务故障 |

## 容易做错的三处

1. 把拟交接请求中的「标记为已付款」当成材料已载明的事实。材料原文只写到发票已开具、未付款，付款状态字段的取值与请求要求不同，该请求属于未获支持的待核实事项。
2. 把插件输出获取方式套用到对话接口。插件输出需查找 responseData 中 moduleType=pluginOutput 的元素，对话接口的输出通过 choices 获取，两者取值位置不同。
3. 把传入的 model、temperature 参数当作可改变编排行为的字段。这些字段由编排决定，不会根据 API 参数改变，核对时不应以请求参数取值推断实际运行模型。

## 怎么确认配好了

1. 输入上述样本材料原文与拟交接请求，比较付款状态字段：材料写「未付款」，请求写「标记为已付款」，两者取值不同，判定为待核实，不判定为材料否定付款。
2. 输入一条 POST 请求，比较 Body 中账单编号、金额与材料原文对应值，同时比较返回值提取 key 与接口响应实际 JSON 结构，观察提取结果是否与响应中对应路径的值一致。
3. 输入一条插件类型请求，比较 responseData 中 moduleType=pluginOutput 元素的 pluginOutput 与预期插件输出，观察输出是否从该元素取得；若响应中不存在该元素，记录为未观察到，不推断接口失败原因。
