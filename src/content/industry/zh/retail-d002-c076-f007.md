# 达人佣金结算与扣佣的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

达人佣金结算与扣佣的对话日志，围绕佣金设置记录、结算账单、退款扣佣明细、发票四类文档展开。结算发生在成交之后，核对重点落在有效推广与售后扣佣。数据来源包括精选联盟后台、订单售后数据、财务系统与达人合同，更新频率为周或月。这些材料进入对话系统后，日志与审计环节要处理的是：某次会话是否对应正确的主体、订单与期间，以及接口实际返回了哪些字段。

## 这些特征在「对话日志与审计」这一环带来什么约束

结合 chatId 核对目标对话与业务记录，不同入口的会话不混算。需要对话接口运行详情时，按官方契约设置 detail 并检查 responseData。核对日志与接口实际返回字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。检索与相似度不承担权限或实体隔离，不能把相似度设置当作排除无关业务或未授权记录的手段。

假设演练样本：一份佣金设置记录原文写“2025年3月1日至3月31日，达人甲在直播间A推广商品X，佣金比例按结算账单执行”。一份退款扣佣明细原文写“订单Y于2025年3月20日退款，对应佣金在3月账单中扣减”。一条待判定交接请求写“请把达人甲3月的全部会话日志导出给财务，用于核对扣佣”。该请求含主体、对象与期间，但未载明导出范围是否限于直播间A，也未载明授权状态。

## 配置怎么定

| 配置或核对项 | 本页用途 | 取值与比较方式 |
| --- | --- | --- |
| appId | 定位目标应用，核对会话归属 | 用样本中应用标识与请求体传入值比较 |
| chatId | 定位目标会话，核对业务记录 | 与佣金记录中会话标识逐字比较 |
| detail | 决定是否返回中间值与完整结果 | 样本核对取 true，检查 responseData 是否存在 |
| responseChatItemId | 标记本次响应消息 ID | 与同 chatId 下已有 ID 比较，确认唯一 |
| source | 区分 API 会话与页面会话 | 取 api 时只取 API 创建会话 |
| pageSize 与 offset | 控制会话或对话列表读取范围 | 本次假设起点 pageSize=20，按核对期间调整 |

pageSize=20 为本次假设演练起点，理由是该期间会话量较小，便于逐条比对；比较对象为实际返回的 total 与 list 长度。

## 容易做错的三处

1. 把相似度分数当作权限过滤。输入是检索返回的 score，比较对象是业务归属字段，观察结果是分数高低与是否属于授权范围无关；分数不能排除未授权记录。
2. 把日志存在当作审计完成。输入是会话记录列表，比较对象是财务对账与合规留存要求，观察结果是日志字段与业务方案要求是否一致；不一致时记录缺口。
3. 把测试模式身份字段直接用于正式核对。输入是测试调用返回的身份字段，比较对象是正式调用传入的 appId 与 chatId，观察结果是两者是否一致；不一致时分别核对。

## 怎么确认配好了

1. 针对样本原文，输入佣金设置记录与退款扣佣明细，比较达人甲、直播间A、订单Y与2025年3月期间是否在同一主体同一期间同一字段下对应；满足条件是四者一致，不一致时记录为待核实。
2. 针对待判定交接请求，输入该请求文本与授权边界字段，比较请求导出范围与授权范围；满足条件是请求范围落在授权范围内且授权状态明确，未载明时保留证据缺口。
3. 针对 detail 设置，输入 detail=true 的请求，比较返回中 responseData 是否出现以及字段是否与官方契约一致；满足条件是字段出现且可读，未出现时记录实际观察结果。
