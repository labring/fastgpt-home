# 进出口许可证件办理的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

许可证件办理发生在申报之前，决定货物能否合法进出口，这一时点差异直接影响订单履约的接口设计。日常材料包括自动进口许可证、两用物项许可证、合同与产品说明，来源涉及商务主管部门系统、海关商品编码、供应商资料与客户用途说明。资料更新为不定期、每票一次，HTTP 模块按每票调用外部接口即可，不据此推导批量同步或交易触发机制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径请求参数，Body 用于 POST/PUT，Headers 用于传递特殊信息，三者均可通过 `{{}}` 引用全局变量、系统变量与前方节点输出，URL 同样支持变量引用。返回值配置代表如何解析响应，通过 JSON path 提取，输出类型选字符串时会将对应 key 的值转为 json 字符串。对话接口以 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 `body.appId`，也支持 `Authorization: Bearer <apiKey>-<appId>`；`chatId` 与 `responseChatItemId` 在测试模式下不存在，调试空值不构成业务故障。`detail=true` 时中间值保存在 `responseData`，`stream=true` 时通过 event 区分，交互节点返回的 `interactive` 仅含 `type` 与 `params`。检索或表单只收集值，业务核验、审批、数据库写入与外部同步需要相应的下游实现。

假设演练样本：某外贸合规岗收到一份自动进口许可证申请材料，合同编号 HT-2024-0517，产品说明载明用途为“工业设备零部件装配”，申请日期 2024 年 5 月 17 日，许可证尚未取得。拟稿交接请求为“请协助确认该票许可证已办结并安排发运”。该请求把未取得的许可证当作已办结事实，主体、对象、状态均需重新核对。

## 配置怎么定

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| 请求地址与 HTTP 方法 | 按外部接口文档填写 | 对照接口文档确认地址与方法 |
| Params 与 Headers | 鉴权凭证经安全配置注入 | 逐项核对实际传入值，样例不写入公开凭证 |
| Body | 仅在对应请求类型下启用 | 核对 JSON 结构与外部接口契约 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 逐项核对引用键与实际值 |
| 返回值提取 | 按 JSON path 配置 key | 对照响应示例确认提取路径 |
| detail 与 stream | 按排查需要选择 | 核对 responseData 或 event 分支 |

表中起点为本次假设试验取值，用于纸面核对，不构成默认值。`maxToken`、`similarity`、`limit` 等字段仅按文档所列含义使用，相似度不作为权限或实体过滤条件。

## 容易做错的三处

1. 把测试模式下 `chatId`、`responseChatItemId` 不存在当作接口故障。检查输入是否为测试模式、是否传入了这两个字段，观察返回结构中对应字段是否缺失。
2. 将 `body.appId` 与 `Authorization` 中的 appId 混用而不核对优先级。检查两处取值是否一致，观察实际生效的 appId 与预期是否相同。
3. 把拟稿句“许可证已办结”当作事实写入交接。检查材料原文中许可证状态字段，观察拟稿句与原文是否一致，不一致时记录为待核实。

## 怎么确认配好了

1. 输入假设样本材料原文与拟稿句，比较拟稿句“已办结”与原文“尚未取得”，观察两者是否一致，不一致即判定为未获支持，保留证据缺口。
2. 输入一条含 `{{变量}}` 的请求配置，比较变量引用键与前方节点输出名称，观察实际传入值是否与预期一致，缺失时记录为待核实。
3. 输入 `detail=true` 与 `stream=false` 的请求，比较返回结构中 `responseData` 是否包含节点响应，观察提取路径是否命中，未命中时记录为待核实。
