# 进出口许可证件办理的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样

许可证办理发生在申报之前，决定货物能否合法进出口，日常材料包括自动进口许可证、两用物项许可证、合同与产品说明。订单履约与售后答疑环节产生的对话，往往夹带许可证号、合同条款、用途说明等业务信息，这些信息与商务主管部门系统、海关商品编码、供应商资料、客户用途说明相互对应。资料更新不定期、每票一次，本页不据此推导批量同步或实时触发机制。

对话日志与审计要处理的是：某一笔订单的沟通记录能否与业务单据对齐，运行详情是否被完整取回，反馈与状态字段是否如实留存。日志存在本身不构成合规审计完成。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份依赖 chatId 与 dataId。chatId 标识一个应用下的某个会话，dataId 标识一个会话下的某条对话。不同入口创建的会话来源不同，获取会话列表时 source=api 只取通过 API 创建的会话，不取页面上的会话。核对时须确认目标会话与业务记录同源，不能把不同入口的会话混算。

需要运行详情时，按官方契约在请求体设置 detail=true，非流式结果保存在 responseData 中；流式通过 event 区分，节点完整响应在 flowResponses。responseData 中不同模块的字段随版本可能有差异，未返回的业务数据不能推定已完整留存。传入的 model、temperature 等参数字段无效，由编排决定。

测试模式与正式调用的身份字段可能不同，须分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：材料原文为“本票货物为自动进口许可证项下，合同号 HT-2024-0317，买方为境内某机械制造企业，卖方为境外供应商，用途说明载明用于自有生产线装配，许可证申请状态为已提交待审批。”待判定的拟稿句为“该票自动进口许可证已获批，可安排出运。”原文只显示已提交待审批，拟稿句把待审批说成已获批，属于未获支持。

## 配置怎么定

下表为本次假设试验的配置起点与核对项，数值为假设起点并注明比较对象，不属官方默认值。

| 配置项 | 本次假设起点 | 理由与比较方法 |
| --- | --- | --- |
| chatId | 沿用同一业务单据对应的会话 ID | 与业务记录中的会话标识比对，确认同源 |
| dataId | 取目标对话的对话 ID | 与获取对话列表返回的 dataId 比对，逐条对应 |
| detail | 设为 true | 需要运行详情时启用，与 false 时返回内容比对 |
| source | 取 api | 与会话列表返回的 source 比对，排除页面会话 |
| loadCustomFeedbacks | 设为 true | 需要读取自定义反馈时启用，与 false 时列表比对 |
| pageSize | 本次假设取 10 | 与返回 list 条数及 total 比对，按需调整 |

## 容易做错的三处

1. 把待审批当作已获批。样本中许可证申请状态为已提交待审批，拟稿句写成已获批，输入是状态字段，比较对象是原文“待审批”与拟稿“已获批”，两者在同一字段上互斥，判定为未获支持。
2. 混算不同入口的会话。获取会话列表时 source=api 只取 API 创建的会话，若把页面会话计入，输入是 source 取值，比较对象是返回列表的 source 字段，出现非 api 记录即说明混算。
3. 把日志存在当作合规审计完成。输入是对话记录，比较对象是业务方案要求的留存与对账材料，缺少对应材料时只能记录缺口，不能判定审计完成。

## 怎么确认配好了

1. 核对对话身份。输入样本中的 chatId 与 dataId，比较对象是获取对话列表返回的 chatId、dataId，两者逐条一致才满足条件；不一致时记录缺口。
2. 核对运行详情取回。输入 detail=true 的请求，比较对象是返回的 responseData 中各模块字段，与业务单据字段逐一比对；字段缺失时记录为未获支持，不断言已完整留存。
3. 核对拟稿句与原文。输入样本原文与拟稿句，比较对象是许可证状态字段，原文为待审批、拟稿为已获批，同字段互斥取值构成矛盾，判定为未获支持。预期为记录矛盾，不声称已实测。
