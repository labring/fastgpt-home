# 进出口许可证件办理的订单履约与售后答疑：知识库检索与召回

## 这个品类的数据长什么样

许可证办理发生在申报之前，决定货物能否合法进出口，检索结果若引用错误证件类型，会直接影响履约判断。资料来自商务主管部门系统、海关商品编码、供应商资料和客户用途说明，每票业务都要重新核对。日常文档包括自动进口许可证、两用物项许可证、合同和产品说明，同一票业务中这些材料的主体、货物范围和有效期需要保持一致。知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨模型的库不能共同关联，核对时先确认向量模型标识，再排除不符合者。

## 这些特征在「知识库检索与召回」这一环带来什么约束

许可证类材料包含证件编号、商品编码和用途表述，全文检索适合编号和专有名词，语义检索适合自然语言问法，混合检索通过 RRF 融合多路结果。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离功能，检索召回不代表某条许可证已获授权或合同已生效。引用上限以 token 为单位，长短差异大的材料需要实际测试后再调整。问题优化用于指代消除和问题扩展，会增加一次模型调用，可能改变问题主体，需要对比原问题与优化后问题。

假设演练样本：某外贸合规岗在订单履约答疑中收到客户追问。知识库中一份产品说明原文为：“本产品用于工业设备润滑，不属于两用物项管制范围。”另有一份合同原文为：“卖方应在收到自动进口许可证后十个工作日内安排发货。”一条待判定的拟稿句为：“该合同已生效，货物可立即发运。”核对时比较合同原文与拟稿句：合同原文只说明发货条件与许可证挂钩，未载明合同生效状态，也未载明许可证已取得，拟稿句的主体、状态和条件均缺少原文支持，应记录为待核实。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联同一向量模型的许可证与合同库 | 先核对向量模型标识，排除不同模型库，不执行跨模型检索比较 |
| 搜索模式 | 先用混合检索 | 对同一测试问题分别比较语义、全文与混合结果，按命中情况取舍 |
| 引用上限 | 设为能覆盖一份完整产品说明的 token 量 | 用长短不同的实际材料测试内容是否被截断，再调整 |
| 最低相关度 | 先标注相关与无关样本再定阈值 | 仅在语义检索或结果重排时生效，按标注样本比较过滤效果 |
| 问题优化 | 对多轮追问开启，对编号类问题关闭 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 候选较多时启用 | 重排须具备模型并按设置启用，用重排得分与向量得分比较 |

## 容易做错的三处

1. 把检索命中当作授权状态。输入是拟稿句“该合同已生效，货物可立即发运”，比较对象是合同原文，原文未载明生效状态，可观察结果是拟稿句缺少原文支持，应记录为待核实，不能写成合同未生效。
2. 把最低相关度当作权限或实体过滤。输入是一条无关查询，比较对象是检索设置，可观察结果是该设置只过滤低相关度内容，不排除未授权记录，检索结果仍需人工核对授权边界。
3. 把混合检索的 RRF 当作可开启的独立开关。输入是搜索模式设置，比较对象是文档说明，可观察结果是 RRF 是混合结果融合过程，配置项是搜索模式，不能写成单独启用 RRF。

## 怎么确认配好了

1. 输入假设样本中的拟稿句与合同原文，比较主体、状态和条件是否一致，可观察结果是拟稿句缺少原文支持时记录为待核实，出现与原文同字段互斥取值时才记录为矛盾。
2. 输入同一测试问题，分别使用语义检索、全文检索和混合检索，比较三组结果的命中内容，可观察结果是编号类问题在全文检索中命中，自然语言问题在语义检索中命中，混合检索结果更丰富时按实际观察记录。
3. 输入空引用结果，比较下游设计是否承接长度为零的引用数组，可观察结果是输出链路走通，不能声称虚构规则检索一定返回空数组。
