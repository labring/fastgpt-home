# 连锁统采统配的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

连锁统采统配的履约数据来自 ERP 采购、WMS、门店 POS 与供应商交货数据，日常文档包括集采合同、补货计划、配送单和门店要货单。订单履约与售后答疑要处理的材料因此带有跨系统、跨主体的特征：一份配送单同时牵涉总部采购、配送中心和收货门店，一次售后答疑可能同时引用集采合同的交付条款和门店要货单的实际数量。HTTP 接口与外部系统这一环的任务，是把这些材料中的关键字段通过 HTTP 模块传给外部业务服务，并从响应中取回可核对的结果。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径请求参数，Body 用于请求体，Headers 用于请求头。三种数据均可通过 {{}} 引用变量，URL 也可以引用变量。变量来源为全局变量、系统变量和前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories；其中 chatId 与 responseChatItemId 在测试模式下不存在，调试时出现的空值属于运行环境差异，不能当作业务故障。

返回值配置不代表接口本身的返回，而是通过 JSON path 语法提取响应中的值；输出类型选择字符串时，会把对应 key 的值转为 json 字符串。对话接口调用时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>；传入的 model、temperature 等字段由编排决定，不随 API 参数改变。这些约束意味着：履约字段的传递依赖编排中已定义好的变量与提取规则，接口调用不会因为外部传入参数而改变编排行为。

假设演练样本（纸面材料，用于说明核对方法，未实际执行）：

材料一，某连锁供应链中心与某供应商签订的集采合同节选：「本合同项下配送单以总部采购系统生成的编号为准，收货门店应在配送单载明到货日后两个工作日内完成签收确认。」

材料二，同一批次的补货计划节选：「本次补货计划覆盖华东区 12 家门店，计划配送日期为 3 月 10 日，实际配送以配送单为准。」

待判定的拟稿句：「配送单已由门店签收，售后答疑可直接引用签收结果。」

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址与方法 | 按外部业务服务文档填写，地址中可引用变量 | 与外部接口契约逐项比对路径与方法是否一致 |
| Params 与 Headers | 鉴权凭证通过安全配置注入，不写入公开样例 | 核对请求头中的凭证来源是否为已配置变量 |
| Body 结构 | 仅在相应请求类型下使用，字段名与外部契约一致 | 将 Body 声明与外部接口文档逐字段比对 |
| 变量引用 | 引用全局变量、系统变量或前方节点输出 | 逐项核对实际传入值与材料原文是否对应 |
| 返回值提取 | 按 JSON path 语法配置 key 与输出类型 | 用材料中已知字段验证提取结果与原文一致 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 测试模式出现空值时记录为环境差异，不判为故障 |

表中数值均为本次假设试验起点，用于说明比较方法，不是官方默认值。

## 容易做错的三处

1. 把测试模式下 chatId 或 responseChatItemId 为空当成业务故障。检查方式：输入测试模式请求，比较响应中这两个字段是否存在，观察是否与正式模式一致；文档已说明测试模式下不存在，空值本身不构成故障证据。
2. 把返回值配置当成接口本身的返回值。检查方式：输入一段已知响应，比较配置的 key 与 JSON path 提取结果，观察提取值是否等于响应中对应字段；配置只决定如何解析，不改变接口返回。
3. 把集采合同中的签收确认条款直接当作已完成签收。检查方式：输入上述材料一与材料二，比较拟稿句中「已由门店签收」与材料中「应在到货日后两个工作日内完成签收确认」的表述，观察材料是否载明实际签收动作与签收日期；材料只给出应然要求，未载明实际签收事实，该拟稿句属于未获支持。

## 怎么确认配好了

1. 输入上述材料一、材料二与拟稿句，比较拟稿句中「已由门店签收」与材料原文的签收表述，观察材料是否包含实际签收主体、签收日期与签收结果；若仅有应然条款，则记录为未获支持，保留证据缺口。
2. 输入一条包含已知字段的响应示例，比较配置的 key 与 JSON path 提取结果，观察提取值是否与响应中对应字段一致；若不一致，记录实际提取值与预期字段的差异。
3. 输入测试模式请求，比较响应中 chatId 与 responseChatItemId 的存在情况，观察是否与文档所述测试模式行为一致；若为空，记录为环境差异，不据此判定业务故障或授权状态。
