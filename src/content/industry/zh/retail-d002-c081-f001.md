# 连锁门店闭店清算的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

在连锁门店闭店清算的订单履约与售后答疑中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。闭店后的订单服务查询仍要核本单物品和处理结果，闭店批准与资产清点不能代替客户售后凭据。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

自拟客户问本单物品去向，输入有闭店批准与资产清单，却没有订单接收关系，退款仍待处理。HTTP读取应先核真实服务按什么对象查本单，不把门店资产当客户物品。批准只说明决定，清点只覆盖列明资产；门店状态变化不能自动结束售后，返回闭店文件也不支持资金已退。尚缺关系时应说明资料不足，不自行选择处理去向。

## 配置怎么定

| 闭店售后读取 | 自拟材料所指 | 需要分开 |
| --- | --- | --- |
| 闭店批准 | 门店决定 | 非本单结案 |
| 资产清单 | 列明店内资产 | 非客户物品 |
| 订单关系 | 接收对应缺 | 补本单依据 |
| 退款待办 | 仍处理中 | 非资金已退 |
| 空查询 | 先核范围权限 | 不推物品丢失 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

闭店冒结案：若批准被写成本单已结束，应查实际售后结果；资产冒客货：若清点项目用于客户物品，应核身份对应；待办冒退款：若处理中被答成已退，应取本次资金执行记录。三项分别核决定范围、物品归属和动作阶段，不能由门店同名合并。

## 怎么确认配好了

验收保存实际发送和返回原文，补订单物品关系后重查，只更新对应去向说明。空响应先核权限、范围与来源完整性，不能推定物品已丢失。合同解除、资产处置、退款和客户通知需另接业务步骤核权限及回执；HTTP读取不执行这些动作，也不从闭店材料判断债务或责任，实际处理仍需本单证据。
