# 连锁门店闭店清算的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样
连锁门店闭店清算围绕退出与资产回收展开，方向与选址开店相反。门店关闭涉及闭店审批、库存清退单、租约解除协议、资产盘点表，这些材料不定期按店产生，来自POS库存、固定资产系统、租赁合同与财务账。订单履约与售后答疑环节需要回答押金退还进度、库存清退状态、员工与加盟款结算等问题，回答依据分散在上述材料中。对话日志与审计要求把每次问答关联到具体门店、具体单据和具体会话，避免把不同门店的会话混算。资料未说明日志留存期限，也未说明日志与财务系统自动对接，这些内容保持未知。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话接口使用chatId标识一个应用下的会话，dataId标识会话下的某次对话。传入chatId时系统从数据库取会话，以messages最后一条作为用户问题，其余message被忽略。传入responseChatItemId时该值作为本次响应消息ID存入数据库，需在当前chatId下唯一。detail=true时responseData包含模块状态与完整结果，非stream模式结果保存在responseData中。这些字段用于定位日志，不构成对业务记录的授权。检索返回的quoteList与score反映语义相似程度，不承担门店归属或权限过滤职责。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某连锁品牌运营人员提交一条交接请求，附材料原文为“门店A闭店审批已通过，库存清退单编号QC-001状态为待复核，租约解除协议尚未签署。”拟稿句为“门店A库存清退已完成，押金可退还。”待判定该拟稿句是否与材料一致。

## 配置怎么定
下表围绕上述样本列出与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，仅用于比较，不作为官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| chatId | 按门店A闭店会话建立唯一字符串 | 与门店A其他会话比较，确认不与其他门店共用 |
| detail | true | 需查看responseData中间值，与false时仅返回choices比较 |
| stream | false | 样本为单次核对，与非stream响应保存于responseData一致 |
| responseChatItemId | 本次核对固定值 | 与同chatId下其他值比较，确认唯一 |
| 核对字段 | 库存清退单status、租约解除协议签署状态 | 与材料原文逐字比较，不推定未载明状态 |
| 日志关联 | 按chatId与dataId定位 | 与业务单据编号比对，确认同一门店同一期间 |

## 容易做错的三处
1. 把“待复核”当作“已完成”。材料原文写库存清退单状态为待复核，拟稿句写库存清退已完成，两者在同字段上取值不同，构成不一致。
2. 把“尚未签署”当作已生效。租约解除协议尚未签署，拟稿句据此推出押金可退还，缺少签署与生效证据。
3. 把检索相似度当作门店过滤。quoteList的score只反映语义相似，不能据此认定记录属于门店A或已获授权。

对应检查：
1. 输入材料原文与拟稿句，比较库存清退单status字段取值，出现“待复核”与“已完成”并存即判定不一致。
2. 输入租约解除协议签署状态，比较是否存在签署完成记录，仅有“尚未签署”时判定押金退还条件未获支持。
3. 输入quoteList，比较返回记录的datasetId与门店A业务单据标识，score高低不作为归属或权限依据。

## 怎么确认配好了
- 验证一：输入材料原文“库存清退单编号QC-001状态为待复核”与拟稿句“门店A库存清退已完成”，比较同字段取值，出现“待复核”与“已完成”互斥取值即满足不一致判定条件。预期结果为判定拟稿句与材料不一致，不声称已实测。

- 验证二：输入材料原文“租约解除协议尚未签署”与拟稿句“押金可退还”，比较签署状态字段，未载明签署完成时判定退还条件未获支持。预期结果为记录证据缺口，不补造授权或生效条款。

- 验证三：输入本次对话的chatId、dataId与responseChatItemId，比较responseChatItemId在当前chatId下是否唯一，并核对detail=true时responseData是否包含对应节点。预期结果为定位到同一门店同一会话的日志，不据此认定已完成合规审计。
