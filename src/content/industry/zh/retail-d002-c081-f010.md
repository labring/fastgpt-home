# 连锁门店闭店清算的订单履约与售后答疑：引用来源与溯源

## 这个品类的数据长什么样

连锁门店闭店清算处理退出与资产回收，方向与选址开店相反。主要数据来源包括 POS 库存、固定资产系统、租赁合同与财务账，日常文档为闭店审批、库存清退单、租约解除协议与资产盘点表。这些材料分散在不同系统与线下签署环节，订单履约与售后答疑时若引用来源标注不清，押金损失、资产流失或加盟纠纷的后果会因缺少可追溯依据而放大。数据更新为不定期、每店，本页不涉及批量同步或实时触发机制。

## 这些特征在「引用来源与溯源」这一环带来什么约束

知识库搜索节点可关联一个或多个相同向量模型的知识库，输出引用内容为数组，长度可以为 0，空数组时输出链路仍走通。检索结果交给回答环节后，需逐条核对回答与引用原文，不以思考过程或回答流畅度替代来源证据。语义召回与相关度分数仅用于排序与过滤，不承担权限或实体隔离；检索本身不构成授权。资料时效需用当前版与历史版文档分别测试来源，是否采用引用仍须结合有效版本审核。

假设演练样本：某连锁品牌运营人员处理已签约门店的退租交接，提供材料原文为「租约解除协议（草稿）载明：甲方与乙方就某路 12 号铺位达成解除意向，签署日期空白，双方盖章处均未填写。」拟稿句为「该门店租约已解除，押金已退还。」待判定该拟稿句是否有来源支持。

## 配置怎么定

| 核对项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 关联知识库 | 仅选入含闭店清算材料的同一向量模型库 | 与现有库的向量模型标识比较，排除不同模型库 |
| 引用上限 | 设为 2000 tokens | 与样本材料总长度比较，确认覆盖退租协议与盘点表 |
| 最低相关度 | 设为 0.5 | 与语义检索得分比较，观察低分片段是否被过滤 |
| 搜索模式 | 混合检索 | 与纯语义检索结果比较，核对编号类字段命中情况 |
| 问题优化 | 关闭 | 与开启后耗时比较，样本问题主体完整时无需补全 |
| 引用展示 | 开启原文展示 | 与回答文本比较，逐条核对引用与原文一致性 |

上述数值为本次假设试验起点，非官方默认值。引用上限使用 tokens 单位，thinking budget 为思考预算，不得移作引用 token 上限。RRF 为混合结果融合过程，不作为可开启开关。

## 容易做错的三处

1. 把检索命中当作授权完成。错误表现：将「检索到退租协议草稿」直接写成「租约已解除」。检查：输入样本材料原文，比较拟稿句与原文的签署状态字段，原文签署日期空白且盖章未填写时，拟稿句未获支持。
2. 把空引用输出当作流程失败。错误表现：引用数组为 0 时判定工作流报错。检查：输入明确的纸面空数组 []，比较下游节点设计，确认空数组时输出链路仍走通。
3. 把不同向量模型库共同关联。错误表现：将不同向量模型的库一起选入。检查：核对各库向量模型标识，排除不符合者并记录实际观察，不执行跨模型检索来比较漏召回。

## 怎么确认配好了

1. 输入假设样本材料原文与拟稿句，比较拟稿句「租约已解除，押金已退还」与原文「签署日期空白，盖章未填写」，预期结果为该拟稿句未获支持，需记录证据缺口。
2. 输入纸面空数组 []，比较下游节点对空引用的承接设计，预期结果为输出链路走通且不判定为报错，不声称虚构规则检索一定返回 []。
3. 输入含退租协议与资产盘点表的检索请求，比较返回引用与原文逐条对应关系，预期结果为引用可追溯至具体材料，若出现无原文对应的引用则记录为待核实。
