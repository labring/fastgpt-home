# 逆向退货入仓质检的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样

逆向退货入仓质检处理的是退回包裹与商品等级，数据来源包括 WMS 退货模块、平台售后、承运商退件与质检台。每件退件都会生成退货入库单，质检环节产生质检照片与等级判定表，判定为重售时生成重售上架单。这些材料共同决定一件退货商品能否回到可售库存。在订单履约与售后答疑场景中，HTTP 接口与外部系统承担把退货入库单、质检照片、等级判定表、重售上架单的字段传给外部售后或库存系统的职责。文档更新频率为每件、日，本页不据此推出批量同步或实时触发机制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 用于路径请求参数，Body 用于请求体，Headers 用于请求头，三者均可通过 {{}} 引用全局变量、系统变量或前方节点输出，URL 同样可引用变量。返回值通过 JSON path 语法提取，输出类型选字符串时会把对应 key 的值转成 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>。chatId 与 responseChatItemId 在测试模式下不存在，调试时出现空值属于该模式特征。detail=true 时返回中间值，stream 模式下通过 event 区分，非 stream 模式结果保存在 responseData 中。

假设演练样本：某售后仓质检员在 2025 年 6 月 10 日处理退货入库单 TH-20250610-018，对象为一件退回的保温杯，等级判定表记录状态为"待复检"，质检照片已上传但复检结论未填写。现拟向外部售后系统发送一条交接请求，内容为"该退件已判定为可重售，请同步库存"。该拟稿句的主体是售后仓质检员，对象是 TH-20250610-018 的保温杯，状态为待复检，有效范围限于该单。核对重点是：等级判定表当前状态与拟稿句所称"已判定为可重售"是否同主体、同期间、同一字段。

## 配置怎么定

| 配置项 | 本页取值或核对动作 | 依据与边界 |
| --- | --- | --- |
| 请求地址与方法 | 按外部售后系统接口文档填写 URL 与方法，URL 可引用变量 | HTTP 模块文档说明地址与变量引用 |
| Headers | 按外部接口契约填写请求头，鉴权凭证安全注入 | 文档说明 Headers 用于传递特殊信息 |
| Body | 仅在该请求类型下使用，核对 JSON 结构与外部契约 | 文档说明 Body 在特定请求类型下生效 |
| 变量引用 | 逐项核对全局变量、系统变量、前方节点输出的实际传入值 | 文档说明三类变量来源 |
| 返回值提取 | 用 JSON path 语法配置 key，输出类型按需选择 | 文档说明返回值解析方式 |
| 鉴权与身份 | 核对 body.appId 或 Authorization 形式，测试模式下 chatId 与 responseChatItemId 不存在 | 对话接口文档说明 |

上述取值均为本次假设试验起点，选择理由是与样本单字段对应，比较对象是外部接口文档所列字段。

## 容易做错的三处

1. 把等级判定表的"待复检"当作"已判定可重售"。输入为样本单 TH-20250610-018 的等级判定表状态字段，比较对象是拟稿句"已判定为可重售"，观察结果是两者在同一字段上取值不同，属于未获支持。
2. 把测试模式下 chatId 与 responseChatItemId 不存在当作业务故障。输入为测试模式请求，比较对象是文档说明的这两个字段在测试模式下不存在，观察结果是调试空值符合该模式特征。
3. 把 HTTP 返回值提取当作业务授权。输入为 responseData 中的字段，比较对象是外部系统的授权状态，观察结果是提取到值不表示外部系统已执行库存同步，该动作需另接系统实现。

## 怎么确认配好了

1. 以样本单 TH-20250610-018 的等级判定表原文为输入，比较拟稿句"已判定为可重售"与原文状态字段，若原文为"待复检"则拟稿句未获支持，需记录证据缺口。
2. 以测试模式请求为输入，比较 chatId 与 responseChatItemId 是否如文档所述不存在，若确实不存在则符合测试模式特征，不判定为业务故障。
3. 以 HTTP 返回值为输入，比较提取到的字段与外部系统实际授权或执行状态，若仅有返回值而无外部执行记录，则库存同步处于待核实状态。
