# 逆向退货入仓质检的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样
逆向退货入仓质检处理的是退回包裹与商品等级，不处理新订单出库。日常材料包括退货入库单、质检照片、等级判定表、重售上架单，数据来源覆盖 WMS 退货模块、平台售后、承运商退件与质检台，更新频率为每件、每日。售后仓、质检员、库存管理员在订单履约与售后答疑中调用对话日志，核对某次退货质检的会话记录与运行详情。质检结论牵动退款争议与库存污染，日志留存与字段完整性直接影响责任追溯。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话身份需要结合 chatId 核对目标对话与业务记录，不同入口的会话不混算。需要运行详情时按官方契约设置 detail 并检查 responseData；未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，需分别核对输入、历史与返回内容。日志存在本身不构成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某售后仓一张退货入库单记载“退件单号 RT-0001，商品为折叠椅，质检员判定为 B 级可重售，日期 2025 年 3 月 10 日，数量 2 件”。同批质检照片标注“椅面划痕，不影响结构”。一条待判定拟稿句为“该退件已通过质检并完成重售上架”。核对材料原文只说明等级判定为 B 级可重售，未载明重售上架单已生成或上架动作已执行，该拟稿句超出原文支持范围，属于未获支持。

## 配置怎么定
下表围绕上述样本，列出本功能与主任务相关的官方已说明设置或实施核对项。数值仅为本次假设试验起点，用于与同字段实际返回值比较，不属官方默认值。

| 配置项 | 本次假设起点 | 核对方法与理由 |
| --- | --- | --- |
| chatId | 假设填 RT-0001-001 | 与退货入库单号关联核对，确认会话归属同一退件 |
| detail | 假设设为 true | 需读取 responseData 中的模块运行详情，与关闭时返回内容比较 |
| appId | 假设填本应用 ID | 与密钥鉴权路径核对，确认会话属于目标应用 |
| responseChatItemId | 假设填 RT-0001-001-A | 在同一 chatId 下核对唯一性，避免响应消息 ID 重复 |
| stream | 假设设为 false | 非流式便于直接读取 choices 与 responseData，与流式 event 分支比较 |
| loadCustomFeedbacks | 假设设为 true | 读取对话列表时核对自定义反馈字段是否随记录返回 |

## 容易做错的三处
1. 把质检照片标注“椅面划痕，不影响结构”当作重售上架已完成的证据。照片只支持外观状态描述，不支持上架动作。检查时输入照片原文与拟稿句，比较拟稿句是否出现“已上架”这类原文未载明的完成态，观察结果为拟稿句含未获支持表述。
2. 把退货入库单的 B 级判定直接写成退款已批准。等级判定与退款审批是不同事实。检查时输入入库单原文与含“退款已批准”的拟稿句，比较两者字段，观察结果为原文无审批字段，拟稿句超出范围。
3. 用测试模式下的 chatId 去核对正式业务记录。测试身份字段与正式调用可能不同。检查时输入测试会话的 chatId 与正式入库单号，比较两者归属，观察结果为标识不一致，需排除该会话。

## 怎么确认配好了
1. 输入上述假设样本原文与拟稿句“该退件已通过质检并完成重售上架”，比较拟稿句是否出现原文未载明的完成动作，观察结果为拟稿句含“完成重售上架”而原文仅有“B 级可重售”，判定为未获支持。
2. 输入 detail=true 与 detail=false 两种请求，比较返回结构中是否出现 responseData 及模块运行详情，观察结果为 detail=true 时返回 responseData，detail=false 时不返回，据此确认运行详情读取路径。
3. 输入同一 chatId 下两个相同 responseChatItemId 的请求，比较返回结果与数据库记录，观察结果为需人工核对唯一性约束是否被违反，若重复则记录为待核实，不推定系统自动拒绝。
