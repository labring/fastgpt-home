# 门店盘点与防损的订单履约与售后答疑：HTTP 接口与外部系统

## 这个品类的数据长什么样
门店盘点与防损围绕账实差异与损耗展开，不处理供应商账款。主要数据来自 POS 库存、WMS、监控系统与 SB/T 盘点规范。日常文档包括盘点表、差异分析、报损审批与监控调阅记录。从业主体为商超防损部、门店库管与财务稽核，数据更新频率为月或季度。订单履约与售后答疑环节需要把盘点差异、报损状态与调阅结论通过 HTTP 接口交给外部系统，接口本身不产生审批效力。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params 用于路径请求参数，Body 用于 POST/PUT，Headers 用于传递特殊信息。URL、Params、Headers、Body 均可通过 {{}} 引用全局变量、系统变量或前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories。chatId 与 responseChatItemId 在测试模式下不存在，调试时出现的空值属于该模式特征。返回值通过 JSON path 或 JS 对象取值规则提取，输出类型选字符串时会把对应 key 的值转成 json 字符串。对话接口以 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId；appId 优先级为 body.appId、apiKey-appId、apikey 关联的 appId。传入的 model、temperature 等字段无效，由编排决定。

假设演练样本：某门店防损部于 2025 年 3 月 10 日整理 2 月闭店盘点结果，材料原文为“盘点表 A-02 记录 SKU 1043 账面 120 件、实盘 96 件，差异 24 件；差异分析初稿标注‘待库管复核’；报损审批单 B-07 状态为‘已提交，待防损主管审批’”。现拟通过 HTTP 接口向外部系统提交一条交接请求，拟稿句为“SKU 1043 差异 24 件已确认损耗，报损审批已通过，请外部系统按已批准报损同步库存”。该拟稿句与材料原文不一致：差异分析仍待复核，报损审批处于已提交待审批状态。

## 配置怎么定
下表围绕上述样本列出与本页功能、主任务相关的官方已说明设置或实施核对项。数值仅作本次假设试验起点，用于与材料原文比对，不代表官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 外部系统提供的接收地址 | 地址与方法按外部接口文档选择，地址可引用已提供变量 |
| Headers 鉴权 | Authorization 引用安全配置中的凭证 | 凭证通过安全配置注入，不写入公开样例 |
| Body 字段 | 差异 SKU、差异数量、报损状态 | 与盘点表 A-02、报损审批单 B-07 原文逐字段比对 |
| 变量引用 | 引用前方节点输出的差异数量 | 核对实际传入值是否等于材料原文的 24 件 |
| chatId | 本次会话标识 | 测试模式下不存在，不作为业务故障判断依据 |
| 返回值提取 | 按 JSON path 提取外部响应字段 | 输出类型选字符串时转为 json 字符串，核对提取结果 |

## 容易做错的三处
1. 把“待防损主管审批”当成审批通过，在 Body 中填写已批准报损。输入为报损审批单 B-07 的状态原文，比较对象是“已提交，待防损主管审批”与拟稿句“报损审批已通过”，可观察结果为两者状态不一致。
2. 把差异分析初稿的“待库管复核”当成已确认损耗。输入为差异分析初稿标注，比较对象是“待库管复核”与拟稿句“已确认损耗”，可观察结果为复核状态尚未完成。
3. 把测试模式下 chatId 或 responseChatItemId 不存在当成接口故障。输入为测试模式请求，比较对象是文档说明的“测试模式下不存在”与实际返回，可观察结果为该空值属于模式特征，需另找业务原因。

## 怎么确认配好了
1. 输入假设样本中的盘点表 A-02 原文与拟稿句，比较 SKU 1043 的差异数量 24 件与拟稿句中的 24 件，观察两者数量一致而状态描述不一致。
2. 输入报损审批单 B-07 的状态原文与拟稿句，比较“已提交，待防损主管审批”与“报损审批已通过”，观察拟稿句缺少审批完成证据，该请求处于待核实状态。
3. 输入差异分析初稿标注与拟稿句，比较“待库管复核”与“已确认损耗”，观察复核未完成，不能将该差异作为已确认损耗提交外部系统。
