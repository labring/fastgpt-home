# 门店盘点与防损的订单履约与售后答疑：对话日志与审计

## 这个品类的数据长什么样
门店盘点与防损围绕账实差异与损耗展开，处理对象是盘点表、差异分析、报损审批与监控调阅记录，不涉及供应商账款结算。数据来源含 POS 库存、WMS、监控系统与 SB/T 盘点规范，更新节奏以月、季度为主。防损部、门店库管与财务稽核共同使用这些材料，库存失真、毛利虚高与员工舞弊是主要后果。

在订单履约与售后答疑环节，对话日志与审计要回答的问题是：某次答疑是否基于正确的会话、正确的运行详情与正确的字段留存。日志存在本身只说明发生过一次调用，不能推出对账、留存与合规审计已经完成，这些要求由完整业务方案另行落实。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话身份需要结合 chatId 核对目标对话与业务记录，不同入口的会话不能混算。获取会话列表时 source=api 只取通过 API 创建的会话，不包含页面上的会话。需要运行详情时按官方契约设置 detail，并在 responseData 中查看模块状态与完整结果。核对日志与接口实际返回字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，输入、历史与返回内容要分别核对。

假设演练样本：某门店防损部于 2025 年 3 月 10 日闭店盘点后，就一笔报损审批向答疑应用提问。供核对的材料原文为：“盘点表 P-20250310 记录 SKU 8842 账面 120 件、实盘 96 件，差异 24 件；差异分析单 A-0310 标注待核实；报损审批单 B-0310 状态为待审核。”拟判定的交接请求为：“请确认该 SKU 差异已审批通过并完成报损。”此请求把待审核状态当作已完成审批，材料中无任何审批通过或已报损的记载。

## 配置怎么定
下表为本次假设试验起点，用于核对本页文档相关字段，非官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| chatId | 门店盘点答疑专用值 | 保证同一会话内取历史，与页面会话分开比较 |
| source | api | 只取 API 创建会话，与页面来源列表比对条目差异 |
| detail | true | 需要 responseData，与 false 时返回结构比较 |
| responseChatItemId | 每次调用唯一 | 与同 chatId 内已有值比较，避免覆盖 |
| loadCustomFeedbacks | true | 取对话列表时读取自定义反馈，与 false 结果比较 |
| pageSize | 20 | 与 total 比较，判断是否需继续翻页 |

## 容易做错的三处
1. 把待审核当作已审批。样本中报损审批单 B-0310 状态为待审核，拟稿句却称已审批通过并完成报损，主体、对象、期间一致而状态字段互斥，属未获支持。
2. 把日志存在当作合规审计完成。会话列表能取到记录，只说明调用发生，对账、留存与合规要求仍需另接系统实现。
3. 把检索当作授权。按相似度取回报损相关片段，不构成对报损操作的权限，审批与数据库写入须有下游实现。

## 怎么确认配好了
1. 输入样本材料原文与拟稿句，比较报损审批单状态字段“待审核”与拟稿句“已审批通过”，若两者在同一审批单上互斥，则判定拟稿句未获支持，保留证据缺口。
2. 输入同一 chatId 与不同 responseChatItemId，比较返回的响应消息 ID 是否唯一，若出现重复则说明唯一性未满足。
3. 输入 source=api 的会话列表请求，比较返回条目与页面会话来源，若列表不含页面会话则符合文档所述范围；若预期为空，可用纸面输入 [] 核对下游设计，不声称虚构规则检索必返回空。
