# B2B平台撮合交易的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

在B2B平台撮合交易的商品与营销文案起草中，本页说明FastGPT的模型接入与配置如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「模型接入与配置」这一环带来什么约束

询报价里“外观可按规格讨论”可以支持邀请进一步沟通的文案，但讨论状态不能改成产品已经定型、功能已测试或认证已取得。接入检查应保留这句的限定，再逐个查看草稿中的动作词：讨论、供应、具备和保证表达的承诺不同。即使商品名完全没变，动词变化也可能把协商意向写成已证实能力。应把草稿交回供稿者的原句核对，确认哪些只是复述、哪些新增了断言，再为新增属性取得对应资料，不用品牌或企业介绍填补单品证明。

## 配置怎么定

| 接入或实施核对项 | 本轮文案依据 | 应保存的证据 |
| --- | --- | --- |
| 文字送达 | 按规格讨论外观的原文 | 实际请求与附页对应 |
| 声明范围 | 未给性能、认证或市场效果 | 草稿扩展逐项回查 |
| 资料类型 | 经营范围与具体产品分开 | 不合成为产品已认证结论 |
| 接入配置 | 服务地址及管理员认证 | 与资料授权和用途分别核对 |
| 定位缺项 | 客户群体与市场范围未提供 | 补充后同设置检查送达与采用 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `AI Proxy依赖` | 按实际版本核服务、渠道与应用。 |
| `AIPROXY_API_ENDPOINT` | 使用AI Proxy服务根地址。 |
| `AIPROXY_API_TOKEN` | 管理员Token非空且与服务端一致。 |
| `模型能力` | 按实际输入路径验证所需能力。 |
| `应用参数` | 接口同名字段未必覆盖应用设置。 |

## 容易做错的三处

- 询报价描述未进入模型，文案却称已核产品条件：并列提供给应用的文字和实际请求，先查漏传，不以服务有响应代替读取。

- 企业经营范围被改写成商品认证或确定性能：保存经营范围句、产品描述及草稿，逐项找证明，企业从事某类业务不能提供商品凭证。

- 从询报价接收方推定全部目标客户：核定位来源及适用商品，未给受众条件就保留待补；新增说明后同题核采用，不能靠参数补证。

## 怎么确认配好了

目标客户和市场定位没有给出时，文案可能仍产生相关说法，验收应逐条查来源。不得从询报价单的接收方直接推定产品面向的全部人群，也不能从企业经营范围补出具体用途。补充定位或产品说明后，保持原问题和设置复测，再记录新增文本是否送达及草稿采用的内容。当前检查只覆盖实际提供的输入，不推定其他模型能力已经可用。
