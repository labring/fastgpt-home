# B2B平台撮合交易的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在B2B平台撮合交易的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

为包装材料起草文案，先把企业主营业务与具体商品特性分开取证。拟议表单收集市场定位和受众说明后，要将提交记录与起草步骤的实际输入并列。如果提交中已有受众原句，下游却没有接到，这就是输入承接失败，应逐项检查实际引用来源与传值映射，再用同一段文字复测。交互结束只表示提交动作走完，不能据此扩写商品认证、效果或适用人群；文案中的每个属性仍要有自己的出处。

## 配置怎么定

| 实施核对项 | 本题输入 | 验收线索 |
| --- | --- | --- |
| 待收集文字 | 企业认证资料、询报价单的阅读要求：企业认证资料中的主营业务与询报价单中的商品特性描述 | 仅将已提供或已核对的内容作为填写依据，未知项保持待补。 |
| 提交与接收 | 企业认证资料中的主营业务与询报价单中的商品特性描述 | 提交含受众原句、下游却缺失时，排查来源引用与传值映射。 |
| 人工选择 | 企业认证资料、询报价单涉及的核对：企业认证资料中的主营业务与询报价单中的商品描述 | 补说明选择与继续起草分支不一致时，保留选择值及实际接收步骤。 |
| 缺项测试 | 关于询报价单的缺项记录：尚缺该商品的市场定位或目标客户群体信息 | 分别用缺项和补齐输入测试，补充材料还需保留实际出处。 |
| 后续业务步骤 | 可另核的资料来源包括 B2B平台、国家企业信用信息公示系统、支付流水、物流轨迹 | 校验、审批和回写如需执行，须另有实际实现及结果凭证。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

- 提交已含受众原句、起草步骤却没收到时，对照提交记录、来源引用与接收值，先修传递再复测。

- 传统制造企业介绍与智能设备功能被当成矛盾时，核两段各自所指对象；主营范围不直接决定某件商品能力。

- 补产品说明的选择实际进入继续起草时，保存选择值、接收步骤与连接关系；草稿生成也不能作为商品管理系统已经发布的记录。

## 怎么确认配好了

报价单没有给出市场定位和目标客户群体时，表单应明确哪些写作依据尚待提供，并安排具体接收步骤。分别测试空缺和补齐后的输入，核对后续节点收到的受众信息来源，不能由应用自行猜测。若需要把成稿写入商品管理系统，字段校验、审批和回写须由实际方案实现，再核业务记录；表单提交或草稿生成本身不证明内容已发布。
