# MCN机构达人管理的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在MCN机构达人管理的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。演示脚本的夸张场景不能改写成已经观察到的商品表现。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

MCN文案自拟培训简报“讲解折叠收纳步骤”，创意提纲另写“镜头快速切换，呈现桌面变整齐”，旁注为示意。输入要让模型读到实际讲解内容与拍摄表达的差别。镜头变化不是商品整理效率实测，也未说明使用者都能达到同样结果。起草口播时可描述步骤，不能把示意画面转成效果承诺，更不能补写真实使用者评价或宣称已取得验证。

## 配置怎么定

| 上下文核对对象 | 具体文字条件 | 验收线索 |
| --- | --- | --- |
| 讲解任务 | 折叠收纳步骤 | 核口播围绕操作。 |
| 画面身份 | 快速切换为示意 | 核旁注进入输入。 |
| 效果缺据 | 无速度或体验实测 | 不转成性能承诺。 |
| 旧标题 | 历史有夸张表达 | 检查是否覆盖当前任务。 |
| 脚本承接 | 口播与拍摄提示分开 | 核分栏内容和解析。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

一种失败是引用丢掉示意旁注，快速切换被文案说成快速整理；另一种是历史聊天里的夸张标题混入当前脚本，覆盖培训简报的步骤任务。排查应对照提纲、旁注和实际输入，确认画面语言是否被当作性能证据。增加回复长度只增加表达空间，不增加观察记录；模型上下文容量需按实际能力核，不能为了保留旧创意而让本次限定被挤出输入。第三处是把拟拍摄的整齐桌面说成真实使用者已经取得的体验。应对照拍摄计划与实际体验证据，检查文案的时态和说话人；只有创意提纲时，不得补出用户评价或已发生的结果。

## 怎么确认配好了

验收用步骤介绍与画面说明两个输出对象对照原文，步骤应围绕折叠收纳，画面要保留示意身份。相同起草要求分别使用空历史与带夸张标题历史，检查是否新增速度、效果或评价结论。固定格式如将口播和拍摄提示分栏，应核两类内容没有互串，旁注可解析且审核人能看见。当前缺少实测，文案应停在操作与创意描述，不把计划拍摄写成已发生的体验。
