# MCN机构达人管理的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在MCN机构达人管理的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

MCN文案起草可以先收集本场直播的题目、达人合作范围原句及拟使用的商品说明。自拟材料把“合同允许推广的品类”与“本次具体商品资料尚缺”分开，避免将宽泛品类直接写成商品承诺。表单提交后需要逐项看起草步骤实际收到的文字，收集值只是本题输入，不意味着系统已经查过合同权限、成分或宣传依据，也不构成内容已获发布批准。

## 配置怎么定

| 核对项 | 自拟输入或选择 | 可观察结果 |
| --- | --- | --- |
| 范围区分 | 合同品类与具体商品资料分列 | 未从品类扩大商品承诺 |
| 原句传递 | 已提交合作范围原文 | 起草步骤收到同一句内容 |
| 选择错接 | 补资料却进入起草路径 | 对照选择值与接收方修复 |
| 材料等待 | 本场商品说明未到位 | 等待与补齐后继续分别检查 |
| 外部发布 | 独立内容批准和账号操作 | 表单结束未充作发布凭证 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

若提交了合作范围原句，下游却只收到排期标题，应排查原句在哪一步丢失，补齐传值后用原题复测。另一项测试可选择“补商品资料”，但连接仍进入起草路径：保存选择值和实际接收内容，修好对应连接再验证等待与继续行为。选择补资料并不会让不存在的商品说明自动出现，不能由分支名称推断信息已经齐备。 若合同只给美妆等品类，成稿却承诺具体商品用途，应回查该型号商品说明和合同范围原句；品类名称不提供用途依据，缺材料时移去具体承诺。

## 怎么确认配好了

验收分别记录原始输入、提交内容、接收步骤与起草结果，检查文案是否只采用有出处的描述，缺商品说明时仍明确所需材料。交互节点触发后记录流程状态并等待交互，完成后继续向下执行；资料校验、内容审批和账号发布若需要，应在后续节点或外部系统另行落实。本次表单完成不证明合同审核或对外发布已经发生。
