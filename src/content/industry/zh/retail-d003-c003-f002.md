# Shopify独立站订单履约的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在Shopify独立站订单履约的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。外套可拆洗与内胆只擦拭必须同时进入清洁文案。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

Shopify商品文案自拟清洁说明“外套可拆洗；内胆仅擦拭”，商品名称只写靠垫。起草整件清洁介绍时，必须把外套与内胆保留为两个部件。可拆洗修饰外套，并不表示整件可以浸洗；仅擦拭也不能改写成所有部件都不可清洗。若输入只留商品名和可拆洗，模型就缺少区分部件所需的文字，回复再详细也没有依据自行恢复内胆条件。

## 配置怎么定

| 上下文核对对象 | 具体文字条件 | 验收线索 |
| --- | --- | --- |
| 外套动作 | 可拆洗只修饰外套 | 核部件主语。 |
| 内胆限制 | 仅擦拭 | 核引用尾句保留。 |
| 风格历史 | 旧文案含全套水洗 | 分开继承风格与事实。 |
| 标题范围 | 局部清洁不能扩为整件 | 核标题与正文关系。 |
| 部件输出 | 对象与方法成对 | 核行对应和解析。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

常见错误是长段资料裁剪停在外套句之后，内胆限制未进入；另一种失败是历史文案曾写全套水洗，当前提问要求保持风格时把该事实也继承。排查应把风格要求与清洁属性分开，核当前输入里的部件主语、限制和引用尾句。实际模型上下文容量按能力核，引用上限则用完整清洁问题看条件是否保留。回复篇幅应容纳两个部件，不能以缩写理由只剩可洗。

## 怎么确认配好了

验收分别检查外套清洁句、内胆清洁句和整体标题，确认标题没有把局部条件扩大为整件承诺。将同一任务置于空历史与带旧文案历史下比较，记录全套水洗是否再次出现。若固定格式输出部件与方法，核两行对象和动作没有错位且解析成功。其他清洁方式在本组未写明，应列为待核，不补温度、清洁剂或处理程序，更不伪称已经执行清洗验证。
