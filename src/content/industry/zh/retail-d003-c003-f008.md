# Shopify独立站订单履约的商品与营销文案起草：工作流编排

## 这个品类的数据长什么样

在Shopify独立站订单履约的商品与营销文案起草中，本页说明FastGPT的工作流编排如何衔接资料。独立站履约文案区分即时下载、实物备货与可选配件，不能把数字资料可用写成商品现货。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

本页自拟商品材料：下载页写可即时取得使用说明，实物套件仍待仓库确认备货，配件需要另选。起草流程收数字资料用途、实物商品和组成原句，人员选择核获取方式或核配件描述。使用说明可下载不代表套件已备好，另选配件也不是默认包含。本题没有真实订单或时效数值，不能按网页都能打开就写成所有内容即时交付。

## 配置怎么定

| 独立站履约文案路由 | 自拟对象 | 核查动作 |
| --- | --- | --- |
| 即时下载 | 仅使用说明 | 不扩实物发货 |
| 实物套件 | 备货待确认 | 不写确定送达 |
| 可选配件 | 需另行选择 | 不当默认标配 |
| 资料入口 | 链接可读 | 不等订单系统连通 |
| 实际履约 | 发运写回另办 | 核授权及回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

- 数字说明即时获取被成稿扩为实物即时发货时，对页面所指对象及仓库原文，将资料访问和商品履约分开。

- 备货待确认被写成买家一定可在某日收货时，核仓库确认与物流依据，不从准备状态补确定送达。

- 可选配件出现在图片中便被文案写成套件标配时，对组成说明和选配记录，展示画面不决定交付范围。

## 怎么确认配好了

两条路径都保留数字与实物身份，对比提交片段、后续接收及拟稿采用句。补下载链接只解决资料入口，不补实物可用；补备货证据也不补送达或配件。不要把资料读取成功当成Shopify订单操作已接通。真实页面发布、配件选择、发运和系统写回需授权接口与回执，流程只组织文案证据，不发货或确认客户已收到。
