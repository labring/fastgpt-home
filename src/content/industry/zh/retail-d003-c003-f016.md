# Shopify独立站订单履约的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在Shopify独立站订单履约的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

独立站商品文案可将商品描述、配送说明与订单的真实进度分开收集。自拟输入给出运费模板的适用区域及一张已生成的发货标签，同时说明没有揽收依据。表单负责收这些文字并交给后续起草，不负责将标签转成承运结果。用于文案的配送措辞应回指已给说明，不能因为某订单已生成标签，就为所有商品写出已经发货或送达的宣传内容。

## 配置怎么定

| 核对项 | 自拟输入或选择 | 可观察结果 |
| --- | --- | --- |
| 配送边界 | 模板中的适用区域 | 文案未扩大到所有地区 |
| 标签状态 | 已生成但无揽收依据 | 没有写成已发货或送达 |
| 区域传值 | 提交原句与下游范围文字 | 范围没有在传递中遗漏 |
| 起草路径 | 整理配送或补商品介绍 | 选择与接收资料对应 |
| 店铺变更 | 规则更新或发布的实际流程 | 文本结果未替代业务记录 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

若填写的适用区域没有进入起草输入，结果可能把局部配送说明扩成所有地区，应排查提交值与下游收到的范围文字。另可让人员选择“只整理配送说明”或“补充商品介绍”，分别查看实际路径；若后一选项直接使用空白商品资料起草，检查接收值和连接，不能把人员选择当成商品信息已补齐的证据。 若生成标签被文案写成已经揽收，应回查本包裹的承运方记录，分开标签创建与接收事件；模板和地址都不能补出实际运输结果。

## 怎么确认配好了

验收保留模板版本、区域原句、缺商品资料的记录与最终措辞，逐段核对有无范围扩大。测试缺项与补齐后的行为，但不声称表单自带业务核验。用户交互完成后流程继续向下，订单更新、库存校验与文案发布需后续节点或外部系统另行实现。完成这次起草只提供文本结果，不证明物流状态发生变化或运费规则已写入店铺。
