# Temu半托管卖家运营的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在Temu半托管卖家运营的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。可取下杯盖描述结构，杯身使用条件不能从中补出。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

Temu商品文案自拟结构说明“杯盖可取下”，使用备注写“杯身不适高温场景”，未提供具体加热适用资料。用户要求写便捷使用介绍时，输入需要保留杯盖与杯身的不同主语及高温限制。取下杯盖只能说明结构，不能推出杯身可加热或可用于任意处理；也不能把杯身限制直接写成杯盖材质结论。文案可写拆取动作，其他使用条件仍需来源。

## 配置怎么定

| 上下文核对对象 | 具体文字条件 | 验收线索 |
| --- | --- | --- |
| 结构主体 | 可取下修饰杯盖 | 核动作归属。 |
| 使用限制 | 高温条件对应杯身 | 核限制未移给其他部件。 |
| 资料缺口 | 无具体加热适用说明 | 不补处理条件。 |
| 别款历史 | 另一款杯具属性 | 定位是否串入当前。 |
| 部件承接 | 部件、动作与限制 | 核配对和解析。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

一种失败是摘要只保留便于拆取，随后补写适合高温；另一处是历史在讨论另一款杯具，当前任务沿用了其使用属性。应查当前输入的对象与限制，分开定位裁剪缺项与商品串用。回复长度需容纳使用条件，实际模型容量则独立核验；两者都不能把未提供的加热资料变成已知。引用token限制看实际片段是否留全，不以短标题字数判断依据充分。第三处是为使使用说明完整，补出未提供的加热步骤或处理时长。应逐项核成稿新增动作是否有本款资料出处；没有对应文字的步骤保留待核，不能用杯盖能取下作为加热依据。

## 怎么确认配好了

验收检查结构介绍、杯身限制和待核场景三个部分，确保可取下只对应杯盖，高温限制仍对应杯身。用相同起草任务对照空历史与另一款历史，核使用属性是否被迁移。若固定格式将部件、动作、限制分别承接，应核对应关系及解析成功。对未见具体资料的加热问题保留待核，不补温度、时长或安全承诺；成稿也不将拟议文字测试说成实际使用测试。
