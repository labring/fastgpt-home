# Temu半托管卖家运营的商品与营销文案起草：引用来源与溯源

## 这个品类的数据长什么样

半托管卖家需要自行维护海外库存与发货，商品申报表、海外库存表、价格申报与平台履约单构成日常文档基础。文案起草所引用的来源，通常落在这些文档的字段与版本上，资料更新频率为日、每单。库存与价格字段的更新节奏，使同一商品在不同日期的申报内容可能不同，起草时须锁定所依据的文档版本与日期范围。

## 这些特征在「引用来源与溯源」这一环带来什么约束

文案中的宣传句能否成立，取决于对应文档字段是否载明。知识库搜索节点先核对已选知识库及资料版本，相同向量模型才可共同关联；输出为引用数组，长度允许为零，空数组不代表工作流报错终止。检索输出须交给回答环节，再逐条核对回答与引用原文。语义召回与相关度是检索环节的得分，不承担权限或实体隔离。

假设演练样本：某半托管卖家运营人员依据一份《商品申报表（假设版）》起草文案。原文两句：「申报主体：假设供货商A；商品对象：假设收纳盒B；申报状态：已提交待平台审核；价格申报有效期：2025年3月1日至2025年3月31日。」拟稿句：「该商品已通过平台审核，价格长期有效。」核对时比较主体、对象、状态字段与拟稿句表述；申报状态为待审核，拟稿句称已通过审核，同字段取值互斥，该句未获支持；有效期仅覆盖3月，长期有效超出载明范围，同样未获支持。

## 配置怎么定

| 配置或核对项 | 本次假设起点 | 比较与说明 |
| --- | --- | --- |
| 关联知识库 | 选择含《商品申报表（假设版）》的知识库 | 核对已选库及资料版本，相同向量模型才可共同关联 |
| 搜索模式 | 混合检索 | 编号、状态类字段用全文或混合召回，语义召回作补充 |
| 引用上限 | 假设起点 2000 tokens | 本次试验起点，与样本原文长度比较后调整 |
| 最低相关度 | 假设起点 0.5 | 仅语义检索或结果重排时生效，与召回样本比较 |
| 引用内容输出 | 数组，长度可为 0 | 空数组时下游须能承接，不视为报错 |
| 回答承接 | 检索输出交给回答环节 | 逐条核对回答与引用原文，不以流畅度替代来源 |

## 容易做错的三处

1. 把「已提交待平台审核」读成审核通过。输入为申报表状态字段，比较对象为拟稿句「已通过审核」，观察结果是同字段取值互斥，判定为未获支持。
2. 把价格申报有效期当作供货期限。输入为有效期起止日期，比较对象为「长期有效」，观察结果是超出载明范围，判定为待核实。
3. 把检索得分当作授权依据。输入为相关度数值，比较对象为文案可用范围，观察结果是得分不区分主体与权限，判定为不能据此放行。

## 怎么确认配好了

1. 用样本原文与拟稿句逐条比对。输入为申报表主体、对象、状态、有效期字段及拟稿句，比较字段取值与句意，观察结果为待审核与已通过互斥、有效期与长期有效不符，两处均判未获支持。
2. 用纸面输入 `[]` 核对空引用承接。输入为空数组，比较下游回答环节设计，观察结果为链路走通且不报错，方可确认空结果可承接。
3. 核对知识库标识与向量模型。输入为已选库列表，比较各库向量模型标识，观察结果为不符者被排除并记录实际观察，不执行跨模型检索比较漏召回。

以上为纸面核对设计，未实际执行检索、审核或发布动作。
