# Temu半托管卖家运营的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在Temu半托管卖家运营的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

半托管商品起草可先收申报中的商品描述和海外库存资料的适用说明，二者分别回答商品是什么与资料覆盖哪里。自拟输入保留这两处文字，并注明没有当前仓库可用依据。表单提交的值可用于整理措辞，但不能由库存表标题推定现货，也不能从申报资料齐全推出平台已经审核通过。需要人员选择的应是下一步阅读安排，不是让用户代替系统挑一个业务事实。

## 配置怎么定

| 核对项 | 自拟输入或选择 | 可观察结果 |
| --- | --- | --- |
| 商品原文 | 申报描述的相关句子 | 未扩大成审核通过声明 |
| 供货范围 | 海外仓适用说明 | 没有替换成店铺身份 |
| 现货缺口 | 无当前可用性依据 | 起草未使用现货承诺 |
| 等待选择 | 人员要求补库存说明 | 核选择、连接和继续步骤 |
| 业务回写 | 真实库存或上架操作 | 与交互完成分别取证 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

若海外仓名称传值时被替换成店铺名称，起草会混淆供货范围，应排查两项原文和接收内容，修正后复测。另可选择“等待库存依据”，观察是否确实进入等待交互的安排；若仍继续生成现货宣传，要核实际选择与连接，并从稿中移除无据现货表述。表单收到了仓库名称，不说明库存信息已经核实。 若稿件由已填仓库名直接写出当前现货，应另取该仓本商品的可用记录，逐句核所据版本；仓库身份正确不说明库存结论已经核实，缺来源时删除现货承诺。

## 怎么确认配好了

验收将商品原文、仓库适用说明和仍缺的可用依据并列，对照每次提交与最终文案，核是否只采用实际材料。补齐后复问原题，检查新增说明真正进入起草。字段校验、平台审批与库存回写要按实际业务在后续节点或外部系统设计；交互完成后的继续执行，不证明申报、采购或上架动作已经办理，也不代表新的库存状态已被确认。
