# TikTok Shop美国店运营的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在TikTok Shop美国店运营的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

TikTok Shop商品文案可先收Listing的原文、拟用的表达范围和可引用的检查说明。自拟材料把客户退货陈述另列为待核线索，不能直接转成商品特点。表单只收集并传递填写的信息，不自动确定哪些宣传有证据。若现有材料没有某项商品属性，应在起草输入中保持缺口，避免把提问中希望出现的表达写成资料已经证实的卖点。

## 配置怎么定

| 核对项 | 自拟输入或选择 | 可观察结果 |
| --- | --- | --- |
| 来源区分 | Listing与客户陈述分开 | 未核线索未变成商品特点 |
| 性质传递 | 陈述附带待核说明 | 接收输入仍保留来源性质 |
| 选择错路 | 保留措辞却到新增卖点步骤 | 核连接与新增句子依据 |
| 属性缺口 | 资料中没有的商品说明 | 没有从愿望表达猜补 |
| 后续发布 | 广告审批及账号发布流程 | 起草未冒充平台接受 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

若填写的“待核陈述”在下游只剩陈述正文，来源性质丢失后可能被当成事实，应逐项查看标签说明与接收文字，补回来源再起草。另可测试人员选择“保留已有Listing措辞”，连接却导向添加新卖点的步骤：排查实际选择值与接收路径，核稿中新增句子的依据，不让一个选择代替商品检查或广告审核。 若单件退货检查被成稿扩为型号共同特点，应核检查对象、观察原句与商品说明覆盖范围；个案观察不提供全部商品属性，缺型号依据时撤去扩大措辞。

## 怎么确认配好了

验收分别保留页面原句、检查资料、未核线索与最后稿件，逐句确认写入的属性能回指已给依据。缺项及补齐后分别测试，用户选择按其连接执行分支，不能称为商品数据库选择器。进一步的字段校验、审批和发布由实际后续流程承担；表单完成或文案生成不证明平台已经接受宣传内容，也不表明退货争议已有处理结果。
