# 一般贸易出口报关的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在一般贸易出口报关的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。散件发货与组装示意图需要分清实际供货状态。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

出口商品文案自拟资料“发货以散件包装；图示为组装示意”，服务范围备注写“未列安装服务”。用户要求描述开箱体验时，输入应同时带实际发货形态、示意身份与服务缺项。组装后的画面不证明开箱即为整机，也不能推出会有人上门安装。未列安装服务只说明本组没有范围依据，不能自行判定所有订单均不提供，文案应避免跨出当前材料。

## 配置怎么定

| 上下文核对对象 | 具体文字条件 | 验收线索 |
| --- | --- | --- |
| 实际形态 | 散件包装发货 | 核发货条件未裁掉。 |
| 图示身份 | 组装示意 | 不转成开箱整机。 |
| 服务缺项 | 未列安装范围 | 不补上门安排。 |
| 历史迁移 | 别款安装服务 | 核当前产品适用关系。 |
| 编辑承接 | 发货、图示及待核服务 | 核字段及解析。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

一种失败是引用只留下组装图示，散件条件被裁掉，正文就写开箱即用；另一处是历史其他产品附安装服务，当前起草把那项服务带入。应核实际输入中的发货对象、画面性质与历史商品，定位形式混用和服务迁移。回复长度需容纳散件条件与待核范围，模型上下文能力则独立确认；更长输出不能补出安装安排，来源齐全与服务已执行也应分别判断。第三处是后续拿到安装安排后，文案直接改成已完成安装。应核安排与实际服务记录的状态区别，并检查成稿是否把计划时态改成完成；服务范围来源不能代替执行证明。

## 怎么确认配好了

验收分别核发货描述、图示说明和服务说明，确保散件包装仍对应本批物品，组装只是示意。将同一开箱起草任务在空历史和安装服务历史下比较，检查是否新增整机或上门承诺。固定格式若用于页面编辑，应保留发货形态、图片说明和待核服务项，核字段及解析完整。取得安装范围资料后再核适用订单，不能仅因资料出现就把服务计划写成已完成安装。
