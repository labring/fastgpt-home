# 一般贸易出口报关的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在一般贸易出口报关的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

出口文案的输入应分开合同里的商品描述与装箱单的包装文字，避免包装数量变成商品规格。自拟材料给出这两处原句，另说明没有制造方用途资料。表单可收集所需段落、来源身份及拟写主题，提交后传向起草步骤；它不负责为交易单据补技术属性。商业发票与合同齐全，也不能直接支持出口许可、质量或使用效果的宣传。

## 配置怎么定

| 核对项 | 自拟输入或选择 | 可观察结果 |
| --- | --- | --- |
| 对象区分 | 合同商品与装箱包装原句 | 没有混成商品规格 |
| 语境传递 | 数量文字附原栏目说明 | 下游未丢掉包装用途 |
| 补资料路径 | 补厂家说明却收到旧合同 | 核版本、选择与接收值 |
| 宣传范围 | 用途资料尚未提供 | 未起草认证或效果声明 |
| 业务生效 | 合同或报关另有处理记录 | 交互未替代批准及受理 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

若起草输入把装箱单栏目名称省掉，只留下数量文字，应排查提交前后含义，补回包装语境再复测。另可选择“补厂家说明”，但后续收到的仍是旧合同段落；核实际选择、接收值与资料版本，修正传递后再起草。不能因节点已经连好，就声称新增厂家依据已参与本次稿件。 若稿件将单证齐全写成商品已获认证，应回查所称认证的实际依据与适用对象；合同、发票和装箱单不补出这份证据，未给来源时应撤去认证说法。

## 怎么确认配好了

验收沿题目、填写值、接收材料和文案逐项比对，保留厂家用途尚缺的状态，确认稿中没有把单证齐备写成商品认证。补充资料后重复原题，看相关句子是否实际采用新来源。需要字段校验、合同批准、报关提交或公开发布时，应由后续节点或外部业务流程落实；交互结束只提供这次传值结果，不证明交易或申报已经生效。
