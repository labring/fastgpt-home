# 一般贸易进口报关的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

一般贸易进口报关的日常文档包括进口报关单、商业发票、装箱单、提单和合同。与出口报关相比，进口报关重点在完税价格、运保费和税费缴纳，商品文案起草需要与这些单据的申报口径保持一致。数据按每单更新，商品描述、成交方式、运保费分摊和原产地信息都可能随单据变化。

这些特征影响文案起草的输入组织方式。商品名称、规格、数量、单价和币制来自商业发票与装箱单，成交方式与运保费影响完税价格表述，合同与提单提供主体和批次信息。文案起草环节需要把这些字段作为待核对材料，不能仅凭模型生成结果直接对外使用。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入需要 AI Proxy 作为依赖服务。App 和 Admin 都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。模型渠道中配置的模型 ID 与模型映射决定实际请求发往哪个上游模型，模型能力如视觉输入、工具调用需要在模型配置中逐项核对。

假设演练样本：某进口商有一批一般贸易进口货物，商业发票载明“商品名称：不锈钢厨具；规格：304 不锈钢；数量：2000 件；单价：USD 4.50；成交方式：CIF”。合同载明“卖方负责运输和保险，货物于 2026 年 3 月 10 日前装运”。现有一条待判定拟稿句：“本批不锈钢厨具采用 304 不锈钢材质，共 2000 件，单价 USD 4.50，已包含运输和保险费用。”

拟稿句中材质、数量和单价与商业发票一致，成交方式 CIF 对应卖方负责运输和保险，与合同表述方向一致。该句未超出材料范围。若拟稿句写成“本批厨具通过某认证机构认证”，材料中无认证信息，属于未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 与官方说明的服务根地址格式比较，确认不附加 `/v1` |
| AIPROXY_API_TOKEN | 假设填非空管理员 Token | 与服务端配置比较，确认一致且非空 |
| 模型渠道模型 ID | 假设选一个语言模型 | 与模型配置中的模型 ID 比较，确认一致 |
| 模型映射 | 假设将起草用模型映射到上游模型 | 与渠道配置比较，确认请求模型名与上游模型名对应 |
| 模型能力 | 假设核对是否支持所需输入类型 | 与模型配置字段比较，确认视觉、工具调用等能力满足起草需要 |
| 模型测试 | 假设对已配置渠道执行模型测试 | 观察测试结果与请求时长，确认模型可用 |

以上数值为本次假设试验起点，不是官方默认值。选择这些起点的原因是需要覆盖接入地址、鉴权、模型标识和能力核对四个环节。

## 容易做错的三处

1. 将 AIPROXY_API_ENDPOINT 填成完整请求地址并附加 `/v1`。检查输入为假设填写的 `http://aiproxy:3000/v1`，比较对象为官方说明的服务根地址格式，观察结果为该值不符合根地址要求。
2. 用应用 API Key 代替 AIPROXY_API_TOKEN。检查输入为假设填写的应用 Key，比较对象为管理员 Token 要求，观察结果为该值不满足非空管理员 Token 条件。
3. 拟稿句写入材料未载明的认证信息。检查输入为假设拟稿句“本批厨具通过某认证机构认证”，比较对象为商业发票和合同原文，观察结果为材料中无认证字段，该句未获支持。

## 怎么确认配好了

1. 输入假设填写的 AIPROXY_API_ENDPOINT 和 AIPROXY_API_TOKEN，比较对象为官方说明的必填与非空要求，观察结果为两项均存在且格式符合，则接入配置满足启动校验条件。
2. 输入假设拟稿句“本批不锈钢厨具采用 304 不锈钢材质，共 2000 件，单价 USD 4.50，已包含运输和保险费用”，比较对象为商业发票和合同原文，观察结果为材质、数量、单价与发票一致，运输和保险责任与合同一致，则该句获得材料支持。
3. 输入假设拟稿句“本批厨具通过某认证机构认证”，比较对象为商业发票和合同原文，观察结果为材料中无认证信息，则该句属于未获支持，需要补充材料或修改表述。
