# 一般贸易进口报关的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

一般贸易进口报关的资料围绕进口报关单、商业发票、装箱单、提单和合同展开。与出口报关相比，进口报关重点在完税价格、运保费和税费缴纳，成交方式与运保费填报是主要耗时环节。这些事实影响知识库检索与召回：商品与营销文案起草需要引用的内容集中在成交方式、运保费口径、税费构成和单据字段上，检索词若只写商品名称，难以召回与价格条款相关的段落。

数据更新频率为每单，资料随每票货物变化。知识库中的集合仅用于分类管理，搜索以库为单位进行。同一库内可包含多组数据，一组数据可对应多个向量，检索时命中任一向量即召回该组原数据。

## 这些特征在「知识库检索与召回」这一环带来什么约束

商品与营销文案起草的检索目标，是找到与待写文案相关的进口单据原文和价格条款说明。检索环节只负责召回引用内容，不负责核验企业身份、不负责判断报关单真伪、不负责执行税费计算。关联知识库要求使用相同向量模型，跨模型的知识库不能共同关联；此项限制只针对本功能关联的库，不扩展到工商网站或其他外部系统。

以下为假设演练样本。供核对的材料原文三句：「本合同项下成交方式为 CIF，运保费已计入发票金额。」「商业发票列明运费与保险费合计 USD 1,200，已包含在单价内。」「进口报关单申报的完税价格以发票金额为基础，运保费不再另行加计。」待判定的拟稿句：「本品进口采用 CIF 成交，运保费已含在发票金额中，完税价格以发票金额为基础。」该样本用于核对拟稿句是否与上述三句原文表述一致，不涉及任何真实客户或编号。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 依据与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 一个含进口单据说明的库 | 该库使用同一向量模型；与其他模型不同的库不共同关联 |
| 搜索模式 | 混合检索 | 对同一测试问题分别比较语义、全文与混合的召回内容 |
| 引用上限 | 800 tokens | 本次假设起点，理由为样本段落较短；与 1200 tokens 比较内容是否完整 |
| 最低相关度 | 0.35 | 本次假设起点，理由为需先标注相关与无关样本；与 0.5 比较过滤后剩余条目 |
| 问题优化 | 开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 启用 | 具备重排模型时使用；比较重排前后候选顺序 |

上述数值为本次假设试验起点，不是官方默认值。引用上限单位为 token。最低相关度仅在语义检索或使用结果重排时生效。RRF 是混合检索后的结果融合过程，不作为独立开关。图片检索须有图像输入且模型能力支持，重排须具备模型并按设置启用，这些路径不表示每次请求全部执行。

## 容易做错的三处

1. 把拟稿句中的「运保费已含在发票金额中」直接判定为与报关单原文冲突。报关单原文写「运保费不再另行加计」，与发票原文写「已包含在单价内」属于同一方向表述，需回到三句原文逐字段比较，不能凭关键词差异下结论。
2. 将最低相关度当作权限或实体过滤器。该参数过滤低相关度结果，不能排除无关业务或未授权记录；检索环节不承担授权判断。
3. 对跨向量模型的库执行共同关联后推断漏召回或冗余。正确做法是先核对各库向量模型标识，排除不符合者，记录实际观察，不编造运行结果。

## 怎么确认配好了

1. 输入假设样本三句原文与拟稿句，比较拟稿句是否与原文在成交方式、运保费归属、完税价格基础三个字段上同向。预期现象为三个字段均可从原文找到对应表述；若某字段原文未载明，记录为未获支持。
2. 用同一测试问题分别以语义检索和全文检索执行，比较两路召回内容。预期现象为能观察到两路结果差异，并记录哪一路召回了含成交方式的段落；不保证首条命中或全部召回。
3. 将引用上限设为 800 tokens 与 1200 tokens 各执行一次，比较返回内容是否完整覆盖样本段落。预期现象为两者返回条目数或截断位置可观察；若下游节点收到空引用数组，按长度为 0 的链路走通处理，不声称检索一定返回空。
