# 亚马逊FBA备货运营的商品与营销文案起草：多轮对话与提示词

## 这个品类的数据长什么样

在亚马逊FBA备货运营的商品与营销文案起草中，本页说明FastGPT的多轮对话与提示词如何衔接资料。跟踪材质与受众依据，防止旧草稿内容成为后续默认事实。所用场景为自拟文字测试。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

自拟入仓计划写明无线耳机及降噪功能，可以把这两项作为本轮文案的明示资料；它没有提供降噪幅度、续航表现或适用人群。提示词应区分允许复述的描述和仍缺依据的效果表述。用新会话与带历史的同一写作请求对照，检查前一商品的特征是否被带入耳机文案，再逐项回查当前草稿中的功能说法是否来自这份附页。

## 配置怎么定

| 核对项 | 当前文案的实际依据 | 需观察的偏差 |
| --- | --- | --- |
| 功能描述 | 无线耳机与降噪为附页明示文字 | 是否扩写未给出的效果与续航 |
| 历史输入 | 本轮以耳机资料为范围 | 是否沿用上一商品的特征 |
| 材质差异 | 入仓附页写塑料，箱唛写金属 | 是否只采信较早一轮的材质 |
| 问题改写 | 保留同一商品与双方资料 | 指代处理是否删去一方来源 |
| 目标受众 | 智能手表的受众资料尚缺 | 是否从名称推定年龄或职业 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `提示词与任务` | 说明资料、任务和缺证据处理。 |
| `历史记录` | 核实际提交的历史输入。 |
| `问题优化` | 指代消除与问题扩展需复核。 |
| `模型与长度` | 上下文与回复长度分别核对。 |
| `回复格式` | json_schema需给格式并验解析。 |

## 容易做错的三处

- 历史塑料描述覆盖箱唛金属，后轮只留一种：并列实际历史、当前附页和草稿，定位来源丢失，不能靠更多轮次裁定材质。

- 耳机已有降噪文字被扩成幅度、续航或确定人群：核每项原文支持，提供功能名不等于取得这些条件，保留缺项。

- 手表定位缺失却沿用别品年龄或职业：保留商品身份及新增受众句，查历史串用或生成扩展；补适用定位后同题复测。

## 怎么确认配好了

智能手表缺少目标用户群体说明，文案中关于受众的内容应逐项检查。商品名称并不提供年龄、职业或使用场景依据，历史中对其他商品的受众判断也不能直接移用。若后续提供了定位资料，应记录其是否进入实际输入，再用同一文案任务复测。返回格式与措辞是否通顺只能说明另一类检查结果，受众描述仍需对应原文。
