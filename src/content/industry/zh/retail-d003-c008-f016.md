# 亚马逊FBA备货运营的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在亚马逊FBA备货运营的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

FBA商品文案需要将商品资料与入仓安排分开。自拟输入只提供入仓计划、箱标描述和待写主题，没有产品性能说明，也没有接收凭证。表单可收集已给文字并传给起草，不能因为计划已建立就写成平台仓现货。若主题涉及商品特点，应先列明哪些信息尚缺，商品名称和标签本身不能补出材质、功效或适配说明。

## 配置怎么定

| 核对项 | 自拟输入或选择 | 可观察结果 |
| --- | --- | --- |
| 计划性质 | 计划和箱标已给 | 未起草平台仓现货承诺 |
| 货件身份 | 其他货件状态混入输入 | 核实际接收范围后移出 |
| 产品原文 | 补资料却只传箱标标题 | 标题未代替商品说明 |
| 属性出处 | 本题没有性能说明 | 材质功效未凭名称猜出 |
| 仓内动作 | 库存查询或发布另接流程 | 提交不代替入仓结果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

若同一商品的其他货件状态被送进当前起草步骤，资料范围不一致会产生错误现货措辞，应排查货件身份和下游收到的说明。另可选择“补产品资料”，但只传入箱标标题；对照实际提交和接收内容，确认缺的产品原文没有被标题替代。人员选择了补充路径，不说明产品说明已经进入流程。 若成稿仍宣称本批商品已在平台仓可售，应另取同货件接收及相应库存依据，核其与当前商品对应；计划和箱标不证明该业务状态，应移除没有来源的现货措辞。

## 怎么确认配好了

验收保留计划性质、货件身份、产品资料缺口及最终稿件，核每个商品属性的出处。补齐后复测原题，确认起草采用新增原文，未把仓库安排写成可售或已接收状态。交互等待和继续按实际节点行为观察，字段核验、库存读取与上架发布需后续节点或外部系统另接；表单提交不能作为入仓完成或商品已发布的凭据。
