# 亚马逊FBM自发货运营的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在亚马逊FBM自发货运营的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

FBM起草输入可区分商品介绍与订单配送措辞。自拟材料给出拣货记录和物流过程说明，但没有制造方商品介绍或客户签收依据。表单只负责收集所填内容，提交后要检查起草步骤收到的资料身份。运输中的文字可用于解释该记录，不支持为商品写出已送达承诺，也不能由退货地址设置推定所有订单采用同一服务条件。

## 配置怎么定

| 核对项 | 自拟输入或选择 | 可观察结果 |
| --- | --- | --- |
| 输入分类 | 商品介绍与运输说明分开 | 未从物流生成商品特点 |
| 转述性质 | 客服消息注明未核 | 下游仍保留这层说明 |
| 选择传递 | 只整理介绍却收到运输过程 | 检查接收文本并补资料 |
| 签收缺口 | 没有买家接收依据 | 成稿未写成已送达 |
| 公开上线 | 真实内容审核和发布记录 | 交互结束未充作上线状态 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

若客服转述进入起草时丢失“转述”说明，结果可能把未核消息写成配送事实，应排查原始填写、下游文本及成稿句子，补回来源性质后再测。另可选择“仅整理商品介绍”，连接却将运输过程直接交给宣传起草；核选择和接收值，缺商品资料时先提出需要的说明，不从物流记录生成商品特点。 若一处退货地址设置被扩为全部订单同样的服务承诺，应核规则适用对象与本订单资料；地点配置不提供所有服务条件，缺对应原文时缩回实际范围。

## 怎么确认配好了

验收沿资料类型、提交内容与文案逐项回查，观察缺介绍与补齐介绍后的差别，保留签收尚未取得的状态。用户选择执行所接分支，不是自动查询订单的业务选择器。内容核验、配送承诺确认和公开发布需在实际后续流程落实；交互完成不证明物流已变化，也不表示买家已经接收商品或店铺文案已上线。
