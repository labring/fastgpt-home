# 京东POP第三方店铺运营的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在京东POP第三方店铺运营的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。台式款安装说明不能扩成全部款式的服务承诺。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

京东POP文案自拟安装说明“本页仅适用台式款”，售后指引写“服务事项需核对应订单”，历史摘要曾介绍壁挂款。用户要求写全系列使用支持时，输入要保留台式款范围与订单核对条件。安装步骤存在不等于提供上门安装，服务指引也没有给出所有订单相同的服务。起草可以说明当前资料覆盖的对象，不能从全系列这一写作要求补出其他款式适用性。

## 配置怎么定

| 上下文核对对象 | 具体文字条件 | 验收线索 |
| --- | --- | --- |
| 当前款式 | 仅台式款 | 核仅适用限定。 |
| 步骤对象 | 本页安装步骤 | 不与壁挂款合并。 |
| 服务条件 | 需核对应订单 | 保留订单核对动作。 |
| 全系列请求 | 写作范围大于资料覆盖 | 列其他款式缺项。 |
| 页面承接 | 款式、步骤与服务待核 | 核配对字段和解析。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

一种失败是引用裁去本页仅适用，台式款步骤被写成全部产品通用；另一处风险是历史壁挂款内容与当前步骤混合，让读者把不同安装方式当成同一套说明。应核当前输入的款式、步骤主体及历史来源，定位范围丢失和对象混并。模型上下文能力不能由回复上限推定，回复长度则要保留范围与待核订单。补长文字不等于补齐其他款式或服务证据。第三处是有安装步骤便宣称订单包含安装服务。应核对应订单的服务范围，区分使用说明与服务约定；步骤完整不等于服务已购买，也不说明已有人实际上门。

## 怎么确认配好了

验收可将输出分为当前适用款式、已见支持资料与待核服务事项，检查全系列标题没有扩大正文依据。相同任务对照空历史与带壁挂款摘要的输入，核是否出现无来源的共同步骤。固定格式若供商品页编辑，应核款式与步骤一一对应，订单条件可解析。尚缺其他款式资料时明确缺项，不补终身服务、免费安装或实际服务效果，更不把文字测试写成已经完成安装。
