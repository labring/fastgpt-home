# 京东POP第三方店铺运营的商品与营销文案起草：多轮对话与提示词

## 这个品类的数据长什么样

在京东POP第三方店铺运营的商品与营销文案起草中，本页说明FastGPT的多轮对话与提示词如何衔接资料。连续修改商品文案时保留素材条件，防止上一款卖点或服务表述进入当前草稿。所用场景为自拟文字测试。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

文案练习可先提供某款配件的接口与包装说明，要求整理介绍，再追问“突出刚才那个优点”。提示词应保留“优点”对应的原句，不能把已描述接口扩成速度、兼容范围或性能承诺。若草稿增加这些结论，应比较原问、历史素材与输出，指出当前无法核实的支持。素材能用于介绍商品，不表示每项营销表达都已有依据，多轮润色也不增加原始事实。

## 配置怎么定

| 文案对话核对项 | 配件素材与历史 | 验收动作 |
| --- | --- | --- |
| 卖点依据 | 接口说明不提供性能承诺 | 新增说法逐句回查 |
| 换款续写 | 两款主体与包装分开 | 原问、历史及优化问 |
| 失败现象 | 旧服务或包装写入新稿 | 保留两份原文和返回 |
| 来源缺项 | 能力原文未给时补资料 | 不由扩大上下文补事实 |
| 编辑承接 | 草稿、结构及写入分开 | 不冒充正式商品更新 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `提示词与任务` | 说明资料、任务和缺证据处理。 |
| `历史记录` | 核实际提交的历史输入。 |
| `问题优化` | 指代消除与问题扩展需复核。 |
| `模型与长度` | 上下文与回复长度分别核对。 |
| `回复格式` | json_schema需给格式并验解析。 |

## 容易做错的三处

- 接口说明被扩大为速度、兼容或性能承诺：回查原句、历史与新增卖点，所给接口不支持这些条件，不能以润色次数补事实。

- 换款后“也这样写”仍用旧包装或服务：保存两款原文及优化问，核当前对象，资料已在却被覆盖与根本缺资料分别查。

- 登记维修被文案写成已完成或更宽质保：对照服务原句与草稿，向责任人补实际条件，不能让历史营销措辞成为新承诺。

## 怎么确认配好了

验收可对空历史、同款续写和换款续写分别用同一任务，逐句核新增说法及其原文。服务记录只写登记维修时，文案不能改成已完成或扩大质保范围；需向责任人补实际条件。输出格式若用于后续商品编辑，核结构与来源再查实际写入，生成文本不更新商品信息表或店铺页面。保留草稿身份，避免把内部练习和未确认条件写成正式承诺。
