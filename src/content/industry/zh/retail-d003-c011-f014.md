# 仅退款争议处理的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

仅退款争议处理的核心材料是仅退款申请、发货凭证、签收证明与申诉材料，证据重点落在发货签收与商品价值，通常没有退件入仓记录。这些材料以每单为节奏产生，文案起草需要逐单核对材料原文，无法用一份通用模板覆盖全部情形。商品与营销文案起草在这一品类里承担的是把材料中已经载明的事实转写为可提交的说明文字，材料未载明的部分保持待核实。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。按 v4.17.2 文档，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败；旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。AIPROXY_API_ENDPOINT 填写服务根地址，不附加 /v1。AIPROXY_API_TOKEN 是管理员 Token，不能以应用 API Key 代替。

假设演练样本：某店铺售后主管在 2026 年 3 月 12 日处理一笔仅退款申请，材料原文为「订单于 2026 年 3 月 5 日由承运商揽收，3 月 8 日显示本人签收，签收人栏为空白」。拟稿句为「买家已于 3 月 8 日确认收货，商品价值无争议」。核对对象是签收人栏为空这一状态，拟稿句中的「确认收货」在该材料中没有对应记载。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址 | 文档要求根地址，比较对象为附加 /v1 的写法 |
| AIPROXY_API_TOKEN | 非空管理员 Token | 文档要求与服务端一致，比较应用 API Key |
| 语言模型启用状态 | 启用至少一个语言模型 | 文档要求系统至少一个语言模型 |
| 索引模型启用状态 | 启用至少一个索引模型 | 文档要求系统至少一个索引模型 |
| 模型探测间隔 | 假设填 30 分钟 | 文档支持 5 至 60 分钟整数，比较上下边界 |
| 模型测试 | 对已配置渠道执行一次测试 | 文档提供渠道测试与模型测试入口 |

## 容易做错的三处

1. 把签收轨迹写成买家确认收货。样本中签收人栏为空白，拟稿句加入「确认收货」缺少材料支持。
2. 用相似度设置承担权限判断。相关度分数不构成实体或权限过滤，检索结果不能替代授权核对。
3. 把待审核状态写成已获批准。仅退款申请处于待审核时，不构成对退款金额或责任的确认。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较「签收人栏为空白」与「确认收货」是否同字段同期间。拟稿句出现材料未载明的确认行为时，判定为未获支持。
2. 输入 AIPROXY_API_ENDPOINT 的两种写法，比较是否附加 /v1。附加后缀的写法与文档要求不一致。
3. 输入一条不含签收信息的假设材料，比较拟稿句是否仍写出签收结论。材料缺少签收字段时，结论保持待核实。
