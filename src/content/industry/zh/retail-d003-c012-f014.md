# 仓内拣货复核打包的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

仓内拣货复核打包处理订单出库，主要数据来自 WMS、订单系统、电子面单平台与称重设备，日常文档包括波次拣货单、复核记录、面单和包装耗材单。这些材料按每单或每小时更新，商品与营销文案起草所需的事实依据通常落在复核记录与包装耗材单上，文案句能否成立取决于对应材料是否载明同一主体、同一期间、同一字段。品类置信度为大致如此，未提供的字段保持未知。

## 这些特征在「模型接入与配置」这一环带来什么约束

从 V4.17.0 起 AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填写 AI Proxy 服务根地址，不附加 /v1。AIPROXY_API_TOKEN 必须与服务端配置一致且不能为空，应用 API Key 不能替代。模型能力按应用所需输入分别核对，多模态、工具调用与思考配置分别验证；应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。语义召回与相关度不承担权限或实体隔离，检索库与向量模型标识需先核对再决定是否共同关联。

假设演练样本：某仓库 2026 年 3 月 12 日波次拣货单 W-0312-07 载明“订单 8841，SKU 白色棉质 T 恤，拣货数量 2 件，复核状态：已复核”。包装耗材单载明“订单 8841 使用 30cm×20cm 纸袋”。拟稿句为“本单商品已通过出库复核”。判定需同主体、同期间、同一字段：复核记录中订单 8841 的复核状态字段若为已复核，则该句获得支持；若该字段未载明或仅有拣货阶段证据，则属未获支持，需记录缺口。

## 配置怎么定

| 设置或核对项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 http://aiproxy:3000 | 文档要求根地址不带 /v1，与带 /v1 的写法比较 |
| AIPROXY_API_TOKEN | 假设填与服务端一致的非空值 | 文档要求非空且一致，与空值或应用 Key 比较 |
| 语言模型与索引模型 | 假设各启用一个 | 文档要求至少各一个，与未启用状态比较 |
| 模型能力核对 | 假设按文案起草所需文本输入核对 | 与多模态、工具调用能力分别验证 |
| 应用参数位置 | 假设在应用或节点配置中设置 | 与对话接口同名字段比较，确认不覆盖编排 |
| 检索库标识核对 | 假设记录库与向量模型标识 | 与另一向量模型库比较，标识不符则不共同关联 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 写成带 /v1 的完整请求地址，启动校验按文档要求比对根地址时出现不匹配。
2. 用应用 API Key 充当 AIPROXY_API_TOKEN，与服务端配置比对时出现不一致，且非空校验不能替代一致性核对。
3. 将语义相关度当作权限或实体过滤，把相似度设置解释为排除无关业务或未授权记录，实际检索不承担该职责。

## 怎么确认配好了

1. 输入假设样本中的波次拣货单原文与拟稿句，比较复核记录中订单 8841 的复核状态字段取值：字段为已复核时该句获得支持；字段未载明或仅有拣货阶段证据时记录为未获支持，保留缺口。
2. 输入假设的 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN，比较是否分别为根地址与非空且与服务端一致：两项均满足时启动校验通过；任一项不满足时记录为未通过，不推断具体报错文本。
3. 输入假设的两个检索库标识与向量模型标识，比较是否同库同模型：标识一致时记录可共同关联；标识不一致时排除不符者并记录实际观察，不执行跨模型检索来比较漏召回。
