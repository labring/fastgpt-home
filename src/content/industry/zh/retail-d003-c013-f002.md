# 便利店加盟门店督导的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在便利店加盟门店督导的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。核本店已调整的对象及待复核事项，防止区域计划进入本店完成稿。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

便利店加盟督导的门店动态稿，可用新拟巡店备注：“本店端架完成位置调整，陈列品项待区域复核。”历史草稿另有“区域门店将逐步调整”的计划。本轮只写这家店的记录，需让上下文包含店别、已调整的对象与待复核事项。位置完成和品项通过不是同一结论；历史区域计划也没有给出其他店的完成记录。拟稿可以说明这些已有信息，但不能扩成全区域整改结束，或让读者将调整照片当作审核结果。

## 配置怎么定

| 上下文核对项 | 本题材料 | 取证动作 |
| --- | --- | --- |
| 门店范围 | 本店记录与区域计划分开 | 不扩写其他店完成。 |
| 完成对象 | 位置调整不等于品项通过 | 待复核条件传入本轮。 |
| 历史指代 | 追问是否都已完成 | 查计划有没有变成结果。 |
| 新版本 | 区域复核另有来源 | 原题核实际采用的新材料。 |
| 结构检查 | 摘要店别和状态逐项回查 | 不把字段齐全当验收。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

- 本店限定从请求丢失、动作扩大到区域时，并列巡店原句、提交素材与稿件，核范围在哪一步改变。

- 追问“都好了吗”把历史区域计划写成完成时，固定当前材料比较有无历史，检查计划是否被当成执行记录。

- 位置调整正确传入，稿件却把待复核品项写成通过时，查品项条件和实际意见来源；位置完成不能替代品项复核。

## 怎么确认配好了

验收时按门店、位置动作、品项复核三项核对每句话的依据，同时查素材有没有新版本。区域复核意见取得后，另行补入并重问原题，记录稿件是否采用这份新来源，不能只因生成时间较晚就说内容已经更新。结构化摘要应先验可解析性，再核门店范围和状态，字段整齐不等于整改已验收。本例没有实际发布门店动态，也不执行巡店或采购确认；缺少的结论仍应等待对应记录。
