# 便利店加盟门店督导的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

加盟督导场景中，商品与营销文案起草的依据分散在巡店表、加盟合同、整改通知与陈列标准四类材料里。这些材料由总部与门店在周、月节奏中分别产生，督导需要把其中的执行要求转写为可下发的文案。与直营鲜食订货相比，此处核心动作是总部对加盟商执行标准的监督，文案一旦偏离材料口径，可能引发加盟纠纷与品牌形象受损。

材料本身并不自带统一的字段结构。巡店表记录陈列与订货核对结果，加盟合同规定可宣传范围，整改通知说明待修正事项，陈列标准给出位置与方式要求。起草文案时，模型接入需要让这些材料可被检索并作为上下文送入模型，同时保留材料原文以便逐句核对。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务都必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。`AIPROXY_API_ENDPOINT` 填写 AI Proxy 服务根地址，不要附加 `/v1`。系统至少需要一个语言模型和一个索引模型才能正常使用。模型 ID 是接口请求 Body 中 `model` 字段的值，全局唯一；模型名仅用于展示。

检索库与向量模型存在关联约束：跨不同向量模型的库不可共同关联。核对时应先确认标识，排除不符合者，再记录实际观察。相关度分数不承担权限或实体隔离职责，检索本身不构成授权。

假设演练样本（纸面材料，非真实记录）：某加盟合同附件载明“本品牌夏季饮品宣传可使用总部提供的物料图，门店自行撰写的推荐语不得出现功效承诺”。同月一份整改通知载明“XX路店冰柜陈列未按标准执行，限七日内整改”。一条待判定拟稿句为“本店饮品清热解暑，效果显著”。核对对象为该拟稿句是否落在合同允许的宣传范围内。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写 AI Proxy 服务根地址，不附加 `/v1` | 与文档要求一致；比较对象为附加了 `/v1` 的写法 |
| `AIPROXY_API_TOKEN` | 填入与服务端一致的非空管理员 Token | 文档要求非空且一致；比较对象为应用 API Key |
| 语言模型与索引模型 | 各启用至少一个 | 文档要求系统至少各一个；比较对象为仅启用语言模型 |
| 模型 ID | 与渠道中“模型”字段一致 | 文档说明二者一致；比较对象为展示用模型名 |
| 上下文送入范围 | 仅送入该合同附件与整改通知原文 | 本次试验限定；比较对象为混入其他门店材料 |
| 检索结果核对 | 逐条记录命中的材料标识 | 本次试验限定；比较对象为仅记录相关度分数 |

## 容易做错的三处

1. 把展示用模型名当作请求 Body 中的模型 ID。输入为渠道列表中的模型名，比较对象为渠道中“模型”字段，观察结果是二者是否一致。
2. 用相关度分数替代权限判断。输入为检索返回的分数，比较对象为该用户可访问的材料范围，观察结果是分数高低是否被当作授权依据。
3. 将未载明事项判定为否定。输入为合同附件未提及的某项宣传方式，比较对象为附件已载明的允许范围，观察结果是该方式被记为未获支持还是被记为禁止。

## 怎么确认配好了

1. 取假设样本中的合同附件原文与拟稿句“本店饮品清热解暑，效果显著”。输入为这两段文本，比较对象为附件中“不得出现功效承诺”的表述，观察结果为拟稿句是否落在该禁止范围内。预期为落在范围内，此预期尚未实测。
2. 取假设样本中的整改通知原文。输入为该通知，比较对象为其中“限七日内整改”的期限表述，观察结果为通知是否载明起算日期。若未载明，记录为待核实，不判定为逾期。
3. 取检索返回结果列表。输入为一次检索的返回项，比较对象为各项所属向量模型标识，观察结果为是否存在跨不同向量模型的库被共同关联。若存在，排除不符合者并记录实际观察；若返回为空，以纸面输入 `[]` 核对下游设计，不声称虚构规则检索必然返回空。
