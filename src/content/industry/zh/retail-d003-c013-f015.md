# 便利店加盟门店督导的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

加盟督导场景的数据围绕总部标准与门店执行之间的核对展开。巡店表记录陈列、订货与整改事项，加盟合同界定双方权利义务，整改通知承载问题描述与期限，陈列标准给出商品位置与宣传口径。这些材料由区域督导在周度或月度节奏中采集与使用，来源包括督导APP、POS销售、加盟系统与门店照片。文案起草时，需要从上述材料中召回可引用的原文，判断拟稿句是否有材料支持。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。搜索模式包含语义检索、全文检索与混合检索。混合检索通过 RRF 融合多路结果，重排模型对候选文本二次排序，重排得分可用于过滤。最低相关度仅在语义检索或使用结果重排时生效。引用上限以 token 为单位，控制单次搜索最多引用的内容量。问题优化用于指代消除和问题扩展，在检索前增加一次模型调用。图片检索需要图像输入及相应模型能力，重排需要模型并按设置启用。检索结果以数组输出，长度可以为 0。

假设演练样本。材料原文一：「加盟合同附件三载明，鲜食区价签须与总部当期陈列标准一致，督导于每月巡店时核对。」材料原文二：「整改通知编号 ZG-2024-0317 记录，该门店冷柜温度记录缺失三日，限五个工作日内补录并提交。」待判定拟稿句：「本店鲜食价签已全部符合总部标准，冷柜温度记录完整。」核对对象为上述两份材料，期间为整改通知载明的五个工作日，字段为价签一致性与温度记录完整性。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 巡店表、加盟合同、整改通知、陈列标准各建一个库 | 四库使用相同向量模型方可共同关联，逐库核对向量模型标识 |
| 搜索模式 | 先按语义检索与全文检索分别测试同一问题 | 比较两种模式对「价签」「ZG-2024-0317」的召回内容差异 |
| 引用上限 | 本次假设起点设为覆盖一份整改通知全文的 token 量 | 用长短不同的整改通知测试内容是否被截断，再调整 |
| 最低相关度 | 先标注相关与无关样本，再确定阈值 | 仅语义检索或重排时生效，比较过滤前后候选数量 |
| 问题优化 | 多轮追问场景开启，单轮明确问题关闭 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型时启用，按设置执行 | 比较重排前后排序，重排得分用于过滤 |

## 容易做错的三处

1. 将检索召回当作授权判断。检索命中加盟合同片段，不代表拟稿句获得合同授权。错误表现是直接把召回内容当作可发布依据。检查方法：输入拟稿句与召回原文，比较两者主体、对象与状态是否一致，观察是否存在未获支持的表述。
2. 跨不同向量模型的库共同关联。错误表现是将使用不同向量模型的库放入同一搜索节点。检查方法：核对各库向量模型标识，排除不符合者，记录实际观察，不执行跨模型检索来比较漏召回。
3. 将待审核状态写成已完成。错误表现是把整改通知的提交动作写成已补录完成。检查方法：输入整改通知原文与拟稿句，比较通知载明的期限与拟稿句声称的完成状态，观察是否缺少完成证据。

## 怎么确认配好了

1. 输入假设样本的材料原文一、材料原文二与待判定拟稿句，比较拟稿句中「价签已全部符合」与合同附件三载明的核对要求，观察召回内容是否包含支持该表述的原文。若召回内容仅显示核对义务而未显示核对结果，该表述未获支持。
2. 输入整改通知编号 ZG-2024-0317，比较全文检索与语义检索对该编号的召回情况，观察全文检索是否命中该编号。若两种模式均未返回该编号对应内容，记录为未召回，不判定为不存在。
3. 输入一份不含价签与温度记录内容的巡店表片段，比较召回结果与拟稿句主题，观察返回引用内容是否为空数组。若返回空数组，按节点输出长度可以为 0 的说明核对下游设计，不声称虚构规则检索一定返回空数组。
