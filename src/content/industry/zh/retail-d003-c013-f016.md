# 便利店加盟门店督导的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在便利店加盟门店督导的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。加盟督导文案收集要区分观察、拟议整改和实际完成，表单提交不产生认证或处罚。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

假设督导便签只记录货架陈列观察，整改建议还在讨论，照片对象属于另一门店。表单收门店、观察原句和照片对应，人员选择核素材或补整改依据，提交后传后续写作。节点等待交互后继续，不自带巡店数据库，业务审批与材料核验另走后续流程。

## 配置怎么定

| 督导文案表单 | 自拟素材 | 核验依据 |
| --- | --- | --- |
| 陈列观察 | 便签层级 | 非正式违规 |
| 整改建议 | 仍在讨论 | 非已完成 |
| 照片对象 | 另一门店 | 核对应关系 |
| 选择分支 | 素材或整改 | 查传入原句 |
| 对外办理 | 发布工单另接 | 权限及回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

观察便签被写正式违规结论时，查适用规则与认定材料；拟议整改被写已完成时，查现场执行凭据；他店照片套本店时，核对象对应。三处分别核观察层级、动作阶段和证据归属，不以字段齐备证明督导结论有效。

## 怎么确认配好了

验收拟写文案逐句对原句与图片说明，缺对应的照片不用作本店事实。补整改依据只更新该项状态，处罚或认证仍需真实授权及流程。对外发布、整改工单和门店回写需要业务接口及回执，表单用于汇集可核素材，不能由一次提交代替经营判断。 观察便签与正式认定依据各留位置，拟议整改的原文状态保留到文案复核，照片另核门店。
