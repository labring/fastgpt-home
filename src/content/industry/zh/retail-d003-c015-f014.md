# 信用证审单交单的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

信用证审单交单服务银行付款条件，核心在于单证一致，与出口退税申报的税务匹配逻辑不同。主要数据来源包括开证行通知、UCP600条款、货代提单和银行交单记录。日常处理的文档为信用证、商业发票、提单、保险单和汇票，更新频率为每单。这些特征意味着模型接入后需要处理的是逐单变化的条款与单据组合，文案起草的核对依据来自这些材料，不能把某类材料的常见做法当作另一类材料的既有状态。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy 服务，App 与 Admin 必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。模型渠道与应用配置需要分别核对，模型能力按应用所需输入验证，多模态、工具调用与思考配置各自独立。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。检索是召回过程，不承担权限或实体隔离；相似度设置不排除无关业务或未授权记录。跨不同向量模型的库不可共同关联，只能先核标识并排除不符合者。

假设演练样本：某信用证项下商业发票草稿拟写宣传句。供核对的材料原文为：“本信用证要求发票注明货物描述与信用证条款一致。”“发票须显示受益人名称、发票号及金额。”拟稿句为：“本产品已获国际认证，品质领先。”该句中的认证与品质表述在材料中没有对应记载。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址 | 文档要求不附加 /v1；与部署实际根地址比较 |
| AIPROXY_API_TOKEN | 填写非空管理员 Token | 文档要求与服务端一致；与渠道配置比较 |
| 模型渠道 | 按协议类型选择 | 文档说明哪家模型选对应服务商；与模型列表比较 |
| 模型能力 | 按输入类型核对 | 文档要求多模态、工具调用分别验证；与拟用输入比较 |
| 应用参数 | 在应用或节点配置中设置 | 文档说明不能假设兼容接口同名字段覆盖；与节点实际值比较 |
| 检索关联 | 核标识并排除不符者 | 文档说明跨向量模型库不可共同关联；与库标识比较 |

## 容易做错的三处

1. 把模型渠道配置完成当作模型能力已满足。输入为渠道列表，比较渠道协议与拟用输入类型，观察是否缺少对应能力声明。
2. 把相似度设置当作权限或实体过滤器。输入为检索配置，比较检索范围与目标记录归属，观察是否出现未授权记录。
3. 把拟稿句中的认证表述当作材料已支持。输入为材料原文与拟稿句，比较主体、对象与状态，观察材料中是否载有该认证记载。

## 怎么确认配好了

1. 输入假设样本的材料原文与拟稿句，比较拟稿句中的认证与品质表述是否出现在材料中，材料未载明时记录为未获支持，不判定为否定或冲突。
2. 输入渠道配置与拟用输入类型，比较模型能力声明与实际输入要求，观察是否缺少多模态或工具调用能力。
3. 输入检索库标识与目标记录归属，比较库标识是否一致，排除不符者并记录实际观察；空结果可用明确的纸面输入 [] 核对下游设计，不声称虚构规则检索一定返回空。
