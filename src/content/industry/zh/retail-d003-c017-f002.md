# 加盟费与保证金结算的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在加盟费与保证金结算的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。核费用品目、服务内容指向及保证金复核状态，防止说明稿借用别店结果。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

加盟服务说明稿可先拟发票品目“培训服务”，另有备注“服务项目详见附表，附表待补”。保证金台账只写“本事项复核中”。当前材料既没有服务附表，也没有本事项复核结果；历史对话中的另一家店已经结束结算。文案应先按本轮门店与事项核实际输入，保留品目、附表指向和复核阶段。发票上的服务名称不列明所有服务项目，也不能作为课程已经全部实施的依据。此处不涉及真实款项或结算条件。

## 配置怎么定

| 上下文核对项 | 本题材料 | 验收动作 |
| --- | --- | --- |
| 品目范围 | 培训服务名称 | 不扩成完整服务包。 |
| 附表缺口 | 项目附表尚未提供 | 逐项查内容出处。 |
| 事项身份 | 本店复核中与别店旧结果 | 核本轮状态指代。 |
| 实施记录 | 品目不等于培训完成 | 回查课程依据。 |
| 新增材料 | 附表与复核意见分开 | 同题核各自改变的句子。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

- 附表待补条件没进入请求，稿件自行列出完整服务包时，逐项回查项目名称来源，不从品目补目录。

- 别店历史结算结果进入本事项说明时，固定当前台账比较有无历史，核门店、事项及状态指代。

- 发票品目被写成培训已完成时，查实际课程记录；开具品目与实施服务需要不同证据，结构化字段齐全也不能替代。

## 怎么确认配好了

验收把服务品目、实际内容和复核进度分别成问，对照本轮收到的材料和稿件对应句。补服务附表后核它属于同一事项，补复核意见后另核状态，不把两份新增资料混成一项结果。引用长度按token检查，回复上限单独核；实际模型能力及上下文配置应有依据，不能由一次成功请求推出完整窗口。文本介绍只说明所给记录，费用处理、课程实施及正式结算各有实际凭证。
