# 加盟费与保证金结算的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

加盟费与保证金结算围绕资金收付与违约扣款展开，主要材料为加盟费发票、保证金台账、扣款通知与合同付款计划。这些材料由财务系统、加盟合同、银行流水与门店违规记录共同产生，更新频率为月及每次扣款。商品与营销文案起草要引用上述材料中的费用项目、金额口径与状态描述，文案句子是否被材料支持，取决于材料原文是否载明对应主体、对象与有效范围。模型接入与配置在此环节的作用，是让起草过程能够调用已启用的语言模型与索引模型，并对文案句子与来源材料做逐句比对。

## 这些特征在「模型接入与配置」这一环带来什么约束

系统至少需要一个语言模型和一个索引模型才能正常使用。从 V4.17.0 起，AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 服务都必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。模型 ID 是请求 Body 中 `model` 字段的值，全局唯一；模型名用于展示，可以自定义。

假设演练样本：某连锁品牌财务人员提供三句材料原文供核对——“2026年3月加盟费发票，金额人民币五万元，对应合同编号 A-2026-017，付款方为某某餐饮管理有限公司。”“保证金台账显示该合同保证金余额人民币十万元，状态为已收讫。”“扣款通知载明 2026年3月因门店违规扣款人民币两千元，扣款事由为未按标准操作。”待判定的拟稿句为：“本品牌加盟费五万元，保证金十万元，违规一次扣两千元，费用透明无争议。”该句把三份材料中的具体金额合并为对外宣传口径，并加入材料未载明的“无争议”表述，需要逐项比对主体、期间与字段。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写 AI Proxy 服务根地址，不附加 `/v1` | 与部署模板给出的服务地址比较，确认路径层级一致 |
| `AIPROXY_API_TOKEN` | 填写与服务端一致的非空管理员 Token | 与 AI Proxy 服务端配置值比较，确认非空且一致 |
| 语言模型启用状态 | 至少启用一个语言模型 | 与系统要求“至少一个语言模型”比较 |
| 索引模型启用状态 | 至少启用一个索引模型 | 与系统要求“至少一个索引模型”比较 |
| 模型能力核对 | 按文案起草所需输入核对模型能力 | 与模型配置中 `vision`、`toolChoice` 等字段比较 |
| 模型探测配置 | 探测间隔设为 5～60 分钟之间的整数 | 与文档给出的探测间隔范围比较 |

## 容易做错的三处

1. 把材料中某一合同的金额直接写成面向所有加盟商的通用宣传金额。假设样本中五万元与十万元均对应合同编号 A-2026-017，拟稿句省略了该主体与期间限定，比对时应发现金额适用范围被扩大。
2. 把“已收讫”的保证金状态改写成“可退”或“无争议”。材料只载明状态为已收讫，未载明退还条件或争议情况，拟稿句中的“无争议”属于未获支持表述。
3. 把扣款通知中的单次扣款金额写成固定标准。材料载明的是 2026年3月一次扣款两千元，拟稿句写成“违规一次扣两千元”，把单次记录变成一般规则，缺少材料支持。

## 怎么确认配好了

1. 输入假设样本中的三句材料原文与拟稿句，比较拟稿句中的每个金额、主体与状态是否能在原文中找到同主体、同期间、同字段的对应表述。若拟稿句出现原文未载明的“无争议”，该句属于未获支持，应记录缺口并保留原文范围。
2. 输入合同编号 A-2026-017 与拟稿句，比较金额适用范围。若拟稿句未限定该合同编号而直接写成通用金额，判定为范围扩大；若拟稿句保留“该合同项下”限定，则与材料一致。
3. 输入保证金台账状态“已收讫”与拟稿句表述，比较状态字段是否被改写。若拟稿句出现“可退”或“无争议”等材料未载明的状态，判定为未获支持；若拟稿句仅写“保证金已收讫”，则与材料一致。
