# 加盟费与保证金结算的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

加盟费与保证金结算的核心资料是加盟合同中的付款计划、保证金台账、扣款通知和加盟费发票。这些资料共同决定一笔费用是否应收、是否已收、是否应退。费用结算关注资金与违约扣款，与特许加盟备案管理分属不同事务，检索时不应把备案类文档当作结算依据。

资料更新频率为每月及每次扣款，因此同一加盟商在不同月份可能对应多条台账记录。检索结果必须能区分月份与扣款事由，否则引用内容容易跨期混用。商品与营销文案起草环节需要判断拟稿句中的金额、期限、退款条件是否被这些资料支持，检索召回的内容就是判断依据。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，应先核对向量模型标识，排除不符合者，并记录实际观察到的关联范围。

语义检索依赖向量距离计算相似度，全文检索依赖关键词命中，混合检索通过 RRF 融合两路结果，结果重排使用 ReRank 模型二次排序。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离功能。引用上限以 token 为单位控制每次搜索引用的内容量。问题优化用于指代消除和问题扩展，会在正式检索前增加一次模型调用。

假设演练样本：材料原文一为“甲方应于签约之日起十日内支付加盟费人民币五万元，保证金人民币三万元，保证金于合同期满且无未结扣款时退还”。材料原文二为“2024年3月扣款通知载明：因门店违规陈列，扣减保证金人民币两千元，扣款事由为陈列不合规”。待判定拟稿句为“加盟商保证金在任何情况下均可全额退还，加盟费可分期支付”。该拟稿句与材料原文一、二在退款条件与支付方式上均未获得支持，属于待核实内容，不能直接用于对外文案。

## 配置怎么定

下表围绕本页样本列出与本功能相关的官方已说明设置或实施核对项。数值为本次假设试验起点，用于与样本比对，不代表官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联含加盟合同与台账的同一向量模型库 | 先核对向量模型标识，排除不同模型的库 |
| 搜索模式 | 混合检索 | 金额与编号需关键词命中，退款条件需语义匹配 |
| 引用上限 | 假设设为 2000 token | 与样本原文长度比较，确认退款条件句完整进入引用 |
| 最低相关度 | 假设设为 0.4 | 用样本拟稿句与原文句分别测试，观察无关片段是否被过滤 |
| 问题优化 | 开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 启用 ReRank | 候选较多时比较重排前后得分，确认退款条件句排位 |

## 容易做错的三处

1. 把最低相关度当作权限过滤。最低相关度只过滤低相关度结果，不排除无关业务或未授权记录。检索本身不构成授权，业务核验与审批需要下游实现。
2. 把 RRF 写成可开启的开关。RRF 是混合检索中多路结果的融合过程，不是独立配置项。
3. 把待审核状态当作缺少操作权限。待审核只表示流程未完成，签署、合作达成与合同生效是三个不同事实。

## 怎么确认配好了

1. 输入样本材料原文一与拟稿句“保证金在任何情况下均可全额退还”。比较原文中“合同期满且无未结扣款”这一退款条件与拟稿句的绝对表述。若检索引用完整包含该条件句，且拟稿句被标注为未获支持，则满足预期。若引用缺失该条件句，则记录为召回不完整。
2. 输入样本材料原文二与查询“保证金扣款事由”。比较召回内容是否包含“陈列不合规”与扣款金额。若召回内容同时包含事由与金额，则满足预期。若仅召回金额而缺失事由，则记录为字段不完整。
3. 输入空结果承接场景，使用明确的纸面输入空数组核对下游设计。比较下游节点是否在引用长度为 0 时仍走通输出链路。若下游按空引用继续执行，则满足预期。不声称虚构规则检索一定返回空数组。

以上三项均以假设样本为输入，未实际执行测试。跨模型库不可共同关联，只核对标识并排除不符合者，不执行跨模型检索比较。
