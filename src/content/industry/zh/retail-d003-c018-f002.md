# 区域经销商库存补货的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在区域经销商库存补货的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。核北区意向登记、包装版本与历史宣传的适用范围，避免新品稿变成交付承诺。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

经销商新品说明可拟北区材料：“新版包装接受意向登记；交付安排另核。”另一份商品附页只写本轮包装已调整，历史宣传稿则介绍旧版套装在另一地区的供应。上下文核对先标出区域、包装版本及意向阶段，再看这些限定是否进入本次请求。材料可以支持新版介绍与登记说明，没有提供本批到货或配送范围。不能把历史的可供应说法移到北区，也不能由包装变更补出商品性能变化。

## 配置怎么定

| 上下文核对项 | 本题材料 | 验收动作 |
| --- | --- | --- |
| 区域阶段 | 北区接受意向 | 不扩成各区交付。 |
| 包装版本 | 当前新版与历史旧套装 | 核本轮对象指代。 |
| 属性范围 | 仅说明包装调整 | 不补商品性能。 |
| 供货缺口 | 交付安排待核 | 原句对照确定措辞。 |
| 新品卡 | 区域、版本与状态 | 解析后逐项追出处。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

- 北区和意向限定丢失，稿件把登记写成各区均可交付时，对照原说明、实际输入及稿件，定位范围扩大。

- 历史旧套装进入新版介绍时，固定当前附页比较有无历史，查版本、地区与“这套”的指代。

- 只有包装调整文字却生成新性能或具体配送安排时，逐句查规格和供货依据，不用完整句式替代缺少的资料。

## 怎么确认配好了

验收分别问新版改了什么、登记面向何处及交付是否已确定，对照实际请求和原文。取得本批供货说明后，再核版本与地区并重复同题，记录新增来源实际改变的句子。模型上下文配置、引用token范围和回复长度各自检查，文本变长不说明全部条件已进入模型。结构化新品卡应先验解析，再核区域、版本和状态。介绍稿保留意向阶段，供货安排仍需对应记录，不由文案生成执行补货或调拨。
