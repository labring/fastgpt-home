# 区域经销商库存补货的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

区域经销商库存补货属于批发与经销商渠道下的日常滚动订单，与季节性集中订货不同。主要数据来源包括经销商ERP、品牌订货系统、仓库库存和销售回款，日常文档涉及补货申请、库存周转表、出库单和回款计划。本页只处理商品与营销文案起草中的模型接入与配置，不涉及企业身份认证或报告分析。

## 这些特征在「模型接入与配置」这一环带来什么约束

文案起草所需的模型能力须按实际输入核对。若补货申请含产品图片，须确认语言模型具备图片输入能力；若需从库存周转表提取字段，须确认工具选择或函数调用能力。AI Proxy 为必需依赖，App 和 Admin 服务必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。模型参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。

假设演练样本：某区域经销商销售内勤于2026年10月14日提交一份补货申请，材料原文为“本批次补货申请涉及产品A共200箱，申请日期2026年10月14日，对应出库单号CK-20261014-001，回款计划约定2026年11月30日前结清”。待判定拟稿句为“该经销商所有补货申请均已在2026年10月14日完成出库”。判断所需主体为“本批次补货申请”，对象为“产品A共200箱”，状态为“申请日期2026年10月14日”，有效范围为“出库单号CK-20261014-001”。拟稿句将“本批次”扩展为“所有”，且将“申请”等同于“完成出库”，材料未载明全部补货申请范围及出库完成状态。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不附加 /v1 | 对照服务端实际部署地址，确认无路径后缀 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空管理员 Token | 确认非空且与 AI Proxy 配置一致 |
| 语言模型图片输入能力 | 按补货申请是否含产品图片核对 | 检查模型元数据 vision 字段 |
| 工具选择或函数调用能力 | 按是否需从库存周转表提取字段核对 | 检查 toolChoice 或 functionCall 字段 |
| 模型映射 | 如 gpt-4o-test 映射到 gpt-4o | 核对模型 ID 与渠道模型一致 |
| 渠道优先级 | 范围 1～100，数值越大越优先 | 按实际渠道配置核对 |

## 容易做错的三处

1. 将“本批次补货申请”拟稿为“所有补货申请”。材料仅载明本批次涉及产品A共200箱，未说明全部申请范围。检查输入为材料原文与拟稿句，比较主体范围是否一致，若拟稿句将限定范围扩展为全部则判定为未获支持。
2. 将“申请日期”等同于“完成出库”。材料载明申请日期2026年10月14日及出库单号，未载明出库完成状态。检查输入为材料原文与拟稿句，比较状态字段是否一致，若拟稿句将申请状态表述为完成出库则判定为未获支持。
3. 将回款计划约定日期当作已回款事实。材料载明回款计划约定2026年11月30日前结清，未载明实际回款。检查输入为材料原文与拟稿句，比较回款状态是否一致，若拟稿句将计划日期表述为已结清则判定为未获支持。

## 怎么确认配好了

1. 针对假设演练样本的拟稿句“该经销商所有补货申请均已在2026年10月14日完成出库”，输入材料原文，比较主体范围“本批次”与“所有”及状态“申请”与“完成出库”。若拟稿句超出材料载明范围，则判定为未获支持，记录证据缺口。
2. 针对回款计划，输入材料原文“回款计划约定2026年11月30日前结清”，比较拟稿句是否将计划日期表述为已结清。若材料未载明实际回款，则判定为待核实，不得表述为已完成。
3. 针对模型配置，输入 AIPROXY_API_ENDPOINT 和 AIPROXY_API_TOKEN 的假设填写值，比较是否与服务端配置一致且非空。若任一项缺失或为空，启动校验将失败，须核对后再重新验证。
