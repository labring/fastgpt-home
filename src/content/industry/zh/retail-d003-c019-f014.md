# 即时零售门店履约的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

即时零售门店履约按分钟处理线上订单，文档来源包括即时订单、拣货清单、缺货报备与配送异常单，资料更新频率为分钟级、每单。商品与营销文案起草要引用这些材料中的商品名称、规格、库存状态与替换说明，供门店人员生成对外文案。材料本身按单生成，文案核对的对象是具体订单记录，不是周期性盘点结果。这一差别决定了本页的配置围绕单条材料的可追溯性展开。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。从 V4.17.0 起，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。系统至少需要一个语言模型和一个索引模型才能正常使用。模型 ID 是接口请求 Body 中 model 字段的值，全局唯一；模型名用于展示，可自定义。

假设演练样本：材料原文为「本单商品：某品牌纯牛奶 250ml×12，门店库存状态为有货，拣货员已完成拣货。」「替换说明：原商品缺货时替换为同规格同品牌商品，替换需门店值班人员确认。」拟稿句为「本单牛奶已拣货完成，库存充足，可放心下单。」待判定该拟稿句是否被材料支持。

配置围绕该样本：语言模型用于生成文案，索引模型用于检索材料。模型能力需按应用所需输入核对，多模态、工具调用及思考配置分别验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。检索库与向量模型标识需先核对，跨不同向量模型的库不可共同关联。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 文档示例为服务根地址，不附加 /v1，比较对象为是否附加路径 |
| AIPROXY_API_TOKEN | 假设填非空管理员 Token | 文档要求与服务端一致且非空，比较对象为是否为空 |
| 语言模型 | 假设启用一个语言模型 | 文档要求至少一个语言模型，比较对象为是否已启用 |
| 索引模型 | 假设启用一个索引模型 | 文档要求至少一个索引模型，比较对象为是否已启用 |
| 模型 ID | 假设与渠道中模型一致 | 文档说明模型 ID 全局唯一，比较对象为渠道配置中的模型名 |
| 模型探测 | 假设开启自动探测，间隔设为 30 分钟 | 文档支持 5～60 分钟整数，比较对象为是否在范围内 |

上表数值均为本次假设试验起点，不是官方默认值。模型探测仅针对已启用模型，首次失败后最多重试 3 次，全部失败才判定异常。

## 容易做错的三处

1. 将 AIPROXY_API_ENDPOINT 填成完整请求地址并附加 /v1。检查方式：输入该变量值，比较其是否只含协议、主机与端口，观察是否附加了路径。
2. 用应用 API Key 代替 AIPROXY_API_TOKEN。检查方式：输入所填 Token，比较其与服务端管理员 Token 是否一致，观察是否为空或类型不符。
3. 把拟稿句中的「库存充足」当作材料已载明。检查方式：输入材料原文与拟稿句，比较两者是否出现同一字段的同一取值，观察材料是否只写了「有货」而未写「充足」。

## 怎么确认配好了

1. 输入假设样本的材料原文与拟稿句，比较拟稿句是否只使用材料中出现的商品名称、规格与状态，观察「库存充足」是否在材料中有对应字段。材料未载明时记为未获支持。
2. 输入所配置的语言模型与索引模型标识，比较两者是否均已启用，观察是否满足至少各一个的要求。缺少任一模型时记为配置不完整。
3. 输入模型探测配置的间隔值，比较其是否为 5～60 之间的整数，观察是否落在文档说明的范围内。超出范围时记为待调整。

以上判定均为纸面核对，未实际执行测试、部署或审批。检索结果为空时，可用明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回空数组。
