# 原产地证书申办的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在原产地证书申办的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。核商品描述、装运地点和待补产地说明，避免来源介绍借入旧批次信息。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

商品来源介绍可拟发票文字：“木质零件，产地说明待补。”装箱单只列装运地点，历史稿件则介绍另一批商品的来源。当前起草任务要保留零件对象、待补状态和各地点角色，先核这些内容是否进入实际请求，再查历史指代。发票品名可以支持商品描述，没有给出产地；装运地点也不能补成生产地点。本例只用普通自拟文字检查文案依据，不给出原产规则、证书结果或实际商品来源结论。

## 配置怎么定

| 上下文核对项 | 本题材料 | 验收动作 |
| --- | --- | --- |
| 商品对象 | 木质零件 | 不补成未给出的成品属性。 |
| 来源缺口 | 产地说明待补 | 核确定产地的真实依据。 |
| 地点角色 | 装运地点另有用途 | 不替代生产地点。 |
| 历史批次 | 另一批来源介绍 | 核本轮这批的指代。 |
| 新增材料 | 当前零件产地说明 | 解析后追地点及状态来源。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

- 待补条件从请求丢失，稿件却给出确定产地时，对照完整发票、实际输入及来源句，定位新增说法。

- 旧批次来源进入“这批”的介绍时，固定当前发票比较有无历史，核商品身份、批次与引用版本。

- 装运地点被写成生产地点时，回查字段角色和实际原句；两者在同段出现不表示能互相替代。

## 怎么确认配好了

验收分别问商品是什么、产地材料是否给出以及装运地点说明什么，逐句对照实际收到的来源。补入本批产地说明后，核它对应当前零件，再用原题查新增资料是否参与；不借旧批说明填空。模型上下文能力及配置、知识引用token范围和回复长度分开核，输入缺失不由长回复补齐。结构化商品卡先验解析，再核地点及状态字段。写作流程不执行证书签发，缺少的来源依据继续标明待补。
