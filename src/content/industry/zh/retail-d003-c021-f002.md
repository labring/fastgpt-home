# 品牌会员私域运营的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在品牌会员私域运营的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。会员邀请稿需保留报名人群、本活动用途与历史活动的不同范围。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

会员邀请文案可拟简报“仅向已报名者发送活动资料”，备注“本轮不含门店体验预约”，旧稿却介绍过店内体验。当前起草需要让两条限制真正进入请求，不能把已报名者缩成所有会员，也不能沿用历史中另场活动的预约话术。资料发送只是一种沟通，当前未给体验名额或安排。文案可复述本活动资料用途，不能由长背景中出现门店一词就补成可预约权益。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 人群原句 | 仅已报名者 | 核实际请求。 |
| 服务限制 | 不含门店预约 | 成稿保留。 |
| 旧活动 | 另场体验 | 同题空历史比较。 |
| 长度条件 | 两条限制均表达 | 不为短稿省略。 |
| 实际权益 | 本轮未给 | 不由背景补齐。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是报名限制在实际输入里缺失，应对完整简报与请求，查人群原句有没有送达。第二处是历史体验预约进入本轮，应固定当前材料比较空历史，核活动及服务身份。第三处是回复为求简短删去本轮不含预约，应逐句核草稿与限制，留足表达条件的空间。三项分别查输入覆盖、历史适用和输出范围，不由增加回复预算生成体验依据或真实发送许可。

## 怎么确认配好了

验收分别问邀请谁、资料用于什么、本轮不含什么，对照实际请求和成稿。引用按token限制时，保留已报名及不含预约两个条件，再看文案是否都采用；回复上限不是模型完整上下文窗口，实际容量需另核。若补门店说明，应对本活动，不借旧稿改变现有范围。本练习不发送信息或改变会员权限，也不判断真实授权效力，当前未给权益不写成已经提供。
