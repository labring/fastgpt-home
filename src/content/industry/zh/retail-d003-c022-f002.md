# 品牌全渠道库存调拨的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在品牌全渠道库存调拨的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。调拨服务文案需完整呈现到仓、到店和适用区域的不同条件。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

全渠道服务文案可拟资料“协助跟踪到区域仓”，附注“门店接收另核”，地域页“目前文字只描述东区”。当前要写门店介绍，不能把到仓缩成到店，也不能省略地域后称各店均支持。实际请求若只保留跟踪和区域名，回答仍缺完整服务边界。检索材料进入上下文后应检查哪些句子实际被保留，不从文档已上传推介绍稿已经读到附注，也不补实际运输承诺。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 服务终点 | 区域仓 | 不改门店。 |
| 接收附注 | 门店另核 | 核引用保留。 |
| 地域范围 | 仅东区 | 输出不扩大。 |
| 丢失定位 | 引用或起草阶段 | 对实际文本。 |
| 新增范围 | 另有门店地区资料 | 先核身份。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是门店接收另核被引用预算裁掉，应对源附注与实际输入，确认丢在检索引用还是起草阶段。第二处是区域仓被稿件改成顾客所在门店，应核地点主体与采用句，不让自然表达改变服务终点。第三处是东区限制在短稿中消失，应查输出覆盖及回复长度，不能由简化扩大范围。三项分别查条件送达、地点含义和地域表达，不把调整预算当服务已升级。

## 怎么确认配好了

验收分别问跟踪到哪里、什么仍待核、当前资料覆盖哪区，逐句比输入与稿件。模型窗口按实际能力核，引用上限与回复长度分别记录；原文条件若没进入请求，先修传递。补门店或其他地区材料后，应核其身份再重写，不从一个地区推广全部。本练习不调拨或通知门店，也不声称真实到货保障，文案只能说明当前资料支持的服务范围。
