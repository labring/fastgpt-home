# 品牌售后维修服务的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

品牌售后维修服务围绕保修责任和线下维修网点展开，处理对象是保修卡、维修工单、检测报告和换货审批，与电商平台退款流程存在明显差别。售后系统、门店订单、维修网点反馈和国家三包目录共同构成文案起草时需要核对的材料来源。文案中涉及保修范围、维修时限或换货条件的表述，必须能回到上述材料中的具体字段，模型接入环节因此需要保证渠道配置、模型能力与应用参数三者一致，使起草结果可追溯到材料原文。

## 这些特征在「模型接入与配置」这一环带来什么约束

从 V4.17.0 起，AI Proxy 为必需依赖，App 和复用 App/Service 配置的 Admin 服务都必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。`AIPROXY_API_ENDPOINT` 填写 AI Proxy 服务根地址，不附加 `/v1`。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。系统至少需要一个语言模型和一个索引模型才能正常使用。模型能力按应用所需输入核对，多模态、工具调用分别验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。

假设演练样本：某品牌售后中心客服依据一份维修工单起草商品文案。工单原文为：“工单号 WX-2026-0417，受理日期 2026 年 4 月 17 日，产品为 A 型净水器，故障描述为出水异味，检测结论为滤芯到期需更换，保修状态为整机保修期内，滤芯属耗材不在保修范围。”待判定拟稿句为：“A 型净水器整机在保修期内，滤芯更换属于保修范围，可免费更换。”主体、对象、期间和字段均可对照工单原文。

## 配置怎么定

| 配置项 | 本页用途 | 核对方式 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 指定 AI Proxy 根地址，供文案起草调用模型 | 核对填写值不含 `/v1` 或 `/chat/completions` |
| `AIPROXY_API_TOKEN` | 服务端管理员 Token | 核对与服务端配置一致且非空 |
| `AGENT_ENGINE` | 选择 Agent 引擎，可选 `fastAgent` 或 `piAgent` | 按本页起草流程所需引擎核对 |
| `CHAT_MAX_QPM` | 聊天 QPM 限制 | 核对是否与套餐限制冲突，以套餐限制为准 |
| `LLM_REQUEST_TRACKING_RETENTION_HOURS` | LLM 请求追踪保留时长 | 核对保留时长是否满足排查需要 |
| `SYSTEM_MAX_STRING_LENGTH_M` | 同步字符串处理最大字符数 | 核对工单与保修卡拼接文本是否在范围内 |

表中数值均为本次假设试验起点，选择理由是便于与官方说明的默认值比较，不代表官方推荐值。

## 容易做错的三处

1. 把 `AIPROXY_API_ENDPOINT` 填成完整模型请求地址并附加 `/v1`。检查输入为假设样本中的工单原文与拟稿句，比较填写值与文档说明的根地址格式，观察填写值是否包含 `/v1` 或 `/chat/completions`。
2. 用旧 OpenAI 环境变量替代 `AIPROXY_API_TOKEN`。检查输入为服务端配置的管理员 Token，比较该 Token 与 `AIPROXY_API_TOKEN` 是否一致且非空，观察启动校验是否通过。
3. 把拟稿句中的保修范围表述直接当作工单结论。检查输入为工单原文“滤芯属耗材不在保修范围”与拟稿句“滤芯更换属于保修范围”，比较同一字段的取值，观察两者是否互斥。

## 怎么确认配好了

1. 输入假设样本工单原文与拟稿句，比较拟稿句“滤芯更换属于保修范围”与原文“滤芯属耗材不在保修范围”，若同一字段取值互斥，则判定拟稿句未获支持，需退回修改。预期结果为该句不通过，尚未实测。
2. 输入 `AIPROXY_API_ENDPOINT` 填写值与文档说明的根地址格式，比较是否附加 `/v1`，若附加则判定配置错误。预期结果为需修正为根地址，尚未实测。
3. 输入 `AIPROXY_API_TOKEN` 与服务端管理员 Token，比较两者是否一致且非空，若不一致或为空则判定启动校验失败。预期结果为需对齐配置，尚未实测。
