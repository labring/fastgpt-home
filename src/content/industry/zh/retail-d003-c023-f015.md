# 品牌售后维修服务的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

品牌售后维修服务围绕保修责任与线下维修网点展开，日常材料包括保修卡、维修工单、检测报告、换货审批。这些材料决定商品与营销文案能否写“保修”“换新”“免费检测”一类表述。售后系统与门店订单按每单、按日更新，文案起草所依据的检索内容必须与当前工单状态同期。

材料之间常有状态差异：检测报告记录故障现象，换货审批记录审批阶段，维修工单记录处理进度。文案起草只能引用材料已载明的字段，未载明的保修期限、授权范围、生效条件保持未知。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库，输出引用内容为数组，长度可以为 0，没有搜索到内容时输出链路仍走通。搜索模式分为语义检索、全文检索、混合检索；混合检索通过 RRF 融合多路结果，再经 ReRank 二次排序。最低相关度是过滤阈值，仅在语义检索或使用结果重排时生效。引用上限以 token 为单位。

检索相似度不承担权限或实体隔离职责，召回内容是否可用于某条文案仍需人工核对材料原文。跨不同向量模型的库不可共同关联，应先核标识并排除不符合者。

假设演练样本：材料原文为“工单 A 记录送修日期 3 月 2 日，故障现象为无法开机，处理状态为检测中”“保修卡 B 载明整机保修期 12 个月，自购机日起算”“换货审批 C 当前状态为待审核”。待判定拟稿句为“本商品享受整机保修，检测确认后可换新”。原文含主体、对象、状态与有效范围，未载明换新条件与审批结果。

## 配置怎么定

| 配置项 | 本页相关设置 | 核对方式 |
| --- | --- | --- |
| 关联的知识库 | 选择含保修卡、维修工单、检测报告、换货审批且向量模型相同的库 | 核向量模型标识，排除不同模型库 |
| 搜索模式 | 按测试问题比较语义、全文与混合检索，不预设一种模式适合全部资料 | 用编号类与自然语言类问题分别观察 |
| 引用上限 | 本次假设试验起点设为覆盖一份工单与一份保修卡正文所需 token 量，理由为需容纳完整状态字段 | 与仅覆盖单一短句的较小值比较内容完整性 |
| 最低相关度 | 先标注相关与无关样本再调阈值 | 比较过滤前后召回条目 |
| 问题优化 | 用于指代消除与问题扩展 | 比较原问题与优化后问题，核对主体是否被改错 |
| 输出引用内容 | 数组格式，长度可为 0 | 用纸面输入空数组核对下游设计 |

## 容易做错的三处

1. 将相似度得分当作权限或实体过滤。输入为跨门店工单查询，比较召回条目与访问范围，观察是否出现不属于目标范围的记录；相似度不承担该职责。
2. 把待审核换货审批当作已完成换货。输入为审批状态“待审核”，比较拟稿句“可换新”与原文，观察原文是否载明换新条件与审批结果；未载明即未获支持。
3. 将不同向量模型的库共同关联。输入为两个向量模型标识不同的库，比较标识，观察是否被排除；跨模型共同关联不可执行，不推断其运行结果。

## 怎么确认配好了

1. 输入假设样本材料原文与拟稿句“本商品享受整机保修，检测确认后可换新”，比较拟稿句与保修卡 B、换货审批 C 的字段，观察保修期限与换新条件是否在原文载明；未载明则记录证据缺口。
2. 输入纸面空引用数组，比较下游文案环节对空结果的承接设计，观察是否出现无依据表述；空结果链路走通，不声称虚构规则检索必返回空。
3. 输入含编号的查询与自然语言查询，分别比较语义、全文、混合检索的召回条目，观察编号类问题是否命中对应工单字段；不保证首条命中或全部召回。
