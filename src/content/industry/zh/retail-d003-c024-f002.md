# 品牌商场专柜运营的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在品牌商场专柜运营的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。专柜介绍中的试摆状态、活动期间和旧长期经营资料不能混用。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

专柜介绍可拟说明“中庭体验台，仅本场试摆”，活动页“结束后撤场安排待核”，旧稿曾写长期柜位。当前写门店介绍时要保留体验台和本场限制，不能把长历史中的正式专柜搬成本次。试摆没有长期经营或租赁结论，撤场待核也不是永久保留。实际请求应能指出当前活动及空间身份，不因都在同一商场就沿用上一柜位地址、营业范围或安排。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 空间身份 | 体验台试摆 | 不升正式店。 |
| 活动限制 | 仅本场 | 核输入保留。 |
| 旧实体 | 长期柜位 | 与当前对照。 |
| 短稿名词 | 试摆不能省 | 查回复覆盖。 |
| 新增资料 | 需指同一空间 | 不由同商场沿用。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是仅本场限制在输入里缺失，应对完整说明与请求，核是否还带活动身份。第二处是旧长期柜位被沿用到当前体验台，应固定当前材料作空历史对照，查地点及服务名。第三处是短稿省掉试摆而只写门店，应核成稿名词及回复长度，避免叙述升级经营地位。三项分别查条件、历史实体和输出身份，不用更大上下文补未给的长期安排。

## 怎么确认配好了

验收分别问这是什么空间、适用哪场、结束安排是否明确，逐句比实际输入和介绍。引用token预算应让体验台、试摆及本场同时保留，回复上限不能当模型完整窗口。新增长期资料也须核它是否指当前空间，再用同题检查采用，不能因同商场推同柜位。本练习不确定租赁或经营资格，不发布门店信息，也不把自拟活动文字称为真实商场批准。
