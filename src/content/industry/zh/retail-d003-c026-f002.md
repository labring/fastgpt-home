# 品牌直营门店运营的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在品牌直营门店运营的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。直营店换款介绍中，咨询入口、库存条件和已办理结果分别表达。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

直营店介绍可拟服务卡“可咨询换款，能否办理须先核本店库存”，接待摘录“已记录顾客所需颜色”，旧介绍则写另一门店曾办理换款。当前要整理问答，所需颜色只说明咨询内容，不能推出库存存在或已经办理。起草输入应把本店范围和确认可办理前先核库存的条件一起保留；如果只送入可咨询，后续文字就缺解释为什么不能直接承诺的材料。旧店的完成记录也不能补当前门店的结果。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 服务卡 | 确认可办理前先核本店库存 | 核请求保留。 |
| 颜色备注 | 顾客所需 | 不写已可换。 |
| 门店主体 | 当前与历史不同 | 比较空历史。 |
| 结果证据 | 本店未提供 | 保留未核。 |
| 表达空间 | 条件与动作同现 | 分别核回复和窗口。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是库存条件在引用中被截去，应将服务卡原句对到实际请求，查条件是否随动作一起进入。第二处是颜色记录被扩成可换该色，应检查草稿主语与结果，找支持库存的独立材料，缺证保留待核。第三处是旧店办理记录进入当前问答，应固定本店服务卡，比较空历史，核门店身份。三种问题分别查输入完整、动作阶段和历史对象，不能用加长回复替代库存依据。

## 怎么确认配好了

验收用能咨询什么、先核什么、当前是否有办理证据三个问题检查输入与成稿。引用和历史各留哪些文字应分别记录，回复长度只解决表达空间，实际上下文容量另核。若业务后来补本店库存表，先查颜色和对象再改说明。本练习不查真实库存、不办理换款，也不从问答成稿推用户已享受服务，未提供当前结果时只能写咨询及核实步骤。
