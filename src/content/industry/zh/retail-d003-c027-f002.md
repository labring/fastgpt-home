# 品牌经销商订货会的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在品牌经销商订货会的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。订货会邀约可说明样品观看和意向登记，供货确认另须依据。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

经销商订货会可拟两份文字：展台清单说样品可现场观看，登记页收集偏好款式，附注批量供货需另行确认。要求写简短邀请时，当前可写的动作是观看和登记，不能因场景叫订货会就把所有样品写成可直接供货。拟议稿件分成活动安排与待确认事项两栏，只是普通写作组织；需要检查生成请求是否带上附注，栏目名称不能当作业务状态来源。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 展示对象 | 样品 | 核库存结论来源。 |
| 供货附注 | 待另行确认 | 保留阶段。 |
| 登记内容 | 款式偏好 | 不变已订购。 |
| 活动轮次 | 本场邀约 | 隔离旧订单。 |
| 稿件栏目 | 普通表达组织 | 核每栏依据。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是展台样品被写成现货，应回指样品清单的身份词，查稿件是否擅加库存结论。第二处是待确认供货被回复压缩成已确认，应对附注与实际输出逐项核阶段，给条件留表达空间。第三处是登记款式与邀约对象混用，应查请求中的经销商人群和偏好记录，避免把登记动作写成已订购。三者分别核样品性质、供货状态和行为主体，增加上下文不能替代确认材料。

## 怎么确认配好了

验收分别追问现场能做什么、供货是否已确认、登记说明什么，再对实际输入和成稿。若有历史订货记录，应核轮次与款式，不能替本场样品补订单。回复预算与材料引用量分别检查，完整模型窗口按所用能力另核。本练习不发邀请、不收集实际资料或形成订单，稿件允许说明拟定安排，但样品展示和意向收集都不足以证明真实供货承诺。
