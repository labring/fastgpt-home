# 品牌自播直播间运营的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在品牌自播直播间运营的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。直播讲解需让展示部件、清洁条件与未提供说明各有明确位置。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

品牌自播可拟讲解卡：展示架的内衬可取下作陈列调整，清洁办法另见随货说明，本次只提供外观页。旧口播曾说另一款部件可清洗。当前写主播提词时，可介绍取下调整，但不能把拆卸便利写成可水洗。输入若只有内衬可取下，模型没有获得清洁条件，拉长历史反会混入别款方法。应先明确这段讲解要回答展示调整，清洁问题仍缺本款资料。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 动作词 | 取下调整 | 对稿件清洁含义。 |
| 部件身份 | 本款内衬 | 核旧口播对象。 |
| 缺失资料 | 随货清洁页 | 不补操作步骤。 |
| 提词长度 | 限制须表达 | 追踪输入和输出。 |
| 后续补件 | 同款同部件 | 核后再改稿。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是可取下被口播改成可清洗，应对原卡动词与稿件动作，定位增加的清洁含义。第二处是历史别款洗护进入当前，应核款式及部件身份，比较不带旧口播的请求。第三处是短提示只留便利结论而删缺说明，应查生成输入和输出各在哪一步丢掉限制；不能因回复短就用未核步骤补齐。三项核动作语义、历史对象与条件传递，均需看到实际文字。

## 怎么确认配好了

验收让稿件回答什么可调整、清洁依据何在、当前缺哪页，逐句回指请求内材料。引用预算应给条件留位，回复长度不等于完整窗口；模型实际容量需另核。补到随货说明后，还要确认本款内衬再写清洁话术。当前练习不做物理操作或检验，也不证明真实耐洗表现，不用另一款口播替代缺失原页，更不把未检索到说明写成厂家没有说明。
