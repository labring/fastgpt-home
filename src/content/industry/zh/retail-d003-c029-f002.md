# 售后维修与补寄的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在售后维修与补寄的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。补寄说明不能让外壳片的范围扩成整套锁扣维修。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

维修补寄邮件可拟工单摘录“拟补外壳片”，配件页注明“不含锁扣”，沟通便笺只说待核收件地址。当前要写客户说明，材料描述配件范围和一个待核动作，未证明已寄出或整件已修好。起草时需要让不含锁扣与补寄对象一同进入上下文；只剩外壳二字容易被写成外壳组件全套。地址待核也不能被流畅结尾变成已安排送达。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 配件范围 | 不含锁扣 | 核限制送达。 |
| 工单动作 | 拟补 | 不改已寄。 |
| 地址状态 | 待核 | 不编实际信息。 |
| 历史维修 | 整锁另案 | 比较本件归属。 |
| 结果外推 | 未做功能检验 | 不写整件恢复。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是对象限制被引用截断，应核配件页和实际请求，定位不含锁扣是否送达。第二处是拟补被改成已寄，应比较工单阶段与邮件动词，另找真实寄件证据，缺证不补完成状态。第三处是旧维修会话把整锁修复带入本件，应核部件及本件身份，用空历史请求比较。三项分别查范围、阶段和历史归属，不由长回复或大窗口形成维修依据。

## 怎么确认配好了

验收对邮件中的每个名词与动作标来源：寄什么、排除什么、还核什么。引用量、历史量及回复长度分开检查，模型完整窗口按实际能力核。收件地址不在本练习中填真实信息，也不发送邮件。补到寄件材料后可核本件配件及状态再更新；当前只允许说明拟补范围与待核事项，不据外壳片的处理推锁扣可用、整机已恢复或责任已经认定。
