# 售后维修与补寄的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

售后维修与补寄以恢复商品使用为目标，与仅退款争议的结案方式不同。日常文档包括维修申请、补寄单、检测报告、配件出库单，数据来源涉及售后系统、订单系统、维修网点、配件仓WMS。文案起草需要在这些材料范围内核对宣传句是否被支持，例如维修周期、补寄范围、配件来源等表述。材料未载明的字段属于未知，不能由相似品类推断。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务必须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。模型需在管理员-模型提供商页面创建渠道并启用，模型 ID 与渠道中的模型一致。文案起草所需的语言模型能力、工具调用、多模态支持需按应用实际输入逐项核对。检索库要求同向量模型，跨不同向量模型的库不可共同关联。

假设演练样本：某品牌售后网点于 2026 年 3 月 10 日受理一笔补寄申请，材料原文为“客户订单号 A-20260310-017，商品为家用净水器滤芯，故障描述为出水异味，检测报告结论为滤芯到期需更换，补寄单状态为待配件仓出库”。待判定拟稿句为“本品牌承诺 48 小时内完成补寄并送达”。材料载明补寄单状态为待出库，未载明送达时限与承诺主体，拟稿句超出材料范围。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 按部署实际填写服务根地址 | 文档要求不附加 `/v1`；与部署记录比较是否含多余路径 |
| AIPROXY_API_TOKEN | 按服务端一致的非空值 | 文档要求不能为空；与 AI Proxy 管理员配置比较 |
| 模型 ID | 与渠道中模型一致 | 文档说明模型 ID 全局唯一；与渠道模型列表比较 |
| 模型能力 | 按文案起草所需输入核对 | 文档列出多模态、工具调用分别验证；与样本材料类型比较 |
| 模型探测间隔 | 本次假设起点 30 分钟 | 文档支持 5～60 整数；与告警接收能力比较，非官方默认 |
| 告警 Webhook 地址 | 按接收端实际填写 | 文档说明可测试连通性；与接收端日志比较 |

## 容易做错的三处

1. 把材料未载明的送达时限写成品牌承诺。样本中补寄单状态为待配件仓出库，未载明时限与承诺主体，拟稿句“48 小时内完成补寄并送达”缺少材料支持。
2. 用旧 OpenAI 环境变量替代 AI Proxy 配置。文档明确旧变量不能替代 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN，缺少任一项启动校验失败。
3. 把相似度设置当作权限或实体过滤。文档说明检索用于相关文本检索，不承担授权或业务归属判断，不能据此排除未授权记录。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句“本品牌承诺 48 小时内完成补寄并送达”。比较拟稿句中的时限与承诺主体是否出现在材料中。材料仅载明补寄单状态为待配件仓出库，未载明时限与承诺主体，该句未获支持，应记录为待核实。
2. 输入 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 的部署填写值。比较 token 是否为空、endpoint 是否附加 `/v1`。两项均满足文档要求时启动校验通过；任一项不满足时启动校验失败，需按文档修正。
3. 输入样本材料中的商品、故障描述、检测结论与补寄单状态。比较拟稿句是否只使用材料已载明字段。若拟稿句引入材料未载明的配件来源或维修周期，则超出支持范围，应保留证据缺口并标注待核实。
