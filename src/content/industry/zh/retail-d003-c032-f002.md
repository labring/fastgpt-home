# 商超收银与会员促销的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在商超收银与会员促销的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。收银促销示意稿不能将占位券面和空白会员卡当成真实权益。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

收银促销文案可拟两件纸面样稿：券面标注“仅供排版，不作兑付”，会员卡是空白展示卡，活动规则页尚未交付。当前要求写柜台提示，能够说明展示用途，不能从券面标题生成可用优惠或填实际会员信息。若请求只送到券名、卡名，模型没有收到用途限制；把回复压短也可能让示意两字消失。应先核输入对象，再组织当前可说明的内容。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 券面用途 | 排版示意 | 核兑换动作。 |
| 卡面内容 | 空白 | 不补持有人。 |
| 规则页 | 当前缺失 | 追具体条款。 |
| 活动身份 | 本轮 | 后补核版本。 |
| 表达预算 | 用途限制完整 | 核输入和回复。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是排版券被稿件写成可兑换，应查原样稿用途与成稿动作，保留不作兑付原意。第二处是空白卡被历史会员记录补成实际持有人，应核输入来源及人物归属，比较无历史请求，不能编个人资料。第三处是活动规则缺页却生成门槛，应核引用原文和具体条款来源，缺证暂不写规则。三项分别核用途、人物和条款，不靠加大上下文补齐真实促销依据。

## 怎么确认配好了

验收问展示什么、能否据此兑付、规则来自哪里，对照实际请求和输出。材料引用、历史与回复预算应分别检查，模型完整窗口另核。后续补规则时先对活动身份及版本，再决定提示怎么写。本练习不发券、不调用会员系统或处理个人信息，也不启动活动；排版成稿不证明真实权益已生效，当前规则没进入请求也不能据此断言活动没有规则。

| 候选来源 | POS系统、会员CRM、支付平台、价签系统 |
