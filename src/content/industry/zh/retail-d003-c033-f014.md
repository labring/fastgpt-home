# 外汇收结汇与贸易名录的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

本页处理外汇收结汇与贸易名录场景下商品与营销文案起草的模型接入与配置。该场景的日常文档包括收汇水单、贸易合同、发票、外汇业务登记资料，更新频率为每单与每月。文案起草所依据的材料以收汇主体、合同对象、发票金额与登记状态为主，模型接入需要让这些字段在生成与核对时保持可追溯。与信用证审单相比，本场景关注外汇资金和贸易背景真实性，不审全套信用证单据。文案中的宣传句是否被材料支持，属于本页的核对范围；企业身份认证与报告分析不在本页处理。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型能力须按应用所需输入核对：多模态、工具调用与思考配置分别验证。AIPROXY_API_ENDPOINT 填写 AI Proxy 服务根地址，不附加 /v1 或 /chat/completions；AIPROXY_API_TOKEN 填写与服务端一致的非空管理员 Token，不能用应用 API Key 代替。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。语义召回与相关度不负责权限或实体隔离；检索库同向量模型要求不扩展到工商网站或其他外部系统。

假设演练样本（纸面，非真实客户）：材料原文一「收汇水单显示付款方为 A 贸易有限公司，收款方为 B 进出口有限公司，金额 120000 美元，日期 2026 年 3 月 5 日」。材料原文二「贸易合同卖方为 B 进出口有限公司，买方为 A 贸易有限公司，货物为户外折叠椅，数量 2000 件」。材料原文三「外汇业务登记资料载明该笔业务状态为已登记，登记日期 2026 年 3 月 6 日」。待判定拟稿句：「本产品由具备多年出口经验的厂家直供，已通过多项国际认证。」该句中的厂家资质与认证信息在以上三份材料中未载明，属于未获支持。

## 配置怎么定

下表围绕上述样本，列出与本功能、主任务相关的已说明设置或实施核对项。数值为本次假设试验起点，并注明比较对象。

| 配置项 | 本次假设起点 | 核对方式与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 比较该值是否附加 /v1 或 /chat/completions；文档要求不附加 |
| AIPROXY_API_TOKEN | 假设填非空管理员 Token | 比较是否与服务端一致且非空；应用 API Key 不满足 |
| 语言模型与索引模型 | 各启用一个 | 比较系统是否至少各有一个可用；文档说明为最低要求 |
| 模型能力（多模态、工具调用） | 按文案节点所需勾选 | 比较节点实际输入类型与模型能力声明是否匹配 |
| 应用参数（温度、上下文） | 假设温度起点0.3，用于观察文案限定保留情况 | 同一材料下比较较低、较高设置的草稿；仍在应用或节点中配置 |
| 模型探测间隔 | 假设起点 30 分钟 | 比较是否落在文档所述 5～60 分钟整数区间 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 写成完整请求地址并附加 /v1。输入为假设值 `http://aiproxy:3000/v1`，比较对象为文档「不要附加 /v1」的要求，可观察结果为该值与要求不符。
2. 用应用 API Key 充当 AIPROXY_API_TOKEN。输入为假设的应用 API Key，比较对象为文档「管理员 Token，不能用应用 API Key 代替」，可观察结果为两者用途不一致。
3. 依据样本材料直接放行「已通过多项国际认证」的拟稿句。输入为上述三份材料原文，比较对象为该句中的认证信息，可观察结果为材料未载明该信息，判定为未获支持。

## 怎么确认配好了

1. 输入水单与贸易合同，分别把付款方A对到合同买方A、收款方B对到合同卖方B。样本中的交易方角色可对应；这项对应不证明B具备厂家资质或国际认证。
2. 取待判定拟稿句「本产品由具备多年出口经验的厂家直供，已通过多项国际认证」，输入为上述三份材料原文，比较该句的认证表述与材料是否载明，可观察结果为材料无认证字段，判定未获支持；原文缺证据，无法据此否定认证存在。
3. 输入拟稿句中的“厂家直供”与合同、登记资料。原文只说明B为卖方及业务已登记，未给制造主体或直供链路证据，厂家直供主张待核；文案无需为此补入无关登记宣传。

检索检查只记录观察与失败分支：空结果可用明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回空。跨不同向量模型的库不可共同关联，先核标识并排除不符合者。文档流程图中的图片检索、重排属于可选路径，须有相应输入、模型能力与设置启用才执行。
