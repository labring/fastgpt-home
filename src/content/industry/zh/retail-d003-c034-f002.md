# 外贸出口退税申报的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在外贸出口退税申报的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。出口资料补件提示只整理缺项，不由清单替审核决定。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

出口资料服务稿可拟核对单“原件目录缺封面页”，交接便笺“业务方补齐后送核”，另有一份旧案资料完整说明。当前要写补件提示，缺封面描述的是本次材料状态，不能由目录缺项判断实际申报结果，也不能借旧案完整表补成本次齐全。起草上下文要让缺哪页、谁补、补后送核同现；标题里出现申报并不支持已经提交或通过的说法。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 缺项名称 | 封面页 | 追实际请求。 |
| 动作顺序 | 补齐后送核 | 核完成时态。 |
| 补件主体 | 业务方 | 保留责任对象。 |
| 旧案状态 | 另案完整 | 核案别版本。 |
| 真实结果 | 本练习未给 | 不作审核判断。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是补后送核被成稿省成已送核，应对便笺与实际输出，核动作时序。第二处是本次封面缺项在输入裁剪中消失，应对完整清单、引用内容及请求，找缺页信息丢失位置。第三处是旧案完整状态进入本案，应核案别和材料版本，比较去掉历史的请求。三项分别核阶段、输入覆盖和案例归属，回复更长也不能生成本次原件或审核结果。

## 怎么确认配好了

验收提示应明确缺什么、由谁补、后续动作是什么，每句对应当前请求内原文。引用量和回复长度分别记录，模型真实窗口另核；若补来封面应核同案身份再重写。此练习不办理申报、判断退税资格或提供真实程序要求，不用自拟缺项充作官方必需材料。没有送核记录只表示本材料未证，不能据无命中断言真实业务从未送核或必然失败。
