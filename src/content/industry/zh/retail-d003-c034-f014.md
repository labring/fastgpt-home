# 外贸出口退税申报的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

外贸出口退税申报在货物出口后做税务凭证匹配，主要资料包括出口免退税申报表、出口报关单、进货发票和收汇凭证。商品与营销文案起草这一任务，需要从这些资料中提取可核对的商品名称、规格、数量、成交方式与日期范围，再据此起草对外文案。资料按月和每批更新，文案所引用的每一处事实都应有对应凭证字段。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入首先要求 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 均已配置且非空，缺少任一项启动校验失败。模型配置中，模型 ID 是请求体 model 字段的值，全局唯一；模型名仅用于展示。分类与内容提取优先使用toolChoice，其次functionCall；两者均不支持时文档给出提示词模式。模型探测仅覆盖已启用模型，单轮最多尝试 4 次，全部失败才判定异常。检索侧，同一向量模型的库才可共同关联，相关度分数不承担权限或实体隔离职责。

假设演练样本：某外贸企业财务提供的资料原文为“出口报关单载明商品为不锈钢保温杯，规格 500 毫升，数量 2000 只，申报日期 2026 年 3 月 10 日”“进货发票载明同一规格保温杯 2000 只，开票日期 2026 年 3 月 5 日”。待判定拟稿句为“本产品已通过出口退税申报审核，可享受全额退税”。该句所述“已通过审核”在原文中没有对应记录。

## 配置怎么定

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 文档要求填根地址，比较时确认未附加 `/v1` |
| AIPROXY_API_TOKEN | 假设填管理员 Token | 需与服务端一致且非空，比较启动校验是否通过 |
| 语言模型工具能力 | 假设启用 toolChoice | 文案分类与字段提取需要该能力，比较提取是否走工具模式 |
| 模型探测间隔 | 假设设 30 分钟 | 文档支持 5～60 分钟整数，比较探测记录是否按该间隔出现 |
| 向量库标识 | 假设仅一个库 | 比较检索范围是否只落在该库，排除跨库关联 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 写成完整对话地址并附加 `/v1`，与根地址要求不符。检查时比较所填值与文档要求的根地址格式。
2. 用应用 API Key 代替 AIPROXY_API_TOKEN，凭证用途不符，调用结果仍待测试。检查时比较 Token 来源与服务端配置是否一致。
3. 将拟稿句“已通过出口退税申报审核”当作已获支持。检查时比较该句与资料原文，原文只载明报关与开票信息，审核状态未出现。

## 怎么确认配好了

1. 输入假设样本中的报关单与发票原文，以及拟稿句“本产品已通过出口退税申报审核，可享受全额退税”。比较拟稿句中的审核状态与原文是否同主体、同期间、同字段。分别查审核通过证据与“全额退税”的范围或金额依据；当前两项均未载明，分别记未获支持。单有审核记录也不能直接补出全额退税结论。

2. 输入同一批资料中的商品名称、规格、数量字段，比较报关单与进货发票是否一致。两处均为不锈钢保温杯、500 毫升、2000 只，字段一致；若任一处不同，记录为待核实。

3. 输入一条仅含商品名称的检索查询，观察返回结果是否落在同一向量库。若返回空结果，以纸面输入 `[]` 核对下游文案设计，不推断虚构规则必然返回空。跨不同向量模型的库不执行共同关联，只核标识并排除不符合者。
