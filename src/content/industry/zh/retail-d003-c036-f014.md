# 多仓分仓与库存同步的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

多仓分仓与库存同步处在订单路由阶段，决定订单从哪个仓发货。这一环节的主要资料来自 WMS、OMS、ERP 库存与平台库存接口，日常文档包括分仓规则、库存同步表、调拨单与缺货预警。商品与营销文案起草要引用这些资料中的仓、库存与时效表述，资料更新频率为日或小时，文案中的库存与发货口径需要与所引用的资料保持同一时间范围。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入与配置在 FastGPT 中通过 AI Proxy 完成。从 V4.17.0 起 AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 服务都必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。`AIPROXY_API_ENDPOINT` 填 AI Proxy 服务根地址，不附加 `/v1`。模型能力按应用所需输入核对，多模态、工具调用与思考配置分别验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。文案起草只依据所引资料判断具体宣传句是否被支持，不扩展到身份认证或报告分析。

假设演练样本：某供应链计划岗在 2026 年 3 月 10 日整理一份分仓规则摘录，原文为「华东仓可售库存 1200 件，当日 18:00 前付款订单从华东仓发出；华南仓可售库存 300 件，仅承接华南区域订单」。同日拟稿句为「全国订单当日 18:00 前付款均可从华东仓发出，库存充足」。待判定的是该拟稿句是否被上述原文支持。

## 配置怎么定

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写 AI Proxy 根地址 | 按官方说明填写根地址，不附加 `/v1`，与含路径的写法比较 |
| `AIPROXY_API_TOKEN` | 填写非空管理员 Token | 官方要求非空且与服务端一致，与空值或应用 API Key 比较 |
| 语言模型 | 启用一个已测试的语言模型 | 系统至少需要一个语言模型，与未启用状态比较 |
| 索引模型 | 启用一个已测试的索引模型 | 系统至少需要一个索引模型，与未启用状态比较 |
| 模型能力 | 按文案任务所需输入核对 | 多模态与工具调用分别验证，与未核对状态比较 |
| 应用参数 | 在应用或节点配置中设置 | 官方说明参数在应用或节点设置，与假设对话接口同名字段覆盖比较 |

## 容易做错的三处

1. 把 `AIPROXY_API_ENDPOINT` 填成含 `/v1` 的完整请求地址。检查时输入官方根地址写法，比较是否附加路径，观察启动校验是否通过。
2. 用应用 API Key 代替 `AIPROXY_API_TOKEN`。检查时输入非空管理员 Token，比较 Token 类型与一致性，观察启动校验是否通过。
3. 把拟稿句中的「全国订单均可从华东仓发出」当作已被原文支持。检查时输入上述原文与拟稿句，比较主体与范围，观察原文是否载明全国范围与华东仓承接关系。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句，比较原文主体、对象与有效范围，观察拟稿句是否落在原文载明的华东仓与华南仓范围内。原文未载明全国范围，该拟稿句属未获支持。
2. 输入 `AIPROXY_API_ENDPOINT` 的根地址写法与含 `/v1` 的写法，比较是否附加路径，观察启动校验结果。含路径写法与官方说明不符。
3. 输入已启用语言模型与索引模型的配置，比较是否各至少启用一个，观察模型测试是否返回结果。未启用时系统不能正常使用。

纸面核对空结果时，可用明确的 `[]` 作为输入承接下游设计，不声称虚构规则检索一定返回空。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察。
