# 大卖场生鲜联营柜台的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在大卖场生鲜联营柜台的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。生鲜柜台记录稿可说明包装观察，不由外观推食品适用性。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

生鲜联营柜台可拟巡看便笺“外袋表面有水迹”，交接卡“该件暂放待核区，内装情况未看”，另张宣传页描述柜台陈列。当前要写交接提示，观察主体是外袋，未观察的是内装，宣传页不能补成食品状态正常。起草请求需要保留待核位置及观察范围；只送进有水迹可能引出过度解释，只送进待核也会丢失为什么留置的文字线索。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 观察主体 | 外袋表面 | 不改内装属性。 |
| 当前位置 | 暂放待核区 | 核处理时态。 |
| 未观察项 | 内装 | 保留缺证。 |
| 宣传资料 | 柜台概述 | 不代单件记录。 |
| 后补观察 | 同一件 | 核身份再改。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是外袋观察被成稿变成内装结论，应对便笺主体和稿件属性，删掉缺依据的食品判断。第二处是待核区在压缩回复中被写成已处理，应核卡片阶段及实际采用句，找独立处置记录。第三处是柜台宣传混入本件交接，应核对象范围，比较空历史及当前引用，不从一般介绍推单件可用。三项分别查观察主体、处理阶段和资料类型，均不能靠增加字数补实测。

## 怎么确认配好了

验收提示应写清哪里观察到什么、当前放哪里、哪项仍未核，对照实际输入和输出。引用预算须容纳观察限制，回复长度与模型窗口分开核。此练习不检查食品、作食用或法规判断，也不执行处置；需要真实业务责任人按其流程处理。若补内装观察，先核同一件再改记录，当前未见资料不能写成没有异常或必有问题，保持缺证范围明确。
