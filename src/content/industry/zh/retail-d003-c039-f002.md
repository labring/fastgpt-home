# 天猫旗舰店日常运营的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在天猫旗舰店日常运营的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。旗舰店品牌介绍应保留标识展示的授权对象与文案审批范围。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

旗舰店介绍可拟往来文字“允许在本次展示页使用标识”，旁注“正文仍待品牌方审阅”，厂商身份介绍未提供。当前写页面文案，标识使用范围不能扩成整页已批准，也不能由品牌标识推店铺是生产者。起草上下文要把展示页对象和待审正文同送；历史页面曾获审阅的记录属于另一稿，不能因同品牌就当成当前版本的审批依据。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 许可对象 | 本次标识展示 | 不扩全文。 |
| 正文阶段 | 待审阅 | 追旁注送达。 |
| 主体角色 | 未给厂商介绍 | 不由标识推定。 |
| 历史批准 | 另一稿 | 核页别版本。 |
| 实际发布 | 本练习未做 | 与生成分开。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是展示标识许可扩成全文获准，应对往来文字的对象与稿件结论，核是否存在本版正文意见。第二处是待审旁注被输入裁掉，应对原页、引用与实际请求，定位条件丢失位置。第三处是标识出现变成生产者身份，应核实体介绍来源，缺证不补厂商角色。三项分别查许可对象、输入限制和主体身份，不能靠更大的窗口或更长回复取得授权与身份依据。

## 怎么确认配好了

验收分别问允许展示什么、正文当前什么阶段、生产者身份有无材料，对照请求和草稿。引用量、历史量及回复预算分开记，模型完整窗口按实际能力核。若收到品牌意见，先核页别及稿件版本再修文案，不由旧稿延续批准。本练习不判断真实法律效力、不发布页面或联系品牌方，文案生成与实际上线、审批、主体资质分别取证，缺资料不能从店名填空。
