# 天猫旗舰店日常运营的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

天猫旗舰店的商品与营销文案起草，素材来自商品发布页、品牌授权书、发货承诺记录与售后工单。品牌授权书决定哪些品牌词与旗舰店身份表述可以出现在文案中，发货承诺记录决定时效类表述的边界，售后工单反映已出现的表述争议。这些材料按日与每单更新，但模型接入与配置环节关心的是素材进入模型前是否可被正确引用，以及文案输出是否落在材料支持范围内。

## 这些特征在「模型接入与配置」这一环带来什么约束

文案起草要求模型具备语言生成能力，若需读取商品主图或授权书扫描件，还要求模型支持图片输入。系统至少需要一个语言模型和一个索引模型才能正常使用。模型通过 AI Proxy 接入，App 与 Admin 必须配置 AIPROXY_API_ENDPOINT 与非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。模型 ID 全局唯一，模型名可自定义；模型映射可将 FastGPT 请求的模型映射到上游实际模型。模型探测仅针对已启用模型，首次失败后最多重试 3 次，4 次全部失败才判定异常。

假设演练样本：材料原文为“本店为 XX 品牌天猫旗舰店，授权有效期 2026 年 1 月 1 日至 2026 年 12 月 31 日”“页面承诺付款后 48 小时内发货”。待判定拟稿句为“本店为 XX 品牌官方旗舰店，全年无休发货”。核对主体为店铺，对象为品牌授权与发货承诺，有效范围为 2026 年度。该拟稿句中的“官方”与“全年无休”在材料中未载明，属于未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 根地址，不附加 /v1 | 与文档要求一致，比较是否误加路径 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空 Token | 与文档要求一致，比较是否误用应用 API Key |
| 语言模型 | 启用一个支持文本生成的模型 | 与系统最低要求比较 |
| 索引模型 | 启用一个索引模型 | 与系统最低要求比较 |
| 模型映射 | 将起草用模型 ID 映射到上游模型 | 比较映射前后 model 字段 |
| 模型探测 | 开启自动探测，间隔取 5 至 60 分钟整数 | 与文档允许区间比较 |

## 容易做错的三处

1. 将 AIPROXY_API_ENDPOINT 填成完整请求地址并附加 /v1，输入为带路径的地址，比较对象为文档要求的根地址，可观察结果为启动校验是否通过。
2. 用应用 API Key 代替 AIPROXY_API_TOKEN，输入为应用侧密钥，比较对象为 AI Proxy 管理员 Token，可观察结果为调用是否被拒绝。
3. 把拟稿句中的“官方”“全年无休”当作已获材料支持，输入为拟稿句与授权书、发货承诺记录，比较对象为材料原文，可观察结果为该表述是否在原文中出现。

## 怎么确认配好了

1. 输入假设样本中的授权书原文与拟稿句，比较“官方”一词是否出现在授权书原文，若未出现则判定为未获支持。
2. 输入发货承诺记录原文与拟稿句，比较“全年无休”是否出现在记录中，若未出现则判定为未获支持。
3. 输入模型映射配置与请求日志中的 model 字段，比较映射前后取值是否一致，若不一致则记录为待核实，不推断上游行为。
