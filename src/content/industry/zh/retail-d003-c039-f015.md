# 天猫旗舰店日常运营的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

天猫旗舰店的商品与营销文案起草，依赖商品发布页、品牌授权书、发货承诺记录与售后工单四类文档。与京东POP店相比，天猫旗舰店更强调品牌授权、旗舰店身份和天猫积分赔付规则，文案中出现的授权主体、授权范围与承诺口径需要与这些材料对应。资料按日、每单更新，检索环节面对的是同一批材料在不同时间点的版本，起草时须确认所引用的材料属于哪个阶段。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨向量模型的库不可共同关联。搜索模式分为语义检索、全文检索与混合检索，混合检索通过 RRF 融合多路结果，Rerank 对候选文本二次排序。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展。输出引用内容为数组，长度可以为 0。检索结果只承担内容召回，不承担授权核验与身份认证。

假设演练样本：材料原文为「授权方甲，被授权方乙，授权对象为乙在天猫平台经营的家用电器旗舰店，授权有效期自2024年1月1日至2024年12月31日，授权范围限于该店铺内甲品牌商品的销售与展示。」拟稿句为「本店所售甲品牌商品均获品牌方长期授权，可放心购买。」核对时比较拟稿句中的授权期限表述与材料原文载明的起止日期，以及授权对象是否与拟稿店铺一致。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 关联知识库 | 仅关联使用同一向量模型的商品文案库与授权书库 | 比较各库向量模型标识，排除标识不一致者 |
| 搜索模式 | 混合检索 | 与单独语义检索、单独全文检索的结果比较 |
| 引用上限 | 设为覆盖一份授权书完整段落的 token 量 | 与较短上限比较，观察授权期限句是否被截断 |
| 最低相关度 | 先取中间值 | 与更高、更低取值比较，观察无关片段是否减少 |
| 问题优化 | 多轮追问场景开启 | 比较原问题与优化后问题，核对授权主体是否被改错 |
| Rerank | 候选较多时启用 | 与不启用时的排序比较，观察授权句是否靠前 |

以上数值均为本次假设试验起点，不是官方默认值。

## 容易做错的三处

1. 把检索结果当作授权核验。输入拟稿句与召回片段，比较片段是否载明授权主体、对象与有效期；召回片段只说明内容被检索到，不说明授权成立。
2. 跨向量模型关联知识库。输入各库的向量模型标识，比较是否一致；标识不一致的库应排除，不执行跨模型检索。
3. 将待审核状态写成已生效。输入工单或授权书的当前状态字段，比较拟稿句是否宣称已生效；状态为待审核时，拟稿句的生效表述未获支持。

## 怎么确认配好了

1. 输入假设样本中的材料原文与拟稿句，比较拟稿句的授权期限表述与原文载明的起止日期；仅当两者同主体、同字段且取值一致时，该表述获支持，否则记录为未获支持或待核实。
2. 输入各知识库的向量模型标识，比较标识是否一致；仅当标识一致时完成关联，标识不一致的库应排除并记录实际观察。
3. 输入一份明确的空引用数组，核对下游节点是否按空结果继续执行；该核对只验证空结果承接设计，不推断具体检索规则一定返回空数组。
