# 客服咨询知识库维护的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

在客服咨询知识库维护的商品与营销文案起草中，本页说明FastGPT的上下文与 token如何衔接资料。客服知识更新说明须核新旧答案与当前输入实际采用的版本。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

客服知识维护说明可拟旧问答“部件含固定底座”，修订便笺“新资料待核，旧答暂不复用”，新页只给标题且未见正文。当前写客服更新提示，不能从新标题猜底座配置，也不能因旧答文字完整就继续采用。实际请求需要带上暂停复用条件；文件进入资料夹不证明其正文已送到模型。当前能说明的是核新资料及暂缓采用旧答，未核参数不写成已更新完成。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 新页内容 | 仅标题 | 核实际正文。 |
| 旧答版本 | 固定底座句 | 追历史来源。 |
| 修订条件 | 暂不复用 | 核输入与回复。 |
| 产品对象 | 同一部件 | 后补先核身份。 |
| 更新状态 | 当前待核 | 不称已完成。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是新页标题被扩成已确认配置，应查实际引用正文，定位配置依据是否存在。第二处是旧答从历史进入本轮，应固定修订便笺比较空历史，核底座句的版本来源。第三处是暂不复用在短回复中丢掉，应对实际请求与成稿，查条件已送达却未表达还是输入先缺失。三项分别查正文来源、历史版本和限制覆盖，增加回复预算不会生成尚未提供的产品内容。

## 怎么确认配好了

验收问当前可确认哪些参数、旧答能否采用、新页哪里有正文，再核每个采用句。引用、历史和回复上限分别记录，模型完整窗口另核。补到新页后需确认对应部件及版本，重写提示时仍对实际输入，不由上传动作推回答已读。本练习不更新真实客服系统或实测产品，也不承诺知识准确率；缺新正文只能列待核，不能据检索未命中说正式资料不存在。
