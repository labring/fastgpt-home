# 平台促销报名与价格管理的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样
平台促销报名与价格管理围绕活动报名表、促销价审批单、库存锁定表、活动复盘表展开，核心字段是价格、库存与活动节奏。文案起草要引用这些材料中的价格口径、活动起止时间和适用范围，材料未载明的字段保持未知。资料给出周与每场活动的更新频率，本页不据此推出批量同步或实时触发机制。

## 这些特征在「模型接入与配置」这一环带来什么约束
模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败；AIPROXY_API_ENDPOINT 填服务根地址，不附加 `/v1`。系统至少需要一个语言模型和一个索引模型。模型 ID 是请求 Body 中 `model` 字段的值，模型映射把 FastGPT 请求的模型映射到上游实际模型。模型状态探测只针对已启用模型，首次失败后最多重试 3 次，4 次全部失败才判定异常。检索与相关度设置不承担权限或实体隔离职责。

假设演练样本：材料原文为「本次报名活动期间为 3 月 1 日至 3 月 7 日；促销价审批单载明到手价 199 元，适用商品为 A 款保温杯；库存锁定表载明该商品活动库存 500 件。」待判定拟稿句为「A 款保温杯活动期间到手价 199 元，库存 500 件，活动结束后恢复原价。」其中活动结束后的价格状态在材料中未载明。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址 | 官方要求不附加 `/v1`；与文档示例格式比较 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空 Token | 官方要求非空且一致；与应用 API Key 区分 |
| 语言模型 | 启用一个已测试渠道的语言模型 | 官方要求至少一个；与渠道测试结果比较 |
| 索引模型 | 启用一个已测试渠道的索引模型 | 官方要求至少一个；与渠道测试结果比较 |
| 模型映射 | 按渠道填写映射对象 | 官方示例 `gpt-4o-test` 映射到 `gpt-4o`；与上游实际模型名比较 |
| 模型状态探测 | 假设试验起点设为启用，间隔按 5～60 分钟整数填写 | 官方给出该范围；与探测面板状态记录比较 |

## 容易做错的三处
1. 把 AIPROXY_API_ENDPOINT 写成带 `/v1` 的完整请求地址，输入为配置值，比较对象是官方根地址要求，可观察结果是启动校验或调用失败。
2. 用应用 API Key 代替 AIPROXY_API_TOKEN，输入为 Token 字段，比较对象是服务端管理员 Token，可观察结果是认证不通过。
3. 在拟稿句中写入材料未载明的「活动结束后恢复原价」，输入为该句，比较对象是样本原文，可观察结果是该表述未获支持。

## 怎么确认配好了
1. 输入假设样本原文与拟稿句，比较「199 元」「500 件」「3 月 1 日至 3 月 7 日」是否与原文一致，一致时价格与数量表述满足条件；「恢复原价」保持未获支持。
2. 输入渠道配置与模型映射，比较映射前后模型标识，映射对象与上游实际模型名对应时满足条件；不一致时记录实际观察。
3. 输入探测面板记录，比较状态与事件类型，出现 `model_status_error` 或 `model_status_recovered` 时按文档解释；未出现时记录为未观察到，不断言原因。
