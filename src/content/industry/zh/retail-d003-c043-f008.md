# 平台多店铺矩阵管理的商品与营销文案起草：工作流编排

## 这个品类的数据长什么样

在平台多店铺矩阵管理的商品与营销文案起草中，本页说明FastGPT的工作流编排如何衔接资料。多店商品文案分别传单品与套装、自提与快递、图片准用页面，不按同名商品复制承诺。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

本页自拟两店素材：一店商品卡只列单品并要求自提，另一店拟套装且快递条件待确认；同一品牌图只批准用于前一店的指定页面。起草流程收店铺、组成和履约原句，让人员选择核套装组成或核取货表述。商品同名不能合并套装，也不能将自提改成可配送。这里没有真实店名、售价或上线结果，图片可见不自动允许跨店复用。

## 配置怎么定

| 多店文案材料传递 | 自拟差别 | 核查动作 |
| --- | --- | --- |
| 组成 | 单品与拟套装 | 不按同名补配件 |
| 取货 | 自提与待核快递 | 不互换承诺 |
| 素材 | 指定店指定页 | 不扩全店 |
| 写作路径 | 组成或履约 | 核对应店接收 |
| 实际发布 | 权限另核 | 不由交互完成 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

- 单品卡被另一店文案写成完整套装时，对组成清单、店铺身份及实际接收，缺配件资料不得凭图片补齐。

- 自提说明被跨店复制为快递到家时，核取货方式及对应店铺条款，文案流畅不产生配送条件。

- 指定页面准用图片被扩作两店通用素材时，对原授权页面及所用稿件，保留图片用途与发布范围。

## 怎么确认配好了

分别走组成与履约路径，把每项限定传到对应店的写作步骤，保留提交、接收和采用句。补套装配件只更新该店该款，不能顺带确认快递；补素材许可也先核页面，不用同品牌覆盖全部账号。正式发布、素材使用及店铺操作需授权流程与回执，编排不自带跨店商品目录或权限系统，本次仅交接自拟文案依据。

| --- | --- |
| 文档类型 | 店铺授权清单、价格管控表、窜货投诉单、月度销售报表 |
