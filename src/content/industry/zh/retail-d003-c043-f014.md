# 平台多店铺矩阵管理的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

平台多店铺矩阵管理涉及多平台商家后台、ERP渠道价、品牌防伪系统与经销商报表，店铺授权清单、价格管控表、窜货投诉单和月度销售报表构成日常文档主体。商品与营销文案起草的任务，是从这些材料中提取可核对的表述，形成待审文案。跨店授权和价格秩序是核心关注点，文案中的价格描述、渠道范围、授权状态需要与材料一致。资料更新频率为日、月，本页不据此推导批量同步或实时触发机制。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy，环境变量 AIPROXY_API_ENDPOINT 填写服务根地址，不附加 /v1；AIPROXY_API_TOKEN 填写非空管理员 Token，不能以应用 API Key 代替。系统至少需要一个语言模型和一个索引模型。模型 ID 全局唯一，模型映射将 FastGPT 请求的模型映射到上游实际模型。模型状态探测仅针对已启用系统模型，重试最多 3 次，连续 4 次失败判定异常，状态分为正常、高延迟、异常三种。检索相关度不承担权限或实体隔离，跨向量模型的库不可共同关联。

假设演练样本：材料原文为“本店为品牌方授权经销商，授权有效期至2026年12月31日”“该商品建议零售价199元，活动价不低于179元”“窜货投诉单编号CK-2026-0317，涉及店铺A，状态待核实”。待判定拟稿句为“本店为品牌官方授权店铺，全网最低价179元，保证正品”。拟稿句将授权范围从“经销商”扩为“官方授权店铺”，将活动价下限写成全网最低价，正品保证在材料中无对应表述。

## 配置怎么定

下表围绕本页样本列出官方已说明设置或实施核对项。数值列为本次假设试验起点，注明选择理由与比较对象。

| 配置项 | 本次假设起点 | 核对说明 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填写 `http://aiproxy:3000` | 根地址，不附加 /v1；与部署实际服务地址比较 |
| AIPROXY_API_TOKEN | 假设填写非空管理员 Token | 与服务端配置一致；与空值比较确认非空 |
| 语言模型与索引模型 | 假设各启用一个 | 系统至少需一个语言模型和一个索引模型 |
| 模型映射 | 假设将 `gpt-4o-test` 映射到 `gpt-4o` | 核对模型 ID 全局唯一；与上游实际模型名比较 |
| 探测间隔 | 假设设为 30 分钟 | 文档支持 5～60 分钟整数；与允许范围比较 |
| 告警 Webhook 地址 | 假设留空 | 留空时不推送；与配置后行为区分 |

## 容易做错的三处

1. 将材料中“授权经销商”直接写成“官方授权店铺”。输入为材料原文与拟稿句，比较授权主体表述，观察拟稿句是否扩大了授权范围。
2. 将“活动价不低于179元”写成“全网最低价179元”。输入为价格管控表原文与拟稿句，比较价格表述，观察是否将价格下限改写为绝对最低价。
3. 将窜货投诉单“状态待核实”当作已确认违规。输入为投诉单原文与拟稿句，比较状态字段，观察是否将待核实写为已认定事实。

## 怎么确认配好了

1. 核对授权表述。输入材料原文“本店为品牌方授权经销商，授权有效期至2026年12月31日”与拟稿句“本店为品牌官方授权店铺”，比较授权主体与有效期，拟稿句与原文一致才满足条件；不一致时记录差异，不补造授权条款。
2. 核对价格表述。输入价格管控表原文“建议零售价199元，活动价不低于179元”与拟稿句“全网最低价179元”，比较价格描述，拟稿句未超出原文范围才满足条件；超出时保留原文表述，不推断其他店铺价格。
3. 核对投诉状态。输入窜货投诉单“状态待核实”与拟稿句“保证正品”，比较状态字段，拟稿句未将待核实写为已确认才满足条件；状态缺失时记录为未获支持，不判定为否定或冲突。

模型探测结果中，正常为绿色且延迟不超过30秒，高延迟为黄色且延迟超过30秒，异常为红色且连续4次失败；这些状态用于核对模型可用性，不用于判断文案内容是否正确。检索结果为空时，可用纸面输入 [] 核对下游设计，不声称虚构规则检索一定返回空。
