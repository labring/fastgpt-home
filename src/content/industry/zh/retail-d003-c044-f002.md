# 平台广告投放与站内流量的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

平台广告投放按流量和转化实时调价，投放专员每天要处理投放计划、关键词报表、人群包说明和转化归因表。商品与营销文案起草处在这个链条的前端：文案里的卖点、价格表述和活动范围，后续会被投手用于素材和落地页。投放数据按日甚至按小时更新，文案一旦写出与材料不符的承诺，纠正成本会随投放消耗同步放大。本页只处理起草环节的上下文与 token，即模型能看到多少材料、引用多少内容、历史对话带入多少信息。

## 这些特征在「上下文与 token」这一环带来什么约束

上下文与 token 涉及三类彼此独立的边界。第一类是模型单次请求可参考的内容长度，由所选模型的最大上下文决定，回复上限只限制输出长度，两者不能互相替代。第二类是知识库引用上限，按 tokens 控制每次搜索最多引用的内容量，单段材料越长，被裁剪的风险越高。第三类是记忆轮数，决定回答时最多参考前面多少轮对话，轮数越大带入内容越多，消耗和响应时间同步上升。

结构化承接需要单独核对。选择 json_schema 回复格式时，后续节点依赖字段齐全，仅检查文本长度无法发现字段缺失。多模态识别依赖模型能力，弹窗不显示对应选项时，该能力不可用。图片检索需要入库时已建立图片索引，且搜索时具备相应图像输入与模型能力，流程图中列出的路径不代表每次请求全部执行。重排需要具备 ReRank 模型并按设置启用，混合检索经 RRF 融合多路结果，RRF 是融合过程，不作为独立开关配置。

### 假设演练样本

以下内容为本次纸面核对虚构，不指向任何真实客户或平台记录。

材料原文一：「本店春季护肤套装，活动期间下单立减 50 元，活动时间以店铺公告为准。」

材料原文二：「该套装适用肤质为干性至中性，油性肤质建议先做局部测试。」

材料原文三：「赠品数量有限，赠完即止，赠品不与店铺其他满减叠加。」

待判定拟稿句：「春季护肤套装全肤质适用，活动期下单立减 50 元，赠品保证随单发出。」

## 配置怎么定

| 配置或核对项 | 本样本中的设定 | 核对方式与说明 |
| --- | --- | --- |
| AI 模型与最大上下文 | 选择弹窗中标注可处理较长材料的模型 | 材料三句合计较短，重点核对模型是否支持 json_schema 结构化输出 |
| 回复上限 | 本次假设试验起点设为中等长度 | 选此起点是因为拟稿句需完整表达依据与限制，与材料三句总长比较后确认无截断 |
| 知识库引用上限 | 按 tokens 设定，覆盖三句材料 | 比较引用内容是否完整包含活动范围与肤质限制，出现裁剪则调高 |
| 记忆轮数 | 本次假设试验起点设为少量轮数 | 选此起点是因为核对对象为单条拟稿句，与空历史输入比较后确认无额外带入 |
| 回复格式 | 需要下游读取字段时选择 json_schema | 核对字段齐全与解析成功，不能只检查文本长度 |
| 最低相关度 | 仅在语义检索或结果重排时生效 | 该值是过滤阈值，不承担权限或实体隔离功能 |

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。输入是模型选择框中显示的最大上下文数值与回复上限设置，比较两者是否为同一字段，观察结果是二者被分别记录，混用即判定配置理解错误。
2. 用相似度设置排除无关材料。输入是最低相关度取值与检索范围，比较该设置是否被描述为过滤业务归属，观察结果是相关度仅过滤低分内容，不区分材料属于哪个主体。
3. 把 RRF 写成可开启的开关。输入是搜索参数界面中列出的选项，比较是否存在名为 RRF 的独立开关，观察结果是 RRF 仅作为混合检索的融合过程出现，界面无对应开关即判定表述错误。

## 怎么确认配好了

- 验证一：针对材料原文一与拟稿句中的「活动期下单立减 50 元」，输入为两句原文，比较活动时间表述是否一致，观察结果是原文写明以店铺公告为准，拟稿句未载明该限定，判定为未获支持，需补入限定或改写。

- 验证二：针对材料原文二与拟稿句中的「全肤质适用」，输入为两句原文，比较适用肤质字段取值，观察结果是原文限定干性至中性并对油性给出测试建议，拟稿句扩大为全肤质，同一字段出现互斥表述，判定为矛盾。

- 验证三：针对材料原文三与拟稿句中的「赠品保证随单发出」，输入为两句原文，比较赠品状态字段，观察结果是原文写明数量有限、赠完即止，拟稿句改为保证发出，判定为未获支持。若检索返回空结果，可用纸面输入 [] 核对下游节点对空引用的处理设计，不声称任何规则检索必然返回空。跨不同向量模型的库不可共同关联，先核标识并排除不符者，记录实际观察，不推断漏召回或冗余结果。
