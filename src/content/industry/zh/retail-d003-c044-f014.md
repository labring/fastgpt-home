# 平台广告投放与站内流量的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

平台广告投放按流量和转化实时调价，不以平台活动审核为主。主要数据来源为巨量千川、京东快车、阿里妈妈与店铺成交数据，日常文档包括投放计划、关键词报表、人群包说明、转化归因表。数据按日或按小时更新，投放专员与代运营投手需要在文案中引用出价、人群与归因口径，这些口径来自上述文档，模型接入与配置环节要保证拟稿所依据的材料可被检索、可被核对。

## 这些特征在「模型接入与配置」这一环带来什么约束

文案起草依赖知识库检索与语言模型生成。AI Proxy 为必需依赖，App 与 Admin 都必须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项启动校验失败。模型 ID 是请求 Body 中 model 字段的值，全局唯一；模型名为展示名称。系统至少需要一个语言模型和一个索引模型。语义召回与相关度分数不承担权限或实体隔离职责，检索结果不等于授权结果。跨不同向量模型的库不可共同关联，只能核对标识并排除不符合者。

假设演练样本：材料原文三句为「本计划投放对象为华东区夏季防晒霜，出价区间见关键词报表 2026-07-01 至 2026-07-31 日更数据；人群包说明限定为近 30 天加购未支付用户；转化归因表口径为点击后 7 日。」待判定拟稿句为「本商品面向全国所有用户，长期有效。」核对主体、对象、期间与字段：材料限定华东区、近 30 天加购未支付、7 日归因窗口，拟稿句扩大地域与期限，属未获支持。

## 配置怎么定

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | `http://aiproxy:3000` | 与部署模板给出的根地址比较，确认不附加 `/v1` |
| AIPROXY_API_TOKEN | 部署时生成的非空值 | 与服务端配置比较，确认非空且一致 |
| 语言模型 | 启用一个已测试通过的模型 | 在模型提供商页面执行模型测试，观察返回结果 |
| 索引模型 | 启用一个已测试通过的模型 | 同上，确认索引模型可用 |
| 知识库文件 | 上述三份材料原文 | 导入后核对文件是否解析成功 |
| 检索核对 | 以「华东区 防晒霜 出价」为纸面查询 | 观察返回片段是否来自该三份材料，记录实际观察 |

起点选择理由：AIPROXY_API_ENDPOINT 采用文档示例形式，便于与部署模板比较；模型选用已测试通过者为起点，便于与测试结果比较。以上为本次假设试验起点，非官方默认值。

## 容易做错的三处

1. 把拟稿句中的地域与期限直接采信。材料限定华东区与 7 日归因，拟稿句写全国与长期有效，输入为材料原文与拟稿句，比较主体、对象、期间、字段，观察结果为拟稿句超出材料范围。
2. 将相关度分数当作权限过滤。输入为一次检索返回的分数与记录，比较记录所属知识库标识，观察结果为分数不改变记录归属，越权记录仍需另行核对。
3. 把待审核状态当作已获授权。输入为材料中「待审核」字样，比较是否存在批准记录，观察结果为仅有待审核时授权事实未获支持。

## 怎么确认配好了

1. 输入上述三份材料原文与拟稿句，比较拟稿句的地域、人群、归因窗口是否落在材料范围内，观察结果为拟稿句超出范围时判定未获支持。
2. 输入纸面查询「华东区 防晒霜 出价」，比较返回片段来源标识是否属于该三份材料，观察结果为片段来源可核对；若返回为空，按空结果承接下游设计，不推断规则检索必为空。
3. 输入材料中「待审核」字样，比较是否存在签署或批准记录，观察结果为无批准记录时保留证据缺口，不判定为授权完成。
