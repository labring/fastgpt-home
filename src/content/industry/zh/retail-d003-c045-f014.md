# 平台店铺评价与体验分维护的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

平台店铺评价与体验分维护的数据来自抖店体验分、天猫服务指标、京东售后评价与客服系统，日常文档包括差评处理记录、体验分明细、服务诊断报告与整改台账。这些材料以日、周频率更新，记录的是售后履约完成后的消费者反馈与平台服务指标，不直接决定活动价格。商品与营销文案起草需要引用这些材料中的事实，因此文案中的宣传句能否成立，取决于材料是否载明了对应主体、对象与状态。

## 这些特征在「模型接入与配置」这一环带来什么约束

文案起草依赖语言模型完成，模型接入由 AI Proxy 承担。从 V4.17.0 起，AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败，旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。AIPROXY_API_ENDPOINT 填写服务根地址，不附加 `/v1`。系统至少需要一个语言模型和一个索引模型才能正常使用。模型能力按应用所需输入分别核对，多模态、工具调用与思考配置各自验证；应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。

假设演练样本：供核对的差评处理记录原文为“2026 年 3 月 5 日，订单 A 的差评原因为‘发货慢’，客服于 3 月 6 日联系买家补充凭证，买家未回复，3 月 8 日该差评状态为待核实”。拟稿句为“本店所有订单均在 24 小时内发货”。判定该句需要材料载明全部订单的发货时限，现有原文只涉及订单 A 且状态为待核实，未载明发货时限，该句未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填写为 `http://aiproxy:3000` | 文档要求根地址且不附加 `/v1`；与文档示例格式比较，核对是否含多余路径 |
| AIPROXY_API_TOKEN | 假设填写一个非空管理员 Token | 文档要求与服务端一致且不能为空；与 AI Proxy 服务端配置逐字符比较 |
| 语言模型 | 假设启用一个已测试通过的语言模型 | 文案起草需要文本对话；与渠道测试结果比较，确认测试成功 |
| 索引模型 | 假设启用一个已测试通过的索引模型 | 系统至少需要一个索引模型；与模型启用状态比较 |
| 模型能力 | 假设核对是否支持图片输入 | 按应用实际输入核对；与模型配置中 vision 字段比较 |
| 应用参数 | 假设在应用配置中设置温度上限 | 参数在应用或节点配置中设置；与编排内实际取值比较 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 写成带 `/v1` 的完整请求地址。输入为拟填写的地址字符串，比较对象为文档要求的不附加 `/v1`，可观察结果为地址是否含多余路径段。
2. 用应用 API Key 代替 AIPROXY_API_TOKEN。输入为拟填写的 Token 来源，比较对象为文档要求的 AI Proxy 管理员 Token，可观察结果为该 Token 是否与服务端配置一致。
3. 把拟稿句“本店所有订单均在 24 小时内发货”当作已获支持。输入为差评处理记录原文与拟稿句，比较对象为原文载明的主体、对象与状态，可观察结果为原文是否出现“所有订单”与发货时限字段。

## 怎么确认配好了

1. 输入假设填写的 AIPROXY_API_ENDPOINT 字符串，比较其是否以根地址结尾且不含 `/v1`，观察结果为字符串末尾形态。
2. 输入假设填写的 AIPROXY_API_TOKEN 与 AI Proxy 服务端记录，比较两者是否一致且非空，观察结果为逐字符比对是否相同。
3. 输入差评处理记录原文与拟稿句，比较原文是否载明全部订单的发货时限，观察结果为原文是否出现对应字段；未出现时记录为未获支持，保留证据缺口。
