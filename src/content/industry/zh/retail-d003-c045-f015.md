# 平台店铺评价与体验分维护的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

平台店铺评价与体验分维护的文档围绕售后履约后的消费者反馈展开，差评处理记录、体验分明细、服务诊断报告与整改台账构成主要材料。这些材料按日或按周更新。商品与营销文案起草需要从材料里找出可引用的表述依据，例如某条差评的归因结论、某次整改的状态描述、某份诊断报告对服务环节的判定。材料覆盖的主体、对象、状态与有效范围往往分散在不同文档中，检索环节要把候选内容召回后交由人工核对，确认拟稿句是否与材料原文一致。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，需先核对向量模型标识并排除不符合者。搜索模式包含语义检索、全文检索与混合检索，混合检索通过 RRF 融合多路结果，RRF 是融合过程，不是可开启的开关。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值。引用上限以 token 为单位。问题优化用于指代消除和问题扩展，会增加一次模型调用。引用内容以数组输出，长度可以为 0。

假设演练样本：材料原文一为“2025年3月1日至3月31日，某店铺售后评价处理记录显示，订单A的差评归因结论为物流时效，整改状态为已提交补充凭证，待平台审核。”材料原文二为“同期服务诊断报告写明，该店铺客服响应环节未列入本期整改台账。”待判定拟稿句为“本店已完成物流时效问题的全部整改。”

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅关联含上述两份材料的同一向量模型库 | 先核对向量模型标识，排除不同模型的库 |
| 搜索模式 | 混合检索 | 与单独语义检索、单独全文检索比较召回内容 |
| 引用上限 | 假设起点 2000 token | 用长短不同的材料片段测试内容完整性后调整 |
| 最低相关度 | 假设起点 0.3 | 先标注相关与无关样本，再比较过滤效果 |
| 问题优化 | 开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 按设置启用 | 比较重排前后候选顺序，确认模型可用 |

## 容易做错的三处

1. 把最低相关度当作权限或实体过滤。该值仅过滤低相关度结果，不排除无关业务或未授权记录。检查方式：输入上述拟稿句，比较召回内容是否仍包含材料原文一与原文二，观察是否出现与主体无关的记录。
2. 把待审核状态读成已完成整改。材料原文一写明整改状态为已提交补充凭证、待平台审核，拟稿句称已完成全部整改。检查方式：将拟稿句与原文一逐字比较，观察“待平台审核”与“已完成”是否在同一字段上互斥。
3. 把未列入台账读成否定结论。材料原文二只说明客服响应环节未列入本期整改台账，未载明该环节是否存在问题。检查方式：比较拟稿句是否出现该环节的否定表述，观察材料是否提供对应字段。

## 怎么确认配好了

1. 输入拟稿句“本店已完成物流时效问题的全部整改”，比较召回内容与材料原文一的整改状态字段，观察召回结果是否包含“待平台审核”原文。若召回内容不含该字段，记录为未获支持，不判定为矛盾。
2. 输入拟稿句，比较召回内容是否包含材料原文二关于客服响应环节的表述，观察拟稿句是否对该环节作出材料未载明的判断。若材料未提供该字段，记录为待核实。
3. 用纸面输入空数组核对下游设计，观察引用内容长度为 0 时下游链路是否走通。该核对不声称虚构规则检索一定返回空数组，只验证空结果承接。
