# 平台店铺评价与体验分维护的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在平台店铺评价与体验分维护的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。评价与整改资料用于服务文案时，要保留陈述、计划和真实复核的区别，不写评分或效果数。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

评价相关文案可收拟写主题、诊断原句和整改资料范围。自拟输入只有差评陈述和整改安排，没有本次复核或完整体验资料；表单提交后应核接收步骤保留这些缺口，不能从计划推出服务已改善。人员可选择补材料或整理原文，不自动查询评分，也不由一条差评推定全部商品状态。适用店铺与资料期间需随原句传递。

## 配置怎么定

| 文案输入核对 | 本题自拟材料 | 接收与写入依据 |
| --- | --- | --- |
| 店期范围 | 单店单期原句 | 未扩大到全部对象 |
| 整改状态 | 安排有，复核缺 | 未写成已经改善 |
| 陈述性质 | 客户说法与检查分开 | 未直接判商品事实 |
| 补证去向 | 补本次核查或整理原文 | 后续实际收到来源 |
| 正式发布 | 回复审批和更新另办 | 稿件未代替业务结果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

范围丢失：若单店单期说明被成稿扩大，应对照填写与接收恢复对象；计划冒效果：若拟整改写成已改善，应查本次实际复核；陈述冒事实：若客户说法被作商品结论，应另查对应检查依据。三项分别核范围、执行与证据性质，不由字段已填补出。

## 怎么确认配好了

验收保留原问题、资料身份、选择路径和实际接收内容，补本次核查后复问，核文案实际采用新来源。节点记录状态并等待，完成后继续，不自带业务数据库或内容审批。字段核验、对外回复、发布与人员权限需后续流程另核授权及回执；本次起草结束不证明体验已改善、责任已确定或页面已经更新。
