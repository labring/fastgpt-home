# 平台类目资质准入的商品与营销文案起草：多轮对话与提示词

## 这个品类的数据长什么样

在平台类目资质准入的商品与营销文案起草中，本页说明FastGPT的多轮对话与提示词如何衔接资料。资质文案多轮补充时核许可主体、品类与期限，不把受理进度写成准入。所用场景为自拟文字测试。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

假设营业执照提供经营主体，商标授权只覆盖部分品类，行业许可申请便笺写已受理。首轮拟写品牌介绍，后轮要求突出资质时，应核实际进入模型的许可资料，保留受理与获许可的区别。授权品类不能扩大为全部商品，营业执照存在也不证明平台已批准类目准入。此自拟例不含真实证号、有效日期或审查结论，缺失字段应列待核，不由提示词补齐。

## 配置怎么定

| 资质文案逐轮补料 | 假设输入 | 复核动作 |
| --- | --- | --- |
| 主体 | 营业执照文字 | 对拟介绍企业 |
| 品类 | 部分商品授权 | 保留覆盖边界 |
| 许可 | 申请已受理 | 不改成已获证 |
| 日期 | 各字段分别给 | 核事件含义 |
| 准入 | 平台结果未给 | 不补批准结论 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `提示词与任务` | 说明资料、任务和缺证据处理。 |
| `历史记录` | 核实际提交的历史输入。 |
| `问题优化` | 指代消除与问题扩展需复核。 |
| `模型与长度` | 上下文与回复长度分别核对。 |
| `回复格式` | json_schema需给格式并验解析。 |

## 容易做错的三处

- 后轮只见上轮“材料已齐”摘要而未见受理便笺时，核历史选择与摘要出处，不以旧生成句证明获许可。

- 部分品类授权在追问中变成全店通用时，对授权商品范围和拟写对象，保留未覆盖品类。

- 许可到期日被误写为平台受理日时，分别对材料字段含义和原文日期，日期相邻不表示同一事件。

## 怎么确认配好了

按主体资料、品类授权、许可状态分轮加料，固定问题“现在可写哪种资质表述”。保存实际输入以及采用句，并用新会话只传最终材料复测。提示词要求缺证号或日期直接说明未给，模型历史选择按实际配置查。只有取得并核对应平台结果后才能表述准入状态；文案草稿本身不提交申请，也不作合规认证。
