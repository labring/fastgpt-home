# 平台类目资质准入的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在平台类目资质准入的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。企业、商标和商品授权资料支持不同描述，文案不能将文件存在写成全部准入已通过。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

资质相关文案可收证照主体原句、商标资料和授权范围，不给法规或类目规则。自拟输入没有本次平台批准，表单应保留待核项，不从企业身份推出商品认证。人员选择可安排核原文或补适用说明，不自动访问证照系统，也不是审批器。提交后要看起草步骤实际收到哪些范围，不能用素材文件名补出许可或主体关系。

## 配置怎么定

| 文案输入核对 | 本题自拟材料 | 接收与写入依据 |
| --- | --- | --- |
| 主体商品 | 证照与本商品关系 | 未直接互换身份 |
| 授权适用 | 单项期间原句 | 接收未丢范围 |
| 平台阶段 | 提交有，批准缺 | 未写成已准入 |
| 原文来源 | 名称与实际段落分开 | 不由素材名补许可 |
| 正式更新 | 提交审批和发布另办 | 稿件未替代机构决定 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

主体混用：若企业资料被写成另一商品持有人，应核主体和商品对应；授权范围丢失：若单项或限定期间被省掉，应对照提交与接收恢复；提交冒通过：若文案将材料已交写成已准入，应取本次平台回复。三项分别核身份、范围和业务阶段，不因资料齐名认定。

## 怎么确认配好了

验收保留原文、版本、选择去向与成稿出处，补对应授权或平台依据后复问，看新增来源实际进入。节点等待交互后继续，不表示宣传或资质已审核。字段校验、平台提交、资料更新和发布需后续业务另核授权及回执；本次起草不证明法律充分、认证有效或商品已获平台认可。
