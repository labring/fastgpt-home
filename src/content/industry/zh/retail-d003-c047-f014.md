# 平台退款退货处理的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

平台退款退货按订单持续发生，与单场直播承诺无必然关联。日常文档包括退款申请、退货物流单、质检照片、退款审批。起草商品与营销文案时，文案素材来自商品资料与售后记录，模型接入只负责生成文本，不负责判定退货责任或审批退款金额。数据更新频率为每单与日，本页不据此推导批量同步或交易触发机制。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两项。模型 ID 是请求 Body 中 model 字段的值，全局唯一；模型名仅用于展示。起草文案使用语言模型，若需识别质检照片则要求模型具备 vision 能力。模型探测仅针对已启用系统模型，探测间隔为 5 至 60 分钟之间的整数，异常判定为连续 4 次请求均失败。

假设演练样本：某平台售后组留存的纸面材料为「订单 A-2201 的退款申请载明商品为保温杯，退货物流单载明签收日期为 3 月 12 日，质检照片说明载明杯身有划痕」。待判定拟稿句为「该商品经质检确认存在划痕，支持全额退款」。材料未载明质检结论与退款审批结果。

## 配置怎么定

以下设置围绕本页样本的文案起草核对，数值为本次假设试验起点，用于与模型探测面板显示值比较。

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 根地址，不附加 `/v1` | 与部署文档示例结构比较 |
| AIPROXY_API_TOKEN | 填写非空管理员 Token | 与 AI Proxy 服务端配置比较 |
| 语言模型启用状态 | 启用一个语言模型 | 与模型探测页面「已启用」列表比较 |
| vision 能力 | 按是否需识别质检照片决定 | 与模型配置字段 vision 取值比较 |
| 模型探测间隔 | 取 5 至 60 之间的整数 | 与探测配置弹窗允许范围比较 |
| 告警 Webhook 地址 | 可选，填写回调 URL | 点击测试后与推送结果比较 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 写成完整对话接口地址并附加 `/v1`，启动校验失败。检查输入是否为根地址，比较部署文档要求，观察服务是否通过启动校验。
2. 将拟稿句「支持全额退款」当作材料已支持的事实。检查输入为样本材料原文，比较材料是否载明质检结论与退款审批，观察该句是否缺乏依据。
3. 用相似度设置排除无关业务或未授权记录。检查输入为检索配置项，比较是否属于权限或实体过滤，观察是否错误扩大该设置的作用范围。

## 怎么确认配好了

1. 输入假设样本材料三句与拟稿句，比较拟稿句是否超出材料载明的划痕事实，若出现「支持全额退款」则判定为未获支持，需保留待核实。
2. 输入 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN，比较是否均为非空且端点未附加 `/v1`，若任一缺失或格式不符则启动校验失败，属未配置完成。
3. 输入纸面检索结果 `[]`，比较下游文案起草是否按空引用处理，若下游仍输出具体宣传结论则说明空结果承接未按设计执行，需记录观察。
