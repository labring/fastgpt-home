# 平台退款退货处理的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在平台退款退货处理的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。破袋陈述、外袋划痕与退款批准分别说明什么，需要在退货服务文案中保留各自出处。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟退货材料中，申请写“袋口破损”，检查摘录只写“外袋有划痕”，另附照片却标为另一订单。起草输入应保留三段各自来源，不把相近描述合成同一检查结果。表单可让人员提交这些原句，再选择整理检查资料或补退款处理凭据；提交完成只表示输入进入后续步骤，申请人说了什么与检查人员确认了什么仍需分开。

## 配置怎么定

| 退货文案对照 | 自拟材料片段 | 对应起草检查 |
| --- | --- | --- |
| 申请人陈述 | 袋口破损原话 | 未冒充检查人员结论 |
| 检查摘录 | 外袋划痕 | 未据此补出袋口判断 |
| 照片来源 | 标记属另一订单 | 不为本件外观背书 |
| 退款批准 | 有批准，缺执行结果 | 不写成已退回 |
| 人员选项 | 补退款处理凭据 | 核连接分支实际接收 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

陈述冒检查结论：若成稿把“袋口破损”写成检查已确认，应回到本件检查摘录，划痕不足以补出袋口结论；他单图片混入：若照片被用于描述本件外观，应核图片的订单标记与来源，标记不符就不能充当本件依据；批准冒实际退款：若批准文字变成“已退回”，应取本次退款处理记录及其结果，批准本身不能填补执行证据。

## 怎么确认配好了

检查表单实际提交内容是否保留申请和检查的不同说话人，再核接收步骤有没有把照片来源与正文分开。人员选“补退款凭据”时，应沿连接的分支查看下游收到的原文，不能因选择已提交就写成退款完成。补入本件检查结论后再起草，比对变化是否仅落在获证的外观描述；退款结果仍缺时，成稿仍须留待核状态。正式退款操作及库存处理由另接业务流程核实。
