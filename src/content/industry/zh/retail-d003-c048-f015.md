# 快递面单与揽收交接的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样
快递交接发生在包裹离仓节点，核心是承运商扫描责任。该环节的文档以电子面单、交接清单、揽收扫描记录和异常件登记为主，来源为快递系统、WMS发运、承运商账单及GB/T快递服务标准。用于商品与营销文案起草时，检索要回答的是某句宣传语能否被面单字段或交接记录支持，例如时效承诺、揽收状态、异常件处理口径。这些材料的更新频率为每批和每日，本页不据此推出批量同步或实时机制。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，只能核对向量模型标识并排除不符合者，不执行跨模型检索来比较漏召回。检索按语义检索、全文检索或混合检索召回候选内容，混合检索通过RRF融合多路结果，RRF是融合过程，不是开启开关。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不是权限或实体隔离手段，检索本身不构成授权。引用上限以token为单位，输出引用内容为数组，长度可以为0。

假设演练样本：材料原文为“本批电子面单于2025年3月10日交由承运商网点，交接清单共120件，揽收扫描记录显示当日扫描118件，异常件登记记录2件待核实”。待判定拟稿句为“本批包裹已全部揽收”。判定要求同主体、同期间、同一字段：扫描记录为118件，拟稿句称全部，属未获支持，2件异常件待核实也未被覆盖。

## 配置怎么定
下表围绕上述样本，只列官方已说明的设置或实施核对项。数值为本次假设试验起点，说明选取理由及比较对象，不表示官方默认值。

| 配置项 | 本次假设起点 | 选取理由与比较对象 |
| --- | --- | --- |
| 关联的知识库 | 面单与交接资料库 | 核对各库向量模型标识一致，排除不一致者 |
| 搜索模式 | 混合检索 | 与语义检索、全文检索分别比较拟稿句的召回情况 |
| 引用上限 | 假设起点800 token | 与交接清单、扫描记录的实际长度比较，观察内容是否完整 |
| 最低相关度 | 假设起点0.4 | 先标注相关与无关样本，再与该阈值比较过滤效果 |
| 问题优化 | 本次开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 本次开启 | 比较重排前后候选排序，重排得分用于过滤 |

## 容易做错的三处
1. 把“扫描记录118件”当作“全部揽收”。输入为拟稿句与扫描记录，比较件数字段，扫描数小于交接数时结果应为未获支持，不能判为一致。
2. 把最低相关度当作权限过滤。输入为无关业务问题，比较其召回结果与授权范围，相关度分数不排除未授权记录，检索结果不能替代授权判断。
3. 把跨模型库强行共同关联。输入为两个向量模型标识不同的库，比较标识后应排除不符合者，不继续编造漏召回或冗余等运行结果。

## 怎么确认配好了
1. 输入假设样本原文与拟稿句“本批包裹已全部揽收”，比较扫描件数与拟稿表述，出现扫描数小于交接数即满足未获支持判定，并记录2件待核实缺口。
2. 输入一条含精确编号的问题，分别用全文检索与语义检索比较命中情况，观察编号字段能否被全文路径召回，不保证首条命中。
3. 输入明确的纸面空引用数组[]，核对下游设计能否承接长度为0的输出，不声称虚构规则检索必然返回空结果。
