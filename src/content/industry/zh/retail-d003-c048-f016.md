# 快递面单与揽收交接的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在快递面单与揽收交接的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。面单、交接和异常资料支持的阶段不同，文案不提供未取得的揽收或送达保证。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

快递服务文案可收拟写主题、交接原句与扫描资料范围，不写时效数字或服务标准结论。自拟输入只有面单和交接说明，没有本件揽收或处理结果；表单应保留这些缺口，不从资料存在写出确定运输状态。人员选择可安排补扫描或整理原文，不自动查询承运系统；清单覆盖哪个批次也应随输入传给起草。

## 配置怎么定

| 文案输入核对 | 本题自拟材料 | 接收与写入依据 |
| --- | --- | --- |
| 揽收阶段 | 面单与实际扫描分开 | 未从建单推已接 |
| 批次范围 | 清单部分覆盖原句 | 接收未扩大全部 |
| 异常结果 | 登记有，处理依据缺 | 未写成已经解决 |
| 补证路径 | 补扫描或整理材料 | 相应分支实际承接 |
| 正式处理 | 确认关闭和发布另办 | 文案未替代运输结果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

面单冒揽收：若标签生成被写成物流已接，应查本件实际扫描；批次范围丢失：若清单部分记录被扩大到全部，应对照提交与接收恢复；异常冒解决：若登记被写成已处理，应取本次核查或结案来源。三项分别核物流阶段、范围和结果，不以一项选择给出。

## 怎么确认配好了

验收保留包裹批次、来源身份、路径与成稿引用，补本次依据后复问，核文案实际采用新来源。节点等待并继续，不代表外部状态已更新。字段核验、交接确认、异常关闭和发布需后续业务另验权限及回执；本次起草不证明包裹已到、责任已确定或宣传内容已获批准。
