# 批发市场档口交易的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

批发市场档口交易依赖现场议价和托运，进货单、手写销售单、摊位租赁合同、货款收据构成日常材料。这些材料零散、格式不统一，同一批货的品名、数量、价格可能分散在多张纸面。起草商品与营销文案时，模型需要从这些材料中提取可引用的表述，上下文与 token 配置决定材料能否被完整纳入、引用是否被裁剪。

## 这些特征在「上下文与 token」这一环带来什么约束

模型上下文按实际模型能力核对，回复上限不等于完整上下文窗口。知识库引用上限按 token 控制，单段材料较长时可能被裁剪，需要结合问题样本核对引用内容是否完整。历史输入会占用上下文，相同问题在空历史和带历史下输入不同，需分别核对。使用固定回复格式时，字段齐全和解析成功是判断依据，文本长度不能替代。

假设演练样本：材料原文为“档口A于2025年3月1日向采购商B出具手写销售单，载明干辣椒200斤、单价每斤12元、货款合计2400元，备注‘三日内结清’”；“摊位租赁合同显示档口A租期至2025年12月31日，月租金3000元”。待判定拟稿句为“本档口干辣椒现货充足，支持三日内结清货款，长期稳定供货”。判定要点：材料仅载明一笔销售单的品名、数量、单价和结清期限，未载明现货库存状态，未载明长期供货承诺。拟稿句中“现货充足”和“长期稳定供货”未获材料支持，“三日内结清”与销售单备注一致。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 模型上下文 | 按所选模型实际显示值 | 与材料总长度比较，确认销售单和租赁合同能否同时纳入 |
| 回复上限 | 假设设为800 tokens | 与拟稿句加依据说明的长度比较，观察是否被截断 |
| 知识库引用上限 | 假设设为2000 tokens | 与单张销售单文本长度比较，核对引用是否完整 |
| 历史轮数 | 假设设为2轮 | 与空历史输入比较，观察历史是否影响材料引用 |
| 回复格式 | 假设选json_schema | 与字段清单比较，核对品名、数量、价格字段是否齐全 |
| 最低相关度 | 假设设为0.5 | 与语义检索得分比较，观察低分材料是否被过滤 |

以上数值为本次假设试验起点，不是官方默认值。最低相关度仅过滤低相关度结果，不承担权限或实体隔离功能。

## 容易做错的三处

1. 将回复上限当作完整上下文窗口。错误表现：材料总长度超过回复上限时，误认为材料无法纳入。检查：输入销售单和租赁合同全文，比较材料总长度与模型上下文显示值，观察材料是否被完整纳入。
2. 将最低相关度用于排除无关业务。错误表现：认为调高最低相关度可过滤其他档口或采购商记录。检查：输入同一档口材料，比较检索结果与材料主体，观察结果是否仍包含其他主体记录。
3. 将拟稿句中的宣传表述直接视为材料支持。错误表现：材料未载明现货库存，拟稿句写入“现货充足”。检查：输入材料原文和拟稿句，逐句比较表述与材料字段，观察“现货充足”是否有对应记载。

## 怎么确认配好了

1. 输入假设样本中的销售单和租赁合同原文，比较材料总长度与模型上下文显示值。若材料被完整纳入且拟稿句依据可追溯至原文，满足条件；若材料被裁剪，记录裁剪位置。
2. 输入拟稿句“本档口干辣椒现货充足，支持三日内结清货款，长期稳定供货”，比较“现货充足”“长期稳定供货”与材料字段。若材料无对应记载，判定为未获支持；若材料有对应记载，判定为已获支持。“三日内结清”与销售单备注一致，判定为已获支持。
3. 使用明确纸面输入[]核对空结果承接设计，观察下游节点是否按空引用处理。不能声称虚构规则检索一定返回[]。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察，不执行跨模型检索比较漏召回。
