# 批发市场档口交易的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在批发市场档口交易的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。档口、手写单和收据只能支持各自事实，起草要先保留角色与可读内容缺口。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

批发档口文案可收经营介绍原句、商品文字和拟写受众，不写金额或真实凭据。自拟材料只有租赁说明、手写单及收款段落，没有当前库存或完整商品说明。表单收集并传递这些来源，不自动识别手写或确定生产身份。人员选择可安排补可读文字或商品资料，不能从摊位地址推定厂家，也不由收据存在推断现货。

## 配置怎么定

| 文案输入核对 | 本题自拟材料 | 接收与写入依据 |
| --- | --- | --- |
| 经营角色 | 租赁方与生产来源分开 | 未直接写成厂家 |
| 可读内容 | 手写原件及可靠文字 | 不预设自动识别 |
| 供货状态 | 收据与当前库存分开 | 未从支付推现货 |
| 补证去向 | 可读原文或商品说明 | 实际进入后续起草 |
| 正式业务 | 确认账务和发布另办 | 成稿未代替履约 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

角色混用：若租赁主体被写成制造商，应核经营原句和实际商品来源；内容未读：若手写商品不清却给出确定名称，应补可靠可读依据；收款冒库存：若凭据被写成当前可供货，应查对应库存或供货确认。三项分别核身份、内容和状态，不从字段已填补出。

## 怎么确认配好了

验收保留受众、来源身份、选项去向和成稿依据，补相应商品或可读原文后复问，看实际采用的材料。节点记录状态并等待，完成后继续，不自带业务数据库。字段核验、采购确认、账务和发布需后续流程另核授权及回执；本次起草不证明商品已备齐、交易已履行或介绍已经上线。
