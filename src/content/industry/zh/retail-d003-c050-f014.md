# 投诉举报与监管回复的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

投诉举报与监管回复面向平台或监管机关，需要正式证据与整改文字。日常材料是投诉工单、监管询问函、订单证据、整改报告。商品与营销文案起草在此场景下，产出的是对涉诉宣传句的说明或整改口径，判断依据来自工单、询问函与订单证据里的原文。

材料不定期更新，每案不同。这一特征决定接入环节无法靠固定批次推进，只能按案核对。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入需要 AI Proxy。App 与 Admin 都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。AIPROXY_API_TOKEN 是管理员 Token，不能用应用 API Key 代替。

模型能力须按应用所需输入核对。多模态、工具调用分别验证。应用参数在应用或节点配置中设置，不能假设对话接口的同名字段会覆盖编排。

假设演练样本：某店铺收到平台投诉工单，工单载明“消费者主张商品页宣称‘三天见效’，订单号 A-2024-0312，下单日期 2024 年 3 月 12 日”。店铺留存商品页历史版本，页面文字为“本品为普通护肤类商品，建议持续使用”。拟稿句待判定：“该商品页面从未作出效果承诺。”核对对象是工单所引宣传句与留存页面文字是否同主体、同期间、同字段。

## 配置怎么定

配置围绕样本核对，只列与本任务相关的已说明设置或实施核对项。数值为本次假设试验起点，用于与样本材料比较。

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填服务根地址 | 与部署文档示例格式比较，确认无 /v1 |
| AIPROXY_API_TOKEN | 假设填非空管理员 Token | 与服务端配置比较，确认一致且非空 |
| 模型能力 | 假设启用文本输入 | 与拟稿任务所需输入比较 |
| 应用参数 | 假设在节点配置中设置 | 与应用编排比较，确认未被接口字段覆盖 |
| 材料范围 | 假设仅工单与页面留存 | 与工单载明主体、期间比较 |

起点选择理由：样本只涉及文本与页面留存，不需要图像输入。比较对象是工单载明的订单号与日期。

## 容易做错的三处

1. 把拟稿句当成已核实事实。拟稿句“从未作出效果承诺”是待判定文本，工单原文只载明消费者主张，页面留存只载明建议持续使用。输入是拟稿句与两份材料，比较的是同主体、同期间、同字段，观察结果是页面留存未出现效果承诺表述，但工单主张仍待核实。
2. 把渠道测试通过当成文案判定通过。渠道测试只验证模型连通，不验证宣传句是否被材料支持。输入是模型测试结果与拟稿句，比较对象不同，观察结果是两者不可互相替代。
3. 把检索相关度当成权限或实体过滤。相关度不排除无关业务或未授权记录。输入是检索返回与工单主体，比较主体标识，观察结果是主体不符的记录须人工排除。

## 怎么确认配好了

1. 核对拟稿句与工单、页面留存。输入为样本三句原文，比较同主体、同期间、同字段，满足条件是页面留存文字与工单主张指向同一商品与同一期间，且拟稿句表述与留存文字一致。
2. 核对模型接入。输入为 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 的假设填写值，比较部署文档格式要求，满足条件是根地址无 /v1 且 Token 非空并与服务端一致。
3. 核对材料缺口。输入为样本材料清单，比较工单载明字段与留存字段，满足条件是缺口被明确记录为待核实，未补造授权或生效条款。空结果可用纸面输入 [] 核对下游设计，不声称虚构规则检索一定返回空。
