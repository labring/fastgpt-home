# 投诉举报与监管回复的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在投诉举报与监管回复的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。投诉与拟回复用于服务说明时要保留陈述性质，不将草稿写成机构已认可。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

投诉相关服务说明可收问题主题、客户原话和整改资料范围，不给法律回复要求。自拟输入没有本次外部处理意见，表单应将缺证传给起草，不从投诉存在推定事实或责任。人员选择可安排补订单依据或整理原文，不自动裁定争议，也不能由稿件完成推定外部机构认可；原句对应哪个订单和事件，需要随来源保留。

## 配置怎么定

| 文案输入核对 | 本题自拟材料 | 接收与写入依据 |
| --- | --- | --- |
| 陈述性质 | 客户原话与实际核查分开 | 未省来源说明 |
| 回复阶段 | 草案无外部接受 | 另查本次真实意见 |
| 个案范围 | 单订单和全部服务分开 | 未扩成普遍保证 |
| 补证路径 | 订单依据或原文整理 | 实际进入相应起草 |
| 正式提交 | 关闭回复和发布另验 | 文案未代替机构认可 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

陈述性质丢失：若客户话语被写成核验结果，应对照完整输入及实际依据；拟稿冒认可：若回复草案写成机构接受，应查本次真实处理回复；个案扩大：若单订单材料被写成全部服务保证，应核适用对象与范围。三项分别核性质、阶段和覆盖，不因一次选择确定。

## 怎么确认配好了

验收保留主题、原文、选择去向和成稿出处，补本案依据后复问，看新资料是否实际采用。节点记录交互并等待，完成后继续，不自带业务审批或法律判断。字段核验、对外提交、整改关闭和发布需后续流程另验授权及回执；本次起草不证明责任已确认、事情已解决或宣传已获批准。
