# 拼多多低价活动店铺运营的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

拼多多低价活动店铺运营的商品与营销文案起草，材料来源集中在活动报名表、商品成本测算表、售后退款单和平台站内信。这些材料各有字段口径：活动报名表载明活动名称、报名商品、活动价与活动库存；商品成本测算表载明进货价、包装费、快递费与毛利测算；售后退款单载明订单、退款原因与退款金额；平台站内信载明活动规则通知与处罚告知。资料给出的更新频率为日、每场活动，本页不据此推出批量同步或实时机制。

文案起草的上下文由这些材料中的字段构成。活动价、活动库存、退款原因属于不同文档的不同字段，起草一句宣传语时需要指明它依据哪份材料的哪个字段。token 消耗来自把材料片段与拟稿要求一并送入模型，引用上限按 token 控制，单段材料越长，可同时纳入的段数越少。

## 这些特征在「上下文与 token」这一环带来什么约束

模型单次请求可参考的内容长度由实际模型能力决定，回复上限只限制回答长度，不能当作完整上下文窗口。引用上限以 token 为单位，混合知识库中不同片段长度差距大，按 token 控制比按条数稳定。历史轮数越大，带入内容越多，消耗与响应时间随之变化。

假设演练样本：材料原文为「活动报名表-2024年5月场：商品A，活动价9.9元，活动库存500件；商品成本测算表-商品A：进货价6.5元，包装费0.3元，快递费2.2元；售后退款单-订单X：退款原因『收到商品与描述不符』，退款金额9.9元。」待判定拟稿句为「商品A活动价9.9元，库存充足，质量有保障。」判定范围为上述三份材料，判定动作限于比较拟稿句用词与材料字段，不涉及平台审核或发布。

## 配置怎么定

| 配置项 | 本页取值或核对动作 | 依据与比较方式 |
| --- | --- | --- |
| AI 模型 | 选择弹窗中显示支持所需能力的模型 | 模型能力决定可用配置项是否显示 |
| 最大上下文 | 核对所选模型实际标注的数值 | 与材料片段加拟稿要求的总长度比较 |
| 回复上限 | 假设试验起点设为能容纳依据与处理动作的长度 | 该起点为本次假设，非官方默认；与拟稿句字数比较 |
| 引用上限 | 按 token 设定，核对材料片段是否被裁剪 | 与单段材料长度及问题样本比较 |
| 记忆轮数 | 单轮起草可保留少量历史 | 与相同问题在空历史下的输入比较 |
| 回复格式 | 普通文案起草保持默认 | 仅当后续流程需读取固定结构时改用 json_schema |

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。回复上限只限制回答长度，材料片段超出模型最大上下文时仍会被裁剪，需分别核对两个数值。
2. 用相关度分数代替字段核对。最低相关度是过滤阈值，不承担实体或权限隔离，拟稿句是否被材料支持要靠逐字段比较。
3. 把待审核状态写成已获授权。活动报名表载明报名状态为待审核时，该状态不证明已获活动资格，也不证明缺少操作权限。

## 怎么确认配好了

1. 输入上述假设样本的三份材料原文与拟稿句，比较拟稿句中「库存充足」与活动报名表「活动库存500件」是否同主体同期同字段，比较「质量有保障」与三份材料中是否存在质量描述字段。只有材料载明对应字段且取值一致时，该用词才获支持；未载明则记录为未获支持。
2. 输入同一拟稿句，分别在空历史与带一轮历史下送入，比较两次实际送入内容是否一致，观察历史是否改变了引用片段。若两次送入内容不同，记录差异片段，不据此断言某种失败原因。
3. 输入一个纸面空结果承接用例：设定检索返回为空列表，核对下游节点在该输入下的设计行为，观察下游是否按空引用处理。该设定为纸面假设，不表示实际检索一定返回空列表。
