# 拼多多低价活动店铺运营的商品与营销文案起草：工作流编排

## 这个品类的数据长什么样

在拼多多低价活动店铺运营的商品与营销文案起草中，本页说明FastGPT的工作流编排如何衔接资料。平台活动文案应分开报名、审核反馈与商品适用范围，提交材料不证明活动已经上线。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟活动报名写“待审核”，站内消息只确认收到材料，商品说明却被草稿写成全店已参加。流程可收商品范围和消息原句，人员选择补实际反馈或核报名对象。这里不写价格、折扣和活动效果；材料收到只说明接收，不能推出审核通过或活动上线，成本资料存在也不证明商品已获准适用任何承诺。

## 配置怎么定

| 活动文案起草 | 自拟状态 | 核对要求 |
| --- | --- | --- |
| 报名原句 | 待审核 | 非审核通过 |
| 站内消息 | 仅确认收件 | 补实际反馈 |
| 参与范围 | 单品非全店 | 核原表对象 |
| 公开状态 | 没有上线记录 | 不写活动已开 |
| 报告承接 | 缺项传到起草 | 新回复限范围更新 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

收件冒通过：若收到材料被写成审核已过，应取本次真实审核反馈；单品扩全店：若报名对象扩大，应查原表范围与接收文字；报名冒上线：若提交动作变活动已开，应核实际公开状态或发布记录。三项分别核消息性质、覆盖和阶段，不从一次选择推定。

## 怎么确认配好了

验收查看补反馈和核对象路径收到哪一项报名，补审核回复后只更新其明确结论；公开状态仍缺时不能一并写成上线。若回复只是继续补材料，应维持待核。正式报名提交、库存设置和文案发布需要另接业务流程核权限及回执，成稿不证明参与成功，也不提供销售增长或曝光承诺。
