# 拼多多低价活动店铺运营的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

拼多多低价活动店铺文案依据活动报名表、商品成本测算表、售后退款单与平台站内信，资料来自商家后台、ERP库存及物流签收，按日或每场活动更新。价格、库存、活动范围和售后承诺须逐项对应原文，模型不能补入未提供的活动结束后安排。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖AI Proxy。App与复用App/Service配置的Admin服务须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺失会启动校验失败，旧OpenAI变量或单模型地址不能替代。根地址不附加 /v1，系统至少需一个语言模型和一个索引模型。模型ID与展示名分开，映射核FastGPT请求与上游目标；渠道优先级1至100，值更大仅更易优先。调用日志文档保留1小时，可由环境变量配置。

假设演练样本：材料原文为“本场活动报名时间为2026年3月1日至3月3日，活动商品为A款收纳盒，活动价9.9元，活动库存500件，售后退款按平台规则处理。”待判定拟稿句为“本商品活动价9.9元，活动库存500件，活动结束后恢复原价。”原文未载明原价及活动结束后价格安排，拟稿句超出材料支持范围。

## 配置怎么定

下表围绕本页商品与营销文案起草任务，列出与模型接入和文案核对相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填写 `http://aiproxy:3000` | 官方要求填写服务根地址且不附加 /v1，与附加 /v1 的写法比较，核根地址格式；整体启动及调用待测。 |
| AIPROXY_API_TOKEN | 假设填写与服务端一致的非空管理员 Token | 官方要求非空且与服务端一致，与空值或应用 API Key 比较，确认启动校验结果。 |
| 语言模型 | 假设启用一个已测试通过的语言模型 | 官方要求至少一个语言模型，与未启用状态比较，确认文案起草可发起请求。 |
| 索引模型 | 假设启用一个已测试通过的索引模型 | 官方要求至少一个索引模型，与未启用状态比较，确认检索环节可用。 |
| 模型映射 | 假设将 gpt-4o-test 映射为 gpt-4o | 官方示例说明请求模型与上游实际模型可不同，与未配置映射比较，核对上游日志中的 model 字段。 |
| 渠道优先级 | 假设设为 50 | 官方说明范围 1～100 且数值越大越优先，与另一渠道的优先级值比较，记录实际路由，数值更大仅更易优先。 |

## 容易做错的三处

1. 把材料未载明的价格承诺写入文案。假设样本原文只写活动价9.9元和活动库存500件，拟稿句加入“活动结束后恢复原价”。原文未载明原价及活动结束后价格安排，该表述属于未获支持。核对时输入原文与拟稿句，比较拟稿句是否只引用原文已载明字段，若出现原文没有的价格安排即不满足条件。
2. 把 AIPROXY_API_ENDPOINT 填成带 /v1 的完整请求地址。官方要求填写服务根地址，不附加 /v1。核对时输入所填地址，与官方要求比较，若地址末尾带 /v1 或 /chat/completions 即不满足条件。
3. 把模型调用日志当作长期可查记录。官方说明调用日志仅保留 1 小时，环境变量里可配置。核对时输入拟查时间范围，与保留时长比较，若超出保留时长则记录不可查，不能据此判断模型当时是否可用。

## 怎么确认配好了

1. 针对假设样本原文与拟稿句，输入材料原文和待判定拟稿句，比较拟稿句中的价格、库存、活动时间是否均能在原文中找到对应字段。若拟稿句出现原文未载明的价格安排，判定为未获支持；若全部字段可对应，判定为材料支持。预期结果为识别出“活动结束后恢复原价”缺少材料依据，不声称已实测。
2. 针对 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN，输入所填两项配置值，比较端点是否为服务根地址且不附加 /v1、Token 是否非空且与服务端一致。若任一项不符合，记录为配置缺口；若均符合，仅记两项配置条件满足。预期结果为确认两项配置满足官方要求，不声称已实际启动服务。
3. 针对模型映射与渠道优先级，输入 FastGPT 侧请求模型 gpt-4o-test 与映射配置，比较上游请求日志中的 model 字段是否为 gpt-4o；输入两个渠道的优先级值，比较优先级配置并记录实际路由，不保证单次选中顺序。若日志中 model 字段与映射不符，记录为映射未生效；若相符，记录为映射按配置执行。预期结果为核对映射与优先级设置，不声称已实际调用上游模型。
