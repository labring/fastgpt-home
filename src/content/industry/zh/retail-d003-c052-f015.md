# 拼多多低价活动店铺运营的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

拼多多低价活动店铺运营围绕活动资源位、活动库存与退款率波动展开，主要数据来源为拼多多商家后台、活动资源位数据、ERP库存与物流签收数据。日常文档包括活动报名表、商品成本测算表、售后退款单与平台站内信，最耗时的环节是估算活动库存、跟踪异常退款与核对活动价毛利。文案起草需要核对商品成本测算表中的价格与库存口径、活动报名表中的报名条件与活动范围、售后退款单中的退款原因分布，以及平台站内信中的活动规则与时限。这些材料共同决定一条宣传句是否有对应依据。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的库。跨不同向量模型的库不可共同关联，实施时先核对向量模型标识，排除不符合者，记录实际观察结果。搜索模式需按测试问题分别比较语义检索、全文检索与混合检索，不预设一种模式适合全部资料。引用上限以 token 为单位，需用长短不同的实际资料测试内容是否完整，再调整上限。最低相关度仅在语义检索或使用结果重排时生效，先标注相关与无关样本再调阈值。问题优化用于指代消除和问题扩展，需比较原问题与优化后问题，核对主体是否被改错。混合检索通过 RRF 融合多路结果，重排需具备模型并按设置启用，图片检索需有相应图像输入及模型能力，这些路径不构成每次请求全部执行。引用内容以数组输出，长度可以为 0，空结果链路仍走通。

假设演练样本：材料原文为“本场活动报名截止时间为3月12日18时，活动资源位为限时秒杀，报名商品须在3月13日0时至3月15日24时期间保持活动价。”以及“商品成本测算表载明：该商品活动价29.9元，单件成本24.5元，活动期间预计日均出库800件，库存余量5000件。”待判定拟稿句为“本商品活动价29.9元，活动期间全程有货，下单后当日发出。”

## 配置怎么定

| 配置项 | 本页取值或核对方式 | 依据与说明 |
| --- | --- | --- |
| 关联的知识库 | 选择使用相同向量模型的活动报名表、成本测算表、退款单、站内信库 | 节点可关联一个或多个相同向量模型的库 |
| 搜索模式 | 对“活动价是多少”“报名截止时间”分别比较语义、全文与混合检索 | 按测试问题比较，不预设单一模式 |
| 引用上限 | 本次假设试验起点设为2000 tokens，与长短不同的实际资料片段比较完整性 | 单位为 token，需用实际资料测试后调整 |
| 最低相关度 | 先标注相关与无关样本，再设本次假设试验起点0.5 | 仅在语义检索或结果重排时生效 |
| 问题优化 | 对“这个多少钱”比较原问题与优化后问题，核对主体是否被改错 | 用于指代消除和问题扩展 |
| 结果重排 | 具备重排模型并按设置启用，对候选文本二次排序 | 重排后得分为0-1，可按得分过滤 |

## 容易做错的三处

1. 把跨向量模型的库强行共同关联。输入为两个向量模型标识不同的库，比较标识是否一致，若不一致则排除，记录实际观察，不执行跨模型检索来比较漏召回。
2. 把最低相关度当作权限或实体过滤器。输入为相似度阈值设置，比较返回内容是否包含未经授权的记录，相关度分数不承担权限过滤功能，检索本身不构成授权。
3. 把拟稿句中的“全程有货”“当日发出”当作材料已支持。输入为成本测算表中的库存余量与出库预计，比较拟稿句是否出现材料未载明的承诺，未载明内容属于未获支持，需保留证据缺口。

## 怎么确认配好了

1. 输入材料原文“本场活动报名截止时间为3月12日18时”与拟稿句“本商品活动价29.9元，活动期间全程有货，下单后当日发出”，比较拟稿句是否包含材料未载明的供货与发货承诺，若拟稿句出现“全程有货”“当日发出”而材料未载明，则判定为未获支持。
2. 输入拟稿句“本商品活动价29.9元”与成本测算表原文“活动价29.9元”，比较价格数值与商品主体是否一致，若一致则价格句获得材料支持，若主体或数值不一致则待核实。
3. 输入空引用数组[]与下游节点，比较下游是否按数组长度0继续走通，若下游正常承接空结果则链路设计成立，若下游报错则记录实际现象，不推断虚构规则必然返回空数组。
