# 拼多多低价活动店铺运营的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在拼多多低价活动店铺运营的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。活动报名、成本说明和退款资料分别提供有限依据，文案不写商业数值或无来源优势。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

拼多多活动文案可收报名说明、商品资料与站内信原句，不写价格、成本或效果数。自拟输入没有本次平台批准和完整属性依据，表单应保留待补状态。人员选择可安排回原文或补商品来源，不自动完成经营计算；成本表名称不提供可宣传优势，报名提交也不直接说明活动已可执行，资料期间和商品身份需随原文传递。

## 配置怎么定

| 文案输入核对 | 本题自拟材料 | 接收与写入依据 |
| --- | --- | --- |
| 活动阶段 | 报名提交无批准 | 未写成已通过 |
| 内容来源 | 成本与商品性能分开 | 不由表名猜优势 |
| 退款执行 | 请求与实际处理分开 | 补本单记录 |
| 对象传递 | 活动商品和资料期间 | 起草收到同组来源 |
| 正式发布 | 提交处理和更新另办 | 成稿未代替业务生效 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

报名冒获准：若提交被稿件写成已通过，应查本次平台回复；成本冒属性：若成本说明变成产品性能，应核实际商品依据；申请冒完成：若退款请求被写成已处理，应取本订单真实处理记录。三项分别核活动阶段、内容来源和业务执行，不由字段非空补出。

## 怎么确认配好了

验收保留主题、资料性质、选择去向与成稿出处，补本活动或商品依据后复问，看新材料实际进入。节点等待并继续，不表示经营或宣传已核准。字段校验、报名提交、退款操作和发布需后续流程另核授权及真实回执；本次起草不证明活动生效、资金处理完成或商品优势已得到验证。
