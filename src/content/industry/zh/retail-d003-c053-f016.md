# 渠道应收账款催收的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在渠道应收账款催收的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。催告、信用和资金资料用于说明文案时，需要保留主体、条件和真实沟通状态。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

渠道应收说明文案可收合同范围、催告原句和拟写受众，不含金额、期限或真实债务人资料。自拟输入没有银行确认或对方认可，表单应保留缺证，不从通知存在推出已收到。人员选择可安排补原文或核记录，不自动作信用或法律判断；账龄表标题不提供计算口径，具体主体和期间应传给后续起草，不由介绍文字补出。

## 配置怎么定

| 文案输入核对 | 本题自拟材料 | 接收与写入依据 |
| --- | --- | --- |
| 约定范围 | 信用适用主体及原句 | 接收未省掉条件 |
| 沟通结果 | 催告发出无对方认可 | 另取本次回复 |
| 合同对应 | 他交易银行材料混入 | 核关系后移出 |
| 公开受众 | 通用说明无真实债务资料 | 实际传到起草 |
| 正式操作 | 确认发送和发布另办 | 稿件未替代法律判断 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

条件丢失：若信用约定的适用对象被省掉，应对照提交与接收恢复；发送冒认可：若催告已发被写成对方同意，应查本次真实回复；凭据错套：若他合同银行材料进入，应核交易关系后移出。三项分别核范围、沟通结果和身份，不由一次选择认定。

## 怎么确认配好了

验收保留受众、合同、资料性质、路径和成稿引用，补对应原文后复问，看实际采用来源。节点记录并等待，完成后继续，不自动处理资金或冻结发货。字段核验、收款确认、对外发送和发布需后续业务另核授权及回执；本次起草不证明资金已到、责任已确定或处理正当性已成立。
