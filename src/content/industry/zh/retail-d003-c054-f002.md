# 渠道窜货稽查的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

渠道窜货稽查围绕区域与价格秩序展开，不涉及返利金额核算。主要数据来源包括防伪码系统、电商平台价格、经销商发货记录与市场巡检结果。日常文档类型为窜货投诉单、防伪码记录、处罚通知与调查照片。数据更新频率为周及不定期。品牌渠道管控、防伪团队与区域经理是典型从业主体。文案起草环节需要从这些材料中提取可核对的表述依据，上下文与 token 配置直接影响材料片段能否完整进入模型输入。

## 这些特征在「上下文与 token」这一环带来什么约束

材料片段长度差异大：防伪码记录可能只有一行编码，调查照片的描述或投诉单正文可能数百字。引用上限按 token 控制，单段过长时可能被裁剪，导致拟稿句失去主体或状态依据。回复上限与模型上下文是两个不同概念，回复上限控制输出长度，不能替代对输入侧引用范围的核对。历史轮数设置影响多轮追问时前文材料是否仍可参考，数值过大增加消耗，数值过小可能丢失前文已确认的核对结论。

假设演练样本：某品牌渠道管控团队收到一份窜货投诉单，材料原文为“投诉单编号 HYP-2024-0312，投诉对象为华东区域授权经销商 A，投诉内容为在电商平台发现低于建议零售价的同款商品链接，发货记录显示该批货物流向为华南区域。”另有一条待判定拟稿句：“该经销商存在跨区域窜货行为，品牌方已启动处罚程序。”材料仅载明投诉内容与发货流向记录，未载明调查结论或处罚决定。拟稿句中的“存在跨区域窜货行为”与“已启动处罚程序”在材料中未获支持，属于待核实状态。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 引用上限 | 假设设为 2000 tokens | 材料样本约 150 字，2000 tokens 可容纳多个片段；与 500 tokens 比较，观察拟稿句依据是否被裁剪 |
| 回复上限 | 假设设为 800 tokens | 拟稿句加核对说明约需 200 字；与 200 tokens 比较，观察输出是否被截断 |
| 最低相关度 | 假设设为 0.3 | 材料样本语义明确；与 0.7 比较，观察投诉单片段是否被过滤 |
| 搜索模式 | 混合检索 | 防伪码编号需全文匹配，投诉描述需语义匹配；与纯语义检索比较编号召回情况 |
| 问题优化 | 开启 | 多轮追问时指代消除有助于关联前文材料；与关闭比较追问场景的召回差异 |
| 回复格式 | 默认 | 拟稿句为自然语言输出；与 json_schema 比较字段解析需求 |

以上数值为本次假设试验起点，非官方默认值。知识库引用上限以 token 为单位，与 top k 不同。最低相关度仅在语义检索或结果重排时生效。

## 容易做错的三处

1. 将回复上限当作模型上下文窗口。回复上限控制输出长度，模型上下文是单次请求可参考的内容长度，两者字段不同。核对时分别查看模型信息中的最大上下文与回复上限设置。
2. 将相似度得分当作权限或实体过滤。最低相关度是过滤阈值，不排除无关业务或未授权记录。核对时确认检索结果是否包含非目标经销商材料，记录实际观察。
3. 将待审核状态当作已执行处罚。材料中投诉单载明投诉内容，未载明调查结论或处罚决定。拟稿句若写“已启动处罚程序”，与材料状态不符。核对时逐字段比较主体、对象、状态与有效范围。

## 怎么确认配好了

1. 输入假设样本材料原文与拟稿句，比较拟稿句中“存在跨区域窜货行为”与材料中投诉内容及发货流向记录。材料未载明调查结论，该表述属于未获支持。若输出将投诉内容直接表述为已认定窜货，则未通过。
2. 输入假设样本材料原文与拟稿句，比较“已启动处罚程序”与材料中处罚通知字段。材料未包含处罚通知，该表述属于待核实。若输出将投诉单编号当作处罚程序启动依据，则未通过。
3. 输入空历史与带一轮前文追问的同一问题，比较两次检索返回的材料片段。若带历史时投诉单片段被裁剪或丢失，检查引用上限与历史轮数设置。若空历史时返回空结果，记录该观察，不推断虚构规则必然返回空数组。

检索检查记录实际观察与失败分支，不保证首条命中或全部召回。跨不同向量模型的库不可共同关联，先核对标识并排除不符合者。图片检索需有图像输入及模型能力，重排需具备模型且按设置启用。
