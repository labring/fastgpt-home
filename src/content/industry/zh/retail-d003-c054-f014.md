# 渠道窜货稽查的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

窜货稽查围绕区域与价格秩序展开，处理对象是货流方向与售价异常，不涉及返利金额核算。主要材料来自防伪码系统、电商平台价格、经销商发货记录与市场巡检。日常文档包括窜货投诉单、防伪码记录、处罚通知与调查照片，更新节奏为周与不定期。

文案起草环节要处理的是：投诉单描述、防伪码记录中的批次与区域信息、处罚通知中的处理口径、调查照片反映的现场状态。这些材料决定一段拟稿句能否被支持。防伪码记录通常包含码段、查询时间、查询地点；投诉单包含被投诉主体、涉及区域、投诉事由；处罚通知包含认定事实与处理结论。起草时需逐项对照，材料未载明的部分保留为待核实。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入需先完成 AI Proxy 依赖部署。App 与 Admin 均须设置 AIPROXY_API_ENDPOINT 与非空 AIPROXY_API_TOKEN，缺少任一项启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两项。系统至少需要一个语言模型和一个索引模型才能正常使用。语音识别模型仅生效一个，配置一个即可。

模型能力按应用所需输入核对：多模态、工具调用与思考配置分别验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。

以下为假设演练样本，仅用于说明核对方法，不指向任何真实主体。

假设材料原文（窜货投诉单摘录，编号与主体均为虚构）：投诉单 CX-2026-0417 载明，被投诉方为华东区域经销商，涉及货码段区间 A0001 至 A0500，投诉事由为上述码段商品在华南区域电商店铺以低于建议零售价销售；附件含两张店铺页面截图，截图时间为 2026 年 4 月 15 日。该投诉单未载明被投诉方的授权销售区域范围，也未附处罚决定。

待判定拟稿句：「经查，该经销商超出授权区域销售，扰乱价格体系，已按公司规定予以处罚。」

核对结论：投诉单载明码段与低价销售事由，未载明授权区域范围，也未载明处罚已作出。拟稿句中「超出授权区域」与「已予处罚」两项均未获材料支持，应保留为待核实。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址 | 官方要求根地址，不附加 /v1；与部署实际地址逐字符比对 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空 Token | 官方要求不能为空；与 AI Proxy 管理员 Token 比对 |
| 语言模型 | 启用一个已测试通过的语言模型 | 官方要求至少一个；以渠道测试结果为准 |
| 索引模型 | 启用一个已测试通过的语言模型之外的索引模型 | 官方要求至少一个；以渠道测试结果为准 |
| 模型能力核对 | 按文案起草所需输入逐项勾选 | 多模态、工具调用分别验证，不合并判断 |
| 应用参数 | 在应用或节点配置中设定 | 不能假设对话接口同名字段覆盖编排 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 写成含 /v1 的完整请求地址。官方说明要求填写服务根地址，不附加 /v1。检查方式：读取该变量值，与部署实际根地址比对，出现 /v1 或 /chat/completions 后缀即为配置错误。
2. 用应用 API Key 充当 AIPROXY_API_TOKEN。官方说明要求填写与服务端一致的管理员 Token。检查方式：读取该变量值，与 AI Proxy 服务端配置的管理员 Token 比对，不一致或为空即不满足。
3. 将「码段在华南低价销售」直接写成「超出授权区域」。材料未载明授权区域范围，该判断缺少依据。检查方式：在投诉单中查找授权区域字段，未找到时该表述保留为待核实，不写入拟稿句。

## 怎么确认配好了

1. 输入假设材料原文与待判定拟稿句，比较拟稿句中「超出授权区域」是否有投诉单对应字段支持。投诉单载明码段与低价销售事由，未载明授权区域范围，该表述未获支持，应保留为待核实。
2. 输入同一拟稿句中「已按公司规定予以处罚」，比较投诉单是否附有处罚决定。材料未附处罚决定，该表述未获支持。处罚通知属于独立文档，投诉单不能替代。
3. 输入材料原文中「码段区间 A0001 至 A0500」与拟稿句引用，比较码段范围是否一致。若拟稿句将码段写成其他区间，则引用不准确，需按原文修正。

以上核对均针对文案起草任务，不涉及企业身份认证或报告分析。模型探测与渠道测试属于接入配置环节的独立核对，与文案判定分开进行。
