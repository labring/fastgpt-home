# 渠道窜货稽查的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

渠道窜货稽查围绕区域与价格秩序展开，资料主体是窜货投诉单、防伪码记录、处罚通知和调查照片。这些材料进入知识库后，用于支撑商品与营销文案起草时的检索与召回。投诉单通常包含被投诉主体、涉及区域、商品对象和受理状态；防伪码记录关联货码与查询时间；处罚通知记录处理决定与生效状态；调查照片提供现场或商品外观信息。周度与不定期的更新节奏意味着检索结果反映的是入库时的材料状态，文案起草需以已入库且完成训练的数据为限。资料中若只有投诉受理记录，不能据此写出处罚已执行的文案；照片若未生成图片描述或图片向量索引，图片内容无法参与检索。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，需先核对向量模型标识，排除不符合者，不执行跨模型检索来比较漏召回。搜索模式可选语义检索、全文检索或混合检索；混合检索通过 RRF 融合多路结果，RRF 是融合过程，不是可开启的独立开关。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离功能；检索结果不构成对某经销商授权状态的确认。引用上限以 token 为单位，输出引用内容以数组格式呈现，长度可以为 0，空结果链路仍走通。问题优化用于指代消除和问题扩展，会增加一次模型调用。

假设演练样本：材料原文为“投诉单 CX-2024-018 记录某区域门店在售商品外包装喷码与授权渠道发货批次不符，受理状态为待核实”“防伪码记录显示该喷码对应发货批次发往另一区域”“处罚通知尚未签发”。待判定拟稿句为“该门店已被认定窜货并已执行处罚”。判定需同主体、同期间、同一字段：受理状态为待核实，处罚通知未签发，拟稿句所称“已认定并已执行”未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅关联含窜货投诉单与防伪码记录的知识库 | 核对其向量模型标识一致后关联，与含处罚通知的库比较召回差异 |
| 搜索模式 | 混合检索 | 投诉单含编号与自然语言描述，与单独语义检索比较候选覆盖 |
| 引用上限 | 设为覆盖一条投诉单完整字段的 token 量 | 以长短不同的投诉单测试内容完整性，与较小值比较截断现象 |
| 最低相关度 | 先取 0.3 作为假设起点 | 先标注相关与无关样本，与 0.5 比较无关片段数量 |
| 问题优化 | 多轮追问场景开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型时启用 | 比较重排前后候选排序，观察编号类查询是否改善 |

## 容易做错的三处

1. 把待核实状态写成已认定。输入为受理状态“待核实”的投诉单，比较拟稿句“已被认定窜货”，观察起草结果是否引入未获支持的结论。
2. 把未签发处罚通知当作已执行。输入为“处罚通知尚未签发”，比较拟稿句“已执行处罚”，观察是否将未完成动作写成完成事实。
3. 用相似度分数推断授权状态。输入为最低相关度过滤后的引用内容，比较拟稿句对门店授权渠道的表述，观察是否将检索得分当作权限或实体隔离依据。

## 怎么确认配好了

1. 输入假设样本中的三条材料原文与拟稿句，比较拟稿句所称“已认定并已执行”与材料中“待核实”“尚未签发”的字段取值，观察到拟稿句未获支持、证据缺口被记录，方满足条件。
2. 输入含喷码编号的查询，比较混合检索与单独语义检索的候选内容，观察到编号对应记录出现在引用内容中，方满足条件；未出现时记录为待核实。
3. 输入纸面空结果数组，比较下游节点对引用内容长度为 0 的处理，观察到链路继续走通且未虚构检索命中，方满足条件。以上均为纸面核对，未实际执行。
