# 渠道窜货稽查的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在渠道窜货稽查的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。渠道投诉、照片和处理通知只能按各自范围用于文案，不把观察写成已认定违规。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

渠道稽查说明文案可收问题原话、防伪资料说明与照片形成的可读内容，不填真实代码或商业数值。自拟输入没有完整调查结论，表单应保留缺口，不从投诉存在推定实际违规。人员可选择补原文或核对象，不自动识别图片或裁定责任；来源所指渠道、商品与拍摄范围需传给起草，不能由名称相近拼成调查完成。

## 配置怎么定

| 文案输入核对 | 本题自拟材料 | 接收与写入依据 |
| --- | --- | --- |
| 投诉性质 | 原话与调查结果分开 | 未省来源说明 |
| 观察范围 | 单次照片与全部渠道分开 | 未直接扩大全局 |
| 处理阶段 | 通知与实际业务记录 | 未写成已处罚 |
| 可读材料 | 图像形成文字的依据 | 不预设识别已完成 |
| 正式确认 | 发送回写和发布另办 | 成稿未替代调查结论 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

陈述性质丢失：若投诉文字被写成已证实，应核完整来源及实际调查；观察扩大：若单次照片被当全部渠道状态，应查拍摄对象与覆盖；通知冒执行：若拟处理被写成已处罚，应取本次真实业务记录。三项分别核性质、范围和阶段，不用字段已填补出。

## 怎么确认配好了

验收保留主题、来源身份、选项去向和成稿依据，补本案对应资料后复问，核句子实际回指原文。节点等待交互后继续，不自动建立处罚或发布记录。字段核验、调查确认、对外发送和渠道回写需后续流程另核授权及回执；本次起草不证明违规、法律责任或处理已完成，也不把自拟情况当真实客户案例。
