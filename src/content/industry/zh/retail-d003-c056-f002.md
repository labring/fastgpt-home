# 生产企业免抵退税的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

生产企业免抵退税把内销税额抵减和退税合并计算，与外贸企业出口退税的处理路径不同。这一差别直接影响文案起草时可供引用的材料范围：出口合同、出口报关单、免抵退税申报明细表、销售明细账共同构成判断依据，任何一句宣传语若涉及退税金额、退税进度或税收优惠，都需要回到这些材料中核对主体、对象与有效范围。数据按月更新，起草时引用的数值与状态须标明所属期间，跨期数据不能混用。

## 这些特征在「上下文与 token」这一环带来什么约束

起草任务中，模型需要同时容纳材料原文、拟稿句和判定要求。模型上下文按实际模型能力核对，回复上限只是单次回答长度，两者不能互相替代。知识库引用上限按 token 控制，单段材料较长时可能被裁剪，需要结合问题样本确认关键句是否完整进入上下文。历史轮数影响输入内容，同一问题在空历史与带历史下的输入并不相同，核对时应固定其中一种。若采用固定回复格式承接下游流程，字段齐全与解析成功需要单独验证，文本长度不能作为通过依据。

假设演练样本：材料原文为“甲方为生产企业，2024年6月出口自产货物一批，出口报关单编号与销售明细账记录一致，免抵退税申报明细表已由税务会计编制，状态为待申报。”拟稿句为“本企业出口货物已全部完成退税。”判定要求：材料仅显示申报表处于待申报状态，未载明退税完成事实，拟稿句未获支持，应记录证据缺口。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AI 模型 | 选用支持长上下文与思考配置的模型 | 与仅支持短上下文的模型比较，确认材料原文可完整进入 |
| 回复上限 | 设为足以容纳依据与判定结论的长度 | 与截断后的回复比较，确认判定句未被提前截断 |
| 知识库引用上限 | 按 token 设定，覆盖样本材料全文 | 与较小取值比较，确认材料关键句未被裁剪 |
| 记忆轮数 | 设为少量历史轮数 | 与空历史输入比较，确认拟稿句判定不依赖额外前文 |
| 回复格式 | 需要固定字段时选择 json_schema | 与纯文本回复比较，确认字段可被下游解析 |
| 思考强度 | 选择标准思考 | 与不思考比较，确认判定过程覆盖材料状态核对 |

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。输入为一份超过回复上限的材料原文，比较材料关键句是否进入请求，观察结果为关键句缺失时说明二者被混用。
2. 用相似度得分代替材料状态核对。输入为拟稿句与材料原文，比较拟稿句所述退税状态与材料载明的待申报状态，观察结果为两者不一致时说明判定未回到原文。
3. 在空历史与带历史之间直接比较输出。输入为同一问题在两种历史设置下的请求内容，比较两次输入是否一致，观察结果为输入不同时说明比较前提未固定。

## 怎么确认配好了

1. 输入假设样本的材料原文与拟稿句，比较拟稿句所述“已全部完成退税”与材料载明的“待申报”状态，观察结果为判定输出未获支持并记录缺口时满足条件。
2. 输入同一问题在空历史与带少量历史下的两次请求，比较两次输入内容，观察结果为输入一致或差异被明确记录时满足条件。
3. 输入纸面空结果 `[]` 与下游承接设计，比较下游是否对空结果有明确处理路径，观察结果为下游未把空结果当作命中内容时满足条件。
