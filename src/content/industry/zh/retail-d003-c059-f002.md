# 生鲜冷链到店验收的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

生鲜冷链到店验收环节的核心材料包括冷链温度记录、到货验收单、拒收单和供应商送货单。这些材料由冷链车温控、WMS、门店收货系统和质检照片产生，更新频率为每批和每日。商品与营销文案起草任务需要从这些材料中提取可核对的依据，例如某批次是否在温控范围内到店、验收结论是接收还是拒收、拒收原因是否载明。文案中涉及商品品质、到货状态或处理动作的表述，必须能在上述材料中找到对应字段。材料未载明的信息，文案不得自行补全。

## 这些特征在「上下文与 token」这一环带来什么约束

上下文窗口按实际模型能力核对，回复上限是输出侧限制，两者不能混同。知识库引用上限以 token 为单位，单段材料较长时可能被裁剪，需要结合问题样本核对引用内容是否完整。历史轮数影响输入内容，相同问题在空历史和带历史下可能产生不同引用结果。使用固定回复格式时，需验证字段齐全和解析成功，不能仅检查文本长度。检索环节的相似度得分用于排序和过滤，不承担权限或实体隔离功能；不同向量模型构建的库不能共同关联，需要先核对标识并排除不符合者。

## 配置怎么定

以下配置围绕商品与营销文案起草任务，结合假设演练样本说明。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AI 模型 | 选择支持所需上下文长度的模型 | 按材料总 token 量与模型最大上下文比较，确认引用内容不被截断 |
| 回复上限 | 设为足以容纳依据引述与处理动作的长度 | 与拟稿句所需字数比较，过短会截断依据表述 |
| 引用上限 | 按单段材料 token 量设定 | 与最长材料段比较，确保关键字段完整进入引用 |
| 记忆轮数 | 保留少量历史轮数 | 比较相同问题在空历史与带历史下的引用差异 |
| 回复格式 | 默认文本 | 仅当后续流程需要固定结构时改用 json_schema |
| 最低相关度 | 按语义检索或重排时生效 | 与检索结果得分分布比较，过滤低相关片段 |

假设演练样本：材料原文为“2025年3月10日，冷链车温控记录显示到店温度为2℃，到货验收单载明该批次共50箱，验收结论为接收。”待判定拟稿句为“本批次全程冷链到店，品质新鲜。”核对该拟稿句时，材料仅载明到店温度与验收结论，未载明“全程”温度记录和“品质新鲜”的判定依据，该拟稿句超出材料支持范围。

## 容易做错的三处

1. 将回复上限当作完整上下文窗口。回复上限控制输出长度，上下文窗口由模型能力决定，两者混同会导致引用材料被误判为已完整载入。检查时输入一段超过回复上限的材料，比较输出是否截断，观察截断位置是否落在依据字段之前。

2. 将相似度得分当作权限或实体过滤。相似度仅用于排序和过滤，不排除无关业务或未授权记录。检查时输入包含不同批次标识的查询，比较返回结果是否仍包含其他批次内容，观察是否出现跨批次引用。

3. 将待审核状态当作已批准。材料中验收结论为待审核时，拟稿句不得表述为已接收。检查时输入验收结论为待审核的材料，比较拟稿句是否包含接收类表述，观察拟稿句是否与材料状态一致。

## 怎么确认配好了

1. 输入假设样本中的材料原文和拟稿句，比较拟稿句中的“全程冷链”和“品质新鲜”是否能在材料中找到对应字段，材料未载明时拟稿句应标注为待核实。

2. 输入空历史下的同一问题，比较带历史与空历史两种条件下的引用内容差异，观察引用内容是否因历史轮数变化而改变。

3. 输入一段超过引用上限的长材料，比较引用内容是否包含验收结论和拒收原因等关键字段，观察关键字段是否被裁剪。
