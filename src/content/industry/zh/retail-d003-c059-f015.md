# 生鲜冷链到店验收的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

冷链到店验收环节的资料围绕批次展开。冷链温度记录、到货验收单、拒收单、供应商送货单分别记录运输温控、到货状态、拒收原因和送货明细。这些材料每批、每日产生，同一批次的温度记录与验收单需要在检索时被同时召回，文案起草才能引用到完整依据。质检照片可能随批次入库，是否参与检索取决于入库时是否建立图片索引以及模型能力。

## 这些特征在「知识库检索与召回」这一环带来什么约束

文案起草需要核对到货状态、温度区间、拒收原因等字段。若资料分散在不同知识库，且向量模型不一致，知识库搜索节点无法共同关联，需先核对向量模型标识并排除不符合的库。语义检索依赖向量距离，全文检索适合批次编号、温度数值等精确字段，混合检索通过 RRF 融合多路结果。最低相关度仅在语义检索或结果重排时生效，属于过滤阈值。问题优化用于指代消除和问题扩展，会增加一次模型调用。引用上限以 token 为单位控制引用内容长度，输出引用内容长度可以为 0，空结果链路仍走通。

假设演练样本：某批次到货验收单原文为“批次 A-2401，到货温度 2.8℃，验收结论：合格，准予入库”；同日冷链温度记录原文为“批次 A-2401，全程温度 1.5℃ 至 3.2℃，无断链”。一条待判定拟稿句为“本批次全程温控稳定，验收合格”。判定需同批次、同字段比对：验收单结论字段为“合格”，温度记录未载明“稳定”这一评价字段，该拟稿句的“温控稳定”未获材料支持，“验收合格”与验收单一致。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 选取向量模型标识一致的冷链温度记录库与到货验收单库 | 先核标识，排除模型不一致的库，不执行跨模型共同关联 |
| 搜索模式 | 混合检索 | 批次编号与温度数值需全文命中，自然语言问法需语义召回，比较两路结果 |
| 引用上限 | 假设起点 2000 tokens | 以长短不同的验收单与温度记录测试引用内容是否完整，再调整 |
| 最低相关度 | 假设起点 0.5 | 先标注相关与无关样本，观察过滤后引用内容变化 |
| 问题优化 | 开启 | 多轮追问中比较原问题与优化后问题，核对批次主体是否被改错 |
| 结果重排 | 按设置启用 | 候选结果较多时比较重排得分与向量得分排序差异 |

## 容易做错的三处

1. 将验收单的“合格”结论与温度记录的“无断链”描述合并推断为“温控稳定”。输入为两份原文，比较字段是否同主体同期同字段，观察拟稿句是否出现原文未载明的评价词。该拟稿句的“温控稳定”属于未获支持。
2. 把最低相关度当作权限或实体过滤。输入为相似度阈值设置，比较返回引用是否按批次或供应商隔离，观察是否出现无关批次内容。相似度分数不承担授权过滤功能。
3. 将不同向量模型的知识库共同关联。输入为多个库的向量模型标识，比较标识是否一致，观察节点是否允许关联。标识不一致的库应排除，不推断关联后的运行结果。

## 怎么确认配好了

1. 输入假设样本中的两份原文和拟稿句，比较“验收合格”与验收单结论字段、“温控稳定”与温度记录字段，观察拟稿句是否仅保留材料支持的表述。满足条件为“验收合格”可引用，“温控稳定”标注为未获支持。
2. 输入批次编号“A-2401”作为检索词，比较全文检索与语义检索返回的引用内容，观察是否召回该批次温度记录与验收单。满足条件为两路结果均包含该批次材料，不保证首条命中。
3. 输入一个明确的纸面空结果场景，即检索返回引用内容为长度 0 的数组，比较下游文案起草环节是否仍能走通并提示无引用依据。满足条件为下游链路不因空引用中断，不声称虚构规则检索必然返回空数组。
