# 生鲜水果门店采购的商品与营销文案起草：工作流编排

## 这个品类的数据长什么样

在生鲜水果门店采购的商品与营销文案起草中，本页说明FastGPT的工作流编排如何衔接资料。水果礼赠介绍应保留可选配件、试吃对象与文案状态，流程不能把单一样品材料扩成全部供货承诺。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟商品说明只有水果，礼袋可另选，试吃便签只描述送来的样品，陈列稿还待审核。起草流程可收这些原句与批次范围，人员选择补组合确认或核试吃出处。礼袋可选不说明随单附送，样品感受不证明每批表现；提交后应核起草步骤仍收到这些限定，不能因资料都属同款水果就并成已批准的商品介绍。

## 配置怎么定

| 水果介绍起草 | 自拟材料性质 | 下游核对 |
| --- | --- | --- |
| 礼袋配件 | 可以另选 | 不作每单附送 |
| 试吃便签 | 仅送来样品 | 不扩全部批次 |
| 陈列文案 | 仍待审核 | 非正式可发 |
| 输入限定 | 组成与对象同行 | 核实际接收 |
| 业务执行 | 采购配装发布另办 | 输出非品质保证 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

选配冒随附：若礼袋被写成每单包含，应查组合原句与实际传入；样品扩全部：若试吃评价用于所有供货，应核观察对象和批次关系；待审冒可发：若陈列稿变已批准介绍，应取真实审阅依据。三项分别核组成、观察范围和发布阶段，不由流程结束补证。

## 怎么确认配好了

验收沿补组合与核出处路径查看实际接收，补本批对应后只改所支持的描述，未核礼袋或审阅仍留待办。若只新增商品标题，不应改变组成判断。正式采购、配装与公开发布需另接业务步骤核权限及回执，节点继续不证明已经装袋或客户收到，也不从样品文字生成品质保证。
