# 生鲜水果门店采购的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样
生鲜水果门店采购围绕采购单、验收单、农残检测报告与损耗记录展开，数据来源包括批发市场行情、供应商报价、门店销售和检测报告，更新频率为日或每批。商品与营销文案起草需要引用这些材料中的等级、产地、检测结论与批次信息。行业事实中，水果采购依赖批发市场行情与等级验收，验收等级与损耗控制耗时较多，文案若引用检测或等级结论，须与对应单据的批次和状态一致。

## 这些特征在「模型接入与配置」这一环带来什么约束
模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务必须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两项配置。模型能力按应用所需输入核对，多模态、工具调用与思考配置分别验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。

假设演练样本：某门店生鲜主管提交一份验收单摘录，原文为“2026年3月12日，批次A-0312，红富士苹果，等级一级，农残检测报告编号JC-0312，检测结论合格，验收数量200公斤”。同日拟稿句为“本批次红富士苹果已通过农残检测，等级一级，欢迎选购”。判定范围为该批次与当日验收记录。

## 配置怎么定
下表围绕本页样本列出与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，用于与文档说明的范围或字段要求比较，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 核对依据 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不附加 `/v1` | 文档要求根地址，缺少则启动校验失败 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空管理员 Token | 文档要求非空且一致 |
| 语言模型与索引模型 | 各启用至少一个 | 文档说明系统至少需要一个语言模型和一个索引模型 |
| 模型能力 vision | 按文案是否含图片输入核对 | 文档说明多模态模型支持图片识别 |
| 模型状态探测 | 开启后按配置间隔调度 | 文档说明探测仅针对已启用系统模型，间隔为 5～60 分钟整数 |
| 模型调用日志保留 | 按 LLM_REQUEST_TRACKING_RETENTION_HOURS 核对 | 文档说明该变量控制保留时长 |

## 容易做错的三处
1. 把拟稿句“已通过农残检测”当作对全部批次的通用结论。输入为样本原文与拟稿句，比较对象为批次A-0312与检测报告编号JC-0312，若拟稿句未限定批次或检测报告编号，则超出材料支持范围。
2. 用 AIPROXY_API_TOKEN 之外的应用 API Key 代替管理员 Token。输入为实际填写的 Token 值，比较对象为服务端配置，若两者不一致或为空，启动校验会失败。
3. 将模型状态探测的“异常”直接当作文案业务结论。输入为探测返回的 event 与 status，比较对象为拟稿句内容，探测结果只反映模型可用性，不构成对检测结论或等级的判定。

## 怎么确认配好了
1. 输入样本原文与拟稿句，比较拟稿句是否限定批次A-0312与检测报告编号JC-0312。若拟稿句出现“全部批次”或未标明批次，则不满足支持条件。
2. 输入实际填写的 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN，比较端点是否为根地址、Token 是否非空且与服务端一致。若端点附加了 `/v1` 或 Token 为空，则不满足配置条件。
3. 输入模型探测配置中的探测间隔，比较其是否为 5～60 分钟之间的整数。若不在该范围，则不满足文档说明的配置条件。以上均为纸面核对，未实际执行探测或启动校验。
