# 生鲜称重分拣的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

生鲜称重分拣发生在仓内履约环节，核心数据围绕重量与规格展开。分拣任务单记录待分拣的订单与商品规格，电子秤产生实际称重值，称重标签承载规格与重量信息，少称补偿单记录重量差异的处理，质检记录保存品控结果。这些文档的更新频率为每单与每日，属于逐单生成、按日汇总的节奏。商品与营销文案起草需要引用这些材料中的具体数值和状态，例如某批次商品的规格范围、称重结果、质检结论。文案中的宣传句能否成立，取决于对应材料是否载明了支持该句的主体、对象、状态与有效范围。

## 这些特征在「上下文与 token」这一环带来什么约束

起草文案时，模型可参考的内容长度受模型最大上下文限制，回复长度由回复上限单独控制，两者不能混同。知识库引用上限按 tokens 计算，单段材料较长时可能被裁剪，需要结合具体问题样本核对引用内容是否完整。历史轮数决定模型能参考多少轮先前对话，相同问题在空历史与带历史条件下输入不同，结果可能不同。若采用固定回复格式，需要验证字段齐全且可解析，不能仅检查文本长度。语义检索与最低相关度只影响召回内容的相似度排序与过滤，不承担权限隔离或业务实体过滤功能。检索库与向量模型的关联关系限于同一模型标识，不能跨不同向量模型共同关联。RRF 是混合检索结果的融合过程，不是可开启的独立开关。思考预算是模型推理阶段的 token 预算，与知识库引用 tokens 上限属于不同配置项。

## 配置怎么定

以下配置项围绕本页的商品与营销文案起草任务，结合假设演练样本说明。

| 配置项 | 本次假设试验起点 | 选择理由与比较方式 |
| --- | --- | --- |
| 最大上下文 | 按所选模型实际能力核对 | 将材料原文与拟稿句合并估算长度，与模型显示的上下文数值比较，确认未被截断 |
| 回复上限 | 开启并设为可容纳依据与处理动作的长度 | 比较拟稿句、材料引用与处理说明的总长度，确认回复未被提前截断 |
| 知识库引用上限 | 按 tokens 设定，覆盖单段材料长度 | 用样本材料原文的 token 量核对，确认引用内容未被裁剪 |
| 记忆轮数 | 先设为较少轮数 | 比较相同问题在空历史与带历史下的输入差异，排除历史带入的无关内容 |
| 最低相关度 | 保持默认或按样本调整 | 仅在语义检索或结果重排时生效，观察召回内容是否包含样本材料 |
| 回复格式 | 普通文本或按需选择 json_schema | 若下游需读取固定字段，选择 json_schema 并验证字段齐全与解析成功 |

## 容易做错的三处

1. 将回复上限当作模型完整上下文窗口。回复上限只控制单次回答长度，模型可参考的内容总长度由最大上下文决定。核对时比较材料原文与拟稿句的合计长度是否超过模型显示的上下文数值，若超过则输入被截断，需缩减材料或更换模型。

2. 将最低相关度当作权限或实体过滤。最低相关度是相似度过滤阈值，仅在语义检索或结果重排时生效，不排除无关业务或未授权记录。核对时观察召回结果是否包含样本材料之外的无关内容，若包含，说明该设置未起到业务过滤作用，需另行设计权限控制。

3. 将 RRF 当作可开启的独立开关。RRF 是混合检索中多路结果的融合过程，不是配置项。核对时确认搜索模式是否为混合检索，观察多路召回结果是否被合并，若仅使用单一检索路径，则不存在 RRF 融合。

## 怎么确认配好了

假设演练样本：材料原文为三句——“本批次菠菜分拣任务单载明规格为 200 克至 250 克，实际称重记录为 218 克、230 克、245 克。质检记录载明该批次叶菜无黄叶、无烂根，判定为合格。少称补偿单载明订单 A 因实际重量低于规格下限，已生成补偿记录。”待判定拟稿句为：“本批次菠菜每份足量 200 克以上，品质新鲜无黄叶。”

1. 输入材料原文与拟稿句，比较拟稿句中“每份足量 200 克以上”与称重记录中的实际值。称重记录包含 218 克、230 克、245 克，均在 200 克以上，但材料未载明每份均达到该下限，仅载明三个称重值。若拟稿句声称全部足量，则超出材料支持范围；若材料仅支持部分称重值，拟稿句应改为与记录一致的表述。

2. 输入材料原文与拟稿句，比较“品质新鲜无黄叶”与质检记录。质检记录载明无黄叶、无烂根、判定合格，该表述与材料一致。若拟稿句增加“新鲜”这一材料未载明的状态，则属于未获支持内容，需删除或补充对应质检字段。

3. 输入空历史与带历史两种条件下的相同问题，比较模型输入内容。若带历史条件下输入包含先前对话中的无关内容，则需调整记忆轮数或问题优化设置，确认输入差异是否影响拟稿句对材料原文的引用准确性。
