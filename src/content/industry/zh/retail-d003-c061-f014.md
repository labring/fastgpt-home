# 生鲜称重分拣的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

生鲜称重分拣的文案起草依赖分拣任务单、称重标签、少称补偿单与质检记录。这些材料带有重量、规格、批次与时间信息，更新频率为每单和日。文案中的重量区间、规格描述与补偿承诺，必须能在上述材料里找到对应字段。材料未载明的等级、产地或时效，属于未获支持内容。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入由 AI Proxy 承担，App 与 Admin 必须配置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项启动校验失败。旧 OpenAI 变量或单模型自定义地址不能替代。模型能力按应用所需输入分别核对：图片识别、工具调用与思考配置各自验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。

假设演练样本：材料原文为“分拣任务单 2026-09-23 批次 A，菠菜净重 480g 至 520g，规格为中叶，质检记录显示叶片完整率 95%。”拟稿句为“本批次菠菜每份净重不低于 480g，叶片完整率 95%。”核对对象为拟稿句与材料原文，比较重量下限与完整率数值是否一致。材料未载明“不低于”是否覆盖全部订单，该表述待核实。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 根地址，不附加 /v1 | 与官方要求比较，确认无路径后缀 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空 Token | 与启动校验要求比较，确认非空 |
| 模型能力核对 | 按文案任务所需输入逐项核对 | 与模型配置页能力字段比较 |
| 应用参数 | 在应用或节点配置中设置温度与回复上限 | 与编排节点实际字段比较 |
| 探测间隔 | 本次假设试验设为 30 分钟 | 与文档 5～60 分钟整数范围比较 |

## 容易做错的三处

1. 将 AIPROXY_API_ENDPOINT 写成完整模型请求地址并附加 /v1，导致启动校验失败。检查输入是否为根地址，比较官方说明，观察是否出现路径后缀。
2. 用应用 API Key 代替 AIPROXY_API_TOKEN。检查 Token 来源，比较服务端配置，观察是否为空或与 ADMIN_KEY 混用。
3. 把拟稿句中的“不低于 480g”当作材料已支持的结论。检查材料原文是否载明该下限覆盖范围，比较字段，观察是否仅有单批次重量区间。

## 怎么确认配好了

1. 输入假设样本中的材料原文与拟稿句，比较重量下限 480g 与完整率 95% 是否在原文出现，观察拟稿句是否仅复述原文数值。原文未载明覆盖范围时记录待核实。
2. 输入 AIPROXY_API_ENDPOINT 假设值，比较其是否以根地址结尾且无 /v1，观察启动校验是否通过。该结果需实际部署验证，本页不声称已执行。
3. 输入空引用列表 []，核对下游设计是否将无引用输出标记为无依据，观察是否出现未获支持的宣传句。该核对为纸面推演，不声称检索一定返回空结果。
