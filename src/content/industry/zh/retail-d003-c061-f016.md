# 生鲜称重分拣的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在生鲜称重分拣的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。分拣商品文案的表单输入应保留净量待核、样张与本单的区别，提交原话不能直接成为已经核实的描述。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟起草材料有分拣标签样张、客户本单说明“净量待核”和补差申请，尚无本单实际复核结果。表单可收各段出处，人员选择补复核或整理标签措辞。样张说明拟用表达，不证明本件已按该内容完成；待核也不能被成稿写成确定。提交后应对下游输入，确认样张与本单没有混成同一来源，选项本身不核实商品数据。

## 配置怎么定

| 分拣文案表单 | 自拟输入性质 | 接收要求 |
| --- | --- | --- |
| 标签样张 | 拟用表达 | 不代本件事实 |
| 本单说明 | 净量待核 | 保留缺项 |
| 补差申请 | 未见执行 | 不写已补偿 |
| 选项分支 | 补复核或整理措辞 | 核实际收到 |
| 正式操作 | 复称发布另核 | 表单不改订单 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

样张冒本件：若标签样例描述实际订单，应核来源与物件对应；待核冒确认：若净量缺项变成已复核，应取本单真实记录；申请冒补偿：若补差请求被写成处理完成，应查实际执行。三项分别核对象、事实状态和业务动作，不由表单结束补证。

## 怎么确认配好了

验收保留提交原句、来源和选择记录，沿补复核路径检查收到的是本单待办，整理措辞路径仍须保留限定。补本件记录后只更新它支持的描述，补差结果仍缺时不顺带确认。现场复称、资金处理及公开发布需另接流程核权限和回执，节点记录交互并继续不证明商品数据正确，也不自动修改标签或订单。
