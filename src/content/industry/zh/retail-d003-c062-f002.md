# 电商仓入库上架的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

入库上架处理货物进入仓库的第一道账实确认，数据来源包括 WMS、ERP 采购、供应商送货单与条码扫描，日常文档为采购到货单、入库验收单、上架任务与差异报告。本页任务是从这些材料起草商品与营销文案，起草时的上下文与 token 控制决定模型能看到多少材料、能写多长、引用哪些片段。

到货数量、验收状态、差异处理进度属于账实确认信息，文案中的宣传句需要与材料原文对应。材料未载明的卖点、时效、库存状态属于未获支持内容，不能凭模型补写。数据更新频率为每批、日，本页不据此推出批量同步或实时触发机制。

## 这些特征在「上下文与 token」这一环带来什么约束

上下文窗口按实际模型能力核对，回复上限只限制输出长度，不能当作完整上下文窗口。知识库引用上限按 token 控制，单段材料较长时可能被裁剪，需结合问题样本核对。历史输入会影响同一问题在不同对话状态下的输入内容，比较时应控制历史差异。使用固定回复格式时，字段齐全与解析成功需要单独验证。

假设演练样本：材料原文为「采购到货单 PO-2024-0417 载明 A 型收纳箱 200 件，入库验收单 YS-0417 记录实收 200 件、外观完好，上架任务 SJ-0417 分配至 B-03 库位，状态为已完成。」待判定拟稿句为「A 型收纳箱现货充足，当日下单当日发出。」该句的「现货充足」「当日发出」在材料中没有对应字段，属于未获支持内容，起草时应删除或改为与验收数量、上架状态一致的表述。

## 配置怎么定

配置围绕上述样本，仅列与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，用于比较，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AI 模型 | 选择支持所需上下文长度的模型 | 按模型显示的最大上下文核对，与样本材料加拟稿句的总长度比较 |
| 回复上限 | 设为足以容纳依据与处理动作的长度 | 与拟稿句字数比较，观察是否被提前截断 |
| 记忆轮数 | 保留少量历史轮数 | 比较相同问题在空历史与带历史下的输入差异 |
| 知识库引用上限 | 按 token 设定，覆盖单段材料长度 | 与样本材料单段 token 比较，观察是否被裁剪 |
| 回复格式 | 需要固定结构时选择 json_schema | 检查字段齐全与解析成功，不只看文本长度 |
| 最低相关度 | 按语义检索或重排生效时设定 | 与样本问题比较，观察低相关片段是否被过滤 |

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。输入为样本材料加拟稿句，比较模型最大上下文与回复上限两个不同数值，观察是否误认为回复上限决定可参考材料长度。回复上限只限制输出。
2. 让模型补写材料未载明的卖点。输入为样本原文与拟稿句，比较「现货充足」「当日发出」是否有对应字段，观察拟稿句是否出现无依据表述。材料未载明即未获支持。
3. 用最低相关度当作权限或实体过滤。输入为样本问题与检索设置，比较返回片段是否属于有访问权的目标范围，观察是否把相似度阈值当成授权控制。检索不承担授权。

## 怎么确认配好了

1. 输入样本原文与拟稿句，比较拟稿句每个宣传点是否能在原文找到对应字段，观察「现货充足」「当日发出」被标为未获支持并删除或改写，视为满足条件。预期如此，未实测。
2. 输入相同问题在空历史与带历史两种状态，比较两次输入内容差异，观察历史轮数设置是否与预期一致。若两次输入无差异，记录实际观察，不推断原因。
3. 输入样本材料，比较引用上限与单段 token，观察材料是否被完整引用或出现裁剪。若出现裁剪，记录缺口，不声称检索一定返回空或一定命中。

空结果承接可用明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回 `[]`。图片检索须有图像输入及模型能力，重排须具备模型且按设置启用，文档流程图列出的路径不代表每次请求全部执行。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察，不编造运行结果。
