# 直播售后集中处理的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

直播售后集中处理围绕单场流量后的退款、补发与解释承诺展开，资料来自抖店售后、客服IM、仓库WMS与物流轨迹，日常文档包括直播订单清单、退款申请、补发单与话术模板。商品与营销文案起草要引用这些材料中的承诺与状态，文案是否成立取决于材料是否载明对应事实。文案输出依赖语言模型，模型接入与配置决定可用能力与参数边界，与售后单据本身无关。

## 这些特征在「模型接入与配置」这一环带来什么约束

AI Proxy 为必需依赖，App 与 Admin 必须设置 AIPROXY_API_ENDPOINT 与非空 AIPROXY_API_TOKEN，缺少任一项会启动校验失败，旧 OpenAI 环境变量或单模型自定义请求地址不能替代。系统至少需要一个语言模型和一个索引模型。模型 ID 是请求 Body 中 model 字段的值，全局唯一；模型名用于展示，可自定义。渠道可配置模型映射，请求模型与上游实际模型可以不同。模型能力按应用所需输入分别核对，多模态、工具调用与思考配置各自验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。

假设演练样本：某直播间售后组留存的材料原文为三句——“本场承诺：7 天内可退，运费由我方承担。”“订单 A 状态：已签收，退款申请待审核。”“补发单 B：已创建，未出库。”待判定拟稿句为“本商品支持 7 天无理由退货，运费全免，签收后即可退款。”该句涉及主体（本商品对应本场承诺）、对象（订单 A、补发单 B）、状态（待审核、未出库）与有效范围（7 天），需逐项与原文比对。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 文档示例形态，比较是否附加 `/v1` |
| AIPROXY_API_TOKEN | 假设填与 AI Proxy 服务端一致的非空值 | 文档要求非空且一致，比较是否误用应用 API Key |
| 语言模型 | 假设启用一个已测试通过的语言模型 | 文档要求至少一个，比较启用状态与测试结果 |
| 索引模型 | 假设启用一个已测试通过的索引模型 | 文档要求至少一个，比较启用状态与测试结果 |
| 模型映射 | 假设将请求模型映射到上游实际模型 | 文档示例 `gpt-4o-test` 映射 `gpt-4o`，比较两侧 model 字段 |
| 模型能力 | 假设按文案任务所需输入核对 | 文档要求分别验证，比较多模态与工具调用配置 |

## 容易做错的三处

1. 把 AIPROXY_API_TOKEN 填成应用 API Key。输入为环境变量值，比较对象为 AI Proxy 服务端管理员 Token，可观察结果为启动校验是否通过。
2. 将模型名当作模型 ID 使用。输入为请求 Body 的 model 字段，比较对象为渠道中配置的模型 ID，可观察结果为渠道测试返回的模型列表与结果。
3. 用待审核或未出库状态推出已退款或已发货。输入为材料原文中的状态字段，比较对象为拟稿句中的状态表述，可观察结果为两者是否同主体同字段且取值一致。

## 怎么确认配好了

1. 输入假设材料原文三句与拟稿句，比较拟稿句中的“7 天”“运费全免”“签收后即可退款”与原文“7 天内可退”“运费由我方承担”“退款申请待审核”，可观察结果为承诺期限与运费表述一致、退款状态表述不一致，待审核不等于已退款。
2. 输入拟稿句主体“本商品”与原文主体“本场承诺”，比较两者是否为同一对象，可观察结果为主体对应关系是否明确，未载明时记为待核实。
3. 输入补发单 B 的状态“已创建，未出库”与拟稿句未提及补发，比较是否出现超出材料的发货表述，可观察结果为拟稿句未新增发货承诺则通过该项，出现则标记为未获支持。
