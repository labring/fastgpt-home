# 直播选品与样品质检的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

选品质检发生在开播前，判断商品能否上播、是否适合直播展示，资料以供应商资料、检测机构报告、平台负面目录与历史退货率为主，按周或每品更新。本页处理的文档是样品评估表、质检报告、供应商资质与禁售清单。文案起草要引用这些材料中的主体、样品、检测项目与有效期，模型接入与配置决定这些字段能否被正确读取与调用。

## 这些特征在「模型接入与配置」这一环带来什么约束

FastGPT 借助 AI Proxy 连接模型提供商。自 V4.17.0 起 AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 与非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败，旧 OpenAI 环境变量或单模型自定义请求地址不能替代。系统至少需要一个语言模型和一个索引模型才能正常使用。模型 ID 是接口请求 Body 中 model 字段的值，全局唯一；模型名可自定义；模型映射把 FastGPT 请求的模型映射到上游实际模型。模型能力按应用所需输入核对，多模态、工具调用与思考配置分别验证；应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。

假设演练样本：某选品经理提交一份待判定拟稿句，供核对材料原文如下。「样品评估表 2026-03-02 批：供应商杭州某日用品厂，样品保温杯，材质标注 304 不锈钢，送检项目为重金属迁移，检测机构报告编号 JC-2026-0311，报告状态为已出具，报告日期 2026-03-05。」拟稿句：「本款保温杯经检测合格，304 不锈钢内胆安全无忧。」核验请求：请判断该拟稿句是否被上述材料支持。

## 配置怎么定

以下设置围绕本页文档与主任务，数值为本次假设试验起点，用于与实测值比较，非官方默认。

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不附加 /v1 | 与部署实际地址逐字符比对，确认无多余路径 |
| AIPROXY_API_TOKEN | 设置非空管理员 Token | 与服务端配置比对，确认非空且一致 |
| 语言模型 | 启用至少一个，用于文案起草 | 在模型测试中发起一次请求，观察返回 |
| 索引模型 | 启用至少一个，用于资料检索 | 确认模型 ID 与渠道中模型一致后启用 |
| 模型映射 | 将拟用模型 ID 映射到上游模型 | 核对映射表键值与上游模型名 |
| 模型探测间隔 | 假设取 30 分钟 | 与 5～60 分钟整数范围比对，观察探测记录 |

## 容易做错的三处

1. 把拟稿句中的「检测合格」当作材料已载明的结论。样本原文只写报告状态为已出具、报告日期 2026-03-05，未写检测结论为合格，也未写「安全无忧」。输入是拟稿句与原文，比较的是原文是否出现合格结论字段，观察结果是该字段未载明，属未获支持。
2. 把报告编号 JC-2026-0311 的出具状态当成对全部检测项目的覆盖。原文只列重金属迁移一个送检项目，输入是拟稿句的笼统表述与原文项目字段，比较的是项目范围，观察结果是范围不一致，需按项目逐项核对。
3. 把模型探测的绿色状态当作模型能力已满足文案任务。探测只反映可用性与延迟，输入是探测状态与任务所需能力，比较的是能力字段是否被验证，观察结果是二者不构成同一事实，能力仍需单独测试。

## 怎么确认配好了

1. 输入假设原文与拟稿句，比较拟稿句是否出现原文未载明的结论词，观察结果为「合格」「安全无忧」在原文中无对应字段，判定为未获支持。
2. 输入报告编号与送检项目，比较拟稿句表述范围与原文项目字段，观察结果为原文仅列重金属迁移，拟稿句未限定项目，判定为范围待核实。
3. 输入模型测试返回与任务能力要求，比较返回是否覆盖文案起草所需输入，观察结果为测试成功仅说明连通，能力是否满足仍需按应用所需输入另行验证。
