# 直播间违规申诉的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

在直播间违规申诉的商品与营销文案起草中，本页说明FastGPT的模型接入与配置如何衔接资料。申诉文案明确通知、录屏说明与商家解释各自来源，不将转写当完整视频核验。所用场景为自拟文字测试。

## 这些特征在「模型接入与配置」这一环带来什么约束

假设违规通知指出某片段，商家申诉草稿说需补完整上下文，录屏文字摘录只覆盖该片段前后的一部分。文案接入应核模型收到的是通知、转写还是视频文件，不能把读了摘录写成已经核完整直播。商品资质也只按其主体与范围使用。本题无真实违规判定或平台结果，仅用自拟文字整理申诉理由与缺证，不宣称可以撤销处罚。

## 配置怎么定

| 申诉文案输入 | 假设材料 | 输出复核 |
| --- | --- | --- |
| 通知 | 指定片段 | 核所涉对象 |
| 转写 | 部分前后文 | 不称全场核验 |
| 解释 | 商家草稿 | 不当平台认可 |
| 资质 | 另一规格 | 核适用商品 |
| 提交 | 有权人员另审 | 不承诺撤销结果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `AI Proxy依赖` | 按实际版本核服务、渠道与应用。 |
| `AIPROXY_API_ENDPOINT` | 使用AI Proxy服务根地址。 |
| `AIPROXY_API_TOKEN` | 管理员Token非空且与服务端一致。 |
| `模型能力` | 按实际输入路径验证所需能力。 |
| `应用参数` | 接口同名字段未必覆盖应用设置。 |

## 容易做错的三处

- 只有录屏摘录送入却生成全场无相关表述时，对转写覆盖时段与实际输入，不把局部材料扩大为全场反证。

- 商家解释被写成平台已认可时，对通知作者、草稿立场和平台处理结果，材料主体不能互换。

- 商品资质对应另一规格却支持当前申诉时，对资质对象及通知所涉商品，不能同品牌就视为同证据。

## 怎么确认配好了

先给通知，再补有边界的文字摘录和对应商品资料，固定问现有证据支持什么、仍需补什么。保留实际请求及草稿新增句，模型比较不用声称胜诉率。若需视频读取，另核实际模型、输入路径与覆盖，不能继承文字测试结论。定稿和提交由有权人员审，模型服务连接不代表可以操作平台申诉。
