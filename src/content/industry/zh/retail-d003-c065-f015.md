# 直播间违规申诉的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

直播间违规申诉针对已经发生的处罚，需要复盘证据链。资料主要来自平台违规中心、直播回放、客服记录和商品资质库，日常处理的文档包括违规通知、直播录屏、商品资质和申诉说明。这些资料更新不定期，每次违规触发一轮整理。

商品与营销文案起草这一任务，核心动作是从既有材料中找出可支撑拟稿句的原文，再判断拟稿句是否被材料支持。知识库检索与召回在此环节承担的是把违规通知、录屏记录、资质文件等文本召回为引用内容，供起草时逐句比对。资料是否完整、主体是否明确、状态是否在有效范围内，直接决定拟稿句能否成立。

## 这些特征在「知识库检索与召回」这一环带来什么约束

资料形态差异大：违规通知偏编号与条目，录屏记录偏时间与画面描述，资质文件偏主体与有效期。语义检索适合自然语言问法，全文检索适合编号、型号、专有名词。混合检索通过 RRF 融合两路结果，重排对候选文本二次排序。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，会增加一次模型调用。

检索库要求关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，操作时先核标识并排除不符合者，记录实际观察。检索结果只提供引用内容，不承担权限判断或实体隔离；相似度得分是相关度数值，不能当作业务归属或授权依据。

假设演练样本：材料原文为「店铺A于2025年3月10日收到平台违规通知，编号为T-20250310-07，载明3月8日直播中商品X的宣传语涉及功效表述问题。商品X的资质文件载明主体为店铺A，有效期至2025年12月31日。录屏记录显示3月8日20时15分主播口播内容与通知描述一致。」待判定拟稿句为「店铺A在2025年3月8日直播中对商品X的功效表述符合资质文件范围。」比对同一主体、同一日期、同一字段：通知认定功效表述存在问题，资质文件只载明主体与有效期，未载明功效表述合规。该拟稿句未获支持，需保留证据缺口。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 违规通知库与资质库，核验向量模型标识一致 | 标识一致才可共同关联；逐一核对，不一致者排除 |
| 搜索模式 | 先分别用语义检索与全文检索各跑一次 | 用同一测试问题比较两路召回内容，再决定是否用混合检索 |
| 引用上限 | 假设起点为 3000 tokens | 用长短不同的实际资料测试引用内容是否完整，与较短起点比较后调整 |
| 最低相关度 | 假设起点为 0.4 | 先标注相关与无关样本，比较过滤后保留内容再调阈值 |
| 问题优化 | 先关闭，用原始问题检索一次 | 再开启，比较优化后问题是否改错主体或对象 |
| 结果重排 | 先不启用 | 候选较多且文本问题明确时，启用后比较重排得分与过滤效果 |

## 容易做错的三处

1. 把检索得分当作授权或归属判断。输入为待判定拟稿句与召回引用内容，比较的是引用原文是否载明同一主体、同一期间、同一字段，观察结果是相似度数值高低。得分高不表示材料支持该句，仍需逐句比对原文。
2. 把未载明当作否定。输入为资质文件原文，比较的是文件是否载明功效表述合规字段，观察结果是该字段缺失。缺失只能记为未获支持或待核实，不能记为冲突或否定。
3. 跨不同向量模型的库强行共同关联。输入为两个知识库的向量模型标识，比较的是标识是否一致，观察结果是不一致。此时排除不符合者并记录，不执行跨模型检索来比较漏召回。

## 怎么确认配好了

1. 用假设样本中的通知原文与拟稿句核对。输入为通知编号 T-20250310-07 的原文与拟稿句，比较同一主体店铺A、同一日期2025年3月8日、同一字段功效表述，观察结果是通知认定存在问题而资质文件未载明合规。满足条件为拟稿句被标为未获支持。
2. 用空结果承接核对下游设计。输入为明确纸面输入的空引用数组，比较下游起草环节是否按零长度引用继续走通，观察结果是链路未中断。满足条件为下游能承接空引用而不中断。
3. 用问题优化前后对照核对主体。输入为原始问题与优化后问题，比较店铺A、商品X、2025年3月8日三个要素是否被保留，观察结果是优化后问题仍含同一主体与对象。满足条件为要素未被替换或增补。
