# 直播间违规申诉的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在直播间违规申诉的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。申诉说明表单保留演示素材身份和待核事项，收集完整不表示申诉已经提交。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟素材注明视频仅是流程演示，实际处理依据待补，旧申诉的回复属于另一事项。表单可收当前视频、用途与缺件，人员再选择补证或起草说明。演示内容不能直接写成真实用户操作，旧回复也不支持本次处理结果。节点收集后需把用途和未核项传给下一环，不能只留一段完整叙述；填写完成不判断平台是否接受申诉。

## 配置怎么定

| 申诉说明表单 | 自拟素材 | 核验动作 |
| --- | --- | --- |
| 视频身份 | 流程演示 | 不冒实测 |
| 资料缺口 | 处理依据待补 | 继续明示 |
| 旧回复 | 另一事项 | 核版本 |
| 表单提交 | 信息承接 | 非正式报送 |
| 实际结果 | 本次回执 | 独立取证 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

演示冒实测时，核素材身份；旧申诉结果串入时，核事项与版本；表单提交变正式报送时，查本次实际回执。三处分别看来源、对象和动作阶段，字段有值不补真实依据。

## 怎么确认配好了

验收比较提交内容、后续接收和草稿，缺材料时应明示所缺。补证后只更新当前事项。节点等待交互后继续只说明信息承接；正式报送、账号权限和平台处理需独立流程与真实记录。 演示视频的拍摄说明与实际处理凭证分别列入待补栏，复核人应能从申诉事项追到所引用的那段画面。
