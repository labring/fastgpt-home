# 社区团购团长运营的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

团长运营围绕社区节点与佣金结算展开，日常材料包括团长协议、佣金表、提货清单与社群公告。商品与营销文案起草需要从这些材料中提取可核对的表述，例如商品名称、规格、提货安排与售后口径。材料按日或按团更新，但更新频率本身不改变本页配置方式，配置只决定模型能否被调用以及应用参数如何生效。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务必须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两项配置。系统至少需要一个语言模型和一个索引模型才能正常使用。模型能力按应用所需输入核对，多模态、工具调用与思考配置分别验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。

假设演练样本：某团长运营方留存的团长协议原文为“本协议自双方签署之日起生效，团长负责本团提货清单核对与社群公告发布”。佣金表原文为“自2025年3月1日起，生鲜类佣金比例为百分之五”。一条待判定的拟稿句为“本团生鲜佣金为百分之五，长期有效”。判断该句是否被材料支持，需要比较主体、对象、期间与字段：佣金表给出起始日期与比例，未载明截止日期；拟稿句写入“长期有效”，属于材料未载明的期间表述。

## 配置怎么定

下表围绕本页样本列出官方已说明的设置或实施核对项。需要数值时明确为本次假设试验起点，并说明比较对象。

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不附加 `/v1` | 与部署实际根地址逐字比较 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空管理员 Token | 与应用 API Key 区分，确认非空且一致 |
| 语言模型 | 启用至少一个语言模型 | 在模型提供商页面确认已启用 |
| 索引模型 | 启用至少一个索引模型 | 在模型提供商页面确认已启用 |
| 模型能力 | 按文案起草所需输入核对 | 多模态、工具调用、思考配置分别验证 |
| 应用参数 | 在应用或节点配置中设置 | 确认参数位置，不假设对话接口同名字段覆盖 |

## 容易做错的三处

1. 把 AIPROXY_API_TOKEN 与应用 API Key 混用。输入为两处凭证，比较其来源与用途，观察结果是启动校验是否通过；Token 为空或与 AI Proxy 服务端不一致时校验失败。
2. 将拟稿句“长期有效”当作佣金表已载明内容。输入为佣金表原文与拟稿句，比较期间字段，佣金表只给出起始日期，拟稿句的“长期有效”未获支持。
3. 假设对话接口同名字段会覆盖应用编排参数。输入为应用或节点参数配置与接口请求字段，比较生效位置，应用参数需在应用或节点配置中设置。

## 怎么确认配好了

1. 核对 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN：输入为部署实际根地址与服务端 Token，比较是否附加 `/v1`、是否非空且一致，两项均满足时启动校验通过；任一项缺失时启动校验失败。
2. 核对拟稿句期间表述：输入为佣金表原文“自2025年3月1日起，生鲜类佣金比例为百分之五”与拟稿句“本团生鲜佣金为百分之五，长期有效”，比较期间字段，佣金表未载明截止日期，拟稿句的“长期有效”判定为未获支持，记录为证据缺口。
3. 核对模型能力与应用参数位置：输入为应用所需输入类型与参数配置位置，比较模型能力是否覆盖该输入、参数是否在应用或节点配置中设置，两项均确认时视为配置核对完成；若模型能力未覆盖或参数仅在对话接口同名字段出现，则记录为待核实。
