# 社区团购预售集单的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

预售集单先收订单再组织采购履约，商品与营销文案需要围绕预售商品表、集单结果、采购计划、截单通知四类材料起草。材料更新频率为日或每场，文案起草时引用的库存、成团量、截单时间来自当日或当场材料。模型接入与配置决定起草环节能否按材料原文生成可核对的文案句，以及这些句子能否追溯到具体字段。

## 这些特征在「模型接入与配置」这一环带来什么约束

系统至少需要一个语言模型和一个索引模型才能正常使用。AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 服务必须设置 `AIPROXY_API_ENDPOINT` 和非空 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。模型 ID 是接口请求 Body 中 `model` 字段的值，全局唯一；模型名用于展示。模型渠道按协议类型配置，代理地址填写 BaseUrl。模型状态探测仅针对已启用的系统模型，首次失败后最多自动重试 3 次。

假设演练样本：材料原文为「本次预售商品表第 12 行：商品名称为‘春笋 500g’，预售状态为‘已截单’，截单时间为 3 月 18 日 20:00；集单结果第 3 行：该商品成团量为 0；采购计划第 5 行：该商品未列入本场采购。」待判定的拟稿句为「春笋 500g 本场已成团，可继续下单」。核对对象为同一商品、同一场次、同一字段，比较拟稿句与材料原文中预售状态、成团量、采购计划三个字段的取值。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写 AI Proxy 服务根地址，不附加 `/v1` | 与文档要求一致；比较是否附加了路径后缀 |
| `AIPROXY_API_TOKEN` | 填写与服务端一致的非空管理员 Token | 文档要求非空；比较是否误用应用 API Key |
| 模型 ID | 与模型渠道中的模型一致 | 文档说明模型 ID 全局唯一；比较请求 Body 的 `model` 字段 |
| 模型类型 | 语言模型与索引模型各至少一个 | 文档要求至少各一个；比较已启用模型列表 |
| 模型状态探测 | 仅针对已启用系统模型 | 文档说明未启用模型不参与探测；比较探测范围 |
| 重试次数 | 首次失败后最多重试 3 次 | 文档说明单轮最多尝试 4 次；比较探测记录 |

## 容易做错的三处

1. 将 `AIPROXY_API_ENDPOINT` 填成完整模型请求地址并附加 `/v1`。检查输入为环境变量值，比较对象为文档中「不要附加 `/v1`」的要求，可观察结果为启动校验是否通过。
2. 用应用 API Key 代替 `AIPROXY_API_TOKEN`。检查输入为环境变量值，比较对象为文档中「必须与服务端配置一致且不能为空」，可观察结果为启动校验是否通过。
3. 将未启用的模型纳入探测范围。检查输入为已启用模型列表，比较对象为文档中「仅针对已启用的系统模型」，可观察结果为探测记录中是否出现未启用模型。

## 怎么确认配好了

- 验证一：输入假设样本中「春笋 500g」的预售状态字段，比较拟稿句「本场已成团」与原文「已截单」，观察拟稿句是否与原文取值一致。预期为不一致，需修改拟稿句或记录证据缺口。

- 验证二：输入假设样本中「春笋 500g」的成团量字段，比较拟稿句「已成团」与原文「成团量为 0」，观察拟稿句是否被原文支持。预期为未获支持，需补充材料或调整表述。

- 验证三：输入假设样本中「春笋 500g」的采购计划字段，比较拟稿句「可继续下单」与原文「未列入本场采购」，观察拟稿句是否与采购计划一致。预期为不一致，需记录缺口并保留原文。

以上验证仅针对本页假设样本，不声称已实际执行。模型状态探测的告警 Webhook、事件类型与请求体字段按文档说明核对，未配置时不产生推送。检索与相关度不承担权限或实体隔离职责。
