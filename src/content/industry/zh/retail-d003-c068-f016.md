# 社区团购预售集单的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在社区团购预售集单的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。预售文案表单保留意向阶段、成团条件缺口与到货待回复，不把提交变成订单。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟材料说本轮只收集意向，成团条件另核，到货安排等待供方回复。表单可收商品对象和已有文字，让人员选择补条件或起草意向说明。填写商品及联系方式不证明订单成立；未给条件也不能从旧活动推定门槛。后续需收到三个待核状态，不能用完整宣传句掩盖缺失来源，也不能把其他商品的供方回复用于本轮。

## 配置怎么定

| 预售说明表单 | 本题阶段 | 实际核验 |
| --- | --- | --- |
| 登记用途 | 仅收意向 | 不冒订单 |
| 成团条件 | 尚待核 | 不借旧活动 |
| 到货安排 | 供方待回 | 不写已定 |
| 补充材料 | 条件与回复 | 分别核对象 |
| 正式交易 | 下单通知另接 | 权限及回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

意向登记冒正式订单时，核实际确认；旧活动条件套入本轮时，核活动身份与原句；待回复到货被写成已定时，查本商品真实答复。三处分别核交易阶段、适用范围和供货依据。

## 怎么确认配好了

验收比较表单文字、下游输入和草稿，逐句说明依据。新增条件或回复分别核对象再更新，仍缺项继续保留。表单交互不会成团、下单或通知供方；实际交易与消息发送须另验授权和业务回执。 文案中的预计到货与开团条件分别标出来源，供应方未回复的内容保留待确认状态，避免读者误认已经成团。
