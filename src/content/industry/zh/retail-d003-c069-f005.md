# 经销商返利核算的商品与营销文案起草：多轮对话与提示词

## 这个品类的数据长什么样

在经销商返利核算的商品与营销文案起草中，本页说明FastGPT的多轮对话与提示词如何衔接资料。返利文案多轮补料保留政策条件、销量核定与开票阶段。所用场景为自拟文字测试。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

假设返利政策限定某活动，销量达成表仍待核退货，对账单未获经销商确认，红字发票资料未给。先写活动介绍、后问返利结果时，应把新问题与实际政策、期间相对，不从介绍稿推已达标。本题不含真实费率或返利额，缺发票也不能自行补已结算。

## 配置怎么定

| 返利文案多轮题 | 假设状态 | 保留边界 |
| --- | --- | --- |
| 政策 | 某活动限定 | 不扩全部经销商 |
| 销量 | 退货待核 | 不称已达标 |
| 对账 | 对方未确认 | 不称已结 |
| 发票 | 资料未给 | 不补已开票 |
| 历史 | 介绍稿 | 不作结果依据 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `提示词与任务` | 说明资料、任务和缺证据处理。 |
| `历史记录` | 核实际提交的历史输入。 |
| `问题优化` | 指代消除与问题扩展需复核。 |
| `模型与长度` | 上下文与回复长度分别核对。 |
| `回复格式` | json_schema需给格式并验解析。 |

## 容易做错的三处

- 追问忽略退货待核而称销量全达标时，对实际历史中的达成表和原限制，核是否摘要删项。

- 某活动政策被后轮套到全部经销商时，对活动对象、期间和经销商身份，语言泛化不扩政策。

- 对账待确认被写成返利已结且已开票时，对双方确认与发票证据，输出不能跳过阶段。

## 怎么确认配好了

按政策、达成表、对账意见逐轮加入，重复问能写的介绍和不能确认的结果。保留每轮采用句，另起会话测最终材料。提示词要求按条件表达，不以“更有吸引力”指令补收益。真实返利核算、发票及外发由负责人员办理，文案不执行结算。 红字发票到齐后，也须核对应交易与调整事项，不能据发票存在推定支付完成。
