# 经销商返利核算的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样
返利核算发生在销售之后，核心是政策口径与财务处理，这决定了文案起草的输入材料来自 ERP 销售、经销商回款、合同台账与财务系统。日常文档包括返利政策、销量达成表、对账单与红字发票，更新频率为月或季。文案起草需要引用这些材料中的主体、对象、期间与状态，材料未载明的字段保持未知。核对达成口径、扣除退货金额与开票冲抵是最耗时的环节，文案若涉及返利金额或达成结论，必须能追溯到对应材料的具体字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
模型接入通过 AI Proxy 完成，App 与 Admin 必须配置 AIPROXY_API_ENDPOINT 与非空 AIPROXY_API_TOKEN，缺少任一项启动校验失败。模型渠道在管理员-模型提供商页面创建，模型 ID 为请求 Body 中 model 字段的值，全局唯一，模型映射可将系统内模型 ID 映射到上游实际模型。模型探测仅针对已启用模型，重试最多 3 次，状态分为正常、高延迟、异常。检索关联要求同一向量模型，跨模型库不可共同关联，只核标识并排除不符合者。空结果按明确的纸面输入核对下游设计，不声称虚构规则检索一定返回空数组。

假设演练样本：某品牌财务提供的返利政策原文为「2026 年第一季度，经销商 A 完成销量达成率 95% 以上，按季度返利 2% 核算」。销量达成表原文为「经销商 A，2026 年 1 月至 3 月，达成率 96%」。待判定拟稿句为「经销商 A 已满足 2026 年第一季度 2% 返利条件」。核对点为政策主体、对象、期间与达成率阈值是否与达成表同字段一致。

## 配置怎么定
| 配置项 | 本页实施核对项 | 与样本的关系 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不附加 /v1 | 模型调用入口，文案起草依赖该地址 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空管理员 Token | 调用凭证，不能用应用 API Key 代替 |
| 模型渠道与模型映射 | 渠道内配置模型，映射键为系统内模型 ID | 决定起草请求发往的上游模型 |
| 模型能力 | 按应用所需输入核对多模态与工具调用 | 文案起草仅需文本能力时按实际配置 |
| 应用参数 | 参数在应用或节点配置中设置 | 不假设对话接口同名字段覆盖编排 |
| 模型探测 | 仅探测已启用模型，间隔 5～60 分钟整数 | 观察起草所用模型是否可用 |

## 容易做错的三处
1. 将模型映射的键与值写反。输入为系统内模型 ID 与上游模型 ID，比较映射 JSON 的键值方向，观察请求 Body 中 model 是否为系统内 ID。
2. 把待审核状态当作已获授权。输入为拟稿句与政策原文，比较主体、期间、阈值字段，观察是否出现原文未载明的授权或生效结论。
3. 用相似度设置排除无关记录。输入为检索请求与结果列表，比较返回记录的业务主体标识，观察是否混入其他经销商或期间的数据。

## 怎么确认配好了
1. 输入假设样本中的政策原文与达成表原文，比较拟稿句的主体、对象、期间与阈值字段，观察拟稿句仅复述原文已载明的 96% 达成率与 2% 返利条件，未添加签署、审批或到账结论。
2. 输入假设样本的拟稿句，比较其与政策原文的字段对应关系，观察「已满足」表述是否超出原文「按季度返利 2% 核算」的载明范围，超出部分记为未获支持。
3. 输入假设样本的期间「2026 年第一季度」，比较达成表覆盖的 1 月至 3 月，观察期间是否同字段一致，若材料仅覆盖部分月份则记录证据缺口。
