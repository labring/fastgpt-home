# 跨境商品合规与标签的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

商品合规发生在商品上架与进口之前，文案起草依赖平台政策中心、检测机构报告、目的国法规库与供应商资料。产品测试报告、英文标签、MSDS、平台禁售清单这几类文档，通常以不定期的节奏更新，每次上新都可能带来新的材料版本。文案起草环节的输入，是这些材料中被引用的具体表述，以及需要判断是否被材料支持的宣传句。材料本身可能只覆盖某一型号、某一批次或某一目的国，文案若超出材料载明的范围，就会形成无法核对的表述。上下文与 token 这一环要解决的，是拟稿所依据的材料片段能否完整进入模型输入，以及输入被裁剪后判断是否仍然成立。

## 这些特征在「上下文与 token」这一环带来什么约束

材料片段长短不一，检测报告与法规条文常包含主体、对象、状态与有效范围四类信息，任一项被截断都可能改变判断结论。知识库引用上限按 token 控制，单段材料较长时，进入模型的内容可能被裁剪，拟稿句的判定依据随之不完整。回复上限只约束模型输出长度，与模型可参考的完整上下文窗口是两个不同的量。历史轮数决定模型是否带入更早对话，同一问题在空历史与带历史两种输入下，参考内容可能不同。使用固定回复格式时，字段是否齐全需要单独核对，文本长度合格不代表结构可解析。语义召回与相关度得分只反映内容相似程度，不承担权限隔离或实体范围过滤。

## 配置怎么定

以下配置项围绕本页样本，列出官方已说明的设置与实施核对动作。数值仅为本次假设演练的起点，用于与对照值比较，不构成默认值。

| 配置项 | 本次假设起点 | 核对动作与比较对象 |
| --- | --- | --- |
| 知识库引用上限 | 假设设为 3000 tokens | 与样本材料片段总长度比较，确认主体、对象、状态、有效范围四类信息是否完整进入 |
| 回复上限 | 假设设为 800 tokens | 与拟稿句加依据说明的实际输出长度比较，确认依据与处理动作未被截断 |
| 记忆轮数 | 假设设为 2 轮 | 与空历史输入下的同一问题比较，确认带入历史后参考材料是否变化 |
| 回复格式 | 假设选用 json_schema | 核对返回字段是否齐全并可解析，不只看文本长度 |
| 最低相关度 | 假设设为 0.4 | 与语义检索或重排得分比较，确认低相关片段被过滤，同时记录被过滤内容 |
| 思考强度 | 假设选用标准思考 | 该配置只影响思考预算，与引用 token 上限无关，不用于控制材料裁剪 |

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。回复上限约束的是模型输出长度，模型可参考的材料长度由模型能力与知识库引用上限共同决定。错误表现是：材料片段被裁剪后，拟稿句仍按完整材料判定为获支持。核对时比较材料原文四类信息与进入模型的内容，确认未被截断。

2. 用语义相关度得分代替范围核对。相关度只反映内容相似程度，不判断材料是否覆盖同一主体、同一目的国或同一批次。错误表现是：一条得分较高的材料被直接用作拟稿依据，而材料载明的型号或目的国与拟稿句不一致。核对时逐项比较主体、对象、状态与有效范围。

3. 把待审核材料当作已生效依据。待审核、已提交、已签署是不同状态，材料处于待审核时，拟稿句不能按已生效材料判定。错误表现是：引用一条尚未完成审核的检测报告，得出拟稿句获支持的结论。核对时记录材料状态，缺失生效证据时保留为待核实。

## 怎么确认配好了

假设演练样本：某供应商提供一份英文标签草稿，材料原文为「本产品适用于型号 A 的家用场景，标签内容依据 2024 年目的国现行标签要求编制」。一条待判定拟稿句为「本产品适用于型号 A 与型号 B 的家用场景」。该样本中，材料主体为型号 A，拟稿句主体为型号 A 与型号 B，两者范围不一致。

- 验证一：核对主体范围。输入材料原文与拟稿句，比较材料载明的型号与拟稿句列出的型号。材料只载明型号 A，拟稿句列出型号 A 与型号 B，判定结果为拟稿句超出材料范围，属未获支持。若材料原文同时载明型号 A 与型号 B，则该项满足。

- 验证二：核对引用上限下的完整性。输入材料原文与知识库引用上限起点 3000 tokens，比较进入模型的内容是否包含型号、场景、依据年份与目的国四项。四项齐全时，判定依据完整；任一项缺失时，记录为输入被裁剪，判定暂缓。

- 验证三：核对空结果承接。输入一个明确的纸面空结果 `[]`，比较下游节点在收到空结果时的行为。下游节点若按设计返回待核实提示，则承接正常；若下游节点按有结果路径继续生成拟稿句，则记录为承接异常。该核对不声称虚构规则检索一定返回空结果。

以上三项均针对本页主任务，即拟稿句是否被材料支持。材料未载明的部分保持缺失，待审核状态不视为已生效，检索行为不视为授权。
