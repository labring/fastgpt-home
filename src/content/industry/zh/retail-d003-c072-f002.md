# 跨境海外仓补货管理的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

跨境海外仓补货管理涉及补货计划、入仓预约、库存库龄表、尾程派送单等文档。这些材料由海外仓WMS、ERP销售预测、货代系统与承运商账单产生，更新频率为周或日。商品与营销文案起草需要引用其中的库存状态、入仓时间窗、库龄区间与派送范围。文案中的具体宣传句是否被材料支持，取决于材料原文是否载明对应主体、对象、状态或有效范围。

## 这些特征在「上下文与 token」这一环带来什么约束

上下文窗口按实际模型能力核对，回复上限是单次回答长度，两者不是同一数值。知识库引用上限以 token 为单位，单段材料较长时可能被裁剪。历史轮数会影响同一问题在空历史与带历史下的输入差异。结构化回复格式需要验证字段齐全与解析成功。

假设演练样本：材料原文为「本批次补货计划覆盖德国海外仓，入仓预约时段为第32周至第34周，库存库龄表显示该批次库龄处于30至60天区间。」待判定拟稿句为「该批次商品支持德国全境尾程派送，下单后三日内送达。」材料未载明尾程派送范围与时效，该拟稿句未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AI 模型 | 选用弹窗中显示支持所需上下文长度的模型 | 比较模型最大上下文与材料总 token，确认是否容纳 |
| 回复上限 | 设为能容纳依据与处理动作的长度 | 比较截断位置与拟稿句完整性 |
| 知识库引用上限 | 按 token 设定，覆盖单段材料长度 | 比较引用内容与原文，确认是否被裁剪 |
| 记忆轮数 | 保留少量历史轮数 | 比较空历史与带历史下同一问题的输入差异 |
| 回复格式 | 需要固定结构时选用 json_schema | 验证字段齐全与解析成功 |
| 最低相关度 | 按语义检索或重排生效条件设定 | 比较过滤后结果与原文对应关系 |

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。检查输入：模型最大上下文数值与回复上限数值。比较两者是否为同一字段。观察结果：若混用，长材料可能被误判为可容纳。
2. 用语义召回或相关度分数替代业务核对。检查输入：检索返回的候选内容与材料原文。比较候选是否含拟稿句所需主体、对象、状态。观察结果：相关度高不表示宣传句被材料支持。
3. 把待审核或报价有效期当作已生效事实。检查输入：材料中状态字段与日期字段。比较同一字段取值是否互斥。观察结果：未载明生效条款时，该事实待核实。

## 怎么确认配好了

1. 输入假设样本材料原文与拟稿句，比较拟稿句中的派送范围与时效是否出现在原文。原文未载明时，判定为未获支持，记录证据缺口。
2. 输入同一问题在空历史与带少量历史两种条件下的请求，比较两次输入内容差异。观察历史轮数是否引入额外内容，确认是否影响拟稿判断。
3. 输入纸面空结果 `[]` 核对下游承接设计，比较下游节点是否处理空引用。观察是否出现未定义字段或解析失败，记录实际观察，不预设必然返回空。
