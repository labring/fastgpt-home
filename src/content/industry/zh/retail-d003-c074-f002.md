# 跨境退货翻新与二次销售的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

退货翻新处理逆向物流和商品状态，与头程补货是两套记录。主要数据来自海外仓WMS、TikTok退货中心、Amazon退货报告和商品质检照片，日常文档包括退货质检表、翻新记录、报废单和二次上架清单。文案起草要判断一条宣传句能否被质检表与翻新记录支持，例如外观等级、配件是否齐全、包装是否更换。数据按日或每批更新，本页只关心起草时把哪些材料放进上下文。

## 这些特征在「上下文与 token」这一环带来什么约束

模型单次请求可参考的内容长度由最大上下文决定，回复上限控制回答长度，两者不能混同。知识库引用上限按 token 控制，不是按条数，单段质检描述较长时可能被裁剪。记忆轮数越大带入的历史越多，消耗与响应速度随之变化；相同问题在空历史和带历史下的输入不同，检索结果也可能不同。选择 json_schema 时，后续流程读取固定字段，只检查文本长度不足以确认结构可用。语义检索与最低相关度只影响相关性排序，不承担权限或实体隔离；检索本身不是授权。混合检索经 RRF 融合多路结果，重排需要具备模型并按设置启用。

假设演练样本：材料原文为「退货质检表：主体为某批次折叠桌，状态为外观轻微划痕、五金件齐全、原包装破损，翻新记录载明更换外箱并复检合格，日期范围为2024年3月1日至3月31日，授权范围为质检与翻新环节内部核对」。拟稿句为「该批次折叠桌经翻新后按全新品相上架销售」。判定需同主体、同期间、同一字段：材料只支持外观轻微划痕与更换外箱，未载明「全新品相」或「上架销售」，该句未获支持，保留证据缺口。

## 配置怎么定

| 配置项 | 本样本设定 | 核对方式 |
| --- | --- | --- |
| 最大上下文 | 按所选模型实际能力显示 | 与质检表加翻新记录总长度比较，确认未被截断 |
| 回复上限 | 本次假设试验起点设为覆盖依据与处理动作 | 与拟稿句长度比较，观察是否提前截断 |
| 引用上限 | 按 token 控制，本次假设起点覆盖两份材料 | 与单段质检描述长度比较，确认内容完整 |
| 记忆轮数 | 本次假设起点保留少量轮次 | 比较空历史与带历史下同一问题的输入差异 |
| 回复格式 | 需要固定字段时选 json_schema | 核对字段齐全与解析成功，不只看长度 |
| 最低相关度 | 仅语义检索或重排时生效 | 观察过滤后是否仍包含本样本材料 |

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。输入为最大上下文与回复上限两项设置，比较两者含义，观察是否误认为回复上限等于可参考内容长度。
2. 把最低相关度当作权限或实体过滤。输入为相似度阈值与一份不属于本批次的质检记录，比较过滤条件，观察该记录是否因相关性高而被带入。
3. 把待审核的报废单当作已执行报废。输入为报废单状态字段与拟稿句，比较状态取值，观察是否将未完成动作写成已完成事实。

## 怎么确认配好了

1. 输入上述材料原文与拟稿句，比较「外观轻微划痕、五金件齐全、更换外箱」与「全新品相、上架销售」，满足条件为拟稿句被标为未获支持并记录缺口。
2. 输入空历史与带历史两种请求，比较同一问题下的检索输入，满足条件为差异被记录，且不据此断言某种结果必然出现。
3. 输入纸面空结果[]与下游承接设计，比较下游是否按空引用处理，满足条件为下游不生成无依据文案；检索是否返回[]属未知，不作保证。
