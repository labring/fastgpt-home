# 跨境退货翻新与二次销售的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

退货翻新场景的资料来自海外仓WMS、TikTok退货中心、Amazon退货报告和商品质检照片，日常文档是退货质检表、翻新记录、报废单和二次上架清单。这些材料记录的是商品实物的状态判断：退货等级、包装是否更换、能否二次上架。商品与营销文案起草要引用这些状态结论，文案中的每一句宣传描述都需要材料中的对应字段支撑。资料更新频率为日或每批，本页不据此推导批量同步或实时触发机制。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务必须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项启动校验失败；AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。模型渠道在管理员-模型提供商页面创建，协议类型、模型映射、代理地址（填 BaseUrl）和 API 密钥分别填写，渠道测试会实际发送请求并输出每个模型的测试结果与请求时长。系统至少需要一个语言模型和一个索引模型。模型能力按应用所需输入核对，多模态、工具调用与思考配置分别验证；应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。模型探测仅针对已启用的系统模型，首次失败后最多重试 3 次，4 次全部失败才判定异常。

假设演练样本：海外仓质检员提交一份退货质检表，材料原文为「退货单号 RT-2041，商品为折叠露营桌，质检结论为外观轻微划痕，配件齐全，外包装破损，已更换外包装，可二次上架」。待判定的拟稿句为「本商品为全新未使用品，原包装完整」。核对对象是质检结论字段与包装字段，判断该拟稿句是否被材料支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 文档要求填根地址；与附加 /v1 的写法比较，确认校验通过 |
| AIPROXY_API_TOKEN | 假设填服务端一致的非空 Token | 文档要求非空且与服务端一致；与应用 API Key 比较，后者不能替代 |
| 语言模型渠道 | 假设新增一个渠道并执行渠道测试 | 文档说明渠道测试实际发送请求；比较测试结果与请求时长是否输出 |
| 模型映射 | 假设配置 `gpt-4o-test` 映射到 `gpt-4o` | 文档示例的映射结构；比较 FastGPT 请求模型与上游实际 model |
| 模型探测 | 假设启用自动探测，间隔填 30 分钟 | 文档支持 5～60 分钟整数；与未启用时的空状态比较 |
| 告警 Webhook | 假设填一个 HTTP 回调地址并点击测试 | 文档说明测试依次推送模拟异常与模拟恢复两条消息 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 填成完整模型请求地址并附加 /v1。检查方式：输入该地址，与文档要求的服务根地址比较，观察启动校验是否通过。
2. 用应用 API Key 充当 AIPROXY_API_TOKEN。检查方式：输入该 Key，与服务端管理员 Token 比较，观察校验是否因 Token 不一致或为空而失败。
3. 把拟稿句「本商品为全新未使用品，原包装完整」直接当作被材料支持的表述。检查方式：输入质检表原文，与拟稿句逐字段比较，观察质检结论「外观轻微划痕」与「全新未使用品」是否互斥、包装字段「已更换外包装」与「原包装完整」是否互斥。

## 怎么确认配好了

1. 输入假设样本中的质检表原文与拟稿句，比较质检结论、配件、包装三个字段，当拟稿句每个描述都能在材料中找到同主体、同期间的对应字段时，才满足被支持条件；出现互斥取值则记录为不支持，字段未载明则记录为待核实。
2. 输入假设的 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN，比较填写形式与文档要求，当端点不含 /v1 且 Token 非空并与服务端一致时，满足启动校验条件；任一不符则记录为配置缺口。
3. 输入假设的渠道配置并执行渠道测试，比较测试输出，当每个模型都输出测试结果与请求时长时，满足渠道可用条件；出现失败结果时记录该模型与错误信息，不推断具体失败原因。

模型探测的告警 Webhook 测试会推送模拟异常与模拟恢复两条消息，这是文档说明的测试行为，不代表真实模型已发生故障或恢复。检索与相关度不承担权限或实体隔离职责。
