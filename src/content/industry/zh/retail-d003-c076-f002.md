# 达人佣金结算与扣佣的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

佣金结算发生在成交之后，文案起草需要同时面对佣金设置记录、结算账单、退款扣佣明细与发票四类材料。这些材料的更新频率为周或月，起草时引用的比例、扣佣条件与结算周期可能来自上一周期，文案中写出的数字与条件需要与材料中的期间和口径对应。

达人合同与精选联盟后台记录共同构成推广关系的依据。文案中涉及佣金比例、有效推广认定与售后扣佣的表述，需要回到这些材料中核对主体、对象与有效范围。财务系统的入账口径与结算账单之间若存在时间差，文案不宜把某一期的数字写成长期承诺。

## 这些特征在「上下文与 token」这一环带来什么约束

文案起草依赖模型读取上述材料。模型单次请求可参考的内容长度由所选模型的最大上下文决定，回复上限只限制输出长度，不能当作完整上下文窗口使用。知识库引用上限按 token 控制，单段材料较长时可能被裁剪，需要结合问题样本核对引用内容是否完整。

历史输入会影响同一问题在空历史与带历史下的表现差异。使用固定回复格式承接结构化字段时，需要验证字段齐全与解析成功，仅检查文本长度不足以确认。语义检索与最低相关度只作用于召回与过滤，不承担权限或实体隔离；检索库与向量模型的关联要求限于知识库内部，不扩展到外部系统。

假设演练样本：材料原文为「2025 年 3 月佣金设置记录：某商品佣金比例为 12%，结算周期为确认收货后 15 日。」「2025 年 4 月退款扣佣明细：该商品 3 月订单发生退款 2 笔，对应佣金已扣回。」待判定拟稿句为「该商品佣金比例长期为 12%，退款不扣佣金。」判定要点：材料仅载明 3 月比例，未载明长期有效；退款扣佣明细显示已扣回，拟稿句与材料同字段取值相反，属未获支持。

## 配置怎么定

| 配置或核对项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AI 模型 | 选用上下文长度覆盖四类材料的模型 | 与材料总长度比较，确认单次请求可容纳 |
| 回复上限 | 假设设为中等长度 | 与拟稿句长度比较，确认不被提前截断 |
| 知识库引用上限 | 假设按 token 设为覆盖单段材料的量 | 与最长单段材料比较，核对是否被裁剪 |
| 记忆轮数 | 假设保留少量轮数 | 与空历史下的同一问题比较输入差异 |
| 回复格式 | 需要固定字段时选用 json_schema | 核对字段齐全与解析成功 |
| 最低相关度 | 假设保持默认 | 与召回结果比较，确认过滤后仍含目标材料 |

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。输入为四类材料与拟稿句，比较对象为模型最大上下文，观察结果为材料被截断或拟稿句依据缺失。
2. 把最低相关度当作权限或实体过滤。输入为同一问题与不同主体材料，比较对象为召回结果中的主体标识，观察结果为无关主体材料仍被召回。
3. 把材料中的单期数字写成长期承诺。输入为 3 月佣金设置记录与拟稿句，比较对象为期间与有效范围字段，观察结果为拟稿句超出材料载明范围。

## 怎么确认配好了

1. 输入假设样本中的两句材料原文与拟稿句，比较拟稿句的比例与扣佣表述同材料同字段取值，观察结果为拟稿句与退款扣佣明细取值相反，判定为未获支持。
2. 输入同一问题在空历史与带少量记忆轮数下的两次请求，比较两次输入内容差异，观察结果为历史未引入材料外的比例或期间信息。
3. 输入明确的纸面空结果 []，核对下游承接设计是否按空引用处理，观察结果为下游未把空引用当作已确认结论。
