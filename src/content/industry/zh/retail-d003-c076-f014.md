# 达人佣金结算与扣佣的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样
佣金结算发生在成交之后，核对重点落在有效推广订单、退款扣佣和开票付款。商品与营销文案起草要引用佣金设置记录、结算账单、退款扣佣明细和发票。文案里的比例、结算周期和扣佣条件，须与这些材料上的主体、期间和字段一致。达人合同与财务系统提供另一组口径，文案引用前要确认所指对象相同。

## 这些特征在「模型接入与配置」这一环带来什么约束
模型接入由 AI Proxy 承担。App 与 Admin 服务必须配置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项会启动校验失败。模型渠道、模型 ID、模型别名、最大上下文、最大回复、最大引用内容、最大温度等字段在模型配置中定义，应用与节点参数在编排侧设置，不能假设兼容对话接口的同名字段会覆盖编排。索引模型、重排模型、语音合成与语音识别各有类型。模型探测只覆盖已启用的系统模型，探测间隔支持 5 至 60 分钟整数，异常判定要求单轮四次尝试全部失败。检索与生成结果不承担权限或实体隔离，也不替代业务核对。

假设演练样本：某次佣金结算核对中，材料原文为“2026 年 3 月结算账单显示达人 A 的有效推广订单佣金为 8000 元”“同期退款扣佣明细记录退款订单对应扣佣 1200 元”“佣金设置记录中该商品佣金比例为 15%”。待判定拟稿句为“达人 A 在 2026 年 3 月按 15% 比例获得佣金 8000 元，退款不扣佣”。该句涉及主体达人 A、对象该商品、期间 2026 年 3 月、字段为佣金比例与扣佣状态，授权边界限于上述三份材料。

## 配置怎么定
| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填写 AI Proxy 根地址 | 文档要求不附加 /v1；与部署模板给出的服务地址比较 |
| AIPROXY_API_TOKEN | 假设填写非空管理员 Token | 文档要求与服务端一致；与 AI Proxy 侧配置值比较 |
| 模型渠道与模型 ID | 假设渠道名与模型 ID 按文案任务命名 | 文档要求模型 ID 全局唯一；与模型配置列表比较 |
| 最大引用内容 | 假设按所选语言模型字段填写 | 文档列为语言模型字段；与所选模型能力值比较 |
| 探测间隔 | 假设设为 30 分钟 | 文档允许 5 至 60 分钟整数；与允许区间比较 |
| 告警 Webhook 地址 | 假设暂不填写 | 文档列为可选；填写后与测试按钮结果比较 |

## 容易做错的三处
1. 把结算账单的佣金金额直接当作拟稿句的比例依据。输入为账单金额与拟稿句比例；比较账单字段与佣金设置记录字段；只有同主体、同期间、同字段取值一致才满足条件，否则记为未获支持。
2. 把退款扣佣明细中的扣佣记录当作退款不扣佣的依据。输入为扣佣明细与拟稿句“退款不扣佣”；比较扣佣状态字段；两者取值互斥时记为矛盾，字段未载明时记为待核实。
3. 把模型探测的绿色状态当作文案内容正确的依据。输入为探测状态与拟稿句；比较探测对象与文案对象；探测只说明模型可用性，不能说明文案引用材料是否成立。

## 怎么确认配好了
1. 输入上述三份材料原文与拟稿句，比较佣金比例字段与扣佣状态字段，预期结果为拟稿句在退款扣佣部分与材料不一致，应改写或标注待核实。
2. 输入 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 的假设填写值，比较是否缺少任一项，预期结果为两项均存在且 Token 非空时通过启动校验；缺项时记录缺口。
3. 输入假设探测间隔 30 分钟，比较是否落在 5 至 60 分钟整数区间，预期结果为区间内可保存；超出区间时记录为未通过。
