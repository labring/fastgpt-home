# 进出口许可证件办理的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

许可证件办理发生在申报之前，决定该批货物能否合法进出口，因此商品与营销文案起草不能只考虑表达效果。日常需要处理的文档包括自动进口许可证、两用物项许可证、合同和产品说明。产品说明与合同中的用途、型号、管制范围描述，直接决定文案里可以写什么、不可以写什么。这些材料按票准备，更新不定期，同一商品在不同票次的证件状态可能不同。

## 这些特征在「上下文与 token」这一环带来什么约束

上下文窗口按实际模型能力核对，回复上限是单次回答长度，两者不是同一个量。知识库引用上限按 token 计算，单段文本过长时，引用内容可能被裁剪，导致判断所依据的用途说明或管制范围句子没有进入上下文。历史轮数会把更早的对话带入请求，同一问题在空历史与带历史下的输入不同，结论可能不同。使用固定回复格式时，字段是否齐全、能否被后续节点解析，需要单独核对，文本长度合格不代表结构合格。

假设演练样本：材料原文为“本票货物为某型号工业泵，用途为一般工业循环水输送”“合同约定交货期为签署后六十日”“自动进口许可证申请处于待审核状态”。待判定拟稿句为“本产品已取得自动进口许可证，可立即安排出口”。该样本中主体、对象、状态均为纸面假设，不指向任何真实企业或证件编号。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AI 模型 | 选择弹窗中显示支持所需能力的模型 | 与弹窗显示的最大上下文和工具调用能力比较 |
| 记忆轮数 | 保留少量历史轮数 | 与空历史下的同一问题输入比较，确认是否引入无关旧内容 |
| 回复上限 | 打开并设为可容纳依据与处理动作的长度 | 与拟稿句加依据说明的实际长度比较 |
| 知识库引用上限 | 按 token 设置，覆盖用途说明与管制范围段落 | 与单段材料长度比较，确认关键句未被裁剪 |
| 回复格式 | 需要下游读取时选择 json_schema 并填写格式要求 | 与下游解析所需字段清单比较 |
| 最低相关度 | 按语义检索或结果重排生效时设置 | 与候选结果得分比较，观察低相关片段是否被过滤 |

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。输入是模型弹窗显示的最大上下文与已设回复上限，比较两者数值含义，观察是否把两者混为同一限制。
2. 把待审核状态写成已取得证件。输入是样本中“自动进口许可证申请处于待审核状态”，比较拟稿句“已取得自动进口许可证”，观察两者是否指向同一事实。
3. 引用上限过小导致用途说明被裁剪。输入是样本材料原文与所设 token 上限，比较进入上下文的文本，观察用途句是否完整出现。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较拟稿句中的证件状态表述与原文状态字段，只有两者同主体、同期间、同一字段且取值一致时，该句才获支持；原文为待审核时，拟稿句的“已取得”未获支持。
2. 输入同一问题分别在空历史与带少量历史下请求，比较两次实际进入上下文的内容，若带历史时引入了与本次商品无关的旧票信息，说明历史轮数需要调低。
3. 输入明确的纸面空结果 `[]` 与下游承接设计，比较下游在收到空引用时的输出，若下游仍生成肯定性文案，说明空结果分支需要补充处理；不得据此推断虚构规则一定返回空结果。
