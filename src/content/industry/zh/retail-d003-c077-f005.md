# 进出口许可证件办理的商品与营销文案起草：多轮对话与提示词

## 这个品类的数据长什么样

许可证办理发生在申报之前，决定货物能否合法进出口。商品与营销文案起草要处理的材料包括自动进口许可证、两用物项许可证、合同和产品说明，这些材料来自商务主管部门系统、海关商品编码、供应商资料和客户用途说明。每票业务的数据不定期更新，出错会导致无法通关、合同违约或行政处罚。文案起草环节依赖的原始材料通常只有上述几类，材料之外的宣传表述没有来源，模型无法自行补充。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

多轮对话中，历史记录会带入前文内容。继续会话时，接口用 messages 数组最后一个内容作为用户问题，其余 message 被忽略；不传 chatId 时不使用数据库上下文，完全由传入的 messages 构建。提示词需要写明资料范围、回答任务和缺证据时的处理方式。回复格式按后续承接选择，选择 json_schema 时需填写格式要求并核对返回结构。模型的最大上下文和回复上限决定长文档与追问组合能否完整处理。

假设演练样本。供核对的材料原文为：「本批货物为数控机床配件，持自动进口许可证，证号列于合同附件一，许可用途为自用生产。合同约定交货期为二〇二五年三月，产品说明标注原产地为德国。」待判定拟稿句为：「本产品已获进口许可，可长期稳定供货。」判定要点：材料只说明本批货物持证及合同交货期，未载明长期供货安排，拟稿句超出材料支持范围。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 记忆轮数 | 保留少量历史轮数 | 文案起草需前文材料，与不传 chatId 的纯 messages 模式比较带入内容差异 |
| 回复上限 | 按材料长度设定 | 与材料实际字符数比较，观察截断位置 |
| 温度 | 偏低 | 与偏高设置比较，观察是否引入材料外表述 |
| 回复格式 | 默认文本 | 与 json_schema 比较，后者需填格式要求并核对结构 |
| 多模态识别 | 按模型能力决定 | 核对弹窗显示的能力项，不支持时换模型 |
| 隐藏 AI 输出 | 保持关闭 | 与开启比较，观察最终回复是否仍可被后续节点读取 |

## 容易做错的三处

1. 把材料中仅涉及本批货物的许可表述扩展为长期供货承诺。输入是上述材料原文，比较对象是拟稿句中的「长期稳定供货」，观察结果是材料未载明该内容。
2. 继续会话时误以为全部 messages 都被使用。输入是带 chatId 的多条 messages，比较对象是接口实际采用的最后一条内容，观察结果是其余 message 被忽略。
3. 选择 json_schema 后未填写格式要求。输入是该选项及空格式要求，比较对象是返回结构，观察结果是无法按预期结构承接。

## 怎么确认配好了

1. 输入假设材料原文与拟稿句，比较拟稿句是否被材料支持，材料未载明长期供货时拟稿句不满足条件。
2. 输入带 chatId 的多条 messages，比较接口采用的用户问题，仅最后一条内容被采用时满足条件。
3. 输入 json_schema 选项及所填格式要求，比较返回结构，结构与格式要求一致时满足条件。以上均为纸面核对，未实际运行。
