# 进出口许可证件办理的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

许可证件办理发生在申报之前，决定该批货物能否合法进出口。这一环节的检索资料以自动进口许可证、两用物项许可证、合同与产品说明为主，来源包括商务主管部门系统、海关商品编码、供应商资料和客户用途说明。资料按每票业务更新，单票之间的商品描述、用途表述和证件状态差异明显。

对文案起草而言，这意味着检索命中只是取回候选原文，不能替代对证件状态的核对。商品说明中的用途描述、许可范围与合同条款分散在不同文档里，需要同一主体、同一期间、同一字段的原文才能比对。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的库，跨不同向量模型的库不可共同关联。检索时对整库执行，集合只作分类管理。语义检索依赖向量距离，全文检索依赖关键词命中，混合检索用 RRF 融合两路结果，结果重排用 ReRank 模型二次排序，得分区间为 0-1。最低相关度仅在语义检索或使用结果重排时生效，是过滤阈值，不承担权限或实体隔离。引用上限以 token 为单位，控制每次引用的内容长度。问题优化在检索前做指代消除与问题扩展，会增加一次模型调用。引用内容以数组输出，长度可以为 0，空结果链路仍走通。

假设演练样本：材料原文为「本票货物为某型号工业泵用密封件，用途为出口设备配套维修，自动进口许可证申请已提交，状态为待审核。」拟稿句为「该批密封件已取得自动进口许可证，可正常办理出口申报。」核对对象为同一票货物、同一期间、许可证状态字段。原文载明状态为待审核，拟稿句称已取得，两者在同一字段上取值互斥，拟稿句未获支持。此处不补造授权条款或生效日期。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方式 |
| --- | --- | --- |
| 关联的知识库 | 关联一个使用相同向量模型的许可证资料库 | 先核各库向量模型标识，排除不一致者，再比较检索结果 |
| 搜索模式 | 对编号类问题用全文检索，对用途描述用语义检索 | 按测试问题比较两路结果，不预设一种模式适合全部资料 |
| 引用上限 | 设为 1500 token | 作为本次试验起点，用长短不同的实际资料比较内容是否完整 |
| 最低相关度 | 设为 0.5 | 作为本次试验起点，先标注相关与无关样本，再比较过滤效果 |
| 问题优化 | 对多轮追问开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 在候选较多时启用 | 需具备重排模型，比较重排前后排序 |

## 容易做错的三处

1. 把待审核当作已取得。输入为上述拟稿句与材料原文，比较许可证状态字段，原文为待审核而拟稿句称已取得，属未获支持。检查方式为逐字段比对同一票货物、同一期间的原文取值。
2. 用相似度分数替代证件状态核对。输入为检索返回的引用内容与证件原文，比较两者是否载明许可范围，分数高不表示许可已生效。检查方式为查看引用原文是否包含状态字段。
3. 跨向量模型的库共同关联。输入为待关联的多个库，比较各库向量模型标识，标识不一致者应排除。检查方式为记录标识并排除不符者，不执行跨模型检索来比较漏召回。

## 怎么确认配好了

1. 输入拟稿句「该批密封件已取得自动进口许可证，可正常办理出口申报。」与材料原文，比较许可证状态字段，原文为待审核，拟稿句称已取得，判定为未获支持，需保留证据缺口。
2. 输入纸面空结果数组 []，核对下游链路对空引用的承接设计，确认引用长度为 0 时链路仍走通，不声称虚构规则检索一定返回 []。
3. 输入待关联的多个库标识，比较各库向量模型标识，标识一致者方可共同关联，不一致者排除并记录实际观察结果。
