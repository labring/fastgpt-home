# 连锁总部选址开店的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

选址开店阶段的核心材料是选址评估表、租赁意向书、装修预算和开业排期，这些文件在门店营业前形成，围绕租赁条件与工程交付展开。商品与营销文案起草要引用其中的商圈客流、店型、租金与交付节点等信息，文案中的每一句宣传性表述都需要在这些材料里找到对应依据。材料由连锁总部拓展、区域开发和工程经理分别维护，更新不定期且逐店发生，同一批文案请求可能同时涉及多个门店的不同版本材料。

## 这些特征在「上下文与 token」这一环带来什么约束

上下文窗口决定单次请求能带入多少材料内容，回复上限只约束输出长度，两者不能互相替代。知识库引用上限按 token 控制，选址材料中租赁条款段落往往较长，引用上限设置偏低时，租金、免租期等关键句可能被裁剪，文案失去依据。历史轮数会把前几轮的选址讨论一并带入，同一问题在空历史与带历史下的输入不同，核对时需要固定历史条件。使用 json_schema 等固定回复格式时，字段齐全与解析成功是独立检查项，文本长度合格不代表结构可用。

## 配置怎么定

以下配置围绕本页样本设定，数值为本次假设演练的起点，用于与对照值比较，不代表官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AI 模型 | 支持长上下文的模型 | 与租赁条款段落长度比较，确认单次请求可容纳样本原文 |
| 记忆轮数 | 0 轮 | 与带 3 轮历史的同问题输入比较，排除历史带入的差异 |
| 回复上限 | 打开并调至可容纳依据与动作的长度 | 与仅输出结论的短回复比较，确认依据句未被截断 |
| 引用上限 | 按 token 设定，覆盖样本原文全部段落 | 与偏小取值比较，观察租金句是否被裁剪 |
| 回复格式 | 默认文本 | 与 json_schema 比较，确认下游是否需要读取固定字段 |
| 温度 | 偏低 | 与偏高的取值比较，选址文案需要稳定复述材料事实 |

假设演练样本。材料原文为选址评估表摘录三句：某社区底商候选点，面积一百二十平方米，商圈客流以周边居民为主；租赁意向书写明月租金上限、免租期两个月，签署状态为待审核；装修预算列明基础工程与门头改造两项。待判定拟稿句为：该店开业即享成熟社区客流，租金条件已与房东达成一致。判定要点在于客流描述是否有材料支持、租金条款是否已签署生效，意向书处于待审核状态不构成已达成一致。

## 容易做错的三处

1. 把回复上限当作上下文窗口。输入是模型最大上下文数值与回复上限数值，比较两者是否被混为一谈，可观察到的结果是长材料被误判为可完整带入。
2. 引用上限设置偏小导致关键句被裁剪。输入是样本原文与引用上限 token 值，比较裁剪后内容是否仍含租金与免租期句，可观察到的结果是文案引用缺失依据。
3. 将待审核的意向书当作已生效合同。输入是材料中的签署状态字段与拟稿句，比较同一字段的取值，可观察到的结果是拟稿句声称租金已达成一致。

## 怎么确认配好了

1. 上下文容量核对。输入为样本原文三句与所选模型的最大上下文数值，比较原文 token 量与容量，满足条件是原文可完整带入且回复上限独立设置。
2. 引用裁剪核对。输入为样本原文与引用上限取值，比较裁剪后文本是否保留租金与免租期句，满足条件是关键依据句未被截断。
3. 拟稿句依据核对。输入为拟稿句与材料原文，比较客流描述与签署状态字段，满足条件是客流句有材料支持、租金句改为待审核状态表述。空结果承接可用纸面输入空数组核对下游设计，检索是否命中不作保证。
