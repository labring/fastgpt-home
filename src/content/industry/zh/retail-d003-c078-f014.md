# 连锁总部选址开店的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

选址开店发生在门店营业前，核心是租赁与工程交付，商品与营销文案要围绕尚未开业的门店展开。主要材料包括商圈客流、地图POI、POS历史店型、房东资料，日常文档为选址评估表、租赁意向书、装修预算、开业排期。这些材料的更新不定期、每店一次，文案起草只能依据当前已归档的那一版，不能假定存在批量同步或实时刷新。文案里出现的面积、租期、开业时间、经营品类，必须能在上述文档中找到对应字段；文档未载明的内容属于未获支持，需要保留待核实状态。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入要区分模型渠道、模型配置与应用侧参数三层。渠道负责协议类型、模型映射、代理地址与API密钥；模型配置负责模型ID、上下文与回复上限、是否支持图片输入与工具调用；应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。系统至少需要一个语言模型和一个索引模型才能正常使用。AI Proxy为必需依赖，App与复用服务端配置的Admin都必须设置AIPROXY_API_ENDPOINT和非空的AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。

假设演练样本：某连锁总部拓展部拟为一家尚未签约的社区店起草开业预热文案。供核对的材料原文为：选址评估表载明“该铺位建筑面积约120平方米，所在商圈为社区型”；租赁意向书载明“意向租期五年，租金条款待谈”；装修预算载明“工程预计45天，开工日期未定”。拟稿句为“本店已确认五年租期，预计三个月后开业”。待判定的是该拟稿句是否被上述材料支持。

## 配置怎么定

下表围绕样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值一栏中标注“假设起点”的，是本次纸面演练的比较基准，用于说明选择理由与比较对象，不代表官方默认值。

| 配置项 | 本页取值或核对对象 | 说明与比较方法 |
| --- | --- | --- |
| 模型类型 | 语言模型与索引模型 | 系统至少各需一个，核对是否均已启用 |
| 模型渠道 | 协议类型与模型映射 | 核对映射后的模型ID与请求体中的model字段是否一致 |
| 代理地址 | BaseUrl | 核对是否只填根地址，是否按需带/v1 |
| 应用参数 | 应用或节点内设置 | 核对参数是否在应用侧生效，未假定对话接口同名字段可覆盖 |
| 上下文与回复 | 假设起点maxContext与maxResponse | 依据样本材料长度选定，与材料实际字符数比较 |
| 图片输入 | 按样本是否含图片核对 | 材料为纯文本时无需图片能力，含图时须核对模型vision字段 |

## 容易做错的三处

1. 把意向书写成已生效合同。样本中租赁意向书只写“意向租期五年，租金条款待谈”，拟稿句却写“已确认五年租期”。意向书是意向，签署与生效是不同事实，核对时应比较材料中的状态词与拟稿句的确定性表述。
2. 把未定日期写成确定日期。装修预算写“开工日期未定”，拟稿句写“预计三个月后开业”。材料未载明开业时间，该表述属于未获支持，应记录证据缺口，不能补造工期条款。
3. 把模型测试通过当作业务授权。渠道测试与模型测试只说明模型可调用，不构成对文案内容的业务审核。核对时应区分模型可用性与文案事实支持，两者不可互相替代。

## 怎么确认配好了

1. 输入样本的三句材料原文与拟稿句，比较拟稿句中的“已确认五年租期”与意向书原文“意向租期五年，租金条款待谈”。同一字段出现互斥取值才构成矛盾；此处属未获支持，预期结果是标记为待核实并保留原文引用。
2. 输入装修预算原文“开工日期未定”与拟稿句“预计三个月后开业”，比较日期字段是否在材料中载明。材料未载明时，预期结果是该句不通过事实核对，检查记录应写明缺失字段为开业日期。
3. 输入渠道配置中的模型映射与请求体model字段，比较两者是否一致。若映射为gpt-4o-test而请求体为gpt-4o-test，上游实际model为gpt-4o，预期结果是映射关系可追溯。若测试返回错误，只记录错误信息与尝试次数，不推断具体失败原因。
