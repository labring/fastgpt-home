# 连锁统采统配的商品与营销文案起草：工作流编排

## 这个品类的数据长什么样

在连锁统采统配的商品与营销文案起草中，本页说明FastGPT的工作流编排如何衔接资料。统采统配服务文案要区分总部约定、门店请货和配送完成，不能从合同存在生成全网履约保证。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟总部合同写集中采购范围，门店请货单仍待确认，配送摘录只涉及其中某店。流程可收门店对象及资料性质，人员选择补请货确认或核配送范围，再交起草服务说明。总部约定说明安排，不证明每店实际供货；某店配送记录也不代表其他门店收到。这里不展示采购数量或效果，原文缺的覆盖范围应随输入保留。

## 配置怎么定

| 统采服务起草 | 自拟材料范围 | 承接检查 |
| --- | --- | --- |
| 总部合同 | 集中采购安排 | 不称各店已供 |
| 门店请货 | 仍待确认 | 另取本店回复 |
| 配送片段 | 仅某家门店 | 不扩全网络 |
| 输入对象 | 门店与原句同行 | 核实际接收 |
| 对外说明 | 只更新获证范围 | 不补全区承诺 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

合同冒履约：若集中采购约定变成全部已供，应取对应实际交付；单店扩全网：若配送片段用于所有门店，应核覆盖对象；请货冒确认：若待核申请被写成已接单，应查本店真实确认。三项分别核阶段、范围和需求状态，不能由同一总部名称代替。

## 怎么确认配好了

验收比较两个分支收到的门店与状态，补某店交付后只更新那家，不同时确认其他门店。若只补总部说明，不能改变待接单结论。采购下单、仓库发运与客户通知需另接业务流程核权限及回执，起草完成不证明统配链路已经执行，也不形成全区域供货或时效承诺。
