# 连锁统采统配的商品与营销文案起草：知识库检索与召回

## 这个品类的数据长什么样

连锁统采统配场景下，知识库检索服务于总部采购与配送链路，涉及集采合同、补货计划、配送单、门店要货单。这些资料的主体是供应商、配送中心与门店，字段包含商品名称、规格、数量、交货日期和有效范围。商品与营销文案起草需要从这些资料中召回可引用的原文，判断拟稿句是否有材料支持。

资料更新频率为日、周。检索配置按实际资料状态核对，不因更新频率改变搜索模式或引用上限。

## 这些特征在「知识库检索与召回」这一环带来什么约束

检索以整个库为最小搜索单位，集合仅作分类管理。知识库搜索节点可关联一个或多个使用相同向量模型的知识库。语义检索依赖向量距离，全文检索依赖关键词命中，混合检索通过 RRF 融合两路结果。最低相关度仅在语义检索或使用结果重排时生效。引用上限以 token 为单位。问题优化用于指代消除和问题扩展，会增加一次模型调用。

检索结果不承担权限或实体隔离功能。相似度得分不判断供应商身份或合同归属。召回内容是否可用，需要人工对照原文核对。

假设演练样本：

材料原文一：“供应商甲于2025年3月1日签署集采合同，合同编号JG-2025-031，约定商品A规格500克，供货有效期至2025年12月31日。”

材料原文二：“配送中心于2025年4月10日收到门店要货单，商品A数量200件，要求4月15日前送达。”

拟稿句：“商品A由供应商甲长期稳定供货，规格500克，可满足门店日常要货需求。”

判断所需主体为供应商甲，对象为商品A，状态为合同签署与供货有效期，有效范围为2025年3月1日至2025年12月31日。拟稿句中“长期稳定供货”在原文中没有对应表述，属于未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 关联一个含集采合同与配送单的库 | 该库使用同一向量模型；核对库标识是否一致 |
| 搜索模式 | 混合检索 | 拟稿句含商品名称与规格，语义与关键词均需覆盖；与单独语义检索结果比较 |
| 引用上限 | 800 tokens | 本次假设起点；与400、1200 tokens比较召回内容是否完整 |
| 最低相关度 | 0.35 | 本次假设起点；先标注相关与无关样本，再比较过滤后结果 |
| 问题优化 | 开启 | 拟稿句含指代；比较原问题与优化后问题的主体是否被改错 |
| 结果重排 | 启用 | 候选结果较多时二次排序；比较重排前后排序变化 |

## 容易做错的三处

1. 将最低相关度当作权限或实体过滤。输入：拟稿句与供应商甲合同。比较：召回内容是否包含其他供应商资料。观察：相关度得分只反映语义相似程度，不排除无关供应商记录。检查：核对召回结果中的供应商标识是否与拟稿句主体一致。
2. 将混合检索的 RRF 融合写成开启开关。输入：搜索模式选择混合检索。比较：配置界面是否存在 RRF 开关。观察：RRF 是融合过程，文档未列出独立开关。检查：核对配置项名称与文档参数表是否一致。
3. 将未载明的供货期限当作已确认事实。输入：拟稿句“长期稳定供货”。比较：材料原文是否载明“长期”或“稳定”。观察：原文仅载明有效期至2025年12月31日。检查：逐字段核对拟稿句与原文，记录未获支持的表述。

## 怎么确认配好了

1. 输入：假设演练样本中的材料原文一、材料原文二与拟稿句。比较：拟稿句“长期稳定供货”与原文中合同签署日期、有效期字段。观察：原文未出现“长期”或“稳定”表述，该拟稿句属于未获支持。若原文补充载明“长期”且与合同有效期一致，则满足支持条件。
2. 输入：同一拟稿句，搜索模式分别设为语义检索与混合检索。比较：两次召回结果中是否包含材料原文一。观察：混合检索同时使用语义与全文召回，可能召回不同结果。若两种模式均未召回材料原文一，记录为未命中，不判定为资料不存在。
3. 输入：引用上限设为800 tokens，使用材料原文一与材料原文二。比较：召回内容是否完整包含合同编号、规格与要货数量。观察：若引用内容被截断，缺少关键字段，则调整上限后重新比较。空结果场景可用纸面输入[]核对下游设计，不声称检索一定返回[]。

跨不同向量模型的库不可共同关联，先核对库标识并排除不符合者。图片检索须有图像输入及模型能力，重排须具备模型且按设置启用。检索不执行授权判断，业务审批与数据库写入需另接系统实现。
