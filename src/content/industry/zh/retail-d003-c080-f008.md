# 连锁门店价格与陈列稽核的商品与营销文案起草：工作流编排

## 这个品类的数据长什么样

在连锁门店价格与陈列稽核的商品与营销文案起草中，本页说明FastGPT的工作流编排如何衔接资料。门店陈列整改说明要区分检查照片、整改通知和复查结论，换过标签不证明整店已经符合要求。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟巡查文字说货架标签待更新，整改通知要求核对，照片却仍是旧陈列。流程可收门店、照片来源和通知原句，人员选择补更新后的材料或核复查结论。这里只写状态说明，不填价格和标准值；通知说明要做什么，旧照片说明拍摄时看到什么，两者都不能证明整改现状。标签清单存在也不说明每处已经更换。

## 配置怎么定

| 整改说明起草 | 自拟材料性质 | 本次核对 |
| --- | --- | --- |
| 巡查文字 | 标签待更新 | 保留待办状态 |
| 整改通知 | 要求核对 | 非完成凭据 |
| 照片来源 | 仍属旧陈列 | 补更新材料 |
| 覆盖范围 | 局部不能扩整店 | 取真实复查 |
| 输入去向 | 补材料或核结果 | 门店对象保持一致 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

通知冒完成：若要求核对被写成已整改，应取实际复查；旧图冒现况：若旧陈列图说明当前状态，应核来源时点与更新材料；单处扩整店：若局部标签变动被写成全店通过，应查覆盖范围。三项分别检查动作阶段、图像来源及结论范围，不能由流程输出填补。

## 怎么确认配好了

验收查看两条分支收到的门店对象与待补项，补新照片后只更新它所见的陈列，不顺带判定整店完成。若没有复查结论，成稿仍需保留待核。现场整改、价格维护和对外发布需另接业务流程核权限及记录，节点继续只说明处理路径运行，不证明门店现况或稽核结果，也不提供经营效果承诺。
