# 连锁门店闭店清算的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

闭店清算处理退出与资产回收，方向与总部选址开店相反。主要数据来自 POS 库存、固定资产系统、租赁合同和财务账，典型文档包括闭店审批、库存清退单、租约解除协议和资产盘点表。起草商品与营销文案时，上下文窗口需要同时容纳门店状态、资产归属、租约期限和结算口径，这些字段分散在不同系统，长度差异大。数据不定期更新，每店一次，因此同一批材料可能来自不同日期，文案中的数量、范围和时间必须与对应材料逐项对照。上下文与 token 的核心约束在于：模型单次请求可参考的内容长度有限，回复上限控制输出长度，引用上限按 token 控制知识库引用，三者作用不同，不能互相替代。

## 这些特征在「上下文与 token」这一环带来什么约束

模型上下文按实际模型能力核对，回复上限不等于完整上下文窗口。闭店清算材料常包含长表格和合同条款，若引用上限设置过低，关键条款可能被裁剪，导致文案遗漏资产范围或结算条件。知识库引用上限以 token 为单位，需结合单段长度与问题样本核对内容是否完整。历史输入会影响检索结果，相同问题在空历史和带历史下可能召回不同内容，需分别核对。使用固定回复格式时，应验证字段齐全和解析成功，不能仅检查文本长度。语义召回和相关度不负责权限或实体隔离，检索库同向量模型要求不能扩展为外部系统也要同模型。RRF 是混合结果融合过程，不是开关。思考预算属于思考配置，不可移作引用 token 上限。

## 配置怎么定

以下配置围绕假设演练样本设定，数值为本次假设试验起点，非官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AI 模型 | 选择弹窗中显示支持所需上下文长度的模型 | 比较模型最大上下文与材料总长度，确认材料不被截断 |
| 回复上限 | 打开并设为覆盖文案正文与依据字段的长度 | 比较输出是否被提前截断，与材料完整表达所需长度对照 |
| 引用上限 | 按 token 设定，覆盖单段材料长度 | 比较引用内容是否包含主体、对象、状态和有效范围 |
| 最低相关度 | 保持默认，仅语义检索或重排时生效 | 比较过滤后结果是否仍包含判断所需材料 |
| 问题优化 | 短问题或多轮追问时开启 | 比较开启前后检索词是否补全主体与对象 |
| 回复格式 | 普通文案保持默认 | 仅当后续流程需读取固定字段时才改用结构化格式 |

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。回复上限控制输出长度，模型上下文按实际模型能力核对，两者作用不同。若仅调大回复上限，输入材料仍可能被截断，导致文案遗漏资产范围。检查时输入完整材料，比较输出是否包含材料中的主体、对象和状态。
2. 把引用上限与思考预算混用。引用上限以 token 控制知识库引用，思考预算属于思考配置，两者不可互换。检查时分别核对引用内容是否完整、思考强度是否与问题复杂度匹配。
3. 把语义召回当作权限或实体隔离。相关度分数不排除无关业务或未授权记录，检索不等于授权。检查时输入同一问题，比较召回结果是否包含不属于本店的材料，记录实际观察，不推断运行结果。

假设演练样本：材料原文为「甲门店于 2025 年 3 月 1 日提交闭店审批，审批状态为待审核。该店租约解除协议尚未签署，库存清退单载明剩余货架 12 组、收银机 3 台。」待判定拟稿句为「甲门店已完成闭店审批，租约已解除，剩余资产 12 组货架和 3 台收银机可对外处置。」核对时比较拟稿句与材料：审批状态为待审核，不构成已完成；租约解除协议尚未签署，不构成已解除；资产数量与材料一致。拟稿句在审批状态和租约状态上未获支持，需保留证据缺口。

## 怎么确认配好了

1. 输入上述假设材料原文与拟稿句，比较拟稿句中的审批状态、租约状态和资产数量是否与材料逐项对应。只有审批状态、租约状态和资产数量均与材料一致时，才满足条件；待审核和未签署应保留为待核实。
2. 输入同一问题分别在空历史和带历史下检索，比较两次召回内容是否包含判断所需的主体、对象和状态。只有两次均包含完整字段时，才满足条件；缺失时记录缺口，不推断原因。
3. 输入明确的纸面空结果 []，核对下游设计是否处理空引用。只有下游对空结果有明确承接时，才满足条件；不声称虚构规则检索一定返回 []。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察。
