# 连锁门店闭店清算的商品与营销文案起草：工作流编排

## 这个品类的数据长什么样

在连锁门店闭店清算的商品与营销文案起草中，本页说明FastGPT的工作流编排如何衔接资料。闭店通知起草要分开批准、清点和租赁终止，获准闭店不证明库存及资产已经处理完。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟材料已有闭店批准原句，库存清理单标待复核，租赁终止文件仍为草稿。流程可收门店与各项状态，让人员选择补库存依据或核对外通知口径。批准只说明决策，不证明实际停业、租约终止或资产移交；资产清点表若属于另一门店，也不能补本店缺项。文案不填写日期承诺或金额，未证实事项随输入保留。

## 配置怎么定

| 闭店通知起草 | 本题自拟状态 | 对应依据 |
| --- | --- | --- |
| 闭店批准 | 已有决定 | 非实际停业 |
| 库存清理 | 仍待复核 | 实际处理记录 |
| 租赁终止 | 草稿 | 不称已经生效 |
| 资产清点 | 排除另一门店 | 核源对象 |
| 成稿边界 | 缺项随状态保留 | 不推全部结束 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

批准冒执行：若闭店决定变成全部清理完成，应取对应处理记录；草稿冒解约：若拟议终止被写成已生效，应查真实确认；资产串店：若他店清点用于本店，应核源对象与接收文本。三项分别检查决策与执行、文件性质和对象，不能因同一连锁品牌而合并。

## 怎么确认配好了

验收沿补库存与核通知路径比较门店对象，补本店清理依据后只改相应状态，租赁仍为草稿时仍留待核。对外通知不能从缺的执行材料推定所有事项结束。正式停业、资产交接和合同处理需另接业务步骤核权限及回执，成稿不证明门店已经关闭，也不构成债务清偿或租赁法律效果结论。
