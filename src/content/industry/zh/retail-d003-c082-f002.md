# 逆向退货入仓质检的商品与营销文案起草：上下文与 token

## 这个品类的数据长什么样

退货入仓质检处理逆向包裹与商品等级，数据来源包括 WMS 退货模块、平台售后、承运商退件与质检台，日常文档为退货入库单、质检照片、等级判定表与重售上架单。起草重售商品文案时，文案依据来自这些材料中已记录的等级与状态，材料未载明的性能、成色细节或授权范围属于未知。上下文与 token 环节的关键在于：模型单次请求可参考的内容长度有限，退货单据、照片描述与等级判定表组合后容易超出可容纳范围，需要按任务裁剪。

## 这些特征在「上下文与 token」这一环带来什么约束

引用上限按 token 控制，不按条数控制；单段材料过长时，后续内容可能被裁剪。最低相关度仅在语义检索或结果重排时生效，属于过滤阈值，不承担实体或权限隔离功能。语义召回与相关度得分不区分商品、单据或授权范围，检索结果需要人工核对主体与期间。问题优化在检索前增加一次模型调用，连续追问场景可补全指代，响应耗时相应增加。回复上限控制单次回答长度，与模型上下文窗口不是同一概念，不能把回复上限当作完整上下文容量。

假设演练样本：某售后仓质检员在 2025 年 6 月 3 日处理退货入库单 TH-20250603-018，商品为一台便携榨汁机，等级判定表记录状态为“外壳轻微划痕，功能测试正常，可重售”，质检照片显示杯体与刀座完整。拟稿句为：“该商品为全新未使用，功能完好，支持七天无理由退换。”待判定：拟稿句中“全新未使用”与材料记录的状态是否一致，“支持七天无理由退换”在材料中是否有对应依据。

## 配置怎么定

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 引用上限 | 假设设为 2000 tokens | 与退货入库单、等级判定表、照片描述合计长度比较，观察材料是否被裁剪 |
| 最低相关度 | 假设设为 0.3 | 与语义检索返回的得分分布比较，观察低相关片段是否仍进入引用 |
| 回复上限 | 假设设为 600 tokens | 与拟稿句加依据说明的预期长度比较，观察回答是否被提前截断 |
| 记忆轮数 | 假设设为 2 轮 | 与单次独立起草场景比较，观察历史对话是否带入无关内容 |
| 问题优化 | 假设开启 | 与关闭时同一问题的检索结果比较，观察指代补全是否改变召回内容 |
| 回复格式 | 假设保持默认 | 与需要固定字段承接的场景比较，观察字段是否齐全 |

## 容易做错的三处

1. 把最低相关度当作权限或实体过滤器。错误表现：认为调高相关度即可排除其他商品或未授权单据。可执行检查：输入同一问题，比较不同相关度设置下返回内容的主体与单据编号，观察是否仍混入其他商品记录。
2. 把回复上限当作完整上下文窗口。错误表现：材料总长超出模型上下文时，仅调高回复上限。可执行检查：统计材料 token 总量与模型上下文数值，比较两者大小，观察超出部分是否未被送入模型。
3. 用未载明的宣传句替代材料记录。错误表现：拟稿句写入“全新未使用”而等级判定表仅记录“可重售”。可执行检查：逐句对照拟稿句与材料原文，比较主体、状态字段取值，观察是否存在材料未载明的表述。

## 怎么确认配好了

- 验证一：输入假设样本中的等级判定表原文与拟稿句，比较“外壳轻微划痕，功能测试正常，可重售”与“全新未使用”，观察输出是否指出该表述未获材料支持。若输出直接采纳拟稿句，判定为未通过。

- 验证二：输入退货入库单 TH-20250603-018 与问题“该商品能否重售”，比较引用内容是否包含等级判定表的状态字段，观察引用上限设置下状态字段是否完整保留。若状态字段被裁剪，判定为需调整引用上限。

- 验证三：以纸面输入空结果 `[]` 核对下游承接设计，比较下游节点对空引用的处理路径，观察是否出现无依据的文案生成。若下游在空引用时仍输出宣传句，判定为承接设计缺口。以上均为纸面核对，未实际执行。
