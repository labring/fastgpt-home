# 门店盘点与防损的商品与营销文案起草：模型接入与配置

## 这个品类的数据长什么样

在门店盘点与防损的商品与营销文案起草中，本页说明FastGPT的模型接入与配置如何衔接资料。盘点说明草稿保留账面差异与调查阶段，模型接通不能替代报损审批。所用场景为自拟文字测试。

## 这些特征在「模型接入与配置」这一环带来什么约束

假设盘点表写“货架实盘待复点”，差异分析便笺怀疑漏扫，报损申请尚未签批。给防损部起草说明时，应先核模型实际收到的表格文本、分析作者与审批状态，不能将怀疑原因写成调查结论。此练习没有监控视频或实际库存数据，也没有确认责任人。文案只可呈现现有差异和待补证据，服务返回正常不能证明盘点、归因或审批已经完成。

## 配置怎么定

| 盘点文案测试 | 假设材料 | 检查动作 |
| --- | --- | --- |
| 数量来源 | 实盘待复点 | 不填差额 |
| 原因 | 漏扫怀疑便笺 | 核作者与措辞 |
| 审批 | 本轮申请未签 | 不称已核销 |
| 轮次 | 旧批复另放 | 核门店与盘点对象 |
| 输入形式 | 文字及扫描分测 | 保留实际请求 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `AI Proxy依赖` | 按实际版本核服务、渠道与应用。 |
| `AIPROXY_API_ENDPOINT` | 使用AI Proxy服务根地址。 |
| `AIPROXY_API_TOKEN` | 管理员Token非空且与服务端一致。 |
| `模型能力` | 按实际输入路径验证所需能力。 |
| `应用参数` | 接口同名字段未必覆盖应用设置。 |

## 容易做错的三处

- 仅盘点表进入请求，分析便笺未送达却出现漏扫定论时，核实际请求和引用句，定位缺材料还是补造原因。

- 模型将库管怀疑写成财务已确认时，对照便笺作者、原动词和审核意见，不由角色名称补出认可。

- 上一轮已批报损单支持本轮核销时，核门店、盘点轮次及签批对象，旧批复不能自动覆盖新差异。

## 怎么确认配好了

可先只传盘点表，再加分析便笺和本轮审批记录，重复问当前状态与可对外表述的原因。保存真实输入和输出，用原文核新增内容。扫描表或监控画面另测实际读取路径；文字模型连通不能证明图片、视频可读。模型服务凭证不授予财务审批或库存写回权限，草稿采用前仍由负责人员核签批及传播范围。
