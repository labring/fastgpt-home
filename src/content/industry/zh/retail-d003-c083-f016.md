# 门店盘点与防损的商品与营销文案起草：表单与交互

## 这个品类的数据长什么样

在门店盘点与防损的商品与营销文案起草中，本页说明FastGPT的表单与交互如何衔接资料。盘点防损文案按观察、差异与原因证据写作，表单不能把盘差自动认定为损失或责任。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

假设便签只说账物待核，初盘清单未复核，现场照片来自另一日期。表单收门店、盘点事项及资料版本，人员选择补复盘或核图片，再传下游写作。节点收信息并记录交互，不自带账本或原因判定；缺门店与补齐都应测。本例不编损失金额或人员责任。

## 配置怎么定

| 盘点文案表单 | 自拟材料 | 核验动作 |
| --- | --- | --- |
| 账物待核 | 结论未定 | 非确认损失 |
| 初盘清单 | 复核尚缺 | 保留标记 |
| 差异原因 | 未给因果证据 | 不推盗损 |
| 现场照片 | 另一日期 | 核时间对象 |
| 正式处理 | 授权流程另核 | 事实及回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

账物待核被写确认损失时，查真实复核；盘差被写盗损原因时，核因果证据；旧日期照片套本次时，对时间及对象。三处分别看结论阶段、原因与资料归属，文字完整不证明差异已解释。

## 怎么确认配好了

验收拟写句子逐一追原便签，清单保留初盘标记，照片旁列可核日期。补复核只改对应差异，原因仍另核，不能顺带写成已追责。正式调整库存、认定损失及处理责任由授权业务流程、事实与回执决定，表单用于汇集素材，不作财务或人员判断。 初盘清单与复核依据单独索引，照片日期按可核材料保留；拟写句子如涉及损失或原因，复核人员应能指出其事实来源以及当前仍缺的证明。
