# B2B平台撮合交易的合同与交易材料比对：引用来源与溯源

## 这个品类的数据长什么样

在B2B平台撮合交易的合同与交易材料比对中，本页说明FastGPT的引用来源与溯源如何衔接资料。采购正文提及的样品附件、后续讨论和本次确认有各自身份。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

B2B交易比对可拟采购正文“外观参照附件样品”、样品页“拉丝表面，仅供讨论”和邮件“已收到本轮附件”。买方询问是否已确认拉丝供货时，需要先知道正文引用的是哪份样品及其版本。样品的讨论用途仍在原文中，收到附件也只说明收件动作。这几份文字能用于列出当前讨论对象，尚不能证明双方已选定该表面，更不能补出当前批次的供货承诺。

## 配置怎么定

| 交易来源核对项 | 材料与行动范围 | 验收动作 |
| --- | --- | --- |
| 附件对应 | 正文未单独确定样品版本 | 核引用与交付记录。 |
| 样品用途 | 仅供讨论 | 保留限制原句。 |
| 规格状态 | 拉丝尚无本次确认 | 找对象一致的确认。 |
| 邮件行动 | 收件不是承接 | 核回复及对象。 |
| 引用内容 | 正文不替代附件 | 查看实际引用文字。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是把同名旧样品当正文所指附件，应核正文引用、附件身份及本轮交付记录，名称相同不证明版本相同。第二处是删去仅供讨论后，把外观样品写成已确认规格，应检查双方针对本次对象的确认文字。第三处是将邮件收件写成接受供货，应读出回复动作及其对象，另取供货确认。三项分别查附件对应、规格状态和交易行动，不以一个引用标记同时证明全部结论。

## 怎么确认配好了

验收可依次问正文指向什么、样品可说明什么、邮件实际确认了什么，逐句展开答案所用的引用内容。若实际引用数组只含正文而未含样品，回答需保留附件身份及讨论状态未核，不能让流畅摘要代填。后来补入确认时，重新核其适用商品、表面和批次。空引用要继续追查检索范围与传递，不由无返回认定不存在附件，也不把读到讨论当作供货已经履行。
