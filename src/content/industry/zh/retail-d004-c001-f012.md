# B2B平台撮合交易的合同与交易材料比对：文档解析与分块

## 这个品类的数据长什么样

在B2B平台撮合交易的合同与交易材料比对中，本页说明FastGPT的文档解析与分块如何衔接资料。交货范围、变更条件和仓库角色在解析后是否仍能对应？所用场景为自拟文字测试。

## 这些特征在「文档解析与分块」这一环带来什么约束

拟议合同文字写着交货仅限约定仓库，下一段说明变更收货点需要另行确认。解析检查应从这两段原文开始，分别记录范围和变更条件在输出中的位置，再检查分块后是否仍能找到它们的关系。若只拿到仓库名称，回答就缺少变更条件的依据。可以用原条款中的词句和一条询问变更收货点的自然问题复测，比较引用究竟保留了哪段文字；这些是提出的检查步骤，没有预设解析结果。

## 配置怎么定

| 核对项 | 本页文字测试 | 保留的证据 |
| --- | --- | --- |
| 原始资料核对 | 交货范围与变更收货点条件 | 完整合同中两段的位置 |
| 分段完整性 | 仓名与发货、收货角色不拆散 | 解析前后的字段关系 |
| 数据与索引 | 原文有角色而候选没有时追查映射 | 原数据、索引及命中片段 |
| 样本检索 | 原条款词句与变更地点自然问题对照 | 两种问法返回的条件文字 |
| 更新后复核 | 新增验收条款后核训练或索引状态 | 同一问题能否回查新增依据 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `原始资料核对` | 对照原文件与解析输出。 |
| `分段完整性` | 条件需与其主体保持可关联。 |
| `数据与索引` | 原数据与索引分别保留依据。 |
| `样本检索` | 用原文词句及自然问题复测。 |
| `更新后复核` | 更新后核训练或索引状态。 |

## 容易做错的三处

- 仓库名与变更收货点需确认的条件拆离时，对照原段、解析输出和块，核地点与限制还能否关联。

- 报价发货仓与合同收货仓被写成条款冲突时，核字段角色，不能只因两个仓名不同判矛盾。

- 原文没有验收方式却得到具体验收条款时，先核完整原件；原件已有而解析遗漏才是处理缺失，不能由分块自行补业务依据。

## 怎么确认配好了

合同未提供验收方式时，解析不能产生这项业务依据。先查看完整原文：确无条款就列入待补资料；原文已有却未出现在解析输出中，才保留失败片段并检查处理路径。补充文字后还需核训练或索引状态，用相同的验收问题再次回查新增条款。文件上传、解析完成和问题能够检索到对应依据，是三个不同的验收对象，各自需要记录实际输入与输出。
