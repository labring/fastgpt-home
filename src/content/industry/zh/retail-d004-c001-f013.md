# B2B平台撮合交易的合同与交易材料比对：权限与数据隔离

## 这个品类的数据长什么样

在B2B平台撮合交易的合同与交易材料比对中，本页说明FastGPT的权限与数据隔离如何衔接资料。分别验证企业资料、询报价和合同的访问范围，不把业务身份认证当作全部资源授权。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

B2B交易材料比对可涉及企业认证资料、询报价和电子合同。应先确认每份资料对应的实际资源，再核当前成员的读取范围。企业身份说明与账号授权是不同依据：认证资料中出现供应商主体，不说明该供应商账号已加入团队或获准阅读所有合同。若一个必需来源不可读，本轮就无法完成相应比对，应先排查资源权限及材料是否已经提供。

## 配置怎么定

| 权限或实施核对项 | B2B比对所用资料 | 实际验收 |
| --- | --- | --- |
| 资源身份 | 认证资料、询报价、电子合同 | 每份原文单独核读取范围 |
| 业务主体 | 供应商名称与团队成员分开 | 不从身份资料推定资源授权 |
| 分类与权限 | 同类或同库不表示同权 | 使用两类账号核真实可见内容 |
| 外部凭证 | 支付与物流来源另行授权 | 内部角色不替代接口鉴权 |
| 变更后复测 | 补资料与授权变化分开记录 | 保留仍缺凭证和访问结果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 认证资料出现供应商便认为账号已加入团队：核真实成员与合同资源，业务主体文字不建立系统授权，缺映射仍待确认。

- 合同同分类便让无权身份可读：用应获权与不获权账号读取同一原文，保留实际结果及操作，不由标签或概括能力证明隔离。

- 物流或支付系统凭证被内部角色代替：独立核外部鉴权与返回，内部能读合同不说明取得这些来源，缺证明仍不能完成相应比对。

## 怎么确认配好了

若比对需要物流或支付系统的凭证，外部鉴权需单独核对，内部团队角色不能自动授予对应数据。补充新来源后，再测试两类身份可见哪些内容，以及原有授权变化是否按方案生效。尚缺的业务证明应继续保留待核状态。验收分别登记资源访问、引用原文和材料适用范围，模型能够概括合同不能替代权限测试，也不能填补未取得的凭证。
