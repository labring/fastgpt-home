# MCN机构达人管理的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在MCN机构达人管理的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。活动回顾片段与完整素材再使用，需要保留不同授权对象。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

MCN合同比对自拟条款“剪辑片段仅用于本次活动回顾；完整素材再使用需另行确认”，另有沟通记录“按上次常规版处理”。问能否长期复用完整视频时，输入必须同时保留片段、完整素材、本次回顾与另行确认，不能只留下可使用几个字。常规版在本组没有附件定义，既不能凭历史指代补出授权，也不能将片段用途扩大到完整素材。需要先列出待核的版本与对象。

## 配置怎么定

| 上下文核对对象 | 具体文字条件 | 验收线索 |
| --- | --- | --- |
| 素材主体 | 剪辑片段与完整素材分开 | 核两类主语均进入输入。 |
| 用途限定 | 仅本次活动回顾 | 核裁剪是否丢限定。 |
| 历史指代 | 上次常规版无正文 | 列版本待核项。 |
| 同题对照 | 空历史与旧项目沟通 | 定位旧用法是否替换本次条件。 |
| 输出承接 | 对象、用途、待确认事项 | 核字段完整及实际解析。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

一种失败条件是知识片段裁去后半句，回答把回顾用途扩成完整视频可长期使用；另一种是历史里出现过去项目的用法，当前提问沿用它而没有核本次条款。应保存实际输入中两类素材的主语、当前条款及历史指代，分别定位条件被剪掉还是对象被替换。模型可接收多少上下文按实际能力核，不用回复长度推算；增加文字额度也不能替代缺少的常规版附件。

## 怎么确认配好了

验收用同一个复用问题分别在空历史和带历史下比较，核当前输入是否仍完整包含用途限定与另行确认。输出可按素材对象、已见用途、待确认事项整理，检查片段和完整素材有没有被混为一项；若下游使用固定格式，再核这些项是否齐全且能够解析。回复应保留缺附件这一处理动作，不能为缩短答案删去限定，更不能将拟议用途写成已经取得的实际授权。
