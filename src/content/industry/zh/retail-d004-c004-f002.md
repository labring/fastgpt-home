# Temu半托管卖家运营的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在Temu半托管卖家运营的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。透明外袋已更换，不能覆盖另需核对的接触内包装。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

自拟Temu交易条款写“外袋使用透明袋；接触内包装另需核对”，作业备注写“透明袋已更换”。比较包装事项是否都已处理时，输入要保留外袋与接触内包装的对象差异。更换备注没有提到内包装，不能从透明袋已换推出内包装已确认；另需核对也不是不合格结论。模型需要读到动作属于哪层包装，不能只用包装二字概括这组材料。

## 配置怎么定

| 上下文核对对象 | 具体文字条件 | 验收线索 |
| --- | --- | --- |
| 包装层级 | 外袋与接触内包装 | 核主语不被合并。 |
| 已见动作 | 仅透明袋已更换 | 核动作指向哪层。 |
| 边界条件 | 内包装另需核对 | 对照引用尾句。 |
| 历史适用 | 旧讨论是否针对本批 | 核批次及确认文字。 |
| 核查输出 | 层级、动作、缺项 | 验证对应关系和解析。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

一种失败是长段引用裁去接触内包装那句，只剩外袋要求和更换动作；另一种是历史曾讨论内包装，当前回答把那次讨论当成本次确认。前者核实际传入片段的尾部条件，后者核历史讨论是否明确指向同一批次及确认结果。两条路径都应保留原输入作对照。模型上下文按实际能力核验，引用token限制则看具体文字是否留全，不用更长回复掩盖输入缺口。第三处是输出承接时把外袋已更换填到内包装状态。应检查实际解析后的层级和动作配对，逐项对照原备注；本次输入保留两层包装，也仍可能在输出字段中发生串位。

## 怎么确认配好了

验收将外袋要求、更换动作、内包装待核三个对象分别列出，并用相同问题比较空历史与带历史的结果。若历史没有本批确认，输出仍需保留内包装待核，不应补写合格、已确认或无需检查。固定格式如供后续核查使用，应检查包装层级与动作是否对应、缺项是否可解析。需要补证的是内包装核查材料，不能仅重复输入同一条外袋备注来增加表面依据。
