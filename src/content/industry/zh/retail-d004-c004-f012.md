# Temu半托管卖家运营的合同与交易材料比对：文档解析与分块

## 这个品类的数据长什么样

在Temu半托管卖家运营的合同与交易材料比对中，本页说明FastGPT的文档解析与分块如何衔接资料。拍摄范围与配件列示说明应保持各自所属标题。所用场景为自拟文字测试。

## 这些特征在「文档解析与分块」这一环带来什么约束

Temu交易资料自拟两级标题：“拍摄范围”下写仅拍主体正面，“清单说明”下写配件另列，不以照片判断。若解析把标题去掉后连续拼接，配件另列可能被误读为拍摄还包括配件，或主体照片被当作全部交付物证明。分段前应先比对原文标题、段落归属与解析文字，明确两个条目分别约束拍摄动作和清单阅读，不用文件总体主题代替局部关系。

## 配置怎么定

| 原文或分块核对项 | 具体材料关系 | 取证动作 |
| --- | --- | --- |
| 标题归属 | 拍摄范围与清单说明 | 对照原文及解析段落。 |
| 动作对象 | 拍主体与读清单不同 | 核主语没有串接。 |
| 分块条件 | 不以照片判断 | 核限制随清单条目。 |
| 检索对象 | 原词及包含物问题 | 对照返回块能支持什么。 |
| 补清单更新 | 实际清单与旧照片块 | 核处理、索引及引用版本。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `原始资料核对` | 对照原文件与解析输出。 |
| `分段完整性` | 条件需与其主体保持可关联。 |
| `数据与索引` | 原数据与索引分别保留依据。 |
| `样本检索` | 用原文词句及自然问题复测。 |
| `更新后复核` | 更新后核训练或索引状态。 |

## 容易做错的三处

常见错误是把仅拍主体正面拆成独立短句，却留下没有标题的配件另列；另一种失败是将清单说明并入照片描述，回答据照片断言配件随附。应查每块的主语与标题是否仍可追溯，分清解析阶段错归属和切块阶段拆条件。原数据与索引也分别核，搜索入口含配件不表示原块已提供配件清单。不能通过多建入口补出原文未列的交付范围。

## 怎么确认配好了

验收分别用主体正面、配件另列原词和“照片是否代表全部包含物”的自然问题检索，对照返回块中的标题与限制。回答应保持拍摄与交付清单两个阅读目标。若补入实际清单，再核它的文档身份、训练与索引状态，复用原问题检查新片段；上传成功不能当作清单已经进入结果。保留每次原文与解析对照，避免更新后标题关系修好，却仍引用旧块作结论。
