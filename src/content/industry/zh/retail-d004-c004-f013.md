# Temu半托管卖家运营的合同与交易材料比对：权限与数据隔离

## 这个品类的数据长什么样

在Temu半托管卖家运营的合同与交易材料比对中，本页说明FastGPT的权限与数据隔离如何衔接资料。将商品申报、海外库存和采购测算按使用主体核权，保留平台与仓库来源的不同范围。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

比对练习可自拟商品申报附页、海外库存表与采购测算，运营拟核申报，境外仓拟核对应库存，供货方仅拟看自身商品说明。先用真实账号逐资源验证，不把同一商品视为全材料共享依据。若仓库身份能读采购内部条件，应保存实际返回及授权配置排查。平台资料与仓库资料可能关联同一商品，但这项对应不证明任一协作者应拥有全部读取或修改权。

## 配置怎么定

| 权限核对项 | 半托管协作资料 | 实际证据 |
| --- | --- | --- |
| 任务来源 | 申报、库存及测算分开 | 账号逐资源读与操作 |
| 仓库边界 | 对应仓与无关仓区分 | 内部条件完整返回 |
| 成员映射 | 仓库及供货主体只是称谓 | 责任人确认账号范围 |
| 外部身份 | 平台、WMS和物流分别核 | 不从单接口推全获权 |
| 内容归属 | 错仓数量另查期间对象 | 权限与库存执行分开 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 库存表仓名或申报供货主体被当作成员：核真实账号及允许操作，业务对应不自动赋权，缺映射由责任人补确认。

- 仓库身份读到内部采购测算：保留完整返回及授权设置查范围，同一商品关联不说明全部材料应共享。

- 平台或WMS接口可读被当成全员获权：独立核外部身份和内部资源，读取正常也不能证明库存可售或申报已接受，业务状态需实际结果。

## 怎么确认配好了

验收用运营、对应仓库、供货方和无关仓库身份询问同一商品，记录各自原文、操作及拒绝。受限测算被转述到答案中，应检查完整返回，不只看附件列示。若权限符合预期但答案取了另一仓的数量，则转查来源对象和期间；扩大授权不解决错仓引用。最终将资源范围与内容待核分开，商品销售、库存同步或履约是否执行另查业务记录。
