# TikTok Shop美国店运营的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在TikTok Shop美国店运营的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。合作期间图片用途与停用素材替换安排分开阅读。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

TikTok Shop合同比对自拟“商品图片仅在合作期间使用；停用素材需替换”，素材清理表写“旧图待换”，先前聊天曾出现长期保留字样。当前问题问能否继续使用旧图，必须让合作期间、停用与待换一起进入输入。清理表本身未说明合作状态，也没有确认旧图是否仍适用；历史措辞不能替代当前条件，更不能从待换推定图已换完。

## 配置怎么定

| 上下文核对对象 | 具体文字条件 | 验收线索 |
| --- | --- | --- |
| 期间条件 | 仅在合作期间 | 核传入文字保留范围。 |
| 清理状态 | 旧图待换 | 不摘要为已更换。 |
| 历史说法 | 长期保留缺对应确认 | 核同素材及期间。 |
| 上下文缺口 | 当前合作状态未知 | 列待补材料。 |
| 流程承接 | 图片身份、条件与清理进度 | 核字段对应及解析。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

常见错误是输入只保留商品图片可使用，时间范围被裁掉；另一处是把清理表的待换摘要成已更换，导致两个不同状态混用。排查要分别核完整条款、传入片段和状态摘要，查清变化发生在哪一步。若带历史回答采用长期保留，应核该说法是否属于同一素材及明确确认。实际模型容量不能从回复上限推断，留出回复空间也不能为缺少的合作状态补证。

## 怎么确认配好了

验收先列本题所涉图片身份、条款适用期间、清理进度和仍待确认的合作状态，避免直接给出笼统可用结论。用相同问题在空历史与带历史下对照，检查长期保留是否压过当前限定。回复格式若交给素材清理流程，应核待换仍对应旧图，条件与缺项都能解析。取得新的确认后要记录其适用素材与期间，不将一张图的结果扩到全部旧素材。
