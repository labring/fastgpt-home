# 一般贸易出口报关的合同与交易材料比对：文档解析与分块

## 这个品类的数据长什么样

在一般贸易出口报关的合同与交易材料比对中，本页说明FastGPT的文档解析与分块如何衔接资料。发票抬头确认与收货联系人另列，需要保留不同身份字段。所用场景为自拟文字测试。

## 这些特征在「文档解析与分块」这一环带来什么约束

出口交易资料自拟合同句“发票抬头按买方确认；收货联系人可另列”，附件上下两栏分别标抬头资料与收货联络。字段值在本组用普通称呼，不含真实个人信息。比对两栏不同时，先核身份角色，不能仅因文字不同认定交易主体冲突。解析若去掉栏名，只留下两个名称，就丢了判断所需的关系；分块前应保留每个名称在文件中承担什么角色。

## 配置怎么定

| 原文或分块核对项 | 具体材料关系 | 取证动作 |
| --- | --- | --- |
| 栏名保留 | 抬头资料与收货联络 | 核解析角色没有丢失。 |
| 确认限制 | 抬头按买方确认 | 核条件随抬头条款。 |
| 另列关系 | 联系人可不同列示 | 不据名称差异判冲突。 |
| 索引回指 | 抬头与联络入口 | 分别核目标原块。 |
| 附件更新 | 新版栏关系与确认内容 | 核处理和同题引用。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `原始资料核对` | 对照原文件与解析输出。 |
| `分段完整性` | 条件需与其主体保持可关联。 |
| `数据与索引` | 原数据与索引分别保留依据。 |
| `样本检索` | 用原文词句及自然问题复测。 |
| `更新后复核` | 更新后核训练或索引状态。 |

## 容易做错的三处

常见错误是把收货联系人归到发票抬头块，回答据此建议替换抬头；另一种失败是把按买方确认切离抬头条款，让草稿值被当成最终确认。应对照原栏、解析顺序与块内条件，分别定位角色错配和确认限制丢失。索引可以给抬头或联络两个入口，但都应回到对应原数据；入口名称本身不能确认主体身份，也不能替代买方确认材料。

## 怎么确认配好了

验收用抬头资料、收货联络原词及“两栏是否必须同名”的问题测试，核返回块是否完整带角色与条件。回答应说明现有文字允许另列联系人，同时保留抬头待核确认范围，不作主体资格判断。附件补更后检查实际处理及索引是否对应新版，再用相同问题复测。上传成功只证明提交动作，不能证明旧栏关系已经修复或新版确认已被回答采用。
