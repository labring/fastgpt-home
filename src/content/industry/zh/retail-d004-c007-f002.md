# 一般贸易进口报关的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在一般贸易进口报关的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。标签样稿校对与本批实物贴标是两个待核对象。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

进口交易比对自拟约定“标签先按样稿校对；实物贴标须核批次”，校对表写“文字已核”，贴标说明没有本批记录。问标签工作是否完成时，应让样稿、文字和实物批次一起留在输入。文字已核只支持校对动作，不能推成标签已贴，也不能证明贴在了本批货物上。样稿本身还可能只展示排版，未说明实际标签数量和适用对象，回答需要保留这一范围。

## 配置怎么定

| 上下文核对对象 | 具体文字条件 | 验收线索 |
| --- | --- | --- |
| 校对对象 | 样稿文字 | 核已核动作的对象。 |
| 实物条件 | 贴标须核批次 | 保留批次限制。 |
| 历史指代 | 这版可能指不同样稿 | 核版本与原文。 |
| 输入完整 | 文字全在仍缺实物记录 | 分开记完整性与证据缺项。 |
| 输出核对 | 样稿、文字、实物批次 | 核缺项及解析。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

一种失败是引用把实物贴标的批次条件裁掉，输出据文字已核宣布整批完成；另一种是历史指代这版被误接到另一份样稿，使已核对象改变。应对照样稿身份、校对对象与本批记录，定位条件截断和指代错配。实际模型容量按所用模型能力核验，不能从回复上限估计。即使文字能够全部放入，缺少的实物记录仍需补证，不能把输入完整当成工作已完成。

## 怎么确认配好了

验收可问校对了什么、是否有本批贴标依据、这版指哪份稿件，要求输出分别对应材料。相同问题在空历史与带历史下比较，核历史是否改变稿件身份。固定格式如需交给核查清单，应保留样稿、文字校对和实物批次三个对象及缺项，验证实际解析。回复太短而省掉批次限定，也应作为输出信息丢失处理；不能因此判定实物贴标已经满足约定。
