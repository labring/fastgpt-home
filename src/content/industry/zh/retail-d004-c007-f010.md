# 一般贸易进口报关的合同与交易材料比对：引用来源与溯源

## 这个品类的数据长什么样

在一般贸易进口报关的合同与交易材料比对中，本页说明FastGPT的引用来源与溯源如何衔接资料。进口单据的收货、通知和交付位置按字段角色核对。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

进口材料阅读可拟交易说明“收货主体为海滨商贸”、运输说明“通知联络人为仓配服务方”和邮件“资料送至仓配地址”。另有一页旧仓库联系单。询问是否已将收货主体改成仓配方时，三处信息的角色不同：主体、通知联系人和资料寄送地点并不互相覆盖。引用应保留字段名称及原句，不能把邮件送达地址作为主体变更凭证，也不能凭旧联系单断定当前仓库仍在使用。

## 配置怎么定

| 交易来源核对项 | 材料与行动范围 | 验收动作 |
| --- | --- | --- |
| 主体字段 | 海滨商贸 | 核交易原句。 |
| 通知角色 | 仓配服务方 | 不替代收货主体。 |
| 邮件对象 | 送的是资料 | 不推货物交付。 |
| 地址版本 | 旧联系单 | 核当前指示。 |
| 修改依据 | 本次未给 | 核交易与对象。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是通知方被写成收货主体，应并列交易说明与运输字段，核有没有本次主体修改文件。第二处是资料送达被写成货物已经交付，应读邮件所指对象，并另找适用货物交接记录。第三处是旧仓地址被当作本次有效地址，应对联系单身份、版本及当前指示。三项分别查角色、行动对象和位置版本；相同公司或地点文字不足以证明业务关系已经改变。

## 怎么确认配好了

验收分别问谁是收货主体、谁接收通知、邮件送的是什么，再将每句输出回指实际引用内容。引用若缺字段标题，即使出现同一公司名称，也需检查是否能判断角色，角色缺口继续留作待核。取得修改页后核它对应的交易与生效对象；没有取得不能直接判变更被拒。此处仅比较自拟文字，收货、清关与放行等实际结果仍需各自凭证，不由文件可读或来源数量推出。
