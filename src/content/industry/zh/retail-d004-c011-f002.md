# 仅退款争议处理的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在仅退款争议处理的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。申请材料核对不执行资金处理，也不决定申诉结果。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

仅退款交易比对练习自拟处理范围“本次只核申请材料；资金处理另行核实”，登记备注写“材料已核”，申诉说明写“可继续补证”。问是否已经处理完毕时，应先在输入中保留核材料与资金处理的对象差异。已核不是所有环节结束，可补证也没有表示申诉已经获准。材料阅读可以指出文本覆盖到哪一步，不能把核查动作升级为实际资金操作或最终决定。

## 配置怎么定

| 上下文核对对象 | 具体文字条件 | 验收线索 |
| --- | --- | --- |
| 核查对象 | 本次仅申请材料 | 核范围句完整传入。 |
| 已见动作 | 材料已核 | 保留材料主语。 |
| 后续补证 | 可继续补证 | 不升级为申诉获准。 |
| 历史建议 | 直接处理是建议 | 核有无实际结果依据。 |
| 人工承接 | 动作对象与缺少记录 | 核格式完整及解析。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

一种失败是引用只留下已核，处理范围那句被剪掉，输出就把全部事项写成完成；另一处风险是历史有人提出直接处理的建议，被当前回答当成已执行。应核已核的主语、建议的身份及实际输入中的范围限定。上下文容量按实际模型能力确认，不以回复长度代替；无论输入空间多大，缺少交易结果仍是证据缺项，不能通过补充叙述把未知变成完成。

## 怎么确认配好了

验收分开问核过哪些材料、是否有实际处理结果、补证目前说明什么，输出分别对应登记、范围条款和申诉说明。相同问题在空历史与带建议历史下比较，保留尚待核实的资金状态。固定格式用于后续人工核查时，检查动作对象与待补材料都完整解析，不能只传完成二字。回复中不添加金额或时间承诺，也不从材料未提供推定处理必定没有发生。
