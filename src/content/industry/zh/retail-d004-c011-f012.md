# 仅退款争议处理的合同与交易材料比对：文档解析与分块

## 这个品类的数据长什么样

在仅退款争议处理的合同与交易材料比对中，本页说明FastGPT的文档解析与分块如何衔接资料。申请理由与处理意见分栏，不能将当事人说法解析成结论。所用场景为自拟文字测试。

## 这些特征在「文档解析与分块」这一环带来什么约束

仅退款比对资料自拟申请表，左栏为申请理由“描述不符”，右栏为处理意见“待核材料”，表头注明左栏为申请人陈述。问是否已确认描述不符时，解析必须保留陈述来源与处理状态。左栏提供的是主张，右栏说明尚待核查，不是双方已认可的事实。分块若只留描述不符四字，既丢了说话人，也会让结论看似已由处理流程给出。

## 配置怎么定

| 原文或分块核对项 | 具体材料关系 | 取证动作 |
| --- | --- | --- |
| 陈述身份 | 左栏为申请人陈述 | 核表头随理由保留。 |
| 处理状态 | 右栏待核材料 | 不转成已确认事实。 |
| 行列关系 | 当前申请对应意见 | 查跨记录错配。 |
| 问题覆盖 | 主张、意见与结论分问 | 核各返回块能支持哪项。 |
| 意见更新 | 新版该行处理和索引 | 复测是否仍回旧状态。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `原始资料核对` | 对照原文件与解析输出。 |
| `分段完整性` | 条件需与其主体保持可关联。 |
| `数据与索引` | 原数据与索引分别保留依据。 |
| `样本检索` | 用原文词句及自然问题复测。 |
| `更新后复核` | 更新后核训练或索引状态。 |

## 容易做错的三处

一种失败是表头注释与理由分开，申请人陈述被当作审核判断；另一处风险是按列拼接导致待核材料连到其他申请，当前记录失去状态。应核表头适用范围、行列身份和实际块，分别定位来源角色丢失与跨记录错配。索引可以帮助搜到理由词，但不能从命中推定主张属实。当前材料不承担资金处理证明，也不能替实际审核作责任判断。

## 怎么确认配好了

验收分别问申请人提出什么、处理意见写什么、是否已有核查结论，检查返回块对三问有不同覆盖。输出应保留主张与待核状态，第三问列明缺实际结论。若修订表加入新意见，核该行实际处理及索引状态再复测，不把上传视为已替换旧意见。保留原文、解析和引用对应，以便识别答案仍在使用旧状态或误读另一条申请的结果。
