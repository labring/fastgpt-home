# 仓内拣货复核打包的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在仓内拣货复核打包的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。包装清单中的物品关系和补充条件需要同时进入当前输入。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

仓内合同比对可拟清单“主件与密封圈同包”、附注“展示样不含密封圈”及当前问题“正式订单是否包含密封圈”。长背景另讲展示样摆放。送给回答的输入需要保留正式订单与展示样的对象区别，以及同包和不含各自所指。若只留下密封圈不含片段，结论可能错用展示条件；若摘要只写两处不一致，也会消除原本可以并存的范围。不能仅凭输入或回答变短就判断哪份业务材料错误。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 当前对象 | 正式订单 | 与清单同送达。 |
| 例外范围 | 展示样不含圈 | 保留对象限定。 |
| 历史对照 | 上一轮讨论展示 | 同题空历史比较输入。 |
| 答复范围 | 两类对象可并存 | 核例外未省。 |
| 输入预算 | 看实际保留文字 | 不以条数判断。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是同包句与正式订单身份被分开，应核实际请求中清单、对象与附注的邻接关系，先定位哪些文字未进入。第二处是上一轮展示样问答影响本轮正式订单，应以同题空历史对照，保存实际输入及其对应回答。第三处是答复只列包含却省掉展示例外，应核输出逐句范围及回复长度，确保可表达两类对象。三项分别查材料送达、历史指代和条件表达，不由增加可回复文字补缺失证据。

## 怎么确认配好了

验收分别问正式订单、展示样及二者为何不同，逐项对照送达文本与输出范围。知识引用按token受限时，还需查看实际保留下来的清单与附注，不用返回条数代替完整性。确认所用模型的真实上下文能力，回复长度不能当完整窗口；若输入本就缺订单身份，先补对应材料。测试只核拟议文字，不执行装箱，也不证明现实订单齐套或仓内作业已经完成。
