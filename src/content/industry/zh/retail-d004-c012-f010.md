# 仓内拣货复核打包的合同与交易材料比对：引用来源与溯源

## 这个品类的数据长什么样

在仓内拣货复核打包的合同与交易材料比对中，本页说明FastGPT的引用来源与溯源如何衔接资料。复核签名、面单重打和包裹内容按记录覆盖范围核验。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

仓内材料比对可拟作业单“杯体与杯盖同套”、复核栏“仅核杯体外观”以及面单备注“地址字迹不清，重打”。问题是这份签名能否证明整套已核齐并送到新地址。复核限定了检查范围，面单备注解释重打原因，并未写地址修改。还附有另一包裹的称重纸条，不能直接作为本包裹的组成证明。引用应保留栏位和包裹归属，不能把纸面痕迹多理解成流程全部完成。

## 配置怎么定

| 交易来源核对项 | 材料与行动范围 | 验收动作 |
| --- | --- | --- |
| 签名栏位 | 仅核杯体外观 | 核实际检查范围。 |
| 套装内容 | 杯体与杯盖 | 另查组成及数量。 |
| 重打原因 | 字迹不清 | 不当地址修改。 |
| 称重身份 | 他包裹纸条 | 核包裹归属。 |
| 作业完成 | 纸面项目不等执行 | 核对应记录。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是外观签名被扩成杯盖数量及整套完整，应读签名对应栏位，补查适用的数量与组成记录。第二处是重打面单被写成地址已改，应核前后文字及修改依据，字迹不清只解释显示问题。第三处是他包裹称重条被用来证明本包裹装齐，应核包裹身份及称重所能支持的范围，重量本身也不逐项证明内容。三项分别检查作业范围、变更对象和凭证归属。

## 怎么确认配好了

验收分别问签名核了什么、为何重打、称重条属于谁，再核回答实际引用是否带出仅核限定和包裹身份。若只返回作业单，尚不能称复核已经执行；若只有面单，不能推整套齐备。补入作业记录后也只按其实际检查项目表述，不把某项签字推广为全部确认。空引用需查来源范围和传入，不由无返回认定漏装，也不声称已经出库或完成交付。
