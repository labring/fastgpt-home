# 便利店加盟门店督导的合同与交易材料比对：引用来源与溯源

## 这个品类的数据长什么样

在便利店加盟门店督导的合同与交易材料比对中，本页说明FastGPT的引用来源与溯源如何衔接资料。门店标准的版本、照片说明和整改反馈按适用对象追溯。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

加盟门店督导可拟标准页“冷饮陈列见当期图示”、本店照片说明“左侧货架暂空”和门店回复“会补陈列”。材料还带上一期图示及隔壁店的整改完成表。问本店是否已按当期标准完成整改时，照片只是某次状态，回复是后续意向，旧图示和他店完成表都需要区分。引用应将本店、当期和已完成分别核实，不能把四份相关材料拼成缺少依据的当前验收结论。

## 配置怎么定

| 交易来源核对项 | 材料与行动范围 | 验收动作 |
| --- | --- | --- |
| 标准指向 | 当期图示 | 核引用版本。 |
| 照片状态 | 本店左架暂空 | 保留观察范围。 |
| 回复时态 | 会补陈列 | 不当已执行。 |
| 完成归属 | 邻店结果 | 不移用本店。 |
| 验收依据 | 本店同项目记录未给 | 核新增记录身份。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是上一期图示被称为当期要求，应核标准页指向的版本及适用期间。第二处是会补陈列被写成已经整改，应查本店实际后续反馈与验收记录，不以计划语气代执行。第三处是隔壁店完成表被引用为本店结果，应对门店身份、照片说明和整改项目。三项分别查版本关系、行动阶段和店别归属，不从加盟或相邻地理位置推出同一标准采用和同一完成状态。

## 怎么确认配好了

验收分别问当前采用哪份图示、照片能说明什么、回复处于哪一步，逐句读实际引用与其门店标签。若引用仅含旧图示，需保留当期要求未核，不能直接判本店不合格；若只有回复，不能代称已验收。补充记录必须针对本店及同一项目，不能将通用整改模板当实际结果。空引用继续查来源和传递，本次文字对照不执行巡店，也不发布任何实际整改判断。
