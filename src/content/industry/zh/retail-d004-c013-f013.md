# 便利店加盟门店督导的合同与交易材料比对：权限与数据隔离

## 这个品类的数据长什么样

在便利店加盟门店督导的合同与交易材料比对中，本页说明FastGPT的权限与数据隔离如何衔接资料。按总部、区域督导和店主分别核合同巡店资料，不让同区域关系扩大门店访问。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

比对练习可自拟本店加盟附页、巡店记录及整改照片说明，总部拟核约定，区域人员拟跟进对应门店，店主拟看自身事项。先以真实账号验证资源和操作，不把区域群或门店称谓当作现成角色。加盟关系可以说明业务主体，不自动开放其他店合同或全部照片。访问记录应能指出具体门店、巡店期间及所读原文，避免按相同整改标题合并权限范围。

## 配置怎么定

| 权限核对项 | 加盟巡店关系 | 验收对象 |
| --- | --- | --- |
| 主体对应 | 总部督导店主只是业务称谓 | 真实账号资源映射 |
| 门店边界 | 本店合同与他店照片分开 | 受限原文完整返回 |
| 期间版本 | 巡店时间及适用标准 | 不能按同标题合并 |
| 外部来源 | 督导APP鉴权单独核 | 不代替资源和验收 |
| 业务批准 | 可读不改合同或批准采购 | 实际责任及记录 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 总部代表或店主称谓被当成系统成员：核实际账号与合同巡店资源，缺对应由责任人确认，业务关系不自动赋权。

- 本店身份能读他店合同或整改照片说明：保存完整返回查资源范围，同区域不构成跨店共享依据，附件未展示也查转述。

- 督导APP接口正常被当全部资料获权或整改已验收：分开核外部鉴权、内部资源和实际确认记录，技术读取不替代业务结论。

## 怎么确认配好了

验收用总部、对应督导、本店与无关店身份询问同一整改事项，记录原句、操作及拒绝。若授权正确而回答套用另一店标准，应查输入门店和适用版本，不通过扩权解决内容错配。新照片或复核意见补入后按原身份范围重测，资料缺项继续待补。合同修改、巡店执行及整改验收需要各自确认，资源可读不自动批准采购或改变加盟约定。
