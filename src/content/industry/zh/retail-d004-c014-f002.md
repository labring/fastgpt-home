# 便利店鲜食订货的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在便利店鲜食订货的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。订货附页与观察记录中的商品批次和未观察项目需要完整送达。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

鲜食材料比对可拟订货页“本批为原味三明治”、观察记录“外袋完整，夹层未查看”和另一页“饭团标签另存”。问题问当前能否说明三明治夹层状态。输入必须保留未查看和商品身份，不能只留下完整两字。饭团标签即使文字较长，也不补三明治观察。历史若谈过饭团的具体条件，应避免被摘要带成本题事实；这里不设真实保存数值或商品处理规范。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 观察粒度 | 外袋与夹层分开 | 核未查看原句。 |
| 商品身份 | 三明治非饭团 | 核当前输入。 |
| 历史影响 | 旧条件可能迁移 | 同题空历史对照。 |
| 答复条件 | 未观察保留 | 不补肯定状态。 |
| 预算效果 | 不能生成缺失事实 | 先核原文覆盖。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是外袋完整被压成商品完整，应逐项核实际输入保留的观察对象与夹层未查看，不把限定丢失归成事实本来如此。第二处是历史饭团条件被用于当前三明治，应对商品指代及来源，再用同题空历史核输入差别。第三处是回答省去未观察状态而作肯定结论，应核输出条件、回复长度与所用依据，保留无法从材料确定的部分。三项分别查观察粒度、历史迁移和答复范围，不靠延长回复补实物检查。

## 怎么确认配好了

验收分别问外袋、夹层和饭团页支持什么，对比真实请求与回答原句。知识引用按token限制时，应检查被保留的是哪种商品及哪项观察，并核每段实际文字覆盖。实际模型上下文能力需单独核，回复上限也应足以陈述依据与未核项目。若原文没有夹层观察，调整预算仍不能产生该事实。本练习不判适售或处置，不执行订货，也不宣称已查验任何真实食品。
