# 便利店鲜食订货的合同与交易材料比对：权限与数据隔离

## 这个品类的数据长什么样

在便利店鲜食订货的合同与交易材料比对中，本页说明FastGPT的权限与数据隔离如何衔接资料。按门店、采购及督导核订货报损资源，不从同商品或温度记录推定共享与适售。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

比对练习可自拟门店订货单、报损备注和温度附页，店长拟核本店数量来源，采购拟核订货条件，区域人员拟看对应处理事项。先确认真实账号与资源操作，不从岗位称谓自动建立团队权限。相同鲜食品名可出现在不同门店和班次，原文身份要保留；温控与报损也支持不同问题，资料能互相查阅不说明商品当前状态已经得到完整判断。

## 配置怎么定

| 权限核对项 | 鲜食门店资料 | 验收对象 |
| --- | --- | --- |
| 人员对应 | 店长采购督导各需材料 | 真实账号和操作 |
| 门店班次 | 同名鲜食可能不同来源 | 实际原文身份 |
| 报损范围 | 本店与他店记录分开 | 受限返回及拒绝 |
| 外部来源 | POS总部订货温控分别核 | 接口和资源授权分开 |
| 商品依据 | 温度报损不提供完整结论 | 实际条件与处理记录 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 店长或采购姓名被当系统成员及全部维护权：核实际账号、门店和允许操作，缺映射由责任人确认，业务职责不配置角色。

- 本店身份取得他店报损或内部订货条件：保留完整返回及资源范围查授权，同商品分类不说明跨店开放，转述文字也检查。

- POS或总部订货接口正常被当全部资源获权和适售已确认：外部鉴权、内部读取及商品依据分别核，单条温度或报损备注不提供完整结论。

## 怎么确认配好了

验收用本店、采购、区域和无关门店身份对同一批资料提问，记录原句、操作和拒绝。若授权正确但答案取别班温度或旧报损，查输入对象和日期，不盲目扩权。新增处理资料后按原账号范围复测，缺适用条件继续待补。资源访问不执行订货、报损或食品处置，真实数量、时间及处理结果需要相应系统和责任人记录，不由可读资料直接确认。
