# 加盟商培训与开业辅导的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在加盟商培训与开业辅导的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。开业检查中的条件先后、缺项清单和责任角色需要完整呈现。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

开业辅导可拟检查页“陈列照片补齐后再约复核”、签到“参加收银介绍”和店长留言“可先准备资料”。当前问是否已经通过开业复核。输入需要同时保留补齐后、再约和准备这些行动阶段；签到只说明另一个活动。若长记录中曾提另一店已经复核，不应带成本店结果。材料没有实际检查结论，不能因为文书都进入同一会话就把准备、参加与通过压成一个完成状态。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 前提顺序 | 补齐后再约 | 请求保留两阶段。 |
| 活动范围 | 收银介绍签到 | 不替开业复核。 |
| 历史门店 | 另店结果 | 同题空历史核对。 |
| 照片缺项 | 当前尚未给 | 输出不省。 |
| 能力边界 | 长度不补验收事件 | 核原文事实。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是补齐后再约被压成已复核，应对检查页原句与实际请求，保留前提及后续动作。第二处是历史另一店的通过结果被接成本店，应核门店与检查项目，并比较空历史同题输入。第三处是答复列了签到却漏掉照片缺项，应核输出任务覆盖和回复长度，不能用已参加介绍代复核依据。三项分别查时间条件、历史主体和材料缺口表达，不让更长回答补出不存在的验收。

## 怎么确认配好了

验收分别问照片当前还缺什么、店长安排到了哪一步、签到覆盖哪场活动，逐句比实际输入与输出。token预算需检查缺项与前提有没有保留，不能只看模型是否能产出短结论；实际模型窗口另核。若照片与本店复核记录未提供，调整引用或回复长度也仍需待补。本页不替门店安排检查或批准开业，不测员工技能，也不把自拟准备清单当真实完成记录。
