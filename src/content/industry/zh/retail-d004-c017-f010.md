# 加盟费与保证金结算的合同与交易材料比对：引用来源与溯源

## 这个品类的数据长什么样

在加盟费与保证金结算的合同与交易材料比对中，本页说明FastGPT的引用来源与溯源如何衔接资料。收据类别、退款申请和复核意见按款项身份及办理动作回指。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

加盟结算材料可拟收据“用途：门店保证金”、申请页“请求退回加盟服务费”和经办回复“材料已转复核”。还有一份退款登记模板，状态栏空白。问是否已经同意退回保证金时，收据与申请写的是不同款项类别，转复核只记录流转，空模板没有本次结果。溯源应首先核款项指向，不把同一家门店的各种文字压成同一笔申请，更不能由收据存在推出当前退回条件已经满足。

## 配置怎么定

| 交易来源核对项 | 材料与行动范围 | 验收动作 |
| --- | --- | --- |
| 收据用途 | 保证金类别 | 保留原文字样。 |
| 申请对象 | 加盟服务费 | 核与收据对应。 |
| 办理阶段 | 已转复核 | 不当审批结果。 |
| 模板身份 | 状态栏空白 | 不当实际登记。 |
| 执行证据 | 批准与支付分列 | 核本次真实记录。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是服务费申请被写成保证金申请，应对收据用途、申请对象及本次材料对应说明，保留类别差异。第二处是转复核被写成已批准退回，应查回复行动及实际审核结果，不以经办流转代决定。第三处是空白登记模板被当成已发生退款，应核文书身份和本次执行凭证，表格有状态栏不等于该栏已有结果。三项分别查款项、办理阶段和记录真实性，不从名称接近作同笔推定。

## 怎么确认配好了

验收分别问收据说明何种用途、申请请求什么、经办做了什么，再看引用原文是否完整保留类别与状态。若引用只有收据，应列申请对应关系及结果待核，不能判一定可退或不可退。补入审核或执行材料后核门店、款项身份和本次流程，批准与实际支付也分开记录。空引用追查范围和传递，本页不提供退款规则或决定责任，也不把模板和业务计划写成已完成结算。
