# 即时零售门店履约的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在即时零售门店履约的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。即时订单比较中的否定偏好、替代提议和历史回复需同轮对应。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

即时零售材料可拟当前备注“不要含坚果的款”、替代提议“芝麻脆片”和配料说明“本页未说明坚果相关条件”。历史另有顾客上一单答复“可以替换”。当前问是否已同意且能满足备注时，需要保留不要限定、配料缺项和回复的上一单身份。芝麻与坚果的实际适用关系不能在此凭名称决定，旧同意也不延续。本页只检查输入与条件支持，不作成分或过敏安全判断。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 否定条件 | 不要含坚果 | 核实际请求保留。 |
| 历史同意 | 上一单 | 核本轮提议归属。 |
| 成分缺项 | 相关条件未写 | 输出保持待核。 |
| 输入预算 | 备注与缺项同入 | 不只看返回页。 |
| 现实适用 | 文字不保证限制满足 | 核对应来源。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是否定备注被摘要省掉，应核本轮原句与实际请求，保留顾客排除范围。第二处是上一单同意被沿用到本次提议，应对订单、提议对象和历史指代，比较空历史同题输入。第三处是答复只说满足却漏配料页未说明，应逐句核依据与缺项，留足回复表达不确定部分。三项分别查条件送达、许可归属和证据不足的表达，不把更多token当作配料依据。

## 怎么确认配好了

验收分别问顾客排除什么、提议是什么、当前资料明确说明什么，保存实际输入及输出条件。引用预算应核备注和配料缺项有没有一同进入，不以商品页返回就称完整。实际模型窗口、引用上限与回复长度各按相应条件核；未给原料资料时仍需补源。测试不执行替代或配送，也不保证满足饮食限制，现实成分及适用判断要有对应资料和责任人核实。
