# 即时零售门店履约的合同与交易材料比对：权限与数据隔离

## 这个品类的数据长什么样

在即时零售门店履约的合同与交易材料比对中，本页说明FastGPT的权限与数据隔离如何衔接资料。比对即时订单、拣货与骑手资料时核门店权限，分开库存时点、作业和实际接收。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

比对练习可拟即时订单附页、拣货说明和骑手交接备注，门店拟核商品对象，配送协作拟看本单承接，区域人员拟查限制事项。先按实际账号核资源及操作，不由“店长”或“配送”文字授予全部门店权限。库存附页和骑手记录的时点可能不同，订单编号一致也只支持这项字面对应；能读到拣货说明不证明骑手已接、顾客已收或门店当前仍有库存。

## 配置怎么定

| 即时订单比对权限 | 实际资料 | 核对对象 |
| --- | --- | --- |
| 账号范围 | 门店区域配送协作 | 成员资源及操作 |
| 对象关系 | 订单拣货骑手分开 | 原文编号和身份 |
| 他店限制 | 库存与无关订单资料 | 完整回答及拒绝 |
| 时点差异 | 库存不由骑手时点更新 | 输入日期及定义 |
| 作业阶段 | 拣货不等承接或送达 | 真实交接及接收 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 订单联系人被当系统成员并可维护全部门店：核真实账号、门店映射及允许操作，缺对应由责任人确认，不从单据头衔创建角色。

- 本店比对读出他店库存或无关订单骑手资料：保存来源身份和完整回答查授权，同商品同渠道不构成跨店开放依据。

- 平台查询正常被当内部库存可读且骑手已接：外部鉴权、内部资源和本单实际交接分别核，拣货文字不替代承接依据。

## 怎么确认配好了

验收让本店、区域、配送及无关门店身份查同一批来源，记录可见原句、操作和拒绝。账号有权却拿旧库存答当前需求时，核输入日期和库存定义，不靠扩大范围补可用性。骑手资料已取得未传入与实际交接记录尚缺分别列证，补后按原权限复测。读取不创建订单、派单或修改库存；配送、接收和商品状态仍靠真实记录及责任确认，不从文件齐名推出。
