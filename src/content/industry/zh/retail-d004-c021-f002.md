# 品牌会员私域运营的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在品牌会员私域运营的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。会员条款比对中的人群、活动与授权限制需要进入当前输入。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

会员材料可拟活动页“仅面向主动报名者”、触达草稿“邀请全部会员”和授权说明“本次报名用于本活动沟通”。当前问题是这份草稿是否有文字依据。输入要保留主动报名、本活动两个范围，不将报名者概括成全部会员，也不从本次沟通推其他用途。历史若讨论过公开邀请，又需辨别活动身份。这里仅核自拟材料支持范围，不判断真实隐私合规或授权效力，更不把草稿准备好当通知已发。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 活动人群 | 主动报名者 | 输入保留范围。 |
| 用途限定 | 本活动沟通 | 答复不扩大。 |
| 草稿增加 | 全部会员 | 逐句查依据。 |
| 历史活动 | 另一公开邀请 | 核身份及指代。 |
| 实际行动 | 未发送或改标签 | 不称已执行。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是主动报名限制在摘要中被丢掉，应对活动原文与实际输入，核人群范围是否完整送达。第二处是历史另一活动的广泛邀请被用于本次，应查活动身份与授权说明，比较空历史同题输入。第三处是答复只列可联系却省去本活动用途，应核输出条件及回复空间，保持用途限定。三项分别查人群、历史活动和答复范围，不以更大上下文自动扩大可用来源或联系人权限。

## 怎么确认配好了

验收分别问活动面向谁、报名说明允许何种沟通、草稿增加了什么，逐句比对请求与回答。引用token预算应让人群及用途条件一同保留，文件已返回不保证这些条件实际进入。模型窗口与回复上限各依实际能力和任务核实，资料没有覆盖全部会员时仍需补适用依据。本页不执行触达、不变更CRM标签，也不代作合规决定，真实发送和权限需另有对应材料与责任人核定。
