# 品牌全渠道库存调拨的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在品牌全渠道库存调拨的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。跨渠道调拨中的预留原因、来源仓和到货状态要保持对应。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

全渠道调拨可拟门店申请“借展示架用于周末陈列”、仓库备注“仅预留，待确认出库”和物流页“旧架退回途中”。当前问新展示架是否已经到店。输入必须保留借用用途、预留未出库以及旧架退回对象，不能把退回途中当新架配送，或把同一架名称压成同一物流事件。历史可能讨论过旧架损坏，不能因此补新架状态。没有本次出库与到货记录时，这些材料只支持申请及预留。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 申请用途 | 借用陈列 | 不改作所有权。 |
| 仓库条件 | 预留待确认 | 实际输入保留。 |
| 运输对象 | 旧架退回 | 不套新架送达。 |
| 输出主语 | 新旧架分开 | 核状态对应。 |
| 到货依据 | 当前无记录 | 不由预算补证。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是仅预留待确认被截断后变成已发，应比对仓库原句及实际请求，明确保留未执行条件。第二处是旧架退回的物流事件被套到新架，应核物品身份、方向和历史指代，分别对同题空历史输入。第三处是输出只写架已在路上而不注明哪个架，应核句子主语及状态对应，回复要留足解释新旧差异。三项分别查行动条件、物流对象和表达归属，不用相同品名填真实到货。

## 怎么确认配好了

验收分别问申请借什么、仓库确认到哪一步、物流描述哪件物品，保存输入和回答。token预算应检查预留限定与新旧身份都在实际材料内，返回物流页不意味着能答当前到货。真实模型窗口和回复长度分别核实；若缺新架记录，增加预算也仍缺证。本练习不审批调拨、不更新库存或签收，不把借用申请写成所有权改变，也不声称新展示架现实中已发出或到店。
