# 品牌全渠道库存调拨的合同与交易材料比对：工具调用与插件

## 这个品类的数据长什么样

品牌全渠道库存调拨处理货品在门店与仓之间的流动，数据来源包括ERP库存、门店POS、电商订单与WMS。本页涉及的材料为调拨申请、库存快照、门店缺货清单与调拨物流单。这些材料的主体、对象、期间与状态字段并不统一：调拨申请记录门店与仓的货品去向，库存快照反映某一时点的可调数量，缺货清单列出待补货项，物流单承载实际发运信息。合同与交易材料比对需要在这些材料之间核对同一主体、同一期间、同一字段的取值是否一致，工具调用与插件决定模型能否按需取回相应材料并执行比对动作。

## 这些特征在「工具调用与插件」这一环带来什么约束

工具介绍用于告诉模型工具的用途，需写清输入条件与不应调用的情形。系统模块的参数已经固定，插件的参数为可配置项，两者分别核对，不把参数介绍当作执行保证。缺少适合的必须参数时，模型可能不调用该工具，需要通过交互补全并核对实际请求。高级编排中把可用工具连接到工具调用模块，建议先用少量工具调试。工具调用终止节点会结束本次工具调用，也不再调用AI总结工具结果。检索与相似度得分不承担权限或实体隔离职责，跨不同向量模型的库不可共同关联，只能先核标识并排除不符合者。

假设演练样本：某品牌门店库管提交一份调拨申请，原文为「申请方：A门店；接收方：B仓；货品：型号X；数量：30件；调拨期间：2025年3月1日至3月31日；状态：待审核」。同期间库存快照原文为「型号X在A门店可调数量：12件；快照时间：2025年3月5日」。拟交接请求句为「A门店已批准向B仓调拨型号X共30件，可执行出库」。待判定要点：申请数量30件与快照可调12件在同一期间同一字段上取值不一致；申请状态为待审核，不构成批准。

## 配置怎么定

| 配置项 | 本页取值或核对方式 | 说明 |
| --- | --- | --- |
| 工具介绍 | 写明输入为调拨申请、库存快照、缺货清单、物流单，并写明无对应材料时不调用 | 介绍影响模型调用时机 |
| 插件参数 | 按插件可配置项逐项填写材料类型与期间字段 | 参数介绍不保证执行 |
| 必须参数 | 将主体、对象、期间、字段设为必须参数 | 缺适合值时模型可能不调用 |
| 工具连接 | 在高级编排中连接工具调用模块，先接入少量工具 | 连接后可编辑介绍 |
| 工具调用终止 | 在比对完成后接入终止节点 | 终止后不再调用其他工具与AI总结 |
| 假设试验起点 | 本次假设样本数量阈值设为12件，用于与申请数量比较 | 起点仅为本次演练，需与实际快照值比较 |

## 容易做错的三处

1. 把待审核状态当成已批准。假设样本中调拨申请状态为「待审核」，拟交接句写「已批准」，输入为申请原文与拟稿句，比较状态字段取值，观察结果为两者不一致，属于未获支持。
2. 用相似度得分代替权限或实体过滤。输入为检索请求与返回记录，比较记录主体是否与目标门店、仓一致，观察结果为得分高但主体不符时仍需排除。
3. 把终止节点当作可继续调用。输入为已接入终止节点的工作流，比较终止后是否仍调用其他工具或AI总结，观察结果为终止后不再调用。

## 怎么确认配好了

- 验证一：输入假设样本中调拨申请原文与拟交接句，比较申请数量30件与快照可调12件，观察结果为两值不一致且申请状态为待审核，满足条件时判定拟稿句未获支持。

- 验证二：输入假设样本中库存快照原文与检索请求，比较返回记录的主体、对象、期间字段，观察结果为记录主体与目标不一致时排除，满足条件时记录实际观察。

- 验证三：输入假设样本中拟交接请求与可用材料清单，比较请求所需材料是否在清单内，观察结果为材料缺失时记录缺口，满足条件时保留待核实状态。若纸面输入为[]，则核对下游设计如何处理空结果，不声称虚构规则检索一定返回[]。
