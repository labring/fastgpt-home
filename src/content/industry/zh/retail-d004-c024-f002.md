# 品牌商场专柜运营的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在品牌商场专柜运营的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。商场活动中的柜位、参与范围和物料收件必须保持对应。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

商场专柜比对可拟活动函“仅参与展示，不含现场销售”、本柜回复“物料已送”和另一柜位备注“已确认销售安排”。当前问本柜是否获准现场销售。输入需同时保留活动排除和另一柜位身份，不能把展示参与缩成参加活动即全部范围。物料已送也不说明销售安排；长对话若沿用另一柜位的确认，可能误接当前主语。这里不设真实商场规则，只核自拟函件各自所述动作和对象。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 活动排除 | 不含现场销售 | 核请求保留。 |
| 柜位身份 | 本柜与另柜 | 不由历史合并。 |
| 物料动作 | 仅已送出 | 不当销售许可。 |
| 答复范围 | 展示及销售分开 | 留条件表达空间。 |
| 确认缺项 | 本柜尚缺 | 列待核不判拒绝。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是不含现场销售被引用裁剪省略，应对活动函原句与实际请求，核排除条件是否传入。第二处是另一柜位确认被历史摘要改成本柜，应核柜位、活动及指代，用空历史同题比输入。第三处是答复以物料已送替销售确认，应逐句核动作对象和证据，回复需能表达收件与安排的差别。三项分别查排除、柜位归属和结论依据，不让较长背景冲淡当前限制。

## 怎么确认配好了

验收先问参与范围是什么、回复证明什么、哪家柜位有何确认，再比较送达文本与输出。知识引用token预算要保留函件排除句及柜位标识，不只看活动名称相关。实际模型上下文另核，回复长度不能决定函件适用。若本柜销售依据未提供，继续列待核，不能因缺返回就断言已经拒绝。本练习不执行活动报名或销售，也不把物料交付写成现实柜位已获批准。
