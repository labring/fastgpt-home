# 品牌奥莱折扣运营的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在品牌奥莱折扣运营的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。奥莱活动比较中的候选清单、排除款式和确认地位必须共同表达。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

奥莱材料可拟候选页“旧季外套待选”、商品附注“皮质款不在本次名单”和活动便签“展示位置已留”。当前问题是所有旧季外套是否已经纳入活动。实际输入要保留待选和皮质排除，位置预留只涉及陈列，不补款式确认。历史曾讨论另一轮皮质活动时也需区分轮次。不能把多份资料压成外套位置已留即全部参加，材料没有任何实际价格或折扣结论，本文也不补这些商业参数。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 候选状态 | 待选 | 不当已经参加。 |
| 款式排除 | 皮质不在本次 | 核后段送达。 |
| 位置用途 | 展示位预留 | 不替选品确认。 |
| 历史轮次 | 另一活动 | 核当前名单。 |
| 商业参数 | 材料未给价格折扣 | 不自行补入。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是皮质排除落在未保留的后段，应核候选页与附注实际进入多少，明确不能仅靠标题判断覆盖。第二处是历史另一轮名单被并成本次，应对活动身份、款式及原对话，空历史同题核当前范围。第三处是回复只写已经纳入而省掉待选，应检查款式状态与输出长度，让候选和确认分开。三项分别查排除送达、活动归属和状态强度，不用预算调整代替选品决定。

## 怎么确认配好了

验收分别问哪些仍待选、明确排除什么、位置预留说明哪项行动，逐句比实际输入和回答。引用token预算要让例外及状态随商品保留，返回一个活动页不代表完整名单已经送达。模型窗口按实际能力核，回复上限不能当作确认依据。补入新名单后仍核本轮与款式。本练习不审批折扣、不改价签或选品，也不由旧季标签推商品当前经营状态，真实采用需对应确认。
