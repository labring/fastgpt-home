# 品牌直营门店运营的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在品牌直营门店运营的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。直营门店安排中的岗位建议、调班确认和活动适用范围按本店回指。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

直营门店材料可拟活动安排“周末展示需另定人员”、区域建议“可由熟悉新品者协助”和本店回复“先核可用班次”。同时留有另一店的已排班表。当前问本店是否已经落实人员。实际输入要保留另定、可由和先核，建议没有指定具体人，回复还在准备。另一店表格即使同一活动名也不能补本店安排。历史曾把某位导购称作负责人时，要核那句话属于哪店与哪次任务。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 建议语气 | 可由协助 | 不当指派。 |
| 本店行动 | 先核班次 | 保留准备状态。 |
| 旧表归属 | 另一门店 | 核店名及活动。 |
| 历史人员 | 责任需对应任务 | 核本轮身份。 |
| 输出待办 | 缺本店安排 | 不能省成已落实。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是岗位建议被压成已经指派，应核实际请求中建议语气与人员身份，避免由熟悉新品推实际责任。第二处是另一店排班沿历史指代变成本店，应对店别、活动与班次，比较空历史同题输入。第三处是回复只列人员已落实而漏可用班次待核，应逐项核状态与输出范围，留空间说明缺少什么。三项分别查建议地位、历史关联和答复待办，不用更多上下文替人排班。

## 怎么确认配好了

验收分别问区域建议什么、本店做了哪项动作、哪店已有排班，保存请求与答复。引用token上限需要核店名、班次及限定实际保留，不以排班表标题出现就认定本店人员齐备。模型窗口与回复长度分别按实际能力和任务核，若缺本店表应先补源。本练习不指派人员或更新排班，也不测导购能力，不从活动安排推销售目标已达成，实际组织与结果仍需对应记录。
