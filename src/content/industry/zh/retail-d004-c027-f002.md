# 品牌经销商订货会的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在品牌经销商订货会的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。订货会中的样品选项、意向单和后续确认要按系列与阶段保留。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

经销订货会可拟样品册“绒面为可选面料”、意向页“希望了解轻薄系列”和后续回复“已收到选款意见”。另一页是上季厚款确认。当前问是否已正式订下绒面轻薄款。输入需要保留面料选项、系列意向与收件动作，不把上季确认或相同款名串成本季订单。历史可能已经多轮讨论厚款，问题中的这组也要重新定位。当前文字没有选款确认，无法由样品组合补出正式采用。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 面料状态 | 可选绒面 | 不当已选。 |
| 系列意向 | 轻薄 | 不接上季厚款。 |
| 季次身份 | 上季确认 | 核历史指代。 |
| 回复对象 | 收到意见 | 不当正式订货。 |
| 新增订单 | 本季系列与面料 | 核对应后采用。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是可选面料被摘要写成已定面料，应核样品原句与实际请求，保留选项状态。第二处是历史上季厚款确认移入本季轻薄，应对系列、季次和当前指代，比较空历史同题输入。第三处是答复用已收到意见宣称已订，应核行动对象及输出状态，回复需表达仍缺确认。三项分别查规格状态、历史产品和交易行动，不用延长上下文把意向升级成订单。

## 怎么确认配好了

验收分别问样品给哪些选项、意向关心哪系列、回复实际确认什么，保存输入与输出。引用token限制应检查可选及季次是否保留，不以样品册被引用就视作规格完整。模型实际窗口与回复上限各自核验，确认材料缺失时仍列待核。新增自拟订单要核系列、面料及本轮身份。本页不下单、不批授信或协调发货，也不从意向页推现实经销商已接受供货条件。
