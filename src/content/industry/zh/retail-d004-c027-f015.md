# 品牌经销商订货会的合同与交易材料比对：知识库检索与召回

## 这个品类的数据长什么样
品牌经销商订货会按季或按年组织，品牌渠道部面向线下经销商收集预订量，日常材料包括订货手册、订货合同、样品清单与授信审批。这些材料在比对任务中承担不同角色：订货手册说明政策与商品范围，订货合同记录双方约定，样品清单列明实物对象，授信审批反映额度状态。材料更新频率低，同一批材料在会期前后被反复引用，检索结果需要能区分同一经销商在不同会期的不同版本。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的库，跨不同向量模型的库不可共同关联，只能先核标识并排除不符合者。搜索模式按测试问题比较语义检索、全文检索与混合检索，不预设一种模式适合全部资料。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展。相似度得分是相关性度量，不承担权限或实体隔离功能，检索本身不构成授权。

假设演练样本：某品牌渠道部拟核对一份材料。材料原文为「华东区经销商甲，2024 秋季订货会，订货合同编号 QD-2024A-017，约定品类为户外鞋，签署状态为已签署，生效状态为待品牌方法务确认。」待判定拟稿句为「经销商甲 2024 秋季订货合同已生效。」原文只给出生效事项待法务确认的记录，未载明已确认生效或未生效的结论；拟稿句中的「已生效」缺少支持依据，需待核实。

## 配置怎么定
| 配置项 | 本页设定 | 说明 |
| --- | --- | --- |
| 关联的知识库 | 订货手册库、订货合同库、样品清单库、授信审批库 | 四库使用相同向量模型，方可共同关联 |
| 搜索模式 | 本次假设起点为混合检索 | 合同编号类问题需全文命中，政策描述需语义命中，故先取混合 |
| 引用上限 | 本次假设起点为 3000 token | 订货合同段落长短差异大，取该值便于比较完整段落与截断段落 |
| 最低相关度 | 本次假设起点为 0.3 | 先标注相关与无关样本，再与 0.2、0.4 比较 |
| 问题优化 | 本次假设起点为开启 | 连续追问含指代，需比较原问题与优化后问题的主体是否被改错 |
| 结果重排 | 本次假设起点为开启 | 候选较多时对文本二次排序，重排得分可用于过滤 |

## 容易做错的三处
1. 把检索命中当作授权执行。检索到订货合同或授信审批记录，只说明该内容在库中，不说明审批已通过、合同已生效或回款已完成。检查：输入同一合同编号，比较检索结果与审批状态字段，观察结果是否仅返回文本而未触发任何业务动作。
2. 把相似度得分当作权限或实体过滤。最低相关度只过滤低相关结果，不排除无关经销商或未授权记录。检查：输入甲经销商问题，比较返回内容中是否混入乙经销商材料，观察得分高低与主体归属是否一致。
3. 把待审核当作否定或冲突。材料只写「待品牌方法务确认」时，属于未获支持，不构成对已生效的否定。检查：输入拟稿句与原文，比较同一字段取值，观察是否存在明确互斥取值。

## 怎么确认配好了
1. 输入假设样本中的材料原文与拟稿句「经销商甲 2024 秋季订货合同已生效。」比较「待品牌方法务确认」与「已生效」两个取值，若系统未将拟稿句判为已获支持，且保留证据缺口，则符合预期。
2. 输入合同编号 QD-2024A-017，比较全文检索与语义检索的返回内容，若编号类问题在全文或混合模式下能命中该编号所在段落，则符合预期；未命中时记录为观察结果。
3. 输入纸面空结果 []，比较下游节点对该数组的处理，若引用内容长度为 0 时链路仍走通，则符合预期；实际检索是否返回空数组仍需按观察记录。
