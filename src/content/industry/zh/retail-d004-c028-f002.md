# 品牌自播直播间运营的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在品牌自播直播间运营的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。品牌自播的脚本提议、商品卡排除和场次确认需要一起承接。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

品牌自播材料可拟脚本草案“可展示滤芯拆卸”、商品卡“本款不附替换滤芯”和场次安排“本场讲解基础套装”。历史另有升级套装含滤芯的问答。当前问本场是否能说随单送替换滤芯。实际输入需保留本款不附和基础套装，拆卸演示只讲动作，不改变套装组成。不能将长历史中的升级信息压入本场，也不从脚本可展示推实际商品或活动已经审核确认。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 组成排除 | 不附替换滤芯 | 核输入限定。 |
| 演示动作 | 拆卸展示 | 不变赠品承诺。 |
| 套装版本 | 本场基础款 | 不接升级历史。 |
| 输出新增 | 随单送 | 逐句查来源。 |
| 场次身份 | 本次安排 | 核新增活动依据。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是不附限定在输入中被截去，应核商品卡原句与请求保留内容，先定位排除送达。第二处是升级套装历史被用于本场基础款，应对商品版本、场次和问题指代，用空历史同题比较输入。第三处是回答保留可展示却加上随单送，应逐句核新增动作与来源，回复需明确演示和赠送不同。三项分别查组成限制、历史版本和输出新增，不以更长脚本填出活动承诺。

## 怎么确认配好了

验收分别问商品卡排除什么、脚本提议做什么、本场是哪套，保存实际输入与答案。引用token预算要核本款限定和套装名是否同在，不以滤芯一词相关就判断完整。模型窗口按实际能力确认，回复上限只管表达空间；活动依据没有提供时仍需补源。本页不执行直播、配置赠品或修改库存，不宣称实际促销有效，也不把自拟脚本称为真实品牌批准的话术。
