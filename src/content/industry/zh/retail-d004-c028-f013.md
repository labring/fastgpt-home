# 品牌自播直播间运营的合同与交易材料比对：权限与数据隔离

## 这个品类的数据长什么样

在品牌自播直播间运营的合同与交易材料比对中，本页说明FastGPT的权限与数据隔离如何衔接资料。核直播脚本、商品卡和评论资料的读取权限，原文访问与真实账号发布及商品主张分开。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

比对练习可拟本场脚本、商品卡限定和评论整理，主播拟看经批准解释，运营核版本，商品人员查原文依据，不放真实观众信息。实际账号应逐项对应资源和操作，主播姓名不能自动建立全素材维护权。脚本写了某句不说明已经播出，观众评论也不提供真实成交；商品卡的限定应保留在所需阅读范围里。可读材料只帮助核文字关系，不确认宣传已获准、性能已核或账号可以发布。

## 配置怎么定

| 自播比对权限 | 素材及职责 | 核对证据 |
| --- | --- | --- |
| 人员映射 | 主播运营商品支持 | 真实账号和操作 |
| 场次来源 | 脚本商品卡及评论分开 | 版本与限定原句 |
| 受限资料 | 他场脚本和个人信息 | 完整回答与拒绝 |
| 发布区别 | 直播登录不代资源批准 | 外部身份及内容依据 |
| 真实执行 | 读取不播出或确认成交 | 本场记录及确认 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 脚本中的主播称谓被当全商品素材维护成员：核真实账号和允许操作，分工不授角色，必要来源由责任人确认。

- 本场比对返回其他场次内部脚本或观众个人资料：保留场次身份与完整回答查授权，重复商品不说明跨场资料均可开放。

- 直播账号可登录被当内部商品卡已获权或内容已批准：外部发布身份、资源读取和真实内容依据分别核，评论与稿件不作经营结果。

## 怎么确认配好了

验收用主播、运营、商品支持和无关场次身份查同一限制来源，记录原句、版本与拒绝。若授权正确但丢商品限定，核实际输入和原句承接，不扩大素材范围。新商品依据尚未取得与取得后未传入分别列缺，补后按原身份复测。读取不发布脚本、不操作直播账号或确认成交；本场播出、宣传核准及交易结果需真实记录和责任确认，不由资料可见或答复流畅推出。
