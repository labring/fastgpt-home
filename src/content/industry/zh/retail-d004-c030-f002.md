# 商超供应商进场结算的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在商超供应商进场结算的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。供应商结算中的验收范围、退回对象和待核差异应分别留在输入。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

商超结算可拟验收页“外箱已点，内装数量另核”、退回留言“退回的是空周转箱”和对账稿“商品明细待补”。当前问是否已确认商品全部验收并退货。输入需保留外箱与内装、空箱与商品的差别，不能把已点和退回相接成货品完成验收后又退回。历史可能讨论过另一批商品退货，仍不能填本次对象。材料只给局部作业和待核状态，没有结算、退货或付款最终结果。

## 配置怎么定

| 上下文材料核对 | 输入与表达条件 | 验收动作 |
| --- | --- | --- |
| 验收范围 | 外箱非内装 | 核另核限定。 |
| 退回对象 | 空周转箱 | 不当商品退货。 |
| 对账缺项 | 商品明细待补 | 输出保留。 |
| 历史批次 | 另一批退货 | 核当前指代。 |
| 结果边界 | 局部动作不结清 | 不补最终状态。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是内装另核从验收摘要中消失，应核原页与实际请求，保留点的是外箱。第二处是空周转箱被历史概括成商品退回，应对退回对象、批次及原对话，用空历史同题核输入。第三处是答复说全部确认却漏商品明细待补，应查逐项覆盖与回复长度，明确哪些来源尚缺。三项分别查验收范围、物流对象和答复缺口，不用更大token预算生成数量或结算依据。

## 怎么确认配好了

验收分别问点了什么、退回什么、明细还缺什么，逐句比实际输入与输出。引用预算需检查外箱、空箱及另核限定实际保留，不以同属一供应商就归为同一动作。模型上下文与回复上限按实际能力分开核。补入明细时仍要对本批商品，不用他批退货记录填缺。本练习不执行结算或退货，也不决定账款责任，不把局部验收写成实际款项已核清或货物全数符合。
