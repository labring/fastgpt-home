# 多仓分仓与库存同步的合同与交易材料比对：知识库检索与召回

## 这个品类的数据长什么样

多仓分仓与库存同步的资料集中在分仓规则、库存同步表、调拨单与缺货预警四类。分仓规则决定订单路由阶段从哪个仓发货，库存同步表按日或按小时更新，调拨单记录仓间转移，缺货预警标记可售不足。合同与交易材料比对要处理的对象包括：分仓规则文本、库存同步记录、调拨单、缺货预警，以及围绕这些材料的交接请求与拟稿句。这些材料的主体、对象、状态与有效范围经常分散在不同字段，检索环节需要把同一主体的同一字段放在一起核对。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，不执行跨模型检索来比较漏召回。搜索模式按测试问题比较语义、全文与混合检索，不预设一种模式适合全部资料。引用上限单位为 token，用长短不同的实际资料测试内容是否完整。最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，需比较原问题与优化后问题，核对主体是否被改错。引用内容以数组输出，长度可以为 0，未搜索到内容时输出链路仍走通。相似度与相关度是过滤阈值，不承担权限或实体隔离。检索本身不是授权，表单收集值，业务核验、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：某供应链计划岗留存的分仓规则原文写道「华东区订单默认由苏州仓发货，苏州仓可售不足时转由杭州仓发货」。同一批材料中的调拨单原文写道「苏州仓向杭州仓调拨 A 型号 200 件，调拨单状态为待审核」。一条待判定的拟稿句为「苏州仓可售不足，已转由杭州仓发货」。核对时比较拟稿句与分仓规则原文的主体、触发条件与发货仓，并比较调拨单状态是否已从不具备执行效力的阶段进入可执行阶段。待审核不构成已执行，拟稿句中的「已转由」在现有材料中未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅关联含分仓规则、库存同步表、调拨单、缺货预警的同一向量模型库 | 先核各库向量模型标识，排除标识不符者，再比较召回内容是否落在目标范围 |
| 搜索模式 | 语义检索与全文检索各跑一轮，再跑混合检索 | 分仓规则含自然语言条件，调拨单与预警含编号与状态词，按问题类型比较三种模式结果 |
| 引用上限 | 起点设为覆盖一条完整分仓规则与一条完整调拨单的 token 量 | 用长短不同的实际材料测试内容是否被截断，与截断现象比较后调整 |
| 最低相关度 | 起点设为中等值，仅用于语义检索或结果重排 | 先标注相关与无关样本，再比较阈值调整后无关片段是否减少 |
| 问题优化 | 对含指代的追问开启，对已明确问题关闭 | 比较原问题与优化后问题，核对主体、对象是否被改错 |
| 结果重排 | 具备重排模型且按设置启用时使用 | 比较重排前后候选顺序，确认问题完整度对得分的影响 |

## 容易做错的三处

1. 把相似度阈值当作权限或实体过滤。最低相关度只过滤低相关结果，不排除无关业务或未授权记录。检查时输入一条越权主体的查询，比较返回内容是否仍包含该主体材料，观察阈值调整是否改变该现象。
2. 把待审核调拨单当作已执行。假设样本中调拨单状态为待审核，拟稿句写「已转由杭州仓发货」。检查时输入调拨单原文与拟稿句，比较状态字段与拟稿句的动作表述，观察两者是否一致。
3. 把不同向量模型的库共同关联。检查时输入两个库的向量模型标识，比较标识是否相同，排除不符者并记录实际观察，不据此推断漏召回或冗余结果。

## 怎么确认配好了

1. 输入假设样本中的分仓规则原文与拟稿句，比较主体、触发条件与发货仓三个字段，观察拟稿句是否与原文一致。若拟稿句出现原文未载明的执行状态，判定为未获支持。
2. 输入假设样本中的调拨单原文与待判定请求，比较调拨单状态字段与请求中的动作表述，观察请求是否把待审核写成已执行。若状态为待审核而请求写已执行，判定为证据缺口。
3. 输入一条明确的编号类问题与一条自然语言问题，分别跑全文检索与语义检索，比较两类问题的命中内容，观察编号是否被精确命中、自然语言问题是否召回语义相近片段。若编号类问题在语义检索下未命中，记录该观察，不据此断言全文检索必然命中。

空结果承接可用明确的纸面输入 [] 核对下游设计，不声称虚构规则检索一定返回空数组。图片检索须有相应图像输入及模型能力，重排须具备模型且按设置启用，文档总流程图列出的可选路径不代表每次请求全部执行。
