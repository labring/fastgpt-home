# 大促仓配排产的合同与交易材料比对：文档解析与分块

## 这个品类的数据长什么样
大促仓配排产围绕短期峰值产能与人车场安排展开，材料来源包括大促预测表、人员排班、快递保障方案与异常日报。这些材料以场次和日期为周期更新，同一场大促内可能出现多版预测与多版排班。合同与交易材料比对在此场景中处理的是材料之间的字段一致性：同一主体、同一期间、同一字段的取值是否互相支持。材料中大量出现日期区间、数量区间、责任方与状态描述，解析与分块需要让这些条件与所约束的内容保持在同一数据块内，避免条件与结论被拆到不同块后无法回指原文。

## 这些特征在「文档解析与分块」这一环带来什么约束
分块完整性直接影响比对结论。若排班表中的日期范围与人员数量被拆开，检索到的片段可能只显示数量而丢失适用期间，导致比对时把不同场次的数据放在一起判断。FastGPT 的向量存储结构中，MongoDB 的 dataset.datas 表存储向量原数据，indexes 字段记录对应的向量 ID，一组原数据可以对应多个向量；检索时先召回向量，再按向量 ID 回到原数据，同一组原数据命中多路时合并并取最高得分。这意味着同一份材料可以建立多组索引以提高召回精度，但索引本身不改变原数据内容，也不构成对材料真实性的核验。最低相关度仅在语义检索或结果重排时生效，它是过滤阈值，不承担主体隔离或权限过滤功能。检索是对整个库进行，集合仅用于分类管理，与搜索效果无关。

## 配置怎么定
以下配置围绕假设演练样本，仅列与本页主任务相关的已说明设置或实施核对项。数值均为本次假设试验起点，用于说明比较方法，不代表官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 材料含编号与自然语言描述，需同时观察语义召回与关键词命中；与单独语义检索的召回片段比较 |
| 引用上限 | 假设设为 3000 tokens | 样本材料含日期区间与数量字段，需容纳完整条件句；与 1500 tokens 时是否截断条件句比较 |
| 最低相关度 | 假设设为 0.35 | 用于观察低相关片段是否被过滤；与 0.2 时返回片段数量及内容比较 |
| 问题优化 | 假设开启 | 样本拟稿句含指代，需观察补全后检索词是否包含主体与期间；与关闭时检索词比较 |
| 分块边界核对 | 人工核对 | 检查日期范围与数量是否同块；与拆分为两块后的检索片段比较 |
| 训练状态核对 | 人工核对 | 上传成功后核对实际训练与索引状态；与仅查看上传成功提示比较 |

## 容易做错的三处
1. 把上传成功当作检索已更新。材料重新上传后，训练与索引状态需要单独核对。若只看到上传完成提示就用于比对，可能仍检索到旧版本片段。检查方式：输入材料中新增的字段值，比较返回片段是否包含该值；若返回旧值或不返回，记录为待核实。
2. 把最低相关度当作权限或主体过滤。最低相关度是相似度阈值，不排除无关主体或未授权记录。检查方式：用样本中不同主体的名称检索，观察返回片段是否包含其他主体内容；若包含，记录该现象，不推断为权限失效。
3. 把混合检索的 RRF 融合写成开关或独立步骤。RRF 是多个召回渠道结果的融合过程，不是可开启的配置项。检查方式：核对配置界面是否存在名为 RRF 的开关；若无，记录为文档未说明该开关，不自行添加。

## 怎么确认配好了
假设演练样本：材料原文为“甲方：某仓储服务部；乙方：某快递商务组；保障期间：2025年11月1日至2025年11月15日；日揽收能力：不低于8000件。”拟稿句为“该快递商务组在保障期间内日揽收能力为8000件。”比对任务为判断拟稿句是否被材料原文支持。

- 验证一：输入拟稿句“该快递商务组在保障期间内日揽收能力为8000件”，比较材料原文中同一主体、同一期间、同一字段的取值。原文写“不低于8000件”，拟稿句写“为8000件”，两者为同字段的不同取值表述，拟稿句未获原文支持。观察返回片段是否同时包含主体、期间与数量字段；若片段缺失期间，需回到原数据核对分块边界。

- 验证二：输入材料原文中的编号或术语“2025年11月1日至2025年11月15日”，比较返回片段是否包含该日期区间及所约束的数量字段。若返回片段只有日期而无数量，记录为分块可能拆离条件与内容，需人工核对原数据。

- 验证三：输入一个材料中未出现的查询词，比较返回结果。预期可能返回空结果或低相关片段，不保证空结果。若返回片段包含无关内容，记录实际观察，不推断为过滤失效。空结果情形可用明确的纸面输入核对下游设计，不声称虚构规则检索一定返回空数组。

以上验证仅描述预期与比较方法，未实际执行，不构成对任何系统行为的确认。
