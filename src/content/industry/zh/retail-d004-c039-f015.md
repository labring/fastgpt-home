# 天猫旗舰店日常运营的合同与交易材料比对：知识库检索与召回

## 这个品类的数据长什么样

天猫旗舰店日常运营围绕品牌授权、旗舰店身份和天猫积分赔付规则展开，资料来自天猫商家后台、天猫规则中心、ERP订单表与客服聊天记录。合同与交易材料比对要处理的文档包括商品发布页、品牌授权书、发货承诺记录和售后工单。这些材料的更新频率为日、每单，检索时面对的是同一业务对象在不同文档中主体、期间与字段取值是否一致的问题。品牌授权书载明授权方、被授权方、授权品牌与有效期间；发货承诺记录载明订单号、承诺发货时间与实际发货时间；售后工单载明工单号、关联订单与处理状态。检索环节只负责把相关材料召回为引用内容，不承担授权判定、赔付计算或数据库写入。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可以关联一个或多个使用相同向量模型的知识库，引用内容以数组输出，长度可以为 0，没有搜索到内容时输出链路依然走通。搜索模式分为语义检索、全文检索与混合检索，混合检索通过 RRF 合并多路结果，结果重排使用 ReRank 模型进行二次排序。最低相关度仅在语义检索或使用结果重排时生效，引用上限以 token 为单位。问题优化用于指代消除和问题扩展，会在正式检索前增加一次模型调用。相似度分数是相关性度量，不构成权限或实体隔离，检索库同向量模型的要求只适用于关联知识库，不扩展到外部系统。

假设演练样本：某天猫旗舰店运营人员准备核对一份品牌授权材料与一条交接请求。知识库中一份品牌授权书原文为：“授权方：某某品牌管理有限公司；被授权方：某某电子商务有限公司；授权品牌：某某；授权有效期间：2025年1月1日至2025年12月31日。”同一知识库中一份发货承诺记录原文为：“订单号：20250101XXXX；承诺发货时间：2025年1月3日18时前；实际发货时间：2025年1月4日10时。”待判定的拟稿句为：“该店铺在授权有效期间内已完成全部订单发货，无延迟发货情形。”需核对的交接请求为：“请确认上述品牌授权材料可用于2025年1月订单的延迟发货判定。”

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅关联一个使用相同向量模型的知识库 | 先核对各库向量模型标识，标识相同的库才可共同关联，标识不同者排除并记录 |
| 搜索模式 | 先分别以语义检索与全文检索运行同一测试问题 | 比较两种模式对授权期间、订单号、发货时间等字段的召回差异，再决定是否使用混合检索 |
| 引用上限 | 设为覆盖一份授权书与一份发货记录所需的 token 量 | 以长短不同的实际材料测试引用内容是否完整，逐步调整该起点 |
| 最低相关度 | 先标注相关样本与无关样本，再取一个 0 至 1 的起点值 | 仅在语义检索或使用结果重排时生效，比较过滤后相关样本是否保留 |
| 问题优化 | 先关闭，再与开启后的结果比较 | 核对优化后问题是否保留授权主体、订单号与期间，主体被改错时记录 |
| 结果重排 | 具备 ReRank 模型时按设置启用，与未启用结果比较 | 重排后得到 0 至 1 的得分，比较候选排序变化 |

## 容易做错的三处

1. 把检索命中当作授权或赔付判定。输入为假设样本中的授权书原文与拟稿句，比较检索返回的引用内容与拟稿句是否同主体、同期间、同字段，观察到的现象是引用内容只包含授权期间与发货时间，拟稿句中的“已完成全部订单发货，无延迟发货情形”在材料中没有对应字段支持。
2. 把最低相关度当作权限或实体过滤。输入为同一测试问题与一个 0 至 1 的最低相关度取值，比较过滤前后返回的引用内容，观察到的现象是过滤只改变相关度排序结果，未授权记录是否被召回不由该数值决定。
3. 把待审核的交接请求当作已批准。输入为假设样本中的交接请求，比较请求文本与任何批准记录，观察到的现象是请求只表达核对意图，没有批准主体与批准时间，该请求处于待处理状态。

## 怎么确认配好了

1. 输入假设样本中的授权书原文、发货记录原文与拟稿句，比较拟稿句中的主体、期间与字段是否能在引用内容中找到对应取值，观察到的现象是拟稿句超出材料记载范围，判定为未获支持，需保留证据缺口。
2. 输入假设样本中的交接请求，比较请求内容与知识库中是否存在批准记录，观察到的现象是仅存在请求文本，没有批准记录，该请求为待处理，不构成授权执行。
3. 以空数组作为纸面输入核对下游设计，比较引用内容输出长度为 0 时下游链路是否仍走通，观察到的现象是输出链路继续执行，不声称虚构规则检索一定返回空数组。
