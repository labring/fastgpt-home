# 平台促销报名与价格管理的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在平台促销报名与价格管理的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。保留活动素材提交许可与费用、生效条件的不同条款，不借用上一场授权。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

活动协议练习可拟授权条款“可提交本场素材；费用口径与生效时间依另函确认”，补充便笺只记录素材已准备。上一场历史函曾写确认生效，本场确认函尚未给出。比对时若上下文只留下可提交，就容易把素材报送许可扩大成活动费用和执行时间均已定。应核本场、许可事项及另函前提在实际请求中是否连在一起；准备素材不是提交，也不能证明活动已经运行。当前纸面条件不包含真实费用数值或付款安排。

## 配置怎么定

| 活动条款上下文 | 原文范围 | 核验动作 |
| --- | --- | --- |
| 有限许可 | 仅可提交本场素材 | 保留许可事项与活动身份。 |
| 另函前提 | 费用和时间尚待确认 | 查实际输入有无前提。 |
| 历史函件 | 上一场已确认 | 不能用来确定本场期间。 |
| 准备记录 | 素材已准备 | 不升级为提交或运行。 |
| 补入本场函 | 适用事项及期间 | 同题核改变的结论。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

- 另函确认从输入丢失，比较结论却称费用与时间已定时，并列完整条款和实际传入，找前提裁剪的位置。

- 本场追问复用了上一场生效函时，保持当前材料不变比较历史条件，核活动身份、函件版本与适用期间。

- 素材准备记录被表格列成活动执行凭据时，核记录动作和真实执行资料，字段可解析不产生新事件。

## 怎么确认配好了

验收分别问许可提交什么、费用依据在哪里、什么资料能够确认生效，逐句查看真实输入。取得本场确认函后，核其活动、适用事项和期间，再重复原题，不以文件收到较晚推断活动较晚生效。知识引用的token预算与回复上限分开核，实际模型上下文能力也另有范围。验收关注必要前提是否送达并被采用，不能只用回答变长或流程有响应作为通过依据。
