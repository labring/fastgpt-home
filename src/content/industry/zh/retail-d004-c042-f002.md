# 平台商品标题与详情合规的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在平台商品标题与详情合规的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。核素材参考与最终规格说明的适用层级，检查长条款和历史标题在请求中的位置。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

商品说明协议练习可拟条款“供稿方提供素材参考；对外规格以该款最终说明书核对”，附件只有画面建议，最终说明书尚缺。上一款标题在历史中曾用“静音”，本款材料没有对应性能说明。比较协议与拟议详情页时，应核供稿用途、该款限定及说明书前提是否实际进入上下文。画面建议可以支持素材选择，不能由合同谈到规格就补出具体性能，也不能沿用上一款修饰词。这里的静音只是历史拟稿用词，不是商品已验证属性。

## 配置怎么定

| 商品条款上下文 | 自拟材料 | 检查动作 |
| --- | --- | --- |
| 供稿用途 | 仅素材参考 | 核请求保留用途限定。 |
| 规格依据 | 该款最终说明书尚缺 | 引用不能遗漏前提。 |
| 历史款式 | 上一款标题有静音 | 核本款是否真有属性依据。 |
| 结构化对照 | 画面建议与性能证据 | 解析后查资料性质。 |
| 新增说明书 | 本款对应版本 | 原题查看支持范围改变。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

- 以最终说明书核对的前提被引用裁去时，并列协议原句、引用片段和实际请求，核规格依据在哪里丢失。

- 追问“这款能用旧标题吗”带入上一款静音时，固定本款附件对照空历史和带历史，核款式与版本指代。

- 结构化对照把画面建议归为性能证明时，核资料性质与原句用途，解析成功后仍需查每项结论依据。

## 怎么确认配好了

验收分别问供稿方给了什么、对外规格要依哪份资料、当前是否具备该款说明书，并追到实际输入。补说明书后先核款式及版本，再比较原有待核项获得了什么支撑。模型上下文能力、知识引用token上限与回复长度分别检查，不把一次短请求成功当成完整窗口实测。输出应保留素材参考和规格证据的层级，不由合同比对替代真实商品性能核查。
