# 平台广告投放与站内流量的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在平台广告投放与站内流量的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。追踪投放委托中的素材确认、预算待定与执行通知，防止历史活动结果借入本次条款。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

投放委托练习可拟条款“确认本版素材方向，执行范围待通知，预算另议”，附件仅列画面建议，没有执行通知。上一活动的历史讨论曾确认交付。比较本次委托与素材页时，应核确认所针对的只是素材方向，不能把同句后半段待通知和另议裁掉。画面建议、预算约定与执行结果属于不同资料，合同没有给的安排仍需待核。这里没有真实投放金额或效果数据，确认素材方向也不说明广告已经运行。

## 配置怎么定

| 投放委托上下文 | 自拟条款 | 检查动作 |
| --- | --- | --- |
| 确认对象 | 本版素材方向 | 不延伸到全部执行安排。 |
| 通知缺口 | 执行范围待通知 | 核实际引用保留后半句。 |
| 预算状态 | 仍需另议 | 不能由画面建议补依据。 |
| 历史活动 | 上一活动已交付讨论 | 核本次指代及阶段。 |
| 对照字段 | 素材、预算、执行 | 解析后逐项查来源身份。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

- 执行范围待通知在实际引用中缺失时，对照完整委托、引用及请求，核素材确认是否被扩大成执行全部已定。

- 追问本次是否交付串入上一活动历史时，固定当前委托比对历史条件，核活动身份与执行阶段。

- 可解析的对照结果将画面建议填成预算依据时，核资料用途及预算约定原句，字段有值不代表有来源。

## 怎么确认配好了

验收分别问确认了哪版素材、执行范围和预算是否给出、有无本次通知，逐句回查实际输入。补入通知或预算材料时，各自核本次活动与适用范围，再复用原题，保留仍未得到依据的项。上下文能力按实际模型配置核，知识引用上限与回复长度分开检查。输出越长不说明委托全部送达，整齐对照表也需逐项核素材、预算与执行的来源身份。
