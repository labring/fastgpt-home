# 平台类目资质准入的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在平台类目资质准入的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。核准入材料整理委托的文件目录、适用主体与补件通知，避免将收件清单写成审核结论。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

类目资料整理练习可拟委托“按本经营主体整理目录，缺项由资料提供方补充；平台审核另行进行”，附件是一份已收文件名清单，不含审查结果。历史轮次出现过另一主体的补件通知，当前主体的同名文件仍待核页内信息。目录记录文件收到与否，不能单凭名称说明适用对象、有效期间或审核状态。长附件的末尾若裁掉平台另审这一句，回答就可能误把受托整理范围解释成准入承诺。这里仅比较自拟文字，不规定任何平台类目的真实准入条件。

## 配置怎么定

| 资料委托上下文 | 当前文本 | 核对动作 |
| --- | --- | --- |
| 委托范围 | 按本主体整理目录 | 保留平台另审说明。 |
| 收件清单 | 只有文件名及收件状态 | 不写成有效性判定。 |
| 历史通知 | 另一主体补件 | 核通知对象和轮次。 |
| 页内证明 | 主体期间尚待回读 | 解析后查真正内容。 |
| 结果材料 | 当前未提供 | 不补驳回或准入结论。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是委托尾部的另审说明从引用中消失，应核完整页末、引用位置及实际请求，查整理动作是否被扩成审核职权。第二处是旧轮次另一主体的补件通知进入本题，应对主体名称和通知对象，再比较有无历史的输入，不能按相同文件名继承状态。第三处是已收目录的文件名被结构化填为有效证明，应回读相应页内主体和期间及当前审核依据；字段能解析不表示证明已经成立。三项各留原句和对象，缺页时标明需要的材料。

## 怎么确认配好了

验收分别列出本主体已收到什么、仍待补什么、哪份材料能够说明审查状态。补入文件后先核页内主体、期间和用途，再用原题比较，不由上传时间推有效时间。引用预算按token检查关键限定的送达情况，模型窗口与回复上限另核，不预设特定数字。最终对照保留目录、证明内容与审查结果三个层次；没有结果材料时，保持状态待核，不从缺件推出正式驳回，也不从目录完整推出已经准入。
