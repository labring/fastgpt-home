# 平台退款退货处理的合同与交易材料比对：权限与数据隔离

## 这个品类的数据长什么样

在平台退款退货处理的合同与交易材料比对中，本页说明FastGPT的权限与数据隔离如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

退款审批附页说明某项退款金额已经获批，只能据此核对审批文字，不能推定资金已经退回，也不说明当前账号获准查看全部交易资料。要比对退款条款，应分别列出申请、审批及相关订单或合同资源，核账号对每份原文的实际读取范围。客服、售后专员和仓库质检是业务从业主体，各自在系统里拥有的权限仍需实测，不能从称谓直接推断。

## 配置怎么定

| 权限或实施核对项 | 退款资料的对象 | 实际取证 |
| --- | --- | --- |
| 审批文字 | 获批记录不等于已执行退款 | 不推定资金退回 |
| 独立资源 | 申请、审批、订单或合同分别列清 | 核各份原文的读取范围 |
| 业务阶段 | 期望金额与批准金额可能不同 | 先核同一事项及各自含义 |
| 外部来源 | 支付及仓库资料另行授权 | 内部角色不替代外部鉴权 |
| 新增资料 | 有权和无权账号访问同一资源 | 记录读取、拒绝及仍缺依据 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 仅能看退款申请却据此核准适用条款：核订单、合同及审批原文是否提供并获权，不能用已见申请补另一个来源。

- 不应获权身份读到审批材料：保存真实可见内容、账号及资源设置，能生成退款说明不代表访问核验通过。

- 审批文字可读被写成资金已退或全流程完成：回查支付结果及外部鉴权，批准与执行是不同证据，申请批准差异也不必然是错误。

## 怎么确认配好了

退款申请没有原始订单或合同，仍不足以核对适用退款条款。应先确认这类资料是否存在以及当前身份是否有权取得；需要支付或仓库系统内容时，外部鉴权单独核对。补入资料后，用获授权与未获授权账号访问同一资源，检查新增内容是否落在正确范围内。验收保留读取或拒绝结果，并标明仍缺哪些交易依据，不由回答能复述审批文字推定整个退款流程已经完成。

| --- | --- |
| 文档类型 | 退款申请、退货物流单、质检照片、退款审批 |
| 候选来源 | 平台售后后台、客服聊天、WMS收货、支付退款记录 |
