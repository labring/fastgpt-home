# 快递面单与揽收交接的合同与交易材料比对：工具调用与插件

## 这个品类的数据长什么样

在快递面单与揽收交接的合同与交易材料比对中，本页说明FastGPT的工具调用与插件如何衔接资料。面单、交接清单和揽收扫描支持不同阶段，需要同包裹对应后再解释差异。所用场景为自拟文字测试。

## 这些特征在「工具调用与插件」这一环带来什么约束

快递交接材料比对可先读面单、清单与扫描原句，不提供服务标准或时效判断。自拟输入只有面单和交接说明，没有本包裹扫描依据；拟议工具只定位给定文字。参数保留包裹和批次，不从一张清单覆盖范围推定所有包裹已揽收，也不把异常登记直接当丢件结论；工具介绍需写清这些输入条件，不保证每次都会调用。

## 配置怎么定

| 交易比对核对 | 本题自拟材料 | 实际取证 |
| --- | --- | --- |
| 包裹批次 | 扫描与当前包裹身份 | 他批记录未代填 |
| 揽收阶段 | 面单生成与实际扫描分开 | 未写成承运已接 |
| 异常性质 | 登记情况与核查结论 | 未直接判责任 |
| 真实请求 | 所需文字及实际调用 | 不由介绍推已执行 |
| 后续确认 | 赔偿或关闭另核授权 | 比对未代替物流结果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `工具介绍` | 介绍用途、输入和不适用情形。 |
| `工具参数` | 模块及插件参数分别核对。 |
| `必须参数` | 缺合适必参时模型可能不调用。 |
| `工具连接` | 可用工具须连接到调用模块。 |
| `工具调用终止` | 结束调用，不再进行后续AI总结。 |

## 容易做错的三处

包裹错配：若其他批次扫描套本件，应核身份及来源；建单冒揽收：若面单生成被写成承运方已接，应查本件实际扫描；登记冒结论：若异常记录被当责任确定，应追所记情况及后续核查。三项分别核对象、物流阶段与证据范围，不由标题补出。

## 怎么确认配好了

验收对照真实请求、调用工具及引用，补本批扫描后复问，核解释实际采用新依据。缺适合必须输入时可能不调用，应交互取得后查看实际请求，先接少量工具。终止后不再调用AI总结本次结果；交接确认、赔偿或异常关闭需另验授权及业务回执，文本比对不证明包裹丢失、已送达或责任已经裁定。
