# 快递面单与揽收交接的合同与交易材料比对：知识库检索与召回

## 这个品类的数据长什么样

快递面单与揽收交接发生在包裹离仓节点，承运商扫描是责任转移的关键动作。主要材料包括电子面单、交接清单、揽收扫描记录和异常件登记，来源为快递系统、WMS发运、GB/T快递服务标准与承运商账单。数据按每批和每日更新。

合同与交易材料比对任务要求把面单、清单、扫描记录和异常登记放在同一主体、同一期间、同一字段下核对。检索环节只负责从知识库中召回相关材料原文，不判断授权状态，也不执行交接或发货。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，应先核标识并排除不符合者。引用内容以数组输出，长度可以为 0，没有搜索到内容时输出链路仍走通。

搜索模式可选语义检索、全文检索或混合检索。混合检索通过 RRF 融合多路结果，RRF 是融合过程，不是独立开关。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不是排序规则，也不承担权限或实体隔离。引用上限以 token 为单位。问题优化用于指代消除和问题扩展，会额外调用模型。图片检索需要图像输入及相应模型能力，重排需要模型且按设置启用。

假设演练样本：某仓库发运组留存一份交接清单原文，内容为“2025年3月10日，发运组将批次B-0310的40件包裹交予承运商网点，面单号段SF3100001至SF3100040，揽收扫描记录显示其中38件已扫描，2件登记为异常件”。另有一条待判定拟稿句：“该批次全部包裹已完成揽收交接。”核对对象为交接清单、揽收扫描记录与异常件登记三份材料。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 面单与交接材料库 | 核对其向量模型标识一致后再关联，排除标识不符者 |
| 搜索模式 | 混合检索 | 面单号段与专有名词需要全文命中，语义描述需要向量召回，比较两种模式单独召回与混合召回的结果差异 |
| 引用上限 | 假设起点 2000 token | 交接清单与扫描记录合计较长，用长短不同的实际材料测试内容是否被截断，再与更大或更小值比较完整性 |
| 最低相关度 | 假设起点 0.3 | 先标注相关与无关样本，比较不同阈值下无关片段的保留情况 |
| 问题优化 | 开启 | 多轮追问中比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 按设置启用 | 候选较多时比较重排前后排序，确认重排得分可用于过滤 |

以上数值为本次假设试验起点，不是官方默认值。

## 容易做错的三处

1. 把检索召回当作授权确认。输入为拟稿句“该批次全部包裹已完成揽收交接”，比较对象为交接清单与扫描记录，若清单载明40件而扫描记录仅38件已扫描、2件异常，则该拟稿句未获支持。检索到材料不表示交接已完成。
2. 把不同向量模型的库强行共同关联。输入为两个知识库标识，比较其向量模型字段，若标识不一致则排除，不执行跨模型检索来比较漏召回。
3. 把最低相关度当作权限或实体过滤。输入为无关企业名称查询，比较返回内容是否仅由相似度决定，若返回了不相关片段，说明该阈值不承担隔离功能，应记录实际观察。

## 怎么确认配好了

1. 输入假设样本中的交接清单原文与拟稿句“该批次全部包裹已完成揽收交接”，比较拟稿句与清单、扫描记录、异常登记的字段取值。只有三份材料在同一主体、同一期间、同一字段下取值一致时，该拟稿句才获支持；38件已扫描与2件异常属于未获支持，需记录证据缺口。
2. 输入面单号段“SF3100001至SF3100040”执行全文检索，比较返回内容是否包含该号段原文。若返回为空数组，用纸面输入[]核对下游设计，不声称虚构规则一定返回空。
3. 输入一个跨向量模型的知识库组合请求，比较两个库的向量模型标识。标识不一致时排除该组合并记录，不继续推断共同关联后的运行结果。

待审核不证明缺少操作权限，签署、合作达成与合同生效是三个不同事实。检索与表单收集值，业务验证、审批、数据库写入与外部同步需要各自的下游实现。
