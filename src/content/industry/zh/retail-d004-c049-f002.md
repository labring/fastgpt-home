# 批发市场档口交易的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在批发市场档口交易的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。核档口订货便笺的样品、货批和尾页限定，防止口头简称或旧批确认扩大本批交易范围。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

档口交易材料练习可拟订货便笺“按展示样布核色，成衣批次待看货确认；衣架只作展示”，另有样布照片说明。前文讨论过上一批已经取货，本批看货记录尚未给。比较便笺、照片与交接栏时，样布只提供核色参照，不能单凭相似画面确定成衣整批品相；展示衣架也未被列成交易物。若长便笺尾句未进入请求，回答可能把展示用具并入供货。应保留所指货批和文本用途，不在自拟案例里补价格、付款或实际成交承诺。

## 配置怎么定

| 档口便笺上下文 | 自拟范围 | 实际核查 |
| --- | --- | --- |
| 样布参照 | 只用于核色 | 不替成衣整批品相。 |
| 展示衣架 | 只作展示 | 引用保留尾句用途。 |
| 当前货批 | 看货记录尚缺 | 不补确认或缺陷结论。 |
| 历史取货 | 上一批已取讨论 | 核这批与动作归属。 |
| 新增看货页 | 批次及所检项目 | 逐项更新有据判断。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是衣架只展示的尾句被引用裁掉，应对便笺末段、照片说明和实际请求，查供货范围为何扩大。第二处是追问这批取了吗借用上一批历史，应固定本批便笺比较空历史与带历史，核批次和取货动作归属。第三处是样布核色被结构化对照写成整批品相已确认，应回到样布用途及本批看货记录，解析后逐项查色样、成衣与确认阶段。三项分别核展示范围、批次指代和样品证据层级，不能用同一张照片补齐。

## 怎么确认配好了

验收分别问样布能支持哪项对照、衣架是什么用途、本批是否有看货与取货记录。取得本批看货页后先核货批及所检项目，再比较哪些判断新增依据，未列项目继续待核。引用token预算、回复长度及实际模型上下文能力分开检查，不以回答缩短就认定便笺尾句保留。这里演示文书对应，不评定商品质量，也不从缺看货页反推本批存在缺陷或没有发生交易。
