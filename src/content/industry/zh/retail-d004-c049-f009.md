# 批发市场档口交易的合同与交易材料比对：工具调用与插件

## 这个品类的数据长什么样

在批发市场档口交易的合同与交易材料比对中，本页说明FastGPT的工具调用与插件如何衔接资料。档口订单、手写记录、租赁和收款资料各有对象，先取得可读原文再比较交易。所用场景为自拟文字测试。

## 这些特征在「工具调用与插件」这一环带来什么约束

档口交易比对可先收进货单、手写销售文字与收款凭据相关段落，不写金额或真实凭据值。自拟输入没有全部交付与支付确认，拟议工具只读已给文本，手写转成可读原文须实际实现。参数保留交易双方和商品，不把摊位租赁主体直接当实际交易方，也不从收据标题推定本次款项已全部核实。

## 配置怎么定

| 交易比对核对 | 本题自拟材料 | 实际取证 |
| --- | --- | --- |
| 交易角色 | 租赁方与实际卖方分开 | 核双方关系原文 |
| 可读内容 | 手写原件与转写依据 | 不预设识别已完成 |
| 凭据身份 | 本单与他单收据 | 核交易对应后再读 |
| 实际调用 | 必需文字和真实请求 | 缺项未由标题代填 |
| 业务履行 | 修改收款及回写另验 | 比较未替代账务确认 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `工具介绍` | 介绍用途、输入和不适用情形。 |
| `工具参数` | 模块及插件参数分别核对。 |
| `必须参数` | 缺合适必参时模型可能不调用。 |
| `工具连接` | 可用工具须连接到调用模块。 |
| `工具调用终止` | 结束调用，不再进行后续AI总结。 |

## 容易做错的三处

主体混同：若租赁方被当本单卖方，应核交易原句及双方关系；手写误读：若文字没有可靠转写却输出确定商品，应回看原件与可读依据；收据错套：若他单凭据填本单，应核交易对应。三项分别核角色、内容和记录身份，不由参数非空补出。

## 怎么确认配好了

验收保留原件来源、可读文字、真实请求与返回引用，补对应交付或确认后复问，核解释仍回指本交易。缺适合必须输入可能不调用，应交互收集后查实际请求，先连接少量所需工具。终止当前调用后无后续AI总结；订单修改、收款确认或外部回写另验业务授权与回执，比对不证明交易已履行或账务已对平。
