# 抖音小店货架运营的合同与交易材料比对：知识库检索与召回

## 这个品类的数据长什么样

抖音小店货架运营围绕商品卡与店铺体验分展开，日常材料包括商品资质页、体验分明细、发货违规申诉、店铺公告。这些材料的更新频率为日、每单。合同与交易材料比对要处理的对象是资质页中的许可范围、体验分明细中的判罚记录、申诉中的处理状态、公告中的生效表述，检索环节需要把同一主体的同一字段放在一起核对。

材料状态差异明显：资质页可能处于待审核，申诉可能处于已提交待处理，公告可能处于草稿。检索返回的文本只说明资料被召回，不说明审核通过、申诉成立或公告生效。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的库。跨不同向量模型的库不可共同关联；发现向量模型标识不一致时，先核标识并排除不符合者，记录实际观察，不执行跨模型检索来比较漏召回。

搜索模式分语义检索、全文检索、混合检索。语义检索按向量距离算相似度，适合自然语言问法；全文检索按关键词命中，适合编号、型号、专有名词；混合检索同时使用两路并通过 RRF 融合。RRF 是混合结果融合过程，不是可开启的开关。重排须具备 ReRank 模型并按设置启用，重排得分为 0-1。最低相关度仅在语义检索或使用结果重排时生效，属于过滤阈值，不承担权限或实体隔离。

引用上限按 token 计，输出引用内容以数组格式给出，长度可以为 0。空结果时输出链路仍走通。问题优化用于指代消除和问题扩展，在正式检索前增加一次模型调用。

假设演练样本：某抖店商家就同一商品提交的资质页原文为“主体：甲商户；对象：某款保温杯；状态：待审核；许可范围：食品接触用”。同店铺公告原文为“主体：甲商户；对象：某款保温杯；生效日期：2025年3月1日；内容：该商品已具备食品接触用销售资质”。拟稿句为“甲商户该款保温杯的食品接触用销售资质已审核通过并生效”。

## 配置怎么定

| 配置项 | 本页设定 | 依据与核对方式 |
| --- | --- | --- |
| 关联知识库 | 仅关联向量模型标识一致的资质页、体验分明细、申诉、公告库 | 逐一核对向量模型标识，标识不符者排除 |
| 搜索模式 | 本次假设试验起点为混合检索 | 资质编号类问法比较全文命中，自然语言问法比较语义命中 |
| 引用上限 | 本次假设试验起点为 2000 token | 依据材料长短差异选取，与较短上限比较内容是否完整 |
| 最低相关度 | 本次假设试验起点为 0.4 | 先标注相关与无关样本，再与相邻取值比较过滤效果 |
| 问题优化 | 多轮追问、短问题场景启用 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 候选较多且具备 ReRank 模型时启用 | 比较重排前后排序，用 0-1 得分核对 |

## 容易做错的三处

1. 把检索召回当作授权结论。拟稿句写“已审核通过并生效”，资质页只写“待审核”，公告只写生效日期。输入为上述两段原文与拟稿句，比较同一主体、同一对象下“状态”字段取值，资质页“待审核”与拟稿句“已审核通过”在同一字段上互斥，判定为未获支持。检索命中不改变这一结论。
2. 把报价有效期当作供货期限。材料只写报价有效期时，供货期限未载明，属于证据缺口，不能据此判定供货义务成立或不存在。
3. 把不同向量模型的库强行关联。输入为两个库的向量模型标识，比较标识是否一致，不一致时排除，记录实际观察，不断言关联后的运行结果。

## 怎么确认配好了

1. 输入假设样本中的资质页原文、公告原文与拟稿句，比较同一主体、同一对象、同一字段“状态”的取值，资质页为“待审核”、拟稿句为“已审核通过”时，判定为未获支持，同时记录公告仅载明生效日期、未载明审核结论。若检索未返回资质页，记录为召回缺口，不判定拟稿句成立。
2. 输入一条仅含报价有效期的材料原文与一条询问供货期限的拟稿句，比较拟稿句是否出现供货期限表述，材料未载明该字段时判定为待核实，不判定为否定或冲突。
3. 输入两个知识库的向量模型标识，比较标识是否一致，标识不一致时排除该库并记录；输入明确的纸面空结果 []，核对下游设计对空引用的承接方式，不声称虚构规则检索必然返回 []。

签署、合作达成、合同生效是三个不同事实。待审核、待处理、草稿均不构成审批完成。检索与表单收集数值，业务核验、审批、数据库写入与外部同步需要各自的下游实现。
