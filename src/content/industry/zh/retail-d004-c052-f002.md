# 拼多多低价活动店铺运营的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在拼多多低价活动店铺运营的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。检查低价活动准备条款中的待核报名、价格备注与执行前提，防止旧轮次状态进入当前判断。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

活动准备文本可自拟“整理拟报商品，价格以本轮确认页为准；收到入选通知后再排素材”，现附候选清单和供内部讨论的价格备注，没有本轮确认页及入选通知。历史对话有上一轮已入选记录。本题比较准备约定和材料，不计算实际售价或折扣，也不说明平台活动准入规则。候选商品进入表格只表示拟报范围；备注用于讨论的数字位置即使被完整传入，也不自动成为对外价格。长条款应保留本轮与收到通知后两个限定。

## 配置怎么定

| 活动准备上下文 | 材料范围 | 对应核验 |
| --- | --- | --- |
| 拟报清单 | 只列候选商品 | 不认作入选结果。 |
| 价格备注 | 内部讨论用途 | 另核本轮确认页。 |
| 排期前提 | 收到入选通知后 | 请求不能遗漏条件。 |
| 历史记录 | 上一轮已入选 | 核当前轮次对象。 |
| 新增本轮通知 | 覆盖商品与阶段 | 不自动确定价格。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是收到通知后在请求中丢失，应核准备约定全文与实际引用，查素材排期是否被提前写成已获执行许可。第二处是本轮入选了吗借用了旧轮次记录，应固定候选清单比较有无历史的输入，核轮次和通知对象。第三处是内部价格备注被结构化填成确认价格，应对备注用途、当前确认页及输出字段，解析后仍查适用范围。三项分别处理条件丢失、轮次串用和价格资料层级，不靠更多候选行证明入选。

## 怎么确认配好了

验收分别问拟报什么、价格依据是哪页、何种材料能支持后续排期，并展开实际输入。取得本轮通知只更新它覆盖的商品及阶段，价格仍依对应确认页核；补件不必令所有待核项同时变为已定。知识引用token预算与回复长度分开记，模型上下文按实际配置检查，不把答复变短当作前提未丢的证明。示例仅演示材料比对，不报名、不定价或执行活动，也不由通知缺失推断正式落选。
