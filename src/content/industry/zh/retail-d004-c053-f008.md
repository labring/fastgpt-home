# 渠道应收账款催收的合同与交易材料比对：工作流编排

## 这个品类的数据长什么样

在渠道应收账款催收的合同与交易材料比对中，本页说明FastGPT的工作流编排如何衔接资料。对账约定、返利复核与对方收件分别承接，合同比对不确认付款或抵扣。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟对账约定只覆盖本季发货，返利事项另行复核，对方邮件仅确认收到清单。工作流先核本季资料与合同范围，再把返利缺项留给后续核对。收件邮件可以说明材料到达，不能作为余额认可或付款完成；不同期间的历史结算也不能补本季结果。流程可分开整理条款和请求缺项，但要保留期间、事项和陈述方，不能合成一项已结状态。

## 配置怎么定

| 对账合同路径 | 自拟范围 | 所需核对 |
| --- | --- | --- |
| 本季发货 | 合同所指期间 | 不借旧期 |
| 返利事项 | 另行复核 | 不并余额 |
| 收件邮件 | 收到清单 | 非款项 |
| 节点输入 | 期间事项陈述方 | 分别保留 |
| 真实处理 | 确认付款抵扣 | 独立记录 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

返利复核项被并入已认可余额时，查原约定与确认范围；旧期结果进入本季时，核期间；清单收件变成到账时，核实际款项凭证。三处分别查事项、时间范围与事件类型。

## 怎么确认配好了

验收逐条比对合同原句、各节点接收与结果，补返利材料只更新对应事项。回复长度不替代原文送达。真实对账确认、付款与抵扣需独立业务权限和记录，工作流比对只能说明已给文字的关系。 本期货款、返利待核与对方确认收件分别记录；后续新增回复需先核究竟确认哪一项，不能泛化为余额认可。
