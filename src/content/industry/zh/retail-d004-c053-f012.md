# 渠道应收账款催收的合同与交易材料比对：文档解析与分块

## 这个品类的数据长什么样

渠道应收催收发生在赊销之后，材料围绕授信、发货、回款三条线展开。应收账龄表按周或按月更新，记录经销商、账期区间与未清金额；授信协议载明额度、账期与生效范围；发货冻结通知对应超授信情形；催款函是沟通动作的载体。合同与交易材料比对要求把销售合同、授信协议与订单、回单放在同一主体、同一期间、同一字段下核对，字段取值互斥才构成矛盾，未载明或仅有相关阶段证据只能记为待核实。

## 这些特征在「文档解析与分块」这一环带来什么约束

分块需要保留主体、对象、金额、期间与状态，条件句与其约束的正文不能拆离。原数据与检索索引分离，同一组原数据可对应多个索引，索引字段记录向量 ID 数组。语义检索依赖向量距离，全文检索依赖关键词命中，混合检索经 RRF 融合多路结果，重排给出 0-1 得分。最低相关度仅在语义检索或结果重排时生效，它是过滤阈值，不承担权限或实体隔离。引用上限以 tokens 计量。图片检索需要图像输入与相应模型能力，重排需要模型且按设置启用，流程图列出的可选路径不代表每次请求全部执行。

假设演练样本：某品牌财务持有《授信协议》摘录，原文为“甲方授予乙方赊销额度人民币八十万元，账期六十天，有效期自二〇二四年一月一日至二〇二四年十二月三十一日”。同批材料含一份订单摘录“乙方于二〇二四年三月十日提交订单，金额人民币九十五万元，发货状态为待发货”。待判定拟稿句为“该经销商本次订单已超出授信额度，应执行发货冻结”。核对需确认协议主体与订单主体是否同一、订单日期是否落在有效期内、额度与订单金额是否为同一字段口径，以及发货冻结是否已有授权文件。

## 配置怎么定

| 配置项 | 本页设定 | 依据与核对方式 |
| --- | --- | --- |
| 检索模式 | 混合检索 | 官方文档说明混合检索同时使用向量与全文并经 RRF 融合，适合编号与自然语言并存 |
| 最低相关度 | 本次假设试验起点 0.4 | 该值为 0-1 数值，仅在语义检索或重排时生效；与样本检索观察到的得分分布比较后调整 |
| 引用上限 | 按 tokens 设定，不设固定数字 | 官方以 tokens 控制引用量，需按实际 chunk 长度观察后确定 |
| 问题优化 | 按实际效果决定是否开启 | 官方说明其增加一次模型调用并提升连续对话检索效果，同时增加耗时 |
| 结果重排 | 具备模型且按设置启用 | 官方说明重排对候选文本二次排序并给出 0-1 得分 |
| 训练状态核对 | 变更后核对实际训练与索引状态 | 上传成功不表示检索已更新，需核对索引是否生成 |

## 容易做错的三处

1. 把最低相关度当作权限或实体过滤。该值是过滤阈值，不排除无关业务或未授权记录，检索本身不构成授权。检查方式：输入同一问题，比较返回内容的业务归属字段，观察是否有非目标主体记录进入候选。
2. 把待审核或已提交当作已批准。拟稿句中的“应执行发货冻结”若只有草稿或待审核状态，不能视为冻结已执行。检查方式：核对审批记录中的状态字段，比较其取值与“已批准”是否一致。
3. 把上传成功当作索引已更新。材料变更后若未核对训练与索引状态，检索可能仍返回旧内容。检查方式：变更后执行样本检索，比较返回内容与新版原文的字段取值。

## 怎么确认配好了

- 验证一：输入假设样本中的授信协议原文与订单原文，比较主体、订单日期与有效期、额度与订单金额三个字段。若主体一致、日期落在有效期内、金额口径相同，则额度与订单金额的比较结果可支持“超出额度”的初步判断；若任一字段缺失，记录为待核实。

- 验证二：输入拟稿句“该经销商本次订单已超出授信额度，应执行发货冻结”，比较其结论与原文可支持的范围。原文仅载明额度、账期与有效期，未载明冻结授权条款，因此“应执行发货冻结”属于未获支持；若下游设计需要空结果承接，可用明确的纸面输入[]核对返回结构，不声称虚构规则必然返回空数组。

- 验证三：以术语“授信额度”、编号类字段与自然语言问法分别检索，比较返回内容的原数据身份与版本。若同一组原数据经多路召回合并，得分取最高值；若返回内容与新版原文不一致，记录为索引待更新。跨不同向量模型的库不可共同关联，需先核对模型标识并排除不符合者，记录实际观察结果。
