# 渠道应收账款催收的合同与交易材料比对：知识库检索与召回

## 这个品类的数据长什么样

渠道应收账款催收发生在赊销之后，授信与现金回收是主线，合同条款与交易凭证必须逐笔对应。主要材料包括应收账龄表、催款函、授信协议、发货冻结通知，来源为财务系统、银行回单、经销商订单和销售合同，更新频率为周或月。合同与交易材料比对这一任务，要求把授信协议中的额度、账期、冻结条件，与订单、回单、账龄表中的实际发生额和状态放在同一主体、同一期间、同一字段下核对。知识库检索与召回在此承担的是把相关条款和凭证片段找出来供比对，检索结果本身不构成授权、审批或业务执行。

## 这些特征在「知识库检索与召回」这一环带来什么约束

检索库由库、集合和数据三级组成，最小搜索单位是库，集合只作分类管理，与搜索效果无关。知识库搜索节点可关联一个或多个使用相同向量模型的知识库；跨不同向量模型的库不可共同关联，应先核对向量模型标识并排除不符合者，不执行跨模型检索来比较漏召回。引用内容以数组输出，长度可以为 0，未检索到内容时输出链路仍走通。

假设演练样本：授信协议原文为“甲方给予乙方信用额度人民币八十万元，账期自发货日起六十日；超额度发货须经甲方书面批准。”经销商订单原文为“本次订单金额人民币九十五万元，发货日二零二四年三月十日。”拟判定句为“该笔订单已获甲方书面批准发货。”账龄表片段为“截至二零二四年三月三十一日，该经销商应收余额人民币九十五万元，账期六十日。”核对时须同主体、同期间、同一字段比较，授信协议载明的批准要求与订单载明的金额、发货日属于不同字段，拟判定句所称书面批准在给定材料中未载明，属于未获支持、待核实，不能据此认定已批准或已拒绝。

## 配置怎么定

下表仅列与本页任务相关的已说明设置或实施核对项。数值为本次假设试验起点，理由与比较对象一并写明，不属官方默认值。

| 配置项 | 本次假设起点 | 理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 授信协议库、订单与回单库 | 两者须使用相同向量模型；先核标识，不符者排除 |
| 搜索模式 | 混合检索 | 与语义检索、全文检索分别跑同一测试问题，比较召回内容 |
| 引用上限 | 按 token 计，起点由长短不同的实际资料试出 | 与资料完整段落比较，观察内容是否被截断 |
| 最低相关度 | 起点由已标注相关与无关样本试出 | 仅在语义检索或使用结果重排时生效；比较过滤前后结果 |
| 问题优化 | 多轮追问、短问题场景开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型且按设置启用时使用 | 比较重排前后候选顺序，得分用于过滤 |

结果重排依赖重排模型，图片检索须有图像输入及相应模型能力，文档总流程图列出的可选路径不代表每次请求全部执行。RRF 是混合检索结果的融合过程，不写成开关。

## 容易做错的三处

1. 把检索命中当作权限或业务授权。输入为一条相似度较高的授信协议片段，比较对象为该片段是否包含批准记录，观察结果为片段仅含额度与账期，缺少批准字段，此时拟判定句仍未获支持。相似度分数不是实体或权限过滤器，检索不构成授权。
2. 跨向量模型关联知识库。输入为两个库的向量模型标识，比较对象为标识是否一致，观察结果为不一致，处理方式是排除并记录，不据此推断漏召回或冗余等运行结果。
3. 把待审核状态写成已完成事实。输入为一份未签署的终止材料，比较对象为是否载明签署与生效字段，观察结果为两项均未载明，结论保持待核实，不写成终止已完成。

## 怎么确认配好了

1. 使用假设样本中的授信协议原文与拟判定句，输入为拟判定句，比较对象为协议中批准字段是否存在，观察结果为未载明，判定为未获支持，满足条件即说明检索未越权补造事实。
2. 使用订单原文与账龄表片段，输入为订单金额与发货日，比较对象为账龄表同期同主体余额，观察结果为金额一致、账期一致，满足条件即说明同字段比对可执行。
3. 使用明确纸面输入空数组，比较对象为下游对引用内容长度为 0 的处理设计，观察结果为下游按空引用继续走通，满足条件即说明空结果承接可用。以上均为纸面核对，未实际执行检索、审批或任何业务动作。
