# 渠道窜货稽查的合同与交易材料比对：权限与数据隔离

## 这个品类的数据长什么样

在渠道窜货稽查的合同与交易材料比对中，本页说明FastGPT的权限与数据隔离如何衔接资料。窜货稽查材料按渠道及案件授权，调查照片可读不代表处罚成立。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

假设渠道投诉单提出疑似跨区销售，防伪码记录待核来源，处罚通知为未发草稿。合同比对需要核稽查人员对合同、照片和码记录分别获何种访问，不能从案件分类推定可读全部渠道材料。照片说明是调查输入，不是处罚结论；合同管理权限也不代替对经销商的处罚批准。此为自拟案件文字，不含真实码值、经销商或执行结果。

## 配置怎么定

| 稽查权限比对 | 假设材料 | 核查边界 |
| --- | --- | --- |
| 投诉 | 疑似跨区 | 不称已证实 |
| 码记录 | 来源待核 | 不填真实码 |
| 照片 | 按案件授权 | 同资源正反测 |
| 通知 | 未发草稿 | 编辑不等于外发 |
| 合同 | 适用渠道 | 不跨渠道推定责任 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 案件标签相同导致另一渠道照片可见时，用同一照片资源测有权和无权账号，核实际角色与文件范围。

- 能编辑处罚通知被写成有权对外发送时，对业务批准、署名主体与实际发出记录，不以编辑权补决定权。

- 防伪码待核被当成窜货已证实时，对记录来源、调查状态及合同适用渠道，缺证据不能由文件可读性补齐。

## 怎么确认配好了

按合同、投诉、照片和通知列明访问用途及需要的读改管权限，优先用自拟样本做成员测试。回答引用也应检查原文地址是否越过资源权限；按文件夹或分类归档不自动建立数据边界。拟处罚前由负责人核案件证据和授权流程，本练习不查询真实防伪系统、不发通知，也不确认违法或违约责任。
