# 特许加盟备案管理的合同与交易材料比对：引用来源与溯源

## 这个品类的数据长什么样

特许加盟备案管理处理法律披露与商务部门系统，不处理具体铺位工程。合同台账、信息披露文件、门店清单和备案材料构成比对工作的主要对象，这些材料的不定期更新意味着同一份合同在不同时期的版本可能并存。引用来源与溯源在此场景中需要回答的问题是：某一句拟稿内容或某一项交接请求，能否在指定材料中找到对应原文，以及该原文的主体、对象、状态和有效范围是否支持该拟稿句。

## 这些特征在「引用来源与溯源」这一环带来什么约束

检索环节的输出是引用数组，长度可以为 0，空数组不代表工作流报错。关联知识库时须核对已选知识库及资料版本，相同向量模型才可共同关联。检索结果是否被采用仍须结合有效版本审核，检索本身不构成授权。

假设演练样本：材料原文为“甲方某某餐饮管理有限公司与乙方某某加盟商于二〇二三年五月十日签署《特许经营合同》，合同编号 HZ-2023-0510，约定备案材料由甲方于签署后三十日内提交商务主管部门。”待判定拟稿句为“该合同已于二〇二三年五月十日生效，甲方已完成备案提交。”原文载明签署日期与提交义务，未载明合同生效条款，也未载明提交已完成。拟稿句中的“已生效”和“已完成备案提交”均未获支持，应标记为待核实。

## 配置怎么定

| 配置项 | 本页相关设置或核对项 | 与样本的关系 |
| --- | --- | --- |
| 关联知识库 | 核对已选库及资料版本，相同向量模型才可共同关联 | 样本合同须位于已选库中且版本可追溯 |
| 搜索模式 | 语义检索、全文检索或混合检索按需选择 | 合同编号适合全文检索，条款语义适合语义检索 |
| 引用上限 | 以 tokens 为单位控制单次引用量 | 样本原文较短，引用上限须覆盖完整条款句 |
| 最低相关度 | 0-1 数值，仅在语义检索或结果重排时生效 | 本次假设起点设为 0.5，因需排除低相关片段，与 0.3 比较观察召回变化 |
| 结果重排 | 具备 ReRank 模型且按设置启用时执行 | 样本候选较少，是否启用依实际配置 |
| 引用内容输出 | 数组格式，长度可为 0 | 空数组时下游须能承接，不视为报错 |

## 容易做错的三处

1. 将检索命中当作授权或生效证明。输入为样本合同原文，比较对象为拟稿句“已完成备案提交”，检索到合同文本仅说明原文存在，不说明提交行为已发生。可观察结果为引用数组包含合同条款，但拟稿句仍缺提交完成证据。
2. 将不同向量模型的库强行共同关联。输入为两个向量模型标识不同的知识库，比较对象为关联条件，可观察结果为关联操作被拒绝或提示不满足条件，此时应排除不符者并记录，不执行跨模型检索来比较漏召回。
3. 将空引用数组判定为工作流故障。输入为一次返回空数组的检索，比较对象为下游节点设计，可观察结果为下游仍走通并输出空引用，须核对下游是否具备承接空数组的能力。

## 怎么确认配好了

1. 输入样本合同原文与拟稿句，比较拟稿句每个事实断言与原文的主体、对象、状态、有效范围，可观察结果为“已生效”和“已完成备案提交”均标记为未获支持，仅签署日期与提交义务获得原文支持。
2. 输入两个向量模型标识不同的知识库，比较关联条件，可观察结果为系统不接受共同关联，记录实际提示，不推断漏召回或冗余等运行结果。
3. 输入一次纸面空引用数组，比较下游节点设计，可观察结果为下游走通并输出空引用，不声称虚构规则检索一定返回空数组。
