# 生产企业免抵退税的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

在生产企业免抵退税的合同与交易材料比对中，本页说明FastGPT的上下文与 token如何衔接资料。对照出口资料整理委托中的交易对应、暂列数据与后续回件，不用企业标题代替本批证据。所用场景为自拟文字测试。

## 这些特征在「上下文与 token」这一环带来什么约束

出口资料整理可自拟委托“归集本批购进与出口对应资料，未核项目暂列；处理结论依本事项回件”，附件只有归集目录和标注待对的关联表，没有对应凭据或处理回件。历史谈话是另一批已收到回复。当前比较委托与表格，不讨论免抵退条件、计算或真实申报手续。企业业务标题只说明材料主题，不能证明该批交易对应或处理资格。上下文须保留本批、未核暂列和本事项回件，不能把归集完成写成申报结果已定。

## 配置怎么定

| 出口资料上下文 | 自拟文书范围 | 核验动作 |
| --- | --- | --- |
| 归集目录 | 只记录资料归集 | 不扩大为处理结果。 |
| 暂列关联 | 尚待核本批对应 | 保留表尾状态。 |
| 历史回件 | 另一批事项 | 核交易及覆盖期间。 |
| 新增对应凭据 | 只补匹配关系 | 结果回件另查。 |
| 企业业务标题 | 仅材料主题 | 不代本批资格证明。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `模型上下文` | 以实际模型可接收范围为准。 |
| `回复长度` | 回复上限不同于上下文窗口。 |
| `知识库引用上限` | 知识引用上限按token计。 |
| `历史输入核对` | 比较空历史与带历史的输入。 |
| `结构化承接` | 先验解析，再核字段事实依据。 |

## 容易做错的三处

第一处是未核暂列的表尾说明被引用裁掉，应核完整关联表、尾注和实际请求，查暂列关系是否升级为已核对应。第二处是这批回了吗借用另一批历史回复，应固定本批交易标识比较历史，核回件覆盖的事项和期间。第三处是归集目录被结构化填为处理完成，应查目录动作及本事项实际回件，字段可解析也不能生成正式结果。三项分别核关系状态、批次指代和文书阶段，企业名称相同不提供替代依据。

## 怎么确认配好了

验收分别问归集了什么、哪些对应仍待核、哪份回件支持处理状态，对结论逐句回到输入。补入购进出口对应资料后只更新匹配关系，结果仍待对应回件；取得时间较新也不说明适用交易期间较新。知识引用token与输出长度单独核，模型实际上下文能力另留依据，不以回复有结果栏就认定有结果材料。本练习不判断税务资格、不计算金额或办理申报，缺回件也不能反向写成正式不予处理。
