# 生鲜临期折价处理的合同与交易材料比对：工作流编排

## 这个品类的数据长什么样

在生鲜临期折价处理的合同与交易材料比对中，本页说明FastGPT的工作流编排如何衔接资料。临期清单、处置批准和报损记录说明不同事情，流程应保留批次与处置方式之间的对应。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟清单列酸奶批次甲，处置文字允许调整陈列，报损摘录却指向批次乙。对合同和处置材料的比对可以收商品、批次和处置原句，再让人员选择补甲的处理依据或查乙的报损来源。这里不填写价格或折扣，也不预设调整陈列等于可以销售。节点传值应保留各材料属于哪一批，不能因为商品名一样就拼成同一次处置记录。

## 配置怎么定

| 临期处置比对 | 自拟材料 | 需要保留 |
| --- | --- | --- |
| 清单对象 | 酸奶批次甲 | 不混入乙的报损 |
| 处置措辞 | 允许调整陈列 | 不扩大批准范围 |
| 报损来源 | 摘录属于乙 | 核本批对应记录 |
| 人员路径 | 补甲或查乙 | 选择与接收一致 |
| 库存结果 | 扣减凭据缺失 | 未写成已经完成 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

批次混用：若乙的报损被写到甲，应核清单与报损的批次原句；批准扩大：若调整陈列被改成允许全部处置，应核批准范围和实际接收值；记录冒完成：若报损申请被写成库存已扣，应查本批实际库存处理结果。三项分别核对象、权限范围及执行，不能由处置文件齐全推定。

## 怎么确认配好了

验收从甲的清单进入，检查补甲依据的选项是否传到对应路径，再查看接收内容是否仍标出乙的报损不能用于甲。加入甲的实际记录后，核解释只改变甲的处理依据，未抹掉批次界线。销售处理、库存变更及报损核准需要后续业务流程的实际记录；人员已选下一步和节点已继续只说明流程动作，不说明商品可售或处置已完成。
