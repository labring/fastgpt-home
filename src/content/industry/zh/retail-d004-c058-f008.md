# 生鲜供应商索赔的合同与交易材料比对：工作流编排

## 这个品类的数据长什么样

在生鲜供应商索赔的合同与交易材料比对中，本页说明FastGPT的工作流编排如何衔接资料。鲜品索赔要分清异常描述、照片所属与供应商确认，扣款通知也不能代替双方处理结论。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟异常单写“部分叶菜压伤”，照片只拍外箱，索赔对账稿留有供应商待回复。工作流可收这些片段及送货对应关系，安排人员补货品检查或追索本次回复。合同若只约定提交异常材料，不能据此认定索赔已获认可；外箱图片也不能说明箱内全部品质。传到后续步骤时应保留“待回复”，不把整理完成变成供应商已经接受。

## 配置怎么定

| 索赔材料比对 | 自拟片段 | 解释边界 |
| --- | --- | --- |
| 异常对象 | 部分叶菜压伤 | 不扩大到全部货品 |
| 照片范围 | 仅有外箱画面 | 另核货品检查 |
| 供应商立场 | 对账稿待回复 | 不写成双方同意 |
| 通知性质 | 扣款通知 | 核是否仅确认收到 |
| 路径记录 | 补检查或补回复 | 接收保留送货对象 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

图片超证：若外箱照被写成全部叶菜受损，应核画面范围与本件检查；单方通知冒共识：若扣款通知被写成双方同意，应取供应商对应回复；待回复被抹除：若分支接收只剩索赔结论，应对照提交原句恢复状态。三项分别核证据覆盖、双方立场与传值完整性，不由同一文件名解决。

## 怎么确认配好了

将补检查和补回复分别连接，验收看选项记录、下游收到的送货对象及待补项。补入回复时先核它针对哪次异常，再复问是否只修正那次处理状态；若只确认收到通知，不能写成接受索赔。正式扣减、付款调整及争议关闭需要另接实际业务回执，流程路径走完只证明已执行相应步骤，不证明商议结果。
