# 生鲜水果门店采购的合同与交易材料比对：工作流编排

## 这个品类的数据长什么样

在生鲜水果门店采购的合同与交易材料比对中，本页说明FastGPT的工作流编排如何衔接资料。水果采购约定、检测报告与到货验收不能只按品名合并，报告批次和实际接收对象要随流程传递。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟采购单要求送青色果，验收摘录写“外观待复核”，检测报告封面却属于上一供货批。比对流程可以收品名、约定原句和各资料的批次说明，让人员选择补本批报告或补外观确认。这里不编造检测标准及结论，也不从上一批报告推定本批符合要求；传值应留下待复核，并将采购要求与实际品质分开。

## 配置怎么定

| 水果采购比对 | 本题自拟文字 | 传递核对 |
| --- | --- | --- |
| 采购要求 | 要求青色果 | 不变成实收描述 |
| 验收状态 | 外观待复核 | 接收仍留缺项 |
| 报告对象 | 上一供货批 | 不得支持本批 |
| 补材料路径 | 报告或外观确认 | 收到对应资料要求 |
| 后续处置 | 损耗退货另核 | 不从节点推归责 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

约定冒现状：若“要求青色”变成“实收青色”，应核本次验收观察；旧批报告套新批：若封面批次被省略，应查完整报告对象与送货对应；待复核冒完成：若分支收到已经验收通过，应对照提交状态及实际结论。三项分别核要求与事实、报告范围及状态传递，不能靠商品同名消除。

## 怎么确认配好了

验收比较原始片段与接收步骤，将补报告和补外观安排到各自路径。补入本批检测依据后，只能更新其覆盖的判断；外观确认仍缺时，应继续保留缺项。损耗归因、退货处置与采购系统回写需要另外的真实记录，节点继续运行不证明水果实际符合全部要求，也不证明损耗已由任何一方承担。
