# 生鲜水果门店采购的合同与交易材料比对：文档解析与分块

## 这个品类的数据长什么样

生鲜水果门店采购的日常材料集中在采购单、验收单、农残检测报告和损耗记录四类。采购单记录档口报价与订货数量，验收单记录到货等级与实收重量，农残检测报告记录批次检测结论，损耗记录记录门店端腐损数量。这些材料按日或按批更新，同一批水果可能同时出现采购单、验收单和检测报告三份文件，三份文件的主体、批次和日期需要互相对应。

与便利店鲜食订货不同，水果采购依赖批发市场行情和等级验收，缺少总部统一标准餐食。同一供应商在同一天可能对多个批次给出不同报价，验收等级也按现场目测确定。文档解析与分块需要保留批次号、供应商名称、日期和等级这类可回指原文的身份字段，使后续比对能定位到具体文件。

## 这些特征在「文档解析与分块」这一环带来什么约束

分块需要按材料自身结构切分。采购单的报价条件、验收单的等级说明、检测报告的检测结论各自独立成段，条件句与所约束的内容不能被拆到不同数据块。同一组原数据可以对应多个索引，一组较长的验收说明可以拆成多组向量，任一向量被召回即可带出整组原数据。原数据存于 MongoDB 的 dataset.datas 表，向量存于 PostgresSQL 的 vector 字段，检索时先召回向量再按向量 ID 回取原数据。

假设演练样本：某门店留存一份验收单原文，内容为“供应商：青禾档口；批次：2026-03-11-A；品名：砂糖橘；验收等级：一级；实收重量：320 公斤；验收日期：2026年3月11日；验收人：门店生鲜主管”。另有一份采购单原文，内容为“供应商：青禾档口；批次：2026-03-11-A；品名：砂糖橘；报价：每公斤6.4元；报价有效期：2026年3月11日当日”。待判定的拟稿句为“青禾档口2026-03-11-A批次砂糖橘验收等级为一级，供货期限至2026年3月31日”。该拟稿句中的供货期限在两份原文中均未载明。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 批次号与供应商名属精确查询，等级描述属语义查询，混合检索同时使用语义召回与全文召回并经 RRF 融合 |
| 最低相关度 | 0.35 | 该值为本次假设试验起点，非官方默认值；与 0.5 比较，观察低相关片段是否被过滤 |
| 引用上限 | 800 tokens | 该值为本次假设试验起点；与 400 tokens 比较，观察验收条件说明是否被截断 |
| 问题优化 | 开启 | 连续追问批次差异时补全指代，与关闭状态比较检索命中情况 |
| 结果重排 | 启用 ReRank | 候选较多时按重排得分二次排序，比较重排前后同一批次的排序位置 |
| 图片检索 | 暂不启用 | 样本材料为纯文本，无图片输入，不触发图片描述或图片向量路径 |

## 容易做错的三处

1. 把验收单的等级说明与采购单的报价条件合并为一个数据块。输入为两份原文，比较对象为分块后的数据块边界，可观察结果是等级条件与报价条件是否落在同一数据块内。若同一数据块同时含两类条件，后续比对无法区分字段来源。

2. 将拟稿句中的供货期限当作已载明事实。输入为拟稿句与两份原文，比较对象为供货期限字段，可观察结果是原文中是否存在该字段。两份原文均未载明供货期限，该字段属未获支持，不能判定为与原文矛盾。

3. 用最低相关度设置排除其他供应商或未授权记录。输入为最低相关度数值与检索结果，比较对象为返回记录的主体字段，可观察结果是返回记录是否包含非目标供应商。最低相关度是过滤阈值，不承担主体或权限隔离。

## 怎么确认配好了

1. 输入假设验收单原文与采购单原文，比较对象为解析后保留的批次号、供应商名、日期字段，可观察结果是这些字段能否回指原文。若批次号在分块后丢失，检索无法按批次定位。

2. 输入拟稿句与两份原文，比较对象为供货期限字段，可观察结果是原文是否载明该字段。原文未载明时记录为未获支持，保留证据缺口，不补造授权或生效条款。

3. 输入批次号“2026-03-11-A”作全文检索，输入“砂糖橘验收等级”作语义检索，比较对象为返回的数据块与原文对应关系，可观察结果是两类检索是否召回同一组原数据。检索只返回候选内容，不构成授权或审批。资料变更后需核对实际训练与索引状态，上传成功不表示检索已更新。
