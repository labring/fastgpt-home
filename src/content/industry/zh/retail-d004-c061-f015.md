# 生鲜称重分拣的合同与交易材料比对：知识库检索与召回

## 这个品类的数据长什么样
生鲜称重分拣在仓内履约环节完成，核心数据围绕重量与规格展开。分拣任务单记录订单与分拣要求，称重标签记录实际称重结果，少称补偿单记录重量差异的处理请求，质检记录记录品质判定。这些材料的更新频率为每单或每日。在合同与交易材料比对任务中，需要核对的字段包括分拣任务单上的规格要求、称重标签上的实际重量、少称补偿单上的差异数量与质检记录中的判定结果。这些材料分属不同环节，主体、对象与状态需要逐项对齐。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的库。跨不同向量模型的库不可共同关联，需先核对向量模型标识并排除不符合者。搜索模式可选语义检索、全文检索或混合检索；混合检索通过 RRF 融合多路结果，该过程属于检索链路内部环节。最低相关度仅在语义检索或使用结果重排时生效，该阈值属于相似度过滤条件，不承担权限或实体隔离功能。引用上限以 token 为单位控制引用内容长度。问题优化用于指代消除与问题扩展，会额外调用模型。图片检索需要图像输入及相应模型能力，重排需要具备模型并按设置启用。

假设演练样本：供核对的材料原文为「分拣任务单 FD-2025-0412-017：订单 O-8841，规格要求 500g±20g，分拣员甲，日期 2025-04-12。」「称重标签 W-2025-0412-017：实际重量 465g，称重时间 2025-04-12 09:15。」「少称补偿单 C-2025-0412-009：订单 O-8841，申报差异 35g，状态待审核，日期 2025-04-12。」待判定拟稿句为「订单 O-8841 已完成少称补偿 35g，分拣任务已闭环。」

## 配置怎么定
以下配置项围绕上述样本的合同与交易材料比对任务列出。数值仅为本次假设试验起点，需与实测结果比较后调整。

| 配置项 | 本次假设试验起点及理由 | 核对方式 |
| --- | --- | --- |
| 关联知识库 | 选择包含分拣任务单、称重标签、少称补偿单、质检记录的库，确认各库向量模型标识一致 | 核对向量模型标识，排除不一致的库 |
| 搜索模式 | 先用混合检索，同时覆盖语义召回与编号类关键词命中 | 用样本中的订单编号与规格描述分别测试 |
| 引用上限 | 设为能容纳上述三类材料完整字段的 token 量，避免截断状态字段 | 检查返回内容是否包含补偿单状态与日期 |
| 最低相关度 | 先标注相关与无关样本，再设初始阈值；该值仅在语义检索或结果重排时生效 | 比较阈值调整前后返回内容的变化 |
| 问题优化 | 对含指代或省略主体的查询开启，比较原问题与优化后问题的主体是否一致 | 核对优化后问题是否保留订单编号与日期 |
| 结果重排 | 在候选结果较多且具备重排模型时启用，用重排得分辅助过滤 | 比较重排前后排序变化，确认状态字段未被丢弃 |

## 容易做错的三处
1. 将少称补偿单的「待审核」状态当作已完成补偿。输入为样本中的补偿单状态字段，比较对象为「待审核」与「已完成」两种取值，若拟稿句写成已完成补偿，则与原文状态不符。待审核不证明补偿已执行。
2. 将称重标签的 465g 与规格要求 500g±20g 直接判定为不合格。输入为规格下限 480g 与实际重量 465g，比较对象为实际重量是否落在允许范围内，若未核对规格公差即下结论，则缺少判定依据。差异存在不等于责任归属已定。
3. 将检索到的材料内容当作授权执行依据。输入为检索返回的补偿单内容，比较对象为检索结果与授权状态，若因检索命中即认为补偿可执行，则混淆了检索与授权。检索不承担授权功能。

## 怎么确认配好了
1. 输入样本中的拟稿句「订单 O-8841 已完成少称补偿 35g，分拣任务已闭环」，比较拟稿句与补偿单原文的状态字段「待审核」，观察返回内容是否包含状态字段且拟稿句是否与原文状态一致。若返回内容缺失状态字段，则需检查引用上限是否截断。
2. 输入样本中的订单编号 O-8841 与日期 2025-04-12，比较检索返回的材料是否同时包含分拣任务单、称重标签与少称补偿单三份材料，观察返回结果是否覆盖同一订单同一日期的材料。若仅返回部分材料，则需检查关联知识库范围与搜索模式。
3. 输入一条不含订单编号的查询「补偿单处理情况」，比较问题优化前后是否补全主体，观察优化后问题是否保留可核对的订单或日期信息。若优化后问题丢失主体，则需记录该现象并核对问题优化设置。空结果可用明确的纸面输入 [] 核对下游设计，不声称虚构规则检索一定返回空数组。
