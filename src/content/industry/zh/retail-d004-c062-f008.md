# 电商仓入库上架的合同与交易材料比对：工作流编排

## 这个品类的数据长什么样

在电商仓入库上架的合同与交易材料比对中，本页说明FastGPT的工作流编排如何衔接资料。到货预告、入库验收和上架任务的完成条件要分开，采购约定也不能补出仓库实际位置。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟采购到货单写“待入库”，验收摘录只确认外箱，货架任务列出计划位置，未附实际上架记录。流程可以收这些阶段说明，让人员选择补入库结论或查位置回执。这里不假定仓储系统已连接，也不把任务上的位置写成货物现址；外箱检查是否足以支持采购条款，需要看条款与本批检查原文，不能由阶段名称代替。

## 配置怎么定

| 仓库合同核对 | 自拟阶段 | 应取依据 |
| --- | --- | --- |
| 到货单 | 待入库 | 实际入库记录 |
| 验收摘录 | 只查外箱 | 与合同覆盖对照 |
| 货架任务 | 计划位置 | 本件上架位置回执 |
| 分支去向 | 补入库或查位置 | 原阶段随输入保留 |
| 业务记录 | 库存与差异另接 | 不从输出推账实一致 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

预告冒入库：若待入库文字变成已收库存，应查本次实际入库依据；外箱冒整体验收：若外箱记录被当全部条款满足，应核检查覆盖和合同要求；计划位置冒现址：若货架任务被写成上架完成，应取本件实际位置记录。三项分别查货物流转、验收覆盖和位置状态，各自需要证据。

## 怎么确认配好了

验收保留原文阶段与物料对象，核补入库、查位置两个选项各自传到哪一步。加入上架记录后，只更新它能证明的仓位信息；采购验收若仍只有外箱说明，仍不得称全部通过。库存入账、仓位更新与差异处理由另接流程核实际业务回执，节点有输出不代表仓库已经完成这些动作，也不证明采购与库存账一致。
