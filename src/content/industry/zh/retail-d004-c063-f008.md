# 直播售后集中处理的合同与交易材料比对：工作流编排

## 这个品类的数据长什么样

在直播售后集中处理的合同与交易材料比对中，本页说明FastGPT的工作流编排如何衔接资料。直播售后交易比对要分别核订单范围、退款申请与补发状态，话术模板不能替代本单结果。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟直播订单清单含待处理订单，退款摘录来自其中一单，补发材料只写已创建安排。流程先收订单对应说明和原句，由人员选择补退款结果或查补发交接。话术中写“完成后告知”只是条件表达，不能改成当前已经完成；一单结果也不代表同场直播所有订单。传递时应保留这些范围和阶段，不预设平台订单与仓储记录已同步。

## 配置怎么定

| 直播售后比对 | 自拟资料 | 需要区分 |
| --- | --- | --- |
| 订单范围 | 清单多单结果单单 | 不扩大到整场 |
| 补发安排 | 只记创建 | 非物流交接 |
| 条件话术 | 完成后再告知 | 非当前完成通知 |
| 分支接收 | 退款或补发待补项 | 订单对象保持对应 |
| 正式操作 | 通知退款回写另核 | 交互结束不等于关闭 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

单单扩整场：若某单退款被写成全场已处理，应核清单覆盖与结果归属；安排冒发出：若补发创建被当作物流已交接，应取本次真实交接记录；模板冒现况：若条件话术变成已完成通知，应对照模板条件与该单证据。三项分别核订单集合、履约阶段和表达性质。

## 怎么确认配好了

验收让两条选项分别接收退款和补发待补项，比对订单对象有没有在传值时被替换。加入物流交接后，可说明该单补发到了哪一步，但退款仍需对应处理结果，不能一并补齐。实际退款、出库、平台状态回写及客户通知需后续流程另核权限和回执，交互结束只表示继续运行，不代表售后全部关闭。
