# 直播间违规申诉的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

直播间违规申诉围绕已经发生的平台处罚展开，材料来自违规中心通知、直播回放、客服记录与商品资质库。一次申诉通常要同时核对违规通知中的处罚对象与违规片段、回放中的口播或展示内容、商品资质文件的有效范围，以及申诉说明中对事实的陈述。这些材料的更新不定期，每次违规各自成组，申诉窗口内材料是否齐全直接决定能否完成比对。

本页只处理合同与交易材料比对中的上下文与 token 环节：把违规通知、回放记录、资质文件和申诉说明放进同一比对请求时，如何控制送入模型的内容长度、历史轮数、引用上限与回复长度，使比对依据不被截断，也不把无关材料挤进上下文。

## 这些特征在「上下文与 token」这一环带来什么约束

比对请求的输入由多份材料拼成，单份材料可能包含时间戳、商品名称、处罚条款编号与截图描述。若引用上限按 token 控制，需要结合单段长度与问题样本核对实际送入的内容是否被裁剪。模型的最大上下文与回复上限是两个不同量：回复上限限制输出长度，不能当作完整上下文窗口使用。

同一比对问题在空历史与带历史下送入模型的输入不同，需要比较两种输入以排除上下文差异。使用固定回复格式承接比对结论时，要验证字段齐全与解析成功，不能只检查文本长度。语义召回与相关度只影响候选内容的排序与过滤，不承担权限或实体隔离；检索库是否可共同关联取决于向量模型标识是否一致，不能把同模型要求扩展到外部系统。

假设演练样本：材料原文为“违规通知载明：处罚对象为店铺A，违规片段为2024年5月10日20时15分至20时18分的直播回放，违规事由为商品资质未在口播中展示。商品资质文件载明：资质编号Z-2024-0510，适用商品为商品B，有效期至2024年12月31日。申诉说明草稿写：本店已于2024年5月10日直播中展示商品B的全部资质。”待判定拟稿句为“本店已于2024年5月10日直播中展示商品B的全部资质。”该句与回放记录、资质文件是否同主体、同期间、同字段，需在比对请求中逐项核对；回放是否实际展示资质属于未载明事实，保留为待核实。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AI 模型 | 选用支持所需上下文长度的模型 | 按模型能力核对最大上下文，与材料总长度比较 |
| 记忆轮数 | 设为 0 轮 | 与带历史输入的同一问题比较，排除上下文差异 |
| 回复上限 | 保留足以写出依据与处理动作的长度 | 与拟稿句所需字段数量比较，避免结论被截断 |
| 引用上限 | 按 token 设定，覆盖样本材料关键段 | 与单段材料长度比较，核对是否发生裁剪 |
| 回复格式 | 选择 json_schema 并填写字段要求 | 与比对结论所需字段比较，验证解析成功 |
| 温度 | 保持默认偏低 | 与规则明确场景的稳定输出要求比较 |

以上数值为本次假设试验起点，不是官方默认值。引用上限使用文档说明的 token 单位，不换算为条目数量。思考预算属于思考配置，不能移作引用 token 上限。

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。输入为长回放记录加资质文件，比较对象为模型最大上下文，观察结果是材料被裁剪后模型仍输出结论。检查方式：核对送入内容长度与最大上下文，确认是否发生截断。
2. 用空历史与带历史输入混用同一比对。输入为同一拟稿句在两种历史下的请求，比较对象为两次送入内容，观察结果是结论不一致。检查方式：固定历史轮数后重跑，比较输入差异。
3. 把语义召回得分当作权限或实体过滤。输入为跨店铺材料，比较对象为材料主体标识，观察结果是无关主体进入候选。检查方式：核对向量模型标识与材料主体，排除不符合者并记录实际观察。

## 怎么确认配好了

- 验证一：输入假设样本中的违规通知原文、资质文件原文与拟稿句，比较三者主体、期间与字段是否一致，观察结果为拟稿句所称展示资质在回放记录中无对应记载，满足条件即判定为待核实，不判定为矛盾。

- 验证二：输入同一拟稿句在记忆轮数为 0 与带历史两种配置下的请求，比较两次送入模型的材料内容，观察结果为两次输入一致，满足条件即排除历史差异影响。

- 验证三：输入空结果承接场景，使用明确的纸面输入 `[]` 核对下游节点设计，比较下游对空引用的处理，观察结果为下游按设计承接空引用，不声称虚构规则检索一定返回 `[]`。跨模型库不可共同关联，先核标识并排除不符合者，记录实际观察。
