# 直播间违规申诉的合同与交易材料比对：知识库检索与召回

## 这个品类的数据长什么样

直播间违规申诉处理已经发生的平台处罚，材料围绕违规通知、直播录屏、商品资质与申诉说明展开。合同与交易材料比对需要把申诉说明中的每一句主张，与知识库中可检索到的原始材料逐项对照。数据来源包括平台违规中心、直播回放、客服记录与商品资质库，更新不定期，每次违规触发一轮材料整理。典型从业主体为店铺合规、直播运营与法务。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的库，跨不同向量模型的库不可共同关联；遇到候选库时应先核对向量模型标识，排除不符合者，记录实际观察。搜索模式分为语义检索、全文检索与混合检索，混合检索通过 RRF 融合多路结果，RRF 是融合过程，不是可开启的开关。最低相关度仅在语义检索或使用结果重排时生效，属于过滤阈值，不承担权限或实体隔离功能。引用上限以 token 为单位，控制单次搜索引用的内容长度。问题优化用于指代消除与问题扩展，开启后增加一次模型调用。图片检索需要图像输入及相应模型能力，文档所列可选路径不代表每次请求全部执行。

假设演练样本：材料原文一为“违规通知载明：2025年3月12日，本店直播间因商品资质展示不全被处以商品禁播，处罚对象为店铺A的直播间，处罚期间为2025年3月12日至3月19日”。材料原文二为“商品资质库记录：店铺A于2025年3月10日上传该商品质检报告，报告编号Q-2025-0310，状态为已通过”。待判定拟稿句为“本店已于处罚前完成该商品资质上传，申诉请求撤销禁播”。比对对象为同一店铺、同一商品、同一期间。拟稿句主张的“处罚前完成上传”与材料原文二的日期一致，但材料原文一未载明申诉通道是否开放、申诉是否已受理，拟稿句中的“请求撤销”属于交接请求，处于待提交状态，检索结果不构成授权。

## 配置怎么定

| 配置项 | 本页取值或核对项 | 依据与说明 |
| --- | --- | --- |
| 关联知识库 | 仅关联使用相同向量模型的申诉材料库 | 跨模型库不可共同关联，先核标识再排除 |
| 搜索模式 | 本次假设演练起点选混合检索 | 编号与自然语言主张并存，需与语义检索、全文检索分别比较 |
| 引用上限 | 本次假设试验起点设为2000 token | 材料含处罚期间与报告编号，需与更小值比较内容完整性 |
| 最低相关度 | 先标注相关与无关样本再定阈值 | 仅在语义检索或结果重排时生效，不作为权限过滤 |
| 问题优化 | 多轮追问或短问题时开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型且按设置启用时使用 | 文档列为可选路径，不默认每次执行 |

## 容易做错的三处

1. 把跨向量模型的库强行共同关联。输入为两个向量模型标识不同的库，比较标识是否一致，观察结果为标识不一致即排除，不继续执行检索。
2. 把最低相关度当作权限或实体隔离手段。输入为一条属于其他店铺的违规通知，比较检索结果与当前店铺标识，观察结果为相关度分数不能替代主体核对，需人工确认归属。
3. 把待提交的申诉请求写成已完成。输入为拟稿句“申诉请求撤销禁播”，比较材料原文一是否载明受理状态，观察结果为未载明受理即记录为待核实，不写成已提交或已批准。

## 怎么确认配好了

1. 用材料原文一与拟稿句做比对。输入为处罚期间2025年3月12日至3月19日与拟稿句“处罚前完成上传”，比较日期字段是否同主体同期间，观察结果为日期一致仅支持上传时间主张，撤销请求仍待核实。
2. 用材料原文二做检索命中核对。输入为报告编号Q-2025-0310，比较全文检索与语义检索的返回内容，观察结果为编号类查询在全文检索下可命中，语义检索结果需逐条核对是否同主体。
3. 用纸面输入空数组核对下游。输入为引用内容返回长度0，比较下游节点是否仍走通，观察结果为输出链路走通、引用为空，记录缺口而不推定为无违规或已澄清。
