# 社区团购团长运营的合同与交易材料比对：知识库检索与召回

## 这个品类的数据长什么样

社区团购团长运营围绕社区节点和佣金结算展开，日常材料包括团长协议、佣金表、提货清单、社群公告。这些材料按日或每团更新，来源为社区团购后台、团长社群、订单明细和售后记录。本页只处理合同与交易材料比对中的知识库检索与召回，检索结果与表单收集值都不构成授权执行。团长协议中的签署、合作达成、合同生效是三个独立事实，比对时须分别核对。

## 这些特征在「知识库检索与召回」这一环带来什么约束

检索以库为最小搜索单位，集合仅用于分类管理。知识库搜索节点可关联一个或多个使用相同向量模型的知识库；跨不同向量模型的库不可共同关联，须先核验向量模型标识并排除不符合者，再记录实际观察。语义检索、全文检索、混合检索适用不同资料，编号、专有名词类查询适合全文或混合检索。最低相关度仅在语义检索或结果重排时生效，是过滤阈值，不是最终排序规则，也不承担权限或实体隔离。RRF 是混合检索中多路结果的融合过程，不是可开启的开关。引用上限以 token 为单位，控制每次搜索最多引用的内容量。按设置开启问题优化后，可做指代消除和问题扩展，并额外调用模型。

## 配置怎么定

下表围绕本页假设演练样本列出与本功能、主任务相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联已核验向量模型标识一致的团长协议库与佣金表库 | 比较各库向量模型标识，排除不一致者，不执行跨模型检索 |
| 搜索模式 | 对协议编号、佣金比例等字段采用混合检索 | 与纯语义检索结果比较，观察编号类查询命中情况 |
| 引用上限 | 设为 1200 token | 本次假设起点，用长短不同的协议与佣金表片段比较内容完整性后调整 |
| 最低相关度 | 设为 0.35 | 本次假设起点，先标注相关与无关样本，比较过滤后保留情况 |
| 问题优化 | 多轮追问团长协议条款时开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 候选较多且具备重排模型时启用 | 比较重排得分与向量得分，观察排序差异 |

## 容易做错的三处

1. 把检索命中当作授权依据。假设演练样本：团长协议原文写“本协议自双方签署之日起生效”，拟稿句写“该团长已获授权开展本团提货”。签署、合作达成、合同生效是三个不同事实，检索到协议文本不表示已签署或已生效，该拟稿句未获支持，须记录证据缺口。
2. 把最低相关度当作权限或实体过滤。假设演练样本：检索返回某团长佣金表片段，相关度 0.82，拟稿句写“该团长有权查看本团全部佣金”。相关度是相似度数值，不承担权限隔离，该拟稿句待核实，须另接权限系统核对。
3. 把跨向量模型知识库共同关联。假设演练样本：团长协议库与提货清单库向量模型标识不同，仍被同时关联。此时只核验标识并排除不符合者，记录实际观察，不得推断漏召回或冗余等运行结果。

## 怎么确认配好了

以下三项验证均使用上节假设演练样本，逐项说明输入、比较与满足条件。

1. 输入团长协议原文“本协议自双方签署之日起生效”与拟稿句“该团长已获授权开展本团提货”，比较协议文本是否载明签署完成与生效事实。原文未给签署完成记录，生效条件履行情况待核；本团提货授权还需对应范围依据，不能只由协议签署或生效推出，缺失分别记录。
2. 输入佣金表检索片段与拟稿句“该团长有权查看本团全部佣金”，比较检索结果是否包含权限字段。若片段仅含佣金比例与结算周期，无权限字段，该拟稿句判定为待核实，须另接权限系统核对，不声称检索即授权。
3. 输入提货清单库与团长协议库的向量模型标识，比较两者是否一致。若标识不一致，排除不符合者，不执行跨模型检索，记录实际观察；空结果可用明确的纸面输入 [] 核对下游设计，不声称虚构规则检索一定返回空数组。
