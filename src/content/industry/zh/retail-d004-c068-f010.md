# 社区团购预售集单的合同与交易材料比对：引用来源与溯源

## 这个品类的数据长什么样

社区团购预售集单先收订单再组织采购履约，合同与交易材料比对需要把预售商品表、集单结果、采购计划、截单通知放在同一组证据里核对。这些材料按日或按场更新，同一场次的商品名称、截单时间、数量口径可能分别出现在不同文档中。引用来源与溯源要回答的问题是：某条拟稿句或交接请求所依据的原文来自哪份材料，该材料处于什么状态，能否支撑该句的表述。

## 这些特征在「引用来源与溯源」这一环带来什么约束

检索环节的引用内容以数组输出，长度可以为 0，空数组不代表工作流报错终止。引用上限按 tokens 控制，最低相关度仅在语义检索或结果重排时生效，该数值是过滤阈值，不承担权限或实体隔离功能。关联的知识库须为相同向量模型，跨模型不可共同关联；核对时先确认知识库标识与向量模型标识，排除不符合者并记录观察，不执行跨模型检索来比较漏召回。RRF 是混合检索结果的融合过程，不作为开关描述。思考预算是模型思考强度参数，与引用 tokens 上限无关。检索输出交给回答环节后，须逐条核对回答与引用原文。

假设演练样本：材料甲为某场次预售商品表原文“商品：青提；规格：500g/份；本场截单时间：3月10日18:00；预售数量上限：200份”。材料乙为截单通知原文“本场3月10日18:00截单，截单后不再接受新增订单”。待判定拟稿句为“本场青提供货数量为200份，供货期限至3月10日18:00”。该拟稿句的主体、对象与材料甲一致，但“供货数量”与“预售数量上限”、“供货期限”与“截单时间”属不同字段，材料未载明供货数量与供货期限，该句未获支持。

## 配置怎么定

| 配置或核对项 | 本页用途 | 本次假设试验起点及理由 |
| --- | --- | --- |
| 关联的知识库 | 限定检索范围 | 选入含材料甲、乙的知识库，核对向量模型标识一致 |
| 搜索模式 | 决定召回路径 | 本次用混合检索，编号与时间类字段依赖全文命中 |
| 引用上限 | 控制引用 tokens 总量 | 起点设为 2000 tokens，便于容纳两份短材料，与检索返回实际长度比较 |
| 最低相关度 | 过滤低相关结果 | 起点设为 0.3，与返回结果的相关度得分比较后再定 |
| 引用内容输出 | 承接检索结果 | 输出为数组，允许长度为 0，下游按空数组设计 |
| 资料时效核对 | 确认版本有效 | 用当前版与历史版截单通知比对，采用哪版须经有效版本审核 |

## 容易做错的三处

1. 把“预售数量上限”当作“供货数量”。输入为材料甲原文与拟稿句，比较字段名称与取值对象，材料甲只写预售数量上限，未写供货数量，该句应标为未获支持。
2. 把“截单时间”当作“供货期限”。输入为材料乙原文与拟稿句，比较字段语义，截单时间是订单截止时点，材料未载明供货期限，该句应标为待核实。
3. 把检索命中当作授权或业务执行。输入为检索返回的引用数组，比较引用内容与交接请求的授权状态，检索只提供来源文本，采购下单、退款等动作须由相应业务环节完成，检索结果不构成授权。

## 怎么确认配好了

1. 输入材料甲、材料乙原文与拟稿句“本场青提供货数量为200份，供货期限至3月10日18:00”，比较拟稿句字段与原文载明字段，若系统将供货数量、供货期限标为未获支持或待核实，则该项通过；若直接判为与原文一致，则不通过。
2. 输入一次无匹配内容的纸面查询，比较检索输出是否为长度为 0 的数组，并核对下游是否按空数组继续走通；若下游将空数组当作报错终止，则该项不通过。
3. 输入两个向量模型标识不同的知识库，比较关联操作是否被拒绝或提示不可共同关联，并记录实际观察；若系统允许关联并继续检索，则该项不通过，须记录该观察而不推断具体漏召回结果。
