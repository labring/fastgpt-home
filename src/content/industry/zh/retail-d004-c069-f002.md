# 经销商返利核算的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

经销商返利核算发生在销售完成之后，核算依据分散在返利政策、销量达成表、对账单与红字发票之间。合同台账记录政策口径与结算条件，交易材料记录实际销量、回款与退货，两者需要逐项对齐后才能进入财务处理。核算周期通常按月或按季推进，单次比对涉及的合同条款与交易明细往往跨越多个月份，材料篇幅较长。这使上下文与 token 成为本环节的直接约束：模型单次请求可参考的内容长度有限，需要判断哪些条款与明细必须同时进入比对范围。

## 这些特征在「上下文与 token」这一环带来什么约束

返利政策条款、销量达成表、对账单与红字发票分属不同文档，比对时需要同时呈现合同约定与实际发生额。模型的最大上下文决定单次请求可容纳的内容长度，回复上限只控制输出长度，两者不能混用。知识库引用上限按 token 控制每次搜索最多引用的内容，单段材料过长时可能被裁剪，导致比对缺少关键字段。历史输入会改变同一问题在空历史与带历史下的实际输入内容，需要分别核对。采用固定回复格式承接比对结论时，字段完整性与解析成功需要单独验证。

假设演练样本：某品牌财务人员核对一份经销商返利材料。合同台账原文为：「甲方于2025年3月1日与乙方签订年度返利协议，约定季度销量达成率不低于90%时按回款额2%计返利，协议有效期至2026年2月28日。」销量达成表原文为：「乙方2025年第二季度销量达成率87%，回款额120万元。」拟稿句为：「乙方2025年第二季度达成返利条件，应按回款额2%计提返利。」待判定该拟稿句是否获得材料支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AI 模型 | 选择支持工具调用且最大上下文满足材料长度的模型 | 按配置弹窗显示的最大上下文与样本材料总长度比较 |
| 回复上限 | 开启并设为能容纳结论与依据的长度 | 与样本拟稿句所需字段数量比较，观察是否被截断 |
| 引用上限 | 按 token 设定，覆盖合同条款与达成表关键段落 | 与单段材料长度比较，核对关键字段是否被裁剪 |
| 最低相关度 | 仅在语义检索或重排生效时设置 | 观察样本条款是否进入引用内容，缺失则记录缺口 |
| 回复格式 | 普通文本，暂不使用 json_schema | 样本结论字段少，固定结构解析暂无必要 |
| 记忆轮数 | 保持默认 | 单次比对不依赖前序对话，空历史与带历史分别核对 |

## 容易做错的三处

1. 把回复上限当作完整上下文窗口。回复上限只限制输出长度，模型单次请求可参考的内容长度由最大上下文决定。检查方式：输入样本合同条款与达成表全文，比较模型实际可参考的内容范围与材料总长度，观察关键条款是否因上下文不足而缺失。
2. 用相似度设置替代权限或实体隔离。最低相关度只过滤低相关结果，不区分经销商主体或授权范围。检查方式：在引用内容中核对合同主体与达成表主体是否一致，缺失主体字段时记录证据缺口，不据此判定授权状态。
3. 跨不同向量模型的库执行共同关联。不同向量模型生成的向量不可直接关联。检查方式：核对各库使用的向量模型标识，排除标识不一致的库，记录实际观察到的检索范围，不推断关联后的运行结果。

## 怎么确认配好了

以下验证均使用前述假设演练样本，不声称已实测。

1. 输入样本合同台账原文、销量达成表原文与拟稿句，比较拟稿句中的「达成返利条件」与合同约定的「季度销量达成率不低于90%」及达成表载明的「87%」。同一主体、同一期间、同一字段出现互斥取值时，判定为矛盾；样本中87%低于90%，拟稿句未获支持，应记录为待核实。
2. 输入空历史与带历史两种条件下的同一比对问题，比较两次实际送入模型的内容差异。若带历史条件下引用了前序对话中的其他经销商材料，需记录该差异并核对是否影响本样本主体判断。
3. 在引用内容中核对合同有效期「至2026年2月28日」与达成表期间「2025年第二季度」是否同时出现。若有效期条款因引用上限被裁剪，记录证据缺口，不补造授权或生效条款以获得确定结论。
