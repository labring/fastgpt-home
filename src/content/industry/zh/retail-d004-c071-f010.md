# 跨境平台结算与汇兑的合同与交易材料比对：引用来源与溯源

## 这个品类的数据长什么样

跨境平台结算与汇兑的合同与交易材料比对，处理的是已成交订单的资金归集材料，不涉及欺诈拒付。主要材料来自平台结算中心、银行流水、支付机构后台和 ERP 订单，日常需要核对平台结算单、汇率表、服务费发票和收款对账表。这些材料按周或按月更新，从业者通常是跨境卖家财务、税务会计和平台运营。

引用来源与溯源这一环，要求每条结论都能指回具体材料原文。材料本身可能来自不同系统，字段命名和期间口径未必一致，核对时需要确认主体、对象、期间和有效范围是否对齐。

## 这些特征在「引用来源与溯源」这一环带来什么约束

检索环节只负责找到候选内容，不负责判断材料是否在授权范围内。知识库搜索节点可以关联一个或多个相同向量模型的知识库，输出为引用数组，长度允许为零。空数组意味着搜索链路走通但未命中内容，下游承接设计需要能处理这种情况。

最低相关度是过滤阈值，仅在语义检索或结果重排时生效，它不承担权限或实体隔离功能。混合检索通过 RRF 融合多路结果，重排模型对候选文本二次排序并给出 0 到 1 的得分。引用上限以 tokens 为单位控制每次搜索最多引用的内容量。这些参数影响的是检索结果的相关性排序，与材料是否获得授权、是否经过审批属于不同层面的事实。

## 配置怎么定

以下配置围绕一个假设演练样本展开，用于说明核对方法，不代表任何真实记录或已执行操作。

假设演练样本：材料原文为“甲方：星海供应链有限公司；乙方：远岸贸易有限公司；结算期间：2025 年 3 月；平台结算单编号：ST-2025-03-001；结算金额：人民币 86,400 元；汇率表版本：FX-2025-03；服务费发票号：INV-2025-0312。”待判定拟稿句为“星海供应链有限公司已于 2025 年 3 月完成对远岸贸易有限公司的结算付款。”待判定交接请求为“请依据上述材料确认该笔结算已执行完毕并归档。”

| 配置项 | 本页相关设置或核对项 | 假设试验起点及理由 |
| --- | --- | --- |
| 关联的知识库 | 核对已选知识库及资料版本，确认向量模型标识一致 | 起点为单一知识库，理由是本样本材料来源集中，便于逐条溯源 |
| 引用上限 | 以 tokens 为单位控制单次搜索引用内容量 | 起点设为 2000 tokens，理由是本样本材料原文较短，需与材料总长度比较后调整 |
| 最低相关度 | 仅在语义检索或结果重排时生效的过滤阈值 | 起点设为 0.3，理由是本样本问题指向明确，需与重排得分分布比较 |
| 搜索模式 | 语义检索、全文检索或混合检索 | 起点为混合检索，理由是材料含编号类字段，需与全文命中情况比较 |
| 结果重排 | 具备重排模型且按设置启用时对候选二次排序 | 起点为启用，理由是本样本候选可能较多，需与未重排时的排序比较 |
| 引用内容承接 | 核对检索输出是否交给回答环节并逐条比对原文 | 起点为人工逐条核对，理由是来源证据不能由回答流畅度替代 |

## 容易做错的三处

1. 把检索命中当作授权确认。检索返回的是候选内容，材料是否在授权范围内、是否经过审批，需要另行核对。假设样本中拟稿句称“已完成结算付款”，但材料原文只载明结算单编号和金额，未载明付款状态，该结论未获支持。

2. 把最低相关度当作实体或权限过滤器。最低相关度只影响低相关度结果的过滤，不排除无关业务或未授权记录。假设样本中若检索到其他公司的结算单，不能因为相关度低就认为已排除，需要人工核对主体标识。

3. 把待审核状态当作已执行。假设样本中交接请求要求“确认该笔结算已执行完毕并归档”，材料原文未载明付款执行状态和归档状态，该请求处于待核实状态，不能据检索结果判定已完成。

## 怎么确认配好了

1. 输入假设样本的材料原文和拟稿句，比较拟稿句中的“已完成结算付款”与材料原文中“结算单编号”“结算金额”字段。材料原文未载明付款状态字段，预期现象为拟稿句结论未获支持，需记录证据缺口。

2. 输入假设样本的交接请求，比较请求中的“已执行完毕并归档”与材料原文中的字段范围。材料原文未载明执行状态和归档状态，预期现象为该请求处于待核实状态，不能判定为已完成。

3. 输入一个明确的纸面空结果数组 `[]`，核对下游承接设计是否能处理引用长度为零的情况。预期现象为下游流程继续执行并记录空引用，不产生报错断言。该输入为纸面假设，不代表任何实际检索返回结果。

以上三项均为纸面核对，未实际执行检索、审批或归档操作。
