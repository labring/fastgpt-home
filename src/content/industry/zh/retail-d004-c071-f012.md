# 跨境平台结算与汇兑的合同与交易材料比对：文档解析与分块

## 这个品类的数据长什么样

跨境平台结算与汇兑围绕已成交订单的资金归集展开，处理欺诈拒付属于跨境支付风控的范围。主要数据来源为平台结算中心、银行流水、支付机构后台与ERP订单，日常材料包括平台结算单、汇率表、服务费发票和收款对账表。典型从业主体是跨境卖家财务、税务会计与平台运营，数据更新频率为周或月。出错会导致利润核算错误、税务申报偏差和资金短缺。

本页只处理合同与交易材料比对中的文档解析与分块。材料进入知识库后，解析结果需要保留可回指原文的文档身份与版本；分段需要按具体资料结构检查，避免条件、说明与所约束的内容被拆离。原数据与检索索引需要区分，同一组原数据可以对应多个索引。检索环节不承担授权判断，运营交接时哪些材料、操作、请求处于何种授权状态，需要另行核对。

## 这些特征在「文档解析与分块」这一环带来什么约束

结算单、汇率表、服务费发票和对账表的结构差异较大，分块时需要按各自结构处理。FastGPT 的向量存储采用 PostgresSQL 的 PG Vector 插件作为向量检索器，索引为 HNSW，PostgresSQL 仅用于向量检索，MongoDB 用于其他数据的存取。MongoDB 的 dataset.datas 表中存储向量原数据信息，indexes 字段记录对应的向量 ID，为数组结构，一组数据可以对应多个向量。

检索时先召回向量，再根据向量 ID 去 MongoDB 寻找原数据内容，对应同一组原数据则合并，向量得分取最高得分。多向量映射用于兼顾内容长度与语义丰富度，一组较长文本可以添加多组向量，其中一组被检索到，该数据也将被召回。全文检索在向量库为 Milvus（≥ 2.5.16）时使用 BM25，向量与全文同存于 modeldata_v2 单表；其他向量库走 MongoDB $text 加 jieba 分词。混合检索通过 RRF 公式合并两个搜索结果，重排后得到 0-1 得分，可根据得分过滤。引用上限按 tokens 控制，最低相关度仅在语义检索或使用结果重排时生效。

## 配置怎么定

以下配置围绕假设演练样本展开。样本材料原文为：「甲方委托乙方办理跨境平台结算单核对，服务期间为2024年1月1日至2024年3月31日。乙方应在收到结算单后5个工作日内完成核对并出具对账说明。本委托不包含汇率差申诉。」待判定拟稿句为：「乙方负责处理2024年第一季度全部汇率差申诉。」该拟稿句超出委托范围。

| 配置项 | 设置或核对内容 | 与本样本的关系 |
| --- | --- | --- |
| 分块依据 | 按结算单、汇率表、发票、对账表各自结构分段 | 保留委托期间与排除条款的完整语义 |
| 多向量映射 | 同一组原数据可对应多个向量 ID | 较长委托文本可拆多组索引 |
| 检索模式 | 语义检索、全文检索或混合检索 | 按术语、期间、编号分别核对 |
| 引用上限 | 按 tokens 控制引用内容量 | 本次假设试验起点设为与单份结算单段落相当的 token 量，选取理由为便于观察分段是否完整，比较对象为不同设置下的引用内容差异 |
| 最低相关度 | 0-1 数值，仅语义检索或结果重排时生效 | 本次假设试验起点设为中间值，比较不同阈值下的候选内容 |
| 更新后复核 | 资料变更后核对实际训练与索引状态 | 上传成功不表示检索已更新 |

## 容易做错的三处

1. 将拟稿句中的「全部汇率差申诉」直接视为委托内容。样本原文明确「本委托不包含汇率差申诉」，拟稿句与原文在服务范围字段上取值互斥，构成矛盾。错误在于未比对同一字段的互斥取值。
2. 将上传成功当作检索已更新。样本材料变更后，需要核对实际训练与索引状态，上传动作本身不表示索引已更新。错误在于混淆上传行为与索引状态。
3. 用最低相关度过滤无关业务记录。最低相关度是过滤阈值，不承担权限或实体隔离功能。样本中委托范围与申诉排除条款的判定，需要依靠原文比对，检索设置不能替代。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较服务范围字段的取值。原文载明「本委托不包含汇率差申诉」，拟稿句载明「负责处理2024年第一季度全部汇率差申诉」，同一字段取值互斥，观察结果为矛盾成立。预期为识别出该矛盾，不声称已实测。
2. 输入样本材料原文，比较委托期间与拟稿句期间。原文期间为2024年1月1日至2024年3月31日，拟稿句期间为2024年第一季度，期间一致；服务范围不一致。观察结果为期间一致而范围矛盾，需分别记录。
3. 输入空结果场景，以纸面输入[]核对下游设计。观察下游对空引用的处理方式，不声称虚构规则检索一定返回[]。若检索结果为空，记录缺口，不推断为否定或冲突。
