# 跨境平台结算与汇兑的合同与交易材料比对：权限与数据隔离

## 这个品类的数据长什么样

在跨境平台结算与汇兑的合同与交易材料比对中，本页说明FastGPT的权限与数据隔离如何衔接资料。将对账材料的文字比对与逐账号访问验证分开取证。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

为交易材料比对另拟一个文字测试：平台结算单说明资金归集批次，收款对账表说明对应到账记录。即使两份文字提到同一事项，也应分别确认当前账号是否有权读取各自资源。跨境卖家财务、税务会计和平台运营是业务从业主体，不能将这些称谓直接视为已经配置好的团队角色。测试时记录真实成员身份、资源范围和可见原文，避免把业务分工描述当作系统授权。

## 配置怎么定

| 权限或实施核对项 | 拟议资料范围 | 验收对象 |
| --- | --- | --- |
| 实际成员 | 业务称谓与团队角色分开 | 记录账号在具体资源上的行为 |
| 双份来源 | 结算单与对账表分别验证 | 不由一份可读推定另一份授权 |
| 否定访问测试 | 按方案不应获权的测试身份 | 保留实际可见范围及拒绝结果 |
| 外部系统 | 银行及支付机构资料另核 | 接口鉴权与内部资源权限分开 |
| 授权变更 | 新增读取与撤销旧访问 | 补资料后再次验证两类身份 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 财务、会计或运营分工被当成已配置角色：核真实成员与结算、汇率及对账资源，称谓不提供读取或维护授权。

- 应获权身份只读结算、无权身份却读到对账：两类结果分别保存账号配置及原文，不能调相关度绕过或据不可见认定记录不存在。

- 内部可读结算被当成能取银行或支付凭证：核外部接口权限和真实返回，新增凭证后复测两类身份，不能由概括能力证明整套设计有效。

## 怎么确认配好了

如果需要继续取得银行或支付机构的记录，应另核对应系统的访问条件与接口授权；FastGPT团队角色不自动授予外部资料权限。补入新凭证后，复测获授权与未获授权身份各能读取哪些文字，并核对过去有权账号在授权撤销后的表现。验收分别保留资源访问结果、材料来源和比对范围，回答能够复述对账内容不构成整套权限设计已经有效的证明。
