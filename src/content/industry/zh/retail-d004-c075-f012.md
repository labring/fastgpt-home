# 达人专场带货合作的合同与交易材料比对：文档解析与分块

## 这个品类的数据长什么样

达人专场带货合作围绕外部达人履约和佣金结算展开，材料来源包括精选联盟、巨量星图、达人历史数据与店铺成交明细。日常文档为达人合作协议、佣金设置单、样品寄送单和直播战报，更新节奏为每场或每周。这些材料决定文档解析与分块需要同时处理合同条款、佣金比例、寄样记录和场次结果，分块时须保留主体、对象、期间和有效范围，避免把条件说明与所约束内容拆离。检索与表单只负责查找和收集值，授权状态、合作达成与合同生效属于不同事实，需要依据材料原文逐项核对。

## 这些特征在「文档解析与分块」这一环带来什么约束

FastGPT 知识库由库、集合和数据组成，最小搜索单位是库。向量存于 PostgresSQL 的 vector 字段，索引为 HNSW；MongoDB 的 dataset.datas 表保存原数据及 indexes 字段，一组数据可对应多个向量。检索时先召回向量，再按向量 ID 回 MongoDB 找原数据，同一组原数据合并后取最高得分。语义检索、全文检索、混合检索、RRF 融合与 ReRank 属于不同路径，RRF 是混合结果融合过程，不是开启开关。最低相关度仅在语义检索或结果重排时生效，属于过滤阈值，不承担权限或实体隔离。跨不同向量模型的库不能共同关联，只能先核标识并排除不符合者。

假设演练样本：材料原文为“甲方委托乙方于2025年6月1日进行一场专场直播，佣金比例为成交额的百分之十五，样品于2025年5月20日前寄出。”待判定拟稿句为“乙方已于2025年5月18日完成样品寄送，佣金按百分之十五结算。”原文只载明寄样期限与佣金比例，未载明实际寄送日期与结算已完成，该拟稿句属于未获支持。

## 配置怎么定

| 配置项 | 本页对应设置 | 核对方式 |
| --- | --- | --- |
| 数据存储 | 库、集合、数据三层，最小搜索单位为库 | 确认待核材料落在同一库内 |
| 向量与索引 | PostgresSQL vector 字段，索引 HNSW | 核对索引标识与库标识 |
| 原数据映射 | MongoDB dataset.datas 的 indexes 数组 | 确认一组原数据可对应多组向量 |
| 检索模式 | 语义检索、全文检索或混合检索 | 按术语、编号、自然语言分别检索 |
| 融合与重排 | RRF 融合，ReRank 二次排序 | 确认重排模型已按设置启用 |
| 引用上限 | 每次搜索最多引用 n 个 tokens | 记录本次假设试验起点并比较 |

引用上限的 n 为本次假设试验起点，选择理由是该值便于观察分块长度对召回的影响，比较对象为同一批材料在不同 n 值下的引用内容。该值不属官方默认值。

## 容易做错的三处

1. 把上传成功当作检索已更新，未核对实际训练与索引状态。检查项：输入同一份达人合作协议，比较上传时间与索引状态，观察检索是否返回该版本内容。
2. 把最低相关度当作权限或实体过滤，认为调高后可排除无关达人。检查项：输入同一查询，比较不同最低相关度下的返回集合，观察是否仍出现无关主体。
3. 把待审核请求当作已批准执行。检查项：输入一条待审核的佣金设置单请求，比较请求状态与执行记录，观察是否出现结算动作。

## 怎么确认配好了

- 验证一：输入假设样本原文与拟稿句，比较“2025年5月20日前寄出”与“2025年5月18日完成寄送”，若检索结果只返回原文而未返回拟稿句所声称的完成事实，则满足预期。

- 验证二：输入术语、编号与自然语言三类查询，比较各路径返回内容，若全文检索命中编号、语义检索命中自然语言描述，则满足预期；若某路径无返回，记录为空并保留缺口。

- 验证三：输入明确的纸面空结果[]，核对下游设计是否按空引用处理，若下游未产生虚构引用内容，则满足预期。以上均为纸面核对，未实际执行检索或结算。
