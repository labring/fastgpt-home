# 进出口许可证件办理的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

进出口许可证件办理发生在申报之前，决定一批货物能否合法进出口。日常材料包括自动进口许可证、两用物项许可证、合同和产品说明，来源涉及商务主管部门系统、海关商品编码、供应商资料与客户用途说明。出错会带来无法通关、合同违约或行政处罚。

合同与交易材料比对需要把许可证、合同、产品说明放在同一上下文中核对。材料更新不定期、每票处理，因此每次比对都以当前票的材料为准。上下文与 token 环节要解决的是：模型单次请求能参考多少内容、引用上限截断哪些片段、历史输入是否改变了本次判定依据。

## 这些特征在「上下文与 token」这一环带来什么约束

许可证与合同通常较长，产品说明可能包含规格、型号、用途。模型最大上下文决定单次请求可参考的内容长度，回复上限只控制回答长度，不能当作完整上下文窗口使用。知识库引用上限按 tokens 控制引用内容，单段材料过长时可能被裁剪，需要结合单段长度与问题样本核对内容是否完整进入上下文。

历史输入会改变模型看到的依据。同一问题在空历史和带历史下的输入不同，可能引用到不同轮次的材料。使用固定回复格式时，字段齐全和解析成功需要单独验证，文本长度不能替代结构检查。

## 配置怎么定

以下设置围绕本页合同与交易材料比对任务，均为官方已说明的配置项或实施核对项。数值为本次假设试验起点，用于与另一组值比较，不代表官方默认值。

| 设置项 | 本次假设试验起点 | 核对方式与理由 |
| --- | --- | --- |
| AI 模型 | 选择弹窗中显示支持所需上下文长度的模型 | 比较模型最大上下文与本次合同加许可证加产品说明的总长度，确认材料不被截断 |
| 回复上限 | 打开并设为可容纳依据与处理动作的长度 | 与拟稿句所需字段数比较，过短会截断依据说明 |
| 记忆轮数 | 先保留少量历史轮数 | 比较同一问题在空历史与带历史下的输入，确认历史未引入无关材料 |
| 引用上限 | 按 tokens 设置，覆盖单段最长材料 | 比较单段材料 token 与引用上限，确认关键条款未被裁剪 |
| 回复格式 | 需要固定字段时选择 json_schema 并填写格式要求 | 核对返回字段是否齐全、能否解析，不只看文本长度 |
| 最低相关度 | 仅在语义检索或结果重排时生效 | 该值是过滤阈值，不承担权限或实体隔离 |

## 容易做错的三处

假设演练样本：某公司持一份自动进口许可证，证载进口商为甲公司，商品为某型号设备，有效期至某日期。一份采购合同卖方为乙公司，买方为甲公司，标的为同型号设备，数量与许可证一致。一条拟稿句写“该许可证与合同主体、标的、数量一致，可安排申报”。

1. 把回复上限当作完整上下文窗口。错误表现：材料总长超过模型最大上下文，但核对时只看了回复上限。检查：输入上述三份材料原文，比较材料总长度与模型最大上下文，观察关键条款是否完整进入请求。
2. 忽略引用上限对长材料的裁剪。错误表现：合同关键条款位于长段落末尾，引用上限不足时该段未进入上下文。检查：输入合同原文与引用上限设置，比较单段 token 与上限值，观察被引用内容是否包含该条款。
3. 用文本长度替代结构化字段核对。错误表现：回复格式设为 json_schema 后，只检查回答长度，未检查字段。检查：输入拟稿句与格式要求，比较返回内容字段与要求字段，观察是否齐全且可解析。

## 怎么确认配好了

- 验证一：输入上述许可证、合同、产品说明原文及拟稿句，比较模型最大上下文与三份材料总长度，观察三份材料关键条款是否完整出现在请求中。若总长度超过最大上下文，记录被截断部分，判定为上下文不足。

- 验证二：输入合同原文与引用上限设置，比较单段材料 token 与引用上限，观察合同关键条款是否被引用。若关键条款未出现在引用内容中，记录裁剪位置，判定为引用上限需调整。

- 验证三：输入拟稿句与 json_schema 格式要求，比较返回字段与要求字段，观察字段是否齐全、能否解析。若字段缺失或解析失败，记录缺失字段，判定为结构化承接未通过。

以上均为纸面核对，不声称已实测。检索与相似度设置不承担权限或实体隔离，检索库同向量模型要求不扩展到外部系统。空结果承接可用纸面输入空列表核对下游设计，不声称虚构规则检索一定返回空列表。
