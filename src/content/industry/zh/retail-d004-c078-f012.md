# 连锁总部选址开店的合同与交易材料比对：文档解析与分块

## 这个品类的数据长什么样

选址开店发生在门店营业前，核心材料是租赁和工程交付。连锁总部拓展人员处理选址评估表、租赁意向书、装修预算、开业排期，这些材料按店产生，更新不定期。合同与交易材料比对要求在同一门店、同一期间、同一字段上判断意向书、预算与排期是否一致。材料被拆成数据块后，条款条件与所约束内容一旦分离，比对就失去可回指的原文依据。

## 这些特征在「文档解析与分块」这一环带来什么约束

FastGPT 的知识库由库、集合和数据三部分组成，最小搜索单位是库，集合仅作分类管理。向量原数据存于 MongoDB 的 dataset.datas 表，indexes 字段记录对应向量 ID，一组数据可对应多个向量；PostgresSQL 的 vector 字段存向量，检索先召回向量再按 ID 回原数据，同一组原数据合并取最高得分。分段应保持单一完整语义，条件、金额、日期与约束对象留在同一数据块。检索不等于授权，相似度得分不承担权限或主体隔离。

假设演练样本：某连锁总部拓展人员持有一份租赁意向书，原文为“甲方为某某商业管理方，乙方为某连锁品牌方；意向金人民币五万元，自签署之日起十个工作日内支付；本意向书有效期三十日，逾期未签署正式租赁合同则意向金退还。”另有装修预算原文“该店装修预算总额人民币八十万元，含消防改造。”待判定拟稿句为“双方已签署正式租赁合同，意向金转为押金。”比对对象为同一门店、同一期间、意向金支付与合同签署状态字段。

## 配置怎么定

| 配置项 | 本页适用设置 | 依据与核对方式 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 语义与全文召回经 RRF 融合，适合条款编号与自然语言并存 |
| 结果重排 | 按需启用 ReRank | 重排得分 0-1，可用于过滤，须模型可用且设置开启 |
| 最低相关度 | 假设试验起点 0.3 | 该值仅在语义检索或结果重排时生效，与观察到的命中情况比较后调整 |
| 引用上限 | 按 tokens 设定 | 官方以 tokens 控制引用，非 top k，避免分块长度差异导致不稳定 |
| 分段核对 | 人工核对 | 检查条件、金额、日期与约束对象是否留在同一数据块 |
| 更新后复核 | 人工核对 | 资料变更后核对实际训练与索引状态，上传成功不等于检索已更新 |

## 容易做错的三处

1. 把“意向金支付”与“合同签署”当成同一字段。两者是不同事实，意向书载明支付义务不代表正式合同已签署，拟稿句把签署状态写成已完成，属于未获支持。
2. 把检索命中当成授权。检索返回意向书原文，只说明内容被召回，不说明签署、生效或退款已发生；授权状态须另查。
3. 把上传成功当成索引已更新。资料变更后须核对实际训练与索引状态，未核对时该数据块的检索状态未知。

## 怎么确认配好了

1. 输入假设演练样本中的意向书原文与拟稿句，比较拟稿句所称“已签署正式租赁合同”与原文“有效期三十日，逾期未签署正式租赁合同则意向金退还”。原文未载明已签署，判定为未获支持；若原文出现同主体、同期间、同字段的签署完成记载，才满足支持条件。
2. 输入“意向金”与“五万元”等术语及金额，观察召回数据块是否同时包含支付条件与期限。若召回块缺失期限或约束对象，说明分段不完整，须重新核对分段。
3. 输入装修预算原文，比较“含消防改造”是否与预算总额处于同一数据块。若两者被拆离，比对结果不可回指原文；用空结果 [] 核对下游展示设计，不声称虚构规则检索必然返回空。
