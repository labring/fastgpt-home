# 连锁总部选址开店的合同与交易材料比对：知识库检索与召回

## 这个品类的数据长什么样

选址开店发生在门店营业之前，材料围绕租赁与工程交付展开。选址评估表记录商圈客流与店型测算，租赁意向书承载房东与总部的初步约定，装修预算与开业排期约束交付节点。这些材料在每店、不定期更新，同一门店在不同阶段会留下多份版本。合同与交易材料比对要求把拟稿句或交接请求放回对应材料的有效范围内核对，检索环节只负责把候选原文召回，不承担授权判断。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联，需先核对向量模型标识并排除不符合者。搜索模式按测试问题比较语义、全文与混合检索，不预设一种模式适合全部资料。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，需比较原问题与优化后问题，核对主体是否被改错。引用内容以数组输出，长度可以为 0，空结果链路仍走通。检索不构成授权，待审核不证明缺少操作权限。

假设演练样本：某连锁总部拓展人员拟提交一份租赁意向交接请求，材料原文为“甲方为某商业管理公司，乙方为某连锁总部；意向书载明租赁标的为三层临街铺位，意向有效期至本年度第三季度末；装修预算表列明该铺位硬装费用上限，开业排期表列明交付后六十日开业。”待判定拟稿句为“双方已就租赁条款达成一致，合同自签署日起生效。”

## 配置怎么定

| 配置项 | 本页取值或核对项 | 依据与比较方式 |
| --- | --- | --- |
| 关联的知识库 | 仅关联使用同一向量模型的选址开店材料库 | 核对向量模型标识，排除不同模型库 |
| 搜索模式 | 本次假设试验起点为混合检索 | 与语义检索、全文检索分别比较召回原文 |
| 引用上限 | 本次假设试验起点为覆盖意向书与预算表全文的 token 量 | 与较短取值比较内容是否被截断 |
| 最低相关度 | 本次假设试验起点为标注相关样本后的中间值 | 与更高、更低取值比较无关片段数量 |
| 问题优化 | 对含指代的交接请求开启 | 比较原问题与优化后问题的主体是否一致 |
| 结果重排 | 候选较多且已具备重排模型时启用 | 比较重排前后候选顺序，非开关式必选 |

## 容易做错的三处

1. 把检索召回当作授权确认。拟稿句称合同自签署日起生效，材料仅载明意向有效期，检索到意向书不表示签署已完成，也不表示合同已生效。
2. 把不同向量模型的知识库共同关联。应先核对向量模型标识并排除不符合者，不执行跨模型检索来比较漏召回。
3. 把待审核交接请求当成已获批准。请求处于待审核状态，不证明缺少操作权限，也不构成执行。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句，比较拟稿句所称“达成一致、签署生效”与原文“意向有效期”是否同主体、同期间、同字段；原文未载明签署与生效，判定为未获支持。
2. 输入含指代的交接请求，比较优化后问题与原文主体“某商业管理公司、某连锁总部”是否一致；主体被改错则不满足条件。
3. 输入明确纸面空结果[]，核对下游设计是否承接空引用链路；不声称虚构规则检索一定返回[]。
