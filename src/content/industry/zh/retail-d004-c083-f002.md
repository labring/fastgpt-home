# 门店盘点与防损的合同与交易材料比对：上下文与 token

## 这个品类的数据长什么样

门店盘点与防损围绕账实差异与损耗展开，处理对象是盘点表、差异分析、报损审批与监控调阅记录，不涉及供应商账款结算。这些材料多按月或按季度更新，比对时须以同一盘点周期、同一门店、同一字段为基准。合同与交易材料比对任务要求把盘点表、差异分析等文档中的关键字段与既有记录逐项核对，判断是否存在同一字段下的互斥取值。上下文与 token 环节决定模型单次请求能纳入多少材料原文，影响多份盘点文档同时比对时的完整性。

## 这些特征在「上下文与 token」这一环带来什么约束

一次比对可能同时纳入盘点表、差异分析、报损审批三类文档。模型最大上下文限制单次请求可参考的内容长度，回复上限只约束输出长度，两者不可混用。知识库引用上限按 token 控制每次搜索引用的内容量，单段材料较长时可能被裁剪。开启多轮对话时，历史轮数会占用上下文空间，同一问题在空历史与带历史下输入不同，须分别核对。使用 json_schema 固定回复格式时，须验证字段齐全与解析成功，仅检查文本长度不足以确认结构完整。语义检索与最低相关度只影响召回排序，不承担权限或主体隔离职责。

## 配置怎么定

假设演练样本：某门店 2024 年 3 月盘点表载明“冻品区盘点差异 -12 件，报损审批单号 BL-0312，状态：待审核”；差异分析记录同期间同区域“差异 -12 件，原因待查”。拟判定句：“该门店冻品区差异已获报损审批通过。”比对须核同一门店、同一期间、同一字段，报损审批单状态为待审核，未载明批准生效信息。

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AI 模型 | 选用支持长上下文的模型 | 与盘点表加差异分析合计长度比较，确认可容纳 |
| 回复上限 | 设为可完整表达依据与处理动作的长度 | 与拟判定句所需字段数比较，避免截断 |
| 知识库引用上限 | 按 token 设定，覆盖单份盘点表主要段落 | 与单段材料长度比较，观察是否被裁剪 |
| 记忆轮数 | 保留少量历史轮数 | 与空历史输入比较，排除上下文差异 |
| 回复格式 | 需要固定字段时选 json_schema | 与解析结果比较，确认字段齐全 |
| 最低相关度 | 保持默认或按召回情况微调 | 与召回结果比较，仅影响排序不影响权限 |

## 容易做错的三处

1. 把待审核状态当作审批通过。报损审批单状态为待审核，未载明批准动作，拟判定句称已获通过，属未获支持。可执行检查：输入报损审批单原文，比较状态字段取值，若为待审核则判定句不成立。
2. 把回复上限当作模型完整上下文窗口。回复上限只约束输出长度，模型最大上下文约束输入可参考长度。可执行检查：输入盘点表与差异分析合计文本，比较其长度与模型最大上下文，若超出则部分内容未纳入。
3. 把语义检索相关度当作权限过滤。最低相关度只过滤低相关结果，不排除无权访问的记录。可执行检查：输入含不同门店标识的查询，比较返回结果中的门店标识，确认相关度设置未隔离主体。

## 怎么确认配好了

- 验证一：输入上述盘点表原文与拟判定句，比较报损审批单状态字段与判定句表述，若状态为待审核则判定句不成立，记录为未获支持。

- 验证二：输入同一问题在空历史与带三轮历史两种条件下的请求，比较两次输入内容差异，确认历史轮数占用上下文后关键材料仍完整纳入。

- 验证三：输入明确的纸面空结果 []，比较下游节点承接设计，确认空结果时下游不产生虚构比对结论；不声称某规则检索必然返回空。

跨不同向量模型的库不可共同关联，须先核标识并排除不符合者，记录实际观察，不推断共同关联后的运行结果。
