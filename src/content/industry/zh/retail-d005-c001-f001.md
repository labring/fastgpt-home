# B2B平台撮合交易的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

在B2B平台撮合交易的库存采购与供应商资料中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

采购人员拿到企业认证资料和询报价单，首先要区分材料中写了什么与外部服务能查到什么。自拟样例的认证资料记载原材料生产资质，报价单列出规格和报价；这些文字可以形成查询需求，却没有给出可直接调用的资质查询接口。使用FastGPT的HTTP节点时，先由实施方核实接口契约，再逐项检查请求地址、方法、鉴权和输入值，保留业务系统实际返回的原始记录。

## 配置怎么定

| 实施核对项 | 本题输入 | 验收线索 |
| --- | --- | --- |
| 地址与方法 | 需外部契约支持的查询目标：企业认证资料中的生产资质与询报价单中的原材料规格 | 从已接服务核地址与方法，不将企业认证资料、询报价单名称当作现成接口。 |
| 实际输入值 | 企业认证资料中的生产资质与询报价单中的原材料规格 | 按契约核对Params、Headers或Body中的来源和真实传入值。 |
| 材料含义 | 企业认证资料、询报价单的核对要求：企业认证资料中的注册地址与询报价单中的发货地 | 先区分字段业务含义，再检查变量映射，不自动把差别判为错误。 |
| 调试与业务缺项 | 企业认证资料的未具备依据：尚缺该供应商的历史供货记录与履约情况报告 | chatId等测试字段的可用性与业务材料缺失分开核对。 |
| 外部响应 | 本题的候选数据来源：B2B平台、国家企业信用信息公示系统、支付流水、物流轨迹 | 检查真实响应具体取回或处理了什么；查询不作为写入凭证。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

注册地址在A市、发货地在B市，描述的是两个不同地点，不能直接判成供应商信息冲突。拟接查询若涉及地址，应明确请求要核注册地址还是实际发货地，分别保留认证资料与报价单的出处。检查Params、Body或前方节点变量时，不将两个地址映射为同一业务含义；请求成功后还需回查返回记录的字段说明，判断它回答的是哪个地点问题。 测试时若chatId为空便认定供应商查询失败，还应核调用模式及真正发出的业务条件；该身份字段在测试中不存在，不能用它代替地址查询的返回证据。

## 怎么确认配好了

仅有企业认证资料，仍无法说明供应商历史供货和履约情况。应先确认这些记录由哪个获授权来源提供，再按外部接口实际要求准备查询输入。调试中chatId或responseChatItemId不存在，与缺少履约报告是两件事；补充会话变量不能补出业务证据。取得真实记录后重放原查询，并核对返回内容与接收步骤，采购准入及下单审批另按业务流程落实。
