# MCN机构达人管理的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

在MCN机构达人管理的库存采购与供应商资料中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

MCN的供应商资料问题可先限定为查找某次合作的现有记录。自拟输入包括达人合同中的合作对象、排期说明及待查培训材料；这些文字并不证明对方已经具备采购准入资格。拟接的外部资料服务应由实际负责人提供接口契约，再核请求地址、方法和对象对应关系。平台资料中没有给出可直接使用的MCN查询端点，本题也不预设一个端点存在。

## 配置怎么定

| 核对对象 | 本题拟议输入 | 验收线索 |
| --- | --- | --- |
| 外部契约 | 资料负责人给出的服务说明 | 方法与地址有实际依据 |
| 合作身份 | 合同对象与排期账号分别列明 | 请求和响应指向同一合作 |
| 版本传递 | 前方节点输出的资料版本 | 发送值没有遗漏或替换 |
| 培训缺口 | 合同已给，培训记录未给 | 返回缺口仍清楚可见 |
| 业务写入 | 拟议台账更新另行授权 | 独立检查真实操作回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

若用排期中的账号显示名代替合同合作对象发请求，返回内容可能属于其他账号，不能据此判断本次资料齐全。应排查原文身份、请求参数与响应所指对象，并保留无法对应的部分。另一项失败是需要携带的资料版本没有进入请求：逐项对照前方节点输出和实际发送值，确认缺的是业务资料还是变量传递，不能由字段名称相似推定已经匹配。 若返回只给培训签到却报告合作资料齐全，应将实际返回与本次所需合同范围、培训内容逐项对照；参加记录不说明具体培训内容已取得，仍须保留对应原文缺口。

## 怎么确认配好了

验收可分别准备合同已给、培训材料尚缺，以及后来补齐对应资料的文字输入。检查调用前后的请求与返回是否保留同一合作对象，答复只解释取得的记录。鉴权从受保护的配置注入，公开测试不展示凭证。需要写入合作台账或发起审批时，另外核授权和真实业务回执；HTTP请求完成只提供这次外部交互的证据，不证明供应商审核已经完成。
