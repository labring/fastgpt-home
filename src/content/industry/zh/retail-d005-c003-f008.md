# Shopify独立站订单履约的库存采购与供应商资料：工作流编排

## 这个品类的数据长什么样

在Shopify独立站订单履约的库存采购与供应商资料中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

独立站补货流程可先收订单需求、拟核库存地点及还缺哪类可用性说明。自拟文字只列订单中的商品和地点，不提供现有库存，也不把发货标签当作备货凭证。提交后检查读取步骤保留的是需求还是库存结论，商品描述是否仍有订单来源；表单可以传递文字，不能从店铺商品名称推定外部库存服务采用同样的标识。

## 配置怎么定

| 核对环节 | 本题自拟资料 | 应观察内容 |
| --- | --- | --- |
| 需求性质 | 订单商品与待满足件数 | 没有转成库存可用量 |
| 地点缺口 | 只有拟查地点无可用说明 | 仍保留需要补证的状态 |
| 选择错接 | 补地点进入下单说明 | 核选择与接收步骤 |
| 身份对应 | 店铺名称与库存系统标识 | 未按名称自动猜映射 |
| 业务写入 | 采购、预留及订单回写另接 | 实际结果分别取证 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

可分别选择先补地点依据、交采购人员核供货或仅整理已给订单，逐条查看实际连接。若选择补地点却进入下单说明步骤，应排查接收内容和选择去向，停止沿用未核的地点。另一个错误是数量所指对象在传递中丢失，订单件数被当成仓库可用量；对照原句与下游输入，恢复“待满足需求”的性质再继续。 若发货标签被流程当成库存已预留，应核标签原文与本地点库存来源；标签创建只说明已有这份运输材料，不提供本商品的实际预留记录。

## 怎么确认配好了

验收记录需求原文、地点资料、实际分支与最终说明，补齐库存来源后重新问同一问题，确认未知项没有被默认变成可用。交互节点等待人员处理后继续执行，这一过程不等于库存已经核准。采购创建、库存预留与订单回写需另外配置接口或业务流程，分别看权限、返回和真实记录，不能以本次整理完成推定采购单已建立或库存已扣减。
