# Temu半托管卖家运营的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

在Temu半托管卖家运营的库存采购与供应商资料中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

半托管卖家的采购阅读可以围绕申报商品与海外仓记录之间的对应关系展开。自拟材料给出商品申报文字、海外库存表的版本说明及待核履约需求，暂不提供仓内可调拨依据。接入外部WMS前，应从真实接口文档核请求对象和方法，再把已给的商品、仓库及版本信息逐项映射；申报资料齐全只说明已有这些文档，不能代替海外仓实际可用状态。

## 配置怎么定

| 核对对象 | 本题拟议输入 | 验收线索 |
| --- | --- | --- |
| 商品对应 | 申报描述与仓内标识依据 | 不是只按名称猜对应 |
| 仓库来源 | 前方已选海外仓 | 请求及返回保留同一仓 |
| 版本范围 | 库存表适用版本说明 | 答复可回指这份记录 |
| 调拨缺口 | 未提供可调拨依据 | 没有推定已可转仓 |
| 写操作 | 拟议补货或转仓需求 | 另核操作范围和业务返回 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

如果请求把店铺商品名称当成仓内编码，可能查到错误对象，需排查申报原句与外部系统实际标识的对应依据。若前方已选海外仓，但发送时仍引用另一仓的输出，应对照调用前变量、请求内容及返回仓库，修好引用再复测。两项资料属于不同仓时，应先保留差异，不能合并成同一采购可用量。 若库存快照被写成本次调拨已发生，应分别核快照适用时点与实际调拨过程记录；表中有余额不证明某项移动已经计入，不能由读取成功替代对应依据。

## 怎么确认配好了

验收时分别查看缺调拨资料、取得对应仓记录和返回对象不明的输入，要求答复写清所据版本及未核部分。只有外部契约要求请求体时才按其结构组织Body；参数与鉴权头分开核。创建补货单、转仓或修改履约记录需要另外检查授权、操作范围和业务返回；一次查询有响应不表示这些动作已经被受理。
