# Temu半托管卖家运营的库存采购与供应商资料：工作流编排

## 这个品类的数据长什么样

在Temu半托管卖家运营的库存采购与供应商资料中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

半托管采购核对可以先把申报商品、海外仓和待补可用依据分别交给流程。自拟输入给出申报描述与库存表版本，明确没有调拨确认。表单提交后，后续步骤要承接这些资料的实际范围，不能从表格存在推断货物可转仓。库存表涉及哪个仓、哪批商品，需要由提供的文字核对；流程节点排列完毕，并不表示系统已经接通WMS或完成库存核验。

## 配置怎么定

| 核对环节 | 本题自拟资料 | 应观察内容 |
| --- | --- | --- |
| 资料范围 | 申报描述与库存表版本 | 未由表存在推可调拨 |
| 仓库错配 | 改选仓库仍传旧仓来源 | 核选择和实际接收值 |
| 交接边界 | 缺调拨依据交经办人 | 输出仍为待处理事项 |
| 新增确认 | 对应仓库的补充原文 | 下游实际收到该依据 |
| 外部状态 | 采购或平台提交另接步骤 | 分支执行未代替业务更新 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

若仓库选项只改变了显示文字，传给下一步的仍是前一个仓的资料，就会造成对象不一致。应排查选择记录、接收文本和版本来源，修好连接后分别试每个去向。另一项测试是缺调拨资料时选择交经办人，但实际输出却写成已调拨；需回看交接内容与结果判断，保留待处理状态，不能由路径执行推定业务已经办理。 若资料节点已连好就称WMS已查询，应另核实际业务接口是否连接、真正发出的请求及仓库返回；现有表格的传递不能代替外部读取证据。

## 怎么确认配好了

验收并列检查申报原文、仓库身份、调拨缺口和实际输出，在补齐对应确认后重复原需求，看下游是否收到新增依据。交互状态由触发节点记录并等待输入，不宣称另有全局状态开关完成审查。若要创建采购、修改海外仓数据或提交平台资料，应另接实际业务步骤，核权限及真实回执；本次选择结束不证明这些外部状态已经更新。
