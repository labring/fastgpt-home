# 一般贸易出口报关的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

一般贸易出口报关每单都要处理出口报关单、商业发票、装箱单和合同，数据来源包括中国国际贸易单一窗口、海关编码库、货代提单和企业 ERP。与一般贸易进口报关相比，出口报关还会影响出口退税凭证匹配。库存采购与供应商资料在这一环节的核心是：采购合同、供应商发票、装箱单与出口报关单之间的数量、金额、品名和计量单位需要保持一致，任何一处不符都可能触发退单查验或申报差错，进而阻碍退税。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params、Headers、Body 三处均可通过 `{{}}` 引用全局变量、系统变量或前方节点输出。系统变量包括 appId、chatId、responseChatItemId、variables、cTime 和 histories。chatId 与 responseChatItemId 在测试模式下不存在，测试环境取到空值属于调试状态，不代表业务数据缺失。返回值需要通过 JSON path 或 JS 对象取值规则配置 key 来提取，输出类型选择字符串时会将对应值转为 json 字符串。HTTP 模块对接外部系统时，检索环节的相似度分数不承担权限过滤或业务实体隔离功能，检索结果不代表授权通过。

假设演练样本：某外贸公司单证员在 2025 年 3 月 10 日整理一笔出口订单的供应商资料。采购合同原文写明：“供应商：华东纺织有限公司；商品：涤纶针织布；数量：12000 米；单价：4.5 元/米；总金额：54000 元；交货日期：2025 年 3 月 20 日。”商业发票原文写明：“Invoice No. INV-20250310；数量：12000 米；总金额：54000 元。”装箱单原文写明：“共 400 箱，每箱 30 米，合计 12000 米。”拟通过 HTTP 接口将上述三份材料的数量与金额字段推送至外部报关系统，待判定请求为：“请将合同金额 54000 元、发票金额 54000 元、装箱单数量 12000 米写入报关单对应字段。”该请求涉及的材料处于已收集待核对状态，尚未获得向外部系统提交的授权。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部报关系统接口文档提供的 URL 和 POST 方法填写 | 比对接口文档中声明的路径与方法 |
| Headers 鉴权 | Authorization 通过安全配置注入，样例中不写入凭证 | 确认凭证来源为独立配置项 |
| Body 结构 | 按接口契约构造 JSON，字段名与外部系统要求一致 | 逐字段比对接口文档字段表 |
| 变量引用 | 合同金额、发票金额、装箱单数量分别引用前方节点输出 | 核对引用 key 与节点输出名称一致 |
| 返回值提取 | 按 JSON path 提取外部系统返回的受理状态字段 | 对照接口响应示例核对 key 路径 |

试验起点选择理由：上述字段均为本次样本中实际出现的材料字段，选择它们是为了验证 HTTP 模块能否正确传递这些值。若外部接口文档给出不同的字段名，以文档为准。

## 容易做错的三处

1. 将合同金额 54000 元直接写入报关单金额字段，未与发票金额和装箱单数量做交叉核对。输入为三份材料原文，比较对象为三者数量与金额是否一致，可观察结果为三份材料数量均为 12000 米、金额均为 54000 元，一致后方可进入下一步。
2. 在 Body 中引用字符串变量时未加双引号，导致 JSON 解析异常。输入为拟稿请求中的金额字段，比较对象为 Body 声明中字符串是否包裹 `""`，可观察结果为解析后的 JSON 将金额保留为字符串类型。
3. 将测试模式下 chatId 为空视为业务故障并中止请求。输入为测试环境调用记录，比较对象为文档说明的测试模式行为，可观察结果为 chatId 在测试模式下不存在属于正常现象。

## 怎么确认配好了

1. 输入假设样本中三份材料原文及拟稿请求，比较合同、发票、装箱单的数量与金额字段是否两两一致，观察三者均为 12000 米和 54000 元时满足核对条件。
2. 输入拟稿请求中的 Body 声明，比较字符串字段是否按文档要求包裹双引号，观察解析后 JSON 结构与接口契约字段表一致时满足条件。
3. 输入外部系统返回的响应示例，比较配置的返回值提取 key 是否与响应中的实际字段路径对应，观察提取结果与接口文档示例一致时满足条件。若响应中不含预期字段，记录实际响应内容，不推断失败原因。
