# 一般贸易进口报关的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样
进口报关围绕完税价格、运保费和税费缴纳展开，数据来源包括国际贸易单一窗口、海关税则、货代到港通知和外汇付款单。库存采购与供应商资料这一环，日常要处理进口报关单、商业发票、装箱单、提单和合同，数据更新频率为每单。这些材料的主体、金额、状态和有效范围各不相同，定时任务读取时必须逐单核对，不能把某单的字段值套用到另一单。

## 这些特征在「定时任务与自动化」这一环带来什么约束
外部数据由已配置接口读取，不能假定定时触发自动建立业务系统连接。触发责任需明确由应用定时能力还是外部调度承担，并按实际版本核对可用入口。HTTP 请求按外部接口文档核对方法、请求头、请求体和变量输入。去重、幂等与业务写入需在接口或后续流程明确设计。执行记录核对触发时间、真实输入、返回结果与业务状态，任务存在不能替代执行成功。

假设演练样本：某进口商关务经理收到货代到港通知，通知原文为「编号 IMP-2024-001 项下货物预计 3 月 18 日到港，提单号 BILL-001，请于到港前提交报关资料」。现有商业发票原文为「发票号 INV-001，合同号 CON-001，成交方式 CIF，金额 120000 美元」。一条待判定的交接请求拟稿句为「系统已自动完成该单报关资料提交，税费已缴纳」。该拟稿句中的自动提交和税费缴纳在本样本中没有对应授权或执行记录。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 触发方式 | 外部调度触发 | 核对实际版本可用入口，与手工触发区分 |
| 请求方法 | POST | 对照外部接口文档确认方法 |
| 请求头 Authorization | Bearer 加变量 | 按接口文档核对令牌来源 |
| 请求体字段 | 合同号、发票号、提单号 | 对照样本原文逐项比对 |
| 返回值提取 | 按 JSON path 取 message 和 data.user.name | 对照接口响应示例核对路径 |
| 执行记录 | 记录触发时间与返回结果 | 核对输入、输出与业务状态 |

## 容易做错的三处
1. 把定时任务存在当成业务执行成功。样本中拟稿句称已自动提交并缴税，实际没有对应执行记录，需核对触发时间、真实输入和返回结果。
2. 把检索或表单当成授权执行。样本中交接请求只列出材料，未附授权边界，不能据此认定提交或缴税已获批准。
3. 把相似度设置当成权限或实体过滤。样本中发票号 INV-001 与提单号 BILL-001 分属不同材料，相关度不负责隔离无关记录。

## 怎么确认配好了
1. 输入样本原文「编号 IMP-2024-001 项下货物预计 3 月 18 日到港，提单号 BILL-001」与拟稿句「系统已自动完成该单报关资料提交，税费已缴纳」。比较拟稿句声称的动作与原文所列材料范围。原文只含到港通知和发票信息，未含提交或缴税记录，拟稿句超出原文范围，判定为不满足。
2. 输入样本发票原文「发票号 INV-001，合同号 CON-001，成交方式 CIF，金额 120000 美元」与请求中引用的合同号、发票号。比较两者是否一致。若请求引用的合同号或发票号与原文不符，判定为输入不匹配，需回到材料核对。
3. 输入样本交接请求，比较其是否写明授权状态。请求未写明授权主体、授权范围或批准记录，判定为授权边界缺失，需补齐后方可进入下游流程。
