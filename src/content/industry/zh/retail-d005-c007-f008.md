# 一般贸易进口报关的库存采购与供应商资料：工作流编排

## 这个品类的数据长什么样

在一般贸易进口报关的库存采购与供应商资料中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

进口采购流程可以先核供应商合同、货物描述与到货说明各自提供了什么。自拟输入保留合同主体和提单相关文字，注明本次仓库接收资料未给。表单传向后续读取时，应区分供应商身份与运输对象，不能从进口资料已提供推定商品已经入库可用。采购人员想知道的供货情况，也需要对应依据，不由货物已经安排运输就推导出当前交付承诺。

## 配置怎么定

| 核对环节 | 本题自拟资料 | 应观察内容 |
| --- | --- | --- |
| 主体区分 | 合同供应商与运输对象 | 未相互替代身份 |
| 缩写缺陷 | 全名被换成无据简称 | 核接收值后保留对应缺口 |
| 补接收路径 | 选择补仓库却只收到到货通知 | 资料范围不足仍列清 |
| 同笔补证 | 新增本次仓库记录 | 后续实际使用对应来源 |
| 业务验收 | 采购登记或档案修改另接 | 不由继续执行推定已办 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

若填写的供应商全名传到下游只剩无对应依据的缩写，应排查原文与接收值，避免引用其他主体资料。可选择补仓库接收或回看合同条款，分别核分支实际去向；若补接收的选择仍只收到到货通知，要指出材料范围不足，不能从“到货”两个字跳到“本次订单已入库”的结论。 若发票仅给一般品名，流程却补出厂家型号，应回查制造方对应说明与原品名范围；运输和贸易描述不提供型号映射，缺来源时不能用于采购选型。

## 怎么确认配好了

验收并列记录主体、运输资料、仓库缺口与分支输出，补入同笔记录后复问，确认新依据被后续步骤收到。交互状态记录是节点行为，不代表供应商审查完成或仓库批准。需要查询外部入库记录、登记采购或修改档案时，另接实际接口并核授权与业务回执；流程继续向下，不证明进口手续、采购验收或付款已经办理。 本题还应将完整合同主体原句与运输对象并列，供接收人直接核对应关系，不能只凭缩写完成身份判断。
