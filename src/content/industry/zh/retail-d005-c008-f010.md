# 亚马逊FBA备货运营的库存采购与供应商资料：引用来源与溯源

## 这个品类的数据长什么样

在亚马逊FBA备货运营的库存采购与供应商资料中，本页说明FastGPT的引用来源与溯源如何衔接资料。仓内现有托盘、待选材料与下次计划要求不能互相代替。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

FBA采购资料自拟仓内盘点“有木托盘”、备料申请“托盘材料待选”和下一次送仓计划“适用要求另确认”。问能否直接用现有托盘完成下次备货时，盘点只说明观察到物料，申请未完成选材，计划也未给适用确认。引用应保留仓内位置与计划对象，不能因为都写托盘，就把库存存在解释成满足下一次要求，或把采购申请写成已经确定木材方案。

## 配置怎么定

| 采购溯源核对项 | 自拟材料与范围 | 取证动作 |
| --- | --- | --- |
| 盘点观察 | 仓内有木托盘 | 保留地点及记录范围。 |
| 选材状态 | 材料待选 | 不改为方案已定。 |
| 计划要求 | 下一计划另确认 | 查对应适用文字。 |
| 分配依据 | 有库存不等于本次可用 | 核位置和分配记录。 |
| 确认适用 | 物料与计划对应 | 不扩到后续全部。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是有木托盘被写成适用本计划，应核计划的具体材料要求。第二处是待选申请被答成已经选定，应查实际选材或确认记录。第三处是盘点数量身份被移到另一仓位，回答当作本次可分配，应核物料所在位置及对应分配依据。三项分别查适用条件、决策状态和库存归属，不由仓内记录存在推定能够直接使用，也不补实际到仓结果。

## 怎么确认配好了

验收分别问盘点观察、申请状态和计划缺项，实际引用应让三者来源可分。对直接使用问题，输出需列出仍待确认的材料与分配，不把待核写成不合格。若引用只含旧盘点，检查计划与申请是否实际进入回答；空引用不证明仓内没有托盘。补入确认后核对应计划及物料位置，再看是否能够支持本次使用条件，不能把某次确认扩大到全部后续备货。
