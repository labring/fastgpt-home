# 亚马逊FBA备货运营的库存采购与供应商资料：知识库检索与召回

## 这个品类的数据长什么样

FBA备货把库存前置到平台仓，入仓计划和箱唛决定货件能否按时上架，库存报告与赔偿申请决定后续费用与索赔能否追溯。这些材料由采购单、供应商资料与货代轨迹共同支撑，检索环节要面对同一供应商的多个版本、同一箱唛的多批货件。资料给出的更新频率为日、周，检索库内容随之变动，本页不据此推断批量或实时机制。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库，最小搜索单位是库，集合只作分类管理。混合检索通过 RRF 融合语义与全文结果，重排须具备模型并按设置启用，图片检索须有图像输入及相应模型能力。最低相关度仅在语义检索或使用结果重排时生效，引用上限以 token 为单位。检索结果不构成授权，供应商是否已确认报价、采购单是否已审批，须由下游实现判断。

假设演练样本。供核对材料原文：“供应商A于2025年3月1日提交报价单，报价有效期至2025年3月31日。采购单PO-0310于2025年3月5日创建，状态为待审批。箱唛文件尚未生成。”待判定拟稿句：“供应商A已确认报价，采购单PO-0310已批准，可安排入仓。”核对该句与原文：报价有效期不表示供货期限，待审批不表示已批准，箱唛未生成表示入仓材料不完整。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 关联知识库 | 采购与供应商资料库 | 与入仓计划库向量模型标识一致才可共同关联 |
| 搜索模式 | 混合检索 | 与语义检索、全文检索分别比较同一问题召回差异 |
| 引用上限 | 假设起点2000 token | 用长短不同的采购单与箱唛片段比较内容完整性 |
| 最低相关度 | 假设起点0.3 | 先标注相关与无关样本，再与0.2、0.4比较 |
| 问题优化 | 开启 | 比较多轮追问下原问题与优化后问题的主体是否被改错 |
| 结果重排 | 按设置启用 | 与未重排结果比较排序，核对是否具备重排模型 |

以上数值为本次假设试验起点，非官方默认值。跨不同向量模型的库不可共同关联，先核标识并排除不符合者。

## 容易做错的三处

1. 把检索命中当作授权。输入为含“待审批”的采购单片段，比较检索输出与审批状态字段，若输出被用于安排入仓即属错误。
2. 把报价有效期当作供货期限。输入为报价单原文，比较有效期字段与供货期限字段，若拟稿句据此断言可供货即属错误。
3. 把空引用数组当作无资料。输入为明确纸面输入[]，比较下游设计是否承接空结果，若下游假定必有内容即属错误。

## 怎么确认配好了

1. 输入上述材料原文与拟稿句，比较拟稿句中的“已确认报价”“已批准”与原文状态字段，仅当原文出现对应审批或确认记录才满足条件；当前原文未载明，属未获支持。
2. 输入同一采购问题分别以语义检索与全文检索执行，比较两路召回内容，观察混合检索经 RRF 融合后是否同时包含两路命中项；无法共同关联的库先排除，不执行跨模型比较。
3. 输入明确纸面输入[]，比较节点输出是否为长度为零的数组，并核对下游设计是否承接该空结果；不声称虚构规则检索必然返回[]。
4. 输入含供应商A的多轮追问，比较问题优化前后检索词的主体是否仍为供应商A，若主体被改为其他供应商则记录为观察到的偏差。
