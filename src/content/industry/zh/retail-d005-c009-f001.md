# 亚马逊FBM自发货运营的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

在亚马逊FBM自发货运营的库存采购与供应商资料中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

FBM采购资料中的需求说明，与发货后的物流记录回答不同问题。自拟输入可以同时提供拣货单商品描述和发货确认，另注明供应商当前供货说明未取得。HTTP步骤应按实际业务目标选择外部契约，不能因存在承运商查询就把它当作供应商查询。前方节点已给的订单、商品及资料身份，应逐项核其用途，不假定不同系统采用同一种标识。

## 配置怎么定

| 核对对象 | 本题拟议输入 | 验收线索 |
| --- | --- | --- |
| 业务问题 | 本次供应商供货咨询 | 没有改成承运商查询 |
| 地址用途 | 退货地点与采购地点分开 | 请求没有错用地址来源 |
| 商品描述 | 拣货单中的待购对象 | 按外部定义核对应身份 |
| 范围错误 | 用发货确认推断供应能力 | 回查原文并移除无据判断 |
| 实际采购 | 业务方授权及操作凭证 | 独立于物流状态验收 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

若把退货地址设置中的地点传作采购收货地点，可能返回无关的供货说明，需排查地址的原文用途和发送位置。另一个错误是发货确认已传入，后续仍把它作为供应商履约能力的证明；应对照响应所支持的范围和答复中的判断，撤去没有采购依据的推论，要求补本次供货资料后再问。 若发货确认被解释成承运方已接包裹，应分别核商家确认与实际揽收记录；前者说明商家作出这项说明，不代替物流方对本包裹的接收依据。

## 怎么确认配好了

验收时保持“当前供货依据尚缺”的输入，观察请求是否只查契约允许的对象、返回能否回指本次问题。公开示例不含真实地址、凭证或接口端点，鉴权用安全配置。采购申请、修改地址或确认发货若要执行，另验权限与业务回执；请求能返回物流状态并不证明采购系统已经接受操作，也不表示供应商已承诺交期。
