# 亚马逊FBM自发货运营的库存采购与供应商资料：工作流编排

## 这个品类的数据长什么样

在亚马逊FBM自发货运营的库存采购与供应商资料中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

FBM采购资料流程可将拣货需求、发货确认与待补供应商说明分开传递。自拟文字明确这次只有订单和运输资料，没有当前供货承诺；后续步骤应保留这个范围，不能从过去发过货推出供应商本次能够供货。表单收的是所填内容，既不自动查询供应商，也不由退货地址设置推定采购收货地点或当前服务约定。

## 配置怎么定

| 核对环节 | 本题自拟资料 | 应观察内容 |
| --- | --- | --- |
| 时间范围 | 历史发货与当前供货分开 | 未从过去执行推出本次承诺 |
| 地址用途 | 退货地点误入采购输入 | 回查原文后纠正 |
| 选择安排 | 补供货、核需求或整理原文 | 各分支接收正确资料 |
| 补证缺口 | 供货路径仍只收发货确认 | 未把历史资料改作承诺 |
| 采购业务 | 登记或订单回写另行连接 | 实际权限和回执独立核 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

若退货地点被传成采购收货地点，路径虽继续也会处理错误对象，应排查地址原文用途与下游接收内容，修正后复测。可分别选择补供货说明、核订单需求或仅整理已给材料，逐项看分支；若补供货步骤只收到发货确认，应保留来源不足，不能让经办人一次选择把历史运输记录变成当前承诺。 若拣货单只有商品文字，流程却自行指定供应商，应核本次供应商资料与商品的对应依据；店铺有需求或库存不说明由谁供货，缺原文时保留主体待核。

## 怎么确认配好了

验收从本次采购问题追到提交文本、分支接收值和最终输出，补真实供货资料后再问，核新增说明是否进入回答。交互状态由节点触发记录，等待结束不代表采购审核完成。外部查档、采购登记或订单回写需要另行连接并核实际权限及回执；流程完成不证明采购单已生效、地址已变更或供应商已经接受本次订单。
