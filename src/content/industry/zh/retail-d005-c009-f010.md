# 亚马逊FBM自发货运营的库存采购与供应商资料：引用来源与溯源

## 这个品类的数据长什么样

在亚马逊FBM自发货运营的库存采购与供应商资料中，本页说明FastGPT的引用来源与溯源如何衔接资料。左右配件目录与补货申请需要核当前主件对象。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

FBM采购溯源自拟配件目录“左右版本分列”、补货申请“补左侧接头”和备货记录“接头包已整理”。问是否已经准备好本次左件时，目录说明存在区分，申请提出需求，整理记录却没有列左右或主件适配。引用应保持三个层次，不能把接头包这一大类词自动补成左侧版本，也不能由目录有左件就推定当前主件适用或本次已经备齐。

## 配置怎么定

| 采购溯源核对项 | 自拟材料与范围 | 取证动作 |
| --- | --- | --- |
| 目录区分 | 左右版本 | 保留选项身份。 |
| 本次需求 | 补左侧接头 | 核所问对象。 |
| 包内明细 | 整理记录只写接头包 | 补核版本及组成。 |
| 主件适配 | 当前主件资料不足 | 核型号关系不借别款。 |
| 备货事件 | 新增明细可能属别次 | 核事件后再引用。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是目录可选左件被写成本次库存已备，应核实际备货明细。第二处是接头包记录被当成左件确认，应查包内版本及对应主件。第三处是另一型号的左件说明被引来回答当前需求，应核主件身份和目录适用范围。三项分别读取活动结果、组成内容与型号关系，不能用名称接近或引用数量代替对象匹配。无具体主件资料时保留适配缺项。

## 怎么确认配好了

验收分别问目录如何区分、申请需要哪侧、整理记录列了哪些细项，再核本次结论有何依据。答案应保留左侧需求与接头包明细缺项，不补已经拣好或适配已验证。检查实际引用是否有主件对应，来源名叫左件也不能跳过正文。补入明细后核它属于哪次备货，再比较引用；空引用不表示左件不可供应，只有目录也不说明供应已经发生。
