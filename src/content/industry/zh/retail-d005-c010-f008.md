# 京东POP第三方店铺运营的库存采购与供应商资料：工作流编排

## 这个品类的数据长什么样

在京东POP第三方店铺运营的库存采购与供应商资料中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

京东POP采购资料流程可先收商品信息、供货相关协议及本次仍待确认的事项。自拟输入还列有一项质保维修记录，但没有当前供货回复；维修属于另一个服务问题，不能直接用来判定供应商本次违约或无法供货。表单提交后应核下游保留了每项来源范围，协议适用对象与商品身份需要文字对应，不由文件标题推定全部材料已经齐备。

## 配置怎么定

| 核对环节 | 本题自拟资料 | 应观察内容 |
| --- | --- | --- |
| 个案范围 | 维修记录与本次供货分开 | 未据维修判供货违约 |
| 主体传递 | 协议适用对象原句 | 下游未丢掉合作范围 |
| 缺证去向 | 补供货却收到维修标题 | 核资料和连接后重测 |
| 补回复 | 同商品本次供货说明 | 输出实际引用新增来源 |
| 业务批准 | 档案修改或下单另接流程 | 选择未充作采购许可 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

可分别选择补本次供货说明、回看协议或交经办人核实，查看每个去向。若补供货的分支只收到维修标题，应排查传入资料和连接，明确缺的是供货依据。若协议的适用主体在下游丢失，可能将其他合作范围套入本题，需要对照原句恢复范围后再继续，不能把分支已经运行当成资料审查通过。 若维修记录被流程写成供应商本次供货违约，应回查质保所记服务范围和当前供货依据；售后个案不是本次供货执行结果，不能用维修发生直接判违约。

## 怎么确认配好了

验收保留商品、协议、维修个案与供货缺口，补对应回复后复问采购需求，看答复是否真正引用新增依据。记录交互状态是节点行为，人员选择只安排已连接路径，不代替采购批准。供应商档案修改、下单或外部状态同步另接真实业务流程，核授权及操作回执；本次资料整理结束不证明供应商已准入或订单已被接受。
