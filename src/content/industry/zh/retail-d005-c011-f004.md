# 仅退款争议处理的库存采购与供应商资料：向量模型与索引

## 这个品类的数据长什么样

在仅退款争议处理的库存采购与供应商资料中，本页说明FastGPT的向量模型与索引如何衔接资料。争议补充采购的替换外盒、内物状态和申请附件按证据对象索引。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

争议补充采购可拟申请“想补一个外盒”、商品页“空盒，不含内物”和买家说明“内物情况另拍”。拟索引却写“商品损坏整套补发”。当前问现有材料能否支持采购整套。外盒申请只指容器，商品页明确空盒，内物还未说明。应让索引聚焦这些原数据的对象与缺项，不从争议背景推商品已经损坏，也不将买家想补外盒写成已经批准整套补发或供方已确认供货。

## 配置怎么定

| 原数据与索引核对 | 具体对象关系 | 验收动作 |
| --- | --- | --- |
| 采购对象 | 当前申请希望补一个外盒，只指容器 | 用外盒问题核原块，不由售后背景扩成整套。 |
| 商品组成 | 商品页明确空盒，不含其中商品 | 逐词核整套补发索引增加了哪些内物。 |
| 观察状态 | 买家说明内物另拍，当前没有所见记录 | 返回申请不代表已返回照片内容或损伤证据。 |
| 旧整套页 | 历史补发可能属于另一申请及商品 | 分别对请求身份和组成，不能以售后主题相同移用。 |
| 业务动作 | 希望补外盒、采购确认和实际补发分别留证 | 查引用采用到哪一步，不把索引写法当批准。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

第一处是空盒索引新增内物，应比原数据组成与拟索引，保留不含条件。第二处是内物另拍被写成已经证实损坏，应核申请附件及实际观察，不让索引增加事件结论。第三处是旧整套补发页被当前外盒问题采用，应对申请、对象和版本，不能以都属售后就沿用。三项分别查组成、事实状态和来源对应，不能用检索相似度决定补发范围。

## 怎么确认配好了

验收分别问申请要什么、空盒含什么、内物还缺什么，逐句看实际引用和索引所连原块。修改后以外盒与整套问题复测，记录当前返回是否保留缺项。未找到内物资料时不推完好或损坏，也不自动判采购已拒。这里只做自拟文字关系测试，无实物检查；模型和索引变化不批准退款、不创建补发订单，也不证明真实客户损失或现实采购已经发生。
