# 仅退款争议处理的库存采购与供应商资料：工作流编排

## 这个品类的数据长什么样

在仅退款争议处理的库存采购与供应商资料中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

仅退款争议引出的采购流程，可以先收客户提出的问题、仓库出库说明及待取供应商回复，分别保留来源性质。自拟输入不含平台责任结论，不能由投诉存在就认定采购商品已核实有问题。表单传给后续读取时，要区分陈述与业务记录，也要核本次商品和订单是否对应；流程安排的是资料承接，不自动完成供应商责任调查或采购处置。

## 配置怎么定

| 核对环节 | 本题自拟资料 | 应观察内容 |
| --- | --- | --- |
| 陈述性质 | 客户问题附待核说明 | 下游未改成检查结果 |
| 订单对应 | 商品与仓库出库记录 | 本次身份有文字依据 |
| 分支来源 | 补供应商却收签收文字 | 来源不足仍清楚列明 |
| 新说明 | 本次供应商回复后复测 | 输出引用实际新增原文 |
| 处置办理 | 索赔或采购调整另接 | 不由资料流程判责任 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

若客户陈述在传递中失去“待核”说明，后续可能把它当成检查结果，应排查原始填写与接收文本，恢复性质再问。可让人员选择补供应商回复或回看仓库记录，逐项核分支；若补回复仍只收到物流签收文字，应明确该材料无法证明供应商认可，不能由选项已经执行推出索赔条件成立。 若仓库出库说明被写成承运方已经接货，应回查出库原句与本订单揽收依据，分开仓内处理和物流接收；前者不提供后者结果，缺记录时继续列待核。

## 怎么确认配好了

验收并列保留订单对应、陈述原文、仓库依据和未回复状态，补同次供应商说明后复测，核新增资料是否进入解释。交互节点等待和继续并不代替业务审批。若需向供应商发起请求、调整采购或登记索赔，另接接口或实际流程并核授权与真实结果；本次资料流程完成不证明责任已确认、退款已处理或供应商已接受处置。
