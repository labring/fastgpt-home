# 仅退款争议处理的库存采购与供应商资料：引用来源与溯源

## 这个品类的数据长什么样

在仅退款争议处理的库存采购与供应商资料中，本页说明FastGPT的引用来源与溯源如何衔接资料。退回样件、补发需求与量产备件目录分别追溯。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

仅退款关联采购可自拟退回件登记“样件待检”、补发申请“拟寻找同类替换件”和供应商目录“接口分两种”。问能否用退回样件直接确定采购备件时，登记没有检测结论，申请只是寻找意向，目录也未说明本件属于哪种接口。引用应保留样件、替换需求与可选接口的对象差异，不把同类二字写成适配已确认，也不能从退回件存在推定可回用。

## 配置怎么定

| 采购溯源核对项 | 自拟材料与范围 | 取证动作 |
| --- | --- | --- |
| 样件状态 | 待检 | 不当已验证样本。 |
| 替换需求 | 拟寻找同类件 | 核正式选件依据。 |
| 接口对应 | 两种目录选项 | 核当前主件与接口。 |
| 争议边界 | 采购与责任判断不同 | 不由需求推责任。 |
| 适用范围 | 个体样件与整批不同 | 核对照资料版本。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是待检样件被当成已验证适配样本，应查实际检测及适用结论。第二处是寻找替换件被写成采购已确定，应核正式选件或采购确认。第三处是目录同名件被直接匹配本件，应核接口及对应主件信息。三项分别需要样件状态、决策过程与规格对应，不能让一份退回登记同时承担所有证据，更不从采购需求推出原争议的责任结论。

## 怎么确认配好了

验收分别问退回记录提供哪项、申请表达什么、目录还需哪些对应资料，核答案与实际引用内容一致。对本件选购问题保留接口与检测缺项，不补供应或处理结果。引用数组若仅含目录，应查退回与申请是否真正进入；若没有引用，不等于没有可选供应。补入对照资料后还需核当前主件与版本，不能把某样件的检测扩成整批备件适用或全体退件可回用。
