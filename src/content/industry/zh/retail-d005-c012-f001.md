# 仓内拣货复核打包的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

在仓内拣货复核打包的库存采购与供应商资料中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

仓内采购可从包装耗材需求与实际拣货复核记录之间的关系入手。自拟材料说明波次清单列有待打包商品，耗材申请尚无仓库可用记录，称重设备数据也未提供。拟用HTTP查外部WMS时，先核其真实契约怎样定位耗材和仓库，不将面单中的商品名称直接充作耗材标识。拣货已经安排，只说明有这项记录，不能推断包装物已经备齐。

## 配置怎么定

| 核对对象 | 本题拟议输入 | 验收线索 |
| --- | --- | --- |
| 采购对象 | 耗材申请与待打包商品分开 | 请求没有错用商品身份 |
| 需求数量 | 波次记录及耗材依据 | 未直接用件数推耗材用量 |
| 称重缺口 | 设备记录尚未提供 | 未由空值判断重量异常 |
| 仓库范围 | 实际契约中的对象对应依据 | 发送和返回覆盖本次需求 |
| 业务结果 | 耗材采购或仓内调整请求 | 另外核操作权限与回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |

## 容易做错的三处

若请求把商品件数当成耗材用量，返回说明无法支持本次采购需求。应回查波次原文、耗材申请和传入条件，区分商品对象与包装物对象。另一项失败是称重记录缺失，答复却据此判定包裹重量异常；需查看实际响应有没有相关数据，不能用空值或面单存在代替称重依据，补齐后再核问题是否仍成立。 若复核记录只写核过拣货清单，却被当成包裹已称重，应回查复核对象和本包裹设备来源；清单核对与实际测量是不同依据，不能由记录名称互相补填。

## 怎么确认配好了

验收时逐段保留波次、耗材申请及可用性依据，观察发送条件与返回范围是否对应同一仓内需求。请求头、参数和适用Body分别按契约验证，鉴权不公开。测试模式身份字段缺失不直接判成业务故障。采购耗材、调整仓库记录或提交异常处置需要另核授权与真实回执；查询返回正常不证明已完成打包或库存变更。
