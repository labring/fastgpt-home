# 便利店加盟门店督导的库存采购与供应商资料：向量模型与索引

## 这个品类的数据长什么样

在便利店加盟门店督导的库存采购与供应商资料中，本页说明FastGPT的向量模型与索引如何衔接资料。区分层板整改、门店身份与样板适配，查索引是否扩大了原文。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

加盟门店督导的采购材料可另拟整改通知：“主柜改用窄层板，下期巡店复核。”供应商样板说明写“展示样板，门店适配待确认”。两份文字分别支持整改方向和样板身份。索引可以围绕层板要求、样板适配分别设置搜索文字，但每项都应指回所属原文。督导提出整改不说明供应商已被选定，样板中出现窄层板也不说明它符合该店柜体；这两侧需要各自的资料依据。

## 配置怎么定

| 实施核对项 | 本题材料 | 取证动作 |
| --- | --- | --- |
| 整改要求 | 窄层板及下期复核 | 不扩写为已批准采购。 |
| 样板身份 | 门店适配仍待确认 | 保留限制和供应方原说明。 |
| 门店映射 | 索引可能指向别店记录 | 连同门店身份核返回来源。 |
| 新增依据 | 柜体规格与采购确认分开 | 明确新旧材料各支持哪一问。 |
| 照片检查 | 是否实际读出所需内容 | 不以文件存在代替尺寸核对。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

- 索引写“总部已批准采购”时，回查整改通知是否真的给出批准；窄层板整改要求不能自行变成采购决定。

- 返回别店整改记录时，连同门店身份核索引目标，不能只看层板名称相近。

- 样板的“适配待确认”若在索引或回答中丢失，应将样板原句、索引和实际答复并列，定位限制在哪一环遗漏。

## 怎么确认配好了

后续取得柜体规格或采购确认材料时，应明确哪些是新来源，不改写旧通知使其看似已含这些信息。复测时分别问整改要求、采购批准与柜体适配，记录各题引用的实际材料。若总部资料与门店资料需要共同关联，先核向量模型条件；原数据增加多个索引后，也逐项查指向是否仍属本店。巡店照片若作为来源，核实际图文处理输出，不能由照片文件存在推定层板尺寸已读取。复查结果只界定当前材料覆盖范围，实际安装与巡店复核仍需各自记录。
