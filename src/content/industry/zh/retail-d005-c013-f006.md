# 便利店加盟门店督导的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

在便利店加盟门店督导的库存采购与供应商资料中，本页说明FastGPT的定时任务与自动化如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「定时任务与自动化」这一环带来什么约束

门店督导采购的周期核对可先限定为读取整改所需物料说明，不自动建立采购单。自拟安排只有巡店发现和陈列标准，没有本店物料可用或整改完成依据。先核实际部署的定时入口及触发责任，再明确哪个已配置服务读取门店资料；周期启动不会自动连接督导APP或库存系统，巡店照片也不能直接提供当前物料数量或采购授权。

## 配置怎么定

| 周期核对 | 自拟安排与缺口 | 执行证据 |
| --- | --- | --- |
| 本轮门店 | 本店发现与物料需求 | 未沿用其他门店输入 |
| 服务连接 | 督导库存服务尚需配置 | 触发未当成业务已接通 |
| 读取缺证 | 只有启动时间无结果 | 未核范围仍列明 |
| 重复办理 | 同缺口多次外部登记 | 另核防重与业务回执 |
| 实际采购 | 下单和整改关闭另验 | 输出未代替批准状态 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `触发责任` | 先核可用触发入口及责任组件。 |
| `数据读取` | 外部读取接口需明确配置。 |
| `HTTP请求` | 请求按外部契约构造并核变量。 |
| `重复触发分工` | 去重、幂等及写入须另行实现。 |
| `执行记录` | 核真实触发、输入及业务返回。 |

## 容易做错的三处

若触发输入沿用了其他门店，返回即使完整也无法支持本店需求，应排查门店身份、真实请求与来源。若任务只有启动时间却没有读取结果，要登记未核范围，不从任务存在推定整改需求已整理。相同缺口重复送外部流程时，逐次核业务回执，去重、幂等及实际写入应另在接口或后续步骤设计，不宣称节点自动防重。

## 怎么确认配好了

验收保留本轮门店、整改原句、实际输入和读取返回，补物料依据后再运行同一问题，核结论只覆盖取得资料。HTTP方法、头、适用Body和变量按真实契约查，鉴权不公开。采购下单、整改关闭和督导回写另核授权与业务状态；本轮有输出不证明门店已采购或整改通过，也不从缺资料判定物料不存在。
