# 便利店鲜食订货的库存采购与供应商资料：向量模型与索引

## 这个品类的数据长什么样

在便利店鲜食订货的库存采购与供应商资料中，本页说明FastGPT的向量模型与索引如何衔接资料。区分订货计划、确认记录与展示样品，核每种状态来自哪份材料。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

便利店鲜食订货可采用新拟记录：“饭团订货计划已保存，待总部确认。”另一条临期处理备注写“柜中展示样品待回收，不计可售”。索引若分别服务订货状态和可售范围，应保留计划、确认与展示样品的区别。前一条没有到货记录，后一条没有提供可售数量。用“是否已确认订货”和“展示样品能否计入可售”两问核返回原文，比只搜饭团名称更能发现索引指向是否合适。

## 配置怎么定

| 实施核对项 | 本题材料 | 取证动作 |
| --- | --- | --- |
| 计划状态 | 保存后仍待总部确认 | 检索不得改成已到货。 |
| 可售范围 | 展示样品不计可售 | 限制应随原数据保留。 |
| 记录阶段 | 计划、确认、入库分开 | 各问回到相应原文。 |
| 门店身份 | 同名鲜食可能跨店 | 同时核店别与材料日期。 |
| 材料补充 | 新确认和收货各有来源 | 复测引用变化，不单计索引数。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

- 计划已保存被写成已到货时，核索引指向计划还是入库记录，并把答复中的到货说法追到原句。

- 展示样品被计入可售时，检查“不计可售”是否仍随样品原数据返回，不能把它并入普通销售商品。

- 补入收货资料后若仍取回别店同名商品，核店别、日期和索引目标；另一店的收货不说明本店库存。

## 怎么确认配好了

取得总部确认与实际收货记录后，分别加入对应来源，再用原订货问题检查引用是否换到了正确阶段。索引新增、订单确认和实物入库应分别记载，不能互相代替。若不同门店共用商品名，还要核来源所属门店及日期，避免把另一店的收货当成本店库存。关联订货库与门店记录库前，核实际向量模型；若温度或保质期材料另以图片提供，按真实处理路径检查所读内容，不能由索引命中推定鲜食状态适合销售。本测试不生成食品处置结论或自动提交订货。
