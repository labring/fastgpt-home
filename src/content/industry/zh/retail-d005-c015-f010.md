# 信用证审单交单的库存采购与供应商资料：引用来源与溯源

## 这个品类的数据长什么样

在信用证审单交单的库存采购与供应商资料中，本页说明FastGPT的引用来源与溯源如何衔接资料。受益人称呼、制造商介绍与货物明细需分别回指。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

信用证关联采购资料自拟通知“受益人为贸易方甲”、制造商介绍“工厂乙生产传感器类产品”和清单指向“本批型号另见明细”。问本批由哪家提供哪些规格时，通知只列受益人角色，介绍只列生产类别，明细正文尚缺。引用不能把贸易方写成制造商，也不能由工厂生产传感器就确认本批型号。角色与货物对应仍需实际资料，不由文件名称或检索相关度完成。

## 配置怎么定

| 采购溯源核对项 | 自拟材料与范围 | 取证动作 |
| --- | --- | --- |
| 通知角色 | 贸易方为受益人 | 不改作制造商。 |
| 生产范围 | 传感器类别 | 不补本批型号。 |
| 明细缺项 | 本批型号另见 | 取得实际清单。 |
| 交易关联 | 别笔明细可能混入 | 核单据及版本。 |
| 结论边界 | 来源角色与交易判断不同 | 保留各自证据范围。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是受益人身份被写成实际制造方，应核对应交易中各主体的原文关系。第二处是工厂类别被写成本批具体规格，应取得型号明细并核适用货物。第三处是另一笔交易的清单被当作本批，应查单据关联及版本。三项分别核角色、规格与交易身份，不能把通知和介绍合成未提供的供货链，也不据这些片段判断银行审单或交易合规结果。

## 怎么确认配好了

验收分别问通知列谁、工厂自述什么、本批明细是否已取得，核答案逐项回到来源。实际供货规格问题应保留缺明细与关系待核，不补承诺或履约。若引用只含工厂介绍，需核通知与指向句是否真正传入；有清单链接也要读取正文。补材料后仍需核本笔交易，不把一项主体关系扩成所有业务，空引用同样不能证明相关主体没有参与。
