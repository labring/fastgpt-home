# 即时零售门店履约的库存采购与供应商资料：向量模型与索引

## 这个品类的数据长什么样

在即时零售门店履约的库存采购与供应商资料中，本页说明FastGPT的向量模型与索引如何衔接资料。分别核单次拣货、供应方库存与补货申请阶段。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

即时零售门店的采购查询可先拟缺货报备：“本次拣货未找到指定规格。”采购申请另记“补货草稿已保存，尚未发送”。前者反映本次拣货观察，后者反映申请阶段，两者都没有给出供应方库存或本店实盘结果。用找货、补货是否发出、供应方能否供货三种问法检查索引，分别回到对应材料；不能把门店没找到商品写成供应方无货，也不能把草稿可检索写成采购已经受理。

## 配置怎么定

| 实施核对项 | 本题材料 | 取证动作 |
| --- | --- | --- |
| 观察范围 | 本次拣货未找到规格 | 不扩至供应方整体缺货。 |
| 申请阶段 | 草稿保存且未发送 | 命中不等于已受理。 |
| 副本时点 | 发送前草稿与后续回执 | 核实际目标及引用时间。 |
| 门店对象 | 同名商品可能跨门店 | 复测保留规格和店别。 |
| 新增记录 | 盘点、回执与收货不同 | 各自支持对应状态。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

- 单次拣货未找到被写成整店零库存时，核观察范围及盘点来源；这次找货记录没有给出全店数量。

- 门店观察又被扩为供应方无货时，查答复是否引用了实际供应方资料，不能让一份门店记录承担两个主体的结论。

- 草稿和发送后的收到回执混用时，核目标记录及其时点。收到回执只说明接收，不能直接改写为受理或批准，也不能由索引更新认定业务已发送。

## 怎么确认配好了

收货、盘点或采购记录（按实际含义区分收到、受理与批准）取得后，按其真实含义分别新增来源，再用同一规格与同一门店问题复测。检查新索引是否仍指旧草稿，也核返回材料有没有跨到别店同名商品。关联门店记录与采购库前，核实际向量模型条件；来源含照片时，根据实际文字或图片处理方式核规格标识，不从照片存在推定已读清商品。仍缺供应方确认时如实记录缺口。检索系统可以呈现当前提供的材料，不自行统计实时库存、提交订单或作出即时到货承诺。
