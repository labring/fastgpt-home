# 即时零售门店履约的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

在即时零售门店履约的库存采购与供应商资料中，本页说明FastGPT的定时任务与自动化如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「定时任务与自动化」这一环带来什么约束

即时零售采购资料的周期检查可先核缺货说明、门店库存和待满足需求，不直接执行替换或退款。自拟安排只有缺货上报和拣货文字，没有当前可用库存依据。应先核部署定时入口、触发责任与已配置读取契约，不因订单更新频繁就推定本轮材料已齐；周期启动不会自动连接骑手、平台和门店库存，也不能从配送异常推导采购原因。

## 配置怎么定

| 周期核对 | 自拟安排与缺口 | 执行证据 |
| --- | --- | --- |
| 需求区别 | 缺货拣货与当前库存分开 | 未推断采购原因 |
| 库存时间 | 其他时点结果用于当前 | 核输入与响应范围 |
| 本轮缺口 | 只有启动没有读取结果 | 未写成备货已核 |
| 重复需求 | 多次触发外部登记 | 另核回执幂等与防重 |
| 处置结果 | 采购换品或退款另办 | 读取未代替平台批准 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `触发责任` | 先核可用触发入口及责任组件。 |
| `数据读取` | 外部读取接口需明确配置。 |
| `HTTP请求` | 请求按外部契约构造并核变量。 |
| `重复触发分工` | 去重、幂等及写入须另行实现。 |
| `执行记录` | 核真实触发、输入及业务返回。 |

## 容易做错的三处

若读取的是另一时点库存，返回无法支持当前门店需求，应排查输入时间、门店与实际响应范围。若任务只有启动记录，没有库存结果，需保留缺口，不能用标签写成备货已核。重复触发向业务登记需求时，应逐次看真实回执，去重、幂等与采购写入另设计，不预设系统自动避开重复处理。

## 怎么确认配好了

验收保留订单对象、门店、资料时间、真实输入和返回，补当前库存来源后再运行同一问题，看未知项是否仍清楚列明。HTTP方法、请求头、适用Body及变量依据实际契约核，不公开鉴权。采购下单、换品、退款或异常关闭另验权限及业务状态；周期读取成功不证明商品已备齐、买家已收到或平台已批准处置。
