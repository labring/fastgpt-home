# 即时零售门店履约的库存采购与供应商资料：引用来源与溯源

## 这个品类的数据长什么样

在即时零售门店履约的库存采购与供应商资料中，本页说明FastGPT的引用来源与溯源如何衔接资料。可售展示摘录、门店实盘与采购补正需要各自的时点。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

即时零售采购资料自拟展示摘录“商品可售”、门店实盘“待核货位”和采购说明“品项需补正”。这些只是普通文字样例，不是已读取的系统字段。问能否据展示直接确定本次采购时，可售显示没有说明货位实盘，待核尚无结果，补正也未给最终品项。引用需保留来源与时点，不能把一条展示当作门店全部可用库存，更不能自动补全采购对象。

## 配置怎么定

| 采购溯源核对项 | 自拟材料与范围 | 取证动作 |
| --- | --- | --- |
| 展示身份 | 可售摘录 | 不作实物核查结论。 |
| 货位状态 | 待核 | 查实际盘点。 |
| 修订状态 | 品项需补正 | 核新版及确认。 |
| 当前适用 | 摘录可能属于旧时点 | 核本次需求时点。 |
| 结果边界 | 更新显示不等于到货 | 逐阶段核证据。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是可售展示被写成当前货位已核，应查本店实际盘点记录。第二处是品项补正要求被写成已修改完毕，应核修订版本和确认。第三处是旧展示被用于当前采购，应对照摘录时点与本次需求。三项分别核实物记录、文档状态和时间适用，不能用同一商品名代替，也不从货位待核直接推出商品必定不可售或采购已经失败。

## 怎么确认配好了

验收分别问展示写了什么、实盘尚缺哪项、采购对象是否已补正，检查实际引用能否覆盖。答案可列已见文字和待核状态，不作真实库存或供应结论。若数组只有展示摘录，应检查门店与修订材料是否传入；有来源名仍需读正文。新材料补入后核门店、品项及时间，再决定它支持当前哪一步，不把一次展示更新说成实际到货或采购完成。
