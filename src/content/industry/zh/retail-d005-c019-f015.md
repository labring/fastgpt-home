# 即时零售门店履约的库存采购与供应商资料：知识库检索与召回

## 这个品类的数据长什么样

即时零售门店履约按分钟处理线上订单，与周期性盘库不同。库存采购与供应商资料因此呈现三类特征：一是单据随每单产生，采购申请、供应商送货单、缺货报备、配送异常单在门店与后台之间流转；二是同一供应商在不同门店的供货状态可能不同，资料必须带门店、供应商、商品三个主体；三是单据状态变化快，待审核、已审核、已生效属于不同事实。这些特征直接影响知识库检索：检索词里若缺少门店或供应商主体，召回内容可能来自其他门店的同名商品资料；资料若把报价有效期当作供货期限，检索到的引用会误导后续采购判断。知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库是整个库搜索，集合仅作分类管理，与搜索效果无关。语义检索依赖向量距离，全文检索依赖关键词命中，混合检索通过 RRF 融合两路结果，再经 ReRank 二次排序。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离职责；检索本身不构成授权。引用上限以 tokens 为单位，不是固定条数。问题优化用于指代消除和问题扩展，会增加一次模型调用。

假设演练样本：某商超到家门店的采购资料原文为“供应商甲，配送范围含本门店，商品A报价有效期至2025年6月30日，当前供货状态为正常”。一条待判定拟稿句为“供应商甲对本门店商品A的供货期限至2025年6月30日”。判定要点：同主体、同期间、同字段。原文只载明报价有效期，未载明供货期限，拟稿句把报价有效期改写为供货期限，属于未获支持的改写。若拟稿句写成“供应商甲对本门店商品A的报价有效期至2025年6月30日”，则与原文一致。待审核的采购申请不证明已获批准，签署、合作达成、合同生效是三个不同事实。

## 配置怎么定

配置围绕本页样本，只列官方已说明设置或实施核对项。

| 配置项 | 本页取值或核对动作 | 依据与说明 |
| --- | --- | --- |
| 关联的知识库 | 选择使用相同向量模型的库存采购与供应商资料库 | 节点可关联一个或多个同向量模型知识库 |
| 搜索模式 | 按测试问题比较语义、全文与混合检索 | 不预设一种模式适合全部资料 |
| 引用上限 | 本次假设试验起点设为 2000 tokens，与 1000 和 4000 比较内容完整性 | 该值为假设起点，非官方默认；单位为 token |
| 最低相关度 | 先标注相关与无关样本，再调阈值 | 仅在语义检索或使用结果重排时生效 |
| 问题优化 | 比较原问题与优化后问题，核对主体是否被改错 | 用于指代消除和问题扩展 |
| 结果重排 | 具备重排模型且按设置启用时核对候选排序 | 重排后得分为 0-1，可按得分过滤 |

## 容易做错的三处

1. 把报价有效期当作供货期限。输入为原文“报价有效期至2025年6月30日”和拟稿句“供货期限至2025年6月30日”，比较字段名，拟稿句出现原文未载明的字段，判定为未获支持。
2. 把待审核采购申请当作已批准。输入为状态字段“待审核”和拟稿句“该采购申请已批准”，比较状态取值，两者不一致，判定为未获支持。
3. 把检索命中当作授权。输入为检索返回的供应商资料引用和拟稿句“该供应商已获本门店采购授权”，比较授权字段，资料未载明授权，判定为待核实。

## 怎么确认配好了

1. 针对样本原文与拟稿句，输入原文、拟稿句和判定要求，比较字段名与字段值，拟稿句字段与原文一致且取值一致时满足条件；出现原文未载明字段时为未获支持。
2. 针对待审核状态，输入状态字段“待审核”和拟稿句“已批准”，比较状态取值，两者一致时满足条件；取值不同时判定为未获支持。
3. 针对空结果承接，输入纸面检索结果 `[]`，比较下游节点是否按空数组继续执行，引用内容长度为 0 时链路走通即满足条件。跨不同向量模型的库先核标识并排除不符合者，不执行跨模型检索比较漏召回。
