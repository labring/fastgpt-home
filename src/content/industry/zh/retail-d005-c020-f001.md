# 原产地证书申办的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

原产地证书服务进口国关税和清关，不一定受信用证约束，因此库存采购与供应商资料需要同时支撑原产规则判断和证书填报。主要数据来自中国国际贸易单一窗口、贸促会系统、企业生产记录和客户清关要求。典型文档包括原产地证申请、商业发票、装箱单和生产成本资料，更新频率为每单或批量。HTTP 接口与外部系统这一环，需要把上述材料中的采购来源、供应商信息和货物描述，通过请求参数、请求头、请求体或变量引用传给外部接口，并核对返回值解析是否符合契约。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径请求参数，Body 用于请求体，Headers 用于传递特殊信息。三种数据均可通过 `{{}}` 引用变量，变量来自全局变量、系统变量和前方节点输出。URL 也可引用变量。获取返回值时，通过 JSON path 语法提取接口响应值，输出类型选择字符串时会将对应 key 的值转为 json 字符串。系统变量中 chatId 和 responseChatItemId 在测试模式下不存在，调试时出现的空值属于模式差异，不能当作业务故障。

假设演练样本：某企业有一份供应商资料原文，内容为“供应商甲于 2025 年 3 月提供一批电子元件，采购合同编号 PO-2025-0312，原产国为越南，对应商业发票号 INV-2025-0456”。另有一条待判定拟稿句：“该批电子元件的原产国为越南，可直接用于原产地证书申请。”判定所需材料包括供应商资料原文和拟稿句。拟稿句中的原产国与供应商资料原文一致，但“可直接用于原产地证书申请”这一结论在原文中没有对应授权或已完成的证书申请记录，属于未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址 | 外部接口文档给出的地址，可引用变量 | 对照接口文档确认地址与方法一致 |
| 请求头 | Authorization 使用 Bearer 加凭证变量 | 确认凭证通过安全配置注入，不写入公开样例 |
| 请求体 | 按外部接口契约组织 JSON 结构 | 仅在相应请求类型下使用，核对字段与样本材料对应关系 |
| 变量引用 | 引用前方节点输出中的供应商名称、发票号 | 逐项核对实际传入值是否来自样本材料 |
| 返回值解析 | 按 JSON path 提取所需字段 | 对照接口响应示例确认 key 与输出类型 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 不把调试空值当成业务故障，记录实际观察 |

## 容易做错的三处

1. 把供应商资料原文中的原产国字段直接当作原产地证书申请已获授权的证据。原文只载明原产国为越南，没有载明证书申请状态或授权范围，该结论属于未获支持。
2. 在测试模式下看到 chatId 或 responseChatItemId 为空，就判断外部接口调用失败。文档说明这两个系统变量在测试模式下不存在，空值属于模式差异。
3. 把 HTTP 模块的返回值解析 key 写成业务授权字段。返回值解析只负责从接口响应中提取值，不承担授权判断或业务审批功能。

## 怎么确认配好了

1. 输入样本供应商资料原文和拟稿句，比较拟稿句中的原产国字段与原文是否一致，并检查“可直接用于原产地证书申请”是否有原文支持。若原文只载明原产国，则该结论为未获支持，需记录证据缺口。
2. 输入样本中的采购合同编号 PO-2025-0312 和发票号 INV-2025-0456，比较 HTTP 请求体中引用的变量值是否与样本材料一致。若请求体中变量值来自前方节点输出且与样本一致，则变量引用配置满足核对条件；若变量值为空或与样本不符，则记录为待核实。
3. 输入一条包含 chatId 为空的测试请求，比较响应中 chatId 字段的实际值与测试模式说明。若 chatId 为空且请求在测试模式下执行，则属于文档说明的模式差异；若 chatId 为空且请求在非测试模式下执行，则记录为待核实，不直接判定为接口故障。
