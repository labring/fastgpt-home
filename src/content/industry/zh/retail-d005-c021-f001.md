# 品牌会员私域运营的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

品牌会员私域运营围绕顾客数据与复购触达展开，不处理门店排班。库存采购与供应商资料这一任务里，主要数据来自 CRM 系统、企微、POS 消费记录与小程序行为数据，日常文档包括会员标签表、触达计划、优惠券规则与隐私授权记录。这些资料按日或每周更新，更新节奏本身不改变 HTTP 模块的请求方式，只影响核对时选取的字段范围。

HTTP 模块向对应地址发送请求，Params、Headers、Body 三处均可用 `{{}}` 引用变量，URL 同样可以引用变量。变量来自全局变量、系统变量与前方节点输出。系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories，其中 histories 默认最多取 10 条且无法修改长度。chatId 与 responseChatItemId 在测试模式下不存在，调试时读到空值属于该模式的既定表现，不构成业务故障。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

库存采购与供应商资料涉及供应商主体、采购对象、单据状态与授权范围，这些字段一旦进入外部请求，就需要逐项核对实际传入值。相似度或检索结果不能代替这项核对。检索与相关度不承担权限或实体隔离职责，不能因为某条记录被召回就认为调用方有权读取或写入。

对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId> 的兼容写法。appId 优先级为 body.appId、<apiKey>-<appId>、apikey 关联的 appId（旧版适配）。传入的 model、temperature 等字段无效，由编排决定。detail=true 时可通过 responseData 查看中间值，tokens 需手动计算。chatId 非空时系统从数据库取会话，messages 数组最后一个内容作为用户问题，其余 message 被忽略，chatId 长度需小于 250。

假设演练样本：某品牌会员私域运营团队向供应商资料接口发起核对请求，供核对的材料原文为「供应商主体：华东某包装材料厂；采购对象：中秋礼盒外箱；单据状态：待审核；授权范围：仅限本次询价单」。拟判定句为「该供应商已完成入库授权」。该句涉及的主体、对象、状态与授权范围均需与材料原文逐项比对，待审核状态不构成授权完成的证据。

## 配置怎么定

下表围绕上述样本，列出与本功能、本任务相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 核对说明 |
| --- | --- | --- |
| 请求地址与方法 | 按供应商接口文档给定的地址与方法 | 地址可引用已提供变量，方法以外部契约为准 |
| Params 与 Headers | Authorization 通过安全配置注入 | 逐项核对请求参数与请求头，凭证不写入公开样例 |
| Body | 仅在相应请求类型下使用 | 核对 JSON 结构与外部接口契约，字符串引用需加引号 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 逐项核对实际传入值，不假定变量已填充 |
| 返回值提取 | 按 JSON path 配置 key | 出参格式化将 json 转为字符串输出，key 遵循对象取值规则 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 不把调试空值当成业务故障 |

## 容易做错的三处

1. 把待审核状态写成已完成授权。单据状态「待审核」说明该单据的处理阶段；「入库授权已完成」是另一项授权事实。材料未给出入库授权完成的依据，该表述应标记为未获支持、待核实。
2. 把检索命中当作权限依据。召回某条供应商记录只说明语义相近，不说明调用方具备读取或写入该记录的权限，权限需另由下游实现判定。
3. 把调试模式下的空值当作接口异常。chatId 与 responseChatItemId 在测试模式下不存在，读到空值属于该模式既定表现，需与真实请求区分。

## 怎么确认配好了

1. 输入样本材料原文与拟判定句，分别核对单据审核状态与入库授权依据。现有材料只给出单据待审核及本次询价授权范围，未载明入库授权完成记录，该表述标为未获支持、待核实。
2. 输入样本中的「授权范围：仅限本次询价单」，核对该记录支持的操作范围。该记录仅支持本次询价范围，入库授权须另有对应依据；未提供时保留待核实。
3. 输入一条不含供应商主体、对象、状态与授权范围的请求，比较返回值提取配置是否仍能定位字段。当提取结果为空或无法定位时，记录为未获支持，不推断接口报错原因。

以上核对均为纸面推演，未实际执行测试、部署或审批，相关业务状态以材料原文为准。
