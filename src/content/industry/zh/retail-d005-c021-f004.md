# 品牌会员私域运营的库存采购与供应商资料：向量模型与索引

## 这个品类的数据长什么样

在品牌会员私域运营的库存采购与供应商资料中，本页说明FastGPT的向量模型与索引如何衔接资料。核活动采购计划、样品配色限制与历史礼遇规则的不同范围。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

会员私域中的礼品采购查询，可拟触达计划“本期拟向符合活动条件者提供布袋，款式待采购确认”，配供应方样品说明“展示色不作为交付颜色承诺”。这些文字没有真实会员资料，也没有确定布袋款式和交付配色。索引应分别支持活动拟议物料、样品说明与尚缺的采购确认。问本期礼品采购定了什么时，应保留计划和确认的区别，不能因展示色易于被搜索，就把营销画面写成供货规格。

## 配置怎么定

| 实施核对项 | 本题材料 | 取证动作 |
| --- | --- | --- |
| 计划身份 | 物料拟议且款式待确认 | 不扩写为已采购。 |
| 样品限制 | 展示色不承诺交付色 | 原限制需随引用保留。 |
| 活动范围 | 一般礼遇与本期计划不同 | 核期间及实际索引目标。 |
| 新增确认 | 采购确认单独留存 | 同题分别核款式与颜色。 |
| 人员边界 | 普通场景无真实会员数据 | 不推定个人资格或领取状态。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

- 索引写“已采购蓝色布袋”时，回查计划是否有已采购与蓝色两项依据，保存新增文字及实际答复。

- 历史一般礼遇规则被用于本期活动时，核活动范围、期间和原数据，不能把可选礼品当成本次确定采购。

- 样品说明已取回但展示色限制没进入最终引用时，对照原句与实际引用，防止样品配色又变成交付承诺。

## 怎么确认配好了

拿到本期采购确认后，新增相应来源，分别用礼品款式与交付颜色问题追查引用；样品描述的历史限制仍应保留。共同关联活动资料与礼品规格库时核向量模型条件，逐个检查索引是否仍指向当前活动，不以索引多或得分高认定采购已落实。展示图若实际参与检索，核所采用的文字提取或图片处理结果；没有读到的颜色条件需补材料。技术验收只检查这些问题的来源范围，不执行采购、不分配会员礼品，也不把查询结果当作活动发送或公开发布记录。

| --- | --- |
| 文档类型 | 会员标签表、触达计划、优惠券规则、隐私授权记录 |
