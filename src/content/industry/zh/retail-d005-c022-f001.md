# 品牌全渠道库存调拨的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样
全渠道调拨处理货品在门店与仓之间流动，主要数据来源为 ERP 库存、门店 POS、电商订单与 WMS。日常文档包括调拨申请、库存快照、门店缺货清单与调拨物流单。库存采购与供应商资料这一任务下，需要把采购单、供应商档案与到货记录与上述库存变动对齐。这些文档的更新频率为日或周，本页不涉及批量同步或实时触发机制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向指定地址发送请求，Params 用于路径参数，Body 用于 POST/PUT，Headers 用于传递特殊信息。URL、Params、Headers、Body 均可通过 {{}} 引用全局变量、系统变量或前方节点输出。返回值通过 JSON path 提取，输出类型选择字符串时会把 key 对应的值转成 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在。检索或表单收集的值不构成业务授权，写库、审批与外部同步需要各自的下游实现。

假设演练样本：某品牌供应链专员持有一份标注日期为 2025-03-10 的调拨申请原文，内容为“申请将 A 仓 200 件 SKU-001 调往 B 门店，申请人：李某，状态：待审批”。同时持有一份供应商资料原文，内容为“供应商编码 SUP-018，联系人：王某，供货品类：SKU-001，合同签署日期：2025-01-05”。拟判定句为“该调拨申请已获批，可直接触发向 SUP-018 的采购下单”。比对范围限定为上述两份材料。

## 配置怎么定
下表为本次假设试验起点，非官方默认值，仅用于说明核对方法。

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址 | 引用外部接口文档给出的地址 | 与文档地址逐字符比对，不自行拼接路径 |
| 请求方法 | 按外部接口契约选择 | 与文档声明的方法比对，不凭习惯选取 |
| Headers 鉴权 | 通过安全配置注入凭证 | 与文档要求的鉴权字段比对，样例中不写入明文凭证 |
| Body 结构 | 按外部接口契约构造 JSON | 与文档字段名、类型逐项比对 |
| 变量引用 | 引用前方节点输出或全局变量 | 与样本材料中的字段名比对，确认取值来源 |
| 返回值提取 | 按 JSON path 声明 key | 与响应示例的结构比对，确认路径层级 |

## 容易做错的三处
1. 把“待审批”当作已批准。样本原文状态字段为“待审批”，拟判定句称“已获批”，两者在同一字段上取值互斥，属于明确矛盾。核对输入为样本原文与拟判定句，比较对象为状态字段，观察结果为两处取值是否一致。
2. 把供应商资料中的合同签署日期当作供货期限。样本只载明“合同签署日期：2025-01-05”，未载明供货有效期，拟判定句直接下单缺少供货期限依据。核对输入为供应商资料原文，比较对象为是否载明供货期限字段，观察结果为该字段是否存在。
3. 把检索或表单收集当作授权执行。样本中调拨申请处于待审批状态，向 SUP-018 下单需要审批与采购系统各自的下游实现。核对输入为申请状态与拟执行动作，比较对象为是否存在已批准记录，观察结果为授权证据是否齐备。

## 怎么确认配好了
1. 状态字段核对。输入为样本原文“状态：待审批”与拟判定句“已获批”。比较同一状态字段的取值。观察结果为两者取值一致时通过，取值互斥时判定为矛盾，需回到审批记录核实。
2. 供货期限字段核对。输入为供应商资料原文。比较该资料是否载明供货期限。观察结果为载明时记录具体期限，未载明时记录证据缺口，不补造条款。
3. 请求构造核对。输入为按配置表构造的请求与外部接口文档。比较地址、方法、Headers 字段名与 Body 结构。观察结果为逐项一致时通过，任一项不一致时记录差异位置，不推断接口返回结果。
