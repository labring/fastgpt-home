# 品牌售后维修服务的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样
品牌售后维修围绕保修责任和线下网点运转，与电商平台售后不同，退款之外还要处理备件采购与供应商资料。售后系统、门店订单、维修网点反馈、国家三包目录构成主要来源。保修卡、维修工单、检测报告、换货审批是日常文档，判断保修范围、协调维修备件、审批换退最耗时。这些材料进入 HTTP 接口时，请求体承载的是工单编号、备件名称、供应商与审批状态，返回值用于回填库存或供应商记录。资料按每单和日更新，本页不据此推出批量同步或实时触发。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params 用于路径参数，Body 用于 POST/PUT，Headers 传递特殊信息。三种数据均可通过 {{}} 引用全局变量、系统变量、前方节点输出，URL 同样可以。系统变量含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取不到值不构成业务故障。返回值通过 JSON path 提取，输出类型选字符串时会把对应 key 的值转为 json 字符串。调用 chat/completions 时推荐在请求体传 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>；传入的 model、temperature 由编排决定。这些机制只负责传输与解析，不承担授权判断。

假设演练样本：某品牌售后中心拟通过 HTTP 模块向外部库存系统提交一条备件采购交接请求。供核对的材料原文为：“维修工单 WX-2024-0517，品牌售后中心，更换件为某型号电池，数量 2 件，供应商资料页标注‘报价有效期至 2024 年 6 月 30 日’，换货审批栏为‘待审核’。”待判定的拟稿句为：“该采购请求已获审批，可按报价直接下单。”该句把待审核状态写成已获审批，并把报价有效期当成供货期限，两处均超出原文。

## 配置怎么定
下表只列与本页样本相关的官方已说明设置或实施核对项。数值为本次假设试验起点，需说明选取理由并与对应值比较，不构成默认值。

| 配置项 | 本次假设起点 | 核对方式与理由 |
| --- | --- | --- |
| 请求地址与方法 | 外部库存系统提供的下单接口，方法按该接口文档选择 | 地址可引用变量，方法以接口文档为准，不预设 |
| Headers 鉴权 | Authorization 通过安全配置注入 | 核对凭证未写入公开样例，代理身份需具备目标权限 |
| Body 结构 | 含工单号、备件、数量、供应商字段 | 按外部接口契约逐项核对 JSON 结构与实际传入值 |
| 变量引用 | 工单号与数量来自前方节点输出 | 逐项核对实际传入值，确认与工单一致 |
| 返回值提取 | 按 JSON path 提取状态字段 | 输出类型选字符串时转为 json 字符串，供下游文本加工 |
| 授权边界 | 审批状态仅作展示字段回填 | 表单收集值不等于审批执行，写入与同步需下游实现 |

## 容易做错的三处
1. 把材料中“换货审批栏为待审核”当作已获审批，据此发起下单。输入是原文审批栏，比较对象是“待审核”与“已获审批”，二者为同字段互斥取值，写成已审批即与原文矛盾。
2. 把“报价有效期至 2024 年 6 月 30 日”当成供货期限或下单依据。输入是报价有效期字段，比较对象是有效期与供货期限，原文未载明供货期限，只能记为未获支持。
3. 把 HTTP 模块返回的相似度或节点状态当作权限或实体隔离依据。输入是返回值中的 score 或状态字段，比较对象是业务授权结论，检索与相似度不承担授权判断，授权需另接系统实现。

## 怎么确认配好了
1. 输入上文假设原文与拟稿句“该采购请求已获审批，可按报价直接下单”。比较拟稿句是否与原文审批栏、报价有效期字段一致。可观察结果是：拟稿句与原文矛盾，判定为不通过；若改为“审批状态为待审核，报价有效期至 2024 年 6 月 30 日”，与原文一致，判定为通过。
2. 输入一条 Body 声明，其中工单号与数量引用前方节点输出。比较实际传入值与工单 WX-2024-0517、数量 2 是否一致。可观察结果是：传入值一致则通过；若数量被写成固定值或引用错误变量，则记录差异，不推断下游写入结果。
3. 输入返回值提取配置与一段接口响应示例。比较提取 key 与响应结构是否对应。可观察结果是：key 命中则得到对应值；若 key 不存在，该项为空，记录缺口，不声称系统必然报错或自动补写。
