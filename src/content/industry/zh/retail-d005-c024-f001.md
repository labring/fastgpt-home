# 品牌商场专柜运营的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

在品牌商场专柜运营的库存采购与供应商资料中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。专柜采购接口区分展示样品、可订商品与供应确认，不由目录返回推库存或采购结果。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

自拟供应目录将一款标为展示样品，另一款的供货期仍待回复，历史采购单属于其他专柜。接口按真实契约携带专柜及商品身份，核Params、Headers与Body的职责，不能自行发明字段名。目录能被读取不证明商品可采购，鉴权凭证也不提供品牌或商场采购授权。

## 配置怎么定

| 专柜采购HTTP | 目录问题 | 核对依据 |
| --- | --- | --- |
| 展示样品 | 用途受限 | 非可售库存 |
| 供货期 | 仍待回复 | 保留未决 |
| 历史采购单 | 其他专柜 | 核身份对应 |
| 请求字段 | 依真实契约 | 不编字段名 |
| 采购写回 | 独立业务接口 | 权限与回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

展示样品被答可售库存时，核目录用途及实际库存来源；未回复的供货期被写确定时，对供应原句；其他专柜采购单被套本柜时，对专柜和商品。三处分别看用途、确定程度与业务对象，纸面材料不含真实采购金额或成交结果。

## 怎么确认配好了

验收查请求真实输入与响应是否包含所问组件，只有摘要时保留正文待补。新增供应回复要核对应商品再重测，不用旧单填空。采购审批、下单及库存写回需要独立接口和权限，查询成功只支持返回材料范围内的资料核对。 展示样品标记与采购可用说明分栏保留，柜别对应材料缺席时继续列待补。

| 文档类型 | 联营扣点合同、商场活动函、销售小票、月结对账单 |
| 候选来源 | 商场POS、品牌ERP、商场会员活动、财务系统 |
