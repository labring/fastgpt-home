# 品牌直营门店运营的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

直营门店由品牌直接雇佣和核算，不通过加盟合同管理，这一差别直接影响库存采购与供应商资料的交接方式。日常文档以日销售报表、排班表、陈列照片、库存调拨单为主，数据来源覆盖 POS、会员 CRM、ERP 库存与门店巡检，更新频率为日或周。库存采购与供应商资料这一任务，需要把调拨申请、供应商资料变更等请求送到外部系统，HTTP 模块承担的是请求发送与返回值提取。日更或周更只说明资料节奏，不推出批量同步、全量同步、实时或交易触发机制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 多用于 GET，Body 多用于 POST/PUT，Headers 用于传递特殊信息。URL、Body、Headers 中均可用 `{{}}` 引用变量，变量来自全局变量、系统变量与前方节点输出。节点输出按JSON path从接口响应中提取，输出类型选择字符串时会把对应 key 的值转成 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试时的空值不构成业务故障。检索或表单只收集与传递值，业务验证、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：某品牌直营门店店长提交一份库存调拨单，材料原文为「调拨单号 DB-2025-0417-03，调出店为直营 A 店，调入店为直营 B 店，商品为某款夏季短袖，数量 24 件，申请日期 2025 年 4 月 17 日，状态为门店已提交，区域经理审批栏为空」。拟交接请求为「请通过 HTTP 接口把该调拨单推送到 ERP 库存系统，并同步更新供应商资料中的供货联系人」。该请求中，门店已提交只表示提交动作完成，审批栏为空，当前材料未给批准记录，审批结果待核；推送与同步属于需另接系统实现的业务动作。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址 | 引用外部接口文档给出的地址变量 | 与外部接口契约中的地址逐字符比较 |
| 请求方法 | 演练候选POST，实际方法待核 | 按真实ERP接口契约确认，不以节点或动词名称代替契约 |
| Headers 鉴权 | 通过安全配置注入凭证，不写入公开样例 | 与外部接口文档要求的鉴权字段名比较 |
| Body 结构 | 按外部接口契约声明调拨单字段 | 与契约中的字段名、类型逐项比较 |
| 返回值提取 | 按 JSON path 提取所需 key | 与接口响应示例中的层级比较 |
| 输出类型 | 字符串，用于后续文本拼接 | 与下游节点可接收的类型比较 |

以上均为本次假设试验起点，不是官方默认值。

## 容易做错的三处

1. 把门店已提交当成审批通过。提交动作与审批结果是不同字段；原文给已提交及空审批栏，没有批准记录，批准主张待核，不能反推审批未发生。
2. 把表单收集的调拨数量当成已写入 ERP。表单只收集值，数据库写入与外部同步需要各自的下游实现。
3. 在测试模式下把 chatId 或 responseChatItemId 的空值当成接口故障。文档说明这两个字段在测试模式下不存在。

## 怎么确认配好了

1. 输入调拨单与拟请求，待取得ERP契约后逐项核地址、方法、字段类型及授权。请求可否发送和审批结果分别核；当前无契约与批准记录，不由推送主张推定审批已变更或不会变更。
2. 输入样本原文，比较拟交接请求中的「同步更新供应商资料中的供货联系人」是否有对应的下游实现说明，只有存在明确实现说明才满足条件；否则记录为证据缺口。
3. 输入测试模式下的请求，比较 chatId 与 responseChatItemId 是否为空，只有确认这是文档所述测试模式行为才满足条件；不据此判定业务故障。
