# 品牌经销商订货会的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

品牌经销商订货会按季、按年推进，围绕订货手册、订货合同、样品清单、授信审批四类文档形成库存采购与供应商资料。订货会系统、历史销售、经销商库存、财务授信构成主要数据来源，渠道部、区域经销商与商品企划共同参与。库存采购与供应商资料常需要与外部系统交换数据，HTTP 模块承担向指定地址发送请求并解析响应的职责。数据更新频率为季、年，本页不据此推导批量同步、全量同步或实时触发机制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块可重复添加、手动配置、触发执行，向对应地址发送 HTTP 请求。Params 为路径请求参数，GET 请求中用的居多；Body 为请求体，POST/PUT 请求中用的居多；Headers 为请求头，用于传递特殊信息。三类数据均可通过 {{}} 引用变量，URL 也可引用变量。变量来自全局变量、系统变量、前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在，histories 默认最多取 10 条且无法修改长度。

返回值用于解析接口响应，通过 JSON path 语法提取。出参格式化在 v4.6.8 后加入，输出类型选择字符串时会把对应 key 的值转成 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>。appId 优先级为 body.appId、<apiKey>-<appId>、apikey 关联的 appId。传入的 model、temperature 等参数字段无效。authProxy 代理团队成员身份需要团队所有者开启，代理身份仍需具备目标应用和会话权限。交互节点返回的 interactive 只含 type 和 params，entryNodeIds、memoryEdges、nodeOutputs、nodeResponseId 等内部运行态字段不会返回。表单输入需要把对象序列化成字符串作为 messages 值，并保持 chatId 一致。这些是节点已有行为与可配置字段，业务审批、数据库写入与外部同步需要另行实现的业务动作。

## 配置怎么定

假设演练样本：材料原文为“华东区域 2024 年秋季订货会样品清单（编号 YP-2024Q3-018）登记样品 12 件，对应订货手册版本 H2，授信审批单尚未签署”。待判定拟稿句为“该经销商已完成授信审批，可提交订货合同”。下表围绕该样本列出与本功能相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址可用 {{}} 引用变量 | 与外部接口契约的路径和方法逐项比较 |
| Params 与 Headers | 分别填写请求参数与请求头，鉴权凭证通过安全配置注入 | 与外部接口文档声明的字段名和取值比较 |
| Body | 仅在相应请求类型下使用，核对 JSON 结构与外部契约 | 与外部接口契约的字段类型比较 |
| 变量引用 | 逐项核对全局变量、系统变量、前方节点输出 | 与实际传入值比较，确认引用来源存在 |
| 返回值解析 | 按 JSON path 语法配置 key | 与接口响应示例的结构比较 |
| 调试身份字段 | 测试模式下 chatId 与 responseChatItemId 不存在 | 与业务运行时的实际取值比较，不把调试空值当业务故障 |

## 容易做错的三处

1. 把检索或表单当成授权执行。样本中授信审批单尚未签署，拟稿句写成“已完成授信审批”，把未签署状态当作已生效。表单收集值不产生审批结果。
2. 把交互节点返回的展示配置当成完整运行态。interactive 只含 type 和 params，若按 entryNodeIds、memoryEdges 等字段做业务判断，输入缺失。
3. 把相似度或检索结果当作权限或实体隔离依据。score 是相关度数值，不能据此判定经销商是否具备订货或授信权限。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较“授信审批单尚未签署”与“已完成授信审批”是否同主体、同期、同字段。两者取值互斥，拟稿句未获支持，保留证据缺口。
2. 输入一条带交互节点的请求，设置 detail=true，比较返回的 interactive 是否只含 type 和 params。未出现 entryNodeIds 等内部字段才满足预期，出现时记录实际观察。
3. 输入样本中 chatId 为空、responseChatItemId 为空的测试模式请求，比较系统变量取值。两者不存在属于文档说明的测试模式行为，不判定为业务故障。
