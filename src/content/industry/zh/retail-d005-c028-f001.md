# 品牌自播直播间运营的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样
品牌自播由品牌自身承担话术、库存与售后，库存采购与供应商资料直接决定讲解卡能否写清可售数量与交付口径。这类资料每场、每小时都在变，直播脚本、商品讲解卡、排班表与直播复盘之间经常需要人工对齐。数据来源包括抖店罗盘、巨量千川、直播间评论与成交明细，HTTP 接口与外部系统这一环的任务是把采购单、供应商回执与库存快照接入工作流，供场控和投流专员在开播前核对。库存拍超与虚假宣传投诉是主要后果，因此接口调用只完成数据搬运，授权与业务确认仍需人工或下游系统完成。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params、Body、Headers 三类数据均可通过 `{{}}` 引用变量，变量来自全局变量、系统变量与前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在，调试时的空值不能当成业务故障。返回值通过 JSON path 提取，输出类型选字符串时会把对应 key 的值转成 json 字符串。对话接口使用 APIKey 鉴权，推荐在请求体传入 `body.appId`，也支持 `Authorization: Bearer <apiKey>-<appId>`；传入的 model、temperature 等字段无效，由编排决定。authProxy 代理团队成员身份需要团队所有者开启，代理身份仍需具备目标应用和会话权限。检索与相似度只影响召回排序，不能承担权限或实体隔离。

假设演练样本：供核对的材料原文为“供应商甲于 2025 年 3 月 10 日确认春季款 A 可供货 800 件，报价有效期至 2025 年 3 月 31 日；采购方尚未签署采购合同。”待判定的交接请求为“在直播脚本中写入春季款 A 可售 800 件并已锁定供货。”该请求把报价有效期与供货承诺混同，签署、合作达成、合同生效是三个不同事实，材料未载明合同生效，因此“已锁定供货”未获支持。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 核对方式与理由 |
| --- | --- | --- |
| 请求地址 BaseUrl | 供应商回执查询接口地址 | 按外部接口文档选择，出现 404 时补充 v1 重试 |
| 请求方法 | POST | 与外部接口契约一致，Body 仅在该类型下生效 |
| Headers 鉴权 | Authorization 引用 token 变量 | 凭证通过安全配置注入，不写入公开样例 |
| Body 字段 | 引用采购单号与日期变量 | 逐项核对 JSON 结构与实际传入值 |
| 返回值提取 | 按 JSON path 提取回执状态 | 输出类型选字符串时转为 json 字符串 |
| 授权边界 | 记录待审核状态 | 待审核不构成审批，不触发下游写入 |

## 容易做错的三处
1. 把报价有效期当作供货期限。材料写明报价有效期至 2025 年 3 月 31 日，未载明供货期限，若在讲解卡写“长期可供货”，属于超出原文的推断。
2. 把待审核请求当成已批准。采购单处于待审核状态时，接口调用只完成查询，业务审批与数据库写入需要下游实现，不能由 HTTP 模块自行完成。
3. 把检索相似度当成权限过滤。相似度只影响召回排序，不能排除无关供应商或未授权记录，跨不同向量模型的库不可共同关联，只能先核标识并排除不符合者。

## 怎么确认配好了
1. 输入假设样本原文与拟稿句“春季款 A 可售 800 件并已锁定供货”，比较“已锁定供货”与原文“尚未签署采购合同”，观察结果是该拟稿句未获支持，需改写为待核实状态。
2. 输入 chatId 为空、responseChatItemId 为空的测试模式请求，比较系统变量说明中两者在测试模式下不存在，观察结果是请求仍可执行，不把空值记录为业务故障。
3. 输入一份明确纸面输入的空结果 `[]`，比较下游节点对空列表的处理设计，观察结果是下游按空结果分支处理，不声称某条虚构规则检索一定返回空列表。
