# 售后维修与补寄的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

在售后维修与补寄的库存采购与供应商资料中，本页说明FastGPT的定时任务与自动化如何衔接资料。维修配件采购复查要区分客户申请、检查发现和真实领用，出库记录不自动产生新的采购需求。所用场景为自拟文字测试。

## 这些特征在「定时任务与自动化」这一环带来什么约束

自拟备料说明引用客户维修申请，检查仍待复测，配件清单列候选件，已有出库记录未说明装到哪件商品。定期复查应核诊断和领用关系有没有补齐，不从申请直接决定要买什么。先核实际可用触发与读取范围，再看本轮得到哪些原文；同型号配件不证明适用本件，已领出也不证明已安装或库存必须补足。

## 配置怎么定

| 维修采购复查 | 自拟材料状态 | 核对依据 |
| --- | --- | --- |
| 维修申请 | 客户描述 | 非已定配件需求 |
| 检查情况 | 待复测 | 补实际诊断 |
| 配件候选 | 尚未批准 | 取采购决定 |
| 出库记录 | 未说明安装对象 | 核真实领用 |
| 后续执行 | 采购维修回写另接 | 复查非修复保证 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `触发责任` | 先核可用触发入口及责任组件。 |
| `数据读取` | 外部读取接口需明确配置。 |
| `HTTP请求` | 请求按外部契约构造并核变量。 |
| `重复触发分工` | 去重、幂等及写入须另行实现。 |
| `执行记录` | 核真实触发、输入及业务返回。 |

## 容易做错的三处

申请冒需求：若客户描述直接形成采购清单，应取真实检查依据；领出冒装入：若出库被当实际使用，应核作业对应；候选冒批准：若备选配件写成已采购，应取实际决定。三项分别核需求基础、使用阶段和采购状态，不由计划任务完成。

## 怎么确认配好了

验收保留输入、读取结果和待复测项，补诊断后复跑，只改获支持的配件关系。实际库存或安装仍缺时不推定补货，旧轮清单不能代新依据。采购、领用、维修与库存回写需另接权限及回执，重复触发按真实实现检查；本次复查不证明维修完成，也不提供配件适配或修复效果保证。
