# 商超供应商进场结算的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

在商超供应商进场结算的库存采购与供应商资料中，本页说明FastGPT的定时任务与自动化如何衔接资料。商超供应商备货复查要分别核合同需求、送货验收和本期确认，不从结算资料推出下一批采购已经获准。所用场景为自拟文字测试。

## 这些特征在「定时任务与自动化」这一环带来什么约束

自拟采购安排列拟补商品，合同摘录限定范围，送货验收来自上一批，对账仍待确认。定期检查可以核本批需求和对应材料是否到齐，不把旧验收用于新采购。先核实际部署可用触发，再看本次读取的期间与供应商；返利协议不能补商品需求，待签对账也不能证明本次采购或资金已经处理。

## 配置怎么定

| 供应商备货复查 | 自拟来源阶段 | 本批所需 |
| --- | --- | --- |
| 拟补商品 | 需求待确认 | 取真实决定 |
| 合同范围 | 限定商品 | 不扩返利说明 |
| 送货验收 | 上一批 | 不能支持新货 |
| 对账状态 | 仍待签 | 非结清 |
| 定期结果 | 按本批更新 | 执行另取回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `触发责任` | 先核可用触发入口及责任组件。 |
| `数据读取` | 外部读取接口需明确配置。 |
| `HTTP请求` | 请求按外部契约构造并核变量。 |
| `重复触发分工` | 去重、幂等及写入须另行实现。 |
| `执行记录` | 核真实触发、输入及业务返回。 |

## 容易做错的三处

旧批冒本批：若先前验收支持新货，应核批次对应；协议冒需求：若返利适用被当采购确认，应查真实业务决定；待签冒结清：若草稿写成已处理，应取本期实际结果。三项分别查来源、需求和执行，不能由定期读取补出。

## 怎么确认配好了

验收保留触发和实际输入，补本批确认后复跑，只更新所指商品。验收和结算仍缺时继续列待核，文件更新不代表它们已经完成。若回复只说已收到计划，仍不是采购确认。实际采购、验收及账务回写需另接权限与回执，重复触发和写入按真实实现核；任务检查完成不证明货物供应、结算或供应商履约已经结束。
