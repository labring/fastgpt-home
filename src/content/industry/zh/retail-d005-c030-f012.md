# 商超供应商进场结算的库存采购与供应商资料：文档解析与分块

## 这个品类的数据长什么样

供应商进场结算以购销或代销账款为主，未必有驻场经营。采购合同约定结算口径，送货验收单记录实收数量，返利协议约定扣点条件，对账单汇总期间往来。四类材料来自 ERP 采购、供应商门户、POS 销售与财务系统，按周或按月更新。文档解析与分块要处理的是这些材料的结构差异：合同条款、验收明细、返利档次、对账汇总的字段与粒度并不一致，分块需要保留条款与所约束内容之间的对应关系。

## 这些特征在「文档解析与分块」这一环带来什么约束

解析先核对原文结构和解析结果，保留能回指原文的文档身份与版本。分段按具体资料结构检查，条件、说明与所约束的内容不宜拆离。原数据与检索索引需要区分，同一组原数据可对应多个索引。检索时用术语、编号和自然语言分别测试，观察分段对实际问题的表现。资料变更后核对实际训练与索引状态，上传成功不等同于检索已更新。

假设演练样本：材料原文为「甲方为某某商超，乙方为某某食品供应商；结算周期为自然月，验收数量以收货部签字确认的送货验收单为准；返利按季度销售额的百分之二计提，退货金额从当期销售额中扣减。」待判定拟稿句为「本季度返利按验收数量计提，退货不冲减基数。」该拟稿句与原文在计提基数、退货处理两处不一致，属于未获支持。

## 配置怎么定

| 配置或核对项 | 本页相关设置 | 与样本的关系 |
| --- | --- | --- |
| 分段依据 | 按合同条款、验收明细、返利档次、对账汇总分别成段 | 保证返利条件与退货说明同段 |
| 索引数量 | 同一组原数据可增加多组索引 | 为术语、编号、自然语言各建索引 |
| 检索模式 | 语义检索、全文检索、混合检索按需选择 | 编号类查询走全文检索或混合检索 |
| 引用上限 | 每次搜索最多引用 n 个 tokens | 本次假设试验起点设为 3000，因样本条款较短，与 2000 比较观察召回完整性 |
| 最低相关度 | 0 至 1 的过滤阈值，仅在语义检索或结果重排时生效 | 本次假设试验起点设为 0.3，与 0.5 比较观察无关片段 |
| 更新后复核 | 资料变更后核对训练与索引状态 | 合同修订后确认检索结果已更新 |

## 容易做错的三处

1. 把返利计提基数写成验收数量。原文明确基数为销售额，退货金额从当期销售额中扣减。检查时输入拟稿句与原文，比较计提基数与退货处理两处，拟稿句与原文一致才满足条件。
2. 把上传成功当作检索已更新。检查时输入修订后的合同文本，比较检索返回内容与修订后条款，返回内容包含修订后条款才满足条件。
3. 把检索结果当作授权执行。检索返回对账单不等于结算已批准。检查时输入一条待审批的结算请求，比较检索结果与审批记录，存在独立审批记录才满足条件。

## 怎么确认配好了

- 验证一：输入假设样本原文与拟稿句，比较计提基数与退货处理，拟稿句与原文一致才满足条件，当前结果为未获支持。

- 验证二：输入样本中的编号类查询，比较全文检索与语义检索的返回内容，返回内容包含对应条款才满足条件，空结果按纸面输入 [] 核对下游设计。

- 验证三：输入修订后的合同文本，比较检索返回内容与修订后条款，返回内容包含修订后条款才满足条件。跨不同向量模型的库先核标识并排除不符合者，不执行跨模型检索来比较漏召回。
