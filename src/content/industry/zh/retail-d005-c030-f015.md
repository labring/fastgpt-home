# 商超供应商进场结算的库存采购与供应商资料：知识库检索与召回

## 这个品类的数据长什么样
本页只处理商超供应商进场结算中库存采购与供应商资料的知识库检索与召回。该品类多按购销或代销账款结算，不一定有驻场经营，检索对象集中在采购合同、送货验收单、返利协议、对账单。资料按周、按月更新，检索时须区分同一供应商、同一期间、同一字段的取值。资料更新频率只影响资料版本新旧，本页不据此推出批量同步或实时触发。检索结果只作为引用内容，不构成授权、审批或账款确认。

## 这些特征在「知识库检索与召回」这一环带来什么约束
检索以库为最小搜索单位，集合只作分类管理。知识库搜索节点可关联一个或多个使用相同向量模型的知识库；向量模型标识不一致的库不能共同关联，须先核对标识并排除不符合者，不执行跨模型检索来比较漏召回。全文检索在向量库为 Milvus（≥ 2.5.16）时使用 BM25，其他向量库走 MongoDB `$text` 加 jieba 分词。语义检索、全文检索、混合检索、结果重排、图片检索属于可选路径，须有对应输入与模型能力才发生。引用上限以 token 为单位，长度可为 0，输出链路仍走通。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离。RRF 是混合结果融合过程，不作为开关。问题优化用于指代消除和问题扩展，会增加一次模型调用。

假设演练样本：某供应商门户导出的《送货验收单》摘要写“供应商：华岳日配；收货门店：城北店；送货日期：2025年3月10日；验收数量：120箱；验收状态：已验收”。同批《对账单》摘要写“供应商：华岳日配；结算期间：2025年3月；验收数量：120箱；对账状态：待供应商确认”。拟核对句：“华岳日配城北店2025年3月送货验收数量为120箱，对账已完成。”该句把待确认写成已完成，属未获支持。

## 配置怎么定
下表只列与本页样本相关的官方已说明设置或实施核对项。需要数值处标为本次假设试验起点，并给出选取理由与比较对象。

| 配置项 | 本次假设取值 | 核对方式与依据 |
| --- | --- | --- |
| 关联知识库 | 供应商资料库、结算资料库 | 两库向量模型标识须一致，不一致则排除，不共同关联 |
| 搜索模式 | 混合检索 | 样本含“华岳日配”“120箱”等词，同时比较语义召回与全文召回 |
| 引用上限 | 假设起点 2000 tokens | 仅为本次试验起点，与对账单、验收单长短差异比较后调整 |
| 最低相关度 | 假设起点 0.5 | 仅为本次试验起点，先标注相关与无关样本，再比较过滤效果 |
| 问题优化 | 开启 | 多轮追问“那批货呢”时比较原问题与优化后问题主体是否被改错 |
| 结果重排 | 按设置启用 | 候选较多时比较重排得分 0-1 与向量得分，确认排序变化 |

## 容易做错的三处
1. 把“对账状态：待供应商确认”读成对账已完成。输入为上述对账单摘要，比较字段“对账状态”取值，观察拟核对句是否把待确认写成已完成；该句未获支持。
2. 把不同向量模型的知识库直接共同关联。输入为两库模型标识，比较标识是否一致，观察是否存在跨模型关联；标识不一致时排除，不推断漏召回或冗余结果。
3. 把引用上限当作 top k 使用。输入为长短差异明显的验收单与对账单，比较返回内容是否被截断，观察引用上限以 token 计；出现截断时调整该值，不改成固定条数。

## 怎么确认配好了
1. 输入上述送货验收单摘要与对账单摘要，比较同一供应商、同一期间、同一字段“验收数量”的取值，观察两处均为120箱；拟核对句中的“对账已完成”与“待供应商确认”不一致，判定为未获支持。
2. 输入上述两库模型标识，比较标识是否一致，观察是否允许共同关联；若不一致，记录缺口并排除，不执行跨模型检索来比较漏召回。
3. 输入一条纸面空结果 []，比较下游设计是否承接长度为 0 的引用；观察输出链路是否走通，不声称虚构规则检索一定返回 []。
