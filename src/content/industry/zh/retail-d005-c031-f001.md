# 商超塑料袋与一次性用品报告的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

该品类围绕一次性塑料制品报告与环保监管展开，数据来源包括商务部报告系统、POS 塑料袋销售记录、采购系统与门店台账。从业主体涉及商超门店、总部合规与行政采购。出错后果为限期整改、一万至十万元罚款及监管约谈。本页只处理库存采购与供应商资料环节中，通过 HTTP 模块对接外部系统的实施条件与核对步骤。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径参数，Body 用于请求体，Headers 用于请求头。三类数据均可通过 `{{}}` 引用变量，变量来源为全局变量、系统变量与前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories。chatId 与 responseChatItemId 在测试模式下不存在，调试空值不构成业务故障。返回值通过 JSON path 语法提取，输出类型选择字符串时会将对应值转为 JSON 字符串。对话接口使用 APIKey 鉴权，推荐在请求体传入 body.appId，也支持 Authorization: Bearer 形式。传入的 model、temperature 等字段无效，由编排决定。detail=true 时返回中间值，stream 模式下通过 event 区分。

假设演练样本：某商超总部合规岗拟通过 HTTP 模块向外部供应商资料系统提交一条采购台账更新请求。供核对的材料原文为：「供应商甲于本年度上半年向本商超供应厚度 0.025 毫米塑料袋，采购台账登记数量为 12000 个，登记状态为已入库。」拟提交的请求 Body 声明为 `{"supplier":"甲","quantity":12000,"status":"已入库"}`。该请求的授权状态未在材料中载明，需另行核实。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址 | 外部供应商资料系统提供的接口地址 | 按外部接口文档选择，与文档中的方法声明比较 |
| 请求方法 | POST | 与外部接口契约要求的写入方法比较 |
| Headers 鉴权 | Authorization 引用已配置的 token 变量 | 与对话接口的 Bearer 鉴权规范比较 |
| Body 字段 | supplier、quantity、status | 与材料原文的供应商、数量、状态逐项比较 |
| 返回值提取 | 配置 key 对应响应中的状态字段 | 与接口响应示例的 JSON path 提取规则比较 |
| 输出类型 | 字符串 | 与自动格式化输出的字符串转换规则比较 |

以上数值为本次假设试验起点，非官方默认值。请求地址与鉴权凭证需通过安全配置注入，不写入公开样例。

## 容易做错的三处

1. 将 Body 中 quantity 直接写为 `{{quantity}}` 而未核对变量来源。若前方节点输出中不存在该变量，请求体将传入空值或原始占位符。应核对变量是否来自全局变量、系统变量或前方节点输出，并确认实际传入值与材料原文的 12000 一致。
2. 将测试模式下 chatId 为空视为接口故障。文档明确 chatId 与 responseChatItemId 在测试模式下不存在，应区分调试空值与业务数据缺失，不据此判定外部系统异常。
3. 将 HTTP 模块的返回值提取结果直接当作供应商资料已更新的证据。返回值仅代表接口响应的解析结果，业务写入与外部同步需由下游实现完成。应核对响应内容与材料原文的登记状态是否一致，并记录授权边界是否明确。

## 怎么确认配好了

1. 输入假设样本中的材料原文与拟提交 Body，比较 Body 中 supplier、quantity、status 三个字段与原文的供应商甲、12000 个、已入库是否逐项对应。若任一字段不一致或变量未解析，则不满足条件。
2. 输入拟提交请求，比较请求头中的 Authorization 是否引用了已配置的 token 变量，并核对请求地址与方法是否与外部接口文档声明一致。若鉴权凭证缺失或方法不匹配，则不满足条件。
3. 输入接口响应示例，比较配置的返回值 key 是否按 JSON path 语法正确提取目标字段，并核对输出类型选择字符串时是否转为 JSON 字符串。若提取路径与响应结构不符，则不满足条件。授权状态与业务写入结果在材料中未载明，保持待核实。
