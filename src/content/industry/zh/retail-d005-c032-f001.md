# 商超收银与会员促销的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

商超收银与会员促销的库存采购与供应商资料，围绕促销价签、会员积分规则、收银日报、异常退款单展开。价格与会员权益是主线，短保库存不进入本页处理范围。数据来源包括 POS 系统、会员 CRM、支付平台与价签系统，更新频率为日或每班。HTTP 接口与外部系统这一环，需要把上述文档中的字段通过请求发送到外部服务，并解析返回值。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 用于路径请求参数，Body 用于请求体，Headers 用于请求头。三种数据均可通过 `{{}}` 引用变量，变量来自全局变量、系统变量、前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories；histories 默认最多取 10 条，无法修改长度。返回值通过 JSON path 提取，输出类型选择字符串时会转为 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId；appId 优先级为 body.appId、`<apiKey>-<appId>`、apikey 关联的 appId。传入的 model、temperature 等字段无效。detail=true 时返回中间值，stream 模式通过 event 区分。交互节点返回的 interactive 只含 type 和 params。

假设演练样本：某门店收银主管于 2025 年 6 月 10 日班次，需要把促销价签文档中的商品条码与促销价，通过 HTTP 接口提交至外部价签系统。供核对的材料原文为：“促销价签文档编号 QJ-20250610-03；商品条码 6901234567890；促销价 9.9 元；生效日期 2025 年 6 月 10 日至 6 月 12 日；审批状态：待审核。”待判定的交接请求为：“请将该促销价签通过 HTTP 接口提交至外部价签系统并生效。”此处审批状态为待审核，提交动作的授权边界尚未满足。

## 配置怎么定

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 外部价签系统文档给出的地址，通过 `{{}}` 引用变量 | 与外部接口文档逐字比对路径与方法 |
| Headers 鉴权 | Authorization 使用 Bearer 加凭证，凭证经安全配置注入 | 与接口文档鉴权段落比对，不写入公开样例 |
| Body 结构 | 按外部接口契约写入条码与促销价字段 | 与价签系统字段说明逐项比对 |
| 变量引用 | 引用前方节点输出的条码与促销价 | 核对实际传入值与价签文档原文一致 |
| 返回值提取 | 配置 key 提取外部系统返回的状态字段 | 与外部接口响应示例比对 JSON path |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 不把调试空值当作业务故障 |

## 容易做错的三处

1. 把待审核的促销价签直接提交至外部价签系统。输入为材料原文中的“审批状态：待审核”，比较对象为提交动作所需的授权状态，观察结果为提交请求是否在授权满足前发出。
2. Body 中引用字符串变量时未加引号，导致 JSON 解析失败。输入为 `{{string}}`，比较对象为文档中 Body 声明需加 `""` 的写法，观察结果为最终解析值是否为字符串。
3. 把 detail=true 返回的中间值当作最终回答。输入为 responseData 中的模块状态，比较对象为 choices 中的 message.content，观察结果为下游使用的字段是否指向最终回答。

## 怎么确认配好了

1. 输入假设样本中的材料原文与交接请求，比较审批状态与提交动作的授权条件，观察结果为在授权未满足时不发出提交请求。
2. 输入 Body 中包含字符串变量的请求声明，比较文档中加引号的写法，观察结果为最终解析值与预期字符串一致。
3. 输入 detail=true、stream=false 的请求，比较 responseData 与 choices 字段，观察结果为最终回答取自 choices，中间值仅作核对用途。
