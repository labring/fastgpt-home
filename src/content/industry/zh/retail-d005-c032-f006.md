# 商超收银与会员促销的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

在商超收银与会员促销的库存采购与供应商资料中，本页说明FastGPT的定时任务与自动化如何衔接资料。会员促销备货复查要跟住商品适用与真实需求，规则更新不说明全部门店已经备妥。所用场景为自拟文字测试。

## 这些特征在「定时任务与自动化」这一环带来什么约束

自拟会员规则新增适用商品，标签素材仍待换，收银资料只来自某班次，备货确认没有补齐。定期复查可查新增商品的需求和库存依据，不从规则发布直接形成采购。实际触发入口和读取范围先按部署核，再检查本轮所指门店；异常退款记录只支持个案，不能代替当前可用库存，也不能推定促销已经执行。

## 配置怎么定

| 会员备货复查 | 自拟变化 | 实际核对 |
| --- | --- | --- |
| 新增适用 | 规则已改 | 不证已经采购 |
| 门店来源 | 某班次资料 | 不扩全区域 |
| 退款个案 | 未见回库 | 不推可用库存 |
| 标签素材 | 仍待换 | 保留待办 |
| 正式促销 | 采购设置另接 | 检查不证兑现 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `触发责任` | 先核可用触发入口及责任组件。 |
| `数据读取` | 外部读取接口需明确配置。 |
| `HTTP请求` | 请求按外部契约构造并核变量。 |
| `重复触发分工` | 去重、幂等及写入须另行实现。 |
| `执行记录` | 核真实触发、输入及业务返回。 |

## 容易做错的三处

规则冒采购：若新适用表变成已备货，应查实际确认；班次扩门店：若局部资料用于全区域，应核来源覆盖；退款冒库存：若退单存在就推商品已回，应查真实回库。三项分别核需求动作、范围和货物阶段，不由任务周期补齐。

## 怎么确认配好了

验收保留规则原句与实际取得资料，补本店备货依据后只更新对应商品，标签和其他门店仍待核。旧轮次输入不充新证据，读取失败应列缺口。正式采购、库存操作与促销设置需另接权限及回执，重复触发按真实实现检查；定期检查不证明会员权益已兑现，也不提供促销效果或供应保障承诺。
