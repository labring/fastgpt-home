# 多仓分仓与库存同步的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

在多仓分仓与库存同步的库存采购与供应商资料中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。多仓规则、库存表与同步状态需要对上本次采购对象，不由合并名称推导可用量。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

多仓采购核对可先区分分仓规则、当前库存和拟议调拨。自拟输入只有规则与同步表说明，没有本轮可用性或完成回执。HTTP拟接WMS或OMS时，方法、对象和条件来自真实契约，不预设已连全部仓库。规则说明怎样安排，不证明本次货物已按此移动；库存术语的含义也要有业务定义，不能只凭名称相同合并。

## 配置怎么定

| 采购读取核对 | 本题自拟资料 | 实际支持依据 |
| --- | --- | --- |
| 仓库角色 | 调出调入与发送值 | 未在请求中互换 |
| 库存含义 | 持有与可分配定义 | 未按词形直接合并 |
| 同步阶段 | 已发请求无完成依据 | 另核返回及业务记录 |
| 本轮来源 | 商品仓库和资料时间 | 覆盖当前采购问题 |
| 后续操作 | 创建调拨和回写另验 | 读取未替代可用确认 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

仓库角色错用：若调出被传成调入，应核原句及真实请求；持有冒可用：若返回持有库存被解释为可分配，应查来源定义与范围；请求冒同步完成：若已发同步被说成已更新，应核本次返回和业务记录。三项分别查角色、含义与执行，不由一份汇总补出。

## 怎么确认配好了

验收保留商品、仓库、资料时间、实际发送值和返回，补本轮对应依据后复问，看结论能否回指原文。请求头和业务参数分开核，Body在契约适用时组织，凭证不公开。采购创建、调拨或库存回写需另验权限及实际回执；读取有响应不证明渠道全部同步、货物可供采购或仓库没有缺货。
