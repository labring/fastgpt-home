# 大卖场生鲜联营柜台的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

在大卖场生鲜联营柜台的库存采购与供应商资料中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。联营约定、供货验收和库存盘点分别核对，采购问题不由损耗记录直接定因。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

鲜食联营采购可先核合同角色、供应商送货说明与本柜库存资料。自拟输入没有完整查验或当前可用依据，不能从联营约定推定实际供货完成。HTTP读取要核真实外部契约支持的主体、商品和批次，不预设POS、台账与供应商系统已经打通；损耗发生只提供这项陈述，不直接证明商品质量、保存条件或供货责任。

## 配置怎么定

| 采购读取核对 | 本题自拟资料 | 实际支持依据 |
| --- | --- | --- |
| 合同角色 | 经营方与送货方分别列 | 不直接合并主体 |
| 查验内容 | 送货签认无检查详情 | 未判质量已核 |
| 库存范围 | 盘点存量与当前可用分开 | 核定义适用时间 |
| 本柜批次 | 请求及真实返回对象 | 来源对应当前需求 |
| 实际处理 | 下单损耗或调整另验 | 查询未代替现场结论 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

主体角色错配：若合同经营方被当成送货方，应核两份原文关系；收货冒查验：若送货签认被写成质量已核，应另查本批实际检查；盘点冒可用：若某时点存量被当当前采购可分配，应核定义与适用时点。三项分别查角色、观察内容和库存范围，不由单据齐名补出。

## 怎么确认配好了

验收保留柜台、批次、资料性质、真实请求与返回，补本批对应依据后复问，看解释是否真实采用来源。请求头、参数和适用Body按契约核，凭证不公开。采购下单、损耗登记或库存调整另验业务授权与回执；读取结束不证明质量合格、现场检查完成或经营结算已确认。
