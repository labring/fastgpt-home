# 大卖场生鲜联营柜台的库存采购与供应商资料：文档解析与分块

## 这个品类的数据长什么样

大卖场生鲜联营柜台的库存采购与供应商资料，与便利店即食鲜食存在结构差异。联营模式下，供应商驻场经营并按销售分成，库存采购凭证与销售报表需要同时支撑食安查验与毛利核对。主要数据来源包括POS系统、供应商送货单、食品安全台账与门店盘点记录，日常处理的文档集中在联营合同、日销售报表、损耗单与食品进货查验记录四类。这些文档的更新频率为每日或每批，因此解析结果需要能回指到具体批次与日期。

文档解析与分块在本任务中的对象是上述四类文档。联营合同确定主体、分成与授权范围；送货单与进货查验记录确定批次、品名与数量；日销售报表与损耗单确定销售与损耗的分摊依据。分块需要保留这些字段之间的约束关系，避免将合同条款与具体批次记录拆散后失去核对能力。

## 这些特征在「文档解析与分块」这一环带来什么约束

分段完整性要求按具体资料结构切分。联营合同中的分成条款、有效期与授权边界应保留在同一数据组内；食品进货查验记录中的批次、品名、数量与查验结论应保持完整，避免条件与所约束的内容被拆离。同一组原数据可以对应多个索引，这为较长文本提供多向量映射，使其中一组向量被检索到时该数据仍可被召回。

数据与索引需要区分。MongoDB 的 dataset.datas 表存储向量原数据信息，indexes 字段记录对应的向量 ID，PostgresSQL 的 vector 字段用于存储向量，检索时先召回向量再根据 ID 回到 MongoDB 寻找原数据并合并。资料变更后需要核对实际训练与索引状态，上传成功不能直接当作检索已更新。语义召回与相关度仅影响内容匹配，不承担权限或实体隔离，检索本身不构成授权。

## 配置怎么定

以下配置围绕本页假设演练样本展开。样本材料原文为：「甲方为某某大卖场生鲜部，乙方为某某蔬菜联营供应商，双方约定叶菜类损耗由乙方承担百分之八，超出部分按销售分成比例分摊。2025年3月1日至2025年3月31日期间，乙方驻场经营叶菜柜台，进货查验记录随每批送货单附具。」待判定的拟稿句为：「乙方叶菜损耗全部由甲方承担，授权乙方自行决定进货批次。」该拟稿句与样本原文的分摊主体和授权边界不一致。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 样本含分成比例与日期，语义与关键词均需覆盖，与纯语义检索比较召回完整性 |
| 引用上限 | 本次假设起点为 3000 tokens | 样本段落含合同条款与批次记录，与 1500 tokens 比较是否截断约束条件 |
| 最低相关度 | 本次假设起点为 0.4 | 样本拟稿句与原文部分词面重叠，与 0.6 比较过滤效果 |
| 问题优化 | 本次假设开启 | 拟稿句含指代，与关闭状态比较指代消除结果 |
| 结果重排 | 本次假设启用 | 候选含合同与报表多段，与不重排比较排序位置 |
| 全文检索 | 本次假设使用 | 样本含日期与比例，与语义检索比较精确命中 |

## 容易做错的三处

1. 将拟稿句中的「全部由甲方承担」直接当作原文事实。输入为拟稿句与样本原文，比较对象为损耗分摊主体，原文写乙方承担百分之八，拟稿句写甲方全部承担，两者在同一字段上取值互斥，该拟稿句未获样本原文支持。待审核状态不证明缺少操作权限，需保留证据缺口。

2. 将上传成功当作检索已更新。输入为变更后的联营合同，比较对象为实际训练与索引状态，上传动作与索引更新是两个阶段，需核对 dataset.datas 中 indexes 字段与向量记录是否对应新版本。未核对前，检索结果可能仍指向旧版本。

3. 将语义召回得分当作权限或实体过滤。输入为检索请求，比较对象为召回内容与授权范围，相关度数值仅反映内容相似程度，不排除未授权记录。检索返回结果需要另行核对主体与授权边界，不能以得分高低推断访问权限。

## 怎么确认配好了

- 验证一：输入样本原文与拟稿句，比较损耗分摊主体字段，原文为乙方承担百分之八，拟稿句为甲方全部承担，同一字段取值互斥，判定拟稿句未获支持。预期现象为比较结果标记为不一致，保留原文作为核对依据。

- 验证二：输入变更后的合同版本，比较上传记录与 indexes 字段对应的向量 ID，核对新版本是否生成对应索引。预期现象为索引指向新版本时判定更新完成，索引仍指向旧版本时记录待复核。

- 验证三：输入检索请求与返回内容，比较返回记录的主体与授权范围，核对是否包含未授权供应商记录。预期现象为返回内容超出授权范围时记录缺口，不以相关度得分作为授权依据。空结果场景可用明确的纸面输入空数组核对下游设计，不声称规则检索一定返回空数组。
