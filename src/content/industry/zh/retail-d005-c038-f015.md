# 大卖场生鲜联营柜台的库存采购与供应商资料：知识库检索与召回

## 这个品类的数据长什么样

大卖场生鲜联营柜台由供应商驻场经营并按销售分成，库存采购与供应商资料同时涉及联营合同、日销售报表、损耗单和食品进货查验记录。这些材料决定核对称重销售、处理损耗分摊和查验进货凭证时能否找到依据。检索环节需要把合同条款、批次送货记录与损耗凭证对应到同一供应商和同一期间，资料缺失时只能记录缺口，不能替代授权判断。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。语义检索、全文检索与混合检索按测试问题分别比较，不预设一种模式适合全部资料。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，会额外调用模型。图片检索需要图像输入及相应模型能力，重排需要模型并按设置启用。这些路径属于可选组合，不代表每次请求全部执行。检索结果不构成授权，也不负责实体隔离。

假设演练样本：某联营合同文本载明“甲方为某大卖场生鲜部，乙方为某蔬菜供应商，合同有效期自二〇二五年一月一日至二〇二五年十二月三十一日，乙方在甲方生鲜区驻场经营，按销售额百分之十五分成”。一份拟稿交接句写道“该供应商合同已终止，库存损耗由门店承担”。待判定请求为“请检索该供应商的损耗分摊依据”。原文含主体、对象与有效期范围，未载明终止事实与损耗承担条款。

## 配置怎么定

| 配置项 | 本页对应设置 | 核对方式 |
| --- | --- | --- |
| 关联知识库 | 关联含联营合同、日销售报表、损耗单、食品进货查验记录的知识库 | 核各库向量模型标识，排除不一致者 |
| 搜索模式 | 对样本问题分别试语义检索与全文检索 | 比较两路返回内容与问题主体的对应关系 |
| 引用上限 | 本次假设试验起点设为 2000 token | 该值用于观察长短材料是否被截断，与较短材料对照 |
| 最低相关度 | 本次假设试验起点设为 0.3 | 先标注相关与无关样本，再比较阈值两侧结果 |
| 问题优化 | 对含指代的样本问题开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型时按设置启用 | 比较重排前后候选顺序，记录实际观察 |

## 容易做错的三处

1. 把检索命中当作授权。样本中拟稿句称合同已终止，原文只载明有效期，未载明终止事实。检索到合同文本只说明存在该材料，不说明终止已生效。
2. 把最低相关度当作实体过滤。该值是过滤阈值，不排除无关供应商或未授权记录。样本请求需另核供应商标识与访问权限。
3. 把混合检索的 RRF 写成开关。RRF 是融合过程，不是可开启项。样本中语义与全文两路结果按融合处理，不保证首条命中。

## 怎么确认配好了

1. 输入样本合同原文与拟稿句，比较拟稿句所称“已终止”与原文有效期字段。原文未载明终止，判定为未获支持，记录证据缺口。
2. 输入样本请求“请检索该供应商的损耗分摊依据”，比较返回内容是否含损耗承担条款。原文未载明该条款，返回为空或仅含合同有效期内容时，记录未找到依据。
3. 输入明确纸面空结果 `[]`，核对下游设计是否承接空引用。节点输出引用长度可为 0，空结果链路仍走通，不据此推断检索规则必然返回空。
