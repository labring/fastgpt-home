# 平台促销报名与价格管理的库存采购与供应商资料：向量模型与索引

## 这个品类的数据长什么样

平台促销报名与价格管理围绕价格、库存和活动节奏展开，主要数据来自活动后台、ERP库存与历史成交价。本页处理库存采购与供应商资料：活动报名表、促销价审批单、库存锁定表、活动复盘表构成待检索材料。这些材料按周和每场活动更新，同一供应商在同一活动期内可能出现多份报价与锁定记录。

材料内部结构决定索引质量。一份库存锁定表通常含供应商主体、商品对象、锁定数量、锁定日期区间与审批状态。一份促销价审批单含报价有效期、审批签署状态与适用活动场次。向量模型与索引环节需要把主体、对象、状态和有效范围一并保留，检索才能返回可核对的原数据。

## 这些特征在「向量模型与索引」这一环带来什么约束

关联检索的知识库须使用相同向量模型，先核实际模型与输入类型。一个原数据块可以关联多个索引，索引与原文内容分别核对。索引内容用完整且聚焦的信息建立，检索覆盖和索引长度需结合样本权衡。图片检索还取决于入库是否生成图片描述或图片向量，不能只看查询端。模型或索引调整后用同组问题比对引用原文，不根据向量分数单独承诺效果。

FastGPT 用 PostgresSQL 的 PG Vector 插件作向量检索器，索引为 HNSW，MongoDB 的 dataset.datas 表存原数据并保留 indexes 字段记录向量 ID。检索先召回向量，再按向量 ID 回 MongoDB 取原数据，同一组原数据合并后取最高得分。语义检索依赖向量距离，全文检索依赖关键词命中，混合检索用 RRF 融合两路结果，Rerank 对候选文本二次排序并给出 0-1 得分。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离。

假设演练样本。 供核对材料原文：其一，“供应商甲，商品A，活动场次S1，锁定数量500件，锁定期间2025年6月1日至6月30日，状态：运营已提交，采购审批栏空白。”其二，“供应商甲，商品A，报价单Q1，报价有效期2025年5月20日至6月20日，签署栏空白。”待判定拟稿句：“供应商甲商品A在S1场次已完成库存锁定与价格审批。”

## 配置怎么定

| 配置项 | 本页取值或核对方式 | 与样本的关系 |
| --- | --- | --- |
| 关联知识库 | 核各库向量模型标识，排除不一致者 | 保证四类材料可共同关联 |
| 索引内容 | 每块保留主体、对象、状态、有效范围 | 锁定表与审批单按此建索引 |
| 索引与原数据 | 一个原数据块可关联多个索引 | 同一锁定记录可挂多组索引 |
| 搜索模式 | 编号、场次用全文或混合检索 | 场次S1、报价单Q1需精确命中 |
| 最低相关度 | 本次假设试验起点0.3，与0.5比较 | 观察过滤后引用条数变化 |
| 引用上限 | 按 tokens 设定，不采用 top k | 控制返回原文长度 |

最低相关度起点0.3为本次假设试验选择，理由是样本问题较短、主体明确，需与0.5对比观察被过滤内容。该值不是官方默认值。

## 容易做错的三处

1. 把检索命中当作授权。样本中采购审批栏空白，检索到锁定表只说明材料存在，不说明审批完成。比较动作：取回原数据后查看审批字段取值。观察结果：字段为空则应记为待核实。
2. 用报价有效期推断供货期限。样本报价有效期至6月20日，锁定期间至6月30日。比较动作：逐字段核对两个日期范围。观察结果：两者不重合部分不能视为已覆盖。
3. 跨向量模型的库共同关联。比较动作：核对各库向量模型标识。观察结果：标识不一致者排除，记录实际观察，不据此推断漏召回或冗余。

## 怎么确认配好了

1. 输入样本原文两句与拟稿句，执行检索。比较返回引用原文与样本原文的主体、对象、状态字段。满足条件：引用原文含供应商甲、商品A、场次S1，且审批状态字段与原文一致。
2. 输入场次标识S1，使用全文或混合检索。比较返回结果是否含该精确标识。满足条件：引用内容出现S1对应锁定记录；若未出现，记录为未命中并检查索引内容。
3. 输入报价单标识Q1，比较返回的签署栏与有效期字段。满足条件：返回原文签署栏为空白、有效期止于6月20日。若返回内容缺失该字段，记录证据缺口，不判定审批已完成或未完成。

空结果以纸面输入空数组核对下游链路是否走通，不声称虚构规则检索一定返回空。
