# 平台促销报名与价格管理的库存采购与供应商资料：知识库检索与召回

## 这个品类的数据长什么样
促销报名与价格管理的核心资料是活动报名表、促销价审批单、库存锁定表、活动复盘表，关注点是价格、库存与活动节奏，不是宣传用语审查。这些资料分别由平台活动运营、品牌销售计划与财务BP持有，更新频率为周和每场活动。知识库检索与召回要面对的是同一活动下多份材料并存、字段口径相近、状态词容易混用的情况。检索结果只反映文本相似程度，不反映材料是否已审批、库存是否已锁定或价格是否已生效。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可以关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不能共同关联，需要先核对向量模型标识，把不符合者排除，记录实际观察，不执行跨模型检索来比较漏召回。搜索模式分为语义检索、全文检索与混合检索，混合检索通过 RRF 融合多路结果，RRF 是融合过程，不是可开启的开关。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效，是过滤阈值，不是排序规则。问题优化用于指代消除和问题扩展，会在检索前增加一次模型调用。输出引用内容以数组格式给出，长度可以为 0，没有搜索到内容时链路也会走通。

假设演练样本：材料原文为“活动报名表-2025年3月春季大促，主体为品牌销售计划，对象为某平台店铺，状态为待审核；促销价审批单同一活动同一字段状态为已审批；库存锁定表同一活动同一字段状态为待锁定”。拟稿句为“该活动价格已生效，库存已锁定，可提交资源位报名”。原文只给出待审核、已审批、待锁定三种状态，未载明价格生效条款与库存锁定完成记录，拟稿句属于未获支持，需要记录证据缺口。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅关联同一向量模型标识的促销报名资料库 | 核对向量模型标识一致后再关联，排除标识不符者 |
| 搜索模式 | 先分别用语义检索与全文检索测试同一问题 | 比较两种模式下活动编号与状态字段的命中差异 |
| 引用上限 | 假设起点为 2000 token | 用长短不同的报名表与审批单比较内容是否被截断 |
| 最低相关度 | 假设起点为 0.5 | 先标注相关与无关样本，再比较过滤后结果 |
| 问题优化 | 仅在多轮追问与短问题场景开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型且按设置启用时使用 | 比较重排前后候选顺序，观察得分变化 |

## 容易做错的三处
1. 把检索命中当成授权通过。输入是待审核的报名表，比较对象是审批状态字段，观察结果是检索返回该材料，这不表示审批已完成，也不表示可以提交资源位报名。
2. 把不同向量模型的库共同关联。输入是两个向量模型标识不同的库，比较对象是模型标识，观察结果是标识不一致，应当排除，不继续编造共同关联后的运行结果。
3. 把最低相关度当成权限或实体过滤。输入是无关业务问题，比较对象是相似度得分，观察结果是得分低于阈值被过滤，这不表示无关业务或未授权记录被排除。

## 怎么确认配好了
1. 输入假设样本中的拟稿句“该活动价格已生效，库存已锁定，可提交资源位报名”，比较对象是材料原文中的待审核、已审批、待锁定三种状态，观察结果是拟稿句所述价格生效与库存锁定在原文中未获支持，判定为待核实。
2. 输入假设样本中的活动报名表与促销价审批单，比较对象是同一活动同一字段的状态取值，观察结果是两处状态取值不同，属于同字段互斥取值，判定为矛盾，需要人工核对。
3. 输入一个明确的纸面空结果数组，比较对象是下游承接设计，观察结果是链路继续走通，记录空结果分支，不声称虚构规则检索一定返回空数组。
