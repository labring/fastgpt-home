# 平台商品标题与详情合规的库存采购与供应商资料：文档解析与分块

## 这个品类的数据长什么样

平台商品标题与详情合规处理宣传真实性和资质展示，不处理包裹交付。库存采购与供应商资料包括供应商资质文件、采购合同、质检报告、广告禁词清单和商品标题表。这些材料在上新与资料变更时需要解析入库，供后续检索核对。解析结果必须能回指原文的文档身份与版本，分块须保留条件与所约束内容的完整关系。

## 这些特征在「文档解析与分块」这一环带来什么约束

文档解析与分块将原始资料转为可检索的数据。FastGPT 中库、集合、数据三层结构中，最小搜索单位是库，集合仅作分类管理。原数据存于 MongoDB 的 `dataset.datas` 表，`indexes` 字段记录对应向量 ID，一组数据可对应多个向量；向量存于 PostgresSQL 的 `vector` 字段，索引为 `HNSW`，检索时先召回向量再按 ID 回 MongoDB 取原数据，同组数据合并、取最高得分。

分段应保持结构和语义完整。较长文本可添加多组向量，其中一组被召回即可召回该数据。检索可组合语义检索、全文检索、混合检索、问题优化和重排，混合检索经 `RRF` 融合。引用上限以 tokens 计，最低相关度仅语义检索或结果重排时生效，均为过滤条件，不承担权限或实体隔离。跨不同向量模型的库不能共同关联。

假设演练样本：某供应商资质文件原文为“供应商甲，营业执照有效期至2027年6月30日，食品经营许可证编号XK-2024-0871，本批次质检报告编号QC-2024-1120，签发日期2024年11月5日。”待判定拟稿句为“供应商甲资质齐全，长期有效。”该拟稿句未载明具体有效期与许可证状态，与原文“有效期至2027年6月30日”不一致，属未获支持。

## 配置怎么定

| 配置项 | 本页相关设置或核对项 | 实施说明 |
| --- | --- | --- |
| 搜索模式 | 语义检索、全文检索或混合检索 | 按样本问题类型选择，编号类优先全文或混合 |
| 引用上限 | 以 tokens 计 | 文档未给出具体数值，按实际候选长度核对 |
| 最低相关度 | 0-1 数值，仅语义检索或重排时生效 | 文档未给出默认值，按观察结果调整 |
| 问题优化 | 检索前指代消除与问题扩展 | 按需开启，会增加一次模型调用 |
| 结果重排 | `ReRank` 二次排序，得分 0-1 | 需具备重排模型并按设置启用 |
| 图片检索 | 视觉模型或支持图片的向量模型 | 须有图像输入及模型能力，非每次请求执行 |

## 容易做错的三处

1. 将上传成功当作检索已更新。资料变更后须核对实际训练与索引状态，上传动作本身不表示索引已生成。
2. 将最低相关度当作权限或实体过滤。该值仅过滤低相关度结果，不排除无关业务或未授权记录。
3. 将混合检索的 `RRF` 融合写成开关。`RRF` 是多路结果融合过程，不是可开启的独立配置项。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句“供应商甲资质齐全，长期有效。”，比较拟稿句与原文有效期字段。原文明确“有效期至2027年6月30日”，拟稿句未载明该日期且表述为“长期有效”，观察结果应为未获支持，须记录证据缺口。
2. 输入样本中的编号“QC-2024-1120”与“XK-2024-0871”，分别用全文检索和语义检索，比较两路召回内容。观察全文检索是否命中编号所在分段，语义检索是否召回同段，据此判断分段对精确查询的影响。
3. 输入空结果承接场景，用明确的纸面输入 `[]` 核对下游设计，比较下游对空引用的处理。观察下游是否按空引用处理，不声称虚构规则检索一定返回 `[]`。
