# 平台多店铺矩阵管理的库存采购与供应商资料：知识库检索与召回

## 这个品类的数据长什么样
多店矩阵的资料围绕店铺授权清单、价格管控表、窜货投诉单、月度销售报表展开，来源包括各平台商家后台、ERP渠道价、品牌防伪系统与经销商报表。这些材料按日或按月更新，同一供应商、同一商品在不同店铺可能对应不同授权状态与价格口径。检索这类资料时，问题往往同时涉及主体、店铺、期间和字段，例如某店铺在某月的授权范围，或某供应商报价的有效区间。资料本身不会自动完成授权核验，检索命中只代表文本被召回，不代表授权成立、审批通过或数据写入完成。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不能共同关联，需要先核对标识并排除不符合者。搜索模式分为语义检索、全文检索和混合检索，混合检索通过 RRF 融合多路结果，RRF 是融合过程，不是可开启的开关。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，会额外调用模型。引用内容以数组输出，长度可以为 0，空结果链路仍会走通。图片检索需要图像输入与相应模型能力，重排需要具备模型并按设置启用，这些可选路径不代表每次请求全部执行。

假设演练样本：材料原文为“授权清单-甲店：供应商A，授权期间2024年1月至2024年6月，授权范围：家用小家电。价格管控表-甲店：供应商A，家用小家电，最低零售价99元，有效期2024年3月。”待判定拟稿句为“甲店供应商A在2024年3月具备家用小家电供货授权，报价有效期覆盖供货期限。”该拟稿句混用了授权期间、价格有效期与供货期限，授权期间与价格有效期属不同字段，报价有效期不表示供货期限，判定为待核实。

## 配置怎么定
| 配置项 | 本样本设定 | 核对方式 |
| --- | --- | --- |
| 关联知识库 | 授权清单库、价格管控表库，使用相同向量模型 | 核对向量模型标识，排除不同模型库 |
| 搜索模式 | 本次假设起点为混合检索 | 与语义检索、全文检索结果比较，观察编号类问题命中 |
| 引用上限 | 本次假设起点为2000 token | 与长短不同的实际资料比较，观察内容是否完整 |
| 最低相关度 | 本次假设起点为0.3 | 与已标注相关、无关样本比较，观察过滤效果 |
| 问题优化 | 本次假设为开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 本次假设为启用 | 与未重排结果比较，观察相关度得分排序 |

## 容易做错的三处
1. 把检索命中当作授权成立。输入拟稿句“甲店供应商A在2024年3月具备供货授权”，比较授权期间字段2024年1月至2024年6月，观察是否仅凭检索命中就判定授权执行，正确结果是授权状态仍需人工核验。
2. 混用不同字段。输入拟稿句“报价有效期覆盖供货期限”，比较价格管控表有效期2024年3月与授权期间，观察是否把报价有效期当作供货期限，正确结果是该字段未载明供货期限。
3. 跨模型库共同关联。输入授权清单库与价格管控表库的向量模型标识，比较两者是否一致，观察是否在标识不一致时仍执行关联，正确结果是标识不符时排除并记录。

## 怎么确认配好了
1. 输入假设样本原文与拟稿句，比较授权期间、价格有效期与供货期限三个字段，观察拟稿句是否被判定为待核实，满足条件为判定结果与字段差异一致。
2. 输入授权清单库与价格管控表库的向量模型标识，比较两者是否相同，观察关联操作是否在标识不符时被排除，满足条件为排除动作被记录。
3. 输入空引用数组[]，比较下游设计是否按空结果处理，观察链路是否走通，满足条件为下游设计明确承接空结果。以上均为纸面核对，未执行实际检索，未声称任何业务动作已完成。
