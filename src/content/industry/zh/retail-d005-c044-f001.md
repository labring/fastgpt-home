# 平台广告投放与站内流量的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

在平台广告投放与站内流量的库存采购与供应商资料中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。投放服务采购要核计划、实际执行和归因定义，不从报告存在直接证明服务成效。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

投放服务采购可先读计划、关键词报告与归因说明，不填预算、效果数据或真实人群记录。自拟输入没有本次完整执行与交易依据，HTTP读取需先核真实服务契约的活动、期间和来源范围，不预设平台数据已全部相接。人群包名称不提供个人权限，归因表说明关系，不自动证明成因，资料获取应保持原文定义。

## 配置怎么定

| 采购读取核对 | 本题自拟资料 | 实际支持依据 |
| --- | --- | --- |
| 服务执行 | 拟投放与本次实际记录 | 未直接写成已交付 |
| 归因含义 | 渠道关系与因果分开 | 核定义及支持依据 |
| 活动期间 | 他期报告进入当前 | 查请求和资料时间 |
| 公开范围 | 无效果数或真实人群记录 | 返回按契约范围核 |
| 正式验收 | 批准修改与发布另验 | 读取未替代成效结论 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

计划冒交付：若拟投放文字被回答为服务已执行，应查本次实际来源；归因冒因果：若渠道归属被写成造成结果，应核定义及支持关系；活动错配：若其他期间报告进入，应核真实请求与资料时间。三项分别查执行、解释范围和对象，不由报告完整样式补出。

## 怎么确认配好了

验收保留活动、定义、真实输入及返回，补相应执行或交易资料后复问，核解释只覆盖所得依据。Headers、Params和适用Body按外部契约核，凭证不公开。采购批准、投放修改、外部回写或报表发布另验权限及实际回执；本次读取不证明服务验收、增长产生或归因已经完成审计。
