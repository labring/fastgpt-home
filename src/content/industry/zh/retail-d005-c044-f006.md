# 平台广告投放与站内流量的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

平台广告投放按流量与转化实时调价，审核环节不构成主要门槛，库存采购与供应商资料因此更依赖投放计划、关键词报表、人群包说明、转化归因表这几类文档。投放专员与代运营投手在日常交接时，需要把采购数量、供应商名称、报价有效期、授权范围写进同一批材料，供后续核对。数据来源包括巨量千川、京东快车、阿里妈妈与店铺成交数据，更新频率为日或小时，这一节奏影响的是材料版本，定时任务本身不因更新频率改变触发方式。

## 这些特征在「定时任务与自动化」这一环带来什么约束

HTTP 请求节点可重复添加、手动配置、触发执行。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 histories 默认最多取 10 条且无法修改长度。Params、Headers、Body 与 URL 均可通过 `{{}}` 引用全局变量、系统变量或前方节点输出。返回值依赖 JSON path 提取，出参格式化以 json 转字符串为主。

定时触发是否由应用定时能力还是外部调度承担，须按实际版本核对可用入口。外部数据由已配置接口读取，定时触发不自动建立业务系统连接。去重、幂等与业务写入须在接口或后续流程明确设计。执行记录须核对触发时间、真实输入、返回结果与业务状态，任务存在不等于执行成功。检索与表单都不构成授权，采购审批、供应商准入、数据库写入与外部同步均需另接系统实现。

## 配置怎么定

下表围绕假设演练样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。

| 配置项 | 设置或核对内容 | 依据与边界 |
| --- | --- | --- |
| 触发责任 | 核对本次由应用定时能力还是外部调度发起，记录入口名称与版本 | 按实际版本核对，不假定默认开启 |
| 请求方法 | 按外部接口文档核对 GET 或 POST 等方法 | 文档未给出具体接口绑定 |
| Headers | 以 `{{token}}` 形式传入 Authorization 等请求头 | 变量来自全局、系统或前方节点输出 |
| Body 变量引用 | 字符串加 `""`，number、boolean、array、object 按类型直接引用 | 仅特定请求类型下生效 |
| 返回值提取 | 用 `$.data.user.name` 一类 JSON path 配置 key | 出参格式化以 json 转字符串为主 |
| 执行记录核对 | 核对触发时间、真实输入、返回结果与业务状态 | 任务存在不等于执行成功 |

假设演练样本：某投放专员提交一份库存采购交接单，材料原文为“供应商：华东某广告物料供应商；采购对象：站内流量包 500 份；报价有效期至 2025 年 6 月 30 日；授权范围：仅限本次投放计划使用”。待判定拟稿句为“该供应商已获授权执行本次采购”。原文只载明授权范围限于本次投放计划使用，未载明审批签署或合同生效，该拟稿句未获支持。

## 容易做错的三处

1. 将检索命中或表单填写当作授权完成。输入为上述交接单原文，比较对象是“授权范围：仅限本次投放计划使用”一句，可观察结果是原文未出现审批、签署或生效字样，因此不能判定采购已获授权。
2. 将定时触发当作已建立业务系统连接。输入为触发入口名称，比较对象是接口配置是否已填写方法、Headers 与 Body，可观察结果是配置为空时外部数据不会被读取。
3. 将任务存在当作执行成功。输入为任务记录，比较对象是触发时间、真实输入与返回结果，可观察结果是缺少返回结果时无法确认业务状态。

## 怎么确认配好了

- 验证一：取上述交接单原文，输入拟稿句“该供应商已获授权执行本次采购”，比较原文授权范围与拟稿句主体、对象、期间、字段是否同一，只有当原文出现同字段的审批或生效记载时，该句才获支持；当前现象为未获支持。

- 验证二：取触发入口名称与接口配置，比较方法、Headers、Body 是否按外部接口文档填写，只有当三者与文档一致且返回结果可提取时，才满足条件；配置为空时记录为缺口。

- 验证三：取任务记录，比较触发时间、真实输入、返回结果与业务状态四项是否齐全，只有当四项均可核对时，才满足条件；缺少返回结果时保留为待核实。检索与相关度不承担权限或实体隔离，空结果可用明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回空。
