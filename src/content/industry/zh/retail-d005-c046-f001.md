# 平台类目资质准入的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样
类目准入发生在入驻或上架之前，核对对象是主体资质与授权链，涉及营业执照、商标注册证、品牌授权链、行业许可证。库存采购与供应商资料环节要把供应商提交的这些材料与采购记录对应起来，交由外部系统做接口传递。资料更新不定期，每次入驻重新收集，接口调用按每次交接触发。资质材料存在有效期与授权范围，采购资料存在数量与批次，两者在接口中属于不同字段，不能互相替代。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params 用于路径参数，Body 用于请求体，Headers 用于请求头，三者均可通过 `{{}}` 引用变量。变量来自全局变量、系统变量和前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在，测试环境取不到值属于该模式的已知情况。返回值通过 JSON path 提取，输出类型选择字符串时会把对应 key 的值转成 json 字符串。接口调用完成只代表请求已发出并收到响应，资质核验、准入批准、数据库写入与外部同步需要另行实现。检索与相似度分数不承担权限或实体过滤职责。

假设演练样本：某供应商提交的营业执照载明主体为“示例市晨星商贸有限公司”，统一社会信用代码字段在材料上留空；商标注册证载明注册人为“示例市晨星商贸有限公司”，核定使用范围含第 25 类；品牌授权链文件载明授权方为商标注册人，被授权方为“示例市晨星商贸有限公司”，授权期限自 2025 年 1 月 1 日至 2025 年 12 月 31 日。待判定的拟稿句为：“该供应商资质齐全，可准入第 25 类并同步至采购系统。”核对要点：营业执照主体与授权链被授权方一致，商标注册人一致；统一社会信用代码未载明，属于证据缺口；授权期限覆盖本次拟采购批次日期；接口同步是否执行未获授权说明。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 理由与比较方法 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址引用已提供变量 | 地址与外部契约一致，方法匹配业务动作 |
| Headers 鉴权 | 通过安全配置注入凭证 | 与接口文档声明的鉴权方式比较，不写入公开样例 |
| Body 结构 | 按外部接口契约声明 JSON 字段 | 与接口文档字段逐项比较，仅相应请求类型下生效 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 逐项核对实际传入值，与材料字段对应 |
| 返回提取 | 按 JSON path 提取所需字段 | 与接口响应结构比较，字符串类型触发格式化输出 |
| 调试身份字段 | 测试模式下 chatId、responseChatItemId 不存在 | 与正式调用比较，不把调试空值当作业务故障 |

## 容易做错的三处
1. 把接口返回成功当作准入批准。输入是 HTTP 响应，比较对象是资质核验与准入批准记录，观察结果是两者是否分别存在；响应成功不产生批准事实。
2. 用相似度分数筛除无关供应商。输入是检索返回的 score，比较对象是供应商主体标识与授权范围，观察结果是是否按标识排除；分数不承担实体或权限过滤。
3. 把测试模式下 chatId 为空当作接口故障。输入是测试模式调用，比较对象是正式调用返回的 chatId，观察结果是该字段在测试模式下的存在状态；空值属于该模式已知情况。

## 怎么确认配好了
1. 针对样本中营业执照统一社会信用代码留空，输入该材料原文与拟稿句“资质齐全”，比较对象是材料已载明字段与拟稿断言，观察结果是拟稿句是否超出材料支持范围；未载明字段应记录为缺口。
2. 针对授权期限 2025 年 1 月 1 日至 2025 年 12 月 31 日与拟采购批次日期，输入两者，比较对象是期限覆盖关系，观察结果是批次日期是否落在区间内；区间外则授权链未覆盖该批次。
3. 针对拟稿句中的“同步至采购系统”，输入接口响应与下游写入记录，比较对象是响应字段与采购系统实际记录，观察结果是下游是否存在对应记录；仅有响应而无写入记录时，同步状态为未获支持。
