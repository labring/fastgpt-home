# 平台退款退货处理的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

普通平台退款按订单持续发生，不必然关联单场直播承诺。退款申请、退货物流单、质检照片与退款审批构成主要材料，来源分散在平台售后后台、客服聊天、WMS收货与支付退款记录。库存采购与供应商资料这一任务中，HTTP 接口承担把外部系统的采购单、供应商信息或退款审批结果接入编排的职责。材料按每单和每日更新，接口核对需要逐单确认。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params、Body、Headers 三处均可通过 `{{}}` 引用变量，变量来自全局变量、系统变量或前方节点输出。URL 也可引用变量。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories。chatId 与 responseChatItemId 在测试模式下不存在，调试时为空值属于已知条件，不能当作业务故障。

出参通过 JSON path 提取，key 遵守 JS 对象取值规则，输出类型选择字符串时会把值转成 json 字符串。接口返回的相似度、检索结果不构成授权或权限过滤，接入采购与供应商数据时，业务校验、审批、数据库写入与外部同步都需要另行实现。

假设演练样本：某平台售后专员在 2025 年 3 月 10 日处理订单 A 的退货，供应商资料页记录“供应商 S 承担退货运费，退款审批单号 R-0310 状态为待审核”。拟交接请求为“请通过 HTTP 接口把 R-0310 同步为已审批并写入供应商 S 的采购结算记录”。该请求中的审批状态与写入动作均无对应已签署审批文件，属于未获支持的交接请求。

## 配置怎么定

| 配置项 | 本页用途 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 对接供应商或退款审批接口 | 按外部接口文档逐项比对地址、方法 |
| Params 与 Headers | 传递路径参数与鉴权凭证 | 核对键名与引用变量名一致 |
| Body | 在 POST/PUT 下传递采购或退款字段 | 核对 JSON 结构与接口契约 |
| 变量引用 | 引用前方节点输出或全局变量 | 逐项核对实际传入值 |
| 返回值提取 | 用 JSON path 取供应商或审批字段 | 核对 key 与响应结构对应 |
| 调试身份字段 | chatId 与 responseChatItemId | 测试模式下为空属已知条件 |

## 容易做错的三处

1. 把待审核当作已审批。样本中 R-0310 状态为待审核，拟交接请求称“同步为已审批”，输入与原文状态字段不一致，比较后可见请求超出授权边界。
2. 把接口返回的检索结果当作业务授权。相似度与检索命中不构成审批或写入许可，样本中未提供任何审批签署材料，写入动作缺少依据。
3. 把测试模式下 chatId 为空当作故障。文档说明测试模式下 chatId 与 responseChatItemId 不存在，空值属于已知条件。

## 怎么确认配好了

1. 输入样本原文与拟交接请求，比较 R-0310 状态字段与请求所述状态。原文为待审核、请求称已审批，两值互斥，判定请求未获支持。
2. 输入接口返回值提取配置，比较提取 key 与响应 JSON 结构。若 key 与响应层级不匹配，提取结果为空，需核对路径。
3. 输入测试模式下的 chatId 与 responseChatItemId，比较实际取值与文档说明。取值为空符合文档描述，不构成故障；若需非空值，须在非测试模式下获取。
