# 平台退款退货处理的库存采购与供应商资料：文档解析与分块

## 这个品类的数据长什么样

平台退款退货处理按订单持续发生，与直播售后集中处理不同，退款申请不一定关联单场直播承诺。库存采购与供应商资料这一任务里，日常材料包括退款申请、退货物流单、质检照片和退款审批。这些材料的主体、对象、阶段和有效范围各不相同：退款申请写明订单与商品，退货物流单写明退件在途或已签收，质检照片反映商品状态，退款审批记录金额与审批状态。资料更新频率为每单、每日，这一频率影响的是分块后索引与原文的对应关系，不推出批量同步或实时触发机制。

## 这些特征在「文档解析与分块」这一环带来什么约束

FastGPT 知识库由库、集合和数据三部分组成，最小搜索单位是库，集合仅用于分类管理。一组数据可对应多个向量，向量得分取最高得分。分段时应保障每组数据语义完整、结构单一，条件、说明与所约束的内容不应被拆离。原数据与检索索引需要区分：MongoDB 的 dataset.datas 存储原数据信息，indexes 字段记录对应向量 ID。检索时先召回向量，再按向量 ID 回 MongoDB 寻找原数据，命中同一组原数据则合并。全文检索在 PG 等向量库走 MongoDB $text 加 jieba 分词，在 Milvus 走 BM25。混合检索通过 RRF 融合多路结果，ReRank 对候选文本二次排序并给出 0-1 得分。引用上限按 tokens 控制，最低相关度仅在语义检索或结果重排时生效。图片检索需要入库时建立对应索引并具备相应模型能力，不是每次请求都执行全部路径。

假设演练样本：材料原文为“退款申请单 A-001，订单 2024-0301，商品为折叠桌，申请日期 3 月 5 日，申请状态为待审核。退货物流单 L-778，同一订单，3 月 8 日显示已签收。质检照片 P-12，同一订单，显示桌面有划痕。”拟交接请求为“请依据上述材料确认该订单退款申请是否已获批准，并安排退款。”该请求中待审核状态与已签收、质检照片属于不同事实，授权边界为仅核对材料，不执行退款。

## 配置怎么定

| 配置或核对项 | 本页用途 | 依据与说明 |
| --- | --- | --- |
| 库与集合划分 | 将库存采购与供应商资料按库组织，集合用于分类 | 文档说明最小搜索单位是库，集合与搜索效果无关 |
| 分段完整性核对 | 检查退款申请、物流单、质检照片的条件与所约束内容未被拆离 | 文档建议保障每组数据完整、语义单一 |
| 原数据与索引区分 | 核对 dataset.datas 中 indexes 字段与向量 ID 的对应 | 文档说明一组数据可对应多个向量 |
| 检索模式选择 | 编号类查询用全文或混合检索，自然语言查询用语义检索 | 文档说明各模式适用场景 |
| 引用上限与最低相关度 | 按 tokens 控制引用量，按 0-1 阈值过滤 | 文档说明最低相关度仅在语义检索或重排时生效 |
| 更新后训练状态核对 | 资料变更后核对实际训练与索引状态 | 文档说明上传成功不等于检索已更新 |

## 容易做错的三处

1. 将待审核状态当作已批准。样本中退款申请单 A-001 申请状态为待审核，拟交接请求要求确认是否已获批准。错误在于把待审核等同于批准，或把物流已签收当作退款审批完成。核对时应比较同一订单、同一字段的取值，待审核与已批准为互斥取值，样本未载明批准记录，属于未获支持。
2. 将检索结果当作授权执行。检索到退款申请或审批记录，不代表已获得执行退款的授权。样本授权边界为仅核对材料，退款属于需另接系统实现的业务动作，检索与表单不承担授权功能。
3. 将不同向量模型的库共同关联。文档说明跨不同向量模型的库不可共同关联，应先核标识并排除不符合者，记录实际观察，不推断漏召回或冗余等运行结果。

## 怎么确认配好了

1. 输入样本材料原文与拟交接请求，比较退款申请单 A-001 的申请状态字段与批准记录。预期现象为：若样本中无批准记录，则判定为未获支持，不能输出已批准结论。
2. 输入样本中退货物流单 L-778 的签收状态与质检照片 P-12 的划痕描述，比较两者是否指向同一订单、同一商品。预期现象为：同一订单下物流已签收与质检有划痕为不同事实，不能互相替代证明退款责任。
3. 输入一条空结果承接的纸面输入，核对下游设计是否将空结果与未获支持区分。预期现象为：空结果按缺失证据处理，不声称虚构规则检索一定返回空数组，也不将空结果解释为否定。

三项验证均使用上述样本原文与请求，逐项说明输入、比较对象与满足条件，不声称已实测。语义召回与相关度不承担权限或实体隔离功能，检索库同向量模型要求不扩展至外部系统。
