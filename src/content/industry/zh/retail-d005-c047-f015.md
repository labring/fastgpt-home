# 平台退款退货处理的库存采购与供应商资料：知识库检索与召回

## 这个品类的数据长什么样

普通平台退款按订单持续发生，不必然关联单场直播承诺，因此库存采购与供应商资料在检索时面对的是逐单累积、来源分散的材料。主要数据来自平台售后后台、客服聊天、WMS收货和支付退款记录，日常要处理的文档包括退款申请、退货物流单、质检照片和退款审批。这些材料分别由客服、售后专员和仓库质检产生，同一笔退货的采购批次、供应商名称、质检结论和退款金额可能落在不同文档里。检索环节要做的是把与当前问题相关的材料召回出来供人工比对，召回结果本身不构成责任认定或退款授权。

## 这些特征在「知识库检索与召回」这一环带来什么约束

关联知识库时，只能选择使用相同向量模型的知识库。知识库搜索节点可关联一个或多个知识库，跨不同向量模型的库不可共同关联，操作上先核对向量模型标识，把不符合的库排除并记录实际观察，不执行跨模型检索来比较漏召回。引用内容以数组输出，长度可以为 0，没有搜索到内容时该输出链路仍然走通，空结果可以承接下游设计，但不能据此断定某条虚拟规则检索一定返回空数组。

检索模式需要按测试问题在语义检索、全文检索和混合检索之间比较，不预设一种模式适合全部资料。混合检索通过 RRF 融合多路结果，RRF 是融合过程，不作为独立开关描述。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担排序职责，也不承担权限或实体隔离职责；相似度设置无法排除无关业务或未授权记录，检索不等于授权。引用上限以 token 为单位，用长短不同的实际资料测试内容是否完整再调整。问题优化用于指代消除和问题扩展，需要比较原问题与优化后问题，核对主体是否被改错。图片检索须有相应图像输入及模型能力，重排须具备模型且按设置启用，文档流程图列出的可选路径不代表每次请求全部执行。

假设演练样本：某供应商资料库中一段原文为“供应商甲，2026 年 3 月批次退货，质检结论为外包装破损，责任归属待售后专员确认，退款审批状态为待审核。”另一条原文为“供应商甲，2026 年 3 月批次退货，质检结论为外包装破损，退款审批状态为已通过。”待判定的拟稿句为“供应商甲 2026 年 3 月批次退货已通过退款审批，责任归属已确认。”该拟稿句与第一条原文在退款审批状态字段上取值互斥，与第二条原文在责任归属字段上缺少记载，属于未获支持或待核实。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅纳入向量模型标识一致的库存采购与供应商资料库 | 核对标识后排除不一致者，不执行跨模型检索 |
| 搜索模式 | 对含批次号、供应商名称的问题比较全文检索与混合检索 | 按测试问题的命中情况比较，不预设单一模式 |
| 引用上限 | 暂设一个 token 值，用于覆盖一条完整质检结论加审批状态 | 以长短不同的实际资料测试内容是否完整，再与相邻取值比较 |
| 最低相关度 | 暂设一个 0 到 1 的数值，先标注相关与无关样本 | 仅在语义检索或结果重排时生效，按样本过滤情况调整 |
| 问题优化 | 对含指代的多轮追问比较优化前后问题 | 核对主体是否被改错，短问题场景单独观察 |
| 结果重排 | 候选较多时比较启用前后的排序 | 重排须具备模型且按设置启用，得分用于过滤 |

以上数值均为本次假设试验起点，不来自官方默认值，也不代表已实际测试。

## 容易做错的三处

1. 把检索召回当成授权。输入一条待审核退款申请，比较检索结果与退款审批状态字段，若检索命中该申请就据此认为退款已获批准，属于错误；待审核不证明已批准，也不证明缺少操作权限。
2. 把跨模型知识库强行共同关联。输入两个向量模型标识不同的库，比较标识后仍将其一起关联，并推断会出现漏召回或冗余，属于错误；正确做法是核对标识、排除不符合者并记录实际观察。
3. 把最低相关度当作权限过滤。输入一条与问题语义相近但属于其他供应商的记录，比较过滤阈值与该记录的权限归属，若因分数高就认为可访问，属于错误；相关度分数不承担实体或权限隔离。

## 怎么确认配好了

1. 输入假设样本第一条原文与拟稿句，比较退款审批状态字段，预期观察到两者取值互斥，拟稿句在该字段上未获支持；若拟稿句被判定为已通过，则不满足条件。
2. 输入假设样本第二条原文与拟稿句，比较责任归属字段，预期观察到原文未记载责任归属结论，拟稿句该部分属于待核实；若拟稿句声称责任已确认，则不满足条件。
3. 输入一个明确标注为纸面输入的引用内容数组 []，比较下游设计对该空结果的承接方式，预期观察到链路继续走通且不据此断言某条虚拟规则必然返回空数组；若据此认定检索失败或业务未发生，则不满足条件。
