# 快递面单与揽收交接的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

快递交接发生在包裹离仓节点，承运商扫描记录决定责任归属，库存采购与供应商资料因此需要与外部快递系统、WMS 发运数据形成可核对的接口链路。电子面单、交接清单、揽收扫描记录和异常件登记是日常文档，更新频率为每批与每日。这些材料在 HTTP 接口环节的核对重点是：请求是否把正确的面单号、交接批次和供应商标识传给外部系统，以及返回值是否被正确解析回本系统。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 用于路径参数，Body 用于 POST/PUT 请求体，Headers 传递鉴权等信息。URL、Params、Headers、Body 均可通过 `{{}}` 引用全局变量、系统变量或前方节点输出。返回值需要配置 key 并通过 JSON path 语法提取，输出类型选择字符串时会将对应值转为 JSON 字符串。chatId 与 responseChatItemId 在测试模式下不存在，调试时这两项为空属于已知条件，不能当作业务故障处理。对话接口的鉴权使用 APIKey，推荐在请求体传入 `body.appId`；`model`、`temperature` 等字段由编排决定，API 参数不改变它们。

假设演练样本

供核对的材料原文：某仓库发运组于 2025 年 3 月 10 日生成交接清单，批次号 JC-20250310-01，含电子面单 40 张，对应供应商编号 GYS-017，交接状态栏填写“待揽收”。同批次异常件登记表记录 1 件面单打印模糊，处理状态“待重打”。

待判定的拟稿句：“该批次已完成揽收交接，供应商 GYS-017 的 40 件包裹全部由承运商扫描确认。”

## 配置怎么定

| 配置项 | 本页对应设置 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部快递系统接口文档选择，地址可引用变量 | 对照接口文档确认路径与 HTTP 方法一致 |
| Params 与 Headers | 路径参数与请求头分别填写，鉴权凭证通过安全配置注入 | 核对实际传入值，确认凭证不出现在公开样例 |
| Body | 仅在对应请求类型下使用，核对 JSON 结构与外部接口契约 | 对照契约逐字段检查，确认 `{{}}` 引用变量已定义 |
| 变量引用 | 可引用全局变量、系统变量、前方节点输出 | 逐项核对变量来源与前端节点输出名称一致 |
| 返回值提取 | 配置 key 并按 JSON path 提取，输出类型按需选择 | 用接口响应示例比对提取结果与预期字段 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 测试模式下为空时记录为已知条件，不判为故障 |

本次假设试验起点：将返回值 key 设为 `data.list[0].status`，输出类型选字符串。选择该路径是因为接口响应示例中 `data.list` 为数组，需取首元素状态字段；与接口文档给出的提取示例 `$.data.list[0]` 比较，确认语法一致。

## 容易做错的三处

1. 把“待揽收”交接清单当作已完成揽收。材料原文中交接状态栏为“待揽收”，异常件登记表有 1 件“待重打”，拟稿句却写“已完成揽收交接”“全部由承运商扫描确认”。输入是交接清单状态栏与异常件登记表，比较对象是拟稿句中的完成性表述，观察结果是状态栏文字与拟稿句不一致。
2. 把测试模式下 chatId 为空当作接口故障。输入是测试模式请求，比较对象是文档说明“测试模式下不存在”，观察结果是该字段为空属于已知条件，不能据此判定外部系统异常。
3. 把 HTTP 模块返回值提取的 key 写成接口原始字段名。输入是配置的 key，比较对象是文档中“从 FastGPT 转化后的格式获取”的说明，观察结果是 key 需按转化后结构填写，直接写原始嵌套路径可能取不到值。

## 怎么确认配好了

1. 用假设样本的交接清单原文核对拟稿句。输入：批次 JC-20250310-01 交接清单状态栏“待揽收”与异常件登记表“待重打”1 件。比较：拟稿句“已完成揽收交接”“全部由承运商扫描确认”。满足条件：拟稿句与材料状态一致，或明确标注为待核实。
2. 用假设样本核对 HTTP 请求的变量引用。输入：请求中引用的面单号、批次号、供应商编号变量。比较：全局变量、系统变量或前方节点输出中是否已定义同名变量。满足条件：每个 `{{}}` 引用均有对应已定义变量，且实际传入值与交接清单一致。
3. 用接口响应示例核对返回值提取。输入：key 配置为 `data.list[0].status`，输出类型选字符串。比较：接口响应中 `data.list[0]` 是否存在 `status` 字段。满足条件：提取结果与响应中该字段值一致；若字段不存在，记录为提取失败并保留原始响应待查。
