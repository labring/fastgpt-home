# 批发市场档口交易的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

批发市场档口交易的库存采购与供应商资料，围绕进货单、手写销售单、摊位租赁合同、货款收据展开。档口交易零散，现场议价与托运安排占去大量时间，货款拖欠、错发漏发、市场纠纷是常见后果。数据来源包括批发市场行情、档口库存、微信收款、物流托运单，更新频率为日与每单。这些特征意味着定时任务与自动化要处理的输入往往来自人工填写的单据和外部接口返回值，格式不统一，字段缺失常见。库存采购与供应商资料这一任务，需要把进货单的商品、数量、供应商信息与货款收据的金额、日期对应起来，核对供应商资料是否完整。定时任务与自动化在此环节的作用，是按既定时间点触发数据读取或请求发送，把分散的单据信息汇总到可核对的记录中。触发本身不建立业务系统连接，外部数据须由已配置接口读取。

## 这些特征在「定时任务与自动化」这一环带来什么约束

定时任务与自动化的触发责任需要明确：由应用定时能力触发，还是由外部调度触发，须按实际版本核对可用入口。HTTP 请求按外部接口文档核对方法、请求头、请求体及变量输入。去重、幂等与业务写入需在接口或后续流程明确设计，不能宣称自动具备。执行记录要核对触发时间、真实输入、返回结果与业务状态，任务存在不能替代执行成功。

假设演练样本：某档口有一份手写销售单，原文为“2025年3月12日，售予采购商刘某，螺纹钢HRB400直径20毫米，数量12吨，单价按当日市场价，货款未付，约定3月20日前结清”。另有一份货款收据，原文为“2025年3月18日，收到刘某货款人民币肆万贰仟元整，对应3月12日销售单”。一条待判定的拟稿句为：“系统定时任务将于3月20日自动向刘某发起尾款催收，并同步更新供应商资料中的欠款状态。”该拟稿句涉及自动发起催收与自动更新状态两项业务动作，材料中未载明授权或生效条款，须保留证据缺口。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对与比较方法 |
| --- | --- | --- |
| 触发入口 | 使用应用定时能力 | 按实际版本核对可用入口，与外部调度方式区分 |
| HTTP 请求方法 | POST | 对照外部接口文档确认方法、请求头、请求体 |
| 请求体变量 | 引用前方节点输出的进货单编号 | 按 `{{key}}` 语法核对变量来源与解析结果 |
| 返回值提取 | 配置 `key` 为 `data.user.name` | 按 JSON path 语法核对提取值，输出类型选字符串 |
| 执行记录字段 | 记录触发时间、真实输入、返回结果 | 与业务状态逐项比较，确认是否一致 |
| 重复触发处理 | 在接口或后续流程明确设计 | 核对去重与幂等设计，不假定自动具备 |

本次假设试验起点选择 POST 方法，理由是外部接口文档标注创建记录使用 POST；选择 `data.user.name` 作为提取键，理由是该路径在文档提取示例中出现。这些起点为本次假设，不代表官方默认值。

## 容易做错的三处

1. 把定时任务存在当作执行成功。输入为任务列表中的一条定时任务，比较对象为执行记录中的触发时间与返回结果，观察结果是任务存在但无对应执行记录或返回为空，此时不能判定执行成功。
2. 把检索或表单当作授权执行。输入为一条待判定的拟稿句，比较对象为材料原文中的授权或生效条款，观察结果是材料未载明授权条款，此时拟稿句中的自动催收与自动更新状态属于未获支持。
3. 把 HTTP 返回值提取键写成不存在的路径。输入为接口响应示例，比较对象为配置的 `key` 与响应中的实际字段，观察结果是配置的键在响应中无对应值，此时提取结果为空，须核对字段名。

## 怎么确认配好了

- 验证一：输入假设演练样本中的手写销售单原文与货款收据原文，比较两份材料中的主体、日期、金额、对应关系，观察结果是两份材料在主体与对应关系上一致，但尾款结清状态未载明，此时保留证据缺口。

- 验证二：输入待判定的拟稿句“系统定时任务将于3月20日自动向刘某发起尾款催收，并同步更新供应商资料中的欠款状态”，比较拟稿句中的自动动作与材料原文中的授权条款，观察结果是材料未载明授权自动催收或自动更新状态的条款，此时该拟稿句未获支持。

- 验证三：输入配置的返回值提取键 `data.user.name` 与文档中的接口响应示例，比较该键与响应中的实际字段路径，观察结果是该路径在示例中存在对应值，提取结果与示例一致；若配置的键在响应中无对应字段，提取结果为空，须核对字段名后重新配置。
