# 批发市场档口交易的库存采购与供应商资料：引用来源与溯源

## 这个品类的数据长什么样

批发市场档口交易的库存采购与供应商资料，围绕进货单、手写销售单、摊位租赁合同、货款收据四类材料展开。交易零散，现场议价与托运安排并行，数据来源包括批发市场行情、档口库存、微信收款和物流托运单。日常更新频率为日更与每单更新。这些特征直接影响引用来源与溯源：同一批进货可能只有手写单据，同一笔货款可能只有微信收款记录，摊位租赁合同与货款收据分属不同主体和期间。引用来源需要逐条对应到具体材料，材料缺失时保留缺口。

## 这些特征在「引用来源与溯源」这一环带来什么约束

知识库搜索节点可关联一个或多个相同向量模型的知识库，输出引用内容为数组，长度可以为 0。空数组意味着没有搜索到内容，该输出链路仍走通。检索结果需要交给回答环节，再逐条核对回答与引用原文。语义召回和相关度不负责权限或实体隔离，检索库同向量模型要求不能扩展为外部系统也要同模型。跨不同向量模型的库不可共同关联，先核标识并排除不符合者。文档总流程图列出的可选路径不代表每次请求全部执行，图片检索须有相应图像输入及模型能力，重排须具备模型且按设置启用。

假设演练样本：某档口老板提交一份进货单原文，内容为“2026年3月12日，向兴隆干果批发行采购核桃50件，单价每件120元，货款收据编号SJ-0312，约定3月20日前结清”。同时提交一条待判定拟稿句：“该供应商资料已通过审核，可用于后续采购引用。”另有一条交接请求：“请将上述进货单和货款收据加入供应商资料库，并标记为已审核。”材料原文含主体、对象、日期、数量和金额，拟稿句涉及审核状态，交接请求涉及入库和标记动作。审核是否完成、入库是否执行，均需另接系统实现，检索或表单不构成授权执行。

## 配置怎么定

| 配置项 | 本页相关设置或核对项 | 与样本的关联 |
| --- | --- | --- |
| 关联的知识库 | 选择一个或多个相同向量模型的知识库 | 核对进货单与货款收据所在库的向量模型标识是否一致 |
| 搜索模式 | 语义检索、全文检索或混合检索 | 样本含编号SJ-0312，全文检索可核对编号命中 |
| 引用上限 | 每次搜索最多引用 n 个 tokens 的内容 | 本次假设试验起点设为 2000 tokens，理由为单条进货单加收据原文长度，与默认值比较后调整 |
| 最低相关度 | 0-1 数值，仅在语义检索或结果重排时生效 | 本次假设试验起点设为 0.5，用于观察样本拟稿句是否被召回 |
| 结果重排 | 利用 ReRank 模型二次排序 | 样本候选较多时启用，按设置核对重排得分 |
| 引用内容输出 | 数组格式，长度可以为 0 | 用纸面输入[]核对空结果下游承接设计 |

## 容易做错的三处

1. 将检索输出直接当作审核完成。样本中拟稿句写“已通过审核”，检索只能返回进货单和收据原文，审核状态需另接系统实现。核对输入为拟稿句与原文，比较审核字段是否在原文中出现，观察结果为原文未载明审核状态，判定为待核实。
2. 将交接请求当作入库执行。样本请求写“加入供应商资料库并标记为已审核”，表单收集值，数据库写入和标记动作需下游实现。核对输入为请求文本与当前库记录，比较请求动作与已执行动作，观察结果为请求处于待处理状态，不构成已入库或已审核。
3. 将跨向量模型库强行共同关联。样本中进货单库与收据库若向量模型标识不同，不可共同关联。核对输入为两库的向量模型标识，比较标识是否一致，观察结果为标识不一致时排除该库，不执行跨模型检索来比较漏召回。

## 怎么确认配好了

1. 用样本进货单原文与拟稿句测试引用来源。输入为进货单原文和拟稿句，比较回答中的引用是否逐条对应原文主体、日期、数量和金额，观察结果为引用条目与原文一致且审核状态标注为待核实，满足条件。
2. 用纸面输入[]测试空结果承接。输入为明确的空数组，比较下游节点是否继续执行且不报错，观察结果为输出链路走通且无引用内容，满足条件。
3. 用样本交接请求测试授权边界。输入为交接请求文本，比较请求动作与当前系统状态，观察结果为请求标记为待处理，未出现入库或审核完成记录，满足条件。
