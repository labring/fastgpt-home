# 抖音小店货架运营的库存采购与供应商资料：工作流编排

## 这个品类的数据长什么样

在抖音小店货架运营的库存采购与供应商资料中，本页说明FastGPT的工作流编排如何衔接资料。供应资料里的外盒可供与内托待确认分开传递，采购路径不自动生成供货承诺。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟供应清单说外盒可供、内托方案尚待确认，商品草稿却想介绍整套包装。工作流先读清单与草稿所指商品，分别整理已给信息和缺项，再决定请求内托资料或继续核外盒说明。供应商名称相同不证明部件都在范围内；可供文字也未提供本批库存或交期。下一节点需收到具体部件和当前阶段，不能只传一段完整包装摘要。

## 配置怎么定

| 供应资料路径 | 清单内容 | 核验动作 |
| --- | --- | --- |
| 外盒 | 文字可供 | 不补库存 |
| 内托 | 方案待确认 | 单列缺项 |
| 商品身份 | 清单与草稿 | 核对应 |
| 补证分支 | 请求资料 | 不冒采购 |
| 正式业务 | 询价下单另接 | 权限与回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

外盒可供扩给内托时，核部件范围；供应说明冒本批现货时，查实际库存依据；请求补证路径被回复为采购已确认时，核正式确认记录。三处分别看对象、现实状态和业务动作。

## 怎么确认配好了

验收分别问外盒支持什么、内托缺什么以及本批是否有凭证，对照每环实际输入。补新方案先核商品再更新缺项。询价、下单、库存读取和采购批准需各自实现权限与回执，流程有返回不建立供货关系。 采购核对表分别列外盒可供说明和内托待定信息，任何整套包装的表述都需查齐对应组件资料后再决定。
