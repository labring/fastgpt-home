# 抖音小店货架运营的库存采购与供应商资料：文档解析与分块

## 这个品类的数据长什么样

抖音小店货架运营围绕商品卡与店铺体验分展开，日常材料包括商品资质页、体验分明细、发货违规申诉与店铺公告。库存采购与供应商资料属于其中一类：供应商资质文件、采购确认记录、供货状态说明与授权范围说明。这些材料的更新频率为日或每单，来源为抖店工作台、抖音电商学习中心、精选联盟数据与物流接口。资料结构差异明显：资质页含主体名称、证件编号与有效期；采购记录含商品、数量、日期与状态；供货说明含承诺范围与生效条件。解析与分块需要保留这些字段与所约束内容之间的对应关系，分块过粗会混入无关字段，分块过细会拆散条件与结论。

## 这些特征在「文档解析与分块」这一环带来什么约束

FastGPT 的知识库由库、集合和数据三层组成，最小搜索单位是库，集合仅作分类管理。向量存储采用 PostgresSQL 的 PG Vector 插件，索引为 HNSW，MongoDB 的 dataset.datas 表保存原数据，indexes 字段记录对应向量 ID，一组数据可对应多个向量。检索时先召回向量，再按向量 ID 回 MongoDB 找原数据，同一组原数据合并后取最高得分。多向量映射用于兼顾内容长度与语义丰富度。检索方案包含问题优化、语义检索、全文检索或混合检索、RRF 融合、ReRank 二次排序，最后经相似度过滤与引用上限裁剪。引用上限以 tokens 为单位，最低相关度仅在语义检索或结果重排时生效，该值是过滤阈值，不承担权限或实体隔离。跨不同向量模型的库不可共同关联，需先核对标识并排除不符合者。图片检索要求存在图像输入与相应模型能力，重排要求具备模型并按设置启用。

## 配置怎么定

以下为假设演练样本，用于说明核对方式，不代表真实记录或已执行测试。

假设演练样本：某供应商资质页原文三句——“主体名称：星海日用品商行。统一社会信用代码：91330100MA2XXXXX7B。本页所列供货范围为厨房清洁类商品，有效期待核，未见签署日期。”另一份采购确认记录原文：“商品：厨房清洁剂；数量：200箱；下单日期：2025年3月10日；状态：待供应商确认。”待判定拟稿句：“星海日用品商行已确认本次200箱厨房清洁剂供货。”

| 核对项 | 本页相关设置或核对内容 | 与假设样本的对应 |
| --- | --- | --- |
| 分块边界 | 按资料结构切分，保留条件与所约束内容同块 | 资质页主体、编号、供货范围同块 |
| 多向量映射 | 一组数据可对应多个向量，按标注提高精度 | 采购记录可按商品与状态分别建索引 |
| 引用上限 | 以 tokens 为单位的引用上限 | 本次假设起点设为较低值，便于观察裁剪现象 |
| 最低相关度 | 仅语义检索或结果重排时生效的过滤阈值 | 本次假设起点设为中间值，与不同取值比较 |
| 检索模式 | 语义检索、全文检索、混合检索可选 | 编号类字段适合全文或混合检索 |
| 更新后复核 | 上传成功不等于检索已更新，需核对训练与索引状态 | 资质页变更后须复核实际索引 |

## 容易做错的三处

1. 把上传成功当作检索已更新。输入为新版资质页上传记录，比较上传时间与检索返回内容，观察返回内容仍为旧版字段时说明索引未更新。
2. 把待供应商确认当作已确认供货。输入为采购确认记录中“状态：待供应商确认”，比较拟稿句“已确认本次200箱供货”，观察两者状态字段不一致时判定拟稿句未获支持。
3. 把最低相关度当作权限过滤。输入为最低相关度设置值，比较该设置与访问控制配置，观察设置中不存在主体或权限字段时说明该值不承担权限隔离。

## 怎么确认配好了

1. 输入假设样本中资质页原文与拟稿句“星海日用品商行已确认本次200箱厨房清洁剂供货”，比较拟稿句所述确认事实与原文中“状态：待供应商确认”，观察原文未载明确认主体与确认日期时，判定该拟稿句为未获支持，记录证据缺口。
2. 输入假设样本中采购确认记录原文，比较“下单日期：2025年3月10日”与“状态：待供应商确认”是否属于同一字段，观察日期与状态分属不同字段时，不将日期作为确认时间的证据。
3. 输入假设样本中资质页“有效期待核，未见签署日期”，比较该表述与任何关于授权生效的推断，观察原文未载明有效期与签署日期时，保留为待核实，不补造授权或生效条款。空结果情形可用纸面输入[]核对下游设计，不声称虚构规则检索一定返回[]。
