# 拼多多低价活动店铺运营的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

拼多多低价活动的采购资料核活动报名表、成本测算表、售后退款单及站内信，来源包括商家后台、ERP库存与物流签收，按日或每场活动更新。接口映射要分别核供应商、料号、报名数量和采购状态；字段缺失时先记缺口，不能预设具体响应或错误。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块可重复添加、手动配置、触发执行，向对应地址发送请求，用法与 Postman、ApiFox 接近。Params 为路径请求参数，GET 请求中用得居多；Body 为请求体，POST/PUT 请求中用得居多；Headers 为请求头，用于传递特殊信息。三种数据均可通过 `{{}}` 引用变量，URL 也可引用变量，变量来自全局变量、系统变量与前方节点输出。系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories（默认最多取 10 条，无法修改长度）。返回值通过 JSON path 语法提取，输出类型选择字符串时会把对应 key 的值转成 json 字符串。

chatId与responseChatItemId是会话系统变量，测试模式下不存在。FastGPT对话API的APIKey、appId、detail与authProxy规则按该API另核，不能用于推定外部ERP的鉴权契约。

假设演练样本：某拼多多店铺活动运营在 2026 年 3 月 10 日整理一份供应商资料，原文为「供应商甲，料号 A-100，活动报名数量 800 件，采购单号 CG-0310-01，状态：待供应商确认。」同日拟向外部 ERP 发起一条 HTTP 请求，请求体拟写为 `{"supplier":"供应商甲","sku":"A-100","qty":"{{活动数量}}","po":"CG-0310-01"}`，其中变量「活动数量」在当前节点输出中未提供。待判定：该请求是否具备可执行的字段依据与授权状态。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址与方法 | 按外部 ERP 接口文档填写，地址可引用变量 | 与外部接口契约逐字段比对，确认路径与方法一致 |
| Params 与 Headers | 鉴权机制及字段待真实ERP契约确认 | 凭证按安全配置提供，不写实际密钥 |
| Body 结构 | 所列supplier、sku、qty、po为演练拟议键名 | 真实字段及类型待契约确认，逐项核变量绑定 |
| 变量引用 | 仅引用全局变量、系统变量、前方节点输出 | 核对「活动数量」是否在可用变量列表中 |
| 返回值提取 | 按 JSON path 语法配置 key 与输出类型 | 用接口响应示例比对提取结果，输出类型选字符串时转 json 字符串 |
| 调试身份字段 | chatId、responseChatItemId 在测试模式下不存在 | 测试模式空值不记为业务故障 |

## 容易做错的三处

1. 把未绑定变量当成已知接口故障。核拟稿Body与可用变量列表，当前没有「活动数量」，先记绑定缺口；保留 `{{活动数量}}` 合法语法，不能在未运行时断言将发送空值、原文本或某种报错。
2. 把待确认状态当成已授权执行。样本原文状态为「待供应商确认」，输入为原文状态字段与拟发出的请求，比较对象为状态取值与执行条件，可观察结果为状态未载明确认完成，请求不具备执行依据。
3. 把检索结果当成权限依据。HTTP 模块可对接外部数据源，但检索或表单收集不构成授权，输入为请求发起动作与授权状态字段，比较对象为是否有明确授权记录，可观察结果为无授权记录时该请求停留在待核实状态。

## 怎么确认配好了

1. 输入原拟稿JSON与变量列表，核「活动数量」的绑定及qty类型。原文800件是活动报名数量，不自动等于已确认采购量；变量与真实ERP契约未给，先补依据。请求前校验及拦截需另实现，不能声称HTTP节点会自动阻止发送。
2. 针对样本原文状态「待供应商确认」，输入为原文状态字段与拟执行动作，比较状态取值与执行条件，当状态未载明确认完成时判定为未获支持，保留证据缺口。
3. 待取得真实ERP响应样例后，核JSON path是否存在及提取值、输出类型是否符合下游约定。当前无响应样例，解析结果待核，不以所配key推定接口已返回该字段。

以上判定均以纸面样本为对象，未实际调用接口，未产生部署、审批或退款等业务动作。空结果承接可用明确的纸面输入核对下游设计，不声称虚构规则检索一定返回空数组。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，不执行跨模型检索比较漏召回。
