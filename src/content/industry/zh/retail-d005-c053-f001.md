# 渠道应收账款催收的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

渠道应收账款催收发生在赊销之后，核心是授信与现金回收。库存采购与供应商资料这一任务，需要把经销商的采购订单、供应商供货记录与应收账龄表放在同一批材料里核对。主要数据来源包括财务系统、银行回单、经销商订单和销售合同，日常文档涵盖应收账龄表、催款函、授信协议和发货冻结通知。数据更新频率为周或月，这一节奏决定了接口调用以批量核对为主，不要求实时触发。

HTTP 模块向对应地址发送请求，操作方式与 Postman、ApiFox 这类工具接近。Params 为路径请求参数，GET 请求中居多；Body 为请求体，POST/PUT 请求中居多；Headers 为请求头。三者均可通过 `{{}}` 引用变量，URL 也可引用变量。变量来自全局变量、系统变量和前方节点输出。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

库存采购与供应商资料的核对，需要调用外部数据源获取供应商供货记录或采购订单状态。HTTP 模块可以重复添加、手动配置、触发执行，属于核中核模块。系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories，其中 histories 默认最多取 10 条，无法修改长度。chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 语法提取，输出类型选择字符串时会将对应 key 的值转成 json 字符串。

假设演练样本：某品牌财务人员整理一份纸面材料，内容为“供应商甲与经销商乙于 2025 年 3 月签订授信协议，约定授信额度 50 万元，账期 60 天。截至 2025 年 6 月 30 日，经销商乙应收账龄表显示逾期金额 12 万元，账龄 45 天。”拟判定句为“该经销商已触发发货冻结条件”。授信协议未载明冻结触发条款，账龄表未载明冻结状态，此判定属于未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址 | 外部供应商接口文档给出的地址 | 与文档比对地址与方法 |
| Params | 按外部接口契约填写路径参数 | 逐项核对实际传入值 |
| Headers | Authorization 通过安全配置注入 | 不在公开样例写入凭证 |
| Body | 仅在 POST/PUT 下使用 | 核对 JSON 结构与契约 |
| 变量引用 | 引用前方节点输出或全局变量 | 核对 `{{key}}` 实际取值 |
| 返回值提取 | 配置 key 按 JSON path 提取 | 核对输出类型与解析结果 |

本次假设试验起点选 50 万元授信额度与 60 天账期，原因是样本材料明确载明这两个数值，比较对象为账龄表显示的逾期金额 12 万元与账龄 45 天。该起点属于样本给定值，不是官方默认值。

## 容易做错的三处

1. 把测试模式下不存在的 chatId 或 responseChatItemId 空值当成业务故障。输入为测试模式请求，比较对象为文档说明的“测试模式下不存在”，观察结果是空值属于预期现象。
2. 把返回值提取的 key 与接口响应字段混为一谈。输入为配置的 key，比较对象为 JSON path 提取规则，观察结果是提取值与响应示例中对应字段一致。
3. 把拟判定句中的“触发发货冻结”当成已执行。输入为假设样本材料，比较对象为授信协议与账龄表原文，观察结果是两份材料均未载明冻结条款或冻结状态，判定不成立。

## 怎么确认配好了

1. 输入假设样本中的授信协议原文与账龄表原文，比较拟判定句“该经销商已触发发货冻结条件”与原文是否载明冻结触发条款及冻结状态，观察结果为两份材料均未载明，判定为未获支持。
2. 输入一条待判定的交接请求“请确认供应商甲的供货记录是否已同步至采购台账”，比较请求中的主体、对象与材料范围，观察结果为材料未提供供货记录同步状态，该请求属于待核实。
3. 输入假设样本中“授信额度 50 万元、账期 60 天”与“逾期金额 12 万元、账龄 45 天”，比较同一字段的取值是否互斥，观察结果为两组数值属于不同字段，不构成矛盾，逾期事实成立而冻结事实未获支持。

检索与相似度不负责权限或实体隔离，不能把相似度设置当成排除未授权记录的手段。空结果可用明确的纸面输入 `[]` 核对下游设计，不能声称检索一定返回空数组。交互节点返回的 interactive 只包含 type 和 params，entryNodeIds 等内部运行态字段不返回。
