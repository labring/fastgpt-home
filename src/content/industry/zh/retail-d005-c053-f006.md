# 渠道应收账款催收的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样
渠道应收账款催收发生在赊销之后，核心数据围绕授信与现金回收展开。财务系统提供应收账龄表，银行回单反映实际到账，经销商订单与销售合同构成发货与赊销依据，授信协议约定额度与账期，发货冻结通知记录超授信处置。典型主体包括品牌财务、销售内勤与经销商老板。资料给出的更新频率为周与月，本页不据此推出批量同步或实时触发机制。

## 这些特征在「定时任务与自动化」这一环带来什么约束
定时任务与自动化在本品类中承担按周期读取外部数据、发出请求并记录结果的角色。触发责任需明确由应用定时能力还是外部调度承担，并按实际版本核对可用入口。外部数据由已配置接口读取，定时触发本身不建立业务系统连接。HTTP 请求按外部接口文档核对方法、请求头、请求体及变量输入。去重、幂等与业务写入需在接口或后续流程明确设计。执行记录核对触发时间、真实输入、返回结果与业务状态，任务存在不能替代执行成功。检索或表单收集值不等于授权执行，授信审批、冻结发货、数据库写入与外部同步均需各自的下游实现。

假设演练样本：某品牌财务留存一份授信协议原文，写明“经销商甲授信额度五十万元，账期三十日，额度用尽后暂停发货”。同批留存一份账龄表原文，写明“截至假设日期，经销商甲应收余额四十八万元，其中逾期十日金额八万元”。拟判定句为“经销商甲已超授信，应自动冻结发货”。该请求涉及授信状态判断与发货冻结，属于需业务系统实现的动作，本页只核对材料与请求的对应关系。

## 配置怎么定
下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值仅为本次假设试验起点，用于与样本原文比较，不代表官方默认值。

| 配置项 | 本次假设起点 | 核对对象与理由 |
| --- | --- | --- |
| 触发责任 | 应用定时能力 | 与样本周期核对，确认由哪一侧发起 |
| 请求方法 | POST | 与外部接口文档核对，Body 在 POST 下生效 |
| 请求体字段 | 账龄表标识与授信协议标识 | 与样本两份材料标识核对，确认引用变量来源 |
| 变量引用 | 全局变量或前方节点输出 | 与样本字段名核对，Body 中字符串需加引号 |
| 返回值提取 | JSON path 提取余额字段 | 与接口响应结构核对，输出类型选字符串时转 json 字符串 |
| 执行记录 | 触发时间、输入、返回结果 | 与样本日期范围核对，任务存在不替代执行成功 |

## 容易做错的三处
1. 把定时触发当作业务系统连接已建立。样本中授信协议与账龄表为纸面材料，触发执行不产生读取动作，需核对接口是否已配置。
2. 把拟判定句当作已获支持的结论。样本原文只给出额度、账期、余额与逾期金额，未载明授信状态字段，超授信判断属于待核实。
3. 把请求发送当作冻结发货已执行。样本请求指向发货冻结，该动作需业务系统实现，请求本身不构成执行。

对应检查：第一项检查触发责任配置与样本周期是否一致，观察是否存在未配置接口即触发的记录。第二项检查拟判定句引用的字段是否在样本原文中出现，观察超授信字段是否缺失。第三项检查请求返回结果与业务状态，观察冻结发货是否另有执行记录。

## 怎么确认配好了
- 验证一：输入样本授信协议原文与账龄表原文，比较拟判定句“经销商甲已超授信，应自动冻结发货”所引用的字段。样本原文含额度、账期、余额、逾期金额，未含授信状态字段，该判定句未获支持，应记录证据缺口。

- 验证二：输入样本请求，比较请求体字段与两份材料标识。请求体引用账龄表标识与授信协议标识，若返回值提取的 JSON path 指向余额字段，则提取结果与样本余额四十八万元对应；若指向未出现字段，则提取为空，需核对接口响应结构。

- 验证三：输入样本触发时间与执行记录，比较任务存在与执行成功。记录需含触发时间、真实输入、返回结果与业务状态。若记录只有触发时间而无返回结果，执行状态待核实；若返回结果与样本材料不符，需核对输入变量来源。以上均为纸面核对，未实际运行。
