# 渠道窜货稽查的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样
窜货稽查围绕区域与价格秩序展开，处理对象是防伪码记录、经销商发货记录、电商平台价格与市场巡检材料，不涉及返利金额核算。日常文档包括窜货投诉单、处罚通知与调查照片，更新节奏为周或不定期。库存采购与供应商资料这一主任务要回答的是：某批货的采购来源、供应商主体与授权范围是否与稽查材料一致。HTTP 接口在此承担的是把外部系统的查询结果取回编排，供后续人工核对使用，它本身不完成授权判定。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
外部接口按自身文档选择请求地址与方法，地址可通过 {{}} 引用变量。Params、Headers、Body 分别核对，鉴权凭证经安全配置注入。变量来自全局变量、系统变量与前方节点输出，需逐项核对实际传入值。chatId 与 responseChatItemId 在测试模式下不存在，调试空值属于正常现象。返回值通过 JSON path 提取，出参格式化后可作为后续节点输入。接口取回的是数据，业务授权、审批与数据库写入仍需下游实现。

假设演练样本：某品牌渠道管控团队收到一份窜货投诉单，原文为“投诉对象：华东区经销商甲；涉及产品：批次 A 系列；投诉事由：该批次在华南区电商店铺低价销售；附件：防伪码记录三页、调查照片两张”。另有一份供应商资料摘录：“供应商乙，供货区域：华东区，授权有效期至 2026 年 3 月”。待判定的拟稿句为：“供应商乙的供货授权覆盖华南区销售。”该句与原文载明的供货区域不一致。

## 配置怎么定
下表围绕上述样本，列出与本功能、主任务相关的核对项。数值为本次假设试验起点，非官方默认值。

| 核对项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址 | 外部供应商资料接口地址 | 按该接口文档确定，与投诉单载明的供应商主体对应 |
| 请求方法 | POST | 按接口文档的查询语义选择，与只读查询目的相符 |
| Headers 鉴权 | Authorization 经安全配置注入 | 与接口文档要求比对，凭证不写入公开样例 |
| Body 字段 | 供应商名称、批次号 | 与投诉单和供应商资料摘录中的字段名逐项比对 |
| 变量引用 | {{supplierName}}、{{batchNo}} | 与前方节点输出核对，确认实际传入值非空 |
| 返回值提取 | 按接口响应结构配置 JSON path | 与接口实际响应结构比对，确认取到供货区域字段 |

## 容易做错的三处
1. 把接口返回的供应商记录直接当作授权结论。样本中供应商乙供货区域为华东区，接口取回该字段只说明数据存在，授权范围判定仍需人工比对投诉单与供应商资料。
2. 把测试模式下 chatId 为空当成接口故障。文档说明测试模式下该字段不存在，需区分调试空值与业务数据缺失。
3. 把 JSON path 提取到的字符串直接拼入结论句。样本拟稿句“授权覆盖华南区”与原文“供货区域：华东区”在同一字段上取值互斥，属于未获支持，需回到原文核对。

## 怎么确认配好了
1. 输入样本投诉单原文与供应商资料摘录，比较接口返回的供货区域字段与原文载明的“华东区”，观察两者是否一致。若返回华南区，记录该差异并保留原文，不据此认定授权成立。
2. 输入拟稿句“供应商乙的供货授权覆盖华南区销售”，比较其与原文“供货区域：华东区、授权有效期至 2026 年 3 月”，观察拟稿句是否获得原文支持。该句在同一字段上与原文取值互斥，判定为未获支持。
3. 输入空结果场景，以纸面输入 [] 核对下游节点设计，观察下游是否对空结果做显式处理。检索或接口返回空结果不表示授权缺失，仅表示本次未取到数据，需记录缺口并转人工核对。
