# 特许加盟备案管理的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样
特许加盟备案管理处理法律披露与商务部门系统对接，不处理具体铺位工程。库存采购与供应商资料属于备案材料与信息披露文件中的经营资源证明部分，通常来自企业证照、门店清单、合同台账与供应商合同。这些资料的主体是特许人总部，对象是采购批次、供应商资质与供货状态。资料更新频率为不定期或按年，本页不据此推出批量同步或实时触发机制。HTTP 接口在此环节的作用是把外部供应商系统或商务部门系统的返回值解析为可核对的字段，供备案材料引用。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params 为路径请求参数，Body 为请求体，Headers 为请求头。三种数据均可通过 {{}} 引用变量，变量来自全局变量、系统变量与前方节点输出。返回值通过 JSON path 语法提取，输出类型选择字符串时会将对应 key 的值转为 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试空值不能当成业务故障。对话接口的 model、temperature 等参数字段无效，由编排决定。插件调用无需传入 chatId 与 messages，通过 variables 传输入，通过 pluginOutput 取输出。

假设演练样本：某特许人总部备案专员在 2025 年 3 月整理库存采购资料，供应商合同台账载明“供应商甲，供货品类为门店耗材，合同有效期至 2025 年 12 月 31 日，当前状态为已签署”。拟稿句为“供应商甲供货期限覆盖本年度备案期间”。待判定：合同有效期与供货期限属于不同字段，拟稿句将有效期直接等同于供货期限，缺少供货期限的独立证据。该判定属于本页主任务，即核对资料字段与外部接口返回值是否一致。

## 配置怎么定
以下设置围绕上述样本，仅列官方已说明项或实施核对项。数值为本次假设试验起点，说明选择理由与比较对象。

| 配置项 | 本次假设起点 | 核对说明 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址可引用变量 | 与供应商系统文档逐项比对 |
| Headers 鉴权 | Authorization 使用 Bearer {{token}} | 核对凭证注入方式，不写入公开样例 |
| Body 结构 | 仅在 POST/PUT 下使用，按接口契约写 JSON | 与供应商接口字段名逐一比对 |
| 返回值提取 | 按 JSON path 配置 key | 与接口响应实际结构比对 |
| 输出类型 | 字符串，用于后续文本加工 | 与下游节点输入要求比对 |
| chatId 使用 | 测试模式下不存在，不填入 | 与测试模式说明比对 |

## 容易做错的三处
1. 把合同有效期字段直接当作供货期限。错误在于两个字段不同，输入是样本中的合同台账原文，比较对象是拟稿句，观察结果是拟稿句缺少供货期限的独立证据。
2. 把测试模式下不存在的 chatId 当成业务故障。错误在于测试模式说明明确该字段不存在，输入是测试模式请求，比较对象是系统变量说明，观察结果是该字段为空属于预期。
3. 把 HTTP 返回值提取的 key 当成接口返回值本身。错误在于返回值代表如何解析接口响应，输入是 JSON path 配置，比较对象是接口响应示例，观察结果是 key 提取的是转化后格式的值。

## 怎么确认配好了
1. 使用样本原文核对拟稿句。输入为合同台账原文与拟稿句，比较对象为合同有效期与供货期限两个字段，观察结果是拟稿句未获供货期限证据支持，记录为待核实。
2. 使用测试模式请求核对 chatId 字段。输入为测试模式下的请求，比较对象为系统变量说明中 chatId 在测试模式下不存在，观察结果是该字段为空不构成业务故障，记录为预期现象。
3. 使用接口响应示例核对返回值提取。输入为文档中的接口响应示例与配置的 key，比较对象为 JSON path 提取结果，观察结果是提取值与示例一致，记录为通过。空结果承接可用明确的纸面输入 [] 核对下游设计，不声称虚构规则检索一定返回 []。
