# 生产企业免抵退税的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样
生产企业免抵退把内销税额抵减与退税合并计算，这一特征使库存采购与供应商资料同时进入两套口径：采购入库与供应商发票对应进项税额，出口销售与报关单对应免抵退税额。资料按月更新，日常处理免抵退税申报明细表、出口合同、销售明细账、出口报关单。库存采购与供应商资料在此承担归集自产出口与核对离岸价差异的底稿作用。定时任务与自动化只能读取已配置接口提供的数据，不能假定触发动作自动建立业务系统连接。

## 这些特征在「定时任务与自动化」这一环带来什么约束
触发责任需明确由应用定时能力还是外部调度承担，并按实际版本核对可用入口。外部数据由已配置接口读取。HTTP 请求按外部接口文档核对方法、请求头、请求体及变量输入，URL 与 Body 中的变量来自全局变量、系统变量或前方节点输出。去重、幂等与业务写入需在接口或后续流程明确设计。执行记录需核对触发时间、真实输入、返回结果与业务状态，任务存在不能替代执行成功。检索与相似度不承担授权或实体隔离功能。

## 配置怎么定
下表围绕本页主任务，列出官方已说明的设置或实施核对项。数值仅为本次假设试验起点，用于与人工核对结果比较。

| 配置项 | 官方已说明的设置或核对项 | 与库存采购供应商资料的关联 |
| --- | --- | --- |
| 触发入口 | 明确由应用定时能力或外部调度触发，按实际版本核对入口 | 决定采购与供应商资料何时被读取 |
| 请求方法 | 按外部接口文档核对 GET、POST、PUT、DELETE | 读取供应商发票与入库记录 |
| 请求头 | Headers 传递 Authorization 等特殊信息，可用 `{{token}}` | 访问受控的供应商资料接口 |
| 请求体 | 仅特定请求类型生效，引用字符串需加 `""` | 提交采购明细查询条件 |
| 返回值提取 | 通过 JSON path 语法提取，key 遵守 JS 对象取值规则 | 取出供应商名称、入库数量 |
| 执行记录 | 核对触发时间、真实输入、返回结果与业务状态 | 判断本次读取是否可用于申报底稿 |

## 容易做错的三处
1. 把任务存在当作执行成功。触发已配置，返回结果与业务状态未核对，采购与供应商资料是否真正读取仍未知。
2. 把检索命中当作授权放行。相似度分数不构成对供应商或采购记录的访问许可，权限需另有实现。
3. 把接口返回的字段直接写入申报底稿。返回值提取正确不等于业务写入与下游同步已完成。

对应三项可执行检查：
- 输入触发时间与接口返回原文，比较任务记录与业务状态字段，两者一致才满足核对条件。
- 输入检索请求与目标供应商范围，比较返回记录与授权清单，落在授权范围内才可继续。
- 输入提取后的字段值与人工底稿，比较同一字段同期间取值，一致才可进入下一步。

## 怎么确认配好了
以下为假设演练样本，仅用于核对方法，不代表真实记录。

假设演练样本：某出口生产企业，2024 年 3 月申报期，核对对象为供应商甲的一笔原材料采购。材料原文为：“供应商甲，采购合同编号 H-2024-03，入库日期 2024 年 3 月 12 日，数量 500 件，金额 20000 元，状态：已入库待开票。”拟判定句为：“该笔采购已取得供应商发票，可计入本期进项税额。”

- 验证一：输入材料原文与拟判定句，比较“已入库待开票”与“已取得发票”两个字段，状态未载明已开票时，该句未获支持。

- 验证二：输入接口返回的供应商名称与人工底稿名称，比较同一字段，名称一致才满足核对条件；名称缺失时记录缺口，不判定为冲突。

- 验证三：输入返回值提取配置与接口响应示例，比较提取 key 与响应结构，能取到目标字段才说明提取配置可用；接口报错或字段不存在时，记录实际观察，不推断失败原因。

以上检查均以纸面样本执行，未实际部署或调用任何接口。
