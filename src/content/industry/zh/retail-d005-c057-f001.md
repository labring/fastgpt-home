# 生鲜临期折价处理的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

临期折价处理围绕货架库存生命周期展开，数据来源包括 POS 库龄、门店巡检、ERP 库存和质检记录。日常文档为临期清单、折价审批、报损单和促销价签。这些材料按日或班次更新，用于识别临期批次、审批折价和隔离不可售商品。库存采购与供应商资料这一任务中，HTTP 模块承担与外部系统的数据交换，把临期清单、审批状态和供应商信息在系统间传递。资料给出的更新频率为日或班次，本页不据此推导批量同步或交易触发机制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params、Headers、Body 均可通过 `{{key}}` 引用全局变量、系统变量和前方节点输出，URL 同样可引用变量。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试期间取空值属于环境差异。返回值通过 JSON path 提取，输出类型选择字符串时会将对应值转为 json 字符串。对话接口以 APIKey 鉴权，appId 优先级为 body.appId、`<apiKey>-<appId>`、apikey 关联的 appId。传入的 model、temperature 字段由编排决定。detail=true 时返回 responseData，其中包含模块状态与完整结果。

假设演练样本：某门店 2025 年 6 月 10 日巡检记录原文为“冷柜 A 批次 20250608 酸奶 12 盒，保质期至 2025 年 6 月 13 日，状态：待折价审批”。同批材料另有一句“供应商资料：该批次由供应商 B 供货，合同编号未载明”。待判定的交接请求拟稿为“请将批次 20250608 折价审批结果同步至供应商 B 结算系统”。原文未载明该批次是否已获折价审批，也未载明供应商 B 结算系统的接口地址与授权范围，该请求的授权边界处于未获支持状态。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对对象与说明 |
| --- | --- | --- |
| 请求地址 | 按外部接口文档填写 | 地址可引用变量，核对是否指向目标系统 |
| 请求方法 | 按外部接口文档选择 | 与外部接口契约一致，不自行假定 |
| Headers 鉴权 | Authorization Bearer 引用 token 变量 | 凭证通过安全配置注入，不写入公开样例 |
| Body 结构 | 按外部接口 JSON 契约 | 仅在相应请求类型下生效 |
| 返回值提取 | 配置 key 与 JSON path | 核对提取值与外部响应字段对应 |
| 输出类型 | 字符串或按需选择 | 字符串会将对应值转为 json 字符串 |

以上起点为本次纸面核对所设，用于与外部接口文档逐项比对，不作为官方默认值。

## 容易做错的三处

1. 把测试模式下 chatId 取空值当成业务故障。该字段在测试模式不存在，需与正式环境请求区分核对。
2. 把待折价审批状态当成已获审批。样本原文只写“待折价审批”，审批结果未载明，同步请求不具备已确认的授权依据。
3. 把返回值提取配置当成接口返回值本身。该配置代表如何解析响应，需与实际响应字段逐项比对。

## 怎么确认配好了

1. 输入样本原文与交接请求拟稿，比较“待折价审批”与拟稿中“折价审批结果同步”的表述。原文未载明审批结果时，该请求处于未获支持状态，需记录证据缺口。
2. 输入样本中“合同编号未载明”一句，比较供应商资料字段是否完整。合同编号缺失时，与供应商 B 结算系统的对接条件无法核对，保留为待核实。
3. 输入一条请求地址与 Headers 配置，比较 Authorization 引用变量是否在正式环境请求中传入实际值。测试模式下 chatId 不存在属于环境差异，与鉴权失败分别记录。
