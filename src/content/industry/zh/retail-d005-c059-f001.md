# 生鲜冷链到店验收的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样
冷链到店验收每批产生温控记录、到货验收单、拒收单与供应商送货单，数据来源包括冷链车温控、WMS、门店收货系统和质检照片。这些材料随每批到货更新，登记内容涉及运输温度、到货批次、抽检品质与拒收原因。本页处理库存采购与供应商资料这一任务下的 HTTP 接口与外部系统环节，即把上述材料送入外部服务或从外部服务取回时，请求怎么组织、变量怎么引用、返回值怎么解析。行业事实中，每批与日更频率只说明材料产生节奏，不推出批量同步、全量同步或交易触发机制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向指定地址发送请求，Params 用于路径请求参数，Body 用于 POST/PUT 请求体，Headers 用于传递特殊信息。三类数据与 URL 均可通过 {{}} 引用变量，变量来自全局变量、系统变量与前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取不到值属于该模式的条件，不构成业务故障。返回值配置的是如何解析接口响应，通过 JSON path 语法提取，输出类型选字符串时会把对应 key 的值转成 json 字符串。

假设演练样本：某门店收货员提交一批冷链到货资料，供核对原文为“到货验收单编号 A-001，运输温度记录显示该批次全程处于约定范围内，抽检品质合格，未开具拒收单”。待判定拟稿句为“该批次已验收合格且供应商送货单已同步至外部系统”。按已载明内容，验收单与温度记录指向合格状态，但“已同步至外部系统”在原文中没有对应记载，属于未获支持，需另行核实同步动作是否发生。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址 | 外部接口文档给出的地址，含 v1 路径 | 与文档地址逐字符比较，出现 404 时补充 v1 重试 |
| 请求方法 | 按外部接口契约选择 | 与外部接口文档声明的方法比较 |
| Headers 鉴权 | Authorization 引用 token 变量 | 与密钥使用规范比较，凭证不写入公开样例 |
| Body 结构 | 按外部接口字段名组织 JSON | 与外部接口契约逐字段比较 |
| 变量引用 | 引用前方节点输出的验收单编号 | 与前方节点实际输出值比较 |
| 返回值解析 | 为所需字段各配一个 key | 与接口响应结构比较，输出类型选字符串 |

自动格式化输出自 v4.6.8 加入，输出类型选字符串时按 json 字符串输出。对话接口中传入的 model、temperature 等字段无效，由编排决定。detail 为真时返回中间值，非流式结果保存在 responseData 中。这些属于节点已有行为与可配置字段，业务侧的验收判定、审批与数据库写入需要另行实现。

## 容易做错的三处
1. 把测试模式下 chatId 或 responseChatItemId 不存在当成接口故障。该现象由文档明确为测试模式条件，核对时应比较当前运行模式与字段取值，观察该字段是否按模式缺失，而不据此判定外部系统异常。
2. 把拟稿句中的“已同步至外部系统”当成已发生事实。输入为上述样本原文与拟稿句，比较对象是原文是否载明同步动作，观察结果是原文只支持验收合格，同步部分应记录为待核实。
3. 把返回值 key 的提取结果当成接口完整响应。输入为接口响应与所配 key，比较对象是 key 对应路径与期望字段，观察结果是提取值可能只是响应的一部分，需与接口契约核对后再使用。

## 怎么确认配好了
1. 输入样本原文与拟稿句，比较原文载明状态与拟稿句断言范围，观察拟稿句是否超出原文。若拟稿句包含原文未载明的同步动作，判定为未获支持，保留证据缺口。
2. 输入一条请求配置，比较 URL、方法与 Headers 是否与外部接口文档一致，观察是否出现 404。若出现，按文档补充 v1 路径重试，并记录实际观察结果。
3. 输入接口响应与所配 key，比较提取值与期望字段，观察输出类型选字符串时是否得到 json 字符串。若提取值与契约不符，核对 key 路径，不推断具体报错原因。
