# 生鲜冷链到店验收的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

生鲜冷链到店验收的文档围绕每批到货展开，冷链温度记录、到货验收单、拒收单、供应商送货单四类材料分别记录运输温控、收货结论、拒收原因和送货明细。与水果采购相比，冷链验收关注运输温度和到货批次，不负责产地询价。这一差别带来两个直接影响：定时任务读取的数据源是温控记录、WMS、门店收货系统和质检照片，任务编排需要按批次标识关联这些来源；拒收原因和温度记录一旦在自动化流程中被错误合并或覆盖，后续供应商争议和监管核查会缺少可追溯的原始记录。

## 这些特征在「定时任务与自动化」这一环带来什么约束

定时触发只负责按设定时间启动流程。外部数据由已配置的 HTTP 请求读取，定时触发不会自动建立与 WMS 或门店收货系统的连接。请求的方法、请求头、请求体和变量引用需要按外部接口文档逐项核对，URL 也可以通过变量引用。返回值解析使用 JSON path 提取，输出类型选择字符串时会将对应值转为 json 字符串。

去重、幂等与业务写入需要在接口或后续流程中明确设计，不宣称自动具备。执行记录要核对触发时间、真实输入、返回结果与业务状态，任务存在不能替代执行成功。

假设演练样本：某门店收货系统于 2025 年 3 月 12 日生成到货验收单，单号 YS-0312-07，批次 B-0312，收货主体为冷链验收组，状态为“已收货待质检”。同日冷链温度记录显示运输温度为 2.8 摄氏度，范围 0 至 4 摄氏度。一条拟提交的交接请求写道：“将 YS-0312-07 的验收状态更新为合格，并同步至供应商送货单。”该请求涉及状态变更与外部同步，需要核对授权边界和下游实现。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式与依据 |
| --- | --- | --- |
| 触发入口 | 由外部调度在每日收货结束后调用 | 核对实际版本中可用入口，确认由应用定时能力还是外部调度触发 |
| 请求方法 | POST | 按外部接口文档核对方法、请求头与请求体 |
| 请求体字段 | 引用批次标识与验收单号 | 通过 `{{key}}` 引用前方节点输出，字符串需加引号 |
| 返回值提取 | 使用 JSON path 提取状态字段 | 按接口响应结构配置 key，输出类型选择字符串 |
| 执行记录 | 记录触发时间、输入、返回结果 | 与业务状态逐项比对，不以任务存在替代成功 |
| 重复触发处理 | 由接口或后续流程设计去重 | 核对幂等设计是否明确，不假定自动具备 |

## 容易做错的三处

1. 把定时触发当作已建立业务系统连接。输入是定时配置，比较对象是外部接口是否已配置，可观察结果是请求是否实际发出并返回数据。
2. 把检索或表单当作授权执行。输入是交接请求中的状态变更，比较对象是授权边界与下游实现，可观察结果是状态是否被实际写入。
3. 把任务存在当作执行成功。输入是任务记录，比较对象是触发时间、真实输入与返回结果，可观察结果是业务状态是否同步更新。

## 怎么确认配好了

1. 以样本单号 YS-0312-07 为输入，比较拟提交请求中的状态变更与原始验收单的“已收货待质检”状态，观察是否出现未经授权的状态覆盖。预期是状态保持原值，缺口记录为待核实。
2. 以批次 B-0312 为输入，比较温度记录 2.8 摄氏度与范围 0 至 4 摄氏度，观察自动化流程是否将温度数据与验收结论正确关联。预期是关联正确，不出现字段错位。
3. 以拟提交请求为输入，比较请求中的同步动作与接口文档说明，观察是否存在未实现的外部同步。预期是同步动作标记为待实现，不声称已执行。
