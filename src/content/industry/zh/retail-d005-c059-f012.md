# 生鲜冷链到店验收的库存采购与供应商资料：文档解析与分块

## 这个品类的数据长什么样

生鲜冷链到店验收环节，每批到货伴随冷链温度记录、到货验收单、拒收单与供应商送货单。这些材料的主体是门店收货方与供应商，对象是具体批次商品，状态包括合格入库、拒收、待复检。温度记录与验收单常含时间点、温度值、批次编号；拒收单含拒收原因与数量；送货单含供应商名称与送货数量。材料以每批为更新单位，部分数据按日汇总。

文档解析与分块需要保留这些字段间的约束关系：温度条件与验收结论不能拆散，拒收原因与对应批次不能分到不同数据块。入库时若把条件句与结论句切开，检索到结论却丢失温度前提，核对就失去依据。

## 这些特征在「文档解析与分块」这一环带来什么约束

分块要按材料结构切分，同一份验收单的温度记录、抽检结论、拒收原因应保留在同一数据块或建立可回指的关联。数据与索引需要区分：MongoDB 的 dataset.datas 存储原数据，indexes 字段记录对应向量 ID，一组原数据可对应多个向量。检索时先召回向量，再按向量 ID 回 MongoDB 找原数据，同一组原数据合并后取最高得分。

假设演练样本：某门店收到一批冷链到货，材料原文为「2025年3月10日，冷链车温度记录显示运输全程2至6摄氏度。到货验收单载明批次A-0310共40箱，抽检6箱，感官合格。供应商送货单载明该批次由乙方送达，数量40箱。当日拒收单未开具。」待判定拟稿句为「该批次A-0310已完成验收并全部入库。」此句将到货验收单的抽检合格与全部入库混同，验收单未载明入库数量与入库状态，该拟稿句缺少入库事实支撑。

## 配置怎么定

配置围绕本页样本的核对需要展开，仅列官方已说明的设置项或实施核对项。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 批次编号与温度值需精确命中，自然语言问法需语义召回，比较两种模式下同一批次的召回内容差异 |
| 最低相关度 | 假设起点0.3 | 该值为0至1的过滤阈值，仅语义检索或重排时生效，与样本中批次编号查询的命中情况比较后调整 |
| 引用上限 | 假设起点2000 tokens | 官方按 tokens 控制引用上限，比较验收单与温度记录合并后是否超出该值 |
| 问题优化 | 暂不开启 | 样本问题含明确批次编号，开启会增加模型调用，比较开启前后批次编号检索结果是否一致 |
| Rerank | 暂不开启 | 需具备重排模型并按设置启用，样本候选较少时比较重排得分与向量得分排序差异 |
| 分块方式 | 按材料结构分块 | 温度记录、验收结论、拒收原因保留在同一数据块，比较拆分前后条件与结论是否仍可回指 |

## 容易做错的三处

1. 把温度记录与验收结论拆到不同数据块，检索到验收合格却丢失运输温度前提。检查时输入样本原文的分块结果，比较温度值与验收结论是否在同一数据块或存在可回指关联，观察拆分后检索「批次A-0310验收」是否返回缺少温度前提的片段。
2. 将拟稿句「已完成验收并全部入库」直接作为事实写入资料。检查时输入该拟稿句与验收单原文，比较「抽检合格」与「全部入库」是否为同一字段的同一事实，观察原文未载明入库数量与状态时该句是否获得支持。
3. 把检索命中当作授权执行。检查时输入检索请求与交接请求，比较检索返回内容与授权状态字段，观察检索结果中是否出现审批、放行或结算等原文未载明的状态。

## 怎么确认配好了

- 验证一：输入样本原文与拟稿句「该批次A-0310已完成验收并全部入库」。比较验收单原文是否载明入库数量与入库状态。原文仅载明抽检6箱感官合格，未载明入库数量与状态，该拟稿句未获支持，应记录为待核实。

- 验证二：输入批次编号「A-0310」与温度值「2至6摄氏度」分别检索。比较两种检索方式返回的数据块是否包含温度记录与验收结论的完整上下文。若返回片段仅含验收结论而缺少温度前提，分块方式需要调整。

- 验证三：输入空结果场景，纸面输入检索词为不存在的批次编号。比较返回结果是否为空，并核对下游设计是否按空结果处理。空结果仅说明该检索词未命中，不说明资料不存在或未训练。

检索与相关度不承担权限或实体隔离功能。同一向量模型的要求限于本知识库内，不扩展到其他系统。资料变更后需核对实际训练与索引状态，上传成功不等于检索已更新。
