# 生鲜水果门店采购的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

水果采购围绕批发市场行情、供应商报价、门店销售与检测报告展开，采购单、验收单、农残检测报告、损耗记录按日或按批更新。等级验收与询价比价直接决定损耗与缺货后果，这类记录需要与外部系统交换数据时，字段口径和批次范围往往比便利店鲜食订货更依赖当日行情与档口实况。

HTTP 模块向目标地址发送请求，Params 用于路径参数，Body 用于请求体，Headers 用于请求头，三者均可通过 `{{}}` 引用全局变量、系统变量与前方节点输出。返回值通过 JSON path 提取，输出类型选择字符串时会把对应值转成 json 字符串。对话接口以 APIKey 鉴权，调用 `chat/completions` 时推荐在请求体传入 `body.appId`，也支持 `Authorization: Bearer <apiKey>-<appId>`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

采购与验收数据按日、按批变化，接口对接需要逐批核对物料、数量与状态，不能把一次请求的结果当作长期有效的授权或库存结论。HTTP 模块可以操作数据库、调用外部数据源、执行联网搜索、发送邮箱，这些是扩展方向，实际写入、审批与同步需要对应的下游实现，模块本身不承担业务授权判断。

假设演练样本：以下为纸面材料，用于核对，不代表任何真实记录。

材料原文一：某门店生鲜主管于 2026 年 3 月 10 日提交采购申请，物料为红富士苹果，等级一级，数量 200 公斤，供货档口为城北批发市场 A 区某档口，申请状态为“待采购主管审核”。

材料原文二：同一档口同日提供的报价单写明“本报价有效期至 2026 年 3 月 12 日”，报价单未载明供货期限与结算条款。

待判定拟稿句：该采购申请已获批准，可安排 3 月 11 日到货。

判定要点：材料一的状态为“待采购主管审核”，待审核不构成批准；报价有效期只约束报价本身，不表示供货期限，也不表示合同生效。拟稿句中的“已获批准”与“可安排到货”均未获支持，属于待核实。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址与方法 | 按外部采购接口文档填写，地址引用已提供的变量 | 与接口文档逐字段比对路径与方法是否一致 |
| Params 与 Headers | 鉴权凭证通过安全配置注入，不写入公开样例 | 核对请求头键名与接口契约，比较实际传入值 |
| Body | 仅在相应请求类型下使用，核对 JSON 结构 | 与外部接口契约比较字段名、类型与嵌套层级 |
| 变量引用 | 引用全局变量、系统变量与前方节点输出 | 逐项核对实际传入值，确认来源节点存在 |
| 返回值提取 | 按 JSON path 配置 key 与输出类型 | 与接口响应示例比较提取路径与结果类型 |
| 调试身份字段 | 测试模式下 chatId 与 responseChatItemId 不存在 | 比较测试与正式环境的字段存在性，不把空值当故障 |

## 容易做错的三处

1. 将材料一的“待采购主管审核”直接读作已批准，把未完成审核的申请当作可执行采购。检查方式：输入材料一原文，比较状态字段与拟稿句中的“已获批准”，观察两者是否一致。
2. 把报价单的“有效期至 2026 年 3 月 12 日”扩展为供货期限或合同生效。检查方式：输入材料二原文，比较有效期字段与拟稿句中的到货安排，观察报价单是否载明供货期限。
3. 在测试模式下将 chatId 为空当作业务故障。检查方式：输入测试模式请求，比较文档说明的“测试模式下不存在”与返回结果，观察该字段缺失是否属于预期现象。

## 怎么确认配好了

1. 针对材料一，输入采购申请原文与拟稿句，比较申请状态与“已获批准”的表述，观察拟稿句是否获得原文支持。若状态仍为待审核，判定为未获支持。
2. 针对材料二，输入报价单原文与到货安排，比较有效期字段与供货期限，观察报价单是否载明供货期限。未载明时记录为证据缺口。
3. 针对接口请求，输入配置好的地址、方法与 Body，比较实际传入值与接口契约，观察返回值提取是否按 JSON path 得到预期字段。若响应为空或字段缺失，记录实际观察结果，不推断确定性失败原因。

检索与相似度不承担权限或实体隔离功能，检索结果不能替代业务授权。跨不同向量模型的库不可共同关联，需先核对标识并排除不符合者。交互节点返回的配置只包含 type 与 params，内部运行态字段不返回；表单收集值，业务验证、审批、数据库写入与外部同步需要各自的下游实现。
