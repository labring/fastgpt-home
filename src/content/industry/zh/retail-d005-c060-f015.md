# 生鲜水果门店采购的库存采购与供应商资料：知识库检索与召回

## 这个品类的数据长什么样

生鲜水果门店采购依赖批发市场行情与等级验收，与总部标准餐食订货存在差别。采购单、验收单、农残检测报告、损耗记录按日或每批产生，资料更新频繁。检索环节面对的是同一供应商、同一批次在不同单据上的字段，主体、期间、字段必须对齐才能判断。资料长度差异大，短至一行报价，长至整页检测结论，引用上限按 token 控制，不按条数。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，需先核标识并排除不符合者。语义检索、全文检索、混合检索按测试问题比较，不预设一种模式适合全部资料。最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展。引用内容以数组输出，长度可以为 0。RRF 是混合结果的融合过程。图片检索须有相应图像输入及模型能力，重排须具备模型且按设置启用。检索不承担授权判断。

假设演练样本：某门店生鲜主管留存一份纸面材料，原文为“供应商甲，2025年3月10日报价：红富士苹果80mm以上，每箱10公斤，报价有效期至2025年3月17日。同日验收单记录该批次到货30箱，等级合格。”待判定拟稿句为“供应商甲已确认2025年3月全月按此价供货。”该句把报价有效期当作供货期限，且未载明全月供货承诺。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 关联知识库 | 仅关联含采购单、验收单、检测报告、损耗记录且向量模型标识一致的库 | 先核向量模型标识，排除不一致者 |
| 搜索模式 | 先用混合检索 | 与单独语义检索、单独全文检索比较命中情况 |
| 引用上限 | 设为覆盖一份完整验收单的 token 量 | 与较短上限比较，观察引用内容是否被截断 |
| 最低相关度 | 先标注相关与无关样本再定阈值 | 比较不同阈值下无关片段是否被滤除 |
| 问题优化 | 对多轮追问与短问题开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型且按设置启用时使用 | 比较启用前后候选排序，观察得分过滤效果 |

以上数值为本次假设试验起点，非官方默认值。

## 容易做错的三处

1. 把报价有效期当作供货期限。样本中“报价有效期至2025年3月17日”只说明报价有效范围，拟稿句写成“全月按此价供货”，属于超出原文的推断。应比较拟稿句与原文的期间字段，确认是否载明全月供货。
2. 把检索命中当作授权确认。检索返回供应商甲的材料，不表示该供应商已获采购授权或合同已生效。应区分检索结果与签署、审批等下游动作。
3. 把未载明当作否定。样本未载明全月供货承诺，只能记为未获支持或待核实，不能记为冲突或否定。应核对同主体、同期间、同一字段是否存在互斥取值。

## 怎么确认配好了

1. 输入样本原文与拟稿句，比较拟稿句的期间表述与原文“报价有效期至2025年3月17日”。若拟稿句出现全月供货表述而原文未载明，则判定为超出原文，需退回修改。
2. 输入样本原文，检索“供应商甲 验收 等级”。比较返回引用是否包含该验收单主体与批次。若引用内容为空数组，则按空结果承接核对下游设计，不推断规则一定返回空。
3. 输入跨向量模型的两个库标识，比较标识是否一致。若不一致，则排除不符合者并记录实际观察，不执行跨模型检索来比较漏召回。
