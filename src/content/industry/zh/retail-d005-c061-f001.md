# 生鲜称重分拣的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样
称重分拣发生在仓内履约环节，数据围绕重量与规格展开，来源包括 WMS、电子秤、订单系统和质检照片。库存采购与供应商资料这条线上，日常材料是分拣任务单、称重标签、少称补偿单和质检记录，更新节奏为每单与每日。这些材料在 HTTP 接口环节的意义在于：分拣任务单和称重标签常需要把重量、规格、批次等字段传给外部系统，少称补偿单与质检记录则可能作为回传或留档内容。字段是否真实、是否在有效期内、是否已获授权，取决于材料本身，与接口能否调通是两件事。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params 为路径请求参数，Body 为请求体，Headers 为请求头。三者均可通过 {{}} 引用变量，URL 也可引用变量。变量来自全局变量、系统变量和前方节点输出。系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 或 JS 对象取值规则提取，输出类型选字符串时会把对应值转成 json 字符串。对话接口使用 APIKey 鉴权，appId 优先级为 body.appId、`<apiKey>-<appId>`、apikey 关联的 appId；传入的 model、temperature 等字段无效。这些是节点已有行为与可配置字段，业务上的采购确认、供应商准入、库存写入与外部同步需要另接系统实现。

假设演练样本：一份分拣任务单原文写「任务单号 SF-2026-0417-03，商品为散装叶菜，规格 500g±20g，分拣仓 A，分拣员已称重 3 件，质检主管尚未复核」。一份少称补偿单原文写「补偿单号 BC-2026-0417-01，关联任务单 SF-2026-0417-03，顾客反馈少称，状态为待审核」。一条待判定拟稿句为「该任务单已完成质检复核，可向供应商系统回传库存增量」。

## 配置怎么定
下表仅列与本页样本相关的官方已说明设置或实施核对项。数值一栏均为本次假设试验起点，用于纸面对照，不代表官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址 BaseUrl | 外部接口文档给出的地址 | 与接口文档列出的路径比较，出现 404 时可补充 v1 重试 |
| 请求方法 | 按外部接口契约选择 | 与文档声明的动作比较，不自行推断 |
| Headers 鉴权 | Authorization 引用已配置变量 | 与密钥使用规范比较，凭证不写入公开样例 |
| Body 结构 | 按外部接口契约声明 JSON | 与任务单字段逐项比较，确认字段名与类型一致 |
| 返回值提取 | 按 JSON path 声明 key | 与接口响应示例比较，确认取值路径存在 |
| 调试身份字段 | 测试模式下 chatId 与 responseChatItemId 不存在 | 与正式请求比较，不把调试空值当作业务故障 |

## 容易做错的三处
1. 把待审核当作已复核。样本中少称补偿单状态为待审核，拟稿句写「已完成质检复核」。输入为该状态字段，比较对象为「待审核」与「已完成」两种取值，观察结果是两者不相等，拟稿句未获支持。
2. 把接口可调用当作业务授权。样本任务单只记录分拣员已称重 3 件，未记录质检主管复核结论。输入为任务单原文，比较对象为「已称重」与「已复核」，观察结果是后者缺失，回传库存增量缺少依据。
3. 把检索相似度当作权限过滤。若用相似度设置判断某条供应商资料是否属于当前操作者，输入为相似度数值，比较对象为资料所属主体与操作者授权范围，观察结果是两者无对应关系，相似度不承担权限隔离。

## 怎么确认配好了
1. 针对样本拟稿句「该任务单已完成质检复核」，输入为任务单原文与补偿单原文，比较对象为质检复核状态字段的实际取值，观察结果为状态字段为待审核或不含复核结论时，该句不成立。
2. 针对回传库存增量的请求，输入为任务单号 SF-2026-0417-03 与授权范围说明，比较对象为请求主体是否在授权范围内，观察结果为授权范围未覆盖该动作时，请求停留在待核实状态。
3. 针对返回值提取，输入为接口响应与声明的 key，比较对象为 JSON path 指向的值与预期字段，观察结果为路径不存在或类型不符时，记录缺口而不推断接口失败原因。
