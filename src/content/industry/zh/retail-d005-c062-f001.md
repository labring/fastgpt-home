# 电商仓入库上架的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

入库上架处理货物进入仓库的第一道账实确认，数据来源包括 WMS、ERP采购、供应商送货单与条码扫描，日常文档为采购到货单、入库验收单、上架任务与差异报告。每批到货都要核对数量、打印条码、分配库位，出错会造成库存账实不符、后续拣货错误与供应商争议。这些特征决定了本页的接口调用围绕单据标识、数量与状态展开，HTTP 模块承担把仓库侧数据送到外部系统、把外部结果取回编排的角色。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 用于路径请求参数，Body 用于请求体，Headers 用于请求头，三者均可通过 `{{}}` 引用变量，URL 同样可以引用变量。变量来自全局变量、系统变量与前方节点输出。系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在，不把调试空值当成业务故障。返回值通过 JSON path 提取，出参格式化在 v4.6.8 后加入，输出类型选择字符串时把对应 key 的值转成 json 字符串。检索与相似度不承担权限或实体隔离，接口调用不代表业务授权。

假设演练样本：某电商仓收货员在 2025 年 3 月 10 日处理一批采购到货，材料原文为“采购到货单 PO-20250310-07 载明供应商为华东某供应商，到货 SKU 为 A 款 200 件，送货单数量 200 件；入库验收单载明实收 200 件、验收结论为合格；上架任务单载明库位 B-02-03、状态为待上架”。待判定拟稿句为“该批货物已完成上架，库存已同步至外部系统”。此句只涉及验收与上架任务状态，上架任务状态为待上架，库存同步属于需另接系统实现的业务动作，该句未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 比较与说明 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档给定的到货单查询地址，方法为 POST | 地址可引用变量；与接口文档比对路径与方法 |
| Headers 鉴权 | Authorization 通过安全配置注入，不写入公开样例 | 与接口文档要求的鉴权头比对 |
| Body 结构 | 传入采购到货单号与供应商标识 | 与接口契约的字段名、类型比对 |
| 变量引用 | 引用前方节点输出的到货单号 | 与节点实际输出值比对 |
| 返回值提取 | 以 JSON path 提取实收数量字段 | 与接口响应示例的层级比对 |
| 输出类型 | 数量字段选择 number，文本字段选择字符串 | 与后续节点需要的类型比对 |

## 容易做错的三处

1. 把验收合格当作上架完成。假设样本中入库验收单结论为合格，上架任务状态为待上架，拟稿句写成已完成上架，输入是两份单据，比较的是上架任务状态字段，观察结果是状态仍为待上架。
2. 把变量引用写成固定值。Body 中到货单号未用 `{{}}` 引用前方节点输出，输入是节点输出与 Body 声明，比较两者是否一致，观察结果是请求体与本次到货单号不匹配。
3. 把接口返回当作授权。接口返回实收数量，拟稿句据此写库存已同步，输入是接口响应与拟稿句，比较的是响应是否含同步结果字段，观察结果是响应只有数量字段。

## 怎么确认配好了

1. 取假设样本的采购到货单号与供应商标识，填入 Body 并发送请求，比较请求体字段与接口契约，响应返回实收数量且与入库验收单 200 件一致，视为该字段核对通过。
2. 取上架任务状态字段，与拟稿句“已完成上架”比较，状态为待上架时该句不成立，记录为未获支持，并保留上架任务单作为证据缺口。
3. 取接口响应与拟稿句“库存已同步至外部系统”比较，响应未含同步结果字段时，该句未获支持，库存同步是否执行需另接系统实现并另行核对。
