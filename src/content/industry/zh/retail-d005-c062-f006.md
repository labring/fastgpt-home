# 电商仓入库上架的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

入库上架处理货物进入仓库的第一道账实确认，数据来源包括 WMS、ERP 采购、供应商送货单与条码扫描。日常文档为采购到货单、入库验收单、上架任务与差异报告，最耗时环节是核对到货数量、打印条码、分配库位。定时任务与自动化在本品类的作用，是把外部系统的到货与验收数据按接口读取，再驱动后续节点。数据更新频率为每批、日，本页不据此推出批量同步、全量同步或实时触发机制。

## 这些特征在「定时任务与自动化」这一环带来什么约束

定时触发只负责按时间发起执行，不自动建立业务系统连接。外部数据须由已配置的 HTTP 请求读取，方法、请求头、请求体与变量输入按外部接口文档核对。去重、幂等与业务写入须在接口或后续流程明确设计，不能宣称自动具备。执行记录须核对触发时间、真实输入、返回结果与业务状态，任务存在不等于执行成功。检索或表单收集的值不构成授权，业务验证、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：某电商仓收货组在 2025 年 3 月 10 日收到供应商送货单，原文为“采购到货单 PO-20250310-07，供应商甲，品项 A 条码 6900000000012，应收 200 件；入库验收单 YS-20250310-07 记录实收 180 件，差异 20 件，状态为待复核”。同日 WMS 生成上架任务 SJ-20250310-07，分配库位 B-01-02，状态为待执行。拟判定句：“差异报告已确认，20 件短少由供应商补发，上架任务可自动完成。”该句涉及补发与自动完成两项业务动作，样本未载明授权与生效条件。

## 配置怎么定

| 配置项 | 本次假设起点 | 核对方式与理由 |
| --- | --- | --- |
| 触发方式 | 由外部调度按日发起 | 按实际版本核对可用入口，确认触发责任归属 |
| 请求地址 | 引用已配置的 url 变量 | 与外部接口文档逐项比对，不假定连接已建立 |
| 请求方法 | POST | 按接口文档核对，Body 仅在特定请求类型下生效 |
| 请求头 | Authorization 为 Bearer {{token}} | 核对 token 来源与有效范围，不视为业务授权 |
| 请求体字段 | 引用到货单号与验收单号变量 | 字符串须加引号，数组与对象按文档写法引用 |
| 返回值提取 | 按 JSON path 提取状态字段 | 出参格式化以 json 转字符串为主，核对 key 与输出类型 |

本次假设起点选 POST，因样本为提交核对请求；与接口文档声明的方法比较，不一致时以文档为准。数值与字段均为本次假设试验起点，非官方默认值。

## 容易做错的三处

1. 把定时触发当作已建立 WMS 或 ERP 连接。输入为已配置触发入口，比较是否另有已配置的 HTTP 请求，可观察结果是请求记录缺失或仅有触发记录。
2. 把检索或表单收集的到货单号当作授权执行。输入为表单值，比较授权状态字段，可观察结果是写入或同步动作无对应授权依据。
3. 把待复核的差异报告当作已确认。输入为样本中状态“待复核”，比较是否存在确认记录，可观察结果是补发与自动完成两项动作均无依据。

## 怎么确认配好了

1. 输入样本原文的到货单 PO-20250310-07 与验收单 YS-20250310-07，比较应收 200 件与实收 180 件，若差异报告状态仍为待复核，则拟判定句中的补发与自动完成不成立，记录为待核实。
2. 输入已配置的请求地址、方法与请求头，比较外部接口文档声明，若方法或字段不一致，则请求结果不可用于后续节点，保留缺口。
3. 输入触发时间与返回结果，比较业务状态字段，若返回结果缺失或状态未更新，则执行记录只能证明触发发生，不能证明写入成功。

三项验证均为纸面核对，未实际执行。
