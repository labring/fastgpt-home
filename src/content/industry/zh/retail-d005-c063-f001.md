# 直播售后集中处理的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

直播售后集中在单场流量后爆发，退款申请与补发单在同一时段堆叠，主播承诺又强相关。库存采购与供应商资料因此要同时承接直播订单清单、退款申请、补发单和话术模板。资料更新频率为每场后与日，这一节奏影响的是核对时点，不推出批量同步、全量同步或交易触发机制。抖店售后、客服IM、仓库WMS和物流轨迹是主要数据来源，HTTP 接口与外部系统承担把上述材料送到下游服务的通道。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params、Body、Headers 三处均可用 `{{}}` 引用变量，URL 也可引用变量。变量来自全局变量、系统变量和前方节点输出。系统变量含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 histories 默认最多取 10 条且无法修改长度；chatId 与 responseChatItemId 在测试模式下不存在，调试空值属于预期现象。

返回值配置表示如何解析接口响应，按 JSON path 提取，输出类型选字符串时会把对应 key 的值转成 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer。传入的 model、temperature 等字段无效，由编排决定。detail=true 可返回中间值，tokens 需手动计算。交互节点返回的 interactive 只含 type 和 params，entryNodeIds、memoryEdges、nodeOutputs、nodeResponseId 不返回。表单输入需将对象序列化成字符串作为 messages 的 content，并保持 chatId 一致。插件应用默认 detail 模式，通过 variables 传输入，从 moduleType=pluginOutput 的元素取 pluginOutput。

假设演练样本：某直播间售后组在 2025 年 6 月 18 日场次后整理补发单，材料原文为“供应商甲确认 6 月 20 日前可补发 30 件；本场退款申请 12 笔仍在平台审核中；仓库异常岗尚未完成错漏件清点”。拟交接请求为“请把上述补发安排同步给供应商并更新库存”。该请求处于待判定状态，未获授权执行。

## 配置怎么定

| 配置项 | 本页相关取值或核对项 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选定，地址可引用已提供变量 | 对照接口文档逐字比对 |
| Params 与 Headers | 分别列出请求参数与请求头，鉴权凭证经安全配置注入 | 检查凭证未写入公开样例 |
| Body | 仅在相应请求类型下使用，核对 JSON 结构与外部契约 | 逐字段比对键名与类型 |
| 变量引用 | 引用全局变量、系统变量或前方节点输出 | 逐项核对实际传入值 |
| 返回值解析 | 按 JSON path 配置 key 与输出类型 | 用响应示例验证提取结果 |
| 调试身份字段 | chatId、responseChatItemId 在测试模式下不存在 | 确认空值属预期，不判为故障 |

## 容易做错的三处

1. 把平台审核中的退款申请当作已批准退款，据此触发库存扣减。检查输入为材料原文中“12 笔仍在平台审核中”，比较对象是退款状态字段的取值，只有状态明确为已完成退款才满足执行条件。
2. 把供应商甲“确认 6 月 20 日前可补发 30 件”当作供货期限承诺，并据此更新库存数量。检查输入为该句原文，比较对象是承诺对象与日期范围，只有出现明确的库存变更授权才满足执行条件。
3. 把仓库异常岗“尚未完成错漏件清点”当作清点结果为无错漏。检查输入为该句原文，比较对象是清点状态，只有出现已完成的清点记录才满足执行条件。

## 怎么确认配好了

1. 以假设样本材料原文为输入，比较拟交接请求中的“同步给供应商并更新库存”与原文授权状态，观察是否出现明确授权记录；未出现授权记录时该请求保持待判定。
2. 以假设样本中退款申请状态为输入，比较状态字段取值与“已完成退款”，观察是否满足扣减条件；状态为审核中时不满足。
3. 以假设样本中供应商补发确认句为输入，比较承诺对象与日期范围，观察是否出现库存变更授权；未出现授权时不得更新库存数量。
