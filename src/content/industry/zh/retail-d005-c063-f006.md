# 直播售后集中处理的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

直播售后集中处理常在一场流量结束后爆发，退款申请、补发单与直播订单清单在同一时段内集中出现，客服IM、仓库WMS与物流轨迹的记录需要与这些单据对齐。库存采购与供应商资料这一主任务所依赖的材料，来自退款申请中的退货原因、补发单中的缺货品项，以及供应商侧的供货与对账记录。这些材料每场后或按日更新，更新节奏本身不构成本页的自动化触发条件。

## 这些特征在「定时任务与自动化」这一环带来什么约束

定时任务与自动化在本品类中承担的是按既定节奏读取外部资料、发出HTTP请求并记录结果，触发责任需要明确由应用定时能力还是外部调度承担，并按实际版本核对可用入口。外部数据由已配置接口读取，定时触发不自动建立业务系统连接。HTTP请求的方法、请求头、请求体及变量输入按外部接口文档核对，去重、幂等与业务写入需要在接口或后续流程明确设计。执行记录核对触发时间、真实输入、返回结果与业务状态，任务存在不能替代执行成功。

假设演练样本：一份待核对的供应商补发确认材料原文为“供应商甲于2025年3月10日确认，针对3月8日直播售后补发单BH-0310，可提供同型号商品200件，报价有效期至2025年3月20日。”一条待判定的拟稿句为“供应商甲已同意在3月20日前供货200件。”材料只载明可提供数量与报价有效期，未载明供货期限，拟稿句把报价有效期当作供货期限，属于未获支持的表述。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 触发方式 | 由应用定时能力按日触发一次 | 核对实际版本可用入口，不假定外部调度已接通 |
| 请求地址 | 供应商资料接口地址，以 `{{url}}` 引用 | 按外部接口文档核对方法、请求头 |
| 请求体字段 | 补发单号与供应商名称，以 `{{}}` 引用前方节点输出 | 核对字段与接口文档一致 |
| 返回值解析 | 配置 `key` 提取 `message` 与 `data.user.name` | 按 JSON path 语法核对提取结果 |
| 输出类型 | 字符串，将对应 `key` 的值转为 json 字符串 | 核对格式化输出与下游文本加工衔接 |
| 执行记录 | 记录触发时间、真实输入与返回结果 | 与业务状态逐项比对，不以任务存在替代执行成功 |

## 容易做错的三处

1. 把报价有效期当成供货期限。拟稿句写“3月20日前供货”，材料只写报价有效期至3月20日，两者属不同字段，判定为未获支持。
2. 把检索或表单当成授权执行。读取到供应商资料接口返回的报价记录，不代表采购或补发已经获批，授权状态需要单独核对。
3. 把定时触发当成业务系统连接已建立。触发方式配置为按日触发，不表示外部数据源已接通或写入已完成，需要核对接口返回与业务状态。

## 怎么确认配好了

1. 输入假设材料原文与拟稿句，比较“报价有效期至3月20日”与“3月20日前供货”，材料未载明供货期限时，拟稿句应判为未获支持，不得判为否定或冲突。
2. 输入一条交接请求“请按供应商甲报价安排补发200件”，比较请求中的授权状态与材料所载状态，材料未载明采购授权时，请求应停留在待核实，不得视为已批准执行。
3. 输入返回值解析配置与接口响应示例，比较 `key` 为 `data.user.name` 的提取结果与响应中的 `name` 字段，两者一致时满足条件；响应为空数组 `[]` 时，核对下游设计如何处理空结果，不声称虚构规则检索一定返回空。
