# 直播选品与样品质检的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

选品质检发生在开播前，判断的是商品能不能卖、是否适合直播展示。支撑判断的材料是样品评估表、质检报告、供应商资质与禁售清单，更新频率为周、每品。库存采购与供应商资料这一任务里，HTTP 模块承担的是把外部系统的库存、资质与检测结论取回编排，供后续节点使用。外部接口的地址、方法、鉴权方式由对方文档决定，FastGPT 侧只负责按契约发送请求并解析响应。资料未说明本任务存在定时触发或批量同步机制，因此不推断此类行为。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块可重复添加、手动配置、触发执行。Params 用于路径请求参数，Body 用于 POST/PUT 请求体，Headers 用于请求头，三处均可用 `{{}}` 引用变量，URL 同样可引用。变量来源为全局变量、系统变量与前方节点输出。系统变量含 appId、chatId、responseChatItemId、variables、cTime、histories；histories 默认最多取 10 条且无法修改长度。chatId 与 responseChatItemId 在测试模式下不存在，调试时为空值属于该模式特性。返回值通过 JSON path 提取，输出类型选字符串时会把对应 key 的值转成 json 字符串。

假设演练样本：某供应商提交一批样品，材料原文为「供应商甲于本次送样单中声明该批保温杯为食品接触级不锈钢，送样日期为本周一，数量 30 件；随附检测机构报告编号 A-01，报告结论为符合食品接触材料要求；供应商营业执照复印件在有效期内」。拟提交的交接请求为「请将该批保温杯按合格样品录入库存采购清单，并同步至供应商资料库」。待判定点在于：送样单声明、检测报告结论与资质有效期分别属于不同字段，请求中的「按合格样品录入」与「同步至供应商资料库」是否已有对应授权与下游实现。

## 配置怎么定

| 配置项 | 本页设置或核对项 | 依据与边界 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址可引用变量 | 官方说明地址可引用变量 |
| Params 与 Headers | 分别核对路径参数与请求头，鉴权凭证经安全配置注入 | 官方说明两处用法与 Postman 类似 |
| Body | 仅在相应请求类型下使用，核对 JSON 结构与契约 | 官方说明 Body 只在特定请求类型生效 |
| 变量引用 | 逐项核对全局变量、系统变量、前方节点输出 | 官方说明三类来源 |
| 返回值提取 | 用 JSON path 配置 key，输出类型按需选字符串 | 官方说明提取语法与格式化 |
| 调试身份字段 | chatId、responseChatItemId 测试模式下不存在 | 官方说明该模式下不存在 |

## 容易做错的三处

1. 把检索或表单当成授权执行。假设样本中请求要求「按合格样品录入并同步至供应商资料库」，而材料只给出送样声明、报告结论与资质有效期，未载明录入与同步的授权。核对输入为该请求与三份材料原文，比较是否存在针对录入与同步的授权字段，观察结果为未获支持，需记录证据缺口。
2. 把不同字段混为同一事实。送样单声明、检测报告结论、资质有效期属不同字段。核对时须同主体、同期间、同一字段，只有同字段明确互斥取值才称矛盾；本样本各字段取值不互斥，属待核实。
3. 把调试空值当成业务故障。若在测试模式下 chatId 或 responseChatItemId 为空，这是官方说明的模式特性。核对输入为当前运行模式，比较字段是否存在，观察结果应与该模式一致，不据此判定接口异常。

## 怎么确认配好了

1. 针对假设样本的拟提交请求，检查是否已存在录入与同步的授权字段。输入为请求原文与三份材料，比较授权字段有无，满足条件为字段明确载明；未载明则记录为待核实，不执行录入或同步。
2. 针对返回值提取，用样本报告编号 A-01 构造纸面响应，按 JSON path 配置 key。输入为纸面响应与提取配置，比较提取值与响应中对应字段，满足条件为取值一致；不一致时记录实际观察，不推断报错原因。
3. 针对字段判定，逐项列出送样日期、数量 30 件、报告编号 A-01、资质有效期。输入为各字段原文，比较同字段取值是否互斥，满足条件为同字段明确互斥；否则记为未获支持。检索结果不承担权限或实体隔离，相关度分数不构成授权依据。
