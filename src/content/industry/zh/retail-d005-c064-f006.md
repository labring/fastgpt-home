# 直播选品与样品质检的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

直播选品与样品质检发生在开播之前，判断重点是商品能否上播、是否适合直播展示。库存采购与供应商资料环节要处理供应商资质、质检报告、样品评估表、禁售清单四类文档，数据更新频率为周、每品。供应商资质与质检报告的有效期、检测对象、报告编号属于逐品核对项，样品评估表的结论与评估日期决定该样品能否进入采购交接。这些材料分散在供应商、检测机构与内部质检之间，定时任务与自动化只能负责按已配置的接口读取和传递，不能替代资质核验、授权确认与采购审批。

## 这些特征在「定时任务与自动化」这一环带来什么约束

触发责任需要明确：由应用定时能力触发，或由外部调度触发，并按实际版本核对可用入口。外部数据由已配置接口读取，定时触发不会自动建立与供应商系统或质检系统的业务连接。HTTP 请求的方法、请求头、请求体与变量输入，需要按外部接口文档逐项核对，变量来自全局变量、系统变量或前方节点输出。去重、幂等与业务写入需要在接口或后续流程中明确设计，不能假定自动具备。执行记录要核对触发时间、真实输入、返回结果与业务状态，任务存在不等于执行成功。

假设演练样本：某选品经理在周度批次中收到一份供应商资质材料，原文为“供应商甲，统一社会信用代码略，食品经营许可证有效期至2026年3月31日，质检报告编号QC-2025-0417，检测对象为批次A样品，报告签发日期2025年4月17日”。另有一条待判定交接请求：“该供应商资质与质检报告齐备，可进入库存采购下单。”本样本仅用于核对字段与状态，不涉及真实主体。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 触发入口 | 由应用定时能力触发，周期按周 | 核对实际版本可用入口，与外部调度分工 |
| 请求方法 | POST | 按外部接口文档核对方法与路径 |
| 请求头 | Authorization 使用 Bearer 变量 | 核对变量来源与取值 |
| 请求体 | 自定义 JSON，引用前方节点输出 | 核对字段名与引用是否对应 |
| 返回值解析 | 按 JSON path 提取所需字段 | 核对 key 与响应结构一致 |
| 执行记录 | 记录触发时间、输入、返回结果 | 与业务状态比对，不替代成功判定 |

## 容易做错的三处

1. 把定时触发当成授权执行。样本中供应商资质与质检报告齐备，只说明材料字段存在，采购下单仍需授权边界内的审批，触发任务不产生授权。
2. 把 HTTP 返回值解析结果当成业务核验结论。返回值提取到报告编号或有效期，只表示接口返回了该值，不表示资质已核验通过。
3. 把待审核状态当成缺少操作权限。样本中若材料处于待审核，只能记录为待核实，不能据此判定供应商无供货资格。

## 怎么确认配好了

1. 输入样本原文与拟稿句，比较“资质与质检报告齐备”与“可进入库存采购下单”是否同一主体、同一期间、同一字段。若原文未载明采购授权，则该拟稿句未获支持，记录证据缺口。
2. 输入样本中的报告编号与检测对象，比较接口返回值解析出的字段是否与原文一致。若返回值缺少报告编号或检测对象，记录为未获支持，不推断接口失败原因。
3. 输入样本中的有效期与报告签发日期，比较两者是否在同一字段上互斥。若有效期与签发日期分属不同字段，记录为待核实，不判定为矛盾。
