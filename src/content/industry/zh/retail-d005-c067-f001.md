# 社区团购团长运营的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

社区团购团长运营管理社区节点和佣金，不直接做冷链质检。库存采购与供应商资料涉及团长协议、佣金表、提货清单、社群公告，日更或每团更新。这些材料在 HTTP 接口与外部系统环节中，通常以请求参数、请求体和返回值的形式出现，需要逐项核对实际传入值与外部接口契约。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，实际操作与 Postman、ApiFox 类似。Params 为路径请求参数，GET 请求中居多；Body 为请求体，POST/PUT 请求中居多；Headers 为请求头，用于传递特殊信息。三种数据均可通过 `{{}}` 引用变量，URL 也可引用变量。变量来自全局变量、系统变量、前方节点输出。系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories。chatId 与 responseChatItemId 在测试模式下不存在，不把调试空值当成业务故障。返回值通过 JSON path 语法提取，可配置多个返回值解析接口响应。

假设演练样本：某社区团购平台与团长签署的团长协议原文写道：“本协议自双方签字之日起生效，有效期至 2025 年 12 月 31 日。团长负责本社区提货清单核对与社群公告发布。”一条待判定的交接请求拟稿句为：“请将团长协议、佣金表、提货清单通过 HTTP 接口推送至供应商资料系统，并确认协议已生效。”该请求需核对协议生效状态、推送对象与授权边界。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 比较方法 |
| --- | --- | --- |
| 请求地址 | 按外部接口文档选择，可引用变量 | 核对地址与方法是否匹配外部契约 |
| Params | 按外部接口文档填写路径参数 | 逐项核对键与值 |
| Headers | Authorization 使用 Bearer 加凭证 | 核对鉴权凭证是否安全注入 |
| Body | 仅在 POST/PUT 下使用，核对 JSON 结构 | 核对字段与外部接口契约 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 逐项核对实际传入值 |
| 返回值提取 | 按 JSON path 配置 key | 核对提取值与响应结构 |

## 容易做错的三处

1. 把测试模式下不存在的 chatId 或 responseChatItemId 当作业务故障。检查输入：测试模式请求；比较：系统变量说明中测试模式下不存在的条件；观察结果：确认该空值属于文档说明的测试模式行为。
2. 在 GET 请求中使用 Body。检查输入：GET 请求配置；比较：文档说明 Body 仅在特定请求类型下生效；观察结果：确认 GET 请求中 Body 不生效。
3. 将待判定的交接请求拟稿句中的“确认协议已生效”当作已生效事实。检查输入：团长协议原文与拟稿句；比较：协议生效需签字，拟稿句未提供签字状态；观察结果：确认该请求处于待核实状态，不能当作已生效执行。

## 怎么确认配好了

1. 输入假设演练样本中的团长协议原文与交接请求拟稿句；比较协议生效条件与拟稿句中的“确认协议已生效”；观察结果：拟稿句未提供签字状态，该请求处于待核实状态，不能当作已生效执行。
2. 输入假设演练样本中的交接请求拟稿句；比较推送对象“供应商资料系统”与团长协议中团长职责范围；观察结果：协议原文未载明供应商资料系统的推送授权，该推送请求处于待核实状态。
3. 输入假设演练样本中的团长协议原文；比较有效期“至 2025 年 12 月 31 日”与交接请求日期；观察结果：若交接请求日期在有效期内，协议有效期覆盖该请求；若超出，则需另行核实。
