# 社区团购团长运营的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

在社区团购团长运营的库存采购与供应商资料中，本页说明FastGPT的定时任务与自动化如何衔接资料。团长运营备货复查要区分群公告需求、提货安排与实际采购，清单汇集不证明供应商已接受。所用场景为自拟文字测试。

## 这些特征在「定时任务与自动化」这一环带来什么约束

自拟社区公告写“可登记需求”，提货清单列暂存名单，团长协议只说明协作范围。定期复查可查需求是否已有真实确认，不把登记人数或名单存在变成采购承诺，也不填写金额或效果数据。先核实际可用触发和读取条件，保留公告与名单原句；如果采购范围仍缺，应明确这次只完成备料核对，未确认供应商或发货。

## 配置怎么定

| 团长备货核对 | 自拟资料性质 | 确认要求 |
| --- | --- | --- |
| 社区公告 | 可登记需求 | 不直接作为确定订单 |
| 提货名单 | 暂存人员 | 不推定货已到 |
| 协作协议 | 说明合作范围 | 不替代下单授权 |
| 补齐变化 | 本次真实采购确认 | 仍留未定需求 |
| 触发结果 | 只完成材料核对 | 另核供应与通知 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `触发责任` | 先核可用触发入口及责任组件。 |
| `数据读取` | 外部读取接口需明确配置。 |
| `HTTP请求` | 请求按外部契约构造并核变量。 |
| `重复触发分工` | 去重、幂等及写入须另行实现。 |
| `执行记录` | 核真实触发、输入及业务返回。 |

## 容易做错的三处

登记冒订单：若需求登记被写成确定采购，应查本次真实确认；提货单冒到货：若暂存名单被当已备货，应取对应收货或供应记录；协议扩授权：若协作范围被当允许自动下单，应查实际授权依据。三项分别核需求状态、货物阶段和操作权限，不能由同一团长名称替代。

## 怎么确认配好了

验收保存触发、读取结果和缺确认清单，补入本次采购确认后再执行，核解释是否仍区分哪些需求尚未确定。材料没有变化时不虚报补齐，重复触发也不应被写成重复采购成功。对外下单、供应确认与提货通知需另接流程核回执；去重与业务写入按实际系统实现检查，任务计划不构成采购动作。
