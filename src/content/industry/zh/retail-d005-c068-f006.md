# 社区团购预售集单的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样

在社区团购预售集单的库存采购与供应商资料中，本页说明FastGPT的定时任务与自动化如何衔接资料。预售集单的周期检查要看截单通知覆盖范围和采购计划状态，汇总结果不是供应商确认。所用场景为自拟文字测试。

## 这些特征在「定时任务与自动化」这一环带来什么约束

自拟预售表含待确认组合，截单通知只覆盖蔬菜，集单结果却同时列水果，采购计划仍标草稿。定期读取可以安排检查哪些范围有依据，不预设到了某时点就全部变成有效订单。触发入口及资料读取按实际部署核实，不能从文件更新推定需求确认，也不从集单输出直接生成采购完成说明；供应商是否接单需要另有来源。

## 配置怎么定

| 预售备料复查 | 自拟范围 | 本次所需 |
| --- | --- | --- |
| 截单通知 | 只覆盖蔬菜 | 水果需对应来源 |
| 集单结果 | 另含水果 | 不直接判定全部有效 |
| 采购计划 | 草稿 | 另取供应商确认 |
| 需求状态 | 组合待确认 | 结果继续保留 |
| 实际业务 | 下单预留通知另核 | 复查不证明供货 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `触发责任` | 先核可用触发入口及责任组件。 |
| `数据读取` | 外部读取接口需明确配置。 |
| `HTTP请求` | 请求按外部契约构造并核变量。 |
| `重复触发分工` | 去重、幂等及写入须另行实现。 |
| `执行记录` | 核真实触发、输入及业务返回。 |

## 容易做错的三处

截单范围扩大：若蔬菜通知被用于水果，应核通知原文和集单品类；草稿冒承诺：若采购计划被写成已接受，应取供应商确认；待确认被清除：若触发输出不再保留需求状态，应对照本次输入和结果。三项分别核范围、对方立场和数据传递，不能由定期运行解决。

## 怎么确认配好了

验收保留输入版本和触发结果，补水果对应通知后再查范围变化，供应商确认仍缺时仍留待核。对没有确认的组合，不能由旧轮次结论补齐。正式下单、库存预留与群内通知需要另接实际步骤并核回执；多次触发时是否重复处理按真实实现检查，材料复查通过不证明预售采购已执行或供货可保障。
