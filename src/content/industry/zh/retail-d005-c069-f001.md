# 经销商返利核算的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

经销商返利核算发生在销售之后，处理的是政策口径与财务冲抵，数据来源集中在 ERP 销售记录、经销商回款、合同台账与财务系统，更新节奏以月、季为主。库存采购与供应商资料这一任务，需要把采购入库数量、供应商对账余额、返利政策适用区间三类材料放在同一口径下核对。返利争议与收入确认错误需要核对口径一致性，并检查资料是否齐备。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径参数，Body 用于 POST/PUT 请求体，Headers 传递特殊信息，URL 与三类数据均可通过 `{{}}` 引用全局变量、系统变量、前方节点输出。返回值按 JSON path 提取，出参可选择字符串类型。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试空值不构成业务故障。对话接口调用时 `model`、`temperature` 由编排决定，API 参数不改变其值。

假设演练样本：某品牌财务提供的返利政策原文为「2024 年 7 月至 9 月，经销商 A 完成季度采购目标后按回款额 2% 计提返利，退货金额从达成口径中扣除」。同一批材料中的对账单显示 8 月退货一笔，红字发票尚未开具。待判定拟稿句为「经销商 A 第三季度返利已具备开票冲抵条件」。原文未给出目标完成与退货扣除结果，也未载明开票冲抵条件，该句未获支持；红字发票状态单独记录。

## 配置怎么定

| 配置项 | 取值来源 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 外部接口文档 | 地址可引用变量，方法按契约选择 |
| Headers 鉴权 | 安全配置注入 | 凭证不写入公开样例 |
| Body 结构 | 外部接口契约 | 仅相应请求类型下生效 |
| 变量引用 | 全局变量、系统变量、前方节点输出 | 逐项核对实际传入值 |
| 返回值提取 | JSON path 语法 | 出参类型与下游用途一致 |
| 调试身份字段 | chatId、responseChatItemId | 测试模式下不存在，记录为空属预期 |

本次核对以原文的 2024 年 7 月至 9 月为区间，确认 8 月退货属于该季度；合同台账未提供，不据此确认周期或达成结果。

## 容易做错的三处

1. 将同一份返利政策原文中的季度区间与对账单月份直接等同，未核对退货扣除条款，导致达成口径被高估。检查：输入政策原文与对账单，比较退货金额是否已从达成口径扣除，观察两项数值是否同期间同字段。
2. 把对话接口返回的 `model` 字段当作可调参数写入请求体，认为 API 参数能改变编排结果。检查：输入含 `model` 的请求体，比较响应中实际使用的模型标识，观察其是否与编排一致。
3. 将测试模式下 chatId 为空解释为会话链路故障。检查：输入测试模式请求，比较系统变量说明，观察 chatId 与 responseChatItemId 是否按文档标注为不存在。

## 怎么确认配好了

1. 输入假设样本中的返利政策原文与对账单，比较退货金额是否从达成口径中扣除，观察两项数值是否同主体、同期间、同字段。样本未给出退货金额和扣除结果，记录缺口，不假定已经扣除。
2. 输入拟稿句「经销商 A 第三季度返利已具备开票冲抵条件」，核对目标达成、退货扣除证据与开票冲抵条件。样本只给政策和未开具状态，证据不足，保持待核实。
3. 输入含 `model`、`temperature` 的请求体，比较响应中的模型标识与编排配置，观察 API 参数是否改变了实际取值。记录实际模型与编排配置的对照结果；参数字段无效的依据是接口文档，单次结果一致不能独立证明该规则。

检索与相似度不承担权限或实体隔离，跨向量模型的库不可共同关联，需先核对标识并排除不符合者。空结果可按明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索必然返回空。
