# 跨境商品合规与标签的库存采购与供应商资料：向量模型与索引

## 这个品类的数据长什么样

库存采购与供应商资料环节要处理的合规材料包括产品测试报告、英文标签、MSDS 和平台禁售清单。这些材料的共同点是来源分散、版本不定期更新、每次上新都要重新核对。采购人员需要从供应商处取得材料，再判断目的国要求是否已被覆盖。

向量模型与索引在这里的作用是让上述材料可被检索到。材料入库时的分块方式、索引内容长度、是否建立图片索引，直接决定后续能否召回对应证据。供应商提交的扫描件若只有图片、入库时未生成图片描述索引或图片向量索引，检索端上传图片也无法命中该材料。

## 这些特征在「向量模型与索引」这一环带来什么约束

关联检索的知识库须使用相同向量模型，选库时先核实际模型与输入类型，不符者排除，不执行跨模型检索来比较漏召回。一个原数据块可以关联多个索引，索引与原文内容分别核对。索引内容宜完整且聚焦，检索覆盖与索引长度需结合样本权衡。图片检索还取决于入库时是否生成图片描述或图片向量，查询端上传图片仅是一个条件。

语义召回和相关度不负责权限或实体隔离。最低相关度是过滤阈值，不是最终排序规则。开启问题优化、混合检索、图片检索或结果重排后，最终结果可能经多路召回融合，不一定严格按单一向量相似度排序。RRF 是混合结果融合过程，不作为开启开关。引用上限以 tokens 为单位控制每次搜索最多引用的内容量。

假设演练样本：某供应商于 2026 年 3 月提交一份英文标签草稿，正文含“Product name: A 型清洁剂”“Batch code: 20260310”“Country of destination: 德国”。同批材料中另有一份待交接请求：“请把上述标签草稿录入知识库，供采购核对目的国标签要求时检索。”该请求处于待处理状态，未获批准，未执行入库。上述主体、对象、状态与范围仅用于本页纸面核对。

## 配置怎么定

| 配置项 | 本页相关取值或核对动作 | 依据与边界 |
| --- | --- | --- |
| 关联知识库的向量模型 | 先核各库实际向量模型标识，仅关联标识一致的库 | 官方说明要求相同向量模型 |
| 索引与原数据对应 | 核对一个原数据块的 indexes 数组与其原文内容 | 索引与原文分别核对 |
| 索引内容长度 | 本次假设试验起点设为聚焦标签字段的短索引，与含整页说明的长索引比较召回覆盖 | 起点为本次假设，非官方默认 |
| 图片索引 | 入库时确认是否生成图片描述索引或图片向量索引 | 查询端上传图片不足以命中 |
| 搜索模式 | 编号、型号类查询用全文检索或混合检索 | 官方调参建议 |
| 引用上限与最低相关度 | 按 tokens 设引用上限；最低相关度仅在语义检索或重排时生效 | 官方参数说明 |

## 容易做错的三处

1. 把待处理请求当作已入库。输入是上述交接请求，比较其状态字段“待处理”与“已执行”，观察到状态仍为待处理即属未执行，不得据此认为材料已在库中可被检索。
2. 跨向量模型强行关联。输入是两个向量模型标识不同的知识库，比较标识是否一致，观察到不一致即排除，不推测共同关联后的召回表现。
3. 用查询端上传图片代替入库索引。输入是仅含图片的扫描件与一次图片查询，比较入库记录中是否存在图片描述索引或图片向量索引，观察到缺失即记录缺口，不将查询端行为当作已建立索引。

## 怎么确认配好了

1. 取假设样本中的标签草稿原文，输入检索词“Batch code 20260310”，比较召回内容是否包含该批次号原文，观察到引用内容含该字段且来源指向该原数据块，方满足。预期如此，未实测。
2. 取假设样本中的交接请求，输入其状态字段，比较状态取值与“已执行”，观察到仍为待处理即确认入库未发生，属未获支持，不判为否定或冲突。
3. 取两个向量模型标识不同的库，输入标识字段，比较是否一致，观察到不一致即排除关联；若需核对空结果承接，可用纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回 `[]`。
