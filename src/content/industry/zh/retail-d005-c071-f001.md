# 跨境平台结算与汇兑的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

库存采购与供应商资料在结算汇兑业务里承担资金归集前的凭证职责。平台结算单记录订单扣费与净额，汇率表记录折算依据，服务费发票记录成本，收款对账表记录到账明细。这些材料按周或按月更新，与支付风控场景关注的欺诈拒付没有交集，核对对象是已成交订单的资金归集结果。

HTTP 接口与外部系统环节把上述资料从采购系统或供应商系统取回，供后续核对。取回动作只完成数据搬运，不改变采购单、发票或对账表自身的业务状态。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

请求地址与方法按外部接口文档确定，地址可通过变量引用。Params 用于路径参数，Headers 用于鉴权与特殊信息，Body 仅在相应请求类型下生效。变量来源为全局变量、系统变量、前方节点输出，均以 `{{}}` 引用。返回值通过 JSON path 提取，输出类型为字符串时会把对应值转为 json 字符串。

假设演练样本。供核对的材料原文：某供应商系统接口文档写明“本接口返回采购单号、供应商名称、含税金额、币种、单据状态”；采购系统导出的记录写明“采购单号 PO-2024-0517，供应商名称 星海配件，含税金额 12000.00，币种 CNY，单据状态 已提交”。一条待判定的交接请求拟稿句：“该采购单已通过审核，可计入本期库存成本。”

chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于环境现象，不能据此判定业务故障。接口返回的单据状态为“已提交”，与“已通过审核”属于不同事实，拟稿句把提交状态写成审核通过，超出原文证据范围。

## 配置怎么定

下表围绕上述样本，列出与本功能、主任务相关的已说明设置或实施核对项。数值项为本次假设试验起点，用于与接口实际返回值比较，不代表官方默认值。

| 配置项 | 本次设定或核对内容 | 选取理由与比较对象 |
| --- | --- | --- |
| 请求地址 | 按供应商系统接口文档填写，路径参数以 `{{}}` 引用 | 与文档给出的接口路径逐字符比对 |
| 方法 | 按文档要求选择，取回采购单用读取类方法 | 与文档方法字段比对 |
| Headers | 鉴权凭证由安全配置注入，样例中不写明文 | 与文档鉴权要求比对 |
| Body | 仅在文档要求请求体时填写，核对 JSON 结构 | 与文档请求体字段清单比对 |
| 返回值提取 | 按 JSON path 提取采购单号、供应商名称、含税金额、币种、单据状态 | 与材料原文五个字段逐一比对 |
| 输出类型 | 单据状态按字符串输出 | 与原文文本值比对 |

## 容易做错的三处

1. 把接口返回的“已提交”直接当作“已通过审核”写入交接材料。输入是返回值字段“单据状态=已提交”，比较对象是原文措辞，可观察结果是拟稿句出现“已通过审核”而原文无此表述。
2. 在 Body 中引用字符串变量时漏掉外层引号。输入是 `"{{supplierName}}"` 与 `{{supplierName}}` 两种写法，比较对象是文档给出的 Body 声明示例，可观察结果是后者无法得到带引号的字符串值。
3. 把测试模式下缺失的 chatId 或 responseChatItemId 判定为接口异常。输入是调试环境的返回，比较对象是文档关于测试模式不存在的说明，可观察结果是误报故障而实际请求参数正常。

## 怎么确认配好了

1. 取假设样本原文，输入五个字段的实际返回值，比较“单据状态”字段值与原文“已提交”是否一致，一致则提取正确；拟稿句中的“已通过审核”仍属未获支持。
2. 取假设请求的 Body 声明，输入含引号与不含引号两种写法，比较返回解析结果是否为带引号的字符串，出现预期字符串则写法正确。
3. 取假设样本的采购单号 PO-2024-0517，输入提取结果，比较是否与原文完全一致，一致则字段映射正确；供应商名称、金额、币种同样逐字段核对，任一不符则记录待核实，不判定为冲突。

以上核对只针对取回与字段映射，采购单是否通过审核、能否计入成本属于另需业务系统确认的事实，本页不代为判定。
