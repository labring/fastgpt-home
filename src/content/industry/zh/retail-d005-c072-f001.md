# 跨境海外仓补货管理的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

第三方海外仓可服务多个渠道，库存由卖家自行分配，补货计划、入仓预约、库存库龄表与尾程派送单分散在海外仓WMS、ERP销售预测、货代系统与承运商账单之间。采购与供应商资料要在这几类来源之间传递，HTTP 模块承担向外部地址发送请求并解析响应的职责，实际操作方式与 Postman、ApiFox 这类工具接近。变量来自全局变量、系统变量与前方节点输出，URL、Params、Headers、Body 均可通过双花括号引用变量。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

Params 为路径请求参数，GET 请求中用得居多；Body 为请求体，POST/PUT 请求中用得居多；Headers 用于传递特殊信息。Body 只在特定请求类型下生效。返回值配置表示如何解析接口返回值，通过 JSON path 语法提取，规则遵守 JS 对象取值规则；输出类型选字符串时，会把对应 key 的值转成 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在。对话接口以 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，appId 优先级为 body.appId、apiKey-appId、apikey 关联的 appId。传入的 model、temperature 等字段由编排决定，不随 API 参数改变。

假设演练样本：某跨境卖家拟把供应商交期写入补货计划。供核对材料原文为“供应商A于假设日期范围2025年3月1日至3月31日提交的报价单载明交货周期30天，报价有效期至2025年4月15日；该报价单未载明是否已签署采购合同”。待判定拟稿句为“供应商A已确认30天供货并已生效”。该句把报价有效期与供货期限混为一谈，签署、合作达成、合同生效是三个不同事实，材料未载明合同状态，判定为未获支持、待核实。

## 配置怎么定

| 核对项 | 假设起点 | 比较对象与理由 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写 | 与供应商系统接口契约逐字比对，地址可引用变量 |
| Params 与 Headers | Authorization 用 Bearer 加凭证变量 | 与密钥使用规范比对，凭证不写入公开样例 |
| Body | 仅在 POST/PUT 下声明 JSON | 与外部接口契约比对，字符串引用需加双引号 |
| 返回值解析 | 按 JSON path 配置 key | 与接口响应示例比对，输出类型决定是否转字符串 |
| 会话标识 | 假设 chatId 取业务单号 | 长度小于250且唯一，与接口参数说明比对 |

## 容易做错的三处

1. 把报价有效期当作供货期限。输入是上述报价单原文，比较“报价有效期至2025年4月15日”与“供货期限30天”两个字段，两者含义不同，拟稿句据此断言已确认供货属于未获支持。
2. 把测试模式下的空值当作业务故障。输入是测试模式下发起的请求，比较 chatId 与 responseChatItemId 是否存在，文档说明这两个字段在测试模式下不存在，不能据此判定外部系统异常。
3. 把返回值配置当作接口返回值本身。输入是已配置的提取 key，比较提取结果与接口原始响应，配置只表示如何解析，输出类型选字符串会改变呈现形式。

## 怎么确认配好了

1. 针对报价单原文与拟稿句，检查拟稿句是否出现“已确认供货”“已生效”等表述，材料未载明合同状态时，观察结果应为待核实，不满足条件即需改写。
2. 针对测试模式请求，检查 chatId 与 responseChatItemId 是否为空，文档说明其不存在，观察结果应为空值属预期，出现报错才需另查。
3. 针对返回值配置，检查提取 key 与接口响应结构是否对应，观察输出类型为字符串时是否转为 json 字符串，与接口响应示例不一致即需修正。
