# 跨境退货翻新与二次销售的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

跨境退货翻新与二次销售处理逆向物流和商品状态，与海外仓头程补货不同。数据来源包括海外仓WMS、TikTok退货中心、Amazon退货报告和商品质检照片，日常文档有退货质检表、翻新记录、报废单和二次上架清单。资料给出的更新频率为日、每批。库存采购与供应商资料这一任务中，采购单、供应商档案与退货质检结论需要与外部系统交换，HTTP 模块承担向外部地址发送请求并解析返回值的角色。退货等级判断、翻新包装安排、报废或重售决定三个环节耗时最多，接口传参的字段口径直接决定这些判断依据能否落到外部系统。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 为路径请求参数，Body 为请求体，Headers 为请求头，三者均可用 `{{}}` 引用变量，URL 也可引用变量。变量来自全局变量、系统变量和前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值配置的是解析方式，通过 JSON path 从响应中提取值，输出类型选择字符串时会把对应值转成 json 字符串。对话接口使用 APIKey 鉴权，推荐在请求体传入 body.appId，也支持 Authorization: Bearer 组合形式；传入的 model、temperature 等字段由编排决定，不随 API 参数改变。authProxy 代理团队成员身份需要团队所有者开启，代理身份仍需具备目标应用和会话权限。

假设演练样本：某跨境卖家售后主管在 2025 年 3 月 10 日整理一批退货，材料原文为“退货质检表编号 RT-0310-07，商品为折叠收纳箱，质检结论为外观轻微划痕，状态为待翻新；报废单编号 SC-0310-02，同一商品状态为待审核；二次上架清单尚未生成。”一条待判定的交接请求拟稿句为“RT-0310-07 已完成翻新并可直接二次上架”。授权边界为售后主管仅提交质检结论，翻新执行与上架决定属另一岗位。

## 配置怎么定

| 配置项 | 本页对应设置 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址可引用已提供变量 | 对照外部接口文档逐项核对 |
| Params 与 Headers | 分别填写路径参数与请求头，鉴权凭证通过安全配置注入 | 核对键名与外部接口契约一致 |
| Body | 仅在相应请求类型下使用，核对 JSON 结构与契约 | 逐字段对照外部接口文档 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 逐项核对实际传入值 |
| 返回值解析 | 配置 key 与 JSON path，选择输出类型 | 用响应示例比对提取结果 |
| 调试身份字段 | chatId 与 responseChatItemId 测试模式下不存在 | 不把调试空值当作业务故障 |

本次假设试验起点：将 RT-0310-07 的质检结论字段作为变量传入 Body，选择该起点是因为该字段是外部系统判断翻新等级的直接输入；与外部接口文档声明的字段类型比较，不设默认值。

## 容易做错的三处

1. 把待翻新状态当作已完成翻新。质检表原文写“状态为待翻新”，翻新记录尚未出现，拟稿句却称“已完成翻新”，同一字段取值互斥，属未获支持。
2. 把报废单待审核当作报废已批准。报废单编号 SC-0310-02 状态为“待审核”，待审核不证明缺少操作权限，也不等于批准，属待核实。
3. 把二次上架清单未生成当作可上架。清单尚未生成，拟稿句称“可直接二次上架”，缺少清单主体与状态证据，属证据缺口。

## 怎么确认配好了

1. 输入 RT-0310-07 质检表原文与拟稿句，比较“待翻新”与“已完成翻新”两个取值，出现同字段互斥取值即判定未获支持。
2. 输入 SC-0310-02 报废单原文，比较“待审核”与任何批准表述，出现批准表述即判定待核实，保留证据缺口。
3. 输入“二次上架清单尚未生成”与拟稿句，比较清单是否存在，清单缺失时拟稿句的“可直接二次上架”判定为证据缺口，不补造授权条款。
