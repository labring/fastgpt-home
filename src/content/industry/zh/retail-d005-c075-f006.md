# 达人专场带货合作的库存采购与供应商资料：定时任务与自动化

## 这个品类的数据长什么样
达人专场带货合作依赖外部达人履约与佣金结算，品牌商务、MCN机构与达人经纪围绕精选联盟、巨量星图、达人历史数据与店铺成交明细展开工作。库存采购与供应商资料环节要处理的文档包括达人合作协议、佣金设置单、样品寄送单与直播战报，数据更新频率为每场与每周。资料给出的更新频率只到这一层，不推出批量同步、全量同步、实时或交易触发机制。这些特征决定定时任务与自动化只能承担资料读取与请求发起，业务授权与写入需要另行设计。

## 这些特征在「定时任务与自动化」这一环带来什么约束
触发责任需要明确由应用定时能力还是外部调度承担，并按实际版本核对可用入口。外部数据由已配置接口读取，定时触发本身不建立业务系统连接。HTTP请求按外部接口文档核对方法、请求头、请求体与变量输入。去重、幂等与业务写入需在接口或后续流程明确设计，不宣称自动具备。执行记录核对触发时间、真实输入、返回结果与业务状态，任务存在不替代执行成功。检索与表单收集值，业务验证、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：某品牌商务持有两份待核对材料。材料一为达人合作协议，原文写“甲方委托乙方于2025年6月1日至6月30日期间完成两场专场直播，样品由甲方寄送，佣金按店铺成交明细结算”。材料二为样品寄送单，原文写“寄送对象：乙方指定收货人；寄送数量：每场样品三件；寄送状态：待寄出”。一条待判定的交接请求写“请定时任务在6月1日自动确认合作已生效并同步供应商库存”。该请求把待寄出状态当成已完成寄送，把协议期间当成合作已生效，授权边界未获支持。

## 配置怎么定
下表围绕上述样本，列出官方已说明设置或实施核对项。数值为本次假设试验起点，选择理由与比较对象一并写明，不描述为官方默认。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 触发来源 | 外部调度触发 | 资料未说明应用侧定时入口，先核实际版本可用入口 |
| 请求方法 | POST | 按外部接口文档核对，与接口文档声明的方法比较 |
| 请求头 | Authorization 为 Bearer {{token}} | 按接口文档核对，与文档要求的请求头字段比较 |
| 请求体 | 引用 {{appId}} 与 {{appointment}} | 按接口文档核对，与文档声明的字段名比较 |
| 返回值提取 | key 为 data.user.name | 按 JSON path 规则核对，与接口响应示例比较 |
| 执行记录 | 记录触发时间与返回结果 | 与业务状态比较，任务存在不替代执行成功 |

## 容易做错的三处
1. 把待寄出状态当成已完成寄送。材料二只写“寄送状态：待寄出”，未写寄出时间与签收结果，该状态不能支持自动确认寄送完成。
2. 把协议期间当成合作已生效。材料一只写委托期间，未写签署、生效或授权条款，不能据此触发自动确认合作生效。
3. 把检索或表单当成授权执行。检索与表单收集值，业务验证、审批、数据库写入与外部同步需要各自的下游实现，请求中“自动同步供应商库存”缺少对应下游设计。

## 怎么确认配好了
1. 输入材料一原文与材料二原文，比较“待寄出”与“已完成寄送”两种取值，只有材料二出现寄出时间与签收结果时，寄送完成才获支持；当前记录为未获支持。
2. 输入材料一原文与待判定请求，比较协议期间与合作生效两种事实，只有材料一出现签署或生效条款时，合作生效才获支持；当前记录为待核实。
3. 输入待判定请求与配置表，比较请求中“自动同步供应商库存”与下游实现字段，只有存在明确下游接口或写入设计时，该动作才可执行；当前记录为缺口，需保留缺失证据。
