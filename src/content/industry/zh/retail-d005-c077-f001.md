# 进出口许可证件办理的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

许可证办理发生在申报之前，决定货物能否合法进出口，因此库存采购与供应商资料环节需要同时处理商务主管部门系统、海关商品编码、供应商资料与客户用途说明。日常文档包括自动进口许可证、两用物项许可证、合同与产品说明。这些材料的更新不定期、按每票发生，HTTP 接口在这一环承担把外部返回的证件状态、商品编码或供应商信息引入编排流程的作用。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径请求参数，Body 用于请求体，Headers 用于请求头，三者均可用 `{{}}` 引用全局变量、系统变量和前方节点输出，URL 同样可引用变量。返回值配置的是解析方式，通过 JSON path 从响应中提取所需值，输出类型选择字符串时会转成 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于该模式的表现，不能据此判断业务异常。对话接口的 `model`、`temperature` 等参数字段由编排决定，传入无效；不会返回实际消耗 Token 值，需要时设置 detail=true 并手动计算 responseData 里的 tokens。交互节点返回给外部调用方的 interactive 只含 type 与 params，内部运行态字段不返回。

假设演练样本：一份纸面材料记载，某外贸企业于 2026 年 3 月 10 日就一批数控机床备件向供应商发出采购询价，供应商当日回复报价单，报价单载明有效期至 2026 年 3 月 31 日，随附产品说明称该备件用于一般工业设备维修。同日关务人员提出一条待判定拟稿句：「供应商已确认供货，可据此提交自动进口许可证申请。」该句与材料原文的差异需要逐项核对。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址 | 引用前方节点输出的外部接口地址变量 | 与外部接口文档给出的地址逐字符比对 |
| 请求方法 | 按外部接口文档选定 | 比对文档标注的方法与当前配置 |
| Headers 鉴权 | 通过安全配置注入凭证 | 检查凭证未写入公开样例与页面正文 |
| Body 结构 | 按外部接口契约组织 JSON | 逐字段比对键名与值的类型 |
| 返回值提取 | 按 JSON path 配置 key | 用响应样例验证提取结果与预期一致 |
| 输出类型 | 字符串或原始类型 | 检查转换结果是否满足下游拼接需要 |

上述起点为本次假设试验的取值，选择原因是便于逐项比对，不代表任何官方默认值。

## 容易做错的三处

1. 把报价单有效期当作供货期限。假设样本中报价单有效期至 2026 年 3 月 31 日，材料未载明供货期限，两者属于不同字段，不能互相替代。
2. 把供应商报价回复当作供货确认。样本中供应商回复的是报价单，材料未记载接受报价或签署合同的动作，拟稿句中的「已确认供货」缺少依据。
3. 把测试模式下的空 chatId 当作接口故障。文档说明该字段在测试模式下不存在，需要区分调试环境与生产环境的表现。

## 怎么确认配好了

1. 输入假设样本的材料原文与拟稿句，比较拟稿句中的「已确认供货」与材料记载的报价回复，材料未出现接受或签约表述时，该句属于未获支持，需要记录证据缺口。
2. 输入报价单有效期 2026 年 3 月 31 日与拟稿句中的提交申请表述，比较两者是否指向同一事实，有效期字段不构成供货或申请授权，判定为待核实。
3. 输入一条引用前方节点输出的请求地址变量，比较实际发出的地址与外部接口文档给出的地址，两者一致且返回值按配置的 key 提取成功时，该配置项满足条件；提取为空时记录实际观察，不推断具体报错原因。
