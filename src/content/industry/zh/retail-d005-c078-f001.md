# 连锁总部选址开店的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

选址开店工作在门店营业前完成，围绕租赁与工程交付展开，日常材料包括选址评估表、租赁意向书、装修预算和开业排期。库存采购与供应商资料处于同一批拓展文档流中，供应商报价单、采购清单与门店排期表往往并行流转，更新节奏为不定期、每店一次。这类资料由连锁总部拓展、区域开发和工程经理共同处理，出错会带来开店亏损、延期交付或押金损失。HTTP 接口与外部系统这一环要解决的是：把上述材料中的字段按外部接口契约发出去，并取回可核对的结果，不承担授权、审批或数据库写入。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params、Headers、Body 与 URL 均可通过 `{{}}` 引用全局变量、系统变量或前方节点输出。系统变量含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值解析通过 JSON path 提取，输出类型选字符串时会把对应 key 的值转为 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传 body.appId，也支持 Authorization: Bearer 形式；appId 优先级为 body.appId、apiKey 与 appId 组合、apikey 关联的 appId。传入的 model、temperature 等参数无效，由编排决定。detail=true 时中间值出现在 responseData 中，stream 模式通过 event 区分。这些是节点已有行为与可配置字段；业务审批、数据库写入和外部同步需要另行实现。

假设演练样本：某连锁总部拓展部一份纸面材料记录，主体为总部拓展组，对象为某候选门店的供应商报价单，状态为“意向阶段、报价有效期至 2026 年 3 月 31 日”，范围为 2026 年第一季度开业排期。待判定拟稿句为：“该供应商报价已通过系统接口提交并完成采购入库。”请判断该句是否被材料支持。

## 配置怎么定

| 配置项 | 取值来源 | 核对方式 |
| --- | --- | --- |
| 请求地址 BaseUrl | 外部接口文档给定；本次假设试验起点为文档示例地址 | 与接口文档逐字符比对 |
| 请求方法 | 按外部接口契约选择，如 POST | 与接口文档声明的方法比对 |
| Headers 鉴权 | Authorization 通过安全配置注入 | 确认凭证未写入公开样例 |
| Body 结构 | 按外部接口契约声明 JSON，引用变量加 `{{}}` | 与接口契约字段名比对 |
| 返回值提取 | JSON path 语法配置 key | 与接口响应示例比对 |
| 调试身份字段 | chatId、responseChatItemId 测试模式下不存在 | 确认未把调试空值当业务故障 |

表中数值为本次假设试验起点，选此值是为与接口文档声明比对，不作为官方默认值。

## 容易做错的三处

1. 把请求地址或方法写成与外部接口文档不一致。检查输入为文档声明的地址与方法，比较对象为配置中的 BaseUrl 与请求方法，观察结果为两者逐字符一致。
2. 在 Body 中引用字符串变量时漏加引号，导致 JSON 结构改变。检查输入为含 `"{{string}}"` 的 Body 声明，比较对象为文档示例的解析结果，观察结果为解析后类型与示例一致。
3. 把检索或表单提交当作授权执行。检查输入为假设样本中的“意向阶段、报价有效期至 2026 年 3 月 31 日”，比较对象为拟稿句中的“已提交并完成采购入库”，观察结果为材料未载明提交与入库记录，判定为未获支持。

## 怎么确认配好了

1. 使用假设样本原文，输入为“意向阶段、报价有效期至 2026 年 3 月 31 日”，比较对象为拟稿句“已通过系统接口提交并完成采购入库”，预期现象为材料未载明提交与入库，结论为未获支持，待核实。
2. 输入为文档给出的 Body 声明示例，比较对象为最终解析示例，预期现象为字符串、数字、布尔、数组与对象的解析结果与示例一致。
3. 输入为接口响应示例与配置的提取 key，比较对象为文档列出的提取示例，预期现象为各 key 取值与示例相同；若响应为空数组 []，则记录为空结果并核对下游设计，不推断虚构规则一定返回 []。
