# 连锁总部选址开店的库存采购与供应商资料：文档解析与分块

## 这个品类的数据长什么样
连锁总部选址开店发生在门店营业前，核心工作是租赁与工程交付，资料以每店为一批、不定期产生。本任务处理的是库存采购与供应商资料，与选址评估表、租赁意向书、装修预算、开业排期同属一批开店材料。这类资料包含供应商报价单、采购清单、供货范围说明与交期条款，主体、对象、有效范围分散在正文和附件中，条件句与它所约束的报价、数量经常相邻出现。解析与分块若把条件与约束拆开，检索到的片段会缺少判断所需的限定信息，后续人工核对只能回到原文。

## 这些特征在「文档解析与分块」这一环带来什么约束
库、集合、数据三层结构中，集合仅用于分类管理，最小搜索单位是库。原数据存于 MongoDB 的 dataset.datas，indexes 字段记录对应向量 ID，一组数据可对应多个向量；PostgresSQL 的 vector 字段存向量，检索先召回向量再按 ID 回 MongoDB 合并，同组原数据取最高得分。分段应保持结构与语义完整，index 内容精简可提高精度但缩小检索范围。语义检索、全文检索、混合检索经 RRF 融合，重排得分可用于过滤；最低相关度是阈值，不承担实体或权限隔离，检索本身也不构成授权。

假设演练样本。供核对材料原文：“本报价单由甲供材供应商于2024年3月1日出具，供货范围为华东区域新开门店的后厨不锈钢台面，报价有效期30日。采购方须在报价有效期内以书面订单确认数量，订单经总部采购负责人签署后生效。”待判定拟稿句：“该供应商已完成供货，总部已批准本次采购。”原文只载明报价主体、对象、有效期与订单生效条件，未载明签署、批准或供货事实。

## 配置怎么定
| 核对项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 分段方式 | 按报价单条款边界切分，条件句与所约束内容同段 | 与按固定长度切分的结果比较，观察条件是否随约束保留 |
| 索引数量 | 同一组数据建立一组文本索引 | 与建立多组索引的结果比较，观察召回范围变化 |
| 搜索模式 | 语义检索与全文检索并用 | 与单一语义检索比较，观察编号与专有名词命中情况 |
| 最低相关度 | 本次假设试验起点取0.3 | 与不设阈值的结果比较，观察低相关片段是否减少 |
| 引用上限 | 本次假设试验起点取2000 tokens | 与更小取值比较，观察条件句是否被裁掉 |
| 更新后复核 | 资料变更后核对训练与索引状态 | 与仅确认上传成功比较，观察检索是否反映新版本 |

以上数值为本次假设试验起点，不是官方默认值。RRF 是混合结果的融合过程，不作为开关配置。图片检索需有图像输入与相应模型能力，重排需具备模型并按设置启用，二者不是每次请求都执行。

## 容易做错的三处
1. 把条件句与它所约束的报价、数量拆到不同段。检查输入为上述原文与拟稿句，比较检索返回片段是否同时含“报价有效期30日”与“书面订单确认数量”，观察条件缺失时拟稿句是否被误判为有据。
2. 把最低相关度当作实体或权限过滤。输入同一问题与两个不同供应商的报价片段，比较返回结果是否按主体区分，观察阈值调整是否改变主体归属。
3. 把上传成功当作检索已更新。输入变更后的报价单版本与旧版本，比较检索命中的有效期与供货范围，观察返回内容对应哪一版本。

## 怎么确认配好了
1. 用原文中的“华东区域”“后厨不锈钢台面”“报价有效期30日”分别作检索输入，比较返回片段是否保留主体、对象与有效范围，条件满足时拟稿句仍应判为未获支持。
2. 用拟稿句“该供应商已完成供货，总部已批准本次采购”作输入，比较返回片段是否含签署、批准或供货字样，未出现时记录为证据缺口，待核实。
3. 以空引用输入核对下游设计，比较系统在无命中时的输出是否为空并保留缺口记录，不推断虚构规则必然返回空结果。跨不同向量模型的库不共同关联，先核标识并排除不符合者，记录实际观察。
