# 连锁统采统配的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

在连锁统采统配的库存采购与供应商资料中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。统采资料接口区分总部需求、区域供货与组件覆盖，目录成功返回不代表采购承诺成立。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

自拟总部需求单尚待批准，供应回复只覆盖某区域，产品目录缺配套组件。按真实契约核请求方法、地址和各类参数，把区域、商品及版本从前方输出逐项对到输入。认证安全注入，不能把接口可查等同总部采购权限。本例不提供金额或实际采购结果。

## 配置怎么定

| 统采资料HTTP | 自拟缺项 | 核对依据 |
| --- | --- | --- |
| 总部需求 | 等待批准 | 非正式订单 |
| 供应区域 | 仅指定地域 | 不扩全连锁 |
| 组件目录 | 配套尚缺 | 不推整套可供 |
| 请求映射 | 区域商品版本 | 核实际输入 |
| 业务写回 | 采购配送另接 | 权限及回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

待批需求被答正式订单时，查审批与下单凭据；某区域回复套全连锁时，核适用地域；缺配件目录被答整套可供时，查组件说明。三处分别核决策阶段、供应范围和资料覆盖，不能由响应成功补承诺。

## 怎么确认配好了

验收需求原句与供应回复分开定位，组件缺项紧邻商品身份，正文只返回摘要时标待核。补区域说明只更新该地域，订单状态仍独立查。采购批准、配送指派和库存写回需真实业务流程、接口及权限回执，HTTP节点只按契约传递所给数据，不确认供应方认可未写明条件。 总部需求和区域供应分别列原文位置，配套组件未给时标明具体缺口；需求批准材料不能替供应方承诺，全链采购范围仍以各份材料适用条件核对。

| --- | --- |
| 文档类型 | 集采合同、补货计划、配送单、门店要货单 |
| 候选来源 | ERP采购、WMS、门店POS、供应商交货数据 |
