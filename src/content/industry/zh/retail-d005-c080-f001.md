# 连锁门店价格与陈列稽核的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样
价格与陈列稽核发生在日常经营期，核心是标准持续执行。数据来自督导系统、POS 价格表、门店摄像、总部促销档期，日常文档包括巡店照片、价签清单、陈列标准、整改通知。本页任务为库存采购与供应商资料，这些资料常以 HTTP 接口方式与外部系统交换。资料更新频率为周或月，本页不据此推断批量同步或实时触发机制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块可重复添加、手动配置、触发执行。Params 用于路径请求参数，Body 用于请求体，Headers 用于请求头，三者均可通过 {{}} 引用变量，URL 同样可以引用变量。变量来自全局变量、系统变量与前方节点输出。返回值通过 JSON path 提取，输出类型选择字符串时会转为 json 字符串。系统变量 chatId 与 responseChatItemId 在测试模式下不存在，调试空值属于预期现象。对话接口调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>。传入的 model、temperature 字段无效，由编排决定。authProxy 代理团队成员身份需团队所有者开启，代理身份仍需具备目标应用和会话权限。

假设演练样本：一份拟通过 HTTP 模块提交的供应商资料交接请求，材料原文为「供应商甲于本年度第三季度列入合格供应商名录，供货范围为冷藏乳制品，授权对接人为乙。」拟稿句为「供应商甲已完成本季度库存采购授权，可执行下单。」该拟稿句尚未提交审批，属于待判定文本。

## 配置怎么定
下表为本次假设试验起点，数值仅用于说明比较方法，不代表官方默认值。

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| 请求方法 | POST | 与外部接口文档声明的方法逐字比较 |
| URL | 外部接口文档给出的地址 | 核对地址可引用变量，不写入公开样例 |
| Headers | Authorization 引用安全配置 | 核对凭证来源与目标应用权限 |
| Body | 仅在该请求类型下生效 | 核对 JSON 结构与外部接口契约 |
| 返回值 key | data.user.name | 按 JS 对象取值规则逐项核对 |
| 输出类型 | 字符串 | 核对是否转为 json 字符串 |

## 容易做错的三处
1. 把检索结果当成授权凭据。检索库返回供应商资料，不等于该供应商已获下单授权。输入为上述材料原文，比较对象为授权状态字段，观察结果是授权字段仍为待审批。
2. 把待审核当成缺少操作权限。材料原文只说明列入名录，未载明授权生效，属于未获支持，不能判定为否定或冲突。
3. 把调试空值当成业务故障。测试模式下 chatId 不存在，输入为空属预期，比较对象为运行模式标记。

## 怎么确认配好了
1. 输入上述材料原文与拟稿句，比较拟稿句中的「已完成授权」与原文「列入名录」是否同主体、同期间、同字段，若原文未载明授权生效，则判定为未获支持。
2. 输入一条带 Body 的 POST 请求，比较请求体 JSON 结构与外部接口契约，若字段类型或层级不符，则记录为待修正。
3. 输入测试模式下的对话请求，比较 chatId 与 responseChatItemId 是否存在，若为空则记录为预期调试现象，不判定为业务故障。
