# 逆向退货入仓质检的库存采购与供应商资料：HTTP 接口与外部系统

## 这个品类的数据长什么样

在逆向退货入仓质检的库存采购与供应商资料中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。退货质检后的补件采购读取要分清物件、定级与供货状态，型号相同不说明检查或配件可用。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

自拟补件请求只给商品型号，退货记录的定级待复核，作业备注写需要补附件，尚无供应确认。HTTP读取先核真实契约能按什么身份区分退货件与采购对象，不能由型号猜具体物件。需要附件是需求，不说明供方有货；待定级也不能变成已允许采购或再销售。返回资料应按各自原句解释，不用同款名填补缺项。

## 配置怎么定

| 退货补件读取 | 自拟身份状态 | 对应依据 |
| --- | --- | --- |
| 商品型号 | 不足确定物件 | 补真实退货关系 |
| 定级记录 | 待复核 | 非采购放行 |
| 作业备注 | 需要附件 | 非供货确认 |
| 返回范围 | 本件与他件分开 | 查实际响应 |
| 正式操作 | 补件建单另接 | 查询不完成质检 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

同款冒同件：若某型号检查用于本退货，应核物件关系和实际请求；待级冒放行：若复核中被写成允许采用，应取真实决定；需求冒现货：若补附件备注变可供货，应查实际供应确认。三项分别核身份、决定和供货阶段，不能由记录非空证明。

## 怎么确认配好了

验收保留来源对象、真实发送与响应，补本件关系后重查，看返回是否仍属于另一件。若只补到作业需求，供货仍待核。Params、Headers及适用Body依实际读取契约检查，不假定仓库或采购系统已连通。正式补件、库存归类和订单创建需另接权限及回执，读取不完成质检，也不证明商品可售或配件适配。
