# B2B平台撮合交易的门店服务与内部培训：知识库检索与召回

## 这个品类的数据长什么样
B2B平台撮合交易依赖在线认证与电子合同，不依赖现场档口，资料以企业认证资料、询报价单、电子合同、平台结算单为主，更新频率为日与每单。门店服务与内部培训需要把身份审核、询报价撮合、履约跟踪三类问题交给知识库检索，检索输出直接进入培训答复与交接说明。同一批资料中，主体名称、统一社会信用代码、合同编号、报价有效期、结算周期等字段分布在不同文档，检索召回必须回到原文核对，不能把检索命中当作审核结论或授权依据。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联，需先核标识并排除不符合者，记录实际观察。搜索模式按测试问题比较语义、全文与混合检索，不预设一种模式适合全部资料。引用上限单位为 token，最低相关度仅在语义检索或使用结果重排时生效，问题优化用于指代消除和问题扩展。混合检索通过 RRF 融合多路结果，重排须具备模型且按设置启用，图片检索须有相应图像输入及模型能力。检索是召回，不承担权限或实体隔离；待审核、已报价、已签署分别属于不同事实，不能相互推导。

### 假设演练样本
材料原文一（内部培训用询报价单摘录）：“供应商甲于2025年3月10日就型号A-100提交报价，报价有效期至2025年3月31日，采购方尚未确认。”材料原文二（平台结算单摘录）：“结算单编号JS-2025-0312，对应合同编号HT-2025-0308，结算状态为待审核。”待判定拟稿句：“供应商甲已与采购方达成合作，型号A-100按报价供货至2025年3月31日。”核对点：报价有效期只约束报价本身，不表示供货期限；待审核不表示结算完成；材料未载明合作达成与合同生效。

## 配置怎么定
下表只列与本页样本相关的官方已说明设置或实施核对项，数值为本次假设试验起点，不属官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 关联的知识库 | 仅关联使用同一向量模型的培训资料库 | 先核向量模型标识，与不满足同模型的库比较并排除 |
| 搜索模式 | 先分别测语义、全文、混合三种 | 用同一测试问题比较命中内容，不预设某模式适合全部资料 |
| 引用上限 | 假设起点 2000 token | 用长短不同的实际资料比较内容是否完整，再调整 |
| 最低相关度 | 假设起点 0.3 | 先标注相关与无关样本，比较过滤后是否保留必需片段 |
| 问题优化 | 先开启，比较原问题与优化后问题 | 核对主体是否被改错，短问题与多轮追问场景重点看 |
| 结果重排 | 按设置启用，比较重排前后排序 | 确认模型可用，用候选较多的文本问题观察排序变化 |

## 容易做错的三处
1. 把检索命中当作授权或审核结论。输入是“供应商甲报价”检索结果，比较对象是材料原文中的“采购方尚未确认”，观察结果是拟稿句是否出现“已达成合作”等原文未载明状态。原文未载明即未获支持，需保留证据缺口。
2. 把报价有效期当作供货期限。输入是材料原文一，比较对象是“有效期至2025年3月31日”与“按报价供货至2025年3月31日”，观察结果是拟稿句是否把两个不同字段混为同一事实。同字段互斥取值才构成矛盾，跨字段推导属未获支持。
3. 把待审核结算当作已完成结算。输入是材料原文二，比较对象是“结算状态为待审核”与拟稿句中的结算完成表述，观察结果是拟稿句是否将待审核写成已完成。待审核不证明缺少操作权限，也不证明结算已执行。

## 怎么确认配好了
1. 针对拟稿句“供应商甲已与采购方达成合作，型号A-100按报价供货至2025年3月31日”，输入材料原文一与原文二，比较拟稿句是否出现原文未载明的合作达成、供货期限、合同生效，观察结果是拟稿句被标注为未获支持并记录缺失字段，方满足条件。
2. 针对检索范围，输入同一向量模型标识的培训资料库清单，比较是否存在跨不同向量模型的库被共同关联，观察结果是清单中仅保留同模型库并记录被排除项，方满足条件。不得执行跨模型检索来比较漏召回。
3. 针对空结果承接，输入纸面检索结果为 []，比较下游设计是否按引用内容长度可为 0 的链路继续，观察结果是下游未把空结果当作检索失败或授权通过，方满足条件。不声称虚构规则检索一定返回 []。
