# 亚马逊FBM自发货运营的门店服务与内部培训：引用来源与溯源

## 这个品类的数据长什么样

在亚马逊FBM自发货运营的门店服务与内部培训中，本页说明FastGPT的引用来源与溯源如何衔接资料。配送客服演练中的角色卡、问答稿和承运事件分开溯源。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

FBM客服培训可拟角色卡“顾客不在家，担心雨淋”、提问脚本“是否方便另约地点”和练习答句“请先核可用方案”。另附承运样例“已尝试联系”，没有顾客回答。学员问是否可回复顾客已同意留门口时，担忧不是同意，提问不是答复，联系尝试也不说明已经沟通。引用应保留练习角色和事件阶段，不把题目想象中的顾客心理写成真实选择，更不能把指导核方案当现成安排。

## 配置怎么定

| 培训来源核对项 | 教材身份与证据范围 | 验收动作 |
| --- | --- | --- |
| 角色意愿 | 担忧雨淋 | 不代填同意。 |
| 句子角色 | 提问脚本 | 不当客户回答。 |
| 联系阶段 | 尝试联系 | 不推已约地点。 |
| 说话方 | 客服与顾客分开 | 核实际归属。 |
| 新增练习答复 | 本题本问 | 保留自拟身份。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |

| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是角色卡担心雨淋被解释成同意门口放置，应回读卡片表述并查是否有明确选择，不能替顾客作答。第二处是提问脚本被引作顾客回复，应核说话方与句子角色，保留问题尚未得到回答。第三处是联系尝试被写成已约好新地点，应对承运事件及真实后续记录。三项分别核意愿、对话归属和事件进度，不让同一客服主题合并不同动作。

## 怎么确认配好了

验收分别问角色表达什么、脚本问了什么、承运记录确认什么，检查答案实际引用是否带出说话方。只返回题目时仍不能补客户决定；只含联系尝试也不推电话已经接通或联系失败。新增答复要核本题及所回复问题，并继续标为自拟。空引用查范围与传入，本练习不更改投递指令、不证明包裹已留置，也不评价真实客服处理效果，实际选择与送达需独立凭证。
