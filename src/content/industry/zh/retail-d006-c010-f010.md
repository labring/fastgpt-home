# 京东POP第三方店铺运营的门店服务与内部培训：引用来源与溯源

## 这个品类的数据长什么样

在京东POP第三方店铺运营的门店服务与内部培训中，本页说明FastGPT的引用来源与溯源如何衔接资料。售后培训的原因假设、排查建议和检测结果保持来源层级。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

京东POP售后培训可拟案例“耳机声音忽大忽小”、讲师便签“可能与连接有关”和指导“先询问是否换过设备”。练习答卷写“设备已经换过，问题由连接造成”。材料中没有顾客对询问的回答，也没有检测结果。引用应把现象、可能原因和拟问动作分开，不能从讲师用了连接二字就确认原因，更不能把指导里的是否问句变成已发生的操作。

## 配置怎么定

| 培训来源核对项 | 教材身份与证据范围 | 验收动作 |
| --- | --- | --- |
| 现象原文 | 音量变化 | 不补原因。 |
| 假设语气 | 可能有关 | 核实际诊断依据。 |
| 问句状态 | 是否换设备 | 不当已执行。 |
| 答卷身份 | 学习输出 | 追查新增事实。 |
| 结果边界 | 未给改善或解决 | 不推实测效果。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是可能与连接有关被写成已确定原因，应核假设语气和实际检测依据，不能用便签代结论。第二处是是否换过设备被当成已经换过，应查顾客回答及其所述设备，提问本身不记录行动。第三处是学员答卷被引用为新增事实，应对案例原文与学习输出，核每项信息来自哪里。三项分别查因果证据、问答状态和来源身份，不由一段完整回答掩盖材料缺项。

## 怎么确认配好了

验收分别问案例现象是什么、老师提出何种可能、下一步要确认什么，再逐句核引用。仅返回便签时，不能声称核过案例或已解决；只有指导也不能补顾客操作记录。补入自拟回答后仍要保留试题身份，不当真实检测。空引用需查范围和传递，本页不推荐实际维修流程或决定保修责任，也不宣称更换设备有效，真实诊断与处理结果需要适用的技术与业务证据。
