# 加盟费与保证金结算的门店服务与内部培训：知识库检索与召回

## 这个品类的数据长什么样

加盟费与保证金结算围绕资金与违约扣款展开，不承担政府备案职责。资料主要来自财务系统、加盟合同、银行流水与门店违规记录，日常文档包括加盟费发票、保证金台账、扣款通知与合同付款计划。出错会引发资金争议、加盟诉讼与保证金退还纠纷。检索与召回要处理的正是这些材料在门店服务与内部培训场景中的定位与引用。

## 这些特征在「知识库检索与召回」这一环带来什么约束

关联知识库要求使用相同向量模型，跨模型库不可共同关联。语义检索依赖向量距离，全文检索适合编号、专有名词与错误码，混合检索经 RRF 融合。最低相关度仅在语义检索或结果重排时生效，引用上限以 token 为单位。图片检索需有图像输入及相应模型能力，重排需具备模型并按设置启用。检索结果不构成权限、审批或授权执行，节点输出引用长度可以为 0。

## 配置怎么定

假设演练样本：材料原文为「2024年3月加盟商甲支付加盟费5万元，保证金台账记3万元，扣款通知载明因巡检违规扣款2000元」。待判定拟稿句为「甲已完成2024年3月全部结算义务」。以下配置围绕该样本核对。

| 配置项 | 本次假设试验起点 | 比较与理由 |
| --- | --- | --- |
| 关联知识库 | 仅选同一向量模型的结算库 | 核对向量模型标识一致，排除不符者 |
| 搜索模式 | 混合检索 | 与语义、全文结果比较召回差异 |
| 引用上限 | 本次设为 3000 tokens | 与较短值比较内容完整性 |
| 最低相关度 | 本次设为 0.4 | 先标注相关与无关样本再调 |
| 问题优化 | 开启 | 比较原问题与优化后主体是否改错 |
| 结果重排 | 按设置启用 | 核对问题完整度与候选数量 |

## 容易做错的三处

1. 把检索命中当作结算完成或授权依据。拟稿句「甲已完成2024年3月全部结算义务」需要合同付款计划、银行流水与扣款事由共同核对，检索到发票不能替代该判断。
2. 将最低相关度当作实体或权限过滤器。该值只过滤低相关度结果，不排除无关业务或未授权记录。
3. 把 RRF 写成开启开关。RRF 是混合检索结果的融合过程，不是可勾选控件。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句，比较检索结果是否包含加盟费、保证金、扣款三类材料，观察引用内容是否覆盖主体与期间；仅命中其中一类即不满足。
2. 输入明确纸面空结果，比较下游链路是否走通，观察输出引用长度为 0 时流程是否继续；出现中断即不满足。
3. 输入跨向量模型的两个库标识，比较系统是否允许共同关联，观察不符合者是否被排除并记录；出现跨模型检索即不满足。
