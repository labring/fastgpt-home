# 即时零售门店履约的门店服务与内部培训：工作流编排

## 这个品类的数据长什么样

在即时零售门店履约的门店服务与内部培训中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

即时零售培训可以用订单、拣货、缺货上报与骑手过程文字练习区分阶段。自拟材料没有最终送达或处理结果，表单只收学员问题和这些来源，不能让解释自动变成处置决定。客户说未收到与骑手记录尚缺是不同性质，后续阅读应保留各自依据，不从一项缺货上报推定整日库存或从配送异常直接判门店责任。

## 配置怎么定

| 培训核对 | 本题自拟输入 | 观察依据 |
| --- | --- | --- |
| 阶段学习 | 订单缺货与骑手过程分开 | 未直接推出处理结果 |
| 时间错配 | 其他时点库存进入问题 | 不从现在倒推过去 |
| 结果路径 | 补送达却只收运输过程 | 核接收文本保留缺口 |
| 陈述性质 | 客户问题与实际记录分列 | 没有互相替代来源 |
| 正式业务 | 退款考核或关闭另办 | 继续未充作执行凭据 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

可让人员选择补库存范围、看运输说明或交经办人核订单，逐项看实际分支。若另一个时点库存传入当前问题，应排查时间与订单对应，不能由现在状态倒推下单时事实。若选择补送达结果却只收到骑手过程，需核接收内容并保留阶段缺口，不能由人员已点击继续写成买家已接收。 若客户说未收到就被答复判成包裹未送达，应分别核客户陈述与承运方本单记录；投诉表达不等于运输结果，缺实际接收依据时保留阶段未知。

## 怎么确认配好了

验收保留阶段、时间、订单身份与解释出处，补同单处理资料后复问，观察新增依据实际传到哪里。交互节点记录并等待人员处理，完成后继续；这不意味着门店业务已经办理。退款、换品、异常关闭与人员考核需实际后续流程另核授权及回执，培训流程结束不证明订单已送达、责任已确定或学员已具备操作资格。
