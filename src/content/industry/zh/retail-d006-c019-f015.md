# 即时零售门店履约的门店服务与内部培训：知识库检索与召回

## 这个品类的数据长什么样

即时零售门店履约按分钟处理线上订单，与周期性盘库不同。门店服务与内部培训场景下，需要检索的资料包括即时订单、拣货清单、缺货报备、配送异常单，来源涉及抖音即时零售、美团或京东到家后台、门店库存与骑手轨迹。这些资料每单更新，单量密集时同一门店一天产生多份缺货报备与配送异常单。检索任务因此集中在两类问题：某笔订单当前处于什么履约状态，某类异常应参照哪份操作要求处理。资料更新频率为分钟级、每单，本页功能不因更新频率改变检索链路，故不展开同步机制。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的库，检索以库为最小搜索单位，集合仅作分类管理。语义检索依赖向量距离，全文检索依赖关键词命中，混合检索通过 RRF 融合两路结果，Rerank 对候选文本二次排序。最低相关度仅在语义检索或使用结果重排时生效，引用上限以 token 为单位。图片检索需要图像输入及相应模型能力，重排需要模型且按设置启用，二者属于可选路径，并非每次请求都执行。

假设演练样本：某商超到家门店培训材料原文三句——“拣货员发现缺货后，在拣货清单对应行选择缺货并提交缺货报备，报备状态为待审核。待审核期间该订单不得标记已拣货完成。审核通过后由调度决定替换或退款。”另有交接请求一句拟稿：“缺货报备提交后即视为门店已完成缺货处理，拣货员可直接继续下一单。”判定对象为“提交报备”与“完成缺货处理”两个事实，期间为同一订单，字段为报备状态。原文载明提交后状态为待审核，待审核不等于审核通过，拟稿句将提交等同于完成处理，与原文同字段取值不一致。授权边界：拣货员提交报备属操作行为，替换或退款由调度决定，门店培训材料未授予拣货员该决定权。

## 配置怎么定

| 配置或核对项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联门店履约培训库 | 该库与待检索资料同向量模型；逐个核对库标识，排除不同向量模型的库，不执行跨模型共同关联 |
| 搜索模式 | 语义检索与全文检索各测一轮 | 缺货报备、配送异常单含编号与状态词，全文检索易命中；自然语言问法用语义检索；比较两轮引用内容 |
| 引用上限 | 起点 2000 tokens | 拣货清单与报备材料段落长短不一；用长短两类实际资料核对引用内容是否完整，再调整 |
| 最低相关度 | 起点 0.4 | 先标注相关与无关样本各若干条，观察过滤后是否保留状态描述句，再调整 |
| 问题优化 | 多轮追问场景开启，单轮明确问题关闭 | 比较原问题与优化后问题的指代对象，核对订单主体是否被改错 |
| 结果重排 | 候选较多时启用并核对得分 | 重排得分范围 0-1；比较重排前后同一候选的排序位置 |

## 容易做错的三处

1. 把检索命中当作授权通过。检索返回缺货报备材料，仅说明资料可被引用，不表示该报备已审核通过，也不表示拣货员获得替换或退款决定权。核对输入为拟稿句与培训材料原文，比较“提交报备”与“审核通过”两个状态字段，观察结果应为两者不同。
2. 把最低相关度当作实体或权限过滤。该值仅在语义检索或结果重排时生效，用于过滤低相关度结果，不能排除无关门店或未授权记录。核对输入为同一问题在不同相关度取值下的引用内容，比较是否出现非本门店资料，观察结果应记录实际出现的资料范围。
3. 把可选检索路径当作每次执行。图片检索需图像输入与模型能力，重排需模型且按设置启用；缺少条件时该路径不产生结果。核对输入为无图片的文本问题，比较输出引用是否包含图片描述或图片向量来源，观察结果应记录实际启用情况，缺失条件记为未启用。

## 怎么确认配好了

1. 使用上述假设培训材料原文与拟稿句，输入拟稿句执行检索，比较引用内容是否包含“待审核”状态句，观察结果应显示该状态句被引用；若引用内容不含状态句，记录为检索缺口，不判定拟稿句成立。
2. 使用同一问题分别以语义检索与全文检索执行，输入为“缺货报备待审核期间能否标记已拣货完成”，比较两轮引用内容是否指向同一原文段落，观察结果应记录两轮是否一致；不一致时保留两轮结果，不合并为单一结论。
3. 使用空引用内容核对下游设计。输入为明确的纸面输入空数组，比较下游节点是否按长度可为 0 的引用链路继续执行，观察结果应记录下游是否走通；该核对不表示虚构规则检索一定返回空数组，仅核对空结果承接设计。
