# 即时零售门店履约的门店服务与内部培训：表单与交互

## 这个品类的数据长什么样

在即时零售门店履约的门店服务与内部培训中，本页说明FastGPT的表单与交互如何衔接资料。即时履约培训保留接单、拣货与骑手交接的角色区别，课程结束不能证明订单已送达。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

假设演练工单显示店员接单，拣货只是待办，截图的骑手姓名来自旧单。表单先收演练订单与门店身份，让人员选择核拣货或补交接材料。缺订单标识和补齐各测一次，检查后续收到的是哪张工单。节点记录交互并传信息，不自带订单数据库，也不从姓名字段授予交接权限。

## 配置怎么定

| 即时履约培训 | 纸面状态 | 核验动作 |
| --- | --- | --- |
| 店员接单 | 尚非拣齐 | 找拣货记录 |
| 骑手姓名 | 来自旧单 | 核订单对应 |
| 课堂提交 | 仅交互结束 | 非送达 |
| 订单必填 | 缺项与补齐 | 查实际输入 |
| 业务执行 | 订单配送另接 | 真实权限凭据 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

接单被答已拣齐时，查实际拣货记录；旧单骑手被套本单时，对订单对应；课堂提交被答已送达时，查真实收件凭据。三处分别看阶段、身份与实体事件，本例不提供时效或履约结果。

## 怎么确认配好了

验收让受训者沿接单原句找仍缺的拣货与交接证据，选择分支逐条核连接。补骑手对应只修身份，送达仍须独立证据。接单操作、库存扣减和配送回写需业务接口及真实权限，培训链用于练习核对，不触发这些动作或确认已执行。 练习工单把店员与骑手的角色分开，拣货待办与真实收件凭据分别定位，便于培训核验。
