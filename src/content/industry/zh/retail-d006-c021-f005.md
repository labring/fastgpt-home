# 品牌会员私域运营的门店服务与内部培训：多轮对话与提示词

## 这个品类的数据长什么样

品牌会员私域运营围绕顾客数据与复购触达展开，日常材料包括会员标签表、触达计划、优惠券规则和隐私授权记录，数据来源覆盖CRM系统、企微、POS消费记录与小程序行为数据。门店服务与内部培训场景下，导购与企微运营需要借助多轮对话完成资料查询、话术演练和交接说明，这些对话直接引用上述材料。

资料更新频率为日、周两级，本页功能不依赖批量同步或交易触发机制。真正影响本任务的是三点：材料本身带有授权状态，触达计划可能处于草稿或待审阶段；对话历史会跨轮带入前文，容易把上一轮的假设条件延续到新一轮；回复格式一旦被下游节点读取，结构变化会中断承接。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

多轮对话的提示词需要写明资料范围、回答任务和缺证据时的处理方式，不能由模型补写业务事实。历史记录按实际带入的上下文核对，区分新会话与继续会话。问题优化用于知识库连续对话时核对指代消除与问题扩展，短问题不必然适用。模型与长度按实际支持的上下文和回复设置核对，长文档与追问组合需要单独测试。回复格式按后续承接选择，选择 json_schema 时填写对应格式要求并验返回结构。

检索与相似度只影响召回排序，不承担权限或实体隔离。交互节点返回的 interactive 为展示配置，只含 type 与 params，entryNodeIds、memoryEdges、nodeOutputs、nodeResponseId 等内部运行态字段不返回。表单收集值，业务核验、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：某品牌会员运营团队留存的内部培训材料原文为：“2025年3月华东区门店导购话术演练计划（草稿），对象为持有效会员标签的到店顾客，授权范围限于本计划列明的触达动作，计划状态为待运营负责人审核。”一条待判定的拟稿句为：“本计划已批准，导购可按计划向全部会员发送优惠券。”该拟稿句需要与上述原文逐项比对主体、对象、状态与有效范围。

## 配置怎么定

| 配置项 | 本页取值或核对方式 | 依据与说明 |
| --- | --- | --- |
| AI 模型 | 选择支持所需上下文长度与工具调用的模型 | 模型能力决定可用配置项是否显示 |
| 记忆轮数 | 本次假设试验起点设为保留少量历史轮数 | 该起点用于对比带入前文与不带入前文的回答差异，非官方默认值 |
| 回复上限 | 按话术演练所需长度设置，并与截断现象对比 | 设置过低会提前截断，过高增加消耗 |
| 温度 | 客服与规则明确的演练场景偏低 | 数值较低时回答更稳定 |
| 回复格式 | 普通问答保持默认；下游读取固定结构时选 json_schema 并填写格式要求 | 选择 json_schema 需填写对应格式要求 |
| 历史与交互核对 | 核对实际带入的 historyPreview 与 interactive 返回字段 | 交互节点只返回 type 与 params |

## 容易做错的三处

1. 把待审核状态读成已批准。输入为上述培训材料原文与拟稿句，比较对象是计划状态字段，原文写明“待运营负责人审核”，拟稿句写“已批准”，两者在同一字段上取值互斥，属于矛盾。可执行检查：逐字比对状态描述，观察是否出现“已批准”字样。
2. 把授权范围扩大为全部会员。输入为原文“授权范围限于本计划列明的触达动作”，比较对象是对象范围，拟稿句写“全部会员”，原文未载明全部会员，属于未获支持。可执行检查：核对对象描述是否超出原文列明范围。
3. 把检索相似度当作权限过滤。输入为一次带相似度分数的检索返回，比较对象是返回记录与当前请求者的可访问范围，相似度分数不构成权限判断。可执行检查：核对返回记录标识是否在授权范围内，超出者排除并记录。

## 怎么确认配好了

1. 取上述培训材料原文与拟稿句，输入为两句完整文本，比较对象是计划状态字段，当拟稿句出现“已批准”而原文为“待运营负责人审核”时，判定为矛盾，该现象满足报错条件。
2. 取原文授权范围句与拟稿句对象描述，输入为两句完整文本，比较对象是对象范围，当拟稿句出现“全部会员”而原文仅列明本计划触达动作时，判定为未获支持，该现象满足报错条件。
3. 取一次纸面输入 `[]` 的空检索结果，比较对象是下游节点对空结果的承接设计，观察下游是否按空结果分支处理；该核对不声称虚构规则检索必然返回空数组。
