# 品牌会员私域运营的门店服务与内部培训：工作流编排

## 这个品类的数据长什么样

在品牌会员私域运营的门店服务与内部培训中，本页说明FastGPT的工作流编排如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

会员运营培训可只用通用规则和自拟文字，收学员问题、活动安排与授权资料缺口，不提供真实会员数据。表单将这些内容传给后续阅读，不从标签名称推定可发送，也不从券规则存在推定会员已领用。培训问题若涉及实际业务权限，应保留由谁提供依据和仍需核什么，不让用户选择把未核授权写成已经具备。

## 配置怎么定

| 培训核对 | 本题自拟输入 | 观察依据 |
| --- | --- | --- |
| 公开范围 | 通用规则和自拟活动文字 | 不含真实会员记录 |
| 权限缺口 | 补授权却只收到计划标题 | 未将计划充作许可 |
| 活动对应 | 其他活动使用说明混入 | 核身份范围再解释 |
| 执行区别 | 安排与发送配置与使用分开 | 未由存在推定已执行 |
| 真实业务 | 发送写入与认定另办 | 状态未代替权限核验 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

可分别选择看规则或补授权说明，逐条核分支。若补授权路径只收到活动计划标题，应排查实际传值，计划不能代替许可依据。若其他活动使用说明进入本题，需核活动身份和来源范围，防止把另一活动结果当成本次执行。触达安排与实际发送、券配置与使用结果都应在接收内容中分开保留。 若触达计划只写拟通知，答复却声称会员已收到，应分别核本活动实际发送和接收依据；计划不证明任何一项已发生，通用规则也不能补接收结果。

## 怎么确认配好了

验收从原问题、公开通用材料、选择去向到解释逐项核，补相应规则说明后复问，确认新增依据真正进入。交互状态由节点记录并等待，不代表权限核验已完成。真实发送、标签写入、优惠处理与人员认定需实际后续业务另验授权和回执；培训流程结束不证明活动已触达、效果已产生或隐私审查已经通过。
