# 品牌自播直播间运营的门店服务与内部培训：表单与交互

## 这个品类的数据长什么样

在品牌自播直播间运营的门店服务与内部培训中，本页说明FastGPT的表单与交互如何衔接资料。脚本、商品讲解与评论各有来源性质，培训需要保留哪些话未被实际执行或核实。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

品牌自播培训表单可收场次问题、脚本原句与商品讲解资料，评论另列为陈述。自拟材料没有本场实际播出或成交依据，不能从脚本完整推定主播已经讲过。提交后应核下游保留资料性质和场次，表单不自动读取直播后台。人员选择可安排补讲解或看现稿，但不是商品选择器，也不能由点击继续推定宣传表述已审核。

## 配置怎么定

| 培训材料核对 | 本题自拟输入 | 可观察依据 |
| --- | --- | --- |
| 发言阶段 | 拟脚本与实际播出分开 | 未从完整稿推已讲过 |
| 商品范围 | 讲解卡限定原句 | 接收未省掉待核说明 |
| 评论性质 | 观众陈述与交易来源分开 | 未直接判成成交 |
| 新增资料 | 本场播出或商品依据 | 解释实际采用来源 |
| 正式发布 | 批准账号与认定另办 | 表单未替代执行效果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

脚本冒执行：若拟说内容被写成本场实际发言，应查对应播出依据；待核说明丢失：若商品卡的限定原句没有进入解释，应对照提交和接收恢复范围；评论冒成交：若观众陈述被当真实交易，应另查本场交易来源。三项分别核执行、属性范围与业务证据，不用材料名称替代。

## 怎么确认配好了

验收保留场次、原文性质、选项去向和实际接收内容，补相应播出或产品来源后复问，看新增依据是否被使用。节点记录等待状态并继续，不形成发布或成交记录。字段核验、内容批准、账号发布和人员认定需后续节点或外部方案另核授权及回执；培训结束不证明直播已执行或经营效果已产生。
