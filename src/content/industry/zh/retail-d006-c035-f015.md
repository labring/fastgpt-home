# 外贸退运与索赔的门店服务与内部培训：知识库检索与召回

## 这个品类的数据长什么样

退运索赔处理出口后的逆向物流与责任认定，资料来自客户邮件、质检报告、海关系统与保险公司理赔系统，日常文档包括退运协议、索赔函、质量报告、退运报关单。门店服务与内部培训场景中，这些材料需要被检索、引用并转成可核对的交接口径。资料更新为不定期、每案一次，检索配置不依赖固定同步节奏。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。搜索模式按测试问题在语义检索、全文检索、混合检索之间比较；混合检索通过 RRF 融合多路结果，RRF 是融合过程，不是可开启的独立开关。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，会额外调用模型。检索返回引用内容，长度可以为 0，空结果链路仍走通。检索本身不承担授权判断，最低相关度是过滤阈值，不是权限或实体隔离手段。

假设演练样本：材料原文为“2025年3月10日，编号TR-0310的退运协议由A方与B方签署，涉及货物为工业泵体12件，退运原因为轴承异响，申报状态为已提交退运报关单，索赔函尚未提交。”待判定的拟稿句为“该批退运已完成索赔提交，可进入赔付流程。”核对时比较拟稿句与原文的字段：原文只载明退运报关单已提交，索赔函尚未提交，拟稿句把索赔提交写为已完成，属于未获支持。

## 配置怎么定

| 配置项 | 本页设置或核对项 | 与样本的关系 |
| --- | --- | --- |
| 关联知识库 | 只关联使用相同向量模型的知识库 | 退运协议、索赔函、质量报告、退运报关单需在同一向量模型下检索 |
| 搜索模式 | 按测试问题比较语义、全文与混合检索 | 编号TR-0310与“轴承异响”分别测试全文与语义路径 |
| 引用上限 | 以 token 为单位，用长短不同的实际资料测试完整性 | 退运协议与质检报告篇幅不同，观察引用是否被截断 |
| 最低相关度 | 先标注相关与无关样本再调阈值 | 仅在语义检索或结果重排时生效，用于过滤低相关片段 |
| 问题优化 | 比较原问题与优化后问题，核对主体是否被改错 | 多轮追问“该批退运状态”时，核对编号与主体是否保留 |
| 结果重排 | 具备重排模型且按设置启用时使用 | 候选较多时对文本结果二次排序，得分0-1 |

## 容易做错的三处

1. 把拟稿句“该批退运已完成索赔提交”当作原文事实。原文只写索赔函尚未提交，比较时须逐字段核对，未载明状态记为未获支持，不写成否定或冲突。
2. 把最低相关度当作权限或实体隔离设置。该值是过滤阈值，仅在语义检索或结果重排时生效，检索不判断门店人员是否有权查看某案。
3. 把不同向量模型的知识库强行共同关联。关联前先核向量模型标识，排除不符合者，不执行跨模型检索来比较漏召回。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句，比较“索赔函尚未提交”与“已完成索赔提交”两个字段，观察是否识别为同字段互斥取值。满足条件为判定拟稿句未获支持，并保留索赔函未提交的证据缺口。
2. 输入编号TR-0310，分别用全文检索与语义检索，比较返回引用是否含该编号及退运原因字段，观察引用内容是否可核对。满足条件为引用内容包含原文主体、对象与状态，不要求首条命中或全部召回。
3. 输入纸面空结果[]，核对下游节点是否仍走通，观察是否出现引用长度为0的链路。满足条件为下游设计能承接空引用，不声称虚构规则一定返回[]，也不声称无关查询必为空。
