# 大促仓配排产的门店服务与内部培训：引用来源与溯源

## 这个品类的数据长什么样
大促仓配排产围绕短期峰值产能和人车场安排展开，与多仓库存同步的日常均衡调度存在明显差别。历史大促订单、平台活动报名、WMS产能与快递揽收能力共同构成排产依据，每场活动及每日均可能产生新版本。门店服务与内部培训场景下，大促预测表、人员排班、快递保障方案与异常日报是主要核对材料，这些文档在引用来源与溯源环节需要逐份确认版本与有效范围。

## 这些特征在「引用来源与溯源」这一环带来什么约束
知识库搜索节点可关联一个或多个相同向量模型的知识库，输出为引用内容数组，长度允许为零。检索结果是否被采用，须结合资料有效版本审核，检索本身不构成授权。引用上限以 tokens 为单位控制单次搜索最多引用的内容量，最低相关度仅在语义检索或结果重排时生效，该阈值是过滤条件，不承担权限或实体隔离功能。混合检索通过 RRF 融合多路结果，重排模型按设置启用，图片检索需要相应图像输入及模型能力，这些可选路径不表示每次请求全部执行。

假设演练样本：某仓库《大促预测表（第3版）》原文载明“本表适用于2025年11月1日至11月3日，覆盖华东仓，预计峰值订单量为每日8万单，数据来源为平台活动报名与历史同期订单”。同批《人员排班表》载明“排班周期为2025年11月1日至11月3日，临时人员到岗时间为每日6时”。一份拟稿句写道“华东仓大促期间峰值订单量已获运营负责人书面批准，可直接用于快递车辆协调”。该拟稿句未在预测表或排班表中找到批准记录，批准状态属于未获支持。

## 配置怎么定
| 配置项 | 本页相关设置或核对项 | 说明 |
| --- | --- | --- |
| 关联知识库 | 核对已选知识库及资料版本，相同向量模型才可共同关联 | 跨模型不可共同关联，先核标识并排除不符合者 |
| 搜索模式 | 按问题类型选择语义检索、全文检索或混合检索 | 混合检索经 RRF 融合，不作为独立开关 |
| 引用上限 | 以 tokens 为单位设定单次搜索引用量 | 本次假设试验起点设为3000 tokens，理由为预测表与排班表合计约2500 tokens，与2000 tokens比较可观察截断 |
| 最低相关度 | 仅在语义检索或结果重排时生效的过滤阈值 | 本次假设试验起点设为0.5，与0.3比较观察召回范围变化 |
| 问题优化 | 按多轮追问或短问题场景决定是否开启 | 开启会增加一次模型调用与整体耗时 |
| 引用内容承接 | 核对检索输出是否交给回答环节并逐条比对原文 | 空数组时下游设计须能承接 |

## 容易做错的三处
1. 将检索命中当作授权依据。输入为上述拟稿句与预测表原文，比较拟稿句声称的批准状态与预测表实际载明的适用期间和覆盖范围，可观察到预测表未记载批准字段，批准状态属于未获支持。
2. 将最低相关度当作权限或实体过滤。输入为跨门店查询与已关联知识库，比较返回引用与查询主体，可观察到相关度分数不承担实体隔离功能，无关记录可能因语义相近被召回。
3. 将空引用数组判定为工作流报错。输入为纸面构造的空数组[]，比较下游节点设计，可观察到引用长度允许为零，空数组不等于工作流终止。

## 怎么确认配好了
1. 输入上述预测表原文与拟稿句，比较拟稿句所述批准状态与原文实际载明的适用期间、覆盖范围，若原文无批准字段则满足“未获支持”判定，若原文出现批准字段则需进一步核对签署主体。
2. 输入上述排班表原文与拟稿句，比较排班周期与临时人员到岗时间是否与拟稿句所述一致，若拟稿句未提及到岗时间则属于信息缺失，不构成矛盾。
3. 输入纸面构造的空数组[]与下游回答节点设计，比较下游是否能承接零长度引用，若下游设计明确处理空数组则满足条件，若下游设计假定必有引用则记录为待修正项。
