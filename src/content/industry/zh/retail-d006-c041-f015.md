# 平台促销报名与价格管理的门店服务与内部培训：知识库检索与召回

## 这个品类的数据长什么样

平台促销报名与价格管理围绕活动报名表、促销价审批单、库存锁定表、活动复盘表展开。与商品标题合规相比，本品类核心是价格、库存和活动节奏。门店服务与内部培训场景中，店员需要依据这些材料回答活动规则、价格口径、库存状态和交接要求。资料按周或每场活动更新，检索结果必须能区分同一活动的不同阶段。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，需先核对向量模型标识，排除不符合者，记录实际观察。检索是召回过程，不承担授权判定。语义检索、全文检索与混合检索可按测试问题比较，不预设一种模式适合全部资料。引用上限以token为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，需比较原问题与优化后问题，核对主体是否被改错。RRF是混合检索后的结果融合过程，不作为独立开关描述。图片检索须有相应图像输入及模型能力，重排须具备模型且按设置启用。空结果以数组形式输出，长度可以为0，下游链路仍走通。

假设演练样本：材料原文为“华东区门店2025年3月促销报名表载明，活动A报名截止日为3月5日，促销价审批单编号P-0312状态为待审核，库存锁定表载明活动A锁定数量200件。”待判定拟稿句为“活动A已完成促销价审批，可执行报名。”核对主体为活动A，对象为促销价审批单P-0312，状态为待审核。待审核不构成审批完成，拟稿句与原文状态不一致，判定为未获支持，需保留证据缺口。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅活动报名表与促销价审批单库 | 两库向量模型标识一致，排除标识不符者 |
| 搜索模式 | 混合检索 | 与语义检索、全文检索比较编号与自然语言问题 |
| 引用上限 | 1200 token | 本次假设起点，与800和1600比较内容完整性 |
| 最低相关度 | 0.35 | 本次假设起点，先标注相关与无关样本再调 |
| 问题优化 | 开启 | 比较多轮追问下原问题与优化后问题主体 |
| 结果重排 | 启用 | 候选较多时比较重排前后排序，无模型时不启用 |

## 容易做错的三处

1. 将待审核状态直接判定为审批完成。输入为促销价审批单P-0312状态待审核，比较对象为“已完成审批”表述，观察结果为状态字段与表述不一致，应记录未获支持。
2. 把检索召回当作授权执行。输入为检索命中的活动报名表片段，比较对象为报名执行请求，观察结果为检索仅返回引用内容，不产生审批或报名动作。
3. 将不同向量模型的知识库共同关联。输入为两个向量模型标识不同的库，比较对象为关联条件，观察结果为标识不一致，应排除并记录，不执行跨模型检索比较。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句“活动A已完成促销价审批，可执行报名”，比较促销价审批单状态字段，观察结果为待审核与已完成审批不一致，判定拟稿句未获支持。
2. 输入一条仅含活动A报名截止日的检索问题，比较返回引用内容与原文日期字段，观察结果为引用内容包含3月5日且无审批完成表述，满足条件。
3. 输入纸面空结果数组[]，比较下游节点是否继续执行，观察结果为链路走通且不产生报名或审批动作，满足条件。
