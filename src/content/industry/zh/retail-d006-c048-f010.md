# 快递面单与揽收交接的门店服务与内部培训：引用来源与溯源

## 这个品类的数据长什么样
快递交接发生在包裹离仓节点，核心是承运商扫描责任。门店服务与内部培训场景下，需要向员工讲清电子面单、交接清单、揽收扫描记录、异常件登记四类材料的来源与引用方式。这些材料每批、每日更新，引用时必须核对版本与批次范围。培训材料若把某批次的扫描记录当作通用规则引用，受训人员会误判责任归属。本页只处理引用来源与溯源，不涉及面单打印操作或揽收扫描执行。

## 这些特征在「引用来源与溯源」这一环带来什么约束
知识库搜索节点可选择多个相同向量模型的知识库，输出为引用数组，长度允许为零。空数组表示搜索链路走通但无引用内容，不表示工作流报错终止。引用内容需逐条与原文核对，回答流畅度或思考过程不能替代来源证据。语义召回与相关度分数只反映相似程度，不承担权限过滤或实体隔离功能。检索本身不是授权，表单收集的值也不等于业务审批已完成。混合检索通过 RRF 融合多路结果，这是融合过程，不是可开启的开关。图片检索需要图像输入及模型能力，重排需要模型并按设置启用，两者都属于可选路径。

假设演练样本：某门店培训负责人拟写一句交接说明：“根据2025年3月12日交接清单第7条，本批包裹已全部由承运商扫描揽收，异常件为零。”供核对的材料原文为：“2025年3月12日交接清单第7条：本批共120件，承运商已扫描揽收118件，异常件登记2件，待承运商确认。”拟判定该拟稿句是否与原文一致。原文含主体（承运商）、对象（本批120件包裹）、状态（118件已扫描、2件异常待确认）及有效范围（2025年3月12日该批次）。

## 配置怎么定
| 配置项 | 本页对应设置或核对项 | 假设试验起点及理由 |
| --- | --- | --- |
| 关联的知识库 | 核对已选知识库及资料版本，相同向量模型才可共同关联 | 本次假设选择两个同向量模型库，因跨模型不可共同关联 |
| 搜索模式 | 语义检索、全文检索或混合检索 | 假设选混合检索，因样本含编号与自然语言 |
| 引用上限 | 每次搜索最多引用的 tokens 数 | 假设起点为2000 tokens，需与样本原文长度比较 |
| 最低相关度 | 0-1 数值，仅在语义检索或结果重排时生效 | 假设起点0.3，需与样本召回得分比较 |
| 问题优化 | 指代消除与问题扩展，增加一次模型调用 | 假设关闭，因样本问题已含明确主体与日期 |
| 结果重排 | 使用 ReRank 模型二次排序 | 假设启用，需确认模型可用并按设置开启 |

## 容易做错的三处
1. 把检索输出直接当作授权执行。输入为搜索节点返回的引用数组，比较对象是业务审批状态，观察结果是引用内容存在但审批记录缺失，此时不能执行交接确认。
2. 把空引用数组当作系统报错。输入为搜索节点输出 `[]`，比较对象是工作流终止条件，观察结果是链路继续执行而下游未收到引用，此时应记录缺口，不将其判定为失败。
3. 把最低相关度当作权限过滤器。输入为相关度阈值设置，比较对象是记录访问权限，观察结果是低分记录被过滤但无权记录仍可能被召回，此时需另行核对权限。

## 怎么确认配好了
1. 用假设样本原文与拟稿句逐字比较。输入为上述交接清单原文与拟稿句，比较对象是“118件已扫描、2件异常”与“全部扫描、异常为零”，观察结果是两者不一致，拟稿句未获支持。
2. 用纸面输入 `[]` 核对下游承接设计。输入为明确的空引用数组，比较对象是下游节点是否继续执行，观察结果是链路走通且无引用内容，确认空结果不被当作报错。
3. 核对知识库向量模型标识。输入为已选知识库列表，比较对象是各库向量模型名称，观察结果是仅保留相同向量模型库，排除不符合者并记录实际观察，不执行跨模型检索比较。
