# 渠道应收账款催收的门店服务与内部培训：知识库检索与召回

## 这个品类的数据长什么样

渠道应收账款催收发生在赊销之后，核心是授信与现金回收。主要资料来自财务系统、银行回单、经销商订单和销售合同，日常文档包括应收账龄表、催款函、授信协议、发货冻结通知。门店服务与内部培训场景下，人员需要从这些资料中检索账龄口径、催款函措辞、授信额度状态和冻结通知条件。检索结果直接影响催收沟通内容与培训口径。资料更新频率为周或月，检索配置不因此改变，本页不涉及同步机制。

## 这些特征在「知识库检索与召回」这一环带来什么约束

账龄表含数字与期间，催款函含措辞与主体，授信协议含额度与有效期，冻结通知含触发条件。编号、金额、日期、主体名称适合全文检索或混合检索；自然语言描述的催收策略适合语义检索。知识库搜索节点可关联一个或多个使用相同向量模型的库，跨不同向量模型的库不可共同关联，需先核对向量模型标识并排除不符合者，记录实际观察。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离。引用上限以 token 为单位，用于控制每次搜索引用的内容长度。问题优化用于指代消除和问题扩展，会额外调用模型。RRF 是混合检索后的结果融合过程。重排需具备模型并按设置启用。图片检索须有图像输入及模型能力。

假设演练样本：某品牌财务留存一份纸质《授信协议》摘录，原文为“经销商甲，授信额度人民币五十万元，有效期至2025年3月31日；截至2025年3月31日，应收账龄表中经销商甲逾期金额为十二万元。”另有一条拟稿句待判定：“经销商甲授信已失效，应停止发货。”判定需同主体、同期间、同一字段。原文载明有效期至2025年3月31日，未载明失效后处理方式，拟稿句中的“应停止发货”未获支持，属待核实。

## 配置怎么定

配置围绕上述样本，仅列官方已说明设置或实施核对项。数值为本次假设试验起点，非官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅关联使用同一向量模型的授信协议库与账龄表库 | 先核对向量模型标识，排除不同模型库，不执行跨模型检索比较 |
| 搜索模式 | 对“有效期至2025年3月31日”用全文检索，对催收策略问句用语义检索 | 比较编号日期类问题与自然语言问题的召回差异 |
| 引用上限 | 设为覆盖一份授信协议摘录所需的 token 量 | 用长短不同的实际资料测试内容是否完整，再调整 |
| 最低相关度 | 先用较低阈值观察召回，再逐步提高 | 先标注相关与无关样本，比较过滤后结果 |
| 问题优化 | 对含指代的追问开启，对完整问句关闭 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 候选较多时启用重排模型 | 比较重排前后排序，确认模型已配置 |

## 容易做错的三处

1. 把检索结果当作授权依据。输入为拟稿句“经销商甲授信已失效，应停止发货”，比较对象为授信协议原文，原文仅载明有效期，未载明失效后处理方式。若将检索命中直接视为可停止发货，属越权。正确做法是记录证据缺口，等待人工核实。
2. 跨不同向量模型的库共同关联。输入为两个向量模型标识不同的库，比较对象为节点关联要求。若强行关联，不编造漏召回或冗余结果，仅核对标识并排除不符合者，记录实际观察。
3. 把最低相关度当作权限过滤。输入为一条语义相近但属其他经销商的记录，比较对象为最低相关度设置。该阈值不隔离实体，若据此认为已排除无关主体，属误判。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句，比较拟稿句“应停止发货”与原文载明的有效期字段。原文未载明失效后处理方式，判定为待核实，不判定为否定或冲突。
2. 输入两个向量模型标识不同的库，比较节点关联要求。核对标识后排除不符合者，不执行跨模型检索，记录实际观察。
3. 输入一条空结果请求，以明确的纸面输入空数组核对下游设计，确认输出链路可走通，不声称虚构规则检索一定返回空数组。

以上验证均为纸面预期，未实际执行。检索与相似度不承担授权、审批或数据库写入，相关业务动作需另接系统实现。
