# 生鲜供应商索赔的门店服务与内部培训：分享与嵌入

## 这个品类的数据长什么样
生鲜供应商索赔追究到货质量责任，不处理门店自然损耗，主要材料是质量异常单、照片证据、扣款通知、索赔对账单，数据按每批和每月更新。门店服务与内部培训要把这些材料分享给门店人员并嵌入日常操作，涉及的主体是生鲜采购、质检和供应商业务。分享动作本身只完成链接分发，不构成索赔授权或扣款执行。

## 这些特征在「分享与嵌入」这一环带来什么约束
免登录窗口从发布渠道创建，系统生成完整链接，链接标识仅用于记录展示，不能当成业务授权。身份验证受商业版范围限制，按接口返回的 success 与 uid 判断是否放行。匿名记录依赖同一设备同一浏览器，跨设备记录需另行设计身份与会话管理。以下为假设演练样本：某门店质检员提交质量异常单，原文为“2025年3月10日，门店A收到批次B-0310菠菜，验收发现叶片腐烂比例约15%，附照片三张，申请扣款。”拟交接请求为“将该索赔分享链接发给供应商业务，对方点击后即可确认扣款。”判断所需主体、对象、状态均在原文内，但扣款确认的授权边界未载明。

## 配置怎么定
下表围绕该样本列出与本页功能相关的官方已说明设置或实施核对项。假设试验起点仅用于本次核对，不是官方默认值。

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| 链接名称 | 索赔材料分享-门店A | 仅用于记录展示，与业务授权无关 |
| 过期时间 | 设7天，因索赔协商通常按月对账 | 与对账单周期比较，超期不可用 |
| QPM | 设10 | 每用户每分钟最大访问次数，观察是否触发限制 |
| 积分上限 | 设本次分享入口用量上限 | 核对费用归属与用量限制 |
| 身份验证 | 填写根地址 | 商业版范围，按接口返回 success 与 uid 放行 |
| 对话记录边界 | 同设备同浏览器 | 跨设备时记录丢失，需另设身份管理 |

## 容易做错的三处
1. 将链接标识当作扣款授权。输入是分享链接，比较对象是质量异常单原文，若原文未载明授权条款，链接点击不产生扣款效力。
2. 将身份验证成功当作索赔审批。输入是接口返回的 success 与 uid，比较对象是审批记录，两者字段不同，成功放行仅表示可进入对话。
3. 将匿名记录当作跨设备可用。输入是同一设备同一浏览器，比较对象是另一设备，记录丢失属已载明边界，需另设身份管理。

## 怎么确认配好了
1. 输入假设样本原文与拟交接请求，比较扣款确认是否载明授权主体与生效条件，原文未载明时记录为待核实，不判定为已授权。
2. 输入身份验证接口返回的 success 与 uid，比较 uid 是否满足不包含特定字符且不超过255字节，满足则放行，不满足则观察 Invalid UID 错误。
3. 输入同一设备同一浏览器与另一设备，比较对话记录是否可拉取，同设备可拉取近30天20条，跨设备记录丢失，需另设身份管理。

检索与相关度不负责权限或实体隔离，检索库同向量模型要求不扩展至外部系统。空结果可用明确的纸面输入核对下游设计，不声称虚构规则一定返回空。未载明或仅有阶段证据的，记录为待核实，保留证据缺口。
