# 生鲜冷链到店验收的门店服务与内部培训：知识库检索与召回

## 这个品类的数据长什么样

冷链到店验收的资料围绕运输温度、到货批次和门店收货动作生成。冷链车温控数据、WMS 记录、门店收货系统条目、质检照片，以及冷链温度记录、到货验收单、拒收单、供应商送货单这几类文档，共同构成检索范围。资料按批、按日更新，同一供应商在不同日期到货的批次各有独立记录。

这些资料进入知识库后，最小搜索单位是库，集合只承担分类管理。一组数据可映射多组向量，检索命中任一向量即召回该组数据。门店服务与内部培训场景中，检索用于让收货人员找到对应批次的温度记录、验收结论和拒收依据。

## 这些特征在「知识库检索与召回」这一环带来什么约束

同一批次涉及温度记录、验收单、拒收单多份文档，检索词若只写“验收”容易召回其他批次的同类文档。文档含批次号、供应商名称、到货日期等精确字段，全文检索适合编号类查询，语义检索适合自然语言描述。混合检索通过 RRF 融合多路结果，重排需具备模型并按设置启用，重排得分为 0-1，可按得分过滤。引用上限以 token 为单位，最低相关度仅在语义检索或结果重排时生效。知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联。检索结果不承担授权判断，也不隔离未经授权的记录。

假设演练样本：供核对的材料原文为“2025年3月12日，供应商甲配送批次 A-0312 到店，冷链车温控记录显示全程 2℃ 至 5℃。门店收货员当日完成抽检，到货验收单登记为合格入库。”一条待判定的拟稿句为“供应商甲批次 A-0312 因温度超标被拒收。”该拟稿句与原文在验收结论字段上取值不同，原文登记合格入库，拟稿句称拒收，二者同主体、同批次、同日期，构成字段冲突。

## 配置怎么定

| 配置项 | 本次假设试验起点及理由 | 核对方式 |
| --- | --- | --- |
| 关联知识库 | 仅关联存放本批次温度记录与验收单的知识库 | 核对各库向量模型标识是否一致，排除不一致者 |
| 搜索模式 | 先以混合检索比对编号类与自然语言类问题 | 分别用批次号与描述性问法检索，观察召回内容 |
| 引用上限 | 假设起点为覆盖一份验收单与一份温度记录的 token 量 | 与长短不同的实际资料比较，观察内容是否完整 |
| 最低相关度 | 假设起点取中间值，用于观察过滤效果 | 先标注相关与无关样本，再比较不同取值 |
| 问题优化 | 对含指代的多轮追问开启，对明确问题关闭 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 在具备重排模型且候选较多时启用 | 观察重排得分是否用于过滤，记录实际排序 |

## 容易做错的三处

1. 把检索命中当作授权通过。检索返回引用内容，业务审批、数据库写入和外部同步需要各自的下游实现，检索结果不构成对批次放行或拒收的授权。
2. 跨向量模型关联知识库。节点要求关联相同向量模型的知识库，遇到模型标识不一致的库应排除，记录实际观察，不执行跨模型检索来比较漏召回。
3. 把拟稿句当作已核实结论。样本中拟稿句称批次被拒收，原文登记合格入库，二者在同一字段上取值不同，属于待核实冲突，不能据此认定拒收已发生。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句，比较验收结论字段。原文为合格入库，拟稿句为拒收，同一主体、同一批次、同一日期下取值不同，判定为字段冲突，需回到原始验收单核实。
2. 输入批次号 A-0312 与描述性问法，比较召回内容是否指向该批次。若召回内容包含其他批次或缺失温度记录，记录为未命中该批次，调整搜索模式后重新观察。
3. 输入一条无对应资料的问题，观察引用内容数组。文档说明引用长度可以为 0，空结果链路仍走通；用明确的纸面输入核对下游设计，不认定虚构规则检索必然返回空数组。
