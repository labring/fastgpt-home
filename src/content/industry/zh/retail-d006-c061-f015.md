# 生鲜称重分拣的门店服务与内部培训：知识库检索与召回

## 这个品类的数据长什么样

称重分拣发生在仓内履约环节，核心是重量与规格，主要数据来源为WMS、电子秤、订单系统与质检照片。门店服务与内部培训要处理的文档集中在分拣任务单、称重标签、少称补偿单和质检记录四类。这些材料的共同点是主体、对象、状态与有效范围写在同一张单据上：分拣任务单记录订单与规格要求，称重标签记录实际重量与时间，少称补偿单记录差额与处理状态，质检记录记录抽检结论。数据更新频率为每单与每日，检索时须按单据类型和日期范围限定范围，否则同类单据会互相干扰。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联。检索是对整个库进行搜索，集合仅用于分类管理。语义检索依赖向量距离，全文检索依赖关键词命中，混合检索通过RRF融合，重排须具备模型并按设置启用，图片检索须有相应图像输入及模型能力。最低相关度仅在语义检索或使用结果重排时生效。引用上限以token为单位，输出引用内容为数组，长度可以为0。检索结果不构成授权，也不负责权限或实体隔离。

假设演练样本：一份分拣任务单原文为「任务单号FQ-0417-023，订单尾号8821，规格要求净重500克±20克，分拣员A，日期2024年4月17日」。一份称重标签原文为「标签号T-0417-023，实际重量486克，打印时间2024年4月17日10时12分」。一份少称补偿单原文为「补偿单号BC-0417-023，差额14克，状态待审核，登记日期2024年4月17日」。一条待判定的拟稿句为「该订单已完成少称补偿并已退款」。核对主体为同一订单尾号8821，核对对象为差额14克，核对状态为待审核。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联同一向量模型的分拣任务单库 | 核向量模型标识，排除不同模型库，比较关联清单 |
| 搜索模式 | 先按语义检索测试，再按全文检索测试 | 比较两种模式下同一问题的召回内容差异 |
| 引用上限 | 本次假设起点为1500 token | 用长短不同的任务单与补偿单比较内容完整性 |
| 最低相关度 | 本次假设起点为0.35 | 先标注相关与无关样本，比较过滤前后条数 |
| 问题优化 | 对多轮追问开启，单轮明确问题关闭 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型时按设置启用 | 比较重排得分与向量得分对同一候选的排序 |

## 容易做错的三处

1. 把待审核的少称补偿单当作已完成退款。输入为补偿单BC-0417-023，比较状态字段「待审核」与拟稿句「已完成少称补偿并已退款」，观察结果为状态字段未载明已完成或已退款，拟稿句未获支持。
2. 把不同向量模型的知识库共同关联后执行检索。输入为两个向量模型标识不同的库，比较标识是否一致，观察结果为标识不一致时排除该库，不执行跨模型检索来比较漏召回。
3. 把最低相关度当作权限或实体过滤。输入为一条属于其他门店的记录，比较最低相关度设置与访问权限来源，观察结果为相关度数值不改变访问范围，权限须由下游实现。

## 怎么确认配好了

1. 输入假设样本中的分拣任务单FQ-0417-023与称重标签T-0417-023，比较检索结果是否同时命中两张单据且主体为同一订单尾号8821，观察结果为两条引用均出现且主体一致时满足条件。
2. 输入拟稿句「该订单已完成少称补偿并已退款」，比较补偿单BC-0417-023的状态字段「待审核」，观察结果为状态字段未载明已完成或已退款时，拟稿句判定为未获支持，保留证据缺口。
3. 输入一个明确不含相关单据的纸面查询，比较输出引用数组，观察结果为数组长度为0时下游链路仍走通，不声称虚构规则检索一定返回空数组。
