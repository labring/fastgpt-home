# 直播售后集中处理的门店服务与内部培训：表单与交互

## 这个品类的数据长什么样

在直播售后集中处理的门店服务与内部培训中，本页说明FastGPT的表单与交互如何衔接资料。直播售后教学表单要保留订单身份、改址申请和补发阶段，演练提交不证明真实订单已经变更。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟教学输入包含客户拟改地址的原话、待确认订单和补发安排，通知模板只是参考。学员可提交这些文字，再选择核本单关系或补执行记录；它们用于材料判断练习，不是真实客户操作。改址申请不证明身份或变更获准，补发安排也不说明包裹已交承运。接收步骤应保留来源及待确认，不能让模板补出本单处理结论。

## 配置怎么定

| 直播售后教学 | 自拟材料阶段 | 接收核法 |
| --- | --- | --- |
| 改址原话 | 仅申请 | 非已授权变更 |
| 订单关系 | 尚待确认 | 排除他单 |
| 补发安排 | 非承运交接 | 取实际执行 |
| 通知模板 | 仅作参考 | 不补处理结果 |
| 学员路径 | 核对应或补记录 | 交互非实操通过 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

他单原话混入：若别单地址用于本题，应核原句订单关系；申请冒改好：若客户提出改址变后台已更新，应取真实授权与修改记录；安排冒发出：若补发计划写成已交运，应查本次实际交接。三项分别核身份、变更动作和履约阶段，不由学员选择确认。

## 怎么确认配好了

验收检查提交原文与所选路径收到的订单，补对应后只修身份说明，地址及物流仍需各自执行依据。若只补通知模板，不应改变订单状态。正式改址、补发和通知发送需另接流程核权限与回执，交互记录及继续不代表平台已受理，也不说明学员通过实操评估或真实售后已关闭。
