# 直播选品与样品质检的门店服务与内部培训：表单与交互

## 这个品类的数据长什么样

在直播选品与样品质检的门店服务与内部培训中，本页说明FastGPT的表单与交互如何衔接资料。样品质检教学需要分清报告对象、观察是否结束和选品意见状态，表单收集不替代真实检查与选品决定。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟练习列样品观察待完成，报告所指为另一送检样，选品意见仍是草稿。表单可收样品关系与这些原句，人员选择补对象对应或核观察记录。商品名称相同不足以拼接报告，未完成观察也不提供最终结论；交互收集应把这些限制传给后续教学步骤，不能从材料提交推定样品已通过或商品可以采购。

## 配置怎么定

| 样品教学表单 | 自拟来源状态 | 所需证据 |
| --- | --- | --- |
| 样品观察 | 尚未完成 | 非最终结论 |
| 报告对象 | 另一送检样 | 核本件对应 |
| 选品意见 | 仍为草稿 | 非批准 |
| 后续输入 | 限制与身份保留 | 查看实际接收 |
| 真实业务 | 质检采购另接 | 提交不评能力 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

报告串样：若他样资料支持本件，应核送检身份与来源；未完冒结论：若观察待办写成检查已定，应取实际完成记录；草稿冒批准：若选品建议被称已获准，应查真实决定依据。三项分别核对象、观察阶段和决策，不能由选项进入下一步补齐。

## 怎么确认配好了

验收比较提交与实际接收的样品身份，补本件对应后只修报告关系，观察和选品仍缺时继续列待核。若只是重新整理草稿，不改变批准状态。真实质检、采购和上架决定需另接业务流程核权限及回执，节点等待与继续不证明样品品质，也不自动评定人员能力或完成现实选品。
