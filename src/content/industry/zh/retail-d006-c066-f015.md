# 短视频挂车分销运营的门店服务与内部培训：知识库检索与召回

## 这个品类的数据长什么样

短视频挂车分销以内容长期曝光配合商品链接转化，日常处理短视频脚本、挂车商品清单、佣金计划与违规反馈。门店服务与内部培训场景中，店员需要按脚本口径回答挂车商品归属、佣金计划有效期和违规整改要求，检索范围集中在这些材料的已入库版本。资料更新频率为日、周，检索结果反映的是入库时点的内容，门店交接时不能把检索命中当成授权生效。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不能共同关联；执行前先核对向量模型标识，排除不符合者并记录观察，不通过跨模型检索比较漏召回。搜索模式按测试问题在语义检索、全文检索与混合检索之间比较，不预设一种模式适合全部资料。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效，问题优化用于指代消除和问题扩展。混合检索经 RRF 融合多路结果，RRF 是融合过程，不作为独立开关。重排与图片检索须具备相应模型能力并按设置启用，文档流程图中的可选路径不代表每次请求全部执行。检索与相关度不承担权限或实体隔离功能，检索命中不表示操作已获授权。

假设演练样本：某门店内部培训材料原文为“挂车商品A的佣金计划自2025年3月1日起生效，有效期至2025年6月30日；门店店员在有效期内可按脚本口径介绍该商品。”待判定的交接请求为“请确认商品A的佣金计划在2025年7月仍可继续用于门店介绍。”该请求涉及的主体为门店店员，对象为商品A佣金计划，状态为有效期届满后的使用请求，有效范围止于2025年6月30日。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方式 |
| --- | --- | --- |
| 关联的知识库 | 仅关联存放脚本、商品清单、佣金计划、违规反馈且向量模型标识一致的知识库 | 核对各库向量模型标识，标识不一致者不纳入关联 |
| 搜索模式 | 先用混合检索 | 与语义检索、全文检索对同一测试问题的召回内容比较，观察编号类与自然语言类问题的差异 |
| 引用上限 | 假设起点设为800 token | 用长短不同的实际资料测试引用内容是否完整，与更长或更短取值下的截断现象比较 |
| 最低相关度 | 假设起点设为0.4 | 先标注相关与无关样本，再与更高或更低阈值下的过滤结果比较 |
| 问题优化 | 先在多轮追问与短问题场景开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 按设置启用并观察得分 | 比较重排前后候选排序，核对得分是否用于过滤 |

## 容易做错的三处

1. 把检索命中当作授权执行。样本中商品A佣金计划有效期止于2025年6月30日，检索到该材料只说明内容已入库，不说明7月仍可使用。核对输入为材料原文与交接请求，比较对象为有效期字段与请求日期，观察到日期超出有效期即记录为待核实，不写成否定或冲突。
2. 把跨向量模型的库共同关联。核对各库向量模型标识，标识不一致者排除并记录实际观察，不据此推断漏召回或冗余等运行结果。
3. 把可选检索路径当成每次执行。图片检索须有图像输入及模型能力，重排须具备模型并按设置启用；未提供对应输入或能力时，记录该路径未执行，不推断其返回结果。

## 怎么确认配好了

1. 输入假设样本中商品A佣金计划的材料原文与交接请求，比较有效期字段与请求日期，观察结果是否落在有效期内；落在有效期外时记录为待核实，保留证据缺口。
2. 输入同一测试问题分别在语义检索与全文检索下执行，比较两者召回内容与编号、自然语言表述的匹配情况，观察是否存在某一路未召回；未召回时记录实际观察，不保证首条命中或全部召回。
3. 输入明确的纸面空结果[]核对下游设计，观察引用内容长度为0时输出链路是否走通；该核对不声称虚构规则检索一定返回[]，也不声称无关查询必为空。
