# 社区团购团长运营的门店服务与内部培训：表单与交互

## 这个品类的数据长什么样

在社区团购团长运营的门店服务与内部培训中，本页说明FastGPT的表单与交互如何衔接资料。团长培训表单分开名单练习、群通知与真实履约，保留当前班次和示例身份。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟培训材料只练习核对一份示例名单，真实通知尚未发送，历史练习是另一班次。表单可收当前班次和练习问题，让学员选择补对象说明或继续阅读示例。示例有人员栏不说明已取得真实会员资料，培训结束也不证明群通知已发。下游应收到班次与练习用途，不能把历史完成状态放进当前演练结果。

## 配置怎么定

| 团长培训表单 | 练习范围 | 核对动作 |
| --- | --- | --- |
| 示例名单 | 只练核对 | 非会员实录 |
| 班次 | 本次与旧班 | 核对应 |
| 真实通知 | 尚未发送 | 不冒完成 |
| 人员选择 | 继续或补说明 | 非发送动作 |
| 业务执行 | 群权限与回执 | 独立验证 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

示例名单冒真实数据时，核材料用途与来源；他班结果串入时，核班次；继续选项被写成通知已发送时，查实际发送记录。三处分别核资料性质、对象和执行阶段。

## 怎么确认配好了

验收对比填写与接收的练习说明，分别问本次做什么、哪些未执行。补示例说明仅改变其阅读范围。节点等待后继续不访问真实群或发布消息，正式通知和履约需独立权限及证据，培训表单不代业务登记。 示例名单保留演示标记，实际通知对象需从本次活动资料取得；缺少名单时记录待补，不从旧团复制。
