# 经销商返利核算的门店服务与内部培训：知识库检索与召回

## 这个品类的数据长什么样

返利核算发生在销售之后，核心是政策口径与财务处理。品牌财务、渠道销售和经销商财务围绕返利政策、销量达成表、对账单、红字发票四类材料核对达成口径、扣除退货金额、开票冲抵。资料更新频率为月或季，本页功能不依赖更新节奏，故不展开。门店服务与内部培训场景中，一线人员需要从知识库取回政策口径、对账说明和开票冲抵规则，检索结果直接影响对外答复的一致性。返利争议、渠道冲突与收入确认错误是出错的后果，因此检索环节要求主体、期间、字段三者对齐。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，只核标识并排除不符合者，记录实际观察，不推断关联后的运行结果。搜索模式分为语义检索、全文检索与混合检索，需按测试问题比较，不预设一种模式适合全部资料。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，需比较原问题与优化后问题，核对主体是否被改错。混合检索通过 RRF 融合多路结果，重排需具备模型且按设置启用，图片检索须有相应图像输入及模型能力，文档总流程图列出的可选路径不代表每次请求全部执行。检索与相似度评分不承担权限或实体隔离职责，检索不是授权。节点输出引用内容为数组，长度可以为 0。

假设演练样本：材料原文为「某品牌2025年第二季度经销商返利政策第4条：季度达成率按扣除退货后的净销售额计算，退货以经销商签收退回入库日期为准。」待判定的拟稿句为「本季度返利按经销商申报销售额计算，退货在原销售月份冲减。」该拟稿句与原文在计算口径和退货归属期间两个字段上取值不同，属于待核实项，需保留证据缺口，不补造授权或生效条款。

## 配置怎么定

| 配置项 | 本页相关取值或核对项 | 依据与说明 |
| --- | --- | --- |
| 关联的知识库 | 返利政策库、对账与开票说明库，核对其向量模型标识一致 | 节点可关联多个相同向量模型的知识库 |
| 搜索模式 | 按测试问题分别比较语义、全文、混合三种结果 | 不预设单一模式适合全部资料 |
| 引用上限 | 本次假设试验起点设为 2000 token，因政策条款与对账说明单条较长，与 1000 token 的结果比较内容完整性 | 单位为 token，起点为假设值，非官方默认 |
| 最低相关度 | 仅在语义检索或结果重排时生效，先标注相关与无关样本再调 | 该值为过滤阈值，不是排序规则 |
| 问题优化 | 比较多轮追问的原问题与优化后问题，核对返利主体与期间是否被改错 | 用于指代消除和问题扩展 |
| 结果重排 | 具备重排模型并按设置启用后，用重排得分过滤 | 重排需模型且按设置启用 |

## 容易做错的三处

1. 将跨向量模型的知识库共同关联。输入为两个库的向量模型标识，比较两者是否一致，观察结果为标识不一致时排除该库，不执行跨模型检索来比较漏召回。
2. 将最低相关度当作权限或实体过滤。输入为一条无关业务的查询，比较返回内容是否属于目标返利政策范围，观察结果为相似度分数不排除未授权记录，权限需另接系统实现。
3. 将问题优化后的主体改错仍直接采用。输入为含指代的原问题与优化后问题，比较返利主体、期间、字段是否一致，观察结果为主体被替换时记录为待核实，不进入答复。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句，比较计算口径与退货归属期间两个字段，观察结果为两处取值不一致时判定为待核实，不得判定为矛盾或否定。
2. 输入一条精确编号类查询，比较全文检索与语义检索的返回内容，观察结果为编号命中情况需按实际观察记录，不保证首条命中或全部召回。
3. 输入空数组引用内容，核对下游节点对长度为零的引用链路的处理设计，观察结果为下游是否走通需按实际配置确认，不声称虚构规则检索一定返回空数组。
