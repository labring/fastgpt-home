# 跨境平台结算与汇兑的门店服务与内部培训：多轮对话与提示词

## 这个品类的数据长什么样

在跨境平台结算与汇兑的门店服务与内部培训中，本页说明FastGPT的多轮对话与提示词如何衔接资料。核对销售趋势问题所需期间，避免在培训中串用其他商品记录。所用场景为自拟文字测试。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

培训样例要求用商品M的结算记录解释销售趋势，但只有销售数量和销售额还不足以形成趋势比较。应先确认是否提供了可比较期间及其记录，把本轮学习任务限定为解读已有数据，或明确列出尚缺的比较材料。测试接续追问时，检查历史中的商品G文案任务是否被带到商品M的培训问题。培训回答引用哪份结算单，应与实际输入逐一对应，不能将另一个任务的概括当作本题来源。

## 配置怎么定

| 核对项 | 培训问题所需内容 | 检查方式 |
| --- | --- | --- |
| 学习目标 | 商品M的销售记录未给出完整趋势比较 | 列清可比较期间是否提供 |
| 追问主体 | 培训用商品M与文案用商品G分开 | 检查历史有无带入另一任务的概括 |
| 双份金额 | 商品N结算单与对账表分别回查 | 不在追问中预设一方优先 |
| 指代处理 | 优化问题继续保留商品N及来源 | 观察是否误用已讨论的商品H |
| 培训缺项 | 商品O仍缺手册或产品说明 | 新增资料、实际历史和答案分别保存 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `提示词与任务` | 说明资料、任务和缺证据处理。 |
| `历史记录` | 核实际提交的历史输入。 |
| `问题优化` | 指代消除与问题扩展需复核。 |
| `模型与长度` | 上下文与回复长度分别核对。 |
| `回复格式` | json_schema需给格式并验解析。 |

## 容易做错的三处

- 商品M只有数量和销售额却被写出升降趋势：核可比较期间与来源，保留原记录和判断，历史G的概括不能补本题比较依据。

- 商品N双份记录追问被优化成H或丢一方：保存原问、优化问及实际输入，恢复两份身份、期间币种和定义，不直接教某份必优先。

- 商品O产品培训沿用历史特征：核手册或产品说明出处，结算只有销售信息，持续追问不使缺手册变成已有材料，补源后同题复核。

## 怎么确认配好了

商品O的产品特点需要内部培训手册或产品说明，结算单只提供销售信息。问题持续出现在对话中，不会让缺少的手册变成已有输入。验收应检查回答是否明确区分销售记录和产品培训依据，是否把早前会话的产品特征移用到商品O。补充手册后，用原培训问题和一次追问复测，分别保存新资料、实际历史与答案，以核对依据变化。
