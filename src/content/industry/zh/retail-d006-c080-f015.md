# 连锁门店价格与陈列稽核的门店服务与内部培训：知识库检索与召回

## 这个品类的数据长什么样

价格与陈列稽核发生在日常经营期，督导按周或按月巡店，产生巡店照片、价签清单、陈列标准与整改通知。这些材料进入知识库后，检索请求通常来自区域督导或门店店长的内部培训场景：询问某档促销的价签要求、某类陈列标准，或某份整改通知的当前状态。资料更新频率为周或月，检索结果反映的是入库时的版本。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的库，跨向量模型的库不能共同关联。检索按语义检索、全文检索或混合检索召回候选，混合检索通过 RRF 融合结果，重排须具备模型并按设置启用。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。检索与相似度不承担权限或实体隔离：命中一份整改通知，不表示该门店已被授权执行整改，也不表示通知已获批准。

假设演练样本：某连锁运营部内部培训资料含三句原文——“2024年6月华东区促销档期要求A类门店价签统一更换，执行期6月1日至6月30日。”“B类门店价签更换执行期为6月15日至6月30日。”“整改通知单编号ZG-2024-0612，状态：待审核。”一条待判定拟稿句为“华东区A类门店6月1日起执行新价签，该整改通知已批准。”核对时，前两句支持A类门店6月1日执行，第三句仅显示待审核，拟稿句后半段未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联使用同一向量模型的培训资料库 | 先核各库向量模型标识，排除不一致者，不执行跨模型检索 |
| 搜索模式 | 混合检索 | 与语义检索、全文检索分别比较同一问题的召回候选 |
| 引用上限 | 本次假设试验起点设为800 token | 用长短不同的价签清单与陈列标准测试内容是否完整，再调整 |
| 最低相关度 | 本次假设试验起点设为0.35 | 先标注相关与无关样本，比较阈值调整后的返回集合 |
| 问题优化 | 先开启，比较原问题与优化后问题 | 核对主体是否被改错，如“A类门店”是否被替换 |
| 结果重排 | 具备重排模型时启用 | 比较启用前后的排序，确认候选是否足够 |

## 容易做错的三处

1. 把检索命中当成授权。输入“ZG-2024-0612整改通知”，检索返回该通知原文，观察结果是返回内容仅含“状态：待审核”。若据此判定门店已获整改授权，输入与比较对象错位，待审核不构成批准。
2. 跨向量模型关联库。输入两个向量模型标识不同的库，比较标识是否一致。若仍执行共同关联并推断漏召回或冗余，属于对未文档化运行结果的断言，正确动作是核标识、排除不符者并记录实际观察。
3. 把相似度当作实体过滤。输入一条涉及A类门店的问题，观察返回是否包含B类门店片段。相似度不排除其他门店记录，若据此认为检索已按门店隔离，属于把相关性误当权限过滤。

## 怎么确认配好了

1. 输入假设原文三句与拟稿句，比较拟稿句后半段与“状态：待审核”是否同主体、同字段。仅当原文出现明确批准字段且取值互斥时，才判定矛盾；当前证据下应记录为未获支持。
2. 输入一条含明确编号的问题，分别以全文检索与语义检索执行，比较返回候选是否包含该编号原文。全文检索更依赖关键词命中，若语义检索未返回该编号，记录为语义路径未命中，不推断编号不存在。
3. 输入纸面空结果[]，核对下游节点是否按引用内容长度可为0继续走通。不声称虚构规则检索一定返回[]，只观察空引用链路的承接设计。
