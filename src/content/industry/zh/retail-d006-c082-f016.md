# 逆向退货入仓质检的门店服务与内部培训：表单与交互

## 这个品类的数据长什么样

在逆向退货入仓质检的门店服务与内部培训中，本页说明FastGPT的表单与交互如何衔接资料。逆向入仓培训分清收件、质检建议与库存处置，练习表单不决定退货合格或可售。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

假设练习单说包裹已收，检测意见只列待检项目，货品身份仍待订单对应。表单收仓库、事项与原句，人员选择补身份或核质检材料。测试必填缺项和补齐的行为，检查下游实际收到的版本；节点交互结束后传信息，不自带质检数据库或库存处置权限。

## 配置怎么定

| 逆向入仓培训 | 假设资料 | 学习核验 |
| --- | --- | --- |
| 包裹接收 | 仅收件事件 | 非货品合格 |
| 待检项目 | 尚待检测 | 非全部通过 |
| 货物身份 | 订单对应未核 | 核实物关系 |
| 必填信息 | 缺项与补齐 | 看实际承接 |
| 库存处置 | 授权流程负责 | 独立检测回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

包裹已收被答货品合格时，查检测依据；待检项目被答全部通过时，对意见状态；身份未明货物被套本单时，核实物与订单对应。三处分别看事件、结论阶段和对象，课堂记录不能替真实检验。

## 怎么确认配好了

验收让学员指出入仓与合格的证据差别，两条路径逐项查输出承接。补订单对应只修身份，检测仍待真实材料；待检标记紧邻原句保留。正式验收、退货判定及库存回写需授权业务流程和回执，培训表单记录核对练习，不自行调整商品状态或确认可售。 退件身份紧邻仓库接收原句，待检项目保留尚未形成结论的性质；学员应说清补订单对应只能修身份，不能据此回答货物已经通过检查。
