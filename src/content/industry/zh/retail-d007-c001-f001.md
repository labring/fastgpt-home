# B2B平台撮合交易的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
B2B平台撮合交易依赖在线认证与电子合同，交易主体、询报价单、结算单分布在平台、企业信用公示系统、支付流水与物流轨迹中。经营报表与异常复盘要围绕企业认证资料、询报价单、电子合同、平台结算单展开，数据按日、按单更新。HTTP 接口把平台侧记录送入外部系统时，请求内容必须与这些材料的实际字段对齐，接口只能传递已存在的值，不能替代身份审核、合同生效或结算确认。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向指定地址发送请求，Params、Headers、Body 均可通过 `{{}}` 引用全局变量、系统变量与前方节点输出，URL 同样可引用变量。返回值通过 JSON path 提取，输出类型选择字符串时按 json 字符串格式化。系统变量含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于环境差异。对话接口以 APIKey 鉴权，appId 优先级为 body.appId、`<apiKey>-<appId>`、apikey 关联的 appId；model、temperature 等字段由编排决定，不随 API 参数改变；detail=true 时可在 responseData 中查看模块状态与 tokens，接口不返回实际消耗 Token 值。检索或表单只收集与传递值，业务核验、审批、数据库写入与外部同步需要对应的下游实现。

假设演练样本：一份供应商认证资料原文写有“主体名称：华北某某机械配件有限公司；统一社会信用代码：911XXXXXXXXXXXXXXX；认证状态：待审核；提交日期：2025-03-11”。同批询报价单原文写有“报价单号：Q-2025-0311-07；报价有效期至：2025-04-10；供货期限：另议”。一条拟稿句写为“该供应商已完成认证，可按电子合同约定供货”。待判定交接请求写为“将上述认证状态与报价有效期通过 HTTP 接口推送至外部系统并标记为已生效”。

## 配置怎么定
下表围绕上述样本，列出与本页主任务相关的官方已说明设置或实施核对项。

| 配置项 | 取值或核对内容 | 与样本的关系 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选择地址与方法，地址可引用变量 | 推送认证状态与报价有效期时先确认目标地址 |
| Headers 鉴权 | Authorization 通过安全配置注入，不写入公开样例 | 调用外部系统时凭证不随材料原文暴露 |
| Body 结构 | 仅在相应请求类型下使用，JSON 结构与外部契约一致 | 认证状态字段应为“待审核”，报价有效期应为日期 |
| 变量引用 | 逐项核对全局变量、系统变量与前方节点输出 | 样本值来自资料与询报价单，不引用未提供字段 |
| 返回值提取 | 按 JSON path 配置 key，输出类型选择字符串 | 核对接口响应中是否含认证状态与有效期字段 |
| 调试身份字段 | chatId、responseChatItemId 在测试模式下不存在 | 调试取空值不记为业务异常 |

## 容易做错的三处
1. 将认证状态“待审核”直接写成“已完成认证”。输入为样本原文的“认证状态：待审核”，比较对象为拟稿句“已完成认证”，可观察结果是两者取值互斥，拟稿句未获支持。
2. 将报价有效期“至 2025-04-10”当作供货期限。输入为询报价单原文，比较对象为拟稿句“可按电子合同约定供货”，可观察结果是报价有效期与供货期限为不同字段，供货期限原文写“另议”，该结论缺少证据。
3. 将待判定的交接请求当作已执行。输入为“推送并标记为已生效”的请求文本，比较对象为接口返回与外部系统状态，可观察结果是请求文本本身不构成执行结果，实际状态需另查。

## 怎么确认配好了
1. 取样本认证资料原文，输入“认证状态：待审核”，与拟稿句“已完成认证”逐字比较，仅当原文出现“已完成”或等效已生效取值时，该结论才满足条件；当前观察为待核实。
2. 取样本询报价单原文，输入“报价有效期至：2025-04-10”与“供货期限：另议”，与拟稿句“可按电子合同约定供货”比较，仅当同一字段出现明确供货期限取值时，该结论才满足条件；当前观察为未获支持。
3. 取待判定交接请求文本，输入“推送并标记为已生效”，与接口响应及外部系统状态比较，仅当响应与外部状态均显示对应结果时，该请求才满足已执行条件；当前观察为请求处于待判定，执行结果未知。
