# B2B平台撮合交易的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

在B2B平台撮合交易的经营报表与异常复盘中，本页说明FastGPT的对话日志与审计如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

平台结算单在自拟样例中列出某期间的交易总额与手续费，经营报表希望汇总这些内容。对话日志只能帮助核对这次请求实际读取和返回了什么；先关联目标会话与结算单身份，再按接口契约检查运行详情及responseData中的真实字段。手续费的定义、金额汇总算法以及期间是否一致，仍需业务原记录和已实现的计算方法支持，不能由日志存在推定。

## 配置怎么定

| 实施核对项 | 本题输入 | 验收线索 |
| --- | --- | --- |
| 目标会话 | 本次平台结算单阅读范围：平台结算单中列明的交易总额与手续费 | 先对应会话与资料身份，避免把另一入口的记录混入。 |
| 运行详情 | 平台结算单中列明的交易总额与手续费 | 按实际接口契约检查detail及responseData，核查真实返回内容。 |
| 字段与解释 | 电子合同、平台结算单需要回查：电子合同中的最终结算金额与平台结算单中的结算金额 | 输入、引用、外部返回和解释分列；未返回字段不推定已留存。 |
| 调试环境 | 平台结算单尚缺的依据：尚缺不同商品类别的销售数据或分类信息 | 先核执行环境和身份字段，再区分技术缺值与业务证据缺口。 |
| 业务核验 | 可回查的业务来源：B2B平台、国家企业信用信息公示系统、支付流水、物流轨迹 | 对账、权限和留存需另有记录；日志存在不等于业务审计完成。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

电子合同的最终结算金额与平台结算单金额不同，应先回查两处原文及适用范围，再看它们是否进入同一次会话。把用户输入、检索引用、外部返回和模型解释分开保存，有助于定位哪一步使用了哪项内容。日志里出现“结算金额”不表示两份数字口径相同；没有返回的字段也不能推定已在后台留存，差异原因需继续取证。 若把测试问答补入正式结算会话，还要核入口、chatId与原始历史，分开两种调用；测试解释不能作为本次财务办理或正式对账的凭证。

## 怎么确认配好了

只有结算合计，无法形成不同商品类别的销售占比；还缺分类信息及对应销售记录。应把这个业务证据缺口与技术日志分列，记录由谁提供，补齐后再核原问题的实际输入和返回。测试与正式调用的身份字段分别查执行环境。对账结论、凭证保存和审计要求须由实际业务方案落实，不能将一次成功对话或可查日志当作报表已完成核验。
