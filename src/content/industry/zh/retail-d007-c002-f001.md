# MCN机构达人管理的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

在MCN机构达人管理的经营报表与异常复盘中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

MCN经营复盘可先核账号表现资料、排期与合同覆盖的对象及时间是否相接。自拟报表材料只说明某段合作曾安排直播，没有给实际执行记录，不能由排期推出已经执行或产生效果。若拟通过HTTP取得外部账号记录，应先有真实服务契约，明确请求地址、方法与查询范围；不预设MCN后台存在特定接口，也不从账号显示名直接推定合同合作方身份。

## 配置怎么定

| 复盘核对 | 本题拟议资料 | 实际验收线索 |
| --- | --- | --- |
| 执行与计划 | 排期有，实际执行依据缺 | 未从计划推出本期效果 |
| 期间传递 | 原定复盘范围与发送值 | 响应覆盖同一期间 |
| 记录类型 | 培训与账号运营资料分开 | 未互相替代执行依据 |
| 对象对应 | 账号显示名及合同主体 | 身份关系有实际材料支持 |
| 后续提交 | 报表发布或台账修改 | 独立授权与操作结果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

若请求引用的是排期时间，返回资料覆盖的却是另一期间，就无法解释本次复盘，应排查原始时间说明、发送值与响应范围。另一个失败是把培训完成记录当成账号运营已执行，需对照返回段落与结论，分开保存不同类型记录。即使HTTP交互成功，资料仍可能不覆盖本次问题，不能因有响应就补出执行次数或成效判断。 可再准备“原定直播、后来取消”的排期说明，与仅列合作品类的合同并读。取消文字要看是否确指本场，合同只能支持合作范围；两者都不能补出实际直播时长或账号表现。若返回培训记录，应先登记来源不符，不纳入运营执行清单。还需区分已通知取消与确未执行，缺实际执行材料时，两种结论都不能仅靠调度描述作出。

## 怎么确认配好了

验收并列保留合作对象、拟复盘期间、真实请求与返回资料范围，补实际执行依据后重复相同问题，看答复是否只解释取得的事实。Params、Headers及适用的Body按外部契约核，鉴权留在安全配置。账号操作、台账修改或对外提交复盘若需要，另核授权与业务结果；读取完成不证明本期执行已对账，也不能从缺记录推断活动没有发生。
