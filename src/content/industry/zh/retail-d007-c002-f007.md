# MCN机构达人管理的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

在MCN机构达人管理的经营报表与异常复盘中，本页说明FastGPT的对话日志与审计如何衔接资料。MCN复盘按机构汇总、达人归属和动作阶段追日志，运行记录不确认个人业绩或款项。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

假设机构汇总只列内容提交，达人对应表尚待复核，结算备注仍请双方确认。定位本次chatId和项目，再查实际输入及历史是否保留这些条件。运行详情按官方契约取得，返回字段不保证完整个人明细、合同或资金资料均已进入上下文；本例不填业绩或真实金额。

## 配置怎么定

| MCN复盘日志 | 纸面状态 | 证据检查 |
| --- | --- | --- |
| 机构汇总 | 内容已提交 | 非个人已发布 |
| 达人对应 | 等待复核 | 不推确定归属 |
| 结算备注 | 请双方确认 | 非双方结清 |
| 个人详情 | 返回覆盖需核 | 不推没有合作 |
| 正式结果 | 发布支付另走 | 独立授权凭据 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

机构提交被答个人已发布时，对主体及发布证据；未核对应表被当确定归属时，查达人关系；请确认被答双方结清时，核认可与资金凭据。三处分别查聚合层级、身份可靠性和动作阶段，日志记录不能自行补这些关系。

## 怎么确认配好了

验收调试与正式请求分别核身份历史，汇总原句和达人对应依据各列位置。补身份只修归属，业绩与结算继续按独立证据核。详情缺个人项时只说明本次未观察到，不推没有合作。正式发布、绩效认定及支付由授权业务流程决定，日志回看不计算或认可这些结果。 机构汇总的覆盖范围紧邻原句，达人对应未核处继续列明，避免个人结论超出已有资料。
