# Temu半托管卖家运营的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样
半托管卖家要自行维护海外库存和发货，经营数据分散在Temu Seller Center、境外仓WMS、物流轨迹和采购成本表中。日常文档包括商品申报表、海外库存表、价格申报和平台履约单，更新频率为日更和每单。经营报表与异常复盘需要把某笔履约单的库存扣减、发货状态和价格申报放在同一对话记录下核对。对话日志与审计在此环节的作用，是确认某次异常复盘所依据的会话、运行详情和字段值确实来自该次对话，不把页面会话与 API 会话混算。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话接口的 `chatId` 决定是否使用 FastGPT 上下文：不传入时完全由 `messages` 构建上下文；传入非空字符串时从数据库取会话，仅用最后一条消息作为用户问题。`detail=true` 才返回中间值和 `responseData`，`detail=false` 不返回。`responseChatItemId` 需在当前 `chatId` 下唯一。会话来源用 `source=api` 区分，清空应用会话仅清空 API Key 创建的会话。运行详情通过 `getResData` 按 `appId`、`chatId`、`dataId` 获取。这些字段决定审计时能核对什么，未返回的业务数据不能推定已完整留存。

假设演练样本：某半托管卖家在 2025 年 3 月 10 日有一笔履约单，商品为“折叠收纳箱”，海外库存表记录当日可售 120 件，平台履约单状态为“待发货”。拟稿句为：“该履约单已扣减库存并完成发货。”资料原文仅含上述三条记录，未载明扣减动作和发货完成时间。判定该拟稿句时，主体为同一履约单，期间为 2025 年 3 月 10 日，字段为库存数量与履约状态；原文未载明扣减和发货完成，该句属于未获支持。

## 配置怎么定
下表围绕上述样本，只列与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，非官方默认。

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| `appId` | 样本应用 ID | 核对请求体 `body.appId` 与会话列表返回的 `appId` 一致 |
| `chatId` | 样本会话 ID | 长度小于 250，与 `getHistories` 返回的 `chatId` 比较 |
| `detail` | `true` | 需核对 `responseData` 中间值，与 `detail=false` 时无该字段比较 |
| `source` | `api` | 区分 API 会话与页面会话，与页面来源记录分别统计 |
| `dataId` | 样本对话 ID | 用于 `getResData` 定位单条对话运行详情 |
| `responseChatItemId` | 样本响应 ID | 在当前 `chatId` 下唯一，与已有记录比较避免重复 |

## 容易做错的三处
1. 把 `detail=false` 的响应当作包含完整运行详情。输入为 `detail=false` 的请求，比较对象是 `responseData` 是否存在，观察结果为该字段缺失，此时不能据以核对模块级中间值。
2. 把页面会话与 API 会话合并统计。输入为 `source=api` 的 `getHistories` 请求，比较对象是返回列表中的 `chatId` 是否属于 API 来源，观察结果为页面会话不出现在该列表，混算会导致会话数偏大。
3. 把检索相似度当作权限或实体过滤。输入为带 `similarity` 的 `responseData`，比较对象是 `quoteList` 中 `datasetId` 是否属于目标库，观察结果为相似度高低不改变记录归属，不能据此判断某条记录已获授权。

## 怎么确认配好了
1. 用样本的 `appId`、`chatId`、`dataId` 调用 `getResData`，比较返回的 `moduleName`、`moduleType` 与预期节点，观察结果需与样本履约单对应的对话记录一致；若返回空列表，记录为未找到对应运行详情。
2. 用样本拟稿句对照原文三条记录，比较主体、期间、字段三项是否均有明确取值，观察结果为原文未载明扣减与发货完成，拟稿句判定为未获支持。
3. 用 `detail=true` 与 `detail=false` 分别请求同一 `chatId`，比较 `responseData` 字段是否存在，观察结果为仅 `detail=true` 时出现该字段；若两次均无该字段，记录为待核实，不推定留存完整。
