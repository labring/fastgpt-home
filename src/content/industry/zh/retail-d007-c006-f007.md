# 一般贸易出口报关的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样
一般贸易出口报关按每单推进，单据围绕出口报关单、商业发票、装箱单与合同展开，数据来自中国国际贸易单一窗口、海关编码库、货代提单与企业ERP。出口环节还会牵动出口退税凭证匹配，一旦申报差错，容易触发退单查验与退税受阻。经营报表与异常复盘要把这些单据与对话日志对齐到同一票业务，核对主体、对象与状态，才能判断某次交接请求处于什么授权位置。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话接口以 chatId 区分会话，以 dataId 区分会话下的对话。传入非空 chatId 时，系统从数据库取会话，并以 messages 数组最后一个内容作为用户问题，其余 message 被忽略；不传 chatId 时不使用上下文功能。responseChatItemId 若传入，会作为本次响应消息 ID 存入数据库，且需在当前 chatId 下唯一。需要中间值时设置 detail=true，非 stream 模式结果保存在 responseData，stream 模式通过 event 区分；不会返回实际消耗 Token 值，可设置 detail=true 后手动计算 responseData 里的 tokens。会话列表可用 source=api 只取通过 API 创建的会话；清空应用会话仅清空 API Key 创建的会话，不影响在线使用、分享链接等其他来源。日志存在只说明记录留存，对账、留存与合规要求由完整业务方案另行落实，检索与相似度不承担权限或实体隔离。

假设演练样本：某外贸公司单证员在 chatId 为 ex-2024-0007 的会话中，提交一条交接请求“请把本票出口报关单的申报要素交接给复核岗”。供核对的材料原文为：“合同号 HT-2024-0007，出口方为 A 公司，报关单草稿状态为待复核，装箱单数量与发票一致。”拟判定句为“该交接请求已获得复核授权”。核对时比较主体、对象与状态：材料只写明草稿处于待复核，未载明复核岗已确认或授权，因此该请求属于待核实，不能判定为已获授权。

## 配置怎么定
| 配置项 | 本页用途 | 依据或核对方式 |
| --- | --- | --- |
| appId | 定位目标应用 | 请求体传入 body.appId，或在密钥中带 appId |
| chatId | 区分目标会话 | 非空时取数据库会话，需自行保证唯一且长度小于 250 |
| dataId | 定位会话下具体对话 | 取自对话列表返回的 dataId |
| detail | 取回中间运行详情 | 设为 true 后检查 responseData |
| source | 限定会话来源 | 取 api 时只获取 API 创建的会话 |
| loadCustomFeedbacks | 读取自定义反馈 | 获取对话列表时可选传入 |

上述取值为本次假设试验起点，用于核对字段是否按预期返回，不表示官方默认值。

## 容易做错的三处
1. 把待复核状态当作已授权。材料写明报关单草稿状态为待复核，未写明复核岗确认，判定句称已获授权，两者主体与状态不一致。
2. 把不同 chatId 的会话合并统计。同一票业务若在多个 chatId 下产生对话，直接相加会混算不同入口的会话。
3. 把日志留存当作合规审计完成。日志记录存在，不能推出对账、留存与合规要求已经落实。

## 怎么确认配好了
1. 输入假设样本中的 chatId ex-2024-0007 与拟判定句，比较材料原文的主体、对象与状态，只有材料明确写出复核岗确认或授权，才满足已获授权条件；当前材料未载明，应记录为待核实。
2. 输入两个不同 chatId 的对话列表，比较各自返回的 list 与 total，只有分别统计且不合并，才满足会话隔离核对条件。
3. 输入 detail=true 的请求，比较返回的 responseData 是否包含模块状态与完整结果，只有字段按文档出现，才满足运行详情核对条件；未返回的业务数据保持未知。
