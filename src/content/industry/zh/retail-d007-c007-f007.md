# 一般贸易进口报关的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样
一般贸易进口报关围绕完税价格、运保费和税费缴纳展开，每单产生的进口报关单、商业发票、装箱单、提单与合同构成经营报表与异常复盘的基础材料。这些材料按每单节奏更新，数据来自国际贸易单一窗口、海关税则、货代到港通知与外汇付款单。对话日志与审计环节需要把一次对话的 chatId、dataId 与具体报关单号、发票号对应起来，才能判断某条问答属于哪一票业务。材料中的成交方式、运保费金额与税费口径若未在对话中留存，复盘时无法从日志本身还原，只能标记为未获支持。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话接口以 appId、chatId、dataId 标识一次会话与一条对话。传入 chatId 时，系统从数据库取会话并以 messages 数组最后一条作为用户问题，其余 message 被忽略；不传 chatId 时完全依赖传入 messages 构建上下文。需要中间值时设置 detail=true，非流式结果保存在 responseData，流式通过 event 区分。responseData 中不同模块的字段随版本有差异，未返回的业务数据不能推定已完整留存。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某进口商关务经理就一票报关单发起对话，材料原文为「报关单号 A-2024-0311，成交方式 CIF，运费人民币 1200 元，保费人民币 300 元，商业发票号 INV-7788，提单号 BILL-9901，合同号 CT-2024-05，上述运保费由卖方承担并已计入完税价格」。拟交接请求为「请确认该票运保费是否已计入完税价格，并生成异常复盘备注」。该请求处于待判定状态，对话日志中是否留存运保费字段尚需核对，不能视为已完成核对或已获授权执行。

## 配置怎么定
| 配置项 | 本页相关取值或核对点 | 说明与来源 |
| --- | --- | --- |
| appId | 请求体传入 body.appId | 官方对话接口说明，优先级高于其他来源 |
| chatId | 非空字符串，长度小于 250 | 用于从数据库取会话，须自行确保唯一 |
| detail | true 时返回中间值 | 非流式存于 responseData，流式按 event 区分 |
| responseChatItemId | 当前 chatId 下唯一 | 传入后作为响应消息 ID 存入数据库 |
| source | 取会话列表时填 api | 仅获取通过 API 创建的会话 |
| loadCustomFeedbacks | 读取对话列表时可选传入 | 决定是否读取自定义反馈 |

本次假设试验起点取 pageSize 为 20，理由是该值可覆盖一票报关单对应的多轮问答，比较对象为响应中 total 字段与实际返回条数是否一致。

## 容易做错的三处
1. 把不传 chatId 的调用与传入 chatId 的调用混算。前者完全依赖 messages 构建上下文，后者以最后一条 message 作为问题并取数据库会话，两者在复盘时对应不同的证据范围。
2. 依据检索结果相似度判断业务归属。score 与 similarity 反映检索相关程度，不构成实体或权限过滤，不能据此认定某条记录属于该票报关单或已获授权。
3. 把表单收集的值当作已完成业务核对。inputForm 仅收集输入，业务验证、审批、数据库写入与外部同步需要另行实现，待审核状态不证明缺少操作权限。

## 怎么确认配好了
1. 输入假设样本中的 chatId 与 messages，比较响应中 choices 内容与样本拟交接请求。若响应未包含运保费字段，则记录该字段在日志中未获支持，不得判定为已计入或未计入。
2. 输入 detail=true 与 stream=false，比较 responseData 中各模块字段与官方文档所列字段。若某模块未返回业务字段，记录缺口，不推定已完整留存。
3. 输入 source=api 调用获取会话列表，比较返回 total 与实际条数。若 total 大于返回条数，说明存在分页未取部分，需调整 offset 后重新观察，不保证一次取全。
