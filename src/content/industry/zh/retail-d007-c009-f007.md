# 亚马逊FBM自发货运营的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

亚马逊FBM自发货由卖家自行履约并设置退货地址，平台仓检验环节不参与，订单拣货单、发货确认单、退货地址设置与物流追踪表构成日常材料。这些材料逐单产生、按日汇总，客服邮件与承运商系统各自留存片段。经营报表与异常复盘依赖对话日志与审计时，核对对象是某笔订单在客服对话中的处理记录与上述单据是否指向同一主体、同一期间、同一字段。对话接口的 chatId 标识一个应用下的会话，dataId 标识会话下的一条对话，两者共同决定日志归属。行业资料给出的更新频率为每单、每日，本页据此理解材料节奏，不据此推断批量同步或实时机制。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话日志只证明某次请求与响应被记录，不证明退货地址已生效、承运商已揽收或退款已执行。检索与相似度分数不承担权限过滤，也不隔离不同店铺或不同客户的记录。运行详情需要按官方契约设置 detail，非流式结果保存在 responseData 中，流式结果通过 event 区分。日志存在与完成合规审计是两件事，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：材料原文为三句。第一句，客服邮件记录“订单 A-1001，买家反馈未收到货，承运商单号 TRK-7788，最后轨迹为运输中”。第二句，物流追踪表同一行记载“A-1001，TRK-7788，状态：运输中，更新日期 3 月 12 日”。第三句，退货地址设置页面记载“A-1001 所属店铺退货地址为 US-CA-01，生效日期 3 月 1 日”。待判定的拟稿句为：“A-1001 已完成退款，退货地址 US-CA-01 已失效。”该拟稿句涉及退款完成与地址失效两项事实，材料中均未出现对应记录。

## 配置怎么定

| 核对项 | 本次假设试验起点 | 比较方法与理由 |
| --- | --- | --- |
| 会话标识 chatId | 假设取值为 fbm-case-0312 | 与邮件、追踪表所记订单号关联的会话逐一比对，确认同一会话 |
| 对话标识 dataId | 假设取值为 rec-0312-01 | 在该 chatId 下核对唯一性，确认指向目标对话 |
| 运行详情 detail | 假设设为 true | 与 false 时的返回比较，确认 responseData 是否出现 |
| 流式开关 stream | 假设设为 false | 与 true 时的返回比较，确认结果位置差异 |
| 响应消息标识 responseChatItemId | 假设取值为 rsp-0312-01 | 在同一 chatId 下核对唯一性，避免覆盖 |
| 变量 variables | 假设传入订单号 A-1001 | 与材料原文比对，确认替换值来源 |

起点取值仅为本次纸面核对选定，用于说明比较对象，不作为官方默认值。

## 容易做错的三处

1. 把日志中出现的相似度分数当作权限或实体过滤依据。分数只表示检索相关程度，不排除其他店铺记录。检查方式：输入同一查询，比较返回条目中的 dataset_id 与目标库标识，观察是否混入非目标库条目。
2. 把待审核的退款申请当作已完成退款。申请处于待审核状态，退款执行需要下游实现。检查方式：在材料中查找退款完成字段，若仅有申请记录，则判定该事实未获支持。
3. 把不同向量模型的库共同关联后推断漏召回。跨模型不可共同关联，只能核对标识并排除不符合者。检查方式：比较各库的模型标识，记录不符合者并保留实际观察，不推断运行结果。

## 怎么确认配好了

1. 输入假设样本三句材料与拟稿句，比较拟稿句中“已完成退款”与材料中是否存在退款完成字段。若材料仅有未收到货反馈与运输中状态，则该句未获支持，需标记待核实。
2. 输入假设样本中“退货地址 US-CA-01 已失效”与退货地址设置页面记载的生效日期 3 月 1 日，比较是否存在失效日期或失效操作记录。若均未出现，则失效事实未获支持。
3. 输入 chatId fbm-case-0312 与 dataId rec-0312-01，比较返回记录中的 appId、chatId、dataId 是否与请求一致。若一致，则日志归属确认；若不一致，则记录差异并保留缺口。以上均为纸面核对，未实际调用接口。
