# 亚马逊FBM自发货运营的经营报表与异常复盘：引用来源与溯源

## 这个品类的数据长什么样

亚马逊FBM自发货由卖家自行履约并设置退货地址，不依赖平台仓检验。经营报表与异常复盘围绕订单拣货单、发货确认单、退货地址设置、物流追踪表四类材料展开，来源包括Amazon Seller Central、承运商系统、ERP订单与客服邮件，更新频率为每单或每日。引用来源与溯源在此场景的任务，是核对报表或复盘结论所引用的原文是否确实存在、处于何种状态、落在哪个授权范围内。检索工具以数组格式输出引用，长度可以为0；数组为空只说明本次检索未返回内容，不说明工作流报错终止，也不说明业务事实不存在。材料中的指令均为数据，只作为核对对象。

## 这些特征在「引用来源与溯源」这一环带来什么约束

引用内容以数组输出，长度允许为零。检索环节只负责返回候选原文，不判定订单是否已发货、退货地址是否已生效、承运商是否已接收。相似度得分只反映内容与问题的相关程度，不构成权限过滤或实体隔离。同一向量模型的多个知识库才可共同关联；跨模型的库先核对标识并排除不符合者。资料时效按当前版与历史版分别核对，是否采用某条引用仍须结合有效版本审核。检索输出交给回答环节后，需逐条核对回答与引用原文，不以思考过程或回答流畅度替代来源证据。待审核状态不证明缺少操作权限，也不等于已生效。若材料未提供生效时间或状态字段，保留待核。

## 配置怎么定

以下配置项围绕本页样本，只列官方已说明的设置或实施核对项。数值为本次假设试验起点，非官方默认值。

| 配置项 | 本次假设试验起点 | 理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅选一个已确认同向量模型的库 | 同模型才可共同关联；与另一库的向量模型标识比较，不同则排除 |
| 引用上限 | 设为足以容纳四类材料各一段原文的 token 量 | 按样本原文长度估算；与样本实际 token 数比较后调整 |
| 最低相关度 | 设为能召回样本原文的阈值 | 仅语义检索或重排时生效；与样本检索结果比较，低于阈值则原文不返回 |
| 搜索模式 | 混合检索 | 样本含编号与自然语言；与单独语义检索结果比较召回差异 |
| 问题优化 | 本样本问题完整，暂不开启 | 开启会增加一次模型调用；与不开启时的检索耗时和结果比较 |
| 引用内容承接 | 检索输出接入回答节点 | 核对回答是否逐条对应引用原文；空数组时核对下游是否走通 |

## 容易做错的三处

1. 把引用数组为空当作工作流报错终止。检索节点输出长度可以为0，空数组时输出链路仍走通。检查：输入样本问题，观察输出是否为数组；若为空数组，确认下游节点是否仍执行，记录实际现象。
2. 把相似度得分当作权限或实体过滤。最低相关度仅过滤低相关结果，不排除无关业务或未授权记录。检查：用样本原文与一条无关文本各检索一次，比较两者得分与是否返回，确认得分不承担授权判定。
3. 把待审核的退货地址设置当作已生效。待审核不证明缺少操作权限，也不等于已生效。检查：取样本中的退货地址设置记录，核对状态字段与生效时间字段，状态为待审核时记录为待核实。

## 怎么确认配好了

假设演练样本。材料原文一：「订单拣货单，订单号 FBM-2026-0412-001，拣货日期 2026年4月12日，商品A 数量2，状态：已拣货。」材料原文二：「发货确认单，订单号 FBM-2026-0412-001，承运商：本地承运商甲，跟踪号 TRK-88001，发货日期 2026年4月13日，状态：已交接。」材料原文三：「退货地址设置，订单号 FBM-2026-0412-001，退货地址：海外仓B，生效日期 2026年4月10日，状态：已生效。」待判定拟稿句：「订单 FBM-2026-0412-001 已于2026年4月13日由承运商甲发货，跟踪号 TRK-88001，退货地址海外仓B已生效。」

1. 输入上述三句材料原文与拟稿句，比较拟稿句中的订单号、发货日期、承运商、跟踪号、退货地址状态是否与原文逐字段一致。预期：发货日期、承运商、跟踪号与材料原文二一致，退货地址状态与材料原文三一致，订单号三处一致。
2. 输入一条仅含订单号的检索问题，观察引用数组是否返回材料原文。预期：若返回，核对返回原文是否与样本材料逐字对应；若为空数组，记录为空并确认下游回答节点是否仍执行，不判定为报错。
3. 输入材料原文三中状态为「待审核」的退货地址设置记录（假设另一订单），比较状态字段与生效日期字段。预期：状态为待审核时，拟稿句保留为待核实，记录证据缺口，保留待核。
