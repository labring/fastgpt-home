# 仓内拣货复核打包的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

在仓内拣货复核打包的经营报表与异常复盘中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

仓内复盘可先核波次拣货、复核记录、面单及称重资料各自覆盖的对象，不从一项记录推断全部打包过程。自拟输入只给拣货和面单说明，未提供本包裹称重数据或完整复核依据。拟通过HTTP读取WMS或设备资料，需要实际契约说明查询对象、方法和范围，不预设称重设备已经与订单系统联通，更不能把面单已生成当成包裹已核重。

## 配置怎么定

| 复盘核对 | 本题拟议资料 | 实际验收线索 |
| --- | --- | --- |
| 对象层级 | 波次与单包裹分别给出 | 汇总未判单包异常 |
| 设备连接 | 称重来源尚未接入 | 未预设订单设备已联通 |
| 空测量 | 本包裹数据没有返回 | 未写成重量异常 |
| 复核批次 | 其他批次检查混入 | 核来源后移出 |
| 仓内执行 | 异常登记或调整另核结果 | 响应未代替打包完成 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

若请求把波次身份当作单包裹标识，返回汇总就无法支持本包裹异常判断，应排查对象对应与实际发送值。若缺测量返回被写成重量异常，需要核服务对空值的说明、设备记录及来源，保留未取得测量的事实。另看复核资料是否属于同一波次。复核文字可能只说明已核拣货清单，没有记录称重，应分别回查检查对象与设备依据，不能把复核完成直接解释成包裹已核重。 可再编“清单复核完成、称重记录未给、面单已创建”的三句材料，检查是否被合并成打包合格。清单核对、测量和面单各自证明不同事项，需按本包裹对象取得对应依据。若复核记录后来补录，应核它描述的实际操作，不把补录时间直接当异常发生时间。资料缺失时报告应列具体缺项和提供方，不能为了填满流程而将其他波次的记录接入。

## 怎么确认配好了

验收并列保存波次、包裹、真实请求与返回覆盖，补对应称重和复核原文后复问，看结论是否只针对有依据的范围。请求头、参数和适用Body按外部契约配置，不公开凭证。仓库调整、异常登记或耗材采购另验权限及真实操作结果；HTTP读取有响应不证明打包已完成，也不从缺记录断言仓库没有进行复核。
