# 仓内拣货复核打包的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样
仓内拣货复核打包处理订单出库，不处理供应商到货。主要数据来自WMS、订单系统、电子面单平台与称重设备，日常文档包括波次拣货单、复核记录、面单与包装耗材单。数据更新频率为每单、小时。经营报表与异常复盘需要把某一张波次拣货单对应的扫描复核动作、面单生成记录与包装耗材领用记录串成一条可核对链路。对话日志与审计在这一环节的作用，是让复核员或包装主管能按chatId回看某次对话的输入、历史与运行详情，判断该次对话关联的拣货单、复核记录是否与WMS一致。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话日志的留存与查询依赖官方接口的字段，不依赖检索相似度。获取会话列表使用appId、offset、pageSize与source；source=api只返回通过API创建的会话，不会获取页面上的会话。获取对话列表使用appId、chatId、offset、pageSize与loadCustomFeedbacks。获取单个对话运行详情使用appId、chatId与dataId。需要中间值时按官方契约设置detail，并在responseData中查看模块状态与完整结果。对话接口不返回实际消耗Token值，需要时设置detail=true并手动计算responseData里的tokens值。对话接口传入的model、temperature等参数字段无效，由编排决定。检索或表单收集值不构成授权，业务对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。

假设演练样本：某仓复核员在2025年6月10日处理波次拣货单PL-0610-A，涉及订单SO-8821，商品为玻璃杯6只，复核记录RC-0610-17记载扫描完成。拟稿句为“该复核员已确认玻璃杯6只全部包装完毕，面单已打印，耗材领用无误”。原文只记载扫描完成，未记载包装完毕、面单打印或耗材领用结果。主体、对象、状态与有效范围仅覆盖扫描完成这一动作，拟稿句超出原文范围。

## 配置怎么定
表格仅列与本页文档相关的官方已说明设置或实施核对项。数值为本次假设试验起点，用于与WMS记录比较，不作为官方默认值。

| 项目 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| chatId | 取本次复核对话的chatId | 与WMS工单号对照，确认同一会话 |
| source | api | 获取会话列表时限定API来源，排除页面会话 |
| detail | true | 需要运行详情时设置，检查responseData |
| pageSize | 20 | 与offset配合分页，逐页核对记录数量 |
| loadCustomFeedbacks | true | 读取自定义反馈，核对复核员是否留痕 |
| dataId | 取本次对话的dataId | 与复核记录RC编号对照 |

## 容易做错的三处
1. 把检索相似度当成权限过滤。相似度只表示文本相关程度，不排除无关业务或未授权记录。检查输入为一次普通查询，比较返回的quoteList是否包含其他订单的拣货单，观察是否出现非目标chatId的记录。
2. 把表单提交当成业务执行。表单只收集值，不完成审批或数据库写入。检查输入为一次复核表单提交，比较WMS中该订单状态是否变化，观察是否存在提交后状态仍为未复核。
3. 把待审核当成缺少权限。待审核只表示流程未结束，不证明操作权限缺失。检查输入为一条待审核的复核请求，比较其授权记录与操作日志，观察是否出现权限拒绝的明确记录。

## 怎么确认配好了
1. 输入假设样本中的chatId与dataId，调用获取单个对话运行详情，比较返回的moduleName与runningTime是否与本次复核动作对应，观察responseData中是否出现该次对话的模块响应。
2. 输入假设样本中的拟稿句，与原文“扫描完成”逐字段比较主体、对象、状态，观察拟稿句是否超出原文范围。超出范围时记录为待核实，不判定为已完成。
3. 输入source=api与pageSize=20，调用获取会话列表，比较返回的list是否只含API来源会话，观察是否混入页面会话。若返回为空，记录为空结果，不推断为无会话。
