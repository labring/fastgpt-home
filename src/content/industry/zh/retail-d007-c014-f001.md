# 便利店鲜食订货的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

在便利店鲜食订货的经营报表与异常复盘中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。鲜食订货复盘保留订购单位、拒收行与补送申请，不能按汇总表推需求已满足。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

自拟鲜食资料包里，订货表按箱描述，验收便笺同时列接收行和拒收行，补送单只是门店申请，尚缺供方确认。报告读取应核真实服务怎样返回单位及各行状态，不把订购量和验收量相加，也不把拒收行并入已收。此例没有真实数量、换算比或品质结论，拒收原因也未给；资料复盘不据退补申请确认再次到货。

## 配置怎么定

| 鲜食订货HTTP复盘 | 自拟记录 | 核对动作 |
| --- | --- | --- |
| 订货单位 | 箱与件分开 | 不自行换算 |
| 接收行 | 与拒收分列 | 逐行核状态 |
| 拒收行 | 原因未给 | 不补质量结论 |
| 补送单 | 只有门店申请 | 不计实际到货 |
| 报告汇总 | 单位状态需可追 | 不按总行数推满足 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

- 按箱订购字段与逐件验收字段被直接合并时，对单位、包装依据与原行，不由商品同名自行换算或推需求缺口。

- 拒收行被汇总为已验收入库时，核行状态、实际收货凭据与返回范围，清单总行数不是接收数量。

- 补送申请被记作第二次实际配送时，对申请方、供方确认及本次交接，需求动作不生成履约事件。

## 怎么确认配好了

按真实接口契约核门店、订货事项与材料范围，安全注入认证并分别查参数与适用请求体。保存响应正文和报告引用，只有汇总摘要时将单位及拒收细节列待补，不猜原表。补包装说明只修计量关系，补供方回复也不补收货。正式改订、补送和库存入账需业务授权与回执，HTTP读取不作食品判断、采购决定或库存写入。
