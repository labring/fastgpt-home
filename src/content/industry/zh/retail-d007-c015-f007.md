# 信用证审单交单的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

信用证审单交单围绕单证一致展开，服务银行付款条件，与出口退税申报的税务匹配方向不同。主要数据来自开证行通知、UCP600条款、货代提单与银行交单记录，日常文档包括信用证、商业发票、提单、保险单与汇票。每单更新一次。经营报表与异常复盘需要把某次交单的对话记录与业务单据对应起来，对话日志与审计环节因此承担核对职责：确认某条日志属于哪一单、哪一次交单、哪一个入口，再判断该记录能否支撑复盘结论。日志存在不表示合规审计已完成，对账、留存与合规要求由完整业务方案另行落实。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份以 chatId 区分会话，以 dataId 区分会话下的对话。核对时须结合 chatId 与业务记录，不能把不同入口的会话混算。需要运行详情时，按官方契约在对话接口设置 detail，并检查 responseData 中的模块状态与完整结果；detail=false 时 responseData 不返回。日志与接口实际返回哪些字段就核对哪些字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，两者分别核对输入、历史与返回内容。检索或表单收集值，不构成授权、审批、数据库写入或外部同步。

假设演练样本（纸面材料，非真实记录）：某信用证项下交单材料原文为“开证行通知载明装运期至2025年3月31日；提单签发日为2025年3月28日；保险单出具日为2025年3月29日。”一条待判定拟稿句为“本单交单在信用证有效期内完成，单据一致，可确认收汇。”该句只涉及装运期与提单、保险单日期，未载明交单日、信用证到期日与银行审单结果，授权边界为单证员内部复核，不含银行付款确认。该句关于“可确认收汇”的部分未获支持，需保留证据缺口。

## 配置怎么定

下表只列与本页文档、主任务相关的官方已说明设置或实施核对项。

| 配置项 | 取值或状态 | 核对说明 |
| --- | --- | --- |
| 对话接口 detail | 假设试验起点 true | 需要 responseData 运行详情时设置；与 false 返回对比，确认中间值是否出现 |
| chatId | 每单一个非空字符串 | 与业务记录对应，长度小于250；核对不同入口会话是否被混算 |
| dataId | 会话下对话标识 | 与单条日志对应，核对反馈与运行详情能否定位到同一对话 |
| source | api | 获取会话列表时用于区分通过 API 创建的会话；核对是否取到页面会话 |
| loadCustomFeedbacks | 假设试验起点 true | 获取对话列表时读取自定义反馈；与不传对比，确认反馈字段是否返回 |
| stream 与 event | 按需选择 | stream=true 时节点状态经 event 区分；核对 flowResponses 是否含完整响应 |

## 容易做错的三处

1. 把同一 chatId 下不同入口的会话合并统计。输入为两份会话列表，一份 source=api、一份页面来源；比较 chatId 与来源字段；若把两者计入同一单的交单次数，则统计口径错误。可执行检查：分别列出 source 字段，核对目标单只取对应来源记录。
2. 以 detail=false 的返回推断运行详情已留存。输入为 detail=false 的响应；比较 responseData 是否存在；若据 choices 内容断言模块状态完整，则结论超出返回范围。可执行检查：改设 detail=true 重取同一 dataId，比较 responseData 是否出现。
3. 把检索或表单提交当作授权执行。输入为一条交互节点表单提交；比较提交值与审批状态字段；若据此认定交单已获银行认可，则混淆收集与审批。可执行检查：核对是否存在独立审批记录，缺失则记录待核实。

## 怎么确认配好了

1. 使用上述假设样本原文与拟稿句。输入为含装运期、提单日、保险单日的三句原文，以及拟稿句“可确认收汇”。比较拟稿句所述事实与原文载明字段：原文未载明交单日与到期日，也未载明银行审单结果。满足条件的现象是拟稿句中被判定为未获支持的部分被标出，已载明的日期被逐项对应，不出现“已确认收汇”的结论。
2. 使用同一假设样本的一条交接请求：“请将该单日志移交合规审计。”输入为该请求与 chatId、dataId。比较请求所述授权状态与实际审批记录。满足条件的现象是记录请求处于待审核，未出现已批准或已执行的表述。
3. 使用假设输入[]核对空结果承接。输入为空引用列表，比较下游设计是否按空结果处理。满足条件的现象是下游显示无引用内容，不产生虚构条目；不声称该输入必然返回空。

三项验证均为纸面预期，未实际执行。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，不据此推断漏召回或冗余结果。
