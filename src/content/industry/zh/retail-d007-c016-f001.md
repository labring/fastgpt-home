# 加盟商培训与开业辅导的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

开业辅导属于经营能力移交，材料围绕培训签到表、开业检查表、SOP手册和考核成绩展开，来源包括培训系统、督导APP、门店照片与总部SOP库。这一品类按每店、每月的节奏更新，出错会直接落到开业失败、顾客体验不一致和加盟投诉上。经营报表与异常复盘要处理的核心，是把这些分散材料里的动作状态、签署状态和授权状态分开记录，再通过 HTTP 模块把外部系统的返回值提取成可核对的字段。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 用于路径请求参数，Body 用于请求体，Headers 用于传递特殊信息。三种数据都可以通过 {{}} 引用变量，URL 也可以引用变量，变量来自全局变量、系统变量和前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime 和 histories，其中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于该模式的已知表现。

返回值通过 JSON path 语法提取，可以配置多个 key，输出类型选择字符串时会将对应值转成 json 字符串。这套机制只负责取数，不负责判断材料是否获批、签署是否完成或门店是否具备开业条件。检索与相似度分数不承担权限过滤职能，接口调用本身也不构成授权。

假设演练样本：某加盟项目培训部于假设日期 2025 年 6 月 10 日提交一份开业辅导异常复盘请求，材料原文为“培训签到表记录 2025 年 6 月 3 日收银与库存课程到店 6 人、签到 6 人；开业检查表记录 2025 年 6 月 5 日物料清点完成，店招安装待供应商确认；考核成绩记录 5 人通过、1 人待补考。”待判定的拟稿句为“该店已完成开业辅导全部动作，可进入开业。”此请求的授权边界为培训部内部复盘，不包含门店开业审批与合同签署。

## 配置怎么定

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址引用已提供变量 | 与外部接口文档逐字比对路径与方法，不采用记忆值 |
| Params 与 Headers | 鉴权凭证通过安全配置注入 | 核对请求头字段名与外部文档一致，凭证不写入公开样例 |
| Body | 按相应请求类型填写 JSON 结构 | 与外部接口契约逐字段比对，确认引用变量加引号规则 |
| 变量引用 | 逐项列出全局变量、系统变量与前方节点输出 | 核对实际传入值与材料字段一一对应，缺失项标注未知 |
| 返回值提取 | 按 JSON path 配置 key 与输出类型 | 用接口响应示例比对提取结果，确认字符串化符合预期 |
| 调试身份字段 | 测试模式下 chatId 与 responseChatItemId 不存在 | 记录该模式空值，不将其判定为业务故障 |

## 容易做错的三处

1. 把“物料清点完成、店招安装待供应商确认”读成开业条件全部满足。检查方式：输入上述材料原文，比较检查表中每一项的状态字段，只有全部项均为完成且无待确认项时才满足；出现待确认即记录为未完成。
2. 把“1 人待补考”当作已通过。检查方式：输入考核成绩原文，比较通过人数与应考人数，通过人数等于应考人数才满足；存在待补考人员时记录为未完成。
3. 把提交复盘请求当作已获得开业审批。检查方式：输入该请求的授权边界描述，比较其范围与开业审批权限，请求仅覆盖培训部内部复盘时不满足审批条件，记录为授权缺口。

## 怎么确认配好了

1. 输入假设样本的材料原文与拟稿句，比较拟稿句“已完成开业辅导全部动作，可进入开业”与材料中“店招安装待供应商确认”“1 人待补考”两项记录，出现任一未完成项即判定拟稿句未获支持。
2. 输入 HTTP 模块配置的返回值提取项，比较提取结果与接口响应示例中的对应字段，提取值与响应字段一致才满足；不一致时记录提取配置与实际响应的差异。
3. 输入该请求的授权边界与材料清单，比较请求范围是否覆盖开业审批与合同签署，范围不覆盖时记录为待核实授权缺口，不推断审批已通过或合同已生效。
