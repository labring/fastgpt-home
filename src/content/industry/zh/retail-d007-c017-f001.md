# 加盟费与保证金结算的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

在加盟费与保证金结算的经营报表与异常复盘中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。加盟结算复盘区分代付款主体、项目名称更正和退还收款人，查询不认可资金处置。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

本题自拟加盟资料：合同属于加盟企业，付款便笺写由门店代付，总部更正函只调整费用项目名称，退还申请指定另一收款主体但未附授权。经营复盘应按真实HTTP契约核合同、代付关系和更正所指原文，不凭同一品牌合并主体。改费用名称不表示退费或资金已动，申请指定收款人不等批准。无真实金额、付款账户或可退权利判断。

## 配置怎么定

| 加盟结算主体HTTP | 自拟资料 | 独立核法 |
| --- | --- | --- |
| 合同主体 | 加盟企业 | 不以代付换身份 |
| 付款便笺 | 门店代付 | 另核关系 |
| 更正函 | 只改项目名称 | 不当减免退款 |
| 退还申请 | 另收款方无授权 | 不推已批准 |
| 实际账务 | 无资金凭据 | 业务流程另核 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |

| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

- 门店代付被答成门店就是合同相对方时，对合同签约主体、代付便笺与关系依据，付款动作不自动改变合同身份。

- 更正费用名称被报告写成费用已减免或返还时，核更正函范围及实际账务凭据，文字分类变化不能补资金结果。

- 申请中的另一收款主体被列为已获准退款对象时，核授权材料、批准与实际执行，收款意向不能代处置权限。

## 怎么确认配好了

保存脱敏请求及原始正文，把合同主体、付款方和拟收款方分别定位，按实际接口检查返回覆盖，不发明财务字段。补代付对应仅解释关系，更正函补齐也只改其覆盖名称，资金状态仍缺证。访问认证和款项权限另核。真实退款、项目调整与账务写回需授权流程及回执，HTTP只读现有材料，不决定合同效力、权利或债务。
