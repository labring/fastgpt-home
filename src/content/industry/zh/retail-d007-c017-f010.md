# 加盟费与保证金结算的经营报表与异常复盘：引用来源与溯源

## 这个品类的数据长什么样

加盟费与保证金结算围绕资金与违约扣款展开，与特许加盟备案管理分属不同事项。主要数据来自财务系统、加盟合同、银行流水与门店违规记录，日常文档包括加盟费发票、保证金台账、扣款通知与合同付款计划。引用来源与溯源在此处的作用，是让经营报表与异常复盘中的每条结论都能回到具体材料与版本。资料更新频率为月与每次扣款，本页不据此推出批量同步或实时触发机制。核对合同账期、确认扣款事由、开具发票是最耗时的三个环节，溯源需求也集中在这三处。

## 这些特征在「引用来源与溯源」这一环带来什么约束

知识库搜索节点选择一个或多个相同向量模型的知识库，输出引用数组，长度可以为 0；没有搜索到内容时输出链路仍走通。引用上限按 tokens 计，最低相关度是过滤阈值，仅在语义检索或结果重排时生效。混合检索通过 RRF 融合多路结果，重排须具备模型并按设置启用，图片检索须有相应图像输入及模型能力。检索与相似度不承担权限或实体隔离，也不构成授权。跨不同向量模型的库不可共同关联，只能核对标识并排除不符合者。

假设演练样本：材料原文为“甲方应于每月十日前支付当月加盟费，逾期按日计收违约金”“保证金台账截至六月三十日余额为人民币五万元”“六月扣款通知载明事由为门店违规记录第 2024-06-011 号”。待判定拟稿句为“该加盟商六月加盟费已结清，保证金余额五万元”。原文只支持台账余额与扣款事由，未载明六月加盟费支付状态，拟稿句前半句未获支持；后半句与台账同主体、同期间、同字段一致，可标注来源为保证金台账六月三十日余额。

## 配置怎么定

| 配置项 | 本页相关设置或核对项 | 与样本的关系 |
| --- | --- | --- |
| 关联的知识库 | 选择一个或多个相同向量模型的知识库 | 先核对合同、台账、扣款通知所在库的向量模型标识 |
| 引用上限 | 按 tokens 控制每次搜索引用内容量 | 本次假设试验起点设为 4000 tokens，理由为单份台账加扣款通知的原文长度，与 2000 tokens 比较观察是否截断 |
| 最低相关度 | 0-1 数值，仅语义检索或结果重排时生效 | 本次假设试验起点设为 0.3，与 0.5 比较观察台账条目是否仍被召回 |
| 搜索模式 | 语义检索、全文检索或混合检索 | 编号类扣款事由适合全文检索或混合检索 |
| 结果重排 | 具备重排模型并按设置启用 | 未配置重排模型时该项不生效，不得假定已启用 |
| 引用内容输出 | 数组格式，长度可以为 0 | 用纸面输入 [] 核对下游承接设计，不声称虚构规则检索必返回 [] |

## 容易做错的三处

1. 把检索命中当作授权。样本中扣款通知只载明事由，检索到该通知不表示扣款已获批准或已执行，需另接系统实现或人工审批记录。
2. 把待审核当作缺少权限。拟稿句处于待审核状态时，不能据此判定缺少操作权限，也不能判定已获批准。
3. 把报价有效期当作供货期限。合同付款计划中的日期字段与供货期限属不同事实，同字段明确互斥取值才构成矛盾。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较拟稿句“六月加盟费已结清”与原文是否同主体、同期间、同字段。原文未载明支付状态，结果应为未获支持，不得标为已结清。
2. 输入样本台账原文，比较“保证金余额五万元”与台账六月三十日余额字段。同主体、同期间、同字段一致，结果可标注来源为台账，并保留日期范围。
3. 输入纸面空数组 []，比较下游节点是否仍继续执行。引用输出长度允许为 0，结果应为链路走通，不得断言检索一定返回空或一定报错。
