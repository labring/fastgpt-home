# 品牌会员私域运营的经营报表与异常复盘：工具调用与插件

## 这个品类的数据长什么样

在品牌会员私域运营的经营报表与异常复盘中，本页说明FastGPT的工具调用与插件如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「工具调用与插件」这一环带来什么约束

会员运营复盘可先核标签说明、触达计划、券规则与授权记录分别覆盖什么。自拟材料只有活动安排和规则原句，没有实际触达或使用结果，不从计划存在推出会员已收到信息。拟议读取工具介绍应限定读取通用说明，不发送真实会员数据；参数保留活动和资料范围，授权资料尚缺时不能由某个标签名称推定可以外发，也不从券已配置推定已核销。

## 配置怎么定

| 复盘步骤 | 本题自拟材料 | 核对证据 |
| --- | --- | --- |
| 计划边界 | 活动安排与实际触达分开 | 未由计划推出已发送 |
| 无据授权 | 参数称已授权但无来源 | 核真实请求并登记缺证 |
| 活动身份 | 其他活动使用资料混入 | 未填本活动结果缺口 |
| 公开范围 | 仅通用规则与自拟文字 | 不使用真实会员资料 |
| 业务执行 | 发送标签或优惠操作 | 另验权限与真实回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `工具介绍` | 介绍用途、输入和不适用情形。 |
| `工具参数` | 模块及插件参数分别核对。 |
| `必须参数` | 缺合适必参时模型可能不调用。 |
| `工具连接` | 可用工具须连接到调用模块。 |
| `工具调用终止` | 结束调用，不再进行后续AI总结。 |

## 容易做错的三处

若请求把计划对象当成实际触达对象，返回文字无法支持执行结论，应排查原文性质及引用。若必须的授权依据只填“已授权”而没有材料来源，需看真实请求和给定记录，登记缺证，不把参数值当授权。另一活动的使用说明也不能补本活动结果，需核活动身份后再解释差异。

## 怎么确认配好了

验收分开保留安排、规则、授权缺口与实际结果，检查工具是否调用、输入范围和返回出处，补通用合规材料后复问，不以真实个人记录作公开样例。先接少量所需工具；终止节点结束当前调用且无后续AI总结。触达发送、标签写入或优惠处理若需执行，另核业务授权与回执，文本复盘不证明活动已发送、效果已产生或个人权限已核完。
