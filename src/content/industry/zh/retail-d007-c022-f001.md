# 品牌全渠道库存调拨的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
全渠道调拨让货品在门店与仓之间流动，ERP 库存、门店 POS、电商订单、WMS 构成主要数据来源。经营报表与异常复盘要围绕调拨申请、库存快照、门店缺货清单、调拨物流单展开，日更或周更的节奏意味着报表口径必须与单据状态对齐。查找可调库存、审批调拨路径、更新到货入库三个环节耗时最多，接口对接时任何字段错位都会放大为超卖、断货或账实不符。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向目标地址发送请求，Params、Headers、Body 三处均可用 `{{}}` 引用全局变量、系统变量或前方节点输出，URL 同样支持变量引用。请求体仅在相应请求类型下生效，引用字符串需加引号，数值与布尔值不加引号。返回值通过 JSON path 或 JS 对象取值规则提取，输出类型选字符串时会将对应值转为 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试空值不构成业务故障。对话接口以 APIKey 鉴权，推荐在请求体传入 body.appId，appId 优先级为 body.appId、`<apiKey>-<appId>`、apikey 关联的 appId。传入的 model、temperature 等字段无效，由编排决定。detail=true 可返回中间值，非 stream 模式结果保存在 responseData。authProxy 代理团队成员身份需团队所有者开启，代理身份仍需具备目标应用和会话权限。交互节点返回的 interactive 只含 type 与 params，entryNodeIds、memoryEdges、nodeOutputs、nodeResponseId 等内部运行态字段不会返回。

假设演练样本：某品牌供应链专员收到一份调拨申请，材料原文为「申请单 T-2024-0312，申请方为华东仓，接收方为南京新街口店，商品为春季针织衫 M 码，申请数量 120 件，申请日期 2024 年 3 月 12 日，状态为待审核」。另有一条待判定的拟稿句：「该调拨申请已审批通过，库存已从华东仓扣减并同步至南京新街口店。」核对时需注意，原文状态为待审核，拟稿句所述审批通过、库存扣减与同步均未在材料中体现，属于未获支持。

## 配置怎么定
下表围绕本样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 核对说明 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选择，地址可引用变量 | 核对地址是否与调拨单据服务契约一致 |
| Headers 鉴权 | Authorization 使用 Bearer 加凭证，凭证经安全配置注入 | 不将凭证写入公开样例 |
| Body 结构 | 引用申请单号、商品、数量等字段 | 核对 JSON 结构与外部接口契约 |
| 变量引用 | 引用全局变量或前方节点输出 | 逐项核对实际传入值 |
| 返回值提取 | 按 JSON path 提取状态字段 | 输出类型选字符串时转为 json 字符串 |
| 调试身份字段 | 测试模式下 chatId 与 responseChatItemId 不存在 | 不把调试空值当成业务故障 |

本次假设试验起点选待审核状态，理由是该状态在材料原文中明确出现，便于与拟稿句逐字比较。

## 容易做错的三处
1. 将待审核状态当作审批通过。输入材料原文「状态为待审核」，拟稿句写「已审批通过」。比较两者状态字段，待审核与审批通过为同字段互斥取值，拟稿句与原文矛盾。
2. 将申请数量当作已扣减数量。输入原文「申请数量 120 件」，拟稿句写「库存已从华东仓扣减」。比较数量字段与动作描述，原文未载明扣减动作，拟稿句未获支持。
3. 将表单收集当作授权执行。输入拟稿句「库存已同步至南京新街口店」，原文无同步记录。比较主体、对象与动作，同步属需另接系统实现的业务动作，原文未载明，属证据缺口。

## 怎么确认配好了
1. 输入假设样本原文与拟稿句，比较状态字段：原文为待审核，拟稿句为已审批通过，两者互斥，判定拟稿句与原文矛盾。预期现象为识别出状态字段冲突。
2. 输入原文「申请数量 120 件」与拟稿句「库存已扣减」，比较数量与动作：原文仅有申请数量，无扣减记录，判定拟稿句未获支持。预期现象为标记证据缺口。
3. 输入原文与拟稿句「库存已同步至南京新街口店」，比较主体、对象与动作：原文无同步记录，同步需下游系统实现，判定证据缺口。预期现象为记录待核实，不声称已执行。

三项验证均以假设样本为输入，比较对象为同主体、同期间、同一字段，未获支持即保留缺口，不补造授权或生效条款。
