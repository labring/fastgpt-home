# 品牌售后维修服务的经营报表与异常复盘：工作流编排

## 这个品类的数据长什么样

在品牌售后维修服务的经营报表与异常复盘中，本页说明FastGPT的工作流编排如何衔接资料。维修复盘分别传递未复现、领件待装与局部复测，不能合并为整机修复。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟维修资料中，检测便笺说本次暂未复现异响，备件领用单注明待安装，复测清单只列按键项目而未覆盖异响。报告流程收工单、被检现象和每份资料的动作，再选择补安装记录或核复测覆盖。未复现是本次检查所见，不证明客户从未遇到故障；领件不是装件，按键检查也不证明异响已解决。无真实设备参数、故障判定或修复效果。

## 配置怎么定

| 维修复盘证据编排 | 自拟动作 | 核验范围 |
| --- | --- | --- |
| 未复现便笺 | 本次未见异响 | 不推无故障 |
| 备件领用 | 待安装 | 不当已更换 |
| 复测清单 | 只列按键 | 不扩异响整机 |
| 补证路径 | 工序或复测 | 逐项核实际承接 |
| 正式维修 | 技师业务另办 | 执行回执另取 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

- 暂未复现被写成整机无故障时，对本次检查范围、客户报修现象和实际检测原句，不从一次未观察到推永久不存在。

- 备件领用被报告列为已更换时，对领用用途、安装记录及本设备对应，物料出库不等于维修工序完成。

- 按键复测通过被扩成异响及整机全部通过时，对复测项目和未覆盖现象，保留局部检查的范围。

## 怎么确认配好了

两条路径分别保留物料工序与复测项目，比较提交原文、下游收到的状态和报告采用句。补安装只能更新安装，异响仍需相应复测；补客户说明也不能补技术结论。资料不足时逐项列缺，不用整齐表格抹平不同阶段。真实维修、零件核销、工单关闭和客户回复需授权业务及回执，编排只组织复盘材料，不修设备或替技术人员认定。
