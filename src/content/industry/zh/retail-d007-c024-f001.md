# 品牌商场专柜运营的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

品牌商场专柜的销售由商场统一收银，品牌方按联营扣点合同与月结对账单核对销售额与扣点费用。日常材料包括联营扣点合同、商场活动函、销售小票和月结对账单，数据来源涉及商场POS、品牌ERP、商场会员活动与财务系统。这些材料在经营报表与异常复盘中进入 HTTP 接口与外部系统环节时，需要逐项确认主体、对象、期间与授权状态。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params、Headers、Body 三类数据均可通过 `{{}}` 引用变量，变量来自全局变量、系统变量和前方节点输出。`chatId` 与 `responseChatItemId` 在测试模式下不存在，测试环境取到空值属于调试条件，不构成业务故障。对话接口以 APIKey 鉴权，appId 优先级为 `body.appId`、`<apiKey>-<appId>`、apikey 关联的 appId。传入的 `model`、`temperature` 等字段无效，由编排决定。`detail=true` 时返回中间值，`usage` 中的 tokens 需手动计算。检索结果中的 `similarity` 是相关度，不承担权限或实体隔离。表单收集值，业务核验、审批与外部同步需另有下游实现。

假设演练样本（纸面，未执行）：材料原文——“联营扣点合同 HT-2024-031 约定，专柜 A 在 2024 年 7 月的扣点比例为 18%，月结对账单以商场 POS 汇总销售额为结算基数。商场活动函 HD-2024-017 载明 7 月 12 日至 7 月 14 日专柜 A 参加满减活动，活动期间销售额不参与扣点。”拟判定句：“专柜 A 2024 年 7 月全月销售额均按 18% 计提扣点。”该句与活动函载明的时段范围不一致，判定为不获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址引用已提供变量 | 比对文档中的地址与方法是否一致 |
| Params 与 Headers | 鉴权凭证通过安全配置注入 | 检查凭证未写入公开样例 |
| Body | 仅在相应请求类型下填写 | 比对 JSON 结构与外部接口契约 |
| 变量引用 | 引用全局变量、系统变量或前方节点输出 | 逐项核对实际传入值 |
| 返回值提取 | 按 JSON path 配置 key | 比对提取结果与响应原文 |
| 调试身份字段 | `chatId`、`responseChatItemId` 在测试模式下不存在 | 区分调试空值与业务故障 |

## 容易做错的三处

1. 把活动函载明的时段范围当作全月适用，导致扣点计提范围与合同、活动函不一致。
2. 把 `similarity` 相关度当作权限或实体过滤条件，误认为低分记录已被排除。
3. 把表单收集到的值当作已完成业务核验或审批，未确认下游实现即视为可执行。

## 怎么确认配好了

1. 输入假设样本中的合同 HT-2024-031、活动函 HD-2024-017 与拟判定句；比较拟判定句与活动函载明的时段范围；当两者对扣点适用期间的表述不一致时，判定该句不获支持。
2. 输入一条含 `similarity` 字段的检索响应；比较该字段与权限或实体标识；当响应中无权限字段时，记录权限状态为未获支持，不将相关度作为过滤依据。
3. 输入一份表单收集结果；比较该结果与业务核验、审批记录；当仅有表单值而无核验或审批记录时，记录该请求处于待核实状态，不视为已获授权执行。
