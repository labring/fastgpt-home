# 品牌直营门店运营的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

品牌直营门店由品牌直接雇佣和核算，不通过加盟合同管理。日销售报表、排班表、陈列照片、库存调拨单构成经营复盘的主要材料，更新频率为日或周。经营报表与异常复盘需要把这些材料与外部系统对接：POS 销售数据、会员 CRM、ERP 库存、门店巡检记录。HTTP 接口承担向这些外部系统发送请求或拉取数据的职责，接口配置的正确性直接决定复盘所依据的数据是否与门店实际状态一致。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径请求参数，Body 用于请求体，Headers 用于请求头，三者均可通过 {{}} 引用变量。变量来源为全局变量、系统变量和前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories。chatId 与 responseChatItemId 在测试模式下不存在，调试时读到空值属于预期现象，不能当作业务故障处理。返回值配置的是解析规则，通过 JSON path 从响应中提取所需字段，输出类型选择字符串时会把对应值转为 json 字符串。接口调用本身不构成授权，也不完成业务审批或数据库写入。

假设演练样本：某品牌直营门店区域经理收到一份日销售报表，材料原文为「门店编号 A-017，报表日期 2026 年 3 月 10 日，当日销售额 48,200 元，客流量 312 人次，调拨单号 DB-20260310-04，调拨状态：待区域审批」。待判定拟稿句为「A-017 门店 3 月 10 日销售异常已确认，调拨单已批准执行」。核对要点：拟稿句中的「已确认」与材料未载明的确认结论不一致，「已批准执行」与材料所载「待区域审批」状态不一致。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址 | 外部系统文档给出的地址，可含 {{}} 变量 | 与外部接口文档逐字符比对 |
| 请求方法 | 按外部接口文档选择 | 确认方法与文档一致 |
| Headers 鉴权 | Authorization 通过安全配置注入 | 检查凭证未出现在公开样例 |
| Body 结构 | 按外部接口契约构造 JSON | 核对字段名与类型 |
| 变量引用 | 引用全局变量或前方节点输出 | 逐项核对实际传入值 |
| 返回值解析 | 按 JSON path 提取字段 | 核对 key 与响应结构对应 |

起点选择理由：以上各项以外部接口文档为唯一依据，不以任何默认值为准。与什么值比较：与外部接口文档载明的地址、方法、字段名、响应结构比较。

## 容易做错的三处

1. 把测试模式下 chatId 与 responseChatItemId 不存在当作业务故障。输入：测试模式发起的 HTTP 请求。比较：系统变量在该模式下的可用状态与正式模式的区别。可观察结果：测试模式下这两个变量为空，属于文档载明的预期现象。
2. 把接口调用成功当作业务审批完成。输入：样本中调拨单状态为「待区域审批」。比较：拟稿句「已批准执行」与材料所载状态。可观察结果：两者不一致，待审批不等于已批准。
3. 把返回值解析配置当作接口本身返回值。输入：配置的 key 与 JSON path。比较：响应实际结构与配置的提取路径。可观察结果：key 与响应结构不对应时提取不到值，需逐项核对。

## 怎么确认配好了

1. 输入：假设样本材料原文与拟稿句。比较：拟稿句「已确认」「已批准执行」与材料所载「待区域审批」。可观察结果：拟稿句与材料状态不一致，应判定为未获支持，保留证据缺口。
2. 输入：测试模式下发起的 HTTP 请求。比较：chatId 与 responseChatItemId 的可用状态。可观察结果：两者为空，符合文档载明的测试模式行为，不作为故障。
3. 输入：配置的返回值 key 与 JSON path。比较：实际响应结构与配置路径。可观察结果：路径与响应结构对应时提取到值，不对应时提取为空，需核对后修正。
