# 品牌直营门店运营的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

品牌直营门店由品牌直接雇佣和核算，不通过加盟合同管理。日销售报表、排班表、陈列照片、库存调拨单构成主要核对材料，数据来源为POS系统、会员CRM、ERP库存与门店巡检，更新频率为日、周。区域经理与店长在异常复盘时，需要把某笔销售或调拨的对话记录与上述纸质或系统材料对应起来。直营模式下没有加盟合同作为授权凭证，任何调拨或折扣执行都必须回到品牌内部的审批边界。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话接口以appId与chatId定位会话，dataId定位某一条对话。传入chatId时，FastGPT从数据库取会话，并以messages数组最后一条作为用户问题，其余message被忽略；不传chatId则完全由messages构建上下文。运行详情需要设置detail=true，中间值保存在responseData中。日志留存不等于合规审计完成，对账、留存与合规要求由完整业务方案另行落实。检索相似度分数只反映文本匹配，不承担权限或实体隔离，不能把score当作门店归属或授权过滤。

假设演练样本：材料原文为“2025年3月12日，A直营门店日销售报表记录调拨出库3件，调拨单号DB-0312-07，审批状态为待区域经理审核；同日排班表显示该店当班店长李某。”拟稿句为“该调拨已获批准并完成出库。”另一条交接请求为“请根据chatId=storeA-0312的对话记录，确认该调拨是否已执行。”待判定点在于：材料只显示待审核，未显示批准签署，也未显示ERP出库完成回执。

## 配置怎么定

下表只列与本页主任务相关的官方已说明设置或实施核对项。数值仅为本次假设试验起点，用于与材料实际值比较，不表示官方默认。

| 配置或核对项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| body.appId | store-report-app | 与材料所属应用标识逐字比较，不一致则记录为待核实 |
| chatId | storeA-0312 | 与交接请求所给会话标识比较，确认指向同一会话 |
| detail | true | 需要responseData中的节点运行详情时设置，检查返回是否含该字段 |
| loadCustomFeedbacks | true | 读取对话列表时按需开启，核对返回customFeedbacks是否为空数组 |
| pageSize | 10 | 假设试验起点，用于分页取记录，与返回list长度比较 |
| source | api | 获取API创建的会话，核对返回list是否含页面来源会话 |

## 容易做错的三处

1. 把待审核当作已批准。材料写“审批状态为待区域经理审核”，拟稿句写“已获批准并完成出库”。输入是同一调拨单号DB-0312-07，比较审批字段取值，待审核与已批准为互斥取值，出现前者即判定拟稿句未获支持。
2. 把检索分数当作权限过滤。输入为quoteList中score=0.89的条目，若据此认定该记录属于A门店，比较对象是门店归属字段，而score不承载该字段，判定为越权推断。
3. 把日志存在当作合规审计完成。输入为getPaginationRecords返回的list，若据此声称对账已完成，比较对象是业务方案中的对账记录，日志条目与对账结论为不同事实，判定为未获支持。

## 怎么确认配好了

1. 输入假设样本材料原文与拟稿句，比较审批状态字段取值，若字段为“待区域经理审核”，则拟稿句“已获批准并完成出库”判定为待核实，不满足条件。
2. 输入交接请求与chatId=storeA-0312，比较返回会话的appId与材料所属应用标识，若两者一致且detail=true返回含responseData，则确认定位正确；若不一致或responseData缺失，记录为缺口。
3. 输入空引用列表[]，比较下游节点对[]的处理设计，若设计未定义空结果分支，则记录为待补充；不声称虚构规则检索一定返回[]。
