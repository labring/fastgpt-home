# 品牌经销商订货会的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
订货会数据以季、年为周期更新，来源包括订货会系统、历史销售、经销商库存与财务授信。经营报表与异常复盘需要把订货手册、订货合同、样品清单、授信审批这几类文档中的字段与外部系统返回值对齐。订货不足、压货纠纷、回款风险这三类后果，决定了核对重点在数量、金额、状态与授权边界，而不在店铺运营指标。文档更新频率低，接口返回的字段一旦与手册或合同口径不一致，复盘就要先定位差异来源。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向指定地址发送请求，Params 用于路径参数，Body 用于 POST/PUT 请求体，Headers 传递鉴权等信息。URL、Params、Body、Headers 均可用 `{{}}` 引用全局变量、系统变量或前方节点输出。返回值通过 JSON path 提取，输出类型选字符串时会把对应 key 的值转成 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于环境差异，不能当作业务故障。对话接口的 model、temperature 等字段由编排决定，API 传入无效；Token 消耗需设 detail=true 后自行计算 responseData 里的 tokens。authProxy 代理团队成员身份需团队所有者开启，且代理身份仍需具备目标应用和会话权限。检索相似度是排序依据，不承担权限或实体隔离。

假设演练样本：某品牌渠道部在 2026 年春季订货会复盘时，供核对的《订货手册》原文含三句：“本次订货范围为 2026 春夏系列。经销商须在 3 月 20 日前提交订货量。授信额度以财务审批结果为准。”《授信审批》记录状态为“待审核”。拟交接请求句为：“将待审核授信额度写入订货合同并同步至外部财务系统。”

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档给定的地址，方法取文档标注值 | 地址可引用变量，比较实际请求行与文档是否一致 |
| Headers 鉴权 | Authorization 通过安全配置注入，样例不写入凭证 | 比较请求头键名与外部文档要求，缺失即记录 |
| Body 结构 | 按外部接口契约列出 JSON 键 | 比较键名、类型与契约，逐项核对实际传入值 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 比较 `{{}}` 内名称与可用变量清单 |
| 返回值提取 | 按 JSON path 语法配置 key | 比较提取结果与接口响应中的实际字段 |
| 调试身份字段 | chatId、responseChatItemId 在测试模式下不存在 | 比较测试模式与正式模式取值，空值不判为故障 |

## 容易做错的三处
1. 把“待审核”授信审批当成已生效额度写入订货合同。输入是《授信审批》状态“待审核”与拟交接请求句；比较状态字段与“以财务审批结果为准”的手册原文；可观察结果是请求句把未生效状态当作已生效事实。
2. 把检索相似度分数当作权限或实体过滤条件。输入是返回结果中的 score 字段；比较该字段与权限字段是否存在；可观察结果是相似度高低被用来判断某经销商是否有权查看。
3. 在测试模式下取 chatId 为空，判定接口或业务记录异常。输入是测试模式请求；比较系统变量文档中“测试模式下不存在”的说明；可观察结果是空值被写成业务故障结论。

## 怎么确认配好了
1. 输入假设样本中《订货手册》三句原文与《授信审批》“待审核”记录；比较拟交接请求句是否把待审核写成已生效；满足条件为请求句明确标注待审核、不触发写入与同步动作。
2. 输入一条返回含 score 的接口响应；比较 score 与权限、实体标识字段；满足条件为结论只说明排序，不据此排除任何经销商或记录。
3. 输入测试模式下 chatId、responseChatItemId 为空的请求；比较系统变量文档说明；满足条件为记录为环境差异，不写成业务故障，且不据此断言接口失败。
授权状态、审批结果与外部系统写入均需下游实现，本页只核对输入、比较与可观察结果。
