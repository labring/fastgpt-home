# 品牌经销商订货会的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

订货会按季或按年开展，日常材料包括订货手册、订货合同、样品清单与授信审批。经营报表与异常复盘要对照这些材料，核对经销商在特定订货周期内的预订量、合同状态与授信状态。对话日志与审计环节需要结合 chatId 核对目标对话与业务记录，避免把不同入口的会话混算。

## 这些特征在「对话日志与审计」这一环带来什么约束

订货会材料按季更新，对话日志按次产生。核对时需要区分节点已有行为、实际可配置字段、人工核对动作，以及需另接系统实现的业务动作。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。检索或表单收集的值不构成授权执行。

假设演练样本：材料原文为“华东区域订货会 2025 年春季场，经销商 A 提交订货意向书，样品清单包含品类 X 三款，授信审批状态为已提交待审核”。待判定拟稿句为“经销商 A 的授信额度已批准，可执行本次订货”。原文只显示授信审批状态为已提交待审核，未载明批准结果。该拟稿句把待审核写成已批准，属于未获支持的判定。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 说明与比较方法 |
| --- | --- | --- |
| chatId 核对 | 假设样本使用 chatId 为 spring2025-east | 与业务记录中的订货会场次标识比较，确认对话归属 |
| detail 设置 | 假设试验起点设为 true | 需要运行详情时按官方契约设置，检查 responseData 是否包含所需字段 |
| 数据来源筛选 | 假设试验起点 source 设为 api | 获取 API 创建的会话，与页面会话区分比较 |
| 反馈字段核对 | 假设样本检查 userGoodFeedback 与 userBadFeedback | 与对话记录中的反馈字段比较，确认是否留存 |
| 运行详情字段 | 假设试验起点检查 moduleType 与 runningTime | 与 responseData 实际返回字段比较，未返回字段记录为未知 |
| 会话标题核对 | 假设样本检查 customTitle 与 title | 与业务材料中的场次名称比较，确认对应关系 |

## 容易做错的三处

1. 把待审核状态写成已批准。假设样本中授信审批状态为已提交待审核，若拟稿句写“已批准”，输入为授信审批状态字段，比较对象为原文“已提交待审核”，可观察结果为拟稿句与原文不一致。
2. 把检索或表单收集的值当作授权执行。假设样本中表单收集了经销商 A 的订货意向，若据此认定授信已批准，输入为表单值，比较对象为授信审批状态字段，可观察结果为表单值不包含批准结论。
3. 把不同 chatId 的会话混算。假设样本中春季场与秋季场使用不同 chatId，若把两场对话合并统计，输入为 chatId 列表，比较对象为业务记录中的场次标识，可观察结果为 chatId 与场次标识不匹配。

## 怎么确认配好了

1. 输入假设样本材料原文与拟稿句，比较拟稿句中的授信状态与原文“已提交待审核”，若拟稿句写“已批准”则判定为未获支持，若写“待审核”则与原文一致。
2. 输入假设样本的表单收集值与授信审批状态字段，比较两者是否包含批准结论，若表单值不包含批准结论则判定为不能据此执行。
3. 输入假设样本的 chatId 列表与业务记录中的场次标识，比较两者是否一一对应，若存在不匹配则判定为会话归属需重新核对。
