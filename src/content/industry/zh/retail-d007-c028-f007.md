# 品牌自播直播间运营的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

品牌自播由品牌自己承担话术、库存和售后，达人佣金不构成主要结算方式。每场直播的对话记录同时承担两项用途：复盘讲解节奏与流量转化，核对客服口径是否与商品讲解卡一致。数据来源包括抖店罗盘、巨量千川、直播间评论和成交明细，更新频率为每场或每小时。日志审计的对象是逐场累积的会话，按场次归集，不做一次性汇总。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份以 chatId 为线索，一个 chatId 对应一个应用下的某一段会话，dataId 指向该会话下某一条对话。核对时把同一 chatId 的会话与同一场次的业务记录对应，不同入口创建的会话分别统计。运行详情按官方契约设置 detail 参数，非流式结果保存在 responseData，流式结果通过 event 区分；未设置 detail 时只取得最终回答，中间节点信息不在返回内。接口实际返回哪些字段，日志就留存哪些字段，未返回的业务数据不能推定已完整留存。测试模式与正式调用的身份字段可能不同，输入、历史与返回内容分别核对。对账、留存与合规要求由完整业务方案另行落实，日志存在本身不表示合规审计已经完成。

假设演练样本：某品牌自播团队留存一份直播复盘草稿，其中一段记录写为「本场 20:00 至 22:00，主播在讲解商品 A 时回复观众『这款支持七天无理由』，该段对话的 chatId 为 demo-chat-0715，dataId 为 demo-data-0715-03，状态为待场控确认」。另一份材料为排班表草稿，写明该时段主播为甲。待判定拟稿句为「该场商品 A 的售后口径已通过场控审批并同步至客服系统」。此句涉及的主体是场控，对象是商品 A 的售后口径，状态是审批与同步，均未在材料中出现。

## 配置怎么定

| 核对项 | 官方已说明的设置或动作 | 与样本的对应 |
| --- | --- | --- |
| 会话身份 | chatId 由调用方自行保证唯一，长度小于 250 | 核对 demo-chat-0715 是否唯一且未与其他场次混用 |
| 对话身份 | dataId 指向会话下某一条对话 | 核对 demo-data-0715-03 是否落在该 chatId 内 |
| 运行详情 | 需要中间值时设置 detail=true，非流式结果在 responseData | 若需核对节点耗时与引用列表，确认该次请求是否设置 detail |
| 会话来源 | source=api 只取通过 API 创建的会话 | 该场会话若来自页面，改用对应来源核对 |
| 反馈字段 | loadCustomFeedbacks 控制是否读取自定义反馈 | 复盘涉及观众反馈时确认该参数取值 |
| 变量替换 | variables 为对象，替换输入框中的 [key] | 讲解卡使用变量时，核对传入值与脚本一致 |

本次假设试验起点：把 detail 设为 true 后核对 responseData 是否包含 chatNode 的 runningTime 与 quoteList，选择该起点的原因是样本需要节点级信息；比较对象为同一 chatId 下未设置 detail 的返回，确认后者不含这些字段。

## 容易做错的三处

1. 把不同 chatId 的会话合并统计。输入是两个 chatId 的对话列表，比较对象是各自 chatId 与场次记录的对应关系，可观察结果是同一场次被重复计入或跨场次混算。
2. 用 detail=false 的返回推断节点行为。输入是未设置 detail 的响应，比较对象是 responseData 是否存在，可观察结果是节点耗时与引用列表缺失，此时节点是否执行无法判断。
3. 把待确认状态当作已审批。输入是样本中「状态为待场控确认」的草稿，比较对象是材料中是否出现审批完成或同步记录，可观察结果是两项均未出现，拟稿句所述事实未获支持。

## 怎么确认配好了

1. 身份核对：输入 demo-chat-0715 与 demo-data-0715-03，比较两者是否属于同一会话，可观察结果是 dataId 出现在该 chatId 的对话列表中；若不在，记录为身份不匹配，不继续推断。
2. 运行详情核对：输入设置 detail=true 的请求，比较返回中是否存在 responseData 及 chatNode 条目，可观察结果是出现 runningTime 与 quoteList；若未出现，记录为本次未取得中间值，节点是否执行保持未知。
3. 拟稿句核对：输入「该场商品 A 的售后口径已通过场控审批并同步至客服系统」，比较材料中是否出现场控审批结论与客服系统同步记录，可观察结果是两项均缺失，该句判定为未获支持，需补交审批与同步证据后再核。

空结果承接：某次请求返回空的引用列表时，可用明确的纸面输入 [] 核对下游展示设计，不据此推断检索规则必然返回空。相关度数值只反映相似程度，不承担权限或实体隔离；跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察即可。
