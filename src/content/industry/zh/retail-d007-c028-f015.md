# 品牌自播直播间运营的经营报表与异常复盘：知识库检索与召回

## 这个品类的数据长什么样

品牌自播由品牌自己承担话术、库存和售后，直播脚本、商品讲解卡、排班表、直播复盘构成日常文档主体。经营报表与异常复盘要回答某一场或某小时的转化异常出在哪，检索范围落在这些文档上。数据来源包括抖店罗盘、巨量千川、直播间评论和成交明细，更新频率为每场或小时级别，复盘材料与检索内容因此常处于同一经营周期内。出错的后果是虚假宣传投诉、库存拍超和转化下滑，检索引用内容若与脚本或讲解卡口径不一致，复盘结论会偏离实际执行。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。不同向量模型的库不能共同关联，只能核对向量模型标识并排除不符者，记录实际观察，不执行跨模型检索来比较漏召回。搜索模式分语义检索、全文检索和混合检索，按测试问题比较，不预设一种模式适合全部资料。引用上限以 token 为单位，用长短不同的实际资料测试内容是否完整。最低相关度仅在语义检索或使用结果重排时生效，先标注相关与无关样本再调阈值。问题优化用于指代消除和问题扩展，比较原问题与优化后问题，核对主体是否被改错。引用内容以数组输出，长度可以为 0，未搜索到内容时输出链路仍走通。RRF 是混合检索的融合过程，不是开关。图片检索须有图像输入及相应模型能力，重排须具备模型且按设置启用，可选路径不表示每次请求全部执行。检索不构成授权，表单收集值，业务核验、审批、数据库写入和外部同步需要各自的下游实现。

假设演练样本：材料原文为“2025年6月12日20时至21时，品牌自播间A的主播按排班表执行商品讲解卡第3版，讲解卡标注该商品库存上限为800件。同期直播复盘记录该时段成交620件，评论出现‘拍超’字样。”待判定拟稿句为“该时段库存已拍超，需追责主播。”原文只载明库存上限、成交量和评论字样，未载明实际库存扣减结果与责任归属。

## 配置怎么定

下表围绕该样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，需与另一组取值比较后调整。

| 配置项 | 本次假设试验起点及理由 | 比较方式与核对动作 |
| --- | --- | --- |
| 关联知识库 | 选择向量模型标识一致的脚本库与复盘库 | 核对各库向量模型标识，排除不一致者并记录 |
| 搜索模式 | 先分别用语义检索与全文检索跑同一问题 | 比较两路返回内容，再决定是否用混合检索 |
| 引用上限 | 起点设为能容纳一份完整讲解卡正文的 token 量 | 用长讲解卡与短复盘记录各测一次，看内容是否被截断 |
| 最低相关度 | 起点设为中间值，理由是该值仅在语义检索或重排时生效 | 先标注相关与无关样本，再上下调整并比较过滤结果 |
| 问题优化 | 对多轮追问与短问题开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型时按设置启用 | 比较重排前后候选顺序，用重排得分观察过滤效果 |

## 容易做错的三处

1. 把最低相关度当成权限或实体过滤。该值是过滤阈值，不排除无关业务或未授权记录，检索不承担授权判断。检查时输入同一问题与一组无关记录，比较返回内容是否仍包含它们，若包含则说明该值未起到隔离作用。
2. 把不同向量模型的库共同关联。文档要求关联相同向量模型的知识库。检查时逐一核对库的向量模型标识，排除不一致者后记录实际观察，不推断共同关联后的运行结果。
3. 把待判定拟稿句直接写成结论。样本中原文只载明库存上限、成交量和评论字样，未载明库存扣减结果与责任归属。检查时逐字段比对原文与拟稿句，缺少的字段记为未获支持。

## 怎么确认配好了

1. 针对样本拟稿句“该时段库存已拍超，需追责主播”，输入原文两句与拟稿句，比较成交620件与库存上限800件、评论字样与库存扣减结果、执行排班与责任归属三组字段。只有原文载明同主体、同时段、同字段的互斥取值时，才判为矛盾；未载明或只有相关阶段证据，判为未获支持或待核实。
2. 针对引用上限，输入一份完整讲解卡与一份短复盘记录，比较返回内容是否被截断。预期是长文档在起点值下可能不完整，需调整后复测，不保证一次命中。
3. 针对空结果，用纸面输入的空引用数组 [] 核对下游设计是否承接长度为 0 的输出。预期是下游链路仍走通，不声称虚构规则检索一定返回 []。

待审核不证明缺少操作权限，签署、合作达成与合同生效是三个不同事实。检索或表单不构成授权执行，审批、写入与同步需各自的下游实现。
