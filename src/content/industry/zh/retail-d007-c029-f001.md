# 售后维修与补寄的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

售后维修与补寄以恢复商品使用为目标，结案方式包含维修完成与配件补寄发出。数据来源覆盖售后系统、订单系统、维修网点与配件仓WMS，日常材料为维修申请、补寄单、检测报告、配件出库单。每单与每日的更新节奏意味着报表口径需要按单号与日期双重维度对齐。

经营报表与异常复盘在本环节要处理的是：把上述单据中的字段通过 HTTP 请求送往外部的报表服务或工单系统。FastGPT 的 HTTP 模块可重复添加、手动配置、触发执行，向对应地址发送请求，Params、Body、Headers 三处均可通过 `{{}}` 引用变量，URL 同样支持变量引用。变量来自全局变量、系统变量与前方节点输出。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories。其中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于环境差异，不能直接判定为业务故障。histories 默认最多取 10 条，长度无法修改。

对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId；appId 优先级为 body.appId、`<apiKey>-<appId>`、apikey 关联的 appId。如需通过 authProxy 代理团队成员身份，需团队所有者开启该选项，代理身份仍需具备目标应用和会话权限。传入的 model、temperature 等参数无效，由编排决定。detail=true 时返回中间值，非流式结果保存在 responseData 中。

假设演练样本。供核对的材料原文：维修申请单 WX-0715-03 载明主体为某品牌售后网点，对象为订单 A 下的整机，故障描述为电源模块不启动，申请日期为 7 月 15 日，状态为待检测。配件出库单 PJ-0716-11 载明同一订单，配件为电源模块一件，出库日期为 7 月 16 日，状态为已出库。待判定的拟稿句为：该订单已完成维修并结案。按上述两份材料，检测报告未提供，维修完成与结案字段未载明，该拟稿句属于未获支持。

## 配置怎么定

| 核对项 | 本页样本中的取值或做法 | 判定条件 |
| --- | --- | --- |
| 请求地址与方法 | 按外部报表接口文档选择地址，地址内可引用变量 | 地址与外部接口契约一致 |
| Headers 鉴权 | Authorization 通过安全配置注入，样例不写明文凭证 | 凭证不落在公开样例文本 |
| Body 结构 | 仅在相应请求类型下使用，按外部接口契约组织 JSON | 字段名与外部接口一致 |
| 变量引用 | 引用维修申请单号、补寄单号、出库单号等前方节点输出 | 逐项核对实际传入值 |
| 返回值提取 | 用 JSON path 语法配置 key，输出类型可选字符串 | key 与响应结构匹配 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 空值记录为环境差异 |

上述取值来自公开文档已说明的配置方式，未给出默认数值。若在本次假设试验中为 pageSize 设一个起点值 20，理由是与会话列表请求示例中出现的取值保持同一量级，比较方法为对照外部接口一次可接受的记录数量。

## 容易做错的三处

1. 把待检测状态当成维修完成。样本中维修申请单状态为待检测，检测报告未提供，若报表把该单计入维修完成，输入是状态字段，比较对象是结案所需字段，可观察结果是完成量被多计。
2. 把配件已出库当成补寄已签收。样本中出库单状态为已出库，签收信息未载明，若报表把出库计入签收，输入是出库状态，比较对象是签收字段，可观察结果是签收率被高估。
3. 把测试模式下的空 chatId 当成会话丢失。测试模式下 chatId 不存在，若据此判定会话异常，输入是调试返回，比较对象是正式调用返回，可观察结果是误报数量上升。

## 怎么确认配好了

1. 输入样本中的维修申请单 WX-0715-03 与配件出库单 PJ-0716-11，比较拟稿句“该订单已完成维修并结案”与两份材料载明的字段，检测报告与结案字段均未载明时，判定为未获支持，满足条件即通过。
2. 输入一条携带 body.appId 的 chat/completions 请求，比较返回中 responseData 的模块字段与请求中传入的 model、temperature，若响应未按传入参数改变，说明参数由编排决定，符合文档说明即通过。
3. 输入一条 detail=true、stream=false 的请求，比较返回体是否包含 responseData 与 choices，两者同时出现说明中间值与最终回答均可取，符合文档说明即通过。若 responseData 缺失，记录为未观察到中间值，保留证据缺口。
