# 商超供应商进场结算的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

商超供应商进场结算的账款关系以购销或代销为主，供应商不一定驻场经营，数据分散在 ERP 采购、供应商门户、POS 销售与财务系统之间。核对验收数量、计算返利扣点、处理退货差异这三项工作占用最多时间，采购合同、送货验收单、返利协议、对账单构成主要文档集合。这些特征对对话日志与审计的含义是：日志需要能定位到具体会话与具体对话，才能把一次问答与某份对账单、某次异常复盘对应起来。资料给出的更新频率为周与月，本页不据此推导批量同步、全量同步或实时触发。

## 这些特征在「对话日志与审计」这一环带来什么约束

会话由 chatId 标识，对话由 dataId 标识，两者在同一 appId 下才有意义。chatId 非空时系统从数据库取会话，messages 数组最后一个内容作为用户问题，其余 message 被忽略；chatId 不传时完全不使用上下文。responseChatItemId 传入后作为本次响应消息 ID 存入数据库，需在当前 chatId 下唯一。detail 决定是否返回中间值，非 stream 模式下结果保存在 responseData 中。日志存在只说明记录被写入，对账、留存与合规审计仍需完整业务方案另行落实。

假设演练样本：某商超与某供应商就 2024 年 10 月对账差异进行复盘，材料原文为“送货验收单编号 YS-20241015-07 记载收货数量 120 箱”“对账单 2024 年 10 月列示结算数量 118 箱”“返利协议约定月度返利按含税销售额 2% 计算”。拟判定句为“本期对账差异已由供应商确认并同意按 118 箱结算”。该句中的确认与同意在材料中均未出现，属于未获支持。另一交接请求为“请把该会话的复盘结论同步到供应商门户”，该请求处于待处理状态，不构成已执行。

## 配置怎么定

| 配置或核对项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求体 body.appId | 填入目标应用 ID | 与 APIKey 关联的 appId 比较，确认优先级取值 |
| chatId | 使用同一复盘会话 ID | 与历史会话列表返回的 chatId 比较 |
| detail | 设为 true | 与 detail=false 的返回比较，确认 responseData 是否出现 |
| stream | 设为 false | 与 stream=true 的事件流比较，确认结果位置 |
| 会话来源 source | 设为 api | 与页面会话比较，确认列表仅含 API 创建会话 |
| 运行详情核对 | 取 getResData 返回数组 | 与 getPaginationRecords 的 dataId 比较 |

以上数值均为本次假设试验起点，非官方默认值。

## 容易做错的三处

1. 把 chatId 不传时的行为当成仍带上下文。输入为省略 chatId 的请求体，比较对象为带 chatId 的请求，可观察结果是返回内容是否受历史会话影响。资料说明不传时不使用上下文，实际表现需按返回内容核对。
2. 把 relevance 分数当作权限或实体过滤。输入为一次检索返回的 score 字段，比较对象为业务授权清单，可观察结果是分数高低与记录是否属于该供应商并无对应关系。检索不承担授权职责。
3. 把待处理交接请求记为已完成同步。输入为“请把复盘结论同步到供应商门户”的请求文本，比较对象为门户侧是否出现对应记录，可观察结果是请求状态仍为待处理。待处理不构成执行。

## 怎么确认配好了

1. 使用假设样本中的对账差异会话。输入为带 chatId 与 detail=true 的请求，比较 responseData 中是否出现对应模块记录，可观察结果是运行详情可定位到该次对话。预期为字段与样本会话一致，未实测。
2. 使用拟判定句“本期对账差异已由供应商确认并同意按 118 箱结算”。输入为该句与三段材料原文，比较对象为材料中是否出现确认与同意，可观察结果是该句缺少依据，属未获支持。预期为不判定为已确认，未实测。
3. 使用交接请求文本。输入为该请求与门户侧记录清单，比较对象为是否存在对应同步记录，可观察结果是请求仍为待处理。若清单为空数组，则下游设计需自行承接，不推定检索一定返回空。预期为保持待核实，未实测。
