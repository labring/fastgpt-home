# 商超塑料袋与一次性用品报告的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

商超塑料袋与一次性用品报告围绕一次性塑料制品使用与回收情况展开，材料来源包括采购台账、销售凭证、半年报告和自律承诺。数据更新存在两种节奏：销售凭证按日产生，半年报告按半年形成。经营报表与异常复盘需要把这两类材料放到同一口径下核对。

采购台账记录进货批次、数量与供应商；销售凭证记录门店实际售出；半年报告汇总使用量与回收情况。三类材料的责任主体、时间范围与字段含义需要逐项对齐，才能判断某期数据是否一致。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向外部地址发送请求，Params、Headers、Body 三类数据均可通过 `{{}}` 引用变量，变量来自全局变量、系统变量和前方节点输出。返回值通过 JSON path 或 JS 对象取值规则提取，输出类型选择字符串时会转为 json 字符串。

对话接口调用时，`chatId` 为空表示不使用上下文，非空时以 messages 数组最后一条作为用户问题；`responseChatItemId` 需在当前 chatId 下唯一。密钥鉴权优先使用 `body.appId`，也支持 `Authorization: Bearer <apiKey>-<appId>`。`authProxy` 代理身份需要团队所有者开启，代理身份仍需具备目标应用和会话权限。

假设演练样本：某商超总部合规岗在 2025 年 7 月 10 日核对 2025 年上半年塑料袋报告，采购台账原文为「2025 年 1 月至 6 月，门店 A 采购手提塑料袋 12000 个，供应商甲」。销售凭证原文为「2025 年 1 月至 6 月，门店 A 售出塑料袋 11500 个」。拟提交的半年报告草稿句为「门店 A 上半年使用塑料袋 12000 个，已全部回收」。待判定请求为「请通过 HTTP 接口把该草稿同步至外部报告系统，并视为已完成报送」。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址 | 外部报告系统提供的报送接口地址 | 与外部接口文档逐字比对路径与方法 |
| 请求方法 | POST | 与外部接口文档声明的动作比对 |
| Headers 鉴权 | `Authorization: Bearer {{token}}` | 核对 token 来源与授权范围 |
| Body 字段 | 门店、期间、使用量、回收量 | 与台账、凭证字段逐项对齐 |
| 变量引用 | `{{appId}}`、`{{token}}` | 核对全局变量与前方节点输出实际值 |
| 返回值提取 | `$.data.status` | 与外部接口响应结构比对 |

起点选择 POST 与表单式 Body，原因是报送动作需要提交结构化数据；该起点为本次假设试验设定，与外部接口文档声明的动作比对后确定。

## 容易做错的三处

1. 把台账采购量 12000 个直接当作使用量写入草稿。输入为采购台账原文，比较对象为销售凭证的 11500 个，观察结果是草稿使用量与凭证不一致。
2. 把草稿句中的「已全部回收」当作已核实事实。输入为草稿句，比较对象为现有材料，观察结果是回收情况在台账与凭证中均未载明。
3. 把待判定请求中的「视为已完成报送」当作已执行。输入为请求文本，比较对象为接口返回状态，观察结果是未取得外部系统确认。

## 怎么确认配好了

1. 输入台账原文与凭证原文，比较 12000 与 11500，观察草稿使用量字段是否与凭证一致。若不一致，记录差异并保留待核实状态。
2. 输入草稿句「已全部回收」，比较现有材料是否载明回收数量与回收主体，观察该表述是否获得支持。未载明时记录为未获支持。
3. 输入待判定请求，比较接口返回的 `status` 与「已完成报送」表述，观察是否取得外部系统确认。未取得确认时，报送状态保持待核实。
