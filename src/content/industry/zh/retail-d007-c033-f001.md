# 外汇收结汇与贸易名录的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

外汇收结汇与贸易名录的数据围绕外汇资金与贸易背景真实性组织，与信用证审单关注全套单据不同。主要来源包括国家外汇管理局政策、银行网银、企业财务账和海关出口数据。日常文档为收汇水单、贸易合同、发票和外汇业务登记资料，更新频率为每单与每月。经营报表与异常复盘要求把收汇主体、金额、合同和登记状态按同一字段对齐，HTTP 接口与外部系统负责把外部返回的数据接入这一核对过程。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径参数，Body 用于 POST/PUT 请求体，Headers 传递特殊信息，三者均可通过 {{}} 引用全局变量、系统变量和前方节点输出，URL 同样可引用变量。返回值配置通过 JSON path 或 JS 对象取值规则提取接口响应内容，输出类型选择字符串时会把对应 key 的值转为 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于环境差异。对话接口调用时 model、temperature 等字段无效，由编排决定；不会返回实际消耗 Token 值，设置 detail=true 后可手动计算 responseData 里的 tokens。检索结果、相似度与引用列表不构成业务授权，外部系统是否允许入账、登记或结汇需要另行确认。

## 配置怎么定

假设演练样本：某外贸企业财务人员持有一份收汇水单，水单载明付款方为境外买方 A，收款方为该企业，金额 50,000 美元，日期为 2025 年 3 月 10 日；另有一份贸易合同编号 HT-2025-031，签约双方与上述主体一致，金额 50,000 美元。拟交接请求句为“请根据水单与合同办理结汇并登记贸易名录”。该句未载明结汇授权与登记权限，属于待核实请求。

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档给定的地址与 GET/POST | 核对地址是否引用已提供变量，方法是否与接口契约一致 |
| Headers 鉴权 | Authorization 通过安全配置注入 | 核对凭证未写入公开样例，变量引用名与配置一致 |
| Body 结构 | 仅在 POST/PUT 下填写 JSON | 逐字段对照外部接口契约，字符串引用加引号 |
| 返回值提取 key | 按接口响应结构配置 JSON path | 用 detail=true 查看 responseData 后确认取值路径 |
| 变量来源 | 全局变量、系统变量、前方节点输出 | 逐项核对实际传入值，测试模式下确认 chatId 不存在 |
| 输出类型 | 字符串或对象 | 字符串会将对应 key 值转为 json 字符串，核对下游文本加工能否解析 |

## 容易做错的三处

1. 把检索结果或相似度当作业务授权。检索返回的引用列表与 score 属于检索结果，不构成结汇、登记或入账许可。检查方式：输入上述水单与合同材料，比较返回内容是否被直接当作办理依据，观察是否出现未经确认的授权结论。
2. 把测试模式下的空 chatId 当成业务故障。系统变量说明 chatId 与 responseChatItemId 在测试模式下不存在。检查方式：在测试模式发起请求，比较返回的 chatId 字段与正式会话记录，观察是否把空值误判为接口异常。
3. 把表单收集的值当作已完成业务动作。交互节点的 inputForm 只收集用户输入，业务验证、审批与数据库写入需要下游实现。检查方式：输入上述拟交接请求句，比较表单返回值与实际业务状态，观察是否把填写动作当成结汇或登记已完成。

## 怎么确认配好了

1. 输入上述水单与合同原文，比较拟交接请求句是否载明结汇授权与登记权限，观察是否保留为待核实请求，未补造授权条款。
2. 在测试模式发起请求，比较系统变量 chatId 与 responseChatItemId 的取值，观察是否记录为测试模式不存在，未当作业务故障。
3. 配置 detail=true 后查看 responseData，比较 tokens 字段与 usage 返回值，观察是否能手动计算消耗，未把 model、temperature 等无效字段当作生效参数。
