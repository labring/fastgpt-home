# 外汇收结汇与贸易名录的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样
外汇收结汇围绕外汇资金与贸易背景真实性展开，不审全套信用证单据。日常材料包括收汇水单、贸易合同、发票、外汇业务登记资料，核对收汇主体、办理结汇、解释贸易背景是耗时环节。经营报表与异常复盘要按每单与月两个频率把对话记录与业务单据对齐，因此对话日志的 chatId、dataId、运行详情成为可追溯的核对线索。日志存在只说明记录留存，对账、留存与合规审计由完整业务方案另行落实。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话身份要结合 chatId 核对目标对话与业务记录，不同入口的会话不混算。需要运行详情时按官方契约设置 detail，检查 responseData 中的模块状态与完整结果。接口实际返回哪些字段，日志就核对哪些字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，输入、历史与返回内容分别核对。检索或表单只是收集与召回，不构成授权。

假设演练样本：某外贸财务在 2025 年 3 月处理一笔出口收汇，材料原文为“收汇水单显示付款方为 A 公司，金额 12,000 美元，日期 2025 年 3 月 5 日；贸易合同卖方为 B 公司，发票开票方为 B 公司；外汇业务登记资料登记的收汇主体为 B 公司。”待判定的交接请求为“请确认该笔收汇主体一致，可直接入账。”此请求中的“可直接入账”属于业务执行动作，纸面材料只能支持主体比对，入账授权边界未载明。

## 配置怎么定
下表为本次假设试验起点，用于核对输入、比较对象与观察结果，不表示官方默认值。

| 配置或核对项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| appId | 假设应用标识 appId=audit-2025-03 | 与 chatId 配对定位目标应用会话，比较请求体与返回是否同一 appId |
| chatId | 假设会话标识 chat-0312 | 核对目标对话与业务记录对应，比较不同入口会话是否被混算 |
| dataId | 假设对话标识 data-0007 | 用于获取单个对话运行详情，比较记录列表与详情是否同一对话 |
| detail | 假设设为 true | 需要模块状态与完整结果时启用，比较 responseData 是否含目标模块 |
| source | 假设设为 api | 获取会话列表时限定 API 来源，比较返回列表是否含页面会话 |
| pageSize | 假设设为 20 | 本次假设记录数量起点，与返回 total 比较判断是否需继续翻页 |

## 容易做错的三处
1. 把检索命中当作授权。输入为上述交接请求，若因相似度较高就认定可入账，比较对象应是材料原文中的收汇主体与合同、发票主体，观察结果是三处主体是否一致；一致只支持主体核对，入账授权仍待核实。
2. 把日志存在当作合规审计完成。输入为假设 chatId 的会话记录，比较对象是业务方案要求的对账与留存要求，观察结果是日志字段是否覆盖这些要求；未载明的要求记录为缺口。
3. 混算不同入口会话。输入为 source=api 的会话列表，比较对象是目标 chatId 与列表中各 chatId，观察结果是目标会话是否唯一出现；出现多个来源时分别核对，不合并计算。

## 怎么确认配好了
1. 主体一致性核对。输入材料原文三句与交接请求，比较收汇水单付款方、合同与发票开票方、登记资料收汇主体，观察结果为主体的相同或不同；相同不推出可入账，不同则记录待核实。
2. 运行详情字段核对。输入假设 appId、chatId、dataId 与 detail=true，比较返回 responseData 中模块名、模块类型与运行时间，观察结果为目标模块是否出现；未出现的字段记录为未返回。
3. 会话来源核对。输入 source=api 与 pageSize=20，比较返回列表中各 chatId 与目标 chatId，观察结果是目标会话是否在列表内且来源一致；无法确认时保留为未获支持，不声称已排除。
