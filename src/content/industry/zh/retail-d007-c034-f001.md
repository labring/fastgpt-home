# 外贸出口退税申报的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

出口退税申报在货物出口后完成税务凭证匹配，主要数据来源为电子税务局、出口退税申报系统、海关电子信息与财务账。日常文档包括出口免退税申报表、出口报关单、进货发票与收汇凭证。数据按月或每批更新，匹配发票与报关单、生成申报数据、处理疑点反馈属于耗时环节。经营报表与异常复盘围绕这些文档展开，HTTP 接口与外部系统承担请求发送与返回值提取。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 用于路径请求参数，Body 用于请求体，Headers 用于请求头。三种数据均可通过 `{{}}` 引用全局变量、系统变量与前方节点输出，URL 同样可以引用变量。返回值配置代表如何解析接口返回值，通过 JSON path 语法提取响应值。引用字符串变量时需加引号，数字与布尔值直接引用。输出类型选择字符串时，对应 key 的值转为 json 字符串。

假设演练样本：某外贸企业财务人员准备一份 2025 年 3 月出口退税申报的异常复盘材料，材料原文为“本批次出口报关单共 12 份，其中 3 份的进货发票号码在申报系统中未匹配成功；收汇凭证已收齐 9 份，其余 3 份状态为待收汇。”待判定的拟稿句为“本批次全部报关单已完成发票匹配，可提交申报。”该拟稿句与材料原文在匹配数量与收汇状态上需要逐项核对。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 外部接口文档给出的地址 | 地址可引用变量，与文档地址逐字符比对 |
| 请求方法 | 文档规定的方法 | 与外部接口契约比对，确认方法一致 |
| Params | 按文档列出的路径参数 | 逐项核对 key 与 value，确认无缺失 |
| Headers | Authorization 使用 Bearer 加凭证 | 凭证通过安全配置注入，不写入公开样例 |
| Body | 按文档 JSON 结构填写 | 核对字段类型，字符串加引号，数字直接引用 |
| 返回值提取 | 按 JSON path 配置 key | 与接口响应示例比对，确认提取路径存在 |

## 容易做错的三处

1. 把返回值配置当成接口返回值本身。返回值配置代表如何解析接口返回值，需要按 JSON path 提取。检查方式：输入一份接口响应示例，比较配置的 key 与响应中实际路径，观察提取结果是否与响应中对应字段一致。
2. 在测试模式下把 chatId 与 responseChatItemId 的空值当成业务故障。文档说明这两个字段在测试模式下不存在。检查方式：输入测试模式请求，比较返回结果与正式模式差异，观察是否仅缺少这两个字段。
3. 将检索或表单填写当成授权执行。表单收集值，业务验证、审批与数据库写入需要下游实现。检查方式：输入一份待审核的交接请求，比较请求状态与审批记录，观察是否存在已完成的审批证据。

## 怎么确认配好了

1. 输入假设样本中的材料原文与拟稿句，比较拟稿句“全部报关单已完成发票匹配”与原文“3 份未匹配成功”，观察拟稿句是否与原文数量一致。若不一致，该拟稿句未获支持。
2. 输入假设样本中收汇凭证状态，比较“已收齐 9 份”与“3 份待收汇”，观察拟稿句是否遗漏待收汇状态。若遗漏，需补充待核实说明。
3. 输入一份 HTTP 请求配置，比较 Params、Headers、Body 与外部接口文档，观察返回值提取路径是否存在于响应示例中。若路径不存在，提取结果为空，需核对文档后调整。
