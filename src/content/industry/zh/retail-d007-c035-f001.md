# 外贸退运与索赔的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
退运索赔处理出口后的逆向物流与责任认定，资料来自客户邮件、质检报告、海关系统与保险公司理赔系统，日常文档包括退运协议、索赔函、质量报告与退运报关单。数据按案更新，每案单独处理。经营报表与异常复盘需要把这些分散材料汇总成可核对的口径，HTTP 接口承担向外部系统取数与回传的职责。文档字段未提供的部分属于未知，不能凭品类印象补全。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向指定地址发送请求，Params 用于路径请求参数，Body 用于 POST/PUT，Headers 传递特殊信息，三者均可通过 `{{}}` 引用全局变量、系统变量和前方节点输出，URL 同样可以引用变量。返回值通过 JSON path 提取，出参格式化后可将值转为 json 字符串输出。对话接口以 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 `body.appId`，也支持 `Authorization: Bearer <apiKey>-<appId>`；传入的 `model`、`temperature` 等字段无效，由编排决定。`chatId` 与 `responseChatItemId` 在测试模式下不存在，调试时的空值属于环境差异。检索与相似度只影响召回内容，不承担权限或实体隔离。

假设演练样本：某外贸售后人员整理一票退运案的经营复盘。材料原文为「退运协议载明买方于 2025 年 3 月 10 日提出退运申请，货物为 200 件电机，退运原因为轴承异响；索赔函载明索赔金额待质检报告确认后填写；质量报告载明抽样 20 件中 6 件异响，报告状态为草稿」。待判定拟稿句为「本案退运原因已确认，索赔金额已确定」。核对对象是材料所述状态与拟稿句的对应关系。

## 配置怎么定
下表围绕本页样本，列出官方已说明的设置或实施核对项。数值为本次假设试验起点，用于与外部接口契约或材料状态比较，不代表官方默认值。

| 配置项 | 取值或核对内容 | 与本页样本的关系 |
| --- | --- | --- |
| 请求地址 | 按外部接口文档填写，可引用变量 | 取质检报告与索赔状态的服务地址 |
| 请求方法 | 按外部接口文档选择 | 读取用 GET，回传用 POST |
| Headers | 鉴权凭证通过安全配置注入 | 不写入公开样例 |
| Body | 仅在对应请求类型下使用，核对 JSON 结构 | 回传退运案字段时逐项核对 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 传入案件标识与报告状态 |
| 返回值提取 | 按 JSON path 配置 key | 提取报告状态与金额字段 |

## 容易做错的三处
1. 把材料中的「草稿」状态当作已确认。质量报告状态为草稿，拟稿句写「退运原因已确认」，输入是报告状态字段，比较对象是草稿与已确认，观察结果是两者不一致，拟稿句未获支持。
2. 把「待填写」当作已确定。索赔函载明金额待质检报告确认后填写，拟稿句写「索赔金额已确定」，输入是索赔函金额字段，比较对象是待填写与已确定，观察结果是字段为空，拟稿句未获支持。
3. 把测试模式下的空 `chatId` 当作业务故障。测试模式下 `chatId` 与 `responseChatItemId` 不存在，输入是测试环境请求，比较对象是测试模式与正式会话，观察结果是字段缺失属于环境差异，不构成业务异常。

## 怎么确认配好了
1. 输入假设样本材料原文与拟稿句，比较报告状态字段与「已确认」表述，若状态为草稿则拟稿句未获支持，记录为待核实。
2. 输入索赔函金额字段与「已确定」表述，比较字段是否为空，若为待填写则拟稿句未获支持，保留证据缺口。
3. 输入测试模式请求，比较 `chatId` 与 `responseChatItemId` 是否存在，若不存在则记录为测试环境差异，不判定为业务故障；正式会话需另取实际值核对。
