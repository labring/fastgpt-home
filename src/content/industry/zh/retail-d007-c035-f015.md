# 外贸退运与索赔的经营报表与异常复盘：知识库检索与召回

## 这个品类的数据长什么样
外贸退运与索赔处理出口后的逆向物流与责任认定，主要数据来源包括客户邮件、质检报告、海关系统与保险公司理赔系统。日常文档为退运协议、索赔函、质量报告与退运报关单，更新频率为不定期、每案。这些材料共同决定一笔退运索赔是否成立、由谁承担费用、是否触发退税调整。经营报表与异常复盘需要从这些文档中检索出同一案件的主体、对象、状态与有效范围，检索结果直接支撑复盘结论。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库。不同向量模型的库不可共同关联，需先核对向量模型标识并排除不符合者，记录实际观察。检索采用语义检索、全文检索或混合检索召回候选，混合检索通过 RRF 融合多路结果，RRF 是融合过程，不是可开启的开关。最低相关度仅在语义检索或使用结果重排时生效，是过滤阈值，不承担权限或实体隔离功能。引用上限以 token 为单位控制引用内容量。问题优化用于指代消除和问题扩展，会在检索前增加一次模型调用。引用内容以数组输出，长度可以为 0，空结果链路仍可走通。以下为假设演练样本，不涉及真实客户或编号。

假设演练样本：材料原文为“2025年3月10日，A公司就批次B-203提交退运协议，退运原因为外包装破损，退运申报状态为已提交未放行；索赔函列明索赔金额与质检报告编号，保险公司理赔系统显示待审核。”待判定拟稿句为“该批次退运申报已完成，索赔已获保险公司批准。”

## 配置怎么定
下表围绕该样本列出与本功能相关的官方已说明设置或实施核对项。本次假设试验起点仅用于演练，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 关联的知识库 | 仅关联同一向量模型的一个库 | 核对向量模型标识，排除不同模型库 |
| 搜索模式 | 混合检索 | 与语义检索、全文检索分别比较召回差异 |
| 引用上限 | 假设起点 2000 token | 用长短不同的实际资料测试内容完整性后调整 |
| 最低相关度 | 假设起点 0.5 | 仅语义检索或重排时生效，先标注相关与无关样本 |
| 问题优化 | 暂不开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 暂不开启 | 需具备模型并按设置启用，比较候选排序变化 |

## 容易做错的三处
1. 将检索命中当作授权或审批完成。输入为样本原文与拟稿句，比较“已提交未放行”与“已完成”、“待审核”与“已获批准”，若拟稿句与原文状态不一致，则判定为未获支持。
2. 把最低相关度当作实体或权限过滤器。输入为跨主体的检索问题，比较返回内容是否包含其他主体记录，若仅凭相似度得分排除，则属于错误理解，检索不负责授权隔离。
3. 将 RRF 写成可开启的开关或把引用上限与思考预算混用。输入为混合检索配置说明，比较是否出现 RRF 开关或 token 上限被移作思考预算，若出现则判定为配置描述错误。

## 怎么确认配好了
1. 输入样本原文与拟稿句，比较“已提交未放行”与“已完成”、“待审核”与“已获批准”，若检索结果与原文状态一致且拟稿句被标注为未获支持，则满足条件。
2. 输入一个跨向量模型的关联请求，比较库的向量模型标识，若不同模型库被排除且记录实际观察，则满足条件；不执行跨模型检索来比较漏召回。
3. 输入一个明确的纸面空结果[]，比较下游链路是否仍走通，若空结果链路走通且未声称虚构规则检索一定返回[]，则满足条件。以上均为纸面核对，不代表已实际部署或执行。
