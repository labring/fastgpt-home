# 多仓分仓与库存同步的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

多仓分仓发生在订单路由阶段，决定从哪个仓发货，数据来源包括 WMS、OMS、ERP 库存与平台库存接口，更新频率为日或小时。经营报表与异常复盘需要把分仓规则、库存同步表、调拨单、缺货预警放在同一时间口径下比对。HTTP 模块向对应地址发送请求，Params 用于路径参数，Body 用于请求体，Headers 用于请求头，三者均可通过 `{{}}` 引用变量，变量来自全局变量、系统变量与前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables 等；chatId 与 responseChatItemId 在测试模式下不存在，调试时取不到值属于正常现象，不构成业务故障。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

返回值配置不代表接口返回值本身，而是描述如何解析响应，通过 JSON path 提取。输出类型选择字符串时，会把对应 key 的值转成 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 `body.appId`，也支持 `Authorization: Bearer <apiKey>-<appId>`；传入的 model、temperature 等参数无效。detail=true 时返回中间值，stream 模式下通过 event 区分。交互节点返回的 interactive 只含 type 与 params，entryNodeIds 等内部运行态字段不返回。检索与相似度不承担权限过滤，节点运行不构成业务授权。

假设演练样本：某供应链计划组拟用 HTTP 模块把 2025 年 3 月 10 日 A 仓缺货预警推送至外部工单系统。供核对的材料原文为：“预警单号 W-0310-A，主体为 A 仓，对象为 SKU-1001，状态为待审核，可售库存字段值 0，统计期间 2025-03-10 00:00 至 2025-03-10 23:59。”待判定的拟稿句为：“A 仓 SKU-1001 已缺货，请立即补货。”该请求当前状态为待审核，尚未获得调拨执行授权。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 外部工单系统接口地址，以变量引用 | 按外部接口文档选择，与文档声明地址逐字符比对 |
| 请求方法 | POST | 与外部接口契约声明的写入方法比对 |
| Headers | Authorization 头由安全配置注入 | 与鉴权规范比对，不在公开样例写入凭证 |
| Body 结构 | 含预警单号、主体、对象、状态字段 | 与材料原文逐字段比对，确认无增删 |
| 返回值 key | 按响应结构配置 JSON path | 与响应示例比对，确认提取路径存在 |
| detail 参数 | 本次设为 true | 用于获取中间值，与 stream 取值组合比对 |

## 容易做错的三处

1. 把待审核状态当作已批准执行。材料原文状态为“待审核”，拟稿句写“已缺货，请立即补货”，输入为状态字段，比较“待审核”与“已批准”，若两者不一致则判定拟稿句超出授权边界。
2. 把测试模式下缺失的 chatId 当成业务故障。输入为测试模式请求，比较 chatId 是否为空，若为空则记录为文档已说明现象，不写入异常复盘。
3. 把返回值配置当成接口返回值。输入为已配置的 JSON path，比较实际响应结构与提取结果，若提取路径不存在则记录为解析配置问题，不推断外部系统数据错误。

## 怎么确认配好了

1. 输入假设样本材料原文与拟稿句，比较状态字段“待审核”与拟稿句“已缺货，请立即补货”，若状态字段未载明批准，则记录为未获授权，保留证据缺口。
2. 输入请求 Body 中的预警单号、主体、对象字段，比较材料原文对应字段，若逐字段一致则满足核对条件，若缺失则记录为待核实。
3. 输入返回响应与已配置 JSON path，比较提取结果与响应实际结构，若路径存在且值可提取则满足条件，若路径不存在则记录为解析配置待调整。
