# 多仓分仓与库存同步的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样
多仓分仓在订单路由阶段决定发货仓，数据来自WMS、OMS、ERP库存与平台库存接口，日更或小时更。经营报表与异常复盘要回答的问题集中在三处：分仓规则优先级是否按预期生效、可售库存同步值是否与各仓实际一致、超卖预警是否被及时处理。这些判断依赖对话日志与审计记录提供的时间、主体与运行字段，日志缺失时结论只能停在未获支持。

## 这些特征在「对话日志与审计」这一环带来什么约束
日志按 chatId 归属单个会话，dataId 归属会话下某条对话，两者混用会把不同入口的会话合并计算。运行详情需要按官方契约设置 detail 并检查 responseData；未返回的业务字段不能推定已完整留存。检索或表单只收集值，业务验证、审批、数据库写入与外部同步须由下游实现，检索结果不构成授权。对话身份、运行详情、字段含义、调试与正式调用、业务审计分工五项事实共同限定本页范围。

假设演练样本：某供应链计划岗于2025年3月10日提交一份分仓异常复盘请求，材料原文为三句：「3月9日华东仓可售库存同步表显示A商品120件；当日超卖预警记录显示A商品触发1次；分仓规则优先级表将华东仓列为该商品首选仓。」待判定拟稿句为「该商品3月9日未发生超卖，华东仓库存同步正常。」样本主体为A商品、华东仓，对象为同步表与预警记录，状态为已提交待核对，有效范围为3月9日单日。该拟稿句与原文材料存在取值方向差异，需逐字段核对。

## 配置怎么定
下表为本次假设试验起点的实施核对项，非官方默认值。

| 核对项 | 本次假设起点及理由 | 比较方法 |
|---|---|---|
| chatId 唯一性 | 假设起点为单会话单 chatId，长度小于250，理由为官方说明要求自行确保唯一 | 与目标会话记录逐一比对 |
| dataId 归属 | 假设起点为按会话下对话逐条定位 | 与 getResData 返回的 dataId 比对 |
| detail 取值 | 假设起点为 true，理由为需中间运行字段 | 与 responseData 是否出现比对 |
| source 取值 | 假设起点为 api，理由为只取 API 创建会话 | 与 getHistories 返回列表比对 |
| 反馈字段 | 假设起点为 loadCustomFeedbacks 读取 | 与对话列表返回字段比对 |
| 权限代理 | 假设起点为 authProxy 已开启且代理身份具备目标应用与会话权限 | 与创建或编辑 key 时的设置比对 |

## 容易做错的三处
1. 将检索命中或表单提交当作授权执行。输入为一次带 chatId 的查询，比较对象为是否存在审批或写入记录，可观察结果为只有检索返回而无下游业务动作。
2. 将不同入口会话合并统计。输入为两个 chatId 的对话列表，比较对象为各自 dataId 集合，可观察结果为合并后条数与单会话条数不一致。
3. 将未返回字段当作已留存。输入为 detail=false 的响应，比较对象为 responseData 是否存在，可观察结果为该字段缺失且无法据此推定留存完整。

## 怎么确认配好了
1. 使用样本原文三句与拟稿句，输入为 chatId 与 dataId 定位请求，比较对象为同步表数值120、预警次数1与拟稿句表述，可观察结果为取值方向不一致即判为未获支持。
2. 使用样本材料，输入为 detail=true 的请求，比较对象为 responseData 中是否出现运行字段，可观察结果为字段出现方满足核对条件；未出现则记录缺口。
3. 使用明确纸面输入空结果，输入为一条检索请求，比较对象为返回列表是否为空，可观察结果为按空结果核对下游设计，不据此断言虚构规则必返回空。跨不同向量模型库先核标识并排除不符者，不执行跨模型检索比较漏召回。
