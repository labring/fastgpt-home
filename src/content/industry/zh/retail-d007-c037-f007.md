# 大促仓配排产的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

大促仓配排产围绕短期峰值产能和人车场安排展开，与多仓库存同步的日常均衡逻辑不同。文档来源包括大促预测表、人员排班、快递保障方案和异常日报，更新频率为每场与每日。经营报表与异常复盘把对话日志当作核对材料：对话接口的 chatId 标识一个会话，dataId 标识会话下某一次对话，接口返回的字段决定哪些内容可供对账。文档说明，传入 detail=true 可取得中间值，非流式结果保存在 responseData 中；不传入 detail 时仅返回最终回答，模块状态与完整结果不出现。日志存在不表示业务数据已完整留存，未返回的字段属于未知。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份需要结合 chatId 与业务记录核对，不同入口的会话不能混算。文档指出，获取会话列表时 source=api 只返回通过 API 创建的会话，不获取页面上的会话；清空应用会话同样只清空 API Key 创建的会话。运行详情需要按官方契约设置 detail 并检查 responseData；detail=false 的响应不含模块级字段。测试模式与正式调用的身份字段可能不同，需分别核对输入、历史与返回内容。业务审计分工由完整业务方案另行落实，检索与表单收集值不构成授权，也不完成合规审计。

假设演练样本：某仓库在 2026 年 7 月 15 日大促首日提交一份异常日报草稿，原文为「7 月 15 日 14 时，A 分拣线因临时人员未到岗，积压订单 1200 单，已协调 B 快递增加一辆揽收车」。另有一条待判定的拟稿句：「本次异常已由系统自动完成排产调整并同步至快递系统。」核对材料为同一 chatId 下该 session 的对话记录，以及一份标注「待审核」的排产调整申请。

## 配置怎么定

| 核对项 | 官方已说明设置或实施核对动作 | 与样本的关系 |
| --- | --- | --- |
| 对话身份 | 结合 chatId 与 dataId 定位目标会话与对话 | 确认拟稿句对应的是哪一次对话记录 |
| 运行详情 | 需要中间值时设置 detail=true，检查 responseData | 判断记录中是否含模块级运行字段 |
| 会话来源 | 获取会话列表时 source=api 只返回 API 创建会话 | 区分页面会话与 API 会话，避免混算 |
| 交互节点 | detail=true 时从 event=interactive 或 content 取展示配置 | 核对表单输入值是否作为独立记录留存 |
| 反馈字段 | loadCustomFeedbacks 控制是否读取自定义反馈 | 判断该对话是否带有反馈记录 |
| 假设试验起点 | 本次假设以 dataId 唯一性作为核对起点，原因在于响应消息 ID 需在当前 chatId 下唯一，比较对象为同一 chatId 下其他 dataId | 用于判断记录是否可稳定定位 |

## 容易做错的三处

1. 把 detail=false 的返回当作完整运行记录。输入为 detail=false 的响应，比较对象为 responseData 是否存在，观察结果是模块级字段缺失，需改设 detail=true 重新调用。
2. 把 source=api 的会话列表当作全部会话。输入为 source=api 的请求，比较对象为页面会话是否出现在列表中，观察结果是页面会话不出现，需另行核对来源。
3. 把「待审核」的排产调整申请读作已执行。输入为标注待审核的申请，比较对象为拟稿句中「已完成调整并同步」的表述，观察结果是申请状态与表述不一致，属于未获支持。

## 怎么确认配好了

1. 输入样本原文与拟稿句，比较拟稿句中「系统自动完成排产调整并同步」是否有对应记录字段，观察结果为该表述在材料中无对应字段时判定为未获支持。
2. 输入同一 chatId 下的对话记录与待审核申请，比较申请状态与拟稿句的完成表述，观察结果为状态为待审核时不能读作已完成执行。
3. 输入 detail=true 的响应，比较 responseData 中是否含模块级字段，观察结果为字段出现时该次运行详情可供核对，字段未出现时记录为缺口。
