# 大促仓配排产的经营报表与异常复盘：知识库检索与召回

## 这个品类的数据长什么样

大促仓配排产围绕短期峰值产能和人车场安排展开，与多仓库存同步的日常均衡逻辑不同。本页涉及的材料包括大促预测表、人员排班、快递保障方案和异常日报。这些材料按每场活动与每日两个节奏更新，检索时要按具体场次和日期定位，不能把上一场数据当作本场依据。

历史大促订单、平台活动报名、WMS产能和快递揽收能力构成主要数据来源。经营报表与异常复盘需要从这些材料中取数核对，检索环节负责把相关段落召回给模型。召回结果只是引用内容，不构成对排产方案、人员安排或快递方案的批准。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，需先核对向量模型标识，排除不符合者，并记录实际观察。检索库的同向量模型要求不扩展到工商网站或其他外部系统。

语义检索、全文检索与混合检索各有适用场景。编号、型号、专有名词适合全文检索或混合检索；自然语言问法适合语义检索或混合检索。混合检索通过 RRF 融合多路结果，RRF 是融合过程，不作为独立开关。结果重排需具备 ReRank 模型并按设置启用，重排后可得到 0-1 得分。图片检索须有相应图像输入及模型能力，文档总流程图列出的可选路径不代表每次请求全部执行。

最低相关度仅在语义检索或使用结果重排时生效，是过滤阈值，不作为最终排序规则。引用上限以 token 为单位。问题优化用于指代消除和问题扩展，会增加一次模型调用。检索与相关度不负责权限或实体隔离，检索结果不构成授权。

假设演练样本：某仓库一份《大促预测表》原文写有：“本场活动为10月20日至10月22日，预测峰值订单量按日均8万单准备。人员排班表覆盖10月19日至10月23日。快递保障方案由商务在10月15日前确认车辆数。”另有一份《异常日报》记录：“10月21日揽收延迟2小时，涉及华东线路。”待判定拟稿句为：“本场大促快递保障方案已于10月15日确认，车辆数满足峰值需求。”核对要点：原文只写商务在10月15日前确认车辆数，未载明确认已完成，也未载明车辆数满足峰值需求。拟稿句的“已确认”和“满足”均未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联使用相同向量模型的大促排产库 | 先核向量模型标识，排除不同模型库，记录实际关联结果 |
| 搜索模式 | 语义检索与全文检索各跑一轮 | 按测试问题比较两路召回，不预设一种模式适合全部资料 |
| 引用上限 | 起点设为能容纳一份完整排班段落的 token 量 | 用长短不同的实际资料测试内容是否完整，再调整 |
| 最低相关度 | 起点设为0.5，仅语义检索或重排时生效 | 先标注相关与无关样本再调阈值，观察过滤后剩余条目 |
| 问题优化 | 对含指代的多轮追问开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 候选较多且具备 ReRank 模型时启用 | 比较重排前后顺序，用重排得分过滤 |

## 容易做错的三处

1. 把检索命中当作授权执行。假设样本中快递保障方案只写到商务在10月15日前确认车辆数，检索到该句不等于确认已完成，也不等于车辆数满足峰值需求。检查时输入该原文与拟稿句，比较“已确认”“满足”是否有对应表述，只有原文明确写出确认完成和满足结论才满足条件。
2. 把不同向量模型的知识库共同关联。假设样本涉及大促排产库与另一外部资料库，若两者向量模型标识不同，不得共同关联。检查时输入两库的向量模型标识，比较是否一致，标识不一致即排除，不执行跨模型检索来比较漏召回。
3. 把最低相关度当作权限或实体过滤。假设样本中异常日报只涉及华东线路，最低相关度不排除其他线路记录。检查时输入同一查询，比较过滤前后返回条目，观察是否仍包含无关线路，相关度阈值不承担线路隔离功能。

## 怎么确认配好了

1. 输入假设样本《大促预测表》原文与拟稿句“本场大促快递保障方案已于10月15日确认，车辆数满足峰值需求”，比较原文是否载明确认完成与满足结论。原文只写“10月15日前确认车辆数”，未载明完成状态，判定为未获支持，记录证据缺口。
2. 输入假设样本《异常日报》中“10月21日揽收延迟2小时，涉及华东线路”，比较拟稿句是否把该异常写成全线路或全时段。原文主体为华东线路、日期为10月21日，超出该范围的表述未获支持。
3. 输入一条空引用内容数组，核对下游设计能否承接长度为0的引用链路。空结果承接可用明确的纸面输入[]核对，不声称虚构规则检索一定返回[]。若检索返回内容，比较其是否属于已关联且同向量模型的知识库，记录实际观察，不保证首条命中或全部召回。
