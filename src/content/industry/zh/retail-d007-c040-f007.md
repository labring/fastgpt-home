# 客服咨询知识库维护的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

客服咨询知识库维护处理前置问答资料，不直接审批退款。数据来源包括客服系统、商品详情页、售后问题统计与质检抽查，日常文档为FAQ条目、话术模板、商品参数表与升级工单。本页聚焦对话日志与审计环节。

对话接口运行详情由detail参数决定。detail=false时响应只含choices与usage；detail=true时responseData保存模块状态与完整结果，stream模式通过event区分，非stream模式保存在responseData内。审计核对需区分节点已有行为、实际可配置字段、人工核对动作、需另接系统实现的业务动作。日志存在不等于完成合规审计。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份需结合chatId核对目标对话与业务记录。chatId不传时，不使用FastGPT上下文，完全由传入messages构建；chatId为非空字符串时，自动从数据库取会话，以messages数组最后一个内容作为用户问题，其余message被忽略。不同入口的会话不能混算。

运行详情需按官方契约设置detail并检查responseData。字段含义需核对日志与接口实际返回字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能不同，需分别核对输入、历史与返回内容。

假设演练样本（纸面材料，非真实记录）：

材料原文一：某知识库运营于2026年3月10日提交交接单，写明"对话日志核对范围：appId=A-100，chatId=C-200，dataId=D-300，来源source=api，期间2026年3月1日至3月7日"。

材料原文二：同日交接单附注"本次仅申请读取上述范围内的会话列表与单条对话运行详情，未申请删除、清空或修改反馈权限"。

待判定拟稿句："已确认该运营对全部会话具备删除权限，审计范围覆盖所有入口。"

判定：材料原文二写明未申请删除权限，原文一将范围限定在source=api且指定chatId与dataId。拟稿句超出授权边界与范围，未获支持。待审核不证明缺少操作权限，此处载明的是申请范围，实际授权状态仍待核实。

## 配置怎么定

下表为本次假设演练的核对项，非官方默认值。

| 核对项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| appId | A-100 | 材料原文一载明的应用标识，与接口返回appId比较 |
| chatId | C-200 | 材料原文一载明的会话标识，与getHistories返回chatId比较 |
| dataId | D-300 | 材料原文一载明的对话标识，与getResData请求参数比较 |
| source | api | 材料原文一限定来源，与getHistories参数说明比较 |
| detail | true | 需读取responseData核对运行详情，与detail=false响应比较 |
| 授权边界 | 仅读取 | 材料原文二载明未申请删除与清空，与删除接口权限比较 |

## 容易做错的三处

1. 将检索相似度当作权限或实体过滤。相似度分数不承担授权判断，检索不是授权。核对时应比较quoteList中的datasetId与目标库标识，排除不符者，记录实际观察。
2. 将detail=false的响应当作完整运行详情。detail=false时responseData不存在，核对时应比较响应字段是否含responseData，缺失时记录缺口。
3. 将交接单中的申请范围当作已批准授权。材料原文二只载明申请内容，核对时应比较实际授权记录，未提供时保留待核实状态。

## 怎么确认配好了

1. 输入材料原文一的appId=A-100、chatId=C-200、source=api，调用getHistories。比较返回list中各项chatId与C-200，返回total与材料限定期间内记录数。若list为空或chatId不符，记录为未命中，不推断数据不存在。
2. 输入材料原文一的dataId=D-300，调用getResData。比较返回data数组中moduleType与moduleName，核对是否含chatNode运行详情。若responseData缺失，记录为未获支持。
3. 输入材料原文二的授权边界"仅读取"，比较删除接口所需权限。若实际授权记录未提供，记录为待核实，不判定为已拒绝或已批准。空结果承接可用纸面输入[]核对下游设计，不声称虚构规则检索必然返回[]。

跨不同向量模型的库不可共同关联，先核标识并排除不符合者，不执行跨模型检索来比较漏召回。图片检索须有相应图像输入及模型能力，重排须具备模型且按设置启用，可选路径不代表每次请求全部执行。
