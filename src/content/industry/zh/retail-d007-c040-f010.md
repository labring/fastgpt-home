# 客服咨询知识库维护的经营报表与异常复盘：引用来源与溯源

## 这个品类的数据长什么样

在客服咨询知识库维护的经营报表与异常复盘中，本页说明FastGPT的引用来源与溯源如何衔接资料。知识维护复盘的参数新稿、FAQ采用和升级收件需要分别溯源。所用场景为自拟文字测试。

## 这些特征在「引用来源与溯源」这一环带来什么约束

知识维护复盘可拟商品参数新稿“开门方向待核”、FAQ旧答“侧开”和升级工单“说明已收”。报告写知识已同步且答疑问题已解决。新稿只是待核文字，旧答仍需适用判断，收说明也不记录升级结案。引用应保留版本和处理阶段，不能将新文件出现等同检索已采用，更不能由一次问答或工单收件推全部问法正确。本页不设真实产品参数或软件默认值，仅核拟议来源的关系。

## 配置怎么定

| 材料核对项 | 本题具体条件 | 实施取证 |
| --- | --- | --- |
| 内容地位 | 待核新稿 | 不作正式参数。 |
| 来源采用 | 实际引用与版本 | 不由上传推新答。 |
| 工单阶段 | 说明收件 | 不代解决。 |
| 问题范围 | 本商品本题 | 不保证所有问法。 |
| 正式维护 | 处理测试另证 | 不从成稿判同步。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `关联的知识库` | 同一检索节点关联的库需使用相同向量模型。 |
| `引用内容输出` | 输出为数组，可为空且继续传递。 |
| `引用输入承接` | 核回答环节实际接收的引用。 |
| `引用展示核对` | 逐项回查展示来源与原文。 |
| `资料时效核对` | 资料身份和有效版本分别核对。 |

## 容易做错的三处

第一处是新稿被写成正式参数，应查实际确认及对应商品，待核不补事实。第二处是文件加入被写成FAQ已采用，应对当前回答实际引用与原数据版本，不只看上传记录。第三处是升级收件被写成问题解决，应取本次真实处理结果及范围，接收说明不说明已修复。三项分别查内容地位、来源采用和业务结案，不用报告完成替知识或服务真实结果。

## 怎么确认配好了

验收分别问新稿确认到哪步、旧答引用什么、工单做了什么，展开实际引用。只有旧FAQ时应保留新参数待核，不能从未返回推新稿不存在；空引用需查范围与传递。补确认后同题看采用的新来源，更新仅限本商品及问题，不保证以后所有提问。此练习不写知识库、重建索引或关闭工单，不宣称真实准确率，正式维护结果仍需对应处理和测试记录。
