# 平台促销报名与价格管理的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

促销报名与价格管理的数据围绕价格、库存和活动节奏展开，与商品标题合规的用语审查不同。主要数据来源包括天猫营销后台、京东活动后台、ERP库存和历史成交价。日常文档为活动报名表、促销价审批单、库存锁定表和活动复盘表。经营报表与异常复盘需要把这几类文档中的字段与外部系统返回值对齐，核对活动期间的价格、库存和报名状态。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，实际操作与 Postman、ApiFox 这类工具接近。Params 为路径请求参数，GET 请求中居多；Body 为请求体，POST/PUT 请求中居多；Headers 为请求头，用于传递特殊信息。URL 可以通过 `{{}}` 引用变量，变量来自全局变量、系统变量和前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime 和 histories。histories 默认最多取 10 条，无法修改长度。返回值配置通过 JSON path 语法提取接口响应值，输出类型选择字符串时，会将 HTTP 对应 key 的值转成 json 字符串输出。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>。传入的 model、temperature 等参数字段均无效，这些字段由编排决定。detail=true 时返回中间值，responseData 中保存模块状态与完整结果。检索或表单收集不构成授权，业务验证、审批、数据库写入和外部同步需另接系统实现。

假设演练样本：某品牌在活动复盘时整理一份材料，原文为“本场活动报名表记录主体为A品牌旗舰店，对象为夏季促销活动，报名状态为已提交，活动日期范围为7月1日至7月7日；促销价审批单记录同一主体同一活动，审批状态为待审核；库存锁定表记录同一主体同一活动，锁定数量为500件，锁定状态为已锁定。”待判定的交接请求为“请通过HTTP接口把本场活动价格同步到外部系统并完成审批。”该请求中审批状态为待审核，属于未完成授权；同步动作需外部系统实现，不能由检索或表单代替。

## 配置怎么定

下表围绕假设演练样本，列出与本功能、本任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，非官方默认值。

| 配置项 | 本次假设试验起点 | 核对说明 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选择 | 地址可引用已提供变量，核对与外部契约一致 |
| Params 与 Headers | 分别核对请求参数与请求头 | 鉴权凭证通过安全配置注入，不写入公开样例 |
| Body | 仅在相应请求类型下使用 | 核对 JSON 结构与外部接口契约 |
| 变量引用 | 引用全局变量、系统变量和前方节点输出 | 逐项核对实际传入值 |
| 调试身份字段 | chatId 与 responseChatItemId | 测试模式下不存在，不把调试空值当成业务故障 |
| 返回值提取 | 按 JSON path 配置 key | 输出类型选字符串时转为 json 字符串 |

## 容易做错的三处

1. 把待审核的促销价审批单当作已完成审批，直接发起价格同步请求。输入为审批状态“待审核”，比较对象为“已完成审批”这一条件，观察结果是同步请求被发出且未核对授权边界。
2. 把测试模式下不存在的 chatId 或 responseChatItemId 空值判定为接口故障。输入为测试模式请求，比较对象为正式对话中的非空标识，观察结果是误报接口异常。
3. 把检索返回的相似记录当作价格或库存的授权依据。输入为知识库检索结果，比较对象为活动报名表与库存锁定表的实际字段，观察结果是引用未授权记录生成报表。

## 怎么确认配好了

1. 核对假设演练样本中的审批状态。输入为“促销价审批单记录审批状态为待审核”，比较对象为“已完成审批”这一条件，观察结果为待审核属于未完成授权，同步请求不应视为可执行，记录为待核实。
2. 核对变量引用与请求体结构。输入为 Body 中引用变量的声明，比较对象为外部接口契约要求的字段，观察结果为字段名与类型一致时满足条件，不一致时记录差异。
3. 核对返回值提取配置。输入为按 JSON path 配置的 key，比较对象为接口响应中的实际路径，观察结果为提取值与响应中对应值一致时满足条件，无法提取时记录缺口。空结果可用纸面输入 [] 核对下游设计，不声称虚构规则检索一定返回空。
