# 平台商品标题与详情合规的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

平台商品标题与详情合规处理宣传真实性与资质展示，不处理包裹交付。主要材料为商品标题表、详情页素材、广告禁词清单与质检报告，更新频率为每周及每次上新。经营报表与异常复盘需要把这些材料中的字段状态汇总为可核对的记录。HTTP 模块向指定地址发送请求，Params 为路径请求参数，Body 为请求体，Headers 为请求头，三者均可通过 {{}} 引用全局变量、系统变量或前方节点输出。外部系统返回的数据经 JSON path 提取后进入报表。核对宣传用语是否属极限词、实物参数是否与详情页一致、违规素材是否已替换，这三项耗时最多，也决定报表能否定位异常。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块可重复添加、手动配置、触发执行。系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。对话接口调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>。传入的 model、temperature 等字段无效，由编排决定。detail=true 时返回 responseData 中间值，可手动计算 tokens。变量来自全局变量、系统变量、前方节点输出，替换输入框内容里的 [key]。

假设演练样本：合规运营整理一份待复核材料，原文为「商品 A 标题含『全网最低』，详情页素材第三屏引用质检报告编号 Q-2024-018，广告禁词清单版本为 2024-06 周更版，上架日期 2024-06-11。质检报告 Q-2024-018 载明检测项目为纤维含量，签发日期 2024-05-20。」拟交接请求为「请把商品 A 标题与详情页素材同步到外部合规台账，并按禁词清单标记异常。」

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址与方法 | 外部合规台账接口地址，POST | 按外部接口文档选择，地址可引用变量 |
| Headers 鉴权 | Authorization 引用已配置的 token 变量 | 与接口文档要求的请求头逐项比较 |
| Body 结构 | JSON 含商品标识、标题文本、素材链接 | 与外部接口契约字段逐项核对 |
| 变量引用 | 标题文本、素材链接取自前方节点输出 | 与节点实际输出值比较 |
| 返回值提取 | 按 JSON path 提取台账记录标识 | 与接口响应结构比较 |
| 调试身份字段 | 测试模式下 chatId 不存在 | 与正式调用时的会话标识比较 |

## 容易做错的三处

1. 把检索或表单收集的值当作已获授权执行。样本中拟交接请求只表达同步意愿，未载明授权主体与生效范围，不能据此认定台账写入已获批准。
2. 把测试模式下 chatId 不存在当作业务故障。该字段在测试模式本就不存在，需与正式调用时的会话标识区分。
3. 把相似度分数当作权限或实体过滤条件。score 与 similarity 只反映检索相关程度，不排除未授权记录或无关业务。

## 怎么确认配好了

1. 输入样本原文与拟交接请求，比较请求体是否含商品标识、标题文本、素材链接，以及 Headers 是否引用 token 变量。观察结果是请求体字段与样本材料逐项对应，且鉴权凭证未写入公开样例。
2. 输入样本中质检报告编号 Q-2024-018 与签发日期 2024-05-20，比较详情页素材第三屏引用编号与报告原文编号是否一致。观察结果是编号一致且签发日期在素材引用范围内，或记录编号不一致的缺口。
3. 输入拟交接请求，比较其是否载明授权主体、对象、生效范围。观察结果是请求未载明授权边界时，台账写入保持待核实，不产生已执行的结论。
