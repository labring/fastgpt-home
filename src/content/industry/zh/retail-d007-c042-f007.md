# 平台商品标题与详情合规的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样
标题详情合规处理宣传真实性与资质展示，不处理包裹交付。主要数据来源为平台规则中心、广告法合规清单、品牌素材库与质检机构报告，日常文档包括商品标题表、详情页素材、广告禁词清单与质检报告。最耗时的环节是核查极限词、比对实物参数、替换违规素材。这些特征决定了对话日志在本页的作用：把一次标题或详情审核的对话身份、运行详情与字段留存情况固定下来，供经营报表与异常复盘核对。资料给出的更新频率为周与每次上新，本页功能不依赖该频率，故不展开。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话身份须结合 chatId 核对目标对话与业务记录，不同入口的会话不混算。需要运行详情时按官方契约设置 detail 并检查 responseData。日志与接口实际返回字段才是可核对的依据，未返回的业务数据不能推定已完整留存。测试模式与正式调用的身份字段可能不同，须分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。

假设演练样本：某次上新审核的纸面材料原文为「商品标题表第 12 行，主体为店铺运营岗，对象为某款保温杯标题，状态为待合规复核，日期范围为 2024 年 10 月当周上新的 3 条标题，授权边界为仅限本店铺标题与详情素材的合规检查」。待判定请求为「请把该保温杯标题的审核对话记录导出，用于本周异常复盘」。该请求的授权边界未载明是否包含导出操作，属待核实。

## 配置怎么定
下表围绕上述样本，只列与本功能、主任务相关的官方已说明设置或实施核对项。

| 配置或核对项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| appId | 样本应用 ID | 官方说明 appId 用于标识应用，与 chatId 配合定位会话 |
| chatId | 样本会话 ID | 官方说明非空 chatId 时从数据库取会话，须自行确保唯一且长度小于 250 |
| detail | true | 官方说明 detail 返回中间值与完整结果，用于获取 responseData |
| stream | false | 官方说明非 stream 模式结果保存在 responseData，便于逐字段核对 |
| source | api | 官方说明 source=api 只获取通过 API 创建的会话，与页面会话区分 |
| loadCustomFeedbacks | true | 官方说明该可选参数读取自定义反馈，用于核对反馈字段 |

## 容易做错的三处
1. 把不同入口的会话混算。输入为样本 chatId 与另一页面会话记录；比较两者 chatId 是否一致；若不一致仍合并统计，则对话身份核对失败。
2. 未设置 detail 却声称已获得运行详情。输入为样本请求且 detail 缺省或为 false；比较返回中是否存在 responseData；若不存在而报告仍列出模块运行详情，则该结论未获支持。
3. 把日志存在当作合规审计完成。输入为样本对话记录与合规审计要求；比较记录是否覆盖对账、留存与授权边界；若仅存在对话记录而授权边界待核实，则不能判定审计完成。

## 怎么确认配好了
1. 输入样本 chatId 与 source=api 的会话列表请求；比较返回 list 中 chatId 是否与样本一致；若一致且 total 与预期会话数相符，则对话身份核对满足条件。
2. 输入样本请求并设 detail=true、stream=false；比较返回 responseData 是否包含模块名、运行时间与 tokens 等字段；若包含且与请求时段对应，则运行详情获取满足条件。
3. 输入样本待判定请求；比较请求授权边界是否载明导出操作；若材料未载明，则记录为证据缺口，不判定导出已获授权。
