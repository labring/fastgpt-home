# 平台广告投放与站内流量的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
平台广告投放按流量与转化实时调价，不以平台活动审核为主，投放计划、关键词报表、人群包说明与转化归因表构成日常核对材料。数据来源包括巨量千川、京东快车、阿里妈妈与店铺成交数据，更新频率为日或小时。这些材料进入 HTTP 接口与外部系统时，核对重点落在请求地址、方法、请求头、请求体与返回值提取上，任何接口调用都只是数据通道，不承担广告授权或预算审批。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params、Body、Headers 与 URL 均可通过 {{}} 引用全局变量、系统变量或前方节点输出。返回值通过 JSON path 提取，输出类型选择字符串时会将对应 key 的值转成 json 字符串。chatId 与 responseChatItemId 在测试模式下不存在，调试空值不能当成业务故障。detail=true 时中间值保存在 responseData，stream 模式通过 event 区分。接口传入的 model、temperature 等参数无效，由编排决定。这些约束意味着投放报表的字段核对必须在明确的请求结构与提取路径下进行，接口返回不构成投放授权或归因结论。

假设演练样本：某投放专员提交一份纸面材料，原文为「投放计划 A 于 2026 年 3 月 1 日至 3 月 31 日执行，关键词报表 B 记录 3 月 5 日点击量 1200，转化归因表 C 记录同日成交 30 单。」拟判定句为「该计划 3 月 5 日 ROI 已确认达标。」此样本中主体为投放计划 A，对象为 3 月 5 日点击与成交字段，状态为待判定，有效范围为 3 月 1 日至 31 日。拟判定句缺少花费字段与达标阈值，属于未获支持。

## 配置怎么定
下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值仅为本次假设试验起点，不属官方默认值。

| 配置项 | 假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 外部接口文档给出的地址 | 地址可引用变量，与文档逐字符比较 |
| 请求方法 | POST | 与外部接口契约声明的方法比较 |
| Headers | Authorization 头 | 鉴权凭证通过安全配置注入，与文档字段名比较 |
| Body | JSON 结构 | 仅在相应请求类型下生效，与样本字段名比较 |
| 返回值提取 | JSON path 表达式 | 与接口响应示例的层级比较 |
| 输出类型 | 字符串 | 与下游文本加工所需格式比较 |

## 容易做错的三处
1. 把接口返回值直接当作投放达标结论。样本中拟判定句缺少花费字段，返回值提取只完成数据搬运，达标判断需要另行核对。
2. 把测试模式下的空 chatId 或空 responseChatItemId 当作业务故障。文档说明这两个字段在测试模式下不存在，核对时应记录缺失，不推断接口异常。
3. 把 detail=true 的 responseData 中某模块的 runningTime 或 tokens 当作投放效果指标。这些字段属于运行中间值，与广告花费和成交归因无对应关系。

## 怎么确认配好了
1. 输入样本原文与拟判定句，比较拟判定句所需字段是否在原文中出现。原文含点击量与成交单数，缺花费字段与达标阈值，判定为未获支持。
2. 输入一条假设请求，其 Body 引用 {{number}} 与 "{{string}}"，比较最终解析是否与文档示例一致。若字符串未加引号或数组未按文档写法，解析结果与预期不符。
3. 输入 detail=true、stream=false 的假设响应，比较 responseData 中 moduleType 与样本任务是否对应。若返回模块与投放报表无关，记录为待核实，不据此判定投放效果。
