# 平台类目资质准入的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

类目准入发生在商品上架或店铺入驻之前，核对对象是主体资质与授权链。日常材料包括营业执照、商标注册证、品牌授权链和行业许可证，来源分散在平台招商页面、国家企业信用信息公示系统、商标局数据与许可证系统。这些材料不定期更新，每次入驻都要重新归集。经营报表与异常复盘要回答的问题很具体：某一份材料在某一环节被谁以什么身份提交，处于什么状态，能否支撑该类目的发布。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向指定地址发送请求，Params 用于路径参数，Body 用于请求体，Headers 用于传递特殊信息，三者均可通过 {{}} 引用全局变量、系统变量和前方节点输出，URL 同样可以引用变量。系统变量包含 appId、chatId、responseChatItemId、variables、cTime 与 histories。chatId 与 responseChatItemId 在测试模式下不存在。返回值按 JSON path 从接口响应中提取，输出类型选择字符串时会把对应值转成 json 字符串。

对话接口使用 APIKey 鉴权，推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>。appId 的优先级为 body.appId、<apiKey>-<appId>、apikey 关联的 appId。传入的 model、temperature 等字段无效，由编排决定。detail=true 时返回中间值，非 stream 模式结果保存在 responseData 中。authProxy 代理团队成员身份需要团队所有者开启，代理身份仍需具备目标应用和会话权限。这些是接口层面的行为，检索或表单本身不构成授权。

假设演练样本。材料原文：「甲公司持有第 12345678 号商标注册证，核定使用商品为第 25 类服装；乙公司出具授权书，授权丙公司在 2025 年 1 月 1 日至 2025 年 12 月 31 日期间于某平台销售第 25 类服装，授权书落款日期 2024 年 12 月 20 日，未见甲公司对乙公司的再授权文件。」待判定的交接请求：「请通过 HTTP 接口把丙公司的第 25 类服装类目准入状态标记为已授权，并把授权链写入外部系统。」

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 外部接口文档给出的地址，含 {{BaseUrl}} | 与接口文档列出的地址逐字符比对 |
| 请求方法 | 按外部接口契约选择 | 与接口文档标注的方法比对 |
| Headers 鉴权 | Bearer {{token}} | 与密钥使用规范比对，确认凭证来源 |
| Body 结构 | 按外部接口契约构造 JSON | 与接口文档字段逐项比对 |
| 返回值提取 | 按 JSON path 配置 key | 与接口响应示例比对提取结果 |
| 输出类型 | 字符串 | 与下游节点所需类型比对 |

上表数值均为本次假设试验起点，不构成官方默认值。

## 容易做错的三处

1. 把待判定的交接请求当作已成立的授权。样本中授权书由乙公司出具，未见甲公司对乙公司的再授权文件，丙公司的类目准入状态缺少完整授权链支撑。核对时应比较主体名称与授权层级，观察授权链是否闭合。
2. 把检索或表单收集到的值当作授权执行。HTTP 模块可以发送请求并提取返回值，返回值提取结果不改变外部系统的授权状态。核对时应比较请求体内容与实际写入结果，观察外部系统是否返回成功标识。
3. 把测试模式下的空 chatId 当作业务故障。文档说明 chatId 在测试模式下不存在。核对时应比较测试模式与正式调用的 chatId 取值，观察是否因模式差异导致字段缺失。

## 怎么确认配好了

1. 输入样本材料原文与交接请求，比较授权书落款主体与商标注册证持有人是否一致，观察授权链是否出现断点。若无法确认再授权文件存在，记录为证据缺口，不判定为已授权。
2. 输入一条按接口文档构造的请求，比较请求体中 appId、chatId、messages 的实际取值与文档说明，观察返回值提取结果是否与接口响应示例的 JSON path 对应。不预设首条命中或全部召回。
3. 输入空结果数组 [] 核对下游设计，比较下游节点对空值的处理方式，观察是否出现未定义行为。该核对仅验证下游设计，不声称检索一定返回空结果。
