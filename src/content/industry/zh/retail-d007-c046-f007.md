# 平台类目资质准入的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

平台类目资质准入发生在商品上架或店铺入驻之前，审核对象是主体资质与授权链。日常文档包括营业执照、商标注册证、品牌授权链与行业许可证，数据来源涉及平台招商页面、国家企业信用信息公示系统、商标局数据与许可证系统。资料更新不定期，每次入驻重新收集。经营报表与异常复盘在这一环要回答的问题是：某次资质问询经过了哪些对话、返回了哪些字段、哪些材料处于待补正状态。对话日志与审计承担的是记录核对，不承担资质真伪判定，也不替代平台审核结论。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份以 chatId 区分。同一应用下不同入口的会话各自独立，统计与复盘时按 chatId 归集，不把不同入口的会话合并计算。需要运行详情时，按官方契约传入 detail=true，中间值与完整结果保存在 responseData 中；stream 模式下通过 event 区分节点状态与完整响应。日志中未返回的字段不能推定已完整留存，接口实际返回什么就核对什么。测试模式与正式调用的身份字段可能不同，输入、历史与返回内容分别核对。日志存在与完成合规审计是两件事，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本。材料原文一：「营业执照：某某供应链管理有限公司，统一社会信用代码 91XXXXXX，经营范围含预包装食品销售，登记状态存续，有效期至 2030 年 3 月。」材料原文二：「商标注册证：第 12345678 号，注册人某某供应链管理有限公司，核定使用商品第 30 类，专用权期限至 2029 年 8 月。」材料原文三：「品牌授权链：品牌方授权某某供应链管理有限公司在华东区域销售，授权期限 2025 年 1 月至 2025 年 12 月，授权书未载明可转授权。」待判定的拟稿句：「该主体资质齐全，授权覆盖全国，可直接通过类目准入审核。」该拟稿句的判定只看材料原文与拟稿句本身，不引入其他记录。

## 配置怎么定

下表围绕上述样本，列出与本功能相关的官方已说明设置或实施核对项。数值为本次假设试验起点，用于比较，不作为官方默认值。

| 配置或核对项 | 假设起点 | 核对方式与理由 |
| --- | --- | --- |
| chatId 归集范围 | 本次样本单独一个 chatId | 与同应用其他入口会话比较，确认未合并 |
| detail 取值 | true | 需要运行详情时按官方契约设置，比较 responseData 是否返回 |
| stream 取值 | false | 与 stream=true 的 event 返回比较，确认取值与响应形式对应 |
| source 过滤 | api | 与页面会话比较，确认只取 API 创建的会话 |
| pageSize | 10 | 与 total 比较，确认本次样本记录落在返回列表内 |
| 反馈字段 | loadCustomFeedbacks=true | 与默认取值比较，确认自定义反馈是否随记录返回 |

## 容易做错的三处

1. 把不同入口的会话按应用合并统计。输入为同一 appId 下两个 chatId 的记录，比较对象是各自 chatId 的对话列表，观察结果是两条会话是否被分别归集。合并后无法定位具体对话。
2. 把 responseData 中未出现的字段当作已留存。输入为一次 detail=true 的响应，比较对象是 responseData 实际包含的模块字段，观察结果是拟引用的字段是否在返回中。未返回即记录缺口。
3. 把待补正材料写成资质齐全。输入为上述样本原文与拟稿句，比较对象是授权区域与授权期限，观察结果是拟稿句的区域表述与材料原文是否一致。原文写华东区域，拟稿句写全国，两者不一致。

## 怎么确认配好了

1. 输入：样本原文一至三与拟稿句。比较：拟稿句的主体、区域、期限与三份原文逐项对照。满足条件：拟稿句的区域与期限表述均能在原文中找到对应文字；出现全国或长期等原文未载明表述时判定为未获支持。
2. 输入：一次 detail=true、stream=false 的响应。比较：responseData 是否包含本次样本所需的模块字段。满足条件：所需字段在返回中可见；字段缺失时记录缺口，不推定已留存。
3. 输入：source=api 的会话列表请求与返回。比较：返回列表中的 chatId 与本次样本 chatId。满足条件：样本 chatId 出现在返回列表中，且列表未包含页面来源会话；样本未出现时记录为未命中，不推定会话不存在。
