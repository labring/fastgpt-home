# 平台退款退货处理的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

在平台退款退货处理的经营报表与异常复盘中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。退款复盘接口保留申请、退件到仓与退款到账的区别，返回缺项不能推出业务事件不存在。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

假设售后系统摘要显示申请已收，退件另有仓内登记，资金回执未包含在本次响应中。按接口契约核售后事项标识、地址及方法，再核变量输入是否来自当前事项。鉴权成功不证明资金权限或所有后台信息均已返回；本例没有真实退款金额，也不推断资金已经到账。

## 配置怎么定

| 退款复盘HTTP | 自拟材料 | 核验重点 |
| --- | --- | --- |
| 申请已收 | 仅受理记录 | 非资金到账 |
| 仓内登记 | 退件事件 | 核角色区别 |
| 回执缺席 | 响应未包含 | 不推事件不存在 |
| 变量身份 | 本次售后事项 | 逐项核传入 |
| 退款执行 | 业务系统负责 | 独立权限回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

申请已收被写退款完成时，查资金凭据；仓内登记被当买家收款时，核事件角色；响应缺回执被答没有退款时，核返回范围与其他真实来源。三处分别看状态、主体和缺证推断，不能把HTTP成功当业务成功。

## 怎么确认配好了

验收保存脱敏请求、原始响应和答复，逐句核实际字段内容及契约定义。仅有摘要时标明详情未核，调试身份字段按官方边界处理。补资金凭证后只更新相应资金结论，仓库处理和退款执行继续由业务系统及授权流程负责。 退件的仓库收件人与资金接收方分别列清，不能仅凭相近事件名称合并判断。
