# 平台退款退货处理的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样
平台退款退货处理按订单持续发生，退款申请、退货物流单、质检照片与退款审批分散在售后后台、客服聊天、WMS收货和支付退款记录中。这一特征决定经营报表与异常复盘需要把对话日志放回具体订单与具体会话中核对，不能把不同入口的会话合并统计。数据更新频率为每单、日，报表口径须与这一节奏一致。对话日志与审计在本页只解决日志层面的核对，对账、留存与合规审计由完整业务方案另行落实，日志存在不等于合规审计已经完成。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话身份需要结合 chatId 核对目标对话与业务记录。运行详情需要按官方契约设置 detail 并检查 responseData。日志与接口实际返回字段是核对依据，未返回的业务数据不能推定已完整留存。测试模式与正式调用的身份字段可能不同，需要分别核对输入、历史与返回内容。检索与表单都不构成授权，待审核不等于已批准，已提供选项不等于已执行。

假设演练样本：某平台售后专员在 2025 年 3 月 10 日处理订单 A 的退款申请，材料原文为「退款申请单号 R-0310，订单号 A，申请日期 2025 年 3 月 10 日，退款金额 120 元，退货物流单号 L-7788，质检照片两张显示外包装破损，退款审批状态为待审核」。拟稿句为「该订单退款已审批通过并完成退款」。核对时须比较审批状态字段与拟稿句表述，待审核状态不支持「已审批通过」，支付退款记录中未见该单退款完成记录，拟稿句属于未获支持。

## 配置怎么定
| 配置项 | 官方已说明设置或实施核对项 | 与本页样本的关系 |
| --- | --- | --- |
| appId | 应用详情路径获取，调用时在请求体传入 body.appId | 核对样本所属应用 |
| chatId | 非空字符串时从数据库取会话，长度小于 250 | 核对样本会话归属 |
| dataId | 会话下某一对话的 ID | 定位样本对话记录 |
| detail | 需要中间值时设为 true，非 stream 模式结果在 responseData | 核对样本运行详情 |
| offset 与 pageSize | 获取会话列表与对话列表的偏移量与记录数量 | 本次假设试验起点 offset 取 0、pageSize 取 20，与列表 total 比较以确认样本是否在范围内 |
| loadCustomFeedbacks | 读取自定义反馈的可选参数 | 核对样本反馈字段是否存在 |

## 容易做错的三处
1. 把 chatId 相同的不同入口会话合并计算。样本中 R-0310 来自 API 创建的会话，页面会话不应并入同一统计。检查方式：输入样本 chatId 与 source=api，比较返回列表是否只含 API 来源会话，观察页面会话是否被排除。
2. 把待审核状态写成已审批通过。样本审批状态字段为待审核，拟稿句写已审批通过。检查方式：输入样本拟稿句与审批状态字段，比较两者取值，观察是否存在同字段互斥取值，待审核与已审批通过属于互斥取值。
3. 把 detail 未开启时缺失的 responseData 当作日志未留存。检查方式：输入样本请求 detail=false，比较返回体中是否存在 responseData，观察缺失属于请求参数未开启，不能据此判断业务数据未留存。

## 怎么确认配好了
1. 输入样本订单 A 与 chatId，调用获取对话列表，比较返回 dataId 是否对应 R-0310 所在对话，观察列表 total 与 offset、pageSize 的关系，确认样本在返回范围内。
2. 输入样本 detail=true 与 stream=false，比较 responseData 中各元素 moduleName 与 moduleType，观察是否返回节点运行详情，确认运行详情可核对。
3. 输入样本拟稿句与审批状态字段，比较同字段取值是否互斥，观察待审核与已审批通过是否同时出现，若拟稿句与字段不一致则判定为未获支持，保留审批与退款完成的证据缺口。
