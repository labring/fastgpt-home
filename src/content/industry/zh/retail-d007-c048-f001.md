# 快递面单与揽收交接的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
快递交接发生在包裹离仓节点，核心是承运商扫描责任。经营报表与异常复盘要处理电子面单、交接清单、揽收扫描记录、异常件登记。这些材料的更新频率为每批与每日，报表口径因此按批或按日归集，不引入其他同步机制。HTTP 模块向外部地址发送请求，实际操作与 Postman、ApiFox 这类工具接近，Params 为路径请求参数，GET 请求中用的居多；Body 为请求体，POST/PUT 请求中用的居多；Headers 为请求头。三类数据与 URL 均可通过 `{{}}` 引用变量，变量来自全局变量、系统变量、前方节点输出。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories。chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于环境差异，不能当成业务故障。返回值配置代表如何解析接口返回值，通过 JSON path 语法提取，规则遵守 JS 对象取值规则，例如 key 写 `data.user.name` 取用户名。输出类型选择字符串时，会将对应 key 的值转成 json 字符串输出。HTTP 模块可对接外部服务，文档示例中按 action 的 post、delete、put、get 分别调用创建、删除、更新、查询记录，异常时返回异常标记，该示例不构成对任何具体承运商系统的承诺。

假设演练样本：仓库发运组在 2025 年 3 月 12 日白班，对 3 月 12 日 14:00 前完成的第 7 批交接，用 HTTP 模块向外部交接服务提交交接清单。供核对的材料原文为：交接清单载明“第 7 批，承运商网点 A，包裹 42 件，交接时间 2025-03-12 14:20”；揽收扫描记录载明“第 7 批，已扫描 40 件，扫描时间 2025-03-12 15:05”；异常件登记载明“第 7 批，2 件外包装破损，待网点确认，登记时间 2025-03-12 15:10”。待判定的拟稿句为：“第 7 批 42 件已全部由网点 A 揽收完成。”该拟稿句把待确认的 2 件写成已完成揽收，与扫描记录的 40 件不一致，属于未获支持的表述。

## 配置怎么定
下表围绕上述样本，只列官方已说明的设置或实施核对项。数值一栏为本次假设试验起点，需说明选取理由与比较对象，不表示官方默认值。

| 配置项 | 本次假设起点 | 核对与比较方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部交接服务文档选定地址，方法取 POST | 地址可引用变量，逐项核对实际传入值 |
| Params 与 Headers | Headers 携带 Authorization，凭证经安全配置注入 | 对照外部接口契约核对键名，不写入公开样例 |
| Body 结构 | 提交第 7 批清单，含批次、网点、件数、交接时间 | 仅在相应请求类型下生效，核对 JSON 结构与契约 |
| 变量引用 | 批次与件数来自前方节点输出 | 变量来自全局变量、系统变量、前方节点输出，逐项核对 |
| 返回值提取 | key 设为 `data.list[0].status` | 按 JSON path 提取，输出类型选字符串时转 json 字符串 |
| 调试身份字段 | chatId 与 responseChatItemId 留空 | 测试模式下二者不存在，空值不作为业务故障 |

## 容易做错的三处
1. 把待确认件数当作已完成件数。输入为样本中 42 件清单、40 件扫描、2 件待确认；比较清单件数与扫描件数；可观察结果是拟稿句与扫描记录不一致，判定为未获支持。
2. 把调试环境缺失的 chatId、responseChatItemId 当成接口异常。输入为测试模式下的空 chatId；比较文档说明的测试模式差异；可观察结果是该空值属于环境差异，不构成业务故障证据。
3. 把返回值提取配置当成接口返回本身。输入为 key 与输出类型设置；比较实际响应与提取结果；可观察结果是提取值取自转化后格式，提取失败时不能推断接口未返回数据。

## 怎么确认配好了
1. 用样本原文核对拟稿句。输入为交接清单、揽收扫描记录、异常件登记三段原文与拟稿句；比较同一批次、同一时间范围内的件数；当扫描件数与清单件数不一致且存在待确认登记时，拟稿句不满足条件，须记录为未获支持。
2. 用样本请求核对变量传入。输入为引用前方节点输出的批次与件数变量；比较请求中实际传入值与节点输出值；当两者一致且请求类型与 Body 生效条件相符时，该请求配置满足条件。
3. 用空结果核对下游设计。输入为纸面约定的空列表 `[]`；比较下游节点对空值的处理设计；当设计明确承接空结果且不产生业务动作时，该分支满足条件，实际返回仍需观察并记录。

以上核对只验证请求构造与文本判定，不执行授权、审批、数据库写入或外部系统同步，这些动作需要各自的实现。
