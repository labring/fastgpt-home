# 批发市场档口交易的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

批发市场档口交易零散，现场议价与托运并存，数据来自行情、档口库存、收款记录和托运单。日常文档包括进货单、手写销售单、摊位租赁合同和货款收据。经营报表与异常复盘要把这些材料对齐到同一主体、同一期间、同一字段，才能判断一笔货款是否结清、一批货是否发出。HTTP 接口与外部系统这一环的作用，是把外部系统返回的字段按 JSON path 取出，供报表比对，接口本身不承担授权、审批或数据库写入。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块可重复添加、手动配置、触发执行。Params 用于路径请求参数，Body 用于 POST/PUT 请求体，Headers 传递特殊信息。URL、Params、Headers、Body 均可通过 {{}} 引用全局变量、系统变量和前方节点输出。系统变量含 appId、chatId、responseChatItemId、variables、cTime、histories。chatId 与 responseChatItemId 在测试模式下不存在，调试时取不到值属于预期，不构成业务故障。返回值通过 JSON path 提取，出参格式化以 json 转字符串为主。对话接口使用 APIKey 鉴权，appId 优先级为 body.appId、<apiKey>-<appId>、apikey 关联的 appId。传入的 model、temperature 无效，由编排决定。detail=true 时 responseData 保留模块状态与完整结果。检索库同向量模型要求只约束知识库关联，不扩展到工商网站或其他外部系统。

假设演练样本：材料原文为“2025 年 3 月 12 日，档口 A 向采购商 B 发出托运单，托运单号 T-0312，货款收据 R-0312 记载金额 8600 元，状态栏写‘已收’。摊位租赁合同 Z-2025 约定租期至 2025 年 12 月 31 日。”待判定拟稿句为“B 的 8600 元货款已结清，托运已完成。”该句把收据状态与托运完成合并断言，缺少托运签收字段。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址 | 外部接口文档给出的地址 | 与接口契约逐字比对 |
| 请求方法 | 按接口文档选择 | 核对是否与文档一致 |
| Headers 鉴权 | 通过安全配置注入 | 不写入公开样例 |
| Body 结构 | 按接口契约的 JSON 字段 | 核对键名与类型 |
| 返回值提取 | JSON path 表达式 | 用样本响应验证取值 |
| 出参类型 | 字符串 | 核对是否转为 json 字符串 |

起点数值为本次假设试验所用，不作为官方默认值。

## 容易做错的三处

1. 把 chatId 或 responseChatItemId 在测试模式下的空值当成接口失败。检查方式：输入测试模式请求，比较返回字段与文档说明，观察到空值即符合预期，不判定为故障。
2. 把收据状态“已收”直接当成托运完成。检查方式：输入样本原文与拟稿句，比较收据字段与托运签收字段，发现托运签收缺失即判定拟稿句超出证据。
3. 把检索相似度当成权限或实体过滤。检查方式：输入一条无关查询，比较返回条目与授权范围，观察到相似度不排除无关记录即确认该设置不承担权限功能。

## 怎么确认配好了

1. 输入样本原文与拟稿句，比较拟稿句断言与原文载明字段，只有收据状态“已收”被支持、“托运已完成”未获支持时，判定为待核实。
2. 输入一条测试模式请求，比较 chatId 与 responseChatItemId 取值，观察到空值且接口其余字段正常，判定调试空值不构成故障。
3. 输入一条无关查询，比较返回条目与授权范围，观察到相似度未排除无关记录，记录实际观察，不推断权限结论。
