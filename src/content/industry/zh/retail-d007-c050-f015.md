# 投诉举报与监管回复的经营报表与异常复盘：知识库检索与召回

## 这个品类的数据长什么样

投诉举报与监管回复面向平台或监管机关，需要正式证据和整改文字。主要数据来源包括12315平台、平台投诉中心、客服聊天和订单系统，日常文档为投诉工单、监管询问函、订单证据和整改报告。这些材料的不定期、每案更新特征，意味着知识库检索与召回必须按个案组织，不能依赖固定周期同步。

最耗时的环节是还原交易过程、准备证据包、提交整改回复。经营报表与异常复盘要求从历史工单和回复中找出同类处理依据，检索结果直接支撑复盘结论。知识库搜索节点可关联一个或多个使用相同向量模型的知识库，这是检索的前提条件。

## 这些特征在「知识库检索与召回」这一环带来什么约束

投诉工单、监管询问函、订单证据、整改报告分别由不同角色维护，内容结构差异大。语义检索依赖向量相似度，适合自然语言问法；全文检索依赖关键词命中，适合编号、型号、专有名词。混合检索同时使用两路召回，通过RRF融合结果。引用上限以token为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，会增加一次模型调用。

检索不等于授权。知识库搜索只返回引用内容，不判断材料是否已获批准、是否可对外提交。检索结果为空时，输出链路仍然走通，引用内容长度可以为0。

假设演练样本：某店铺收到监管询问函，要求说明一笔订单的退款处理依据。知识库中存有一份投诉工单，原文为：“工单编号TS-2024-0312，投诉人主张订单A退款未到账，客服于2024年3月15日回复称退款已发起，银行处理需3至5个工作日。”另存有一份整改报告草稿，原文为：“针对TS-2024-0312，本店已核实退款记录，拟于2024年3月20日前提交银行流水凭证。”现有一条待判定拟稿句：“该投诉已处理完毕，退款已到账。”需核对拟稿句与上述材料是否一致。

## 配置怎么定

| 配置项 | 本页相关设置或核对项 | 说明 |
| --- | --- | --- |
| 关联的知识库 | 选择存放投诉工单、监管询问函、订单证据、整改报告的知识库 | 多个知识库须使用相同向量模型，否则不可共同关联 |
| 搜索模式 | 按测试问题比较语义、全文与混合检索 | 编号类查询优先全文或混合，自然语言问法优先语义或混合 |
| 引用上限 | 以token为单位，用长短不同的实际资料测试内容完整性 | 本次假设试验起点设为2000 token，理由为单份整改报告通常较长，与500 token起点比较内容是否被截断 |
| 最低相关度 | 仅在语义检索或使用结果重排时生效 | 先标注相关与无关样本，再调整阈值，本次假设起点0.4，与0.6比较过滤效果 |
| 问题优化 | 用于指代消除和问题扩展 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 需具备ReRank模型并按设置启用 | 重排后得到0至1得分，可根据得分过滤 |

## 容易做错的三处

1. 把检索命中当作授权执行。输入为“TS-2024-0312 退款到账”，检索返回投诉工单原文，该原文只记录客服回复“退款已发起”，未记录到账。比较拟稿句“退款已到账”与工单原文，两者状态不一致。可观察结果为拟稿句中的“已到账”在工单中无对应记载，属于未获支持。

2. 跨不同向量模型的知识库共同关联。输入为两个知识库标识，其中一个使用不同向量模型。核对标识后发现不满足相同向量模型条件，应排除不符合者，不执行跨模型检索来比较漏召回。

3. 把最低相关度当作权限或实体过滤器。输入为一条与投诉无关的查询，设置最低相关度0.4。该值仅过滤低相关度结果，不排除无关业务或未授权记录。可观察结果为检索仍可能返回其他业务的相似文本，需人工核对引用内容是否属于本案范围。

## 怎么确认配好了

1. 输入假设样本中的工单原文和拟稿句“该投诉已处理完毕，退款已到账”。比较拟稿句与工单原文中“退款已发起，银行处理需3至5个工作日”的记载。满足条件为：检索返回工单原文，且拟稿句中的“已到账”被识别为与原文状态不一致，记录为待核实。

2. 输入假设样本中的整改报告草稿原文和查询“TS-2024-0312 整改提交时间”。比较检索结果是否包含“拟于2024年3月20日前提交银行流水凭证”。满足条件为：全文检索或混合检索命中该句，引用内容完整保留日期和对象。若返回空数组，则按空结果核对下游设计，不声称虚构规则一定返回空。

3. 输入两个知识库标识，其中一个使用不同向量模型。比较两个标识对应的向量模型是否相同。满足条件为：确认不相同后排除不符合者，记录实际观察，不继续执行跨模型检索，也不推断漏召回或冗余结果。
