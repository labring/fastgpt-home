# 拼多多低价活动店铺运营的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

低价活动店铺的经营数据围绕活动资源位、活动库存与退款率波动展开，主要来源包括拼多多商家后台、活动资源位数据、ERP 库存与物流签收数据。日常文档为活动报名表、商品成本测算表、售后退款单与平台站内信。本页只处理经营报表与异常复盘环节中的 HTTP 接口与外部系统对接，不延伸至报名审批或库存扣减执行。更新频率为日或每场活动，接口核对按此节奏逐场进行。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 用于路径参数，Body 用于 POST/PUT 请求体，Headers 传递鉴权等信息。变量可来自全局变量、系统变量与前方节点输出，URL 与三类数据均可通过 `{{}}` 引用变量。返回值通过 JSON path 提取，输出类型选字符串时会将对应 key 的值转为 json 字符串。对话接口使用 APIKey 鉴权，调用 `chat/completions` 时推荐在请求体传入 `body.appId`；chatId 非空时自动从数据库取会话，messages 最后一个内容作为用户问题。detail=true 时中间值保存在 responseData。检索库的同向量模型要求仅约束知识库共同关联，不扩展到外部业务系统。

假设演练样本：某活动店铺运营人员持有 2024 年 10 月 12 日签收的一批低价活动订单，物流签收数据记录签收数量 480 件，ERP 库存表记录该批次出库 500 件。待判定拟稿句为“签收数据与出库数据一致，异常复盘可结案”。该句涉及同一批次、同一期间的两个数量字段，需先核对主体与字段口径。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址引用已提供变量 | 与外部接口契约逐字比对路径与方法 |
| Headers 鉴权 | 通过安全配置注入凭证，样例不写入 | 核对凭证来源是否为已授权配置 |
| Body 结构 | 按接口契约声明 JSON 字段 | 与外部接口文档字段表逐项比对 |
| 变量引用 | 逐项核对实际传入值 | 与全局变量、系统变量、前方节点输出对照 |
| 返回值提取 | 按 JSON path 配置 key | 与接口响应示例结构比对 |
| 调试身份字段 | chatId 在测试模式下不存在 | 区分测试空值与业务故障，不当作异常 |

## 容易做错的三处

1. 将签收数量 480 与出库数量 500 直接判为矛盾。两字段口径不同，差异属未获支持，需先确认是否含退货或补发。
2. 把测试模式下 chatId 不存在当作会话丢失。该字段在测试模式本就不存在，应记录为环境差异。
3. 将检索相关度分数当作权限或实体过滤依据。相关度只反映相似程度，不承担授权判断。

对应检查：输入上述两个数量字段，比较批次与期间是否一致，观察是否同主体同期间；输入测试模式请求，比较 chatId 返回情况，观察是否为空；输入检索结果，比较分数字段，观察是否被误用为过滤条件。

## 怎么确认配好了

- 第一，输入假设样本中 480 与 500 两个数量，比较批次标识与日期范围，若主体、对象、期间一致而字段口径不同，判定为待核实，不判为矛盾。
- 第二，输入拟稿句“签收数据与出库数据一致，异常复盘可结案”，比较该句与两份原始记录，若原文未载明一致结论，判定为未获支持。
- 第三，输入一条测试模式请求，比较 chatId 与 responseChatItemId 的返回状态，若为空则记录为测试环境差异，不触发业务处置。以上均为纸面核对，未实际执行。
