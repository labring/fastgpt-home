# 渠道窜货稽查的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

窜货稽查围绕区域与价格秩序展开，处理对象是防伪码记录、电商平台价格、经销商发货记录与市场巡检材料，不涉及返利金额核算。日常文档包括窜货投诉单、防伪码记录、处罚通知与调查照片，更新频率为周及不定期。经营报表与异常复盘需要把这些材料按投诉单、货源码、店铺价格、处罚状态逐项归集，HTTP 接口承担向外部防伪码系统、价格监测服务或内部处罚台账发起请求并解析返回值的职责。材料分散在多个外部系统，接口层需要明确每次请求对应哪份投诉单、哪段货源码范围、哪次巡检批次。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 用于路径请求参数，Body 用于请求体，Headers 用于传递特殊信息，三者均可通过 `{{}}` 引用变量，URL 同样可以引用变量。变量来源为全局变量、系统变量与前方节点输出。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于调试环境特征，不能据此判定外部系统故障。返回值配置的是解析规则，通过 JSON path 从响应中提取需要的值，输出类型选择字符串时会把对应 key 的值转成 json 字符串。接口调用本身不构成授权，也不完成处罚执行或数据库写入。

假设演练样本：某品牌渠道管控团队收到一份窜货投诉单，原文为「投诉单号 TS-2024-0317，被投诉经销商为华东区 A 经销商，涉及防伪码区间 HZ-0001 至 HZ-0200，投诉人提供的电商店铺链接显示售价低于区域指导价，巡检照片拍摄日期为 2024 年 3 月 15 日，投诉单当前状态为待核实」。另有一条待判定的交接请求拟稿句：「请 HTTP 接口调用防伪码系统查询上述区间，返回结果直接写入处罚通知并同步至经销商台账。」该拟稿句把查询、处罚通知生成与台账同步合并为一次请求，处罚通知与台账写入均无对应授权依据，属于待核实事项。

## 配置怎么定

下表围绕上述样本，列出与本页主任务相关的核对项。数值为本次假设试验起点，仅用于纸面对比，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址 | 按外部防伪码系统文档填写，地址中引用投诉单号变量 | 与外部接口文档逐字符比对路径与方法 |
| Headers 鉴权 | 通过安全配置注入凭证，不写入公开样例 | 核对请求头字段名与凭证来源，确认未硬编码 |
| Body 结构 | 仅在该请求类型生效时填写，含防伪码区间与投诉单号 | 与外部接口契约比对字段名与嵌套层级 |
| 变量引用 | 引用前方节点输出的投诉单号与货源码区间 | 逐项核对实际传入值与样本原文一致 |
| 返回值解析 | 按 JSON path 提取查询状态与码段记录 | 用样本区间核对提取结果与响应结构对应 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 确认调试空值不进入业务判定 |

## 容易做错的三处

1. 把 HTTP 查询返回的码段记录直接当作处罚依据。输入为样本投诉单与查询响应，比较查询结果与处罚通知所需字段，观察是否存在处罚决定字段；查询结果只反映码段信息，处罚通知需要另行确认授权与流程。
2. 把调试模式下 chatId 为空判定为外部系统异常。输入为测试模式请求，比较系统变量可用范围，观察 chatId 与 responseChatItemId 是否缺失；缺失属于文档说明的调试特征。
3. 把拟稿句中的台账同步视为已执行。输入为上述交接请求拟稿句，比较请求内容与实际授权状态，观察是否存在同步动作的授权记录；拟稿句只表达请求意图，不构成执行事实。

## 怎么确认配好了

1. 取样本投诉单原文与 HTTP 请求配置，比较请求地址、Body 中防伪码区间与投诉单号是否与原文一致，观察请求内容是否只包含查询所需字段，不包含处罚通知或台账写入字段。
2. 取样本响应结构与返回值解析配置，比较 JSON path 提取结果是否对应查询状态与码段记录，观察提取值是否落在 HZ-0001 至 HZ-0200 范围内；范围外结果需要记录为待核实。
3. 取上述交接请求拟稿句，比较拟稿句所述动作与可确认的授权状态，观察处罚通知生成与台账同步是否有对应授权材料；无授权材料时记录为未获支持，保留证据缺口。
