# 特许加盟备案管理的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
特许加盟备案管理的数据围绕法律披露与商务部门系统展开，与总部选址开店处理的铺位工程事项不同。主要数据来源包括商业特许经营信息管理系统、企业证照、门店清单与合同台账，日常文档为特许经营合同、操作手册、备案材料与信息披露文件。数据更新频率为不定期或按年，本页功能不依赖该频率，故不展开同步机制。最耗时的环节是准备备案材料、核对两店一年条件、更新加盟信息。经营报表与异常复盘因此需要把合同台账、门店清单与备案材料的状态汇总为可核对的记录，HTTP 接口承担向外部系统取数或送数的通道角色。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params 为路径请求参数，Body 为请求体，Headers 为请求头，三者均可通过 {{}} 引用全局变量、系统变量或前方节点输出。返回值通过 JSON path 语法提取，输出类型选择字符串时会将对应 key 的值转为 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试期这两项为空属于已知条件。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，appId 优先级为 body.appId、<apiKey>-<appId>、apikey 关联的 appId。detail=true 时返回中间值，非 stream 模式结果保存在 responseData，stream 模式通过 event 区分。检索或表单收集数值，业务核验、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：某特许人总部法务在年度复盘时，持有一份纸面材料，原文为「加盟商甲于备案年度内提交门店清单一份，合同台账显示该合同状态为已签署，信息披露文件回执未见。」待判定的拟稿句为「加盟商甲已完成备案信息更新」。该样本用于核对拟稿句是否超出材料所载状态，不涉及任何真实主体或编号。

## 配置怎么定
配置围绕该样本的核对需求设定，仅列官方已说明的设置或实施核对项。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址与方法 | 按外部系统文档给定的地址与方法 | 地址可引用变量，需与外部接口契约逐项核对 |
| Headers 鉴权 | Authorization 头承载凭证，值由安全配置注入 | 与公开样例分离，核对注入值是否与目标系统匹配 |
| Body 结构 | 仅在对应请求类型下启用，按 JSON 结构填写 | 与外部接口契约比较字段名与层级 |
| 变量引用 | 引用全局变量、系统变量或前方节点输出 | 逐项核对实际传入值，测试模式下 chatId 为空属已知 |
| 返回值提取 | 按 JSON path 语法配置 key | 与接口响应示例比较提取路径与输出类型 |
| 状态核对 | 人工比对材料所载状态与拟稿句 | 同主体、同期间、同一字段才构成矛盾判定 |

## 容易做错的三处
1. 将合同台账的「已签署」直接当作备案信息更新完成。输入是台账状态字段，比较对象是备案材料回执，若回执缺失则拟稿句未获支持，不能判定为已完成。
2. 把测试模式下 chatId 与 responseChatItemId 为空当作业务故障。输入是调试请求，比较对象是文档说明的测试模式条件，空值属于已知情形，不构成异常。
3. 将检索返回的相似度分值理解为权限或实体过滤结果。输入是 score 与 similarity 字段，比较对象是授权边界，分值不承担排除无关业务或未授权记录的功能，检索不构成授权。

## 怎么确认配好了
1. 针对样本原文「合同台账显示该合同状态为已签署，信息披露文件回执未见」与拟稿句「加盟商甲已完成备案信息更新」，输入为这两段文字，比较对象是材料所载字段与拟稿句断言，只有回执等支持材料在同一主体、同一期间、同一字段上明确载明更新完成，拟稿句才满足条件；当前材料仅支持合同已签署，拟稿句未获支持。
2. 针对请求配置，输入为按外部文档填写的地址、方法与 Body，比较对象是外部接口契约，仅当字段名、层级与请求类型一致时满足条件；测试模式下 chatId 为空按文档说明处理，不记为失败。
3. 针对返回值提取，输入为接口响应与配置的 key，比较对象是 JSON path 提取结果与输出类型，仅当提取值与响应示例中对应路径一致时满足条件；空结果可用明确的纸面输入 [] 核对下游设计，不声称虚构规则检索必然返回空。
