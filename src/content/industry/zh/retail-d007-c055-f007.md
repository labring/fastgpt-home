# 特许加盟备案管理的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

特许加盟备案管理处理法律披露与商务部门系统，不处理具体铺位工程。主要数据来源包括商业特许经营信息管理系统、企业证照、门店清单和合同台账。日常文档涉及特许经营合同、操作手册、备案材料、信息披露文件。这些材料的主体是特许人总部、加盟法务、商务主管对接人。出错后果为被责令备案、加盟合同争议、行政处罚。

经营报表与异常复盘在这一品类中，需要把对话日志与审计落到具体材料核对上。备案材料与信息披露文件的版本、门店清单的更新时点、合同台账的签署状态，都会影响复盘结论。对话日志记录的是系统交互过程，不直接等于备案材料已提交或合同已生效。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话日志与审计围绕特许经营合同、操作手册、备案材料、信息披露文件展开。系统提供对话接口的运行详情获取能力：设置 detail=true 后，非流式响应中 responseData 保存模块状态与完整结果，流式响应通过 event 区分。detail=true 时 responseData 内可出现 moduleName、moduleType、runningTime、tokens、quoteList、completeMessages 等字段。对话 CRUD 提供会话列表、对话列表、单条对话运行详情、反馈更新等接口，分别使用 appId、chatId、dataId、contentId 等标识。

这些能力用于核对目标对话与业务记录，不把不同入口的会话混算。日志存在不等于完成合规审计；对账、留存与合规要求由完整业务方案另行落实。检索或表单收集值不构成授权执行。交互节点返回的 interactive 是展示配置，表单收集值后继续运行仍需按接口再次发起会话。

假设演练样本

材料原文一：「特许人甲于2024年3月1日与加盟商乙签署《特许经营合同》，合同编号 HZ-2024-031，约定区域为某市某区，有效期三年。」

材料原文二：「2024年4月10日，甲向商务主管部门提交备案材料，材料清单含合同副本、操作手册、信息披露文件，受理状态为待审核。」

拟判定句：「甲已完成备案，合同已生效，乙可在该区域开店。」

判定：材料原文二显示受理状态为待审核，待审核不构成备案完成；材料原文一显示合同已签署，签署不构成合同生效；开店授权未在材料中载明。该拟判定句三项事实均未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| detail | true | 需要运行详情时按官方契约设置，与 detail=false 的响应结构比较 |
| stream | false | 便于直接读取 responseData，与 stream=true 的 event 区分方式比较 |
| chatId | 假设演练样本会话标识 | 核对目标对话，与不同入口会话的 chatId 比较 |
| dataId | 假设演练样本对话标识 | 定位单条对话运行详情，与同会话其他 dataId 比较 |
| loadCustomFeedbacks | true | 读取自定义反馈，与不传该参数时的返回比较 |
| source | api | 获取通过 API 创建的会话，与页面会话来源比较 |

以上数值为本次假设试验起点，非官方默认值。appId 优先级按文档为 body.appId、apiKey-appId、apikey 关联的 appId。

## 容易做错的三处

1. 把待审核当作备案完成。输入为材料原文二的受理状态「待审核」，比较对象为「已完成」含义，观察结果是状态字段取值不同，判定为未获支持。
2. 把合同签署当作合同生效。输入为材料原文一的签署事实，比较对象为生效条件，观察结果是材料未载明生效条款，判定为待核实。
3. 把表单收集值当作授权执行。输入为交互节点 inputForm 收集的字段值，比较对象为授权边界，观察结果是表单仅收集值，判定为不构成授权。

## 怎么确认配好了

1. 输入假设演练样本的拟判定句，比较材料原文一与原文二的记载，观察拟判定句三项事实是否均有材料支持。三项均未获支持时，判定句不成立。
2. 输入 chatId 与 dataId，调用单条对话运行详情接口，比较返回的 responseData 字段与材料记载，观察 moduleType、runningTime 等是否与目标对话对应。字段缺失时记录缺口。
3. 输入 loadCustomFeedbacks=true，比较返回的 customFeedbacks 与业务记录，观察反馈内容是否指向同一 dataId。无法对应时保留未核实状态。
