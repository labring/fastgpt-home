# 特许加盟备案管理的经营报表与异常复盘：知识库检索与召回

## 这个品类的数据长什么样

特许加盟备案管理处理法律披露与商务部门系统事项，不涉及具体铺位工程。主要资料来自商业特许经营信息管理系统、企业证照、门店清单与合同台账。日常文档包括特许经营合同、操作手册、备案材料与信息披露文件。这些材料的更新不定期，部分按年推进。经营报表与异常复盘需要从上述文档中核对主体、对象、状态与有效范围，检索环节只负责把候选内容带回，不承担授权判断。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的库。不同向量模型的库不能共同关联，需先核对库标识并排除不符合者，不执行跨模型检索来比较漏召回。搜索模式按测试问题分别比较语义检索、全文检索与混合检索，不预设一种模式适合全部资料。引用上限以 token 为单位，需用长短不同的实际资料测试内容是否完整。最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除与问题扩展，需比较原问题与优化后问题，核对主体是否被改错。混合检索经 RRF 融合多路结果，重排须具备模型且按设置启用，图片检索须有相应图像输入及模型能力。检索结果不构成授权，也不隔离业务实体。

假设演练样本：某特许人总部法务在经营异常复盘中，需核对一份加盟合同台账记录。材料原文为：“甲方某某餐饮管理有限公司与乙方某某加盟商于二〇二三年五月签订特许经营合同，合同编号为 HZ-2023-0512，约定备案材料由甲方于签约后三十日内提交。截至二〇二四年一月，台账登记状态为‘备案材料待提交’。”待判定拟稿句为：“该合同已完成商务部门备案。”该句与材料原文在备案状态字段上取值互斥，属未获支持。

## 配置怎么定

| 配置项 | 本页假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅关联使用同一向量模型的备案材料库与合同台账库 | 先核库标识，排除不同向量模型的库 |
| 搜索模式 | 对编号类问题用全文检索，对状态描述类问题用混合检索 | 按测试问题分别比较命中内容 |
| 引用上限 | 本次假设试验起点设为 3000 token | 用长短不同的备案材料段落比较内容完整性 |
| 最低相关度 | 本次假设试验起点设为 0.4 | 先标注相关与无关样本，再比较过滤结果 |
| 问题优化 | 对含指代的追问开启，对完整问题关闭 | 比较原问题与优化后问题的主体是否一致 |
| 结果重排 | 候选较多且具备重排模型时启用 | 比较重排前后候选顺序与得分 |

## 容易做错的三处

1. 把不同向量模型的库共同关联。输入为两个库标识，比较其向量模型标识，若不一致则排除，记录实际观察，不推测运行结果。
2. 把最低相关度当作权限或实体过滤。输入为无关业务问题，比较返回内容是否仍可能包含其他主体资料，确认该参数只过滤低相关度结果。
3. 把检索命中当作备案已完成。输入为上述拟稿句与材料原文，比较备案状态字段，原文为“待提交”，拟稿句称“已完成”，判定为未获支持。

## 怎么确认配好了

1. 输入假设样本中的材料原文与拟稿句，比较备案状态字段取值，若原文为“待提交”而拟稿句称“已完成”，则判定该拟稿句未获支持，保留证据缺口。
2. 输入合同编号 HZ-2023-0512 作全文检索，比较返回内容是否包含该编号所在段落，若返回结果为空，记录空结果并核对数据是否已完成训练。
3. 输入含指代的追问，比较原问题与优化后问题的主体，若优化后主体与材料原文不一致，则记录问题优化改错主体的现象，不据此断定检索失败原因。
