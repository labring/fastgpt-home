# 生产企业免抵退税的经营报表与异常复盘：知识库检索与召回

## 这个品类的数据长什么样
生产企业免抵退税把内销税额抵减与退税合并计算，这一特征使经营报表与异常复盘需要同时核对内销、外销与进项三类数据。主要数据来自电子税务局、ERP销售、海关电子信息和财务账，日常文档包括免抵退税申报明细表、出口合同、销售明细账、出口报关单。数据按月更新，复盘时须锁定同一所属期，把申报明细表、销售明细账与报关单逐项对齐，任何跨期或跨主体拼接都会让异常定位失真。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的库，跨不同向量模型的库不能共同关联，须先核对向量模型标识并排除不符合者。搜索模式按测试问题比较语义、全文与混合检索，没有一种模式适合全部资料。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，须比较原问题与优化后问题，核对主体是否被改错。检索与相似度不承担权限或实体隔离，召回结果不构成授权。

假设演练样本：某生产企业税务会计在复盘2025年7月所属期时，拟在检索框输入“免抵退税申报明细表里免抵退税额与销售明细账出口销售额对不上，是什么原因”。待判定拟稿句为：“检索命中申报明细表条款即说明该月免抵退税额计算正确，可直接提交更正申报。”该请求涉及主体为生产企业，对象为所属期2025年7月的申报明细表与销售明细账，状态为待核对，授权边界为仅限内部复盘，不含提交或更正申报。

## 配置怎么定
| 配置或核对项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 关联一个向量模型标识一致的免抵退税库 | 先核标识，排除不同向量模型的库，不执行跨模型检索 |
| 搜索模式 | 混合检索 | 与语义检索、全文检索分别跑同一问题，比较命中内容 |
| 引用上限 | 假设起点设为覆盖一份申报明细表片段所需 token | 以长短不同的实际资料测试内容完整性，再调整 |
| 最低相关度 | 假设起点取中间值 | 先标注相关与无关样本，再比较过滤效果 |
| 问题优化 | 开启，比较原问题与优化后问题 | 核对主体与所属期是否被改写 |
| 输出引用内容 | 以数组核对，长度可以为0 | 空结果链路仍走通，下游按空数组设计 |

## 容易做错的三处
1. 把检索命中当作税额计算正确的证据。输入为上述拟稿句，比较对象是申报明细表与销售明细账的同一字段，观察结果是两份材料未显示同一字段的互斥取值，该拟稿句未获支持。
2. 把不同向量模型的库强行共同关联。输入为两个库的向量模型标识，比较两者是否一致，观察结果是标识不同即排除，不比较漏召回。
3. 把待审核的更正请求当成已执行。输入为该请求的状态字段，比较状态与执行记录，观察结果是缺少执行证据，只能记为待核实。

## 怎么确认配好了
1. 输入假设样本拟稿句，比较检索返回的引用内容与申报明细表原文，观察引用是否含主体、所属期与字段名；若引用为空数组，记录为未命中，不判定为无此规则。
2. 输入同一问题分别走语义检索与全文检索，比较两路命中内容是否覆盖申报明细表编号与销售明细账金额字段，观察哪一路更完整，据此决定是否改用混合检索。
3. 输入原问题与问题优化后问题，比较两者主体与所属期是否一致，观察优化后是否把“2025年7月”改写成其他期间；若被改写，记录为需人工修正检索词，不据此认定申报数据错误。
