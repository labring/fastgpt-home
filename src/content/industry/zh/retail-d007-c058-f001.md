# 生鲜供应商索赔的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

在生鲜供应商索赔的经营报表与异常复盘中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。索赔复盘中的资料接收、供应商意见与处理结果分别引用，HTTP可读不表示已认可。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

自拟查询正文写计量资料已收、供应商意见待回，附件目录仅列本批照片，未有处理结论。HTTP节点衔接实际数据源时，应核本批、陈述方与附件实际可读内容，不能把目录名称当照片已经完整返回。接收资料没有认可责任，意见未回也不证明拒绝。报表可整理现有证据和缺口，不能从同一供应商历史事项补本批结果。

## 配置怎么定

| 索赔报表读取 | 自拟记录 | 所需检查 |
| --- | --- | --- |
| 资料接收 | 计量材料已收 | 非责任认可 |
| 供应商意见 | 待回复 | 不推拒绝 |
| 附件目录 | 本批照片名称 | 核实际内容 |
| 历史事项 | 另批结论 | 不串用 |
| 正式执行 | 独立权限与凭证 | 读取不结项 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

收件冒认可时，核供应商原回复；目录冒附件正文时，核实际返回内容；旧事项结果进入本批时，对批次与事项身份。三处分别查陈述含义、资料覆盖和对象，不能由响应可解析替代。

## 怎么确认配好了

验收比较契约约定的返回类型、原始正文和答复引用，未返回附件应保留缺证。补意见后只更新本事项对应表述。认证、材料访问和正式索赔处理权限各自核，读取不发函、不结项，赔付或其他执行需要真实业务凭证。
