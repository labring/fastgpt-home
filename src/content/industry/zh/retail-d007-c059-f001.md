# 生鲜冷链到店验收的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

冷链到店验收围绕温度记录、到货验收单、拒收单和供应商送货单展开，数据来源包括冷链车温控、WMS、门店收货系统和质检照片。每批到货都要测量温度、抽检品质、登记拒收原因，日更频率意味着接口每天要承接多批次的记录写入与状态回传。

经营报表与异常复盘需要把验收结果、拒收原因和温控读数汇总成可追溯的记录。HTTP 模块向外部地址发送请求，请求参数、请求头、请求体均可引用全局变量、系统变量和前方节点输出。返回值通过 JSON path 提取，出参可格式化为字符串。这些能力决定报表数据能否从验收现场流入复盘视图。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

验收数据写入外部系统时，接口地址和方法按外部接口文档选择，地址可引用已提供的变量。请求头用于传递鉴权信息，凭证通过安全配置注入。请求体只在相应请求类型下生效，JSON 结构须与外部接口契约一致。变量引用逐项核对实际传入值，避免把未赋值的调试字段当成业务数据。

对话接口中，chatId 与 responseChatItemId 在测试模式下不存在，调试空值属于环境差异，不构成业务故障。传入的 model、temperature 等字段由编排决定，不随 API 参数改变。检索或表单收集值不等于业务授权，验收放行、拒收确认、供应商结算仍需下游系统按其规则执行。

假设演练样本：某生鲜仓配主体有一份纸面材料，原文为“2025年3月12日，冷链车C-07到店，车厢温度记录为6.8℃，门店收货员在到货验收单上登记该批次叶菜抽检合格，供应商送货单编号SD-0312。”另有一条待判定拟稿句：“该批次已完成验收放行，可进入结算。”材料只记录温度读数与抽检登记，未载明放行审批或结算授权。判定该拟稿句时，比较对象是材料原文的登记状态与拟稿句声称的放行、结算状态，主体、批次、日期须一致。

## 配置怎么定

下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，非官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址 | 引用外部验收接口地址变量 | 地址来自外部接口文档，核对变量是否已赋值 |
| 请求方法 | POST | 验收记录写入采用请求体，与外部契约一致 |
| 请求头鉴权 | Authorization 引用 token 变量 | 凭证经安全配置注入，核对请求头键值 |
| 请求体字段 | 批次号、温度、验收状态 | 与送货单、验收单字段逐项比对 |
| 返回值提取 | 按 JSON path 取验收状态字段 | 核对提取键与实际响应结构 |
| 出参格式 | 字符串 | 便于下游文本加工拼接复盘描述 |

## 容易做错的三处

1. 把调试环境缺失的 chatId 或 responseChatItemId 当作业务故障。测试模式下这两个字段不存在，输入是调试请求，比较对象是正式会话字段，观察结果是调试响应中无对应值，需记录为环境差异。
2. 把表单收集的验收登记当作放行授权。输入是到货验收单的抽检登记，比较对象是放行审批记录，观察结果是材料未载明审批字段，判定为未获支持。
3. 把检索返回的相似记录当作权限过滤结果。输入是检索请求，比较对象是目标记录的访问权限，观察结果是相似度不承担权限判断，需另行核对授权范围。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句，比较材料登记状态与拟稿句声称的放行、结算状态，主体、批次、日期一致时，拟稿句仍因缺少审批证据而判定为未获支持。
2. 输入一条引用变量地址的请求配置，比较请求头鉴权键值与安全配置，观察请求头中 token 已注入且地址变量已赋值，满足条件。
3. 输入空结果 `[]` 作为纸面承接，比较下游复盘视图对空列表的处理设计，观察下游未将空结果渲染为验收完成，满足条件。
