# 生鲜冷链到店验收的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

生鲜冷链到店验收围绕冷链车温控、WMS、门店收货系统与质检照片展开，日常文档为冷链温度记录、到货验收单、拒收单、供应商送货单。与水果采购相比，这一品类关注运输温度与到货批次，不负责产地询价。数据按每批与每日更新，出错会带来食材变质、供应商争议与监管处罚，因此经营报表与异常复盘需要把对话日志中的请求、返回与业务单据逐项对齐。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话接口以 appId、chatId、dataId 组织会话与对话记录。chatId 非空时，FastGPT 自动从数据库取会话，并以 messages 数组最后一个内容作为用户问题，其余 message 被忽略；chatId 不传入时，不使用上下文功能，完全通过 messages 构建上下文。responseChatItemId 传入后会作为本次响应消息 ID 存入数据库，需在当前 chatId 下保持唯一。detail=true 时返回中间值与完整结果，非 stream 模式保存在 responseData，stream 模式通过 event 区分。对话 CRUD 提供会话列表、对话列表、单个对话运行详情、反馈与删除接口，source=api 只取通过 API 创建的会话，清空应用会话只清空 API Key 创建的会话。运行详情里的 moduleName、moduleType、runningTime、tokens、quoteList 等字段反映节点执行情况，未返回的业务数据不能推定已完整留存。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本

材料原文一（到货验收单摘录）：门店 A 于 3 月 12 日收到冷链车批次 L-0312，到货验收单记录温度为 2 摄氏度，质检员签字确认抽检合格。

材料原文二（拒收单摘录）：同日另一批次 L-0313 因温度记录缺失，门店 A 开具拒收单，状态为待供应商确认。

待判定拟稿句：「门店 A 于 3 月 12 日收到的两个批次均已验收合格。」

## 配置怎么定

| 配置项 | 取值或核对方式 | 说明 |
| --- | --- | --- |
| appId | 请求体传入或由 APIKey 关联 | 用于定位应用，与 chatId 配合核对目标对话 |
| chatId | 非空字符串，长度小于 250 | 使用数据库会话，最后一个 message 作为用户问题 |
| responseChatItemId | 当前 chatId 下唯一 | 作为响应消息 ID 存入数据库 |
| detail | true 或 false | true 时返回中间值，非 stream 保存于 responseData |
| source | api | 会话列表只取通过 API 创建的会话 |
| dataId | 从对话列表获取 | 用于查询单个对话运行详情 |

本次假设试验起点将 detail 设为 true，理由是需要核对 responseData 中的节点字段；比较对象为 detail=false 时缺失的中间值，不将该起点描述为官方默认值。

## 容易做错的三处

1. 把 chatId 为空时的请求与 chatId 非空时的请求混入同一会话统计。检查方式：输入两条请求，一条不传 chatId、一条传入 chatId，比较返回的会话归属与历史内容，观察两者是否被分别记录。
2. 将 responseChatItemId 在不同 chatId 下重复使用。检查方式：输入同一 responseChatItemId 与两个不同 chatId，比较返回的存储结果，观察是否出现覆盖或异常。
3. 依据 quoteList 的 score 推断检索已排除无关业务记录。检查方式：输入一条查询，比较返回的 quoteList 与业务单据主体，观察 score 高低与记录归属是否对应。

## 怎么确认配好了

1. 输入假设样本中的到货验收单与拒收单原文，比较拟稿句「两个批次均已验收合格」与两份材料，观察拒收单中 L-0313 状态为待供应商确认，拟稿句未获支持。
2. 输入 detail=true 与 detail=false 两次请求，比较返回结构中 responseData 是否存在，观察 detail=true 时出现节点响应字段、detail=false 时该字段缺失。
3. 输入 chatId 为空与 chatId 非空两次请求，比较返回的历史内容，观察 chatId 非空时使用数据库会话、为空时不使用上下文功能。空结果承接可用纸面输入 [] 核对下游展示设计，不声称检索一定返回空数组。
