# 生鲜称重分拣的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
称重分拣发生在仓内履约环节，核心数据是重量与规格，来源包括 WMS、电子秤、订单系统和质检照片。经营报表与异常复盘要处理分拣任务单、称重标签、少称补偿单和质检记录。少发带来赔付，毛利损耗和顾客差评随之出现。这些材料按每单和按日更新，接口取数时须区分单据主体、单据状态和有效范围。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向目标地址发送请求，Params、Headers 和 Body 均可通过 {{}} 引用全局变量、系统变量或前方节点输出，URL 同样可以引用变量。返回值通过 JSON path 提取，输出类型选字符串时会把对应 key 的值转为 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>。传入的 model、temperature 等字段无效，由编排决定。测试模式下 chatId 与 responseChatItemId 不存在。检索结果的相关度分数不承担权限或实体隔离职责，检索本身不构成授权。

假设演练样本：某前置仓 2025 年 6 月 18 日分拣任务单 A-0618-07 记载，对象为 500 克规格西兰花两份，分拣员已称重并贴标，质检主管尚未复核。少称补偿单 B-0618-03 记载顾客反馈少称 80 克，状态为待审核。拟稿句为“A-0618-07 已完成质检复核，B-0618-03 的补偿已执行”。该拟稿句与原文不符：任务单只记录贴标，复核未完成；补偿单只有待审核状态。

## 配置怎么定
下表围绕上述样本，列出官方已说明的设置或实施核对项。数值为本次假设试验起点，用于比较，不作为官方默认值。

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写 | 比对地址、方法与文档契约 |
| Params 与 Headers | Authorization 引用凭证变量 | 核对请求头取值与鉴权方式 |
| Body | 按接口契约写 JSON 结构 | 比对字段结构与外部接口 |
| 变量引用 | 引用单据号与状态变量 | 逐项核对实际传入值 |
| 返回值提取 | 按 JSON path 配置 key | 比对提取值与响应结构 |
| 调试身份字段 | chatId 为空时视为测试模式 | 核对是否存在，不判为业务故障 |

## 容易做错的三处
1. 把待审核状态写成已执行。样本中 B-0618-03 为待审核，拟稿句写补偿已执行，输入是补偿单状态字段，比较对象是原文状态，可观察结果是两者不一致。
2. 把贴标写成复核完成。样本中 A-0618-07 只记录贴标，拟稿句写已完成质检复核，输入是任务单记录，比较对象是复核字段，可观察结果是原文未载明复核。
3. 把检索或表单当作授权执行。样本中检索到单据不表示具备复核权限，输入是检索结果，比较对象是授权边界，可观察结果是缺少授权记录。

## 怎么确认配好了
1. 输入样本原文与拟稿句，比较拟稿句中的复核结论与任务单 A-0618-07 的记录，当拟稿句出现原文未载明的复核完成表述时，判定为未获支持。
2. 输入少称补偿单 B-0618-03 的状态字段，比较“待审核”与“已执行”，当两者取值互斥时，判定为矛盾，须保留待核实。
3. 输入一条明确纸面空结果 []，比较下游设计对空值的承接方式，当输出未把空结果当作授权或执行成功时，判定为符合预期。
