# 电商仓入库上架的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

电商仓入库上架处理货物进入仓库的第一道账实确认，数据来源包括 WMS、ERP 采购、供应商送货单与条码扫描。日常文档为采购到货单、入库验收单、上架任务与差异报告，更新频率为每批与每日。经营报表与异常复盘要回答的问题，是到货数量、验收结论、上架库位与差异原因能否在外部系统之间对齐。HTTP 接口在这一环承担把入库上架结果送往外部报表或异常系统的通道，外部系统的返回值决定复盘口径能否闭环。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 用于路径请求参数，Body 用于 POST/PUT 请求体，Headers 用于传递特殊信息，三者均可通过 `{{}}` 引用变量，URL 同样可以引用变量。变量来源为全局变量、系统变量与前方节点输出。系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories，其中 histories 默认最多取 10 条且无法修改长度；chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 语法提取，输出类型选择字符串时会把对应 key 的值转成 json 字符串。对话接口使用 APIKey 鉴权，推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>；传入的 model、temperature 等字段无效，由编排决定。detail=true 时返回中间值，responseData 中可查看模块状态与完整结果。

假设演练样本：某电商仓 WMS 管理员在 2025 年 3 月 10 日整理 3 月 9 日到货批次 A-0310 的入库上架复盘。材料原文为：采购到货单载明供应商送货 120 件，WMS 收货扫描记录 118 件；入库验收单载明验收结论为“短少 2 件，待供应商确认”；上架任务记录 118 件已分配至库位 B-07。拟稿句为“本批次到货 120 件已全部上架，无差异”。待判定请求为：把该拟稿句作为异常复盘说明，通过 HTTP 接口提交至外部报表系统。

## 配置怎么定

| 配置项 | 本次假设设置 | 核对说明 |
| --- | --- | --- |
| 请求地址与方法 | 按外部报表接口文档选择地址与方法 | 地址可引用已提供的变量，方法须与外部契约一致 |
| Headers 鉴权 | Authorization 使用 Bearer 引用 token 变量 | 凭证通过安全配置注入，不写入公开样例 |
| Body 结构 | 按外部接口契约组织 JSON，引用复盘字段变量 | 按外部契约与请求方法核对 Body，逐项核对实际传入值 |
| 返回值提取 | 按 JSON path 配置 key 与输出类型 | 输出字符串时转成 json 字符串，供下游文本加工使用 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 调试空值不作为业务故障判定依据 |
| 运行详情 | detail=true 时查看 responseData 中模块状态 | 用于核对节点实际运行情况，不替代业务确认 |

## 容易做错的三处

1. 把供应商送货数量直接当作已上架数量。样本中采购到货单为 120 件，WMS 收货扫描为 118 件，验收结论为短少 2 件待确认，上架任务为 118 件。拟稿句写“120 件已全部上架，无差异”，与验收单和上架任务记录不一致。检查方式：取采购到货单、验收单、上架任务三份材料，按同一批次 A-0310 比较数量字段，观察三处数值是否一致。
2. 把待供应商确认当作差异已关闭。验收单状态为“待供应商确认”，属于未完成状态。拟稿句写“无差异”，把待确认当成已确认。检查方式：读取验收单结论字段，比较其状态词与拟稿句的差异描述，观察状态是否仍处于待确认。
3. 把 HTTP 提交成功当作业务已确认。HTTP 状态码为 200 不能单独证明外部报表系统已采纳复盘结论，仍需核对响应内容与业务确认记录。检查方式：比较接口响应中的 code 与业务侧确认记录，观察是否存在独立于接口返回的确认凭据。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较采购到货单 120 件、WMS 收货扫描 118 件、上架任务 118 件与验收单“短少 2 件，待供应商确认”。若拟稿句仍写“120 件已全部上架，无差异”，则该句与材料不一致，不得作为复盘说明提交。预期为识别出数量与状态两处不一致。
2. 输入样本的待判定请求，比较拟稿句中的“已全部上架”与上架任务记录的 118 件。若上架任务仅记录 118 件，则“全部上架”未获材料支持。预期为标记该表述待核实，保留短少 2 件的证据缺口。
3. 输入 HTTP 请求配置，比较请求体字段与外部报表接口契约，观察返回值提取的 key 是否对应实际响应结构。若响应中不存在所配置的 key，则提取结果为空，需记录该缺口并核对接口契约，不推断为业务无差异。
