# 电商仓入库上架的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样
入库上架处理货物进入仓库的第一道账实确认，主要数据来源为 WMS、ERP 采购、供应商送货单与条码扫描，日常文档包括采购到货单、入库验收单、上架任务与差异报告。这些材料按每批和每日更新。经营报表与异常复盘需要把对话日志与这些单据对齐，才能判断某次差异讨论是否对应同一批到货。对话日志本身不是库存凭证，日志存在不代表账实已经核清。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话接口以 appId 标识应用，以 chatId 标识一个应用下的会话，以 dataId 标识一个会话下的对话。核对时必须用同一 chatId 与 dataId 定位，不能把不同入口的会话混算。需要运行详情时按官方契约设置 detail，并检查 responseData 中的模块响应；未返回的业务字段不能推定已完整留存。检索结果中的 similarity 与 score 是召回相关度，不构成权限或实体隔离，检索到某条记录不等于该记录已获授权使用。

假设演练样本：某电商仓 2026 年 3 月 12 日一批采购到货，采购到货单载明“供应商甲，物料 A，应收 200 件”，入库验收单载明“实收 198 件，差异 2 件待核实”，上架任务载明“物料 A 上架 198 件，库位 B-01”。同日在 chatId 为 C-0312 的会话中，操作员提交一条拟稿交接请求：“本批差异 2 件已确认由供应商补发，请按 200 件结账。”该请求未附供应商确认回复，也未附任何审批记录。此样本仅用于纸面核对。

## 配置怎么定
下表只列与本功能、本任务相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设取值 | 选择理由与比较方法 |
| --- | --- | --- |
| appId | 假设为入库上架应用标识 | 用于定位目标应用，与请求中实际传入值比较 |
| chatId | C-0312 | 用于定位会话，与单据日期批次的会话标识比较 |
| detail | true | 需要运行详情时按契约设置，检查 responseData 是否返回 |
| stream | false | 便于一次性读取响应，与流式返回逐事件读取方式比较 |
| dataId | 待从对话列表取得 | 用于定位具体对话，与获取到的记录逐条比较 |
| loadCustomFeedbacks | true | 读取自定义反馈，与记录中实际反馈字段比较 |

本次假设取值为纸面演练起点，非官方默认值，也未实际调用。

## 容易做错的三处
1. 把检索命中的记录当作已获授权使用。输入为一次带 score 的检索结果，比较该结果与授权范围记录，观察是否出现未授权记录被当作可用依据。
2. 把待核实差异写成已确认结论。输入为上述拟稿句，比较其“已确认由供应商补发”与验收单“待核实”表述，观察结论是否超出材料支持。
3. 混用不同 chatId 或 dataId 的对话。输入为两次不同会话的记录，比较其标识字段，观察是否被并入同一批差异复盘。

## 怎么确认配好了
1. 输入上述采购到货单、入库验收单、上架任务原文与拟稿句。比较拟稿句结论与三份材料载明的数量与状态。仅当材料中出现供应商确认补发且数量一致时，该结论才获支持；样本中未出现，属未获支持。
2. 输入 chatId C-0312 与取得的 dataId，比较返回记录中的会话与对话标识是否一致。仅当标识逐项对应时，才确认定位到同一对话；标识不符时记录为待核实。
3. 输入 detail=true 的请求，比较响应中是否出现 responseData 及其模块字段。仅当字段实际返回时才可引用；未返回的字段记录为未知，不推定已留存。
