# 直播选品与样品质检的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

选品质检发生在开播之前，判断对象是商品能否上播、展示是否合规。主要材料包括样品评估表、质检报告、供应商资质与禁售清单，来源覆盖供应商资料、检测机构报告、平台负面目录与历史退货率。典型角色为选品经理、供应链BD与质检专员，出错会带来翻车退货、虚假宣传认定与平台处罚。这些材料按周和每品更新，日常核对量大，对话日志与审计要处理的是这些材料在会话中如何被引用、如何被留痕。

## 这些特征在「对话日志与审计」这一环带来什么约束

审计对象是对话本身，不是质检结论。会话由 chatId 标识，对话由 dataId 标识，运行详情通过对话接口的 detail 参数获取。detail=false 时只返回最终回答；detail=true 时中间值与完整结果进入 responseData，stream 模式下以 event 区分。文档说明不会返回实际消耗 Token 值，需要时设置 detail=true 并手动计算 responseData 里的 tokens。日志存在不表示已完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某选品经理在会话中提交一份样品评估表原文，内容为“样品编号 SP-0417，供应商为示例供应链公司，评估结论为待复检，评估日期为 2025 年 4 月 17 日”。同一会话内另有一条拟交接句：“该样品已通过质检，可安排上播。”供核对的材料原文只写明待复检，未出现通过结论。该拟交接句与原文在结论字段上取值互斥，属于未获支持。待复检状态不证明缺少上播操作权限，也不表示质检已通过。

## 配置怎么定

| 配置项 | 类型 | 本页用途 |
| --- | --- | --- |
| appId | 应用标识 | 核对会话归属的应用，避免跨应用混算 |
| chatId | 会话标识 | 定位目标会话，长度小于 250，需自行保证唯一 |
| dataId | 对话标识 | 定位具体对话记录，用于运行详情核对 |
| detail | 布尔 | 需要中间值时设为 true，检查 responseData |
| stream | 布尔 | 决定 event 区分方式，影响中间值读取路径 |
| loadCustomFeedbacks | 布尔 | 获取对话列表时决定是否读取自定义反馈 |

以上均为文档已说明字段。本页不指定任何默认数值，不设置全局开关。

## 容易做错的三处

1. 把 detail=false 的返回当作完整运行记录。detail=false 只返回最终回答，中间模块状态与完整结果不出现。可执行检查：同一 chatId 与 dataId 下，分别以 detail=false 与 detail=true 请求，比较返回中是否出现 responseData，缺失即为未获取。
2. 把 chatId 与 dataId 混用。chatId 标识会话，dataId 标识对话。可执行检查：用样本中的 chatId 与 dataId 调用获取单个对话运行详情，比较返回记录是否对应同一对话，错配即为标识混用。
3. 把待复检读成已通过。样本原文结论为待复检，拟交接句写已通过。可执行检查：将拟交接句与原文结论字段逐字比较，取值互斥即为未获支持，不判定为否定或冲突。

## 怎么确认配好了

1. 输入样本中的 chatId 与 dataId，以 detail=true 请求运行详情，比较返回是否含 responseData 及节点记录。出现对应记录即满足读取条件；未出现则记录缺口，不推断原因。
2. 输入样本原文与拟交接句，比较结论字段取值。原文为待复检、拟句为已通过，属同字段互斥取值，判定为未获支持。
3. 输入同一 chatId 下的对话列表请求，比较返回的 dataId 是否与样本一致。一致即定位正确；不一致则记录为标识不符，不执行后续判定。

检索或表单收集不构成授权，待审核不证明缺少操作权限。相似度分值不承担权限或实体隔离功能。跨不同向量模型的库不可共同关联，先核标识并排除不符合者。空结果可用明确的纸面输入核对下游设计，不声称虚构规则检索必然返回空。
