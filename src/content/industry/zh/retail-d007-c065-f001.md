# 直播间违规申诉的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
直播间违规申诉针对已经发生的处罚，需要复盘证据链。主要材料来自平台违规中心、直播回放、客服记录和商品资质库，日常文档包括违规通知、直播录屏、商品资质和申诉说明。数据更新不定期，每次违规触发一轮材料整理。最耗时的环节是定位违规片段、补充证据和撰写申诉理由。经营报表与异常复盘环节需要把上述材料通过 HTTP 接口送入外部系统，并保留可核对的请求与响应记录。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params、Headers、Body 均可通过 `{{}}` 引用全局变量、系统变量和前方节点输出，URL 同样可以引用变量。返回值通过 JSON path 提取，输出类型选择字符串时会将对应 key 的值转为 json 字符串。对话接口使用 APIKey 鉴权，调用 `chat/completions` 时推荐在请求体传入 `body.appId`，也支持 `Authorization: Bearer <apiKey>-<appId>`。`chatId` 与 `responseChatItemId` 在测试模式下不存在，测试空值不构成业务故障。检索与相似度不承担权限或实体隔离职责，检索结果不能当作授权凭据。

假设演练样本：某店铺合规人员于 2026 年 3 月 10 日收到一份违规通知，原文写“2026 年 3 月 8 日 20:15 至 20:22 的直播回放中，商品 A 的讲解片段出现资质表述与商品资质库登记不一致，现对该商品采取禁播处理，申诉期为通知送达后 5 个工作日”。同批材料含该时段直播录屏链接和商品 A 的资质文件。待判定拟稿句为“商品 A 的资质表述不一致已整改完毕，申请解除禁播”。该拟稿句声称整改完毕，材料中只有违规通知、录屏和资质文件，没有整改记录或复核结论，该主张未获支持。

## 配置怎么定
| 配置项 | 本次设定 | 核对方式 |
| --- | --- | --- |
| 请求地址 | 外部申诉系统地址，按对方接口文档填写 | 与接口文档逐字比对路径与方法 |
| Headers | `Authorization` 引用已配置的鉴权变量 | 核对变量来源与注入位置，不写入公开样例 |
| Body | 按对方接口契约构造 JSON，字段引用前方节点输出 | 核对字段名、类型与嵌套结构 |
| 变量引用 | 引用全局变量、系统变量和前方节点输出 | 逐项核对实际传入值 |
| 返回值提取 | 按 JSON path 提取所需字段，输出类型按用途选择 | 用样本响应核对提取结果 |
| 调试身份字段 | `chatId` 与 `responseChatItemId` 在测试模式下不存在 | 测试模式下记录空值，不判定为业务故障 |

## 容易做错的三处
1. 把检索结果或相似度分数当成授权凭据。检索返回的是内容匹配，不判断材料是否具备申诉资格，也不判断操作人是否有权提交。
2. 把拟稿句中的“整改完毕”当成已核实事实。样本材料只有违规通知、录屏和资质文件，没有整改记录或复核结论，该主张属于未获支持。
3. 在测试模式下把 `chatId` 或 `responseChatItemId` 缺失判定为接口故障。文档说明这两个字段在测试模式下不存在，需区分调试空值与业务异常。

## 怎么确认配好了
1. 输入样本中的违规通知原文、录屏链接和资质文件，比较拟稿句“商品 A 的资质表述不一致已整改完毕，申请解除禁播”与材料范围。材料未载明整改记录或复核结论，该拟稿句属于未获支持，不应作为已核实事实提交。
2. 输入样本中的违规通知原文，比较其中“2026 年 3 月 8 日 20:15 至 20:22”的时段与录屏链接指向的时段。两者一致时，时段核对通过；不一致或录屏未覆盖该时段时，记录为待核实。
3. 在测试模式下发起一次请求，比较返回中 `chatId` 与 `responseChatItemId` 是否存在。两者缺失时，按文档说明记录为测试模式下的正常现象，不判定为接口故障；若需确认业务会话，改用非测试模式并核对实际返回值。
