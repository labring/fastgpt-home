# 直播间违规申诉的经营报表与异常复盘：工作流编排

## 这个品类的数据长什么样

在直播间违规申诉的经营报表与异常复盘中，本页说明FastGPT的工作流编排如何衔接资料。直播申诉报告应把通知覆盖、材料准备和处理结果分开，流程不能把待回复条目计作已经解决。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟报告草稿列通知、准备说明和待回复事项，却把材料已汇集放入处理完成部分。可收各段原句及涉及直播场次，由人员选择核材料范围或补实际结果；流程应传递这些分类依据，不从文件名生成完成结论。录像片段只覆盖通知中的部分事件时，报告要保留未覆盖项，不能因申诉说明写完而将其一并转成已处理。

## 配置怎么定

| 申诉报告流程 | 自拟条目 | 本次核法 |
| --- | --- | --- |
| 准备部分 | 材料已汇集 | 不列处理完成 |
| 录像覆盖 | 只含部分事件 | 与通知逐项对应 |
| 场次身份 | 资料可能来自他场 | 核原文及接收 |
| 人员路径 | 核范围或补结果 | 输入带对应事项 |
| 结果变化 | 只补某事件回复 | 其他条目仍待核 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

备料冒解决：若材料汇集被写成处理完成，应取真实处理回复；片段扩范围：若局部录像支持全部通知，应核片段内容与通知事件；场次串档：若另一场说明进入本报告，应查原始场次和下游接收。三项分别核状态、证据覆盖和业务对象，不能由报告标题相同省略。

## 怎么确认配好了

验收分别沿核范围与补结果路径查看实际输入，保留报告条目仍缺哪些来源。补入某事件处理回复后，只更新该事件，未覆盖录像或其他待回复仍留缺项。正式申诉、外部状态查询和报告发布需要另接实际步骤核权限及回执；本次输出只说明材料怎样组织，不证明平台已认可或全部事项已经关闭。
