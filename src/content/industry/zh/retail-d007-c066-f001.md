# 短视频挂车分销运营的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
短视频挂车分销以内容长期曝光和商品链接转化为主，不依赖实时讲解，因此经营报表与异常复盘所需的原始记录分散在精选联盟、短视频播放数据、商品成交数据和平台规则中，更新频率为日、周。日常需要处理的文档包括短视频脚本、挂车商品清单、佣金计划和违规反馈。这些材料决定报表口径与异常范围，接口层只负责把外部系统返回的记录取回并交给后续节点解析，不承担授权判断。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params 用于路径参数，Body 用于请求体，Headers 用于请求头，三者均可通过 `{{}}` 引用全局变量、系统变量和前方节点输出，URL 同样可以引用变量。系统变量包括 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在，调试时取到空值属于该模式的正常表现。返回值配置的是如何解析接口响应，按 JSON path 提取，输出类型选择字符串时会把对应 key 的值转成 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>；BaseUrl 是否需要补 v1 视调用方而定，出现 404 时可补充 v1 重试。authProxy 代理团队成员身份需要团队所有者在创建或编辑 key 时开启，代理身份仍需要具备目标应用和会话权限。传入的 model、temperature 等参数字段无效，由编排决定。detail=true 时中间值保存在 responseData，stream 模式下通过 event 区分。

假设演练样本：某内容运营在 2025 年 6 月 3 日整理一份挂车商品清单，材料原文为“商品 A 挂车视频于 6 月 1 日发布，佣金计划状态为待审核，违规反馈栏为空”。拟交接请求句为“商品 A 的佣金计划已生效，可计入本周经营报表”。本样本仅用于核对接口取回字段与交接表述是否一致，不代表任何真实业务动作。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档填写，地址引用前方节点输出 | 与接口文档给出的路径和方法逐字符比较 |
| Headers 鉴权 | Authorization 使用 Bearer 形式，凭证由安全配置注入 | 与密钥使用规范中的两种鉴权方式比较 |
| Body 结构 | 按外部接口契约写 JSON，字符串变量加引号 | 与文档中 Body 声明示例的引号规则比较 |
| 返回值提取 | 按 JSON path 配置 key 与输出类型 | 与接口响应示例的字段路径比较 |
| 变量来源 | 逐项标注全局变量、系统变量或前方节点输出 | 与系统变量说明列表比较 |
| 调试身份字段 | 测试模式下 chatId 与 responseChatItemId 为空 | 与正式调用时的非空取值比较 |

上述起点为本次假设试验所用，不是官方默认值。

## 容易做错的三处
1. 把待审核状态写成已生效。样本原文写明佣金计划状态为待审核，拟稿句却写“已生效”，输入是同一商品同一字段，比较对象是材料原文的状态取值，观察结果是拟稿句与原文取值不一致。
2. 把测试模式下的空 chatId 当成业务故障。输入是测试模式返回的空值，比较对象是系统变量说明中 chatId 在测试模式下不存在的条件，观察结果是该空值符合文档描述，不构成故障证据。
3. 把 HTTP 取回记录当成授权结果。输入是接口返回的商品记录，比较对象是业务侧授权状态字段，观察结果是取回记录本身不携带授权结论，需另接系统实现核验。

## 怎么确认配好了
1. 取样本原文“佣金计划状态为待审核”，与拟稿句“已生效”逐字比较。同主体、同期间、同一字段出现互斥取值时判定为表述冲突；原文未载明生效时间或审批结论时，记录为待核实，不判定为否定。
2. 在测试模式发起一次请求，观察 chatId 与 responseChatItemId 的返回值。与系统变量说明比较，两者为空符合文档条件；正式调用时应传入非空 chatId，并在当前 chatId 下保持 responseChatItemId 唯一。
3. 用纸面输入 `[]` 核对下游对空结果的处理设计，观察下游是否按空列表分支处理。该核对只验证空结果承接逻辑，不声称任何检索规则必然返回空数组；若接口实际返回非空记录，记录实际观察值并保留待核实项。
