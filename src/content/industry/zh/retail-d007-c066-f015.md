# 短视频挂车分销运营的经营报表与异常复盘：知识库检索与召回

## 这个品类的数据长什么样

短视频挂车分销以内容长期曝光和商品链接转化为主，不依赖实时讲解。精选联盟、短视频播放数据、商品成交数据与平台规则构成主要数据来源，日常需要处理的文档包括短视频脚本、挂车商品清单、佣金计划与违规反馈。这些材料在经营报表与异常复盘中承担核对依据的角色，检索环节需要把脚本、清单、计划与反馈中的主体、对象、状态和有效范围准确召回，供人工比对。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联。检索输出以数组格式返回引用内容，长度可以为 0，未搜索到内容时输出链路仍走通。语义检索、全文检索与混合检索按测试问题比较，不预设一种模式适合全部资料。最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，需核对主体是否被改错。检索与相似度得分不承担授权或实体隔离职责。

假设演练样本：材料原文为“2025年3月1日至3月31日，达人A的挂车视频V-017使用佣金计划P-203，佣金比例按计划载明值执行；计划P-203在3月20日处于待审核状态。”待判定拟稿句为“达人A在3月全月按P-203完成佣金结算。”该请求涉及同一主体、同一期间与同一字段的核对。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅关联使用相同向量模型的脚本库与计划库 | 核验向量模型标识一致后再关联，排除标识不符者 |
| 搜索模式 | 先按全文检索测试含编号的拟稿句 | 编号、型号类问题适合全文检索，再与语义检索结果比较 |
| 引用上限 | 起点设为覆盖一条完整计划条款的 token 量 | 用长短不同的实际资料测试内容是否完整，再调整 |
| 最低相关度 | 起点设为中间值，仅语义检索或重排时生效 | 先标注相关与无关样本再调阈值，比较过滤前后结果 |
| 问题优化 | 对含指代的短问题开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型且按设置启用时开启 | 比较重排前后候选顺序，观察得分是否用于过滤 |

## 容易做错的三处

1. 把检索得分当作权限过滤。输入为达人A的拟稿句，比较对象为返回的引用内容，若返回了其他达人的计划条款，说明检索未承担实体隔离，需人工排除。
2. 把待审核状态当作已生效。输入为材料原文中“3月20日处于待审核状态”，比较对象为拟稿句“全月按P-203完成佣金结算”，若拟稿句未标注待审核范围，判定为未获支持。
3. 把跨向量模型的库强行共同关联。输入为两个向量模型标识不同的库，比较对象为节点关联配置，若标识不一致仍尝试关联，应排除不符者并记录实际观察。

## 怎么确认配好了

1. 输入材料原文与拟稿句，比较拟稿句是否与原文同主体、同期间、同字段。若拟稿句把待审核状态写成已完成结算，判定为未获支持，需保留证据缺口。
2. 输入含编号的拟稿句，分别在全文检索与语义检索下观察返回引用。若全文检索命中计划编号而语义检索未命中，记录两种模式的差异，不保证首条命中。
3. 输入明确纸面空结果[]核对下游设计，观察引用内容数组长度为 0 时输出链路是否走通。若下游仍要求继续处理，记录该分支并核对下游设计，不声称虚构规则检索一定返回空数组。
