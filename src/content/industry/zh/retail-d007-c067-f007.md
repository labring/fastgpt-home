# 社区团购团长运营的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

团长运营管理社区节点与佣金，不直接承担冷链质检，日常材料集中在团长协议、佣金表、提货清单与社群公告。经营报表与异常复盘需要把对话记录同这些业务材料对齐：同一团长、同一提货批次、同一佣金期间的记录才具备可比性。数据来源包括社区团购后台、团长社群、订单明细与售后记录，更新频率为日、每团，因此核对时先确认记录所属日期与团点范围。对话日志在本任务中承担的是留痕与追溯角色，日志存在本身不构成对账完成或合规审计完成。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份需要结合 chatId 核对目标对话与业务记录，不同入口的会话不能混算。需要运行详情时，按官方契约设置 detail 并检查 responseData；字段含义以接口实际返回为准，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，应分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，检索与表单收集值不构成授权执行。

假设演练样本：团长协议原文为“甲方委托乙方在指定社区开展团购推广，乙方按有效订单计提佣金，协议有效期至本年度末”。佣金表原文为“6 月 1 日至 6 月 30 日，团点 A 有效订单 120 单，佣金比例 5%”。待判定拟稿句为“团点 A 六月佣金已结清”。判定所需资料为同主体、同期间、同字段的结算凭证，该凭证未提供，因此该句未获支持。

## 配置怎么定

| 配置项 | 取值或核对项 | 说明 |
| --- | --- | --- |
| chatId | 假设演练中设为团点 A 六月对话标识 | 用于核对目标对话，不跨入口混算 |
| detail | 假设演练中设为 true | 需要运行详情时按官方契约设置 |
| responseData | 检查其中模块字段 | 字段以实际返回为准，未返回不推定留存 |
| 会话来源 source | 假设演练中设为 api | 区分 API 创建会话与页面会话 |
| 结算凭证 | 假设演练中作为待补材料 | 未提供时拟稿句保持未获支持 |
| 佣金比例 | 假设演练起点 5% | 取自样本佣金表原文，用于与结算凭证比较 |

## 容易做错的三处

1. 把不同入口的会话合并计算。输入为页面会话与 API 会话的 chatId，比较是否属于同一团点同一期间，观察到的现象是两段记录被当作同一对话统计。
2. 把检索结果当成授权。输入为一次查询返回的团长记录，比较该记录是否带有可执行的授权状态，观察到的现象是把可检索误认为可结算。
3. 把待审核当成已批准。输入为佣金表的待审核标记，比较是否存在同期间的结算凭证，观察到的现象是把待审核写成已结清。

## 怎么确认配好了

1. 输入假设样本中的团长协议、佣金表原文与拟稿句，比较拟稿句是否具备同主体、同期间、同字段的结算凭证，观察到凭证缺失时拟稿句维持未获支持。
2. 输入团点 A 六月对话的 chatId 与另一入口会话的 chatId，比较两者是否指向同一团点同一期间，观察到分属不同入口时分别记录，不合并统计。
3. 输入佣金表中的待审核标记，比较是否存在同期间的结算凭证或批准记录，观察到仅有待审核标记时记录为待核实，不写成已批准或已完成。
