# 社区团购预售集单的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
预售集单先收订单再组织采购履约，经营报表要同时覆盖预售商品表、集单结果、采购计划与截单通知。数据来源包括小程序订单、供应商库存、团长反馈与仓配排线，更新频率为日或每场。报表与异常复盘落在 HTTP 接口与外部系统这一环，意味着数值来自外部返回，核对对象是请求与响应，缺少的字段保持未知。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向对应地址发送请求，Params 为路径请求参数，Body 为请求体，Headers 为请求头，三者均可通过 `{{}}` 引用全局变量、系统变量与前方节点输出，URL 也可引用变量。系统变量含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 chatId 与 responseChatItemId 在测试模式下不存在。返回值通过 JSON path 提取，输出类型选择字符串时转为 json 字符串。对话接口使用 APIKey 鉴权，调用 chat/completions 时推荐在请求体传入 body.appId，也支持 Authorization: Bearer <apiKey>-<appId>。传入的 model、temperature 等参数无效，由编排决定。detail=true 时非 stream 结果保存在 responseData，stream 模式通过 event 区分。HTTP 模块可对接外部 API，也用于操作数据库、调用外部数据源等，属于需另接系统实现的业务动作。

假设演练样本：某平台运营在 2025 年 6 月 10 日复盘 6 月 9 日一场预售，材料原文为“截单通知：6 月 9 日 20:00 截单，集单结果共 1200 单，其中缺货 30 单”“采购计划：按 1200 单下采，6 月 10 日到仓”。待判定拟稿句为“本场缺货退款 30 单已完成”。该句只与集单结果的缺货数量同字段，退款完成状态在材料中未载明，属于未获支持。

## 配置怎么定
下表只列与本页样本相关的官方已说明设置或实施核对项，数值为本次假设试验起点并注明理由。

| 配置项 | 本次假设起点 | 核对方法 |
| --- | --- | --- |
| 请求方法 | POST | 与外部接口文档比对，确认该接口使用 POST |
| 请求地址 | 含 `{{BaseUrl}}` 的路径 | 核对 BaseUrl 与路径拼接后是否指向目标服务 |
| Headers | Authorization: Bearer `{{token}}` | 核对鉴权凭证由安全配置注入，不写入公开样例 |
| Body | 含 `{{appId}}` 的 JSON | 仅在相应请求类型下使用，核对 JSON 结构与外部契约 |
| 返回值提取 | `data.list` | 按 JSON path 提取，核对输出类型与字段路径 |
| 调试身份字段 | chatId 为空 | 测试模式下 chatId 不存在，不把空值当业务故障 |

## 容易做错的三处
1. 把材料中“缺货 30 单”直接写成“退款 30 单已完成”。输入是集单结果的缺货数量，比较对象是退款完成状态，两者字段不同，材料未载明退款状态，该拟稿句属于未获支持。
2. 在测试模式下把 chatId 为空当成会话丢失。输入是测试模式请求，比较对象是 chatId 是否存在，文档说明测试模式下 chatId 不存在，空值属于预期现象。
3. 在 Body 中引用字符串变量时漏写引号。输入是 `{{string}}`，比较对象是最终解析结果，文档要求字符串引用加 `""`，漏写会导致解析结构不符。

## 怎么确认配好了
1. 输入假设样本材料原文与拟稿句“本场缺货退款 30 单已完成”，比较缺货数量字段与退款状态字段，只有材料同时载明退款完成状态时该句才获支持，当前观察结果为未获支持。
2. 输入一条测试模式请求，比较 chatId 取值，文档说明测试模式下 chatId 不存在，观察到 chatId 为空时符合预期，不判定为业务故障。
3. 输入含字符串变量的 Body 声明，比较最终解析结果，文档要求字符串引用加 `""`，观察到解析后字符串类型正确时满足条件，类型不符时记录为待核实。
