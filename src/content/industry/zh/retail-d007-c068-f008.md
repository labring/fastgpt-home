# 社区团购预售集单的经营报表与异常复盘：工作流编排

## 这个品类的数据长什么样

在社区团购预售集单的经营报表与异常复盘中，本页说明FastGPT的工作流编排如何衔接资料。预售复盘中的登记、集单和供应确认有不同对象，流程要保留截单范围与实际确认范围的差别。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟复盘摘录写需求已汇总，采购计划待确认，水果追加项未列入原截单说明。流程可收这些原句，人员选择核追加范围或补供应确认，不将汇总动作写成订单履约。报告若讨论某轮预售，应把对应通知与清单一起传入；前轮已经结束不能补出本轮状态，采购计划文件存在也不能说明供应商已接受。

## 配置怎么定

| 预售复盘流程 | 自拟摘录 | 对应核法 |
| --- | --- | --- |
| 需求汇总 | 已合并 | 非供应确认 |
| 采购计划 | 待处理 | 另取真实回复 |
| 水果追加 | 不在原通知 | 保留待核范围 |
| 预售轮次 | 本轮与前轮分开 | 核材料归属 |
| 结果更新 | 只补某项来源 | 不同时改全部状态 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

汇总冒确认：若需求合并被写成供应已定，应取供应商真实回复；追加被抹除：若水果进入报告却未留其待核性质，应对照通知与实际输入；轮次串用：若前轮结果填入本轮，应核材料所指与接收文本。三项分别核供应立场、范围差异及事件身份，不从定稿报告反推。

## 怎么确认配好了

验收让追加核对与供应补证分别接收对应项，补本轮水果说明后只更新范围，不顺带确认供应。供应回复若仅表示收到需求，仍要保留待处理阶段。正式采购、客户通知与预留库存需要另接实际业务记录，流程输出不证明预售已执行，也不提供达成或转化效果结论；未知状态应留在报告，旧材料不能补出本次结果。
