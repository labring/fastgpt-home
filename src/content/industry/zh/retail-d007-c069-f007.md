# 经销商返利核算的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

在经销商返利核算的经营报表与异常复盘中，本页说明FastGPT的对话日志与审计如何衔接资料。返利复盘按对话身份追查合同前提、发货记录和签收缺口，日志不自行核算或认可返利。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

自拟合同片段把处理条件指向另份确认，发货摘要只有发出记录，签收材料尚缺。复盘应先用chatId核目标对话与本期事项，再检查实际输入及历史引用，不能把上期已结讨论用于本期。需要运行详情时按官方契约核detail与responseData，但返回字段存在不证明条件确认或签收材料已读到。这里没有真实金额和核算结果。

## 配置怎么定

| 返利复盘日志 | 本题资料 | 核对动作 |
| --- | --- | --- |
| 对话身份 | 本期事项 | 核chatId对应 |
| 合同前提 | 另份确认尚缺 | 对实际输入 |
| 发货摘要 | 仅发出 | 非签收 |
| 历史期间 | 上期结果另列 | 不串用 |
| 正式处理 | 核算审批另接 | 业务凭据 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

合同前提被遗漏却答达成时，查输入原句；他期历史结果串入时，核事项期间；发货摘要被当签收时，核事件与实际凭据。三处分别看条件、历史归属和业务阶段，不由日志完整推结论完整。

## 怎么确认配好了

验收保存脱敏对话定位、当前输入与原始返回，分开比较调试和正式请求。缺失材料不能由运行详情参数补出。对账、核算和正式返利处理需业务规则及回执，日志回看只提供核对链，不确认款项或审批。 另份确认的文件身份单列，便于后续补齐时核对它是否真正覆盖本期；仅同名文件不能证明条件已满足。
