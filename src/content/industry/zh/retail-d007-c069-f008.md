# 经销商返利核算的经营报表与异常复盘：工作流编排

## 这个品类的数据长什么样

在经销商返利核算的经营报表与异常复盘中，本页说明FastGPT的工作流编排如何衔接资料。返利报告整理应区分政策适用、达成材料和双方确认，不从表格齐全推出已经核算或入账。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟报告附政策原句、渠道达成表和未确认对账稿，结论却写全部已处理。流程可收适用期间与渠道说明，交人员选择核政策范围或补双方确认；这里只整理来源，不填写金额和比例，也不代财务核算。达成表的编制完成不证明政策适用，红字资料出现也不能单独证明本次返利处理，原文所指必须随输入保留。

## 配置怎么定

| 返利报告整理 | 本题自拟材料 | 所需依据 |
| --- | --- | --- |
| 政策适用 | 期间与渠道限定 | 不合并不适用项 |
| 达成材料 | 编制完成 | 不代表核算成立 |
| 对账草稿 | 单方未确认 | 补真实双方回复 |
| 相关单据 | 不能单证处理 | 另查本次结果 |
| 流程承接 | 期间渠道随输入 | 缺项继续列明 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

范围混并：若不适用渠道被放进政策结论，应核渠道与适用原句；编制冒确认：若单方对账稿变成双方认可，应取本期真实确认；单据冒入账：若相关资料被当已处理，应查本次实际账务结果。三项分别核适用、立场和执行，文件齐名不能补出业务关系。

## 怎么确认配好了

验收比较两条处理路径接收的期间与渠道，补范围说明后看报告有没有只修正适用解释。确认或处理结果仍缺时，应继续列待核，不因某张资料加入就关闭。正式核算、凭证处理和报告对外发布需要另接实际步骤核权限及回执；节点有输出不证明返利应得、账已处理或所有交易均已对平。
