# 跨境商品合规与标签的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

跨境商品合规的核心证据产生在上架与进口之前，围绕产品测试报告、英文标签、MSDS 与平台禁售清单展开。资料更新不定期，随每次上新触发，因此同一款商品在不同目的国的要求可能分属不同批次的文档。经营报表与异常复盘要处理的，是把这些材料与对话记录对齐，确认某次询问、某次交接所处的实际状态。合规出错会带来下架、扣货与索赔，日志留存本身不构成合规审计。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话接口以 chatId 标识一个应用下的会话，dataId 标识会话下的某条对话。detail 为真时返回中间值与完整结果，非流式保存在 responseData，流式通过 event 区分。会话列表接口带 source 参数，source=api 只取通过 API 创建的会话，不取页面会话。清空应用会话同样只清空 API Key 创建的会话。这些边界说明：日志存在不等于全部入口的记录都在同一集合内，跨入口混算会失真。检索结果里的 score 是相似度，不承担权限或实体过滤。

假设演练样本（纸面，非实测）：某合规专员持有一份材料原文，写有「产品：便携式充电宝；目的国：德国；测试报告编号 TR-2024-0117，签发日期 2024 年 3 月；标签语言：英文；状态：报告已签发，德文标签待补」。另一份交接请求写道：「该商品德文标签已补齐，请按合规完成归档。」待判定点：交接请求所述状态与材料原文是否同一主体、同一字段。

## 配置怎么定

| 核对项 | 设置或动作 | 判定依据 |
| --- | --- | --- |
| 会话范围 | 请求体传 appId 与 chatId，列表接口 source=api | 只覆盖 API 创建的会话 |
| 运行详情 | detail=true，非流式读 responseData，流式读 event | 中间值与完整结果按此返回 |
| 响应标识 | 传 responseChatItemId，当前 chatId 下唯一 | 与 dataId 对应关系可核对 |
| 材料字段 | 逐字比对产品、目的国、报告编号、签发日期、标签语言、状态 | 同主体同字段才可比较 |
| 状态判定 | 待补与已补齐为互斥取值 | 无补齐凭证即待核实 |
| 假设起点 | 以样本原文为本次比较起点，不设为默认值 | 与交接请求逐字对照 |

## 容易做错的三处

1. 把会话列表返回的 total 当作全部入口的对话总数。source=api 只取 API 会话，页面会话不在其中，两者相加会高估。
2. 把检索返回的 score 当作权限或实体筛选结果。score 是相似度，不排除无关业务或未授权记录。
3. 把交接请求里的「已补齐」当作已完成事实。材料原文状态为待补，缺少补齐凭证时该字段为待核实，不构成矛盾也不构成确认。

## 怎么确认配好了

1. 输入样本原文与交接请求，比较产品、目的国、报告编号、签发日期、标签语言、状态六个字段。仅当同主体同字段取值互斥时才判为矛盾；样本中状态字段一方为待补、一方称已补齐，但缺少补齐凭证，结论为待核实。
2. 以 source=api 请求会话列表，观察返回的 list 与 total 是否只含 API 会话；再以同一 appId 核对页面会话是否出现在结果中。若页面会话未出现，符合文档所述边界。
3. 以 detail=true 非流式请求，检查 responseData 是否含模块级字段；再以流式请求，检查 event 是否区分 answer、flowNodeStatus、flowResponses。若字段缺失，记录为未返回，不推定已完整留存。
