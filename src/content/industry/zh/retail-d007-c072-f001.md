# 跨境海外仓补货管理的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

第三方海外仓可服务多个渠道，库存分配由卖家自行完成，补货计划、入仓预约、库存库龄表与尾程派送单因此分散在海外仓 WMS、ERP 销售预测、货代系统和承运商账单之间。经营报表与异常复盘需要把这些来源按周、按日汇总，而 HTTP 接口承担的是向外部系统取数或送数的通道。

数据更新频率为周或日，接口调用按报表或复盘的实际需要发起，不由此推出批量同步、全量同步或实时触发机制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，实际操作与 Postman、ApiFox 这类工具接近。Params 为路径请求参数，GET 请求中居多；Body 为请求体，POST/PUT 请求中居多；Headers 为请求头。三类数据均可通过 `{{}}` 引用变量，URL 也可引用变量。变量来自全局变量、系统变量、前方节点输出。系统变量包含 appId、chatId、responseChatItemId、variables、cTime、histories，其中 histories 默认最多取 10 条且无法修改长度。返回值配置描述如何解析接口响应，通过 JSON path 提取；输出类型选择字符串时，会把对应 key 的值转成 json 字符串输出。

对话接口使用 APIKey 鉴权，调用 `chat/completions` 时推荐在请求体传入 `body.appId`；为兼容 OpenAI SDK 也支持 `Authorization: Bearer <apiKey>-<appId>`。appId 优先级为 `body.appId`、`<apiKey>-<appId>`、apikey 关联的 appId。传入的 model、temperature 等字段无效，由编排决定。如需 `authProxy` 代理团队成员身份，需团队所有者开启，代理身份仍需具备目标应用和会话权限。chatId 非空时自动从数据库取会话，仅用 messages 数组最后一个内容作为用户问题。

假设演练样本：某跨境卖家运营人员留下一份纸面材料，原文为「补货计划表 2025 年第 12 周，覆盖德国仓，计划补货 400 件；入仓预约单号预约状态为已提交，海外仓尚未回复确认时间」。待判定的拟稿句为「德国仓第 12 周补货已获海外仓确认入仓时间」。该请求处于已提交、未获回复的状态，拟稿句把提交当成确认，判定为不获支持。

## 配置怎么定

下表围绕该样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选定，地址可引用变量 | 对照接口文档核地址与方法是否对应 |
| Params 与 Headers | 按接口契约填写，鉴权凭证经安全配置注入 | 逐项核对实际传入值，不写入公开样例 |
| Body | 仅在相应请求类型下使用 | 核对 JSON 结构与外部接口契约 |
| 变量引用 | 引用全局变量、系统变量或前方节点输出 | 逐项核对实际传入值 |
| 返回值解析 | 按 JSON path 配置 key 与输出类型 | 对照响应示例核提取路径 |
| 调试身份字段 | chatId、responseChatItemId 在测试模式下不存在 | 不把调试空值当成业务故障 |

## 容易做错的三处

1. 把预约状态「已提交」当作已获确认。样本原文只写已提交、尚未回复确认时间，拟稿句写成已获确认入仓时间，输入与结论之间缺少确认证据。检查为：输入样本原文与拟稿句，比较预约状态字段取值，拟稿句出现「已获确认」而原文无确认记录时判为不获支持。
2. 把接口返回的相似度分值当作权限或实体过滤。相似度是检索结果的相关度数值，不承担排除未授权记录或无关企业的功能。检查为：输入一条含相似度字段的响应，比较该字段与授权字段，若拟稿句据相似度断言记录已授权，判为不获支持。
3. 把测试模式下不存在的 chatId、responseChatItemId 当作业务故障。检查为：输入测试模式请求记录，比较该字段是否存在，若拟稿句据此判定会话或响应异常，判为不获支持。

## 怎么确认配好了

1. 输入上述样本原文与拟稿句，比较预约状态字段，拟稿句含「已获确认」而原文无确认记录，预期判定为不获支持；若原文出现确认时间字段并载明确认，才满足支持条件。
2. 输入一条带相似度与授权字段的假设响应，比较两字段，拟稿句据相似度断言已授权时预期判为不获支持；仅当授权字段本身载明授权，才满足支持条件。
3. 输入测试模式请求记录，比较 chatId、responseChatItemId 是否存在，拟稿句据此判定业务故障时预期判为不获支持；仅当非测试模式下该字段缺失，才满足继续核查条件。
