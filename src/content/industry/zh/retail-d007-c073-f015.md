# 跨境独立站支付风控的经营报表与异常复盘：知识库检索与召回

## 这个品类的数据长什么样

支付风控的资料围绕卡组织争议与收款账户展开，与包裹状态类订单履约资料不同。日常材料包括支付拒付通知、欺诈订单清单、发票、物流签收证明。这些材料按日、按单更新，单笔订单的争议状态与资金状态可能在同一期间内并存。经营报表与异常复盘需要把同一订单、同一期间、同一字段的证据放在一起比对，检索环节承担从库中取出对应材料的职责。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察，不执行跨模型检索来比较漏召回。搜索模式按测试问题在语义、全文与混合之间比较，不预设一种模式适合全部资料。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，比较原问题与优化后问题，核对主体是否被改错。引用内容以数组输出，长度可以为 0，没有搜索到内容时输出链路仍走通。相似度与相关度不承担权限或实体隔离职责。

假设演练样本：材料原文为“2025年3月10日，订单A-1001收到卡组织拒付通知，争议阶段为待审核，涉及金额100美元”。另一份材料原文为“2025年3月10日，订单A-1001的发票已开具，金额100美元”。待判定拟稿句为“订单A-1001的拒付已处理完成”。判定所需主体为订单A-1001，对象为拒付通知，期间为2025年3月10日，状态字段为争议阶段。待审核不证明缺少操作权限，也不构成处理完成。该拟稿句未获支持，应记录为待核实。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 支付风控资料库一个 | 先核各库向量模型标识，排除不同模型者，再决定是否加入 |
| 搜索模式 | 混合检索 | 与语义检索、全文检索分别跑同一测试问题，比较召回内容 |
| 引用上限 | 假设起点 2000 token | 因样本含通知与发票两类长短不一的材料，与 1000、3000 比较内容完整性 |
| 最低相关度 | 假设起点 0.3 | 先标注相关与无关样本，再与 0.2、0.4 比较过滤后的结果 |
| 问题优化 | 开启 | 与关闭状态比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 按设置启用 | 与不启用比较候选排序，核对重排得分与最低相关度的配合 |

## 容易做错的三处

1. 把检索命中当作授权。输入为拟稿句“订单A-1001的拒付已处理完成”，检索返回拒付通知与发票，比较材料中的争议阶段字段，观察到“待审核”与“已处理完成”不一致，该拟稿句未获支持。检索不负责权限判断，业务处理状态需另行核实。
2. 跨向量模型共同关联。输入为两个库的向量模型标识，比较标识是否相同，观察到标识不同即排除该库，不执行跨模型检索来比较漏召回，记录实际观察。
3. 把混合检索的 RRF 融合写成开关。输入为搜索模式设置，比较语义检索与全文检索两路结果，观察融合后的引用内容排序，RRF 是融合过程，不作为独立开关配置。

## 怎么确认配好了

1. 输入假设样本的材料原文与拟稿句，比较争议阶段字段的取值，观察到材料为“待审核”而拟稿句为“已处理完成”时，判定拟稿句未获支持并记录缺口。
2. 输入同一测试问题，分别在语义检索、全文检索、混合检索下运行，比较返回的引用内容数组，观察各模式召回内容的差异，不保证首条命中或全部召回。
3. 输入明确的人工空结果 `[]` 核对下游设计，比较下游对空数组的处理，观察输出链路是否走通，不声称虚构规则检索一定返回 `[]`。
