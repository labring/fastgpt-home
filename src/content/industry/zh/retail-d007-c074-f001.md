# 跨境退货翻新与二次销售的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

跨境退货翻新与二次销售处理逆向物流和商品状态，与海外仓头程补货属于不同业务。主要数据来自海外仓 WMS、TikTok 退货中心、Amazon 退货报告和商品质检照片，日常文档包括退货质检表、翻新记录、报废单和二次上架清单。经营报表与异常复盘要把这些来源的字段对齐到同一主体、同一期间、同一字段，才能判断退款成本、二次投诉和库存账实差异。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

HTTP 模块向对应地址发送请求，Params 用于路径请求参数，Body 用于 POST/PUT 请求体，Headers 用于传递特殊信息。URL、Params、Body、Headers 均可通过 {{}} 引用全局变量、系统变量或前方节点输出。返回值通过 JSON path 提取，输出类型选择字符串时会把对应 key 的值转成 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在，调试时出现的空值不能当作业务故障。

假设演练样本：某海外仓 2025 年 3 月 10 日一批退货质检表原文为「主体：深圳某跨境卖家；对象：蓝牙耳机 200 件；状态：质检完成，等级 B，可翻新；授权范围：仅限海外仓质检组内部核对」。同日翻新记录原文为「主体：海外仓质检组；对象：蓝牙耳机 200 件；状态：已安排翻新包装；授权范围：翻新组执行」。待判定交接请求为「将上述 200 件按可二次上架状态写入二次上架清单，并同步至外部销售系统」。该请求涉及库存状态变更和外部同步，属于需另接系统实现的业务动作。

## 配置怎么定

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| BaseUrl | 按外部接口文档填写 | 与接口文档给出的地址逐字比对 |
| Headers.Authorization | Bearer 加凭证 | 核对凭证由安全配置注入，不写入样例 |
| Body 结构 | 按接口契约的 JSON 字段 | 与外部接口文档字段清单比对 |
| 变量引用 | 引用质检表与翻新记录字段 | 核对实际传入值与原文一致 |
| 返回值 key | 按 JSON path 提取状态字段 | 与接口响应实际结构比对 |
| chatId | 本次核对会话标识 | 确认非测试模式下的真实会话 |

本次假设起点选择上述取值，原因是样本中质检表与翻新记录已给出主体、对象和状态，需要按接口契约逐项核对；比较对象是接口文档字段清单和样本原文，不涉及官方默认值。

## 容易做错的三处

1. 把待判定交接请求中的「同步至外部销售系统」当作已执行。输入是该请求文本，比较对象是样本中翻新记录仅写到「已安排翻新包装」，可观察结果是请求未包含外部系统写入确认，因此同步状态为待核实。
2. 把测试模式下 chatId 与 responseChatItemId 不存在当作业务故障。输入是测试模式请求，比较对象是文档说明这两个字段在测试模式下不存在，可观察结果是空值属于调试环境特征。
3. 把 JSON path 提取的返回值直接当作业务授权。输入是接口响应中的状态字段，比较对象是样本中授权范围仅限质检组内部核对，可观察结果是返回值不含授权判定，业务写入需下游实现。

## 怎么确认配好了

1. 输入样本中质检表原文「等级 B，可翻新」和翻新记录原文「已安排翻新包装」，比较两者对象均为蓝牙耳机 200 件、主体分别为卖家和质检组，可观察结果是两份材料在同一对象上状态递进，但均未载明二次上架授权。
2. 输入待判定交接请求「写入二次上架清单并同步至外部销售系统」，比较样本授权范围「仅限海外仓质检组内部核对」，可观察结果是该请求超出已载明授权范围，需补充授权材料后才能继续。
3. 输入接口响应中提取的状态字段，比较外部接口文档中该字段的定义，可观察结果是字段值仅表示接口返回内容，不表示业务审批通过或数据库写入完成。
