# 达人专场带货合作的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
达人专场带货合作围绕外部达人履约与佣金结算展开，品牌商务、MCN机构、达人经纪共同参与。经营报表与异常复盘需要把精选联盟、巨量星图、达人历史数据、店铺成交明细与达人合作协议、佣金设置单、样品寄送单、直播战报逐场对齐。每场直播产生一批待核对的结算记录，周度汇总时容易出现口径差异。HTTP 接口在此承担把外部系统返回值引入工作流、供报表与复盘比对的职责，接口本身不改变任何结算状态。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向目标地址发送请求，Params 用于路径请求参数，Body 用于 POST/PUT，Headers 传递特殊信息，URL 与三类数据均可通过 {{}} 引用全局变量、系统变量和前方节点输出。返回值通过 JSON path 或 JS 对象取值规则提取，输出类型选择字符串时会把对应 key 的值转成 json 字符串。系统变量中 chatId 与 responseChatItemId 在测试模式下不存在。对话接口的 model、temperature 等参数由编排决定，不随 API 参数改变。

假设演练样本：某品牌商务留存一份达人合作协议原文，其中写明“本协议自双方签署之日起生效，佣金按直播战报确认的结算口径核算”。同批材料中一份佣金设置单记载“本场佣金比例待运营复核后确认”，一份样品寄送单记载“样品已寄出，签收状态未回传”。一条待判定的交接请求拟稿为：“合作协议已生效，佣金比例已确认，可直接按战报结算。”判定需同主体、同期间、同一字段比对：协议生效与佣金比例确认属不同字段，佣金设置单显示的待复核状态与拟稿句的“已确认”指向同一字段且取值互斥，该拟稿句未获支持。样品签收状态未回传，属证据缺口，保持未知。

## 配置怎么定
下表围绕上述样本，列出官方已说明的设置或实施核对项，数值仅为本次假设试验起点。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选定，地址用 {{}} 引用变量 | 与接口文档声明的路径逐字符比对 |
| Headers 鉴权 | Authorization 采用 Bearer 加凭证引用 | 凭证经安全配置注入，与公开样例分离 |
| Body 结构 | 仅在 POST/PUT 下按接口契约写 JSON | 与外部接口文档字段逐项核对 |
| 返回值提取 | 按 JSON path 配置 key 与输出类型 | 用接口响应示例比对提取结果 |
| chatId 使用 | 测试模式下该变量不存在 | 不把调试空值记为业务故障 |
| 结算字段核对 | 佣金比例字段与设置单状态比对 | 同字段取值互斥时判为未获支持 |

## 容易做错的三处
1. 把协议生效等同于佣金比例已确认。输入为协议原文与佣金设置单，比较的是“生效”与“待复核”两个不同字段，观察结果是拟稿句所称“已确认”缺乏对应证据。
2. 把 HTTP 返回值提取成功当作业务授权完成。输入为接口响应与提取配置，比较的是数据读取与审批状态，观察结果是返回值存在不代表结算已获批准。
3. 把测试模式下 chatId 缺失判为接口故障。输入为测试模式请求，比较系统变量说明，观察结果是该变量在测试模式下本就不存在。

## 怎么确认配好了
1. 取样本中协议原文与拟稿句，比较“生效”字段与“已确认”字段，若两者指向不同字段且设置单显示待复核，则拟稿句未获支持，此为预期。
2. 取接口响应示例与提取配置，比较 key 与输出类型，若提取值与响应示例一致，则提取配置正确；若返回空数组 []，则按下游设计核对承接，不推断检索规则必返回空。
3. 取测试模式请求与系统变量说明，比较 chatId 是否存在，若测试模式下该值不存在，则记录为文档已说明现象，不计入业务异常。三项均为纸面核对，未实际执行。
