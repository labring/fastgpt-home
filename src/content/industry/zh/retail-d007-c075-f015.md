# 达人专场带货合作的经营报表与异常复盘：知识库检索与召回

## 这个品类的数据长什么样
达人专场带货合作由外部达人履约并涉及佣金结算，资料围绕达人合作协议、佣金设置单、样品寄送单、直播战报四类文档展开。经营报表与异常复盘需要从这些材料中调取主体、对象、期间与状态，用于核对佣金口径与售后扣佣。检索环节面对的是同一达人、同一场次、同一字段的多份记录，字段取值可能分别来自协议、设置单与战报。资料更新频率为每场与每周，检索时需按场次与期间限定范围，避免把不同场次的数据混入同一次复盘。

## 这些特征在「知识库检索与召回」这一环带来什么约束
检索单位是库，集合仅作分类管理，与搜索效果无关。关联多个知识库时须使用相同向量模型，标识不符者应先排除，不执行跨模型检索来比较漏召回。检索结果以数组输出引用，长度可以为 0，空结果链路仍会走通。最低相关度仅在语义检索或结果重排时生效，它是过滤阈值，不承担权限或实体隔离，检索本身也不构成授权。混合检索经 RRF 融合多路结果，重排与图片检索须具备相应模型并按设置启用，流程图列出的路径不代表每次请求全部执行。

假设演练样本：某品牌商务留存一份纸面材料，原文为「合作协议载明甲方为某品牌方，乙方为某达人，合作场次为三月十八日专场，佣金比例为百分之十五」；「佣金设置单载明同一场次佣金比例为百分之十二，生效日期为三月十日」；「直播战报载明该场次成交金额为若干，售后扣佣待核」。一条待判定拟稿句为：「该场次佣金按百分之十五结算，售后扣佣已完成。」该拟稿句的判定范围限于上述三份材料所载主体、场次与字段。

## 配置怎么定
| 配置项 | 本页相关设置或核对项 | 与样本的对应关系 |
| --- | --- | --- |
| 关联的知识库 | 可关联一个或多个使用相同向量模型的库 | 四类文档须同向量模型方可共同关联 |
| 搜索模式 | 语义检索、全文检索、混合检索 | 场次与比例属精确字段，可比较全文与混合 |
| 引用上限 | 单位为 token | 按战报与设置单实际长度设定，观察内容是否完整 |
| 最低相关度 | 仅在语义检索或结果重排时生效 | 先标注相关与无关样本，再比较阈值 |
| 问题优化 | 指代消除与问题扩展 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备模型并按设置启用 | 候选较多时比较重排前后顺序 |

引用上限的本次假设试验起点设为 800 token，理由是该值足以容纳设置单与战报片段，并与 400 token 的结果比较内容完整性。该起点为假设值，不属官方默认。

## 容易做错的三处
1. 把检索命中的协议比例直接当作结算依据。错误在于输入仅取协议一条，比较时未纳入设置单的生效日期与不同取值，可观察结果是拟稿句采信了未核对的口径。
2. 把待核状态写成已完成。错误在于输入为战报中「售后扣佣待核」，比较对象是拟稿句的「已完成」，可观察结果是状态被改写。
3. 把空结果当作无此记录。错误在于输入为明确的纸面空数组，比较对象是下游设计，可观察结果是空链路被误读为否定结论。

## 怎么确认配好了
1. 输入上述三份材料原文与拟稿句，比较协议比例、设置单比例及生效日期是否同主体、同场次、同字段，仅当同字段出现明确互斥取值时才判定为矛盾，否则记录为待核实。
2. 输入战报中「售后扣佣待核」与拟稿句「已完成」，比较状态字段取值，仅当材料载明完成事实时才满足条件，当前证据未获支持。
3. 输入纸面空数组，比较下游对引用长度为 0 的处理设计，观察空结果是否仍走通链路，不据此声称检索必然返回空。
