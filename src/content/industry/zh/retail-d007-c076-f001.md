# 达人佣金结算与扣佣的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样
本类别的结算发生在成交之后，核对重点落在有效推广订单与售后扣佣。数据来源包括精选联盟后台、订单售后数据、财务系统与达人合同，日常文档为佣金设置记录、结算账单、退款扣佣明细和发票。更新频率为周或月，报表与异常复盘按同一周期口径取数。文档字段不完整时按未知处理，不据缺失字段推断结论。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
HTTP 模块向目标地址发送请求，Params 用于路径参数，Body 用于请求体，Headers 用于请求头，三者均可通过 {{}} 引用变量，地址同样可引用变量。变量来自全局变量、系统变量与前方节点输出。返回值配置代表解析接口响应的方法，按 JSON path 提取，输出类型选字符串时会把对应值转成 json 字符串。鉴权凭证通过安全配置注入，不写入公开样例。

假设演练样本：某结算运营在 2026 年 3 月月度复盘时持有以下材料原文——“结算账单（月度）：达人甲 3 月有效推广订单佣金 8000 元，已扣退款佣金 1200 元，应付 6800 元。”“退款扣佣明细：达人甲 3 月退款订单 4 笔，扣佣合计 1200 元。”待判定的拟稿句为“达人甲 3 月佣金已结算完成，退款扣佣已全部扣除。”验收边界：该拟稿句仅用于核对，不代表结算、付款或扣佣已实际执行。

## 配置怎么定
下表围绕上述样本，列出官方已说明的设置或实施核对项。

| 配置项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| 请求地址与方法 | 按外部接口文档选定，地址引用已提供变量 | 对照接口文档核对地址与方法是否一致 |
| Params 与 Headers | 鉴权凭证经安全配置注入 | 核对请求参数与请求头，凭证不写入样例 |
| Body | 仅在相应请求类型下使用 | 对照接口契约核对 json 结构与字段 |
| 变量引用 | 引用全局变量、系统变量、前方节点输出 | 逐项核对实际传入值 |
| 返回值解析 | 按 JSON path 提取所需字段 | 核对 key 与输出类型是否匹配响应结构 |
| 调试身份字段 | chatId 与 responseChatItemId 在测试模式下不存在 | 不把调试空值当成业务故障 |

上述起点为本次假设试验所用，选取理由是便于逐字段核对，比较对象为外部接口文档所载契约。

## 容易做错的三处
1. 把拟稿句中的“已结算完成”当作已发生事实。输入为样本原文与拟稿句，比较拟稿句是否超出原文所载的账单与明细范围，观察结果是拟稿句包含原文未载的结算状态。
2. 把待审核或不完整的接口返回当作扣佣已执行。输入为接口响应与退款扣佣明细，比较两者字段是否同主体、同期间、同字段，观察结果是缺少可对应字段时仍写成已扣除。
3. 把相似度或检索结果当作权限或实体过滤。输入为返回值解析配置，比较其是否被用于排除无关记录，观察结果是相似度设置无法承担权限判断。

## 怎么确认配好了
1. 取样本原文与拟稿句，输入为上述两句材料，比较拟稿句是否只陈述原文所载的账单金额与扣佣明细，观察结果为拟稿句未出现原文未载的结算完成表述时满足条件。
2. 取接口响应与退款扣佣明细，输入为响应字段与明细字段，比较主体、期间与字段是否一致，观察结果为同字段互斥取值才记为矛盾，未载明记为待核实。
3. 取返回值解析配置，输入为 key 与输出类型，比较其与响应结构是否匹配，观察结果为能按 JSON path 提取目标字段时满足条件；空结果按纸面输入 [] 核对下游设计，不声称虚构规则检索必然返回 []。
