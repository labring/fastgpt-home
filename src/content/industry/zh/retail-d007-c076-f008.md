# 达人佣金结算与扣佣的经营报表与异常复盘：工作流编排

## 这个品类的数据长什么样

在达人佣金结算与扣佣的经营报表与异常复盘中，本页说明FastGPT的工作流编排如何衔接资料。佣金复盘查同一发布凭据的重复引用、退单状态和删重立场，不按表格行数认定结算。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

本题自拟两份统计稿引用同一发布凭据，退单明细并列已撤销申请与待核行，合作方更正函仅要求删除重复引用，没有认可整份账单。复盘流程先收凭据身份、明细状态和更正原句，让人员选择核重复来源或核退单对应。两份稿并不证明发生两次发布，撤销退单申请也不是退款执行；本页无真实次数、佣金额或处理结果，只测试纸面引用关系。

## 配置怎么定

| 佣金复盘证据关系 | 自拟记录 | 独立核法 |
| --- | --- | --- |
| 统计稿 | 重复引用同一凭据 | 不当重复发布 |
| 退单行 | 撤销与待核分列 | 不转退款执行 |
| 更正函 | 仅要求删重 | 不扩整账认可 |
| 补稿 | 引用位置需对照 | 资金另取证 |
| 实际核算 | 未给真实数额 | 不由行数计算 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

- 同一发布凭据在两稿出现被报告计作不同执行时，核原凭据身份及引用位置，将文档数量与业务事件数分开。

- 已撤销退单申请被列入已退款扣佣时，对原行状态、退款记录及适用交易，不因标题有退单就产生扣佣事实。

- 更正函同意删重被写成接受整账时，对函件覆盖项和明确意见，局部修订立场不能扩大为余额认可。

## 怎么确认配好了

分别沿来源去重和明细核对路径保存原句及下游实际收到的标识，不预设业务系统字段。补交易对应只解决对应，补新版统计稿仍核哪些引用确已更正，资金结论另取证。没有真实事件凭据时只列待查，不通过行数推算应付。正式核算、退款扣回与外发账单需授权系统和回执，流程只整理复盘证据，不修改账本或代任何一方确认。
