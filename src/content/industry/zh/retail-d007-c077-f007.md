# 进出口许可证件办理的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样

许可证办理发生在申报之前，决定货物能否合法进出口。日常材料包括自动进口许可证、两用物项许可证、合同、产品说明，来源涉及商务主管部门系统、海关商品编码、供应商资料、客户用途说明。每票业务的数据更新不定期发生，经营报表与异常复盘需要把这些材料与对话记录对齐。对话日志在这一环的作用是保留每次询问、检索与回答的原始输入和返回内容，供后续核对。日志存在不等于合规审计已经完成，对账、留存与合规要求由完整业务方案另行落实。

## 这些特征在「对话日志与审计」这一环带来什么约束

结合 chatId 核对目标对话与业务记录，不同入口的会话不混算。需要运行详情时按官方契约设置 detail，检查 responseData 中的节点响应。接口实际返回哪些字段就以哪些字段为准，未返回的业务数据不能推定已完整留存。测试模式与正式调用的身份字段可能不同，分别核对输入、历史与返回内容。

假设演练样本：某外贸合规岗在核对一票自动进口许可证的异常复盘。材料原文为三句：一，合同编号 HT-2024-0311 约定供应商在收到信用证后 30 日内交付钢卷 200 吨；二，自动进口许可证申请记录显示该票货物用途为「自用加工」，申请日期 2024 年 3 月 12 日，状态为「已提交待审核」；三，客户说明邮件写明「最终用户为境外加工厂，加工后再出口」。待判定的拟稿句为：「该票许可证已获批准，可用于本批钢卷进口申报。」核对要点：材料只写到状态为已提交待审核，拟稿句把待审核写成已获批准，属于未获支持的表述。

## 配置怎么定

下表只列与本页功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，说明选择理由与比较对象。

| 配置项 | 本次假设起点 | 说明与比较方法 |
| --- | --- | --- |
| chatId | 使用业务系统对话框 ID，长度小于 250 | 与获取会话列表返回的 chatId 逐条比对，确保复盘对象唯一 |
| detail | 设为 true | 与 false 返回对比，确认 responseData 中含节点运行详情 |
| responseChatItemId | 按当前 chatId 下唯一值传入 | 与数据库记录比对，确认同一 chatId 下未重复 |
| loadCustomFeedbacks | 设为 true | 与 false 返回对比，确认对话列表含自定义反馈字段 |
| pageSize | 本次假设起点 20 | 与获取会话列表返回的 total 比较，判断是否需要翻页 |
| source | 设为 api | 与会话来源比对，排除页面或分享链接创建的会话 |

## 容易做错的三处

1. 把待审核状态写成已获批准。材料原文只写「已提交待审核」，拟稿句写「已获批准」，两者在同一字段上取值互斥，属于未获支持。
2. 把检索命中当成授权执行。检索返回许可证相关条目，不代表该票已获审批或可用于申报。
3. 跨不同向量模型的库共同关联。先核对库标识并排除不符合者，不执行跨模型检索来比较漏召回。

## 怎么确认配好了

1. 输入假设样本的三句材料原文与拟稿句「该票许可证已获批准，可用于本批钢卷进口申报」。比较材料中状态字段取值与拟稿句表述。若状态字段为「已提交待审核」，则拟稿句属于未获支持，需退回修改。
2. 输入 chatId 与 source=api，调用获取会话列表。比较返回 list 中 chatId 与目标会话是否一致。若一致，说明复盘对象锁定正确；若不一致，记录缺口并核对输入。
3. 输入 detail=true 发起会话。比较返回 responseData 是否含节点运行详情。若含，说明运行详情已返回；若为空数组，说明本次未返回运行详情，需记录实际观察而不推定原因。
