# 进出口许可证件办理的经营报表与异常复盘：工作流编排

## 这个品类的数据长什么样

在进出口许可证件办理的经营报表与异常复盘中，本页说明FastGPT的工作流编排如何衔接资料。证件办理复盘保留撤回请求、新申请与附件目录的不同证据，不把企业动作当主管结论。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟进度包中，企业便笺请求撤回旧申请，新整理的申请稿尚待内部确认，旧收件回执仍在目录，许可附件只列名称未给正文。报告流程先收申请关系与文件用途，再选择核新旧对应或补附件内容。企业提出撤回不等于主管拒绝，旧回执不能不经对应支持新稿，目录中有附件名也不说明许可覆盖商品。本题不确定办理规则或法定结果。

## 配置怎么定

| 证件进度复盘 | 自拟材料用途 | 核验动作 |
| --- | --- | --- |
| 撤回便笺 | 企业提出请求 | 不当主管驳回 |
| 新申请稿 | 内部待确认 | 不沿旧状态 |
| 旧回执 | 原事项收件 | 核新旧对应 |
| 附件目录 | 只有名称 | 不称已审正文 |
| 正式动作 | 撤回重提另办 | 节点不执行 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

- 企业撤回请求被报告写成主管驳回时，对便笺作者、请求动词与正式处理资料，不把申请方立场改成机构决定。

- 旧收件回执被用于新申请已受理时，对新旧稿身份、回执所指事项和实际接收，文件整理不自动转移办理状态。

- 许可附件目录被填成已核商品范围时，对真实正文及其对象，未取得的附件保持缺证，不从名称作内容结论。

## 怎么确认配好了

两条路径分别保留申请身份链与附件可见范围，比较提交原文、下游输入及报告行。新回执到齐只更新其对应事项，正文补齐也先核覆盖对象，不顺带宣布获准。若只有申请名称或报告标题，应继续列待办。正式撤回、重提、许可判断和对外报送由主管业务与授权流程执行，节点选择和交互记录不实施这些动作，也不提供准入意见。
