# 连锁总部选址开店的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

在连锁总部选址开店的经营报表与异常复盘中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。选址复盘接口保留意向、候选门店与实际开店事件，获取清单不确认租约或营业。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

假设候选点位表只列考察意向，租赁邮件尚待条件确认，历史开店照片属于其他地址。按真实接口契约传点位及事项身份，核请求地址、方法与变量，凭证安全配置。查询鉴权与签约权限分别核，不由系统可读推总部已批准开店。本例不编面积、租金或经营预测。

## 配置怎么定

| 选址复盘HTTP | 假设材料 | 核验动作 |
| --- | --- | --- |
| 候选意向 | 尚非签约 | 查实际合同 |
| 租赁条件 | 双方待确认 | 保留原限定 |
| 开店照片 | 其他地址 | 核事件对象 |
| 点位变量 | 简称需对应 | 查真实传入 |
| 项目办理 | 授权流程另走 | 审批及回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

候选意向被答已签约时，查真实合同；条件待确认被写双方认可时，对邮件原句；他址开店照片被答本址营业时，核地址及事件。三处分别看阶段、意见状态和证据对象，返回成功不证明项目推进结果。

## 怎么确认配好了

验收保留脱敏请求、原始响应和来源位置，地址写法需有实际对应依据，不能凭简称猜。只有照片名称时明确内容未核；补合同只更新签约判断，营业仍独立核。签约、开店审批与项目回写由授权流程及接口负责，HTTP读取用于核既有资料。 候选地址的简称另附真实对应，租赁邮件只用于其所谈条件；开店照片按地点与事件独立索引，复盘时能指出缺的是合同、认可还是营业凭据。
