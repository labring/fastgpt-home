# 连锁总部选址开店的经营报表与异常复盘：对话日志与审计

## 这个品类的数据长什么样
选址开店发生在门店营业前，核心工作是租赁谈判与工程交付，日常材料为选址评估表、租赁意向书、装修预算与开业排期。这些材料的更新不定期且每店一次，因此对话日志中出现的租金销售比测算、条款谈判记录与装修节点协调记录，往往对应单店独立周期。经营报表与异常复盘要核对的是：某条对话是否属于某家待开店，以及该对话的运行详情能否支撑复盘结论。

## 这些特征在「对话日志与审计」这一环带来什么约束
日志接口按 chatId 取会话，按 dataId 取单条对话。source=api 只返回通过 API 创建的会话，不返回页面或分享链接来源的会话。这意味着复盘时先要确认对话来源，再确认身份归属。

假设演练样本：材料原文为“某意向书载明甲方为某商业管理方，乙方为某连锁总部拓展部，标的为某楼层铺位，状态为意向待签，有效期至某日期”；拟稿句为“该铺位租赁已生效，装修排期可启动”。待判定请求为“请依据该对话日志确认该店已具备开业条件”。原文只支持意向待签，拟稿句与请求均超出原文范围。

运行详情需按官方契约设置 detail=true 并检查 responseData，其中包含 moduleName、moduleType、runningTime、tokens、quoteList 等字段。日志存在只说明该轮对话被记录，不说明业务对账、留存或合规审计已完成。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 说明与比较方法 |
| --- | --- | --- |
| detail | true | 为取得 responseData 中间值，与 detail=false 的返回比较 |
| stream | false | 便于直接读取 responseData，与 stream=true 的事件流比较 |
| chatId | 样本会话标识 | 核对同一会话下的对话归属 |
| dataId | 样本对话标识 | 核对单条对话运行详情 |
| source | api | 核对会话来源范围 |
| loadCustomFeedbacks | true | 读取自定义反馈，与不传时比较 |

起点选择理由：复盘需要运行详情与来源范围，故取上述值；它们仅为本次假设试验起点，不是官方默认值。

## 容易做错的三处
1. 把意向待签当作合同生效，进而认为装修排期可启动。检查：输入样本原文与拟稿句，比较“意向待签”与“已生效”是否同字段互斥取值，观察拟稿句是否超出原文。
2. 把检索或表单提交当作授权执行。检查：输入待判定请求，比较请求中“已具备开业条件”与原文授权边界，观察是否缺少签署或批准证据。
3. 把日志存在当作合规审计完成。检查：输入 responseData 字段清单，比较业务对账、留存要求与已返回字段，观察缺失项是否被记录为缺口。

## 怎么确认配好了
1. 输入样本原文与拟稿句，比较“意向待签”与“已生效”，若拟稿句超出原文则判定为未获支持。
2. 输入待判定请求，比较请求结论与原文授权边界，若缺少签署或批准证据则记录为待核实。
3. 输入 responseData 实际字段，比较业务所需字段，若未返回则记录缺口，不推定已完整留存。
