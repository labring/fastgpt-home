# 连锁门店价格与陈列稽核的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

在连锁门店价格与陈列稽核的经营报表与异常复盘中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。价签陈列复盘区分单件与组合装、照片覆盖段及改排面回执，不把陈列变化当价格修正。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

本页自拟巡店资料：价签说明按单件展示，活动卡只适用组合装，照片文字说明仅覆盖货架左段，门店回执称已调整排面但未说改价。经营报告应核HTTP实际返回的是哪种包装、哪段货架和何种操作，不将组合装条件套单件，也不按一段照片概括全店。无真实价格、数量、影像分析或违规认定，文字仅用于核对资料覆盖与行动语义。

## 配置怎么定

| 价签陈列HTTP取证 | 自拟覆盖 | 检查动作 |
| --- | --- | --- |
| 单件价签 | 与组合装分开 | 不互套条件 |
| 活动卡 | 仅组合装 | 不补换算优惠 |
| 照片说明 | 货架左段 | 不扩大全店 |
| 门店回执 | 只改排面 | 不当已改价 |
| 报告结论 | 逐包装区域动作 | 各留原文依据 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |
| `调试身份字段` | 测试时无chatId及responseChatItemId。 |

## 容易做错的三处

- 活动组合装被答成单件价签适用时，对包装计量对象、活动原句和引用行，不自行换算或补优惠条件。

- 左段照片说明被报告扩成全货架检查完成时，对拍摄覆盖文字及实际返回附件，局部可见不能证明未覆盖区域。

- 调整排面的回执被写成已修正价格时，对回执动作、价签变更记录及复查来源，位置调整与改价分别留证。

## 怎么确认配好了

按真实读取契约传门店、商品包装与巡检事项，核Params、Headers及适用Body，凭证脱敏。保存请求范围、响应正文和报告采用句，只有照片目录就不称看过画面。补右段材料只扩所证区域，补改价记录也不直接确认全店一致。实际价格调整、稽核结论和对外说明需负责人授权及业务回执，查询本身不修改POS或陈列数据。
