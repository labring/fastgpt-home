# 连锁门店闭店清算的经营报表与异常复盘：HTTP 接口与外部系统

## 这个品类的数据长什么样

在连锁门店闭店清算的经营报表与异常复盘中，本页说明FastGPT的HTTP 接口与外部系统如何衔接资料。闭店资产复盘核盘点用途、租赁归属和抵扣提议，HTTP读取不决定资产处置或清偿。所用场景为自拟文字测试。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

自拟闭店资料中，现场盘点便笺只记设备在店，租赁附件将其中一项列为出租方设备，移交意见提出由房东接收并另议抵扣；水电停用资料只是申请。经营复盘读取前先按门店及设备对应核真实接口返回，不从设备在场推公司拥有，也不把接收提议写成抵扣完成。这里没有真实设备编号、资产额或结算余额，报告只列每项文字支持的状态与缺证。

## 配置怎么定

| 闭店资产HTTP复盘 | 自拟资料性质 | 独立核法 |
| --- | --- | --- |
| 现场盘点 | 设备在店 | 不推公司权属 |
| 租赁附件 | 出租方设备 | 逐设备对应 |
| 移交提议 | 房东接收另议抵扣 | 不改账务阶段 |
| 水电申请 | 仅提出停用 | 不推费用结清 |
| 实际处置 | 需授权和记录 | 查询不决定 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `请求地址与方法` | 请求地址与方法遵循外部契约。 |
| `Params与Headers` | 参数、请求头及鉴权分别核对。 |
| Body | 采用JSON请求体时按外部契约核结构。 |
| `变量引用` | 可引用全局、系统或前序输出变量。 |

## 容易做错的三处

- 现场盘点记录被用来认定设备归公司可处置时，核租赁附件的权属说明和设备对应，存在地点不是所有权凭据。

- 房东拟接收设备被汇总成租金已抵扣时，对移交提议、明确接受及款项处理记录，实物安排不自动产生账务结果。

- 水电停用申请被列作费用已结清时，核申请动作、处理回执及对应结算材料，不按文件标题补销户或无欠费结论。

## 怎么确认配好了

保留脱敏请求、原始响应和逐设备出处，按真实契约核地址方法及变量，不猜资源字段。只有清单或文件名时明确未见附件正文；补权属只修归属，补接收也不补抵扣。查询鉴权与处置、资金权限分别核。实际退租、资产处置、水电办理和账务写回由授权流程处理，本次HTTP只读材料，不代负责人作财产或债务决定。
