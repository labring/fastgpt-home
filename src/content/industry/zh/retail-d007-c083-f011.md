# 门店盘点与防损的经营报表与异常复盘：数据库与运维

## 这个品类的数据长什么样

在门店盘点与防损的经营报表与异常复盘中，本页说明FastGPT的数据库与运维如何衔接资料。防损复盘核实盘、账面与调查资料的来源，正常数据库不证明损耗原因。所用场景为自拟文字测试。

## 这些特征在「数据库与运维」这一环带来什么约束

假设盘点表实盘待复点，差异便笺提出漏扫可能，报损审批未签，监控调阅记录仅写已申请。运维复盘只核这些自拟文本能否完整存取，不认定员工责任或库存损失。没有真实差额、影像或审批结果；调阅申请存在不等于已看监控，更不能由数据库连通证明差异原因。

## 配置怎么定

| 防损复盘存储 | 假设输入 | 检查边界 |
| --- | --- | --- |
| 实盘 | 待复点 | 不生成差额 |
| 原因 | 漏扫可能 | 不定员工责任 |
| 报损 | 未签审批 | 不推核销 |
| 监控 | 调阅申请 | 不称已看影像 |
| 恢复 | 同门店轮次 | 逐句核引用 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `依赖连接` | 按部署核相关服务连接。 |
| `数据与向量职责` | 分清原文存储与检索后端。 |
| `连接与负载` | 保留实际错误和耗时记录。 |
| `备份与恢复` | 验证备份及实际恢复内容。 |
| `变更后复核` | 变更前后复用相同资料。 |

## 容易做错的三处

- 恢复后的分析把可能漏扫写成确定原因时，对原文动词及调查资料，检查状态是否丢失。

- 监控申请被问答称已完成影像核查时，对调阅回执和实际视频证据，文字记录不证明视频读取。

- 旧轮次已签报损单支撑本次核销时，对门店轮次和批准对象，检索同名不能扩批准范围。

## 怎么确认配好了

以盘点、分析、审批和调阅文字为固定组，分查原数据保存、检索返回与引用。备份后实际恢复，复问差异是否已定、审批是否完成。按实装核数据库及后端，记录真实错误耗时，不代设备或视频链路作未经实测的声明。真实复点、监控核查和报损仍须授权人员执行。
