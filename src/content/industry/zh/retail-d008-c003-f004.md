# Shopify独立站订单履约的跨境资料与多语检索：向量模型与索引

## 这个品类的数据长什么样

在Shopify独立站订单履约的跨境资料与多语检索中，本页说明FastGPT的向量模型与索引如何衔接资料。多语索引核滤芯、主机和housing的实体对应，保留初译与原订单的身份差异。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

Shopify多语索引可改用一组自拟订单原句与初译稿：中文写“替换滤芯单件，不含过滤主机”，英文草稿写“replacement cartridge only; housing not included”。cartridge与滤芯的对应、housing所指部件都要核原文对象，不能只凭流畅程度认定已校对。检索入口可以连接同一原数据，但应保留订单原文与初译稿各自身份。两边都有排除词，并不表示排除的是同一实体；本组尚缺确认术语的对照说明。

## 配置怎么定

| 多语身份核对 | 本题词句与来源 | 取证动作 |
| --- | --- | --- |
| 原订单对象 | 替换滤芯单件，不含过滤主机 | 核单件及排除词同在。 |
| 初译用词 | cartridge与housing | 核术语及其部件所指。 |
| 索引新增 | complete unit with replacement filter | 逐词对照是否增加主机。 |
| 版本映射 | 初译稿与已校对稿身份不同 | 核目标原数据和实际引用。 |
| 同题复测 | 中英问同一购买组成 | 保留排除对象，另核用途问法。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

第一处是英文入口写complete unit with replacement filter，增加原订单未给出的主机，应逐词比较入口与订单的单件、排除条件。第二处是初译housing被直接当成过滤主机；应查术语对照及原数据中的部件对象，在确认前保留歧义，不能从词近推定等义。第三处是英文入口指向旧初译稿，回答却说采用已校对订单；应核入口目标的文档身份与版本关系，再看实际引用，避免把来源名称当成已经校对的证据。

## 怎么确认配好了

验收可用中文问是否含过滤主机，用英文问whether the purchase includes a complete filter unit，并分别查看实际引用哪份原文。中文依据应保留不含主机，英文only与not included也应回指它们所约束的对象；无法确定housing时不要擅自统一术语。再用配件用途问题检查是否被改写成购买组成。若补入术语对照或已校对稿，先核对应订单与处理、索引状态，再比较同题引用；同一检索节点关联多个库时按官方条件核相同向量模型，不扩成所有工作流用库的要求。
