# 一般贸易出口报关的跨境资料与多语检索：工作流编排

## 这个品类的数据长什么样

在一般贸易出口报关的跨境资料与多语检索中，本页说明FastGPT的工作流编排如何衔接资料。出口双语文件传递核提单角色、重量字段和译稿修订，不能把译文更新当申报更改。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟出口材料包有英文提单摘录，分别列consignee与notify party；中文装箱说明并列毛重与净重但未填数值，译稿更正便笺只要求核术语。先按文件收角色和字段原句，让人员选择核收货角色或核毛净标签，再看下游是否连同来源收到。通知方不自动成为收货方，重量字段不可互换；修订译稿也不证明已修改实际报关资料。本题没有真实提单、重量或海关结果。

## 配置怎么定

| 出口双语字段路由 | 自拟原文 | 核法 |
| --- | --- | --- |
| 提单角色 | consignee与notify party | 分别核主体 |
| 重量标签 | 毛重净重未填数 | 不交换口径 |
| 译稿意见 | 仅核术语 | 不称申报更改 |
| 接收输入 | 角色字段带出处 | 逐路径比较 |
| 正式单据 | 未给提交回执 | 另核授权操作 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

- notify party在中文承接被写成实际收货人时，对提单两种角色及所对应主体，不用相同联系人姓名合并身份。

- 装箱说明的毛重标签被下游换成净重时，核原字段及说明范围，不能凭文件能解析就默认计量口径正确。

- 译稿更正意见被答为报关资料已经更改时，对更正对象、译稿版本和正式提交记录，文字修订不产生外部系统操作。

## 怎么确认配好了

验收分别问谁是通知方、哪项是毛重、这次更正改哪份文字，并对照两路径实际接收。补角色对应只解决角色，补计量说明也不能补重量值或申报状态。保留英文原词与译句的逐项位置，不自行命名官方字段或补海关规则。正式报关、原单据更正及业务回填需授权接口与回执，语言工作流只把可追溯材料送入下一步，不办理申报。
