# 仅退款争议处理的跨境资料与多语检索：知识库检索与召回

## 这个品类的数据长什么样
仅退款争议处理与普通退款退货存在关键差别：通常没有退件入仓，证据重点落在发货签收与商品价值。资料主要来自平台售后后台、承运商轨迹、客服聊天与仓库出库记录。这些材料按每单或每日更新。日常文档包括仅退款申请、发货凭证、签收证明与申诉材料。最耗时的环节是判断是否需退货、收集物流证据与提交平台申诉。跨境场景下同一争议可能同时涉及中文申请与英文轨迹，检索需要覆盖多语言语义匹配。

## 这些特征在「知识库检索与召回」这一环带来什么约束
检索对象是库，集合仅作分类管理，与搜索效果无关。关联的知识库须使用相同向量模型，跨模型库不可共同关联，只能先核标识并排除不符合者。语义检索具备跨多语言理解能力，可让中文问题匹配英文知识点。混合检索通过 RRF 融合语义与全文结果，RRF 是融合过程，不是独立开关。全文检索适合编号、型号与专有名词。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离功能。引用上限以 token 为单位，长短资料混存时用 token 控制比 top k 稳定。问题优化做指代消除与问题扩展，会额外调用模型并增加耗时。图片检索需要相应图像输入及模型能力，重排需要模型并按设置启用，二者不是每次请求都执行。

假设演练样本：某跨境店铺售后主管收到一份仅退款申请，申请原文为“订单 A-2291 商品为冬季外套，客户主张未收到货，申请仅退款”。仓库出库记录原文为“A-2291 于 3 月 2 日出库，承运商单号 TEST-8842”。承运商轨迹原文为“TEST-8842 于 3 月 6 日显示已签收，签收人栏为空白”。待判定拟稿句为“该订单已签收，不符合仅退款条件，建议驳回”。核对对象为该拟稿句与三份原文，判断签收状态与签收人字段是否支持该结论。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅关联使用同一向量模型的中文申请库与英文轨迹库 | 先核向量模型标识，排除不同模型库，不执行跨模型检索 |
| 搜索模式 | 语义检索与全文检索同时启用 | 用样本问题分别测试，比较语义命中与单号 TEST-8842 的全文命中 |
| 引用上限 | 假设起点 3000 token | 因样本含申请、出库与轨迹三段长短不一的材料，与 1500 token 结果比较内容是否被截断 |
| 最低相关度 | 假设起点 0.4 | 先标注相关与无关样本，与 0.2、0.6 比较过滤后保留量 |
| 问题优化 | 多轮追问场景开启 | 比较原问题与优化后问题，核对订单号与主体是否被改错 |
| 结果重排 | 具备重排模型时启用 | 比较重排前后候选排序，观察签收相关片段位置变化 |

## 容易做错的三处
1. 将检索命中当作授权结论。输入为拟稿句与三份原文，若仅因轨迹出现“已签收”就认定不符合仅退款条件，忽略了签收人栏空白这一未载明字段，属于把未获支持当作已否定。
2. 把不同向量模型的库共同关联。输入为中文申请库与英文轨迹库，若未先核向量模型标识就合并检索，属于越过文档要求的同模型前提，实际观察到的结果不能作为漏召回或冗余的依据。
3. 将最低相关度当作权限过滤器。输入为含无关订单的检索请求，若期望调高该值即可排除其他店铺或未授权记录，属于混淆相似度过滤与业务授权，检索本身不执行权限隔离。

## 怎么确认配好了
1. 输入上述三份原文与拟稿句，比较拟稿句结论与原文中签收人栏空白的事实。若检索返回的引用内容包含轨迹原文且未将空白签收人补写为确定签收人，满足核对条件；若引用内容缺失轨迹原文，则记录为证据缺口。
2. 输入订单号 TEST-8842 进行全文检索，比较返回结果是否包含对应出库与轨迹材料。若返回结果中该单号命中且引用内容完整，满足条件；若返回为空数组，用明确的纸面输入 [] 核对下游设计，不声称虚构规则必然返回空。
3. 输入一条仅含中文问题“这个订单签收了吗”的检索请求，比较语义检索返回的英文轨迹片段与问题语义是否对应。若返回片段包含签收状态字段且未被问题优化改写订单主体，满足条件；若问题优化后主体变为其他订单，记录为待核实，不判定为检索失败原因。
