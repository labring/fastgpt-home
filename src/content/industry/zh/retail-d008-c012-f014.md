# 仓内拣货复核打包的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样
仓内拣货复核打包处理订单出库，不处理供应商到货。波次拣货单、复核记录、面单与包装耗材单按每单或小时级节奏产生，错发漏发与包裹破损会带来售后赔付。跨境资料与多语检索这一任务，要求把上述单据中的字段与多语说明交给模型处理，因此模型接入与配置直接决定这些材料能否被正确读取。数据来源包括 WMS、订单系统、电子面单平台与称重设备，模型侧只接触被送入的文本或图像，不接触这些系统的写入权限。

## 这些特征在「模型接入与配置」这一环带来什么约束
FastGPT 借助 AI Proxy 连接模型提供商。App 与 Admin 共享变量中，AIPROXY_API_ENDPOINT 为必填的服务根地址，不要附加 /v1；AIPROXY_API_TOKEN 为必填的非空管理员 Token，不能用应用 API Key 代替。系统至少需要一个语言模型和一个索引模型才能正常使用。模型 ID 是请求 Body 中 model 字段的值，全局唯一；模型名为展示名称，可自定义。模型渠道决定协议类型，一个模型可配置在不同渠道以实现负载均衡。检索库内的向量关联要求同一向量模型，此要求不扩展到工商网站或其他外部系统。重排模型须具备模型并按设置启用，图片检索须有相应图像输入及模型能力。模型探测仅针对已启用的系统模型，未启用模型不参与探测。

假设演练样本：某仓一份波次拣货单原文写「波次 W-0912，订单 SO-4471，商品 A 数量 2，目的国 DE，面单语种 DE」。复核记录原文写「SO-4471 已扫描 2 件，外箱重量 1.8kg，耗材箱型 M」。一条待判定拟稿句为「该订单已按 DE 语种面单完成复核打包，可交运」。原文只载明扫描数量、重量与箱型，未载明交运授权，也未载明面单打印完成状态。

## 配置怎么定
以下配置项均为官方文档已说明的设置或实施核对项，数值一栏标注为本次假设试验起点时，仅用于纸面对照，不作为官方默认值。

| 配置项 | 官方说明的设置或核对项 | 本次假设试验起点与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 必填，AI Proxy 服务根地址，不附加 /v1 | 起点填 http://aiproxy:3000，与文档示例格式比较 |
| AIPROXY_API_TOKEN | 必填，非空管理员 Token，与服务端一致 | 起点填非空字符串，与「不能为空」条件比较 |
| 模型渠道协议类型 | 按模型提供商协议选择，多数可选 OpenAI | 起点选 OpenAI，与所配渠道协议比较 |
| 模型 ID 与模型映射 | 模型 ID 全局唯一，映射把请求模型指向实际模型 | 起点设 gpt-4o-test 映射到 gpt-4o，与请求 Body 中 model 值比较 |
| 模型能力项 | 语言模型、索引模型、重排模型分别核对 vision、toolChoice 等 | 起点 vision 设 true，与样本是否含图像输入比较 |
| 模型探测范围 | 仅探测已启用系统模型，首次失败最多重试 3 次 | 不设数值，与「已启用」条件比较 |

## 容易做错的三处
1. 把 AIPROXY_API_ENDPOINT 写成含 /v1 或 /chat/completions 的完整请求地址。输入为配置值，比较对象为文档所述根地址格式，观察结果为是否附加了路径后缀。
2. 用应用 API Key 充当 AIPROXY_API_TOKEN。输入为 Token 来源，比较对象为「管理员 Token 且非空」条件，观察结果为该值是否来自 AI Proxy 管理员配置。
3. 把检索库同向量模型要求扩展到外部系统。输入为向量库标识，比较对象为「同一向量模型才可共同关联」条件，观察结果为是否对工商网站等外部系统提出同模型要求。

## 怎么确认配好了
1. 对样本拟稿句「该订单已按 DE 语种面单完成复核打包，可交运」，输入为波次拣货单与复核记录原文，比较对象为原文是否载明交运授权与面单打印完成状态，观察结果为原文未载明这两项时，该句属未获支持，须记录证据缺口。
2. 对样本中「SO-4471 已扫描 2 件」，输入为复核记录原文，比较对象为扫描数量与波次拣货单商品 A 数量 2，观察结果为同主体同字段取值一致，可判定该字段相符。
3. 对模型探测配置，输入为已启用模型清单，比较对象为「未启用模型不参与探测」条件，观察结果为未启用模型是否出现在探测记录中；若出现则与文档条件不符。空结果核对可用明确的纸面输入 [] 承接下游设计，不声称虚构规则检索一定返回 []。
