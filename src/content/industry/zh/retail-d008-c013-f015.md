# 便利店加盟门店督导的跨境资料与多语检索：知识库检索与召回

## 这个品类的数据长什么样
加盟督导的核心资料是巡店表、加盟合同、整改通知与陈列标准，更新频率为周或月。跨境场景下，同一批资料常同时存在中文与目标市场语言版本，语义检索具备跨多语言理解能力，输入中文问题可以匹配英文知识点。资料主体涉及总部、区域督导与加盟店主，检索结果只反映内容相似程度，不反映谁有权查看或执行。督导APP、POS销售、加盟系统与门店照片构成主要数据来源，检索环节只处理已入库并完成训练的内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可以关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联。搜索模式分为语义检索、全文检索与混合检索，混合检索通过 RRF 融合多路结果，再经 ReRank 二次排序，最终经过相似度过滤和引用上限裁剪得到引用内容。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，会增加一次模型调用。图片检索需要图像输入及相应模型能力，未配置视觉模型或不支持图片的向量模型时，图片路径不参与。引用内容以数组输出，长度可以为 0，空结果链路仍然走通。

假设演练样本：某加盟合同附件载明“甲方为总部，乙方为华南区加盟店主，合同有效期至2026年12月31日，陈列标准以2025年3月版为准”。一份巡店表记录“2025年6月，该门店端架陈列不符合2025年3月版标准，已发整改通知，整改期限7日”。待判定拟稿句：“该加盟合同已于2025年6月终止。”核对时须比较主体、期间与字段：合同原文只载明有效期至2026年12月31日，未载明终止事实，该拟稿句未获支持。

## 配置怎么定
| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 中文巡店表库与英文合同库，两者使用相同向量模型 | 先核对向量模型标识，标识一致才可共同关联；不一致者排除 |
| 搜索模式 | 对编号类问题用全文检索，对自然语言问题用混合检索 | 用同一测试问题分别比较三种模式的召回内容 |
| 引用上限 | 假设起点为2000 token | 用长短不同的巡店表与合同片段测试内容完整性，再与更大或更小值比较 |
| 最低相关度 | 假设起点为0.5 | 先标注相关与无关样本，再与相邻阈值比较过滤效果 |
| 问题优化 | 对多轮追问开启，对独立明确问题关闭 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 候选较多时启用 ReRank | 比较重排前后排序，重排得分可用于过滤 |

## 容易做错的三处
1. 把检索当成授权。输入“华南区加盟店主合同”并命中合同片段，只能说明内容相似，不能说明当前请求方有权查看或执行该合同。检查时应比较检索输出与授权记录，授权记录缺失则记录缺口。
2. 把未载明当成否定。合同原文只写有效期至2026年12月31日，拟稿句写成已于2025年6月终止，属于同字段取值不一致的待核实情形，不能判定为已终止。
3. 跨向量模型强行共同关联。两个库向量模型标识不同时，节点无法共同关联，应核对标识并排除不符者，记录实际观察，不推断漏召回或冗余结果。

## 怎么确认配好了
1. 输入上述假设合同原文与拟稿句，比较“合同有效期”字段取值，预期现象为拟稿句未获支持，须保留证据缺口。
2. 输入“端架陈列不符合标准”这一检索词，比较巡店表与陈列标准两库的召回内容，预期现象为能返回对应片段；若返回空数组，则核对数据是否完成训练及引用上限。
3. 输入一个仅存在于英文合同库的中文问题，比较中文库与英文库的召回结果，预期现象为语义检索可跨语言命中英文知识点；若未命中，则核对向量模型与最低相关度设置，不据此断言该问题一定无答案。
