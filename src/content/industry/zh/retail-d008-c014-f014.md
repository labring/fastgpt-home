# 便利店鲜食订货的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

便利店鲜食按短保质期高频订货，门店每日或每班次产生订货单、报损单、临期处理表与温度记录。跨境场景下，同一批资料可能同时存在中文、日文、英文等多语版本，店长与区域督导需要借助检索定位对应单据。资料更新频率为日或班次，检索配置须匹配这一节奏。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与 Admin 必须设置 `AIPROXY_API_ENDPOINT` 和非空 `AIPROXY_API_TOKEN`，缺少任一项启动校验失败。端点填服务根地址，不附加 `/v1`。旧 OpenAI 变量或单模型自定义地址不能替代这两项。系统至少需要一个语言模型和一个索引模型。语音识别模型仅生效一个。检索库须与查询使用同一向量模型才可共同关联；跨不同向量模型的库不可共同关联，只能核标识并排除不符合者。相关度分数不承担权限或实体隔离，检索不构成授权。

假设演练样本：某便利店区域督导收到一份日文订货单原文，内容为“2026年10月8日 便当A 発注数 40個 納品期限 2026年10月9日 午前”。同批中文报损单原文为“2026年10月8日 便当A 报损 3份 原因：临期”。拟稿句为“便当A在10月8日已按40份全部订货并完成交付”。待判定该拟稿句是否与两份原文一致。

## 配置怎么定

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://aiproxy:3000` | 官方示例形态，不含 `/v1`；与含路径的地址比较 |
| `AIPROXY_API_TOKEN` | 非空管理员 Token | 官方要求非空；与应用 API Key 比较，二者不可互换 |
| 索引模型 `defaultToken` | `512` | 官方字段示例值；与待检索日文短句长度比较 |
| 索引模型 `maxToken` | `3000` | 官方字段示例值；与单据段落长度比较 |
| 检索库向量模型标识 | 与查询同标识 | 官方要求同模型才可共同关联；与另一库标识比较 |
| `MILVUS_LANGUAGE_IDENTIFIER` | `lingua` | 官方默认值；与 `whatlang` 比较，仅 Milvus BM25 生效 |

## 容易做错的三处

1. 把 `AIPROXY_API_ENDPOINT` 写成含 `/v1` 的完整请求地址。检查方式：读取环境变量值，与官方“不附加 `/v1`”的说明逐字比较，出现 `/v1` 即为不符。
2. 用应用 API Key 充当 `AIPROXY_API_TOKEN`。检查方式：核对 Token 来源字段，与“管理员 Token”说明比较，来源为应用侧即为不符。
3. 把相关度分数当作权限过滤。检查方式：查看检索配置是否以分数排除未授权记录，与“检索不构成授权”比较，出现此类设置即为不符。

## 怎么确认配好了

以下验证使用前述假设样本，均为纸面核对，未实际执行。

1. 将日文订货单原文与拟稿句逐字段比较。原文载明订货数 40 個、纳品期限 2026年10月9日午前；拟稿句称“全部订货并完成交付”。比较对象为“纳品期限”与“完成交付”。原文只给出期限，未载明交付已完成，拟稿句该部分未获支持。
2. 将中文报损单原文与拟稿句比较。原文载明报损 3 份，拟稿句未提报损。比较对象为同一主体“便当A”、同一日期“2026年10月8日”的报损字段。拟稿句遗漏该字段，属未获支持。
3. 检索核对：以日文订货单原文作为查询输入，观察返回结果是否包含该单据。若返回空结果，核对下游设计是否以明确的空输入 `[]` 承接，不推断虚构规则必然返回空。若返回其他语言版本，核对其向量模型标识是否与查询一致，不一致者排除，记录实际观察。
