# 信用证审单交单的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

信用证审单交单围绕单证一致展开，服务的是银行付款条件，与出口退税申报的税务匹配属于不同任务。日常材料包括开证行通知、UCP600 条款、货代提单、银行交单记录，每单更新。跨境资料与多语检索环节要把信用证、商业发票、提单、保险单、汇票等文本纳入可检索范围，供单证员核对条款与单据表述。这些材料的语种、版式和字段位置差异较大，检索结果需要回到原文逐项比对。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。按所用版本部署依赖服务，模型渠道与应用配置分别核对。App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。AIPROXY_API_TOKEN 填与服务端一致的非空管理员 Token，不能用应用 API Key 代替。系统至少需要一个语言模型和一个索引模型。检索库使用同一向量模型才可共同关联，标识不同的库先核标识并排除不符者，不执行跨模型检索比较漏召回。语义召回和相关度不承担权限或实体隔离。

假设演练样本：某单证员收到一份信用证通知，原文含“开证行：示例银行；申请人：示例进口商；受益人：示例出口商；金额：USD 100,000；最迟装运期：2026-09-30；交单期：装运后 21 天内”。拟稿句为“本信用证允许分批装运”。原文未载明分批装运条款，该拟稿句待核实。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 官方要求填根地址不附加 /v1；与文档示例格式比较 |
| AIPROXY_API_TOKEN | 假设填非空管理员 Token | 官方要求非空且与服务端一致；与 AI Proxy 侧配置比较 |
| 语言模型 | 假设启用一个已测试模型 | 官方要求至少一个语言模型；与渠道测试结果比较 |
| 索引模型 | 假设启用一个已测试模型 | 官方要求至少一个索引模型；与渠道测试结果比较 |
| 模型映射 | 假设 `gpt-4o-test` 映射到 `gpt-4o` | 官方示例说明映射关系；与渠道模型列表比较 |
| 渠道优先级 | 假设取 50 | 官方范围 1～100，数值越大越优先；与同渠道其他值比较 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 填成带 /v1 的完整请求地址。检查输入是否为服务根地址，与文档示例格式比较，出现 /v1 即不符合。
2. 用应用 API Key 充当 AIPROXY_API_TOKEN。检查该值是否为空、是否与服务端管理员 Token 一致，不一致即不符合。
3. 把假设样本中未载明的分批装运条款当作已确认事实。检查拟稿句是否有原文对应字段，原文无该字段即待核实。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句，比较拟稿句“允许分批装运”是否能在原文找到对应字段。原文未载明该条款，预期结果为待核实，不判定为矛盾。
2. 输入 AIPROXY_API_ENDPOINT 候选值，比较其是否附加 /v1。附加 /v1 时不符合官方格式要求，需改回根地址。
3. 输入 AIPROXY_API_TOKEN 候选值，比较其是否非空且与 AI Proxy 服务端一致。为空或与端侧不一致时启动校验失败，需修正后重启。

检索观察：输入信用证关键词查询，记录返回条目与原文位置；空结果用纸面输入 `[]` 核对下游设计，不断言虚构规则必返回空。图片检索须有图像输入及模型能力，重排须具备模型并按设置启用，未满足条件时该路径不执行。
