# 加盟费与保证金结算的跨境资料与多语检索：知识库检索与召回

## 这个品类的数据长什么样
加盟费与保证金结算围绕资金与违约扣款展开，不承担政府备案职责。资料来自财务系统、加盟合同、银行流水与门店违规记录，日常文档包括加盟费发票、保证金台账、扣款通知与合同付款计划。跨境与多语场景下，同一笔保证金退还请求可能同时出现中文扣款通知与英文付款计划，检索需要跨语言理解与精确编号命中并存。资料按月及每次扣款更新，本页只处理检索与召回，不推断批量同步或实时触发机制。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联，只能核对标识并排除不符合者，不执行跨模型检索来比较漏召回。语义检索支持跨多语言理解，全文检索适合编号、型号与专有名词，混合检索通过 RRF 融合两路结果，结果重排使用 ReRank 模型二次排序。最低相关度仅在语义检索或使用结果重排时生效，引用上限以 token 为单位。问题优化用于指代消除与问题扩展，会增加一次模型调用。检索结果不承担权限或实体隔离职责，检索库同向量模型要求不扩展到工商网站或其他外部系统。

假设演练样本：材料原文为“2025年3月扣款通知：加盟商A因未按合同第7条完成季度培训，扣减保证金人民币8000元，扣款事由已由加盟管理部确认。”以及“付款计划：加盟商A保证金余额于2025年4月复核后安排退还，退还以扣款结清为前提。”待判定拟稿句为“加盟商A的保证金已于2025年4月完成退还。”原文只载明4月复核后安排退还，且以扣款结清为前提，未载明退款已执行。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅关联使用相同向量模型的中文合同库与英文付款计划库 | 核对向量模型标识一致后共同关联，排除标识不符者 |
| 搜索模式 | 对扣款事由类问题用混合检索，对编号类问题用全文检索 | 比较语义、全文与混合三路结果，不预设单一模式适合全部资料 |
| 引用上限 | 本次试验起点设为覆盖一份扣款通知与一段付款计划的 token 量 | 用长短不同的实际资料测试内容完整性，再与更大或更小值比较 |
| 最低相关度 | 本次试验起点设为能保留扣款事由段落的值 | 先标注相关与无关样本，再比较过滤前后结果 |
| 问题优化 | 对多轮追问开启，对已明确编号问题关闭 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 在具备 ReRank 模型且候选较多时启用 | 比较重排前后得分与排序，观察是否更贴近问题 |

## 容易做错的三处
1. 把最低相关度当作权限或实体过滤器。最低相关度只过滤低相关度结果，不排除无关业务或未授权记录。检查：输入同一问题，比较过滤前后返回内容，确认未授权记录是否仅因相似度低而未出现，并记录检索不承担授权职责。
2. 把待审核的退还请求当作已完成退款。原文只写“安排退还”与“以扣款结清为前提”，未载明退款执行。检查：比较拟稿句与原文，确认原文缺少退款完成的主体、时间与金额证据，标记为未获支持。
3. 跨不同向量模型的知识库共同关联。检查：核对各库向量模型标识，排除标识不符者，记录实际观察，不推断共同关联后的运行结果。

## 怎么确认配好了
1. 输入假设样本原文与拟稿句，比较“安排退还”与“完成退还”的差异，观察是否将拟稿句标记为未获支持，并保留退款执行证据缺口。
2. 输入扣款通知中的“未按合同第7条完成季度培训”作为检索词，比较语义检索与全文检索结果，观察编号与事由是否被召回，失败分支记录为未命中并保留人工核对。
3. 输入明确的空引用内容数组，核对下游设计是否按长度可以为 0 的引用链路走通，不声称虚构规则检索一定返回空数组。
