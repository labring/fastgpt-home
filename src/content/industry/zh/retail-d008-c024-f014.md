# 品牌商场专柜运营的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

品牌商场专柜运营要处理联营扣点合同、商场活动函、销售小票、月结对账单，数据来源包括商场POS、品牌ERP、商场会员活动与财务系统。商场统一收银和扣点结算意味着专柜的销售流水与结算金额由商场侧记录，品牌侧需要按合同口径核对。跨境资料与多语检索场景下，这些材料可能以不同语言版本存在，检索系统需要同时覆盖合同条款、活动条件与对账明细。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy 服务。App 与 Admin 共享配置中，`AIPROXY_API_ENDPOINT` 填写 AI Proxy 服务根地址，不附加 `/v1`；`AIPROXY_API_TOKEN` 填写与服务端一致的非空管理员 Token。缺少任一项会导致启动校验失败。系统至少需要一个语言模型和一个索引模型才能正常使用。模型渠道在管理员-模型提供商页面配置，渠道测试会输出每个模型的测试结果与请求时长。模型状态探测仅针对已启用的系统模型，探测请求首次失败后最多自动重试 3 次，单轮最多尝试 4 次，全部失败才判定为异常。

假设演练样本：某专柜有一份联营扣点合同，原文含“本合同扣点比例为当月含税销售额的百分之二十二，结算周期为自然月，乙方须在次月五日前确认商场提供的月结对账单”。另有一份商场活动函，原文含“本次活动期间为三月一日至三月三十一日，活动扣点按百分之十八执行”。一条待判定的拟稿句为“三月活动期间该专柜扣点按百分之十八结算”。该拟稿句需要与合同原文、活动函原文逐字段比对：主体为同一专柜，期间为三月，字段为扣点比例。合同载明百分之二十二，活动函载明活动期间百分之十八，两者属同字段不同取值，活动函是否覆盖合同、活动期间是否与结算周期重合，均需依据原文进一步确认。检索请求的授权边界为：仅限该专柜已上传的合同与活动函范围。

## 配置怎么定

以下为本页假设试验起点，用于核对配置项与样本材料的对应关系，非官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写 AI Proxy 根地址，不带 `/v1` | 与文档说明的根地址格式比较，确认未附加路径 |
| `AIPROXY_API_TOKEN` | 填写与服务端一致的非空 Token | 与文档要求的非空管理员 Token 比较 |
| 索引模型 | 启用一个索引模型 | 与文档“至少一个语言模型和一个索引模型”比较 |
| 语言模型 | 启用一个语言模型 | 同上，核对两类模型均已启用 |
| 渠道测试 | 对已配置渠道执行模型测试 | 与测试输出结果及请求时长比较，确认模型有效 |
| 模型状态探测 | 启用自动探测，间隔设为 5 分钟 | 与文档支持范围 5～60 分钟整数比较；选 5 为本次试验起点 |

## 容易做错的三处

1. 把 `AIPROXY_API_ENDPOINT` 填成完整请求地址并附加 `/v1`。输入为带 `/v1` 的地址，比较对象为文档说明的根地址格式，可观察结果为启动校验或渠道调用出现地址相关错误。
2. 用应用 API Key 代替 `AIPROXY_API_TOKEN`。输入为应用侧 Key，比较对象为文档要求的服务端管理员 Token，可观察结果为 Token 校验不一致。
3. 将检索结果直接当作授权依据。输入为检索返回的合同片段，比较对象为合同原文的签署与生效状态，可观察结果为检索命中但授权状态仍待核实。

## 怎么确认配好了

1. 输入假设样本中的合同原文与活动函原文，比较拟稿句“三月活动期间该专柜扣点按百分之十八结算”与两份原文的同字段取值。合同载明百分之二十二，活动函载明百分之十八，两者同字段不同取值，可观察结果为该拟稿句在活动期间字段上与合同原文不一致，需进一步核实活动函的适用范围。
2. 输入假设样本中的检索请求，比较返回结果是否限于该专柜已上传的合同与活动函。可观察结果为返回条目均在授权范围内；若出现范围外材料，记录为越界观察。检索相关度不承担权限过滤功能。
3. 输入假设样本中的月结对账单核对请求，比较对账单金额与合同扣点比例、活动函扣点比例的计算结果。可观察结果为金额与哪个比例口径吻合；若两者均不吻合，记录为待核实，不判定为否定或冲突。空结果可用明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回空。
