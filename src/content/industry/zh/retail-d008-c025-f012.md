# 品牌奥莱折扣运营的跨境资料与多语检索：文档解析与分块

## 这个品类的数据长什么样
奥莱折扣运营以清理过季库存为目标，不维护新品正价形象，折扣审批、滞销清单、价签与毛利测算表构成日常资料主体。这些资料常含折扣比例、生效区间、SKU 编号与多语价签文本，解析与分块需要保留条件与所约束内容之间的绑定关系。资料更新以周、月为节奏，本页不据此推出批量同步或实时触发机制。跨境场景下同一份折扣审批可能包含中文与外语版本，检索需要覆盖跨语言语义匹配，同时保留编号类精确查询路径。

## 这些特征在「文档解析与分块」这一环带来什么约束
FastGPT 以库为最小搜索单位，集合仅作分类管理，与搜索效果无关。原数据存放于 MongoDB 的 dataset.datas 表，indexes 字段记录对应向量 ID，一组数据可对应多个向量；向量存于 PostgresSQL 的 vector 字段，索引为 HNSW。检索先召回向量，再按向量 ID 回查原数据，命中同一组原数据则合并，向量得分取最高得分。多向量映射用于缓解内容长度与语义丰富度的矛盾，同一数据块可标注多组索引。混合检索经 RRF 合并语义与全文结果，重排须具备 ReRank 模型并按设置启用。引用上限以 tokens 计，最低相关度仅在语义检索或结果重排时生效，该阈值是过滤条件，不承担权限或实体隔离。

假设演练样本：一份折扣审批原文为“本审批适用于华东奥莱店 2025 年 3 月滞销 SKU 清货，折扣上限 40%，审批人王某某，状态：待审核。”另一份价签原文为“价签编号 OL-2025-0312，对应 SKU 同上，生效日期 2025-03-15。”待判定拟稿句为“该审批已批准，价签可于 3 月 15 日执行。”原文仅载明待审核状态，未载明批准记录。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 折扣比例用语义、SKU 编号用全文，比较纯语义与纯全文的召回差异 |
| 引用上限 | 假设起点 2000 tokens | 因审批原文较短，与 1000 tokens 比较是否覆盖完整条件句 |
| 最低相关度 | 假设起点 0.3 | 与 0.5 比较，观察是否过滤掉含折扣条件的片段 |
| 问题优化 | 暂不开启 | 单轮明确问题，与开启后耗时比较 |
| 结果重排 | 具备 ReRank 模型时启用 | 与不重排比较候选排序变化 |
| 数据块索引 | 按审批、价签分别标注 | 比较单索引与多索引对编号命中的影响 |

## 容易做错的三处
1. 把“待审核”当作已批准。输入为上述审批原文与拟稿句，比较状态字段取值，原文为待审核而拟稿句写已批准，属于未获支持的判定。
2. 把检索命中当作授权执行。输入为价签检索请求，比较检索结果与执行权限，检索返回片段不构成价签可执行的授权。
3. 把上传成功当作索引已更新。输入为资料变更后的检索请求，比较实际训练与索引状态，上传完成不表示检索已更新。

## 怎么确认配好了
1. 输入上述审批原文与拟稿句，比较状态字段，只有原文出现批准记录且主体、期间、字段一致时，拟稿句才获支持；否则记录为待核实。
2. 输入 SKU 编号“OL-2025-0312”执行全文检索，比较返回片段是否含该编号与对应折扣条件；未命中时记录缺口，不声称无关查询必为空。
3. 输入中文问题“华东奥莱店三月清货折扣上限”，比较语义召回片段是否含 40% 与适用期间；同时核对向量模型标识，跨不同向量模型的库不共同关联，仅核标识并排除不符合者。
