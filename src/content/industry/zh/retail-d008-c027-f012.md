# 品牌经销商订货会的跨境资料与多语检索：文档解析与分块

## 这个品类的数据长什么样

订货会面向线下经销商预订，不直接管理平台店铺，资料以订货手册、订货合同、样品清单、授信审批为主，更新按季或按年。跨境场景下同一份订货手册常有中文、英文等多语版本，经销商用不同语言提问，检索需要跨语言命中同一段原文。资料结构上，合同条款、样品编号、授信条件往往与说明文字连写，分块时若把条件与所约束的内容拆开，召回片段会失去可判断的上下文。这些特征决定本页只处理文档解析与分块的实施条件、文档差异和核对步骤。

## 这些特征在「文档解析与分块」这一环带来什么约束

FastGPT 中知识库由库、集合和数据组成，最小搜索单位是库，搜索对整个库进行，集合仅作分类管理。向量存于 PostgresSQL 的 vector 字段，索引为 HNSW，MongoDB 的 dataset.datas 表存原数据并含 indexes 字段记录向量 ID，一组数据可对应多个向量。检索先召回向量，再按向量 ID 回 MongoDB 取原数据，同一组原数据合并，向量得分取最高分。多向量映射用于兼顾内容长度与语义丰富度，同一 chunk 可加多组 index。跨语言命中依赖语义检索，编号、型号类精确查询更适合全文检索或混合检索。语义检索与最低相关度只影响召回与过滤，不承担权限或实体隔离；跨不同向量模型的库不可共同关联，只能先核标识并排除不符合者。

假设演练样本：某品牌渠道部拟核对一份订货手册分块。供核对的材料原文为：“本节适用于2025年秋季订货会。经销商在授信审批通过后方可提交订货量。样品清单中的编号以英文版为准。”一条待判定的拟稿句为：“经销商提交订货量后，授信审批自动通过。”该拟稿句与原文在授信审批与提交订货量的先后关系上不一致，原文要求审批通过在前，拟稿句写成提交在后且自动通过，属于未获原文支持。此处主体为经销商，对象为订货量与授信审批，状态为审批通过，有效范围为2025年秋季订货会。

## 配置怎么定

下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。假设试验起点仅为本次核对所选，用于与另一取值比较，不作为官方默认值。

| 配置或核对项 | 本次假设试验起点及理由 | 比较方式与观察对象 |
| --- | --- | --- |
| 搜索模式 | 语义检索与全文检索各跑一次，样本含编号与自然语言 | 比较两种模式下返回片段是否覆盖原文条件句 |
| 引用上限 | 设为覆盖原文三句所需的 tokens 量 | 与更小取值比较，观察条件句是否被裁掉 |
| 最低相关度 | 取一个中间值，观察过滤后是否仍含条件句 | 与更低取值比较返回条数与相关性 |
| 问题优化 | 样本问题完整，先关闭再开启各一次 | 比较开启后是否改变对条件句的召回 |
| 结果重排 | 具备重排模型时启用一次 | 比较重排前后条件句排序位置 |
| 更新后复核 | 资料变更后核对训练与索引状态 | 比较上传成功与检索实际命中是否一致 |

## 容易做错的三处

1. 把条件与所约束内容拆到不同 chunk。样本中“授信审批通过后方可提交订货量”若被拆开，召回片段只剩“提交订货量”，判断会失去前提。检查方法：输入该条件句，比较返回片段是否同时含审批状态与提交动作，观察条件是否完整。
2. 将上传成功当作检索已更新。资料变更后未核对训练与索引状态，检索仍返回旧片段。检查方法：输入变更后的新表述，比较返回内容与变更前原文，观察是否仍命中旧句。
3. 用语义相似度替代授权判断。检索命中授信审批段落，并不表示该经销商已获审批。检查方法：输入拟稿句，比较原文中的审批状态与拟稿句表述，观察是否把“审批通过后”误读为“自动通过”。

## 怎么确认配好了

以下验证均使用上文完整给出的假设原文、拟稿句与请求，逐项说明输入、比较与满足条件，均为预期，未声称已实测。

1. 输入材料原文三句与拟稿句，比较拟稿句“提交订货量后授信审批自动通过”与原文“授信审批通过后方可提交订货量”，若两者在审批与提交的先后关系上不一致，则判定拟稿句未获原文支持，需保留证据缺口，不得补造授权条款。
2. 输入“授信审批通过后方可提交订货量”作检索，比较返回片段是否同时包含审批状态与提交动作，若条件句完整保留，则分块满足要求；若只剩提交动作，则记录为分块缺陷。
3. 输入一条仅含样品编号的查询，比较全文检索与语义检索的返回，若编号类查询在全文检索下命中更准，则对精确编号采用全文检索或混合检索；空结果情况可用明确的纸面输入[]核对下游设计，不声称虚构规则一定返回[]。

检索为授权之外的独立环节，表单收集值不等于业务验证、审批、数据库写入或外部同步已完成。待审核不证明缺少操作权限，签署、合作达成、合同生效是三个不同事实，未载明字段保持未知。
