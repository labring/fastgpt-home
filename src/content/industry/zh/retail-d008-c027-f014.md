# 品牌经销商订货会的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

品牌经销商订货会围绕线下经销商预订展开，不直接管理平台店铺。主要数据来自订货会系统、历史销售、经销商库存与财务授信，日常文档包括订货手册、订货合同、样品清单与授信审批。这些材料按季或按年更新，跨境场景下还需处理多语言版本。模型接入与配置这一环，要解决的是让多语检索能正确读取这些文档，并区分资料状态与授权状态。

## 这些特征在「模型接入与配置」这一环带来什么约束

跨境资料与多语检索需要语言模型和索引模型配合。按官方文档，系统至少需要一个语言模型和一个索引模型才能正常使用。模型通过 AI Proxy 接入，App 与 Admin 服务必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。检索层面，向量库为 Milvus 时全文检索走 BM25，其他向量库全文走 MongoDB `$text`；跨不同向量模型的库不可共同关联，应先核对模型标识并排除不符合者。检索结果的相关度分数不承担权限或实体隔离功能，检索本身也不构成授权。

假设演练样本：某品牌渠道部一份中文订货手册原文写“本手册适用于2026年春季订货会，经销商可在3月1日至3月15日提交预订量，授信额度以财务审批结果为准”。另有一份英文版样品清单，标注“Sample list for Spring 2026, subject to final confirmation”。一条待判定的拟稿句为“经销商已完成授信审批，可按手册提交预订量”。该拟稿句混同了资料说明与审批状态，样品清单的“待最终确认”也未在拟稿句中体现。

## 配置怎么定

围绕上述样本，配置项应限于官方已说明的设置或实施核对项。下表列出与本页任务直接相关的项目。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://aiproxy:3000` | 官方示例格式，不附加 `/v1`；与部署实际地址比较 |
| `AIPROXY_API_TOKEN` | 假设填入非空管理员 Token | 官方要求非空且与服务端一致；与 AI Proxy 配置比较 |
| 语言模型启用 | 假设启用一个多语语言模型 | 官方要求至少一个语言模型；与检索语种需求比较 |
| 索引模型启用 | 假设启用一个索引模型 | 官方要求至少一个索引模型；与文档语种比较 |
| `MILVUS_LANGUAGE_IDENTIFIER` | 假设设为 `lingua` | 官方默认值，用于 BM25 语言识别；与文档语种比较 |
| 模型映射 | 假设将请求模型映射到上游模型 | 官方说明模型 ID 与上游模型可不同；与渠道配置比较 |

## 容易做错的三处

1. 将检索结果当作授权依据。假设样本中拟稿句写“经销商已完成授信审批”，而原文只写“授信额度以财务审批结果为准”，审批状态在原文中未载明。检索命中该手册不能证明审批已完成，属于未获支持。

2. 将不同向量模型的库共同关联。假设样本的中文手册与英文样品清单若分别存入不同向量模型的库，不能直接共同关联检索，应先核对模型标识并排除不符合者，记录实际观察，不推断漏召回或冗余结果。

3. 将待确认状态当作已确认。英文样品清单写“subject to final confirmation”，拟稿句未体现该限制。待确认不等于已确认，属于证据缺口，不能补造确认条款。

## 怎么确认配好了

1. 输入假设样本的中文手册原文与拟稿句，比较拟稿句“已完成授信审批”与原文“以财务审批结果为准”，观察拟稿句是否超出原文支持范围。若拟稿句声称审批已完成而原文未载明，则判定为未获支持。

2. 输入假设样本的英文样品清单原文与拟稿句，比较“subject to final confirmation”与拟稿句表述，观察拟稿句是否保留待确认限制。若拟稿句未保留该限制，则判定为证据缺口。

3. 输入假设样本的两份文档与检索请求，比较两份文档所属向量模型的标识，观察是否属于同一模型。若标识不同，则排除共同关联，仅记录各自检索观察，不执行跨模型比较。
