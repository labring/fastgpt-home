# 品牌自播直播间运营的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

品牌自播由品牌自己承担话术、库存和售后，跨境资料与多语检索因此直接关系脚本、讲解卡和复盘的可核对程度。直播脚本、商品讲解卡、排班表、直播复盘是日常文档，每场与每小时更新，多语版本一旦与原始资料脱节，投诉与转化下滑风险随之上移。资料更新频率本身不改变本页功能，本页只处理模型接入与配置这一环：把模型渠道、模型能力与文档检索条件配到可核对状态。

## 这些特征在「模型接入与配置」这一环带来什么约束

从 V4.17.0 起 AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 都必须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项启动校验失败。AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两项。系统至少需要一个语言模型和一个索引模型才能正常使用；语音识别模型仅生效一个。模型 ID 是请求 Body 中 model 字段的值，全局唯一；模型名可自定义。渠道优先级范围 1～100，数值越大越容易被优先选中。检索是取回过程，不承担授权判断；相关度分数不是实体或权限过滤器。跨不同向量模型的库不可共同关联，只能先核对标识并排除不符合者，记录实际观察。

假设演练样本：某品牌自播团队为跨境场次准备多语讲解卡。材料原文为“本次直播商品为A款保温杯，讲解卡中文版标注容量500毫升，英文版标注容量500毫升，两版均标注‘以实物为准’”。待判定拟稿句为“英文讲解卡已确认容量为500毫升并可直接用于本场直播”。该请求的授权边界为：讲解卡处于待审核状态，尚无审核通过记录，也无多语一致性核对记录。

## 配置怎么定

| 配置项 | 本页设定或核对动作 | 与样本的关系 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填 AI Proxy 服务根地址，不附加 /v1 | 多语检索请求经此依赖发出 |
| AIPROXY_API_TOKEN | 填与服务端一致的非空管理员 Token | 缺失时启动校验失败，检索不可用 |
| 语言模型与索引模型 | 各启用至少一个 | 多语文本对话与索引分别需要 |
| 模型能力 vision | 按应用所需输入核对，不假设默认支持 | 讲解卡含图片时须先核对 |
| 模型映射 | 将 FastGPT 请求的模型映射到上游实际模型 | 多语请求的 model 字段按映射发出 |
| 渠道优先级 | 本次假设起点设为 50，与同渠道其他值比较后调整 | 仅作本次试验起点，非官方默认 |

## 容易做错的三处

1. 把待审核当作已通过。样本中讲解卡处于待审核状态，拟稿句写成“已确认”，输入为待审核状态记录，比较对象为审核通过记录，观察结果是两者不一致，该句未获支持。
2. 用检索命中替代一致性核对。输入为中文版与英文版讲解卡，比较对象为两版容量字段与“以实物为准”表述，观察结果是两版字段相同但均未载明多语一致性核对结论，不能据此判定可直接使用。
3. 把相关度分数当成权限过滤。输入为一次多语检索返回的分数，比较对象为文档授权状态字段，观察结果是分数不携带授权信息，不能据此排除未授权记录。

## 怎么确认配好了

1. 输入样本原文与拟稿句，比较拟稿句中的“已确认”与原文的待审核状态，观察结果是二者不一致时判定该句未获支持，保留审核缺口。
2. 输入中文版与英文版讲解卡字段，比较容量数值与免责表述，观察结果是字段一致但无一致性核对记录时，记录为待核实，不判定可直接使用。
3. 输入一次检索返回结果，比较结果中的文档标识与授权字段，观察结果是标识不符者被排除，授权字段缺失时记录缺口；空结果可用明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回 `[]`。
