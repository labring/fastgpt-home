# 售后维修与补寄的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

售后维修与补寄围绕恢复商品使用展开，结案方式与仅退款争议不同。维修申请、补寄单、检测报告、配件出库单构成日常处理对象，来源覆盖售后系统、订单系统、维修网点与配件仓。跨境资料与多语检索环节需要把这些单据中的主体、商品、故障描述、语言版本对应起来，供后续判断维修或补寄。维修申请与补寄单的更新频率为每单，配件出库单为日。这些频率影响检索侧对单据状态的读取节奏，不推出全量同步或交易触发机制。

## 这些特征在「模型接入与配置」这一环带来什么约束

多语资料意味着同一故障描述存在不同语言版本，模型接入需按应用所需输入核对语言模型能力。检索侧依赖索引模型对文本块建立关联，系统至少需要一个语言模型和一个索引模型才能正常使用。AI Proxy 是模型接入的依赖服务，App 与 Admin 分别核对渠道配置。相似度分数只反映文本相关程度，不承担权限过滤或业务实体隔离；检索结果是否可用，还需人工核对单据主体与授权状态。

假设演练样本：某品牌售后网点提交一份维修申请，原文为“客户于 2026 年 3 月 5 日申报故障，商品为电动工具，故障描述为无法启动，附件含检测报告一份，申请状态为待审核”。同批还有一份补寄单草稿，原文为“补寄配件：电池包一只，关联维修申请编号 WX-2026-0305，出库状态：未出库”。拟稿句为“该维修申请已批准补寄电池包一只”。待判定请求为“请检索该申请的历史处理记录，确认补寄是否已执行”。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写 AI Proxy 服务根地址，不附加 `/v1` | 与部署文档示例格式比对，确认无多余路径 |
| `AIPROXY_API_TOKEN` | 填写非空管理员 Token | 与服务端配置比对，确认一致且非空 |
| 语言模型 | 启用一个支持中文与目标外语的模型 | 按应用所需输入核对模型能力 |
| 索引模型 | 启用一个索引模型 | 确认系统至少有一个索引模型可用 |
| 模型映射 | 将 FastGPT 请求的模型映射到上游实际模型 | 核对映射关系与上游模型 ID 一致 |
| 渠道测试 | 对已配置渠道执行模型测试 | 观察测试结果与请求时长，确认模型有效 |

起点选择理由：以上取值来自官方文档已说明的字段与条件，用于本次纸面核对，不代表官方默认值。检索侧未在文档中说明与权限过滤相关的开关，配置中不设此类项。

## 容易做错的三处

1. 把检索命中的补寄单草稿当作补寄已执行。补寄单原文写“出库状态：未出库”，拟稿句写“已批准补寄”，两者主体相同、字段不同，草稿状态不构成执行证据。
2. 把维修申请的“待审核”当作缺少操作权限。待审核只说明申请处于审核阶段，不证明提交方无权限，也不证明补寄被拒绝。
3. 用相似度分数替代实体核对。检索返回的相关文本可能来自其他维修申请，分数高低不表示该记录属于同一申请编号，需按申请编号逐一核对。

## 怎么确认配好了

1. 输入假设样本中的维修申请原文与拟稿句，比较“待审核”与“已批准补寄”两个字段取值。若两者在同一申请编号下指向不同状态，则拟稿句与原文不一致，拟稿句未获支持。
2. 输入待判定请求“请检索该申请的历史处理记录，确认补寄是否已执行”，比较检索返回的记录中是否存在出库状态为“已出库”的补寄单。若返回记录仅含“未出库”草稿，则补寄执行状态待核实，不能判定已执行。
3. 输入补寄单草稿原文，比较关联维修申请编号 WX-2026-0305 与维修申请原文的编号是否一致。若编号一致且出库状态为“未出库”，则补寄处于未执行状态；若检索返回空结果，记录该缺口，不推断补寄已执行或已取消。

以上核对为纸面演练，未实际执行检索、测试或部署。空结果、待审核、草稿状态均按原文保留，不补造授权或生效条款。
