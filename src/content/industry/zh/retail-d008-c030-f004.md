# 商超供应商进场结算的跨境资料与多语检索：向量模型与索引

## 这个品类的数据长什么样

商超供应商进场结算围绕采购合同、送货验收单、返利协议与对账单展开，数据来自 ERP 采购、供应商门户、POS 销售与财务系统，更新节奏为周或月。该品类与联营柜台的关键差别在于结算多为购销或代销账款，供应商不一定驻场经营，因此跨境资料常包含境外主体名称、外币金额与多语条款。这些特征直接影响向量模型与索引的构建：多语条款要求向量模型具备跨语言语义匹配能力，而合同编号、验收单号、返利扣点等精确字段则依赖全文检索或混合检索。

## 这些特征在「向量模型与索引」这一环带来什么约束

知识库由库、集合与数据三部分组成，最小搜索单位是库，集合仅用于分类管理，与搜索效果无关。FastGPT 采用 PostgresSQL 的 PG Vector 插件作为向量检索器，索引为 HNSW，MongoDB 的 dataset.datas 表存储向量原数据，indexes 字段记录对应的向量 ID，一组数据可对应多个向量。关联检索的知识库须使用相同向量模型，需先核实际模型与输入类型，跨不同向量模型的库不可共同关联。图片检索还取决于入库时是否生成图片描述或图片向量，不能只看查询端。RRF 是混合检索中多路结果的融合过程，不是独立开关。检索环节不承担权限或实体隔离功能。

假设演练样本：某供应商门户导出一份对账单，原文为“供应商：Northwind Foods Ltd.；对账期间：2025年3月1日至2025年3月31日；结算方式：代销；返利扣点：按含税销售额2%计算；退货差异：2025年3月12日验收单号DN-0312记录退货120件，金额待财务确认。”另有一条待判定拟稿句：“该供应商2025年3月返利已按2%结算完毕。”判断所需的主体、对象与期间均在原文中，但结算是否完毕在原文中未载明。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 向量模型 | 选用支持中英文的同一模型 | 多语条款要求跨语言语义匹配，比较不同模型对同一批中英问句的召回原文 |
| 索引方式 | HNSW | 文档记载 PG Vector 插件索引为 HNSW，比较启用前后同一查询的召回内容 |
| 搜索模式 | 混合检索 | 合同编号与自然语言问句并存，比较语义检索与全文检索各自命中情况 |
| 引用上限 | 本次假设试验起点设为 3000 tokens | 对账单段落较长，比较不同取值下引用原文是否覆盖关键字段 |
| 最低相关度 | 本次假设试验起点设为 0.3 | 该值仅在语义检索或结果重排时生效，比较过滤前后候选内容变化 |
| 问题优化 | 多轮追问场景开启 | 连续对话中指代消除可提升召回，比较开启前后同一追问的召回原文 |

## 容易做错的三处

1. 把关联检索的知识库须使用相同向量模型，扩展为工商网站或其他外部系统也要同模型。错误输入是不同向量模型的两个知识库被同时勾选；比较对象是各库实际登记的模型标识；观察结果是模型标识不一致时不应执行共同关联，只记录标识并排除不符者。
2. 把检索或表单提交当成授权执行。错误输入是一条待审核的返利结算请求；比较对象是原文中是否载明审批状态与授权范围；观察结果是待审核状态不证明缺少操作权限，也不等于审批通过，只能记录为待核实。
3. 把图片检索视为每次请求必然执行。错误输入是纯文本问句且未上传图片；比较对象是本次请求是否包含图像输入及模型能力；观察结果是缺少图像输入时不走图片描述或图片向量路径，只按文本侧召回。

## 怎么确认配好了

1. 输入假设样本中的对账单原文与拟稿句“该供应商2025年3月返利已按2%结算完毕”，比较拟稿句中的“结算完毕”与原文载明的“金额待财务确认”，观察结果是原文未载明结算完成，该拟稿句属于未获支持，需记录证据缺口。
2. 输入同一批中英问句，比较各知识库登记的向量模型标识，观察结果是模型标识一致时方可共同关联；标识不一致时排除不符者并记录实际观察，不执行跨模型检索来比较漏召回。
3. 输入一条明确无对应资料的查询，比较返回引用内容数组，观察结果是数组长度为 0 时下游链路仍走通；该现象用于核对下游设计，不声称虚构规则检索一定返回空数组。
