# 商超供应商进场结算的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

商超供应商进场结算围绕购销或代销账款展开，多数情形没有驻场经营。资料来自 ERP 采购、供应商门户、POS 销售与财务系统，日常文档包括采购合同、送货验收单、返利协议与对账单。跨境与多语场景下，同一份验收单可能同时存在中文、英文或第三语种的字段描述，采购合同里的返利条款与对账单上的扣点口径需要跨文档比对。供应商业务、商超采购与财务结算三方各自持有片段信息，任何一方在检索时看到的材料范围都可能不同。这些特征决定了模型接入与配置要解决的是：让多语资料在检索环节可被定位，同时不把检索命中当成授权凭证。

## 这些特征在「模型接入与配置」这一环带来什么约束

从 V4.17.0 起 AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。AIPROXY_API_ENDPOINT 填服务根地址，不要附加 /v1。系统至少需要一个语言模型和一个索引模型才能正常使用。语音识别模型仅生效一个。模型 ID 是接口请求 Body 中 model 字段的值，全局唯一；模型名可自定义用于展示。一个模型可配置在不同渠道实现负载均衡。渠道优先级范围 1～100，数值越大越容易被优先选中。模型探测仅针对已启用的系统模型，首次失败后最多自动重试 3 次，4 次全部失败才判定异常。检索是定位材料的过程，不承担权限或实体隔离；跨不同向量模型的库不可共同关联。

## 配置怎么定

以下为本次假设演练样本，用于说明配置核对方式，不代表任何真实记录，也不表示已完成测试。

假设演练样本：某商超供应商结算场景中，一份中文采购合同写明“返利按季度结算，以验收数量为基数”，一份英文送货验收单写明“accepted quantity: 1200 cartons”，一份对账单写明“本季返利扣点 3%”。现有一条待判定拟稿句：“该供应商本季返利已按验收数量与 3% 扣点完成结算。”核对材料仅覆盖合同条款、验收数量与扣点比例三项，未载明结算已完成的事实。

| 核对项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 与文档示例一致，比较是否误加 /v1 |
| AIPROXY_API_TOKEN | 假设填非空管理员 Token | 与文档要求一致，比较是否为空或误用应用 API Key |
| 语言模型与索引模型 | 假设各启用一个 | 与文档最低要求比较，确认两类均存在 |
| 渠道优先级 | 假设填 50 | 与文档范围 1～100 比较，确认在区间内 |
| 模型探测间隔 | 假设填 30 分钟 | 与文档 5～60 分钟整数区间比较 |
| 模型 ID 与模型名 | 假设模型 ID 为 `gpt-4o-test`，模型名为展示别名 | 比较两者是否被混用为同一字段 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 填成完整模型请求地址并附加 /v1。输入是配置文本，比较对象是文档所述“服务根地址，不要附加 /v1”，若地址末尾出现 /v1 或 /chat/completions 则不符合。
2. 把应用 API Key 填入 AIPROXY_API_TOKEN。输入是 Token 字段内容，比较对象是文档所述“管理员 Token，必须与服务端配置一致且不能为空”，若填入的是应用侧凭证则不符合。
3. 把检索命中当作授权或结算已完成的证据。输入是检索返回的材料片段，比较对象是材料原文是否载明授权或结算完成事实，若原文只写返利比例与验收数量而未写结算完成，则拟稿句中的“已完成结算”未获支持。

## 怎么确认配好了

以下三项验证均使用上文假设演练样本，预期为纸面核对结论，未实际执行。

1. 核对 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN。输入为假设配置文本，比较地址是否为根地址且 Token 是否非空，分别核根地址格式、Token非空及其与服务端的一致性。这只核两项配置条件，整体启动与调用结果仍待测试；缺少必填项时按文档记录启动校验缺口。

2. 核对拟稿句“该供应商本季返利已按验收数量与 3% 扣点完成结算”。输入为拟稿句与三份材料原文，比较同一主体、同一期间、同一字段，材料载明返利基数与扣点比例，未载明结算完成事实，因此“已完成结算”属于未获支持，需记录证据缺口，不得判定为已完成。

3. 核对模型探测状态。输入为假设的探测配置与探测结果，比较探测范围是否为已启用模型、单轮尝试次数是否为1至4，若某模型 4 次尝试全部失败则状态为异常，若成功且延迟不超过 30s 则为正常；未启用模型不参与探测，不产生历史记录。
