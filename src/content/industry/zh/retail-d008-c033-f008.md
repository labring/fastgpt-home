# 外汇收结汇与贸易名录的跨境资料与多语检索：工作流编排

## 这个品类的数据长什么样

在外汇收结汇与贸易名录的跨境资料与多语检索中，本页说明FastGPT的工作流编排如何衔接资料。外汇资料跨语传递保留登记主体、收款阶段和待补条件，节点继续不代表银行办理完成。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

假设英文邮件说资料仅供预审，中文名录记录属于关联企业，收款说明只有提交银行的申请。先收原句、企业身份与对应事项，再让人员选择核词义或补身份。提交后逐项看下游实际收到的限定，预审用途不能改成办妥。纸面材料没有银行回执和真实交易结果，名录中出现关联企业也不证明本企业的业务资格。

## 配置怎么定

| 外汇双语流程 | 假设资料 | 接收核验 |
| --- | --- | --- |
| 英文邮件 | 仅供预审 | 不改批准 |
| 名录主体 | 关联企业 | 补本企业对应 |
| 银行申请 | 无入账凭据 | 保留待核 |
| 人员选择 | 词义或主体 | 核分支连接 |
| 正式办理 | 外部流程 | 核实际回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

预审被译成批准时，对邮件原句；关联企业名录被套本企业时，对主体及对应依据；收款申请被写入账时，对银行实际凭据。三处分别核词义、主体与事件阶段，人员选择和节点连接本身不证明这些事实。

## 怎么确认配好了

验收走核词义与补主体两条路径，缺回执时继续列明缺项。身份补齐只解决对应关系，不能顺带补银行处理结果。流程输出留可追溯原句，正式外汇办理、资金确认与外部回填由相应机构和业务接口承担，不由一次交互决定。 名录摘录旁附企业对应依据，银行申请旁留回执待补位置，复核时逐项查证。
