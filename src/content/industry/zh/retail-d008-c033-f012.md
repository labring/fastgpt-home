# 外汇收结汇与贸易名录的跨境资料与多语检索：文档解析与分块

## 这个品类的数据长什么样
收汇水单、贸易合同、发票与外汇业务登记资料构成这一品类的核心材料。与信用证审单相比，收结汇环节关注外汇资金和贸易背景真实性，不审全套信用证单据，因此解析与分块的对象集中在收汇主体、金额、合同编号与登记状态等字段。资料按每单与每月更新，单笔收汇水单与对应合同、发票需要在同一检索范围内可被同时召回，多语资料还涉及中英文术语混用。出错后果包括银行退单、外汇分类异常与资金无法入账，解析分段若把主体或状态与所约束内容拆离，检索结果就无法支撑核对。

## 这些特征在「文档解析与分块」这一环带来什么约束
分段完整性要求按具体资料结构切分，条件、说明与所约束的内容保持在同一数据块内。数据与索引需要区分：原数据存于 MongoDB 的 dataset.datas 表，indexes 字段记录对应向量 ID，一组原数据可对应多个向量，向量存于 PostgresSQL 的 vector 字段，索引为 HNSW。检索时先召回向量，再按向量 ID 回 MongoDB 寻找原数据，同一组原数据合并后取最高得分。多向量映射让较长文本可添加多组向量，其中一组被召回即召回该数据。语义检索支持跨多语言理解，全文检索适合编号与专有名词，混合检索经 RRF 融合，重排按 0-1 得分过滤。最低相关度仅在语义检索或结果重排时生效，引用上限按 tokens 控制。检索与相似度不承担授权或实体隔离功能，跨不同向量模型的库不可共同关联。

假设演练样本：材料原文为“甲方：A公司；乙方：B公司；合同号：HX-2024-017；收汇金额：USD 52,000；收汇日期：2024年11月5日；对应发票号：FP-2024-1105；外汇业务登记状态：已登记。”待判定拟稿句为“B公司已于2024年11月5日完成HX-2024-017合同项下USD 52,000的结汇。”该拟稿句将收汇日期与结汇完成混为同一事实，原文只载明收汇与登记状态，未载明结汇完成。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 样本含合同号与自然语言问法，与单独语义检索、单独全文检索的召回内容比较 |
| 最低相关度 | 假设起点 0.3 | 该值仅在语义检索或结果重排时生效，与 0.2、0.4 的召回条数比较，观察是否过滤掉主体不符片段 |
| 引用上限 | 假设起点 2000 tokens | 按 tokens 控制，与 1000、3000 比较，观察合同号与状态字段是否完整进入引用内容 |
| 问题优化 | 开启 | 样本含指代与多语混用，与关闭时对同一问题的召回内容比较 |
| 重排 | 启用 | 候选结果较多时按 0-1 得分二次排序，与不启用时的排序位置比较 |
| 分块核对 | 按资料结构人工核对 | 检查主体、合同号、状态是否与所约束内容处于同一数据块 |

## 容易做错的三处
1. 把收汇日期当作结汇完成日期。输入为上述样本原文与拟稿句，比较“收汇日期”与“结汇完成”两个字段，原文未载明结汇完成，该拟稿句未获支持。
2. 把上传成功当作检索已更新。输入为资料变更记录与训练状态，比较上传时间与索引建立状态，未完成训练时检索结果仍为旧内容。
3. 把相似度得分当作权限过滤。输入为跨主体查询与返回片段，比较返回内容与查询主体，得分高低不排除无关主体记录。

## 怎么确认配好了
1. 输入样本原文与拟稿句，比较拟稿句中的日期、金额、合同号与原文同字段取值，原文未载明结汇完成时，判定为未获支持并记录证据缺口。
2. 输入合同号“HX-2024-017”与自然语言问法，比较两种输入的召回片段是否包含主体、金额与登记状态，缺失任一项时记录分块问题。
3. 输入空结果承接场景，以纸面输入空列表核对下游设计，观察下游是否按缺口处理，不声称虚构规则检索一定返回空列表；跨模型场景先核对标识并排除不符合者，记录实际观察。
