# 外汇收结汇与贸易名录的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

外汇收结汇与贸易名录场景处理收汇水单、贸易合同、发票与外汇业务登记资料，关注外汇资金和贸易背景真实性，不审全套信用证单据。资料更新频率为每单与每月，跨境资料与多语检索需要把不同语种的水单、合同与登记资料放在同一检索入口下。与信用证审单相比，本场景核对收汇主体、办理结汇、解释贸易背景，出错会导致银行退单、外汇分类异常或资金无法入账。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入通过 AI Proxy 完成，App 与 Admin 必须配置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项启动校验失败。模型 ID 是请求 Body 中 model 字段的值，全局唯一；模型渠道决定协议类型与上游地址。检索环节的语义召回与相关度不承担权限或实体隔离职责，检索库同向量模型要求只适用于同一向量库内部的关联，不能扩展为工商网站或其他外部系统也要同模型。跨不同向量模型的库不可共同关联，只核标识、排除不符合者并记录实际观察。

假设演练样本：某外贸财务人员收到一份 2026 年 3 月的水单，付款方为“HONG KONG SUNRISE TRADING LIMITED”，收款方为境内某出口企业，金额 USD 48,200.00，附言“PAYMENT FOR CONTRACT NO. SR-2026-0312”。同批材料含一份贸易合同，签约双方与上述付款方、收款方一致，合同号 SR-2026-0312，货物为家用电器配件，约定结算方式为电汇。待判定拟稿句为：“该笔收汇已对应合同 SR-2026-0312，可办理结汇。”判定所需材料为水单原文、合同原文与外汇业务登记资料；登记资料中是否载明该笔收汇的对应关系属于未提供字段，保持未知。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填写 AI Proxy 服务根地址，不带 /v1 | 官方要求根地址；与文档示例格式比较 |
| AIPROXY_API_TOKEN | 假设填写与服务端一致的非空管理员 Token | 官方要求非空且一致；与应用 API Key 区分 |
| 模型渠道协议类型 | 假设选择 OpenAI 协议 | 多数自建渠道遵守该协议；与厂商文档比较 |
| 模型映射 | 假设将检索用模型 ID 映射到上游实际模型 | 官方示例 gpt-4o-test 到 gpt-4o；核对映射前后一致 |
| 模型能力 | 假设启用 vision 与 toolChoice | 按应用所需输入核对；分别验证多模态与工具调用 |
| 模型探测间隔 | 假设设为 30 分钟 | 官方支持 5～60 分钟整数；与业务核对频率比较 |

## 容易做错的三处

1. 把 AIPROXY_API_TOKEN 与应用 API Key 混用。输入为假设样本中的 Token 配置，比较对象为服务端管理员 Token 字段，观察结果是启动校验是否通过；Token 为空或与应用 Key 相同属于配置错误。
2. 把语义相关度当成权限或实体过滤。输入为假设样本中水单付款方名称，比较对象为检索返回记录的主体字段，观察结果是返回记录是否包含非授权主体；相关度分数不承担排除无关企业或未授权记录的职责。
3. 把待审核的登记资料当成已生效授权。输入为假设样本中外汇业务登记资料，比较对象为登记状态字段与拟稿句“可办理结汇”，观察结果是登记资料是否载明该笔收汇的对应关系；未载明时属于未获支持，不能判定为可办理。

## 怎么确认配好了

1. 输入假设样本水单原文与合同原文，比较两者付款方、收款方、合同号是否一致，观察结果是三字段同主体同期一致；拟稿句“已对应合同 SR-2026-0312”获得支持，但“可办理结汇”仍需登记资料载明对应关系。
2. 输入假设样本中登记资料缺失字段，比较对象为拟稿句中的结汇授权，观察结果是登记资料未载明对应关系时保留证据缺口，记录为待核实；不得补造授权条款。
3. 输入假设样本中付款方名称做检索，比较对象为返回记录的主体字段与向量库标识，观察结果是排除不同向量模型库后仅保留同库同模型记录；空结果分支以明确的纸面输入 [] 核对下游设计，不声称虚构规则检索一定返回 []。
