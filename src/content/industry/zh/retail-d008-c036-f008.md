# 多仓分仓与库存同步的跨境资料与多语检索：工作流编排

## 这个品类的数据长什么样

在多仓分仓与库存同步的跨境资料与多语检索中，本页说明FastGPT的工作流编排如何衔接资料。不同仓库的名称、库存术语与同步阶段需要随原文传递，不能用译词补库存事实。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

多仓跨语流程可先收中文分仓说明、外文库存文字和术语来源。自拟材料只有库存记录及同步请求说明，没有完成返回。表单传给后续读取时应保留仓库角色与资料时点，不将持有库存直接写成可用；术语是否对应需业务资料解释，不宣称节点自动判同义。人员选择可安排核定义或补同步回执，不是仓库数据库选择器。

## 配置怎么定

| 跨语流程核对 | 本题自拟材料 | 实际承接依据 |
| --- | --- | --- |
| 地点角色 | 两语调出调入说明 | 译写没有互换 |
| 库存定义 | 持有与可分配说明分开 | 未凭词形判同义 |
| 同步阶段 | 已发请求无完成结果 | 另查真实返回记录 |
| 补定义路径 | 核术语或补回执 | 接收实际对应原文 |
| 外部状态 | 查询调拨和写入另验 | 交互未代替库存同步 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

仓库角色错置：若调出调入在译写中互换，应核两处原文及地点对应；库存含义混用：若持有量被写成可分配，应查资料定义和适用范围；请求冒同步完成：若已发请求被说成已更新，应另查本次真实返回与记录。三项分别核角色、定义和执行，不从同名字段补出关系。

## 怎么确认配好了

验收逐项对照原文、译写、定义和实际接收值，补对应依据后复问，核新增资料实际参与解释。用户选择沿已接“是”分支继续，逐一验证路径与输入；交互等待结束不等于库存已同步。外部查询、调拨和库存写入需另接实际接口并核授权与回执，本次流程走完不证明所有仓库口径一致或货物已经移动。
