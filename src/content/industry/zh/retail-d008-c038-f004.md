# 大卖场生鲜联营柜台的跨境资料与多语检索：向量模型与索引

## 这个品类的数据长什么样

大卖场生鲜联营柜台由供应商驻场经营并按销售分成，资料同时牵涉商超生鲜部、联营供应商与门店店长三方。联营合同、日销售报表、损耗单、食品进货查验记录构成日常文档主体，其中进货查验记录按每批更新，日销售报表与损耗单按日更新。

跨境资料与多语检索的核心难点在于：同一批到货的查验凭证可能由境外供应商出具，品名、产地、批次用不同语言书写，而联营合同与损耗分摊又要求按门店口径核对。向量模型与索引环节要解决的，是让这些不同语言、不同来源的文档在同一个检索入口下被找到，并保留可核对的原文出处。

## 这些特征在「向量模型与索引」这一环带来什么约束

关联检索的知识库须使用相同向量模型，先核实际模型与输入类型。一个原数据块可以关联多个索引，索引与原文内容分别核对。索引内容要用完整且聚焦的信息建立，检索覆盖和索引长度需结合样本权衡。图片检索还取决于入库是否生成图片描述或图片向量，不能只看查询端。模型或索引调整后用同组问题比对引用原文，不根据向量分数单独承诺效果。

语义检索通过向量距离计算相似度，具备跨多语言理解能力，输入中文问题可匹配英文知识点。全文检索依赖关键词命中，适合编号、型号、专有名词。混合检索同时使用两路召回并通过 RRF 融合。最低相关度是过滤阈值，仅在语义检索或使用结果重排时生效，它不是权限或实体隔离手段。检索库同向量模型要求不能扩展为外部系统也要同模型。

## 配置怎么定

假设演练样本：某门店生鲜联营柜台收到一批境外供应商到货，材料原文为“Supplier: A-Fresh Co.; Product: frozen shrimp; Batch: AF-2024-0312; Origin: Ecuador; 查验状态：待门店收货确认”。一条拟稿句为“该批冻虾已完成进货查验并准予上架”。待判定请求为“请检索该批次的查验记录并确认上架状态”。样本中主体为 A-Fresh Co.，对象为批次 AF-2024-0312 冻虾，状态为待门店收货确认，有效范围仅限该批次。

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 向量模型 | 关联知识库统一使用同一向量模型 | 与另一知识库的模型标识比较，标识不同则排除关联 |
| 索引内容 | 每批查验记录以批次号、品名、产地建立索引 | 与完整原文长度比较，权衡覆盖与索引长度 |
| 搜索模式 | 混合检索 | 与单独语义检索比较，编号类查询需关键词命中 |
| 引用上限 | 本次假设起点 2000 tokens | 与样本原文长度比较，确保覆盖整批记录 |
| 最低相关度 | 本次假设起点 0.3 | 与 0 比较，观察待判定请求是否仍召回该批次 |
| 图片索引 | 入库时确认是否生成图片描述或图片向量 | 与查询端是否上传图片分别核对 |

## 容易做错的三处

1. 把检索结果当作授权依据。输入“请检索该批次的查验记录并确认上架状态”，比较检索返回的引用原文与样本状态“待门店收货确认”，若引用原文仍为待确认状态，则拟稿句“已完成进货查验并准予上架”未获支持。检索本身不产生授权。
2. 跨向量模型关联知识库。输入两个知识库的模型标识，比较两者是否一致，若标识不同则排除关联并记录，不执行跨模型检索来比较漏召回。
3. 把最低相关度当作实体或权限过滤。输入同一批次但不同供应商的记录，比较最低相关度设置是否改变召回范围，相关度阈值只过滤低相关结果，不排除无关企业或未授权记录。

## 怎么确认配好了

1. 输入样本原文与拟稿句，比较拟稿句所述“已完成查验并准予上架”与原文“待门店收货确认”，若原文未载明完成查验，则判定为未获支持，记录证据缺口。
2. 输入待判定请求与批次号 AF-2024-0312，比较召回引用是否包含该批次原文，若引用内容与原文一致且状态为待确认，则检索链路可用；若返回为空，用明确的纸面输入 [] 核对下游设计，不声称规则检索一定返回空数组。
3. 输入两个知识库的模型标识，比较是否相同，若相同则允许共同关联，若不同则排除不符合者并记录实际观察，不编造共同关联后的运行结果。
