# 大卖场生鲜联营柜台的跨境资料与多语检索：工作流编排

## 这个品类的数据长什么样

在大卖场生鲜联营柜台的跨境资料与多语检索中，本页说明FastGPT的工作流编排如何衔接资料。联营合同、损耗说明和进货查验记录分别保留性质，跨语处理不直接形成质量或责任结论。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

鲜食联营跨语流程可收合同原句、损耗说明和对应进货资料的已有译写，不给食品处理或法规要求。自拟材料没有完整检查过程，表单传递时应保留本柜、本批及来源性质。联营约定不等于实际销售，损耗出现也不直接说明原因；人员可选择核合同范围或补查验依据，不能由节点自动补成质量鉴定。

## 配置怎么定

| 跨语流程核对 | 本题自拟材料 | 实际承接依据 |
| --- | --- | --- |
| 主体角色 | 合同经营方和资料提供者 | 译写未互相替换 |
| 损耗性质 | 记录发生与原因结论分开 | 补实际检查依据 |
| 批次对应 | 本柜本批进货资料 | 他批记录未代填 |
| 选择承接 | 核合同或补查验 | 对应分支收到原文 |
| 正式业务 | 处置登记和回写另验 | 整理未代替质量或责任 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

角色误译：若合同经营方被换成资料提供方，应核原句所指主体；损耗冒原因：若记录发生被译成质量结论，应查观察范围与真实检查依据；批次错配：若其他进货材料套本柜，应核商品及批次关系。三项分别核角色、证据性质和对象，不从同一种商品推定可互用。

## 怎么确认配好了

验收保留原文、译写、柜台批次与实际接收内容，补本批查验后复问，核解释实际采用新来源。每个选择的“是”分支逐一看连接，交互等待结束不等于现场已检查。合同处理、进货登记、损耗处置与外部回写需另验业务授权及回执，本次跨语整理不证明质量合格、责任确认或经营结算已完成。
