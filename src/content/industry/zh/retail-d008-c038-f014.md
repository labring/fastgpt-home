# 大卖场生鲜联营柜台的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

大卖场生鲜联营柜台常由供应商驻场经营并按销售分成，日常资料包括联营合同、日销售报表、损耗单与食品进货查验记录。跨境资料与多语检索场景下，这些材料可能包含外文供应商名称、外文送货单或双语合同条款。日销售报表与损耗单按日或每批产生，食品进货查验记录随每批到货形成。核对称重销售、处理损耗分摊、查验进货凭证是三个耗时环节，检索结果需要回到这些原始材料核对主体、批次与状态。

## 这些特征在「模型接入与配置」这一环带来什么约束

联营供应商可能使用外文名称，合同、送货单与查验记录中的主体表述需要跨语言对齐。模型接入时，语言模型与索引模型至少各配一个，系统才能正常使用。多语检索依赖索引模型对文本块建立向量，检索结果只表示相似程度，不承担权限或实体隔离职责。配置模型渠道时，代理地址填写 BaseUrl，不填写完整模型请求地址；模型 ID 与渠道中的模型保持一致。模型状态探测仅针对已启用的系统模型，未启用模型不参与探测，也不产生历史记录。

假设演练样本：某门店生鲜部收到一份联营供应商提交的纸质材料，原文为「本柜台上月损耗单已由驻场人员签字确认，损耗金额按合同附件三比例分摊。随附日销售报表一份，批次号 2024-05-18-A。」另有一条待判定的交接请求：「请依据上述材料确认损耗分摊已生效，并授权从本月货款中扣除。」该请求中的签字确认与分摊比例属于材料载明内容，扣款授权属于另一项业务动作，材料未载明授权条款。

## 配置怎么定

配置围绕本页材料核对与多语检索任务。需要数值时，以下均为本次假设试验起点，并说明选择理由与比较对象。

| 配置项 | 假设试验起点或核对方式 | 说明与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不附加 `/v1` | 与官方文档要求一致；比较对象为实际部署的 AI Proxy 根地址 |
| AIPROXY_API_TOKEN | 使用与服务端一致的非空管理员 Token | 比较对象为 AI Proxy 服务端配置的 Token，不使用应用 API Key 代替 |
| 模型渠道代理地址 | 填写 BaseUrl，按需增加 `/v1` | 比较对象为模型厂商提供的 BaseUrl 说明 |
| 模型 ID 与渠道模型名 | 保持两者一致 | 比较对象为渠道配置中的模型名，不一致时映射关系需另行核对 |
| 语言模型与索引模型 | 至少各启用一个 | 比较对象为系统已启用模型列表，未启用模型不参与探测 |
| 模型状态探测间隔 | 假设起点 30 分钟，取 5～60 区间中值 | 比较对象为文档允许的 5～60 分钟整数范围，选择理由为便于观察一轮探测结果 |

## 容易做错的三处

1. 将检索结果当作授权依据。输入为假设样本中的损耗单与交接请求，比较对象为材料是否载明扣款授权条款，可观察结果为材料仅载明签字确认与分摊比例，未载明扣款授权。将相似检索命中视为已授权属于错误。
2. 将待审核状态当作已完成签署。输入为假设样本中「已由驻场人员签字确认」的表述，比较对象为材料是否载明签署主体、签署日期与生效条件，可观察结果为材料未载明上述字段，该状态属于待核实。
3. 将不同向量模型的库共同关联。输入为两个使用不同索引模型的检索库标识，比较对象为两库的索引模型标识是否一致，可观察结果为标识不一致时不可共同关联，仅记录实际观察，不推断漏召回或冗余结果。

## 怎么确认配好了

1. 输入假设样本原文与交接请求，比较材料载明内容与请求中的授权表述，可观察结果为材料未载明扣款授权条款，判定为未获支持，保留证据缺口。
2. 输入假设样本中的批次号 2024-05-18-A 与日销售报表，比较报表批次号与损耗单批次号是否一致，可观察结果为两者一致时属于同批次材料，不一致时记录为待核实。
3. 输入一条明确标注为假设的空结果 `[]`，比较下游设计对空结果的承接方式，可观察结果为下游按空结果处理，不声称虚构规则检索一定返回 `[]`。
