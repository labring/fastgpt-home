# 天猫旗舰店日常运营的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样
天猫旗舰店日常运营围绕品牌授权、旗舰店身份与天猫积分赔付规则展开，资料以商品发布页、品牌授权书、发货承诺记录、售后工单为主，更新频率为日与每单。跨境资料与多语检索这一任务要处理的是这些材料中的外文名称、授权范围与承诺条款，需要模型具备对应语种的识别与理解能力。资料日更与每单更新的节奏意味着检索结果会随单据变化，模型接入与配置必须支持按需重新索引，配置层面只核对已启用的系统模型，未启用模型不参与探测与检索。

## 这些特征在「模型接入与配置」这一环带来什么约束
AI Proxy 为必需依赖，App 与 Admin 都必须设置 AIPROXY_API_ENDPOINT 与非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败，旧 OpenAI 环境变量或单模型自定义请求地址不能替代。AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。AIPROXY_API_TOKEN 为管理员 Token，不能用应用 API Key 代替。系统至少需要一个语言模型和一个索引模型才能正常使用。模型 ID 全局唯一，模型名可自定义，模型渠道对应提供商协议，一个模型可配置在不同渠道实现负载均衡。自定义请求地址与 Key 属于绕过渠道的方式，不推荐使用。系统模型探测仅针对已启用的系统模型，未启用模型不参与探测也不产生历史记录。检索库若使用同一向量模型才可共同关联，不同向量模型的库不可共同关联，核标识并排除不符合者，不执行跨模型检索比较漏召回。

假设演练样本：某天猫旗舰店运营人员提交一份品牌授权书扫描件，原文含三句：授权方为 A 品牌管理有限公司，被授权方为 B 电子商务有限公司，授权期限自 2026 年 1 月 1 日至 2026 年 12 月 31 日，授权范围为在天猫平台销售 A 品牌第 25 类服饰商品。拟稿句为“B 公司已获得 A 品牌全品类授权”。待判定请求为“请确认该授权书是否支持在商品发布页标注全品类授权”。该样本仅用于纸面核对，不涉及真实客户或合法身份编号。

## 配置怎么定
下表围绕本页样本列出与本功能、主任务相关的官方已说明设置或实施核对项。假设试验起点仅用于本次纸面核对，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 核对是否为服务根地址，不附加 /v1 |
| AIPROXY_API_TOKEN | 假设填非空管理员 Token | 核对与服务端配置一致且非空 |
| 语言模型 | 假设启用一个语言模型 | 核对已启用状态，未启用不参与探测 |
| 索引模型 | 假设启用一个索引模型 | 核对已启用状态，满足系统最低要求 |
| 模型 ID | 假设与渠道中模型一致 | 核对全局唯一，与模型名区分 |
| 渠道优先级 | 假设填 50 | 核对范围 1～100，数值越大越优先 |

## 容易做错的三处
1. 将 AIPROXY_API_ENDPOINT 填成完整请求地址并附加 /v1。检查方式：输入该配置值，比较其是否仅为协议、主机与可选端口组成的根地址，若出现 /v1 或 /chat/completions 则不满足。
2. 用应用 API Key 代替 AIPROXY_API_TOKEN。检查方式：输入该 Token，比较其是否为管理员 Token 且非空，若为应用 API Key 则不满足。
3. 将未启用的模型纳入检索或探测范围。检查方式：输入模型启用状态，比较探测范围是否仅含已启用系统模型，若未启用模型出现在探测记录中则不满足。

## 怎么确认配好了
1. 针对样本拟稿句“B 公司已获得 A 品牌全品类授权”，输入授权书原文三句，比较授权范围字段是否为第 25 类服饰商品，若拟稿句所述全品类与原文范围不一致，则该句未获支持。
2. 针对样本待判定请求“请确认该授权书是否支持在商品发布页标注全品类授权”，输入授权书原文与请求，比较请求所需的全品类授权是否在原文授权范围内出现，若原文仅载明第 25 类服饰，则该请求待核实，不判定为已授权。
3. 针对检索范围，输入模型启用状态与向量模型标识，比较参与检索的库是否使用同一向量模型，若标识不一致则排除该库，记录实际观察，不推断漏召回或冗余结果。
