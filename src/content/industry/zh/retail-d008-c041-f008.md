# 平台促销报名与价格管理的跨境资料与多语检索：工作流编排

## 这个品类的数据长什么样

在平台促销报名与价格管理的跨境资料与多语检索中，本页说明FastGPT的工作流编排如何衔接资料。活动报名、批准范围和库存锁定说明在跨语资料中分开，不能把提交译成通过。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

活动报名跨语流程可收报名表、批准适用说明及锁定资料的原文与已有译写，不写金额或折扣比例。自拟输入没有本次平台接受或实际预留结果，表单应保留这些缺口。人员可选择核活动原句、补批准或查库存依据，逐项看连接和接收值，不预设平台营销接口已接通，也不由活动名相同推定所有商品都适用。

## 配置怎么定

| 跨语流程核对 | 本题自拟材料 | 实际承接依据 |
| --- | --- | --- |
| 报名阶段 | 提交文字无平台回复 | 未译成已经通过 |
| 批准范围 | 商品期间适用原句 | 两语接收没有丢失 |
| 预留状态 | 锁定安排与实际变化分开 | 另查执行记录 |
| 选择承接 | 补批准或库存依据 | 分支收到同活动资料 |
| 正式办理 | 提交写入与发布另验 | 交互未代替活动执行 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

提交冒通过：若报名文字被译成平台已接受，应取本次处理回复；范围丢失：若批准所指商品或期间被省掉，应对照两语原句恢复；锁定说明冒已预留：若计划被写成实际库存变化，应查对应执行记录。三项分别核平台阶段、适用对象和业务状态，不由译词肯定程度给出。

## 怎么确认配好了

验收保留活动、商品、原文译写和实际接收内容，补对应批准或库存依据后复问，核新增来源真正进入解释。交互状态记录并等待，不等于活动批准。报名提交、库存写入、价格处理或内容发布需另接实际业务并核权限与回执；本次跨语整理不证明平台已受理、商品已锁定或活动已执行。
