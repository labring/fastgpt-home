# 平台多店铺矩阵管理的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

多店铺矩阵的跨境资料来自各平台商家后台、ERP渠道价、品牌防伪系统与经销商报表，日常文档包括店铺授权清单、价格管控表、窜货投诉单和月度销售报表。这些材料按日或按月更新，语言与格式在不同平台间不统一。跨境资料与多语检索任务要把授权、价格和投诉信息转成可检索的语料，模型接入与配置决定这些语料能否被正确索引和召回。检索本身不构成授权，表单收集的字段值需要下游业务核对才能生效。

## 这些特征在「模型接入与配置」这一环带来什么约束

AI Proxy 为必需依赖，App 与 Admin 都必须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项会启动校验失败。AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。模型 ID 为请求 Body 中 model 字段的值，全局唯一；模型名可自定义。一个模型可配置在不同渠道实现负载均衡，渠道优先级范围 1～100，数值越大越容易被选中。系统至少需要一个语言模型和一个索引模型。语音识别模型仅生效一个。索引模型字段包含 defaultToken 与 maxToken。语言模型字段包含 maxContext、maxResponse、quoteMaxToken、maxTemperature、vision、toolChoice、functionCall。模型状态探测仅针对已启用系统模型，首次失败后最多重试 3 次，单轮最多尝试 4 次，全部失败才判定异常；正常为延迟不高于 30s，高延迟为高于 30s，异常为连续 4 次错误。告警 Webhook 在状态边沿变化时按模型分别推送，事件类型为 model_status_error 与 model_status_recovered，请求方法 POST，超时 5 秒。

假设演练样本：某品牌电商负责人提交一份店铺授权清单，原文为“授权对象：华东区三家平台店铺；授权事项：使用品牌方提供的多语产品资料进行店铺页面展示；授权有效期：2026-01-01 至 2026-12-31；授权状态：待品牌方法务审核”。同时提交一条待判定拟稿句：“上述三家店铺已获授权在有效期内使用多语资料。”该拟稿句把待审核写成已获授权，属于未获支持的表述。

## 配置怎么定

下表为本次假设试验起点的实施核对项，不表示官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 根地址，不附加 /v1 | 与文档要求比较，确认无路径后缀 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空管理员 Token | 与应用 API Key 比较，确认类型不同 |
| 索引模型 defaultToken | 设为 512 | 与语料分块长度比较，观察召回是否覆盖多语段落 |
| 索引模型 maxToken | 设为 3000 | 与单块最大长度比较，超过则分块 |
| 模型状态探测间隔 | 设为 30 分钟 | 与文档允许的 5～60 分钟整数范围比较 |
| 告警 Webhook 地址 | 填写接收端 URL | 用测试按钮推送模拟异常与恢复两条消息核对连通性 |

## 容易做错的三处

1. 把待审核状态写成已获授权。样本中授权状态为“待品牌方法务审核”，拟稿句写“已获授权”，同一主体、同一期间、同一字段出现互斥取值，属于未获支持。
2. 把检索结果当作授权凭证。检索只返回语料，授权是否生效需要品牌方法务审核完成，检索命中不改变授权状态。
3. 把 AIPROXY_API_ENDPOINT 填成带 /v1 的完整请求地址。文档要求填根地址，附加路径会导致请求地址错误。

## 怎么确认配好了

1. 输入样本授权清单原文与拟稿句，比较“待品牌方法务审核”与“已获授权”是否同主体同期间同字段。若两者互斥，拟稿句判定为未获支持；若原文改为“审核通过”，才可支持已获授权表述。
2. 输入 AIPROXY_API_ENDPOINT 候选值，比较是否以根地址结尾且不含 /v1。若含 /v1，判定为不符合文档要求；若为纯根地址，进入下一步核对 Token。
3. 输入模型状态探测配置，比较探测间隔是否在 5～60 分钟整数范围。若超出范围，判定为不符合；若在范围内，记录配置值，实际探测结果以系统运行观察为准，不预先断言成功。
