# 平台店铺评价与体验分维护的跨境资料与多语检索：文档解析与分块

## 这个品类的数据长什么样
评价维护处理售后履约后的消费者反馈，材料以差评处理记录、体验分明细、服务诊断报告、整改台账为主，更新频率为日或周。跨境场景下同一批材料常含多语字段，检索需同时覆盖中文问法与外语原文。文档解析与分块若把条件句与所约束的数值拆开，语义检索召回的片段会缺少判断依据，客服主管据此回复会偏离实际明细。

## 这些特征在「文档解析与分块」这一环带来什么约束
一组原数据可对应多个向量，索引字段记录向量 ID，向量得分取最高分。分段应保持语义单一与结构完整，使每组数据能回指原文。全文检索适合编号与专有名词，语义检索适合自然语言与跨语言问法，混合检索经 RRF 融合后通常再经 ReRank 二次排序，重排得分为 0-1。最低相关度仅在语义检索或结果重排时生效，它是过滤阈值，不承担权限或实体隔离。检索库与向量模型需一致，跨模型不可共同关联。

假设演练样本：材料原文为「2025年3月1日至3月31日，店铺A差评处理记录第12条：订单号 H-2031，消费者反馈物流延迟，客服于3月5日联系补充凭证，状态为待消费者回复。」待判定拟稿句为「该差评已完成整改并关闭。」原文仅载明联系补充凭证与待回复状态，未载明整改完成或关闭，该拟稿句未获支持。

## 配置怎么定
| 配置项 | 本页相关取值或核对项 | 说明 |
| --- | --- | --- |
| 搜索模式 | 语义检索、全文检索、混合检索 | 按问法选择，编号类走全文或混合 |
| 最低相关度 | 假设试验起点 0.4 | 与 0.3、0.5 比较命中范围，非官方默认 |
| 引用上限 | 假设试验起点 2000 tokens | 与 1500、3000 比较引用完整度 |
| 问题优化 | 按多轮追问场景决定启用 | 增加一次模型调用，提升连续对话检索 |
| 结果重排 | 具备模型且按设置启用 | 重排得分 0-1，可据此过滤 |
| 索引核对 | 核对 indexes 与训练状态 | 上传成功不等于检索已更新 |

## 容易做错的三处
1. 将「待消费者回复」当作整改完成。输入为样本原文与拟稿句，比较状态字段，原文无整改完成记录，拟稿句属未获支持。
2. 用最低相关度排除无关业务。输入为阈值设置，比较其文档定义，该值仅过滤低相关度结果，不执行权限或实体隔离。
3. 将上传成功当作索引已更新。输入为上传动作，比较实际训练与索引状态，二者需分别核对，缺失时记录缺口。

## 怎么确认配好了
1. 输入样本原文与拟稿句，比较状态字段是否一致，原文出现整改完成或关闭字样才满足支持条件，否则记为未获支持。
2. 输入订单号 H-2031 作全文检索，比较返回片段是否含该编号及对应期间，命中编号且期间一致为满足，未命中记为待核实。
3. 输入中文问法「3月差评处理状态」，比较返回片段是否回指样本原文，片段含主体、期间与状态为满足，缺失任一项记录缺口。
