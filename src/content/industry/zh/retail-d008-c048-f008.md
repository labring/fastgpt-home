# 快递面单与揽收交接的跨境资料与多语检索：工作流编排

## 这个品类的数据长什么样

在快递面单与揽收交接的跨境资料与多语检索中，本页说明FastGPT的工作流编排如何衔接资料。快递交接双语链保留制单、交给承运与收件的区别，译文不能把物流阶段向前推进。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

假设英文交接单写标签已建立，中文仓内说明说包裹等待承运，附件中的签收属于另一票。收原句及运单对应后，人员选择核物流词义或补本票记录；检查后续节点是否收到本票身份和等待条件。创建标签不能证明揽收，语言整理也不提供物流执行回执。

## 配置怎么定

| 快递双语交接 | 纸面状态 | 承接核验 |
| --- | --- | --- |
| 标签建立 | 只完成制单 | 不译已揽收 |
| 等待承运 | 尚待本票记录 | 保留等待 |
| 附件签收 | 另一票 | 核运单对应 |
| 人员路径 | 词义或补件 | 逐支核传入 |
| 物流执行 | 真实接口另接 | 独立回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

制单被译为已揽收时，对事件原句；他票签收套本票时，对运单身份；等待承运被写送达时，对实际收件凭据。三处分别核词义、对象与阶段，不能由交互继续判断快件已经移动。

## 怎么确认配好了

验收两种语言保留相同未决状态，逐一测分支连接并看输出承接。补本票揽收记录后仍需单独查送达证据；若仅修正译词，只更新文字。面单打印、承运提交和物流回写另接实际接口并核权限及回执，纸面流程不声称已操作。 交接记录旁保留包裹与运单的对应说明，两种语言分别对制单和承运原句核验。
