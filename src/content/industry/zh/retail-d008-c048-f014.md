# 快递面单与揽收交接的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

快递交接发生在包裹离仓节点，核心是承运商扫描责任。电子面单、交接清单、揽收扫描记录、异常件登记构成该品类的资料主体，来源包括快递系统、WMS 发运、承运商账单。资料更新频率为每批、每日。跨境场景下，同一批交接可能同时出现中文面单、外文面单、双语交接清单，多语检索需要模型接入与配置提供稳定的语言模型和索引模型。系统至少需要一个语言模型和一个索引模型才能正常使用。语音识别模型仅生效一个，配置一个即可。

## 这些特征在「模型接入与配置」这一环带来什么约束

从 V4.17.0 起，AI Proxy 为必需依赖。App 和复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN；缺少任一项会导致启动校验失败。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。AIPROXY_API_ENDPOINT 填写 AI Proxy 服务根地址，不要附加 /v1。模型能力按应用所需输入核对，多模态、工具调用分别验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。检索是资料查找动作，不承担授权判断；检索结果不能当作放行、交接完成或退款依据。

假设演练样本：某仓库 2026 年 3 月 10 日一批跨境包裹，交接清单原文写「本批共 48 件，其中 3 件面单收件人地址为外文，揽收扫描记录显示 45 件已扫描，3 件待扫描」。待判定拟稿句为「本批全部包裹已完成揽收扫描，可提交发货」。该拟稿句与原文冲突：原文明确 3 件待扫描，拟稿句声称全部完成。此样本仅用于纸面核对，不代表任何真实业务操作。

## 配置怎么定

配置围绕本页样本的核对需求，只列与本任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，说明选择理由及比较对象。

| 配置项 | 假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | `http://aiproxy:3000` | 官方说明填写服务根地址，不附加 /v1；与是否可启动校验比较 |
| AIPROXY_API_TOKEN | 非空管理员 Token | 官方说明必须与服务端一致且不能为空；与空值比较 |
| 语言模型 | 启用一个，模型 ID 与渠道模型一致 | 官方说明系统至少需要一个语言模型；与未启用状态比较 |
| 索引模型 | 启用一个，模型 ID 与渠道模型一致 | 官方说明系统至少需要一个索引模型；与未启用状态比较 |
| 模型类型 | 按样本所需语言与索引能力分别核对 | 官方说明模型类型分语言、索引、重排、语音合成、语音识别；与样本实际输入比较 |
| 模型测试 | 对已配置渠道执行模型测试 | 官方说明模型测试会实际发送请求并输出结果与请求时长；与测试结果比较 |

## 容易做错的三处

1. 把 AIPROXY_API_ENDPOINT 填成带 /v1 的完整请求地址。输入为配置值，比较对象为官方说明「不要附加 /v1」，可观察结果为启动校验是否通过。此项为配置错误，不涉及业务执行。
2. 把待扫描的 3 件当作已扫描。输入为样本原文「3 件待扫描」，比较对象为拟稿句「全部包裹已完成揽收扫描」，可观察结果为两者在同一字段上取值互斥，拟稿句未获支持。
3. 用检索结果替代授权判断。输入为多语检索返回的交接清单片段，比较对象为是否存在明确的放行或交接完成记录，可观察结果为检索命中不构成授权执行；缺失授权记录时保留缺口。

## 怎么确认配好了

1. 输入为假设样本原文「本批共 48 件，其中 3 件面单收件人地址为外文，揽收扫描记录显示 45 件已扫描，3 件待扫描」，比较对象为拟稿句「本批全部包裹已完成揽收扫描，可提交发货」。预期现象为拟稿句与原文在同一字段上取值互斥，判定为未获支持。不声称已实测。
2. 输入为假设配置 AIPROXY_API_ENDPOINT 填写 `http://aiproxy:3000`，比较对象为官方说明「不要附加 /v1」。预期现象为配置值不含 /v1，满足启动校验条件；若填写带 /v1 的地址，则与说明不符。不声称已实测。
3. 输入为假设样本中的 3 件待扫描记录，比较对象为是否存在对应的揽收扫描完成记录。预期现象为若检索范围内无该 3 件的扫描完成记录，则记录证据缺口；若检索返回空结果，以明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回空。不声称已实测。
