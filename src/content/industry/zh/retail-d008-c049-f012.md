# 批发市场档口交易的跨境资料与多语检索：文档解析与分块

## 这个品类的数据长什么样
批发市场档口交易更零散，依赖现场议价和托运，进货单、手写销售单、摊位租赁合同、货款收据往往由不同人经手，格式不统一。跨境资料与多语检索场景下，同一批货可能同时出现中文品名、外文托运单和手写金额，文档解析与分块需要先保留能回指原文的文档身份与版本，再按资料结构切分。日更或每单更新的资料在重新上传后，实际训练与索引状态需要单独核对。

## 这些特征在「文档解析与分块」这一环带来什么约束
分块要避免把条件、说明与所约束的内容拆离。同一组原数据可对应多个索引，原数据与检索索引需要区分。语义检索依赖向量距离，跨多语言理解是其文档化优点，但精度受关键词和句子完整度影响。全文检索适合编号、型号、专有名词。混合检索通过 RRF 融合多路结果，重排须具备模型并按设置启用。检索与相似度不承担权限或实体隔离，跨不同向量模型的库不可共同关联。

## 配置怎么定
假设演练样本：材料原文为“档口A于2024年3月5日向采购商B出具手写销售单，货品为女士外套200件，货款收据载明未付尾款人民币8000元，摊位租赁合同租期至2024年12月31日。”待判定拟稿句为“采购商B已结清全部货款。”该句与货款收据载明的未付尾款状态在同一字段上取值互斥。

| 核对项 | 本页相关设置或实施核对 | 与样本的关系 |
| --- | --- | --- |
| 分段完整性 | 按进货单、销售单、合同、收据各自结构检查段落 | 核对拟稿句所引货款状态是否与收据同段保留 |
| 数据与索引 | 区分原数据与 indexes 字段记录的向量 ID | 确认收据原数据与其索引可回指 |
| 搜索模式 | 语义检索、全文检索或混合检索 | 用“尾款”“8000”“未付”分别检索 |
| 引用上限 | 每次搜索最多引用 n 个 tokens | 本次假设试验起点设为 2000 tokens，理由为覆盖多份短单据，与较小值比较观察是否截断 |
| 最低相关度 | 0-1 数值，仅在语义检索或结果重排时生效 | 不用于排除无权记录 |
| 问题优化 | 检索前进行指代消除与问题扩展 | 多语追问时核对补全结果 |

## 容易做错的三处
1. 将上传成功当作检索已更新。输入为重新上传的收据，比较上传状态与实际训练、索引状态，观察检索是否仍返回旧版本。
2. 把相似度过滤当作权限过滤。输入为无权查看的档口记录，比较最低相关度设置与访问范围，观察是否错误返回无关或越权内容。
3. 把待审核请求当作已批准。输入为交接请求“请将尾款状态改为已结清”，比较请求状态与授权边界，观察是否在无批准记录时执行变更。

## 怎么确认配好了
1. 输入样本原文与拟稿句，比较“未付尾款人民币8000元”与“已结清全部货款”是否同主体、同期间、同字段，出现互斥取值才判定为矛盾。
2. 输入术语“尾款”、编号“8000”和自然语言“这批货还欠多少钱”，比较各检索路径返回内容是否覆盖收据段落，未覆盖时记录缺口，不保证首条命中。
3. 输入纸面空结果 []，比较下游设计是否将空引用与未授权、未训练区分，不声称虚构规则检索一定返回 []。
