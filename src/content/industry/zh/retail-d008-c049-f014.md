# 批发市场档口交易的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样
批发市场档口交易的现场议价与托运安排更零散，进货单、手写销售单、摊位租赁合同、货款收据往往同日产生且格式不一。跨境资料与多语检索要处理这些材料的翻译与查找，数据按日、每单更新。模型接入与配置因此需要先确定语言模型与索引模型可用，再核对渠道与模型 ID 的对应关系。

## 这些特征在「模型接入与配置」这一环带来什么约束
AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。模型 ID 是接口请求 Body 中 model 字段的值，全局唯一；模型映射把 FastGPT 请求的模型映射到上游实际模型。检索库的向量模型要求属于检索侧条件，不能扩展为外部工商网站或其他系统也必须同模型。语义召回与相关度不承担权限或实体隔离。

假设演练样本：一份手写销售单原文为“2026年3月12日，档口A向采购商B售出干辣椒40箱，单价与总价另议，托运由买方安排，尾款未结”。一份摊位租赁合同原文为“出租方C与承租方D约定，2026年4月1日起租，月租金另议，押金未载明”。一条待判定拟稿句为“该销售单与租赁合同均已结清并完成托运”。材料未载明结清、托运完成或押金状态。

## 配置怎么定
下表为本页相关的官方已说明设置或实施核对项。本次假设试验起点仅用于演练比较，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不附加 /v1 | 与服务端配置比对，确认非空 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空管理员 Token | 核对一致，确认未用应用 API Key 代替 |
| 模型映射 | 将 FastGPT 模型 ID 映射到上游模型 | 比对模型 ID 与渠道模型字段 |
| 语言模型与索引模型 | 各至少启用一个 | 在模型提供商页面核对启用状态 |
| 模型探测间隔 | 本次假设起点 30 分钟 | 与 5～60 分钟范围比较 |
| 告警 Webhook 地址 | 本次假设起点为空 | 为空时不推送，核对配置状态 |

## 容易做错的三处
1. 把模型映射当成授权：映射只改变上游 model 字段，不改变材料是否结清、托运是否完成。检查输入为映射配置与销售单原文，比较映射前后 model 值，观察映射生效但结清状态仍为未载明。
2. 把相关度当成实体过滤：相关度不排除无关业务或未授权记录。检查输入为检索请求与租赁合同原文，比较返回条目与合同主体，观察返回内容不因分数高低而改变授权状态。
3. 把待审核当成已批准：待审核不证明缺少操作权限，也不等于执行完成。检查输入为拟稿句与两份材料，比较“已结清并完成托运”与原文，观察原文未载明该状态，判定为未获支持。

## 怎么确认配好了
1. 输入为上述销售单原文与拟稿句“该销售单与租赁合同均已结清并完成托运”。比较拟稿句中的结清、托运完成与原文记载。原文只载明售出、托运由买方安排、尾款未结，未载明结清与托运完成，判定为未获支持。
2. 输入为上述租赁合同原文与同一拟稿句。比较合同中的起租日、租金与押金字段。合同未载明押金与结清状态，判定为待核实，保留证据缺口。
3. 输入为一条明确纸面空结果 [] 与下游设计。比较空结果承接逻辑与文档所述空引用输出条件，观察下游是否按空输入处理；不声称虚构规则检索一定返回 []，缺失证据保持缺失。
