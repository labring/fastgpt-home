# 拼多多低价活动店铺运营的跨境资料与多语检索：文档解析与分块

## 这个品类的数据长什么样
拼多多低价活动店铺运营围绕活动资源位、活动库存与退款率波动展开，日常材料包括活动报名表、商品成本测算表、售后退款单与平台站内信。跨境资料与多语检索场景下，同一批材料可能同时存在中文原文与外语版本，检索需求落在术语、活动编号与自然语言问法三类输入上。资料更新频率以日、每场活动为节奏，文档解析与分块需要在每场活动前后都能回指原文，保留能定位到具体材料与版本的文档身份。材料中的活动价、库存数量与退款状态属于同一字段的不同取值，分块时若把条件句与所约束的数值拆开，检索结果会失去判断依据。

## 这些特征在「文档解析与分块」这一环带来什么约束
知识库由库、集合和数据三部分组成，最小搜索单位是库，集合仅用于分类管理。一组原数据可对应多个向量索引，检索时先召回向量，再按向量 ID 回 MongoDB 的 dataset.datas 取原数据，同一组原数据取最高得分合并。分段应保持结构与语义完整，条件、说明与所约束内容留在同一数据块内。语义检索具备跨多语言理解能力，输入中文问题可匹配外语知识点；全文检索依赖关键词命中，适合活动编号、错误码与专有名词。混合检索通过 RRF 融合多路结果，重排模型给出 0-1 得分用于过滤。最低相关度仅在语义检索或结果重排时生效，引用上限以 tokens 为单位控制。检索环节不承担权限或实体隔离，跨不同向量模型的库不可共同关联，需先核对标识并排除不符合者。

## 配置怎么定
以下配置项围绕本页样本，只列官方已说明的设置或实施核对项。数值为本次假设试验起点，用于与同字段其他取值比较，不代表官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 样本含活动编号与自然语言问法，需同时覆盖语义召回与全文召回 |
| 最低相关度 | 0.4 | 用于过滤低相关结果，与 0.2、0.6 比较观察召回范围变化 |
| 引用上限 | 2000 tokens | 控制引用内容长度，与 1000、4000 比较观察答案完整性 |
| 问题优化 | 开启 | 样本含多轮指代，与关闭状态比较连续追问检索效果 |
| 结果重排 | 启用 | 候选结果较多时二次排序，与不启用比较排序稳定性 |
| 分段核对 | 人工核对原文结构 | 确认条件与数值未被拆离，与仅看解析结果比较 |

## 容易做错的三处
1. 把同一组原数据的多个向量索引误认为多组独立数据。检查输入为样本材料原文与解析后的数据块列表，比较原数据标识与 indexes 字段记录，观察同一原数据是否只出现一次并对应多个向量 ID。
2. 将最低相关度当作权限或实体过滤条件。检查输入为含活动编号的检索词与目标库范围，比较返回结果是否仅由相似度决定，观察无关业务记录是否仍可能被召回。
3. 把上传成功当作检索已更新。检查输入为变更后的材料与检索请求，比较训练与索引状态记录，观察检索结果是否仍指向旧版本内容。

## 怎么确认配好了
假设演练样本：材料原文为「2024年8月1日至8月7日，A款商品活动价9.9元，活动库存500件，报名状态为已提交。」待判定拟稿句为「A款商品活动价9.9元，供货期限至8月31日。」原文只载明活动期间与报名状态，未载明供货期限，该拟稿句未获支持，需记录证据缺口。另一条交接请求为「请确认A款商品报名是否已通过。」原文仅载明报名状态为已提交，待审核不证明已通过，该请求应标记为待核实。

- 验证一：输入上述材料原文与拟稿句，比较拟稿句中的活动价、活动期间与原文同字段取值，观察拟稿句数值与原文一致且供货期限字段在原文中无对应记载，判定为部分获支持、部分未获支持。

- 验证二：输入检索词「A款 活动价」与「活动库存 500」，比较语义检索与全文检索返回的数据块，观察含活动编号与数值的数据块是否被召回，且条件句与数值是否位于同一数据块内。

- 验证三：输入空结果对照，以明确的纸面输入 [] 核对下游设计，观察下游在无引用内容时的处理路径是否按设计执行，不声称虚构规则检索一定返回 []。

检索检查只记录观察与失败分支：若首条未命中，核对分段完整性与检索词主体；若返回内容包含无关片段，核对最低相关度与引用上限设置。跨不同向量模型的库先核对标识并排除不符合者，不执行跨模型检索比较漏召回。文档总流程图列出的可选路径不代表每次请求全部执行，图片检索须有相应图像输入及模型能力，重排须具备模型且按设置启用。
