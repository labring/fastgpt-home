# 渠道窜货稽查的跨境资料与多语检索：工作流编排

## 这个品类的数据长什么样

在渠道窜货稽查的跨境资料与多语检索中，本页说明FastGPT的工作流编排如何衔接资料。多语渠道线索保留出库、目的地和待核状态，各语言分支都应回到同批原文。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟中文记录只说明本批从某仓出库，目的地尚待核；英文练习对照同样保留未定去向。另批历史记录提到销售地区。工作流可按问题整理两语原文或请求目的方材料，但每路需保留批次与地点角色。发货仓不是销售地区，缺目的信息也不证明无异地流向。语言切换只改变提问和承接文字，不能自行确认渠道行为或使旧批材料适用本批。

## 配置怎么定

| 多语流向路径 | 本题对象 | 实际核验 |
| --- | --- | --- |
| 出库仓 | 地点起点 | 非销售地 |
| 目的信息 | 本批待核 | 保留缺项 |
| 旧批记录 | 另一批地区 | 不串用 |
| 两语承接 | 相同状态 | 核实际输入 |
| 业务结论 | 调查另有依据 | 分支不处罚 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

出库地点被写成销售地区时，核地点角色；他批去向进入本批答复时，核对象与期间；中文待核在英文承接变成已查实时，对照两语原句及实际传入。三处分别查角色、批次与状态。

## 怎么确认配好了

验收分别问什么地点有依据、哪批仍待查，比较两语分支接收及引用。补目的方记录先核同批，再更新对应信息；调查结论仍需其真实依据。查询或写回实际业务系统须另验权限和回执，语言分支不执行稽查或处罚。 双语核对记录保留调出地、目的地与已确认程度三个字段，目的地缺证时，两种语言均应指向同一待核事项。
