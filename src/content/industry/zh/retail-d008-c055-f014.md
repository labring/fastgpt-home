# 特许加盟备案管理的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样
特许加盟备案管理处理的是法律披露和商务部门系统，不处理具体铺位工程。日常文档包括特许经营合同、操作手册、备案材料、信息披露文件，来源为商业特许经营信息管理系统、企业证照、门店清单与合同台账。跨境资料与多语检索的难点在于同一份合同的中文正本与译文可能并存，门店清单可能含境外地址，检索时需要按语言与文件类型分别核对。资料更新为不定期或按年，本页不依赖同步频率。

## 这些特征在「模型接入与配置」这一环带来什么约束
多语检索要求索引模型对中英文本都能生成向量，系统至少需要一个语言模型和一个索引模型才能正常使用。模型 ID 是接口请求 Body 中 model 字段的值，全局唯一；模型名仅用于展示。一个模型可配置在不同渠道中实现负载均衡。渠道优先级范围 1～100，数值越大越容易被优先选中。模型状态探测仅针对已启用的系统模型，未启用模型不参与探测。

假设演练样本：某特许人总部法务准备一份中英双语加盟合同台账检索请求。供核对材料原文为：「甲方授予乙方在上海市静安区经营『示例品牌』加盟店的权利，合同期限自2026年1月1日至2028年12月31日。」另一份英文披露文件写：「The franchisor grants the franchisee the right to operate in Jing'an District, Shanghai.」待判定拟稿句为：「该加盟合同期限为三年，覆盖静安区。」此样本仅用于说明核对方法，不代表真实客户或已发生的业务。

## 配置怎么定
下表只列与本页主任务相关的已说明设置或实施核对项。假设试验起点仅用于本次纸面对照，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 核对对象与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不附加 /v1 | 与部署实际地址比较，确认不含 /v1 或 /chat/completions |
| AIPROXY_API_TOKEN | 非空管理员 Token | 与服务端配置比较，确认一致且未用应用 API Key 代替 |
| 索引模型 | 启用一个支持中英的索引模型 | 与样本中英文本分别核对，确认同一模型可处理两种语言 |
| 模型 ID | 与渠道中模型字段一致 | 与请求 Body 的 model 值比较，确认全局唯一且映射正确 |
| 渠道优先级 | 本次假设试验起点设为 50 | 与另一渠道的优先级数值比较，确认选中顺序符合预期 |
| 模型状态探测 | 仅对已启用模型开启 | 与启用列表比较，确认未启用模型不产生探测记录 |

## 容易做错的三处
1. 把相似度分数当作权限或实体过滤条件。检索相似度不排除未授权记录，也不隔离不同加盟主体的材料。检查方式：输入样本中英两段原文，观察返回结果是否包含其他主体的合同片段，若包含则说明过滤未生效。
2. 将跨模型向量库共同关联。不同索引模型生成的向量不可共同关联。检查方式：核对两个库的模型标识，若标识不同则排除共同检索，记录实际观察结果。
3. 把待审核状态当作已获授权。样本中拟稿句的合同期限来自原文，但若某字段仅有相关阶段证据，应标为未获支持。检查方式：逐字段对照原文，同主体同期间同字段明确互斥才判矛盾，否则记录待核实。

## 怎么确认配好了
1. 针对样本原文与拟稿句，输入中英两段材料，比较拟稿句中的「三年」「静安区」是否与原文的起止日期和区域一致。若一致则满足条件；若拟稿句出现原文未载明的授权范围，则标为未获支持。
2. 针对空结果分支，以纸面输入空数组核对下游设计，观察下游是否按空结果处理。不声称虚构规则检索一定返回空数组。
3. 针对模型状态探测，核对已启用模型列表与探测记录，观察未启用模型是否出现探测条目。若出现则说明探测范围配置有误。以上均为纸面核对，未实际执行部署或测试。
