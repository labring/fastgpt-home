# 生鲜临期折价处理的跨境资料与多语检索：向量模型与索引

## 这个品类的数据长什么样

在生鲜临期折价处理的跨境资料与多语检索中，本页说明FastGPT的向量模型与索引如何衔接资料。保留批次标签与拟议处理的区别，两语索引不从日期文字推定商品可售或处理已执行。所用场景为自拟文字测试。

## 这些特征在「向量模型与索引」这一环带来什么约束

生鲜处理资料练习可拟便笺“标签批次已登记，处理方案另核”，英文对照保留recorded batch label与pending plan review。另一份旧陈列表属于上一批商品，没有本批处理确认。若索引把标签已记简写成discount applied，就把记录工作变成已执行处理；若从标签文字补出商品仍可售，也超过现有资料。日期、批次、外观记录及处理决定各有不同用途，原文没有实物检查结论时，应明确现有证据只能支持哪些字段。本例不提供食品状态或可食用判断。

## 配置怎么定

| 批次处理多语核对 | 自拟材料 | 检查动作 |
| --- | --- | --- |
| 登记状态 | 已记标签批次 | 不能写成方案已执行。 |
| 方案阶段 | 处理安排待核 | 核本批实际决定与记录。 |
| 批次身份 | 上一批陈列表 | 不替本批作状态证明。 |
| 标签范围 | 只有纸面标签信息 | 不新增商品可售或实物结论。 |
| 补入记录 | 检查与执行各有对象 | 核同批身份、记录性质和事件时间。 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `向量模型` | 同一检索节点关联的库需使用相同向量模型。 |
| `原数据与索引` | 一条原数据可关联多条索引。 |
| `索引内容` | 索引内容应完整且聚焦。 |
| `图片索引` | 采用图片检索时核描述或图片向量。 |
| `版本与结果复核` | 变更后复用同题比对原文。 |

## 容易做错的三处

- 批次登记被入口写成处理已执行时，核登记原句、方案和本批执行记录，定位新增动作。

- 上一批陈列信息被用于本批状态时，核批次与商品身份，不以品名相同沿用旧结论。

- 仅有标签文字却回答商品可售时，核实际适用检查依据和决定，索引命中不能提供实物状态。

## 怎么确认配好了

验收用中英分别问记录了什么、方案是否已核、哪一批有处理凭证，逐条查看实际引用。补入检查或处理记录后先核同批对象与记录性质，再分别比较结论，不将登记时间当作检查时间。同一原数据增加多索引时保留批次与阶段限定，若共同关联多个库，在同一搜索节点核向量模型一致。跨语问答只做资料追踪，不执行折价、报损或上架，也不代替真实食品检查与业务决定。
