# 生鲜临期折价处理的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

临期折价处理围绕货架库存生命周期展开，资料以临期清单、折价审批、报损单和促销价签为主。门店巡检与POS库龄按日或班次更新，同一批次商品在不同语言的门店记录里可能使用不同名称。跨境资料与多语检索要求把这些材料送入知识库后，能够按批次、日期和状态被检索到，检索结果只呈现文档内容，不改变审批或销售状态。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务都需要设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。语言模型与索引模型是系统运行的最低要求，索引模型决定文本块能否被检索。模型渠道配置中的模型映射只改变向上游发送的 `model` 值，不改变文档的授权状态。检索按向量模型建立关联，不同向量模型的库不能共同关联。

假设演练样本：一份门店交接材料原文为“2026年3月10日班次，批次A-0310的临期折价审批单已由店长签字，折价幅度待财务稽核确认；该批次促销价签尚未打印。”另一份材料为“2026年3月10日，批次A-0310报损单已提交，状态为待审核。”拟判定句为“批次A-0310已完成折价审批并可执行折价销售。”核对范围限于这两份材料。

## 配置怎么定

| 核对项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 假设填 `http://aiproxy:3000` | 文档要求填根地址且不附加 `/v1`；与文档示例格式逐字符比较 |
| `AIPROXY_API_TOKEN` | 假设填非空管理员 Token | 文档要求与服务端一致且不能为空；与 AI Proxy 服务端配置比较 |
| `AGENT_ENGINE` | 假设保持 `fastAgent` | 文档列出 `fastAgent` 与 `piAgent` 两个可选值；按实际部署选择比较 |
| 索引模型启用状态 | 假设启用一个索引模型 | 文档说明系统至少需要一个语言模型和一个索引模型；核对启用列表 |
| 模型渠道模型映射 | 假设将请求模型映射到实际上游模型 | 文档示例 `gpt-4o-test` 映射为 `gpt-4o`；核对映射前后名称 |
| 向量库标识 | 假设同一批资料使用同一向量库 | 文档说明不同向量模型的库不可共同关联；比较库标识是否一致 |

## 容易做错的三处

1. 把拟判定句中的“已由店长签字”当作折价审批完成。原文写的是“折价幅度待财务稽核确认”，签字与稽核确认属于不同字段，比较时应看同一字段是否有互斥取值。
2. 把报损单“待审核”读成“已报损完成”。待审核只是提交后的状态，材料未载明审核结果，该字段属于未获支持。
3. 把检索到的临期清单当成折价授权。检索只返回文档内容，不执行审批、不写入数据库、不同步外部系统。

## 怎么确认配好了

1. 输入假设样本中的两份材料原文与拟判定句，比较“折价幅度待财务稽核确认”与拟判定句的“已完成折价审批”，若材料未出现稽核完成记录，则拟判定句未获支持。
2. 输入报损单原文“状态为待审核”，比较是否存在审核通过或驳回的记录，若只有待审核字段，则报损完成状态待核实。
3. 输入同一批次的临期清单与促销价签材料，比较向量库标识是否一致，若标识不同，则记录为不可共同关联并保留缺口，不执行跨库比较。
