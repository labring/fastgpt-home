# 生鲜水果门店采购的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

生鲜水果门店采购的资料围绕采购单、验收单、农残检测报告和损耗记录展开，来源包括批发市场行情、供应商报价、门店销售与检测报告。与便利店鲜食订货相比，水果采购依赖批发市场行情和等级验收，缺少总部标准餐食作为统一基准。跨境资料与多语检索场景下，同一批次的采购单、验收单可能由不同语言填写，农残检测报告也可能来自境外机构，资料更新频率为日或每批。这些差异意味着模型接入后需要按资料类型分别核对，检索结果不能替代采购或验收的授权判断。

## 这些特征在「模型接入与配置」这一环带来什么约束

系统至少需要一个语言模型和一个索引模型才能正常使用。AI Proxy 为必需依赖，App 和复用 App/Service 配置的 Admin 服务都必须设置 `AIPROXY_API_ENDPOINT` 和非空的 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。`AIPROXY_API_ENDPOINT` 填写服务根地址，不附加 `/v1`。旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两个配置。模型能力按应用所需输入核对，多模态、工具调用分别验证。应用参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。检索是召回过程，不承担授权或实体隔离职责。

假设演练样本：以下为纸面核对材料，非真实客户数据。

材料原文一：“采购单 PO-2025-0417，采购方为某水果门店，供应商为境外果园 A，品项为鲜食葡萄，数量 200 箱，交货日期 2025 年 4 月 20 日，验收标准按等级验收。”

材料原文二：“验收单 RC-2025-0420，对应采购单 PO-2025-0417，验收日期 2025 年 4 月 20 日，实收 200 箱，等级合格，验收人签字栏空白。”

待判定拟稿句：“本次采购已完成验收，损耗记录已归档。”

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式与理由 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填写 AI Proxy 根地址，例如 `http://aiproxy:3000` | 与文档要求比对，确认不附加 `/v1`；缺少则启动校验失败 |
| `AIPROXY_API_TOKEN` | 填写与服务端一致的管理员 Token | 确认非空且与服务端一致；不能用应用 API Key 代替 |
| 语言模型与索引模型 | 各启用至少一个 | 系统至少需要一个语言模型和一个索引模型才能正常使用 |
| 模型能力核对 | 按采购单、验收单的文本输入核对 | 多模态、工具调用分别验证，不假设同名字段覆盖编排 |
| 检索范围核对 | 按采购单、验收单、检测报告分别标识 | 跨不同向量模型的库不可共同关联，先核标识并排除不符者 |

## 容易做错的三处

1. 把检索结果当成验收授权。材料原文二显示验收人签字栏空白，检索命中验收单不等于验收已完成，签字栏空白属于未获支持的证据缺口。
2. 把 `AIPROXY_API_ENDPOINT` 填成完整请求地址。文档要求填写服务根地址，不附加 `/v1`，附加后启动校验会失败。
3. 用旧 OpenAI 环境变量替代 AI Proxy 配置。文档明确旧变量不能替代 `AIPROXY_API_ENDPOINT` 和 `AIPROXY_API_TOKEN`。

## 怎么确认配好了

1. 输入材料原文一与材料原文二，比较采购单号与验收单号是否一致。若两单号一致且验收人签字栏空白，则拟稿句中“已完成验收”未获支持，应记录为待核实。
2. 输入 `AIPROXY_API_ENDPOINT` 的配置值，比较是否附加了 `/v1` 或 `/chat/completions`。若附加了路径，则与文档要求不符，启动校验可能失败。
3. 输入待判定拟稿句“本次采购已完成验收，损耗记录已归档”，比较材料原文中是否载明损耗记录。若材料未载明损耗记录，则该句关于归档的部分未获支持，应保留证据缺口。
