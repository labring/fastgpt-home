# 生鲜称重分拣的跨境资料与多语检索：引用来源与溯源

## 这个品类的数据长什么样
生鲜称重分拣发生在仓内履约环节，核心数据围绕重量与规格展开，主要来自 WMS、电子秤、订单系统和质检照片，日常文档包括分拣任务单、称重标签、少称补偿单和质检记录。这些材料的更新频率为每单或每日。跨境资料与多语检索场景中，同一批分拣任务可能对应不同语种的称重标签和补偿说明，引用来源与溯源要求每一条回答都能回到具体的任务单、标签或质检记录原文。资料更新频繁意味着引用时必须核对版本，不能把历史版本的称重数据当作当前有效记录使用。

## 这些特征在「引用来源与溯源」这一环带来什么约束
知识库搜索节点输出的引用内容以数组格式呈现，长度可以为 0，意味着即使没有搜索到内容，输出链路也会走通。这一节点行为决定了溯源核对不能假定每次检索都有结果。关联知识库时，只能选择相同向量模型的知识库用于向量搜索，跨不同向量模型的库不可共同关联，核对时先检查向量模型标识并排除不符合者，不执行跨模型检索来比较漏召回。最低相关度是过滤阈值，仅在语义检索或使用结果重排时生效，该数值不承担权限或实体隔离功能，检索本身不构成授权。混合检索通过 RRF 融合多路结果，重排模型按设置启用，图片检索需要相应的图像输入及模型能力，这些可选路径不代表每次请求全部执行。引用上限以 tokens 为单位控制每次搜索最多引用的内容量，该参数与思考预算无关，思考预算仅控制模型思考强度。

## 配置怎么定
下表围绕本页假设演练样本列出与本功能、主任务相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 仅勾选向量模型标识相同的两个库 | 核对向量模型标识字段，排除标识不同的库 |
| 搜索模式 | 混合检索 | 与语义检索单独使用时的召回范围比较，观察编号类查询是否命中 |
| 最低相关度 | 假设起点 0.3 | 与 0.5 比较，观察返回条目数量变化，确认阈值仅作用于语义检索或重排 |
| 引用上限 | 假设起点 2000 tokens | 与 1000 tokens 比较，观察引用内容是否被截断，确认单位为 tokens |
| 问题优化 | 开启 | 与关闭时比较连续追问的检索结果，观察指代消除是否生效 |
| 结果重排 | 启用 | 与未启用时比较候选排序，观察重排得分是否用于过滤 |

## 容易做错的三处
1. 把检索输出当作授权执行。知识库搜索节点输出引用数组，该输出仅表示检索到的内容，不表示任何业务审批或授权状态。待审核的少称补偿单不证明缺少操作权限，检索到该单据也不等于补偿已获批准。
2. 把跨向量模型的知识库强行关联。相同向量模型才可共同关联，核对时应检查向量模型标识并排除不符合者，不编造共同关联后的漏召回或冗余结果。
3. 把最低相关度当作权限或实体过滤器。该数值仅在语义检索或结果重排时生效，不负责排除无关业务或未授权记录，检索结果仍需结合有效版本审核。

## 怎么确认配好了
假设演练样本：某前置仓分拣任务单原文为「任务单号 SF-2024-001，商品为进口车厘子，规格 2kg 装，分拣员已完成称重，实际重量 1.95kg，质检记录显示外观完好，少称补偿单状态为待审核。」一条待判定拟稿句为「该任务单已完成少称补偿审批。」

- 验证一：输入上述任务单原文和拟稿句，比较拟稿句中的「已完成审批」与原文中「待审核」的状态字段，观察两者是否矛盾。预期现象为拟稿句与原文状态不一致，待审核不构成审批完成。

- 验证二：输入上述任务单原文，检查引用输出数组是否包含该原文内容，比较引用条目与原文的主体、对象和状态字段，观察引用是否逐条对应。预期现象为引用条目应与原文一致，若数组为空则记录缺口。

- 验证三：输入拟稿句和任务单原文，核对向量模型标识是否相同，比较两个知识库的向量模型字段，观察是否存在标识不一致。预期现象为标识不同的库不可共同关联，需排除后记录实际观察。

三项验证均使用上述假设原文和拟稿句，不声称已实测。空结果承接可用明确的纸面输入 [] 核对下游设计，不声称虚构规则检索一定返回 []。
