# 生鲜称重分拣的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

生鲜称重分拣发生在仓内履约环节，围绕重量与规格产生分拣任务单、称重标签、少称补偿单和质检记录。跨境资料与多语检索任务中，这些材料需要被模型读取、跨语言比对，并输出可核对的草稿。资料更新频率为每单与日，单笔任务对应一张分拣任务单，称重标签与质检记录随单生成。多语检索要求同一批材料在不同语言下保持标识一致，模型接入与配置需先解决材料进入检索范围前的标识与能力匹配问题。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy 服务。App 与 Admin 共享配置中，`AIPROXY_API_ENDPOINT` 填写服务根地址，不附加 `/v1`；`AIPROXY_API_TOKEN` 填写与服务端一致的非空管理员 Token，不能用应用 API Key 代替。缺少任一项会导致启动校验失败。模型能力按应用所需输入核对：多模态、工具调用与思考配置分别验证，参数在应用或节点配置中设置，不能假设兼容对话接口的同名字段会覆盖编排。检索关联要求同一向量模型，跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察。

## 配置怎么定

以下表格围绕本页样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 核对方式与理由 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 假设填写 `http://aiproxy:3000` | 与文档示例格式比较，确认不附加 `/v1`；此为假设起点，非官方默认 |
| `AIPROXY_API_TOKEN` | 假设填写非空字符串 | 与服务端配置比较，确认一致且非空；不能用应用 API Key 替代 |
| 模型能力 | 假设需图片输入 | 按应用所需输入核对多模态能力，与模型元数据比较 |
| 向量模型标识 | 假设两个库使用同一向量模型 | 核标识并排除不符合者，不执行跨模型检索比较 |
| 检索范围 | 假设目标材料在有权访问的检索范围内 | 确认材料可被读取，缺失时记录缺口 |

## 容易做错的三处

1. 把 `AIPROXY_API_ENDPOINT` 填成完整请求地址并附加 `/v1`。输入为配置值，比较对象为文档示例格式，可观察结果为地址是否附加路径。
2. 用应用 API Key 充当 `AIPROXY_API_TOKEN`。输入为 Token 值，比较对象为服务端管理员 Token，可观察结果为启动校验是否通过。
3. 将不同向量模型的库共同关联。输入为库标识，比较对象为向量模型标识，可观察结果为标识是否一致；不一致时排除该库并记录。

## 怎么确认配好了

假设演练样本：材料原文为“分拣任务单 A-001，对象为批次 B-2024，状态为待分拣，有效范围为 2024-06-01 至 2024-06-30；称重标签 T-001 对应批次 B-2024，状态为已打印。”拟稿句为“A-001 已完成分拣并生成补偿单。”待判定请求为“请确认 A-001 的补偿单是否已生成。”

- 验证一：输入为上述材料原文与拟稿句，比较对象为原文中 A-001 的状态字段“待分拣”，可观察结果为拟稿句声称“已完成分拣”与原文状态字段不一致，该句未获支持。

- 验证二：输入为上述待判定请求，比较对象为原文中是否存在补偿单记录，可观察结果为原文未载明补偿单，该请求的证据缺口为缺失，不能判定已生成。

- 验证三：输入为上述材料原文，比较对象为批次 B-2024 与称重标签 T-001 的对应关系，可观察结果为两者批次标识一致，且 T-001 状态为已打印；若标识不一致则排除关联并记录实际观察。
