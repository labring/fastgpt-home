# 电商仓入库上架的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

入库上架处理货物进入仓库的第一道账实确认，主要数据来源为 WMS、ERP 采购、供应商送货单与条码扫描，日常文档包括采购到货单、入库验收单、上架任务与差异报告。跨境场景下这些文档常含多语字段，收货员需要借助检索确认品名、规格与批次信息。模型接入与配置决定检索能否按预期返回可用文本，配置错误会直接影响核对到货数量与分配库位两个环节。

## 这些特征在「模型接入与配置」这一环带来什么约束

多语资料涉及不同语种文本块，索引模型与语言模型分别承担向量化与生成，系统至少需要一个语言模型和一个索引模型才能正常使用。模型 ID 全局唯一，是请求 Body 中 model 字段的值，检索关联以该标识为准。AI Proxy 为必需依赖，AIPROXY_API_ENDPOINT 填写服务根地址，不附加 /v1；AIPROXY_API_TOKEN 必须与服务端一致且非空。模型能力按应用所需输入核对，多模态、工具调用与思考配置分别验证。检索本身不承担权限或实体隔离，相似度设置不排除无关业务或未授权记录。

假设演练样本：某仓库收到供应商送货单，原文两段为「PO-2026-0417，品名 Stainless Steel Bottle 500ml，数量 1200 pcs，批次 B2409」与「到货日期 2026-04-17，收货仓 WH-SH-02，送货方签名栏空白」。待判定拟稿句为「该批 1200 pcs 已完成验收并分配库位 A-03」。核对要点：送货单载明数量与批次，签名栏空白表示送货方签署状态未载明，验收与库位分配属下游业务动作，拟稿句把未载明状态写成了已完成事实。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 文档要求根地址不附加 /v1，与带路径写法比较 |
| AIPROXY_API_TOKEN | 假设填与服务端一致的非空值 | 文档要求一致且非空，与应用 API Key 区分 |
| 索引模型 | 假设启用一个已测试通过的 embedding 模型 | 文档要求至少一个索引模型，与未启用状态比较 |
| 语言模型 | 假设启用一个已测试通过的 llm 模型 | 文档要求至少一个语言模型，与仅配索引模型比较 |
| 模型 ID | 假设沿用渠道中模型字段值 | 文档规定全局唯一，与自行改写别名比较 |
| 模型能力核对 | 假设按多语文本输入逐项验证 | 文档要求按所需输入核对，与未验证直接启用比较 |

## 容易做错的三处

1. 把拟稿句中的「已完成验收并分配库位」当作送货单已载明事实。送货单签名栏空白，验收与库位分配属下游动作，输入中无对应记录。
2. 把 AIPROXY_API_TOKEN 填成应用侧 API Key。文档要求管理员 Token 与服务端一致，两者来源不同，混用会导致启动校验失败或调用被拒。
3. 用相似度设置推断检索已排除未授权记录。相关度分数不承担权限或实体隔离，检索结果仍需人工核对主体与范围。

## 怎么确认配好了

1. 输入假设送货单原文与拟稿句，比较拟稿句是否把签名栏空白写成已签署、把未载明的验收与库位写成已完成。预期现象：拟稿句与原文状态不一致，应标记为未获支持。
2. 输入 AIPROXY_API_ENDPOINT 假设值，比较其是否附加 /v1 或 /chat/completions。预期现象：附加路径的写法与文档要求不符，需改为根地址。
3. 输入两个不同模型 ID 的检索请求，比较返回记录是否都标注同一模型标识。预期现象：跨模型不可共同关联，仅保留标识一致者，其余记录实际观察并记录缺口。
