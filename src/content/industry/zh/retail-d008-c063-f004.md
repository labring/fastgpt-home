# 直播售后集中处理的跨境资料与多语检索：向量模型与索引

## 这个品类的数据长什么样
直播售后资料集中在单场流量后形成，退款申请、补发单与话术模板往往同时出现。售后人员需要跨语言查找历史处理口径，检索结果直接影响对外解释的一致性。资料按每场后与日更新，检索环节读取的是已经入库的订单清单、退款申请、补发单和话术模板。

## 这些特征在「向量模型与索引」这一环带来什么约束
同一组原数据可以对应多个索引，索引内容与原文分别核对。关联检索的知识库须使用相同向量模型，先核实际模型与输入类型。图片能否被检索到，取决于入库时是否生成图片描述或图片向量。向量得分只反映相似度，不承担权限或实体隔离。

假设演练样本：某售后组整理一份《跨境退款话术模板》原文，含三句：“本模板适用于东南亚站点直播订单的退款解释。模板状态为待审核。适用期间为某场直播结束次日起七日。”另有一条拟稿句：“该模板已生效，可直接用于补发单解释。”待判定该拟稿句与原文是否一致。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 向量模型 | 选用一种支持多语文本的模型 | 核对该模型标识与知识库登记是否一致 |
| 关联知识库 | 仅关联同一向量模型的库 | 逐一核对模型标识，排除不符者 |
| 索引内容 | 以完整且聚焦的模板句建立索引 | 与原文逐句比对，确认主体与状态 |
| 图片索引 | 本次样本不含图片 | 记录为未涉及，不推断图片检索结果 |
| 引用上限 | 设为本次试验起点值 | 与样本实际 token 量比较后调整 |
| 最低相关度 | 设为本次试验起点值 | 仅在语义检索或重排时生效 |

## 容易做错的三处
1. 把拟稿句中的“已生效”当作原文事实。原文写“待审核”，二者同字段取值互斥，属于矛盾。
2. 将检索得分当作授权依据。得分不判断模板能否用于补发单，授权状态须另核。
3. 用不同向量模型的知识库共同关联。模型标识不一致时应排除，不执行跨模型检索。

## 怎么确认配好了
1. 输入上述三句原文与拟稿句，比较“模板状态”字段。原文为待审核，拟稿句为已生效，出现同字段互斥取值即判定矛盾。
2. 输入原文与提问“该模板适用期间”，比较返回引用是否含“某场直播结束次日起七日”。引用含该期间即满足，缺失则记录为未获支持。
3. 输入明确纸面输入空数组，核对下游设计是否承接长度为 0 的引用链路。下游正常走通即满足，不声称虚构规则检索一定返回空。
