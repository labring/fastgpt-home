# 直播间违规申诉的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

直播间违规申诉处理已经发生的处罚，需要复盘证据链。跨境场景下，违规通知、直播录屏、商品资质、申诉说明可能来自不同语言站点，检索时先要确认资料归属的店铺、违规单号与处罚期间，再判断某份材料能否支持某句申诉理由。资料随每次违规不定期产生，检索配置围绕单次申诉的文档集合展开，不承担跨店铺批量同步。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入决定多语资料能否被索引和召回。按 v4.17.2 文档，App 与复用服务配置的 Admin 必须设置 `AIPROXY_API_ENDPOINT` 和非空 `AIPROXY_API_TOKEN`，缺少任一项启动校验失败；旧 OpenAI 变量或单模型自定义地址不能替代。系统至少需要一个语言模型和一个索引模型。检索库与索引模型存在同模型关联要求，跨不同向量模型的库不可共同关联，只核标识并排除不符合者。语义召回和相关度不负责权限或实体隔离，检索不构成授权。空结果、上下文上限、同模型关联都保留文档所述条件。

假设演练样本：某跨境店铺收到一份英文违规通知，原文为“Notice ID: CN-2026-0417. This notice applies to store S-8842 and covers the live session held on 2026-04-10. The alleged violation is the display of an unverified cosmetic claim.” 同批材料含一份中文商品资质说明，落款日期 2026-03-28，未写明覆盖的店铺编号。拟稿申诉句为“该商品资质已于直播前完成备案，可覆盖本次违规时段。”该句与资质说明的落款日期相关，但资质说明未载明店铺与违规单号，属未获支持，需先补齐覆盖范围再判断。

## 配置怎么定

| 配置或核对项 | 本次假设起点及理由 | 比较方法 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填 AI Proxy 根地址，不附加 `/v1` | 与文档要求比对，确认无路径后缀 |
| `AIPROXY_API_TOKEN` | 填与服务端一致的非空管理员 Token | 与应用 API Key 区分，确认非空 |
| 索引模型启用 | 至少启用一个索引模型 | 核对系统模型列表中索引模型为已启用 |
| 检索库与索引模型 | 同库使用同一索引模型标识 | 逐库核对模型标识，排除不一致者 |
| 多语资料解析 | 按文档勾选 PDF 增强解析并配置对应服务 | 核对上传时是否勾选，未勾选走内置解析 |
| 模型探测 | 假设开启自动探测，间隔按文档 5～60 分钟取整 | 与文档区间比较，确认取值为整数 |

## 容易做错的三处

1. 把检索命中当作授权。输入为上述英文通知与中文资质说明，比较检索结果与拟稿句的覆盖范围，若资质说明未载明店铺与违规单号，该句仍属未获支持，检索到文档不表示申诉理由成立。
2. 跨不同向量模型的库共同关联。输入为两个索引模型标识不同的检索库，比较模型标识，标识不一致时排除该库，不执行跨模型检索来比较漏召回。
3. 用相似度设置排除无关业务或未授权记录。输入为一次普通查询，比较返回结果与权限边界，相关度分数不承担实体或权限过滤，未授权记录是否出现取决于下游权限实现，属未知。

## 怎么确认配好了

1. 输入上述英文通知原文与拟稿句，比较拟稿句所称“已完成备案”与资质说明实际载明的落款日期和覆盖范围，只有资质说明载明店铺编号与违规单号且日期早于直播时段，该句才获支持；当前材料缺失这些字段，记录为待核实。
2. 输入两个索引模型标识不同的检索库，比较标识是否一致，一致才允许共同关联，不一致时排除并记录实际观察，不推断运行结果。
3. 输入一份明确的纸面空结果 `[]`，比较下游设计是否按空结果处理，不声称某虚构规则检索一定返回 `[]`；同时核对 `AIPROXY_API_ENDPOINT` 无 `/v1` 后缀且 `AIPROXY_API_TOKEN` 非空，作为启动校验的核对项，不表示已完成部署或测试。
