# 达人专场带货合作的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

达人专场带货合作围绕外部达人履约与佣金结算展开，日常材料集中在达人合作协议、佣金设置单、样品寄送单与直播战报。跨境资料与多语检索要处理的是这些材料在语言、版本与主体上的差异：同一场合作可能同时存在中文协议与外文佣金确认，达人历史数据与店铺成交明细分属不同来源。检索结果用于人工核对，不构成授权。材料更新频率为每场与每周，本页不据此推出批量同步或交易触发机制。

## 这些特征在「模型接入与配置」这一环带来什么约束

模型接入依赖 AI Proxy。App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。系统至少需要一个语言模型和一个索引模型。模型 ID 全局唯一，模型别名可自定义。语义召回与相关度不承担权限或实体隔离；检索库与向量模型标识需先核对，跨不同向量模型的库不可共同关联。

假设演练样本：某品牌商务留存一份《达人专场合作确认》纸面摘录，原文为“甲方：星野贸易有限公司；乙方：达人林某；合作场次：2026年9月20日专场；佣金比例：按结算单执行；样品寄送：已寄出，签收状态未回传。”同批留存一份佣金设置单摘录：“场次2026年9月20日，佣金比例15%，状态：待审核。”待判定拟稿句为“该场合作佣金比例已确认，可据此结算。”核法所需资料须在有访问权的目标检索范围或明确人工输入中，缺失时记录缺口。

## 配置怎么定

| 配置项 | 本页假设起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000`，理由为官方示例根地址形式 | 与部署实际服务根地址比较，确认未附加 /v1 |
| AIPROXY_API_TOKEN | 假设填入与服务端一致的非空管理员 Token | 与 AI Proxy 服务端配置比较，确认非空且一致 |
| 语言模型 | 假设启用一个已测试通过的语言模型 | 在模型渠道测试后与启用状态比较 |
| 索引模型 | 假设启用一个已测试通过的索引模型 | 与系统至少一个索引模型的要求比较 |
| 模型 ID | 假设与渠道中模型字段一致 | 与渠道配置的模型字段逐字比较 |
| 检索库向量模型标识 | 假设记录为同一标识 | 与目标库标识比较，不符者先排除 |

以上数值均为本次假设试验起点，不是官方默认值。

## 容易做错的三处

1. 把佣金设置单的“待审核”当作已确认。输入为两份摘录，比较字段为佣金比例状态，观察结果为设置单状态仍为待审核。
2. 用 AIPROXY_API_TOKEN 之外的应用 API Key 代替管理员 Token。输入为环境变量填写值，比较对象为服务端管理员 Token，观察结果为两者不一致。
3. 将语义召回分数当作权限过滤。输入为一次检索请求，比较对象为记录归属主体，观察结果为分数高低不改变无权记录的可见性。

## 怎么确认配好了

1. 输入上述两份摘录与拟稿句，比较拟稿句“佣金比例已确认”与设置单状态“待审核”，观察结果为该句未获支持，记录为待核实。
2. 输入 AIPROXY_API_ENDPOINT 填写值，比较是否附加 /v1 或 /chat/completions，观察结果为未附加才满足条件。
3. 输入两个检索库的向量模型标识，比较是否一致，观察结果为标识不一致时排除共同关联，仅记录实际观察，不推断漏召回或冗余结果。
