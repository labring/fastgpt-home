# 进出口许可证件办理的跨境资料与多语检索：工作流编排

## 这个品类的数据长什么样

在进出口许可证件办理的跨境资料与多语检索中，本页说明FastGPT的工作流编排如何衔接资料。双语许可材料传递保留持证人、签发日期与有效期字段的身份，不在译文中合并申请角色。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

本题自拟一份英文证件摘录和中文办理便笺：摘录分别标holder、issued和valid until，未填真实名称或日期；便笺说代理代递资料，申请企业与持证人的对应尚待核。货物说明只覆盖列明型号。先把这几段按文件及字段收集，再让人员选择核日期含义或补主体对应。递交代理不自动成为持证人，签发时点与有效期截止也不能合为同一天；本页不判断许可类别或实际证件效力。

## 配置怎么定

| 许可双语字段传递 | 自拟原文 | 逐项取证 |
| --- | --- | --- |
| 持证角色 | holder与代递人分开 | 对便笺及接收主体 |
| 日期含义 | issued与valid until | 不换成收件日 |
| 商品范围 | 仅列明型号 | 后续保留限定 |
| 选择路径 | 日期词义或主体对应 | 检查实际承接 |
| 正式办理 | 未给真实批准 | 另核主管流程 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

- holder在中文承接中被填成递交代理时，逐项对英文持证字段、代理便笺和后续收到的主体，查角色在何处被替换。

- valid until被转成申请收件日时，比较两份自拟文件的字段含义和采用句，日期值即使能解析也不能换事件名称。

- 仅列明型号的货物说明进入下一步却丢掉型号限定时，查输入片段与下游引用范围，不由同一证件标题扩大到其他商品。

## 怎么确认配好了

验收在两条路径各保留文件身份、原字段及中文解释，分别问谁被列为持证人、哪项表示截止、覆盖哪个型号。补主体关系只解决该关系，日期或许可批准仍按各自原件核。对照提交与接收内容可发现标签翻译或字段丢失；不预设任何实际接口字段名，也不发明官方证件译名。正式递交、有效性判断与外部回填需主管业务流程和授权，语言路由不签证或确认资格。
