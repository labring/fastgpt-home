# 进出口许可证件办理的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样
许可证办理发生在申报之前，决定货物能否合法进出口，这一时点差异使资料核对带有前置约束。日常材料包括自动进口许可证、两用物项许可证、合同与产品说明，来源涉及商务主管部门系统、海关商品编码、供应商资料与客户用途说明。资料更新不定期，按每票处理，同一商品在不同票次可能对应不同证件与用途表述。跨境资料与多语检索要处理的是这些材料的字段提取与跨语言比对，模型接入与配置负责让语言模型与索引模型可用，不承担证件真伪判断或审批状态确认。

## 这些特征在「模型接入与配置」这一环带来什么约束
模型接入依赖 AI Proxy 服务，App 与 Admin 的共享变量中，AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 为必填，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填写服务根地址，不附加 /v1。模型渠道配置中的代理地址填写 BaseUrl，模型映射把系统内模型标识映射到上游实际模型。系统至少需要一个语言模型和一个索引模型才能正常使用。检索结果的相关度不构成权限或实体隔离，检索库的向量模型一致性要求限于同一检索库范围，不延伸到外部系统。

假设演练样本：某票货物材料原文为「自动进口许可证，申请主体：华东某机械贸易公司，商品：数控车床，许可证有效期至二〇二六年十二月三十一日，用途：自用生产设备」。交接请求为「请依据上述材料确认该票可凭此证办理进口申报」。该样本仅用于纸面核对，不涉及真实主体或编号。

## 配置怎么定
配置围绕样本的检索与比对需求确定，下列数值为本次假设试验起点，用于人工核对，不作为官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 根地址 | 与服务端实际部署地址比较，确认未附加 /v1 |
| AIPROXY_API_TOKEN | 填写非空管理员 Token | 与服务端配置比较，确认一致且非空 |
| 语言模型 | 启用一个 | 与索引模型成对，满足系统最低要求 |
| 索引模型 | 启用一个 | 与语言模型成对，用于文本块检索 |
| 模型映射 | 系统标识映射到上游模型 | 与渠道内实际模型名比较，确认可解析 |
| 模型测试 | 对已配置渠道执行 | 与测试返回的模型列表比较，确认各模型有结果 |

## 容易做错的三处
1. 把 AIPROXY_API_ENDPOINT 写成含 /v1 的完整请求地址，输入为带路径的地址，比较对象为文档要求的根地址，可观察结果是启动校验或渠道请求出现地址类错误。
2. 用应用 API Key 充当 AIPROXY_API_TOKEN，输入为应用侧凭证，比较对象为服务端管理员 Token，可观察结果是渠道调用返回鉴权失败。
3. 把检索命中的材料当作已获授权的办理依据，输入为检索返回的许可证文本，比较对象为授权状态字段，可观察结果是材料存在但授权状态未载明。

## 怎么确认配好了
1. 输入为样本原文与交接请求，比较对象为原文中是否载明授权主体、有效期与用途，可观察结果是原文仅载明申请主体与有效期，授权状态字段缺失，判定为待核实。
2. 输入为模型渠道测试请求，比较对象为测试返回的各模型结果与请求时长，可观察结果是语言模型与索引模型均返回结果，判定为接入可用；若某模型无结果，记录该模型标识与错误信息。
3. 输入为检索请求与目标检索库标识，比较对象为库所用向量模型标识与请求模型标识，可观察结果是标识一致时执行检索并记录返回条目，标识不一致时排除该库并记录未执行检索；空结果以明确的纸面输入空列表核对下游展示，不推断检索规则必然返回空。
