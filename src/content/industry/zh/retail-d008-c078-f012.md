# 连锁总部选址开店的跨境资料与多语检索：文档解析与分块

## 这个品类的数据长什么样

选址开店发生在门店营业前，核心事务围绕租赁与工程交付展开，资料以每店为单位不定期产生。选址评估表、租赁意向书、装修预算、开业排期四类文档构成主要处理对象，来源涵盖商圈客流、地图POI、POS历史店型与房东资料。这些材料常含跨境主体、双语或多语条款、金额与日期范围，中文问题匹配外文知识点属于语义检索的跨语言理解范围，取决于向量模型训练效果，精度不稳定。

## 这些特征在「文档解析与分块」这一环带来什么约束

资料结构差异直接决定分块方式。租赁意向书的条件与所约束的租金条款若被拆离，单块语义不完整，检索精度下降。同一组原数据可映射多组向量，检索命中任一向量即可召回该组数据，向量得分取最高分。原数据存于 MongoDB 的 dataset.datas，indexes 字段记录对应向量 ID；向量存于 PostgresSQL 的 vector 字段，索引为 HNSW。检索时先召回向量，再按向量 ID 回查原数据并合并。知识库搜索以库为最小单位，集合仅作分类管理。

假设演练样本：某连锁总部拓展部拟就一处境外商铺签署租赁意向书。供核对材料原文为：“甲方为物业持有人，乙方为连锁总部拓展部。意向书自双方签署之日起生效，有效期九十日。押金为三个月租金，于签署后十日内支付。”待判定拟稿句为：“本意向书签署即代表租赁合同成立，押金支付后门店可进场装修。”该拟稿句将签署、合同成立、进场三个不同事实混同，材料仅载明意向书生效与押金支付时点，未载明租赁合同成立条件与进场许可，判定为未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 依据与比较方式 |
| --- | --- | --- |
| 搜索模式 | 混合检索 | 编号与专有名词需全文命中，自然语言问法需语义召回，取两者并用 |
| 最低相关度 | 假设起点 0.5 | 仅语义检索或结果重排时生效，与样本检索的命中情况比较后调整 |
| 引用上限 | 假设起点 2000 tokens | 按 tokens 控制引用量，与返回内容长度比较 |
| 问题优化 | 暂不开启 | 样本问题主体完整，与开启后的耗时和命中比较 |
| 结果重排 | 具备模型时启用 | 混合检索范围大，无法直接相似度过滤，按重排得分过滤 |
| 分段核对 | 人工执行 | 核对条件句与所约束条款是否同块，保留文档身份与版本 |

## 容易做错的三处

1. 将上传成功当作检索已更新。资料变更后需核对实际训练与索引状态，上传动作与索引生成是两个环节。
2. 把最低相关度当作权限或实体过滤。该值是过滤阈值，不承担排除无关业务或未授权记录的功能，检索不构成授权。
3. 把语义检索的跨语言能力扩展为跨模型关联。不同向量模型的库不可共同关联，需先核标识并排除不符者，记录实际观察。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较拟稿句所述合同成立、进场许可与原文载明的生效、押金支付条款，原文未载明合同成立条件与进场许可时，判定为未获支持，不得补造授权条款。
2. 输入术语、编号与自然语言三类检索词，比较返回内容是否覆盖对应分段，观察条件句与所约束条款是否同块返回；空结果以明确的纸面输入 [] 核对下游设计，不声称虚构规则必返回空。
3. 输入含图像的问题时，先确认入库是否生成图片索引及模型是否支持图片输入，比较图片描述检索与图片向量检索的返回差异；未配置视觉模型且向量模型不支持图片时，图搜图基本不可用，记录为观察结果。
