# 连锁门店价格与陈列稽核的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样
连锁门店价格与陈列稽核发生在日常经营期，资料围绕标准持续执行产生。督导系统记录巡店过程，POS价格表反映门店实际售价，门店摄像与巡店照片承担取证作用，总部促销档期决定当期应执行的价格与陈列要求，价签清单、陈列标准与整改通知构成核对与闭环材料。这些材料以周、月为周期更新，跨境场景下可能同时存在多种语言的价签、标准文本与整改记录。

## 这些特征在「模型接入与配置」这一环带来什么约束
多语检索要求索引模型对中文、英文及其他语种文本给出可比的向量表示，检索库与向量模型必须同源，跨不同向量模型的库不可共同关联。模型接入依赖 AI Proxy，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 与非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。检索结果只承担召回，不承担权限判断，相似度设置不排除无关业务或未授权记录。图片检索须有相应图像输入及模型能力，重排须具备重排模型并按设置启用，文档流程图列出的可选路径不代表每次请求全部执行。

假设演练样本：某连锁品牌区域督导提交一份待核对材料，原文为“门店A于2026年3月第2周执行总部促销档期P-2603，价签清单显示该店当期价签已更换，巡店照片拍摄时间为2026年3月11日”。另有一条待判定拟稿句：“门店A已完成本期整改闭环”。材料未载明整改通知的签发与回复记录，拟稿句的完成状态缺少证据支持。

## 配置怎么定
配置围绕上述样本的检索与核对需要确定，只列与本功能、主任务相关的官方已说明设置或实施核对项。

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 服务根地址，不附加 /v1 | 文档要求根地址，与附加路径的写法比较可发现校验失败 |
| AIPROXY_API_TOKEN | 填写与服务端一致的非空管理员 Token | 文档要求非空且一致，与应用 API Key 比较可识别误用 |
| 索引模型 | 启用一个索引模型 | 文档要求至少一个语言模型和一个索引模型，与未启用状态比较 |
| 检索库与向量模型 | 同一向量模型对应同一检索库 | 文档要求同源，与跨模型库标识比较可排除不符者 |
| 模型探测 | 按需开启自动探测并设置间隔 | 文档支持 5～60 分钟整数，与未开启的空状态比较 |
| 文件解析并发 | 按默认队列并发处理价签与标准文本 | 文档给出 DATASET_PARSE_MAX_PROCESS 等队列并发变量，与调低后处理速度比较 |

## 容易做错的三处
1. 把相似度分数当作权限或实体过滤条件。输入为样本中门店A的巡店照片检索请求，比较返回记录是否包含其他门店或未授权材料，观察结果是相似度高低不改变记录归属。
2. 将跨向量模型的库直接关联检索。输入为两个不同向量模型建立的检索库标识，比较标识是否一致，观察结果是标识不符者应被排除，不执行跨模型检索来比较漏召回。
3. 把待审核或已提交的整改材料当作已完成闭环。输入为样本中缺少签发与回复记录的整改通知，比较拟稿句“已完成整改闭环”与材料所载状态，观察结果是完成状态未获支持。

## 怎么确认配好了
- 验证一：输入样本原文与拟稿句，比较拟稿句所述完成状态与原文所载的价签更换、照片拍摄时间，原文未载明整改通知签发与回复，拟稿句的完成结论未获支持，需记录证据缺口。

- 验证二：输入样本中门店A的检索请求与返回记录列表，比较返回记录的库标识与向量模型标识是否与请求库一致，标识不符者应排除，观察返回列表是否仅含同源库记录。

- 验证三：输入一条明确为空结果的纸面检索请求，比较下游处理是否按空列表设计承接，观察下游是否对空结果给出明确分支，不声称虚构规则检索一定返回空列表。

模型探测的故障与恢复通知按文档所述边沿变化触发，未配置 Webhook 时无推送。检索与表单收集值，业务验证、审批、数据库写入与外部同步需其声明的下游实现。
