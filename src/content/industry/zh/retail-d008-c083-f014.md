# 门店盘点与防损的跨境资料与多语检索：模型接入与配置

## 这个品类的数据长什么样

门店盘点与防损围绕账实差异和损耗展开，不处理供应商账款。日常材料包括盘点表、差异分析、报损审批和监控调阅记录，来源涉及 POS 库存、WMS、监控系统及盘点规范。跨境与多语场景下，同一批盘点资料可能以不同语言、不同格式出现，模型接入需要先解决资料能否被正确解析、检索与引用。资料更新以月、季度为主，本页不据此推导任何自动同步或交易触发机制。

## 这些特征在「模型接入与配置」这一环带来什么约束

AI Proxy 为必需依赖，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。AIPROXY_API_ENDPOINT 填服务根地址，不附加 /v1。系统至少需要一个语言模型和一个索引模型才能正常使用。模型能力按应用所需输入逐项核对，多模态、工具调用分别验证。检索是取回资料的过程，不构成授权判断；相似度得分不承担实体隔离或权限过滤职责。

假设演练样本：某门店提交一份跨境盘点资料，原文为「2026 年 3 月闭店盘点表：门店 A 乳制品货架，账面 120 件，实盘 113 件，差异 7 件，状态为待复核。」拟稿句为「该门店 3 月乳制品差异已确认并完成报损。」待判定请求为「请依据上述盘点表确认差异并执行报损审批。」

## 配置怎么定

下表为本次假设试验起点的实施核对项，数值仅为说明比较方式，不表示官方默认值。

| 配置项 | 本次假设试验起点 | 核对方式与理由 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 填写 AI Proxy 根地址 | 与服务端实际地址逐字符比较，确认未附加 /v1 |
| AIPROXY_API_TOKEN | 填写非空管理员 Token | 与服务端配置比较，确认非空且一致 |
| 语言模型 | 启用一个语言模型 | 在模型列表确认 isActive 为 true，并执行页面测试 |
| 索引模型 | 启用一个索引模型 | 确认 defaultToken 与 maxToken 已按资料填写 |
| 模型映射 | 按需填写模型 ID 映射 | 比较 FastGPT 请求模型 ID 与上游实际 model 字段 |
| 检索范围 | 限定在已授权的盘点资料库 | 人工核对资料库与访问权限，不依赖相似度得分 |

## 容易做错的三处

1. 把相似度得分当作权限过滤。输入为门店 A 的检索请求，比较对象是返回记录的业务归属，观察结果是得分高低不改变记录是否属于授权范围，需另行核对权限。
2. 把待复核状态读成已确认。输入为上述盘点表原文，比较对象是「待复核」与「已确认」，观察结果是原文未载明确认结论，拟稿句不获支持。
3. 把检索结果当成审批执行。输入为待判定请求，比较对象是检索返回与报损审批记录，观察结果是检索不产生审批动作，审批需另接下游实现。

## 怎么确认配好了

1. 输入假设样本原文与拟稿句，比较「待复核」与「已确认」是否为同一字段的互斥取值，观察结果是两者不构成同一事实，拟稿句判定为未获支持。
2. 输入待判定请求，比较请求内容与资料库中是否存在报损审批记录，观察结果是检索仅返回盘点表，审批状态仍为待核实，不判定为已执行。
3. 输入一条仅含门店 A 资料的检索请求，比较返回记录的业务归属与授权范围，观察结果是得分不排除未授权记录，需人工核对权限；若返回为空，以明确的纸面输入空结果核对下游设计，不声称规则检索必然返回空。
