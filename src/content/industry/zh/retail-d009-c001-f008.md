# B2B平台撮合交易的运营权限与交接管理：工作流编排

## 这个品类的数据长什么样

在B2B平台撮合交易的运营权限与交接管理中，本页说明FastGPT的工作流编排如何衔接资料。撮合交易交接区分联系人、意向与正式权限，工作分派不构成买卖双方承诺。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

假设平台线索只有询价联系人，买方仍在评估，接手人被分派整理供应材料。表单收交易事项、主体与原句，人员选择补买方对应或核接手权限后继续。节点记录交互并传信息，不提供买方组织目录，也不从接手姓名自动生成账号权限。本例没有真实成交或付款。

## 配置怎么定

| B2B交易交接 | 自拟材料 | 检查依据 |
| --- | --- | --- |
| 询价联系人 | 代表资格未核 | 查真实授权 |
| 买方评估 | 尚非采购确认 | 保留意向 |
| 整理分派 | 工作待办 | 非账号权限 |
| 人员选择 | 对应或权限 | 查下游限定 |
| 正式交易 | 独立确认流程 | 实际认可回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

联系人被答授权签约人时，查实际授权；评估意向被答采购确认时，对买方原文；整理分派被答可改交易记录时，查平台权限。三处分别看代表资格、交易阶段与操作边界，流程继续不证明双方已约定。

## 怎么确认配好了

验收每条选择路径收到的主体及限定，联系材料旁单列代表权限待核。补买方身份只解决对应关系，签约和平台操作仍另核。正式报价认可、交易确认及业务回填需独立授权和接口回执，交接编排只组织待办，不替另一方认可商业条件。 接手清单把联系人姓名和代表资格分栏，买方评估原句贴近交易事项；供应材料整理完毕也继续保留签约权限待核，便于后续负责人接续查证。
