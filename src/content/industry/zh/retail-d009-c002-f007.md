# MCN机构达人管理的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

在MCN机构达人管理的运营权限与交接管理中，本页说明FastGPT的对话日志与审计如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

MCN交接记录应先区分是哪次对话讨论哪位达人的哪份合作资料。自拟输入将合同解读、排期核对和账号操作请求分别注明，交接人目前只有对话说明，没有账号实际操作回执。可结合chatId核对目标会话与材料身份，但不能将一段对话存在解释成发布权限已经移交，也不能从聊天里提到某个账号推定该账号操作记录完整留存。

## 配置怎么定

| 核对对象 | 交接中的自拟材料 | 可核依据 |
| --- | --- | --- |
| 会话定位 | 达人、问题与chatId | 没有混入其他入口记录 |
| 资料版本 | 本次合同及排期说明 | 旧合作范围未沿用 |
| 运行详情 | 依契约请求detail | 实际检查responseData |
| 操作缺口 | 没有账号发布回执 | 另取业务记录，不猜未返字段 |
| 业务交接 | 权限确认与留存方案 | 日志存在未代替正式移交 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

若不同入口讨论同一达人，直接合并记录可能把旧合作范围带进新任务，应排查会话身份、原问题和所据合同版本。若接口返回没有账号操作字段，就无法由日志证明发布动作已执行；对照实际返回与交接清单，明确该项需要另取业务记录。请求运行详情时按官方契约设置detail并检查responseData，不把请求参数存在当成细节已返回。 若日志里提到合同就宣称交接资料留存完整，应逐项查看能否回读合同原句、版本和本次排期，缺哪项便列哪项；会话中出现文档名不表示原文已经留存。

## 怎么确认配好了

验收可并列保留目标对话、资料版本、返回内容与尚缺的账号回执，说明接手人还应查什么。调试和正式调用的身份字段、历史及返回分别核，不因测试身份为空就拼接其他会话补足。权限确认、内容留存与合规审计需要完整业务方案；日志能帮助回看已取得的对话依据，不证明达人合作审批、账号交接或对外发布已经完成。
