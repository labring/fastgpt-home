# MCN机构达人管理的运营权限与交接管理：权限与数据隔离

## 这个品类的数据长什么样

在MCN机构达人管理的运营权限与交接管理中，本页说明FastGPT的权限与数据隔离如何衔接资料。交接按达人账号及在办事项核访问，验证新经纪可用与旧经纪撤权。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

交接练习可列经纪接手的达人账号、当前排期及尚在补材料的处理事项，另列不移交账号。先核新身份能否取得相应合同、培训与通知版本，记录来源所指账号。若只能读历史排期而读不到当前处理原文，无法证明任务材料可用，应保留实际拒绝及清单指向排查资源映射。经纪职务相同不授予机构所有达人资料，交接范围由责任人逐项确认。

## 配置怎么定

| 交接权限核对项 | 达人账号及在办事项 | 实际验证 |
| --- | --- | --- |
| 账号范围 | 接手及不移交账号分开 | 责任人确认资源边界 |
| 当前原文 | 合同、培训及处理通知版本 | 新身份读取及拒绝 |
| 旧经纪 | 应撤销的排期与附件 | 原账号完整返回 |
| 外部身份 | 平台及机构接口分别核 | 内部调整不推同步停用 |
| 后续事项 | 交接不处置账号或发布排期 | 保留外部撤权与业务批准 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 新经纪只读历史排期便称当前处理可用：并列交接所指与实际通知版本，核接手账号及资源，旧材料不提供当前在办依据。

- 旧经纪仍读取应撤销通知或合同：保留完整返回及账号范围查残留，签字或归档不说明真实拒绝。

- 团队成员调整被当平台和机构接口已停用：独立核外部账号会话与允许操作，内部角色变化不自动终止外部访问，也不发布排期。

## 怎么确认配好了

验收用新身份核当前在办事项所需读取，用旧身份及不相关账号身份做同源否定测试，记录原句与操作结果。若获权后答案仍混用未移交达人的培训记录，另查输入与版本，不盲目扩权。交接不执行平台处置或排期发布，技术可操作也不代表合作条款已获业务批准。保留未解决项和外部撤权待办，不把经纪换岗写成全部账号事项已处理。
