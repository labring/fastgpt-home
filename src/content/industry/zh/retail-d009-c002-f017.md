# MCN机构达人管理的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

MCN机构管理多个达人的长期账号合规，日常材料包括达人签约合同、培训记录、违规处理单与账号排期。这些材料的更新频率为日或周，交接时同一份合同可能处于不同状态：已签署、待补签、已终止。部署与升级环节需要核对这些材料在系统中的可见范围，以及运营人员对它们的读取与修改权限是否随版本变化。

## 这些特征在「部署与升级」这一环带来什么约束

升级前需核对当前版本与目标版本对应的升级说明，不能从旧配置名称推断现行行为。AI Proxy 为必需依赖，`AIPROXY_API_ENDPOINT` 与 `AIPROXY_API_TOKEN` 均需设置，缺少任一项会导致启动校验失败。`FILE_TOKEN_KEY`、`AES256_SECRET_KEY` 与 `INVOKE_TOKEN_SECRET` 为运行期必填。检索结果不构成授权，表单收集值不等于业务验证或审批完成。

假设演练样本：某MCN机构运营交接记录原文为「达人A的签约合同于2026年3月1日生效，状态为已签署；账号排期表显示达人A在2026年4月参与三场直播；违规处理单编号V-2026-018记录达人A于2026年3月15日因内容违规被警告，处理状态为已关闭。」拟判定交接请求为「将达人A的合同编辑权限移交给新运营，并确认违规处理单V-2026-018已关闭。」该请求中合同编辑权限移交属于权限变更操作，违规处理单状态需核对原文，两者均不能由检索结果直接判定为已完成。

## 配置怎么定

| 核对项 | 本次假设试验起点 | 说明与比较方法 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 假设填写 `http://aiproxy:3000` | 与部署文档示例格式比较，确认未附加 `/v1` |
| `AIPROXY_API_TOKEN` | 假设填写非空字符串 | 与服务端配置比较，确认一致且非空 |
| `FILE_TOKEN_KEY` | 假设填写随机强密钥 | 与必填要求比较，长度至少6位 |
| `AES256_SECRET_KEY` | 假设填写随机强密钥 | 与必填要求比较，长度至少6位 |
| `INVOKE_TOKEN_SECRET` | 假设填写随机强密钥 | 与必填要求比较，长度至少32位 |
| `DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED` | 假设设为 `false` | 与 FastGPT 及 Pro Admin 配置比较，确认一致 |

## 容易做错的三处

1. 将检索结果当作权限依据。输入为达人A合同检索命中，比较对象为合同编辑权限的授权记录，可观察结果为检索命中存在但授权记录未变更。检索不负责权限隔离，命中不表示有权编辑。
2. 将拟稿句中的「已关闭」当作已核实状态。输入为违规处理单V-2026-018的拟稿描述，比较对象为原文记录的处理状态字段，可观察结果为拟稿句与原文一致或存在差异。拟稿句不构成状态确认。
3. 将表单提交当作交接完成。输入为权限移交表单已提交，比较对象为系统内实际权限变更记录，可观察结果为表单有提交记录但权限记录未更新。表单收集值，业务验证与写入需下游实现。

## 怎么确认配好了

1. 核对 `AIPROXY_API_ENDPOINT` 与 `AIPROXY_API_TOKEN`。输入为假设填写的端点与令牌，比较对象为部署文档中的格式要求与必填条件，可观察结果为两项均存在且端点未附加 `/v1`、令牌非空。缺少任一项时启动校验失败。
2. 核对达人A合同编辑权限的授权状态。输入为假设样本中的合同原文与拟移交请求，比较对象为系统内该合同的权限记录，可观察结果为权限记录中编辑权限的持有者与请求一致或存在差异。检索命中不改变该比较结果。
3. 核对违规处理单V-2026-018的状态。输入为假设样本中的处理单原文与拟稿句，比较对象为原文记录的处理状态字段，可观察结果为拟稿句描述与原文一致或存在差异。原文未提供状态时，该字段为未知。
