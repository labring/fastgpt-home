# Shopify独立站订单履约的运营权限与交接管理：工作流编排

## 这个品类的数据长什么样

在Shopify独立站订单履约的运营权限与交接管理中，本页说明FastGPT的工作流编排如何衔接资料。独立站履约交接要区分面单、实物交接与退款结果，模板介绍不证明本单已经送达或退款。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟订单备注写地址待核，面单已经生成，退款记录只见申请，运费模板未注明本单适用。流程可收订单关系和各段状态，人员选择补地址依据或核退款处理。面单生成不等于包裹交给承运方，模板存在也不证明运输安排适合本单；这些信息传给下游时应保留缺项，不自行判断客户身份或替换真实收货地址。

## 配置怎么定

| 独立站交接流程 | 自拟材料状态 | 需补依据 |
| --- | --- | --- |
| 订单地址 | 仍待核 | 保留来源 |
| 面单生成 | 非承运交接 | 取本单实际记录 |
| 运费模板 | 未明本单适用 | 核条件及关系 |
| 退款申请 | 没有执行结果 | 不写已退 |
| 系统写入 | 地址发运退款另接 | 交接非后台变更 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

面单冒发出：若打印记录被写成已交运，应查本单真实交接；模板冒适用：若一般运费说明用于本单，应核适用条件与订单关系；申请冒退款：若提出退款变成资金已处理，应取本次执行记录。三项分别核物流、范围和资金阶段，不由交接完成证明。

## 怎么确认配好了

验收检查补地址与核退款分支收到同一订单，补承运交接后只更新物流步骤，退款仍待核时不顺带改动。若地址只由人员口述，应留来源而不假定已经验证。正式地址变更、发运和退款操作需要另接流程核权限及回执，节点继续不证明货已送达或钱已退，也不代表独立站后台已被写入。
