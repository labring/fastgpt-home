# Temu半托管卖家运营的运营权限与交接管理：工作流编排

## 这个品类的数据长什么样

在Temu半托管卖家运营的运营权限与交接管理中，本页说明FastGPT的工作流编排如何衔接资料。半托管卖家交接应保留申报、海外库存和平台履约的各自状态，不从资料提交推出商品已获确认。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟交班有商品申报草稿、海外库存旧快照和待处理履约单，申报说明也未确认。流程可收商品版本与来源性质，人员选择补申报结果或核库存来源。这里不展示价格或库存数值，也不假定平台和仓库已同步；申报草稿只能说明准备内容，旧快照不能证明当前可用，履约单存在更不证明实物已经发出。

## 配置怎么定

| 卖家交班核对 | 自拟资料性质 | 下游检查 |
| --- | --- | --- |
| 商品申报 | 草稿待确认 | 不称平台认可 |
| 海外库存 | 旧时点快照 | 非当前可用 |
| 履约单 | 待处理安排 | 非实物发运 |
| 版本传递 | 商品随原句 | 比较实际接收 |
| 正式操作 | 申报同步回写另核 | 输出不证履约 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

草稿冒确认：若拟申报被写成平台已认可，应取真实处理回复；旧快照冒当前：若先前库存用作现况，应核时点与来源；任务冒发运：若履约安排变成已交承运，应取本次实际交接。三项分别核文件阶段、库存时态与物流执行，不由流程输出统一确认。

## 怎么确认配好了

验收比较两条路径收到的商品版本，补申报回复后只更新它覆盖的项目，库存和发运仍需各自记录。若回复只要求补材料，仍为待核。正式申报、库存同步和平台回写需要另接业务步骤核权限及回执，交接完成不证明商品已经可售或订单已履约，也不提供平台政策判断。
