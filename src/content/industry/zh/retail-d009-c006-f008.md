# 一般贸易出口报关的运营权限与交接管理：工作流编排

## 这个品类的数据长什么样

在一般贸易出口报关的运营权限与交接管理中，本页说明FastGPT的工作流编排如何衔接资料。出口报关交接要保留合同、装箱和申报稿的对应范围，文件准备完不说明本次已经办结。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟合同列成套货物，装箱说明分列附件，申报稿仍待核名称关系。流程可收这些原句及所指业务，让人员选择补货物对应或核办理状态。这里不解释报关要求，也不填金额与申报数据；不同名称是否同一批货需要实际说明，文件交齐只说明准备，不证明已提交、被受理或得到处理结果。

## 配置怎么定

| 出口交接流程 | 自拟资料所指 | 应取证据 |
| --- | --- | --- |
| 合同货物 | 成套名称 | 与附件真实对应 |
| 装箱说明 | 附件另列 | 不直接合并 |
| 申报文字 | 草稿待核 | 非实际提交 |
| 办理记录 | 本次结果缺 | 排除他批文件 |
| 流程更新 | 补关系不补结果 | 不推已经出境 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

名称强配：若附件被自动当成合同成套货物，应核真实对应依据；草稿冒提交：若待核文字被写成已申报，应取实际提交记录；他批结果套用：若另一批文件支持本次办结，应核业务归属。三项分别查货物关系、动作阶段与对象，不由流程接收补出。

## 怎么确认配好了

验收比较货物对应与办理核对路径收到的原句，补名称说明后只更新关系，办理仍需本次记录。若提交回执只证明收到材料，不能写成已经办结。正式报关、物流处理和外部回读需另接流程核实际权限与回执，节点继续不构成报关结果，也不证明货物已经出境。
