# 一般贸易进口报关的运营权限与交接管理：工作流编排

## 这个品类的数据长什么样

在一般贸易进口报关的运营权限与交接管理中，本页说明FastGPT的工作流编排如何衔接资料。进口业务交接应区分提单、到港和本次办理结果，不把运输文件变成放行或入库证明。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟交班有提单摘录和装箱说明，进口申报仍为草稿，收货记录缺失。流程可收货物关系与材料性质，让人员选择补单货对应或核办理进展。提单说明其记载内容，不自动证明当前货物到港、获放行或已入库；合同和发票名称相近也不能补出同批关系。这里不填写金额，也不提供进口程序或准入判断。

## 配置怎么定

| 进口交接核对 | 自拟来源性质 | 所需区分 |
| --- | --- | --- |
| 提单摘录 | 运输文件 | 不代办理结果 |
| 申报稿 | 尚待核 | 非真实提交 |
| 单货关系 | 名称相近不足 | 补实际对应 |
| 收货状态 | 没有记录 | 不推入库完成 |
| 后续办理 | 放行接收另核 | 缺项不判准拒 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

运输文件冒放行：若提单被写成已完成办理，应取本次真实结果；名称替对应：若相似品名强连合同和装箱，应核实际货物说明；草稿冒执行：若待核申报写成已经提交，应查提交记录。三项分别核结果类型、货物关系和动作阶段，不由交接完成解决。

## 怎么确认配好了

验收核两条路径实际收到哪份原句，补单货关系后只更新对应说明，收货和办理状态仍需独立记录。若只加入到港描述，不改成入库完成。正式申报、放行核实和仓库接收需另接流程核权限及回执，节点记录交互不说明货物已被处理，更不能以缺的资料推定被拒或获准。
