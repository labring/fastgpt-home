# 一般贸易进口报关的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样
进口报关的日常材料围绕进口报关单、商业发票、装箱单、提单和合同展开，数据来源包括国际贸易单一窗口、海关税则、货代到港通知和外汇付款单，更新频率为每单。这些材料在运营权限与交接管理中的意义在于：单证上的主体、货物、金额与状态构成交接时的核对对象，材料本身记录的是申报与随附信息，不构成对任何人或任何系统的操作授权。关务经理、报关行与进口商之间的交接请求，需要与材料原文逐项比对后才能判断处于何种状态。

## 这些特征在「部署与升级」这一环带来什么约束
部署与升级期间，运营权限与交接管理的核心约束是：检索、表单填写和页面展示都只呈现或收集信息，业务核验、审批、数据库写入与外部同步需要各自的下游实现。从 V4.17.0 起，App 与复用 App/Service 配置的 Admin 服务都必须设置 AIPROXY_API_ENDPOINT 和非空的 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败。FILE_TOKEN_KEY、AES256_SECRET_KEY 与 INVOKE_TOKEN_SECRET 为运行期必填。V4.17.2 包含两个手动触发升级脚本，历史分块训练任务迁移与知识库重建状态迁移均不阻塞服务启动，执行前需确认旧实例已完全停止且旧任务租约过期。

假设演练样本：某进口商关务经理留存一份交接说明，原文为“本单商业发票所列收货人为甲公司，提单通知方为甲公司，合同签署方为甲公司；发票金额与合同金额一致；该批货物尚未向海关申报。”另一份拟稿句写道：“交接完成，报关行已获得本单申报权限，可直接向海关提交。”核对对象是上述三份材料的主体、金额与申报状态，判定目标是拟稿句所述权限是否获得材料支持。

## 配置怎么定
下表围绕本页样本，列出与部署升级及交接核对相关的官方已说明设置或实施核对项。数值均为本次假设试验起点，用于与自身环境实际值比较，不作为官方默认值。

| 项目 | 本次假设起点 | 核对方式与理由 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 与文档示例格式比较，确认未附加对话接口路径；文档说明此项必填。 |
| AIPROXY_API_TOKEN | 假设填非空管理员 Token | 与 AI Proxy 服务端配置比较，确认一致且非空；文档说明缺少则启动校验失败。 |
| 必填密钥三项 | 假设各填随机强密钥 | 与文档长度下限比较，FILE_TOKEN_KEY 与 AES256_SECRET_KEY 至少 6 位，INVOKE_TOKEN_SECRET 至少 32 位。 |
| 升级脚本执行前置 | 假设确认旧实例已停止 | 与脚本说明比较，确认旧任务租约过期后再点击执行；文档说明属手动触发、不阻塞启动。 |
| 样本材料主体核对 | 假设三份材料主体均为甲公司 | 逐份比较收货人、通知方、签署方字段，确认同主体；材料未载明授权条款。 |
| 样本申报状态核对 | 假设原文为尚未申报 | 与拟稿句“已获得申报权限”比较，确认状态字段是否载明；原文未载明该权限。 |

## 容易做错的三处
1. 将检索或表单展示当作授权执行。错误表现：根据知识库检索到样本材料后，直接认定报关行已获得申报权限。输入是样本三份材料与拟稿句，比较对象是材料中是否载明授权条款，可观察结果是材料原文仅记载主体、金额与申报状态，未出现授权表述。
2. 将待审核状态写成已获批准。错误表现：把交接流程中处于待审核的请求描述为审批完成。输入是交接请求及其状态字段，比较对象是状态取值，可观察结果是待审核与已批准属不同取值，材料未载明批准记录时该事实未获支持。
3. 将跨向量模型的知识库共同关联。错误表现：把使用不同向量模型的库放在同一次关联检索中比较漏召回。输入是各库的向量模型标识，比较对象是标识是否一致，可观察结果是标识不同者应先行排除，文档未说明共同关联后的运行结果。

## 怎么确认配好了
1. 输入为样本三份材料原文与拟稿句“交接完成，报关行已获得本单申报权限”。比较对象是材料中收货人、通知方、签署方三个字段与拟稿句所述主体是否一致，以及材料是否载明授权条款。可观察结果是三份材料主体一致但均未载明授权，拟稿句所述权限未获支持，需记录为待核实。
2. 输入为样本原文“该批货物尚未向海关申报”与拟稿句“已获得申报权限”。比较对象是同一申报状态字段的取值。可观察结果是原文取值为尚未申报，与拟稿句所述已获权限不属同一事实，判定为未获支持，不写成否定或冲突。
3. 输入为本次假设的 AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 配置值。比较对象是文档所述必填要求与格式说明。可观察结果是两项均已设置且 Token 非空时通过启动校验；若任一项缺失，按文档所述启动校验失败。该判定基于文档说明，未在本环境实测。
