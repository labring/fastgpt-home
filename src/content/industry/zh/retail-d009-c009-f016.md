# 亚马逊FBM自发货运营的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在亚马逊FBM自发货运营的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。FBM交接表单保留工作分配、账户权限和承运证据，填入接手人不代表获得发货权限。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

假设交接单已分派打单任务，账号授权仍待确认，承运记录只有预约。表单收店铺、订单与待办，缺店铺和补齐分别测试；人员选择核账号或补物流，再看后续收到的信息。选择节点不提供平台人员目录，表单也不能自带平台订单数据库或办理账号授权。

## 配置怎么定

| FBM交接表单 | 假设状态 | 检查重点 |
| --- | --- | --- |
| 打单分派 | 仅工作分工 | 非账号授权 |
| 承运预约 | 未证揽收 | 查物流阶段 |
| 订单摘要 | 店铺对应待核 | 核当前身份 |
| 缺店铺输入 | 对比补齐 | 查下游字段 |
| 平台操作 | 真实系统办理 | 权限及回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

任务分配被答账号获准时，查真实权限；预约承运被答已揽收时，查物流事件；另店订单摘要套本店时，核店铺与订单对应。三处分别看分工与权限、阶段和对象，交接文件完整不证明发货已执行。

## 怎么确认配好了

验收每条路径保留原句与实际接收字段，账户证据补齐只改权限判断，包裹仍按物流凭据核。订单摘要紧邻所属店铺，缺对应时继续待补。平台操作、面单执行与业务回写由实际系统、权限及回执确认，交互完成只说明信息已传递。 打单待办紧邻当前店铺，承运预约保留其事件原句，授权材料只用于对应账号的核验。
