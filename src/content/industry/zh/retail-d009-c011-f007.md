# 仅退款争议处理的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

仅退款争议常没有退件入仓，证据重心落在发货签收与商品价值。售后主管、平台申诉专员、仓库质检在平台售后后台、承运商轨迹、客服聊天与仓库出库记录之间流转材料。每单与日更的节奏意味着交接时点密集，日志与审计要能回答某条会话属于哪一单、由哪个入口产生、当时处于什么授权状态。仅退款申请、发货凭证、签收证明、申诉材料构成核对对象，检索结果与表单填写不构成权限授予。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份按 chatId 核对目标对话与业务记录，不同入口的会话不混算。需要运行详情时按官方契约设置 detail，检查 responseData。日志与接口实际返回哪些字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，输入、历史与返回内容分别核对。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。

假设演练样本：某店铺售后专员在内部系统提交一条交接请求，内容为「将 chatId 为 A-2024-1013-01 的会话日志移交给申诉专员，用于处理仅退款申请单 R-7781，该单状态为待补签收证明」。供核对的材料原文为：「会话 A-2024-1013-01 由 API 入口创建，source 为 api；最近一条 AI 回复的 dataId 为 x9KQWcK9MApGdDQH7z7bocw1；该会话未附签收证明文件。」拟稿句为「该会话日志已完整留存，可直接作为申诉材料提交」。判定要点：材料只说明会话来源与一条回复标识，未载明日志留存完整性，也未载明申诉提交授权，拟稿句属于未获支持。

## 配置怎么定

| 核对项 | 官方已说明设置或实施核对项 | 本样本的核对动作 |
| --- | --- | --- |
| 对话身份 | chatId 用于取会话，需自行确保唯一，长度小于 250 | 核对 A-2024-1013-01 是否对应 R-7781 |
| 会话来源 | 获取会话列表按 source 区分，source=api 取 API 创建的会话 | 核对 source 字段与实际入口一致 |
| 运行详情 | detail 为 true 时返回中间值，非 stream 存于 responseData | 核对 responseData 是否含所需节点字段 |
| 响应标识 | responseChatItemId 传入后作为响应消息 ID 存入数据库 | 核对 dataId 是否与材料所载一致 |
| 反馈字段 | userGoodFeedback、userBadFeedback 为可选反馈信息 | 核对是否存在与交接相关的反馈记录 |
| 授权边界 | authProxy 需团队所有者开启，代理身份仍需目标应用与会话权限 | 核对代理身份是否具备该应用与会话权限 |

假设试验起点：将 pageSize 设为 10 用于本次纸面核对，理由是样本仅涉及一条会话与一条对话，取 10 足以覆盖；与 total 返回的实际条数比较，若 total 大于 10 则需另行取数。该值不是官方默认值。

## 容易做错的三处

1. 把检索或表单填写当成授权执行。样本中表单收集了 chatId 与单号，检索返回了会话记录，两者都不表示申诉提交权限已授予。检查时比较表单字段与授权记录，观察是否存在独立的授权凭据。
2. 把待补签收证明当成缺少操作权限。R-7781 状态为待补签收证明，这只说明证据缺口，不说明售后专员无权操作。检查时比较状态字段与权限字段，观察二者是否在同一记录中分别载明。
3. 把日志存在当成合规审计完成。材料只载明会话来源与一条回复标识。检查时比较材料所载字段与审计所需字段清单，观察缺口是否被记录为缺失。

## 怎么确认配好了

1. 针对样本材料原文，输入 chatId A-2024-1013-01 与 source=api 的会话列表请求，比较返回的 chatId 与材料所载是否一致，观察 total 与 list 是否覆盖该会话。若 list 为空，记录为空结果，不推断会话不存在。
2. 针对拟稿句「该会话日志已完整留存，可直接作为申诉材料提交」，输入材料原文与拟稿句，比较拟稿句是否超出材料所载范围，观察材料是否载明留存完整性与提交授权。材料未载明，判定为未获支持。
3. 针对交接请求「移交给申诉专员」，输入请求内容与授权边界核对项，比较代理身份是否具备目标应用与会话权限，观察 authProxy 是否开启且权限是否覆盖。权限未载明时记录缺口，不判定为已授权。
