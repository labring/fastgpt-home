# 仅退款争议处理的运营权限与交接管理：工作流编排

## 这个品类的数据长什么样

在仅退款争议处理的运营权限与交接管理中，本页说明FastGPT的工作流编排如何衔接资料。仅退款争议交接要保留申请、发货与签收证据的范围，任何一张凭据都不能自动代替处理决定。所用场景为自拟文字测试。

## 这些特征在「工作流编排」这一环带来什么约束

自拟交班有退款申请、发货证明和待核签收图片，申诉材料仍是整理稿。流程可收订单与证据原句，让人员选择核签收对应或补处理结果。发货证明不自动证明客户收到，签收图片也不能只按商品名连接本单；申请存在不决定应批或应拒，材料缺项只说明待核，不应据此推定没有履约或客户陈述不实。

## 配置怎么定

| 仅退款交接 | 本题自拟证据 | 所需界线 |
| --- | --- | --- |
| 申请原句 | 提出处理请求 | 非批准或驳回 |
| 发货证明 | 仅交寄阶段 | 不代客户收到 |
| 签收图片 | 订单对应待核 | 查真实来源 |
| 申诉材料 | 整理稿 | 非处理决定 |
| 流程结果 | 补事实不补裁决 | 缺项保持待核 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入节点` | 提交收集值后传给后续步骤。 |
| `用户选择节点` | 沿所选项连接的分支继续。 |
| `交互状态核对` | 检查等待与提交后的状态。 |
| `输出承接核对` | 逐项比较前后步骤传值。 |
| `外部操作分工` | 外部业务操作需另接实现。 |

## 容易做错的三处

发货冒收到：若交寄记录变客户签收，应取实际接收依据；图片错单：若他单图用于本案，应核订单及来源；整理冒裁决：若申诉稿写成已处理，应取真实结果。三项分别核物流阶段、证据归属和决定性质，不能由人员选择或节点连通补出。

## 怎么确认配好了

验收比较核签收与补结果路径收到的订单，补本单接收依据后只更新对应事实，不顺带得出退款决定。若申诉回复只是收材料，应继续留待处理。正式退款、申诉提交及争议关闭需另接流程核权限和回执，交互完成不证明平台已裁决，也不把未知状态写成任何一方已经承担责任。
