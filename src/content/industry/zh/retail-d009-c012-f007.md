# 仓内拣货复核打包的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
仓内拣货复核打包处理订单出库，与入库上架相比不处理供应商到货，主要数据来自WMS、订单系统、电子面单平台与称重设备，日常材料包括波次拣货单、复核记录、面单与包装耗材单，数据按每单或小时更新。这些材料决定对话日志里可以核对的业务对象：一次拣货复核交接涉及具体波次、订单、包裹与操作人。运营权限与交接管理在对话日志与审计环节，需要判断某条日志、某个会话、某次请求处于何种授权状态，检索命中、表单填写或接口返回都不构成授权执行。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话日志的身份由 appId、chatId、dataId 共同界定。chatId 为非空字符串时，系统从数据库取该会话，messages 数组最后一个内容作为用户问题，其余 message 被忽略；chatId 不传入时不使用上下文，完全由 messages 构建。responseChatItemId 在当前 chatId 下需唯一。detail=true 时返回中间值，非 stream 模式结果保存在 responseData，stream 模式通过 event 区分。authProxy 代理团队成员身份需团队所有者创建或编辑 key 时开启，代理身份仍需具备目标应用和会话权限。检索是检索，相似度 score 不是权限过滤，日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某仓一份波次拣货单原文为“波次 W-0715，订单 O-2231，拣货员甲，2025-07-15，数量 12 件，状态：已拣货待复核”。一条交接请求拟稿为“请开启复核员乙对波次 W-0715 的复核权限并直接放行”。该请求未附复核员乙的授权记录，也未附主管对 W-0715 的放行审批，属于待核实状态，不构成已授权。

## 配置怎么定
| 配置项 | 官方已说明的设置或核对点 | 与本页样本的关系 |
| --- | --- | --- |
| appId | 应用 ID，body.appId 优先级高于 apiKey 后缀 | 核对交接请求指向的应用 |
| chatId | 非空字符串时取数据库会话，长度小于 250 | 核对 W-0715 交接所在会话 |
| dataId | 会话下某条对话 ID | 核对复核记录对应的对话条目 |
| detail | true 时返回 responseData 中间值 | 需要运行详情时设置并检查返回 |
| authProxy | 需团队所有者开启，代理身份仍需应用与会话权限 | 核对乙是否具备目标会话权限 |
| source | source=api 时获取 API 创建的会话 | 区分 API 会话与页面会话 |

假设试验起点：将 pageSize 设为 20，理由是该值与官方示例一致，便于与示例返回的 total 字段比较；此为本次假设试验起点，非官方默认值。

## 容易做错的三处
1. 把 chatId 不传入时的无上下文行为，误当成该会话已存在并已授权。检查：核对请求是否传入 chatId，未传入时比较 messages 是否被完整使用。
2. 把相似度 score 当成权限或实体过滤，认为命中即有权操作 W-0715。检查：核对返回的 datasetId、collectionId 与目标库标识，排除不符者，记录实际观察。
3. 把待复核状态当作已放行。检查：比较波次拣货单原文的状态字段与交接请求所述状态，状态为已拣货待复核时不满足放行条件。

## 怎么确认配好了
1. 输入假设样本原文与拟稿句，比较拟稿句是否载明复核员乙的授权记录与主管审批，未载明时记录为待核实，不判定为已授权。
2. 输入 detail=true 的请求，比较 responseData 中是否存在 moduleType=chatNode 的元素及其 query 字段，存在时满足查看运行详情条件，未返回的业务数据不能推定已完整留存。
3. 输入 chatId 非空的请求，比较返回会话的 chatId 与目标会话是否一致，一致时满足同会话核对条件；不一致或未返回时记录缺口，不执行跨会话合并。
