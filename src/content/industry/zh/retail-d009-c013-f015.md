# 便利店加盟门店督导的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样

加盟督导场景的资料围绕总部对加盟商执行标准的监督展开。巡店表记录门店陈列、订货与整改事项，加盟合同载明双方权利义务与授权边界，整改通知体现问题发现与跟进状态，陈列标准提供可对照的执行要求。这些材料在检索中混合存在，文档长度差异大，合同条款偏长，整改通知偏短，巡店表条目细碎。知识库搜索节点可关联一个或多个使用相同向量模型的知识库，检索以库为最小单位，集合仅用于分类管理。督导在运营权限与交接管理中提出的问题，往往涉及某份材料当前处于何种状态，检索只负责找出候选内容，状态判断仍需回到原文。

## 这些特征在「知识库检索与召回」这一环带来什么约束

检索环节需要区分不同材料的语义特征。加盟合同中的编号、条款序号、日期属于精确查询对象，全文检索或混合检索更适配；巡店表中的自然语言描述适合语义检索。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离功能。引用上限以 token 为单位，长短不一的材料需要实际核对内容完整性。问题优化用于指代消除和问题扩展，会额外调用模型，可能改变问题主体，需要比较原问题与优化后问题。混合检索通过 RRF 融合多路结果，重排需要模型并按设置启用，图片检索需要图像输入及模型能力支持。检索结果为空时，引用内容以数组输出，长度可以为 0，下游链路仍会走通。

假设演练样本：某加盟合同文本载明“甲方授权乙方在××路门店使用品牌标识，授权期限自2024年1月1日至2024年12月31日”。一份整改通知载明“该门店2024年3月陈列检查发现冷柜温度记录缺失，要求2024年4月10日前完成整改”。一条待判定的交接请求写道“请确认该门店当前仍具备品牌标识使用授权，并办理督导交接”。该请求将检索到的合同期限与交接办理混在一起，合同期限是否延续、交接是否获批，原文均未载明。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 巡店表库、加盟合同库、整改通知库、陈列标准库 | 四库使用相同向量模型方可共同关联；逐一核对向量模型标识，排除不一致者 |
| 搜索模式 | 混合检索 | 合同编号类问题需全文命中，巡店描述需语义命中；以同一测试问题分别比较语义、全文与混合的候选差异 |
| 引用上限 | 本次假设试验起点设为2000 token | 因合同条款较长，需容纳完整条款；与较短整改通知对照，观察内容是否被截断 |
| 最低相关度 | 本次假设试验起点设为0.3 | 先标注相关与无关样本，再比较不同阈值下无关片段是否被滤除；该值仅在语义检索或结果重排时生效 |
| 问题优化 | 开启 | 用于指代消除与问题扩展；比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 按设置启用 | 需具备重排模型；比较启用前后候选排序，重排得分可用于过滤 |

## 容易做错的三处

1. 将检索命中的合同条款当作当前有效授权。假设样本中合同期限截至2024年12月31日，检索到该条款只说明原文如此记载，是否续签、是否仍有效，原文未载明。检查动作：输入该合同原文，比较检索结果与原文表述，观察是否出现原文没有的续签或生效结论。
2. 将待审核的交接请求当作已批准执行。假设样本中交接请求处于待判定状态，未载明审批结果。检查动作：输入该请求文本，比较请求中的“请确认”与任何审批记录，观察是否存在批准字段或签署记录；缺失时记录为待核实。
3. 将最低相关度当作权限过滤器。假设样本中督导仅被授权查看所辖门店资料，最低相关度只过滤低相关度结果。检查动作：输入一个跨区域门店问题，比较返回内容与授权范围，观察是否出现授权外门店资料；该参数不承担实体隔离功能。

## 怎么确认配好了

1. 针对假设样本中的合同原文，输入“该门店品牌标识授权期限”，比较检索返回内容与原文两句表述，观察是否完整返回授权主体、对象与起止日期；若返回内容包含原文未载明的续签结论，则不满足条件。
2. 针对假设样本中的整改通知，输入“冷柜温度记录整改要求”，比较返回内容与通知原文，观察是否返回整改事项与期限；若返回内容将整改完成状态写成已完成，而原文仅有要求，则不满足条件。
3. 针对假设样本中的交接请求，输入该请求文本，比较返回内容与请求原文，观察是否将“请确认”呈现为待核实状态；若返回内容直接呈现为已批准或已执行，则不满足条件。空结果场景可用明确的纸面输入[]核对下游设计，不声称虚构规则检索一定返回[]。
