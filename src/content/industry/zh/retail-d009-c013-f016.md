# 便利店加盟门店督导的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在便利店加盟门店督导的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。通知发出后，接手人仍需知道属于哪家店、依据哪版标准，以及是否已有接收或复核记录。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

门店督导交接可先收本店巡店问题、适用标准原句及整改资料缺口。自拟材料只有发现事项和通知，没有本次复核；表单收集这些文字并交给后续步骤，不负责核准现场。人员选择可以安排补资料或整理现有记录，不能写成人员目录选择器。实际接收方与资料范围需由连接和业务方案确定，也不能从交互结束推定整改已经被接手。

## 配置怎么定

| 交接核对 | 本题自拟输入 | 接收证据 |
| --- | --- | --- |
| 门店身份 | 巡店原句与本店对象 | 他店资料没有混入 |
| 标准范围 | 提交的版本适用说明 | 接收文字未丢范围 |
| 通知阶段 | 已发送但无接收依据 | 没有改写成已收到 |
| 人工去向 | 补复核或整理原文 | 实际连接接收对应资料 |
| 正式交接 | 后续确认与整改关闭 | 表单未代替业务回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

门店对象混用：若他店巡店文字进入本店交接，应核门店身份和原文来源后移出；标准适用说明丢失：若标准版本说明在传值中丢失，应对照提交与接收内容，补回适用范围再读；通知发送冒接收：若通知写已发送却被输出改成已接收，应另查本店真实接收依据，不能用通知存在补出对方收到。三种检查分别处理对象、范围和交接阶段，不由一次选择替代。

## 怎么确认配好了

验收沿本店问题、填写值、选项去向与接收文字回查，补本次复核后再问，确认新增依据实际进入解释。节点触发后记录流程状态并等待交互，完成后继续，不自动把材料写入督导系统。字段校验、正式移交和整改关闭需后续节点或外部流程按实际责任另行落实，核真实回执；本次表单结束不证明门店已整改或接手方已确认。
