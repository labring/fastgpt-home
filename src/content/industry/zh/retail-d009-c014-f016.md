# 便利店鲜食订货的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在便利店鲜食订货的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。交班中的批次时间、温控资料内容和报损问题，需要传给各自实际接收步骤。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

鲜食交接表单可先收门店班次、批次问题与对应订货或处理原句，不提供食品处理阈值。自拟材料只有订货和报损说明，没有本批温控数据；后续读取应保留这种缺口，不能从交班完成推定质量已核。人员可以选择补资料或交实际负责人核实，具体业务接收与处理由真实连接落实，不能把选择本身写成已完成食品处置。

## 配置怎么定

| 交接核对 | 本题自拟输入 | 接收证据 |
| --- | --- | --- |
| 班次批次 | 库存文字及适用时点 | 未沿用其他班记录 |
| 测量缺口 | 只给温控标题无内容 | 未写成设备数据已得 |
| 补原因路径 | 只收到订货安排 | 核选择和真实接收值 |
| 补齐变化 | 本批新增资料及原问题 | 解释实际采用对应来源 |
| 业务处理 | 确认和处置另有流程 | 交班不充作质量批准 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

班次批次错配：若另一班次库存被交给当前问题，应核时间与批次对应；温控标题冒测量：若温控资料只有标题，却被写成测量已取得，应回看本批实际设备来源；补原因走错路径：若选择补报损原因仍只收到订货安排，应查选项和接收值，不从需求说明推定原因。不同动作分别核对象、证据内容与路径，不能用表单非空代表全部依据已齐。

## 怎么确认配好了

验收保留原问题、资料性质、班次批次与实际接收内容，补对应记录后复问，看解释是否真用新依据。交互节点等待并继续，收集值不自带业务数据库功能。人员确认、字段校验、订货修改和实际处理需后续节点或外部方案另办，核授权与真实记录；本次提交不证明处理批准、质量结论或接手方已完成业务。
