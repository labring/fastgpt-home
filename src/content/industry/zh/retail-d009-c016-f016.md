# 加盟商培训与开业辅导的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在加盟商培训与开业辅导的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。签到、考核和现场清单支持不同结论，交接要保留本店适用的版本与缺证。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

加盟开业交接可先收适用SOP、本店待办与培训资料身份。自拟输入有签到和开业清单，没有本次考核或现场确认；表单传给后续步骤时应保留哪些是说明、哪些仍待核，不能由文件标题齐全推定交接完成。人员选择安排的是补证或继续阅读，实际接手岗位和权限需业务方案落实，不宣称节点自带人员目录或开业审批。

## 配置怎么定

| 交接核对 | 本题自拟输入 | 接收证据 |
| --- | --- | --- |
| 版本适用 | SOP原文与本店说明 | 旧版未冒充当前 |
| 人员考核 | 签到有，实际测验缺 | 未直接判能力合格 |
| 清单性质 | 开业待查项目 | 没有改写为检查完成 |
| 补证去向 | 本学员或本店新增依据 | 后续读取实际收到 |
| 正式认定 | 培训开业和移交另办 | 提交未代替批准 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

手册版本错用：若旧SOP被当当前版本，应核手册来源与适用说明；签到冒考核通过：若签到记录被解释成能力合格，应补本学员实际考核依据；待查清单冒已完成：若开业清单只列待查项目却被写成检查已完成，应查本店逐项复核记录。三项分别核版本、人员表现和现场执行，不由表单提交或一次选择补出任何结果。

## 怎么确认配好了

验收沿门店问题、提交原文、选择去向和接收材料逐项核，补对应考核或复核后再问，确认新依据被后续读取。交互状态触发后记录并等待，完成后向下继续，不自动创建档案。字段校验、正式培训认定、开业批准与交接确认需后续流程另核授权和真实回执；本次表单结束不证明人员通过或门店已经准许营业。
