# 加盟费与保证金结算的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
加盟费与保证金结算的数据来自财务系统、加盟合同、银行流水与门店违规记录，日常文档包括加盟费发票、保证金台账、扣款通知与合同付款计划。结算关注资金与违约扣款，不承担政府备案职责。出错后果为资金争议、加盟诉讼与保证金退还纠纷。数据更新频率为月及每次扣款。对话日志与审计这一环，需要把某次会话的身份、运行详情与字段含义逐项核对，不能把日志存在当作合规审计完成。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话身份结合 chatId 核对目标对话与业务记录，不同入口的会话不混算。需要运行详情时按官方契约设置 detail，并检查 responseData。核对日志与接口实际返回字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能不同，分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某连锁品牌加盟管理部于 2026 年 3 月 10 日交接一份会话记录，材料原文为“会话 chatId 为 jm-20260310-01，对话 dataId 为 d-7788，扣款通知编号 K-2026-031，事由为门店违规扣款，金额 5000 元，状态为待审核；保证金台账显示该加盟商保证金余额 30000 元。”待判定拟稿句为“该笔扣款已执行，保证金余额应更新为 25000 元。”判定需比较扣款通知状态字段与台账余额字段，同主体、同期间、同字段。

## 配置怎么定
下表为本次假设试验起点，非官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| chatId | jm-20260310-01 | 与材料原文一致，核对会话归属 |
| dataId | d-7788 | 与材料原文一致，核对对话记录 |
| detail | true | 需运行详情时按官方契约设置，比较 responseData |
| source | api | 获取 API 创建会话，比较来源字段 |
| 扣款通知状态 | 待审核 | 材料原文值，与台账余额比较 |
| 保证金余额 | 30000 元 | 材料原文值，与拟稿句 25000 元比较 |

## 容易做错的三处
1. 把待审核的扣款通知当作已执行。输入为材料原文“状态为待审核”，比较拟稿句“已执行”，观察结果为两者状态字段不一致。
2. 把保证金余额直接按拟稿句改写。输入为台账原文 30000 元，比较拟稿句 25000 元，观察结果为余额字段未获支持。
3. 把日志存在当作合规审计完成。输入为会话记录，比较对账与留存要求，观察结果为业务审计分工未落实。

## 怎么确认配好了
1. 输入材料原文“状态为待审核”，比较拟稿句“已执行”，若两者状态字段不一致，则拟稿句不成立。
2. 输入台账原文 30000 元，比较拟稿句 25000 元，若余额字段未获支持，则拟稿句不成立。
3. 输入会话 chatId 与 dataId，比较接口返回的 responseData，若字段未返回，则记录缺口，不推定已完整留存。
