# 加盟费与保证金结算的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样

加盟费与保证金结算围绕资金与违约扣款展开，不承担政府备案职责。资料以加盟合同、保证金台账、扣款通知、合同付款计划、加盟费发票为主，来源覆盖财务系统、银行流水与门店违规记录。典型主体包括连锁财务、加盟管理部与加盟商，出错后果集中于资金争议、加盟诉讼与保证金退还纠纷。这些材料在运营交接时经常跨越岗位与期间，检索环节需要先确认材料所属主体、对象与有效范围，再判断某条拟稿或请求处于何种授权状态。检索本身只返回引用内容，不构成审批、退款或扣款执行。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。搜索模式可选语义检索、全文检索或混合检索；混合检索通过 RRF 融合多路结果，结果重排由 ReRank 模型二次排序。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，会增加一次模型调用。引用内容以数组输出，长度可以为 0，即使没有搜索到内容，输出链路也会走通。图片检索需要相应图像输入及模型能力，重排需要具备模型并按设置启用，文档流程图中的可选路径不代表每次请求全部执行。这些能力只影响召回与排序，不承担权限或实体隔离；跨不同向量模型的库不可共同关联，应先核标识并排除不符合者，记录实际观察。

假设演练样本：供核对的材料原文为“甲方某某连锁管理有限公司与乙方某某加盟商于2024年3月1日签署《加盟合同》，合同编号JMF-2024-031，付款计划约定加盟费分两期，第一期于2024年4月10日前支付；保证金台账登记乙方保证金人民币五万元，状态为已收讫；2024年6月5日扣款通知载明因乙方违反陈列条款扣款两千元，事由为门店违规记录编号VG-2024-0601。”一条待判定的拟稿句为“乙方保证金已退还，合同已终止。”该拟稿句涉及退款与终止两项事实，材料未载明退款记录与终止签署，属于未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 加盟结算资料库一个 | 该库使用同一向量模型；与其他库比较向量模型标识，标识不同则不共同关联 |
| 搜索模式 | 混合检索 | 合同编号、扣款事由含编号与专有名词，比较语义检索与全文检索的召回内容 |
| 引用上限 | 假设起点 3000 token | 台账与合同段落长短差异大，比较不同上限下引用内容是否完整 |
| 最低相关度 | 假设起点 0.4 | 先标注相关与无关样本，比较过滤后保留内容与拟核对字段的对应关系 |
| 问题优化 | 开启 | 交接请求常含指代，比较原问题与优化后问题的主体是否被改错 |
| 结果重排 | 启用 | 候选较多时比较重排得分，仅作排序参考，不用于权限判断 |

## 容易做错的三处

1. 把检索命中当作授权执行。假设样本中拟稿句称保证金已退还，检索到台账“已收讫”只说明收款状态，退款需另有退款记录与审批，二者不可混同。检查时输入该拟稿句，比较台账状态字段与拟稿句表述，若台账无退款记录则判定未获支持。
2. 把待审核当作缺少权限。假设样本中扣款通知处于待审核，不能由此推出操作人无扣款权限，也不能推出扣款已执行。检查时输入扣款通知与审批记录，比较审核状态字段，状态为待审核时记录为待核实。
3. 跨向量模型共同关联。假设样本库与另一库向量模型标识不同，不可共同关联，也不可推断漏召回或冗余等运行结果。检查时输入两库标识，比较模型标识是否一致，不一致则排除该库并记录实际观察。

## 怎么确认配好了

1. 针对拟稿句“乙方保证金已退还，合同已终止”，输入该句与假设材料原文，比较保证金台账状态字段与终止签署记录。若台账仅登记已收讫且无退款记录、无终止签署，则拟稿句未获支持，需记录证据缺口。
2. 针对扣款通知，输入通知文本与审批记录，比较审核状态与事由字段。若状态为待审核，则记录为待核实，不判定扣款已执行，也不判定操作人无权限。
3. 针对空结果承接，输入明确的纸面输入[]，核对下游设计是否按引用长度为0继续走通。该核对只验证链路承接，不声称虚构规则检索一定返回[]。
