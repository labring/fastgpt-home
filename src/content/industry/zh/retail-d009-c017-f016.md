# 加盟费与保证金结算的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在加盟费与保证金结算的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。合同主体和资料性质随原文交接，开票、通知与银行执行分别取证。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

加盟结算交接可收合同主体、计划和待取凭据，不在自拟文字中写金额。现有材料只有发票与通知说明，没有银行执行记录，表单应把这种状态完整交给接收步骤，不自动完成财务核对。人员选择可以安排查合同或补凭据，但不是账务审批器，也不因为选了“继续”就取得实际扣款或修改台账的业务权限。

## 配置怎么定

| 交接核对 | 本题自拟输入 | 接收证据 |
| --- | --- | --- |
| 状态区分 | 发票说明与银行记录分开 | 未由开票推到账 |
| 主体错配 | 他店台账进入本合同 | 核来源后移出 |
| 凭证路径 | 补记录却只传通知标题 | 核连接与接收内容 |
| 权限范围 | 继续阅读或补材料 | 选择未作为扣款授权 |
| 正式确认 | 对账处理与移交另办 | 交互未替代真实回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

开票冒到账：若发票已开被写成款已收到，应分别核开票原句与对应银行依据；他店台账混入：若另一门店台账混入本合同，应核主体及资料身份后移出；通知标题代凭证：若选择补凭证仍只传通知标题，应查连接和实际接收值，保留执行资料缺口。三项分别处理状态、对象和传递，不以内容已填写认定账务已经清楚。

## 怎么确认配好了

验收记录本主体、各来源性质、选择去向与接收文字，补对应凭据后复问，核实际采用的来源。节点记录交互状态并等待，完成后继续不代表结算批准。字段校验、账务处理、正式对账和留存需后续节点或外部流程落实，核授权及真实回执；本次提交不证明收付已完成、合同处理正当或责任方已接受交接。
