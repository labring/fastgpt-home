# 区域经销商库存补货的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在区域经销商库存补货的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。需求、库存定义和回款计划在交接后仍要保持原来的口径与主体。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

经销商资料交接可先收补货需求、库存口径说明和回款计划，明确本次缺哪些执行记录。自拟材料没有出库或到账凭据，表单只传递已填文字，不从计划推定业务已经办理。需要人员选择时可安排补记录或解释原文，具体接收方由实际连接落实；同商品跨经销商出现，也不意味着库存口径相同或资料可以互相代填。

## 配置怎么定

| 交接核对 | 本题自拟输入 | 接收证据 |
| --- | --- | --- |
| 经销商对应 | 本对象与同名商品资料 | 他人库存未代填 |
| 计划执行 | 回款计划与实际凭据分开 | 没有写成已收款 |
| 口径传递 | 库存定义及适用范围 | 标题没有替代完整说明 |
| 补证承接 | 出库或回款新增原文 | 后续实际收到该资料 |
| 业务移交 | 下单回写及确认另办 | 提交未替代正式对账 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

经销商库存错配：若其他经销商库存进入本对象，应核主体与商品关系；回款计划冒到账：若回款计划被写成已经到账，应查原句性质和实际收款依据；库存定义丢失：若库存定义在传值中丢失，接收人只剩汇总标题，应对照提交与接收补回适用范围。三项分别核对象、执行和口径，不以一项选择替代资料本身。

## 怎么确认配好了

验收保留经销商、期间、来源性质、分支去向和实际接收内容，补对应出库或回款资料后复问，看新增依据是否进入解释。交互状态记录与继续不等于采购登记。字段核验、补货下单、库存回写和正式交接需后续业务另核权限及回执；表单结束不证明经营指标已核定、库存已变动或财务已完成对账。
