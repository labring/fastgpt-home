# 即时零售门店履约的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

即时零售门店履约按分钟处理线上订单，不是周期性盘库。订单、拣货清单、缺货报备、配送异常单随每单产生，数据来源包括即时零售渠道后台、门店库存与骑手轨迹。这一特征对对话日志与审计的影响在于：交接发生在班次之间，上一班留下的对话记录、会话标识与运行详情，是下一班核对履约状态的依据。分钟级与每单的更新节奏意味着日志条目持续增长，但更新频率本身不改变本页的核对方式。日志条目存在，只说明系统留存了该次调用的记录，不等于对账、留存或合规审计已经完成。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话日志通过 chatId 区分会话，通过 dataId 区分某会话下的具体对话。交接时须把业务记录与目标会话、目标对话对应起来，不同入口创建的会话不能混算。需要查看运行详情时，按官方契约在请求中设置 detail，并在 responseData 中检查模块响应；未返回的字段属于未知，不能推定为已完整留存。测试模式与正式调用的身份字段可能不同，输入、历史与返回内容须分别核对。检索与相似度只影响召回结果，不承担权限或实体隔离；检索库之间是否可共同关联，取决于向量模型标识是否一致，标识不同则先排除。

假设演练样本：某商超到家门店的拣货员在 2025 年 6 月 3 日 14 时 20 分，就订单 A 的缺货替换，向履约助手应用发起一次对话。供核对材料原文为：「订单 A 于 14 时 05 分进入拣货；14 时 18 分拣货员报备原品缺货，替换未获门店值班主管确认；14 时 20 分对话请求继续处理该单。」待判定的交接请求拟稿句为：「上一班已确认订单 A 的缺货替换，本班按已确认状态继续履约。」核对对象为：该拟稿句与材料原文在「替换是否获得确认」这一字段上是否一致。

## 配置怎么定

下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设演练的起点，用于与材料原文比较，不表示官方默认值。

| 配置项 | 本次假设演练起点 | 选择理由与比较方式 |
| --- | --- | --- |
| appId | 样本应用的 appId | 用于定位目标应用，与请求中传入的 appId 比较 |
| chatId | 样本会话的 chatId | 长度小于 250，用于取会话上下文，与业务记录中的会话标识比较 |
| dataId | 样本对话的 dataId | 用于取单个对话运行详情，与待核对对话条目比较 |
| detail | 设为 true | 需要运行详情时按契约设置，检查 responseData 是否返回模块响应 |
| source | 设为 api | 获取会话列表时限定来源，核对是否包含目标会话 |
| 向量模型标识 | 记录检索库所用模型标识 | 仅用于核对库之间标识是否一致，不一致则排除共同关联 |

## 容易做错的三处

1. 把日志条目存在当作合规审计已完成。日志留存与对账、合规审计由完整业务方案另行落实，本页只解决交接时的核对。
2. 把检索或表单当作授权执行。检索返回结果、表单收集字段值，都不构成对替换、退款或继续履约的授权；授权须有明确来源。
3. 把不同来源的会话混算。页面会话与 API 创建的会话来源不同，清空应用会话仅影响 API Key 创建的会话，交接核对须先确认来源。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较「替换是否获得确认」字段：原文载明未获确认，拟稿句写为已确认，二者在同一字段上取值互斥，判定为不一致，该拟稿句不能作为交接依据。
2. 输入样本的 appId、chatId、dataId，比较返回的运行详情是否对应本次对话：若 responseData 中模块响应与样本对话条目一致，则核对通过；若未返回相关字段，记录为未知，不推定已留存。
3. 输入样本会话列表请求，比较返回列表是否包含目标 chatId：若目标会话出现在列表中，来源与标识核对通过；若目标会话不在列表内，记录缺口，不据此判定该会话不存在。
