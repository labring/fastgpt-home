# 即时零售门店履约的运营权限与交接管理：权限与数据隔离

## 这个品类的数据长什么样

在即时零售门店履约的运营权限与交接管理中，本页说明FastGPT的权限与数据隔离如何衔接资料。交接未结即时订单时核新旧班次访问，区分原始记录留存和平台身份撤销。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

交班练习可拟尚未确认承接的订单、上一班拣货备注和当前库存说明，接班人拟取得本店未结来源。先列订单、门店与资料时点，真实新账号需要哪些读取和操作由责任人确认；交班表列名不能自动赋权。历史拣货记录有追溯作用，不代表原班人员继续可读，也不说明当前订单已完成。平台账号、配送服务和内部团队可能各自管理，不能从内部换班推出全部身份已同步。

## 配置怎么定

| 即时订单交接权限 | 本店未结来源 | 实际验证 |
| --- | --- | --- |
| 接班需要 | 待承接订单与当前库存 | 新账号读取及操作 |
| 旧班记录 | 拣货备注不代本次承接 | 订单及资料时点 |
| 原班限制 | 库存骑手来源撤权 | 同源回答和拒绝 |
| 外部身份 | 平台配送与团队分别核 | 账号接口实际结果 |
| 业务关闭 | 交班不关单或确认送达 | 真实处理记录 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 接班人只取旧班拣货便称本单交接齐备：并列未结清单、订单关系和实际返回，缺本次承接依据继续列出，不借同商品补阶段。

- 原班或他店身份仍读应限制的库存及骑手资料：保留同源完整回答查授权范围，班表改动和归档不证明实际拒绝。

- 内部换班被当平台与配送服务身份同步终止：分别核外部账号接口，撤权不派单也不确认顾客接收，业务责任另核。

## 怎么确认配好了

验收让接班账号读本店未结订单，再以原班和无关门店身份请求相同限制来源，记录原句、操作与拒绝。若新身份可读却答旧班状态，查本轮历史及输入，不扩大资源范围。外部身份撤销、历史保留和本次承接缺证分别留档，补后复测同题。交班不关闭订单、修改库存或确认送达；未结状态需真实处理记录，不能由交接结束认定已办妥。
