# 即时零售门店履约的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在即时零售门店履约的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。订单时点、仓内拣货与骑手接收分别保留，待核说明不能在交班中消失。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

即时零售交接可先收本订单问题、门店资料和骑手过程说明，保留每项来源的时点。自拟输入只有拣货与缺货文字，没有最终配送或处理结果；表单将这些内容交给后续读取，不由接班完成推定买家已收到。人员选择安排的是补材料或继续解释，不能称为自动订单选择器，实际业务接收与责任确认须由真实流程落实。

## 配置怎么定

| 交接核对 | 本题自拟输入 | 接收证据 |
| --- | --- | --- |
| 时间对应 | 旧库存与本单时点分开 | 未倒推下单状态 |
| 阶段区分 | 拣货与骑手接货分别给 | 未用仓内记录代揽收 |
| 待核性质 | 提交附有待核说明 | 接收没有变确定结论 |
| 新增依据 | 本订单配送资料 | 实际进入后续阅读 |
| 正式处置 | 交接替换及关闭另办 | 选择未充作责任或执行 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

库存时点错用：若旧时点库存被当作下单时状态，应核资料时间与订单对应；拣货冒骑手接收：若仓内拣货被输出写成骑手已接，应分别查拣货原句和本单实际交接依据；待核说明丢失：若“待核”在传值中消失，接收人只得到确定结论，应对照原始提交恢复性质。三项分别核时间、业务阶段和陈述状态，不因选择继续就视为已验证。

## 怎么确认配好了

验收保留订单、门店、资料范围、选项去向和真实接收文字，补同单配送依据后复问，看新资料是否进入解释。交互节点记录并等待，完成后继续，不自动办理退款或变更库存。字段校验、正式移交、替换及异常关闭需后续节点或外部方案另核权限与回执；本次表单结束不证明处置已执行或责任已经确定。
