# 即时零售门店履约的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样
即时零售门店履约按分钟处理线上订单，与周期性盘库的门店盘点防损属于不同作业节奏。主要数据来源包括抖音即时零售、美团或京东到家后台、门店库存与骑手轨迹，日常文档为即时订单、拣货清单、缺货报备与配送异常单。这些材料在交接时承载拣货、替换、配送状态回传等操作请求，因此权限边界必须与文档本身的状态一致。门店库存与平台后台之间的同步关系、骑手轨迹的归属与可见范围，文档未给出统一规定，属于待核实项。

## 这些特征在「部署与升级」这一环带来什么约束
分钟级节奏意味着交接窗口短，但部署与升级本身不因此获得自动触发或实时同步能力。升级到 v4.17.2 时，App 与 Pro 镜像 tag 需同步更新；两项手动触发脚本（`20261008_migrate_chunk_training`、`20261009_migrate_dataset_rebuild_status`）不阻塞服务启动，需在确认旧版本实例完全停止、旧任务租约过期后再执行，且第二项依赖第一项完成。AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 为必填，缺少任一项会导致启动校验失败，旧单模型地址不能替代。升级后应用相同样本复核导入、检索与调用，步骤执行完成不等于零中断。

假设演练样本：某连锁便利店区域运营在交接单中写道「门店 A 的拣货清单与缺货报备已由早班移交晚班，晚班可继续处理配送异常单」。另一份平台后台截图显示该门店晚班账号仅有订单只读权限，缺货报备与配送异常单处理权限未列出。待判定拟稿句为「晚班已获得缺货报备与配送异常单的完整处理权限」。该样本中主体为晚班账号，对象为缺货报备与配送异常单，状态为权限未列出，有效范围限于门店 A 当日班次。

## 配置怎么定
配置围绕上述样本的核对需求展开，只列与本任务相关的已说明设置或实施核对项。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填写内部 AI Proxy 根地址 | 与官方要求「不追加 /v1」比较，确认格式 |
| AIPROXY_API_TOKEN | 假设配置非空管理员 Token | 与服务端配置比较，确认一致且非空 |
| AGENT_SANDBOX_PROVIDER | 假设留空 | 与本页交接任务无关，留空即不启用沙箱 |
| DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED | 假设 false | 与 Pro Admin 配置比较，确认两服务一致 |
| 手动升级脚本执行顺序 | 假设先执行训练任务迁移 | 与官方依赖说明比较，确认第二项在后 |
| 升级后样本复核 | 假设复用同一拣货清单样本 | 与升级前检索与调用结果比较，记录差异 |

## 容易做错的三处
1. 把平台后台截图中的只读权限当作缺货报备与配送异常单处理权限已授予。输入为晚班账号权限列表，比较对象为拟稿句所主张的处理权限，观察结果是权限列表未出现对应条目，拟稿句未获支持。
2. 把交接单中「已移交」理解为权限已生效。输入为交接单文字，比较对象为账号实际权限状态，观察结果是移交描述与权限列表不一致，需记录为待核实，不能判定为已授权。
3. 把升级脚本执行完成当作业务零中断。输入为脚本执行记录，比较对象为升级前后同一拣货清单样本的检索与调用结果，观察结果是样本结果是否一致，不一致时记录差异，不推断原因。

## 怎么确认配好了
1. 输入为晚班账号权限列表与拟稿句「晚班已获得缺货报备与配送异常单的完整处理权限」，比较账号权限条目与拟稿句主张的权限范围，观察结果为权限列表未列出该两项权限时，拟稿句判定为未获支持，需补充授权材料。
2. 输入为交接单原文与门店 A 当日班次范围，比较交接描述与账号实际权限状态，观察结果为两者不一致时，记录为待核实项，不将移交描述等同于权限生效。
3. 输入为升级前后同一拣货清单样本的检索与调用结果，比较两次结果是否一致，观察结果为出现差异时记录具体差异字段，不将脚本执行完成表述为业务零中断。
