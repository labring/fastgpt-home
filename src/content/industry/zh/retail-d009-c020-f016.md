# 原产地证书申办的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在原产地证书申办的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。当前申请、实际生产段落和签发寄送阶段，需要逐项交给对应接收步骤。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

证书申办交接可先收申请身份、商品文字与仍缺的签发或寄送材料。自拟输入只有申请和生产说明，没有实际处理回复；表单应把已给和待取的范围传给接收步骤，不由资料齐备推定已签发。选择可以安排补证或查看原文，不替代签发机构判断，也不能由一次交互完成认定经办方已经正式承接或办结事项。

## 配置怎么定

| 交接核对 | 本题自拟输入 | 接收证据 |
| --- | --- | --- |
| 申请身份 | 旧证与当前申请分开 | 核版本后移出错配 |
| 办理阶段 | 提交说明无签发回复 | 未改写为证书已出 |
| 生产内容 | 只给标题没有相关原句 | 接收范围仍列缺口 |
| 补证路径 | 本申请新增处理回复 | 后续实际使用该来源 |
| 正式移交 | 更新寄送及确认另办 | 表单未替代机构回执 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

旧证套当前申请：若旧证书资料进入当前申请，应核申请身份与版本后移出；提交冒签发：若提交说明被写成已签发，应另查本次签发回复，不以材料存在补出结果；生产标题代内容：若只填了生产资料标题却被当成组成内容已给，应回看真实接收文本并补相关段落。三项分别核对象、阶段和内容，不能由表单非空替代。

## 怎么确认配好了

验收沿本申请、填写值、分支接收和解释回查，补相应回复后复问，确认新依据实际传入。交互状态随节点触发记录，等待结束后继续，不自动修改外部申办状态。字段核验、申请更新、寄送和正式交接需后续业务另核授权及真实回执；本次提交不证明证书效力、机构受理或客户已经收到原件。
