# 品牌会员私域运营的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
品牌会员私域运营围绕顾客数据与复购触达展开，主要数据来自CRM系统、企微、POS消费记录和小程序行为数据，日常文档包括会员标签表、触达计划、优惠券规则和隐私授权记录。这类数据的更新频率为日、周。在对话日志与审计环节，会话以chatId标识某一应用下的会话，以dataId标识该会话下的某一条对话，日志留存与业务对账属于两件事。运营交接时需要区分：哪些材料只是被检索到，哪些请求处于待审核状态，哪些操作已经完成。检索命中一段历史对话，只说明该文本存在于可访问的检索范围，不说明交接已获授权。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话接口的响应字段决定日志里能核对到什么。detail=false时返回choices与usage；detail=true时额外返回responseData，其中包含模块名称、模型、tokens、similarity、limit、quoteList、completeMessages等运行详情。字段含义须与接口实际返回核对，未返回的业务数据不能推定已完整留存。authProxy用于代理团队成员身份，需要团队所有者在创建或编辑key时开启，代理身份仍需要具备目标应用和会话权限。检索与相似度不承担权限或实体隔离功能。

假设演练样本：某品牌会员私域运营团队整理一份交接材料，原文为“2025年3月1日至3月31日期间，导购A通过企微会话向会员B发送触达计划中的优惠券提醒，该批会话由API Key创建，chatId为api-202503-017，dataId为rec-0007。3月20日提交的会员标签表变更申请处于待审核状态，未取得审批记录。”拟判定句为“导购A在3月已完成对会员B的触达授权交接，可继续使用该API Key发起新会话。”此样本中，待审核不是审批通过，API Key创建会话与触达授权属于不同事实。

## 配置怎么定
下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。假设试验起点仅用于本次纸面核对，选值理由与比较对象一并写明。

| 配置项 | 本次假设试验起点 | 核对方式与理由 |
| --- | --- | --- |
| chatId 唯一性 | api-202503-017 | 官方要求自行确保chatId唯一、长度小于250，与样本中会话标识逐字比对 |
| responseChatItemId 唯一性 | rec-0007 | 官方要求在当前chatId下唯一，与样本中dataId比对，确认未重复 |
| detail 取值 | true | 需要运行详情时按官方契约设置，检查responseData是否返回 |
| authProxy 状态 | 未开启 | 官方说明开启需团队所有者操作，样本未载明开启记录，保持未知 |
| 会话来源 source | api | 官方说明source=api只获取API创建的会话，与样本中API Key创建条件比对 |
| 交接请求状态 | 待审核 | 样本原文写明未取得审批记录，不按已授权处理 |

## 容易做错的三处
1. 把检索命中当成权限授予。样本中检索到chatId为api-202503-017的历史对话，只说明该文本在可访问范围内，不能据此认定导购A已获得触达授权。
2. 把待审核当成审批通过。样本明确3月20日提交的会员标签表变更申请处于待审核状态，未取得审批记录，交接材料不能写成已完成变更。
3. 把API Key创建会话等同于业务授权。样本中该批会话由API Key创建，只说明会话来源为api，与导购A是否获得触达授权属于不同事实。

## 怎么确认配好了
1. 输入样本原文中“chatId为api-202503-017，dataId为rec-0007”与接口实际返回的chatId、dataId逐字比较。若两者一致且responseChatItemId在当前chatId下唯一，则满足核对条件；若出现重复或缺失，记录为待核实。
2. 输入样本原文中“3月20日提交的会员标签表变更申请处于待审核状态，未取得审批记录”，与交接材料中关于该申请的表述比较。若材料写成待审核，则与原文一致；若材料写成已完成或已批准，则属于未获支持的表述。
3. 输入样本原文中“该批会话由API Key创建”与source=api的会话列表返回结果比较。若返回列表中包含该chatId，则来源核对一致；若返回为空或该chatId不在列表中，记录实际观察结果，不推断未载明的失败原因。
