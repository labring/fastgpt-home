# 品牌会员私域运营的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在品牌会员私域运营的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。本题只用通用活动文字，分别核活动适用、权限来源与通知是否真实接收。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

会员运营交接可以只收通用活动规则、自拟需求和待补授权说明，不传真实个人记录。表单负责收集并交给后续步骤，不能从活动计划存在推定会员已触达。人员可选择看规则或补资料，具体接收角色和业务权限仍由实际方案确定，不将选择节点称为会员数据库或人员目录，也不由交互状态推出权限已核完。

## 配置怎么定

| 交接核对 | 本题自拟输入 | 接收证据 |
| --- | --- | --- |
| 活动范围 | 规则所指活动和期间 | 未沿用其他活动 |
| 许可来源 | 只有标签名无授权说明 | 缺证明确保留 |
| 通知阶段 | 拟发送与实际接收分开 | 计划未变成已收到 |
| 公开材料 | 通用文字不含个人记录 | 接收范围符合本题 |
| 正式业务 | 发送留存及移交另办 | 交互未充作权限通过 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

活动规则错配：若另一活动规则进入本期交接，应核活动身份和适用范围；标签冒授权：若标签名称被当成可以发送的授权，应回查真正许可依据，保留缺证；拟通知冒已收到：若计划只写拟通知却被接收成会员已收到，应分开查实际发送及接收记录。三项分别核对象、权限来源和执行阶段，不用选择或填写值补出结果。

## 怎么确认配好了

验收保留公开通用材料、活动、分支去向与实际接收文字，补相应规则后复问，看新增依据是否进入。交互节点记录等待状态并继续，不自动发送消息或写标签。字段核验、正式交接、发送和留存要求需后续节点或外部流程另落实，核业务授权与真实回执；本次表单完成不证明触达效果或个人数据处理已通过审查。
