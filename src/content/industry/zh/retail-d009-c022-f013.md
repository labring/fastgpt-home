# 品牌全渠道库存调拨的运营权限与交接管理：权限与数据隔离

## 这个品类的数据长什么样

在品牌全渠道库存调拨的运营权限与交接管理中，本页说明FastGPT的权限与数据隔离如何衔接资料。移交未结调拨的读取范围，核两地角色、旧人员撤权及外部仓库身份。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

交接可拟已提交未确认接收的调拨清单、调出库存快照和运输备注，接手人拟查本次未结环节。先列调出调入地点和记录时点，再由责任人确认新账号需要哪些资源与操作，地点参与不自动授予所有仓库资料。历史运输说明可以留存，原人员继续读取则另需授权。清单“已移交”只描述工作交接，不说明货物已到、库存已记或账务已核平。

## 配置怎么定

| 调拨交接权限 | 未结来源 | 验收对象 |
| --- | --- | --- |
| 地点角色 | 调出调入及记录时点 | 新账号范围 |
| 接收缺证 | 运输快照不代本次收货 | 实际返回及来源 |
| 原人员 | 两店库存及仓库说明 | 同源回答和拒绝 |
| 外部账号 | WMS渠道库存分别验 | 接口撤权及留存 |
| 业务完成 | 访问转交不关闭调拨 | 接收账务实际记录 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 新人员只读运输备注便称调入已收且依据齐备：并列未结事项、地点角色及实际返回，确认本次接收来源，不借快照补发生量。

- 原人员仍读应撤销的两店库存或其他仓库内部说明：保留同源完整回答和权限范围，改交接名单不证明真实拒绝。

- 内部职责移交被当WMS或渠道库存身份同步终止：核外部账号接口，历史留存与继续访问分开，撤权不执行货物或账务动作。

## 怎么确认配好了

验收让接手身份读未结调拨，再用原人员和无关仓库身份请求同一受限来源，保留原句、操作和拒绝。对已获权请求中的地点颠倒，逐一比对原文调出调入角色与本轮实际传入值；更正映射后在原范围复测。外部身份撤销、本次接收缺证与历史留存分别记录，补后按原范围复测。交接不确认收货、扣减库存或生成对账结果；尚缺业务依据的阶段继续待核；调拨结项须有真实接收、账务记录和责任人确认。
