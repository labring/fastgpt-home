# 品牌全渠道库存调拨的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在品牌全渠道库存调拨的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。调出调入角色、库存余额和实际接收，不能在资料交接中合成同一结论。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

调拨交接可收商品、调出调入地点及库存资料范围，明确本次没有接收依据。自拟输入只有申请、快照和运输文字，表单提交后要核后续仍区分需求、余额、移动与接收；资料传完不意味着库存同步完成。人员选择安排补证或解释，不自带业务数据库功能，实际接手、审批和写入需由已实现的业务连接承担。

## 配置怎么定

| 交接核对 | 本题自拟输入 | 接收证据 |
| --- | --- | --- |
| 地点角色 | 调出调入原句 | 接收时没有互换 |
| 数量性质 | 快照余额与实际移动分开 | 未由余额补发生量 |
| 接收阶段 | 运输有，本次接收缺 | 物流单未代签收 |
| 补证承接 | 同次新增原文 | 进入所选后续步骤 |
| 正式移交 | 创建回写和对账另核 | 表单未代替账实确认 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

调出调入混用：若调出角色在接收时变成调入，应对照地点原句纠正；余额冒发生量：若快照余额被当成本次发生量，应另查实际移动记录和时点；运输记录冒接收：若物流单存在就被写成门店已收到，应核本次接收凭据。三项分别处理角色、数量性质与业务阶段，不由同商品或一次选择把不同来源拼成完成链。

## 怎么确认配好了

验收保留商品、地点、资料时间、选项去向与接收原文，补同次凭据后复问，核新增来源是否真正进入解释。节点触发后记录交互状态并等待，完成后继续，不代表外部系统已接受操作。字段校验、调拨创建、库存回写、对账和正式交接需后续流程另核授权与真实回执；本次表单结束不证明货物已移动或账实已平。
