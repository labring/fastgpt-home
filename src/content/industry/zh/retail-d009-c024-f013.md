# 品牌商场专柜运营的运营权限与交接管理：权限与数据隔离

## 这个品类的数据长什么样

在品牌商场专柜运营的运营权限与交接管理中，本页说明FastGPT的权限与数据隔离如何衔接资料。围绕专柜未结月结与活动事项移交资源，另核商场身份与品牌旧人员访问。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

交接可拟本柜待核月结、已收活动函和旧期销售说明，接手人员拟取得当前未结依据，不填费用数。先按商场、柜台和期间列资源，新账号需要哪些原文和操作由责任人确认。旧月结留存能解释往期处理，不说明原店长继续读取全部合同，也不保证新人员已有本期确认。商场收银身份和品牌团队身份可能独立，岗位转交不能代替两边真实授权与撤销结果。

## 配置怎么定

| 专柜交接权限 | 本期未结来源 | 核对动作 |
| --- | --- | --- |
| 当前任务 | 月结待核及活动函 | 新账号原文范围 |
| 旧期资料 | 小票不代本期确认 | 期间及实际返回 |
| 原店长 | 月结及内部活动撤权 | 同源回答和拒绝 |
| 商场身份 | POS营运门户另验 | 账号接口实际结果 |
| 账务完成 | 转交不调费或确认款项 | 处理依据及责任确认 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 新人员只取旧期小票便称本期月结资料齐备：并列待核清单、期间和实际返回，确认本期来源，不借同柜名称替版本。

- 原店长仍读应撤销月结或品牌内部活动意见：保留同源完整回答和授权范围，柜台交接签字及归档不证明拒绝。

- 品牌换岗被当商场POS或营运门户身份同步终止：核外部账号接口，保留历史与持续读取分开，撤权不确认结算已办。

## 怎么确认配好了

验收让新账号读取本柜当前事项，再用原店长及无关柜台身份请求同一限制来源，记录原句、操作和拒绝。若权限正常却套旧活动范围，查实际输入日期和版本，不扩大合同访问。外部身份撤销、历史保存和本期缺证分别列明，补后按原范围复测。交接不登记活动、调整扣费或确认收款；未结月结需实际处理依据和责任确认，团队访问已转交不等于账务已核平。
