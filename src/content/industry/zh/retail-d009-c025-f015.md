# 品牌奥莱折扣运营的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样
奥莱折扣运营以清理过季库存为目标，主要数据来源包括 ERP 库龄、POS 销售、奥莱商场活动与历史折扣。日常文档集中在折扣审批、滞销清单、价签与毛利测算表。这些材料的更新频率为周或月，检索与召回环节据此处理跨周、跨月的版本并存问题。运营权限与交接管理需要判断某份折扣审批处于何种状态、某次交接请求是否已获授权，检索只负责把候选材料取回，授权判断由人工核对完成。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，需要先核标识并排除不符合者，记录实际观察，不执行跨模型检索来比较漏召回。搜索模式可按测试问题在语义检索、全文检索与混合检索之间比较，不预设一种模式适合全部资料。引用上限以 token 为单位；最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，需要比较原问题与优化后问题，核对主体是否被改错。语义召回和相关度不承担权限或实体隔离功能，检索不是授权。

假设演练样本：某奥莱门店交接场景中，材料原文为“折扣审批单 A-0417：主体为华东某奥莱店，对象为三款过季鞋类 SKU，状态为待运营主管审核，有效范围为本月内清货批次。”另一句为“滞销清单 B-0520：主体为同一门店，对象为上述三款 SKU，状态为已列入本周清货建议，未标注审批结论。”待判定的交接请求为：“将 A-0417 的折扣执行权限移交下一班次。”判定时需比较同一主体、同一期间、同一字段：A-0417 的状态字段为待审核，未载明已批准；B-0520 未标注审批结论。待审核不证明缺少操作权限，也不等于批准。该请求缺少已生效的授权依据，应记录为待核实，不执行权限移交。

## 配置怎么定
下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，用于与样本中的实际材料比较，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅关联一个使用相同向量模型的知识库 | 样本材料同属一个门店资料集；先核向量模型标识，排除不同模型库 |
| 搜索模式 | 先按语义检索与全文检索分别试跑 | 样本含编号 A-0417 与自然语言描述，比较两种模式对编号与语义的命中差异 |
| 引用上限 | 设为能容纳两份材料全文的 token 量 | 材料含主体、对象、状态、有效范围，比较截断后是否仍保留状态字段 |
| 最低相关度 | 先取中间值，再与标注样本比较 | 仅在语义检索或结果重排时生效；用相关与无关样本观察过滤效果 |
| 问题优化 | 对短问题开启，比较优化前后主体 | 样本问题含指代时核对主体是否被改错；问题明确时可关闭以观察差异 |
| 结果重排 | 具备模型且按设置启用时比较得分 | 重排得分为 0-1，用于比较候选文本相关性，不用于判断授权状态 |

## 容易做错的三处
1. 把检索命中当作授权成立。输入为待判定的交接请求与 A-0417 原文，比较检索结果与审批状态字段，观察到的现象是材料被召回但状态仍为待审核。错误在于据此执行权限移交；正确做法是记录授权依据缺口。
2. 把待审核读成缺少操作权限或已批准。输入为 A-0417 状态字段，比较同一字段的互斥取值，观察到待审核与已批准并非同一取值。错误在于补造授权或生效条款；正确做法是保留待核实。
3. 把跨向量模型库共同关联。输入为两个向量模型标识不同的知识库，比较标识是否一致，观察到标识不同。错误在于继续关联并推断漏召回或冗余；正确做法是排除不符合者并记录实际观察。

## 怎么确认配好了
1. 输入假设样本中的 A-0417 原文与交接请求，比较检索返回内容是否包含主体、对象、状态、有效范围四个字段，观察到的现象是状态字段为待审核且未被改写。满足条件为检索结果保留原状态，授权判断仍标记为待核实。
2. 输入 B-0520 原文与同一交接请求，比较同一主体、同一期间下审批结论字段，观察到的现象是未标注审批结论。满足条件为不将未标注读成否定或冲突，记录为未获支持。
3. 输入一份明确纸面空结果，比较下游设计是否承接空引用，观察到的现象是引用内容以数组输出且长度可以为 0。满足条件为下游链路走通，不声称虚构规则检索一定返回空数组。以上均为纸面核对，未执行实际部署或审批。
