# 品牌直营门店运营的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

在品牌直营门店运营的运营权限与交接管理中，本页说明FastGPT的对话日志与审计如何衔接资料。门店对话可帮助回看排班、陈列和调拨的解释，但实际出勤与库存移动仍各有记录。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

直营店交接可先核目标会话属于哪家店、哪个班次和哪份资料。自拟交流只有排班、照片与调拨说明，没有实际出勤或接收凭据。chatId结合业务对象回看解释，不表示POS、CRM和库存记录已全部同步进日志；会话结束也不证明门店完成了安排。实际返回的字段和材料范围需核，未返回的数据不推定已完整保存。

## 配置怎么定

| 日志交接核对 | 本题自拟记录 | 需补或回查的依据 |
| --- | --- | --- |
| 门店来源 | 他店陈列会话混入 | 核入口与图片身份 |
| 出勤阶段 | 排班说明无实际记录 | 未写成已经到岗 |
| 移动时点 | 日志运行与业务事件分开 | 查本次调拨记录 |
| 详情范围 | 契约请求及实际返回 | 不推定数据全留存 |
| 正式确认 | 变更权限和交班另办 | 日志未替代业务接受 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

错店会话：若其他店陈列问答进入本题，应核入口及照片来源；排班冒到岗：若答复将安排当执行，应查原输入与实际出勤记录；运行时间冒调拨时间：若日志时点被当货物移动，应另核本次业务记录。三项分别核来源、人员执行和事件时点，不由同品牌或最近会话补出。

## 怎么确认配好了

验收保留门店班次、资料身份、真实返回和缺证，调试与正式的输入历史分别核。需要对话接口运行详情时依契约设置detail并查responseData，不把参数设置当成细节已取得。排班变更、库存回写、权限及留存要求需完整业务方案落实；本次日志回看不证明现场已核、库存同步或接班方已经正式确认。
