# 品牌直营门店运营的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在品牌直营门店运营的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。直营店交接表分别收封包记录、终端故障和接班职责，提交不证明点收或设备恢复。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟直营店夜班交接单有封包登记，注明待双方点收；终端故障工单只记报修，接班职责写继续跟进。表单收门店、封包标识、故障事项与原句，人员选择补点收记录或核设备处理。这里未给现金数量或设备恢复结果，也没有实际封包照片。封包登记只说明纸面登记，报修不说明已修，接班人接受跟进任务不代表获系统维修或资金处置权限。

## 配置怎么定

| 直营夜班交接表 | 自拟材料 | 核法 |
| --- | --- | --- |
| 封包登记 | 待双方点收 | 不作无差异确认 |
| 终端工单 | 仅报修 | 对设备及复测 |
| 接班职责 | 继续跟进 | 不授权资金或账号 |
| 输入标识 | 缺项与补齐 | 核两路径承接 |
| 真实交班 | 点收修复另核 | 不由提交完成 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

- 封包已登记被答为双方已点收时，对原单的待点收措辞与双方确认记录，不能从表单提交推实物或款项无差异。

- 故障工单已建立被答为终端可用时，核本设备的处理与复测凭证；工单编号不是恢复结果。

- 接班职责的跟进人被写成可处置封包或修改收银资料时，核职责原句及真实授权，工作联系人不产生操作权。

## 怎么确认配好了

对缺封包标识与补齐的输入分别测试，将原句和事项对应传给两个下游路径。补点收只更新该封包确认，设备仍待复测，权限仍独立核；测试不填写余额或猜测差异。检查实际接收可发现标识、待办被省略的位置。真实点收、设备复测、资金与账号操作需授权流程及回执，这张表不自带收银数据库，也不自动完成交班或写回门店记录。
