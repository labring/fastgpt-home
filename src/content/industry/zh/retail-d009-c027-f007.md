# 品牌经销商订货会的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

在品牌经销商订货会的运营权限与交接管理中，本页说明FastGPT的对话日志与审计如何衔接资料。订货会交流中的样品、合同和授信资料要保持经销商身份，不能以问答结果代订单确认。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

订货会交接可先定位讨论本经销商、手册和样品的会话，不公开商业金额。自拟交流只有样品和合同文字，没有订单接受或授信结果。chatId用于关联问题与输入，不能从对话提到订货就推定已成交，也不说明系统已留存所有财务审批。具体返回字段与资料版本需要核，日志中出现文件名不代表原文已完整保存。

## 配置怎么定

| 日志交接核对 | 本题自拟记录 | 需补或回查的依据 |
| --- | --- | --- |
| 主体会话 | 其他经销商记录混入 | 核合同及原问题 |
| 展示执行 | 样品清单与实际订单分开 | 未由展示判成交 |
| 许可性质 | 建议无本次正式决定 | 不充作授信批准 |
| 资料留存 | 文档名与原文范围分开 | 核真实返回内容 |
| 业务接受 | 提交确认与移交另办 | 会话未代替受理结果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

经销商错配：若其他主体会话进入，应核原问题和合同身份；样品冒订单：若展示清单被答复当采购记录，应另查实际订单；授信建议冒批准：若交流解释被当业务许可，应核本次正式决定。三项分别查对象、执行和权限依据，不由同商品或聊天完成补出。

## 怎么确认配好了

验收保留目标会话、资料版本、实际返回与待取结果，调试及正式调用分别核输入、历史和身份。需要运行详情时按官方契约核detail及responseData，不从请求成功推定资料齐全。订单提交、合同确认、权限移交与留存需完整业务方案另落实；本次回看不证明经销商承诺采购、授信已获准或交接已正式接受。
