# 品牌经销商订货会的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

订货会面向线下经销商预订，不直接管理平台店铺，数据来源包括订货会系统、历史销售、经销商库存与财务授信。文档以订货手册、订货合同、样品清单、授信审批为主，更新频率为季或年。这些材料在部署与升级环节构成交接的核对对象：订货量、授信额度、合同状态分散在不同文档中，版本与授权边界需要逐份确认。

## 这些特征在「部署与升级」这一环带来什么约束

升级前须核对当前版本与目标版本及对应升级说明，不从旧配置名称推断现行行为。App 与 Admin 必须设置 AIPROXY_API_ENDPOINT 与非空 AIPROXY_API_TOKEN，缺少任一项会导致启动校验失败；旧 OpenAI 环境变量或单模型自定义请求地址不能替代这两项。依赖与备份按官方部署步骤检查，恢复能力须用自身环境验证。升级后用相同样本复核导入、检索与应用调用，步骤执行完成不等于零中断。

假设演练样本：某品牌渠道部一份《订货手册》第 3 页写“本次订货会样品清单以附件二为准，授信审批由区域财务在订货会前完成”。一份《授信审批》单写“申请额度 200 万元，状态：待审核”。待判定拟稿句为“该经销商授信已批准，可执行订货”。核对该句时，审批单状态字段为“待审核”，与“已批准”属同字段互斥取值，拟稿句未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 与官方示例比对，确认未附加 `/v1` |
| AIPROXY_API_TOKEN | 假设填管理员 Token | 确认非空且与服务端一致 |
| FILE_TOKEN_KEY | 假设填随机强密钥 | 确认长度至少 6 位，未用示例值 |
| INVOKE_TOKEN_SECRET | 假设填随机强密钥 | 确认长度至少 32 位 |
| PRO_TOKEN 与 PRO_URL | 假设两者同时配置 | 确认取值一致，App 配置 PRO_URL 时 PRO_TOKEN 必填 |
| DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED | 假设保持 false | 确认 App 与 Admin 配置一致 |

起点取值的理由为满足文档所述最小长度或成对配置要求，比较对象为文档中对应变量的必填与一致条件。

## 容易做错的三处

1. 把“待审核”审批单当作已批准授权，输入为审批单状态字段，比较对象为拟稿句中的“已批准”，可观察结果为同字段取值互斥，拟稿句未获支持。
2. 把检索命中当作权限校验，输入为一次知识库查询，比较对象为团队成员的实际授权记录，可观察结果为检索返回内容与授权范围不一致，需回到成员权限配置核对。
3. 把旧 `config.json` 字段名当作现行环境变量，输入为旧配置字段 `systemEnv.hnswEfSearch`，比较对象为现行变量 `HNSW_EF_SEARCH`，可观察结果为旧字段不再被读取，须改为环境变量。

## 怎么确认配好了

1. 输入假设审批单原文与拟稿句，比较状态字段取值，仅当审批单状态为“已批准”且拟稿句与之一致时，拟稿句才获支持；当前为“待审核”，记录为未获支持。
2. 输入一次检索请求，比较返回内容与成员授权记录，观察是否出现授权范围外材料；出现即记录为权限核对缺口，检索本身不构成授权。
3. 输入旧配置字段名与现行变量名，比较服务启动日志中是否出现变量校验失败；仅当现行变量已按文档设置且启动校验通过时，记录为配置就绪，不声称已实测。
