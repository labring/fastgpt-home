# 品牌自播直播间运营的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

在品牌自播直播间运营的运营权限与交接管理中，本页说明FastGPT的对话日志与审计如何衔接资料。直播脚本、商品卡和评论在会话中各有性质，需要回查场次与真实执行依据。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

品牌自播交接可先定位解释脚本、商品卡或本场评论的会话。自拟交流没有播出或成交记录，chatId要结合场次和资料身份核对，不能从聊天生成脚本推定主播已经说过。日志实际返回字段需看，不宣称完整直播、广告与交易资料自动留存。评论是陈述，商品卡是依据范围，两者不能借一次答复互相补成实际执行结果。

## 配置怎么定

| 日志交接核对 | 本题自拟记录 | 需补或回查的依据 |
| --- | --- | --- |
| 场次身份 | 旧场对话进入本场 | 核原题和资料时间 |
| 脚本执行 | 拟说内容与实际播出分开 | 另取本场来源 |
| 评论性质 | 话语与真实交易分开 | 未直接判成交 |
| 运行返回 | detail与responseData | 答复未充作全部证据 |
| 正式发布 | 批准权限留存另落实 | 日志未代替直播效果 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

场次错配：若上一场对话进入当前交接，应核原问题和资料时间；脚本冒发言：若拟说内容被当真实播出，应另取本场播出依据；评论冒交易：若观众话语被写成成交，应查实际交易来源。三项分别核身份、内容执行与业务记录，不以对话最近或名称相似合并。

## 怎么确认配好了

验收保留场次、来源性质、真实返回和缺证，调试及正式输入历史分别核。需要运行详情时按官方契约设置detail并检查responseData，不把答复文本当全部运行证据。内容批准、账号发布、权限及留存要求由完整业务方案落实；本次日志交接不证明直播已执行、宣传已核准或经营效果已经产生。
