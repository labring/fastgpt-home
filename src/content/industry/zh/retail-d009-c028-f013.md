# 品牌自播直播间运营的运营权限与交接管理：权限与数据隔离

## 这个品类的数据长什么样

在品牌自播直播间运营的运营权限与交接管理中，本页说明FastGPT的权限与数据隔离如何衔接资料。交接直播场次资料时核未播内容和商品依据，另验原账号及外部发布身份。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

场次交接可拟待核脚本、商品卡新版和上一场评论摘记，接手人员拟查本场仍缺什么，不包含真实观众资料。先按场次、商品和版本列资源，由责任人确认新账号读取及维护范围。旧脚本留存供追溯，不说明原运营继续获权，也不能替本场适用条件。未播稿转交只描述工作安排，不能把“已交给主播”改成已经播出或已获宣传批准，账号发布资格也需独立核对。

## 配置怎么定

| 直播交接权限 | 本场待核来源 | 验收动作 |
| --- | --- | --- |
| 当前任务 | 未播脚本和新版商品卡 | 新账号必要原文 |
| 旧场次 | 历史稿不代本场条件 | 版本及实际返回 |
| 原运营 | 内部脚本评论撤权 | 同源回答和拒绝 |
| 外部发布 | 平台身份和资格另验 | 账号及业务许可 |
| 播出结果 | 交接不排播发布核成交 | 真实记录及确认 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 接手人员只读上一场脚本便称本场内容齐备：并列待核清单、限定和实际返回，确认新商品卡是否取得，不借同商品补版本。

- 原运营仍读应撤销的内部脚本或受限评论资料：保留同源完整回答查范围，场次结束和归档不证明真实拒绝。

- 内部运营更换被当直播平台身份终止或发布资格转交：分别核外部账号及业务许可，移交素材不发布，也不证明商品主张已核。

## 怎么确认配好了

验收让接手账号读本场待办，再用原人员及无关场次身份请求同一限制来源，记录原句、操作与拒绝。若访问正确却答旧限定，查本轮输入版本，不扩全商品素材。外部发布身份撤销、旧记录留存及本场缺证分开留档，补新依据后按原范围复测。交接不排直播、发内容或核成交；实际播出和结果需对应记录，未确认条件继续待核，不由团队访问转交认定经营已执行。
