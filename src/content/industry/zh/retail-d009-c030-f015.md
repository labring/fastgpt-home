# 商超供应商进场结算的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样

商超供应商进场结算以购销或代销账款为主，供应商不一定驻场经营。这一差别直接影响交接范围：采购合同、送货验收单、返利协议、对账单构成核心材料，ERP采购、供应商门户、POS销售与财务系统是主要数据来源。资料更新频率为周、月，检索侧不据此推导批量同步或实时触发机制。

运营权限与交接管理的检索任务，是把材料中的主体、对象、状态、有效范围找出来供人工核对。检索召回只负责返回引用内容，不承担授权判定。引用内容以数组输出，长度可以为0，未检索到内容时输出链路仍走通。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，此时只核对向量模型标识、排除不符合者并记录实际观察，不执行跨模型检索来比较漏召回。

搜索模式按测试问题在语义检索、全文检索与混合检索之间比较，不预设一种模式适合全部资料。混合检索通过RRF融合多路结果，RRF是融合过程，不作为开关描述。结果重排须具备重排模型并按设置启用，图片检索须有相应图像输入及模型能力，文档总流程图列出的可选路径不代表每次请求全部执行。

最低相关度是0-1的过滤阈值，仅在语义检索或使用结果重排时生效，不承担权限或实体隔离。引用上限以token为单位，控制每次搜索最多引用的内容量。问题优化用于指代消除与问题扩展，会增加一次模型调用。

## 配置怎么定

假设演练样本：某商超与某供应商签订购销采购合同，合同载明结算周期为月结30天，返利协议约定按进货额2%计算季度返利，送货验收单记录实收数量与差异，对账单列出本期应付。交接请求拟稿句为“供应商进场结算的返利扣点按合同约定执行，交接后由接手人继续核对”。该句未载明返利比例、计算期间与授权边界，属未获支持。

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 采购合同库、返利协议库 | 两库向量模型标识相同方可共同关联，不同则排除 |
| 搜索模式 | 混合检索 | 与语义检索、全文检索分别跑同一测试问题，比较引用内容 |
| 引用上限 | 假设起点2000 token | 用长短不同的送货验收单与对账单测试内容完整性，再调整 |
| 最低相关度 | 假设起点0.5 | 先标注相关与无关样本，比较过滤后引用内容 |
| 问题优化 | 开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 按设置启用 | 具备重排模型时比较重排前后候选排序 |

## 容易做错的三处

1. 把检索召回当成授权执行。输入为交接请求拟稿句与检索返回的引用内容，比较引用内容是否载明授权主体与有效范围，观察结果为引用内容未载明授权边界时，该请求仍处待核实。
2. 把最低相关度当成权限或实体过滤。输入为最低相关度设置值与不同主体的对账单，比较过滤前后返回内容，观察结果为相关度阈值不排除无关主体记录。
3. 把跨向量模型的知识库强行共同关联。输入为两个知识库的向量模型标识，比较标识是否一致，观察结果为标识不同时排除该库，不执行跨模型检索比较。

## 怎么确认配好了

- 验证一：输入假设样本中的采购合同原文与拟稿句“返利扣点按合同约定执行”，比较拟稿句是否载明返利比例与计算期间，观察结果为原文未载明该比例时，判定为未获支持，保留证据缺口。

- 验证二：输入假设样本中的送货验收单与对账单，比较同一期间同一供应商的实收数量与应付金额字段，观察结果为同字段取值互斥时判定矛盾，仅有相关阶段证据时判定待核实。

- 验证三：输入明确的纸面空结果[]，核对下游设计是否按引用长度为0继续走通输出链路，观察结果为下游未因空数组中断时满足条件。检索检查只记录观察与失败分支，不保证首条命中或全部召回。
