# 外贸退运与索赔的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在外贸退运与索赔的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。退运索赔交接分开核原仓接收、损伤依据与申报状态，拟退安排和承运交接均不证明原仓已经收到。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟交接文字写“拟退回原仓”，品质说明仍待补，退运申报只有草稿。表单可收这些原句和物件对应，人员选择补品质依据或核退运安排；它们是拟议业务输入，不是现成软件参数。提交后应核接收内容仍保留拟退和草稿，不从协议讨论推定对方接受索赔，也不提供报关规则或法律结论。

## 配置怎么定

| 退运交接表单 | 本题自拟原句 | 输入与业务核对 |
| --- | --- | --- |
| 原仓接收 | 仅拟退原仓 | 原仓本件接收凭据另取 |
| 品质缺项 | 待补检查 | 不改确定损伤 |
| 申报状态 | 草稿 | 不写办理完成 |
| 人员选项 | 补品质或核安排 | 连接分支收到原文 |
| 业务结果 | 原仓接收、申报、认可另核 | 承运交接不代原仓收到 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

拟退冒原仓收到：若拟退回原仓被写成原仓已接收，应取原仓对本件的实际接收凭据，交给承运方仅说明发起退运；缺品质变损伤确定：若待补说明变成已核损伤，应取对应检查；草稿冒申报完成：若整理文字被写成办理结果，应查真实提交与处理依据。三项分别核原仓接收、事实依据和办理状态，表单结束不能补齐。

## 怎么确认配好了

验收比较提交原文和下游收到的对象、去向及缺项，再沿所选分支检查实际输入。补品质原文后，只改变它支持的判断；原仓接收、申报处理和对方认可仍需各自凭据。正式退运、申报和索赔确认需要另接流程核权限及回执；节点记录交互并等待后继续，不自带货运系统或对方认可，表单交接完成不证明原仓已经收到，也不证明业务已结束。
