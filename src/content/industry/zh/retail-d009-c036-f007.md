# 多仓分仓与库存同步的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

在多仓分仓与库存同步的运营权限与交接管理中，本页说明FastGPT的对话日志与审计如何衔接资料。多仓交接历史要分清同步表更新、调出调入角色与记录环境，查到对话不说明库存已经同步。所用场景为自拟文字测试。

## 这些特征在「对话日志与审计」这一环带来什么约束

自拟人员消息写同步表已更新，调出备注仍待核，助手却答两仓已平；另有测试会话演示类似问法。日志复核应先关联会话与真实业务环境，再看实际详情返回的原句及角色。文件更新不证明外部库存已写，测试回答也不说明真实系统执行。若某些业务记录未在响应中返回，应另取，不假设对话天然包含全部仓库凭据。

## 配置怎么定

| 多仓交接历史 | 自拟记录差别 | 核对对象 |
| --- | --- | --- |
| 更新说明 | 仅文件文字 | 非库存同步 |
| 调出角色 | 不可记成调入 | 对源备注与回答 |
| 测试环境 | 演示会话 | 非正式执行 |
| 返回缺项 | 业务凭据未全返 | 另取真实记录 |
| 后续状态 | 写库撤权另核 | 日志不证账实一致 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `对话身份` | 将目标会话与资料身份对应。 |
| `运行详情` | 按接口契约查看运行详情。 |
| `字段含义` | 以实际返回字段为准。 |
| `调试与正式调用` | 核调试与正式调用的输入差别。 |
| `业务审计分工` | 对账及留存需方案另行落实。 |

## 容易做错的三处

文字冒同步：若更新说明被当两仓已平，应查实际系统结果；调出记成调入：若角色被倒置，应对源备注与回答实际用词；测试冒正式：若演示会话支持真实交班，应核环境和业务关联。三项分别核执行、角色与记录来源，不由同仓名补齐。

## 怎么确认配好了

验收保留会话标识、来源环境及真实返回，补正确角色后复问，只修对应解释，库存结果仍需独立回执。若信息只是旧表更新，不改变同步状态。外部库存写入、权限变更和交班结项需另接业务记录，日志存在不证明撤权或账实一致，也不自动调整仓库；未返回数据不等于实际没有库存。
