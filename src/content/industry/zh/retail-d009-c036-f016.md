# 多仓分仓与库存同步的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在多仓分仓与库存同步的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。多仓交接表单要保留调拨角色与库存时点，提交的同步说明不证明另一仓已收到货物。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟交接说明写调出仓待出库、调入仓等待接收，库存同步片段只是读取时快照。表单可收两仓角色原句、快照性质和待补项，让人员选择核调出或补调入接收。不能让选择直接指定真实库存或人员身份，也不假定仓储系统已经连上。提交后这些内容需要由实际下游接收，角色和时点不能在整理时合并。

## 配置怎么定

| 多仓交接核对 | 自拟角色状态 | 下游所需 |
| --- | --- | --- |
| 调出仓 | 待出库 | 不传成调入角色 |
| 调入仓 | 等待接收 | 不写已经到货 |
| 库存快照 | 读取时存量 | 不称本次移动 |
| 人员选择 | 核出库或补接收 | 实际仓库对象正确 |
| 业务写入 | 同步与关闭另核 | 节点不证账实一致 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

角色颠倒：若调出仓原句被传成调入仓，应对照提交角色与接收值；快照冒移动：若存量被写成本次流转，应查真实出入记录；等待冒收到：若待接收被写成到仓，应取调入仓本次实际接收。三项分别核角色、数量含义和阶段，不能由同步字样证明。

## 怎么确认配好了

验收逐项比较表单提交与接收内容，沿选中分支查看对应仓库是否正确。补调出记录后，仅更新出库状态，调入仍待接收时不顺带确认。库存同步、调拨写入与异常关闭需要另接流程核权限及回执；交互记录和节点继续只说明流程动作，不证明货物移动或多个仓库账实一致。
