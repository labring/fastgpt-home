# 大卖场生鲜联营柜台的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样
大卖场生鲜联营柜台由供应商驻场经营并按销售分成，日常资料集中在联营合同、日销售报表、损耗单与食品进货查验记录。这些资料同时承载权限事实：谁可签署损耗确认、哪一批进货凭证对应哪个供应商、交接时哪些操作仍处于待审核状态。检索环节只负责从已入库资料中召回文本，不能替代授权判断。资料更新频率为日或每批，检索结果反映的是入库时的内容，不承担实时同步职责。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库；跨不同向量模型的库不可共同关联，应先核标识并排除不符合者。搜索模式可选语义检索、全文检索或混合检索，混合检索通过 RRF 融合多路结果，RRF 是融合过程，不是开关。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离。引用上限以 token 为单位。问题优化用于指代消除和问题扩展，会额外调用模型。输出引用内容以数组返回，长度可以为 0，空结果链路仍走通。图片检索须有图像输入及相应模型能力，重排须具备模型并按设置启用。

假设演练样本：某门店生鲜部与联营供应商甲签订联营合同，约定损耗由双方按比例分摊。纸面材料原文为：“供应商甲驻场人员负责每日损耗单初填，门店生鲜部主管复核后确认；未经复核的损耗单不得进入结算。”另有一条交接请求拟稿：“请将供应商甲昨日损耗单直接确认并计入分成结算。”该拟稿未附复核记录，也未说明复核人。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 只关联存放联营合同与损耗单的同一向量模型库 | 先核各库向量模型标识，排除不同模型者，不执行跨模型检索 |
| 搜索模式 | 对“损耗单复核”类问题分别试语义检索与全文检索 | 比较同一问题在两模式下的召回内容，观察哪类资料被命中 |
| 引用上限 | 假设起点设为能容纳一段损耗单条款的 token 量 | 用长短不同的实际资料测试内容是否完整，再调整 |
| 最低相关度 | 先标注相关与无关样本，再设一个待比较值 | 仅在语义检索或结果重排时生效，比较过滤前后候选 |
| 问题优化 | 对多轮追问短问题开启，对明确问题关闭 | 比较原问题与优化后问题，核对主体是否被改错 |
| 重排 | 按实际是否具备重排模型决定启用 | 启用后比较重排得分与向量得分，观察排序变化 |

## 容易做错的三处
1. 把检索命中当作授权完成。输入是“损耗单复核”检索结果，比较的是该结果是否包含复核人签署字段，若结果只有初填记录，则复核状态未获支持。
2. 把待审核交接请求当作已确认。输入是上述拟稿句，比较的是拟稿与材料原文中“未经复核不得进入结算”的条件，若拟稿未附复核记录，该请求处于待核实。
3. 把不同向量模型的库强行共同关联。输入是两个库的向量模型标识，比较二者是否一致，若不一致则排除，不推断关联后的运行结果。

## 怎么确认配好了
1. 输入假设材料原文与拟稿句，比较检索返回内容是否含“复核后确认”字段，出现该字段且对应同一损耗单，才满足核对条件；仅出现初填记录则记录缺口。
2. 输入同一问题分别走语义检索与全文检索，比较两次召回内容差异，观察精确词命中与语义命中各自覆盖哪些条款，不保证首条命中或全部召回。
3. 输入一个明确无对应资料的纸面问题，比较输出引用数组是否为 []，核对下游设计能否承接空结果；不声称虚构规则检索一定返回 []。
