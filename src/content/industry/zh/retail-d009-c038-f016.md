# 大卖场生鲜联营柜台的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在大卖场生鲜联营柜台的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。生鲜联营柜台交接要分开合同范围、进货检查和损耗待核，日报存在不证明当班已经履约。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟柜台交班有当班日报标题、进货检查待补和损耗说明草稿，合同摘录只写联营责任范围。表单可收柜台与这些原句，人员选择补检查或核损耗来源，不能由选项自动判定责任。日报标题不说明食品检查已做，合同也不能补出当班执行；这里不写食品安全标准、损耗金额或经营效果，未证实状态随输入留下。

## 配置怎么定

| 联营柜台交接 | 自拟原句状态 | 接收检查 |
| --- | --- | --- |
| 合同范围 | 说明责任约定 | 非当班履责 |
| 进货检查 | 资料待补 | 不称已经完成 |
| 损耗说明 | 草稿待核 | 不确定归因 |
| 日报对象 | 特定柜台 | 排除其他点位 |
| 后续业务 | 验收库存对账另核 | 交互非业务结论 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

合同冒履责：若责任约定变成已完成检查，应取当班实际记录；草稿冒损耗确定：若待核说明被写成已确认，应查对应依据；柜台串用：若另一联营点日报进入本次，应核原对象与接收文本。三项分别核约定与行动、事实状态和覆盖对象，不能因同商场而合并。

## 怎么确认配好了

验收查看提交与实际接收是否保留柜台范围和待补项，沿补检查与核损耗的连接分支逐项核。补入检查原文后只更新覆盖的进货，不顺带确认损耗归因或其他货物。正式验收、库存处理和双方对账需要另接流程核权限及回执，交互完成不证明食品合格、责任已定或当班所有事情结束。
