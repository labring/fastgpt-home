# 天猫旗舰店日常运营的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
天猫旗舰店日常运营围绕商品发布页、品牌授权书、发货承诺记录、售后工单展开，品牌授权与旗舰店身份是平台强调的重点。对话日志与审计这一环，数据来源包括天猫商家后台、天猫规则中心、ERP订单表与客服聊天记录。品牌电商部、天猫店长与代运营公司之间常有运营权限交接，交接期间哪些材料、操作与请求处于何种授权状态，需要逐项核对。客服聊天记录按每单产生，日更节奏使日志量持续累积，核对工作需按对话身份逐条定位，不能把不同入口的会话混算。

## 这些特征在「对话日志与审计」这一环带来什么约束
运营交接时，对话日志用于还原某轮对话由哪个 chatId 承载、由哪个 dataId 标识、经哪个 appId 调用。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。检索或表单收集值，业务验证、审批、数据库写入与外部同步需要各自的下游实现。相似度分值属于检索相关度，不承担业务实体或权限过滤职责。

假设演练样本：某天猫旗舰店代运营交接，材料原文为“品牌授权书载明授权方A，被授权方B，授权范围限于天猫旗舰店商品发布页维护，有效期至2025年3月31日”“发货承诺记录载明48小时发货承诺由B执行”。拟稿句为“B自2025年4月起继续以授权方名义维护商品发布页”。判定时，拟稿句的期间超出授权书载明的有效期，授权范围仅含商品发布页维护，未载明4月后的续期或新授权，该期间的使用主张未获支持。

## 配置怎么定
下表为本次假设试验起点，选值理由与比较对象一并列出，非官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| appId | 交接样本指定应用 | 与请求体 body.appId 及密钥关联值比较，取优先级最高者 |
| chatId | 交接样本对话标识 | 与日志记录中的 chatId 比较，确认同一会话 |
| dataId | 待核对对话标识 | 与对话列表中 dataId 比较，定位单条对话 |
| detail | true | 需要运行详情时设置，核对 responseData 是否返回 |
| loadCustomFeedbacks | true | 读取自定义反馈时设置，核对返回字段是否含该项 |
| source | api | 获取 API 创建会话时设置，与页面会话区分 |

## 容易做错的三处
1. 把 chatId 相同当作业务身份相同。输入为两个不同入口的会话记录，比较 chatId 与业务主体字段，观察是否指向同一被授权方。
2. 把 detail=true 返回的 responseData 当作完整业务留存。输入为一次调用响应，比较返回字段与业务所需字段，观察缺失项是否被标记为未知。
3. 把相似度分值当作权限过滤结果。输入为检索返回的 score，比较其与授权范围的对应关系，观察是否仅反映相关度。

## 怎么确认配好了
1. 取假设样本材料原文与拟稿句，输入拟稿句与授权书有效期字段，比较拟稿期间是否落在授权有效期内，观察拟稿句是否因超出期间而未获支持。
2. 取一次调用请求，输入 appId 与 chatId，比较日志中记录的 chatId 与请求 chatId 是否一致，观察能否定位到对应 dataId。
3. 取 detail=true 的响应，输入 responseData，比较其中模块字段与业务所需字段清单，观察未返回字段是否保持未知状态，不推定已留存。
