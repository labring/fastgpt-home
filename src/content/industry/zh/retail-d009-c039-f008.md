# 天猫旗舰店日常运营的运营权限与交接管理：工作流编排

## 这个品类的数据长什么样

天猫旗舰店的日常运营材料围绕商品发布页、品牌授权书、发货承诺记录和售后工单展开。品牌授权书载明授权方、被授权主体、授权商品范围和有效期，这些字段决定谁可以代表品牌在旗舰店执行发布、改价或售后处置。发货承诺记录以每单为更新单位，记录承诺时限与实际交付节点。售后工单承载退换、赔付等诉求的处理状态。

这三类材料的共同特征是主体、对象、状态和有效范围必须同时可读。授权书只有授权方和被授权方，缺少商品范围时无法判断某次商品发布是否落在授权内。发货承诺记录只有承诺时间，缺少订单归属时无法与具体交接请求对应。日常运营以日、每单为更新节奏，交接动作需要在这些材料之间建立可核对的对应关系。

## 这些特征在「工作流编排」这一环带来什么约束

工作流编排在运营权限与交接管理中承担的是把材料与请求串成可核对路径的职责。表单输入节点触发后对话进入交互状态，记录工作流状态，用户填写必填信息并提交后，节点把信息传给后续节点。用户选择节点同样进入交互状态，用户作出选择后执行相应的“是”分支。这两个节点的行为是收集与分支判断，不构成授权审批，也不构成订单写入或外部状态同步。

假设演练样本：材料原文为“授权方甲授权乙在天猫旗舰店销售A类商品，授权有效期至2025年12月31日”“发货承诺记录显示订单号T001承诺48小时内发出，实际发出时间为下单后72小时”“售后工单W001状态为待审核”。待判定拟稿句为“乙有权在2025年12月31日前对A类商品执行发布，且T001延迟发货赔付已由系统自动完成”。

该拟稿句包含两项待核实内容。授权范围与有效期在材料中有对应字段，可以比对主体、商品范围与日期。延迟发货赔付是否自动完成，材料只显示实际发出时间晚于承诺时间，未载明赔付执行状态，属于未获支持。工作流编排可以设计表单输入收集交接请求、用户选择判断分支，赔付执行需要另接业务接口或后续流程，检索与表单不承担授权执行。

## 配置怎么定

| 配置项 | 设置或核对内容 | 与本页样本的关系 |
| --- | --- | --- |
| 表单输入节点 | 触发后进入交互状态，收集必填信息，提交后传给后续节点 | 收集交接请求中的主体、商品范围、订单号 |
| 用户选择节点 | 用户作出选择后执行相应的“是”分支 | 对授权有效期与赔付状态分别设置分支 |
| 交互状态核对 | 记录状态是交互节点行为，不另设全局状态开关 | 确认交接请求进入交互状态后继续执行 |
| 输出承接核对 | 将收集信息明确传给后续检索、判断或接口节点 | 比对表单输出与授权书、发货记录字段 |
| 外部操作分工 | 订单写入、文档回填及外部状态同步须另接业务接口 | 赔付执行不放在表单或选择节点内 |
| 假设试验起点 | 本次假设试验将授权有效期比对起点设为2025年12月31日 | 选择理由为样本授权书载明的截止日期，与拟稿句日期比较 |

## 容易做错的三处

1. 将表单输入收集到的交接请求当作授权已获批准。输入是收集动作，授权状态需要比对品牌授权书的主体、商品范围和有效期。样本中乙的授权范围是A类商品，拟稿句若扩展到A类以外商品，缺少对应字段支持。

2. 将用户选择节点的“是”分支当作赔付已执行。分支判断只决定流程走向，赔付执行需要业务接口。样本中T001实际发出时间晚于承诺时间，材料未载明赔付状态，拟稿句声称自动完成属于未获支持。

3. 将检索结果当作权限隔离手段。语义召回和相关度不负责权限或实体隔离，跨不同向量模型的库不可共同关联。样本中授权书与发货记录若来自不同模型库，需要先核标识并排除不符合者，记录实际观察，不执行跨模型检索来比较漏召回。

## 怎么确认配好了

1. 输入样本材料原文与拟稿句，比较授权书的主体、商品范围、有效期三项字段与拟稿句声明。预期现象为三项字段均可对应时授权范围部分获得支持；样本中有效期至2025年12月31日与拟稿句日期一致，商品范围为A类，若拟稿句限于A类则该项获得支持。

2. 输入样本发货承诺记录与拟稿句赔付声明，比较订单号T001的承诺时间、实际发出时间与赔付执行字段。预期现象为材料载明赔付执行状态时该项获得支持；样本只载明实际发出时间晚于承诺时间，赔付执行字段缺失，该项待核实。

3. 输入样本售后工单W001与交接请求，比较工单状态字段与请求中关于处置完成的声明。预期现象为工单状态为待审核时，处置完成声明未获支持；待审核不证明缺少操作权限，也不构成处置完成。若材料未载明审核结果，记录证据缺口。
