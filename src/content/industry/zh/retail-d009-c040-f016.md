# 客服咨询知识库维护的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在客服咨询知识库维护的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。知识库维护交接应保留旧问答、当前参数与升级工单的状态差别，表单提交不自动更新知识内容。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟交接列旧FAQ仍在引用、参数说明已改而待核，升级工单只记已接收。表单可收旧句、新说明与适用商品，人员选择核参数或补升级结果。这里是拟议交接材料，不假定表单直接写知识库或重新索引；话术模板存在也不证明已发布。接收步骤应能分清建议修改和真实生效内容，不能从交接完成推定旧答复已撤下。

## 配置怎么定

| 知识维护交接 | 自拟待办 | 接收所需 |
| --- | --- | --- |
| 旧FAQ | 仍被引用 | 保留待改原句 |
| 新参数 | 已改但待核 | 核适用商品 |
| 话术模板 | 不证已经发布 | 取实际更新记录 |
| 升级工单 | 只说明收件 | 补真实处理结果 |
| 后续变更 | 写库索引另接 | 提交不代表同步 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

建议冒生效：若拟改问答被写成已经替换，应查真实更新记录；参数错商品：若另一型号说明用于本题，应核适用对象与接收原句；接收冒解决：若升级工单收件被写成问题已结，应取对应处理结果。三项分别核内容状态、对象和业务阶段，不由人员选择补齐。

## 怎么确认配好了

验收比较提交与接收是否同时保留旧句和新说明，沿核参数或补结果分支查具体商品。补参数确认后，只更新被证实的修改建议，正式发布仍需自己的记录。知识变更、索引处理和升级关闭需要另接步骤核权限及回执，交互记录不证明资料已同步，也不证明以后所有问法都会得到正确答复。
