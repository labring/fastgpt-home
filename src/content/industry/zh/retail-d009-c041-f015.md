# 平台促销报名与价格管理的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样

平台促销报名与价格管理围绕活动报名表、促销价审批单、库存锁定表、活动复盘表展开。与商品标题合规相比，本品的核心材料是价格、库存与活动节奏，宣传用语审查处于次要位置。数据来源包括天猫营销后台、京东活动后台、ERP库存与历史成交价，更新频率为周或每场活动。运营交接时，材料、操作与请求各自处于不同授权状态。检索结果只是候选引用，不构成审批、锁库或改价授权。促销价审批单的签署状态、库存锁定表的执行状态、报名表的提交状态，均需与检索到的原文逐项比对，不能由召回得分推断。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，应先核标识并排除不符合者，记录实际观察，不执行跨模型检索来比较漏召回。语义检索依赖向量相似度，全文检索依赖关键词命中，混合检索通过 RRF 融合两路结果。RRF 是混合结果的融合过程，不是可开启的开关。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不是权限或实体隔离手段。引用上限以 token 为单位。问题优化用于指代消除和问题扩展，会增加一次模型调用。图片检索须有图像输入及相应模型能力，重排须具备模型且按设置启用，可选路径不代表每次请求全部执行。引用内容以数组输出，长度可以为 0，空结果链路仍走通。

假设演练样本：某品牌销售计划人员拟交接一份促销价审批单，原文为“活动名称：春季焕新；适用平台：天猫；报名商品：A款；促销价：129元；审批状态：待审核；申请人：销售计划岗；提交日期：3月1日”。另一份库存锁定表原文为“锁定对象：A款；锁定数量：500件；锁定状态：已锁定；锁定日期：3月2日”。待判定拟稿句为“A款促销价已审批通过，可执行锁库并同步多平台价格”。核对时须比较审批状态字段与拟稿句的“已审批通过”是否同一字段、同一期间；锁定状态字段与“可执行锁库”是否同一对象；拟稿句中的“同步多平台价格”在原文中无对应字段，属未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 仅关联促销报名与价格管理资料库 | 该库须使用相同向量模型，核对库标识后排除不符者 |
| 搜索模式 | 先按语义检索与全文检索分别试跑 | 用同一测试问题比较两路召回内容，再决定是否混合 |
| 引用上限 | 设为覆盖一份审批单全文的 token 量 | 以审批单与库存锁定表实际长度为准，比较内容是否被截断 |
| 最低相关度 | 先标注相关与无关样本再调阈值 | 仅在语义检索或结果重排时生效，不用于权限过滤 |
| 问题优化 | 对含指代词的交接追问开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 候选较多且问题完整时启用 | 重排得分用于过滤，须确认重排模型已具备 |

## 容易做错的三处

1. 把检索召回当作授权执行。输入为待审核审批单，比较审批状态字段与拟稿句，若拟稿句写“已审批通过”而原文为“待审核”，则属把待审核当作批准。可执行检查：读取审批状态字段，与拟稿句逐字比对，观察是否出现状态不一致。
2. 把不同向量模型的库共同关联。输入为两个库标识，比较其向量模型标识，若不一致仍尝试关联，则违反相同向量模型要求。可执行检查：核对库标识与模型标识，排除不符者并记录实际观察。
3. 把空引用输出当作检索失败或权限拒绝。输入为明确的纸面空数组，比较下游设计是否仍走通，若将空结果判定为无权限，则混淆了输出长度与授权状态。可执行检查：以空引用数组核对下游链路，观察是否按设计继续执行。

## 怎么确认配好了

1. 针对“待审核”审批单拟稿句，输入审批单原文与拟稿句，比较审批状态字段是否同一字段、同一期间，若原文为“待审核”而拟稿句为“已审批通过”，则拟稿句未获支持，应记录证据缺口。
2. 针对库存锁定表，输入锁定状态字段与拟稿句“可执行锁库”，比较锁定对象与状态是否同一对象，若原文为“已锁定”而拟稿句称“可执行锁库”，则须区分锁定状态与执行动作，不将检索结果当作执行授权。
3. 针对“同步多平台价格”一句，输入审批单与库存锁定表全部字段，比较是否存在对应同步字段，若两份原文均无该字段，则该句属未获支持，保留为待核实，不补造授权或生效条款。
