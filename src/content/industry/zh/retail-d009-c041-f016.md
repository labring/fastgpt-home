# 平台促销报名与价格管理的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在平台促销报名与价格管理的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。促销交接表单要分清报名、批准范围与库存预留，申请材料不能替代实际上线和执行。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟交接有待审核报名、限定商品的批准说明和库存预留计划，复盘资料仍为空白。表单可收商品与这些阶段原句，让人员选择核批准范围或补预留结果，不填价格或活动效果。批准只覆盖明示对象，不自动扩到全店；库存计划也不是预留完成，空白复盘更不能补出活动已发生。提交后应检查下游是否仍留下这些界线。

## 配置怎么定

| 促销交接表单 | 自拟阶段 | 核对依据 |
| --- | --- | --- |
| 报名状态 | 待审核 | 非已上线 |
| 批准对象 | 限定商品 | 不扩全店 |
| 库存安排 | 预留计划 | 取实际锁定记录 |
| 复盘材料 | 空白 | 不补活动事实 |
| 路径结果 | 按范围传原句 | 缺项继续保留 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

批准扩范围：若某商品批准被传成全店，应核源范围与接收值；计划冒锁定：若预留安排写成库存已锁，应取实际业务记录；报名冒上线：若待审被说成活动已开，应查真实发布状态。三项分别核覆盖、库存动作和活动阶段，不由一次提交决定。

## 怎么确认配好了

验收保留表单原句和所选去向，分别检查核范围与补结果的实际输入。补商品批准后只改该范围，未核预留和上线状态仍待补。正式活动设置、库存操作与对外发布需要另接流程核权限及回执，节点等待后继续不代表平台已受理，更不证明活动运行或商品供应得到保障。
