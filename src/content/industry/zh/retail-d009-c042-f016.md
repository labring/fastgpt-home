# 平台商品标题与详情合规的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在平台商品标题与详情合规的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。标题详情交接要保留文案版本、资料覆盖和待核意见，禁用词清单不等于整页已经审查通过。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟标题清单拟改商品描述，详情素材仍用旧版，质检资料只覆盖送检对象。表单可收版本与待核原句，人员选择核素材对应或补质量依据；词语清单只是相关材料，不替代完整审查，也不在本题给出法律判断。拟改标题不能当已发布，送检资料不能自动扩为所有商品，接收步骤应保留这些来源界线。

## 配置怎么定

| 标题详情交接 | 自拟资料差别 | 传递检查 |
| --- | --- | --- |
| 拟改标题 | 尚未发布 | 保留建议性质 |
| 详情素材 | 仍属旧版 | 核实际对应 |
| 质检范围 | 仅送检对象 | 不扩全部商品 |
| 词语清单 | 非完整审阅 | 取真实审查记录 |
| 正式页面 | 替换发布另接 | 表单不自动改页 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

新旧素材混用：若新标题配旧详情，应核提交版本与实际接收；报告扩覆盖：若送检样被用于全部商品，应查报告所指与适用；清单冒通过：若查过词语表就写整页已获准，应取实际审阅记录。三项分别查版本、证据范围和批准性质，不能由文件齐全补齐。

## 怎么确认配好了

验收沿素材核对与质量补证路径看实际输入，补版本说明后只修对应关系，审阅和发布仍需各自依据。若新资料只含标题，不应顺带确认详情全部适用。正式审查、页面替换与发布需另接流程核权限及回执，表单交互不证明内容符合法规或平台要求，也不自动修改商品页。
