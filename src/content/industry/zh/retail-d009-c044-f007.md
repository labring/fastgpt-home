# 平台广告投放与站内流量的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
广告投放按流量和转化实时调价，投放专员、品牌市场部与代运营投手在巨量千川、京东快车、阿里妈妈与店铺成交数据之间协作，日更或小时级数据使交接频繁发生。对话日志与审计环节要处理投放计划、关键词报表、人群包说明与转化归因表，这些材料决定谁在何时以何种身份发起了哪次对话。材料本身不构成授权，检索与表单收集只提供待核对的值。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话身份须结合 chatId 核对目标对话与业务记录，不同入口的会话不能混算。需要运行详情时按官方契约设置 detail 并检查 responseData，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，须分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。以下为假设演练样本，用于说明核对方式，不指向任何真实主体。

假设演练样本：材料原文为“2025年3月1日至3月31日，投放组A使用应用 X 的 API Key 创建会话，用于关键词报表核对；会话 chatId 记为 adgroupA-0312；该期间内归因表由运营组B维护。”拟判定句为“投放组A已获得运营组B的归因表写入授权。”该句涉及主体、对象、期间与权限范围，材料未载明授权条款，故该句未获支持，属待核实，不构成对权限的否定。

## 配置怎么定
下表围绕上述样本，列出与本页功能、主任务相关的官方已说明设置或实施核对项。数值仅为本次假设试验起点，用于与对照值比较，不是官方默认值。

| 配置或核对项 | 本次假设起点及选择理由 | 比较对象与观察结果 |
| --- | --- | --- |
| body.appId 与鉴权 | 样本以 API Key 调用，优先在请求体传 appId | 与密钥关联的 appId 比较，确认是否一致 |
| chatId | 样本记为 adgroupA-0312，长度小于 250 | 与归因表记录中的会话标识比较 |
| detail | 样本需运行详情，设为 true | 与响应中 responseData 是否出现比较 |
| source | 会话列表查询用 source=api | 与页面来源会话比较，确认范围差异 |
| responseChatItemId | 样本按同一 chatId 下唯一设定 | 与已有响应 ID 比较，重复即需更换 |
| authProxy | 样本涉及成员身份代理，须由团队所有者开启 | 与目标应用和会话权限比较，权限不足即不通过 |

## 容易做错的三处
1. 把 chatId 相同当作权限相同。样本中 chatId 为 adgroupA-0312，仅说明会话标识，未载明归因表写入权限，须与授权材料比较后判断。
2. 把 detail=true 返回的 responseData 当作完整业务留存。样本只要求运行详情，未返回的字段仍属未知，须逐字段核对。
3. 把 API 来源会话与页面会话合并统计。source=api 只取 API 创建会话，与页面来源比较时须分开记录。

## 怎么确认配好了
1. 输入样本材料原文与拟判定句，比较主体、对象、期间与权限范围四项是否同源同字段，只有授权条款明确载明写入权限才满足条件，否则记为待核实。
2. 输入样本请求参数，比较 body.appId 与密钥关联 appId、chatId 与归因表记录，观察响应中 responseData 是否出现，出现即满足 detail 生效条件。
3. 输入 source=api 的会话列表查询，比较返回 list 与页面来源会话，观察 total 是否只覆盖 API 来源，覆盖范围一致即满足条件。
