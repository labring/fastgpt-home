# 平台广告投放与站内流量的运营权限与交接管理：权限与数据隔离

## 这个品类的数据长什么样

在平台广告投放与站内流量的运营权限与交接管理中，本页说明FastGPT的权限与数据隔离如何衔接资料。按在投计划移交投手访问，检查旧代理、历史报表与外部投放身份的撤权范围。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

交接练习可列一份在投计划和一份已结束的品牌复盘，接手投手拟跟进前者。先确认完成任务需要的关键词、人群说明和归因资源，再以新账号试读当前版本。若只能读取已结束计划，不能证明当前工作资料可用；保留交接清单与实际所读计划排查指向或授权。相同渠道名或投手职务不应自动扩大到历史全部品牌，交接范围需责任人逐项确认。

## 配置怎么定

| 交接权限核对项 | 在投与历史资源 | 实际验收 |
| --- | --- | --- |
| 当前计划 | 关键词、人群及归因当前版 | 新账号实际试读 |
| 历史边界 | 结束计划及其他品牌另定 | 责任人确认移交范围 |
| 旧代理 | 计划报表附页逐项撤权验 | 完整返回及拒绝结果 |
| 外部身份 | 后台账号与接口会话另核 | 不从角色变更推同步失效 |
| 后续动作 | 换岗不执行出价或后台停用 | 保留未解决项与业务批准 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 新投手仅读已结束计划便称在投工作可用：核当前关键词、人群及归因版本，保存清单与返回，渠道职务不自动给全品牌权限。

- 历史他品牌资料因同代理被全部移交：逐资源确认必要范围，用无关品牌身份做否定测试，协作关系不构成跨品牌授权。

- 旧代理仍读受限人群，或内部变化被当后台会话已停：分别保存原身份返回及外部检查，归档不代替撤权，换岗也不执行出价调整。

## 怎么确认配好了

验收让新投手对在投计划完成必要读取，让旧身份和无关品牌身份对受限资源做否定测试，记录操作及拒绝结果。若授权正常但答案带入已结束期间，应查历史和来源对象；计划混用不是扩大资源权限就能解决。交接不自动执行出价修改或后台停用，技术操作权也不代表业务批准。最终保留未解决访问与外部撤权项，不把人员换岗写成投放调整已经完成。
