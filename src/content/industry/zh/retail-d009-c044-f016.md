# 平台广告投放与站内流量的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在平台广告投放与站内流量的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。广告运营交接要分开投放计划、关键词资料和归因解释，表单接收不代表已经投放或效果已经确定。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟交接有拟投计划、待核关键词表和归因说明草稿，人群包只描述适用条件。表单可收版本与渠道范围，人员选择核关键词来源或补归因依据，不填预算、点击或转化数值。计划不证明广告已经运行，归因草稿不证明某个渠道造成结果；人群描述也不等于真实用户明细，接收时应保留资料性质，不自动调广告后台。

## 配置怎么定

| 广告运营交接 | 自拟材料性质 | 接收核法 |
| --- | --- | --- |
| 拟投计划 | 非上线记录 | 不写广告已运行 |
| 关键词表 | 来源待核 | 核具体渠道 |
| 归因说明 | 草稿 | 不确定真实效果 |
| 人群描述 | 仅适用条件 | 非用户明细授权 |
| 后续分析 | 需数据和方法 | 表单不自动出报告 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

计划冒投放：若拟投文字变成已经上线，应查真实发布记录；关键词串渠道：若另一渠道资料进入本次，应核来源与接收对象；归因稿冒确定：若草案被写成真实效果结论，应取对应数据与方法依据。三项分别核运行阶段、范围和推断基础，不由材料提交解决。

## 怎么确认配好了

验收比较提交版本、所选分支和实际输入，补关键词来源后只更新对应范围，归因仍缺时仍待核。若只补投放计划，不能顺带确认广告可见。正式设置、上线和结果分析需要另接流程核权限、数据及回执，节点交互不证明广告效果，也不产生真实人群访问权限或自动对外报告。
