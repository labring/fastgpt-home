# 平台广告投放与站内流量的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

投放计划、关键词报表、人群包说明与转化归因表按日或按小时更新，交接时需核对材料的主体、对象、有效范围与当前状态。日更或小时更的数据意味着交接文档可能只反映某一时点，后续调整不在其中。投放专员、品牌市场部与代运营投手之间的权限边界，往往不体现在报表数值上，而体现在谁有权修改出价、谁有权导出人群包、谁有权确认归因口径。这些材料本身不构成授权，表单收集与检索命中也不产生操作许可。

## 这些特征在「部署与升级」这一环带来什么约束

升级前后，旧配置名称不能推断现行行为。AI Proxy 为必需依赖，`AIPROXY_API_ENDPOINT` 需填根地址，不追加 `/v1`；`AIPROXY_API_TOKEN` 需与服务端一致且非空。升级脚本属手动触发，需确认旧实例已停止、旧任务租约过期后再执行。检索命中不负责权限隔离，相关度分数不排除无关业务或未授权记录。以下为假设演练样本，用于说明核对方法。

假设演练样本：材料原文为「甲方品牌市场部于2026年3月1日将巨量千川账户A的出价修改权限交接给乙方代运营投手，交接范围限于关键词报表与人群包说明，有效期至2026年6月30日。转化归因表由甲方保留确认权。」待判定拟稿句为「乙方已获得账户A全部投放权限，可直接修改转化归因表并对外同步。」

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://aiproxy:3000` | 按文档要求填根地址，比较对象为带 `/v1` 的地址，后者不符合 |
| `AIPROXY_API_TOKEN` | 空值待填 | 文档要求非空且与服务端一致，比较服务端配置值 |
| `CODE_SANDBOX_TOKEN` | 与 `SANDBOX_TOKEN` 一致 | 文档要求两者一致，比较沙箱服务实际配置 |
| `AGENT_SANDBOX_PROVIDER` | 空 | 文档说明为空时不启用沙箱，比较是否配置对应 provider 必填变量 |
| `CHECK_INTERNAL_IP` | `false` | 文档说明仅作用于用户或工作流可控出站 URL，比较受影响范围 |
| 升级脚本执行前提 | 旧实例停止、租约过期 | 文档要求确认后再执行，比较集群实例状态 |

## 容易做错的三处

1. 把检索命中当作授权。输入为上述样本中「乙方代运营投手」的检索请求，比较对象为材料原文限定的「关键词报表与人群包说明」，观察结果为检索返回转化归因表时，不能据此认定乙方有权修改该表。材料原文明确归因表确认权由甲方保留。

2. 把待审核当作已批准。输入为「交接请求已提交」的记录，比较对象为材料原文「有效期至2026年6月30日」的授权状态，观察结果为请求处于待审核时，不能认定权限已生效。待审核不证明缺少操作权限，也不证明已获授权。

3. 把表单收集当作执行。输入为乙方填写的权限申请表单，比较对象为材料原文的授权边界，观察结果为表单已提交时，不能认定出价修改权限已转移。业务验证、审批与外部同步需有明确的下游实现。

## 怎么确认配好了

1. 针对样本原文「有效期至2026年6月30日」，输入为2026年7月1日的拟稿句「乙方当前持有账户A出价修改权限」，比较对象为原文有效期上限，观察结果为拟稿句超出有效期时，判定为未获支持，需记录证据缺口。

2. 针对样本原文「转化归因表由甲方保留确认权」，输入为拟稿句「乙方可直接修改转化归因表并对外同步」，比较对象为原文确认权归属，观察结果为拟稿句与原文同主体、同对象、同字段的取值互斥时，判定为矛盾。

3. 针对空结果承接，输入为纸面输入 `[]`，比较对象为下游设计是否对空结果作显式处理，观察结果为下游设计未说明空结果处理时，记录为未获支持，不声称虚构规则检索一定返回 `[]`。
