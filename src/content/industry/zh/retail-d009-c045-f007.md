# 平台店铺评价与体验分维护的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
评价维护处理售后履约后的消费者反馈，数据来源包括抖店体验分、天猫服务指标、京东售后评价与客服系统。差评处理记录、体验分明细、服务诊断报告与整改台账构成日常文档，更新频率为日或周。对话日志与审计环节需要把客服对话与这些业务记录对应起来，核对目标对话、运行详情与字段含义。体验分变化直接影响搜索权重、活动报名与店铺转化，交接时若把检索结果或表单提交当成授权完成，会留下权限断点。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话身份依赖 chatId 核对目标对话与业务记录，不同入口的会话不能混算。需要运行详情时按官方契约设置 detail，检查 responseData 中的模块状态与完整结果。接口实际返回字段决定日志留存范围，未返回的业务数据不能推定已完整留存。测试模式与正式调用的身份字段可能不同，需分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，日志存在不表示合规审计已经完成。运营权限与交接管理要区分节点已有行为、实际可配置字段、人工核对动作与需另接系统实现的业务动作。

假设演练样本：某店铺运营交接一批差评处理记录，材料原文为「2025年3月1日至3月7日，客服系统会话 chatId 为 A1001 至 A1050，其中 A1007 对应订单 20250303-001 的差评处理，处理状态为已联系消费者补充凭证，整改台账未登记完成时间」。待判定的交接请求为「将 A1007 的对话日志与整改台账一并移交给质检专员，并确认该差评已闭环」。此样本中主体为店铺运营与质检专员，对象为 A1007 对话与整改台账，状态为已联系但未登记完成时间，有效范围为上述日期与 chatId 区间。

## 配置怎么定
下表围绕该样本列出与本功能、主任务相关的官方已说明设置或实施核对项。数值仅为本次假设试验起点，并说明比较对象。

| 配置项 | 假设起点 | 核对方式 |
| --- | --- | --- |
| appId 与 chatId 对应 | 使用样本中 A1007 所属 appId | 与材料原文的 chatId 区间比较，确认同一应用下唯一 |
| detail 取值 | 设为 true | 与 responseData 中模块状态和完整结果比较，确认运行详情可读 |
| responseChatItemId | 假设为 A1007-R1 | 与当前 chatId 下已有响应消息 ID 比较，确认唯一 |
| loadCustomFeedbacks | 设为 true | 与对话列表返回的 customFeedbacks 字段比较，确认反馈可读 |
| 交接授权状态 | 材料未载明 | 与整改台账完成时间字段比较，未登记即待核实 |
| 审计留存范围 | 材料未载明 | 与接口实际返回字段比较，未返回项记录为缺口 |

## 容易做错的三处
1. 把 chatId 区间内所有会话当成同一业务记录。输入为 A1001 至 A1050，比较对象为 A1007 对应订单，若未逐条核对 chatId 与订单号，会把无关会话混入交接材料。
2. 把已联系消费者补充凭证当成差评闭环。输入为处理状态字段，比较对象为整改台账完成时间，该字段未登记，判定应为待核实。
3. 把检索结果或表单提交当成授权执行。输入为对话日志查询结果，比较对象为质检专员的交接授权记录，检索与表单收集值不构成授权，缺少授权记录时业务动作不能执行。

## 怎么确认配好了
1. 输入样本材料原文与 A1007 的 chatId，比较对象为同一 appId 下该 chatId 的唯一性，观察接口返回的 chatId 与材料一致且无重复，才满足身份核对条件。
2. 输入 detail=true 的请求，比较对象为 responseData 中模块状态与完整结果，观察运行详情字段存在且与对话列表记录对应，才满足运行详情核对条件。
3. 输入待判定的交接请求与整改台账字段，比较对象为完成时间登记状态，观察台账完成时间仍为空，判定为未获支持，需保留证据缺口并等待补充登记。
