# 平台类目资质准入的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

平台类目资质准入发生在商品上架或店铺入驻之前，核心材料是营业执照、商标注册证、品牌授权链与行业许可证。这些材料来自平台招商页面、国家企业信用信息公示系统、商标局数据与许可证系统，更新不定期，每次入驻重新收集。招商运营、店铺入驻专员与品牌方渠道经理在交接时，需要确认某份材料当前处于收集、待补正、已提交还是已驳回状态。对话日志与审计记录的是这些沟通过程：谁在哪个会话里提交了哪份材料、哪条请求处于待审核、哪次补正已经完成。日志本身不改变材料的授权状态，它只留存操作轨迹。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话接口中，`chatId` 决定从 FastGPT 数据库取哪一段会话，`dataId` 指某个会话下的某一条对话。运营交接时，核对目标对话必须结合 `chatId` 与业务记录，不能把不同入口的会话混算。需要运行详情时按官方契约设置 `detail=true`，在 `responseData` 中查看模块状态与完整结果；`detail=false` 时只有最终回答，中间状态不返回。接口实际返回哪些字段以响应为准，未返回的业务数据不能推定已完整留存。测试模式与正式调用的身份字段可能不同，需要分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。

假设演练样本：某品牌方渠道经理向店铺入驻专员提交一份商标注册证扫描件，拟稿句为“该商标注册证已覆盖第35类，授权链完整，可提交类目准入”。供核对的材料原文为：“商标注册证第XXXX号，注册人：某食品有限公司；核定使用商品/服务项目：第30类 咖啡、茶；有效期至2029年某月某日。”另一条交接请求为：“请确认该品牌授权链中经销商层级是否已提供二级授权书。”材料中未出现第35类，也未出现二级授权书内容。

## 配置怎么定

| 设置或核对项 | 本页用途 | 与样本的关联 |
| --- | --- | --- |
| `chatId` 与 `dataId` | 定位某次入驻沟通的会话与单条对话 | 核对拟稿句所在对话是否属于该品牌方渠道经理的会话 |
| `detail=true` 与 `responseData` | 查看模块运行详情与完整结果 | 检查该轮对话是否返回了材料原文相关模块输出 |
| `source=api` | 区分 API 创建会话与页面会话 | 确认交接记录来自 API 调用，不混入页面会话 |
| `loadCustomFeedbacks` | 读取自定义反馈 | 核对专员是否对该轮回答留下反馈，反馈内容单独记录 |
| `updateHistory` 的 `customTitle` | 修改会话标题 | 为入驻交接会话命名，便于后续按标题检索 |
| `variables` 传入 `uid` | 标识调用方身份 | 假设试验起点：传入渠道经理 uid，用于区分调用来源；与正式调用身份分别核对 |

## 容易做错的三处

1. 把 `detail=false` 的返回当作完整运行记录。该模式下只有最终回答，`responseData` 不出现，模块状态与中间结果无法从该次响应中获得。检查时比较同一次请求在 `detail=true` 与 `detail=false` 下返回字段的差异，观察 `responseData` 是否存在。
2. 用 `chatId` 相同就认定业务记录一致。`chatId` 只标识会话，同一会话下不同 `dataId` 对应不同对话。核对拟稿句时，输入该 `chatId` 与目标 `dataId`，比较返回的 `obj`、`value` 与业务记录中的材料名称、提交时间，观察是否指向同一条对话。
3. 把检索结果或表单填写当作授权完成。检索返回的 `quoteList` 与 `score` 只表示召回内容与相似度，不表示材料已通过审核或授权已生效。核对时输入拟稿句中的“已覆盖第35类”，比较材料原文的核定使用项目，观察原文是否出现第35类；未出现时记录为未获支持，保留证据缺口。

## 怎么确认配好了

1. 输入样本中的材料原文与拟稿句，比较拟稿句“已覆盖第35类”与原文“第30类 咖啡、茶”。预期现象：原文未出现第35类，该句未获材料支持，记录为待核实。不声称已实测。
2. 输入交接请求“经销商层级是否已提供二级授权书”，比较材料原文中是否出现二级授权书内容。预期现象：原文未载明二级授权书，该请求对应的授权链完整性未获支持，保留缺口。
3. 输入同一 `chatId` 下两个不同 `dataId` 的查询请求，比较两次返回的 `value` 是否对应不同对话内容。预期现象：两次返回内容不同，可确认 `dataId` 区分单条对话；若返回内容相同，记录为待核实，不推断数据重复原因。
