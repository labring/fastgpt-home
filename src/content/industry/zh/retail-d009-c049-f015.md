# 批发市场档口交易的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样

批发市场档口交易依赖现场议价和托运，进货单、手写销售单、摊位租赁合同、货款收据构成日常文档主体。档口老板、采购商与托运方之间的交接频繁，材料多为纸质或拍照留存，字段完整度参差。检索环节需要把这些材料按库归集，使交接时的授权状态可以被准确引用，检索本身不改变任何授权状态。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联。检索输出为数组，长度可以为 0，未检索到内容时该输出链路仍然走通。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不承担权限或实体隔离功能。引用上限以 token 为单位，用于控制每次搜索引用的内容量。问题优化用于指代消除和问题扩展，会增加一次模型调用。

假设演练样本：某档口老板与采购商之间的摊位租赁合同复印件载明“出租方：甲档口；承租方：乙采购；租赁期：2024年3月1日至2025年2月28日；月租金：3000元；签署日期：2024年2月20日”。同一批材料中有一张手写销售单，载明“2024年4月10日，出货30箱，货款未结”。一条待判定的交接请求拟稿句为：“乙采购在2024年4月的摊位使用权限已随合同生效而延续，检索该合同即可确认。”该拟稿句把合同生效与摊位使用权限延续混为同一事实，合同载明的租赁期不表示2024年4月的操作权限状态，货款未结也不表示承租方失去摊位使用权。检索该合同只能返回合同原文，不能返回权限延续的结论。

## 配置怎么定

| 配置项 | 本页假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 档口租赁合同库、销售单库 | 两库使用相同向量模型方可共同关联，先核向量模型标识，排除不符合者 |
| 搜索模式 | 混合检索 | 合同编号、日期等精确字段与自然语言问法并存，比较语义与全文两路召回结果 |
| 引用上限 | 本次假设试验起点 2000 tokens | 合同与销售单长度差异大，用长短不同的实际资料比较内容是否完整，再调整 |
| 最低相关度 | 本次假设试验起点 0.4 | 先标注相关与无关样本，再调阈值，该值仅在语义检索或结果重排时生效 |
| 问题优化 | 开启 | 交接追问常出现指代，比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 按设置启用 | 重排须具备模型且按设置启用，重排得分可用于过滤 |

## 容易做错的三处

1. 把检索返回的合同原文当作权限判定结论。合同载明租赁期，检索只能返回该段原文，权限是否延续需另行核对授权材料，检索不执行授权。
2. 把最低相关度当作实体或权限过滤器。该值是过滤阈值，不排除无关业务或未授权记录，相似度设置不承担隔离功能。
3. 把待审核的交接请求当作已批准。待审核不证明缺少操作权限，也不证明已获授权，未载明的状态保持待核实。

## 怎么确认配好了

1. 输入上述假设合同原文与拟稿句，比较检索返回内容与合同原文是否一致，返回内容包含合同原文且不含权限延续结论时满足条件；返回内容出现权限延续表述时记录为异常。
2. 输入上述手写销售单原文，比较检索结果是否包含“货款未结”字段，包含该字段且不附带任何权限变更结论时满足条件；未返回该字段时记录为待核实。
3. 用明确的纸面输入空数组核对下游设计，比较下游节点是否按空引用继续执行，下游链路走通且不产生虚构引用时满足条件；出现系统报错或自动业务动作时记录为未获支持。
