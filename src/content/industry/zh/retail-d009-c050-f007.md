# 投诉举报与监管回复的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
投诉举报与监管回复面向平台或监管机关，需要正式证据和整改文字，与售后维修补寄的日常工单处理存在明显差别。主要数据来自12315平台、平台投诉中心、客服聊天与订单系统，日常文档包括投诉工单、监管询问函、订单证据与整改报告。数据更新不定期、每案一次，因此对话日志与审计的重点落在个案可追溯，而不落在批量同步。

典型从业主体是客服主管、法务合规与店铺负责人。出错后果涉及行政调查、平台处罚与品牌舆情，运营权限与交接管理需要区分谁可以查看对话、谁可以提交材料、谁可以代表店铺对外回复。对话日志本身只是运行记录，业务对账、留存与合规要求由完整业务方案另行落实。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话接口按chatId定位会话，按dataId定位对话。交接时应核对目标对话与业务记录是否指向同一chatId，不同入口创建的会话不能混算。需要运行详情时，按官方契约设置detail并检查responseData；detail为true时返回模块状态与完整结果，非stream模式结果保存在responseData中。接口实际返回哪些字段，日志就记录哪些字段，未返回的业务数据不能推定已完整留存。

检索与相似度不承担权限或实体隔离。相似度是检索结果排序依据，不能当作权限过滤或业务归属判断。authProxy用于代理团队成员身份，需要团队所有者开启，代理身份仍需具备目标应用和会话权限。表单只收集值，业务核验、审批、数据库写入与外部同步需要各自的下游实现。

假设演练样本：某店铺客服主管在2025年3月10日离职交接，交接材料原文为：“投诉工单TS-0310-07，对象为店铺A的订单退款争议，当前状态为待补充证据；监管询问函尚未收到正式编号；客服聊天记录由客服账号创建，chatId为api-0310-a。”待判定交接请求句为：“将chatId为api-0310-a的全部对话日志移交给接任人，并视为已完成该工单的证据准备。”此句中的“视为已完成证据准备”缺少授权依据，工单状态为待补充证据，材料未载明证据已齐备。

## 配置怎么定
下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值仅为本次假设试验起点，用于与目标值比较，不代表官方默认值。

| 配置项 | 本次假设试验起点 | 核对方式与依据 |
| --- | --- | --- |
| appId | 样本店铺A的应用ID | 与工单记录中的应用标识比对，确认同一应用 |
| chatId | api-0310-a | 与客服聊天记录中的chatId比对，确认同一会话 |
| detail | true | 需要运行详情时按官方契约设置，检查responseData |
| stream | false | 非stream模式结果保存在responseData中，便于逐条核对 |
| authProxy | 由团队所有者按需开启 | 代理身份仍需具备目标应用和会话权限 |
| source | api | 获取通过API创建的会话，与页面会话区分 |

## 容易做错的三处
1. 把chatId相同当作整条工单证据链完整。样本中chatId为api-0310-a只说明会话归属，工单状态为待补充证据，材料未载明证据已齐备，对话日志存在不等于证据准备完成。
2. 把相似度或检索结果当作权限判断。检索返回相关片段，不判断该片段是否属于店铺A、是否允许接任人查看。权限需要按authProxy与目标应用会话权限另行核对。
3. 把待审核或待补充状态写成已完成。样本中工单为待补充证据，监管询问函未收到正式编号，两项都属于未获支持，不能写成已提交或已回复。

## 怎么确认配好了
1. 输入样本中的chatId api-0310-a与工单TS-0310-07，比较两者是否指向同一会话与同一订单争议。若chatId一致而工单状态仍为待补充证据，则日志可追溯但证据准备未完成，此现象满足核对条件。
2. 输入待判定句“将chatId为api-0310-a的全部对话日志移交给接任人，并视为已完成该工单的证据准备”，比较“视为已完成证据准备”与材料中“待补充证据”的记载。若材料未载明证据齐备或授权完成，则该句超出授权边界，此现象满足核对条件。
3. 输入detail为true、stream为false的请求，比较responseData中实际返回的字段与交接清单所列字段。若清单列有材料未载明或接口未返回的字段，则该项标记为未获支持，此现象满足核对条件。
