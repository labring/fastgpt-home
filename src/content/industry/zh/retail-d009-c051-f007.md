# 抖音小店货架运营的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

抖音小店货架运营围绕商品卡与店铺体验分展开，主要数据来自抖店工作台、抖音电商学习中心、精选联盟数据与物流接口，日常文档包括商品资质页、体验分明细、发货违规申诉与店铺公告，数据更新为日更与每单。这些材料在运营权限与交接管理中直接影响对话日志与审计：资质页与体验分明细决定谁在什么授权状态下查看或提交，发货违规申诉与店铺公告决定交接时哪些请求处于待审、已提交或已关闭。对话日志与审计在本页只解决一件事——运营交接时哪些材料、操作、请求处于什么授权状态，检索或表单不能当成授权执行。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话身份需要结合 chatId 核对目标对话与业务记录，不同入口的会话不能混算。需要运行详情时按官方契约设置 detail 并检查 responseData。核对日志与接口实际返回字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，输入、历史与返回内容分别核对。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。

假设演练样本：供核对的材料原文为「本店商品资质页于 2025 年 3 月 1 日提交更新，状态为待审核；同月 5 日店铺公告写明该批次资质补充由运营甲负责跟进，尚未收到审核结论。」一条待判定的交接请求为「请将运营甲名下该批次资质的审核结论与操作权限一并交接给运营乙。」此请求中，审核结论在材料里未载明，操作权限的授予边界也未载明，因此该请求的授权状态为待核实，不能视为已批准或已执行。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 对话接口鉴权方式 | 请求体传入 body.appId | 与 Authorization 头方式比较，核对 appId 取值来源 |
| 运行详情开关 | detail 设为 true | 与 detail 为 false 的返回比较，检查 responseData 是否存在 |
| 会话来源筛选 | source 设为 api | 与页面会话比较，确认返回列表不含页面来源记录 |
| 会话标识核对 | chatId 逐条比对 | 与业务记录中的 chatId 比较，排除不一致者 |
| 分页读取 | offset 为 0，pageSize 为 20 | 与 total 比较，判断是否还有未读记录 |
| 反馈读取 | loadCustomFeedbacks 设为 true | 与不传该参数比较，检查 customFeedbacks 字段 |

这些取值是本次假设试验起点，不是官方默认值，比较方法如上。

## 容易做错的三处

1. 把检索结果当成授权凭证。输入为上述待判定请求，比较对象为材料原文，可观察结果是请求中的审核结论在原文中未载明，因此该请求仍为待核实。
2. 把不同来源会话混算。输入为 source 为 api 的会话列表，比较对象为页面来源会话，可观察结果是两者 chatId 不同，不能合并统计。
3. 把 detail 为 false 的返回当作完整运行详情。输入为 detail 为 false 的响应，比较对象为 detail 为 true 的 responseData，可观察结果是前者不含中间模块字段，无法据此判断留存是否完整。

## 怎么确认配好了

1. 输入上述材料原文与待判定请求，比较请求所述审核结论与原文是否同主体、同期间、同字段，只有原文明确载明该结论时才满足条件，否则记录为未获支持。
2. 输入 source 为 api 的会话列表请求，比较返回的 chatId 与业务记录中的 chatId，只有逐条一致时才满足条件，不一致者排除并记录实际观察。
3. 输入 detail 为 true 的对话请求，比较 responseData 中出现的字段与日志核对所需字段，只有所需字段实际出现时才满足条件，缺失字段记录为缺口，不推定已留存。
