# 拼多多低价活动店铺运营的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

拼多多低价活动店铺运营围绕低价资源位、活动库存与退款率波动展开，日常材料包括活动报名表、商品成本测算表、售后退款单与平台站内信。材料按日或按场更新。运营交接时需要把某场活动的报名、成本、退款与站内信记录对应到具体会话，对话日志与审计在此承担核对入口：确认某条对话属于哪场活动、哪个会话、哪个对话 ID，以及该对话的运行详情是否被接口返回。材料分散在多个来源，核对时以 chatId、dataId 为线索把对话记录与业务材料对齐，不把不同入口的会话合并计算。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话接口通过 chatId 关联会话，dataId 标识某条对话。不传 chatId 时系统不使用数据库上下文，完全由 messages 构建；传非空 chatId 时系统取数据库会话并以 messages 最后一条为用户问题。responseChatItemId 需在当前 chatId 下唯一。detail 决定是否返回中间值，非流式结果保存在 responseData，流式通过 event 区分。会话管理接口按 source=api 只取 API 创建的会话，清空应用会话只清空 API Key 创建的会话，不影响在线使用与分享链接来源。检索结果中的 similarity 是相关度数值，不承担权限或实体隔离；日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某拼多多活动运营在交接一场低价活动时，提供材料原文三句——“活动报名表第 12 行：活动场次 A，商品编码 P-100，报名价 9.9 元，报名状态已提交”；“商品成本测算表第 5 行：商品编码 P-100，单件成本 8.6 元，测算日期 3 月 4 日”；“售后退款单第 3 行：商品编码 P-100，退款金额 9.9 元，退款日期 3 月 6 日”。待判定拟稿句：“该场活动 P-100 的对话日志已完整留存并可用于合规审计。”该句涉及主体、对象、状态与有效范围，需逐项核对。

## 配置怎么定

| 配置或核对项 | 官方已说明内容 | 本样本中的核对方式 |
| --- | --- | --- |
| chatId | 非空字符串时使用数据库会话，长度小于 250 | 核对交接材料中的 chatId 是否与本场活动会话一致 |
| dataId | 指一个会话下某一条对话的 ID | 核对退款单与对话记录是否指向同一 dataId |
| detail | 是否返回中间值，非流式结果在 responseData | 需要运行详情时设置 detail 并检查 responseData |
| responseChatItemId | 传入后作为响应消息 ID 存入数据库，当前 chatId 下需唯一 | 核对拟稿句涉及的响应消息 ID 是否唯一 |
| source=api | 获取通过 API 创建的会话，不获取页面会话 | 核对会话来源是否为 API，避免混入页面会话 |
| 检索 similarity | 相关度数值 | 记录数值，不将其当作权限或实体过滤条件 |

本样本假设试验起点：把 detail 设为 true，理由是需要 responseData 中的运行详情；与 detail 设为 false 时仅返回 choices 的结果比较。该起点为本次假设，不是官方默认值。

## 容易做错的三处

1. 把检索相关度当作权限过滤。输入：某次检索返回 similarity 0.89 的引用。比较：该数值与权限字段。观察：数值只反映相关度，不表示该记录已获授权。
2. 把日志存在当作合规审计完成。输入：拟稿句声称对话日志已完整留存并可用于合规审计。比较：材料中是否有留存范围、审计主体与合规结论。观察：材料只有报名、成本与退款三行，未载明留存范围与审计结论，该句未获支持。
3. 把待审核状态当作已获授权。输入：报名状态“已提交”。比较：是否存在审核通过记录或授权边界说明。观察：材料未载明审核结果，待审核不证明缺少操作权限，也不证明已获授权。

## 怎么确认配好了

1. 核对 chatId 与 dataId。输入：假设样本中活动场次 A 的 chatId 与退款单第 3 行对应的 dataId。比较：两者是否指向同一会话与同一对话。观察：若一致，可确认对话记录与退款材料对应；若不一致，记录缺口，不推定已完整留存。
2. 核对 detail 与 responseData。输入：假设样本中一次 detail=true、stream=false 的请求。比较：responseData 是否包含模块运行详情。观察：若返回 responseData 且含 moduleName、runningTime 等字段，可取得运行详情；若未返回，记录为未取得，不推断系统报错原因。
3. 核对 source=api 的会话范围。输入：假设样本中一次 source=api 的会话列表请求。比较：返回列表是否只含 API 创建的会话。观察：若列表含页面来源会话，则该次核对不满足条件；若只含 API 会话，记录实际观察，不声称全部召回或无关查询必为空。
