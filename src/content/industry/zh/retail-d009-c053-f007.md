# 渠道应收账款催收的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
渠道应收账款催收发生在赊销之后，围绕授信与现金回收展开，数据来自财务系统、银行回单、经销商订单与销售合同，日常文档包括应收账龄表、催款函、授信协议、发货冻结通知。资料给出的更新频率为周、月，本页不据此推出批量同步、全量同步、实时或交易触发机制。对对话日志与审计而言，真正影响工作的是：催收对话往往跨销售内勤、品牌财务与经销商老板多方交接，会话标识与业务记录的对应关系必须逐条核对；日志留存与对账、合规审计是两件事，日志存在不等于完成合规审计；接口返回的字段范围决定哪些业务数据可被追溯，未返回的内容不能推定已完整留存。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话接口以 chatId 标识一个应用下的会话，以 dataId 标识会话下的某一条对话。chatId 为非空字符串时，系统从数据库取会话，仅用 messages 数组最后一个内容作为用户问题，其余 message 被忽略；chatId 不传入时不使用上下文功能。responseChatItemId 传入后作为本次响应消息 ID 存入数据库，并要求在当前 chatId 下唯一。detail 决定是否返回中间值，非 stream 模式下结果保存在 responseData，stream 模式下通过 event 区分。会话列表接口的 source=api 只获取通过 API 创建的会话，清空应用会话同样只清空 API Key 创建的会话，不涉及在线使用与分享链接来源。authProxy 代理团队成员身份需团队所有者开启，代理身份仍需具备目标应用和会话权限。

假设演练样本：某品牌财务在 2025 年 3 月对一家经销商做催收交接，供核对的材料原文为三句——“授信协议载明该经销商信用额度为 50 万元，账期 60 天，协议签署日期 2025 年 1 月 10 日。”“截至 2025 年 3 月 5 日应收账龄表显示该经销商逾期金额 12 万元，逾期 15 天。”“发货冻结通知为草稿状态，尚未发出。”待判定的交接请求句为：“该经销商已超授信，发货冻结已完成，可停止催收。”此样本中主体、对象、日期与金额范围明确，冻结通知处于草稿状态，属未执行。

## 配置怎么定
配置围绕本页样本的日志与交接核对展开，只列官方已说明的设置或实施核对项。

| 核对项 | 设置或动作 | 与样本的关联 |
| --- | --- | --- |
| chatId | 交接双方使用同一 chatId 取会话 | 确认双方查看同一催收会话 |
| dataId | 按 dataId 取单条对话运行详情 | 定位 3 月 5 日那条交接对话 |
| detail | 需要运行详情时设为 true | 检查 responseData 内节点响应 |
| source | 会话列表查询传 source=api | 只取 API 创建的会话 |
| authProxy | 由团队所有者开启后代理身份 | 代理身份仍需目标应用与会话权限 |
| 数值起点 | 本次假设试验以账龄表逾期 12 万元为核对起点 | 与授信协议 50 万元额度比较 |

该 12 万元为本次假设试验起点，选它是因为样本账龄表原文如此，比较对象是授信协议的 50 万元额度，二者只做同主体同期间的字段对照，不构成任何官方默认值。

## 容易做错的三处
1. 把草稿当执行。样本中发货冻结通知为草稿状态，交接请求句称“发货冻结已完成”。输入是通知原文与请求句，比较对象是通知的状态字段，出现“草稿”与“已完成”同字段互斥取值才构成矛盾，此处应记录为未获支持。
2. 把检索或表单当授权。检索相似度是排序依据，不承担权限或实体隔离；表单只收集值。输入为交接请求句，比较对象是授权状态字段，未载明授权时记录证据缺口。
3. 把日志存在当合规审计完成。输入为会话与对话记录，比较对象是对账、留存与合规要求，这些由完整业务方案另行落实，接口返回字段之外的内容保持未知。

## 怎么确认配好了
1. 取样本中 2025 年 3 月 5 日那条对话，输入 chatId 与 dataId，比较运行详情内节点响应字段与交接请求句所述事实，只有响应字段明确显示冻结已发出且授权已载明，请求句才获支持；当前样本显示草稿，预期结果为未获支持。
2. 用样本授信协议原文与账龄表原文，输入 50 万元额度与 12 万元逾期金额，比较同主体同期间同一字段，只有出现同字段互斥取值才记为矛盾，否则记为待核实。
3. 纸面输入空结果列表 []，核对下游设计对空值的处理，观察是否将空结果误判为已授权或已执行；不声称虚构规则检索一定返回 []。跨不同向量模型的库不可共同关联，只核标识并排除不符者，记录实际观察，不编造漏召回或冗余结果。
