# 渠道窜货稽查的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样

渠道窜货稽查围绕区域与价格秩序展开，主要资料包括窜货投诉单、防伪码记录、处罚通知与调查照片。这些资料来自防伪码系统、电商平台价格、经销商发货记录和市场巡检，更新频率为周或不定期。资料形态差异明显：投诉单含投诉主体、被投诉对象、涉及区域与时间；防伪码记录含码段、查询时间与查询位置；处罚通知含处罚对象、依据条款与执行状态；调查照片含拍摄时间、地点与画面内容。运营交接时，这些材料常处于不同状态：已提交、待审核、已签署、已生效。检索环节只负责按问题召回引用内容，不判断材料是否获得授权、是否已执行。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，需先核对向量模型标识并排除不符合者，不执行跨模型检索来比较漏召回。搜索模式按测试问题比较语义检索、全文检索与混合检索，不预设一种模式适合全部资料。引用上限以 token 为单位，用长短不同的实际资料测试内容是否完整，再调整上限。最低相关度仅在语义检索或使用结果重排时生效，先标注相关与无关样本再调阈值。问题优化用于指代消除和问题扩展，比较原问题与优化后问题，核对主体是否被改错。语义召回和相关度不负责权限或实体隔离，检索库同向量模型要求不能扩展为工商网站或其他外部系统也要同模型。RRF 是混合结果融合过程。空结果以数组形式输出，长度可以为 0。

假设演练样本：供核对的材料原文为“投诉单 CX-2024-0317 载明：投诉主体为华东区经销商甲，被投诉对象为华南区经销商乙，涉及区域为华南区，投诉日期为 2024 年 3 月 17 日，状态为待审核。处罚通知 CF-2024-0402 载明：处罚对象为经销商乙，依据条款为区域窜货第 3 条，执行状态为未签署。”待判定的拟稿句为：“经销商乙的处罚已执行完毕，可解除其区域授权。”该样本用于核对检索引用内容能否支持该判定。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联的知识库 | 关联一个含投诉单、处罚通知的知识库 | 核对向量模型标识一致；跨模型库不可共同关联 |
| 搜索模式 | 先以语义检索测试投诉单类自然语言问题 | 与全文检索、混合检索结果比较，观察编号类问题命中差异 |
| 引用上限 | 设为足以容纳一份投诉单全文的 token 量 | 以长短不同的投诉单测试引用是否完整，再调整 |
| 最低相关度 | 先标注相关与无关样本，再设一个 0-1 之间的阈值 | 仅在语义检索或结果重排时生效，比较过滤前后结果 |
| 问题优化 | 对短问题与多轮追问开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 具备重排模型且按设置启用时使用 | 比较重排前后排序，观察相关度得分变化 |

## 容易做错的三处

1. 把检索命中当作授权确认。输入为待审核的投诉单与未签署的处罚通知，若直接依据检索到的处罚通知拟稿“处罚已执行”，比较处罚通知的执行状态字段“未签署”与拟稿句“已执行完毕”，可观察到两者不一致。检索只返回引用内容，不判断执行状态。
2. 把跨向量模型库强行共同关联。输入为两个向量模型标识不同的知识库，若将其共同关联，比较两库的向量模型标识，可观察到标识不一致。正确做法是核对标识并排除不符合者，不执行跨模型检索来比较漏召回。
3. 把最低相关度当作权限过滤。输入为包含无关业务记录的知识库，若将最低相关度设为较高值并期望排除无关记录，比较过滤前后结果，可观察到相关度阈值不按业务实体或权限过滤。语义召回和相关度不负责权限或实体隔离。

## 怎么确认配好了

1. 以假设样本中的投诉单原文与拟稿句为输入，比较拟稿句“处罚已执行完毕”与处罚通知执行状态字段“未签署”，观察检索引用内容是否包含该字段。若引用内容仅含待审核投诉单，则拟稿句未获支持，需记录证据缺口。
2. 以两个向量模型标识不同的知识库为输入，比较其向量模型标识，观察是否一致。若标识不一致，则排除共同关联，记录实际观察，不推断运行结果。
3. 以一份投诉单全文为输入，比较引用上限 token 量与投诉单实际长度，观察引用内容是否完整。若引用内容被截断，则调整引用上限后重新比较。空结果以数组形式输出，长度可以为 0，可用明确的纸面输入 [] 核对下游设计。
