# 渠道窜货稽查的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样
渠道窜货稽查围绕区域与价格秩序处理防伪码记录、电商平台价格、经销商发货记录与市场巡检信息，日常文档为窜货投诉单、防伪码记录、处罚通知与调查照片。数据按周与不定期更新。本页只处理运营权限与交接管理中的部署与升级环节，判断交接时哪些材料、操作与请求处于何种授权状态。检索结果与表单填写只呈现信息，不构成授权、审批或处罚执行。

## 这些特征在「部署与升级」这一环带来什么约束
版本升级改变数据索引与任务状态，交接期间须核对材料所处阶段。假设演练样本：某品牌渠道管控团队在升级到 V4.17.2 后交接一批窜货材料。供核对原文为三句：「投诉单编号 A-07，对象为某经销商，状态为待核实，授权范围仅限本区域价格比对。」「防伪码记录显示该码首次查询时间为 2026-10-01，查询地点为外省。」「处罚通知为草稿，未签发，未送达。」待判定的交接请求句为：「该经销商窜货事实已确认，可执行处罚并同步电商平台下架。」核对时比较：原文状态为待核实与草稿未签发，请求句称已确认并可执行处罚；材料授权范围仅限价格比对，请求句涉及处罚执行与外部同步。两者在主体、对象、状态与授权范围上不一致，请求句未获原文支持。

## 配置怎么定
配置围绕本页文档与主任务，列出官方已说明的设置或实施核对项。

| 项目 | 假设起点与理由 | 比较与核对方式 |
| --- | --- | --- |
| 部署版本 | 目标 v4.17.2，依据升级说明镜像 tag | 核对 fastgpt-app 与 fastgpt-pro 镜像 tag 是否为 v4.17.2 |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000`，为根地址 | 核对未追加 `/v1`，未填单模型地址 |
| AIPROXY_API_TOKEN | 假设填非空管理员 Token | 核对与服务端一致且非空 |
| 升级脚本 | 假设先执行 `20261008_migrate_chunk_training` | 核对集群旧实例已停止、租约过期后再执行 |
| 升级脚本 | 假设后执行 `20261009_migrate_dataset_rebuild_status` | 核对依赖前项完成 |
| 升级后验证 | 假设用相同样本复核导入与检索 | 核对结果与升级前样本一致，不承诺零中断 |

## 容易做错的三处
1. 把待核实状态当作已确认。样本原文写「状态为待核实」，若交接记录写成「已确认窜货」，输入为原文状态与记录状态，比较同一字段取值，两者互斥即矛盾。
2. 把草稿处罚通知当作已执行。原文写「草稿，未签发，未送达」，若记录写「已处罚并同步下架」，比较签发与送达字段，未载明即未获支持。
3. 把检索或表单当作授权。样本授权范围仅限价格比对，若据此执行处罚或对外同步，输入为授权范围与请求动作，比较两者边界，超出范围即越权。

## 怎么确认配好了
1. 输入样本原文三句与待判定请求句，比较主体、对象、状态与授权范围，只有请求句各项均被原文覆盖才满足条件；样本请求句在状态与授权范围上未覆盖，判为未获支持。
2. 输入升级脚本执行顺序与前置条件，比较 `20261008` 与 `20261009` 的依赖关系，只有前项完成且旧实例停止才满足后项执行条件。
3. 输入升级后相同样本的导入与检索结果，比较升级前后是否一致，只有一致才满足验证条件；不一致时记录差异，不推断原因。空结果可用明确的纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回 `[]`。
