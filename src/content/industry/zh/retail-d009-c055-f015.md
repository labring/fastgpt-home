# 特许加盟备案管理的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样

特许加盟备案管理处理法律披露与商务部门系统，不处理具体铺位工程。日常文档集中在特许经营合同、操作手册、备案材料与信息披露文件四类。这些材料的主体、期间和状态字段直接决定运营交接时哪些内容可被引用。特许人总部、加盟法务与商务主管对接人共用同一批文档，检索结果若混入其他主体的合同或未生效版本，交接判断就会偏离。资料更新频率为不定期与年，本页不据此推出批量同步或实时机制。知识库由库、集合和数据三层组成，最小搜索单位是库，集合仅作分类管理，与搜索效果无关。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的库，跨不同向量模型的库不可共同关联。语义检索依赖向量距离，全文检索适合编号与专有名词，混合检索通过 RRF 融合两路结果，重排须具备模型并按设置启用。最低相关度仅在语义检索或使用结果重排时生效，引用上限以 token 为单位。检索是召回行为，不承担授权判断，相似度分数不构成主体、实体或权限过滤。问题优化用于指代消除和问题扩展，会增加一次模型调用。

假设演练样本：某特许人总部法务在交接前核对一份材料。原文为：“甲方某某餐饮管理有限公司与乙方某某加盟商于二〇二三年五月十日签署《特许经营合同》，合同状态为已生效，备案状态为已提交商务主管部门。”另有一条待判定拟稿句：“该加盟合同已完成备案。”核对该句时须比对主体、期间与备案字段，原文仅载明备案已提交，未载明备案完成，该拟稿句属未获支持。

## 配置怎么定

| 配置项 | 本页取值或核对方式 | 与样本的关系 |
| --- | --- | --- |
| 关联的知识库 | 仅关联使用相同向量模型的一个或多个库 | 先核各库向量模型标识，排除不一致者 |
| 搜索模式 | 本次假设试验起点为混合检索，因样本含主体名称与状态词 | 与单独语义检索结果比较，观察编号类词命中 |
| 引用上限 | 本次假设试验起点为 2000 token，因样本含合同主体与状态两句 | 与 1000 token 结果比较，看状态句是否被截断 |
| 最低相关度 | 本次假设试验起点为 0.4，先标注相关与无关样本再调 | 仅在语义检索或重排时生效，观察无关片段是否减少 |
| 问题优化 | 本次假设试验起点为开启，因拟稿句含指代 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 本次假设试验起点为启用，须具备重排模型 | 与未重排结果比较，观察相关句是否前移 |

## 容易做错的三处

1. 把检索命中当作授权结论。输入为拟稿句“该加盟合同已完成备案”，比较对象为原文备案状态字段“已提交”，可观察结果为拟稿句超出原文范围。若直接采信，交接判断会缺少依据。
2. 把不同向量模型的库共同关联。输入为两个库的向量模型标识，比较二者是否一致，可观察结果为标识不一致时不可共同关联。跨模型关联不产生可比较的召回结果。
3. 把 RRF 当作可开启开关。输入为搜索模式设置与结果列表，比较融合前后排序，可观察结果为混合检索下多路命中内容排位变化。RRF 是融合过程，不存在独立开关。

## 怎么确认配好了

1. 输入上述假设原文与拟稿句，比较拟稿句的备案表述与原文“已提交”字段，可观察结果为拟稿句被标注为未获支持，原文未载明备案完成。
2. 输入两个库的向量模型标识，比较二者是否相同，可观察结果为标识不同时排除该库，不执行跨模型检索比较漏召回。
3. 输入一条纸面空结果数组，比较下游节点是否仍走通，可观察结果为引用内容长度为 0 时输出链路继续执行。该核对不声称虚构规则检索一定返回空数组。

以上为纸面核对设计，未实际执行，不构成测试、部署或审批结论。
