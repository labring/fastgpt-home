# 生产企业免抵退税的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

生产企业免抵退税把内销抵减与出口退税合并计算，月度申报要归集自产出口、处理离岸价差异，出错会带来税额计算错误、退税调减或申报更正。数据来源包括电子税务局、ERP销售、海关电子信息和财务账，日常文档是免抵退税申报明细表、出口合同、销售明细账和出口报关单。这些特征落到对话日志与审计上，意味着日志要能对应到具体会话与具体对话，身份字段与业务记录要按 chatId 和 dataId 分别核对，不同入口的会话不混算。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话接口以 APIKey 鉴权，推荐在请求体传 body.appId；appId 优先级为 body.appId、`<apiKey>-<appId>`、apikey 关联的 appId。authProxy 代理团队成员身份需团队所有者开启，代理身份仍要具备目标应用和会话权限。chatId 非空时从数据库取会话，messages 数组最后一个内容作为用户问题，其余被忽略；responseChatItemId 在当前 chatId 下需唯一。需要中间值时按契约设置 detail，非 stream 结果保存在 responseData。会话列表可用 source=api 只取 API 创建的会话，清空应用会话仅清空 API Key 创建的会话。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某出口生产企业税务会计在 2025 年 7 月申报期交接，材料原文为“免抵退税申报明细表（2025年6月所属期）第 3 行：出口销售额 1200000 元，不得免征和抵扣税额 48000 元”，以及“出口合同 HT-2025-06 约定 FOB 价 1200000 元，报关单号 202506180001”。拟稿句为“本次会话已确认该笔出口业务的免抵退税额，可直接用于申报”。该拟稿句把对话记录当作业务确认，待判定其是否获得授权支持。

## 配置怎么定

| 配置项 | 本页用途 | 核对方式 |
| --- | --- | --- |
| body.appId | 指定目标应用 | 与目标应用 ID 逐字比对 |
| chatId | 定位本次交接会话 | 确认非空且与业务记录对应 |
| responseChatItemId | 标记本次响应消息 | 确认在当前 chatId 下唯一 |
| detail | 取得中间运行值 | 按契约检查 responseData 字段 |
| source=api | 筛选 API 创建的会话 | 与会话列表返回来源比对 |
| authProxy | 代理团队成员身份 | 确认已开启且具备会话权限 |

本次假设试验起点：以 detail=true、stream=false 发起一次请求，理由是便于逐字段核对 responseData，与 stream=true 的 event 分流结果比较。

## 容易做错的三处

1. 将 chatId 非空时被忽略的 messages 内容当作本轮问题。检查输入 messages 数组与返回 query 字段，观察实际采用哪一个。
2. 将 responseData 中未返回的业务字段推定已完整留存。检查返回对象实际含有的字段名，缺失字段记录为未获支持。
3. 将 similarity 或 score 当作权限或实体过滤。检查返回 quoteList 的 dataset_id 与目标范围，确认相似度不承担授权判断。

## 怎么确认配好了

1. 输入样本原文与拟稿句，比较拟稿句“已确认免抵退税额”与材料中仅有的销售额、不得免征和抵扣税额字段，观察是否存在同主体、同期间、同字段的确认依据；未见确认字段时记录为未获支持。
2. 输入 chatId 与 responseChatItemId，比较同一 chatId 下是否重复，观察返回是否接受该响应 ID；重复时记录为待核实，不推定自动去重。
3. 输入 source=api 的会话列表请求，比较返回 list 的 chatId 与目标交接会话，观察目标会话是否在 API 来源内；不在时记录为入口不一致，不据此判定权限缺失。
