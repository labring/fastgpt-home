# 生鲜临期折价处理的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
临期折价处理管理的是货架库存生命周期，与称重分拣逐件过秤的作业方式不同。门店巡检、ERP库存与质检记录通常按日或按班次更新，临期清单、折价审批、报损单、促销价签构成交接时的主要材料。识别临期批次、审批折价、隔离不可售商品消耗较多人力。这些材料进入对话系统后，日志记录的是会话与节点运行数据，业务授权状态仍需另行核对。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话日志按 chatId 区分会话，按 dataId 区分单条对话。运行详情通过 detail 参数获取，非流式结果保存在 responseData，流式结果按 event 区分。日志中出现的检索结果、表单字段与节点状态属于运行记录，不构成对折价审批、报损或商品隔离的授权。会话清空接口仅清空通过 API Key 创建的会话，不会清空在线使用、分享链接等其他来源的会话。

假设演练样本：某生鲜门店店长在 2025 年 3 月 10 日班次提交一份临期清单，原文为“对象：冷藏酸奶批次 A，到期日 2025-03-12，数量 24 盒，建议折价七折，报损单尚未开具，促销价签未打印”。交接请求拟稿句为“该批次已完成折价审批并已隔离不可售商品”。核对时需比较拟稿句与清单原文：原文仅载明建议折价，未载明审批完成，也未载明隔离动作，拟稿句的完成状态在材料中未获支持。

## 配置怎么定
下表围绕上述样本列出与本功能、本主任务相关的核对项。数值仅为本次假设试验起点，用于与样本原文比较。

| 配置或核对项 | 假设起点 | 核对方法与理由 |
| --- | --- | --- |
| 会话标识 chatId | 样本会话 ID 假设为 store0310 | 与临期清单班次日期对应，避免不同入口会话混算 |
| 对话标识 dataId | 样本对话 ID 假设为 rec001 | 定位单条交接记录，与清单原文逐条比对 |
| 运行详情 detail | 设为 true | 非流式时检查 responseData 中模块字段 |
| 响应消息标识 responseChatItemId | 假设为 resp0310a | 同一 chatId 下需唯一，便于回查 |
| 身份代理 authProxy | 未开启 | 开启需团队所有者设置，且代理身份仍需目标应用与会话权限 |
| 知识库引用范围 | 按文档单位核对 | 引用上限使用文档记载单位，不按条目数推定 |

## 容易做错的三处
1. 把日志中的检索结果当成折价审批依据。检索相似度是排序值，不承担权限或实体隔离功能，日志存在不等于审批完成。
2. 把交互节点返回的表单字段当成业务执行结果。表单收集值，审批、报损与隔离需下游实现，提交表单不表示已执行。
3. 把清空会话接口理解为清空全部来源记录。该接口仅清空 API Key 创建的会话，其他来源会话不在范围内。

## 怎么确认配好了
1. 输入样本原文与拟稿句，比较“建议折价”与“已完成折价审批”是否同主体、同期间、同字段。原文未载明审批完成，拟稿句该状态属未获支持，需记录证据缺口。
2. 输入样本原文与报损单字段，比较原文“报损单尚未开具”与拟稿句所称隔离动作。两者均无对应材料时，判定为待核实，不得判定为否定或冲突。
3. 输入样本 chatId 与 dataId，按 detail=true 获取运行详情，观察 responseData 中是否出现与样本对应的模块记录。未返回的业务字段保持缺失，不推定已完整留存。
