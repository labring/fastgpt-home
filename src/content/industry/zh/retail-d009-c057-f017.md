# 生鲜临期折价处理的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

在生鲜临期折价处理的运营权限与交接管理中，本页说明FastGPT的部署与升级如何衔接资料。临期材料恢复保留批次、货架时点与折价审批，不因应用恢复推定仍可售。所用场景为自拟文字测试。

## 这些特征在「部署与升级」这一环带来什么约束

假设临期清单标一批商品待复查，折价申请未批，促销价签仍为设计稿。升级验收应检查这些纸面状态和记录时点是否完整恢复，不能把价签存在当成折价已授权或商品仍可售。旧货架时点不能回答当前保质状态，本题也没有真实日期、售价、库存或检测结论。可恢复的文档与门店实际处理分别核，资料缺项不由应用正常启动补齐。

## 配置怎么定

| 临期升级样本 | 纸面状态 | 恢复检查 |
| --- | --- | --- |
| 批次 | 待复查清单 | 保留记录时点 |
| 折价 | 申请未批 | 不补授权 |
| 价签 | 设计稿 | 不称已促销 |
| 报损 | 原文与检索 | 核备份是否覆盖 |
| 回退 | 拟回原版本 | 需实测恢复内容 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `部署版本` | 先核当前及目标版本说明。 |
| `AIPROXY_API_ENDPOINT` | 环境变量采用服务根地址。 |
| `AIPROXY_API_TOKEN` | 两端Token需一致且非空。 |
| `依赖与备份核对` | 备份生成后仍需实测恢复内容。 |
| `升级后验证` | 复用同一组资料验证导入及调用。 |

## 容易做错的三处

- 恢复后价签稿被答成已执行促销时，对文档用途、审批记录及实际执行证据，不用文件生成时间替代批准时间。

- 旧批次临期清单被当成当前货架状态时，对批次及记录时点，缺当前复查不称仍可售。

- 只恢复检索索引而报损原文缺失时，核备份范围、原文与引用是否一致，不以查询有命中宣称全资料恢复。

## 怎么确认配好了

升级前按部署版本留存依赖、配置和样本文档身份，实际测试备份恢复；源存储与检索后端分别核。变更后使用同一问题问折价授权、批次时点及缺项，按真实账号查附件权限。若切回原版本也应检验数据可用内容，不能仅有回退计划就承诺可恢复。真实货架复查和价格发布仍按业务授权另行执行。
