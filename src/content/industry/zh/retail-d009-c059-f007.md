# 生鲜冷链到店验收的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
生鲜冷链到店验收的核心材料是冷链温度记录、到货验收单、拒收单和供应商送货单，数据来源包括冷链车温控、WMS、门店收货系统和质检照片。与水果采购相比，冷链验收关注运输温度和到货批次，产地询价不在这一环节。出错会带来食材变质、供应商争议和监管处罚，因此对话日志与审计要能还原每批验收的操作主体、时间和材料状态。数据按每批和每日更新，日更频率意味着交接时点与批次边界需要同时核对。

## 这些特征在「对话日志与审计」这一环带来什么约束
运营权限与交接管理涉及会话身份、运行详情、字段含义和调试与正式调用的区分。对话身份需要结合 chatId 核对目标对话与业务记录，不同入口的会话不能混算。需要运行详情时按官方契约设置 detail，并检查 responseData 中的模块响应。日志与接口实际返回的字段决定哪些业务数据可核对，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，需分别核对输入、历史与返回内容。业务审计分工中，对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。检索或表单收集值，业务验证、审批、数据库写入和外部同步需要各自的下游实现。

假设演练样本：某门店收货组交接记录中，材料原文为“2025年3月10日批次 A 的冷链温度记录显示运输温度 4.2 摄氏度，到货验收单由收货员甲签字，拒收单载明抽检不合格两项”。一条待判定的交接请求为“将该批次验收操作权限由收货员甲转交收货员乙，并确认乙可查看该批次对话日志”。该请求涉及主体为收货员甲与乙，对象为批次 A 的验收操作与对话日志，状态为待转交，有效范围限于该批次。是否已获授权、乙是否具备目标应用和会话权限，均属未载明事项，需要另行核对。

## 配置怎么定
下表围绕上述样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。本次假设试验起点仅用于演练，不作为官方默认值。

| 配置项 | 本次假设试验起点 | 核对方式与理由 |
| --- | --- | --- |
| 会话身份 chatId | 使用样本批次的唯一会话 ID | 核对目标对话与业务记录是否指向同一批次，避免不同入口混算 |
| 运行详情 detail | 设为 true | 需要中间值时按官方契约设置，并检查 responseData 中的模块响应 |
| 响应消息 ID responseChatItemId | 在当前 chatId 下唯一 | 官方要求同一 chatId 下唯一，用于定位本次对话的响应消息 |
| 身份代理 authProxy | 由团队所有者创建或编辑 key 时开启 | 代理身份仍需具备目标应用和会话权限，开启状态需核对 |
| 对话源 source | 样本取值为 api | 获取通过 API 创建的会话，不包含页面上的会话 |
| 反馈读取 loadCustomFeedbacks | 本次假设试验起点为 true | 用于读取自定义反馈，是否开启按实际核对需求决定 |

## 容易做错的三处
1. 把 chatId 相同当作业务记录一致。输入是样本批次的 chatId 与验收单批次号，比较两者是否指向同一对象，若不同则不能合并计算。
2. 把 detail 返回的 responseData 当作全部业务数据。输入是接口实际返回字段，比较验收单、拒收单是否在返回中出现，未出现时记录为未返回，不能推定已完整留存。
3. 把待转交请求当作已授权执行。输入是交接请求文本，比较是否载明授权主体、生效条件和目标应用权限，未载明时保持待核实状态。

## 怎么确认配好了
1. 使用样本原文“2025年3月10日批次 A 的冷链温度记录显示运输温度 4.2 摄氏度，到货验收单由收货员甲签字，拒收单载明抽检不合格两项”，输入 chatId 与批次号，比较两者是否指向同一对象，一致时满足核对条件。
2. 使用样本交接请求“将该批次验收操作权限由收货员甲转交收货员乙，并确认乙可查看该批次对话日志”，输入请求文本与授权记录，比较是否载明授权主体、生效条件和目标应用权限，未载明时记录为未获支持。
3. 使用 detail=true 的响应，输入 responseData，比较其中是否包含验收单与拒收单字段，包含时满足核对条件，未包含时记录为未返回，不推定已完整留存。
