# 生鲜水果门店采购的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

生鲜水果门店采购的日常文档包括采购单、验收单、农残检测报告和损耗记录。与便利店鲜食订货相比，水果采购更多依赖批发市场行情和等级验收，数据来源涵盖批发市场行情、供应商报价、门店销售和检测报告。这些材料按日或每批更新，出错会带来腐损亏损、食安投诉和门店缺货。在运营权限与交接管理中，对话日志与审计要解决的核心问题是：交接时哪些材料、操作和请求处于什么授权状态，检索结果和表单填写不能替代授权执行。

## 这些特征在「对话日志与审计」这一环带来什么约束

审计需要结合 chatId 核对目标对话与业务记录，避免把不同入口的会话混算。需要对话接口运行详情时，按官方契约设置 detail 并检查 responseData。核对日志与接口实际返回字段，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，需分别核对输入、历史与返回内容。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。语义召回和相关度不负责权限或实体隔离。

假设演练样本：某生鲜采购员提交一条会话，chatId 为 "sg-2024-1015-a"，appId 为 "app-fruit-001"。对话接口返回 responseData 中含 moduleName 为 "AI 对话" 的节点，query 为 "10月15日A档口红富士苹果报价"，answer 为 "A档口红富士苹果报价为每斤4.2元，等级为一级，报价有效期至10月16日"。待判定拟稿句为："该报价已确认供货，采购单可据此创建。" 原文仅载明报价及有效期，未载明供货确认或采购单授权。

## 配置怎么定

| 核对项 | 本次假设起点 | 比较与说明 |
| --- | --- | --- |
| chatId 唯一性 | "sg-2024-1015-a" | 与同应用下其他会话 ID 比较，确认不重复 |
| appId 归属 | "app-fruit-001" | 与目标应用路径中的 AppId 比较，确认一致 |
| detail 设置 | true | 需要运行详情时设置，检查 responseData 是否返回 |
| 运行详情字段 | moduleName、query、answer | 与接口实际返回字段比较，未返回项不推定留存 |
| 授权状态核对 | 报价有效期至10月16日 | 与拟稿句"已确认供货"比较，原文未载明供货确认 |
| 交接请求范围 | 采购单创建 | 与原文授权边界比较，原文未载明采购单创建授权 |

## 容易做错的三处

1. 把报价有效期当作供货期限。输入为假设样本中"报价有效期至10月16日"，比较拟稿句"已确认供货"，两者字段不同，报价有效期不表示供货期限，应判定为未获支持。

2. 把检索结果当作权限依据。输入为 responseData 中返回的 answer 内容，比较交接请求中的采购单创建动作，检索命中不构成授权，应记录授权缺口。

3. 把待审核状态当作缺少操作权限。输入为假设样本中未载明的采购单状态，比较"缺少权限"的判断，未载明状态属于待核实，不能判定为否定。

## 怎么确认配好了

1. 使用假设样本原文，输入 chatId "sg-2024-1015-a" 与 appId "app-fruit-001"，比较接口返回的 responseData 中 moduleName 为 "AI 对话" 的 query 字段是否与"10月15日A档口红富士苹果报价"一致。若一致，运行详情可核对；若不一致或字段缺失，记录缺口。

2. 使用拟稿句"该报价已确认供货，采购单可据此创建"，输入原文中"报价有效期至10月16日"，比较"已确认供货"与原文载明字段。若原文无供货确认表述，判定为未获支持；若原文有明确供货确认字段，方可进一步核对。

3. 使用交接请求中的采购单创建动作，输入原文授权边界，比较原文是否载明采购单创建授权。若原文未载明，记录授权缺口并保留待核实；若原文载明，按载明范围核对。
