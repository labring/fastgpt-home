# 生鲜称重分拣的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
生鲜称重分拣发生在仓内履约环节，核心是重量和规格。分拣任务单、称重标签、少称补偿单、质检记录构成主要文档面，数据来源包括 WMS、电子秤、订单系统和质检照片。这些材料按单产生，涉及分拣员与质检主管的交接。少发赔付、毛利损耗和顾客差评是出错后果，因此交接时对材料状态与操作权限的核对要求较高。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话日志与审计在 FastGPT 侧依赖 chatId、dataId、appId 等标识关联会话与对话。交接时需先核对目标对话与业务记录是否指向同一对象，不同入口的会话不能混算。需要运行详情时按官方契约设置 detail，检查 responseData 中的实际返回字段；未返回的业务数据不能推定已完整留存。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。检索与表单不承担授权执行，相关度分数不构成权限或实体过滤。

假设演练样本：某前置仓 2025 年 6 月 3 日分拣任务单 A-0603 载明“分拣员李某负责 12 号订单称重，质检主管王某复核”。同日少称补偿单 B-0603 载明“申请对象 12 号订单，状态待审核，申请人李某”。拟交接请求为“将 A-0603 的称重标签复核权限移交王某并确认 B-0603 已通过”。该请求涉及权限移交与状态确认，待判定。

## 配置怎么定
围绕上述样本，仅列与本功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，用于比较，不作为官方默认值。

| 设置或核对项 | 本次假设起点 | 核对方式 |
| --- | --- | --- |
| appId 传入 | 请求体传入 body.appId | 与目标应用 ID 比较，确认指向同一应用 |
| chatId 一致性 | 交接前后使用同一 chatId | 比较两次请求的 chatId 字段是否相同 |
| detail 取值 | 设为 true | 检查 responseData 是否返回节点响应 |
| authProxy 状态 | 未开启 | 核对 key 创建时的开关记录，未开启时按普通身份处理 |
| 会话来源 source | 设为 api | 比较返回列表是否仅含 API 创建的会话 |
| 交互节点返回字段 | 仅含 type 与 params | 检查 entryNodeIds 等内部字段是否未返回 |

## 容易做错的三处
1. 把检索结果当作授权依据。输入为样本中的拟交接请求，若仅凭检索命中 A-0603 就认定权限已移交，比较对象是权限移交记录本身，观察结果是检索命中与授权记录不一致，属错误。
2. 把待审核当作已通过。输入为 B-0603 状态“待审核”，若在交接结论中写为已通过，比较对象是补偿单状态字段，观察结果是状态文本与结论不符，属错误。
3. 混用不同 chatId 的会话。输入为两次请求的 chatId，若交接时把不同 chatId 的历史合并计算，比较对象是 chatId 字段，观察结果是字段不一致，属错误。

## 怎么确认配好了
1. 针对样本拟交接请求，输入为请求体中的 appId 与 chatId，比较对象是目标应用与会话标识，满足条件为两者与 A-0603 关联记录一致，否则记录为待核实。
2. 针对 B-0603 状态，输入为补偿单原文“状态待审核”，比较对象是交接结论中的状态描述，满足条件为结论保留待审核表述，出现已通过表述则不满足。
3. 针对权限移交，输入为 authProxy 开关记录与 key 权限说明，比较对象是移交请求中的权限范围，满足条件为存在明确授权记录，仅有检索命中或表单填写不构成满足。
