# 生鲜称重分拣的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

生鲜称重分拣在仓内履约环节完成，核心数据是重量与规格。主要来源包括 WMS、电子秤、订单系统与质检照片，日常文档为分拣任务单、称重标签、少称补偿单与质检记录。数据更新频率为每单与每日，出错会产生少发赔付、毛利损耗与顾客差评。这些特征决定部署与升级时必须核对称重、贴标、补偿与质检四类文档的字段口径，避免升级后交接材料缺项。

## 这些特征在「部署与升级」这一环带来什么约束

升级涉及 fastgpt-app 与 fastgpt-pro 镜像 tag 更新至 v4.17.2，并包含两个手动触发脚本：`20261008_migrate_chunk_training` 与 `20261009_migrate_dataset_rebuild_status`。前者要求确认集群中所有旧版本实例已完全停止、旧任务租约过期后再执行，后者依赖前者完成。二者均不阻塞服务启动。AI Proxy 为必需依赖，App 与 Admin 均须设置 `AIPROXY_API_ENDPOINT` 与非空 `AIPROXY_API_TOKEN`，缺少任一项会启动校验失败。运营交接中的材料、操作与请求处于何种授权状态，须以文档字段与人工核对为准，检索或表单收集值不构成授权执行。

假设演练样本：某前置仓分拣主管提交交接请求，材料原文为三句。第一句：“分拣任务单 FP-2026-0417-03，分拣员甲，2026年4月17日，品项菠菜，目标规格500克±10克。”第二句：“称重标签 TL-0417-0891，实际重量478克，状态已贴标。”第三句：“少称补偿单 BC-0417-012，关联订单 ORD-88231，补偿数量1份，状态待质检主管审核。”待判定拟稿句为：“上述补偿单已获批准，可在升级后直接执行退款。”该拟稿句与材料原文比较：材料仅载明状态为待质检主管审核，未载明批准主体、批准时间或退款执行记录，故拟稿句未获支持。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 选择理由与比较对象 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://aiproxy:3000` | 文档要求填根地址，不追加 `/v1`；与单模型地址比较 |
| `AIPROXY_API_TOKEN` | 假设为32位随机串 | 文档要求非空且与服务端一致；与空值比较 |
| `AGENT_SANDBOX_PROVIDER` | 留空 | 文档说明为空时不启用沙箱；与 `sealosdevbox` 比较 |
| `SYNC_INDEX` | 保持 `true` | 文档说明启动时创建缺失索引；与关闭后自行维护比较 |
| `DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED` | 保持 `false` | 文档要求 App 与 Pro Admin 一致；与 `true` 比较 |

上述数值为本次假设试验起点，非官方默认值。`SYNC_INDEX` 与 `DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED` 的文档默认值分别为 `true` 与 `false`。

## 容易做错的三处

1. 将待审核状态当作已批准。输入为补偿单 BC-0417-012 状态“待质检主管审核”，比较对象为“已批准”，观察结果为两者不相等，判定未获支持。
2. 将表单收集值当作授权执行。输入为交接请求中填写的补偿数量，比较对象为质检主管审核记录，观察结果为缺少审核字段，判定授权未完成。
3. 将检索结果当作权限隔离。输入为按关键词检索到的补偿单，比较对象为该分拣主管的授权范围，观察结果为检索返回不证明读取权限，判定需人工核对。

## 怎么确认配好了

1. 核对 `AIPROXY_API_ENDPOINT` 与 `AIPROXY_API_TOKEN`。输入为假设起点值，比较对象为文档要求的根地址与非空 Token，观察结果为两项均非空且地址不含 `/v1`，满足条件。
2. 核对升级脚本执行顺序。输入为 `20261008_migrate_chunk_training` 与 `20261009_migrate_dataset_rebuild_status`，比较对象为文档要求的先后依赖，观察结果为前者先于后者执行且旧实例已停止，满足条件。
3. 核对拟稿句与材料原文。输入为“上述补偿单已获批准，可在升级后直接执行退款”，比较对象为材料原文的状态字段，观察结果为原文未载明批准与退款执行，判定未获支持，缺口保留。
