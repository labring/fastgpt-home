# 电商仓入库上架的运营权限与交接管理：表单与交互

## 这个品类的数据长什么样

在电商仓入库上架的运营权限与交接管理中，本页说明FastGPT的表单与交互如何衔接资料。入库交接表单要区分暂存位置、正式上架和异常待办，指定处理路径不能自动完成仓库动作。所用场景为自拟文字测试。

## 这些特征在「表单与交互」这一环带来什么约束

自拟交接原句说物料暂放临时区，正式货位待补，差异单已交下一班但未有处理结果。表单可收物料、仓库与这些状态，让人员选择补位置或转差异核查。临时区说明当前记载，不证明正式上架；工作交给下一班也不等于差异关闭。提交后应查下游保留仓别和待补项，人员选项不自动切换仓库身份或写库存。

## 配置怎么定

| 入库交接表单 | 自拟位置状态 | 实际核对 |
| --- | --- | --- |
| 临时区 | 暂放记录 | 非正式货位 |
| 货位缺项 | 仍待补 | 本件上架证据 |
| 仓库对象 | 提交与接收一致 | 排除他仓 |
| 差异交班 | 未有处理结果 | 不冒关闭 |
| 业务写回 | 收货调整另接 | 选择非执行 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `表单输入` | 收集输入并在提交后传值。 |
| `必填信息核对` | 业务必填与缺项处理需另设计。 |
| `用户选择` | 选择结果对应已连接的分支。 |
| `交互状态` | 分别核等待和完成交互状态。 |
| `后续处理分工` | 校验、审批及写入另核结果。 |

## 容易做错的三处

暂存冒上架：若临时位置被写成正式货位，应取本件实际上架依据；仓别错传：若另一仓说明用于本次，应对提交对象与接收文字；交班冒关闭：若已交差异单变成已解决，应查真实处理结果。三项分别核位置性质、对象和业务阶段，不能由连接分支证明。

## 怎么确认配好了

验收逐项比较表单提交与接收内容，补本仓位置后只更新所指物料，差异仍缺时留待核。若选择的是转核查，不能写成已执行库存调整。正式收货、上架和差异写回需另接业务流程核权限及回执，节点等待后继续只说明交互动作，不能从记录存在推账实一致或所有货物已经可用。
