# 电商仓入库上架的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样
入库上架处理货物进入仓库的第一道账实确认，数据源为 WMS、ERP 采购、供应商送货单与条码扫描，出错会带来库存账实不符、后续拣货错误与供应商争议。日常文档是采购到货单、入库验收单、上架任务与差异报告。这些材料在部署与升级环节的约束在于：升级前后同一批到货单、验收单与上架任务的字段与状态必须能被同一套权限口径解释，交接时的授权状态不能被检索或表单替代。

## 这些特征在「部署与升级」这一环带来什么约束
升级说明列出两个手动触发脚本：`20261008_migrate_chunk_training` 与 `20261009_migrate_dataset_rebuild_status`，均不阻塞服务启动，后者依赖前者完成。执行前需确认旧版本实例已完全停止、旧任务租约过期。运营权限与交接管理在升级中的边界是：脚本执行、成员权限调整、上架任务交接分属不同动作，任一动作的完成状态不能由另一动作推定。

假设演练样本：某电商仓 WMS 管理员在升级前整理交接材料。采购到货单原文：「到货单 DH-2026-0417，供应商 A，采购单 CG-3312，到货数量 480 件，状态：待验收。」入库验收单原文：「验收单 YS-2026-0417，对应到货单 DH-2026-0417，实收 480 件，验收员：李，状态：已验收，待上架。」上架任务原文：「任务 SJ-2026-0417，关联验收单 YS-2026-0417，目标库位 B-12，执行人：未分配，状态：待分配。」待判定拟稿句：「上架任务 SJ-2026-0417 已由李完成上架，库存已同步。」该句与原文的比对点是执行人与状态：原文执行人为未分配、状态为待分配，验收员李与上架执行人不是同一字段，库存同步在原文中没有记录。

## 配置怎么定
下表为本页相关的官方已说明设置或实施核对项，数值若出现均标注为本次假设试验起点，不作为官方默认值。

| 项目 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 假设填 `http://aiproxy:3000` | 官方要求根地址且不追加 `/v1`；与官方示例格式逐字符比较 |
| `AIPROXY_API_TOKEN` | 假设填非空字符串 | 官方要求非空且与服务端一致；与 AI Proxy 服务端配置值比较 |
| `FILE_TOKEN_KEY`、`AES256_SECRET_KEY`、`INVOKE_TOKEN_SECRET` | 假设各填随机强密钥 | 官方要求运行期必填；核对长度下限与是否为示例值 |
| `PRO_URL` 与 `PRO_TOKEN` | 假设同时配置 | 官方说明 App 配置 `PRO_URL` 时 `PRO_TOKEN` 必填；核对两者是否同时存在 |
| `DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED` | 假设 App 与 Pro Admin 取同一值 | 官方要求两服务保持一致；比较两侧取值 |
| 升级脚本执行前置 | 人工核对项 | 官方要求确认旧实例停止、旧任务租约过期后再执行；核对实例状态与租约记录 |

## 容易做错的三处
1. 把验收单的「已验收，待上架」当成上架任务已完成。输入是验收单与上架任务两份材料；比较对象是上架任务的执行人与状态字段；验收单状态与上架任务状态属于不同单据的不同字段，不能互相替代。
2. 把检索到到货单、验收单或上架任务记录当成获得了操作授权。输入是检索结果或表单填写内容；比较对象是授权记录本身；检索与表单收集值不构成权限授予或交接完成。
3. 把升级脚本「手动触发、不阻塞启动」当成脚本已执行或迁移已完成。输入是升级说明中的脚本标识与触发方式；比较对象是实际执行记录；待触发状态不证明已执行，也不证明迁移结果。

## 怎么确认配好了
1. 输入假设样本中三份材料原文与拟稿句，比较拟稿句所述执行人、状态与原文对应字段，若拟稿句称李已完成上架，而任务原文执行人为未分配、状态为待分配，则该句未获支持，需记录证据缺口。
2. 输入假设的 `AIPROXY_API_ENDPOINT` 与 `AIPROXY_API_TOKEN` 配置值，比较地址是否含 `/v1`、Token 是否非空，若地址追加了路径或 Token 为空，则与官方要求不符，启动校验预期失败。
3. 输入升级脚本标识与实例停止、租约状态的核对记录，比较脚本是否已实际执行，若仅有触发入口而无执行记录，则迁移完成状态待核实，不判定为已完成。
