# 直播选品与样品质检的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
直播选品与样品质检在开播前完成，判断商品能否上播、是否适合直播展示。主要材料来自供应商资料、检测机构报告、平台负面目录与历史退货率，日常文档包括样品评估表、质检报告、供应商资质与禁售清单。对话日志与审计环节要面对的是：同一件样品在选品经理、供应链BD、质检专员之间交接时，哪些对话属于同一会话、哪些运行详情可以调取、哪些字段实际留存。资料按周、每品更新，这一频率只说明材料刷新节奏，本页不据此推导批量同步或实时触发。

## 这些特征在「对话日志与审计」这一环带来什么约束
会话身份用 chatId 区分。不传入 chatId 时，系统不使用 FastGpt 提供的上下文功能，完全以传入的 messages 构建上下文；传入非空字符串时，系统从数据库取该会话，并以 messages 数组最后一个内容作为用户问题，其余 message 被忽略。交接时若把不同入口的会话混算，日志对账就失去共同主体。需要运行详情时按官方契约设置 detail，非 stream 模式下中间值保存在 responseData，stream 模式下通过 event 区分。接口返回的字段有限，未返回的业务数据不能推定已完整留存。检索与相似度只影响内容匹配，不承担权限或实体隔离，日志存在也不等于完成合规审计。

假设演练样本：某质检专员在 2025 年 3 月 10 日提交一条交接请求，原文为「样品 A 的质检报告已上传，请选品经理确认是否可进入 3 月 12 日直播清单」。同一 chatId 下另有一条记录：「供应商资质待补充，暂缓上播」。待判定拟稿句为「样品 A 已完成全部资质核验，可直接上播」。核对材料只含上述两句，未载明资质核验完成的主体、时间与结论。

## 配置怎么定
下表只列与本页功能、主任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，用于与另一取值比较，不作为官方默认值。

| 配置项 | 本次假设起点 | 核对方式与理由 |
| --- | --- | --- |
| chatId | 一条质检交接会话一个值 | 与业务记录一一对应，长度小于 250，比较不同入口是否被并入同一值 |
| detail | 需要运行详情时设为 true | 与 false 比较，确认 responseData 或 event 是否出现节点响应 |
| stream | 按调用方渲染需要选择 | 与另一取值比较，确认中间值通过 event 还是 responseData 获取 |
| responseChatItemId | 同一 chatId 下唯一 | 与已有值比较，重复即无法区分本次响应消息 |
| source | 取 API 创建的会话时填 api | 与页面会话比较，确认返回列表范围 |
| loadCustomFeedbacks | 需要读取自定义反馈时开启 | 与关闭比较，确认反馈字段是否出现在记录中 |

## 容易做错的三处
1. 把未返回字段当作已留存。接口响应没有给出供应商资质核验结论，据此认定资质已核验，输入是响应体，比较对象是实际返回字段清单，可观察结果是结论字段缺失。
2. 把不同 chatId 的会话合并对账。输入是两条来自不同 chatId 的记录，比较对象是各自 chatId，可观察结果是主体不一致，无法构成同一会话的日志链。
3. 把待补充状态读成已通过。样本中「供应商资质待补充，暂缓上播」是待办描述，拟稿句写成已完成核验，输入是这两句原文，比较对象是状态词，可观察结果是状态字段取值互斥。

## 怎么确认配好了
1. 会话身份核对。输入为假设样本中两条记录及各自 chatId，比较两条 chatId 是否相同，若不同则不能合并计算，记录为待核实。
2. 运行详情核对。输入为一次 detail=true 的请求，比较返回体中是否出现 responseData 或 event=flowResponses，出现节点响应才满足条件；未出现时记录缺口，不推断失败原因。
3. 拟稿句核对。输入为「样品 A 已完成全部资质核验，可直接上播」与两句原文，比较主体、时间与结论字段，原文未载明核验完成的主体与结论，该句属于未获支持，需补充材料后重新核对。
