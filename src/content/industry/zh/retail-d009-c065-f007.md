# 直播间违规申诉的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
直播间违规申诉处理已经发生的平台处罚，需要复盘违规通知、直播录屏、商品资质与申诉说明构成的证据链。数据来自平台违规中心、直播回放、客服记录与商品资质库，更新不定期，每次违规触发一轮材料归集。这决定对话日志与审计环节的核心任务：把某次申诉相关的会话、运行详情与交接请求对应到同一主体、同一期间与同一字段，避免把不同入口的会话或不同轮次的记录混算。

## 这些特征在「对话日志与审计」这一环带来什么约束
会话以 chatId 标识，对话以 dataId 标识，应用以 appId 标识。获取会话列表用 source=api 只取通过 API 创建的会话，页面上的会话不在其中；清空应用会话同样只清空 API Key 创建的会话。需要运行详情时按官方契约设置 detail，非流式结果保存在 responseData，流式通过 event 区分，event 取值包含 flowResponses 与 error。日志字段只反映接口实际返回的内容，未返回的业务数据不能推定已完整留存。对账、留存与合规要求由完整业务方案另行落实，日志存在不等于完成合规审计。检索相似度不承担权限或实体隔离职能，检索本身不构成授权。

假设演练样本：某店铺合规岗在 2026 年 3 月 10 日收到一条商品禁播违规通知，编号与商品对象写在通知正文内，处理期间产生一条会话，chatId 为演练值，该会话下一条待判定对话的 dataId 为演练值。拟交接请求原文为：“该会话已包含违规片段定位记录，交接后由接手人直接提交申诉说明。”供核对材料原文为：“违规通知载明处罚对象为某商品，处罚状态为已生效；申诉说明文档当前状态为草稿，未提交。”拟稿句与请求均需按此原文核对。

## 配置怎么定
下表围绕本页样本，列出官方已说明的设置或实施核对项。

| 配置或核对项 | 取值与来源 | 用途与边界 |
| --- | --- | --- |
| appId | 请求体传入，官方参数说明 | 定位应用，不能替代会话与对话标识 |
| chatId | 请求体传入，长度小于 250 | 定位目标会话，需自行确保唯一 |
| dataId | 会话下某一对话的 ID | 定位待判定对话，与 chatId 配合核对 |
| detail | 官方参数，true 返回中间值 | 取运行详情时设置，非流式看 responseData |
| source | 会话列表参数，source=api | 只取 API 创建的会话，页面会话不在其中 |
| authProxy | 需团队所有者开启，代理身份仍需目标应用与会话权限 | 代理不产生超出原有权限的授权 |

本次假设试验起点：把 pageSize 设为 20，理由是样本会话数量少、便于逐条核对，比较对象为接口返回的 total 与 list 长度是否一致。该数值为本次演练起点，非官方默认值。

## 容易做错的三处
1. 把检索或表单当作授权。样本中拟交接请求称可直接提交申诉说明，但材料原文显示申诉说明为草稿、未提交。检索命中或表单填写不产生提交权限，提交属需另接系统实现的业务动作。
2. 混算不同入口的会话。用 source=api 取会话时，页面会话不返回；若把两类会话合并计数，chatId 与 dataId 的对应关系即失真。
3. 把日志存在等同于合规审计完成。运行详情只反映接口实际返回字段，未返回的业务数据保持未知，对账与留存需由完整业务方案落实。

## 怎么确认配好了
1. 输入样本的 appId 与 chatId，调用获取会话列表并设 source=api，比较返回 list 中是否存在该 chatId。出现该 chatId 且 total 与 list 长度一致，满足条件；未出现则记录为未获支持。
2. 输入样本的 appId、chatId 与 dataId，设 detail=true 且 stream=false，比较 responseData 中是否存在该对话的运行记录。存在对应记录且含 moduleName、moduleType 等字段，满足条件；responseData 为空或缺少对应 dataId，记录缺口。
3. 输入拟交接请求原文与材料原文，比较请求所称“已包含违规片段定位记录”与材料所称“申诉说明为草稿、未提交”。两处指向同一主体、同一期间、同一字段且取值互斥时，判定请求所述状态与材料不符，交接不得据此执行提交；材料未载明的部分保留待核实。

纸面空结果承接：以明确的输入 [] 核对下游设计，观察下游是否按空结果处理，不声称虚构检索必然返回空。跨不同向量模型的库不可共同关联，先核标识并排除不符合者，记录实际观察。
