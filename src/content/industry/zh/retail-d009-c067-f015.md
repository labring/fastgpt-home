# 社区团购团长运营的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样

社区团购团长运营围绕社区节点与佣金结算展开，日常材料包括团长协议、佣金表、提货清单和社群公告。这些材料的更新频率为日、每团，检索时必须按具体日期与团点范围限定，不能把不同团点或不同日期的字段混用。团长协议、佣金表、提货清单、社群公告四类材料分别对应授权约定、结算依据、履约凭据和通知记录，检索结果只能反映这些材料中已载明的内容。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，需先核对向量模型标识并排除不符合者，记录实际观察，不执行跨模型检索来比较漏召回。混合检索通过 RRF 融合语义与全文结果，RRF 是融合过程，不是可开启的独立开关。重排须具备模型且按设置启用。图片检索须有相应图像输入及模型能力。最低相关度仅在语义检索或使用结果重排时生效，它是过滤阈值，不是最终排序规则，也不承担权限或实体隔离功能。引用上限以 token 为单位，输出引用内容长度可以为 0。

假设演练样本（纸面材料，非真实记录）：

材料原文一：「团长协议第 3 条：本协议自双方签署之日起生效，甲方为平台运营方，乙方为团长。协议期内乙方可申请提货清单核对权限。」

材料原文二：「佣金表（2025 年 3 月，A 团点）：基础佣金比例 5%，售后扣减按实际退款金额计。本表仅适用于 A 团点 3 月订单。」

拟判定句：「团长协议已生效，乙方已获得提货清单核对权限。」

该拟判定句存在证据缺口：材料原文一载明协议自签署之日起生效，但未载明签署已完成；也未载明提货清单核对权限已实际开通。两个事实均待核实。

## 配置怎么定

| 配置项 | 本页取值或核对方式 | 依据与边界 |
| --- | --- | --- |
| 关联的知识库 | 仅关联使用相同向量模型的团长协议、佣金表、提货清单、社群公告库 | 跨向量模型的库不可共同关联 |
| 搜索模式 | 对拟判定句分别测试语义检索与全文检索，比较召回内容 | 不预设一种模式适合全部资料 |
| 引用上限 | 本次假设试验起点设为 2000 token，与 1000 token 结果比较内容完整性 | 该数值为本次试验起点，非官方默认值 |
| 最低相关度 | 先标注相关与无关样本，再比较阈值调整后的过滤结果 | 仅在语义检索或结果重排时生效 |
| 问题优化 | 比较原问题与优化后问题，核对主体、团点、日期是否被改错 | 用于指代消除和问题扩展 |
| 结果重排 | 确认重排模型已配置并按设置启用，再比较重排得分 | 未启用时不产生重排得分 |

## 容易做错的三处

1. 将检索命中当作授权已生效。输入拟判定句检索团长协议库，若召回材料原文一，只说明协议生效条件被载明，签署是否完成、权限是否开通仍待核实。
2. 将最低相关度当作权限或实体过滤器。输入拟判定句并调高最低相关度，比较过滤前后结果，若无关团点的佣金表仍被召回，说明该阈值不隔离实体。
3. 将 RRF 当作可开启开关。核对搜索参数配置界面，若不存在名为 RRF 的开关项，则混合检索的融合过程不可单独启停。

## 怎么确认配好了

1. 输入拟判定句，比较召回内容与材料原文一、材料原文二。若召回内容包含协议生效条件但未包含签署完成记录，则判定为未获支持，记录证据缺口。
2. 输入拟判定句，分别以语义检索与全文检索执行，比较两次召回结果。若全文检索命中「团长协议」「提货清单核对权限」等词，语义检索命中相近表述，则两路结果均需与原文逐字核对。
3. 以纸面输入空数组核对下游设计。若搜索节点输出引用内容长度为 0，确认下游链路仍走通，不声称虚构规则检索一定返回空数组。
