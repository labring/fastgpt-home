# 社区团购团长运营的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

社区团购团长运营管理社区节点与佣金，不直接做冷链质检。日常材料包括团长协议、佣金表、提货清单、社群公告，数据按日、每团更新。这些材料同时承载权限信息：谁可以查看佣金明细，谁可以发起提货核对，谁可以发布社群公告。部署与升级时，团长协议与佣金表的字段结构、提货清单的归属范围、社群公告的发布主体，都可能在版本间发生变化。材料本身只记录约定与结果，不记录系统授权状态，因此核对时必须把材料内容与系统配置分开看待。

## 这些特征在「部署与升级」这一环带来什么约束

升级前需核对当前版本与目标版本及对应升级说明，不从旧配置名称推断现行行为。App 与 Admin 必须设置 `AIPROXY_API_ENDPOINT` 和非空 `AIPROXY_API_TOKEN`，缺少任一项会导致启动校验失败。`FILE_TOKEN_KEY`、`AES256_SECRET_KEY`、`INVOKE_TOKEN_SECRET` 为运行期必填。开源版从 4.15.0 起不再读取 `config.json`，旧挂载需删除并改为环境变量。升级脚本 `20261008_migrate_chunk_training` 与 `20261009_migrate_dataset_rebuild_status` 为手动触发，不阻塞服务启动；`20261008_migrate_chunk_training` 需在旧实例完全停止、旧任务租约过期后执行，`20261009_migrate_dataset_rebuild_status` 依赖前者完成。检索或表单收集值不构成授权执行；团长协议的签署、合作达成、合同生效是三个不同事实。

假设演练样本：材料原文为「团长甲与平台于2026年3月1日签署团长协议，约定甲负责A小区提货点，佣金按提货清单结算，协议有效期至2026年12月31日。」拟稿句为「团长甲已获得A小区提货点佣金结算权限，可自行发布社群公告。」待判定请求为「请为团长甲开通社群公告发布权限。」原文只说明协议签署与提货点归属，未说明系统权限已开通，也未说明公告发布权限归属。拟稿句把协议签署等同于权限开通，且增加了原文未提及的公告权限。请求处于待审核状态，不证明缺少操作权限，也不构成已批准。

## 配置怎么定

| 配置项 | 假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 本次假设起点为 `http://aiproxy:3000` | 按官方示例填写根地址，比较是否附加 `/v1` 或对话接口路径 |
| `AIPROXY_API_TOKEN` | 本次假设起点为空待填 | 必须非空且与服务端一致，比较 App 与 Admin 两侧取值 |
| `FILE_TOKEN_KEY` | 本次假设起点为随机强密钥 | 长度至少6位，比较是否使用示例值 |
| `AES256_SECRET_KEY` | 本次假设起点为随机强密钥 | 长度至少6位，比较是否使用示例值 |
| `INVOKE_TOKEN_SECRET` | 本次假设起点为随机强密钥 | 长度至少32位，比较是否使用示例值 |
| `PRO_TOKEN` | 本次假设起点为空待填 | App 配置 `PRO_URL` 时必填，比较两侧是否一致 |

## 容易做错的三处

1. 把团长协议签署当作系统权限已开通。输入为协议原文与拟稿句，比较原文是否载明权限开通字段，可观察结果为原文未载明该字段，拟稿句超出原文范围。
2. 把待审核的权限请求写成已批准。输入为待判定请求，比较请求状态与批准状态，可观察结果为请求处于待审核，未获批准证据。
3. 从旧 `config.json` 字段推断现行环境变量行为。输入为旧字段名，比较官方升级说明中的对应关系，可观察结果为旧字段已不再读取，需按环境变量重新配置。

## 怎么确认配好了

1. 输入假设样本中的协议原文与拟稿句，比较拟稿句是否增加原文未载明的权限内容，若拟稿句出现「已获得」「可自行」等超出原文的表述，则判定为超出原文范围。
2. 输入待判定请求，比较请求状态与批准状态，若请求仍为待审核且无批准记录，则记录为未获支持，保留证据缺口。
3. 输入旧 `config.json` 字段与当前环境变量配置，比较两者对应关系，若旧字段仍被挂载且未改为环境变量，则记录为需按升级说明调整。
