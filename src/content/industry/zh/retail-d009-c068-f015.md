# 社区团购预售集单的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样

社区团购预售集单先收订单再组织采购履约，资料围绕预售商品表、集单结果、采购计划、截单通知展开，更新频率为日或每场。这些资料在运营交接时同时承担两种角色：说明商品与场次事实，以及记录谁在什么状态下可以继续操作。检索环节只负责把相关内容召回并交给模型，不判断操作人是否获得授权。交接材料里常见的状态词包括待审核、已提交、已签署、已生效，这些词各自指向不同事实，检索结果中出现其中一个，不能推出其余状态成立。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可以关联一个或多个使用相同向量模型的知识库，跨不同向量模型的库不可共同关联。搜索模式按测试问题比较语义检索、全文检索与混合检索，不预设一种模式适合全部资料。引用上限以 token 为单位，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，会增加一次模型调用。混合检索通过 RRF 融合多路结果，重排需要具备模型并按设置启用，图片检索需要相应图像输入及模型能力。相似度得分只反映文本相关程度，不承担权限或实体隔离。

假设演练样本：某平台运营交接材料原文为“预售商品表 V3 于本场截单前一日 18:00 更新，集单结果状态为待审核，采购计划尚未生成”。待判定拟稿句为“集单结果已审核通过，采购计划已下发”。核对时比较主体、期间与字段：原文只载明待审核，拟稿句写已审核通过，属于同字段互斥取值的矛盾；采购计划在原文中为尚未生成，拟稿句写已下发，属于未获支持。交接请求若写“请按已审核状态继续下采”，该请求本身不构成授权，需另接审批与采购系统实现。

## 配置怎么定

| 配置项 | 本页取值或核对项 | 依据与说明 |
| --- | --- | --- |
| 关联知识库 | 仅关联使用相同向量模型的预售集单资料库 | 节点可关联一个或多个相同向量模型的知识库，跨模型先核标识并排除 |
| 搜索模式 | 假设试验起点为混合检索，与语义检索、全文检索分别比较 | 按测试问题比较三种模式，不预设一种适合全部资料 |
| 引用上限 | 假设试验起点为覆盖一份截单通知全文的 token 量 | 单位为 token，用长短不同的实际资料测试内容是否完整 |
| 最低相关度 | 先标注相关与无关样本，再设本次假设起点 | 仅在语义检索或结果重排时生效，属过滤阈值 |
| 问题优化 | 对含指代的交接追问开启，比较原问题与优化后问题 | 用于指代消除和问题扩展，核对主体是否被改错 |
| 结果重排 | 具备模型并按设置启用后，比较重排前后排序 | 重排得分可用于过滤，需模型且按设置启用 |

## 容易做错的三处

1. 把检索命中当作授权。输入为交接请求“按已审核状态继续下采”，比较检索返回的集单结果字段与请求引用的状态，若返回为待审核而请求写已审核，则出现同字段互斥取值矛盾。可执行检查：读取返回内容的状态字段，与请求中的状态逐字比较，记录一致、矛盾或未载明。
2. 把待审核写成已生效。输入为原文“集单结果状态为待审核”，比较拟稿句是否出现审核通过、已生效等表述，出现即属未获支持。可执行检查：列出拟稿句中全部状态词，逐一回到原文同字段核对，缺失即记录证据缺口。
3. 跨向量模型库共同关联。输入为两个知识库标识，比较其向量模型标识是否一致，不一致即排除，不执行跨模型检索来比较漏召回。可执行检查：记录两库模型标识与排除动作，实际观察到的召回差异另行记录。

## 怎么确认配好了

1. 用假设样本原文“预售商品表 V3 于本场截单前一日 18:00 更新，集单结果状态为待审核，采购计划尚未生成”作为检索输入。比较返回内容是否包含该状态字段，若返回待审核且拟稿句写已审核通过，则矛盾判定成立。预期是识别矛盾，不声称已实测。
2. 用拟稿句“集单结果已审核通过，采购计划已下发”作为核对对象。比较其中每个状态词与原文同字段取值，原文未载明的部分记为未获支持或待核实。预期是给出缺口清单，不补造授权或生效条款。
3. 用纸面输入空数组核对下游设计。比较节点输出引用长度为 0 时下游链路是否仍走通，以及下游是否把空结果当作无授权结论。预期是确认空结果承接方式，不声称虚构规则检索一定返回空数组。
