# 社区团购预售集单的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

预售集单按场次推进，先收订单再组织采购履约，与团长关系维护属于不同工作。日常材料包括预售商品表、集单结果、采购计划、截单通知，更新频率为日或每场。运营交接时，这些材料分别对应不同授权状态：商品表与集单结果记录已收订单的范围，采购计划记录下采安排，截单通知记录截单动作。交接请求能否执行，取决于请求所指对象是否处于对应授权边界内。检索或表单只呈现数据，不构成授权执行。

## 这些特征在「部署与升级」这一环带来什么约束

部署与升级需先核对当前版本与目标版本及对应升级说明，不从旧配置名称推断现行行为。App 与 Admin 共用服务端配置，升级时需同时核对 fastgpt-app 与 fastgpt-pro 镜像 tag。AI Proxy 为必需依赖，AIPROXY_API_ENDPOINT 与 AIPROXY_API_TOKEN 缺一即启动校验失败。升级脚本为手动触发，不阻塞服务启动，执行前需确认旧版本实例已完全停止、旧任务租约过期。

假设演练样本：某平台计划将预售集单系统从旧版本升级至 v4.17.2，运营交接材料原文为三句。第一句：本场预售商品表列明商品与截单时间，截单时间已过。第二句：集单结果记录本场已收订单数量，状态为已截单。第三句：采购计划记录下采安排，状态为待下采。待判定拟稿句：本场集单结果已确认，采购计划可执行下采。判定需比较拟稿句与三句原文的主体、对象、状态。原文未载明采购计划已获授权执行下采，拟稿句超出原文范围。

## 配置怎么定

| 配置项 | 本次假设试验起点 | 核对方式 |
| --- | --- | --- |
| 镜像 tag | fastgpt-app 与 fastgpt-pro 均为 v4.17.2 | 对照升级说明所列版本号 |
| AIPROXY_API_ENDPOINT | 假设填 `http://aiproxy:3000` | 检查是否为根地址，未附加 `/v1` |
| AIPROXY_API_TOKEN | 假设填入非空值 | 检查与服务端配置一致且非空 |
| 升级脚本执行条件 | 假设旧实例已停止、租约过期 | 核对实例状态与租约记录 |
| 升级后验证样本 | 假设沿用同一预售商品表样本 | 用相同样本复核导入与调用 |

AIPROXY_API_ENDPOINT 起点选根地址，因文档说明不要附加 `/v1`，比较对象为文档示例格式。AIPROXY_API_TOKEN 起点选非空值，因文档说明不能为空，比较对象为服务端配置。升级脚本执行条件起点选已停止，因文档要求确认旧实例停止，比较对象为实际实例状态。

## 容易做错的三处

1. 把检索结果当作授权执行。输入为一次检索请求，比较对象为授权边界记录，观察结果为检索返回数据但无授权记录，此时不能执行采购计划下采。
2. 把表单提交当作审批完成。输入为一份采购计划表单，比较对象为审批状态字段，观察结果为表单已提交但状态为待审核，此时不能认定已获授权。
3. 把旧配置名称当作现行行为。输入为旧版 config.json 字段，比较对象为当前环境变量说明，观察结果为字段名不一致，此时不能按旧名称推断行为。

## 怎么确认配好了

1. 输入假设样本三句原文与拟稿句，比较拟稿句是否超出原文范围，观察结果为拟稿句含原文未载明的授权，判定为未获支持。
2. 输入 AIPROXY_API_ENDPOINT 假设值，比较是否附加 `/v1`，观察结果为未附加且与文档示例格式一致，判定为符合。
3. 输入升级脚本执行条件假设值，比较旧实例状态与租约记录，观察结果为实例已停止且租约过期，判定为可执行。若实例未停止或租约未过期，记录为待核实，不执行脚本。

检索检查观察返回结果与授权记录是否分离，失败分支为检索返回数据但无授权记录，此时不执行下游动作。空结果承接可用明确纸面输入 `[]` 核对下游设计，不声称虚构规则检索一定返回 `[]`。跨模型不可共同关联，先核标识并排除不符合者。
