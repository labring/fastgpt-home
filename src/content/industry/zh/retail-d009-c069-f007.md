# 经销商返利核算的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
经销商返利核算发生在销售完成之后，主要处理政策口径与财务冲抵。日常材料包括返利政策、销量达成表、对账单和红字发票，数据来源涉及 ERP 销售、经销商回款、合同台账与财务系统。核算结果直接影响收入确认，口径分歧会形成返利争议。对话日志与审计在本品类中的价值，是把每一次关于达成口径、退货扣除、开票冲抵的问答与操作请求留下可追溯记录，供运营交接时核对授权状态。

## 这些特征在「对话日志与审计」这一环带来什么约束
返利核算的问答常跨月、跨季，同一经销商在同一期间可能有多轮沟通。对话接口以 chatId 标识一个会话，以 dataId 标识会话下的一条对话。运营交接时，需要按 chatId 核对目标对话与对应业务记录，避免把不同入口的会话混算。会话列表接口的 source=api 只获取通过 API 创建的会话，页面会话不在其中，交接材料若来自页面入口，需另行确认来源。

需要运行详情时，按官方契约设置 detail。detail=true 且 stream=false 时，中间值保存在 responseData；detail=true 且 stream=true 时，通过 event 区分，节点完整响应在 flowResponses。字段含义以接口实际返回为准，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能与正式调用不同，需分别核对输入、历史与返回内容。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某品牌财务在季度返利交接中持有一份材料，原文为“2025 年第三季度经销商 A 返利政策：达成率按回款口径计算，退货金额从达成基数中扣除。”另有一条待判定的拟稿句：“经销商 A 第三季度返利已按回款口径核算完成，可交接。”材料只载明政策口径，未载明核算是否完成、由谁完成、是否经过审批。该拟稿句把政策口径写成核算完成，属于未获支持的表述，应退回补充完成状态与审批记录。

## 配置怎么定
下表围绕上述样本，列出与本功能、本任务相关的官方已说明设置或实施核对项。数值为本次假设试验起点，仅为便于比较，不代表官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较方法 |
| --- | --- | --- |
| chatId | 交接样本专用字符串 | 用于定位该轮返利问答，与业务记录一一对应后再比较 |
| dataId | 样本对话记录 ID | 定位单条对话，核对返回内容是否与材料一致 |
| detail | true | 需查看 responseData 或 flowResponses 中的节点详情 |
| stream | false | 便于一次性读取 responseData，减少事件拼接 |
| source | api | 只取 API 创建的会话，核对交接材料来源是否一致 |
| loadCustomFeedbacks | true | 读取自定义反馈，核对交接期间是否有标注 |

## 容易做错的三处
1. 把政策口径当成核算完成。样本材料只写“达成率按回款口径计算”，拟稿句写成“已按回款口径核算完成”。输入是材料原文与拟稿句，比较对象是“口径规定”与“完成状态”，两者不同字段，不构成支持。可观察结果是拟稿句缺少完成主体与审批记录。
2. 把不同入口的会话合并统计。输入是页面会话与 API 会话，比较对象是 source 取值，页面会话不在 source=api 的返回中。可观察结果是会话列表条数与实际交接范围不一致。
3. 把日志留存当成合规审计完成。输入是对话记录，比较对象是合规审计所需的完整业务材料。日志只证明问答存在，不证明对账、留存与合规要求已落实。可观察结果是缺少独立审计结论。

## 怎么确认配好了
1. 输入样本材料原文与拟稿句，比较“政策口径”与“核算完成”是否为同一字段，观察拟稿句是否获得材料支持。预期结果是拟稿句被标记为未获支持，需补充完成状态与审批记录。
2. 输入 chatId 与 source=api，比较返回会话列表与交接材料清单，观察两者条目是否一致。预期结果是页面来源会话不出现在列表中，交接范围据此修正。
3. 输入 detail=true 与 stream=false，比较 responseData 中模块返回字段与材料所需字段，观察缺失字段。预期结果是未返回字段记录为证据缺口，不推定已留存。
