# 经销商返利核算的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样
返利核算发生在销售之后，围绕政策口径与财务处理展开。主要资料来自 ERP 销售记录、经销商回款、合同台账与财务系统，日常文档包括返利政策、销量达成表、对账单与红字发票。资料更新频率为月、季，本页功能不依赖该频率，故不展开同步机制。这些资料在部署与升级环节决定了两件事：第一，版本变更后导入、检索与调用的行为可能改变，需用同一样本复核；第二，运营交接中材料、操作与请求各有授权状态，检索结果或表单填写不能替代授权执行。

## 这些特征在「部署与升级」这一环带来什么约束
升级前需核对当前版本与目标版本及对应升级说明，不从旧配置名称推断现行行为。App 与 Admin 均须设置 `AIPROXY_API_ENDPOINT` 与非空 `AIPROXY_API_TOKEN`，缺少任一项会启动校验失败；旧单模型地址不能替代。按官方部署与升级步骤检查依赖及备份，恢复能力须用自身环境验证。升级后用相同样本复核导入、检索与应用调用，步骤执行完成不构成零中断承诺。

假设演练样本：某品牌财务在升级后交接返利核算运营权限。材料原文为：“2026 年 3 月华东区返利政策适用于一级经销商，达成口径以 ERP 出库数量为准。”“2026 年 3 月对账单显示经销商甲回款状态为已核销，返利金额待财务复核。”“红字发票申请单已提交，状态为待审核。”待判定拟稿句：“经销商甲 2026 年 3 月返利已核定，红字发票已开具。”

## 配置怎么定
下表为本次实施核对项，数值仅为假设试验起点并说明选取理由。

| 配置项 | 假设试验起点 | 选取理由与比较方法 |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | 填 AI Proxy 根地址，不加 `/v1` | 官方说明根地址格式，与旧单模型地址比较，确认未追加对话接口路径 |
| `AIPROXY_API_TOKEN` | 填非空管理员 Token | 官方要求与服务端一致且非空，与 AI Proxy 服务端配置比较 |
| `AGENT_ENGINE` | 保留 `fastAgent` | 官方可选 `fastAgent` 或 `piAgent`，与升级前实际值比较，确认变更意图 |
| `DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED` | 保持 App 与 Admin 一致 | 官方要求两服务配置一致，比较两侧取值 |
| `CHECK_INTERNAL_IP` | 保留 `false` | 官方默认关闭，与部署方是否需降低 SSRF 风险的需求比较 |
| `SYSTEM_MIGRATION_BATCH_SIZE` | 保留 `100` | 官方范围 50～1000，与本次迁移记录量比较后决定是否调整 |

## 容易做错的三处
1. 把“待财务复核”当作已核定。输入为对账单原文“返利金额待财务复核”，比较对象为拟稿句“返利已核定”，可观察结果是两者状态字段不一致，拟稿句未获支持。
2. 把“待审核”当作已开具。输入为红字发票申请单状态“待审核”，比较对象为拟稿句“红字发票已开具”，可观察结果是申请状态与开具事实不匹配，属于未获支持。
3. 用检索结果代替授权执行。输入为检索返回的政策文档片段，比较对象为交接请求中的授权动作，可观察结果是检索仅呈现文本，未产生授权或执行记录，权限状态仍待核实。

## 怎么确认配好了
1. 输入材料原文“2026 年 3 月华东区返利政策适用于一级经销商”，比较对象为拟稿句中的适用主体“经销商甲”，可观察结果是主体层级需另行核实，若原文未载明甲为一级经销商，则该句主体范围未获支持。
2. 输入对账单原文“返利金额待财务复核”，比较对象为拟稿句“返利已核定”，可观察结果是同期间同一字段取值互斥，拟稿句与原文矛盾。
3. 输入红字发票申请单原文“状态为待审核”，比较对象为拟稿句“红字发票已开具”，可观察结果是待审核不等于已开具，拟稿句未获支持。三项均以纸面样本核对，未进行实际部署或业务操作。
