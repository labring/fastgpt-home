# 达人专场带货合作的运营权限与交接管理：权限与数据隔离

## 这个品类的数据长什么样

在达人专场带货合作的运营权限与交接管理中，本页说明FastGPT的权限与数据隔离如何衔接资料。核对资料实际支持的范围及其引用。所用场景为自拟文字测试。

## 这些特征在「权限与数据隔离」这一环带来什么约束

合作协议把最终内容审核责任交给甲方，只说明这份自拟文字中的分工，不能据此判断谁能登录达人账号或修改发布设置。交接应先列清实际账号、团队成员和需访问的协议或直播材料，逐项核读取与操作范围。内容审核责任、平台账号操作和FastGPT资源权限是不同对象，测试记录应能够指出每个身份究竟对哪项资源做了什么。

## 配置怎么定

| 交接需核的行为 | 协议文字的作用 | 验收身份与结果 |
| --- | --- | --- |
| 最终内容审核 | 甲方责任不等于平台登录权 | 核该人员账号及所需阅读资源 |
| 自行发布及确认 | 两句可能约束不同环节 | 请责任人说明各自适用内容 |
| 接手阅读 | 协议和直播资料需要实际授权 | 新身份对同一原文试读 |
| 原身份撤权 | 签字不说明旧访问失效 | 保存旧身份的拒绝或仍可读结果 |
| 外部账号操作 | 达人平台登录或接口条件独立 | 不从FastGPT角色推定发布权限 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `团队角色` | 按实际成员身份核角色。 |
| `资源权限` | 读写与管理范围需按资源核对。 |
| `资料分类` | 分类和标签不能代替授权。 |
| `外部系统权限` | 外部接口鉴权单独验证。 |
| `逐账号验证` | 有权与无权账号访问同一资料。 |

## 容易做错的三处

- 甲方内容审核责任被当作能登录达人账号或改发布设置：核实际平台身份和FastGPT资源操作，业务分工不自动配置技术权限。

- 达人自行发布与甲方确认被直接判权限冲突：保留各自内容及环节，查适用范围和责任人说明，访问测试不能替业务裁决。

- 审核方名称代替新旧身份移交测试：用实际账号验证新成员所需读取和旧成员撤权，保留拒绝及仍可读结果，外部平台鉴权另核。

## 怎么确认配好了

交接可按三种实际行为分别核对：取得协议用于阅读、记录内容确认、操作外部发布账号。这些是提出的阅读核对事项，不是软件新增角色。协议把审核责任给甲方，不说明确认记录由谁维护，更不说明达人平台登录已移交。应由责任人提供对应账号、材料与允许操作，再用新旧身份试读同一协议和直播资料，保留可读及拒绝结果。只移交阅读、不移交发布的安排若未确认，就继续待核；不能由模型复述审核方替任何人完成这项决定。
