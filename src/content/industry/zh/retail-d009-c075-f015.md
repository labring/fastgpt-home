# 达人专场带货合作的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样

达人专场带货合作依赖外部达人履约与佣金结算，日常材料包括达人合作协议、佣金设置单、样品寄送单、直播战报。这些材料在运营交接时往往处于不同状态：协议可能已签署但合作尚未达成，佣金设置单可能是待审核版本，样品寄送单可能只记录寄出，直播战报可能只是阶段数据。知识库检索与召回环节需要把材料原文、交接请求和授权状态并列核对，不能把检索命中当成授权已生效。

## 这些特征在「知识库检索与召回」这一环带来什么约束

知识库搜索节点可关联一个或多个使用相同向量模型的知识库。跨不同向量模型的库不可共同关联，应先核标识并排除不符合者，记录实际观察结果。

搜索模式按测试问题比较语义、全文与混合检索，不预设一种模式适合全部资料。语义检索依赖向量距离，全文检索依赖关键词命中，混合检索通过 RRF 融合多路结果。RRF 是融合过程，不写成开启开关。最低相关度仅在语义检索或使用结果重排时生效，是过滤阈值，不负责权限或实体隔离。引用上限以 token 为单位，需用长短不同的实际资料测试内容完整性。

问题优化用于指代消除和问题扩展，会增加一次模型调用。图片检索须有相应图像输入及模型能力，重排须具备模型且按设置启用。节点输出引用内容以数组格式返回，长度可以为 0，空结果链路仍走通。

假设演练样本：材料原文为“甲方与乙方于2025年3月1日签署《达人专场合作协议》，约定2025年3月15日专场，佣金比例20%。乙方尚未确认排期。”待判定拟稿句为“乙方已确认2025年3月15日专场排期，佣金按20%执行。”核对时比较签署日期、专场日期、佣金比例和排期确认状态。原文只载明签署和约定，未载明排期确认，拟稿句的“已确认”未获支持。

## 配置怎么定

| 配置项 | 本页相关设置或核对项 | 与样本的关联 |
| --- | --- | --- |
| 关联的知识库 | 选择使用相同向量模型的一个或多个库 | 先核协议、佣金、样品、战报是否同模型 |
| 搜索模式 | 按问题类型比较语义、全文、混合检索 | 日期和比例适合全文或混合检索 |
| 最低相关度 | 仅在语义检索或结果重排时生效 | 先标注相关与无关样本再调阈值 |
| 引用上限 | 单位为 token | 用长短不同的材料测试内容完整性 |
| 问题优化 | 用于指代消除和问题扩展 | 比较原问题与优化后问题的主体 |
| 结果重排 | 需具备模型并按设置启用 | 候选较多时二次排序 |

假设本次试验起点将最低相关度设为0.5，理由是该值介于0与1之间，便于同时观察相关与无关样本的过滤差异；比较方法为分别输入已标注的相关样本和无关样本，观察哪些结果被保留。该值不是官方默认值。

## 容易做错的三处

1. 把检索命中当成授权生效。输入为拟稿句“乙方已确认排期”，比较对象为协议原文的排期确认状态，若原文未载明确认，则拟稿句未获支持。
2. 把待审核当成缺少操作权限。输入为佣金设置单的待审核状态，比较对象为审核完成记录，若只有待审核标记，则审核结果待核实。
3. 跨不同向量模型的库共同关联。输入为两个库的向量模型标识，比较对象为是否一致，若不一致则排除，不执行跨模型检索。

## 怎么确认配好了

1. 输入假设样本的材料原文和拟稿句，比较拟稿句的“已确认”与原文的排期确认状态，若原文未载明确认，则判定未获支持，记录证据缺口。
2. 输入空数组[]作为引用内容，比较下游设计是否承接长度0的输出，若下游能处理空数组，则空结果链路走通。
3. 输入两个库的向量模型标识，比较标识是否一致，若不一致则排除不符合者并记录实际观察，不编造运行结果。
