# 达人佣金结算与扣佣的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样
佣金结算发生在成交之后，核对对象集中在有效推广订单、退款扣佣明细、结算账单与发票。财务结算、精选联盟运营、达人商务三类角色共享这些材料，周与月的更新节奏让交接窗口与账单周期重叠。本页只处理运营权限与交接管理下的对话日志与审计：交接时哪些材料、操作与请求处于何种授权状态，日志与接口返回能核对到什么程度。对话日志本身不构成授权凭证，检索命中不表示调用方获得结算或扣佣的操作权限。

## 这些特征在「对话日志与审计」这一环带来什么约束
对话身份以 chatId 界定，同一应用下不同 chatId 属于不同会话，核对目标对话与业务记录时不能把不同入口的会话混算。需要运行详情时按官方契约设置 detail=true，在 responseData 中查看模块状态与完整结果；未在该结构中返回的业务数据不能推定已完整留存。测试模式下的身份字段可能与正式调用不同，输入、历史与返回内容需分别核对。日志存在只说明该次调用被记录，对账、留存与合规审计由完整业务方案另行落实。

假设演练样本：某财务结算人员离职交接，交接材料原文为「结算账单 A-0715，覆盖 7 月 1 日至 7 月 15 日有效推广订单；退款扣佣明细 R-0715，含 3 笔退款对应佣金冲回；发票 I-0715 状态为待开票。以上材料由精选联盟运营在 7 月 16 日移交，接收人尚未在系统内获得该应用的操作权限。」拟稿句为「交接完成，接收人已可执行佣金调整与扣佣确认。」该拟稿句涉及的主体是接收人，对象是佣金调整与扣佣确认，状态为尚未获得操作权限。

## 配置怎么定
下表围绕该样本，列出与本功能、主任务相关的官方已说明设置或实施核对项。数值仅为本次假设试验起点，用于与目标值比较，不代表官方默认。

| 配置项 | 本次假设起点 | 核对方式与理由 |
| --- | --- | --- |
| appId | 样本应用标识 | 与 chatId 组合界定目标会话，确认日志归属同一应用 |
| chatId | 交接对话的会话标识 | 同一 chatId 下取会话，跨 chatId 不合并计算 |
| detail | true | 需要中间值与完整结果时按契约设置，检查 responseData |
| source | api | 获取会话列表时限定来源，避免与页面会话混算 |
| loadCustomFeedbacks | true | 读取自定义反馈，核对对话记录中的反馈字段 |
| pageSize | 10 | 分页读取记录，与 total 比较确认是否取全 |

## 容易做错的三处
1. 把检索命中当作授权。输入为交接对话中检索到结算账单的记录，比较对象是接收人的操作权限状态，可观察结果为检索返回与权限字段分别呈现，权限字段仍为未授予。
2. 把待开票状态当作已开票。输入为发票 I-0715 状态「待开票」，比较对象是拟稿句中「已完成开票」的表述，可观察结果为两者不一致，该表述未获支持。
3. 把测试模式身份字段用于正式调用核对。输入为测试模式下的调用记录，比较对象是正式调用所需的 appId 与 chatId，可观察结果为身份字段不同，需分别核对后再判断归属。

## 怎么确认配好了
1. 输入假设样本中的交接材料原文与拟稿句，比较拟稿句所述权限状态与原文「尚未获得操作权限」，可观察结果为拟稿句与原文不一致，判定为未获支持。
2. 输入交接对话的 chatId 与另一会话的 chatId，比较两次取回的记录，可观察结果为记录分属不同会话，不合并计算。
3. 输入 detail=true 的一次调用，比较 responseData 中是否出现目标模块的运行详情，可观察结果为出现则记录该次运行详情，未出现则记录为未返回，不推定已留存。
