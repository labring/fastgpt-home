# 达人佣金结算与扣佣的运营权限与交接管理：知识库检索与召回

## 这个品类的数据长什么样
佣金结算发生在成交之后，核对对象是有效推广订单与售后扣佣，资料以周、月为更新节奏。佣金设置记录、结算账单、退款扣佣明细、发票四类文档共同构成检索库，字段口径分散在精选联盟后台、订单售后数据、财务系统与达人合同之间。检索环节只负责把相关段落召回给模型，授权判断与业务执行由下游承接。资料更新频率仅说明文档产生节奏，检索配置本身不随之改变。

## 这些特征在「知识库检索与召回」这一环带来什么约束
知识库搜索节点可关联一个或多个使用相同向量模型的知识库，跨向量模型的库不可共同关联，需先核对向量模型标识并排除不符者。语义检索、全文检索、混合检索按测试问题比较，不预设一种模式适合全部资料。引用上限单位为 token，最低相关度仅在语义检索或使用结果重排时生效。问题优化用于指代消除和问题扩展，会额外调用模型。混合检索通过 RRF 融合多路结果，RRF 是融合过程，不是可开启的开关。图片检索需要图像输入及模型能力，重排需要重排模型且按设置启用，文档列出的可选路径不代表每次请求全部执行。引用内容以数组输出，长度可以为 0，空结果链路仍走通。相似度与相关度是排序与过滤依据，不承担权限或实体隔离。

假设演练样本：材料原文为“达人甲 2025 年 3 月结算账单显示有效订单佣金 8000 元，退款扣佣 1200 元，实结 6800 元；同月佣金设置记录写明食品类目佣金率 15%；发票栏备注‘待达人确认后开具’。”待判定拟稿句为“达人甲 3 月佣金已结清并完成开票。”核对时同主体、同期间、同字段比较：账单实结字段与拟稿句“已结清”是否一致，发票备注状态与“完成开票”是否一致。备注为待确认状态，开票事实未获支持，拟稿句应保留证据缺口。

## 配置怎么定
| 配置项 | 本次假设试验起点 | 选择理由与比较方法 |
| --- | --- | --- |
| 关联知识库 | 佣金设置记录、结算账单、退款扣佣明细、发票四个库 | 四库使用同一向量模型标识，逐一核对后关联 |
| 搜索模式 | 先以混合检索测试 | 与语义检索、全文检索分别比较同一测试问题的召回内容 |
| 引用上限 | 假设起点 3000 token | 用长短不同的账单与明细段落测试内容是否完整，再与更大值比较 |
| 最低相关度 | 假设起点 0.3 | 先标注相关与无关样本，再与更高阈值比较过滤效果 |
| 问题优化 | 多轮追问与短问题场景开启 | 比较原问题与优化后问题，核对主体是否被改错 |
| 结果重排 | 按设置启用并比较得分 | 重排得分为 0-1，与向量得分比较后再决定过滤 |

以上数值为本次假设试验起点，不属官方默认值。

## 容易做错的三处
1. 把检索命中当作授权。输入为“达人甲 3 月佣金已结清并完成开票”的拟稿句，检索可能召回结算账单段落，比较时须核对发票备注状态；召回相关段落不表示开票已执行，待确认状态仍属未获支持。
2. 把最低相关度当作权限或实体过滤。输入为同一测试问题，比较不同阈值下的召回内容；相关度只影响排序与过滤，不排除无关业务或未授权记录，授权判断需下游实现。
3. 把待审核请求当作已批准操作。输入为交接请求中“申请开通结算账单导出权限”一项，比较请求状态字段；待审核不证明缺少操作权限，也不构成批准，签署、合作达成、合同生效是三个不同事实。

## 怎么确认配好了
1. 输入假设样本原文与拟稿句，比较账单实结字段与“已结清”、发票备注与“完成开票”；拟稿句保留待核实表述、不写成确定结论时满足条件。
2. 输入同一测试问题分别走语义检索与全文检索，比较召回内容；编号、专有名词类问题在全文检索下命中、自然语言问题在语义检索下命中时满足条件，未命中则记录观察。
3. 输入明确的纸面空结果 []，核对下游节点是否正常承接；引用数组长度为 0 且链路走通时满足条件，不声称虚构规则检索必然返回空数组。跨向量模型的库先核标识并排除，不执行跨模型检索比较。
