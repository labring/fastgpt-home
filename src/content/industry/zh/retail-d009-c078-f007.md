# 连锁总部选址开店的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

选址开店发生在门店营业前，核心是租赁与工程交付，日常材料包括选址评估表、租赁意向书、装修预算与开业排期。这些材料由总部拓展、区域开发与工程经理在不同阶段填写与流转，更新频率为不定期、每店一次。

对话日志与审计在此环节的作用，是把与选址测算、条款沟通、节点协调相关的会话内容按应用、会话、对话三层标识留存，供交接时核对。材料本身的状态（意向、待审、已签）不因日志存在而改变。

## 这些特征在「对话日志与审计」这一环带来什么约束

会话标识决定日志归属。chatId 指一个应用下某一个会话的 ID，dataId 指一个会话下某一个对话的 ID，两者与 appId 共同定位记录。运营交接时，材料、操作与请求处于何种授权状态，需要按这三层标识分别核对，检索结果与表单填写都不构成授权或执行。

需要完整运行过程时，按官方契约设置 detail 并检查 responseData；detail 为真时，模块状态与完整结果保存在 responseData 中，流式模式下通过 event 区分。日志中未返回的业务字段不能推定已完整留存，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本（纸面核对，未实际运行）：某连锁总部拓展部拟将一份选址评估表从区域开发移交工程经理。材料原文写为：「本表对象为XX路门店选址评估，编制阶段为意向洽谈，授权范围为区域开发内部测算，尚未提交租赁意向书。」拟判定句为：「该选址评估已完成交接，工程可按此表安排装修排期。」

## 配置怎么定

下表围绕上述样本，列出与本功能及主任务相关的官方已说明设置或实施核对项。数值仅为本次假设试验起点，用于说明选择理由与比较对象，不代表官方默认值。

| 配置项 | 本次假设起点 | 选择理由与比较对象 |
| --- | --- | --- |
| appId | 样本应用标识 | 与 chatId、dataId 共同定位日志，核对是否为同一应用 |
| chatId | 样本会话标识 | 长度小于 250，核对会话是否唯一且属同一入口 |
| dataId | 样本对话标识 | 核对对话是否属该会话，避免跨会话混算 |
| detail | 设为真 | 需要运行详情时启用，与不返回 responseData 的情形比较 |
| source | api | 获取 API 创建的会话，与页面会话分开核对 |
| loadCustomFeedbacks | 启用 | 读取自定义反馈，与不读取时返回内容比较 |

## 容易做错的三处

1. 把检索命中当作权限。样本中评估表处于意向洽谈阶段，检索到该表不表示区域开发已获授权对外提交意向书。应比较材料原文的授权范围与拟执行动作，观察两者是否一致。
2. 把会话标识混用。将不同 chatId 或不同 dataId 的记录合并统计，会使交接清单包含非本会话内容。应逐条核对 appId、chatId、dataId 三层标识，观察归属是否一致。
3. 把表单填写当作业务完成。样本拟判定句称已完成交接，但材料原文只写编制阶段为意向洽谈。应比较原文状态与拟稿结论，观察是否存在未载明的签署或生效证据。

## 怎么确认配好了

以下核对均使用前述假设样本，预期为纸面判断，未实际执行。

1. 输入样本材料原文与拟判定句，比较「意向洽谈、尚未提交租赁意向书」与「已完成交接、可安排装修排期」两处表述，观察结论是否超出原文状态。若超出，则该句不获支持。
2. 输入样本的 appId、chatId、dataId，比较三者是否指向同一应用、同一会话、同一对话，观察是否存在跨会话或跨应用混算。若不一致，则记录归属待核实。
3. 输入 detail 设为真的请求与设为假的请求，比较返回中是否出现 responseData 及模块状态，观察运行详情是否可得。若未出现，则运行详情缺失，保留为证据缺口。

以上核对不声称已实测，不产生审批、交接或装修排期的业务结果。
