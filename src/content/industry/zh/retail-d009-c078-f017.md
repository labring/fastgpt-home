# 连锁总部选址开店的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

在连锁总部选址开店的运营权限与交接管理中，本页说明FastGPT的部署与升级如何衔接资料。交接选址问答的版本、资料恢复和账号范围，确保租赁意向与未测空间没有被升级过程改写。所用场景为自拟文字测试。

## 这些特征在「部署与升级」这一环带来什么约束

选址问答交接可拟踏勘便笺“前场已看，后场测量另排”，房东邮件仅表示愿继续讨论，尚无签署或开业记录。升级前记录应用引用的便笺、地址及版本，升级后用相同问题核资料是否恢复并被采用。若新页面能打开但只取回前场文字，仍不能回答后场面积；邮件可读也不说明租约成立。图片或平面图路径需要对应输入测试，本题文字样本不验证实际图纸完整读取。所用场景不涉及真实租赁、费用或营业批准。

## 配置怎么定

| 选址升级交接 | 纸面资料 | 核对动作 |
| --- | --- | --- |
| 空间范围 | 前场已看后场另量 | 原句及引用保留 |
| 地点身份 | 本址与旧候选点 | 核地址和版本 |
| 恢复层次 | 备份、原文、应用引用 | 各留实际证据 |
| 接入配置 | 服务根地址与两端Token | 不代租赁授权 |
| 测试边界 | 文字样本 | 图纸读取另验 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `部署版本` | 先核当前及目标版本说明。 |
| `AIPROXY_API_ENDPOINT` | 环境变量采用服务根地址。 |
| `AIPROXY_API_TOKEN` | 两端Token需一致且非空。 |
| `依赖与备份核对` | 备份生成后仍需实测恢复内容。 |
| `升级后验证` | 复用同一组资料验证导入及调用。 |

## 容易做错的三处

- 升级后回答把前场观察扩成全址已测时，对照原便笺、恢复原文与实际请求，核后场另排条件是否遗漏。

- 恢复出旧候选点资料并用于当前地址时，核地址、空间范围及版本；文件名称和更新时间不能单独证明对应同一地点。

- 管理员连接可用被写成交接人员均可读租赁附件时，核团队成员、资源授权和实际账号返回，技术依赖与业务访问分别验证。

## 怎么确认配好了

验收先核当前与目标版本及官方升级说明，再保存适用于本次部署的备份与依赖记录。恢复后分别问看过哪处、哪个区域待测、房东表示什么，并将实际引用与原句比较。若更换服务配置，核AI Proxy服务根地址和两端管理员Token，接入参数不代替租赁资料授权。备份文件生成、资料实际恢复及应用能引用是不同证据；记录测试结果，不以服务启动承诺选址工作未受影响。
