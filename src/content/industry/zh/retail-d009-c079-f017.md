# 连锁统采统配的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

在连锁统采统配的运营权限与交接管理中，本页说明FastGPT的部署与升级如何衔接资料。在统采问答升级交接中复核单位关系、拆箱缺项与实际收货，避免恢复记录被当成配货结果。所用场景为自拟文字测试。

## 这些特征在「部署与升级」这一环带来什么约束

统采交接练习可拟需求单“门店按件提出需求，仓内按箱备货，拆箱规则待核”，配送说明还没有本轮门店接收记录。升级验收应保存这两份文字及原有引用，重建服务后仍能分清请求单位和备货单位。箱装目录存在不说明可以拆零，恢复到一张配送计划也不证明门店收到货。原文存储、向量检索和应用调用涉及不同环节，某一服务连接正常不能替其他环节给出恢复结论。此处没有真实库存或可执行供货安排。

## 配置怎么定

| 统采升级核对 | 固定练习输入 | 验证线索 |
| --- | --- | --- |
| 单位关系 | 按件需求与按箱备货 | 不补拆零换算 |
| 缺项 | 拆箱规则待核 | 恢复及引用均保留 |
| 配送状态 | 计划无本轮收货 | 门店批次与接收分别核 |
| 服务层次 | 原数据、检索、应用 | 各验真实样本 |
| 依赖认证 | 根地址与两端Token | 应用凭证另查 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `部署版本` | 先核当前及目标版本说明。 |
| `AIPROXY_API_ENDPOINT` | 环境变量采用服务根地址。 |
| `AIPROXY_API_TOKEN` | 两端Token需一致且非空。 |
| `依赖与备份核对` | 备份生成后仍需实测恢复内容。 |
| `升级后验证` | 复用同一组资料验证导入及调用。 |

## 容易做错的三处

- 恢复后丢失拆箱待核句却答复能按件发放时，核原文件、恢复文本及引用来源，定位限制在恢复还是检索时消失。

- 旧配送单被当成本轮各店已收时，核门店、批次与实际接收事件，不用计划或单据同名补收货。

- 向量服务可用被写成全部业务资料已恢复时，分别核原数据存储、检索返回和应用样本，检查每层实际内容，不以进程存活代证。

## 怎么确认配好了

验收先按当前与目标版本核升级说明及依赖，再保存备份并测试恢复内容。用同组问题询问按什么单位提出需求、哪些规则仍缺、哪家门店有接收依据，比较原数据身份和实际引用。调整AI Proxy连接时核服务根地址及两端管理员认证，应用调用凭证另查。恢复验证只覆盖实际测试的样本与环境，不承诺无中断，也不能由升级步骤完成推配送完成。
