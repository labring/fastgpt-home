# 连锁门店价格与陈列稽核的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

价格与陈列稽核发生在日常经营期，数据按周或按月更新，来源包括督导系统、POS 价格表、门店摄像与总部促销档期。这一节奏决定对话日志与审计处理的是跨周、跨月累积的会话记录。日常文档为巡店照片、价签清单、陈列标准与整改通知，分别对应不同主体与不同阶段。稽核会话中出现的价签照片是否属于本次巡店范围，需要结合 chatId 与业务记录逐条核对。运营权限与交接管理的要点在于，督导、店长、运营部在会话中提交的材料与请求各自处于何种状态，检索命中或表单填写都不构成授权。

## 这些特征在「对话日志与审计」这一环带来什么约束

对话接口文档说明，chatId 为非空字符串时，系统从数据库取会话，并以 messages 数组最后一个内容作为用户问题，其余 message 被忽略。同一 chatId 下的多次调用共享上下文，审计时须确认目标对话与业务记录一致，不能把不同入口的会话混算。需要运行详情时，按官方契约设置 detail，非 stream 模式下结果保存在 responseData 中；responseData 内不同模块字段随版本可能有差异，未返回的业务数据不能推定已完整留存。测试模式的身份字段可能不同，输入、历史与返回内容应分别核对。日志存在不等于完成合规审计，对账、留存与合规要求由完整业务方案另行落实。

假设演练样本：某连锁品牌区域督导在 2026 年 3 月 10 日至 3 月 16 日巡店期间，通过某应用提交会话，chatId 记为 store-0310-A，messages 最后一条为“请确认 A 店 3 月 12 日价签整改是否已闭环”。随附材料原文两句：“整改通知单编号 A-0312，签发日期 2026 年 3 月 12 日，状态：待门店确认。”“门店回传照片时间 2026 年 3 月 14 日，照片内容为货架价签。”待判定拟稿句：“A 店 3 月 12 日价签整改已闭环。”该拟稿句涉及主体 A 店、对象价签整改、状态闭环，材料仅显示待门店确认与回传照片，未载明确认完成或复核通过。

## 配置怎么定

| 配置或核对项 | 本页相关设置 | 核对要点 |
| --- | --- | --- |
| chatId | 非空字符串，长度小于 250 | 与业务记录中的巡店批次对应，确认同一会话未被其他入口复用 |
| detail | 按官方契约设为 true 或 false | 需要运行详情时设 true，非 stream 模式检查 responseData |
| messages | 最后一条作为用户问题 | 其余 message 被忽略，审计时以最后一条为准 |
| source | 获取会话列表时传 api | 只取 API 创建的会话，页面会话不在此列 |
| 假设试验起点 | 本次样本 chatId 长度记为 12 | 仅为演练起点，与 250 上限比较判断是否越界 |

## 容易做错的三处

1. 把检索命中当作授权。输入：chatId store-0310-A 的会话中检索到整改通知单 A-0312。比较：该单状态字段为“待门店确认”。观察结果：检索命中只说明记录存在，不表示门店已确认或整改已闭环。
2. 把回传照片当作闭环证据。输入：门店 3 月 14 日回传的货架价签照片。比较：材料未载明复核通过或确认完成字段。观察结果：照片属于相关阶段证据，闭环状态仍未获支持。
3. 把不同入口会话混算。输入：同一 appId 下页面会话与 API 会话。比较：获取会话列表时 source 传 api，页面会话不返回。观察结果：若未区分来源，会把页面会话计入 API 会话统计，导致主体与期间错配。

## 怎么确认配好了

1. 输入：假设样本中 chatId store-0310-A 与 messages 最后一条“请确认 A 店 3 月 12 日价签整改是否已闭环”。比较：该 chatId 是否与巡店批次记录一一对应，长度是否小于 250。观察结果：对应且未越界时满足条件，否则记录缺口。
2. 输入：拟稿句“A 店 3 月 12 日价签整改已闭环”。比较：材料原文中整改通知单状态为“待门店确认”，且无确认完成字段。观察结果：拟稿句与材料同主体、同期间、同字段，取值互斥，判定为未获支持。
3. 输入：会话列表请求中 source 传 api。比较：返回列表是否只含 API 创建的会话。观察结果：页面会话未出现在列表中时满足条件；若出现，记录来源字段核对结果。
