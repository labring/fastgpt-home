# 连锁门店价格与陈列稽核的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

在连锁门店价格与陈列稽核的运营权限与交接管理中，本页说明FastGPT的部署与升级如何衔接资料。价签稽核升级保留门店轮次与整改接收状态，图片文件和文字引用分测。所用场景为自拟文字测试。

## 这些特征在「部署与升级」这一环带来什么约束

假设巡店照片说明只记已拍摄，价签清单待与POS复核，陈列标准为总部要求，整改通知尚未收回执。升级交接应用此自拟文字核状态是否恢复，不从照片存在宣布价签已一致。这里没有实际照片识别、价格数字或整改完成证据，标准与现场执行必须分开。

## 配置怎么定

| 价签升级交接 | 假设材料 | 恢复核法 |
| --- | --- | --- |
| 照片 | 已拍摄说明 | 不当比价结果 |
| 清单 | POS待核 | 保留阶段 |
| 标准 | 总部要求 | 不称现场达标 |
| 通知 | 回执未到 | 不称已整改 |
| 附件 | 图文分路径 | 实测恢复与访问 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `部署版本` | 先核当前及目标版本说明。 |
| `AIPROXY_API_ENDPOINT` | 环境变量采用服务根地址。 |
| `AIPROXY_API_TOKEN` | 两端Token需一致且非空。 |
| `依赖与备份核对` | 备份生成后仍需实测恢复内容。 |
| `升级后验证` | 复用同一组资料验证导入及调用。 |

## 容易做错的三处

- 恢复后总部标准被写成本店已达标时，对原文用途及现场核查证据，不能把规范恢复当执行恢复。

- 上一轮照片说明被引入本轮整改时，对门店、轮次与拍摄对象，旧文件名不代本轮身份。

- 应用能响应而原图缺失时，分核文件存储、文本检索与模型路径，文字可读不证明图片已恢复。

## 怎么确认配好了

按v4.17.2及目标部署资料记录依赖和备份范围，实际恢复后核清单、通知与附件。升级前后同题问比价阶段与整改回执，保存真实请求和结果；按实际成员核访问。连接成功和备份文件存在都不足以放行，不承诺零中断，真实巡店和价格纠正另行执行。
