# 连锁门店闭店清算的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

在连锁门店闭店清算的运营权限与交接管理中，本页说明FastGPT的部署与升级如何衔接资料。闭店系统升级核清退、解约与资产记录各自阶段，不将关闭应用当闭店清算。所用场景为自拟文字测试。

## 这些特征在「部署与升级」这一环带来什么约束

假设闭店审批尚待补资料，库存清退单仅拟移交，租约解除协议未签，资产盘点表待双方核。升级或迁移这些材料时，应用停止、恢复和门店清算是不同事件。自拟样本不给真实资产额、解约日或批准结果；目录完整也不证明清算手续齐全。

## 配置怎么定

| 闭店资料迁移 | 假设状态 | 检查 |
| --- | --- | --- |
| 审批 | 待补资料 | 不称已批准 |
| 清退 | 拟移交 | 不称已清空 |
| 解约 | 协议未签 | 不补解除日 |
| 资产 | 双方待核 | 不补余额 |
| 备份 | 配置原文索引 | 实际恢复分查 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `部署版本` | 先核当前及目标版本说明。 |
| `AIPROXY_API_ENDPOINT` | 环境变量采用服务根地址。 |
| `AIPROXY_API_TOKEN` | 两端Token需一致且非空。 |
| `依赖与备份核对` | 备份生成后仍需实测恢复内容。 |
| `升级后验证` | 复用同一组资料验证导入及调用。 |

## 容易做错的三处

- 恢复后的目录把未签解约改成已解除时，对协议原句和签署记录，不用文件迁移完成替代业务完成。

- 其他门店资产盘点被答成本店交接时，对门店主体与盘点对象，不能用归档同名合并。

- 只保存应用配置便声称可恢复全清算资料时，核数据库、原文附件与检索实际覆盖，需实际恢复结果。

## 怎么确认配好了

留存当前版本、依赖和各类资料身份后执行备份测试，按实装确认恢复途径；此处只提出核法，不声称已备份。前后固定问题核谁批准、哪份已签、哪些待核，另检查交接成员权限。回退也需核内容可用，不承诺无损迁移。真实闭店与租约处置由授权责任人处理。
