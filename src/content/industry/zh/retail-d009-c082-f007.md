# 逆向退货入仓质检的运营权限与交接管理：对话日志与审计

## 这个品类的数据长什么样

逆向退货入仓质检处理退回包裹与商品等级，与仓内新订单出库不同。数据来自WMS退货模块、平台售后、承运商退件与质检台，日常文档为退货入库单、质检照片、等级判定表与重售上架单。

## 这些特征在「对话日志与审计」这一环带来什么约束

chatId 用于区分会话。传入非空字符串时，系统从数据库取该会话，以 messages 数组最后一个内容作为用户问题，其余 message 被忽略。交接时只复制对话文本而未记录 chatId，两份记录无法确认属于同一会话。responseChatItemId 在当前 chatId 下需唯一，该值会存入数据库，可作为单条响应的定位标识。

需要运行详情时按官方契约设置 detail。detail=true 且 stream=false 时，responseData 保存模块状态与完整结果；detail=true 且 stream=true 时通过 event 区分，flowResponses 提供节点完整响应。detail=false 时不返回中间值。日志中未出现的字段属于未提供，不能据日志推定业务数据已完整留存。

假设演练样本

材料原文一（退货入库单摘要，纸面）：单号 RT-2024-0871，商品为某型号保温杯，数量 12 件，退件日期 2024-10-13，质检台判定外观等级 B，判定人签名栏空白。

材料原文二（质检照片说明，纸面）：照片 3 张，对应单号 RT-2024-0871，拍摄时间 2024-10-13，说明栏写“杯身有划痕，杯盖完好”。

待判定拟稿句：依据上述材料，RT-2024-0871 已通过质检并批准重售上架。

该拟稿句将“等级判定为 B”和“照片说明划痕”写成“通过质检并批准重售上架”。材料中判定人签名栏空白，重售上架单未出现，授权边界未载明，该结论属于未获支持。

## 配置怎么定

| 配置项 | 本页用途 | 核对方式 |
| --- | --- | --- |
| chatId | 区分质检会话，关联退货入库单编号 | 同一单号在两次交接中 chatId 是否一致 |
| responseChatItemId | 定位单条响应记录 | 当前 chatId 下该值是否唯一 |
| detail | 决定是否返回中间值 | 需要运行详情时设为 true，检查 responseData 或 flowResponses |
| appId | 标识应用，配合密钥使用 | 请求体 appId 与密钥关联应用是否一致 |
| authProxy | 代理团队成员身份 | 由团队所有者开启，代理身份仍需目标应用与会话权限 |
| source | 获取 API 创建的会话 | 列表请求中 source=api，确认不混入页面会话 |

本页假设试验起点：detail 设为 true，理由是本次核对需要 responseData 中的模块状态，比较对象为 detail=false 时同一请求不返回中间值。该起点为本次纸面演练设定，不是官方默认值。

## 容易做错的三处

1. 将日志中质检照片说明当作质检结论。照片说明记“杯身有划痕”，等级判定表记B，二者字段不同。执行检查：取材料原文二与拟稿句，比较“划痕”与“通过质检”是否同一字段同一取值。
2. 将等级判定为B当作授权重售。等级判定表给出B，重售上架单未出现。把B读成“批准重售上架”，属于把等级值当成授权动作。执行检查：取材料原文一与拟稿句，查找重售上架单是否载明批准主体与日期。
3. 将不同chatId的会话记录合并计算。两次交接若chatId不同，对话记录指向不同会话。把两份记录合并成一条审计线索，属于混算会话。执行检查：取两次交接的chatId与responseChatItemId，比较是否指向同一会话与同一响应。

## 怎么确认配好了

1. 验证一：取材料原文一与拟稿句。输入为单号 RT-2024-0871、等级 B、签名栏空白；比较拟稿句“已通过质检”与材料中判定人签名栏状态；满足条件为拟稿句与材料字段一致，当前材料未提供签名，该结论待核实。

2. 验证二：取材料原文二与拟稿句。输入为照片说明“杯身有划痕，杯盖完好”；比较拟稿句“批准重售上架”与材料中是否存在重售上架单；满足条件为重售上架单载明批准主体与日期，当前材料未出现该单，该结论未获支持。

3. 验证三：取两次交接的 chatId 与 responseChatItemId。输入为两组标识；比较是否同一 chatId 且 responseChatItemId 在当前 chatId 下唯一；满足条件为同一 chatId 下标识唯一，若 chatId 不同则记录为两条独立会话，不合并计算。

检索与相似度不承担权限或实体隔离。quoteList 与 score 用于展示召回内容，不表示调用方有权访问对应业务记录。空结果核对可用明确的纸面输入空列表，观察下游是否按无内容处理。跨不同向量模型的库不可共同关联，先核对 datasetId 与模型标识，排除不符合者并记录实际观察。
