# 逆向退货入仓质检的运营权限与交接管理：部署与升级

## 这个品类的数据长什么样

在逆向退货入仓质检的运营权限与交接管理中，本页说明FastGPT的部署与升级如何衔接资料。逆向质检升级核同一退货批次，照片恢复不等于等级判定或重售。所用场景为自拟文字测试。

## 这些特征在「部署与升级」这一环带来什么约束

假设退货入库单只记收件，质检照片说明待复核，等级表未定，重售上架单为候选稿。升级验收应核同一退货对象的资料链，不能从入库成功推出质检合格或商品已重售。此自拟文字不包含真实图片、等级、数量或销售记录，恢复结果只证明实测内容，不替代仓内检验。

## 配置怎么定

| 逆向质检升级 | 假设输入 | 核法 |
| --- | --- | --- |
| 收件 | 入库登记 | 不推合格 |
| 照片 | 说明待复核 | 图文分测 |
| 等级 | 未判定 | 不补级别 |
| 重售 | 候选稿 | 不称已上架 |
| 恢复 | 同批物品资料链 | 逐项核原文附件 |

### 固定版本条件

| 文档项或实施核对项 | 条件 |
| --- | --- |
| `部署版本` | 先核当前及目标版本说明。 |
| `AIPROXY_API_ENDPOINT` | 环境变量采用服务根地址。 |
| `AIPROXY_API_TOKEN` | 两端Token需一致且非空。 |
| `依赖与备份核对` | 备份生成后仍需实测恢复内容。 |
| `升级后验证` | 复用同一组资料验证导入及调用。 |

## 容易做错的三处

- 恢复后收件单被概括成质检合格时，对收件原句、等级表与检验依据，查阶段跳跃。

- 另一退货批次照片支持本批等级时，对批次、物品及照片说明，文件同名不能配对。

- 重售候选稿可读而原图未恢复时，分核原文、附件与检索，不能按上架清单存在宣布链路齐全。

## 怎么确认配好了

按实际部署记录版本、存储和检索依赖，备份后真实测试恢复范围。前后用同一组材料问收件、质检、等级和重售分别到哪一步；照片读取另测真实路径。保留实际错误与访问结果，不猜配置值或容量阈值。切换或回退计划须经实测，真实等级、报废与上架由负责人员授权执行。
