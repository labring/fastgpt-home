# FastGPT Community, Commercial and Cloud Edition Matrix

## Turn requirements into testable tasks

List the required tasks first. Engineering and support might share an answer entry point but need access to different manuals. Another requirement might keep the environment under company management, with databases and configuration available for migration checks. Record the task, user and test result so procurement can compare installation, team management and file permissions against the same list.

## Compare features before documenting hosting and service

The feature entries below come from the FastGPT v4.17.4 [edition feature table](https://doc.fastgpt.io/guide/version/commercial). For file-level permissions or team spaces, check whether each edition lists the capability, then verify the actual environment, activation path and service terms. Document who manages access, handles incidents and schedules upgrades for each hosted or self-managed option.

| Dimension | Community | Commercial | Cloud |
| --- | --- | --- | --- |
| File-level permissions | Not listed as supported | Listed as supported | Listed as supported |
| Team spaces and permissions | Not listed as supported | Listed as supported | Listed as supported |
| Operations | Name self-managed environment owners | Check actual deployment option and service terms | Check account management and support scope |

## Test file permissions with two member identities

With the commercial capability enabled, the [file-level permission documentation](https://doc.fastgpt.io/guide/dataset/collection_permission) describes assigning collaborators to a file or folder. A search authenticated as the current member retrieves only files that member has permission to read. Test entry points that preselect a knowledge base without current-member authentication separately. Run one question with authorized and unauthorized accounts and record the returned passages and source visibility.

## Check team management and operations separately

Review who adds teams and users, who checks account changes and who can still see shared entry points. On the operations side, use an upgrade or recovery exercise to identify the owner and materials needed. Record company-managed and provider-assisted work separately and confirm the scope against purchase and support terms.

## Keep the selection record tied to tests

For each requirement, record the edition, actual configuration, test account and evidence location. If file separation is essential, confirm it at the real entry point. Assign unresolved conditions to a procurement or technical owner and record when to revisit them. Save the trial results with deployment and service records so the same tests can be reused after an edition change. Keep separate records for shared accounts, temporary accounts and sharing entry points.
