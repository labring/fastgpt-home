# Agent 复用：六个入口分清可复用与需重做

**第一个场景上线后要复制到其他部门，最先要回答的是“哪些东西能带走、哪些必须重做”，模板清单排在后面。六个入口逐项核，复制的成本才可估。**

## 入口一：工作流编排

入口：[FastGPT 接口说明](https://fastgpt.cn/api/fastgpt-chat-api-guide)。

位置在应用的工作流画布。编排逻辑可以整份复制后改节点，也可以抽成固定链路复用。核对动作是标出流程里哪些节点依赖本部门的系统与字段，把这些节点列成替换清单。

失败表现是整份复制后发现节点仍指向旧系统的接口，改到最后等于重画。边界：辅助生成属于商业版能力，产出是候选版本，仍需人工应用、检查、调试后发布，不能用它替代复用设计。

## 入口二：插件与工具

入口：[FastGPT MCP说明](https://doc.fastgpt.cn/zh-CN/guide/build/tools/mcp_tools)。

位置在插件管理与工具配置。插件把第三方能力注册成可复用的工具，MCP 则连接已有的工具服务。核对动作是给每个工具标注维护方与变更频率：维护方在平台内、变更少的适合做公共工具；维护方在外部、变动频繁的适合走 MCP 接入。

失败表现是每个部门各自注册一套同样的工具，权限与配额分散在多个入口。边界：MCP 与外部渠道消息统一纳入团队每分钟请求数限制，公共工具被多部门共用时，额度要按合计峰值估。

## 入口三：知识库与文件权限

入口：[FastGPT 权限说明](https://doc.fastgpt.cn/zh-CN/guide/dataset/collection_permission)。

位置在知识库结构与文件权限设置。可复用的是结构与检索配置，需重做的是语料本身。核对动作是区分三类资料：全公司通用的制度、部门专属的业务资料、项目级的临时文件，分别落在不同知识库。

失败表现是把所有资料堆进一个库，靠文件权限隔离，结果每次加人都要重新配。边界：文件级权限开启后，成员身份鉴权的检索路径按可读文件过滤，公共库与部门库混用时，先确认哪些文件属于两类都可见。

## 入口四：变量与参数

入口：[FastGPT 更新说明](https://doc.fastgpt.cn/zh-CN/self-host/upgrading/4-17/4173)。

位置在应用变量与节点参数。可复用的是变量名与取值规则，需重做的是各部门的取值清单。核对动作是把变量分成环境类（地址、凭据）、业务类（部门、产品线）、展示类（称谓、口径）三组，环境类与业务类分开管理。

失败表现是变量写死在提示词里，换个部门要全文替换。边界：单选、多选支持由变量动态生成选项，选项为空时会明确报错，这一条要在联调时先验。

## 入口五：发布渠道

入口：[FastGPT 服务说明](https://fastgpt.cn/contact)。

位置在发布配置。渠道覆盖企业微信、公众号、个人微信、飞书、钉钉与嵌入页面。可复用的是发布流程与配置模板，需重做的是各部门的渠道凭据与可见范围。

失败表现是渠道配置集中在一人手上，新部门上线要等排期。边界：发布后静态资源按发布快照校验、动态资源按运行用户校验，渠道变更后要重新验一次权限。

## 入口六：版本与回滚

入口：[FastGPT 更新说明](https://doc.fastgpt.cn/zh-CN/self-host/upgrading/4-17/4173)。

位置在版本记录。复用不只是复制功能，还包括复制“出问题怎么退”。核对动作是给每个场景定一条回滚路径：应用回滚到哪个版本、知识库回滚到哪次导入、模型回滚到哪个引用。

失败表现是只有升级流程没有回滚流程，第一次出问题就靠人工改配置。边界：启用 Agent 沙盒时，主服务、Agent 沙盒与其预览代理须使用配套版本，回滚同样要成套回滚。

六个入口核完，输出一张复用矩阵：行是场景，列是六类资产，格子里写“复用”“改造”“重做”。矩阵出来，第二个场景的工期就能按格子估，不必每次从零讨论。第三个场景起，矩阵本身变成内部标准。
