# 定制 Agent 的交付核对入口

**定制项目的争议大多不发生在技术上，发生在范围上：改的是配置、集成还是代码。把三层范围、三档接口、五类模型、六步联调四个入口核清，交付就有边界。**

## 入口一：三层范围

入口：[FastGPT 服务说明](https://fastgpt.cn/contact)。

位置在方案与合同的交付清单。配置层包括知识库结构、工作流编排、提示词、发布渠道与权限，业务与实施方在管理台完成；集成层靠对外接口、插件与工具调用衔接 OA、ERP 与业务系统；代码层取决于授权形态，商业版镜像不支持修改，社区版部分可以改。

核对动作是给每条需求打一个层标签，标不出层的需求先放待议。失败表现是需求写在合同里却没有对应层，实施时只能临时谈。边界：超出应用层的改动属于定制开发，需要另行评估并写入订单与合同。

## 入口二：三档接口

外部工具构建的 Agent，先登记交付的是服务还是源码。服务接入核 HTTP／MCP 的输入输出与鉴权，源码项目先安排部署，再把调用接口加入联调清单。

入口：[FastGPT HTTP说明](https://doc.fastgpt.cn/zh-CN/guide/build/tools/http_tools)。

位置在接口清单。读、写、审批三档按风险排列，读操作配只读凭据与字段白名单，写操作配幂等键、回滚与人工确认，审批类操作保留人在原系统里点确认。

核对动作是清单里每个接口标注五项：档位、字段范围、调用身份、失败处理、负责人。失败表现是清单只有接口名，联调时才发现字段范围没定。边界：涉及业务系统写入与对外披露的环节保留人工确认，这条要在方案里明写。

## 入口三：五类模型清点

入口：[FastGPT 模型说明](https://fastgpt.cn/deploy/fastgpt-model-configuration)。

位置在模型配置页。语言、向量、重排、语音合成、语音识别五类逐项清点，各记服务地址、部署位置、版本与凭据归属。系统支持模型厂商接入并可扩展，已有算力通常可以继续用。

核对动作是替换前后各跑一轮同一批问题，记录检索命中与引用质量。失败表现是更换向量模型后沿用旧索引，查询向量与存量索引不再匹配；仅替换语言模型不要求联动更换向量模型。边界：向量模型切换意味着重建索引，这一条要写进排期。

## 入口四：六步联调

入口：[FastGPT 接口说明](https://fastgpt.cn/api/fastgpt-chat-api-guide)。

位置在测试环境与联调记录。顺序是模型连通、知识库就绪、接口连通、身份打通、链路串通、异常演练。每一步留一条记录，验收材料自然成型。

失败表现是排期按人排、不按依赖排，前三步没通就开始录正式数据。边界：工作流辅助生成属于商业版能力，产出是候选版本，需要人工应用、检查、调试后再保存发布，并要求应用编辑权限与管理员启用辅助生成及沙盒。

## 责任怎么分

四类失败对应四个责任方。接口不通、字段缺失、返回格式变化，归集成方与系统运维方；检索结果与预期不符、引用质量下降，归知识库与模型配置方；越权或该看到的看不到，归权限设计方；响应慢、调用被限流，归容量与配额规划方。核对动作是在方案里把四类写成一张表，每类写明验收由谁签。失败表现是所有问题都报给一个“技术负责人”，最后由他一个人转派，周期被拉长。边界：责任划分要先于联调确定，联调开始后再分，等于把争议留给验收。

四个入口核完，交付清单可以直接复用为验收清单：范围按层列，接口按档列，模型按类列，联调按步列，四张表对齐后，责任方一目了然。交付清单之外再附一页变更流程：谁提、谁评估、谁签字，改动落在哪一层，避免每次调整都从零讨论。变更单上留一栏“影响到的接口”，下次升级前按这一栏逐个回归，比凭记忆列清单可靠。
