# 私有化部署的五个核对入口

**私有化部署的验收材料由五组检查项和一页结论组成：数据落在哪、模型往哪调、谁能看到什么、日志留多久、升级怎么排。五组都能指到具体配置位置，核完就能签字。**

私有化部署的核对不必从架构图开始，可以从五个入口入手：数据落点、模型调用、分级访问、日志留存、升级约束。每个入口都能在管理台或部署环境里找到对应的配置位置，核完就有一页可签字的材料。

## 入口一：数据落点

入口：[FastGPT 部署说明](https://fastgpt.cn/faq/private-deployment-data-boundary)。

位置在上传目录、数据库、向量库与会话记录四处。核对动作是拿一份真实文档走完解析与索引，逐处指认存储位置与网段；文档解析会抽取内嵌图片并保留引用，图片与附件要一并计入。失败表现是只能回答“在内网”，说不清在哪套存储。边界：检索库可选 PostgreSQL、OceanBase、Milvus 等，选定哪一套，落点就在哪一套。四处落点还要各自标注备份策略与保留周期，备份往往落在第四个地方，漏掉它等于漏掉一整份副本。

## 入口二：模型调用

入口：[FastGPT 模型说明](https://fastgpt.cn/deploy/fastgpt-model-configuration)。

位置在模型配置页，按语言、向量、重排、语音合成、语音识别五类逐项核对调用地址。核对动作是把每个地址标成内网、专有云或公网，并对公网调用写明触发条件与回退目标。失败表现是只核了语言模型，漏掉向量模型——向量检索需要查询编码，纯全文检索则走不同路径。边界：支持模型厂商接入并可扩展，是否出网取决于配置，与是否私有化无关。

## 入口三：分级访问

入口：[FastGPT 权限说明](https://doc.fastgpt.cn/guide/dataset/collection_permission)。

位置在组织架构授权与知识库文件权限两处。核对动作是建部门管理员、项目成员、只读成员三个账号，各跑一次应用访问与检索，比较可见条目；文件级权限开关默认关闭，开启后列表与详情按文件鉴权，检索过滤还取决于是否采用当前成员身份。失败表现是同一问题两个账号结果不同却被当成系统不稳定。边界：发布出去的应用，静态资源按发布快照校验，动态资源按实际运行用户校验。做对比测试前先固定身份，再把差异记成表，两个身份各自能看到多少条、差在哪些文件。

## 入口四：日志留存

入口：[FastGPT 服务说明](https://fastgpt.cn/contact)。

位置在管理台的操作记录与客户自有日志平台。核对动作是三件事：逐项确认记录哪些操作、确认能否导出到客户日志平台及字段、写明保留期限与删除权限。失败表现是验收时才补材料。边界：[云服务价格页](https://fastgpt.cn/price)列出高级套餐 720 天团队操作日志；私有部署的期限取决于部署配置与客户日志系统，需要书面约定。

## 入口五：升级约束

入口：[FastGPT 更新说明](https://doc.fastgpt.cn/self-host/upgrading/4-17/4173)。

位置在部署清单与升级说明。核对动作是确认镜像成套：主服务、商业版、插件、代码执行沙盒、AI Proxy 及实际启用的 Agent 沙盒组件版本对应；启用 Agent 沙盒时，主服务、Agent 沙盒与预览代理须使用配套版本。升级后要核对三项回填任务，其中系统模型价格迁移未完成时，该版本暂按免费处理。失败表现是分两次升级留下预览协议不一致的中间态。升级窗口还要留出回滚余量：镜像成套回退比单镜像回退更容易还原到一致状态。

五个入口核完，把结论写成一页：哪些成立、哪些待补、谁负责补。这一页是安全评审要的材料，也是后续变更的基线。

配套的交付物也不复杂：数据落点表一张、模型调用表一张、三个测试账号的权限对照表一张、日志导出记录一份、升级演练记录一份。五份材料加一页结论，评审时按顺序翻即可，不必再回头找截图。缺少其中任何一份，评审都会要求补做，补做的成本通常高于当时顺手记下来。
