# 能源与化工企业的生产报告：巡检记录、指标汇总与成稿复核怎么拆

## 这个行业做这件事，卡在哪
能源与化工企业的生产报告所需材料来源分散，巡检记录多为纸质表单或零散电子文件，生产指标来自分散的控制系统与报表文件。报告需经生产部门、安全管理部门、合规岗位共同审核，审核内容涵盖数据准确性、指标偏差范围、合规条款匹配度、文本逻辑连贯性。人工完成该流程需跨系统收集材料，手动核对多源数据，反复调整报告格式，且需逐页复核内容，固定周期的日报与周报任务带来重复劳动。

## 动手之前要先确认的五件事
- 确认生产指标的统计口径由谁制定并留存书面依据。确认不了会导致生成的报告数据标准不统一，无法通过合规审核。
- 确认巡检记录、生产报表的文件格式是否属于pdf、doc、docx、xlsx、pptx、md、txt、html、htm范围。确认不了会导致部分材料无法自动读取，需额外手动处理。
- 确认报告的复核节点与责任主体，明确不合格报告的整改流程。确认不了会导致生成的报告无法流转到对应审核环节，无法完成闭环。
- 确认需要汇总的巡检项、生产指标的固定字段清单，无临时变动需求。确认不了会导致工作流无法适配临时调整的统计项，需频繁修改配置。
- 确认用于检索的知识库内容的更新频率与权限范围。确认不了会导致检索结果依赖过时或越权的信息，影响报告准确性。

## 怎么搭：四段工作流
| 阶段 | 这一段做什么 | 用到的节点 | 配置要点 |
| ---- | ---- | ---- | ---- |
| 数据收集与预处理 | 从指定系统或文件中拉取生产指标数据、提取巡检记录文本，完成基础格式清洗 | 开始、HTTP 请求、文本内容提取、循环开始、循环节点、循环终止、文本拼接 | 配置HTTP请求的认证参数与接口地址，设置循环节点的遍历范围为已上传的巡检文件列表 |
| 指标计算与巡检汇总 | 基于固定口径计算生产指标，整合巡检记录的关键项，检索合规要求与历史参考数据 | 知识库搜索、知识库搜索引用合并、代码运行 | 设置知识库搜索的召回参数，配置代码运行的指标计算逻辑，引用合并最多3条检索结果 |
| 报告初稿生成 | 基于汇总的数据与检索结果，生成符合固定格式的生产报告初稿 | AI 对话、文本拼接 | 指定AI对话的prompt模板为行业通用生产报告格式，使用文本拼接待生成的报告内容 |
| 成稿复核与输出 | 按照预设规则复核报告的准确性与合规性，完成最终输出 | 判断器、自定义反馈、结束 | 配置判断器的复核条件，设置自定义反馈的触发规则与整改提示 |

### 易出错配置点展开
循环节点的终止条件是常见配置失误点，需设置循环次数等于巡检文件的总数量，或通过判断器触发循环终止的条件为无剩余待处理文件，避免工作流陷入无限循环。
知识库搜索的召回与重排配置需贴合场景需求，不可盲目调整参数。针对巡检记录与指标汇总任务，召回条数需控制在合理区间，重排后保留最相关的结果。
判断器的阈值配置需结合企业内部标准，不可直接套用通用模板，例如指标偏差的判定条件需对应生产部门的允许波动范围，确保复核逻辑符合实际业务要求。

## 知识库与检索怎么配
切分策略需结合业务场景制定：巡检记录按单个巡检班次、单台设备为单位切分，确保检索时可快速定位特定设备的巡检内容；生产指标按每日/每周的统计维度切分，便于按报告周期快速召回对应数据。索引方式可选用PostgreSQL(pgvector)或Milvus作为向量库，支持高效的相似度检索。
召回条数的取值需根据信息密度调整：对于需要详细参考的合规检索，召回条数可设置为5-8条，使用fastgpt-plugin v1.1.2支持的重排模型后保留3-4条；对于常规的巡检与指标汇总，召回条数设置为3-5条即可。重排模型需选用fastgpt-plugin v1.1.2支持的8个重排模型之一，确保检索结果的相关性排序符合业务需求。

## 验收怎么做
选取连续3个报告周期的历史数据作为测试样本，包括日报与周报类型。验收时需核对三个核心维度：数据提取的一致性、指标汇总的准确性、复核逻辑的覆盖率。合格口径由生产部门与合规部门共同制定，具体阈值需结合行业合规标准、企业内部的历史差错率与业务精度需求标定，不可直接套用通用标准。验收通过的标准为所有测试样本的报告符合预设的合格口径要求。

## 这个行业容易踩的坑
- 未提前确认统计口径的更新机制，导致生成的报告与最新合规要求不符。原因是未在前置确认环节明确口径的变更流程与责任主体。
- 未对巡检记录的非结构化文本做基础清洗，导致AI提取的内容存在冗余或错误。原因是未在数据预处理阶段增加文本过滤步骤，未剔除无效的备注信息。
- 未按设备、车间分类构建知识库索引，导致检索结果分散，无法快速定位相关信息。原因是未针对行业场景优化知识库的分类维度，仅使用全局检索。
- 未设置循环节点的终止条件，导致工作流陷入无限循环，无法完成任务。原因是未在配置阶段验证循环逻辑的正确性，未关联文件列表的总数量作为终止依据。
- 未将复核规则固化为判断器节点，导致复核流程依赖人工手动操作，无法实现自动化。原因是未将固定的复核条件转化为可配置的判断逻辑，仍保留人工介入环节。

## 什么情况下先不要做
当生产指标的统计系统未完成标准化改造，多源数据无法通过统一接口获取时，该场景的自动化搭建会面临大量手动数据处理的问题。当报告的复核规则频繁变动，无法固化为固定的判断条件时，自动化工作流的维护成本会大幅升高。当企业内部未明确报告的责任主体与合规要求时，生成的报告无法通过内部审核，上线后无法实现预期价值。上述场景下，该工作流不宜上线。
