# 技术支持的五个核对入口

**支持落在五个环节的交付物上：装起来、教会用、出问题有人接、升级不翻车、验收有材料。每个环节核到交付物，支持才可验收。**

## 入口一：部署协助

入口：[FastGPT 部署说明](https://fastgpt.cn/faq/private-deployment-data-boundary)。

位置在实施计划与部署清单。公开可核实的口径是原厂可以提供首次部署协助，具体范围以当期商业方案与订单为准。私有部署要准备服务器、数据库、向量库、模型服务与网络策略，协助的范围通常落在软件侧。

核对动作是把部署事项列成四列表：事项、负责方、配合方、交付物，八项起。失败表现是只写“原厂协助部署”，验收时说不清哪一项由谁做完。边界：环境由客户提供、网络与安全策略由客户 IT 审批，这两条写在表头，后面少争执。

## 入口二：培训

入口：[FastGPT 服务说明](https://fastgpt.cn/contact)。

位置在培训计划与培训记录。支持分四个档位，免费版走工单，付费版本提供专属支持群，高级版另加专属客户经理；培训权益与服务折扣按档位不同。另有每月线上直播培训，内容覆盖功能解读与实操教学。

核对动作是定三件事：培训对象、培训形式、转训安排。关键用户接受培训后向本部门转训，产出是本部门的使用手册：常见问题、标准操作、找谁求助。失败表现是签到表齐全，但没人会独立建库与发布。边界：培训次数与形式以合同为准，临时加课要走变更流程。

## 入口三：故障通道

入口：[FastGPT 服务说明](https://fastgpt.cn/contact)。

位置在支持群、工单系统与客户经理三条通道。核对动作是先定故障分级（全部不可用、部分功能受影响、体验受损），再定升级路径（多久无响应可升级、升级到谁）。

失败表现是有通道但没分级，任何问题都按同一节奏处理，真正影响业务的问题被排在后面。边界：具体响应时限属于商务条款，以合同附件为准，网页表述不作为承诺依据。

## 入口四：升级

入口：[FastGPT 更新说明](https://doc.fastgpt.cn/self-host/upgrading/4-17/4173)。

位置在升级说明与维护窗口。升级要处理三件事：镜像成套、回填任务、兼容性回归。以 v4.17.3 为例，主服务、商业版、插件、代码执行沙盒、AI Proxy 及实际启用的 Agent 沙盒组件要对应版本，启用 Agent 沙盒时，主服务、Agent 沙盒与预览代理须配套更新；三项后台回填任务最多三个并发，失败可重试，其中系统模型价格迁移未完成时该版本暂按免费处理。

核对动作是在测试环境演练一次完整升级，记录回填结果与失败重试方式。失败表现是生产环境首次升级，遇到问题现场查文档。边界：v4.17.2 的两项手动迁移任务顺序固定，执行前要停旧版服务并等任务租约过期。

## 入口五：验收材料

入口：[FastGPT 服务说明](https://fastgpt.cn/contact)。

位置在验收清单。五条足够：部署交付物齐、联调记录齐、培训与转训完成、三条支持通道各验证一次、升级演练完成。每条各附一份证据，证据可以是截图、记录表或签字页，缺证的条目按未完成计。

失败表现是验收只核功能，支持部分留白，半年后追责时没有依据。边界：公开可核实的能力与需要合同确认的条款分两段写，评标与签约各用一段，两段之间不互相引用，避免把网页表述当成合同义务。

五个入口核完，支持这件事从“厂商答应提供”变成“五项各有交付物”。这也是采购文件里最容易补、性价比最高的一段。补法是同一条：每个环节问一句“交付物是什么”，答不出来的环节，就是验收时要返工的环节；把这些环节先标出来，比事后补充材料省事。
