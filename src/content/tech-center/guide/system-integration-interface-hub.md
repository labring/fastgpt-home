# 接口集成的四个核对入口

**接口集成的返工多来自四件事没提前定：清单只写接口名、凭据不知归谁、调用身份说不清、配额没算峰值。四条入口逐项核完，联调时可以按清单定位问题。**

## 入口一：接口清单

入口：[FastGPT 接口说明](https://fastgpt.cn/api/fastgpt-chat-api-guide)。

位置在集成方案与接口文档。清单至少五列：接口用途、读写档位、字段范围、调用身份、失败处理。读写档位决定审批要求，字段范围决定扩散面，调用身份决定日志能不能追到人。

核对动作是拿清单逐个对文档，确认字段确实在返回体里，不只写了“客户信息”这类笼统描述。失败表现是清单与文档两套说法，联调时按清单写代码、按文档改代码。边界：接口可以按业务场景裁剪，裁剪后的字段集合要复核一遍是否仍够用；字段给少了业务跑不通，给多了权限收不回。

## 入口二：凭据归属

入口：[FastGPT 接口说明](https://fastgpt.cn/api/fastgpt-chat-api-guide)。

位置在团队设置与 API Key 管理。凭据归哪个团队、谁能创建、多久轮换，三件事都要写进运维手册。凭据创建权限受团队默认权限开关影响：开关开启后，新团队的全员组会增加创建权限，既有团队不自动补授。

核对动作是把现有凭据列一遍，标注用途、归属人与最后轮换时间。失败表现是凭据由个人创建、人一走就没人敢动。边界：服务账号的权限按接口逐个开，能读的字段与能写的单据分开授权，泄露后的影响面才可控。

## 入口三：调用身份

入口：[FastGPT 权限说明](https://doc.fastgpt.cn/zh-CN/guide/dataset/collection_permission)。

位置在接口鉴权与日志。以服务账号调用，日志只记到服务账号；以用户身份调用，日志能追到人。两种做法各有代价：前者实现简单，后者审计完整。

核对动作是同一个操作分别用两种身份各跑一次，比对日志里记录的主体。失败表现是安全评审问“这条操作是谁做的”，答不出具体人。边界：涉及业务系统写入与审批的环节，身份与人工确认要一起设计，单靠日志补不回来。

## 入口四：配额与限流

入口：[FastGPT 更新说明](https://doc.fastgpt.cn/zh-CN/self-host/upgrading/4-17/4173)。

位置在团队配额与调用记录。MCP 应用工具调用与外部渠道消息统一纳入团队每分钟请求数限制，超限返回额度与重试等待时间，外部渠道消息去重后计数。通用分页参数超过上限按上限处理，分页取数脚本要据此调整。

核对动作是按峰值估额度，并把页面会话与接口调用合起来算——两者共享同一份额度。失败表现是压测只测一侧，上线后另一侧被限流。边界：高频自动化要配退避与重试，重试策略本身也要计入额度，不能假设重试免费。

## 升级时的回归范围

接口集成做完不算稳定。版本变化会动到接口字段、工具调用行为与权限模型。以 v4.17.3 为例，知识库导出接口改为只导单库，开启文件级权限时只导出当前成员可读文件；成员可配置专属模型与渠道，团队所有者可替换失效的语言、语音与重排模型引用；4.17.0 起增加 CSRF 防御，嵌入第三方页面时先验证提交行为。

核对动作是每次升级前按接口清单逐个比对请求与响应字段，升级后跑一遍读、写、审批三档的成功与失败路径。失败表现是升级后某个接口静默少返回字段，业务侧用空值继续跑，几天后才发现数据不对。边界：升级窗口与镜像约束绑定，启用代码沙盒的部署要整套升级，接口回归排在同一窗口内。

四个入口加一段回归范围，构成接口集成的完整核对链。清单、凭据、身份、配额各有负责人，交付时按人签字，比按文档签字更容易追溯。
