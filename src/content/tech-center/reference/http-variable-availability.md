# FastGPT HTTP变量可用性与调试模式基准

HTTP节点的变量是否存在，要结合运行入口判断。FastGPT v4.17.2文档明确列出了测试模式下不可用的身份变量，以及历史记录的默认条数。联调时先按这份固定版本基准核变量来源，再检查外部接口收到的请求，避免把调试环境缺少变量误判为业务系统故障。

## 系统变量与输入基准

| 变量或输入 | 文档明确的值或含义 | 可用条件与核对点 |
| --- | --- | --- |
| appId | 应用ID | 按应用范围核对，不作为业务账号授权凭证 |
| chatId | 当前对话ID | 测试模式下不存在 |
| responseChatItemId | 当前响应消息ID | 测试模式下不存在 |
| variables | 当前对话的全局变量 | 变量值来自实际输入，不预设业务字段 |
| cTime | 当前时间 | 核对本次请求中的实际值与接口需要的格式 |
| histories | 默认最多10条；不能修改长度 | 不是完整历史归档，应检查实际带入的历史内容 |
| 请求变量来源 | 全局变量、系统变量、前方节点输出 | 变量来源与实际值分别核对 |
| Params / Headers / Body / URL | 支持变量引用 | Body是否生效还取决于请求类型及接口契约 |
| JSON中的字符串 | 需要双引号 | 数组、对象和数字按实际类型引用，勿当作字符串默认处理 |

## 调试模式先检查身份变量

chatId与responseChatItemId在测试模式下不存在，因此依赖它们的请求不能只凭编辑器测试结果判断正式调用是否可用。需要会话或消息标识的接口，应分别记录测试与实际调用时带入的变量。appId标识应用，不能替代当前业务人员对订单、库存或合同的访问授权。

## 请求格式与业务返回分开核对

检查Params、Headers、Body与URL中的变量时，先核变量是否有值，再核值的类型及放置位置。字符串在JSON中需要双引号；数字、数组和对象需要保持接口契约要求的类型。接口响应值的提取还应核对实际响应结构与配置的取值路径，不能仅以HTTP请求成功判断订单、审批或其他业务操作已经完成。

## 固定版对照的方法

联调前分别准备无需会话身份的请求、确实依赖会话标识的请求，以及缺少必要输入的请求。比较它们实际发出的内容和接口返回。引用的histories有文档规定的数量限制，需要更完整的会话证据时应另核数据来源，不能把这组变量当作完整审计存档。
