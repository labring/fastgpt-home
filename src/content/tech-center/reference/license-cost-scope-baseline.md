# 授权与费用范围基线：四科目、四变更、三退出

**基线要回答的是“花在哪些科目上、哪些变更要追加、退出时怎么收场”，总额排在后面。三张表写完，年度预算才有依据。**

## 四项费用科目

第一项，授权。私有部署以单台服务器 License 为基础授权，按约定期限、版本与范围描述。第二项，服务器与基础设施，含数据库、向量库与模型推理资源。第三项，模型调用，接外部模型时按用量计费，接本地模型时转为显卡与电力成本。第四项，支持与升级服务，按档位与合同约定。

四项分开记，是基线的第一条要求。合并成一行，第二年做预算时无法判断哪一项在涨。

## 四类变更成本

| 变更 | 通常处理方式 |
| --- | --- |
| 增加服务器 | 另行确认授权，写入订单 |
| 扩展集群 | 通常另行报价，写入合同 |
| 启用未购模块 | 另行确认授权 |
| 升级大版本 | 按版本范围判断是否补差 |

四类变更都要在签约前问清计价方式。报价单只写总价时，扩容与模块变更的处理依据仍不清楚，应补齐对应的计价方式、适用范围与确认人员。把答复写进比价表的同一行，注明依据是报价单还是口头说明。

## 三项退出安排

第一，终止后软件还能用多久。第二，数据以什么形式导出，范围包含哪些。第三，原厂协助迁移的义务到什么程度。

三项都要在合同或订单里。私有部署的数据在客户环境，导出范围受权限影响：开启文件级权限时，导出只包含当前成员可读的文件，换人执行导出会漏掉一部分。这一条要在退出方案里写明由谁执行、如何验证完整性。

## 授权范围的四项

对象、期限、版本范围、范围与限制。对象写服务器数量；期限写授权有效时长，与维保期限分开；版本范围写是否覆盖下一大版本；范围与限制写租户上限与模块。

四项对着条款编号核一遍，缺项进待确认清单。清单在签约前清零，签约后再发现只能走补充协议，周期通常以月计。

## 数据条款的基线

私有部署的数据保存在客户本地或客户自有云环境。现行合同第六条约定，未经客户书面同意，不得将可识别客户数据、内部资料或知识库语料用于合同外模型训练、展示或提供给无关第三方；服务终止后按客户合理要求返还或删除实际控制的数据。

基线记录方式是摘录条款编号与关键句，不复制全文。复查时按编号回原文，避免转述走样。

## 季度对账口径

四项：授权范围与实际使用是否一致；更新是否在维保期内；模型调用费用与用量是否匹配；支持通道是否仍有效。

模型调用这一项按百万 Tokens 换算后比对，语音合成按百万字符、语音识别按每 60 秒。口径不统一时，两个数字根本不能比较，对账会变成各说各的。

## 授权与预算怎么衔接

年度预算按四个科目提报，授权科目写续签与可能的大版本补差，基础设施科目写扩容与备份存储，模型调用科目写按量估算与峰值余量，支持科目写档位与培训。四项各自有负责人，预算讨论时按科目过，比按总额争论有效。

预算调整先按业务必要性、容量需求和已购服务范围评估。把可以延后、必须保留和需替代方案的支出分别列清，再由项目负责人确定调整项；许可、模型、基础设施与支持服务之间存在依赖，不按固定顺序削减。

## 基线怎么用

年度预算按四个科目列，季度对账按四项核，变更前查四类成本，退出前对三项安排。四张表填完，授权这件事就从“合同里的一段话”变成“可以核算的科目”，年度预算、续约谈判与退出安排都从这四张表起算，不必再翻合同正文。
