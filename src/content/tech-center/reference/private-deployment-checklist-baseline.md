# 私有部署检查项基线：五组二十项

**基线的作用是让第二次部署不必从零讨论。下面五组二十项，每项给判定口径与留档位置，按组打勾即可复用。**

## 基线怎么用

用法有两种。新项目按清单从第一组往后走，每项留档；老项目每季度按清单复核一次，只补缺项。两种用法都要求同一件事：判定口径写清楚，不靠记忆。

口径存在的意义在于可比。同一个项目换人复核，按口径得出的结论应当一致；不一致时先查口径，再查执行。

## 第一组：部署交付物（八项）

| 项 | 判定口径 |
| --- | --- |
| 服务器与网络 | 地址、网段、可用区各一份记录 |
| 数据库与向量库 | 版本、连接方式、备份策略 |
| 镜像版本 | 主服务、商业版、插件、代码执行沙盒与实际启用的代理组件版本齐全 |
| 模型服务 | 五类模型的地址、部署位置、版本 |
| 管理员账号 | 初始化完成，密码策略已改默认值 |
| 域名与证书 | 证书有效期、签发机构、自动续期 |
| 日志与备份 | 落点、周期、保留期、恢复演练记录 |
| 渠道配置 | 已启用的发布渠道与凭据归属 |

八项里最容易缺的是日志与备份的恢复演练记录。有备份没演练，等于没有验证过备份可用。

## 第二组：数据落点（四处）

| 落点 | 判定口径 |
| --- | --- |
| 原始文件 | 上传目录或对象存储，标注路径与网段 |
| 解析文本块 | 数据库表名与分片策略 |
| 向量索引 | 向量库集合名与维度 |
| 会话记录 | 会话表与保留期 |

四处都要能指到具体环境。解析环节会抽取内嵌图片并保留引用，图片与附件单独记一行，不要并入原文件一行。

## 第三组：权限验证（三项）

第一，三个账号对照：部门管理员、项目成员、只读成员，各自的可见范围写成表。第二，文件级权限：开关打开后，同一问题用两个身份各跑一次，比较返回条目。第三，发布快照：发布后新成员访问，比对静态资源与动态资源的表现。

三项验证都要固定身份再做对比。身份不固定，结果差异无法归因，容易被当成系统不稳定。

## 第四组：日志与审计（两项）

第一，导出：导一次操作记录，确认字段与落点。第二，留存：写明保留期限与删除权限。云服务高级套餐公开七百二十天的团队操作日志；私有部署的期限取决于部署配置与客户日志系统，需要书面约定。

这一组的判定不用追求长，追求可核。写明“保留一年、由运维负责人删除”比写“长期保留”有用。

## 第五组：升级演练（两项）

第一，镜像成套：确认已安装组件与目标升级清单对应，Agent 沙盒与预览代理使用配套版本。第二，回填核对：三项回填任务（沙盒团队归属、目录祖先路径、系统模型价格换算）逐项看结果，价格迁移未完成时该版本暂按免费处理。

演练在测试环境做，记录三段时间：镜像替换与启动、回填执行、回归验证。三段记录是排生产窗口的依据。

## 留档位置怎么定

二十项检查项如果各自存档，找起来很费时间。建议按三层落档：交付记录进项目交付目录，按组编号；测试记录进测试目录，按执行日期；签字页单独一份，只放结论与签字，不夹过程材料。三层之间的关系用编号串起来，一个编号能同时找到记录、测试与签字页。

落档的责任人是实施方，复核的责任人是客户 IT。两个人签字之后，这份基线才算成立。只有一方签字时，缺的那一方通常会在评审时提出补充要求。

## 判定口径的写法

口径要写成可判定的句子，避免写成形容词。例如“镜像版本齐全”可以写成“各已安装组件的版本分别与部署清单一致，差异为零”；“权限符合设计”可以写成“三个账号的可见范围与授权表逐行一致，差异项已登记”。

写成可判定的句子之后，复核会快很多，争议也会少。口径写不出来的检查项，通常说明这一项本身没有被想清楚，先把它拆细再写。

## 缺项怎么处理

复核时发现缺项，按影响面分三档处理：影响上线与合规的当场补；影响后续运维的排期补；属于记录不全的，本轮补记录并注明补记日期。三档分开处理，比一律“回头补”有效，也比一律停工务实。

补记必须注明日期与补记人，不能伪装成当时记录。这一点看似细节，实际决定了这份基线以后还能不能作为证据使用。

## 基线的维护

基线每季度复核一次，两件事：口径有没有变、项目有没有新缺项。口径变化来自版本升级与客户要求，缺项来自新增场景。复核后更新版本号与日期，旧版本归档但不删除，便于对照。
