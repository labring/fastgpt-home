# 解决FastGPT高级编排自定义全局变量API赋值失效问题

## 现象
高级编排中创建自定义全局变量aaa，通过Python代码在Post调用的Data参数中为aaa赋值后，后续流程获取该变量为空。为自带全局变量如chatid赋值可正常生效。仅自定义any类型全局变量通过API赋值失效，直接在高级编排界面为该自定义变量赋值可成功生效。

## 可能原因
API赋值逻辑对全局变量的类型存在校验规则。自定义全局变量aaa的预设类型为any，自带全局变量chatid的预设类型为string，二者的API赋值行为存在差异，推测校验逻辑未正确适配any类型变量的API赋值场景。

## 排查步骤
1. 确认高级编排中已创建目标自定义全局变量，并记录该变量的预设类型。
2. 检查API调用时Data参数中传入的赋值内容的类型，与变量预设类型是否匹配。
3. 对比测试自带全局变量与自定义全局变量的API赋值行为，确认类型差异带来的影响。
4. 尝试直接在高级编排界面中为自定义全局变量赋值，验证赋值是否可正常生效。

## 解决与验证
若需通过API为自定义全局变量赋值，需确保传入的参数类型与变量预设类型一致。对于预设为any类型的自定义变量，需确认API传入的参数格式符合平台要求。验证时，通过API传入匹配类型的参数，执行流程后检查全局变量的取值是否正确。若直接在编排界面赋值可正常生效，说明变量本身配置无误，问题源于API调用的参数类型匹配校验。
