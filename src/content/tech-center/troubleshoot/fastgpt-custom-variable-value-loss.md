# 解决FastGPT全局自定义变量多轮交互值丢失问题

## 现象
配置全局变量text并设置为自定义变量类型后，出现以下表现：用户输入信息经判断器else分支存入变量text，AI回复确认提示后用户输入ok触发if分支，此时变量text为空值。若将变量类型改为文本类型，重复测试可正常保留变量值。此外，文本类型变量即使配置为非必填，首次打开应用时仍会显示输入提示框，影响用户体验。

## 可能原因
暂无官方公开的根因说明，需按实际环境确认具体问题来源。仅从测试现象可知，自定义变量类型与文本类型变量的会话存储逻辑存在差异。

## 排查步骤
1. 确认全局变量的类型配置，检查是否设置为自定义变量类型。
2. 按照测试流程复现问题：先触发判断器else分支存入变量，再触发if分支读取变量，观察变量值是否为空。
3. 切换变量类型为文本类型，重复上述测试步骤，验证变量值是否正常保留。
4. 检查文本类型变量的非必填配置是否生效，确认前端提示框的显示情况。

## 解决与验证
1. 临时适配方案：将全局变量类型修改为文本类型，可保证多轮交互中变量值正常保留。
2. 已知限制：文本类型变量即使配置为非必填，首次打开应用时仍会显示输入提示框，可能影响用户体验。
3. 自定义变量类型的当前表现：多轮交互中变量值会丢失，暂无公开的官方修复方案，需按实际环境确认后续优化情况。
