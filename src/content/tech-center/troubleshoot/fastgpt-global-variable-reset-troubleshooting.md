# FastGPT私有部署v4.8全局变量问答后被清空的排错方法

## 现象
FastGPT私有部署v4.8版本中，用户使用下拉单选组件设置全局变量作为问题分类参数，完成第一轮AI问答后，全局变量被自动清空。再次发起提问时，因缺失全局变量无法正常发送请求。前端控制台显示全局变量已完成存储，但实际调用时无法读取该变量。

## 可能原因
该问题未在官方公开文档中明确披露根因，需结合实际部署环境的后端日志、前端控制台报错信息进一步定位。已知该问题的触发场景为使用全局变量作为问题分类参数的问答流程。

## 排查步骤
1.  打开浏览器开发者工具的控制台面板，查看是否存在与全局变量存储、读取相关的报错文本。
2.  查看FastGPT后端部署日志，确认是否存在全局变量重置、会话存储异常的相关记录。
3.  复现问题流程：重新设置全局变量，完成一次问答后，查看前端页面的全局变量存储状态，确认是否在AI回答完成后变量被清空。
4.  核对全局变量的配置流程，确认下拉单选组件的变量绑定、参数传递步骤是否符合配置要求，细节需按实际环境确认。

## 解决与验证
临时恢复方案为：在每次提问前重新设置全局变量，确保会话中携带正确的分类参数。若需彻底解决该问题，需等待官方发布对应版本的修复补丁，或根据排查得到的根因进行自定义调整。验证方式为：重新设置全局变量后发起多次连续问答，确认全局变量未被清空，且可正常用于问题分类参数。
