# 解决FastGPT HTTP请求失败导致流程无法继续执行的问题

## 现象
在FastGPT私有部署v4.7版本中，当使用无法访问的链接配置HTTP请求节点并连接后续流程节点时，HTTP请求失败后流程直接终止，无法进入后续流程节点，且无法将请求相关内容传递至下一流程。

## 可能原因
HTTP请求节点未配置异常捕获与容错逻辑，当请求返回非200状态码或请求无法完成时，流程触发未捕获的异常直接终止，未继续执行后续配置的流程节点。

## 排查步骤
1. 确认当前部署的FastGPT版本为v4.7私有部署版。
2. 复现问题：使用无法访问的链接配置HTTP请求节点，并连接后续流程节点。
3. 查看流程执行日志，确认HTTP请求失败时是否抛出未被处理的异常。
4. 检查HTTP请求节点的配置项，确认是否存在异常处理相关的设置选项。

## 解决与验证
解决方法为配置HTTP请求节点的异常处理逻辑，允许请求失败后继续执行后续流程并传递相关内容。验证步骤如下：
1. 重新配置HTTP请求节点，开启异常处理功能，设置请求失败时继续执行后续流程。
2. 使用无法访问的链接发起HTTP请求，观察流程是否继续执行至后续节点。
3. 确认后续节点是否成功接收到前一节点传递的内容。
4. 使用可正常访问的链接发起HTTP请求，确认流程执行流程符合预期。
