# 解决FastGPT中MCP工具集调用的400参数格式错误问题

## 现象
在FastGPT私有部署4.13.2版本中，通过MCP地址新建MCP工具集后，在工作流中添加工具调用节点并调用模型时，会返回400报错。当MCP工具集的工具ID以数字开头时，会触发该问题，使用gemini-2.5-pro调用时也会出现相同的报错情况。结合用户提供的相关截图，该报错与工具ID的格式不匹配直接相关。

## 可能原因
MCP工具集的工具ID以数字开头，不符合对应模型API的参数命名规范，导致请求的参数格式不符合API要求，从而触发400报错。

## 排查步骤
1.  确认当前使用的FastGPT为私有部署4.13.2版本，确认已正确配置MCP相关的环境参数。
2.  查看已创建的MCP工具集的工具ID，确认是否以数字字符开头，检查工具ID的整体命名格式是否符合通用规范。
3.  在工作流中添加工具调用节点，使用该工具集调用模型，观察是否返回400报错，记录报错的具体触发场景。
4.  调整工具ID格式，将其修改为不以数字开头的格式，例如添加字母前缀或使用符合通用命名规则的字符串，重新创建MCP工具集。
5.  再次在工作流中添加工具调用节点，使用调整后的工具集调用模型，验证是否不再返回400报错。
6.  若仍存在报错，需按实际环境确认其他相关配置是否正常。

## 解决与验证
解决方法：将MCP工具集的工具ID修改为不以数字开头的格式，例如添加字母前缀或使用符合通用命名规范的字符串，确保工具ID符合对应模型API的参数命名要求。验证步骤：重新创建符合格式要求的MCP工具集，在工作流中添加工具调用节点并调用模型，确认不再返回400报错，工具调用功能可以正常执行并返回预期结果。
