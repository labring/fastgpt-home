# 解决FastGPT私有部署开发时全量编译卡顿问题

## 现象
本地化部署FastGPT私有部署4.12.2版本时，开发过程中修改代码内容后，触发全项目编译操作，导致开发设备出现长时间卡顿情况。参与开发的人员为初次接触该Nextjs项目，对项目的编译机制不熟悉。

## 可能原因
该项目基于Nextjs框架开发，Nextjs开发模式下的默认编译逻辑可能未实现增量编译，即仅针对修改的文件进行编译，而是触发全项目编译，占用大量系统CPU、内存资源，进而引发开发设备卡顿。

## 排查步骤
1. 确认当前使用的FastGPT私有部署版本为4.12.2，核对部署包的版本标识。
2. 观察每次代码修改后，控制台输出的编译日志，确认编译涉及的文件范围，判断是否为全项目编译。
3. 查阅Nextjs官方开发文档中关于编译模式的相关说明，核对默认编译逻辑。
4. 需按实际环境确认开发服务的相关配置参数，如编译缓存、热更新设置等。

## 解决与验证
可通过调整Nextjs开发模式的编译配置，启用增量编译功能，仅针对修改的文件进行编译，避免全项目编译触发。验证时，修改代码后观察控制台编译日志，确认仅涉及修改的文件，且开发设备无长时间卡顿情况，即问题解决。若需进一步参考，可查阅官方提供的开发配置指导或相关Nextjs开发优化资料。
