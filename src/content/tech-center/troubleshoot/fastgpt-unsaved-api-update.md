# 解决FastGPT未保存修改即同步更新发布API的问题

## 现象
私有部署版本fastgpt:v4.8.20-fix2的FastGPT中，工作台内的应用未点击保存或保存并发布按钮，切换模型后点击返回按钮，通过API调用的线上服务的模型会同步发生变更，不符合预期配置逻辑。

## 可能原因
暂未明确具体技术根因，未保存的应用配置变更被错误同步至发布后的API服务，需结合系统部署日志与配置加载机制进一步排查确认。

## 排查步骤
1. 确认当前FastGPT部署版本为v4.8.20-fix2。
2. 进入目标应用的工作台编辑页面，切换模型配置，不点击保存或保存并发布按钮。
3. 点击返回按钮离开编辑页面。
4. 调用该应用对应的发布后API，检查返回结果中的模型配置是否已变更。
5. 查看FastGPT系统运行日志，确认配置同步的触发节点与相关信息。

## 解决与验证
临时规避方案：编辑应用配置后，务必点击保存或保存并发布按钮再离开编辑页面。验证步骤：
1. 编辑应用模型配置，点击保存并发布按钮后调用API，确认模型配置符合预期。
2. 再次编辑应用模型配置，不点击保存按钮直接离开编辑页面，调用API确认模型配置未发生变更。
若需彻底修复该问题，需结合官方更新日志与代码变更记录排查对应逻辑漏洞。
