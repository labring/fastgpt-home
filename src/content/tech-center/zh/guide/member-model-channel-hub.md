# FastGPT 成员级模型与渠道的配置入口

多团队共用一套部署时，模型和渠道的归属最容易出错：成员以为自己换了模型，实际走的还是团队渠道。4.17.3 支持成员配置专属模型与渠道，配置入口集中在三处。

## 成员模型配置

入口在团队管理页的成员设置与模型供应商配置。核对动作是先确认该成员有没有独立渠道，再在成员级配置里指定语言、索引、重排、语音等模型；保存后用一条测试对话确认请求确实走了成员自己的渠道。失败表现是配置成功但计费记在团队渠道上。边界：成员级配置不改变团队级默认值，未配置的成员继续继承团队设置。

配置完成后用同一个问题在两个账号下各跑一次，对比响应里的模型标识，确认走的是各自的渠道；只看配置文件，看不出实际走哪条链路。

## 失效模型替换

入口在团队管理页的模型引用检查。核对动作是团队所有者按语言、语音播放、重排三类逐项替换失效引用；索引模型、动态引用与空值三类不参与替换，需要单独核对。失败表现是替换后仍有节点报模型不存在，原因是引用藏在动态配置里。边界：替换只改引用，不删除原渠道，回滚时按原引用恢复。

## 渠道与 AI Proxy

入口在模型供应商配置页的渠道详情。核对动作是确认渠道的鉴权方式与 AI Proxy 的转发规则一致，成员级渠道不要复用团队渠道的密钥；改完渠道后检查一次实际调用的响应头与耗时。失败表现是调用返回鉴权错误或落到非预期供应商。边界：渠道决定计价归属，同一模型挂在不同渠道下账单口径不同。

AI Proxy 的转发规则改过之后，成员级渠道与团队渠道各回归一次；只测团队渠道，成员侧的鉴权差异会留到上线后才暴露。

## 权限与隔离

入口在团队与成员权限页。核对动作是确认成员只能看到自己的渠道凭据，团队所有者能看到全部；`DEFAULT_TEAM_BASIC_PERMISSIONS_ENABLED` 默认关闭，开启后新团队的全员组会增加创建 API Key 的权限，既有团队不自动补授。失败表现是新成员能建 Key 而老成员不能，或相反。边界：这项开关影响的是新团队，老团队要按需手工补。

成员离职前先收回专属渠道的凭据，再转移模型引用。只停用账号不收回凭据，渠道仍然可用，账单上会继续出现这个人的调用。
