# FastGPT 计费单位迁移的核对入口

4.17.3 把模型计价的字段与单位一起改了：LLM 走阶梯结构，其他模型走单价格式，Token 相关数值统一按百万计。做过一次升级之后，账单金额对不对得上，取决于下面四组核对有没有做完。

## 计价字段

入口在模型配置的计价区块。核对动作是确认 LLM 的计价写在 `pricing.tiers` 里，其他模型写在 `pricing.unitPrice` 里；同一个模型两处都写时以当前版本读取的字段为准。失败表现是模型调用正常但账单为 0，原因通常是配置还留在旧根级字段上，新版本不读那里。边界：团队模型不计费，成员级模型按各自渠道计价。

核对时按模型逐条记录四个值：计价字段、单位、单价、阶梯上限。四项齐了再比对账单，缺项时先补配置，不要靠金额反推单位。

## 单位与换算

入口在同一个计价区块的单位说明。核对动作是把 Token 单价与阶梯上限都按百万 Tokens 填写，TTS 按百万字符填写，STT 仍按 60 秒计；单价最多两位小数。迁移方向是 Token 与 TTS 的旧单价乘 1000、LLM 旧阶梯上限除以 1000、STT 不变。失败表现是金额整体放大或缩小三个数量级，几乎都出在这一步。

换算之后抽查两条调用：一条短请求、一条长请求，分别看计费记录里的单位与数量是否落在预期区间。换算只改存储口径，调用量本身不随之变化。

## 迁移兜底

入口在管理页的后台任务列表，任务名为系统模型价格迁移。核对动作是等启动依赖完成后查看任务状态，失败则修数据重试，再逐模型抽查一条调用记录与计费记录。失败表现是系统模型暂按免费处理，账面上看不到消耗。边界：迁移任务与另外两项回填任务共享最多三个并发，排队期间不要重复触发。

## 成员模型与团队模型

入口在团队管理页的成员配置与模型供应商配置。核对动作是确认成员专属模型挂在成员自己的渠道下，团队所有者在替换失效的语言、语音播放与重排模型引用时，索引模型、动态引用与空值不参与替换。失败表现是成员换了模型但对话仍走旧渠道，或某个环节没有可用模型却没人发现。边界：计费按模型所属渠道归属，跨团队复用渠道要在账单侧单独核对。

月末对账按三层看：模型层看单价与阶梯，应用层看 Token 统计，团队层看总额。哪一层先对不上，就往那一层的配置回溯，从总额倒推得不出结论。
