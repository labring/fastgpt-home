# FastGPT 4.17.3 升级的核对入口

先核对 v4.17.3 镜像和启动状态，再检查后台回填与应用回归。若升级路径涉及 v4.17.2，单独核对该版本的两项手动迁移及各自状态。

## 版本与镜像

入口在镜像仓库的 tag 列表与各组件的版本页。核对动作是确认主应用为 v4.17.3、插件为 v1.2.0、代码沙盒为 v5.0.0、AI Proxy 为 v0.7.7，并按顺序替换后重启。节点调用或预览异常时，先记录实际镜像与错误日志，再检查相应组件。边界：插件与沙盒独立发版，不能按主版本号推断。

变更记录里写清四处 tag 与部署时间，回滚时按同一组取值复现；只记主应用 tag 的做法，回滚时最容易在插件与沙盒上卡住。

## 核查 v4.17.2 手动迁移是否适用

入口在版本升级页，两项任务分别是迁移旧版知识库训练任务、迁移索引重建状态。页面默认倒序排列，第二项显示在上面，容易点反；点反时系统会拦住并提示前置任务。核对动作是先确认集群内旧版本的 App 与 Pro 已停止、旧任务租约（约两小时）已过期，再依次执行两项。失败表现是任务报冲突或长时间无进展。

## 三项后台回填任务

入口在管理页的任务列表。三项分别是沙盒团队归属、目录祖先路径、系统模型价格，启动依赖完成后独立执行，最多三个并发。核对动作是逐项查看状态，失败项修数据后重试；其中价格迁移要单独确认，因为未迁入的系统模型会按免费处理。失败表现是账单金额与调用量不匹配、成员看不到自己的沙盒实例。

三项任务并列展示，顺序不固定，按任务名称对照。位置会随执行顺序变化，不作为判断依据；三项都结束之前，不把升级标记为完成。

## 升级后的功能回归

入口在应用编辑页、知识库设置页与团队管理页。核对动作是四步：打开一个发布后的应用确认对话正常；检查知识库文件列表与检索结果是否按文件权限返回；确认文件夹导航只作入口、不带管理授权；用一条 MCP 或外部渠道消息确认配额计数正常。失败表现是检索结果随账号变化却查不到原因、外部渠道重复扣额度。

四步回归按影响面排序即可：对话主链路、知识库检索、文件权限、外部渠道。前两项影响面最大，先跑；后两项牵涉账号与凭据，放在有对应账号的人在场时再跑。
