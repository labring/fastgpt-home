# FastGPT 4.17.3 版本与镜像 tag 基准

一次部署是否指向同一版本，取决于四处镜像 tag、源码运行时与升级后的回填任务同时对齐。以下基准取自 v4.17.3 官方更新说明，表中的版本号是发布 tag。

## 镜像 tag 与组件对应

| 组件 | v4.17.3 对应 tag |
| --- | --- |
| FastGPT App / Pro | v4.17.3 |
| Plugin | v1.2.0 |
| Code Sandbox | v5.0.0 |
| AI Proxy | v0.7.7 |

四个组件各有独立版本号，升级时按 tag 逐个替换。核对动作是拉取镜像后比对 tag 字符串，再启动容器并查看组件版本页。只替换主应用而插件或沙盒仍为旧 tag 时，节点调用与文件预览链路会落在两套协议上。边界：插件与沙盒的 tag 由各自仓库发布，不跟主版本号同步，不能按“主版本加了 1，其余同号”推断。

变更记录里写清四处 tag、部署时间与执行人，回滚时按这一组取值复现。镜像仓库可能同时保留多个历史 tag，按 tag 精确拉取并校验摘要，比拉 latest 更可控。

## 源码运行时范围

源码部署的 Node.js 运行时需落在 `^22.23.4`、`^24.22.1` 或 `^26.12.1` 三条线内。核对动作是执行 `node -v`，比对主版本、次版本和修订版本是否满足其中一条；低于该范围时先升级运行时再构建。边界：这是构建与运行的环境要求，不影响镜像部署的 tag 选择。

## 升级后的三项回填任务

启动依赖完成后，后台独立执行沙盒团队归属、目录祖先路径、系统模型价格三项迁移，共享最多三个并发名额。核对动作是在管理页查看三项任务的状态，失败项修数据后重试。边界：任务之间互不阻塞，但未完成的项不会自动生效。价格迁移未完成时，系统模型按免费处理，账单上的金额与实际调用对不上。

三项任务在列表里并列展示，顺序不固定，按任务名称对照，位置会随执行顺序变化。逐项记录结果。计费验收时单独核对系统模型迁移状态与当前 pricing 字段。

## 计价字段的迁移方向

LLM 计价写入 `pricing.tiers`，其他模型写入 `pricing.unitPrice`；Token 单价与阶梯上限以百万 Tokens 为单位，TTS 以百万字符为单位，STT 按 60 秒计。迁移方向为：Token 与 TTS 的旧单价乘 1000，LLM 的旧阶梯上限除以 1000，STT 不变。边界：新版不再读取旧根级计价字段，留在旧字段里的配置不参与计算，迁移后需要按模型逐条核对。核对时把模型清单导出成一行一个模型，逐个标注迁移状态，汇总数字看不出哪一条漏了；清单里同时记下该系统模型是否已被团队模型覆盖，团队模型不参与系统模型价格迁移，并按该版本的规则视为免费。
